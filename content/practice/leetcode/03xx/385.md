[LeetCode 第 385 题](https://leetcode.com/problems/mini-parser/)

 **难度：** 🟡 中等
 **主题：** 字符串、堆栈、深度优先搜索

 ## 解决方案

 ## 问题理解

 该问题为我们提供了嵌套整数结构的字符串表示形式，并要求我们重建相应的`NestedInteger`对象层次结构。 

一个`NestedInteger`可以代表两件事之一：

 1. 单个整数值
 2.其他清单`NestedInteger`物体

 输入字符串使用类似于 JSON 数组的格式。 例如：

-`"324"`代表单个整数
 -`"[123,[456,[789]]]"`表示嵌套列表结构

 挑战是在保留层次结构的同时正确解析嵌套括号。 

所提供的`NestedInteger`接口处理实际存储。 我们的工作只是解析字符串并使用以下方法构建结构：

 -`NestedInteger(value)`对于整数
 -`add(elem)`用于将子项添加到列表中

 约束条件很重要：

 - 字符串长度可达`5 * 10^4`- 嵌套可以很深
 - 数字可能为负数
 - 保证输入有效

 这些限制告诉我们：

 - 递归子串解析可能会变得低效
 - 应避免重复的字符串切片
 - 我们需要一个线性时间解析策略

 一些边缘情况尤其重要：

 - 不带括号的单个整数，例如`"324"`- 负数，例如`"-12"`- 空嵌套列表，例如`"[[]]"`- 深层嵌套结构
 - 多位数字
 - 以逗号分隔的连续嵌套列表

 当区分不同嵌套级别的分隔元素的逗号时，幼稚的解析器很容易失败。 适当的筑巢管理是核心挑战。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是递归地解析子字符串。 

这个想法是：

 - 如果字符串不以`'['`，它必须是单个整数
 - 否则，拆下外支架
 - 将内部拆分为顶级组件
 - 递归解析每个组件

 困难来自于正确的分割。 我们不能简单地用逗号分隔，因为嵌套列表内的逗号不会分隔顶级元素。 

例如：```
[123,[456,789]]
```用逗号盲目分割会产生：```
["123", "[456", "789]"]
```这是不正确的。 

为了解决这个问题，暴力解决方案在扫描子串时跟踪括号深度。 

尽管这种方法有效，但它会重复创建子字符串和递归调用。 对于深度嵌套的输入和大字符串，开销会变得昂贵。 

### 最佳方法

 最佳解决方案使用基于堆栈的迭代解析器。 

关键的观察是括号自然地描述了层次结构，而堆栈是管理嵌套范围的理想选择。 

该算法逐字符处理字符串：

 -`'['`表示新的嵌套列表开始
 -`']'`表示当前列表已完成
 - 数字和`'-'`构建整数值
 -`','`分隔元素

 每当我们输入一个新列表时，我们都会将其压入堆栈。 当我们完成一个列表时，我们弹出它并将其附加到其父级。 

这可以避免：

 - 昂贵的子字符串创建
 - 复杂的递归分裂逻辑
 - 多次传递输入

 整个字符串只被处理一次。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 递归子字符串解析创建重复扫描和复制 |
 | 最佳| O(n) | O(n) | 单遍基于堆栈的解析器 |

 ## 算法演练

 ### 基于堆栈的解析算法

 1. 首先，处理最简单的情况。 

如果字符串不以`'['`，那么整个输入只是一个整数。 我们直接返回：```
NestedInteger(int(s))
```2. 创建一个空堆栈。 

堆栈存储当前活动的嵌套列表。 堆栈的顶部始终代表我们正在构建的当前列表。 
3. 初始化用于数字解析的变量。 

我们需要：

 -`num_start`跟踪数字的开始位置
 - 扫描字符串时的当前索引
 4. 逐个字符地遍历字符串。 

对于每个字符，我们确定它是否开始列表、结束列表或属于数字。 
5、遇到时`'['`:

 创建一个新的空`NestedInteger`列表并将其压入堆栈。 

这代表进入更深的嵌套层次。 
6. 当遇到数字或`'-'`:

 如果我们要开始一个新数字，请记录开始位置。 

我们不会立即创建整数，因为数字可能包含多个数字。 
7、遇到时`','`或者`']'`:

 如果我们正在解析一个数字，则提取子字符串，将其转换为整数，并将其添加到当前的顶级列表中。 

这是有效的，因为逗号和右括号标记了数字标记的结尾。 
8. 处理完一个数字后，如果当前字符是`']'`并且堆栈有多个元素：

 - 弹出已完成的嵌套列表
 - 将其添加到其父列表中

 这自然地重建了层次结构。 
9. 循环结束后：

 堆栈上剩余的对象是完全构造的结果。 

### 为什么它有效

 堆栈始终维护活动的嵌套层次结构。 

每当我们看到`'['`，我们进入更深的列表并推送一个新容器。 每当我们看到`']'`，我们完成当前容器并将其附加到其父容器。 

因为每个嵌套列表都只处理一次并在正确的时刻附加，所以最终的结构与序列化表示完全匹配。 

## Python 解决方案```python
# """
# This is the interface that allows for creating nested lists.
# You should not implement it, or speculate about its implementation
# """
# class NestedInteger:
#     def __init__(self, value=None):
#         """
#         If value is not specified, initializes an empty list.
#         Otherwise initializes a single integer equal to value.
#         """
#
#     def isInteger(self):
#         pass
#
#     def add(self, elem):
#         pass
#
#     def setInteger(self, value):
#         pass
#
#     def getInteger(self):
#         pass
#
#     def getList(self):
#         pass

class Solution:
    def deserialize(self, s: str) -> NestedInteger:
        # Single integer case
        if s[0] != '[':
            return NestedInteger(int(s))

        stack = []
        num_start = None

        for i, char in enumerate(s):

            if char == '[':
                stack.append(NestedInteger())

            elif char == '-' or char.isdigit():
                if num_start is None:
                    num_start = i

            elif char == ',' or char == ']':
                # Finish parsing a number
                if num_start is not None:
                    number = int(s[num_start:i])
                    stack[-1].add(NestedInteger(number))
                    num_start = None

                # Finish current nested list
                if char == ']' and len(stack) > 1:
                    completed = stack.pop()
                    stack[-1].add(completed)

        return stack[0]
```实现首先检查输入是否是普通整数。 这种特殊情况很重要，因为像这样的输入`"324"`不包含括号，因此不需要堆栈处理。 

堆栈存储部分构造的嵌套列表。 每次我们遇到`'['`，我们创建一个新的空`NestedInteger`并将其压入堆栈。 

数字解析是惰性处理的。 我们不是逐位构造整数，而是记录起始索引并等待，直到到达逗号或右括号。 在那一刻，我们知道数字令牌已经完成。 

当出现右括号时，当前的嵌套结构就完成了。 如果堆栈上有父列表，我们会弹出已完成的子列表并将其添加到父列表中。 

遍历结束时，堆栈恰好包含一个完全构造好的`NestedInteger`。 

## 解决方案```go
import "strconv"

/**
 * // This is the interface that allows for creating nested lists.
 * // You should not implement it, or speculate about its implementation
 * type NestedInteger struct {
 * }
 *
 * // Return true if this NestedInteger holds a single integer, rather than a nested list.
 * func (n NestedInteger) IsInteger() bool {}
 *
 * // Return the single integer that this NestedInteger holds, if it holds a single integer
 * func (n NestedInteger) GetInteger() int {}
 *
 * // Set this NestedInteger to hold a single integer.
 * func (n *NestedInteger) SetInteger(value int) {}
 *
 * // Set this NestedInteger to hold a nested list and adds a nested integer to it.
 * func (n *NestedInteger) Add(elem NestedInteger) {}
 *
 * // Return the nested list that this NestedInteger holds, if it holds a nested list
 * func (n NestedInteger) GetList() []*NestedInteger {}
 */

func deserialize(s string) *NestedInteger {

	if s[0] != '[' {
		num, _ := strconv.Atoi(s)
		result := &NestedInteger{}
		result.SetInteger(num)
		return result
	}

	stack := []*NestedInteger{}
	numStart := -1

	for i := 0; i < len(s); i++ {
		char := s[i]

		if char == '[' {

			stack = append(stack, &NestedInteger{})

		} else if char == '-' || (char >= '0' && char <= '9') {

			if numStart == -1 {
				numStart = i
			}

		} else if char == ',' || char == ']' {

			if numStart != -1 {
				num, _ := strconv.Atoi(s[numStart:i])

				newInteger := NestedInteger{}
				newInteger.SetInteger(num)

				stack[len(stack)-1].Add(newInteger)

				numStart = -1
			}

			if char == ']' && len(stack) > 1 {

				completed := stack[len(stack)-1]
				stack = stack[:len(stack)-1]

				stack[len(stack)-1].Add(*completed)
			}
		}
	}

	return stack[0]
}
```Go 实现遵循与 Python 解决方案相同的逻辑，但在一些特定于语言的细节上有所不同。 

Go不支持直接堆栈操作，因此切片被用作堆栈。 追加会推送元素，而切片则会删除顶部元素。 

由于 Go 区分值和指针，因此堆栈存储`*NestedInteger`指针。 这可以避免不必要的复制并确保修改影响正确的对象。 

字符串到整数的转换使用`strconv.Atoi`。 

与 Python 不同，Go 需要在将元素添加到嵌套列表之前显式创建整数对象。

 ## 边缘情况

 ### 单个整数输入

 像这样的输入`"324"`不包含括号。 假设每个输入都是列表的解析器可能会错误地初始化堆栈结构或完全失败。 

该实现显式检查第一个字符是否是`'['`。 如果没有，则直接构造并返回一个`NestedInteger`。 

### 负数

 负整数会带来解析复杂性，因为`'-'`不是数字，但仍然属于数字标记。 

实施处理`'-'`作为数字解析的一部分，并在转换前提取子字符串时包含它`int()`或者`strconv.Atoi()`。 

### 深度嵌套列表

 输入例如：```
[[[[[1]]]]]
```由于递归深度限制或重复的子字符串创建，很容易破坏递归解决方案。 

基于堆栈的迭代解决方案完全避免了递归，并在内存限制内处理任意嵌套深度。 

### 空嵌套列表

 案例如下：```
[[]]
```可能会暴露空列表被忽略或从未附加到其父级的错误。 

该实施创建了一个新的`NestedInteger`遇到时立即`'['`，甚至在添加任何元素之前。 这保证了空列表被正确保留。
