[LeetCode 第 356 题](https://leetcode.com/problems/line-reflection/)

 **难度：** 🟡 中等
 **Topics:** Array, Hash Table, Math

 ## 解决方案

 ## 问题理解

 该问题为我们提供了 2D 平面上的点的集合，其中每个点表示为`[x, y]`。 我们需要确定是否存在一条垂直线，即一条与 y 轴平行的线，以便反射穿过该线的每个点都会产生完全相同的点集。 

垂直反射线始终具有以下形式：$$x = c$$对于一些常数`c`。 

如果一个点`(x, y)`穿过这条线反射，其反射位置变为：$$(2c - x,\ y)$$重要的要求是在反映所有点之后，结果集必须与原始集完全匹配。 每个点都必须有一个相应的反射对应点。 直接位于反射线上的点是有效的，因为它们会反射到自身。 

输入大小可以大到`10^4`点，坐标的范围可以是`-10^8`到`10^8`。 这些限制立即告诉我们，`O(n^2)`在最坏的情况下，解决方案可能会变得太慢。 因此，我们需要一种更有效的方法，最好是线性或接近线性的时间。 

另一个微妙的细节是允许重复点。 这意味着实现必须正确处理重复项，而不会错误地拒绝有效反射。 

一些边缘情况很重要：

 - 多个点可能正好位于反射线上。 
- 重复点可能会出现多次。 
- 允许负坐标。 
- 反射线可能不会穿过任何实际点。 
- 使用浮点算法进行简单的中点计算可能会引入大坐标的精度问题。 

关键的挑战是有效地确定正确的反射轴并验证每个点都有一个有效的镜像对应点。 

## 方法

 ### 蛮力方法

 最直接的方法是尝试每一条可能的垂直反射线，并检查反射该线上的所有点是否保留了该集合。 

导出候选线的一种方法是获取每对点并计算它们的 x 坐标的中点。 由于反射对必须共享相同的中点，因此每条有效反射线必须等于这些中点之一。 

对于每个候选行：

 1. 反思每一点。 
2. 检查原集中是否存在反射点。 

使用哈希集允许在恒定时间内进行点查找，但仍然可能存在`O(n)`候选线，每次验证都需要`O(n)`，产生一个`O(n^2)`整体解决方案。 

这种方法是正确的，因为它显式地测试了每个可能的反射轴，但对于上限约束来说太慢了`10^4`点。 

### 最佳方法

 关键的观察是，如果存在有效的反射线，则所有反射点对必须沿着 x 轴共享相同的中点。 

假设最小的 x 坐标是`minX`最大的 x 坐标是`maxX`。 如果该集合是对称的，则反射线必须恰好位于它们之间的中间：$$x = \frac{minX + maxX}{2}$$这意味着我们不需要猜测反射线。 它由极值 x 唯一确定。 

我们不将中点存储为浮点数，而是存储：$$sum = minX + maxX$$那么对于每一个点`(x, y)`，其反映的对应部分必须是：$$(sum - x,\ y)$$对所有点使用哈希集可以进行恒定时间的存在检查。 

这将问题简化为计算后的单遍验证`minX`和`maxX`。

 ## 算法演练

 1. 迭代所有点以确定最小和最大 x 坐标。 

这两个值定义了唯一可能的反射轴。 如果该集合是对称的，则该线必须恰好位于最左边点和最右边点之间的中间。 
2. 计算反射和：$$sum = minX + maxX$$我们没有将反射线存储为浮点值，而是使用这个整数和来避免精度问题。 

1. 将每个点插入到一个哈希集中。 

在检查反射对应项是否存在时，哈希集允许恒定时间查找。 
2. 迭代每个点`(x, y)`。 

为了保持对称性，反射点：$$(sum - x,\ y)$$也必须存在于集合中。 

1. 如果缺少任何反射对应项，请立即返回`False`。 

单个缺失反射证明不存在有效的垂直反射线。 
2.如果所有点都通过检查，则返回`True`。 

### 为什么它有效

 该算法之所以有效，是因为任何有效的垂直反射线都必须恰好位于最小和最大 x 坐标之间的中间。 一旦该轴固定，每个点都必须在相应的反射位置有一个镜像对应点。 哈希集验证确保此条件适用于整个集合。 由于每个点都会根据唯一确定的反射轴进行检查，因此算法可以正确确定点集是否对称。 

## Python 解决方案```python
from typing import List

class Solution:
    def isReflected(self, points: List[List[int]]) -> bool:
        point_set = set()

        min_x = float("inf")
        max_x = float("-inf")

        for x, y in points:
            min_x = min(min_x, x)
            max_x = max(max_x, x)
            point_set.add((x, y))

        reflection_sum = min_x + max_x

        for x, y in points:
            reflected_point = (reflection_sum - x, y)

            if reflected_point not in point_set:
                return False

        return True
```该实现首先扫描所有点一次以计算最小和最大的 x 坐标。 同时，每个点都被插入到一个哈希集中以进行快速查找。 

变量`reflection_sum`商店`min_x + max_x`，这完全避免了浮点运算。 这很重要，因为坐标可能非常大，而整数算术可以保证精确的比较。 

第二个循环验证对称性。 对于每一点`(x, y)`，算法计算其反射对应项`(reflection_sum - x, y)`并检查它是否存在于集合中。 

如果缺少任何反射点，函数立即返回`False`。 否则，在所有检查通过后，该集合是对称的并且函数返回`True`。 

## 解决方案```go
func isReflected(points [][]int) bool {
	pointSet := make(map[[2]int]bool)

	minX := int(^uint(0) >> 1)
	maxX := -minX - 1

	for _, point := range points {
		x, y := point[0], point[1]

		if x < minX {
			minX = x
		}

		if x > maxX {
			maxX = x
		}

		pointSet[[2]int{x, y}] = true
	}

	reflectionSum := minX + maxX

	for _, point := range points {
		x, y := point[0], point[1]

		reflected := [2]int{reflectionSum - x, y}

		if !pointSet[reflected] {
			return false
		}
	}

	return true
}
```Go 实现遵循与 Python 版本相同的逻辑，但有一些特定于语言的细节。 

Go没有内置的元组类型，所以是固定大小的数组`[2]int`用作哈希映射键。 数组在 Go 中是可比较的，这使得它们成为有效的映射键。 

实现初始化`minX`和`maxX`手动，因为 Go 不提供内置的整数无穷大值。 表达式：```go
int(^uint(0) >> 1)
```计算平台的最大可能整数值。 

所有算术都使用整数，这可以避免精度问题并安全地处理约束中指定的坐标范围。

 ## 边缘情况

 ### 直接位于反射线上的点

 正好位于反射线上的点会反射到自身。 如果实现假设每个点必须与不同的第二个点配对，这很容易导致错误。 

例如：```
[[0,0], [1,0], [-1,0]]
```重点`(0,0)`当该线为`x = 0`。 

该实现自然地处理了这个问题，因为反射坐标计算产生相同的点，并且哈希集查找成功。 

### 重复点

 该问题明确允许重复点。 依赖于计数或对删除的简单实现可能会意外拒绝有效输入或双重处理点。 

例如：```
[[1,1], [-1,1], [1,1]]
```该解决方案通过将点存储在哈希集中并仅检查反射对应项是否存在来避免此问题。 重复的条目不会影响正确性。 

### 大坐标值

 坐标可以大到`10^8`，这意味着浮点中点计算可能会在某些语言或实现中引入精度问题。 

而不是计算：$$mid = (minX + maxX) / 2$$该算法存储：$$reflectionSum = minX + maxX$$并仅使用整数算术检查反射。 这保证了精确的比较并完全避免了与精度相关的错误。
