[LeetCode 第 322 题](https://leetcode.com/problems/coin-change/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划、广度优先搜索

 ## 解决方案

 ## 问题理解

 问题给了我们一个名为`coins`，其中每个元素代表一个硬币面额，以及一个称为`amount`，它代表我们想要构建的目标总和。 

我们的目标是确定准确制作所需的最小硬币数量`amount`。 我们可以无限次使用每种面额的硬币。 如果使用可用硬币无法形成目标数量，我们将返回`-1`。 

例如，如果`coins = [1,2,5]`和`amount = 11`，我们可以形成`11`使用两个`5`硬币和一枚`1`硬币，总共`3`硬币。 由于没有解决方案使用少于三个硬币，所以答案是`3`。 

重要的细节是我们没有计算不同组合的数量。 相反，我们正在最大限度地减少使用的硬币数量。 

这些约束告诉我们一些重要的事情：

 - 硬币种类最多，数量很少`12`- 目标金额可以大到`10^4`- 硬币本身的价值可能非常大

 相对较小的`amount`limit 强烈建议基于为所有金额构建答案的动态规划解决方案`0`到`amount`是可行的。 

一些边缘情况很重要：

 -`amount = 0`，答案应该总是`0`因为不需要硬币
 - 有些金额可能无法形成，例如`coins = [2]`和`amount = 3`- 硬币面额可能大于目标金额
 - 可能存在多种组合，因此我们必须确保选择使用最少硬币的组合

 简单的递归解决方案很容易变得非常慢，因为它反复重新计算相同的子问题。 这种重叠是动态规划在这里表现良好的关键原因。 

## 方法

 ### 蛮力方法

 一种简单的方法是递归地尝试每种可能的硬币组合。 

对于目标金额`A`，我们可以尝试减去每个硬币面额并递归地解决剩余的子问题。 例如：

 - 尝试使用硬币`1`，求解`A - 1`- 尝试使用硬币`2`，求解`A - 2`- 尝试使用硬币`5`，求解`A - 5`然后我们在所有可能性中取最小有效答案。 

这种方法是正确的，因为它探索了每种可能的硬币组合。 最终，如果存在解，递归就会发现它。 

然而，问题是许多子问题被重复重新计算。 例如，在求解时`amount = 11`，我们可以计算答案`amount = 6`来自不同递归路径的许多不同时间。 

这导致指数时间复杂度，对于`amount`值高达`10^4`。 

### 最优动态规划方法

 关键的观察结果是该问题具有最优子结构。 

如果我们已经知道形成较小金额所需的最小硬币数量，我们可以使用这些结果来计算较大的金额。 

定义：

-`dp[i]`= 达到金额所需的最少硬币数量`i`然后对于每个硬币：

 - 如果我们使用硬币`c`，剩余金额变为`i - c`- 如果我们已经知道形成的最佳方式`i - c`， 然后：`dp[i] = min(dp[i], dp[i - c] + 1)`这是有效的，因为任何金额的最佳解决方案`i`必须以最后的硬币结束。 

我们从少量到大量逐步构建解决方案，完全避免重复计算。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(k^金额) | O（金额）| 探索所有递归组合 |
 | 最优动态规划| O(数量 × n) | O（金额）| 使用以前的结果自下而上构建解决方案 |

 这里：

-`n`= 硬币面额的数量
 -`k`= 递归中的分支因子

 ## 算法演练

 1. 创建一个动态规划数组，名为`dp`尺寸的`amount + 1`。 

每个指标代表一个目标量。 存储的值代表形成该金额所需的最小硬币数量。 
2. 将所有条目初始化为一个非常大的值。 

这代表该金额目前无法达到。 
3. 设置`dp[0] = 0`。 

成型量`0`需要零币，这是基本情况。 
4. 迭代每个金额`1`到`amount`。 

对于每个金额，我们尝试使用所有可用的硬币面额。 
5. 对于每个币，检查它是否可以为当前金额做出贡献。 

如果`coin <= current_amount`，那么我们就可以考虑使用它了。 
6. 更新DP状态。 

如果我们使用这个硬币，剩余金额将变为：`current_amount - coin`自从`dp[current_amount - coin]`已经包含了较小数量的最佳解决方案，我们可以将其扩展为一枚硬币：`dp[current_amount] = min(dp[current_amount], dp[current_amount - coin] + 1)`7. 继续，直到处理完所有金额。 

到最后，`dp[amount]`包含所需的最小数量的硬币。 
8. 如果`dp[amount]`从未更新过，返回`-1`。 

否则，返回存储的最小值。 

### 为什么它有效

 该算法之所以有效，是因为每个金额的解决方案`i`必须以一些硬币结束`c`。 去掉最后的硬币剩下的金额`i - c`。 如果我们已经知道最优解`i - c`，然后再添加一枚硬币会产生一个有效的解决方案`i`。 

通过考虑所有可能的最终硬币并取最小值，我们保证`dp[i]`存储最优答案。 

由于我们处理的数量从小到大，因此每个所需的子问题在需要之前就已经解决了。 

## Python 解决方案```python
from typing import List

class Solution:
    def coinChange(self, coins: List[int], amount: int) -> int:
        # Large sentinel value representing unreachable states
        INF = amount + 1

        # dp[i] = minimum coins needed to make amount i
        dp = [INF] * (amount + 1)

        # Base case
        dp[0] = 0

        # Build solutions for all amounts
        for current_amount in range(1, amount + 1):
            for coin in coins:
                if coin <= current_amount:
                    dp[current_amount] = min(
                        dp[current_amount],
                        dp[current_amount - coin] + 1
                    )

        return dp[amount] if dp[amount] != INF else -1
```实现首先创建一个名为的哨兵值`INF`。 由于所需硬币的最大数量永远不会超过`amount`， 使用`amount + 1`安全地表示无法到达的状态。 

这`dp`数组存储每个金额所需的最小硬币数量`0`到`amount`。 

基本情况`dp[0] = 0`至关重要，因为它代表了所有未来计算的起点。 

外循环按升序迭代每个目标金额。 这保证了当我们计算时`dp[current_amount]`，所有较小的子问题都已解决。 

内循环尝试每种硬币面额。 如果硬币可以容纳当前数量，我们尝试使用以下方法改进解决方案：```python
dp[current_amount - coin] + 1
```这表示采用最知名的解决方案来计算剩余金额并添加当前硬币。 

最后，如果目标金额仍然无法达到，我们返回`-1`。 

## 解决方案```go
func coinChange(coins []int, amount int) int {
    inf := amount + 1

    dp := make([]int, amount+1)

    for i := 1; i <= amount; i++ {
        dp[i] = inf
    }

    dp[0] = 0

    for currentAmount := 1; currentAmount <= amount; currentAmount++ {
        for _, coin := range coins {
            if coin <= currentAmount {
                candidate := dp[currentAmount-coin] + 1

                if candidate < dp[currentAmount] {
                    dp[currentAmount] = candidate
                }
            }
        }
    }

    if dp[amount] == inf {
        return -1
    }

    return dp[amount]
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个显着的区别是显式数组初始化。 在 Go 中，切片默认为零值，因此我们手动初始化除`dp[0]`到哨兵值`inf`。 

Go 也不提供内置的`min`旧版本中的整数函数，因此我们在更新 DP 数组之前手动比较值。 

由于约束条件完全符合标准整数范围，因此这里不存在溢出问题。

 ## 边缘情况

 一个重要的边缘情况是当`amount = 0`。 一个常见的错误是返回`-1`因为没有使用硬币。 然而，正确答案是`0`，因为形成零数量需要零个硬币。 该实现通过初始化自然地处理这个问题`dp[0] = 0`。 

当不存在解决方案时，会发生另一个重要情况。 例如，`coins = [2]`和`amount = 3`。 一些实现意外地返回一个非常大的占位符值而不是`-1`。 该解决方案使用哨兵值`INF`并明确检查目标是否仍然无法到达。 

第三种边缘情况涉及比当前数量更大的硬币。 例如，如果当前金额是`3`硬币是`5`，减去将产生负指数。 该实现通过检查来防止这种情况：```
if coin <= current_amount:
```在尝试任何 DP 转换之前。 

一个微妙的例子涉及贪婪算法的失败。 例如：```
coins = [1,3,4]
amount = 6
```贪心策略会选择`4 + 1 + 1`，使用三个硬币。 最优解是`3 + 3`，仅使用两枚硬币。 动态规划正确评估所有可能性并保证最佳答案。
