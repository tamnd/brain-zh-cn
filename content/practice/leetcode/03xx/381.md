 ## 解决方案

 ## 问题理解

 该问题要求我们设计一个数据结构，称为`RandomizedCollection`其行为类似于多重集。 与普通集合不同，允许重复值。 数据结构必须支持三种操作：

 - 插入一个值
 - 删除某个值的一次出现
 - 返回一个随机元素

 关键要求是每个操作必须平均运行`O(1)`时间复杂度。 

随机行为尤其重要。 如果一个值在集合中多次出现，则它更有可能被返回`getRandom()`。 例如，如果集合包含`[1,1,2]`， 然后`1`应该以概率返回`2/3`， 尽管`2`应该以概率返回`1/3`。 

输入由一系列方法调用组成`RandomizedCollection`目的。 每个操作都会修改集合的内部状态或返回一个值。 输出反映了每个操作的返回值。 

这些约束告诉我们一些重要的事情：

 - 最多`2 * 10^5`将执行操作。 
- 值可以是非常大或非常小的整数。 
-`getRandom()`仅当集合非空时调用。 

操作计数足够大，任何线性时间操作都会太慢。 例如，在每次删除期间扫描集合将导致最坏情况的二次行为。 这立即表明我们需要基于哈希的结构和仔细的索引。 

一些边缘情况很重要：

 - 重复插入重复项
 - 当存在重复项时仅删除一次出现的情况
 - 删除最后一个剩余出现的值
 - 删除不存在的值
 - 删除期间交换元素后正确更新索引
 - 确保`getRandom()`自然地反映重复的频率

 在删除过程中处理重复索引时，幼稚的实现通常会失败。 正确维护索引映射是这个问题的核心挑战。 

## 方法

 ### 蛮力方法

 一个简单的实现将使用动态数组或列表来存储所有值。 

插入很容易，因为我们可以将值附加到列表的末尾。`getRandom()`也很简单，因为我们可以从数组中选择一个随机索引。 

困难出现在拆卸过程中。 要删除一个值，我们必须搜索数组以查找目标值的出现。 在最坏的情况下，这需要扫描整个集合，这会花费`O(n)`时间。 

虽然这种做法在逻辑上是正确的，但它违反了所有操作平均运行的要求`O(1)`时间。 

### 最佳方法

 关键的见解是数组提供高效的随机访问和随机选择，而哈希映射提供高效的查找。 

我们将这两种结构结合起来：

 - 动态数组存储所有元素。 
- 哈希映射跟踪每个值出现的所有索引。 

挑战是删除。 从数组中间删除一个元素通常会花费一些成本`O(n)`因为元素必须左移。 我们通过将目标元素与数组中的最后一个元素交换，然后删除最后一个位置来避免这种情况。 

为了支持重复项，每个值映射到一组索引而不是单个索引。 

这种设计允许：

 -`insert`在`O(1)`-`remove`平均而言`O(1)`-`getRandom`在`O(1)`因为所有操作只涉及哈希查找、集合更新、数组追加以及从数组末尾删除。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 插入`O(1)`， 消除`O(n)`， 随机的`O(1)`|`O(n)`| 仅使用数组，移除需要线性扫描 |
 | 最佳 | 平均的`O(1)`对于所有操作|`O(n)`| 使用数组加索引集的哈希映射 |

 ## 算法演练

 1. 维护一个动态数组，名为`values`。 

该数组存储当前集合中的每个元素，包括重复项。 使用数组有两个重要的优点：

 - 追加的是`O(1)`- 随机索引选择是`O(1)`2. 维护一个名为的哈希图`indices`。 

键是集合中的值。 

该值是一个包含该数字出现在其中的每个索引的集合`values`。 

例子：```
values  = [1, 1, 2]
indices = {
    1 -> {0, 1},
    2 -> {2}
}
```3. 插入时：

 - 检查该值是否已经存在于地图中并且仍然具有索引。 
- 将新值附加到末尾`values`。 
- 将新索引添加到相应的集合中`indices`。 
- 返回`true`如果这是第一次发生。 
4. 拆除过程中：

 - 首先检查该值是否存在。 
- 如果不存在，则返回`false`。 
- 否则，从值的索引集中删除一个索引。 

假设我们删除索引`remove_index`。 
5. 为避免移动元件：

 - 从数组中取出最后一个元素。 
- 将最后一个元素移动到`remove_index`。 
- 更新移动元素的索引集：

 - 删除旧的最后一个索引
 - 添加新索引
 6. 删除最后一个数组元素。 

由于不需要的元素现在位于末尾，因此将其删除`O(1)`。 
7. 如果某个值不再有任何索引，则将其从哈希映射中删除。 
8. 期间`getRandom()`：

 - 生成随机索引`0`到`len(values) - 1`- 返回该索引处的元素

 由于重复项占据多个数组位置，因此它们自然会按比例获得更高的概率。 

### 为什么它有效

 中心不变量是数组内每个元素的索引都在哈希映射中准确跟踪。 

每当元素在删除过程中由于交换而移动时，我们都会立即更新其记录的索引。 因此，哈希图和数组始终保持同步。 

自从`getRandom()`在阵列位置中均匀选择，并且重复项占据多个位置，概率分布自动匹配所需的频率。 

## Python 解决方案```python
import random
from collections import defaultdict
from typing import Dict, List, Set

class RandomizedCollection:

    def __init__(self):
        self.values: List[int] = []
        self.indices: Dict[int, Set[int]] = defaultdict(set)

    def insert(self, val: int) -> bool:
        is_new = len(self.indices[val]) == 0

        self.values.append(val)
        self.indices[val].add(len(self.values) - 1)

        return is_new

    def remove(self, val: int) -> bool:
        if not self.indices[val]:
            return False

        remove_index = self.indices[val].pop()

        last_value = self.values[-1]
        last_index = len(self.values) - 1

        self.values[remove_index] = last_value

        if remove_index != last_index:
            self.indices[last_value].remove(last_index)
            self.indices[last_value].add(remove_index)

        self.values.pop()

        if not self.indices[val]:
            del self.indices[val]

        return True

    def getRandom(self) -> int:
        return random.choice(self.values)

# Your RandomizedCollection object will be instantiated and called as such:
# obj = RandomizedCollection()
# param_1 = obj.insert(val)
# param_2 = obj.remove(val)
# param_3 = obj.getRandom()
```该实现使用两个核心结构。`self.values`存储当前集合中的所有元素。 重复项出现多次。 该数组支持恒定时间追加操作和高效的随机选择。`self.indices`将每个值映射到它在数组中出现的一组位置。 使用集合是因为​​集合中的插入和删除是平均的`O(1)`运营。 

在插入过程中，代码首先通过检查其索引集是否为空来检查该值是否已存在。 该值将附加到数组中，并将其新索引添加到集合中。 

删除逻辑是最重要的部分。 从集合中删除与目标值关联的一个索引。 然后将最后一个数组元素移动到空出的位置。 如果删除的元素还不是最后一个元素，则必须仔细更新移动值的索引。 

最后，弹出数组的最后一个元素。 如果某个值不再存在于集合中的任何位置，则其条目将从哈希映射中删除。`getRandom()`只是简单地委托给`random.choice`，它从底层数组中统一选择。 

## 解决方案```go
package main

import (
	"math/rand"
)

type RandomizedCollection struct {
	values  []int
	indices map[int]map[int]struct{}
}

func Constructor() RandomizedCollection {
	return RandomizedCollection{
		values:  []int{},
		indices: make(map[int]map[int]struct{}),
	}
}

func (this *RandomizedCollection) Insert(val int) bool {
	_, exists := this.indices[val]

	if !exists {
		this.indices[val] = make(map[int]struct{})
	}

	this.values = append(this.values, val)
	index := len(this.values) - 1
	this.indices[val][index] = struct{}{}

	return !exists
}

func (this *RandomizedCollection) Remove(val int) bool {
	indexSet, exists := this.indices[val]

	if !exists || len(indexSet) == 0 {
		return false
	}

	var removeIndex int
	for idx := range indexSet {
		removeIndex = idx
		break
	}

	delete(this.indices[val], removeIndex)

	lastIndex := len(this.values) - 1
	lastValue := this.values[lastIndex]

	this.values[removeIndex] = lastValue

	if removeIndex != lastIndex {
		delete(this.indices[lastValue], lastIndex)
		this.indices[lastValue][removeIndex] = struct{}{}
	}

	this.values = this.values[:lastIndex]

	if len(this.indices[val]) == 0 {
		delete(this.indices, val)
	}

	return true
}

func (this *RandomizedCollection) GetRandom() int {
	randomIndex := rand.Intn(len(this.values))
	return this.values[randomIndex]
}

/**
 * Your RandomizedCollection object will be instantiated and called as such:
 * obj := Constructor();
 * param_1 := obj.Insert(val);
 * param_2 := obj.Remove(val);
 * param_3 := obj.GetRandom();
 */
```Go 实现遵循与 Python 版本相同的算法结构，但存在一些特定于语言的差异。 

Go 没有内置的集合类型，因此集合是使用`map[int]struct{}`。 空结构消耗零存储空间，通常用于此模式。 

与Python不同`set.pop()`, Go 地图不支持直接任意删除。 我们迭代一次映射来检索任何索引。 

切片截断用于从数组中删除最后一个元素：```go
this.values = this.values[:lastIndex]
```随机选择使用`rand.Intn`，它生成所需范围内的随机整数。

 ## 边缘情况

 删除多次出现的值时会出现一种重要的边缘情况。 有缺陷的实现可能会意外删除所有出现的情况，而不是仅删除一个。 该解决方案避免了这一问题，因为每次删除操作都只针对值索引集中的一个存储索引进行操作。 

当被删除的元素已经是数组中的最后一个元素时，会发生另一种棘手的情况。 在这种情况下，盲目执行交换逻辑可能会破坏索引跟踪。 该实现具体检查是否`remove_index != last_index`在更新移动的索引之前，防止不必要的修改。 

第三个重要的边缘情况涉及删除最后剩余出现的值。 如果之后不删除哈希映射条目，则将来的操作可能会错误地认为该值仍然存在。 该实现检查索引集是否变空并完全删除映射条目。 

当删除过程中交换重复项时，会出现一个微妙但关键的问题。 考虑删除一个`1`而另一个`1`保留在数组的末尾。 不正确的索引更新可能会意外删除剩余的事件。 该算法仅仔细更新移动元素的索引，保留所有有效位置。 

最后，随机选择必须正确考虑重复项。 一些幼稚的实现尝试对唯一值进行随机化，这会产生不正确的概率。 通过将每次出现的情况直接存储在数组中，重复的频率自然会反映在随机分布中。
