[LeetCode 第 392 题](https://leetcode.com/problems/is-subsequence/)

 **难度：** 🟢简单
 **主题：** 两个指针、字符串、动态规划

 ## 解决方案

 ## 问题理解

 问题询问字符串是否`s`可以由字符串组成`t`通过删除一些字符`t`而不改变其余字符的顺序。 

子序列不要求字符相邻。 唯一的要求是相对顺序保持不变。 例如，`"abc"`是一个子序列`"ahbgdc"`因为我们可以选择角色`'a'`,`'b'`， 和`'c'`为了。 然而，`"axc"`不是子序列，因为字符`'x'`不以正确的顺序存在`t`。 

输入由两个字符串组成：

 -`s`, 候选子序列
 -`t`，我们要检查的源字符串

 预期输出是：

 -`true`如果中的每个字符`s`出现在`t`以相同的相对顺序
 -`false`否则

 限制很小：

 -`s.length <= 100`-`t.length <= 10^4`这些限制强烈表明线性扫描解决方案就足够了。 自从`s`很短，我们可以在遍历时高效地尝试将其字符一一匹配`t`。 

一些边缘情况很重要：

 -`s`为空，空字符串始终是任何字符串的子序列
 -`t`为空时`s`不是，匹配变得不可能
 - 重复的字符，例如`"aaa"`里面`"aaab"`- 字符出现顺序不正确，例如`"aec"`在`"abcde"`-`s`长于`t`，这会自动使匹配变得不可能

 预先了解这些情况有助于避免实施中的错误假设。 

## 方法

 ### 蛮力方法

 暴力解决方案会尝试每一个可能的子序列`t`并检查其中是否有一个等于`s`。 

为每个字符生成子序列`t`，我们要么包含它，要么排除它。 由于每个位置有两个选择，所以子序列的总数为`2^n`， 在哪里`n`的长度是`t`。 

生成每个子序列后，我们将其与`s`。 

这种方法是正确的，因为它详尽地探索了每一个可能的子序列。 如果`s`作为子序列存在，最终会被发现。 

然而，这种方法在计算上是不可行的。 即使对于中等大小的字符串，子序列的数量也会变得巨大。 自从`t`可以有长度`10^4`，在合理的时间或内存限制内生成所有子序列是不可能的。 

### 最优方法，两个指针

 关键的观察是我们不需要显式地生成子序列。 

相反，我们可以扫描`t`一次，同时跟踪有多少个字符`s`我们已经匹配成功了。 

我们使用两个指针：

 - 一个指针`s`- 一个指针`t`当我们穿过`t`，每当我们找到与当前字符匹配的字符时`s`，我们将指针前进`s`。 

如果我们到达终点`s`，那么每个字符都已按顺序匹配，所以`s`是一个子序列。 

这是有效的，因为子序列只需要相对排序，而不是连续性。 一次从左到右的扫描足以验证该顺序。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n * n) | O(2^n * n) | O(2^n) | O(2^n) | 生成的每个子序列`t`|
 | 最佳| O(n + m) | O(1) | O(1) | 使用两个指针的单遍 |

 这里：

-`n = len(t)`-`m = len(s)`## 算法演练

 ### 最优两指针算法

 1.初始化两个指针，`i`对于字符串`s`和`j`对于字符串`t`。 

指针`i`跟踪我们需要匹配的下一个字符`s`。 指针`j`扫描通过`t`。 
2.开始遍历`t`从左到右。 

我们检查每个字符`t`恰好一次，因为子序列仅取决于排序。 
3.比较`s[i]`和`t[j]`。 

如果字符匹配，我们前进`i`因为我们成功地找到了下一个所需的字符`s`。 
4、永远前进`j`。 

无论字符是否匹配，我们都会继续扫描`t`因为未来的角色仍然可能有助于完成子序列。 
5. 继续直到：

 -`i == len(s)`，表示中的每个字符`s`已匹配
 -`j == len(t)`，意味着我们筋疲力尽`t`6.返回是否`i == len(s)`。 

如果为真，则整个子序列按顺序匹配。 

### 为什么它有效

 该算法保持了索引之前的所有字符的不变性`i`在`s`已经在该部分内以正确的顺序匹配`t`扫描到此为止。 

每当找到匹配的字符时，前进`i`保留了这个不变量。 自从`t`从左到右扫描，保证匹配字符的相对顺序。 

如果`i`到达末尾`s`，那么每个字符都已按顺序匹配，证明`s`是一个子序列`t`。 

## Python 解决方案```python
class Solution:
    def isSubsequence(self, s: str, t: str) -> bool:
        s_index = 0
        t_index = 0

        while s_index < len(s) and t_index < len(t):
            if s[s_index] == t[t_index]:
                s_index += 1

            t_index += 1

        return s_index == len(s)
```实现直接遵循二指针算法。 

变量`s_index`跟踪我们正在尝试匹配的当前字符`s`。 变量`t_index`扫描通过`t`。 

在循环内，我们比较当前字符：```python
if s[s_index] == t[t_index]:
```当他们匹配时，我们前进`s_index`因为我们成功匹配了另一个字符`s`。 

无论比赛是否发生，我们都会移动`t_index`前进，因为我们继续寻找`t`。 

循环在以下任一情况下停止：

 - 中的所有角色`s`已匹配
 - 我们到达了终点`t`最后，return 语句检查整个子序列是否匹配。 

## 解决方案```go
func isSubsequence(s string, t string) bool {
    sIndex := 0
    tIndex := 0

    for sIndex < len(s) && tIndex < len(t) {
        if s[sIndex] == t[tIndex] {
            sIndex++
        }

        tIndex++
    }

    return sIndex == len(s)
}
```Go 实现与 Python 版本几乎相同。 

Go 中的字符串内部是字节切片。 由于该问题只保证小写英文字母，因此直接使用索引`s[i]`和`t[j]`是安全的，因为每个字符占用一个字节。 

这里不需要对 Unicode 字符进行特殊处理。 

Go 不区分`nil`和空字符串在这种情况下，所以空字符串自然可以正确地与指针逻辑一起工作。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n + m) | 每个指针最多在其字符串中移动一次 |
 | 空间| O(1) | O(1) | 仅使用常量额外变量 |

 该算法对两个字符串执行一次传递。 每个字符最多检查一次，从而使运行时间呈线性。 

没有分配与输入大小成比例的额外数据结构，因此空间复杂度保持不变。 

## 后续讨论

 后续询问如果有很多传入查询会发生什么`s`，可能有数十亿个，同时`t`保持固定。 

在这种情况下，重复扫描所有`t`变得低效。 

更好的策略是预处理`t`。 

我们可以构建从每个字符到该字符出现的索引排序列表的映射`t`。 

例如：```
t = "ahbgdc"

a -> [0]
h -> [1]
b -> [2]
g -> [3]
d -> [4]
c -> [5]
```对于每个查询字符串`s`，我们使用二分查找来查找每个字符的下一个有效出现位置。 

这减少了每个查询：```
O(len(t))
```粗略地：```
O(len(s) * log(len(t)))
```在处理许多后续检查时，速度明显更快。

 ## 边缘情况

 ### 空子序列

 空字符串始终是任何字符串的子序列，因为我们可以删除所有字符而不保留任何内容。 

如果实现假设至少存在一个字符，那么这种情况很容易被错误处理。 在此解决方案中，循环条件在以下情况下立即失败：`s`为空，最后检查：```
s_index == len(s)
```正确返回`True`。 

### 源字符串为空

 如果`t`是空的但是`s`不是，匹配是不可能的，因为没有可用于形成子序列的字符。 

该实现自然地处理了这个问题，因为遍历循环永远不会开始，留下`s_index`不变。 由于并非所有字符都匹配，因此该函数返回`False`。 

### 字符存在但顺序错误

 一个常见的错误是仅检查所有字符是否存在于`t`。 

例如：```
s = "aec"
t = "abcde"
```所有字符均出现，但未按所需顺序排列。 

两指针方法避免了这个错误，因为它从左到右扫描并且从不向后移动。 一旦扫描通过`'e'`，以后无法匹配`'c'`，正确返回`False`。
