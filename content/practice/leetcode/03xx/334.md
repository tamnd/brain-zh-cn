 # LeetCode 334 - 增加三元组子序列

 ## 问题理解

 该问题要求我们确定一个数组是否包含三个数字，这三个数字形成严格递增的子序列。 更具体地说，我们需要找到索引`i`,`j`， 和`k`这样：

 -`i < j < k`-`nums[i] < nums[j] < nums[k]`索引必须按顺序出现，这意味着我们不允许重新排列数组。 我们只需要确定这样的三元组是否存在，而不返回实际的索引或值。 

输入是一个整数数组`nums`，预期输出是一个布尔值：

 - 返回`true`如果至少存在一个递增三元组
 - 返回`false`否则

 约束条件很重要：

 - 该数组最多可以包含`5 * 10^5`元素
 - 值的范围可以是`-2^31`到`2^31 - 1`这些限制立即告诉我们，低效的算法将无法工作。 任何解决方案`O(n^2)`或者`O(n^3)`对于最大的输入来说，复杂性将太慢。 后续行动明确要求`O(n)`时间和`O(1)`空间解决方案，强烈建议采用贪婪或状态跟踪方法。 

需要考虑一些重要的边缘情况：

 - 少于三个元素的数组永远不能包含三元组
 - 应该返回严格递减的数组`false`- 具有重复值的数组需要小心处理，因为比较必须严格递增
 - 最优子序列可能不使用数组中的最小值或最大值
 - 在几个误导性候选者之后可能会出现有效的三元组

 例如，在`[2,1,5,0,4,6]`，序列`1 < 4 < 6`即使数组稍后包含较小的值，也会形成有效的三元组。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每个可能的三元组`(i, j, k)`。 

我们可以使用三个嵌套循环：

 - 第一个循环选择`i`- 第二次循环选择`j > i`- 第三次循环选择`k > j`对于每个三元组，我们验证是否：```
nums[i] < nums[j] < nums[k]
```如果我们找到这样的三元组，我们就会返回`true`。 如果检查了所有三元组但没有一个满足条件，我们返回`false`。 

这种方法是正确的，因为它详尽地检查了三个有序索引的每种可能的组合。 然而，对于大输入来说，速度非常慢。 

高达`500,000`元素，一个`O(n^3)`算法完全不切实际。 

### 最优贪心法

 关键的见解是我们不需要记住每个候选子序列。 我们只需要跟踪递增三元组的第一个和第二个元素的最佳候选者。 

我们维护两个变量：

 -`first`，迄今为止看到的最小值
 -`second`，最小值大于`first`当我们扫描数组时：

 - 如果当前数字小于或等于`first`，我们更新`first`- 否则如果数字小于或等于`second`，我们更新`second`- 否则，我们找到一个比两者都大的数字`first`和`second`，这意味着存在递增三元组

 这是有效的，因为保持`first`和`second`尽可能小可以最大化以后找到更大的第三个元素的机会。 

例如：```
nums = [2,1,5,0,4,6]
```我们逐步改进我们的候选人：

 -`first = 1`-`second = 5`- 然后`first = 0`- 然后`second = 4`- 最后`6 > 4`，所以存在三元组

 该解决方案以线性时间运行并使用恒定的额外空间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n3) | O(1) | O(1) | 检查每个可能的三元组 |
 | 最佳 | O(n) | O(1) | O(1) | 贪婪地跟踪最小的有效对 |

 ## 算法演练

 1.初始化两个变量，`first`和`second`，到正无穷大。 

这些变量代表迄今为止遇到的最小和第二小的值，它们可以形成递增三元组的开始。 
2. 迭代数组中的每个数字。 

我们从左到右处理元素，因为索引顺序很重要。 
3. 如果当前数量小于或等于`first`， 更新`first`。 

这意味着我们找到了潜在三元组中最小值的更好候选者。 
4. 否则，如果当前数量小于或等于`second`， 更新`second`。 

此时，我们已经知道数字大于`first`，所以它可以作为三元组的第二个元素。 我们保留`second`尽可能小，以最大化未来的机会。 
5. 否则，当前数字大于两者`first`和`second`。 

这意味着我们发现：```
first < second < current
```由于元素是按顺序处理的，因此索引的顺序也是正确的。 我们可以立即返回`true`。 
6. 如果循环结束没有找到这样的数字，则返回`false`。 

### 为什么它有效

 该算法保持了一个重要的不变量：

 -`first`始终是迄今为止看到的最小值
 -`second`始终是大于的最小值`first`通过贪婪地最小化这两个值，我们最大化了后面的元素成为递增三元组的第三个值的机会。 

每当我们遇到一个比两者都大的数字时，我们就知道存在一个有效的子序列。 

## Python 解决方案```python
from typing import List
import math

class Solution:
    def increasingTriplet(self, nums: List[int]) -> bool:
        first = math.inf
        second = math.inf

        for num in nums:
            if num <= first:
                first = num
            elif num <= second:
                second = num
            else:
                return True

        return False
```实现从初始化开始`first`和`second`到无穷大。 这确保了数组中的任何实数最初都会替换它们。 

迭代期间：

 - 如果`num <= first`，我们更新`first`- 否则如果`num <= second`，我们更新`second`- 否则，我们找到了有效的第三个元素

 使用`<=`而不是`<`很重要。 重复值不能形成严格递增的序列，因此重复值应替换现有候选值，而不是扩展子序列。 

一旦找到有效的三元组，算法就会立即停止，从而保持运行时的效率。 

## 解决方案```go
import "math"

func increasingTriplet(nums []int) bool {
    first := math.MaxInt
    second := math.MaxInt

    for _, num := range nums {
        if num <= first {
            first = num
        } else if num <= second {
            second = num
        } else {
            return true
        }
    }

    return false
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一些 Go 的具体细节值得注意：

 -`math.MaxInt`使用而不是无穷大
 - Go 切片自然安全地处理空数组
 - 整数溢出不是问题，因为我们只执行比较
 - 的`range`循环提供了一种迭代切片的干净方法

 ## 边缘情况

 ### 长度小于三的数组

 少于三个元素的数组永远不可能包含有效的三元组。 幼稚的实现可能会忘记这一点，并由于不正确的初始化或比较逻辑而意外返回 true。 

当前的实现自然会处理这种情况，因为循环永远找不到有效的第三个元素，因此它返回`false`。 

### 重复值

 该序列必须严格递增，这意味着不能重复使用相同的值。 

例如：```
[1,1,2,2,3]
```一个有缺陷的实现仅使用`<`更新期间的比较可能会错误地将重复项视为三元组的进展。 

该解决方案通过使用来避免此问题`<=`更新时`first`和`second`。 这可确保重复项替换现有候选项，而不是扩展子序列。 

### 重置最小候选者

 当较小的值出现在较大的第二个候选值之后时，就会出现一种微妙的情况。 

例如：```
[2,1,5,0,4,6]
```看到后`1`和`5`，我们后来遇到`0`。 幼稚的实现可能会认为序列被破坏并错误地丢弃进度。 

贪心策略通过仅更新来处理这个问题`first`同时保留以后形成更好配对的可能性。 最终，`4`成为新的`second`， 和`6`完成三连音。
