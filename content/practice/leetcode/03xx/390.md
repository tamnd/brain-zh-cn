 ## 解决方案

 ## 问题理解

 这个问题给了我们一个排序列表，其中包含来自`1`到`n`。 我们不断地交替方向消除数字，直到只剩下一个数字。 

消除过程是这样的：

 - 在第一遍中，我们从左向右移动并删除第一个数字以及此后的所有其他数字。 
- 在第二遍中，我们反转方向并从右向左移动，再次删除第一个遇到的数字和所有其他数字。 
- 我们继续交替方向，直到只剩下一个数字。 

目标是返回最终剩余的数字。 

例如，如果`n = 9`，序列演变如下：```
[1,2,3,4,5,6,7,8,9]
[2,4,6,8]
[2,6]
[6]
```答案是`6`。 

输入由单个整数组成`n`， 在哪里`1 <= n <= 10^9`。 上限非常重要，因为它立即告诉我们显式构造和修改数组是不切实际的。 任何从大小不超过 10 亿的列表中重复删除元素的算法都会太慢并且占用大量内存。 

该问题保证了`n`总是至少`1`，因此列表中始终至少有一个数字。 这消除了处理空输入情况的需要。 

尽早考虑几个边缘情况很重要：

 - 当`n = 1`，答案很简单`1`。 
- 非常大的值，例如`10^9`需要有效的数学解决方案。 
- 从右到左消除时奇数和偶数长度的行为不同，这是最常见的错误来源之一。 
- 重复减半意味着我们需要仔细跟踪每次通过后幸存序列的变化。 

## 方法

 ### 蛮力方法

 简单的模拟将显式地构建列表`[1, 2, 3, ..., n]`并在交替方向的同时重复删除所有其他元素。 

例如：

 - 从完整列表开始。 
- 删除交替索引处的元素。 
- 反转方向。 
- 重复直到只剩下一个元素。 

这种方法在概念上很简单，并且直接遵循问题陈述，因此可以保证产生正确的答案。 

然而，对于限制而言，它太慢了。 构建尺寸列表`10^9`在内存限制内已经是不可能的了。 即使对于较小的输入，重复删除元素也会产生昂贵的操作，因为必须复制或移动列表的大部分内容。 

因此，暴力解决方案无法扩展。 

### 最优数学模拟

 关键的见解是我们根本不需要存储实际列表。 

每轮淘汰赛结束后：

 - 剩余的数字构成等差数列。 
- 每轮幸存数字之间的间距加倍。 
- 每轮剩余数字减半。 

我们不跟踪所有幸存值，而是只跟踪：

 - 第一个剩余的号码，称为`head`- 剩余数字之间的差距，称为`step`- 剩余元素的数量
 - 当前消除方向

 这是有效的，因为每次通过后的剩余序列总是完全规则的。 

例如：```
[2,4,6,8]
```可以表示为：

 -`head = 2`-`step = 2`再次消除后：```
[2,6]
```变成：

 -`head = 2`-`step = 4`通过数学更新这些变量，我们可以在对数时间内确定最终答案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) 到 O(n²) | O(n) | 显式模拟从列表中删除 |
 | 最佳| O(log n) | O(1) | O(1) | 仅跟踪算术级数状态 |

 ## 算法演练

 ### 最优算法

 1.初始化四个变量：

 -`head = 1`, 第一个剩余数
 -`step = 1`，连续存活数之间的差
 -`remaining = n`，仍然存活的元素数量
 -`left_to_right = True`，消除方向
 2. 当剩下一个以上号码时，一次进行一轮淘汰赛。 
3. 如果我们从左向右消除，第一个剩余的数字总是会改变。 

例如：```
[1,2,3,4,5,6] -> [2,4,6]
```新的头变成了`head + step`。 
4. 如果我们从右向左消除，只有当剩余元素的数量为奇数时，头部才会改变。 

考虑：```
[2,4,6,8]
```从右边消除得到：```
[2,6]
```头还留着`2`。 

但：```
[2,4,6]
```变成：```
[4]
```这里头部发生变化，因为计数是奇数。 
5. 每当头部应该前进时，更新：```
head += step
```6. 每轮淘汰赛结束后：

 - 剩下一半的数字：```
remaining //= 2
```- 幸存数字之间的距离加倍：```
step *= 2
```- 反转方向：```
left_to_right = not left_to_right
```7. 继续下去，直到只剩下一个数字。 
8. 返回`head`。 

### 为什么它有效

 该算法之所以有效，是因为在每一轮淘汰之后，幸存的数字总是形成一个算术级数。 我们不需要存储每个幸存的数字，我们只需要知道：

 - 进展开始的地方，
 - 连续元素之间的距离有多远，
 - 还剩下多少元素。 

消除规则准确地确定了级数的第一个元素何时发生变化。 由于每轮将剩余数字减半，因此该过程在对数时间内完成。 

## Python 解决方案```python
class Solution:
    def lastRemaining(self, n: int) -> int:
        head = 1
        step = 1
        remaining = n
        left_to_right = True

        while remaining > 1:
            if left_to_right or remaining % 2 == 1:
                head += step

            remaining //= 2
            step *= 2
            left_to_right = not left_to_right

        return head
```该实现直接反映了前面描述的数学模拟。 

变量`head`存储当前序列中第一个幸存的数字。 变量`step`存储连续幸存数字之间的间距。 

在循环的每次迭代期间，我们确定头部是否应该向前移动。 在从左到右消除过程中，它总是前进，因为第一个元素被删除。 从右向左消除时，仅当剩余计数为奇数时才前进。 

处理一轮后，我们将剩余元素的数量减半，因为所有其他数字都被删除。 然后，我们将步长加倍，因为幸存的数字之间的距离增加了一倍。 

方向标志在每一轮后交替，直到只剩下一个数字。 

## 解决方案```go
func lastRemaining(n int) int {
    head := 1
    step := 1
    remaining := n
    leftToRight := true

    for remaining > 1 {
        if leftToRight || remaining%2 == 1 {
            head += step
        }

        remaining /= 2
        step *= 2
        leftToRight = !leftToRight
    }

    return head
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

由于 Go 整数是固定宽度的，因此值得考虑溢出。 然而，问题的约束`n <= 10^9`将所有中间值安全地保持在 Go 的范围内`int`在现代平台上输入。 

与 Python 不同，Go 需要显式变量声明和使用`:=`用于初始化。 布尔方向标志使用以下方式切换`!leftToRight`。

 ## 边缘情况

 一个重要的边缘情况是`n = 1`。 粗心的实现可能会不必要地进入消除循环或错误地删除唯一的元素。 在这个实现中，循环条件是`while remaining > 1`，所以算法立即返回`1`而不执行任何操作。 

当剩余计数为奇数时，另一个重要的边缘情况发生在从右到左消除期间。 这是问题中最棘手的部分之一。 例如：```
[2,4,6]
```从右向左消除后变为：```
[4]
```头部发生变化，因为第一个元素在消除模式期间被间接删除。 实现正确地处理了这个问题：```
if left_to_right or remaining % 2 == 1:
```第三个重要的边缘情况涉及极大的值，例如`n = 10^9`。 由于内存限制，任何显式存储数组的实现都会失败。 该解决方案完全避免了构建列表，而是仅跟踪四个整数变量，从而使其能够有效地处理最大约束。
