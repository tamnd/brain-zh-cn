 # LeetCode 327 - 范围和的计数

 ## 问题理解

 这个问题要求我们计算有多少子数组的总和落在给定的包含范围内`[lower, upper]`。 

范围总和`S(i, j)`表示索引中所有元素的总和`i`通过索引`j`在数组中。 对于每一个可能的对`(i, j)`在哪里`i <= j`，我们计算子数组和并检查它是否位于`lower`和`upper`。 

输入包括：

 - 整数数组`nums`- 两个整数`lower`和`upper`预期输出是总和满足以下条件的有效子数组的总数：$$lower \leq S(i, j) \leq upper$$约束条件极其重要：

 -`nums.length`可以大到`10^5`- 数组值可以是非常大的正整数或负整数
 - 答案适合 32 位整数

 这些限制立即告诉我们，`O(n^2)`解决方案将不够快。 和`10^5`元素，大致有`10^{10}`子数组，这远远超出了实际运行时的限制。 

负数的存在也很重要。 如果所有数字都是非负数，我们可能会使用滑动窗口技术。 然而，由于负值可能会不可预测地减少运行总和，因此滑动窗口方法在这里不起作用。 

一些边缘情况尤其重要：

 - 包含负值的数组
 - 包含零的数组
 - 非常大的正整数和负整数
 - 每个子数组都有效的情况
 - 没有子数组有效的情况
 - 单元素数组
 - 重复的前缀和

 正确的解决方案必须有效地计算有效子数组的总和，而无需显式枚举每个子数组。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每个可能的子数组。 

我们可以生成所有`(i, j)`对，计算总和`nums[i:j+1]`，并检查总和是否在范围内`[lower, upper]`。 

一个简单的实现会从头开始重新计算每个子数组的总和，从而导致`O(n^3)`复杂。 使用前缀和将其改进为`O(n^2)`因为每个子数组的总和可以在常数时间内计算出来。 

这个想法是：

 - 构建前缀和数组
 - 每对`(i, j)`，计算：$$S(i, j) = prefix[j+1] - prefix[i]$$- 计算有多少个满足范围条件

 这种方法是正确的，因为它只检查每个可能的子数组一次。 

然而，它仍然太慢`n = 10^5`。 

### 最优方法，前缀和+改进的归并排序

 关键的见解是将问题转化为计算前缀和对的数量。 

定义：$$prefix[k] = nums[0] + nums[1] + \dots + nums[k-1]$$那么任意子数组的和就变成：$$S(i, j) = prefix[j+1] - prefix[i]$$我们需要数对`(i, j)`这样：$$lower \leq prefix[j] - prefix[i] \leq upper$$重新排列：$$prefix[j] - upper \leq prefix[i] \leq prefix[j] - lower$$因此，对于每个前缀和，我们需要计算有多少个较早的前缀和落在特定范围内。 

这成为排序前缀和的计数问题。 

修改后的合并排序效果很好，因为：

 - 归并排序自然地将数组分成已排序的两半
 - 在合并过程中，我们可以使用两个指针有效地计算有效的跨半对
 - 每级递归在线性时间内处理所有元素
 - 总复杂度变为`O(n log n)`这对于约束来说足够有效。

 ## 算法演练

 1. 首先，构建一个前缀和数组。 

我们创建一个数组`prefix`在哪里：$$prefix[i]$$存储第一个的总和`i`元素。 

我们初始化`0`因为子数组可以从索引开始`0`。 
2. 将问题转化为计算前缀和对的问题。 

对于每对`(i, j)`在哪里`i < j`，子数组和为：$$prefix[j] - prefix[i]$$我们需要这个值介于`lower`和`upper`。 
3. 对前缀和数组应用合并排序。 

合并排序递归地将数组分成两个已排序的两半。 

在组合两半时，我们计算有效对，其中：

 - 左前缀和来自左半部分
 - 右前缀和来自右半部分
 4. 对于每个左侧前缀和，在右半部分找到有效窗口。 

假设我们正在检查左前缀和：$$prefix[i]$$我们需要所有右侧前缀和满足：$$lower \leq prefix[j] - prefix[i] \leq upper$$重新排列：$$prefix[i] + lower \leq prefix[j] \leq prefix[i] + upper$$5. 使用两个指针跟踪有效范围。 

由于右半部分已经排序：

 - 指针`start`移动直到值变得足够大
 - 指针`end`移动直到值超过上限

 然后：$$end - start$$给出当前左前缀和的有效右前缀和的数量.
 6. 继续计算所有左侧前缀和。 

由于两半已排序，因此指针仅向前移动。 这使计数步骤保持线性。 
7. 合并已排序的两半。 

计数后，我们执行合并排序的正常合并步骤，以维持更高递归级别的排序顺序。 
8. 返回所有递归调用累积的总计数。 

### 为什么它有效

 正确性来自于前缀和变换。 

每个子数组和可以表示为两个前缀和之间的差。 修改后的合并排序保证当两个前缀和在递归期间属于不同的一半时，每个有效对都被精确计数一次。 

由于每个递归级别都保持排序顺序，因此两指针扫描可以在线性时间内正确计算所有有效对。 

## Python 解决方案```python
from typing import List

class Solution:
    def countRangeSum(self, nums: List[int], lower: int, upper: int) -> int:
        prefix_sums = [0]

        for num in nums:
            prefix_sums.append(prefix_sums[-1] + num)

        def merge_sort(left: int, right: int) -> int:
            if right - left <= 1:
                return 0

            mid = (left + right) // 2

            count = merge_sort(left, mid)
            count += merge_sort(mid, right)

            start = mid
            end = mid

            for i in range(left, mid):
                while start < right and prefix_sums[start] - prefix_sums[i] < lower:
                    start += 1

                while end < right and prefix_sums[end] - prefix_sums[i] <= upper:
                    end += 1

                count += end - start

            merged = []
            p1 = left
            p2 = mid

            while p1 < mid and p2 < right:
                if prefix_sums[p1] <= prefix_sums[p2]:
                    merged.append(prefix_sums[p1])
                    p1 += 1
                else:
                    merged.append(prefix_sums[p2])
                    p2 += 1

            while p1 < mid:
                merged.append(prefix_sums[p1])
                p1 += 1

            while p2 < right:
                merged.append(prefix_sums[p2])
                p2 += 1

            prefix_sums[left:right] = merged

            return count

        return merge_sort(0, len(prefix_sums))
```实现首先构建前缀和数组。 最初的`0`是必不可少的，因为它允许从索引开始的子数组`0`自然地被代表。 

递归`merge_sort`函数对前缀和数组的范围进行操作。 如果范围包含的元素少于两个，则没有可计数的对。 

递归将数组分成两半。 每半部分都会被递归处理，以便首先计算这些半部分内的所有有效对。 

重要的逻辑发生在合并阶段。 对于左半部分中的每个前缀和，两个指针确定右半部分中差异所在的有效区间`[lower, upper]`。 

由于右半部分已排序，因此指针仅向前移动。 这避免了重复扫描，并使每个合并级别的运行时间保持线性。 

最后，标准合并步骤恢复排序顺序，以便更高的递归调用可以继续使用高效的两指针计数。 

## 解决方案```go
func countRangeSum(nums []int, lower int, upper int) int {
	prefixSums := make([]int64, len(nums)+1)

	for i, num := range nums {
		prefixSums[i+1] = prefixSums[i] + int64(num)
	}

	var mergeSort func(left, right int) int

	mergeSort = func(left, right int) int {
		if right-left <= 1 {
			return 0
		}

		mid := (left + right) / 2

		count := mergeSort(left, mid)
		count += mergeSort(mid, right)

		start := mid
		end := mid

		for i := left; i < mid; i++ {
			for start < right &&
				prefixSums[start]-prefixSums[i] < int64(lower) {
				start++
			}

			for end < right &&
				prefixSums[end]-prefixSums[i] <= int64(upper) {
				end++
			}

			count += end - start
		}

		merged := make([]int64, 0, right-left)

		p1 := left
		p2 := mid

		for p1 < mid && p2 < right {
			if prefixSums[p1] <= prefixSums[p2] {
				merged = append(merged, prefixSums[p1])
				p1++
			} else {
				merged = append(merged, prefixSums[p2])
				p2++
			}
		}

		for p1 < mid {
			merged = append(merged, prefixSums[p1])
			p1++
		}

		for p2 < right {
			merged = append(merged, prefixSums[p2])
			p2++
		}

		copy(prefixSums[left:right], merged)

		return count
	}

	return mergeSort(0, len(prefixSums))
}
```Go 实现与 Python 解决方案非常相似，但有一些特定于语言的注意事项。 

最重要的区别是使用`int64`对于前缀和。 由于前缀和可能会超出 32 位整数的范围，因此使用`int64`避免溢出问题。 

使用 Go 切片代替 Python 列表。 在合并期间，会分配一个临时片，然后将其复制回原始前缀和片。 

与 Python 不同，Go 不直接支持嵌套列表赋值，因此`copy`函数用于覆盖相关范围。

 ## 边缘情况

 ### 单元素数组

 单元素数组是最小的有效输入大小。 当实现假设至少有两个元素或无法正确初始化前缀和数组时，经常会出现错误。 

此实现可以自然地处理这种情况，因为前缀和数组始终以初始值开头`0`，允许将单元素子数组表示为两个前缀和之间的差异。 

### 具有许多重复前缀和的数组

 数组如`[0, 0, 0]`生成重复的前缀和：```
[0, 0, 0, 0]
```如果合并逻辑错误地处理相等值或指针移动，这可能会导致计数错误。 

该实现可以正确处理重复项，因为合并步骤保留排序顺序，并且计数逻辑仔细使用包含边界：

 -`< lower`-`<= upper`This guarantees exact counting without missing or double-counting equal prefix sums.

 ### 大正数和负数

 The constraints allow values near the 32-bit integer limits. Prefix sums can exceed standard integer ranges if accumulated repeatedly.

 The Python solution handles this automatically because Python integers have arbitrary precision.

 Go 解决方案明确使用`int64`用于前缀和，以防止累加和减法运算期间溢出。
