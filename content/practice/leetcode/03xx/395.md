[LeetCode 第 395 题](https://leetcode.com/problems/longest-substring-with-at-least-k-repeating-characters/)

 **难度：** 🟡 中等
 **主题：** 哈希表、字符串、分而治之、滑动窗口

 ## 解决方案

 ## 问题理解

 该问题要求我们找到每个字符至少出现的最长子串的长度`k`次。 

子字符串是原始字符串内的连续字符序列。 对于任何候选子串，我们必须验证该子串内的每个不同字符的频率大于或等于`k`。 

例如，如果`s = "aaabb"`和`k = 3`, 子串`"aaa"`是有效的，因为`'a'`正好出现 3 次。 然而，`"aaabb"`无效，因为`'b'`仅出现2次。 

输入包括：

 - 一根绳子`s`仅包含小写英文字母
 - 一个整数`k`输出是一个整数，表示有效子字符串的最大长度。 

约束条件很重要：

 -`1 <= s.length <= 10^4`- 字符串仅包含小写英文字母
 -`1 <= k <= 10^5`该字符串仅包含小写英文字母，这意味着最多有 26 个不同的字符。 这是一个重要的观察结果，可以实现有效的解决方案。 

一些边缘情况很重要：

 - 如果`k > len(s)`，没有子串可以满足条件
 - 如果每个字符至少已经出现`k`次，整个字符串有效
 - 具有许多低频分隔符的字符串可以将搜索空间分割成更小的独立区域
 - 非常小的字符串，例如长度1，需要小心处理

 检查每个子字符串的简单解决方案会太慢，因为有`O(n^2)`子串。 

## 方法

 ### 蛮力方法

 暴力方法生成每个可能的子字符串并检查它是否有效。 

对于每个子串：

 1.统计每个字符出现的频率
 2. 验证每个字符频率至少为`k`3.更新最大有效长度

 这是有效的，因为它详尽地检查了所有可能性，保证了正确性。 

然而，有`O(n^2)`子字符串，验证每个子字符串可能需要`O(n)`频率计数的时间。 这导致整体复杂性`O(n^3)`，这对于`n = 10^4`。 

### 最优方法，分而治之

 关键的见解是任何出现次数少于`k`子字符串中的时间不能属于该子字符串的有效解。 

假设我们分析某个子字符串并发现该字符`'x'`出现少于`k`次。 然后任何包含的子字符串`'x'`则自动无效。 

这意味着`'x'`充当分隔符。 我们可以围绕这个无效字符分割问题并递归地解决较小的部分。 

例如：```
ababbc
```和`k = 2`。 

人物`'c'`只出现一次，因此不能包含有效的子字符串`'c'`。 因此我们分为：```
ababb
```并递归求解。 

这极大地减少了不必要的工作，因为无效字符会划分搜索空间。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n3) | O(1) | O(1) | 独立检查每个子字符串 |
 | 最佳 | 平均 O(26 × n)，最坏情况 O(n²) | O(log n) 递归 | 使用无效字符划分搜索空间 |

 ## 算法演练

 ### 分而治之算法

 1. 从当前子字符串范围开始。 

我们不是重复地物理创建新的子字符串，而是递归地处理原始字符串的各个部分。 
2. 统计当前范围内每个字符的出现频率。 

我们使用大小为 26 的频率数组，因为该字符串仅包含小写英文字母。 这允许恒定时间计数和查找。 
3. 识别无效字符。 

频率大于 0 但小于的任何字符`k`无效。 这样的字符不能出现在当前范围内的任何有效子字符串中。 
4. 如果不存在无效字符，则返回当前子字符串的长度。 

这意味着每个字符都满足要求，因此整个子字符串都是有效的。 
5. 否则，将子字符串拆分为无效字符。 

每个无效字符都充当边界。 我们递归地解决无效字符之间的每个段。 
6. 返回所有递归段中最大的结果。 

由于任何有效的子字符串都必须避免无效字符，因此最佳答案必须完全位于这些段之一内。 

### 为什么它有效

 正确性来自于一个字符出现的次数少于`k`times 永远不能属于覆盖当前范围的有效子字符串。 任何包含该字符的子字符串都会立即违反问题条件。 

因此，分割无效字符不会丢弃任何有效的候选字符。 每个有效子字符串必须完全位于结果分区之一内，因此递归求解这些分区可以保证最佳答案。 

## Python 解决方案```python
class Solution:
    def longestSubstring(self, s: str, k: int) -> int:
        def divide(left: int, right: int) -> int:
            if right - left < k:
                return 0

            frequency = [0] * 26

            for i in range(left, right):
                frequency[ord(s[i]) - ord('a')] += 1

            for mid in range(left, right):
                if frequency[ord(s[mid]) - ord('a')] < k:
                    mid_next = mid + 1

                    while (
                        mid_next < right
                        and frequency[ord(s[mid_next]) - ord('a')] < k
                    ):
                        mid_next += 1

                    left_part = divide(left, mid)
                    right_part = divide(mid_next, right)

                    return max(left_part, right_part)

            return right - left

        return divide(0, len(s))
```该实现使用了一个名为的递归辅助函数`divide`。 

该函数处理由以下定义的子字符串`[left, right)`。 

第一个优化检查子串长度是否小于`k`。 如果是的话，至少任何角色都不可能出现`k`次，所以我们立即返回 0。 

接下来，我们使用长度为 26 的固定大小数组来计算当前范围内的字符频率。这比哈希映射更有效，因为字母大小是固定的。 

然后我们扫描子字符串以查找无效字符。 如果遇到一个，我们就将其周围的子字符串分开。 

这`while`循环会跳过连续的无效字符，因为它们不能构成任何有效的子字符串。 

最后，我们递归地计算左右分区的最佳答案并返回最大值。 

如果不存在无效字符，则整个子字符串有效，因此我们直接返回其长度。 

## 解决方案```go
func longestSubstring(s string, k int) int {
	var divide func(left int, right int) int

	divide = func(left int, right int) int {
		if right-left < k {
			return 0
		}

		frequency := make([]int, 26)

		for i := left; i < right; i++ {
			frequency[s[i]-'a']++
		}

		for mid := left; mid < right; mid++ {
			if frequency[s[mid]-'a'] < k {
				midNext := mid + 1

				for midNext < right &&
					frequency[s[midNext]-'a'] < k {
					midNext++
				}

				leftPart := divide(left, mid)
				rightPart := divide(midNext, right)

				if leftPart > rightPart {
					return leftPart
				}

				return rightPart
			}
		}

		return right - left
	}

	return divide(0, len(s))
}
```Go 的实现与 Python 版本非常相似。 

Go 不像 Python 那样具有自动闭包的嵌套函数，而是需要在分配函数体之前显式声明递归函数变量。 

Go 中字符索引更简单，因为字符串可以直接作为字节索引，并且所有字符都是小写英文字母。 

频率阵列使用`make([]int, 26)`用于高效的固定尺寸计数。 

不存在整数溢出问题，因为最大字符串长度仅为`10^4`。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`k`大于字符串长度。 在这种情况下，任何子字符串都不可能满足要求，因为即使整个字符串也太短了。 实现通过条件自然地处理这个问题：```
if right - left < k:
    return 0
```当每个角色都满足要求时，就会出现另一种棘手的情况。 例如：```
s = "aaabbb"
k = 3
```有缺陷的实现可能会不必要地递归或拆分。 我们的解决方案正确检测到不存在无效字符并立即返回整个子字符串长度。 

第三个重要的边缘情况涉及连续的无效字符。 考虑：```
s = "aaaxxxbbb"
k = 3
```人物`'x'`均无效。 如果我们一次拆分一个字符，就会创建不必要的递归调用。 该实现通过使用以下命令跳过连续的无效字符来避免这种情况`while`环形：```
while mid_next < right and frequency[...] < k:
    mid_next += 1
```这提高了效率并避免了冗余递归。 

当有效子字符串位于字符串中间时，会发生另一种微妙的情况。 例如：```
s = "caaab"
k = 3
```有效答案是`"aaa"`。 分而治之的策略正确地隔离和独立评估中间部分，确保不会错过最佳子串。
