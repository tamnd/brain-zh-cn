[LeetCode 第 346 题](https://leetcode.com/problems/moving-average-from-data-stream/)

 **难度：** 🟢简单
 **主题：** 数组、设计、队列、数据流

 ## 解决方案

 ## 问题理解

 该问题要求我们设计一种数据结构，该结构连续从流中接收整数，并返回固定大小滑动窗口内最新值的平均值。 

滑动窗口意味着我们只关心最新的`size`元素。 随着新值的到来，一旦超出容量，旧值最终就会从窗口中消失。 

例如，如果窗口大小是`3`流是：```
1, 10, 3, 5
```那么移动平均线是：```
[1]                -> 1.0
[1, 10]            -> 5.5
[1, 10, 3]         -> 4.66667
[10, 3, 5]         -> 6.0
```注意插入后`5`，最旧的值`1`被删除是因为窗口只能包含三个元素。 

输入由重复调用组成`next(val)`方法。 每次调用都会向流中插入一个新整数并返回当前滑动窗口的平均值。 

限制相对较小：

 - 窗口大小最大为`1000`- 至多`10^4`已拨打电话
 - 值可能为负

 尽管限制不是很大，但问题显然是测试高效的流处理和基于队列的设计。 每次重新计算整个窗口总和的简单实现是可行的，但它会执行不必​​要的重复计算。 

一些边缘情况很重要：

 - 窗口可能尚未满，因此除数是当前元素数而不是最大大小。 
- 平均值中必须正确处理负数。 
- 窗口大小为`1`意味着答案始终是最新值。 
- 大型操作序列应避免重复对整个窗口求和。 

## 方法

 ### 蛮力方法

 最简单的解决方案是将当前滑动窗口内的所有值存储在列表或队列中。 每当`next(val)`称为：

 1. 将新值添加到窗口中。 
2. 如果窗口超出允许的大小，则删除最旧的值。 
3. 重新计算窗口中所有元素的总和。 
4. 除以当前存储的元素数量。 

这种方法是正确的，因为平均值始终定义为：```
sum(window) / len(window)
```然而，每次都重新计算总和是低效的。 如果窗口大小是`k`，每次调用`next()`需要`O(k)`时间，因为我们迭代整个窗口来计算总和。 

虽然`k <= 1000`，这种重复的工作是不必要的。 

### 最佳方法

 关键的观察结果是窗口逐渐变化。 

当新值到达时：

 - 添加一个值
 - 最多删除一个旧值

 我们可以维护一个运行总和，而不是每次都重新计算整个总和。 

假设当前窗口总和为：```
current_sum
```添加新值时：```
current_sum += val
```如果窗口变得太大并且我们删除最旧的值：```
current_sum -= removed_value
```现在可以立即计算平均值：```
current_sum / len(window)
```这避免了重复遍历窗口并将每个操作减少到恒定时间。 

队列是理想的数据结构，因为：

 - 新值插入到后面
 - 最旧的值从前面删除

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 每次操作 O(k) | O(k) | 每次都重新计算整个总和 |
 | 最佳| 每次操作 O(1) | O(k) | 使用队列维护运行总和 |

 这里，`k`是窗口大小。 

## 算法演练

 ### 最优滑动窗口算法

 1. 初始化一个空队列，用于存储当前滑动窗口内的元素。 
2. 将允许的最大窗口大小存储在变量中，例如`size`。 
3. 维护一个初始化为的运行总和变量`0`。 
4. 什么时候`next(val)`被调用，附加`val`到队列中，因为它成为当前窗口的一部分。 
5. 添加`val`到运行总和。 这会更新总和，而无需重新计算所有内容。 
6. 检查队列大小是否超过允许的窗口大小。 

- 如果是，则从队列前面删除最旧的元素。 
- 从运行总和中减去删除的值。 
7. 使用以下方法计算平均值：```
running_sum / current_window_size
```8. 返回计算出的浮点平均值。 

### 为什么它有效

 该算法保持了一个重要的不变量：```
running_sum == sum(all elements currently in the queue)
```每当一个新值进入窗口时，它就会被添加到队列和运行总和中。 每当旧值离开窗口时，它就会从队列和运行总和中删除。 

因为这个不变量总是被保留，所以将运行总和除以队列中的元素数量总是会产生正确的移动平均值。 

## Python 解决方案```python
from collections import deque
from typing import Deque

class MovingAverage:

    def __init__(self, size: int):
        self.size = size
        self.window: Deque[int] = deque()
        self.current_sum = 0

    def next(self, val: int) -> float:
        self.window.append(val)
        self.current_sum += val

        if len(self.window) > self.size:
            removed_value = self.window.popleft()
            self.current_sum -= removed_value

        return self.current_sum / len(self.window)

# Your MovingAverage object will be instantiated and called as such:
# obj = MovingAverage(size)
# param_1 = obj.next(val)
```该实现使用Python的`deque`从`collections`module because it provides efficient insertion and removal operations from both ends.

 构造函数存储：

 - 最大窗口尺寸
 - 队列本身
 - 运行总和

 里面`next()`:

 - 新值被追加到队列中。 
- 运行总和立即更新。 
- 如果队列变得太大，则使用删除最旧的值`popleft()`。 
- 从运行总和中减去删除的值。 
- 使用当前队列长度返回平均值。 

该实现直接遵循前面描述的滑动窗口算法。 

## 解决方案```go
type MovingAverage struct {
	size       int
	window     []int
	currentSum int
}

func Constructor(size int) MovingAverage {
	return MovingAverage{
		size:       size,
		window:     []int{},
		currentSum: 0,
	}
}

func (this *MovingAverage) Next(val int) float64 {
	this.window = append(this.window, val)
	this.currentSum += val

	if len(this.window) > this.size {
		removedValue := this.window[0]
		this.currentSum -= removedValue
		this.window = this.window[1:]
	}

	return float64(this.currentSum) / float64(len(this.window))
}

/**
 * Your MovingAverage object will be instantiated and called as such:
 * obj := Constructor(size);
 * param_1 := obj.Next(val);
 */
```Go 实现使用切片来模拟队列。 

附加是通过以下方式完成的：```go
append(this.window, val)
```删除最旧的元素是通过切片完成的：```go
this.window = this.window[1:]
```Go 需要显式转换为`float64`在除法之前以避免整数除法。 

因为约束很小，所以这里使用切片重新分配是完全可以接受的。

 ## 边缘情况

 ### 窗口大小为一

 当窗口大小为`1`，每个新值立即替换前一个值。 有缺陷的实现可能会意外保留旧值或除以错误的计数。 

此实现可以自然地处理这种情况，因为只要大小超过，队列就会自动删除最旧的值`1`。 

### 窗口尚未满

 在流的开头，插入元素的数量可能小于最大窗口大小。 

例如：```
size = 5
stream = [1, 2]
```平均值应该是：```
(1 + 2) / 2
```不除以`5`。 

实现正确地除以`len(window)`而不是固定的窗口大小。 

### 负数

 负值可能会暴露运行求和逻辑中的错误，尤其是在删除处理不当的情况下。 

例如：```
window = [-5, 3]
sum = -2
average = -1
```该实现在插入和删除期间始终一致地更新运行总和，因此负数无需任何特殊处理即可正常工作。 

### 持续流增长

 幼稚的实现可能会意外存储见过的每个值，从而导致内存随着时间的推移而增长。 

该实现最多只存储`size`队列中的元素。 旧元素一旦离开滑动窗口就会立即被删除，从而保证有限的内存使用。
