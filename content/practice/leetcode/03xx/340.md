[LeetCode 问题 340](https://leetcode.com/problems/longest-substring-with-at-most-k-distinct-characters/)

 **难度：** 🟡 中等
 **主题：** 哈希表、字符串、滑动窗口

 ## 解决方案

 ## 问题理解

 该问题要求我们找到给定字符串中最长连续子串的长度`s`使得子串最多包含`k`鲜明的人物。 

子串是字符串的连续部分。 重要的条件不是字符总数，而是当前子字符串内唯一字符类型的数量。 例如，在子串中`"ece"`，只有两个不同的字符，`'e'`和`'c'`。 

输入包括：

 - 一根绳子`s`- 一个整数`k`输出应该是一个整数，表示有效子字符串的最大可能长度。 

例如：

-`s = "eceba"`和`k = 2`- 最长的有效子串是`"ece"`- 它只包含两个不同的字符
 - 它的长度是`3`约束条件很重要：

 -`1 <= s.length <= 5 * 10^4`-`0 <= k <= 50`该字符串可能相当大，最多 50,000 个字符，因此任何比线性或接近线性时间更差的算法都可能太慢。 检查所有子串的强力解决方案性能不佳，因为子串的数量呈二次方增长。 

有几种边缘情况值得尽早识别：

 -`k = 0`，不允许有任何字符，所以答案必须是`0`- 该字符串包含少于`k`不同的字符，整个字符串有效
 - 该字符串由所有相同的字符组成
 - 字符串在许多不同的字符之间交替，迫使窗口频繁缩小
 - 非常小的字符串，例如长度`1`这些情况很容易暴露不正确的滑动窗口实现中的错误。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每个可能的子字符串并确定它是否最多包含`k`鲜明的人物。 

我们可以使用两个嵌套循环生成所有子字符串：

 - 选择起始索引
 - 选择结束索引
 - 计算子字符串中不同字符的数量
 - 如果子字符串有效，则更新最大长度

 为了计算不同的字符，我们可以使用哈希集或频率图。 

这种方法是正确的，因为它显式检查每个可能的子字符串，保证最终找到最长的有效子字符串。 

然而，对于问题的限制来说，它太慢了。 有`O(n^2)`子字符串，并且检查不同的字符可能需要另一个`O(n)`在最坏的情况下，产生的整体复杂度高达`O(n^3)`。 即使使用增量计数，最好的强力改进仍然是`O(n^2)`。 

为了`n = 50,000`，二次时间不切实际。 

### 最优滑动窗口方法

 关键的观察是我们不需要为每个子字符串从头开始。 

假设我们已经知道一个有效的子字符串。 如果我们将其向右扩展一个字符：

 - 子字符串可能仍然有效
 - 或者它现在可能包含太多不同的字符

 如果它变得无效，我们可以缩小左侧，直到它再次有效。 

这自然就引出了滑动窗口技术。 

我们维持：

 - 左指针
 - 右指针
 - 频率图存储当前窗口内的字符计数

 窗口始终表示最多包含一个有效子字符串`k`鲜明的人物。 

当我们在字符串中移动右指针时：

 - 将新字符添加到频率图中
 - 如果不同字符超过`k`, 左指针向前移动
 - 删除计数为零的字符
 - 更新最大窗口长度

 每个字符最多进入和离开窗口一次，时间复杂度为线性。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n2) 到 O(n3) | O(k) 或 O(n) | 显式检查所有子字符串 |
 | 最佳 | O(n) | O(k) | 带有频率图的滑动窗口 |

 ## 算法演练

 1.处理特殊情况`k == 0`。 

如果不允许使用不同的字符，则非空子字符串都不能有效。 返回`0`立即地。 
2.初始化滑动窗口。 

创造：

-`left = 0`-`max_length = 0`- 一个名为的哈希图`char_count`窗口将代表子字符串`s[left:right+1]`。 
3. 使用右指针展开窗口。 

遍历字符串`right`。 

对于每个字符：

 - 将其添加到频率图
 - 增加其计数
 4. 检查窗口是否仍然有效。 

一个有效的窗口最多包含`k`鲜明的人物。 

如果`len(char_count) > k`，窗口已失效。 
5. 从左侧缩小窗口。 

虽然不同字符的数量超过`k`：

 - 减少数量`s[left]`- 如果其计数变为零，则将其从地图中删除
 - 移动`left`前进

 此过程恢复窗口的有效性。 
6.更新答案。 

一旦窗口再次有效：

 - 计算当前窗口长度
 - 更新`max_length`7. 继续，直到右指针到达末尾。 

由于两个指针仅向前移动，因此该算法在线性时间内高效运行。 

### 为什么它有效

 该算法保持了一个重要的不变量：

 - 当前窗口始终最多包含`k`收缩步骤完成后有不同的字符。 

在每次迭代中，该窗口都是以当前结束的最长有效窗口`right`指数。 由于在扩展和收缩过程中考虑了每个可能的有效窗口，因此最大记录长度必须是全局最优的。 

由于每个字符都添加一次并删除一次，因此不会不必要地重复工作。 

## Python 解决方案```python
class Solution:
    def lengthOfLongestSubstringKDistinct(self, s: str, k: int) -> int:
        if k == 0:
            return 0

        left = 0
        max_length = 0
        char_count = {}

        for right in range(len(s)):
            current_char = s[right]

            char_count[current_char] = char_count.get(current_char, 0) + 1

            while len(char_count) > k:
                left_char = s[left]
                char_count[left_char] -= 1

                if char_count[left_char] == 0:
                    del char_count[left_char]

                left += 1

            current_window_length = right - left + 1
            max_length = max(max_length, current_window_length)

        return max_length
```实现首先处理特殊情况，其中`k`为零。 由于不允许使用任何字符，因此必须立即给出答案`0`。 

变量`left`跟踪滑动窗口的开始，而循环变量`right`一次将窗口展开一个字符。 

字典`char_count`存储当前窗口内每个字符的频率。 这使我们能够有效地确定存在多少个不同的字符。 

每当不同字符的数量超过`k`， 这`while`循环从左侧缩小窗口。 字符频率会降低，一旦条目计数达到零，条目就会被完全删除。 删除零计数条目至关重要，因为字典大小直接表示不同字符的数量。 

恢复有效性后，算法计算当前窗口长度并更新最佳答案。 

该实现直接反映了前面描述的滑动窗口算法。 

## 解决方案```go
func lengthOfLongestSubstringKDistinct(s string, k int) int {
    if k == 0 {
        return 0
    }

    left := 0
    maxLength := 0

    charCount := make(map[byte]int)

    for right := 0; right < len(s); right++ {
        currentChar := s[right]
        charCount[currentChar]++

        for len(charCount) > k {
            leftChar := s[left]
            charCount[leftChar]--

            if charCount[leftChar] == 0 {
                delete(charCount, leftChar)
            }

            left++
        }

        currentWindowLength := right - left + 1

        if currentWindowLength > maxLength {
            maxLength = currentWindowLength
        }
    }

    return maxLength
}
```Go 实现遵循与 Python 版本相同的逻辑。 主要区别在于 Go 使用显式的`map[byte]int`为频率表。 

由于输入由 LeetCode 的典型约束中的标准 ASCII 字符组成，因此将字符串索引为字节就足够且高效了。 

Go 不提供内置的`max`函数用于整数，因此最大长度更新是通过标准条件比较来处理的。 

这`delete`函数删除频率达到零的字符，确保`len(charCount)`准确反映当前窗口中不同字符的数量。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`k = 0`。 在这种情况下，不允许使用不同的字符，这意味着每个非空子字符串都是无效的。 幼稚的实现可能会错误地返回`1`因为窗口在缩小之前会短暂包含一个字符。 该实现通过返回来避免这种情况`0`就在处理开始之前。 

另一个重要的情况是整个字符串已经满足条件。 例如，`"aaaaaa"`和`k = 1`或者`"abcdef"`和`k = 10`。 一些不正确的解决方案会不必要地缩小窗口或无法正确更新最大长度。 滑动窗口实现自然会处理这个问题，因为窗口永远不会变得无效，从而允许它扩展到整个字符串。 

第三种微妙的边缘情况涉及在收缩期间计数降至零的字符。 如果这些字符没有从哈希映射中删除，算法将错误地认为它们仍然存在于窗口中。 这会导致不同字符数仍然太大，从而导致不正确的结果或无限缩小。 一旦字符频率达到零，该实现就会显式删除字符，以确保地图准确反映窗口内容。 

另一个棘手的场景发生在角色快速交替的情况下，例如`"abcabcabc"`和`k = 2`。 窗口反复失效，必须多次缩小。 不正确的实现有时只缩小一次，而不是继续直到窗口再次有效。 这`while`循环保证收缩继续，直到恢复不变量。
