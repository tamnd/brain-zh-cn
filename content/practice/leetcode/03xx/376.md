[LeetCode 第 376 题](https://leetcode.com/problems/wiggle-subsequence/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划、贪心

 ## 解决方案

 ## 问题理解

 该问题要求我们找到数组中最长子序列的长度，使得连续元素之间的差异在正负之间交替。 

摆动序列遵循严格的交替模式：

 - 正差异，然后负差异，然后再次正差异
 - 或者负差异，然后正差异，然后再次负差异

 实际值并不像相邻元素之间的变化方向那么重要。 

例如，序列`[1, 7, 4, 9, 2, 5]`有差异：

 -`7 - 1 = 6`→ positive
 -`4 - 7 = -3`→ negative
 -`9 - 4 = 5`→ 积极
 -`2 - 9 = -7`→ 负面
 -`5 - 2 = 3`→ 积极

 由于符号完美交替，因此整个序列是有效的摆动序列。 

重要的细节是我们正在寻找一个子序列，不一定是一个连续的子数组。 我们可以在保留原始顺序的同时删除元素。 

输入是一个整数数组`nums`，输出是一个整数，表示摆动子序列的最大可能长度。 

限制条件是：

 -`1 <= nums.length <= 1000`-`0 <= nums[i] <= 1000`由于数组长度最多为 1000，即使是`O(n^2)`动态规划解决方案将通过。 然而，后续明确询问我们是否可以实现`O(n)`时间，这强烈表明存在贪婪优化。 

一些边缘情况很重要：

 - 应该返回只有一个元素的数组`1`- 所有元素都相等的数组应该返回`1`- 应该返回严格增加或严格减少的数组`2`- 必须忽略连续的重复值，因为零差值既不是正值也不是负值
 - 无需额外内存即可有效处理大型交替模式

 ## 方法

 ### 蛮力方法

 强力解决方案将生成每个可能的子序列，并检查每个子序列是否形成有效的摆动序列。 

对于每个子序列，我们将计算连续的差异并验证它们的符号是否严格交替。 然后我们将跟踪最大有效长度。 

这种方法是正确的，因为它详尽地探索了所有可能的子序列。 然而，它在计算上是不可行的，因为长度的数组`n`有`2^n`可能的子序列。 

即使是为了`n = 30`，这变得非常大。 由于约束允许最多`1000`元素，蛮力是完全不切实际的。 

### 动态规划洞察

 关键的观察是我们只关心最后一个差异的方向。 

在每个位置，我们都可以保持：

 - 以正差结尾的最长摆动子序列
 - 以负差值结尾的最长摆动子序列

 如果当前数字大于前一个数字，我们可以扩展之前以负差结束的序列。 

如果当前数字小于前一个数字，我们可以扩展之前以正差值结束的序列。 

这导致了贪婪优化，我们只跟踪两个值：

 -`up`→ 以向上移动结束的最长摆动子序列
 -`down`→ 以向下移动结束的最长摆动子序列

 因为每个元素只依赖于先前的状态，所以我们可以在线性时间和常量空间中解决问题。

 ## 算法演练

 ### 最优贪心动态规划算法

 1.初始化两个变量：

 -`up = 1`-`down = 1`这些代表最长的摆动子序列长度，结尾为：

 - 积极的差异
 - 负差异

 我们从`1`因为单个元素本质上就是一个摆动序列。 
2. 从索引开始迭代数组`1`。 
3. 将当前元素与前一个元素进行比较。 
4. 如果`nums[i] > nums[i - 1]`，我们发现了正差异。 

这意味着我们可以扩展之前以负差值结束的任何序列。 

更新：```
up = down + 1
```5. 如果`nums[i] < nums[i - 1]`，我们发现了负差异。 

这意味着我们可以扩展之前以正差值结束的任何序列。 

更新：```
down = up + 1
```6. 如果值相等，则不执行任何操作。 

相等的值会产生零差值，这不会对摆动序列产生影响。 
7. 继续直到数组末尾。 
8. 返回最大值`up`和`down`。 

### 为什么它有效

 该算法保持一个不变量：

 -`up`始终存储以正差结尾的最长摆动子序列
 -`down`始终存储以负差异结尾的最长摆动子序列

 每当我们遇到正差异时，唯一有效的扩展就是来自以负差异结尾的序列。 类似地，负差异只能扩展以正差异结尾的序列。 

因为我们只需要到目前为止的最佳长度，所以我们永远不需要存储实际的子序列。 这使得解决方案能够在恒定的空间中运行，同时仍然保证最优性。 

## Python 解决方案```python
from typing import List

class Solution:
    def wiggleMaxLength(self, nums: List[int]) -> int:
        if not nums:
            return 0

        up = 1
        down = 1

        for i in range(1, len(nums)):
            if nums[i] > nums[i - 1]:
                up = down + 1
            elif nums[i] < nums[i - 1]:
                down = up + 1

        return max(up, down)
```实现首先处理空数组的情况，尽管问题保证至少有一个元素。 

变量`up`和`down`两者都开始于`1`因为任何单个元素都会形成有效的摆动子序列。 

该循环处理相邻的元素对。 当当前元素大于前一个元素时，我们将向下序列扩展为向上序列。 当当前元素较小时，我们将向上序列扩展为向下序列。 

相等的值会被忽略，因为它们不会导致交替。 

最后，该算法返回两个状态中较大的一个，因为最佳序列可能以任一方向结束。 

## 解决方案```go
func wiggleMaxLength(nums []int) int {
    if len(nums) == 0 {
        return 0
    }

    up := 1
    down := 1

    for i := 1; i < len(nums); i++ {
        if nums[i] > nums[i-1] {
            up = down + 1
        } else if nums[i] < nums[i-1] {
            down = up + 1
        }
    }

    if up > down {
        return up
    }

    return down
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

Go 没有内置的`max`函数用于整数，因此最终的比较是手动完成的。 

Go 中的切片的行为类似于动态数组，并且整数溢出不是问题，因为最大子序列长度最多为`1000`。

 ## 边缘情况

 ### 所有元素都相等

 像这样的输入`[5,5,5,5]`很棘手，因为每个差异都是零。 幼稚的实现可能会错误地将相等的值视为摆动序列的一部分。 

正确答案是`1`因为当不存在正差或负差时，只有单个元素可以形成有效的摆动序列。 

该实现通过忽略相等的相邻值自然地处理这个问题。 

### 严格递增或递减数组

 数组就像`[1,2,3,4,5]`或者`[5,4,3,2,1]`切勿改变方向。 

一个常见的错误是计算整个序列，但最长的有效摆动子序列只有长度`2`。 

该算法正确地保留了`up`或者`down`固定在`2`而另一个仍然存在`1`。 

### 方向变化之间的重复值

 输入如`[1,7,7,7,4]`如果相同的值处理不当，可能会暴露错误。 

重复的`7`s 不应影响摆动结构，因为它们产生零差异。 

该实现完全忽略相等的值，确保重复项既不会增加也不会重置序列长度。
