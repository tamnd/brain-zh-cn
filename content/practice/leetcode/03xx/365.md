 **难度：** 🟡 中等
 **主题：** 数学、深度优先搜索、广度优先搜索

 ## 解决方案

 ## 问题理解

 这个问题给了我们两个容量的水壶`x`和`y`。 我们只能执行三种类型的操作：

 - 完全装满一个水壶
 - 完全清空水壶
 - 将水从一个罐子倒入另一个罐子，直到源罐子变空或目标罐子变满

 我们的目标是确定是否可以精确测量`target`升使用这些操作。 

系统任意时刻的状态可以表示为`(a, b)`， 在哪里`a`是第一个水罐中的当前水量，`b`是第二个罐中的当前数量。 该问题并不要求将水盛装在特定的壶中。 唯一的要求是两个水壶之间的可用水总量等于`target`。 

例如，如果`x = 3`,`y = 5`， 和`target = 4`，然后有这样的状态`(0,4)`或者`(1,3)`都满足要求，因为总水量等于`4`。 

限制相对较小：

 -`1 <= x, y, target <= 1000`这些限制意味着即使是 BFS 或 DFS 等图遍历解决方案也是可行的，因为状态总数受下式限制：`(x + 1) * (y + 1)`。 然而，还有一种数学观察可以带来更干净、更有效的解决方案。 

立即识别几个边缘情况非常重要。 

如果`target > x + y`，答案自动`false`因为即使两个水壶都完全满了，总容量也不足以容纳目标数量。 

如果`target == 0`，答案很简单`true`，尽管约束保证目标至少是`1`。 

如果一罐已经等于目标，或者如果总容量等于目标，则答案立即`true`。 

最重要的数学边缘情况是整除性。 由于数论特性，有些目标根本不可能构建。 例如，带有尺寸的水壶`2`和`6`，每个可测量的数量必须被整除`2`， 所以`5`永远无法生产。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是将问题建模为图遍历问题。 

每个状态由`(a, b)`， 在哪里：

-`a`是壶中的水量`x`-`b`是壶中的水量`y`从每个状态，我们可以生成最多六个可能的下一个状态：

 - 填充壶`x`- 填充壶`y`- 空壶`x`- 空壶`y`- 倒入`x`进入`y`- 倒入`y`进入`x`我们可以从以下位置开始执行 BFS 或 DFS`(0, 0)`并探索所有可到达的状态。 如果我们遇到这样的情况：```
a + b == target
```那么答案是`true`。 

这种方法是正确的，因为它详尽地探索了两个罐子的每一个可到达的配置。 如果存在有效的解决方案，遍历最终会找到它。 

然而，尽管这些限制是可以管理的，但这种方法仍然比必要的更昂贵。 状态空间最多可以包含：```
(x + 1) * (y + 1)
```状态，每个状态生成多个转换。 

### 最优数学方法

 关键的见解来自贝祖特的数论恒等式。 

对于两个整数`x`和`y`，任何可测量的金额必须是以下的倍数：```
gcd(x, y)
```这意味着当且仅当满足以下条件时，目标才可以实现：

 1.`target <= x + y`2.`target % gcd(x, y) == 0`原因是每次操作都保留了系统中的水量是以下各项的线性组合的性质：`x`和`y`。 

贝佐特恒等式指出以下形式的整数：```
ax + by
```正好是`gcd(x, y)`。 

因此，如果目标可被罐尺寸的最大公约数整除，则可以通过重复的倾倒操作构造目标。 

这将问题从图遍历转变为简单的数学检查。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(x * y) | O(x * y) | 使用 BFS 或 DFS 探索所有可到达的壶状态 |
 | 最佳| O(log(min(x, y))) | O(log(min(x, y))) | O(1) | O(1) | 使用 Bézout 的恒等式和 GCD |

 ## 算法演练

 ### 最优算法

 1. 首先，检查目标是否超过两个水壶的总容量。 

如果：```
target > x + y
```那么就不可能测量目标，因为罐子在一起无法容纳足够的水。 
2. 如果目标恰好等于罐容量或组合容量，则返回`true`。 

这些是不需要额外操作的直接解决方案。 
3. 计算最大公约数`x`和`y`。 

GCD 代表通过重复浇注操作可获得的最小可测量单位。 
4. 检查目标是否能被GCD整除。 

如果：```
target % gcd(x, y) == 0
```那么目标是可以实现的。 

否则的话，那是不可能的。 
5. 返回整除性检查的结果。 

### 为什么它有效

 该算法之所以有效，是因为通过填充、清空和倾倒操作形成的每个可测量的量都必须可表示为两个罐尺寸的整数线性组合。 

根据贝祖特的身份：$ax + by = \gcd(x,y)$所有可测量的量都是以下的倍数`gcd(x, y)`。 因此，当且仅当目标可以被 GCD 整除并且不超过罐子的总容量时，才可以精确测量目标。 

## Python 解决方案```python
class Solution:
    def canMeasureWater(self, x: int, y: int, target: int) -> bool:
        if target > x + y:
            return False
        
        def gcd(a: int, b: int) -> int:
            while b:
                a, b = b, a % b
            return a
        
        return target % gcd(x, y) == 0
```实施从最重要的不可能性检查开始。 如果目标超过两个罐子的总容量，则没有有效的操作序列可以产生所需的量。 

接下来，该解决方案使用欧几里德算法计算最大公约数。 欧几里得算法反复替换对`(a, b)`和`(b, a % b)`直到`b`变为零。 剩余价值为`a`是GCD。 

最后，算法检查目标是否能被 GCD 整除。 如果它是可整除的，则目标是可测量的。 否则的话，那是不可能的。 

该解决方案很简洁，因为数学洞察力完全消除了状态探索的需要。 

## 解决方案```go
func canMeasureWater(x int, y int, target int) bool {
    if target > x+y {
        return false
    }

    return target%gcd(x, y) == 0
}

func gcd(a int, b int) int {
    for b != 0 {
        a, b = b, a%b
    }
    return a
}
```Go 实现遵循与 Python 版本相同的数学方法。 主要区别在于 Go 中必须单独声明辅助函数。 

Go 整数足以满足给定的约束，因此不存在溢出风险。 迭代欧几里得算法非常高效并且避免了递归开销。

 ## 边缘情况

 当目标超过两个罐子的总容量时，就会出现一种重要的边缘情况。 例如，如果`x = 3`,`y = 5`， 和`target = 10`，根本就没有足够的物理容量来容纳10升。 仅检查整除性的幼稚实现可能会错误地返回`true`。 该实现通过检查来防止此错误`target > x + y`在执行 GCD 计算之前。 

当壶容量共享一个重要的 GCD 时，会出现另一个重要的边缘情况。 例如，具有容量`2`和`6`，每个可测量的量必须被整除`2`。 遍历解决方案最终可能会隐式地发现这一点，但数学解决方案会立即检测到它。 该实现通过要求正确处理这个问题：```
target % gcd(x, y) == 0
```当目标等于两个水壶的总容量时，就会出现第三种边缘情况。 例如，`x = 1`,`y = 2`， 和`target = 3`。 一些不正确的实现仅检查目标是否等于一个单独的水罐尺寸，而忽略了完全填充两个水罐的可能性。 当前的实现可以自然地处理这个问题，因为`target <= x + y`且整除条件均成立。 

另一个微妙的边缘情况涉及互质壶尺寸，例如`999`和`1000`。 因为他们的 GCD 是`1`，每个目标来自`1`到`1999`是可测量的。 这是一个重要的正确性属性，因为它证明了为什么 GCD 条件既是必要的又是充分的。
