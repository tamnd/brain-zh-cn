[LeetCode 第 993 题](https://leetcode.com/problems/cousins-in-binary-tree/)

 **难度：** 🟢简单
 **主题：** 树、深度优先搜索、广度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 该问题要求我们确定二叉树中的两个节点是否是表兄弟。 如果两个节点同时满足两个条件，则它们被视为表兄弟：

 1. 它们位于树中的相同深度。 
2.他们有不同的父母。 

输入包括：

 -`root`，它是二叉树的根节点。 
- 两个整数值，`x`和`y`，表示树中两个不同节点的值。 

树中的每个节点值都是唯一的，这很重要，因为它允许我们仅通过节点的值来识别节点，而不会产生歧义。 

预期输出是一个布尔值：

 - 返回`true`如果节点对应于`x`和`y`是表兄弟。 
- 返回`false`否则。 

树的深度开始于`0`为根。 每个子节点都比其父节点深一级。 

限制相对较小：

 - 树包含之间`2`和`100`节点。 
- 节点值是唯一的，范围为`1`到`100`。 

由于树很小，即使优化程度较低的解决方案也可以轻松通过。 然而，目标仍然是设计一个干净、高效的遍历策略。 

尽早识别一些边缘情况很重要：

 - 如果一个节点是另一个节点的父节点，则它们不能是表兄弟，因为它们的深度不同。 
- 如果两个节点共享相同的父节点，则它们是兄弟姐妹，而不是表兄弟姐妹。 
- 如果一个节点是根，它不能是任何其他节点的表亲，因为根没有父节点和深度`0`。 
- 该问题保证了两者`x`和`y`存在于树中，所以我们永远不需要处理丢失的目标。 

## 方法

 ### 蛮力方法

 一个简单的暴力策略是独立搜索树两次：

 1.求节点深度`x`。 
2. 查找节点的父节点`x`。 
3.求节点深度`y`。 
4. 查找节点的父节点`y`。 

收集这些信息后，我们进行比较：

 - 深度是否相等。 
- 父母是否不同。 

这种方法之所以有效，是因为表兄弟定义仅取决于这两个属性。 

一种可能的暴力实现方式是重复遍历树以获取每条信息。 例如：

 - 一个 DFS 来查找深度`x`- 另一个 DFS 来查找父级`x`- 另一个 DFS 来查找深度`y`- 另一个 DFS 来查找父级`y`尽管正确，但这会执行多余的工作，因为树被遍历了多次。 

### 最佳方法

 关键的观察是，在单次遍历期间，我们可以收集每个目标节点的深度和父信息。 

深度优先搜索自然提供：

 - 当前节点深度。 
- 父节点引用。 

一旦我们遇到`x`或者`y`，我们记录：

 - 它的深度。 
- 它的父级。 

一旦找到两个节点，我们只需比较：

 - 深度平等。 
- 父母不平等。 

这减少了不必要的重复遍历，并保持实现的干净和高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n) 到 O(4n) | O(h) | 多次遍历树以分别查找深度和父级 |
 | 最佳| O(n) | O(h) | 单次 DFS 遍历收集所有所需信息 |

 这里，`n`是节点数，`h`是树的高度。 

## 算法演练

 1. 从根节点开始深度优先遍历。 
2. 对于每个递归调用，跟踪：

 - 当前节点。 
- 父节点。 
- 当前深度。 
3.当当前节点的值等于`x`， 记录：

-`x_depth`-`x_parent`4.当当前节点的值等于`y`， 记录：

-`y_depth`-`y_parent`5. 继续遍历左子树和右子树，直到探索完整棵树或找到两个目标。 
6、遍历完成后，比较：

 - 是否`x_depth == y_depth`- 无论`x_parent != y_parent`7. 返回`True`仅当两个条件都满足时。 

### 为什么它有效

 该算法之所以有效，是因为树中的每个节点都被访问了一次，并且在遍历过程中我们准确地捕获了表兄弟节点的两个定义属性：

 - 它们在树中的深度。 
- 他们的父节点。 

当且仅当两个节点具有相同的深度但具有不同的父节点时，它们才是表兄弟。 由于 DFS 会探索整个树并正确记录这些信息，因此最终的比较总是会产生正确的答案。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

class Solution:
    def isCousins(self, root: Optional[TreeNode], x: int, y: int) -> bool:
        x_info = None
        y_info = None

        def dfs(node, parent, depth):
            nonlocal x_info, y_info

            if not node:
                return

            if node.val == x:
                x_info = (parent, depth)

            if node.val == y:
                y_info = (parent, depth)

            dfs(node.left, node, depth + 1)
            dfs(node.right, node, depth + 1)

        dfs(root, None, 0)

        x_parent, x_depth = x_info
        y_parent, y_depth = y_info

        return x_depth == y_depth and x_parent != y_parent
```解决方案首先初始化两个变量，`x_info`和`y_info`，它将存储目标节点的父节点和深度信息。 

嵌套的`dfs`函数执行递归遍历。 每个呼叫都会收到：

 - 当前节点。 
- 父节点。 
- 当前深度。 

如果当前节点匹配`x`或者`y`，算法将其父级和深度记录为元组。 

然后递归继续进入左子树和右子树，深度增加一。 

遍历完成后，两个元组都包含所需的信息。 最终的返回语句直接检查表弟条件：

 - 相同的深度。 
- 不同的父母。 

因为树保证两个节点都存在，所以解包元组总是安全的。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func isCousins(root *TreeNode, x int, y int) bool {
	var xParent, yParent *TreeNode
	var xDepth, yDepth int

	var dfs func(node *TreeNode, parent *TreeNode, depth int)

	dfs = func(node *TreeNode, parent *TreeNode, depth int) {
		if node == nil {
			return
		}

		if node.Val == x {
			xParent = parent
			xDepth = depth
		}

		if node.Val == y {
			yParent = parent
			yDepth = depth
		}

		dfs(node.Left, node, depth+1)
		dfs(node.Right, node, depth+1)
	}

	dfs(root, nil, 0)

	return xDepth == yDepth && xParent != yParent
}
```Go 实现遵循与 Python 版本相同的逻辑。 主要区别在于 Go 需要显式变量声明并使用树节点指针。 

递归 DFS 函数是使用函数变量声明的，以便它可以递归地引用自身。 

家长跟踪的处理方式是`*TreeNode`指针。 比较父母变成了简单的指针比较：```go
xParent != yParent
```该实现还使用`nil`而不是Python的`None`。

 ## 边缘情况

 当两个节点是兄弟节点时，会出现一种重要的边缘情况。 由于兄弟姐妹自然共享相同的深度，因此仅检查深度相等的简单解决方案将错误地返回`true`。 该实现通过显式记录和比较父节点来避免这种情况。 

另一个重要的边缘情况是高度倾斜的树，其中每个节点只有一个子节点。 在这种情况下，递归深度变得等于节点数。 该算法仍然可以正常工作，因为每个递归调用都正确跟踪增加的深度和父关系。 

第三个重要的边缘情况涉及根节点。 根没有父级并且存在于深度`0`，所以它永远不可能与另一个节点成为表兄弟。 该实现自然地处理这个问题，因为任何其他节点的深度必须大于`0`，导致深度比较失败。 

最后一个微妙的情况是两个节点出现在相同的深度但属于完全不同的子树。 这实际上是正常的表亲场景，并且 DFS 遍历正确地识别了它，因为父跟踪对于每个子树都是独立的。
