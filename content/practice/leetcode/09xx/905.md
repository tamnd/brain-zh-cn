[LeetCode 905 题](https://leetcode.com/problems/sort-array-by-parity/)

 **难度：** 🟢简单
 **主题：** 数组、两个指针、排序

 ## 解决方案

 ## 问题理解

 该问题要求我们重新排列数组，使所有偶数出现在所有奇数之前。 偶数之间的相对顺序无关紧要，奇数之间的相对顺序也无关紧要。 该问题明确指出任何有效的安排都是可以接受的。 

我们得到一个整数数组`nums`。 每个元素都是非负整数。 我们的目标是返回相同的数组或另一个数组，其中每个偶数值首先出现，每个奇数值随后出现。 

例如，如果输入是：```
[3,1,2,4]
```那么有效的输出包括：```
[2,4,3,1]
[4,2,1,3]
[2,4,1,3]
```因为所有偶数都分组在开头，所有奇数都分组在末尾。 

限制相对较小：

 - 数组长度在1到5000之间
 - 每个数字都在 0 到 5000 之间

 这些限制告诉我们，即使`O(n log n)`排序解决方案可以轻松工作。 然而，这个问题实际上可以使用两指针技术在线性时间内解决。 

一个重要的观察结果是，奇偶性是通过检查一个数字是否能被 2 整除来确定的：

 - 偶数：`num % 2 == 0`- 奇数：`num % 2 == 1`有几种边缘情况值得考虑：

 - 仅包含偶数的数组
 - 仅包含奇数的数组
 - 具有单个元素的数组
 - 偶数和奇数频繁交替的数组
 - 包含零的数组，因为`0`是偶数

 该问题保证输入数组非空，因此我们永远不需要处理完全空的输入。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是创建两个单独的列表：

 1. 一个偶数列表
 2. 一份奇数列表

 我们遍历数组一次。 对于每个值：

 - 如果是偶数，则将其添加到偶数列表中
 - 否则，将其追加到奇数列表中

 最后，连接两个列表并返回结果。 

这是有效的，因为每个偶数都保证出现在最终连接数组中的每个奇数之前。 

尽管这种方法对于约束来说已经足够有效，但它使用与输入大小成比例的额外内存。 

### 最优方法，两个指针

 关键的见解是我们实际上不需要额外的数组。 我们可以重新排列元素。 

我们维护两个指针：

 - 左指针可搜索放错位置的奇数
 - 右指针可搜索放错位置的偶数

 如果左指针找到奇数而右指针找到偶数，则交换它们。 这逐渐将偶数推向前面，将奇数推向后面。 

这种方法效果很好，因为该问题不需要保留元素的原始顺序。 由于接受任何有效的安排，因此交换是完全安全的。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 使用单独的偶数和赔率列表 |
 | 最佳 | O(n) | O(1) | O(1) | 就地使用两个指针交换 |

 ## 算法演练

 ### 最优二指针算法

 1.初始化两个指针：

 -`left = 0`-`right = len(nums) - 1`左指针从头开始扫描，右指针从末尾开始扫描。 
2. 继续处理`left < right`。 

这确保了指针没有交叉。 
3. 检查该值是否为`left`已经是均匀的了。 

如果它是偶数，则它已经位于数组的正确区域中，因此递增`left`。 
4. 检查该值是否为`right`已经很奇怪了。 

如果是奇数，则它已经属于接近末尾的位置，因此递减`right`。 
5. 如果左侧为奇数，右侧为偶数，则交换它们。 

交换后：

 - 偶数向前移动
 - 奇数向后移动
 6. 交换后将两个指针向内移动。 

这可以避免重新处理现在正确定位的元素。 
7. 当指针交叉时，每个偶数都将位于每个奇数之前。 

### 为什么它有效

 该算法在执行过程中保持不变：

 - 之前的所有元素`left`是偶数
 - 之后的所有元素`right`are odd

 每当我们发现左侧有一个错位的奇数，而右侧有一个错位的偶数时，交换同时修复两个位置。 由于指针不断向内移动，每个元素最多被处理一次，并且数组最终被划分为偶数和奇数。 

## Python 解决方案```python
from typing import List

class Solution:
    def sortArrayByParity(self, nums: List[int]) -> List[int]:
        left = 0
        right = len(nums) - 1

        while left < right:
            if nums[left] % 2 == 0:
                left += 1
            elif nums[right] % 2 == 1:
                right -= 1
            else:
                nums[left], nums[right] = nums[right], nums[left]
                left += 1
                right -= 1

        return nums
```The implementation starts by creating two pointers at opposite ends of the array.

 Inside the loop, the algorithm first checks whether the left value is already even. If so, the left pointer advances because that element is correctly placed.

 Next, it checks whether the right value is already odd. If so, the right pointer moves backward because that element is also correctly placed.

 如果两个条件都不成立，则：

 - 左侧包含奇数
 - 右侧包含偶数

 These elements are misplaced relative to the desired partition, so the algorithm swaps them.

 After the swap, both pointers move inward because both newly placed elements are now correct.

 最后返回修改后的数组。 

## 解决方案```go
func sortArrayByParity(nums []int) []int {
    left := 0
    right := len(nums) - 1

    for left < right {
        if nums[left]%2 == 0 {
            left++
        } else if nums[right]%2 == 1 {
            right--
        } else {
            nums[left], nums[right] = nums[right], nums[left]
            left++
            right--
        }
    }

    return nums
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 由于 Go 中的切片的行为类似于数组的引用，因此修改会自动发生。 

Go 在这里不需要对整数溢出进行特殊处理，因为所有值都非常小。 该算法对于长度为 1 的切片也能正确工作，因为循环条件`left < right`立即失败。 

## 工作示例

 ### 示例 1

 输入：```
nums = [3,1,2,4]
```初始状态：

 | 左| 对| 数组|
 | --- | --- | --- |
 | 0 | 3 | [3,1,2,4]|

 步骤一：

 -`nums[left] = 3`， 奇怪的
-`nums[right] = 4`, 甚至
 - 交换它们

 | 左| 对| 数组|
 | --- | --- | --- |
 | 1 | 2 | [4,1,2,3] |

 步骤2：

 -`nums[left] = 1`， 奇怪的
-`nums[right] = 2`, 甚至
 - 交换它们

 | 左| 对| 数组|
 | --- | --- | --- |
 | 2 | 1 | [4,2,1,3] |

 现在`left > right`，因此算法停止。 

最终结果：```
[4,2,1,3]
```这是有效的，因为所有偶数都出现在所有奇数之前。 

### 示例 2

 输入：```
nums = [0]
```初始状态：

 | 左| 对| 数组|
 | --- | --- | --- |
 | 0 | 0 | [0]|

 自从`left < right`立即为 false，循环永远不会运行。 

最终结果：```
[0]
```该数组已经满足条件，因为`0`是均匀的。

 ## 边缘情况

 ### 单元素数组

 仅包含一个元素的数组很容易暴露边界条件错误。 例如，如果循环条件不正确，基于指针的实现可能会意外访问无效索引。 

此实现可以安全地处理这种情况，因为循环仅执行 while`left < right`。 对于单元素数组，两个指针都从索引开始`0`，所以循环永远不会运行。 

### 全偶数或全奇数数组

 每个元素都具有相同奇偶校验的数组可能会在设计不当的解决方案中导致不必要的交换。 

例如：```
[2,4,6,8]
```或者```
[1,3,5,7]
```在此实现中，指针只是向内移动而不执行交换，因为每个元素已经相对于分区正确定位。 

### 输入为零

 某些实现错误地将零视为特殊情况。 然而，从数学上讲，零是偶数，因为它可以被二整除。 

该解决方案使用以下方法正确对零进行分类：```
num % 2 == 0
```因此数组如：```
[0,1,2]
```被正确处理，零被放置在前面的偶数值中。
