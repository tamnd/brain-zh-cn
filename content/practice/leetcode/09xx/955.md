[LeetCode 955 题](https://leetcode.com/problems/delete-columns-to-make-sorted-ii/)

 **难度：** 🟡 中等
 **主题：** 数组、字符串、贪婪

 ## 解决方案

 ## 问题理解

 这个问题要求我们从等长字符串列表中删除最小数量的列，以便生成的字符串数组按字典顺序排序。 

重要的细节是，当我们删除一列时，我们同时从每个字符串中删除该字符位置。 我们不能有选择地从单个字符串中删除字符。 

词典顺序与词典中使用的顺序相同。 给定两个字符串`a`和`b`:

 - 如果第一个不同的字符`a`比对应的字符小`b`， 然后`a < b`- 如果所有比较的字符都相等并且一个字符串先结束，则较短的字符串较小
 - 也允许相同的字符串，因为要求是`<=`，不严格`<`输入包括：

 -`n`字符串
 - 每个字符串的长度相同`m`-`1 <= n <= 100`-`1 <= m <= 100`目标是返回所需的最小删除列数，以便：```
strs[0] <= strs[1] <= strs[2] <= ... <= strs[n-1]
```一个关键的观察是字典顺序比较是从左到右进行的。 一旦由于较早的列而确定两个相邻字符串的顺序正确，则后面的列对该对不再重要。 

例如：```
["abx", "acy"]
```在列`1`:```
'b' < 'c'
```这两个字符串之间的顺序已经固定。 无论后来出现什么，都不能使其无效。 

这个性质是贪婪解的基础。 

一些重要的边缘情况包括：

 - 字符串可能已经排序，需要`0`删除
 - 每列都可能需要删除
 - 许多行可以共享相同的前缀
 - 列可能对某些相邻对有效，但对其他对无效
 - 允许重复的字符串
 - 相邻行之间的一次错误比较会强制删除该列

 因为`n`和`m`至多都是`100`， 一个`O(n * m)`或者`O(n * m^2)`解决方案是完全可以接受的。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试删除所有可能的列子集。 

有`m`列，每列都可以保留或删除。 这会创建：```
2^m
```可能的子集。 

对于每个子集，我们将：

 1. 构造转换后的字符串
 2.检查结果数组是否按字典顺序排序
 3. 跟踪所有有效子集中的最小删除

 这种方法保证找到最佳答案，因为它会检查每种可能的删除配置。 

然而，复杂性呈指数级增长。 

如果`m = 100`， 然后：```
2^100
```是一个天文数字，而且完全不可行。 

我们需要更明智的策略。 

### 最优贪心法

 关键的见解是字典顺序是从左到右逐渐确定的。 

比较相邻行时：```
strs[i]
strs[i+1]
```列中有三种可能性：

 -`strs[i][col] < strs[i+1][col]`- 他们的订单永久解决
 -`strs[i][col] == strs[i+1][col]`- 我们仍然需要未来的专栏来确定排序
 -`strs[i][col] > strs[i+1][col]`- 此栏使订购无效，必须删除

 我们从左到右贪婪地处理列。 

我们维护哪些相邻行对已被确认排序正确。 一旦确认了一对，我们就不需要再次比较该对。 

对于每一列：

 - 如果它违反了任何未解析对的排序，我们将其删除
 - 否则，我们保留它并更新新解析的对

 这是有效的，因为稍后删除列无法修复由先前保留的列引起的顺序冲突。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(2^m × n × m) | O(2^m × n × m) | O(n × m) | 尝试已删除列的每个子集 |
 | 最优贪心 | O(n × m) | O(n) | 从左到右处理列，同时跟踪已解析的对 |

 ## 算法演练

 ### 第 1 步：初始化跟踪结构

 我们创造：

 -`deletions`计算删除的列数
 - 布尔数组`sorted_pairs`

`sorted_pairs[i]`方法：```
strs[i] < strs[i+1]
```已经由早期保留的专栏永久建立。 

最初，每一对都未解决。 

### 步骤 2：从左到右处理列

 对于每一列：

 1. 检查保留此列是否会违反任何未解析的相邻对的排序
 2. 如果甚至有一对未解决的问题：```
strs[i][col] > strs[i+1][col]
```那么必须删除该列

 为什么？ 

因为字典比较使用第一个不同的字符。 如果我们保留一个错误的列，则最终的排序将无法在以后修复。 

### 步骤 3：删除无效列

 如果该列无效：

 - 增量`deletions`- 跳过更新任何对状态
 - 移至下一栏

 我们假装这个专栏从未存在过。 

### 步骤 4：更新有效列的解析对

 如果该色谱柱可以安全保留：

 对于每个未解决的相邻对：```
strs[i][col] < strs[i+1][col]
```我们将该对标记为已解决。 

未来的专栏对于这一对来说不再重要。 

### 步骤 5：继续，直到处理完所有列

 处理完所有列后，返回删除总数。 

## 为什么它有效

 贪婪策略是正确的，因为字典顺序取决于第一个不同的字符。 

如果保留的列创建：```
strs[i][col] > strs[i+1][col]
```对于未解决的对，未来的专栏无法修复该违规行为。 因此，必须立即删除该列。 

相反，如果一列安全地维持排序，则保留它只会有所帮助，因为它可能会永久解析其他行对。 

通过贪婪地仅删除必要的列，我们实现了尽可能少的删除。 

## Python 解决方案```python
from typing import List

class Solution:
    def minDeletionSize(self, strs: List[str]) -> int:
        rows = len(strs)
        cols = len(strs[0])

        deletions = 0

        # sorted_pairs[i] means:
        # strs[i] < strs[i + 1] is already guaranteed
        sorted_pairs = [False] * (rows - 1)

        for col in range(cols):

            # Check whether this column causes an invalid ordering
            should_delete = False

            for row in range(rows - 1):
                if not sorted_pairs[row]:
                    if strs[row][col] > strs[row + 1][col]:
                        should_delete = True
                        break

            # Delete the column if invalid
            if should_delete:
                deletions += 1
                continue

            # Otherwise, update resolved pairs
            for row in range(rows - 1):
                if not sorted_pairs[row]:
                    if strs[row][col] < strs[row + 1][col]:
                        sorted_pairs[row] = True

        return deletions
```实现首先确定行数和列数。 

这`sorted_pairs`数组是核心优化。 我们不是重复比较完全构建的字符串，而是跟踪哪些相邻对已经确认了排序。 

对于每一列，我们首先确定该列是否可以安全保留。 我们只比较未解析的对，因为已解析的对不再重要。 

如果我们检测到顺序违规，我们会增加删除计数并完全跳过该列。 

如果该列有效，我们将使用它来解析其他对。 每当：```python
strs[row][col] < strs[row + 1][col]
```这两行之间的相对顺序永久固定。 

最后，删除计数包含已删除列的最小数量。 

## 解决方案```go
func minDeletionSize(strs []string) int {
	rows := len(strs)
	cols := len(strs[0])

	deletions := 0

	// sortedPairs[i] means:
	// strs[i] < strs[i+1] is already guaranteed
	sortedPairs := make([]bool, rows-1)

	for col := 0; col < cols; col++ {

		shouldDelete := false

		// Check whether this column breaks ordering
		for row := 0; row < rows-1; row++ {
			if !sortedPairs[row] {
				if strs[row][col] > strs[row+1][col] {
					shouldDelete = true
					break
				}
			}
		}

		// Delete invalid column
		if shouldDelete {
			deletions++
			continue
		}

		// Update resolved pairs
		for row := 0; row < rows-1; row++ {
			if !sortedPairs[row] {
				if strs[row][col] < strs[row+1][col] {
					sortedPairs[row] = true
				}
			}
		}
	}

	return deletions
}
```Go 实现遵循与 Python 版本相同的逻辑。 

Go 字符串直接支持字节索引，因为输入仅包含小写英文字母。 这允许进行字符比较，例如：```go
strs[row][col]
```无需额外的符文转换。 

这`sortedPairs`slice 与 Python 中完全相同地存储已解析的相邻行关系。 

不需要对整数溢出进行特殊处理，因为所有值相对于 Go 的整数限制都非常小。

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n × m) | 每列扫描相邻的行对 |

 该算法对每一列处理一次。 对于每一列，它可能会扫描所有相邻的行对两次：

 - 一次发现违规行为
 - 一次更新解析对

class Solution:
    def minDeletionSize(self, strs: List[str]) -> int:
        rows = len(strs)
        cols = len(strs[0])

        deletions = 0
        sorted_pairs = [False] * (rows - 1)

        for col in range(cols):

            should_delete = False

 ## 边缘情况

 一种重要的边缘情况是输入中只有一个字符串。 单个字符串始终按字典顺序排序，因为没有要比较的相邻对。 有缺陷的实现可能会错误地尝试配对比较并产生索引错误。 此实现可以自然地处理这种情况，因为相邻对循环执行零次。 

当许多字符串共享长的相等前缀时，会发生另一个重要的情况。 在这些情况下，算法必须避免过早地将对标记为已解决。 仅当找到严格较小的字符时，一对才会被解析。 相同的字符意味着未来的专栏仍然很重要。 这`sorted_pairs`数组正确地保留未解析的对，直到出现决定性的比较。 

第三种棘手的情况是，某列对于大多数对有效，但对一个未解析的对无效。 整个列仍必须删除，因为删除操作全局适用于所有字符串。 在决定保留列之前，实现会正确检查每个未解析的相邻对。 即使是一次违规也会强制删除。 

当一些相邻对已经解析时，会出现最后一个微妙的情况。 未来的列可能包含这些对的降序字符，但这些违规行为不再重要，因为字典顺序已在之前确定。 该实现通过跳过已解析对的比较来避免错误删除。
