[LeetCode 966 题](https://leetcode.com/problems/vowel-spellchecker/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、字符串

 ## 解决方案

 ## 问题理解

 该问题要求我们构建一个具有三个匹配优先级的拼写检查器。 对于每个查询词，我们必须搜索`wordlist`并根据严格的优先顺序返回最佳匹配的单词。 

第一个也是最高优先级的规则是完全匹配。 如果查询与中的某个单词完全匹配`wordlist`，包括相同的大小写，我们立即返回该确切的单词。 

如果没有完全匹配，我们会尝试不区分大小写的匹配。 这意味着如果单词的小写形式相同，则单词被视为相等。 当多个单词满足这个规则时，我们必须返回原文中第一个出现的单词`wordlist`。 

如果仍然没有匹配，我们尝试元音错误匹配。 在此规则中，元音被视为可互换的。 将两个单词转换为小写后，每个元音字符 (`a`,`e`,`i`,`o`,`u`) 被认为是等价的。 例如：

-`"KiTe"`和`"keti"`匹配因为：

 - 小写形式是`"kite"`和`"keti"`- 用占位符替换元音会产生相同的标准化形式

 同样，如果多个单词匹配，我们返回原始单词中第一个出现的单词`wordlist`。 

如果没有任何规则产生匹配，我们返回一个空字符串。 

输入包括：

 -`wordlist`，有效词词典
 -`queries`，我们必须纠正的单词列表

 输出是一个列表，其中每个查询都根据优先级规则替换为最佳匹配的单词。 

限制相对较小：

 - 最多 5000 字
 - 每个单词长度最多7个

 尽管输入大小不是很大，但为每个查询重复扫描整个单词列表的简单实现仍然会变得低效。 由于每个查询可能需要多种比较，因此将字典预处理为有效的查找结构是自然的优化。 

有几个重要的边缘情况：

 - 多个单词可能映射到相同的小写形式，例如`"KiTe"`和`"kite"`。 我们必须保留第一次出现的情况。 
- 多个单词可以映射到相同的元音标准化形式。 同样，必须保留第一次出现的情况。 
- 精确匹配必须始终覆盖不区分大小写或元音匹配。 
- 缺少或多余字符的查询无法匹配，即使元音不同。 
- 没有元音的单词应该仍然可以正常工作。 

## 方法

 ### 蛮力方法

 最简单的解决方案是独立处理每个查询并扫描整个查询`wordlist`多次。 

对于每个查询：

 1. 首先扫描精确匹配。 
2. 如果不存在，则再次扫描是否存在不区分大小写的匹配项。 
3. 如果不存在，则再次扫描元音标准化匹配。 

为了实现元音匹配，我们可以通过以下方式标准化单词：

 - 转换为小写
 - 用常见的占位符替换每个元音，例如`'*'`例如：

-`"KiTe"`→`"k*t*"`-`"keti"`→`"k*t*"`这种强力方法是正确的，因为它按优先级顺序显式检查规则并返回第一个有效匹配。 

然而，它的效率很低，因为每个查询可能需要多次扫描整个单词列表。 由于多达 5000 个查询和 5000 个字典单词，这变得不必要的昂贵。 

### 最佳方法

 关键的观察是匹配规则取决于单词的确定性变换。 

我们可以预处理`wordlist`分为三个查找结构：

 1. 精确匹配的集合
 2.从小写单词→第一个匹配的字典单词的哈希映射
 3. 元音标准化单词 → 第一个匹配字典单词的哈希映射

 然后每个查询都可以在恒定时间查找中得到回答。 

关键的细节是保留原始内容中的第一次出现`wordlist`。 如果键尚不存在，我们通过仅插入哈希映射来实现这一点。 

预处理将重复扫描转化为高效的哈希查找。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(Q × 宽 × 长) | O(1) | O(1) | 重复扫描每个查询的单词列表 |
 | 最佳| O(宽 × 长 + Q × 长) | O(宽 × 长) | 使用哈希图进行预处理以进行快速查找 |

 在哪里：

-`Q`= 查询数
 -`W`= 单词列表中的单词数
 -`L`= 最大字长

 ## 算法演练

 ### 第 1 步：创建精确匹配集

 我们存储每个单词`wordlist`在哈希集中。 

This allows constant time checking for the highest-priority rule, exact case-sensitive matches.

 例如：```
{"KiTe", "kite", "hare", "Hare"}
```### 步骤 2：构建不区分大小写的映射

 对于文中的每一个字`wordlist`：

 1.将其转换为小写
 2. 商店：

 - 小写单词 → 原单词

 仅当小写键尚不存在时我们才插入。 

这保留了首次出现规则。 

示例：

 | 词| 小写键| 储值|
 | --- | --- | --- |
 | 风筝 | 风筝| 风筝 |
 | 风筝| 风筝| 被忽略 |
 | 野兔 | 野兔 | 野兔 |
 | 野兔 | 野兔 | 被忽略 |

 最终地图：```
{
    "kite": "KiTe",
    "hare": "hare"
}
```### 步骤 3：构建元音标准化映射

 我们定义一个标准化函数：

 1. 将单词转换为小写
 2. 将每个元音替换为`'*'`示例：

 | 词| 标准化|
 | ---| ---|
 | 风筝 | k_t_ |
 | 酮 | k_t_ |
 | 野兔 | h_r_ |

 同样，我们只存储第一次出现的情况。 

地图示例：```
{
    "k*t*": "KiTe",
    "h*r*": "hare"
}
```### 步骤 4：处理每个查询

 对于每个查询：

 1.检查精确匹配
 2. 检查小写匹配
 3. 检查元音标准化匹配
 4.否则返回`""`该顺序至关重要，因为该问题指定了严格的优先规则。 

### 第 5 步：收集结果

 将每个查询的所选结果附加到答案列表中。 

## 为什么它有效

 该算法之所以有效，是因为每个匹配规则都对应于一个确定性变换：

 - 精确匹配使用原始单词
 - 不区分大小写的匹配使用小写标准化
 - 元音错误匹配使用元音标准化

 通过将字典预处理为由这些规范化形式作为键控的哈希映射，我们可以直接检索正确的第一个匹配单词。 由于查询是按照严格的优先级顺序检查的，因此返回的结果始终遵循所需的优先级规则。 

## Python 解决方案```python
from typing import List

class Solution:
    def spellchecker(self, wordlist: List[str], queries: List[str]) -> List[str]:
        vowels = set("aeiou")

        def normalize(word: str) -> str:
            chars = []
            
            for ch in word.lower():
                if ch in vowels:
                    chars.append("*")
                else:
                    chars.append(ch)

            return "".join(chars)

        exact_words = set(wordlist)

        case_map = {}
        vowel_map = {}

        for word in wordlist:
            lower_word = word.lower()
            normalized_word = normalize(word)

            if lower_word not in case_map:
                case_map[lower_word] = word

            if normalized_word not in vowel_map:
                vowel_map[normalized_word] = word

        result = []

        for query in queries:
            if query in exact_words:
                result.append(query)
                continue

            lower_query = query.lower()

            if lower_query in case_map:
                result.append(case_map[lower_query])
                continue

            normalized_query = normalize(query)

            if normalized_query in vowel_map:
                result.append(vowel_map[normalized_query])
                continue

            result.append("")

        return result
```实现首先定义规范化辅助函数。 此函数将单词转换为小写并将每个元音替换为`'*'`。 使用共享占位符可确保所有元音变体映射到相同的标准化表示。 

这`exact_words`set 支持常数时间精确匹配。 

这`case_map`字典存储与每个小写形式关联的第一个单词。 条件：```python
if lower_word not in case_map:
```至关重要，因为该问题需要保留原始单词中的第一个匹配单词`wordlist`。 

这`vowel_map`字典的工作原理类似，但使用元音标准化表示作为键。 

处理查询时，实现会按确切的优先顺序检查规则：

 1. 精确匹配
 2. 不区分大小写的匹配
 3. 元音错误匹配

 一旦找到匹配项，相应的单词就会添加到结果列表中。 

## 解决方案```go
package main

import "strings"

func spellchecker(wordlist []string, queries []string) []string {
	vowels := map[byte]bool{
		'a': true,
		'e': true,
		'i': true,
		'o': true,
		'u': true,
	}

	normalize := func(word string) string {
		word = strings.ToLower(word)

		chars := []byte(word)

		for i := 0; i < len(chars); i++ {
			if vowels[chars[i]] {
				chars[i] = '*'
			}
		}

		return string(chars)
	}

	exactWords := make(map[string]bool)

	caseMap := make(map[string]string)
	vowelMap := make(map[string]string)

	for _, word := range wordlist {
		exactWords[word] = true

		lowerWord := strings.ToLower(word)
		normalizedWord := normalize(word)

		if _, exists := caseMap[lowerWord]; !exists {
			caseMap[lowerWord] = word
		}

		if _, exists := vowelMap[normalizedWord]; !exists {
			vowelMap[normalizedWord] = word
		}
	}

	result := make([]string, 0, len(queries))

	for _, query := range queries {
		if exactWords[query] {
			result = append(result, query)
			continue
		}

		lowerQuery := strings.ToLower(query)

		if word, exists := caseMap[lowerQuery]; exists {
			result = append(result, word)
			continue
		}

		normalizedQuery := normalize(query)

		if word, exists := vowelMap[normalizedQuery]; exists {
			result = append(result, word)
			continue
		}

		result = append(result, "")
	}

	return result
}
```Go 解决方案遵循与 Python 版本相同的算法结构。 

一些特定于 Go 的细节值得注意：

 - Go没有内置的集合类型，所以`map[string]bool`用于精确匹配。 
- Go 中的字符串是不可变的，因此规范化会在修改字符之前将字符串转换为字节切片。 
- 这`exists`idiom 用于保留哈希映射中的第一次出现。 
- 结果切片的初始化容量等于查询数量以提高效率。

class Solution:
    def spellchecker(self, wordlist: List[str], queries: List[str]) -> List[str]:

            chars = []

            for ch in word.lower():

 ## 边缘情况

 ### 多个单词映射到相同的小写形式

 错误的常见来源是覆盖不区分大小写映射中的较早条目。 

例如：```
wordlist = ["KiTe", "kite"]
```两者均归一化为`"kite"`小写形式。 该问题需要返回第一个出现的情况，即`"KiTe"`。 

如果键尚不存在，则实现仅通过插入到映射中来正确处理此问题。 

### 精确匹配必须覆盖其他匹配

 考虑：```
wordlist = ["KiTe"]
query = "KiTe"
```此查询也在不区分大小写和元音错误规则下进行匹配，但精确匹配规则具有更高的优先级。 

该实现首先检查精确匹配集，保证正确的优先顺序。 

### 不同长度的单词

 幼稚的实现可能会错误地将缺少或多余字母的单词视为元音匹配。 

例如：```
wordlist = ["YellOw"]
query = "yllw"
```尽管辅音有些对齐，但单词并不等同，因为缺少字符。 

规范化函数保留单词长度和辅音位置，因此这些单词会产生不同的规范化形式，并且无法正确匹配。
