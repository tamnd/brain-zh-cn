[LeetCode 904 题](https://leetcode.com/problems/fruit-into-baskets/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、滑动窗口

 ## 解决方案

 ## 问题理解

 该问题要求我们找到最多包含两个不同值的最长连续子数组的长度。 

中的每个元素`fruits`数组代表一棵树结出的果实的类型。 我们可以从任何位置开始，只向右移动，从我们访问的每棵树上采集一个水果。 然而，我们只有两个篮子，每个篮子只能装一种水果。 

这意味着在遍历数组时，我们最多可以从两种不同的水果类型中收集水果。 当我们遇到第三种水果时，我们必须停下来。 

目标是确定我们在一次连续步行中可以收集的最大水果数量。 

例如，在：```
[1,2,3,2,2]
```最多具有两种不同水果类型的最长有效连续段是：```
[2,3,2,2]
```其中有长度`4`。 

约束条件很重要：

 -`1 <= fruits.length <= 10^5`-`0 <= fruits[i] < fruits.length`输入大小为`10^5`意味着一个`O(n^2)`解决方案可能会太慢。 我们需要一个线性或近线性算法。 

该问题保证：

 - 数组非空。 
- 水果类型是整数。 
- 我们只关心连续的线段，因为我们必须不断向右移动而不跳过树。 

需要考虑一些重要的边缘情况：

 - 仅包含一种水果类型的数组。 
- 恰好有两种水果类型的数组。 
- 每个元素都不同的数组。 
- 遇到第三种水果后，有效窗口必须多次缩小的情况。 
- 非常小的数组，例如长度`1`。 

简单的实现可能会重复扫描子数组，导致时间复杂度为二次方。 

## 方法

 ### 蛮力方法

 蛮力的想法是考虑每个可能的起始位置并将子数组向右扩展，直到出现两种以上不同的水果类型。 

对于每个起始索引：

 1. 创建集合或频率图。 
2. 一次一步地扩展结束索引。 
3. 当不同水果类型的数量超过两种时停止。 
4. 记录找到的最大有效长度。 

这是有效的，因为它显式地检查每个可能的连续段。 

然而，问题是效率。 如果我们尝试所有起始位置并每次向前扫描，则总复杂度变为`O(n^2)`在最坏的情况下。 

和`n = 10^5`，二次复杂度太慢。 

### 最优滑动窗口方法

 关键的观察是我们只关心最多包含两种不同水果类型的连续子数组。 

这是一个经典的滑动窗口场景：

 - 我们维护一个窗口`[left, right]`。 
- 窗口始终满足规则：```
at most two distinct fruit types
```当我们通过移动来扩大窗口时`right`转发：

 - 我们将新水果添加到频率图中。 
- 如果窗口变得无效，意味着它包含两种以上的水果类型，我们会从左侧缩小它，直到它再次有效。 

在每一步中，当前窗口都代表一个有效的收集路径。 

由于每个元素最多进入和离开窗口一次，因此该算法以线性时间运行。

 ## 算法演练

 ### 最优滑动窗口算法

 1.初始化两个指针：

 -`left = 0`-`right`将迭代数组。 
2. 创建一个名为的哈希图`fruit_count`。 

该地图存储：```
fruit type -> frequency inside current window
```3. 初始化变量`max_fruits = 0`。 
4. 使用迭代遍历数组`right`。 
5. 对于每个`fruits[right]`:

 - 将其添加到频率图。 
- 增加其数量。 
6.添加新水果后，检查窗口是否失效。 

该窗口在以下情况下无效：```
len(fruit_count) > 2
```7. 当窗口无效时：

 - 删除`fruits[left]`从窗口。 
- 减少其计数。 
- 如果其计数变为零，则从地图上完全删除该水果类型。 
- 移动`left`向前。 
8. 此时，窗口再次有效。 

当前窗口长度为：```
right - left + 1
```9. 更新`max_fruits`如果当前窗口更大。 
10. 继续，直到处理完整个数组。 
11. 返回`max_fruits`。 

### 为什么它有效

 滑动窗口始终维护一个有效的连续子数组，最多包含两种不同的水果类型。 

每当出现第三种水果类型时，我们就会从左侧缩小窗口，直到再次只剩下两种水果。 

因为在扩展过程中每个有效窗口都会被考虑一次，并且算法总是保留迄今为止看到的最大有效窗口，所以最终的答案保证是正确的。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def totalFruit(self, fruits: List[int]) -> int:
        left = 0
        max_fruits = 0
        
        fruit_count = defaultdict(int)
        
        for right in range(len(fruits)):
            fruit = fruits[right]
            fruit_count[fruit] += 1
            
            while len(fruit_count) > 2:
                left_fruit = fruits[left]
                fruit_count[left_fruit] -= 1
                
                if fruit_count[left_fruit] == 0:
                    del fruit_count[left_fruit]
                
                left += 1
            
            current_window = right - left + 1
            max_fruits = max(max_fruits, current_window)
        
        return max_fruits
```该实现首先初始化滑动窗口边界和频率图。 

这`fruit_count`字典跟踪每种水果类型在当前窗口中出现的次数。 这使我们能够有效地确定当前存在多少种不同的水果类型。 

这`right`指针一次将窗口展开一个元素。 每个新水果都会添加到频率图中。 

如果添加新水果导致不同水果类型的数量超过两种，则该窗口无效。 这`while`然后循环从左侧缩小窗口，直到再次满足约束。 

每当水果数量变为零时，该水果类型就会从字典中完全删除。 这可以确保：```python
len(fruit_count)
```正确表示窗口中不同水果类型的数量。 

恢复有效性后，将计算当前窗口长度并将其与迄今为止找到的最佳答案进行比较。 

由于每个指针仅向前移动，因此该算法在线性时间内高效运行。 

## 解决方案```go
func totalFruit(fruits []int) int {
    left := 0
    maxFruits := 0

    fruitCount := make(map[int]int)

    for right := 0; right < len(fruits); right++ {
        fruit := fruits[right]
        fruitCount[fruit]++

        for len(fruitCount) > 2 {
            leftFruit := fruits[left]
            fruitCount[leftFruit]--

            if fruitCount[leftFruit] == 0 {
                delete(fruitCount, leftFruit)
            }

            left++
        }

        currentWindow := right - left + 1

        if currentWindow > maxFruits {
            maxFruits = currentWindow
        }
    }

    return maxFruits
}
```Go 实现遵循与 Python 解决方案相同的滑动窗口逻辑。 

Go 使用内置地图：```go
map[int]int
```存储水果频率。 

与Python不同`defaultdict`，Go 映射会针对缺失的键自动返回零值，因此递增计数自然有效。 

这`delete()`函数删除计数为零的水果类型，确保地图大小准确反映当前窗口中不同水果类型的数量。 

整数溢出不是问题，因为最大数组长度仅为`10^5`。

 ## 边缘情况

 ### 单元素数组

 仅包含一棵树的数组是最小的有效输入。 

例子：```
[5]
```有缺陷的实现可能会错误地假设至少存在两个元素或错误地处理窗口初始化。 

这个实现很自然地处理它，因为滑动窗口开始为空并正常扩展。 最大窗口大小变为`1`。 

### 所有树都有相同的果实类型

 示例：```
[2,2,2,2,2]
```一些实现不必要地缩小了窗口或错误地计算了不同的水果类型。 

在这里，频率图总是恰好包含一个键，因此窗口永远不会变得无效。 该算法正确返回整个数组长度。 

### 每种水果类型都不同

 示例：```
[1,2,3,4,5]
```这种情况迫使窗口频繁缩小。 

幼稚的实现可能无法正确删除计数为零的水果类型，从而导致不同计数仍然不正确。 

当条目的频率达到零时，该解决方案就会从频率图中删除条目，从而确保窗口有效性条件保持准确。 

### 长交替模式

 示例：```
[1,2,1,2,1,2,1]
```整个数组有效，因为只出现了两种水果类型。 

不正确的实现可能会在看到重复交替时过早地缩小窗口。 

该算法正确地识别出不同水果类型的数量永远不会超过两种，因此整个数组都被计算在内。
