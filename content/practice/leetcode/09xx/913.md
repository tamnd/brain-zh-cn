 ## 解决方案

 ## 问题理解

 在这个问题中，我们给出了一个无向图，其中两个玩家（老鼠和猫）根据特定规则在图上交替移动。 该图表示为邻接列表，其中`graph[a]`包含直接连接到节点的所有节点`a`。 

鼠标总是从节点开始`1`，并且 Cat 总是从节点开始`2`。 鼠标先移动。 有一个特殊的节点，node`0`，代表一个洞。 如果鼠标到达节点`0`，老鼠立即获胜。 如果猫曾经占据与老鼠相同的节点，则猫立即获胜。 

猫还有一个额外的限制：它不能移入节点处的洞中`0`。 

比赛也可能以平局结束。 当完全相同的游戏状态再次出现时，就会发生平局。 游戏状态由三部分信息组成：

 - 鼠标的位置
 - 猫的位置
 - 轮到谁了

 如果这三者都重复，则游戏被视为无限，结果为平局。 

该问题要求我们在假设双方都发挥最佳状态的情况下确定游戏的结果。 我们必须返回：

 -`1`如果老鼠能强行获胜
 -`2`如果猫能强行获胜
 -`0`如果双方都无法取得胜利并且比赛以平局结束

 限制因素很重要。 该图最多包含`50`节点，这意味着可能的游戏状态总数是可控的：

 - 鼠标位置：`50`- 猫的位置：`50`- 回合：`2`这最多给出`50 × 50 × 2 = 5000`州。 

这个数字足够小，我们可以将问题视为状态图并执行基于图的动态规划或逆行分析。 

一些边缘情况很重要：

 - 老鼠可能已经接近洞并立即获胜。 
- 猫可能会很快困住老鼠。 
- 图中的循环可能会产生无限循环，因此会绘制。 
- 由于猫无法进入节点`0`，我们必须小心地排除这些转变。 
- 有些状态无法立即确定，只有在通过游戏图向后传播信息后才能解决。 

简单的递归模拟可以轻松地重复访问相同的状态，并且在没有循环检测的情况下可能无法正确终止。 

## 方法

 ### 蛮力方法

 一种简单的方法是使用极小极大逻辑递归地模拟所有可能的游戏路径。 

对于每个州`(mouse, cat, turn)`:

 - 如果鼠标到达节点`0`，返回鼠标获胜。 
- 如果老鼠和猫占据同一个节点，则返回猫获胜。 
- 否则：

 - 如果轮到老鼠了，尝试老鼠的每一个动作。 
- 如果轮到猫了，尝试除了节点之外的每一个猫的动作`0`。 

当前玩家选择能够最大化其结果的行动。 

然而，这种方法遇到了一个主要问题：周期。 

由于图形可能包含循环，因此相同的游戏状态可能会重复出现。 如果没有记忆和循环跟踪，递归可能永远不会终止。 即使使用记忆，正确处理绘图也会变得极其复杂，因为某些状态递归地依赖于自身。 

蛮力搜索有效地探索了指数级大的博弈树。 

### 最佳解决方案背后的关键见解

 关键的观察是，这是一个状态数量有限的有限确定性博弈。 

我们可以从已知的结果向后推算，而不是从起始位置向前搜索。 

这种技术称为逆行分析，通常使用游戏状态上的拓扑传播来解决。 

我们将状态分为三类：

 - 鼠标获胜
 - 猫获胜
 - 抽奖

 我们从结果已知的状态开始：

 - 如果鼠标位于节点`0`，鼠标获胜。 
- 如果老鼠和猫在同一节点上，则猫获胜。 

然后我们将这些结果向后传播到前驱状态。 

关键的博弈论规则是：

 - 如果玩家可以进入自己的获胜状态，那么当前状态对该玩家来说就是获胜。 
- 如果每一步可能的行动都会导致对手获胜，那么当前的状态就是失败。 

这将问题转化为类似于拓扑排序的图传播问题。 

由于状态数量是有界的，因此这种方法可以有效地求解整个游戏状态空间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 指数| 指数| 递归探索所有可能的游戏路径 |
 | 最佳| O(n3) | O(n3) | 使用反向 BFS 和游戏状态传播 |

 ## 算法演练

 ### 状态定义

 我们使用以下方式表示每个游戏状态：

 -`mouse`位置
-`cat`位置
-`turn`在哪里：

-`turn = 0`表示鼠标下一步移动
 -`turn = 1`意味着猫接下来要移动

 我们存储：

 -`color[mouse][cat][turn]`-`0`= 抽奖/未知
 -`1`= 鼠标获胜
 -`2`= 猫赢了

 我们还维护：

 -`degree[mouse][cat][turn]`这代表该状态还剩下多少合法动作。 

### 逐步算法

 1. 将所有状态初始化为平局。 

最初，我们不知道大多数州的结果。 每个州一开始都是犹豫不决的。 
2. 标记最终获胜状态。 

这些状态是立即可知的：

 - 如果`mouse == 0`，老鼠已经到达洞口了，所以老鼠获胜。 
- 如果`mouse == cat`，猫已经抓住了老鼠，所以猫赢了。 

这些状态被插入到队列中以进行 BFS 传播。 
3. 计算每个状态的出度。 

对于每个状态，计算当前玩家有多少合法动作。 

这很重要，因为如果所有举措最终都失败了，那么国家本身就会失败。 

对于鼠标转动：

 - 度数等于老鼠邻居的数量。 

对于 Cat 转弯：

 - 度数等于不包括节点的 Cat 邻居的数量`0`。 
4. 使用反向 BFS 处理状态。 

我们反复从队列中删除已解决的状态。 

假设状态`(m, c, t)`已知是老鼠获胜或猫获胜。 

然后我们检查所有可能进入的前任状态`(m, c, t)`。 
5. 确定前置结果。 

对于每个前任：

 - 如果前任玩家可以进入获胜状态，则立即将前任玩家标记为获胜。 
- 否则，减少其程度。 
- 如果度数为零，则每一步都会导致对手获胜，因此将前任标记为失败。 
6. 继续，直到队列变空。 

最终所有被迫的胜利和失败都会通过状态图传播。 

任何剩余的未解决状态都是平局。 
7. 返回起始状态结果。 

初始游戏状态为：

 - 鼠标位于`1`- 猫在`2`- 鼠标转动

 返回该状态的计算结果。 

### 为什么它有效

 该算法之所以有效，是因为每个游戏状态仅取决于未来状态。 通过从终端状态开始向后传播，我们保证当一个状态被解析时，其结果在逻辑上是正确的。 

如果当前玩家至少有一步棋可以让对手进入失败状态，则该状态变为获胜状态。 如果每一个可能的举动都会导致对手获胜，那么一个国家就会失败。 

这完全符合最佳游戏玩法。 

由于状态总数是有限的，BFS 传播最终会稳定下来。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def catMouseGame(self, graph: List[List[int]]) -> int:
        n = len(graph)

        DRAW = 0
        MOUSE = 1
        CAT = 2

        MOUSE_TURN = 0
        CAT_TURN = 1

        color = [[[DRAW] * 2 for _ in range(n)] for _ in range(n)]
        degree = [[[0] * 2 for _ in range(n)] for _ in range(n)]

        # Compute degrees
        for mouse in range(n):
            for cat in range(n):
                degree[mouse][cat][MOUSE_TURN] = len(graph[mouse])

                cat_moves = 0
                for nxt in graph[cat]:
                    if nxt != 0:
                        cat_moves += 1

                degree[mouse][cat][CAT_TURN] = cat_moves

        queue = deque()

        # Mouse reaches hole -> Mouse wins
        for cat in range(n):
            for turn in range(2):
                if color[0][cat][turn] == DRAW:
                    color[0][cat][turn] = MOUSE
                    queue.append((0, cat, turn, MOUSE))

        # Cat catches mouse -> Cat wins
        for node in range(1, n):
            for turn in range(2):
                if color[node][node][turn] == DRAW:
                    color[node][node][turn] = CAT
                    queue.append((node, node, turn, CAT))

        def parents(mouse: int, cat: int, turn: int):
            if turn == MOUSE_TURN:
                # Previous was Cat turn
                for prev_cat in graph[cat]:
                    if prev_cat != 0:
                        yield mouse, prev_cat, CAT_TURN
            else:
                # Previous was Mouse turn
                for prev_mouse in graph[mouse]:
                    yield prev_mouse, cat, MOUSE_TURN

        while queue:
            mouse, cat, turn, result = queue.popleft()

            for pmouse, pcat, pturn in parents(mouse, cat, turn):
                if color[pmouse][pcat][pturn] != DRAW:
                    continue

                # Current player can force a win
                if (
                    (pturn == MOUSE_TURN and result == MOUSE)
                    or
                    (pturn == CAT_TURN and result == CAT)
                ):
                    color[pmouse][pcat][pturn] = result
                    queue.append((pmouse, pcat, pturn, result))
                else:
                    degree[pmouse][pcat][pturn] -= 1

                    # All moves lose
                    if degree[pmouse][pcat][pturn] == 0:
                        losing_result = CAT if pturn == MOUSE_TURN else MOUSE

                        color[pmouse][pcat][pturn] = losing_result
                        queue.append(
                            (pmouse, pcat, pturn, losing_result)
                        )

        return color[1][2][MOUSE_TURN]
```实现首先定义代表游戏结果和玩家回合的常量。 这使得逻辑更具可读性，并避免在整个代码中依赖幻数。 

这`color`数组存储每个状态的解析结果。 最初，所有状态都标记为`DRAW`，意思是未解决。 

这`degree`数组跟踪每个状态还剩下多少合法的移动。 这对于确定一个国家何时会失败至关重要，因为所有选择都已用尽。 

该算法首先初始化终端状态：

 - 鼠标在节点上`0`鼠标立即获胜。 
- 鼠标和猫在同一节点上，猫会立即获胜。 

这些状态被插入到 BFS 队列中。 

这`parents`生成器计算游戏图中的反向边。 我们不是从一个状态继续前进，而是确定哪些早期状态可以转换到当前状态。 

BFS 传播期间：

 - 如果前任玩家能够进入保证自己获胜的状态，则前任玩家立即获胜。 
- 否则，我们减少前驱度数。 
- 一旦所有动作都用尽，前任就失败了。 

最后，未解决的状态仍然是绘制的，我们返回初始状态的值`(1, 2, MouseTurn)`。 

## 解决方案```go
package main

import "container/list"

func catMouseGame(graph [][]int) int {
	n := len(graph)

	const (
		DRAW  = 0
		MOUSE = 1
		CAT   = 2
	)

	const (
		MOUSE_TURN = 0
		CAT_TURN   = 1
	)

	color := make([][][]int, n)
	degree := make([][][]int, n)

	for i := 0; i < n; i++ {
		color[i] = make([][]int, n)
		degree[i] = make([][]int, n)

		for j := 0; j < n; j++ {
			color[i][j] = make([]int, 2)
			degree[i][j] = make([]int, 2)
		}
	}

	// Compute degrees
	for mouse := 0; mouse < n; mouse++ {
		for cat := 0; cat < n; cat++ {
			degree[mouse][cat][MOUSE_TURN] = len(graph[mouse])

			catMoves := 0
			for _, nxt := range graph[cat] {
				if nxt != 0 {
					catMoves++
				}
			}

			degree[mouse][cat][CAT_TURN] = catMoves
		}
	}

	type State struct {
		mouse  int
		cat    int
		turn   int
		result int
	}

	queue := list.New()

	// Mouse reaches hole
	for cat := 0; cat < n; cat++ {
		for turn := 0; turn < 2; turn++ {
			color[0][cat][turn] = MOUSE
			queue.PushBack(State{0, cat, turn, MOUSE})
		}
	}

	// Cat catches mouse
	for node := 1; node < n; node++ {
		for turn := 0; turn < 2; turn++ {
			color[node][node][turn] = CAT
			queue.PushBack(State{node, node, turn, CAT})
		}
	}

	for queue.Len() > 0 {
		front := queue.Front()
		queue.Remove(front)

		state := front.Value.(State)

		mouse := state.mouse
		cat := state.cat
		turn := state.turn
		result := state.result

		if turn == MOUSE_TURN {
			// Parent was Cat turn
			for _, prevCat := range graph[cat] {
				if prevCat == 0 {
					continue
				}

				pmouse := mouse
				pcat := prevCat
				pturn := CAT_TURN

				if color[pmouse][pcat][pturn] != DRAW {
					continue
				}

				if result == CAT {
					color[pmouse][pcat][pturn] = CAT
					queue.PushBack(State{
						pmouse,
						pcat,
						pturn,
						CAT,
					})
				} else {
					degree[pmouse][pcat][pturn]--

					if degree[pmouse][pcat][pturn] == 0 {
						color[pmouse][pcat][pturn] = MOUSE
						queue.PushBack(State{
							pmouse,
							pcat,
							pturn,
							MOUSE,
						})
					}
				}
			}
		} else {
			// Parent was Mouse turn
			for _, prevMouse := range graph[mouse] {
				pmouse := prevMouse
				pcat := cat
				pturn := MOUSE_TURN

				if color[pmouse][pcat][pturn] != DRAW {
					continue
				}

				if result == MOUSE {
					color[pmouse][pcat][pturn] = MOUSE
					queue.PushBack(State{
						pmouse,
						pcat,
						pturn,
						MOUSE,
					})
				} else {
					degree[pmouse][pcat][pturn]--

					if degree[pmouse][pcat][pturn] == 0 {
						color[pmouse][pcat][pturn] = CAT
						queue.PushBack(State{
							pmouse,
							pcat,
							pturn,
							CAT,
						})
					}
				}
			}
		}
	}

	return color[1][2][MOUSE_TURN]
}
```Go 实现与 Python 版本非常相似，但存在一些特定于语言的差异。 

Go 不会自动提供动态多维数组，因此我们显式分配了所有三个维度`color`和`degree`。 

BFS队列使用`container/list`，因为 Go 没有内置的双端队列结构。 

定制`State`struct 干净地存储 BFS 状态信息。 

由于 Go 切片是引用类型，因此邻接遍历无需复制数据即可保持高效。 

整数溢出不是问题，因为状态计数非常小。

空间复杂度来自于存储：

 - 每个状态的结果
 - 每个州的程度

 所有这些都受到游戏状态数量的限制。

from typing import List

class Solution:
    def catMouseGame(self, graph: List[List[int]]) -> int:
        from collections import deque

        n = len(graph)

        DRAW = 0
        MOUSE = 1
        CAT = 2

        MOUSE_TURN = 0
        CAT_TURN = 1

        color = [[[DRAW] * 2 for _ in range(n)] for _ in range(n)]
        degree = [[[0] * 2 for _ in range(n)] for _ in range(n)]

        for m in range(n):
            for c in range(n):
                degree[m][c][MOUSE_TURN] = len(graph[m])
                degree[m][c][CAT_TURN] = sum(
                    1 for nxt in graph[c] if nxt != 0
                )

        queue = deque()

        for c in range(n):
            for t in range(2):
                color[0][c][t] = MOUSE
                queue.append((0, c, t, MOUSE))

        for x in range(1, n):
            for t in range(2):
                color[x][x][t] = CAT
                queue.append((x, x, t, CAT))

        def parents(m, c, t):
            if t == MOUSE_TURN:
                for pc in graph[c]:
                    if pc != 0:
                        yield m, pc, CAT_TURN
            else:
                for pm in graph[m]:
                    yield pm, c, MOUSE_TURN

        while queue:
            m, c, t, result = queue.popleft()

            for pm, pc, pt in parents(m, c, t):
                if color[pm][pc][pt] != DRAW:
                    continue

                if (
                    (pt == MOUSE_TURN and result == MOUSE)
                    or
                    (pt == CAT_TURN and result == CAT)
                ):
                    color[pm][pc][pt] = result
                    queue.append((pm, pc, pt, result))
                else:
                    degree[pm][pc][pt] -= 1

                    if degree[pm][pc][pt] == 0:
                        lose = CAT if pt == MOUSE_TURN else MOUSE
                        color[pm][pc][pt] = lose
                        queue.append((pm, pc, pt, lose))

        return color[1][2][MOUSE_TURN]

 ## 边缘情况

 当鼠标可以立即移入洞中时，就会出现一种重要的边缘情况。 幼稚的实现可能会不必要地继续搜索更深层次的游戏状态，但正确的行为是通过鼠标获胜立即终止。 该实现通过初始化所有状态来处理这个问题`mouse == 0`作为 BFS 传播开始之前的最终鼠标获胜状态。 

另一个关键的边缘情况涉及永远不会转化为强制胜利的循环。 如果不仔细处理，递归解决方案可能会永远循环或错误地对这些状态进行分类。 反向 BFS 方法完全避免了这个问题，因为在所有强制获胜和失败传播后，未解决的状态自然会保持标记为平局。 

第三种微妙的情况发生是因为猫被禁止进入节点`0`。 忘记这个限制可能会完全改变游戏结果并产生无效的转换。 该实现明确排除节点`0`每当生成 Cat 移动和计算 Cat 出度时。 

最后的边缘情况涉及每一种可能的行动都会导致对手获胜的状态。 有些实现在发现失败的一步后会错误地停止。 然而，一个国家只有在所有合法举措都用尽之后才变得失败。 度跟踪机制通过减少剩余的有效移动直到没有剩余移动来保证正确处理这种情况。
