[LeetCode 第 932 题](https://leetcode.com/problems/beautiful-array/)

 **难度：** 🟡 中等
 **主题：** 数组、数学、分而治之

 ## 解决方案

 ## 问题理解

 该问题要求我们构造一个整数的排列`1`到`n`使得数组满足特殊条件。 具体来说，对于每对索引`i < j`, 不得存在任何索引`k`他们之间：$2 \cdot nums[k] = nums[i] + nums[j]$这个条件意味着中间的元素不能是周围两个元素的算术平均值。 换句话说，数组不能包含按索引顺序排列时形成算术级数的任何三个值。 

输入由单个整数组成`n`，表示我们必须生成的排列的大小。 输出应该是任何有效的漂亮长度数组`n`。 该问题保证至少有一个解决方案始终存在。 

约束条件相对较小，`n <= 1000`，但挑战不在于大输入量的原始性能。 相反，挑战在于发现能够有效构建此类数组的数学结构。 

幼稚的实现很容易失败，因为检查每个可能的三元组`(i, k, j)`会非常昂贵。 另一个常见问题是生成有效的排列，同时保持美丽的属性。 因为每个数字都来自`1`到`n`必须恰好出现一次，粗心的构造方法可能会意外引入算术级数。 

一些边缘情况很重要：

 - 当`n = 1`，唯一有效的答案是`[1]`。 
- 小值，例如`n = 2`或者`n = 3`对于验证构造逻辑很有用。 
- 较大的值需要确保在组合较小的子数组后不会出现隐藏的算术级数。 
- 解决方案必须保证元素的唯一性，同时保留美丽的财产。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试生成以下数字的排列`1`到`n`并检查每个排列是否满足美丽条件。 

为了验证排列，我们将检查每一对`(i, j)`并检查所有索引`k`在它们之间确定是否：$2 \cdot nums[k] = nums[i] + nums[j]$如果有这样一个`k`存在，则排列无效。 

这种方法是正确的，因为它直接测试问题的定义。 然而，这在计算上是不可行的。 有`n!`排列，验证每个排列大约需要`O(n^3)`最坏情况下的时间。 即使对于中等值`n`，这变得不可能。 

### 最佳分而治之的见解

 关键的见解是，美丽的财产在某些转变下得以保留。 

假设我们已经有一个漂亮的数组`A`。 然后：

 - 将每个元素乘以`2`并减去`1`只产生奇数。 
- 将每个元素乘以`2`只产生偶数。 

最重要的是，两个变换后的数组仍然很漂亮。 

这是可行的，因为算术级数关系在线性变换下得以保留。 此外，奇数和偶数不能组合起来形成所需的相等条件。 

递归结构变为：

 - 为奇数位置构建一个漂亮的数组。 
- 为偶数位置构建漂亮的数组。 
- 将它们连接在一起。 

例如：

 - 来自`[1]`- 产生赔率：`[1]`- 生成事件：`[2]`- 合并成`[1,2]`然后继续递归：

 - 赔率来自`[1,2]`变得`[1,3]`- 埃文斯来自`[1,2]`变得`[2,4]`- 合并成`[1,3,2,4]`这种结构保证了正确性，同时完全避免了暴力搜索。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n! × n3) | O(n! × n3) | O(n) | 尝试每一种排列并验证每一种 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 使用递归分而治之构造 |

 ## 算法演练

 1. 从一个基本的美丽数组开始，仅包含`[1]`。 

单个元素数组非常漂亮，因为没有三元组违反条件。 
2. 使用奇数和偶数变换重复扩展数组。 

对于每个数字`x`在当前美丽的数组中：

 - 使用生成奇数值`2*x - 1`- 使用生成偶数值`2*x`3. 仅保留小于或等于的值`n`。 

转换可能会产生大于`n`，这在最终排列中是不允许的。 
4.构造下一个漂亮的数组。 

首先附加所有有效的奇数值，然后附加所有有效的偶数值。 

顺序很重要，因为：

 - 奇怪的部分内部仍然很漂亮。 
- 均匀部分内部保持美丽。 
- 奇数和偶数不能一起创建禁止的算术级数。 
5. 继续扩展，直到数组包含`n`元素。 

由于每次迭代大约使有效元素的数量增加一倍，因此该过程很快完成。 

### 为什么它有效

 核心不变量是每个中间数组都保持美观。 

如果一个数组`A`很漂亮，那么两个变换后的数组：$2A-1$和$2A$也很漂亮，因为线性变换保留了算术级数的缺失。 

此外，组合奇数和偶数不会导致违规，因为：

 - 奇数和偶数的平均值不是整数。 
- 因此，没有任何中间元素能够满足跨越两组的美丽条件。 

这保证了最终的串联数组是漂亮的。 

## Python 解决方案```python
from typing import List

class Solution:
    def beautifulArray(self, n: int) -> List[int]:
        beautiful = [1]

        while len(beautiful) < n:
            next_array = []

            # Generate odd numbers
            for value in beautiful:
                odd = 2 * value - 1
                if odd <= n:
                    next_array.append(odd)

            # Generate even numbers
            for value in beautiful:
                even = 2 * value
                if even <= n:
                    next_array.append(even)

            beautiful = next_array

        return beautiful
```实施从基本案例开始`[1]`，已经很漂亮了。 

主循环重复扩展当前数组。 在每次迭代期间，分两个阶段构建一个新数组。 

第一阶段使用生成奇数`2 * value - 1`。 这些值保留了 beautiful 属性，因为它们只是先前 beautiful 数组的转换版本。 

第二阶段使用生成偶数`2 * value`。 美丽的财产再次被保留。 

值大于`n`被跳过，因为最终的排列必须只包含范围内的整数`[1, n]`。 

最后，新生成的数组替换之前的数组，这个过程一直持续到恰好`n`存在有效值。 

## 解决方案```go
func beautifulArray(n int) []int {
    beautiful := []int{1}

    for len(beautiful) < n {
        nextArray := []int{}

        // Generate odd numbers
        for _, value := range beautiful {
            odd := 2*value - 1
            if odd <= n {
                nextArray = append(nextArray, odd)
            }
        }

        // Generate even numbers
        for _, value := range beautiful {
            even := 2 * value
            if even <= n {
                nextArray = append(nextArray, even)
            }
        }

        beautiful = nextArray
    }

    return beautiful
}
```Go 实现遵循与 Python 版本相同的逻辑。 

使用切片而不是动态列表。 这`append`函数自动处理动态调整大小。 

整数溢出不是一个问题，因为`n <= 1000`，因此所有生成的值相对于 Go 的整数限制仍然非常小。 

与 Python 不同，Go 没有内置列表推导式，因此使用显式循环来构造奇数部分和偶数部分。

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n log n) | O(n log n) | 每次扩展都会处理当前数组，每次迭代数组大小大约加倍 |

空间复杂度是线性的，因为该算法只存储当前的漂亮数组和下一个生成的数组。

def is_beautiful(arr):
    n = len(arr)

    # Must be a permutation of 1..n
    assert sorted(arr) == list(range(1, n + 1))

    # Check beautiful condition
    for i in range(n):
        for j in range(i + 1, n):
            for k in range(i + 1, j):
                assert 2 * arr[k] != arr[i] + arr[j]

    return True

 ## 边缘情况

 一个重要的边缘情况是`n = 1`。 简单的递归解决方案可能会意外地假设总是有多个元素需要划分或转换。 在这个实现中，算法直接从`[1]`，它已经满足了美丽的条件，所以结果立即返回。 

当转换后的值超过`n`。 在递归扩展期间，诸如`2*x`或者`2*x-1`可能会变得大于允许的范围。 如果包含这些值，结果将不再是有效的排列`1`通过`n`。 该实现使用显式过滤值`if odd <= n`和`if even <= n`。 

第三种边缘情况涉及在保留美丽财产的同时保持独特性。 一些简单的构造会意外地重复值或完全跳过数字。 此实现避免了该问题，因为奇数变换始终生成不同的奇数，而偶数变换始终生成不同的偶数。 由于奇数集和偶数集不相交，因此不会出现重复。 

另一个微妙的边缘情况是确保组合两个有效的漂亮数组不会意外地引入跨越边界的算术级数。 奇偶划分保证了这种情况不会发生，因为奇数和偶数的平均值是小数，使得禁止的相等不可能发生。
