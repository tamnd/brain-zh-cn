[LeetCode 第 974 题](https://leetcode.com/problems/subarray-sums-divisible-by-k/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、前缀和

 ## 解决方案

 ## 问题理解

 该问题要求我们计算有多少个非空连续子数组的总和可被给定整数整除`k`。 

子数组是数组的任何连续段。 例如，在数组中`[1,2,3]`，子数组包括`[1]`,`[2]`,`[3]`,`[1,2]`,`[2,3]`， 和`[1,2,3]`。 

对于每个可能的子数组，我们计算其总和。 如果求和模`k`等于`0`，那么该子数组被认为是有效的。 任务是返回此类有效子数组的总数。 

输入包括：

 -`nums`，一个可以包含正值和负值的整数数组
 -`k`, 正整数除数

 输出是一个整数，表示有效子数组的数量。 

约束很重要，因为它们决定哪些算法可行：

 -`nums.length`可以大到`3 * 10^4`- 每个数字都可以为负数
 -`k`可以达到`10^4`单独检查每个子数组的简单解决方案将需要二次时间，这对于这种大小的数组来说太慢了。 

负数会带来额外的复杂性。 在许多编程语言中，负值的模运算会产生负余数。 正确的实现必须对余数进行标准化，使其始终落在范围内`[0, k-1]`。 

一些边缘情况尤其重要：

 - 包含负数的数组
 - 许多前缀和产生相同余数的数组
 - 不存在有效子数组的数组
 - 完全由零组成的数组
 - 单元素数组

 该问题保证了`k >= 2`，所以除以零从来都不是问题。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每个可能的子数组。 

对于每个起始索引`i`，我们将子数组扩展到每个结束索引`j >= i`，计算子数组总和，并检查总和是否能被整除`k`。 

对此进行稍微优化的一种方法是在扩展子数组时保持运行总和，而不是每次都从头开始重新计算总和。 

这种方法是正确的，因为它显式地评估每个可能的子数组并计算有效的子数组。 

但是，长度数组中子数组的数量`n`是：$$\frac{n(n+1)}{2}$$和`n = 30000`，这变得太大了。 一个`O(n^2)`解决方案不会在时限内通过。 

### 最优前缀和+哈希图方法

 关键的见解来自前缀和和模运算。 

认为：

-`prefixSum[i]`是索引中元素的总和`0`通过`i`- 我们想要子数组的和`(l...r)`该总和等于：$$prefixSum[r] - prefixSum[l-1]$$我们希望这个值可以被整除`k`:$$(prefixSum[r] - prefixSum[l-1]) \mod k = 0$$重新排列：$$prefixSum[r] \mod k = prefixSum[l-1] \mod k$$这意味着：

 两个前缀和具有相同的余数模`k`定义一个子数组，其总和可被整除`k`。 

因此，我们不是直接检查每个子数组，而是：

 - 增量计算前缀和
 - 跟踪每个余数出现的次数
 - 每当我们再次看到相同的余数时，我们就知道存在其他有效子数组

 哈希映射是理想的，因为它允许恒定时间查找和更新剩余频率。

 ## 算法演练

 ### 最优算法

 1. 初始化一个名为的哈希图`remainder_count`。 

该映射存储在处理前缀和时每个余数出现的次数。 

我们从以下开始：```
remainder_count = {0: 1}
```这非常重要，因为前缀和本身可能已经可以被整除`k`。 最初的`0:1`代表空前缀。 
2.初始化三个变量：

 -`prefix_sum = 0`-`result = 0`-`remainder_count = {0:1}`3. 迭代数组中的每个数字。 

在每一步中，将当前数字添加到`prefix_sum`。 
4. 计算当前余数。```
remainder = prefix_sum % k
```在Python中，`%`已经返回非负余数。 

在像 Go 这样的语言中，我们必须手动标准化负余数。 
5. 检查该余数以前是否出现过。 

如果已经出现了`x`次，那么有`x`前面的前缀和具有相同的余数。 

每个匹配的前缀和形成一个以当前位置结束的有效子数组。 

所以：```
result += remainder_count[remainder]
```6.更新频率图。 

计算完匹配项后，记录当前的余数：```
remainder_count[remainder] += 1
```7. 继续，直到处理完所有元素。 
8. 返回`result`。 

### 为什么它有效

 该算法依赖于模运算的数学特性。 

如果两个前缀和除以后余数相同`k`，那么它们的差可以除以`k`。 

由于子数组和是两个前缀和之间的差，因此每对相等的余数都对应于一个有效的子数组。 

哈希映射有效地计算已经出现了多少个兼容的前缀和。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def subarraysDivByK(self, nums: List[int], k: int) -> int:
        remainder_count = defaultdict(int)
        remainder_count[0] = 1

        prefix_sum = 0
        result = 0

        for num in nums:
            prefix_sum += num

            remainder = prefix_sum % k

            result += remainder_count[remainder]

            remainder_count[remainder] += 1

        return result
```实现直接遵循算法。 

我们使用`defaultdict(int)`以便缺失的余数自动默认为零频率。 

初始值`remainder_count[0] = 1`考虑从索引开始的子数组`0`。 

当我们迭代数组时，我们不断更新运行的前缀和。 该前缀和模的余数`k`确定先前兼容的前缀和是否存在。 

每当余数重复时，我们立即知道有多少新的有效子数组以当前索引结尾。 

最后，我们更新剩余频率，以便将来的迭代可以使用它。 

## 解决方案```go
func subarraysDivByK(nums []int, k int) int {
    remainderCount := make(map[int]int)
    remainderCount[0] = 1

    prefixSum := 0
    result := 0

    for _, num := range nums {
        prefixSum += num

        remainder := prefixSum % k

        if remainder < 0 {
            remainder += k
        }

        result += remainderCount[remainder]

        remainderCount[remainder]++
    }

    return result
}
```Go 实现在结构上与 Python 版本相同，但存在一个涉及模行为的重要区别。 

在 Go 中，负数可以产生负余数。 例如：```go
-2 % 5 == -2
```确保余数保持在有效范围内`[0, k-1]`，我们将它们标准化：```go
if remainder < 0 {
    remainder += k
}
```如果没有这种更正，等效的余数可能会被视为哈希映射中的不同键，从而产生错误的结果。 

Go 映射还会自动返回缺失键的零值，这对于频率计数非常有效。

 ## 边缘情况

 ### 包含负数的数组

 负值是错误的常见来源，因为编程语言之间的模行为不同。 

例如，在 Go 中：```
-2 % 5 == -2
```如果负余数未标准化，则逻辑上等效的余数可能会显示为不同的哈希映射键。 

该实现通过将负余数转换为范围来修复此问题`[0, k-1]`。 

### 全零数组

 考虑：```
nums = [0,0,0]
k = 5
```每个可能的子数组总和等于`0`，可以被任何正数整除`k`。 

这种情况强调算法是否正确地计算重复的剩余匹配。 由于每个前缀和余数是`0`，频率图快速增长并生成许多有效的子数组。 

该实现通过重复频率累积自然地处理这个问题。 

### 从索引零开始的子数组

 一个常见的错误是忘记计算从数组开头开始的子数组。 

例如：```
nums = [5]
k = 5
```前缀和本身可以被整除`k`。 

这就是哈希映射以以下方式开头的原因：```
remainder_count[0] = 1
```这个初始条目代表一个空的前缀和，并确保此类子数组被正确计数。
