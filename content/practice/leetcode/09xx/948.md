[LeetCode 第 948 题](https://leetcode.com/problems/bag-of-tokens/)

 **难度：** 🟡 中等
 **主题：** 数组、两个指针、贪婪、排序

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个标记集合，其中每个标记都有一个数值。 我们还从初始功率和初始分数开始`0`。 每个令牌最多可以使用一次，并且每个令牌都可以以两种方式之一进行播放。 

如果我们面朝上玩代币，我们会花费等于代币价值和收益的能量`1`分数。 只有当我们目前有足够的权力来支付成本时，才允许采取此行动。 

如果我们面朝下玩一个代币，我们会获得等于代币价值的力量并失去`1`分数。 仅当我们当前至少有一个可用分数时才允许执行此操作。 

目标是在执行任何有效动作序列后最大化最终得分。 

换句话说，问题是要求我们小心地在两种资源之间进行交易：

 - 权力，允许我们购买分数
 - 分数，有时可以牺牲分数来恢复力量

 输入包括：

 -`tokens`，非负整数数组
 -`power`, 代表初始可用功率的整数

 预期输出是表示可达到的最高分数的单个整数。 

约束条件很重要：

 -`tokens.length <= 1000`-`tokens[i] < 10^4`由于代币数量相对较少，`O(n log n)`解决方案是完全可以接受的。 然而，对所有可能的移动序列进行指数探索将变得不可行，因为每个标记可能有与其相关的多个选择。 

尽早识别一些边缘情况很重要：

 - 代币列表可能为空
 - 初始威力可能太小，无法面朝上玩任何代币
 - 令牌可能包含零值
 - 我们可能需要暂时牺牲分数来获得足够的力量来进行未来有利可图的行动
 - 在错误的时间打出面朝下的令牌可能会减少最终答案

 正确的解决方案必须仔细平衡这些权衡。 

## 方法

 ### 蛮力方法

 暴力解决方案将探索每一个可能的移动顺序。 对于每个未玩的令牌，我们可以决定：

 - 如果有足够的电量，请面朝上播放
 - 如果分数至少为 1，请面朝下进行游戏
 - 完全跳过它

 这自然会导致递归回溯或状态空间搜索。 在每一步，算法都会跟踪：

 - 剩余未使用的代币
 - 当前功率
 - 当前分数

 暴力方法是正确的，因为它检查所有有效的移动序列，因此不会错过最佳答案。 

然而，可能的状态数量呈指数增长。 即使进行了修剪，随着标记数量的增加，搜索空间也会变得巨大。 对于多达 1000 个代币，这种方法是完全不切实际的。 

### 最佳解决方案的关键见解

 关键的观察是，并非所有代币在每个角色中都具有同等价值。 

如果我们想要高效地获得分数，我们就应该花费尽可能少的力量。 因此，当面朝上玩时，最便宜的可用代币始终是最佳选择。 

如果我们需要通过牺牲分数来恢复力量，我们应该获得尽可能多的力量作为回报。 因此，面朝下玩时，最昂贵的可用代币始终是最佳选择。 

这自然建议对标记进行排序并使用两指针策略：

 - 使用左指针表示最小的标记
 - 对最大的标记使用正确的指针

 该算法贪婪地尽可能便宜地购买分数，并且仅在必要时出售分数以解锁更多未来分数收益。

 ## 算法演练

 1. 按升序对标记进行排序。 

排序至关重要，因为我们希望快速访问：

 - 最便宜的面朝游戏代币
 - 面朝下游戏最昂贵的代币

 排序后：

 - 左侧包含低成本代币
 - 右侧包含高价值的恢复代币
 2. 初始化两个指针。 

-`left = 0`-`right = len(tokens) - 1`这`left`指针代表下一个最便宜的未使用令牌。 

这`right`指针代表下一个最昂贵的未使用令牌。 
3. 追踪当前分数和最佳分数。 

我们维持：

 -`score`, 当前活跃分数
 -`max_score`, the best score achieved so far

 我们不能简单地返回最终分数，因为某些序列会暂时降低分数，然后再增加分数。 
4. 尽可能尝试以面朝上的方式玩最便宜的代币。 

如果`power >= tokens[left]`，我们应该花费力量来获得分数，因为：

 - 这是最便宜的得分增益
 - 任何更昂贵的代币都会花费更多的力量来获得相同的奖励

 然后我们：

 - 从权力中减去代币价值
 - 分数增加一
 - 移动`left`前进
 5. 如果我们无法承担面朝上的玩法，请考虑面朝下的玩法。 

如果：

-`score > 0`-`left < right`那么我们就可以牺牲一个分数来获得大量的力量。 

我们使用最大的剩余令牌，因为它可以提供最大可能的电力恢复。 

然后我们：

 - 添加`tokens[right]`上电
 - 分数减少一分
 - 移动`right`落后
 6. 当无法取得进一步进展时停止。 

如果：

 - 我们买不起最便宜的代币
 - 我们没有足够的分数来交易
 - 或者所有有用的代币都用完了

 然后该过程结束。 
7. 返回记录的最高分数。 

### 为什么它有效

 贪婪策略之所以有效，是因为每次面朝上的游戏都会给出相同的奖励，恰好一个分数。 因此，我们应该始终尽量减少获得奖励所花费的力量。 同样，每一次面朝下的游戏都会花费一个分数，所以我们应该最大化获得的力量作为回报。 

排序使我们始终能够做出局部最优的选择，并且这些局部决策组合成全局最优的解决方案。 

## Python 解决方案```python
from typing import List

class Solution:
    def bagOfTokensScore(self, tokens: List[int], power: int) -> int:
        tokens.sort()

        left = 0
        right = len(tokens) - 1

        score = 0
        max_score = 0

        while left <= right:
            if power >= tokens[left]:
                power -= tokens[left]
                score += 1
                max_score = max(max_score, score)
                left += 1
            elif score > 0 and left < right:
                power += tokens[right]
                score -= 1
                right -= 1
            else:
                break

        return max_score
```该实现首先对令牌进行排序，以便始终可以使用两个指针有效地访问最便宜和最昂贵的未使用令牌。 

这`left`指针从数组的开头开始，代表下一个可能面朝上播放的令牌。 这`right`指针从末尾开始，代表下一个可能面朝下玩的令牌。 

在循环内，算法首先优先考虑面朝上的游戏，因为增加分数是主要目标。 如果存在足够的电力，则购买最小的代币。 

每当面朝上的比赛成功时，当前的分数可能会成为迄今为止看到的最好的分数，所以`max_score`已更新。 

如果面朝上的玩法不可能，算法会检查面朝下的玩法是否有帮助。 仅当我们仍然有可用分数并且还有剩余代币值得转换为能量时，这才有用。 

如果这两种操作都不可能，则循环终止，因为无法获得额外的分数。 

最后，返回过程中观察到的最大分数。 

## 解决方案```go
package main

import "sort"

func bagOfTokensScore(tokens []int, power int) int {
	sort.Ints(tokens)

	left := 0
	right := len(tokens) - 1

	score := 0
	maxScore := 0

	for left <= right {
		if power >= tokens[left] {
			power -= tokens[left]
			score++
			if score > maxScore {
				maxScore = score
			}
			left++
		} else if score > 0 && left < right {
			power += tokens[right]
			score--
			right--
		} else {
			break
		}
	}

	return maxScore
}
```Go 实现遵循与 Python 版本完全相同的贪婪逻辑。 

主要区别在于使用`sort.Ints(tokens)`用于对切片进行就位排序。 Go 切片的行为与动态数组类似，因此不需要额外的复制。 

整数溢出不是问题，因为约束很小。 该实现也自然地处理空切片，因为`right`变成`-1`，导致循环条件立即失败。

 ## 边缘情况

 ### 空令牌数组

 如果输入数组为空，则没有可能的移动。 粗心的实现可能会尝试错误地初始化指针或访问不存在的元素。 

此实现可以自然地处理这种情况，因为：```
right = len(tokens) - 1
```变成`-1`，因此主循环条件立即失败。 

### 初始电量不足

 考虑：```
tokens = [100]
power = 50
```玩家无法承受任何面朝上的移动，并且面朝下的移动没有​​可用分数。 

有缺陷的实现可能会意外地允许无效交易或进入无限循环。 该解决方案正确终止，因为循环的两个分支都无法执行。 

### 零值代币

 代币可能包含价值`0`。 

例如：```
tokens = [0, 0, 0]
power = 0
```每个令牌都可以免费正面朝上播放，在不消耗电量的情况下产生分数。 

某些实现错误地假设令牌值为正，并且可能会错误地处理这种情况。 这里的贪婪逻辑仍然可以正确工作，因为：```
power >= tokens[left]
```当两个值都为零时为真。 

### 防止浪费的面朝下交易

 条件：```
left < right
```很微妙但很重要。 

如果只剩下一个代币，那么花费分数来获得该代币的力量是没有用的，因为之后就没有剩余的代币可供购买。 

如果没有这个条件，实现可能会执行无意义的交易，从而降低最终得分。 该解决方案避免了不必要的面朝下游戏并保持了正确性。
