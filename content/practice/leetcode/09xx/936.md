[LeetCode 936 题](https://leetcode.com/problems/stamping-the-sequence/)

 **难度：** 🔴难
 **主题：** 字符串、堆栈、贪婪、队列

 ## 解决方案

 ## 问题理解

 这个问题要求我们通过重复应用一个较小的字符串来重建目标字符串，称为`stamp`。 

我们从一个字符串开始`s`其长度与`target`，但每个字符最初都是`'?'`。 在一次操作中，我们可以将`stamp`字符串到任意有效位置`s`，这样做会用来自的字符覆盖该范围内的字符`stamp`。 

目标是生产出精确的`target`最多使用字符串`10 * target.length`冲压作业。 

输出不是最终字符串本身，而是应用标记的起始索引序列。 该序列应描述从初始全问号字符串到最终目标字符串的标记顺序。 

直接正向模拟很困难，因为可能有许多不同的印记顺序，并且后面的印记可能会覆盖前面的字符。 相反，关键的观察结果是逆转该过程要容易得多。 

而不是从建立目标`'?'`，我们可以从`target`并重复替换有效的邮票形区域`'?'`直到整个字符串变成问号。 

约束条件很重要：

 -`target.length <= 1000`-`stamp.length <= target.length`这个尺寸足够小`O(n^2)`风格算法，但对于指数回溯或强力搜索来说太大。 

一些边缘情况很重要：

 - 目标可能已经等于标记。 
- 某些字符可能需要重叠印章。 
- 有些目标根本无法形成。 
- 可能存在多个有效答案。 
- 反向标记操作必须替换至少一个非问号字符，否则我们可能会永远循环。 

## 方法

 ### 蛮力方法

 一种简单的方法会尝试从左到右构建目标字符串。 

每一步，我们都可以尝试在每一个可能的位置上踩踏，并检查它是否有助于我们更接近目标。 这很快就会变得困难，因为图章可能会重叠并覆盖以前的字符。 当地有效的举动可能会导致施工无法进行。 

一种可能的暴力策略是回溯：

 1. 尝试每一个可能的印章位置。 
2. 盖上印章。 
3. 递归继续。 
4. 如果当前路径失败则回溯。 

这种方法是正确的，因为它探索了冲压操作的所有可能顺序。 然而，可能的序列数量随着目标长度呈指数增长。 

由于目标长度可达1000，穷举搜索是完全不可行的。 

### 最优贪婪逆向模拟

 关键的见解是，逆转流程比向前构建流程容易得多。 

而不是开始于`'?????'`并建立目标，我们从`target`并尝试将其擦回问号。 

假设一个子字符串与图章匹配，或者与图章匹配，但某些字符已被替换`'?'`。 那么该子字符串可能是由之前的标记操作生成的。 因此，我们可以安全地将该区域中的所有字符替换为`'?'`。 

这自然会导致一个贪心的过程：

 - 找到一个可以盖章的窗口。 
- 将其字符替换为`'?'`。 
- 记录索引。 
- 重复直到整个字符串变成`'?'`。 

因为我们是反转操作，所以在返回之前必须反转记录的索引。 

关键规则是每次反向冲压操作必须替换至少一个真实字符。 否则，我们可能会永远重复地标记同一个全问号区域。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 指数| 指数| 递归尝试所有冲压序列 |
 | 最佳 | O((N - M + 1) * N * M) | O(N) | 重复扫描的贪婪反向冲压 |

 这里：

-`N = len(target)`-`M = len(stamp)`## 算法演练

 1. 将目标字符串转换为可变字符数组。 

由于字符串在 Python 和 Go 中是不可变的，因此我们需要一个可变的表示形式，以便我们可以将字符替换为`'?'`。 
2. 维护一个已访问的标记位置数组。 

一旦一个窗口已经被处理过，我们就不需要再次处理它。 
3. 重复扫描每个可能的印章位置。 

对于每个位置`i`，检查印章是否可以反贴。 
4. 反面印章在以下情况下有效：

 - 每个非问号字符都与印记字符匹配。 
- 窗口中至少有一个字符尚未出现`'?'`。 

第二个条件防止无限循环。 
5. 如果找到有效窗口：

 - 将该窗口中的所有字符替换为`'?'`。 
- 计算有多少新字符被删除。 
- 记录位置。 
- 将窗口标记为已访问。 
6. 继续扫描直到：

 - 所有角色都变成`'?'`, 或
 - 整个关卡中无法取得任何进展。 
7. 如果所有字符都被删除，则反转记录位置并返回。 

由于我们向后处理了目标，因此反转会恢复原始的冲压顺序。 
8. 如果我们在擦除所有内容之前遇到困难，请返回一个空数组。 

### 为什么它有效

 该算法之所以有效，是因为每个反向标记操作都对应于有效的正向标记操作。 

每当一个窗口与除已擦除字符之外的标记相匹配时，该窗口必须在转发过程中的某个较早时刻是可标记的。 替换为`'?'`因此是安全的。 

该算法仅在真正取得进展时才删除字符，从而保证终止。 如果算法无法擦除整个目标，则不存在有效的标记序列。 

## Python 解决方案```python
from typing import List

class Solution:
    def movesToStamp(self, stamp: str, target: str) -> List[int]:
        stamp_len = len(stamp)
        target_len = len(target)

        target_chars = list(target)

        visited = [False] * (target_len - stamp_len + 1)

        result = []

        replaced_count = 0

        def can_replace(position: int) -> bool:
            changed = False

            for i in range(stamp_len):
                current_char = target_chars[position + i]

                if current_char == '?':
                    continue

                if current_char != stamp[i]:
                    return False

                changed = True

            return changed

        def do_replace(position: int) -> int:
            replaced = 0

            for i in range(stamp_len):
                if target_chars[position + i] != '?':
                    target_chars[position + i] = '?'
                    replaced += 1

            return replaced

        while replaced_count < target_len:
            progress = False

            for i in range(target_len - stamp_len + 1):
                if visited[i]:
                    continue

                if can_replace(i):
                    replaced = do_replace(i)

                    if replaced > 0:
                        visited[i] = True
                        progress = True
                        replaced_count += replaced
                        result.append(i)

            if not progress:
                return []

        result.reverse()
        return result
```实现直接遵循逆向模拟策略。 

这`target`字符串被转换为名为的可变列表`target_chars`。 这允许字符替换为`'?'`。 

这`can_replace()`助手检查是否可以安全地擦除标记窗口。 它确保每个非问号字符与相应的印记字符匹配。 它还验证至少一个实际字符将被删除。 

这`do_replace()`帮助程序执行实际的替换并返回新删除的字符数。 该计数用于跟踪总体进度。 

主循环重复扫描每个可能的印记位置。 每当找到有效窗口时，算法就会将其删除并记录索引。 

如果整个过程完成而没有任何进展，则无法完全擦除目标，这意味着不存在有效的标记序列。 

最后，结果是相反的，因为我们以相反的顺序记录了操作。 

## 解决方案```go
func movesToStamp(stamp string, target string) []int {
	stampLen := len(stamp)
	targetLen := len(target)

	targetChars := []byte(target)

	visited := make([]bool, targetLen-stampLen+1)

	result := []int{}

	replacedCount := 0

	canReplace := func(position int) bool {
		changed := false

		for i := 0; i < stampLen; i++ {
			currentChar := targetChars[position+i]

			if currentChar == '?' {
				continue
			}

			if currentChar != stamp[i] {
				return false
			}

			changed = true
		}

		return changed
	}

	doReplace := func(position int) int {
		replaced := 0

		for i := 0; i < stampLen; i++ {
			if targetChars[position+i] != '?' {
				targetChars[position+i] = '?'
				replaced++
			}
		}

		return replaced
	}

	for replacedCount < targetLen {
		progress := false

		for i := 0; i <= targetLen-stampLen; i++ {
			if visited[i] {
				continue
			}

			if canReplace(i) {
				replaced := doReplace(i)

				if replaced > 0 {
					visited[i] = true
					progress = true
					replacedCount += replaced
					result = append(result, i)
				}
			}
		}

		if !progress {
			return []int{}
		}
	}

	for left, right := 0, len(result)-1; left < right; left, right = left+1, right-1 {
		result[left], result[right] = result[right], result[left]
	}

	return result
}
```Go 实现密切反映了 Python 逻辑。 

可变目标字符串使用字节片表示。 由于 Go 字符串是不可变的，因此转换为`[]byte`对于就地更换来说是必要的。 

辅助函数作为闭包实现。 切片操作和索引处理是明确的，但其他逻辑是相同的。 

Go 不区分`nil`和 LeetCode 评分中针对此问题的空切片，因此返回`[]int{}`当不存在解时就足够了。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O((N - M + 1) * N * M) | 每次扫描都会检查每个窗口，并且每次检查都可能会检查完整的印章 |
 | 空间| O(N) | 可变目标数组、访问数组和结果存储 |

 该算法可能会在整个目标变成问号之前重复扫描所有可能的窗口。 每个窗口比较最多可以检查`M`人物。 由于在成功操作过程中至少会擦除一个新字符，因此成功替换的次数受下式限制：`N`。

 ## 边缘情况

 当目标与印记完全相等时，就会出现一种重要的边缘情况。 幼稚的实现可能不必要地继续搜索其他标记操作。 在此实现中，第一个成功的反向标记立即将整个目标转换为问号，并且算法以单个索引正确终止。 

另一个棘手的情况涉及重叠邮票。 例如，在`"aabcaca"`有邮票`"abca"`，某些字符属于多个邮票应用程序。 前向贪婪策略在这里很容易失败，因为选择错误的邮票顺序可能会阻碍未来的进展。 反向贪婪方法避免了这个问题，因为它只删除已经与标记一致的窗口。 

第三个重要的边缘情况是防止无限循环。 假设一个窗口已经完全由问号组成。 从技术上讲，它仍然“匹配”标记，因为问号在逆向处理过程中被视为通配符。 然而，允许在已经擦除的区域上重复标记会导致无限循环。 该实现通过要求每个反向标记操作擦除至少一个真实字符来避免这种情况。 

当不存在有效的解决方案时，会出现另一种微妙的边缘情况。 例如，`stamp = "abc"`和`target = "def"`。 该算法最终完成了全面扫描，但没有取得任何进展。 此时，它正确返回一个空数组，而不是永远循环或返回部分解决方案。
