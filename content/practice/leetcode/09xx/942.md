 **难度：** 🟢简单
 **主题：** 数组、两个指针、字符串、贪婪

 ## 解决方案

 ## 问题理解

 在这个问题中，我们给定一个字符串`s`仅由字符组成`'I'`和`'D'`。 字符串有长度`n`，我们必须构造一个整数的排列`0`到`n`，包含在内。 

排列意味着范围内的每个数字只出现一次。 由于范围是`[0, n]`，结果数组必须恰好包含`n + 1`元素。 

字符的含义由排列中相邻元素之间的相对顺序决定：

 - 如果`s[i] == 'I'`， 然后`perm[i] < perm[i + 1]`- 如果`s[i] == 'D'`， 然后`perm[i] > perm[i + 1]`目标是返回满足所有这些关系的任何有效排列。 

例如，如果输入是：```
s = "IDID"
```那么我们需要一个排列`[0,1,2,3,4]`这样：

 - 索引 0 正在增加
 - 指数 1 正在减少
 - 指数 2 正在增加
 - 指数 3 正在减少

 一个有效的答案是：```
[0,4,1,3,2]
```因为：

-`0 < 4`-`4 > 1`-`1 < 3`-`3 > 2`约束条件很重要：

 -`1 <= s.length <= 10^5`这意味着解决方案必须高效。 Any factorial-time or exponential approach is impossible because the number of permutations grows extremely quickly. 甚至一个`O(n^2)`当解决方案不太理想时`n`变得非常大。 

该问题保证：

 - 每个角色都是`'I'`或者`'D'`- 有效的排列总是存在的

 重要的边缘情况包括完全由`'I'`，字符串完全由`'D'`，以及交替模式，例如`"IDIDID"`。 如果实现没有仔细维护有效的剩余数字，这些模式可能会暴露天真的贪婪策略的缺陷。 

## 方法

 ### 蛮力方法

 暴力解决方案将生成整数的所有可能的排列`[0, n]`并检查它是否满足所描述的模式`s`。 

对于每个排列，我们将迭代字符串并验证：

 - 如果`s[i] == 'I'`， 然后`perm[i] < perm[i + 1]`- 如果`s[i] == 'D'`， 然后`perm[i] > perm[i + 1]`然后可以返回第一个有效排列。 

这种方法是正确的，因为它详尽地检查了所有可能的候选者。 最终，它会找到一个有效的排列，因为问题保证存在一个排列。 

然而，这种方法太慢了。 的排列数`n + 1`元素是：$$(n + 1)!$$即使对于相对较小的值`n`，阶乘增长在计算上变得不可行。 自从`n`可以大到`100000`，蛮力是完全不切实际的。 

### 最优贪婪两指针方法

 关键的观察是我们不需要尝试每一种排列。 相反，我们可以贪婪地构造一个有效的排列。 

在每一个位置上，我们只关心接下来的关系是应该增加还是减少。 

我们维护两个可用号码：

 -`low`, 最小的未使用数
 -`high`, 最大未使用数

 最初：```
low = 0
high = n
```然后我们逐个字符地处理字符串：

 - 如果我们看到`'I'`，我们放置最小的可用数字。 

- 这保证了下一个数字仍然可以更大。 
- 如果我们看到`'D'`，我们放置最大的可用数字。 

- 这保证了下一个数字仍然可以更小。 

使用数字后，我们将相应的指针向内移动。 

最后，恰好有一个数字未使用，我们将其附加。 

这是有效的，因为每个决策都为未来的立场保留了足够的灵活性，同时立即满足当前的约束。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O((n + 1)！ * n) | O(n) | 生成每个排列并验证每个排列 |
 | 最佳 | O(n) | O(n) | 使用两个指针的贪婪构造 |

 ## 算法演练

 1.初始化两个指针：

 -`low = 0`-`high = n`这些代表可用于排列的最小和最大未使用值。 
2. 创建一个空结果数组。 

该数组将存储构造的排列。 
3. 迭代字符串中的每个字符`s`。 

在每一步中，我们都会决定接下来放置哪个数字。 
4. 如果当前字符是`'I'`:

 - 追加`low`到结果。 
- 增量`low`。 

我们选择最小的可用数字，因为下一个数字必须更大。 
5. 如果当前字符是`'D'`:

 - 追加`high`到结果。 
- 递减`high`。 

我们选择最大的可用数字，因为下一个数字必须更小。 
6. 继续处理，直到所有字符都在`s`被处理。 

自从`s`有长度`n`，我们将准确附加`n`在此循环期间的数字。 
7. 1 个号码将保持未使用状态。 

在此刻，`low == high`。 
8. 将最终剩余的数字附加到结果中。 

这样就完成了大小的排列`n + 1`。 

### 为什么它有效

 该算法保持了一个重要的不变量：

 - 所有未使用的号码始终在范围内`[low, high]`。 

当我们遇到`'I'`，选择最小的可用值可以保证稍后仍有更大的可用值。 

当我们遇到`'D'`，选择最大的可用值可以保证稍后仍有一些较小的可用值。 

因为每个选择立即满足当前条件，同时保留有效的未来选项，所以最终的排列始终满足整个模式。 

## Python 解决方案```python
from typing import List

class Solution:
    def diStringMatch(self, s: str) -> List[int]:
        low = 0
        high = len(s)

        result = []

        for char in s:
            if char == 'I':
                result.append(low)
                low += 1
            else:
                result.append(high)
                high -= 1

        result.append(low)

        return result
```实现直接遵循贪婪策略。 

我们首先初始化`low`和`high`表示最小和最大的未使用数字。 由于排列必须包含来自`0`到`n`，初始范围恰好是`[0, len(s)]`。 

循环处理字符串中的每个字符：

 - 对于`'I'`，代码附加最小的可用数字并前进`low`。 
- 为了`'D'`，代码附加最大的可用数字并减少`high`。 

每一步都会消耗一个值并将其从可用范围中删除。 

循环结束后，只剩下一个未使用的数字。 因为之间的所有数字`low`和`high`我们知道，除了一个以外都已被消耗掉`low == high`。 附加此最终值即可完成排列。 

该实现以线性时间运行，并且仅使用输出数组作为额外存储。 

## 解决方案```go
func diStringMatch(s string) []int {
    low := 0
    high := len(s)

    result := make([]int, 0, len(s)+1)

    for _, ch := range s {
        if ch == 'I' {
            result = append(result, low)
            low++
        } else {
            result = append(result, high)
            high--
        }
    }

    result = append(result, low)

    return result
}
```Go 的实现与 Python 解决方案非常相似。 

创建一个带有容量的切片`len(s) + 1`以避免追加期间不必要的重新分配。 算法仍然使用相同的`low`和`high`指针策略。 

Go 在中使用符文迭代`for _, ch := range s`循环，它可以正常工作，因为输入仅包含 ASCII 字符。 

不存在整数溢出问题，因为最大值最多为`100000`，它很容易适合 Go 的`int`类型。

        high = len(s)

            if char == 'I':

                result.append(high)

        result.append(low)

def is_valid(s: str, perm: List[int]) -> bool:
    n = len(s)

    # Must contain all numbers from 0 to n exactly once
    if sorted(perm) != list(range(n + 1)):
        return False

    # Must satisfy I/D conditions
    for i, ch in enumerate(s):
        if ch == 'I' and not (perm[i] < perm[i + 1]):
            return False
        if ch == 'D' and not (perm[i] > perm[i + 1]):
            return False

    return True

sol = Solution()

 ## 边缘情况

 一个重要的边缘情况是完全由以下内容组成的字符串`'I'`字符，例如`"IIII"`。 有缺陷的实现可能会意外地重用值或无法在整个数组中保持递增的顺序。 贪心策略通过始终取最小的剩余值来自然地处理这个问题。 由此产生的排列变得严格递增。 

另一个关键的边缘情况是完全由以下内容组成的字符串`'D'`字符，例如`"DDDD"`。 这可能会暴露实现中无法正确保留较小未来值的问题。 该算法通过重复选择最大的可用数字来处理这个问题，保证每个相邻对保持递减。 

交替图案如`"IDIDID"`也很重要，因为它们迫使算法在最小和最大剩余值之间重复切换。 天真的贪婪策略很容易将自己陷入困境，并且不会为后面的位置留下有效的数字。 两指针方法避免了这个问题，因为每个选择都有意保留范围的另一侧以供将来使用。 

最终的微妙边缘情况是可能的最小输入大小，其中`s.length == 1`。 该算法仍然可以正确工作，因为正好有两个可用的数字，`[0,1]`，第一个字符立即决定它们的顺序。 最后的追加操作正确地放置了剩余值。
