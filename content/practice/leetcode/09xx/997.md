 **主题：** 数组、哈希表、图论

 ## 解决方案

 ## 问题理解

 该问题描述了一个城镇，其中包含`n`被标记为来自`1`到`n`。 在这些人中，可能存在着一个特殊的人，叫做镇法官。 

法官必须满足两个严格的条件：

 1. 法官不相信任何人。 
2. 其他人都信任法官。 

另外，这个问题保证了如果有这样的人存在，那么只能有一个法官。 

输入包括：

 - 一个整数`n`，代表人数。 
- 一个名为`trust`，其中每个元素是一对`[a, b]`, 意思是人`a`信任的人`b`。 

目标是确定是否存在有效的法官。 如果有人这样做，请归还该人的标签。 否则，返回`-1`。 

限制从小到中等：

 -`n`最多可以是`1000`-`trust.length`可以大到`10^4`这些限制足够小，以至于`O(n^2)`解决方案在技术上是可以通过的，但是这个问题有一个更清晰的线性时间图解释。 

这个问题本质上是关于有向图中的传入和传出关系：

 - 信任某人是一种外向优势。 
- 被信任是一个即将到来的优势。 

因此，一名有效的法官必须具备：

 - 出度`0`- 入度`n - 1`一些边缘情况很重要：

 - 小镇只有一个人，没有信任关系。 在这种情况下，这个人就是法官。 
- 循环信任关系，人们相互信任。 法官不能相信任何人。 
- 多个高度信任的人​​。 只有一个人才能满足所有条件。 
- 清空信任列表时`n > 1`。 法官不可能存在，因为没有人受到其他人的信任。 

该问题还保证信任对是唯一的并且`ai != bi`，这简化了实现，因为我们永远不需要处理重复的边或自信任。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是单独检查每个人并验证他们是否满足判断条件。 

对于每个候选人：

 1. 扫描整个`trust`大批。 
2. 确保候选人永远不会以信任者的身份出现。 
3. 计算有多少人信任该候选人。 
4. 如果候选人不信任任何人并且完全信任他`n - 1`人们，请返回那个候选人。 

这是有效的，因为判断定义是明确的并且易于直接验证。 

然而，这种方法效率低下，因为对于每个人，我们可能会再次扫描整个信任列表。 如果有`n`人们和`m`信任关系，复杂性变成`O(n * m)`。 

和`n = 1000`和`m = 10000`，这仍然可以接受，但没有必要。 

### 最佳方法

 关键的见解是判断条件可以使用入度和出度计数来表示。 

对于每个信任对`[a, b]`:

 -`a`信任某人，所以`a`不能成为法官。 
-`b`多了一个信任他们的人。 

我们可以维护：

 -`outdegree[a] += 1`-`indegree[b] += 1`在处理完所有信任关系之后，法官就是满足以下条件的人：

 -`outdegree[i] == 0`-`indegree[i] == n - 1`这将问题转化为对边缘的单次传递和对人的单次传递。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n * m) | O(1) | O(1) | 重新检查每个候选人的信任列表 |
 | 最佳| O(n + m) | O(n) | 使用入度和出度计数 |

 这里，`m`代表`trust.length`。 

## 算法演练

 1.创建两个大小的数组`n + 1`:

 -`indegree`，计算每个人有多少人信任。 
-`outdegree`，计算每个人信任的人数。 

我们使用`n + 1`因为人们被标记为从`1`， 不是`0`。 
2. 迭代每一个信任关系`[a, b]`。 

对于每对：

 - 增量`outdegree[a]`因为人`a`信任某人。 
- 增量`indegree[b]`因为人`b`被某人信任。 
3. 处理完所有信任关系后，迭代所有来自`1`到`n`。 
4. 对于每个人：

 - 检查是否`outdegree[person] == 0`- 检查是否`indegree[person] == n - 1`如果两个条件都成立，则此人满足法官定义。 
5.立即返回匹配的人。 
6. 如果没有人满足这两个条件，则返回`-1`。 

### 为什么它有效

 该算法直接对法官的数学定义进行建模。 

法官必须信任任何人，这意味着他们的传出信任计数必须为零。 

法官必须受到其他人的信任，这意味着他们收到的信任数必须相等`n - 1`。 

因为我们对每个信任关系只计算一次这些计数，所以最终扫描正确地识别了唯一可能的判断。 如果没有人同时满足这两个条件，那么就不存在法官。 

## Python 解决方案```python
from typing import List

class Solution:
    def findJudge(self, n: int, trust: List[List[int]]) -> int:
        indegree = [0] * (n + 1)
        outdegree = [0] * (n + 1)

        for a, b in trust:
            outdegree[a] += 1
            indegree[b] += 1

        for person in range(1, n + 1):
            if indegree[person] == n - 1 and outdegree[person] == 0:
                return person

        return -1
```该实现紧密遵循前面描述的算法。 

两个数组，`indegree`和`outdegree`，存储每个人进出的信任关系数量。 由于人们被标记为从`1`， 指数`0`未使用。 

循环结束`trust`每个关系只处理一次。 每当`[a, b]`出现：

 -`a`获得传出优势
 -`b`获得传入优势

 处理完所有关系后，第二个循环根据判断条件检查每个人。 

第一个入度等于的人`n - 1`其出度等于`0`立即返回。 

如果没有找到有效的候选者，该函数返回`-1`。 

## 解决方案```go
func findJudge(n int, trust [][]int) int {
    indegree := make([]int, n+1)
    outdegree := make([]int, n+1)

    for _, relation := range trust {
        a := relation[0]
        b := relation[1]

        outdegree[a]++
        indegree[b]++
    }

    for person := 1; person <= n; person++ {
        if indegree[person] == n-1 && outdegree[person] == 0 {
            return person
        }
    }

    return -1
}
```Go 实现与 Python 版本几乎相同。 

使用切片而不是 Python 列表。 数组初始化使用`make([]int, n+1)`。 

Go 在这里不需要对整数溢出进行特殊处理，因为所有值都很小并且完全在标准范围内`int`类型。 

使用 Go 迭代信任关系`range`句法。

 ## 边缘情况

 ### 单人小镇

 当`n = 1`并且信任列表为空，镇上唯一的人自动满足判定条件。 

他们不信任任何人，因为不存在信任关系。 

他们也被其他人空洞地信任，因为没有其他人。 

一个常见的错误是返回`-1`每当信任列表为空时。 该实现通过直接检查入度和出度条件来避免这种情况。 

### 候选人受到所有人的信任，但也信任某人

 一个人可能看起来像是法官，因为每个人都信任他，但如果他们信任另一个人，他就会立即变得无效。 

例如：```rust
n = 3
trust = [[1,3],[2,3],[3,1]]
```人`3`被两个人信任，也信任一个人`1`。 

该实现正确地捕获了这一点，因为它单独跟踪出度并要求其等于零。 

### 没有普遍信任的人

 当信任关系存在，但没有一个人受到所有其他人的信任时，就会出现另一种棘手的情况。 

例如：```rust
n = 4
trust = [[1,2],[2,3],[3,4]]
```每个人至多只受到一个人的信任。 

简单的解决方案可能会错误地返回信任计数最高的人。 该实现通过要求入度精确地避免了这种情况`n - 1`。 

### 多个具有高信任度的人

 几个人可能会收到很多传入的信任关系，但只有一个人能够满足完整的判断条件。 

例如：```rust
n = 4
trust = [[1,3],[2,3],[1,4],[2,4]]
```两个人`3`和`4`受到两个人的信任，但没有一个人受到所有其他三个人的信任。 

该实现通过检查所需的确切入度值而不是选择最大值来确保正确性。
