[LeetCode 923 题](https://leetcode.com/problems/3sum-with-multiplicity/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、两个指针、排序、计数

 ## 解决方案

 ## 问题理解

 该问题要求我们计算有多少个索引三元组`(i, j, k)`满足两个条件：

 - 索引必须遵循顺序`i < j < k`- 这些指数的值之和必须等于给定值`target`正式地，我们想要：```
arr[i] + arr[j] + arr[k] == target
```重要的细节是我们正在计算索引元组，而不是唯一值组合。 如果相同的值在数组中出现多次，则必须单独计算每个有效的索引组合。 

例如，如果数组包含多个`2`和几个`3`s，每一个不同的指数选择都有助于得出答案。 

输入包括：

 -`arr`，一个整数数组
 -`target`, 所需金额

 输出是有效三元组的模数`10^9 + 7`。 

约束在这里尤其重要：

 -`arr.length <= 3000`-`arr[i] <= 100`-`target <= 300`数组大小足够大，可以`O(n^3)`暴力解决方案太慢。 然而，这些值本身非常小，范围仅为`0`到`100`。 这一观察结果为基于计数的优化打开了大门。 

有几种边缘情况很容易引入错误：

 - 具有许多重复值的数组
 - 所有三个所选数字都相同的情况
 - 两个数字完全相同的情况
 - 需要模运算的大量计数
 - 许多组合产生相同总和的数组

 该问题保证：

 - 至少存在三个要素
 - 所有值都是非负整数
 - 在 Python 中应用模之前，答案符合正常整数算术，但问题陈述仍然需要模

 ## 方法

 ### 蛮力方法

 最直接的解决办法就是尝试每一个可能的三元组`(i, j, k)`在哪里`i < j < k`。 

我们可以使用三个嵌套循环：

 - 第一个循环选择`i`- 第二个循环选择`j`- 第三个循环选择`k`对于每个三元组，我们计算总和并检查它是否等于`target`。 如果是，我们就增加答案。 

这种方法是正确的，因为它明确地检查每个有效索引组合一次。 

然而，复杂性太高。 和`n = 3000`，三元组的数量大约为：```
3000^3 = 27,000,000,000
```这远远超出了可接受的运行时间限制。 

### 最佳解决方案的关键见解

 关键的观察结果是数组值非常小：```
0 <= arr[i] <= 100
```我们可以计算每个值出现的次数，而不是直接关注索引。 

一旦我们知道每个数字的频率，我们就可以迭代值组合而不是索引组合。 

只有`101`可能的值，来自`0`到`100`。 

我们可以尝试所有组合`(x, y, z)`这样：```
x + y + z == target
```然后我们计算这些值生成了多少个索引三元组。 

这将问题从迭代多达数十亿个索引组合转变为迭代非常小的值空间。 

主要挑战是在以下情况下正确计算组合：

 - 三个值都不同
 - 两个值相等
 - 所有三个值都相等

 ## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n3) | O(1) | O(1) | 直接检查每个可能的三元组 |
 | 最佳| O(101²) | 奥(101) | 使用频率计数和组合学 |

 ## 算法演练

 1. 创建一个频率数组或哈希图来统计每个数字出现的次数`arr`。 

由于值的范围仅为`0`到`100`，我们可以使用长度固定的数组`101`。 
2. 将答案变量初始化为`0`。 
3. 迭代所有可能的值`x`从`0`到`100`。 
4. 对于每个`x`，迭代所有可能的值`y`从`x`到`100`。 

开始`y`从`x`确保我们避免重复排列。 
5. 计算所需的第三个值：```
z = target - x - y
```6. 跳过无效案例：

 - 如果`z < y`，跳过它，因为我们保持排序`x <= y <= z`- 如果`z > 100`，跳过它，因为值是有界的
 7. 现在确定该值组合贡献了多少个三元组。 

有四种不同的情况：

 - 案例1：`x == y == z`我们需要从出现的情况中选择任意 3 个索引`x`。 

计数为：$\binom{count[x]}{3}$- 案例2：`x == y != z`我们选择2份`x`和 1 份`z`。 

计数为：$\binom{count[x]}{2} \cdot count[z]$- 案例3：`x != y == z`我们选择1份`x`和 2 份`y`。 

计数为：$count[x] \cdot \binom{count[y]}{2}$- 情况4：`x < y < z`所有的价值观都是不同的。 

计数为：$count[x] \cdot count[y] \cdot count[z]$8. 将计算出的贡献添加到答案中。 
9. 返回模数答案`10^9 + 7`。 

### 为什么它有效

 该算法之所以有效，是因为每个有效的索引三元组都对应于一个有序值组合，满足：```
x <= y <= z
```通过强制执行此顺序，我们可以避免重复计算。 

组合公式正确计算每个值模式存在多少个索引选择：

 - 选择3个相同的值
 - 选择2个相同的值
 - 选择 3 个不同的值

 由于会检查所有可能的值组合，因此每个有效的三元组都会被精确计数一次。 

## Python 解决方案```python
from typing import List

class Solution:
    def threeSumMulti(self, arr: List[int], target: int) -> int:
        MOD = 10**9 + 7
        
        count = [0] * 101
        
        for num in arr:
            count[num] += 1
        
        answer = 0
        
        for x in range(101):
            for y in range(x, 101):
                z = target - x - y
                
                if z < y or z > 100:
                    continue
                
                if x == y == z:
                    n = count[x]
                    answer += n * (n - 1) * (n - 2) // 6
                
                elif x == y != z:
                    n = count[x]
                    answer += (n * (n - 1) // 2) * count[z]
                
                elif x < y and y == z:
                    n = count[y]
                    answer += count[x] * (n * (n - 1) // 2)
                
                else:
                    answer += count[x] * count[y] * count[z]
        
        return answer % MOD
```该实现首先计算数组中每个值的频率。 因为值的范围仅为`0`到`100`，固定大小的列表比字典更有效。 

嵌套循环迭代所有有效的有序对`(x, y)`。 对于每一对，所需的第三个值`z`直接从目标计算。 

条件：```python
if z < y or z > 100:
```确保：

 - 我们维持订单`x <= y <= z`- 第三个值保持在有效范围内

 这四种组合情况需要单独处理，因为每种情况都需要不同的计数公式。 

对于相同的值，使用标准组合公式计算组合：

 - 选择 2 件物品`n`- 选择 3 件物品`n`最后，将答案取模返回`10^9 + 7`。 

## 解决方案```go
func threeSumMulti(arr []int, target int) int {
    const MOD int = 1000000007

    count := make([]int, 101)

    for _, num := range arr {
        count[num]++
    }

    answer := 0

    for x := 0; x <= 100; x++ {
        for y := x; y <= 100; y++ {
            z := target - x - y

            if z < y || z > 100 {
                continue
            }

            if x == y && y == z {
                n := count[x]
                answer += n * (n - 1) * (n - 2) / 6

            } else if x == y && y != z {
                n := count[x]
                answer += (n * (n - 1) / 2) * count[z]

            } else if x < y && y == z {
                n := count[y]
                answer += count[x] * (n * (n - 1) / 2)

            } else {
                answer += count[x] * count[y] * count[z]
            }

            answer %= MOD
        }
    }

    return answer
}
```Go 实现遵循与 Python 版本相同的逻辑。 

固定大小的长度切片`101`用于频率计数。 由于 Go 使用显式整数类型，因此在累加期间应用模归约以避免不必要的增长。 

与 Python 不同，Go 不会自动支持任意大的整数，但此问题中的值安全地保持在正常整数限制内。

 ## 边缘情况

 当所有三个选定值都相同时，就会出现一种重要的边缘情况。 例如：```
arr = [2,2,2,2]
target = 6
```幼稚的实现可能会错误地计算排列或无法正确使用组合。 正确答案来自于从 4 次出现中选择任意 3 个索引。 该实现使用组合公式来处理这个问题：$\binom{n}{3}$当两个值恰好相等时，会出现另一种棘手的边缘情况。 例如：```
arr = [1,1,2,2,2]
target = 5
```该算法必须区分：

 -`x == y != z`-`x != y == z`这些情况需要不同的公式。 对它们进行相同处理会产生错误计数或重复计数。 

第三个重要的边缘情况涉及大量重复频率。 考虑：```
arr = [0] * 3000
target = 0
```有效三元组的数量变得非常大。 如果没有模运算，某些语言可能会溢出整数限制。 该实现应用模运算来确保结果保持在范围内。 

当不存在有效的三元组时，会发生另一种微妙的情况。 例如：```
arr = [1,2,3]
target = 100
```该算法正确地跳过不可能的值组合，因为`z`要么超出有效范围，要么不存在于频率表中。
