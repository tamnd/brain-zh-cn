 # LeetCode 908 - 最小范围 I

 ## 问题理解

 问题给了我们一个整数数组`nums`和一个整数`k`。 对于数组中的每个元素，我们可以通过添加范围内的任何整数值来修改它一次`[-k, k]`。 换句话说，每个数字最多可以增加`k`, 最多减少`k`，或保持不变。 

执行这些操作后，我们将数组的分数定义为：$\text{score} = \max(nums) - \min(nums)$我们的目标是尽可能减少这个分数。 

更直观地说，我们想要缩小数组中最大和最小数字之间的差距。 由于每个数字都可以在有限的范围内移动，因此我们应该尽量将大数向下移动，将小数向上移动。 

限制相对较小：

 -`1 <= nums.length <= 10^4`-`0 <= nums[i] <= 10^4`-`0 <= k <= 10^4`这些限制告诉我们，性能并不是极其苛刻，但我们仍然应该以干净的线性时间解决方案为目标。 

有几个重要的边缘情况需要考虑：

 - 只有一个元素的数组已经有一个分数`0`- 什么时候`k = 0`，无法修改
 - 当最大值和最小值之差小于或等于`2 * k`，范围可以完全消除
 - 具有重复值的数组仍应正确运行
 - 非常大`k`值可以允许所有元素重叠成一个公共值

 该问题保证数组非空，因此我们永远不需要处理空输入。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试探索每个元素的所有可能的调整值。 由于每个数字都可以成为区间内的任意值：$[nums[i]-k,\ nums[i]+k]$理论上我们可以尝试每种组合并计算结果分数。 

然而，这很快就变得不可行。 即使对于小型数组，可能的调整数组的数量也会呈指数增长。 如果每个元素大致有`2k + 1`可能的值，组合总数变为：$(2k+1)^n$这对于约束来说太慢了。 

蛮力思想在概念上是正确的，因为它检查每一种可能的最终配置，但在计算上是不切实际的。 

### 最佳观察

 关键的见解是只有最小和最大元素才重要。 

认为：

-`minimum = min(nums)`-`maximum = max(nums)`要最小化范围：

 - 我们应该尽可能增加最小值，这意味着添加`k`- 我们应该尽可能减少最大值，这意味着减去`k`调整后：$\text{new range} = (\max(nums)-k) - (\min(nums)+k)$简化为：$\text{new range} = \max(nums)-\min(nums)-2k$如果该值变为负数，则意味着间隔完全重叠，因此最小可能得分为`0`。 

因此最终的答案是：$\max(0,\ \max(nums)-\min(nums)-2k)$### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O((2k+1)^n) | O((2k+1)^n) | O(n) | 尝试每一种可能的修改组合 |
 | 最佳 | O(n) | O(1) | O(1) | 仅使用全局最小值和最大值 |

 ## 算法演练

 1. 找出数组中的最小值。 

这代表对分数有贡献的最小元素。 为了缩小范围，我们希望尽可能向上移动该值。 
2. 找出数组中的最大值。 

这代表数组中最大的元素。 为了缩小范围，我们希望尽可能向下移动该值。 
3. 计算原始范围。 

原来的分数是：$\max(nums)-\min(nums)$4. 将范围缩小`2 * k`。 

由于最小值可以增加`k`最大值可以减少`k`，总减少量为：$2k$5. 将结果钳位为零。 

如果调整后的范围变为负值，则意味着间隔重叠，并且可以有效地使所有数字相等。 由于范围不能为负数，因此返回`0`。 

### 为什么它有效

 该算法之所以有效，是因为分数仅取决于最大值和最小值。 对中间元素的任何调整都不会影响最终范围，除非它们成为新的极端。 通过最大化最小元素的增加和最大化最大元素的减少，我们实现了它们之间的最小可能距离。 如果它们的可调间隔重叠，则分数为零。 

## Python 解决方案```python
from typing import List

class Solution:
    def smallestRangeI(self, nums: List[int], k: int) -> int:
        minimum_value = min(nums)
        maximum_value = max(nums)

        reduced_range = maximum_value - minimum_value - 2 * k

        return max(0, reduced_range)
```该实现直接遵循先前得出的数学观察。 

首先，我们计算数组中的最小值和最大值。 这是对分数计算唯一重要的两个元素。 

接下来，我们计算一下范围可以缩小多少。 由于最小值可以增加`k`最大值可以减少`k`，范围缩小`2 * k`。 

最后，我们通过使用确保结果不是负数`max(0, reduced_range)`。 

该解决方案很简洁，因为核心见解完全消除了模拟或动态编程的需要。 

## 解决方案```go
func smallestRangeI(nums []int, k int) int {
    minimumValue := nums[0]
    maximumValue := nums[0]

    for _, value := range nums {
        if value < minimumValue {
            minimumValue = value
        }

        if value > maximumValue {
            maximumValue = value
        }
    }

    reducedRange := maximumValue - minimumValue - 2*k

    if reducedRange < 0 {
        return 0
    }

    return reducedRange
}
```Go 实现遵循与 Python 版本相同的逻辑。 由于 Go 没有提供内置的`min()`和`max()`对于切片函数，我们手动迭代数组以跟踪最小值和最大值。 

整数溢出不是问题，因为约束很小。 该数组保证至少包含一个元素，因此从`nums[0]`是安全的。

 ## 边缘情况

 ### 单元素数组

 仅包含一个元素的数组的得分始终为零，因为最小值和最大值相同。 幼稚的实现可能仍会尝试不必要的计算或转换。 当前的解决方案可以自然地处理这个问题，因为：$\max(nums)-\min(nums)=0$所以最终的答案仍然是零。 

＃＃＃ 大的`k`造成重叠

 当`k`足够大时，所有数字的可调区间重叠。 这意味着每个值都可能成为相同的数字。 如果不仔细处理，实现可能会返回负值范围。 该解决方案通过将答案限制为以下内容来避免此错误：$\max(0,\ reducedRange)$### 不允许修改

 当`k = 0`，没有元素可以改变。 因此，答案应该等于原始范围。 某些实现可能会错误地假设每个操作都会更改值。 在这个解决方案中，公式自然简化为：$\max(nums)-\min(nums)-0$它准确地保留了原始分数。
