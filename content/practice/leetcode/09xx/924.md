[LeetCode 问题 924](https://leetcode.com/problems/minimize-malware-spread/)

 **难度：** 🔴难
 **主题：** 数组、哈希表、深度优先搜索、广度优先搜索、并查找、图论

 ## 解决方案

 ## 问题理解

 在这个问题中，我们给出了一个表示为邻接矩阵的无向图。 每个节点代表网络中的一台计算机，两个节点之间的边意味着这些计算机直接连接。 

某些节点子集最初感染了恶意软件。 恶意软件通过连接传播，这意味着如果受感染的节点连接到另一个节点，感染最终也会传播到该节点。 由于该图是无向的，并且感染会不断传播，直到没有新节点可以被感染为止，因此如果该组件包含至少一个最初感染的节点，则连接组件内的每个节点都会受到感染。 

我们可以从节点中删除一个节点`initial`恶意软件开始传播之前的受感染列表。 被删除的节点最初不再被感染，尽管它以后仍可能通过同一连接组件中的另一个受感染节点被感染。 

我们的目标是选择删除的节点，以最大限度地减少恶意软件传播完成后受感染节点的最终数量。 如果多个选择产生相同的最小感染计数，我们必须返回具有最小索引的节点。 

输入图最多有`300`节点，对于 DFS、BFS 或 Union-Find 等图遍历算法来说足够小。 由于图是作为邻接矩阵给出的，因此扫描节点的邻居需要`O(n)`时间。 

关键的观察结果是恶意软件在每个连接的组件内独立传播。 如果连接的组件包含：

 - 没有受感染的节点，它保持干净。 
- 一个受感染的节点，删除该受感染的节点可以完全保存组件。 
- 多个受感染节点，仅删除其中一个并无帮助，因为其余受感染节点仍会感染整个组件。 

一些边缘情况很重要：

 - 同一连接组件中可能存在多个受感染节点。 
- 被删除的节点以后仍可能被感染。 
- 完全断开的图表仍必须遵循最小索引平局规则。 
- 如果没有删除改善情况，我们返回最小的节点索引`initial`。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是尝试删除中的每个节点`initial`逐个。 

对于每个候选删除：

 1. 暂时将该节点从感染集中排除。 
2. 使用DFS或BFS模拟恶意软件传播。 
3. 计算有多少节点被感染。 
4. 跟踪产生最小最终感染计数的移除。 

这是有效的，因为它直接遵循问题定义。 然而，它对每个候选节点重复执行图遍历。 

如果有`k`受感染的节点和`n`总节点数，每次模拟可能需要`O(n²)`时间，因为图存储为邻接矩阵。 对所有受感染的节点重复此操作，大致得出`O(k * n²)`复杂。 

虽然`n <= 300`并不是很大，我们可以通过利用连通组件结构做得更好。 

### 最佳方法

 最佳见解是恶意软件的传播完全由连接的组件决定。 

假设连接的组件具有大小`S`。 

- 如果该组件恰好包含一个最初被感染的节点，则删除该节点可以防止所有节点被感染`S`节点。 
- 如果组件包含多个最初感染的节点，删除一个节点并不重要，因为其他节点仍然会感染整个组件。 

因此，我们只关心只有一个受感染节点的组件。 

算法变为：

 1. 找到所有连接的组件。 
2. 计算：

 - 每个组件的大小。 
- 每个组件包含多少个受感染节点。 
3. 对于每个受感染的节点：

 - 如果其组件恰好包含一个受感染节点，则删除它可以节省整个组件的大小。 
4. 选择保存最多节点的节点。 
5. 用较小的指数打破平局。 

这避免了重复的感染模拟。

 | ---| ---| ---| ---|
 | 蛮力 | O(k * n²) | O(k * n²) | O(n) | 模拟恶意软件的传播以进行每一次可能的删除 |
 | 最佳| O(n²) | O(n) | 使用连接的组件直接计算影响 |

 ## 算法演练

 ### 第 1 步：查找连接的组件

 我们使用 DFS 遍历该图。 

每个节点恰好属于一个连接的组件。 在遍历过程中，我们为每个节点分配一个组件ID。 

我们还计算每个组件的大小，因为组件大小决定了可以保存多少节点。 

使用邻接矩阵，因此对于每个节点，我们扫描所有`n`可能的邻居。 

### 步骤 2：记录组件尺寸

 在执行 DFS 时，我们计算有多少个节点属于当前组件。 

我们存储：

 -`component_id[node]`，每个节点属于哪个组件
 -`component_size[id]`，该组件中的节点数

 这些信息让我们稍后可以确定删除受感染节点的价值。 

### 步骤 3：计算每个组件的受感染节点数

 我们迭代通过`initial`大批。 

对于每个受感染的节点：

 1. 找到其组件ID。 
2. 增加该组件的受感染计数。 

现在我们知道一个组件是否具有：

 - 恰好有一个受感染的节点
 - 多个受感染节点

 这个区别是优化的核心。 

### 第 4 步：评估每个候选者的移除情况

 我们排序`initial`所以打破平局变得更容易。 

对于每个受感染的节点：

 1.找到它的组成部分。 
2. 检查该组件中存在多少个受感染节点。 

如果计数正好是`1`，删除此节点可以防止整个组件受到感染。 保存的节点数等于组件大小。 

如果计数大于`1`，删除节点不会改变任何情况，因为其他受感染的节点仍然传播恶意软件。 

我们跟踪：

 - 删除的最佳节点
 - 保存节点的最大数量

 ### 第 5 步：应用平局打破

 如果两个节点保存相同数量的节点，则返回较小的索引。 

排序`initial`事先自然保证了这种行为，因为我们首先处理较小的索引。 

### 为什么它有效

 该算法之所以有效，是因为恶意软件在连接的组件内独立传播。 如果组件内部至少有一个受感染的节点，则该组件将被完全感染。 

因此：

 - 具有多个受感染节点的组件无法通过仅删除一个节点来保存。 
- 仅有一个受感染节点的组件可以通过删除该节点来得到完全保护。 

选择唯一感染最大组件的节点可以最大限度地减少最终感染总数。 

## Python 解决方案```python
from typing import List

class Solution:
    def minMalwareSpread(self, graph: List[List[int]], initial: List[int]) -> int:
        n = len(graph)

        component_id = [-1] * n
        component_size = []

        def dfs(node: int, current_id: int) -> int:
            component_id[node] = current_id
            size = 1

            for neighbor in range(n):
                if (
                    graph[node][neighbor] == 1
                    and component_id[neighbor] == -1
                ):
                    size += dfs(neighbor, current_id)

            return size

        current_component = 0

        for node in range(n):
            if component_id[node] == -1:
                size = dfs(node, current_component)
                component_size.append(size)
                current_component += 1

        infected_count = [0] * current_component

        for node in initial:
            infected_count[component_id[node]] += 1

        initial.sort()

        best_node = initial[0]
        max_saved = -1

        for node in initial:
            comp = component_id[node]

            if infected_count[comp] == 1:
                saved = component_size[comp]

                if saved > max_saved:
                    max_saved = saved
                    best_node = node

        return best_node
```实现首先创建数组来跟踪组件成员资格和组件大小。 

DFS函数在计算组件大小的同时，将所有可达节点分配给相同的组件ID。 由于图被表示为邻接矩阵，因此 DFS 检查每个可能的邻居`0`到`n - 1`。 

识别出所有连接的组件后，我们计算每个组件有多少个最初感染的节点。 

排序`initial`确保如果多个节点保存相同数量的顶点，则自动选择最小的索引。 

最后，我们评估每个受感染的节点。 只有作为其组件的唯一受感染成员的节点才能保存任何节点。 返回保存最大分量的节点。 

## 解决方案```go
package main

import "sort"

func minMalwareSpread(graph [][]int, initial []int) int {
	n := len(graph)

	componentID := make([]int, n)
	for i := 0; i < n; i++ {
		componentID[i] = -1
	}

	componentSize := []int{}

	var dfs func(node int, currentID int) int

	dfs = func(node int, currentID int) int {
		componentID[node] = currentID
		size := 1

		for neighbor := 0; neighbor < n; neighbor++ {
			if graph[node][neighbor] == 1 && componentID[neighbor] == -1 {
				size += dfs(neighbor, currentID)
			}
		}

		return size
	}

	currentComponent := 0

	for node := 0; node < n; node++ {
		if componentID[node] == -1 {
			size := dfs(node, currentComponent)
			componentSize = append(componentSize, size)
			currentComponent++
		}
	}

	infectedCount := make([]int, currentComponent)

	for _, node := range initial {
		infectedCount[componentID[node]]++
	}

	sort.Ints(initial)

	bestNode := initial[0]
	maxSaved := -1

	for _, node := range initial {
		comp := componentID[node]

		if infectedCount[comp] == 1 {
			saved := componentSize[comp]

			if saved > maxSaved {
				maxSaved = saved
				bestNode = node
			}
		}
	}

	return bestNode
}
```Go 的实现与 Python 版本非常相似。 

使用切片而不是动态 Python 列表。 DFS 是作为递归闭包实现的，因此它可以自然地访问外部变量。 

Go 需要显式初始化`componentID`到`-1`，因为整数切片默认为`0`。 

排序是使用处理的`sort.Ints(initial)`。 

因为问题约束很小，所以对于这个问题大小，Go 中的递归深度是安全的。

 ## 边缘情况

 ### 一个组件中存在多个受感染节点

 一个常见的错误是假设删除任何受感染的节点有助于减少传播。 如果某个组件包含多个受感染节点，仅删除其中一个并不能阻止感染，因为其余受感染节点仍会在整个组件中传播恶意软件。 

该实现通过计算每个组件的受感染节点数并仅考虑具有一个受感染节点的组件来正确处理这一问题。 

### 多个有效答案之间的平局打破

 多次删除可能会节省相同数量的节点。 该问题明确要求在这种情况下返回最小的节点索引。 

实施排序`initial`加工前。 由于节点按升序评估，因此第一个达到最大保存计数的节点自动成为最小的有效答案。 

### 孤立节点

 节点可以形成大小为一的组件。 如果该隔离节点被感染并且是唯一感染的，则将其删除可以完全防止该组件内的任何感染。 

DFS 自然地将孤立节点视为大小为 1 的组件，因此该算法无需任何特殊逻辑即可处理这种情况。
