[LeetCode 941 题](https://leetcode.com/problems/valid-mountain-array/)

 **难度：** 🟢简单
 **主题：** 数组

 ## 解决方案

 ## 问题理解

 该问题要求我们确定给定的整数数组是否构成有效的山数组。 山阵的结构非常特殊。 这些值必须首先严格增加直至达到单个峰值，然后在峰值后严格减少。 

更正式地说，必须存在一个索引`i`这样：

 - 之前的一切`i`是严格增加的
 - 之后的一切`i`严格递减
 - 峰值不能是第一个或最后一个元素

 这意味着有效的山脉数组看起来就像爬上山顶，然后下山。 

例如，数组`[0,3,2,1]`有效，因为：

 -`0 < 3`-`3 > 2 > 1`价值`3`作为山峰。 

另一方面，`[3,5,5]`无效，因为增加不是严格增加。 重复的`5`违反要求。 

输入是一个整数数组`arr`，输出是一个布尔值：

 - 返回`true`如果数组是有效的山
 - 返回`false`否则

 约束条件告诉我们：

 - 数组长度可以大到`10^4`- 值是非负整数

 这个尺寸足够小，线性解决方案可以在限制范围内舒适地运行。 由于该问题只需要检查数组中的模式，因此我们应该瞄准`O(n)`遍历。 

一些边缘情况很重要：

 - 长度小于 3 的数组永远无法形成一座山
 - 只增加的数组无效
 - 只减的数组无效
 - 相邻值相等的数组无效
 - 峰值不能位于索引处`0`或者`n - 1`简单的实现很容易错过这些条件之一，尤其是相邻元素相等或峰值放置无效。 

## 方法

 ### 蛮力方法

 蛮力策略是测试每一个可能的指标作为山峰。 

对于每个索引`i`，我们可以：

 1.检查之前的所有元素是否`i`正在严格增加
 2.检查后面的所有元素是否`i`严格递减

 如果我们找到满足这两个条件的索引，我们返回`true`。 

这是有效的，因为山阵的定义直接基于这样一个山峰的存在。 

然而，这种方法会重复扫描阵列的大部分以查找每个候选峰。 在最坏的情况下，这会导致二次时间复杂度。 

对于长度的数组`n`，每个峰值检查可能需要`O(n)`工作，并且有`O(n)`候选人高峰。 

### 最优两指针/单次遍历方法

 关键的观察是我们不需要独立测试每个指标。 

一座有效的山恰好有两个阶段：

 1、严格增加
 2. 严格递减

 我们可以模拟爬山：

 - 从头开始
 - 价值增加时向上移动
 - 一旦增加停站，我们就应该到达高峰
 - 然后继续向下移动，同时值下降

 最后：

 - 我们一定已经到达了最后一个索引
 - 峰不能是第一个或最后一个元素

 这是有效的，因为一座有效的山恰好包含一个转折点。 

我们不是重复地重新扫描各个部分，而是在线性时间内处理一次数组。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 尝试将每个索引作为可能的峰值 |

 ## 算法演练

 1. 首先检查数组长度是否小于3。一座山至少需要三个元素，因为它需要上坡、山顶和下坡。 
2. 初始化一个指针`index = 0`。 当我们爬山时，该指针将在数组中移动。 
3、遍历严格递增部分。 当下一个元素大于当前元素时，将指针向前移动。 这模拟爬上坡。 
4. 上坡穿越停止后，验证峰值是否有效。 峰值不能是：

 - 第一个元素，表示没有发生上坡运动
 - 最后一个元素，意味着不存在下坡运动

 如果任一条件为真，则返回`false`。 
5. 遍历严格递减部分。 当下一个元素小于当前元素时，继续向前移动指针。 
6. 下坡遍历结束后，检查指针是否到达最终索引。 如此一来，整个阵法就形成了一座有效的山峰。 否则，存在一些无效模式。 
7. 返回指针是否结束于最终位置。 

### 为什么它有效

 该算法保持指针始终遵循有效山形的不变式：

 - 第一阶段，只能通过严格增加数值来推进
 - 在第二阶段，它仅通过严格递减值来前进

 如果指针在完成两个阶段后正好到达最后一个索引，则该数组满足 mountain 定义。 任何平稳状态、多个峰值或无效排序都会阻止遍历正确到达末尾。 

## Python 解决方案```python
from typing import List

class Solution:
    def validMountainArray(self, arr: List[int]) -> bool:
        n = len(arr)

        if n < 3:
            return False

        index = 0

        # Walk uphill
        while index + 1 < n and arr[index] < arr[index + 1]:
            index += 1

        # Peak cannot be first or last
        if index == 0 or index == n - 1:
            return False

        # Walk downhill
        while index + 1 < n and arr[index] > arr[index + 1]:
            index += 1

        return index == n - 1
```实现严格遵循算法演练。 

变量`n`存储数组长度，这样我们就可以避免重复调用`len(arr)`。 

第一个条件处理太短而无法形成山的数组。 

这`index`指针代表我们翻山时的当前位置。 

第一个`while`循环处理上坡路段。 当价值严格增加时，它才会进步。 

上坡阶段之后，我们验证峰值位置。 如果峰位于任一边界，则该数组不能是有效的山。 

第二个`while`循环处理下坡部分。 当价值严格下降时，它只会上涨。 

最后，该函数检查指针是否到达最后一个索引。 如果不是，则某些无效结构中断了遍历。 

## 解决方案```go
func validMountainArray(arr []int) bool {
    n := len(arr)

    if n < 3 {
        return false
    }

    index := 0

    // Walk uphill
    for index+1 < n && arr[index] < arr[index+1] {
        index++
    }

    // Peak cannot be first or last
    if index == 0 || index == n-1 {
        return false
    }

    // Walk downhill
    for index+1 < n && arr[index] > arr[index+1] {
        index++
    }

    return index == n-1
}
```Go 实现几乎完全反映了 Python 逻辑。 

Go 使用`for`循环而不是Python`while`循环，但遍历行为保持不变。 

不用担心整数溢出，因为问题约束很小，而且我们只执行比较。 

Go 中的切片已经追踪了它们的长度，所以`len(arr)`有效地给出数组大小。 

Nil 切片是自然处理的，因为`len(nil)`是`0`，它正确地未通过最小长度检查。

### 示例 2```
Input: [3,5,5]
Output: false
```| 步骤| 索引 | 比较| 行动|
 | ---| ---| ---| ---|
 | 开始| 0 |`3 < 5`| 上坡 |
 | 上坡| 1 |`5 < 5`是假的 | 停止攀登|
 | 高峰检查| 1 | 迄今为止高峰有效| 继续 |

 -`index = 1`-`n - 1 = 2`由于遍历没有到达最后一个索引，因此返回`false`。

 ## 边缘情况

 一个重要的边缘情况是数组只会增加，例如`[1,2,3,4]`。 幼稚的实现可能会错误地假设达到最大值会自动形成一座山。 然而，一座有效的山需要在顶峰之后有一个下降阶段。 该实现通过拒绝峰值最终位于最终索引的情况来处理此问题。 

另一个关键的边缘情况是相邻值相等，例如`[1,2,2,1]`。 由于该问题需要严格递增和严格递减序列，因此重复的相邻值会使山结构无效。 该实现使用严格的比较运算符（`<`和`>`）而不是非严格比较，确保正确拒绝高原。 

第三个重要的边缘情况是峰值出现在数组的开头或末尾。 数组就像`[3,2,1]`或者`[1,2,3]`失败是因为他们缺少山的一侧。 该实现显式检查峰值索引是否为`0`或者`n - 1`，立即驳回此类案件。 

最后一个微妙的边缘情况涉及非常短的数组，例如`[1]`或者`[1,2]`。 这些数组不可能同时包含上升和下降。 初始长度检查确保立即处理这些无效情况，而无需进行不必要的遍历。
