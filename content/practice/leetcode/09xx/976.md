[LeetCode 第 976 题](https://leetcode.com/problems/largest-perimeter-triangle/)

 **难度：** 🟢简单
 **主题：** 数组、数学、贪心、排序

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个整数数组，称为`nums`，其中每个整数表示可能的边长。 我们的目标是恰好选择三个可以形成面积非零的有效三角形的长度，并在所有有效三角形中返回最大可能的周长。 

仅当两个较小边的总和严格大于最大边时，三角形才有效。 这就是所谓的三角不等式定理。 如果不满足这个条件，则这三个长度要么形成面积为零的简并三角形，要么根本不能形成三角形。 

例如，边长`[1, 2, 2]`形成一个有效的三角形，因为：$1 + 2 > 2$周长是：$1 + 2 + 2 = 5$另一方面，`[1, 1, 2]`无效，因为：$1 + 1 = 2$这会创建一个面积为零的退化三角形，这是该问题明确不允许的。 

输入约束很重要：

 - 数组长度可以大到`10^4`- 每个值可以大到`10^6`这些约束告诉我们，极其缓慢的三次解可能不够高效。 我们需要比在实践中检查每个可能的三元组更好的东西。 

一些边缘情况很重要：

 - 根本无法形成三角形的数组
 - 存在多个有效三角形的数组，但只有一个三角形的周长最大
 - 具有重复值的数组
 - 数组已经排序或完全未排序
 - 非常小的数组，仅包含三个元素

 该问题保证数组至少有三个数字，因此我们永远不需要处理少于三个元素的数组。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查数组中三个数字的每种可能的组合。 对于每个三元组，我们检查它是否满足三角不等式定理。 如果是这样，我们计算它的周长并跟踪最大值。 

这种方法是正确的，因为它详尽地评估了所有可能的三角形，因此它不会错过最佳答案。 

然而，运行时间太昂贵了。 如果数组包含`n`元素，有：$\binom{n}{3} = \frac{n(n-1)(n-2)}{6}$可能的三胞胎。 

和`n = 10^4`，这在计算上变得不可行。 立方时间算法将执行数十亿次运算。 

### 最优贪心法

 关键的观察来自对数组的排序。 

假设数组按非降序排序。 对于任意三个连续元素：```
a <= b <= c
```我们需要检查的唯一条件是：$a + b > c$另外两个三角形不等式自动为真，因为所有边长均为正。 

现在考虑周长最大化。 由于我们想要最大的周长，因此我们应该首先尝试最大值。 排序后，我们可以从数组末尾向开头扫描。 

当我们找到满足三角不等式的三个数时，我们可以立即返回它们的和。 这是有效的，因为：

 - 我们首先检查最大边长
 - 任何后来的三元组将具有相同或更小的值
 - 因此，遇到的第一个有效三角形必须具有最大周长

 这将问题转化为排序问题，然后进行线性扫描。

 ## 算法演练

 1. 对数组进行非降序排序。 

排序很重要，因为它使我们能够有效地推理辅助关系。 一旦排序，任何候选三元组中最大的边始终是最右边的元素。 
2. 从数组末尾开始迭代。 

由于我们想要最大周长，因此我们首先检查最大的数字。 
3. 对于每个索引`i`，考虑三元组：```
nums[i-2], nums[i-1], nums[i]
```这是按排序顺序排列的三个连续元素。 
4. 检查三角不等式条件。 

由于数组已排序：```
nums[i-2] <= nums[i-1] <= nums[i]
```我们只需要验证：$nums[i-2] + nums[i-1] > nums[i]$5. 如果条件为真，则立即返回周长。 

周长是：```
nums[i-2] + nums[i-1] + nums[i]
```因为我们是从最大到最小值扫描，所以这保证是最大的可能周长。 
6. 如果没有找到有效的三元组，则返回`0`。 

这意味着数组中没有三个数字可以形成有效的三角形。 

### 为什么它有效

 正确性依赖于两个属性：

 - 在排序数组中，三角形不等式只需为每个三元组检查一次。 
- 通过从最大的元素向下扫描，遇到的第一个有效三角形自动具有最大可能的周长。 

任何后来的候选者都将包含较小的边长，因此不能产生更大的周长。 

## Python 解决方案```python
from typing import List

class Solution:
    def largestPerimeter(self, nums: List[int]) -> int:
        nums.sort()

        for i in range(len(nums) - 1, 2, -1):
            if nums[i - 2] + nums[i - 1] > nums[i]:
                return nums[i - 2] + nums[i - 1] + nums[i]

        return 0
```实现首先按升序对数组进行排序。 这可以实现高效的三角形验证并保证首先考虑较大的周长。 

循环从最终索引开始向后移动。 在每个步骤中，代码都会检查三个连续的元素：```python
nums[i - 2], nums[i - 1], nums[i]
```因为数组是有序的，`nums[i]`是最大的一面。 该代码检查两个较小边的总和是否超过最大边。 

如果满足条件，该函数立即返回周长，因为这是可能的最大有效三角形。 

如果循环完成时没有找到有效的三角形，则函数返回`0`。 

## 解决方案```go
package main

import "sort"

func largestPerimeter(nums []int) int {
	sort.Ints(nums)

	for i := len(nums) - 1; i >= 2; i-- {
		if nums[i-2]+nums[i-1] > nums[i] {
			return nums[i-2] + nums[i-1] + nums[i]
		}
	}

	return 0
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 主要区别在于使用`sort.Ints(nums)`从 Go 的标准库中对切片进行就地排序。 

Go 切片是对数组的可变引用，因此排序会直接修改原始切片。 整数溢出在这里不是一个问题，因为最大可能的周长是：```go
3 * 10^6
```很容易适合 Go 的内部`int`在现代平台上输入。

 ## 边缘情况

 一种重要的边缘情况是根本无法形成三角形。 数组如`[1, 1, 2]`或者`[1, 2, 10]`三角不等式定理失败。 幼稚的实现可能会意外地允许相等，但条件必须严格更大。 实施正确地检查：$a + b > c$而不是`>=`。 

当最大的数字不形成三角形，但较小的数字却形成三角形时，就会出现另一个重要的边缘情况。 例如：```
[3, 6, 2, 3]
```排序后：```
[2,3,3,6]
```三胞胎`(3,3,6)`是无效的，但是`(2,3,3)`是有效的。 向后扫描自然会继续处理这个问题，直到找到有效的组合。 

第三种边缘情况涉及重复值。 数组就像`[5,5,5,5]`包含许多相同的边长。 一些实现错误地假设唯一性或在排序或迭代期间错误地处理重复项。 此解决方案独立处理所有元素，因此重复值可以正常工作。 

最后，只有三个元素的数组需要仔细处理，因为只有一个可能的三元组。 实现中的循环边界正确地允许检查单个候选者，而不会导致索引错误。
