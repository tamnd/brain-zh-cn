[LeetCode 964 题](https://leetcode.com/problems/least-operators-to-express-number/)

 **难度：** 🔴难
 **主题：** 数学、动态规划、记忆

 ## 解决方案

 ## 问题理解

 这个问题要求我们仅使用数字构造一个数学表达式`x`反复与运营商结合`+`,`-`,`*`， 和`/`，这样最终表达式的计算结果恰好为`target`。 

挑战不仅仅是达到目标值，而是用最少的操作员数量来实现这一目标。 

例如，如果`x = 3`和`target = 19`，一种最佳表达式是：```
3 * 3 + 3 * 3 + 3 / 3
```这评估为：```
9 + 9 + 1 = 19
```并使用 5 个运算符：```
*, +, *, +, /
```一些限制使得这个问题比最初看起来要困难得多。 

首先，我们不能使用括号，因此正常的运算符优先级规则会自动应用。 乘法和除法发生在加法和减法之前。 

其次，禁止一元否定。 我们不能写`-x`，虽然表达式像`x - x`是有效的。 

第三，除法产生有理数，这一点极其重要。 自从：```
x / x = 1
```我们总是可以构造这个数字`1`仅使用一个运算符。 

输入包括：

 -`x`，我们唯一可以使用的号码
 -`target`，我们必须表达的值

 输出是所需的最少操作员数量。 

限制条件是：

 -`2 <= x <= 100`-`1 <= target <= 2 * 10^8`目标可能非常大，这立即告诉我们暴力表达生成是不可行的。 我们需要高度优化的数学策略。 

一些边缘情况很重要：

 - 当`target < x`，乘法不会立即有用，我们必须使用涉及的加法或减法来构建该值`1 = x/x`。 
- 什么时候`target`正好是`x`，最佳答案是直接乘法。 
- 有时，超调和减去比直接建立值更便宜。 例如，代表`24`和`x = 5`更便宜，因为`25 - 1`比建造`24`直接地。 
- 因为允许减法，所以每一步都必须考虑多种表示。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试使用重复的副本生成所有有效的表达式`x`和不同的运算符组合，然后评估哪些表达式相等`target`。 

从概念上讲，这是可行的，因为每个有效的表达式最终都可以被枚举。 我们可以递归地尝试：

 - 添加另一个`x`- 减去另一个`x`- 乘以另一个`x`- 除以另一个`x`并不断探索，直到达到目标。 

然而，这很快在计算上变得不可能。 

可能的表达式的数量随着表达式长度呈指数增长。 此外，由于划分创造了理性价值，因此状态空间变得巨大。 即使进行了修剪，搜索树也会爆炸性地寻找附近的目标`2 * 10^8`。 

因此，这种方法是完全不切实际的。 

### 关键见解

 关键的观察是每个数字都可以用基数表示`x`。 

例如：```
target = 19, x = 3

19 = 2 * 3^2 + 0 * 3^1 + 1 * 3^0
```这表明我们应该将问题视为构建权力`x`。 

创建权力的成本是可以预测的：```
x^0 = x / x    -> cost 1
x^1 = x        -> cost 0
x^2 = x * x    -> cost 1
x^3 = x * x * x -> cost 2
```一般来说：```
cost(x^k) = k
```运营商。 

现在问题变成了基于基础的动态规划问题`x`目标的数字。 

对于每个数字，我们有两种选择：

 - 直接构建数字
 - 过冲到下一个幂并减去

 这会产生一个具有重叠子问题的递归优化问题，使记忆化成为理想的选择。

 ## 算法演练

 ### 第 1 步：定义构建权力的成本

 我们首先观察每个幂次的算子成本`x`。 

例如：```
x^1 = x
```无需操作员。```
x^2 = x * x
```需要一次乘法。```
x^k
```需要`k - 1`乘法，但在 DP 公式中，我们将位置成本视为`k`。 

特殊情况是：```
1 = x / x
```这需要一名操作员的费用。 

### 第 2 步：将问题转化为基础问题 -`x`我们反复将目标除以`x`。 

例如：```
target = 19
x = 3
```Base-3 表示法：```
19 = 2 * 9 + 0 * 3 + 1
```数字按从最低有效位到最高有效位的顺序进行处理。 

### 步骤 3：维持两个 DP 状态

 对于每个数字位置`k`，我们维持：

 -`positive`，如果我们直接构建当前余数，则最小成本
 -`negative`，如果我们超调然后减去的最小成本

 这是核心优化技巧。 

有时构建：```
digit * x^k
```直接就贵了。 

相反，建造成本可能会更便宜：```
(digit + 1) * x^k
```然后减去多余的部分。 

### 步骤 4：状态之间的转换

 假设：```
target % x = remainder
```在数字位置`k`:

 直接建设成本：```
remainder * k
```超调成本：```
(x - remainder) * k
```我们使用最佳可能的转换来更新两个 DP 状态。 

### 步骤 5：继续，直到处理完整个目标

 我们反复将目标除以`x`：```
target //= x
```直到目标变为零。 

每次迭代都会处理一个碱基`x`数字。 

### 第 6 步：返回最终最小值

 最终的答案是：```
min(positive, k + negative) - 1
```发生减 1 是因为第一个数字不需要前导运算符。 

### 为什么它有效

 该算法之所以有效，是因为每个整数都有一个唯一的基数`x`表示。 在每个数字位置，最佳解决方案必须：

 - 直接构建数字，或者
 - 过冲并稍后补偿

 DP 探索了这两种可能性，同时记住了最优成本。 由于所有有效的构造都简化为以下幂的组合`x`，并且每个幂都有确定性的算子成本，该算法详尽地考虑了所有最优表示，而没有冗余计算。 

## Python 解决方案```python
class Solution:
    def leastOpsExpressTarget(self, x: int, target: int) -> int:
        positive = 0
        negative = 0
        power_cost = 0

        while target:
            target, remainder = divmod(target, x)

            if power_cost == 0:
                positive = remainder * 2
                negative = (x - remainder) * 2
            else:
                next_positive = min(
                    remainder * power_cost + positive,
                    (remainder + 1) * power_cost + negative
                )

                next_negative = min(
                    (x - remainder) * power_cost + positive,
                    (x - remainder - 1) * power_cost + negative
                )

                positive = next_positive
                negative = next_negative

            power_cost += 1

        return min(positive, negative + power_cost) - 1
```该实现在基数中逐位处理目标数字`x`。 

变量`positive`和`negative`跟踪两个 DP 状态的最小操作员计数。`positive`表示直接构建当前前缀，而`negative`代表超调，稍后减去。 

变量`power_cost`对应于当前功率`x`。 在位置`k`，构造一个副本`x^k`成本`k`运营商。 

第一个数字经过特殊处理，因为代表`1`要求：```python
x / x
```在 DP 计费方案中，这需要两个符号和一个运算符。 

对于每个后续数字，我们计算两个转换：

 - 直接施工
 - 超调施工

 最后，我们减一，因为第一个操作数不需要前面的运算符。 

## 解决方案```go
func leastOpsExpressTarget(x int, target int) int {
    positive := 0
    negative := 0
    powerCost := 0

    for target > 0 {
        remainder := target % x
        target /= x

        if powerCost == 0 {
            positive = remainder * 2
            negative = (x - remainder) * 2
        } else {
            nextPositive := min(
                remainder*powerCost+positive,
                (remainder+1)*powerCost+negative,
            )

            nextNegative := min(
                (x-remainder)*powerCost+positive,
                (x-remainder-1)*powerCost+negative,
            )

            positive = nextPositive
            negative = nextNegative
        }

        powerCost++
    }

    return min(positive, negative+powerCost) - 1
}

func min(a, b int) int {
    if a < b {
        return a
    }
    return b
}
```Go 实现遵循与 Python 版本完全相同的 DP 逻辑。 

因为Go没有提供内置的`min`对于整数函数，我们手动定义一个助手。 

所有值都安全地适合 Go 的范围`int`范围在给定的约束下，因此不需要特殊的溢出处理。 

与 Python 不同，Go 需要显式变量声明和手动整数除法处理，但其他实现结构是相同的。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`target < x`。 在这种情况下，乘法并不会立即有用，因为即使是单个乘法也会产生大于目标的值。 该算法必须决定直接使用重复构建目标是否更便宜`1`s 或使用超调`x`并减去回来。 这正是为什么`positive`和`negative`DP 状态都存在。 

当目标恰好是`x`， 例如：```
x = 100
target = 100000000
```幼稚的实现可能仍然会探索不必要的加法和减法组合。 DP 公式自然可以有效地处理这个问题，因为基本`x`表示包含单个非零数字。 

第三种微妙的边缘情况涉及在超调时更便宜的表示。 例如：```
24 with x = 5
```直接建造是昂贵的，但是：```
25 - 1
```便宜得多。 仅考虑直接数字构造的算法在这里将失败。 负进位状态确保始终考虑过冲解决方案。 

错误的另一个潜在来源是处理构建成本`1`。 自从：```
1 = x / x
```运算符计数不同于更高的幂`x`。 该实现通过在以下情况下单独处理最低数字位置来处理此问题：`power_cost == 0`。 

Finally, the problem statement forbids unary negation. 表达如`-x + x`均无效。 DP 从不构造独立的否定项。 相反，减法始终表示为从一个有效表达式中减去另一个有效表达式，这完全符合问题约束。
