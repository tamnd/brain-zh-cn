 **难度：** 🟡 中等
 **主题：** 字符串、动态规划

 ## 解决方案

 ## 问题理解

 该问题要求我们使用最少的字符翻转次数将二进制字符串转换为单调递增字符串。 

一个二进制字符串被认为是单调递增的，如果`0`s出现在所有之前`1`s。 换句话说，一旦`1`出现，没有`0`可以出现在它之后。 有效的例子包括：

 -`"000111"`-`"111"`-`"000"`-`""`conceptually, though the constraints guarantee at least one character

 无效的示例包括：

 -`"010"`-`"101"`-`"1100"`我们得到一个字符串`s`仅由`'0'`和`'1'`。 我们可以翻转任何字符：

 -`'0'`→`'1'`-`'1'`→`'0'`我们的目标是计算所需的最小翻转次数，以便最终的字符串变为单调递增。 

约束条件很重要：

 -`1 <= s.length <= 10^5`- 字符串仅包含二进制数字

 长度为`10^5`意味着指数或二次解可能太慢。 我们需要一种以线性时间或接近线性时间运行的算法。 

一些边缘情况很重要：

 - 字符串已经单调递增，例如`"000111"`或者`"11111"`- 完全由一个字符组成的字符串
 - 交替模式，例如`"010101"`- 提前翻转的情况`1`s 比稍后翻转便宜`0`s
 - 非常短的字符串，例如`"0"`或者`"1"`如果仅查看本地而不考虑字符串的全局结构，幼稚的实现很容易做出错误的贪婪决策。 

## 方法

 ### 蛮力方法

 单调递增的二进制字符串总是有一个边界点：

 - 边界之前的所有内容都是`0`- 边界之后的所有内容都是`1`对于一个长度的字符串`n`， 有`n + 1`可能的边界。 

对于每个边界位置`i`：

 - 之前的字符`i`都应该是`0`- 人物来自`i`以后应该都是`1`我们可以数一下：

 - 有多少`1`s 出现在之前`i`，这些必须翻转到`0`- 有多少`0`s 出现在`i`，这些必须翻转到`1`该边界的总翻转次数为：```
(flips on left) + (flips on right)
```我们对每个可能的边界进行计算并取最小值。 

这是有效的，因为每个有效的单调递增字符串都可以由之间的某种分割来表示`0`沙`1`s。 

然而，一个简单的实现会扫描字符串的每个边界，产生`O(n^2)`时间复杂度，对于`n = 10^5`。 

### 最佳解决方案的关键见解

 重要的观察是，从左到右扫描字符串时，我们只需要两条信息：

 - 有多少`1`到目前为止我们已经看到了
 - 到目前为止所需的最少翻转次数

 当我们遇到一个`'0'`，我们有两个选择：

 - 翻转这个`'0'`到`'1'`- 翻转所有以前的内容`'1'`字符到`'0'`我们选择更便宜的选择。 

这导致了具有恒定额外空间的动态编程风格解决方案。 

每一步：

 -`ones_count`跟踪有多少`1`s已经出现了
 -`flips`跟踪到达当前位置所需的最少翻转次数

 当我们看到：

 -`'1'`，我们增加`ones_count`-`'0'`，我们决定：

 - 翻转电流`0`，成本变为`flips + 1`- 翻转上一个`1`s，成本变为`ones_count`所以：```
flips = min(flips + 1, ones_count)
```这给出了一个优雅的线性时间解决方案。

 ## 算法演练

 1.初始化两个变量：

 -`ones_count = 0`-`flips = 0`

`ones_count`跟踪有多少`1`到目前为止我们已经遇到过。`flips`存储使处理后的前缀单调递增所需的最小翻转。 
2. 逐个字符地遍历字符串。 
3. 如果当前字符是`'1'`:

 - 增量`ones_count`一个`1`自然地适合单调递增序列，因此不需要立即翻转。 
4. 如果当前字符是`'0'`:

 - 这会产生潜在的违规行为，因为`0`早先之后`1`s 打破了单调性。 
- 我们有两个可能的修复方案：

 - 翻转这个`0`进入`1`- 成本变为`flips + 1`- 翻转所有以前的内容`1`进入`0`- 成本变为`ones_count`5.更新：```
flips = min(flips + 1, ones_count)
```6. 继续，直到处理完整个字符串。 
7. 返回`flips`。 

### 为什么它有效

 该算法在处理索引后保持了不变式`i`,`flips`等于形成前缀所需的最少翻转次数`s[0:i+1]`单调递增。 

每当我们遇到一个`0`经过一些`1`s，只有两种有效的可能性：

 - 转换电流`0`进入`1`- 转换以前的`1`进入`0`复发总是选择更便宜的选项，保证最佳结果。 

## Python 解决方案```python
class Solution:
    def minFlipsMonoIncr(self, s: str) -> int:
        ones_count = 0
        flips = 0

        for char in s:
            if char == '1':
                ones_count += 1
            else:
                flips = min(flips + 1, ones_count)

        return flips
```该实现紧密遵循前面描述的算法。 

变量`ones_count`记录了多少`1`到目前为止已经出现了。 这很重要，因为如果我们以后遇到问题`0`，一种可能的策略是提前全部翻转`1`进入`0`是。 
变量`flips`存储处理后的前缀所需的最少翻转。 

遍历字符串时：

 - A`'1'`只是增加`ones_count`- A`'0'`强制做出决定：

 - 翻转这个`0`- 或翻转上一个`1`is
 该行：```python
flips = min(flips + 1, ones_count)
```直接编码这个决定。 

The algorithm only uses constant extra memory and processes each character exactly once.

 ## 解决方案```go
func minFlipsMonoIncr(s string) int {
    onesCount := 0
    flips := 0

    for _, ch := range s {
        if ch == '1' {
            onesCount++
        } else {
            if flips+1 < onesCount {
                flips = flips + 1
            } else {
                flips = onesCount
            }
        }
    }

    return flips
}
```Go 实现与 Python 版本几乎相同。 

一些特定于 Go 的细节值得注意：

 - Go 中的字符串使用以下方式进行迭代`range`，返回符文
 - 整数溢出不是问题，因为最大答案最多是`10^5`- 不需要额外的切片或数组，因此内存使用量保持不变
 - Go没有内置的`min`整数函数，因此比较是显式编写的

 ## 边缘情况

 ### 字符串已经单调递增

 输入如`"000111"`或者`"11111"`已经有效。 有缺陷的实现可能会执行不必​​要的翻转，因为它无法正确识别有效的前缀。 

此实现可以正确处理这些问题，因为：

 - 遇到`1`s 仅增量`ones_count`- 遇到领导`0`s 不增加`flips`因此，`flips`遗迹`0`。 

### 所有角色都相同

 仅包含的字符串`0`或仅`1`s 是平凡单调递增的。 

示例：

 -`"00000"`-`"11111"`某些实现错误地假设两个数字都必须出现。 这个解决方案不做那个假设，自然返回`0`。 

### 交替模式

 输入如`"101010"`具有挑战性，因为局部贪婪的选择可能会失败。 

例如：```
101010
```在几个点上，算法必须决定翻转是否更便宜：

 - 当前`0`- 或之前的`1`是
 复发：```
min(flips + 1, ones_count)
```确保每一步都保留全局最优选择。 

### 非常短的字符串

 长度的字符串`1`可以很容易地暴露出相差一的错误。 

示例：

 -`"0"`-`"1"`由于循环独立处理字符并且不使用索引技巧，因此实现可以安全地处理这些字符，而无需特殊情况逻辑。
