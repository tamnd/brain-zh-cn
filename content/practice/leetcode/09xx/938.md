[LeetCode 第 938 题](https://leetcode.com/problems/range-sum-of-bst/)

 **难度：** 🟢简单
 **主题：** 树、深度优先搜索、二叉搜索树、二叉树

 ## 解决方案

 ## 问题理解

 这个问题给了我们二叉搜索树（缩写为 BST）的根，以及两个整数，`low`和`high`。 我们必须计算其值位于包含范围内的所有节点值的总和`[low, high]`。 

二叉搜索树有一个重要的属性：

 - 左子树中的每个节点的值都小于当前节点。 
- 右子树中的每个节点都有比当前节点更大的值。 

这种排序属性是使我们能够有效解决问题的关键观察结果。 

输入包括：

 -`root`，这是 BST 的根节点
 -`low`, 允许范围的下限
 -`high`, 允许范围的上限

 输出是一个整数，表示所有节点值的总和，如下所示：```
low <= node.val <= high
```这些约束告诉我们一些重要的事情：

 - 树最多可以包含`2 * 10^4`节点，因此理想的解决方案应该是线性或接近线性的。 
- 节点值是唯一的，这简化了推理，因为我们永远不需要处理重复的值。 
- 值可以大到`10^5`，但这并不会显着影响算法的选择，因为我们是遍历节点，而不是按值索引。 

一个重要的细节是，这是一个 BST，而不仅仅是一个常规的二叉树。 幼稚的实现可能会忽略此属性并遍历每个节点。 虽然这仍然有效，但它错过了优化机会。 

有几种边缘情况值得考虑：

 - 一棵树可能只包含一个节点。 
- 每个节点都可能落在该范围内。 
- 任何节点都不能落入该范围内。 
- 有效范围只能包括叶节点。 
- BST 可能严重倾斜，表现得像一个链表。 

该问题保证树至少包含一个节点，并且所有节点值都是唯一的。 

## 方法

 ### 蛮力方法

 暴力解决方案很简单。 我们对树进行完整的遍历，访问每个节点，无论其值如何。 

对于每个节点：

 - 如果其值在`[low, high]`，我们将其添加到运行总和中。 
- 否则，我们会忽略它。 

深度优先遍历（例如前序、中序或后序）都同样有效，因为最终必须检查每个节点。 

这种方法是正确的，因为它显式地评估每个节点并准确地包括那些满足范围条件的节点。 

然而，该解决方案忽略了 BST 属性。 即使整个子树不可能包含有效值，算法仍然会遍历它。 对于大树来说，不必要的工作变得低效。 

### 使用 BST 剪枝的最佳方法

 BST 排序属性允许我们跳过整个子树。 

考虑一个有价值的节点`x`：

- 如果`x < low`，那么左子树中的每个值也小于`low`，因为所有左子树值都小于`x`。 因此，可以跳过整个左子树。 
- 如果`x > high`，那么右子树中的每个值也都大于`high`，因此可以跳过整个右子树。 
- 如果`low <= x <= high`，那么当前节点对总和有贡献，并且两个子树仍可能包含有效节点。 

这种修剪大大减少了不必要的遍历。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(h) | 访问每个节点，无论 BST 排序如何 |
 | 最佳 | O(n) 最坏情况，通常要好得多 | O(h) | 使用 BST 属性修剪不需要的子树 |

 这里：

-`n`是节点数
 -`h`是树的高度

 在平衡树中，修剪通常会消除树的大部分。 

## 算法演练

 1. 从根节点开始递归DFS遍历。 
2. 如果当前节点是`None`， 返回`0`。 

这是基本情况。 空子树对总和没有任何贡献。 
3. 如果当前节点值小于`low`，仅递归搜索右子树。 

由于这是一个 BST，左子树中的每个节点都更小，因此它们都不属于有效范围。 
4. 如果当前节点值大于`high`，仅递归搜索左子树。 

右子树中的每个节点都更大，因此右子树可以完全忽略。 
5. 否则，当前节点位于范围内。 

将当前节点值添加到左递归调用和右递归调用返回的总和中。 
6. 将计算出的总和返回给调用者。 

### 为什么它有效

 该算法之所以有效，是因为 BST 属性保证了子树内的排序。 

每当节点值小于`low`，保证整个左子树包含无效值。 类似地，当节点值大于`high`，保证整个右子树包含无效值。 

因此，该算法永远不会跳过可能包含有效值的子树，并且永远不会包含范围之外的节点。 这样就保证了正确性。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional

class Solution:
    def rangeSumBST(
        self,
        root: Optional["TreeNode"],
        low: int,
        high: int
    ) -> int:

        def dfs(node: Optional["TreeNode"]) -> int:
            if node is None:
                return 0

            if node.val < low:
                return dfs(node.right)

            if node.val > high:
                return dfs(node.left)

            return (
                node.val
                + dfs(node.left)
                + dfs(node.right)
            )

        return dfs(root)
```该实现使用名为的递归辅助函数`dfs`。 

第一个条件处理基本情况。 如果节点是`None`，子树对总和的贡献为零。 

第二个条件检查节点值是否小于`low`。 在这种情况下，整个左子树都会被跳过，因为那里的所有值都保证更小。 

第三个条件检查节点值是否大于`high`。 然后算法出于同样的原因跳过右子树。 

如果这两个条件都不适用，则该节点位于有效范围内。 该算法将当前节点值相加并递归地探索两个子树。 

最终答案通过调用返回`dfs(root)`。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */

func rangeSumBST(root *TreeNode, low int, high int) int {
    var dfs func(node *TreeNode) int

    dfs = func(node *TreeNode) int {
        if node == nil {
            return 0
        }

        if node.Val < low {
            return dfs(node.Right)
        }

        if node.Val > high {
            return dfs(node.Left)
        }

        return node.Val + dfs(node.Left) + dfs(node.Right)
    }

    return dfs(root)
}
```Go 实现遵循与 Python 解决方案相同的递归逻辑。 

主要的语言差异是处理`nil`指针而不是`None`。 

Go 还要求在分配函数定义之前显式声明递归函数变量，这就是原因：```go
var dfs func(node *TreeNode) int
```出现在函数体之前。 

整数溢出在这里不是问题，因为最大可能的和仍然在 Go 的标准整数范围内。

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | 最坏情况 | O(n) 最坏情况下每个节点仍可能被访问 |
 | 空间| O(h) | 递归调用栈高度等于树高|

 最坏的情况发生在以下情况：

 - 树完全倾斜，或者
 - 几乎所有节点都在该范围内

 在平衡树中，修剪通常会显着减少访问节点的数量，尽管理论上最坏的情况仍然存在`O(n)`。 

递归栈使用`O(h)`空间，哪里`h`是树的高度。 在平衡树中，这变成了`O(log n)`。 在倾斜的树木中，它可以降解为`O(n)`。

 ## 边缘情况

 ### 单节点树

 只有一个节点的树是最小的有效输入。 这种情况可能会暴露错误处理递归基本情况的错误。 

如果单个节点位于范围内，算法将返回其值。 否则，它返回`0`。 该实现自然地处理了这个问题，因为递归立即计算根并终止。 

### 范围内没有值

 每个节点值都有可能位于外部`[low, high]`。 

幼稚的实现可能仍然不必要地遍历整个树。 优化的 BST 解决方案通过修剪避免了大部分工作。 例如，如果所有节点值都小于`low`，算法反复跳过左子树并仅向右移动。 

执行正确返回`0`因为没有节点满足包含条件。 

### 高度倾斜的树

 BST 可能会变得完全不平衡，实际上变成了链表。 

例如：```
1
 \
  2
   \
    3
     \
      4
```这种情况很重要，因为递归深度变成`O(n)`而不是`O(log n)`。 

该实现仍然会产生正确的答案，因为递归逻辑不依赖于树平衡。 然而，在这种情况下，递归堆栈随着树的高度线性增长。
