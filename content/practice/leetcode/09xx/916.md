[LeetCode 916 题](https://leetcode.com/problems/word-subsets/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、字符串

 ## 解决方案

 ## 问题理解

 该问题要求我们确定哪些字符串`words1`满足中每个字符串施加的所有字符要求`words2`。 

一个字符串`b`被认为是另一个字符串的子集`a`如果中的每个字符`b`出现在`a`至少与它出现的次数一样多`b`。 这包括重复的字符。 例如，`"eoo"`需要一个`'e'`和两个`'o'`人物。 

对于其中的每个单词`words1`，我们必须检查它是否满足每个单词的每个约束`words2`。 如果是，则称为通用词，应包含在结果中。 

输入包括：

 -`words1`，我们要测试的候选词列表
 -`words2`，所需字符模式列表

 输出是一个包含所有通用单词的列表`words1`。 

约束条件很重要：

 - 两个数组最多可以包含`10^4`话
 - 每个单词长度最多`10`- 仅使用小写英文字母

 短字长很重要，因为它意味着字符频率计数很便宜。 然而，单词的数量可能很大，因此重复比较每对单词会变得很昂贵。 

如果简单的实现检查中的每个单词，它很容易变得太慢`words1`反对其中的每一个字`words2`独立。 

有几个重要的边缘情况：

 -`words2`可能包含重叠的要求，例如`"e"`和`"ee"`- 多个单词`words2`可能需要不同的字符
 - 必填单词可能包含重复的字母，例如`"ccc"`- 候选词可能包含额外的字符，这应该不重要
 - 非常短的单词，包括单字符字符串，仍然必须正常工作

 该问题保证了所有字符串`words1`是唯一的，这简化了结果处理，因为重复项不需要特殊处理。 

## 方法

 ### 蛮力方法

 最直接的解决办法就是测试每一个单词`words1`反对其中的每一个字`words2`。 

对于每个候选词：

 1. 建立其字符的频率计数
 2. 对于每一个单词`words2`:

 - 建立另一个频率计数
 - 验证候选字符是否包含具有足够多重性的每个所需字符

 如果候选人通过了每项检查，请将其添加到结果中。 

这种方法是正确的，因为它独立地显式验证每个需求。 然而，它重复了大量的工作。 如果有几个词`words2`需要相同的字符，这些要求会被一遍又一遍地重新计算。 

高达`10^4`每个数组中都有单词，这种重复检查变得低效。 

### 最佳解决方案的关键见解

 批判性的观察是，所有单词`words2`可以合并为单个组合需求。 

认为`words2 = ["e", "oo"]`。 

一个通用词只需要：

 - 至少一个`'e'`- 至少两个`'o'`一旦我们知道每个字符所需的最大数量，就不需要单独检查这两个单词。 

相似地：

-`"e"`需要`e:1`-`"ee"`需要`e:2`真正的组合要求很简单`e:2`。 

因此，不要检查中的每个单词`words2`独立地，我们可以计算一个全局频率要求数组，其中每个字符存储所有单词所需的最大频率`words2`。 

然后每个候选词`words1`只需根据此组合要求检查一次。 

这极大地减少了冗余工作。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n × m × 26) | O(26) | 反复重新检查每个约束 |
 | 最佳| O((n + m) × 26) | O(26) | 将所有要求合并到一个频率配置文件中 |

 这里：

-`n = total characters across words1`-`m = total characters across words2`由于每个字长最多为 10，因此复杂度实际上与字数成线性关系。 

## 算法演练

 1. 创建一个频率数组，表示每个字符所需的最大计数。 

我们使用大小为 26 的数组，因为输入仅包含小写英文字母。 指数`0`对应于`'a'`， 指数`1`到`'b'`， 等等。 
2. 遍历其中的每个单词`words2`。 

对于每个单词，计算其字符频率计数。 
3. 将当前单词的频率合并到全局需求数组中。 

对于每个角色：

 - 保持迄今为止看到的最大计数
 - 这代表了所有单词中最强的要求

 例如：

 -`"e"`给出`e:1`-`"ee"`给出`e:2`合并后的需求变为`e:2`。 
4. 迭代中的每个单词`words1`。 

对于每个候选词：

 - 计算其字符频率计数
 - 将其与全局需求数组进行比较
 5. 验证候选人是否满足每项要求。 

对于每个角色：

 - 如果候选频率小于所需频率，则立即拒绝该词
 6. 如果满足所有要求，则将该单词附加到结果列表中。 
7. 返回最终结果列表。 

### 为什么它有效

 该算法之所以有效，是因为合并的需求数组捕获了所有单词中每个字符的最强需求。`words2`。 

如果候选单词满足这些最大要求，那么它会自动满足中的每个单词`words2`。 

这已经足够了，因为子集关系是针对每个字符频率独立确定的。 

## Python 解决方案```python
from typing import List

class Solution:
    def wordSubsets(self, words1: List[str], words2: List[str]) -> List[str]:
        def count_chars(word: str) -> List[int]:
            counts = [0] * 26
            
            for ch in word:
                counts[ord(ch) - ord('a')] += 1
            
            return counts

        required = [0] * 26

        # Build the maximum requirement from words2
        for word in words2:
            word_counts = count_chars(word)

            for i in range(26):
                required[i] = max(required[i], word_counts[i])

        result = []

        # Check each word in words1
        for word in words1:
            word_counts = count_chars(word)

            is_universal = True

            for i in range(26):
                if word_counts[i] < required[i]:
                    is_universal = False
                    break

            if is_universal:
                result.append(word)

        return result
```实现从一个名为的辅助函数开始`count_chars`，它将单词转换为大小为 26 的频率数组。这种表示形式允许恒定时间访问字符计数。 

这`required`数组存储所有单词的合并需求`words2`。 对于其中的每一个词`words2`，我们计算其频率计数并用迄今为止看到的最大值更新每个字符位置。 

预处理完需求后，我们迭代中的每个候选词`words1`。 将其频率数组与全局需求数组进行比较。 

如果候选人缺少任何字符的足够出现次数，则使用早期中断立即拒绝。 否则，它被添加到结果列表中。 

最终结果包含所有通用单词。 

## 解决方案```go
func wordSubsets(words1 []string, words2 []string) []string {
	countChars := func(word string) [26]int {
		var counts [26]int

		for _, ch := range word {
			counts[ch-'a']++
		}

		return counts
	}

	var required [26]int

	// Build maximum requirement from words2
	for _, word := range words2 {
		wordCounts := countChars(word)

		for i := 0; i < 26; i++ {
			if wordCounts[i] > required[i] {
				required[i] = wordCounts[i]
			}
		}
	}

	result := []string{}

	// Check each word in words1
	for _, word := range words1 {
		wordCounts := countChars(word)

		isUniversal := true

		for i := 0; i < 26; i++ {
			if wordCounts[i] < required[i] {
				isUniversal = false
				break
			}
		}

		if isUniversal {
			result = append(result, word)
		}
	}

	return result
}
```Go 解决方案与 Python 实现非常相似。 一个显着的区别是使用固定大小的数组`[26]int`而不是字符频率的切片。 由于字母表大小是恒定的，因此固定数组非常高效并且可以避免额外的分配。 

Go 字符串的迭代使用`range`，产生符文。 因为保证输入只包含小写英文字母，所以减去`'a'`安全地将字符映射到索引中`0`到`25`。 

结果切片开始为空并动态增长`append`。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`words2`包含对同一字符的重复要求，例如`["e", "ee", "eee"]`。 幼稚的实现可能会错误地对这些计数求和并需要六个`'e'`人物。 正确的行为是仅需要最大计数，即三。 该实现通过存储每个字符的最大频率来正确处理这个问题。 

另一个重要的情况涉及单个单词内重复的字母，例如`"ccc"`或者`"aabb"`。 有缺陷的实现可能只检查字符是否存在，而不检查它是否出现足够的次数。 该解决方案使用全频率阵列，因此可以精确处理多重性。 

当没有单词满足约束时，就会出现第三种边缘情况。 例如，如果`words2 = ["zzz"]`并且没有候选人包含三个`'z'`字符，结果应该是一个空列表。 该实现自然会处理这个问题，因为每个候选者都未能通过频率比较，并且结果中不会附加任何内容。 

一个微妙的情况涉及包含许多额外字符的单词。 额外的字符不应使候选人无效。 例如，`"facebook"`对于要求仍然有效`"eo"`即使它包含许多不相关的字母。 该算法仅检查所需频率的下限，因此额外的字符会被正确忽略。 

最后，单字符输入是重要的边界情况。 包含单词的数组，例如`"a"`或者`"b"`验证索引逻辑和频率计数即使在最小尺寸下也能正常工作。
