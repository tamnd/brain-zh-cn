[LeetCode 981 题](https://leetcode.com/problems/time-based-key-value-store/)

 **难度：** 🟡 中等
 **主题：** 哈希表、字符串、二分搜索、设计

 ## 解决方案

 ## 问题理解

 这个问题要求我们设计一个行为类似于键值存储的数据结构，但有一个重要的变化：随着时间的推移，同一个键可以有多个值。 每个值都与一个时间戳相关联，后续查询必须返回请求的时间戳或之前存在的最新值。 

在普通的哈希图中，每个键都指向一个值。 在这个问题中，单个key可以累积多个历史版本。 例如，如果我们存储：

 -`"foo" -> "bar"`在时间戳`1`-`"foo" -> "bar2"`在时间戳`4`然后查询`"foo"`在时间戳`5`应该返回`"bar2"`因为它是之前或当时存在的最新值`5`。 查询`"foo"`在时间戳`3`应该返回`"bar"`因为`"bar2"`还不存在。 

输入由两个操作组成：

 -`set(key, value, timestamp)`在特定时间戳存储键的值。 
-`get(key, timestamp)`检索与小于或等于请求时间戳的最大时间戳关联的值。 

这些约束对于确定正确的解决方案策略极其重要。 最多可以有`2 * 10^5`操作，因此低效的查找将变得太慢。 时间戳提供给`set`保证在全局范围内每次插入都会严格增加，这为我们提供了可以利用的重要排序属性。 

该问题保证：

 - 键和值是短字符串。 
- 时间戳是正整数。 
- 时间戳通过插入`set`严格增加。 

最终的保证是关键的见解，因为它意味着键的值自然地以排序的时间戳顺序存储，而不需要显式排序。 

一些边缘情况很重要：

 - 查询从未插入的密钥应该返回`""`。 
- 在键的第一个时间戳之前查询应该返回`""`。 
- 精确地在存储的时间戳处查询应该返回精确匹配的值。 
- 两个时间戳之间的查询应返回最接近的较早时间戳。 
- 同一键的多个值必须保留历史顺序。 

## 方法

 ### 蛮力方法

 最直接的解决办法就是存储每一个`(timestamp, value)`列表中每个键的配对。 期间`get`操作时，我们扫描整个列表以查找该键并找到小于或等于请求时间戳的最大时间戳。 

这种方法是正确的，因为我们明确检查每个存储的时间戳并选择最佳的有效候选者。 然而，当同一个键存在多个值时，它会变得低效。 

假设一把钥匙有`n`存储的时间戳。 单个`get`操作需要扫描所有`n`条目。 由于该问题最多允许`2 * 10^5`操作中，重复的线性扫描在最坏的情况下可能会退化为二次行为。 

### 最佳方法

 关键的观察结果是时间戳是严格按递增顺序插入的。 这意味着对于每个键，当我们附加新条目时，时间戳已经自然排序。 

每当对数据进行排序并且我们需要找到小于或等于目标的最大值时，二分查找就成为理想的工具。 

我们为每个键存储一个列表`(timestamp, value)`按时间顺序配对。 期间`get`，我们不是线性扫描，而是二分查找小于或等于请求时间戳的最右边时间戳。 

这极大地减少了查找时间，从线性时间缩短到对数时间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 |`set: O(1), get: O(n)`|`O(n)`| 线性扫描某个键的所有时间戳 |
 | 最佳 |`set: O(1), get: O(log n)`|`O(n)`| 对排序时间戳使用二分搜索 |

 ## 算法演练

 1. 初始化一个哈希映射，其中每个键映射到一个列表`(timestamp, value)`对。 

哈希映射提供对任何键的历史记录的恒定时间访问。 每个列表都存储该键的时间历史记录。 
2. 期间`set(key, value, timestamp)`, 附加`(timestamp, value)`到密钥列表。 

由于时间戳保证严格递增，因此追加会自动保持列表排序。 不需要额外的排序。 
3.期间`get(key, timestamp)`，首先检查key是否存在。 

如果key不存在则返回`""`立即，因为没有可用的历史值。 
4. 检索键的时间戳-值对列表。 

由于时间戳是排序的，因此我们可以有效地执行二分搜索。 
5. 使用二分查找查找小于或等于请求时间戳的最右边时间戳。 

目标不仅仅是找到完全匹配。 我们需要最新的有效历史值。 二分搜索帮助我们有效地缩小搜索空间。 
6. 如果找到有效的时间戳，则返回其关联值。 

否则，返回`""`。 

### 为什么它有效

 正确性取决于一个不变量：对于每个键，时间戳都以严格递增的顺序存储。 由于这种排序，二分搜索可以安全地消除每一步剩余搜索空间的一半，同时保证最终找到最右边的有效时间戳。 

该算法始终返回与小于或等于请求时间戳的最大时间戳关联的值，与问题定义完全匹配。 

## Python 解决方案```python
from collections import defaultdict
from typing import List, Tuple

class TimeMap:

    def __init__(self):
        self.store: defaultdict[str, List[Tuple[int, str]]] = defaultdict(list)

    def set(self, key: str, value: str, timestamp: int) -> None:
        self.store[key].append((timestamp, value))

    def get(self, key: str, timestamp: int) -> str:
        if key not in self.store:
            return ""

        values = self.store[key]

        left = 0
        right = len(values) - 1

        answer = ""

        while left <= right:
            mid = (left + right) // 2

            current_timestamp, current_value = values[mid]

            if current_timestamp <= timestamp:
                answer = current_value
                left = mid + 1
            else:
                right = mid - 1

        return answer

# Your TimeMap object will be instantiated and called as such:
# obj = TimeMap()
# obj.set(key, value, timestamp)
# param_2 = obj.get(key, timestamp)
```实施首先创建一个`defaultdict`其中每个键映射到时间戳值对的列表。 这种结构允许对键的所有历史值进行有效分组。 

这`set`方法非常有效，因为时间戳按排序顺序到达。 我们只需将新的对添加到列表中即可。 

这`get`方法首先检查key是否存在。 如果不是，它立即返回一个空字符串。 

二分查找维护两个指针，`left`和`right`。 每当中点时间戳小于或等于请求的时间戳时，它就成为有效的候选答案。 然而，我们继续向右搜索，因为可能有更新的有效时间戳。 

如果中点时间戳太大，我们丢弃右半部分并继续向左搜索。 

在搜索结束时，`answer`contains the value associated with the largest valid timestamp.

 ## 解决方案```go
package main

type Pair struct {
	timestamp int
	value     string
}

type TimeMap struct {
	store map[string][]Pair
}

func Constructor() TimeMap {
	return TimeMap{
		store: make(map[string][]Pair),
	}
}

func (this *TimeMap) Set(key string, value string, timestamp int) {
	this.store[key] = append(this.store[key], Pair{
		timestamp: timestamp,
		value:     value,
	})
}

func (this *TimeMap) Get(key string, timestamp int) string {
	values, exists := this.store[key]

	if !exists {
		return ""
	}

	left := 0
	right := len(values) - 1

	answer := ""

	for left <= right {
		mid := (left + right) / 2

		current := values[mid]

		if current.timestamp <= timestamp {
			answer = current.value
			left = mid + 1
		} else {
			right = mid - 1
		}
	}

	return answer
}

/**
 * Your TimeMap object will be instantiated and called as such:
 * obj := Constructor();
 * obj.Set(key,value,timestamp);
 * param_2 := obj.Get(timestamp);
 */
```Go 实现遵循与 Python 版本相同的算法结构。 一个显着的区别是 Go 需要显式的`Pair`结构体将时间戳和值存储在一起。 

Go 映射在查找期间返回两个值，该值和一个指示键是否存在的布尔值。 这使我们能够区分丢失的键和空的切片。 

Go 中的切片天然地支持高效的追加操作，这使得它们非常适合存储按时间顺序排序的时间戳值对。

 ## 边缘情况

 当查询从未插入的键时，会出现一种重要的边缘情况。 幼稚的实现可能会尝试对空列表进行二分搜索或访问丢失的数据，从而导致运行时错误。 该实现通过在搜索之前检查哈希映射中是否存在该键来避免这种情况。 

另一个关键的边缘情况是查询早于第一个存储的时间戳的时间戳。 例如，如果某个键的最早值存储在时间戳处`5`，然后查询时间戳`2`应该返回一个空字符串。 二分搜索自然会处理这个问题，因为没有找到小于或等于目标的有效时间戳，因此答案变量保持为空。 

第三种微妙的边缘情况涉及两个存储的时间戳之间的查询。 假设值存在于时间戳处`1`和`10`，我们查询时间戳`7`。 该算法必须返回时间戳的值`1`，不会因为没有完全匹配而失败。 这就是为什么二分搜索搜索小于或等于目标的最右边时间戳，而不是仅检查相等性。 

错误的另一个潜在来源是维护排序顺序。 如果底层数据未排序，许多二分搜索解决方案都会失败。 这个问题保证严格增加时间戳`set`操作，允许仅追加插入，同时自动保留排序顺序。
