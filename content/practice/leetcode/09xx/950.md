[LeetCode 950 题](https://leetcode.com/problems/reveal-cards-in-increasing-order/)

 **难度：** 🟡 中等
 **主题：** 数组、队列、排序、模拟

 ## 解决方案

 ## 问题理解

 这个问题给了我们一副独特的整数牌，并要求我们排列这副牌，以便一个非常具体的揭示过程以递增的顺序产生牌。 

揭示过程的工作原理如下：

 1. 翻开最上面的牌并将其从牌堆中取出。 
2. 将下一张最上面的牌移动到牌堆的底部。 
3. 重复，直到没有剩余卡片为止。 

重要的细节是，我们可以在流程开始之前重新排序牌组。 我们的任务是找到一个初始排序，使得显示的序列按升序排序。 

例如，假设显示的顺序必须变为：```
2, 3, 5, 7, 11, 13, 17
```我们需要确定哪种初始排列会导致揭示模拟准确地输出该序列。 

输入是一个整数数组`deck`，其中每个值都是唯一的。 输出是另一个包含相同值的数组，但经过排列，以便显示过程产生递增的顺序。 

限制相对较小：

 -`1 <= deck.length <= 1000`- 所有卡的面值都是唯一的
 - 卡面值可高达`10^6`因为输入大小只有 1000，所以我们不需要极其高级的优化。 一个`O(n log n)`解决方案绰绰有余。 

一些边缘情况很重要：

 - 一副牌只包含一张牌。 答案很简单，就是原卡。 
- 一副包含两张牌的牌。 揭示过程变得微不足道。 
- 已经排序的输入。 正确的输出通常与排序后的数组不同。 
- 大卡价值。 由于只有顺序很重要，因此大小不会影响算法。 
- 甲板尺寸小。 队列操作必须正确处理删除后的空状态。 

该问题保证所有值都是唯一的，这简化了逻辑，因为我们永远不需要处理关系。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试每一种可能的牌组顺序，并模拟每种排列的揭示过程。 

对于每个排列：

 1. 模拟显示操作。 
2. 记录显示的序列。 
3. 检查显示的序列是否按升序排序。 

这种方法是正确的，因为它详尽地检查了所有可能的甲板布置。 最终，它会找到有效的排序。 

然而，这种方法在计算上是不可行的。 甲板尺寸`n`有`n!`排列。 即使对于相对较小的值，例如`n = 10`，排列的数量变得巨大。 

模拟本身的成本`O(n)`时间，因此总复杂度约为`O(n! * n)`，这太慢了。 

### 最佳方法

 关键的见解是逆转揭示过程而不是猜测安排。 

假设我们已经知道必须展示牌的顺序：```
sorted(deck)
```我们不是向前模拟，而是向后重建原始牌组。 

前向过程是：

 1. 展示顶牌。 
2. 将下一张顶牌移至底端。 

相反的过程就变成：

 1. 取出最后一张翻开的牌并将其放在前面。 
2. 在插入下一个值之前，将底部卡片移至顶部以反转旋转。 

更简单、更直观的版本使用索引队列。 

我们模拟翻牌的位置：

 1. 对牌组进行排序。 
2. 维护一个包含索引的队列`0...n-1`。 
3. 将最小的卡片放入第一个显示的索引中。 
4. 将下一个索引移至队列末尾以模拟轮换步骤。 
5. 继续，直到所有卡片都放置完毕。 

这直接对显示过程进行建模并有效地产生正确的初始排列。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n! * n) | O(n! * n) | O(n) | 尝试所有可能的套牌顺序 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 使用排序和队列模拟 |

 ## 算法演练

 1. 按升序对牌组进行排序。 

翻牌过程必须按升序产生纸牌，因此第一张翻牌的牌应该是最小值，第二张翻牌的牌应该是第二小的值，依此类推。 
2. 创建一个包含所有牌组索引的队列。 

如果甲板有长度`n`，初始化队列：```
[0, 1, 2, ..., n-1]
```这些索引表示最终答案数组中的位置。 
3. 创建一个大小为答案的数组`n`。 

该数组最终将存储初始牌组顺序。 
4. 从最小到最大处理卡片。 

对于已排序的牌组中的每张牌：

 - 从队列中删除前面的索引。 
- 将当前卡片放入答案数组中的该位置。 

这是有效的，因为队列的前面代表将要显示的下一个位置。 
5. 模拟旋转步骤。 

放置卡片后：

 - 如果队列不为空：

 - 删除下一个前面的索引。 
- 将其推到队列后面。 

这反映了将下一张顶牌移动到牌堆底部的操作。 
6. 继续，直到放置完所有卡片。 

一旦所有排序的牌都被分配到揭示位置，答案数组就代表所需的初始牌组顺序。 

### 为什么它有效

 队列始终保持模拟过程中显示位置的顺序。 通过将排序后的卡片分配给按升序显示的位置，我们保证显示过程按升序输出卡片。 索引的旋转完全反映了原始问题陈述中卡片的移动，因此构造的排列是正确的。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def deckRevealedIncreasing(self, deck: List[int]) -> List[int]:
        n = len(deck)

        sorted_deck = sorted(deck)

        index_queue = deque(range(n))

        result = [0] * n

        for card in sorted_deck:
            reveal_index = index_queue.popleft()
            result[reveal_index] = card

            if index_queue:
                index_queue.append(index_queue.popleft())

        return result
```实现首先对输入卡片进行排序，因为我们知道显示顺序必须递增。 

双端队列用于有效地模拟队列行为。 队列存储索引而不是卡值。 这是一个重要的设计选择，因为我们正在确定每张排序的卡片应放置在最终排列中的位置。 

这`result`数组存储重建的牌组顺序。 

对于已排序的牌组中的每张牌：

 - 该算法从队列中删除前面的索引。 
- 该索引代表下一个显示的位置。 
- 当前剩余的最小的卡放在那里。 

放置后，下一个索引被移动到队列的后面，以模拟问题中描述的卡旋转操作。 

该过程一直持续到所有卡都被分配为止。 

因为双端队列操作是`O(1)`，模拟是有效的。 

## 解决方案```go
package main

import "sort"

func deckRevealedIncreasing(deck []int) []int {
	n := len(deck)

	sort.Ints(deck)

	queue := make([]int, n)
	for i := 0; i < n; i++ {
		queue[i] = i
	}

	result := make([]int, n)

	for _, card := range deck {
		revealIndex := queue[0]
		queue = queue[1:]

		result[revealIndex] = card

		if len(queue) > 0 {
			moved := queue[0]
			queue = queue[1:]
			queue = append(queue, moved)
		}
	}

	return result
}
```Go 解决方案遵循与 Python 版本相同的逻辑。 

一个区别是Go在标准库中没有提供内置的双端队列结构，因此队列是使用切片来模拟的。 

移除前面的元件是通过以下方式完成的：```go
queue = queue[1:]
```附加到后面使用：```go
queue = append(queue, moved)
```由于问题规模很小，因此这种实现对于约束来说是完全有效的。 

不存在整数溢出问题，因为值仅被重新排列，而不是经过数学操作。

 ## 边缘情况

 ### 单卡牌

 如果这副牌只包含一张牌，则揭牌过程会立即揭开该牌并停止。 这种情况可能会暴露队列轮换逻辑中的错误，因为没有第二张卡可以移动到底部。 

该实现自然地处理了这个问题，因为在放置唯一的卡之后，队列变空并且跳过轮换步骤。 

### 两张牌

 有了两张牌，揭牌过程就变得非常短：

 1. 翻开第一张牌。 
2. 翻开第二张牌。 

有缺陷的实现可能会在队列变空后错误地旋转索引。 

该解决方案明确检查：```
if queue:
```在执行旋转步骤之前，防止无效操作。 

### 已排序的输入

 一个重要的微妙之处是答案通常不是排序后的牌组本身。 

例如：```
[1,2,3,4]
```如果直接使用，则不会按升序显示。 

幼稚的实现可能会错误地认为单独排序就足够了。 队列模拟正确计算实际所需的排列。 

### 非常大的卡值

 卡面值可能大到`10^6`，但只有相对顺序才重要。 该算法从不对卡片值执行算术运算，仅在排序过程中进行比较。 

因此，大整数不会引入溢出或精度问题。 

### 奇数与偶数牌组尺寸

 根据剩余牌的数量是奇数还是偶数，揭示和旋转过程的行为略有不同。 

在这些情况下，不正确的队列操作很容易产生一个错误。 由于该算法直接一步步模拟翻牌位置，因此奇数和偶数牌组尺寸都能得到统一且正确的处理。
