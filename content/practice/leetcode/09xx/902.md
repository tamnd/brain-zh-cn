 ## 解决方案

 ## 问题理解

 该问题为我们提供了一组允许的数字（存储为字符串）和一个整数`n`。 我们可以通过重复使用给定集合中的数字来构造任何正整数。 每个数字可以重复使用任意次。 

目标是计算可以形成多少个正整数，使得结果整数小于或等于`n`。 

例如，如果数字集是`["1","3","5"]`，然后像这样的数字`1`,`13`,`551`， 和`1351315`有效，因为使用的每个数字都属于允许的集合。 

一个关键细节是生成的数字必须小于或等于`n`。 这将问题从简单的组合问题转变为逐位比较问题。 

限制相对较小：

 - 最多 9 个不同的数字
 -`n <= 10^9`， 所以`n`最多 10 位数字
 - 数字是唯一的且已排序
 - 数字范围仅从`'1'`到`'9'`，意味着没有`'0'`缺席`'0'`简化了问题，因为我们永远不需要担心前导零。 

关键的挑战是在不显式生成每个可能的数字的情况下高效计数。 

一些边缘情况很重要：

 - 当数字组仅包含一位数字时
 - 当`n`本身无法形成
 - 当所有有效数字的位数少于`n`- 当某些前缀`n`与构造的数字匹配，但后面的数字失败
 - 当`n`非常大，不可能产生暴力破解

 例如：

 -`digits = ["7"]`,`n = 8`只生产`7`-`digits = ["1","2"]`,`n = 100`允许所有 1 位数和 2 位数组合，但不允许使用有效的 3 位数
 -`digits = ["1","4","9"]`,`n = 999999999`允许所有可能的 9 位数字组合

 了解如何按长度对数字进行计数，然后仔细比较等长数字的数字是解决方案的核心。 

## 方法

 ### 蛮力方法

 暴力解决方案将使用允许的数字生成每个可能的数字，并计算有多少个数字小于或等于`n`。 

一种方法是使用 DFS 或 BFS：

 - 以每个数字作为数字开始
 - 重复附加每个可能的数字
 - 数量超过时停止`n`这种方法是正确的，因为它明确地探索了每个有效的可构造数字。 

然而，随着组合数量呈指数级增长，它会变得太慢。 

假设有 9 位可用数字，`n`有 10 位数字。 可能的候选人数量变为：$$9^1 + 9^2 + \dots + 9^{10}$$这太大了，无法直接枚举。 

### 最优方法，数字动态计数

 关键的见解是我们不需要显式地生成数字。 

相反，我们计算可能有多少个数字。 

问题自然分为两类：

 1. 位数少于的数字`n`2. 与 位数相同的数字`n`对于位数较少的数字，计数很简单：

 - 如果数字集大小为`k`- 然后一段长度`L`， 有`k^L`有效数字

 对于长度相同的数字`n`，我们逐位处理：

 - 在每个位置，计算有多少个允许的数字小于当前数字`n`- 每个较小的选择都允许所有剩余位置自由变化
 - 如果当前数字本身不可用，我们立即停止
 - 否则，继续下一个数字

 这本质上是一种数字 DP 式计数方法。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(k^d) | O(k^d) | O(k^d) | O(k^d) | 显式生成所有有效数字 |
 | 最佳 | O(d × k) | O(1) | O(1) | 以数学方式计算组合 |

 在哪里：

-`k`= 允许的位数
 -`d`= 中的位数`n`## 算法演练

 ### 第 1 步：转换`n`成一个字符串

 我们转换`n`到一个字符串，这样我们就可以逐位处理它。 

例如：```
n = 357
n_str = "357"
```这允许对每个数字进行索引访问。 

### 步骤 2：计算所有位数较少的数字

 假设：

 -`k = len(digits)`-`m = len(n_str)`每个长度小于的数字`m`自动小于`n`。 

对于每个长度`L`从`1`到`m - 1`:$$k^L$$数字是可能的。 

如果`digits = ["1","3","5","7"]`，那么：

 - 1 位数字：$4^1 = 4$- 2 位数字：$4^2 = 16$全部的：$$4 + 16 = 20$$### 第三步：处理相同长度的数字

 现在我们计算与以下位数完全相同的数字`n`。 

我们从左到右检查每个数字的位置。 

在位置`i`：

- 让`current_digit = n_str[i]`我们计算有多少个允许的数字严格小于`current_digit`。 

每个较小的选择都会固定当前位置，而其余位置可以是任何位置。 

如果有`smaller_count`有效的较小数字和`remaining`剩余职位：$$smaller\_count \times k^{remaining}$$添加有效数字。 

### 第四步：检查当前数字是否存在

 如果`current_digit`不存在于`digits`，那么不可能有更多的等前缀数。 

此时，我们返回累积的答案。 

### 步骤 5：如果数字存在则继续

 如果当前数字存在于数字集中，我们继续到下一个位置。 

这保留了与`n`迄今为止。 

### 第 6 步：包含`n`如果完全匹配则自身

 如果每个数字`n`存在于数字集合中，则`n`本身是可构造的。 

我们将结果加 1。 

### 为什么它有效

 该算法之所以有效，是因为每个有效数字都属于一个类别：

 - 长度比`n`- 长度相同`n`对于较短的长度，每种组合都有效。 

对于相同的长度，逐位比较可确保我们精确计算小于或等于的数字`n`。 

在每个位置：

 - 较小的数字创建完全有效的后缀组合
 - 相同的数字保留了匹配的可能性`n`- 较大的数字无效

 这保证了每个有效数字都被精确计算一次。 

## Python 解决方案```python
from typing import List

class Solution:
    def atMostNGivenDigitSet(self, digits: List[str], n: int) -> int:
        n_str = str(n)
        digit_count = len(digits)
        length = len(n_str)

        result = 0

        # Count numbers with fewer digits
        for current_length in range(1, length):
            result += digit_count ** current_length

        # Count numbers with same length
        for index, current_digit in enumerate(n_str):
            smaller_digits = 0

            for digit in digits:
                if digit < current_digit:
                    smaller_digits += 1
                else:
                    break

            remaining_positions = length - index - 1
            result += smaller_digits * (digit_count ** remaining_positions)

            # If current digit does not exist, stop
            if current_digit not in digits:
                return result

        # n itself is valid
        return result + 1
```实现从转换开始`n`到一个字符串中，这样我们就可以单独比较数字。 

第一个循环计算所有有效数字的位数少于`n`。 由于每个位置都可以独立选择任何允许的数字，因此长度计数`L`是：$$k^L$$第二个循环处理与以下长度相同的数字`n`。 

对于每个位置：

 - 我们计算有多少个允许的数字更小
 - 那些较小的选择会产生整个有效的后缀范围
 - 我们立即添加这些计数

 然后我们检查当前数字本身是否存在。 

如果不存在，则不可能进行等前缀延续，因此我们返回累积的答案。 

如果每个数字都匹配成功，那么`n`本身有效，所以我们在末尾加1。 

## 解决方案```go
func atMostNGivenDigitSet(digits []string, n int) int {
	nStr := strconv.Itoa(n)

	digitCount := len(digits)
	length := len(nStr)

	result := 0

	// Count numbers with fewer digits
	for currentLength := 1; currentLength < length; currentLength++ {
		result += intPow(digitCount, currentLength)
	}

	// Count numbers with same length
	for index := 0; index < length; index++ {
		currentDigit := string(nStr[index])

		smallerDigits := 0

		for _, digit := range digits {
			if digit < currentDigit {
				smallerDigits++
			} else {
				break
			}
		}

		remainingPositions := length - index - 1
		result += smallerDigits * intPow(digitCount, remainingPositions)

		found := false

		for _, digit := range digits {
			if digit == currentDigit {
				found = true
				break
			}
		}

		if !found {
			return result
		}
	}

	return result + 1
}

func intPow(base int, exponent int) int {
	result := 1

	for exponent > 0 {
		result *= base
		exponent--
	}

	return result
}
```Go 实现遵循与 Python 解决方案完全相同的逻辑。 

一个区别是 Go 没有提供内置的整数求幂函数，因此我们实现`intPow`。 

另一个区别是字符串处理。 由于 Go 字符串是字节切片，因此访问字符需要转换：```go
string(nStr[index])
```约束足够小，整数溢出不是问题。

 ## 边缘情况

 ### 边缘情况 1：没有有效数字

 考虑：```
digits = ["9"]
n = 8
```幼稚的实现可能会错误地计数`9`因为它存在于数字集中。 

然而，`9 > 8`，所以答案一定是`0`。 

该算法可以正确处理这个问题，因为：

 - 不存在更短的长度
 - 在第一个数字比较时，没有小于的数字`8`-`8`不存在
 - 算法立即返回`0`### 边缘情况 2：`n`本身是可构造的

 考虑：```
digits = ["1","2","3"]
n = 123
```该算法必须包括`123`本身。 

一个常见的错误是忘记添加最后的`+1`成功匹配每个数字后。 

仅当所有数字都正确时，此实现才正确加 1`n`存在于数字集中。 

### 边缘情况 3：早期前缀失败

 考虑：```
digits = ["1","3","5"]
n = 342
```第一个数字：

 - 较小的有效数字是`1`- 所以所有以以下开头的数字`1`被计算在内

 数字`3`存在，所以我们继续。 

在第二位数字处：

 - 当前数字是`4`- 较小的有效数字是`1`和`3`这些组合都被计算在内。 

自从`4`如果数字集中不存在，则算法立即终止。 

这可以防止过度计算无效数字，否则会超出`n`。
