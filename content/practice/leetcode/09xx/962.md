[LeetCode 962 题](https://leetcode.com/problems/maximum-width-ramp/)

 **难度：** 🟡 中等
 **主题：** 数组、两个指针、堆栈、单调堆栈

 ## 解决方案

 ## 问题理解

 该问题要求我们在整数数组中找到最大宽度斜坡。 斜坡被定义为一对索引`(i, j)`这样：

 -`i < j`-`nums[i] <= nums[j]`斜坡的宽度就是两个索引之间的距离：$$\text{width} = j - i$$我们的目标是计算数组中所有有效斜坡的最大可能宽度。 

输入是一个整数数组`nums`，输出是表示最大宽度斜坡的单个整数。 如果不存在有效的斜坡，我们返回`0`。 

约束条件很重要：

 -`2 <= nums.length <= 5 * 10^4`-`0 <= nums[i] <= 5 * 10^4`多达 50,000 个元素的数组大小立即告诉我们二次解可能会太慢。 一个`O(n^2)`在最坏的情况下，该算法需要进行多达 25 亿次比较，这在标准 LeetCode 时间限制内是不可行的。 这强烈表明我们需要一个`O(n log n)`或者`O(n)`解决方案。 

一些边缘情况值得尽早识别：

 - 严格递减数组，例如`[5,4,3,2,1]`，除了微不足道的无效情况外不包含任何有效的斜坡，所以答案是`0`。 
- 严格递增数组，例如`[1,2,3,4,5]`，产生最大可能的宽度，即`n - 1`。 
- 具有重复值的数组很重要，因为允许相等，这意味着`nums[i] <= nums[j]`包括相等的值。 
- 长度非常小的数组`2`仍应表现正确。 
- 相同数字的大平台可能会产生宽阔的斜坡，如果幼稚的实现仅搜索严格增加的值，则它们可能会错过。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每一个可能的对`(i, j)`在哪里`i < j`。 

对于每个索引`i`，我们迭代后面的每个索引`j`。 如果`nums[i] <= nums[j]`，我们计算宽度`j - i`并更新最大答案。 

这是有效的，因为它明确地检查每一个可能的斜坡，因此不会错过最佳的斜坡。 

但时间复杂度极差。 大约有：$$\frac{n(n-1)}{2}$$对进行检查，这给出了`O(n^2)`时间复杂度。 

和`n = 50,000`，这种方法变得太慢了。 

### 最优单调堆栈方法

 关键的见解是，并非每个索引都可用作左端点。 

假设我们有两个索引：

 -`i1 < i2`-`nums[i1] <= nums[i2]`然后`i2`永远不会比`i1`作为坡道的左侧，因为：

 -`i1`更左边
 -`i1`具有相同或更小的值

 任何有效的斜坡使用`i2`可以使用产生相同或更大的宽度`i1`。 

这意味着我们只关心从左到右扫描时形成新最小值的索引。 

我们可以将这些候选索引存储在单调递减堆栈中。 堆栈包含的索引的值随着我们在数组中移动而严格减小。 

然后我们从右向左扫描。 对于每个位置`j`，我们尝试将其与堆栈中最早的有效左端点进行匹配。 

每当：$$nums[\text{stack[-1]}] \le nums[j]$$我们找到了一个有效的斜坡，并且因为我们从右向左扫描，所以这为左侧索引提供了最宽的可能斜坡。 

这会产生一个`O(n)`解决方案，因为每个索引最多被推送和弹出一次。

 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 检查每对索引 |
 | 最佳 | O(n) | O(n) | 使用单调递减堆栈 |
