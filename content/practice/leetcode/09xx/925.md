[LeetCode 925 题](https://leetcode.com/problems/long-pressed-name/)

 **难度：** 🟢简单
 **主题：** 两个指针，字符串

 ## 解决方案

 ## 问题理解

 在这个问题中，我们给出两个字符串，`name`和`typed`。 

字符串`name`代表您的朋友想要输入的预期字符序列。 字符串`typed`代表出现在屏幕上的实际字符。 

复杂的是，某些键可能被长按了。 长按意味着当一个字符被输入一次`name`，它可能连续出现多次`typed`。 

例如：

-`name = "alex"`-`typed = "aaleex"`这是有效的，因为：

 -`'a'`被长期压制，变成`"aa"`-`'e'`被长期压制，变成`"ee"`字符的相对顺序必须保持不变。 长按仅允许重复当前字符，而不能插入新的不相关字符或跳过所需字符。 

目标是确定是否`typed`实际上可以由`name`使用零次或多次长按。 

限制很小：

 -`1 <= name.length, typed.length <= 1000`- 两个字符串仅包含小写英文字母。 

由于字符串很短，即使效率较低的方法也可以在一定范围内发挥作用。 然而，问题本质上是关于顺序匹配，这自然建议采用线性扫描解决方案。 

一些边缘情况很重要：

 -`typed`可能包含额外的重复字符，长按有效。 
-`typed`可能会跳过出现在`name`。 
-`typed`可能会引入完全不同的角色。 
-`typed`可能会以最终字符的重复副本结束。 
-`typed`可能短于`name`，它自动无效，因为其中的每个字符`name`必须至少出现一次。 

例如：

-`name = "alex"`-`typed = "ale"`这是无效的，因为`'x'`永远不会出现。 

另一个例子：

 -`name = "saeed"`-`typed = "ssaaedd"`这是无效的，因为第二个`'e'`从`name`失踪了。 

## 方法

 ### 蛮力方法

 蛮力策略将尝试模拟所有可能的长按组合。 

对于中的每个字符`name`，我们可以认为它可能出现一次或多次`typed`。 我们可以递归地尝试每个有效的分组，看看某些排列是否能够准确地重建`typed`。 

例如，如果`name = "alex"`和`typed = "aaleex"`，暴力法可以尝试：

 -`'a' -> "a"`或者`"aa"`-`'l' -> "l"`-`'e' -> "e"`或者`"ee"`-`'x' -> "x"`最终，一个有效的分解将匹配整个`typed`细绳。 

这种方法是正确的，因为它探索了长按可能发生的所有可能方式。 然而，它的效率很低，因为当存在许多重复字符时，可能性的数量呈指数增长。 

尽管约束足够小，可以通过一些低效的解决方案，但这种方法不必要地复杂。 

### 最佳两指针方法

 关键的观察是两个字符串必须按顺序处理。 

中的每个角色`typed`必须满足两个条件之一：

 1. 匹配当前字符`name`，这意味着我们将两个指针都向前推进。 
2.它匹配前一个字符`typed`，这意味着长按最后一个有效字符。 

如果两个条件都不成立，则字符串不兼容。 

这自然会导致两个指针的解决方案：

 - 一根指针遍历`name`- 一根指针遍历`typed`我们贪婪地从左到右匹配字符。 

这是有效的，因为长按只会重复现有的字符。 他们从不重新排列角色或引入新的过渡。

 | ---| ---| ---| ---|

 ## 算法演练

 1.初始化两个指针：

 -`i`为了`name`-`j`为了`typed`两者都从索引开始`0`。 
2. 遍历`typed`字符串同时`j < len(typed)`。 
3. 在每一步中，首先检查是否：

 -`i < len(name)`-`name[i] == typed[j]`如果为 true，则该字符正常匹配。 将两个指针向前移动。 
4. 否则，检查当前字符是否在`typed`等于中的前一个字符`typed`。 

这意味着：

-`j > 0`-`typed[j] == typed[j - 1]`如果为真，则当前字符只是长按重复。 只移动`j`。 
5. 如果两个条件都不成立，则返回`False`。 

这意味着当前字符`typed`不能用以下任一方式解释：

 - 匹配下一个字符`name`- 重复之前输入的字符
 6.遍历完成后`typed`，验证中的所有字符`name`已匹配。 

返回：

-`True`如果`i == len(name)`-`False`否则

 ### 为什么它有效

 该算法保持了之前所有字符的不变性`i`在`name`之前已与所有已处理的字符正确匹配`j`在`typed`。 

每当字符直接匹配时，两个指针都会前进。 

每当出现重复字符时`typed`，仅当它重复前一个有效字符时才有效，这与长按的定义完全一致。 

如果一个字符不能满足任一规则，则没有合法的方式来解释它，因此答案必须是`False`。 

由于该算法按顺序处理字符并且从不跳过不匹配的所需字符，因此它可以正确验证是否`typed`可能是长按造成的。 

## Python 解决方案```python
class Solution:
    def isLongPressedName(self, name: str, typed: str) -> bool:
        i = 0
        j = 0

        while j < len(typed):
            if i < len(name) and name[i] == typed[j]:
                i += 1
                j += 1
            elif j > 0 and typed[j] == typed[j - 1]:
                j += 1
            else:
                return False

        return i == len(name)
```实现直接遵循两指针策略。 

指针`i`跟踪进度通过`name`， 尽管`j`跟踪进度通过`typed`。 

在循环内部，第一个条件检查当前字符是否正常匹配。 如果匹配，则两个指针都会前进，因为已成功匹配一个预期字符。 

第二个条件处理长按。 如果当前字符在`typed`等于先前键入的字符，那么这种额外的出现可以解释为重复按键。 在这种情况下，仅`j`进步。 

如果两个条件都不适用，则当前字符无效，因此该函数立即返回`False`。 

处理完所有字符后`typed`，最终检查确保每个字符`name`已匹配。 如果某些字符仍然不匹配，则键入序列不完整。 

## 解决方案```go
func isLongPressedName(name string, typed string) bool {
	i := 0
	j := 0

	for j < len(typed) {
		if i < len(name) && name[i] == typed[j] {
			i++
			j++
		} else if j > 0 && typed[j] == typed[j-1] {
			j++
		} else {
			return false
		}
	}

	return i == len(name)
}
```Go 实现与 Python 版本几乎相同。 

由于 Go 字符串是字节索引的，并且问题保证小写英文字母，因此直接索引`name[i]`和`typed[j]`是安全的。 

不需要额外的内存分配或辅助数据结构。 该实现使用恒定的额外空间并执行单个线性扫描。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`typed`末尾包含额外的重复字符。 例如：```
name = "abc"
typed = "abccccc"
```幼稚的实现可能会错误地拒绝这一点，因为`typed`长于`name`。 然而，重复的尾随字符是完全有效的长按。 该算法可以正确处理此问题，因为只要与先前键入的字符匹配，就允许重复的字符。 

另一个重要的边缘情况是当`typed`短于`name`。```
name = "abcd"
typed = "abc"
```这种情况是无效的，因为每个字符`name`必须至少出现一次`typed`。 该算法自然会检测到这一点，因为指针`i`永远不会到达终点`name`，导致最终条件`i == len(name)`失败。 

第三个重要的边缘情况涉及无效的字符转换。```
name = "abc"
typed = "aabbdcc"
```人物`'d'`在有效组之间意外出现。 它既不是下一个预期的角色`name`也不是重复先前键入的字符。 算法立即返回`False`当遇到这个无效转换时。 

另一个微妙的边缘情况是重复的字符已经存在于`name`。```
name = "aabb"
typed = "aaaabbbb"
```该算法仍然可以正常工作，因为匹配始终优先考虑前进`name`只要有可能。 只有多余的重复字符才会被视为长按。
