[LeetCode 984 题](https://leetcode.com/problems/string-without-aaa-or-bbb/)

 **难度：** 🟡 中等
 **主题：** 字符串、贪婪

 ## 解决方案

 ## 问题理解

 该问题给了我们两个整数，`a`和`b`，代表有多少个`'a'`字符和`'b'`我们必须将字符放入字符串中。 我们的任务是构造任意长度的有效字符串`a + b`这样：

 - 正是如此`a`字符是`'a'`- 确切地`b`字符是`'b'`- 子串`"aaa"`从未出现
 - 子串`"bbb"`从未出现

 输出不需要是唯一的。 任何有效的安排都是可以接受的。 

关键的难点在于平衡角色，确保没有角色连续出现3次。 一个幼稚的方法可能只是简单地附加所有`'a'`后面跟着所有字符`'b'`字符，但只要任一计数至少为 3，就会立即违反约束。 

例如：

 - 如果`a = 4`和`b = 1`, 字符串`"aaaab"`无效，因为它包含`"aaa"`。 
- 有效的排列会将字符分散开，例如`"aabaa"`。 

限制相对较小：

 -`0 <= a, b <= 100`由于输入量很小，因此即使效率较低的算法也可以工作。 然而，挑战更多的是如何正确构造字符串，而不是处理大的输入大小。 

问题陈述提供了一个重要的保证：

 > 保证存在这样的字符串。 

这意味着我们永远不需要处理不可能的情况。 我们可以完全专注于建立有效的安排。 

一些边缘情况很重要：

 - 一个字符数可能比另一个字符数多得多。 
- 一次计数可能为零。 
- 计数可能已经平衡。 
- 我们必须确保贪婪地添加字符不会意外地创建三个连续的相同字母。 

核心挑战是决定接下来放置哪个角色，同时在整个构建过程中保持有效性。 

## 方法

 ### 蛮力方法

 强力解决方案将生成所有可能长度的字符串`a + b`确切地包含`a` `'a'`字符和`b` `'b'`人物。 对于每个生成的字符串，我们将检查它是否包含`"aaa"`或者`"bbb"`。 

这种方法是正确的，因为它详尽地检查了每种可能的安排。 最终，它会找到一个有效的字符串，因为问题保证了它的存在。 

然而，这种方法效率极低。 可能的字符串数量为：$\binom{a+b}{a}$随着输入大小的增加，该值呈指数增长。 尽管约束很小，但生成所有组合是不必要的且效率低下。 

### 最优贪心法

 关键的见解是，我们应该始终尝试放置具有较大剩余计数的字符，但前提是这样做不会创建三个连续的相同字符。 

为什么这有效？ 

如果一个字符比另一个字符出现的频率更高，我们必须在整个字符串中小心地分配它。 延迟放置较频繁的角色可能会导致以后无法在不违反约束的情况下放置。 

因此，贪心策略变为：

 - 优先选择剩余数量较多的角色。 
- 追加之前，检查最后两个字符是否已经相同。 
- 如果附加首选字符会创建三个连续的相同字符，则附加另一个字符。 

因为问题保证存在有效的解决方案，所以该策略总是成功的。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(2^(a+b)) | O(2^(a+b)) | O(a+b) | 生成所有可能的有效排列 |
 | 最佳 | O(a+b) | O(a+b) | 贪婪地增量构建有效字符串 |

 ## 算法演练

 1. 初始化一个空的结果列表。 

我们使用列表而不是重复连接字符串，因为追加到列表在 Python 和 Go 中都是高效的。 
2. 继续构建字符串，同时`a`或者`b`仍然大于零。 

在每次迭代时，我们决定是否追加`'a'`或者`'b'`。 
3. 检查当前结果的最后两个字符。 

如果最后两个字符相同，则再次附加相同的字符将创建无效的子字符串。 

例如：

 - 当前结果：`"aa"`- 追加另一个`'a'`会创造`"aaa"`4. 如果最后两个字符相同：

 - 我们被迫添加相反的字符。 
- 这可以防止出现三个连续的相同字母。 
5. 否则，选择剩余数量较大的角色。 

这是算法的贪心部分。 

如果`a > b`, 附加`'a'`。 

否则，附加`'b'`。 

原因是，出现频率较高的字符以后很难放置，因此我们应该尽可能使用它。 
6. 追加后，减少相应的计数器。 

如果我们追加`'a'`, 递减`a`。 

如果我们追加`'b'`, 递减`b`。 
7. 重复此操作，直至两个计数器都归零。 
8. 将结果列表转换为字符串并返回。 

### 为什么它有效

 该算法保持了一个重要的不变量：

 > 构造的前缀在任何时候都不包含`"aaa"`或者`"bbb"`。 

每当两个连续的相同字符已经存在时，算法就被迫放置相反的字符。 否则，它会贪婪地放置更频繁的字符，以避免未来的不平衡问题。 

因为问题保证存在有效的解决方案，所以这种贪心策略总是可以成功完成而不会陷入困境。 

## Python 解决方案```python
class Solution:
    def strWithout3a3b(self, a: int, b: int) -> str:
        result = []

        while a > 0 or b > 0:
            n = len(result)

            # If the last two characters are the same,
            # we must place the opposite character.
            if n >= 2 and result[-1] == result[-2]:
                if result[-1] == 'a':
                    result.append('b')
                    b -= 1
                else:
                    result.append('a')
                    a -= 1
            else:
                # Otherwise, greedily place the character
                # with the larger remaining count.
                if a >= b and a > 0:
                    result.append('a')
                    a -= 1
                else:
                    result.append('b')
                    b -= 1

        return "".join(result)
```实现直接遵循贪心算法。 

这`result`list 在我们构建字符串时存储字符。 使用列表可以避免重复的字符串重新分配。 

在循环内，我们首先检查最后两个字符。 如果它们相同，我们就被迫放置相反的字符以避免创建三个连续的字母。 

如果最后两个字符不相同，我们会贪婪地追加剩余计数较大的字符。 这有助于尽早分配更频繁的字符。 

添加一个字符后，相应的计数器就会递减。 循环继续，直到所有字符都被使用。 

最后，`"".join(result)`将字符列表转换为最终字符串。 

## 解决方案```go
func strWithout3a3b(a int, b int) string {
	result := make([]byte, 0)

	for a > 0 || b > 0 {
		n := len(result)

		// If the last two characters are the same,
		// we must place the opposite character.
		if n >= 2 && result[n-1] == result[n-2] {
			if result[n-1] == 'a' {
				result = append(result, 'b')
				b--
			} else {
				result = append(result, 'a')
				a--
			}
		} else {
			// Otherwise, greedily place the character
			// with the larger remaining count.
			if a >= b && a > 0 {
				result = append(result, 'a')
				a--
			} else {
				result = append(result, 'b')
				b--
			}
		}
	}

	return string(result)
}
```Go 实现密切反映了 Python 逻辑。 

Go 使用的不是 Python 列表，而是`[]byte`用于高效字符附加的切片。 由于 Go 中的字符串是不可变的，因此使用字节切片构建结果比重复字符串连接更有效。 

最终转换自`[]byte`到`string`是使用完成的`string(result)`。 

由于约束非常小，因此不需要对整数溢出进行特殊处理。

 ## 边缘情况

 当一个字符数远大于另一个字符数时，就会出现一种重要的边缘情况，例如`a = 7`和`b = 2`。 幼稚的实现可能会重复附加`'a'`因为它的数量较多，最终产生`"aaa"`。 贪心解决方案通过在每次追加之前检查最后两个字符来避免这种情况。 一次两`'a'`字符连续出现，算法强制插入`'b'`。 

当一个计数为零时，会出现另一种重要的边缘情况。 例如，`a = 1`和`b = 0`。 该算法必须仍然正常工作，而不会尝试附加不存在的字符。 该实现自然地处理了这个问题，因为它仅在确认字符可用后才递减计数。 

当计数完全平衡时会出现第三种边缘情况，例如`a = 3`和`b = 3`。 在这种情况下，存在许多有效字符串。 该算法仍然表现正确，因为当计数相等时，它始终首先选择一个字符，同时继续强制执行非三连续规则。 

最后，空输入案例`a = 0`和`b = 0`值得关注。 该算法立即退出循环并返回一个空字符串，该空字符串是有效的，因为满足所有约束。
