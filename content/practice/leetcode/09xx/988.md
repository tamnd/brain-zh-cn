[LeetCode 第 988 题](https://leetcode.com/problems/smallest-string-starting-from-leaf/)

 **难度：** 🟡 中等
 **主题：** 字符串、回溯、树、深度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个二叉树的根，其中每个节点都存储一个整数`0`和`25`。 每个整数对应一个小写英文字母：

 -`0 -> 'a'`-`1 -> 'b'`- ...
 -`25 -> 'z'`我们需要构造从叶节点开始并向上移动到根的字符串。 在所有此类从叶到根的字符串中，我们必须返回字典顺序最小的字符串。 

一个关键细节是弦的方向。 虽然遍历自然是从根向下移动，但所需的字符串是从叶到根形成的。 例如，如果从根到叶的路径是：```
a -> b -> d
```那么结果字符串是：```
"dba"
```不是`"abd"`。 

词典比较的工作原理与词典排序完全相同。 第一个不同的字符确定哪个字符串较小。 如果一个字符串是另一个字符串的前缀，则较短的字符串被认为较小。 

该树最多可以包含`8500`节点，它足够大，我们应该避免不必要的重复字符串构造或存储每个可能的路径（如果可以的话）。 然而，对于深度优先遍历来说，这个大小仍然是可以管理的，因为树的高度受到节点数量的限制。 

一些边缘情况很重要：

 - 一棵只有一个节点的树。 在这种情况下，根也是叶子，所以答案是单个字符。 
- 多个叶路径生成具有公共前缀的字符串。 词典比较必须仍然正确。 
- 深树，重复的字符串连接可能会变得昂贵。 
- 字典顺序最小答案不是最短路径的树。 
- 包含许多重复值的树，这可以使比较变得微妙。 

该问题保证每个节点值都是有效的并且至少存在一个节点。 

## 方法

 ### 蛮力方法

 最直接的解决方案是生成每个从叶到根的字符串，然后返回字典顺序最小的字符串。 

我们可以从根执行深度优先遍历，同时保持当前的根到节点路径。 每当我们到达叶子时，我们都会反转收集到的字符以生成所需的叶子到根字符串。 然后我们将该字符串存储在列表中。 遍历整棵树后，我们对列表进行排序或反复比较字符串以找到最小的一个。 

这种方法是正确的，因为它显式枚举了每个有效的候选字符串。 由于答案必须是这些字符串之一，因此比较所有字符串可以保证我们找到正确的结果。 

缺点是我们可能会同时存储许多完整的字符串。 在最坏的情况下，树可能有很多叶子，并且每个生成的字符串可能很长。 重复的反转和字符串创建也会增加开销。 

### 最佳方法

 关键的观察是我们实际上不需要存储所有候选字符串。 我们只需要目前为止见过的最小的一个。 

我们仍然可以执行 DFS 遍历，但我们不收集所有结果，而是维护全局最佳字符串。 在每片叶子上：

 1. 构造当前的叶到根字符串。 
2. 直接将其与迄今为止看到的最佳答案进行比较。 
3. 如果新字符串较小，请替换答案。 

这减少了内存使用，因为我们只保留当前的遍历路径和当前的最佳答案。 

DFS 遍历自然而然地只探索每一条从根到叶的路径一次，这使其成为解决此问题的理想选择。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(N × H) | O(N × H) | 在比较之前存储每个叶字符串 |
 | 最佳 | O(N × H) | O(H) | 具有即时词典比较功能的 DFS |

 这里：

-`N`是节点数
 -`H`是树的高度

 ## 算法演练

 ### 最优DFS算法

 1. 从根节点开始深度优先遍历。 

我们使用 DFS 是因为该问题需要检查每条从根到叶的路径。 DFS自然会维护当前的遍历路径。 
2. 在遍历过程中保持可变的路径结构。 

当我们访问每个节点时，我们使用以下方法将其数值转换为字符：```
chr(node.val + ord('a'))
```我们将此字符附加到当前路径。 
3. 继续递归到左子节点和右子节点。 

该路径现在表示从根到当前节点的字符序列。 
4. 当到达叶节点时，构造候选字符串。 

由于所需的方向是从叶到根，因此我们反转当前路径并将其连接成一个字符串。 

例如：```
path = ['a', 'b', 'd']
```变成：```
"dba"
```5. 将候选字符串与当前最佳答案进行比较。 

如果：

 - 尚未记录任何答复，或者
 - 新字符串按字典顺序更小，

 然后更新答案。 
6.处理完节点后回溯。 

在返回父调用之前从路径中删除当前字符。 这确保路径始终准确地反映活动的递归分支。 
7. DFS完成后，返回存储的最小字符串。 

### 为什么它有效

 DFS 遍历只访问每条从根到叶的路径一次。 每个有效答案都对应一条这样的路径，因此不会遗漏任何候选字符串。 在每个叶子上，我们生成问题所需的精确的从叶到根的字符串。 因为我们不断维护迄今为止遇到的字典顺序最小的候选者，所以最终存储的字符串必须是所有可能的叶到根字符串中最小的。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional

class Solution:
    def smallestFromLeaf(self, root: Optional[TreeNode]) -> str:
        smallest = None
        path = []

        def dfs(node: Optional[TreeNode]) -> None:
            nonlocal smallest

            if not node:
                return

            path.append(chr(node.val + ord('a')))

            if not node.left and not node.right:
                candidate = ''.join(reversed(path))

                if smallest is None or candidate < smallest:
                    smallest = candidate

            dfs(node.left)
            dfs(node.right)

            path.pop()

        dfs(root)
        return smallest
```该实现使用递归 DFS 遍历。 这`path`list 存储从根节点到当前节点的字符。 使用列表很重要，因为递归内重复的字符串连接效率很低。 

每当我们访问一个节点时，我们都会将其字符表示附加到路径中。 如果节点是叶子，我们反转路径以产生所需的叶子到根排序，并将其与当前最佳答案进行比较。 

变量`smallest`存储迄今为止找到的最佳字符串。 由于Python支持直接字典顺序比较字符串，我们可以简单地使用：```python
candidate < smallest
```回溯处理是通过`path.pop()`。 这会在返回父递归调用之前恢复路径状态。 

递归自然地探索所有从根到叶的路径，同时保持实现的简洁和高效。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func smallestFromLeaf(root *TreeNode) string {
    smallest := ""
    path := make([]byte, 0)

    var dfs func(node *TreeNode)

    dfs = func(node *TreeNode) {
        if node == nil {
            return
        }

        path = append(path, byte('a'+node.Val))

        if node.Left == nil && node.Right == nil {
            candidateBytes := make([]byte, len(path))

            for i := 0; i < len(path); i++ {
                candidateBytes[i] = path[len(path)-1-i]
            }

            candidate := string(candidateBytes)

            if smallest == "" || candidate < smallest {
                smallest = candidate
            }
        }

        dfs(node.Left)
        dfs(node.Right)

        path = path[:len(path)-1]
    }

    dfs(root)

    return smallest
}
```Go 解决方案遵循与 Python 版本相同的 DFS 和回溯策略。 

一个重要的区别是字符串结构。 由于 Go 字符串是不可变的，我们使用`[]byte`遍历路径的切片。 在每个叶子上，我们手动构造反向候选字符串。 

回溯是通过缩小切片来实现的：```go
path = path[:len(path)-1]
```Go 还需要显式处理`nil`递归期间的指针。

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(N × H) | 每片叶子可能需要构建一个长度达到树高的字符串 |
 | 空间| O(H) | DFS递归栈和路径存储|

 DFS 只访问每个节点一次，贡献`O(N)`遍历成本。 然而，在每片叶子上，我们可以构造一个反向字符串，其长度可以达到树的高度`H`。 在最坏的情况下，存在许多叶子，总体复杂度为`O(N × H)`。 

辅助空间复杂度为`O(H)`因为递归栈和当前遍历路径只存储当前分支沿线的节点。

 ## 边缘情况

 ### 单节点树

 仅包含一个节点的树是一个重要的边界条件，因为根也是叶子。 有缺陷的实现可能会假设叶节点始终有父节点，或者可能错误地反转空路径。 在此实现中，DFS 立即将根识别为叶子并正确构造单字符字符串。 

### 词典前缀比较

 类似的情况`"abc"`相对`"abcc"`很微妙，因为即使所有现有字符都匹配，较短的字符串按字典顺序也较小。 仅按长度进行比较或过早停止比较的实现可能会失败。 Python 和 Go 都使用标准的字典字符串比较，它可以自动正确处理前缀排序。 

### 深倾斜树

 高度不平衡的树的行为几乎就像链表一样。 在每个递归步骤中重复复制字符串的简单解决方案可能会变得低效。 此实现通过维护可变路径结构并仅在到达叶子时构造字符串来避免过度复制。 

### 多个相同的字符

 许多节点包含相同值的树可以创建许多几乎相同的候选字符串。 这可能会暴露比较逻辑或路径处理中的问题。 由于该算法构造精确的从叶到根的字符串并直接比较它们，因此可以自然且正确地处理重复的字符。
