[LeetCode 922 题](https://leetcode.com/problems/sort-array-by-parity-ii/)

 **难度：** 🟢简单
 **主题：** 数组、两个指针、排序

 ## 解决方案

 ## 问题理解

 问题给出一个整数数组`nums`其中恰好一半元素是偶数，另一半是奇数。 任务是重新排列数组，使每个偶数索引包含一个偶数，每个奇数索引包含一个奇数。 

换句话说：

 - 如果有一个索引`i`是偶数，那么`nums[i]`也必须是均匀的。 
- 如果有一个索引`i`是奇数，那么`nums[i]`也一定是奇数。 

该问题保证始终存在有效的排列，因为数组包含相等数量的偶数和奇数，并且数组的总长度为偶数。 

例如，给定：```
nums = [4,2,5,7]
```有两个偶数（`4`,`2`) 和两个奇数 (`5`,`7`）。 有效的重新排列是：```
[4,5,2,7]
```因为：

 - 索引`0`是偶数并且包含`4`这是偶数
 - 索引`1`是奇数并且包含`5`这很奇怪
 - 索引`2`是偶数并且包含`2`这是偶数
 - 索引`3`是奇数并且包含`7`这很奇怪

 约束很重要，因为它们指导解决方案的预期效率：

 -`nums.length`可以大到`2 * 10^4`- 数组长度始终是偶数
 - 恰好一半的值是偶数，一半是奇数
 - 值是小整数，但它们的大小无关紧要，因为只有奇偶校验很重要

 这些限制强烈表明`O(n)`解决方案是理想的。 由于后续具体询问该解决方案是否可以就地完成，因此尽量减少额外的内存也是可取的。 

预先识别一些边缘情况很重要。 最小可能的输入只有两个元素，例如`[2,3]`。 另一个重要的情况是当数组已经正确排列时，因为算法应该避免破坏有效的配置。 当许多值放错位置时会出现更微妙的情况，例如所有偶数出现在奇数位置，反之亦然。 该问题保证奇数和偶数的计数相等，因此我们永远不需要处理不可能的输入。 

## 方法

 ### 蛮力方法

 解决该问题的一个直接方法是将所有偶数和所有奇数分成两个临时列表。 分离后，我们可以通过将偶数放入偶数索引并将奇数放入奇数索引来重建结果数组。 

该过程的工作原理如下：

 - 遍历数组一次。 
- 将所有偶数存储在一个列表中。 
- 将所有奇数存储在另一个列表中。 
- 创建结果数组。 
- 使用偶数列表填充偶数索引。 
- 使用奇数列表填充奇数索引。 

这种方法很容易理解并保证正确性，因为该问题已经保证偶数和奇数元素的数量相等。 

然而，该解决方案使用与输入大小成比例的额外内存。 虽然时间复杂度高效，但后续问问题是否可以就地解决，这样我们就可以在空间利用方面做得更好。 

### 最佳两指针方法

 关键的观察是我们不需要对数组进行完全排序。 我们只需要确保奇偶校验与索引奇偶校验匹配。 

这建议采用两指针策略：

 - 一个指针扫描偶数索引，寻找错误放置的奇数。 
- 另一个指针扫描奇数索引，查找位置不正确的偶数。 
- 每当发现两个放错位置的值时，交换它们。 

这是有效的，因为：

 - 偶数位置上的奇数最终必须移动到奇数位置。 
- 奇数位置上的偶数最终必须移动到偶数位置。 
- 交换这两个不正确的值同时修复两个位置。 

由于每个指针仅向前移动，并且每个元素最多处理一次，因此该算法以线性时间运行并使用恒定的额外空间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(n) | 使用单独的偶数和奇数列表来重建数组 |
 | 最佳| O(n) | O(1) | O(1) | 使用两个指针并就地交换放错位置的元素 |

 ## 算法演练

 ### 最优两指针算法

 1. 初始化一个指针`even_index`到`0`。 该指针只会在偶数索引上移动。 
2. 初始化另一个指针`odd_index`到`1`。 该指针只会在奇数索引上移动。 
3. 遍历数组使用`even_index`。 在每个偶数位置，检查该值是否放置正确。 
4. 如果`nums[even_index]`是偶数，那么这个位置已经有效。 移动`even_index`转发通过`2`。 
5. 如果`nums[even_index]`是奇数，则该值放错位置，因为偶数索引必须包含偶数。 
6. 现在在奇数索引中搜索错误放置的偶数。 移动`odd_index`转发通过`2`直到`nums[odd_index]`是均匀的。 
7. 找到两个放错位置的元素后：

 -`nums[even_index]`奇怪且位置错误
 -`nums[odd_index]`均匀且位置错误

 交换它们。 
8. 交换后：

 - 偶数索引现在包含偶数
 - 奇数索引现在包含奇数
 9. 继续，直到处理完所有偶数索引。 

### 为什么它有效

 该算法维护一个重要的不变量：每个处理的偶数索引包含一个偶数，每个处理的奇数索引包含一个奇数。 

每当发现不匹配时，算法就会找到互补的不匹配并交换两个元素。 由于偶数和奇数的计数相等，因此必须始终存在匹配的错位元素。 每次交换一次修复两个不正确的位置，保证最终的数组满足奇偶校验条件。 

## Python 解决方案```python
from typing import List

class Solution:
    def sortArrayByParityII(self, nums: List[int]) -> List[int]:
        even_index = 0
        odd_index = 1
        n = len(nums)

        while even_index < n:
            # If the current even index already contains an even number,
            # move to the next even index.
            if nums[even_index] % 2 == 0:
                even_index += 2
                continue

            # Find an odd index containing an even number.
            while nums[odd_index] % 2 == 1:
                odd_index += 2

            # Swap misplaced numbers.
            nums[even_index], nums[odd_index] = (
                nums[odd_index],
                nums[even_index],
            )

            even_index += 2

        return nums
```该实现遵循算法演练中描述的确切逻辑。 

变量`even_index`仅扫描偶数位置。 每当遇到奇数时，我们就知道该位置无效。 

变量`odd_index`仅扫描奇数位置，搜索同样位置错误的偶数。 

一旦识别出两个不匹配，交换就会同时修复两个位置。 由于每个指针仅向前前进并跳过已经正确的位置，因此该算法仍然有效。 

该方案直接修改输入数组，满足in-place算法的后续需求。 

## 解决方案```go
func sortArrayByParityII(nums []int) []int {
	evenIndex := 0
	oddIndex := 1
	n := len(nums)

	for evenIndex < n {
		// Correct placement for even index
		if nums[evenIndex]%2 == 0 {
			evenIndex += 2
			continue
		}

		// Find misplaced even number at odd index
		for nums[oddIndex]%2 == 1 {
			oddIndex += 2
		}

		// Swap misplaced values
		nums[evenIndex], nums[oddIndex] = nums[oddIndex], nums[evenIndex]

		evenIndex += 2
	}

	return nums
}
```Go 实现与 Python 版本几乎相同。 主要区别在于语法。 

Go 切片是可变的，因此交换直接修改原始切片。 不需要对空或 nil 切片进行特殊处理，因为约束保证至少有两个元素。 整数溢出不是问题，因为该算法仅执行奇偶校验和索引移动。

 ## 边缘情况

 一种重要的边缘情况是最小尺寸的数组，例如`[2,3]`。 小输入通常会暴露出相差一的错误或不正确的循环条件。 在此实现中，循环条件`even_index < n`确保安全遍历，算法在处理完唯一的偶数索引后正确终止。 

另一个重要的情况是数组已经有效，例如`[2,1,4,3]`。 有缺陷的实现可能会执行不必​​要的交换或意外破坏正确的放置。 此解决方案避免了该问题，因为它会立即跳过正确放置的元素。 

当几乎所有元素都放错位置时，就会出现更具挑战性的情况，例如`[1,2,3,4]`。 在这种情况下，算法必须重复搜索互补不匹配并正确交换它们。 两指针方法可以自然地处理这个问题，因为每次交换都会同时修复一个不正确的偶数位置和一个不正确的奇数位置。 

重复的值也很重要。 数组就像`[2,2,1,1]`验证算法仅依赖于奇偶性，而不依赖于唯一性。 由于逻辑仅检查数字是奇数还是偶数，因此无需任何特殊处理即可正确处理重复项。
