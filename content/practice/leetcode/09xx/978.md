[LeetCode 第 978 题](https://leetcode.com/problems/longest-turbulent-subarray/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划、滑动窗口

 ## 解决方案

 ## 问题理解

 该问题要求我们找到给定整数数组内最长的**湍流子数组**的长度`arr`。 

如果每个相邻数字对之间的关​​系在大于 (`>`) 且小于 (`<`）。 换句话说，当我们在子数组中移动时，比较符号必须不断翻转。 

例如，考虑：```
[4, 2, 10, 7, 8]
```比较是：```
4 > 2 < 10 > 7 < 8
```由于比较交替进行`>`和`<`每一步，这个子数组都是动荡的。 

问题并不关心哪个模式首先开始。 以下两项均有效：```
a > b < c > d
```和```
a < b > c < d
```输入是一个整数数组`arr`， 在哪里：

-`arr[i]`表示索引处的值`i`- 数组长度可以大到`4 * 10^4`- 每个值可以大到`10^9`输出应该是**任何连续湍流子阵列的最大长度**。 

这些约束很重要，因为它们会立即排除低效的解决方案。 自从`n`可以达到`40,000`， 一个`O(n²)`在实践中解决方案可能太慢，而且更糟糕的情况肯定是不可行的。 这强烈表明我们应该以线性或近线性方法为目标。 

有几个重要的边缘情况需要预先考虑。 

如果数组只包含一个元素，则答案必须是`1`因为单个元素是微不足道的湍流。 

如果相邻元素相等，则湍流会立即破裂，因为两者都不是`>`也不`<`成立。 例如：```
[9, 9]
```它有一个最长的湍流子数组，长度为`1`。 

严格递增或严格递减的数组也很有趣：```
[1, 2, 3, 4]
```比较永远不会交替，所以最好的答案是`2`，因为任何相邻的货币对在技术上都是动荡的。 

我们还需要处理湍流多次中断和重新启动的情况。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是检查**每个可能的子数组**并检查它是否是湍流。 

对于每个起始索引`i`，我们尝试每个结束索引`j`，然后验证每个相邻对之间的比较是否正确交替。 

为了验证子数组，我们比较连续的元素并确保：

 - 没有相邻的值相等
 - 比较方向交替

 如果任何比较失败，则子数组不是混乱的。 

这种方法是正确的，因为它详尽地检查了所有可能性并保证最终会找到最大有效长度。 

然而，它的计算成本很高。 有`O(n²)`子数组，检查每个子数组可以采取`O(n)`时间，导致 **O(n3)** 复杂度。 即使进行了一些优化，它仍然太慢`n = 40,000`。 

### 最佳解决方案的关键见解

 关键的观察结果是，湍流仅取决于**相邻元素**之间的关系。 

我们可以一次性处理数组并跟踪当前的湍流窗口，而不是重复检查整个子数组。 

在每个指标上，我们都比较：```
arr[i - 1] and arr[i]
```有以下三种可能：

 1.`arr[i] > arr[i - 1]`2.`arr[i] < arr[i - 1]`3.`arr[i] == arr[i - 1]`如果比较与之前的比较交替，则混乱的序列将继续。 

如果比较变得相等，则湍流完全重置。 

如果比较重复相同的方向，当前的动荡序列就会中断，但我们可以从前一个元素重新开始。 

这自然会导致以线性时间运行的**滑动窗口/动态编程风格**解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n3) | O(1) | O(1) | 检查每个子阵列并验证湍流 |
 | 最佳 | O(n) | O(1) | O(1) | 一次性跟踪交替比较 |

 ## 算法演练

 ### 最优滑动窗口方法

 我们维持：

 -`current_length`, 当前湍流子数组的长度
 -`max_length`，迄今为止找到的最佳答案
 -`previous_comparison`，它存储前一对是增加、减少还是相等

 我们将比较表示为：```
1  -> increasing
-1 -> decreasing
0  -> equal
```#### 第 1 步：初始化变量

 从以下开始：```
max_length = 1
current_length = 1
previous_comparison = 0
```单个元素总是动荡的，所以最小的答案是`1`。 

#### 步骤 2：迭代相邻对

 对于每个索引`i`从`1`到`n - 1`， 比较：```
arr[i] with arr[i - 1]
```确定当前比较：

 -`1`如果增加
 -`-1`如果减少
 -`0`如果相等

 #### 步骤 3：处理相等元素

 如果：```
arr[i] == arr[i - 1]
```然后湍流立即破裂。 

重置：```
current_length = 1
```因为当前元素开始一个新的可能的子数组。 

#### 步骤 4：扩展湍流序列

 如果当前比较与前一个比较交替：```
current_comparison != previous_comparison
```也不是`0`，然后动荡的格局仍在继续。 

增加：```
current_length += 1
```#### 步骤 5：重新启动序列

 如果比较方向重复：```
>, >
```或者```
<, <
```然后湍流破裂。 

然而，当前对本身形成一个有效的长度为的湍流子数组`2`。 

所以重置：```
current_length = 2
```#### 步骤 6：更新最大值

 处理完每个元素后：```
max_length = max(max_length, current_length)
```存储当前比较以供下一次迭代使用。 

### 为什么它有效

 该算法保持不变式`current_length`始终表示以当前索引结尾的最长湍流子数组的长度。 

每当相邻比较交替时，我们就安全地扩展当前子数组。 当模式打破时，我们从最小的有效湍流段重新开始。 由于每个索引都被处理一次并且考虑了每种可能的混乱结局，因此保证找到的最大长度是正确的。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxTurbulenceSize(self, arr: List[int]) -> int:
        n = len(arr)

        if n == 1:
            return 1

        max_length = 1
        current_length = 1
        previous_comparison = 0

        for i in range(1, n):
            if arr[i] > arr[i - 1]:
                current_comparison = 1
            elif arr[i] < arr[i - 1]:
                current_comparison = -1
            else:
                current_comparison = 0

            if current_comparison == 0:
                current_length = 1
            elif current_comparison == -previous_comparison:
                current_length += 1
            else:
                current_length = 2

            max_length = max(max_length, current_length)
            previous_comparison = current_comparison

        return max_length
```该实现首先处理最小的边缘情况，即长度为 1 的数组。 

然后我们维护三个变量：

 -`max_length`存储最佳答案。 
-`current_length`跟踪以当前索引结尾的湍流子数组。 
-`previous_comparison`记住之前比较的方向。 

在每次迭代中，我们确定当前对是增加、减少还是相等。 

如果元素相等，则湍流会重置，因为相等的数量不能满足任一交替条件。 

如果当前的比较与前一个相反，我们就延长动荡段。 

否则，湍流中断，但当前相邻对仍然形成长度为有效的湍流子数组`2`。 

最后，我们在每一步之后更新全局最大值。 

## 解决方案```go
func maxTurbulenceSize(arr []int) int {
	n := len(arr)

	if n == 1 {
		return 1
	}

	maxLength := 1
	currentLength := 1
	previousComparison := 0

	for i := 1; i < n; i++ {
		currentComparison := 0

		if arr[i] > arr[i-1] {
			currentComparison = 1
		} else if arr[i] < arr[i-1] {
			currentComparison = -1
		}

		if currentComparison == 0 {
			currentLength = 1
		} else if currentComparison == -previousComparison {
			currentLength++
		} else {
			currentLength = 2
		}

		if currentLength > maxLength {
			maxLength = currentLength
		}

		previousComparison = currentComparison
	}

	return maxLength
}
```Go 的实现与 Python 解决方案非常相似。 

Go 切片已经是引用类型，因此不需要特殊的数组处理。 由于这些约束很适合 Go 的内部`int`，整数溢出不是这里的问题。 我们显式初始化`currentComparison`到`0`，它自然代表相等的元素。 

与 Python 不同，Go 不提供内置的`max()`整数函数，所以我们更新`maxLength`使用简单的条件比较。

 ## 边缘情况

 ### 单元素数组

 只有一个元素的数组是微不足道的，因为不存在违反规则的相邻比较。 

如果实现假设至少存在一个比较，这种情况很容易导致错误。 我们的实现立即处理它：```
if n == 1:
    return 1
```### 相邻元素相等

 平等的价值尤其重要，因为它们完全打破了动荡。 

例如：```
[4, 4, 5]
```这对`4 == 4`不能参与任何交替比较模式。 我们的实施重置`current_length`到`1`，确保算法随后正确地重新开始。 

### 单调数组

 完全递增或完全递减的数组可能具有欺骗性。 

例如：```
[1,2,3,4]
```幼稚的实现可能会错误地返回`1`，但任何相邻的元素对已经形成长度为有效的湍流子数组`2`。 

我们的实现正确重置为`2`每当比较方向重复时，确保保留最小有效相邻湍流对。
