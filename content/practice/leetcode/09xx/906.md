 # LeetCode 906 - 超级回文

 ## 问题理解

 这个问题要求我们计算给定范围内有多少个数字是“超级回文”。 

如果满足以下两个条件，则数字被视为超级回文：

 1. 数字本身是回文数。 
2. 该数字是另一个回文数的平方。 

例如：

-`121`是一个回文。 
-`121 = 11 * 11`-`11`也是一个回文。 

所以，`121`是一个超级回文。 

输入由两个字符串组成，`left`和`right`，分别表示搜索范围的下限和上限。 这些值可能非常大，高达`10^18 - 1`，这意味着我们不能在整个区间内依赖简单的强力迭代。 

目标是返回整数的总数`x`这样：

 -`left <= x <= right`-`x`是一个回文
 -`sqrt(x)`也是回文整数

 这里的约束非常重要：

 - 范围端点最多可以包含 18 位数字。 
- 因此，该区间可以跨越近五万亿个数字。 
- 任何检查范围内每个数字的方法都是完全不可行的。 

关键的观察结果是超级回文非常罕见。 我们不应该搜索范围内的每个数字，而应该直接生成回文根，将它们平方，然后测试平方是否也是回文。 

一些边缘情况很重要：

 - 非常小的范围，例如`[1, 2]`- 仅包含一个数字的范围
 - 附近大范围`10^18`- 根不是回文的回文平方，例如`676 = 26^2`- 如果处理不慎，平方根超出整数限制的数字

 该问题保证：

 - 输入是有效的正整数
 - 不存在前导零
 -`left <= right`这使我们能够完全专注于高效的生成和验证。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是迭代区间中的每个数字`[left, right]`。 

对于每个数字：

 1. 检查数字本身是否是回文。 
2. 计算其整数平方根。 
3. 验证平方根是否等于该数字。 
4. 检查平方根是否也是回文。 

这种方法在逻辑上是正确的，因为它直接验证了超级回文的定义。 

然而，这些限制使得这在实践中变得不可能。 该范围最多可以包含`10^18`数字，这远远超出了计算的可行性。 

即使回文检查是有效的，迭代如此大的间隔也无法在时间限制内完成。 

### 最佳方法

 关键的见解是超级回文是从回文根生成的。 

我们不是迭代该范围内的所有数字，而是生成其平方可能落在该范围内的所有回文数。 

认为：```
x = y^2
```如果`x <= 10^18`， 然后：```
y <= 10^9
```这大大减少了搜索空间。 

现在观察更重要的事情：

 - 我们只关心回文根。 
- 下面的回文整数的个数`10^9`实际上很小。 

我们可以通过镜像数字来有效地构造回文：

 - 奇数长度回文
 - 偶数长度回文

 对于每个生成的回文根：

 1. 将其平方。 
2. 平方超过则停止`right`。 
3. 检查正方形本身是否是回文。 
4. 计数是否在范围内。 

这将问题从搜索数十亿或数百万的值转变为仅生成数万个回文候选。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(右 - 左) | O(1) | O(1) | 单独检查每个数字 |
 | 最佳 | O(P 日志 P) | O(1) | O(1) | 仅生成回文根 |

 这里，`P`表示生成的回文根的数量，与区间大小相比非常小。 

## 算法演练

 1. 转换`left`和`right`从字符串到整数，因此数值比较变得高效。 
2. 计算可能根的上限。 自从`right <= 10^18`，任何有效根必须满足：```
root^2 <= right
```所以：```
root <= sqrt(right)
```3. 生成回文根而不是检查每个数字。 

我们生成两种类型：

 - 奇数长度回文
 - 偶数长度回文

 这确保我们覆盖所有回文整数。 
4. 构建奇数长度回文：

 - 从一个基数开始，例如`"123"`- 镜像除最后一位之外的所有数字
 - 结果变成`"12321"`5. 构建偶数回文：

 - 开始于`"123"`- 镜像整个字符串
 - 结果变成`"123321"`6. 将每个生成的回文根转换为整数。 
7. 回文根的平方。 
8. 如果平方超过`right`，停止处理该类型的较大回文，因为生成的回文是单调增长的。 
9. 检查正方形本身是否是回文。 
10. 如果：

 -`left <= square <= right`- 正方形是回文的

 增加答案。 
11. 继续，直到处理完所有可能的回文根。 

### 为什么它有效

 每个超级回文数必须是回文整数的平方。 因此，不必搜索目标范围内的所有数字，只需枚举平方可能落在该区间内的所有回文根即可。 

该算法只生成每个可能的回文根一次。 对于每个根，它检查平方是否也是回文。 由于每个有效的超级回文都源自这样的根，因此该算法会计算所有有效答案，而不会遗漏任何情况。 

## Python 解决方案```python
class Solution:
    def superpalindromesInRange(self, left: str, right: str) -> int:
        left_num = int(left)
        right_num = int(right)

        def is_palindrome(value: int) -> bool:
            s = str(value)
            return s == s[::-1]

        count = 0

        # Generate odd-length palindrome roots
        k = 1
        while True:
            s = str(k)
            palindrome = int(s + s[-2::-1])

            square = palindrome * palindrome

            if square > right_num:
                break

            if square >= left_num and is_palindrome(square):
                count += 1

            k += 1

        # Generate even-length palindrome roots
        k = 1
        while True:
            s = str(k)
            palindrome = int(s + s[::-1])

            square = palindrome * palindrome

            if square > right_num:
                break

            if square >= left_num and is_palindrome(square):
                count += 1

            k += 1

        return count
```实现首先将字符串边界转换为整数以进行有效的算术运算。 

辅助函数`is_palindrome`将数字转换为字符串并将其与相反的数字进行比较。 这是执行回文检查的有效且可读的方法。 

然后，该解决方案分别生成奇数长度和偶数长度的回文根。 

对于奇数长度回文：```python
s + s[-2::-1]
```镜像除最后一位之外的所有数字。 

例子：```python
"123" -> "12321"
```对于偶数长度回文：```python
s + s[::-1]
```镜像整个字符串。 

例子：```python
"123" -> "123321"
```每个回文根立即平方。 如果平方超过上限，则循环终止，因为未来的回文只会变得更大。 

每当一个正方形位于目标区间内并且本身是回文时，答案计数器就会增加。 

该算法避免了不必要的工作，因为它只探索数学上相关的候选者。 

## 解决方案```go
package main

import (
	"strconv"
)

func superpalindromesInRange(left string, right string) int {
	leftNum, _ := strconv.ParseInt(left, 10, 64)
	rightNum, _ := strconv.ParseInt(right, 10, 64)

	isPalindrome := func(value int64) bool {
		s := strconv.FormatInt(value, 10)

		i := 0
		j := len(s) - 1

		for i < j {
			if s[i] != s[j] {
				return false
			}

			i++
			j--
		}

		return true
	}

	count := 0

	// Odd-length palindrome roots
	for k := 1; ; k++ {
		s := strconv.Itoa(k)

		palStr := s
		for i := len(s) - 2; i >= 0; i-- {
			palStr += string(s[i])
		}

		palindrome, _ := strconv.ParseInt(palStr, 10, 64)

		square := palindrome * palindrome

		if square > rightNum {
			break
		}

		if square >= leftNum && isPalindrome(square) {
			count++
		}
	}

	// Even-length palindrome roots
	for k := 1; ; k++ {
		s := strconv.Itoa(k)

		palStr := s
		for i := len(s) - 1; i >= 0; i-- {
			palStr += string(s[i])
		}

		palindrome, _ := strconv.ParseInt(palStr, 10, 64)

		square := palindrome * palindrome

		if square > rightNum {
			break
		}

		if square >= leftNum && isPalindrome(square) {
			count++
		}
	}

	return count
}
```Go 实现遵循与 Python 版本相同的逻辑，但使用显式字符串构造，因为 Go 不提供 Python 风格的切片语法。`strconv.ParseInt`将字符串转换为整数，同时`strconv.FormatInt`将整数转换回字符串以进行回文检查。 

回文验证使用两指针技术而不是反转字符串。 这避免了分配第二个反向字符串，并且在 Go 中是惯用的。 

所有算术用途`int64`因为价值观可能会接近`10^18`。

 ## 边缘情况

 ### 单数字范围

 范围如下：```
left = "121"
right = "121"
```可以很容易地暴露出相差一的错误。 某些实现意外地将间隔视为一侧独占。 该解决方案正确地使用了包容性比较：```
square >= left_num and square <= right_num
```这确保了精确边界匹配的计数。 

### 具有非回文根的回文平方

 像这样的数字：```
676 = 26^2
```本身就是一个回文，但是`26`不是。 仅检查数字及其平方根关系是否存在的简单解决方案可能会错误地计算它。 

此实现通过首先仅生成回文根来完全避免该问题。 

### 极大的上限

 上限可能接近：```
10^18 - 1
```由于时间限制，暴力解决方案会立即失败。 此外，粗心的实现可能会溢出标准整数类型。 

该算法通过以下方式安全地处理这个问题：

 - 仅生成相关的回文根
 - 使用 64 位整数运算
 - 一旦平方超过上限就停止生成

 这保证了最大允许输入的正确性和效率。
