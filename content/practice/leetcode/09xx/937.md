[LeetCode 937 题](https://leetcode.com/problems/reorder-data-in-log-files/)

 **难度：** 🟡 中等
 **主题：** 数组、字符串、排序

 ## 解决方案

 ## 问题理解

 在这个问题中，我们得到了一个日志字符串列表。 每个日志都包含一个标识符，后跟一个或多个以空格分隔的单词。 第一个标记始终是标识符，其后的所有内容代表日志的内容。 

日志分为两类：

 - 字母日志，其中标识符后面的每个单词仅包含小写英文字母。 
- 数字日志，其中标识符后面的每个单词仅包含数字。 

目标是根据三个规则对日志重新排序：

 1. 所有字母日志必须出现在所有数字日志之前。 
2. 信件日志必须按其内容的字典顺序排序。 
3. 如果两个字母日志内容相同，则必须按标识符排序。 
4. 数字日志必须保留其原始相对顺序。 

输入是字符串数组，输出应该是满足所有这些要求的重新排序的字符串数组。 

限制相当小：

 - 最多 100 个日志
 - 每条日志长度最多100个字符

 这些限制意味着性能并不是极其关键，但我们仍然需要一个干净、高效的解决方案。 由于涉及到排序，`O(n log n)`解决方案是理想的并且完全足够。 

有几个重要的边缘情况需要记住：

 - 多个字母日志可以具有相同的内容，需要进行标识符比较。 
- 所有日志可能已经是数字日志。 
- 所有日志可能已经是字母日志。 
- 数字日志必须保持原始顺序，因此排序过程必须保持它们的稳定性。 
- 内容比较最初应忽略标识符，因为排序主要基于内容。 

## 方法

 ### 蛮力方法

 强力方法将手动分离字母日志和数字日志，然后使用自定义排序例程（例如冒泡排序）重复比较和重新排序字母日志。 

该算法将：

 1、遍历所有日志。 
2. 将它们分成两个数组：

 - 信函日志
 - 数字日志
 3. 使用嵌套循环比较每对字母日志。 
4. 首先比较内容，然后根据需要比较标识符。 
5. 随后附加数字日志。 

这是有效的，因为它直接遵循问题规则。 但是，使用嵌套循环手动排序会导致`O(n²)`时间复杂度，这是不必要的，因为现代语言已经提供了高效的排序算法。 

### 最佳方法

 关键的观察结果是可以使用自定义排序键清晰地表示排序规则。 

对于每个日志：

 - 如果它是字母日志，我们使用以下方法对其进行排序：

 - 内容
 - 标识符
 - 如果它是数字日志，我们将其放置在所有字母日志之后，同时保留原始顺序。 

稳定的排序在这里变得很重要。 Python 的内置排序是稳定的，Go 的`sort.SliceStable`还保留相等元素的顺序。 

我们定义了一个自然执行所有要求的比较规则，而不是手动重新排列日志。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 手动比较和交换|
 | 最佳 | O(n log n) | O(n log n) | O(n) | 使用自定义排序的稳定排序 |

 ## 算法演练

 1. 迭代每个日志并将其分为两部分：

 - 标识符
 - 内容
 2. 确定日志是字母日志还是数字日志。 

这可以通过检查内容的第一个字符来完成：

 - 如果是数字，则日志是数字日志。 
- 否则，它是一个字母日志。 
3. 为每个日志定义一个排序键。 

对于信件日志：

 - 主键：内容
 - 辅助键：标识符

 对于数字日志：

 - 它们应该出现在所有字母日志之后。 
- 它们的相对顺序必须保持不变。 
4.使用稳定的排序算法。 

稳定性很重要，因为数字日志不应相对于彼此重新排列。 
5. 返回排序后的日志数组。 

### 为什么它有效

 该算法之所以有效，是因为自定义排序与问题规范完全匹配。 

- 信件日志按内容按字典顺序排序。 
- 标识符比较解决了联系。 
- 数字日志始终放在字母日志之后。 
- 稳定的排序保证数字日志保持其原始顺序。 

由于每个规则都直接编码到排序逻辑中，因此保证最终排序是正确的。 

## Python 解决方案```python
from typing import List

class Solution:
    def reorderLogFiles(self, logs: List[str]) -> List[str]:

        def sort_key(log: str):
            identifier, content = log.split(" ", 1)

            # Letter-log
            if content[0].isalpha():
                return (0, content, identifier)

            # Digit-log
            return (1,)

        return sorted(logs, key=sort_key)
```该实现定义了一个名为的辅助函数`sort_key`。 

每个日志一次分为：

 -`identifier`-`content`使用`split(" ", 1)`很重要，因为我们只希望第一个空格将标识符与日志的其余部分分开。 

如果内容以字母开头，我们返回一个元组：```python
(0, content, identifier)
```领先的`0`确保所有字母日志都在数字日志之前。 

对于数字日志，我们返回：```python
(1,)
```由于 Python 排序是稳定的，数字日志会自动保持其原始的相对顺序。 

最后直接返回排序后的结果。 

## 解决方案```go
package main

import (
	"sort"
	"strings"
)

func reorderLogFiles(logs []string) []string {

	sort.SliceStable(logs, func(i, j int) bool {

		id1, content1 := splitLog(logs[i])
		id2, content2 := splitLog(logs[j])

		isDigit1 := isDigit(content1[0])
		isDigit2 := isDigit(content2[0])

		// Both are letter-logs
		if !isDigit1 && !isDigit2 {

			if content1 == content2 {
				return id1 < id2
			}

			return content1 < content2
		}

		// One is letter-log, one is digit-log
		if !isDigit1 && isDigit2 {
			return true
		}

		if isDigit1 && !isDigit2 {
			return false
		}

		// Both are digit-logs, preserve order
		return false
	})

	return logs
}

func splitLog(log string) (string, string) {
	parts := strings.SplitN(log, " ", 2)
	return parts[0], parts[1]
}

func isDigit(ch byte) bool {
	return ch >= '0' && ch <= '9'
}
```Go 解决方案使用`sort.SliceStable`，这很重要，因为数字日志必须保留其相对顺序。 

与 Python 不同，Go 需要显式比较器函数而不是排序键元组。 

比较器处理四种情况：

 1. 两个日志都是字母日志
 2. 第一个是字母日志，第二个是数字日志
 3. 第一个是数字对数，第二个是字母对数
 4. 两者都是数字日志

 返回`false`当两者都是数字日志时，会保留其原始顺序，因为排序是稳定的。

 ## 边缘情况

 ### 具有相同内容的多个字母日志

 当两个字母日志共享相同内容时，会出现一个常见错误。 如果实现仅按内容排序，则最终排序将变得不正确。 

例如：```
["b1 act car", "a1 act car"]
```两个内容是相同的，因此标识符必须确定顺序。 该实现通过使用来处理这个问题`(content, identifier)`作为排序键。 

### 所有日志都是数字日志

 如果每个日志都是数字日志，则不应发生重新排序。 

即使问题明确要求保留日志的相对顺序，不稳定的排序也可能会意外地重新排列日志。 

该实现避免了这个问题，因为：

 - Python 排序稳定。 
- Go 使用`sort.SliceStable`。 

### 具有非常相似前缀的日志

 日志可以共享相似的起始词，但稍后会有所不同：```
["let1 art can",
 "let2 art zero"]
```幼稚的实现可能只比较标识符后面的第一个单词，这会产生不正确的排序。 

该解决方案按字典顺序比较整个内容字符串，确保所有单词的完整且正确的排序。
