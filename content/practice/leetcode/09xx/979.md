[LeetCode 问题 979](https://leetcode.com/problems/distribute-coins-in-binary-tree/)

 **难度：** 🟡 中等
 **主题：** 树、深度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 在这个问题中，我们得到一个二叉树，其中每个节点都包含一定数量的硬币。 整棵树上的硬币总数恰好等于树中的节点数。 我们的目标是重新分配硬币，以便每个节点最终都只有一枚硬币。 

单次移动包括在两个相邻节点之间转移一枚硬币。 由于树的运动是无向的，因此一枚硬币可以从父节点移动到子节点，或者从子节点移动到父节点。 一枚硬币的每一次边缘遍历都算作一次移动。 

挑战在于确定使分布平衡所需的最小移动次数。 

输入是二叉树的根。 每个节点有：

 -`node.val`，代表节点当前持有多少币
 -`left`和`right`指向它的孩子的指针

 输出是一个整数，表示所需的最小代币转移数量。 

限制很小：

 - 树最多包含 100 个节点
 - 每个节点可以包含 0 到`n`硬币
 - 硬币总数始终等于节点总数

 这些限制告诉我们，即使`O(n^2)`该解决方案在技术上可以通过，但问题的结构强烈表明线性遍历是可能的。 

有几个重要的边缘情况：

 - 一个节点可能已经拥有一枚硬币，无需移动。 
- 节点可能有零币并且完全依赖于传入的传输。 
- 一个节点可能包含许多多余的硬币，必须向上和向下分配。 
- 树可能高度不平衡，实际上成为链表。 
- 根本身可能需要发送或接收许多硬币。 

如果没有正确考虑有多少硬币流过每条边，那么幼稚的实现很容易错误计算移动次数。 

## 方法

 ### 蛮力方法

 暴力策略会反复搜索有多余硬币的节点，并将硬币移向缺少硬币的节点。 

一种可能的实现是：

 1. 找到一个有多个币的节点。 
2. 找到最近的零币节点。 
3. 沿着硬币之间的路径移动硬币。 
4. 重复，直到每个节点都包含一枚硬币。 

这最终会产生正确的结果，因为每一步都会逐渐减少不平衡。 然而，它的效率很低，因为每次重新分配可能需要遍历树的大部分来定位缺陷并计算路径。 

主要问题是相同的边可能会被重复遍历。 在最坏的情况下，每次重新分配操作的成本`O(n)`，我们可能需要`O(n)`重新分配，导致`O(n^2)`复杂。 

更重要的是，暴力法并没有自然地暴露问题的关键结构，即每个子树可以独立地确定它必须发送或接收多少个硬币。 

### 最佳解决方案的关键见解

 关键的观察是每个子树都有一个自然的“硬币余额”。 

对于任意子树：

 - 如果它包含的硬币多于节点，则它有多余的硬币可以赠送。 
- 如果它包含的硬币少于节点，则它需要来自其父节点的硬币。 

假设子树包含：

 -`totalCoins`硬币
 -`totalNodes`节点

 那么它的余额为：```
balance = totalCoins - totalNodes
```这个平衡告诉我们：

 - 正平衡，子树向上发送硬币
 - 负余额，子树从父树接收硬币
 - 零平衡，子树已经内部平衡

 子树贡献的移动次数只是通过连接其父树的边转移的余额的绝对值。 

这自然表明后序深度优先遍历：

 1. 求解左子树。 
2. 求解右子树。 
3. 计算当前节点余额。 
4. 将转移的硬币数量添加到答案中。 

因为每条边都被处理一次，所以解变成线性的。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 反复搜索并重新分配硬币|
 | 最优 DFS | O(n) | O(h) | 后序遍历高效计算子树平衡 |

 这里，`h`代表树的高度。 

## 算法演练

 ### 最优后序 DFS 算法

 1. 对树执行后序深度优先遍历。 

我们在父级之前处理子级，因为父级需要知道每个子树有多少多余或丢失的硬币。 
2. 递归计算左子树的平衡。 

返回的值表示左子树发送给其父节点的硬币数量：

 - 正值表示多余的硬币
 - 负数意味着缺少硬币
 3. 递归计算右子树的平衡。 

处理方式完全相同。 
4. 计算两个子树所需的移动次数。 

每一枚硬币越过边缘都会花费一次移动时间。 所以：```
moves += abs(leftBalance) + abs(rightBalance)
```绝对值很重要，因为发送和接收都需要越过边缘移动。 
5. 计算当前节点的余额。 

该节点贡献：

 -`node.val`硬币
 - 本身只需要一枚硬币

 因此：```
currentBalance = node.val + leftBalance + rightBalance - 1
```6. 将天平调回上方。 

家长将使用此余额来确定有多少硬币穿过连接边缘。 

### 为什么它有效

 该算法之所以有效，是因为每个子树独立地确定相对于其包含的节点数量的盈余或赤字。 

任何不平衡都必须正好穿过一条边，该边将子树连接到其父树。 因此，该子树贡献的最小移动次数恰好是其余额的绝对值。 

由于在后序遍历期间每条边都被处理一次，并且每个必要的硬币转移都被精确计算一次，因此该算法会产生尽可能少的移动次数。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional

class Solution:
    def distributeCoins(self, root: Optional[TreeNode]) -> int:
        moves = 0

        def dfs(node: Optional[TreeNode]) -> int:
            nonlocal moves

            if not node:
                return 0

            left_balance = dfs(node.left)
            right_balance = dfs(node.right)

            moves += abs(left_balance) + abs(right_balance)

            current_balance = (
                node.val + left_balance + right_balance - 1
            )

            return current_balance

        dfs(root)

        return moves
```实现直接遵循后序遍历策略。 

这`dfs`函数返回当前子树的余额。 正值意味着子树有额外的硬币可以向上发送，而负值意味着它需要来自父树的硬币。 

递归首先处理左子树和右子树。 一旦知道了它们的余额，我们就可以确切地知道有多少硬币必须穿过将它们连接到当前节点的边缘。 

声明：```python
moves += abs(left_balance) + abs(right_balance)
```计算通过这些边缘的所有硬币转移。 

最后，当前节点通过组合以下方式计算自己的余额：

 - 自己的硬币
 - 两个孩子的余额
 - 它必须为自己保留的一枚硬币

 最终答案累计为`moves`。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func distributeCoins(root *TreeNode) int {
    moves := 0

    var dfs func(node *TreeNode) int

    dfs = func(node *TreeNode) int {
        if node == nil {
            return 0
        }

        leftBalance := dfs(node.Left)
        rightBalance := dfs(node.Right)

        moves += abs(leftBalance) + abs(rightBalance)

        currentBalance := node.Val + leftBalance + rightBalance - 1

        return currentBalance
    }

    dfs(root)

    return moves
}

func abs(x int) int {
    if x < 0 {
        return -x
    }

    return x
}
```Go 解决方案密切反映了 Python 实现。 

主要区别在于 Go 没有为通用整数提供内置的整数绝对值函数，因此我们定义了一个助手`abs`功能。 

Go 也使用显式`nil`检查而不是 Python 的真实性检查。 否则，递归逻辑和平衡计算保持相同。 

## 工作示例

 ### 示例 1```
Input: [3,0,0]

      3
     / \
    0   0
```### 逐步遍历

 | 节点| 左平衡 | 正确的平衡| 添加动作 | 当前余额|
 | ---| ---| ---| ---| ---|
 | 左子 (0) | 0 | 0 | 0 | -1 |
 | 右子 (0) | 0 | 0 | 0 | -1 |
 | 根 (3) | -1 | -1 | 2 | 0 |

 ### 解释

 左边的孩子需要一枚硬币，所以它返回`-1`。 

右边的孩子也需要一枚硬币，所以它返回`-1`。 

根有 3 个硬币。 它给每个孩子一枚硬币：```
3 + (-1) + (-1) - 1 = 0
```总动作：```
abs(-1) + abs(-1) = 2
```最终答案：```
2
```## 示例2```
Input: [0,3,0]

      0
     / \
    3   0
```### 逐步遍历

 | 节点| 左平衡 | 正确的平衡| 添加动作 | 当前余额|
 | ---| ---| ---| ---| ---|
 | 左子 (3) | 0 | 0 | 0 | 2 |
 | 右子 (0) | 0 | 0 | 0 | -1 |
 | 根 (0) | 2 | -1 | 3 | 0 |

 ### 解释

 左孩子有3个硬币，但只需要1个，所以返回`2`。 

右孩子没有硬币，需要一枚，所以返回`-1`。 

根从左侧接收 2 个硬币，并向右侧发送 1 个硬币。 

添加的动作：```
abs(2) + abs(-1) = 3
```最终答案：```
3
```## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个节点都被访问一次 |
 | 空间| O(h) | 递归调用堆栈深度等于树高 |

 DFS 遍历对每个节点进行一次处理，并且每个节点仅执行恒定的工作，从而产生线性时间复杂度。 

空间复杂度来自递归深度。 在平衡树中，这是`O(log n)`，而在倾斜树的最坏情况下，它变成`O(n)`。

 ## 边缘情况

 ### 单节点树

 一棵只包含一个节点和一枚硬币的树已经是平衡的。 这种情况很重要，因为递归算法有时会错误地计算移动次数或错误地处理叶节点。 

实现自然地处理了这个问题。 DFS 返回余额为零，并且不添加任何移动。 

### 高度倾斜的树

 形状像链表的树可以创建深度递归路径。 这很重要，因为硬币转移可能需要跨多个边缘传播。 

该实现正确地处理自下而上的平衡，确保无论树形状如何，每个边缘传输都被精确计数一次。 

### 有大量硬币过剩的节点

 一个节点可能包含比需要的更多的硬币。 例如，一个节点可以包含所有`n`硬币，而其他每个节点都包含零。 

这可能很棘手，因为多次传输必须通过中间节点传播。 该算法可以优雅地处理这个问题，因为余额会自然累积并通过递归向上传播。 

### 已经平衡的子树

 某些子树内部可能已经包含了正确数量的硬币。 

有缺陷的实现可能仍然会计算不必要的移动。 在此解决方案中，平衡子树返回零平衡，这意味着不会为其父边添加任何移动。
