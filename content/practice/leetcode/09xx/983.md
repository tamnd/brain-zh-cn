[LeetCode 983 题](https://leetcode.com/problems/minimum-cost-for-tickets/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划

 ## 解决方案

 ## 问题理解

 在这个问题中，我们得到了一年中的旅行天数列表以及三种不同火车通票的费用。 每个通行证涵盖连续的天数范围：

 - 一日通票正好涵盖一天。 
- 7 天通票涵盖连续 7 天。 
- 30 天通行证涵盖连续三十天。 

目标是确定覆盖每个旅行日所需的最低总成本`days`大批。 

输入数组`days`严格递增，这意味着旅行天数已经排序并且不包含重复项。 此属性非常有用，因为它允许我们按顺序处理行程安排，而不必担心重新排序或重复工作。 

这`costs`数组始终包含三个整数：

 -`costs[0]`是 1 日通行证的价格
 -`costs[1]`是 7 天通行证的价格
 -`costs[2]`是 30 天通行证的价格

 重要的细节是通票涵盖连续的日历日，而不仅仅是旅行日。 例如，如果 7 天通行证从第 10 天开始，则涵盖第 10 天到第 16 天（含），即使我们不在其中某些日子旅行。 

限制相对较小：

 - 最多 365 个旅行日
 - 天数范围仅从 1 到 365

 这些限制强烈表明动态规划是一个合适的解决方案。 由于一年中的总天数是固定的且很小，因此我们可以提供有效处理每一天或每个旅行指数的解决方案。 

需要考虑一些重要的边缘情况：

 - 仅存在一个旅行日。 
- 所有旅行日都是连续的。 
- 旅行的日子非常少。 
- 较长的通行证实际上可能比反复购买较短的通行证更便宜。 
- 之前购买的通行证可能已经涵盖了某些日期。 

A naive implementation can easily make mistakes when determining which future days are covered by a pass, especially around inclusive boundaries.

 ## 方法

 ### 蛮力方法

 暴力解决方案会尝试所有可能的购票组合。 

在每个旅行日，我们可以做出以下三种选择之一：

 1. 购买一日通票
 2.购买7天通行证
 3.购买30天通行证

 购买通行证后，我们递归地移动到下一个未覆盖的旅行日并重复该过程。 最终，我们计算每种可能组合的总成本并返回最小值。 

这种方法是正确的，因为它详尽地探索了每一种有效的购买策略。 然而，它会重复地重新计算相同的子问题。 例如，多个决策路径最终可能会问：

 “从旅行日指数 10 开始，最低成本是多少？”

 如果没有记忆，这些重复的计算会产生指数增长。 

### 最佳解决方案的关键见解

 关键的观察是该问题具有重叠的子问题和最优子结构。 

假设我们已经知道从某个索引开始的所有旅行日所需的最低成本`i`。 然后我们可以使用该信息来计算早期索引的答案。 

对于每个旅行日，我们只需要考虑三种可能性：

 - 购买 1 日通票
 - 购买 7 天通行证
 - 购买 30 天通行证

 选择通行证后，我们直接跳转到第一个未覆盖的旅行日。 

这自然会导致带有记忆的动态编程。 

我们不是重复地重新计算相同的状态，而是存储之前计算的结果。 由于旅行日最多为 365 个，因此州总数很少。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(3^n) | O(3^n) | O(n) | 递归探索所有购票组合 |
 | 最佳 | O(n) | O(n) | 具有记忆功能的动态规划 |

 ## 算法演练

 ### 最优动态规划策略

 1.定义递归函数`dp(i)`。 

该函数表示从索引开始的所有旅行日所需的最低成本`i`在`days`大批。 

如果`i`到达数组末尾，没有剩余行程天数，因此成本为`0`。 
2. 在索引处`i`，确定当前出行日期。 

让：```
current_day = days[i]
```我们现在考虑从这一天开始购买每种类型的通行证。 
3. 尝试购买一日通票。 

一日通行证仅适用于当天。 

我们进入下一个旅行日：```
cost1 = costs[0] + dp(i + 1)
```4. 尝试购买 7 天通行证。 

该通票涵盖以下日期起的所有旅行日期：```
current_day through current_day + 6
```我们将指针向前推进，直到到达第一个未覆盖的旅行日。 
5. 尝试购买 30 天的通行证。 

同样，此通行证涵盖：```
current_day through current_day + 29
```我们再次跳过所有承保的旅行日。 
6. 选择三个选项中的最小值。 

索引的最优解`i`是：```
min(cost1, cost7, cost30)
```7. 记住结果。 

存储索引的计算答案`i`这样以后的调用就可以立即重用它。 

### 为什么它有效

 该算法之所以有效，是因为每个有效的旅行计划都必须决定如何涵盖当前未覆盖的旅行日。 只有三种有效门票选择。 对于每个选择，一旦确定了覆盖范围，剩下的问题在结构上就与原始问题相同，只是从稍后的旅行日开始。 

动态规划保证了正确性，因为每个子问题都会计算其旅行天数后缀的真实最小成本，并且最终答案是根据这些最佳子问题解决方案构建的。 

## Python 解决方案```python
from typing import List
from functools import lru_cache

class Solution:
    def mincostTickets(self, days: List[int], costs: List[int]) -> int:
        n = len(days)

        @lru_cache(None)
        def dp(index: int) -> int:
            if index >= n:
                return 0

            # Option 1: Buy 1-day pass
            cost_1_day = costs[0] + dp(index + 1)

            # Option 2: Buy 7-day pass
            next_index = index
            while next_index < n and days[next_index] < days[index] + 7:
                next_index += 1

            cost_7_day = costs[1] + dp(next_index)

            # Option 3: Buy 30-day pass
            next_index = index
            while next_index < n and days[next_index] < days[index] + 30:
                next_index += 1

            cost_30_day = costs[2] + dp(next_index)

            return min(cost_1_day, cost_7_day, cost_30_day)

        return dp(0)
```该实现严格遵循前面描述的动态编程策略。 

这`dp(index)`函数计算涵盖从 开始的所有旅行日所需的最低成本`index`。 

这`@lru_cache(None)`装饰器自动记忆结果，防止对同一索引进行重复计算。 

对于每个递归调用，算法都会评估所有三个传递选项：

 - 1 日通票可提前 1 个旅行日。 
- 7 天通票可跳过连续七个日历日内涵盖的每个旅行日。 
- 30 天通票可跳过连续 30 个日历日内涵盖的每个旅行日。 

while 循环很重要，因为旅行天数很少。 我们不按固定位置前进。 相反，我们会跳过所选通票已涵盖的所有旅行日期。 

最后，该函数返回三种可能成本中的最小值。 

## 解决方案```go
func mincostTickets(days []int, costs []int) int {
	n := len(days)

	memo := make(map[int]int)

	var dp func(int) int

	dp = func(index int) int {
		if index >= n {
			return 0
		}

		if value, exists := memo[index]; exists {
			return value
		}

		// Option 1: 1-day pass
		cost1 := costs[0] + dp(index+1)

		// Option 2: 7-day pass
		nextIndex := index
		for nextIndex < n && days[nextIndex] < days[index]+7 {
			nextIndex++
		}

		cost7 := costs[1] + dp(nextIndex)

		// Option 3: 30-day pass
		nextIndex = index
		for nextIndex < n && days[nextIndex] < days[index]+30 {
			nextIndex++
		}

		cost30 := costs[2] + dp(nextIndex)

		result := min(cost1, min(cost7, cost30))

		memo[index] = result

		return result
	}

	return dp(0)
}

func min(a int, b int) int {
	if a < b {
		return a
	}
	return b
}
```Go 实现使用显式记忆映射而不是 Python 的`lru_cache`。 

Go 不提供内置的记忆装饰器，因此我们手动将计算结果存储在`memo`。 

递归结构和转换逻辑与 Python 版本保持相同。 

由于最大可能答案很小，因此 Go 中不存在整数溢出问题。

 ## 边缘情况

 ### 单人旅行日

 如果只有一个旅行日，最佳解决方案几乎总是最便宜的适用通票，通常是 1 日通票。 

有缺陷的实现可能仍然会尝试不必要的递归或错误地计算覆盖范围。 我们的实现自然地处理了这个问题，因为递归在覆盖一天后立即到达基本情况。 

### 连续旅行天数

 当许多旅行日连续发生时，较长的行程会变得更加高效。 

例如：```
days = [1,2,3,4,5,6,7]
```总是购买最便宜的即时票的天真贪婪策略在这里可能会严重失败。 我们的动态规划方法评估每个状态的所有三种传递类型，保证全局最优答案。 

### 稀疏的旅行日

 当旅行日期相距很远时，长期通行证可能会浪费金钱，因为大多数涵盖的日期都未使用。 

例如：```
days = [1,100,200,300]
```该算法可以正确处理此问题，因为 while 循环仅跳过涵盖的旅行日，而不是日历日。 因此，每个递归状态准确地反映了下一个未覆盖的旅行日。
