 # LeetCode 956，最高的广告牌

 ## 问题理解

 这个问题要求我们将一组钢棒分成两组，使得两组的总高度完全相同。 在所有可能的等高对中，我们想要最大可达到的高度。 

每根杆可以通过以下三种方式之一使用：

 1. 将其放入左侧支架中
 2. 将其放在正确的支架上
 3.完全忽略它

 重要的限制是杆不能重复使用。 每根杆最多属于一个支撑。 

输入是一个数组`rods`，其中每个元素代表钢棒的长度。 输出是一个整数，表示两个支撑的最高可能相等高度。 

例如，如果我们有：```
[1,2,3,6]
```我们可以构建：```
Left  = 1 + 2 + 3 = 6
Right = 6
```两边高度相等`6`，所以答案是`6`。 

约束对于确定正确的算法策略非常重要：

 - 最多20根棒
 - 每根杆长度最多1000
 - 杆总数最多为 5000

 杆数较少表明指数式推理可能是可能的，但纯粹的蛮力解决方案仍然太大。 5000 的有限总和强烈暗示基于和或差的动态规划可能是预期的解决方案。 

一些边缘情况很重要：

 - 可能无法形成两个相等的支撑，在这种情况下我们返回`0`- 有些杆可能需要完全忽略
 - 多个不同的子集可以在支撑之间产生相同的差异
 - 使用所有棒不一定能得到最佳答案
 - 如果处理效率低下，非常大的杆可能会主导搜索空间

 关键的挑战是有效地探索所有分配杆的方法，同时跟踪足够的信息以了解最终是否可以形成相等的支撑。 

## 方法

 ### 蛮力方法

 蛮力解决方案考虑了每根杆的每种可能的分配。 

对于每根杆，我们有三种选择：

 1. 将其放在左侧支架上
 2. 将其放在正确的支架上
 3.忽略它

 与`n`棒，这创造了`3^n`可能的状态。 

对于每个配置，我们计算：```
left_sum
right_sum
```如果两个总和相等，我们更新最大答案。 

这种方法是正确的，因为它详尽地检查了杆的每种可能的分布，保证最终找到最佳的等高对。 

然而，复杂性变得太大：```
3^20 ≈ 3.4 billion
```这远远超出了可行的限度。 

### 最优动态规划方法

 关键的见解是我们不需要记住两种支撑物的确切组成。 相反，我们只需要跟踪：```
difference = abs(left_sum - right_sum)
```以及与该差异相关的最大可能的较小支撑高度。 

这极大地压缩了状态空间。 

假设我们目前有：```
difference = d
smaller_side = s
```那么较高的一侧一定是：```
s + d
```加工新棒时，我们有三种选择：

 1.忽略杆
 2.将其添加到较高的一侧
 3.将其添加到较小的一侧

 使用这种表示，许多不同的配置会崩溃为相同的 DP 状态。 

由于杆总和最多为 5000，因此可能的差异数量是有界的，使得动态规划变得可行。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(3^n) | O(3^n) | O(n) | 尝试所有可能的杆分配 |
 | 最优动态规划| O(n × sum(棒)) | O(总和(棒)) | 跟踪高度差异而不是精确的子集 |

 ## 算法演练

 ### 动态规划状态

 我们维护一个哈希图：```
dp[diff] = maximum smaller-side height
```意义：

-`diff`是两个支撑之间的高度差
 - 该值是该差异的较小支撑的最大可实现高度

 例如：```
dp[3] = 7
```意味着我们可以创建：```
smaller side = 7
larger side  = 10
difference   = 3
```### 逐步算法

 1. 使用以下命令初始化 DP 映射：```
dp[0] = 0
```这意味着两个支撑最初的高度均为 0。 

1. 一次处理一根棒。 
2. 对于每个现有状态`(diff, smaller_height)`在当前的DP地图中，考虑三种可能性。 
3.第一种可能，忽略杆。 

现有状态已经保持有效，因此不需要更新。 

1.第二种可能性，将杆添加到较高的支撑上。 

如果当前的差值是`diff`我们添加杆`r`对于较高的一侧，新的差异变为：```
new_diff = diff + r
```较小的支撑高度不会改变。 

1. 第三种可能性，将杆添加到较小的支撑上。 

这是更微妙的转变。 

认为：```
larger = smaller + diff
```添加杆后`r`到较小的一侧：```
new_smaller = smaller + min(diff, r)
new_diff = abs(diff - r)
```为什么？ 

如果`r <= diff`，之前较小的一侧仍然较小。 

如果`r > diff`，较小的一侧成为新的较高的一侧。 

较小的支持准确地获得：```
min(diff, r)
```1. 使用当前状态的副本仔细更新 DP 图。 

我们无法在迭代映射时修改映射，否则新状态可能会错误地影响同一迭代。 

1.处理完所有棒材后，返回：```
dp[0]
```不同之处`0`意味着两个支持相等。 

### 为什么它有效

 DP 不变量为：```
dp[diff] stores the maximum achievable smaller support height
for that exact height difference.
```每个杆的分配都通过转换来表示：

 - 忽略
 - 添加到较高的一侧
 - 添加到较小的一侧

 因此，每个有效的配置都会被探索。 

对于每个差异，我们仅保留具有最大较小支撑高度的配置，因为任何较小的值严格来说都更差，并且永远不会导致更好的最终答案。 

当我们最终达到：```
diff = 0
```两个支撑相等，并且存储的值是可达到的最高广告牌高度。 

## Python 解决方案```python
from typing import List

class Solution:
    def tallestBillboard(self, rods: List[int]) -> int:
        dp = {0: 0}

        for rod in rods:
            current = dp.copy()

            for diff, smaller_height in current.items():
                # Add rod to taller side
                new_diff = diff + rod
                dp[new_diff] = max(
                    dp.get(new_diff, 0),
                    smaller_height
                )

                # Add rod to smaller side
                new_diff = abs(diff - rod)
                new_smaller = smaller_height + min(diff, rod)

                dp[new_diff] = max(
                    dp.get(new_diff, 0),
                    new_smaller
                )

        return dp[0]
```实现首先用单个状态初始化 DP 映射：```python
{0: 0}
```这表示两个高度相等的零支撑。 

对于每个杆，我们使用以下命令创建当前 DP 状态的快照：```python
current = dp.copy()
```这很重要，因为我们只能从处理当前棒之前存在的状态进行转换。 

第一个过渡将杆添加到较高的支撑上。 差异增加，但较小的支撑高度保持不变。 

第二个过渡将杆添加到较小的支撑件上。 差异变为：```python
abs(diff - rod)
```较小的支撑高度增加：```python
min(diff, rod)
```对于每个产生的差异，我们仅保留最佳的较小边高度，使用`max`。 

在最后，`dp[0]`包含最大等支撑高度。 

## 解决方案```go
func tallestBillboard(rods []int) int {
	dp := map[int]int{
		0: 0,
	}

	for _, rod := range rods {
		current := make(map[int]int)

		for k, v := range dp {
			current[k] = v
		}

		for diff, smallerHeight := range current {
			// Add rod to taller side
			newDiff := diff + rod

			if val, exists := dp[newDiff]; !exists || smallerHeight > val {
				dp[newDiff] = smallerHeight
			}

			// Add rod to smaller side
			newDiff = abs(diff - rod)
			newSmaller := smallerHeight + min(diff, rod)

			if val, exists := dp[newDiff]; !exists || newSmaller > val {
				dp[newDiff] = newSmaller
			}
		}
	}

	return dp[0]
}

func abs(x int) int {
	if x < 0 {
		return -x
	}
	return x
}

func min(a, b int) int {
	if a < b {
		return a
	}
	return b
}
```Go 实现遵循与 Python 版本相同的逻辑。 

由于 Go 映射是引用类型，因此我们在迭代之前显式创建一个复制的映射。 这避免了迭代期间改变 DP 状态。 

Go 没有提供内置的`abs`或者`min`对于整数，因此辅助函数是手动实现的。 

整数溢出不是问题，因为棒总和的上限为 5000。

 ## 边缘情况

 ### 不可能的建造

 输入如：```
[1,2]
```不能形成两个相等的支撑。 

幼稚的实现可能会错误地返回最大的单个杆或意外地允许重复使用杆。 DP 解决方案避免了这种情况，因为只有状态`difference = 0`为最终答案做出贡献。 

### 重复的杆长度

 输入例如：```
[1,1,1,1]
```包含重复值。 

当出现重复项时，某些实现会意外地错误地覆盖状态。 使用 DP 图的复制快照可确保每个棒在每次迭代中精确处理一次。 

### 必须忽略的杆

 考虑：```
[3,4,3,3,2]
```最佳解决方案不一定使用每根杆。 

总是使用所有棒的贪婪方法可能会失败。 DP 公式自然支持忽略杆，因为每个状态在迭代期间都可以简单地保持不变。 

### 大差异过渡

 当向较小的一侧添加杆时，较小的一侧可能会变成较大的一侧。 

例如：```
difference = 2
rod = 5
```新的差异变为：```
abs(2 - 5) = 3
```不正确的实施常常会错误地处理这种逆转。 使用：```
abs(diff - rod)
```正确处理这两种情况。
