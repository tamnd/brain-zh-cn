[LeetCode 914 题](https://leetcode.com/problems/x-of-a-kind-in-a-deck-of-cards/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表、数学、计数、数论

 ## 解决方案

 ## 问题理解

 问题询问是否可以对表示为整数数组的一副纸牌进行分区`deck`，分成组，使每个组包含**完全**`x`卡，所有卡都具有相同的整数值，并且`x`大于1。本质上，我们需要找到一个数字`x`均匀地划分牌组中每张不同卡牌的数量。 如果这样一个`x`存在，我们返回`true`; 否则，我们返回`false`。 

输入`deck`是一个整数列表，每个整数代表一张卡的值。 输出是一个布尔值，指示是否存在有效分区。 约束告诉我们，牌组最多可以有 10,000 张牌，值范围从 0 到 10,000，这意味着解决方案在实践中必须线性或接近线性扩展。 边缘情况包括所有牌都相同的牌组、计数为素数的牌组或只有一张牌的牌组，这些牌无法形成有效的组（`x > 1`）。 

需要考虑的重要边缘情况包括重复多次的单张独特卡牌、数量不大于 1 的公因数的多张独特卡牌，以及只有一张卡牌且无法分区的牌组。 

## 方法

 蛮力方法涉及检查所有可能的组大小，从 2 到牌组的大小。 对于每个潜在的组大小，我们检查它是否可以除以这副牌中每张牌的数量。 如果我们找到适用于所有计数的组大小，我们将返回`true`; 否则，我们返回`false`。 虽然这是正确的，但效率很低，因为我们可能会检查许多不必要的组大小，特别是对于大型套牌，从而导致性能不佳。 

最佳方法利用了数论的关键见解。 我们可以计算所有牌数的**最大公约数 (GCD)**，而不是检查每个潜在的组大小。 如果GCD大于1，则说明存在一个数`x`将所有计数相除，满足问题的要求。 这种方法利用了所有计数的任何公约数都必须除以其 GCD 的数学特性，使其既优雅又高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(N * K) | O(N) | N = 牌组长度，K = 可能的组大小范围（最多最大数量）|
 | 最佳| O(N) | O(N) | 使用哈希映射计算出现次数，计算所有计数的 GCD |

 ## 算法演练

 1. 首先，使用哈希映射或字典计算牌组中每张不同卡牌的出现次数。 这一步可以让我们准确地知道每张卡有多少张。 
2. 将字典中的所有计数提取到列表中以供进一步处理。 
3. 计算所有计数的 GCD。 从第一个计数开始作为初始 GCD，并迭代计算每个后续计数的 GCD。 这确保了最终的 GCD 是能整除所有计数的最大数。 
4. 检查最终GCD是否大于1，如果大于，则返回`true`，因为可以将牌组划分为大小等于 GCD 的组。 否则，返回`false`。 

原理：GCD 代表除以所有牌数的最大数字。 如果这个数字大于1，就保证每张牌都能被分成这个大小的组，满足问题要求。 如果 GCD 为 1，则不可能进行此类分组。 

## Python 解决方案```python
from collections import Counter
from math import gcd
from functools import reduce
from typing import List

class Solution:
    def hasGroupsSizeX(self, deck: List[int]) -> bool:
        if not deck:
            return False
        
        count = Counter(deck)
        counts = list(count.values())
        
        deck_gcd = reduce(gcd, counts)
        
        return deck_gcd > 1
```在这个实现中，`Counter`有效地计算每张卡片的出现次数。 这`reduce`函数迭代计算所有计数的 GCD。 我们检查 GCD 是否大于 1，以确定是否存在有效分区。 

## 解决方案```go
package main

func gcd(a, b int) int {
    for b != 0 {
        a, b = b, a % b
    }
    return a
}

func hasGroupsSizeX(deck []int) bool {
    if len(deck) == 0 {
        return false
    }
    
    countMap := make(map[int]int)
    for _, card := range deck {
        countMap[card]++
    }
    
    var deckGCD int
    first := true
    for _, c := range countMap {
        if first {
            deckGCD = c
            first = false
        } else {
            deckGCD = gcd(deckGCD, c)
        }
    }
    
    return deckGCD > 1
}
```在 Go 中，我们实现了一个`gcd`手动函数，因为标准库没有提供整数函数。 我们使用映射来计算出现次数并迭代计算 GCD。 

## 工作示例

 **示例1：**`deck = [1,2,3,4,4,3,2,1]`计算卡片出现次数：

 | 卡| 计数|
 | ---| ---|
 | 1 | 2 |
 | 2 | 2 |
 | 3 | 2 |
 | 4 | 2 |

 计数的 GCD：`gcd(2, 2, 2, 2) = 2`由于 2 > 1，返回`true`。 

**示例2：**`deck = [1,1,1,2,2,2,3,3]`计算卡片出现次数：

 | 卡| 计数|
 | ---| ---|
 | 1 | 3 |
 | 2 | 3 |
 | 3 | 2 |

 计数的 GCD：`gcd(3, 3, 2) = 1`由于 1 ≤ 1，返回`false`。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(N) | 计算出现次数的时间复杂度为 O(N)，计算最多 N 次计数的 GCD 为 O(N) |
 | 空间| O(N) | 在最坏的情况下，将计数存储在哈希映射中需要 O(N) 空间 |

 时间复杂度是线性的，因为每张卡都被处理一次进行计数，并且每次计数都参与 GCD 计算。 由于将计数存储在字典中，空间复杂度是线性的。

 ## 边缘情况

 关键的边缘情况是一副只有一张牌的牌。 由于有效的组需要多张卡，因此解决方案正确返回`false`不尝试 GCD 计算。 

另一种边缘情况涉及质数计数。 例如，`[1,1,1,2,2,2,3,3,3]`结果计数`[3,3,3]`GCD 3，所以它返回`true`。 这突出表明，如果质数相等，它们仍然有效。 

当计数变化并且共享的公约数不大于 1 时，就会出现第三种边缘情况。 例如，`[1,1,2,2,2,3,3,3,3]`有计数`[2,3,4]`GCD 1. 解必须返回`false`因为没有组大小 >1 可以除以所有计数。 此案例证明了使用 GCD 而不是尝试任意组大小的重要性。
