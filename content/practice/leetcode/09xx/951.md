 # LeetCode 951 - 翻转等效二叉树

 ## 问题理解

 这个问题要求我们确定是否可以通过执行称为翻转的特殊操作使两个二叉树相同。 翻转操作可以应用于任何节点，它只是交换该节点的左右子子树。 

重要的细节是我们可以在树中的任何节点上执行此操作任意次数。 如果存在某种将一棵树转换为另一棵树的翻转序列，则认为两棵树翻转等效。 

输入由两个二叉树根组成，`root1`和`root2`。 每个树节点都包含一个整数值以及对左子节点和右子节点的引用。 输出应该是`true`如果树是翻转等价的，否则`false`。 

限制相对较小。 每棵树最多包含 100 个节点，并且所有节点值在树中都是唯一的。 唯一性属性非常重要，因为它意味着在比较节点时，匹配值明确地标识相应的位置。 由于树很小，递归深度优先遍历是完全实用的。 

立即识别几个边缘情况非常重要。 如果两棵树都是空的，那么它们基本上是等价的。 如果一棵树是空的而另一棵不是空的，则它们不能等价。 如果两个对应的节点具有不同的值，则无论进行多少翻转都无法使它们匹配。 当一个子树必须正常匹配而另一个子树必须在翻转后匹配时，会发生另一种微妙的情况。 在这种情况下，仅按固定的从左到右顺序检查子级的简单比较将失败。 

## 方法

 ### 蛮力方法

 暴力解决方案会尝试所有可能的翻转组合。 在每个节点，我们有两种选择：要么翻转子节点，要么保持不变。 我们可以递归地生成第一棵树的所有可能的转换版本，并将每个版本与第二棵树进行比较。 

这种方法是正确的，因为它明确地探索了通过翻转可以获得的每种可能的排列。 如果任何转换后的版本与第二棵树完全匹配，则这些树是翻转等效的。 

然而，这种方法效率极低。 对于一棵树来说`n`节点，每个节点可能使配置数量增加一倍。 在最坏的情况下，这会产生`O(2^n)`可能的树结构。 即使只有 100 个节点，这在计算上也是不可行的。 

### 最佳深度优先搜索方法

 关键的观察是我们不需要显式地生成每个可能的翻转树。 相反，我们可以递归地比较树，同时考虑每个节点的两种可能的匹配配置。 

假设我们正在比较节点`a`和`b`。 

它们的子树只有两种有效的匹配方式：

 1. 不带翻转：

 -`a.left`比赛`b.left`-`a.right`比赛`b.right`2. 翻转：

 -`a.left`比赛`b.right`-`a.right`比赛`b.left`如果任一配置递归成功，则当前节点对翻转等效。 

这种方法完全避免了构建转换树。 相反，它通过递归结构匹配直接验证等效性。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 尝试每一种可能的翻转组合 |
 | 最优 DFS | O(n) | O(h) | 递归地检查两种匹配的可能性 |

 这里，`n`是节点数，`h`是树的高度。 

## 算法演练

 1. 首先比较两棵树的当前节点。 

如果两个节点都是`None`，它们是等价的，因为两棵空树完美匹配。 
2. 检查是否正好有一个节点`None`。 

如果一个节点存在而另一个节点不存在，则树无法匹配，因此返回`false`。 
3. 比较节点值。 

如果值不同，则任何翻转序列都不能使节点相等，因此返回`false`。 
4. 递归检查非翻转配置。 

比较：

-`root1.left`和`root2.left`-`root1.right`和`root2.right`如果两个递归比较都返回`true`，则子树无需翻转即可匹配。 
5. 递归检查翻转后的配置。 

比较：

-`root1.left`和`root2.right`-`root1.right`和`root2.left`如果两个递归比较都返回`true`，那么翻转后子树就匹配了。 
6. 返回`true`如果任一配置成功。 

如果两种配置都不起作用，则树不是翻转等效的。 

### 为什么它有效

 在每个节点，子节点之间只有两种可能的有效对齐方式：要么它们已经按顺序匹配，要么在左右交换后匹配。 递归算法详尽地检查每个节点的两种可能性。 由于每个子树必须递归地满足相同的属性，因此算法正确地确定整个树是否翻转等价。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional

class Solution:
    def flipEquiv(
        self,
        root1: Optional[TreeNode],
        root2: Optional[TreeNode]
    ) -> bool:
        
        # Both nodes are empty
        if not root1 and not root2:
            return True

        # One node is empty
        if not root1 or not root2:
            return False

        # Values must match
        if root1.val != root2.val:
            return False

        # Check without flipping
        no_flip = (
            self.flipEquiv(root1.left, root2.left) and
            self.flipEquiv(root1.right, root2.right)
        )

        # Check with flipping
        flip = (
            self.flipEquiv(root1.left, root2.right) and
            self.flipEquiv(root1.right, root2.left)
        )

        return no_flip or flip
```该实现直接反映了算法演练中的递归推理。 

第一部分处理基本情况。 如果两个节点都是`None`，它们是等价的。 如果只有一个节点`None`，等价是不可能的。 

接下来，比较节点值。 由于节点值是唯一的，不同的值会立即使等效性失效。 

然后该算法计算两个递归条件。 这`no_flip`条件检查孩子们是否在原来的位置上匹配。 这`flip`条件检查交换位置后子级是否匹配。 

最后该方法返回`True`如果任一递归配置成功。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */

func flipEquiv(root1 *TreeNode, root2 *TreeNode) bool {

    // Both nodes are nil
    if root1 == nil && root2 == nil {
        return true
    }

    // One node is nil
    if root1 == nil || root2 == nil {
        return false
    }

    // Values must match
    if root1.Val != root2.Val {
        return false
    }

    // Check without flipping
    noFlip := flipEquiv(root1.Left, root2.Left) &&
        flipEquiv(root1.Right, root2.Right)

    // Check with flipping
    flip := flipEquiv(root1.Left, root2.Right) &&
        flipEquiv(root1.Right, root2.Left)

    return noFlip || flip
}
```Go 实现遵循与 Python 版本完全相同的递归结构。 

主要的语言特定差异是使用`nil`而不是`None`。 Go 还使用带有大写名称的结构字段访问，例​​如`Val`,`Left`， 和`Right`。 

由于节点值是小整数，并且递归深度最多限制为 100 个节点，因此 Go 中不存在整数溢出或递归深度问题。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个节点对都被递归处理 |
 | 空间| O(h) | 递归调用堆栈取决于树的高度 |

 该算法递归地访问相应的节点。 由于除了递归调用之外，每个节点比较都执行恒定的工作，因此总运行时间与节点数量呈线性关系。 

空间复杂度来自递归深度。 在完全倾斜的树的最坏情况下，递归堆栈可以增长到`O(n)`。 在平衡树中，递归深度为`O(log n)`。

 ## 边缘情况

 当两棵树都为空时，就会出现一种重要的边缘情况。 粗心的实现可能会错误地返回`false`因为没有可以比较的节点。 正确的行为是返回`true`，因为两棵空树在结构上是相同的。 该实现立即使用第一个基本情况来处理这个问题。 

另一个重要的情况是当恰好有一个节点是`None`。 这种情况可能发生在递归的任何深度。 如果一棵子树存在而另一棵不存在，则无法通过翻转使两棵树等价，因为翻转仅交换现有子树。 实现在继续递归之前显式检查此条件。 

当子级仅在翻转后匹配时，会出现第三种微妙的边缘情况。 例如，一棵树可以将子项存储为`(2, 3)`而其他商店`(3, 2)`。 仅比较从左到左和从右到右的简单算法将错误地返回`false`。 该实现通过递归检查正常配置和翻转配置来避免此问题。 

最后一个重要的案例涉及深度嵌套的翻转。 有些树需要多个级别的翻转，而不仅仅是根部。 递归结构自然地处理这个问题，因为每个子树独立地检查两种可能的对齐方式。 即使对于复杂的嵌套转换，这也确保了正确性。
