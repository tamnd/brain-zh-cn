[LeetCode 911 题](https://leetcode.com/problems/online-election/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、二分搜索、设计

 ## 解决方案

 ## 问题理解

 问题是要求我们设计一种数据结构，能够在任何给定时间有效地回答有关选举领导者的查询。 我们有两个整数数组，`persons`和`times`。 这`persons`数组表示投票的顺序，其中`persons[i]`是收到的候选人`i`第 次投票。 这`times`数组代表每次投票发生的时间，这样`times[i]`是的时间`i`第 次投票。 

如有时间查询`t`，我们需要确定哪位候选人在当时获得最多选票。 如果多名候选人在最高票数上并列，则并列候选人中最新的投票决定领先者。 该解决方案必须有效支持多个查询，因为多达 10,000 次调用`q(t)`可能会被制作。 

约束告诉我们输入数组相对较小（`persons.length`≤ 5000），但查询数量可能很大。 这`times`数组是严格递增的，这使得我们能够使用二分搜索有效地搜索相关的投票数。 

要考虑的边缘情况包括第一次投票之前发生的查询、恰好在投票时间发生的查询以及多个候选人票数相同但最近的投票决定获胜者的情况。 

## 方法

 暴力解决方案将通过迭代所有投票来评估每个查询`t`并统计每位候选人的选票。 虽然这会给出正确的结果，但对于重复查询来说效率很低，因为为每个查询计算投票需要 O(n) 时间。 假设最多 10,000 个查询，这种方法在最坏的情况下可能会导致 50,000,000 次操作，这太慢了。 

最佳解决方案的关键在于我们可以在每次投票后预先计算领导者。 一旦我们知道每次投票时间的领导者，任何查询都会简化为简单搜索当时或之前的最新投票`t`。 自从`times`排序后，我们可以使用二分查找来高效地找到正确的索引。 预计算领导者允许每个查询在 O(log n) 时间内运行。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * q) | O(n) | 分别计算每个查询的票数 |
 | 最佳 | O(n + q * log n) | O(n + q * log n) | O(n) | 预计算leader数组，使用二分搜索进行查询 |

 ## 算法演练

 1.初始化一个字典（哈希图）`vote_count`跟踪每个候选人的票数。 
2.初始化一个空列表`leaders`每次投票后存储领导者。 
3. 初始化变量`current_leader`跟踪迄今为止得票最多的候选人。 
4. 迭代每个投票`persons`数组：

 - 增加当前候选人的得票数`vote_count`。 
- 如果当前候选人的票数大于或等于当前领导者的票数，则更新`current_leader`给当前的候选人。 这通过优先考虑最近的投票来处理关系。 
- 追加`current_leader`到`leaders`列表。 
5. 回答询问`q(t)`:

 - 使用二分查找`times`查找数组中最大的索引`i`这样`times[i] ≤ t`。 
- 返回`leaders[i]`。 

工作原理：通过在每个投票时间预先计算领导者并按顺序存储它，我们确保可以通过查找与查询时或之前的最接近投票时间相对应的领导者来回答任何查询。 每当候选人达到与当前领导者相同的票数时，自然会通过更新领导者来处理平局打破规则。 

## Python 解决方案```python
from typing import List
import bisect

class TopVotedCandidate:

    def __init__(self, persons: List[int], times: List[int]):
        self.times = times
        self.leaders = []
        self.vote_count = {}
        current_leader = -1
        max_votes = 0

        for i, person in enumerate(persons):
            self.vote_count[person] = self.vote_count.get(person, 0) + 1
            if self.vote_count[person] >= max_votes:
                if person != current_leader:
                    current_leader = person
                max_votes = self.vote_count[person]
            self.leaders.append(current_leader)

    def q(self, t: int) -> int:
        # Find rightmost time <= t using bisect
        index = bisect.bisect_right(self.times, t) - 1
        return self.leaders[index]
```Python 实现维护每个候选人的投票计数，每次投票后更新当前领导者，并预先计算领导者数组。 使用二分搜索回答查询（`bisect_right`）以有效地查找查询时间或之前的最新投票。 

## 解决方案```go
package main

import "sort"

type TopVotedCandidate struct {
	times   []int
	leaders []int
}

func Constructor(persons []int, times []int) TopVotedCandidate {
	voteCount := make(map[int]int)
	leaders := make([]int, len(persons))
	currentLeader := -1
	maxVotes := 0

	for i, person := range persons {
		voteCount[person]++
		if voteCount[person] >= maxVotes {
			if person != currentLeader {
				currentLeader = person
			}
			maxVotes = voteCount[person]
		}
		leaders[i] = currentLeader
	}

	return TopVotedCandidate{
		times:   times,
		leaders: leaders,
	}
}

func (this *TopVotedCandidate) Q(t int) int {
	index := sort.Search(len(this.times), func(i int) bool {
		return this.times[i] > t
	})
	return this.leaders[index-1]
}
```Go 实现遵循与 Python 相同的逻辑。 它使用`sort.Search`对于二分查找，返回条件为真的第一个索引。 我们减去 1 得到最大时间小于或等于`t`。 地图有效地处理投票计数，切片存储领导者历史记录。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n + q * log n) | O(n + q * log n) | 预先计算 O(n) 中的领导者，每个查询都使用二分搜索 O(log n) |
 | 空间| O(n) | 店铺`leaders`数组和`vote_count`字典 |

 原因是计算投票数和领导者数组与投票数呈线性关系。 查询是独立的，并使用二分搜索，使其投票数呈对数。
