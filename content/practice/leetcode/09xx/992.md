[LeetCode 992 题](https://leetcode.com/problems/subarrays-with-k- Different-integers/)

 **难度：** 🔴难
 **主题：** 数组、哈希表、滑动窗口、计数

 ## 解决方案

 ## 问题理解

 该问题要求我们计算有多少个连续子数组恰好包含`k`不同的整数。 

我们得到：

 - 整数数组`nums`- 一个整数`k`子数组是数组的任何连续部分。 对于每个可能的子数组，我们需要确定它是否恰好包含`k`独特的价值观。 如果有的话，就有贡献`1`到答案。 

例如，在：```
nums = [1,2,1,2,3], k = 2
```子数组`[1,2,1]`有效，因为它恰好包含两个不同的整数，`1`和`2`。 

然而：

-`[1,2,1,2,3]`无效，因为它包含三个不同的整数
 -`[1]`无效，因为它只包含一个不同的整数

 约束条件很重要：

 -`nums.length`可以大到`2 * 10^4`- 如果需要重复重新计算不同的计数，则单独检查每个子数组的强力解决方案会太慢

 由于可能的子数组的数量是`O(n²)`，我们需要比二次时间更好的东西。 

一些边缘情况很重要：

 - 所有元素都相同的数组
 - 每个元素都是唯一的数组
 -`k = 1`-`k = nums.length`- 非常小的阵列
 - 扩展窗口频繁超过的情况`k`独特的价值观

 这些情况可能会暴露窗口缩小逻辑或频率计数中的错误。 

## 方法

 ### 蛮力方法

 最直接的解决方案是生成每个可能的子数组并计算它包含多少个不同的整数。 

对于每个起始索引`i`，我们将子数组扩展到每个结束索引`j`。 在扩展时，我们维护一个集合或频率图来跟踪不同的元素。 

每当不同元素的数量恰好变为`k`，我们增加答案。 

这种方法是正确的，因为它显式检查每个子数组。 不会遗漏任何内容，并且会计算每个有效的子数组。 

但时间复杂度太大。 有`O(n²)`子数组，虽然保持频率可以使每次扩展变得高效，但总运行时间仍然是二次的。 

和`n = 20000`， 一个`O(n²)`解决方案不切实际。 

### 最优方法，最多 K 个不同的滑动窗口

 关键的见解是精确地计算子数组`k`直接计算不同的整数是很困难的，但是计算最多具有的子数组`k`不同的整数要容易得多。 

我们使用身份：```
exactly(k) = atMost(k) - atMost(k - 1)
```为什么这有效？ 

-`atMost(k)`计算包含最多的所有子数组`k`不同的整数
 -`atMost(k - 1)`计算包含少于的所有子数组`k`不同的整数
 - 它们的差异只留下完全包含的子数组`k`不同的整数

 滑动窗口技术对于`atMost(k)`计算因为：

 - 我们展开右指针
 - 每当不同的值超过时，我们就会缩小左指针`k`- 在每个位置，我们可以计算有多少个有效子数组以当前右侧索引结尾

 这将问题转化为线性时间解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 枚举每个子数组 |
 | 最佳 | O(n) | O(n) | 使用 atMost(k) 技巧的滑动窗口 |

 ## 算法演练

 我们首先定义一个辅助函数：```
countAtMost(k)
```该函数返回最多包含的子数组的数量`k`不同的整数。 

然后：```
answer = countAtMost(k) - countAtMost(k - 1)
```### 逐步过程

 1. 初始化滑动窗口。 

我们维持：

 -`left`指针
 -`right`指针
 - 频率图
 - 不同整数的数量

 窗口始终代表一个有效的子数组，最多包含`k`不同的整数。 
2. 通过移动扩大窗口`right`。 

对于每个新元素：

 - 将其添加到频率图
 - 如果其频率变为`1`，我们发现了一个新的不同整数
 3. 如果不同的整数超过`k`，缩小窗口。 

虽然不同计数大于`k`：

- 消除`nums[left]`- 降低其频率
 - 如果频率变为`0`，删除该不同的整数
 - 移动`left`前进
 4. 计算以 结尾的有效子数组`right`。 

一旦窗口再次有效：```
window length = right - left + 1
```每个子数组结束于`right`并从之间的任意位置开始`left`和`right`是有效的。 

所以：```
result += right - left + 1
```5. 重复此操作，直至处理完整个数组。 
6. 计算：```
exactly(k) = atMost(k) - atMost(k - 1)
```### 为什么它有效

 滑动窗口始终保持当前窗口最多包含的不变量`k`不同的整数。 

对于每个职位`right`，所有以`right`并开始之间`left`和`right`是有效的。 由于缩小后窗口最小，因此每个较短的后缀也是有效的。 

减法`atMost(k - 1)`删除所有小于的子数组`k`不同的整数，只留下那些完全一致的整数`k`。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def subarraysWithKDistinct(self, nums: List[int], k: int) -> int:
        
        def count_at_most(max_distinct: int) -> int:
            left = 0
            result = 0
            
            frequency = defaultdict(int)
            distinct_count = 0
            
            for right in range(len(nums)):
                value = nums[right]
                
                if frequency[value] == 0:
                    distinct_count += 1
                
                frequency[value] += 1
                
                while distinct_count > max_distinct:
                    left_value = nums[left]
                    
                    frequency[left_value] -= 1
                    
                    if frequency[left_value] == 0:
                        distinct_count -= 1
                    
                    left += 1
                
                result += right - left + 1
            
            return result
        
        return count_at_most(k) - count_at_most(k - 1)
```该实现遵循前面描述的确切算法。 

辅助函数`count_at_most()`执行滑动窗口逻辑。 这`frequency`map 跟踪每个整数在当前窗口中出现的次数。 

每当一个新的不同整数进入窗口时，`distinct_count`增加。 如果窗口变得无效，这意味着不同的整数超出了允许的限制，我们会反复缩小左边界，直到恢复约束。 

关键的计数步骤是：```python
result += right - left + 1
```这是有效的，因为有效窗口的每个后缀都以`right`也是有效的。 

最后，main方法应用公式：```python
count_at_most(k) - count_at_most(k - 1)
```隔离恰好包含的子数组`k`不同的整数。 

## 解决方案```go
func subarraysWithKDistinct(nums []int, k int) int {

	countAtMost := func(maxDistinct int) int {
		left := 0
		result := 0

		frequency := make(map[int]int)
		distinctCount := 0

		for right := 0; right < len(nums); right++ {
			value := nums[right]

			if frequency[value] == 0 {
				distinctCount++
			}

			frequency[value]++

			for distinctCount > maxDistinct {
				leftValue := nums[left]

				frequency[leftValue]--

				if frequency[leftValue] == 0 {
					distinctCount--
				}

				left++
			}

			result += right - left + 1
		}

		return result
	}

	return countAtMost(k) - countAtMost(k-1)
}
```Go 的实现与 Python 版本非常相似。 

而不是Python的`defaultdict`，Go 使用标准映射：```go
frequency := make(map[int]int)
```Go 映射会针对缺失的键返回零值，这使得频率跟踪变得简单。 

不需要对 nil 或空切片进行特殊处理，因为约束保证至少有一个元素。 整数溢出也不是问题，因为对于给定的约束，子数组的最大数量在 Go 的标准整数范围内。

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个指针最多移动n次|
 | 空间| O(n) | 频率图最多可以存储 n 个不同的整数 |

 滑动窗口是高效的，因为每个元素最多进入和离开窗口一次。 

虽然有嵌套`while`循环中，左指针在整个执行过程中仅向前移动。 这意味着左指针移动的总数受以下限制：`n`。 

频率图存储当前窗口内不同整数的计数。 在最坏的情况下，所有元素都是唯一的，需要`O(n)`额外的空间。

 ## 边缘情况

 当所有元素都相同时，就会出现一种重要的边缘情况。 

例如：```
nums = [1,1,1,1]
k = 1
```每个可能的子数组都是有效的，因为每个子数组都包含一个不同的整数。 当重复出现时，有缺陷的实现可能会错误地缩小窗口或错误地处理频率计数。 滑动窗口自然地处理这个问题，因为不同的计数永远不会超过`1`。 

另一个重要的情况是每个元素都是唯一的。 

例如：```
nums = [1,2,3,4]
k = 4
```只有整个数组才有效。 这测试实现是否正确处理最大可能的不同计数。 频率图变大`4`，并且该算法正确地识别出一个有效的子数组。 

第三个棘手的情况发生在`k = 1`。 

在这种情况下，只有包含相同数字的重复副本的子数组才有效。 许多实现在这里失败是因为：```
exactly(1) = atMost(1) - atMost(0)
```需要辅助函数来正确处理`max_distinct = 0`。 此实现中的收缩逻辑可以安全地减小窗口，直到它包含零个不同的整数，从而确保正确性。 

另一个微妙的边缘情况涉及频繁的窗口扩展和收缩。 

例如：```
nums = [1,2,1,3,4]
k = 2
```窗口反复超出明显的限制，必须缩小几次。 不正确的指针移动或频率更新很容易产生相差一的错误。 该实现保持了严格的不变量，即窗口始终最多包含`k`收缩后的整数不同，保证计数准确。
