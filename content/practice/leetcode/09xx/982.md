[LeetCode 982 题](https://leetcode.com/problems/triples-with-bitwise-and-equal-to-zero/)

 **难度：** 🔴难
 **主题：** 数组、哈希表、位操作

 ## 解决方案

 ## 问题理解

 这道题要求我们计算三元组的数量`(i, j, k)`来自整数数组`nums`such that the bitwise AND of the three numbers at these indices equals zero. 换句话说，我们想要所有组合`nums[i] & nums[j] & nums[k] == 0`。 

输入是一个整数数组，其中每个元素的范围为`0`到`2^16 - 1`（即 0 到 65535），数组长度最大为 1000。输出是一个整数，表示有效三元组的数量。 

要考虑的边缘情况包括仅包含零的数组、具有最大值的数组或具有重复元素的数组。 由于潜在的组合数量，天真的实现可能会很困难 - 对于`n = 1000`，一个简单的三重嵌套循环将导致十亿次迭代，这是不可行的。 

## 方法

 蛮力方法迭代所有可能的三元组`(i, j, k)`使用三个嵌套循环。 对于每个三元组，它计算按位与并检查它是否等于零。 虽然这种方法简单且正确，但它的立方时间复杂度为`O(n^3)`，这对于`n = 1000`。 

最佳方法依赖于按位 AND 是结合性和交换性的观察。 我们可以预先计算所有可能的对`(i, j)`并将它们的 AND 结果的频率存储在哈希图中。 对于每个数字`nums[k]`，然后我们可以迭代该映射的键并检查是否`key & nums[k] == 0`。 如果是这样，我们将地图中的计数添加到结果中。 这显着降低了时间复杂度，因为我们避免直接迭代所有三元组。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n^3) | O(n^3) | O(1) | O(1) | 所有元素的三重嵌套循环 |
 | 最佳 | 最坏情况下为 O(n^2 * 2^16) | O(2^16) | O(2^16) | 预先计算成对 AND 并使用哈希映射进行计数 |

 ## 算法演练

 1. 初始化一个哈希图来存储所有对的AND结果的频率`(nums[i] & nums[j])`。 
2. 迭代每一对`(i, j)`在数组中并计算`nums[i] & nums[j]`。 增加哈希图中该值的频率。 
3. 初始化变量`result`为零以存储有效三元组的计数。 
4. 迭代每个数字`nums[k]`在数组中。 对于哈希映射中的每个键，检查是否`key & nums[k] == 0`。 如果为 true，则将地图中相应的频率添加到`result`。 
5. 返回`result`。 

**为什么有效：** 预先计算成对 AND 并计算它们的频率可确保对于每个潜在的第三个元素，我们有效地对所有与它进行 AND 运算时将产生零的对进行求和。 这避免了对所有三元组的三次迭代。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def countTriplets(self, nums: List[int]) -> int:
        pair_count = defaultdict(int)
        
        # Count all pairwise AND results
        for i in nums:
            for j in nums:
                pair_count[i & j] += 1
        
        result = 0
        
        # For each number, sum all pair counts that AND to 0 with it
        for num in nums:
            for key, count in pair_count.items():
                if key & num == 0:
                    result += count
        
        return result
```**说明：** 我们首先建立一个字典`pair_count`存储每个 AND 结果在所有对中出现的次数。 然后，对于数组中的每个数字，我们迭代字典中的所有键，并检查与该数字进行 AND 运算是否给出零。 所有这些计数的总和就是我们的最终结果。 

## 解决方案```go
func countTriplets(nums []int) int {
    pairCount := make(map[int]int)
    
    for _, i := range nums {
        for _, j := range nums {
            pairCount[i & j]++
        }
    }
    
    result := 0
    for _, num := range nums {
        for key, count := range pairCount {
            if key & num == 0 {
                result += count
            }
        }
    }
    
    return result
}
```**说明：** Go 实现镜像了 Python 解决方案。 我们使用地图`pairCount`跟踪成对的 AND 频率。 与 Python 不同，Go 需要显式初始化映射。 迭代和加法的处理方式相同。 

## 工作示例

 **示例1：**`nums = [2,1,3]`1. 计算成对 AND：

 - 2&2=2、2&1=0、2&3=2、1&2=0、1&1=1、1&3=1、3&2=2、3&1=1、3&3=3
 -`pair_count`= {2:3, 0:2, 1:3, 3:1}
 2. 对于每个数字：

 - num=2 → 与 2 相与得到 0 的键 → key=0 → 将 2 添加到结果中
 - num=1 → 与 1 相与得到 0 的键 → key=0 → 将 2 添加到结果中
 - num=3 → 与 3 AND 得到 0 的键 → key=0 → 将 2 添加到结果中
 3. 继续所有键→最终`result = 12`**示例2：**`nums = [0,0,0]`1. 所有成对 AND = 0 →`pair_count = {0:9}`2. 每个数字与 0 = 0 → 3 个数字每次加 9 →`result = 27`## 复杂度分析

 ## 边缘情况

 **单元素数组：** 单元素数组仍然形成重复的三元组`(i,j,k)`如果数字为 0，则全部等于 0。该实现可以正确处理重复的索引。 

**全零数组：** 每个索引组合都会产生零，从而导致`n^3`三倍。 我们的算法使用预先计算的配对图有效地处理这个问题。 

**具有最大数量的数组：** 元素等于`2^16 - 1`AND 运算时很少会产生零。 该算法通过检查正确排除这些对`key & num == 0`在最后的积累过程中。 

这些边缘情况确保算法正确处理小输入、重复零和最大边界值，而不会出现错误或过度计数。
