[LeetCode 第 927 题](https://leetcode.com/problems/ Three-equal-parts/)

 **难度：** 🔴难
 **主题：** 数组、数学

 ## 解决方案

 ## 问题理解

 该问题要求我们对二进制数组进行分区`arr`分成三个非空连续段，使得每个段在解释为二进制数（允许前导零）时等于其他两个段。 该数组仅包含零和一，目标是返回索引`[i, j]`在哪里`i + 1 < j`这样第一段是`arr[0..i]`，第二段是`arr[i+1..j-1]`，第三段是`arr[j..n-1]`。 如果不存在这样的分区，我们返回`[-1, -1]`。 

约束条件告诉我们`arr`最多可以有 30,000 个元素，因此任何尝试简单地检查所有可能分区的解决方案都会太慢。 允许使用前导零，这意味着像`[0,1,1]`和`[1,1]`被视为价值相等。 这很重要，因为它会影响我们比较细分的方式。 边缘情况包括全为零的数组、多个 1 不能被 3 整除的数组，以及唯一有效的分割需要精确对齐 1 的数组。 

## 方法

 暴力方法会考虑每一个可能的对`(i, j)`满足`i + 1 < j`，将每个段转换为其十进制或二进制字符串表示形式，并对它们进行比较。 这是正确的，但不可行，因为有 O(n^2) 对，每次比较需要 O(n) 工作，导致时间复杂度为 O(n^3)。 考虑到最多 30,000 个元素的限制，这太慢了。 

最佳解决方案的关键观察是，段的二进制值由其位置确定，前导零并不重要。 因此，如果总数为`arr`能被三整除，每个部分必须恰好包含`total_ones / 3`那些。 这使我们可以通过计数直接找到每个部分的开始和结束索引。 一旦我们知道从每个部分的第一个部分开始到最后一个部分结束的段，我们就可以逐个元素地比较这些段。 我们还考虑了最后一段的最后一个后面的尾随零，以确保对齐。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n^3) | O(n^3) | O(n) | 检查所有可能的分区，将每个分区转换为整数或字符串，然后比较 |
 | 最佳| O(n) | O(1) | O(1) | 计算个数，按个数位置识别段，仅比较必要的元素 |

 ## 算法演练

 1. 计算 1 的总数`arr`。 如果不能被3整除，则立即返回`[-1, -1]`因为相等的二进制部分是不可能的。 
2.如果`total_ones`为零，每个段都为零，所以返回`[0, n-1]`就像任何拆分一样。 
3. 计算`ones_per_part = total_ones / 3`。 这告诉我们每个段中必须有多少个。 
4. 通过扫描数组来识别三个段中每个段中第一个和最后一个的索引。 例如，第一段从第一个开始，到第一个结束`ones_per_part`-第一个。 
5. 逐个比较三个段以验证它们是否相同（考虑到尾随零）。 如果出现任何不匹配的情况，则返回`[-1, -1]`。 
6. 如果段匹配，则计算索引`i`和`j`作为第一段的结尾和第三段的开头减一，根据对齐段所需的尾随零的数量进行调整。 
7. 返回`[i, j]`作为有效分区。 

工作原理：每个段必须包含相同数量的 1，并且尾随位置中 1 和 0 的序列必须匹配。 通过使用每个段中的第一个和最后一个对齐段并验证相等性，我们保证二进制值相同，这满足了问题要求。 

## Python 解决方案```python
from typing import List

class Solution:
    def threeEqualParts(self, arr: List[int]) -> List[int]:
        total_ones = sum(arr)
        if total_ones % 3 != 0:
            return [-1, -1]
        if total_ones == 0:
            return [0, len(arr) - 1]

        ones_per_part = total_ones // 3
        first = second = third = 0
        ones_count = 0

        for i, val in enumerate(arr):
            if val == 1:
                ones_count += 1
                if ones_count == 1:
                    first = i
                elif ones_count == ones_per_part + 1:
                    second = i
                elif ones_count == 2 * ones_per_part + 1:
                    third = i

        n = len(arr)
        length = n - third
        if arr[first:first + length] != arr[second:second + length] or arr[first:first + length] != arr[third:]:
            return [-1, -1]

        return [first + length - 1, second + length]
```该实现首先计算 1 的总数并处理零和不可整除的情况。 然后根据个数确定这三个部分的起始索引。 要检查的每个段的长度由数组末尾的尾随零确定。 Finally, the equality check is done slice by slice, and the indices are returned.

 ## 解决方案```go
func threeEqualParts(arr []int) []int {
    totalOnes := 0
    for _, val := range arr {
        totalOnes += val
    }
    if totalOnes%3 != 0 {
        return []int{-1, -1}
    }
    if totalOnes == 0 {
        return []int{0, len(arr) - 1}
    }

    onesPerPart := totalOnes / 3
    n := len(arr)
    first, second, third := 0, 0, 0
    onesCount := 0

    for i, val := range arr {
        if val == 1 {
            onesCount++
            if onesCount == 1 {
                first = i
            } else if onesCount == onesPerPart+1 {
                second = i
            } else if onesCount == 2*onesPerPart+1 {
                third = i
            }
        }
    }

    length := n - third
    for i := 0; i < length; i++ {
        if arr[first+i] != arr[second+i] || arr[first+i] != arr[third+i] {
            return []int{-1, -1}
        }
    }

    return []int{first + length - 1, second + length}
}
```Go 版本与 Python 版本非常相似。 切片用于通过循环而不是切片相等进行比较。 Go 特定的考虑因素包括显式处理切片和安全地使用整数算术。 

## 工作示例

 示例1：`[1,0,1,0,1]`

`total_ones = 3`,`ones_per_part = 1`。 第一个是索引`[0, 2, 4]`。 各部分长度为`n - third = 5 - 4 = 1`。 切片`[0:1]`,`[2:3]`,`[4:5]`一切平等`[1]`。 返回`[0,3]`。 

示例2：`[1,1,0,1,1]`

`total_ones = 4`，不能被 3 整除。返回`[-1,-1]`。 

示例3：`[1,1,0,0,1]`

`total_ones = 3`,`ones_per_part = 1`。 第一个位于`[0,1,4]`。 长度`5-4 = 1`。 切片`[0:1]=[1]`,`[1:2]=[1]`,`[4:5]=[1]`匹配。 返回`[0,2]`。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 我们最多扫描数组两次：一次是为了计数，一次是为了比较段 |
 | 空间| O(1) | O(1) | 仅使用了几个整数变量，没有与输入成比例的额外数组 |

 推理：计数和确定起始索引是线性的。 切片比较仅覆盖必要的尾随序列，而不是整个数组，因此总工作量为 O(n)。
