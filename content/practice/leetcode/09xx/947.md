[LeetCode 947 题](https://leetcode.com/problems/most-stones-removed-with-same-row-or-column/)

 **难度：** 🟡 中等
 **主题：** 哈希表、深度优先搜索、并查找、图论

 ## 解决方案

 ## 问题理解

 该问题为我们提供了放置在二维网格上的石头集合。 每块石头都有一个独特的坐标`(x, y)`。 只有当至少有一颗其他石子共享同一行或同一列时，才能移除该石子。 

目标是确定可以移除的最大石子数量，同时在每一步仍遵守此规则。 

关键的观察结果是，如果石头变得孤立，则无法将其移除，这意味着没有剩余的石头共享其行或列。 因此，每一组相连的石头都必须留下至少一块石头。 

我们可以将石头视为图中的节点：

 - 如果两块石头共享一行或一列，则它们是相连的。 
- 任何可以相互到达的石头都属于同一个连接的组件。 

在连接的组件内包含`k`石头，我们可以准确去除`k - 1`石头。 必须保留一颗棋子，因为最后一颗棋子在同一行或同一列中没有相邻的棋子。 

因此：

 - 如果有`n`总结石数
 - 以及`c`连接的组件

 那么答案是：$\text{Answer} = n - c$约束条件很重要：

 -`stones.length <= 1000`- 坐标的边界为`10^4`- 不存在重复的坐标

 由于最多有 1000 颗石头，`O(n^2)`宝石之间的比较是可以接受的。 这强烈表明图遍历或并查方法是可行的。 

一些边缘情况很重要：

 - 一块石头无法移除。 
- 多个断开连接的组每个都需要一颗剩余的石头。 
- 通过链条间接连接的石头仍然属于同一个组件。 
- 完全连接的行或柱结构可以移除除一颗石头之外的所有石头。 

## 方法

 ### 蛮力方法

 一种简单的方法是反复搜索可移动的石头并一一模拟移动。 

每一步：

 1. 扫描每块石头。 
2. 检查是否有其他棋子共享其行或列。 
3. 取出一颗这样的石头。 
4. 重复此操作，直至无法再进行删除。 

这是有效的，因为它直接遵循问题规则。 然而，它的效率很低，因为每次移除都可能需要重新扫描整个宝石集合。 在最坏的情况下，这会导致立方行为。 

更重要的是，关于要移除哪块石头的推理变得不必要地复杂。 该过程在很大程度上取决于连接性而不是确切的移除顺序。 

### 关键见解

 关键的观察结果是石头形成了连接的组件。 

如果两块石头共用一行或一列，则它们属于同一连通结构。 即使两块石头不直接共享一行或一列，它们仍然可以通过中间石头间接连接。 

例如：```
[0,0] -> [0,1] -> [1,1]
```第一块和第三块石头通过中间的石头连接起来。 

在任何连接的组件内：

 - 我们总是可以移走石头，直到只剩下一颗为止。 
- 因此，具有尺寸的组件`k`贡献`k - 1`可移动的石头。 

这将问题转化为：

 1. 求连通分量的数量。 
2. 从石子总数中减去该计数。 

我们可以使用以下任一方法有效地解决这个问题：

 - 深度优先搜索
 - 广度优先搜索
 - 并查

 在这里，我们将使用 Union-Find，因为它可以清晰地模拟连接性。

## 算法演练

 ### 最优并查算法

 1. 初始化并查结构，其中每块石头都从其自己的组件开始。 

最初，每个石头都是断开连接的，因此每个石头都是它自己的父代。 
2. 比较每对宝石。 

自从`n <= 1000`，检查所有对是可以接受的。 
3. 如果两颗棋子共用一行或一列，请将它们合并。 

如果满足以下条件，两块棋子属于同一连通分量：```
x1 == x2 OR y1 == y2
```Union-Find 有效地合并这些连接的组。 
4. 处理完所有对后，计算唯一根的数量。 

每个唯一的根代表一个连接的组件。 
5. 计算结果。 

如果有`components`连接的组和`n`总石数：$\text{Removable Stones} = n - \text{components}$### 为什么它有效

 每个连接的组件必须保留至少一块石头。 该组件中的所有其他石头最终都可以被移除，因为总会存在共享一行或一列的另一块石头，直到只剩下一个。 

并查正确识别所有连接的组件，包括间接连接。 因此，从棋子总数中减去连通分量的数量就可以得出可移动棋子的最大数量。 

## Python 解决方案```python
from typing import List

class Solution:
    def removeStones(self, stones: List[List[int]]) -> int:
        n = len(stones)

        parent = list(range(n))
        rank = [0] * n

        def find(x: int) -> int:
            if parent[x] != x:
                parent[x] = find(parent[x])
            return parent[x]

        def union(x: int, y: int) -> None:
            root_x = find(x)
            root_y = find(y)

            if root_x == root_y:
                return

            if rank[root_x] < rank[root_y]:
                parent[root_x] = root_y
            elif rank[root_x] > rank[root_y]:
                parent[root_y] = root_x
            else:
                parent[root_y] = root_x
                rank[root_x] += 1

        for i in range(n):
            for j in range(i + 1, n):
                if (
                    stones[i][0] == stones[j][0]
                    or stones[i][1] == stones[j][1]
                ):
                    union(i, j)

        components = set()

        for i in range(n):
            components.add(find(i))

        return n - len(components)
```实现首先初始化并查数据结构。 

这`parent`数组存储每个石头的代表父级。 最初，每块石头都指向自己。 这`rank`数组有助于在联合操作期间保持树浅。 

这`find`函数执行路径压缩。 每当我们搜索根时，我们都会通过直接将节点附加到其根父节点来展平结构。 这显着提高了效率。 

这`union`函数合并两个连接的组件。 按等级并集可确保较浅的树附加到较深的树下，从而最大限度地减少未来的查找成本。 

接下来，嵌套循环比较每对石头。 如果两个石头共享一行或一列，则它们属于同一个连通分量，因此我们将它们联合起来。 

最后，我们计算不同根的数量。 每个唯一的根对应于一个连接的组件。 

答案是石子总数减去成分数。 

## 解决方案```go
package main

func removeStones(stones [][]int) int {
	n := len(stones)

	parent := make([]int, n)
	rank := make([]int, n)

	for i := 0; i < n; i++ {
		parent[i] = i
	}

	var find func(int) int

	find = func(x int) int {
		if parent[x] != x {
			parent[x] = find(parent[x])
		}
		return parent[x]
	}

	union := func(x int, y int) {
		rootX := find(x)
		rootY := find(y)

		if rootX == rootY {
			return
		}

		if rank[rootX] < rank[rootY] {
			parent[rootX] = rootY
		} else if rank[rootX] > rank[rootY] {
			parent[rootY] = rootX
		} else {
			parent[rootY] = rootX
			rank[rootX]++
		}
	}

	for i := 0; i < n; i++ {
		for j := i + 1; j < n; j++ {
			if stones[i][0] == stones[j][0] ||
				stones[i][1] == stones[j][1] {
				union(i, j)
			}
		}
	}

	components := make(map[int]bool)

	for i := 0; i < n; i++ {
		root := find(i)
		components[root] = true
	}

	return n - len(components)
}
```Go 实现遵循与 Python 版本相同的并查策略。 

一个`map[int]bool`用于计算唯一的连通分量，因为 Go 没有内置的集合类型。 

递归`find`函数执行路径压缩的方式与 Python 版本完全相同。 

由于约束很小，因此不必担心整数溢出。 Go 切片自然地处理所需的动态数组`parent`和`rank`。

 ## 边缘情况

 一个非常重要的边缘情况是单颗宝石。 由于没有其他石头共享其行或列，因此无法将其移走。 有缺陷的实现可能会错误地假设每个组件都贡献可移动的石头。 我们的实现正确地计算了一个连接的组件并返回`1 - 1 = 0`。 

另一个重要的边缘情况是间接连接。 两个棋子可能不直接共享行或列，但仍然可以通过中间棋子属于同一个连通组件。 例如：```
[0,0] -> [0,1] -> [1,1]
```仅在删除推理期间检查直接邻居的简单实现可能会错过这种关系。 Union-Find 可以自然地处理这个问题，因为并集可以传递连接性。 

第三个重要的边缘情况是多个断开连接的组。 每个组件必须恰好留下一颗石头。 如果实现仅跟踪全局连接棋子的总数，则可能会过多计算可移动棋子。 通过显式计算唯一组件根，该解决方案可以正确地为每个连接的组件保留一颗石头。 

当许多石头共享同一行或同一列时，会出现第四种微妙的情况。 这可以通过多次重复的联合尝试创建密集连接。 如果没有路径压缩和按等级联合，性能可能会显着下降。 该实施通过优化并查操作避免了这个问题。
