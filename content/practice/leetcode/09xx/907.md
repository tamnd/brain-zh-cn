[LeetCode 问题 907](https://leetcode.com/problems/sum-of-subarray-minimums/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划、堆栈、单调堆栈

 ## 解决方案

 ## 问题理解

 该问题要求我们计算给定数组的每个可能的连续子数组的最小值之和。 

对于数组`arr`，数组的每个连续切片都被视为子数组。 对于每个子数组，我们确定其最小元素。 最终答案是所有这些最小值的总和。 

例如，如果数组是：```
[3,1,2]
```子数组是：```
[3]       minimum = 3
[1]       minimum = 1
[2]       minimum = 2
[3,1]     minimum = 1
[1,2]     minimum = 1
[3,1,2]   minimum = 1
```答案变成：```
3 + 1 + 2 + 1 + 1 + 1 = 9
```约束条件很重要：

 - 数组长度可以大到`3 * 10^4`- 每个值也可以大到`3 * 10^4`生成每个子数组并扫描其最小值的简单解决方案会太慢。 由于子数组的数量大约为`n^2`，天真地找到最小值需要另一个`O(n)`时间，总复杂度可能达到`O(n^3)`。 

即使是维持最低运行的优化蛮力解决方案仍然需要`O(n^2)`时间，对于`30,000`元素。 

该问题保证：

 - 数组非空
 - 所有值均为正整数
 - 结果可能会变得非常大，所以我们必须将其取模返回`10^9 + 7`重要的边缘情况包括：

 - 具有单个元素的数组
 - 严格增加数组
 - 严格递减数组
 - 包含重复值的数组
 - 大型数组会导致溢出问题

 重复值尤其重要，因为它们会影响我们唯一计算子数组的方式，而不会重复计算贡献。 

## 方法

 ### 蛮力方法

 最简单的解决方案是枚举每个可能的子数组。 

对于每个起始索引`i`，我们将子数组扩展到每个结束索引`j >= i`。 在扩张的同时，我们维持迄今为止看到的最小值。 

例如：```
arr = [3,1,2]

Start at index 0:
[3]       min = 3
[3,1]     min = 1
[3,1,2]   min = 1

Start at index 1:
[1]       min = 1
[1,2]     min = 1

Start at index 2:
[2]       min = 2
```这避免了每次重新扫描整个子数组，因为我们增量更新最小值。 

该算法是正确的，因为每个子数组都被访问一次，并且其最小值被添加到答案中。 

但时间复杂度仍然是`O(n^2)`，对于大小的数组来说太慢了`30,000`。 

### 最优方法，单调堆栈

 关键的见解是，不要问：

 >“每个子数组的最小值是多少？”

 我们可以换个角度问：

 > “对于多少个子数组，每个元素最小？”

 假设一个元素`arr[i]`是某些子数组集合的最小值。 如果我们可以准确地计算出有多少个这样的子数组，那么它的总贡献就变成了：```
arr[i] * number_of_subarrays_where_it_is_minimum
```为了有效地计算这一点，我们确定：

 - 左边有多少个连续元素大于当前元素
 - 右侧有多少个连续元素大于或等于当前元素

 这些边界定义了所有子数组，其中`arr[i]`是最小值。 

单调递增堆栈使我们能够在线性时间内找到这些边界。 

对重复项的微妙处理至关重要：

 - 一方面我们严格使用更大的（`>`）
 - 另一方面，我们使用大于或等于（`>=`）

 这可以防止重复的最小值被多次计算。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 枚举每个子数组并跟踪运行最小值 |
 | 最佳 | O(n) | O(n) | 使用单调堆栈来计算每个元素的贡献 |

 ## 算法演练

 ### 步骤 1：计算先前较小的元素

 对于每个索引`i`，我们想知道最接近左侧的包含严格较小值的索引。 

我们维护一个包含索引的单调递增堆栈。 

当栈顶的值大于当前值时，我们将其弹出。 

弹出后：

 - 如果栈为空，则左边没有更小的元素
 - 否则，栈顶是前一个较小的元素

 这决定了当前元素可以向左延伸多远，同时保持最小值。 

### 步骤 2：计算下一个较小或相等的元素

 接下来，我们计算右侧最近的包含小于或等于当前值的索引。 

同样，我们使用单调递增堆栈。 

这次，当堆栈顶部的值大于或等于当前值时，我们将其弹出。 

使用`>=`这对于正确处理重复项至关重要。 

这决定了当前元素在保持最小值的同时可以向右延伸多远。 

### 步骤 3：计算有效子数组的数量

 对于每个索引`i`:```
left_count = i - previous_smaller_index
right_count = next_smaller_or_equal_index - i
```子数组的数量，其中`arr[i]`最小值变为：```
left_count * right_count
```这是有效的，因为：

 - 我们可以独立选择任何有效的左边界
 - 我们可以独立选择任何有效的右边界

 笛卡尔积给出所有有效的子数组。 

### 第 4 步：添加贡献

 每个元素贡献：```
arr[i] * left_count * right_count
```我们将所有贡献相加并取模`10^9 + 7`。 

### 为什么它有效

 每个子数组都恰好有一个由边界规则分配给它的最小元素。 单调堆栈有效地确定每个元素保持最小值的最大范围。 

一方面使用严格比较，另一方面使用非严格比较，可以保证重复值的分配一致，而不会重叠或重复计算。 

## Python 解决方案```python
from typing import List

class Solution:
    def sumSubarrayMins(self, arr: List[int]) -> int:
        MOD = 10**9 + 7
        n = len(arr)

        previous_smaller = [-1] * n
        next_smaller_equal = [n] * n

        stack = []

        # Previous smaller element
        for i in range(n):
            while stack and arr[stack[-1]] > arr[i]:
                stack.pop()

            if stack:
                previous_smaller[i] = stack[-1]

            stack.append(i)

        stack = []

        # Next smaller or equal element
        for i in range(n - 1, -1, -1):
            while stack and arr[stack[-1]] >= arr[i]:
                stack.pop()

            if stack:
                next_smaller_equal[i] = stack[-1]

            stack.append(i)

        result = 0

        for i in range(n):
            left_count = i - previous_smaller[i]
            right_count = next_smaller_equal[i] - i

            contribution = arr[i] * left_count * right_count
            result = (result + contribution) % MOD

        return result
```该实现首先初始化数组，该数组将存储每个元素最近的较小边界。 

第一个循环计算每个索引的前一个较小元素。 堆栈按值的递增顺序维护。 每当一个较大的元素出现在堆栈顶部时，它就不能再充当有效的先前较小的边界，因此它会被删除。 

第二个循环通过从右到左迭代来计算下一个较小或相等的元素。 使用`>=`确保一致地处理重复值。 

构建两个边界数组后，算法会计算每个元素对子数组的数量最少。 贡献公式直接从有效左扩展和右扩展的数量得出。 

最后对答案进行模累加`10^9 + 7`。 

## 解决方案```go
func sumSubarrayMins(arr []int) int {
    const MOD int = 1_000_000_007

    n := len(arr)

    previousSmaller := make([]int, n)
    nextSmallerEqual := make([]int, n)

    for i := 0; i < n; i++ {
        previousSmaller[i] = -1
        nextSmallerEqual[i] = n
    }

    stack := []int{}

    // Previous smaller element
    for i := 0; i < n; i++ {
        for len(stack) > 0 && arr[stack[len(stack)-1]] > arr[i] {
            stack = stack[:len(stack)-1]
        }

        if len(stack) > 0 {
            previousSmaller[i] = stack[len(stack)-1]
        }

        stack = append(stack, i)
    }

    stack = []int{}

    // Next smaller or equal element
    for i := n - 1; i >= 0; i-- {
        for len(stack) > 0 && arr[stack[len(stack)-1]] >= arr[i] {
            stack = stack[:len(stack)-1]
        }

        if len(stack) > 0 {
            nextSmallerEqual[i] = stack[len(stack)-1]
        }

        stack = append(stack, i)
    }

    result := 0

    for i := 0; i < n; i++ {
        leftCount := i - previousSmaller[i]
        rightCount := nextSmallerEqual[i] - i

        contribution := ((arr[i] * leftCount) % MOD * rightCount) % MOD
        result = (result + contribution) % MOD
    }

    return result
}
```Go 实现遵循与 Python 版本相同的算法结构。 

切片用于模拟堆栈。 元素被推入`append`并通过重新切片弹出。 

Go 需要更明确地处理整数溢出问题。 尽管问题约束可以轻松地适应 64 位算术，但在贡献计算过程中仍需谨慎应用模乘法。 

与 Python 不同，Go 不会自动支持负索引或动态整数大小调整，因此边界初始化是显式处理的。

 ## 边缘情况

 单元素数组是最简单的边缘情况。 由于只有一个子数组，因此答案必须等于该元素本身。 错误初始化边界或错误处理空堆栈的实现可能会在这里失败。 这个解决方案可以自然地处理它，因为左右跨度都变成了`1`。 

包含重复值的数组是错误的常见来源。 如果两个边界搜索使用相同的比较运算符，则某些子数组可能会被多次计数或完全丢失。 这个实现通过使用解决了这个问题`>`对于之前较小的搜索和`>=`对于下一个较小的搜索，为重复项创建一致的所有权规则。 

严格递增数组强调算法是否正确地将范围向左扩展。 除第一个元素外，每个元素前面都有一个较小的元素。 单调堆栈自然地保留了这种结构并正确计算跨度。 

严格递减数组会创建相反的模式。 每个新元素都会成为迄今为止最小的元素，从而导致重复的堆栈弹出。 这是堆栈正确性的一个重要压力情况。 即使发生多次弹出，每个元素仍然只被压入和弹出一次，从而保持线性时间复杂度。 

大型数组可以产生巨大的中间和。 如果没有模运算，某些语言中可能会发生整数溢出。 该实现在累加过程中应用模运算，以确保正确性并符合问题要求。
