 # LeetCode 994，腐烂的橙子

 ## 问题陈述

 您将获得一个 2D 网格，其中每个单元格代表三种可能状态之一：

 -`0`意味着单元格是空的。 
-`1`表示细胞内含有新鲜的橙子。 
-`2`表示细胞内含有腐烂的橙子。 

每分钟，任何与腐烂橙子直接相邻的新鲜橙子也会腐烂。 仅在四个基本方向上考虑相邻性：上、下、左、右。 

目标是确定直到网格中没有新鲜橙子为止所需的最短分钟数。 如果一些新鲜的橙子因为被隔离而永远不会腐烂，那么该函数必须返回`-1`。 

输入是一个`m x n`两个维度最多为的矩阵`10`。 这是一个相对较小的网格，但问题仍然需要仔细模拟，因为感染是从多个腐烂的橙子同时传播的。 

重要的细节是，当前所有腐烂的橙子在每一分钟内同时传播。 这意味着我们不会先处理一个腐烂的橙子，然后再处理另一个腐烂的橙子。 相反，传播会随着时间逐级发生。 

Several edge cases are important:

 - 没有新鲜橙子的网格应该立即返回`0`。 
- 一个有新鲜橙子但没有腐烂橙子的网格永远不会完全腐烂，所以答案是`-1`。 
- 被空单元隔开的新鲜橙子可能会变得无法到达。 
- 多个腐烂的橙子可能会同时感染不同的区域。 

## 问题理解

 这个问题从根本上讲是关于模拟条件随时间在网格中的传播。 

每个腐烂的橙子都像是一个感染源。 每分钟，感染就会在四个有效方向上向外传播一个细胞。 由于所有腐烂的橙子同时扩散，自然会形成层层扩张。 

输出不是腐烂的橙子总数，而是所有可到达的新鲜橙子腐烂所需的时间。 

约束很小，但问题的结构强烈暗示了图遍历解释。 每个单元格都可以看作图中的一个节点，相邻单元格之间存在边。 感染一次向外传播一层，这正是广度优先搜索 (BFS) 建模的行为。 

## 方法

 ### 蛮力方法

 一种简单的模拟方法会每分钟重复扫描整个网格。 

在每次通过期间：

 1.找到所有当前腐烂的橙子。 
2.标记相邻的新鲜橙子是否已腐烂。 
3. 扫描完成后，更新网格。 
4. 重复直到没有变化发生。 

这是有效的，因为它准确地模拟了每分钟的传播过程。 然而，即使只有少数单元格发生变化，它也会重复遍历整个矩阵。 

如果有`k`分钟的传播和网格包含`m * n`细胞，总复杂度大约变为`O(k * m * n)`。 在最坏的情况下，`k`也可以接近`m * n`，导致低效的重复工作。 

### 最佳方法

 关键的一点是，腐烂过程的行为与多源 BFS 完全相同。 

我们可以：

 - 同时从每个烂橙子开始 BFS。 
- 逐层处理感染。 
- 每个 BFS 级别代表一分钟的经过时间。 

这是高效的，因为每个橙子最多被加工一次。 

BFS 在这里是理想的选择，因为：

 - 感染均匀向外扩散。 
- 我们第一次拿到新鲜的橙子是它最早腐烂的那一刻。 
- 同时传播自然地映射到基于队列的级别遍历。

 ## 算法演练

 1. 遍历整个网格一次，收集初始信息。 

在这次遍历过程中：

 - 数一下新鲜橙子的数量。 
- 将每个腐烂的橙色位置添加到队列中。 

该队列代表当前时刻处于活动状态的所有感染源。 
2、处理没有新鲜橙子的小事。 

如果新鲜橙子数量已经为零，则返回`0`立即，因为不需要时间。 
3. 启动BFS进程。 

BFS 循环的每次迭代代表一分钟的过去。 

对于当前队列大小：

 - 仅处理在该分钟开始时已经腐烂的橙子。 
- 新感染的橙子将在下一分钟添加进行加工。 
4. 对于每个腐烂的橙子，检查其四个相邻的单元格。 

有效的方向是：

 - 向上
 - 向下
 - 左
 - 右

 对于每个邻居：

 - 确保它在网格边界内。 
- 检查是否含有新鲜橙子。 
5. 当发现新鲜橙子时：

 - 立即将其更改为腐烂。 
- 减少新鲜橙子的数量。 
- 将其添加到队列中。 

这确保了它在下一分钟参与传播。 
6. 处理完一个 BFS 层后，递增分钟计数器。 

这可以准确地跟踪已经发生了多少轮传播。 
7. 继续，直到队列变空。 
8. BFS完成后：

 - 如果仍有新鲜橙子，请返回`-1`。 
- 否则返回经过的分钟数。 

### 为什么它有效

 BFS 保证节点按照距起始源的距离递增的顺序进行处理。 由于每个 BFS 层对应一分钟的传播时间，因此新鲜橙子第一次腐烂的时间就是其腐烂的最短时间。 同时处理所有初始烂橙子可确保模拟完全符合问题规则。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def orangesRotting(self, grid: List[List[int]]) -> int:
        rows = len(grid)
        cols = len(grid[0])

        queue = deque()
        fresh_count = 0

        # Collect all rotten oranges and count fresh oranges
        for row in range(rows):
            for col in range(cols):
                if grid[row][col] == 2:
                    queue.append((row, col))
                elif grid[row][col] == 1:
                    fresh_count += 1

        # No fresh oranges already
        if fresh_count == 0:
            return 0

        minutes = 0
        directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

        # Multi-source BFS
        while queue and fresh_count > 0:
            current_level_size = len(queue)

            for _ in range(current_level_size):
                row, col = queue.popleft()

                for dr, dc in directions:
                    new_row = row + dr
                    new_col = col + dc

                    # Check bounds and fresh orange
                    if (
                        0 <= new_row < rows
                        and 0 <= new_col < cols
                        and grid[new_row][new_col] == 1
                    ):
                        # Rot the orange
                        grid[new_row][new_col] = 2
                        fresh_count -= 1

                        queue.append((new_row, new_col))

            minutes += 1

        return minutes if fresh_count == 0 else -1
```该实现首先扫描网格一次，以找到所有腐烂的橙子并计算所有新鲜的橙子。 烂橙子插入队列是因为BFS要求按照先进先出的顺序处理节点。 

这`fresh_count`变量很重要，因为它允许算法快速确定是否所有橙子都已被感染。 

BFS循环逐级处理队列。 变量`current_level_size`确保仅处理在当前分钟开始时腐烂的橙子。 任何新腐烂的橙子都会被推迟到下一个 BFS 层，该层正确地模拟了同时传播。 

四个方向偏移简化了邻居遍历，同时避免了重复的代码。 

最后，BFS 完成后，算法会检查是否有任何新鲜橙子仍然无法到达。 如果是，该函数返回`-1`。 

## 解决方案```go
package main

func orangesRotting(grid [][]int) int {
	rows := len(grid)
	cols := len(grid[0])

	type Pair struct {
		row int
		col int
	}

	queue := []Pair{}
	freshCount := 0

	// Collect rotten oranges and count fresh oranges
	for r := 0; r < rows; r++ {
		for c := 0; c < cols; c++ {
			if grid[r][c] == 2 {
				queue = append(queue, Pair{r, c})
			} else if grid[r][c] == 1 {
				freshCount++
			}
		}
	}

	// No fresh oranges
	if freshCount == 0 {
		return 0
	}

	minutes := 0

	directions := [][]int{
		{1, 0},
		{-1, 0},
		{0, 1},
		{0, -1},
	}

	// Multi-source BFS
	for len(queue) > 0 && freshCount > 0 {
		levelSize := len(queue)

		for i := 0; i < levelSize; i++ {
			current := queue[0]
			queue = queue[1:]

			for _, dir := range directions {
				newRow := current.row + dir[0]
				newCol := current.col + dir[1]

				if newRow >= 0 &&
					newRow < rows &&
					newCol >= 0 &&
					newCol < cols &&
					grid[newRow][newCol] == 1 {

					grid[newRow][newCol] = 2
					freshCount--

					queue = append(queue, Pair{newRow, newCol})
				}
			}
		}

		minutes++
	}

	if freshCount == 0 {
		return minutes
	}

	return -1
}
```Go 实现遵循与 Python 版本相同的算法结构。 由于Go没有提供内置的双端队列结构，因此使用切片作为BFS队列。 使用切片从前面删除元素。 

Go 还需要显式的结构定义来存储行和列坐标。 整数溢出在这里不是问题，因为网格尺寸非常小。

from typing import List

class Solution:
    def orangesRotting(self, grid: List[List[int]]) -> int:
        from collections import deque

        rows = len(grid)
        cols = len(grid[0])

        queue = deque()
        fresh_count = 0

        for r in range(rows):
            for c in range(cols):
                if grid[r][c] == 2:
                    queue.append((r, c))
                elif grid[r][c] == 1:
                    fresh_count += 1

        if fresh_count == 0:
            return 0

        directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]
        minutes = 0

        while queue and fresh_count > 0:
            for _ in range(len(queue)):
                r, c = queue.popleft()

                for dr, dc in directions:
                    nr = r + dr
                    nc = c + dc

                    if (
                        0 <= nr < rows
                        and 0 <= nc < cols
                        and grid[nr][nc] == 1
                    ):
                        grid[nr][nc] = 2
                        fresh_count -= 1
                        queue.append((nr, nc))

            minutes += 1

        return minutes if fresh_count == 0 else -1

 ## 边缘情况

 ### 最初没有新鲜橙子

 一个常见的错误是即使没有新鲜的橙子也不必要地运行 BFS。 在像这样的网格中`[[0,2]]`，正确答案是`0`因为什么都不需要发生。 该实现通过在初始化期间计算新鲜橙子并立即返回来处理此问题`0`如果计数为零。 

### 新鲜橙子，无腐烂来源

 如果网格中包含新鲜橙子但没有腐烂的橙子，则感染永远不会开始。 例如：```
[[1,1],
 [1,1]]
```幼稚的实现可能会错误地返回`0`因为队列一开始是空的。 该解决方案通过检查 BFS 完成后是否剩余新鲜橙子来避免这种情况。 如果他们这样做，它会返回`-1`。 

### 孤立的新鲜橙子

 新鲜的橙子可能会被困在空的单元格后面。 例如：```
[[2,0,1]]
```新鲜的橙子是无法到达的，因为感染无法通过空细胞。 BFS 自然会处理这个问题，因为无法访问的单元永远不会被访问。 遍历结束后，`fresh_count`保持正值，导致算法正确返回`-1`。 

### 多个腐烂来源

 另一个微妙的问题是确保多个腐烂的橙子同时传播。 按顺序而不是逐级处理它们可能会产生不正确的计时结果。 BFS 层序遍历保证分钟内所有橙子都被感染`t`仅在几分钟内开始感染他人`t + 1`。
