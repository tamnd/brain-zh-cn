[LeetCode 903 题](https://leetcode.com/problems/valid-permutations-for-di-sequence/)

 **难度：** 🔴难
 **主题：** 字符串、动态规划、前缀和

 ## 解决方案

 ## 问题理解

 问题给了我们一个字符串`s`长度`n`，其中每个字符描述排列中两个相邻元素之间的关系。 

排列必须包含以下每个整数`0`到`n`恰好一次，因此排列长度始终为`n + 1`。 

字符串中的每个字符都会施加一个约束：

 -`'I'`表示下一个数字必须大于当前数字。 
-`'D'`表示下一个数字必须小于当前数字。 

例如，如果`s = "DID"`，那么排列必须满足：

 -`perm[0] > perm[1]`-`perm[1] < perm[2]`-`perm[2] > perm[3]`我们被要求计算有多少有效排列满足所有这些条件。 

重要的细节是我们只需要计数，而不需要排列本身。 由于排列数量增长得非常快，答案可能变得非常大，因此我们将其模数返回`10^9 + 7`。 

约束条件尤其重要：

 -`n <= 200`长度的排列`201`有`201!`可能的安排，这是一个天文数字。 任何暴力枚举都是完全不可行的。 这强烈表明该解决方案必须使用动态规划并利用约束中的结构。 

一些边缘情况很重要：

 - 完全由以下内容组成的字符串`'I'`， 例如`"III"`，只允许严格增加排列。 
- 完全由以下内容组成的字符串`'D'`， 例如`"DDD"`，只允许严格递减排列。 
- 交替模式，例如`"DIDID"`创造许多分支的可能性。 
- 由于答案是模数`10^9 + 7`，每个算术运算都必须仔细应用模归约。 

## 方法

 ### 蛮力方法

 最直接的解决方案是生成每个数字的排列`0`到`n`并检查是否满足DI约束。 

对于每个排列：

 1. 遍历字符串`s`。 
2.如果`s[i] == 'I'`， 核实`perm[i] < perm[i + 1]`。 
3.如果`s[i] == 'D'`， 核实`perm[i] > perm[i + 1]`。 
4. 计算满足所有约束的每个排列。 

这种方法是正确的，因为它明确地检查每个可能的排列。 然而，它太慢了。 

有`(n + 1)!`排列。 即使是为了`n = 10`，这已经是数以百万计的可能性了。 为了`n = 200`，暴力是不可能的。 

### 最优动态规划方法

 关键的见解是我们不需要迄今为止使用的确切值。 我们只需要相关的订购信息。 

我们不是构建实际的排列，而是增量地构建它们并跟踪最后选择的数字在剩余候选者中的排名。 

定义：

-`dp[i][j]`作为构建长度序列的有效方法的数量`i + 1`,
 - 最后一个元素有排名`j`在未使用的号码中。 

每一步：

 - 如果下一个关系是`'I'`，下一个等级一定更大。 
- 如果下一个关系是`'D'`，下一个等级一定更小。 

简单的转换需要嵌套求和，从而导致`O(n^3)`复杂。 自从`n = 200`，这在优化的语言中可能仍然可以通过，但我们可以做得更好。 

重要的优化是使用前缀和。 

对于每行 DP：

 - 如果我们需要较小索引的总和，请使用从左到右的前缀总和。 
- 如果我们需要对较大索引求和，请使用从右到左的后缀式累加。 

这将总复杂度降低到`O(n^2)`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 |`O((n + 1)! * n)`|`O(n)`| 生成每个排列并验证它 |
 | 最优动态规划|`O(n^2)`|`O(n)`| 使用基于排名的 DP 和前缀和优化 |

 ## 算法演练

 1.让`n = len(s)`。 

排列长度为`n + 1`。 
2. 初始化DP阵列。 

我们使用一维 DP 数组，其中：

 -`dp[j]`表示当前长度的有效序列数，
 - 最后选择的数字具有相对排名`j`。 

最初：```
dp = [1]
```这表示一个长度的序列`1`，其中仅存在一个等级。 
3. 一次处理一个字符的字符串。 

对于每个位置`i`:

 - 我们正在从长度上扩展序列`i + 1`到长度`i + 2`。 
- 新的 DP 行将包含`i + 2`州。 
4. 处理`'I'`案件。 

如果`s[i] == 'I'`，那么下一个等级一定更大。 

对于每一个可能的新等级`j`:

 - 之前的有效排名均小于`j`。 

所以：```
new_dp[j] = sum(dp[0:j])
```不要重复重新计算总和，而是维护一个运行的前缀总和。 
5. Handle the`'D'`案件。 

如果`s[i] == 'D'`，那么下一个等级一定更小。 

对于每一个可能的新等级`j`:

 - 之前的有效排名是所有大于或等于的排名`j`。 

所以：```
new_dp[j] = sum(dp[j:])
```使用反向运行和来有效地计算这些。 
6. 替换当前的DP 行。 

计算完所有转换后：```
dp = new_dp
```7. 处理完所有字符后，对所有剩余状态求和。 

每个剩余的状态都对应于一个有效的排列。 
8. 返回模数结果`10^9 + 7`。 

### 为什么它有效

 DP 状态仅存储相对排名信息，而不存储确切的数字。 这是可行的，因为 DI 约束仅取决于相邻元素之间的比较。 

在每一步中，算法都会正确计算将较小的有效序列扩展为较大的有效序列的所有方式，同时保留所需的排序关系。 

前缀和优化不会改变递归关系。 它只会更有效地计算重复范围和。 

## Python 解决方案```python
class Solution:
    def numPermsDISequence(self, s: str) -> int:
        MOD = 10**9 + 7
        
        dp = [1]
        
        for i, ch in enumerate(s):
            new_dp = [0] * (i + 2)
            
            if ch == 'I':
                prefix = 0
                
                for j in range(i + 1):
                    prefix = (prefix + dp[j]) % MOD
                    new_dp[j + 1] = prefix
            
            else:
                suffix = 0
                
                for j in range(i, -1, -1):
                    suffix = (suffix + dp[j]) % MOD
                    new_dp[j] = suffix
            
            dp = new_dp
        
        return sum(dp) % MOD
```实现以单个有效长度序列开始`1`。 

对于输入字符串中的每个字符，我们构造下一个 DP 行。 

当角色是`'I'`，我们从左到右累加前缀和。 每个新的等级只能来自较小的先前等级。 

当角色是`'D'`，我们从右到左累加后缀和。 每个新的等级只能来自更大的先前等级。 

每次更新时都会应用求模运算，以防止溢出并满足问题要求。 

最后，最终 DP 数组中的每个状态都对应一个有效的排列，因此我们将所有条目相加。 

## 解决方案```go
func numPermsDISequence(s string) int {
    const MOD int = 1_000_000_007

    dp := []int{1}

    for i, ch := range s {
        newDp := make([]int, i+2)

        if ch == 'I' {
            prefix := 0

            for j := 0; j <= i; j++ {
                prefix = (prefix + dp[j]) % MOD
                newDp[j+1] = prefix
            }
        } else {
            suffix := 0

            for j := i; j >= 0; j-- {
                suffix = (suffix + dp[j]) % MOD
                newDp[j] = suffix
            }
        }

        dp = newDp
    }

    result := 0

    for _, value := range dp {
        result = (result + value) % MOD
    }

    return result
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

使用切片而不是动态 Python 列表。 由于 Go 整数在某些平台上可能会溢出，因此每次算术更新都会立即应用模归约。 

由于每行的大小不同，因此每次迭代都会重新创建 DP 数组。

 ## 边缘情况

 一种重要的边缘情况是当字符串仅包含`'I'`人物。 In this situation, the permutation must be strictly increasing. There is only one valid permutation, namely`[0, 1, 2, ..., n]`。 有缺陷的实现可能会意外地过度计数，因为许多 DP 状态看起来是可达的。 前缀和转换正确地仅保留一种有效的排序。 

另一个重要的边缘情况是当字符串仅包含`'D'`人物。 这里，排列必须是严格递减的，所以只有`[n, n-1, ..., 0]`是有效的。 这种情况大量运用了后缀和逻辑。 如果反向累积执行不正确，这种情况通常会立即失败。 

交替模式，例如`"DIDIDID"`是错误的另一个常见来源。 这些模式产生许多分支可能性，并且需要在两个方向上重复转换。 这里经常出现不正确的 DP 索引，因为有效范围每次迭代都会发生变化。 该实现通过仔细匹配前缀和来正确处理这个问题`'I'`和后缀总和`'D'`。 

最后一个微妙的边缘情况涉及模运算。 对于较长的字符串，有效排列的数量会快速增长。 如果在中间计算过程中不应用模归约，像 Go 这样的语言可能会发生整数溢出。 两种实现都在每次加法后应用模数缩减，确保所有允许的输入大小的正确性。
