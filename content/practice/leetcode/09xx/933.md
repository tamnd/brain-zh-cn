[LeetCode 933 题](https://leetcode.com/problems/number-of-recent-calls/)

 **难度：** 🟢简单
 **主题：** 设计、队列、数据流

 ## 解决方案

 ## 问题理解

 问题要求我们实现一个类`RecentCounter`跟踪过去 3000 毫秒内发出的请求（或 ping）数量。 每次`ping(t)`方法被调用时有时间`t`，我们被要求返回在时间间隔内发生了多少个请求`[t - 3000, t]`。 该课程以零请求开始，每次调用`ping`使用严格递增的时间值`t`。 

输入`t`表示以毫秒为单位的时间，输出只是 3000 毫秒窗口内最近请求的计数。 关键的限制是`t`严格递增，最多可以有 10,000 个调用。 这保证了我们永远不必处理无序时间戳，并且我们使用的数据结构最多可容纳 10,000 个项目，大小适中。 

重要的边缘情况包括第一个请求、恰好相隔 3000 毫秒的请求以及全部落在 3000 毫秒窗口内的突发请求。 严格增量的保障`t`简化管理，因为我们只需要从队列前面删除较旧的请求，而无需搜索或重新排序。 

## 方法

 暴力方法会将所有请求存储在一个列表中，并且对于每个请求`ping(t)`，迭代列表以计算有多少个时间戳在该范围内`[t - 3000, t]`。 这是正确的，因为它确实检查每个请求的条件，但效率很低，因为每个调用都需要相对于存储的请求数量呈线性时间。 

最佳方法是使用队列仅维护最近 3000 毫秒内的请求。 每次我们打电话`ping(t)`，我们附加新的时间戳并从前面删除任何早于`t - 3000`。 这是有效的，因为输入保证严格增加时间，因此所有过时的请求将始终位于前面。 队列确保从末端高效地插入和删除 O(1)。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 每次 ping 的 O(n) | O(n) | 迭代所有以前的请求以计算最近的请求 |
 | 最佳 | O(1) 每 ping 摊销 | O(n) | 使用队列仅存储相关请求，有效删除旧请求 |

 ## 算法演练

 1. 初始化一个空队列`RecentCounter`对象被创建。 该队列将保存 3000 毫秒窗口内最近请求的所有时间戳。 
2. 什么时候`ping(t)`被调用，附加`t`到队列中。 这代表新的传入请求。 
3. 当最前面的时间戳小于时，从队列的最前面移除时间戳`t - 3000`。 这些请求超出了 3000 毫秒窗口，不应再被计算在内。 
4. 移除旧请求后，队列的长度代表最近3000毫秒内的请求数。 返回这个长度。 

工作原理：队列不变式确保它始终只包含有效窗口内的时间戳`[t - 3000, t]`。 因为`t`值严格递增，一旦删除时间戳，它将永远不再相关。 这保证了正确性和效率。 

## Python 解决方案```python
from collections import deque

class RecentCounter:

    def __init__(self):
        self.queue = deque()

    def ping(self, t: int) -> int:
        self.queue.append(t)
        while self.queue and self.queue[0] < t - 3000:
            self.queue.popleft()
        return len(self.queue)

# Your RecentCounter object will be instantiated and called as such:
# obj = RecentCounter()
# param_1 = obj.ping(t)
```在此 Python 实现中，我们使用`deque`从`collections`模块，因为它允许在后面插入 O(1) 并从前面删除 O(1)。 每次致电`ping`追加新请求，然后删除过时的请求，直到仅保留相关时间戳。 然后返回双端队列的长度，它直接代表最近请求的数量。 

## 解决方案```go
type RecentCounter struct {
	queue []int
}

func Constructor() RecentCounter {
	return RecentCounter{queue: []int{}}
}

func (this *RecentCounter) Ping(t int) int {
	this.queue = append(this.queue, t)
	for len(this.queue) > 0 && this.queue[0] < t-3000 {
		this.queue = this.queue[1:]
	}
	return len(this.queue)
}

/**
 * Your RecentCounter object will be instantiated and called as such:
 * obj := Constructor();
 * param_1 := obj.Ping(t);
 */
```在Go中，我们使用切片来实现队列。 我们附加新的时间戳并通过切掉切片的前面来删除旧的时间戳。 这种方法对于 Go 来说是惯用的，尽管当旧的前端被删除时切片会创建一个新的底层数组，这对于问题大小来说仍然是有效的。 

## 工作示例

 对于输入序列`[1, 100, 3001, 3002]`:

 | 致电 | 插入后的队列状态| 删除旧的后队列状态| 返回值|
 | ---| ---| ---| ---|
 | 平(1) | [1] | [1] | 1 |
 | 平(100) | [1, 100] | [1, 100] | 2 |
 | 平(3001) | [1, 100, 3001] | [1, 100, 3001] | 3 |
 | 平(3002) | [1, 100, 3001, 3002] | [100, 3001, 3002] | 3 |

 ## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(1) 每 ping 摊销 | 每个请求在队列中添加一次并删除一次，因此所有 ping 的总工作量是线性的 |
 | 空间| O(n) | 队列最多存储最近 3000 毫秒内的所有请求，以 ping 数量为界 |

 摊销时间为 O(1)，因为每个元素在队列的生命周期内只添加和弹出一次。

 ## 边缘情况

 一个重要的边缘情况是第一次调用`ping`。 没有先前的请求，因此队列开始为空，并且该函数必须正确返回 1。这是通过附加到空队列来自然处理的。 

当多个 ping 在同一毫秒内到达时，会出现另一种边缘情况。 队列中将包含多个相同的时间戳，并且所有时间戳都应计入返回结果中。 该算法无需任何特殊逻辑即可处理此问题，因为内的所有时间戳`[t - 3000, t]`被保留。 

第三种边缘情况涉及在最早 ping 之后恰好 3000 毫秒进行 ping。 包容性窗口`[t - 3000, t]`表示仍应计算最早的 ping。 我们的循环仅删除严格小于的时间戳`t - 3000`，因此这种边缘情况得到了正确处理。
