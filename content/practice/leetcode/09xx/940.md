[LeetCode 940 题](https://leetcode.com/problems/distinct-subsequences-ii/)

 **难度：** 🔴难
 **主题：** 字符串、动态规划

 ## 解决方案

 ## 问题理解

 该问题要求我们计算给定字符串可以形成多少个不同的非空子序列`s`。 

子序列是通过删除零个或多个字符同时保留剩余字符的原始顺序而形成的。 例如，从`"abc"`我们可以形成像这样的子序列`"a"`,`"ac"`， 和`"bc"`，但不是`"ca"`因为这会改变顺序。 

重要的细节是我们只计算不同的子序列。 如果同一个子序列可以由多种方式组成，则只计算一次。 

例如，考虑`"aba"`:

 - 使用第一个`'a'`给出子序列`"a"`- 使用最后一个`'a'`还给出子序列`"a"`尽管有多种生产方式`"a"`，只计算一次。 

输入是一个字符串`s`仅由小写英文字母组成，长度可达`2000`。 由于子序列的数量呈指数增长，我们显然无法直接为上限生成所有子序列。 

答案可能变得非常大，因此问题需要返回结果模`10^9 + 7`。 

一些边缘情况很重要：

 - 包含所有唯一字符的字符串，例如`"abcde"`，最大化子序列的数量。 
- 含有很多重复字符的字符串，例如`"aaaaa"`，创建许多重复的子序列，不得重复计算。 
- 非常长的字符串需要高效的动态编程解决方案。 
- 单字符字符串应该正确返回`1`。 

## 方法

 ### 蛮力方法

 强力解决方案使用递归或位掩码枚举生成每个可能的子序列。 

对于一个长度的字符串`n`，每个角色有两种选择：

 - 包括它
 - 排除它

 这会产生`2^n`总子序列，包括空子序列。 

生成它们后，我们可以将每个子序列插入到一个集合中以删除重复项，然后返回集合的大小减去空子序列的一。 

这种方法是正确的，因为它显式枚举每个子序列并使用集合来确保唯一性。 

然而，对于`n = 2000`。 即使是为了`n = 30`,`2^30`已经超过十亿个子序列。 

### 最优动态规划方法

 关键的观察是，当我们处理一个新字符时，每个现有的子序列都可以：

 - 保持不变
 - 追加新字符

 如果所有字符都是唯一的，则每个新字符只会使子序列的数量加倍。 

但是，重复的字符会产生重复。 

例如：

 - 假设我们已经处理了`"ab"`- 现有的子序列是：`""`,`"a"`,`"b"`,`"ab"`现在我们处理另一个`'a'`。 

追加`'a'`创建：

 -`"a"`-`"aa"`-`"ba"`-`"aba"`但`"a"`之前就已经存在了，所以我们必须避免重复计算。 

主要的见解是：

 处理字符时`c`，我们将子序列的数量加倍，然后减去上次看到的已经计数的子序列`c`。 

我们追踪：

 -`total`，包括空子序列的不同子序列的数量
 -`last[c]`，在上一个字符出现之前存在的子序列的数量`c`这使我们能够有效地删除重复项。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n * n) | O(2^n * n) | O(2^n * n) | O(2^n * n) | 显式生成所有子序列 |
 | 最佳 | O(n) | O(1) | O(1) | 带有最后出现跟踪的动态规划 |

 ## 算法演练

 1. 初始化`total = 1`。 

这表示包括空子序列在内的不同子序列的数量。 最初，仅存在空子序列。 
2. 创建数组`last`大小 26 初始化为`0`。`last[i]`存储的值`total`在上一次出现的字符之前`i`。 
3. 迭代每个字符`ch`在字符串中。 
4. 更新前`total`，将当前值存储在`previous_total`。 

我们需要这个，因为在处理当前字符之后，未来的重复项必须知道这次出现之前的总计数。 
5. 计算新的总数：```
new_total = total * 2 - last[ch]
```乘以`2`发生这种情况是因为每个现有子序列都可以：

 - 忽略当前字符
 - 追加当前字符

 但这会为重复的字符创建重复的子序列。 重复项正是在该字符上次出现之前计数的子序列，因此我们减去`last[ch]`。 
6. 应用模运算。 

由于减法可能暂时产生负值，因此我们使用：```
total = (new_total + MOD) % MOD
```7. 更新`last[ch]`。 

放：```
last[ch] = previous_total
```这记录了在该字符出现之前存在多少个子序列。 
8. 处理完所有字符后，减一以排除空子序列。```
return total - 1
```### 为什么它有效

 该算法保持不变式`total`始终等于不同子序列的数量，包括已处理字符串前缀的空子序列。 

当出现新字符时，每个现有子序列都可以包含或排除它，这会使计数加倍。 但是，如果该字符之前出现过，则将其附加到前一个出现之前已经存在的子序列会创建重复项。 减法`last[ch]`准确删除那些重复项，确保每个子序列都被计算一次。 

## Python 解决方案```python
class Solution:
    def distinctSubseqII(self, s: str) -> int:
        MOD = 10**9 + 7
        
        # total includes the empty subsequence
        total = 1
        
        # last[i] stores the total count before the previous
        # occurrence of character i
        last = [0] * 26
        
        for ch in s:
            index = ord(ch) - ord('a')
            
            previous_total = total
            
            total = (2 * total - last[index]) % MOD
            
            last[index] = previous_total
        
        # remove the empty subsequence
        return (total - 1) % MOD
```其实现直接遵循动态规划思想。`total`跟踪包括空子序列在内的不同子序列的数量。 开始于`1`简化了递归，因为每一步都可以统一使计数加倍。 

这`last`数组跟踪每个字符的重复生成状态。 由于字符串仅包含小写英文字母，因此大小为数组`26`比哈希图足够并且更有效。 

在循环内部，我们首先保存`previous_total`因为该值成为新值`last`当前字符的条目。 

复发：```python
total = (2 * total - last[index]) % MOD
```实现核心逻辑：

 - 将所有子序列加倍
 - 删除重复字符造成的重复

 最后，我们减一以从最终答案中排除空子序列。 

## 解决方案```go
func distinctSubseqII(s string) int {
	const MOD int = 1000000007

	total := 1

	last := make([]int, 26)

	for _, ch := range s {
		index := ch - 'a'

		previousTotal := total

		total = (2*total - last[index] + MOD) % MOD

		last[index] = previousTotal
	}

	return (total - 1 + MOD) % MOD
}
```Go 的实现与 Python 解决方案非常相似。 

Go 需要显式处理模减法，因为负值可能会暂时出现。 添加`MOD`申请之前`% MOD`确保结果保持非负数。 

这`last`结构体被实现为长度固定的整数切片`26`，因为只能使用小写英文字母。 

Go 使用`rune`中的迭代`for _, ch := range s`循环，但由于所有字符都是小写英文字母，因此索引仍然很简单。

 ## 边缘情况

 ### 所有字符都相同

 像这样的字符串`"aaaaaa"`看似棘手，因为尽管字符串中存在许多位置，但可能的子序列的数量增长缓慢。 

幼稚的实现可能会意外地对同一子序列进行多次计数。 例如，`"a"`可以由任何个人位置组成。 

动态规划解决方案可以正确处理这个问题，因为每个重复`'a'`使用减去先前重复的子序列`last['a']`。 

### 所有角色都是独一无二的

 对于像这样的字符串`"abcdef"`，每个新字符都会使子序列的数量加倍，因为没有引入重复项。 

这是理想的增长场景：```
2^n - 1
```该算法自然地处理这个问题，因为每个`last[ch]`第一次出现时值保持为零。 

### 非常长的输入

 该约束允许字符串的长度达到`2000`。 暴力解决方案需要处理`2^2000`子序列，这在计算上是不可能的。 

动态编程方法对每个字符处理一次并使用恒定的额外空间，即使在最大约束大小下也使其高效。
