[LeetCode 第 991 题](https://leetcode.com/problems/broken-calculator/)

 **难度：** 🟡 中等
 **主题：** 数学、贪心

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个以整数开头的计算器`startValue`并且只允许两个操作：

 1. 将当前数字乘以`2`2. 减法`1`我们的目标是转型`startValue`进入`target`使用最少的操作次数。 

乍一看，这看起来像是一个最短路径问题，我们尝试不同的操作序列，直到达到`target`。 然而，挑战在于，两者`startValue`和`target`可以大到`10^9`，这使得暴力探索变得不可行。 

为了用更简单的术语重述这个问题，我们希望找到仅使用加倍和减量将一个整数转换为另一个整数所需的最少按键次数。 

输入由两个整数组成：

 -`startValue`，计算器上最初显示的数字。 
-`target`，所需的最终数字。 

输出是一个整数，表示所需的最小操作数。 

约束在这里很重要：

 -`1 <= startValue, target <= 10^9`由于值可能非常大，因此任何探索许多可能的中间状态的方法都可能太慢或消耗太多内存。 我们需要比对所有可达数字进行图遍历更有效的方法。 

一些边缘情况立即脱颖而出：

 - 当`startValue >= target`，加倍是没有用的，因为它只会增加价值。 最好的策略就是简单地做减法`1`反复。 
- 什么时候`target`是奇数，它不能直接由另一个整数加倍得到，因为加倍总是产生偶数。 
- 非常大的值需要一种算法来避免向前一一模拟不必要的操作。 

## 方法

 ### 蛮力方法

 一个自然的第一个想法是将其视为最短路径问题。 开始于`startValue`，我们可以重复尝试这两种可能的操作：

 - 乘以`2`- 减法`1`我们可以将其建模为一个图，其中每个数字都是一个节点，并且操作创建边。 由于每个操作都有相同的成本，因此广度优先搜索（BFS）将保证最少的步骤数。 

这样做的原因是 BFS 逐级探索状态。 我们第一次相遇`target`，我们知道我们用最少的操作次数达到了这个目标。 

然而，对于给定的约束，这种方法变得不切实际。 由于数字会因重复加倍而变大，因此搜索空间会迅速扩大。 即使进行剪枝，BFS 也可能会探索大量状态以获取接近的值`10^9`。 

### 最佳解决方案的关键见解

 关键的观察结果是，**向后**解决问题要容易得多。 

而不是转型`startValue → target`，我们逆向操作，思考如何改造`target → startValue`。 

原来的操作是：

 - 乘以`2`- 减法`1`反转它们给出：

 - 除以`2`（如果是的话）
 - 添加`1`现在考虑一下当我们向后工作时会发生什么：

 - 如果`target`是偶数，它一定是某个数字加倍而成的。 除以`2`总是最好的举动，因为它会急剧缩小价值。 
- 如果`target`很奇怪，它不可能是通过加倍产生的。 因此，取得进步的唯一方法就是添加`1`，使其均匀。 

这种贪婪策略之所以有效，是因为除以`2`比反复相减消除的距离要远得多`1`。 

一次`target <= startValue`，进一步的逆向操作没有任何好处。 我们只需减去剩余的差值即可。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 实践中 O(目标) 到指数 | O（目标）| BFS 在可达状态上，对于大值来说太昂贵 |
 | 最佳 | O(对数目标) | O(1) | O(1) | 从目标贪婪地向后工作 |

 ## 算法演练

 1.初始化一个计数器`operations = 0`跟踪我们做了多少步。 
2. 继续处理`target > startValue`。 

我们只需要在目标值保持大于起始值的情况下进行贪心反向操作。 
3.如果`target`是奇数，将其增加`1`。 

由于加倍不能得到奇数，因此逆运算必须是加法`1`。 这使得数字成为偶数并为除法做好准备。 
4. 如果`target`是偶数，除以`2`。 

这对应于加倍操作的反转。 除以`2`减少数字比重复递减要快得多。 
5. 每次转换后增加操作计数器。 
6.一次`target <= startValue`，停止循环。 

此时，唯一可能的前向操作是减法`1`，这意味着相反的过程只需要添加剩余的差值。 
7、退货：```
operations + (startValue - target)
```这说明了弥补差距所需的其余步骤。 

### 为什么它有效

 正确性来自贪婪不变量。 

每当`target`是偶数，除以`2`始终是最佳的，因为任何涉及递增和递减的替代序列在最终达到相同的较小值之前都将需要更多操作。 

每当`target`是奇数，递增`1`是被迫的，因为奇数不能来自加倍。 没有替代的最佳移动。 

由于每一步要么是强制的，要么是可证明最优的，所以贪心策略总是产生最少的操作数。 

## Python 解决方案```python
class Solution:
    def brokenCalc(self, startValue: int, target: int) -> int:
        operations = 0

        while target > startValue:
            if target % 2 == 1:
                target += 1
            else:
                target //= 2

            operations += 1

        return operations + (startValue - target)
```实现直接遵循反向贪婪策略。 

我们首先初始化一个`operations`柜台。 那么，只要`target`仍然大于`startValue`，我们反复缩小它。 

在循环内部，我们检查是否`target`是奇数还是偶数：

 - 如果是奇数，我们将其递增，因为加倍不能产生奇数。 
- 如果是偶数，我们除以`2`有效地逆转加倍操作。 

每个转换都算作一次操作。 

最终，`target`变得小于或等于`startValue`。 在此阶段，最佳前向解决方案只需减去`1`重复，所以我们添加差异`startValue - target`到答案。 

## 解决方案```go
func brokenCalc(startValue int, target int) int {
    operations := 0

    for target > startValue {
        if target%2 == 1 {
            target++
        } else {
            target /= 2
        }

        operations++
    }

    return operations + (startValue - target)
}
```Go 的实现与 Python 解决方案非常相似。 

主要区别在于语法。 整数除法自然可以使用`/=`在整数上，Go 中自动执行地板除法。 由于所有值都在`10^9`，整数溢出不是标准的问题`int`现代 LeetCode 环境中的类型。 

不需要额外的数据结构，因此实现保持紧凑并使用恒定的额外内存。

 ## 边缘情况

 ### 什么时候`startValue`已经大于`target`如果`startValue >= target`，加倍会适得其反，因为它只会增加距离目标更远的数字。 

幼稚的实现可能仍然会尝试不必要的操作，但最佳解决方案立即认识到只有减法是有用的。 答案变成：```
startValue - target
```例如：```
startValue = 10
target = 4
```最优路径很简单：```
10 → 9 → 8 → 7 → 6 → 5 → 4
```＃＃＃ 什么时候`target`是奇数

 奇数目标很棘手，因为加倍总是产生偶数。 

简单的逆向实现可能会错误地将奇数除以`2`，产生无效状态。 相反，我们必须首先递增奇数目标，使其变为偶数。 

例如：```
startValue = 2
target = 7
```逆过程：```
7 → 8 → 4 → 2
```这保证了正确性。 

### 非常大的输入

 随着价值观的接近`10^9`，暴力方法变得不可行。 

例如：```
startValue = 1
target = 1000000000
```正向模拟或 BFS 会探索太多的可能性。 贪心逆向解决方案仍然有效，因为每次除以`2`显着缩小搜索空间，保持运行时对数。
