[LeetCode 929 题](https://leetcode.com/problems/unique-email-addresses/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表、字符串

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个电子邮件地址列表，并询问在应用类似 Gmail 的标准化规则后有多少唯一目的地实际收到电子邮件。 

每封电子邮件由两部分组成，各部分之间用`'@'`符号：

 - 本地名称，出现在前面`'@'`- 域名，出现在`'@'`域名始终按原样保留。 转换仅适用于本地名称。 

有两个特殊规则：

 1. 经期`'.'`里面的本地名称会被忽略。 
2. 如果是加号`'+'`出现在本地名称中，第一个之后的所有内容`'+'`被忽略。 

例如：

-`"test.email@leetcode.com"`变成`"testemail@leetcode.com"`-`"test+spam@leetcode.com"`变成`"test@leetcode.com"`-`"t.e.s.t+abc@leetcode.com"`也变成`"test@leetcode.com"`任务是根据这些规则对每封电子邮件进行标准化，然后计算剩余的不同标准化电子邮件地址。 

输入是电子邮件字符串的数组。 输出是一个整数，表示唯一标准化地址的数量。 

限制很小：

 - 最多 100 封电子邮件
 - 每封邮件长度最多100个字符

 这些限制告诉我们，性能并不是主要问题。 即使效率相对较低的解决方案也会在一定范围内发挥作用。 然而，问题主要在于仔细的字符串操作和正确的规则处理。 

一些边缘情况很重要：

 - 电子邮件可能同时包含两者`'.'`和`'+'`- 本地名称中可能会出现多个句点
 - 加号仅影响本地名称
 - 域名必须保持不变
 - 不同的域始终被视为不同的地址，即使本地名称规范化相同
 - 保证恰好有一个`'@'`性格
 - 本地和域部分保证非空

 幼稚的实现很容易因意外修改域名或错误地处理加号后的句点而犯错误。 

## 方法

 ### 蛮力方法

 暴力解决方案将手动将每封标准化电子邮件与其他标准化电子邮件进行比较。 

对于每封电子邮件，我们会：

 1.按照规则规范化
 2. 将其与所有先前处理的标准化电子邮件进行比较
 3.仅在尚不存在时添加

 这是有效的，因为每封电子邮件在比较之前都会转换为其规范形式。 如果两封电子邮件标准化为相同的字符串，则它们代表相同的实际邮箱。 

然而，这种方法效率很低，因为每封新电子邮件都可能需要扫描所有以前处理过的电子邮件。 和`n`电子邮件，这会导致二次行为。 

尽管约束足够小，这仍然可以通过，但这是不必要的工作。 

### 最佳方法

 关键的观察结果是，一旦电子邮件被规范化，唯一性检查就成为标准的哈希集问题。 

哈希集允许：

 - 快速插入
 - 快速重复检测
 - 恒定的平均时间会员检查

 算法变为：

 1. 标准化每封电子邮件
 2.将规范化版本插入集合中
 3.返回集合的大小

 这是有效的，因为集合会自动消除重复项。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n² × m) | O(n × m) | 将每封标准化电子邮件与之前的所有电子邮件进行比较 |
 | 最佳| O(n × m) | O(n × m) | 使用哈希集进行恒定时间唯一性检查 |

 这里：

-`n`是电子邮件的数量
 -`m`是最大电子邮件长度

 ## 算法演练

 ### 最优算法

 1. 创建一个空哈希集来存储规范化的电子邮件地址。 

哈希集是理想的选择，因为它会自动删除重复项并提供快速查找和插入操作。 
2. 迭代输入数组中的每封电子邮件。 

每封电子邮件都必须独立处理，因为标准化规则适用于每个地址。 
3. 使用以下命令将电子邮件拆分为本地名称和域名`'@'`。 

例如：```
"test.email+alex@leetcode.com"
```变成：```
local = "test.email+alex"
domain = "leetcode.com"
```4. 处理本地名称。 

首先检查本地名称是否包含`'+'`。 

如果是，则仅保留第一个之前的子字符串`'+'`。 

例子：```
"test.email+alex"
```变成：```
"test.email"
```5.删除所有句点`'.'`来自剩余的本地名称。 

例子：```
"test.email"
```变成：```
"testemail"
```6. 重建规范化电子邮件。 

将清理后的本地名称与未更改的域结合起来：```
"testemail@leetcode.com"
```7. 将规范化的电子邮件插入哈希集中。 

重复的标准化电子邮件将自动折叠成一个条目。 
8. 处理完所有电子邮件后，返回哈希集的大小。 

设置的大小等于唯一接收地址的数量。 

### 为什么它有效

 该算法之所以有效，是因为每封电子邮件都会根据问题陈述中的确切规则转换为规范表示。 

当且仅当两封电子邮件的规范化形式相同时，它们才代表同一个实际邮箱。 通过将规范化的电子邮件存储在哈希集中，重复项将被自动删除。 因此，最终设置的大小正是接收邮件的唯一地址的数量。 

## Python 解决方案```python
from typing import List

class Solution:
    def numUniqueEmails(self, emails: List[str]) -> int:
        unique_emails = set()

        for email in emails:
            local_name, domain_name = email.split("@")

            if "+" in local_name:
                local_name = local_name.split("+")[0]

            local_name = local_name.replace(".", "")

            normalized_email = local_name + "@" + domain_name

            unique_emails.add(normalized_email)

        return len(unique_emails)
```该实现紧密遵循前面描述的算法。 

解决方案首先创建一个名为`unique_emails`。 该集存储处理过程中遇到的每个标准化电子邮件地址。 

对于每封电子邮件，代码使用以下命令将字符串分成两部分`split("@")`。 左侧成为本地名称，右侧成为域名。 

首先处理加规则。 如果本地名称包含`'+'`，代码仅保留第一个加号之前的部分。 这是使用以下方法完成的：```python
local_name.split("+")[0]
```接下来，使用以下命令从剩余的本地名称中删除所有句点：```python
local_name.replace(".", "")
```然后，标准化的本地名称与未更改的域名相结合，形成最终的规范电子邮件地址。 

此标准化电子邮件将插入到集合中。 由于集合仅保留唯一值，因此重复项将被自动丢弃。 

最后，该函数返回集合的大小，它等于唯一接收地址的数量。 

## 解决方案```go
package main

import "strings"

func numUniqueEmails(emails []string) int {
	uniqueEmails := make(map[string]bool)

	for _, email := range emails {
		parts := strings.Split(email, "@")

		localName := parts[0]
		domainName := parts[1]

		if plusIndex := strings.Index(localName, "+"); plusIndex != -1 {
			localName = localName[:plusIndex]
		}

		localName = strings.ReplaceAll(localName, ".", "")

		normalizedEmail := localName + "@" + domainName

		uniqueEmails[normalizedEmail] = true
	}

	return len(uniqueEmails)
}
```Go 解决方案使用映射作为哈希集等效项，因为 Go 不提供内置的集合类型。 

地图：```go
map[string]bool
```将规范化的电子邮件字符串存储为键。 布尔值并不重要，只有关键的存在才重要。 

字符串处理与 Python 略有不同：

 -`strings.Split`分隔本地部分和域部分
 -`strings.Index`找到第一个`'+'`-`strings.ReplaceAll`删除句号

 Go 使用索引范围对字符串进行切片：```go
localName[:plusIndex]
```这会提取加号之前的所有内容。 

不需要对 nil 或空输入进行特殊处理，因为约束保证至少有一封电子邮件。

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n × m) | 每封电子邮件都会被扫描和标准化一次 |
 | 空间| O(n × m) | 该集合可以存储所有规范化的电子邮件 |

 这里：

-`n`是电子邮件的数量
 -`m`是最大电子邮件长度

 每封电子邮件都需要处理本地名称中的字符并构建规范化的字符串。 字符串操作（例如拆分和替换句点）所花费的时间与电子邮件长度呈线性关系。 由于每封电子邮件都被处理一次，因此总时间复杂度为`O(n × m)`。 

空间复杂度也为`O(n × m)`因为，在最坏的情况下，每封标准化电子邮件都是唯一的并存储在哈希集中。
