 # LeetCode 910，最小范围 II

 ## 问题理解

 问题给了我们一个整数数组`nums`和一个整数`k`。 对于数组中的每个元素，我们必须选择以下两个操作之一：

 - 添加`k`- 减去`k`修改每个元素后，我们计算数组的分数，定义为：```
max(nums) - min(nums)
```我们的目标是最小化这个分数。 

重要的细节是每个元素都必须独立更改。 一个数字可能会增加，而另一个数字可能会减少。 我们可以自由选择有助于最小化最终范围的操作。 

例如，如果：```
nums = [0, 10], k = 2
```我们可以将数组转换为：```
[2, 8]
```范围变为：```
8 - 2 = 6
```比原来的范围要小`10`。 

限制条件是：

 -`1 <= nums.length <= 10^4`-`0 <= nums[i] <= 10^4`-`0 <= k <= 10^4`这些限制足够大，以至于不可能对所有可能性进行指数或强力探索。 由于每个元素都有两个选择，因此有`2^n`可能的变换数组。 即使对于中等值`n`，这在计算上变得不可行。 

这些约束强烈表明我们需要贪婪或基于排序的优化。 

一些边缘情况很重要：

 - 只有一个元素的数组总是产生分数`0`-`k = 0`意味着没有发生有效的改变
 - 已经紧密集群的阵列可能无法从修改中受益
 - 相邻排序值之间的较大间隙是重要的决策点
 - 必须正确处理重复值

 ## 方法

 ### 蛮力方法

 蛮力策略是尝试所有可能的加法或减法组合`k`。 

对于每个元素：

 - 选择`+k`- 或选择`-k`然后计算结果数组的最大值和最小值，并跟踪找到的最小范围。 

这是有效的，因为它详尽地检查了每个有效的转换数组，保证了最佳答案。 

然而，可能性的数量是：```
2^n
```为了`n = 10^4`，这是完全不切实际的。 

即使是递归回溯解决方案也会很快变得无法使用。 

### 最佳解决方案的关键见解

 关键的观察来自对数组的排序。 

假设数组已排序：```
a0 <= a1 <= a2 <= ... <= an-1
```如果我们决定：

 - 左侧的元素增加`k`- 右侧的元素减少`k`那么变换后的值保持相对紧凑。 

最优解总是可以用分割点来表示：```
[ increase ] [ decrease ]
```排序后，我们只需要测试相邻元素之间每一个可能的分裂。 

对于索引处的分割`i`:

 - 元素`0..i`变得`nums[j] + k`- 元素`i+1..n-1`变得`nums[j] - k`然后我们计算所得的最小值和最大值。 

这将问题从指数复杂度降低到排序后的简单线性扫描。

 ## 算法演练

 1. 对数组进行非降序排序。 

排序至关重要，因为它允许我们推断修改后的最小值和最大值。 一旦排序，我们就可以系统地考虑从哪里过渡`+k`到`-k`发生。 
2. 用原来的范围初始化答案。 

在进行任何更改之前：```
answer = nums[n-1] - nums[0]
```这作为基线结果。 
3. 迭代每个可能的分区点。 

对于每个索引`i`从`0`到`n-2`:

 - 元素`0..i`增加了`k`- 元素`i+1..n-1`减少了`k`4. 计算新的最大值。 

最大的变换值只能来自：

 - 增加后最大的左侧元素：```
nums[i] + k
```- 或减少后的原始最大元素：```
nums[n-1] - k
```所以：```
high = max(nums[i] + k, nums[n-1] - k)
```5. 计算新的最小值。 

最小的变换值只能来自：

 - 增加后原来的最小元素：```
nums[0] + k
```- 或减少后的第一个右侧元素：```
nums[i+1] - k
```所以：```
low = min(nums[0] + k, nums[i+1] - k)
```6.更新答案。 

当前变换的范围是：```
high - low
```相应地更新最小答案。 
7. 返回找到的最小范围。 

### 为什么它有效

 排序后，任何最优排列都可以看作一个边界，边界之前的元素增加，边界之后的元素减少。 

如果两个元素违反此顺序，则交换它们的操作不能增加范围。 因此，检查所有分区点足以探索每个有意义的配置。 

因为我们评估每个可能的边界，所以算法保证找到可实现的最低分数。 

## Python 解决方案```python
from typing import List

class Solution:
    def smallestRangeII(self, nums: List[int], k: int) -> int:
        n = len(nums)

        if n == 1:
            return 0

        nums.sort()

        answer = nums[-1] - nums[0]

        for i in range(n - 1):
            high = max(nums[i] + k, nums[-1] - k)
            low = min(nums[0] + k, nums[i + 1] - k)

            answer = min(answer, high - low)

        return answer
```实现从处理最简单的边缘情况开始。 如果数组仅包含一个元素，则范围始终为零，无论`k`。 

接下来，对数组进行排序，以便我们可以推断连续的分区。 初始答案设置为修改前的原始范围。 

该循环检查每个可能的分割位置。 在每次迭代时：

 - 左侧部分被视为增加了`k`- 右侧部分被视为减少`k`仅使用边界元素计算可能的最大和最小变换值。 由于数组已排序，因此任何内部元素都不能超过这些极限值。 

最后，返回最小的观测范围。 

## 解决方案```go
package main

import "sort"

func smallestRangeII(nums []int, k int) int {
	n := len(nums)

	if n == 1 {
		return 0
	}

	sort.Ints(nums)

	answer := nums[n-1] - nums[0]

	for i := 0; i < n-1; i++ {
		high := max(nums[i]+k, nums[n-1]-k)
		low := min(nums[0]+k, nums[i+1]-k)

		answer = min(answer, high-low)
	}

	return answer
}

func max(a, b int) int {
	if a > b {
		return a
	}
	return b
}

func min(a, b int) int {
	if a < b {
		return a
	}
	return b
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一些特定于 Go 的细节值得注意：

 - Go不提供内置`min`和`max`整数函数，因此辅助函数是手动实现的。 
-`sort.Ints(nums)`用于就地排序。 
- 整数溢出不是问题，因为相对于 Go 的整数范围来说，约束很小。 
- 直接修改切片，高效且避免不必要的复制。

 ## 边缘情况

 ### 单元素数组

 当数组只包含一个数字时，修改后最大值和最小值始终相同。 即使我们加或减`k`，仍然只有一个元素。 

幼稚的实现可能仍会尝试分区逻辑并意外访问无效索引。 该实现通过返回来避免这种情况`0`立即地。 

###`k = 0`什么时候`k`为零，无论我们选择加法还是减法，每个元素都保持不变。 

这种情况很重要，因为某些实现错误地假设修改总是会更改值。 该算法自然地处理这个问题，因为：```
nums[i] + 0 == nums[i] - 0
```计算出的答案只是成为原始范围。 

### 相邻元素之间的间隙较大

 最佳分区通常出现在排序数组中的大间隙附近。 

例如：```
nums = [1, 2, 3, 100]
```幼稚的本地策略可能无法确定最佳分割。 该算法正确评估每个分区边界，确保充分考虑大的不连续性。 

### 重复值

 包含许多重复值的数组可能会暴露最小/最大计算中的错误。 

例如：```
nums = [5, 5, 5, 5]
```无论如何修改值，范围都可能保持很小甚至为零。 

由于该算法仅依赖于排序的边界值，因此无需特殊逻辑即可正确处理重复项。
