[LeetCode 第 999 题](https://leetcode.com/problems/available-captures-for-rook/)

 **难度：** 🟢简单
 **主题：** 数组、矩阵、模拟

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个`8 x 8`棋盘表示为字符矩阵。 每个单元格包含四个可能值之一：

 -`'R'`代表白车
 -`'p'`代表一个黑棋子
 -`'B'`代表一位白人主教
 -`'.'`代表一个空的正方形

 棋盘上只有一个车。 任务是确定车一步可以捕获多少个棋子。 

国际象棋中的车可以水平或垂直移动。 它可以继续朝一个方向移动，直到发生以下两种情况之一：

 - 它到达了棋盘的边缘
 - 它遇到了另一块

 车不能穿过棋子。 这是问题中最重要的规则。 如果象或棋子出现在某个方向，车就停在那里，不能继续超越它。 

在以下情况下，棋子被认为是可捕获的：

 - 它与车位于同一行或同一列
 - 车和棋子之间没有棋子

 输入尺寸是固定的，因为板总是`8 x 8`。 这意味着性能并不是一个严重的问题，但我们仍然需要一个干净高效的解决方案。 

约束保证：

 - 电路板尺寸始终有效
 - 只有一只车
 - 每个字符都是该问题的有效国际象棋符号

 一些边缘情况很重要：

 - 主教可以在到达棋子之前阻挡车
 - 一个方向上可能存在多个棋子，但只有第一个可到达的棋子很重要
 - 车可能靠近棋盘边缘
 - 可能根本没有可捕获的棋子
 - 棋子可能存在于主教后面，因此无法到达

 幼稚的实现可能会在击中主教后错误地继续扫描或沿同一方向计算多个棋子。 正确处理阻塞件至关重要。 

## 方法

 ### 蛮力方法

 蛮力策略将单独检查棋盘上的每个棋子。 对于每个棋子，我们可以检查它是否与车共享同一行或同一列，以及它们之间是否存在任何阻挡棋子。 

该算法将按如下方式进行：

 1. 找到车。 
2. 遍历板上的每个方格。 
3. 每当发现棋子时：

 - 检查它是否与车水平或垂直对齐。 
- 扫描车和棋子之间的单元格，以确定主教或另一个棋子是否阻挡了路径。 
4. 计算所有可到达的 pawn。 

这种方法可以正常工作，因为每个 pawn 都经过显式验证。 然而，它执行了不必要的工作。 车只能沿四个方向攻击，因此独立检查每个棋子比需要的更复杂。 

### 最佳方法

 关键的观察是车只与四个方向的棋子交互：

 - 向上
 - 向下
 - 左
 - 右

 一旦我们找到了车，我们就可以独立地模拟它在每个方向上的运动。 

对于每个方向：

 - 一次移动一格。 
- 如果出现以下情况，请立即停止：

 - 我们离开董事会
 - 我们遇到了一位主教
 - 如果我们先遇到一个棋子，则增加答案并停止朝该方向搜索。 

这反映了国际象棋中车的真实移动规则，并避免了不必要的检查。 

由于电路板尺寸很小且固定，因此这种方法非常有效并且很容易推理。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(8² × 8) | O(1) | O(1) | 单独检查每个棋子并扫描路径 |
 | 最佳| O(8²) | O(1) | O(1) | 仅从车的四个方向扫描 |

 ## 算法演练

 1. 首先，扫描整个棋盘以定位车的位置。 存储其行索引和列索引，因为所有未来的移动都源自该正方形。 
2. 定义四个运动方向：

 - 向上：`(-1, 0)`- 向下：`(1, 0)`- 左边：`(0, -1)`- 正确的：`(0, 1)`3. 对于每个方向，从车的位置开始，每次移动一步。 
4. 每一步：

 - 计算下一行和下一列。 
- 如果新位置在棋盘外，则停止沿该方向搜索，因为车无法进一步移动。 
- 如果单元格包含主教`'B'`，停止搜索，因为主教阻止移动。 
- 如果单元格包含棋子`'p'`，增加捕获计数并停止搜索，因为车捕获了第一个可到达的 pawn。 
5. 对所有四个方向继续此过程。 
6. 返回可捕获棋子的总数。 

### 为什么它有效

 车在四个基本方向上独立移动。 在国际象棋中，在一个方向上遇到的第一个棋子完全决定了接下来会发生什么：

 - 如果它是象，则移动停止，并且不能捕获超出其范围的棋子。 
- 如果它是一个棋子，则该棋子是可捕获的并且运动停止在那里。 

通过从车向外扫描，就像车在真实游戏中的移动一样，该算法保证每个可捕获的棋子都被精确计数一次。 

## Python 解决方案```python
from typing import List

class Solution:
    def numRookCaptures(self, board: List[List[str]]) -> int:
        rook_row = -1
        rook_col = -1

        # Locate the rook
        for row in range(8):
            for col in range(8):
                if board[row][col] == 'R':
                    rook_row = row
                    rook_col = col
                    break

            if rook_row != -1:
                break

        captures = 0

        # Four directions: up, down, left, right
        directions = [
            (-1, 0),
            (1, 0),
            (0, -1),
            (0, 1)
        ]

        for dr, dc in directions:
            row = rook_row + dr
            col = rook_col + dc

            while 0 <= row < 8 and 0 <= col < 8:
                if board[row][col] == 'B':
                    break

                if board[row][col] == 'p':
                    captures += 1
                    break

                row += dr
                col += dc

        return captures
```实施从定位车开始。 由于问题保证只有一个车，所以一旦找到它我们就停止搜索。 

定位车后，代码定义了四个可能的移动方向。 每个方向都表示为行和列偏移。 

对于每个方向，算法都会从车一步步向外移动。 这`while`循环确保运动保持在棋盘边界内。 

循环内部：

 - 主教立即终止该方向的搜索，因为车无法穿过该方向。 
- 棋子会增加答案并终止搜索，因为只有第一个可到达的棋子很重要。 
- 空单元格允许扫描继续。 

最后，返回捕获的总数。 

## 解决方案```go
func numRookCaptures(board [][]byte) int {
    rookRow, rookCol := -1, -1

    // Locate the rook
    for r := 0; r < 8; r++ {
        for c := 0; c < 8; c++ {
            if board[r][c] == 'R' {
                rookRow = r
                rookCol = c
                break
            }
        }

        if rookRow != -1 {
            break
        }
    }

    captures := 0

    directions := [][]int{
        {-1, 0},
        {1, 0},
        {0, -1},
        {0, 1},
    }

    for _, dir := range directions {
        dr, dc := dir[0], dir[1]

        row := rookRow + dr
        col := rookCol + dc

        for row >= 0 && row < 8 && col >= 0 && col < 8 {
            if board[row][col] == 'B' {
                break
            }

            if board[row][col] == 'p' {
                captures++
                break
            }

            row += dr
            col += dc
        }
    }

    return captures
}
```Go 实现遵循与 Python 版本相同的逻辑。 主要区别在于使用`[][]byte`而不是字符串列表。 因此，字符比较使用字节文字，例如`'R'`,`'B'`， 和`'p'`。 

Go 切片自然适合表示棋盘，除了几个整数变量之外不需要额外的内存分配。 

整数溢出不是问题，因为最大答案只有 4。

 电路板尺寸固定为`8 x 8`，因此该算法在恒定时间内有效运行。 更一般地，对于一个`n x n`板，复杂度为`O(n²)`因为我们可能会扫描一次棋盘来找到车，然后最多遍历一遍`n`四个方向中每个方向的细胞。 

该算法使用恒定的额外空间，因为它仅存储坐标、计数器和方向向量。

 ## 边缘情况

 ### 紧邻车的主教

 当主教直接在相邻方格上包围车时，就会出现一种重要的边缘情况。 有缺陷的实现可能会继续扫描主教并错误地计算他们后面的棋子。 

该实现正确地处理了这个问题，因为遇到主教会立即触发`break`，终止该方向的搜索。 

### 多个棋子朝同一方向

 当多个棋子沿着一条线出现时，会发生另一种微妙的情况。 在真正的国际象棋中，车只能吃掉遇到的第一个棋子。 一个幼稚的实现可能会计算行或列中的每个棋子。 

该算法通过在捕获某个方向上的第一个棋子后立即停止来避免这种情况。 

### 车位于棋盘边缘附近

 当车开始靠近边界或角落时，粗心的索引处理可能会导致越界访问错误。 

该实现使用以下条件来防止这种情况发生：```
while 0 <= row < 8 and 0 <= col < 8:
```这保证了在读取单元之前每个板访问都是有效的。 

### 除车外的空棋盘

 如果棋盘上任何地方都不存在棋子，则正确答案是`0`。 一些实现意外地假设至少存在一个 pawn。 

当前的解决方案自然地处理这种情况，因为所有定向扫描都会终止而不增加计数器。
