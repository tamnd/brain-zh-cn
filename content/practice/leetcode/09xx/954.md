[LeetCode 954 题](https://leetcode.com/problems/array-of-doubled-pairs/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、贪心、排序

 ## 解决方案

 ## 问题理解

 问题询问是否可以对偶数长度的数组进行重新排序`arr`整数，使得每个元素都可以与另一个恰好是其值两倍的元素配对。 换句话说，重新排序后，对于每个索引`i`在数组的前半部分，`arr[2 * i + 1]`应该等于`2 * arr[2 * i]`。 

输入是整数数组，可以是正数、负数或零。 输出是一个布尔值：`true`如果存在有效的重新排序，`false`否则。 

约束告诉我们，数组可能非常大，最多可达 30,000 个元素，因此比 O(n log n) 更差的算法可能会太慢。 输入数组保证具有偶数长度，这确保在值允许的情况下理论上可以进行配对。 边缘情况包括带有零、负数、重复数字或无法形成所需双对的数字的数组。 

## 方法

 暴力方法将尝试生成数组的所有可能排列，并检查其中是否有任何排列满足加倍条件。 虽然这可以保证给出正确的答案，但排列的数量随着数组的长度呈阶乘增长，对于长度高达 30,000 的数组来说完全不切实际。 

最佳解决方案的关键见解是考虑**频率计数和按绝对值排序**。 我们可以计算每个数字出现的次数，并尝试将每个数字与其双精度数配对，而不是尝试所有排列。 按绝对值排序可确保我们正确处理负数（例如，仅当我们在 -4 之前处理 -2 时，将 -2 与 -4 配对才有效）。 这种方法使用哈希映射进行计数，并使用贪婪策略进行配对，从而提供了更有效的解决方案。

 ## 算法演练

 1. 初始化一个哈希图，统计数组中每个整数出现的频率。 
2. 按绝对值对数组进行排序。 按绝对值排序可确保较小的数字（包括负数）在其双精度数之前配对。 
3. 迭代排序数组中的每个数字：

 1. 如果当前号码的频率为零，则跳过该号码，因为该号码已经配对。 
2. 检查频率图中是否存在当前数字的两倍并且计数为正。 
3、如果不存在或者计数不足，则返回`false`因为有效的配对是不可能的。 
4. 如果存在，则减少当前数字及其双倍数的频率以将它们标记为配对。 
4. 如果所有号码都配对成功，则返回`true`。 

**为什么有效**：通过按绝对值排序，我们确保每个数字都与尚未使用的最小可能的双精度数配对。 这保证了没有有效合作伙伴的号码不会被留下，从而满足问题的要求。 

## Python 解决方案```python
from collections import Counter
from typing import List

class Solution:
    def canReorderDoubled(self, arr: List[int]) -> bool:
        count = Counter(arr)
        for x in sorted(arr, key=abs):
            if count[x] == 0:
                continue
            if count[2 * x] == 0:
                return False
            count[x] -= 1
            count[2 * x] -= 1
        return True
```该实现首先构建数组中所有元素的频率图。 然后，它按绝对值递增的顺序处理每个数字，以确保负数正确配对。 对于每个数字，它检查其双倍是否可用。 如果不是，函数返回`false`。 否则，它会通过减少计数来将两个数字标记为已使用。 如果所有数字都配对成功，则函数返回`true`。 

## 解决方案```go
import "sort"

func canReorderDoubled(arr []int) bool {
    count := make(map[int]int)
    for _, num := range arr {
        count[num]++
    }
    
    sort.Slice(arr, func(i, j int) bool {
        a, b := arr[i], arr[j]
        if a < 0 {
            a = -a
        }
        if b < 0 {
            b = -b
        }
        return a < b
    })
    
    for _, x := range arr {
        if count[x] == 0 {
            continue
        }
        if count[2*x] == 0 {
            return false
        }
        count[x]--
        count[2*x]--
    }
    
    return true
}
```Go 版本反映了 Python 方法。 它使用地图来计算频率并`sort.Slice`按绝对值排序。 主要区别在于 Go 对映射访问和切片排序的处理，但算法逻辑保持不变。

 ## 边缘情况

 一个关键的边缘情况是包含零的数组。 由于 0 加倍仍然是 0，因此我们需要偶数个零来组成对。 该实现通过频率图自动处理这个问题。 

负数是另一个潜在的陷阱。 如果不按绝对值排序，算法可能会尝试错误地将较大的负数与其较小的双精度数配对。 按绝对值排序可确保正确的贪婪配对。 

最后，重复的数字会使配对变得复杂，特别是当同一个数字出现多次但其双倍出现的数量不足时。 哈希映射确保每个元素仅使用一次，避免过度计数和错误配对。
