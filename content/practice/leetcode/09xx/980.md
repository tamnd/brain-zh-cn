[LeetCode 980 题](https://leetcode.com/problems/unique-paths-iii/)

 **难度：** 🔴难
 **主题：** 数组、回溯、位操作、矩阵

 ## 解决方案

 ## 问题理解

 这个问题要求我们在非常严格的移动规则下计算网格中有效路径的数量。 我们得到一个矩阵，其中每个单元格都有特殊含义：

 -`1`是起始位置
 -`2`是结束位置
 -`0`是一个我们可以行走的空广场
 -`-1`是无法访问的障碍物

 我们只能朝四个方向移动：上、下、左、右。 

重要的要求不仅仅是到达终点方块。 有效路径必须恰好访问每个无障碍方格一次。 这意味着该路径的行为类似于网格中所有可遍历单元格的哈密顿路径。 

就总单元格而言，输入大小相对较小：```
1 <= m * n <= 20
```这个约束极其重要。 最多包含 20 个单元的网格表明指数算法可能仍然可行，尤其是在修剪或回溯的情况下。 

输出是一个整数，表示从起点到终点满足所有条件的有效路径的总数。 

一些边缘情况很重要：

 - 开始和结束可能出现在网格中的任何位置。 
- 障碍物可能会隔离棋盘的区域。 
- 某些网格可能根本没有有效路径。 
- 太早到达结束方格的路径是无效的，因为仍然必须访问每个空方格。 
- 起始方格也算作必须访问一次的方格。 
- 结束方格必须被访问一次，并且只有在所有其他有效单元格都被覆盖之后。 

简单的实现很容易犯错误：

 - 重新审视细胞，
 - 到达终点方块后立即停止，
 - 忘记计算起始方格，
 - 或未能正确回溯。 

## 方法

 ### 蛮力方法

 暴力解决方案从起始方格开始尝试所有可能的路径。 在每一步中，它都会递归地探索所有四个方向并跟踪已经访问过的单元格。 

每当递归到达结束方块时，它都会检查每个无障碍方块是否都被访问过一次。 如果是，则该路径有贡献`1`到答案。 

这种方法是正确的，因为它系统地枚举了每一种可能遵守运动规则的行走。 

然而，搜索空间增长极其迅速。 在最坏的情况下，每一步都会分支到多个方向，从而产生阶乘式增长。 由于每个单元可能导致几种未来的可能性，因此即使对于中等大小的网格，路径总数也会变得巨大。 

如果没有仔细的修剪和有效的状态管理，蛮力方法就会变得太慢。 

### 最佳方法，用剩余细胞计数回溯

 关键的观察是，我们只关心访问每个无障碍方格一次的路径。 

我们可以维护仍待访问的有效方格的数量，而不是重复检查整个棋盘。 

该算法的工作原理如下：

 - 计算所有无障碍物的方块。 
- 从起始单元开始 DFS。 
- 将单元格标记为遍历过程中访问过的单元格。 
- 每当我们输入新单元格时，减少剩余单元格计数器。 
- 当我们到达结束方块时，仅当剩余计数变为零时路径才有效。 

这将问题转化为经典的回溯搜索。 

约束足够小，带回溯的 DFS 在实践中足够高效。 由于网格最多包含 20 个单元，因此通过修剪进行详尽的探索是可以接受的。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(4^(m*n)) | O(4^(m*n)) | O(m*n) | 探索所有可能的行走而无需高效修剪 |
 | 最佳 | O(4^(m*n)) 最坏情况 | O(m*n) | 通过访问状态修剪和剩余单元跟踪进行回溯 |

 尽管两种方法具有相同的理论上限，但优化的回溯解决方案的性能显着提高，因为无效路径会提前终止。 

## 算法演练

 1.遍历网格一次，定位：

 - 起始位置，
 - 以及非障碍细胞的总数。 

我们计算每个不存在的细胞`-1`因为这些单元中的每一个最终都必须被恰好访问一次。 
2. 定义四个运动方向：

 - 向上，
 - 下来，
 - 左，
 - 对。 
3. 从起始单元格开始深度优先搜索。 
4. DFS内部：

 - 首先验证当前位置是否在网格内。 
- 如果单元格是障碍物或已经访问过，则拒绝移动。 
5. 如果当前单元格是结束方块：

 - 检查这是否是最终所需的单元格。 
- 如果剩余计数等于`1`，这意味着每个无障碍方格都被访问过一次。 
- 返回`1`为有效路径。 
- 否则返回`0`。 
6. 将当前单元格标记为已访问。 

- 一种常见的技术是暂时用以下内容替换其值`-1`。 
7. 递归地探索所有四个相邻单元。 

- 每次递归调用都会将剩余单元格计数减一。 
8. 对递归调用返回的所有有效路径求和。 
9. 通过恢复原始单元格值进行回溯。 

- 这很重要，因为其他递归分支仍然需要使用该单元。 
10. 返回从当前位置发现的有效路径的总数。 

### 为什么它有效

 该算法保持了一个重要的不变量：

 > 每个递归 DFS 调用都代表一条仅访问过一组唯一单元格一次的路径。 

由于单元在进入时立即被标记为已访问并在回溯期间恢复，因此没有路径可以重新访问单元。 剩余单元计数器保证仅当所有有效方格都被覆盖时才接受结束方格。 由于 DFS 会探索每一个可能的有效移动序列，因此每条合法路径都会被精确计数一次。 

## Python 解决方案```python
from typing import List

class Solution:
    def uniquePathsIII(self, grid: List[List[int]]) -> int:
        rows = len(grid)
        cols = len(grid[0])

        start_row = 0
        start_col = 0
        non_obstacle_cells = 0

        for r in range(rows):
            for c in range(cols):
                if grid[r][c] != -1:
                    non_obstacle_cells += 1

                if grid[r][c] == 1:
                    start_row = r
                    start_col = c

        directions = [
            (1, 0),
            (-1, 0),
            (0, 1),
            (0, -1),
        ]

        def dfs(row: int, col: int, remaining: int) -> int:
            if (
                row < 0
                or row >= rows
                or col < 0
                or col >= cols
                or grid[row][col] == -1
            ):
                return 0

            if grid[row][col] == 2:
                return 1 if remaining == 1 else 0

            original_value = grid[row][col]
            grid[row][col] = -1

            total_paths = 0

            for dr, dc in directions:
                next_row = row + dr
                next_col = col + dc

                total_paths += dfs(next_row, next_col, remaining - 1)

            grid[row][col] = original_value

            return total_paths

        return dfs(start_row, start_col, non_obstacle_cells)
```该实现首先扫描网格以计算所有非障碍单元并定位起始位置。 

这`non_obstacle_cells`变量很关键，因为它代表在路径被认为完整之前必须访问多少个单元格。 

DFS 函数执行递归回溯。 第一个条件处理无效的移动，例如：

 - 离开董事会，
 - 跨过障碍物，
 - 或重新访问之前访问过的单元格。 

当算法到达结束方块时，它会检查是否正好存在一个剩余单元格。 剩余的单元格对应于结束方块本身。 如果是这样，则该路径有效。 

然后将当前单元格标记为已访问，将其值替换为`-1`。 这避免了需要单独的访问矩阵。 

递归探索所有四个方向并累积成功路径的数量。 

最后，单元格值在回溯期间被恢复，以便将来的递归分支可以正确地重用它。 

## 解决方案```go
func uniquePathsIII(grid [][]int) int {
    rows := len(grid)
    cols := len(grid[0])

    startRow, startCol := 0, 0
    nonObstacleCells := 0

    for r := 0; r < rows; r++ {
        for c := 0; c < cols; c++ {
            if grid[r][c] != -1 {
                nonObstacleCells++
            }

            if grid[r][c] == 1 {
                startRow = r
                startCol = c
            }
        }
    }

    directions := [][]int{
        {1, 0},
        {-1, 0},
        {0, 1},
        {0, -1},
    }

    var dfs func(int, int, int) int

    dfs = func(row int, col int, remaining int) int {
        if row < 0 || row >= rows || col < 0 || col >= cols || grid[row][col] == -1 {
            return 0
        }

        if grid[row][col] == 2 {
            if remaining == 1 {
                return 1
            }
            return 0
        }

        originalValue := grid[row][col]
        grid[row][col] = -1

        totalPaths := 0

        for _, dir := range directions {
            nextRow := row + dir[0]
            nextCol := col + dir[1]

            totalPaths += dfs(nextRow, nextCol, remaining-1)
        }

        grid[row][col] = originalValue

        return totalPaths
    }

    return dfs(startRow, startCol, nonObstacleCells)
}
```Go 实现遵循与 Python 解决方案相同的算法结构。 

一个区别是 Go 需要显式函数变量声明来实现递归闭包。 DFS 函数使用以下方式声明：```go
var dfs func(int, int, int) int
```网格本身针对已访问标记进行了适当修改，与 Python 版本完全相同。 由于 Go 切片是基于引用的，因此递归调用都在相同的底层网格结构上运行。 

不存在整数溢出问题，因为有效路径的数量对于 Go 的标准来说仍然足够小`int`给定约束下的类型。

 ## 边缘情况

 当过早到达结束方块时会出现一种重要的边缘情况。 简单的解决方案可能会立即将此类路径视为有效。 然而，该问题要求每个无障碍方格都被恰好访问一次。 该实现通过检查是否正确处理这个问题`remaining == 1`在接受结束方块之前。 

另一个棘手的情况涉及由障碍物造成的孤立区域。 一些网格在开始处包含看起来有效的路径，但最终在所有单元格都可以被访问之前捕获遍历。 因为DFS探索了每一条可能的路线并正确回溯，这样的死胡同分支自然会返回`0`。 

第三个微妙的情况是意外地重新访问细胞。 如果没有正确的访问跟踪，递归 DFS 可能会进入无限循环或过度计数路径。 该实现通过暂时将访问过的单元标记为来防止这种情况发生`-1`。 由于在回溯期间恢复了原始值，因此每个递归分支独立地看到正确的板状态。 

最后的边缘情况涉及非常小的网格，例如单行或单列板。 这些布局可能会暴露索引错误或不正确的移动逻辑。 DFS 内部的边界检查确保所有越界移动都被安全拒绝。
