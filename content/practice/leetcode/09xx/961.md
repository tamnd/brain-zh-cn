 ## 解决方案

 ## 问题理解

 问题给了我们一个整数数组`nums`其长度正好是`2 * n`。 数组中的所有数字中，有`n + 1`独特的价值观。 一个特殊值恰好出现`n`次，而其他所有值仅出现一次。 

我们的任务是识别并返回重复出现的值。 

思考这个问题的另一种方式是这样的：

 - 该数组包含一个“主导”数字。 
- 该数字出现多次，特别是数组总长度的一半。 
- 其他每个数字都只出现一次。 

例如，考虑：```
nums = [2,1,2,5,3,2]
```数组长度为`6`， 所以`n = 3`。 

价值`2`出现`3`次，匹配`n`。 其他数字每隔一次出现一次。 因此，答案是`2`。 

限制相对较小：

 -`2 <= n <= 5000`- 最大数组大小为`10000`- 值范围为`0`到`10^4`这些限制告诉我们，即使`O(n^2)`解决方案在技术上会通过，因为`10000^2`在许多环境中操作仍然是可管理的。 然而，该问题旨在鼓励更有效的解决方案。 

一项重要的保证是始终存在一个有效的重复元素。 这意味着我们永远不需要处理模棱两可的情况或不存在答案的情况。 

尽早识别一些边缘情况很重要：

 - 重复的元素可能连续出现，例如`[3,3,1,2]`- 重复的元素可能分散在整个数组中，例如`[5,1,5,2,5,3,5,4]`- 重复值可以是`0`- 最小有效输入大小是长度`4`- 重复元素可能在遍历中出现得很早或很晚

 因为该问题保证恰好出现一个重复值`n`有时，一旦检测到重复项，我们就可以立即安全返回。 

## 方法

 ### 蛮力方法

 暴力解决方案将每个元素与其他元素进行比较。 

对于每个索引`i`，我们扫描数组的剩余部分并计算次数`nums[i]`出现。 如果其频率大于`1`，我们知道它是重复元素，因为所有其他元素都只出现一次。 

这种方法之所以有效，是因为该问题保证只有一个值出现多次。 

然而，该方法效率低下，因为它会重复扫描数组。 使用嵌套循环，总时间复杂度变为二次。 

### 最佳解决方案的关键见解

 关键的观察是我们实际上不需要完全计算频率。 

由于所有非重复值都只出现一次，因此我们遇到两次的第一个值必定是重复元素。 

这自然建议使用哈希集：

 - 从左到右遍历数组
 - 将每个以前见过的数字存储在一组中
 - 如果当前数字已存在于集合中，则立即返回

 哈希集提供平均值`O(1)`查找时间，使整个算法呈线性。

 ## 算法演练

 1. 创建一个名为的空哈希集`seen`。 

该集合将存储我们已经处理过的所有数字。 哈希集是理想的选择，因为成员资格检查平均来说非常快。 
2. 迭代中的每个数字`nums`。 

我们一次处理一个数组元素。 
3. 对于当前号码，检查是否已存在`seen`。 

- 如果是，我们就找到了重复的元素。 
- 立即归还。 

这是有效的，因为每个不重复的数字都只出现一次。 
4. 如果该号码尚未在集合中，请将其插入到`seen`。 

这记录了我们现在遇到的值。 
5. 继续，直到找到重复项。 

该问题保证只有一个元素重复`n`次，因此算法将始终返回一个值。 

### 为什么它有效

 正确性取决于问题保证除一个值之外的每个值都恰好出现一次。 

当我们遍历数组时：

 - 第一次出现的数字被添加到集合中
 - 任何第二次出现都必须属于重复元素，因为其他值不能出现多次

 因此，遇到的第一个重复项肯定是正确答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def repeatedNTimes(self, nums: List[int]) -> int:
        seen = set()

        for number in nums:
            if number in seen:
                return number

            seen.add(number)

        return -1
```实现首先创建一个名为的空集`seen`。 该集合跟踪遍历期间遇到的每个值。 

这`for`循环对数组中的每个数字只处理一次。 在将数字插入集合之前，算法会检查该数字是否已存在。 

如果该值已经存在，则意味着我们遇到了重复元素，因此函数立即返回它。 

否则，该数字将被添加到集合中并继续遍历。 

决赛`return -1`语句在技术上是不必要的，因为问题保证了有效的答案，但它满足了Python所有执行路径都返回一个值的要求。 

## 解决方案```go
func repeatedNTimes(nums []int) int {
    seen := make(map[int]bool)

    for _, number := range nums {
        if seen[number] {
            return number
        }

        seen[number] = true
    }

    return -1
}
```Go 解决方案遵循与 Python 实现相同的逻辑。 

由于 Go 没有内置的集合类型，因此我们使用`map[int]bool`。 映射键代表我们已经看到的值。 

迭代期间：

 - 如果`seen[number]`已经是`true`，我们返回重复的
 - 否则，我们将号码存储在地图中

 不存在整数溢出问题，因为约束非常小。 尽管该问题保证了有效的非空输入，但该解决方案也适用于类似空的边缘行为。

 ## 边缘情况

 一种重要的边缘情况是最小输入大小。 最小的有效数组有长度`4`， 意义`n = 2`。 例如：```
[1,2,2,3]
```有缺陷的实现可能会错误地假设较大的输入大小或依赖于多次重复的遭遇。 哈希集方法立即起作用，因为它只需要一次重复出现即可识别答案。 

当重复值是时，会出现另一个重要的边缘情况`0`。 一些实现意外地对待`0`作为特殊的虚假值或无法将其正确存储在映射或集合中。 由于该算法使用标准哈希集成员资格检查，`0`与任何其他整数的处理方式完全相同。 

第三种边缘情况是重复元素连续出现在数组的开头，例如：```
[7,7,1,2]
```一些依赖于间隔模式或延迟检测的算法可能会在这里失败。 哈希集解决方案在第二次迭代时正确检测到重复项并立即返回。 

当重复元素分布在整个数组而不是聚集在一起时，会发生另一种微妙的情况。 例如：```
[5,1,5,2,5,3,5,4]
```该实现不依赖于邻接。 它仅依赖于某个值之前是否见过，因此分布模式不会影响正确性。
