 **难度：** 🟡 中等
 **主题：** 数组、哈希表、数学、位操作

 ## 解决方案

 ## 问题理解

 该问题提出了一个模拟场景，其中有一排恰好有 8 个牢房，其中每个牢房要么被占用 (1)，要么空置 (0)。 每天，细胞的状态都会根据其直接邻居的状态而变化。 具体来说，如果一个单元格的两个邻居都处于相同状态（都被占用或都空闲），则该单元格将被占用，否则将变为空闲。 该行中的第一个和最后一个单元格只有一个邻居，因此不能满足两个邻居的条件，因此它们的更新始终基于邻居的规则（实际上，如果遵循标准规则，它们总是在第一天之后变为空置）。 输入是代表细胞初始状态的 8 个整数和一个整数的列表`n`代表要模拟的天数。 预期输出是之后细胞的状态`n`天。 

就单元格数量而言，约束很小（始终为 8），但是`n`可以非常大，最多$10^9$。 这意味着每天的暴力模拟对于大数据来说太慢了`n`。 关键的见解是，在状态数量有限（2^8 = 256 种可能的配置）的情况下，系统最终必须进入一个循环，这使我们能够有效地计算最终状态，而无需模拟所有状态`n`天。 

重要的边缘情况包括最小的`n = 1`，最大的`n = 10^9`、所有单元最初都相同的配置（全 0 或全 1）以及交替模式（例如，`[0,1,0,1,0,1,0,1]`）可能会立即揭示周期。 

## 方法

 暴力方法按顺序模拟每一天。 每天，通过对每个单元应用邻居规则来创建新的单元状态列表。 该方法简单且保证正确性，因为它直接实现问题陈述。 然而，随着`n`最多$10^9$，日复一日地迭代是不可行的，因为它需要太多的操作。 

最佳方法利用了 8 个单元只有 256 种可能状态这一事实。 通过将之前看到的状态及其发生的日期存储在哈希图中，我们可以检测循环。 一旦检测到循环，我们就可以计算余数`n`对循环长度取模并仅模拟剩余的步骤，从而大大减少迭代次数。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n * 8) = O(n) | O(8) = O(1) | O(8) = O(1) | 按顺序模拟每一天； 对于小 n 可行，但对于大 n 则不可行。 |
 | 最佳 | O(循环长度) ≤ O(256) | 奥(256) | 检测重复状态以避免完全模拟； 使用哈希映射来存储以前的状态。 |

 ## 算法演练

 1. 初始化一个哈希映射来存储以前看到的状态，将每个状态映射到它发生的日期。 另外，初始化一个变量来跟踪当天。 
2. 将初始单元列表转换为元组，以便可以将其用作映射中的可哈希键。 
3. 迭代同时`n > 0`。 在每次迭代中，检查当前状态是否以前见过。 如果有，则将周期长度计算为当前日期与首次出现日期之间的差异，并减少`n`对周期长度取模。 
4. 对于每一天，通过应用以下规则计算下一个状态：如果每个单元格（第一个和最后一个单元格除外）的邻居都相同，则它被占用； 否则，它将成为空缺。 将第一个和最后一个单元设置为 0，因为它们只有一个邻居。 
5.更新当前状态并减量`n`1. 将当前状态与当前日期一起存储在哈希映射中。 
6. 重复直到`n`达到 0。以列表形式返回当前状态。 

**为什么有效**：由于只有 256 种可能的状态，因此保证了一个循环。 通过检测环路，该算法减少了冗余模拟。 应用邻居规则可确保状态之间的转换与问题的规则一致，并分别处理第一个和最后一个单元可防止边界错误。 

## Python 解决方案```python
from typing import List

class Solution:
    def prisonAfterNDays(self, cells: List[int], n: int) -> List[int]:
        seen = {}
        current = tuple(cells)
        
        while n > 0:
            if current in seen:
                cycle_length = seen[current] - n
                n %= cycle_length
            seen[current] = n
            
            if n >= 1:
                next_state = [0] * 8
                for i in range(1, 7):
                    next_state[i] = 1 if current[i-1] == current[i+1] else 0
                current = tuple(next_state)
                n -= 1
        
        return list(current)
```该实现首先将列表转换为元组以进行散列。 这`seen`字典存储状态和相应的剩余天数。 如果检测到循环，`n`以循环长度为模减少，这避免了不必要的计算。 下一个状态是使用邻居规则计算的，而第一个和最后一个单元格设置为 0，因为它们只有一个邻居。 

## 解决方案```go
func prisonAfterNDays(cells []int, n int) []int {
    seen := make(map[string]int)
    current := make([]int, 8)
    copy(current, cells)
    
    for n > 0 {
        key := fmt.Sprint(current)
        if val, ok := seen[key]; ok {
            cycle := val - n
            n %= cycle
        }
        seen[key] = n
        
        if n >= 1 {
            nextState := make([]int, 8)
            for i := 1; i < 7; i++ {
                if current[i-1] == current[i+1] {
                    nextState[i] = 1
                } else {
                    nextState[i] = 0
                }
            }
            current = nextState
            n--
        }
    }
    
    return current
}
```在 Go 中，切片用于当前状态，并且`fmt.Sprint`将切片转换为哈希映射键的字符串。 复制切片可以避免修改输入。 循环和下一个状态计算的处理类似于 Python，为下一个状态显式创建切片。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(256) = O(1) | O(256) = O(1) | 仅存在最多 256 个唯一状态，因此循环检测限制了迭代。 |
 | 空间| O(256) = O(1) | O(256) = O(1) | 哈希图存储多达 256 个状态用于循环检测。 |

 由于只有 8 个单元，状态总数很小且固定，因此时间和空间实际上都是恒定的。
