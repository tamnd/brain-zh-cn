[LeetCode 985 题](https://leetcode.com/problems/sum-of-even-numbers-after-queries/)

 **难度：** 🟡 中等
 **主题：** 数组、模拟

 ## 解决方案

 ## 问题理解

 问题给了我们一个整数数组`nums`和一个名为的更新操作列表`queries`。 每个查询包含两个值：

 -`vali`, 添加量
 -`indexi`，数组中要更新的位置

 对于每个查询，我们必须首先更新数组元素：```
nums[indexi] = nums[indexi] + vali
```应用更新后，我们必须计算数组中当前存在的所有偶数的总和。 每次查询后的结果都存储在输出数组中。 

重要的细节是查询是按顺序处理的。 每次更新都会在下一个查询开始之前永久更改数组。 

例如，如果数组开头为：```
[1,2,3,4]
```偶数的初始和为：```
2 + 4 = 6
```如果查询发生变化`nums[0]`从`1`到`2`，偶数和变为：```
2 + 2 + 4 = 8
```约束告诉我们数组长度和查询数量都可以大到`10^4`。 在每次查询后从头开始重新计算偶数和的简单解决方案需要每次扫描整个数组，这可能会导致大致：```
10^4 * 10^4 = 10^8
```最坏情况下的操作。 对于每个查询仅更改一个元素的问题来说，这是不必要的昂贵的。 

一些边缘情况很重要：

 - 数字可以从奇数变为偶数
 - 数字可以从偶数变为奇数
 - 负偶数仍计入总和
 - 加零仍然需要正确处理
 - 数组只能包含一个元素
 - 查询可能会重复修改同一个索引

 关键的观察结果是每个查询仅影响一个数组元素，因此我们应该增量更新偶数和，而不是完全重新计算它。 

## 方法

 ### 蛮力方法

 暴力解决方案直接模拟问题陈述。 

对于每个查询：

 1. 更新指定元素。 
2. 遍历整个数组。 
3. 将所有偶数值相加。 
4. 存储结果。 

这种方法很容易理解，并保证能产生正确的答案，因为它在每次更新后都遵循问题定义。 

然而，其性能较差。 如果有`q`查询并且数组有长度`n`，那么每个查询都需要扫描所有`n`元素。 总复杂度变为`O(n * q)`。 

两个值都可能达到`10^4`，与更优化的方法相比，这可能会变得太慢。 

### 最优增量更新方法

 重要的一点是每个查询仅修改数组中的一个元素。 

我们可以动态维护当前的偶数和，而不是在每次更新后重新计算整个偶数和。 

该过程的工作原理如下：

 - 保留运行变量`even_sum`- 更新元素之前：

 - 如果旧值是偶数，则将其从`even_sum`- 应用更新
 - 更新后：

 - 如果新值是偶数，则将其添加到`even_sum`这是可行的，因为每次查询期间只有一个数字发生变化。 所有其他数组元素保持不变，因此它们对偶数和的贡献保持不变。 

因此，每个查询都会在恒定时间内得到处理。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n × q) | O(1) | O(1) | 每次查询后重新计算偶数和 |
 | 最佳 | O(n + q) | O(1) 额外 | 增量地维持偶数总和 |

 ## 算法演练

 1. 首先计算中所有偶数的初始总和`nums`。 

这为我们提供了代表数组中当前偶数贡献的基线。 
2. 创建一个空结果数组。 

我们将在处理每个查询后附加偶数总和。 
3. 一次处理一个查询。 

每个查询包含：

 -`value`, 添加量
 -`index`,要修改的数组位置
 4. 修改元素前，先检查当前值是否为偶数。 

如果`nums[index]`是偶数，它目前对偶数总和有贡献。 由于值即将发生变化，我们必须首先删除其旧的贡献。 
5. 应用更新。 

使用以下命令更新数组元素：```
nums[index] += value
```6. 更新后，检查新值是否为偶数。 

如果更新后的数字是偶数，则它现在对偶数总和有贡献，因此将其加回去。 
7. 追加当前`even_sum`到答案数组。 

这表示处理当前查询后所有偶数的总和。 
8. 继续，直到处理完所有查询。 
9. 返回答案数组。 

### 为什么它有效

 该算法保持一个不变量：```
even_sum always equals the sum of all even numbers currently in nums
```在每次更新之前，我们都会删除旧值（如果它对总和有贡献）。 更新后，我们会添加新值（如果有贡献）。 

由于每个查询仅更改一个数组元素，因此更新运行总计足以保持正确性，而无需重新扫描整个数组。 

## Python 解决方案```python
from typing import List

class Solution:
    def sumEvenAfterQueries(self, nums: List[int], queries: List[List[int]]) -> List[int]:
        even_sum = sum(num for num in nums if num % 2 == 0)

        answer = []

        for value, index in queries:
            # Remove old contribution if current value is even
            if nums[index] % 2 == 0:
                even_sum -= nums[index]

            # Apply the update
            nums[index] += value

            # Add new contribution if updated value is even
            if nums[index] % 2 == 0:
                even_sum += nums[index]

            answer.append(even_sum)

        return answer
```该实现首先计算数组中所有偶数的初始总和。 此预处理步骤需要一次通过`nums`。 

变量`even_sum`然后在整个算法中保持。 代码不会在每次查询后重新计算总和，而是增量调整该值。 

在循环内部，代码首先检查目标索引处的当前数字是否为偶数。 如果是，则该数字当前对偶数总和有贡献，因此必须在更新发生之前将其删除。 

然后数组元素就地更新。 

更新后，代码检查新值是否为偶数。 如果是这样，它将计入运行总计并重新添加到`even_sum`。 

最后，更新后的偶数和被追加到结果列表中。 

此实现完全遵循前面描述的不变量，并在恒定时间内处理每个查询。 

## 解决方案```go
func sumEvenAfterQueries(nums []int, queries [][]int) []int {
    evenSum := 0

    // Compute initial even sum
    for _, num := range nums {
        if num%2 == 0 {
            evenSum += num
        }
    }

    result := make([]int, 0, len(queries))

    for _, query := range queries {
        value := query[0]
        index := query[1]

        // Remove old contribution if current value is even
        if nums[index]%2 == 0 {
            evenSum -= nums[index]
        }

        // Apply update
        nums[index] += value

        // Add new contribution if updated value is even
        if nums[index]%2 == 0 {
            evenSum += nums[index]
        }

        result = append(result, evenSum)
    }

    return result
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

一个名为`result`预分配的容量等于查询数量，这避免了追加期间不必要的重新分配。 

Go 整数足以满足给定的约束，因此这里不存在溢出问题。 该算法使用直接切片索引和就地更新，与 Python 解决方案完全相同。

 ## 边缘情况

 当数字从偶数变为奇数时，就会出现一种重要的边缘情况。 如果更新前没有删除旧值，很容易出现误操作。 例如，如果`4`变成`5`，偶数总和必须减少`4`。 该实现通过在修改数组之前减去旧值来正确处理此问题。 

当数字从奇数变为偶数时，会发生另一个重要情况。 在这种情况下，更新后的值必须添加到运行总计中。 该实现显式检查更新的值，如果是偶数则添加它。 

负数也会引入微妙的错误。 即使一个数是负数，即使它能被整除，它仍然算作`2`。 例如，`-2`和`-4`必须两者都贡献总和。 该实现直接使用模运算，因此可以正确处理负偶数。 

最后的边缘情况是对同一索引的重复更新。 由于数组是就地修改的，因此每个查询都取决于先前查询的结果。 该实现正确地维护了更新的状态`nums`贯穿整个过程，确保后续操作使用最新值。
