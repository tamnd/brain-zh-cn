[LeetCode 问题 915](https://leetcode.com/problems/partition-array-into-disjoint-intervals/)

 **难度：** 🟡 中等
 **主题：** 数组

 ## 解决方案

 ## 问题理解

 该问题要求我们将数组分成两个连续的部分，`left`和`right`，这样每个值`left`小于或等于中的每个值`right`。 在所有有效分区中，我们必须返回尽可能小的大小`left`。 

连续分区意味着我们选择一个索引并在那里分割数组。 例如，如果分区点位于索引处`k`， 然后：

-`left = nums[0:k+1]`-`right = nums[k+1:]`两个子数组都必须至少包含一个元素，因此分割点不能位于最开头或最末尾。 

关键条件是：```
max(left) <= min(right)
```输出不是子数组本身，而是子数组的长度`left`分割。 

约束条件很重要：

 - 该数组最多可以包含`10^5`元素。 
- 值可以大到`10^6`。 

这些限制立即表明二次解可能会超时。 一个`O(n^2)`算法将执行高达`10^10`在最坏的情况下，操作速度太慢了。 我们需要一个线性或近线性的解决方案。 

一些边缘情况很重要：

 - 具有许多重复值的数组，其中相等性仍必须满足条件。 
- 有效分区发生得很晚的数组。 
- 第一个有效分区也是最佳分区的数组。 
- 包含强制左侧分区扩展的递减段的数组。 
- 最小元素出现在数组中间的情况。 

该问题保证至少有一个有效分区始终存在，这简化了实现，因为我们不需要处理失败情况。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是尝试每个可能的分区点。 

对于每个分割索引`i`，我们计算：

 - 中的最大值`nums[0:i+1]`- 中的最小值`nums[i+1:]`如果：```
max(left) <= min(right)
```那么分区是有效的，并且由于我们从左到右检查，第一个有效分区是可能的最小分区。 

这种方法是正确的，因为它明确地验证了问题所需的确切条件。 然而，重复扫描子阵列的成本很高。 

对于每个分区索引，计算最大值和最小值需要`O(n)`工作，并且有`O(n)`可能的分区。 这导致`O(n^2)`时间复杂度。 

和`n = 100000`，这种方法太慢了。 

### 最佳方法

 重要的观察结果是，分区条件仅取决于：

 - 左侧看到的最大值
 - 右侧剩余的最小值

 我们可以对它们进行预处理，而不是重复地重新计算这些值。 

我们构建一个后缀最小数组，其中：```sql
suffix_min[i] = minimum value from nums[i] to nums[n-1]
```然后，当从左到右扫描时，我们保持：```
left_max = maximum value in nums[0:i]
```在每个位置`i`，我们检查：```
left_max <= suffix_min[i + 1]
```如果为 true，则左侧分区中的每个元素都小于或等于右侧分区中的每个元素。 

因为我们从左到右扫描，所以第一个有效的分割会自动给出尽可能小的左分区。

 ## 算法演练

 1. 创建一个后缀最小数组，名为`suffix_min`。 

这个数组的目的是快速回答这个问题：```
What is the minimum value to the right of index i?
```我们初始化：```
suffix_min[n - 1] = nums[n - 1]
```然后向后填充数组：```
suffix_min[i] = min(nums[i], suffix_min[i + 1])
```经过预处理后，`suffix_min[i]`存储索引中的最小元素`i`到最后。 
2. 初始化`left_max`。 

该变量跟踪当前左侧分区中的最大值。 

最初：```
left_max = nums[0]
```3. 从左到右扫描阵列。 

对于以索引结尾的每个可能的分区`i`:

 - 更新左侧分区中的最大值。 
- 将其与右侧分区中的最小值进行比较。 

具体来说：```
left_max = max(left_max, nums[i])
```然后检查：```
left_max <= suffix_min[i + 1]
```4. 返回第一个有效分区大小。 

如果条件为真，则：

 - 每个值`left`小于或等于中的每个值`right`。 
- 由于我们从左到右扫描，这是最小的有效左分区。 

因此，返回：```
i + 1
```### 为什么它有效

 该算法保持两个关键属性：

 -`left_max`是建议的左分区中的最大值。 
-`suffix_min[i + 1]`是建议的右分区中的最小值。 

如果：```
left_max <= suffix_min[i + 1]
```then every element in the left partition is guaranteed to be less than or equal to every element in the right partition.

 Because the scan proceeds from left to right, the first valid split necessarily produces the smallest possible left partition.

 ## Python 解决方案```python
from typing import List

class Solution:
    def partitionDisjoint(self, nums: List[int]) -> int:
        n = len(nums)

        suffix_min = [0] * n
        suffix_min[n - 1] = nums[n - 1]

        for i in range(n - 2, -1, -1):
            suffix_min[i] = min(nums[i], suffix_min[i + 1])

        left_max = nums[0]

        for i in range(n - 1):
            left_max = max(left_max, nums[i])

            if left_max <= suffix_min[i + 1]:
                return i + 1

        return n
```实施从构建`suffix_min`大批。 每个位置存储从该索引到数组末尾的最小值。 此预处理允许恒定时间访问未来右侧分区中的最小值。 

接下来，算法从左到右扫描，同时保持`left_max`，它表示迄今为止在左侧分区中遇到的最大值。 

在每个位置，算法都会检查左侧的最大值是否小于或等于右侧的最小值。 如果此条件成立，则当前分区有效，并且由于扫描按升序进行，因此它也是最小的有效分区。 

决赛`return n`从技术上讲，语句是不必要的，因为问题保证了有效答案的存在，但它使函数在结构上保持完整。 

## 解决方案```go
func partitionDisjoint(nums []int) int {
    n := len(nums)

    suffixMin := make([]int, n)
    suffixMin[n-1] = nums[n-1]

    for i := n - 2; i >= 0; i-- {
        if nums[i] < suffixMin[i+1] {
            suffixMin[i] = nums[i]
        } else {
            suffixMin[i] = suffixMin[i+1]
        }
    }

    leftMax := nums[0]

    for i := 0; i < n-1; i++ {
        if nums[i] > leftMax {
            leftMax = nums[i]
        }

        if leftMax <= suffixMin[i+1] {
            return i + 1
        }
    }

    return n
}
```Go 实现遵循与 Python 解决方案相同的算法结构。 由于 Go 没有提供内置的`min`和`max`对于整数函数，则使用显式比较。 

切片用于后缀最小数组，整数溢出不是问题，因为约束完全在 Go 的整数范围内。 

该函数假设输入数组非空，这是由问题约束保证的。

 ## 边缘情况

 一种重要的边缘情况是所有值都相等。 例如：```
[2,2,2,2]
```一个常见的错误是使用严格的不平等而不是允许平等。 问题需要：```
left <= right
```不严格小于。 实现正确使用：```
left_max <= suffix_min[i + 1]
```因此可以正确处理相等的值。 

当分区必须延伸到阵列中很远时，就会出现另一个重要的边缘情况。 考虑：```
[5,4,3,2,6]
```如果幼稚的实现仅比较本地邻居而不是全局最大值和最小值，则可能会过早错误地进行分区。 该算法通过维护整个左分区的最大值并将其与整个剩余右分区的最小值进行比较来避免这种情况。 

第三个重要的情况是当一个非常小的值出现在几个较大的值之后时：```
[1,1,1,0,6,12]
```这`0`强制左分区扩展，因为左分区中的每个元素必须保持小于或等于右分区中的每个元素。 该算法正确地处理了这个问题，因为`left_max`即使稍后遇到较小的值，也会保留迄今为止看到的最大值。 

最终的边缘情况是允许的最小输入大小：```
[1,2]
```由于两个分区都必须非空，因此只有一种可能的分割。 该实现自然会处理这个问题，因为循环仅检查最后一个元素之前的有效分区边界。
