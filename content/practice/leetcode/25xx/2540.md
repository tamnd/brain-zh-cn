[LeetCode 问题 2540](https://leetcode.com/problems/minimum-common-value/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表、两个指针、二分查找

 ## 解决方案

 ## 问题理解

 该问题给了我们两个整数数组，`nums1`和`nums2`，并且两个数组都已按非降序排序。 我们的任务是找到两个数组中出现的最小整数。 如果两个数组之间没有共享值，我们必须返回`-1`。 

换句话说，我们需要确定两个排序列表之间的最小公共元素。 一个值只需要在每个数组中至少出现一次就有资格作为通用值。 除了确认值的存在之外，重复出现并不重要。 

例如，如果：```
nums1 = [1,2,3]
nums2 = [2,4]
```数量`2`出现在两个数组中，并且由于它是最小的此类值，因此答案是`2`。 

约束条件很重要：

 - 每个数组最多可以包含`10^5`元素。 
- 值可以大到`10^9`。 
- 两个数组都已排序。 

这些约束立即告诉我们，简单的嵌套循环解决方案可能会变得太慢。 具有复杂性的二次解`O(n × m)`可能需要最多`10^10`在最坏的情况下进行比较，这远远超出了可接受的范围。 

两个数组都已排序这一事实是关键的观察结果。 排序顺序通常允许使用有效的技术，例如两个指针或二分搜索。 

有几个重要的边缘情况需要记住：

 - 数组可能根本没有共同值。 
- 一个数组可能包含重复项。 
- 最小的共同值可能很早就出现。 
- 公共值可能出现在两个数组的末尾附近。 
- 每个数组只能包含一个元素。 

该问题保证两个数组都非空且已排序，因此我们不需要处理空或未排序的输入。 

## 方法

 ### 蛮力方法

 最直接的解决方案是比较每个元素`nums1`中的每个元素`nums2`。 

对于第一个数组中的每个值，我们扫描第二个数组以查找匹配项。 每当我们找到一个共同值时，我们都会记录遇到的最小值。 

这种方法是正确的，因为它详尽地检查了所有可能的元素对。 如果存在共同的价值，它最终会被发现。 

然而，这种方法对于大量输入来说效率极低。 如果两个数组都包含`10^5`元素，该算法可以执行高达`10^10`最坏情况下的比较。 

因此，对于给定的约束，暴力解决方案太慢。 

### 最优方法，两个指针

 数组已经排序，这使得我们可以使用两个指针有效地处理它们。 

我们为每个数组维护一个指针：

 -`i`指向`nums1`-`j`指向`nums2`每一步：

 - 如果`nums1[i] == nums2[j]`，我们找到了最小的公共值并且可以立即返回它。 
- 如果`nums1[i] < nums2[j]`， 然后`nums1[i]`不可能匹配任何未来值`nums2`，因为所有未来值`nums2`大于或等于。 因此，我们移动指针`i`向前。 
- 如果`nums1[i] > nums2[j]`，我们移动指针`j`出于同样的原因前进。 

因为每个指针只向前移动，所以每个元素最多被处理一次。 

这产生了线性时间解。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n × m) | O(1) | O(1) | 比较每对元素 |
 | 最佳| O(n + m) | O(1) | O(1) | 在排序数组上使用两个指针 |

 ## 算法演练

 1.初始化两个指针，`i`和`j`，都开始于`0`。 
2. 当两个指针都保持在各自的数组边界内时继续循环。 
3. 比较当前值：

 -`nums1[i]`-`nums2[j]`4. 如果两个值相等，则立即返回该值。 

由于两个数组都已排序，因此可以保证这是最小的公共值。 
5. 如果`nums1[i]`小于`nums2[j]`, 增量`i`。 

这是有效的，因为较小的值无法匹配第二个数组中的任何后续元素。 
6. 否则，增加`j`。 

第二个数组中较小的值不能与第一个数组中任何后面的元素匹配。 
7. 如果循环结束后没有找到匹配项，则返回`-1`。 

### 为什么它有效

 正确性来自两个数组的排序属性。 

在每一步中，算法都会丢弃较小的值，因为它不可能稍后出现在另一个数组中。 由于指针仅向前移动，因此不会跳过任何潜在的匹配。 

遇到的第一个相等必须是最小公数值，因为所有较小的值都已被消除。 

## Python 解决方案```python
from typing import List

class Solution:
    def getCommon(self, nums1: List[int], nums2: List[int]) -> int:
        i = 0
        j = 0

        while i < len(nums1) and j < len(nums2):
            if nums1[i] == nums2[j]:
                return nums1[i]

            if nums1[i] < nums2[j]:
                i += 1
            else:
                j += 1

        return -1
```该实现首先初始化两个指针，每个指针对应一个数组。 

这`while`只要两个指针仍然有效，循环就会继续。 在循环内，比较当前元素。 

如果值匹配，算法会立即返回该值，因为数组已排序，并且这保证是最小的公共元素。 

如果当前值在`nums1`越小，指针`i`进步。 否则，指针`j`进步。 

最终，要么找到一个公共值，要么一个指针到达其数组的末尾。 如果不存在匹配项，函数返回`-1`。 

## 解决方案```go
func getCommon(nums1 []int, nums2 []int) int {
    i := 0
    j := 0

    for i < len(nums1) && j < len(nums2) {
        if nums1[i] == nums2[j] {
            return nums1[i]
        }

        if nums1[i] < nums2[j] {
            i++
        } else {
            j++
        }
    }

    return -1
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

直接使用切片，并使用整数变量手动管理索引。 由于约束完全符合 Go 的整数范围，因此不存在溢出问题。 

在这种情况下，Go 不会区分空切片和 nil 切片进行长度检查，因此该实现对于所有有效输入都可以正常工作。

 ## 边缘情况

 当数组根本没有共同值时，就会出现一种重要的边缘情况。 粗心的实现可能会意外返回错误的值或超出数组边界。 双指针解决方案可以安全地处理这个问题，因为一旦一个指针到达其数组的末尾，循环就会终止，之后`-1`被返回。 

另一个重要的情况涉及重复值。 例如：```
nums1 = [1,1,2,2]
nums2 = [2,2,3]
```该算法仍然有效，因为重复项不会影响指针的正确性。 指针继续前进，直到找到匹配项。 第一个遇到的共享值仍然是最小公共值。 

当公共值在两个数组中出现得很晚时，就会出现第三种边缘情况。 例如：```
nums1 = [1,2,3,100]
nums2 = [50,60,70,100]
```该实现通过许多不匹配的值正确地推进指针，而无需重新访问较早的元素。 由于每个指针仅向前移动，因此运行时间保持线性。 

另一个微妙的边缘情况是数组相同时。 在这种情况下，第一个元素立即匹配，并且算法返回正确的最小值，而无需进行不必要的处理。
