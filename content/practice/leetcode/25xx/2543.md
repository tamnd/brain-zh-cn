[LeetCode 问题 2543](https://leetcode.com/problems/check-if-point-is-reachable/)

 **难度：** 🔴难
 **主题：** 数学、数论

 ## 解决方案

 ## 问题理解

 该问题给了我们一个无限的二维网格，并询问我们是否可以从起点出发`(1, 1)`到目标点`(targetX, targetY)`使用一组特定的操作。 

从任何一点`(x, y)`，我们可以执行以下四个动作之一：

 - 减法`x`从`y`，生产`(x, y - x)`- 减法`y`从`x`，生产`(x - y, y)`- 双倍的`x`，生产`(2x, y)`- 双倍的`y`，生产`(x, 2y)`任务是确定经过有限次数的操作后是否可以到达目标点。 

输入由两个整数组成：

 -`targetX`，目标x坐标
 -`targetY`，目标 y 坐标

 输出是一个布尔值：

 -`true`如果目标可以达到
 -`false`否则

 约束条件非常重要：```
1 <= targetX, targetY <= 10^9
```因为坐标可能大到十亿，所以通过状态空间进行任何强力搜索都是不可能的。 网格是无限的，并且可到达的中间状态的数量增长得非常快。 

一些观察结果立即引人注目：

 - 坐标始终保持整数。 
- 减法运算类似于计算最大公约数的欧几里得算法。 
- 加倍运算仅引入二的幂。 
-可达性可能取决于一些在有效移动期间永远不会改变的不变属性。 

重要的边缘情况包括：

 - 当一个坐标为`1`- 当两个坐标相等时
 - 非常大的二的幂
 - 最大公约数包含奇数因子的对
 - 最少的输入`(1,1)`这些案例有助于揭示问题背后的数学结构。 

## 方法

 ### 蛮力方法

 一个自然的第一个想法是将问题建模为图搜索。 每个点`(x, y)`是一个节点，每个允许的操作都会创建到另一个节点的边。 

开始于`(1,1)`，我们可以使用 BFS 或 DFS 来探索可达状态，直到我们：

 - 达到`(targetX, targetY)`- 穷举所有可能的状态

 这种方法是正确的，因为图遍历系统地探索了每个有效的操作序列。 

然而，这种方法完全不切实际。 

由于重复的倍增操作，坐标可能会变得非常大。 即使我们施加限制，例如将坐标限制为最多`targetX`和`targetY`，状态的数量仍然是巨大的。 BFS 可能会检查数十亿个点。 

此外，减法运算会创建许多重叠的路径和循环，使状态图高度连接。 

因此，在有限的条件下，暴力破解是行不通的。 

### 关键见解

 关键的见解是，这些运算保留了涉及最大公约数的非常具体的数学属性。 

考虑减法运算：```
gcd(x, y) = gcd(x, y - x)
gcd(x, y) = gcd(x - y, y)
```这些正是欧几里得算法中使用的变换。 

现在考虑加倍运算：```
gcd(2x, y)
gcd(x, 2y)
```加倍可以将 gcd 乘以`2`，但它不能引入任何奇质因数。 

既然我们从`(1,1)`，其最大公约数为：```
gcd(1,1) = 1
```我们可以引入 GCD 的唯一因素是 2 的幂。 

这意味着：```
gcd(targetX, targetY)
```必须是 2 的幂才能达到目标。 

这将整个问题变成了一个简单的数论检查。 

如果 gcd 为：```
1, 2, 4, 8, 16, ...
```那么该点是可达的。 

否则的话，那是不可能的。 

我们可以使用经典的位技巧来检查一个数字是否是 2 的幂：```
g & (g - 1) == 0
```在哪里`g`是gcd。

 ## 算法演练

 ### 最优算法

 1. 计算最大公约数`targetX`和`targetY`。 

减法运算保留 gcd，而加倍运算仅将其乘以 2 的幂。 因此，gcd完全决定了可达性。 
2. 将 gcd 存储在变量中`g`。 

例如：```
g = gcd(targetX, targetY)
```3. 检查是否`g`是二的幂。 

正整数是 2 的幂当且仅当：```
g & (g - 1) == 0
```这是可行的，因为二的幂恰好包含二进制形式的一组位。 
4. 返回该检查的结果。 

如果 gcd 是 2 的幂，则返回`true`。 

否则，返回`false`。 

### 为什么它有效

 关键的不变量是减法运算永远不会改变 gcd，而加倍运算只能将 gcd 乘以`2`。 

因为我们从 gcd 开始`1`，唯一可能达到的 gcd 值是：```
1 * 2^k
```对于一些非负整数`k`。 

因此，当且仅当目标点的 gcd 是 2 的幂时，目标点才是可到达的。 

这个条件既是必要的，也是充分的。 

## Python 解决方案```python
from math import gcd

class Solution:
    def isReachable(self, targetX: int, targetY: int) -> bool:
        common_divisor = gcd(targetX, targetY)
        
        return (common_divisor & (common_divisor - 1)) == 0
```该实现非常紧凑，因为数学洞察消除了模拟或图形遍历的需要。 

首先，我们导入`gcd`来自Python的`math`模块。 这可以使用欧几里德算法有效地计算最大公约数。 

接下来，我们计算：```python
common_divisor = gcd(targetX, targetY)
```这提取了决定可达性的不变属性。 

最后，我们使用以下命令检查 gcd 是否为 2 的幂：```python
(common_divisor & (common_divisor - 1)) == 0
```2 的幂在二进制表示中恰好有一个设置位。 减一会翻转所有低位，因此仅对于 2 的幂，按位 AND 才会变为零。 

该表达式的结果直接返回。 

## 解决方案```go
func isReachable(targetX int, targetY int) bool {
    commonDivisor := gcd(targetX, targetY)

    return (commonDivisor & (commonDivisor - 1)) == 0
}

func gcd(a int, b int) int {
    for b != 0 {
        a, b = b, a%b
    }

    return a
}
```Go 版本遵循与 Python 解决方案相同的逻辑。 

由于Go标准库中没有提供内置的整数gcd函数，因此我们手动实现欧几里德算法。 

两次检查的按位幂在 Go 中的工作方式相同，因为整数直接支持位运算。 

不存在溢出问题，因为约束最多是`10^9`，它很容易适合 Go 的内部`int`在现代平台上输入。

 ## 边缘情况

 一个重要的边缘情况是起点本身，`(1,1)`。 粗心的实施可能会错误地认为成功之前需要进行一些移动。 这里，gcd 是`1`，它是 2 的幂，因此算法正确返回`true`。 

当两个坐标相等时会出现另一个重要的边缘情况，例如`(8,8)`或者`(3,3)`。 在这些情况下，gcd 等于坐标值本身。 这使得结果完全取决于该值是否是 2 的幂。 实现通过 gcd 检查自然地处理这个问题。 

第三个关键边缘情况涉及接近约束上限的非常大的输入。 对于接近的值，暴力搜索将完全失败`10^9`，要么超时，要么耗尽内存。 数学解决方案仍然有效，因为即使对于巨大的数字，欧几里得算法也会以对数时间运行。 

当 gcd 为偶数但不是 2 的纯幂时，会出现微妙的边缘情况，例如`6`或者`10`。 乍一看，加倍运算可能会产生这样的值，但加倍仅引入了 2 的因数。 从gcd开始后，奇质因数永远不会出现`1`。 由于两次检查的幂失败，实现正确地拒绝了这些情况。
