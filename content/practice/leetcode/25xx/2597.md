 **难度：** 🟡 中等
 **主题：** 数组、哈希表、数学、动态规划、回溯、排序、组合

 ## 解决方案

 ## 问题理解

 该问题要求我们计算数组中有多少个非空子集`nums`被认为是“美丽的”。 

如果子集中不存在绝对差等于的两个数字，则子集是美丽的`k`。 

例如，如果`k = 2`，那么子集不能同时包含两者`2`和`4`， 因为：$$|2 - 4| = 2$$同样，它不能同时包含两者`4`和`6`。 

输入包括：

 - 整数数组`nums`- 正整数`k`输出应该是满足条件的非空子集的总数。 

一个重要的细节是子集由索引决定，而不仅仅是由值决定。 如果数组包含重复值，则选择不同的副本将视为不同的子集。 

约束条件极其重要：

 -`nums.length <= 18`- 每个值最多`1000`由于数组长度只有18，所以子集总数为：$$2^{18} = 262144$$该值足够小，指数解是可以接受的。 该观察结果强烈表明回溯或子集枚举是有意为之的。 

一些边缘情况很重要：

 - 具有重复数字的数组
 - 许多对不同的情况`k`- 没有一对有差异的情况`k`- 长度数组`1`- 情况`k`大于任何可能的差异

 例如：

 -`nums = [1,1,1]`,`k = 2`- 每个子集都是美丽的，因为没有差异可以等于 2。 
-`nums = [1,3,5]`,`k = 2`- 由于相邻值相差 2，许多组合变得无效。 
-`nums = [1]`- 单个非空子集有效。 

该问题保证：

 - 所有数字均为正数
 -`k`是积极的
 - 数组大小足够小，可以进行指数探索

 这意味着我们可以安全地使用递归子集生成，而无需冒时间限制问题的风险。 

## 方法

 ### 蛮力方法

 最直接的解决办法就是生成每一个可能的子集，然后检查它是否漂亮。 

有`2^n`子集。 对于每个子集，我们可以比较每对元素并验证没有一对具有绝对差异`k`。 

对于大小的子集`m`，检查有效性成本`O(m^2)`。 

在最坏的情况下：

 - 有`2^n`子集
 - 每个子集最多可以包含`n`元素
 - 有效性检查费用`O(n^2)`因此总复杂度变为：$$O(2^n \cdot n^2)$$这适用于`n <= 18`，但它执行了不必要的重复工作，因为许多无效子集在拒绝之前已被完全探索。 

### 最佳方法

 关键的观察是我们不需要在检查有效性之前生成整个子集。 

相反，在逐步构建子集时，我们可以立即拒绝违反条件的选择。 

假设我们正在考虑是否添加一个值`x`。 

仅当子集已包含以下内容时，该子集才会无效：$$x - k$$或者$$x + k$$因为条件具体是关于绝对差等于`k`。 

我们可以维护当前包含在子集中的数字的频率图。 

添加前`x`，我们简单地检查是否`x - k`子集中已存在。 

为什么只是检查`x - k`充足的？ 

因为我们对元素进行一一处理。 如果`x + k`之前已插入，那么当添加更大的数字时，它已经进行了检查`x`。 在递归构造期间，一次定向检查就足够了。 

这允许立即修剪无效分支。 

由此产生的算法是一个经典的回溯解决方案，使用哈希图进行有效的有效性检查。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n * n^2) | O(2^n * n^2) | O(n) | 生成每个子集，然后分别验证 |
 | 最佳| O(2^n) | O(2^n) | O(n) | 使用频率图进行剪枝回溯 |

 ## 算法演练

 ### 第 1 步：初始化频率图

 我们维护一个名为的哈希图`frequency`。 

该映射存储每个数字当前在正在构建的子集中存在的次数。 

例如：```
Subset: [2, 6]
frequency = {
    2: 1,
    6: 1
}
```该映射允许持续检查冲突。 

### 步骤 2：定义递归回溯函数

 递归函数逐一处理元素。 

在索引处`i`，我们有两个选择：

 1. 跳过`nums[i]`2. 包括`nums[i]`，如果不违反美丽条件

 这自然就形成了二叉决策树。 

### 步骤 3：基本案例

 如果我们到达数组的末尾：```
if index == len(nums):
```那么我们就构建了一个有效的子集。 

我们返回`1`。 

这会计算当前子集配置。 

### 第 4 步：探索“跳过”选项

 我们总是可以选择忽略当前的数字。 

所以我们递归地继续：```
count = backtrack(index + 1)
```### 步骤 5：检查包含是否安全

 假设当前值为：```
value = nums[index]
```仅当出现以下情况时，子集才无效：```
value - k
```子集中已存在。 

所以我们检查：```
if frequency[value - k] == 0:
```如果不存在冲突，我们可以安全地包含该值。 

### 第 6 步：包含值

 我们更新频率图：```
frequency[value] += 1
```然后递归继续：```
count += backtrack(index + 1)
```### 第 7 步：回溯

 递归完成后，我们必须恢复之前的状态。 

所以我们删除该值：```
frequency[value] -= 1
```这确保同级递归分支以正确的子集状态开始。 

### 步骤 8：删除空子集

 递归计算所有子集，包括空子集。 

该问题仅要求非空子集。 

所以最终的答案是：```
backtrack(0) - 1
```### 为什么它有效

 在每个递归步骤中，算法都保持当前子集是美丽的不变量。 

仅当新值不会产生禁止的差异时才会添加`k`。 

由于每个子集都是通过包含/排除决策生成一次，并且永远不会探索无效状态，因此该算法精确地计算所有漂亮的子集。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def beautifulSubsets(self, nums: List[int], k: int) -> int:
        frequency = defaultdict(int)
        n = len(nums)

        def backtrack(index: int) -> int:
            if index == n:
                return 1

            count = backtrack(index + 1)

            value = nums[index]

            if frequency[value - k] == 0:
                frequency[value] += 1
                count += backtrack(index + 1)
                frequency[value] -= 1

            return count

        return backtrack(0) - 1
```该实现严格遵循前面描述的递归决策过程。 

这`frequency`哈希映射跟踪哪些值当前位于子集中。 这使得恒定时间冲突检测成为可能。 

递归函数`backtrack(index)`返回从当前索引开始可以形成的漂亮子集的数量。 

对于每个元素，算法首先探索跳过该元素的分支。 然后它检查包含该元素是否会违反美观条件。 

如果包含是安全的，则将该值添加到频率图中，继续递归，然后在回溯期间删除该值。 

最后，通过减一将空子集从结果中排除。 

## 解决方案```go
func beautifulSubsets(nums []int, k int) int {
	frequency := make(map[int]int)
	n := len(nums)

	var backtrack func(int) int

	backtrack = func(index int) int {
		if index == n {
			return 1
		}

		count := backtrack(index + 1)

		value := nums[index]

		if frequency[value-k] == 0 {
			frequency[value]++

			count += backtrack(index + 1)

			frequency[value]--
		}

		return count
	}

	return backtrack(0) - 1
}
```Go 的实现非常接近地反映了 Python 的逻辑。 

Go 使用一个`map[int]int`而不是Python的`defaultdict(int)`。 丢失的键会自动返回零值，因此不需要显式的存在检查。 

使用以下方法将递归函数声明为闭包：```go
var backtrack func(int) int
```由于 Go 整数在大多数现代系统上都是 64 位的，因此答案的边界为`2^18`，整数溢出不是问题。

 ## 边缘情况

 ### 重复的数字

 包含重复项的数组很容易被错误处理，因为子集是基于索引的，而不是基于值的。 

例如：```
nums = [1,1,1]
k = 2
```所有非空子集都是有效的，因为没有一对相差 2。 

有缺陷的实现可能会意外地将重复项视为相同且计数不足的子集。 

此实现可以正确处理重复项，因为递归独立处理索引，而频率图跟踪计数而不是仅跟踪唯一存在。 

### 无有效配对限制

 考虑：```
nums = [10,20,30]
k = 100
```没有两个数字相差 100。 

因此每个非空子集都是美丽的。 

该算法正确地计算了所有：$$2^n - 1$$可能的非空子集，因为包含检查不会失败。 

### 长冲突链

 考虑：```
nums = [1,3,5,7]
k = 2
```每个数字都与相邻的值冲突。 

幼稚的解决方案可能会意外地允许无效的组合，例如`[1,3]`。 

频率图验证在施工期间立即防止这种情况发生。 在发生更深层次的递归之前，无效分支会被修剪。 

### 空子集处理

 递归自然会计算空子集，因为重复选择“跳过”会到达基本情况。 

然而，该问题明确要求仅非空子集。 

该实现通过从最终计数中减一来仔细处理这个问题。
