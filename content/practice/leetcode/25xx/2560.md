[LeetCode 2560 题](https://leetcode.com/problems/house-robber-iv/)

 **难度：** 🟡 中等
 **主题：** 数组、二分搜索、动态规划、贪心

 ## 解决方案

 ## 问题理解

 该问题描述了这样一种场景：劫匪想要从街道两旁的房屋中偷窃，但有一个限制：**相邻的房屋不能同时被抢劫**。 每个房子都有一定数量的钱，表示为一个数组`nums`，而强盗至少想从**偷东西`k`房屋**。 重要的是，抢劫者的**能力**被定义为所有被抢劫房屋中单个房屋被盗的最大金额。 目标是在所有有效的抢劫方式中**最小化这种能力**`k`房屋。 

输入`nums`是一个整数数组`1 <= nums.length <= 10^5`和`1 <= nums[i] <= 10^9`。 价值`k`满足`1 <= k <= (nums.length + 1) / 2`。 这些约束表明，由于子集的指数数量，检查所有可能组合的强力解决方案是不可行的。 该问题保证总是有可能至少偷窃`k`房屋。 

边缘情况包括房屋数量最少、房屋价值相同的情况，或者`k`正好是房屋数量的一半，这可能会迫使每隔一个房屋挑选一次。 

## 方法

 暴力方法将涉及生成所有不相邻的房屋子集，计算有多少房屋被抢劫，然后计算每个子集的能力。 虽然这保证了正确性，但其复杂度为 **O(2^n)**，这对于`n`最多 10^5。 

关键的见解是**问题简化为决策问题**：对于给定的最大能力`x`，我们可以至少选择`k`房屋中没有两栋是相邻的，并且每栋选定的房屋都有价值`<= x`？ 如果我们可以的话`x`是一种可行的能力。 利用这种洞察力，我们可以对功能应用**二分搜索**。 对于给定的`mid`在二分查找中，我们可以贪婪地遍历数组来计算在不违反邻接性的情况下可以抢劫的最大房屋数量。 如果我们能达到`k`，我们尝试更小的`mid`; 否则，我们增加`mid`。 

这样就将问题转化为**二分查找+贪心选择**，效率高很多。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 检查所有非相邻子集，对于大n | 不可行
 | 二分查找+贪心| O(n log(max(nums))) | O(n log(max(nums))) | O(1) | O(1) | 对能力进行二分搜索，对可行性进行贪心检查 |

 ## 算法演练

 1. 初始化二分查找范围：`low = min(nums)`和`high = max(nums)`。 这些代表了最小和最大的可能能力。 
2. 虽然`low < high`， 计算`mid = (low + high) // 2`。 
3.检查是否至少可以抢劫`k`有能力的房子`mid`使用贪心方法：

 - 迭代`nums`。 
- 维护一个柜台`count`对于被抢劫的房屋。 
- 目前的房子是否有价值`<= mid`，抢劫它并跳过下一个房子（以遵守邻接规则），递增`count`。 
4.如果`count >= k`，这意味着`mid`是一种可行的能力。 更新`high = mid`尝试较小的值。 
5. 如果`count < k`,`mid`太小了。 更新`low = mid + 1`。 
6.一次`low >= high`,`low`是所需的最低能力。 

**为什么有效：** 贪心检查保证我们在给定的条件下最大化被抢劫的房屋数量`mid`因为我们按顺序获取每个符合条件的房屋并跳过下一个以尊重邻接性。 二分查找确保我们找到最小的可行值`mid`高效。 

## Python 解决方案```python
from typing import List

class Solution:
    def minCapability(self, nums: List[int], k: int) -> int:
        def can_rob_with_cap(cap: int) -> bool:
            count = 0
            i = 0
            n = len(nums)
            while i < n:
                if nums[i] <= cap:
                    count += 1
                    i += 2  # skip next house
                else:
                    i += 1
            return count >= k
        
        low, high = min(nums), max(nums)
        while low < high:
            mid = (low + high) // 2
            if can_rob_with_cap(mid):
                high = mid
            else:
                low = mid + 1
        return low
```**实现演练：** 函数`can_rob_with_cap`贪婪地遍历房屋，计算可以被抢劫的房屋数量，如果每个被抢劫的房屋不得超过`cap`。 二分查找调整`low`和`high`基于是否`mid`是可行的。 当循环结束时，`low`代表最小能力。 

## 解决方案```go
func minCapability(nums []int, k int) int {
    canRob := func(cap int) bool {
        count := 0
        i := 0
        n := len(nums)
        for i < n {
            if nums[i] <= cap {
                count++
                i += 2
            } else {
                i++
            }
        }
        return count >= k
    }

    low, high := nums[0], nums[0]
    for _, val := range nums {
        if val < low {
            low = val
        }
        if val > high {
            high = val
        }
    }

    for low < high {
        mid := (low + high) / 2
        if canRob(mid) {
            high = mid
        } else {
            low = mid + 1
        }
    }
    return low
}
```**Go特定注释：** 我们明确计算`low`和`high`而不是使用`min`/`max`功能。 使用切片迭代而不是使用范围索引。 否则，逻辑与 Python 类似。
