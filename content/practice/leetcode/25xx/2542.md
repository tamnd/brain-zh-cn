 # LeetCode 2542 - 最大子序列分数

 ## 问题理解

 该问题给了我们两个整数数组，`nums1`和`nums2`, 两者长度相同`n`，以及一个整数`k`。 我们必须准确选择`k`数组中的索引。 所选索引形成一个子序列，这意味着所选位置来自原始数组，而不修改数组本身。 

对于选定的指数，分数由两部分计算得出：

 1. 相应值的总和`nums1`2. 相应值的最小值`nums2`最终得分为：$$(\text{sum of selected nums1 values}) \times (\text{minimum selected nums2 value})$$我们的目标是最大化这个分数。 

一个关键细节是最小值`nums2`充当整个总和的乘数。 这产生了一个有趣的权衡：

 - 我们希望获得大的价值`nums1`使总和最大化。 
- 我们还想要一个大的最小值`nums2`，因为它乘以总和。 

约束条件很重要：

 -`n`可以大到`100000`- 检查所有子序列的强力解决方案是不可能的
 - 我们需要一些接近的东西`O(n log n)`有效地处理输入大小

 该问题保证：

 - 两个数组的长度相同
 -`k`总是有效的，意思是`1 <= k <= n`- 值是非负整数

 记住几个边缘情况很重要：

 -`k = 1`，其中答案成为最大乘积`nums1[i] * nums2[i]`-`k = n`，其中每个元素都必须被选择
 - 包含零的数组，可以将分数降低到零
 - 大值可能会溢出 32 位整数，尤其是在 Go 中

 ## 方法

 ### 蛮力方法

 最直接的方法是生成每个可能的大小子序列`k`。 对于每个子序列：

 1. 计算所选的总和`nums1`价值观
 2. 计算所选的最小值`nums2`值
 3. 将它们相乘得到分数
 4. 追踪最高分

 这种方法是正确的，因为它评估每个有效的选择。 

然而，它太慢了。 子序列的个数为：$$\binom{n}{k}$$在最坏的情况下，这将变得天文数字般巨大。 即使对于中等值`n`，枚举所有组合是不可行的。 

### 最佳解决方案的关键见解

 关键的观察是，当选择一组指数时，其中的最小值`nums2`决定乘数。 

假设我们决定某个特定元素`nums2`将是所选子序列中的最小值。 然后：

 - 每个选定的`nums2`值必须至少那么大
 - 在所有有效候选人中，我们希望获得最大可能的总金额`nums1`这建议对这些对进行排序`(nums1[i], nums2[i])`按降序排列`nums2`。 

当我们迭代排序对时：

 - 当前`nums2`值成为当前组的最小可能乘数
 - 我们需要选择最好的`k`值来自`nums1`在迄今为止看到的所有元素中

 高效维护最大`k`值来自`nums1`，我们使用最小堆。 

堆允许我们：

 - 只保留最好的`k`候选人
 - 快速删除最小的`nums1`必要时值
 - 有效维持当前金额

 这将问题转化为高效的贪婪+堆解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(C(n, k) * k) | O(C(n, k) * k) | O(k) | 尝试每一个可能的子序列 |
 | 最佳| O(n log k) | O(n log k) | O(k) | 排序+贪婪+最小堆|

 ## 算法演练

 ### 第 1 步：将阵列配对在一起

 创建值对：```
(nums1[i], nums2[i])
```这使相应元素之间的关系保持完整。 

### 第 2 步：排序依据`nums2`按降序排列

 对所有对进行排序`nums2`从最大到最小。 

为什么？ 

因为当处理具有值的对时`nums2 = x`，每个先前见过的元素都有`nums2 >= x`。 

这意味着如果我们选择一个以此位置结束的子序列，则最小`nums2`值将恰好是`x`。 

### 步骤 3：使用最小堆`nums1`我们现在迭代排序对。 

对于每对：

 1. 添加`nums1`值放入最小堆
 2. 将其添加到运行总和中

 堆存储当前选择的`nums1`价值观。 

### 步骤 4：只保留最大的`k`价值观

 如果堆大小超过`k`：

 - 删除最小的元素
 - 从运行总和中减去它

 这保证了堆总是包含最大可能的`k`已处理元素中的值。 

### 步骤 5：计算候选人分数

 每当堆大小恰好变为`k`：

 - 当前`nums2`value 是最小乘数
 - 运行总和是该乘数的最佳总和

 计算：$$\text{score} = \text{currentSum} \times \text{currentNums2}$$如果这个分数更大，请更新答案。 

### 第 6 步：返回最高分数

 处理完所有对后，记录的最大分数就是答案。 

### 为什么它有效

 该算法之所以有效，是因为排序顺序。 在每次迭代中，当前`nums2`value 保证是所有已处理元素中的最小值。 因此，任何使用当前元素的有效子序列都有一个固定的乘数。 

给定固定乘数，最佳策略是最大化所选的总和`nums1`价值观。 最小堆确保我们始终保留最大的可能`k`值来自`nums1`。 

因此，每个可能的最小乘数仅被考虑一次，并且对于每个乘数，我们计算最佳总和。 这保证了全局最优。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def maxScore(self, nums1: List[int], nums2: List[int], k: int) -> int:
        pairs = sorted(
            zip(nums2, nums1),
            reverse=True
        )

        min_heap = []
        current_sum = 0
        best_score = 0

        for num2_value, num1_value in pairs:
            heapq.heappush(min_heap, num1_value)
            current_sum += num1_value

            if len(min_heap) > k:
                removed = heapq.heappop(min_heap)
                current_sum -= removed

            if len(min_heap) == k:
                score = current_sum * num2_value
                best_score = max(best_score, score)

        return best_score
```实现首先将数组组合成对。 请注意，排序顺序使用`nums2`首先，因为该算法围绕固定最小乘数而展开。 

最小堆存储当前选择的`nums1`价值观。 蟒蛇的`heapq`模块提供了高效的最小堆实现。 

变量`current_sum`跟踪当前堆内元素的总和。 这避免了重复重新计算总和。 

每当堆变得大于`k`，我们删除最小的`nums1`价值。 这确保了我们对总和保持最大可能的贡献。 

当堆大小恰好变为`k`，我们使用当前的计算候选分数`nums2`值作为最小乘数。 

最后，返回迭代过程中找到的最大得分。 

## 解决方案```go
package main

import (
	"container/heap"
	"sort"
)

type MinHeap []int

func (h MinHeap) Len() int {
	return len(h)
}

func (h MinHeap) Less(i, j int) bool {
	return h[i] < h[j]
}

func (h MinHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MinHeap) Push(x interface{}) {
	*h = append(*h, x.(int))
}

func (h *MinHeap) Pop() interface{} {
	old := *h
	n := len(old)
	value := old[n-1]
	*h = old[:n-1]
	return value
}

func maxScore(nums1 []int, nums2 []int, k int) int64 {
	n := len(nums1)

	pairs := make([][2]int, n)

	for i := 0; i < n; i++ {
		pairs[i] = [2]int{nums2[i], nums1[i]}
	}

	sort.Slice(pairs, func(i, j int) bool {
		return pairs[i][0] > pairs[j][0]
	})

	minHeap := &MinHeap{}
	heap.Init(minHeap)

	var currentSum int64
	var bestScore int64

	for _, pair := range pairs {
		num2Value := pair[0]
		num1Value := pair[1]

		heap.Push(minHeap, num1Value)
		currentSum += int64(num1Value)

		if minHeap.Len() > k {
			removed := heap.Pop(minHeap).(int)
			currentSum -= int64(removed)
		}

		if minHeap.Len() == k {
			score := currentSum * int64(num2Value)

			if score > bestScore {
				bestScore = score
			}
		}
	}

	return bestScore
}
```Go 实现遵循与 Python 解决方案相同的算法结构。 主要区别在于 Go 需要使用自定义堆实现`container/heap`包裹。 

另一个重要的区别是整数溢出处理。 由于分数可能变得非常大，因此实现使用`int64`求总分和最终分数。 

堆存储常规整数，但所有与分数相关的算术都转换为`int64`。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`k = 1`。 在这种情况下，每个子序列只包含一个元素，因此分数变得简单：$$nums1[i] \times nums2[i]$$有缺陷的实现可能仍会尝试不必要的堆管理逻辑或错误地假设存在多个元素。 当前的实现自然地处理这个问题，因为堆达到了大小`1`立即并正确计算分数。 

另一个重要的情况是当`k = n`。 在这里，必须选择每个元素。 最低`nums2`value 成为整个数组的全局最小值，总和成为所有数组的总和`nums1`价值观。 一些贪婪算法会失败，因为它们试图不必要地丢弃元素。 此实现可以正常工作，因为堆最终包含所有元素并且永远不会删除任何内容。 

包含零的数组也很重要。 如果选择最小值`nums2`值为零，则无论总和如何，整个分数都为零。 同样，如果全部选择`nums1`值总和为零，分数也为零。 该算法无需任何特殊逻辑即可处理此问题，因为乘法自然会产生正确的结果。 

大整数值是错误的另一个微妙来源，尤其是在 Go 中。 分数可以超出 32 位整数的范围：$$100000 \times (100000 \times 100000)$$这比`2^31 - 1`。 因此，Go 解决方案使用`int64`用于所有与分数相关的计算，以防止溢出。
