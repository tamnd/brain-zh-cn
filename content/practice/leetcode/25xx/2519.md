 # LeetCode 2519 - 计算 K-Big 指数的数量

 ## 问题理解

 这个问题要求我们确定数组中有多少个索引满足与两侧较小值相关的非常特定的条件。 

对于一个索引`i`有待考虑`k-big`，两个单独的要求必须同时满足：

 1. 必须至少有`k`左边的索引`i`其值严格小于`nums[i]`。 
2. 必须至少有`k`右边的索引`i`其值严格小于`nums[i]`。 

“不同索引”这个词只是意味着我们计算数组中不同的位置。 这些值本身可能会重复。 

输入包括：

 - 整数数组`nums`- 正整数`k`输出是满足这两个条件的索引的数量。 

约束条件很重要：

 -`nums.length`可以大到`10^5`- 里面的价值观`nums`也可以大到`10^5`这些限制立即排除了昂贵的二次方法。 任何独立检查每个索引左侧和右侧所有元素的算法都会太慢。 

该问题也使用了严格比较：```
nums[idx] < nums[i]
```相同的值不算数。 这个细节非常重要，因为测试用例中经常出现重复的数字。 

一些边缘情况值得尽早关注：

 - 所有元素都相等的数组，因为没有索引可以具有严格较小的邻居。 
- 情况`k`大于一侧可用的元素数量。 
- 非常小的数组，尤其是长度`1`。 
- 具有许多重复项的数组，因为不能计算相等性。 
- 增加或减少数组，其中只有一侧可以满足条件。 

挑战在于对每个索引进行高效计算：

 - 前面有多少个较小的值
 - 其后出现多少个较小的值

 一旦我们知道了这两个计数，我们只需检查每个计数是否至少`k`。 

## 方法

 ### 蛮力方法

 最直接的解决办法就是对每个指标进行独立检查。 

For each position`i`，我们扫描：

 - 左边的所有索引`i`- 右侧的所有索引`i`在这些扫描期间，我们计算有多少值严格小于`nums[i]`。 

如果两个计数至少为`k`，我们增加答案。 

这种方法是正确的，因为它明确地评估了 a 的确切定义`k-big`指数。 然而，它的效率很低，因为每个索引可能需要扫描几乎整个数组。 

对于大小的数组`n`，这大约导致：```
O(n^2)
```最坏情况下的操作。 

自从`n`可以是`100000`，二次解太慢了。 

### 最佳方法

 关键的观察是我们反复需要前缀和后缀频率信息。 

对于每个元素，我们想知道：

 - 有多少个之前看到的值较小
 - 有多少个未来值更小

 这是二元索引树（也称为 Fenwick 树）的经典用例。 

芬威克树有效地支持：

 - 更新频率
 - 查询前缀和

 都在：```
O(log n)
```时间。 

我们对数组进行两次处理：

 1.从左到右

 - 计算每个索引之前存在多少个较小的值。 
2.从右到左

 - 计算每个索引后面存在多少个较小的值。 

因为值可以大到`10^5`，我们直接使用这些值作为芬威克树索引。 

最终答案是两个计数至少都为的索引数`k`。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 左右扫描每个索引 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 使用 Fenwick Tree 进行高效频率计数 |

 ## 算法演练

 ### 第 1 步：创建一棵 Fenwick 树

 芬威克树存储迄今为止遇到的值的频率。 

它支持两种操作：

 -`update(index, delta)`为位置添加一个值。 
-`query(index)`返回前缀和`1`到`index`。 

这使我们能够有效地计算出现了多少小于给定值的数字。 

### 步骤 2：计算左侧较小的元素

 我们从左到右遍历数组。 

对于每个值`nums[i]`:

 1. 查询 Fenwick 树：```
count of values < nums[i]
```2. 将此计数存储在名为的数组中`left_smaller`。 
3. 插入`nums[i]`进入芬威克树。 

查询使用：```
query(nums[i] - 1)
```因为比较必须严格更小。 

### 步骤 3：重置 Fenwick 树

 在第一次遍历之后，树包含来自左侧遍历的频率。 

在从右侧进行处理之前，我们创建一棵新鲜的空芬威克树。 

### 步骤 4：计算右侧较小的元素

 我们现在从右向左遍历。 

对于每个值`nums[i]`:

 1、查询有多少个值小于`nums[i]`已经存在于树中。 
2. 将此计数存储在`right_smaller`。 
3. 插入`nums[i]`到树里。 

由于我们从右向左移动，因此树表示位于当前索引右侧的元素。 

### 步骤 5：计算有效的 K-Big 指数

 最后，迭代所有索引。 

如果两个条件都成立：```
left_smaller[i] >= k
right_smaller[i] >= k
```然后增加结果。 

### 为什么它有效

 Fenwick 树始终存储先前处理的值的频率。 

从左到右遍历时，树恰好包含索引之前的元素`i`，因此查询树会给出左侧较小值的数量。 

从右向左遍历时，树恰好包含索引之后的元素`i`，因此查询得到右边较小值的个数。 

因为两次遍历都正确计算了所需的计数，所以检查两者是否至少`k`正确识别每一个`k-big`指数。 

## Python 解决方案```python
from typing import List

class FenwickTree:
    def __init__(self, size: int):
        self.size = size
        self.tree = [0] * (size + 1)

    def update(self, index: int, delta: int) -> None:
        while index <= self.size:
            self.tree[index] += delta
            index += index & -index

    def query(self, index: int) -> int:
        total = 0

        while index > 0:
            total += self.tree[index]
            index -= index & -index

        return total

class Solution:
    def kBigIndices(self, nums: List[int], k: int) -> int:
        max_value = max(nums)

        left_smaller = [0] * len(nums)
        right_smaller = [0] * len(nums)

        fenwick = FenwickTree(max_value)

        for i, value in enumerate(nums):
            left_smaller[i] = fenwick.query(value - 1)
            fenwick.update(value, 1)

        fenwick = FenwickTree(max_value)

        for i in range(len(nums) - 1, -1, -1):
            value = nums[i]
            right_smaller[i] = fenwick.query(value - 1)
            fenwick.update(value, 1)

        answer = 0

        for i in range(len(nums)):
            if left_smaller[i] >= k and right_smaller[i] >= k:
                answer += 1

        return answer
```实现首先定义一个 Fenwick Tree 类。 该树存储值的累积频率。 

这`update`方法通过增加某个位置的频率并通过芬威克树向上传播变化来将值插入到结构中。 

这`query`方法计算前缀和，它表示到目前为止已插入多少个小于或等于给定数字的值。 

然后该算法对数组执行两次遍历。 

第一遍计算`left_smaller`。 在将当前值插入树之前，我们查询已经出现了多少个较小的值。 

第二遍计算`right_smaller`。 由于我们从右向左遍历，因此树表示位于当前索引之后的元素。 

最后，我们计算有多少个索引满足这两个条件。 

## 解决方案```go
package main

type FenwickTree struct {
	tree []int
	size int
}

func NewFenwickTree(size int) *FenwickTree {
	return &FenwickTree{
		tree: make([]int, size+1),
		size: size,
	}
}

func (f *FenwickTree) Update(index int, delta int) {
	for index <= f.size {
		f.tree[index] += delta
		index += index & -index
	}
}

func (f *FenwickTree) Query(index int) int {
	sum := 0

	for index > 0 {
		sum += f.tree[index]
		index -= index & -index
	}

	return sum
}

func kBigIndices(nums []int, k int) int {
	maxValue := 0

	for _, value := range nums {
		if value > maxValue {
			maxValue = value
		}
	}

	leftSmaller := make([]int, len(nums))
	rightSmaller := make([]int, len(nums))

	fenwick := NewFenwickTree(maxValue)

	for i, value := range nums {
		leftSmaller[i] = fenwick.Query(value - 1)
		fenwick.Update(value, 1)
	}

	fenwick = NewFenwickTree(maxValue)

	for i := len(nums) - 1; i >= 0; i-- {
		value := nums[i]
		rightSmaller[i] = fenwick.Query(value - 1)
		fenwick.Update(value, 1)
	}

	answer := 0

	for i := 0; i < len(nums); i++ {
		if leftSmaller[i] >= k && rightSmaller[i] >= k {
			answer++
		}
	}

	return answer
}
```Go 实现遵循与 Python 版本相同的结构。 

Fenwick 树被实现为包含内部切片及其大小的结构。 

Go 切片的大小是动态调整的，因此不需要对数组进行特殊处理。 整数溢出不是问题，因为计数永远不会超过`n`，这最多是`100000`。 

逻辑仍然相同：

 - 从左到右一次传球
 - 一次从右向左传球
 - 最终验证步骤

 Fenwick Tree支持对数时间更新和前缀和查询。 

我们对每个元素处理两次：

 - 从左到右一次
 - 从右到左一次

 每次迭代执行一次查询和一次更新，两者都会花费`O(log n)`。 

因此，总复杂度为：```
O(n log n)
```辅助空间包括：

 -`left_smaller`-`right_smaller`- 芬威克树存储

 全部与输入大小成正比。

 ## 边缘情况

 ### 所有元素都相等

 考虑：```
nums = [5,5,5,5]
```一个常见的错误是不小心将相等的值计为较小的值。 

该问题需要严格的不平等：```
nums[idx] < nums[i]
```实现通过查询正确处理这个问题：```
query(value - 1)
```它从计数中排除相等的值。 

### K 大于可用元素

 考虑：```
nums = [1,2,3]
k = 5
```任何索引都不可能在两侧都有五个较小的值，因为数组本身太小。 

该实现自然会处理这个问题，因为计算的计数永远不会达到`k`，因此不计算任何索引。 

### 严格递增或递减数组

 对于递增数组：```
[1,2,3,4,5]
```每个元素的左侧可能有许多较小的值，但右侧没有。 

对于递减数组：```
[5,4,3,2,1]
```相反的情况就会发生。 

这些情况很重要，因为一些不正确的实现仅正确验证一侧。 

该解决方案显式计算独立的左计数和右计数，保证两种单调模式的正确性。
