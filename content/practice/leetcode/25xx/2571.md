[LeetCode 问题 2571](https://leetcode.com/problems/minimum-operations-to-reduce-an-integer-to-0/)

 **难度：** 🟡 中等
 **主题：** 动态规划、贪心、位操作

 ## 解决方案

 ## 问题理解

 该问题要求我们找到减少给定正整数所需的最少运算次数`n`到`0`，其中每个操作都包括从当前值中添加或减去 **2 的幂**`n`。 二的幂被定义为以下形式的任何数字$2^i$在哪里$i \ge 0$。 

换句话说，我们从一个整数开始`n`在每一步中，我们都可以增加或减少`n`由 1、2、4、8、16 等数字组成。 目标是准确达到`0`使用尽可能少的步骤。 

输入约束`1 <= n <= 10^5`告诉我们`n`可以是中等大，但不是天文数字。 这意味着具有指数时间复杂度的算法将无法扩展，我们需要一些高效的算法。 

重要的边缘情况包括小数字，例如`1`或两个本身的幂，其中单个操作可以解决问题。 另一个棘手的情况是略高于 2 的幂的数字，其中添加下一个 2 的幂然后减去可能比顺序减去较小的幂更优化。 

## 方法

 ### 蛮力方法

 蛮力方法会尝试将 2 的幂相加或相减的每一种组合`n`直到达到`0`。 这可以可视化为广度优先搜索 (BFS) 或深度优先搜索 (DFS)，其中每个节点代表一个数字，每条边代表加或减 2 的幂。 虽然正确，但这种方法很快就变得不可行，因为可能的序列数量呈指数增长`n`。 

### 最佳方法

 关键的观察结果是，该问题相当于最小化表达所需的操作数`n`作为二的幂的和，允许正号和负号。 这与**二进制表示**密切相关`n`。 如果我们解释`n`以二进制表示，每个`1`可以通过减去相应的 2 的幂或添加下一个更高的 2 的幂并结转来“取消”。 这产生了**贪婪的位操作方法**，我们从最低有效位到最高有效位检查位，并在每一步决定是结转还是减去更好。 该方法保证了最少的操作，因为每一步都最佳地减少了剩余的 1 数量。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 尝试二的加/减幂的每种组合； 对于 n=10^5 | 不可行
 | 最佳| O(log n) | O(1) | O(1) | 贪婪的位操作； 高效处理搬运，保证最少的操作 |

 ## 算法演练

 1. 转换`n`进入其二进制表示形式。 
2. 初始化一个运算计数器和一个进位变量。 
3. 遍历bits`n`从最低有效位 (LSB) 到最高有效位 (MSB)。 
4. 对于每一位：

 - 将当前进位添加到该位。 
- 如果结果是`0`或者`1`，将操作计数器增加该值并将进位设置为`0`。 
- 如果结果是`2`（位为 1 且进位为 1）或更多时，将操作计数器加 0，将下一位进位设置为 1。 
5. 处理完所有位后，如果还有剩余进位，则操作计数器加 1。 
6. 返回操作计数器作为最小操作数。 

**为什么有效**：此方法之所以有效，是因为加或减 2 的幂相当于解析二进制表示中的 1。 进位处理添加下一个 2 的幂可减少所需操作总数的情况，有效地执行“向上舍入”策略以最小化总移动次数。 

## Python 解决方案```python
class Solution:
    def minOperations(self, n: int) -> int:
        operations = 0
        carry = 0
        
        while n > 0 or carry > 0:
            current_bit = n & 1
            total = current_bit + carry
            
            if total == 0 or total == 1:
                operations += total
                carry = 0
            else:  # total == 2
                operations += 0
                carry = 1
            
            n >>= 1
        
        return operations
```该实现保持运行进位来处理添加更高的 2 次幂比顺序减去更小的幂更优化的情况。 我们一点一点地迭代，适当增加操作计数器，然后移位`n`直到处理完所有位和进位。 

## 解决方案```go
func minOperations(n int) int {
    operations := 0
    carry := 0
    
    for n > 0 || carry > 0 {
        currentBit := n & 1
        total := currentBit + carry
        
        if total == 0 || total == 1 {
            operations += total
            carry = 0
        } else { // total == 2
            carry = 1
        }
        
        n >>= 1
    }
    
    return operations
}
```在 Go 中，我们以类似的方式处理进位和位操作。 由于 Go 有明确的整数类型，我们依赖`int`和直接按位运算符。 不需要额外的空间或动态内存。

 ## 边缘情况

 第一个重要的边缘情况是`n`已经是2的幂了，就像`2`或者`16`。 在这里，一次减法就足够了，算法通过二进制检查正确地识别了这一点。 

第二个边缘情况是当`n`是`1`。 幼稚的实现可能会尝试不必要的操作，但我们的按位方法正确地计算了一个操作。 

第三种边缘情况涉及略高于 2 的幂的数字，例如`33`或者`65`。 最佳序列可能涉及添加下一个 2 的幂，然后减去，我们的进位机制可以有效地处理，确保计算出最少的操作数。 

这种方法对所有人来说都是稳健的`n`在约束范围内`1 <= n <= 10^5`并避免溢出和过多的计算步骤。
