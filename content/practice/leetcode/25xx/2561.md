[LeetCode 问题 2561](https://leetcode.com/problems/rearranging-fruits/)

 **难度：** 🔴难
 **主题：** 数组、哈希表、贪婪、排序

 ## 解决方案

 ## 问题理解

 这个问题给了我们两个数组，`basket1`和`basket2`，其中每个元素代表篮子中水果的成本。 两个篮子均包含`n`水果。 我们的目标是使两个篮子相等，其中相等意味着对两个数组进行排序后，它们包含完全相同的多重值集。 

我们可以反复交换一种水果`basket1`与一个水果`basket2`。 交换的成本是两个交换水果价值中的最小值。 

重要的细节是篮子顺序并不重要。 只有每种水果值的最终频率很重要。 这意味着我们正在有效地改变两个篮子的频率分布，直到它们匹配。 

任务是计算使篮子相等所需的最小总交换成本。 如果不可能，我们就返回`-1`。 

限制条件很大：

 - 最多`10^5`元素
 - 水果价值高达`10^9`这些约束立即排除了任何指数或二次强力模拟。 我们需要一个接近的算法`O(n log n)`。 

一个关键的观察结果是，每个水果值在两个篮子中出现的次数必须为偶数。 如果某个值总体出现奇数次，则无法将其平均分配到两个篮子之间，因此答案是`-1`。 

一些重要的边缘情况包括：

 - 篮子已经相等，所以答案是`0`- 水果值在全球范围内出现奇数次
 - 直接交换比使用中间最小的水果更昂贵
 - 大型重复组
 - 水果价值极高，需要小心降低成本

 ## 方法

 ### 蛮力方法

 暴力策略将尝试模拟篮子之间的交换，直到频率分布匹配。 一种可能的实现将重复定位不匹配的值并尝试所有可能的交换以确定最小成本安排。 

从概念上讲，这是可行的，因为最终所有不平衡都可以通过互换来纠正。 然而，可能的交换序列的数量增长得非常快。 即使是贪婪的本地选择，在不考虑未来后果的情况下也很难评估。 

如果我们尝试所有不匹配水果的配对，复杂性很容易变成二次或更糟。 和`n = 10^5`，这太慢了。 

### 最佳解决方案的关键见解

 重要的见解是我们不需要模拟实际的篮子状态。 相反，我们只关心哪些额外价值必须从一个篮子转移到另一个篮子。 

假设某个值出现多次`basket1`比在`basket2`。 然后必须交换该值的一些副本。 类似地，如果一个值出现多次`basket2`，必须交换一些副本。 

我们可以收集：

 - 额外价值来自`basket1`- 额外价值来自`basket2`这些列表必须配对和交换。 

另一个重要的优化来自于观察到直接交换并不总是最佳的。 

假设我们要交换一个大值`x`具有另一个大值`y`。 而不是直接用成本交换`min(x, y)`，我们可以通过使用全球最小的水果价值来获得更便宜的结果`m`作为中间体：

 1. 交换`x`和`m`2. 交换`m`和`y`这需要花费`2 * m`。 

因此，对于每次所需的交换，可实现的最低成本为：$$\min(\text{direct swap cost}, 2 \times \text{global minimum})$$这将问题转化为排序和配对问题。

 | 蛮力 | 指数或 O(n²) | O(n) | 尝试显式交换模拟 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 使用频率平衡和贪婪配对 |

 ## 算法演练

 1. 计算两个篮子中每个水果值的出现频率。 

我们使用哈希图，因为水果值可以大到`10^9`，使得数组索引不切实际。 
2. 检查可行性。 

对于每个水果值，计算：$$\text{count in basket1} + \text{count in basket2}$$如果总数为奇数，则返回`-1`。 

这是必要的，因为两个篮子最终必须恰好包含总出现次数的一半。 
3. 找出全局最小水果值。 

该值很重要，因为它可以用作中间交换以降低成本。 
4. 建立不匹配列表。 

对于每个水果值：

 - 如果`basket1`有额外的副本，将它们添加到`extra1`- 如果`basket2`有额外的副本，将它们添加到`extra2`添加的副本数量为：$$\frac{|\text{freq1} - \text{freq2}|}{2}$$因为每次交换都会修复两个丢失的副本。 
5. 对不匹配列表进行排序。 

我们排序：

 -`extra1`按升序排列
 -`extra2`按降序排列

 这种配对最大限度地减少了直接交换成本。 
6. 计算最小成本。 

对于每对`(a, b)`：

 - 直接互换成本为`min(a, b)`- 间接互换成本为`2 * globalMin`添加：$$\min(\min(a, b), 2 \times globalMin)$$到答案。 
7. 返回总成本。 

### 为什么它有效

 所有不平衡最终都必须通过互换来纠正。 不匹配列表精确地捕获了哪些值必须在篮子之间移动。 

对最小与最大进行排序和配对可以贪婪地最小化直接交换成本。 此外，任何昂贵的直接交换总是可以被涉及全球最小水果的两次交换所取代。 由于平衡频率后每次交换都是独立的，因此将局部最小成本相加即可得出全局最小答案。 

## Python 解决方案```python
from typing import List
from collections import Counter

class Solution:
    def minCost(self, basket1: List[int], basket2: List[int]) -> int:
        freq1 = Counter(basket1)
        freq2 = Counter(basket2)

        all_values = set(freq1.keys()) | set(freq2.keys())

        global_min = min(min(basket1), min(basket2))

        extra1 = []
        extra2 = []

        for value in all_values:
            total = freq1[value] + freq2[value]

            if total % 2 != 0:
                return -1

            diff = freq1[value] - freq2[value]

            if diff > 0:
                extra1.extend([value] * (diff // 2))
            elif diff < 0:
                extra2.extend([value] * ((-diff) // 2))

        extra1.sort()
        extra2.sort(reverse=True)

        total_cost = 0

        for a, b in zip(extra1, extra2):
            direct_cost = min(a, b)
            indirect_cost = 2 * global_min

            total_cost += min(direct_cost, indirect_cost)

        return total_cost
```该实现首先使用以下方法计算两个篮子中的频率`Counter`。 这允许恒定时间查找每个水果值出现的次数。 

然后，我们迭代所有不同的水果值并验证总出现次数是否为偶数。 如果没有，我们立即返回`-1`。 

接下来，我们计算每个篮子中哪些价值是额外的。 如果某个值出现太多次`basket1`，一半的差异必须转移到`basket2`。 同样的逻辑反过来也适用。 

收集完所有超额值后，我们对列表进行策略性排序。 将一侧的最小剩余价值与另一侧的最大剩余价值配对可以最大限度地降低交换成本。 

最后，对于每个所需的交换，我们比较：

 - 直接交换成本
 - 间接成本使用全局最小值两次

 这些最小成本的总和就是最终的答案。 

## 解决方案```go
package main

import (
	"sort"
)

func minCost(basket1 []int, basket2 []int) int64 {
	freq1 := make(map[int]int)
	freq2 := make(map[int]int)

	globalMin := basket1[0]

	for _, v := range basket1 {
		freq1[v]++
		if v < globalMin {
			globalMin = v
		}
	}

	for _, v := range basket2 {
		freq2[v]++
		if v < globalMin {
			globalMin = v
		}
	}

	allValues := make(map[int]bool)

	for k := range freq1 {
		allValues[k] = true
	}

	for k := range freq2 {
		allValues[k] = true
	}

	extra1 := []int{}
	extra2 := []int{}

	for value := range allValues {
		total := freq1[value] + freq2[value]

		if total%2 != 0 {
			return -1
		}

		diff := freq1[value] - freq2[value]

		if diff > 0 {
			for i := 0; i < diff/2; i++ {
				extra1 = append(extra1, value)
			}
		} else if diff < 0 {
			for i := 0; i < (-diff)/2; i++ {
				extra2 = append(extra2, value)
			}
		}
	}

	sort.Ints(extra1)

	sort.Slice(extra2, func(i, j int) bool {
		return extra2[i] > extra2[j]
	})

	var totalCost int64 = 0

	for i := 0; i < len(extra1); i++ {
		a := extra1[i]
		b := extra2[i]

		directCost := min(a, b)
		indirectCost := 2 * globalMin

		totalCost += int64(min(directCost, indirectCost))
	}

	return totalCost
}

func min(a, b int) int {
	if a < b {
		return a
	}
	return b
}
```Go 实现遵循与 Python 版本相同的逻辑，但使用原生映射而不是`Counter`。 

一个重要的区别是 Go 需要显式的整数类型处理。 由于答案可能会变大，因此函数返回`int64`。 

切片用于存储多余的元素，需要自定义排序，降序排列`extra2`。

 ## 边缘情况

 当某个水果值在两个篮子中出现奇数次时，就会出现一种重要的边缘情况。 由于两个篮子必须以相同的频率分布结束，因此每个值都必须可以在两个篮子之间整除。 一个天真的实现可能会尝试交换，但正确的行为是立即返回`-1`。 该实现在进行任何交换计算之前显式检查奇偶校验。 

当直接交换比通过全局最小的水果路由更昂贵时，就会出现另一种微妙的边缘情况。 例如，交换`100`和`200`直接成本`100`，但是使用全局最小水果`1`仅成本`2`。 仅考虑直接交换的实现将产生错误的答案。 该算法通过始终采用最小的直接成本来处理这个问题`2 * globalMin`。 

第三个重要的边缘情况涉及排序后已经相等的篮子。 由于顺序并不重要，因此数组就像`[1,2]`和`[2,1]`要求零操作。 简单的基于位置的算法可能会错误地尝试交换。 该实现完全与频率一起工作，因此它自然可以正确处理此类情况。 

最后的边缘情况涉及大量重复组。 如果一个篮子包含许多相同价值的额外副本，则很容易意外地多算所需的掉期。 该算法正确地仅添加了一半的频率差，因为每次交换同时修复了每个篮子中一个错误放置的元素。
