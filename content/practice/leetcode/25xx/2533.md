[LeetCode 问题 2533](https://leetcode.com/problems/number-of-good-binary-strings/)

 **难度：** 🟡 中等
 **主题：** 动态规划

 ## 解决方案

 ## 问题理解

 该问题要求我们计算有多少二进制字符串满足特定的结构规则。 

我们有四个整数：

 -`minLength`，有效字符串的最小允许长度
 -`maxLength`，有效字符串的最大允许长度
 -`oneGroup`，每个连续块所需的整除条件`1`s
 -`zeroGroup`，每个连续块所需的整除条件`0`s

 如果相同字符的每个连续块的长度可被相应的组大小整除，则认为二进制字符串是好的。 

例如，假设：

 -`oneGroup = 2`-`zeroGroup = 3`然后每次连续运行`1`s 必须有长度`2`,`4`,`6`，依此类推，而每次连续运行`0`s 必须有长度`3`,`6`,`9`， 等等。 

重要的细节是块是独立的。 只要每个块单独满足其整除性规则，字符串就可以在零和一之间交替任意多次。 

我们需要统计总长度在包含范围内的所有好的二进制字符串`[minLength, maxLength]`。 

答案可能会变得非常大，因此我们必须将其模数返回：$$10^9 + 7$$约束条件至关重要：

 -`maxLength`可以大到`100000`- 任何算法在字符串长度上呈指数增长都是不可能的
 - 即使是二次解在实践中也太慢

 这立即表明我们需要一个线性或接近线性的动态规划解决方案。 

一些边缘情况很重要：

 - 当`oneGroup = 1`，任何连续的 1 都是允许的
 - 当`zeroGroup = 1`，允许任何连续的零
 - 当`minLength = maxLength`，我们只计算一个精确大小的字符串
 - 有些长度可能根本无法构建
 - 非常大的范围需要仔细的模处理和高效的内存使用

 另一个微妙的观察是，问题本质上是通过附加有效块来构造字符串。 这种洞察力直接导致最佳的动态规划公式。 

## 方法

 ### 蛮力方法

 一种简单的方法将生成长度介于`minLength`和`maxLength`。 

对于每个生成的字符串，我们将扫描它并计算每个连续的 0 和 1 块的长度。 然后我们将验证是否：

 - 每个零块长度都可以被整除`zeroGroup`- 每个块的长度都可以被整除`oneGroup`如果两个条件都成立，我们就增加答案。 

这种方法是正确的，因为它显式地检查每个可能的候选字符串。 

然而，对于给定的约束，这是完全不切实际的。 长度为二进制的字符串`n`有：$$2^n$$可能的配置。 

自从`maxLength`可以是`100000`，穷举生成是不可能的。 

### 关键见解

 我们不应该考虑单个字符，而应该考虑逐块构建字符串。 

始终可以通过重复附加来形成有效的字符串：

 - 一块`0`s 的大小正好是`zeroGroup`- 一块`1`s 的大小正好是`oneGroup`为什么这就足够了？ 

因为任何有效的块长度都是组大小的倍数。 一块长度`6`和`zeroGroup = 3`可以被视为两个附加的有效零长度块`3`。 

这将问题转化为字符串长度的计数问题。 

认为：

-`dp[length]`表示总长度的好字符串数`length`然后：

 - 如果我们附加一个有效的零大小块`zeroGroup`，我们从`length - zeroGroup`- 如果我们附加一个有效的大小块`oneGroup`，我们从`length - oneGroup`这给出了递归式：$$dp[i] = dp[i - zeroGroup] + dp[i - oneGroup]$$只要这些指数有效。 

该动态规划解决方案以线性时间运行。

 ## 算法演练

 1.创建动态规划数组`dp`尺寸的`maxLength + 1`。 

价值`dp[i]`将准确存储总长度的好二进制字符串的数量`i`。 
2. 初始化基本情况：```
dp[0] = 1
```这代表空字符串。 

空字符串很重要，因为它是构造更大字符串的起点。 
3. 迭代所有长度`1`到`maxLength`。 

对于每个长度`i`，计算有多少个有效字符串可以以此长度结尾。 
4. 检查是否可以附加零块。 

如果：```
i >= zeroGroup
```那么任何有效的长度字符串：```
i - zeroGroup
```可以成为长度有效的字符串`i`通过附加一个块`0`尺寸s`zeroGroup`。 

所以：```
dp[i] += dp[i - zeroGroup]
```5. 检查是否可以追加一个块。 

如果：```
i >= oneGroup
```那么任何有效的长度字符串：```
i - oneGroup
```可以成为长度有效的字符串`i`通过附加一个块`1`尺寸s`oneGroup`。 

所以：```
dp[i] += dp[i - oneGroup]
```6. 每次更新后应用模数。 

由于有效字符串的数量快速增长，我们计算：```
dp[i] %= MOD
```7. 当当前长度位于所需范围内时：```
minLength <= i <= maxLength
```添加`dp[i]`到最终的答案。 
8. 返回累加答案模数$10^9 + 7$。 

### 为什么它有效

 递归之所以有效，是因为每个好的字符串都必须以以下任一结尾：

 - 有效的零块
 - 一个有效的块

 删除最后一个块会留下另一个较小的好字符串。 

相反，每个较小的好字符串可以通过附加有效块来生成更大的好字符串。 

这会创建所有好字符串的完整且不重叠的分解，从而保证动态编程循环对每个有效字符串恰好计数一次。 

## Python 解决方案```python
class Solution:
    def goodBinaryStrings(
        self,
        minLength: int,
        maxLength: int,
        oneGroup: int,
        zeroGroup: int
    ) -> int:
        MOD = 10**9 + 7

        dp = [0] * (maxLength + 1)
        dp[0] = 1

        answer = 0

        for length in range(1, maxLength + 1):
            if length >= zeroGroup:
                dp[length] += dp[length - zeroGroup]

            if length >= oneGroup:
                dp[length] += dp[length - oneGroup]

            dp[length] %= MOD

            if minLength <= length <= maxLength:
                answer = (answer + dp[length]) % MOD

        return answer
```该实现遵循算法部分中描述的精确递归。 

这`dp`数组存储每个精确长度的有效字符串的数量。 我们从`dp[0] = 1`因为只有一种方法可以构造长度为零的字符串，即空字符串。 

对于每个长度`1`到`maxLength`，我们尝试两种转换：

 - 附加有效的零块
 - 附加一个有效的块

 如果任一转换都是可能的，我们就会添加达到先前长度的方法数量。 

每次迭代后应用模运算，以防止整数溢出并保持值有界。 

最后，每当当前长度落在所需范围内时，我们就会将其计数添加到运行答案中。 

## 解决方案```go
func goodBinaryStrings(minLength int, maxLength int, oneGroup int, zeroGroup int) int {
	const MOD int = 1_000_000_007

	dp := make([]int, maxLength+1)
	dp[0] = 1

	answer := 0

	for length := 1; length <= maxLength; length++ {
		if length >= zeroGroup {
			dp[length] += dp[length-zeroGroup]
		}

		if length >= oneGroup {
			dp[length] += dp[length-oneGroup]
		}

		dp[length] %= MOD

		if length >= minLength {
			answer = (answer + dp[length]) % MOD
		}
	}

	return answer
}
```Go 的实现与 Python 解决方案非常相似。 

主要区别在于显式整数处理。 由于 Go 使用固定宽度的整数类型，因此我们始终应用模运算来防止溢出。 

使用切片而不是 Python 列表，但索引逻辑保持相同。 

该算法仍然以线性时间运行并使用线性辅助空间。

 ## 边缘情况

 当两者都存在时，就会出现一种重要的边缘情况`oneGroup`和`zeroGroup`平等的`1`。 在这种情况下，每个可能的二进制字符串都是有效的，因为每个正整数都可以被整除`1`。 有缺陷的实现仍然可能会意外地限制转换或错误处理计数。 动态编程循环自然地处理这个问题，因为每个长度都可以使用零块或一块从前一个长度转换。 

当某些长度根本无法构造时，就会出现另一种关键的边缘情况。 例如：```
minLength = 1
maxLength = 1
oneGroup = 2
zeroGroup = 2
```长度无效的字符串`1`存在是因为所有有效块的大小必须均匀。 执行正确离开`dp[1] = 0`因为这两个转移条件都不满足。 

第三个重要的边缘情况涉及接近上限的非常大的输入`100000`。 递归解决方案或暴力枚举将由于指数增长或堆栈溢出而失败。 自下而上的迭代动态编程解决方案完全避免了递归，并且只处理每个长度一次，即使在最大规模下也能确保高效的性能。 

第四个微妙的边缘情况涉及精确长度查询，其中`minLength == maxLength`。 一些实现错误地将所有长度累积到`maxLength`。 此解决方案仅在当前长度位于所需间隔内时添加计数，因此精确长度查询无需特殊处理即可正常工作。
