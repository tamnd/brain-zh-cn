[LeetCode 问题 2534](https://leetcode.com/problems/time-taken-to-cross-the-door/)

 **难度：** 🔴难
 **主题：** 数组、队列、模拟

 ## 解决方案

 ## 问题理解

 这个问题要求我们模拟人们如何随着时间的推移通过一扇门，同时遵循特定的优先级策略。 每个人都会在某一时刻到达并想要进入或退出。 每秒只有一个人可以使用门，当多人等待时，规则决定谁优先。 

输入包含两个数组：

 -`arrival[i]`代表人的时间`i`到达门口。 
-`state[i]`代表方向：

 -`0`意味着这个人想要进入。 
-`1`意味着这个人想要退出。 

数组按索引对齐，即人`i`有到达时间`arrival[i]`以及想要的方向`state[i]`。 

输出是一个数组`answer`在哪里`answer[i]`是人的确切秒数`i`顺利过门。 

问题的重要部分是优先级逻辑。 门记得前一秒发生的事情：

 - 如果门在前一秒未被使用，则退出的人优先。 
- 如果门用于进入，则进入者优先。 
- 如果该门用于退出，则退出人员优先。 
- 在同一方向内，较小的指数先行。 

限制条件很大：

 -`n`可以达到`10^5`- 到达时间按非降序排列

 这立即告诉我们二次模拟太慢了。 我们需要一个接近线性时间的解决方案。 

一些边缘情况尤其重要：

 - 多人同时到达不同方向。 
- 长时间的闲置间隙，没有人在等待。 
- 一个队列已空而另一队列仍有人的情况。 
- 连续序列，其中同一方向重复获得优先级，因为门一直在该方向上使用。 
- 到达时间有很多重复。 

在处理空闲和活动状态之间的转换时，简单的实现通常会失败，因为优先级会在未使用的秒后重置。 

## 方法

 ### 蛮力方法

 暴力模拟将独立检查每一秒并重复扫描所有人，以确定谁有资格使用这扇门。 

每一秒：

 1.找出所有已经到达但尚未穿越的人。 
2. 将他们分成进入组和退出组。 
3. 应用门规则。 
4. 选择下一个人。 

这会产生正确的答案，因为它直接遵循问题陈述。 然而，该实现在每一模拟秒内重复扫描整个阵列。 

在最坏的情况下，最多可能有`O(n)`模拟秒数，每一秒可能需要`O(n)`扫描。 这导致`O(n^2)`时间复杂度，对于`n = 10^5`。 

### 最佳方法

 关键的观察是，人们按排序顺序到达，一旦有人到达，他们只需按照其方向排队等候。 

这自然建议使用两个队列：

 - 排队等候进入的人。 
- 排队等候退出的人。 

我们按时间顺序处理时间，并不断地将新到达的人添加到适当的队列中。 然后，我们每秒根据之前的门使用情况来决定哪个队列获得优先级。 

重要的见解是我们永远不需要重新扫描老年人。 每个人：

 - 进入队列一次。 
- 离开队列一次。 

这使得模拟可以在线性时间内运行。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 每秒重复扫描所有等待的人 |
 | 最佳| O(n) | O(n) | 使用两个队列和时间顺序模拟 |

 ## 算法演练

 1.初始化两个队列：

 -`enter_queue`对于想要进入的人。 
-`exit_queue`对于想要退出的人。 

这些队列自动保留索引顺序，因为人员是按到达顺序处理的。 
2. 维护指针`i`到输入数组中。 

该指针跟踪哪些人尚未添加到等待队列中。 
3. 维护一个变量`current_time`。 

这代表当前正在模拟的第二个。 
4.维护另一个变量`last_direction`。 

这存储了前一秒门的使用方式：

 -`0`用于输入
 -`1`用于退出
 -`-1`如果门在前一秒内未被使用
 5. 在每个时间步，将所有新到达的人添加到相应的队列中。 

自从`arrival`已排序，我们可以使用指针有效地处理到达`i`。 
6. 如果两个队列都是空的，则门空闲。 

在这种情况下：

 - 设置`last_direction = -1`- 跳跃`current_time`直接到下一个到达时间，而不是逐一递增。 

这种优化避免了浪费时间来模拟空秒。 
7. 否则，确定哪个方向优先。 

规则是：

 - 如果`last_direction == -1`，退出优先。 
- 如果`last_direction == 1`，退出保持优先。 
- 如果`last_direction == 0`，进入保持优先。 
8. 从所选队列中选择前面的人员。 

如果首选队列为空，则使用其他队列。 
9. 记录该人过马路的时间。 

店铺`current_time`到结果数组中。 
10. 更新`last_direction`到这一秒使用的方向。 
11. 增量`current_time`一个。 
12. 继续前进，直到所有人都通过。 

### 为什么它有效

 The algorithm maintains an exact simulation of the system state at every second. The queues always contain precisely the people who have arrived but not yet crossed. 由于队列保留到达顺序并且较小的索引自然首先出现，因此自动满足同一方向内的平局打破规则。 

这`last_direction`variable correctly models the door memory from the previous second, which guarantees that the priority rules are applied exactly as specified.

 由于每个人都从队列中插入和删除一次，因此该算法在执行忠实模拟的同时保持线性。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def timeTaken(self, arrival: List[int], state: List[int]) -> List[int]:
        n = len(arrival)

        enter_queue = deque()
        exit_queue = deque()

        answer = [0] * n

        current_time = 0
        i = 0

        # -1 = unused last second
        #  0 = enter used last second
        #  1 = exit used last second
        last_direction = -1

        while i < n or enter_queue or exit_queue:

            # If nobody is waiting, jump to next arrival time
            if not enter_queue and not exit_queue and i < n:
                current_time = max(current_time, arrival[i])
                last_direction = -1

            # Add everyone arriving at current_time
            while i < n and arrival[i] <= current_time:
                if state[i] == 0:
                    enter_queue.append(i)
                else:
                    exit_queue.append(i)
                i += 1

            # Decide who uses the door
            if exit_queue and (
                last_direction == 1 or last_direction == -1 or not enter_queue
            ):
                person = exit_queue.popleft()
                answer[person] = current_time
                last_direction = 1

            else:
                person = enter_queue.popleft()
                answer[person] = current_time
                last_direction = 0

            current_time += 1

        return answer
```实施直接遵循模拟策略。 

二`deque`使用结构体是因为Python中两端的队列操作都很高效。 变量`i`跟踪哪些人已经被插入等待队列。 

最重要的优化出现在空闲处理块中：```python
if not enter_queue and not exit_queue and i < n:
    current_time = max(current_time, arrival[i])
    last_direction = -1
```该算法不是模拟每一空秒，而是直接跳转到下一个到达时间。 这对于维持线性复杂度至关重要。 

决策逻辑密切反映问题陈述。 如果满足以下条件，退出人员将获得优先权：

 - 先前的用法已退出。 
- 门之前闲置着。 
- 没有进入的人在等待。 

否则，进入的人使用门。 

每个人都只被处理一次，从而使实施高效且可扩展。 

## 解决方案```go
func timeTaken(arrival []int, state []int) []int {
	n := len(arrival)

	enterQueue := make([]int, 0)
	exitQueue := make([]int, 0)

	answer := make([]int, n)

	currentTime := 0
	i := 0

	// -1 = unused
	//  0 = enter
	//  1 = exit
	lastDirection := -1

	for i < n || len(enterQueue) > 0 || len(exitQueue) > 0 {

		// Jump to next arrival if idle
		if len(enterQueue) == 0 && len(exitQueue) == 0 && i < n {
			if currentTime < arrival[i] {
				currentTime = arrival[i]
			}
			lastDirection = -1
		}

		// Add all arrived people
		for i < n && arrival[i] <= currentTime {
			if state[i] == 0 {
				enterQueue = append(enterQueue, i)
			} else {
				exitQueue = append(exitQueue, i)
			}
			i++
		}

		// Choose who crosses
		if len(exitQueue) > 0 &&
			(lastDirection == 1 ||
				lastDirection == -1 ||
				len(enterQueue) == 0) {

			person := exitQueue[0]
			exitQueue = exitQueue[1:]

			answer[person] = currentTime
			lastDirection = 1

		} else {

			person := enterQueue[0]
			enterQueue = enterQueue[1:]

			answer[person] = currentTime
			lastDirection = 0
		}

		currentTime++
	}

	return answer
}
```Go 实现密切反映了 Python 逻辑。 Since Go does not provide a built-in deque structure, slices are used as queues. 删除前面的元素是通过以下方式处理的：```go
queue = queue[1:]
```这对于这个问题来说足够有效，因为每个元素总共只被删除一次。 

整数溢出不是问题，因为所有值都保持在标准 32 位整数范围内。

 ## 边缘情况

 当门闲置一秒或多秒时，就会出现一种重要的边缘情况。 问题表明，在未使用的一秒后，退出的人会重新获得优先权。 许多不正确的实施方式忘记在空闲期后重置门状态。 该实现明确设置`last_direction = -1`每当两个队列都为空时，确保正确处理规则。 

当很多人同时到达时，就会发生另一个棘手的情况。 由于该问题需要较小的索引在同一方向上首先进行，因此队列必须准确地保留插入顺序。 由于到达是按排序顺序处理的，并直接附加到 FIFO 队列中，因此该实现自然满足了这一要求。 

当一个队列变空而另一个队列仍然有等待的人时，就会发生第三种重要的边缘情况。 例如，如果没有剩下进入的人，则退出的人必须继续穿越，无论先前的方向优先级如何。 该实现通过在决定哪一侧交叉之前显式检查首选队列是否为空来处理此问题。 

最后一个微妙的情况涉及到达时间之间的巨大差距。 幼稚的逐秒模拟可能会浪费大量时间迭代空间隔。 该实现通过在两个队列都为空时直接跳转到下一个到达时间来避免这种情况，即使对于稀疏的到达时间表也保留了线性复杂性。
