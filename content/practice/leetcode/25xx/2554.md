[LeetCode 问题 2554](https://leetcode.com/problems/maximum-number-of-integers-to-choose-from-a-range-i/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、二分搜索、贪婪、排序

 ## 解决方案

 ## 问题理解

 这个问题给了我们三个输入：

 -`banned`, 不允许选择的整数数组
 -`n`，定义有效的整数范围`[1, n]`-`maxSum`，所有选定整数允许的最大总和

 我们必须选择尽可能多的不同整数，同时满足四个条件：

 1. 每个选择的整数必须介于`1`和`n`2. 任何整数不能被选择多次
 3. 所选整数不能出现在`banned`4. 所有选择的整数的总和必须小于或等于`maxSum`目标不是最大化总和，而是最大化所选整数的数量。 

这个区别非常重要。 如果我们想要最大可能的数量，我们应该更喜欢较小的数字，因为它们消耗的可用总预算较少。 例如，选择`1 + 2 + 3`给出三个整数的总和`6`，在选择时`6`单独给出相同的和只能给出一个整数。 

限制相对较小：

 -`banned.length <= 10^4`-`n <= 10^4`-`maxSum <= 10^9`自从`n`仅取决于`10^4`，迭代所有数字`1`到`n`是完全可行的。 重要的部分是有效地检查号码是否被禁止。 线性搜索`banned`对于每个候选人来说都会不必要地慢，所以我们应该使用基于散列的结构来进行恒定时间的成员资格检查。 

一些边缘情况很重要：

 - 所有号码都可能被禁止
 -`maxSum`可能太小而无法选择最小的有效数字
 -`banned`可能包含大于的值`n`，应该简单地忽略
 - 一旦添加另一个数字超过，最佳解决方案可能需要提前停止`maxSum`- 重复值可能出现在`banned`，所以使用集合是有帮助的

 ## 方法

 ### 蛮力方法

 一个简单的暴力解决方案将尝试来自的每个可能的整数子集`[1, n]`，过滤掉包含禁止号码的子集，计算它们的总和，并跟踪总和不超过最大大小的子集`maxSum`。 

这是有效的，因为它明确地检查每个可能的有效选择，保证找到最佳答案。 

然而，这种方法效率极低。 有`2^n`可能的子集，即使对于中等值也是不可能的`n`。 自从`n`可以是`10^4`，这个方法完全不切实际。 

另一种不太极端的暴力变体会反复搜索`banned`对每个数字进行线性排列`1`到`n`。 虽然比子集枚举好得多，但这仍然会导致不必要的重复工作。 

### 最优贪心法

 关键的见解是，如果我们想要最大化所选整数的数量，我们应该始终首先选择最小的可用有效数字。 

这是一个经典的贪婪观察。 数量越少消耗越少`maxSum`预算，为以后包含更多整数留出空间。 

例如：

 - 选择`1 + 2 + 3 = 6`给出三个数字
 - 选择`6`只给出一个数字

 所以最优策略是：

 1. 迭代自`1`到`n`2. 跳过禁用号码
 3. 如果运行总和保持在以下范围内，则添加当前数字`maxSum`4. 一旦下一个数字超出限制就停止

 为了有效地检查某个号码是否被禁止，我们将所有被禁止的值存储在哈希集中。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 枚举所有子集 |
 | 最佳| O(n + b) | O(b) | 通过哈希集查找进行贪婪选择 |

 这里，`b`代表大小`banned`。 

## 算法演练

 1. 创建一个哈希集`banned`大批。 

哈希集允许恒定时间的成员资格检查。 这比重复扫描阵列要快得多。 
2.初始化两个变量：

 -`current_sum = 0`-`count = 0`

`current_sum`跟踪所选整数的总数，以及`count`跟踪我们选择了多少个整数。 
3. 迭代其中的每个整数`1`到`n`。 

我们按升序处理数字，因为在尝试最大化计数时，较小的数字总是更有利。 
4. 对于每个数字：

 - 如果它存在于禁止集中，则跳过它。 
- 否则，检查添加是否超出`maxSum`。 
5. 如果`current_sum + number <= maxSum`：

 - 将数字添加到运行总和中
 - 增加计数
 6. 否则，立即停止迭代。 

由于数字在增加，未来的数字将会更大。 如果当前的数字无法容纳，则后面的数字也无法容纳。 
7. 返回`count`。 

### 为什么它有效

 贪婪策略是正确的，因为选择较小的有效数字总是留下至少与选择较大的有效数字一样多的剩余预算。 

假设最佳解决方案跳过较小的有效数字而选择较大的有效数字。 用较小的数字替换较大的数字将减少或维持总和，同时保持相同的计数，并且可能允许稍后容纳更多数字。 因此，按升序选择数字总是会导致最大可能计数。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxCount(self, banned: List[int], n: int, maxSum: int) -> int:
        banned_set = set(banned)

        current_sum = 0
        count = 0

        for number in range(1, n + 1):
            if number in banned_set:
                continue

            if current_sum + number > maxSum:
                break

            current_sum += number
            count += 1

        return count
```实现从转换开始`banned`成一个集合。 这将平均查找性能从线性时间提高到恒定时间。 

然后该算法迭代所有整数`1`到`n`。 对于每个号码，它首先检查该号码是否被禁止。 如果是这样，循环立即跳过该值。 

如果允许该数量，算法会检查添加该数量是否会超过`maxSum`。 如果总和变得太大，则循环终止，因为所有未来的数字都更大，因此无法容纳任何一个。 

否则，该数字将包含在选择中，更新运行总和，并且计数增加。 

最后，该方法返回所选整数的总数。 

## 解决方案```go
func maxCount(banned []int, n int, maxSum int) int {
    bannedSet := make(map[int]bool)

    for _, num := range banned {
        bannedSet[num] = true
    }

    currentSum := 0
    count := 0

    for number := 1; number <= n; number++ {
        if bannedSet[number] {
            continue
        }

        if currentSum+number > maxSum {
            break
        }

        currentSum += number
        count++
    }

    return count
}
```Go 解决方案遵循与 Python 实现相同的逻辑。 由于 Go 没有内置的哈希集类型，因此`map[int]bool`被用来代替。 

整数溢出在这里不是一个问题，因为最大可能的和完全在 Go 的标准整数范围内。 

该算法使用一个简单的`for`循环遍历范围`[1, n]`, maintaining the running sum and count exactly as in the Python version.

 ## 边缘情况

 当范围内的每个号码都被禁止时，就会出现一种重要的边缘情况。 粗心的实现可能仍会尝试添加数字或无法正确处理空的有效集。 此实现安全地跳过所有禁止值并返回`0`当无法选择有效号码时。 

另一个重要的情况发生在`maxSum`非常小。 例如，如果`maxSum = 1`和号码`1`被禁止，则不存在有效选择。 该算法在添加每个数字之前正确检查总和并返回`0`当没有合适的时候立即。 

第三种边缘情况涉及超出有效范围的禁止值`[1, n]`。 这些值应该没有任何影响，因为无论如何它们都永远不会被选择。 由于该算法仅迭代`1`到`n`，超出范围的禁止号码自然会被忽略，不需要任何特殊处理。 

中的重复条目`banned`也值得考虑。 如果被禁止的数组包含重复的值，则使用列表查找可能会导致多余的工作。 将数组转换为集合会自动删除重复项并保证有效的成员资格检查。 

最后，提前终止对于效率和正确性很重要。 一旦当前数字无法满足剩余预算，后面的每个数字也会失败，因为序列是递增的。 实现使用`break`此时，避免不必要的迭代。
