[LeetCode 问题 2555](https://leetcode.com/problems/maximize-win-from-two-segments/)

 **难度：** 🟡 中等
 **主题：** 数组、二分搜索、滑动窗口

 ## 解决方案

 ## 问题理解

 问题给了我们一个排序数组`prizePositions`，其中每个值代表奖品在 X 轴上的位置。 同一位置可能存在多个奖品。 我们还得到一个整数`k`。 

我们可以在数轴上恰好选择两条线段。 每个段必须有长度`k`，意味着如果左端点是`x`，那么右端点一定是`x + k`。 如果奖品的位置位于两个线段中的至少一个（包括端点）内，则将获得奖品。 

我们的目标是最大化收集奖品的总数。 

一个关键细节是数组已经排序。 这立即表明数组中的连续范围对应于数轴上的连续区域。 由于约束允许最多`10^5`奖品，任何比粗略更糟糕的算法`O(n log n)`或者`O(n)`可能会太慢。 

另一个重要的观察结果是片段可能重叠。 我们不需要让它们保持不相交。 然而，重叠的线段通常没有好处，除非最佳窗口自然相交。 

输入约束还告诉我们一些重要的事情：

 -`prizePositions.length <= 10^5`，所以二次方法太慢。 
- 头寸可以大到`10^9`，这意味着我们不能使用坐标压缩网格或按位置索引的计数数组。 
- 数组已经排序，这强烈暗示了滑动窗口或二分搜索技术。 

一些边缘情况很重要：

 -`k = 0`，这意味着每个线段只能覆盖一个坐标。 
- 许多重复的职位。 
- 所有奖品均位于一个部分内。 
- 最好的两个片段重叠。 
- 位置之间的差距非常大。 

该问题仅要求最大计数，而不要求实际的线段端点。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试第一段的每种可能的段放置以及第二段的每种可能的段放置。 

由于数组已排序，因此我们可以通过选择起始索引来定义段`i`，然后找到最远的索引`j`这样：```
prizePositions[j] - prizePositions[i] <= k
```这给出了一个有效的段。 然后，我们可以类似地尝试每隔一个部分并计算涵盖的奖品的并集。 

问题是有`O(n)`可能的片段，并且比较每一对会导致`O(n^2)`组合。 即使每次比较都是有效的，这对于`n = 10^5`。 

蛮力方法是正确的，因为它显式地检查所有可能的段对，但在计算上是不可行的。 

### 最佳方法

 关键的见解是，一旦我们知道在某个位置之前结束的最佳片段，我们就可以将其与当前片段结合起来。 

假设我们使用滑动窗口来确定，对于每个右端点`r`，结束于的分段可以涵盖多少个奖品`r`。 

然后我们维护：```
best[i] = maximum prizes collectible using one segment among indices [0..i]
```现在，当考虑涵盖指数的部分时`[left, right]`，我们知道：

 - 当前部分贡献：```
right - left + 1
```- 之前最好的不重叠段`left`贡献：```
best[left - 1]
```将它们组合起来给出最佳的两段答案。 

这可以有效地工作，因为滑动窗口和前缀最大数组都可以在线性时间内维护。

 ## 算法演练

 1.初始化两个指针，`left`和`right`，对于滑动窗口。 

窗口代表可以被单段长度覆盖的奖品`k`。 因为数组是有序的，如果：```
prizePositions[right] - prizePositions[left] <= k
```那么这些指数之间的所有奖品都适合一个有效的部分。 
2. 通过移动扩大窗口`right`从左到右。 

对于每一个新`right`，我们尝试将其包含在当前段中。 
3. 窗口失效时缩小窗口。 

如果：```
prizePositions[right] - prizePositions[left] > k
```那么该段太长，所以我们增加`left`直到窗口再次有效。 
4. 计算当前窗口大小。 

一旦窗口有效：```
current_window = right - left + 1
```这代表结束于某一部分的奖品数量`right`。 
5.维护一个前缀最大数组。 

定义：```
best[i]
```作为使用指数中的一个部分可收集的奖品的最大数量`0..i`。 

更新：```
best[right] = max(best[right - 1], current_window)
```6. 将当前片段与前一个片段合并。 

当前部分涵盖指数`[left, right]`。 

任何先前的段必须在此之前结束`left`以避免重复计算。 

所以：```
previous_best = best[left - 1]
```如果`left > 0`， 否则`0`。 

收集到的奖品总额：```
current_window + previous_best
```7. 跟踪所有窗口的最大总数。 

每次迭代更新答案。 

### 为什么它有效

 滑动窗口保证每个有效段都被视为排序数组中的连续范围一次。 

这`best`array 保证对于每个可能的第二段，我们已经知道在开始之前结束的最佳第一段。 由于数组是从左到右处理的，因此在需要时该信息始终可用。 

因为每个可能的有效段都显示为某种滑动窗口状态，并且因为我们将其与最佳的早期段最佳地结合起来，所以算法总是找到全局最优值。 

## Python 解决方案```python
from typing import List

class Solution:
    def maximizeWin(self, prizePositions: List[int], k: int) -> int:
        n = len(prizePositions)

        best = [0] * n

        left = 0
        answer = 0

        for right in range(n):
            while prizePositions[right] - prizePositions[left] > k:
                left += 1

            current_window = right - left + 1

            if right == 0:
                best[right] = current_window
            else:
                best[right] = max(best[right - 1], current_window)

            previous_best = best[left - 1] if left > 0 else 0

            answer = max(answer, current_window + previous_best)

        return answer
```实现直接遵循算法。 

变量`left`跟踪当前有效窗口的开始，而`right`迭代数组。 

这`while`循环保持当前窗口始终满足的不变量：```python
prizePositions[right] - prizePositions[left] <= k
```变量`current_window`存储当前段涵盖的奖品数量。 

数组`best`存储前缀最大值。 在每个索引处，它记录迄今为止找到的最大有效段。 这允许在当前窗口之前恒定时间查找最佳片段。 

最后，该算法将当前片段与最佳的较早片段结合起来并更新答案。 

## 解决方案```go
func maximizeWin(prizePositions []int, k int) int {
	n := len(prizePositions)

	best := make([]int, n)

	left := 0
	answer := 0

	for right := 0; right < n; right++ {
		for prizePositions[right]-prizePositions[left] > k {
			left++
		}

		currentWindow := right - left + 1

		if right == 0 {
			best[right] = currentWindow
		} else {
			best[right] = max(best[right-1], currentWindow)
		}

		previousBest := 0
		if left > 0 {
			previousBest = best[left-1]
		}

		answer = max(answer, currentWindow+previousBest)
	}

	return answer
}

func max(a, b int) int {
	if a > b {
		return a
	}
	return b
}
```Go 的实现与 Python 版本非常相似。 

使用切片而不是 Python 列表。 由于 Go 没有提供内置的`max`对于整数函数，辅助函数是手动实现的。 

整数溢出不是问题，因为奖品的最大数量仅为`10^5`，完全在 Go 的整数范围内。

 ## 边缘情况

 一个重要的边缘情况是当`k = 0`。 在这种情况下，每个段只能覆盖一个坐标。 如果索引相邻，幼稚的实现可能会错误地假设每个窗口的大小至少为 2。 滑动窗口条件可以正确处理此问题，因为窗口内仅保留相等的值。 

另一个关键情况是许多奖品共享相同的位置。 例如：```
[2,2,2,2]
```即使与`k = 0`，一个片段可以收集所有奖品，因为它们占据相同的坐标。 该实现自然地处理这个问题，因为窗口条件取决于坐标差异，而不是索引差异。 

当所有奖品都已适合一个部分时，就会出现第三种重要情况。 有缺陷的实现可能会不必要地强制两个不相交的段并低估答案。 该解决方案避免了该问题，因为第二段可能贡献零额外奖品，而仅第一段就已经可以覆盖整个阵列。 

另一个微妙的情况涉及重叠最佳窗口。 既然允许重叠，算法就不能人为地禁止交叉。 该实现仅通过以下方式防止重复计算`best[left - 1]`组合逻辑，同时仍然允许实际的线段间隔本身在数轴上几何重叠。
