 # LeetCode 2517 - 糖果篮的最大美味

 ## 问题理解

 问题给了我们一个数组`price`其中每个元素代表糖果的价格。 我们必须准确选择`k`独特的糖果并最大限度地提高篮子的“美味”。 

篮子的美味度定义为该篮子内任意两种糖果价格之间的最小绝对差值。 

换句话说，如果我们选择`k`糖果价格，我们检查每对选定的糖果并计算它们的绝对价格差异。 这些差异中最小的一个就是篮子的味道。 我们的目标是使这个最小差异尽可能大。 

例如，如果我们选择带有价格的糖果`[5, 13, 21]`，两两差异为：

 -`|13 - 5| = 8`-`|21 - 13| = 8`-`|21 - 5| = 16`最小的差异是`8`，所以篮子的味道是`8`。 

约束条件非常重要：

 -`price.length`可以大到`10^5`- 每个价格可以大到`10^9`这些限制立即排除了指数或二次子集生成方法。 任何尝试所有可能的糖果组合的解决方案都会太慢。 

该问题保证：

 - 我们总是至少有两颗糖果
 -`k`始终有效
 - 价格为正整数
 - 糖果本身是不同的物品，即使有些价格相同

 一些边缘情况很重要：

 - 多种糖果可能具有相同的价格
 - 最大答案可以是`0`-`k`可能等于`price.length`- 最佳篮子可能不涉及最小值或最大值
 - 大输入量需要高效的算法

 关键的挑战是有效地找到最大可能的最小差异。 

## 方法

 ### 蛮力方法

 最直接的解决方案是生成每个可能的大小子集`k`。 对于每个子集，我们计算最小成对绝对差并跟踪所有子集的最大值。 

这是有效的，因为它明确地检查每个有效的篮子，因此不会错过最佳答案。 

然而，子集的数量是巨大的。 可供选择的方式数量`k`元素来自`n`糖果是：$$\binom{n}{k}$$当以下情况时，这在计算上变得不可能：`n`达到`10^5`。 

此外，每个子集都需要成对比较，这会增加更多成本。 

因此，对于给定的约束，暴力破解是完全不可行的。 

### 最佳方法

 重要的观察是，该问题要求我们最大化最小值。 这种结构的问题通常建议对答案进行二分搜索。 

假设我们猜测一个候选美味值`d`。 

问题变成：

 “我们至少可以选择`k`糖果，使得每对选定的糖果至少相差`d`？”

 这种可行性检查要容易得多。 

整理好价格后，我们就可以贪心挑选糖果了：

 - 始终先拿走最小的可用糖果
 - 然后继续选择下一个糖果，其价格与之前选择的糖果至少相差`d`如果我们至少可以选择`k`糖果就这样`d`是可行的。 

这是有效的，因为排序将问题转化为检查连续选定元素之间的间隙。 贪婪策略按排序顺序变得最优。 

由于可行性单调变化：

 - 如果距离`d`是可能的，那么每个更小的距离也是可能的
 - 如果距离`d`是不可能的，那么任何更大的距离都是不可能的

 这种单调属性允许对答案空间进行二分搜索。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(k) | 尝试所有大小子集`k`|
 | 最佳 | O(n log n + n log M) | O(n log n + n log M) | O(1) 额外，不包括排序 | 通过贪婪可行性检查对答案进行二分搜索 |

 这里，`M`是价格范围，大约`10^9`。 

## 算法演练

 1. 排序`price`大批。 

排序很重要，因为它使我们能够推断顺序上的差异。 排序后，如果连续选择的糖果满足最小距离要求，则所有其他成对距离也将满足它。 
2. 定义二分查找范围。 

最小可能的味道是`0`。 

最大可能的美味是：```
max(price) - min(price)
```因为任何成对差异都不能超过整个值范围。 
3. 对答案进行二分查找。 

对于每个候选者的最小差异`mid`，判断是否可以构建一个大小的篮子`k`。 
4. 贪婪地实施可行性检查。 

首先按排序顺序选择第一个糖果。 

然后遍历数组：

 - 如果当前糖果与上次选择的糖果至少相差`mid`，选择它。 
- 继续直到：

 -`k`选择糖果，或
 - 数组结束
 5. 更新二分查找范围。 

- 如果`mid`是可行的，尝试更大的值，因为我们想要最大化美味。 
- 否则，尝试较小的值。 
6. 返回找到的最大可行值。 

### 为什么它有效

 正确性取决于两个属性。 

首先，可行性函数是单调的。 如果我们可以选择`k`最小距离的糖果`d`，那么我们也可以对任何更小的距离这样做。 

其次，贪心选择策略在排序后是最优的。 选择最早有效的糖果总是为以后的选择留下最大的空间。 如果贪婪方法无法构建有效的篮子，那么其他选择策略就无法构建。 

这些属性共同保证二分搜索找到最大可行的美味。 

## Python 解决方案```python
from typing import List

class Solution:
    def maximumTastiness(self, price: List[int], k: int) -> int:
        price.sort()

        def can_form_basket(min_diff: int) -> bool:
            count = 1
            last_selected = price[0]

            for current_price in price[1:]:
                if current_price - last_selected >= min_diff:
                    count += 1
                    last_selected = current_price

                    if count >= k:
                        return True

            return False

        left = 0
        right = price[-1] - price[0]
        answer = 0

        while left <= right:
            mid = (left + right) // 2

            if can_form_basket(mid):
                answer = mid
                left = mid + 1
            else:
                right = mid - 1

        return answer
```实现首先对数组进行排序。 这将问题转化为连续选定糖果之间的差异足以验证最小距离条件的问题。 

辅助函数`can_form_basket`检查候选最小差异是否可行。 它贪婪地选择糖果，同时保持至少`min_diff`连续选择的糖果之间的间隔。 

变量`count`跟踪到目前为止已选择了多少糖果。 变量`last_selected`商店最近选择的糖果价格。 

二分搜索探索之间的答案空间`0`以及最大可能的差异。 每当候选值可行时，我们将其存储为当前最佳答案并搜索更大的值。 

最终，二分搜索收敛到最大可行的美味。 

## 解决方案```go
package main

import (
	"sort"
)

func maximumTastiness(price []int, k int) int {
	sort.Ints(price)

	canFormBasket := func(minDiff int) bool {
		count := 1
		lastSelected := price[0]

		for i := 1; i < len(price); i++ {
			if price[i]-lastSelected >= minDiff {
				count++
				lastSelected = price[i]

				if count >= k {
					return true
				}
			}
		}

		return false
	}

	left := 0
	right := price[len(price)-1] - price[0]
	answer := 0

	for left <= right {
		mid := left + (right-left)/2

		if canFormBasket(mid) {
			answer = mid
			left = mid + 1
		} else {
			right = mid - 1
		}
	}

	return answer
}
```Go 的实现与 Python 版本非常相似。 

Go 使用`sort.Ints`将切片排序到位。 可行性检查作为分配给的匿名函数来实现`canFormBasket`。 

二分查找中点计算使用：```go
mid := left + (right-left)/2
```这种形式避免了整数溢出，尽管溢出对于当前的约束来说并不是一个实际问题。 

Go 中的切片的行为与动态数组类似，因此对于空输入不需要特殊处理，因为约束保证至少有两个元素。

 ## 边缘情况

 当所有糖果价格相同时，就会出现一种重要的边缘情况。 在这种情况下，每对差异为零，因此最大美味度也必须为零。 有缺陷的实现可能会错误地假设正间距始终存在。 二分查找可以正确处理这个问题，因为搜索范围变为`[0, 0]`。 

另一个重要的情况是当`k`等于数组的长度。 在这种情况下，每一颗糖果都必须被选择。 因此，答案由排序后的最小相邻差值决定。 贪婪的可行性检查自然会处理这个问题，因为它尝试在尊重最小距离的同时包含尽可能多的糖果。 

高价格也很重要。 由于价格可能大至`10^9`，算术溢出可能成为某些语言中的问题。 Go 实现通过使用以下方式避免中点溢出：```go
mid := left + (right-left)/2
```最后，具有许多重复值的数组可能会很棘手。 例如，`[1,2,2,2,10]`和`k=3`强制算法包含至少两个非常接近的值。 忽略重复项的幼稚贪婪策略可能会错误地高估答案。 排序的贪婪可行性检查正确地拒绝了不可能的最小距离。
