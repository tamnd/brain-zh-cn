[LeetCode 问题 2588](https://leetcode.com/problems/count-the-number-of-beautiful-subarrays/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、位操作、前缀和

 ## 解决方案

 ## 问题理解

 问题给了我们一个数组`nums`，并且我们可以对元素对重复执行特殊操作。 

在一次操作中，我们选择两个不同的索引`i`和`j`，并选择一个位位置`k`使得两者`nums[i]`和`nums[j]`目前有`k`th 位设置为`1`。 然后我们减去`2^k`从这两个数字。 由于减去`2^k`从数字中精确删除该位，此操作有效地同时从两个不同元素中删除一个匹配的设置位。 

如果在执行任意数量的这些操作之后，子数组中的每个元素都可以变成，则子数组被认为是美丽的`0`。 

关键的观察是操作总是成对地删除位。 因此，对于独立的每个位位置，子阵列中设置的位总数必须是偶数。 如果某个位出现奇数次，则总会有一个剩余位无法配对。 

这直接导致问题的等价表述：

 当且仅当子数组中所有元素的异或等于时，子数组才是美丽的`0`。 

这种等价性至关重要，因为 XOR 自然会跟踪位的奇偶校验：

 - 即使出现一点点也会被抵消
 - 奇怪的现象仍然存在

 所以我们不用模拟运算，只需要统计有多少个子数组异或等于`0`。 

输入大小可以大到`10^5`，这立即排除了昂贵的三次或二次模拟。 我们需要接近线性时间的东西。 

还有几个重要的边缘情况：

 - 仅包含零的数组，每个子数组都很漂亮。 
- 没有零异或子数组的数组，答案是`0`。 
- 单元素子数组只有在元素本身是美丽的`0`。 
- 大型数组需要高效的基于前缀的解决方案，因为直接枚举所有子数组会太慢。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每个可能的子数组。 

对于每个子数组，我们计算其所有元素的异或。 如果异或等于`0`，那么子数组就很漂亮了。 

有`O(n^2)`子数组。 如果我们从头开始为每个子数组重新计算 XOR，则总复杂度变为`O(n^3)`。 

我们可以通过增量扩展子数组来稍微改进：

 - 修复起始索引
 - 一次一步地扩展结束索引
 - 维护正在运行的XOR

 这将复杂性降低到`O(n^2)`。 

该方法是正确的，因为 XOR 精确地捕获了每个位是否出现偶数次。 然而，随着`n = 10^5`,`O(n^2)`太慢了。 

### 最佳方法

 关键的见解来自前缀 XOR。 

定义：```
prefixXor[i] = nums[0] ^ nums[1] ^ ... ^ nums[i]
```子数组的异或`[l, r]`可以计算为：```
prefixXor[r] ^ prefixXor[l - 1]
```我们希望这个值等于`0`。 

这意味着：```
prefixXor[r] = prefixXor[l - 1]
```那么问题就变成了：

 计算存在多少对相等前缀 XOR 值。 

这与经典的“计算总和/异或等于目标的子数组”模式相同。 

我们使用哈希映射来跟踪到目前为止每个前缀 XOR 出现的次数。 

每当当前前缀 XOR 之前出现过时，之前的每个出现都会形成一个以当前索引结尾的漂亮子数组。

 ## 算法演练

 1. 初始化一个名为的哈希图`xor_count`。 

该映射存储到目前为止每个前缀 XOR 值出现的次数。 
2. 插入值`0`进入地图的频率`1`。 

这处理从索引开始的子数组`0`。 在处理任何元素之前，会考虑前缀 XOR`0`。 
3. 维护运行变量`prefix_xor`。 

当我们迭代数组时，我们不断地将当前数字异或到该值中。 
4. 对于中的每个元素`nums`:

 - 更新运行前缀XOR：```
prefix_xor ^= num
```- 检查这个确切的 XOR 值之前出现过多少次。 

之前的每个出现都对应一个子数组，其 XOR 为`0`。 
5.添加频率`prefix_xor`从哈希映射到答案。 

如果`prefix_xor`已经出现`k`之前有几次，然后有`k`以当前索引结尾的美丽子数组。 
6. 增加电流频率`prefix_xor`在哈希映射中。 

这使得它可用于未来的子阵列。 
7. 继续，直到处理完所有元素。 
8. 返回累计答案。 

### 为什么它有效

 该算法依赖于前缀 XOR 恒等式：```
XOR(l, r) = prefixXor[r] ^ prefixXor[l - 1]
```子数组具有 XOR`0`确切的时间：```
prefixXor[r] = prefixXor[l - 1]
```因此，每一对相等的前缀异或值定义了一个漂亮的子数组。 哈希映射在扫描一次数组时有效地计算这些匹配对。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def beautifulSubarrays(self, nums: List[int]) -> int:
        xor_count = defaultdict(int)
        xor_count[0] = 1
        
        prefix_xor = 0
        beautiful_count = 0
        
        for num in nums:
            prefix_xor ^= num
            
            beautiful_count += xor_count[prefix_xor]
            
            xor_count[prefix_xor] += 1
        
        return beautiful_count
```实现直接遵循前缀异或策略。 

我们首先创建一个频率图，称为`xor_count`。 条目`xor_count[0] = 1`很重要，因为它代表数组开始之前的空前缀。 

变量`prefix_xor`存储到目前为止处理的所有元素的异或。 

当我们迭代时`nums`，我们使用以下命令更新正在运行的 XOR：```python
prefix_xor ^= num
```如果这个 XOR 值之前出现过，则之前的每个出现都对应于一个以当前位置结尾的漂亮子数组。 因此，我们将其频率添加到答案中。 

最后，我们在映射中记录当前前缀异或以供将来迭代。 

整个过程以线性时间运行，因为每个元素只被处理一次。 

## 解决方案```go
func beautifulSubarrays(nums []int) int64 {
    xorCount := make(map[int]int64)
    xorCount[0] = 1

    prefixXor := 0
    var beautifulCount int64 = 0

    for _, num := range nums {
        prefixXor ^= num

        beautifulCount += xorCount[prefixXor]

        xorCount[prefixXor]++
    }

    return beautifulCount
}
```Go 实现密切反映了 Python 逻辑。 

一个重要的区别是返回类型是`int64`，因为子数组的数量可能超出标准 32 位整数的范围。 因此，哈希图将频率存储为`int64`价值观也是如此。 

Go 映射会针对缺失的键自动返回零值，这使得频率更新变得简洁。

 ## 边缘情况

 一个非常重要的边缘情况是数组仅包含零。 由于与零进行异或不会改变任何内容，因此每个子数组的异或等于`0`。 对于长度的数组`n`，答案就变成了`n * (n + 1) / 2`。 该实现自然地处理了这个问题，因为前缀 XOR 仍然存在`0`在整个遍历过程中，导致哈希映射中出现重复匹配。 

另一个重要的情况是单元素数组。 包含一个非零数字的子数组永远不会变成全零，因为操作需要跨两个不同索引的一对匹配位。 该算法可以正确处理此问题，因为单个非零值会产生非零 XOR。 

重复的前缀 XOR 值也很重要。 例如，在`[2,2,2,2]`，相同的前缀异或出现多次。 每次重复出现都会同时创建多个有效子数组。 频率图正确计算所有先前出现的次数，而不是仅检查是否存在，从而确保对每个有效子数组进行计数。 

微妙的边缘情况涉及具有许多有效子数组的大输入。 美丽子数组的总数可以超过32位整数范围。 Go 实现明确使用`int64`计算答案和频率以避免溢出问题。
