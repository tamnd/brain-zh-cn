 # LeetCode 2529 - 正整数和负整数的最大计数

 ## 问题理解

 该问题给了我们一个排序的整数数组`nums`按非递减顺序。 我们的任务是计算有多少个数字是正数和多少个数字是负数，然后返回两个计数中较大的一个。 

正整数是大于的任何值`0`，而负整数是小于的任何值`0`。 价值`0`它本身既不是正数也不是负数，所以它不应该对任何一个计数有贡献。 

例如，在数组中`[-2, -1, -1, 1, 2, 3]`，有三个负值和三个正值。 由于两个计数相等，所以答案是`3`。 

重要的细节是数组已经排序。 这个属性使我们能够做的不仅仅是简单地扫描每个元素。 由于所有负值都出现在零之前，并且所有零都出现在正值之前，因此我们可以使用二分搜索来有效地定位这些区域之间的边界。 

限制相对较小：

 -`1 <= nums.length <= 2000`-`-2000 <= nums[i] <= 2000`即使是线性扫描也很容易通过这些限制。 然而后续问我们能否解决这个问题`O(log n)`时间，强烈建议使用二分搜索。 

一些边缘情况很重要：

 - 仅包含正数的数组
 - 仅包含负数的数组
 - 仅包含零的数组
 - 中间有多个零的数组
 - 正数和负数相等的数组
 - 长度数组`1`幼稚的实现很容易因错误地计算零或在二分搜索期间错误处理边界索引而犯错误。 

## 方法

 ### 蛮力方法

 最简单的解决方案是迭代数组一次并维护两个计数器：

 -`negative_count`-`positive_count`对于每个数字：

 - 如果数量小于`0`，增加负计数器。 
- 如果数量大于`0`，增加正计数器。 
- 忽略零。 

最后，返回两个计数器中较大的一个。 

这种方法很简单并且保证是正确的，因为每个元素都被检查一次。 但是，它没有利用数组已经排序的事实。 

### 使用二分搜索的最佳方法

 由于数组已排序，因此所有负值在开头形成一个连续块，所有正值在末尾形成一个连续块。 

这意味着我们可以使用二分搜索来定位：

 - 第一个索引包含`0`或正数
 - 第一个包含正数的索引

 从这些位置：

 - 负数的数量等于第一个非负值的索引。 
- 正数的数量等于`n - first_positive_index`。 

这避免了扫描整个阵列并实现`O(log n)`时间复杂度。 

关键的观察是排序顺序允许边界搜索而不是逐个元素计数。

 ## 算法演练

 ### 最优二分查找算法

 1.计算数组的长度`n`。 
2.使用二分查找查找第一个值大于等于的索引`0`。 

该索引表示非负区域的开始。 由于所有负数都出现在该点之前，因此负数的数量等于该索引。 
3. 将此值存储为`negative_count`。 
4. 使用另一个二分查找来查找第一个值严格大于的索引`0`。 

该指数代表正区域的开始。 
5. 计算阳性数：```
positive_count = n - first_positive_index
```6. 返回最大值`negative_count`和`positive_count`。 

### 为什么它有效

 该算法依赖于数组的排序属性。 由于所有负数都出现在零和正数之前，因此第一个非负数位置将负数与其他所有数字完全分开。 类似地，第一个正值位置将零与正值分开。 

二分搜索在对数时间内正确识别这些边界，因此从这些索引得出的计数是准确的。 

## Python 解决方案```python
from bisect import bisect_left, bisect_right
from typing import List

class Solution:
    def maximumCount(self, nums: List[int]) -> int:
        negative_count = bisect_left(nums, 0)
        positive_count = len(nums) - bisect_right(nums, 0)

        return max(negative_count, positive_count)
```该实现使用Python的内置`bisect`模块，提供高效的二分搜索实用程序。`bisect_left(nums, 0)`返回第一个索引，其中`0`可以在保持排序顺序的同时插入。 这正是第一个非负数的位置，也等于负数的数量。`bisect_right(nums, 0)`返回全零之后的第一个索引。 该位置之后的每个元素都是正数，因此正数元素的数量为`len(nums) - bisect_right(nums, 0)`。 

最后，解决方案返回两个计数中较大的一个。 

## 解决方案```go
import "sort"

func maximumCount(nums []int) int {
	n := len(nums)

	negativeCount := sort.Search(n, func(i int) bool {
		return nums[i] >= 0
	})

	firstPositive := sort.Search(n, func(i int) bool {
		return nums[i] > 0
	})

	positiveCount := n - firstPositive

	if negativeCount > positiveCount {
		return negativeCount
	}

	return positiveCount
}
```Go 解决方案使用`sort.Search`，它对索引执行二分搜索。 

第一个搜索找到第一个索引，其中`nums[i] >= 0`，它决定了负数。 

第二次搜索找到第一个索引，其中`nums[i] > 0`，它确定正数的开始位置。 

与 Python 不同，Go 不提供直接等效项`bisect_left`和`bisect_right`，因此我们使用匿名函数手动表达搜索条件。

 ## 边缘情况

 ### 仅包含零的数组

 像这样的数组`[0, 0, 0]`如果零被错误地视为正数或负数，可能会导致错误计数。 该实现通过专门搜索大于的值来避免这种情况`0`当计算正数和小于的值时`0`计算负数时。 结果，两个计数都正确变为`0`。 

### 没有正数的数组

 考虑`[-5, -4, -1]`。 在这种情况下，对第一个正值的二分搜索将返回数组长度。 正数变为：```
n - n = 0
```这正确地表明不存在正数。 

### 没有负数的数组

 For an array like`[1, 2, 3]`，第一个非负索引是`0`，意味着负数是`0`。 第一个正指数也是`0`，因此正计数成为整个数组长度。 这确保了实现正确处理完全由正值组成的数组。 

### 负区域和正区域之间的多个零

 数组如`[-3, -2, 0, 0, 0, 5, 6]`特别重要，因为零形成中间部分，不应该影响任何计数。 使用两个单独的二分搜索可保证从两个总数中排除零。
