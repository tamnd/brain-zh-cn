[LeetCode 问题 2547](https://leetcode.com/problems/minimum-cost-to-split-an-array/)

 **难度：** 🔴难
 **主题：** 数组、哈希表、动态规划、计数

 ## 解决方案

 ## 问题理解

 问题要求我们分割数组`nums`到一个或多个连续的非空子数组中，以使总成本最小化。 

对于每个子数组，我们定义一个特殊的量，称为其重要性值。 为了计算它，我们首先构建`trimmed`通过删除仅出现一次的每个元素来更改子数组的版本。 仅保留重复值。 

例如：

-`[1,2,3]`变成`[]`因为每个值都出现一次。 
-`[1,2,1,3,3]`变成`[1,1,3,3]`因为`1`和`3`出现多次。 
-`[4,4,4]`遗迹`[4,4,4]`。 

子数组的重要性值为：$$k + \text{length of trimmed(subarray)}$$最终答案是所有选定子数组的重要性值的最小可能总和。 

约束条件很重要：

 -`nums.length <= 1000`-`nums[i] < nums.length`数组大小为 1000 对于指数分区枚举来说太大了，因为有$2^{n-1}$分割数组的可能方法。 然而，它对于二次动态规划解决方案来说足够小。 

取值范围为`nums[i]`也很有用。 由于值的边界为`n`，如果需要的话，我们可以使用数组而不是哈希图来进行频率计数。 

一些边缘情况尤其重要：

 - 所有值都是唯一的数组。 在这种情况下，每个修剪长度都为零，因此最佳策略可能涉及许多小子数组或一个大子数组，具体取决于`k`。 
- 每个值重复多次的数组。 然后修剪的长度会变大，有策略地分割可以减少重复的惩罚。 
- 非常大`k`。 由于每次拆分都会添加另一个固定的`k`，更少的子阵列变得更好。 
- 非常小`k`。 积极地分割可能会成为最佳选择，因为减少重复计数比固定分区成本更重要。 
- 单元素数组。 它们的修剪长度始终为零。 

## 方法

 ### 蛮力方法

 暴力解决方案会尝试一切可能的方法来对数组进行分区。 

对于长度的数组`n`， 有`n - 1`可能的切割位置。 每个位置可以包含分割，也可以不包含分割，因此分区总数为：$$2^{n-1}$$对于每个分区，我们通过计算频率并确定有多少元素属于重复值来计算每个子数组的重要性值。 

这种方法是正确的，因为它详尽地评估了所有有效分区并选择最小成本。 

不幸的是，它太慢了。 即使是为了`n = 30`，分区的数量变得巨大。 和`n = 1000`，穷举搜索是完全不可行的。 

### 最优动态规划方法

 关键的观察结果是该问题具有最优子结构。 

假设我们知道分割前缀的最小成本`nums[0:i]`。 然后，对于每个可能的最后一个子数组`nums[j:i]`，我们可以计算：$$dp[i] = \min(dp[j] + \text{cost}(j,i))$$在哪里：

-`dp[i]`表示分割第一个的最小成本`i`元素。 
-`cost(j,i)`是子数组的重要性值`nums[j:i]`。 

挑战在于计算`cost(j,i)`高效。 

对于子数组，修剪长度会计算属于至少出现两次的值的所有元素。 

我们可以在从位置向后扩展子数组的同时增量地保持频率`i`。 

当出现数字时：

 - 第一次，它没有做出任何贡献。 
- 第二次，两个副本现在都属于修剪后的数组，因此贡献增加`2`。 
- 第三次或以后，每次额外发生都会有贡献`1`。 

这让我们可以在扩展子数组的同时在常数时间内计算修剪后的长度。 

最终的复杂度变成二次的，这是可以接受的`n <= 1000`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 |$O(2^n \cdot n)$|$O(n)$| 枚举所有分区 |
 | 最优动态规划|$O(n^2)$|$O(n)$| 逐步构建最低成本 |

 ## 算法演练

 1.创建DP阵列`dp`长度`n + 1`。 

这里，`dp[i]`存储分割第一个的最小成本`i`的元素`nums`。 

初始化：```
dp[0] = 0
```因为拆分空前缀不需要任何成本。 
2. 初始化所有其他值`dp`到无穷大。 

这使我们能够最大限度地减少候选过渡。 
3. 迭代每个结束位置`i`从`1`到`n`。 

我们将计算以索引结尾的最佳分区`i - 1`。 
4. 对于每个`i`，向后扩展最后一个子数组。 

我们考虑每一个可能的起始索引`j`对于最终的子数组`nums[j:i]`。 
5. 向后移动时保持频率计数器。 

这使我们能够增量更新修剪的长度，而不是从头开始重新计算频率。 
6. 跟踪当前的重复贡献。 

让`trimmed_length`表示修剪后的数组的大小。 

处理值时`x`：

 - 如果频率变为`1`，贡献保持不变。 
- 如果频率变为`2`，贡献增加`2`。 
- 如果频率变为`3`或更多，贡献增加`1`。 
7. 计算子数组重要性值。 

当前子阵列成本为：$$k + \text{trimmed\_length}$$8. 更新 DP 转换。 

对于每一个可能`j`：$$dp[i] = \min(dp[i], dp[j] + k + \text{trimmed\_length})$$9.处理完所有位置后，返回`dp[n]`。 

### 为什么它有效

 该算法之所以有效，是因为每个最佳分区都有一个明确定义的最终子数组。 如果最后一个子数组从位置开始`j`，然后之前的一切`j`本身必须是最佳分区的。 否则，用更便宜的分区替换它会改善整体解决方案。 

所以：$$dp[i] = \min_{0 \le j < i}(dp[j] + \text{cost}(j,i))$$正确捕获每个前缀的最佳答案。 

频率计数逻辑还可以正确计算修剪长度，因为它准确地跟踪有多少元素属于至少出现两次的值。 

## Python 解决方案```python
from typing import List

class Solution:
    def minCost(self, nums: List[int], k: int) -> int:
        n = len(nums)

        dp = [float('inf')] * (n + 1)
        dp[0] = 0

        for i in range(1, n + 1):
            freq = [0] * n
            trimmed_length = 0

            for j in range(i - 1, -1, -1):
                value = nums[j]
                freq[value] += 1

                if freq[value] == 2:
                    trimmed_length += 2
                elif freq[value] > 2:
                    trimmed_length += 1

                cost = k + trimmed_length

                dp[i] = min(dp[i], dp[j] + cost)

        return dp[n]
```实现直接遵循动态规划公式。 

这`dp`数组存储每个前缀长度的最小成本。 对于每个结束位置`i`，我们检查所有可能的起始位置`j`对于最后一个子数组。 

内循环向后移动`i - 1`到`0`。 在此遍历过程中，我们维护当前子数组的频率计数。 

这`trimmed_length`变量增量更新：

 - 第二次出现的值会增加`2`因为两个副本现在都属于修剪后的数组。 
- 此后每次出现都会添加`1`。 

这可以避免重复重新计算修剪后的数组。 

在每一步中，我们都会计算当前子数组的成本并更新 DP 状态。 

## 解决方案```go
package main

import "math"

func minCost(nums []int, k int) int {
	n := len(nums)

	dp := make([]int, n+1)

	for i := 1; i <= n; i++ {
		dp[i] = math.MaxInt32
	}

	for i := 1; i <= n; i++ {
		freq := make([]int, n)
		trimmedLength := 0

		for j := i - 1; j >= 0; j-- {
			value := nums[j]
			freq[value]++

			if freq[value] == 2 {
				trimmedLength += 2
			} else if freq[value] > 2 {
				trimmedLength++
			}

			cost := k + trimmedLength

			if dp[j]+cost < dp[i] {
				dp[i] = dp[j] + cost
			}
		}
	}

	return dp[n]
}
```Go 实现密切反映了 Python 逻辑。 

Go 使用的不是用无穷大初始化的 Python 列表`math.MaxInt32`作为一个大的哨兵值。 

频率跟踪使用整数切片，因为约束保证：$$0 \le nums[i] < n$$所以直接索引是安全高效的。 

Go 切片会自动进行零初始化，这简化了设置。

 ## 边缘情况

 当所有元素都是唯一的时，就会出现一种重要的边缘情况。 在这种情况下，每个子数组的长度都被修剪为零，因为没有值出现多次。 有缺陷的实现可能会错误地计算频率或意外地在修剪的长度中包含唯一元素。 当前的实现可以正确处理此问题，因为值仅在其频率达到至少 2 时才起作用。 

另一个重要的情况是每个元素都相同。 例如，`[1,1,1,1]`导致修剪后的长度快速增长。 不正确的实现通常会错误地处理频率的转换`1`到频率`2`。 该算法明确添加`2`当一个值达到频率时`2`，确保两份副本都被正确计数。 

大的`k`价值观也很关键。 什么时候`k`很大，分割变得非常昂贵，因此即使存在重复项，最佳答案通常也使用单个子数组。 总是试图减少重复的贪婪策略在这里会失败。 DP 解决方案自然地评估所有划分可能性，并正确平衡划分成本和重复惩罚。 

最后一个微妙的边缘情况涉及长度为一的数组。 由于唯一的子数组包含单个唯一值，因此修剪后的长度为零，答案恰好是`k`。 该实现会自动处理此问题，因为频率永远不会超过 1。
