 ## 解决方案

 ## 问题理解

 在这个问题中，我们有一个正多边形`n`顶点，并且每个顶点最初只包含一只猴子。 每只猴子必须同时移动到其两个相邻顶点之一。 由于每只猴子只有两种选择，顺时针或逆时针，因此可能的运动配置总数为`2^n`。 

碰撞在两种情况下发生。 第一种情况是两只或更多猴子移动后最终到达同一顶点。 第二种情况是两只猴子朝相反的方向穿过同一条边，并在边的中间交叉。 

任务是计算有多少运动配置产生至少一次碰撞。 因为答案可能变得非常大，所以我们返回模数结果`10^9 + 7`。 

输入由单个整数组成`n`，表示多边形的顶点数。 输出是一个整数，即产生至少一次碰撞的运动模式的数量。 

约束条件`3 <= n <= 10^9`非常重要。 自从`n`可以大到十亿，任何迭代所有可能的运动模式的算法都是不可能的。 如果需要明确模拟所有运动，即使是线性时间解决方案也会太慢。 这强烈表明该解决方案必须依赖于数学推理和快速求幂。 

一个重要的观察结果是，每只猴子总是精确地移动一步。 因此，完全避免碰撞的唯一方法是所有猴子都朝同一方向移动。 即使一只猴子的动作与邻居不同，碰撞也不可避免。 

另一个重要的边缘情况是非常大的值`n`。 自从`2^n`由于增长速度非常快，求幂期间必须应用模运算以避免溢出。 

## 方法

 ### 蛮力方法

 强力解决方案将生成所有可能的运动配置。 由于每只猴子都有两种选择，因此有`2^n`总配置。 

对于每个配置，我们可以模拟所有猴子的运动并检查是否发生碰撞。 我们需要跟踪目标顶点，并检测沿相反方向移动的相邻猴子之间的边缘交叉。 

这种方法是正确的，因为它明确地评估每种可能的运动模式并直接验证是否发生碰撞。 

然而，复杂性是完全不切实际的。 和`n = 10^9`，甚至存储所有配置也是不可能的。 指数增长使得暴力破解对于任何超出非常小的值的东西都是不可行的。`n`。 

### 最优数学观察

 关键的见解是只有两种方法可以完全避免碰撞：

 1. 每只猴子都按顺时针方向移动。 
2. 每只猴子都逆时针移动。 

在这两种情况下，每只猴子都会移动到唯一的相邻顶点，并且不会有两只猴子交叉路径。 

现在考虑任何混合运动模式。 假设一只猴子顺时针移动，而相邻的猴子逆时针移动。 它们必须沿着共同的边缘相互交叉，立即产生碰撞。 

因此：

 - 总运动模式 =`2^n`- 无碰撞图案 =`2`- 碰撞模式=`2^n - 2`剩下的挑战是高效计算`2^n mod (10^9 + 7)`对于非常大的`n`。 这是使用快速模幂（也称为二进制幂）来完成的。

 | 最佳| O(log n) | O(1) | O(1) | 使用数学观察和快速求幂 |

 ## 算法演练

 1. 定义模数值为`10^9 + 7`。 

需要该模数，因为结果可能变得非常大。 所有计算必须保持在模算术限制内。 
2. 计算`2^n mod MOD`。 

自从`n`可以大到`10^9`,直接计算`2^n`是不可能的。 相反，请使用二进制求幂，它会重复对基数进行平方并一次处理一位指数。 
3. 减去两个无碰撞配置。 

唯一的无碰撞安排是：

 - 所有猴子都顺时针移动
 - 所有猴子逆时针移动

 因此，答案是：$2^n - 2$4. 确保结果保持非负值。 

在模运算中，减法可以产生负的中间值。 添加`MOD`在进行最后的模运算之前。 
5. 返回最终结果。 

### 为什么它有效

 每只猴子都会移动到两个相邻顶点之一。 如果所有猴子都朝同一方向移动，则每只猴子都会围绕多边形均匀移动，因此不会发生碰撞。 

现在假设至少一只猴子的动作与其相邻的一只猴子不同。 沿着连接它们的边缘，一只猴子顺时针移动，而另一只猴子逆时针移动。 它们的路径在该边缘相交，保证了碰撞。 

因此，恰好有两种配置避免了碰撞，并且所有剩余的配置`2^n - 2`配置产生至少一次碰撞。 

## Python 解决方案```python
class Solution:
    def monkeyMove(self, n: int) -> int:
        MOD = 10**9 + 7
        
        total_ways = pow(2, n, MOD)
        
        return (total_ways - 2 + MOD) % MOD
```该实现非常紧凑，因为 Python 已经通过以下方式提供了高效的模幂函数：`pow(base, exponent, mod)`。 

变量`MOD`存储所需的模数。 表达式`pow(2, n, MOD)`计算`2^n mod MOD`内部使用二进制求幂，以对数时间运行。 

计算出运动模式的总数后，我们减去两个无碰撞的情况。 表达式`(total_ways - 2 + MOD) % MOD`保证模运算下结果保持非负。 

## 解决方案```go
func monkeyMove(n int) int {
    const MOD int64 = 1_000_000_007

    power := modPow(2, int64(n), MOD)

    return int((power - 2 + MOD) % MOD)
}

func modPow(base, exponent, mod int64) int64 {
    result := int64(1)

    base %= mod

    for exponent > 0 {
        if exponent%2 == 1 {
            result = (result * base) % mod
        }

        base = (base * base) % mod
        exponent /= 2
    }

    return result
}
```Go 版本显式实现了二进制求幂，因为 Go 不提供与 Python 等效的内置模块化幂函数`pow`。 

辅助函数`modPow`重复对底数求平方并逐位处理指数。 使用`int64`很重要，因为中间乘法结果可能超出标准 32 位整数的范围。 

最后的减法使用`(power - 2 + MOD) % MOD`以避免减法后出现负值。

 ## 边缘情况

 一种重要的边缘情况是最小有效输入，`n = 3`。 小多边形通常是逻辑错误的根源，因为邻接会立即环绕。 该实现自然地处理了这个问题，因为公式`2^n - 2`即使对于最小的多边形也仍然有效。 

另一个重要的边缘情况是极大的值，例如`n = 10^9`。 一个简单的计算实现`2^n`直接会溢出或无限期运行。 使用模二进制求幂可确保计算在对数时间内高效完成。 

第三个重要的边缘情况涉及模减法。 如果表达式`2^n mod MOD`恰好小于`2`，直接相减可能会产生负结果。 该实现通过以下方式避免了此问题：```
(total_ways - 2 + MOD) % MOD
```这保证了最终答案保持在有效的模数范围内。
