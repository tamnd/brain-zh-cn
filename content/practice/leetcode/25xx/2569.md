 # LeetCode 2569 - 更新后处理求和查询

 ## 问题理解

 这个问题给了我们两个数组，`nums1`和`nums2`, 两者长度相同`n`，以及查询列表。 每个查询都会修改其中一个数组或询问有关它们的信息。 

重要的细节是`nums1`仅包含二进制值，这意味着每个元素都是`0`或者`1`。 三种查询类型的行为不同：

 - 类型 1 翻转子数组中的所有位`nums1`。 每一个`0`变成`1`，以及每一个`1`变成`0`。 
- 类型 2 更新每个元素`nums2`通过添加`nums1[i] * p`到它。 
- 类型 3 要求当前所有值的总和`nums2`。 

目标是返回所有类型 3 查询的结果。 

直接实现乍一看似乎很简单，但限制非常大：

 - 数组大小可达`10^5`- 查询数量也可以达到`10^5`这意味着任何重复扫描整个阵列以获取更新的方法都会变得太慢。 

关键的观察结果是，类型 2 查询实际上并不需要修改`nums2`。 自从：```
nums2[i] += nums1[i] * p
```总增量为`nums2`很简单：```
(number of 1s in nums1) * p
```因此，不要将所有更新存储在`nums2`，我们只需要：

 - 当前总和`nums2`- 当前计数`1`进入`nums1`困难的部分变得有效地支持范围位翻转，同时保持数量`1`s。 这正是具有惰性传播的线段树的用处。 

重要的边缘情况包括：

 - 多次翻转同一范围
 - 长度数组`1`- 查询地点`p = 0`- 整个数组翻转
 - 大量重叠更新序列

 该问题保证了有效的索引和正确格式化的查询，因此我们不需要额外的边界检查。 

## 方法

 ### 蛮力方法

 一个简单的实现会直接模拟每个查询。 

对于类型 1 查询：

 - 迭代自`l`到`r`- 单独翻转每个位

 对于类型 2 查询：

 - 迭代所有索引
 - 更新每一个`nums2[i]`对于类型 3 查询：

 - 计算总和`nums2`这种方法是正确的，因为它完全遵循问题陈述。 然而，它太慢了。 

假设我们有`10^5`查询和每个查询处理`10^5`元素。 总复杂度变为：```
O(n * q) = O(10^10)
```which is infeasible.

 ### 最佳方法

 优化来自于认识到我们从来没有真正需要内部的个体值`nums2`。 

对于类型 2 查询：```
nums2[i] += nums1[i] * p
```总和的增量为：```
p * count_of_ones_in_nums1
```因此，我们不更新整个数组，而是只维护：

 -`total_sum = sum(nums2)`-`ones_count = number of 1s in nums1`现在的主要挑战是有效处理范围翻转`nums1`。 

具有惰性传播的线段树有效地解决了这个问题。 

每个节点存储：

 - 数量`1`s 在其段中

 翻转范围时：

 - 数量`1`s 变为：```
segment_length - current_ones
```延迟传播允许将更新推迟到必要时，从而使每个操作都在`O(log n)`时间。

 ## 算法演练

 1.初始化总和`nums2`。 

由于类型 3 查询仅要求总和，因此我们不需要在`nums2`。 我们计算：```
total_sum = sum(nums2)
```2. 构建线段树`nums1`。 

每个线段树节点存储了个数`1`s 在其段中。 

例如：```
nums1 = [1,0,1,1]
```根节点存储`3`，因为有三个`1`s。 
3. 添加惰性传播支持。 

如果逐个元素处理，范围翻转的成本会很高。 

相反，每个节点都有一个惰性标志，指示其段是否应稍后翻转。 

当一个段被翻转时：```
ones = segment_length - ones
```并且惰性标志被切换。 
4. 处理每个查询。 

对于类型 1：

 - 对线段树执行范围翻转
 - 自动更新受影响的计数

 对于类型 2：

 - 获取当前的数量`1`从根节点开始
 - 增加总金额：```
ones_count * p
```对于类型 3：

 - 将当前总和附加到答案列表中
 5. 返回所有记录的答案。 

### 为什么它有效

 核心不变量是线段树根始终存储当前的总数`1`进入`nums1`。 

因为类型 2 查询仅取决于包含多少个位置`1`，我们可以直接更新全局总和，无需修改`nums2`逐个元素。 

延迟传播保证正确表示所有范围翻转，同时避免不必要的重复更新。 因此，每个查询都会有效地产生正确的结果。 

## Python 解决方案```python
from typing import List

class Solution:
    def handleQuery(
        self,
        nums1: List[int],
        nums2: List[int],
        queries: List[List[int]]
    ) -> List[int]:

        n = len(nums1)

        tree = [0] * (4 * n)
        lazy = [False] * (4 * n)

        def build(node: int, left: int, right: int) -> None:
            if left == right:
                tree[node] = nums1[left]
                return

            mid = (left + right) // 2

            build(node * 2, left, mid)
            build(node * 2 + 1, mid + 1, right)

            tree[node] = tree[node * 2] + tree[node * 2 + 1]

        def apply_flip(node: int, left: int, right: int) -> None:
            tree[node] = (right - left + 1) - tree[node]
            lazy[node] = not lazy[node]

        def push(node: int, left: int, right: int) -> None:
            if not lazy[node] or left == right:
                return

            mid = (left + right) // 2

            apply_flip(node * 2, left, mid)
            apply_flip(node * 2 + 1, mid + 1, right)

            lazy[node] = False

        def update(
            node: int,
            left: int,
            right: int,
            query_left: int,
            query_right: int
        ) -> None:

            if query_left <= left and right <= query_right:
                apply_flip(node, left, right)
                return

            push(node, left, right)

            mid = (left + right) // 2

            if query_left <= mid:
                update(
                    node * 2,
                    left,
                    mid,
                    query_left,
                    query_right
                )

            if query_right > mid:
                update(
                    node * 2 + 1,
                    mid + 1,
                    right,
                    query_left,
                    query_right
                )

            tree[node] = tree[node * 2] + tree[node * 2 + 1]

        build(1, 0, n - 1)

        total_sum = sum(nums2)

        answers = []

        for query_type, x, y in queries:

            if query_type == 1:
                update(1, 0, n - 1, x, y)

            elif query_type == 2:
                ones_count = tree[1]
                total_sum += ones_count * x

            else:
                answers.append(total_sum)

        return answers
```实现首先构建一个线段树`nums1`。 每个节点存储多少个`1`s 存在于其段中。 

这`apply_flip`函数执行关键转换：```python
tree[node] = segment_length - tree[node]
```因为翻转位会转换所有`1`进入`0`s，反之亦然。 

这`lazy`数组跟踪延迟翻转。 当节点有待翻转时，`push`函数仅在必要时才将更新传播到其子级。 

这`update`函数执行范围翻转`O(log n)`使用惰性传播的时间。 

在查询处理期间：

 - 类型1触发线段树范围更新
 - 类型 2 使用根值`tree[1]`，它总是存储总数`1`s
 - Type 3记录当前总和

 没有明确的更新`nums2`初始化后执行。 

## 解决方案```go
func handleQuery(nums1 []int, nums2 []int, queries [][]int) []int64 {
	n := len(nums1)

	tree := make([]int, 4*n)
	lazy := make([]bool, 4*n)

	var build func(node, left, right int)

	build = func(node, left, right int) {
		if left == right {
			tree[node] = nums1[left]
			return
		}

		mid := (left + right) / 2

		build(node*2, left, mid)
		build(node*2+1, mid+1, right)

		tree[node] = tree[node*2] + tree[node*2+1]
	}

	applyFlip := func(node, left, right int) {
		tree[node] = (right - left + 1) - tree[node]
		lazy[node] = !lazy[node]
	}

	var push func(node, left, right int)

	push = func(node, left, right int) {
		if !lazy[node] || left == right {
			return
		}

		mid := (left + right) / 2

		applyFlip(node*2, left, mid)
		applyFlip(node*2+1, mid+1, right)

		lazy[node] = false
	}

	var update func(node, left, right, ql, qr int)

	update = func(node, left, right, ql, qr int) {
		if ql <= left && right <= qr {
			applyFlip(node, left, right)
			return
		}

		push(node, left, right)

		mid := (left + right) / 2

		if ql <= mid {
			update(node*2, left, mid, ql, qr)
		}

		if qr > mid {
			update(node*2+1, mid+1, right, ql, qr)
		}

		tree[node] = tree[node*2] + tree[node*2+1]
	}

	build(1, 0, n-1)

	var totalSum int64

	for _, value := range nums2 {
		totalSum += int64(value)
	}

	answer := []int64{}

	for _, query := range queries {
		queryType := query[0]

		if queryType == 1 {
			update(1, 0, n-1, query[1], query[2])

		} else if queryType == 2 {
			onesCount := tree[1]
			totalSum += int64(onesCount * query[1])

		} else {
			answer = append(answer, totalSum)
		}
	}

	return answer
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 一个重要的区别是整数处理。 

总和`nums2`可以变得非常大，因为：

 -`nums2[i]`可以达到`10^9`- 可以有`10^5`元素
 - 额外的更新可能会进一步增加总数

 因此该解决方案使用`int64`以获得最终总和并返回答案。 

Go 切片的大小是动态调整的，因此答案列表是使用重复构建的`append`运营。

 ## 边缘情况

 ### 单元素数组

 当`n = 1`，线段树只包含一个有意义的节点。 由于不正确的中点处理或不必要的子传播，递归实现有时会在最小范围内失败。 

此实现可以安全地处理这种情况，因为在以下情况下递归会立即停止：```
left == right
```并且惰性传播不会尝试进一步推送更新。 

### 在同一范围内重复翻转

 翻转同一范围两次应该会恢复原始值。 如果惰性标志被覆盖而不是切换，这很容易引入错误。 

实现正确地处理了这个问题：```
lazy[node] = not lazy[node]
```这保留了翻转的奇偶性。 

### 大总和值

 总和为`nums2`经过多次更新后可能会变得非常大。 使用标准 32 位整数可能会溢出。 

Go 解决方案明确使用`int64`，Python天然支持任意大的整数。 即使在最大约束下，这也保证了正确性。
