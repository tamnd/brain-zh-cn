[LeetCode 问题 2587](https://leetcode.com/problems/rearrange-array-to-maximize-prefix-score/)

 **难度：** 🟡 中等
 **主题：** 数组、贪婪、排序、前缀和

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个**0索引的整数数组**，`nums`，可以包括负数、零和正数。 我们可以**以我们选择的任何方式**重新排序元素。 重新排序后，我们计算**前缀和数组**，`prefix`， 在哪里`prefix[i]`是索引中所有元素的总和`0`到`i`。 该数组的 **score** 是数组中正数的计数`prefix`大批。 我们的目标是通过选择最佳顺序来**最大化分数**`nums`。 

要点是：

 - 正前缀和对分数有贡献； 负值或零值则不然。 
- 允许重新排序，因此数字的放置会影响总和。 
- 约束表明`nums`可以大到`10^5`元素和值高达`10^6`在幅度上。 因此，算法必须最多是线性的，O(n log n)，才能有效运行。 
- 边缘情况包括所有负数、所有正数、零或混合的数组。 对于全部为负数的数组，最大分数为零。 对于所有正数，最大分数是数组的长度。 

了解这些约束至关重要，因为像尝试**所有排列**这样简单的方法在计算上是不可行的。 

## 方法

 ### 蛮力

 暴力方法将涉及生成输入数组的**所有可能的排列**，计算每个排列的前缀和，并对正前缀和进行计数。 然后，我们将在所有排列中取最大分数。 这保证了正确性，因为它探索了所有选项，但它是 **指数慢**，O(n!)，这是不可能的`n`最多`10^5`。 

### 最佳方法

 关键的观察是，为了最大化正前缀和的数量，我们应该**尽早积累正和**。 这意味着我们应该**将最大的正数放在前面**。 负数或零应该稍后出现，因为它们可能会减少运行前缀和并减少正前缀的数量。 

正式来说，步骤是：

 1. **按降序对数组进行排序**。 正数将首先出现。 
2. **迭代已排序的数组**，维护运行总和。 
3. **计算每个保持正数的前缀**。 一旦运行总和变为非正数，我们就停止计数，因为任何进一步的负数都不会对前缀产生正向贡献。 

这种方法之所以有效，是因为第一个的总和`k`最大数量在每个前缀处最大化，确保正前缀和的数量最大。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n) | 尝试所有排列，不切实际 |
 | 最佳 | O(n log n) | O(n log n) | O(1) | O(1) | 降序排序、累加、统计正前缀 |

 ## 算法演练

 1. **排序`nums`按降序排列**。 这确保了首先考虑最大值，从而最大限度地提高了我们在遍历时保持正前缀和的机会。 
2. **初始化运行总和`prefix_sum`到 0** 和`score`与 0** 相反。 
3. **迭代已排序的数组**：

 - 将当前元素添加到`prefix_sum`。 
- 如果`prefix_sum > 0`, 增量`score`1.
 - 如果`prefix_sum <= 0`，我们仍然可以继续添加数字，但它们可能不会增加分数。 
4. **返回`score`** 完成迭代后。 

**为什么有效**：通过按降序排序，每个前缀总和在给定剩余数字的情况下尽可能大。 这最大化了正前缀和的数量，因为稍后添加较小或负数无法撤消之前从较大数字累积的正数。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxScore(self, nums: List[int]) -> int:
        nums.sort(reverse=True)  # Step 1: Sort descending
        prefix_sum = 0
        score = 0
        for num in nums:  # Step 2-3: Iterate and accumulate
            prefix_sum += num
            if prefix_sum > 0:
                score += 1
        return score  # Step 4: Return the total positive prefixes
```**说明**：首先，我们对数组进行降序排序。 运行总和将元素一一累加。 每次运行总和为正数时，我们都会增加分数。 这直接实现了上面讨论的最优方法。 

## 解决方案```go
import "sort"

func maxScore(nums []int) int {
    sort.Slice(nums, func(i, j int) bool {
        return nums[i] > nums[j] // Sort descending
    })
    
    prefixSum := 0
    score := 0
    for _, num := range nums {
        prefixSum += num
        if prefixSum > 0 {
            score++
        }
    }
    return score
}
```**Go 特定注释**：我们使用`sort.Slice`使用自定义比较器进行降序排序。 切片的大小是动态调整的，因此不需要额外的空间。 在问题的约束范围内，整数运算是安全的。 

## 工作示例

 ### 示例 1：`nums = [2,-1,0,1,-3,3,-3]`1. 降序排序：`[3, 2, 1, 0, -1, -3, -3]`2. 初始化`prefix_sum = 0`,`score = 0`。 
3. 迭代：

 - 3 → prefix_sum = 3 → 分数 = 1
 - 2 → prefix_sum = 5 → 分数 = 2
 - 1 → prefix_sum = 6 → 分数 = 3
 - 0 → prefix_sum = 6 → 分数 = 4
 - -1 → prefix_sum = 5 → 分数 = 5
 - -3 → prefix_sum = 2 → 分数 = 6
 - -3 → prefix_sum = -1 → 分数仍为 6
 4.返回6

 ### 示例 2：`nums = [-2, -3, 0]`1. 降序排序：`[0, -2, -3]`2. 初始化`prefix_sum = 0`,`score = 0`。 
3. 迭代：

 - 0 → prefix_sum = 0 → 分数 = 0
 - -2 → prefix_sum = -2 → 分数 = 0
 - -3 → prefix_sum = -5 → 分数 = 0
 4.返回0

 ## 边缘情况

 1. **所有负数**：任何订单都会产生永远不会为正的运行总和。 我们的实现正确返回 0 作为最高分数。 
2. **零与负数混合**：添加零不会增加前缀和，因此对分数没有贡献。 该算法自然只计算正和。 
3. **单元素数组**：正负单元素数组均处理，酌情返回1或0。 
4. **具有大量数字的大型数组**：就地排序和迭代可确保整数累积不会在问题约束内溢出，从而使解决方案对于最大允许输入具有鲁棒性。 

对于所有指定的约束，该解决方案既高效又安全。
