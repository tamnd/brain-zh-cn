[LeetCode 问题 2564](https://leetcode.com/problems/substring-xor-queries/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、字符串、位操作

 ## 解决方案

 ## 问题理解

 该问题给了我们一个二进制字符串`s`和查询列表。 每个查询包含两个整数，`first`和`second`。 

对于每个查询，我们需要找到一个子串`s`其十进制值满足：$$val \oplus first = second$$在哪里`⊕`表示按位异或运算。 

我们可以使用 XOR 属性重新排列方程：$$val = first \oplus second$$这种转变是整个问题的关键见解。 我们可以直接计算子字符串必须表示的精确十进制值，而不是搜索满足方程的子字符串。 

任务变为：

 1. 计算`target = first ^ second`2. 找到最短的子串`s`其二进制值等于`target`3. 如果多个子串的最短长度相同，则选择左索引最小的一个
 4.返回其`[left, right]`指数
 5. 如果不存在这样的子串，则返回`[-1, -1]`二进制字符串长度最多为`10^4`，而查询数量可以达到`10^5`。 这立即告诉我们，通过子字符串生成独立处理每个查询会太慢。 

子字符串值被解释为二进制数。 例如：

-`"101"`→`5`-`"11"`→`3`-`"0"`→`0`一个重要的观察是查询值可以大到`10^9`。 自从：$$2^{30} > 10^9$$任何相关的二进制子串最多只需要 30 位。 较长的子字符串将超出可能的查询目标。 

一些边缘情况很重要：

 - 目标值可能是`0`，这需要处理子字符串，例如`"0"`- 子字符串中允许使用前导零，但它们会创建相同值的较长表示形式，因此始终首选较短的表示形式
 - 多个子字符串可能会产生相同的值，因此我们必须保留最短的子字符串，然后保留最左边的子字符串
 - 查询可能会要求从未出现在字符串中的值

 ## 方法

 ### 蛮力方法

 蛮力方法将生成每个可能的子串`s`，将每个子字符串转换为其十进制值，然后将其与每个查询目标进行比较。 

有`O(n^2)`长度字符串中的子字符串`n`。 将每个子字符串转换为二进制数会花费额外的时间，并且最多要匹配`10^5`查询使得该方法完全不切实际。 

即使我们逐步优化转化，总工作量仍然巨大，因为：

 -`n`可以是`10^4`- 子串的数量约为`5 × 10^7`- 查询可以`10^5`这种方法很容易超时。 

### 最佳方法

 关键的观察是每个查询都可以减少到目标值：$$target = first \oplus second$$我们不是单独处理查询，而是对字符串进行一次预处理。 

我们枚举长度最多为 30 的每个二进制子串，计算其十进制值，并将每个值的最短出现次数存储在哈希映射中。 

为什么只有30个字符？ 

因为查询值最多是`10^9`，大于 30 位的二进制表示超出了该范围。 

这将预处理减少到：$$O(n \times 30)$$经过预处理后，每个查询就变成了一个简单的哈希图查找。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n² × q) | O(1) | O(1) | 枚举每个查询的所有子字符串 |
 | 最佳| O(n × 30 + q) | O(唯一值的数量) | 预处理所有相关子字符串值一次 |

 ## 算法演练

 1. 创建一个名为的哈希图`value_to_indices`。 

该地图将存储：```
decimal_value -> [left, right]
```对于每个值，我们只保留产生它的最短子字符串。 如果长度相等，我们保留最左边的出现。 
2. 遍历每个起始索引`left`在字符串中。 

在每个位置，我们尝试逐步构建二进制数。 
3. 将子字符串扩展到最多 30 个字符。 

我们使用连续整数值：```
current_value = (current_value << 1) | bit
```这可以有效地构建二进制数，而无需重复转换字符串。 
4. 如果子字符串是该值的最佳表示，则存储该子字符串。 

如果该值以前从未出现过，请立即存储它。 

否则，比较子字符串长度：

 - 保留较短的子串
 - 如果长度相等，则保留较早的起始索引
 5. 处理值`0`自然。 

一个子串`"0"`产生价值`0`。 较长的字符串如`"00"`更糟糕，因为它们更长。 
6. 处理查询。 

对于每个查询：```
target = first ^ second
```然后检查是否`target`存在于地图中。 
7. 返回存储的索引或`[-1, -1]`。 

### 为什么它有效

 每个有效的查询答案都对应一个子字符串，其十进制值等于：$$first \oplus second$$预处理步骤枚举查询中可能出现的每个可能的相关子字符串值。 由于我们总是存储每个值的最短子字符串，并通过较小的左索引来断开关系，因此存储的答案完全符合问题要求。 

因为所有查询都是从这个预先计算的映射中得到答复的，所以正确性直接来自于对最多 30 位的所有可能子字符串值进行详尽的预处理。 

## Python 解决方案```python
from typing import List

class Solution:
    def substringXorQueries(self, s: str, queries: List[List[int]]) -> List[List[int]]:
        value_to_indices = {}

        n = len(s)

        for left in range(n):
            value = 0

            for right in range(left, min(n, left + 30)):
                value = (value << 1) | int(s[right])

                current_length = right - left + 1

                if value not in value_to_indices:
                    value_to_indices[value] = [left, right]
                else:
                    prev_left, prev_right = value_to_indices[value]
                    prev_length = prev_right - prev_left + 1

                    if current_length < prev_length:
                        value_to_indices[value] = [left, right]

                if value == 0:
                    break

        answer = []

        for first, second in queries:
            target = first ^ second

            if target in value_to_indices:
                answer.append(value_to_indices[target])
            else:
                answer.append([-1, -1])

        return answer
```实现首先对字符串进行预处理。 嵌套循环生成从每个索引开始的每个子字符串，但长度最多为 30。 

变量`value`使用位操作增量更新。 左移会将当前数字乘以 2，并且与新位进行“或”运算会附加下一个二进制数字。 

哈希映射存储遇到的每个值的最佳子字符串。 

条件：```python
if value == 0:
    break
```是一种优化。 一旦子字符串值变为零，扩展它只会产生更长的零表示，这永远不是最佳的。 

预处理之后，查询处理变得非常高效。 每个查询计算：```python
target = first ^ second
```并执行恒定时间哈希映射查找。 

## 解决方案```go
func substringXorQueries(s string, queries [][]int) [][]int {
	valueToIndices := make(map[int][]int)

	n := len(s)

	for left := 0; left < n; left++ {
		value := 0

		limit := left + 30
		if limit > n {
			limit = n
		}

		for right := left; right < limit; right++ {
			value = (value << 1) | int(s[right]-'0')

			currentLength := right - left + 1

			if prev, exists := valueToIndices[value]; !exists {
				valueToIndices[value] = []int{left, right}
			} else {
				prevLength := prev[1] - prev[0] + 1

				if currentLength < prevLength {
					valueToIndices[value] = []int{left, right}
				}
			}

			if value == 0 {
				break
			}
		}
	}

	answer := make([][]int, 0, len(queries))

	for _, query := range queries {
		target := query[0] ^ query[1]

		if indices, exists := valueToIndices[target]; exists {
			answer = append(answer, indices)
		} else {
			answer = append(answer, []int{-1, -1})
		}
	}

	return answer
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个`map[int][]int`使用而不是 Python 字典。 二进制值构造使用整数位运算的方式完全相同。 

Go 字符串是字节数组，因此可以通过以下方式提取各个位：```go
s[right] - '0'
```该解决方案安全地适合 Go 的整数范围，因为子字符串长度永远不会超过 30 位。

 ## 边缘情况

 ### 目标值等于零

 价值`0`很特殊，因为许多带有前导零的子字符串的计算结果也为零。 

例如：```
"0"
"00"
"000"
```全部代表十进制值`0`。 

正确答案必须始终是最短的子串，这很简单`"0"`。 

该实现自然地处理这个问题，因为一旦`value == 0`，内循环立即中断。 从不考虑更长的零子串。 

### 多个子字符串产生相同的值

 带有前导零的二进制字符串可能会生成重复值。 

例如：```
"11"   -> 3
"011"  -> 3
"0011" -> 3
```该问题需要选择最短的子串。 如果长度相等，则选择最小的左侧索引。 

哈希映射更新逻辑在替换现有答案之前显式比较子字符串长度。 

### 大查询值

 查询整数可能大到`10^9`。 

幼稚的实现可能会尝试生成任意长的子字符串，从而导致不必要的工作和可能的溢出问题。 

该实现通过将子字符串探索限制为 30 位来避免这种情况，因为：$$2^{30} > 10^9$$这可以保持预处理的效率，并保证所有相关值仍然被正确覆盖。
