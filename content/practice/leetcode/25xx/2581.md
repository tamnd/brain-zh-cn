[LeetCode 问题 2581](https://leetcode.com/problems/count-number-of-possible-root-nodes/)

 **难度：** 🔴难
 **主题：** 数组、哈希表、动态规划、树、深度优先搜索

 ## 解决方案

 ## 问题理解

 这个问题给了我们一棵无向树`n`节点和定向父子猜测列表。 每个猜测都声称当树以某种方式扎根时，一个节点是另一个节点的父节点。 

重要的细节是树本身是无向的。 亲子关系只有在选择根之后才被定义。 一旦选择了根，每条边都会根据有根树结构获得从父节点到子节点的方向。 

对于每个可以充当根的可能节点，我们必须确定有多少猜测是正确的。 一个猜测`[u, v]`是正确的，如果在树生根之后，`u`确实是`v`。 

爱丽丝至少告诉我们`k`猜测是正确的。 我们必须计算在这种情况下有多少个节点可以作为有效根。 

输入包括：

 -`edges`，它定义了无向树
 -`guesses`，其中包含有向父子假设
 -`k`，必须正确的猜测的最小数量

 输出是可以选择作为根的节点数，使得至少`k`猜测成真。 

约束条件非常重要：

 -`n`可以大到`10^5`-`guesses.length`也可以大到`10^5`这立即告诉我们，任何比粗略慢的解决方案`O(n log n)`或者`O(n)`可能会超时。 

重新计算每个可能的根的所有父关系的简单解决方案将变得过于昂贵。 

有几个边缘情况值得注意。 

什么时候`k = 0`，每个节点自动有效，因为总是满足零正确猜测。 

这棵树可能极度不平衡，比如一条直链。 递归深度可能会变大，因此递归深度处理在 Python 中很重要。 

这些猜测可能彼此严重矛盾。 可能没有根至少满足`k`正确的猜测。 

猜测保证与树中的实际边相对应，这简化了验证逻辑，因为我们永远不需要检查猜测的边是否存在。 

## 方法

 ### 蛮力方法

 最直接的解决方案是尝试将每个节点都作为根。 

对于每个根：

 1. 运行 DFS 或 BFS 以确定每个节点的父节点。 
2. 迭代所有猜测。 
3. 计算有多少猜测与计算出的父关系相匹配。 
4. 如果计数至少为`k`，增加答案。 

这种方法是正确的，因为它显式地为每个可能的根构建有根树，并根据实际的父子结构检查每个猜测。 

然而，它太慢了。 

对于每个根：

 - DFS 采取`O(n)`- 检查猜测需要`O(g)`， 在哪里`g = len(guesses)`因为我们对所有人重复这一点`n`根，总复杂度变为：```
O(n * (n + g))
```两者都有`n`和`g`最多`10^5`，这大约变成`10^10`在最坏的情况下进行操作，这在时间限制内是不可能的。 

### 关键见解

 重要的观察结果是，重新扎根树一次只会改变一条边的方向。 

假设我们已经知道当树以节点为根时正确猜测的数量`u`。 

现在想象一下将树重新扎根`u`给它的一个孩子`v`。 

只有一条边改变方向：```
u -> v
```变成```
v -> u
```树中的所有其他父子关系保持不变。 

这意味着我们可以逐步更新正确猜测的计数，而不是从头开始重新计算所有内容。 

具体来说：

 - 如果你猜`(u, v)`存在，以前是正确的，现在变得不正确了。 
- 如果你猜`(v, u)`存在，以前是不正确的，现在变成了正确的。 

因此我们可以在常数时间内计算邻近根的答案。 

这将问题转化为重新根DFS问题。 

我们分两个阶段进行：

 1. 树最初在节点处生根`0`并计算有多少猜测是正确的。 
2. 执行另一个 DFS，在每条边上重新定位树，同时动态更新正确的猜测计数。 

这产生了线性时间解。

 ## 算法演练

 1. 构建树的邻接表。 

由于树是无向的，因此每条边都会在两个方向上添加。 邻接表是理想的选择，因为树是稀疏的并且 DFS 遍历变得高效。 
2. 将所有猜测存储在哈希集中。 

我们需要极快的查找来检查是否有向边`(u, v)`作为猜测而存在。 哈希集提供平均值`O(1)`查找时间。 
3. 选择节点`0`作为初始根。 

实际的根是未知的，但我们可以从任何节点开始。 生根于`0`允许我们计算正确猜测的初始计数。 
4. 运行第一个 DFS 来计算 root 的正确猜测`0`。 

DFS 期间：

 - 如果`(parent, child)`存在于猜测集中，增加计数。 
- 继续递归遍历。 

在 DFS 结束时，我们确切地知道当树的根位于`0`。 
5. 运行第二个 DFS 进行重新 root。 

假设我们将根从`u`给孩子`v`。 

最初我们有一些计数`current_correct`。 

发生两种可能的调整：

 - 如果`(u, v)`存在于猜测中，减少计数，因为这种关系相反。 
- 如果`(v, u)`存在于猜测中，增加计数，因为这种关系现在变得正确了。 

更新后的值成为 root 的正确猜测计数`v`。 
6. 检查每个根是否满足条件。 

在重新root DFS期间：

 - 如果`current_correct >= k`，增加答案。 
- 继续向邻居传播更新的计数。 
7. 返回最终答案。 

### 为什么它有效

 该算法之所以有效，是因为跨一条边重新扎根只会改变该单条边的方向。 所有其他亲子关系保持不变。 

因此，当将根从`u`到`v`，唯一可以改变正确性的猜测是：

 -`(u, v)`-`(v, u)`通过仅使用这些本地更改来更新计数，我们可以正确维护每个可能根的有效猜测数。 

由于在重新生根期间每个节点都被访问一次，因此所有可能的根都会被正确且有效地评估。 

## Python 解决方案```python
from typing import List
from collections import defaultdict
import sys

sys.setrecursionlimit(1 << 20)

class Solution:
    def rootCount(self, edges: List[List[int]], guesses: List[List[int]], k: int) -> int:
        n = len(edges) + 1

        graph = defaultdict(list)

        for u, v in edges:
            graph[u].append(v)
            graph[v].append(u)

        guess_set = set()

        for u, v in guesses:
            guess_set.add((u, v))

        initial_correct = 0

        def count_correct(node: int, parent: int) -> None:
            nonlocal initial_correct

            for neighbor in graph[node]:
                if neighbor == parent:
                    continue

                if (node, neighbor) in guess_set:
                    initial_correct += 1

                count_correct(neighbor, node)

        count_correct(0, -1)

        answer = 0

        def reroot(node: int, parent: int, current_correct: int) -> None:
            nonlocal answer

            if current_correct >= k:
                answer += 1

            for neighbor in graph[node]:
                if neighbor == parent:
                    continue

                next_correct = current_correct

                if (node, neighbor) in guess_set:
                    next_correct -= 1

                if (neighbor, node) in guess_set:
                    next_correct += 1

                reroot(neighbor, node, next_correct)

        reroot(0, -1, initial_correct)

        return answer
```实现首先构建树的邻接列表表示。 由于输入是无向的，因此每条边都会在两个方向上插入。 

猜测存储在一组元组中。 这很重要，因为我们反复检查是否存在特定的有向边。 使用列表会使查找速度太慢。 

第一个 DFS 计算假设节点的正确猜测数`0`是根。 在遍历过程中，每条边自然地从 DFS 方向接收父子方向。 每当`(parent, child)`存在于猜测集中，计数增加。 

第二个DFS执行重新root。 它不会重新计算每个根的整个答案，而是仅根据重新根期间方向发生变化的边缘来调整当前计数。 

如果移动根推翻了先前正确的猜测，则计数会减少。 如果它创建了新的正确猜测，计数就会增加。 

在重新根过程中每个节点都会被访问一次，并且运行计数始终反映当前根的有效猜测的正确数量。 

## 解决方案```go
package main

func rootCount(edges [][]int, guesses [][]int, k int) int {
	n := len(edges) + 1

	graph := make([][]int, n)

	for _, edge := range edges {
		u, v := edge[0], edge[1]

		graph[u] = append(graph[u], v)
		graph[v] = append(graph[v], u)
	}

	guessSet := make(map[[2]int]bool)

	for _, guess := range guesses {
		guessSet[[2]int{guess[0], guess[1]}] = true
	}

	initialCorrect := 0

	var countCorrect func(node, parent int)

	countCorrect = func(node, parent int) {
		for _, neighbor := range graph[node] {
			if neighbor == parent {
				continue
			}

			if guessSet[[2]int{node, neighbor}] {
				initialCorrect++
			}

			countCorrect(neighbor, node)
		}
	}

	countCorrect(0, -1)

	answer := 0

	var reroot func(node, parent, currentCorrect int)

	reroot = func(node, parent, currentCorrect int) {
		if currentCorrect >= k {
			answer++
		}

		for _, neighbor := range graph[node] {
			if neighbor == parent {
				continue
			}

			nextCorrect := currentCorrect

			if guessSet[[2]int{node, neighbor}] {
				nextCorrect--
			}

			if guessSet[[2]int{neighbor, node}] {
				nextCorrect++
			}

			reroot(neighbor, node, nextCorrect)
		}
	}

	reroot(0, -1, initialCorrect)

	return answer
}
```Go 实现遵循与 Python 版本相同的重新根策略。 

Go 使用长度为 2 的固定大小数组作为哈希映射键，而不是 Python 元组：```go
map[[2]int]bool
```Go 切片用于邻接列表。 由于Go不存在Python的递归限制问题，因此不需要显式的递归深度调整，尽管极深的递归理论上在病态情况下仍然可能溢出堆栈。 

所有计数都安全地符合标准`int`因为最大猜测次数只有`10^5`。

from typing import List

class Solution:
    def rootCount(self, edges: List[List[int]], guesses: List[List[int]], k: int) -> int:
        from collections import defaultdict

        graph = defaultdict(list)

        for u, v in edges:
            graph[u].append(v)
            graph[v].append(u)

        guess_set = set(map(tuple, guesses))

        initial_correct = 0

        def dfs(node, parent):
            nonlocal initial_correct

            for neighbor in graph[node]:
                if neighbor == parent:
                    continue

                if (node, neighbor) in guess_set:
                    initial_correct += 1

                dfs(neighbor, node)

        dfs(0, -1)

        answer = 0

        def reroot(node, parent, current):
            nonlocal answer

            if current >= k:
                answer += 1

            for neighbor in graph[node]:
                if neighbor == parent:

                next_current = current

                if (node, neighbor) in guess_set:
                    next_current -= 1

                if (neighbor, node) in guess_set:
                    next_current += 1

                reroot(neighbor, node, next_current)

        reroot(0, -1, initial_correct)

        return answer

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`k = 0`。 在这种情况下，每个节点都必须被认为是有效的，因为至少有零个正确的猜测总是正确的。 有错误的实现可能会意外地应用更严格的逻辑或无法计算所有节点。 这个实现很自然地处理它，因为每个根都满足条件`current_correct >= 0`。 

另一个重要的情况是高度倾斜的树，例如链表形状的树。 递归 DFS 实现可能会变得非常深入。 在 Python 中，递归深度通常会在深度 1000 左右失败。该实现使用以下方式显式增加递归限制：```
sys.setrecursionlimit(1 << 20)
```它安全地支持最大约束大小。 

第三个重要的边缘情况涉及相互矛盾的猜测。 例如，猜测列表可能包含两者`(u, v)`和`(v, u)`。 对于给定的有根树来说，只有其中之一是正确的。 当边缘方向翻转时，不正确的重新根逻辑可能会意外地重复计数或无法正确更新。 重新定位转换显式地独立处理两个方向，确保正确性。 

当没有根满足条件时，会发生另一种微妙的情况。 某些实现错误地假设至少存在一个有效的根。 该解决方案独立检查每个根，并且仅在计数达到时才增加答案`k`，所以返回`0`工作正常。
