[LeetCode 问题 2530](https://leetcode.com/problems/maximal-score-after-applying-k-operations/)

 **难度：** 🟡 中等
 **主题：** 数组、贪婪、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 该问题要求我们在准确执行后最大化分数`k`对整数数组的操作。 每个操作都允许我们选择任何元素`nums[i]`，将其值添加到分数中，然后将其替换为其上限除以 3。本质上，每次我们选择一个数字时，它都会因未来的操作而减少，因此贪婪的选择是始终选择当时**最大的可用数字**，以最大化即时收益。 

输入由一个整数数组组成`nums`长度可达 100,000 和一个数字`k`最多 100,000。 每个数组元素最多可达 10 亿个。 这表明迭代数组以查找每个操作中的最大值的简单方法会太慢，因为它可能导致 O(n * k) 时间复杂度，可能达到 10^10 次操作。 

重要的边缘情况包括具有所有相同数字的数组、具有单个非常大数字的数组以及其中的小数组`k`超过元素数量。 该问题保证至少一个元素和至少一个操作，因此我们不必处理空输入。 

输出是一个整数，表示精确后可达到的最大可能分数`k`运营。 

## 方法

 **暴力方法**将涉及迭代数组以找到每次操作的最大元素，更新它并重复`k`次。 这种方法可以正常工作，因为选择最大的元素可以最大化即时增益。 然而，对于大型阵列和大型`k`，这种方法太慢，最坏情况的时间复杂度为 O(n * k)。 

**最佳方法**使用**最大堆**（优先级队列）。 通过将所有元素推入最大堆，我们可以在 O(log n) 时间内提取当前最大元素，将其添加到分数中，应用上限除法，并将更新后的值推回堆中。 重复这个`k`times 确保我们始终有效地选择最大的可用元素。 

关键的见解是，**在每次操作中贪婪地选择最大元素**始终是最佳的，因为元素的值只会在选择后减少。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n * k) | O(1) | O(1) | 每次扫描数组以找到最大元素 |
 | 最佳 | O(k * log n) | O(k * log n) | O(n) | 使用 max-heap 高效跟踪最大元素 |

 ## 算法演练

 1. **初始化一个最大堆**，其中包含以下所有元素`nums`。 由于 Python 只有最小堆，因此存储负值来模拟最大堆。 
2. **初始化`score`到 0**。 这将累积各个操作的总分。 
3. **重复`k`次数**：

 a. 从堆中提取最大元素（Python 堆中最负的）。 

b. 将此值添加到分数中。 

c. 将更新值计算为`ceil(value / 3)`并将其推回堆中。 
4.完成后`k`运算，**返回累计分数**。 

**为什么有效**：在每一步中，我们总是选择最大的可用元素，确保最大可能的分数增加。 堆保证我们可以有效地找到并更新每次操作的最大元素。 这种贪婪的选择是最优的，因为任何其他元素选择都会产生较小的即时分数，并且对于后续操作来说不会更好，因为所有元素只会随着时间的推移而减少。 

## Python 解决方案```python
from typing import List
import heapq
import math

class Solution:
    def maxKelements(self, nums: List[int], k: int) -> int:
        # Convert nums into a max-heap using negative values
        max_heap = [-num for num in nums]
        heapq.heapify(max_heap)
        
        score = 0
        
        for _ in range(k):
            # Pop the largest element
            current = -heapq.heappop(max_heap)
            score += current
            
            # Apply ceil division and push back
            updated = math.ceil(current / 3)
            heapq.heappush(max_heap, -updated)
        
        return score
```**实施演练**：我们首先转换`nums`通过取负值进入最大堆。 为了`k`操作，我们弹出最大的元素，将其添加到`score`，计算上限除以 3，并将其推回。 使用堆可确保提取和插入元素的时间复杂度为 O(log n)，从而使算法高效。 

## 解决方案```go
package main

import (
    "container/heap"
    "math"
)

type IntHeap []int

func (h IntHeap) Len() int            { return len(h) }
func (h IntHeap) Less(i, j int) bool  { return h[i] > h[j] } // Max-heap
func (h IntHeap) Swap(i, j int)       { h[i], h[j] = h[j], h[i] }
func (h *IntHeap) Push(x any)         { *h = append(*h, x.(int)) }
func (h *IntHeap) Pop() any {
    old := *h
    n := len(old)
    x := old[n-1]
    *h = old[0 : n-1]
    return x
}

func maxKelements(nums []int, k int) int64 {
    maxHeap := &IntHeap{}
    heap.Init(maxHeap)
    for _, num := range nums {
        heap.Push(maxHeap, num)
    }

    var score int64 = 0
    for i := 0; i < k; i++ {
        current := heap.Pop(maxHeap).(int)
        score += int64(current)
        updated := int(math.Ceil(float64(current) / 3.0))
        heap.Push(maxHeap, updated)
    }

    return score
}
```**Go 特定注释**：Go 需要定义堆接口。 这`Less`函数被反转以实现最大堆。 整数溢出是通过使用来处理的`int64`对于分数，因为单个元素最多可达 10^9 并且`k`最多 10^5。

 ## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(k * log n) | O(k * log n) | k 个操作中的每一个都需要提取并插入到堆中，每个 O(log n) |
 | 空间| O(n) | 最大堆存储所有 n 个元素 |

 该算法非常高效，因为它避免了重复扫描数组。 即使对于最大的约束，对 10^5 个元素的堆进行 10^5 次操作也是可行的。
