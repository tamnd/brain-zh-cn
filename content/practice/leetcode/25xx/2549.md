[LeetCode 问题 2549](https://leetcode.com/problems/count-distinct-numbers-on-board/)

 **难度：** 🟢简单

 ## 解决方案

 ## 问题理解

 问题从一个整数开始`n`写在一块板上。 每天，我们都会检查板上当前的每个数字。 对于每个数字`x`，我们寻找所有整数`i`这样：

 -`1 <= i <= n`-`x % i == 1`每当这样的整数`i`存在，我们将其添加到面板中。 数字永远不会被删除，并且重复并不重要，因为最终答案要求在很多天后出现的不同整数的数量。 

尽管模拟持续了`10^9`几天来，重要的观察结果是该过程很快就稳定下来。 任务是确定最终可以在棋盘上出现多少个唯一整数。 

输入由单个正整数组成`n`， 在哪里：```
1 <= n <= 100
```输出是一个整数，表示过程完全稳定后板上将存在的不同整数的总数。 

这个小约束表明，即使是强力模拟在技术上也是可行的，但问题是围绕发现数学模式而不是实施长时间模拟而设计的。 

一个重要的边缘情况是当`n = 1`。 由于没有整数`i`满意：```
1 % i == 1
```对于任何有效的`i`，董事会永远不会改变。 答案依然存在`1`。 

另一个微妙之处是该过程仅添加小于当前数字的数字。 这意味着棋盘逐渐向下填充`2`，但从未达到`1`除非`n`已经开始为`1`。 

## 方法

 ### 暴力模拟

 最简单的方法是完全按照描述模拟该过程。 

我们维护一个包含当前棋盘上所有不同数字的集合。 对于每个数字`x`在集合中，我们测试每个整数`i`从`1`到`n`。 如果：```
x % i == 1
```然后我们添加`i`到集合。 

我们重复这个过程，直到没有新的数字被添加。 

这种方法是正确的，因为它直接遵循问题的规则。 最终，集合稳定下来，因为只有来自的整数`1`到`n`可能会出现。 

然而，对于如此简单的数学模式，该解决方案不必要地复杂。 虽然`n <= 100`使其可行，重复的模块化检查是浪费的。 

### 关键见解

 关键的观察是每个整数`2`通过`n`最终将出现在董事会上`n > 1`。 

为什么？ 

对于任意整数`x > 2`：```
x % (x - 1) == 1
```这意味着如果`x`是在棋盘上，那么`x - 1`最终会被添加。 

开始于`n`，我们可以重复生成：```
n - 1
n - 2
n - 3
...
2
```但`1`永远无法生成，因为：```
x % 1 == 0
```对于每个整数`x`。 

因此：

 - 如果`n == 1`， 仅有的`{1}`存在，答案是`1`- 否则，所有整数`2`到`n`出现，给予`n - 1`不同的整数

 这导致了恒定时间的解决方案。

 | 蛮力 | O(n²) | O(n) | 使用一组 | 模拟整个过程
 | 最佳| O(1) | O(1) | O(1) | O(1) | 使用数学观察从 2 到 n 的所有数字都出现 |

 ## 算法演练

 ### 最优算法

 1. 检查是否`n`等于`1`。 

这是问题中唯一的特殊情况。 如果董事会以`1`，无法生成额外的数字，因为`1 % i`从来没有`1`对于任何有效的`i`。 
2.如果`n == 1`， 返回`1`。 

董事会永远只包含号码`1`。 
3.否则返回`n - 1`。 

开始于`n`，该过程重复生成较小的整数，因为：```
x % (x - 1) == 1
```所以：```
n -> n - 1 -> n - 2 -> ... -> 2
```每个整数来自`2`通过`n`最终出现。 

### 为什么它有效

 关键不变量是任何大于`2`可以生成其直接前身。 由于董事会开始于`n`，重复应用模规则保证每个数字都下降到`2`最终会被添加。 数量`1`永远无法生成，因为取模`1`总是产生`0`， 绝不`1`。 因此，最终的集合恰好包含：```
{2, 3, ..., n}
```什么时候`n > 1`。 

## Python 解决方案```python
class Solution:
    def distinctIntegers(self, n: int) -> int:
        if n == 1:
            return 1
        
        return n - 1
```该实现直接对分析中发现的数学观察结果进行编码。 

第一个条件处理特殊情况，其中董事会以`1`。 在这种情况下，无法添加新数字，所以答案很简单`1`。 

对于每个其他值`n`，算法返回`n - 1`因为所有整数都来自`2`通过`n`最终会出现在黑板上。 

该解决方案不需要模拟、集合、循环或额外的内存，因为过程的行为可以通过数学方式完全表征。 

## 解决方案```go
func distinctIntegers(n int) int {
    if n == 1 {
        return 1
    }

    return n - 1
}
```Go 实现遵循与 Python 解决方案完全相同的逻辑。 

Go 使用显式大括号和类型化整数参数，但除此之外算法保持相同。 由于约束非常小并且结果始终在整数范围内，因此不存在溢出问题。 

不需要切片、地图或额外的数据结构，因为数学观察完全消除了模拟的需要。

 ## 边缘情况

 ### 边缘情况 1，`n = 1`这是问题中最重要的特殊情况。 幼稚的实现可能会错误地返回`0`因为没有生成新的数字。 然而，原来的数字永久保留在棋盘上，所以正确答案是`1`。 

该实现通过以下方式显式处理此问题：```
if n == 1:
    return 1
```### 边缘情况 2，小值，例如`n = 2`为了`n = 2`，该过程不会生成超出以下范围的其他不同数字`2`本身。 由于有效集合变为`{2}`，答案是`1`。 

此案例验证公式应返回`n - 1`， 不是`n`。 

### 边缘情况 3，最大约束`n = 100`尽管约束很小，但该案例证实了数学方法可以完美扩展并避免不必要的模拟。 

暴力解决方案仍然有效，但优化的实现会立即计算结果，无论输入大小如何。
