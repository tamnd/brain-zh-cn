[LeetCode 问题 2535](https://leetcode.com/problems/difference- Between-element-sum-and-digit-sum-of-an-array/)

 **难度：** 🟢简单
 **主题：** 数组、数学

 ## 解决方案

 ## 问题理解

 该问题给了我们一个正整数数组，称为`nums`。 我们需要从这个数组中计算两个不同的值。 

第一个值是元素总和，它只是数组中每个数字的总和。 例如，如果数组是`[1, 15, 6, 3]`，则元素和为：$$1 + 15 + 6 + 3 = 25$$第二个值是数字和。 我们不是直接将数字相加，而是将每个数字分解为单独的数字，然后将这些数字相加。 使用相同的示例：

 -`1`贡献`1`-`15`贡献`1 + 5`-`6`贡献`6`-`3`贡献`3`因此数字和变为：$$1 + 1 + 5 + 6 + 3 = 16$$最后，我们返回这两个总和之间的绝对差：$$|25 - 16| = 9$$输入大小相当小。 数组长度最多可以是`2000`，并且每个数字最多可以是`2000`。 这告诉我们，即使是简单的实现也可以在时间限制内轻松运行。 不需要先进的优化技术或复杂的数据结构。 

一个重要的细节是每个数字都是正数。 这保证了使用重复除法和模运算的数字提取行为干净，无需处理负号。 

一些边缘情况值得注意：

 - 仅包含一位数的数组。 在这种情况下，元素和与数字和相同，所以答案是`0`。 
- 包含数字的数组，例如`1000`其中数字中出现零。 在数字提取过程中仍必须正确处理零。 
- 只有一个元素的数组。 该算法仍必须正确计算两个总和。 
- 最大输入尺寸。 尽管限制很小，但实施仍应避免不必要的开销。 

## 方法

 ### 蛮力方法

 最直接的方法是分别计算元素和和数字和。 

首先，迭代数组并计算所有元素的总和。 然后，再次迭代数组，并使用重复的模和除运算从每个数字中提取每个数字。 

对于每个数字：

 - 采取`num % 10`获取最后一位数字
 -将该数字添加到数字和中
 - 使用删除最后一位数字`num //= 10`- 重复直到数字变为`0`这种方法是正确的，因为每个数字的每个数字都只处理一次，并且每个数组元素在元素和中只包含一次。 

尽管这被称为强力方法，但对于给定的约束来说它已经足够有效了。 

### 最佳方法

 我们可以通过在一次数组遍历中计算两个总和来稍微改进实现。 

而不是进行两次单独的传递：

 - 将每个数字直接添加到元素和中
 - 同时提取其数字并累加为数字和

 这避免了对数组的额外传递，并保持逻辑紧凑和高效。 

关键的见解是数字提取本身已经非常便宜，因为每个数字只包含几个数字。 由于最大值是`2000`，每个数字最多有四位数字。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n × d) | O(1) | O(1) | 元素和和数字和的单独传递 |
 | 最佳| O(n × d) | O(1) | O(1) | 在一次遍历中计算两个总和 |

 这里：

-`n`是元素的数量
 -`d`是每个元素的位数

 自从`d`至多是`4`，运行时间实际上是线性的。 

## 算法演练

 1.初始化两个变量，`element_sum`和`digit_sum`，都开始于`0`。 
2. 遍历里面的每一个数`nums`。 
3.直接将当前号码添加到`element_sum`。 
4. 创建一个等于当前数字的临时变量。 这可以防止修改原始值。 
5. 使用模和除法一位一位地提取数字：

 - 使用`temp % 10`得到最后一位数字。 
-将该数字添加到`digit_sum`。 
- 使用整数除法删除最后一位数字：`temp //= 10`。 
6. 继续数字提取循环，直到临时值变为`0`。 
7. 处理完所有数字后，计算：$$|element\_sum - digit\_sum|$$8. 返回绝对差值。 

### 为什么它有效

 该算法之所以有效，是因为每个数字对元素和只贡献一次，并且每个数字的每个数字对数字和只贡献一次。 模运算从右到左检索数字，而整数除法则删除已处理的数字。 由于没有数字被跳过或重复，因此计算出的数字和是正确的。 无论哪个和较大，最后取绝对差都可以保证所需的结果。 

## Python 解决方案```python
from typing import List

class Solution:
    def differenceOfSum(self, nums: List[int]) -> int:
        element_sum = 0
        digit_sum = 0

        for num in nums:
            element_sum += num

            temp = num

            while temp > 0:
                digit_sum += temp % 10
                temp //= 10

        return abs(element_sum - digit_sum)
```该实现紧密遵循前面描述的算法。 

变量`element_sum`和`digit_sum`存储两个所需的总计。 在循环过程中`nums`，每个数字立即添加到`element_sum`。 

为了计算数字和，代码将当前数字复制到`temp`。 使用整数除法重复减少该临时变量，同时使用模提取最后一位数字。 

循环：```python
while temp > 0:
```继续，直到处理完所有数字。 每个提取的数字都添加到`digit_sum`。 

最后，该函数返回两个计算总和之间的绝对差。 

## 解决方案```go
func differenceOfSum(nums []int) int {
	elementSum := 0
	digitSum := 0

	for _, num := range nums {
		elementSum += num

		temp := num

		for temp > 0 {
			digitSum += temp % 10
			temp /= 10
		}
	}

	diff := elementSum - digitSum

	if diff < 0 {
		return -diff
	}

	return diff
}
```Go 实现非常接近地反映了 Python 解决方案。 

一个小小的区别是 Go 没有提供内置的`abs`标准库中的整数函数无需导入额外的包，因此代码手动检查差异是否为负数。 

问题约束保证整数溢出不是问题，因为最大可能的和相对于 Go 的整数范围非常小。 

空切片不需要特殊处理，因为约束保证至少有一个元素。

 ## 边缘情况

 当每个数字都已经是一位数字时，就会出现一个重要的边缘情况。 在这种情况下，数字和和元素和是相同的，因为每个数字贡献的数字恰好等于其自身。 粗心的实现可能会使逻辑过于复杂，但该解决方案自然可以处理它，因为数字提取只是返回原始数字。 

另一个重要的情况涉及包含零的数字，例如`1000`。 一些有缺陷的实现会意外地跳过零或错误地终止数字提取。 此实现避免了该问题，因为模运算正确提取`0`数字，除法循环继续进行，直到处理完整个数字。 

第三种边缘情况是尽可能小的数组大小，其中数组仅包含一个元素。 错误地假设多次迭代或依赖成对处理的算法可能会在这里失败。 此实现可以正常工作，因为每个数字都是独立处理的。 

最后，最大约束情况测试实现在大量输入下是否保持高效。 即使与`2000`数字，每个数字最多包含四位数字，该算法仅对每个元素执行少量恒定的工作，因此它很容易保持在可接受的运行时间限制内。
