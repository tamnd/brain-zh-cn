[LeetCode 问题 2528](https://leetcode.com/problems/maximize-the-minimum-powered-city/)

 **难度：** 🔴难
 **主题：** 数组、二分搜索、贪婪、队列、滑动窗口、前缀和

 ## 解决方案

 ## 问题理解

 该问题要求我们确定任何城市在优化添加后可以拥有的**最大可能的最小功率**`k`现有配置的新发电站。 每个城市已经有一些发电站，每个发电站都有一个**范围**`r`它为附近城市的力量做出了贡献。 **一座城市的力量**是影响该城市的所有站点的总和，包括原始站点和新增站点。 

输入由一个数组组成`stations`长度`n`， 在哪里`stations[i]`是城市现有车站的数量`i`。 我们还给出了范围`r`以及新站数量`k`可以添加到任何地方。 输出是一个代表**最大最小功率**的单个整数，如果我们将`k`新站优化。 

约束表明`n`可以大到`10^5`和`k`最多`10^9`。 这表明检查所有可能的站位置的简单解决方案是不可行的，并且需要**对数或线性扫描方法**。 边缘情况包括`r = 0`其中车站只影响自己的城市，`k = 0`这意味着无法添加站点，并且站点分布均匀或高度倾斜的阵列。 

## 方法

 **暴力方法**会尝试所有可能的分发方式`k`跨城市的站点并计算由此产生的最小城市功率。 这显然是不可行的，因为分布的数量与`n`和`k`。 

**最佳解决方案**的关键见解是，问题可以简化为**决策问题**：对于给定的目标最小功率`target`，我们能否放置站点使得每个城市的功率至少为`target`？ 如果我们能够有效地解决这个问题，我们就可以对可能的最小功率值使用**二分搜索**。 检查给定的可行性`target`，我们可以使用**带有前缀和数组的滑动窗口**来有效地维护添加站点的累积效果，确保 O(n) 检查。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O((n+k)^n) | O((n+k)^n) | O(n) | 检查k个站的所有可能的放置位置； 约束条件下不可行 |
 | 最佳 | O(n log(max_possible_power)) | O(n log(max_possible_power)) | O(n) | 使用最小功率二分搜索和滑动窗口/前缀和来有效检查可行性 |

 ## 算法演练

 1. 初始化`low`作为所有城市的最小当前功率，并且`high`作为最大可能的功率，如果所有`k`将站点添加到单个城市及其范围贡献。 
2. 执行二分查找`low < high`。 对于每个`mid = (low + high + 1) // 2`:

 a. 检查确保每个城市至少有`mid`力量。 

b. 为了有效地做到这一点，请使用**滑动窗口**来表示影响当前城市的添加车站的总和。 

c. 从左到右遍历城市，每当当前城市的有效功率（原始+通过窗口添加）低于`mid`，添加必要的电台以使其达到`mid`。 更新滑动窗口以将其影响传播到下一个城市。 

d. 如果添加的总站数超过`k`,`mid`不可行。 
3.如果`mid`可行，更新`low = mid`; 否则，更新`high = mid - 1`。 
4. 返回`low`二分查找结束后。 

为什么有效：二分搜索保证我们找到最大可行最小值，因为每个可行性检查都是单调的 - 如果目标可以实现，则任何较低的目标也可以实现。 滑动窗口确保有效地考虑添加站点的影响，而无需针对每个城市重新计算。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxPower(self, stations: List[int], r: int, k: int) -> int:
        n = len(stations)

        def is_feasible(target: int) -> bool:
            added = [0] * n
            window_sum = 0
            used_stations = 0
            for i in range(n):
                if i > r:
                    window_sum -= added[i - r - 1]
                current_power = stations[i] + window_sum
                if current_power < target:
                    need = target - current_power
                    added[i] = need
                    window_sum += need
                    used_stations += need
                    if used_stations > k:
                        return False
            return True

        low, high = min(stations), max(stations) + k
        while low < high:
            mid = (low + high + 1) // 2
            if is_feasible(mid):
                low = mid
            else:
                high = mid - 1
        return low
```Python代码使用滑动窗口实现了二分查找。 这`is_feasible`函数检查是否可以使用最多使用来实现给定的最小功率`k`额外的站点，使用类似前缀的滑动窗口来有效地传播添加的站点效果。 

## 解决方案```go
func maxPower(stations []int, r int, k int) int64 {
    n := len(stations)
    added := make([]int64, n)

    var isFeasible func(int64) bool
    isFeasible = func(target int64) bool {
        var windowSum, usedStations int64
        for i := 0; i < n; i++ {
            if i > r {
                windowSum -= added[i - r - 1]
            }
            currentPower := int64(stations[i]) + windowSum
            if currentPower < target {
                need := target - currentPower
                added[i] = need
                windowSum += need
                usedStations += need
                if usedStations > int64(k) {
                    return false
                }
            } else {
                added[i] = 0
            }
        }
        return true
    }

    low, high := int64(stations[0]), int64(k)
    for _, val := range stations {
        if int64(val) > high {
            high = int64(val) + int64(k)
        }
    }

    for low < high {
        mid := (low + high + 1) / 2
        // reset added array
        for i := range added {
            added[i] = 0
        }
        if isFeasible(mid) {
            low = mid
        } else {
            high = mid - 1
        }
    }
    return low
}
```在 Go 中，切片和 int64 用于安全地处理大数。 逻辑反映了 Python 版本，并显式重置了`added`在每次可行性检查之前进行切片。 

## 工作示例

 ### 示例 1

 输入：`stations = [1,2,4,5,0], r = 1, k = 2`，目标最小功率检查：`5`。 

| 城市 | 原创| 窗口总和 | 添加| 有效 |
 | ---| ---| ---| ---| ---|
 | 0 | 1 | 0 | 4 | 5 |
 | 1 | 2 | 4 | 0 | 6 |
 | 2 | 4 | 4 | 0 | 8 |
 | 3 | 5 | 4 | 0 | 9 |
 | 4 | 0 | 0 | 5 | 5 |

 达到的最小功率为5，总添加站= 2 ≤ k，因此可行。 

### 示例 2

 输入：`stations = [4,4,4,4], r = 0, k = 3`，可实现的最大最小值 = 4，因为每个站点仅影响其城市。 在任意位置添加 3 都无法使最小值超过 4。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n log(max_possible_power)) | O(n log(max_possible_power)) | 对可能的功率值进行二分搜索并进行 O(n) 可行性检查 |
 | 空间| O(n) | 对于`added`滑动窗口中使用的数组|

 二分搜索范围以最大当前功率加上 k 为界，每次检查都会迭代 n 个城市，从而给出整体复杂性。
