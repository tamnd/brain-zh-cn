[LeetCode 问题 2509](https://leetcode.com/problems/cycle-length-queries-in-a-tree/)

 **难度：** 🔴难
 **主题：** 数组、树、二叉树

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个完整的二叉树，其中节点的标记方式与二叉堆相同。 

对于每个有值的节点`x`：

 - 它的左孩子是`2 * x`- 它的右孩子是`2 * x + 1`该树包含来自的所有节点值`1`到`2^n - 1`。 

对于每个查询`[a, b]`，我们临时添加一条额外的直接连接节点的边`a`和节点`b`。 由于原始结构是一棵树，因此任意两个节点之间都存在一条简单路径。 在之间添加一条额外的边`a`和`b`恰好创建一个周期。 

该周期的长度等于：

 - 之间的原始路径中的边数`a`和`b`- 加上新添加的边缘

 所以真正的任务是计算节点之间的距离`a`和`b`在二叉树中，然后添加`1`。 

因此，每个查询的输出为：```
distance(a, b) + 1
```约束条件很重要：

 -`n <= 30`-`m <= 10^5`尽管理论上这棵树可以包含最多`2^30 - 1`节点，我们从未被要求显式构建它。 在内存中构建整个树是不可能的。 

节点编号方案为我们提供了一个非常重要的属性：

 - 节点的父节点`x`是`x // 2`这意味着我们可以在不存储树的情况下有效地向上移动到根。 

一些重要的边缘情况包括：

 - 一个节点是另一个节点的祖先
 - 涉及根节点的查询
 - 附近的深层节点`2^30 - 1`- 大量查询，低效遍历会超时

 该问题保证：

 -`a != b`- 所有节点值均有效
 - 在添加额外边之前，图始终是一棵树

 这些保证简化了实现，因为我们永远不需要处理无效输入或断开连接的结构。 

## 方法

 ### 蛮力方法

 一个简单的解决方案将二叉树显式建模为图。 

对于每个查询：

 1. 构建或遍历树
 2. 使用BFS或DFS寻找之间的最短路径`a`和`b`3.添加`1`考虑新添加的边

 这是可行的，因为一棵树在任意两个节点之间只有一条简单路径。 

然而，这种方法太慢并且占用大量内存。 该树最多可以包含：```
2^30 - 1 ≈ 1 billion nodes
```建立这样的图表是不可能的。 

即使我们避免了完整的构造并动态搜索，执行图形遍历最多`10^5`查询仍然效率低下。 

### 关键见解

 节点编号直接编码树结构。 

对于任意节点：```
parent(x) = x // 2
```这意味着我们可以从任何节点向上移动到根，而无需存储树。 

通过重复向上移动较深的节点直到两个节点变得相等，可以找到两个节点之间的路径。 这正是使用父跳转找到最低共同祖先的过程。 

每一次向上的移动都对应于路径中的一条边。 

因此：

 - 计算两个节点相遇之前需要多少次向上移动
 - 添加`1`对于新插入的边

 因为节点值最多是`2^30 - 1`，每个节点最多有高度`30`。 所以每个查询最多需要大约`60`向上移动。 

这是非常有效的。

## 算法演练

 1. 初始化一个空答案列表。 
2. 对于每个查询`[a, b]`，启动一个计数器`1`。 

计数器开始于`1`因为之间新添加的边`a`和`b`始终是循环的一部分。 
3.同时`a`和`b`不同时，将较大的节点向上移动。 

由于在此编号方案中较大的节点值总是较深或处于相同深度，因此向上移动较大的值有助于两个节点向其最低公共祖先收敛。 
4.如果`a > b`， 代替`a`和`a // 2`。 

这会移动节点`a`给它的父级。 
5. 否则，更换`b`和`b // 2`。 

这会移动节点`b`给它的父级。 
6. 每次向上移动后递增计数器。 

每一步都代表在原始路径中遍历一个树边缘`a`和`b`。 
7. 继续直到`a == b`。 

此时，两个节点已在其最低共同祖先处相遇。 
8. 将计数器添加到答案列表中。 
9. 处理完所有查询后返回答案列表。 

### 为什么它有效

 一棵树只包含任意两个节点之间的一条简单路径。 反复向上移动更深的节点会逐条重建该路径，直到两个节点在其最低公共祖先处相遇。 

向上移动的次数等于原始树中两个节点之间的距离。 由于添加的边也属于环，所以最终的环长度为：```
distance(a, b) + 1
```该算法精确计算这些边缘，因此它总是产生正确的答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def cycleLengthQueries(self, n: int, queries: List[List[int]]) -> List[int]:
        answers = []

        for a, b in queries:
            cycle_length = 1

            while a != b:
                if a > b:
                    a //= 2
                else:
                    b //= 2

                cycle_length += 1

            answers.append(cycle_length)

        return answers
```实现直接遵循算法。 

这`answers`list 存储每个查询的结果。 

对于每个查询，变量`cycle_length`开始于`1`因为两个节点之间添加的额外边总是包含在循环中。 

这`while a != b`循环继续，直到两个节点在其最低公共祖先处相遇。 

循环内部：

 - 使用整数除法将较大的节点向上移动`2`- 周期长度计数器增加`1`每次迭代对应于遍历树中的一条边。 

一旦两个节点变得相等，它们之间的整个路径就被计算在内，并且最终的循环长度被附加到结果列表中。 

参数`n`未显式使用，因为节点标签已包含导航树所需的所有结构信息。 

## 解决方案```go
func cycleLengthQueries(n int, queries [][]int) []int {
    answers := make([]int, 0, len(queries))

    for _, query := range queries {
        a := query[0]
        b := query[1]

        cycleLength := 1

        for a != b {
            if a > b {
                a /= 2
            } else {
                b /= 2
            }

            cycleLength++
        }

        answers = append(answers, cycleLength)
    }

    return answers
}
```Go 的实现与 Python 解决方案非常相似。 

一个名为`answers`预分配的容量等于查询数量，以提高效率。 

Go 自动对整数使用整数除法，所以`a /= 2`正确地将节点移动到其父节点。 

不需要对溢出进行特殊处理，因为最大节点值低于`2^30`，很容易符合 Go 的标准`int`在 LeetCode 平台上输入。

 ## 边缘情况

 ### 一个节点是另一个节点的祖先

 错误的常见来源是当一个节点直接位于到另一节点的根的路径上时。 

例如：```
a = 2
b = 8
```路径是：```
8 -> 4 -> 2
```该实现自然地处理了这个问题，因为更深的节点会重复向上移动，直到两个值匹配。 不需要特殊的祖先检测。 

### 涉及根的查询

 根节点没有父节点，因此假设每个节点都可以继续向上移动的算法可能会失败。 

例如：```
a = 1
b = 31
```一旦两个节点变得相等，实现就会立即停止，因此可以安全地处理根，而不会产生无效的父访问。 

### 非常大的节点值

 最大可能的节点值接近于`2^30`。 

简单的图构造在内存和运行时都是不可能的。 

该实现完全避免了构建树，而是仅依赖于整数算术。 每次向上移动都会将该值除以`2`，所以即使是最大的节点最多也需要大约`30`迭代。 

### 不同深度子树中的节点

 当节点属于完全不同的分支时，最低共同祖先可能接近根。 

例如：```
16 and 31
```该实现根据当前较大的节点正确地交替向上移动，最终收敛于共同祖先，同时对每个遍历的边进行一次计数。
