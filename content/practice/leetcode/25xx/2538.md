[LeetCode 问题 2538](https://leetcode.com/problems/difference- Between-maximum-and-minimum-price-sum/)

 **难度：** 🔴难
 **主题：** 数组、动态规划、树、深度优先搜索

 ## 解决方案

 ## 问题理解

 我们有一棵无向树`n`节点。 每个节点都有一个价格值。 由于图是一棵树，因此任意两个节点之间都存在一条简单路径。 

该问题允许我们选择任何节点作为树的根。 选择根后，我们考虑从该根开始并向下到达树中任何节点的所有路径。 每条这样的路径都有一个价格总和，即该路径上所有节点的价格总和。 

对于选定的根：

 - 最大价格总和是最昂贵的根到节点路径。 
- 最小价格总和是最便宜的根到节点路径。 

该根的成本是：$$\text{maximum path sum} - \text{minimum path sum}$$我们必须计算所有根选择中可能的最大成本。 

一个重要的观察是，最小根起始路径始终只是根本身，因为所有价格都是正数：$$1 \le price[i]$$这意味着延长路径总是会增加总和。 所以：$$\text{minimum path sum} = price[root]$$那么问题就变成了：$$\max_{root} (\text{maximum root-to-node path sum} - price[root])$$同样，对于每个节点，我们想要从该节点开始到其他任何地方结束的最大路径总和，从减法中排除起始节点自身的贡献。 

限制条件很大：

 -`n <= 10^5`- 该图是一棵树，所以有`n - 1`边缘。 

这立即排除了从每个节点独立执行 DFS 或 BFS 的算法，因为`O(n^2)`解决方案会超时。 

重要的边缘情况包括：

 - 一棵只有一个节点的树。 
- 链形树，可以创建深度递归和长路径和。 
- 一棵星形树，其中一个节点连接到所有其他节点。 
- 到处都是同等的价格。 
- 价格总和非常大，需要在 Go 中进行 64 位整数处理。 

## 方法

 ### 蛮力方法

 暴力方法尝试将每个节点作为根。 

对于每个根：

 1. 运行 DFS 或 BFS 来计算从该根开始的最大路径和。 
2. 由于最小路径始终是根本身，因此减去`price[root]`。 
3. 跟踪全局最大值。 

这是有效的，因为它直接遵循问题的定义。 

然而，每个 DFS 需要`O(n)`时间，我们为所有人表演`n`节点：$$O(n^2)$$和`n = 10^5`，这太慢了。 

### 关键见解

 重要的观察结果是，节点的答案取决于穿过其邻居的最佳路径。 

这成为一个经典的树动态规划和重生问题。 

对于每个节点，我们想知道：

 - 其子树内的最佳向下路径。 
- 来自其父方的最佳路径。 

我们可以计算可重用的 DP 值，而不是独立地重新计算每个根的所有内容。 

一个特别优雅的公式在 DFS 期间保持两种状态：

 - 端点正常贡献的路径。 
- 一个端点被视为“免费”的路径，这意味着我们不会将该端点的价格计入最终差异中。 

在遍历树时，我们结合子贡献并全局更新答案。 

最佳解决方案使用两个 DFS 遍历合并为一个递归转换并以线性时间运行。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 从每个节点运行 DFS |
 | 最佳| O(n) | O(n) | 具有重新生根功能的树 DP |

 ## 算法演练

 我们为树建立一个邻接表，因为树是稀疏图，邻接表允许有效的遍历。 

我们从任意节点开始执行DFS，通常是节点`0`。 

在DFS期间，每个节点返回两个值：

 -`with_leaf`，从该节点开始到下方某处结束的最大路径总和，其中结束节点已被完全计数。 
-`without_leaf`，最大路径总和，其中结束叶被排除在贡献之外。 

第二个状态是模拟最小路径减法的关键技巧。 

### 第 1 步：构建邻接表

 对于每一个边缘`[u, v]`：

- 添加`v`到`u`的邻接表。 
- 添加`u`到`v`的邻接表。 

这允许在两个方向上进行有效的遍历。 

### 步骤 2：定义 DFS 状态

 对于每个节点：

 -`max_with_leaf`表示从该节点开始并包括所有节点价格的最佳路径总和。 
-`max_without_leaf`表示从该节点开始且排除一个端点的最佳路径总和。 

最初：$$max\_with\_leaf = price[node]$$

$$max\_without\_leaf = 0$$第二个值为零，因为仅由当前节点组成的路径在排除叶子后没有任何贡献。 

### 步骤 3：处理子进程

 对于每个孩子：

 - 递归计算子状态。 
- 将当前节点状态与子状态组合。 

假设孩子返回：

 -`child_with`-`child_without`然后出现两个候选答案：$$max\_with\_leaf + child\_without$$和$$max\_without\_leaf + child\_with$$这些代表组合两种互补的路径类型。 

使用这些组合中的最大值更新全局答案。 

### 步骤 4：更新 DP 状态

 我们使用子贡献来扩展当前节点的最佳状态。 

更新：$$max\_with\_leaf = \max(max\_with\_leaf,\ price[node] + child\_with)$$

$$max\_without\_leaf = \max(max\_without\_leaf,\ price[node] + child\_without)$$### 步骤 5：向上返回状态

 将两个更新后的值返回给父级。 

最终，全局答案包含最大可能的差异。 

### 为什么它有效

 每个有效答案都对应一条路径，其中一个端点完全贡献，而另一个端点则被排除在减法之外。 

两个 DP 状态精确地模拟了这两种可能性。 在 DFS 期间，每条边都被视为两个部分路径之间的连接点。 由于该算法结合了所有可能的子贡献并向上传播最佳状态，因此每个有效路径配置都会被检查一次。 

因此，DFS计算出的全局最大值就是最优答案。 

## Python 解决方案```python
from typing import List
import sys

sys.setrecursionlimit(1 << 20)

class Solution:
    def maxOutput(self, n: int, edges: List[List[int]], price: List[int]) -> int:
        graph = [[] for _ in range(n)]

        for u, v in edges:
            graph[u].append(v)
            graph[v].append(u)

        answer = 0

        def dfs(node: int, parent: int):
            nonlocal answer

            max_with_leaf = price[node]
            max_without_leaf = 0

            for neighbor in graph[node]:
                if neighbor == parent:
                    continue

                child_with_leaf, child_without_leaf = dfs(neighbor, node)

                answer = max(
                    answer,
                    max_with_leaf + child_without_leaf,
                    max_without_leaf + child_with_leaf,
                )

                max_with_leaf = max(
                    max_with_leaf,
                    price[node] + child_with_leaf
                )

                max_without_leaf = max(
                    max_without_leaf,
                    price[node] + child_without_leaf
                )

            return max_with_leaf, max_without_leaf

        dfs(0, -1)

        return answer
```实现首先构建树的邻接列表表示。 由于该图是无向的，因此每条边都在两个方向上插入。 

DFS 函数为每个节点返回两个 DP 值。 第一个表示包括所有节点的最佳路径总和，而第二个表示排除一个端点的最佳路径总和。 

对于每个孩子，算法首先递归地计算孩子的状态。 然后它将这些状态与当前节点的状态组合起来以更新全局答案。 

更新公式确保探索所有有效的路径配置。 

最后，DFS 向上返回最佳状态，以便父节点可以继续构建更大的路径。 

## 解决方案```go
package main

func maxOutput(n int, edges [][]int, price []int) int64 {
	graph := make([][]int, n)

	for _, edge := range edges {
		u := edge[0]
		v := edge[1]

		graph[u] = append(graph[u], v)
		graph[v] = append(graph[v], u)
	}

	var answer int64 = 0

	var dfs func(int, int) (int64, int64)

	dfs = func(node int, parent int) (int64, int64) {
		maxWithLeaf := int64(price[node])
		var maxWithoutLeaf int64 = 0

		for _, neighbor := range graph[node] {
			if neighbor == parent {
				continue
			}

			childWithLeaf, childWithoutLeaf := dfs(neighbor, node)

			candidate1 := maxWithLeaf + childWithoutLeaf
			candidate2 := maxWithoutLeaf + childWithLeaf

			answer = max64(answer, candidate1)
			answer = max64(answer, candidate2)

			maxWithLeaf = max64(
				maxWithLeaf,
				int64(price[node])+childWithLeaf,
			)

			maxWithoutLeaf = max64(
				maxWithoutLeaf,
				int64(price[node])+childWithoutLeaf,
			)
		}

		return maxWithLeaf, maxWithoutLeaf
	}

	dfs(0, -1)

	return answer
}

func max64(a, b int64) int64 {
	if a > b {
		return a
	}
	return b
}
```Go 实现遵循与 Python 版本完全相同的 DP 逻辑。 

主要的实现差异在于整数处理。 由于路径总和可能会变大，因此该解决方案使用`int64`到处都是 DP 值和最终答案。 

DFS 是作为递归闭包实现的。 邻接表使用切片的切片，这是 Go 中的标准图形表示形式。

 DFS 恰好遍历每条边两次，每个方向一次。 所有 DP 转换都是恒定时间操作，因此总运行时间与节点数量呈线性关系。

 ## 边缘情况

 单节点树是最小的有效输入。 由于唯一的路径是节点本身，因此最大和最小路径和相等。 因此正确答案是零。 许多实现意外地假设至少存在一个边，但该解决方案正确地初始化了 DFS 状态，以便不会发生无效转换。 

如果父跟踪处理不当，链形树可能会产生递归深度问题和不正确的 DP 传播。 由于除了末端之外，每个节点只有一个子节点，因此该算法的行为实际上类似于链表上的动态编程。 该实现避免了重新访问父节点，防止无限递归并确保每条边都被处理一次。 

星形树强调合并逻辑，因为一个中心节点结合了许多子贡献。 不正确的实现有时会在迭代子级时过早覆盖 DP 值。 该解决方案在修改当前节点的 DP 状态之前仔细更新全局答案，确保正确评估每个子组合。 

当所有节点价格相同时，会出现另一种微妙的边缘情况。 在这种情况下，最佳答案完全取决于路径长度而不是值分布。 DP 转换保持正确，因为无论值是否不同，它们都会最大化累积和。
