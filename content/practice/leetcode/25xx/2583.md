[LeetCode 问题 2583](https://leetcode.com/problems/kth-largest-sum-in-a-binary-tree/)

 **难度：** 🟡 中等
 **主题：** 树、广度优先搜索、排序、二叉树

 ## 解决方案

 ## 问题理解

 该问题给出了二叉树的根和一个整数`k`。 对于树中的每个级别，我们计算该级别上出现的所有节点值的总和。 计算完所有级别的总和后，我们必须返回`kth`最大级别总和。 

二叉树的层级由距根的距离决定。 根本身是水平的`0`，它的孩子们处于同一水平`1`，他们的孩子处于同一水平`2`， 等等。 共享相同深度的节点属于同一级别。 

例如，如果一个级别包含节点`[2, 1, 3, 7]`，则水平总和为：```
2 + 1 + 3 + 7 = 13
```该问题明确指出，总和不需要不同。 这意味着在确定重复金额时会单独计算`kth`最大的值。 

约束条件很重要：

 - 树最多可以包含`10^5`节点
 - 节点值可以大到`10^6`-`k`也可以大到`10^5`这些限制立即告诉我们，我们需要有效的遍历。 任何比粗略更糟糕的算法`O(n log n)`可能会在上限上挣扎。 

一个重要的观察是，级别顺序遍历自然地按深度对节点进行分组。 因此，广度优先搜索（BFS）非常适合解决这个问题。 

一些边缘情况值得预先考虑：

 - 树可能只包含一层
 -`k`可能大于级别数，在这种情况下我们必须返回`-1`- 多个级别可能具有相同的总和
 - 树可能极度不平衡，表现得几乎像一个链表
 - 级别总和可能会变得非常大，尤其是在 Go 中，因此使用`int64`很重要

 ## 方法

 ### 蛮力方法

 强力解决方案将首先单独计算每个节点的深度。 对于每个可能的级别，我们可以运行另一个遍历来对属于该级别的所有节点求和。 

例如：

 1.计算树高
 2. 对于每个级别`0`到`height`3. 再次遍历整棵树，收集该深度的节点
 4. 存储级别总和
 5. 对所有总和进行排序并返回`kth`最大的

 这种方法是正确的，因为每个级别都是独立处理的，并且所有总和都经过准确计算。 

然而，它的效率很低。 如果树有高度`h`，并且我们为每个级别遍历树一次，总复杂度约为`O(n * h)`。 在最坏的情况下，倾斜的树有高度`n`，生产`O(n^2)`时间复杂度。 

和`10^5`节点，这太慢了。 

### 最佳方法

 关键的见解是广度优先搜索已经逐级处理树。 

我们可以执行一次 BFS 遍历，而不是重复遍历树：

 1、使用队列逐级处理节点
 2. 对于每个级别，计算总和，同时从队列中删除节点
 3. 存储每个级别的总和
 4. 将收集到的金额按降序排序
 5. 返回`kth`最大值

 这可以有效地工作，因为每个节点都被访问一次。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(h) | 重复遍历树的每一层|
 | 最佳 | O(n + L log L) | O(n + L log L) | O(L + w) | 单次BFS遍历，其中`L`是级别数并且`w`是最大宽度|

 这里：

-`L`是级别数
 -`w`是一次存储在队列中的最大节点数

 ## 算法演练

 ### 第 1 步：初始化 BFS 队列

 我们使用队列是因为 BFS 自然地逐级处理节点。 首先将根节点放入队列中。 

### 步骤 2：一次处理一个级别

 在每次迭代开始时，队列恰好包含当前级别的节点。 

我们记录当前队列大小，因为这告诉我们有多少节点属于该级别。 

### 第 3 步：计算级别总和

 准确删除`level_size`队列中的节点。 

对于每个节点：

 - 将其值添加到当前级别总和中
 - 将其左孩子推入队列（如果存在）
 - 将其右子节点推入队列（如果存在）

 处理完当前级别的所有节点后，我们就得到了该级别的完整总和。 

### 步骤 4：存储级别总和

 将计算出的总和附加到级别总和列表中。 

###第5步：重复直到遍历完成

 继续 BFS 过程，直到队列变空。 

那时，所有级别都已被处理一次。 

### 第 6 步：检查是否`k`有效

 如果层数小于`k`， 返回`-1`。 

### 步骤 7：对级别总和进行排序

 按降序对总和进行排序。 

这`kth`最大的总和位于索引处`k - 1`。 

### 为什么它有效

 BFS保证节点被逐级处理。 在每次迭代开始时，队列仅包含来自相同深度的节点。 通过精确处理当前队列大小，我们可以在进入下一个级别之前完全隔离一个级别。 

因为每个节点都被访问一次并且对其相应的级别和贡献一次，所以结果列表包含所有正确的级别和。 对这些总和进行排序可以直接检索`kth`最大的值。 

## Python 解决方案```python
from collections import deque
from typing import Optional

# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

class Solution:
    def kthLargestLevelSum(self, root: Optional[TreeNode], k: int) -> int:
        queue = deque([root])
        level_sums = []

        while queue:
            level_size = len(queue)
            current_sum = 0

            for _ in range(level_size):
                node = queue.popleft()
                current_sum += node.val

                if node.left:
                    queue.append(node.left)

                if node.right:
                    queue.append(node.right)

            level_sums.append(current_sum)

        if len(level_sums) < k:
            return -1

        level_sums.sort(reverse=True)

        return level_sums[k - 1]
```The implementation follows the BFS algorithm directly.

 队列以根节点初始化。 During each iteration of the outer loop, we process one full level. 变量`level_size`捕获有多少节点属于当前级别，确保我们不会意外地混合不同深度的节点。 

变量`current_sum`累加当前层所有节点的值。 在处理节点时，我们还将它们的子节点排队，以便下一次迭代可以处理下一个级别。 

处理完所有级别后，列表`level_sums`包含树中每个级别的总和。 我们验证至少`k`水平存在。 如果没有，我们返回`-1`。 

最后，我们按降序对总和进行排序并返回索引处的元素`k - 1`。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */

import "sort"

func kthLargestLevelSum(root *TreeNode, k int) int64 {
    queue := []*TreeNode{root}
    levelSums := []int64{}

    for len(queue) > 0 {
        levelSize := len(queue)
        var currentSum int64 = 0

        for i := 0; i < levelSize; i++ {
            node := queue[0]
            queue = queue[1:]

            currentSum += int64(node.Val)

            if node.Left != nil {
                queue = append(queue, node.Left)
            }

            if node.Right != nil {
                queue = append(queue, node.Right)
            }
        }

        levelSums = append(levelSums, currentSum)
    }

    if len(levelSums) < k {
        return -1
    }

    sort.Slice(levelSums, func(i, j int) bool {
        return levelSums[i] > levelSums[j]
    })

    return levelSums[k-1]
}
```Go 实现密切反映了 Python 逻辑。 

一个重要的区别是使用`int64`为级别总和。 由于节点值可能很大，并且单个级别上可能存在许多节点，因此使用常规`int`在某些系统上可能存在溢出风险。 将节点值转换为`int64`确保正确性。 

Go 没有像 Python 那样内置双端队列，因此队列是使用切片来实现的。 移除前面的元件是通过以下方式完成的：```go
queue = queue[1:]
```排序是使用`sort.Slice`使用自定义的降序比较器。

 ## 边缘情况

 ###`k`大于层数

 一个常见的错误是假设总是至少有`k`水平。 如果树包含的级别少于请求的级别，则访问`kth`排序后的元素会导致错误或不正确的结果。 

实现明确检查：```
if len(level_sums) < k:
    return -1
```这保证了级别不足时的正确行为。 

### 高度倾斜的树

 一棵树可能会退化为一个链表，其中每个节点只有一个子节点。 在这种情况下，高度变为`n`，并且在某些语言中，基于深度的递归方法可能会变得低效，甚至存在堆栈溢出的风险。 

BFS 实现自然地处理倾斜树，因为它使用队列迭代地处理节点。 

### 重复级别总和

 问题表明总和不需要不同。 有缺陷的实现可能会在排序之前错误地使用集合删除重复项。 

例如：```
Level sums = [10, 5, 10]
```第二大值应该仍然是`10`。 

该实现保留列表中的每个级别总和，确保正确计算重复项。 

### 非常大的水平总和

 由于节点值最多可达`10^6`并且一个关卡上可能有很多节点，总和可能会变得相当大。 

Go 解决方案使用`int64`明确避免溢出问题。 Python 整数会根据需要自动扩展，因此不需要特殊处理。
