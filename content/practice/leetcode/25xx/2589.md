[LeetCode 问题 2589](https://leetcode.com/problems/minimum-time-to-complete-all-tasks/)

 **难度：** 🔴难
 **主题：** 数组、二分搜索、堆栈、贪婪、排序

 ## 解决方案

 ## 问题理解

 该问题要求我们确定计算机必须打开以执行一组任务的最短时间，假设每个任务都有指定的时间窗口`[starti, endi]`并需要总持续时间`durationi`这不需要是连续的。 换句话说，计算机可以同时运行多个任务，我们可以有选择地选择在每个任务允许的时间窗口内何时打开它，以最小化总运行时间。 

输入`tasks`是一个二维数组，其中每个子数组`[starti, endi, durationi]`代表一个任务。 预期输出是一个整数，表示计算机必须运行才能满足所有任务的总秒数。 

这些约束表明最多可以有 2000 个任务，每个任务的时间范围最多可以达到 2000 个。这排除了尝试单独模拟每个任务的每一秒的简单方法，因为这可能太慢。 

重要的边缘情况包括：

 - 任务完全或部分重叠，需要仔细安排以避免不必要地打开计算机。 
- 持续时间等于其总范围的任务，这意味着计算机必须在该范围内每秒处于开启状态。 
- 相对于其持续时间而言范围非常小或非常大的任务。 

## 方法

 ### 蛮力

 蛮力方法会尝试在最大可能的时间窗口内模拟每一秒（从最小的`starti`到最大的`endi`）并每秒跟踪哪些任务仍未完成。 每秒钟，我们都可以决定打开计算机是否有助于完成任何剩余任务并更新其剩余持续时间。 虽然这种方法可以产生正确的答案，但它会非常慢，因为时间窗口可能大到 2000，并且每秒迭代超过 2000 个任务可能会导致 O(N * maxTime) 解决方案，这对于约束来说是不切实际的。 

### 最佳方法

 关键的见解是可以从最近的可能时间向后贪婪地安排任务。 通过按结束时间对任务进行排序，我们确保首先填充最新的可用槽位，从而避免不必要的早期激活。 我们维护一个布尔数组来跟踪计算机已经打开的秒数。 对于每个任务，我们计算已经覆盖了多少秒，如果任务仍然需要更多时间，我们会在其范围内最晚可能的可用时间贪婪地打开计算机，直到满足其持续时间要求。 这确保我们在满足所有任务的同时始终最大限度地减少计算机运行的秒数。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(N * 最大时间) | O(最大时间) | 模拟时间范围内的每一秒并检查所有任务 |
 | 最佳 | O(N * 最大持续时间) | O(最大时间) | 按结束时间排序并从最新可用时间贪婪地填充 |

 ## 算法演练

 1.初始化布尔数组`used`大小略大于最大结束时间，代表计算机每秒是否开机。 
2. 按任务的顺序对任务进行排序`endi`按升序排列。 
3. 迭代每个任务`[starti, endi, durationi]`。 
4. 计算任务范围内有多少秒已标记为已使用。 这给出了该任务已经涵盖的秒数。 
5. 如果任务仍需要额外时间才能达到其持续时间，请从以下位置开始贪婪地打开计算机：`endi`向后，将未使用的秒数标记为已使用，直到满足所需的持续时间。 
6. 继续执行下一个任务。 
7. 处理完所有任务后，将标记为已使用的总秒数相加并返回该值。 

**为什么有效：** 按结束时间对任务进行排序可以保证当我们安排额外的秒数时，不会与稍后结束的任务发生冲突。 从最新的可用时间开始填充可确保我们最大限度地减少重叠并避免不必要地过早打开计算机。 这种贪婪的策略保证了最小的总准点时间。 

## Python 解决方案```python
from typing import List

class Solution:
    def findMinimumTime(self, tasks: List[List[int]]) -> int:
        max_time = max(task[1] for task in tasks)
        used = [False] * (max_time + 2)
        
        # Sort tasks by end time
        tasks.sort(key=lambda x: x[1])
        
        for start, end, duration in tasks:
            covered = sum(used[start:end+1])
            need = duration - covered
            # Greedily fill from end backwards
            t = end
            while need > 0:
                if not used[t]:
                    used[t] = True
                    need -= 1
                t -= 1
        
        return sum(used)
```**解释：** 我们首先找到最大值`endi`来确定我们的规模`used`大批。 按结束时间对任务进行排序后，我们迭代每个任务并计算已经覆盖的秒数。 对于任何剩余的持续时间，我们将从最近的可用时间向后标记已使用的秒数。 最后总结一下`used`给出最短的接通时间。 

## 解决方案```go
func findMinimumTime(tasks [][]int) int {
    maxTime := 0
    for _, task := range tasks {
        if task[1] > maxTime {
            maxTime = task[1]
        }
    }

    used := make([]bool, maxTime+2)

    // Sort tasks by end time
    sort.Slice(tasks, func(i, j int) bool {
        return tasks[i][1] < tasks[j][1]
    })

    for _, task := range tasks {
        start, end, duration := task[0], task[1], task[2]
        covered := 0
        for t := start; t <= end; t++ {
            if used[t] {
                covered++
            }
        }
        need := duration - covered
        t := end
        for need > 0 {
            if !used[t] {
                used[t] = true
                need--
            }
            t--
        }
    }

    total := 0
    for _, u := range used {
        if u {
            total++
        }
    }
    return total
}
```**说明：** Go 版本镜像了 Python 实现。 主要区别在于切片初始化、循环语法和显式`sort.Slice`用于排序。 算法逻辑保持不变。 

## 工作示例

 ### 示例 1

 任务：`[[2,3,1],[4,5,1],[1,5,2]]`- 按末尾排序：`[[2,3,1],[4,5,1],[1,5,2]]`- 任务`[2,3,1]`: [2,3] 中没有使用秒，标记 3 → 使用 = {3}
 - 任务`[4,5,1]`: [4,5] 中没有使用秒数，标记 5 → 使用 = {3,5}
 - 任务`[1,5,2]`: 已经覆盖了秒 = 2 (3,5)，还需要 0 → 完成
 - 总使用秒数 = 2

 ### 示例 2

 任务：`[[1,3,2],[2,5,3],[5,6,2]]`- 按末尾排序：`[[1,3,2],[2,5,3],[5,6,2]]`- 任务`[1,3,2]`: [1,3] 中没有使用秒，标记 3 和 2 → 使用 = {2,3}
 - 任务`[2,5,3]`：已覆盖秒数 = 2 (2,3)，还需要 1 → 标记 5 → 已使用 = {2,3,5}
 - 任务`[5,6,2]`：已覆盖秒数 = 1 (5)，还需要 1 → 标记 6 → 已使用 = {2,3,5,6}
 - 总使用秒数 = 4

 ## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(N * D) | 排序需要 O(N log N)，迭代任务并可能检查 D = 每个任务的持续时间以标记已使用时间 |
 | 空间| O(T)|`used`大小等于最大结束时间 T | 的数组

 时间复杂度是合理的，因为`N`和`T`最多为 2000。空间在最大时间上也是线性的。
