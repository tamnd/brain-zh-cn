[LeetCode 问题 2595](https://leetcode.com/problems/number-of-even-and-odd-bits/)

 **难度：** 🟢简单
 **主题：** 位操作

 ## 解决方案

 ## 问题理解

 该问题要求我们分析正整数的二进制表示`n`并数数有多少个`1`位出现在偶数索引处以及有多少位出现在奇数索引处。 

位位置从索引处开始从**右到左**计数`0`。 这意味着最低有效位（最右边的位）位于索引处`0`，下一位位于索引处`1`， 等等。 

我们只关心其值为`1`。 如果有一点是`0`，它对任一计数都没有贡献。 

例如，如果`n = 50`，其二进制表示为`110010`。 

从右到左阅读：

 | 索引 | 位|
 | ---| ---|
 | 0 | 0 |
 | 1 | 1 |
 | 2 | 0 |
 | 3 | 0 |
 | 4 | 1 |
 | 5 | 1 |

 这`1`位出现在索引处`1`,`4`， 和`5`。 

- 指数`4`是偶数，所以`even = 1`- 指数`1`和`5`是奇数，所以`odd = 2`结果是`[1, 2]`。 

输入由单个正整数组成`n`， 在哪里：```
1 <= n <= 1000
```这个约束告诉我们这个数字非常小。 自从`1000`二进制只有大约 10 位，即使是简单的解决方案也足够快。 然而，这个问题属于**位操作**类别，因此预期的解决方案是直接有效地处理位。 

一个重要的保证是`n`总是积极的，这意味着我们永远不需要处理`0`或负数。 这简化了实现，因为我们可以安全地停止一次`n`变成`0`位处理期间。 

一些边缘情况值得尽早识别。 仅具有一位设置位的数字，例如`n = 1`或者`n = 2`，测试索引逻辑是否正确。 所有相关位都属于同一奇偶校验类别的数字（例如 2 的幂）可能会因一个错误而暴露。 具有交替位模式的输入也可以揭示索引错误。 

## 方法

 ### 蛮力方法

 暴力解决方案首先使用类似的方法将整数转换为二进制字符串`bin(n)`，反转字符串，使索引与问题语句匹配，然后迭代每个字符。 

对于每个位位置，我们将检查：

 - 该位是否等于`'1'`？ 
- Is its index even or odd?

 根据索引的奇偶校验，我们增加偶数计数或奇数计数。 

这种方法是正确的，因为它明确地检查每一位并直接遵循问题定义。 然而，它通过将数字转换为字符串并需要额外的内存来表示该表示，从而引入了不必要的开销。 

尽管约束足够小，可以完美地工作，但它并不是最自然的位操作解决方案。 

### 最佳方法

 关键的观察是可以使用按位运算直接处理二进制数字。 

任何时刻：

 -`n & 1`告诉我们最低有效位是否是`1`-`n >>= 1`通过右移所有位来删除最低有效位

 我们可以在保持当前索引的同时逐一迭代这些位。 

对于每一位：

 - 如果最低有效位是`1`，根据当前索引奇偶校验递增偶数或奇数计数器
 - 转变`n`有权处理下一位
 - 增加索引

 这完全避免了字符串转换并使用恒定的额外空间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(log n) | O(log n) | 将数字转换为二进制字符串并扫描它 |
 | 最佳| O(log n) | O(1) | O(1) | 使用按位运算直接处理位 |

 ## 算法演练

 1.初始化两个计数器，`even_count`和`odd_count`，两者都设置为`0`。 这些将存储的数量`1`在偶数和奇数位置找到的位。 
2. 初始化变量`bit_index = 0`。 这会跟踪正在检查的位的当前位置。 
3.同时`n > 0`，重复检查最低有效位。 我们使用`n & 1`因为它可以有效地提取最右边的位。 
4.如果`(n & 1) == 1`，判断是否`bit_index`是偶数还是奇数：

 - 如果`bit_index % 2 == 0`, 增量`even_count`- 否则，增加`odd_count`5. 使用将数字右移`n >>= 1`。 这会删除当前的最低有效位并将下一位移动到位。 
6. 增量`bit_index`因为我们现在正在移动到下一个二进制位置。 
7. 继续直到`n`变成`0`，表示所有位均已处理。 
8. 返回`[even_count, odd_count]`。 

### 为什么它有效

 该算法之所以有效，是因为每次迭代只处理一个二进制数字，从最低有效位开始，对应于索引`0`根据问题的要求。 移位操作确保每个位都被访问一次，索引变量保证我们对每个位进行分类`1`位进入正确的奇偶校验组。 由于每个相关位都经过正确检查和计数，因此最终结果必须准确。 

## Python 解决方案```python
from typing import List

class Solution:
    def evenOddBit(self, n: int) -> List[int]:
        even_count = 0
        odd_count = 0
        bit_index = 0

        while n > 0:
            if n & 1:
                if bit_index % 2 == 0:
                    even_count += 1
                else:
                    odd_count += 1

            n >>= 1
            bit_index += 1

        return [even_count, odd_count]
```该实现严格遵循上述算法。 

我们首先初始化偶数和奇数索引的计数器`1`位。 这`bit_index`当我们在二进制表示中移动时，变量会跟踪当前位置。 

里面的`while`环形，`n & 1`检查是否设置了最低有效位。 如果是，我们使用模运算符确定当前索引是偶数还是奇数，并更新适当的计数器。 

处理完当前位后，`n >>= 1`将所有位向右移动，有效地丢弃我们刚刚处理的位。 同时，`bit_index`递增，因此下一次迭代对应于下一个二进制位置。 

一次`n`变成`0`，所有位都已被处理，我们将结果作为两个元素列表返回。 

## 解决方案```go
func evenOddBit(n int) []int {
	evenCount := 0
	oddCount := 0
	bitIndex := 0

	for n > 0 {
		if n&1 == 1 {
			if bitIndex%2 == 0 {
				evenCount++
			} else {
				oddCount++
			}
		}

		n >>= 1
		bitIndex++
	}

	return []int{evenCount, oddCount}
}
```Go 实现非常接近地反映了 Python 解决方案。 由于 Go 没有 Python 风格的列表，我们使用以下命令返回一个切片`[]int{evenCount, oddCount}`。 

在 Go 中，按位运算自然适用于整数，因此`n&1`和`n >>= 1`行为完全符合预期。 整数溢出不是一个问题，因为约束`n <= 1000`非常小。 

与Python不同的是，这里不存在影响实现的可变和不可变整数的区别，并且不用担心`nil`与空集合相比，因为我们总是返回固定大小的切片。

 ## 边缘情况

 One important edge case is the **smallest valid input**,`n = 1`。 Since the binary representation is simply`1`，索引处只有一个设置位`0`，这是偶数。 有缺陷的实现可能会错误地从以下位置开始索引`1`，产生错误的结果。 我们的实施开始于`bit_index = 0`，保证正确性。 

另一个重要的情况是**二的幂**，例如`n = 2`或者`n = 4`。 这些数字恰好包含一组位，这使得它们成为索引准确性的绝佳测试。 如果移位或索引逻辑不正确，这些情况会立即失败。 因为我们的算法是递增的`bit_index`每次移位后，位置与实际位保持同步。 

第三种边缘情况是具有**交替位模式**的数字，例如`n = 10`（`1010`二进制）。 这些值有助于验证偶数和奇数索引是否已正确分类。 一个常见的错误是反转索引方向或将最左边的位视为索引`0`。 因为我们总是使用从最低有效位开始处理`n & 1`，我们的实现自然遵循问题的从右到左索引规则。 

最后，具有**许多连续设置位**的值，例如`n = 15`（`1111`），确保算法正确计算两个奇偶校验组中的多个位。 由于每个位都被独立且恰好处理一次，因此不会跳过或重复计数。
