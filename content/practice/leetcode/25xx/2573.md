[LeetCode 问题 2573](https://leetcode.com/problems/find-the-string-with-lcp/)

 **难度：** 🔴难
 **主题：** 数组、字符串、动态规划、贪心、并查、矩阵

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个`n x n`矩阵称为`lcp`， 在哪里：

-`lcp[i][j]`表示以下之间的最长公共前缀的长度：

 - 从索引开始的后缀`i`- 从索引开始的后缀`j`如果未知字符串是`word`，那么：

 - 后缀`i`是`word[i:]`- 后缀`j`是`word[j:]`任务是重建字典顺序最小的有效字符串`word`与给定的完全匹配`lcp`矩阵。 如果不存在这样的字符串，我们必须返回一个空字符串。 

例如，假设：```
word = "abab"
```然后：```
word[0:] = "abab"
word[2:] = "ab"
```他们的共同前缀是`"ab"`，其长度为`2`， 所以：```
lcp[0][2] = 2
```该矩阵完整地描述了所有后缀如何相互关联。 

约束条件很重要：

 -`n <= 1000`- 矩阵有`n²`条目

 这立即告诉我们：

 - 安`O(n²)`解决方案是可以接受的
 - 任何接近的东西`O(n³)`可能会超时

 另一个重要的观察结果是答案仅使用小写英文字母，这意味着我们最多有`26`可用的不同字符组。 如果构建所需的平等关系需要超过`26`不同的人物，答案是不可能的。 

几种边缘情况很容易破坏简单的实现：

 - 对角线值必须满足：```
lcp[i][i] = n - i
```因为后缀总是与自身完全匹配。 
- 矩阵必须是对称的：```
lcp[i][j] = lcp[j][i]
```- 如果`lcp[i][j] > 0`， 然后：```
word[i] == word[j]
```- 如果`lcp[i][j] = k > 0`， 然后：```
lcp[i+1][j+1] = k - 1
```除非指数超出范围。 

问题本质上是要求我们从成对的后缀-前缀关系重建字符串，同时确保所有矩阵条目保持一致。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试生成所有可能的长度字符串`n`使用小写字母，计算它们`lcp`矩阵，并将它们与输入矩阵进行比较。 

要计算一个候选字符串的矩阵：

 - 每对`(i, j)`- 逐个字符比较后缀
 - 存储最长公共前缀长度

 这种方法显然是正确的，因为它检查每个可能的字符串。 如果存在有效的字符串，暴力破解最终会找到它。 

然而，这是完全不可行的。 

即使我们只限制两个字母，也已经有了：```
2^1000
```最坏情况下可能出现的字符串。 

使用全部`26`小写字母会使搜索量变得非常大。 

### 关键见解

 重要的观察是：```
lcp[i][j] > 0
```立即意味着：```
word[i] == word[j]
```因为后缀至少共享一个匹配字符。 

这将问题转化为分组问题：

 - 所有必须包含相同字符的位置都属于同一等价类。 
- 我们可以使用 Union-Find 建立这些组。 

将同等位置分组后：

 - 从左到右贪婪地分配字符
 - 使用`'a'`， 然后`'b'`， 然后`'c'`等
 - 这保证了字典顺序上最小的结构

 最后，我们必须验证构造的字符串是否准确再现`lcp`矩阵。 

验证步骤至关重要，因为仅靠等式约束是不够的。 格式错误的矩阵仍可能产生一致的相等组，但违反了更深层次的后缀关系。

 | ---| ---| ---| ---|

 ## 算法演练

 ### 第 1 步：验证基本对角线约束

 对于每个索引`i`， 核实：```
lcp[i][i] == n - i
```后缀始终与自身完全匹配。 

如果任何对角线值不正确，则返回`""`。 

### 步骤 2：使用 Union-Find 建立平等组

 如果：```
lcp[i][j] > 0
```那么两个后缀的第一个字符必须匹配：```
word[i] == word[j]
```我们联合指数`i`和`j`。 

Union-Find 在这里是理想的选择，因为：

 - 它有效地合并等价类
 - 它支持接近恒定时间的查询
 - 它自然地模拟了平等关系

 处理完所有矩阵条目后，每个连接的分量表示必须共享相同字符的位置。 

### 第 3 步：贪婪地分配角色

 我们现在构造按字典顺序最小的有效字符串。 

从左到右遍历索引：

 - 如果组件尚未接收到字符：

 - 分配下一个未使用的字符
 - 在同一组件中的所有位置重复使用该字符

 这种贪婪的分配之所以有效，是因为较早的位置主导了字典顺序。 

如果超过`26`需要不同的组件，返回`""`。 

### 步骤 4：重新计算 LCP 矩阵

 现在我们验证候选字符串。 

定义：```
dp[i][j]
```作为从以下位置开始的后缀之间的最长公共前缀长度`i`和`j`。 

我们从下往上计算：

 - 如果`word[i] != word[j]`

```
dp[i][j] = 0
```- 否则：```
dp[i][j] = 1 + dp[i+1][j+1]
```这种循环之所以有效，是因为匹配的前缀向前扩展了一步。 

我们从右下角到左上角处理索引，以便：```
dp[i+1][j+1]
```是已知的。 

### 步骤 5：与输入矩阵比较

 如果任何计算值与给定矩阵不同：```
dp[i][j] != lcp[i][j]
```矩阵不一致，所以返回`""`。 

否则，返回构造的字符串。 

### 为什么它有效

 该算法之所以有效，是因为`lcp`矩阵施加了两种约束：

 1、角色的平等约束
 2.后缀匹配的递归一致性约束

 Union-Find 正确地捕获了所有强制性平等。 贪婪字符分配保证了字典顺序上最小的有效字符串。 最终的动态规划验证确保了每一个`lcp`值完全匹配，消除了因矩阵不一致而导致的无效构造。 

## Python 解决方案```python
from typing import List

class Solution:
    def findTheString(self, lcp: List[List[int]]) -> str:
        n = len(lcp)

        parent = list(range(n))

        def find(x: int) -> int:
            while parent[x] != x:
                parent[x] = parent[parent[x]]
                x = parent[x]
            return x

        def union(a: int, b: int) -> None:
            pa = find(a)
            pb = find(b)

            if pa != pb:
                parent[pb] = pa

        # Step 1: validate diagonals
        for i in range(n):
            if lcp[i][i] != n - i:
                return ""

        # Step 2: union positions that must match
        for i in range(n):
            for j in range(i + 1, n):
                if lcp[i][j] > 0:
                    union(i, j)

        # Step 3: build lexicographically smallest string
        result = [''] * n
        group_to_char = {}

        next_char = ord('a')

        for i in range(n):
            root = find(i)

            if root not in group_to_char:
                if next_char > ord('z'):
                    return ""

                group_to_char[root] = chr(next_char)
                next_char += 1

            result[i] = group_to_char[root]

        word = ''.join(result)

        # Step 4: recompute lcp
        dp = [[0] * (n + 1) for _ in range(n + 1)]

        for i in range(n - 1, -1, -1):
            for j in range(n - 1, -1, -1):
                if word[i] == word[j]:
                    dp[i][j] = 1 + dp[i + 1][j + 1]

        # Step 5: verify
        for i in range(n):
            for j in range(n):
                if dp[i][j] != lcp[i][j]:
                    return ""

        return word
```该实现首先初始化一个并查结构，其中每个位置最初属于其自己的组。 

对角线验证立即拒绝不可能的矩阵。 这可以尽早捕获无效的自匹配长度。 

接下来，每一对都带有积极的`lcp`被合并到同一个组件中，因为它们的第一个字符必须匹配。 

然后贪婪地构建字符串。 每个新遇到的组件都会接收最小的未使用字符。 由于我们从左到右处理索引，这会产生按字典顺序排列的最小有效答案。 

构建完成后，算法重新计算整个`lcp`使用自下而上动态规划的矩阵。 复发：```python
dp[i][j] = 1 + dp[i+1][j+1]
```自然地模型匹配后缀前缀。 

最后，将计算出的矩阵与输入进行比较。 任何不匹配都证明矩阵不一致。 

## 解决方案```go
package main

func findTheString(lcp [][]int) string {
	n := len(lcp)

	parent := make([]int, n)
	for i := 0; i < n; i++ {
		parent[i] = i
	}

	var find func(int) int
	find = func(x int) int {
		for parent[x] != x {
			parent[x] = parent[parent[x]]
			x = parent[x]
		}
		return x
	}

	union := func(a, b int) {
		pa := find(a)
		pb := find(b)

		if pa != pb {
			parent[pb] = pa
		}
	}

	// Step 1: validate diagonals
	for i := 0; i < n; i++ {
		if lcp[i][i] != n-i {
			return ""
		}
	}

	// Step 2: union matching positions
	for i := 0; i < n; i++ {
		for j := i + 1; j < n; j++ {
			if lcp[i][j] > 0 {
				union(i, j)
			}
		}
	}

	// Step 3: construct smallest string
	result := make([]byte, n)

	groupToChar := make(map[int]byte)

	nextChar := byte('a')

	for i := 0; i < n; i++ {
		root := find(i)

		if _, exists := groupToChar[root]; !exists {
			if nextChar > 'z' {
				return ""
			}

			groupToChar[root] = nextChar
			nextChar++
		}

		result[i] = groupToChar[root]
	}

	word := string(result)

	// Step 4: recompute lcp
	dp := make([][]int, n+1)
	for i := range dp {
		dp[i] = make([]int, n+1)
	}

	for i := n - 1; i >= 0; i-- {
		for j := n - 1; j >= 0; j-- {
			if word[i] == word[j] {
				dp[i][j] = 1 + dp[i+1][j+1]
			}
		}
	}

	// Step 5: verify
	for i := 0; i < n; i++ {
		for j := 0; j < n; j++ {
			if dp[i][j] != lcp[i][j] {
				return ""
			}
		}
	}

	return word
}
```Go 的实现与 Python 版本非常相似。 主要区别在于显式切片管理和字节处理。 

构造的字符串使用`[]byte`切片，因为字符是 ASCII 小写字母。 这比重复连接字符串更有效。 

动态规划矩阵被分配为二维切片。 由于 Go 自动将整数初始化为零，因此不需要额外的设置。 

不存在整数溢出问题，因为所有值都受以下限制`n <= 1000`。

 ## 边缘情况

 ### 无效的对角线值

 错误的一个常见来源是忘记：```
lcp[i][i] = n - i
```必须始终持有。 

例如：```
lcp[3][3] = 3
```当后缀中仅保留一个字符时，这是不可能的。 

该实现在进行任何进一步处理之前立即验证所有对角线条目。 

### 导致矛盾的平等约束

 成对的相等关系可能看起来有效，而更深层次的后缀关系仍然不一致。 

例如：```
lcp[i][j] = 1
```表示第一个字符匹配，但接下来的字符必须不同。 如果后面的矩阵条目意味着它们也匹配，则该矩阵变得矛盾。 

最终的 DP 验证步骤捕获了所有此类不一致之处。 

### 超过 26 个不同的组件

 该问题将字符限制为小写英文字母。 

如果并查结构产生超过`26`断开的组件，不存在有效的字符串。 

贪心赋值步骤显式检查此条件并返回`""`必要时。
