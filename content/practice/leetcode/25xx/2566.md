[LeetCode 问题 2566](https://leetcode.com/problems/maximum-difference-by-remapping-a-digit/)

 **难度：** 🟢简单
 **主题：** 数学、贪心

 ## 解决方案

 ## 问题理解

 该问题要求我们最大化从给定整数创建的两个数字之间的差异`num`通过特定的重新映射操作。 

我们可以只选择一位数字`d1`从`0`通过`9`，并将该数字的**所有出现**替换为`num`与另一个数字`d2`，也可以是以下任意数字`0`通过`9`。 重要的是，`d1`和`d2`可能是相同的数字，这意味着该数字不必更改。 

任务是计算：```
maximum possible remapped value - minimum possible remapped value
```用于获得最大值的重映射和用于获得最小值的重映射是完全独立的。 我们可以为每个数字选择不同的源数字和目标数字。 

一个关键细节是结果数字可能包含**前导零**。 由于结果被解释为整数，因此前导零将被自动忽略。 例如：```
"0890" → 890
```输入是单个整数`num`， 在哪里：```
1 <= num <= 10^8
```这告诉我们这个数字最多包含 9 位数字，这是非常小的。 即使是蛮力方法也是可行的。 然而，该问题被归类为简单的贪婪问题，这表明存在直接观察，使我们能够有效地计算答案，而无需检查每种可能性。 

一些重要的边缘情况立即脱颖而出：

 - 数字可能已经包含`9`s 无处不在，这意味着最大值无法增加。 
- 一个数字可能只包含一个不同的数字，这意味着重新映射会影响每个位置。 
- 将前导数字替换为`0`可以显着降低该值，因为允许使用前导零。 
- 包含的数字`0`最小化时可能会有不同的行为。 
- 个位数需要小心处理，因为重新映射可以将它们变成`0`。 

例如：```
num = 9
```最大限度：```
9 → 9
```最低限度：```
9 → 0
```不同之处：```
9 - 0 = 9
```## 方法

 ### 蛮力方法

 The most direct way to solve this problem is to try every possible remapping operation.

 由于有 10 个可能的源数字 (`0`到`9`) 和 10 个可能的目标数字 (`0`到`9`），我们可以测试每一对`(d1, d2)`。 

对于每对：

 1. 转换`num`成字符串。 
2. 替换每个出现的数字`d1`带数字`d2`。 
3. 将结果转换回整数。 
4. 跟踪遇到的最小值和最大值。 

最后返回：```
max_value - min_value
```这种方法是正确的，因为它明确地评估每个有效的重新映射，因此不会错过最佳答案。 

然而，它执行了不必要的工作。 尽管限制很小，但我们正在检查所有 100 位数字映射，而实际上只有少量有意义的重新映射很重要。 

### 最佳贪婪解决方案的关键见解

 为了最大化数字，我们希望使最高有效数字尽可能大。 

最好的策略是：

 - 找到**第一个不是的数字`9`**
 - 将该数字的 **所有出现** 替换为`9`为什么这有效？ 

左边的数字比右边的数字对数字的贡献更大。 因此，尽早增加一位数的机会带来最大的收益。 替换较晚的数字而忽略较早的可改进数字总是次优的。 

为了最大限度地减少数量，我们希望使数量尽可能小。 

由于允许使用前导零，因此最佳策略变为：

 - 将**所有出现的第一个数字**替换为`0`为什么？ 

第一个数字是最重要的。 把它变成`0`产生尽可能最大的减少。 由于允许使用前导零，因此没有限制阻止这种情况。 

例如：```
11891
```最大限度：```
1 → 9
99899
```最低限度：```
1 → 0
00890 → 890
```不同之处：```
99899 - 890 = 99009
```| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(100 × d) = O(d) | O(d) | 尝试每个数字重新映射对 |
 | 最佳| O(d) | O(d) | 贪心构造最大值和最小值 |

 这里，`d`是数字的个数`num`。 

## 算法演练

 1. 转换`num`到一个字符串中，以便可以轻松地操作各个数字。 
2. 要计算**最大值**，请从左到右扫描数字并找到第一个不是的数字`'9'`。 

该数字代表最早增加数量的机会。 将所有出现的该数字替换为`'9'`产生最大可能的增长。 
3. 如果每个数字都已经是`'9'`，最大值保持不变。 
4. 要计算**最小值**，请取数字的第一位数字。 

由于允许使用前导零，因此将该数字的每次出现替换为`'0'`产生尽可能小的数字。 
5. 将两个重新映射的字符串转换回整数。 
6、退货：```
maximum - minimum
```### 为什么它有效

 该算法依赖于数字的位置意义。 

对于最大值，更改较高有效数字始终优先于更改较低有效数字。 因此，可以改进的第一个数字应始终升级为`9`。 

对于最小值，减少最左边的数字会产生最大的减少，因为它贡献了最大的位值。 由于允许使用前导零，因此将第一位数字替换为`0`总是最优的。 

因为这两种选择在最重要的位置都是局部最优的，所以它们也是全局最优的。 

## Python 解决方案```python
class Solution:
    def minMaxDifference(self, num: int) -> int:
        num_str = str(num)

        # Compute maximum value
        max_str = num_str
        digit_to_replace = None

        for digit in num_str:
            if digit != '9':
                digit_to_replace = digit
                break

        if digit_to_replace is not None:
            max_str = num_str.replace(digit_to_replace, '9')

        # Compute minimum value
        min_str = num_str.replace(num_str[0], '0')

        return int(max_str) - int(min_str)
```实现首先将整数转换为字符串，因为使用字符串操作进行数字替换更容易。 

为了计算最大值，代码从左到右扫描数字，寻找第一个不是的数字`'9'`。 一旦找到，该数字的所有出现都将被替换为`'9'`。 如果不存在这样的数字，则该数字已经代表最大可能的排列。 

对于最小值，实现只需将出现的第一个数字替换为`'0'`。 这是可行的，因为最左边的数字对总数的贡献最大，并且允许使用前导零。 

最后，两个转换后的字符串都被转换回整数并返回它们的差值。 

## 解决方案```go
import "strconv"

func minMaxDifference(num int) int {
	numStr := strconv.Itoa(num)

	// Compute maximum value
	maxStr := numStr
	digitToReplace := byte(0)

	for i := 0; i < len(numStr); i++ {
		if numStr[i] != '9' {
			digitToReplace = numStr[i]
			break
		}
	}

	if digitToReplace != 0 {
		maxBytes := []byte(numStr)

		for i := 0; i < len(maxBytes); i++ {
			if maxBytes[i] == digitToReplace {
				maxBytes[i] = '9'
			}
		}

		maxStr = string(maxBytes)
	}

	// Compute minimum value
	firstDigit := numStr[0]
	minBytes := []byte(numStr)

	for i := 0; i < len(minBytes); i++ {
		if minBytes[i] == firstDigit {
			minBytes[i] = '0'
		}
	}

	maxVal, _ := strconv.Atoi(maxStr)
	minVal, _ := strconv.Atoi(string(minBytes))

	return maxVal - minVal
}
```Go 解决方案遵循与 Python 实现相同的贪婪逻辑。 由于 Go 字符串是不可变的，因此我们在执行就地字符替换之前将它们转换为字节切片。 

哨兵值`digitToReplace := byte(0)`用于指示是否非`9`找到了用于最大化数字的数字。 

不存在整数溢出问题，因为：```go
num <= 10^8
```所有派生值都保持在 Go 的标准整数范围内。

 ## 边缘情况

 当数字已经完全由以下组成时，就会出现一种重要的边缘情况`9`s。 

例如：```
9999
```幼稚的实现可能无法找到最大化的数字并意外地产生无效的替换。 该实现通过检查是否有非`9`应用替换之前数字已存在。 如果没有找到，则保留原始数字作为最大值。 

另一个棘手的情况涉及最小化后的前导零。 

例如：```
1001
```更换主导`1`和`0`给出：```
0000
```某些实现错误地将其视为无效转换或保留前导数字。 由于该问题明确允许前导零，因此将字符串正确转换回整数会产生`0`。 

第三个重要的边缘情况是所有数字都相同。 

例如：```
7777
```两个重映射操作都会影响每个位置。 最大值变为：```
9999
```最小值变为：```
0000
```该实现可以正确处理此问题，因为字符串替换会全局更新所选数字的每次出现。 

最后，个位数很容易引入相差一的错误。 

例如：```
5
```最大值变为：```
9
```最小值变为：```
0
```由于无论长度如何，该算法都会统一处理第一个数字，因此不需要特殊情况处理。
