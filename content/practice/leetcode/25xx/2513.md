 # LeetCode 2513 - 最小化两个数组的最大值

 ## 问题理解

 问题给了我们两个空数组，`arr1`和`arr2`，并要求我们在几个约束下用正整数填充它们。 

第一个数组，`arr1`，必须准确包含`uniqueCnt1`不同的正整数，并且这些整数都不能被`divisor1`。 

第二个数组，`arr2`，必须准确包含`uniqueCnt2`不同的正整数，并且这些整数都不能被`divisor2`。 

此外，两个数组必须完全不相交。 为一个数组选择的数字不能出现在另一数组中。 

我们的目标是最小化两个阵列中使用的最大数量。 换句话说，如果任一数组中出现的最大值是`x`，我们想要尽可能最小的这样`x`。 

输入由四个整数组成：

 -`divisor1`，可分性限制`arr1`-`divisor2`，可分性限制`arr2`-`uniqueCnt1`，所需尺寸为`arr1`-`uniqueCnt2`，所需尺寸为`arr2`输出是一个整数，表示允许成功构造两个数组的最小可能最大值。 

约束条件极其重要：

 -`uniqueCnt1`和`uniqueCnt2`每个都可以靠近`10^9`- 它们的总和也可以接近`10^9`这些限制立即排除了任何显式构建数组的基于模拟的解决方案。 我们需要一种数学方法。 

一个重要的观察是我们实际上不需要知道数组的确切内容。 我们只需要知道是否某个最大值`x`提供足够的有效数字来同时满足两个数组。 

一些边缘情况很重要：

 -`divisor1`和`divisor2`可能共享因素
 - 一个除数可以整除另一个除数
 - 所需的数量可能非常大
 - 许多数字可能无法用于一个或两个阵列
 - 某些数字可能对两个数组均有效，而另一些数字则仅对一个数组有效

 不相交要求是问题中最棘手的部分，因为适用于两个数组的数字只能分配一次。 

## 方法

 ### 蛮力方法

 强力解决方案会尝试一一增加最大值。 

对于每个候选最大`x`，我们可以枚举所有数字`1`到`x`，对哪些数字可用进行分类`arr1`，可用于`arr2`，然后尝试分布它们，同时保持数组不相交。 

这是有效的，因为最终我们会找到最小的有效值`x`。 

然而，这种方法太慢了。 最大答案可能会变得非常大，可能超过数十亿。 迭代每个整数并显式构造集合在计算上是不可行的。 

即使天真地检查单个候选值也会花费`O(x)`，这对于给定的约束是不可能的。 

### 关键见解

 关键的观察是我们不需要显式构建数组。 

相反，对于候选最大值`x`，我们只需要计算：

 1.有多少个数字`1`到`x`有效期为`arr1`2. 共有多少个数字`1`到`x`有效期为`arr2`3. 至少一个数组有多少个数字有效

 这些计数可以使用整除性进行数学计算。 

例如：

 - 不能被整除的数字`divisor1`:`x - x // divisor1`- 不能被整除的数字`divisor2`:`x - x // divisor2`棘手的部分是计算至少一个数组可用的数字。 

仅当一个数字可以同时被两个除数整除时，该数字才无法使用。 这意味着它可以被以下整除：$$\text{lcm}(divisor1, divisor2)$$因此，至少一个数组可用的数字计数为：$$x - x // \text{lcm}(divisor1, divisor2)$$现在问题变成了决策问题：

 “我们可以使用最多的数字来满足两个数组吗？`x`？”

 该属性是单调的：

 - 如果`x`有效，那么每个更大的值也有效。 
- 如果`x`不起作用，那么每个较小的值也会失败。 

这种单调的行为使二分搜索成为完美的工具。

 ## 算法演练

 ### 步骤 1：计算最小公倍数

 我们计算：$$lcm = \frac{divisor1 \times divisor2}{gcd(divisor1, divisor2)}$$LCM 让我们可以同时计算可被两个除数整除的数字。 

### 步骤 2：对答案进行二分搜索

 我们寻找最小的最大值`x`。 

搜索范围为：

 - 左边界：`1`- 右边界：足够大的数，例如`10^18`我们使用较大的上限，因为约束允许非常大的答案。 

### 第 3 步：计算有效数字`arr1`对于候选人`mid`:$$count1 = mid - mid // divisor1$$这些数字来自`1`到`mid`不能被整除的`divisor1`。 

他们有资格获得`arr1`。 

### 步骤 4：计算有效数字`arr2`相似地：$$count2 = mid - mid // divisor2$$这些有资格获得`arr2`。 

### 步骤 5：计算总体可用的数量

 有些数字可能适用于两个阵列。 

唯一不可用的数字是那些同时被两个除数整除的数字。 

该计数是：$$mid // lcm$$因此，至少一个数组可用的数字计数为：$$total = mid - mid // lcm$$### 第 6 步：检查可行性

 候选人`mid`如果所有三个条件都满足，则有效：$$count1 \ge uniqueCnt1$$

$$count2 \ge uniqueCnt2$$

$$total \ge uniqueCnt1 + uniqueCnt2$$第三个条件保证我们可以在两个数组之间分配不同的数字而不会重叠。 

### 步骤 7：调整二分查找

 如果`mid`是可行的：

 - 将其存储为可能的答案
 - 搜索较小的值

 否则：

 - 搜索更大的值

 ### 步骤 8：返回最小有效值

 二分查找最终收敛到最小可行最大整数。 

### 为什么它有效

 正确性依赖于单调性。 

如果有最大值`x`为两个数组提供足够的可用数字，然后任何大于的值`x`也会起作用，因为它只会引入更多候选整数。 

计数公式正确确定有多少整数满足每个整除条件。 使用 LCM 的组合计数保证总体上存在足够的不同整数以保持数组不相交。 

因此，二分查找找到最小的可行最大值。 

## Python 解决方案```python
from math import gcd

class Solution:
    def minimizeSet(
        self,
        divisor1: int,
        divisor2: int,
        uniqueCnt1: int,
        uniqueCnt2: int
    ) -> int:

        lcm = divisor1 * divisor2 // gcd(divisor1, divisor2)

        left = 1
        right = 10**18

        while left < right:
            mid = (left + right) // 2

            count1 = mid - mid // divisor1
            count2 = mid - mid // divisor2
            total = mid - mid // lcm

            if (
                count1 >= uniqueCnt1 and
                count2 >= uniqueCnt2 and
                total >= uniqueCnt1 + uniqueCnt2
            ):
                right = mid
            else:
                left = mid + 1

        return left
```该实现首先使用最大公约数计算最小公倍数。 

二分搜索维护一个包含所有可能答案的搜索空间。 在每次迭代中，都会测试中点的可行性。 

变量`count1`和`count2`表示最多有多少个整数`mid`对每个数组单独有效。 变量`total`表示总共有多少个整数可用。 

可行性条件确保：

 -`arr1`可以填
 -`arr2`可以填
 - 数组可以保持不相交

 如果满足所有条件，我们会尝试较小的值，因为我们想要最小的可能的最大值。 否则，我们会增加搜索范围。 

循环终止时`left == right`，这是最小的可行值。 

## 解决方案```go
package main

func gcd(a int64, b int64) int64 {
	for b != 0 {
		a, b = b, a%b
	}
	return a
}

func minimizeSet(divisor1 int, divisor2 int, uniqueCnt1 int, uniqueCnt2 int) int {
	d1 := int64(divisor1)
	d2 := int64(divisor2)
	u1 := int64(uniqueCnt1)
	u2 := int64(uniqueCnt2)

	lcm := d1 * d2 / gcd(d1, d2)

	left := int64(1)
	right := int64(1e18)

	for left < right {
		mid := (left + right) / 2

		count1 := mid - mid/d1
		count2 := mid - mid/d2
		total := mid - mid/lcm

		if count1 >= u1 &&
			count2 >= u2 &&
			total >= u1+u2 {
			right = mid
		} else {
			left = mid + 1
		}
	}

	return int(left)
}
```Go 实现在结构上与 Python 版本相同，但它使用`int64`到处避免整数溢出。 

这一点尤其重要，因为二分搜索上限是`10^18`，这超出了标准 32 位整数的容量。 

习俗`gcd`函数使用欧几里德算法。

 ## 边缘情况

 ### 情况 1：两个除数相等

 如果`divisor1 == divisor2`，那么两个数组都会拒绝完全相同的数字。 

这会造成对可用整数的最大竞争，因为每个有效数字都符合两个数组的条件。 有缺陷的实现可能只验证单个计数，而忘记数组必须保持不相交。 

该实现通过以下条件避免了此问题：$$total \ge uniqueCnt1 + uniqueCnt2$$这保证了总体上有足够的不同可用数量。 

### 情况 2：一个除数是另一个除数的倍数

 例如：```
divisor1 = 2
divisor2 = 4
```每个数字都可以被`4`也可除以`2`。 

这很容易打破不正确的包含-排除逻辑。 

该实现通过使用最小公倍数安全地处理这个问题。 LCM 正确识别可同时被两个除数整除的数字。 

### 情况 3：计数极大

 计数可以接近`10^9`，并且答案本身可能会变得非常大。 

构造数组或迭代数字的简单实现会超时或耗尽内存。 

该解决方案避免了所有显式构造，仅使用算术计数公式，即使对于最大的输入也能有效扩展。
