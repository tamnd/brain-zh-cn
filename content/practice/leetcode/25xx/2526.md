[LeetCode 问题 2526](https://leetcode.com/problems/find-consecutive-integers-from-a-data-stream/)

 **难度：** 🟡 中等
 **主题：** 哈希表、设计、队列、计数、数据流

 ## 解决方案

 ## 问题理解

 该问题要求我们设计一个数据结构，连续处理整数流并确定是否是最新的`k`整数都等于特定的目标值。 

初始化数据结构时我们给定了两个参数：

 -`value`，它代表我们有兴趣跟踪的整数。 
-`k`，它代表连续出现的次数`value`我们需要看看。 

这`consec(num)`方法一次从流中接收一个整数。 将新整数插入流后，我们必须判断**last是否`k`整数**都等于`value`。 

换句话说，每次插入后的问题就变成：

 >“仅查看最近的`k`数字，它们都完全等于`value`？”

 如果流包含的内容少于`k`到目前为止的整数，答案一定是`false`，因为我们还没有足够的数量来满足要求。 

例如，假设`value = 4`和`k = 3`。 

如果流变成：`[4]`我们回来`false`，因为只有一个数字存在。 

如果流变成：`[4, 4]`我们仍然回来`false`，因为只有两个数字。 

如果流变成：`[4, 4, 4]`我们回来`true`，因为最后三个数字都是`4`。 

如果流变成：`[4, 4, 4, 3]`最后三个数字是`[4, 4, 3]`，所以我们返回`false`。 

这些约束揭示了有关问题规模的重要信息：

 -`k`可以大到`10^5`- 最多`10^5`打电话给`consec()`可能发生
 - 值本身可能非常大，最多可达`10^9`由于可能有`100,000`方法调用时，我们应该避免重复扫描最后一个`k`每次插入后的元素。 一个简单的解决方案，检查最后一个`k`每次整数可能会变得太慢。 

有几种边缘情况值得尽早识别：

 - 当少于`k`数字已被处理，答案必须始终是`false`。 
- 什么时候`k = 1`，每次出现`value`立即返回`true`，而任何其他数字都会返回`false`。 
- 流中的不匹配应立即中断连续记录，即使许多先前的数字匹配。 
- 大值`k`重复重新扫描的成本很高，因此需要一种有效的增量方法。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是显式维护数字流，并在每次插入后检查最后一个`k`元素。 

每次`consec(num)`称为：

 1. 追加`num`到溪流。 
2. 如果流大小小于`k`， 返回`false`。 
3. 否则，迭代最后一个`k`元素并检查每个数字是否相等`value`。 

这种做法是正确的，因为它直接验证了问题需求。 我们实际上是在检查是否是最新的`k`整数都与目标匹配。 

然而，问题是效率。 在最坏的情况下，每个`consec()`通话需要扫描`k`元素。 由于最多可以有`10^5`来电和`k`还可以`10^5`，总复杂度变得太大。 

### 最佳方法

 关键的观察是我们**不需要**需要记住整个流或重复检查最后一个流`k`元素。 

我们只关心是否是最新的`k`整数等于`value`。 

我们可以维护一个变量，而不是存储所有值：

 > 当前连续出现的次数`value`。 

每次有新号码到达时：

 - 如果数字等于`value`，增加连续计数。 
- 否则，将计数重置为`0`。 

然后我们简单地检查一下：```
count >= k
```为什么这有效？ 

因为如果我们至少见过`k`连续出现的`value`，那么最后一个`k`整数必须全部相等`value`。 

类似地，如果出现不同的数字，则连胜会立即中断，这意味着该条件不成立。 

这将问题从重复重新扫描流转变为恒定时间更新。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 每次调用 O(k) | O(n) | 存储流并最后扫描`k`值每个查询 |
 | 最佳 | 每次调用 O(1) | O(1) | O(1) | 仅跟踪连续匹配计数 |

 ## 算法演练

 ### 最优算法

 1.用目标初始化数据结构`value`，所需的条纹长度`k`，和一个计数器`count = 0`。 

计数器表示有多少个连续整数等于`value`最近出现过。 
2. 什么时候`consec(num)`被称为，比较`num`和`value`。 

如果`num == value`, 增量`count`因为连胜还在继续。 
3.如果`num != value`， 重置`count = 0`。 

此重置很重要，因为任何不匹配的数字都会完全破坏连续序列。 
4. After updating the counter, check whether`count >= k`。 

如果为真，则返回`true`因为最后`k`数字必须全部相等`value`。 
5.否则返回`false`。 

这意味着我们要么还没有足够的匹配值，要么连胜被中断。 

### 为什么它有效

 该算法保持不变式`count`始终等于连续出现的次数`value`结束于流中的当前位置。 

如果`count >= k`，那么根据定义最后一个`k`整数都等于`value`。 相反，如果`count < k`，不可能有`k`流末尾的连续匹配整数。 由于每次插入后都会保留此不变量，因此算法始终返回正确的结果。 

## Python 解决方案```python
class DataStream:

    def __init__(self, value: int, k: int):
        self.value = value
        self.k = k
        self.count = 0

    def consec(self, num: int) -> bool:
        if num == self.value:
            self.count += 1
        else:
            self.count = 0

        return self.count >= self.k

# Your DataStream object will be instantiated and called as such:
# obj = DataStream(value, k)
# param_1 = obj.consec(num)
```该实现存储三个实例变量：

 -`self.value`存储我们正在跟踪的目标号码。 
-`self.k`存储所需的连续长​​度。 
-`self.count`跟踪当前的条纹长度。 

里面`consec()`，我们将传入的数字与`self.value`。 

如果它们匹配，我们就增加条纹计数器。 如果不是，我们将其重置为零，因为连续序列已被中断。 

最后，我们返回条纹长度是否至少为`k`。 这直接实现了算法演练中的逻辑。 

请注意，我们从不存储完整的流。 我们只维护有效回答查询所需的最小状态。 

## 解决方案```go
type DataStream struct {
	value int
	k     int
	count int
}

func Constructor(value int, k int) DataStream {
	return DataStream{
		value: value,
		k:     k,
		count: 0,
	}
}

func (this *DataStream) Consec(num int) bool {
	if num == this.value {
		this.count++
	} else {
		this.count = 0
	}

	return this.count >= this.k
}

/**
 * Your DataStream object will be instantiated and called as such:
 * obj := Constructor(value, k);
 * param_1 := obj.Consec(num);
 */
```Go 实现遵循与 Python 解决方案完全相同的逻辑。 

Go 使用结构体字段代替实例属性：

 -`value`存储目标整数。 
-`k`存储所需的条纹长度。 
-`count`跟踪当前的连续条纹。 

这`Consec()`方法使用指针接收器，因此更新为`count`在通话之间坚持。 

整数溢出在这里不是一个问题，因为`count`永远不会超过方法调用的次数，最多是`10^5`，正好在 Go 的整数范围内。 

## 工作示例

 ### 示例 1

 输入：```
DataStream(4, 3)
consec(4)
consec(4)
consec(4)
consec(3)
```我们跟踪价值`4`并要求`k = 3`。 

| 步骤| 输入| 计数之前 | 行动| 之后计数 | 返回 |
 | ---| ---| ---| ---| ---| ---|
 | 1 | 4 | 0 | 匹配目标，增量 | 1 | 假 |
 | 2 | 4 | 1 | 匹配目标，增量| 2 | 假 |
 | 3 | 4 | 2 | 匹配目标，增量| 3 | 真实|
 | 4 | 3 | 3 | 不匹配，重置| 0 | 假 |

 详细推理：

 第一个之后`4`，我们只有一个匹配的数字，小于`k`。 

第二次之后`4`，条纹变为`2`，仍小于`3`。 

第三次之后`4`，条纹变为`3`，满足`count >= k`，所以我们返回`true`。 

什么时候`3`到达时，连胜完全中断并重置为`0`，所以答案就变成了`false`。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(1) | O(1) | 每个`consec()`调用执行恒定时间工作 |
 | 空间| O(1) | O(1) | 只存储了几个整型变量 |

 时间复杂度是恒定的，因为里面的每个操作`consec()`由一次比较、一次可能的增量或重置以及一次最终比较组成。 

空间复杂度也是恒定的，因为我们不存储流本身。 无论有多少数字到达，内存使用量都保持固定。

 ## 边缘情况

 ### 少于`k`流中的元素

 一个常见的错误是意外返回`true`太早了。 例如，如果`k = 5`并且只出现了三个匹配值，答案仍然是`false`。 

该实现自然地处理了这个问题，因为`count`必须至少达到`k`返回之前`true`。 直到那时，`count >= k`评估为`false`。 

###`k = 1`什么时候`k`等于`1`，每个匹配的数字都应该立即满足条件。 

例如：```
value = 10, k = 1
consec(10) → true
consec(5) → false
```该实现工作正常，因为匹配值到达后，`count`变成`1`，立即满足`count >= k`。 

### 失配打破了长时间的连胜

 当已经看到许多连续的匹配值，但突然出现不同的数字时，会发生另一种微妙的情况。 

例如：```
value = 4, k = 3
stream = [4, 4, 4, 9]
```前三个值之后，结果为`true`。 然而，有一次`9`到达后，最后三个值不再是全部`4`，所以答案必须变成`false`。 

该实现通过重置正确处理了这个问题`count`到`0`每当出现不匹配时，立即使连胜无效。
