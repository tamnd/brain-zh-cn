[LeetCode 问题 2545](https://leetcode.com/problems/sort-the-students-by-their-kth-score/)

 **难度：** 🟡 中等
 **主题：** 数组、排序、矩阵

 ## 解决方案

 ## 问题理解

 在这个问题中，我们给出一个矩阵，名为`score`有尺寸`m x n`。 每行代表一个学生，每列代表一次考试。 价值`score[i][j]`是获得的分数`i`th 学生在`j`第次考试。 

任务是根据特定列中的值对矩阵的行进行排序`k`。 排序必须按降序进行，即考试成绩最高的学生`k`应首先出现，该次考试中得分最低的学生应最后出现。 

重要的细节是我们不对行内的各个值进行排序。 相反，我们根据索引处的值重新排列整个行`k`在每一行内。 

例如，如果`k = 2`，然后我们比较`score[i][2]`为每个学生并根据这些值对行进行排序。 

限制相对较小：

 - 学生人数`m`最多可以为 250。 
- 考试次数`n`最多也可以是 250。 
- 矩阵内的所有值都是不同的。 

这些限制立即表明标准排序算法已经足够快了。 甚至一个`O(m log m)`排序解决方案对于`m = 250`。 

保证所有整数都是不同的很重要，因为这意味着在比较时没有联系`k`th 分数。 每个学生在所选考试中都会有一个独特的排名。 

有几种边缘情况值得考虑：

 - 只有一名学生的矩阵。 排序应保持矩阵不变。 
- 只有一次考试的矩阵。 这样，排序就相当于按单个值对行进行排序。 
- 选定的列`k`可能是第一列或最后一列。 
- 行可能已经按降序排序。 
- 行可能按升序排序，需要完全颠倒。 

幼稚的实现可能会意外地对每行中的值进行排序，而不是对行本身进行排序。 另一个常见错误是按升序而不是降序排序。 

## 方法

 ### 蛮力方法

 一种直接的方法是手动执行排序算法，例如对矩阵的行进行冒泡排序。 

在这种方法中，我们使用相邻行重复比较它们`k`th 分数。 如果当前行有较小的`k`th 分数比下一行高，我们交换两行。 重复此过程最终会将行按降序排列。 

这种方法是正确的，因为基于比较的排序保证了行最终将根据所需的列进行排序。 然而，冒泡排序执行许多不必要的比较和交换。 

由于冒泡排序需要`O(m^2)`在最坏的情况下进行比较，它的效率低于使用语言内置的优化排序实现。 

### 最佳方法

 关键的观察是我们只需要根据一个特定的列值对行进行排序。 

现代编程语言已经提供了高度优化的排序功能。 我们可以直接使用索引处的值对行进行排序`k`作为排序键。 

在 Python 中，可以使用以下命令完成此操作：```
sorted(score, key=lambda row: row[k], reverse=True)
```在Go中，我们可以使用`sort.Slice`具有自定义比较功能。 

这种方法比实现手动排序算法更简单、更高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(平方米) | O(1) | O(1) | 对行使用手动冒泡排序 |
 | 最佳| O(m log m) | O(1) 或 O(m) 取决于实现 | 使用内置优化排序 |

 ## 算法演练

 1.读取输入矩阵`score`和列索引`k`。 
2. 将每一行视为代表一名学生的单个单元。 我们从不修改行内的值。 
3. 使用索引处的值比较行`k`。 对于两行`a`和`b`， 比较`a[k]`和`b[k]`。 
4. 根据这些对所有行进行降序排序`k`th 值。 需要降序排列，因为分数较高的学生应该较早出现。 
5. 排序完成后返回重新排序后的矩阵。 

### 为什么它有效

 该算法之所以有效，是因为每一行都使用列指定的分数进行比较`k`。 基于比较的排序算法保证排序后，对于每个相邻的行对`i`和`i + 1`，我们有：```
score[i][k] >= score[i + 1][k]
```由于所有行都满足此排序条件，因此整个矩阵正确排序`k`考试成绩从最高到最低。 

## Python 解决方案```python
from typing import List

class Solution:
    def sortTheStudents(self, score: List[List[int]], k: int) -> List[List[int]]:
        return sorted(score, key=lambda row: row[k], reverse=True)
```由于Python提供了强大的内置排序功能，因此实现非常简洁。 

这`sorted()`函数创建一个新的排序列表。 这`key`参数指定如何比较行。 对于每一行，我们提取`row[k]`，代表学生在目标考试中的分数。 

论点`reverse=True`确保降序排列。 

由于行本身是列表，因此排序会重新排列整个行而不是单个值。 

该算法直接遵循前面描述的方法：

 - 每行都被视为学生记录。 
- 这`k`th 值成为比较键。 
- 行根据该键重新排序。 

## 解决方案```go
package main

import "sort"

func sortTheStudents(score [][]int, k int) [][]int {
	sort.Slice(score, func(i, j int) bool {
		return score[i][k] > score[j][k]
	})

	return score
}
```在 Go 中，排序是使用以下命令就地执行的`sort.Slice`。 

比较函数接收索引`i`和`j`。 我们比较`k`两行的第 分数：```go
score[i][k] > score[j][k]
```使用`>`而不是`<`确保降序排列。 

与Python不同`sorted()`，它返回一个新列表，`sort.Slice`直接修改原始切片。 

Go 切片是对底层数组的引用，因此行本身会重新排列，而无需单独复制每个元素。

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(m log m) | 排序`m`行需要基于比较的排序 |
 | 空间| O(1) 到 O(m) | 取决于语言排序实现 |

 主要操作是对行进行排序。 由于有`m`同学们，排序需要`O(m log m)`比较。 

每次比较仅检查索引处的单个整数`k`，所以比较是常数时间。 

空间复杂度取决于语言的实现。 Go 的就地排序只使用很少的额外内存，而 Python 的`sorted()`创建一个新的列表结构。

 ## 边缘情况

 一个重要的边缘情况是矩阵仅包含一名学生。 在这种情况下，没有什么可以排序，因为只有一行存在。 一些不正确的实现可能仍然会尝试不必要的交换或比较。 所提供的解决方案自然地处理了这个问题，因为对单元素列表进行排序只是返回相同的列表不变。 

另一个重要的边缘情况是只有一个考试栏时。 在这种情况下，`k`必须是`0`，并且排序完全基于每行中的单个值。 有缺陷的实现可能会错误地假设存在多个列。 由于该算法直接访问`row[k]`，即使每一行只包含一个元素，它也能正常工作。 

当矩阵已经按降序排序时，会出现第三种边缘情况。 由于不正确的交换逻辑，一些手动排序实现意外地破坏了已排序的数据的稳定性或损坏。 使用该语言的内置排序机制可以保证正确的排序，而不会引入不必要的修改。 

另一个微妙的边缘情况是按最后一列索引排序。 在处理矩阵列时，相差一索引错误很常见。 由于解决方案始终使用精确的索引`k`由问题和约束保证提供`0 <= k < n`，该实现安全地处理第一列和最后一列。
