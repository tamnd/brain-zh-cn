[LeetCode 问题 2511](https://leetcode.com/problems/maximum-enemy-forts-that-can-be-captured/)

 **难度：** 🟢简单
 **主题：** 数组、两个指针

 ## 解决方案

 ## 问题理解

 在这个问题中，我们有一个数组叫做`forts`，其中每个位置代表三种可能状态之一：

 -`1`意味着堡垒属于我们。 
-`0`意味着有敌人的堡垒。 
-`-1`表示该位置为空。 

我们想将我们的军队从我们的一个堡垒转移到一个空的位置。 然而，只有当起始堡垒和目的地之间的每个位置都是敌方堡垒时，该移动才有效。 

这个条件极其重要。 假设我们从索引移动`i`索引`j`。 那么它们之间严格的每个位置都必须包含`0`。 我们无法穿过另一个友方堡垒或另一个空地。 

移动时，沿途经过的每个敌方堡垒都会被占领。 我们的目标是计算在一次有效的移动中可以占领的敌方堡垒的最大数量。 

数组长度最多为`1000`，相对较小。 对于这个约束，甚至二次解也是可以接受的。 然而，问题的结构使我们能够设计出更简单、更高效的线性时间解决方案。 

关键的观察是，有效的举动总是如下所示：

 - 一个端点是`1`- 另一个端点是`-1`- 它们之间的每个值都是`0`有效段的示例：```
[1,0,0,-1]
[-1,0,0,0,1]
```无效段的示例：```
[1,0,-1,0]      # extra values after destination
[1,0,1,-1]      # another friendly fort in between
[1,-1]           # captures 0 forts
```一些边缘情况很重要：

 - 该阵列可能根本不包含友方堡垒。 
- 可能没有空位`-1`。 
- 敌方堡垒之间可能没有连续的序列`1`和`-1`。 
- 邻近的`1`和`-1`占领零个堡垒。 
- 可能存在多个有效段，我们必须返回最大捕获计数。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是尝试每对索引`(i, j)`其中：

 - 一个位置包含`1`- 另一个包含`-1`对于每一对这样的对，我们检查它们之间的所有位置以验证它们是否都是`0`。 

如果该段有效，则占领的堡垒数量等于：```
abs(i - j) - 1
```因为端点之间的所有位置都是敌方堡垒。 

这种方法是正确的，因为它明确地检查每个可能的移动并直接验证问题约束。 

然而，实现变得效率低下，因为对于每对位置，我们可能会扫描它们之间的整个间隔。 在最坏的情况下：

 - 有`O(n^2)`对
 - 每次验证需要`O(n)`导致`O(n^3)`时间复杂度。 

虽然`n <= 1000`虽然这在技术上可行，但速度却不必要地慢。 

### 最佳方法

 更好的方法来自于观察有效动作的结构。 

有效的移动需要：

 - 一个端点`1`- 另一个端点是`-1`- 他们之间的一切`0`这意味着我们只关心连续的非零位置。 

每当我们遇到非零值时，我们都会将其与之前看到的非零值进行比较：

 - 如果它们是相反的值（`1`和`-1`）
 - 那么它们之间的所有位置必须为零
 - 因此该段有效

 占领的堡垒数量就是这两个非零位置之间的距离减一。 

这使我们能够一次性解决数组中的问题。

 ## 算法演练

 ### 最佳线性扫描算法

 1.初始化两个变量：

 -`previous_index = -1`-`max_captured = 0`这`previous_index`变量存储包含以下任一内容的最新位置`1`或者`-1`。 
2. 从左到右迭代数组。 
3. 对于每个索引`i`，跳过该位置，如果`forts[i] == 0`。 

敌方堡垒本身不是移动的终点，因此在扫描过程中它们并不直接重要。 
4. 每当我们遇到非零值时，检查我们之前是否见过另一个非零位置。 

如果`previous_index != -1`，然后我们比较：

 -`forts[i]`-`forts[previous_index]`5. 如果两个值不同，则它们之间的段仅包含零。 

这是有效的，因为：

 - 我们只更新`previous_index`当遇到非零值时
 - 因此它们之间不能有另一个非零值
 6. 计算占领的堡垒：```
captured = i - previous_index - 1
```7.更新答案：```
max_captured = max(max_captured, captured)
```8. 更新`previous_index = i`。 

这为下一段的算法做好了准备。 
9.遍历结束后，返回`max_captured`。 

### 为什么它有效

 该算法保持不变式`previous_index`始终指向最近的非零位置。 

当我们遇到另一个非零位置时：

 - 两个非零索引之间的所有位置必须为零
 - 否则我们会更早遇到另一个非零值

 因此，如果端点值相反（`1`和`-1`），保证该段代表有效的移动。 由于每个有效的移动都必须发生在连续的非零位置之间，因此检查这些对足以找到最佳答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def captureForts(self, forts: List[int]) -> int:
        previous_index = -1
        max_captured = 0

        for current_index, value in enumerate(forts):
            if value == 0:
                continue

            if previous_index != -1:
                if forts[previous_index] != value:
                    captured = current_index - previous_index - 1
                    max_captured = max(max_captured, captured)

            previous_index = current_index

        return max_captured
```该实现完全遵循线性扫描策略。 

变量`previous_index`存储最后看到的非零位置。 在迭代过程中，敌方堡垒（`0`）被忽略，因为它们只作为可能被捕获的位置而重要。 

每当我们遇到另一个非零位置时，我们都会比较端点值。 如果它们不同，则它们之间的段有效。 占领的堡垒数量等于两个端点之间的位置数量。 

表达式：```python
current_index - previous_index - 1
```准确计算两个端点之间有多少个敌人堡垒。 

最后，我们更新最大结果并继续扫描。 

## 解决方案```go
func captureForts(forts []int) int {
    previousIndex := -1
    maxCaptured := 0

    for currentIndex, value := range forts {
        if value == 0 {
            continue
        }

        if previousIndex != -1 {
            if forts[previousIndex] != value {
                captured := currentIndex - previousIndex - 1

                if captured > maxCaptured {
                    maxCaptured = captured
                }
            }
        }

        previousIndex = currentIndex
    }

    return maxCaptured
}
```Go 实现密切反映了 Python 逻辑。 

Go 切片是数组上动态大小的视图，因此不需要特殊处理。 整数溢出不是问题，因为最大数组长度仅为`1000`。 

手动最大比较取代了Python的内置`max()`功能。

 ## 边缘情况

 ### 相邻`1`和`-1`一个非常常见的错误是错误地将相邻端点视为占领一个堡垒。 考虑：```
[1, -1]
```端点之间没有位置，所以正确答案是`0`。 

该实现正确处理了这个问题，因为：```
captured = current_index - previous_index - 1
```评估为：```
1 - 0 - 1 = 0
```### 连续非零值

 当非零值连续出现时，会出现另一个棘手的情况：```
[1, 1, 0, -1]
```第一个`1`无法直接连接到`-1`因为另一个非零值中断了该段。 

该算法通过不断更新来处理这个问题`previous_index`每当遇到非零值时。 因此，仅检查连续的非零端点。 

### 没有有效移动的数组

 有些数组根本不包含有效的移动：```
[0,0,0]
[1,1,1]
[-1,-1]
```幼稚的实现可能会意外地产生负计数或无效结果。 

此实现安全返回`0`因为：

-`max_captured`开始于`0`- 仅当找到有效的相反端点段时才更新
 - 无效段会被自动忽略
