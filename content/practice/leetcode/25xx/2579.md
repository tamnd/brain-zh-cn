[LeetCode 问题 2579](https://leetcode.com/problems/count-total-number-of-colored-cells/)

 **难度：** 🟡 中等
 **主题：** 数学

 ## 解决方案

 ## 问题理解

 该问题描述了在无限二维网格上对单元进行着色的过程`n`分钟。 分钟`1`，我们首先将任意一个单元格着色为蓝色。 此后的每一分钟，与已经蓝色的单元格共享一侧的每个未着色的单元格也会变成蓝色。 

简单来说，彩色区域一次向外扩展一层。 由于只有边缘接触现有蓝色单元的单元才被着色，因此形状对称地生长成以原始单元为中心的菱形图案。 

输入是单个正整数`n`，表示着色过程运行了多少分钟。 输出应该是精确之后的彩色单元格总数`n`分钟。 

约束相对较小，`1 <= n <= 10^5`，但这仍然足够大，以至于每分钟模拟每个细胞可能会变得低效。 由于网格理论上是无限的，任何强力模拟都需要仔细记录以避免过多的内存使用。 

重要的观察是该问题保证`n`总是正数，所以我们永远不需要处理无效值，例如`0`或负整数。 最小的情况是`n = 1`，其中仅存在初始单元。 较大的值`n`创建越来越大的菱形扩展，而简单的模拟可能会变得不必要的昂贵。 

## 方法

 ### 暴力模拟

 解决这个问题的直接方法就是逐分钟模拟着色过程。 

我们可以维护一组当前有颜色的单元格。 最初，该集合包含一个单元格，例如`(0, 0)`。 在每一分钟，我们都会检查所有当前着色的单元格，并在四个基本方向上添加任何未着色的相邻单元格：上、下、左、右。 

这种方法之所以有效，是因为它忠实地遵循问题陈述中描述的确切过程。 通过从所有蓝色单元反复向外扩展，我们最终达到正确的最终配置。 

然而，这种方法效率低下。 有色细胞的数量呈二次方增长`n`，这意味着模拟需要存储和处理许多坐标。 自从`n`可以大到`100000`，明确跟踪数十亿个细胞是完全不切实际的。 

### 数学观察

 我们可以对模式进行数学分析，而不是模拟该过程。 

如果我们观察每分钟添加的细胞数量：

 - 分钟`1`：`1`- 分钟`2`：`+4`- 分钟`3`：`+8`- 分钟`4`：`+12`我们注意到一个清晰的模式。 每新一分钟都会增加`4 × (minute - 1)`细胞。 

发生这种情况是因为形状像钻石一样膨胀，并且每个新层都会贡献四个不断增长的边缘。 

因此，有色细胞的总数变为：$$1 + 4(1 + 2 + 3 + ... + (n-1))$$使用算术级数公式：$$1 + 4 \cdot \frac{(n-1)n}{2}$$简化：$$1 + 2n(n-1)$$这给了我们一个`O(1)`无需模拟即可直接计算答案的解决方案。

 ## 算法演练

 1. 从观察开始`1`， 确切地`1`细胞是有颜色的。 
2. 请注意，随后的每一分钟都会添加可预测数量的单元格。 分钟`2`,`4`添加细胞。 分钟`3`,`8`添加细胞。 分钟`k`， 确切地`4 × (k - 1)`添加细胞。 
3. 将所有添加的单元格相加`n`分钟：$$1 + 4(1 + 2 + 3 + ... + (n-1))$$4. 使用以下公式替换算术和：$$\sum_{i=1}^{n-1} i = \frac{(n-1)n}{2}$$5、简化表达式：$$1 + 4 \cdot \frac{(n-1)n}{2}$$

$$1 + 2n(n-1)$$6. 直接返回计算值。 

### 为什么它有效

 关键的不变量是，每分钟之后，彩色细胞就会形成完美对称的菱形。 每个膨胀层均匀地增加周长，从而导致`4 × (minute - 1)`新细胞出现。 由于这种生长模式是确定性的并形成算术序列，因此将这些加法相加即可得出彩色细胞的确切总数。 

## Python 解决方案```python
class Solution:
    def coloredCells(self, n: int) -> int:
        return 1 + 2 * n * (n - 1)
```实现故意简单，因为数学公式已经捕获了整个过程。 

表达式`2 * n * (n - 1)`计算初始单元之外的所有扩展层的总贡献。 这`+1`占分钟时着色的原始蓝色单元格`1`。 

Python 整数自动支持任意大的值，因此溢出不是问题，即使答案可能变得相当大`n = 100000`。 

## 解决方案```go
func coloredCells(n int) int64 {
	return 1 + int64(2*n*(n-1))
}
```Go 实现遵循与 Python 版本相同的公式。 

主要区别在于整数处理。 自从Go的`int`类型可能因平台而异，结果可能会变大，函数返回`int64`根据问题签名的要求。 我们将计算结果显式转换为`int64`确保正确性并避免溢出问题。

 ## 边缘情况

 ### 最小输入，`n = 1`这是最小的有效输入，也是差一错误的常见来源。 有缺陷的实现可能会错误地假设扩展立即开始并错误地返回`5`。 我们的公式正确地处理了这个问题，因为：$$1 + 2 \times 1 \times (1 - 1) = 1$$乘以零自然会防止添加任何额外的单元格。 

### 接近约束极限的大输入

 当`n = 100000`，答案就变得很大：$$19999800001$$强力模拟是不可行的，因为它需要跟踪数十亿个细胞。 数学解决方案可以在恒定时间内有效地处理这个问题。 

### 模式识别中的差一错误

 一个常见的错误是错误地假设分钟`k`添加`4k`细胞而不是`4(k-1)`。 这会过度计算每一层并产生不正确的结果。 我们的实现通过直接从观察到的序列和算术级数推导出公式来避免这个问题。
