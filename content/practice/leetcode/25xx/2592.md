## 问题理解

 问题给了我们一个整数数组`nums`并要求我们将其排列到一个新数组中`perm`这样索引的数量`i`为此`perm[i] > nums[i]`被最大化。 这个计数被称为排列的**伟大**。 任何排列后的输出应该是最大可能的值。 

换句话说，对于原始数组中的每个元素，如果可能的话，我们希望在其位置上放置一个更大的数字。 由于数组可以排列，因此`nums`不限制我们。 关键是确定哪些元素可以“击败”其他元素以最大化计数。 

约束为我们提供了有关输入规模的重要信息：`nums`最多可以有 100,000 个元素，每个元素最大可以为 10^9。 这立即排除了任何暴力排列解决方案，因为有`n!`可能的排列。 我们需要一个运行时间为 O(n log n) 或 O(n) 的解决方案。 

重要的边缘情况包括具有所有相同元素的数组（最大伟大度为 0）、已经严格递增或递减的数组以及具有重复数字的数组。 

## 方法

 ### 蛮力

 蛮力方法将产生所有排列`nums`，然后对于每个排列，计算位置数`i`这样`perm[i] > nums[i]`。 所有排列的最大计数就是答案。 

这显然太慢了：生成`n!`排列是不可行的`n`最多 10^5。 因此，暴力破解是不切实际的。 

### 最佳方法

 关键的观察结果是，问题简化为**贪婪匹配问题**。 如果我们排序`nums`，那么对于每个元素`x`，我们希望将它与数组中大于 x** 的最小数字配对。 这确保我们最大限度地增加职位数量`perm[i] > nums[i]`。 

我们可以使用排序和两指针方法有效地实现这一点：

 1. 排序`nums`。 
2. 使用一个指针来存储原始排序数组，使用另一个指针来选择排列的候选者。 
3. 计算排序数组中有多少个元素可以与严格更大的元素匹配。 

实际上，这类似于计算多重集中可以与另一个元素严格配对的元素数量，从而最大化“胜利”。

 ## 算法演练

 1. 排序`nums`按升序排列。 
2.初始化两个指针：`i`在排序数组的开头（跟踪要击败的元素）和`j`在排序数组的开头（跟踪候选者`perm`）。 
3. 初始化`greatness = 0`。 
4. 遍历数组`j`。 对于每个候选元素`nums[j]`，检查是否`nums[j] > nums[i]`。 

- 如果为真，则增加`greatness`并将两个指针向前移动（我们已成功配对一个元素）。 
- 如果为 false，则仅移动`j`前进（当前候选人无法击败当前候选人`i`元素，尝试下一个候选）。 
5. 继续，直到任一指针到达数组末尾。 
6. 返回`greatness`。 

**为什么有效：** 排序保证我们总是尝试用最小的可用较大元素击败最小的剩余元素。 这种贪婪的配对最大化了我们可以“获胜”的元素总数，这正是最大的伟大。 

## Python 解决方案```python
from typing import List

class Solution:
    def maximizeGreatness(self, nums: List[int]) -> int:
        nums.sort()
        n = len(nums)
        i = 0
        greatness = 0
        
        for j in range(n):
            if nums[j] > nums[i]:
                greatness += 1
                i += 1
        
        return greatness
```**解释：** 我们首先排序`nums`启用贪婪配对。 指针`i`跟踪我们试图击败的元素。 指针`j`按排序顺序迭代可能的候选者。 每当`nums[j] > nums[i]`，我们可以增加伟大度并移动到下一个要击败的元素。 这个循环确保我们最大化索引总数，其中`perm[i] > nums[i]`。 

## 解决方案```go
import "sort"

func maximizeGreatness(nums []int) int {
    sort.Ints(nums)
    n := len(nums)
    i := 0
    greatness := 0
    
    for j := 0; j < n; j++ {
        if nums[j] > nums[i] {
            greatness++
            i++
        }
    }
    
    return greatness
}
```**Go 特定说明：** 实现镜像了 Python 版本。 排序用途`sort.Ints`。 Go 切片自动处理带索引的迭代，并且整数在此问题范围内不会溢出。 诸如空切片之类的边缘情况由循环边界隐式处理。

 ## 边缘情况

 1. **所有相同的元素**：如果`nums = [x, x, x, ...]`，没有一个元素可以击败另一个元素，所以伟大度为 0。算法正确地处理了这个问题，因为`nums[j] > nums[i]`永远不成立。 
2. **单元素数组**：有`nums = [x]`，没有什么可以配对，所以伟大度为 0。循环永远不会递增`greatness`并返回 0。 
3. **具有多个重复项的数组**：例如，`nums = [1,2,2,3]`。 排序确保我们匹配每个`i`与下一个最大的`j`，防止过度计算并正确地最大化伟大。 贪婪配对避免将大数字分配给小数字，而这不会产生额外的伟大。
