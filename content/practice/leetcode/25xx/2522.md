 # LeetCode 2522 - 将字符串划分为值最多为 K 的子字符串

 ## 问题理解

 问题给了我们一个数字字符串`s`，其中每个字符都是介于`'1'`和`'9'`，和一个整数`k`。 我们必须将字符串拆分为连续的子字符串，以便每个子字符串在解释为整数时具有小于或等于的值`k`。 

目标是最小化分区中子串的数量。 

分区必须满足两个重要条件：

 1. 字符串中的每个字符必须恰好属于一个子字符串。 
2. 每个结果子串必须代表一个小于或等于的数字`k`。 

如果不存在有效分区，我们返回`-1`。 

例如，假设：```
s = "165462"
k = 60
```一个有效的分区是：```
"16" | "54" | "6" | "2"
```所有数字最多为`60`，我们用了`4`子串。 

约束条件非常重要：

 -`s.length`可以大到`10^5`-`k`可以大到`10^9`这些限制立即告诉我们昂贵的指数或二次算法将不起作用。 我们需要一个高效的解决方案，最好是线性时间。 

另一个关键的观察结果是这些数字仅来自`'1'`到`'9'`。 无需担心前导零，这简化了解析和比较。 

一些边缘情况很重要：

 - 一位数可能已经大于`k`。 在这种情况下，不可能进行任何分区。 
- 最佳划分不一定是平衡的。 有时我们需要很长的子串，有时需要很短的子串。 
- 由于字符串可能非常大，因此如果简单地重复将大子字符串转换为整数会太慢。 

## 方法

 ### 蛮力方法

 暴力解决方案会尝试一切可能的方法来划分字符串。 

对于一个长度的字符串`n`， 有`2^(n-1)`可能的分区模式，因为字符之间的每个间隙可以包含剪切或不包含剪切。 

对于每个分区配置，我们将：

 1. 构造所有子串。 
2. 将每个子字符串转换为整数。 
3. 验证每个子串最多`k`。 
4. 跟踪有效分区中子串的最小数量。 

这种方法是正确的，因为它详尽地检查了每个可能的分区，保证找到最小的有效分区计数。 

然而，它太慢了。 和`n = 10^5`，指数复杂度是完全不可行的。 

### 关键见解

 重要的观察是，为了最小化子串的数量，我们应该在切割之前使每个子串尽可能大。 

假设我们从左到右构建当前子字符串。 只要附加下一个数字即可使数值小于或等于`k`，扩展子字符串总是有益的，因为：

 - 较长的子串意味着较少的总分区。 
- 提前切割永远不会减少分区总数。 

这自然会导致贪婪策略。 

我们从左到右处理字符串：

 - 继续扩展当前的数量。 
- 如果附加下一个数字会超过`k`，开始一个新的子串。 
- 如果超过一个数字`k`， 返回`-1`。 

这是有效的，因为每个贪婪扩展都会最大化当前子字符串的长度，从而最小化子字符串的总数。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |

 ## 算法演练

 1.初始化一个计数器`partitions`到`1`因为我们从一个子字符串开始。 
2. 初始化`current_value`到`0`。 该变量表示当前正在构建的子字符串的数值。 
3. 迭代字符串中的每个字符。 
4. 将当前字符转换为其数字值。 
5. 在添加数字之前，检查数字本身是否大于`k`。 

如果是，则不存在有效分区，因为即使是单字符子字符串也会违反条件。 返回`-1`。 
6. 如果我们附加数字，则计算新值：```
new_value = current_value * 10 + digit
```7. 如果`new_value <= k`，通过更新扩展当前子字符串：```
current_value = new_value
```8. 否则，我们必须开始一个新的子字符串，因为附加数字会超过`k`。 

增加分区计数：```
partitions += 1
```仅使用当前数字开始新的子字符串：```
current_value = digit
```9.处理完所有字符后，返回`partitions`。 

### 为什么它有效

 贪心选择始终是最优的，因为每个分区边界都会将答案增加一。 因此，我们应该尽可能推迟分区。 

如果扩展当前子串最多仍然保持其值`k`，提前创建剪切只会增加子串的总数，而不会带来任何好处。 因此，在每一步贪婪地获取最长的可能有效子串会产生最小数量的分区。 

## Python 解决方案```python
class Solution:
    def minimumPartition(self, s: str, k: int) -> int:
        partitions = 1
        current_value = 0

        for ch in s:
            digit = int(ch)

            if digit > k:
                return -1

            new_value = current_value * 10 + digit

            if new_value <= k:
                current_value = new_value
            else:
                partitions += 1
                current_value = digit

        return partitions
```实现直接遵循贪心算法。 

变量`partitions`跟踪到目前为止已经形成了多少个子串。 我们将其初始化为`1`因为该算法总是以一个活动子串开始。 

变量`current_value`存储当前正在构建的子字符串的数值。 

对于每个字符：

 - 我们将其转换为数字。 
- 我们立即检查数字本身是否超出`k`。 
- 我们尝试将数字附加到当前子字符串。 
- 如果结果值仍然有效，我们将继续扩展。 
- 否则，我们创建一个新分区并从当前数字重新启动。 

该算法对每个字符只处理一次，因此对于大输入来说非常高效。 

## 解决方案```go
func minimumPartition(s string, k int) int {
    partitions := 1
    currentValue := 0

    for _, ch := range s {
        digit := int(ch - '0')

        if digit > k {
            return -1
        }

        newValue := currentValue*10 + digit

        if newValue <= k {
            currentValue = newValue
        } else {
            partitions++
            currentValue = digit
        }
    }

    return partitions
}
```Go 实现与 Python 版本几乎相同。 

一些特定于 Go 的细节值得注意：

 - 字符被迭代为符文，所以我们使用`ch - '0'`。 
- 整数算术是安全的，因为`k <= 10^9`，它很适合 Go 的内部`int`。 
- 不需要额外的切片或数组，因此空间使用保持不变。

 ## 边缘情况

 当一位数已经大于`k`。 例如：```
s = "9"
k = 5
```不存在有效分区，因为每个子字符串必须至少包含一位数字，而该一位数字已经违反了约束。 实现通过检查立即处理此问题：```
if digit > k:
    return -1
```当整个字符串已经小于或等于时，会发生另一个重要情况`k`。 例如：```
s = "123"
k = 1000
```在这种情况下，最优答案是`1`因为不需要拆分。 贪心算法自然地实现了这一点，因为它仅在附加另一个数字超出时才创建一个新分区`k`。 

当重复扩展频繁超过时，会出现更微妙的边缘情况`k`。 考虑：```
s = "999999"
k = 9
```每次尝试附加另一个数字都会立即超出限制，迫使每个数字进入自己的子字符串。 每当扩展值变得太大时，算法就会通过创建新分区来正确处理此问题。 

另一个棘手的场景涉及精确的边界匹配。 例如：```
s = "1000"
k = 1000
```子字符串值恰好等于`k`，这是允许的。 由于条件使用`<= k`，实现正确地继续扩展子字符串而不是不必要的分割。
