[LeetCode 问题 2575](https://leetcode.com/problems/find-the-divisibility-array-of-a-string/)

 **难度：** 🟡 中等
 **主题：** 数组、数学、字符串

 ## 解决方案

 ## 问题理解

 问题给了我们一个数字字符串`word`和一个整数`m`。 对于字符串的每个前缀，我们必须确定该前缀是否表示一个可以被整除的数字`m`。 

一个前缀`word[0...i]`表示从索引处开始的子字符串`0`并以索引结束`i`，包含在内。 由于字符串仅包含数字，因此每个前缀都可以解释为十进制整数。 

对于每个前缀：

 - 如果前缀的数值可以整除`m`，我们放置`1`在结果数组中。 
- 否则，我们放置`0`。 

最终的答案是一个数组`div`长度`n`， 在哪里`n`是字符串的长度。 

例如，假设：```
word = "1010"
m = 10
```前缀是：

 -`"1"`→ 1 % 10 != 0 → 0
 -`"10"`→ 10 % 10 == 0 → 1
 -`"101"`→ 101 % 10 != 0 → 0
 -`"1010"`→ 1010 % 10 == 0 → 1

 所以答案就变成了：```
[0, 1, 0, 1]
```约束条件极其重要：

 -`n`可以大到`10^5`-`m`可以大到`10^9`将每个前缀转换为完整整数的简单实现很快就会变得低效。 事实上，前缀最多可以包含`100000`数字，它不适合许多语言中的标准整数类型。 

这些约束强烈表明我们需要一种数学方法来增量处理字符串而不构造巨大的整数。 

一些边缘情况很重要：

 - 单字符字符串。 
- 包含前导零的前缀。 
- 非常大的字符串，直接构造整数会溢出。 
- 每个前缀都是可整除的情况。 
- 没有前缀可整除的情况。 
- 大值`m`。 

该问题保证：

 - 该字符串仅包含数字。 
-`m`总是积极的。 
- 字符串长度至少为 1。 

这些保证简化了无效输入情况的处理。 

## 方法

 ### 蛮力方法

 最直接的方法是独立检查每个前缀。 

对于每个索引`i`：

 1.提取子串`word[0:i+1]`。 
2. 将其转换为整数。 
3. 计算是否能被整除`m`。 
4. 追加`1`或者`0`到结果。 

这是有效的，因为它直接遵循问题定义。 

然而，这种方法对于大量输入来说太慢了。 

如果字符串长度为`n`，那么：

 - 创建每个前缀需要`O(i)`时间。 
- 将其转换为整数也需要花费`O(i)`时间。 

对于所有前缀，这大约导致：$1+2+3+\cdots+n = \frac{n(n+1)}{2}$这给出了二次时间复杂度，`O(n^2)`。 

此外，前缀可能会变得非常大，导致固定宽度整数类型出现溢出问题。 

### 最佳方法

 关键的观察是我们永远不需要前缀的完整数值。 我们只需要它的模余数`m`。 

假设我们已经知道：```
previous_prefix % m
```当我们追加一个新数字时`d`，新的数字变为：$new\_value = old\_value \times 10 + d$取模`m`：$new\_remainder = (old\_remainder \times 10 + d) \bmod m$这使我们能够逐位处理字符串，同时仅保留当前的余数。 

每一步：

 - 更新剩余部分。 
- 如果余数为零，则当前前缀可以被整除`m`。 

这完全避免了大整数构造并以线性时间运行。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 重复重新计算大前缀 |
 | 最佳| O(n) | O(n) | 保持运行余数模`m`|

 ## 算法演练

 ### 第 1 步：初始化结果数组

 创建一个空结果数组来存储`1`或者`0`对于每个前缀。 

同时初始化一个变量`remainder = 0`。 

该变量代表：```
current_prefix % m
```而不是存储完整的号码。 

### 第 2 步：迭代每个字符

 从左到右处理字符串。 

对于每个字符：

 1. 将字符转换为数值。 
2. 使用模运算更新运行余数。 

更新公式为：$remainder = (remainder \times 10 + digit) \bmod m$此公式模拟将数字附加到当前数字。 

### 步骤 3：检查整除性

 更新剩余部分后：

 - 如果`remainder == 0`, 附加`1`。 
- 否则，附加`0`。 

余数为零意味着当前前缀可以被整除`m`。 

### 第 4 步：继续直到结束

 对字符串中的每个数字重复该过程。 

最后返回结果数组。 

### 为什么它有效

 该算法在处理索引后保持了不变式`i`,`remainder`等于：```
numeric_value_of(word[0:i]) % m
```当添加新数字时，十进制数字结构如下：```
new_number = old_number * 10 + digit
```由于模算术分布在加法和乘法上，因此更新的余数公式会生成新前缀的精确模值，而无需构造完整的数字。 

因此，每当余数变为零时，相应的前缀就可以被整除`m`。 

## Python 解决方案```python
from typing import List

class Solution:
    def divisibilityArray(self, word: str, m: int) -> List[int]:
        result = []
        remainder = 0

        for ch in word:
            digit = int(ch)

            remainder = (remainder * 10 + digit) % m

            if remainder == 0:
                result.append(1)
            else:
                result.append(0)

        return result
```实现直接遵循最优算法。 

变量`remainder`存储当前前缀的模值。 该代码不是构建大整数，而是使用模算术增量更新余数。 

对于每个角色：

 1. 将字符转换为数字。 
2. 更新运行余数。 
3. 检查余数是否为零。 
4. 附加相应的结果值。 

该解决方案只处理一次字符串，即使对于最大约束大小也能保持高效。 

## 解决方案```go
func divisibilityArray(word string, m int) []int {
    result := make([]int, len(word))

    remainder := 0

    for i := 0; i < len(word); i++ {
        digit := int(word[i] - '0')

        remainder = (remainder*10 + digit) % m

        if remainder == 0 {
            result[i] = 1
        }
    }

    return result
}
```Go 实现与 Python 版本几乎相同。 

预先创建固定大小的切片，因为输出长度是预先知道的。 

使用以下方法提取数字：```go
word[i] - '0'
```它将字符字节转换为其整数值。 

整数溢出不是问题，因为余数总是按模减少`m`， 和`m <= 10^9`，它很适合 Go 的内部`int`在现代系统上键入。

 ## 边缘情况

 ### 前导零

 输入如`"0000"`可能会导致天真的实现出现问题，错误地解释前缀或去除前导零。 在此问题中，前缀仍必须被视为有效的十进制数。 

模块化算术方法可以自然地处理这个问题。 附加零只是正确更新余数，而前缀如`"00"`评估为零，可被任何正数整除`m`。 

### 极大的前缀值

 简单的解决方案可能会尝试直接将前缀转换为整数。 字符串长度可达`100000`，前缀可能会变得远远大于标准整数限制。 

此实现从不存储完整的数字。 它只存储当前的模余数`m`，始终保持在范围内`[0, m-1]`。 这完全避免了溢出问题。 

### 大模值

 当`m`非常大，比如`10^9`，某些实现可能会错误地假设整除模式或使用不安全的算术。 

该算法仍然正确，因为所有操作都是简单的模块化更新。 由于余数在每一步后都会减少，因此中间值保持可管理且高效。
