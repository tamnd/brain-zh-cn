## LeetCode 2598 - 运算后最小缺失的非负整数

 ### 问题理解

 问题给了我们一个整数数组`nums`和一个整数`value`。 我们可以对数组的任何元素重复执行操作：加或减`value`任意次数。 

关键的观察是添加或减去`value`不允许元素变成任意数字。 相反，每个数字都保留在相同的余数类模中`value`。 

例如，如果`value = 5`：

 -`1`可以成为`..., -9, -4, 1, 6, 11, ...`-`7`可以成为`..., -3, 2, 7, 12, ...`请注意，所有值均可从`7`有余数`2`当除以`5`。 

任务是在应用任意次操作后最大化数组的 MEX。 

数组的 MEX（最小排除值）是数组中未出现的最小非负整数。 

例如：

-`[0,1,2,4]`有墨西哥`3`-`[1,2,3]`有墨西哥`0`-`[0,1,3]`有墨西哥`2`由于我们可以使用允许的操作自由修改数字，因此我们希望尽可能有效地重新排列这些值，以创建从`0`。 

约束条件很重要：

 -`nums.length <= 10^5`-`value <= 10^5`-`nums[i]`可能非常大或为负，最多`10^9`这些限制立即排除了操作的强力模拟。 由于值可能变得非常大或为负，因此我们无法真正尝试所有可能的转换。 

相反，我们需要利用运算的数学结构。 

一些边缘情况很重要：

 - 负数，因为必须小心处理模行为。 
- 重复余数组，因为多个数字可能会竞争相同的目标值。 
- 非常大的值`nums[i]`，其中暴力转移变得不可能。 
- 情况`value = 1`，因为每个数字都可以转化为任何整数。 

## 方法

 ### 蛮力方法

 思考这个问题的一个天真的方法是反复尝试构建序列`0,1,2,...`看看某个元素是否可以转化为每个数字。 

对于每个目标整数`x`，我们可以扫描`nums`并检查是否可以将一些未使用的数字转换为`x`。 

一个数字`num`可以成为`x`如果：```
(num - x) % value == 0
```如果我们找到这样的号码，我们将其标记为已使用并继续`x + 1`。 否则，`x`是墨西哥。 

此方法是正确的，因为它明确尝试构建非负整数的最长连续前缀。 

然而，它太慢了。 对于每个候选 MEX 值，我们可以扫描整个数组。 由于答案本身可能与`n`，复杂度大致变为：```
O(n^2)
```这对于`n = 10^5`。 

### 关键见解

 关键的观察是添加或减去`value`保留模类。 

如果：```
x % value == r
```那么只有余数为模的数字`value`也是`r`可以转变为`x`。 

这就把问题转化为资源分配问题。 

认为：```
value = 5
```然后我们计算有多少个数字属于每个余数组。 

例子：```
nums = [1,-10,7,13,6,8]
```模数`5`：```
1  -> 1
-10 -> 0
7  -> 2
13 -> 3
6  -> 1
8  -> 3
```频率表：```
0 -> 1
1 -> 2
2 -> 1
3 -> 2
4 -> 0
```现在尝试从以下位置开始构建数字`0`。 

-`0`需要剩余`0`， 可用的
-`1`需要剩余`1`， 可用的
-`2`需要剩余`2`， 可用的
-`3`需要剩余`3`， 可用的
-`4`需要剩余`4`, 不可用

 所以答案是`4`。 

我们不关心使用哪个确切数字。 我们只关心每个余数桶中有多少个数字。

 ## 算法演练

 ### 最优算法

 1. 创建余数模的频率图`value`。 

对于每一个数字`nums`，计算：```
remainder = num % value
```由于负模在某些语言中表现不同，因此将其标准化：```
remainder = ((num % value) + value) % value
```存储有多少个数字属于每个余数类别。 
2. 开始构建序列`0`。 

初始化：```
current = 0
```这代表我们尝试创建的下一个数字。 
3. 确定需要哪个剩余类别。 

构造数`current`，我们需要来自以下位置的号码：```
current % value
```4. 检查可用性。 

如果这个余数的频率为零，我们就不能形成`current`。 

由于 MEX 是第一个缺失的非负整数，因此立即返回`current`。 
5. 消耗该余数组中的一个数字。 

将其频率减一，因为我们用一个数字来表示`current`。 
6. 继续计算下一个整数。 

增量：```
current += 1
```7. 重复此操作，直到剩余班级变得不可用。 

### 为什么它有效

 该算法有效是因为每个整数`x`只能由带有余数的数字组成：```
x % value
```由于操作永远不会改变模类，唯一的问题是该类中是否仍有未使用的数字。 

贪婪地构建数字`0`向上是最优的，因为 MEX 仅取决于第一个缺失的整数。 如果我们能够建造`x`，没有理由为了更多的数字而推迟它。 因此，按顺序消耗剩余资源可以保证最大可能的 MEX。 

## Python 解决方案```python
from typing import List
from collections import Counter

class Solution:
    def findSmallestInteger(self, nums: List[int], value: int) -> int:
        remainder_count = Counter()

        for num in nums:
            remainder = ((num % value) + value) % value
            remainder_count[remainder] += 1

        current = 0

        while True:
            required_remainder = current % value

            if remainder_count[required_remainder] == 0:
                return current

            remainder_count[required_remainder] -= 1
            current += 1
```该实现首先计算有多少个数字属于每个模类。 由于数字只能转换为具有相同余数模的值`value`，该频率图捕获了所有有用的信息。 

接下来，算法贪婪地尝试构造从以下位置开始的整数：`0`。 对于每个候选号码，它检查所需剩余类别中的号码是否仍然可用。 

如果该桶中不存在数字，则当前整数丢失，这意味着它是 MEX。 

否则，将消耗一个计数，算法将移至下一个整数。 

这`Counter`数据结构在这里很有用，因为它会自动返回`0`对于丢失的钥匙，避免特殊情况处理。 

## 解决方案```go
func findSmallestInteger(nums []int, value int) int {
	remainderCount := make(map[int]int)

	for _, num := range nums {
		remainder := ((num % value) + value) % value
		remainderCount[remainder]++
	}

	current := 0

	for {
		requiredRemainder := current % value

		if remainderCount[requiredRemainder] == 0 {
			return current
		}

		remainderCount[requiredRemainder]--
		current++
	}
}
```Go 实现遵循与 Python 相同的逻辑，但使用`map[int]int`而不是`Counter`。 

一个重要的细节是模归一化：```go
((num % value) + value) % value
```Go 可以产生负数的负模结果，因此归一化可确保余数始终落在以下范围内：```go
[0, value - 1]
```与 Python 不同，Go 映射会针对缺失的键返回零值，因此请检查：```go
remainderCount[key] == 0
```自然有效。

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 一次计算余数，一次构建 MEX |
 | 空间| O（值）| 最多`value`剩余桶|

 计数阶段对每个数字处理一次，成本`O(n)`时间。 

贪婪构建阶段最多可以运行`n + 1`次，因为每个成功的步骤都会消耗频率图中的一个数字。 由于只有`n`个数，循环不能超过`O(n)`迭代。 

频率图最多存储`value`唯一的余数类，因此辅助空间是`O(value)`。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`value = 1`。 在这种情况下，每个数字都属于同一模类，因为所有数字都有余数`0`。 因为我们可以加或减`1`每个元素都可以自由地变成任何整数。 因此，答案就变成了数组中元素的数量。 该实现自然地处理了这一问题，因为所有频率都进入一个存储桶并按顺序消耗。 

另一个重要的边缘情况涉及负数。 Go 等语言可能会产生负模值，这可能会错误地将数字放入错误的余数组中。 例如：```
-1 % 5 = -1
```而不是`4`。 该实现使用以下方法避免了此错误：```
((num % value) + value) % value
```这保证了范围内的有效余数`[0, value - 1]`。 

第三个重要的边缘情况是重复的剩余类。 多个数字可能共享相同的模值，必须谨慎使用。 例如：```
nums = [0,0,0]
value = 1
```所有数字都属于同一个余数桶。 贪心算法一次消耗一个来构造：```
0,1,2
```第三次使用后，桶变空，正确答案变为`3`。 

最后，大输入量需要有效的解决方案。 自从`nums.length`可以达到`100000`，任何二次算法都会超时。 该实现避免了重复扫描，而是使用哈希图进行恒定时间余数计数，从而保持整体复杂性呈线性。
