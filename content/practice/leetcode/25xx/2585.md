[LeetCode 问题 2585](https://leetcode.com/problems/number-of-ways-to-earn-points/)

 **难度：** 🔴难
 **主题：** 数组、动态规划

 ## 解决方案

 ## 问题理解

 这个问题本质上是问我们可以从多种类型中选择多少种不同的方法来准确达到目标分数。 每种类型的问题都有固定数量的问题（`counti`）和每个问题的固定分数（`marksi`）。 相同类型的问题是不可区分的，这意味着选择具有相同数量的相同类型问题的任何子集都算作一种方式。 

输入由一个整数组成`target`和一个二维数组`types`其中每个子数组`[counti, marksi]`表示该类型的问题数和每个问题的分数。 输出是精确到达的方法总数`target`点，模数`10^9 + 7`。 

约束表明`target`最多可以有 1000 个，最多可以有 50 种问题，每种问题最多 50 个问题。 这表明朴素的组合枚举是不可行的，因为组合的数量呈指数增长。 边缘情况包括目标小于可能的最低组合、恰好等于所有最大点的总和，或者某些类型的问题多于所需的情况。 

## 方法

 暴力方法需要递归地尝试每种类型的问题的所有组合。 对于每种类型，我们可以选择 0 到`counti`问题并递归地尝试通过后续类型实现剩余目标。 虽然正确，但这种方法太慢，因为递归调用的数量在类型数量和每种类型的问题数量上都是指数级的。 

最佳方法是动态规划。 关键的见解是认识到这是一个有界背包问题：每种问题类型都可以对总数做出多次贡献，但只能达到其计数。 我们可以使用一维 DP 数组`dp[j]`在哪里`j`代表从 0 到`target`。 最初，`dp[0] = 1`因为只有一种方法可以达到零分：不选择任何问题。 然后，对于每种类型，我们迭代`target`降至 0，并针对该类型的每个可能的问题数量，更新获得新分数的方法。 

使用 DP 进行仔细迭代可确保我们计算所有组合而无需冗余，并保持在可行的时间复杂度内。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O((count1+1)_(count2+1)_...*(countn+1)) | O（目标）| 指数级的多种组合； 约束条件下不可行 |
 | 最佳 | O(n * 目标 * 最大计数) | O（目标）| 具有滚动阵列优化的有界背包DP |

 ## 算法演练

 1.初始化一个大小为DP的数组`target + 1`和`dp[0] = 1`所有其他值为 0。这表示获得每个分数的方法数。 
2. 对于每种类型`[counti, marksi]`:

 1. 迭代`j`从`target`下降到 0。这种反向迭代可以防止同一类型内的过度计数。 
2. 对于每个`k`从 1 到`counti`:

 1. 计算`next_score = j + k * marksi`。 
2.如果`next_score > target`，中断，因为不需要更大的分数。 
3. 更新`dp[next_score] = (dp[next_score] + dp[j]) % MOD`。 
3.处理完所有类型后，`dp[target]`包含达到确切目标分数的方法总数。 

**为什么有效：** 该算法正确地维护了以下不变式：`dp[j]`代表获得分数的方式总数`j`使用到目前为止处理的类型。 通过反向迭代并考虑每种类型的所有计数，我们可以考虑所有有效组合而不会过度计数。 

## Python 解决方案```python
from typing import List

class Solution:
    def waysToReachTarget(self, target: int, types: List[List[int]]) -> int:
        MOD = 10**9 + 7
        dp = [0] * (target + 1)
        dp[0] = 1
        
        for count, marks in types:
            for j in range(target, -1, -1):
                for k in range(1, count + 1):
                    next_score = j + k * marks
                    if next_score > target:
                        break
                    dp[next_score] = (dp[next_score] + dp[j]) % MOD
        return dp[target]
```**说明：**`dp`数组记录了达到每个可能分数的方法数量。 对于每种类型，我们反向迭代以避免在一次迭代中多次使用相同的类型。 内部循环遍历该类型的可能计数，更新所有可实现的分数。 模运算确保我们保持在所需的数值限制内。 

## 解决方案```go
func waysToReachTarget(target int, types [][]int) int {
    const MOD int = 1e9 + 7
    dp := make([]int, target+1)
    dp[0] = 1

    for _, t := range types {
        count, marks := t[0], t[1]
        for j := target; j >= 0; j-- {
            for k := 1; k <= count; k++ {
                nextScore := j + k*marks
                if nextScore > target {
                    break
                }
                dp[nextScore] = (dp[nextScore] + dp[j]) % MOD
            }
        }
    }
    return dp[target]
}
```**说明：** Go 解决方案反映了 Python 方法，使用 DP 数组的切片和模运算的常量。 反向迭代用于确保正确性，当分数超过目标时，内部循环会提前中断。 

## 工作示例

 ### 示例 1`target = 6`,`types = [[6,1],[3,2],[2,3]]`1. 开始于`dp = [1,0,0,0,0,0,0]`2. 流程`[6,1]`:

 - 添加 1 题 1 分：dp[1] = 1
 - 添加 2 个问题，每题 1 分：dp[2] = 1
 - … dp[6] = 1
 3. 流程`[3,2]`:

 - 结合之前的dp值来更新dp[2]、dp[4]、dp[6]等。 
4. 流程`[2,3]`:

 - 通过添加新组合来更新 dp[3]、dp[6]。 
5.最终dp[6] = 7

 ## 边缘情况

 1. **最小目标和单一类型：** 如果`target = 1`和`types = [[1,1]]`，算法正确识别一种方式。 这很重要，因为 DP 初始化必须处理`dp[0] = 1`以确保存在基本情况。 
2. **多个大类型的最大目标：** 当`target`如果数据量很大且类型计数最多为 50，则嵌套循环可能会很慢。 DP 方法避免了指数递归，并在约束范围内有效地处理了这个问题。 
3. **目标无法实现：** 如果没有任何问题组合可以得出`target`，DP阵列将离开`dp[target] = 0`。 该算法无需显式检查即可正确返回零。 

这种方法保证了正确性、效率，并优雅地处理边缘情况。
