[LeetCode 问题 2563](https://leetcode.com/problems/count-the-number-of-fair-pairs/)

 **难度：** 🟡 中等
 **主题：** 数组、两个指针、二分查找、排序

 ## 解决方案

 ## 问题理解

 该问题要求我们计算有多少对索引`(i, j)`满足两个条件：

 1.`i < j`2. 总和`nums[i] + nums[j]`位于包含范围内`[lower, upper]`我们得到一个整数数组`nums`和两个界限，`lower`和`upper`。 目标是返回有效索引对的总数。 

关键细节是我们计算的是索引对，而不是不同的值。 如果相同的值在数组中出现多次，则不同的索引组合将计为不同的对。 

例如，如果`nums = [1, 1, 1]`目标范围包括`2`，那么所有三个索引对都是有效的：

 -`(0,1)`-`(0,2)`-`(1,2)`约束条件非常重要：

 -`nums.length`可以大到`10^5`- 数组内的值可以是非常大的正整数或负整数
 -`lower`和`upper`也可以很大

 一个简单的嵌套循环会检查每个可能的对，这需要`O(n^2)`时间。 和`n = 100000`，这大约意味着`10^10`操作，这太慢了。 

这些约束强烈表明我们需要一种算法`O(n log n)`。 

一些边缘情况很重要：

 - 包含重复值的数组
 - 包含负数的数组
 - 所有对都有效的情况
 - 没有对有效的情况
 - 非常小的数组，例如长度`1`- 在某些语言中，大整数和可能会溢出 32 位整数

 该问题保证了`lower <= upper`，因此有效范围始终是明确定义的。 

## 方法

 ### 蛮力

 最直接的解决方案是检查每一个可能的对`(i, j)`在哪里`i < j`。 

对于每对：

 1. 计算`nums[i] + nums[j]`2. 检查总和是否介于`lower`和`upper`3. 如果有则增加答案

 这种方法是正确的，因为它明确地检查每个有效对一次。 

但是，该数组最多可以包含`100000`元素。 可能的对数为：$\frac{n(n-1)}{2}$什么时候`n = 100000`，这大约变成`5 * 10^9`对，太大而无法有效处理。 

### 最佳方法

 关键的见解是排序将问题转化为二分搜索或两个指针变得有用的问题。 

Suppose the array is sorted.

 对于固定索引`i`，我们想要计算有多少个索引`j > i`满足：$lower \le nums[i] + nums[j] \le upper$重新排列给出：$lower - nums[i] \le nums[j] \le upper - nums[i]$现在任务变成：

 - 找到第一个位置`nums[j] >= lower - nums[i]`- 找到第一个位置`nums[j] > upper - nums[i]`由于数组是有序的，二分查找可以有效地找到这些边界。 

指数有效合作伙伴数量`i`很简单：```
right_boundary - left_boundary
```对每个索引重复此操作会得到`O(n log n)`解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 直接检查每个可能的对 |
 | 最佳| O(n log n) | O(n log n) | O(1) 或 O(log n) | 对数组进行排序并使用二分搜索来查找有效范围 |

 ## 算法演练

 1. 按非降序对数组进行排序。 

排序很重要，因为二分搜索仅适用于有序数据。 排序后，所有满足范围条件的值都会变得连续。 
2. 初始化变量`count`存储公平对的总数。 
3. 迭代每个索引`i`从`0`到`n - 1`。 

对于每个元素`nums[i]`，我们想要确定后面有多少元素可以与其形成有效对。 
4. 计算允许的最小合作伙伴值。 

该对必须满足：$nums[j] \ge lower - nums[i]$因此，我们对第一个满足条件的索引进行二分搜索。 
5. 计算允许的最大合作伙伴值。 

该对还必须满足：$nums[j] \le upper - nums[i]$我们对值大于此限制的第一个索引进行二分搜索。 
6. 将搜索限制为以下索引`i`。 

由于问题需要`i < j`，我们只在范围内搜索`[i + 1, n)`。 
7. 将有效索引的数量添加到答案中。 

如果：```
left = first valid index
right = first invalid index
```那么有效伙伴的数量为：```
right - left
```8. 继续，直到处理完所有索引。 
9. 返回总计数。 

### 为什么它有效

 排序后，所有满足数值范围的值都连续出现。 对于每个固定`nums[i]`，有效的伙伴值在排序数组中形成连续的区间。 二分查找正确地找到了这个区间的边界，减去两个边界就得到了有效伙伴的确切数量。 由于每对都被计算一次`i < j`，最终结果是正确的。 

## Python 解决方案```python
from bisect import bisect_left, bisect_right
from typing import List

class Solution:
    def countFairPairs(self, nums: List[int], lower: int, upper: int) -> int:
        nums.sort()
        n = len(nums)

        fair_pairs = 0

        for i in range(n):
            min_value = lower - nums[i]
            max_value = upper - nums[i]

            left = bisect_left(nums, min_value, i + 1)
            right = bisect_right(nums, max_value, i + 1)

            fair_pairs += right - left

        return fair_pairs
```实现首先对数组进行排序。 这使得有效的合作伙伴范围的二进制搜索成为可能。 

对于每个索引`i`，代码计算可以配对的最小和最大值`nums[i]`同时保持在目标总和范围内。`bisect_left`找到第一个有效位置，其中元素至少`min_value`。`bisect_right`查找所有小于或等于的元素之后的第一个位置`max_value`。 

这两个索引之间的差异给出了当前元素的有效伙伴的数量。 

搜索开始于`i + 1`以确保仅与`i < j`are counted.

 最后，所有计数都被累加并返回。 

## 解决方案```go
package main

import (
	"sort"
)

func countFairPairs(nums []int, lower int, upper int) int64 {
	sort.Ints(nums)

	n := len(nums)
	var fairPairs int64 = 0

	for i := 0; i < n; i++ {
		minValue := lower - nums[i]
		maxValue := upper - nums[i]

		left := sort.Search(n, func(j int) bool {
			return j > i && nums[j] >= minValue
		})

		right := sort.Search(n, func(j int) bool {
			return j > i && nums[j] > maxValue
		})

		fairPairs += int64(right - left)
	}

	return fairPairs
}
```Go 解决方案遵循与 Python 版本相同的算法思想。`sort.Ints`对数组进行就地排序。 

Go 不提供内置的`bisect_left`和`bisect_right`，所以我们使用`sort.Search`实现等效的二分搜索。 

答案存储在`int64`因为对的数量可能超出 32 位整数的范围。 在最坏的情况下，对的数量大约为`5 * 10^9`。 

与 Python 整数不同，Go 整数具有固定大小，因此显式溢出处理非常重要。

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n log n) | O(n log n) | 排序成本 O(n log n)，每次迭代执行二分搜索 |

 主要成本是对数组进行排序。 

排序后，每一个`n`迭代执行两次二分搜索，每次都会花费`O(log n)`时间。 

因此，总复杂度为：$O(n \log n)$除了排序数组本身之外，该算法仅使用一些额外的变量。 Python的排序实现可能在内部使用辅助堆栈空间，这就是为什么一些分析报告`O(log n)`辅助空间。

    def countFairPairs(self, nums: List[int], lower: int, upper: int) -> int:
        from bisect import bisect_left, bisect_right

        total = 0

 ## 边缘情况

 一种重要的边缘情况是元素少于两个的数组。 由于一对需要两个不同的索引，因此不能存在有效的对。 该实现自然地处理了这个问题，因为二分搜索开始于`i + 1`，所以没有找到匹配项。 

另一个重要的情况涉及重复值。 例如，`[1,1,1]`与目标总和`2`包含三个有效对。 有缺陷的实现可能会意外地计算唯一值而不是唯一索引对。 该解决方案在排序后对索引范围进行计数，因此正确包含每个有效的索引组合。 

负数也很重要，因为排序和范围计算必须在正值和负值上正确工作。 例如，与`nums = [-3,-2,-1]`，有效总和可能仍落在目标范围内。 二分搜索逻辑工作正常，因为它仅取决于排序顺序，而不取决于值符号。 

最后一个重要的边缘情况涉及非常大的整数。 由于值可以大到`10^9`，对和可能达到`2 * 10^9`。 在 Go 中，有效对的总数可以超过 32 位整数限制，因此实现将答案存储在`int64`以避免溢出。
