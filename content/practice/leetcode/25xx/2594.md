[LeetCode 问题 2594](https://leetcode.com/problems/minimum-time-to-repair-cars/)

 **难度：** 🟡 中等
 **主题：** 数组、二分查找

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个机械师列表，其中每个机械师都有特定的等级。 有等级的机械师`r`需要`r * n^2`分钟修复`n`汽车。 这意味着随着分配的汽车数量的增加，维修时间呈二次方增长。 

我们还得到一个整数`cars`，代表必须维修的汽车总数。 所有机械师同时工作，因此总完成时间由分配的工作负载中最慢的机械师决定。 

目标是确定所有汽车都能集体维修所需的最短时间。 

为了更好地理解这个公式，考虑一个具有等级的机械师`2`：

 - 修理 1 辆车需要`2 * 1^2 = 2`- 修理 2 辆车需要`2 * 2^2 = 8`- 修理 3 辆车需要`2 * 3^2 = 18`重要的观察是，在固定的时间内`T`，我们可以通过解决以下问题来确定机械师可以修理多少辆汽车：$$r \cdot n^2 \le T$$重新排列：$$n^2 \le \frac{T}{r}$$

$$n \le \sqrt{\frac{T}{r}}$$所以一个有等级的机械师`r`最多可修复：$$\left\lfloor \sqrt{\frac{T}{r}} \right\rfloor$$时间内的汽车`T`。 

限制条件很大：

 - 最多`10^5`力学
 - 最多`10^6`汽车

 这些限制立即排除了基于模拟的解决方案或详尽的搜索方法。 我们需要更高效的东西。 

一些边缘情况很重要：

 - 只有一名机械师存在
 - 只有一辆车存在
 - 所有机械师都有相同的等级
 - 一名机械师比其他机械师快得多
 - 最优答案可能会变得很大，所以Go中必须考虑整数溢出

 该问题保证：

 - 至少存在一名机械师
 - 所有排名均为正数
 - 至少存在一辆车

 这意味着我们永远不需要处理无效或空的输入。 

## 方法

 ### 蛮力方法

 一种幼稚的方法是逐分钟地模拟时间，并检查每个时刻可以修理多少辆汽车。 

对于每一次`t`，我们可以计算：$$\sum \left\lfloor \sqrt{\frac{t}{r_i}} \right\rfloor$$如果修理车辆总数达到或超过`cars`， 然后`t`是一个有效的答案。 

虽然这种方法在概念上很简单，但迭代每个可能的时间值太慢。 最大可能的答案可能变得非常大。 例如，如果一名机械师的等级为`100`修理`10^6`汽车：$$100 \cdot (10^6)^2 = 10^{14}$$检查每个时间值最多`10^{14}`是不可行的。 

### 关键见解

 关键的观察是答案空间是单调的。 

如果可以及时修复所有车辆`T`，那么在任何更长的时间内也是可能的。 

同样：

 - 如果时间`T`不足，所有较小的时代也不足。 
- 如果时间`T`有效，所有更大的时间也有效。 

这种单调属性使二分查找成为理想的选择。 

我们不是线性搜索所有时间，而是对答案空间进行二分搜索。 

对于候选人时间`mid`，我们计算所有机械师总共可以修理多少辆汽车：$$\sum \left\lfloor \sqrt{\frac{mid}{r_i}} \right\rfloor$$如果总数至少为`cars`， 然后`mid`是可行的，我们尝试较小的次数。 

否则，我们需要更多时间。 

这将问题从巨大的线性搜索减少为对数搜索。

 | ---| ---| ---| ---|
 | 蛮力 | O(最大时间 × n) | O(1) | O(1) | 检查每个可能的时间值 |

 ## 算法演练

 ### 最优二分查找算法

 1. 初始化搜索边界。 

最短可能的时间是`1`。 

当最快的机械师单独修理所有汽车时，就会出现最大可能的时间。 

如果最低等级是`minRank`， 然后：$$maxTime = minRank \cdot cars^2$$2. 在范围内开始二分查找`[left, right]`。 

在每次迭代时：$$mid = \frac{left + right}{2}$$3. 计算时间内可以修理多少辆汽车`mid`分钟。 

对于每个有等级的机械师`r`：$$repaired = \left\lfloor \sqrt{\frac{mid}{r}} \right\rfloor$$将所有修理过的汽车加在一起。 
4. 检查可行性。 

- 如果修理的汽车总数至少为`cars`， 然后`mid`就足够了。 
- 将其存储为候选答案并继续搜索左半部分。 
- 否则，搜索右半部分。 
5. 继续直到`left > right`。 
6. 返回找到的最小可行时间。 

### 为什么它有效

 二分搜索之所以有效，是因为可行性是单调的。 

如果机械师可以及时修复所有汽车`T`，那么给他们更多的时间并不能减少他们的能力。 因此，所有较大的时间也是可行的。 

这保证了从不可行值到可行值的干净过渡点，这正是二分搜索所需的条件。 

## Python 解决方案```python
from typing import List
import math

class Solution:
    def repairCars(self, ranks: List[int], cars: int) -> int:
        left = 1
        right = min(ranks) * cars * cars

        answer = right

        while left <= right:
            mid = (left + right) // 2

            repaired_cars = 0

            for rank in ranks:
                repaired_cars += math.isqrt(mid // rank)

            if repaired_cars >= cars:
                answer = mid
                right = mid - 1
            else:
                left = mid + 1

        return answer
```实现首先定义二分搜索边界。 

下界是`1`，而上限假设最快的机械师单独修理每辆车。 

在二分搜索循环内，中点表示候选修复时间。 

对于每个机械师，我们计算：$$\left\lfloor \sqrt{\frac{mid}{rank}} \right\rfloor$$蟒蛇的`math.isqrt()`使用它是因为它可以有效地执行整数平方根并避免浮点精度问题。 

如果修复的汽车总数达到或超过了所需的汽车数量，则当前时间是可行的，因此我们尝试找到更小的有效时间。 

否则，我们会增加搜索范围。 

最终的答案是在搜索过程中发现的最小可行时间。 

## 解决方案```go
package main

import "math"

func repairCars(ranks []int, cars int) int64 {
	left := int64(1)

	minRank := ranks[0]
	for _, rank := range ranks {
		if rank < minRank {
			minRank = rank
		}
	}

	right := int64(minRank) * int64(cars) * int64(cars)

	answer := right

	for left <= right {
		mid := left + (right-left)/2

		repairedCars := int64(0)

		for _, rank := range ranks {
			repairedCars += int64(math.Sqrt(float64(mid / int64(rank))))
		}

		if repairedCars >= int64(cars) {
			answer = mid
			right = mid - 1
		} else {
			left = mid + 1
		}
	}

	return answer
}
```Go 实现遵循与 Python 版本相同的二分搜索逻辑。 

一个重要的区别是整数溢出处理。 由于上限可以达到`10^14`，所有与时间相关的变量都使用`int64`。 

Go 没有提供与 Python 等效的整数平方根函数`math.isqrt`， 所以`math.Sqrt`与浮点转换一起使用。 结果被转换回`int64`。 

中点计算使用：```go
mid := left + (right-left)/2
```这避免了可能发生的溢出`(left + right) / 2`。

 | ---| ---| ---|

 二分查找范围扩展到：$$minRank \cdot cars^2$$由于二分搜索每次迭代将搜索空间减半，因此迭代次数为：$$O(\log(maxTime))$$对于每次迭代，我们都会遍历所有机制一次。 

因此，总复杂度变为：$$O(n \log(maxTime))$$无论输入大小如何，该算法仅使用几个变量，因此空间复杂度是恒定的。

 ## 边缘情况

 ### 单一机械师

 如果只有一名机械师，则该机械师必须单独修理每辆车。 

例如：```
ranks = [2]
cars = 5
```答案变成：$$2 \cdot 5^2 = 50$$幼稚的实现可能会错误地假设工作总是可以分配的。 我们的解决方案可以自然地处理这个问题，因为即使只有一名机械师，可行性计算也能正确工作。 

### 极大的答案空间

 最大可能的答案可能非常大：$$100 \cdot (10^6)^2 = 10^{14}$$这可能会溢出 32 位整数。 

Go 实现使用`int64`到处进行时间计算以避免溢出错误。 

### 一名机械师比其他机械师快得多

 考虑：```
ranks = [1,100,100]
cars = 10
```有等级的机械师`1`几乎完成所有工作。 

一些贪婪的方法可能会错误地尝试在机械师之间均匀分配汽车。 这不会产生最佳答案。 

我们的二分搜索解决方案完全避免了显式分配。 它仅检查给定时间内的总修复能力，这会自动考虑不平等的工作负载。 

### 完美的方形边界

 该公式涉及平方根，可能会引入相差一的误差。 

例如：```
mid = 16
rank = 1
```

$$\sqrt{16} = 4$$机械师正好可以修理 4 辆车。 

不小心使用浮点运算可能会错误地产生`3.999999`。 Python 避免了这个问题`math.isqrt`，Go 安全地截断结果`math.Sqrt`。
