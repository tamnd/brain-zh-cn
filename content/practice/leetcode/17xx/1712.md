[LeetCode 问题 1712](https://leetcode.com/problems/ways-to-split-array-into- Three-subarrays/)

 **难度：** 🟡 中等
 **主题：** 数组、两个指针、二分查找、前缀和

 ## 解决方案

 ## 问题理解

 该问题要求我们计算将数组分为三个连续的非空部分的有效方法的数量：

 -`left`-`mid`-`right`分割必须满足两个条件：

 1.`sum(left) <= sum(mid)`2.`sum(mid) <= sum(right)`该数组仅包含非负整数，这是一个极其重要的属性，因为前缀和变得单调。 这种单调行为允许二分搜索或两个指针技术有效地工作。 

通过选择两个剪切位置来定义分割：

 - 第一个切口分开`left`和`mid`- 第二次切割分离`mid`和`right`如果数组长度是`n`， 然后：

-`left`使用索引`[0 ... i]`-`mid`使用索引`[i+1 ... j]`-`right`使用索引`[j+1 ... n-1]`所有三个子数组必须至少包含一个元素，因此：

 -`i >= 0`-`j > i`-`j < n - 1`限制条件很大：

 -`n`可以达到`10^5`这立即告诉我们三次或二次枚举不够快。 我们需要一些接近的东西`O(n log n)`或者`O(n)`。 

因为所有数字都是非负数，所以前缀和是非递减的。 这是能够有效搜索有效分割范围的关键观察结果。 

一些重要的边缘情况包括：

 - 不存在有效分割的数组
 - 包含许多零的数组
 - 每个分割都有效的数组
 - 长度非常小的数组`3`- 大型数组，暴力破解会超时

 该问题保证非负整数，这对于最优解所使用的单调行为至关重要。 

## 方法

 ### 蛮力方法

 最直接的解决方案是尝试每对可能的分割点。 

对于每一个可能的第一次切割`i`，我们尝试一切可能的第二次切割`j`，然后计算：

 -`leftSum`-`midSum`-`rightSum`如果两个要求的不等式都成立，我们就增加答案。 

使用前缀和，每个范围和可以计算为`O(1)`，但仍有`O(n^2)`可能的分裂对。 

和`n = 10^5`，这变得太慢了，因为：```
10^5 * 10^5 = 10^10
```操作是不可行的。 

### 最佳方法

 关键的见解是对于固定的`left`子数组，有效范围`mid`边界形成连续的区间。 

由于所有数字都是非负数：

 - 前缀和按非降序排序
 - 增加第二次切割增加`midSum`- 增加第二次切割减少`rightSum`这创建了可以有效搜索的单调条件。 

对于每个第一个分割位置`i`，我们想要找到：

 - 最小的`j`在哪里`midSum >= leftSum`- 最大的`j`在哪里`midSum <= rightSum`这两个边界之间的所有索引都是有效的。 

我们可以使用前缀和数组上的二分搜索有效地找到这些边界。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 尝试每一对分体位置 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 使用前缀和进行二分搜索 |

 ## 算法演练

 ### 第 1 步：构建前缀和

 创建一个前缀和数组，其中：```
prefix[i] = sum(nums[0...i])
```这允许常数时间子数组和计算。 

例如：```
nums = [1,2,2,2,5,0]

prefix = [1,3,5,7,12,12]
```### 步骤 2：迭代第一个分割

 选择结束索引`i`的`left`子数组。 

由于所有三个子数组都必须非空：```sql
i ranges from 0 to n - 3
```对于每个`i`：```
leftSum = prefix[i]
```### 步骤 3：找到最小有效第二分割

 我们需要：```
midSum >= leftSum
```使用前缀和：```
prefix[j] - prefix[i] >= prefix[i]
```重新排列：```
prefix[j] >= 2 * prefix[i]
```我们二分查找第一个索引`j`满足这个条件。 

### 步骤 4：找到最大有效第二分割

 我们还需要：```
midSum <= rightSum
```使用前缀和：```
prefix[j] - prefix[i] <= totalSum - prefix[j]
```重新排列：```
2 * prefix[j] <= totalSum + prefix[i]
```我们二分查找最后一个索引`j`满足这个条件。 

### 步骤 5：计算有效分割数

 如果：```
leftBound <= rightBound
```那么有效分割数为：```
rightBound - leftBound + 1
```将其添加到答案模中`10^9 + 7`。 

### 为什么它有效

 对于固定的`left`边界，条件为`mid`产生连续的有效范围，因为前缀和是单调的。 

- 一次`midSum >= leftSum`成为事实，它仍然是事实
 - 一次`midSum > rightSum`为真，之后仍然无效

 因此，所有有效的第二分割位置都位于一个连续区间内，二分查找可以有效地定位。 

## Python 解决方案```python
from bisect import bisect_left, bisect_right
from typing import List

class Solution:
    def waysToSplit(self, nums: List[int]) -> int:
        MOD = 10**9 + 7
        n = len(nums)

        prefix = [0] * n
        prefix[0] = nums[0]

        for i in range(1, n):
            prefix[i] = prefix[i - 1] + nums[i]

        total_sum = prefix[-1]
        answer = 0

        for i in range(n - 2):
            left_sum = prefix[i]

            min_j = bisect_left(prefix, 2 * left_sum, i + 1, n - 1)

            max_target = (total_sum + left_sum) // 2
            max_j = bisect_right(prefix, max_target, min_j, n - 1) - 1

            if min_j <= max_j:
                answer += (max_j - min_j + 1)

        return answer % MOD
```实现首先构建前缀和数组。 这允许使用简单的算术而不是重复求和范围来表示每个子数组和。 

该循环遍历每个可能的结束索引`left`子数组。 对于每一个，该算法都会计算第二次分割的最小和最大有效位置。`bisect_left`用于查找第一个有效的`j`在哪里：```python
prefix[j] >= 2 * left_sum
```这可以确保：```python
midSum >= leftSum
```下一个，`bisect_right`找到最大的有效值`j`满意：```python
2 * prefix[j] <= total_sum + left_sum
```该范围内的每个索引都会产生有效的分割，因此算法将间隔的大小添加到答案中。 

最后返回结果取模`10^9 + 7`。 

## 解决方案```go
package main

import "sort"

func waysToSplit(nums []int) int {
	const MOD int = 1e9 + 7

	n := len(nums)

	prefix := make([]int, n)
	prefix[0] = nums[0]

	for i := 1; i < n; i++ {
		prefix[i] = prefix[i-1] + nums[i]
	}

	totalSum := prefix[n-1]
	answer := 0

	for i := 0; i < n-2; i++ {
		leftSum := prefix[i]

		minJ := sort.Search(n-1-(i+1), func(k int) bool {
			j := k + i + 1
			return prefix[j] >= 2*leftSum
		}) + i + 1

		maxTarget := (totalSum + leftSum) / 2

		maxJ := sort.Search(n-1-minJ, func(k int) bool {
			j := k + minJ
			return prefix[j] > maxTarget
		}) + minJ - 1

		if minJ <= maxJ {
			answer = (answer + (maxJ - minJ + 1)) % MOD
		}
	}

	return answer
}
```Go 实现遵循与 Python 版本相同的算法结构。 

由于 Go 不像 Python 那样提供内置的二等分实用程序，因此该解决方案使用`sort.Search`实现二分搜索行为。 

整数算术是安全的，因为约束将前缀和保持在 Go 的范围内`int`在现代平台上输入。 

切片用于前缀和数组，所有计算都保持迭代，没有递归。

 ## 边缘情况

 一种重要的边缘情况是所有值都为零。 在这种情况下，每个子数组的总和为零，因此两个不等式始终成立。 幼稚的实现可能会意外地错过有效范围，因为许多前缀和是相同的。 基于二分搜索的解决方案可以正确处理此问题，因为它在非递减前缀和上搜索包含范围。 

当第一部分变得太大时，会出现另一个严重情况。 例如：```
[5,0,0,0,0]
```一次`leftSum`超出了剩余数组可以支持的范围，没有有效的第二个分割位置。 二分搜索自然会返回一个空区间，并且实现正确地将零添加到答案中。 

第三个重要的边缘情况是尽可能最小的数组长度：```
n = 3
```确切地说，只有一种可能的拆分配置。 不正确的边界处理可能会意外地允许空子数组或产生超出范围的二分搜索间隔。 该实现通过仅迭代直到`n - 2`并限制第二次分割发生在最终元素之前。 

另一个微妙的情况涉及由数组内的零引起的重复前缀和。 由于多个有效的分割位置可能共享相同的前缀和值，因此使用以下命令很重要：

 -`bisect_left`对于第一个有效索引
 -`bisect_right`对于最后一个有效索引

 使用错误的二分搜索变体可能会少算或多算有效的分割。
