 # LeetCode 1761 - 图中连通三重奏的最小度

 ## 问题理解

 这个问题给了我们一个无向图`n`节点和边列表。 连接的三重奏是一组恰好三个不同的节点，其中每对节点之间都有一条边。 用图论术语来说，这只是一个三角形。 

该问题要求我们找到图中所有相连三元组之间的最小度数。 

三元组的度数与标准图节点的度数不同。 相反，它表示将三元组内部的节点连接到三元组外部的节点的边的数量。 

假设我们有一个三人组`(a, b, c)`。 每个节点都有自己的图度：

 -`degree[a]`-`degree[b]`-`degree[c]`如果我们将它们加在一起，则三个内部三重边将被计数两次，因为该图是无向的：

 - 边缘`(a, b)`- 边缘`(a, c)`- 边缘`(b, c)`其中每一个都为总度数贡献两个计数，因此内部三边贡献`6`总计数。 

因此，三重奏的度为：$\text{trio degree} = degree[a] + degree[b] + degree[c] - 6$输入包括：

 -`n`，标记的节点数`1`到`n`-`edges`，其中每条边连接两个节点

 输出应该是：

 - 所有有效连接三重奏中的最小三重奏度数
 -`-1`如果图表根本不包含连接的三重奏

 约束条件很重要：

 -`n <= 400`- 该图可以很密集，可能包含几乎所有可能的边

 自从`n`只有400，一个`O(n^3)`解决方案是可以接受的，因为：$400^3 = 64,000,000$这是很大的，但在优化的实现中仍然可以管理。 

一些边缘情况很重要：

 - 图表可能根本不包含三角形
 - 该图可能包含许多重叠的三重奏
 - 有些三人组可能有学位`0`，意味着没有外部连接
 - 密集图可以产生许多候选三重奏，因此重复昂贵的邻接检查可能会出现问题
 - 由于图是无向的，邻接表示必须支持对称查找

 该问题保证：

 - 没有重复的边缘
 - 无自循环
 - 有效节点索引

 这些保证大大简化了实施。 

## 方法

 ### 蛮力方法

 最直接的解决方案是枚举每个可能的三个节点集合，并检查它们是否形成一个连接的三重奏。 

对于每一个三元组`(a, b, c)`：

 1. 检查是否：

 -`(a, b)`存在
 -`(a, c)`存在
 -`(b, c)`存在
 2. 如果所有三个边都存在，则计算三重度。 

为了简单地计算三重奏的度数，我们可以扫描每条边并计算有多少条边将三重奏连接到外部节点。 

这种方法是正确的，因为它明确地检查每个可能的三重奏并计算其准确的度数。 然而，它变得低效，因为：

 - 有`O(n^3)`可能的三元组
 - 度数计算可能需要`O(E)`每三人组的时间

 这导致：$O(n^3 \cdot E)$在密集图中：$E = O(n^2)$总复杂度变为：$O(n^5)$这太慢了。 

### 最佳方法

 关键的观察是，一旦我们知道三个节点形成一个三重奏，我们就可以立即使用节点度来计算三重奏的度数。 

如果节点`(a, b, c)`形成一个三角形：

 - 每个节点贡献其所有关联边
 - 三重奏的内部边缘被计算两次
 - 正好有 3 个内部边缘

 所以我们减去`6`从总度数总和。 

这消除了昂贵的边缘扫描步骤。 

我们还使用邻接矩阵或邻接集进行恒定时间边缘存在检查。 

结果算法：

 1. 建立邻接表示
 2.计算每个节点的度
 3. 枚举三元组`(a, b, c)`4. 检查它们是否形成三角形
 5. 计算：`degree[a] + degree[b] + degree[c] - 6`6. 追踪最小值

 这将复杂性降低到：$O(n^3)$这是可以接受的`n <= 400`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n^3 * E) | O(n^3 * E) | O(E) | 枚举所有三元组并重新扫描边缘 |
 | 最佳 | O(n^3) | O(n^3) | O(n^2) | O(n^2) | 使用邻接矩阵和度计数 |

 ## 算法演练

 ### 第 1 步：构建邻接矩阵

 创建二维布尔矩阵`connected`在哪里：

-`connected[u][v] = True`-`connected[v][u] = True`这允许恒定时间边缘存在检查。 

我们选择邻接矩阵是因为：

 -`n`够小，只有400
 - 边缘查找速度至关重要
 -`O(1)`邻接检查比搜索邻接列表更快

 ### 步骤 2：计算节点度数

 创建一个数组`degree`。 

对于每一个边缘`(u, v)`：

 - 增量`degree[u]`- 增量`degree[v]`这存储每个节点的关联边总数。 

### 步骤 3：枚举所有可能的三重奏

 使用三个嵌套循环：

 1.`a`从`1`到`n`2.`b`从`a + 1`到`n`3.`c`从`b + 1`到`n`这保证了每个无序三元组都被恰好处理一次。 

### 步骤 4：检查三元组是否构成三元组

 有效的三重奏需要所有三个成对边：

 -`(a, b)`-`(a, c)`-`(b, c)`所以检查一下：```
connected[a][b] and connected[a][c] and connected[b][c]
```如果缺少任何边，则跳过三元组。 

### 步骤 5：计算三重度

 对于有效的三重奏：```
trio_degree = degree[a] + degree[b] + degree[c] - 6
```我们减去`6`因为：

 - 每个内部边缘贡献两个度数
 - 有三个内部边缘

 ### 第 6 步：跟踪最低答案

 维护一个变量`minimum_degree`。 

每当发现较小的三度数时就更新它。 

###第七步：返回结果

 如果没有找到三人组，则返回`-1`。 

否则返回最小度数。 

### 为什么它有效

 该算法对每个可能的三重奏恰好检查一次，因此不会错过任何有效的连接三重奏。 

邻接矩阵保证了准确检测三个节点是否构成完整三角形。 

三重度公式是正确的，因为节点度计算所有关联边，包括内部三重边。 由于三个内部边缘总共计数了两次，因此减去`6`删除这些内部贡献，只留下将三个节点连接到外部节点的边。 

因此，该算法始终计算出正确的最小三重度。 

## Python 解决方案```python
from typing import List

class Solution:
    def minTrioDegree(self, n: int, edges: List[List[int]]) -> int:
        connected = [[False] * (n + 1) for _ in range(n + 1)]
        degree = [0] * (n + 1)

        for u, v in edges:
            connected[u][v] = True
            connected[v][u] = True

            degree[u] += 1
            degree[v] += 1

        minimum_degree = float("inf")

        for a in range(1, n + 1):
            for b in range(a + 1, n + 1):
                if not connected[a][b]:
                    continue

                for c in range(b + 1, n + 1):
                    if (
                        connected[a][c]
                        and connected[b][c]
                    ):
                        trio_degree = (
                            degree[a]
                            + degree[b]
                            + degree[c]
                            - 6
                        )

                        minimum_degree = min(
                            minimum_degree,
                            trio_degree
                        )

        return -1 if minimum_degree == float("inf") else minimum_degree
```实现首先构建邻接矩阵并同时计算节点度。 每个无向边更新矩阵中的两个方向并增加两个端点度数。 

三元组嵌套循环枚举所有唯一的节点三元组。 优化：```python
if not connected[a][b]:
    continue
```避免尽早对许多无效三元组进行不必要的检查。 

一旦识别出有效的三重奏，就会立即应用度数公式。 该算法连续跟踪遇到的最小三度数。 

最后，如果不存在三重奏，则答案仍为无穷大，并且函数返回`-1`。 

## 解决方案```go
func minTrioDegree(n int, edges [][]int) int {
    connected := make([][]bool, n+1)
    for i := range connected {
        connected[i] = make([]bool, n+1)
    }

    degree := make([]int, n+1)

    for _, edge := range edges {
        u := edge[0]
        v := edge[1]

        connected[u][v] = true
        connected[v][u] = true

        degree[u]++
        degree[v]++
    }

    const INF = int(1e9)
    minimumDegree := INF

    for a := 1; a <= n; a++ {
        for b := a + 1; b <= n; b++ {
            if !connected[a][b] {
                continue
            }

            for c := b + 1; c <= n; c++ {
                if connected[a][c] && connected[b][c] {
                    trioDegree := degree[a] + degree[b] + degree[c] - 6

                    if trioDegree < minimumDegree {
                        minimumDegree = trioDegree
                    }
                }
            }
        }
    }

    if minimumDegree == INF {
        return -1
    }

    return minimumDegree
}
```Go 实现密切反映了 Python 逻辑。 

Go 对邻接矩阵和度数组都使用切片。 由于 Go 没有为整数提供无穷大常数，因此较大的哨兵值`INF`被用来代替。 

因为所有计算都保持在整数限制内`n <= 400`，整数溢出不是问题。

 ## 边缘情况

 ### 没有连接三重奏的图

 一个图可能包含许多边而不包含任何三角形。 例如，简单的链或树结构不包含连接的三元组。 

有缺陷的实现可能会错误地假设至少存在一个三重奏并返回无效值。 该解决方案通过将答案初始化为无穷大并返回来避免该问题`-1`如果没有找到三人组。 

### 零度三重奏

 三人组可以完全没有外部连接。 当图仅由三个三元组节点组成或当三元组与图的其余部分隔离时，就会发生这种情况。 

这种情况很重要，因为一些不正确的实现会意外地将内部边缘计为外部边缘。 的减法`6`正确地消除内部贡献并产生程度`0`。 

### 密集图

 该图可能接近完整，这意味着几乎每个节点对都是连接的。 

在密集图中，邻接查找极其频繁地发生。 使用邻接表进行线性搜索会使算法太慢。 邻接矩阵保证边存在检查的时间恒定，并将总运行时间保持在可接受的范围内。 

### 重叠的三重奏

 不同的三元组可以共享节点和边。 

例如：```
(1,2,3)
(2,3,4)
```有缺陷的实现可能会重复计数或错误地跳过重叠结构。 由于该解决方案独立检查每个唯一的节点三元组，因此可以自然且正确地处理重叠的三元组。
