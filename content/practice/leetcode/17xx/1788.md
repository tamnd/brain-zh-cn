[LeetCode 第 1788 题](https://leetcode.com/problems/maximize-the-beauty-of-the-garden/)

 **难度：** 🔴难
 **主题：** 数组、哈希表、贪婪、前缀和

 ## 解决方案

 ## 问题理解

 我们得到一个整数数组`flowers`，其中每个元素代表一行中一朵花的美丽值。 我们可以移除任何我们想要的花朵，同时保留剩余花朵的相对顺序。 拆除后，剩余的序列必须形成一个有效的花园。 

一个有效的花园必须满足两个条件：

 1. 至少包含两朵花。 
2.第一朵花和最后一朵花具有相同的美丽价值。 

花园的美丽只是所有剩余花朵的总和。 

任务是最大化这个总和。 

重要的细节是我们不需要保留连续的子数组。 我们可以删除所选端点之间的任意花。 但是，剩下的第一朵花和最后一朵花必须具有相同的值。 

假设我们选择两个位置`i`和`j`这样：

 -`i < j`-`flowers[i] == flowers[j]`这两朵花成为有效花园的边界。 它们之间的任何花都可以保留或移除。 

现在考虑室内花卉：

 - 如果它的价值是正数，保留它会增加整体的美感。 
- 如果它的值为负数，则将其删除会增加整体美感。 
- 如果它的值为零，保留或删除它并不重要。 

这一观察结果是最优解决方案的关键。 

限制条件很大：

 -`n`可以达到`10^5`这立即排除了二次或三次强力解。 我们需要接近线性时间的东西。 

一些边缘情况很重要：

 - 所有值都可能为负值。 
- 最佳花园可能只包含两朵边界花。 
- 多个相等的值可能会出现多次。 
- 通常应删除内部负值。 
- 必须正确处理零值。 
- 答案本身可能是否定的。 

该问题保证至少可以形成一个有效的花园。 

## 方法

 ### 蛮力方法

 最直接的方法是尝试每对索引`(i, j)`这样：

 -`i < j`-`flowers[i] == flowers[j]`对于每一对有效的花，我们使用这两朵花作为边界来确定最好的花园。 

由于我们可能会移除任何室内花卉，因此最佳选择是：

 - 保留所有积极的花朵`i`和`j`- 删除之间的所有负面花朵`i`和`j`- 边界花必须始终保留

 因此，一对的美丽`(i, j)`变成：```
flowers[i] + flowers[j] + sum(max(0, flowers[k])) for i < k < j
```我们可以通过每次扫描间隔来计算这个总和。 

这是正确的，因为每个可能的有效花园都对应于一些等值的边界对。 

然而，复杂性太大。 

- 有`O(n^2)`对。 
- 每对可能需要`O(n)`工作。 

这导致`O(n^3)`最坏情况下的时间。 

即使使用前缀和将间隔计算减少到`O(1)`，检查所有对仍然需要花费`O(n^2)`，这对于`10^5`元素。 

### 关键见解

 关键的观察是，只有积极的内在价值观才重要。 

对于一对相等的边界花：```
beauty = boundary_value * 2 + sum_of_positive_values_between
```我们可以使用前缀和重写它。 

定义：```sql
positive_prefix[i] = sum of positive values from index 0 to i-1
```然后：```
sum_of_positive_values_between(i, j)
= positive_prefix[j] - positive_prefix[i + 1]
```重新整理一下公式：```
beauty
= flowers[i] + flowers[j]
  + positive_prefix[j]
  - positive_prefix[i + 1]
```自从`flowers[i] == flowers[j]`，令共同值为`x`。 

然后：```
beauty
= positive_prefix[j] + x
  + (x - positive_prefix[i + 1])
```对于每个职位`j`，我们想要最好的早期匹配位置`i`。 

这意味着对于每朵花的价值`x`，我们应该保持最大可能的值：```
x - positive_prefix[i + 1]
```这将问题转化为带有哈希图的线性扫描。

 ## 算法演练

 1. 初始化一个运行前缀和，称为`positive_sum`。 

该变量存储迄今为止遇到的所有正花值的总数。 负值被忽略，因为它们永远不会被保留在最佳花园内。 
2. 创建一个名为的哈希图`best_start`。 

对于每朵花的价值`x`，该映射存储以下最大值：```
x - positive_prefix[i + 1]
```这代表了迄今为止所看到的最佳可能的左边界价值`x`。 
3. 将答案初始化为负无穷大。 

由于所有数字都可能为负数，因此最大美感也可能为负数。 
4. 从左到右迭代数组。 

在每个位置`j`有价值`x`:

 - 首先检查我们之前是否已经看到过相同的值。 
- 如果是，计算：```
candidate = positive_sum + best_start[x]
```这完全对应于：```
flowers[i] + flowers[j]
+ sum_of_positive_values_between
```如果该候选人更大，请更新答案。 
5. 计算未来匹配所需的值。 

处理完当前索引后，计算：```
current = x - new_positive_sum
```在哪里`new_positive_sum`如果是正数，则包括当前的花。 

该值代表：```
x - positive_prefix[i + 1]
```6. 存储该花型的最佳值。 

如果之前没有出现过该花值，则将其插入。 

否则，保留最大值。 
7. 继续直到数组末尾。 
8. 返回找到的最大答案。 

### 为什么它有效

 对于每个有效的花园，端点必须相等。 一旦端点固定，最优策略就确定了：

 - 保留每一朵积极的室内花卉。 
- 去除所有负面的室内花朵。 

该算法通过将区间计算转换为前缀和表达式来有效地评估每个可能的等值端点对。 哈希映射保证对于每个右端点，我们立即检索最佳兼容的左端点。 由于每个有效对都会被考虑一次，因此该算法总是能找到最佳的美感。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def maximumBeauty(self, flowers: List[int]) -> int:
        best_start = {}
        
        positive_sum = 0
        answer = float("-inf")
        
        for flower in flowers:
            if flower in best_start:
                answer = max(answer, positive_sum + best_start[flower])
            
            next_positive_sum = positive_sum + max(flower, 0)
            
            current_value = flower - next_positive_sum
            
            if flower in best_start:
                best_start[flower] = max(
                    best_start[flower],
                    current_value
                )
            else:
                best_start[flower] = current_value
            
            positive_sum = next_positive_sum
        
        return answer
```该实现在整个扫描过程中维护两条核心信息。 

变量`positive_sum`存储迄今为止遇到的所有正花的累积和。 这使我们能够立即计算正内部花朵的贡献，而无需重新扫描间隔。 

字典`best_start`追踪每朵美丽花朵的最佳转化价值。 具体来说，对于每朵花的值`x`，它存储以下最大值：```python
x - positive_prefix[i + 1]
```当我们遇到另一朵具有相同值的花时，我们立即计算在当前位置结束的最佳花园。 

更新的顺序很重要。 

我们首先尝试利用早期发生的事件来形成花园。 只有之后我们才会更新当前的花朵作为未来可能的起点。 

这可以防止意外使用相同的索引作为左边界和右边界。 

## 解决方案```go
package main

func maximumBeauty(flowers []int) int {
	bestStart := make(map[int]int)

	positiveSum := 0
	answer := -1 << 60

	for _, flower := range flowers {
		if val, exists := bestStart[flower]; exists {
			candidate := positiveSum + val
			if candidate > answer {
				answer = candidate
			}
		}

		nextPositiveSum := positiveSum
		if flower > 0 {
			nextPositiveSum += flower
		}

		currentValue := flower - nextPositiveSum

		if val, exists := bestStart[flower]; exists {
			if currentValue > val {
				bestStart[flower] = currentValue
			}
		} else {
			bestStart[flower] = currentValue
		}

		positiveSum = nextPositiveSum
	}

	return answer
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

一个显着的区别是整数初始化。 Go 没有内置的整数无穷大值，因此答案是用一个非常小的数字初始化的：```go
answer := -1 << 60
```哈希图是使用Go内置的实现的`map[int]int`。 

由于约束相对较小，标准`int`算术就足够了，溢出不是问题。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每朵花都被处理一次|

 该算法对数组执行一次从左到右的遍历。 每次哈希映射查找和更新都是预期的`O(1)`，所以整体运行时间是线性的。 

额外的空间来自于在哈希映射中为每个不同的花值存储一个条目。

 ## 边缘情况

 ### 所有值都是负数

 实现可能会错误地认为去除所有负面花朵总是有益的。 然而，边界花必须保留，即使它们是负面的。 

例如：```
[-1,-2,0,-1]
```唯一有效的花园是：```
[-1,-1]
```该算法可以正确处理这个问题，因为它永远不会删除边界花并允许最终答案保持否定。 

### 内部负值

 一个常见的错误是将问题视为连续子数组问题。 内部的花朵可以单独移除。 

例如：```
[10,-100,10]
```最佳花园是：```
[10,10]
```与美丽`20`。 

该算法自动忽略负的内部花，因为前缀和仅包含正值。 

###同一朵花多次出现

 当花值出现多次时，最佳左边界并不总是最早出现的。 

例如：```
[1,-2,1,5,1]
```使用第一个和最后一个`1`给出：```
1 + 5 + 1 = 7
```这比使用前两个更好`1`s。 

哈希图存储每种花类型的最佳变换起始值，确保算法始终选择最佳的较早出现的值。
