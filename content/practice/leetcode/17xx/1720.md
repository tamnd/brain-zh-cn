[LeetCode 第 1720 题](https://leetcode.com/problems/decode-xored-array/)

 **难度：** 🟢简单
 **主题：** 数组、位操作

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个编码数组，其中每个元素表示来自未知原始数组的两个连续元素的异或。 具体来说：```
encoded[i] = arr[i] XOR arr[i + 1]
```我们还给出了原始数组的第一个元素，`first = arr[0]`。 使用这两条信息，我们必须重建整个原始数组。 

关键的观察结果是 XOR 具有可逆属性。 如果：```
a XOR b = c
```然后：```
a XOR c = b
```这意味着如果我们已经知道原始数组中的一个值以及它与下一个值之间的异或结果，我们可以直接恢复下一个值。 

例如，假设：```
encoded = [1,2,3]
first = 1
```我们知道：```
arr[0] = 1
encoded[0] = arr[0] XOR arr[1] = 1
```所以：```
arr[1] = arr[0] XOR encoded[0]
       = 1 XOR 1
       = 0
```然后我们继续：```
arr[2] = arr[1] XOR encoded[1]
       = 0 XOR 2
       = 2
```等等。 

限制相对较小：

 -`2 <= n <= 10^4`-`0 <= encoded[i], first <= 10^5`这告诉我们，即使是`O(n)`解决方案足够快。 问题主要在于正确理解 XOR 行为，而不是针对大量输入大小进行优化。 

一个重要的保证是答案总是存在并且是唯一的。 这意味着只有一个有效的原始数组与所提供的输入相对应。 

一些可能导致错误的边缘情况包括：

 - 最小尺寸的数组，其中`encoded`仅包含一个值。 
- 值等于零，因为与零的异或使值保持不变。 
- 重复的数字，可能会产生零编码值。 
- 忘记输出数组有长度`encoded.length + 1`。 

## 方法

 ### 蛮力方法

 一种简单的暴力方法会尝试猜测原始数组的每个可能值，并检查它是否生成给定的编码数组。 

对于每个相邻对：```
arr[i] XOR arr[i + 1] == encoded[i]
```我们将验证猜测的数组是否满足所有约束。 

这种方法在技术上是正确的，因为它探索了所有可能性，但它是完全不切实际的。 每个数组元素可以大到`10^5`，这创造了巨大的搜索空间。 即使对于很小的输入，详尽的搜索也将变得不可行。 

蛮力法在概念上证明了正确性，但它忽略了异或的可逆性质。 

### 最佳方法

 最佳解决方案依赖于基本的 XOR 属性：```
a XOR b = c
```意味着：```
b = a XOR c
```由于数组的第一个元素是已知的，我们可以逐个重建剩余的元素。 

如果：```
encoded[i] = arr[i] XOR arr[i + 1]
```然后：```
arr[i + 1] = arr[i] XOR encoded[i]
```这使我们能够在一次传递中按顺序构建数组。 

由于每个元素只计算一次，因此该算法以线性时间运行。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(n) | 尝试所有可能的数组并验证它们 |
 | 最佳 | O(n) | O(n) | 使用 XOR 属性直接重建数组 |

 ## 算法演练

 1.创建结果数组并放置`first`作为第一个元素。 

我们已经知道的价值`arr[0]`，因此重建就从这个保证值开始。 
2. 迭代中的每个值`encoded`。 

每个编码值代表原始数组中两个相邻元素的异或。 
3. 使用 XOR 反转恢复下一个元素。 

自从：```
encoded[i] = arr[i] XOR arr[i + 1]
```我们计算：```
arr[i + 1] = arr[i] XOR encoded[i]
```这是有效的，因为 XOR 会取消相同的值。 
4. 将恢复的值附加到结果数组中。 

每个新值都成为计算下一个值的基础。 
5. 继续，直到处理完所有编码值。 

自从`encoded`有长度`n - 1`，重建的数组将恰好包含`n`元素。 
6. 返回完成的数组。 

### 为什么它有效

 该算法之所以有效，是因为 XOR 是可逆的。 对于每个相邻对：```
encoded[i] = arr[i] XOR arr[i + 1]
```如果我们已经知道`arr[i]`，然后再次进行异或`encoded[i]`删除它并显示`arr[i + 1]`。 

此属性保证每个下一个值都被正确且唯一地重建。 

## Python 解决方案```python
from typing import List

class Solution:
    def decode(self, encoded: List[int], first: int) -> List[int]:
        result = [first]

        for value in encoded:
            next_number = result[-1] ^ value
            result.append(next_number)

        return result
```实现首先使用已知的第一个值初始化结果数组。 

循环处理中的每个值`encoded`。 在每次迭代中，使用以下命令检索先前解码的数字`result[-1]`。 

使用 XOR 属性：```python
arr[i + 1] = arr[i] XOR encoded[i]
```计算下一个原始值并将其附加到结果数组中。 

处理完所有编码值后，返回重建的数组。 

## 解决方案```go
func decode(encoded []int, first int) []int {
    result := make([]int, 1, len(encoded)+1)
    result[0] = first

    for _, value := range encoded {
        nextNumber := result[len(result)-1] ^ value
        result = append(result, nextNumber)
    }

    return result
}
```Go 解决方案遵循与 Python 版本相同的逻辑。 

切片用容量初始化`len(encoded) + 1`以避免追加期间重复重新分配。 

Go 整数完全足以满足给定的约束，因此这里不存在溢出问题。 

与 Python 列表不同，Go 切片需要显式初始化`make`。

 ## 边缘情况

 一种重要的边缘情况是最小有效输入大小。 自从`encoded.length = n - 1`，最小可能的编码数组仅包含一个元素。 有缺陷的实现可能会意外地进行多次迭代或错误处理索引。 当前的实现自然地处理了这个问题，因为循环只运行一次并附加一个恢复值。 

另一个重要的情况涉及零。 XOR 具有恒等性质：```
x XOR 0 = x
```还有：```
x XOR x = 0
```因此，具有重复值的数组会生成零编码值。 某些实现错误地将零视为特殊的无效情况，但无论编码值是否为零，算法都会一致工作。 

第三种边缘情况是接近约束上限的大值。 由于 XOR 是按位运算，并且不会将值增长到超出这些约束的整数存储容量，因此该算法仍然高效且安全。 Python 和 Go 都能轻松处理所需的整数范围。 

一个微妙的实现问题是确保输出数组具有长度`encoded.length + 1`。 由于每个编码值对应于两个原始元素之间的转换，因此忘记包含初始元素`first`value 将产生一个太短的数组。 初始化结果`first`保证正确的最终尺寸。
