 # LeetCode 1725 - 可以形成最大正方形的矩形数量

 ## 问题理解

 该问题给了我们一个矩形列表，其中每个矩形表示为`[li, wi]`。 这里，`li`是矩形的长度，`wi`是它的宽度。 

我们想要从每个矩形中确定可以从中切出的最大正方形。 正方形要求所有边都相等，因此正方形的边长不能超过矩形的任何一个尺寸。 因此，可以由矩形形成的最大正方形的边长为：$$\min(li, wi)$$例如：

 - 矩形`[5,8]`可以产生一个边长为正方形的`5`- 长方形`[3,9]`可以产生一个边长为正方形的`3`任务不是返回最大的正方形大小本身。 相反，我们必须计算有多少个矩形可以在所有矩形中产生最大可能的正方形。 

假设可实现的最大正方形边长是`5`。 然后每个矩形的最小边也是`5`对答案有贡献。 

输入约束相对较小：

 - 最多`1000`矩形
 - 矩形尺寸可以大到`10^9`矩形数量较少意味着即使是简单的线性扫描也足够高效。 非常大的维度值表明我们应该避免依赖于维度本身大小的算法。 

该问题还保证：

 - 每个矩形恰好包含两个整数
 - 两个维度均为正值
 -`li != wi`，这意味着输入矩形永远不是正方形

 重要的边缘情况包括：

 - 输入中只有一个矩形
 - 多个矩形产生相同的最大正方形
 - 所有矩形产生不同的正方形尺寸
 - 附近非常大的矩形尺寸`10^9`- 较小边出现在不同位置的矩形，例如`[5,8]`相对`[16,5]`幼稚的实现可能会意外地比较较大的一侧而不是较小的一侧，这会产生不正确的结果。 

## 方法

 ### 蛮力方法

 蛮力的想法是首先计算每个矩形可以产生的最大正方形。 我们将所有这些值存储在一个单独的数组中。 然后我们找到该数组中的最大值。 最后，我们再次扫描数组并计算最大值出现的次数。 

这种方法是正确的，因为矩形中最大的正方形始终由其较小的边确定。 通过显式存储每个可能的正方形大小，我们可以稍后确定全局最大值并计算其频率。 

尽管这种方法对于给定的约束是可以接受的，但它使用了不必要的额外空间，因为我们实际上不需要保留所有中间值。 

### 最佳方法

 关键的观察是，我们在扫描矩形时只需要两条信息：

 1.当前最大正方形边长
 2. 有多少个矩形达到最大值

 当我们处理每个矩形时：

 - 计算`currentSquare = min(length, width)`- 如果`currentSquare`大于当前最大值：

 - 更新最大值
 - 将计数重置为`1`- 如果`currentSquare`等于当前最大值：

 - 增加计数

 这使我们能够一次性解决问题，而无需存储所有中间正方形尺寸。

 ## 算法演练

 1.初始化两个变量：

 -`maxSquareSide`存储迄今为止发现的最大正方形边
 -`count`存储有多少个矩形达到该尺寸
 2. 迭代输入数组中的每个矩形。 
3. 对于每个矩形`[length, width]`，计算：$$currentSquare = \min(length, width)$$这是可行的，因为正方形边不能超过较小的矩形尺寸。 
4. 比较`currentSquare`和`maxSquareSide`。 
5. 如果`currentSquare`大于`maxSquareSide`：

- 更新`maxSquareSide`- 重置`count`到`1`这意味着我们发现了一个新的更大的正方形，因此之前的计数不再相关。 
6. 如果`currentSquare`等于`maxSquareSide`:

 - 增量`count`这意味着另一个矩形可以产生相同的最大正方形。 
7. 继续，直到处理完所有矩形。 
8. 返回`count`。 

### 为什么它有效

 该算法在处理每个矩形后保持不变：

 -`maxSquareSide`是迄今为止看到的最大的正方形边
 -`count`是可以产生最大正方形的矩形数量

 每当找到更大的方块时，之前的计数就会变得无效，因为存在新的最大值。 每当相同的最大值再次出现时，计数就会增加。 由于每个矩形都被处理一次，因此最终计数是正确的。 

## Python 解决方案```python
from typing import List

class Solution:
    def countGoodRectangles(self, rectangles: List[List[int]]) -> int:
        max_square_side = 0
        count = 0

        for length, width in rectangles:
            current_square = min(length, width)

            if current_square > max_square_side:
                max_square_side = current_square
                count = 1
            elif current_square == max_square_side:
                count += 1

        return count
```实现从初始化开始`max_square_side`和`count`。 

对于每个矩形，代码使用以下方法计算最大可能的正方形边`min(length, width)`。 这反映了正方形必须完全适合矩形的几何约束。 

比较逻辑直接反映了算法演练：

 - 较大的方块会更新最大值并重置计数
 - 等平方增加计数

 不需要额外的数组或数据结构，这可以保持解决方案的内存效率。 

## 解决方案```go
func countGoodRectangles(rectangles [][]int) int {
    maxSquareSide := 0
    count := 0

    for _, rectangle := range rectangles {
        length := rectangle[0]
        width := rectangle[1]

        currentSquare := length
        if width < currentSquare {
            currentSquare = width
        }

        if currentSquare > maxSquareSide {
            maxSquareSide = currentSquare
            count = 1
        } else if currentSquare == maxSquareSide {
            count++
        }
    }

    return count
}
```Go 实现遵循与 Python 版本相同的逻辑。 由于 Go 没有提供内置整数`min`对于基本整数的函数，最小值是使用手动计算的`if`陈述。 

Go 切片用于矩形输入。 除了几个整数变量之外，不需要额外的内存分配，因此空间复杂度保持不变。 

整数溢出不是问题，因为矩形尺寸最多为`10^9`，它安全地符合 LeetCode 平台上 Go 的标准整数范围。

 ## 边缘情况

 一种重要的边缘情况是输入仅包含单个矩形。 在这种情况下，答案必须始终是`1`因为该矩形会自动生成尽可能大的正方形。 该实现自然地处理了这个问题，因为第一个矩形初始化了最大正方形大小和计数。 

当几个矩形产生相同的最大正方形边长时，会发生另一个重要的情况。 有缺陷的实现可能会意外地覆盖计数而不是增加计数。 该算法显式检查相等性，并在找到另一个匹配矩形时增加计数器。 

第三种边缘情况涉及尺寸不同顺序的矩形，例如`[5,8]`和`[16,5]`。 实现总是计算`min(length, width)`，所以维度的顺序并不重要。 无论矩形尺寸如何排列，这都保证了正确性。 

接近的大整数值`10^9`是另一个考虑因素。 由于该算法仅执行比较和最少操作，因此不存在溢出或昂贵的算术的风险。 Python 和 Go 实现都可以安全地处理完整的约束范围。
