[LeetCode 问题 1747](https://leetcode.com/problems/leetflex-banned-accounts/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 这个问题要求我们识别可疑帐户`LogInfo`桌子。 每行代表一个用户帐户的登录会话，包括帐户 ID、会话期间使用的 IP 地址以及登录和注销时间戳。 

如果至少有一个时刻同一帐户同时从两个不同的 IP 地址处于活动状态，则应禁止该帐户。 

重要的细节是会议必须在时间上重叠。 仅仅在不同的时间从不同的IP登录是完全有效的。 仅当来自不同 IP 地址的两个会话在任何时刻相交时，我们才会禁止该帐户。 

输入表包含：

 | 专栏 | 意义|
 | --- | --- |
 |`account_id`| 用户帐户|
 |`ip_address`| 会话期间使用的 IP |
 |`login`| 会议开始时间 |
 |`logout`| 会话结束时间 |

 该问题保证了`logout > login`，因此每个会话都有正的持续时间。 

预期输出是一个仅包含`account_id`应该被禁止的价值观。 

一个微妙但极其重要的细节是如何定义间隔重叠。 带有帐户的示例`4`证明区间两端都包含在内。 一场会议恰好结束于`17:00:00`，另一个正好开始于`17:00:00`，这仍然算作重叠。 

这意味着两个会话重叠，如果：```
session1.login <= session2.logout
AND
session2.login <= session1.logout
```几种边缘情况很容易导致错误：

 - 两个完全接触边界的会话仍然重叠。 
- 可能存在重复的行。 
- 来自同一 IP 的会话不应触发禁令。 
- 同一帐户可能存在多个重叠会话。 
- 会话可以完全嵌套在另一个会话中。 

核心挑战是检测一个账户是否有两个不同IP地址的重叠区间。 

## 方法

 ### 蛮力方法

 暴力解决方案会比较表中的每对会话。 

对于每对行：

 1. 检查是否属于同一个账户。 
2. 检查IP 地址是否不同。 
3. 检查时间间隔是否重叠。 

如果所有三个条件都成立，则该帐户应包含在答案中。 

重叠条件为：```
login1 <= logout2
AND
login2 <= logout1
```这是有效的，因为如果每个间隔在另一个间隔结束之前开始，两个间隔就会重叠。 

暴力方法是正确的，因为它显式地检查每对可能的会话。 如果存在任何具有不同 IP 的重叠对，我们就会找到它。 

然而，这种方法效率低下，因为比较每一对都需要二次时间。 

### 最佳方法

 最佳的 SQL 解决方案使用自连接。 

我们让数据库引擎有效地将表与其自身连接起来，而不是手动迭代应用程序代码中的每一对。 

关键的见解是，该问题本质上是一个成对区间重叠检测问题。 

对于两行`a`和`b`，我们需要：

 - 同一帐户
 - 不同的IP地址
 - 重叠间隔

 自连接自然地模拟了这种关系。 

我们还使用`DISTINCT`因为同一帐户可能存在多个重叠对。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 手动比较每对会话 |
 | 最佳 | 最坏情况 | O(n²) O(1) 额外 | 具有重叠过滤的自连接 |

 尽管 SQL 自连接在最坏的情况下仍然可能是二次的，但它是预期的关系数据库解决方案，并且通常由数据库引擎进行内部优化。 

## 算法演练

 1. 创建两个别名`LogInfo`表，通常称为`a`和`b`。 

这使我们能够将同一个表中的一个会话与另一个会话进行比较。 
2. 匹配属于同一帐户的行。 

我们只关心同一用户的并发活动，因此我们需要：```
a.account_id = b.account_id
```3. 确保IP 地址不同。 

来自同一 IP 的多个重叠会话并不可疑。```
a.ip_address != b.ip_address
```4. 检查时间间隔是否重叠。 

如果满足以下条件，则两个区间重叠：```
a.login <= b.logout
AND
b.login <= a.logout
```这可以正确处理：

 - 部分重叠
 - 完全遏制
 - 精确的边界接触
 5. 选择不同的帐户 ID。 

一个帐户可能有许多重叠的会话对，但它应该在输出中只出现一次。 

### 为什么它有效

 该算法检查属于同一帐户的每对相关会话。 重叠条件在数学上保证两个间隔共享至少一个时刻。 由于我们还需要不同的 IP 地址，因此每个返回的帐户都满足被禁止帐户的确切定义。 

相反，如果一个帐户应该被禁止，则至少存在一对具有不同 IP 的重叠会话，并且自加入将找到该对。 

## Python 解决方案

 尽管这是一个数据库问题并且通常使用 SQL 解决，但以下 Python 实现在算法上演示了相同的逻辑。```python
from typing import List
from collections import defaultdict

class Solution:
    def bannedAccounts(self, log_info: List[List[int]]) -> List[int]:
        sessions_by_account = defaultdict(list)

        for account_id, ip_address, login, logout in log_info:
            sessions_by_account[account_id].append(
                (ip_address, login, logout)
            )

        banned_accounts = []

        for account_id, sessions in sessions_by_account.items():
            n = len(sessions)

            banned = False

            for i in range(n):
                ip1, login1, logout1 = sessions[i]

                for j in range(i + 1, n):
                    ip2, login2, logout2 = sessions[j]

                    if ip1 == ip2:
                        continue

                    overlaps = (
                        login1 <= logout2 and
                        login2 <= logout1
                    )

                    if overlaps:
                        banned_accounts.append(account_id)
                        banned = True
                        break

                if banned:
                    break

        return banned_accounts
```该实现首先使用哈希映射按帐户 ID 对会话进行分组。 这可以防止不同帐户之间不必要的比较。 

对于每个帐户，我们都会比较每对会话。 我们会跳过使用相同 IP 地址的对，因为它们并不可疑。 

重叠测试直接实现区间相交条件：```python
login1 <= logout2 and login2 <= logout1
```一旦我们发现某个帐户的可疑重叠，我们就会将其添加到结果中并停止检查该帐户的其他对。 

这种提前终止稍微提高了实际性能。 

## 解决方案```go
package main

type Session struct {
	ip     int
	login  int
	logout int
}

func bannedAccounts(logInfo [][]int) []int {
	sessionsByAccount := make(map[int][]Session)

	for _, row := range logInfo {
		accountID := row[0]
		ipAddress := row[1]
		login := row[2]
		logout := row[3]

		sessionsByAccount[accountID] = append(
			sessionsByAccount[accountID],
			Session{
				ip:     ipAddress,
				login:  login,
				logout: logout,
			},
		)
	}

	var result []int

	for accountID, sessions := range sessionsByAccount {
		n := len(sessions)

		banned := false

		for i := 0; i < n; i++ {
			for j := i + 1; j < n; j++ {
				s1 := sessions[i]
				s2 := sessions[j]

				if s1.ip == s2.ip {
					continue
				}

				overlaps := (
					s1.login <= s2.logout &&
					s2.login <= s1.logout
				)

				if overlaps {
					result = append(result, accountID)
					banned = true
					break
				}
			}

			if banned {
				break
			}
		}
	}

	return result
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个小的结构差异是使用专用的`Session`struct 使代码更具可读性和类型安全。 

Go 切片在运行期间会自动动态调整大小`append`，因此不需要手动内存管理。 

这里不存在整数溢出问题，因为问题约束很小并且时间戳被象征性地处理。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n²) | 帐户的每对会话可能都需要比较 |
 | 空间| O(n) | 哈希图存储分组会话|

 主要成本来自每个帐户的会话列表中的成对比较。 在最坏的情况下，如果所有会话都属于一个帐户，我们会比较每一对。 

额外的内存使用量来自按帐户 ID 对会话进行分组。

class Solution:
    def bannedAccounts(self, log_info: List[List[int]]) -> List[int]:
        sessions_by_account = defaultdict(list)

        for account_id, ip_address, login, logout in log_info:
            sessions_by_account[account_id].append(
                (ip_address, login, logout)
            )

        banned_accounts = []

        for account_id, sessions in sessions_by_account.items():
            n = len(sessions)

            banned = False

            for i in range(n):
                ip1, login1, logout1 = sessions[i]

                for j in range(i + 1, n):
                    ip2, login2, logout2 = sessions[j]

                    if (
                        login1 <= logout2 and
                        login2 <= logout1
                    ):
                        banned_accounts.append(account_id)
                        banned = True
                        break

                if banned:
                    break

        return sorted(banned_accounts)

 ## 边缘情况

 ### 会话仅在一个时间戳处发生

 最棘手的情况之一是一个会话在另一个会话开始的同时结束。 

例如：```
Session A: 16:00 -> 17:00
Session B: 17:00 -> 18:00
```严格的不平等检查会错误地将它们视为不重叠。 问题陈述明确认为这是重叠。 该实现通过使用正确处理这个问题`<=`比较而不是`<`。 

### 使用相同 IP 的多个会话

 一个帐户可以合法地具有来自同一 IP 地址的重叠会话。 例如，用户可以同时打开多个浏览器选项卡。 

仅检查间隔重叠的简单实现会错误地禁止此类用户。 该解决方案明确检查：```
if ip1 == ip2:
    continue
```这保证了只有不同的IP地址才会触发禁令。 

### 重复行

 该表可能包含重复的行。 粗心的实施可能会意外地多次添加相同的帐户或执行多余的工作。 

该实现可以安全地处理这个问题，因为：

 - 具有相同 IP 的重复行不会触发禁令。 
- 一旦帐户被标记为禁止，处理就会提前停止。 
- 结果仅包含每个被禁止的帐户一次。
