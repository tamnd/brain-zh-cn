[LeetCode 第 1781 题](https://leetcode.com/problems/sum-of-beauty-of-all-substrings/)

 **难度：** 🟡 中等
 **主题：** 哈希表、字符串、计数

 ## 解决方案

 ## 问题理解

 该问题要求我们计算给定字符串的所有子字符串的**美丽总和**`s`。 子字符串的“美度”定义为该子字符串中出现的任何字符的最高频率和最低频率之间的差异。 简单来说，对于每个子串，我们统计每个字符出现的次数，找到出现次数最多的字符和出现次数最少的字符（排除不出现的字符），并取差值。 

输入是一个字符串`s`长度在1到500之间，仅由小写英文字母组成。 输出是一个整数，表示每个可能的子串的美丽值的总和`s`。 

需要注意的要点包括单字符子字符串的美度为 0，因为最频繁和最不频繁的字符是相同的。 此外，具有所有相同字符的子字符串也贡献 0。 这些约束表明，由于输入量较小，直接的暴力解决方案可能是可行的，但我们应该考虑在可能的情况下进行优化。 

重要的边缘情况包括非常短的字符串（`s`长度为 1)、具有所有相同字符的字符串以及具有最大长度的字符串，其中频率计算的成本可能很高。 

## 方法

 **暴力方法**涉及生成每个可能的子串`s`，使用哈希表或数组计算该子字符串中每个字符的频率，并通过从最大频率减去最小非零频率来计算美感。 这种方法很简单并且保证正确，因为它显式地计算所有子串的美度，但计算成本很高，因为存在 O(n^2) 个子串，并且每个子串的计算频率可能需要 O(n)，从而导致 O(n^3) 时间复杂度。 

**优化方法**利用了这样的观察结果：尽管有 O(n^2) 个子字符串，但该字符串仅包含 26 个小写字母。 通过固定起始索引并将子串向右扩展，我们可以维护一个运行频率数组。 在每次扩展时，我们可以通过扫描 26 长度的频率数组来计算当前的美感，相对于子串长度来说，这实际上是 O(1)。 这将内部频率计算从 O(n) 减少到 O(26)，总体时间复杂度为 O(n^2 * 26)，简化为 O(n^2)，并且对于给定的约束来说足够高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n^3) | O(n^3) | O(26) | 生成所有子串并分别计算每个子串的频率 |
 | 最佳 | O(n^2) | O(n^2) | O(26) | 从每个起始索引展开子字符串并维护频率数组以增量计算美感 |

 ## 算法演练

 1. 初始化变量`total_beauty`为零。 这将保存所有子字符串的美丽值的总和。 
2. 迭代每个可能的起始索引`i`从 0 到 的子串`len(s) - 1`。 
3. 对于每个`i`，初始化频率数组`freq`大小为 26（小写字母），全为零。 
4. 从索引展开子字符串`i`向右，迭代结束索引`j`从`i`到`len(s) - 1`。 
5. 对于每个角色`s[j]`，增加其相应的计数`freq`大批。 
6. 通过查找中的最大频率和最小非零频率来计算当前子串的美度`freq`并取它们的差异。 
7. 将计算出的美感添加到`total_beauty`。 
8. 从所有可能的索引开始迭代所有子字符串后，返回`total_beauty`。 

**为什么有效：** 通过从每个起始索引扩展子字符串并维护运行频率数组，我们可以在相对于子字符串计数的线性时间内有效地计算每个子字符串的美度。 频率数组确保我们只考虑子字符串中存在的字符并计算正确的最大和最小频率。 

## Python 解决方案```python
class Solution:
    def beautySum(self, s: str) -> int:
        total_beauty = 0
        n = len(s)
        
        for i in range(n):
            freq = [0] * 26
            for j in range(i, n):
                freq[ord(s[j]) - ord('a')] += 1
                
                max_freq = max(freq)
                min_freq = min(f for f in freq if f > 0)
                
                total_beauty += max_freq - min_freq
                
        return total_beauty
```此 Python 实现初始化总美丽计数器并迭代所有可能的起始索引。 对于每个起始索引，它将子字符串向右扩展，更新 26 长度的频率数组。 计算每个子串的最大和最小非零频率以找出美度，然后将其添加到总数中。 

## 解决方案```go
func beautySum(s string) int {
    totalBeauty := 0
    n := len(s)
    
    for i := 0; i < n; i++ {
        freq := [26]int{}
        for j := i; j < n; j++ {
            freq[s[j]-'a']++
            
            maxFreq, minFreq := 0, n+1
            for _, f := range freq {
                if f > 0 {
                    if f > maxFreq {
                        maxFreq = f
                    }
                    if f < minFreq {
                        minFreq = f
                    }
                }
            }
            totalBeauty += maxFreq - minFreq
        }
    }
    
    return totalBeauty
}
```在 Go 中，我们使用长度为 26 的固定大小数组来表示字符频率。 我们仔细处理最小频率初始化，以确保我们跳过零频率。 算法逻辑与 Python 版本非常相似，具有 Go 特有的数组和索引处理。

 ## 边缘情况

 第一个重要的边缘情况是长度为 1 的字符串。任何单字符子字符串的美度为 0。该实现很自然地处理这个问题，因为频率数组仅包含一个非零值，因此`max_freq - min_freq`= 0。 

第二种边缘情况是所有字符都相同的字符串。 这里，每个子串的美度都是 0。我们的方法正确地计算了这个，因为频率数组具有相同的值，并且`max_freq - min_freq`= 0。 

第三种边缘情况涉及字符以非常不同的频率出现的子字符串。 例如，`"aaab"`有一个子串`"aaab"`和`a:3, b:1`，产生的美度为 2。该算法正确计算非零频率上的最大值和最小值，确保美度计算考虑到这种情况。 当频率数组中存在零时，这可以防止误计数。
