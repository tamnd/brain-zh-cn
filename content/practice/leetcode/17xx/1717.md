[LeetCode 第 1717 题](https://leetcode.com/problems/maximum-score-from-removing-substrings/)

 **难度：** 🟡 中等
 **主题：** 字符串、堆栈、贪婪

 ## 解决方案

 ## 问题理解

 问题给了我们一个字符串`s`以及两条评分规则：

 - 删除子字符串`"ab"`赚到`x`点。 
- 删除子字符串`"ba"`赚到`y`点。 

我们可以按照我们选择的任何顺序尽可能多次地执行这些删除。 每次我们删除一个子字符串时，剩余的字符都会靠近在一起，这可能会创建新的可删除子字符串。 目标是最大化总分。 

重要的细节是删除的顺序很重要。 删除一个子字符串可以防止以后再次删除，或者创造一个新的机会。 因此，需要一种贪心策略，而不是简单地计算出现次数。 

例如，考虑字符串`"aba"`:

 - 如果我们删除`"ab"`首先，我们获得`x`点并留下`"a"`。 
- 如果我们删除`"ba"`首先，我们获得`y`点并留下`"a"`。 

我们只能执行一次删除，因此我们应该选择得分较大的那个。 

输入大小可以大到`10^5`，它立即告诉我们，对所有可能性进行昂贵的回溯或递归探索是行不通的。 我们需要一个接近线性时间的解决方案。 

另一个重要的观察是，只有角色`'a'`和`'b'`与得分有关。 任何其他字符都充当分隔符，因为子字符串不能跨越它。 例如：```
"aabxbaa"
```人物`'x'`将问题分成两个独立的部分：```
"aab" and "baa"
```这极大地简化了问题的结构。 

一些边缘情况很重要：

 - 没有的字符串`"ab"`或者`"ba"`子字符串应该返回`0`。 
- 字符串仅包含`'a'`或仅`'b'`不能产生任何分数。 
- 什么时候`x > y`，去除`"ab"`第一个是最优的。 
- 什么时候`y > x`，去除`"ba"`第一个是最优的。 
- 大型交替图案，例如`"abababab"`可以产生许多重叠的选择，并且会破坏不仔细处理删除的天真贪婪实现。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试所有可能的删除顺序。 

每一步：

 1. 搜索当前字符串中的所有内容`"ab"`和`"ba"`子串。 
2. 排除一种可能性。 
3. 在较小的字符串上继续递归。 
4. 追踪所有选项中的最高分。 

这种方法是正确的，因为它探索了每个有效的操作序列。 最终，它找到最佳分数。 

然而，可能的移除令数量呈指数级增长。 每次删除都会改变字符串结构，从而创建许多分支的可能性。 即使对于中等长度的字符串，状态的数量也会变得巨大。 

由于字符串长度可以达到`10^5`，这种做法是完全不可行的。 

### 关键见解

 关键的观察是我们应该始终首先优先考虑得分较高的子字符串。 

认为：

-`x > y`这意味着删除`"ab"`比删除更有价值`"ba"`。 

如果我们首先删除较低值对，我们可能会破坏稍后删除较高值对的机会。 因此，尽可能贪婪地获取更高价值的对是最佳的。 

例如：```
"abab"
```如果`x = 10`和`y = 1`:

 - 删除`"ba"`首先只给出`1`。 
- 删除`"ab"`首先允许两个`"ab"`总共拆除了`20`。 

这导致了最优策略：

 1. 首先删除所有出现的较高值子字符串。 
2. 然后从剩余字符串中删除所有出现的较低值子字符串。 

堆栈是理想的选择，因为子字符串的删除取决于删除后动态变化的相邻字符。

 ## 算法演练

 ### 步骤 1：决定哪个子字符串具有更高的优先级

 比较`x`和`y`。 

- 如果`x >= y`， 消除`"ab"`第一的。 
- 否则，删除`"ba"`第一的。 

这确保了我们在低价值的移除干扰之前贪婪地最大化高价值的移除。 

### 步骤 2：创建用于基于堆栈的删除的辅助函数

 我们使用堆栈来有效地模拟移除。 

对于字符串中的每个字符：

 - 如果栈顶和当前字符构成目标子串，则出栈并添加点。 
- 否则，将字符压入堆栈。 

这是有效的，因为删除后的相邻字符自然会成为堆栈表示中的邻居。 

例如，删除`"ab"`从`"cabxbae"`:

 | 人物 | 堆栈之前 | 行动| 堆栈之后 |
 | ---| ---| ---| ---|
 | c | []| 推| [c] |
 | 一个 | [c] | 推| [c，a] |
 | 乙| [c，a] | 删除“ab” | [c] |
 | x| [c] | 推| [c,x] |

 ### 步骤 3：删除所有高值子字符串

 对原始字符串运行一次辅助函数。 

此通行证：

 - 最大化高价值清除。 
- 在所有可能的贪婪删除之后生成剩余的字符串。 

### 步骤 4：删除所有低值子字符串

 使用第二个子字符串模式对剩余字符串再次运行辅助函数。 

此时，所有高优先级机会已经用尽，因此删除较低价值对不会损害最优性。 

### 第 5 步：返回总分

 将两次通过的分数相加并返回结果。 

### 为什么它有效

 关键的不变量是，较早移除得分较高的对永远不会减少稍后可用的得分较高的移除的数量，而首先移除得分较低的对可能会破坏得分较高的机会。 

由于每次删除仅影响局部邻接，因此首先贪婪地消耗更有价值的模式可以保证最大利润。 该堆栈正确地对删除后的动态邻接进行建模，确保每次有效的删除都被准确地检测到一次。 

## Python 解决方案```python
class Solution:
    def maximumGain(self, s: str, x: int, y: int) -> int:
        def remove_substring(text: str, first: str, second: str, points: int):
            stack = []
            score = 0

            for char in text:
                if stack and stack[-1] == first and char == second:
                    stack.pop()
                    score += points
                else:
                    stack.append(char)

            return "".join(stack), score

        total_score = 0

        if x >= y:
            remaining, score = remove_substring(s, 'a', 'b', x)
            total_score += score

            remaining, score = remove_substring(remaining, 'b', 'a', y)
            total_score += score
        else:
            remaining, score = remove_substring(s, 'b', 'a', y)
            total_score += score

            remaining, score = remove_substring(remaining, 'a', 'b', x)
            total_score += score

        return total_score
```该实现使用了一个名为的辅助函数`remove_substring`。 此函数对特定子字符串模式执行一次完整的贪婪传递。 

堆栈存储尚未匹配成可移除对的字符。 每当当前字符和堆栈顶部形成目标子字符串时，就会删除堆栈顶部并添加点。 

辅助函数返回两件事：

 - 所有删除后剩余的字符串。 
- 该传球获得的总分。 

main函数首先判断哪个子串的值更高。 它首先处理该模式，然后处理剩余字符串上的较低值模式。 

这完全遵循了之前被证明是最佳的贪婪策略。 

## 解决方案```go
func maximumGain(s string, x int, y int) int {
	removeSubstring := func(text string, first byte, second byte, points int) (string, int) {
		stack := make([]byte, 0)
		score := 0

		for i := 0; i < len(text); i++ {
			char := text[i]

			if len(stack) > 0 && stack[len(stack)-1] == first && char == second {
				stack = stack[:len(stack)-1]
				score += points
			} else {
				stack = append(stack, char)
			}
		}

		return string(stack), score
	}

	totalScore := 0

	if x >= y {
		remaining, score := removeSubstring(s, 'a', 'b', x)
		totalScore += score

		_, score = removeSubstring(remaining, 'b', 'a', y)
		totalScore += score
	} else {
		remaining, score := removeSubstring(s, 'b', 'a', y)
		totalScore += score

		_, score = removeSubstring(remaining, 'a', 'b', x)
		totalScore += score
	}

	return totalScore
}
```Go 解决方案遵循与 Python 版本完全相同的逻辑。 主要区别在于使用字节片而不是 Python 列表。 

该堆栈是使用`[]byte`片。 删除顶部元素是通过切片完成的：```go
stack = stack[:len(stack)-1]
```Go 中的字符串是不可变的，因此剩余的字符将使用以下方法转换回字符串：```go
string(stack)
```整数溢出不是问题，因为最大可能分数完全在 Go 的范围内`int`范围。

 ## 边缘情况

 当字符串根本不包含可移动子字符串时，就会出现一种重要的边缘情况。 例如：```
"ccccddd"
```有缺陷的实现可能仍然会错误地尝试堆栈操作，或者假设至少存在一个删除操作。 提供的解决方案安全地处理每个字符并简单地返回`0`当没有找到匹配的相邻对时。 

另一个关键的边缘情况涉及重叠选择，例如：```
"aba"
```两个都`"ab"`和`"ba"`出现，但实际上只能发生一次删除。 贪婪地删除字符串中第一个出现的内容的简单实现可能会产生次优的答案。 该算法通过在处理得分较低的子字符串之前全局优先考虑得分较高的子字符串来避免这种情况。 

第三个棘手的情况涉及分隔符：```
"abxba"
```这`'x'`防止左右部分之间的相互作用。 不正确的实现可能会意外地允许在字符串重建后跨分隔符进行删除。 基于堆栈的方法自然地保留了边界，因为字符是按顺序处理的，并且只有相邻的堆栈字符才能形成可移动的对。 

最后，长交替字符串，例如：```
"abababababab"
```可以产生许多重叠的去除机会。 由于重复的字符串复制，递归或重复的字符串切片实现可能会变得非常慢。 堆栈方法保证了线性性能，因为每个字符每次最多被压入和弹出一次。
