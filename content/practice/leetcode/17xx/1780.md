[LeetCode 问题 1780](https://leetcode.com/problems/check-if-number-is-a-sum-of-powers-of- Three/)

 **难度：** 🟡 中等
 **主题：** 数学

 ## 解决方案

 ## 问题理解

 该问题询问给定的整数是否`n`可以表示为三的不同幂的总和。 

三的幂是以下形式的任意数：$3^x$在哪里`x`是一个非负整数。 这意味着有效的权力是：

 -`3^0 = 1`-`3^1 = 3`-`3^2 = 9`-`3^3 = 27`- 等等。 

“独特”二字极其重要。 每个三的幂最多可以使用一次。 例如：

-`12 = 9 + 3`，有效，因为两种权力不同
 -`21 = 9 + 9 + 3`，无效，因为`9`使用两次

 输入由单个整数组成`n`，我们必须返回：

 -`true`如果存在这样的表示
 -`false`否则

 限制相对较小：```
1 <= n <= 10^7
```这告诉我们暴力解决方案仍然是可能的，因为以下三的幂数`10^7`很小。 然而，问题实际上是确定一个数学属性，从而产生更清晰、更优化的解决方案。 

一个重要的观察结果是，三的幂增长得很快：```
3^0 = 1
3^1 = 3
3^2 = 9
3^3 = 27
...
3^15 = 14348907
```自从`3^15`已经超过`10^7`，只有大约15个相关权力需要考虑。 

一些重要的边缘情况包括：

 -`n = 1`，这就是简单的`3^0`- 像这样的数字`2`，无法表示，因为唯一可用的权力是`1, 3, 9, ...`- 需要重复幂的数字，这是不允许的
 - 大值接近`10^7`关键的挑战是确定每种能力是否最多使用一次。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是首先生成小于或等于的三的幂`n`，然后尝试这些权力的每个可能的子集。 

例如，如果权力是：```
[1, 3, 9, 27]
```我们可以测试每个子集：```
[]
[1]
[3]
[1,3]
[9]
[1,9]
...
```并检查是否有任何子集总和为`n`。 

这是有效的，因为该问题明确询问不同权力的某种组合是否等于`n`。 

问题是子集的生成是指数级的。 如果有`k`三的幂，则有：$2^k$可能的子集。 

虽然`k`这里很小，当存在直接数学观察时，指数算法通常是不可取且不必要的。 

### 最佳方法

 关键的见解来自 3 进制表示。 

任何以 3 为基数书写的数字都使用数字：```
0, 1, 2
```例如：```
12 in base 3 = 110
```这意味着：$12 = 1\cdot3^2 + 1\cdot3^1 + 0\cdot3^0$注意一些重要的事情：

 - 一个数字`0`表示未使用电源
 - 一个数字`1`表示用电一次
 - 一个数字`2`意味着需要使用两次电源

 由于该问题需要不同的幂，因此每个基数 3 的数字必须是`0`或者`1`。 

因此：

 - 如果三进制表示中的任何数字是`2`，答案是`false`- 否则，答案是`true`这给出了一个非常优雅的贪心数学解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^k) | O(2^k) | O(k) | 生成三 | 的幂的所有子集
 | 最佳 | O(log₃n)| O(1) | O(1) | 直接检查三进制数字 |

 ## 算法演练

 1. 从给定的整数开始`n`。 
2.除法时反复检查余数`n`经过`3`。 

操作：$n \bmod 3$给出当前的三进制数字。 
3. 如果余数是`2`，立即返回`false`。 

一个三进制数字`2`意味着我们需要使用相同的三的幂两次，这违反了所有幂都不同的要求。 
4.否则，除`n`经过`3`使用整数除法。 

这会将三进制表示向右移动一位数，并允许我们处理下一个 3 的幂。 
5. 继续直到`n`变成`0`。 
6. 如果循环结束时没有遇到数字`2`， 返回`true`。 

### 为什么它有效

 每个整数都有唯一的以 3 为底的表示形式。 每个三进制数字对应于特定的三的幂的使用次数。 

如果所有数字都只有`0`或者`1`，那么该数字恰好是三的不同幂的和。 如果有任意数字是`2`，那么至少一种力量必须被多次使用，这是被禁止的。 

因为基本表示是唯一的，所以这个条件既是必要的也是充分的。 

## Python 解决方案```python
class Solution:
    def checkPowersOfThree(self, n: int) -> bool:
        while n > 0:
            if n % 3 == 2:
                return False
            
            n //= 3
        
        return True
```其实现直接遵循三进制数字的数学观察。 

这`while`循环以 3 为基数逐位处理数字。在每次迭代时：```python
n % 3
```提取当前的三进制数字。 

如果该数字等于`2`，函数立即返回`False`因为表示需要重用三的幂。 

否则，算法将使用以下方法删除已处理的数字：```python
n //= 3
```最终，所有数字都被处理并`n`变成`0`。 如果没有找到无效数字，函数返回`True`。 

该解决方案很简洁，因为数学消除了递归、回溯或子集生成的需要。 

## 解决方案```go
func checkPowersOfThree(n int) bool {
    for n > 0 {
        if n%3 == 2 {
            return false
        }

        n /= 3
    }

    return true
}
```Go 实现与 Python 版本几乎相同。 

当两个操作数都是整数时，Go 自动使用整数除法，因此：```go
n /= 3
```正确删除当前的三进制数字。 

不存在溢出问题，因为最大输入值仅为`10^7`，完全在 Go 的范围内`int`范围。 

不需要额外的内存分配或切片，因此实现保持恒定的空间。

 ## 边缘情况

 一个重要的边缘情况是当`n`本身就是三的幂，比如`1`,`3`,`9`， 或者`27`。 这些数字应立即评估为`true`因为它们已经由一种独特的力量组成。 该实现自然地处理了这个问题，因为它们的三元表示包含一个`1`数字和所有剩余的数字是`0`。 

当三元表示包含数字时，会出现另一个重要的边缘情况`2`。 例如，`21`变成：```
210
```以 3 为底数。数字`2`意味着该算法需要相同的三的幂的两个副本。 在不了解基本表示的情况下贪婪地减去幂的幼稚实现可能会意外地允许重复。 当前的实现通过直接检查每个三进制数字来避免这种情况。 

第三个重要的边缘情况涉及接近上限约束的非常大的输入，例如`10^7`。 递归子集生成解决方案可能变得效率低下或不必要地复杂。 该数学解决方案仍然高效，因为它仅处理对数的三进制数字，对于最大输入大小大约需要 15 次迭代。 

最后一个微妙的情况是像这样的数字`2`或者`5`，它们接近有效总和，但仍然无法使用不同的幂来表示。 这些情况确保算法正确地拒绝需要重复幂的数字。 三进制数字检查可以精确可靠地处理这些问题。
