 **难度：** 🔴难
 **主题：** 数学、二分查找、贪心

 ## 解决方案

 ## 问题理解

 问题给了我们`n`必须放置在立方体房间内的相同单位立方体。 目标是尽量减少直接接触地板的盒子数量。 

放置规则是问题的重要部分。 如果一个盒子的所有四个垂直边都得到完全支撑，则它只能支撑其顶部的另一个盒子。 每一侧都必须接触另一个盒子或墙壁。 这意味着不允许浮动或不稳定的堆栈。 

最佳结构自然形成角金字塔。 由于墙壁算作支撑，因此将盒子放在角落总是最好的，因为墙壁有助于满足侧面支撑条件。 当我们向上构建时，每个较高层都必须位于足够大的较低层上。 

输入是单个整数`n`，代表两者：

 1. 房间的尺寸，足够容纳所有箱子。 
2. 必须放置的盒子数量。 

输出是必须接触地板的盒子的最小数量。 

约束条件`1 <= n <= 10^9`非常重要。 对布局进行强力模拟是不可能的。 我们需要在对数或平方根时间范围内进行数学或贪婪观察。 

一些边缘情况很重要：

 - 非常小的值，例如`n = 1`，其中答案很简单 1。 
- 完全形成完整金字塔结构的价值观。 
- 落在两个完整金字塔尺寸之间的值。 
- 附近非常大的值`10^9`，低效迭代会超时。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试模拟每个可能的有效盒子放置，并搜索地板盒子最少的布置。 

考虑这个问题的一种方法是递归地逐层放置盒子，同时检查每个支撑盒子是否满足侧面支撑规则。 我们可以尝试所有的地板布局，并确定上面可以堆放多少个盒子。 

这种方法是正确的，因为它探索所有有效的配置并最终找到最小楼层数。 

然而，这在计算上是不可行的。 即使对于中等`n`，可能的配置数量呈爆炸式增长。 自从`n`可以大到`10^9`，穷举搜索是完全不可能的。 

### 最优贪心和数学方法

 关键的见解是最密集的有效结构始终是四面角金字塔。 

如果底层形成三角形排列：```
1
1 1
1 1 1
```那么上面的下一层也可以形成一个更小的三角形，依此类推。 

完整高度金字塔中盒子的数量`h`是：$1+3+6+\cdots+\frac{h(h+1)}{2}=\frac{h(h+1)(h+2)}{6}$基础层包含：$\frac{h(h+1)}{2}$地板箱。 

策略是：

 1. 建造尽可能最大的完整金字塔。 
2. 如果还有盒子，则用额外的盒子贪婪地扩展底层。 
3. 每个附加地板箱可以支持其上方逐渐增加的箱子。 

这是有效的，因为金字塔排列可以最大限度地提高垂直堆叠效率。

 ## 算法演练

 1. 首先建造尽可能最大的完整金字塔。 

金字塔的高度`h`包含：$\frac{h(h+1)(h+2)}{6}$盒子。 

我们反复增加高度，同时盒子的总数仍然在范围之内`n`。 
2. 跟踪使用的盒子总数和楼层盒子数量。 

金字塔的地板与高度`h`包含：$\frac{h(h+1)}{2}$盒子。 

一旦找到最大的完整金字塔，我们就知道这些盒子当前的最小楼层使用量。 
3. 计算还剩下多少个盒子。 

构建完最大的完整金字塔后，可能仍然需要放置一些剩余的盒子。 
4. 贪婪地添加额外的地板箱。 

额外的地板盒按升序添加：

 - 第一个额外的地板箱可以支持 1 个额外的箱子。 
- 第二个可以支持2个。 
- 第三个可以支持3个。 

这形成了另一个三角形增长模式。 
5. 继续添加地板箱，直到覆盖所有剩余的箱子。 

我们不断地从剩余的盒子中减去增加的计数，直到没有盒子剩下。 
6. 返回总楼层箱数。 

### 为什么它有效

 角金字塔是最密集的有效排列，因为每个上层都需要其下方有一个完全支撑的三角形层。 对于给定数量的地板箱，完整的三角形底座最大化了上面可以堆叠的箱子数量。 

最大的完整金字塔建成后，放置剩余盒子的最佳方法是在保留支撑条件的同时尽可能地扩展地板。 以增加支撑能力的顺序贪婪地添加地板箱可以实现地板使用量的最小可能增加。 

## Python 解决方案```python
class Solution:
    def minimumBoxes(self, n: int) -> int:
        total_boxes = 0
        height = 0

        # Build the largest complete pyramid
        while True:
            next_layer = (height + 1) * (height + 2) // 2

            if total_boxes + next_layer > n:
                break

            total_boxes += next_layer
            height += 1

        # Floor boxes in the complete pyramid
        floor_boxes = height * (height + 1) // 2

        remaining = n - total_boxes

        # Add extra floor boxes greedily
        extra = 0

        while remaining > 0:
            extra += 1
            remaining -= extra

        return floor_boxes + extra
```实现直接遵循最优排列的数学结构。 

第一个循环构建尽可能最大的完整金字塔。 每次迭代都会增加一个三角形层。 变量`next_layer`表示将金字塔扩展一层需要多少个盒子。 

一旦循环停止，`height`代表完全完成的金字塔的最大高度`n`。 

该金字塔的地板箱数是使用三角数公式计算的。 

然后剩下的盒子被贪婪地处理。 每增加一个地板箱就会逐渐增加支撑能力。 循环减去`1`， 然后`2`， 然后`3`，依此类推，直到所有剩余的盒子都被占满。 

最后，该解决方案返回原始楼层数加上所需的额外楼层盒。 

## 解决方案```go
func minimumBoxes(n int) int {
    totalBoxes := 0
    height := 0

    // Build the largest complete pyramid
    for {
        nextLayer := (height + 1) * (height + 2) / 2

        if totalBoxes+nextLayer > n {
            break
        }

        totalBoxes += nextLayer
        height++
    }

    // Floor boxes in the complete pyramid
    floorBoxes := height * (height + 1) / 2

    remaining := n - totalBoxes

    // Add extra floor boxes greedily
    extra := 0

    for remaining > 0 {
        extra++
        remaining -= extra
    }

    return floorBoxes + extra
}
```Go 实现几乎完全反映了 Python 逻辑。 

由于所有计算都保持在整数范围内`n <= 10^9`， 标准`int`在 Go 中算术就足够了。 

Go 使用显式整数除法`/`，而Python使用`//`。 不需要额外的数据结构，因此实现保持紧凑并使用恒定的额外内存。

 ## 边缘情况

 ### 精确的金字塔尺寸

 的一些值`n`正好等于完整的四面体数。 例如，`n = 4`和`n = 10`形成完美的金字塔，没有剩余的盒子。 

如果循环条件错误地过早或过晚停止，则很容易导致差一错误。 该实现通过检查下一层是否会超出来正确处理这个问题`n`添加之前。 

### 非常小的输入

 输入如`n = 1`或者`n = 2`很重要，因为金字塔结构还几乎不存在。 

简单的实现有时假设总是可以形成至少一个完整的更高层。 此实现正确地从高度零开始并逐渐向上构建，因此微小的输入可以自然地工作。 

### 附近的大量输入`10^9`大值可能会暴露性能问题或整数溢出错误。 

该实现避免了递归并避免模拟实际的盒子位置。 相反，它完全依赖于数学增长公式，即使对于最大输入大小也非常高效。 

此外，对于 Python 和 Go，所有中间值都安全地保持在整数限制内。
