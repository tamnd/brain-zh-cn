[LeetCode 第 1792 题](https://leetcode.com/problems/maximum-average-pass-ratio/)

 **难度：** 🟡 中等
 **主题：** 数组、贪婪、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 该问题给了我们几个类，其中每个类表示为`[passi, totali]`。 价值`passi`告诉我们目前有多少学生通过了考试，同时`totali`告诉我们该班级的学生总数。 

某班的通过率是：$\frac{pass_i}{total_i}$我们还被赋予`extraStudents`，并且每个额外的学生都保证通过他们被分配到的班级。 如果我们在一个班级中增加一名学生，那么通过的学生人数和学生总数都会增加一名。 

例如，如果一个类是`[3,5]`，那么在添加一名保证通过的学生之后，它就变成了`[4,6]`。 

目标是将所有额外的学生分配到各个班级，以便最终的平均通过率尽可能高。 

平均通过率为：$\frac{1}{n}\sum_{i=1}^{n}\frac{pass_i}{total_i}$在哪里`n`是班级数量。 

限制条件很大：

 - 最多`10^5`类
 - 最多`10^5`额外的学生

 这些限制立即告诉我们，昂贵的重复扫描方法行不通。 任何比粗略更糟糕的解决方案`O((n + extraStudents) log n)`可能会超时。 

一个重要的观察结果是，将学生添加到不同的班级会带来不同的改进。 通过率低的班级可能比已经接近完美的班级从额外的及格学生中受益更多。 

该问题保证：

 - 每个班级至少有一名及格学生
 -`passi <= totali`- 至少有一名额外学生

 重要的边缘情况包括：

 - 已有比例的课程`1.0`， 例如`[5,5]`- 输入中只有一类
 - 大量额外学生重复分配到同一班级
 - 多个类别具有相同的增益
 - 班级规模非常不均匀

 如果重新计算增益的效率低下，幼稚的实现很容易变得太慢。 

## 方法

 ### 蛮力方法

 蛮力的想法很简单。 对于每一个额外的学生，我们尝试将该学生分配到每个班级，并计算哪个分配使平均通过率增幅最大。 

班级中增加一名学生所获得的增长`[p, t]`是：$\left(\frac{p+1}{t+1}\right)-\left(\frac{p}{t}\right)$对于每个额外的学生：

 1. 迭代所有类
 2. 计算每个类别的增益
 3. 选择增益最大的类别
 4. 更新该类

 这是有效的，因为每一步都会贪婪地选择局部最佳改进。 

然而，这种方法太慢了。 如果我们有`n`类和`k`额外的学生，然后我们对每个学生的所有课程进行全面扫描。 

这导致`O(n * k)`时间复杂度，可以变成`10^10`最坏情况下的操作。 

### 最佳方法

 关键的见解是我们总是需要快速访问当前提供最大改进的类。 

这正是最大堆或优先级队列的设计目的。 

对于每个类别，我们计算其当前的边际收益：$\Delta=\frac{p+1}{t+1}-\frac{p}{t}$我们将类存储在按此增益排序的最大堆中。 

然后对于每个额外的学生：

 1. 提取增益最高的类
 2. 将学生添加到该班级
 3. 重新计算增益
 4.将更新后的类推回堆中

 这避免了重复扫描所有类。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * 额外学生) | O(1) | O(1) | 反复扫描每个学生的所有班级 |
 | 最佳 | O((n + 额外学生) log n) | O(n) | 使用最大堆有效检索最佳增益 |

 ## 算法演练

 1. 定义一个辅助函数，用于计算将一名及格学生添加到班级中所获得的收益。 

对于有以下课程的班级`p`通过的学生和`t`学生总数，增益为：$\left(\frac{p+1}{t+1}\right)-\left(\frac{p}{t}\right)$这个值告诉我们，如果我们将下一个额外的学生安置在那里，班级比例会提高多少。 
2. 构建包含所有类的最大堆。 

蟒蛇的`heapq`默认情况下是最小堆，因此我们存储负增益来模拟最大堆行为。 

每个堆条目存储：

 - 电流增益
 - 及格学生
 - 学生总数
 3、反复分配额外的学生。 

虽然我们还有额外的学生：

 - 弹出增益最大的类别
 - 添加一名学生，意思是：

 -`pass += 1`-`total += 1`- 重新计算更新类别的增益
 - 将更新后的类推回到堆中

 这保证了每个额外的学生都会去到当时平均成绩提高最多的地方。 
4. 计算最终平均值。 

所有任务完成后：

 - 将堆中的所有类别比率相加
 - 除以班级数量

 ### 为什么它有效

 该算法之所以有效，是因为我们在每一步都选择边际改进最大的类别。 随着更多学生的添加，将学生分配到班级的收益会减少，这会创建适合优先级队列的贪婪结构。 

堆始终包含正确的下一个最佳选择，因此重复选择最大增益会产生全局最优结果。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def maxAverageRatio(self, classes: List[List[int]], extraStudents: int) -> float:
        
        def gain(passed: int, total: int) -> float:
            return (passed + 1) / (total + 1) - passed / total

        max_heap = []

        for passed, total in classes:
            current_gain = gain(passed, total)
            heapq.heappush(max_heap, (-current_gain, passed, total))

        for _ in range(extraStudents):
            negative_gain, passed, total = heapq.heappop(max_heap)

            passed += 1
            total += 1

            updated_gain = gain(passed, total)
            heapq.heappush(max_heap, (-updated_gain, passed, total))

        total_ratio = 0.0

        while max_heap:
            _, passed, total = heapq.heappop(max_heap)
            total_ratio += passed / total

        return total_ratio / len(classes)
```实现从一个名为的辅助函数开始`gain`，它计算添加一名保证通过的学生后，班级获得的进步程度。 

然后创建一个堆来存储所有类。 由于Python仅提供最小堆，因此使用负增益，以便最大增益的行为类似于堆排序中的最小值。 

每次迭代都会分配一名额外的学生。 具有最大增益的类将从堆中删除、更新并使用其新的增益值再次插入。 

最后，在所有作业完成后，代码通过将所有类别的比率相加并除以类别数量来计算平均通过率。 

## 解决方案```go
package main

import (
	"container/heap"
)

type Class struct {
	gain   float64
	passed int
	total  int
}

type MaxHeap []Class

func (h MaxHeap) Len() int {
	return len(h)
}

func (h MaxHeap) Less(i, j int) bool {
	return h[i].gain > h[j].gain
}

func (h MaxHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MaxHeap) Push(x interface{}) {
	*h = append(*h, x.(Class))
}

func (h *MaxHeap) Pop() interface{} {
	old := *h
	n := len(old)
	item := old[n-1]
	*h = old[:n-1]
	return item
}

func gain(passed int, total int) float64 {
	return float64(passed+1)/float64(total+1) -
		float64(passed)/float64(total)
}

func maxAverageRatio(classes [][]int, extraStudents int) float64 {
	h := &MaxHeap{}

	for _, class := range classes {
		passed := class[0]
		total := class[1]

		heap.Push(h, Class{
			gain:   gain(passed, total),
			passed: passed,
			total:  total,
		})
	}

	for extraStudents > 0 {
		best := heap.Pop(h).(Class)

		best.passed++
		best.total++
		best.gain = gain(best.passed, best.total)

		heap.Push(h, best)

		extraStudents--
	}

	totalRatio := 0.0

	for h.Len() > 0 {
		current := heap.Pop(h).(Class)
		totalRatio += float64(current.passed) / float64(current.total)
	}

	return totalRatio / float64(len(classes))
}
```Go 实现使用`container/heap`包来实现最大堆。 由于 Go 的堆接口是可定制的，`Less`功能相反，因此较大的增益具有较高的优先级。 

与 Python 不同，Go 需要显式的堆类型定义和接口方法。 浮点除法还需要使用显式转换`float64`。 

逻辑本身与 Python 解决方案相同。

```堆为每个类存储一个条目，因此辅助空间的使用是线性的。 

## 测试用例```python
from typing import List
import math

class Solution:
    def maxAverageRatio(self, classes: List[List[int]], extraStudents: int) -> float:
        import heapq

        def gain(passed: int, total: int) -> float:
            return (passed + 1) / (total + 1) - passed / total

        heap = []

        for passed, total in classes:
            heapq.heappush(heap, (-gain(passed, total), passed, total))

        for _ in range(extraStudents):
            _, passed, total = heapq.heappop(heap)

            passed += 1
            total += 1

            heapq.heappush(heap, (-gain(passed, total), passed, total))

        result = 0.0

        while heap:
            _, passed, total = heapq.heappop(heap)
            result += passed / total

        return result / len(classes)

solution = Solution()

# Provided example 1
assert math.isclose(
    solution.maxAverageRatio([[1, 2], [3, 5], [2, 2]], 2),
    0.78333,
    rel_tol=1e-5
)

# Provided example 2
assert math.isclose(
    solution.maxAverageRatio([[2, 4], [3, 9], [4, 5], [2, 10]], 4),
    0.53485,
    rel_tol=1e-5
)

# Single class only
assert math.isclose(
    solution.maxAverageRatio([[1, 2]], 1),
    2 / 3,
    rel_tol=1e-5
)

# Already perfect ratio
assert math.isclose(
    solution.maxAverageRatio([[5, 5]], 10),
    1.0,
    rel_tol=1e-5
)

# Multiple identical classes

 ## 边缘情况

 一个重要的边缘情况是当一类已经具有完美的通过率时，例如`[5,5]`。 添加另一名保证通过的学生会将班级更改为`[6,6]`，仍然有比率`1.0`。 增益变为零，因此堆自然会降低这些类的优先级，除非所有类都已经是完美的。 

另一个重要的情况是只有一个类时。 在这种情况下，每个额外的学生都必须进入同一个班级。 该算法仍然可以正常工作，因为堆只包含一个重复更新的条目。 

当多个类具有相同的增益时，就会出现第三种棘手的情况。 一些实现错误地假设增益是唯一的。 堆自然地处理绑定，因为可以选择任何绑定类而不影响正确性。 

最后的边缘情况涉及非常大的总数，例如`[1,100000]`。 浮点精度在这里变得很重要，因为增益可能非常小。 两种实现都仔细地使用浮点运算，并依赖于问题的可接受精度阈值`10^-5`。
