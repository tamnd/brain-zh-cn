 # LeetCode 1762，海景建筑

 ## 问题理解

 这个问题给了我们一个名为`heights`，其中每个元素代表建筑物的高度。 建筑物从左到右呈直线排列，海洋位于最后一座建筑物的右侧。 

如果一栋建筑物右侧的每栋建筑物都严格较短，则该建筑物具有海景。 如果右侧存在一栋高度大于或等于当前建筑物的建筑物，则当前建筑物的视野将被遮挡。 

任务是返回所有可以看到海洋的建筑物的索引。 返回的索引必须按升序排序。 

例如，给定：```
heights = [4,2,3,1]
```建筑`0`有高度`4`。 右边的每栋建筑的高度都较小，因此可以看到海景。 

建筑`1`有高度`2`。 建筑`2`有高度`3`，挡住了视线，所以建筑`1`不符合资格。 

建筑`2`有高度`3`。 它右边唯一的建筑物是高度`1`，所以它符合条件。 

建筑`3`是最右边的建筑，所以总是能看到海景。 

答案是：```
[0,2,3]
```约束条件很重要：

 -`1 <= heights.length <= 10^5`-`1 <= heights[i] <= 10^9`该阵列最多可以包含十万座建筑物，因此低效的二次解可能会变得太慢。 高度也可能非常大，这意味着我们应该避免对小值范围或频率计数的假设。 

一些边缘情况很重要：

 - 单一建筑总是可以看到海景。 
- 严格降低高度意味着每栋建筑都可以看到海景。 
- 严格增加高度意味着只有最后一座建筑符合资格。 
- 相同的高度很重要，因为条件要求右侧的建筑物严格较小。 如果两栋建筑高度相同，左边的那栋看不到海景。 
- 非常大的输入需要`O(n)`获得良好性能的解决方案。 

## 方法

 ### 蛮力方法

 最直接的解决办法就是对每栋建筑进行独立检查。 

对于每栋建筑`i`，我们扫描其右侧的所有建筑物。 如果我们发现一座建筑物的高度大于或等于`heights[i]`，然后构建`i`没有海景。 

如果不存在这样的建筑物，我们添加`i`到结果。 

这种方法是正确的，因为它直接实现了海景的定义。 然而，对于大量输入来说，它的效率很低，因为每个建筑物都可以与几乎所有其他建筑物进行比较。 

在最坏的情况下，这大致会导致：```
1 + 2 + 3 + ... + (n-1)
```比较，即`O(n^2)`时间复杂度。 

和`n = 10^5`，这太慢了。 

### 最佳方法

 关键的观察结果是，建筑物只需要知道其右侧建筑物的最大高度。 

如果我们从右向左处理数组，我们就可以保持迄今为止看到的最高的建筑物。 

假设我们目前正在检查建筑物`i`：

- 如果`heights[i]`大于其右侧看到的最大高度，则构建`i`享有海景。 
- 否则，其视野会被阻挡。 

加工后建筑`i`，我们更新运行最大值。 

这是有效的，因为从右向左扫描可以保证运行最大值始终代表当前位置右侧最高的建筑物。 

这将复杂性降低到线性时间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) 不包括输出 | 将每座建筑物与其右侧的所有建筑物进行比较 |
 | 最佳 | O(n) | O(1) 不包括输出 | 从右向左移动，同时跟踪最大高度 |

 ## 算法演练

 1. 初始化一个空列表，名为`result`。 

该列表将存储可以看到海洋的建筑物的索引。 
2. 初始化一个名为`max_height_right`到`0`。 

该变量表示从右向左扫描时迄今为止遇到的最高建筑物。 
3. 从最后一个索引向下遍历数组到第一个索引。 

我们从右向左移动，因为海洋在右侧。 这使我们能够知道当前建筑物右侧的所有建筑物。 
4. 对于每座建筑物，将其高度与`max_height_right`。 

如果当前建筑物的高度严格更大，则其右侧的每座建筑物都更矮，因此该建筑物具有海景。 
5. 如果建筑物符合条件，请将其索引附加到`result`。 

由于我们向后遍历，因此索引以相反的顺序添加。 
6. 更新`max_height_right`。 

将其设置为当前最大值和当前建筑物高度之间的较大值。 
7. 反转`result`返回之前列出。 

这将根据问题的需要将索引恢复为递增顺序。 

### 为什么它有效

 该算法保持了一个重要的不变量：

 > 每一步，`max_height_right`将最高的建筑物严格存储在当前位置的右侧。 

如果当前建筑物比该值高，则其右侧的每个建筑物都较小，这与海景条件完全匹配。 

由于在反向遍历过程中始终保持不变式，因此每个符合条件的建筑物都被正确识别。 

## Python 解决方案```python
from typing import List

class Solution:
    def findBuildings(self, heights: List[int]) -> List[int]:
        result = []
        max_height_right = 0

        for index in range(len(heights) - 1, -1, -1):
            if heights[index] > max_height_right:
                result.append(index)

            max_height_right = max(max_height_right, heights[index])

        result.reverse()
        return result
```实现首先创建一个空的`result`列表和一个名为的变量`max_height_right`。 

该循环使用以下命令向后迭代数组：```python
range(len(heights) - 1, -1, -1)
```这从最后一个索引开始并向索引移动`0`。 

在循环内，我们检查当前建筑物是否比右侧之前看到的所有建筑物都高。 自从`max_height_right`商店右侧最高的建筑，对比：```python
heights[index] > max_height_right
```直接决定建筑物是否有海景。 

如果条件为真，则将索引添加到`result`。 

接下来我们更新`max_height_right`因此未来的迭代可以正确地知道右侧最高的建筑物。 

最后，由于索引是按相反顺序收集的，因此我们在返回结果列表之前反转结果列表。 

## 解决方案```go
func findBuildings(heights []int) []int {
    result := []int{}
    maxHeightRight := 0

    for i := len(heights) - 1; i >= 0; i-- {
        if heights[i] > maxHeightRight {
            result = append(result, i)
        }

        if heights[i] > maxHeightRight {
            maxHeightRight = heights[i]
        }
    }

    // Reverse result
    left, right := 0, len(result)-1
    for left < right {
        result[left], result[right] = result[right], result[left]
        left++
        right--
    }

    return result
}
```Go 解决方案遵循与 Python 实现相同的逻辑。 

一个区别是 Go 没有提供内置的列表反转方法，因此我们使用两指针交换方法手动反转切片。 

Go 切片随着元素的添加而动态增长，类似于 Python 列表。 

这里不存在整数溢出问题，因为这些约束完全符合 Go 的标准`int`在现代系统上键入。

 ## 边缘情况

 单个建筑物是最简单的输入。 由于右侧没有建筑物，因此它自动具有海景。 粗心的实现可能会错误地初始化比较值，或者在向后遍历时失败。 该解决方案可以自然地处理它，因为将单个建筑物与初始最大值进行比较`0`并添加到结果中。 

等高建筑是另一个重要的边缘情况。 该问题要求右侧的所有建筑物严格变小。 这意味着相同的高度仍然会阻挡视线。 例如：```
[2,2,2]
```只有最后一座建筑符合资格。 实现正确使用了条件：```
heights[index] > max_height_right
```而不是`>=`，保留了严格的不平等要求。 

严格增加数组可能会暴露朴素逻辑中的缺陷。 例如：```
[1,2,3,4]
```只有最后一座建筑可以看到海景，因为每座较早的建筑都被右侧更高的建筑挡住了。 反向遍历正确地保持了运行最大值并过滤掉了所有较早的建筑物。 

严格减少阵列也很重要，因为每个建筑物都符合要求。 一些不正确的实现会意外删除较早的有效建筑物或错误处理排序。 由于从右到左遇到的每个建筑物都比当前最大值高，因此收集每个索引，然后将其反转为正确的递增顺序。
