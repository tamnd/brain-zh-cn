[LeetCode 第 1778 题](https://leetcode.com/problems/shortest-path-in-a-hidden-grid/)

 **难度：** 🟡 中等
 **主题：** 数组、深度优先搜索、广度优先搜索、矩阵、交互

 ## 解决方案

 ## 问题理解

 这个问题要求我们找到从机器人未知的起始位置到网格内隐藏目标的最短路径。 主要挑战是网格本身无法直接访问。 我们不是接收矩阵作为输入，而是通过`GridMaster`API。 

机器人只能确定本地信息：

 -`canMove(direction)`告诉我们是否可以朝某个方向移动。 
-`move(direction)`物理地移动机器人。 
-`isTarget()`告诉当前单元格是否是目标。 

网格的实际尺寸未知。 我们不知道机器人从哪里开始，目标位于哪里，或者哪些单元格被阻挡。 发现网格的唯一方法是通过交互方式探索它。 

目标是返回从起始位置到达目标所需的最少移动次数。 如果目标无法到达，我们返回`-1`。 

尽管隐藏网格可能有那么大`500 x 500`，我们只关心从起点开始可达的区域。 由于我们无法直接访问任意坐标，因此我们必须在探索时自己模拟坐标。 

最重要的观察是，这实际上是一个图遍历问题。 每个可达单元都是一个节点，相邻可步行单元之间存在边。 

一些边缘情况很重要：

 - 即使目标存在于网格中的某个位置，也可能无法到达。 
-可达区域可能包含循环，因此重新访问单元格而不跟踪访问的状态将导致无限递归或重复工作。 
- 由于运动是物理性的，因此每个 DFS 步骤都必须小心回溯以恢复机器人之前的位置。 
- 网格边界未知，因此必须相对于起始单元动态分配坐标。 
- 目标可能邻近起始位置或非常远。 

## 方法

 ### 蛮力方法

 一种简单的方法会尝试重复搜索目标，同时从起始单元探索所有可能的运动序列。 

例如，我们可以在每一步递归地尝试每个可能的方向，而无需记录以前访问过的状态。 每当我们移动时，我们都会继续递归分支，直到找到目标或移动变得不可能。 

这种方法在技术上是正确的，因为它最终枚举了所有可达路径。 然而，它的效率极其低下，因为相同的单元会通过不同的路径重复访问。 由于网格可以包含循环，因此递归树可以呈指数增长。 

此外，由于移动是交互式的和物理的，因此过度的重新访问会因重复的 API 调用而产生巨大的开销。 

### 最佳方法

 关键的见解是我们应该将问题分为两个阶段：

 1. 使用 DFS 发现隐藏网格的可达部分。 
2. 在发现的地图上运行 BFS 来计算最短路径。 

DFS 非常适合探索，因为它天然支持回溯。 探索期间：

 - 我们为单元分配虚拟坐标。 
- 我们记录哪些小区可以到达。 
- 如果遇到，我们会识别目标位置。 

关键的细节是，在递归地探索一个方向之后，我们必须将机器人物理移动回其先前的位置。 如果没有这个回溯步骤，未来的探索将从错误的位置开始。 

一旦重建了可达网格，交互部分就完成了。 我们现在有一个标准的图形问题。 由于所有边的权重相等，BFS 保证了最短路径。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 反复重访相同的状态和路径 |
 | 最佳 | O(V + E) | O(V) | DFS重构网格，BFS寻找最短路径 |

 这里，`V`表示可达单元格的数量，`E`表示它们之间的邻接关系。 

## 算法演练

 1. 首先将机器人的初始位置指定为虚拟坐标`(0, 0)`。 
2. 创建一个探索可达单元格的 DFS 函数。 DFS接收当前虚拟坐标。 
3. 维护一个访问集，这样我们就不会两次探索同一个虚拟坐标。 这可以防止无限循环和冗余工作。 
4. 在每个 DFS 位置：

 - 将当前坐标标记为已访问。 
- 查看`master.isTarget()`。 
- 如果为 true，则存储目标坐标。 
5. 对于四个方向中的每一个：

 - 使用`master.canMove(direction)`以确定是否可以移动。 
- 如果移动受阻，请跳过该方向。 
- 否则计算邻居坐标。 
6. 如果邻居没有被访问过：

 - 打电话`master.move(direction)`物理移动机器人。 
- 递归地 DFS 进入邻居。 
- 递归完成后，使用相反方向将机器人向后移动。 
7.回溯步骤至关重要，因为DFS假设递归调用返回到调用者的状态。 由于机器人物理移动，我们必须手动恢复其之前的位置。 
8. DFS 完成后，我们重建了所有可达单元并可能识别了目标位置。 
9. 如果从未找到目标，则返回`-1`。 
10. 否则执行 BFS`(0, 0)`:

 - 使用队列存储`(row, col, distance)`。 
- 逐级扩大邻居。 
- 第一次到达目标坐标时，返回距离。 
11. BFS 保证最短路径，因为每次移动的成本相等。 

### 为什么它有效

 DFS 保证每个可到达的单元都被恰好探索一次。 因为我们在递归探索后正确回溯，所以机器人的物理位置始终与递归状态匹配。 

发现的地图准确地表示了可达图。 未加权图上的 BFS 始终会找到两个节点之间的最小边数。 因此，返回的距离是从起点到目标的真正最短路径。 

## Python 解决方案```python
from collections import deque
from typing import Dict, Set, Tuple

# """
# This is GridMaster's API interface.
# You should not implement it, or speculate about its implementation
# """
# class GridMaster(object):
#     def canMove(self, direction: str) -> bool:
#         pass
#
#     def move(self, direction: str) -> None:
#         pass
#
#     def isTarget(self) -> bool:
#         pass

class Solution(object):
    def findShortestPath(self, master: 'GridMaster') -> int:
        directions = {
            'U': (-1, 0),
            'D': (1, 0),
            'L': (0, -1),
            'R': (0, 1)
        }

        opposite = {
            'U': 'D',
            'D': 'U',
            'L': 'R',
            'R': 'L'
        }

        reachable = set()
        visited = set()
        target = [None]

        def dfs(row: int, col: int) -> None:
            visited.add((row, col))
            reachable.add((row, col))

            if master.isTarget():
                target[0] = (row, col)

            for direction, (dr, dc) in directions.items():
                next_row = row + dr
                next_col = col + dc

                if (next_row, next_col) in visited:
                    continue

                if not master.canMove(direction):
                    continue

                master.move(direction)

                dfs(next_row, next_col)

                master.move(opposite[direction])

        dfs(0, 0)

        if target[0] is None:
            return -1

        queue = deque([(0, 0, 0)])
        bfs_visited = {(0, 0)}

        while queue:
            row, col, distance = queue.popleft()

            if (row, col) == target[0]:
                return distance

            for dr, dc in directions.values():
                next_row = row + dr
                next_col = col + dc

                if (next_row, next_col) not in reachable:
                    continue

                if (next_row, next_col) in bfs_visited:
                    continue

                bfs_visited.add((next_row, next_col))
                queue.append((next_row, next_col, distance + 1))

        return -1
```实施分为两个明确的阶段。 

第一阶段使用 DFS 重建隐藏网格。 我们维护两组：

 -`visited`确保 DFS 不会重新访问坐标。 
-`reachable`存储每个可访问的单元格。 

这`target`变量存储为单元素列表，因此嵌套的 DFS 调用可以修改它。 

在 DFS 期间，我们迭代所有四个方向。 如果可以移动并且邻居尚未被访问，我们会物理移动机器人，递归地探索邻居，然后使用相反的方向回溯。 

探索完成后，第二阶段将在发现的图上运行 BFS。 由于所有边的权重相等，BFS 自然会计算最短路径。 

BFS 队列存储坐标以及距起始单元的当前距离。 

## 解决方案```go
/**
 * // This is the GridMaster's API interface.
 * // You should not implement it, or speculate about its implementation
 * type GridMaster struct {
 * }
 *
 * func (this *GridMaster) CanMove(direction byte) bool {}
 * func (this *GridMaster) Move(direction byte) {}
 * func (this *GridMaster) IsTarget() bool {}
 */

type Pair struct {
    row int
    col int
}

type State struct {
    row      int
    col      int
    distance int
}

func findShortestPath(master *GridMaster) int {
    directions := map[byte]Pair{
        'U': {-1, 0},
        'D': {1, 0},
        'L': {0, -1},
        'R': {0, 1},
    }

    opposite := map[byte]byte{
        'U': 'D',
        'D': 'U',
        'L': 'R',
        'R': 'L',
    }

    reachable := make(map[Pair]bool)
    visited := make(map[Pair]bool)

    targetFound := false
    target := Pair{}

    var dfs func(int, int)

    dfs = func(row int, col int) {
        current := Pair{row, col}

        visited[current] = true
        reachable[current] = true

        if master.IsTarget() {
            targetFound = true
            target = current
        }

        for direction, delta := range directions {
            nextRow := row + delta.row
            nextCol := col + delta.col

            next := Pair{nextRow, nextCol}

            if visited[next] {
                continue
            }

            if !master.CanMove(direction) {
                continue
            }

            master.Move(direction)

            dfs(nextRow, nextCol)

            master.Move(opposite[direction])
        }
    }

    dfs(0, 0)

    if !targetFound {
        return -1
    }

    queue := []State{{0, 0, 0}}
    bfsVisited := make(map[Pair]bool)
    bfsVisited[Pair{0, 0}] = true

    for len(queue) > 0 {
        current := queue[0]
        queue = queue[1:]

        if current.row == target.row && current.col == target.col {
            return current.distance
        }

        for _, delta := range directions {
            nextRow := current.row + delta.row
            nextCol := current.col + delta.col

            next := Pair{nextRow, nextCol}

            if !reachable[next] {
                continue
            }

            if bfsVisited[next] {
                continue
            }

            bfsVisited[next] = true

            queue = append(queue, State{
                row:      nextRow,
                col:      nextCol,
                distance: current.distance + 1,
            })
        }
    }

    return -1
}
```Go 实现遵循与 Python 版本相同的总体策略。 

由于 Go 没有元组、自定义结构体`Pair`和`State`用于坐标和 BFS 状态。 

地图有`Pair`键的作用类似于 Python 哈希集。 BFS 是使用切片作为队列来实现的，在遍历过程中从前面删除元素。 

Go 使用`byte`而不是`string`用于方向字符，因为 API 签名需要字节值。

 ## 边缘情况

 当目标无法到达时，就会出现一种重要的边缘情况。 DFS 探索可能完全遍历可到达区域而不会遇到目标。 有缺陷的实现可能仍会尝试向未定义的目标坐标进行 BFS。 此实现通过在启动 BFS 之前显式检查是否发现目标来避免该问题。 

另一个关键的边缘情况涉及可达图中的循环。 如果没有访问集，DFS 可能会永远重复访问相同的坐标。 该实现将每个探索的虚拟坐标存储在`visited`，确保每个可达单元仅被处理一次。 

回溯正确性是另一个微妙的问题。 由于机器人在 DFS 期间发生物理移动，因此仅靠递归不足以恢复状态。 如果实现在递归探索后忘记返回，则未来的 DFS 调用将从错误的物理位置进行操作，从而破坏整个遍历。 该解决方案通过在递归调用返回后立即发出相反的移动来保证正确性。 

最后的边缘情况涉及极深的可到达区域，例如长走廊。 DFS 递归深度随着路径长度而增长。 虽然可达组件受到问题约束的限制，但算法仍然可以正确处理这些情况，因为每次递归调用都会探索一个新坐标，然后安全地回溯。
