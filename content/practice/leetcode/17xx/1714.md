[LeetCode 第 1714 题](https://leetcode.com/problems/sum-of-special-evenly-spaced-elements-in-array/)

 **难度：** 🔴难
 **主题：** 数组、动态规划

 ## 解决方案

 ## 问题理解

 该问题需要计算整数数组的特定子集的总和`nums`基于查询。 每个查询`[xi, yi]`指定起始索引`xi`和一个步骤`yi`。 此查询的总和包括所有元素`nums[j]`这样`j`开始于`xi`并以步长增加`yi`（IE。，`j = xi, xi + yi, xi + 2*yi, ...`) 直到数组末尾。 每个查询的结果必须取模`10^9 + 7`。 

输入如下：`nums`是一个长度为非负整数的列表`n`最多`5 * 10^4`。 查询数组最多可以包含`1.5 * 10^5`查询和步长值`yi`在一个查询中最多是`5 * 10^4`。 这些约束表明，迭代每个查询的所有步骤的简单解决方案可能会太慢。 

关键的边缘情况包括查询，其中步骤`yi`大于剩余数组长度、从最后一个索引开始的查询以及所有数字为零或较大的数组。 问题保证`xi`是有效的并且`yi >= 1`，因此无需检查无效索引或零步长。 

## 方法

 ### 蛮力

 暴力方法将通过迭代来独立处理每个查询`nums`开始于`xi`并以间隔添加元素`yi`。 这工作正常，但最多`1.5 * 10^5`查询和步骤`5 * 10^4`，时间复杂度可以达到`O(Q * n / y)`在最坏的情况下，这对于最大的投入是不可行的。 

### 优化方法

 关键的观察是具有相同步骤的查询`yi`可以重复使用预先计算的位置模数总和`yi`。 对于固定的`yi`， 有`yi`索引时可能存在的余数`nums`。 通过预先计算每个余数的前缀和，可以在恒定时间内回答任何查询。 这是可行的，因为最大步长`yi`是`5 * 10^4`，限制我们需要维护的金额。 

因此，该算法将查询分为两类：小查询`yi`（达到阈值，例如 √n）可以使用预先计算的总和来处理，并且可以使用大的查询来处理`yi`直接处理，因为求和的步骤较少。 这种混合方法有效地平衡了时间和空间复杂性。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(Q * n / y) | O(1) | O(1) | 对每个查询进行简单迭代，对于大输入来说太慢 |
 | 最佳 | O(n * √n + Q) | O(n * √n) | O(n * √n) | 预先计算小步的总和，直接处理大步 |

 ## 算法演练

 1. 定义阈值`B`作为平方根`n`。 步骤`yi`以下`B`被认为很小，上面的步骤`B`被认为是大的。 该阈值平衡了预先计算的总和和查询计算的数量。 
2. 对于所有小步骤`yi <= B`，创建一个字典，其中每个键是一个步骤，每个值是每个可能的余数模的前缀和列表`yi`。 
3. 以相反的顺序预先计算每个余数的总和。 对于剩余的`r`和步骤`yi`,`prefix[r][i]`包含总和`nums[i], nums[i + yi], ...`直到数组末尾。 
4. 对于小查询`yi`，直接使用起始索引检索预先计算的和`xi`模数`yi`。 
5. 对于大的查询`yi`，迭代从以下位置开始的索引`xi`与步骤`yi`并直接累加总和，取模`10^9 + 7`。 
6. 收集输出数组中的所有查询结果。 

**为什么有效：** 中的每个元素`nums`通过小步长的预先计算的前缀和或大步长的直接求和，准确地包含在正确的总和集中。 通过根据余数预先计算总和，该算法确保不会重复计算并保持所有查询的正确性。 

## Python 解决方案```python
from typing import List

class Solution:
    def solve(self, nums: List[int], queries: List[List[int]]) -> List[int]:
        MOD = 10**9 + 7
        n = len(nums)
        B = int(n ** 0.5) + 1  # Threshold for small steps
        small = {}
        
        # Precompute sums for small steps
        for y in range(1, B):
            small[y] = [0] * y
            for i in range(n - 1, -1, -1):
                small[y][i % y] = (nums[i] + small[y][i % y]) % MOD
        
        answer = []
        for xi, yi in queries:
            if yi < B:
                answer.append(small[yi][xi % yi] % MOD)
            else:
                s = 0
                for j in range(xi, n, yi):
                    s = (s + nums[j]) % MOD
                answer.append(s)
        return answer
```实现首先定义一个阈值`B`对于小步骤并预先计算这些步骤的总和。 然后，它通过查找小步长的预先计算的总和或直接对大步长的元素求和来处理每个查询。 所有总和均以模计算`10^9 + 7`。 

## 解决方案```go
package main

func solve(nums []int, queries [][]int) []int {
    const MOD = int(1e9 + 7)
    n := len(nums)
    B := 1
    for B*B <= n {
        B++
    }

    small := make(map[int][]int)
    for y := 1; y < B; y++ {
        small[y] = make([]int, y)
        for i := n - 1; i >= 0; i-- {
            r := i % y
            small[y][r] = (nums[i] + small[y][r]) % MOD
        }
    }

    answer := make([]int, len(queries))
    for idx, q := range queries {
        xi, yi := q[0], q[1]
        if yi < B {
            answer[idx] = small[yi][xi%yi]
        } else {
            s := 0
            for j := xi; j < n; j += yi {
                s = (s + nums[j]) % MOD
            }
            answer[idx] = s
        }
    }
    return answer
}
```在 Go 中，方法几乎相同。 地图`small`存储小步骤的预先计算的总和。 小心切片初始化和模运算以避免溢出。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n * √n + Q) | 预计算小步骤需要 O(n*B)，迭代大步骤需要 O(Q * n / B) ≤ O(Q) |
 | 空间| O(n * √n) | O(n * √n) | 存储每个余数模 y 的预先计算的总和，直到阈值 B |

 推理是，对于小步长，预先计算的最大和数与`n * B`，对于小步长，每个查询的处理时间为 O(1)；对于大步长，每个查询的处理时间为 O(n/B)。
