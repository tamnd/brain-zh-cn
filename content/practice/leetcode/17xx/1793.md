[LeetCode 问题 1793](https://leetcode.com/problems/maximum-score-of-a-good-subarray/)

 **难度：** 🔴难
 **主题：** 数组、两个指针、二分查找、堆栈、单调堆栈

 ## 解决方案

 ## 问题理解

 在这个问题中，我们给出一个整数数组`nums`以及具体的索引`k`。 我们必须找到一个包含索引的连续子数组`k`，并在所有此类子数组中，最大化以下分数：$$\text{score} = \min(\text{subarray}) \times \text{length of subarray}$$所选子数组内的最小元素决定了分数的限制值，而子数组长度决定了有多少元素对该分数有贡献。 挑战来自平衡这两个因素。 扩展子数组会增加长度，但也可能会减少最小值。 

仅当子数组包含索引时才被认为是“好的”`k`。 这个限制很重要，因为我们不会搜索所有可能的子数组。 每个候选区间必须满足：$$i \le k \le j$$输入大小可以大到：$$1 \le n \le 10^5$$这立即告诉我们二次方法会太慢。 任何比粗略更糟糕的算法$O(n \log n)$存在超时的风险，并且$O(n)$解决方案是理想的。 

里面的数值`nums`都是正整数，这简化了推理，因为增加长度总是有帮助的，除非最小值变得太小。 

一些边缘情况很重要：

 - 当数组只有一个元素时，答案就是该元素。 
- 什么时候`k`如果位于数组的开头或结尾，则某些步骤只能在一个方向上进行扩展。 
- 当许多值相等时，必须小心避免错误的边界处理。 
- 严格增加或严格减少数组可能会暴露扩展逻辑中的错误。 
- 非常小的最小值可以支配大的区间，因此盲目扩展并不总是最佳的。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每个可能包含索引的子数组`k`。 

对于每个左边界`i`这样`0 <= i <= k`，以及每个右边界`j`这样`k <= j < n`，我们计算：

 1. 中的最小值`nums[i:j+1]`2、长度`(j - i + 1)`3. 分数

 然后我们保留找到的最高分数。 

这种方法是正确的，因为它详尽地检查了每个有效的好子数组。 然而，对于限制而言，它太慢了。 

有$O(n^2)$可能的子数组包含`k`，并且天真地计算每个子数组的最小值会花费另一个$O(n)$。 即使进行增量优化，总运行时间仍然$O(n^2)$，这是不可接受的$n = 10^5$。 

### 最佳方法

 关键的观察结果是分数由所选区间内的最小值决定。 

假设我们固定一个特定值作为最小值。 然后我们想要包含最宽可能的子数组`k`其中每个元素至少是该最小值。 

这自然会导致两指针贪婪扩张策略。 

我们从尽可能小的好子数组开始：$$[left, right] = [k, k]$$目前的最小值是`nums[k]`。 

然后我们一步步向外扩展。 在每一步中，我们都会选择相邻值较大的一侧，因为这样做可以尽可能长时间地保持最小值尽可能大。 

随着窗口展开：

 - 宽度增加
 - 最小值可能会降低
 - 我们不断计算候选人分数

 由于在扩展过程中每个索引最多被访问一次，因此整个算法以线性时间运行。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 检查包含的每个有效子数组`k`|
 | 最佳 | O(n) | O(1) | O(1) | 贪婪两指针扩展保持窗口最小 |

 ## 算法演练

 ### 第 1 步：初始化窗口

 从以下开始：

 -`left = k`-`right = k`当前子数组仅包含索引处的元素`k`。 

当前最小值为：$$currentMin = nums[k]$$最初的答案也是`nums[k]`。 

### 步骤 2：扩展直至覆盖整个数组

 趁双方还可以扩张的时候继续。 

在每次迭代中，我们决定是向左还是向右移动。 

### 第三步：选择更好的方向

 如果双方都可用：

 - 比较`nums[left - 1]`和`nums[right + 1]`- 向更大的价值扩展

 为什么？ 

因为分数取决于窗口中的最小值。 选择较大的相邻元素会延迟最小值的减小。 

如果只有一侧可用，则朝该方向扩展。 

### 步骤 4：更新当前最小值

 扩展后：$$currentMin = \min(currentMin, newlyAddedValue)$$这有效地维持了当前窗口的最小值。 

### 第 5 步：计算分数

 当前窗口长度为：$$right - left + 1$$分数变为：$$currentMin \times (right - left + 1)$$如果这个分数更大，请更新答案。 

### 第 6 步：继续扩展

 重复此操作，直到两个指针都到达数组边界。 

### 为什么它有效

 贪心选择之所以有效，是因为分数很大程度上取决于最小值。 向更大的邻近值扩展可以在更长的时间内保留更大的最小值。 每个可能的窗口大小包含`k`最终考虑的是，对于每种尺寸，算法都会构建通过向外扩展可获得的最佳可能的最小值。 由于窗口只会扩展而不会缩小，因此可以有效地探索所有有效的候选区间。 

## Python 解决方案```python
from typing import List

class Solution:
    def maximumScore(self, nums: List[int], k: int) -> int:
        n = len(nums)

        left = k
        right = k

        current_min = nums[k]
        best_score = nums[k]

        while left > 0 or right < n - 1:

            if left == 0:
                right += 1
            elif right == n - 1:
                left -= 1
            elif nums[left - 1] > nums[right + 1]:
                left -= 1
            else:
                right += 1

            current_min = min(current_min, nums[left], nums[right])

            window_length = right - left + 1
            best_score = max(best_score, current_min * window_length)

        return best_score
```实现首先创建包含索引的最小有效子数组`k`。 两个指针都开始于`k`，这意味着窗口最初仅包含一个元素。 

变量`current_min`存储当前窗口内的最小值。 我们不是每次都重新计算最小值，而是在窗口扩展时增量更新它。 

在循环内部，算法决定向哪个方向扩展。 如果一侧已经到达边界，则另一侧必然发生扩张。 否则，我们会比较相邻值并转向较大的值。 

扩展后，更新最小值和窗口长度。 计算当前窗口的分数并与迄今为止看到的最佳答案进行比较。 

由于每个指针最多移动`n`次总计，运行时间保持线性。 

## 解决方案```go
func maximumScore(nums []int, k int) int {
    n := len(nums)

    left := k
    right := k

    currentMin := nums[k]
    bestScore := nums[k]

    for left > 0 || right < n-1 {

        if left == 0 {
            right++
        } else if right == n-1 {
            left--
        } else if nums[left-1] > nums[right+1] {
            left--
        } else {
            right++
        }

        currentMin = min(currentMin, nums[left])
        currentMin = min(currentMin, nums[right])

        windowLength := right - left + 1
        bestScore = max(bestScore, currentMin*windowLength)
    }

    return bestScore
}

func min(a, b int) int {
    if a < b {
        return a
    }
    return b
}

func max(a, b int) int {
    if a > b {
        return a
    }
    return b
}
```Go 实现遵循与 Python 版本相同的逻辑。 由于 Go 没有提供内置的`min`和`max`整数函数，辅助函数是手动定义的。 

Go 中的切片的行为与动态数组类似，因此指针操作自然有效。 整数溢出在这里不是一个问题，因为最大可能的分数是：$$2 \times 10^4 \times 10^5 = 2 \times 10^9$$它安全地适合 32 位有符号整数，而 Go 的`int`类型就足够了。

 ## 边缘情况

 当数组仅包含单个元素时，会出现一种重要的边缘情况。 在这种情况下，唯一可能的子数组是元素本身，并且分数等于该值。 假设扩展总是可能的实现可能会意外访问无效索引。 该解决方案可以自然地处理这种情况，因为循环条件立即失败。 

另一个棘手的情况发生在`k`位于数组的开头或结尾。 由于扩展只能在一个方向上进行，因此粗心的指针逻辑可能会导致越界错误。 该实现在比较相邻值之前显式检查边界条件，以确保安全移动。 

具有许多重复值的数组也会引入微妙的错误。 如果算法在扩展决策期间错误地假设严格不等式，则可能会跳过有效间隔或产生不一致的行为。 此实现通过在值相等时允许在任一方向上扩展来正确处理相等的相邻值。 

当最佳答案是一个非常小的区间（可能只是位于的单个元素）时，就会出现最后一个重要的边缘情况。`k`。 扩大窗口可能会大大降低最小值并破坏分数。 该实现在每次扩展后正确检查分数，同时保留初始单元素分数作为候选。
