 # LeetCode 1713，生成子序列的最少操作

 ## 问题理解

 问题给了我们两个数组，`target`和`arr`。 

这`target`数组包含不同的整数，这一点非常重要。 这`arr`数组可能包含重复项。 

我们可以执行插入操作`arr`。 在单个操作中，我们可以在数组中的任何位置插入任何整数。 我们的目标是让`target`成为的子序列`arr`使用最少的插入次数。 

子序列意味着我们可以从中删除元素`arr`而不改变其余元素的顺序。 因此，元素的顺序`target`必须出现在`arr`以完全相同的相对顺序。 

关键的观察是我们不需要使数组相同。 我们只需要每个元素`target`按顺序出现在内部某处`arr`。 

例如：

-`target = [5,1,3]`-`arr = [9,4,2,3,4]`目前，仅`3`相对于以正确的顺序出现`target`。 我们必须插入`5`和`1`，所以答案是`2`。 

限制条件非常大：

 -`target.length <= 10^5`-`arr.length <= 10^5`这立即告诉我们二次解太慢了。 任何接近的解决方案`O(n^2)`会超时。 我们周围需要一些东西`O(n log n)`。 

该问题还保证了`target`包含不同的整数。 这种保证是最佳解决方案的基础，因为它允许我们将每个值映射到唯一索引。 

一些边缘情况很重要：

 -`arr`可能包含许多重复项。 
-`arr`可能包含不存在的值`target`。 
-`target`可能已经是`arr`，给出答案`0`。 
-`arr`可能不包含任何目标值，这意味着我们必须插入每个目标元素。 
- 数组可能非常大，因此内存使用和算法效率很重要。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试计算最长的子序列`target`已经存在于里面`arr`。 

思考这个问题的一种方法是将其视为之间的最长公共子序列问题`target`和`arr`。 

如果我们找到最长公共子序列的长度，称其为`L`，那么：

 - 我们已经有了`L`元素的顺序正确。 
- 我们必须插入剩余的`target.length - L`元素。 

所以答案就变成了：$$\text{answer} = \text{len(target)} - LCS(target, arr)$$这种方法是正确的，因为 LCS 表示已经以正确的相对顺序出现的目标元素的最大数量。 

然而，LCS 的经典动态规划解决方案采用：$$O(n \times m)$$在哪里：

-`n = len(target)`-`m = len(arr)`两个长度都可达`10^5`，这变得完全不可行。 

### 最佳方法

 关键的见解来自以下事实：`target`包含不同的值。 

因为每个值都是唯一的，所以我们可以将每个目标值映射到其索引。 

例子：```
target = [6,4,8,1,3,2]

index map:
6 -> 0
4 -> 1
8 -> 2
1 -> 3
3 -> 4
2 -> 5
```现在我们迭代`arr`。 

每当一个值存在于`target`，我们将其替换为其相应的目标索引。 

对于前面的例子：```
arr = [4,7,6,2,3,8,6,1]

mapped indices:
[1,0,5,4,2,0,3]
```现在问题完全改变了。 

我们需要索引严格递增的最长子序列。 

为什么？ 

因为增加索引对应于以相同相对顺序出现的元素`target`。 

这成为一个经典的最长递增子序列问题。 

一旦我们计算：$$LIS = \text{length of longest increasing subsequence}$$答案是：$$\text{len(target)} - LIS$$我们可以计算 LIS`O(n log n)`使用二分查找。

 ## 算法演练

 1. 根据中的每个值创建一个哈希映射`target`到它的索引。 

这是有效的，因为所有值`target`是不同的。 该映射允许恒定时间查找每个值所需的排序位置。 

例子：```
position = {
    6: 0,
    4: 1,
    8: 2,
    1: 3,
    3: 4,
    2: 5
}
```2. 遍历`arr`并建立一系列索引。 

对于每一个值`arr`:

 - 如果它不存在于`target`，忽略它。 
- 否则，将其替换为其目标索引。 

例子：```
arr = [4,7,6,2,3,8,6,1]

transformed:
[1,0,5,4,2,0,3]
```3. 计算变换后的数组的最长递增子序列。 

我们维护一个名为`lis`。 

的含义`lis[i]`是：

 - 长度递增子序列的最小可能尾值`i + 1`。 

对于每个数字：

 - Use binary search to find where it belongs.
 - If it is larger than all elements, append it.
 - 否则，替换第一个大于或等于它的元素。 
4. 长度`lis`等于已存在的最长有效子序列的长度`arr`。 
5、退货：```
len(target) - len(lis)
```这些是我们必须插入的缺失元素。 

### 为什么它有效

 转换后的数组表示内部出现的目标元素的位置`arr`。 

的任意子序列`arr`匹配的顺序`target`必须与严格增加的目标指数相对应。 

因此：

 - 查找已按正确顺序排列的最长子序列等同于查找 LIS。 
- 必须插入每个剩余的目标元素。 

由于 LIS 最大，因此所需的插入次数最少。 

## Python 解决方案```python
from typing import List
from bisect import bisect_left

class Solution:
    def minOperations(self, target: List[int], arr: List[int]) -> int:
        position = {value: index for index, value in enumerate(target)}

        lis = []

        for value in arr:
            if value not in position:
                continue

            target_index = position[value]

            insert_pos = bisect_left(lis, target_index)

            if insert_pos == len(lis):
                lis.append(target_index)
            else:
                lis[insert_pos] = target_index

        return len(target) - len(lis)
```实施从构建`position`哈希映射。 这提供了对每个目标值的索引的恒定时间访问。 

接下来，我们迭代`arr`。 值不存在于`target`无法帮助形成子序列，因此它们会被立即跳过。 

对于匹配值，我们将它们转换为相应的目标索引。 

这`lis`数组存储不同长度的递增子序列的最小可能尾值。 

我们使用`bisect_left`在对数时间内有效地找到插入位置。 

如果当前索引扩展了 LIS，我们会追加它。 否则，我们替换现有值以保持尽可能小的尾部。 保持尾部较小可以最大限度地提高未来的扩展机会。 

最后，答案被计算为尚未包含在 LIS 中的目标元素的数量。 

## 解决方案```go
package main

import "sort"

func minOperations(target []int, arr []int) int {
	position := make(map[int]int)

	for i, value := range target {
		position[value] = i
	}

	lis := []int{}

	for _, value := range arr {
		targetIndex, exists := position[value]

		if !exists {
			continue
		}

		insertPos := sort.SearchInts(lis, targetIndex)

		if insertPos == len(lis) {
			lis = append(lis, targetIndex)
		} else {
			lis[insertPos] = targetIndex
		}
	}

	return len(target) - len(lis)
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

而不是Python的`bisect_left`, Go 使用`sort.SearchInts`用于二分查找。 

Go 中的切片通过以下方式自然地支持动态增长`append`。 

不存在整数溢出问题，因为索引的边界为`10^5`。 

哈希映射查找使用 Go 的二值赋值语法：```go
targetIndex, exists := position[value]
```它干净地处理缺失值。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`arr`已经包含`target`作为子序列。 在这种情况下，变换后的索引序列已经严格递增，因此 LIS 长度等于`len(target)`。 算法正确返回`0`，意味着不需要插入。 

另一个重要的情况是当`arr`不包含以下任何值`target`。 转换后的序列变为空，因为每个值都被跳过。 因此 LIS 长度为`0`，并且算法正确地确定必须插入每个目标元素。 

内部重复`arr`是错误的另一个潜在来源。 自从`target`包含唯一值，重复项`arr`映射到重复索引。 LIS 算法自然可以处理这个问题，因为重复值不能扩展严格递增的子序列。 使用`bisect_left`确保重复项替换现有位置，而不是错误地增加子序列长度。 

最后一个微妙的边缘情况发生在`arr`包含目标值，但顺序相反。 例如：```
target = [1,2,3]
arr = [3,2,1]
```变换后的序列变为：```
[2,1,0]
```LIS 长度仅为`1`，意味着只有一个目标元素已经正确排序。 因此该算法返回`2`，这是正确的。
