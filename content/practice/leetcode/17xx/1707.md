[LeetCode 问题 1707](https://leetcode.com/problems/maximum-xor-with-an-element-from-array/)

 **难度：** 🔴难
 **主题：** 数组、位操作、Trie

 ## 解决方案

 ## 问题理解

 这个问题给了我们两个输入：

 - 整数数组`nums`- 查询列表，其中每个查询是`[xi, mi]`对于每个查询，我们必须找到以下值的最大可能值：```
nums[j] XOR xi
```须符合以下条件：```
nums[j] <= mi
```如果没有数字`nums`满足条件`nums[j] <= mi`，那么该查询的答案是`-1`。 

XOR 运算是按位运算。 对于这个问题，它最重要的属性是两个位不同时贡献最大：

 -`1 XOR 0 = 1`-`0 XOR 1 = 1`因此，为了最大化异或，我们通常希望尽可能使用相反的位。 

约束条件极其重要：

 -`nums.length`和`queries.length`每个都可以达到`100000`- 值可以大到`10^9`一种简单的方法，检查中的每个数字`nums`对于每个查询都需要：```
100000 * 100000 = 10^10
```在最坏的情况下，操作速度太慢了。 

因此，该问题需要一种更先进的方法来避免重复扫描整个阵列。 

一些边缘情况很重要：

 - 查询可能没有有效的数字，因为每个值`nums`大于`mi`-`nums`可能包含重复值
 - 查询是独立的并且可以以任意顺序出现
 - 值可以为零
 - 大值需要处理最多 31 位，因为`10^9 < 2^30`核心挑战是有效地回答许多受限的最大异或查询。 

## 方法

 ### 蛮力方法

 最直接的解决方案是独立处理每个查询。 

对于查询`[xi, mi]`：

 1. 迭代中的每个数字`nums`2. 忽略大于的数字`mi`3. 计算`nums[j] XOR xi`对于有效数字
 4. 追踪最大结果

 这是有效的，因为它直接检查每个可能的候选者。 

然而，它太慢了。 

如果有`n`数字和`q`查询：

 - 每个查询都会扫描所有`n`数字
 - 总复杂度变为`O(n * q)`两个值可能等于`100000`，这种方法不可行。 

### 关键见解

 重要的观察是约束`nums[j] <= mi`每个查询都会发生变化，但可以按排序顺序处理查询。 

如果我们排序：

 -`nums`- 查询通过`mi`然后我们可以逐步将有效数字添加到数据结构中，如下所示`mi`增加。 

第二个见解是二进制 Trie 允许我们有效地计算最大 XOR 值。 

二进制 Trie 逐位存储数字：

 - 每个节点有：

 - 孩子`0`- 孩子`1`当尝试最大化 XOR 时：

 - 如果当前位`xi`是`0`，我们更喜欢`1`- 如果当前位`xi`是`1`，我们更喜欢`0`这种贪婪的选择之所以有效，是因为较高的位对最终数值的贡献更大。 

结合：

 - 离线查询处理
 - 排序
 - 二进制特里树

 给出了有效的解决方案。

 ## 算法演练

 ### 最优算法

 1. 排序`nums`数组按升序排列。 

排序允许我们只逐步添加满足当前查询限制的数字`mi`。 
2. 将查询转换为可排序的结构。 

对于每个查询，存储：```
(mi, xi, original_index)
```我们保留原始索引，因为排序会改变查询顺序，但答案必须按原始顺序返回。 
3. 对转换后的查询进行排序`mi`。 

这确保了当我们处理查询时，允许的最大值只会增加。 
4. 创建一个空的二进制 Trie。 

trie 存储数字的二进制表示形式。 

由于值最多是`10^9`，我们从位置处理位`30`下降到`0`。 
5. 维护一个指向已排序的指针`nums`大批。 

对于每个有限制的查询`mi`：

 - 插入所有数字`<= mi`进入特里树
 - 相应地推进指针

 每个数字只插入一次。 
6. 使用贪心异或遍历回答查询。 

对于每一位来自`30`下降到`0`：

 - 提取当前位`xi`- 更喜欢特里树中相反的位
 - 如果相反存在：

 - 搬到那里
 - 设置结果中相应的位
 - 否则：

 - 遵循相同的一点

 这贪婪地从最高有效位向下最大化异或值。 
7. 处理空特里树案例。 

如果尚未插入数字，则没有有效数字满足`nums[j] <= mi`。 

返回`-1`。 
8. 将结果存储在查询的原始索引处。 

这将恢复所需的输出顺序。 

### 为什么它有效

 该算法之所以有效，是因为查询是按升序处理的`mi`。 在任何时候，特里结构都准确地包含当前查询允许的数字。 

trie 遍历是最佳的，因为 XOR 值是按字典顺序从最高有效位到最低有效位确定的。 尽可能选择相反的位可以最大化当前位的贡献，而不会牺牲已经优化的较高位。 

由于每个数字都插入一次并且每个查询执行固定的 31 位遍历，因此该算法对于约束来说足够有效。 

## Python 解决方案```python
from typing import List

class TrieNode:
    def __init__(self):
        self.children = {}

class BinaryTrie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, num: int) -> None:
        node = self.root

        for bit in range(30, -1, -1):
            current_bit = (num >> bit) & 1

            if current_bit not in node.children:
                node.children[current_bit] = TrieNode()

            node = node.children[current_bit]

    def max_xor(self, num: int) -> int:
        node = self.root
        result = 0

        for bit in range(30, -1, -1):
            current_bit = (num >> bit) & 1
            opposite_bit = 1 - current_bit

            if opposite_bit in node.children:
                result |= (1 << bit)
                node = node.children[opposite_bit]
            else:
                node = node.children[current_bit]

        return result

class Solution:
    def maximizeXor(self, nums: List[int], queries: List[List[int]]) -> List[int]:
        nums.sort()

        indexed_queries = []

        for index, (x, m) in enumerate(queries):
            indexed_queries.append((m, x, index))

        indexed_queries.sort()

        trie = BinaryTrie()

        answers = [-1] * len(queries)

        nums_index = 0
        n = len(nums)

        for limit, x, original_index in indexed_queries:

            while nums_index < n and nums[nums_index] <= limit:
                trie.insert(nums[nums_index])
                nums_index += 1

            if nums_index == 0:
                answers[original_index] = -1
            else:
                answers[original_index] = trie.max_xor(x)

        return answers
```实现从排序开始`nums`，这使得可以增量插入到 trie 中。 

查询被转换为包含以下内容的元组：

 - 极限`mi`- 异或值`xi`- 原始查询索引

 查询排序依据`mi`保证一旦一个数字变得有效，它对于以后的所有查询仍然有效。 

这`BinaryTrie`类处理插入和异或最大化。 每个数字从最高有效位到最低有效位逐位存储。 

这`max_xor`方法贪婪地尝试移向相反的位，因为相反的位会产生 XOR 值`1`。 

主循环在回答每个查询之前插入所有新的有效数字。 由于每个数字仅插入一次，因此总插入成本与元素数量保持线性关系。 

最后，使用原始查询索引写回答案，以便返回的数组与输入顺序匹配。 

## 解决方案```go
package main

import "sort"

type TrieNode struct {
	children [2]*TrieNode
}

type BinaryTrie struct {
	root *TrieNode
}

func NewBinaryTrie() *BinaryTrie {
	return &BinaryTrie{
		root: &TrieNode{},
	}
}

func (t *BinaryTrie) Insert(num int) {
	node := t.root

	for bit := 30; bit >= 0; bit-- {
		currentBit := (num >> bit) & 1

		if node.children[currentBit] == nil {
			node.children[currentBit] = &TrieNode{}
		}

		node = node.children[currentBit]
	}
}

func (t *BinaryTrie) MaxXor(num int) int {
	node := t.root
	result := 0

	for bit := 30; bit >= 0; bit-- {
		currentBit := (num >> bit) & 1
		oppositeBit := 1 - currentBit

		if node.children[oppositeBit] != nil {
			result |= (1 << bit)
			node = node.children[oppositeBit]
		} else {
			node = node.children[currentBit]
		}
	}

	return result
}

func maximizeXor(nums []int, queries [][]int) []int {
	sort.Ints(nums)

	type Query struct {
		limit int
		x     int
		index int
	}

	indexedQueries := make([]Query, len(queries))

	for i, q := range queries {
		indexedQueries[i] = Query{
			limit: q[1],
			x:     q[0],
			index: i,
		}
	}

	sort.Slice(indexedQueries, func(i, j int) bool {
		return indexedQueries[i].limit < indexedQueries[j].limit
	})

	trie := NewBinaryTrie()

	answers := make([]int, len(queries))

	for i := range answers {
		answers[i] = -1
	}

	numsIndex := 0
	n := len(nums)

	for _, query := range indexedQueries {

		for numsIndex < n && nums[numsIndex] <= query.limit {
			trie.Insert(nums[numsIndex])
			numsIndex++
		}

		if numsIndex == 0 {
			answers[query.index] = -1
		} else {
			answers[query.index] = trie.MaxXor(query.x)
		}
	}

	return answers
}
```Go 实现遵循与 Python 版本相同的算法结构。 

固定大小的数组：```go
children [2]*TrieNode
```为了提高效率，使用哈希图代替哈希图，因为每个节点只有两个可能的子节点。 

Go 整数安全地处理所需的范围，因为值最多`10^9`。 

切片用于动态查询存储，并且`sort.Slice`用于对自定义结构进行排序。 

Nil 指针自然代表缺失的 trie 分支。

在最坏的情况下，特里树可能包含每个插入数字最多 31 个新节点，从而产生`O(31 × n)`空间使用情况。

 ## 边缘情况

 ### 没有有效号码

 查询可能有限制`mi`小于中的每个数字`nums`。 

例子：```
nums = [5,6,7]
query = [2,1]
```没有一个数满足`nums[j] <= 1`。 

这是错误的常见来源，因为 trie 遍历假设至少存在一个插入值。 

实现通过检查来处理这个问题：```
if nums_index == 0:
```在尝试遍历 trie 之前。 

### 重复的数字

 输入可能包含重复的值。 

例子：```
nums = [4,4,4]
```有缺陷的实现可能会错误地尝试重复数据删除或错误地处理重复插入。 

trie 安全地支持重复项，因为多次插入相同的路径不会影响正确性。 

### 大位值

 值可能大到`10^9`。 

这需要处理到位位置`30`。 

If the implementation uses too few bits, higher-order contributions to XOR would be lost, producing incorrect answers.

 该解决方案明确迭代：```
for bit in range(30, -1, -1):
```它安全地覆盖所有可能的输入值。
