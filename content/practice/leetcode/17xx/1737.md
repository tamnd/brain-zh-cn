[LeetCode 问题 1737](https://leetcode.com/problems/change-minimum-characters-to-satisfy-one-of- Three-conditions/)

 **难度：** 🟡 中等
 **主题：** 哈希表、字符串、计数、前缀和

 ## 解决方案

 ## 问题理解

 该问题给了我们两个小写英文字符串，`a`和`b`。 在一次操作中，我们可以将任一字符串中的任何字符更改为任何其他小写英文字母。 

我们的任务是确定所需的最少字符更改次数，以便至少满足以下条件之一：

 1. 剧中的每一个角色`a`严格小于中的每个字符`b`。 
2. 里面的每个角色`b`严格小于中的每个字符`a`。 
3. 两个字符串均仅包含一个不同的字符。 

短语“严格较小”指的是字母顺序。 例如，`'a' < 'b'`,`'b' < 'c'`， 等等。 如果满足条件1，则其中最大的字符`a`仍必须小于中的最小字符`b`。 

每个输入大小可以大到`10^5`，它立即告诉我们，涉及重复重新扫描或显式检查所有转换的昂贵方法是行不通的。 我们需要接近线性时间的东西。 

另一个重要的观察结果是字母表大小固定为仅 26 个小写字母。 这强烈表明频率计数和前缀和将很有用，因为我们可以有效地推理所有可能的字符边界。 

一些重要的边缘情况包括：

 - 已经满足条件之一的字符串。 
- 仅包含一个重复字母的字符串。 
- 两个字符串在字符范围内严重重叠的情况。 
- 非常小的字符串，例如长度 1。 
- 最佳答案来自条件 3 而不是条件 1 或 2 的情况。 

因为字母表大小是恒定的，所以我们可以有效地评估字母之间所有可能的分割点。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试所有可能的目标转换。 

对于条件 1 和 2，我们可以尝试所有可能的边界特征。 例如，假设我们选择`'d'`作为条件 1 的分界点。然后`a`必须成为其中之一`'a'`,`'b'`， 或者`'c'`，以及其中的每个字符`b`必须成为`'d'`或更大。 我们可以计算出该边界需要进行多少次更改。 

对于条件 3，我们可以尝试每个可能的目标字母`'a'`到`'z'`，将两个字符串中的所有字符转换为该字母。 

即使是这种简化的蛮力也已经暗示了更好的方向。 一个真正幼稚的实现可能会重复扫描两个字符串的每个边界和每个字母，大致导致：

 - 条件 3 的 26 种可能性
 - 条件 1 的 25 个分割边界
 - 条件 2 的 25 个分割边界
 - 每次都完整扫描两个字符串

 这给出了大约的复杂度`O(26 * (n + m))`，这实际上是可以接受的，因为字母表大小是恒定的。 

然而，重复地重新扫描字符串是不必要的。 我们可以使用频率数组和前缀和进一步优化。 

### 关键见解

 关键的观察是只有 26 个小写字母。 

我们可以：

 1. 统计每个字符出现的次数`a`和`b`。 
2. 构建前缀和以快速确定：

 - 少于边界的字符数
 - 有多少个字符大于或等于边界

 这使我们能够在每个边界的恒定时间内评估每个条件。 

对于条件 3，我们只需选择一个目标字符并保留所有已与该字符匹配的匹配项。 

对于条件 1 和 2，我们测试字母之间的每个分割：

 - 如果分裂是在之后`'c'`， 然后：

-`a`必须仅包含`'a'`到`'c'`-`b`必须仅包含`'d'`到`'z'`使用前缀和可以使这些计数变得非常高效。

 ## 算法演练

 1. 创建两个大小为 26 的频率数组。 

每个索引对应一个小写字母：

 - 索引0代表`'a'`- 索引1代表`'b'`- ...
 - 索引25代表`'z'`我们计算每个字母出现的次数`a`和`b`。 
2. 计算条件 3 的答案。 

我们尝试使两个字符串仅包含一个不同的字符。 

对于每个字母：

 - 保留所有已经等于该字母的出现
 - 改变所有其他角色

 如果：

 -`countA[i]`是出现的次数`a`-`countB[i]`是出现的次数`b`那么需要的操作是：```
len(a) + len(b) - countA[i] - countB[i]
```我们取所有 26 个字母中的最小值。 
3. 为两个频率数组构建前缀和。 

索引处的前缀和`i`告诉我们有多少个字符小于或等于字母`i`。 

这使我们能够快速回答范围计数查询。 
4. 评估条件 1。 

我们尝试相邻字母之间的每一个分割。 

假设分割是在字母之后`i`。 

然后：

-`a`只能包含字母`0..i`-`b`只能包含字母`i+1..25`所需的更改是：

 - 中的人物`a`大于`i`- 中的人物`b`小于或等于`i`5. 评估条件 2。 

这与条件 1 对称。 

对于相同的分割：

 -`b`只能包含字母`0..i`-`a`只能包含字母`i+1..25`6. 返回所有可能性中的最小值。 

### 为什么它有效

 该算法之所以有效，是因为条件 1 和 2 的每个有效配置都可以由两个相邻字母之间的边界表示。 由于字母表仅包含 26 个字母，因此测试所有 25 个边界可以保证我们检查每种可能的排序安排。 

对于条件 3，任何有效的最终状态都必须完全由一个重复字符组成，因此检查所有 26 个目标字母可以保证我们找到最佳的一个。 

由于该算法在使用精确的频率计数时详尽地评估了所有有效的结构可能性，因此保证最小计算值是最佳的。 

## Python 解决方案```python
class Solution:
    def minCharacters(self, a: str, b: str) -> int:
        count_a = [0] * 26
        count_b = [0] * 26

        for ch in a:
            count_a[ord(ch) - ord('a')] += 1

        for ch in b:
            count_b[ord(ch) - ord('a')] += 1

        n = len(a)
        m = len(b)

        answer = n + m

        # Condition 3:
        # Both strings consist of only one distinct letter
        for i in range(26):
            changes = (n - count_a[i]) + (m - count_b[i])
            answer = min(answer, changes)

        prefix_a = count_a[:]
        prefix_b = count_b[:]

        for i in range(1, 26):
            prefix_a[i] += prefix_a[i - 1]
            prefix_b[i] += prefix_b[i - 1]

        # Conditions 1 and 2
        for i in range(25):
            # Condition 1:
            # all chars in a < all chars in b
            changes_a = n - prefix_a[i]
            changes_b = prefix_b[i]
            answer = min(answer, changes_a + changes_b)

            # Condition 2:
            # all chars in b < all chars in a
            changes_b = m - prefix_b[i]
            changes_a = prefix_a[i]
            answer = min(answer, changes_a + changes_b)

        return answer
```该实现首先构建两个频率数组，每个字符串一个。 这使我们能够恒定地访问每个字符出现的次数。 

接下来，代码评估条件 3。对于每个可能的目标字母，我们计算有多少个字符已经与该字母匹配以及有多少个字符必须更改。 

之后，构建前缀和。 这些前缀数组使我们能够快速确定：

 - 有多少个字符小于或等于给定字母
 - 有多少个字符比给定的字母大

 最后的循环迭代字母之间所有 25 个可能的边界。 对于每个边界，代码计算两个排序条件所需的更改数量并更新全局最小值。 

该解决方案非常高效，因为预处理后的每次计算都是恒定时间。 

## 解决方案```go
func minCharacters(a string, b string) int {
	countA := make([]int, 26)
	countB := make([]int, 26)

	for _, ch := range a {
		countA[ch-'a']++
	}

	for _, ch := range b {
		countB[ch-'a']++
	}

	n := len(a)
	m := len(b)

	answer := n + m

	// Condition 3
	for i := 0; i < 26; i++ {
		changes := (n - countA[i]) + (m - countB[i])
		if changes < answer {
			answer = changes
		}
	}

	prefixA := make([]int, 26)
	prefixB := make([]int, 26)

	copy(prefixA, countA)
	copy(prefixB, countB)

	for i := 1; i < 26; i++ {
		prefixA[i] += prefixA[i-1]
		prefixB[i] += prefixB[i-1]
	}

	// Conditions 1 and 2
	for i := 0; i < 25; i++ {
		// Condition 1
		changesA := n - prefixA[i]
		changesB := prefixB[i]

		if changesA+changesB < answer {
			answer = changesA + changesB
		}

		// Condition 2
		changesB = m - prefixB[i]
		changesA = prefixA[i]

		if changesA+changesB < answer {
			answer = changesA + changesB
		}
	}

	return answer
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 由于 Go 没有像 Python 那样内置动态列表，因此固定大小的切片用于频率和前缀数组。 

字符索引是使用符文算术执行的：```go
countA[ch-'a']++
```这会将每个小写字母转换为 0 到 25 之间的索引。 

不需要对空字符串进行特殊处理，因为约束保证两个字符串都至少包含一个字符。

 ## 边缘情况

 当字符串已经满足其中一个条件时，就会出现一种重要的边缘情况。 例如，`a = "abc"`和`b = "xyz"`已经满足条件 1 因为中的每个字符`a`小于中的每个字符`b`。 有缺陷的实现仍然可能会执行不必​​要的更改。 此实现正确返回 0，因为边界检查自然会产生零所需的修改。 

另一种棘手的边缘情况是两个字符串仅包含一个重复字符，例如`a = "aaaa"`和`b = "aaaa"`。 在这种情况下，条件3已经满足。 该实现可以有效地处理这个问题，因为频率计数立即显示所有字符已经与目标字母匹配。 

第三个重要的边缘情况涉及字母表末尾附近的边界。 例如，如果分裂发生在`'y'`，那么一个字符串中的所有字符都必须是`'z'`。 前缀处理不正确的实现通常会因这里的一个错误而失败。 该解决方案通过仔细地将拆分解释为以下内容来避免该问题：

 - 左侧使用字母`0..i`- 右侧使用字母`i+1..25`并且仅通过有效边界进行迭代`0`到`24`。 

另一个微妙的情况是长度为 1 的非常小的字符串。由于单个字符很容易形成一个统一的字符串，因此条件 3 总是很容易满足。 该实现可以正常工作，因为频率数组和前缀和自然支持任何有效大小的字符串。
