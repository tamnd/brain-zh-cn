[LeetCode 第 1729 题](https://leetcode.com/problems/find-followers-count/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 问题是要求我们确定社交媒体应用程序中的每个用户有多少关注者。 输入是一个名为的表`Followers`有两列：`user_id`和`follower_id`。 每行代表一个关系，其中`follower_id`如下`user_id`。 组合`(user_id, follower_id)`是唯一的，因此用户没有重复的关注者条目。 

预期输出是一个包含每个的表`user_id`以及他们拥有的关注者数量，标记为`followers_count`。 结果必须按以下顺序排序`user_id`按升序排列。 

这些约束意味着`Followers`表可能包含多个用户和每个用户的多个关注者，但每一对都是唯一的。 边缘情况包括零关注者、单个用户或单个关注者的用户。 该问题保证了`user_id`和`follower_id`是整数，主键确保不重复。 

## 方法

 暴力方法会迭代每个用户并计算该用户出现的次数`user_id`在表中。 虽然正确，但这种方法效率低下，因为它可能需要扫描每个用户的整个表，如果表很大，则会导致很高的时间复杂度。 

最佳解决方案的关键是利用 SQL 聚合函数。 通过对表进行分组`user_id`计算每个组的行数，我们可以直接有效地计算关注者的数量。 使用`GROUP BY`确保我们处理每一个`user_id`仅一次并对结果进行排序可确保其满足输出规范。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n * m) | O(u) | 通过扫描每个用户的表来计算关注者数量；`n`是用户数量，`m`是行数，`u`是不同的用户|
 | 最佳 | O(米) | O(u) | 使用SQL`GROUP BY`和`COUNT(*)`;`m`是行数，`u`是不同的用户|

 ## 算法演练

 1. 识别所有不同的`user_id`中的值`Followers`桌子。 
2. 对所有行进行分组`user_id`。 此步骤确保将特定用户的所有关注者收集在一起。 
3. 计算每组中的行数。 该计数代表该关注者的数量`user_id`。 
4. 构建包含列的输出表`user_id`和`followers_count`，使用获得的计数。 
5. 对结果进行排序`user_id`按升序排列。 这是满足输出规格所必需的。 

为什么它有效： 中的每一行`Followers`表恰好对应一个关注者关系。 分组依据`user_id`计算每个组中的行数可以直接得出每个用户的关注者数量。 订购可确保按要求提供结果。 

## Python 解决方案```python
import sqlite3
from typing import List, Tuple

def find_followers_count(cursor: sqlite3.Cursor) -> List[Tuple[int, int]]:
    query = """
    SELECT user_id, COUNT(*) AS followers_count
    FROM Followers
    GROUP BY user_id
    ORDER BY user_id ASC
    """
    cursor.execute(query)
    return cursor.fetchall()
```在此实现中，SQL 查询选择`user_id`并使用以下方法计算每个用户的关注者数量`COUNT(*)`。`GROUP BY user_id`按用户对行进行分组，并且`ORDER BY user_id ASC`对结果进行排序。`cursor.fetchall()`返回最终的元组列表。 

## 解决方案```go
package main

import (
    "database/sql"
    _ "github.com/mattn/go-sqlite3"
)

func FindFollowersCount(db *sql.DB) ([][2]int, error) {
    query := `
    SELECT user_id, COUNT(*) AS followers_count
    FROM Followers
    GROUP BY user_id
    ORDER BY user_id ASC;
    `
    rows, err := db.Query(query)
    if err != nil {
        return nil, err
    }
    defer rows.Close()

    var results [][2]int
    for rows.Next() {
        var userID int
        var count int
        err := rows.Scan(&userID, &count)
        if err != nil {
            return nil, err
        }
        results = append(results, [2]int{userID, count})
    }
    return results, nil
}
```在 Go 中，我们使用`db.Query`执行 SQL。 我们迭代一遍`rows`并将结果扫描到整数变量中。 我们附加每个`[2]int`对结果进行切片。 Go 需要显式的错误处理和行关闭，这是通过`defer`。 

## 工作示例

 对于给定的示例：```
Followers table:
| user_id | follower_id |
| 0       | 1           |
| 1       | 0           |
| 2       | 0           |
| 2       | 1           |
```一步一步：

 1. 分组依据`user_id`:

 - 0 → [1]（计数 1）
 - 1 → [0]（计数 1）
 - 2 → [0, 1]（计数 2）
 2. 构建结果表：```
| user_id | followers_count |
| 0       | 1               |
| 1       | 1               |
| 2       | 2               |
```## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(米) | 表中的每一行都会在`GROUP BY`操作，其中`m`是行数。 |
 | 空间| O(u) | 为聚合存储每个不同用户的一个条目，其中`u`是用户数量。 |

 推理：SQL 聚合函数经过优化，可以扫描每行一次，同时维护每个组的内部计数。 这导致相对于表大小的线性时间和相对于唯一用户数量的线性空间。

 ## 边缘情况

 一个重要的边缘情况是空的`Followers`桌子。 该函数应该返回一个没有错误的空列表，我们的 SQL 将其优雅地处理为`GROUP BY`超过零行会导致零输出。 

第二个边缘情况是没有关注者的用户。 自从`Followers`表仅包含现有关系，具有零关注者的用户不会出现在表中，并且我们的函数不会将它们包含在输出中，这与问题规范相匹配。 

第三种边缘情况是存在单个用户被多个用户关注或只有一个关注者。 我们的实现通过聚合给定的所有行来处理这个问题`user_id`并正确计算追随者的数量，无论存在多少。 这可确保准确考虑高扇出场景和低扇出场景。
