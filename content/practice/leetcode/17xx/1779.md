[LeetCode 问题 1779](https://leetcode.com/problems/find-nearest-point-that-has-the-same-x-or-y-cooperative/)

 **难度：** 🟢简单
 **主题：** 数组

 ## 解决方案

 ## 问题理解

 该问题给出了您在 2D 笛卡尔网格上的当前位置：`(x, y)`以及其他要点的列表。 每个点都表示为`[ai, bi]`。 

如果一个点具有以下任一特征，则该点被视为有效：

 - 与您所在位置相同的 x 坐标，含义`ai == x`- 与您所在位置相同的 y 坐标，含义`bi == y`在所有有效点中，我们必须找到与 曼哈顿距离最小的点`(x, y)`。 

两点之间的曼哈顿距离为：$|x_1-x_2|+|y_1-y_2|$在这个问题中，距离`(x, y)`到`(ai, bi)`变成：$|x-a_i|+|y-b_i|$如果多个有效点具有相同的最小距离，我们返回其中索引最小的一个`points`大批。 

如果没有点与任何一个坐标共享`(x, y)`，我们返回`-1`。 

限制相对较小：

 -`points.length <= 10^4`- 坐标最多为`10^4`这些限制立即表明对所有点进行简单的线性扫描是完全可以接受的。 甚至一个`O(n)`或者`O(n log n)`解决方案将足够快，但不需要比单次传递更复杂的东西。 

有几个重要的边缘情况需要记住：

 - 可能根本没有有效积分。 
- 多个点可以具有相同的最小距离。 
- 有效点可以与当前位置完全相同，产生距离`0`。 
- 遇到的第一个有效点可能不是最近的点。 
- 稍后的点可能会平局最小距离，但平局必须保留较小的索引。 

因为该问题明确要求距离相等时最小索引，所以只有当我们找到严格较小的距离时，我们才必须更新答案。 

## 方法

 ### 蛮力方法

 蛮力方法是逐一检查数组中的每个点。 

对于每个点：

 1. 检查是否有效，即x坐标或y坐标相同。 
2. 如果有效，计算其曼哈顿距离。 
3. 将此距离与迄今为止看到的最小距离进行比较。 
4. 如果当前点更好，则更新答案。 

这种方法是正确的，因为每个可能的候选者都会被检查一次，因此不会遗漏任何有效点。 

从技术上讲，这已经以线性时间运行，这对于约束来说足够有效。 这里没有需要优化的较慢的简单解决方案。 蛮力方法实际上是最佳方法。 

### 关键见解

 关键的观察结果是有效性仅取决于简单的坐标比较：

 -`ai == x`- 或者`bi == y`不需要排序、预处理或高级数据结构。 

由于我们只需要有效点之间的最小曼哈顿距离，因此一次通过数组就足够了。 在此扫描期间，我们维护：

 - 迄今为止找到的最佳距离
 - 对应点的索引

 由于曼哈顿距离可以在恒定时间内计算出来，因此整个算法在具有恒定额外空间的线性时间内工作。

 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(1) | O(1) | 扫描每个点并计算有效点的距离 |
 | 最佳 | O(n) | O(1) | O(1) | 相同的线性扫描，对于问题约束已经是最佳的 |

 ## 算法演练

 1.初始化两个变量：

 -`best_distance`作为无穷大
 -`best_index`作为`-1`这些变量跟踪迄今为止发现的最接近的有效点。 
2. 迭代`points`同时使用索引和点坐标的数组。 
3. 对于每个点`(px, py)`，检查是否有效：

 -`px == x`- 或者`py == y`如果两个条件都不成立，则立即跳过该点。 
4. 对于有效点，计算曼哈顿距离：$|x-p_x|+|y-p_y|$5. 将此距离与`best_distance`。 

- 如果新的距离更小，则更新：

 -`best_distance`-`best_index`6. 当距离相等时不要更新答案。 

这会自动保留最小的索引，因为较早的点仍然被存储。 
7.处理完所有点后，返回`best_index`。 

### 为什么它有效

 该算法对每个点精确地检查一次并评估所有有效的候选点。 自从`best_distance`始终存储迄今为止遇到的最小距离，最终答案必须是最近的有效点。 通过仅更新严格较小的距离，关系会自动保留最早的索引，满足问题要求。 

## Python 解决方案```python
from typing import List

class Solution:
    def nearestValidPoint(self, x: int, y: int, points: List[List[int]]) -> int:
        best_distance = float("inf")
        best_index = -1

        for index, (px, py) in enumerate(points):
            if px == x or py == y:
                distance = abs(x - px) + abs(y - py)

                if distance < best_distance:
                    best_distance = distance
                    best_index = index

        return best_index
```实现直接遵循算法。 

变量`best_distance`和`best_index`维持当前最优答案。`best_distance`从无穷大开始，以便第一个有效点自动成为当前的最佳候选点。 

循环使用`enumerate`所以我们可以同时访问该点及其索引。 对于每个点，我们首先验证它是否与当前位置共享任一坐标。 

如果该点有效，我们将使用绝对差计算曼哈顿距离。 每当计算出的距离严格小于当前最佳距离时，我们就会更新两个跟踪变量。 

最后，处理完所有点后，我们返回`best_index`。 如果未找到有效点，则该值保持不变`-1`。 

## 解决方案```go
func nearestValidPoint(x int, y int, points [][]int) int {
	bestDistance := int(^uint(0) >> 1)
	bestIndex := -1

	for i, point := range points {
		px := point[0]
		py := point[1]

		if px == x || py == y {
			distance := abs(x-px) + abs(y-py)

			if distance < bestDistance {
				bestDistance = distance
				bestIndex = i
			}
		}
	}

	return bestIndex
}

func abs(value int) int {
	if value < 0 {
		return -value
	}

	return value
}
```Go 的实现与 Python 解决方案非常相似。 

由于 Go 没有提供内置的整数无穷大值，因此代码初始化`bestDistance`使用最大可能的整数值。 

Go 也缺乏内置的`abs`函数用于整数，因此手动实现一个小辅助函数。 

该解决方案的其余部分使用点切片上的标准范围循环，并以与 Python 版本完全相同的方式更新最佳候选。

 ## 边缘情况

 ### 没有有效积分

 一个常见的错误是忘记处理没有点与当前位置共享任一坐标的情况。 在这种情况下，算法应该返回`-1`。 

这个实现自然地处理了这种情况，因为`best_index`开始于`-1`并且仅当找到有效点时才更改。 

### 具有相同距离的多个点

 当多个有效点具有相同的曼哈顿距离时，会出现另一个微妙的问题。 该问题需要返回最小的索引。 

该实现仅在新距离严格小于当前最佳距离时才更新答案，从而避免意外覆盖。 忽略相等的距离，保留较早的索引。 

### 指向与当前位置相同的位置

 一个点可能恰好等于`(x, y)`。 其曼哈顿距离为：$|x-x|+|y-y|=0$距离`0`是可能的最小距离，所以这一点应该立即成为最佳答案。 

该实现正确计算该值并按预期​​更新答案。
