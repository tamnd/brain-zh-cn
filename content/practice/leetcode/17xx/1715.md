[LeetCode 第 1715 题](https://leetcode.com/problems/count-apples-and-oranges/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题要求我们计算所有盒子中苹果和橙子的总数，并考虑到某些盒子可能包含一个箱子。 这`Boxes`表为我们提供了每个盒子中苹果和橙子的数量，以及可选的`chest_id`如果该盒子中有箱子。 这`Chests`表给出了每个箱子中包含的苹果和橙子的数量。 

输出是具有两列的单行：`apple_count`和`orange_count`，代表每个盒子中所有苹果和橙子的总和，包括存在的箱子中的内容。 

需要注意的要点是，并非每个盒子都包含一个箱子（`chest_id`可以为空）并且并非每个箱子都可以使用（`chest_id`在`Chests`表可能不会出现在`Boxes`）。 即使多个盒子引用同一个箱子，我们也需要正确求和。 

边缘情况包括没有箱子的盒子、chest_id 指向箱子的盒子以及 chest_id 可能不存在的盒子（尽管问题约束可能会确保引用完整性）。 该问题保证了`box_id`和`chest_id`是各自表的唯一标识符。 

## 方法

 蛮力方法是迭代所有盒子，并且对于每个包含箱子的盒子，在`Chests`表来检索相应的计数。 这种方法是正确的，但效率低下，因为它可能会导致 O(n*m) 时间复杂度，其中 n 是盒子的数量，m 是箱子的数量。 

最佳方法利用 SQL`LEFT JOIN`之间`Boxes`和`Chests`在`chest_id`。 通过执行此连接，我们可以直接将箱子中的苹果和橙子一次性添加到相应的盒子中。 使用 SQL 聚合函数 (`SUM`) 确保在 O(n) 时间内有效计算总和（相对于行数）`Boxes`桌子。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n*m) | O(1) | O(1) | 每个盒子的胸部嵌套查找，对于大数据集来说很慢 |
 | 最佳 | O(n) | O(1) | O(1) | 使用SQL LEFT JOIN直接对盒子和箱子内容求和 |

 ## 算法演练

 1. 执行`LEFT JOIN`的`Boxes`到`Chests`在`chest_id`。 这确保了每个盒子都会出现在结果中，即使它没有箱子。 
2. 在连接结果中，对于每一行，计算苹果总数为`box.apple_count + IFNULL(chest.apple_count, 0)`橙子总数为`box.orange_count + IFNULL(chest.orange_count, 0)`。 通过将 null 视为零，可以正确处理没有箱子的盒子。 
3.使用SQL`SUM()`根据这些计算出的总数，得到苹果和橙子的最终总数。 
4. 将结果作为单行和列返回`apple_count`和`orange_count`。 

工作原理：通过将盒子连接到各自的箱子并求和，每个盒子都会贡献自己的苹果和橙子，如果存在箱子，则将其内容包括在内。 LEFT JOIN 保证没有箱子的盒子仍然被计算在内。 

## Python 解决方案```python
import sqlite3
from typing import Tuple

def countApplesAndOranges(conn: sqlite3.Connection) -> Tuple[int, int]:
    cursor = conn.cursor()
    query = """
    SELECT
        SUM(b.apple_count + IFNULL(c.apple_count, 0)) AS apple_count,
        SUM(b.orange_count + IFNULL(c.orange_count, 0)) AS orange_count
    FROM Boxes b
    LEFT JOIN Chests c
    ON b.chest_id = c.chest_id
    """
    cursor.execute(query)
    result = cursor.fetchone()
    return result[0], result[1]
```Python 解决方案在提供的数据库连接上执行 SQL 查询。 这`LEFT JOIN`确保每个盒子都包含在内，并且`IFNULL`通过使用零来处理没有箱子的情况。 这`SUM`汇总所有箱子（包括箱内物品）的总数。 

## 解决方案```go
package main

import (
    "database/sql"
    _ "github.com/mattn/go-sqlite3"
)

func countApplesAndOranges(db *sql.DB) (int, int, error) {
    query := `
    SELECT
        SUM(b.apple_count + IFNULL(c.apple_count, 0)) AS apple_count,
        SUM(b.orange_count + IFNULL(c.orange_count, 0)) AS orange_count
    FROM Boxes b
    LEFT JOIN Chests c
    ON b.chest_id = c.chest_id
    `
    row := db.QueryRow(query)
    var appleCount, orangeCount int
    err := row.Scan(&appleCount, &orangeCount)
    if err != nil {
        return 0, 0, err
    }
    return appleCount, orangeCount, nil
}
```Go 中的查询逻辑与 Python 中相同。 我们使用`QueryRow`和`Scan`提取单行结果。 在 Go 中，错误处理对于捕获执行查询的任何问题非常重要。

 ## 边缘情况

 一个重要的边缘情况是当`Boxes`没有行。 该算法正确地处理了这个问题，因为 SQL`SUM`在空表上返回`NULL`，在获取结果时被解释为零。 

另一个边缘情况是没有箱子的盒子（`chest_id`为空）。 这`LEFT JOIN`确保包含这些行，并且`IFNULL`保证空箱子值对总和的贡献为零。 

第三种边缘情况是多个盒子引用同一个箱子。 我们的实现正确地总结了引用它的每个框的箱子内容，因为 SQL 连接复制了每个引用框的箱子行，确保包括所有计数。
