[LeetCode 问题 1731](https://leetcode.com/problems/the-number-of-employees-which-report-to-each-employee/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 的`Employees`表存储有关公司内部员工的信息。 每行代表一名员工并包含四列：

 | 专栏 | 意义|
 | ---| ---|
 |`employee_id`| 员工的唯一标识符 |
 |`name`| 员工姓名|
 |`reports_to`| 该员工向其汇报的经理 |
 |`age`| 员工年龄|

 如果`reports_to`是`NULL`，该员工不向任何人报告。 

该问题将经理定义为至少有一名直接下属的任何员工。 直接下属是指其雇员`reports_to`价值等于经理的`employee_id`。 

我们需要生成一个结果表，其中包含：

 | 专栏 | 意义|
 | ---| ---|
 |`employee_id`| 经理 ID |
 |`name`| 经理姓名 |
 |`reports_count`| 直接向经理汇报的员工人数 |
 |`average_age`| 直接下属的平均年龄，四舍五入至最接近的整数 |

 最终结果必须按以下顺序排序`employee_id`。 

重要的细节是我们只考虑直接报告，而不考虑间接报告。 例如，如果员工 A 管理 B，B 管理 C，则 C 不会计入 A 的报告计数。 

对于数据库问题来说，输入大小相对较小，主要挑战是理解如何使用 SQL 分组操作正确聚合员工信息。 

一些边缘情况很重要：

 1. 员工`NULL`在`reports_to`并不是自动成为管理者。 只有当其他员工在以下场合引用他们时，他们才会成为经理`reports_to`。 
2. 有些员工可能只有一名直接下属。 聚合逻辑必须仍然正常工作。 
3. 有些员工可能永远不会以经理的身份出现，因为没有人向他们报告。 它们不应出现在输出中。 
4. 平均年龄必须四舍五入到最接近的整数，而不是截断。 
5.关系只有一层深，因此不需要递归逻辑。 

## 方法

 ### 蛮力方法

 强力策略会检查每个员工，然后再次扫描整个表以查找向他们汇报的员工。 

对于每位员工：

 1. 迭代所有行。 
2. 统计有多少员工`reports_to = current_employee_id`。 
3. 总结他们的年龄。 
4. 计算四舍五入平均值。 
5. 如果至少存在一份报告，则将该员工包括在结果中。 

这种方法之所以有效，是因为它明确地检查了每种可能的经理与下属关系。 然而，它的效率很低，因为对于每个员工，我们都会再次扫描整个表。 

如果有`n`员工，这导致`O(n^2)`时间复杂度。 

### 最佳方法

 关键的观察结果是，可以使用 SQL 聚合直接将向同一经理报告的员工分组在一起。 

我们可以：

 1. 对员工进行分组`reports_to`。 
2. 统计各组的员工人数。 
3. 计算每组的平均年龄。 
4. 将分组结果与`Employees`用于检索经理姓名的表。 

这是高效的，因为 SQL 数据库针对分组和聚合操作进行了优化。 

分组操作处理表一次，使解决方案更具可扩展性。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 重复扫描表中的每个员工 |
 | 最佳 | O(n) | O(n) | 使用 SQL 聚合和分组 |

 ## 算法演练

 1. 从`Employees`桌子。 

每个员工行可以通过以下方式引用经理`reports_to`柱子。 
2. 对员工进行分组`reports_to`。 

这将为每个经理 ID 创建一个组。 每个组包含直接向该经理报告的所有员工。 
3. 对于每组：

 - 计算员工人数。 
- 计算平均年龄。 
- 将平均年龄四舍五入到最接近的整数。 

这些值变成`reports_count`和`average_age`。 
4. 将分组结果与`Employees`桌子。 

分组数据仅包含管理者ID。 我们加入使用：```
Employees.employee_id = grouped.reports_to
```这使我们能够检索经理的姓名。 
5. 选择所需的列。 

我们输出：

 -`employee_id`-`name`-`reports_count`-`average_age`6. 对结果进行排序`employee_id`。 

该问题明确要求升序。 

### 为什么它有效

 分组操作保证所有员工共享相同的信息`reports_to`价值被收集在一起。 自从`reports_to`标识直接经理，在该组上计算的每个聚合都正确代表该经理的直接报告。 重新连接员工表会检索相应的经理信息，而不会更改聚合结果。 

## Python 解决方案

 尽管这是一个数据库问题，LeetCode 仍然期望 SQL 查询作为解决方案。```python
# Write your MySQL query statement below

SELECT
    m.employee_id,
    m.name,
    COUNT(e.employee_id) AS reports_count,
    ROUND(AVG(e.age)) AS average_age
FROM Employees e
JOIN Employees m
    ON e.reports_to = m.employee_id
GROUP BY m.employee_id, m.name
ORDER BY m.employee_id;
```该查询使用自联接，因为员工和经理都存储在同一个表中。 

别名`e`代表正式员工。 别名`m`代表管理者。 

加入条件：```python
e.reports_to = m.employee_id
```将每个员工与其经理进行匹配。 

加入后，员工按经理身份分组。 然后聚合函数计算：

 -`COUNT(e.employee_id)`用于直接报告计数
 -`AVG(e.age)`平均报告年龄

 的`ROUND`函数确保平均年龄符合问题要求。 

最后，输出按经理 ID 排序。

 ## 边缘情况

 当没有员工向任何人汇报时，就会出现一种重要的边缘情况。 在这种情况下，每`reports_to`值为`NULL`，因此聚合过程中不会形成任何组。 有缺陷的实施可能会意外地将所有员工纳入经理。 连接条件可以防止这种情况发生，因为没有报告的员工永远不会参与连接结果。 

另一个重要的边缘情况是经理只有一个直接下属。 聚合逻辑有时假设存在多行，但 SQL 聚合函数即使对于单行也能正常工作。 这`COUNT`变成`1`，平均年龄就是该员工的年龄。 

一个微妙的边缘情况涉及分层管理结构。 例如，首席执行官可能通过中级管理人员间接管理许多员工。 这个问题只需要直接报告。 使用`reports_to = manager_id`确保仅计算直接关系，避免意外的递归聚合。 

最后一个边缘情况是平均舍入行为。 SQL 数据库可能会返回小数平均值，例如`38.5`。 该问题需要四舍五入到最接近的整数，而不是截断。 使用`ROUND(AVG(age))`保证正确的输出格式。
