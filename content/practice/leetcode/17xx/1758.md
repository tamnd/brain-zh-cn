[LeetCode 问题 1758](https://leetcode.com/problems/minimum-changes-to-make-alternating-binary-string/)

 **难度：** 🟢简单
 **主题：** 字符串

 ## 解决方案

 ## 问题理解

 该问题给了我们一个二进制字符串`s`，这意味着字符串仅包含字符`'0'`和`'1'`。 在一次操作中，我们可以翻转一个角色，这意味着我们可以改变`'0'`进入`'1'`或者`'1'`进入`'0'`。 

我们的目标是使用最少的操作次数将字符串转换为交替的二进制字符串。 

交替二进制字符串是没有两个相邻字符相等的字符串。 由于字符串仅包含两个可能的字符，因此对于任何给定长度，仅可能有两种有效的交替模式：

 - 以以下开头的字符串`'0'`， 例如`"010101..."`- 以以下开头的字符串`'1'`， 例如`"101010..."`因此，该任务相当于确定必须更改多少个字符才能匹配这两种可能模式中的每一种，然后返回较小的值。 

输入大小约束为：

 -`1 <= s.length <= 10^4`这告诉我们字符串相对较小，但我们仍然应该以线性时间解决方案为目标。 从技术上讲，二次方法仍然可以满足此约束，但对于这样一个简单的问题来说，它的效率会不必要地低下。 

需要考虑一些重要的边缘情况：

 - 一个长度的字符串`1`已经是交替的了，不管是不是`"0"`或者`"1"`。 
- 已经交替的字符串应该返回`0`。 
- 所有字符都相同的字符串，例如`"1111"`，需要多次翻转。 
- 奇数和偶数长度字符串在模式结尾方面的行为略有不同，但交替模式逻辑保持不变。 

该问题保证每个字符都是`'0'`或者`'1'`，所以我们不需要验证输入字符。 

## 方法

 ### 蛮力方法

 强力解决方案将明确生成长度相同的两个可能的交替字符串`s`。 

例如，如果`s = "0100"`：

 - 模式 1 是`"0101"`- 模式 2 是`"1010"`然后，我们将原始字符串与两种模式逐个字符进行比较，并计算有多少位置不同。 每个不同的位置代表一项所需的操作。 

最后，我们将返回较小的不匹配计数。 

这种方法是正确的，因为任何有效的交替二进制字符串都必须遵循两个交替模式之一。 由于我们完全检查了两种可能性，因此我们保证找到最少的更改数量。 

尽管此解决方案对于给定的约束已经足够有效，但它使用额外的空间来构造模式字符串。 

### 最佳方法

 关键的观察是我们实际上不需要构建交替弦。 

相反，我们可以根据索引奇偶校验确定每个位置应该出现什么字符：

 - 对于以以下开头的模式`'0'`：

 - 甚至索引也应该包含`'0'`- 奇数索引应包含`'1'`- 对于以以下开头的模式`'1'`：

 - 甚至索引也应该包含`'1'`- 奇数索引应包含`'0'`当我们遍历字符串一次时，我们会同时计算两种模式的不匹配情况。 

如果当前字符与模式的预期字符不匹配，则该模式需要在此位置进行一次更改。 

最后，我们返回较小的不匹配计数。 

这消除了不必要的字符串构造，同时保持算法简单高效。

 ## 算法演练

 1. 初始化两个计数器：

 -`start_with_zero`-`start_with_one`这些计数器表示如果交替字符串开头，则需要进行多少次更改`'0'`或者`'1'`。 
2. 使用索引迭代字符串`i`。 
3. 对于每个位置，确定两种模式的预期字符。 

如果模式以`'0'`：

 - 偶数指数 → 预期`'0'`- 奇数索引 → 预期`'1'`如果模式以`'1'`：

 - 偶数指数 → 预期`'1'`- 奇数索引 → 预期`'0'`4. 将当前字符与两个预期值进行比较。 

如果字符与模式的预期值不匹配，则增加该模式的不匹配计数器。 
5. 继续，直到处理完所有字符。 
6. 返回两个计数器中较小的一个，因为它代表所需的最少操作数。 

### 为什么它有效

 每个交替的二进制字符串必须严格遵循两种可能的结构之一：`'0'`或从`'1'`。 该算法独立地计算必须更改多少个字符才能匹配每个结构。 由于每个不匹配恰好对应于一个所需的操作，因此较小的不匹配计数是最佳答案。 

## Python 解决方案```python
class Solution:
    def minOperations(self, s: str) -> int:
        start_with_zero = 0
        start_with_one = 0

        for index, char in enumerate(s):
            expected_zero_pattern = '0' if index % 2 == 0 else '1'
            expected_one_pattern = '1' if index % 2 == 0 else '0'

            if char != expected_zero_pattern:
                start_with_zero += 1

            if char != expected_one_pattern:
                start_with_one += 1

        return min(start_with_zero, start_with_one)
```实现直接遵循算法。 

在整个遍历过程中维护两个计数器。 对于每个字符，代码计算两个交替模式的当前索引处应出现的值。 

表达式`index % 2 == 0`确定当前位置是偶数还是奇数。 根据该奇偶性，选择期望的字符。 

每当当前字符与预期字符不同时，相应的不匹配计数器就会加一。 

处理整个字符串后，返回两个计数器中的最小值，因为它代表使字符串交替所需的最少更改。 

## 解决方案```go
func minOperations(s string) int {
    startWithZero := 0
    startWithOne := 0

    for i := 0; i < len(s); i++ {
        var expectedZeroPattern byte
        var expectedOnePattern byte

        if i%2 == 0 {
            expectedZeroPattern = '0'
            expectedOnePattern = '1'
        } else {
            expectedZeroPattern = '1'
            expectedOnePattern = '0'
        }

        if s[i] != expectedZeroPattern {
            startWithZero++
        }

        if s[i] != expectedOnePattern {
            startWithOne++
        }
    }

    if startWithZero < startWithOne {
        return startWithZero
    }

    return startWithOne
}
```Go 实现密切反映了 Python 逻辑。 

由于 Go 字符串以字节为索引，因此解决方案使用`byte`预期字符的变量。 该算法仍然对字符串执行单次传递并维护两个不匹配计数器。 

不用担心整数溢出，因为最大字符串长度仅为`10^4`。

 ## 边缘情况

 ### 单字符串

 仅包含一个字符的字符串始终是交替的，因为没有可比较的相邻字符。 有缺陷的实现可能会错误地尝试比较邻居或假设至少存在两个字符。 该解决方案可以自然地处理这种情况，因为对于两个有效模式之一，不匹配计数器保持为零。 

### 具有所有相同字符的字符串

 输入如`"0000"`或者`"111111"`很重要，因为它们需要翻转所有其他角色。 幼稚的实现可能会错误地尝试贪婪地修复相邻的重复项，而不考虑全局交替结构。 该算法通过与两个完整的交替模式进行比较来避免该问题。 

### 已经交替的字符串

 输入如`"010101"`或者`"1010"`应该返回`0`。 一些不正确的解决方案会意外执行不必要的操作，因为它们只测试一种起始模式。 此实现评估有效的交替配置并正确识别何时不需要更改。
