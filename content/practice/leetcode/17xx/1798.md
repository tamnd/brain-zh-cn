 # LeetCode 1798 - 你可以做出的连续值的最大数量

 ## 问题理解

 这个问题给了我们一个硬币值的数组，其中每个硬币最多可以使用一次。 我们被要求确定从以下位置开始可以形成的连续整数值的最大数量：`0`。 

更具体地说，如果答案是`k`，这意味着我们可以形成范围内的每个整数值：```
[0, k - 1]
```但我们无法形成价值`k`。 

重要的细节是序列必须从`0`并保持连续无间隙。 即使我们稍后可以形成较大的值，丢失的较小值也会破坏序列。 

例如，如果我们可以形成：```
0, 1, 2, 3, 5
```那么答案是`4`，因为连续序列之前停止`4`。 

输入数组可以包含重复值，并且输入中硬币的顺序并不重要，因为我们可以自由选择硬币的任何子集。 

约束条件很重要：

 -`1 <= n <= 4 * 10^4`-`1 <= coins[i] <= 4 * 10^4`暴力子集枚举需要检查`2^n`子集，这对于`n = 40000`。 

这强烈表明该问题需要贪婪或数学观察，而不是显式子集生成。 

立即识别几个边缘情况很重要：

 - 没有数组`1`， 例如`[2,3,4]`- 我们只能形成`0`，所以答案是`1`- 具有许多重复项的数组`1`s

 - 这些逐渐扩大连续范围
 - 具有大间隙的阵列

 - 大于当前可达到范围的间隙立即停止扩展
 - 单元素数组

 -`[1]`给出答案`2`-`[5]`给出答案`1`理解间隙为何重要是最佳贪婪解决方案背后的关键见解。 

## 方法

 ### 蛮力方法

 暴力解决方案将生成每个可能的硬币子集并计算所有可实现的总和。 

对于每个子集：

 1. 计算子集和
 2. 将总和存储在集合中
 3.处理完所有子集后，从`0`并检查存在多少个连续整数

 这是有效的，因为每个可实现的值都是显式计算的。 

然而，子集的数量为：```
2^n
```即使对于适度的值，它也会变得天文数字般大`n`。 

例如：```
n = 40
```已经产生了超过一万亿个子集。 

由于实际约束是`40000`，暴力是不可能的。 

### 最优贪心法

 关键的观察出奇地优雅。 

假设我们已经处理了一些硬币并且当前可以形成该范围内的每个值：```
[0, reachable]
```现在考虑下一个最小的硬币价值`coin`。 

有两种情况：

 #### 情况 1：`coin <= reachable + 1`然后我们就可以扩展可达范围。 

为什么？ 

因为：

 - 我们已经可以形成每一个值`0`到`reachable`- 添加`coin`每个价值创造：```
[coin, reachable + coin]
```自从`coin <= reachable + 1`，旧范围和新范围之间没有差距。 

因此新的可达范围变为：```
[0, reachable + coin]
```#### 情况 2：`coin > reachable + 1`然后我们就找到了一个缺口。 

我们不能形成：```
reachable + 1
```因为：

 - 所有之前的总和最多为`reachable`- 新硬币太大，无法弥补差距

 到那时，扩张就变得不可能了，我们就停下来了。 

只有当硬币按排序顺序处理时，这种贪婪属性才能正确工作。

 ## 算法演练

 1. 排序`coins`数组按升序排列。 

分类确保我们首先处理较小的硬币。 这是至关重要的，因为贪心证明取决于每一步都知道剩余的最小硬币。 
2. 初始化变量`reachable = 0`。 

这意味着我们目前可以形成该范围内的所有值：```
[0, reachable]
```最初，仅`0`无需使用硬币即可实现。 
3. 按排序顺序迭代每个硬币。 
4. 对于每个硬币，检查是否：```
coin <= reachable + 1
```如果属实，硬币可以不断扩大可达范围。 
5. 如果条件为真，则更新：```
reachable += coin
```这意味着我们现在可以形成直到新最大值的所有值。 
6. If the condition is false, stop immediately.

 We have discovered a gap at:```
reachable + 1
```未来任何更大的硬币都无法解决这个问题。 
7、退货：```
reachable + 1
```因为从开始的连续值的数量`0`等于范围的大小：```
[0, reachable]
```### 为什么它有效

 不变量是：```
Before processing each coin, we can form every value in [0, reachable].
```如果下一枚硬币最多是`reachable + 1`，然后将该硬币与之前可达到的总和相结合，连续填充该范围而没有间隙。 

如果下一枚硬币超过`reachable + 1`，那么值`reachable + 1`是不可能形成的，因为所有现有的金额都太小，而所有未来的硬币甚至更大。 

因此，贪婪扩张既安全又最优。 

## Python 解决方案```python
from typing import List

class Solution:
    def getMaximumConsecutive(self, coins: List[int]) -> int:
        coins.sort()

        reachable = 0

        for coin in coins:
            if coin > reachable + 1:
                break

            reachable += coin

        return reachable + 1
```该实现首先对硬币进行排序，以便首先处理较小的值。 这种排序对于维持贪婪不变量至关重要。 

变量`reachable`跟踪我们当前可以形成的最大连续值`0`。 

在迭代过程中，每个硬币都会被检查`reachable + 1`。 

如果硬币足够小，它就会不断延长可达区间。 我们更新`reachable`通过增加硬币的价值。 

如果硬币太大，就会出现间隙，循环立即终止，因为后面的硬币无法修复缺失的值。 

最后该方法返回`reachable + 1`，它表示从开始的连续值的总数`0`。 

## 解决方案```go
package main

import "sort"

func getMaximumConsecutive(coins []int) int {
	sort.Ints(coins)

	reachable := 0

	for _, coin := range coins {
		if coin > reachable+1 {
			break
		}

		reachable += coin
	}

	return reachable + 1
}
```Go 实现遵循与 Python 版本完全相同的贪婪逻辑。 

The main difference is that Go uses`sort.Ints()`使用 a 对切片进行排序和迭代`range`环形。 

这里不关心整数溢出，因为最大可能的总和是：```go
40000 * 40000 = 1.6 * 10^9
```它仍然安全地适合 32 位有符号整数，而 Go 的`int`现代系统上的类型通常为 64 位。 

空切片是不可能的，因为约束保证至少有一枚硬币。

 ## 边缘情况

 当数组不包含有价值的硬币时，就会出现一个重要的边缘情况`1`。 例如：```
[2,3,4]
```既然我们无法形成价值`1`，连续序列立即停止于`0`。 有缺陷的实现可能会错误地假设较大的硬币仍然可以做出有意义的贡献，但贪婪条件会立即正确地检测到差距。 

另一个重要案件涉及重复的小硬币，尤其是许多`1`s。 例如：```
[1,1,1,1]
```每增加一个`1`将可达范围恰好增加一。 不正确的实现有时无法识别重复值会持续延长间隔。 贪婪不变量自然地处理重复项。 

第三个关键边缘情况涉及在成功扩张后出现的巨大差距。 考虑：```
[1,2,10]
```加工后`1`和`2`，我们可以从`0`到`3`。 然而，下一枚硬币是`10`，大于`reachable + 1 = 4`。 自从`4`无法形成，算法必须立即停止。 未来更大的硬币无法修复缺失的值，因为数组已排序。 

最后一个微妙的边缘情况已经被排序，而不是未排序的输入。 该算法从根本上取决于按升序处理硬币。 如果不排序，贪婪属性就会崩溃。 例如：```
[4,1,2]
```如果按照这个顺序处理，我们会错误地停在第一个硬币上。 排序将其转化为：```
[1,2,4]
```这允许连续扩展至`7`。
