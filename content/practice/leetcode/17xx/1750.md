[LeetCode 问题 1750](https://leetcode.com/problems/minimum-length-of-string-after-deleting-similar-ends/)

 **难度：** 🟡 中等
 **主题：** 两个指针，字符串

 ## 解决方案

 ## 问题理解

 问题给了我们一个字符串`s`仅包含字符`'a'`,`'b'`， 和`'c'`。 我们可能会重复对字符串进行删除操作。 在每个操作中，我们必须删除：

 - 非空前缀，其中每个字符都相同
 - 非空后缀，其中每个字符都相同
 - 两个组必须包含相同的字符
 - 前缀和后缀不能重叠

 我们的目标是在执行我们想要的多次操作后最小化字符串的剩余长度。 

重要的细节是我们不仅限于从每一侧删除一个角色。 如果左侧以多个相同的字符开头，我们可以将它们全部删除。 同样，如果右侧以多个相同的字符结尾，我们可以将它们一起删除。 只要双方使用相同的字符且不重叠，操作就有效。 

例如，在`"aabccabba"`：

 - 我们可以删除`"aa"`从左边和`"a"`从右边
 - 剩余的字符串变为`"bccabb"`输入大小可以大到`10^5`，因此任何重复创建新字符串或多次扫描大部分的算法可能会变得太慢。 这强烈表明我们需要一个线性时间解决方案。 

一些边缘情况很重要：

 - 第一个和最后一个字符不同的字符串，因为无法进行任何操作
 - 完全由一个字符组成的字符串，因为整个字符串可能会消失
 - 非常短的字符串，例如长度`1`或者`2`- 移除一层会暴露另一层的情况
 - 两侧重复字符必须完全跳过的情况，而不是一次一个字符

 幼稚的实现可能会错误地每一步仅删除一个字符，而不是删除所有连续的匹配字符。 

## 方法

 ### 蛮力方法

 暴力策略将使用重复的字符串操作直接模拟该过程。 

每一步：

 1. 检查第一个字符和最后一个字符是否相等。 
2. 如果不同，则停止。 
3. 否则，确定由该字符组成的最大前缀。 
4. 确定由该字符组成的最大后缀。 
5. 通过创建新的子字符串来删除这两个部分。 
6. 重复此操作，直至无法再进行删除。 

这种方法是正确的，因为它直接遵循问题的规则。 每个有效的操作都会从两端删除匹配的字符块。 

但是，如果使用重复的子字符串创建来完成此实现，则效率低下。 每次删除可能需要构造一个新的大小的字符串`O(n)`，而且这种情况可能会发生很多次。 在最坏的情况下，总复杂度变为`O(n^2)`。 

### 最佳方法

 关键的观察是我们永远不需要物理修改字符串。 

字符串中唯一重要的部分是两个指针之间的当前活动窗口：

 -`left`，指向开头
 -`right`，指向末尾

 如果`s[left] != s[right]`，无法进行任何操作，我们就完成了。 

如果它们相等，则两侧该字符的每个连续出现最终都将被删除。 因此，我们可以立即跳过所有匹配的字符，而不是一次删除一个操作。 

这自然会导致两指针解决方案：

 - 移动`left`转发匹配字符的所有副本
 - 移动`right`向后过去匹配字符的所有副本
 - 继续直到指针交叉或边界字符不同

 由于每个字符最多被访问一次，因此该算法以线性时间运行。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 重复子字符串创建和重新扫描 |
 | 最佳 | O(n) | O(1) | O(1) | 两个指针有效缩小活动窗口 |

 ## 算法演练

 1.初始化两个指针：

 -`left = 0`-`right = len(s) - 1`这些指针代表当前活动的子字符串。 
2. 继续处理，同时：

 -`left < right`-`s[left] == s[right]`如果末尾的字符不同，则不再存在有效的操作。 
3. 存储当前字符：```
current_char = s[left]
```这是我们将从两端删除的字符。 
4. 移动`left`指针向前，同时：

 -`left <= right`-`s[left] == current_char`这会跳过整个匹配的前缀。 
5. 移动`right`指针向后同时：

 -`left <= right`-`s[right] == current_char`这会跳过整个匹配后缀。 
6. 重复该过程直到：

 - 指针交叉，意味着整个字符串被删除
 - 或者边界字符不同
 7. 剩余长度为：```
right - left + 1
```如果指针交叉，这个值自然就变成了`0`。 

### 为什么它有效

 该算法依赖于这样一个事实：每当第一个和最后一个字符匹配时，删除少于该字符的所有连续副本永远不会有好处。 任何一端的任何剩余副本仍会阻止未来的操作。 因此，最优策略始终是立即从两侧移除整个匹配块。 

这两个指针始终定义所有处理后的删除后剩余的子字符串。 由于每个可移动层都被完全处理，因此最终剩余的窗口是最小的。 

## Python 解决方案```python
class Solution:
    def minimumLength(self, s: str) -> int:
        left = 0
        right = len(s) - 1

        while left < right and s[left] == s[right]:
            current_char = s[left]

            while left <= right and s[left] == current_char:
                left += 1

            while left <= right and s[right] == current_char:
                right -= 1

        return right - left + 1
```实现直接遵循两指针算法。 

这`left`和`right`指针跟踪当前有效的子字符串。 仅当边界字符匹配时，外循环才会继续。 一旦它们不同，就不可能再进行删除。 

在循环内部，当前可移动字符存储在`current_char`。 然后，内部循环会跳过两侧该字符的每个连续出现。 

条件`left <= right`防止越界访问并正确处理整个字符串消失的情况。 

最后，剩余子串长度计算为`right - left + 1`。 

## 解决方案```go
func minimumLength(s string) int {
    left := 0
    right := len(s) - 1

    for left < right && s[left] == s[right] {
        currentChar := s[left]

        for left <= right && s[left] == currentChar {
            left++
        }

        for left <= right && s[right] == currentChar {
            right--
        }
    }

    return right - left + 1
}
```Go 实现与 Python 版本几乎相同。 

Go 中的字符串内部是字节切片，并且由于输入仅包含 ASCII 字符`'a'`,`'b'`， 和`'c'`，索引为`s[i]`是完全安全的。 

不需要对整数溢出进行特殊处理，因为最大字符串长度仅为`10^5`。

 ## 边缘情况

 一种重要的边缘情况是字符串长度为`1`。 由于该操作需要不重叠的前缀和后缀，因此不可能删除。 该实现自然地处理这个问题，因为条件`left < right`立即为假。 

另一个关键的边缘情况是整个字符串由相同的字符组成，例如`"aaaaaa"`。 有缺陷的实现可能会过早停止或错误地留下一个字符。 在此解决方案中，两个指针继续跳过匹配的字符，直到它们交叉，产生最终长度`0`。 

当重复删除暴露新的可删除边界时，就会出现第三种棘手的情况。 例如，`"cabaabac"`最初仅删除`'c'`，但之后，剩余的子字符串公开匹配`'a'`字符，然后匹配`'b'`人物。 外循环继续处理，直到不可能进一步删除为止，确保所有层都得到正确处理。 

另一个微妙的边缘情况是当两端出现不同大小的大的连续块时，例如`"aabccabba"`。 这些规则允许删除不同长度的前缀和后缀，只要它们包含相同的字符即可。 无论块大小差异如何，该实现都会正确地独立地跳过两侧的整个连续区域。
