[LeetCode 问题 1751](https://leetcode.com/problems/maximum-number-of-events-that-can-be-attending-ii/)

 **难度：** 🔴难
 **主题：** 数组、二分查找、动态规划、排序

 ## 解决方案

 ## 问题理解

 您将获得一个事件列表，其中每个事件表示为：

 -`startDay`-`endDay`-`value`如果您参加活动，则必须参加从`startDay`到`endDay`，包含在内。 由于间隔是包含性的，因此如果一个事件在另一个事件结束的同一天开始，则两个事件会发生冲突。 

您最多可以参加`k`事件，目标是最大化总收集价值。 

挑战来自于同时结合两个约束：

 1. 活动不能重叠。 
2.您最多可以选择`k`事件。 

这立即表明问题不仅仅是间隔调度。 我们不是最大化事件数量，而是在可选择的间隔数量限制下最大化加权利润。 

输入大小足够大，无法进行暴力破解：

 -`events.length`可以达到`10^5`-`k * events.length <= 10^6`第二个约束很重要。 它强烈暗示，一个`O(n * k)`期待动态规划解决方案。 

另一个重要的观察结果是，活动天数可以长达`10^9`。 这意味着我们无法根据实际日历天数构建 DP。 我们必须直接处理事件本身。 

一个微妙但极其重要的规则是，结束日是包容性的。 如果一项活动于当天结束`5`，当天开始的另一个活动`5`被认为是重叠的。 下一个兼容活动必须严格在当前活动结束日之后开始。 

几种边缘情况很容易导致错误：

 - 接触端点的事件，例如`[1,2]`和`[2,3]`- 采取少于的情况`k`事件是最优的
 - 具有不同值的多个重叠事件
 -`k = 1`，这将问题简化为选择单个最佳事件
 - 所有事件不重叠，答案变为选择顶部`k`按时间顺序排列的盈利事件

 ## 方法

 ### 蛮力

 最直接的方法是尝试每个事件子集的大小`k`。 

对于每个子集，我们将：

 1. 检查事件是否重叠。 
2. 计算总值。 
3. 保留最大有效总数。 

之所以有效，是因为它详尽地探索了每种可能的组合，保证最终找到最佳答案。 

不幸的是，子集的数量是指数级的。 和`n`事件，有`2^n`可能的子集。 即使我们修剪的选择大于`k`，复杂性仍然是巨大的。 

这一旦发生就完全不可行了`n`甚至达到几十个，而实际限制最多允许`10^5`事件。 

### 关键见解

 这个问题是以下问题的经典组合：

 - 加权间隔调度
 - 动态规划
 - 二分查找

 关键的观察是，在按开始时间对事件进行排序后，当我们决定是否采取事件时，我们只需要知道：

 - 我们目前正在考虑哪些事件索引
 - 我们还可以参加多少场比赛

 如果我们选择当前事件，我们必须跳转到下一个不重叠的事件。 由于事件已排序，我们可以使用二分搜索找到下一个兼容事件。 

这将指数搜索转化为动态规划问题。 

定义：`dp(i, remaining)`= 从事件开始可获得的最大值`i`和`remaining`剩下的选择。 

在每次活动中，我们都有两种选择：

 1. 跳过事件
 2. 获取事件并跳转到下一个兼容事件

 递归变为：

 - 跳过：`dp(i + 1, remaining)`- 拿：`value[i] + dp(nextIndex, remaining - 1)`我们计算这两个选项中的最大值。 

因为只有`n * k`状态，并且每个转换都使用二分搜索，解决方案对于约束变得足够有效。

 | 最优DP+二分查找| O(n * k * log n) | O(n * k * log n) | O(n * k) | 使用记忆和二分搜索来查找下一个兼容事件 |

 ## 算法演练

 1. 按开始日期对所有事件进行排序。 

排序使我们能够按时间顺序处理事件，并能够对下一个兼容事件进行二分搜索。 
2. 将所有开始日期提取到一个单独的数组中。 

该数组使我们能够有效地二分搜索其开始日期严格大于当前事件结束日期的第一个事件。 
3. 定义一个记忆递归函数：`dfs(index, remaining)`该函数返回从以下位置开始可获得的最大值`index`当我们仍然可以参加时`remaining`事件。 
4. 处理基本情况。 

如果：

-`index == n`，没有更多事件
 -`remaining == 0`，我们无法参加额外的活动

 那么答案是`0`。 
5. 计算“跳过”选项。 

忽略当前事件并转到下一个事件：```
dfs(index + 1, remaining)
```6. 计算“采取”选项。 

如果我们参加当前的活动：

 - 增加其价值
 - 使用二分搜索查找下一个非重叠事件
 - 将剩余选择减少一```
value + dfs(nextIndex, remaining - 1)
```7. 存储并返回两个选择中的最大值。 

记忆化确保每个状态仅计算一次。 
8. 从以下位置开始递归：```
dfs(0, k)
```### 为什么它有效

 在每个事件中，算法都会考虑唯一的两种有效可能性：参加该事件或跳过该事件。 由于事件是按排序顺序处理的，因此二分搜索可以正确识别下一个兼容事件。 记忆化保证每个子问题都被解决一次，并且通过递归决策考虑非重叠事件的每个有效组合。 因此，算法总是找到最优的总值。 

## Python 解决方案```python
from typing import List
from functools import lru_cache
from bisect import bisect_right

class Solution:
    def maxValue(self, events: List[List[int]], k: int) -> int:
        events.sort()

        start_days = [event[0] for event in events]
        n = len(events)

        @lru_cache(None)
        def dfs(index: int, remaining: int) -> int:
            if index == n or remaining == 0:
                return 0

            skip = dfs(index + 1, remaining)

            start, end, value = events[index]

            next_index = bisect_right(start_days, end)

            take = value + dfs(next_index, remaining - 1)

            return max(skip, take)

        return dfs(0, k)
```实施首先根据事件的开始日期对事件进行排序。 这保证了所有未来的兼容事件出现在当前事件之后。 

这`start_days`数组的存在纯粹是为了支持二分查找。 由于我们需要第一个事件的开始日期严格大于当前事件的结束日期，`bisect_right`是完美的工具。 

递归函数`dfs(index, remaining)`表示从特定事件索引开始，剩余有限数量的选择可实现的最佳答案。 

记忆缓存是必不可少的。 如果没有它，递归将重复解决相同的子问题并呈指数增长。 

在递归内部，评估两个决策：

 - 跳过当前事件
 - 获取当前事件并直接跳转到下一个兼容事件

 该算法返回产生较大总价值的选择。 

## 解决方案```go
package main

import (
	"sort"
)

func maxValue(events [][]int, k int) int {
	sort.Slice(events, func(i, j int) bool {
		return events[i][0] < events[j][0]
	})

	n := len(events)

	startDays := make([]int, n)
	for i := 0; i < n; i++ {
		startDays[i] = events[i][0]
	}

	memo := make([][]int, n)
	for i := 0; i < n; i++ {
		memo[i] = make([]int, k+1)
		for j := 0; j <= k; j++ {
			memo[i][j] = -1
		}
	}

	var dfs func(int, int) int

	dfs = func(index int, remaining int) int {
		if index == n || remaining == 0 {
			return 0
		}

		if memo[index][remaining] != -1 {
			return memo[index][remaining]
		}

		skip := dfs(index+1, remaining)

		end := events[index][1]
		value := events[index][2]

		nextIndex := sort.Search(n, func(i int) bool {
			return startDays[i] > end
		})

		take := value + dfs(nextIndex, remaining-1)

		if take > skip {
			memo[index][remaining] = take
		} else {
			memo[index][remaining] = skip
		}

		return memo[index][remaining]
	}

	return dfs(0, k)
}
```Go 实现遵循与 Python 版本相同的算法结构。 

而不是Python的`lru_cache`，Go 使用手动分配的 2D 记忆表，初始化为`-1`。 

二进制搜索是通过以下方式实现的`sort.Search`，找到第一个满足条件的索引`startDays[i] > end`。 

Go 切片本质上是动态的，因此不需要对空数组进行特殊处理。 整数溢出在这里也不是问题，因为最大可能的答案很适合 Go 的内部`int`在 LeetCode 平台上。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n * k * log n) | O(n * k * log n) | 有`n * k`DP 状态，每个状态执行一次二分搜索 |
 | 空间| O(n * k) | 记忆表为每个状态存储一个结果 |

 排序步骤成本`O(n log n)`，但动态规划在运行时占主导地位。 由于每个状态仅执行常量工作加上二分搜索，因此总复杂度变为`O(n * k * log n)`。 

记忆表存储所有计算状态，产生`O(n * k)`内存使用情况。

 ## 边缘情况

 一种重要的边缘情况是端点接触的事件。 例如，`[1,2]`和`[2,3]`重叠是因为结束日包含在内。 许多实现错误地允许这些事件在一起。 该解决方案通过使用避免了该错误`bisect_right(start_days, end)`，它查找开始日期严格大于当前结束日期的第一个事件。 

另一个重要的情况是当采取的少于`k`事件产生最佳答案。 一些不正确的解决方案试图完全强制`k`选择。 这里的DP不需要精确选择`k`事件。 它只是探索所有有效的可能性`k`，允许算法正确返回答案，例如`10`在示例 2 中。 

当所有事件重叠时，就会出现第三种棘手的情况。 在这种情况下，算法必须正确识别单个最高值事件。 由于每个状态都考虑跳过和获取当前事件，因此递归自然会比较所有重叠的替代方案并保留最佳的一个。 

最后一个微妙的边缘情况涉及非常大的日值，高达`10^9`。 任何基于数天迭代的解决方案都会在运行时或内存使用方面失败。 此实现从不依赖于实际的日历范围。 它完全适用于排序事件索引和二分搜索，无论日期有多大，它都非常高效。
