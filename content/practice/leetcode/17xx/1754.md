[LeetCode 问题 1754](https://leetcode.com/problems/largest-merge-of-two-strings/)

 **难度：** 🟡 中等
 **主题：** 两个指针、字符串、贪婪

 ## 解决方案

 ## 问题理解

 这个问题要求我们通过重复地从两个给定字符串的前面选择字符来构建字典顺序上最大的可能字符串。 在每一步中，我们都可以从其中取出第一个字符`word1`或者`word2`，将其附加到结果中，并将其从原始字符串中删除。 

重要的细节是我们不允许对任一字符串内的字符重新排序。 我们只能从左到右消费字符。 这意味着最终的合并必须保留每个原始单词的字符相对顺序。 

我们的目标不仅仅是创建任何有效的合并，而是创建字典序上最大的合并。 词典比较的工作原理与词典排序类似。 比较两个字符串时，我们查看它们不同的第一个位置。 该位置具有较大字符的字符串被认为较大。 

例如：

-`"cab"`大于`"caa"`因为`'b' > 'a'`-`"abc"`小于`"abd"`因为`'c' < 'd'`约束条件很重要：

 -`1 <= word1.length, word2.length <= 3000`- 仅使用小写英文字母

 最大组合长度为`6000`，对于二次解足够小，但对于指数强力方法来说太大。 

尽早考虑几个边缘情况很重要：

 - 一个字符串可能会先于另一个字符串变空
 - 两个字符串当前的前导字符可能相同
 - 可能会出现长公共前缀，迫使进行更深入的比较
 - 一个字符串可能是另一个字符串的前缀，例如`"abc"`和`"abcde"`这些情况使得幼稚的贪婪策略变得危险。 当字符相等时，仅选择较大的当前字符是不够的。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试所有可能的有效合并。 在每一步中，如果两个字符串都非空，我们会分为两种递归可能性：

 - 取出第一个字符`word1`- 取出第一个字符`word2`然后，我们生成所有可能的合并并返回字典顺序最大的合并。 

这种方法是正确的，因为它详尽地探索了整个决策树。 考虑每个有效的合并，因此保证找到最佳答案。 

然而，可能的合并数量呈指数增长。 如果总长度是`n + m`，交织数为：$$\binom{n+m}{n}$$即使对于中等大小的输入，这也会变得巨大。 长度可达`3000`，暴力破解是完全行不通的。 

### 最优贪心法

 关键的观察是，在决定接下来采用哪个字符时，我们应该比较两个字符串的其余后缀。 

假设我们当前正在查看：

 -`word1[i:]`-`word2[j:]`如果`word1[i:]`按字典顺序大于`word2[j:]`，然后取自`word1`立即给出更好的结果。 否则，我们应该从`word2`。 

这是有效的，因为当前的决策决定了最终合并中最早的不同位置，这主导了字典顺序。 

一个微妙但关键的点是处理平等的主角。 考虑：

-`word1 = "abz"`-`word2 = "abc"`第一个字符都是`'a'`。 我们不能仅根据当前的角色来决定。 我们必须比较其余的后缀：

 -`"abz" > "abc"`所以我们应该从`word1`。 

这将问题转化为基于后缀比较的干净贪婪策略。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 尝试所有可能的合并 |
 | 最佳 | O((n + m)^2) | O((n + m)^2) | O(n + m) | 贪婪地比较剩余的后缀 |

 ## 算法演练

 1. 初始化两个索引，每个索引对应一个字符串。 

让：

-`i`跟踪当前位置`word1`-`j`跟踪当前位置`word2`还创建一个结果列表以有效构建最终字符串。 
2. 当两个字符串仍包含字符时继续。 

在每一步中，比较：

 -`word1[i:]`-`word2[j:]`这些是剩余的后缀。 
3.如果`word1[i:]`按字典顺序较大，追加`word1[i]`到结果。 

然后递增`i`。 

这是最优的，因为后缀比较保证了选择`word1`产生更大的最终合并。 
4. 否则，追加`word2[j]`到结果。 

然后递增`j`。 
5. 一旦一个字符串用完，就附加另一字符串中的所有剩余字符。 

由于不再需要做出任何选择，因此必须直接附加其余部分。 
6. 将结果列表连接成最终字符串并返回。 

### 为什么它有效

 贪心选择总是安全的，因为字典顺序是由最早的不同位置决定的。 在每一步中，比较剩余的后缀都会告诉我们哪个选择会创建更大的未来字符串。 通过始终选择字典顺序上较大的后缀，我们保证最终合并中最早可能的不同字符被最大化。 这个不变量在整个过程中都成立，证明了正确性。 

## Python 解决方案```python
class Solution:
    def largestMerge(self, word1: str, word2: str) -> str:
        i = 0
        j = 0

        merge = []

        while i < len(word1) and j < len(word2):
            if word1[i:] > word2[j:]:
                merge.append(word1[i])
                i += 1
            else:
                merge.append(word2[j])
                j += 1

        merge.append(word1[i:])
        merge.append(word2[j:])

        return "".join(merge)
```实现直接遵循贪心算法。 

变量`i`和`j`跟踪我们在每个字符串中的当前位置。 我们不是通过连接重复创建新字符串，而是将字符存储在列表中`merge`。 这更有效，因为循环内的 Python 字符串连接可能会变得昂贵。 

在主循环内，我们比较剩余的后缀：```python
word1[i:] > word2[j:]
```Python对字符串自动进行字典序比较，这使得实现极其简洁。 

如果剩余的后缀为`word1`更大，我们从中取出下一个字符`word1`。 否则，我们从`word2`。 

循环结束后，一根字符串就被完全消耗掉了。 直接附加另一个单词的剩余子字符串。 

最后，`"".join(merge)`将列表转换为最终结果字符串。 

## 解决方案```go
func largestMerge(word1 string, word2 string) string {
    i := 0
    j := 0

    result := make([]byte, 0, len(word1)+len(word2))

    for i < len(word1) && j < len(word2) {
        if word1[i:] > word2[j:] {
            result = append(result, word1[i])
            i++
        } else {
            result = append(result, word2[j])
            j++
        }
    }

    for i < len(word1) {
        result = append(result, word1[i])
        i++
    }

    for j < len(word2) {
        result = append(result, word2[j])
        j++
    }

    return string(result)
}
```Go 实现与 Python 版本非常相似，但存在一些特定于语言的差异。 

我们不使用通过连接的动态字符串生成器，而是使用`[]byte`切片以有效地构建结果。 这避免了重复的字符串分配。 

Go 还支持使用以下方法在字符串之间进行字典顺序比较`>`运算符，因此后缀比较仍然很简单：```go
word1[i:] > word2[j:]
```与 Python 不同，Go 不允许将整个子字符串直接附加到字节切片中，因此我们使用循环在一个字符串用完后附加剩余的字符。 

不存在整数溢出问题，因为索引永远不会超过`6000`。

 ## 边缘情况

 当当前主要字符相等时，会出现一种重要的边缘情况。 一种幼稚的实现可能会从一个字符串中任意选择，但这可能会产生次优的答案。 例如，与`"abz"`和`"abc"`，两者都以`'a'`， 但`"abz"`按字典顺序排列更大，因为`'z' > 'c'`之后。 该实现通过比较完整的剩余后缀而不是仅比较当前字符来正确处理此问题。 

当一个字符串是另一个字符串的前缀时，会出现另一种棘手的情况。 考虑`"abc"`和`"abcde"`。 较短的字符串在开头完全匹配，因此决定取决于哪个后缀持续时间更长并且按字典顺序保持更大。 Python 和 Go 字符串比较自然会正确处理此问题，因为字典顺序会在匹配前缀后考虑字符串长度。 

重复的字符也会带来性能和正确性方面的挑战。 输入如`"aaaaaa"`和`"aaaaaa"`强制进行许多深度后缀比较，因为字符串的大部分是相同的。 该算法仍然可以正确工作，因为它始终比较剩余的后缀。 尽管这会增加二次最坏情况的运行时间，但对于问题约束来说它仍然是可以接受的。 

当一个字符串过早变空时，就会出现最后一种重要的边缘情况。 一旦发生这种情况，就不再需要做出任何决定，并且必须直接附加另一个字符串中的剩余字符。 该实现使用主循环终止后的最后附加步骤来处理此问题。
