[LeetCode 第 1708 题](https://leetcode.com/problems/largest-subarray-length-k/)

 **难度：** 🟢简单
 **主题：** 数组，贪婪

 ## 解决方案

 ## 问题理解

 该问题要求我们找到按字典顺序排列的最大长度的连续子数组`k`来自给定的不同整数数组。 

按字典顺序比较两个数组。 这意味着我们从左到右比较元素，直到找到数组不同的第一个位置。 在该位置具有较大值的数组被认为较大。 

例如：

-`[5,2,3]`大于`[4,9,9]`因为第一个不同的元素位于索引处`0`， 和`5 > 4`。 
-`[1,4,7]`大于`[1,3,100]`因为第一个不同的元素位于索引处`1`， 和`4 > 3`。 

输入包括：

 -`nums`，不同整数的数组
 -`k`，所需的子数组长度

 我们必须返回 size 的连续子数组`k`在该长度的所有可能的子数组中，它是按字典顺序最大的。 

由于所有整数都是不同的，因此两个子数组之间的比较变得更简单。 第一个元素立即确定哪个子数组更大，除非第一个元素相等，而这种情况不会发生，因为所有数字都是唯一的。 

约束条件很重要：

 -`nums.length`可以大到`10^5`- 二次解太慢
 - 整数是不同的，这为优化创建了非常有用的属性

 重要的边缘情况包括：

 -`k = 1`，我们只返回最大元素
 -`k = nums.length`，其中整个数组是唯一可能的答案
 - 最大值出现在末尾附近的数组
 - 非常大的数组，低效比较会超时

 该问题保证所有值都是唯一的，这是实现非常有效的贪婪解决方案的关键观察。 

## 方法

 ### 蛮力方法

 暴力解决方案生成每个可能的长度子数组`k`并按字典顺序比较它们以确定最大的一个。 

有`n - k + 1`可能的子数组。 对于每个候选子数组，我们可能需要最多`k`比较以确定是否大于当前最佳值。 

该算法的工作原理如下：

 1. 从第一个子数组开始，将其作为当前最佳子数组。 
2. 生成每隔一个长度的子数组`k`。 
3. 将当前候选与最佳子数组逐个元素进行比较。 
4. 如果候选项按字典顺序更大，则替换最佳子数组。 

这种方法是正确的，因为它明确地检查了每一个有效的可能性。 然而，它的效率很低，因为重复的字典顺序比较可能会花费高达`O(k)`每个。 

在最坏的情况下：

 - 子阵列数量：`O(n)`- 每次比较的成本：`O(k)`整体复杂度变为`O(n * k)`。 

和`n`最多`10^5`，这可能会变得太慢。 

### 最优贪心法

 关键的见解来自于所有数字都是不同的这一事实。 

由于每个值都是唯一的，因此两个子数组永远不能以相同的元素开头。 这意味着第一个元素单独决定哪个子数组按字典顺序更大。 

例如：

-`[5,2,3]`自动大于`[4,100,200]`- 一旦第一个元素不同，我们就不需要比较后面的元素

 因此，问题简化为在所有有效子数组起始位置中找到最大可能的起始元素。 

长度有效的子数组`k`可以从索引开始：```
0 to n - k
```所以我们只需扫描这个范围并选择包含最大值的索引。 

这会产生一个`O(n)`具有恒定额外空间的解决方案。

 ## 算法演练

 ### 最优贪心算法

 1. 计算最后一个有效的起始索引。 

长度的子数组`k`从索引开始`i`以索引结束`i + k - 1`。 

所以：```
i + k - 1 < n
```重新排列：```
i <= n - k
```所以有效的起始位置是从`0`通过`n - k`。 
2.初始化最佳起始索引。 

首先假设索引`0`是最好的起点。 
3. 迭代所有有效的起始位置。 

对于每个索引`i`从`1`到`n - k`：

- 比较`nums[i]`和`nums[best_index]`- 如果`nums[i]`较大，更新`best_index`4.提取答案。 

扫描完成后，返回：```
nums[best_index : best_index + k]
```5. 返回结果子数组。 

### 为什么它有效

 由于所有整数都是不同的，因此两个候选子数组的第一个元素始终不同。 字典比较在第一个不同位置停止，因此第一个元素较大的子数组总体上总是较大。 

因此，选择最大可能的起始元素可以保证字典顺序上最大的子数组。 

## Python 解决方案```python
from typing import List

class Solution:
    def largestSubarray(self, nums: List[int], k: int) -> List[int]:
        n = len(nums)

        best_index = 0

        for i in range(1, n - k + 1):
            if nums[i] > nums[best_index]:
                best_index = i

        return nums[best_index:best_index + k]
```实现首先将数组长度存储在`n`。 

然后我们使用以下方法跟踪最佳起始位置`best_index`。 最初，第一个有效子数组被认为是最好的。 

循环遍历每个有效的起始位置`1`到`n - k`。 

在每一步中，我们都会将当前起始值与迄今为止看到的最佳起始值进行比较。 由于所有数字都是不同的，因此较大的起始值立即决定较大的子数组。 

最后，我们返回长度的切片`k`开始于`best_index`。 

Python 切片操作会自动创建所需的子数组。 

## 解决方案```go
func largestSubarray(nums []int, k int) []int {
	n := len(nums)

	bestIndex := 0

	for i := 1; i <= n-k; i++ {
		if nums[i] > nums[bestIndex] {
			bestIndex = i
		}
	}

	return nums[bestIndex : bestIndex+k]
}
```Go 的实现与 Python 解决方案非常相似。 

Go 使用切片范围而不是 Python 切片语法：```go
nums[bestIndex : bestIndex+k]
```Go 切片引用原始底层数组，而不是立即复制元素。 这对于 LeetCode 提交来说是高效且完全可以接受的。 

不需要对整数溢出进行特殊处理，因为比较很简单并且约束完全适合 Go 的整数范围。

 ## 边缘情况

 ### 案例 1：`k = 1`什么时候`k`等于`1`，每个子数组仅包含一个元素。 这个问题就相当于寻找数组中的最大值。 

如果实现错误地假设需要进行多元素比较，则可能会暴露错误。 

当前的解决方案可以自然地处理这个问题，因为它只是选择最大的有效起始元素。 

### 案例 2：`k = nums.length`当子数组长度等于整个数组长度时，只有一个可能的子数组。 

有缺陷的实现可能会错误地迭代超出有效边界或假设存在多个候选者。 

该算法正确计算：```
n - k = 0
```所以只有索引`0`被考虑，并返回整个数组。 

### 情况 3：接近末尾的最大元素

 考虑：```
nums = [1,2,3,9,5], k = 2
```最佳子数组从最终有效的起始索引开始。 

这种情况很重要，因为计算时通常会出现相差一错误：```
n - k
```循环条件：```
range(1, n - k + 1)
```确保包含最终有效的起始位置。 

### 情况 4：严格降序数组

 考虑：```
nums = [9,8,7,6,5]
```天真的直觉可能会错误地假设后面的位置仍然可以由于后面的元素而产生更大的子数组。 

然而，词典编排的比较完全取决于最早的不同位置。 由于第一个子数组的第一个元素已经是可能的最大值，因此第一个子数组仍然是最佳的。 

该实现正确地保留了最早的最大起始值。
