[LeetCode 问题 1796](https://leetcode.com/problems/second-largest-digit-in-a-string/)

 **难度：** 🟢简单
 **主题：** 哈希表、字符串

 ## 解决方案

 ## 问题理解

 问题给了我们一个字符串`s`包含小写英文字母和数字。 我们的任务是找到出现在字符串中任意位置的第二大不同数字。 

重要的细节是我们关心不同的数字，而不是频率。 如果字符串包含`"111222333"`，不同的数字是`{1, 2, 3}`。 最大的数字是`3`，所以第二大数字是`2`。 

如果字符串中只有一位唯一数字，则不存在第二大数字，我们必须返回`-1`。 

例如，在字符串中`"dfa12321afd"`，出现的数字是`1`,`2`， 和`3`。 最大的数字是`3`，所以第二大的是`2`。 

限制很小：

 -`1 <= s.length <= 500`- 字符串仅包含小写字母和数字

 由于输入量很小，即使效率较低的解决方案仍然可以正常工作。 然而，该问题旨在测试干净的字符串处理和对不同值的仔细处理。 

一些边缘情况很重要：

 - 完全没有数字的字符串，例如`"abcdef"`，应该返回`-1`。 
- 只有一个唯一数字重复多次的字符串，例如`"1111"`，也应该返回`-1`。 
- 数字可能以任何顺序出现，因此我们不能假设第二大数字出现在末尾附近。 
- 重复的数字不得影响结果。 我们只关心独特的价值观。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是扫描字符串并将所有不同的数字收集到一个集合中。 处理完整个字符串后，我们可以按降序对不同的数字进行排序，并返回第二个元素（如果存在）。 

这是有效的，因为集合会自动删除重复项，只留下唯一的数字。 然后排序给出了按数字顺序排列的数字。 

例如：

 - 输入：`"dfa12321afd"`- 不同的数字：`{1, 2, 3}`- 降序排序：`[3, 2, 1]`- 第二大：`2`尽管这种方法对于给定的约束是完全可以接受的，但它通过对所有数字进行排序来执行额外的工作，即使最多只有 10 个可能的数字。 

### 最佳方法

 关键的观察是只有 10 个可能的数字，从`0`到`9`。 我们可以在扫描一次字符串时跟踪最大和第二大的不同数字，而不是存储和排序所有数字。 

我们维护两个变量：

 -`largest`-`second_largest`当我们遇到每个数字时：

 - 如果它大于`largest`，那么旧的`largest`变成`second_largest`- 如果介于`largest`和`second_largest`，我们更新`second_largest`- 重复的数字被忽略

 这使我们能够在具有恒定额外空间的单次传递中计算答案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n + k log k) | O(n + k log k) | O(k) | 使用一组并对不同的数字进行排序 |
 | 最佳 | O(n) | O(1) | O(1) | 直接追踪最大和第二大 |

 这里，`k`是不同数字的数量，并且`k <= 10`。 

## 算法演练

 1.初始化两个变量，`largest`和`second_largest`， 到`-1`。 

这些变量将跟踪迄今为止看到的两个最大的不同数字。 使用`-1`有效，因为所有有效数字都在`0`和`9`。 
2. 迭代字符串中的每个字符。 

我们检查每个字符，因为数字可以出现在输入中的任何位置。 
3. 检查当前字符是否为数字。 

如果字符是字母，我们会跳过它，因为只有数字才重要。 
4. 将数字字符转换为整数。 

例如，`'3'`变成`3`。 
5. 将数字与`largest`。 

如果数字大于`largest`，那么：

 - 移动当前`largest`进入`second_largest`- 更新`largest`与新数字

 这保留了迄今为止看到的两个最高的不同数字。 
6. 否则，检查该数字是否应变为`second_largest`。 

该数字成为新的`second_largest`如果：

 - 它不同于`largest`- 它大于`second_largest`7. 继续，直到处理完整个字符串。 
8. 返回`second_largest`。 

如果不存在有效的第二大数字，则该变量仍将是`-1`。 

### 为什么它有效

 在扫描的每一步，算法都会保持以下不变式：

 -`largest`存储迄今为止遇到的最大不同数字
 -`second_largest`存储迄今为止遇到的第二大不同数字

 每当出现新的较大数字时，前一个最大值就会成为第二个最大值。 每当一个数字严格落在两个跟踪值之间时，它就会更新第二个最大值。 由于每个数字都被处理一次，因此最终值`second_largest`保证是正确的。 

## Python 解决方案```python
class Solution:
    def secondHighest(self, s: str) -> int:
        largest = -1
        second_largest = -1

        for char in s:
            if char.isdigit():
                digit = int(char)

                if digit > largest:
                    second_largest = largest
                    largest = digit
                elif largest > digit > second_largest:
                    second_largest = digit

        return second_largest
```实现从初始化开始`largest`和`second_largest`到`-1`。 这些变量跟踪遍历过程中遇到的两个最大的不同数字。 

循环处理字符串中的每个字符。 这`isdigit()`方法过滤掉字母，以便仅考虑数字字符。 

当找到数字时，将其转换为整数以进行数值比较。 

如果该数字超过当前`largest`，旧的最大值被移入`second_largest`，新的数字变为`largest`。 

这`elif`条件处理数字小于的情况`largest`但仍然大于`second_largest`。 条件`largest > digit > second_largest`还可以防止重复项错误地更新结果。 

最后该方法返回`second_largest`。 如果不存在第二个不同的数字，则该值保持不变`-1`。 

## 解决方案```go
func secondHighest(s string) int {
    largest := -1
    secondLargest := -1

    for _, ch := range s {
        if ch >= '0' && ch <= '9' {
            digit := int(ch - '0')

            if digit > largest {
                secondLargest = largest
                largest = digit
            } else if digit < largest && digit > secondLargest {
                secondLargest = digit
            }
        }
    }

    return secondLargest
}
```Go 实现遵循与 Python 版本相同的逻辑。 由于 Go 没有提供 Python 的直接等价物`isdigit()`对于符文值，我们手动检查字符是否位于`'0'`和`'9'`。 

The conversion from rune to integer is done using:```go
digit := int(ch - '0')
```Go 使用显式整数处理，但溢出不是问题，因为数字仅限于范围`0`通过`9`。

 ## 边缘情况

 当字符串根本不包含数字时，就会出现一种重要的边缘情况。 例如，`"abcdef"`没有数字字符。 假设至少存在一位数字的简单实现可能会失败或产生无效结果。 在此解决方案中，两个跟踪变量都保持不变`-1`，所以算法正确返回`-1`。 

另一个关键的边缘情况是当字符串仅包含一个重复多次的不同数字时，例如`"111111"`。 有缺陷的解决方案可能会意外地将重复出现的情况视为单独的值并错误地返回`1`。 条件`largest > digit > second_largest`防止重复项更新第二大值。 

第三个边缘情况涉及数字`0`。 自从`0`是一个有效的数字，依赖真实或虚假检查的实现可能会意外地忽略它。 例如，`"700"`应该返回`0`因为不同的数字是`{7, 0}`。 这个实现处理`0`正确，因为所有比较都是数字比较，并且使用显式整数值而不是布尔检查。 

最后一种边缘情况是数字以任意顺序出现，例如`"5a3b9c1"`。 第二大数字可能出现在最大数字之前或之后。 由于算法在遍历过程中不断更新两个跟踪变量，因此字符的顺序不会影响正确性。
