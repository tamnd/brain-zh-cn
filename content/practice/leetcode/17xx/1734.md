[LeetCode 问题 1734](https://leetcode.com/problems/decode-xored-permutation/)

 **难度：** 🟡 中等
 **主题：** 数组、位操作

 ## 解决方案

 ## 问题理解

 问题给了我们一个名为`encoded`，它是从未知的排列数组生成的`perm`。 

第一个的排列`n`正整数意味着数组包含来自`1`到`n`正好一次。 例如：

-`[1,2,3]`是一个有效的排列`1..3`-`[2,4,1,5,3]`是一个有效的排列`1..5`编码规则为：```
encoded[i] = perm[i] XOR perm[i + 1]
```其中 XOR 是按位异或运算。 

我们只得到`encoded`数组并且必须重建原始数组`perm`大批。 

重要的细节是`n`总是很奇怪。 自从`encoded.length == n - 1`，我们可以计算：```
n = encoded.length + 1
```约束条件允许`n`最多`10^5`，这立即告诉我们暴力排列生成是不可行的。 任何阶乘时间方法都会慢得惊人。 

该问题还保证答案存在并且是唯一的。 这意味着我们不需要担心不明确的重建或无效的输入。 

一些重要的观察结果：

 - XOR 具有有用的取消属性：

 -`a XOR a = 0`-`a XOR 0 = a`- XOR 具有结合性和交换性
 - 因为`perm`是一个排列`1..n`, 中所有元素的异或`perm`很简单：```
1 XOR 2 XOR 3 XOR ... XOR n
```简单实施的潜在陷阱包括：

 - 忘记了`n`是奇数，这对于数学技巧来说是必不可少的
 - 误解哪些指数`encoded`应该一起进行异或运算
 - 发现第一个元素后错误地重建排列
 - 使用无法扩展的阶乘暴力方法`10^5`## 方法

 ### 蛮力方法

 最直接的想法就是尝试所有可能的数字排列`1..n`。 

对于每个排列：

 1. 计算编码表示。 
2. 将其与给定的进行比较`encoded`大批。 
3. 如果匹配则返回排列。 

这是有效的，因为该问题保证了唯一的有效答案。 最终，我们会找到正确的排列。 

然而，这种方法是完全不切实际的。 

有`n!`可能的排列。 即使对于相对较小的`n`，这变得巨大：```
10! = 3,628,800
15! = 1,307,674,368,000
```自从`n`可以大到`100000`，暴力是不可能的。 

### 最佳方法

 关键的见解来自 XOR 属性以及以下事实：`perm`是一个排列`1..n`。 

认为：```
perm = [p0, p1, p2, p3, p4]
encoded = [p0^p1, p1^p2, p2^p3, p3^p4]
```如果我们对所有元素进行异或`encoded`在奇数索引处：```
encoded[1] XOR encoded[3]
=
(p1^p2) XOR (p3^p4)
```请注意，这为我们提供了以下所有元素`perm`除了`p0`。 

现在计算：```
total = 1 XOR 2 XOR ... XOR n
```自从：```
total = p0 XOR p1 XOR p2 XOR p3 XOR p4
```我们可以恢复：```
p0 = total XOR (p1 XOR p2 XOR p3 XOR p4)
```一旦我们知道第一个元素，其余元素就可以按顺序重建：```
encoded[i] = perm[i] XOR perm[i+1]
```所以：```
perm[i+1] = perm[i] XOR encoded[i]
```这给出了线性时间解。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n! × n) | O(n! × n) | O(n) | 尝试每一种排列 |
 | 最佳 | O(n) | O(1) 额外空间 | 使用XOR属性直接重建|

 ## 算法演练

 1. 计算`n`作为`len(encoded) + 1`。 

由于编码数组有长度`n - 1`，我们可以立即恢复原始排列的大小。 
2. 计算所有整数的 XOR`1`到`n`。 

该值表示中每个元素的异或`perm`， 因为`perm`正是这些数字的排列。 
3. 计算奇数索引处编码元素的 XOR。 

具体来说，异或：```
encoded[1], encoded[3], encoded[5], ...
```这些值中的每一个都扩展为相邻排列元素的异或。 

由于取消属性，这会产生：```
perm[1] XOR perm[2] XOR ... XOR perm[n-1]
```4. 恢复第一个元素`perm`。 

自从：```
total_xor = perm[0] XOR perm[1] XOR ... XOR perm[n-1]
```我们已经计算过：```
perm[1] XOR perm[2] XOR ... XOR perm[n-1]
```我们可以隔离：```
perm[0] = total_xor XOR odd_encoded_xor
```5. 重建剩余元素。 

使用：```
encoded[i] = perm[i] XOR perm[i+1]
```重新排列得到：```
perm[i+1] = perm[i] XOR encoded[i]
```迭代`encoded`并一次构建一个元素的排列。 

### 为什么它有效

 该算法之所以有效，是因为 XOR 允许消除重复值。 对奇数索引编码值进行异或给出除第一个之外的所有排列元素。 因为我们也知道完整排列的异或`1..n`，我们可以精确地分离出第一个元素。 一旦第一个元素已知，每个后续元素都由编码关系唯一确定。 

## Python 解决方案```python
from typing import List

class Solution:
    def decode(self, encoded: List[int]) -> List[int]:
        n = len(encoded) + 1

        # XOR of all numbers from 1 to n
        total_xor = 0
        for num in range(1, n + 1):
            total_xor ^= num

        # XOR of encoded elements at odd indices
        odd_xor = 0
        for i in range(1, len(encoded), 2):
            odd_xor ^= encoded[i]

        # Recover first element of perm
        first = total_xor ^ odd_xor

        # Reconstruct permutation
        perm = [first]

        for value in encoded:
            perm.append(perm[-1] ^ value)

        return perm
```实现首先确定排列的大小。 自从`encoded`有长度`n - 1`，加一给出原始排列长度。 

接下来，代码计算所有整数的异或`1`到`n`。 由于排列恰好包含这些值，因此该 XOR 表示每个排列元素的 XOR。 

奇数索引的循环`encoded`提取除第一个元素之外的所有排列元素的 XOR。 这是使问题可以在线性时间内解决的数学技巧。 

恢复第一个元素后，依次重建排列的其余部分。 每个编码值都存储相邻排列元素的异或，因此知道一个元素可以立即确定下一个元素。 

重建循环将每个新值附加到结果列表中，直到恢复完整排列。 

## 解决方案```go
func decode(encoded []int) []int {
	n := len(encoded) + 1

	// XOR of all numbers from 1 to n
	totalXor := 0
	for i := 1; i <= n; i++ {
		totalXor ^= i
	}

	// XOR of encoded elements at odd indices
	oddXor := 0
	for i := 1; i < len(encoded); i += 2 {
		oddXor ^= encoded[i]
	}

	// Recover first element
	first := totalXor ^ oddXor

	// Reconstruct permutation
	perm := make([]int, n)
	perm[0] = first

	for i := 0; i < len(encoded); i++ {
		perm[i+1] = perm[i] ^ encoded[i]
	}

	return perm
}
```Go 实现遵循与 Python 解决方案完全相同的逻辑。 主要区别是显式切片分配`make`，这避免了重建期间重复动态调整大小。 

Go 整数足以解决这个问题，因为所有值都保持在标准整数限制内。 由于 XOR 是按位运算，因此在实践中对于给定的约束不存在溢出问题。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个循环处理数组一次 |
 | 空间| O(1) 额外空间 | 除了输出数组之外，只使用了几个变量 |

 该算法对输入执行多次线性传递：

 - 一次通过 XOR 数字`1`到`n`- 一次跳过奇数索引
 - 一次重建排列

 由于所有传递都是线性且独立的，因此总时间复杂度保持不变`O(n)`。 

该算法使用常量辅助存储器。 输出数组本身是必需的，并且不计入额外的空间复杂度。

 ## 边缘情况

 ### 最小有效输入

 最小可能的排列大小是`n = 3`， 因为`n`必须是奇数并且至少`3`。 

这很重要，因为错误地假设较大数组的算法可能会在边界条件下失败。 该实现自然地处理了这个问题，因为对于长度数组，所有循环仍然正确执行`2`。 

### 非排序排列

 不保证排列是排序的。 有缺陷的解决方案可能会意外地假设值增加或遵循可预测的模式。 

例如：```
perm = [2,4,1,5,3]
```实现从不依赖于顺序。 它仅使用 XOR 关系来重建值，因此任意排列都可以正常工作。 

### 接近约束极限的大输入

 输入大小可以接近`100000`，使得低效的解决方案变得不可能。 

暴力破解或回溯解决方案会立即超时。 所实现的算法仅对数据使用线性传递，因此即使对于最大尺寸的输入，它也可以有效地扩展。 

### 异或取消陷阱

 一个常见的错误是对编码索引的错误子集进行异或。 

仅使用奇数索引，因为：```
encoded[1] = perm[1] ^ perm[2]
encoded[3] = perm[3] ^ perm[4]
```此模式排除`perm[0]`，以便稍后将其隔离。 使用偶数索引不会产生正确的取消行为。
