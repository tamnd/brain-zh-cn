[LeetCode 问题 1786](https://leetcode.com/problems/number-of-restricted-paths-from-first-to-last-node/)

 **难度：** 🟡 中等
 **主题：** 动态规划、图论、拓扑排序、堆（优先级队列）、最短路径

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个无向加权图`n`节点标记为`1`到`n`。 每条边连接两个节点并具有正权重。 该图保证是连通的，这意味着任何一对节点之间始终至少有一条路径。 

目标不仅仅是计算来自节点的所有路径`1`到节点`n`。 相反，我们只计算满足涉及最短路径距离的特殊限制的路径。 

对于每个节点`x`， 定义：```
distanceToLastNode(x)
```作为距节点的最短距离`x`到节点`n`。 

如果沿着路径移动时，到节点的最短距离，则路径被视为受限路径`n`每一步都严格减少。 

假设我们有一条路径：```
z0 -> z1 -> z2 -> ... -> zk
```在哪里`z0 = 1`和`zk = n`。 

如果满足以下条件，则路径受到限制：```
distanceToLastNode(zi) > distanceToLastNode(zi+1)
```对于每对相邻的节点。 

这意味着每一步都必须使我们更加接近节点`n`就最短路径距离而言。 

重要的细节是，限制是基于最短路径距离，而不是直接的边权重。 

### 输入代表什么

 输入包括：

 -`n`, 节点数
 -`edges`，其中每条边表示为：```
[ui, vi, weighti]
```这意味着之间存在无向边`ui`和`vi`有成本`weighti`。 

该图可能包含循环、多个可能的最短路径以及许多不同的有效受限路径。 

### 输出的含义

 我们必须返回来自节点的受限路径的数量`1`到节点`n`。 

由于路径数量可能变得非常大，因此必须以模数返回答案：```
10^9 + 7
```### 约束及其含义

 限制条件是：

 -`1 <= n <= 2 * 10^4`-`n - 1 <= edges.length <= 4 * 10^4`这个图比较大。 暴力枚举所有可能的路径是不可能的，因为路径的数量可能呈指数增长。 

边权重为正：```
1 <= weighti <= 10^5
```这很重要，因为这意味着 Dijkstra 算法可以安全、高效地计算最短路径。 

该图是连通的，因此每个节点到节点的最短距离`n`永远存在。 

### 重要的边缘案例

 一个重要的边缘情况是具有许多循环的图。 一个未经仔细修剪就探索所有路径的幼稚 DFS 可能会重复访问节点并呈指数爆炸。 

另一个重要的情况是当多个节点到节点的最短距离相同时`n`。 由于限制要求严格减小距离，因此不允许等距离节点之间的转换。 

第三种边缘情况是，尽管有许多图连接，但只有一条有效的受限路径。 该算法必须避免计算暂时移动较远的无效路线。 

最后一个重要的例子是形状像树的图。 在这种情况下，任何一对节点之间都存在一条简单路径，但并非所有这样的路径都必须受到限制。 

## 方法

 ### 蛮力方法

 一个简单的想法是从节点生成每条可能的路径`1`到节点`n`使用DFS或回溯。 

对于每条路径，我们可以首先计算到节点的所有最短距离`n`，然后验证路径是否满足每一步距离严格减小的限制。 

这种方法是正确的，因为它显式检查每个候选路径并仅计算有效路径。 

然而，它太慢了。 

图可以包含循环和指数数量的简单路径。 即使进行修剪，可能的路径数量也会变得巨大。 自从`n`可以大到`20000`，穷举路径枚举是不可行的。 

### 关键见解

 关键的观察结果是最短路径距离在图表上创建了自然排序。 

如果我们计算：```sql
dist[x] = shortest distance from x to n
```那么每条受限路径必须从具有更大的节点移动`dist`到较小的节点`dist`。 

这将问题转化为有向非循环结构中的路径计数问题。 

尽管原始图可能包含循环，但一旦我们只允许边缘移动到严格更小的距离，循环就变得不可能，因为距离不断减小。 

这允许动态编程。 

最优策略是：

 1.从节点使用Dijkstra算法`n`计算到每个节点的最短距离。 
2.使用DFS+memoization来统计受限路径。 
3. 从每个节点，仅移动到最短距离严格较小的邻居。 

这样可以避免重新计算并保证效率。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数| O(n) | 枚举所有可能的路径 |
 | 最佳 | O((V + E) log V) | O(V + E) | Dijkstra + 记忆 DFS |

 ## 算法演练

 ### 第 1 步：构建图表

 创建图的邻接列表表示。 

每个节点存储对：```
(neighbor, weight)
```邻接表是有效的，因为图是稀疏的：```
E <= 4 * 10^4
```### 步骤 2：使用 Dijkstra 计算最短距离

 从节点开始运行 Dijkstra 算法`n`。 

这计算：```
dist[x]
```这是距节点的最短距离`x`到节点`n`。 

我们使用优先级队列，因为所有边权重都是正数。 

结果为我们提供了受限路径所需的排序。 

### 步骤 3：定义 DP 状态

 让：```
dp[x]
```表示从节点开始的受限路径的数量`x`到节点`n`。 

我们的最终答案将是：```
dp[1]
```### 步骤 4：DFS 转换

 对于节点的每个邻居`x`：

- 如果：```
dist[neighbor] < dist[x]
```然后允许在受限路径中移动到该邻居。 

所以：```
dp[x] += dp[neighbor]
```### 步骤 5：基本案例

 在节点处`n`，只有一条到达其自身的受限路径：```
dp[n] = 1
```### 第 6 步：记忆

 如果没有记忆，DFS 将重复重新计算相同的状态。 

我们将之前计算的值存储在缓存中，因此每个节点仅处理一次。 

### 步骤7：返回结果

 返回：```
dp[1] % MOD
```在哪里：```
MOD = 10^9 + 7
```### 为什么它有效

 正确性来自于最短距离沿着每条受限路径严格减少的事实。 

由于距离严格减小，因此限制图中不会出现循环。 这有效地创建了 DAG 结构。 

DFS 递归将每个有效的下一步考虑一次，并且记忆确保每个子问题仅解决一次。 

由于每条受限路径必须遵循递减的距离，并且会探索每个递减距离的转换，因此该算法对所有有效的受限路径仅计数一次。 

## Python 解决方案```python
from typing import List
from collections import defaultdict
import heapq
from functools import lru_cache

class Solution:
    def countRestrictedPaths(self, n: int, edges: List[List[int]]) -> int:
        MOD = 10**9 + 7

        graph = defaultdict(list)

        for u, v, w in edges:
            graph[u].append((v, w))
            graph[v].append((u, w))

        # Dijkstra from node n
        dist = [float('inf')] * (n + 1)
        dist[n] = 0

        min_heap = [(0, n)]

        while min_heap:
            current_dist, node = heapq.heappop(min_heap)

            if current_dist > dist[node]:
                continue

            for neighbor, weight in graph[node]:
                new_dist = current_dist + weight

                if new_dist < dist[neighbor]:
                    dist[neighbor] = new_dist
                    heapq.heappush(min_heap, (new_dist, neighbor))

        @lru_cache(None)
        def dfs(node: int) -> int:
            if node == n:
                return 1

            total_paths = 0

            for neighbor, _ in graph[node]:
                if dist[neighbor] < dist[node]:
                    total_paths += dfs(neighbor)
                    total_paths %= MOD

            return total_paths

        return dfs(1)
```实现首先为无向加权图构建邻接表。 

接下来，Dijkstra算法计算每个节点到节点的最短距离`n`。 优先级队列总是扩展当前最近的节点，保证正确的最短距离，因为所有边权重都是正的。 

知道最短距离后，问题就变成了有向遍历问题。 从任何节点，我们只允许移动到最短距离严格较小的邻居。 

这`dfs`函数计算从给定节点开始的受限路径的数量。 

递归在节点终止`n`，其中恰好存在一条有效路径。 

记忆与`lru_cache`确保每个节点的结果计算一次，从而大大降低了复杂性。 

## 解决方案```go
package main

import (
	"container/heap"
	"math"
)

const MOD int = 1e9 + 7

type Edge struct {
	to     int
	weight int
}

type Item struct {
	node int
	dist int
}

type PriorityQueue []Item

func (pq PriorityQueue) Len() int {
	return len(pq)
}

func (pq PriorityQueue) Less(i, j int) bool {
	return pq[i].dist < pq[j].dist
}

func (pq PriorityQueue) Swap(i, j int) {
	pq[i], pq[j] = pq[j], pq[i]
}

func (pq *PriorityQueue) Push(x interface{}) {
	*pq = append(*pq, x.(Item))
}

func (pq *PriorityQueue) Pop() interface{} {
	old := *pq
	n := len(old)
	item := old[n-1]
	*pq = old[:n-1]
	return item
}

func countRestrictedPaths(n int, edges [][]int) int {
	graph := make([][]Edge, n+1)

	for _, e := range edges {
		u, v, w := e[0], e[1], e[2]

		graph[u] = append(graph[u], Edge{v, w})
		graph[v] = append(graph[v], Edge{u, w})
	}

	// Dijkstra from node n
	dist := make([]int, n+1)

	for i := 1; i <= n; i++ {
		dist[i] = math.MaxInt64
	}

	dist[n] = 0

	pq := &PriorityQueue{}
	heap.Init(pq)

	heap.Push(pq, Item{n, 0})

	for pq.Len() > 0 {
		current := heap.Pop(pq).(Item)

		node := current.node
		currentDist := current.dist

		if currentDist > dist[node] {
			continue
		}

		for _, edge := range graph[node] {
			neighbor := edge.to
			newDist := currentDist + edge.weight

			if newDist < dist[neighbor] {
				dist[neighbor] = newDist
				heap.Push(pq, Item{neighbor, newDist})
			}
		}
	}

	memo := make([]int, n+1)

	for i := 0; i <= n; i++ {
		memo[i] = -1
	}

	var dfs func(int) int

	dfs = func(node int) int {
		if node == n {
			return 1
		}

		if memo[node] != -1 {
			return memo[node]
		}

		total := 0

		for _, edge := range graph[node] {
			neighbor := edge.to

			if dist[neighbor] < dist[node] {
				total += dfs(neighbor)
				total %= MOD
			}
		}

		memo[node] = total
		return total
	}

	return dfs(1)
}
```Go 实现遵循与 Python 版本相同的总体策略。 

一个重要的区别是 Go 不提供内置的优先级队列，因此我们使用`container/heap`包裹。 

记忆化是使用初始化的切片手动实现的`-1`，而不是Python的`lru_cache`。 

距离数组使用`math.MaxInt64`作为一个有效的无限初始值。

from typing import List

class Solution:
    def countRestrictedPaths(self, n: int, edges: List[List[int]]) -> int:
        from collections import defaultdict
        import heapq
        from functools import lru_cache

        MOD = 10**9 + 7

        graph = defaultdict(list)

        for u, v, w in edges:
            graph[u].append((v, w))
            graph[v].append((u, w))

        dist = [float('inf')] * (n + 1)
        dist[n] = 0

        heap = [(0, n)]

        while heap:
            d, node = heapq.heappop(heap)

            if d > dist[node]:
                continue

            for nei, w in graph[node]:
                nd = d + w

                if nd < dist[nei]:
                    dist[nei] = nd
                    heapq.heappush(heap, (nd, nei))

        @lru_cache(None)
        def dfs(node):
            if node == n:
                return 1

            total = 0

            for nei, _ in graph[node]:
                if dist[nei] < dist[node]:
                    total += dfs(nei)

            return total % MOD

        return dfs(1)

 ## 边缘情况

 当相邻节点到节点的最短距离相等时，就会出现一种重要的边缘情况`n`。 由于受限路径要求严格减小距离，因此等距离节点之间的转换是无效的。 一个常见的错误是使用`<=`而不是`<`。 实现正确地使用了严格比较：```
if dist[neighbor] < dist[node]:
```另一个重要的边缘情况是包含循环的图。 原始图可能包含许多循环，这可能会导致在简单的 DFS 实现中无限递归或重复计数。 距离递减规则保证递归调用总是向更小的距离移动，因此受限遍历图中不会出现循环。 

第三种重要的边缘情况是，即使存在许多物理路径，图表也仅包含一条可能的受限路径。 某些路线可能会暂时远离节点`n`，使它们无效。 该算法在对这些路径进行计数之前，使用最短距离排序正确地过滤这些路径。 

最后的边缘情况是接近约束极限的非常大的图。 由于指数增长，递归蛮力搜索会超时。 Dijkstra 算法和记忆 DFS 的结合确保每个节点和边都得到有效处理，将解决方案保持在可接受的范围内。
