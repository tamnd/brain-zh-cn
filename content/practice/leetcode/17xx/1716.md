 ## 解决方案

 ## 问题理解

 该问题描述了每周重复的储蓄模式。 Hercy每天都会把钱存入LeetCode银行，并且金额有条理地增加。 

在第一个星期一，他存入`1`美元。 同一周中的每一天都会增加`1`。 这意味着第一周看起来像这样：

 - 星期一：`1`- 周二：`2`- 周三：`3`- 周四：`4`- 星期五：`5`- 周六：`6`- 星期日：`7`当下周一到来时，起始金额也会增加`1`。 所以第二周就变成了：

 - 星期一：`2`- 周二：`3`- 周三：`4`- 周四：`5`- 星期五：`6`- 周六：`7`- 星期日：`8`这种模式每周都会持续。 

输入`n`代表 Hercy 存钱的天数。 任务是计算准确后存入的总金额`n`天。 

限制非常小：

 -`1 <= n <= 1000`自从`n`至多是`1000`，即使直接模拟每一天也足够高效。 然而，该问题还包含清晰的数学结构，这使我们能够得出更清晰、更优雅的解决方案。 

重要的边缘情况包括部分周、7 天的精确倍数以及可能的最小输入值。 在几周之间转换或计算每日增量时，天真的实现很容易因一个错误而失败。 

## 方法

 ### 蛮力方法

 暴力解决方案模拟了日复一日的存款过程。 

我们维持：

 - 本周的星期一值
 - 当日存款
 - 运行总计

 每天：

 1. 将当前存款添加到答案中。 
2. 每日存款增加`1`。 
3. 每第七天之后，重置每日存款，以便下周一开始时比上周一大。 

这种方法之所以有效，是因为它直接遵循问题陈述中给出的规则。 每个存入的值均完全按照描述生成。 

尽管该解决方案对于给定的约束是完全可以接受的，但它仍然执行不必要的日常模拟。 由于存款模式形成算术序列，因此我们可以用数学方法计算总数。 

### 最优数学方法

 关键的观察是，每个整周都形成一个算术序列。 

例如：

 - 第 1 周总和 =`1 + 2 + 3 + 4 + 5 + 6 + 7 = 28`- 第 2 周总和 =`2 + 3 + 4 + 5 + 6 + 7 + 8 = 35`- 第 3 周总和 =`3 + 4 + 5 + 6 + 7 + 8 + 9 = 42`每周总数增加`7`。 

我们可以将总天数分为：

 - 整周
 - 剩余天数

 如果：

 -`weeks = n // 7`-`days = n % 7`然后：

 1. 计算所有完整周的贡献。 
2. 计算部分周剩余天数的贡献。 
3. 将两者相加。 

这避免了显式模拟并产生简洁的数学解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(1) | O(1) | 模拟每日存款 |
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 使用算术级数公式 |

 ## 算法演练

 1. 使用整数除法计算完整周数。```
weeks = n // 7
```每个完整的星期都会贡献一个可预测的算术序列。 
2. 计算整周后剩余的天数。```
days = n % 7
```这些代表最后一周的存款。 
3. 计算所有完整周的总贡献。 

第一周的总和是`28`。 

接下来的每周增加`7`。 

因此，每周总和的顺序是：```
28, 35, 42, ...
```这是一个算术级数。 

公式变为：```
full_weeks_total =
    weeks * 28 + 7 * (weeks * (weeks - 1) // 2)
```第二项说明周一起始值的增加。 
4. 计算剩余天数的贡献。 

下周一开始于：```
weeks + 1
```剩余的存款构成另一个等差数列：```
(weeks + 1), (weeks + 2), ...
```总和是：```
remaining_total =
    days * (weeks + 1) + days * (days - 1) // 2
```5. 返回两部分的总和。```
answer = full_weeks_total + remaining_total
```### 为什么它有效

 该算法之所以有效，是因为存款在周内和每周内都遵循算术级数。 

每个完整的星期开始时都会比前一周上涨一美元，从而使每周总额出现可预测的增长。 其余天数也从本周的星期一值开始形成连续的算术序列。 

由于等差数列公式精确地模拟了存款模式，因此计算结果始终与实际存款金额相符。 

## Python 解决方案```python
class Solution:
    def totalMoney(self, n: int) -> int:
        weeks = n // 7
        days = n % 7

        full_weeks_total = (
            weeks * 28
            + 7 * (weeks * (weeks - 1) // 2)
        )

        remaining_total = (
            days * (weeks + 1)
            + days * (days - 1) // 2
        )

        return full_weeks_total + remaining_total
```实现首先将输入分为完整的周和剩余的天。 

变量`weeks`表示存在多少个完整的周一到周日周期。 变量`days`存储此后还剩下多少天。 

表达式为`full_weeks_total`计算所有完整周的总贡献。 每周贡献的基本金额为`28`，并且每晚一周的起始价格都比前一周高 1 美元。 算术级数公式可以有效地计算这种累积增长。 

表达式为`remaining_total`计算部分周的存款。 存款开始于`weeks + 1`，因为每完成一周，周一起始值就会增加`1`。 

最后，该函数返回两个分量的总和。 

## 解决方案```go
func totalMoney(n int) int {
    weeks := n / 7
    days := n % 7

    fullWeeksTotal :=
        weeks*28 +
            7*(weeks*(weeks-1)/2)

    remainingTotal :=
        days*(weeks+1) +
            days*(days-1)/2

    return fullWeeksTotal + remainingTotal
}
```Go 实现遵循与 Python 版本完全相同的数学逻辑。 

Go 自动使用整数运算来进行这些操作，因此不需要特殊处理。 由于最大值为`n`只是`1000`，整数溢出不是问题。 

与 Python 不同，Go 需要使用显式变量声明`:=`。

 ## 边缘情况

 一个重要的边缘情况是当`n`小于`7`。 在这种情况下，没有完整的周，只有部分第一周。 有缺陷的实现可能会错误地假设至少存在完整一周。 当前的实现可以正确处理这个问题，因为`weeks = n // 7`变成`0`，整个答案是通过剩余天数公式计算出来的。 

另一个重要的边缘情况发生在`n`正好可以整除`7`。 在这种情况下，没有剩余天数。 许多实现都犯了一个错误，即意外地增加了额外一周的存款。 这个实现避免了这个问题，因为`days = n % 7`变成`0`，使剩余贡献自动为零。 

第三种边缘情况涉及周之间的过渡，例如`n = 8`或者`n = 15`。 这些输入验证星期一起始值每周是否正确增加。 该实现通过使用来处理这个问题`weeks + 1`作为部分周的起始值，确保算术级数从正确的量开始。
