[LeetCode 问题 1759](https://leetcode.com/problems/count-number-of-homous-substrings/)

 **难度：** 🟡 中等
 **主题：** 数学、字符串

 ## 解决方案

 ## 问题理解

 该问题要求我们计算字符串中的所有子字符串，其中子字符串中的每个字符都是相同的。 这些称为同质子串。 

子字符串必须是连续的，这意味着字符必须在原始字符串中彼此相邻出现。 例如，在字符串中`"abbcccaa"`, 子串`"ccc"`有效，因为所有字符都是`'c'`， 尽管`"bcc"`不是同质的，因为它包含不同的字符。 

输入是单个字符串`s`仅由小写英文字母组成。 输出应该是同质子串的总数，模`10^9 + 7`。 

约束条件`1 <= s.length <= 10^5`很重要。 它告诉我们解决方案必须是有效的。 任何具有二次复杂度的算法，例如单独检查每个可能的子串，对于上限来说可能会太慢。 

关键的观察结果是同质子串仅来自同一字符的连续运行。 例如：

-`"aaa"`包含：

 -`"a"`三次
 -`"aa"`两次
 -`"aaa"`一次

 这总共给出：```
3 + 2 + 1 = 6
```更一般地说，如果跑步有长度`k`，那么该运行贡献的同质子串的数量为：```
k * (k + 1) / 2
```一些重要的边缘情况包括：

 - 只有一个字符的字符串
 - 所有字符都不同的字符串
 - 所有字符都相同的字符串
 - 非常长的重复运行，可能会产生需要模运算的非常大的计数

 该问题保证字符串非空且仅包含小写字母，因此我们不需要处理无效输入的情况。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是生成每个可能的子字符串并检查其中的所有字符是否相同。 

有`O(n^2)`长度字符串中的子字符串`n`。 对于每个子串，我们可能需要最多`O(n)`努力验证每个字符是否匹配。 即使进行了优化，暴力解决方案仍然至少需要`O(n^2)`时间。 

例如：```
s = "abbcccaa"
```我们将检查：

 -`"a"`-`"ab"`-`"abb"`-`"abbc"`- 等等

 对于每个子字符串，我们将检查每个字符是否等于第一个字符。 

这种方法是正确的，因为它显式地计算每个子字符串，但对于`n = 100000`。 

### 最佳方法

 重要的见解是同质子串仅依赖于相同字符的连续运行。 

假设我们有一次运行：```
"cccc"
```它的长度是`4`。 

有效的同质子串是：```
"c"    -> 4
"cc"   -> 3
"ccc"  -> 2
"cccc" -> 1
```全部的：```
4 + 3 + 2 + 1 = 10
```我们可以处理一次字符串并跟踪当前的游程长度，而不是显式生成子字符串。 

每当我们延长一个角色的运行时间时，我们都会获得准确的收益`current_run_length`以当前位置结束的新同质子串。 

例如：```
s = "ccc"
```处理步骤：

 - 首先`'c'`添加`1`- 第二`'c'`添加`2`- 第三`'c'`添加`3`全部的：```
1 + 2 + 3 = 6
```这使我们能够在线性时间内解决问题。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n2) 到 O(n3) | O(1) | O(1) | 单独检查每个子字符串 |
 | 最佳 | O(n) | O(1) | O(1) | 跟踪连续的字符运行 |

 ## 算法演练

 1. 初始化变量`result`存储同质子串的总数。 
2. 初始化变量`current_run_length`到`0`。 该变量跟踪到目前为止我们看到的连续相同字符的数量。 
3. 逐个字符地遍历字符串。 
4. 对于每个字符：

 - 如果与前一个字符匹配，则递增`current_run_length`。 
- 否则，重置`current_run_length`到`1`因为新的一轮开始了。 
5. 添加`current_run_length`到`result`。 

- 这是有效的，因为运行的每次扩展都会创建以当前位置结尾的新同质子字符串。 
- 如果游程长度是`k`，那么正好有`k`在此位置结束的同质子串。 
6. 应用模数`10^9 + 7`每次加法之后以避免整数溢出。 
7. 返回最终结果。 

### 为什么它有效

 在每个索引处，算法都会计算以该位置结尾的所有同质子字符串。 

如果当前游程长度是`k`，那么以此处结尾的有效子字符串为：```
length 1
length 2
...
length k
```正好有`k`这样的子串。 由于每个同质子串都在字符串中的某个位置结束，因此将所有位置上的这些贡献相加就会对每个有效子串恰好计数一次。 

## Python 解决方案```python
class Solution:
    def countHomogenous(self, s: str) -> int:
        MOD = 10**9 + 7

        result = 0
        current_run_length = 0

        for i, char in enumerate(s):
            if i > 0 and char == s[i - 1]:
                current_run_length += 1
            else:
                current_run_length = 1

            result = (result + current_run_length) % MOD

        return result
```该实现遵循算法演练中的确切逻辑。`result`存储同质子串的累积计数。`current_run_length`跟踪当前相同字符序列的长度。 

迭代期间：

 - 如果当前字符与前一个字符匹配，则继续运行并且长度增加。 
- 否则，新的运行开始，因此长度重置为`1`。 

在每一步中，我们都会将当前游程长度添加到答案中，因为许多同质子字符串以当前索引结尾。 

在累加过程中应用模运算以将值保持在范围内。 

## 解决方案```go
func countHomogenous(s string) int {
    const MOD int = 1_000_000_007

    result := 0
    currentRunLength := 0

    for i := 0; i < len(s); i++ {
        if i > 0 && s[i] == s[i-1] {
            currentRunLength++
        } else {
            currentRunLength = 1
        }

        result = (result + currentRunLength) % MOD
    }

    return result
}
```Go 实现与 Python 版本几乎相同。 

由于 Go 字符串是字节可索引的，并且输入仅包含小写英文字母，因此可以使用`s[i]`安全高效。 

在累加期间执行模运算，以防止大输入的整数溢出。 

Go 不需要对空字符串进行特殊处理，因为约束保证至少有一个字符。

 ## 边缘情况

 ### 单字符串

 仅包含一个字符的字符串是最小的有效输入。 有缺陷的实现可能会错误地初始化计数器并返回`0`而不是`1`。 

例子：```
s = "a"
```该算法可以正确处理这个问题，因为第一个字符总是开始一个新的长度`1`，恰好贡献了一个同质子串。 

### 所有角色都不同

 当每个字符都与前一个字符不同时，每个游程长度恰好是`1`。 

例子：```
s = "abcdef"
```唯一有效的同质子串是各个字符本身。 

实施正确重置`current_run_length`到`1`每当角色发生变化时。 

### 整个字符串相同

 长时间运行相同的字符会产生非常大的计数。 

例子：```
s = "aaaaa"
```同质子串的数量变为：```
1 + 2 + 3 + 4 + 5 = 15
```对于最大约束大小，该值变得非常大，因此需要进行模运算。 该实现在累加期间应用取模，防止溢出并确保正确性。
