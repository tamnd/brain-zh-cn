 # LeetCode 1724 - 检查边长有限路径的存在性 II

 ## 问题理解

 这个问题给了我们一个无向加权图`n`节点和边列表。 每条边连接两个节点并具有关联的距离值。 该图可能包含同一对节点之间的多条边，也可能是断开的。 

我们必须设计一个名为`DistanceLimitedPathsExist`支持两种操作：

 1. 用图初始化。 
2. 重复查询，询问两个节点是否通过一条路径连接，其中路径上每条边的权重严格小于给定限制。 

重要的细节是短语“严格小于限制”。 如果边权重等于限制，则不能使用该边。 

对于查询`query(p, q, limit)`，我们必须判断是否存在从节点出发的有效路径`p`到节点`q`使得该路径上的每条边都满足：$$edgeWeight < limit$$该图在构建后是静态的。 查询期间不会添加或删除任何边。 

约束条件很重要：

 -`n <= 10^4`-`edgeList.length <= 10^4`- 最多`10^4`查询

 每个查询的简单图遍历可能会花费：$$O(Q \times (V + E))$$在最坏的情况下，这可能会变得太慢。 

关键的观察结果是，所有查询都询问不同边权重阈值下的连接性。 这表明预处理和有效的连接结构，而不是从头开始重复搜索图。 

一些边缘情况很重要：

 - 图表可能已断开。 
- 相同节点之间可能存在多条边。 
- 有效路径可能需要几条小边而不是一条直接边。 
- 限制是严格的，不包括在内。 
- 查询可能会询问根本没有可能连接的节点。 

因为图是静态的，查询也很多，所以预处理是正确的方向。 

## 方法

 ### 蛮力方法

 最直接的解决方案是使用DFS或BFS独立处理每个查询。 

对于查询`(p, q, limit)`:

 1. 启动DFS/BFS`p`。 
2. 只遍历权重严格小于的边`limit`。 
3.如果`q`可达，返回`true`。 
4.否则返回`false`。 

这是有效的，因为图遍历精确地探索了查询约束下允许的有效路径。 

然而，性能较差。 每个查询可能会扫描几乎所有的顶点和边。 高达`10^4`查询和`10^4`边缘，最坏情况复杂度变为：$$O(Q \times (V + E))$$可以接近`10^8`运营。 

这对于重复查询来说太昂贵了。 

### 最佳方法

 关键的见解是，仅当允许新边缘时，连接才会发生变化。 

假设我们按权重对所有边进行排序。 对于一个极限`L`，每条边都有权重`< L`是可以使用的，而其他的都是禁止的。 

如果我们使用并查找从最小权重到最大权重逐步添加边，那么对于任何限制，我们都可以快速确定两个节点是否属于同一连接组件。 

挑战在于查询是在线到达的，而不是离线的。 我们无法对查询进行排序并一次性处理它们。 

为了支持快速重复查询，我们使用 Kruskal 算法预处理最小生成森林，然后为最低公共祖先样式查询构建二进制提升结构。 

一个关键的图属性是：

 如果两个节点使用小于的边连接`limit`，那么 MST 中它们之间的路径上的最大边权值也小于`limit`。 

因此：

 1. 构建最小生成森林。 
2. 使用二进制提升预先计算祖先和最大边权重。 
3. 对于每个查询：

 - 检查节点是否已连接。 
- 找到它们之间的 MST 路径上的最大边权重。 
- 返回最大值是否为`< limit`。 

这会将每个查询的时间减少到对数。

 ## 算法演练

 ### 第 1 步：按权重对所有边进行排序

 我们首先按距离非降序对边进行排序。 

这是 Kruskal 算法所必需的，该算法通过始终选择连接两个不同组件的最小可用边来构建最小生成森林。 

### 步骤 2：使用并集查找构建最小生成森林

 我们初始化一个 Union Find 结构。 

然后我们迭代排序后的边：

 1. 对于每条边`(u, v, w)`,
 2.如果`u`和`v`属于不同的组件，
 3.合并它们，
 4. 将边添加到MST 邻接表中。 

这会创建一个森林，因为原始图可能会断开连接。 

MST 保留节点之间的最小可能最大边，这正是阈值连通性查询所需的属性。 

### 步骤 3：准备二元升降台

 我们对森林中每个未访问的节点执行 DFS。 

在 DFS 期间我们记录：

 -`depth[node]`-`parent[node][0]`-`maxEdge[node][0]`在哪里：

-`parent[node][0]`是直接父级
 -`maxEdge[node][0]`是父级的边权重

 然后我们构建更高的祖先表：$$parent[node][k]$$这代表了`2^k`祖先。 

相似地：$$maxEdge[node][k]$$存储攀爬时遇到的最大边缘权重`2^k`向上迈出一步。 

此预处理支持对数路径查询。 

### 步骤 4：存储连接的组件

 在 Kruskal 构建之后，并集查找已经知道哪些节点属于同一连通分量。 

如果两个节点断开连接，它们之间的每个查询都会立即返回`false`。 

### 步骤 5：处理查询

 供查询`(p, q, limit)`:

 1.如果`p`和`q`未连接，返回`false`。 
2. 向上提升较深的节点，直到两个节点处于相同深度。 
3. 提升时，跟踪遇到的最大边缘重量。 
4. 将两个节点一起向上提升，直到其祖先节点匹配。 
5. 包括通向 LCA 的最终边。 
6. 结果是MST路径上的最大边权重。 
7、返回是否：$$maxWeight < limit$$### 为什么它有效

 正确性依赖于经典的 MST 属性：

 对于任意两个节点，最小生成树中它们之间的路径最小化原始图中所有可能路径中的最大边权重。 

因此，如果 MST 路径上的最大边权值小于`limit`，则原图中存在有效路径。 反之，如果 MST 路径包含权重至少为`limit`，不存在有效路径。 

这使得每个查询都可以减少为检查一个树路径上的最大边。 

## Python 解决方案```python
from typing import List
import math

class UnionFind:
    def __init__(self, n: int):
        self.parent = list(range(n))
        self.rank = [0] * n

    def find(self, x: int) -> int:
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])
        return self.parent[x]

    def union(self, a: int, b: int) -> bool:
        root_a = self.find(a)
        root_b = self.find(b)

        if root_a == root_b:
            return False

        if self.rank[root_a] < self.rank[root_b]:
            root_a, root_b = root_b, root_a

        self.parent[root_b] = root_a

        if self.rank[root_a] == self.rank[root_b]:
            self.rank[root_a] += 1

        return True

class DistanceLimitedPathsExist:

    def __init__(self, n: int, edgeList: List[List[int]]):
        self.n = n
        self.LOG = math.ceil(math.log2(max(2, n)))

        edgeList.sort(key=lambda x: x[2])

        self.graph = [[] for _ in range(n)]

        self.uf = UnionFind(n)

        for u, v, w in edgeList:
            if self.uf.union(u, v):
                self.graph[u].append((v, w))
                self.graph[v].append((u, w))

        self.depth = [0] * n
        self.parent = [[-1] * self.LOG for _ in range(n)]
        self.max_edge = [[0] * self.LOG for _ in range(n)]

        visited = [False] * n

        for node in range(n):
            if not visited[node]:
                self._dfs(node, -1, 0, 0, visited)

        for j in range(1, self.LOG):
            for node in range(n):
                prev_parent = self.parent[node][j - 1]

                if prev_parent != -1:
                    self.parent[node][j] = self.parent[prev_parent][j - 1]

                    self.max_edge[node][j] = max(
                        self.max_edge[node][j - 1],
                        self.max_edge[prev_parent][j - 1]
                    )

    def _dfs(
        self,
        node: int,
        par: int,
        depth: int,
        weight: int,
        visited: List[bool]
    ) -> None:
        visited[node] = True

        self.depth[node] = depth
        self.parent[node][0] = par
        self.max_edge[node][0] = weight

        for neighbor, edge_weight in self.graph[node]:
            if not visited[neighbor]:
                self._dfs(
                    neighbor,
                    node,
                    depth + 1,
                    edge_weight,
                    visited
                )

    def query(self, p: int, q: int, limit: int) -> bool:
        if self.uf.find(p) != self.uf.find(q):
            return False

        maximum = 0

        if self.depth[p] < self.depth[q]:
            p, q = q, p

        diff = self.depth[p] - self.depth[q]

        for bit in range(self.LOG):
            if diff & (1 << bit):
                maximum = max(maximum, self.max_edge[p][bit])
                p = self.parent[p][bit]

        if p == q:
            return maximum < limit

        for bit in range(self.LOG - 1, -1, -1):
            if self.parent[p][bit] != self.parent[q][bit]:
                maximum = max(maximum, self.max_edge[p][bit])
                maximum = max(maximum, self.max_edge[q][bit])

                p = self.parent[p][bit]
                q = self.parent[q][bit]

        maximum = max(maximum, self.max_edge[p][0])
        maximum = max(maximum, self.max_edge[q][0])

        return maximum < limit
```实现首先使用 Kruskal 算法构建最小生成森林。 并查找有效地确定一条边是否连接两个不同的组件。 

邻接表只存储MST边，而不存储所有原始边。 这很重要，因为 MST 路径保留了尽可能小的瓶颈边缘。 

深度优先搜索初始化二进制提升表。 每个节点记录：

 - 它的父级
 - 它的深度
 - 与祖先的最大优势

 预处理阶段构建两个祖先的幂，因此查询可以对数向上跳跃。 

这`query`方法首先检查连接性。 如果节点断开连接，答案立即`false`。 

否则，它使用二进制提升计算沿 MST 路径的最大边权重。 最终对比`limit`决定了答案。 

## 解决方案```go
package main

import (
	"math"
	"sort"
)

type UnionFind struct {
	parent []int
	rank   []int
}

func NewUnionFind(n int) *UnionFind {
	parent := make([]int, n)
	rank := make([]int, n)

	for i := 0; i < n; i++ {
		parent[i] = i
	}

	return &UnionFind{
		parent: parent,
		rank:   rank,
	}
}

func (uf *UnionFind) Find(x int) int {
	if uf.parent[x] != x {
		uf.parent[x] = uf.Find(uf.parent[x])
	}
	return uf.parent[x]
}

func (uf *UnionFind) Union(a, b int) bool {
	rootA := uf.Find(a)
	rootB := uf.Find(b)

	if rootA == rootB {
		return false
	}

	if uf.rank[rootA] < uf.rank[rootB] {
		rootA, rootB = rootB, rootA
	}

	uf.parent[rootB] = rootA

	if uf.rank[rootA] == uf.rank[rootB] {
		uf.rank[rootA]++
	}

	return true
}

type Edge struct {
	to     int
	weight int
}

type DistanceLimitedPathsExist struct {
	n       int
	log     int
	graph   [][]Edge
	depth   []int
	parent  [][]int
	maxEdge [][]int
	uf      *UnionFind
}

func Constructor(n int, edgeList [][]int) DistanceLimitedPathsExist {
	logVal := int(math.Ceil(math.Log2(float64(max(2, n)))))

	graph := make([][]Edge, n)

	sort.Slice(edgeList, func(i, j int) bool {
		return edgeList[i][2] < edgeList[j][2]
	})

	uf := NewUnionFind(n)

	for _, edge := range edgeList {
		u, v, w := edge[0], edge[1], edge[2]

		if uf.Union(u, v) {
			graph[u] = append(graph[u], Edge{v, w})
			graph[v] = append(graph[v], Edge{u, w})
		}
	}

	parent := make([][]int, n)
	maxEdge := make([][]int, n)

	for i := 0; i < n; i++ {
		parent[i] = make([]int, logVal)
		maxEdge[i] = make([]int, logVal)

		for j := 0; j < logVal; j++ {
			parent[i][j] = -1
		}
	}

	obj := DistanceLimitedPathsExist{
		n:       n,
		log:     logVal,
		graph:   graph,
		depth:   make([]int, n),
		parent:  parent,
		maxEdge: maxEdge,
		uf:      uf,
	}

	visited := make([]bool, n)

	for i := 0; i < n; i++ {
		if !visited[i] {
			obj.dfs(i, -1, 0, 0, visited)
		}
	}

	for j := 1; j < logVal; j++ {
		for node := 0; node < n; node++ {
			prevParent := obj.parent[node][j-1]

			if prevParent != -1 {
				obj.parent[node][j] = obj.parent[prevParent][j-1]

				obj.maxEdge[node][j] = max(
					obj.maxEdge[node][j-1],
					obj.maxEdge[prevParent][j-1],
				)
			}
		}
	}

	return obj
}

func (this *DistanceLimitedPathsExist) dfs(
	node int,
	par int,
	depth int,
	weight int,
	visited []bool,
) {
	visited[node] = true

	this.depth[node] = depth
	this.parent[node][0] = par
	this.maxEdge[node][0] = weight

	for _, edge := range this.graph[node] {
		if !visited[edge.to] {
			this.dfs(
				edge.to,
				node,
				depth+1,
				edge.weight,
				visited,
			)
		}
	}
}

func (this *DistanceLimitedPathsExist) Query(
	p int,
	q int,
	limit int,
) bool {
	if this.uf.Find(p) != this.uf.Find(q) {
		return false
	}

	maximum := 0

	if this.depth[p] < this.depth[q] {
		p, q = q, p
	}

	diff := this.depth[p] - this.depth[q]

	for bit := 0; bit < this.log; bit++ {
		if diff&(1<<bit) != 0 {
			maximum = max(maximum, this.maxEdge[p][bit])
			p = this.parent[p][bit]
		}
	}

	if p == q {
		return maximum < limit
	}

	for bit := this.log - 1; bit >= 0; bit-- {
		if this.parent[p][bit] != this.parent[q][bit] {
			maximum = max(maximum, this.maxEdge[p][bit])
			maximum = max(maximum, this.maxEdge[q][bit])

			p = this.parent[p][bit]
			q = this.parent[q][bit]
		}
	}

	maximum = max(maximum, this.maxEdge[p][0])
	maximum = max(maximum, this.maxEdge[q][0])

	return maximum < limit
}

func max(a, b int) int {
	if a > b {
		return a
	}
	return b
}
```Go 实现密切反映了 Python 逻辑。 切片用于邻接表和提升表。 整数溢出不是问题，因为边权重适合 Go 的范围`int`现代平台的限制。 

递归DFS初始化二进制提升数据。 这`max`辅助函数简化了重复的最大比较。

 ## 边缘情况

 ### 严格小于限制

 最常见的错误之一是使用`<= limit`而不是`< limit`。 

例如：```
Edge weight = 5
Limit = 5
```这条边是无效的，因为该问题需要严格的不平等。 

该实现通过检查来正确处理此问题：```
maximum < limit
```而不是允许平等。 

### 断开的组件

 该图可能包含完全独立的组件。 此类节点之间的查询应立即返回`false`。 

该实现使用 Union Find 有效地处理了这个问题。 在执行任何 LCA 逻辑之前，它会检查两个节点是否属于同一组件。 

这可以防止无效的祖先遍历并避免不必要的计算。 

### 同一节点之间的多条边

 该图可能包含连接具有不同权重的相同端点的多条边。 

幼稚的实现可能会错误地使用较大的边缘。 Kruskal 算法自然避免了这个问题，因为边是按排序顺序处理的。 首先选择最小的有用边缘，如果较大的冗余边缘产生循环，则跳过它们。 

这保证了MST保留最优的瓶颈结构。 

### 无边图

 如果`edgeList`为空，每个节点形成自己的组件。 

DFS 预处理仍然有效，因为每个节点都成为一个孤立的树根。 查询正确返回`false`对于所有不同的节点对。 

该实现可以安全地处理此问题，无需特殊情况逻辑。
