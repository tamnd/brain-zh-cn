 # LeetCode 1702，更改后的最大二进制字符串

 ## 问题理解

 这个问题给了我们一个只包含以下内容的二进制字符串`'0'`和`'1'`。 我们可以重复应用两个转换规则：

 - 更换`"00"`和`"10"`- 代替`"10"`和`"01"`我们可以按照任意顺序多次执行这些操作，目标是生成数值上最大的二进制字符串。 

由于二进制数是按十进制值进行比较的，因此最大化字符串意味着我们希望最左边的位尽可能大。 在实践中，这意味着我们希望有尽可能多的领先`'1'`尽可能的字符。 

输入长度可以大到`10^5`，它立即告诉我们指数探索或对所有可能的变换进行重复模拟是不可行的。 我们需要一个线性或接近线性的解决方案。 

最重要的观察是这些操作允许零以非常特殊的方式移动和组合。 简单的实现可能会重复扫描字符串并应用转换，直到无法进行更多更改，但这对于大型输入来说太慢了。 

一些边缘情况很重要：

 - 不包含零的字符串，例如`"1111"`，已经是最大值了。 
- 恰好包含一个零的字符串，例如`"10111"`，无法完全消除该零。 
- 像这样的字符串`"0000"`可以发生重大转变，理解最终的安排至关重要。 
- 非常短的字符串，例如`"0"`或者`"01"`仍必须正常工作。 
- 在最佳结果中，多个分离的零最终会崩溃为单个零。 

该问题保证输入仅包含有效的二进制字符并且字符串长度至少为 1。 

## 方法

 ### 蛮力方法

 强力解决方案将重复应用所有可能的操作，直到无法进一步改进为止。 

一种方法是：

 1. 扫描字符串中是否出现`"00"`并将它们替换为`"10"`。 
2. 扫描是否出现以下情况`"10"`并将它们替换为`"01"`。 
3. 继续，直到绳子稳定。 

这种方法是正确的，因为它直接遵循允许的操作并探索向更大的二进制值的转换。 

然而，问题是每次转换只改变字符串的一小部分。 在最坏的情况下，我们可能会执行大量的操作。 对于一个长度的字符串`n`，变换次数可以接近`O(n^2)`。 自从`n`可以是`100000`，这变得太慢了。 

### 最优贪婪观察

 关键的见解是除 1 之外的所有 0 最终都可以转换为 1。 

这些操作有效地允许零向右移动，同时将较早的位置转换为 1。 

考虑会发生什么：

 -`"00" -> "10"`将零的数量减少 1。 
-`"10" -> "01"`向右移动一个零。 

最终：

 - 所有零合并为一个剩余零。 
- 该零最终处于可预测的位置。 

认为：

-`first_zero`是第一个的索引`'0'`-`zero_count`是零的总数

 那么最终的字符串将包含：

 - 全部`'1'`- 除了一个`'0'`- 位于索引：```
first_zero + zero_count - 1
```为什么？ 

第一个之后的每个零都可以有效地转换为`'1'`，而剩余的零则通过变换向右推。 

这为我们提供了线性时间内的直接构造算法。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 模拟重复变换 |
 | 最佳 | O(n) | O(n) | 直接构造最终最大字符串 |

 ## 算法演练

 1. 扫描字符串以找到第一次出现的位置`'0'`。 

如果不存在零，则该字符串已经是最大的，因为所有位都已`'1'`。 
2. 计算字符串中零的总数。 

这告诉我们最终可以将多少个零合并在一起。 
3. 计算剩余零的最终位置。 

剩余的零最终将是：```
first_zero + zero_count - 1
```发生这种情况是因为每个附加的零都会有效地将幸存的零向右移动一个位置。 
4. 创建一个完全填充的结果数组`'1'`。 

由于最佳字符串仅包含一个零，因此每隔一个位置都应该是`'1'`。 
5.放置一个`'0'`在计算的索引处。 

这直接构造了最大可实现的二进制字符串。 
6. 将数组转换回字符串并返回。 

### 为什么它有效

 关键的不变量是操作永远不会增加零的数量。 手术`"00" -> "10"`将零计数减一，同时`"10" -> "01"`保留它但将零向右移动。 

由于零总是可以向右移动并合并在一起，因此最佳配置是仅保留 1 个零，并在不违反转换规则的情况下将其尽可能向右推。 得出的指数`first_zero + zero_count - 1`正是剩余的零必须结束的地方。 

## Python 解决方案```python
class Solution:
    def maximumBinaryString(self, binary: str) -> str:
        first_zero = binary.find('0')

        if first_zero == -1:
            return binary

        zero_count = binary.count('0')

        result = ['1'] * len(binary)

        remaining_zero_index = first_zero + zero_count - 1
        result[remaining_zero_index] = '0'

        return ''.join(result)
```实现首先查找字符串中的第一个零。 如果不存在零，则输入已经是最佳的，因此我们立即返回它。 

接下来，我们计算总共存在多少个零。 这决定了剩余的零将向右移动多远。 

然后我们构造一个结果数组，仅包含`'1'`人物。 由于最佳最终状态恰好包含一个零，因此我们使用以下方法计算其最终位置：```python
first_zero + zero_count - 1
```最后，我们将零放在该位置并将数组连接到最终的字符串中。 

实现很简洁，因为贪婪观察消除了显式模拟的需要。 

## 解决方案```go
func maximumBinaryString(binary string) string {
    firstZero := -1
    zeroCount := 0

    for i := 0; i < len(binary); i++ {
        if binary[i] == '0' {
            zeroCount++

            if firstZero == -1 {
                firstZero = i
            }
        }
    }

    if firstZero == -1 {
        return binary
    }

    result := make([]byte, len(binary))

    for i := 0; i < len(binary); i++ {
        result[i] = '1'
    }

    remainingZeroIndex := firstZero + zeroCount - 1
    result[remainingZeroIndex] = '0'

    return string(result)
}
```Go 实现遵循与 Python 解决方案完全相同的逻辑。 

一个区别是 Go 字符串是不可变的，因此我们使用`[]byte`切片以有效地构造结果。 修改切片后，我们将其转换回字符串。 

不存在整数溢出问题，因为索引保留在字符串长度的范围内，字符串长度最多为`10^5`。

 ## 边缘情况

 当字符串根本不包含零时，会出现一种重要的边缘情况，例如`"11111"`。 有缺陷的实现可能会错误地尝试在结果中的某个位置放置零。 正确的行为是立即返回原始字符串不变。 该实现通过检查是否`first_zero == -1`。 

另一个关键情况是当字符串恰好包含一个零时，例如`"10111"`。 既然没有`"00"`对存在，零的数量不能进一步减少。 因此，最佳字符串在相同的有效位置仍然恰好包含一个零。 该公式自然可以处理这个问题，因为`zero_count - 1`变为零。 

第三个重要的边缘情况是完全由零组成的字符串，例如`"00000"`。 单纯的模拟可能会变得低效，因为许多操作都是可能的。 贪婪构造正确地认识到所有零最终都会在字符串末尾附近崩溃为一个剩余的零。 最终输出变为`"11110"`。 

另一个微妙的情况涉及由许多个分隔的零，例如`"100001"`。 这些操作允许零在字符串中移动和合并，因此最终的排列与原始位置相比并不明显。 数学放置公式可确保剩余的零准确地落在应有的位置，而不管间距如何。
