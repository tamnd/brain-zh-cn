[LeetCode 第 1748 题](https://leetcode.com/problems/sum-of-unique-elements/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表、计数

 ## 解决方案

 ## 问题理解

 问题给了我们一个整数数组`nums`并要求我们计算数组中仅出现一次的所有元素的总和。 

仅当某个元素的频率恰好为 1 时，该元素才被视为唯一。 如果某个值出现两次或多次，则它根本不能对最终总和产生影响。 

例如，在数组中`[1,2,3,2]`, 数量`2`出现两次，因此它不是唯一的。 数字`1`和`3`每个都出现一次，所以答案变成`1 + 3 = 4`。 

输入是一个整数列表，其中：

 -`nums.length`范围从`1`到`100`-`nums[i]`范围从`1`到`100`这些限制非常小。 即使是二次解在技术上也能轻松通过。 然而，我们的目标仍然是设计一种干净、高效的方法，能够自然扩展并展示良好的算法思维。 

关键的观察是我们需要频率信息。 我们无法通过单独查看一个数字来确定它是否唯一。 我们必须知道每个值在数组中出现了多少次。 

一些重要的边缘情况值得尽早考虑：

 - 每个元素都是重复的数组，例如`[1,1,2,2]`，应该返回`0`- 每个元素都是唯一的数组，例如`[1,2,3]`，应返回所有值的总和
 - 只包含一个元素的数组，例如`[7]`，应该返回该元素本身
 - 具有分散在整个输入中的重复值的数组仍应正确计算频率

 该问题保证数组非空并且所有值都是正整数，因此我们永远不需要处理无效或丢失的输入。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是单独检查每个元素并计算它在数组中出现的次数。 

对于每个数字`nums[i]`，我们可以扫描整个数组并计算它的出现次数。 如果计数等于 1，我们将其添加到答案中。 

这种方法之所以有效，是因为它直接遵循问题定义。 我们明确确定每个元素是否恰好出现一次。 

然而，这种方法效率低下，因为对于每个元素，我们都会对数组执行另一次完整遍历。 如果数组有`n`元素，总工作变为`O(n²)`。 

尽管约束足够小，可以通过，但这并不是最好的设计。 

### 最佳方法

 更好的解决方案是首先使用哈希图来计算频率。 

我们遍历数组并记录每个数字出现的次数。 然后，我们再次遍历频率图，并仅对频率恰好为 1 的值求和。 

重要的见解是频率计数将重复的昂贵扫描转换为恒定时间查找。 

哈希映射在这里是理想的选择，因为：

 - 它有效地存储计数
 - 插入和查找是平均水平`O(1)`- 它自然地处理重复值

 这将总时间复杂度从二次降低到线性。

 | 方法| 时间复杂度| 空间复杂度| 笔记|

 ## 算法演练

 1. 创建一个空的哈希映射，名为`frequency`。 

该映射将每个数字存储为键，并将其出现的次数存储为值。 
2. 遍历数组一次。 

对于每一个数字`nums`，增加其在哈希图中的计数。 

在此过程之后，映射包含所有元素的完整频率信息。 
3. 初始化一个名为`unique_sum`到`0`。 

这个变量将累积最终的答案。 
4. 遍历频率图。 

对于每个`(number, count)`对：

 - 如果`count == 1`，将数字添加到`unique_sum`- 否则，忽略它，因为它不是唯一的
 5. 返回`unique_sum`。 

此时，总和恰好包含数组中出现过一次的值。 

### 为什么它有效

 该算法之所以有效，是因为频率图存储了每个不同元素的准确出现次数。 

当且仅当一个元素的频率等于 1 时，该元素才对答案做出贡献。 由于第一次遍历时每个数字都被正确计数，因此第二次遍历可以准确识别所有唯一元素。 

没有遗漏任何元素，也没有错误地包含重复元素。 

## Python 解决方案```python
from typing import List
from collections import Counter

class Solution:
    def sumOfUnique(self, nums: List[int]) -> int:
        frequency = Counter(nums)

        unique_sum = 0

        for number, count in frequency.items():
            if count == 1:
                unique_sum += number

        return unique_sum
```该实现使用Python的`Counter`类来自`collections`模块来简化频率计数。 

The line`frequency = Counter(nums)`自动创建一个哈希映射，其中每个键是数组中的一个数字，每个值是其出现次数。 

接下来，变量`unique_sum`被初始化为零。 我们迭代每一个`(number, count)`频率图中的对。 每当计数等于 1 时，我们就把该数字添加到运行总数中。 

最后，我们返回累计的总和。 

该实现直接反映了前面描述的算法，并保持代码简洁和可读。 

## 解决方案```go
func sumOfUnique(nums []int) int {
	frequency := make(map[int]int)

	for _, num := range nums {
		frequency[num]++
	}

	uniqueSum := 0

	for num, count := range frequency {
		if count == 1 {
			uniqueSum += num
		}
	}

	return uniqueSum
}
```Go 解决方案遵循与 Python 版本相同的逻辑，但使用 Go 的内置映射类型进行频率计数。 

声明`make(map[int]int)`创建从整数到整数的哈希映射。 在迭代过程中，每个数字的计数都会递增。 

Go 没有内置的`Counter`与Python等效，因此频率计数是手动执行的。 

由于约束非常小，因此无需特别担心整数溢出。 最大可能总和最多为`1 + 2 + ... + 100 = 5050`，它很容易适合 Go 的内部`int`类型。

 ## 边缘情况

 一个重要的边缘情况是每个元素出现多次。 例如，`[1,1,2,2]`不包含唯一值。 如果一个有缺陷的实现只检查某个数字以前是否见过，那么它可能会意外地包含重复的数字。 频率图方法可以正确处理这个问题，因为只有计数恰好等于 1 的数字才会添加到总和中。 

另一个重要的情况是每个元素都是唯一的，例如`[1,2,3,4]`。 在这种情况下，算法应返回整个数组的总和。 由于每个频率计数都变成一，因此在求和阶段自然包括每个数字。 

第三种边缘情况是单元素数组，例如`[42]`。 由于唯一元素恰好出现一次，因此必须直接返回。 该实现会自动处理这个问题，因为频率图存储`{42: 1}`，求和阶段将其添加到答案中。 

一个微妙的情况涉及数组中相距较远出现的重复元素，例如`[1,2,3,1]`。 仅比较相邻值的简单实现在这里会失败。 哈希映射方法完全避免了这个问题，因为它全局跟踪整个阵列的总频率。
