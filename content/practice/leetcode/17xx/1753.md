[LeetCode 问题 1753](https://leetcode.com/problems/maximum-score-from-removing-stones/)

 **难度：** 🟡 中等
 **主题：** 数学、贪婪、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 问题是一个组合游戏，涉及**三堆石头**和计数`a`,`b`， 和`c`。 在每次移动中，您都可以选择**两个不同的非空堆**，并从每个堆中移走**一颗石头**，每次移动获得**1分**。 当剩下的石子少于两堆时，游戏结束。 目标是通过最佳地执行这些动作来计算可能的**最大分数**。 

输入由三个整数组成`a`,`b`， 和`c`，每个代表一堆石头的数量。 输出是一个整数，表示可达到的最高分数。 限制条件`1 <= a, b, c <= 10^5`告诉我们解决方案必须**有效**，理想情况下为 O(1) 或 O(log n)，因为单独迭代每个石头可能会太慢。 

主要观察结果包括这样一个事实：移动总是会使石子总数减少 **2**，并且您一次只能将两堆石子配对。 要考虑的边缘情况包括当一堆比其他两堆的总和大得多时，或者当所有堆的数量相等时。 

## 方法

 **暴力方法**涉及直接模拟游戏：重复挑选最大的两堆，从每堆中取出一块石头，然后将分数加 1，直到少于两堆保持非空状态。 这保证了正确性，因为每一步都是有效的，但效率很低：如果所有棋子的总和达到 3×10^5，重复选择桩和更新计数会很慢。 

最佳解决方案的**关键见解**基于**排序和数学推理**。 让`x ≤ y ≤ z`是排序后堆的大小。 最大移动次数受以下任一限制`x + y`（如果最大的一堆大于其他两堆的总和，则多余的石子不能成对）或`(a + b + c) // 2`（由于每次移动会消除 2 个石子，因此您得分不能超过总石子的一半）。 这给出了一个直接的公式：```
max_score = min(a + b, a + c, b + c, (a + b + c) // 2)
```该公式消除了模拟的需要，并且在**恒定时间**内运行。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(a + b + c) | O(1) | O(1) | 通过重复选择两个最大的桩来模拟每次移动 |
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 使用排序或最大最小逻辑来计算`min(a + b, a + c, b + c, (a + b + c) // 2)`|

 ## 算法演练

 1. 取输入整数`a`,`b`， 和`c`。 
2.将三个数排序得到`x ≤ y ≤ z`。 这有助于推断相对于其他堆而言最大的堆。 
3. 计算所有石子的总和`total = a + b + c`。 
4. 计算两个最小堆的总和`x + y`。 
5. 最高分是以下各项中的最小值`x + y`和`total // 2`。 这可以确保您不会移除比现有石子更多的石子，并且还考虑到移动需要两块石子的事实。 
6. 返回该值作为结果。 

**为什么有效：** 排序可确保`x + y`始终是可能的移动次数，如果`z`非常大。 服用`min(x + y, total // 2)`保证我们不会超过可配对的宝石数量。 这个不变量保证了任何有效输入的正确性。 

## Python 解决方案```python
class Solution:
    def maximumScore(self, a: int, b: int, c: int) -> int:
        piles = sorted([a, b, c])
        x, y, z = piles
        return min(x + y, (a + b + c) // 2)
```**实现说明：** 首先，我们对堆进行排序，确定哪些是最大的，哪些是较小的。`x + y`代表当最大的一堆可能占主导地位时的最大可能移动。`(a + b + c) // 2`代表绝对上限，因为每次移动消耗两颗棋子。 返回其中的最小值可确保我们尊重这两个约束。 

## 解决方案```go
func maximumScore(a int, b int, c int) int {
    // Sort a, b, c using simple comparisons
    if a > b {
        a, b = b, a
    }
    if b > c {
        b, c = c, b
    }
    if a > b {
        a, b = b, a
    }
    if a+b < (a+b+c)/2 {
        return a + b
    }
    return (a + b + c) / 2
}
```**Go 特定说明：** 由于 Go 没有针对三个整数的内置排序，因此我们使用条件交换手动排序。 其余部分遵循与 Python 解决方案相同的逻辑，确保我们不会超出任何一个`x + y`或者`total // 2`。

 ## 边缘情况

 **1. 巨大的差异：** 当一堆比其他两堆的总和大得多时，它不能贡献更多的动作。 该解决方案正确地将最大分数限制为`x + y`。 

**2. 相等的桩：** 当所有桩都相等时，每次移动都可以通过将任意两桩配对来完成。 该公式仍然可以正确计算`total // 2`作为最大移动次数。 

**3. 最小输入值：** 如果桩全部为 1，则解决方案对其进行处理并返回 1。这可确保约束的边缘不会导致差一错误。 

**4. 最大输入值：** 桩数`10^5`测试具有固定大小整数的语言中的整数溢出。 Python 自然地处理它，并且在 Go 中，整数除法和加法在这些值的 32 位 int 限制内保持安全。
