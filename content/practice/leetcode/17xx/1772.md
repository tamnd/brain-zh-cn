[LeetCode 问题 1772](https://leetcode.com/problems/sort-features-by-popularity/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、字符串、排序

 ## 解决方案

 ## 问题理解

 这个问题要求我们根据用户调查回复来确定产品功能的受欢迎程度。 我们得到了一份清单`features`其中每个元素是一个单字特征名称，以及一个列表`responses`其中每个元素都是用户报告喜欢的一串以空格分隔的单词。 某个功能的**受欢迎程度**定义为至少一次提及该功能的响应数量。 如果某个响应多次提及同一功能，则该响应仅计数一次。 

目标是返回按流行度非递增顺序排序的功能。 如果两个功能具有相同的受欢迎程度，则原始功能中出现较早的功能`features`清单应该放在第一位。 

约束表明`features`最多可以有 10,000 个项目，每个响应最多可以有 1,000 个字符，但响应数量限制为 102。这表明迭代响应的成本相对较低，而迭代响应中每个单词的特征列表的成本可能会很高。 重要的边缘情况包括重复提及某个功能的响应、未提及任何功能的响应或根本未提及的功能。 

## 方法

 ### 蛮力方法

 暴力解决方案将迭代每个响应的每个特征，计算有多少个响应包含每个特征。 对于每个响应，我们可以检查该功能是否作为子字符串出现在响应字符串中。 虽然这种方法有效，但效率较低，因为它需要扫描每个响应字符串中的每个特征，导致时间复杂度为 O(F * R * L)，其中 F 是特征数量，R 是响应数量，L 是响应的平均长度。 对于 10,000 个特征的上限，此方法可能会很慢。 

### 最佳方法

 关键的见解是我们不需要为每个功能重复搜索相同的响应。 相反，我们可以将每个响应标记为一组唯一的单词，并检查该组中是否存在任何特征。 使用哈希图（字典）来跟踪功能流行度使我们能够有效地进行计数。 计数后，我们可以使用稳定的排序方式按流行程度对特征进行排序，该排序在出现平局时尊重原始特征顺序。 

这种方法提高了效率，因为将响应转换为一组单词并检查成员资格比重复的子字符串搜索要快得多。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(F * R * L) | O(F * R * L) | O(F) | 直接根据每个响应字符串检查每个功能 |
 | 最佳 | O(R * W + F * log F) | O(R * W + F * log F) | O(F + R * W) | O(F + R * W) | 使用响应中唯一单词的集合、计数的哈希映射以及稳定排序 |

 这里，W 是每个响应的平均字数。 

## 算法演练

 1.初始化一个字典`feature_count`用键作为特征，值为零来存储流行度计数。 
2. 对于每个响应`responses`：

 1. 将响应字符串拆分为单独的单词。 
2. 将单词列表转换为集合`words_in_response`删除重复项。 
3. 对于每个特征`features`，检查它是否存在于`words_in_response`。 如果是，则增加其计数`feature_count`。 
3. 处理完所有响应后，对`features`基于两个标准的列表：

 1. 人气由高到低排列。 
2. 原始索引`features`打破平局的名单。 
4. 返回排序后的列表。 

**为什么有效：** 由于转换为集合，每个响应最多对每个特征的计数贡献一次。 使用字典可确保有效计数。 以流行度作为主键、以原始索引作为辅助进行排序可以保留所需的顺序并保证正确性。 

## Python 解决方案```python
from typing import List

class Solution:
    def sortFeatures(self, features: List[str], responses: List[str]) -> List[str]:
        feature_count = {feature: 0 for feature in features}
        feature_index = {feature: idx for idx, feature in enumerate(features)}
        
        for response in responses:
            words_in_response = set(response.split())
            for feature in features:
                if feature in words_in_response:
                    feature_count[feature] += 1
        
        sorted_features = sorted(
            features,
            key=lambda f: (-feature_count[f], feature_index[f])
        )
        
        return sorted_features
```该代码初始化计数字典和索引字典以进行平局打破。 每个响应都被分成唯一的单词，并且计数会有效更新。 最后，按流行度和原始顺序对特征进行稳定排序。 

## 解决方案```go
package main

import (
	"sort"
	"strings"
)

func sortFeatures(features []string, responses []string) []string {
	featureCount := make(map[string]int)
	featureIndex := make(map[string]int)
	for i, feature := range features {
		featureCount[feature] = 0
		featureIndex[feature] = i
	}
	
	for _, response := range responses {
		words := strings.Fields(response)
		wordsSet := make(map[string]struct{})
		for _, word := range words {
			wordsSet[word] = struct{}{}
		}
		for _, feature := range features {
			if _, exists := wordsSet[feature]; exists {
				featureCount[feature]++
			}
		}
	}
	
	sort.SliceStable(features, func(i, j int) bool {
		if featureCount[features[i]] == featureCount[features[j]] {
			return featureIndex[features[i]] < featureIndex[features[j]]
		}
		return featureCount[features[i]] > featureCount[features[j]]
	})
	
	return features
}
```在 Go 中，我们使用映射来计数和存储原始索引。`strings.Fields`方便地将响应拆分为单词，并且`sort.SliceStable`保证为关系保留原始顺序。 

## 工作示例

 **示例1：**```
features = ["cooler","lock","touch"]
responses = ["i like cooler cooler","lock touch cool","locker like touch"]
```步骤 1：初始化计数：```
feature_count = {"cooler":0, "lock":0, "touch":0}
```第 2 步：处理第一个响应`"i like cooler cooler"`：```
words_in_response = {"i","like","cooler"}
feature_count["cooler"] += 1
```第 3 步：处理第二个响应`"lock touch cool"`：```
words_in_response = {"lock","touch","cool"}
feature_count["lock"] += 1
feature_count["touch"] += 1
```第 4 步：处理第三个响应`"locker like touch"`：```
words_in_response = {"locker","like","touch"}
feature_count["touch"] += 1
```最终计数：```
{"cooler":1,"lock":1,"touch":2}
```按人气排序：`["touch","cooler","lock"]`**示例2：**```
features = ["a","aa","b","c"]
responses = ["a","a aa","a a a a a","b a"]
```最终计数：```
{"a":4,"aa":1,"b":1,"c":0}
```排序：`["a","aa","b","c"]`## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(R * W + F * log F) | O(R * W + F * log F) | R 是响应数，W 是每个响应的平均字数； 排序特征需要 F * log F |
 | 空间| O(F + R * W) | O(F + R * W) | O(F) 用于计数和索引映射，O(W) 用于每个响应中设置的单词 |

 该算法具有良好的扩展性，因为 R 与 F 相比较小，并且检查集合中的成员资格的时间复杂度为 O(1)。

 ## 边缘情况

 **1. 特征永远不会出现在响应中：** 计数为零的特征应出现在排序列表的末尾。 实现处理这个问题是因为它们的计数保持为零，并且稳定排序尊重原始顺序。 

**2. 响应包含重复的单词：** 单个响应中多次出现某个功能应仅算一次。 将每个响应转换为一组可确保重复
