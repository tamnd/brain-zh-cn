[LeetCode 1774 题](https://leetcode.com/problems/closest-dessert-cost/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划、回溯

 ## 解决方案

 ## 问题理解

 该问题要求我们使用一种冰淇淋底料和零种或多种配料制作甜点，并附加限制，即每种配料类型最多可以使用两次。 每个底料和配料都有成本，我们的目标是制作总成本尽可能接近给定目标值的甜点。 如果多种组合产生的成本同样接近目标，我们应该返回较小的一种。 

输入是两个整数数组，`baseCosts`和`toppingCosts`，和一个整数`target`。 中的每个元素`baseCosts`代表一种冰淇淋底料的成本，而其中的每个元素`toppingCosts`代表单个单位的配料类型的成本。 约束告诉我们两个数组的长度最多为 10，并且所有成本和目标都有合理的界限（1 到 10^4）。 小输入大小表明穷举搜索是可行的，但我们仍然需要一种有效的方法，因为每个打顶可以出现 0、1 或 2 次，从而导致每个碱基最多有 3^m 个打顶组合。 

边缘情况包括目标小于所有基本成本、目标与基本成本完全匹配或多种组合产生与目标相同的最小距离的场景。 如果存在平局，算法必须通过选择较小的成本来优雅地处理这些问题。 

## 方法

 **暴力方法**是通过迭代每个基础并考虑每种配料的 0、1 或 2 的所有组合来生成所有可能的甜点。 对于每种组合，我们计算总成本并跟踪最接近目标的成本。 这是正确的，因为它考虑了所有有效的甜点，但复杂性以 O(n * 3^m) 的形式增长，这对于 n, m ≤ 10 是可以接受的，但考虑到问题规模较小，可能是不必要的。 

**优化方法**使用回溯 (DFS) 策略。 我们迭代每个基础，然后递归地探索添加 0、1 或 2 个每个配料，每当我们找到更接近目标的组合时更新最接近的成本。 递归确保考虑所有有效组合，而无需在内存中显式存储所有可能性。 该方法通过修剪无法改进解决方案的路径来避免不必要的计算，特别是当当前总数已经超过目标并且添加更多配料只会使情况变得更糟时。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * 3^m) | O(n * 3^m) | O(1) | O(1) | 显式生成每个碱基的所有配料组合 |
 | 回溯/DFS | O(n * 3^m) | O(n * 3^m) | O(米) | 递归探索配料，动态更新最接近的成本 |

 ## 算法演练

 1. 初始化变量`closest`从任何基本成本开始，跟踪最接近目标的成本。 
2. 定义递归辅助函数`dfs(index, currentCost)`在哪里`index`代表正在考虑的配料，并且`currentCost`是迄今为止甜点的总成本。 
3. 在每次topping时，递归调用`dfs`对于三种情况：使用 0、1 或 2 个单位的配料。 添加相应的打顶成本`currentCost`。 
4. 在每次递归调用中，更新`closest`如果`currentCost`比当前更接近目标`closest`。 如果两种成本同样接近，则选择较小的一种。 
5. 为每个基本成本启动 DFS`baseCosts`和`index = 0`和`currentCost = base`。 
6. 返回`closest`在探索了所有组合之后。 

工作原理：DFS 探索每个碱基的所有有效配料组合，同时动态更新最接近的成本。 不变量是在访问完所有递归路径之后，`closest`保持与目标的最小差异。 由于考虑了所有路径，因此保证了正确性。 

## Python 解决方案```python
from typing import List

class Solution:
    def closestCost(self, baseCosts: List[int], toppingCosts: List[int], target: int) -> int:
        closest = min(baseCosts, key=lambda x: (abs(x - target), x))
        
        def dfs(index: int, currentCost: int):
            nonlocal closest
            if abs(currentCost - target) < abs(closest - target) or \
               (abs(currentCost - target) == abs(closest - target) and currentCost < closest):
                closest = currentCost
            if index == len(toppingCosts):
                return
            for count in range(3):
                dfs(index + 1, currentCost + toppingCosts[index] * count)
        
        for base in baseCosts:
            dfs(0, base)
        return closest
```Python 实现初始化`closest`以最接近目标的基本成本作为起点。 递归 DFS 考虑每个 topping 的 0、1 或 2 个并更新`closest`当找到更好的选择时。 使用`nonlocal`允许递归函数修改`closest`在外部范围内。 

## 解决方案```go
func closestCost(baseCosts []int, toppingCosts []int, target int) int {
    closest := baseCosts[0]
    for _, b := range baseCosts {
        if absDiff(b, target) < absDiff(closest, target) || (absDiff(b, target) == absDiff(closest, target) && b < closest) {
            closest = b
        }
    }

    var dfs func(int, int)
    dfs = func(index int, currentCost int) {
        if absDiff(currentCost, target) < absDiff(closest, target) || 
           (absDiff(currentCost, target) == absDiff(closest, target) && currentCost < closest) {
            closest = currentCost
        }
        if index == len(toppingCosts) {
            return
        }
        for count := 0; count <= 2; count++ {
            dfs(index+1, currentCost + toppingCosts[index]*count)
        }
    }

    for _, base := range baseCosts {
        dfs(0, base)
    }
    return closest
}

func absDiff(a, b int) int {
    if a > b {
        return a - b
    }
    return b - a
}
```Go 实现镜像了 Python 版本，使用 DFS 闭包。 它还使用辅助函数`absDiff`干净地计算绝对差异。 由于 Go 没有`nonlocal`，闭包捕获`closest`通过参考。

 | 1 | 3+0=3 | 4 | 7 |

 返回10。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n * 3^m) | O(n * 3^m) | 每个碱基都会触发 DFS，探索每种配料的 3 个选择，因此总数为 n * 3^m |
 | 空间| O(米) | 最大递归深度是toppings的数量，m |

 给定 n、m ≤ 10 时，时间复杂度是可以接受的。空间复杂度仅限于递归堆栈深度。
