[LeetCode 问题 1709](https://leetcode.com/problems/biggest-window- Between-visits/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 的`UserVisits`表存储用户访问零售商的时间记录。 每行包含一个`user_id`和一个`visit_date`。 用户可能会出现多次，因为他们可以在许多不同的日子访问。 

目标是计算每个用户连续访问之间的最大天数。 对于用户的最终访问，应与固定日期进行比较`'2021-01-01'`。 

换句话说，对于每个用户：

 1. 按时间顺序对所有访问日期进行排序。 
2. 计算每次访问与下一次访问之间的天数差距。 
3. 对于上次访问，计算该访问与上次访问之间的差距`'2021-01-01'`。 
4. 返回该用户的最大间隙。 

输出应包含：

 -`user_id`-`biggest_window`，这是连续访问之间或上次访问与上次访问之间的最大天数`'2021-01-01'`结果必须按以下顺序排序`user_id`。 

该表没有主键，这意味着可能存在重复行。 这很重要，因为重复的访问日期可能会产生时间间隔`0`天，并且解决方案仍然必须正确处理它们。 

该问题从根本上讲是关于将同一用户的每一行与下一个按时间顺序排列的行进行比较。 这自然建议使用 SQL 窗口函数，尤其是`LEAD`，这使我们能够向前查看分区内的下一行。 

一些重要的边缘情况包括：

 - 仅访问过一次的用户
 - 重复的访问日期
 - 访问已经接近`'2021-01-01'`- 具有交错访问记录的多个用户
 - 未排序的输入数据

 如果假设输入已经排序或者忘记将上次访问与`'2021-01-01'`。 

## 方法

 ### 蛮力方法

 强力解决方案将通过以下方式独立处理每个用户：

 1. 提取该用户的所有访问
 2. 按日期对访问进行排序
 3. 将每次访问与下一次访问进行比较
 4. 追踪最大差距

 这种方法在逻辑上是正确的，因为排序保证了连续日期按时间顺序进行比较。 

然而，在 SQL 中手动实现这一点变得很麻烦。 一种可能性是使用自连接来查找每一行的下一次访问日期。 对于每次访问，我们都会搜索属于同一用户的最晚访问日期。 

这会带来昂贵的重复扫描和连接，尤其是对于大型数据集。 

### 最佳方法

 关键的见解是 SQL 窗口函数正是为这种类型的行间比较而设计的。 

使用`LEAD(visit_date)`允许我们访问同一用户的下一次访问日期，而不需要复杂的连接。 

该过程变为：

 1. 行分区依据`user_id`2. 对每个分区进行排序`visit_date`3. 使用`LEAD`获取下一次访问
 4. 如果不存在下一次访问，则替换`'2021-01-01'`5. 计算日期差异
 6. 取每个用户的最大差异

 这种方法既干净又高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 自加入重复搜索下次访问|
 | 最佳 | O(n log n) | O(n log n) | O(n) | 使用排序加窗口函数 |

 ## 算法演练

 1. 首先，对所有行进行分区`user_id`。 

这确保了每个用户的访问都是独立处理的。 决不能将不同用户的访问进行比较。 
2. 在每个用户分区内，对行进行排序`visit_date`。 

按时间顺序排序是必要的，因为我们只关心按时间顺序连续访问之间的间隔。 
3. 使用`LEAD()`窗口函数检索下次访问日期。 

对于每一行，`LEAD(visit_date)`返回属于同一用户的下一次访问日期。 
4. 处理每个用户的最终访问。 

上次访问没有下一行，所以`LEAD()`回报`NULL`。 在这种情况下，请将缺失值替换为`'2021-01-01'`。 
5. 计算日差。 

使用`DATEDIFF(next_date, visit_date)`计算访问之间的天数。 
6. 分组依据`user_id`并计算最大间隙。 

由于问题要求最大的窗口，因此我们取每个用户的最大差异。 
7. 对最终结果进行排序`user_id`。 

### 为什么它有效

 该算法之所以有效，是因为每次访问都会与其直接按时间顺序排列的后续访问进行一次比较。 由于访问已排序，因此会检查每个可能的有效窗口。 取这些窗口的最大值可以保证为每个用户返回最大的间隙。 

## Python 解决方案

 尽管这是一个数据库问题并且预期的解决方案是 SQL，但以下 Python 实现以编程方式演示了相同的逻辑。```python
from collections import defaultdict
from datetime import datetime
from typing import List, Dict

class Solution:
    def biggestWindow(self, userVisits: List[List[str]]) -> List[List[int]]:
        visits_by_user = defaultdict(list)

        for user_id, visit_date in userVisits:
            visits_by_user[user_id].append(
                datetime.strptime(visit_date, "%Y-%m-%d")
            )

        today = datetime.strptime("2021-01-01", "%Y-%m-%d")

        result = []

        for user_id in sorted(visits_by_user.keys()):
            visits = sorted(visits_by_user[user_id])

            max_gap = 0

            for i in range(len(visits) - 1):
                gap = (visits[i + 1] - visits[i]).days
                max_gap = max(max_gap, gap)

            last_gap = (today - visits[-1]).days
            max_gap = max(max_gap, last_gap)

            result.append([user_id, max_gap])

        return result
```实施首先按用户对访问日期进行分组。 一个`defaultdict(list)`使用它是因为它允许有效地附加访问而无需检查密钥是否已存在。 

每个访问日期字符串都会转换为`datetime`对象，以便可以直接执行日期减法。 

分组后，算法按排序顺序处理用户以满足所需的输出排序。 

对于每个用户：

 - 访问日期按时间顺序排序。 
- 连续访问与计算间隙进行比较。 
- 与上次访问进行比较`'2021-01-01'`。 
- 存储最大间隙。 

最后返回结果列表。 

## 解决方案```go
package main

import (
	"sort"
	"time"
)

type Solution struct{}

func (s Solution) biggestWindow(userVisits [][]string) [][]int {
	visitsByUser := make(map[int][]time.Time)

	for _, visit := range userVisits {
		userID := 0
		for _, ch := range visit[0] {
			userID = userID*10 + int(ch-'0')
		}

		date, _ := time.Parse("2006-01-02", visit[1])
		visitsByUser[userID] = append(visitsByUser[userID], date)
	}

	today, _ := time.Parse("2006-01-02", "2021-01-01")

	userIDs := make([]int, 0, len(visitsByUser))
	for userID := range visitsByUser {
		userIDs = append(userIDs, userID)
	}

	sort.Ints(userIDs)

	result := make([][]int, 0)

	for _, userID := range userIDs {
		visits := visitsByUser[userID]

		sort.Slice(visits, func(i, j int) bool {
			return visits[i].Before(visits[j])
		})

		maxGap := 0

		for i := 0; i < len(visits)-1; i++ {
			gap := int(visits[i+1].Sub(visits[i]).Hours() / 24)

			if gap > maxGap {
				maxGap = gap
			}
		}

		lastGap := int(today.Sub(visits[len(visits)-1]).Hours() / 24)

		if lastGap > maxGap {
			maxGap = lastGap
		}

		result = append(result, []int{userID, maxGap})
	}

	return result
}
```Go 实现遵循与 Python 版本相同的算法结构。 

一个重要的区别是日期处理。 Go 使用`time`包，并使用参考格式解析日期`"2006-01-02"`。 

排序是使用`sort.Slice`，它允许自定义比较逻辑`time.Time`价值观。 

间隙计算是通过减去时间戳并将持续时间从小时转换为天来完成的。 

Go没有Python的动态字典或元组解包，因此需要显式的映射管理和切片操作。 

## SQL 解决方案```sql
SELECT
    user_id,
    MAX(
        DATEDIFF(
            next_visit,
            visit_date
        )
    ) AS biggest_window
FROM (
    SELECT
        user_id,
        visit_date,
        IFNULL(
            LEAD(visit_date) OVER (
                PARTITION BY user_id
                ORDER BY visit_date
            ),
            '2021-01-01'
        ) AS next_visit
    FROM UserVisits
) AS visits
GROUP BY user_id
ORDER BY user_id;
```内部查询使用`LEAD()`检索每个用户的下一次访问日期。 

如果没有下次访问，`IFNULL()`替代品`'2021-01-01'`。 

外部查询计算日期差异并为每个用户选择最大值。

 ## 边缘情况

 ### 仅访问过一次的用户

 用户可能在表中只出现一次。 在这种情况下，不存在连续的访问对。 唯一有效的窗口是在单次访问日期和`'2021-01-01'`。 

如果实现假设每一行都有下一次访问，这种情况很容易导致错误。 该解决方案通过替换缺失的内容来正确处理这个问题`LEAD()`结果与`'2021-01-01'`。 

### 重复访问日期

 由于表没有主键，因此可能存在重复行。 两次访问可能发生在完全相同的日期，产生的窗口大小为`0`。 

幼稚的实现可能会错误地删除重复项或假设严格增加的日期。 该解决方案保持重复完整，并且`DATEDIFF()`自然回归`0`当日期相等时。 

### 未排序的输入

 不保证输入行是有序的。 如果按插入顺序而不是按时间顺序处理访问，则计算出的间隙将不正确。 

该解决方案显式地对访问进行排序`visit_date`使用`ORDER BY`在窗口函数内部，保证始终按时间顺序进行比较。 

### 最后访问处理

 每个用户的最终访问没有下一次访问行。 忘记比较`'2021-01-01'`会错过潜在的大窗户。 

该解决方案使用以下方式处理此问题`IFNULL(LEAD(...), '2021-01-01')`，确保每次访问都参与一次窗口计算。
