[LeetCode 问题 1703](https://leetcode.com/problems/minimum-adjacent-swaps-for-k-consecutive-ones/)

 **难度：** 🔴难
 **主题：** 数组、贪婪、滑动窗口、前缀和

 ## 解决方案

 ## 问题理解

 这个问题要求我们确定准确地进行相邻交换所需的最小数量`k`一个在二进制数组中连续出现。 

输入数组`nums`仅包含`0`和`1`。 在一次操作中，我们可以交换两个相邻元素。 由于交换仅是相邻的，因此移动`1`来自索引`i`索引`j`成本`|i - j|`互换。 

目标不是对数组进行排序或将所有数组移动到一起。 我们只需要一些组`k`变得连续，同时最大限度地减少所需的相邻交换总数。 

一个关键的观察是这些的相对顺序永远不会改变。 相邻交换仅将那些向左或向右滑过零。 因此，我们可以完全关注这些元素的位置，而不是整个二进制数组。 

约束条件很重要：

 -`nums.length`可以大到`10^5`- 我们最多可能有`10^5`那些
 - 二次解会太慢

 这告诉我们我们需要一个接近线性时间的算法。 

一些边缘情况很重要：

 -`k = 1`，其中不需要交换，因为单个`1`已经是连续的
 - 已经连续的数组
 - 数组，其中所选组`k`必须移动很长的距离
 - 奇数和偶数`k`，因为中位行为略有不同
 - 非常稀疏的数组，其中很少有分散得很远的数组

 该问题保证至少`k`数组中存在。 

## 方法

 ### 蛮力方法

 一种简单的方法是尝试每个可能的目标长度块`k`在数组中并计算移动一些的成本`k`进入那个街区。 

对于每个候选区间，我们可以：

 1. 收集最近的位置`k`那些
 2. 计算需要多少次相邻交换才能将它们移动到连续位置
 3. 取所有区间的最小值

 这是有效的，因为相邻的交换直接对应于移动距离。 

然而，重复计算移动成本变得昂贵。 如果有`m`的，有`O(m)`可能的规模组`k`，天真地计算每个成本可能需要`O(k)`时间。 在最坏的情况下，这会变成`O(mk)`，它可以降级为`O(n^2)`。 

这太慢了`n = 10^5`。 

### 最佳方法

 关键的见解是我们只关心这些人的职位。 

假设他们的位置是：```
positions = [p0, p1, p2, ...]
```如果我们选择`k`从这个列表中连续的，我们希望将它们移动到连续的目标位置。 

最佳排列以中间位置为中心。 这是最小化绝对距离和的经典属性。 

然而，有一个微妙的细节。 如果目标位置是连续的，则不直接最小化：```
|p_i - target_i|
```我们变换位置：```
adjusted[i] = positions[i] - i
```这消除了连续间距的影响。 

现在问题变成寻找中值最小化：```
|adjusted[i] - median|
```使用前缀和允许我们在预处理后在恒定时间内计算每个窗口的成本。 

这给出了一个`O(n)`整体解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 尝试多个组并重复计算运动 |
 | 最佳 | O(n) | O(n) | 使用 1 的位置、中位数属性和前缀和 |

 ## 算法演练

 1. 遍历数组并记录其中的索引`nums[i] == 1`。 

例如：```
nums = [1,0,0,1,0,1]
positions = [0,3,5]
```这些是唯一重要的指数。 
2. 转换位置数组。 

定义：```
adjusted[i] = positions[i] - i
```此转换消除了连续放置所造成的间距效应。 

例子：```
positions = [0,3,5]
adjusted  = [0,2,3]
```3. 构建前缀和数组`adjusted`。 

Prefix sums let us quickly compute sums over any window.
 4.滑动大小窗口`k`穿过调整后的阵列。 

每个窗口代表选择`k`ones that will become consecutive.
 5. For each window, choose the median element.

 中位数最小化绝对差值之和。 

如果：```
mid = left + k // 2
median = adjusted[mid]
```那么移动成本就变成了到中位数的总距离。 
6. 计算左侧成本。 

对于中位数之前的所有元素：```
median * countLeft - sumLeft
```7. 计算右侧成本。 

对于中位数之后的所有元素：```
sumRight - median * countRight
```8. 将两个成本加在一起。 

这给出了该窗口所需的最小交换量。 
9. 返回所有窗口中的最小成本。 

### 为什么它有效

 变换后的数组将问题从将数字排列到连续槽中转换为标准中值距离最小化问题。 中位数使绝对偏差之和最小化，从而保证了相邻交换的数量最少。 前缀和允许有效计算每个窗口的偏差和。 

## Python 解决方案```python
from typing import List

class Solution:
    def minMoves(self, nums: List[int], k: int) -> int:
        positions = []

        for index, value in enumerate(nums):
            if value == 1:
                positions.append(index)

        adjusted = [positions[i] - i for i in range(len(positions))]

        prefix = [0]

        for value in adjusted:
            prefix.append(prefix[-1] + value)

        answer = float("inf")

        for left in range(len(adjusted) - k + 1):
            right = left + k - 1
            mid = left + k // 2

            median = adjusted[mid]

            left_cost = (
                median * (mid - left)
                - (prefix[mid] - prefix[left])
            )

            right_cost = (
                (prefix[right + 1] - prefix[mid + 1])
                - median * (right - mid)
            )

            answer = min(answer, left_cost + right_cost)

        return answer
```实现首先收集包含以下内容的所有索引`1`。 由于零仅充当零之间的空白，因此我们永远不需要再次直接处理它们。 

接下来，使用以下方法构造转换后的数组：```python
positions[i] - i
```这一调整考虑了目标排列是连续的这一事实。 

前缀求和数组可以实现恒定时间范围求和查询。 这很重要，因为我们在滑动窗口上重复计算总和。 

对于每个尺寸的窗户`k`，算法选择中值变换位置。 使用前缀和分别计算左侧和右侧移动成本。 

最后，返回所有窗口的最小总成本。 

## 解决方案```go
func minMoves(nums []int, k int) int {
	positions := []int{}

	for i, value := range nums {
		if value == 1 {
			positions = append(positions, i)
		}
	}

	adjusted := make([]int, len(positions))

	for i := range positions {
		adjusted[i] = positions[i] - i
	}

	prefix := make([]int64, len(adjusted)+1)

	for i, value := range adjusted {
		prefix[i+1] = prefix[i] + int64(value)
	}

	const INF int64 = 1 << 60
	answer := INF

	for left := 0; left+k-1 < len(adjusted); left++ {
		right := left + k - 1
		mid := left + k/2

		median := int64(adjusted[mid])

		leftCost := median*int64(mid-left) -
			(prefix[mid] - prefix[left])

		rightCost := (prefix[right+1] - prefix[mid+1]) -
			median*int64(right-mid)

		total := leftCost + rightCost

		if total < answer {
			answer = total
		}
	}

	return int(answer)
}
```Go 实现遵循与 Python 版本相同的算法结构。 

一个重要的区别是使用`int64`用于前缀总和和成本计算。 尽管指数符合`int`，累积移动成本可能变得足够大，以至于使用`int64`更安全。 

全程使用切片进行动态存储，逻辑直接反映数学公式。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`k = 1`。 In this situation, any single`1`已经满足连续的要求了。 有缺陷的实现可能仍会尝试不必要的计算或中值计算。 此实现可以自然地处理它，因为每个窗口只包含一个元素，从而产生零的移动成本。 

另一个重要的情况是当这些已经连续时。 例如：```
[1,1,1,0,0]
```和`k = 3`。 

变换后的位置在所选窗口内变得相同，因此绝对偏差和为零。 该算法正确返回零交换。 

第三个棘手的情况涉及由大间隙分隔的非常稀疏的情况：```
[1,0,0,0,0,1]
```简单的实现可能会错误地计算直接移动距离，而不考虑重叠移动或连续放置结构。 调整位置变换通过将问题转换为纯中值最小化问题来避免这种错误。 

的偶数和奇数`k`也可能导致微妙的错误。 对于奇数`k`，中位数是唯一的。 对于甚至`k`，任一中间元素都可以最小化距离。 该实现始终使用：```
mid = left + k // 2
```这对于两种情况都能正确产生最佳结果。 

最后，接近约束极限的大量输入需要仔细的复杂性管理。 二次算法会超时。 使用前缀和可确保在恒定时间内计算每个窗口成本，从而使整个解决方案能够在线性时间内高效运行。
