 **难度：** 🟡 中等
 **主题：** 数组、链表、分而治之、设计、模拟、双向链表

 ## 解决方案

 ## 问题理解

 该问题要求我们设计一个特殊的队列，称为“最近使用的队列”，缩写为MRUQueue。 最初，队列包含来自的整数`1`到`n`按递增顺序。 

关键操作是`fetch(k)`， 在哪里`k`是 1 索引的。 这个操作做了两件事：

 1. 它找到`kth`当前队列中的元素。 
2. 它从当前位置删除该元素并将其附加到队列末尾。 

然后该方法返回该移动元素的值。 

例如，如果队列是：```
[1, 2, 3, 4, 5]
```我们称之为：```
fetch(2)
```那么第二个元素是`2`。 我们将其删除并将其移动到最后：```
[1, 3, 4, 5, 2]
```并返回`2`。 

限制相对较小：

 -`n <= 2000`- 至多`2000`获取操作

 这些限制意味着即使`O(n)`每个操作的解决方案在实践中是可以接受的，因为总工作仍然是可管理的。 然而，后续明确要求比每次获取的线性时间更有效的东西，所以我们应该探索更好的设计。 

有几个重要的边缘情况需要考虑：

 - 获取最后一个元素，因为将其移动到末尾没有任何改变。 
- 重复获取相同的位置，因为队列顺序不断变化。 
- 排队人数非常少，例如`n = 1`，其中每次获取都必须简单地返回单个元素。 
- 正确处理 1 索引位置，因为基于数组的实现自然使用 0 索引。 

在 1 索引的获取位置和 0 索引的数组索引之间转换时，简单的实现很容易引入差一错误。 

## 方法

 ### 蛮力方法

 最简单的实现是直接使用动态数组或列表来模拟队列。 

对于每个`fetch(k)`操作：

 1. 访问索引处的元素`k - 1`。 
2. 将其从阵列中删除。 
3. 将其附加到末尾。 
4. 返回值。 

这是有效的，因为数组保留了确切的队列顺序，因此每个操作都直接反映问题定义。 

但是，从数组中间删除一个元素需要将所有后面的元素向左移动一位。 在最坏的情况下，这会花费`O(n)`每次获取操作的时间。 

虽然在有限的限制下这个通过了，但它并不能满足后续的挑战。 

### 最佳方法

 关键的观察结果是，昂贵的部件在移除后会反复移动元件。 

我们可以通过使用平方根分解（也称为块分解）来改进这一点。 

这个想法是将队列分成几个更小的块。 我们没有将所有元素存储在一个大列表中，而是将它们分成大小大致相等的块。 

例如：```
[1,2,3] [4,5,6] [7,8]
```现在，当我们需要`kth`元素：

 1. 我们定位哪个块包含该位置。 
2. 从该块中删除元素。 
3. 仅在块之间移动，而不是在整个阵列上移动。 
4. 将获取的值附加到最后一个块。 

由于每个块都很小，因此操作比扫描或移动整个队列要快得多。 

这将每次获取的摊销复杂性降低到大约`O(sqrt(n))`。

 ## 算法演练

 ### 最优平方根分解算法

 1. 初始化时，将数字除以`1`通过`n`分成大约大小的块`sqrt(n)`。 

例如，如果`n = 8`，我们可以创建：```
[1,2,3]
[4,5,6]
[7,8]
```使用块可以使每个内部操作保持较小的规模。 
2. 什么时候`fetch(k)`被调用，将位置转换为块坐标。 

我们反复减去块大小，直到找到包含`kth`元素。 
3. 从块中删除目标元素。 

由于每个块都很小，因此从中间移除的成本很低。 
4. 重新平衡区块。 

删除一个元素后，后面的块可能需要调整，以便逻辑队列顺序保持正确。 

我们通过重复从下一个块中取出第一个元素并将其附加到当前块来实现这一点。 
5. 将获取的值附加到最终块。 

这模拟将最近使用的元素移动到队列末尾。 
6. 返回获取的值。 

### 为什么它有效

 该算法保持了一个不变量，即按顺序连接所有块始终会产生准确的队列状态。 

当从块中删除元素时，从后续块中移动第一个元素可以保留元素的整体顺序。 将获取的元素附加到最终块与所需的 MRU 行为完全匹配。 

因为每个块的大小大约为`sqrt(n)`，各个块内的操作仍然高效。 

## Python 解决方案```python
from math import sqrt
from collections import deque
from typing import List

class MRUQueue:

    def __init__(self, n: int):
        self.block_size = int(sqrt(n)) + 1
        self.blocks = []

        current_block = []

        for value in range(1, n + 1):
            current_block.append(value)

            if len(current_block) == self.block_size:
                self.blocks.append(deque(current_block))
                current_block = []

        if current_block:
            self.blocks.append(deque(current_block))

    def fetch(self, k: int) -> int:
        k -= 1

        block_index = 0

        while k >= len(self.blocks[block_index]):
            k -= len(self.blocks[block_index])
            block_index += 1

        value = self.blocks[block_index][k]
        del self.blocks[block_index][k]

        for i in range(block_index, len(self.blocks) - 1):
            shifted = self.blocks[i + 1].popleft()
            self.blocks[i].append(shifted)

        self.blocks[-1].append(value)

        return value
```该实现首先使用以下值的平方根计算适当的块大小：`n`。 这平衡了块的数量和每个块的大小。 

构造函数增量地构建队列并将元素存储在双端队列中。 每个双端队列代表一个块。 

里面`fetch`，我们首先将 1 索引位置转换为 0 索引位置。 然后，我们通过减去块大小直到目标位置适合块来确定哪个块包含所请求的元素。 

找到正确的块后，我们删除目标元素。 由于块大小很小，因此该操作是高效的。 

接下来，我们重新平衡结构。 每个块从下一个块中提取第一个元素以保持正确的整体顺序。 

最后，我们将获取的值附加到最终块并返回它。 

## 解决方案```go
package main

import "math"

type MRUQueue struct {
	blocks [][]int
	size   int
}

func Constructor(n int) MRUQueue {
	blockSize := int(math.Sqrt(float64(n))) + 1

	blocks := [][]int{}
	current := []int{}

	for value := 1; value <= n; value++ {
		current = append(current, value)

		if len(current) == blockSize {
			blocks = append(blocks, current)
			current = []int{}
		}
	}

	if len(current) > 0 {
		blocks = append(blocks, current)
	}

	return MRUQueue{
		blocks: blocks,
		size:   blockSize,
	}
}

func (this *MRUQueue) Fetch(k int) int {
	k--

	blockIndex := 0

	for k >= len(this.blocks[blockIndex]) {
		k -= len(this.blocks[blockIndex])
		blockIndex++
	}

	value := this.blocks[blockIndex][k]

	this.blocks[blockIndex] = append(
		this.blocks[blockIndex][:k],
		this.blocks[blockIndex][k+1:]...,
	)

	for i := blockIndex; i < len(this.blocks)-1; i++ {
		shifted := this.blocks[i+1][0]

		this.blocks[i] = append(this.blocks[i], shifted)

		this.blocks[i+1] = this.blocks[i+1][1:]
	}

	this.blocks[len(this.blocks)-1] =
		append(this.blocks[len(this.blocks)-1], value)

	return value
}
```Go 版本遵循与 Python 实现相同的总体策略。 主要区别在于 Go 切片需要使用切片串联手动删除元素。 

与Python不同`deque`，Go没有提供内置的双端队列，因此我们使用切片来模拟块行为。 

整数溢出不是问题，因为所有值都保持在非常小的范围内。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | 每次获取 O(sqrt(n)) | 每个操作最多涉及一个区块加上区块再平衡 |
 | 空间| O(n) | 所有队列元素仅存储一次 |

 队列大约分为`sqrt(n)`块，每个块大致包含`sqrt(n)`元素。 

找到正确的块最多需要遍历`sqrt(n)`块。 从块中删除最多花费`O(sqrt(n))`，并且重新平衡最多也影响`sqrt(n)`块。 

因此，每个获取操作的运行时间大约为`O(sqrt(n))`时间。

 ## 边缘情况

 ### 获取最后一个元素

 当`k`等于当前队列长度，则所选元素已位于队列末尾。 有缺陷的实现可能会在删除和重新插入期间意外地重复元素或损坏顺序。 

此实现安全地删除元素并将其附加回最终块，产生相同的逻辑队列状态。 

### 队列大小为一

 仅包含一个元素的队列是一种特殊情况，因为每个获取操作都必须返回相同的值并保持队列不变。 

该实现自然地处理了这一问题，因为单个块包含一个元素，删除后追加会恢复原始状态。 

### 重复重新排序

 连续的获取操作会不断改变队列顺序。 幼稚的实现可能会使用有关原始指数的过时假设来错误地计算位置。 

该解决方案始终根据当前块结构计算位置，确保任意重新排序后的正确性。
