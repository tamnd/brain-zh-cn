[LeetCode 问题 1775](https://leetcode.com/problems/equal-sum-arrays-with-minimum-number-of-operations/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、贪心、计数

 ## 解决方案

 ## 问题理解

 该问题给了我们两个整数数组，`nums1`和`nums2`，其中每个元素都位于`1`和`6`。 在一个操作中，我们可以从任一数组中选择任何元素并将其更改为以下任意值：`1`到`6`。 

我们的目标是使用尽可能少的操作数使两个数组的总和相等。 

重要的细节是我们可以修改两个数组中的值，并且每个操作都可以将数字完全替换为任何有效值。 这意味着根据我们是否想要增加或减少总和，元素可以做出不同的贡献。 

例如：

 - 改变`1`到`6`将总和增加`5`- 改变`6`到`1`将总和减少`5`- 改变`3`到`5`将总和增加`2`输出应该是使总和相等所需的最少运算次数。 如果不可能，我们就返回`-1`。 

限制条件很大：

 - 数组长度可以达到`10^5`- 值仅限于`1`通过`6`这些约束立即告诉我们，指数搜索或模拟所有可能的修改是不可能的。 我们需要一种接近线性时间的算法。 

一个重要的观察结果是，每个元素对减少总和之间的差异都有最大可能的贡献：

 - 如果我们需要增加一个总和，一个元素`x`最多可以贡献`6 - x`- 如果我们需要减少一个总和，一个元素`x`最多可以贡献`x - 1`一些边缘情况很重要：

 - 数组的长度可能非常不同
 - 一个数组可能已经与另一个数组具有相同的总和
 - 在数学上可能不可能使总和相等
 - 一侧可能需要许多小操作而不是一些大操作
 - 数组只能包含`1`或仅`6`s，限制可能的变化

 一个特别重要的不可能条件来自值限制。 由于每个数字必须保持在`1`和`6`，对可能的金额有硬性限制。 

对于长度的数组`n`:

 - 最小可能总和为`n`- 最大可能的总和是`6n`如果两个数组可达到的和的范围不重叠，则均衡是不可能的。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试对两个数组中的元素进行所有可能的修改，直到总和相等。 

对暴力的一种可能的解释是：

 1. 生成每一个可能的修改状态
 2. 计算总和
 3. 跟踪所需的最少操作

 这很快就变得不可行，因为每个元素都有 6 个可能的值。 如果数组包含`n`元素总数，搜索空间约为：```
6^n
```即使对于相对较小的阵列，这也是一个天文数字。 

另一种不太极端的蛮力想法将重复测试每一种可能的修改并贪婪地选择一个。 然而，如果没有结构化策略，这仍然会变得昂贵，因为每个操作可能需要重复扫描许多可能性。 

对于数组来说，蛮力方法太慢了`10^5`。 

### 最佳解决方案的关键见解

 关键的见解是我们不关心数组的确切最终值。 我们只关心尽快减少总和之间的差异。 

认为：```
sum(nums1) < sum(nums2)
```然后我们需要：

 - 增加元素`nums1`- 减少元素`nums2`对于每个元素，我们可以计算其对减少差异的最大可能贡献。 

示例：

 - 在较小和数组中：

 -`1`可以成为`6`， 贡献`5`-`2`可以成为`6`， 贡献`4`- 在较大总和数组中：

 -`6`可以成为`1`， 贡献`5`-`5`可以成为`1`， 贡献`4`一旦我们计算出所有可能的贡献，最优策略就变得显而易见：

 始终首先使用最大的可用贡献。 

这是一个经典的贪婪策略。 由于每个操作都有相同的成本，即一次操作，因此选择最大程度地减少差异的操作始终是最佳的。 

因为值仅介于`1`和`6`，贡献仅限于`1`通过`5`，这使得计数极其高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(6^n) | O(6^n) | O(6^n) | O(6^n) | 探索大量可能的状态 |
 | 最佳 | O(n) | O(1) | O(1) | 使用贡献计数进行贪婪选择 |

 ## 算法演练

 1. 计算两个数组的总和。 

让：```
sum1 = sum(nums1)
sum2 = sum(nums2)
```如果总和已经相等，则返回`0`。 
2. 确保一个数组始终代表较小的总和。 

如果`sum1 > sum2`，交换数组和总和。 

这一步之后：```
sum1 <= sum2
```现在我们只需要考虑增加`nums1`并减少`nums2`。 
3. 计算所需的差值。```
diff = sum2 - sum1
```这就是我们仍然需要消除的数量。 
4. 计算所有可能的贡献。 

对于每一个数字`nums1`，最大可能的增量为：```
6 - num
```对于每一个数字`nums2`，最大可能的减少量为：```
num - 1
```每一项贡献都告诉我们一次操作可以减少多少差异。 
5. 按大小计算贡献。 

由于贡献只能是`1`通过`5`，我们将计数存储在一个小数组中。 

例子：```
gain[5] = number of operations that can reduce diff by 5
gain[4] = number of operations that can reduce diff by 4
```6. 贪婪地首先使用最大的贡献。 

从贡献开始`5`下降到`1`。 

对于每个贡献值：

 - 根据需要使用尽可能多的操作
 - 减少`diff`- 增加操作次数

 我们总是优先考虑较大的贡献，因为每次操作的成本相同。 
7. 一旦差值变为零或负值，则停止。 

到那时，我们已经平衡了总和。 
8. 如果所有捐款都用完并且`diff > 0`， 返回`-1`。 

### 为什么它有效

 贪心策略是最优的，因为每个操作都有相同的成本，即一次操作。 因此，只要我们能够将剩余差异减少较大的量，这样做总是至少与使用较小的减少量一样好。 

如果最佳解决方案使用较小的贡献，而存在较大的未使用贡献，则我们可以用较大的贡献替换较小的贡献，并且无需额外操作即可实现相同或更好的减少。 因此，首先选择最大的可用贡献不会使解决方案变得更糟，这证明了贪心方法的正确性。 

## Python 解决方案```python
from typing import List

class Solution:
    def minOperations(self, nums1: List[int], nums2: List[int]) -> int:
        sum1 = sum(nums1)
        sum2 = sum(nums2)

        if sum1 == sum2:
            return 0

        # Ensure nums1 has the smaller sum
        if sum1 > sum2:
            nums1, nums2 = nums2, nums1
            sum1, sum2 = sum2, sum1

        diff = sum2 - sum1

        # gain[i] = how many operations can reduce diff by i
        gain = [0] * 6

        # Increasing nums1 elements
        for num in nums1:
            gain[6 - num] += 1

        # Decreasing nums2 elements
        for num in nums2:
            gain[num - 1] += 1

        operations = 0

        # Greedily use biggest gains first
        for value in range(5, 0, -1):
            while gain[value] > 0 and diff > 0:
                diff -= value
                gain[value] -= 1
                operations += 1

        return operations if diff <= 0 else -1
```该实现首先计算两个数组的总和。 如果总和已经相等，则立即得到答案`0`。 

接下来，代码确保`nums1`总和总是较小的。 这简化了其余的逻辑，因为我们只需要考虑增加`nums1`和递减的值`nums2`。 

变量`diff`存储总和之间的剩余差值。 

这`gain`数组是核心优化。 由于每次操作最多只能将差异缩小`5`，我们只需要索引为 6 个槽`0`到`5`。 

对于每一个值`nums1`，代码计算该值可以增加多少：```python
6 - num
```对于每一个值`nums2`，代码计算该值可以减少多少：```python
num - 1
```这些可能的减少计入`gain`。 

最终循环处理增益`5`下降到`1`。 这实现了总是首先使用最强大的操作的贪婪策略。 

立刻`diff <= 0`，可以使总和相等，因此算法返回所使用的操作数。 

## 解决方案```go
package main

func minOperations(nums1 []int, nums2 []int) int {
	sum1 := 0
	sum2 := 0

	for _, num := range nums1 {
		sum1 += num
	}

	for _, num := range nums2 {
		sum2 += num
	}

	if sum1 == sum2 {
		return 0
	}

	// Ensure nums1 has the smaller sum
	if sum1 > sum2 {
		nums1, nums2 = nums2, nums1
		sum1, sum2 = sum2, sum1
	}

	diff := sum2 - sum1

	// gain[i] = count of operations reducing diff by i
	gain := make([]int, 6)

	// Increase nums1
	for _, num := range nums1 {
		gain[6-num]++
	}

	// Decrease nums2
	for _, num := range nums2 {
		gain[num-1]++
	}

	operations := 0

	for value := 5; value >= 1; value-- {
		for gain[value] > 0 && diff > 0 {
			diff -= value
			gain[value]--
			operations++
		}
	}

	if diff > 0 {
		return -1
	}

	return operations
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 切片用于`gain`频率数组和范围循环简化了数组的迭代。 

Go 在这里不需要对整数溢出进行任何特殊处理，因为最大可能的和是：```go
6 * 10^5
```很容易适合 Go 的`int`类型。 

与 Python 不同，Go 没有内置求和函数，因此求和是通过循环手动计算的。

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个元素都会被处理固定次数 |
 | 空间| O(1) | O(1) | 增益数组的大小固定为 6 |

 该算法扫描两个数组一次以计算总和，并再次扫描一次以计算贡献频率。 贪婪循环仅迭代来自的增益值`5`下降到`1`，这是持续的工作。 

尽管操作总数在概念上可能很大，但每个可能的贡献都会通过频率计数处理一次，从而使运行时与总输入大小保持线性关系。 

额外的内存使用量是恒定的，因为`gain`无论输入大小如何，数组始终包含六个条目。

 ## 边缘情况

 当总和一开始就相等时，就会出现一个重要的边缘情况。 粗心的实现可能会继续不必要的处理，甚至产生错误的肯定答案。 实现立即处理这个问题：```
if sum1 == sum2:
    return 0
```另一个重要的边缘情况是不可能实现均衡。 当数组的总可实现范围不重叠时，就会发生这种情况。 例如：```
nums1 = [1,1,1,1,1,1,1]
nums2 = [6]
```即使在所有可能的变化之后，总和也永远不会变得相等。 该实现自然会检测到这一点，因为所有可能的增益都已用尽，而`diff`保持正值，导致函数返回`-1`。 

第三个关键边缘情况涉及输入尺寸非常大的极其不平衡的阵列。 由于约束允许数组最多`10^5`元素，任何二次解都会超时。 该实现通过使用固定大小的计数数组并仅处理每个元素恒定的次数来避免这种情况。 

当许多元件贡献零增益时，会出现另一种微妙的边缘情况。 例如：```
nums1 = [6,6,6]
nums2 = [1,1,1]
```如果我们试图增加`nums1`，它的元素已经相等`6`，所以他们没有做出任何贡献。 相似地，`1`s 不能进一步减小。 该实现正确地处理了这个问题，因为零增益操作在频率计数过程中自然被忽略。 

最后，重要的是算法始终首先处理较大的贡献。 如果过早使用较小的贡献，解决方案可能会使用不必要的操作。 下降的贪心循环保证总是找到最少的操作数。
