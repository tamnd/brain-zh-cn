[LeetCode 问题 1777](https://leetcode.com/problems/products-price-for-each-store/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 The problem provides a table named`Products`，其中每行代表特定商店中特定产品的价格。 每行包含三个值：

 -`product_id`, 识别产品
 -`store`，确定哪家商店销售该产品
 -`price`，代表该产品在该商店的价格

 的`(product_id, store)`pair 保证是唯一的，因为它是主键。 这意味着产品不能在同一商店出现多次。 

任务是将表从面向行的格式转换为面向列的格式。 而不是每行一行`(product, store)`对，我们希望每个产品一行，每个商店都有单独的列：

 -`store1`-`store2`-`store3`如果该商店中存在该产品，则每列应包含相应的价格。 如果该产品不在特定商店出售，则其价值应为`NULL`。 

这本质上是一个旋转问题。 我们根据商店名称将行转换为列。 

例如，如果输入包含：

 | 产品 ID | 商店 | 价格|
 | --- | --- | --- |
 | 0 | 商店1 | 95 | 95
 | 0 | 商店2 | 100 | 100
 | 0 | 商店3 | 105 | 105

 那么输出行变为：

 | 产品 ID | 商店1 | 商店2 | 商店3 |
 | --- | --- | --- | --- |
 | 0 | 95 | 95 100 | 100 105 | 105

 该问题保证商店仅来自固定集合：

 -`store1`-`store2`-`store3`这很重要，因为我们已经知道输出中必须出现的确切列。 

一个重要的边缘情况是当一个或多个商店中不存在某种产品时。 在这种情况下，输出必须包含`NULL`对于那些列。 另一个重要的细节是产品可能只出现在一个商店中，因此查询仍然必须生成完整的行，并正确表示缺失值。 

## 方法

 ### 蛮力方法

 暴力方法将针对每个产品多次手动查询表。 对于每一个不同的`product_id`，我们可以单独搜索价格`store1`,`store2`， 和`store3`。 

从概念上讲，这的工作原理如下：

 1. 获取所有不同的产品 ID。 
2. For each product:

 - 搜索 store = 的行`store1`- 搜索 store = 的行`store2`- 搜索 store = 的行`store3`3. 构造最后一行。 

这会产生正确的答案，因为每个产品-商店对都是独立检查的。 然而，它的效率很低，因为可能会针对每个产品重复扫描该表。 

### 最佳方法

 更好的解决方案使用带有条件逻辑的 SQL 聚合。 

关键的见解是每个产品应该恰好成为输出中的一行。 因此，我们可以通过以下方式对行进行分组`product_id`。 Then, for each store column, we selectively extract the corresponding price using conditional aggregation.

 我们使用这样的表达方式：```
MAX(CASE WHEN store = 'store1' THEN price END)
```这是有效的，因为：

 - 的`CASE`表达式仅返回与目标商店匹配的行的价格。 
- 所有其他行返回`NULL`。 
- 由于每个`(product_id, store)`对是唯一的，每组最多有一个非空值。 
-`MAX()`只是提取该值。 

这可以干净有效地将多行转换为单行。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n × s) | O(1) | O(1) | 重复扫描每个商店的数据|
 | 最佳 | O(n) | O(1) | O(1) | 使用分组和条件聚合 |

 这里，`n`是行数并且`s`是商店数量，固定为3。 

## 算法演练

 1. 首先使用以下命令对所有行进行分组`product_id`。 

分组可确保每个产品在最终结果中恰好生成一行。 同一产品的所有商店条目都收集在一起。 
2. 对于`store1`列，评估条件表达式。 

使用：```
CASE WHEN store = 'store1' THEN price END
```这将返回：

 - 该行所属的价格`store1`-`NULL`否则
 3. 应用聚合函数，例如`MAX()`。 

由于每个商店的每种产品最多有一行，因此最多有一个非空值。`MAX()`安全地提取该值。 
4. 重复相同的逻辑`store2`和`store3`。 

每个商店都有自己的条件聚合列。 
5. 返回分组结果。 

最终输出包含：

 - 每个产品一行
 - 每个商店一栏
 -`NULL`对于缺失的商店

 ### 为什么它有效

 正确性来自于唯一性`(product_id, store)`。 对于给定的产品和商店组合，最多有一个价格。 这`CASE`表达式隔离所需的存储值，聚合函数将其从组中提取。 因为分组是通过`product_id`，同一产品的所有商店价格都合并到一个输出行中。 

## Python 解决方案

 尽管这是一个数据库问题并且通常用 SQL 解决，但可以用 Python 演示等效的转换逻辑。```python
from collections import defaultdict
from typing import List, Dict, Optional

class Solution:
    def productsPrice(self, products: List[List]) -> List[Dict[str, Optional[int]]]:
        result = defaultdict(lambda: {
            "store1": None,
            "store2": None,
            "store3": None
        })

        for product_id, store, price in products:
            result[product_id][store] = price

        answer = []

        for product_id, stores in result.items():
            row = {
                "product_id": product_id,
                "store1": stores["store1"],
                "store2": stores["store2"],
                "store3": stores["store3"]
            }
            answer.append(row)

        return answer
```该实现使用一个字典作为键`product_id`。 每个产品都存储另一个字典，其中包含所有三个商店的价格。 

最初，每个存储值都设置为`None`。 处理行时，会更新相应的商店价格。 

最后，将结果转换为所需的输出格式，其中每个产品恰好只有一行，并且保留缺失的商店`None`。 

对于实际的LeetCode数据库提交，预期的SQL解决方案是：```python
SELECT
    product_id,
    MAX(CASE WHEN store = 'store1' THEN price END) AS store1,
    MAX(CASE WHEN store = 'store2' THEN price END) AS store2,
    MAX(CASE WHEN store = 'store3' THEN price END) AS store3
FROM Products
GROUP BY product_id;
```## 解决方案```go
package main

import "fmt"

type Product struct {
	ProductID int
	Store     string
	Price     int
}

type Result struct {
	ProductID int
	Store1    *int
	Store2    *int
	Store3    *int
}

func productsPrice(products []Product) []Result {
	resultMap := make(map[int]*Result)

	for _, product := range products {
		if _, exists := resultMap[product.ProductID]; !exists {
			resultMap[product.ProductID] = &Result{
				ProductID: product.ProductID,
			}
		}

		current := resultMap[product.ProductID]

		switch product.Store {
		case "store1":
			price := product.Price
			current.Store1 = &price
		case "store2":
			price := product.Price
			current.Store2 = &price
		case "store3":
			price := product.Price
			current.Store3 = &price
		}
	}

	answer := []Result{}

	for _, value := range resultMap {
		answer = append(answer, *value)
	}

	return answer
}

func main() {
	products := []Product{
		{0, "store1", 95},
		{0, "store2", 100},
		{0, "store3", 105},
		{1, "store1", 70},
		{1, "store3", 80},
	}

	result := productsPrice(products)

	fmt.Println(result)
}
```Go 实现使用商店价格指针，以便缺失值可以表示为`nil`，对应于SQL`NULL`。 

与 Python 字典不同，Go 需要显式的结构定义。 一个`map[int]*Result`用于对产品进行分组`ProductID`。 

整体逻辑与Python版本保持相同。 

对于实际的LeetCode数据库问题，SQL解决方案仍然是预期的答案。

 ## 边缘情况

 当一种产品仅存在于一家商店时，就会出现一种重要的边缘情况。 幼稚的实现可能会意外地完全忽略丢失的存储列。 正确的行为是包含所有存储列并使用`NULL`对于没有该产品的商店。 该实现通过将所有商店密钥设置为初始化每个产品来处理此问题`None`。 

另一个边缘情况是多种产品具有完全不同的商店可用性模式。 例如，一种产品可能只出现在`store1`而另一个只出现在`store3`。 分组逻辑确保每个产品都是独立处理的，因此产品之间的值不会泄漏。 

另一个边缘情况是空输入。 如果表不包含任何行，则结果也应该为空。 该实现自然会处理此问题，因为分组结构保持为空并且不会生成输出行。 

微妙的边缘情况涉及唯一性保证。 问题保证`(product_id, store)`是独一无二的。 如果没有这种保证，聚合函数如`MAX()`可能会无意中隐藏重复的行。 由于存在唯一性约束，条件聚合可以安全地为每个商店提取一个值。
