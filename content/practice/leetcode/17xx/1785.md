[LeetCode 问题 1785](https://leetcode.com/problems/minimum-elements-to-add-to-form-a-given-sum/)

 **难度：** 🟡 中等
 **主题：** 数组、贪心

 ## 解决方案

 ## 问题理解

 问题给了我们一个整数数组`nums`，最大允许绝对值`limit`，以及称为的目标总和`goal`。 

数组中的每个元素都已满足条件：```
abs(nums[i]) <= limit
```我们可以向数组添加新整数，但每个新添加的整数也必须满足相同的限制：```
abs(x) <= limit
```我们的任务是确定必须添加的最小元素数，以使数组的最终总和恰好等于`goal`。 

简单来说，我们首先计算数组的当前总和。 如果当前总和已经等于目标，则无需添加任何元素。 否则，当前总和与目标之间存在一些差异。 我们必须使用尽可能少的数字来弥补这一差异，同时确保每个添加的数字保持在范围内`[-limit, limit]`。 

约束条件很重要：

 -`nums.length`可以大到`10^5`-`limit`可以大到`10^6`-`goal`可以大到`10^9`在大小上

 这些限制立即告诉我们，我们需要一个非常有效的解决方案。 任何对总和的指数搜索或动态规划都会太慢。 我们需要接近线性时间的东西。 

有几个重要的边缘情况需要考虑：

 - 数组总和可能已经相等`goal`- 当前总和与目标之间的差异可能为负数
 - 差异可能很大，需要添加多个元素
 -`limit`可能很小，迫使我们使用很多元素
 - 在某些语言中，涉及的值可能超过 32 位整数范围，因此小心处理整数很重要

 该问题保证每个原始元素都已经满足极限限制，因此我们只需要担心选择有效的添加元素。 

## 方法

 ### 蛮力方法

 暴力方法会尝试不同的数字组合进行相加，直到数组达到目标总和。 

假设当前总和与目标之间的差是`diff`。 一种幼稚的策略会递归地尝试所有可能的值`-limit`到`limit`，探索每一个可能的加法序列，直到剩余的差值变为零。 

这种方法是正确的，因为它最终会探索相加数字的每个有效组合。 然而，这是完全不切实际的。 分支因子是巨大的，因为每个添加的元素可以取许多可能的值，并且深度也可以变大。 

即使基于可达总和的动态规划方法也是不可行的，因为目标范围可能达到数十亿。 

蛮力思想有助于揭示关键的观察结果：为了最大限度地减少添加元素的数量，每个添加的元素应尽可能为缩小剩余差异做出贡献。 

### 关键见解

 让：```
current_sum = sum(nums)
diff = abs(goal - current_sum)
```每个添加的数字最多可以贡献`limit`旨在减少这种差异，因为：```
abs(x) <= limit
```因此，最优策略始终是每次使用最大可能的贡献。 

如果我们仍然需要弥补剩余的差异`diff`，那么：

 - 最多一个元素可以覆盖`limit`- 最多可以覆盖两个元素`2 * limit`- 最多可覆盖三个元素`3 * limit`因此所需的最小元素数量很简单：```
ceil(diff / limit)
```这种贪婪推理是最优的，因为使用小于最大允许贡献的任何东西只能增加所需元素的数量。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 递归尝试所有可能的附加值 |
 | 最佳 | O(n) | O(1) | O(1) | 计算差异并使用贪心数学 |

 ## 算法演练

 1. 使用中的所有元素计算数组的当前总和`nums`。 

这告诉我们数组当前相对于目标的位置。 
2. 计算当前总和与`goal`。```
diff = abs(goal - current_sum)
```我们使用绝对值，因为无论我们是否需要增加或减少总和并不重要。 所需元件的数量仅取决于间隙的大小。 
3. 确定添加的一种元素可以贡献多少。 

由于每个相加的数字必须满足：```
abs(x) <= limit
```一个元素的最大贡献恰好是`limit`。 
4. 将剩余差值除以`limit`。```
diff / limit
```这告诉我们我们需要多少个最大的完整贡献。 
5. 将除法结果四舍五入。 

如果差值不能被整除`limit`，我们需要一个额外的元素来覆盖剩余的数量。 

数学上：```
answer = ceil(diff / limit)
```6. 返回结果。 

### 为什么它有效

 该算法之所以有效，是因为每个添加的元素对于它可以改变总和的程度都有一个硬性上限。 没有任何元素可以贡献超过`limit`朝向剩余的差值。 因此，最好的策略始终是使用最大允许量级的元素，直到间隙缩小。 

如果`k`使用元素时，可能的最大总调整为：```
k * limit
```所以我们需要最小的`k`这样：```
k * limit >= diff
```这正是：```
ceil(diff / limit)
```证明贪心公式是最优的。 

## Python 解决方案```python
from typing import List

class Solution:
    def minElements(self, nums: List[int], limit: int, goal: int) -> int:
        current_sum = sum(nums)

        difference = abs(goal - current_sum)

        return (difference + limit - 1) // limit
```该实现首先计算中所有元素的总和`nums`。 这给出了当前数组的总数。 

接下来，我们计算当前总和与期望目标之间的绝对差。 使用绝对值可以简化问题，因为我们只关心差距有多大，而不关心它是正还是负。 

最后，我们使用以下方法执行上限划分：```python
(difference + limit - 1) // limit
```这是用于计算的标准整数算术技巧：```python
ceil(difference / limit)
```不使用浮点运算。 

该算法仅使用几个变量，并通过数组执行一次传递来计算总和。 

## 解决方案```go
func minElements(nums []int, limit int, goal int) int {
	currentSum := 0

	for _, num := range nums {
		currentSum += num
	}

	difference := goal - currentSum
	if difference < 0 {
		difference = -difference
	}

	return (difference + limit - 1) / limit
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

Go 特定的一个重要细节是手动处理整数的绝对值：```go
if difference < 0 {
    difference = -difference
}
```Go 在标准库中没有提供内置的整数绝对值函数。 

另一个考虑因素是整数溢出。 在这个问题中，约束安全地符合 Go 的标准`int`在 LeetCode 环境中输入，因此不需要特殊处理。 

## 工作示例

 ### 示例 1```
Input: nums = [1, -1, 1], limit = 3, goal = -4
```首先计算当前总和：

 | 元素| 运行总和 |
 | --- | --- |
 | 1 | 1 |
 | -1 | 0 |
 | 1 | 1 |

 所以：```
current_sum = 1
```现在计算差异：```
difference = abs(-4 - 1)
           = abs(-5)
           = 5
```每个添加的元素最多可以贡献`3`。 

现在计算：```
ceil(5 / 3) = 2
```使用整数运算：```
(5 + 3 - 1) // 3
= 7 // 3
= 2
```回答：```
2
```一种有效的构造是添加`-3`和`-2`。 

### 示例 2```
Input: nums = [1, -10, 9, 1], limit = 100, goal = 0
```计算当前总和：

 | 元素| 运行总和 |
 | --- | --- |
 | 1 | 1 |
 | -10 | -9 |
 | 9 | 0 |
 | 1 | 1 |

 所以：```
current_sum = 1
```不同之处：```
difference = abs(0 - 1)
           = 1
```每个元素最多可以贡献`100`。 

所以：```
ceil(1 / 100) = 1
```回答：```
1
```我们可以简单地添加`-1`。

 ## 边缘情况

 当数组总和已经等于目标时，就会出现一种重要的边缘情况。 在这种情况下，差异为零，正确答案也为零。 有缺陷的实现可能会由于不正确的上限划分逻辑而意外返回 1。 此实现可以正确处理它，因为：```
(0 + limit - 1) // limit
```评估为零。 

当所需的调整为负时，会出现另一个重要的边缘情况。 例如，当前总和可能远大于目标。 由于我们使用：```
abs(goal - current_sum)
```该算法对称地处理正调整和负调整。 这可以防止与标志相关的错误。 

第三个重要的边缘情况涉及到不能被整除的差异`limit`。 假设剩余差值为`10`和`limit`是`3`。 最多可以贡献三个要素`9`，所以第四个元素是必要的。 上限除法公式正确地处理了这个问题：```
(10 + 3 - 1) // 3
= 12 // 3
= 4
```如果没有上限除法，使用普通整数除法的实现将错误地返回`3`。 

最后的边缘情况涉及接近问题极限的非常大的值。 差异可能会变得非常大，尤其是当`goal`就在附近`10^9`。 由于该算法仅执行简单的算术并且不分配与目标大小成比例的内存，因此即使在最大约束下它仍然高效且安全。
