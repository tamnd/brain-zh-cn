[LeetCode 第 1718 题](https://leetcode.com/problems/construct-the-lexicographyally-largest-valid-sequence/)

 **难度：** 🟡 中等
 **主题：** 数组、回溯

 ## 解决方案

 ## 问题理解

 该问题要求我们使用以下数字构造一个特殊的整数序列`1`到`n`。 

结果序列的长度`2 * n - 1`因为：

 - 号码`1`恰好出现一次。 
- 每个数字来自`2`到`n`正好出现两次。 

这意味着元素总数为：

 -`1`出现为`1`-`2 * (n - 1)`数字的出现次数`2`通过`n`所以总长度变为：$$1 + 2(n - 1) = 2n - 1$$关键的限制是距离。 对于每个数字`i >= 2`，如果它的两次出现位于索引处`a`和`b`， 然后：$$|b - a| = i$$例如，如果我们将数字`4`在索引处`2`，然后是第二个`4`必须出现在索引处`6`。 

该问题还要求字典顺序上最大的有效序列。 字典顺序从左到右比较序列。 在第一个不同的位置，具有较大值的序列被认为较大。 

这个要求极其重要，因为可能存在许多有效的序列。 我们必须尽早专门构建一个放置更大数字的模型。 

限制相对较小：

 -`1 <= n <= 20`虽然`n`很小，可能的排列数量增长得非常快。 简单的暴力排列搜索仍然是不可行的。 这强烈表明我们需要一个仔细修剪的回溯解决方案。 

有几个重要的边缘情况需要记住：

 -`n = 1`是最小的输入。 答案很简单`[1]`。 
- 大量数字更难放置，因为它们需要很大的间隙。 
- 一旦职位变得分散，一些剩余的数字可能不再适合。 
- 仅贪婪放置是不够的，因为早期选择可能会阻止所有未来的有效完成。 
- 该问题保证至少有一个有效的解决方案始终存在。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试生成每个可能的长度序列`2n - 1`使用每个数字所需的计数，然后验证距离约束是否成立。 

该过程如下所示：

 1. 生成多重集的所有排列：

 - 一个`1`- 每个号码的两份副本`2`到`n`2. 对于每个排列：

 - 检查每个重复的数字是否准确出现`i`指数分开。 
3. 跟踪字典顺序最大的有效序列。 

这种方法是正确的，因为它检查了每种可能的候选排列。 最终它会找到最佳答案。 

然而，搜索空间是巨大的。 即使对于中等`n`，排列的数量变得非常大。 由于序列长度可以达到`39`，穷举排列生成是完全不切实际的。 

### 最优方法，贪婪排序回溯

 关键的见解是我们不需要生成所有排列。 

相反，我们可以增量构建序列，同时立即强制执行距离约束。 

每一步：

 - 找到第一个空位置。 
- 尝试将数字从最大到最小排列。 
- 对于大于的数字`1`，同时放置两个事件。 
- 如果以后无法放置，则原路返回。 

首先尝试更大的数字至关重要。 由于字典顺序优先考虑较早的位置，因此将较大的值放在较早的位置可以保证我们发现的第一个完整的有效解决方案已经是按字典顺序最大的解决方案。 

这极大地减少了搜索空间，因为：

 - 无效状态立即被放弃。 
- 施工期间执行距离规则。 
- 贪心降序避免探索许多较小的词典编目候选者。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O((2n)!) | O((2n)!) | O((2n)!) | O((2n)!) | 生成并验证所有排列 |
 | 最佳 | 大约 O(2^n) | O(n) | 强剪枝和贪婪排序的回溯 |

 回溯的确切复杂性很难精确表达，因为修剪在实践中消除了大多数分支。 

## 算法演练

 ### 第 1 步：初始化序列

 创建一个名为的数组`sequence`长度`2 * n - 1`，最初充满`0`。 

值为`0`表示该位置仍为空。 

还创建一个`used`数组来跟踪数字是否已经完全放置。 

### 步骤 2：定义递归回溯函数

 递归函数尝试从左到右填充序列。 

该函数接收当前正在处理的索引。 

### 第 3 步：跳过已填补的职位

 有时，先前的位置会同时填补多个位置。 

如果当前索引已被占用，则递归移动到下一个索引。 

### 步骤 4：检测完成情况

 如果索引达到序列长度，则每个位置都已成功填充。 

返回`True`来表示成功。 

### 步骤 5：尝试从最大到最小的数字

 迭代自`n`下降到`1`。 

这种排序至关重要，因为我们想要字典顺序最大的序列。 

首先尝试更大的数字可确保较早的位置包含最大可能的值。 

### 第 6 步：跳过已使用的号码

 如果已经放置了号码：

 - 跳过它。 
- 继续下一个候选人。 

### 步骤 7：单独处理数字 1

 数量`1`仅出现一次。 

如果当前位置为空：

 - 地点`1`- 将其标记为已使用
 - 递归到下一个位置

 如果递归成功则返回`True`。 

否则：

 - 撤消放置
 - 继续搜索

 ### 步骤 8：处理大于 1 的数字

 对于任何数字`num > 1`，我们必须准确地放置两个副本`num`指数分开。 

如果我们将第一个副本放在索引处`i`，第二个副本必须位于：$$i + num$$放置之前，请验证：

 -`i + num`在数组边界内
 - 两个位置都是空的

 如果有效：

 - 将号码放在两个位置
 - 将其标记为已使用
 - 递归

 如果递归失败：

 - 删除两个展示位置
 - 再次标记未使用的号码

 ### 步骤 9：必要时回溯

 如果当前位置没有号码可以成功放置：

 - 返回`False`这向呼叫者发出信号，撤消之前的决定并尝试另一种安排。 

### 为什么它有效

 该算法始终维护有效的部分序列。 每个放置都会立即满足距离要求，因此不允许继续进行无效的配置。 

由于数字是按降序排列的，因此搜索会先探索字典顺序较大的前缀，然后再探索较小的前缀。 因此，找到的第一个完整的有效序列保证是字典顺序上最大的有效序列。 

回溯保证了完整性，因为除非被已经违反的约束修剪，否则最终会探索每个有效的安排。 

## Python 解决方案```python
from typing import List

class Solution:
    def constructDistancedSequence(self, n: int) -> List[int]:
        length = 2 * n - 1
        sequence = [0] * length
        used = [False] * (n + 1)

        def backtrack(index: int) -> bool:
            if index == length:
                return True

            if sequence[index] != 0:
                return backtrack(index + 1)

            for num in range(n, 0, -1):
                if used[num]:
                    continue

                if num == 1:
                    sequence[index] = 1
                    used[1] = True

                    if backtrack(index + 1):
                        return True

                    sequence[index] = 0
                    used[1] = False
                else:
                    second_index = index + num

                    if (
                        second_index < length
                        and sequence[index] == 0
                        and sequence[second_index] == 0
                    ):
                        sequence[index] = num
                        sequence[second_index] = num
                        used[num] = True

                        if backtrack(index + 1):
                            return True

                        sequence[index] = 0
                        sequence[second_index] = 0
                        used[num] = False

            return False

        backtrack(0)
        return sequence
```实现首先创建目标序列数组和`used`大批。 该序列用零初始化以指示空位置。 

递归`backtrack`函数尝试从左到右填充序列。 如果某个位置已被占用，则递归会跳过该位置，因为先前的放置已经处理了该位置。 

该算法始终按降序尝试数字。 这是保证词典编纂最大化的核心机制。 

对于大于的数字`1`，该实现使用以下方法计算所需的第二个索引`index + num`。 在放置之前，两个位置都必须有效且为空。 

如果递归探索失败，算法将删除放置并恢复之前的状态。 这个撤销操作就是回溯的本质。 

最终，返回第一个完整的有效序列。 

## 解决方案```go
func constructDistancedSequence(n int) []int {
	length := 2*n - 1
	sequence := make([]int, length)
	used := make([]bool, n+1)

	var backtrack func(int) bool

	backtrack = func(index int) bool {
		if index == length {
			return true
		}

		if sequence[index] != 0 {
			return backtrack(index + 1)
		}

		for num := n; num >= 1; num-- {
			if used[num] {
				continue
			}

			if num == 1 {
				sequence[index] = 1
				used[1] = true

				if backtrack(index + 1) {
					return true
				}

				sequence[index] = 0
				used[1] = false
			} else {
				secondIndex := index + num

				if secondIndex < length &&
					sequence[index] == 0 &&
					sequence[secondIndex] == 0 {

					sequence[index] = num
					sequence[secondIndex] = num
					used[num] = true

					if backtrack(index + 1) {
						return true
					}

					sequence[index] = 0
					sequence[secondIndex] = 0
					used[num] = false
				}
			}
		}

		return false
	}

	backtrack(0)
	return sequence
}
```Go 的实现与 Python 解决方案非常相似。 使用切片而不是动态 Python 列表。 

递归函数被声明为闭包，因此它可以访问`sequence`,`used`， 和`length`不需要额外的参数。 

Go 在这里不需要对整数溢出进行特殊处理，因为在问题约束下所有值仍然非常小。 

与 Python 不同，Go 没有隐式布尔真值，因此所有条件都是显式编写的。

def is_valid(sequence, n):
    positions = {}

    for i, value in enumerate(sequence):
        positions.setdefault(value, []).append(i)

    if positions[1] and len(positions[1]) != 1:
        return False

    for num in range(2, n + 1):
        if len(positions.get(num, [])) != 2:
            return False

        a, b = positions[num]

        if abs(b - a) != num:
            return False

    return True

 ## 边缘情况

 ### 边缘情况 1，`n = 1`这是可能的最小输入。 序列长度变为`1`，并且只有数字`1`必须放置。 

有缺陷的实现可能会错误地假设每个数字出现两次或尝试为第二次出现`1`。 

该实现通过处理来正确处理这个问题`1`作为特殊情况，仅放置一次。 

### 边缘情况 2，数组末尾附近有大量数字

 假设我们尝试在序列的右侧附近放置一个大数字。 

例如，如果`n = 5`我们试图放置`5`在索引处`6`，第二次出现需要在索引处`11`，它位于数组之外。 

如果不仔细检查边界，这将导致索引错误。 

该实现通过验证来防止这种情况：```
second_index < length
```安置前。 

### 边缘情况 3，零散的空槽

 当序列填满时，空位置可能会变得分散，从而阻止剩余数字的拟合。 

例如，可能存在孤立的空单元格，其中大量单元格无法满足其距离要求。 

在这种情况下，没有回溯的贪婪算法将永久失败。 

该实现通过撤销无效的放置并通过递归探索替代安排来解决这个问题。 

### 边缘情况 4，字典顺序

 通常存在多个有效序列。 

例如，当`n = 3`:```
[2,3,2,1,3]
```是有效的，但是：```
[3,1,2,3,2]
```按字典顺序更大。 

如果按升序尝试数字，算法可能会首先返回较小的有效序列。 

该实现通过始终尝试来自的数字来保证正确的答案`n`下降到`1`。
