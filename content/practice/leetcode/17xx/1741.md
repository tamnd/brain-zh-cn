[LeetCode 问题 1741](https://leetcode.com/problems/find-total-time-spent-by-each-employee/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题要求我们根据进出时间表计算每个员工每天在办公室花费的总时间。 中的每一行`Employees`表代表员工在办公室的单个时间段，其中各列为`emp_id`,`event_day`,`in_time`， 和`out_time`。 这`in_time`和`out_time`只需几分钟，并且`in_time < out_time`是有保证的。 同一名员工可以在同一天有多个条目，这意味着我们需要将他们当天的所有时间间隔相加。 

预期输出是一个包含三列的表：`day`,`emp_id`， 和`total_time`， 在哪里`total_time`是所有的总和`out_time - in_time`该员工当天的间隔时间。 行的顺序并不重要。 

重要的观察和限制是：

 1. 每个参赛作品保证有`in_time < out_time`。 
2.同一员工同一天的条目不重叠。 
3. 主键确保唯一性`(emp_id, event_day, in_time)`。 
4. 我们可以安全地对区间求和，而不必担心重叠。 

可能会导致幼稚实施失败的边缘情况包括员工在同一天有多个条目、只有一个条目的日子或仅在一天出现的员工。 空表应该返回空结果。 

## 方法

 一种蛮力方法是迭代每个员工的所有条目，并将它们分组`emp_id`和`event_day`，然后手动对间隔求和。 虽然这可以正常工作，但在 SQL 中，使用聚合函数而不是嵌套循环可以更有效地完成此操作。 

最佳解决方案的关键观察是 SQL 支持`GROUP BY`和直接算术运算。 通过对条目进行分组`emp_id`和`event_day`，我们可以使用以下方法计算每个员工每天的总时间`SUM(out_time - in_time)`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 手动迭代每个员工日，汇总时间 |
 | 最佳 | O(n) | O(n) | 使用 SQL 聚合`GROUP BY`和`SUM`|

 ## 算法演练

 1. 选择相关列`event_day`和`emp_id`分组依据。 
2. 对于每组，计算使用所花费的总时间`SUM(out_time - in_time)`。 这每天会自动处理多个条目。 
3. 将总和别名为`total_time`以匹配预期的输出列。 
4. 返回结果。 除非指定，否则 SQL 不需要显式排序，因此排序可以是任意的。 

**为什么有效**：分组依据`emp_id`和`event_day`确保同一员工在同一天的所有间隔都汇总在一起。 总结差异`out_time - in_time`由于时间间隔不重叠，因此可以正确计算每天在办公室花费的总分钟数。 

## Python 解决方案```python
import sqlite3
from typing import List, Tuple

def total_time_per_employee(conn: sqlite3.Connection) -> List[Tuple[str, int, int]]:
    """
    Calculates total time spent by each employee per day.

    Args:
    conn (sqlite3.Connection): Connection to the SQLite database containing Employees table.

    Returns:
    List[Tuple[str, int, int]]: List of tuples (day, emp_id, total_time)
    """
    query = """
    SELECT event_day AS day, emp_id, SUM(out_time - in_time) AS total_time
    FROM Employees
    GROUP BY event_day, emp_id
    """
    cursor = conn.cursor()
    cursor.execute(query)
    result = cursor.fetchall()
    return result
```在此 Python 实现中，我们使用标准 SQLite 连接。 我们执行一个 SQL 查询，将条目分组为`event_day`和`emp_id`，计算总和`out_time - in_time`对于每个组。 结果作为元组列表返回。 

## 解决方案```go
package main

import (
    "database/sql"
    _ "github.com/mattn/go-sqlite3"
    "log"
)

type EmployeeTime struct {
    Day       string
    EmpID     int
    TotalTime int
}

func TotalTimePerEmployee(db *sql.DB) ([]EmployeeTime, error) {
    query := `
    SELECT event_day AS day, emp_id, SUM(out_time - in_time) AS total_time
    FROM Employees
    GROUP BY event_day, emp_id
    `
    rows, err := db.Query(query)
    if err != nil {
        return nil, err
    }
    defer rows.Close()

    var results []EmployeeTime
    for rows.Next() {
        var et EmployeeTime
        if err := rows.Scan(&et.Day, &et.EmpID, &et.TotalTime); err != nil {
            return nil, err
        }
        results = append(results, et)
    }
    return results, nil
}
```在 Go 中，我们执行相同的 SQL 查询，将结果扫描到结构中，并将它们附加到切片中。 注意处理数据库查询和行扫描中的潜在错误。

| 1      | 2020-11-28 | 55      | 200      |

+--------+------------+---------+----------+
```分组后按`event_day`和`emp_id`：

 | 日 | 员工 ID | 间隔|
 | --- | --- | --- |
 | 2020-11-28 | 1 | (32-4), (200-55) |
 | 2020-12-03 | 1 | (42-1) |
 | 2020-11-28 | 2 | (33-3) |
 | 2020-12-09 | 2 | (74-47) |

 对间隔求和：

 | 日 | 员工 ID | 总时间 |
 | --- | --- | --- |
 | 2020-11-28 | 1 | 28 + 145 = 173 |
 | 2020-12-03 | 1 | 41 | 41

 | 2020-12-09 | 2 | 27 | 27

 ## 边缘情况

 一种极端情况是一名员工当天只有一个条目。 该实现可以正确处理这个问题，因为对单个间隔求和仍然会产生正确的总数。 

另一个边缘情况是员工在同一天有多个不重叠的条目。 由于该问题保证不重叠，因此将所有`out_time - in_time`间隔产生精确的总数，无需任何额外的逻辑。 

最后，一个空的`Employees`表应返回空结果。 SQL 聚合自然地处理这个问题，如下所示`GROUP BY`在空表上不会产生任何行。 这可以避免运行时错误或空处理问题。
