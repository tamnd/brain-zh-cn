[LeetCode 第 1705 题](https://leetcode.com/problems/maximum-number-of-eaten-apples/)

 **难度：** 🟡 中等
 **主题：** 数组、贪婪、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 该问题描述了一系列苹果树种植苹果的场景`n`连续几天。 每天，这棵树会结出一定数量的苹果，由下式给出：`apples[i]`，这些苹果的寿命有限，由下式给出`days[i]`。 当天生长的苹果`i`之后会腐烂`days[i]`天，这意味着它在这一天变得不可食用`i + days[i]`。 有些日子可能有零个苹果，代表为`apples[i] = 0`和`days[i] = 0`。 您**每天最多可以吃一个苹果**，但在结束后您可以继续吃苹果`n`- 天的生长期（如果有）保持未受破坏。 

输入是两个长度相等的数组`n`， 在哪里`1 <= n <= 20,000`苹果数量和保质期可达 20,000 个。 这告诉我们，迭代苹果和天数的每种可能组合的蛮力方法可能会太慢。 

预期输出是一个整数，表示在这些限制下您可以吃的最大苹果数量。 需要考虑的边缘情况包括苹果不生长的日子、所有苹果在食用前就腐烂的日子以及同时存在多批不同保质期的苹果的日子。 该问题保证了`days[i] = 0`仅发生在`apples[i] = 0`，所以我们不需要处理不一致的输入。 

## 方法

 蛮力方法需要日复一日地迭代并检查迄今为止种植的所有苹果，以找到未腐烂的苹果来吃。 每天，你都会扫描到目前为止收集到的苹果清单，去掉腐烂的苹果，然后选择一个吃。 这种方法是正确的，因为它准确地模拟了进食过程。 然而，对于大输入来说它太慢了，因为每天你可能会检查`O(n)`苹果，总体复杂度为`O(n^2)`。 

最佳方法的关键观察是，您**总是想吃最快腐烂的苹果**，以最大化吃掉的总数。 这是一个经典的贪婪策略。 通过维护以每个苹果批次的到期日为键的 **最小堆**（优先级队列），您可以有效地跟踪必须首先消耗的批次。 每天，您移除过期的苹果，添加新的苹果，然后从最早过期的批次中食用。 这降低了复杂性`O(n^2)`到`O(n log n)`因为堆操作需要对数时间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 每天检查所有未腐烂的苹果 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 使用最小堆总是吃腐烂最快的苹果 |

 ## 算法演练

 1. 初始化一个最小堆来存储元组`(expiration_day, apple_count)`。 
2. 初始化计数器`total_eaten`至 0。 
3. 迭代每一天`i`从 0 到`n-1`。 
4. 从堆中删除到期日小于或等于当天的所有苹果批次，因为它们已经腐烂。 
5.如果`apples[i] > 0`， 推`(i + days[i], apples[i])`到堆上来代表新苹果及其到期日。 
6. 如果清理后堆不为空，则弹出过期日期最早的批次并从中吃掉一个苹果。 如果这批苹果还有剩余，就少推一个苹果。 
7. 增量`total_eaten`每次吃一个苹果。 
8. 继续迭代一天之后`n-1`如果堆不为空，则模拟消耗剩余的苹果，直到全部腐烂。 

**为什么有效：** 通过始终食用最早过期的苹果，可以确保不会不必要地浪费苹果。 这种贪婪策略保证了吃掉最大数量的苹果，因为延迟吃很快就会腐烂的苹果可能会阻止你吃那个苹果。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def eatenApples(self, apples: List[int], days: List[int]) -> int:
        min_heap = []
        total_eaten = 0
        n = len(apples)
        day = 0
        
        while day < n or min_heap:
            if day < n and apples[day] > 0:
                heapq.heappush(min_heap, (day + days[day], apples[day]))
            
            while min_heap and min_heap[0][0] <= day:
                heapq.heappop(min_heap)
            
            if min_heap:
                exp_day, count = heapq.heappop(min_heap)
                if count > 1:
                    heapq.heappush(min_heap, (exp_day, count - 1))
                total_eaten += 1
            
            day += 1
        
        return total_eaten
```该实现首先初始化最小堆和天计数器。 每天，它都会向堆中添加新苹果，删除腐烂的苹果，并消耗最早过期批次中的一个苹果。 循环继续超出`n`几天吃剩下的未腐烂的苹果。 堆确保查找和删除最快腐烂的苹果等操作的效率。 

## 解决方案```go
package main

import (
    "container/heap"
)

type AppleBatch struct {
    expDay int
    count  int
}

type MinHeap []AppleBatch

func (h MinHeap) Len() int { return len(h) }
func (h MinHeap) Less(i, j int) bool { return h[i].expDay < h[j].expDay }
func (h MinHeap) Swap(i, j int) { h[i], h[j] = h[j], h[i] }

func (h *MinHeap) Push(x interface{}) {
    *h = append(*h, x.(AppleBatch))
}

func (h *MinHeap) Pop() interface{} {
    old := *h
    n := len(old)
    item := old[n-1]
    *h = old[0 : n-1]
    return item
}

func eatenApples(apples []int, days []int) int {
    h := &MinHeap{}
    heap.Init(h)
    totalEaten := 0
    n := len(apples)
    day := 0

    for day < n || h.Len() > 0 {
        if day < n && apples[day] > 0 {
            heap.Push(h, AppleBatch{expDay: day + days[day], count: apples[day]})
        }

        for h.Len() > 0 && (*h)[0].expDay <= day {
            heap.Pop(h)
        }

        if h.Len() > 0 {
            batch := heap.Pop(h).(AppleBatch)
            if batch.count > 1 {
                heap.Push(h, AppleBatch{expDay: batch.expDay, count: batch.count - 1})
            }
            totalEaten++
        }

        day++
    }

    return totalEaten
}
```Go 实现镜像了 Python 逻辑，使用自定义的最小堆类型`AppleBatch`。 主要区别在于使用 Go 处理堆操作`container/heap`接口和结构类型。
