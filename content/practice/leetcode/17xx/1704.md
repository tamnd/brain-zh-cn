 # 判断字符串的两半是否相似

 ## 问题理解

 问题给了我们一个字符串`s`其长度保证是偶数。 我们将字符串分成两个相等的部分：

 - 上半场称为`a`- 下半场称为`b`我们必须确定两半是否包含相同数量的元音。 元音包括小写和大写英语元音：

 - 小写：`a`,`e`,`i`,`o`,`u`- 大写：`A`,`E`,`I`,`O`,`U`如果两半包含相同的元音计数，我们返回`true`。 否则，我们返回`false`。 

例如，如果输入是`"book"`：

 - 上半场：`"bo"`- 下半场：`"ok"`每半部分恰好包含一个元音（`o`），所以答案是`true`。 

限制很小：

 -`2 <= s.length <= 1000`- 字符串长度始终为偶数
 - 字符串仅包含大写和小写字母

 由于最大长度仅为 1000，因此即使相对简单的解决方案也能高效工作。 然而，我们仍然可以设计一个具有恒定额外空间的最佳线性时间解决方案。 

一个重要的观察是，问题只关心元音的数量，而不关心它们的位置。 我们不需要存储子字符串或执行复杂的比较。 

有几种边缘情况值得考虑：

 - 根本没有元音的字符串，两半都有零元音，因此是相似的。 
- 元音多次出现的字符串，每次出现都必须单独计数。 
- 大写和小写字母混合，我们必须正确识别两种情况下的元音。 
- 非常短的字符串，例如长度`2`，其中每一半仅包含一个字符。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是显式地将字符串拆分为两个子字符串：

 - 创建上半场
 - 创建下半场
 - 独立计算每一半的元音
 - 比较计数

 这是有效的，因为单独计算元音可以保证准确的比较。 

尽管此解决方案对于约束来说已经足够高效，但它会创建额外的子字符串对象并执行两次单独的遍历。 

### 最佳方法

 更好的方法是一次处理两半。 

我们可以保持运行平衡，而不是用两个循环分别计算元音：

 - 添加`1`当我们在前半部分看到元音时
 - 减法`1`当我们在后半部分看到元音时

 最后：

 - 如果余额为`0`，两半包含相同数量的元音
 - 否则，它们是不同的

 这避免了存储子字符串并保持解决方案简洁高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 创建子字符串并分别计算元音 |
 | 最佳 | O(n) | O(1) | O(1) | 具有运行元音平衡的单次遍历 |

 ## 算法演练

 ### 最优算法

 1. 创建一个包含所有元音（大写和小写）的集合。 
2. 使用以下命令计算字符串的中点`len(s) // 2`。 由于该问题保证了偶数长度，因此可以将字符串干净地分成相等的两半。 
3. 初始化一个名为`balance`到`0`。 该变量跟踪两半中元音计数之间的差异。 
4.从索引开始遍历字符串`0`到`len(s) - 1`。 
5. 对于每个字符：

 - 如果该字符不是元音，则忽略它。 
- 如果是元音：

 - 添加`1`到`balance`如果角色属于前半部分。 
- 减法`1`从`balance`如果角色属于下半场。 
6、遍历结束后：

 - 返回`True`如果`balance == 0`- 否则返回`False`### 为什么它有效

 该算法保持不变式`balance`始终等于：```
(number of vowels in first half processed so far)
-
(number of vowels in second half processed so far)
```前半部分的每个元音都会增加平衡，而后半部分的每个元音都会减少平衡。 如果两半包含相同的元音总数，则最终余额必须为零。 因此，检查`balance == 0`正确判断两半是否相似。 

## Python 解决方案```python
class Solution:
    def halvesAreAlike(self, s: str) -> bool:
        vowels = set("aeiouAEIOU")
        half = len(s) // 2
        balance = 0

        for index, char in enumerate(s):
            if char in vowels:
                if index < half:
                    balance += 1
                else:
                    balance -= 1

        return balance == 0
```解决方案首先创建一组元音。 集合提供平均 O(1) 查找时间，使元音检查更加高效。 

变量`half`存储字符串的中点。 由于保证长度是偶数，因此之前的索引`half`属于上半年，指数来自`half`接下来属于下半场。 

这`balance`变量跟踪元音计数的差异。 迭代期间：

 - 前半部分的元音增加平衡
 - 后半部分的元音降低了平衡度

 最后，平衡为零意味着两半包含相同数量的元音。 

此实现避免创建临时子字符串并在一次传递中处理输入。 

## 解决方案```go
func halvesAreAlike(s string) bool {
    vowels := map[byte]bool{
        'a': true,
        'e': true,
        'i': true,
        'o': true,
        'u': true,
        'A': true,
        'E': true,
        'I': true,
        'O': true,
        'U': true,
    }

    half := len(s) / 2
    balance := 0

    for i := 0; i < len(s); i++ {
        if vowels[s[i]] {
            if i < half {
                balance++
            } else {
                balance--
            }
        }
    }

    return balance == 0
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 Go 不使用集合，而是使用`map[byte]bool`来表示元音。 

Go 中的字符串按字节索引，这在这里可以正常工作，因为输入仅包含英文字母字符。 

该解决方案使用单次遍历和恒定的额外内存。

 ## 边缘情况

 ### 没有元音的字符串

 输入如`"bcdfBCDF"`两边都不包含元音。 有缺陷的实现可能会错误地假设至少存在一个元音。 该解决方案可以自然地处理这种情况，因为余额永远不会从零开始变化。 

### 混合大小写字母

 该问题明确指出元音可能以大写或小写形式出现。 仅检查小写元音的实现对于以下输入将失败`"AbCdEfGh"`。 该解决方案在查找集中包括大写和小写元音。 

### 多个重复元音

 输入如`"textbook"`包含重复的元音。 每个元音的出现必须单独计数。 使用独特的元音跟踪的简单实现会产生不正确的结果。 该算法独立处理每个字符，因此可以正确计算重复的元音。 

### 最小长度字符串

 最小有效输入长度为`2`。 例子包括`"xY"`和`"uU"`。 某些实现可能会错误地处理非常短字符串的索引或中点计算。 由于中点是使用整数除法计算的，并且循环统一处理所有索引，因此这些情况可以正常工作。
