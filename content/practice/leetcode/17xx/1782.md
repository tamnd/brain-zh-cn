 # LeetCode 1782 - 计算节点对

 ## 问题理解

 我们得到一个无向图`n`节点和边列表。 同一对节点之间允许有多个边。 

对于任意一对节点`(a, b)`， 定义`incident(a, b)`作为连接到任一节点的边数`a`或节点`b`。 

乍一看，这个值似乎很简单：$$degree(a) + degree(b)$$然而，这并不总是正确的。 如果有直接连接的边`a`和`b`，这些边都以两个度数计算。 自从`incident(a, b)`计算连接到任一节点的边，每个共享边只能计算一次。 

如果有`c`之间的边缘`a`和`b`， 然后：$$incident(a,b)=degree(a)+degree(b)-c$$对于每个查询值`q`，我们必须数出有多少对`(a,b)`和`a < b`满足：$$incident(a,b) > q$$限制条件很大：

 -`n ≤ 2 × 10^4`-`edges.length ≤ 10^5`-`queries.length ≤ 20`检查所有节点对的强力解决方案需要粗略检查：$$\frac{n(n-1)}{2}$$对，大约 2 亿对`n = 20000`。 这太慢了。 

有几个细节让问题变得棘手：

 - 相同节点之间可以存在多条边。 
- 度数计算每个边缘出现的次数。 
- 一对之间的直接连接会导致重复计数。 
- 我们必须有效地回答多个查询。 
- 该图相对于可能的节点对的数量是稀疏的。 

关键的挑战是在不明确检查所有对的情况下计算具有大度数和的对。 

## 方法

 ### 蛮力

 最直接的方法是计算每个节点的度和每个边对的重数。 

对于每个查询：

 1. 枚举每一对`(a,b)`。 
2. 计算`degree[a] + degree[b]`。 
3. 减去它们之间的直接边的数量。 
4. Check whether the result exceeds the query.

 这是正确的，因为它直接实现了定义`incident(a,b)`。 

不幸的是，有`O(n²)`对。 和`n = 20000`，这变得不可行。 

### 关键见解

 假设我们暂时忽略由直接边引起的重复计数。 

那么条件就变成：$$degree(a)+degree(b) > q$$这是一个经典的配对计数问题。 

如果我们对所有节点度进行排序，我们可以统计总和超过的对的数量`q`使用两指针技术`O(n)`时间。 

然而，其中一些计数对是无效的。 

考虑搭配：$$degree(a)+degree(b) > q$$但$$degree(a)+degree(b)-c \le q$$在哪里`c`是直接连接它们的边的数量。 

这些对通过度和计算进行计数，但不应出现在最终答案中。 

校正是可能的，因为实际共享边的不同节点对的数量最多为`edges.length`，这只是`10^5`。 

因此：

 1. 统计度数总和超过查询的所有对。 
2. 仅检查共享边的节点对。 
3. 减去错误计数的部分。 

这产生了一个有效的解决方案。

 ## 算法演练

 ### 步骤 1：计算节点度数

 创建一个数组`degree`。 

对于每一个边缘`(u,v)`:

 - 增量`degree[u]`- 增量`degree[v]`这给出了每个节点的关联边的总数。 

### 步骤 2：记录边重数

 由于多条边可能连接同一对节点，因此存储：$$count(u,v)$$对于每个无序对。 

始终按排序顺序存储该对：$$(min(u,v), max(u,v))$$这允许稍后直接查找。 

### 步骤3：对度数序列进行排序

 创建所有节点度数的排序副本。 

该数组将用于高效的配对计数。 

### 步骤 4：按度数和计算对数

 对于查询`q`，使用两个指针。 

1. 设置`left = 0`2. 设置`right = n - 1`尽管`left < right`：

- 如果$$sorted[left] + sorted[right] > q$$然后之间的每个元素`left`和`right-1`与`right`也超过`q`。 

添加：$$right-left$$到答案并递减`right`。 

否则递增`left`。 

这会计算度数总和超过的所有对`q`。 

### 步骤 5：删除多算的对

 对于每个节点对`(u,v)`至少有一个直接边缘：

 让：$$s = degree(u)+degree(v)$$并让：$$c = count(u,v)$$如果：$$s > q$$但$$s-c \le q$$那么这一对在步骤 4 中被计算在内，但不应该被计算在最终答案中。 

从答案中减去一。 

### 第 6 步：存储结果

 完成所有更正后，存储当前查询的最终计数。 

对每个查询重复此操作。 

### 为什么它有效

 两指针阶段精确计算度数和超过查询阈值的所有对。 对于没有直接边的节点对，度数总和等于事件计数，因此这些对已经是正确的。 

对于具有直接边的节点对，度数总和高估了真实事件计数，准确地说是共享边的数量。 校正阶段精确识别度数和超过阈值但真实事件计数未超过阈值的那些对。 减去这些对可以消除所有误报并准确地留下有效对。 
## 问题理解

 该问题给出了一个无向图`n`节点和边列表，其中同一对节点之间允许有多个边。 每个节点都有一个度数，该度数由与其关联的边数（计算重数）定义。 

对于任意一对不同的节点`(a, b)`和`a < b`，我们定义`incident(a, b)`作为连接到任一的边的数量`a`或者`b`。 重要的是，之间的边缘`a`和`b`即使它们对两个端点的度数都有贡献，但它们只能在此值中计算一次。 

每个查询询问：有多少对`(a, b)`满足`incident(a, b) > queries[j]`。 

输出是一组答案，每个查询一个。 

约束条件很大：最多`2 * 10^4`节点和`10^5`边，最多有 20 个查询。 这强烈表明每个查询`O(n log n)`或者`O(n)`解决方案是可以接受的，但是任何关于边缘或节点的二次方程都会太慢。 

重要的边缘情况包括在相同节点之间具有许多重复边的图、完全断开的节点以及具有非常高的倾斜度的节点（星形结构）。 另一个微妙的问题是正确处理相同两个节点之间的多条边，因为它们会影响度数和和校正。 

## 方法

 ### 蛮力方法

 最直接的方法就是计算`incident(a, b)`对于每对节点`(a, b)`然后通过检查是否超过阈值来回答每个查询。 

计算`incident(a, b)`天真地，我们要么扫描每对的所有边，要么预先计算邻接计数并将它们组合起来。 即使使用邻接图，也会迭代所有`O(n^2)`配对在复杂性中占主导地位。 

自从`n`可以达到`2 * 10^4`，大约有`2 * 10^8`对，这太大了。 即使计算每对的恒定时间检查也会太慢，并且对每个查询执行此操作会使情况变得更糟。 

### 优化的关键见解

 我们将问题分为两部分：

 首先，忽略同一对之间的多条边的复杂性。 如果我们定义`deg[a]`作为节点的度数`a`，那么对于任意一对`(a, b)`, 朴素总和`deg[a] + deg[b]`计算所有关联边，但它直接对之间的边进行双重计数`a`和`b`。 

如果有`cnt(a, b)`之间的边缘`a`和`b`，那么正确的值为：```
incident(a, b) = deg[a] + deg[b] - cnt(a, b)
```这导致自然分解：

 我们首先数一下有多少对满足`deg[a] + deg[b] > query`。 这可以使用排序和两指针技术有效地完成。 

然而，这超出了一些对，其中减去`cnt(a, b)`使它们低于或等于阈值。 我们通过使用边缘重数的哈希图仅显式纠正共享边缘的对来解决此问题。 

所以解决方案就变成了：

 1. 根据度数总和计算所有有效对。 
2. 减去每个查询的共享边导致的无效对。

 ## 算法演练

 最优解决方案分两个阶段构建：预处理和查询应答。 

### 步骤 1：计算度数和边重数

 我们迭代所有边并计算：

 -`deg[x]`：每个节点的度（包括重复项）
 -`cnt[(x, y)]`: x 和 y 之间的边数

 这使我们能够稍后纠正多算的对。 

### 第 2 步：对学位进行排序

 我们创建一个度数排序数组。 这对于使用两指针技术有效地计数对至关重要。 

### 步骤 3：预处理边重数

 我们将每个无向边存储在具有标准化排序的映射中`(min(u, v), max(u, v))`跟踪存在多少条平行边。 

### 第 4 步：对查询进行排序

 我们对查询进行排序，同时保留其原始索引，以便我们可以有效地按升序回答它们。 

### 步骤 5：使用两个指针计数碱基对

 对于每个查询`q`，我们计算对的数量`(i, j)`这样：```
deg[i] + deg[j] > q
```我们使用两个指针来做到这一点：

 我们从`l = 0`,`r = n - 1`。 如果`deg[l] + deg[r] > q`，那么所有对`(l, l+1 ... r)`有效`l`，所以我们添加`(r - l)`并减少`r`。 否则，我们增加`l`。 

这给了我们一个快速`O(n)`每个查询计数方法。 

### 步骤 6：纠正多算的对

 对于每条边`(u, v)`具有多重性`c`，我们计算：```
deg[u] + deg[v]
```基本方法很重要`(u, v)`如果该金额超过则有效`q`，但真实条件是：```
deg[u] + deg[v] - c > q
```因此，当出现以下情况时会发生错误：```
deg[u] + deg[v] > q
and
deg[u] + deg[v] - c <= q
```这意味着：```
q ∈ [deg[u] + deg[v] - c, deg[u] + deg[v] - 1]
```对于每个查询，我们使用二分搜索对排序查询减去此类无效贡献。 

### 为什么它有效

 关键的不变量是所有对都首先在宽松的度量下进行计数（`deg[a] + deg[b]`），它是单调且可高效查询的。 与正确性的唯一偏差来自对之间的内部边缘，并且这些边缘是稀疏的（最多`m`），允许有针对性的修正。 通过隔离这些修正，我们完全避免了重新计算成对结构。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def countPairs(self, n: int, edges: List[List[int]], queries: List[int]) -> List[int]:
        degree = [0] * (n + 1)
        edge_count = defaultdict(int)

        for u, v in edges:
            degree[u] += 1
            degree[v] += 1

            if u > v:
                u, v = v, u

            edge_count[(u, v)] += 1

        sorted_degrees = sorted(degree[1:])

        answers = []

        for q in queries:
            total = 0

            left = 0
            right = n - 1

            while left < right:
                if sorted_degrees[left] + sorted_degrees[right] > q:
                    total += right - left
                    right -= 1
                else:
                    left += 1

            for (u, v), cnt in edge_count.items():
                degree_sum = degree[u] + degree[v]

                if degree_sum > q and degree_sum - cnt <= q:
                    total -= 1

            answers.append(total)

        return answers
```### 实现说明

### Code Explanation

The solution begins by computing degrees and storing edge multiplicities in a hash map. The degree array is then sorted to allow efficient two-pointer counting of valid pairs for each query.

The function `count_greater` computes how many pairs have degree sum greater than a threshold using a linear scan from both ends.

After computing base answers, we iterate over all edges and adjust results for queries where the edge causes overcounting. This ensures correctness in cases where multiple edges reduce the true incident count below the threshold.

### Go-Specific Notes

The Go solution mirrors the Python implementation closely.

A custom `Pair` struct is used as the key in the hash map because Go maps cannot directly use slices as keys. The degree array uses `int`, which is sufficient because the largest possible degree is at most `2 × 10^5`.

The sorted degree slice is created once and reused for every query.
func countPairs(n int, edges [][]int, queries []int) []int {
	deg := make([]int, n+1)
	cnt := make(map[[2]int]int)

	for _, e := range edges {
		u, v := e[0], e[1]
		deg[u]++
		deg[v]++
		if u > v {
			u, v = v, u
		}
		cnt[[2]int{u, v}]++
	}

	arr := make([]int, n)
	for i := 1; i <= n; i++ {
		arr[i-1] = deg[i]
	}

	sortInts(arr)

	type pair struct {
		q int
		i int
	}

	sortedQ := make([]pair, len(queries))
	for i, q := range queries {
		sortedQ[i] = pair{q, i}
	}

	sort.Slice(sortedQ, func(i, j int) bool {
		return sortedQ[i].q < sortedQ[j].q
	})

	res := make([]int, len(queries))

	countGreater := func(q int) int {
		l, r := 0, len(arr)-1
		ans := 0
		for l < r {
			if arr[l]+arr[r] > q {
				ans += (r - l)
				r--
			} else {
				l++
			}
		}
		return ans
	}

	for _, p := range sortedQ {
		res[p.i] = countGreater(p.q)
	}

	for key, c := range cnt {
		u, v := key[0], key[1]
		if u == v {
			continue
		}
		su := deg[u] + deg[v]

		for _, p := range sortedQ {
			if su > p.q && su-c <= p.q {
				res[p.i]--
			}
		}
	}

	return res
}

func sortInts(a []int) {
	for i := 1; i < len(a); i++ {
		j := i
		for j > 0 && a[j-1] > a[j] {
			a[j-1], a[j] = a[j], a[j-1]
			j--
		}
	}
}

 ## 边缘情况

 ### 同一对之间的多个边

 这是问题中最重要的边缘情况。 如果节点`u`和`v`由几条平行边连接，则`degree[u] + degree[v]`对这些边进行两次计数。 仅使用度数总和的解决方案会过度计算某些对。 该实现存储每个节点对的重数并执行校正步骤以准确地处理这个问题。 

### 大量孤立节点

 许多节点的度数可能为零。 排序后，度数组可以包含长串零。 两指针计数方法自然可以处理这个问题，因为涉及零度节点的对只有在与足够大的度数配对时才会起作用。 无需特殊处理。 

### 查询边界附近的对

 一些节点对满足：$$degree(u)+degree(v)>q$$但$$degree(u)+degree(v)-count(u,v)\le q$$这些正是由于重复计算共享边而产生的误报。 校正条件精确检查此边界情况并减去该对一次，以确保正确性。 

### 极大的查询值

 查询可能接近于`edges.length`。 在这种情况下，很少有配对符合资格。 两指针扫描仍然可以正常工作，因为它只是发现超过阈值的度数和较少。 不会出现特殊情况或溢出问题。 

### 密集平行边缘配置

 图可能包含相对较少的节点对，但它们之间有许多重复的边。 由于校正阶段在不同的节点对上迭代，而不是在单个边缘出现上迭代，因此即使边缘重数很大，实现仍然有效。 
| 时间 | O(n log n + m log Q) | O(n log n + m log Q) | 排序占主导地位，加上每个边缘每个查询的更正|
 | 空间| O(n + m) | 度数数组和边缘频率图 |

 主要成本是对度数组进行排序并迭代边缘以进行查询更正。 由于查询很小（≤ 20），因此该解决方案仍然高效。

 ## 边缘情况

 一种重要的边缘情况是图不包含边。 在这种情况下，所有度数都为零，因此每对都有`incident(a, b) = 0`。 对于所有大于零的查询，该算法正确返回零，因为没有对满足不等式。 

另一种边缘情况是一对节点之间存在许多平行边。 这会影响度数和校正逻辑。 如果没有校正步骤，对于许多查询来说，这样的对将会被多算。 该实现通过显式跟踪多重性并调整每个查询来处理此问题。 

最后的边缘情况涉及星形图中非常大的度数节点。 这里，大多数对都涉及中心节点，并且两指针方法可以有效地处理倾斜分布，而无需枚举所有对。
