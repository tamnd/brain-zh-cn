[LeetCode 问题 1757](https://leetcode.com/problems/recyclable-and-low-fat-products/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个名为`Products`。 每行代表一个产品并包含三列：

 | 专栏 | 意义|
 | --- | --- |
 |`product_id`| 产品的唯一标识符|
 |`low_fats`|`'Y'`如果产品是低脂肪的，否则`'N'`|
 |`recyclable`|`'Y'`如果产品可回收，否则`'N'`|

 任务是返回同时满足这两个条件的产品的ID：

 1.产品低脂
 2.产品可回收

 换句话说，我们只需要以下行：```
low_fats = 'Y'
AND recyclable = 'Y'
```输出应包含单个列：```
product_id
```结果的顺序并不重要。 

从概念上讲，约束非常小，因为这是一个介绍性的 SQL 过滤问题。 该表已经保证了`product_id`是唯一的，因为它是主键。 的值`low_fats`和`recyclable`仅限于`'Y'`和`'N'`，所以我们不需要处理无效值。 

一个重要的观察是，该问题并不要求我们修改数据、聚合行或连接多个表。 我们只需要根据两个条件过滤行。 

一些边缘情况值得考虑：

 - 没有产品满足这两个条件，结果应该为空。 
- 每个产品都满足这两个条件，所有 ID 都应退回。 
- 产品可能只满足一个条件，这些行不得出现在结果中。 
- 由于顺序是任意的，因此不需要排序。 

## 方法

 ### 蛮力方法

 思考这个问题的蛮力方法是检查数组中的每一行`Products`一一表。 对于每种产品，我们都会检查：

 - 是`low_fats = 'Y'`？ 
- 是`recyclable = 'Y'`？ 

如果两者都为真，我们将包括`product_id`在结果中。 

这种方法保证有效，因为每一行都根据所需条件进行显式检查。 任何产品都不能漏掉，更不能包含无效的产品。 

实际上，这已经很有效，因为过滤表中的行是线性操作。 由于任务本身很简单，因此没有比扫描相关行更快的方法了。 

### 最佳方法

 最佳解决方案使用 SQL`WHERE`子句直接在数据库引擎内部过滤表。 

关键的见解是 SQL 是专门为声明性过滤操作而设计的。 我们让数据库引擎仅返回匹配的行，而不是手动迭代应用程序代码中的行。 

我们需要的条件是：```
low_fats = 'Y' AND recyclable = 'Y'
```这个解决方案是简洁、高效且符合惯用的 SQL。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(1) | O(1) | 扫描每一行并手动检查条件 |
 | 最佳 | O(n) | O(1) | O(1) | 使用 SQL 过滤`WHERE`条款|

 ## 算法演练

 1. 从`Products`包含所有产品的表。 
2. 使用 SQL 应用过滤条件`WHERE`条款。 
3. 检查是否`low_fats`等于`'Y'`。 这确保了产品是低脂肪的。 
4. 检查是否`recyclable`等于`'Y'`。 这确保了产品是可回收的。 
5. 使用`AND`运算符，以便仅返回满足这两个条件的行。 
6. 仅选择`product_id`列，因为问题要求提供产品 ID，而不是完整的行。 

最终查询变为：```sql
SELECT product_id
FROM Products
WHERE low_fats = 'Y'
AND recyclable = 'Y';
```### 为什么它有效

 该算法之所以有效，是因为每个产品行都是根据问题陈述中的确切要求进行评估的。 仅当两个布尔条件都为 true 时才包含行。 由于 SQL 过滤对表行具有确定性和详尽性，因此结果精确地包含可回收且低脂肪的产品。 

## Python 解决方案

 尽管这是一个数据库问题并且 LeetCode 需要 SQL 查询，但以下 Python 示例以编程方式演示了相同的逻辑。```python
from typing import List, Dict

class Solution:
    def recyclableAndLowFat(
        self,
        products: List[Dict[str, str]]
    ) -> List[int]:
        result = []

        for product in products:
            if (
                product["low_fats"] == "Y"
                and product["recyclable"] == "Y"
            ):
                result.append(product["product_id"])

        return result
```该实现会迭代输入列表中的每个产品。 对于每个产品，它检查两个必填字段是否等于`"Y"`。 

如果满足条件，则将产品 ID 添加到结果列表中。 处理完所有产品后，返回结果列表。 

这准确地反映了 SQL 逻辑。 这`if`条件直接对应SQL`WHERE`条款。 

为了完整起见，实际的 LeetCode SQL 解决方案是：```python
SELECT product_id
FROM Products
WHERE low_fats = 'Y'
AND recyclable = 'Y';
```## 解决方案```go
package main

type Product struct {
	ProductID  int
	LowFats    string
	Recyclable string
}

func recyclableAndLowFat(products []Product) []int {
	result := []int{}

	for _, product := range products {
		if product.LowFats == "Y" && product.Recyclable == "Y" {
			result = append(result, product.ProductID)
		}
	}

	return result
}
```Go 实现遵循与 Python 版本相同的逻辑。 我们迭代产品切片并将匹配的产品 ID 附加到结果切片中。 

Go 特有的一个小细节是，切片在使用时会动态调整大小`append`。 与 Python 列表不同，Go 切片区分`nil`和空切片，但是这两种表示形式在这里都可以正常工作，因为问题只关心返回值。 

为了完整起见，实际的 LeetCode SQL 解决方案是：```go
SELECT product_id
FROM Products
WHERE low_fats = 'Y'
AND recyclable = 'Y';

 ## 边缘情况

 ### 没有符合条件的产品

 一种常见的边缘情况是每个产品至少不符合一个条件。 例如，所有产品可能都是不可回收的或不是低脂的。 

有缺陷的实现可能会意外使用`OR`而不是`AND`，这会错误地包含部分匹配的产品。 当前的实现通过同时要求这两个条件来避免这种情况。 

### 空输入表

 该表可能包含零行。 在这种情况下，正确的结果只是一个空结果集。 

该实现自然地处理了这个问题，因为迭代空集合执行零迭代，使结果为空。 

### 产品仅匹配一个条件

 有些产品可能是低脂肪但不可回收的，或者可回收但不是低脂肪的。 

这很重要，因为幼稚的实现可能会意外地将任一条件视为充分条件。 实现明确检查：```
product["low_fats"] == "Y" and product["recyclable"] == "Y"
```这保证了仅包含满足这两个要求的产品。 

### 所有产品均匹配

 当每行都满足条件时，就会出现另一个重要的边缘情况。 该实现必须返回所有产品 ID，且不跳过任何行。 

由于该算法独立检查每一行并附加每个有效 ID，因此所有符合条件的产品都会正确返回。
