[LeetCode 问题 1733](https://leetcode.com/problems/minimum-number-of-people-to-teach/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、贪婪

 ## 解决方案

 ## 问题理解

 该问题对社交网络中的通信进行建模，其中每个用户都知道一种或多种语言。 如果两个用户至少有一种共同语言，那么他们就可以直接交流。 目标是确保每对友谊对在向某些用户教授一种选定的语言后都可以进行交流。 

输入由三部分组成：

 -`n`，可能的语言总数。 
-`languages`， 在哪里`languages[i]`包含用户已知的语言`i + 1`。 
-`friendships`，其中每对`[u, v]`代表着用户之间的友谊`u`和`v`。 

重要的细节是，仅检查直接友谊的通信。 沟通不具有传递性。 即使用户 A 可以与 B 通话并且 B 可以与 C 通话，但这并不意味着 A 可以与 C 通话。 

我们可以选择一种语言并将其教授给任意数量的用户。 教学结束后，每一对友谊都必须至少有一种共同语言。 我们希望最大限度地减少受教用户的数量。 

限制相对较小：

 - 最多 500 个用户
 - 最多 500 个好友
 - 最多 500 种语言

 这些界限表明涉及用户和语言嵌套循环的解决方案是可以接受的。 精心设计的暴力方法可能已经通过了，但我们仍然可以显着优化逻辑。 

一些边缘情况很重要：

 - 一些友谊对可能已经进行了交流，这意味着他们不需要采取任何行动。 
- 多对互不相干的友谊可能需要教导。 
- 用户可能已经知道所选的教学语言，因此不应被计算在内。 
- 可能根本没有有问题的友谊，在这种情况下答案是`0`。 
- 幼稚的实现可能会错误地对不同好友之间的用户进行多次计数。 

核心挑战是确定哪些用户实际上需要针对给定候选语言进行教学。 

## 方法

 ### 蛮力方法

 一个简单的暴力解决方案将尝试所有可能的语言`1`到`n`。 对于每种语言，我们都会检查每对友谊。 

如果两个朋友已经共享一种语言，则无需执行任何操作。 否则，他们中至少有一个人必须学习所选的语言。 我们可以通过收集所有涉及有问题的友谊但还不知道候选语言的用户来模拟这个过程。 

处理完所有好友后，收集到的用户数量代表有多少人必须学习该语言。 我们对每种语言都重复此操作，并采用最少的语言。 

这种方法是正确的，因为我们明确测试了每种可能的语言选择并计算了必须教授的确切用户数量。 

对于给定的约束，暴力破解的想法已经足够有效，但关键的优化是意识到我们只关心当前无法通信的好友关系中的用户。 

### 关键见解

 最重要的观察是，已经有共同语言的友谊是无关紧要的。 无论我们选择哪种语言，都不需要对他们进行教学。 

因此，我们首先识别所有“有问题的”友谊对，即没有共同语言的友谊对。 

一旦我们知道了有问题的用户，问题就变成了：

 > 选择一种尽可能多的有问题的用户已知的语言。 

如果我们选择语言`L`，那么每个已经知道的有问题的用户`L`不需要教导。 其他人都必须学习它。 

因此，我们可以：

 1.收集所有参与有问题好友的用户。 
2. 计算其中有多少用户已经了解每种语言。 
3. 选择计数最多的语言。 
4. 教导剩下的有问题的用户。 

这将问题转化为频率计数问题。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n × f × k) | O(n × f × k) | O(米) | 尝试每种语言并直接处理所有友谊 |
 | 最佳 | O(f × k + m × k) | O(f × k + m × k) | O(m + n) | 仅关注有问题的友谊并计算语言频率 |

 在哪里：

-`f`= 好友数量
 -`m`= 用户数量
 -`k`= 每个用户的平均语言数量

 ## 算法演练

 1. 将每个用户的语言列表转换为一个集合。 

使用集合可以实现高效的成员资格测试和交集检查。 由于我们反复需要确定两个用户是否共享一种语言，因此设置使此操作更快、更清晰。 
2. 迭代每对友谊。 

为了每一份友谊`[u, v]`，检索两个用户的语言集。 
3. 检查两个用户是否已经有共同语言。 

我们可以通过检查两个集合的交集是否非空来测试这一点。 

如果他们已经共享一种语言，则无需执行任何操作。 
4. 从有问题的好友中收集用户。 

如果两个用户无法通信，请将两个用户添加到名为`need_teaching`。 

我们使用一个集合是因为​​同一个用户可能会出现在多个有问题的友谊中，但我们只想对它们计数一次。 
5. 计算有问题的用户的语言频率。 

对于每个用户`need_teaching`，计算有多少用户已经了解每种语言。 

这告诉我们，如果我们选择该语言，有多少用户不需要教学。 
6. 找出最大数量有问题的用户所知道的语言。 

假设最好的语言已经被已知`best_count`用户。 
7. 计算答案。 

每个尚不知道所选语言的有问题的用户都必须学习它。 

所以：`answer = len(need_teaching) - best_count`### 为什么它有效

 每段有问题的友谊最终都必须至少有一种共同语言。 由于我们在全球范围内只能教授一种语言，因此所有未解决的用户都必须转向同一种语言。 

对于所选语言`L`，唯一需要指导的用户是尚不知道的有问题的用户`L`。 因此，最小化教学相当于最大化有问题的用户已经知道所选语言的数量。 

由于该算法通过频率计数隐式评估所有语言，因此它总是能找到最佳答案。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def minimumTeachings(self, n: int, languages: List[List[int]], friendships: List[List[int]]) -> int:
        language_sets = [set(lang_list) for lang_list in languages]

        need_teaching = set()

        for u, v in friendships:
            user_u_languages = language_sets[u - 1]
            user_v_languages = language_sets[v - 1]

            if user_u_languages.isdisjoint(user_v_languages):
                need_teaching.add(u - 1)
                need_teaching.add(v - 1)

        language_count = defaultdict(int)

        for user in need_teaching:
            for language in language_sets[user]:
                language_count[language] += 1

        max_known = 0

        for count in language_count.values():
            max_known = max(max_known, count)

        return len(need_teaching) - max_known
```实现首先将每个用户的语言列表转换为一个集合。 这很重要，因为通过集合操作检查两个用户是否共享一种语言会变得高效。 

接下来，我们遍历每对友谊。 这`isdisjoint()`方法检查两个集合是否没有公共元素。 如果两个用户无法通信，则两个用户都会添加到`need_teaching`放。 

这`need_teaching`集合恰好包含参与至少一个未解决的友谊的用户。 这个集合之外的用户永远不需要教导，因为他们所有的友谊都已经发挥作用了。 

识别出有问题的用户后，我们会计算语言频率。 对于每个用户`need_teaching`，我们增加他们已经知道的每种语言的计数。 

频率最高的语言是最好的教学语言，因为它可以最大限度地减少必须学习它的新用户的数量。 

最后，我们从有问题的用户总数中减去最大频率，以计算所需的最少教学。 

## 解决方案```go
package main

func minimumTeachings(n int, languages [][]int, friendships [][]int) int {
	languageSets := make([]map[int]bool, len(languages))

	for i, langs := range languages {
		languageSets[i] = make(map[int]bool)

		for _, lang := range langs {
			languageSets[i][lang] = true
		}
	}

	needTeaching := make(map[int]bool)

	for _, friendship := range friendships {
		u := friendship[0] - 1
		v := friendship[1] - 1

		canCommunicate := false

		for lang := range languageSets[u] {
			if languageSets[v][lang] {
				canCommunicate = true
				break
			}
		}

		if !canCommunicate {
			needTeaching[u] = true
			needTeaching[v] = true
		}
	}

	languageCount := make(map[int]int)

	for user := range needTeaching {
		for lang := range languageSets[user] {
			languageCount[lang]++
		}
	}

	maxKnown := 0

	for _, count := range languageCount {
		if count > maxKnown {
			maxKnown = count
		}
	}

	return len(needTeaching) - maxKnown
}
```Go 实现密切反映了 Python 逻辑。 由于 Go 没有内置的集合类型，因此使用带有布尔值的映射来模拟集合。 

语言成员资格检查是通过`map[int]bool`。 这`needTeaching`结构也被实现为地图以避免重复用户。 

与Python不同`isdisjoint()`，Go 通过迭代一个用户的语言映射并检查另一个用户的成员资格来手动检查两个用户是否共享一种语言。 

整数溢出不是一个问题，因为在给定的约束下所有值仍然非常小。

from typing import List

class Solution:
    def minimumTeachings(self, n: int, languages: List[List[int]], friendships: List[List[int]]) -> int:
        from collections import defaultdict

        language_sets = [set(lang_list) for lang_list in languages]

        need_teaching = set()

        for u, v in friendships:
            if language_sets[u - 1].isdisjoint(language_sets[v - 1]):
                need_teaching.add(u - 1)
                need_teaching.add(v - 1)

        language_count = defaultdict(int)

        for user in need_teaching:
            for language in language_sets[user]:
                language_count[language] += 1

        return len(need_teaching) - max(language_count.values(), default=0)

solution = Solution()

 ## 边缘情况

 当每对友谊都已经共享共同语言时，就会出现一个重要的边缘情况。 粗心的实现可能仍然会尝试不必要地教导用户。 在这个解决方案中，这种友谊被完全忽略，留下`need_teaching`空的。 最终答案变成`0`正确。 

当同一用户参与多个有问题的友谊时，会发生另一种微妙的情况。 幼稚的实现可能会对同一用户进行多次计数，从而夸大答案。 使用一组`need_teaching`保证每个用户都被精确计数一次，无论他们出现在多少有问题的友谊中。 

当几种候选语言产生相同的最佳答案时，就会出现第三种棘手的情况。 例如，相同数量的有问题的用户可能已经知道多种语言。 该实现自然地通过获取最大频率计数来处理这个问题。 由于只有最少数量的教义才重要，因此联系不会影响正确性。 

最后一个边缘情况涉及已经了解多种语言的用户。 这些用户可能已经知道所选择的教学语言，即使他们参与了有问题的友谊。 频率计数步骤正确地避免了再次教导这些用户，因为它们有助于该语言的现有计数。
