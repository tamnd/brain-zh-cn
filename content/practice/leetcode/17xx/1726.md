[LeetCode 问题 1726](https://leetcode.com/problems/tuple-with-same-product/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、计数

 ## 解决方案

 ## 问题理解

 该问题要求我们计算所有元组的数量`(a, b, c, d)`来自给定的**不同正整数**数组，使得前两个元素的乘积等于后两个元素的乘积，`a * b = c * d`，并且所有元素都是不同的。 重要的是，相同数字的排列被视为单独的元组。 输入数组`nums`长度可达 1000，值可达 10,000。 

输出是表示有效元组数量的单个整数。 该问题保证所有元素都是不同的，这简化了重复处理，但需要仔细计算不同对的数量。 要考虑的边缘情况包括元素很少（少于 4 个）的数组、没有配对产品匹配的数组，以及可能创建许多有效元组的大量数组。 

## 方法

 蛮力方法涉及检查所有可能的四元组`(a, b, c, d)`从数组中。 这确保了正确性，因为每个可能的元组都会被检查，但它的速度非常慢，因为四元组的数量是`O(n^4)`。 为了`n = 1000`，这在计算上是不可行的。 

更优化解决方案的关键观察是我们只需要考虑**成对的乘积**。 如果两个不同的对`(a, b)`和`(c, d)`产生相同的乘积，则这四个数字通过排列形成 8 个有效元组：`(a, b, c, d)`,`(a, b, d, c)`,`(b, a, c, d)`,`(b, a, d, c)`，以及首先与另一对对称的情况。 使用哈希图来计算每个产品的出现次数使我们能够有效地计算元组的数量。 这降低了复杂性`O(n^4)`到`O(n^2)`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n^4) | O(n^4) | O(1) | O(1) | 显式检查每个四元组，保证正确性，但速度极慢 |
 | 最佳 | O(n^2) | O(n^2) | O(n^2) | O(n^2) | 使用哈希映射按乘积对对进行计数，然后根据组合计算元组计数

 ## 算法演练

 1. 初始化一个哈希映射来存储每个对的乘积的计数。 关键是产品`a * b`该值是生产该产品的不同对的数量。 
2. 迭代所有对`(i, j)`在`nums`在哪里`i < j`。 计算乘积`nums[i] * nums[j]`。 
3. 增加哈希图中该产品的计数。 
4. 初始化变量`result`为零。 
5. 对于哈希图中的每个产品，如果它出现在`k`不同的对，计算元组的数量为`k * (k - 1) * 4`。 因素`4`解释了所描述的两对的排列。 
6. 返回存储在中的总计数`result`。 

**为什么有效：** 出现在多对中的每个产品都保证两个不同对的每个组合都满足`a * b = c * d`。 计数公式`k * (k - 1) * 4`正确枚举所有排列，确保不会遗漏任何有效元组。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def tupleSameProduct(self, nums: List[int]) -> int:
        product_count = defaultdict(int)
        
        n = len(nums)
        for i in range(n):
            for j in range(i + 1, n):
                product = nums[i] * nums[j]
                product_count[product] += 1
        
        result = 0
        for count in product_count.values():
            if count > 1:
                result += count * (count - 1) * 4
        
        return result
```Python 解决方案使用`defaultdict`有效跟踪产品数量。 嵌套循环生成所有对`(i, j)`无需重复，确保`i < j`保持不同的对。 最后，使用所有排列的对组合乘以 4 来计算元组计数。 

## 解决方案```go
func tupleSameProduct(nums []int) int {
    productCount := make(map[int]int)
    n := len(nums)

    for i := 0; i < n; i++ {
        for j := i + 1; j < n; j++ {
            product := nums[i] * nums[j]
            productCount[product]++
        }
    }

    result := 0
    for _, count := range productCount {
        if count > 1 {
            result += count * (count - 1) * 4
        }
    }

    return result
}
```Go 版本与 Python 实现非常相似，使用`map[int]int`来计算产品数量。 嵌套循环处理对生成，并且使用整数算术计算元组计数非常简单。 不需要对 nil 或空切片进行特殊处理，因为循环自然会跳过空数组。 

## 工作示例

 **示例1：**`nums = [2,3,4,6]`| 配对| 产品 |
 | ---| ---|
 | (2,3) | 6 |
 | (2,4) | 8 |
 | (2,6) | 12 | 12
 | (3,4) | 12 | 12
 | (3,6) | 18 | 18
 | (4,6) | 24 |

 唯一产品`12`有计数`2`（对`(2,6)`和`(3,4)`），贡献`2 * 1 * 4 = 8`元组。 输出是`8`。 

**示例2：**`nums = [1,2,4,5,10]`生成重复产品的对：

 | 产品 | 成对|
 | ---| ---|
 | 10 | 10 (1,10), (2,5) | (1,10), (2,5) |
 | 20 | (2,10), (4,5) | (2,10), (4,5) |

 对于每个产品，计算`2`, 贡献`2 * 1 * 4 = 8`元组。 元组总数=`8 + 8 = 16`。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n^2) | O(n^2) | 生成所有对`(i,j)`从`n`数字，计算乘积，然后迭代哈希映射值 |
 | 空间| O(n^2) | O(n^2) | 在最坏的情况下，每对都有一个唯一的产品，存储在哈希映射中 |

 该方法有效地减少了`O(n^4)`通过认识到只有成对乘积的计数才重要，而不是所有四元组的数量都明确。

 ## 边缘情况

 **1. 没有匹配的产品：** 类似的数组`[1,2,3,4]`为所有配对生产独特的产品。 该算法可以正确处理此问题，因为哈希映射计数全部为`1`，因此元组计算循环不会向结果添加任何内容。 

**2. 最小长度数组：** 元素少于 4 个的数组，例如，`[1,2,3]`，无法形成有效的元组。 嵌套循环运行但找不到满足要求的对，返回`0`自然。 

**3. 大数字：** 值接近上限的数组，例如，`[1000,2000,3000,4000]`，可能会产生大型产品，但 Python 原生处理大整数，而 Go 使用`int`有足够的范围（假设 64 位）。 该算法可以正确扩展，在 Python 和通常的 64 位 Go 环境中不会出现溢出问题。
