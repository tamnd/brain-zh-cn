[LeetCode 问题 1773](https://leetcode.com/problems/count-items-matching-a-rule/)

 **难度：** 🟢简单
 **主题：** 数组、字符串

 ## 解决方案

 ## 问题理解

 该问题要求我们确定列表中有多少项满足给定的规则。 每个项目都表示为三个字符串的列表：其类型、颜色和名称。 该规则以两个字符串给出：`ruleKey`和`ruleValue`。 这`ruleKey`指定要比较项目的哪个属性（`type`,`color`， 或者`name`），以及`ruleValue`指定属性必须匹配的值。 任务是计算列表中有多少项目满足此规则。 

输入由列表数组组成，其中每个子列表始终包含三个字符串。 这些约束确保列表最多包含 10,000 个项目，并且每个字符串最多包含 10 个字符。 这是相对较小的，使得简单的线性扫描变得高效。 我们保证`ruleKey`将始终是三个有效键之一，并且所有字符串都是小写的，因此我们不需要处理无效键或大小写差异。 

可能会导致幼稚实现失败的边缘情况包括`ruleValue`不匹配任何项目，或多个属性共享相同字符串值的项目。 这些约束保证非空输入和有效的字符串长度，因此我们不需要处理空字符串或格式错误的列表。 

## 方法

 蛮力方法很简单。 我们迭代每个项目，确定哪个属性对应于`ruleKey`，并检查属性是否匹配`ruleValue`。 每次比较的时间复杂度为 O(1)，并且我们对所有项目重复此操作。 这给出了线性时间解决方案，在给定约束的情况下该解决方案已经是有效的。 不需要更复杂的算法，因为超过 10,000 个项目的线性扫描非常快。 

关键的见解是绘制地图`ruleKey`到项目列表中的正确索引：`"type"`映射到索引 0，`"color"`映射到索引 1，并且`"name"`映射到索引 2。通过执行一次此映射，我们避免了循环内重复的条件检查，稍微提高了清晰度和效率。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(1) | O(1) | 迭代所有项目，比较相关字段 |
 | 最佳 | O(n) | O(1) | O(1) | 地图`ruleKey`索引、迭代和计算匹配项； 相同的渐进式，但更清晰、更易于阅读 |

 ## 算法演练

 1. 创建映射`ruleKey`到项目列表中相应的索引：`"type" -> 0`,`"color" -> 1`,`"name" -> 2`。 
2. 将计数器初始化为零。 这将跟踪有多少项目符合规则。 
3. 使用映射确定要检查的属性的索引。 
4. 循环遍历列表中的每一项`items`列表。 
5. 对于每个项目，检查确定索引处的值是否等于`ruleValue`。 
6. 如果匹配，则递增计数器。 
7. 循环结束后，返回计数器。 

为什么它有效：这是有效的，因为映射确保我们始终检查正确的属性。 由于每个项目恰好具有相同顺序的三个属性，并且比较是精确的，因此每个匹配都被正确计数。 

## Python 解决方案```python
from typing import List

class Solution:
    def countMatches(self, items: List[List[str]], ruleKey: str, ruleValue: str) -> int:
        # Map ruleKey to the correct index in the sublist
        key_to_index = {"type": 0, "color": 1, "name": 2}
        index = key_to_index[ruleKey]
        
        # Count items that match the rule
        count = 0
        for item in items:
            if item[index] == ruleValue:
                count += 1
        return count
```这个Python实现首先映射`ruleKey`到其对应的索引。 然后，我们迭代输入列表中的每个项目。 通过直接索引到具有映射索引的项目，我们检查是否与`ruleValue`。 每场比赛都会增加计数器，最后我们返回总计数。 

## 解决方案```go
func countMatches(items [][]string, ruleKey string, ruleValue string) int {
    keyToIndex := map[string]int{"type": 0, "color": 1, "name": 2}
    index := keyToIndex[ruleKey]
    
    count := 0
    for _, item := range items {
        if item[index] == ruleValue {
            count++
        }
    }
    return count
}
```Go版本使用map来关联`ruleKey`与索引。 然后我们循环遍历每个项目切片并比较相关属性。 Go 可以有效地处理切片和字符串比较，因此其行为与 Python 相同。 诸如空切片之类的边缘情况会被隐式处理，因为约束保证每个子列表恰好具有三个元素。

 ## 边缘情况

 一种重要的边缘情况是没有项目符合规则。 幼稚的实现可能假设至少存在一个匹配项，但我们的方法通过将计数器初始化为零来正确返回零。 另一个边缘情况是当多个项目具有相同的值时，测试重复项是否正确地单独计数。 最后，如果`ruleValue`出现在其他字段中，但不在指定的字段中`ruleKey`，我们的实现正确地忽略了这些字段并仅比较目标字段。 这可以防止过度计数并确保准确性。
