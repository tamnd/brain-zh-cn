[LeetCode 第 1783 题](https://leetcode.com/problems/grand-slam-titles/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题要求我们计算数据库中记录的所有年份中每位运动员赢得了多少个大满贯网球冠军。 

我们有两张表：

 的`Players`表包含有关网球运动员的信息。 每行存储一个唯一的`player_id`以及相应的`player_name`。 

这`Championships`表存储了每年四项大满贯赛事的获胜者：

 -`Wimbledon`-`Fr_open`-`US_open`-`Au_open`这些列中的每一列都包含`player_id`在该特定年份赢得该锦标赛的球员。 

目标是计算每位玩家在所有年份和所有锦标赛中赢得锦标赛的总数。 如果一名玩家从未在任何锦标赛栏目中作为获胜者出现，那么他们不应出现在最终结果中。 

预期输出包含：

 -`player_id`-`player_name`-`grand_slams_count`输出行的顺序并不重要。 

重要的观察是每一行`Championships`包含四名独立的锦标赛获胜者。 从概念上讲，这意味着该表每年存储四个独立的获胜者记录。 为了正确计算总获胜次数，我们需要将所有锦标赛列视为单个获胜者流。 

尽管该问题被归类为数据库问题，但其核心思想本质上是计数和聚合任务。 

一些重要的边缘情况包括：

 - 一名球员可以在同一年赢得多场比赛。 
- 一名球员可能会在多年内赢得同一场比赛。 
- 有些玩家可能永远不会赢得任何东西，必须被排除在外。 
- 多个玩家可以拥有相同数量的头衔。 
- 数据库保证有效的玩家ID，因此每个获胜者ID都存在于`Players`桌子。 

由于每行的锦标赛数量固定为四，因此即使对于多年的数据，该解决方案仍然保持高效。 

## 方法

 ### 蛮力方法

 暴力解决方案将迭代每个玩家，并为每个玩家扫描整个`Championships`表来计算该玩家的 ID 在四个锦标赛列中出现的次数。 

对于每一行`Championships`，我们会将当前玩家的 ID 与：

 -`Wimbledon`-`Fr_open`-`US_open`-`Au_open`如果发生任何匹配，我们就会增加计数。 

这种方法是正确的，因为它明确检查每个玩家可能赢得的每场比赛。 然而，这是低效的，因为我们重复扫描每个球员的相同冠军记录。 

如果有`P`球员和`C`冠军行，那么工作就成正比`P * C`。 

### 最佳方法

 关键的见解是我们不需要重复扫描每个球员的冠军数据。 

相反，我们可以首先使用以下方法将所有锦标赛获胜者转换为一个统一的列表：`UNION ALL`。 一旦所有获奖者合并为一列，我们就可以简单地分组`player_id`并计算出现次数。 

这是有效的，因为合并结果中出现的每一位球员的 ID 都恰好对应一个大满贯冠军。 

计算计数后，我们将聚合结果与`Players`表来检索玩家姓名。 

这种方法仅处理冠军数据一次并有效地使用 SQL 聚合。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(P × C) | O(1) | O(1) | 扫描每位球员的所有冠军行|
 | 最佳 | O(C)| O(C)| 使用 UNION ALL 和 GROUP BY 进行高效聚合 |

 ## 算法演练

 1. 提取所有获奖者`Championships`桌子。 

每年都有四个获奖者专栏。 我们使用`UNION ALL`将它们组合成一个名为`player_id`。 
2. 保留重复值。 

我们有意使用`UNION ALL`而不是`UNION`因为每一次出现都代表着一个单独的大满贯冠军。 删除重复项会错误地减少计数。 
3. 按玩家 ID 对组合结果进行分组。 

将获胜者数据平铺到一列后，我们计算每个获胜者的次数`player_id`出现。 
4. 加入`Players`桌子。 

分组结果仅包含玩家 ID 和计数。 我们加入`Players`检索相应的玩家名称。 
5. 返回最终结果。 

输出包括：

 -`player_id`-`player_name`-`grand_slams_count`### 为什么它有效

 每一场大满贯胜利都会在锦标赛栏目中出现一次。 通过将所有锦标赛列合并到一个统一列表中，玩家 ID 的每次出现都对应于一个标题。 因此，根据球员 ID 进行分组并计算出现次数，可以得出每位球员赢得的大满贯冠军的准确数量。 

## Python 解决方案

 LeetCode 数据库问题是使用 SQL 而不是可执行的 Python 代码来解决的。 以下查询是正确的 LeetCode 提交。```python
SELECT
    p.player_id,
    p.player_name,
    COUNT(*) AS grand_slams_count
FROM Players p
JOIN (
    SELECT Wimbledon AS player_id FROM Championships
    UNION ALL
    SELECT Fr_open AS player_id FROM Championships
    UNION ALL
    SELECT US_open AS player_id FROM Championships
    UNION ALL
    SELECT Au_open AS player_id FROM Championships
) winners
ON p.player_id = winners.player_id
GROUP BY p.player_id, p.player_name;
```该查询首先创建一个名为的派生表`winners`。 该派生表包含每年的所有锦标赛获胜者。 

这`UNION ALL`操作至关重要，因为我们必须保留重复的胜利。 如果一名玩家赢得了多项锦标赛或多年的胜利，则每次发生的事件都必须保留在数据集中。 

创建统一的获奖者名单后，我们将其加入`Players`表使用`player_id`。 这使我们能够检索与每个获胜者相关的玩家姓名。 

最后，我们将两者分组`player_id`和`player_name`并使用`COUNT(*)`计算大满贯冠军的数量。 

由于只有出现在获胜者表中的玩家才会参与加入，因此头衔为零的玩家将被自动排除。 

## 解决方案

 LeetCode数据库问题不需要Go实现，因为提交是直接用SQL编写的。 然而，Go 中的等效逻辑在概念上看起来像这样：```go
package main

import "fmt"

type Player struct {
	ID   int
	Name string
}

type Championship struct {
	Year       int
	Wimbledon  int
	FrOpen     int
	USOpen     int
	AuOpen     int
}

func main() {
	players := []Player{
		{1, "Nadal"},
		{2, "Federer"},
		{3, "Novak"},
	}

	championships := []Championship{
		{2018, 1, 1, 1, 1},
		{2019, 1, 1, 2, 2},
		{2020, 2, 1, 2, 2},
	}

	winCount := make(map[int]int)

	for _, c := range championships {
		winCount[c.Wimbledon]++
		winCount[c.FrOpen]++
		winCount[c.USOpen]++
		winCount[c.AuOpen]++
	}

	playerNames := make(map[int]string)

	for _, p := range players {
		playerNames[p.ID] = p.Name
	}

	for playerID, count := range winCount {
		fmt.Println(playerID, playerNames[playerID], count)
	}
}
```Go 版本使用哈希映射来计算每个玩家 ID 的获胜次数。 每个锦标赛获胜者都会增加相应的计数器。 

与 SQL 不同，Go 需要显式迭代所有冠军记录并手动维护聚合图。 

这里没有关于整数溢出的特别问题，因为锦标赛计数仍然相对较小。 与 SQL 解决方案的主要区别在于聚合是按过程而不是声明方式实现的。

 ## 边缘情况

 ### 从未获胜的玩家

 一个常见的错误是不小心将从未出现在锦标赛结果中的球员纳入其中。 由于该解决方案使用了内部联接`Players`和汇总获胜者表中，只有至少有一场胜利记录的玩家才会出现在输出中。 

### 同年多次获胜

 一名球员可以在一年内赢得几场比赛。 例如，一名球员可能在同一赛季赢得温布尔登、法国公开赛和美国公开赛。 使用`UNION`而不是`UNION ALL`会错误地删除重复的玩家 ID 并少算标题。 该实现通过使用正确地保留了每一次胜利`UNION ALL`。 

### 多年来屡获殊荣

 一名球员可能会在多年内赢得同一场比赛。 聚合逻辑独立处理每次出现的事件，确保无论赛季或锦标赛重复如何，所有冠军都能正确计数。
