[LeetCode 第 1728 题](https://leetcode.com/problems/cat-and-mouse-ii/)

 **难度：** 🔴难
 **主题：** 数组、数学、动态规划、图论、拓扑排序、记忆、矩阵、博弈论

 ## 解决方案

 ## 问题理解

 该问题描述了在小网格上进行的两人完美信息博弈。 一名玩家控制老鼠，另一名玩家控制猫。 两名玩家都以最佳方式移动并交替轮流，鼠标始终首先移动。 

网格包含多种单元：

 -`'M'`代表鼠标的起始位置。 
-`'C'`代表猫的起始位置。 
-`'F'`代表食物。 
-`'.'`代表空的地板单元。 
-`'#'`代表无法跨越的墙。 

在每一回合中，活跃玩家可以向上、向下、向左或向右移动任意距离`0`达到他们的跳跃极限。 移动不能穿过墙壁或离开网格。 留在原地也是允许的。 

获胜条件是不对称的：

 - 如果猫落在老鼠身上，猫立即获胜。 
- 如果猫先到达食物，则猫获胜。 
- 如果老鼠先到达食物，则老鼠获胜。 
- 如果游戏持续时间过长，并且老鼠在 1000 回合内没有到达食物，则猫自动获胜。 

任务是确定在双方发挥最佳的情况下，鼠标是否可以强行获胜。 

限制很小：

 - 网格尺寸最多为`8 x 8`。 
- 细胞总数最多为`64`。 
- 跳跃距离最多为`8`。 

尽管棋盘很小，但游戏状态空间很大，因为每个状态都取决于：

 - 鼠标位置
 - 猫的位置
 - 轮到谁了

 此外，循环也是可能的，因为玩家可以留在原地或重新访问位置。 这意味着除非仔细控制，否则简单的递归很容易永远循环。 

一些边缘情况很重要：

 - 老鼠或猫可能已经有了到达食物的直接路径。 
- 保持静止可能是战略上的最佳选择。 
- 墙壁可以完全阻止移动。 
- 猫只需阻止老鼠长时间接触食物即可获胜。 
- 必须正确处理循环游戏状态。 
- 必须考虑具有不同跳跃长度的多条路径。 

这本质上是有向状态图上的博弈论问题。 

## 方法

 ### 蛮力方法

 最直接的解决方案是使用极小极大风格搜索递归地模拟每个可能的游戏。 

对于每个州：

 - 如果轮到鼠标了，尝试每一个合法的鼠标移动。 
- 如果轮到猫了，尝试所有合法的猫动作。 
- 继续递归，直到有人获胜。 

这在概念上产生了正确的答案，因为它探索了最佳游戏下的完整博弈树。 

然而，问题是游戏图包含循环。 玩家可以重复地重新访问相同的位置，特别是因为允许保持静止。 如果没有仔细的记忆和循环处理，递归可能会变得无限。 

即使有记忆，分支因子也很大，因为每个状态都可能产生许多可能的跳转。 额外的 1000 回合规则也使递归变得复杂，因为结果可能取决于移动计数。 

简单的暴力搜索变得不切实际。 

### 最佳方法

 关键的见解是，这是一个有限的公正博弈，可以建模为状态图。 

状态由以下部分组成：

 - 鼠标位置
 - 猫的位置
 - 转向指示器

 每个状态根据有效的移动转换到其他状态。 

我们不是递归地向前求解，而是使用反向图传播和拓扑博弈分析向后求解。 

这种技术类似于国际象棋残局中使用的逆行分析。 

这个想法是：

 - 首先标记终端获胜状态。 
- 向后传播结果。 
- 如果玩家能够为自己进入胜利状态，那么当前状态就是胜利。 
- 如果每一步可能都会导致对手获胜，那么当前状态就是失败。 

这避免了无限递归，因为状态是系统处理的。 

状态数量是可控的：

 - 至多`64 * 64 * 2 = 8192`州。 

这使得基于图的动态规划变得可行。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 指数| 指数| 递归探索所有可能的游戏路径 |
 | 最佳 | O(N² × D) | O(N²) | 具有记忆结果的游戏状态的反向 BFS |

 这里：

-`N`是可行走单元格的数量
 -`D`是一个状态的最大合法移动次数

 ## 算法演练

 ### 第 1 步：对可步行单元进行编码

 首先，扫描网格并为每个非壁单元分配一个整数索引。 

这简化了状态存储，因为位置现在可以表示为整数而不是坐标对。 

我们还记录：

 - 鼠标起始位置
 - 猫起始位置
 - 食物位置

 ### 步骤 2：预先计算合法的移动

 对于每个单元格，预先计算以下所有有效目的地：

 - 鼠标移动
 - 猫的运动

 这包括：

 - 留在原地
 - 跳跃任意距离`1`跳跃极限
 - 在墙前停下来

 预计算动作避免了游戏分析过程中重复的网格遍历。 

### 第 3 步：定义游戏状态

 状态表示为：```
(mouse_position, cat_position, turn)
```在哪里：

-`turn = 0`表示鼠标转动
 -`turn = 1`意味着猫转弯

 对于我们存储的每个状态：

 - 结果状态

 - 未知
 - 鼠标获胜
 - 猫赢
 - 剩余学位

 - 可用的合法移动次数

 该度对于反向传播很重要。 

### 步骤 4：初始化终端状态

 一些州的结果立即已知。 

如果老鼠和猫占据同一个单元格：

 - 猫立即获胜。 

如果猫到达食物：

 - 猫立即获胜。 

如果老鼠到达食物：

 - 鼠标立即获胜。 

这些状态成为反向 BFS 的起点。 

### 步骤 5：构建反向状态传播

 我们向后处理状态。 

假设我们知道某个州正在为老鼠获胜。 

那么任何先前的鼠标转动状态只要能够进入这个状态，对于鼠标来说也是获胜的。 

同样：

 - 如果某个状态的每一步行动都会导致对手获胜，则该状态就会失败。 

为了有效地支持这一点，我们动态计算父状态。 

### 步骤 6：反向 BFS

 我们使用包含已解决状态的队列。 

对于每个已解决的状态：

 1. 查找所有前驱状态。 
2.如果前任的当前玩家可以为自己进入获胜状态：

 - 将前任标记为获胜。 
3.否则降低其剩余度。 
4. 如果度数变为零：

 - 所有动作都失败，因此将其标记为对手胜利。 

这是标准的游戏图逆行传播技术。 

### 步骤7：返回初始状态结果

 最后，检查：```
(mouse_start, cat_start, mouse_turn)
```如果该状态被标记为鼠标获胜：

 - 返回`True`否则：

 - 返回`False`### 为什么它有效

 该算法之所以有效，是因为每个状态都是根据最佳玩法进行分类的。 

如果该玩家能够迫使游戏进入已知对他们有利的状态，则该状态对于该玩家来说是获胜的。 如果每一个合法的举动都会导致对手获胜，那么一个州就会失败。 

反向 BFS 保证只有在有足够的信息可用后才能解决状态。 由于游戏图是有限的，每个可达状态最终都会得到正确的分类。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def canMouseWin(self, grid: List[str], catJump: int, mouseJump: int) -> bool:
        rows = len(grid)
        cols = len(grid[0])

        positions = []
        pos_to_id = {}

        mouse_start = 0
        cat_start = 0
        food = 0

        for r in range(rows):
            for c in range(cols):
                if grid[r][c] != '#':
                    idx = len(positions)
                    positions.append((r, c))
                    pos_to_id[(r, c)] = idx

                    if grid[r][c] == 'M':
                        mouse_start = idx
                    elif grid[r][c] == 'C':
                        cat_start = idx
                    elif grid[r][c] == 'F':
                        food = idx

        n = len(positions)

        directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

        def build_moves(jump_limit: int):
            moves = [[] for _ in range(n)]

            for i, (r, c) in enumerate(positions):
                moves[i].append(i)

                for dr, dc in directions:
                    for step in range(1, jump_limit + 1):
                        nr = r + dr * step
                        nc = c + dc * step

                        if not (0 <= nr < rows and 0 <= nc < cols):
                            break

                        if grid[nr][nc] == '#':
                            break

                        moves[i].append(pos_to_id[(nr, nc)])

            return moves

        mouse_moves = build_moves(mouseJump)
        cat_moves = build_moves(catJump)

        MOUSE_TURN = 0
        CAT_TURN = 1

        UNKNOWN = 0
        MOUSE_WIN = 1
        CAT_WIN = 2

        result = [[[UNKNOWN] * 2 for _ in range(n)] for _ in range(n)]
        degree = [[[0] * 2 for _ in range(n)] for _ in range(n)]

        for m in range(n):
            for c in range(n):
                degree[m][c][MOUSE_TURN] = len(mouse_moves[m])
                degree[m][c][CAT_TURN] = len(cat_moves[c])

        queue = deque()

        for pos in range(n):
            for turn in range(2):
                if pos != food:
                    result[pos][pos][turn] = CAT_WIN
                    queue.append((pos, pos, turn, CAT_WIN))

                result[food][pos][turn] = MOUSE_WIN
                queue.append((food, pos, turn, MOUSE_WIN))

                if pos != food:
                    result[pos][food][turn] = CAT_WIN
                    queue.append((pos, food, turn, CAT_WIN))

        def parents(mouse_pos: int, cat_pos: int, turn: int):
            if turn == MOUSE_TURN:
                for prev_cat in cat_moves[cat_pos]:
                    yield mouse_pos, prev_cat, CAT_TURN
            else:
                for prev_mouse in mouse_moves[mouse_pos]:
                    yield prev_mouse, cat_pos, MOUSE_TURN

        while queue:
            mouse_pos, cat_pos, turn, state_result = queue.popleft()

            for pm, pc, pt in parents(mouse_pos, cat_pos, turn):
                if result[pm][pc][pt] != UNKNOWN:
                    continue

                if (
                    pt == MOUSE_TURN and state_result == MOUSE_WIN
                ) or (
                    pt == CAT_TURN and state_result == CAT_WIN
                ):
                    result[pm][pc][pt] = state_result
                    queue.append((pm, pc, pt, state_result))
                else:
                    degree[pm][pc][pt] -= 1

                    if degree[pm][pc][pt] == 0:
                        loser_result = (
                            CAT_WIN if pt == MOUSE_TURN else MOUSE_WIN
                        )

                        result[pm][pc][pt] = loser_result
                        queue.append((pm, pc, pt, loser_result))

        return result[mouse_start][cat_start][MOUSE_TURN] == MOUSE_WIN
```实现首先将每个可步行单元转换为紧凑的整数标识符。 这允许使用数组而不是哈希图有效地索引所有游戏状态。 

接下来，该解决方案预先计算老鼠和猫的每个合法运动。 由于两个玩家的跳跃距离不同，因此建立了两个单独的移动表。 

这`result`数组存储每个可能状态的结果。 最初，所有状态都是未知的。 这`degree`数组跟踪每个状态有多少未解决的合法动作。 

然后初始化终端获胜状态：

 - 老鼠吃食物意味着老鼠获胜。 
- 猫吃东西意味着猫赢。 
- 猫抓老鼠意味着猫赢。 

这些已知状态被插入到 BFS 队列中。 

这`parents()`生成器动态计算反向边缘。 不是显式存储反向图，而是在需要时生成前驱状态。 

BFS 传播期间：

 - 如果一名玩家能够为自己进入获胜状态，则前任玩家将立即获胜。 
- 否则，一项合法的举动将被消除。 
- 如果没有剩余动作，该状态就会失败。 

最后，算法检查初始游戏状态是否被分类为鼠标获胜。 

## 解决方案```go
package main

import "container/list"

func canMouseWin(grid []string, catJump int, mouseJump int) bool {
	rows := len(grid)
	cols := len(grid[0])

	type Pair struct {
		r int
		c int
	}

	positions := []Pair{}
	posToID := map[Pair]int{}

	mouseStart := 0
	catStart := 0
	food := 0

	for r := 0; r < rows; r++ {
		for c := 0; c < cols; c++ {
			if grid[r][c] != '#' {
				id := len(positions)
				positions = append(positions, Pair{r, c})
				posToID[Pair{r, c}] = id

				if grid[r][c] == 'M' {
					mouseStart = id
				} else if grid[r][c] == 'C' {
					catStart = id
				} else if grid[r][c] == 'F' {
					food = id
				}
			}
		}
	}

	n := len(positions)

	directions := [][]int{
		{1, 0},
		{-1, 0},
		{0, 1},
		{0, -1},
	}

	buildMoves := func(jumpLimit int) [][]int {
		moves := make([][]int, n)

		for i, p := range positions {
			moves[i] = append(moves[i], i)

			for _, d := range directions {
				for step := 1; step <= jumpLimit; step++ {
					nr := p.r + d[0]*step
					nc := p.c + d[1]*step

					if nr < 0 || nr >= rows || nc < 0 || nc >= cols {
						break
					}

					if grid[nr][nc] == '#' {
						break
					}

					moves[i] = append(moves[i], posToID[Pair{nr, nc}])
				}
			}
		}

		return moves
	}

	mouseMoves := buildMoves(mouseJump)
	catMoves := buildMoves(catJump)

	const (
		MOUSE_TURN = 0
		CAT_TURN   = 1

		UNKNOWN    = 0
		MOUSE_WIN  = 1
		CAT_WIN    = 2
	)

	result := make([][][]int, n)
	degree := make([][][]int, n)

	for i := 0; i < n; i++ {
		result[i] = make([][]int, n)
		degree[i] = make([][]int, n)

		for j := 0; j < n; j++ {
			result[i][j] = make([]int, 2)
			degree[i][j] = make([]int, 2)

			degree[i][j][MOUSE_TURN] = len(mouseMoves[i])
			degree[i][j][CAT_TURN] = len(catMoves[j])
		}
	}

	type State struct {
		mouse int
		cat   int
		turn  int
		res   int
	}

	queue := list.New()

	for pos := 0; pos < n; pos++ {
		for turn := 0; turn < 2; turn++ {

			if pos != food {
				result[pos][pos][turn] = CAT_WIN
				queue.PushBack(State{pos, pos, turn, CAT_WIN})
			}

			result[food][pos][turn] = MOUSE_WIN
			queue.PushBack(State{food, pos, turn, MOUSE_WIN})

			if pos != food {
				result[pos][food][turn] = CAT_WIN
				queue.PushBack(State{pos, food, turn, CAT_WIN})
			}
		}
	}

	for queue.Len() > 0 {
		front := queue.Front()
		queue.Remove(front)

		cur := front.Value.(State)

		mousePos := cur.mouse
		catPos := cur.cat
		turn := cur.turn
		stateResult := cur.res

		if turn == MOUSE_TURN {

			for _, prevCat := range catMoves[catPos] {

				pm := mousePos
				pc := prevCat
				pt := CAT_TURN

				if result[pm][pc][pt] != UNKNOWN {
					continue
				}

				if stateResult == CAT_WIN {
					result[pm][pc][pt] = CAT_WIN
					queue.PushBack(State{pm, pc, pt, CAT_WIN})
				} else {
					degree[pm][pc][pt]--

					if degree[pm][pc][pt] == 0 {
						result[pm][pc][pt] = MOUSE_WIN
						queue.PushBack(State{pm, pc, pt, MOUSE_WIN})
					}
				}
			}

		} else {

			for _, prevMouse := range mouseMoves[mousePos] {

				pm := prevMouse
				pc := catPos
				pt := MOUSE_TURN

				if result[pm][pc][pt] != UNKNOWN {
					continue
				}

				if stateResult == MOUSE_WIN {
					result[pm][pc][pt] = MOUSE_WIN
					queue.PushBack(State{pm, pc, pt, MOUSE_WIN})
				} else {
					degree[pm][pc][pt]--

					if degree[pm][pc][pt] == 0 {
						result[pm][pc][pt] = CAT_WIN
						queue.PushBack(State{pm, pc, pt, CAT_WIN})
					}
				}
			}
		}
	}

	return result[mouseStart][catStart][MOUSE_TURN] == MOUSE_WIN
}
```Go 实现遵循与 Python 解决方案相同的算法结构。 

主要区别在于内存处理。 Go 需要显式分配多维切片，因此`result`和`degree`数组是逐层初始化的。 

Go 还缺少 Python 生成器，因此前驱遍历是在 BFS 传播期间内联编写的。 

队列是使用以下方式实现的`container/list`，它提供了来自两端的高效推入和弹出操作。 

由于所有状态值都适合标准整数，因此不必担心溢出。

 ## 边缘情况

 当老鼠第一次移动就能立即到达食物时，就会出现一个重要的边缘情况。 幼稚的实现可能会不必要地继续搜索，而不是识别即时获胜条件。 该解决方案可以正确处理该问题，因为涉及食物处的鼠标的所有最终状态都在 BFS 传播开始之前初始化。 

另一个棘手的情况涉及循环。 由于允许两个玩家保持静止，因此游戏图可以包含许多循环。 由于无限递归或不正确的记忆，递归 DFS 解决方案经常在此失败。 反向 BFS 方法完全避免了这种情况，因为每个状态都是通过图传播有限地处理的。 

墙壁造成了另一个微妙的问题。 玩家无法跳墙，即使他们的跳跃距离通常允许。 不正确的实现有时会允许移动穿过阻塞的单元格。 一旦遇到墙壁，该解决方案就会明确停止移动生成，确保每个生成的移动都是有效的。 

最后一个边缘情况是猫先于老鼠到达食物。 有些实现只关注直接捕获，而忘记了猫也通过占领食物来获胜。 初始化阶段明确地将猫在食物上的每个状态标记为猫的胜利，保证正确的传播。
