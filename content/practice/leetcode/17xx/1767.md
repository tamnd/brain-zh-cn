[LeetCode 问题 1767](https://leetcode.com/problems/find-the-subtasks-that-did-not-execute/)

 **难度：** 🔴难
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题围绕着识别任务的哪些子任务未执行。 我们有两张表：`Tasks`和`Executed`。 这`Tasks`表列出了所有任务以及每个任务划分为的子任务数量，而`Executed`表列出了给定任务成功运行的子任务。 目标是生成一个包含所有内容的表`(task_id, subtask_id)`应该根据运行的对`Tasks`但失踪了`Executed`。 

换句话说，对于每个任务，我们必须从中生成所有子任务`1`到`subtasks_count`并减去已经执行的。 剩下的子任务是需要报告的缺失子任务。 约束告诉我们，每个任务至少有两个子任务，最多有 20 个，因此每个任务的子任务数量很少且易于管理。 这`Executed`表保证没有子任务 ID 超过其任务的子任务数量，因此我们不需要验证 ID。 

重要的边缘情况包括没有执行子任务的任务（全部丢失）、所有子任务都已执行的任务（没有丢失）以及仅执行部分子任务的任务。 该解决方案应该正确处理所有三种情况。 

## 方法

 蛮力方法将涉及生成所有可能的`(task_id, subtask_id)`对每个任务进行配对，然后过滤掉任务中存在的任务`Executed`使用连接或内存检查的表。 虽然简单，但效率可能较低，因为它会为每个任务生成最多 20 个子任务，然后检查每对子任务的存在性，如果任务数量很大，则会导致不必要的计算和大量中间结果。 

最佳方法依赖于为每个任务生成所有潜在的子任务 ID，并与`Executed`桌子。 然后，我们只过滤`NULL`匹配，代表缺失的执行。 这可以有效地利用 SQL 集操作，而无需生成冗余检查或进行复杂的过滤。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(T * S) | O(T * S) | 生成所有子任务并检查是否存在`Executed`|
 | 最佳 | O(T * S) | O(T * S) | 生成所有子任务并使用 LEFT JOIN 和 NULL | 过滤器

 这里`T`是任务数量，`S`是最大子任务数 (≤ 20)。 

## 算法演练

 1. 对于每个任务`Tasks`表，生成从 1 到 的所有子任务 ID`subtasks_count`。 这可以使用数字表或 SQL 来完成`generate_series`在支持它的数据库中。 
2. 将生成的子任务列表左连接到`Executed`两个表`task_id`和`subtask_id`。 
3. 过滤其中的行`subtask_id`从`Executed`表是`NULL`，表示该子任务尚未执行。 
4. 返回结果`(task_id, subtask_id)`成对作为最终结果。 

为什么它有效：创建每个任务的潜在子任务的完整列表，因此任何丢失的执行都可以被检测为`NULL`左连接后。 不变的是，左连接始终保留任务的所有可能的子任务 ID，并过滤`NULL`准确捕捉缺失的内容。 

## Python 解决方案```python
import sqlite3
from typing import List, Tuple

def find_missing_subtasks(tasks: List[Tuple[int, int]], executed: List[Tuple[int, int]]) -> List[Tuple[int, int]]:
    conn = sqlite3.connect(":memory:")
    cur = conn.cursor()
    
    cur.execute("CREATE TABLE Tasks(task_id INT, subtasks_count INT)")
    cur.execute("CREATE TABLE Executed(task_id INT, subtask_id INT)")
    
    cur.executemany("INSERT INTO Tasks VALUES (?, ?)", tasks)
    cur.executemany("INSERT INTO Executed VALUES (?, ?)", executed)
    
    query = """
    WITH numbers(n) AS (
        SELECT 1
        UNION ALL
        SELECT n + 1 FROM numbers WHERE n < 20
    ),
    all_subtasks AS (
        SELECT t.task_id, n.n AS subtask_id
        FROM Tasks t
        JOIN numbers n ON n.n <= t.subtasks_count
    )
    SELECT a.task_id, a.subtask_id
    FROM all_subtasks a
    LEFT JOIN Executed e
    ON a.task_id = e.task_id AND a.subtask_id = e.subtask_id
    WHERE e.subtask_id IS NULL
    """
    
    cur.execute("PRAGMA recursive_triggers = ON")
    cur.execute(query)
    result = cur.fetchall()
    conn.close()
    return result
```此 Python 解决方案使用 SQLite 模拟 SQL 执行。 递归 CTE`numbers`生成 1 到 20 之间的整数，足以覆盖所有子任务。 然后`all_subtasks`计算所有任务-子任务组合，以及左连接`Executed`识别缺失的子任务。 

## 解决方案```go
package main

import (
    "database/sql"
    _ "github.com/mattn/go-sqlite3"
)

func findMissingSubtasks(tasks [][2]int, executed [][2]int) [][2]int {
    db, _ := sql.Open("sqlite3", ":memory:")
    defer db.Close()

    db.Exec("CREATE TABLE Tasks(task_id INT, subtasks_count INT)")
    db.Exec("CREATE TABLE Executed(task_id INT, subtask_id INT)")

    for _, t := range tasks {
        db.Exec("INSERT INTO Tasks VALUES (?, ?)", t[0], t[1])
    }
    for _, e := range executed {
        db.Exec("INSERT INTO Executed VALUES (?, ?)", e[0], e[1])
    }

    query := `
    WITH RECURSIVE numbers(n) AS (
        SELECT 1
        UNION ALL
        SELECT n + 1 FROM numbers WHERE n < 20
    ),
    all_subtasks AS (
        SELECT t.task_id, n.n AS subtask_id
        FROM Tasks t
        JOIN numbers n ON n.n <= t.subtasks_count
    )
    SELECT a.task_id, a.subtask_id
    FROM all_subtasks a
    LEFT JOIN Executed e
    ON a.task_id = e.task_id AND a.subtask_id = e.subtask_id
    WHERE e.subtask_id IS NULL
    `

    rows, _ := db.Query(query)
    defer rows.Close()

    var result [][2]int
    for rows.Next() {
        var task_id, subtask_id int
        rows.Scan(&task_id, &subtask_id)
        result = append(result, [2]int{task_id, subtask_id})
    }
    return result
}
```Go 版本反映了 Python 实现。 Go 需要显式的切片处理和使用`database/sql`执行查询。 CTE 中的递归工作方式与 Python/SQLite 类似。 

## 工作示例

 **示例 1 输入**

 任务表：

 | 任务 ID | 子任务计数 |
 | --- | --- |
 | 1 | 3 |
 | 2 | 2 |
 | 3 | 4 |

 执行表：

 | 任务 ID | 子任务 ID |
 | --- | --- |
 | 1 | 2 |
 | 3 | 1 |
 | 3 | 2 |
 | 3 | 3 |
 | 3 | 4 |

 **逐步执行**

 1. 生成数字1到20。 
2. 与Tasks连接，获取所有子任务：

 | 任务 ID | 子任务 ID |
 | --- | --- |
 | 1 | 1 |
 | 1 | 2 |
 | 1 | 3 |
 | 2 | 1 |
 | 2 | 2 |
 | 3 | 1 |
 | 3 | 2 |
 | 3 | 3 |
 | 3 | 4 |

 1. 与执行和过滤器左连接`NULL`：

 | 任务 ID | 子任务 ID |
 | --- | --- |
 | 1 | 1 |
 | 1 | 3 |
 | 2 | 1 |
 | 2 | 2 |

 输出符合预期。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(T * S) | 对于每个任务，生成最多 20 个子任务并执行连接 |
 | 空间| O(T * S) | 将生成的子任务对存储在内存中以进行连接/过滤 |

 该方法具有良好的扩展性，因为 S 是有界的 (≤20)。 左连接确保每个任务都独立且高效地处理。
