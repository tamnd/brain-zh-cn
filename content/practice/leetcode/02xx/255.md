 ## 解决方案

 ## 问题理解

 该问题给出了一个唯一整数数组，称为`preorder`。 这个数组应该代表二叉搜索树的前序遍历，我们必须确定这样的二叉搜索树是否真的存在。 

在前序遍历中，节点按以下顺序访问：

 1.访问当前节点
 2. 遍历左子树
 3. 遍历右子树

 二叉搜索树还有一个附加属性：

 - 左子树中的每个值都小于当前节点
 - 右子树中的每个值都大于当前节点

 挑战在于验证给定的预序序列是否可以由某些有效的 BST 生成。 

例如，序列`[5,2,1,3,6]`是有效的，因为我们可以构造一个 BST，其中：

 -`5`是根
 -`2,1,3`属于左子树
 -`6`属于右子树

 该 BST 的前序遍历与输入完全匹配。 

然而，`[5,2,6,1,3]`无效。 一旦我们访问`6`，我们已经进入了右子树`5`。 因此任何后来的值都必须大于`5`。 价值`1`随后出现，这违反了 BST 排序规则。 

这些约束告诉我们一些重要的事情：

 - 该数组最多可以包含`10^4`元素，因此指数或二次解是有风险的。 
- 所有值都是唯一的，这简化了 BST 验证，因为我们永远不需要处理重复项。 
- 值是相对较小的整数，但实际的数值范围不是重要的部分。 顺序关系很重要。 

一些重要的边缘情况包括：

 - 单元素数组，始终有效。 
- 严格递增的序列，例如`[1,2,3,4]`，它表示一个 BST，其中每个节点只有一个右子节点。 
- 严格递减序列，例如`[4,3,2,1]`，它表示一个 BST，其中每个节点只有一个左子节点。 
- 进入右子树后错误返回较小值的序列。 

## 方法

 ### 蛮力方法

 暴力解决方案尝试从前序遍历递归地重建 BST 结构。 

第一个元素始终是根。 随后的每个小于根的值都属于左子树，每个大于根的值都属于右子树。 我们可以递归地将数组分为左右部分，并验证每个子树是否满足 BST 规则。 

这是可行的，因为前序遍历自然分为：

 - 根
 - 左子树预序
 - 右子树预序

 在每个递归步骤中，我们搜索左子树元素和右子树元素之间的边界。 

尽管正确，但这种方法变得低效，因为每个递归调用可能会扫描数组的很大一部分来定位子树边界。 在最坏的情况下，例如严格递增或递减的数组，递归变得高度不平衡并导致二次时间复杂度。 

### 最佳方法

 关键的见解是前序遍历隐式定义了左子树和右子树之间的转换。 

从左到右扫描预序数组时：

 - 小于当前节点的值属于其左子树。 
- 一旦遇到更大的值，我们就在 BST 中向上移动并开始遍历右子树。 
- 进入某个祖先的右子树后，我们再也看不到小于该祖先的值。 

这一观察结果使我们能够维持一个下限。 

我们使用单调栈来模拟 BST 的遍历路径：

 - 堆栈存储右子树尚未完全处理的祖先。 
- 每当当前值大于堆栈顶部时，我们就会从堆栈中弹出，因为我们正在向上移动并进入右子树。 
- 最后弹出的值成为新的下限。 
- 如果我们遇到小于下限的值，则预排序序列无效。 

这给出了线性时间解。

 | 蛮力 | O(n²) | O(n) | 递归划分前序数组 |
 | 最佳| O(n) | O(n) | 使用单调堆栈和下界跟踪 |

 ## 算法演练

 1. 初始化一个空堆栈。 

堆栈代表我们当前在 BST 中遍历的祖先的路径。 它帮助我们确定何时从左子树移动到右子树。 
2. 初始化一个名为`lower_bound`到负无穷大。 

该变量跟踪未来节点允许拥有的最小值。 一旦我们移动到节点的右子树，所有未来的值都必须大于该节点。 
3. 迭代前序数组中的每个值。 

我们完全按照前序遍历顺序处理值。 
4. 检查当前值是否违反BST 性质。 

如果当前值小于`lower_bound`， 返回`False`。 

这意味着我们已经进入了某个祖先的右子树，因此在有效的 BST 中不可能看到较小的值。 
5. 当栈不为空且当前值大于栈顶时，从栈中弹出。 

弹出意味着我们从左子树向上移动到右子树。 

弹出的值成为新的值`lower_bound`因为所有未来的价值都必须大于它。 
6. 将当前值压入堆栈。 

该值稍后可能成为我们进入其右子树的祖先。 
7. 如果整个数组处理完毕且没有违规，则返回`True`。 

### 为什么它有效

 该算法保持一个关键的不变量：

 - 每个处理的值必须大于`lower_bound`。 
- 堆栈始终包含其右子树尚未完全遍历的祖先的递减序列。 

当我们从堆栈中弹出值时，我们模拟在 BST 中向上移动并转换到右子树。 一旦发生这种情况，所有未来的节点都必须保持比那些弹出的祖先更大。 任何违规行为都会立即证明预购序列是不可能的。 

## Python 解决方案```python
from typing import List

class Solution:
    def verifyPreorder(self, preorder: List[int]) -> bool:
        stack = []
        lower_bound = float("-inf")

        for value in preorder:
            if value < lower_bound:
                return False

            while stack and value > stack[-1]:
                lower_bound = stack.pop()

            stack.append(value)

        return True
```该实现紧密遵循前面描述的算法。 

这`stack`模拟通过 BST 的遍历路径。 每个元素代表一个祖先节点，该节点可能仍有未探索的右子节点。 

这`lower_bound`变量跟踪未来节点的最小允许值。 最初，没有限制，因此它从负无穷大开始。 

对于每个值：

 - 如果它小于`lower_bound`，预购序列违反了 BST 规则，我们立即返回`False`。 
- 当当前值大于堆栈顶部时，我们从堆栈中弹出祖先。 这模拟了在树中向上移动并进入右子树。 
- 每个弹出的祖先成为新的下限，因为未来的值必须保持大于它。 
- 最后，我们将当前值压入堆栈。 

如果我们处理完每个值而没有检测到违规，则该序列是有效的。 

## 解决方案```go
func verifyPreorder(preorder []int) bool {
	stack := []int{}
	lowerBound := -1 << 31

	for _, value := range preorder {
		if value < lowerBound {
			return false
		}

		for len(stack) > 0 && value > stack[len(stack)-1] {
			lowerBound = stack[len(stack)-1]
			stack = stack[:len(stack)-1]
		}

		stack = append(stack, value)
	}

	return true
}
```Go 实现遵循与 Python 版本相同的逻辑。 

切片用于实现堆栈。 切片的最后一个元素代表堆栈的顶部。 

Go 没有内置的整数负无穷大，因此实现初始化`lowerBound`使用一个非常小的整数值`-1 << 31`。 

出栈操作是通过重新切片来实现的：```go
stack = stack[:len(stack)-1]
```这可以有效地删除最后一个元素，而无需分配新的内存。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个元素最多被压入和弹出一次 |
 | 空间| O(n) | 最坏情况下堆栈可能存储所有元素 |

 时间复杂度是线性的，因为每个值恰好进入堆栈一次，最多离开堆栈一次。 没有必要地重新审视任何元素。 

最坏情况下空间复杂度是线性的。 对于严格递减的前序序列，堆栈的大小会增长`n`。

 ## 边缘情况

 单元素数组是一种重要的边缘情况，因为它表示可能的最小有效 BST。 假设左子树和右子树都存在的简单实现可能会在此输入上意外失败。 当前的实现可以自然地处理它，因为循环运行一次并且没有违反任何约束。 

严格递增序列，例如`[1,2,3,4,5]`是另一个重要案例。 这些对应于每个节点只有一个右子节点的 BST。 在处理过程中，算法会反复从堆栈中弹出并更新下界。 不正确的堆栈管理通常会导致此处出现错误，但实现正确地模拟了连续右子树的移动。 

严格递减序列，例如`[5,4,3,2,1]`也很重要。 这些生成的 BST 中每个节点只有一个左子节点。 在这种情况下，堆栈不断增长并且不会发生弹出。 某些实现错误地假设堆栈弹出始终是必要的，但该算法正确地处理纯左偏树。 

当序列在进入右子树后不正确地返回到较小的值时，会出现一种特别棘手的情况，例如`[5,2,6,1]`。 一次`6`被处理后，我们知道我们在右子树中`5`。 价值`1`违反了下限要求。 该实现立即使用以下方法检测到这一点`lower_bound`查看。
