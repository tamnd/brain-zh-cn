[LeetCode 第 257 题](https://leetcode.com/problems/binary-tree-paths/)

 **难度：** 🟢简单
 **主题：** 字符串、回溯、树、深度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 该问题要求我们返回从二叉树的根到每个叶节点的每条路径。 从根节点开始，不断向下穿过子节点，直到到达没有子节点的节点，从而形成根到叶路径。 

输入是二叉树的根节点。 每个节点都包含一个整数值以及指向其左子节点和右子节点的指针。 该树可以包含 1 到 100 个节点，节点值的范围为 -100 到 100。 

输出应该是一个字符串列表，其中每个字符串代表一个完整的根到叶路径。 沿路径的值使用以下连接`"->"`分隔符。 例如，从节点的路径`1`到节点`2`到节点`5`变成`"1->2->5"`。 

一个关键细节是仅应包含根到叶路径。 中间路径无效，除非它们终止于叶节点。 叶节点被定义为既没有左子节点也没有右子节点的节点。 

约束很小，最多只有 100 个节点，这意味着即使是递归深度优先遍历也是完全安全的。 由于每个节点都可能出现在输出路径中，因此任何有效的解决方案都需要至少访问所有节点一次。 

尽早识别一些边缘情况很重要：

 - 只有一个节点的树应该返回仅包含该节点值的单个路径。 
- 树木可能完全向左或完全向右倾斜，从而创建具有最大可能深度的路径。 
- 节点值可以为负数，因此路径构造必须正确地将负数处理为字符串。 
- 某些节点可能只有一个子节点，这意味着遍历逻辑不能假设两个子节点都存在。 

## 方法

 ### 蛮力方法

 暴力解决方案将生成从根到每个节点的所有可能路径，然后仅过滤掉以叶节点结束的路径。 一种方法是在遍历过程中重复复制当前路径列表并存储遇到的每个部分路径。 

这是有效的，因为每个可能的根到节点路径都被探索，保证最终发现所有根到叶路径。 但是，它会执行不必​​要的工作，因为仍会临时构建和存储不以叶结尾的路径。 

此外，在每次递归调用时重复复制路径数组或字符串会带来额外的开销。 尽管约束足够小，这仍然可以通过，但这不是最干净或最有效的策略。 

### 最佳方法

 最佳解决方案使用带有回溯的深度优先搜索。 关键的观察结果是，根到叶路径自然对应于 DFS 中的遍历路径。 

当我们递归地沿着树向下移动时，我们保持当前路径。 当我们到达叶节点时，我们知道当前路径是完整的，因此我们将其转换为所需的字符串格式并将其添加到答案中。 

这种方法避免了不必要的工作，因为路径仅在到达叶子时才最终确定。 每个节点只被访问一次，使得遍历高效且简单。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(N²) | O(N²) | 遍历过程中重复复制部分路径 |
 | 最佳| O(N²) | O(N) | 带回溯的DFS，每个节点访问一次 |

 在最坏的情况下，时间复杂度变为 O(N²)，因为构造输出字符串需要复制路径内容，特别是在路径长度接近 N 的倾斜树中。 

## 算法演练

 1. 从根节点开始深度优先遍历。 

我们使用 DFS 是因为每条从根到叶的路径自然对应于树中的一个遍历分支。 DFS 允许我们在转向另一条路径之前完全探索一条路径。 
2. 维护一个代表当前路径的列表。 

当我们访问节点时，我们将当前节点的值附加到路径列表中。 该列表始​​终表示从根节点到当前节点的确切节点序列。 
3. 检查当前节点是否为叶子节点。 

如果一个节点的左子节点和右子节点都是叶节点`None`。 当我们到达叶子时，当前路径是完整且有效的。 
4. 将路径转换为所需的字符串格式。 

我们将路径值转换为字符串并使用`"->"`。 这会产生所需的输出表示。 
5. 将完成的路径存储在结果列表中。 

每次遇到叶节点时，我们都会将构建的路径字符串添加到最终答案中。 
6. 递归遍历左子树。 

如果存在左子节点，则继续 DFS，同时保留当前路径状态。 
7. 递归遍历右子树。 

如果存在右孩子，则继续类似的DFS。 
8.处理完children后回溯。 

在返回父调用之前从路径列表中删除当前节点。 这确保路径列表正确反映同级分支的遍历状态。 

### 为什么它有效

 该算法保持了不变式`path`列表始终包含从根节点到当前节点的节点值的精确序列。 DFS 保证每条从根到叶的路径都被恰好探索一次。 当到达叶子时，存储的路径因此是有效的根到叶子路径，并且因为访问了每个叶子，所以所有有效路径都包含在最终答案中。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import List, Optional

class Solution:
    def binaryTreePaths(self, root: Optional[TreeNode]) -> List[str]:
        result = []

        def dfs(node: TreeNode, path: List[str]) -> None:
            path.append(str(node.val))

            # Leaf node
            if not node.left and not node.right:
                result.append("->".join(path))
            else:
                if node.left:
                    dfs(node.left, path)

                if node.right:
                    dfs(node.right, path)

            # Backtrack
            path.pop()

        dfs(root, [])
        return result
```解决方案首先初始化一个空的`result`将存储所有完整路径字符串的列表。 

嵌套的`dfs`函数执行递归深度优先遍历。 它接受当前节点和当前路径列表。 

在每次调用开始时，当前节点的值都会附加到路径中。 这保持了路径列表始终表示从根开始的当前遍历路线的不变量。 

然后算法检查该节点是否是叶子。 如果两个孩子都不存在，则当前路径是完整的。 这些值连接在一起`"->"`并添加到结果列表中。 

如果该节点不是叶节点，则递归会继续到任何现有的子节点。 

最后，`path.pop()`执行回溯。 这会在返回父调用之前删除当前节点，以便路径对于将来的遍历分支保持正确。 

由于递归只探索每个根到叶分支一次，因此会收集所有有效路径。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */

import "strconv"
import "strings"

func binaryTreePaths(root *TreeNode) []string {
    result := []string{}

    var dfs func(node *TreeNode, path []string)

    dfs = func(node *TreeNode, path []string) {
        path = append(path, strconv.Itoa(node.Val))

        // Leaf node
        if node.Left == nil && node.Right == nil {
            result = append(result, strings.Join(path, "->"))
            return
        }

        if node.Left != nil {
            dfs(node.Left, path)
        }

        if node.Right != nil {
            dfs(node.Right, path)
        }
    }

    dfs(root, []string{})
    return result
}
```Go 解决方案遵循与 Python 版本相同的 DFS 策略。 主要区别在于切片在 Go 中的行为方式。 

而不是显式回溯`pop`, Go 切片按值作为切片头传递。 追加会为递归调用创建一个新的切片状态，因此单独的遍历分支不会相互干扰。 

节点值使用以下命令转换为字符串`strconv.Itoa`，并使用连接完成的路径`strings.Join`。 

使用 Nil 检查代替 Python 的检查`None`。 

## 工作示例

 ### 示例 1

 输入：```
root = [1,2,3,null,5]
```树结构：```
      1
     / \
    2   3
     \
      5
```遍历过程：

 | 步骤| 当前节点| 当前路径| 行动|
 | --- | --- | --- | --- |
 | 1 | 1 | [“1”]| 继续 DFS |
 | 2 | 2 | [“1”，“2”] | 继续 DFS |

 | 4 | 3 | [“1”，“3”] | 找到叶子，添加`"1->3"`|

 最终结果：```
["1->2->5", "1->3"]

```## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(N²) | 每个节点都会被访问一次，但在倾斜树中创建路径字符串可能会花费 O(N) |
 | 空间| O(N) | 递归调用栈和当前路径存储|

 DFS 遍历本身是线性的，因为每个节点只处理一次。 但是，构建路径字符串需要复制字符。 在完全倾斜的树的最坏情况下，可能有 O(N) 条长度为 O(N) 的路径，从而产生 O(N²) 总字符串构建工作。 

由于递归深度和当前路径列表，辅助空间复杂度为 O(N)。 在平衡树中，递归深度更接近 O(log N)，但最坏情况的倾斜树需要 O(N) 堆栈空间。

 ## 边缘情况

 单节点树是最重要的边缘情况之一。 由于根也是叶子，因此算法必须立即识别出路径是完整的。 一些不正确的实现尝试在检查叶条件之前递归，这可能导致丢失唯一有效的路径。 此实现在将节点添加到路径后立即正确检查叶子。 

倾斜的树是另一个重要的例子。 行为类似于链表的树可以创建等于节点数的递归深度。 在这些场景中经常出现不正确的回溯逻辑，因为没有兄弟分支来暴露路径损坏错误。 该实现通过在返回之前始终从路径中删除当前节点来避免此问题。 

包含负值的树也会引入微妙的格式错误。 由于输出格式是基于字符串的，因此算法必须正确转换整数而不丢失负号。 使用`str(node.val)`在Python和`strconv.Itoa(node.Val)`在 Go 中保证负数被正确表示。 

仅具有一个子节点的节点是另一个常见的错误来源。 某些实现错误地假设两个子级都存在并尝试不必要的递归。 该解决方案在递归之前显式检查每个子节点是否存在，确保稀疏树的遍历保持正确。
