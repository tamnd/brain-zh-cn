[LeetCode 第 212 题](https://leetcode.com/problems/word-search-ii/)

 **难度：** 🔴难
 **主题：** 数组、字符串、回溯、Trie、矩阵

 ## 解决方案

 ## 问题理解

 LeetCode 212，LeetCode Word Search II，要求我们从给定的字典中查找可以在 2D 字符网格内形成的每个单词。 每个单词必须通过水平或垂直移动一个单元格来构建。 不允许对角线移动，并且板单元不能在同一字结构中重复使用。 

输入由两部分组成。 第一个是`m x n`矩阵称为`board`，其中每个单元格都包含一个小写英文字母。 第二个是候选字符串列表，称为`words`。 任务是根据移动规则返回棋盘上实际可以组成的每一个单词。 

重要的细节是我们不是在搜索任何一个单词。 我们可能需要搜索最多`3 * 10^4`单词，每个单词的长度可达`10`。 电路板本身可以有这么大`12 x 12`，这意味着最多可以有`144`起始位置。 

独立搜索每个单词的简单实现很快就会变得过于昂贵。 如果我们分别对每个单词执行完整的 DFS，我们将重复遍历所有相同的前缀。 关键的挑战是避免重复工作。 

一些边缘情况很重要：

 - 多个单词可以共享前缀，例如`"eat"`和`"eater"`，因此前缀重用对于效率至关重要。 
- 在一条 DFS 路径中不能重新访问同一单元，这意味着我们必须仔细管理访问状态。 
- 有些单词可能根本不存在，算法必须有效终止，而不探索不必要的路径。 
- 棋盘可能包含许多重复的字符，导致天真的回溯组合爆炸。 
- 该问题保证所有单词都是唯一的，这稍微简化了重复处理，尽管同一个单词仍然可以从多个路径中发现。 

## 方法

 ### 蛮力方法

 暴力解决方案独立搜索每个单词。 对于每个单词，我们都会迭代每个棋盘单元，并在第一个字符匹配时启动 DFS。 在 DFS 过程中，我们递归地探索相邻单元格，同时检查当前路径是否仍然与目标单词匹配。 

这是可行的，因为 DFS 探索了可以构造单词的所有有效路径。 如果任何路径与整个单词匹配，则该单词存在于棋盘中。 

然而，这种方法会执行大量重复工作。 假设字典包含许多共享前缀的单词，例如`"oa"`,`"oat"`， 和`"oath"`。 暴力方法为每个单词分别重复遍历相同的板路径。 

在给定的约束下，复杂性变得非常大。 高达`30,000`换句话说，重复的 DFS 遍历成本太高了。 

### 最佳方法

 关键的见解是许多单词共享共同的前缀。 我们可以构建一个包含所有单词的 Trie（也称为前缀树），而不是独立搜索每个单词。 

Trie 允许我们同时探索棋盘和字典。 当我们在板上执行 DFS 时，我们同时遍历 Trie 节点。 一旦路径不再匹配任何 Trie 前缀，我们就会立即停止探索。 

这种修剪的威力非常大。 我们不会探索每个单词的每一种可能路径，而是只探索与至少一个有效字典前缀相对应的路径。 

该算法结合了：

 - 高效前缀匹配的 Trie
 - 棋盘遍历的 DFS 回溯
 - 就地访问标记以避免额外的内存开销

 这极大地减少了冗余工作，并使解决方案在约束限制下可行。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(宽×米×N×4^L) | O(L) | 独立搜索每个单词 |
 | 最佳| O(M × N × 4^L + 总单词长度) | O(总字数长度) | Trie 启用前缀修剪 |

 在哪里：

-`W`= 字数
 -`M × N`= 板尺寸
 -`L`= 最大字长

 ## 算法演练

 1. 构建一个包含所有单词的 Trie。 

每个 Trie 节点存储：

 - 下一个字符的子指针
 - 可选的完整单词标记

 我们使用 Trie 是因为它有效地表示共享前缀。 如果许多单词以相同的字符开头，则它们共享相同的 Trie 路径。 
2. 将每个单词插入 Trie 树中。 

插入字符时，根据需要创建子节点。 在每个单词的最后一个节点，存储完整的单词本身。 

在终端节点存储完整的单词可以避免在 DFS 期间重建字符串。 
3. 从每个板单元启动 DFS。 

每个单元格都可能开始一个有效单词，因此我们从每个位置启动 DFS。 
4、DFS时，检查Trie节点中是否存在当前棋盘字符。 

如果该角色不是有效的孩子，请立即停止。 这种修剪可以防止不必要的探索。 
5. 进入 Trie。 

从当前Trie节点移动到棋盘角色对应的子节点。 
6. 检查Trie节点是否完成一个单词。 

如果节点包含存储的单词，则将其添加到结果集中。 

为避免重复，请在发现后清除存储的单词。 
7. 将当前面板单元标记为已访问。 

我们暂时用哨兵值替换该字符，例如`"#"`。 

这可以防止在当前 DFS 路径期间重新访问同一单元。 
8. 探索所有四个方向。 

递归搜索：

 - 向上
 - 向下
 - 左
 - 右
 9. DFS 返回后恢复板单元。 

此回溯步骤可确保其他 DFS 路径稍后可以重用该单元。 
10.可选择修剪空的 Trie 分支。 

如果 Trie 节点在探索后没有剩余的子节点，则将其从父节点中删除。 这种优化减少了未来的 DFS 工作。 

### 为什么它有效

 该算法保持每个 DFS 路径与有效 Trie 前缀精确对应的不变式。 因此，DFS从不探索不可能的单词前缀。 由于只要 Trie 中存在前缀，就会探索每个有效的板路径，因此最终会找到所有可构造的单词。 回溯保证单元永远不会在同一路径中重复使用，同时仍然可用于将来的搜索。 

## Python 解决方案```python
from typing import List

class TrieNode:
    def __init__(self):
        self.children = {}
        self.word = None

class Solution:
    def findWords(self, board: List[List[str]], words: List[str]) -> List[str]:
        root = TrieNode()

        # Build Trie
        for word in words:
            node = root

            for char in word:
                if char not in node.children:
                    node.children[char] = TrieNode()

                node = node.children[char]

            node.word = word

        rows = len(board)
        cols = len(board[0])

        result = []

        def dfs(row: int, col: int, parent: TrieNode) -> None:
            char = board[row][col]

            if char not in parent.children:
                return

            node = parent.children[char]

            # Found a complete word
            if node.word is not None:
                result.append(node.word)
                node.word = None

            # Mark visited
            board[row][col] = "#"

            directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

            for dr, dc in directions:
                new_row = row + dr
                new_col = col + dc

                if (
                    0 <= new_row < rows
                    and 0 <= new_col < cols
                    and board[new_row][new_col] != "#"
                ):
                    dfs(new_row, new_col, node)

            # Restore board
            board[row][col] = char

            # Trie pruning optimization
            if not node.children and node.word is None:
                del parent.children[char]

        for row in range(rows):
            for col in range(cols):
                dfs(row, col, root)

        return result
```实现首先定义一个`TrieNode`班级。 每个节点包含一个子字典和一个可选的存储单词。 存储的词仅存在于终端节点。 

Trie 构建阶段逐个字符插入每个字典单词。 共享前缀自然会重用现有的 Trie 节点。 

DFS 函数执行主搜索。 它首先检查当前Trie节点中是否存在当前棋盘字符。 如果不是，搜索将立即停止，因为没有字典单词可以从此路径继续。 

当 Trie 节点包含完整单词时，该单词将被追加到结果列表中。 然后该词被设置为`None`因此可以避免重复的发现。 

通过暂时将棋盘字符替换为`"#"`。 这避免了分配单独的访问矩阵并保持空间使用效率。 

递归探索相邻单元格后，原始棋盘特征被恢复。 这是经典的回溯步骤。 

最后，Trie 剪枝优化删除耗尽的分支。 一旦 Trie 节点不再包含子节点或单词，它就变得不必要，可以将其删除以减少未来的 DFS 工作。 

## 解决方案```go
package main

type TrieNode struct {
	children map[byte]*TrieNode
	word     string
}

func newTrieNode() *TrieNode {
	return &TrieNode{
		children: make(map[byte]*TrieNode),
	}
}

func findWords(board [][]byte, words []string) []string {
	root := newTrieNode()

	// Build Trie
	for _, word := range words {
		node := root

		for i := 0; i < len(word); i++ {
			char := word[i]

			if _, exists := node.children[char]; !exists {
				node.children[char] = newTrieNode()
			}

			node = node.children[char]
		}

		node.word = word
	}

	rows := len(board)
	cols := len(board[0])

	result := []string{}

	var dfs func(int, int, *TrieNode)

	dfs = func(row int, col int, parent *TrieNode) {
		char := board[row][col]

		node, exists := parent.children[char]
		if !exists {
			return
		}

		// Found a word
		if node.word != "" {
			result = append(result, node.word)
			node.word = ""
		}

		// Mark visited
		board[row][col] = '#'

		directions := [][2]int{
			{1, 0},
			{-1, 0},
			{0, 1},
			{0, -1},
		}

		for _, dir := range directions {
			newRow := row + dir[0]
			newCol := col + dir[1]

			if newRow >= 0 &&
				newRow < rows &&
				newCol >= 0 &&
				newCol < cols &&
				board[newRow][newCol] != '#' {

				dfs(newRow, newCol, node)
			}
		}

		// Restore board
		board[row][col] = char

		// Trie pruning
		if len(node.children) == 0 && node.word == "" {
			delete(parent.children, char)
		}
	}

	for row := 0; row < rows; row++ {
		for col := 0; col < cols; col++ {
			dfs(row, col, root)
		}
	}

	return result
}
```Go 实现密切反映了 Python 逻辑，但一些特定于语言的差异值得注意。 

Go 没有具有隐式插入语义的 Python 字典，因此我们在创建子节点之前显式检查子节点是否存在。 

Go 中的字符串是不可变的，但按字节索引非常高效，因为输入仅包含小写英文字母。 

而不是使用`None`为了指示不存在存储的单词，Go 使用空字符串`""`。 

DFS 函数是作为闭包实现的，因此它可以自然地访问共享变量，例如`result`,`rows`， 和`cols`。

 ## 边缘情况

 当多个单词共享前缀时，会出现一种重要的边缘情况。 例如，像这样的词`"art"`,`"artist"`， 和`"arts"`Trie 中部分重叠。 简单的实现可能会多次冗余地搜索相同的板区域。 基于 Trie 的解决方案可以自然地处理这个问题，因为共享前缀重用相同的 Trie 路径。 

另一个关键的边缘情况涉及棋盘上的重复字符。 考虑一个充满了`"a"`字符和单词，如`"aaaa"`。 如果没有正确的访问跟踪，DFS 可能会错误地多次重复使用同一单元。 该实现通过临时标记单元格来防止这种情况发生`"#"`在探索过程中。 

第三个重要的边缘情况是起始位置不存在有效前缀时。 如果没有 Trie 剪枝，DFS 仍然会探索许多不必要的路径。 在这个解决方案中，如果Trie节点中不存在当前棋盘字符，DFS会立即终止，从而大大减少了无用的工作。 

当可以通过多个路径发现同一个单词时，就会出现最后一个微妙的边缘情况。 由于该问题需要唯一的输出字，因此必须防止重复添加。 实现通过清除来处理这个问题`node.word`在第一次成功发现之后。
