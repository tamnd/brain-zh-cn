[LeetCode 第 230 题](https://leetcode.com/problems/kth-smallest-element-in-a-bst/)

 **难度：** 🟡 中等
 **主题：** 树、深度优先搜索、二叉搜索树、二叉树

 ## 解决方案

 ## 问题理解

 这个问题给了我们二叉搜索树（缩写为 BST）的根，以及一个整数`k`。 我们需要返回`kth`树中的最小值。 

二叉搜索树有一个非常重要的属性：

 - 左子树中的每个值都小于当前节点。 
- 右子树中的每个值都大于当前节点。 

由于这种排序属性，如果我们以称为中序遍历的特定顺序遍历树，则值会按升序排列。 

问题本质上是在问：

 >“如果你将 BST 中的所有节点值收集到一个排序列表中，那么结果会怎样？`kth`元素是？”

 例如，考虑这个 BST：```
    3
   / \
  1   4
   \
    2
```其中序遍历为：```
[1, 2, 3, 4]
```如果`k = 1`，答案是`1`。 

如果`k = 3`，答案是`3`。 

这些约束告诉我们一些有用的信息：

 - 该树至少包含一个节点。 
-`k`总是有效的，意思是`1 <= k <= n`。 
- 最大节点数为`10^4`，它足够大，以至于低效的重复排序方法是不可取的。 
- 节点值是非负整数。 

该问题保证输入树是有效的 BST，因此我们不需要自己验证 BST 的正确性。 

一些边缘情况很重要：

 - 一棵只有一个节点的树。 
- 完全倾斜的树，其行为类似于链表。 
-`k = 1`，我们想要最小的元素。 
-`k = n`，我们想要最大的元素。 
- 高度不平衡树中的深度递归遍历。 

这些情况可能会暴露遍历顺序或停止条件方面的问题。 

## 方法

 ### 蛮力方法

 最简单的解决方案是遍历整棵树，将每个节点值收集到一个数组中，对数组进行排序，然后返回`kth`最小元素。 

步骤是：

 1. 执行树的任意遍历。 
2. 将所有节点值存储在列表中。 
3. 对列表进行排序。 
4. 返回`values[k - 1]`。 

这是可行的，因为排序保证了升序，无论树是如何遍历的。 

然而，这种方法完全忽略了 BST 属性。 BST 已经包含有序结构，因此再次排序是不必要的工作。 

排序步骤成本`O(n log n)`时间，比必要的要慢。 

### 最佳方法

 关键的观察结果是 BST 的中序遍历自然会按升序顺序访问节点。 

中序遍历顺序为：

 1. 访问左子树
 2. 访问当前节点
 3. 访问右子树

 由于 BST 节点是相对于其子树排序的，因此这种遍历会自动生成排序值。 

我们可以在遍历时计算节点数，而不是存储每个值。 一旦我们访问`kth`节点，我们立即返回它的值。 

这提高了效率，因为：

 - 我们完全避免排序。 
- 一旦找到答案，我们可以提前终止。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n log n) | O(n log n) | O(n) | 收集所有值并对它们进行排序 |
 | 最佳| 平均 O(h + k)，最坏 O(n) | O(h) | 提前停止的中序遍历 |

 这里，`h`代表树的高度。 

## 算法演练

 ### 最优中序遍历算法

 1. 初始化一个计数器来跟踪中序遍历期间访问了多少个节点。 

由于中序遍历按排序顺序访问节点，因此第一个访问的节点是最小的，第二个访问的节点是第二小的，依此类推。 
2、从根开始递归中序遍历。 

对于每个节点：

 - 首先遍历左子树，因为那里存在较小的值。 
- 处理左子树之后的当前节点。 
- 最后遍历右子树，因为那里存在较大的值。 
3. 当访问当前节点时，递增计数器。 

这告诉我们到目前为止我们已经看到了多少个排序元素。 
4. 检查计数器是否等于`k`。 

如果是的话，我们就达到了`kth`最小的元素，因此立即存储并返回其值。 
5. 一旦找到答案就尽早停止遍历。 

定位到目标节点后无需继续探索树。 

### 为什么它有效

 正确性直接来自 BST 属性。 

对于每个节点：

 - 左子树中的所有值都较小。 
- 右子树中的所有值都较大。 

中序遍历总是访问：```
left subtree -> node -> right subtree
```因此，节点是严格按升序访问的。 这`kth`访问过的节点必须是`kth`树中的最小元素。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional

class Solution:
    def kthSmallest(self, root: Optional[TreeNode], k: int) -> int:
        self.count = 0
        self.answer = -1

        def inorder(node: Optional[TreeNode]) -> None:
            if not node or self.answer != -1:
                return

            inorder(node.left)

            self.count += 1

            if self.count == k:
                self.answer = node.val
                return

            inorder(node.right)

        inorder(root)

        return self.answer
```实现直接遵循中序遍历策略。 

我们维护两个实例变量：

 -`self.count`，跟踪已访问的节点数量。 
-`self.answer`，存储找到后的最终结果。 

递归辅助函数执行中序遍历。 

基本情况在以下情况下停止递归：

 - 节点是`None`——答案已经找到了

 首先遍历左子树可以保证在当前节点之前处理较小的值。 

从左子树返回后，我们增加计数器，因为当前节点现在按排序顺序被访问。 

什么时候`self.count == k`，我们发现了`kth`最小元素并将其存储在`self.answer`。 

然后遍历会提前退出以避免不必要的工作。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */

func kthSmallest(root *TreeNode, k int) int {
    count := 0
    answer := -1

    var inorder func(node *TreeNode)

    inorder = func(node *TreeNode) {
        if node == nil || answer != -1 {
            return
        }

        inorder(node.Left)

        count++

        if count == k {
            answer = node.Val
            return
        }

        inorder(node.Right)
    }

    inorder(root)

    return answer
}
```Go 解决方案密切反映了 Python 实现。 

Go 使用递归闭包捕获的局部变量，而不是实例变量。 

Go 使用`nil`而不是Python的`None`。 

递归函数是使用函数变量声明的，因此它可以递归地调用自身。 

由于问题保证存在有效答案，因此返回`-1`仅用作占位符初始化值。 

## 工作示例

 ### 示例 1```

```树：```
    3
   / \
  1   4
   \

```中序遍历顺序：```
1 -> 2 -> 3 -> 4
```遍历过程：

 | 步骤| 当前节点| 计数| 回答 |

 | 1 | 访问 1 | 1 | 1 |
 | 2 | 早点停下来| 1 | 1 |

 自从`k = 1`，第一个访问的节点就是答案。

```## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | 平均 O(h + k)，最坏 O(n) | 我们按排序顺序访问节点，直到到达第 k 个元素 |
 | 空间| O(h) | 递归调用堆栈深度等于树高 |

 在平衡 BST 中，高度为`O(log n)`，因此递归深度仍然很小。 

在最坏的情况下，BST 可能会完全倾斜，使得高度`O(n)`。 

仅访问后遍历可能会提前停止`k`节点，这就是为什么平均运行时间通常比遍历整个树更好。

 ## 边缘情况

 单节点树是最小的有效输入。 这种情况可能会暴露出遍历假设左或右子节点存在的错误。 该实现正确地处理了这个问题，因为递归函数在遇到`None`或者`nil`。 

完全倾斜的树的行为类似于链表，而不是平衡的 BST。 递归深度变大，遍历顺序就变得尤为重要。 该算法仍然有效，因为无论树的形状如何，中序遍历仍然有效。 

什么时候`k = n`，算法必须找到 BST 中最大的元素。 这需要遍历几乎整棵树。 一些不正确的实现停止得太早或在遍历结束时错误地处理计数逻辑。 我们的实现在每个访问的节点上精确地递增计数器一次，从而保证准确的排序。 

另一种微妙的边缘情况发生在`k = 1`。 在这种情况下，答案就是 BST 中最左边的节点。 早期停止优化在这里很重要，因为它可以防止在找到最小值后对剩余树进行不必要的遍历。
