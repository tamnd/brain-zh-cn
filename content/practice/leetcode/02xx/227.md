[LeetCode 第 227 题](https://leetcode.com/problems/basic-calculator-ii/)

 **难度：** 🟡 中等
 **主题：** 数学、字符串、堆栈

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个表示数学表达式的字符串，其中包含非负整数、空格和四个运算符`+`,`-`,`*`， 和`/`。 我们的任务是计算表达式并返回结果整数值。 

重要的细节是乘法和除法必须遵循正常的算术优先规则。 这意味着`*`和`/`必须先评估`+`和`-`。 除法向零截断，这符合问题陈述而不是浮点除法预期的行为。 

例如，表达式`"3+2*2"`应该评估为`7`， 不是`10`，因为乘法发生在加法之前。 乘法`2*2`首先被评估，产生`4`， 然后`3+4`给出`7`。 

输入字符串可以在标记之间的任意位置包含空格。 这些空格在解析过程中应该被忽略。 该表达式保证有效，这简化了实现，因为我们不需要处理格式错误的输入情况，例如连续运算符或丢失操作数。 

限制因素很重要。 字符串长度可以大到`3 * 10^5`，这意味着任何低效的解析策略都可能变得太慢。 我们需要一种能够单遍或接近单遍处理表达式的算法。 二次解不会扩展到最大输入大小。 

有几种边缘情况很容易引入错误：

 - 在任意位置带有空格的表达式，例如`" 3+5 / 2 "`- 多位数字，例如`"123+456"`- 以数字结尾的表达式，其中最终挂起的操作仍必须处理
 - 涉及负中间结果的除法，其中向零截断很重要
 - 必须正确保留优先级的乘法和除法运算符序列

 该问题保证所有中间结果都适合有符号的 32 位整数，因此不需要溢出处理。 

## 方法

 暴力方法首先将表达式标记为数字和运算符，然后重复扫描表达式以根据优先级规则评估运算符。 一次可以解决所有乘法和除法，然后另一次可以解决加法和减法。 

这种方法是正确的，因为它明确地模拟了标准算术评估顺序。 然而，如果简单地使用重复的列表修改或字符串重建来实现，它可能会变得低效。 在最坏的情况下，重复从数组中删除元素可能会导致二次行为。 

最佳解决方案的关键见解是我们实际上不需要构建完整的表达式树或重复重新处理输入。 由于乘法和除法的优先级高于加法和减法，因此我们可以从左到右处理字符串，同时维护中间值堆栈。 

每当我们遇到：

 -`+`，我们将当前数字压入堆栈
 -`-`，我们推送当前数字的负版本
 -`*`，我们弹出前一个数字，将其与当前数字相乘，然后将结果推回
 -`/`，我们弹出前一个数字，将其除以当前数字并截断为零，然后将结果推回

 最后，对堆栈求和会产生正确的答案，因为所有乘法和除法运算都已立即解决。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 反复扫描、修改表达式 |
 | 最佳| O(n) | O(n) | 使用堆栈强制执行优先级的单遍 |

 ## 算法演练

 1.初始化一个空栈，一个变量`current_number`设置为`0`，和一个变量`previous_operator`初始化为`'+'`。 

堆栈将存储准备稍后求和的数字。 这`previous_operator`告诉我们一旦遇到下一个运算符，当前的数字应该如何处理。 
2. 逐个字符地遍历字符串。 

我们从左到右扫描一次表达式。 这保证了线性时间复杂度。 
3. 如果当前字符是数字，则构建完整的数字。 

由于数字可能包含多个数字，我们更新：```
current_number = current_number * 10 + digit
```这使我们能够正确解析值，例如`123`。 
4. 如果当前字符是运算符或者我们已经到达最后一个字符，则处理之前累加的数字。 

在此刻，`current_number`代表与关联的操作数`previous_operator`。 
5. 应用之前的运算符：

 - 如果`previous_operator`是`'+'`， 推`current_number`到堆栈上
 - 如果`previous_operator`是`'-'`， 推`-current_number`- 如果`previous_operator`是`'*'`，弹出顶部值，将其乘以`current_number`，并推送结果
 - 如果`previous_operator`是`'/'`，弹出顶部值，将其除以`current_number`使用向零截断，并将结果压入

 这是可行的，因为乘法和除法应该在考虑较低优先级操作之前立即发生。 
6. 更新`previous_operator`到当前操作员并重置`current_number`到`0`。 

这为我们解析下一个数字做好了准备。 
7. 处理整个字符串后，对堆栈中的所有值求和。 

通过在堆栈中存储有符号值来延迟加法和减法。 因此，对堆栈求和会产生最终结果。 

### 为什么它有效

 核心不变量是堆栈始终包含已经完全解析乘法和除法的值。 加法和减法简单地表示为等待稍后求和的有符号数。 由于遇到乘法和除法时会立即处理，因此在从左到右的单次传递中可以正确保留运算符优先级。 

## Python 解决方案```python
class Solution:
    def calculate(self, s: str) -> int:
        stack: list[int] = []
        current_number = 0
        previous_operator = "+"

        for i, char in enumerate(s):
            if char.isdigit():
                current_number = current_number * 10 + int(char)

            if char in "+-*/" or i == len(s) - 1:
                if previous_operator == "+":
                    stack.append(current_number)

                elif previous_operator == "-":
                    stack.append(-current_number)

                elif previous_operator == "*":
                    stack.append(stack.pop() * current_number)

                elif previous_operator == "/":
                    previous_value = stack.pop()
                    stack.append(int(previous_value / current_number))

                previous_operator = char
                current_number = 0

        return sum(stack)
```该实现遵循前面描述的确切算法。 

堆栈存储准备用于最终求和的中间值。 加法和减法只是推动正数或负数。 乘法和除法立即与先前的堆栈值结合，确保遵守运算符优先级。 

变量`current_number`用于在扫描字符串时构造多位整数。 每个数字都会增量更新数字。 

条件：```python
if char in "+-*/" or i == len(s) - 1:
```确保每当我们到达运算符或字符串末尾时都会进行处理。 这个最终条件很重要，因为表达式总是以数字而不是运算符结尾。 

对于除法，表达式：```python
int(previous_value / current_number)
```正确地截断为零，满足问题要求。 

最后，对堆栈求和产生完整的评估结果。 

## 解决方案```go
func calculate(s string) int {
    stack := []int{}
    currentNumber := 0
    previousOperator := '+'

    for i := 0; i < len(s); i++ {
        char := s[i]

        if char >= '0' && char <= '9' {
            currentNumber = currentNumber*10 + int(char-'0')
        }

        if (char < '0' || char > '9') && char != ' ' || i == len(s)-1 {

            switch previousOperator {

            case '+':
                stack = append(stack, currentNumber)

            case '-':
                stack = append(stack, -currentNumber)

            case '*':
                lastValue := stack[len(stack)-1]
                stack = stack[:len(stack)-1]
                stack = append(stack, lastValue*currentNumber)

            case '/':
                lastValue := stack[len(stack)-1]
                stack = stack[:len(stack)-1]
                stack = append(stack, lastValue/currentNumber)
            }

            previousOperator = rune(char)
            currentNumber = 0
        }
    }

    result := 0

    for _, value := range stack {
        result += value
    }

    return result
}
```Go 实现密切反映了 Python 逻辑，但存在一些特定于语言的差异。 

Go 使用切片而不是 Python 列表。 从堆栈中删除顶部元素需要切片：```go
stack = stack[:len(stack)-1]
```Go 整数除法已经向零截断，因此除法不需要额外的转换。 

字符被处理为字符串中的字节，数字解析是使用 ASCII 算术手动完成的：```go
int(char - '0')
```与 Python 不同，Go 不提供内置方法，例如`isdigit()`，因此改用字符比较。

 ## 边缘情况

 一种重要的边缘情况是表达式在不可预测的位置包含许多空格。 天真的解析器可能会错误地将空格解释为有意义的字符，或者无法正确处理最终的数字。 此实现自然会忽略空格，因为仅在遇到运算符或数字时才会进行处理。 

另一个重要的边缘情况是多位数。 如果算法独立处理每个数字，则像这样的输入`"123+45"`会被错误地解释。 该实现通过使用以下方法不断构建当前数字来避免这种情况：```
current_number = current_number * 10 + int(char)
```无论数字长度如何，这都会保留完整的数值。 

第三个关键边缘情况涉及具有负中间结果的除法。 不同语言对负数的整数除法的处理方式有所不同。 该问题需要向零截断，而不是向下除法。 在Python中，使用：```
int(previous_value / current_number)
```确保结果正确地截断为零。 

另一个微妙的情况发生在字符串的末尾。 由于表达式以数字而不是运算符结尾，因此如果我们只对运算符做出反应，则最终的数字将永远不会被处理。 条件：```
or i == len(s) - 1
```确保始终应用最后一个挂起的操作。
