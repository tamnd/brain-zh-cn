[LeetCode 第 218 题](https://leetcode.com/problems/the-skyline-problem/)

 **难度：** 🔴难
 **主题：** 数组、分而治之、二叉索引树、线段树、扫描线、排序、堆（优先级队列）、有序集

 ## 解决方案

 ## 问题理解

 天际线问题要求我们计算从远处观看时由一组矩形建筑物形成的可见外部轮廓。 每个建筑物由三个整数表示：左 x 坐标、右 x 坐标和高度。 建筑物坐落在地面上，这被认为是高度`0`。 

输出不是完整的形状本身，而是使用“关键点”的天际线的紧凑表示。 关键点是天际线高度变化的位置。 例如，如果天际线从高处升起`10`到高度`15`在`x = 3`， 然后`[3, 15]`是一个关键点。 同样，当建筑物结束并且天际线下降时，这种下降也会创建一个关键点。 

挑战在于建筑物可能会以多种方式重叠：

 - 较高的建筑物可以完全隐藏较低的建筑物
 - 多个建筑物可以在相同的 x 坐标处开始或结束
 - 建筑物可能部分重叠
 - 几座相邻的建筑物可能具有相同的高度

 最终的天际线不得包含多余的水平线段。 如果天际线在多个间隔内保持相同高度，则它应显示为单个连续线段。 

输入约束很重要：

 - 最多`10^4`建筑物
 - 坐标和高度可以大到`2^31 - 1`- 建筑物已按起始坐标排序

 这些约束立即排除了跨每个 x 坐标的简单几何模拟。 坐标范围很大，因此我们无法构建代表每个可能的 x 位置的密集数组。 

一些边缘情况尤其重要：

 - 起始和结束位置相同的建筑物
 - 多个具有相同高度的建筑物
 - 建筑物完全包含在较高的建筑物内
 - 相邻建筑物高度相等，应合并为一个部分
 - 事件发生在同一 x 坐标，其中处理顺序很重要

 正确的解决方案必须仔细管理重叠高度，并确保仅当可见最大高度真正发生变化时才会发出天际线变化。 

## 方法

 ### 蛮力方法

 一种简单的方法是模拟每个 x 坐标的高度。 我们可以确定覆盖每个坐标的所有建筑物的最大高度，然后将所得高度剖面压缩为天际线关键点。 

从概念上讲，这是可行的，因为任何位置的天际线都是该点最高的活动建筑。 

然而，这种方法变得不切实际，因为坐标可能非常大，最多可达`2^31 - 1`。 即使我们压缩坐标，根据每个间隔检查每个建筑物仍然会很昂贵。 

另一种暴力破解的变体是：

 1. 从建筑物边界收集所有唯一的 x 坐标
 2. 对于连续 x 值之间的每个间隔，确定最大建筑物高度
 3. 从这些高度生成天际线过渡

 这改善了坐标问题，但仍然需要重复扫描许多建筑物。 

蛮力方法是正确的，因为它显式地计算各处的可见高度，但对于问题约束来说太慢了。 

### 最优方法，使用最大堆扫描线

 关键的观察结果是天际线仅在建筑物边界处发生变化。 

在两个连续事件点之间，天际线高度保持不变。 因此，我们只需要处理构建开始和结束事件，而不是检查每个 x 坐标。 

这自然导致了扫线算法：

 - 沿 x 轴从左向右扫描
 - 当我们遇到建筑物的左边缘时添加建筑物
 - 当我们遇到建筑物的右边缘时将其移除
 - 维护当前最高的活跃建筑

 为了随时有效地检索最高的活动建筑物，我们使用最大堆。 

该堆存储按高度排序的活动建筑物。 随着扫描线移动：

 - 插入新建筑物
 - 过期的建筑物会被懒惰地移除
 - 堆顶始终代表可见的天际线高度

 每当最大高度发生变化时，我们都会记录一个新的天际线关键点。 

这种方法很有效，因为每个建筑物最多插入和删除一次，并且堆操作是对数的。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 跨时间间隔反复扫描建筑物 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 活动建筑的最大堆扫线 |

 ## 算法演练

 ### 第 1 步：将建筑物转变为活动

 对于每栋建筑`[left, right, height]`，创建两个事件：

 - 开始活动于`left`- 结束活动于`right`我们按 x 顺序处理这些事件，因为天际线仅在建筑物边界发生变化。 

例如：```
[2,9,10]
```变成：```
start at x=2 with height=10
end at x=9
```### 第 2 步：仔细对事件进行排序

 相同 x 坐标的排序非常重要。 

我们代表：

 - 以负高度开始活动
 - 以正高度结束赛事

 这会自动创建正确的排序行为：

 - 在较短的开始之前处理较高的开始
 - 在结束之前开始处理
 - 较短的末端先于较高的末端处理

 这可以防止临时错误的天际线过渡。 

### 步骤 3：维护具有最大堆的活动建筑

 堆存储当前活动的建筑物。 

每个堆条目包含：```
(-height, right_edge)
```我们使用负高度是因为 Python`heapq`是最小堆，因此负值模拟最大堆。 

堆顶始终代表最高的可见建筑物。 

### 步骤 4：在开始事件中添加建筑物

 当遇到启动事件时：

 - 将建筑物推入堆中
 - 建筑物立即投入使用

 ### 步骤 5：延迟删除过期的建筑物

 当扫描线到达x坐标时`x`，一些建筑物可能已经结束了。 

我们不是在结束事件发生时立即删除它们，而是延迟删除它们：

 - 虽然堆顶有`right_edge <= x`- 从堆中弹出它

 这是有效的，因为在任何时候只有最高的活跃建筑才重要。 

延迟删除避免了昂贵的任意堆删除。 

### 第 6 步：检测天际线变化

 处理位置事件后`x`：

 - 当前的天际线高度是堆顶
 - 如果此高度与之前的高度不同
 - 追加新的关键点

 这确保我们只记录实际的天际线过渡。 

### 步骤 7：继续，直到处理完所有事件

 处理完所有事件后：

 - 堆最终变空
 - 天际线恢复高度`0`- 自动添加最终终止点

 ### 为什么它有效

 该算法保持堆始终包含所有当前活动建筑物的不变量，并且堆顶始终表示当前扫描位置处最高的可见建筑物。 

由于天际线变化只能发生在建筑物边界处，因此按排序顺序处理事件可确保每个可能的高度过渡都被检查一次。 每当最大活动高度发生变化时，天际线轮廓也必须发生变化，因此记录这些过渡会产生正确的天际线。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def getSkyline(self, buildings: List[List[int]]) -> List[List[int]]:
        events = []

        for left, right, height in buildings:
            events.append((left, -height, right))
            events.append((right, 0, 0))

        events.sort()

        result = []

        # (negative_height, right_edge)
        max_heap = [(0, float('inf'))]

        previous_height = 0

        for x, neg_height, right in events:
            # Remove expired buildings
            while max_heap and max_heap[0][1] <= x:
                heapq.heappop(max_heap)

            # Add new building
            if neg_height != 0:
                heapq.heappush(max_heap, (neg_height, right))

            current_height = -max_heap[0][0]

            # Skyline changed
            if current_height != previous_height:
                result.append([x, current_height])
                previous_height = current_height

        return result
```实施首先将每个建筑物转换为两个扫描线事件。 开始事件存储负高度，以便排序自然地优先考虑同一 x 坐标处较高的建筑物。 

对所有事件进行排序后，算法从左到右扫描，同时保持活动建筑物的最大堆。 每个堆条目包含建筑物高度及其结束坐标。 

在处理新位置之前，过期的建筑物将从堆中删除。 这种惰性删除策略非常有效，因为我们只关心最高的活动建筑，它总是出现在堆顶。 

每当遇到启动事件时，建筑物就会插入堆中。 然后从堆顶确定当前的天际线高度。 

如果可见高度与之前的高度不同，则表示发生了天际线过渡，因此将向结果添加新的关键点。 

堆是用一个虚拟的地面建筑高度来初始化的`0`。 这避免了空堆边缘情况，并自然地产生最终下降到地面水平的结果。 

## 解决方案```go
package main

import (
	"container/heap"
	"sort"
)

type Event struct {
	x      int
	height int
	right  int
}

type MaxHeap [][2]int

func (h MaxHeap) Len() int {
	return len(h)
}

func (h MaxHeap) Less(i, j int) bool {
	return h[i][0] < h[j][0]
}

func (h MaxHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MaxHeap) Push(x interface{}) {
	*h = append(*h, x.([2]int))
}

func (h *MaxHeap) Pop() interface{} {
	old := *h
	n := len(old)
	item := old[n-1]
	*h = old[:n-1]
	return item
}

func getSkyline(buildings [][]int) [][]int {
	events := []Event{}

	for _, b := range buildings {
		left, right, height := b[0], b[1], b[2]

		events = append(events, Event{
			x:      left,
			height: -height,
			right:  right,
		})

		events = append(events, Event{
			x:      right,
			height: 0,
			right:  0,
		})
	}

	sort.Slice(events, func(i, j int) bool {
		if events[i].x != events[j].x {
			return events[i].x < events[j].x
		}
		return events[i].height < events[j].height
	})

	result := [][]int{}

	maxHeap := &MaxHeap{}
	heap.Init(maxHeap)

	heap.Push(maxHeap, [2]int{0, int(^uint(0) >> 1)})

	prevHeight := 0

	for _, event := range events {
		x := event.x

		for maxHeap.Len() > 0 && (*maxHeap)[0][1] <= x {
			heap.Pop(maxHeap)
		}

		if event.height != 0 {
			heap.Push(maxHeap, [2]int{event.height, event.right})
		}

		currentHeight := -(*maxHeap)[0][0]

		if currentHeight != prevHeight {
			result = append(result, []int{x, currentHeight})
			prevHeight = currentHeight
		}
	}

	return result
}
```Go 实现遵循与 Python 版本相同的算法结构，但 Go 需要使用显式堆接口实现`container/heap`。 

由于 Go 不提供内置的最大堆，因此再次使用负高度来模拟最大堆。 堆条目存储为固定大小的数组`[2]int`，其中值表示：```go
[negative_height, right_edge]
```Go 切片自然地处理事件和结果数组的动态调整大小。 整数溢出不是一个问题，因为 Go 的`int`type 可以轻松处理现代 64 位平台上的问题约束。

 | 测量 | 复杂性 | 说明|

 该算法创建`2n`事件并对它们进行排序，这需要`O(n log n)`时间。 每个建筑物最多插入和从堆中移除一次，并且每次堆操作都有成本`O(log n)`。 

堆最多可以包含`n`同时激活建筑物，并且事件列表还存储`2n`元素，因此整体空间复杂度是线性的。

 ## 边缘情况

 当多个建筑物以相同的 x 坐标开始时，就会出现一种重要的边缘情况。 如果在较高的建筑物之前处理较短的建筑物，则算法可能会错误地生成不应出现的中间天际线点。 按高度降序对开始事件进行排序可以避免此问题。 使用负高度自然会强制执行正确的排序。 

另一个棘手的情况是相邻建筑物具有相同的高度。 考虑：```
[[0,2,3],[2,5,3]]
```一个幼稚的实现可能会输出：```
[[0,3],[2,3],[5,0]]
```其中包含冗余的连续高度。 该实现通过仅在可见高度实际发生变化时附加天际线点来防止这种情况发生。 

第三个重要的边缘情况涉及完全隐藏在较高建筑物后面的建筑物。 例如：```
[[1,10,10],[2,5,5]]
```较小的建筑物永远不应该出现在天际线上。 堆结构自然地处理了这个问题，因为最高的活动建筑总是决定可见性。 即使堆中存在较小的建筑物，它也永远不会达到最大高度，因此不会产生天际线过渡。 

当建筑物的结束位置与其他建筑物的开始位置相同时，就会出现另一个微妙的问题。 正确的事件顺序在这里至关重要。 开始事件必须在同一位置的结束事件之前处理，以便天际线不会暂时下降到不正确的较低高度。 事件排序策略自动确保此行为。
