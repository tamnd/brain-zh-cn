[LeetCode 第 248 题](https://leetcode.com/problems/strobegrammatic-number-iii/)

 **难度：** 🔴难
 **主题：** 数组、字符串、递归

 ## 解决方案

 ## 问题理解

 问题要求我们统计有多少个数字在包含范围内`[low, high]`是频闪图。 

频闪数字是旋转 180 度后看起来没有变化的数字。 轮换后只有某些数字仍然有效：

 | 原创| 旋转|
 | --- | --- |
 | 0 | 0 |
 | 1 | 1 |
 | 6 | 9 |
 | 8 | 8 |
 | 9 | 6 |

 例如，`"69"`变成`"96"`旋转后，但由于整个数字在位置上翻转，旋转后的结果在视觉上仍然表示相同的数字。 所以`"69"`是频闪的。 

输入由两个字符串组成，`low`和`high`，而不是整数。 这很重要，因为数字可能最多包含 15 位数字，并且该问题要求我们仔细处理前导零和字典比较。 目标是计算每个有效的频闪图数字，其数值介于`low`和`high`，包含在内。 

约束足够小，可以生成长度之间的所有有效频闪图数`len(low)`和`len(high)`是可行的。 然而，暴力破解范围内的每个整数是完全不切实际的，因为范围可能跨越大到`10^15`。 

一些边缘情况很重要：

 - 号码`"0"`有效且必须正确计数。 
- 数字不能包含前导零，除非数字本身恰好是`"0"`。 
- 范围边界本身可能是频闪图。 
- 只允许个位数`0`,`1`， 和`8`。 
- 奇数长度的数字必须有一个有效的中心数字，该数字只能是`0`,`1`， 或者`8`。 

了解这些约束是构建高效递归生成解决方案的关键。 

## 方法

 ### 蛮力方法

 一个简单的方法是迭代每个数字`low`到`high`, convert each number into a string, rotate it digit by digit, and check whether the rotated result equals the original number.

 为了验证数字，我们可以使用映射：```
0 -> 0
1 -> 1
6 -> 9
8 -> 8
9 -> 6
```对于每个数字，我们将以相反的顺序构建旋转的字符串并将其与原始字符串进行比较。 

这种方法是正确的，因为它明确地检查范围内的每个数字。 然而，它太慢了。 范围可能很大，可能接近`10^15`, which makes iterating through every integer impossible within time limits.

 ### 最佳方法

 The key observation is that strobogrammatic numbers have a very strict structure. Instead of checking every number, we can directly generate only valid strobogrammatic numbers.

 We construct numbers recursively from the inside outward using valid digit pairs:

 | 左| 对|
 | --- | --- |
 | 0 | 0 |
 | 1 | 1 |
 | 6 | 9 |
 | 8 | 8 |
 | 9 | 6 |

 例如，如果我们已经知道`"11"`is valid, we can create larger valid numbers such as:

 -`"0110"`-`"1111"`-`"6119"`-`"8118"`-`"9116"`我们递归地生成长度之间的所有频闪图数`len(low)`和`len(high)`，然后过滤掉：

 - 带有前导零的数字
 - 超出目标范围的数字

 这极大地减少了搜索空间，因为我们只生成有效的候选者。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(N × D) | O(D) | 检查范围 | 中的每个数字
 | 最佳| O(5^(n/2)) | O(5^(n/2)) | O(n) | 仅生成有效的频闪图数字 |

 这里，`N`是范围的数字大小，`D`是位数。 在最优方法中，`n`是最大数字长度。 

## 算法演练

 1. 定义所有有效的频闪数字对。 

我们存储五个有效的旋转对：```
(0,0), (1,1), (6,9), (8,8), (9,6)
```这些数字对是唯一在 180 度旋转后仍然有效的数字。 
2. 构建递归辅助函数。 

助手生成给定长度的所有频闪字符串。 

递归是从内向外进行的。 如果我们知道所有长度有效的字符串`n - 2`，我们可以用有效的数字对包围它们来构建长度的字符串`n`。 
3. 处理基本情况。 

有两个重要的基本情况：

 - 长度`0`回报`[""]`- 长度`1`回报`["0", "1", "8"]`单位数字只能使用旋转到自身的数字。 
4. 递归构造更大的数字。 

对于每个较小的有效字符串，在前面和后面添加每个有效对。 

例子：```
inner = "1"

-> "101"
-> "111"
-> "619"
-> "818"
-> "916"
```5. 避免使用前导零。 

我们必须拒绝像这样的数字`"0110"`因为不允许使用前导零。 

然而，`"0"`本身是有效的。 

我们通过禁止配对来强制执行此操作`(0,0)`在最外层，除非整个数字长度是`1`。 
6. 生成所有相关长度的数字。 

我们为每个长度生成频闪图数：```
len(low) to len(high)
```7. 按范围过滤数字。 

生成候选人后：

 - 如果它的长度等于`len(low)`，确保它至少是`low`- 如果它的长度等于`len(high)`，保证最多是`high`8. 计算有效数字。 

剩下的每个候选人都对最终答案做出了贡献。 

### 为什么它有效

 递归结构保证了正确性，因为每个生成的数字都是由有效的旋转数字对专门形成的。 由于每个递归步骤都保留了频闪特性，因此每个生成的数字都是有效的。 相反，每个有效的频闪数字都可以分解为由允许的对之一包围的较小的有效内部子串，这意味着递归仅生成一次所有可能的有效数字。 

## Python 解决方案```python
class Solution:
    def strobogrammaticInRange(self, low: str, high: str) -> int:
        pairs = [
            ('0', '0'),
            ('1', '1'),
            ('6', '9'),
            ('8', '8'),
            ('9', '6')
        ]

        def build(length: int, total_length: int) -> list[str]:
            if length == 0:
                return [""]

            if length == 1:
                return ["0", "1", "8"]

            result = []

            for middle in build(length - 2, total_length):
                for left, right in pairs:
                    if length == total_length and left == '0':
                        continue

                    result.append(left + middle + right)

            return result

        count = 0

        for length in range(len(low), len(high) + 1):
            candidates = build(length, length)

            for num in candidates:
                if length == len(low) and num < low:
                    continue

                if length == len(high) and num > high:
                    continue

                count += 1

        return count
```实现首先定义有效的轮换数字对。 这些是构造频闪数字时唯一允许的对。 

递归`build()`函数生成特定长度的所有有效频闪字符串。 参数`total_length`是必要的，因为我们必须检测最外层的递归层以防止出现前导零。 

长度的基本情况`0`返回一个空字符串。 这是构造偶数长度的基础。 长度的基本情况`1`回报`"0"`,`"1"`， 和`"8"`因为这些是奇数长度数字的唯一有效的中间数字。 

递归步骤生成较小的有效字符串并用有效数字对包围它们。 当构建最外层时，这对`('0', '0')`被跳过以避免无效的前导零。 

生成特定长度的所有候选后，算法将每个候选与边界进行比较`low`和`high`。 由于所有被比较的字符串都具有相同的长度，因此字典比较可以正常工作。 

最后，算法返回总计数。 

## 解决方案```go
func strobogrammaticInRange(low string, high string) int {
	pairs := [][2]byte{
		{'0', '0'},
		{'1', '1'},
		{'6', '9'},
		{'8', '8'},
		{'9', '6'},
	}

	var build func(int, int) []string

	build = func(length int, totalLength int) []string {
		if length == 0 {
			return []string{""}
		}

		if length == 1 {
			return []string{"0", "1", "8"}
		}

		var result []string

		middles := build(length-2, totalLength)

		for _, middle := range middles {
			for _, pair := range pairs {
				left := pair[0]
				right := pair[1]

				if length == totalLength && left == '0' {
					continue
				}

				result = append(result,
					string(left)+middle+string(right))
			}
		}

		return result
	}

	count := 0

	for length := len(low); length <= len(high); length++ {
		candidates := build(length, length)

		for _, num := range candidates {
			if length == len(low) && num < low {
				continue
			}

			if length == len(high) && num > high {
				continue
			}

			count++
		}
	}

	return count
}
```Go 实现遵循与 Python 版本相同的递归结构。 一个显着的区别是 Go 没有元组文字，因此数字对存储为两个字节的数组。 

字符串连接需要显式地将字节转换为字符串`string(left)`和`string(right)`。 

Go 切片动态地用于存储生成的候选者。 由于最大长度仅为 15，因此递归深度仍然较小且安全。

 ## 边缘情况

 一种重要的边缘情况是前导零的处理。 在递归构造过程中，对像`('0', '0')`自然生成字符串，例如`"0110"`。 根据问题陈述，这些不是有效的数字表示。 幼稚的实现可能会意外地计算它们。 该解决方案通过明确拒绝以开头的最外层结构来避免这种情况`'0'`，同时仍然允许个位数`"0"`本身。 

另一个关键的边缘情况涉及奇数长度的数字。 在奇数长度频闪数中，旋转后中心数字必须保持不变。 仅有的`0`,`1`， 和`8`满足这个性质。 数字如`6`和`9`不能出现在中心，因为它们相互旋转。 长度的递归基本情况`1`正确限制中间选择。 

第三个微妙的边缘情况是字符串之间的字典比较。 仅当字符串具有相同长度时，按字典顺序比较数字字符串才有效。 仅当候选长度与`low`或者`high`。 这保证了正确的数字排序而无需整数转换。 

当范围跨越多个数字长度时，会出现最后的边缘情况，例如`"99"`到`"1001"`。 幼稚的实现可能会错过中间长度的数量或错误处理不同数字计数之间的比较。 该解决方案显式地为之间的每个长度生成候选者`len(low)`和`len(high)`，确保范围的完全覆盖。
