[LeetCode 第 243 题](https://leetcode.com/problems/shortest-word-distance/)

 **难度：** 🟢简单
 **主题：** 数组、字符串

 ## 解决方案

 ## 问题理解

 该问题给了我们一个名为的字符串数组`wordsDict`，以及两个不同的目标词，`word1`和`word2`。 保证两个目标词都存在于数组中的某个位置。 我们的目标是计算任意出现之间的最小距离`word1`以及任何发生`word2`。 

两个单词之间的距离定义为它们在数组中索引之间的绝对差。 例如，如果`word1`出现在索引处`3`和`word2`出现在索引处`7`，则距离为`|7 - 3| = 4`。 

输入数组表示按顺序排列的单词序列。 我们必须扫描这个序列并确定两个目标单词出现的最接近的一对位置。 

这些约束提供了有关预期解决方案效率的重要信息：

 - 数组长度可以大到`3 * 10^4`- 每个单词都很短，最多长度`10`- 两个目标词都保证存在
 -`word1 != word2`由于数组可以包含数万个元素，因此低效的二次解可能会变得不必要的缓慢。 这强烈表明我们应该以线性时间解决方案为目标。 

有几种边缘情况值得尽早识别：

 - 这两个词可能会相邻出现，产生的距离为`1`- 一个或两个单词可能出现多次
 - 最接近的一对可能不涉及任一单词的第一次出现
 - 单词可能出现在数组的开头或结尾
 - 数组可能包含许多出现之间不相关的单词

 这两个词都存在的保证简化了实现，因为我们永远不需要处理丢失的目标。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是首先收集所有索引，其中`word1`出现并且所有索引都在其中`word2`出现。 之后，我们将第一个列表中的每个索引与第二个列表中的每个索引进行比较并计算绝对距离。 

例如：

-`word1`职位：`[1, 5, 10]`-`word2`职位：`[3, 8]`我们将计算：

 -`|1 - 3|`-`|1 - 8|`-`|5 - 3|`-`|5 - 8|`-`|10 - 3|`-`|10 - 8|`然后我们返回最小值。 

这种方法是正确的，因为它明确地检查每个可能的有效对。 然而，如果这两个词出现多次，则比较次数可能会变得非常大。 在最坏的情况下，这可能接近二次行为。 

### 最佳方法

 关键的观察是我们不需要比较每对出现的情况。 

相反，当从左到右扫描数组时，我们只需要记住我们最近看到的位置`word1`以及我们最近看到的位置`word2`。 

每当我们遇到目标单词之一时，我们都会更新其最新索引。 如果我们之前已经见过另一个单词，我们会立即计算当前距离并更新最小答案。 

这是可行的，因为涉及当前出现的最短距离必须来自最近出现的另一个单词。 通过不断更新最新位置，我们可以一次有效地跟踪所有相关的候选距离。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 存储所有索引并比较每对 |
 | 最佳| O(n) | O(1) | O(1) | 使用最新看到的位置单次通过 |

 ## 算法演练

 1. 初始化两个变量来存储最近的索引`word1`和`word2`。 

这些变量以标记值开头，例如`-1`表示该词尚未见过。 
2. 初始化变量`minimum_distance`具有非常大的价值。 

该变量将存储迄今为止找到的最小距离。 
3. 使用索引从左到右遍历数组。 

在每个位置，检查当前单词。 
4. 如果当前单词匹配`word1`，更新最新索引`word1`。 

更新后检查是否`word2`已经被看到了。 如果有，计算两个索引之间的距离，并在必要时更新最小值。 
5. 如果当前单词匹配`word2`，更新最新索引`word2`。 

更新后检查是否`word1`已经被看到了。 如果有，计算距离并更新最小值。 
6. 继续扫描直到阵列末尾。 

每当目标词之一出现时，我们就可能发现更短的距离。 
7. 返回最终的最小距离。 

### 为什么它有效

 该算法在整个遍历过程中保持一个重要的不变量：

 -`index1`总是存储最近出现的`word1`-`index2`总是存储最近出现的`word2`当我们遇到一个目标单词时，与另一个单词最接近的可能配对必须涉及该另一个单词最近出现的情况。 较旧的事件总是距离较远，因为遍历是从左到右进行的。 

由于每个事件都被处理一次，并且每个候选最接近的对在遇到时都会被评估，因此该算法正确地找到了全局最小距离。 

## Python 解决方案```python
from typing import List

class Solution:
    def shortestDistance(
        self,
        wordsDict: List[str],
        word1: str,
        word2: str
    ) -> int:
        
        index1 = -1
        index2 = -1
        minimum_distance = float("inf")

        for i, word in enumerate(wordsDict):

            if word == word1:
                index1 = i

                if index2 != -1:
                    minimum_distance = min(
                        minimum_distance,
                        abs(index1 - index2)
                    )

            elif word == word2:
                index2 = i

                if index1 != -1:
                    minimum_distance = min(
                        minimum_distance,
                        abs(index1 - index2)
                    )

        return minimum_distance
```该实现遵循算法演练中描述的确切逻辑。 

变量`index1`和`index2`跟踪看到两个目标词的最新位置。 他们开始于`-1`因为这两个词一开始都没有遇到过。 

循环遍历数组一次使用`enumerate`，它提供索引和当前单词。 

每当`word1`遇到的是，`index1`已更新。 如果`word2`has already appeared earlier, we compute the distance and update the minimum answer.

 同样的逻辑对称地适用于`word2`遇到。 

使用`elif`很重要，因为这个问题保证了`word1`和`word2`是不同的。 这可以防止不必要的双重检查。 

最后，算法返回遍历过程中找到的最小距离。 

## 解决方案```go
import "math"

func shortestDistance(wordsDict []string, word1 string, word2 string) int {

	index1 := -1
	index2 := -1
	minDistance := math.MaxInt32

	for i, word := range wordsDict {

		if word == word1 {
			index1 = i

			if index2 != -1 {
				distance := index1 - index2

				if distance < 0 {
					distance = -distance
				}

				if distance < minDistance {
					minDistance = distance
				}
			}

		} else if word == word2 {
			index2 = i

			if index1 != -1 {
				distance := index1 - index2

				if distance < 0 {
					distance = -distance
				}

				if distance < minDistance {
					minDistance = distance
				}
			}
		}
	}

	return minDistance
}
```Go 的实现与 Python 解决方案非常相似。 由于 Go 没有提供内置的整数绝对值函数，因此我们手动将负距离转换为正值。 

变量`minDistance`初始化使用`math.MaxInt32`，它充当一个大的初始值。 

Go 中的切片的行为类似于动态数组，因此迭代`range`有效地提供索引和单词。 

除了几个整数变量之外，不需要额外的内存分配，从而保持恒定的空间复杂度。

 ## 边缘情况

 当两个目标词彼此相邻时，就会出现一种重要的边缘情况。 在这种情况下，最小可能的有效距离是`1`。 有错误的实现可能会意外地跳过更新或无法正确比较连续位置。 此实现可以自然地处理这种情况，因为每次出现都会立即计算与另一个单词的最新出现的距离。 

另一个重要的情况涉及这两个词多次出现。 幼稚的实现可能会错误地仅比较第一次出现的情况或仅比较最后一次出现的情况。 例如，在`["a", "b", "a", "b"]`，最近的距离来自中间对，不一定是第一对。 该算法在遍历过程中正确更新最新看到的索引，确保考虑每个相关配对。 

第三种边缘情况是当单词出现在数组的最末端时。 例如，`["start", "x", "x", "x", "end"]`。 当计算阵列边界附近的距离时，某些实现可能包含相差一的错误。 由于该解决方案使用绝对值的直接索引减法，因此它可以正确处理位于数组中任何位置的字。 

当一个词在另一个词第一次出现之前多次出现时，就会出现最后一种微妙的情况。 例如，`["a", "a", "a", "b"]`。 该算法安全地延迟距离计算，直到两个索引都初始化为止。 哨兵值`-1`防止在遇到两个目标单词之前进行无效计算。
