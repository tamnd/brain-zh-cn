[LeetCode 第 205 题](https://leetcode.com/problems/isomorphic-strings/)

 **难度：** 🟢简单
 **主题：** 哈希表、字符串

 ## 解决方案

 ## 问题理解

 该问题要求我们确定两个字符串是否`s`和`t`，是**同构**。 如果两个字符串中的字符之间存在一对一的映射，则认为两个字符串是同构的`s`和中的人物`t`这样替换中的每个字符`s`根据这个映射产生`t`。 

简单来说，每个角色`s`必须一致地映射到中的一个字符`t`，并且中没有两个不同的字符`s`可以映射到相同的字符`t`。 但是，允许角色映射到其自身。 

例如，在`s = "egg"`和`t = "add"`:

 -`'e'`映射到`'a'`-`'g'`映射到`'d'`该映射在整个字符串中是一致的，因此结果是`true`。 

相比之下，在`s = "f11"`和`t = "b23"`:

 -`'f'`映射到`'b'`-`'1'`首先映射到`'2'`-`'1'`后来尝试映射到`'3'`由于同一字符不能映射到多个字符，因此字符串不是同构的。 

输入由两个长度相等的字符串组成。 输出是一个布尔值：

 -`true`是否存在有效的一对一字符映射
 -`false`否则

 这些约束告诉我们一些重要的事情：

 - 最大长度为`5 * 10^4`，这意味着低效的二次解可能会变得太慢。 
- 字符串包含**任何有效的 ASCII 字符**，这意味着我们不能仅假设小写字母。 
- 问题保证`s.length == t.length`，所以我们永远不需要处理不匹配的长度。 

预先考虑一些边缘情况很重要。 重复的字符必须始终一致地映射，不同的字符不能映射到相同的目标字符，并且单字符字符串应始终返回`true`。 由于允许使用 ASCII 字符，因此该解决方案还必须适用于数字、标点符号和混合字符集。 

## 方法

 ### 蛮力方法

 暴力解决方案会尝试模拟字符替换，同时反复检查一致性。 对于每个字符对`(s[i], t[i])`，我们可以扫描之前的位置来验证是否存在相同的字符`s`总是匹配相同的字符`t`，并且没有两个不同的字符映射到同一目标。 

例如，处理索引时`i`，我们将查看所有早期的指数`j < i`：

- 如果`s[j] == s[i]`， 然后`t[j]`必须等于`t[i]`- 如果`t[j] == t[i]`， 然后`s[j]`必须等于`s[i]`这保证了正确性，因为每个映射规则都经过显式验证。 然而，对于每个字符，我们可能会扫描所有先前的字符，从而导致时间复杂度为二次方。 

给定最大输入大小`50,000`， 一个`O(n²)`方法会太慢。 

### 最佳方法

 关键的观察是我们只需要在字符之间维护**一致的双向映射**。 

单个哈希映射来自`s`到`t`还不够。 考虑：```
s = "ab"
t = "cc"
```单向地图将允许：```
a → c
b → c
```但这违反了不同字符不能映射到同一个字符的规则。 

为了强制执行有效的一对一对应关系，我们维护**两个哈希映射**：

 1. 人物地图`s`到字符`t`2. 人物地图`t`到字符`s`当我们遍历字符串时：

 - 如果某个字符以前见过，则其映射必须匹配。 
- 如果还没有看到，我们在两个方向上建立一个新的映射。 

这为我们提供了一个有效的线性时间解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 将每个字符与之前的所有位置进行比较 |
 | 最佳| O(n) | O(n) | 使用两个哈希映射来维护双向映射 |

 ## 算法演练

 1. 创建两个哈希图：

 -`s_to_t`映射字符`s`到`t`-`t_to_s`映射字符`t`到`s`我们使用哈希映射是因为它们允许恒定时间的查找和更新，这使得它们成为有效验证映射的理想选择。 
2. 使用两个字符串的索引同时迭代它们。 
3. 各位置`i`， 取回：

-`source_char = s[i]`-`target_char = t[i]`4. 检查是否`source_char`已经存在于`s_to_t`。 

如果存在，验证它是否映射到`target_char`。 如果没有，则返回`False`立即因为映射不一致。 
5. 检查是否`target_char`已经存在于`t_to_s`。 

如果存在，验证它是否映射回`source_char`。 如果没有，则返回`False`因为两个角色试图映射到同一个目标。 
6. 如果两个映射都不存在，则建立两个方向的关系：```
source_char → target_char
target_char → source_char
```7. 继续，直到处理完所有字符。 
8.如果没有发生冲突，则返回`True`。 

### 为什么它有效

 该算法保持了每个处理的字符对都满足双向有效的一对一映射的不变性。 前向映射保证了字符的一致性`s`，而反向映射保证了唯一性`t`。 由于每个位置都只验证一次，因此会立即检测到任何无效映射，并且整个字符串的有效映射保证字符串是同构的。 

## Python 解决方案```python
class Solution:
    def isIsomorphic(self, s: str, t: str) -> bool:
        s_to_t: dict[str, str] = {}
        t_to_s: dict[str, str] = {}

        for source_char, target_char in zip(s, t):
            if source_char in s_to_t:
                if s_to_t[source_char] != target_char:
                    return False
            else:
                s_to_t[source_char] = target_char

            if target_char in t_to_s:
                if t_to_s[target_char] != source_char:
                    return False
            else:
                t_to_s[target_char] = source_char

        return True
```该实现首先创建两个字典来维护字符之间的双向映射。 

该循环同时使用两个字符串进行迭代`zip(s, t)`，这是一种干净高效的方式来一起处理相应的字符。 

对于每个字符对，代码首先检查当前字符是否来自`s`已经有了映射。 如果是，则映射必须与中的当前字符匹配`t`。 否则，字符串不能同构。 

使用反向执行相同的验证`t_to_s`。 这可以防止多个字符`s`从映射到相同的字符`t`。 

If no conflicts are found after processing all characters, the function returns`True`。 

## 解决方案```go
func isIsomorphic(s string, t string) bool {
	sToT := make(map[byte]byte)
	tToS := make(map[byte]byte)

	for i := 0; i < len(s); i++ {
		sourceChar := s[i]
		targetChar := t[i]

		if mappedChar, exists := sToT[sourceChar]; exists {
			if mappedChar != targetChar {
				return false
			}
		} else {
			sToT[sourceChar] = targetChar
		}

		if mappedChar, exists := tToS[targetChar]; exists {
			if mappedChar != sourceChar {
				return false
			}
		} else {
			tToS[targetChar] = sourceChar
		}
	}

	return true
}
```Go 的实现与 Python 解决方案非常相似。 由于问题保证了有效的 ASCII 字符，因此我们可以安全地使用`byte`而不是`rune`，这简化了索引并提高了效率。 

Go 中的映射的行为与 Python 字典类似。 这`value, exists := map[key]`语法允许我们检查映射是否已存在并验证一致性。 

不需要对空字符串进行特殊处理，因为约束保证最小长度为 1，尽管逻辑对于空输入仍然可以正常工作。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个字符都会处理一次，并进行恒定时间的哈希映射操作 |
 | 空间| O(n) | 在最坏的情况下，每个角色都是唯一的并存储在地图中 |

 时间复杂度是线性的，因为该算法对字符串执行单次传递。 哈希图中的每次查找和插入均取平均值`O(1)`时间。 

空间复杂度与遇到的不同字符的数量呈线性关系。 在最坏的情况下，每个角色都是唯一的，因此两个地图一起存储最多`O(n)`映射。

 ## 边缘情况

 一种重要的边缘情况是当多个字符出现在`s`尝试映射到相同的字符`t`。 例如，`"ab"`和`"cc"`如果我们只检查前向一致性，则可能会显得有效。 天真的单向映射会错误地接受这种情况。 我们实现中的反向映射通过确保每个字符都在`t`映射回恰好一个字符`s`。 

另一个重要的情况涉及必须一致映射的重复字符。 例如，`"foo"`和`"bar"`失败是因为`'o'`首先映射到`'a'`稍后需要映射到`'r'`。 该实现通过前向哈希图一致性检查立即捕获这一点。 

第三个重要的边缘情况是包含非字母 ASCII 字符（例如数字或标点符号）的字符串。 由于该问题允许任何 ASCII 字符，因此仅假定小写字母的解决方案可能会失败。 我们的实现通常通过哈希映射来处理每个字符，因此像这样的值`"1!1"`和`"2@2"`无需特殊处理即可正常工作。
