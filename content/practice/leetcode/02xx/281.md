[LeetCode 第 281 题](https://leetcode.com/problems/zigzag-iterator/)

 **难度：** 🟡 中等
 **主题：** 数组、设计、队列、迭代器

 ## 解决方案

 ## 问题理解

 该问题要求我们设计一个迭代器，在两个输入数组之间交替，以循环或之字形顺序返回元素。 我们必须尽可能在它们之间来回切换，而不是消耗第一个向量中的所有元素然后移动到第二个向量。 

例如，如果输入向量是`[1, 2]`和`[3, 4, 5, 6]`，迭代器应按以下顺序生成值：```
1, 3, 2, 4, 5, 6
```迭代器从第一个向量开始，然后从第二个向量中获取一个元素，然后返回到第一个向量，依此类推。 一旦一个向量耗尽，迭代器就会继续消耗另一向量的剩余元素。 

该类公开了三个操作：

 - 构造函数用两个向量初始化迭代器。 
-`next()`返回锯齿形顺序中的下一个元素。 
-`hasNext()`报告是否有任何元素剩余。 

约束相对较小，总共最多 2000 个元素。 这意味着几乎任何合理的线性解决方案都可以顺利通过。 然而，问题的根本在于迭代器的设计和可扩展性，特别是后续涉及的问题`k`向量。 

一个重要的细节是迭代器必须以增量方式运行。 我们不只是被要求提前构造最终的输出数组。 相反，迭代器应该在调用之间维护内部状态`next()`。 

一些边缘情况很重要：

 - 一个向量可能为空。 
- 两个向量的长度可能非常不同。 
- 一个向量可能会比另一个向量更早耗尽。 
- 迭代器绝不能尝试访问越界索引。 
-`hasNext()`和`next()`在整个迭代过程中必须保持一致。 

后续将问题从两个向量推广到`k`向量。 这强烈暗示我们应该考虑活动迭代器或索引的队列，而不是硬编码恰好两个数组之间的交替。 

## 方法

 ### 蛮力方法

 一种直接的方法是在构建过程中预先计算整个锯齿形遍历。 我们可以维护两个索引，重复地将元素交替附加到结果数组中，然后使用另一个指针迭代该预先计算的数组。 

这是有效的，因为之字形顺序是确定性的。 一旦建立了合并订单，每个`next()`操作只是从预先计算的列表中返回下一个元素。 

然而，从设计角度来看，这种方法并不理想。 即使只请求几个元素，它也会急切地计算整个遍历。 它也不会自然延伸到涉及后续行动`k`向量，因为随着向量数量的增加，逻辑变得越来越麻烦。 

### 最佳方法

 更好的解决方案是将问题建模为活动迭代器队列。 

关键的见解是仍然包含剩余元素的每个向量都应该参与循环。 使用向量中的一个元素后，如果该向量仍有更多元素，则应将其放回队列中，以便稍后可以再次参与。 

这创建了一个自然的循环遍历模式。 

对于每个活动向量，我们只需要：

 - 对向量本身的引用
 - 该向量内的当前索引

 当`next()`称为：

 1. 从队列中移除最前面的迭代器状态。 
2. 返回其当前元素。 
3.推进其指标。 
4. 如果还有元素，则将其推回到队列中。 

这种方法优雅、高效，并且可以直接推广到`k`矢量跟踪。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) 预处理，O(1) 每个查询 | O(n) | 预先计算整个遍历顺序 |
 | 最佳| O(1) 每次操作摊销 | O(k) | 基于队列的循环迭代器，轻松扩展到 k 个向量 |

 这里，`n`是元素总数，`k`是活动向量的数量。 

## 算法演练

 ### 基于队列的最优算法

 1. 初始化一个存储活动迭代器状态的队列。 

每个状态包含：

 - 向量本身
 - 该向量中的当前索引

 我们只添加非空向量。 这样可以避免以后不必要的检查。 
2. 在构建过程中，检查两个向量。 

如果`v1`包含元素，添加`(v1, 0)`到队列中。 

如果`v2`包含元素，添加`(v2, 0)`到队列中。 

指数`0`表示从该向量返回的下一个元素。 
3. 什么时候`next()`被调用时，从队列中删除前面的状态。 

这表示当前轮到的向量。 
4. 读取存储索引处的元素。 

这是要返回的下一个锯齿形元素。 
5. 将索引前进一。 

消耗一个元素后，迭代器状态必须向前移动。 
6. 如果向量仍有剩余元素，则将更新后的状态推回到队列中。 

这保留了循环顺序。 在其他活跃向量轮到之后，该向量将再次参与。 
7. 返回提取的元素。 
8.为了`hasNext()`，只需检查队列是否非空。 

如果队列仍然包含迭代器状态，则至少一个向量仍然具有剩余元素。 

### 为什么它有效

 队列始终保持不变式，即其元素表示具有剩余未消耗值的向量，按循环遍历中的下一个轮次排序。 

每次致电`next()`仅消耗前向量中的一个元素，然后仅在剩余元素时重新将该向量入队。 这保证了：

 - 元素按循环顺序返回。 
- 没有元素被跳过。 
- 筋疲力尽后没有向量参与。 

由于每个向量在队列中公平地旋转，因此遍历完全符合所需的锯齿形行为。 

## Python 解决方案```python
from collections import deque
from typing import List, Deque, Tuple

class ZigzagIterator:
    def __init__(self, v1: List[int], v2: List[int]):
        self.queue: Deque[Tuple[List[int], int]] = deque()

        if v1:
            self.queue.append((v1, 0))

        if v2:
            self.queue.append((v2, 0))

    def next(self) -> int:
        vector, index = self.queue.popleft()

        value = vector[index]
        index += 1

        if index < len(vector):
            self.queue.append((vector, index))

        return value

    def hasNext(self) -> bool:
        return len(self.queue) > 0

# Your ZigzagIterator object will be instantiated and called as such:
# i, v = ZigzagIterator(v1, v2), []
# while i.hasNext(): v.append(i.next())
```该实现使用一个`deque`因为我们反复从前面删除元素并将元素追加到后面。 双端队列为两者提供了高效的 O(1) 操作。 

构造函数仅使用非空向量初始化队列。 每个队列条目都存储向量和要从该向量使用的下一个索引。 

这`next()`方法删除前面的迭代器状态，检索当前值，前进索引，如果向量仍然包含元素，则将向量重新添加到队列中。 

这`hasNext()`方法很简单，因为队列本身代表所有剩余的活动迭代器。 如果队列为空，则迭代完成。 

这样的设计自然延伸到了后续涉及`k`向量。 我们可以使用所有非空向量来初始化队列，而不是专门处理两个向量。 

## 解决方案```go
type IteratorState struct {
	vector []int
	index  int
}

type ZigzagIterator struct {
	queue []IteratorState
}

func Constructor(v1, v2 []int) *ZigzagIterator {
	z := &ZigzagIterator{
		queue: []IteratorState{},
	}

	if len(v1) > 0 {
		z.queue = append(z.queue, IteratorState{
			vector: v1,
			index:  0,
		})
	}

	if len(v2) > 0 {
		z.queue = append(z.queue, IteratorState{
			vector: v2,
			index:  0,
		})
	}

	return z
}

func (this *ZigzagIterator) next() int {
	current := this.queue[0]
	this.queue = this.queue[1:]

	value := current.vector[current.index]
	current.index++

	if current.index < len(current.vector) {
		this.queue = append(this.queue, current)
	}

	return value
}

func (this *ZigzagIterator) hasNext() bool {
	return len(this.queue) > 0
}

/**
 * Your ZigzagIterator object will be instantiated and called as such:
 * obj := Constructor(param_1, param_2);
 * for obj.hasNext() {
 *	 ans = append(ans, obj.next())
 * }
 */
```Go 实现遵循与 Python 版本相同的基于队列的设计。 由于Go没有内置的双端队列结构，因此我们使用切片来模拟队列。 

删除前面的元素是使用以下方法完成的：```go
this.queue = this.queue[1:]
```使用 Go 的内置功能追加回队列`append()`功能。 

与 Python 不同，Go 区分 nil 切片和空切片，但两者的行为都正确`len(slice) == 0`，因此无需特殊处理。 

整数溢出不是问题，因为迭代器仅存储大小最多为 1000 的数组内的索引。

 ## 边缘情况

 当一个向量从一开始就为空时，就会出现一个重要的边缘情况。 盲目地在向量之间交替的简单实现可能会尝试访问无效索引或重复检查已经耗尽的向量。 此实现通过在初始化期间仅将非空向量插入队列来完全避免该问题。 

另一种重要的边缘情况是一个向量先于另一个向量耗尽。 例如，`[1, 2]`和`[3, 4, 5, 6, 7]`。 某些实现错误地继续交替并意外地跳过元素或产生无效访问。 在此解决方案中，一旦向量用完元素，它就不会重新插入队列中。 其余向量正常继续。 

一个微妙的边缘情况涉及重复调用`hasNext()`接近迭代结束时。 一些有缺陷的迭代器实现在执行过程中意外修改了内部状态`hasNext()`，导致之间的不一致`hasNext()`和`next()`。 这个实现保留了`hasNext()`完全被动，仅检查队列是否为空。 没有发生内部状态变化。 

另一种边缘情况涉及每个仅包含一个元素的向量。 迭代器仍必须正确交替并干净地终止。 由于每个向量在其单个元素被消耗后就会从队列中删除，因此在返回两个元素后队列立即变空。
