[LeetCode 第 245 题](https://leetcode.com/problems/shortest-word-distance-iii/)

 **难度：** 🟡 中等
 **主题：** 数组、字符串

 ## 解决方案

 ## 问题理解

 问题给了我们一个字符串数组，`wordsDict`，和两个目标词，`word1`和`word2`。 我们必须找到数组中这两个单词出现的最小距离。 

两个单词之间的距离定义为它们在数组中索引之间的绝对差。 例如，如果`"coding"`出现在索引处`3`和`"makes"`出现在索引处`4`，距离为`1`。 

这个问题的重要细节是`word1`和`word2`可能是同一个词。 与问题的简单版本相比，这显着改变了逻辑。 如果两个目标词不同，我们只需要跟踪每个词的最新位置。 然而，当两个目标相同时，我们必须找到同一单词连续出现之间的最小距离。 

输入约束告诉我们：

 - 该数组最多可以包含`10^5`字。 
- 每个单词的长度最多很小`10`。 
- 保证两个目标词都存在于数组中。 

由于输入大小可能非常大，任何比线性时间更差的算法都会变得有风险。 二次解的性能可能高达`10^10`操作，这太慢了。 

有几个重要的边缘情况需要考虑：

 -`word1`和`word2`是不同的词。 
-`word1`和`word2`是同一个词。 
- 连续出现的事件之间的距离最短。 
- 目标词在整个数组中出现多次。 
- 数组长度最小。 
- 最佳对出现在数组的开头或结尾附近。 

保证单词存在于数组中简化了实现，因为我们不需要处理丢失的目标。 

## 方法

 ### 蛮力方法

 暴力解决方案检查数组中每一个可能的索引对。 

我们迭代所有位置`i`和`j`。 每当`wordsDict[i]`匹配一个目标并且`wordsDict[j]`匹配另一个目标，我们计算绝对差`abs(i - j)`并更新最小距离。 

如果单词相同，我们必须确保比较两个不同的位置。 

这种方法是正确的，因为它明确地检查每对有效的事件，因此不会错过最佳答案。 

然而，时间复杂度极其低效。 和`n`换句话说，我们可能会比较每一对位置，从而产生`O(n^2)`时间复杂度。 鉴于`n`可以大到`100000`，这种方法太慢了。 

### 最佳方法

 关键的见解是我们不需要比较每对事件。 

当我们从左到右扫描数组时，对于最小化距离而言唯一重要的事件是最近的相关事件。 

如果`word1`和`word2`是不同的：

 - 跟踪最新索引所在位置`word1`出现了。 
- 跟踪最新索引所在位置`word2`出现了。 
- 每当两者都被看到时，计算当前距离。 

如果`word1`和`word2`是相同的：

 - 我们只需要连续出现之间的距离。 
- 每次我们再次遇到该单词时，计算当前索引与上一次出现之间的差异。 

这使我们能够通过数组一次解决问题。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 比较每对有效的位置 |
 | 最佳| O(n) | O(1) | O(1) | 跟踪近期指数时单次通过 |

 ## 算法演练

 ### 最优算法

 1. 初始化变量`minimum_distance`具有非常大的价值。 
2. 判断是否`word1`和`word2`是同一个词。 这会影响我们跟踪指数的方式。 
3. 如果词语不同：

 - 维护两个变量：

 -`last_word1_index`-`last_word2_index`- 将两者初始化为`-1`以表明他们还没有被发现。 
4.使用索引从左到右遍历数组`i`。 
5. 对于每个单词：

 - 如果当前单词等于`word1`， 更新`last_word1_index`。 
- 如果当前单词等于`word2`， 更新`last_word2_index`。 
6. 更新索引后：

 - 如果两个索引都有效，则计算距离：

 -`abs(last_word1_index - last_word2_index)`- 更新`minimum_distance`如果这个距离更小。 
7. 如果单词相同：

 - 维护单个变量`previous_index`。 
- 每当目标词出现时：

 - 如果`previous_index`已经存在，计算：

 -`i - previous_index`- 更新最小距离。 
- 放`previous_index = i`。 
8.处理完整个数组后，返回`minimum_distance`。 

### 为什么它有效

 该算法之所以有效，是因为任何位置的最接近的有效对必须涉及另一个目标单词的最新出现。 

当单词不同时，任何较旧的事件都会比最新的事件产生更大的距离。 因此，仅保留最新的索引就足够了。 

当单词相同时，连续出现之间的距离一定是最短的。 任何不连续的对都必然具有较大的距离，因为它们之间存在另一个事件。 

## Python 解决方案```python
from typing import List

class Solution:
    def shortestWordDistance(self, wordsDict: List[str], word1: str, word2: str) -> int:
        minimum_distance = float("inf")

        # Case where both target words are the same
        if word1 == word2:
            previous_index = -1

            for index, word in enumerate(wordsDict):
                if word == word1:
                    if previous_index != -1:
                        minimum_distance = min(
                            minimum_distance,
                            index - previous_index
                        )

                    previous_index = index

        # Case where target words are different
        else:
            last_word1_index = -1
            last_word2_index = -1

            for index, word in enumerate(wordsDict):
                if word == word1:
                    last_word1_index = index

                if word == word2:
                    last_word2_index = index

                if last_word1_index != -1 and last_word2_index != -1:
                    minimum_distance = min(
                        minimum_distance,
                        abs(last_word1_index - last_word2_index)
                    )

        return minimum_distance
```该实现首先将最小距离初始化为无穷大，以便任何有效距离将取代它。 

然后，代码将逻辑分为两种情况。 这种分离很重要，因为相同的目标词需要根本不同的处理。 

在相同单词的情况下，我们仅跟踪该单词的前一次出现。 每个新的出现都与前一个出现形成候选对。 由于连续出现总是会产生该段的最小可能距离，因此这保证了正确性。 

在不同单词的情况下，我们独立跟踪每个目标单词的最新索引。 每次更新后，如果两个单词都被看到，我们会计算当前距离并根据需要更新答案。 

该算法仅对数组执行一次遍历，并且仅使用几个整数变量。 

## 解决方案```go
import "math"

func shortestWordDistance(wordsDict []string, word1 string, word2 string) int {
	minimumDistance := math.MaxInt32

	// Case where both target words are the same
	if word1 == word2 {
		previousIndex := -1

		for index, word := range wordsDict {
			if word == word1 {
				if previousIndex != -1 {
					distance := index - previousIndex

					if distance < minimumDistance {
						minimumDistance = distance
					}
				}

				previousIndex = index
			}
		}
	} else {
		// Case where target words are different
		lastWord1Index := -1
		lastWord2Index := -1

		for index, word := range wordsDict {
			if word == word1 {
				lastWord1Index = index
			}

			if word == word2 {
				lastWord2Index = index
			}

			if lastWord1Index != -1 && lastWord2Index != -1 {
				distance := lastWord1Index - lastWord2Index

				if distance < 0 {
					distance = -distance
				}

				if distance < minimumDistance {
					minimumDistance = distance
				}
			}
		}
	}

	return minimumDistance
}
```Go 的实现与 Python 解决方案非常相似。 

一个小小的区别是 Go 没有提供内置的整数无穷大值，因此我们使用以下方式初始化答案`math.MaxInt32`。 

另一个区别是 Go 在标准库中没有内置的整数绝对值函数。 因此，绝对差是手动计算的。 

Go 中的切片自然地用于数组遍历，除了一些整数变量之外不需要额外的内存分配。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`word1`和`word2`是相同的。 为不同单词设计的简单实现通常会失败，因为它可能会将单词出现与其自身进行比较，从而产生距离`0`，这是无效的。 该实现通过单独跟踪连续发生并始终比较两个不同的索引来避免这种情况。 

另一个重要的边缘情况是当最短距离为`1`。 当目标词彼此相邻时就会发生这种情况。 一些不正确的实现会延迟更新或跳过比较，可能会丢失相邻对。 由于算法在每次出现后立即更新距离，因此可以自然地处理相邻匹配。 

第三个重要的边缘情况是一个单词在另一个单词第一次出现之前多次出现。 例如：```
["a", "a", "a", "a", "b"]
```有缺陷的解决方案可能会错误地使用过时的索引或无法正确更新。 该实现始终存储每个目标单词的最新出现，确保一旦看到两个单词，就可以正确计算当前的最小距离。 

另一种微妙的边缘情况是连续出现相同的情况，例如：```
["x", "x", "x"]
```正确答案是`1`，因为最接近的对是由相邻的出现形成的。 该实现可以正确计算连续出现之间的距离，因此始终捕获尽可能小的间隙。
