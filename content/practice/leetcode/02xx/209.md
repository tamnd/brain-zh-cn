 **难度：** 🟡 中等
 **主题：** 数组、二分查找、滑动窗口、前缀和

 ## 解决方案

 ## 问题理解

 该问题给了我们一个正整数数组，称为`nums`和一个正整数称为`target`。 我们需要找到一个连续子数组的最小可能长度，其总和大于或等于`target`。 

连续子数组意味着元素必须在原始数组中彼此相邻出现。 我们不允许跳过元素。 

例如，如果：```
target = 7
nums = [2,3,1,2,4,3]
```然后子数组`[4,3]`总和为`7`，其长度为`2`。 没有长度的子数组`1`满足条件，所以正确答案是`2`。 

重要的细节是我们正在最小化长度，而不是总和本身。 

限制条件很大：

 -`nums.length`可以达到`10^5`- 中的每个值`nums`是积极的
 -`target`可以大到`10^9`这些限制立即告诉我们，`O(n^2)`在最坏的情况下，暴力解决方案可能会太慢。 和`100,000`元素，检查每个可能的子数组将导致数十亿次操作。 

所有数字均为正数这一事实是实现有效解决方案的关键属性。 由于每个元素都大于零，因此扩大窗口总是会增加总和，而缩小窗口总是会减少总和。 这种单调行为使得滑动窗口技术成为可能。 

尽早识别一些边缘情况非常重要：

 - 不存在有效的子数组，在这种情况下我们必须返回`0`- 单个元素可能已经满足目标
 - 可能需要整个阵列才能到达目标
 - 数组可能包含许多永远不会达到目标的小值
 - 由于值是正数，我们永远不需要担心负数会破坏滑动窗口逻辑

 ## 方法

 ### 暴力方法

 最直接的解决方案是检查每个可能的连续子数组。 

我们可以选择每个起始索引`i`，然后将子数组一次向右扩展一个元素，同时保持运行总和。 每当总和大于或等于`target`，我们计算子数组长度并更新最小答案。 

这种方法是正确的，因为它显式检查所有可能的子数组，保证最终找到最短的有效子数组。 

但时间复杂度太高。 有`O(n^2)`size 数组中可能的子数组`n`，在最坏的情况下，我们可能会检查其中的大多数。 和`n = 10^5`，这在计算上变得不可行。 

### 最优滑动窗口方法

 关键的观察结果是所有数字都是正数。 

正因为如此：

 - 向右扩大窗口只能增加总和
 - 从左边缩小窗口只能减少总和

 这允许我们使用两个指针维护一个动态窗口。 

我们扩展右指针，直到窗口总和变得足够大。 一旦总和达到或超过`target`，我们尝试在保持条件不变的情况下尽可能地从左侧缩小窗口。 这保证了对于每个右边界，我们都能找到以该位置结束的最小有效窗口。 

我们不是重复地重新计算总和，而是维护一个随着指针移动而增量更新的运行总和。 

由于每个元素都被添加到窗口一次并被删除一次，因此该算法以线性时间运行。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 检查每个可能的子数组 |
 | 最优滑动窗口| O(n) | O(1) | O(1) | 使用两个指针和一个运行总和 |

 ## 算法演练

 1. 初始化两个指针调用`left`和`right`。 

这`left`指针代表当前窗口的开始，`right`指针代表结束。 
2. 维护一个运行变量，名为`current_sum`。 

该变量存储当前窗口内所有元素的总和。 我们不是每次都重新计算总和，而是随着窗口的变化逐步更新它。 
3. 初始化answer 变量。 

我们存储迄今为止找到的最小有效长度。 一种常见的方法是将其初始化为无穷大，以便任何有效的子数组长度都将替换它。 
4. 通过移动扩大窗口`right`。 

对于每个位置`right`， 添加`nums[right]`到`current_sum`。 
5. 检查当前窗口是否满足条件。 

如果`current_sum >= target`，则当前窗口有效。 
6. 在窗口保持有效的情况下从左侧缩小窗口。 

由于我们想要最小长度，因此我们应该尝试使窗口尽可能小。 

尽管`current_sum >= target`:

 - 更新最小长度
 - 删除`nums[left]`从`current_sum`- 增量`left`7. 继续，直到处理完整个数组。 

每个可能的最小有效窗口将仅被考虑一次。 
8. 返回结果。 

如果没有找到有效的子数组，则返回`0`。 否则，返回记录的最小长度。 

### 为什么它有效

 该算法之所以有效，是因为所有数字都是正数。 一旦窗口达到目标总和，任何进一步向右延伸的较大窗口都无法产生更短的答案，除非我们首先从左侧缩小。 

滑动窗口始终维护一个连续的子数组，并且内部收缩循环保证每当给定右边界存在有效窗口时，我们都会将其缩小到可能的最小有效窗口。 因此，检查每个候选最小值，并正确找到全局最小值。 

## Python 解决方案```python
from typing import List

class Solution:
    def minSubArrayLen(self, target: int, nums: List[int]) -> int:
        left = 0
        current_sum = 0
        min_length = float('inf')

        for right in range(len(nums)):
            current_sum += nums[right]

            while current_sum >= target:
                window_length = right - left + 1
                min_length = min(min_length, window_length)

                current_sum -= nums[left]
                left += 1

        return 0 if min_length == float('inf') else min_length
```实现首先初始化滑动窗口状态。 这`left`指针从索引处开始`0`， 和`current_sum`跟踪当前窗口内元素的总和。 

外循环通过移动`right`指针穿过数组。 每个新元素都会添加到`current_sum`。 

每当运行总和大于或等于`target`，内部`while`循环从左侧开始缩小窗口。 此步骤至关重要，因为它确保我们在继续之前最小化当前有效窗口。 

表达式：```python
right - left + 1
```计算当前窗口长度。 

记录长度后，算法从运行总和中删除最左边的元素，并将`left`指针。 这将持续到窗口不再有效为止。 

最后，如果`min_length`从未更新，不存在有效的子数组，因此函数返回`0`。 

## 解决方案```go
func minSubArrayLen(target int, nums []int) int {
	left := 0
	currentSum := 0
	minLength := len(nums) + 1

	for right := 0; right < len(nums); right++ {
		currentSum += nums[right]

		for currentSum >= target {
			windowLength := right - left + 1

			if windowLength < minLength {
				minLength = windowLength
			}

			currentSum -= nums[left]
			left++
		}
	}

	if minLength == len(nums)+1 {
		return 0
	}

	return minLength
}
```Go 实现遵循与 Python 版本相同的滑动窗口逻辑。 

一个显着的区别是 Go 没有像 Python 那样方便地内置整数无穷大值。 相反，该实现初始化`minLength`到`len(nums) + 1`，保证大于任何有效的子数组长度。 

Go 切片是数组上动态大小的视图，因此迭代`nums`无需额外的内存分配即可高效工作。 

由于问题约束完全符合 Go 的整数范围，因此整数溢出在这里不是问题。

 ## 边缘情况

 当不存在有效子数组时，会出现一种重要的边缘情况。 例如：```
target = 20
nums = [1,2,3,4]
```整个数组的总和仍然小于目标。 有缺陷的实现可能会意外返回未初始化的值或数组长度。 此实现通过初始化避免了该问题`min_length`到无穷大并返回`0`如果它从未更新过。 

另一个重要的情况是当单个元素已经满足目标时。 例如：```
target = 4
nums = [1,4,4]
```一些实现错误地继续扩大窗口而不立即缩小，这可能会错过最佳答案`1`。 内部`while`循环保证窗口一旦有效就最小化。 

当整个阵列需要满足目标时，就会出现第三种边缘情况。 例如：```
target = 15
nums = [1,2,3,4,5]
```该算法必须正确处理增长以覆盖整个数组的窗口。 由于滑动窗口是逐步扩大的，只有在有效时才缩小，所以它自然支持这种情况，无需任何特殊处理。 

另一个微妙的情况涉及重复的小数字：```
target = 3
nums = [1,1,1,1,1]
```这里，存在许多具有相同总和的重叠窗口。 不正确的指针移动可能会意外跳过候选窗口。 由于此实现在条件保持满足的情况下将左指针一次移动一步，因此每个最小有效窗口都会被正确考虑。
