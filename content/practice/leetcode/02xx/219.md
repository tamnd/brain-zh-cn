[LeetCode 第 219 题](https://leetcode.com/problems/contains-duplicate-ii/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表、滑动窗口

 ## 解决方案

 ## 问题理解

 该问题要求我们确定一个数组是否包含两个索引彼此接近的相等值。 更具体地说，我们需要检查是否存在两个不同的索引`i`和`j`这样：

 -`nums[i] == nums[j]`-`abs(i - j) <= k`数组`nums`包含整数，并且`k`定义重复元素之间允许的最大距离。 

简单来说，我们正在寻找最多再次出现的重复数字`k`其上次出现的位置。 如果存在这样的一对，我们返回`true`。 否则，我们返回`false`。 

例如，考虑：```
nums = [1,2,3,1], k = 3
```价值`1`出现在索引处`0`和`3`。 他们之间的距离是：```
abs(0 - 3) = 3
```自从`3 <= k`，答案是`true`。 

约束很重要，因为它们影响哪些算法可行：

 -`nums.length`可以大到`100000`-`k`也可以大到`100000`比较每对指数的简单二次解需要最多`10^10`在最坏的情况下，操作速度太慢了。 这强烈表明我们需要一个线性或近线性的解决方案。 

一些边缘情况值得尽早识别：

 -`k = 0`，永远不允许重复，因为索引必须不同并且它们的距离必须最多`0`- 完全没有重复项的数组
 - 存在但相距较远的重复项`k`- 负数，因为值的范围可以小至`-10^9`- 非常大的阵列，效率很重要

 该问题保证输入数组非空，因此我们不需要处理完全空的数组。 

## 方法

 ### 蛮力方法

 最直接的解决方案是比较每对索引`(i, j)`在哪里`i < j`。 

对于每对：

 - 检查是否`nums[i] == nums[j]`- 如果它们相等，则计算`abs(i - j)`- 返回`true`如果距离最多为`k`这种方法是正确的，因为它详尽地检查了每对可能的索引。 如果存在有效的重复对，算法最终会找到它。 

但时间复杂度极差。 对于大小的数组`n`，大约有：$\frac{n(n-1)}{2}$配对进行检查。 

这导致`O(n²)`时间复杂度，对于`n = 100000`。 

### 最佳方法

 关键的观察是我们实际上并不需要比较每对指数。 

相反，在处理一个元素时，我们只关心最近是否在最后一个元素中看到了相同的值`k`指数。 

哈希映射正好提供了我们所需要的：

 - 存储每个数字及其最新索引
 - 当我们迭代数组时，检查当前数字是否已存在于地图中
 - 如果是，则计算索引之间的距离
 - 如果距离最大`k`， 返回`true`这是有效的，因为最近出现的值始终是满足距离条件的最佳候选值。 

使用哈希映射允许每次查找和插入在大约恒定的时间内执行，从而产生线性的整体解决方案。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 比较每对索引 |

 ## 算法演练

 1. 创建一个名为的哈希图`last_seen`。 

哈希映射将每个数字存储为键，并将该数字出现的最新索引存储为值。 
2. 使用索引和值迭代数组。 

在每一步中，我们都会检查当前数字并确定它以前是否出现过。 
3. 检查当前号码是否已存在于哈希图中。 

如果不存在，则这是该数字第一次出现，因此我们只需记录其索引。 
4. 如果该号码存在，则检索其先前的索引。 

计算当前索引和前一个索引之间的距离：$|i-j|$5. 比较距离`k`。 

如果距离小于或等于`k`，我们立即返回`true`因为我们发现附近有一个有效的重复项。 
6. 使用当前索引更新哈希映射。 

即使该数字已经存在，我们也会覆盖旧索引，因为最近出现的索引对于将来的比较最有用。 
7. 如果循环完成后没有找到有效的对，则返回`false`。 

### 为什么它有效

 该算法维护一个重要的不变量：对于迄今为止遇到的每个值，哈希图都会存储其最新的索引。 

当我们遇到重复值时，最接近的前一个值始终是最近的值。 如果即使是最接近的事件也比`k`，那么所有较早发生的事件距离更远，不能满足条件。 

由于每个元素都会根据其最近的先前重复候选进行检查，因此该算法可以正确检测是否存在有效的附近重复项。 

## Python 解决方案```python
from typing import List

class Solution:
    def containsNearbyDuplicate(self, nums: List[int], k: int) -> bool:
        last_seen = {}

        for index, value in enumerate(nums):
            if value in last_seen:
                previous_index = last_seen[value]

                if index - previous_index <= k:
                    return True

            last_seen[value] = index

        return False
```实现首先创建一个名为的字典`last_seen`。 该字典将每个数字映射到它出现的最新索引。 

循环使用`enumerate(nums)`以便在迭代过程中当前索引和当前值都可用。 

对于每个值：

 - 代码首先检查字典中是否已存在该值。 
- 如果是，则检索前一个索引。 
- 计算当前索引和先前索引之间的差异。 
- 如果该差值小于或等于`k`，函数立即返回`True`。 

检查后，字典将更新为当前索引。 这确保字典始终包含每个数字最近出现的位置。 

如果循环结束且没有返回`True`，则附近不存在有效的重复项，因此函数返回`False`。 

## 解决方案```go
func containsNearbyDuplicate(nums []int, k int) bool {
	lastSeen := make(map[int]int)

	for index, value := range nums {
		if previousIndex, exists := lastSeen[value]; exists {
			if index-previousIndex <= k {
				return true
			}
		}

		lastSeen[value] = index
	}

	return false
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个`map[int]int`用于存储每个值的最新索引。 Go 映射在查找期间返回两个值：```go
value, exists := map[key]
```这`exists`布尔值允许我们确定密钥是否已经存在。 

不存在整数溢出问题，因为在给定问题约束的情况下，索引差异完全在 Go 的整数范围内。 

Go 切片是数组上动态大小的视图，因此迭代`nums`和`range`高效且惯用。

 该算法对数组执行单次遍历。 每次查找和插入哈希映射大约是`O(1)`平均而言，因此总运行时间随着数组的大小线性增长。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`k = 0`。 由于索引必须不同，因此两个不同索引的距离不能为零。 即使存在重复项，答案也必须始终是`false`。 该实现自然地处理了这个问题，因为任何重复的对都会有一个正的索引差，这不能满足`<= 0`。 

另一个重要的情况是当存在重复项但相距较远时`k`。 幼稚的实现可能会错误地返回`true`看到任何重复值后立即。 例如：```
nums = [1,2,3,1], k = 2
```重复的`1`值是距离`3`分开，所以答案应该是`false`。 该算法在返回之前显式检查索引差异。 

第三个重要的边缘情况涉及重复的重复。 考虑：```
nums = [1,0,1,1], k = 1
```如果算法在每次出现后未能更新存储的索引，它将与过时的位置进行比较，并且可能会错过附近的有效重复项。 通过始终存储最新的索引，该实现可以正确检测索引处的重复对`2`和`3`。 

另一个微妙的情况是包含所有唯一元素的数组。 在这种情况下，哈希映射在整个迭代过程中都会增长，但不会触发重复条件。 算法正确完成循环并返回`false`。
