[LeetCode 第 261 题](https://leetcode.com/problems/graph-valid-tree/)

 **难度：** 🟡 中等
 **主题：** 深度优先搜索、广度优先搜索、并查找、图论

 ## 解决方案

 ## 问题理解

 该问题询问给定的无向图是否形成有效的树。 

树是一种特殊类型的图，具有两个重要属性：

 1. 该图是全连接的，这意味着每个节点都可以从其他每个节点到达。 
2. 该图不包含循环。 

输入由两部分组成：

 -`n`，图中的节点数，标记为`0`到`n - 1`-`edges`，其中每对`[a, b]`表示节点之间的无向连接`a`和节点`b`目标是回归`true`如果这些边正好形成一棵有效的树，否则返回`false`。 

例如，如果每个节点都连接并且没有循环，则该图是一棵树。 如果存在断开的组件或循环，则该图就不是树。 

约束很重要，因为它们指导解决方案的预期效率：

 -`n`最大可达 2000
 -`edges.length`最多可达 5000

 这意味着指数或重复遍历解决方案会太慢。 我们需要一个相对于节点和边的数量大约以线性时间运行的解决方案。 

一些边缘情况尤其重要：

 - 具有一个节点且没有边的图是一棵有效的树。 
- 边太多的图必须包含环。 
- 边太少的图无法完全连接。 
- 断开连接的图即使不包含环也是无效的。 
- 即使所有节点均可到达，循环图也是无效的。 

树的一个关键数学属性在这里非常有用：

 图表与`n`节点是一个有效的树当且仅当：

 - 它包含确切的`n - 1`边缘
 - 它是完全连接的

 这一观察大大简化了问题。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试以不太优化的方式独立验证每个树属性。 

一种可能性是：

 - 对于每个节点，执行遍历以确保所有其他节点均可访问。 
- 使用重复的 DFS 或 BFS 遍历单独检查循环。 
- 多次重新计算连接信息。 

这种方法是正确的，因为它显式验证了所需的树属性。 然而，它执行了不必要的重复工作。 从许多起始节点运行图遍历会导致效率低下。 

例如，如果从每个节点执行 DFS，则复杂度可以接近`O(n * (n + e))`，这是不必要的昂贵。 

### 最佳方法

 最佳解决方案使用图论观察。 

一棵有效的树必须满足两个条件：

 1. 该图准确包含`n - 1`边缘。 
2.图形是连通的。 

为什么这有效？ 

- 如果连通图恰好有`n - 1`边，它不能包含循环。 
- 如果图表的数量少于`n - 1`边缘，必须将其断开。 
- 如果一个图有超过`n - 1`边，它必须包含一个循环。 

因此，一旦我们验证了边数，我们只需要确认连通性即可。 

我们可以使用 DFS 或 BFS 有效地做到这一点：

 - 建立邻接表。 
- 从节点开始遍历`0`。 
- 计算有多少个节点被访问。 
- 如果所有节点都被访问并且边数为`n - 1`，该图是一棵有效的树。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * (n + e)) | O(n * (n + e)) | O(n + e) | 重复图遍历 |
 | 最佳| O(n + e) | O(n + e) | 具有边数属性的单次遍历 |

 ## 算法演练

 1.首先检查边数是否等于`n - 1`。 

这是最重要的早期优化。 一棵有效的树`n`节点必须准确包含`n - 1`边缘。 如果这个条件不成立，我们可以立即返回`false`不执行任何图遍历。 
2. 构建图的邻接列表表示。 

由于图是无向的，所以每条边`[a, b]`双向存储：

 - 添加`b`到`a`的邻居列表
 - 添加`a`到`b`的邻居列表

 选择邻接列表是因为它允许有效遍历稀疏图并使用与边数成比例的空间。 
3. 创建一个名为`visited`。 

这会跟踪 DFS 期间已经探索过哪些节点。 如果没有这种结构，遍历可能会无限期地重新访问循环图中的节点。 
4.从节点启动DFS`0`。 

遍历从起点开始探索每个可到达的节点。 
5. DFS期间：

 - 将当前节点标记为已访问。 
- 递归访问所有未访问过的邻居。 

这逐渐探索了包含节点的整个连接组件`0`。 
6. DFS完成后，检查访问了多少个节点。 

如果图是全连接的，则从节点应该已经到达每个节点`0`。 
7. 返回`true`仅当所有节点都被访问时。 

与之前的边计数检查相结合，这保证了该图是一棵有效的树。 

### 为什么它有效

 该算法依赖于一个基本的树属性：

 无向图是树当且仅当：

 - 它包含确切的`n - 1`边缘
 - 已连接

 边计数条件消除了所有循环和连接不足的情况。 DFS 连接性检查确保每个节点都属于同一个连接的组件。 总的来说，这些条件既是必要的，也是充分的。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def validTree(self, n: int, edges: List[List[int]]) -> bool:
        # A valid tree with n nodes must have exactly n - 1 edges
        if len(edges) != n - 1:
            return False

        # Build adjacency list
        graph = defaultdict(list)

        for a, b in edges:
            graph[a].append(b)
            graph[b].append(a)

        visited = set()

        def dfs(node: int) -> None:
            visited.add(node)

            for neighbor in graph[node]:
                if neighbor not in visited:
                    dfs(neighbor)

        # Start DFS from node 0
        dfs(0)

        # Graph is a tree only if all nodes are connected
        return len(visited) == n
```实施从关键边缘计数检查开始。 这立即消除了不可能的情况并避免了不必要的遍历工作。 

邻接表的构造方法是使用`defaultdict(list)`，简化了插入逻辑并自动初始化邻居列表。 

这`visited`set prevents revisiting nodes during DFS. 这对于正确性和效率至关重要。 

嵌套的`dfs`函数递归地探索当前节点的所有可达邻居。 每个访问过的节点都被添加到集合中一次。 

遍历完成后，算法将访问的节点数与`n`。 如果到达所有节点，则图已连接。 由于边数已经验证，因此该图必须是一棵树。 

## 解决方案```go
func validTree(n int, edges [][]int) bool {
    // A valid tree must have exactly n - 1 edges
    if len(edges) != n-1 {
        return false
    }

    // Build adjacency list
    graph := make([][]int, n)

    for _, edge := range edges {
        a := edge[0]
        b := edge[1]

        graph[a] = append(graph[a], b)
        graph[b] = append(graph[b], a)
    }

    visited := make([]bool, n)

    var dfs func(int)

    dfs = func(node int) {
        visited[node] = true

        for _, neighbor := range graph[node] {
            if !visited[neighbor] {
                dfs(neighbor)
            }
        }
    }

    // Start DFS from node 0
    dfs(0)

    // Verify all nodes were visited
    for _, seen := range visited {
        if !seen {
            return false
        }
    }

    return true
}
```Go 实现遵循与 Python 版本相同的整体算法。 

Go 不使用基于哈希的邻接结构，而是使用切片的切片：`[][]int`。 由于节点标签保证在范围内`[0, n - 1]`，直接索引高效且简单。 

这`visited`结构是使用布尔切片而不是集合来实现的。 这在 Go 中更惯用，也更节省内存。 

Go 不像 Python 一样支持嵌套命名函数，因此 DFS 函数被声明为函数变量并递归赋值。 

由于约束很小，因此不需要特殊的整数溢出处理。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n + e) | 构建图并 DFS 遍历每个流程节点和边一次 |
 | 空间| O(n + e) | 邻接表和访问过的结构存储图信息 |

 邻接表将每个无向边存储两次，每个方向一次，因此其总大小与`e`。 

DFS 遍历访问每个节点一次并检查每条边一次，从而导致相对于图大小的线性复杂度。 

递归堆栈可以增长到`O(n)`在链形图的最坏情况下。

 ## 边缘情况

 一种重要的边缘情况是具有单个节点且没有边的图。 许多实现意外地拒绝了这种情况，因为它们假设必须存在至少一条边。 然而，单个节点是平凡连接的并且不包含循环，因此它是一棵有效的树。 该实现正确处理了这个问题，因为`len(edges) == n - 1`评估为`0 == 0`，DFS成功访问唯一节点。 

另一个重要的情况是边数太少的断开图。 例如：```
n = 4
edges = [[0,1],[2,3]]
```仅检查循环的简单实现可能会错误地接受该图，因为它没有循环。 然而，树也必须连接起来。 DFS 遍历确保该图被拒绝，因为只有部分图可以从节点访问`0`。 

第三个重要的边缘情况是包含循环的图。 循环违反了树的属性，因为节点之间存在多条路径。 一些实现尝试昂贵的显式循环检测，但该解决方案使用边缘计数属性有效地处理问题。 任意无向连通图超过`n - 1`边必须包含循环，因此算法在遍历开始之前立即拒绝这种情况。
