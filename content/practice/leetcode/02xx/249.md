[LeetCode 第 249 题](https://leetcode.com/problems/group-shifted-strings/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、字符串

 ## 解决方案

 ## 问题理解

 该问题要求我们将属于同一循环移位序列的字符串分组。 如果两个字符串属于同一组，则可以通过在字母表中重复向前或向后移动每个字符来将一个字符串转换为另一个字符串，并在其之间进行换行`'z'`和`'a'`。 

例如，`"abc"`变成`"bcd"`右移一次后，并且`"xyz"`也变成`"yza"`右移一圈后。 因为移位保留了字符之间的相对距离，`"abc"`,`"bcd"`， 和`"xyz"`都属于同一序列。 

输入是小写字符串数组。 输出应该是一个组列表，其中组内的每个字符串都属于相同的移位序列。 组的顺序并不重要，每个组内字符串的顺序也并不重要。 

限制相对较小：

 - 最多 200 个字符串
 - 每个字符串的长度最多为 50

 这些限制意味着即使是适度昂贵的操作也是可以接受的，但我们仍然需要一个干净且可扩展的解决方案。 

最重要的观察结果是，移位保留了相邻字符之间的差异模式。 例如：

-`"abc"`有差异`[1, 1]`-`"bcd"`也有差异`[1, 1]`-`"xyz"`也有差异`[1, 1]`因此，这三个人都属于同一组。 

有几个重要的边缘情况：

 - 单字符字符串，例如`"a"`和`"z"`应始终属于同一组，因为任何单个字符都可以转换为任何其他单个字符。 
- 环绕式案例，例如`"az"`和`"ba"`是有效的匹配，因为移位`'z'`向前产生`'a'`。 
- 不同长度的字符串永远不能属于同一组，因为移位不会改变长度。 
- 如果模处理不正确，简单的实现很容易在环绕算术上失败。 

## 方法

 ### 蛮力方法

 暴力解决方案将比较每对字符串并确定它们是否属于相同的移位序列。 

要比较两个字符串，我们会：

 1. 检查它们的长度是否相同。 
2. 计算对应字母之间的字符差异。 
3. 验证每个位置是否具有相同的循环差。 

例如：

-`"abc"`到`"bcd"`轮班`[1,1,1]`-`"abc"`到`"xyz"`轮班`[23,23,23]`如果所有字符的移位量一致，则字符串属于同一组。 

我们可以重复扫描所有字符串并将兼容的字符串合并在一起。 

这种方法是正确的，因为它显式检查移位字符串的定义属性。 然而，它变得低效，因为每个字符串可能需要与其他每个字符串进行比较。 

### 最佳方法的关键见解

 重要的观察是相同移位序列中的字符串共享相同的归一化差异模式。 

我们可以计算每个字符串的规范表示，而不是成对比较字符串。 

例如：

-`"abc"`→ 差异`(1,1)`-`"bcd"`→ 差异`(1,1)`-`"xyz"`→ 差异`(1,1)`相似地：

-`"az"`→`(25)`-`"ba"`→`(25)`我们可以使用这个差异模式作为哈希映射键。 每个具有相同键的字符串都属于同一组。 

这将问题从重复比较转换为使用哈希表的简单分组问题。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n² × m) | O(n) | 比较每对字符串 |
 | 最佳| O(n × m) | O(n × m) | 使用归一化差异模式作为哈希键 |

 这里：

-`n`是字符串的数量
 -`m`是最大字符串长度

 ## 算法演练

 ### 最优算法

 1. 创建一个哈希映射，其中：

 - 关键是标准化的换班模式
 - 该值是属于该模式的字符串列表
 2. 对于每个字符串，计算其签名。 

签名是通过计算连续字符之间的循环差形成的。 

例如：

-`"abc"`-`'b' - 'a' = 1`-`'c' - 'b' = 1`- 签名：`(1,1)`-`"xyz"`-`'y' - 'x' = 1`-`'z' - 'y' = 1`- 签名：`(1,1)`3. 使用模运算来处理环绕情况。 

例如：

-`"az"`-`'z' - 'a' = 25`- 签名：`(25)`-`"ba"`-`'a' - 'b' = -1`-`(-1 + 26) % 26 = 25`- 签名：`(25)`4. 将字符串插入与其签名对应的哈希映射桶中。 
5. 处理完所有字符串后，返回所有哈希映射值。 

### 为什么它有效

 该算法之所以有效，是因为将字符串中的每个字符移动相同的量可以保留相邻字符之间的相对差异。 因此，同一移位序列中的所有字符串都会产生相同的差异签名。 相反，具有不同签名的字符串不能属于同一移位序列。 

## Python 解决方案```python
from collections import defaultdict
from typing import List, Tuple

class Solution:
    def groupStrings(self, strings: List[str]) -> List[List[str]]:
        
        def get_signature(s: str) -> Tuple[int, ...]:
            signature = []
            
            for i in range(1, len(s)):
                diff = (ord(s[i]) - ord(s[i - 1])) % 26
                signature.append(diff)
            
            return tuple(signature)
        
        groups = defaultdict(list)
        
        for s in strings:
            key = get_signature(s)
            groups[key].append(s)
        
        return list(groups.values())
```实现首先定义一个名为的辅助函数`get_signature`。 此函数计算字符串的归一化差异模式。 

对于每对相邻的字符，我们使用模 26 算术计算循环差。 使用模可确保环绕式案例正常工作。 例如，从`'z'`到`'a'`正确地产生差异`1`。 

签名存储为元组，因为元组是不可变的并且可以用作字典键。 

然后我们创建一个`defaultdict(list)`将共享相同签名的字符串分组。 

当我们迭代每个字符串时：

 - 计算其签名
 - 将字符串插入到对应的hashmap桶中

 最后，我们从字典中返回所有分组值。 

单字符字符串自然会产生一个空元组`()`，它将所有单字母字符串正确分组在一起。 

## 解决方案```go
package main

func groupStrings(strings []string) [][]string {
    
    groups := make(map[string][]string)

    for _, s := range strings {
        key := getSignature(s)
        groups[key] = append(groups[key], s)
    }

    result := [][]string{}

    for _, group := range groups {
        result = append(result, group)
    }

    return result
}

func getSignature(s string) string {
    if len(s) == 1 {
        return ""
    }

    signature := make([]byte, 0)

    for i := 1; i < len(s); i++ {
        diff := (int(s[i]) - int(s[i-1]) + 26) % 26

        signature = append(signature, byte(diff)+'a')
    }

    return string(signature)
}
```Go解决方案遵循与Python版本相同的整体策略，但在实现细节上略有不同。 

由于 Go 切片不能直接用作映射键，因此我们将签名转换为字符串表示形式。 每个循环差被编码为一个字符。 

例如：

 - 差异`0`变成`'a'`- 不同之处`1`变成`'b'`这将创建一个紧凑且可散列的签名字符串。 

Go 映射会自动为缺失的键返回零值，因此附加到 nil 切片自然可以工作，无需额外的初始化。 

不存在整数溢出问题，因为所有算术都保持在较小的字母大小范围内。

 ## 边缘情况

 ### 单字符字符串

 单字符字符串没有相邻字符差异，因此其签名成为空元组。 这意味着所有单字母字符串都属于同一组。 

如果实现假设每个字符串至少有一个差异值，那么这种情况很容易导致错误。 我们的实现自然地处理它，因为相邻字符上的循环根本不会运行。 

### 字母环绕

 字符串像`"az"`和`"ba"`是等价的，因为移位`"az"`转发一次产生`"ba"`。 

一个天真的减法会产生`-1`为了`'a' - 'b'`，这会错误地分隔这些字符串。 该实现通过使用模算术解决了这个问题：```
(ord(current) - ord(previous)) % 26
```这会将负差转换为其正确的循环表示。 

### 不同长度的字符串

 不同长度的字符串永远不能属于同一移位序列，因为移位会保留字符串长度。 

例如：

-`"ab"`和`"abc"`无法匹配

 我们的签名构造本质上可以处理此问题，因为签名包含的元素比字符串长度少一个。 因此，不同的长度会产生不同大小的签名。
