[LeetCode 第 246 题](https://leetcode.com/problems/strobegrammatic-number/)

 **难度：** 🟢简单
 **主题：** 哈希表、两个指针、字符串

 ## 解决方案

 ## 问题理解

 该问题要求我们确定给定的数字字符串旋转 180 度后是否仍然有效且不变。 该属性称为“频闪”。 

频闪数字仅由旋转后仍代表有效数字的数字组成。 有效的转换是：

 -`0 -> 0`-`1 -> 1`-`6 -> 9`-`8 -> 8`-`9 -> 6`轮换后所有其他数字均无效。 例如，`2`,`3`,`4`,`5`， 和`7`颠倒旋转时不会映射到有效数字。 

输入以字符串而不是整数的形式提供，因为该操作基本上是基于字符的。 我们不是在执行算术运算，而是在检查数字序列在旋转下是否正确转换。 

预期输出是：

 -`true`如果旋转后的数字与原始数字匹配
 -`false`否则

 限制很小，最大长度为 50 个字符。 这告诉我们，性能不是主要问题，但我们仍然应该以干净高效的解决方案为目标。 由于输入仅包含数字且不包含无效字符，因此我们只需要验证旋转兼容性。 

一些边缘情况很重要：

 - 个位数的数字，例如`"0"`,`"1"`， 和`"8"`是有效的，因为它们映射到自身。 
- 个位数，例如`"2"`或者`"5"`无效，因为它们没有有效的轮换。 
- 奇数长度的数字必须有一个映射到其自身的中心数字，仅表示`0`,`1`， 或者`8`允许在中间。 
- 像这样的数字`6`和`9`必须出现在镜像位置，因为它们相互旋转。 

## 方法

 ### 蛮力方法

 强力解决方案将模拟完整的旋转过程。 我们可以反转字符串，然后用旋转后的对应数字替换每个数字，最后将转换后的结果与原始输入进行比较。 

例如：

 - 反向`"69"`要得到`"96"`- 旋转每个数字：

 -`9 -> 6`-`6 -> 9`- 结果变成`"69"`- 由于它与原始字符串匹配，因此该数字是频闪的。 

这种方法之所以有效，是因为颠倒旋转数字可以有效地反转数字的顺序，同时根据旋转映射变换每个数字。 

然而，这种方法需要构造一个全新的字符串。 尽管限制很小，但它使用了不必要的额外空间并执行了超出需要的工作。 

### 最佳方法

 关键的观察是我们实际上不需要构建旋转数。 

相反，我们可以使用两个指针比较字符串两端的字符：

 - 左边的数字必须旋转到右边的数字。 
- 右侧数字必须与左侧数字正确对应。 

例如：

 - 在`"69"`, 左边的数字`6`旋转成`9`，与右侧匹配。 
- 在`"88"`，两个数字都旋转到自身。 

这使我们能够在一次传递中验证数字，而无需构造新字符串。 

哈希映射在这里是理想的，因为它为每个数字的旋转对应项提供恒定时间查找。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 构建字符串 | 的旋转副本
 | 最佳| O(n) | O(1) | O(1) | 使用两个指针和常量大小的映射 |

 ## 算法演练

 1. 创建一个存储所有有效频闪数字映射的哈希映射。 

映射是：```
0 -> 0
1 -> 1
6 -> 9
8 -> 8
9 -> 6
```该结构允许恒定时间验证数字是否具有有效的旋转形式。 
2. 初始化两个指针。 

-`left = 0`-`right = len(num) - 1`左指针从字符串的开头开始，右指针从字符串的末尾开始。 
3. 比较数字`left <= right`。 

每一步：

 - 检查映射中是否存在左侧数字。 
- 如果不存在，则返回`False`。 
- 否则，验证左侧数字的旋转值是否等于右侧数字。 

这直接检查当前对是否形成有效的频闪关系。 
4. 将两个指针向内移动。 

- 增量`left`- 递减`right`继续，直到检查完所有对。 
5. 如果所有比较都成功，则返回`True`。 

这意味着每个数字对都满足旋转属性。 

### 为什么它有效

 该算法依赖于频闪数字的定义属性：左侧的每个数字必须旋转为右侧的相应数字。 

通过同时检查镜像位置，我们保证旋转 180 度后整个数字保持不变。 由于每对都是独立验证的，并且映射涵盖了所有有效旋转，因此该算法可以正确确定该数字是否是频闪图。 

## Python 解决方案```python
class Solution:
    def isStrobogrammatic(self, num: str) -> bool:
        rotation_map = {
            '0': '0',
            '1': '1',
            '6': '9',
            '8': '8',
            '9': '6'
        }

        left = 0
        right = len(num) - 1

        while left <= right:
            left_digit = num[left]
            right_digit = num[right]

            if left_digit not in rotation_map:
                return False

            if rotation_map[left_digit] != right_digit:
                return False

            left += 1
            right -= 1

        return True
```实现首先在字典中定义有效的旋转关系。 这允许恒定时间查找每个数字的旋转对应项。 

然后初始化两个指针以从字符串的两端向内扫描。 在每次迭代时，算法都会检查当前左边的数字是否可以旋转到当前右边的数字。 

如果数字无效或旋转后的映射与相反的一侧不匹配，则该函数立即返回`False`。 

如果所有镜像对满足条件，则循环完成并且函数返回`True`。 

该实现严格遵循频闪数的数学定义，并避免不必要的字符串构造。 

## 解决方案```go
func isStrobogrammatic(num string) bool {
    rotationMap := map[byte]byte{
        '0': '0',
        '1': '1',
        '6': '9',
        '8': '8',
        '9': '6',
    }

    left := 0
    right := len(num) - 1

    for left <= right {
        leftDigit := num[left]
        rightDigit := num[right]

        rotatedDigit, exists := rotationMap[leftDigit]

        if !exists {
            return false
        }

        if rotatedDigit != rightDigit {
            return false
        }

        left++
        right--
    }

    return true
}
```Go 实现遵循与 Python 版本相同的逻辑。 主要区别在于 Go 字符串以字节为索引，因此哈希映射使用`byte`键和值而不是字符串。 

Go 还需要使用显式处理地图查找`exists`布尔值来确定密钥是否存在。 

由于输入长度非常小，因此不存在内存使用或溢出的问题。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个数字最多检查一次 |
 | 空间| O(1) | O(1) | 旋转映射包含固定数量的条目 |

 该算法使用两个向中心移动的指针来处理字符串。 每次迭代执行恒定时间工作，从而产生线性时间复杂度。 

额外的空间使用量是恒定的，因为无论输入大小如何，哈希映射始终包含恰好五个映射。

 ## 边缘情况

 一个重要的边缘情况是单位数字输入。 仅有的`0`,`1`， 和`8`旋转后仍然有效，因为它们映射到自身。 数字如`6`和`9`不能单独出现，因为旋转它们会改变数字。 该实现自然地处理了这个问题，因为左指针和右指针在相同的索引处相遇，并且映射检查确保数字映射到其自身。 

另一个重要的情况是奇数长度数字。 在这些输入中，中间数字没有镜像伙伴，因此它必须是自旋转的。 例如，`"818"`有效，因为中心数字是`1`， 尽管`"696"`无效，因为中间数字`9`旋转成`6`。 条件`left <= right`确保正确检查中间数字。 

第三种边缘情况涉及无效数字，例如`2`,`3`,`4`,`5`， 和`7`。 这些数字没有有效的旋转表示。 幼稚的实现可能会忘记明确拒绝它们。 该解决方案通过在尝试比较之前检查旋转图中是否存在每个数字来避免该问题。 如果数字不存在，函数立即返回`False`。
