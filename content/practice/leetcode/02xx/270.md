[LeetCode 第 270 题](https://leetcode.com/problems/closest-binary-search-tree-value/)

 **难度：** 🟢简单
 **主题：** 二分搜索、树、深度优先搜索、二分搜索树、二叉树

 ## 解决方案

 ## 问题理解

 该问题为我们提供了二叉搜索树（缩写为 BST）的根和浮点目标值。 我们的任务是返回 BST 中存储的在数值上最接近目标的整数值。 

二叉搜索树有一个非常重要的属性：

 - 左子树中的每个节点都包含比当前节点小的值。 
- 右子树中的每个节点都包含比当前节点更大的值。 

这种排序属性是使我们能够有效解决问题的关键观察结果。 

输入包括：

 -`root`，BST的根节点
 -`target`，一个浮点数，可能存在于树中，也可能不存在

 预期输出是：

 - 其绝对差值的节点值`target`是最小的
 - 如果两个值同样接近，我们必须返回较小的一个

 例如，如果目标是`3.7`并且树包含值`3`和`4`， 然后`4`更接近，因为：

 -`|3.7 - 3| = 0.7`-`|3.7 - 4| = 0.3`因此答案是`4`。 

这些约束告诉我们一些重要的事情：

 - 树包含之间`1`和`10^4`节点
 - 节点值可以非常大，最多`10^9`- 目标甚至可能超出所有节点值的范围

 由于树最多可以包含一万个节点，因此线性遍历是可以接受的，但 BST 结构表明我们可以比扫描每个节点做得更好。 

一些边缘情况很重要：

 - 树可能只包含一个节点
 - 目标可能小于 BST 中的每个值
 - 目标可能大于 BST 中的每个值
 - 两个值可能同样接近目标，在这种情况下我们必须返回较小的值
 - 目标可能与节点值完全匹配

 该问题保证树是非空的，因此我们永远不需要将空根作为整个输入来处理。 

## 方法

 ### 蛮力方法

 最简单的方法是遍历整个树并将每个节点值与目标进行比较。 

在遍历过程中，我们跟踪：

 - 当前最接近的值
 - 迄今为止看到的最小绝对差异

 对于每个节点：

 1. 计算`abs(node.val - target)`2. 与当前最佳差值进行比较
 3. Update the answer if this node is closer
 4. 如果差值相等，则选择较小的值

 这种方法是正确的，因为它检查树中的每个节点，保证最终找到最接近的值。 

However, this ignores the BST property entirely. 即使树是有序的，暴力解决方案仍然会访问所有节点。 

### 最优 BST 方法

 BST 属性使我们能够做出更明智的决策。 

在每个节点：

 - 如果`target < node.val`，那么任何可能更接近的值必须位于左子树中
 - 如果`target > node.val`，那么任何可能更接近的值都必须位于右子树中

 这意味着我们可以沿着树沿着单一路径前进，而不是探索每个节点。 

在遍历的过程中，我们不断地维护迄今为止遇到的最接近的值。 

关键的见解是 BST 排序让我们在每一步丢弃一半的剩余搜索空间，类似于排序数组上的二分搜索。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(h) 递归或 O(n) 最坏情况 | 遍历每个节点 |
 | 最佳 | 平均 O(h)，最坏情况 O(n) | O(1) 迭代 | 使用 BST 排序来跳过子树 |

 这里：

-`n`是节点数
 -`h`是树的高度

 在平衡 BST 中，`h = log n`，使得最优解非常高效。 

## 算法演练

 1. 初始化一个名为`closest`与根值。 

我们需要一些初步的候选答案。 由于树保证非空，因此根值是一个安全的起点。 
2、从根节点开始遍历。 

我们使用一个名为`current`迭代地遍历 BST。 
3. 在每个节点，将其值与当前最佳答案进行比较。 

我们计算：```
abs(current.val - target)
```并将其与以下内容进行比较：```
abs(closest - target)
```如果当前节点更接近，我们更新`closest`。 

如果两个距离相等，我们选择较小的值，因为问题明确需要打破平局规则。 
4. 决定接下来要探索哪个子树。 

BST 属性告诉我们哪里可能存在更好的候选者。 

- 如果`target < current.val`, 向左移动
 - 如果`target > current.val`, 向右移动
 - 如果它们相等，我们可以立即返回，因为没有任何值可以比精确匹配更接近
 5.继续，直到遍历到空节点。 

一次`current`变成`None`或者`nil`，我们已经用尽了唯一相关的搜索路径。 
6.返回存储的`closest`价值。 

### 为什么它有效

 该算法之所以有效，是因为 BST 是有序的。 在每个节点，我们知道整个子树不能包含更接近目标的值。 

如果目标小于当前值，则右子树中的每个值都会更大，从而使它们的前景较差。 类似地，如果目标更大，左子树就变得不太有用。 

通过始终向可能存在更接近值的一侧移动，我们可以有效地仅搜索相关路径，同时不断维护迄今为止遇到的最佳候选路径。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional

class Solution:
    def closestValue(self, root: Optional[TreeNode], target: float) -> int:
        closest = root.val
        current = root

        while current:
            current_diff = abs(current.val - target)
            closest_diff = abs(closest - target)

            if (
                current_diff < closest_diff
                or (
                    current_diff == closest_diff
                    and current.val < closest
                )
            ):
                closest = current.val

            if target < current.val:
                current = current.left
            elif target > current.val:
                current = current.right
            else:
                return current.val

        return closest
```实现首先将根值存储为当前最佳候选值。 由于保证树至少包含一个节点，因此该初始化始终有效。 

这`while current:`循环迭代地遍历 BST。 这避免了递归并保持空间复杂度恒定。 

在循环内部，代码计算当前节点和目标之间的距离，然后将其与迄今为止看到的最佳距离进行比较。 

更新条件处理两种情况：

 - 当前节点更接近
 - 当前节点同样接近但较小，满足平局要求

 如有必要，更新候选答案后，使用 BST 排序确定遍历方向：

 - 当目标较小时向左移动
 - 当目标较大时向右移动
 - 完全匹配时立即返回

 一旦遍历从树上掉下来，循环就会结束，并返回最好的存储值。 

## 解决方案```go
import "math"

/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func closestValue(root *TreeNode, target float64) int {
    closest := root.Val
    current := root

    for current != nil {
        currentDiff := math.Abs(float64(current.Val) - target)
        closestDiff := math.Abs(float64(closest) - target)

        if currentDiff < closestDiff ||
            (currentDiff == closestDiff && current.Val < closest) {
            closest = current.Val
        }

        if target < float64(current.Val) {
            current = current.Left
        } else if target > float64(current.Val) {
            current = current.Right
        } else {
            return current.Val
        }
    }

    return closest
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

一个重要的区别是 Go 需要整数和浮点值之间的显式类型转换。 自从`target`是一个`float64`，在减法和比较之前必须转换节点值。 

Go 还使用`nil`而不是`None`对于空指针。 

迭代遍历避免了递归，因此除了一些局部变量之外不需要额外的堆栈空间。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | 平均 O(h)，最坏情况 O(n) | 遍历一条 BST 路径 |
 | 空间| O(1) | O(1) | 使用迭代遍历 |

 该算法仅遵循从根到叶的单一路径。 在平衡 BST 中，高度是对数，因此运行时间变为`O(log n)`。 

在最坏的情况下，BST 可能会像链表一样完全倾斜，使得高度等于`n`。 在这种情况下，运行时间会降低到`O(n)`。 

该实现是迭代的，并且仅存储几个变量，因此辅助空间的使用保持不变。

 ## 边缘情况

 当树仅包含单个节点时，会出现一种重要的边缘情况。 粗心的实现可能会假设子级的存在并尝试无效的遍历操作。 在此实现中，算法安全地初始化`closest`具有根值，一旦遍历到达就退出`None`或者`nil`。 

另一个关键的边缘情况是目标位于 BST 中所有值的范围之外。 例如，目标可能远小于最小节点值或远大于最大节点值。 在这些情况下，遍历自然会向树的最边缘继续，并且保留最接近的边界值作为答案。 

平局决胜规则也很容易被误用。 如果两个值同样接近目标，则问题需要返回较小的值。 仅在严格较小的距离上更新的幼稚实现可能会根据遍历顺序错误地返回较大的值。 该解决方案显式检查是否存在相等差异，并且更喜欢较小的整数。 

最后的边缘情况涉及高度不平衡的树。 BST 可以退化为链表，产生高度`n`而不是`log n`。 在某些环境中，递归实现可能会面临堆栈溢出的风险。 这里使用的迭代方法完全避免了递归并安全地处理倾斜树。
