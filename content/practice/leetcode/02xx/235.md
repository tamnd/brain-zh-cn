[LeetCode 第 235 题](https://leetcode.com/problems/lowest-common-ancestor-of-a-binary-search-tree/)

 **难度：** 🟡 中等
 **主题：** 树、深度优先搜索、二叉搜索树、二叉树

 ## 解决方案

 ## 问题理解

 该问题要求我们找到二叉搜索树 (BST) 中两个节点的最低公共祖先（通常缩写为 LCA）。 

两个节点的最低共同祖先`p`和`q`是树中最深的节点，同时具有`p`和`q`作为后代。 节点可以是其自身的后代，这意味着如果一个目标节点直接位于到另一个目标节点的路径上，则祖先可能只是该节点本身。 

输入包括：

 -`root`，二叉搜索树的根节点
 -`p`, 1个目标节点
 -`q`,另一个目标节点

 输出应该是代表它们最低公共祖先的树节点。 

重要的细节是该树具体是二叉搜索树。 在二叉搜索树中：

 - 左子树中的每个节点的值都小于当前节点
 - 右子树中的每个节点都有比当前节点更大的值

 这个属性可以提供有效的解决方案。 

这些约束告诉我们一些重要的事情：

 - 树最多可以包含`10^5`节点，因此低效的算法可能会超时
 - 所有值都是唯一的，保证每个节点都可以通过其值来识别
 - 两者`p`和`q`保证存在于树中
 -`p != q`，所以我们永远不需要处理相同的目标节点

 一些边缘情况很重要：

 - 一个节点可能是另一个节点的祖先
 - 根本身可能是LCA
 - 两个节点可能完全位于左子树中
 - 两个节点可能完全位于右子树中
 - 树可能高度不平衡，表现得几乎像一个链表

 忽略 BST 属性的简单实现可能仍然有效，但会错过重要的优化机会。 

## 方法

 ### 蛮力方法

 暴力解决方案将树视为普通二叉树并忽略 BST 排序属性。 

一种常见的策略是：

 1.使用DFS或BFS为每个节点构建父指针
 2. 存储节点的所有祖先`p`3.从节点向上遍历`q`4. 始祖也出现在`p`的祖先集是 LCA

 这种方法之所以有效，是因为每个节点都有一条到根的路径。 最终，向上遍历`q`必须与祖先链相交`p`。 

但是，此解决方案需要额外的内存用于父映射和祖先集。 它还执行不必要的遍历，因为它忽略了已经告诉我们要搜索的位置的 BST 结构。 

### 最佳方法

 关键的见解来自 BST 排序属性。 

假设当前节点有值`x`。 

- 如果两者都`p`和`q`小于`x`，那么两个节点必须位于左子树中
 - 如果两者都`p`和`q`大于`x`，那么两个节点必须位于右子树中
 - 否则，当前节点位于它们之间，或者等于其中之一，这意味着它是最低公共祖先

 这使我们能够从根部向下走，同时缩小每一步的搜索空间。 

由于每个决策都会消除剩余树结构的一半，因此该算法非常高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 建立父母关系和祖先集 |
 | 最佳| O(h) | O(1) | O(1) | 利用BST排序直接定位分割点|

 这里，`h`代表树的高度。 

## 算法演练

 1. 从 BST 的根节点开始。 
2. 比较值`p`和`q`与当前节点的值。 
3. 如果两个目标值都小于当前节点的值，则移至左子节点。 

这是可行的，因为 BST 属性保证两个节点必须位于左子树中。 
4. 如果两个目标值都大于当前节点的值，则移至右子节点。 

同样，BST 属性保证两个节点必须位于右子树中。 
5. 否则，当前节点为分割点。 

这意味着：

 - 一个节点位于左侧，另一个节点位于右侧，或者
 - 当前节点等于目标之一
 6. 返回当前节点作为最低公共祖先。 

### 为什么它有效

 BST 属性保证所有较小的值位于左子树中，所有较大的值位于右子树中。 只要两个目标节点位于当前节点的同一侧，我们就可以安全地继续在该子树中搜索。 目标分歧的第一个节点，或者一个目标等于当前节点的节点，必须是包含两个后代的最低节点。 因此，该节点就是 LCA。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, x):
#         self.val = x
#         self.left = None
#         self.right = None

from typing import Optional

class Solution:
    def lowestCommonAncestor(
        self,
        root: 'TreeNode',
        p: 'TreeNode',
        q: 'TreeNode'
    ) -> 'TreeNode':

        current = root

        while current:
            if p.val < current.val and q.val < current.val:
                current = current.left
            elif p.val > current.val and q.val > current.val:
                current = current.right
            else:
                return current
```实现从一个名为的指针开始`current`初始化为根节点。 

在循环内，算法将两个目标值与当前节点的值进行比较。 

如果两个目标都较小，则搜索向左移动。 如果两者都较大​​，则搜索向右移动。 由于 BST 排序，这些动作保证是正确的。 

这`else`条件处理临界分割点。 此时，要么：

 - 目标位于相对两侧，或者
 - 一个目标等于当前节点

 无论哪种情况，当前节点都是最低公共祖先，因此会立即返回。 

迭代方法避免了递归堆栈开销并保持空间复杂度恒定。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val   int
 *     Left  *TreeNode
 *     Right *TreeNode
 * }
 */

func lowestCommonAncestor(root, p, q *TreeNode) *TreeNode {
	current := root

	for current != nil {
		if p.Val < current.Val && q.Val < current.Val {
			current = current.Left
		} else if p.Val > current.Val && q.Val > current.Val {
			current = current.Right
		} else {
			return current
		}
	}

	return nil
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

Go 使用`nil`而不是Python的`None`。 指针遍历是显式的`*TreeNode`参考。 该算法保持迭代，即使对于高度不平衡的树也可以避免递归堆栈增长。 

决赛`return nil`从技术上讲是不可达的，因为该问题保证两个节点都存在于 BST 中，但它满足 Go 的所有控制路径都返回一个值的要求。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(h) | 每树级别最多访问一个节点 |
 | 空间| O(1) | O(1) | 仅使用几个指针变量 |

 该算法向下遍历树而无需重新访问节点。 在最坏的情况下，它遵循单一的根到叶路径。 

对于平衡 BST，高度`h`是`O(log n)`，所以该算法非常高效。 

对于完全不平衡的 BST，高度变为`O(n)`，使最坏情况下的运行时间呈线性。 

迭代实现使用恒定的额外内存，因为它不分配辅助数据结构或递归堆栈。

 ## 边缘情况

 ### 一个节点是另一个节点的祖先

 当一个目标节点在其子树中直接包含另一个目标节点时，就会出现一种非常常见的错误来源。 一些不正确的实现继续深入搜索而错过了正确的答案。 

例如：```
    2
   /
  1
```如果`p = 2`和`q = 1`，正确答案是`2`。 

该实现自然地处理了这个问题，因为当当前节点位于两个目标之间或等于其中一个目标时，算法立即返回。 

### 根是最低的共同祖先

 当目标位于根的不同子树中时，会发生另一个重要情况。 

例如：```
      6
     / \
    2   8
```一个目标小于`6`另一个大于`6`。 

该算法立即检测到分裂并返回根，无需不必要的遍历。 

### 高度不平衡的树

 BST 可以退化为链表：```
1
 \
  2
   \
    3
     \
      4
```对于极深的树，递归实现可能会面临堆栈溢出的风险。 

迭代实现完全避免了这个问题，因为它使用循环而不是递归。 即使身高变成`O(n)`，内存使用量保持不变。
