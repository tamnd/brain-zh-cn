 **难度：** 🔴难
 **主题：** 数学、字符串、回溯

 ## 解决方案

 ## 问题理解

 问题给了我们一个数字字符串`num`和一个整数`target`。 我们必须插入二元运算符，具体来说`'+'`,`'-'`， 和`'*'`，在字符串的数字之间，以便生成的数学表达式精确计算为`target`。 

重要的细节是我们不允许对数字重新排序。 我们可能只会决定：

 1. 在哪里将字符串分割成操作数
 2. 操作数之间放置哪个运算符

 例如，如果`num = "123"`，我们可以创建如下表达式：

 -`"1+2+3"`-`"1*2*3"`-`"12-3"`-`"1+23"`但我们不能将数字重新排列成类似的形式`"321"`。 

输出应包含计算结果为目标值的所有有效表达式。 

另一个关键规则是操作数不能包含前导零。 这意味着：

-`"0"`有效
 -`"5"`有效
 -`"10"`有效
 -`"05"`无效
 -`"00"`作为多位操作数无效

 此限制是此问题中最常见的错误来源之一。 

限制相对较小：

 -`num.length <= 10`乍一看，这似乎很小，但可能的表达式数量呈指数增长，因为在每个位置我们都可以：

 - 继续构建当前数量
 - 插入`+`- 插入`-`- 插入`*`这立即表明存在组合搜索问题。 

一个简单的实现可以生成每个可能的表达式字符串并随后对其进行评估，但是重复的解析和评估将是极其低效的。 更好的方法是逐步构建表达式，同时跟踪其评估值。 

有几个重要的边缘情况：

 - 包含零的字符串，例如`"105"`或者`"000"`- 需要乘法优先级的表达式
 - 较大的中间值
 - 不存在有效表达式的情况
 - 个位数输入

 乘法优先级问题尤其重要，因为表达式是根据正常算术规则求值的。 例如：```
1 + 2 * 3 = 7
```不是：```
(1 + 2) * 3 = 9
```任何正确的解决方案都必须在构造过程中正确处理运算符优先级。 

## 方法

 ### 蛮力方法

 蛮力策略是通过尝试数字之间所有可能的运算符插入来生成每个可能的表达式。 生成表达式后，我们使用解析器或内置评估函数对其进行评估。 

对于一个长度的字符串`n`， 有`n - 1`数字之间的间隙。 对于每个差距，我们都有几种选择：

 - 插入`+`- 插入`-`- 插入`*`- 不插入任何内容，意味着扩展当前数字

 这将创建指数数量的可能表达式。 

虽然暴力破解可以保证正确性，因为它会探索所有可能的表达式，但它的效率很低，因为：

 - 必须构造每个候选表达式
 - 然后必须解析和评估每个表达式
 - 运算符优先级必须单独处理
 - 可能会生成许多带有前导零的无效表达式

 重复的解析成本使得这种方法不必要地昂贵。 

### 最优回溯方法

 关键的见解是我们可以在构建表达式时逐步评估它们。 

我们不生成完整的表达式并稍后求值，而是维护：

 - 当前的表达式字符串
 - 当前评估值
 - 最后使用的操作数

 跟踪最后一个操作数是使乘法优先级正常工作的关键技巧。 

假设我们目前有：```
1 + 2
```有价值`3`。 

如果我们现在追加`*3`，正确的评价变为：```
1 + (2 * 3) = 7
```我们可以通过以下方式计算：```
current_value - last_operand + (last_operand * current_num)
```变成：```
3 - 2 + (2 * 3) = 7
```This eliminates the need for a full expression parser.

 The algorithm uses depth-first search with backtracking to explore all valid operator placements efficiently.

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(4^n * n) | O(4^n * n) | O(4^n * n) | O(4^n * n) | Generates all expressions, then evaluates each separately |
 | 最佳| O(4^n) | O(4^n) | O(n) 不包括输出 | Builds and evaluates expressions simultaneously using backtracking |

 ## 算法演练

 1. Start a depth-first search from the beginning of the string.

 At every recursive call, we decide what the next operand should be. Since operands may contain multiple digits, we try every possible substring starting at the current index.
 2. 逐位构建当前操作数。 

例如，从`"123"`在索引处`0`，我们可以选择：

 -`"1"`-`"12"`-`"123"`每个都成为候选操作数。 
3. 拒绝带有前导零的操作数。 

如果一个数字开头为`'0'`并且有超过一位数字，我们立即停止探索该分支。 

例如：

-`"0"`被允许
 -`"05"`被拒绝
 4. 对第一个操作数进行特殊处理。 

表达式中的第一个数字不能有前面的运算符。 

所以对于第一个递归步骤：

 - 表达式变为`"1"`- 当前值变为`1`- 最后一个操作数变为`1`5. 对于后面的所有操作数，尝试所有三个运算符。 

假设当前操作数是`current_num`。 

补充：```
new_value = current_value + current_num
```最后一个操作数变为正数`current_num`。 
6. 对于减法：```
new_value = current_value - current_num
```最后一个操作数变为负数`current_num`。 

将其存储为负数很重要，因为乘法调整取决于符号。 
7. 对于乘法，调整优先级。 

假设我们目前有：```
expression = "1+2"
current_value = 3
last_operand = 2
```追加`*3`应该产生：```
1 + (2 * 3)
```我们计算：```
new_value = current_value - last_operand + (last_operand * current_num)
```变成：```
3 - 2 + 6 = 7
```新的最后一个操作数变为：```
last_operand * current_num
```8. 继续递归，直到消耗完所有数字。 

当我们到达字符串末尾时：

 - 如果评估值等于`target`，我们将表达式添加到答案中。 
- 否则，我们将丢弃它。 

### 为什么它有效

 该算法之所以有效，是因为每个递归分支都代表一个唯一的有效表达式结构。 在每一步中，我们都会正确维护部分构建的表达式的评估值。 这`last_operand`机制保证乘法优先级完全按照标准算术要求进行处理。 由于每个有效的运算符放置和操作数分区都会被探索一次，因此该算法会找到所有正确的表达式，而不会重复。 

## Python 解决方案```python
from typing import List

class Solution:
    def addOperators(self, num: str, target: int) -> List[str]:
        result = []

        def backtrack(
            index: int,
            expression: str,
            current_value: int,
            last_operand: int
        ) -> None:
            if index == len(num):
                if current_value == target:
                    result.append(expression)
                return

            for end in range(index, len(num)):
                # Prevent leading zeros
                if end > index and num[index] == '0':
                    break

                current_str = num[index:end + 1]
                current_num = int(current_str)

                # First number in expression
                if index == 0:
                    backtrack(
                        end + 1,
                        current_str,
                        current_num,
                        current_num
                    )
                else:
                    # Addition
                    backtrack(
                        end + 1,
                        expression + "+" + current_str,
                        current_value + current_num,
                        current_num
                    )

                    # Subtraction
                    backtrack(
                        end + 1,
                        expression + "-" + current_str,
                        current_value - current_num,
                        -current_num
                    )

                    # Multiplication
                    backtrack(
                        end + 1,
                        expression + "*" + current_str,
                        current_value - last_operand + (last_operand * current_num),
                        last_operand * current_num
                    )

        backtrack(0, "", 0, 0)

        return result
```该实现使用递归回溯来探索所有可能的表达式。 

这`backtrack`函数维护四个状态：

 -`index`，字符串中的当前位置
 -`expression`，到目前为止构建的表达式
 -`current_value`, 表达式的计算结果
 -`last_operand`, 最近使用的操作数

 该循环生成从当前索引开始的所有可能的操作数。 

前导零检查非常重要：```python
if end > index and num[index] == '0':
    break
```这确保了像这样的值`"05"`从未被探索过。 

第一个操作数被单独处理，因为它不能有前面的运算符。 

对于所有后面的操作数，该函数递归地尝试：

 - 添加
 - 减法
 - 乘法

 乘法使用优先级调整公式：```python
current_value - last_operand + (last_operand * current_num)
```这模拟了正确的算术优先级，而不需要解析器或堆栈。 

当所有数字都被消耗完时，递归终止。 如果计算值等于目标，则表达式将添加到结果列表中。 

## 解决方案```go
package main

import (
	"strconv"
)

func addOperators(num string, target int) []string {
	var result []string

	var backtrack func(
		index int,
		expression string,
		currentValue int64,
		lastOperand int64,
	)

	backtrack = func(
		index int,
		expression string,
		currentValue int64,
		lastOperand int64,
	) {
		if index == len(num) {
			if currentValue == int64(target) {
				result = append(result, expression)
			}
			return
		}

		for end := index; end < len(num); end++ {
			// Prevent leading zeros
			if end > index && num[index] == '0' {
				break
			}

			currentStr := num[index : end+1]
			currentNum, _ := strconv.ParseInt(currentStr, 10, 64)

			// First operand
			if index == 0 {
				backtrack(
					end+1,
					currentStr,
					currentNum,
					currentNum,
				)
			} else {
				// Addition
				backtrack(
					end+1,
					expression+"+"+currentStr,
					currentValue+currentNum,
					currentNum,
				)

				// Subtraction
				backtrack(
					end+1,
					expression+"-"+currentStr,
					currentValue-currentNum,
					-currentNum,
				)

				// Multiplication
				backtrack(
					end+1,
					expression+"*"+currentStr,
					currentValue-lastOperand+(lastOperand*currentNum),
					lastOperand*currentNum,
				)
			}
		}
	}

	backtrack(0, "", 0, 0)

	return result
}
```Go 实现遵循与 Python 解决方案相同的递归策略。 

一个显着的区别是使用`int64`而不是`int`。 中间乘法结果可能超出正常的 32 位整数范围，因此使用`int64`避免溢出问题。 

Go 切片用于动态累积结果。 与 Python 列表不同，Go 切片需要显式追加操作。 

字符串连接很简单，因为最大输入长度仅为 10，因此在不使用`strings.Builder`。

 ## 边缘情况

 一种关键边缘情况涉及前导零。 输入如`"105"`很容易产生无效的操作数，例如`"05"`如果算法不小心。 许多简单的解决方案错误地允许这些表达式。 该实现通过在多位操作数开头时立即停止扩展来防止这种情况发生`'0'`。 

另一个重要的边缘情况是乘法优先级。 表达式如`"1+2*3"`必须评估为`7`， 不是`9`。 幼稚的从左到右的评估会产生不正确的结果。 该实现通过单独跟踪前一个操作数并在乘法期间调整运行总计来解决此问题。 

第三种边缘情况是重复的零，例如`"000"`。 这些输入生成许多有效的表达式，因为每个零都可以独立参与算术运算。 然而，像这样的操作数`"00"`保持无效。 递归结构小心地允许单位数零操作数，同时拒绝带有前导零的较长操作数。 

第四种边缘情况是整个字符串本身形成目标。 例如：```
num = "123"
target = 123
```该算法可以正确处理这一问题，因为一个递归分支选择整个剩余子字符串作为单个操作数，而无需插入运算符。 

最后，在某些语言中，大的中间乘法结果可能会溢出较小的整数类型。 Go 解决方案使用`int64`在递归求值期间安全地容纳中间计算。
