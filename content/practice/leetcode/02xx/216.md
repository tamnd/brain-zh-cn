[LeetCode 第 216 题](https://leetcode.com/problems/combination-sum-iii/)

 **难度：** 🟡 中等
 **主题：** 数组、回溯

 ## 解决方案

 ## 问题理解

 这个问题要求我们准确地生成所有唯一的组合`k`从范围中选择不同的数字`1`到`9`使得它们的总和等于`n`。 

每个数字只能在组合中使用一次。 这意味着像这样的组合`[1,1,5]`无效，因为该号码`1`被重复。 顺序也没关系，所以`[1,2,4]`和`[4,2,1]`代表相同的组合，并且只能在输出中出现一次。 

输入由两个整数组成：

 -`k`，我们必须选择的整数的确切数量
 -`n`，这些整数必须产生的目标总和

 输出应该是满足这两个条件的所有有效组合的列表。 

例如，如果`k = 3`和`n = 9`，我们需要所有由三个不同数字组成的组`1`通过`9`其总和是`9`。 有效答案是：

 -`[1,2,6]`-`[1,3,5]`-`[2,3,4]`限制相对较小：

 -`2 <= k <= 9`-`1 <= n <= 60`由于搜索空间很小，这强烈建议采用回溯或深度优先搜索解决方案。 只有九个可能的数字可供选择，因此递归地探索组合是可行的。 

一些边缘情况很重要：

 - 目标金额可能太小而无法实现。 例如，`k = 4`和`n = 1`。 
- 目标总和可能太大。 即使是最大的四位不同数字的总和也只能是`9+8+7+6 = 30`。 
- 我们必须避免由于不同的顺序而导致的重复组合。 
- 当当前总和已经超过目标时，我们必须尽早停止递归。 

这些观察结果引导我们采用剪枝的递归回溯解决方案。 

## 方法

 ### 蛮力方法

 蛮力方法是生成数字的每个可能的子集`1`通过`9`，然后过滤子集：

 - 准确包含`k`数字
 - 总和为`n`有`2^9 = 512`总共的子集，对于这个问题的规模来说实际上是可以管理的。 我们可以使用位掩码或递归生成每个子集，计算其大小和总和，并仅保留有效的子集。 

这种方法是正确的，因为每种可能的组合都会被检查一次。 

然而，它执行了不必要的工作，因为许多子集在该过程的早期显然是无效的。 例如：

 - 数字太多的子集
 - 总和已经超过的子集`n`- 不可能到达的子集`n`更智能的解决方案可以避免探索这些死胡同。 

### 最优方法，回溯与剪枝

 关键的见解是，我们不需要在决定每个子集是否有用之前完全生成它。 

我们可以使用回溯逐步构建组合：

 - 选择一个号码
 - 递归选择下一个数字
 - 如果部分组合无效，立即停止

 这很有效，因为：

 - 数字按递增顺序选择，防止重复
 - 每个数字最多使用一次
 - 递归自然地探索所有有效的组合
 - 修剪尽早消除了搜索树的大部分

 例如，如果当前总和已经超过`n`，没有理由继续探索这条道路。 

同样，如果当前组合已经包含超过`k`数字，我们立即停止。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^9 * 9) | O(2^9 * 9) | O(9) | 生成所有子集，然后过滤有效的子集 |
 | 最佳| O(C(9,k)) | O(C(9,k)) | O(k) | 回溯仅探索有用的组合 |

 ## 算法演练

 ### 步骤1，初始化结果列表

 创建一个名为的空列表`result`存储所有有效的组合。 

一旦我们准确找到每个有效组合，就会添加`k`总和等于的数字`n`。 

### 步骤2，定义回溯函数

 我们定义一个递归辅助函数来跟踪：

 - 我们可以使用的下一个号码
 - 当前正在构建的组合
 - 组合的当前总和

 该递归函数探索所有可能的有效延续。 

### 步骤 3，检查有效组合

 在每次递归调用的开始处：

 - 如果当前组合恰好有`k`数字
 - 当前总和等于`n`然后我们找到了一个有效的答案。 

我们将当前组合的副本附加到结果列表中。 

### 步骤 4，尽早修剪无效路径

 如果以下任一条件成立：

 - 当前总和超过`n`- 组合长度超过`k`那么继续下去是没有意义的。 

我们立即从递归返回。 

这种修剪显着减少了不必要的探索。 

### 步骤 5，尝试所有可能的下一个数字

 循环遍历从以下位置开始的所有候选编号`start`最多`9`。 

这`start`参数确保数字始终按升序选择。 

对于每个候选人编号：

 1. 将其添加到当前组合中。 
2. 递归：

 - 下一个起始数字为`num + 1`- 更新后的总和
 3. 之后删除该号码即可原路返回。 

这会一次性探索所有可能的有效组合。 

###第六步，返回结果

 递归完成后，返回有效组合列表。 

### 为什么它有效

 该算法系统地探索来自不同数字的所有组合`1`通过`9`。 

因为递归总是使用`num + 1`，相同的数字永远不会被重复使用，并且组合永远不会以不同的顺序生成。 

修剪保证我们永远不会浪费时间探索不可能的状态。 

每个有效组合最终都会被构造一次，因此该算法既完整又正确。 

## Python 解决方案```python
from typing import List

class Solution:
    def combinationSum3(self, k: int, n: int) -> List[List[int]]:
        result = []

        def backtrack(start: int, current: List[int], current_sum: int) -> None:
            if len(current) == k:
                if current_sum == n:
                    result.append(current[:])
                return

            if current_sum > n:
                return

            for num in range(start, 10):
                current.append(num)

                backtrack(
                    num + 1,
                    current,
                    current_sum + num
                )

                current.pop()

        backtrack(1, [], 0)

        return result
```解决方案首先创建一个名为的空列表`result`这将存储所有有效的组合。 

这`backtrack`函数负责递归地构建组合。 它接收三个参数：

 -`start`，我们可以使用的下一个数字
 -`current`，当前组合
 -`current_sum`, 当前组合的总和

 第一个基本情况检查组合是否已经完全包含`k`数字。 如果是，我们验证总和是否等于`n`。 如果两个条件都满足，我们会将当前组合的副本附加到结果列表中。 

如果总和已经超过目标，第二个修剪条件将停止递归。 

循环迭代自`start`通过`9`，确保按严格升序选择数字。 这可以防止重复并保证每个号码最多使用一次。 

对于每个候选人编号：

 - 我们将其添加到组合中
 - 递归探索更深层次的组合
 - 之后将其删除以恢复之前的状态

 这种添加-递归-删除模式是回溯的标准结构。 

最后，算法开始递归：

 - 起始号码`1`- 空组合
 - 总和`0`并返回完成的结果列表。 

## 解决方案```go
func combinationSum3(k int, n int) [][]int {
    result := [][]int{}
    current := []int{}

    var backtrack func(start int, currentSum int)

    backtrack = func(start int, currentSum int) {
        if len(current) == k {
            if currentSum == n {
                combination := make([]int, k)
                copy(combination, current)
                result = append(result, combination)
            }
            return
        }

        if currentSum > n {
            return
        }

        for num := start; num <= 9; num++ {
            current = append(current, num)

            backtrack(num+1, currentSum+num)

            current = current[:len(current)-1]
        }
    }

    backtrack(1, 0)

    return result
}
```Go 实现遵循与 Python 解决方案相同的递归结构。 

一个重要的区别是 Go 切片是对底层数组的引用。 因此，我们必须在将有效组合附加到之前创建一个复制的切片`result`。 否则，回溯期间的后续修改将影响之前存储的答案。 

该行：```go
combination := make([]int, k)
copy(combination, current)
```创建安全的独立副本。 

Go 还使用切片调整大小语法：```go
current = current[:len(current)-1]
```在回溯期间删除最后一个元素。 

这里不存在整数溢出问题，因为所有值都非常小。

 ## 边缘情况

 当目标总和太小而无法实现时，就会出现一种重要的边缘情况。 例如，`k = 4`和`n = 1`。 即使是最小的四个不同数字之和也等于`10`，因此不存在有效的解决方案。 简单的算法可能会继续进行不必要的探索，但是一旦运行总和超过目标，回溯解决方案就会快速修剪这些分支。 

当目标总和太大时，会发生另一种棘手的情况。 例如，`k = 2`和`n = 50`。 由于使用来自不同数字的最大可能总和`1`通过`9`是`17`对于两个数字（`8 + 9`），不存在解。 该算法自然会处理这个问题，因为递归最终会耗尽所有可能性而找不到匹配项。 

第三个重要的边缘情况涉及防止重复组合。 如果不小心处理，该算法可能会生成`[1,2,6]`和`[2,1,6]`。 该实现通过始终使用以下方法从严格增加的范围中选择未来的数字来避免这种情况`start`范围。 这保证了每个组合只生成一次。 

另一个微妙的边缘情况是确保数字不被重复使用。 由于递归调用前进到`num + 1`，一旦选择了一个数字，它以后就不能以相同的组合再次出现。 这正确地执行了“最多使用一次”的要求。
