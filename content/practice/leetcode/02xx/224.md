[LeetCode 第 224 题](https://leetcode.com/problems/basic-calculator/)

 **难度：** 🔴难
 **主题：** 数学、字符串、堆栈、递归

 ## 解决方案

 ## 问题理解

 该问题给出了一个字符串，表示包含整数、加法、减法、括号和空格的数学表达式。 我们的任务是计算表达式并返回最终的整数结果。 

该表达式保证有效。 这种保证非常重要，因为它简化了解析。 我们不需要担心格式错误的括号、无效的运算符或意外的字符。 每个表达式仅包含：

 - 数字
 -`'+'`-`'-'`-`'('`-`')'`- 空间

 计算器只需要支持加法和减法，但是括号引入了嵌套表达式，这使得问题变得更有趣。 简单的从左到右计算是不够的，因为必须首先计算括号内的表达式。 

例如：```
"(1+(4+5+2)-3)+(6+8)"
```要求我们在将嵌套子表达式组合到最终结果之前对其进行求值。 

另一个重要的细节是一元减号。 表达式如：```
"-1"
"-(2+3)"
```是有效的。 这意味着`-`并不总是意味着两个操作数之间的减法。 有时它会更改以下值或子表达式的符号。 

约束条件：```
1 <= s.length <= 3 * 10^5
```很大。 任何低效的解析策略都很容易超时。 重复子字符串提取或对字符串的大部分进行递归重新解析的成本太高。 我们需要一个能够在线性时间内处理字符串的解决方案。 

一些重要的边缘情况包括：

 - 前导负数，例如`"-5"`- 嵌套括号，例如`"((1+2)-3)"`- 括号前的一元减号，例如`"-(3+(2-1))"`- 带有许多空格的表达式
 - 多位数字，例如`"12345"`- 深度嵌套的表达式

 该问题保证所有中间结果和最终结果都适合有符号的 32 位整数，因此不需要溢出处理。 

## 方法

 ### 蛮力方法

 强力策略会尝试重复计算最里面的括号表达式。 该算法可以扫描字符串，找到匹配的括号，计算内部的值，用计算结果替换该子字符串，然后继续，直到没有括号剩余。 

例如：```
"(1+(4+5))"
```可能会变成：```
"(1+9)"
```然后：```
"10"
```这种方法在逻辑上是正确的，因为括号定义了可以逐步缩减的独立子表达式。 

然而，重复重建字符串的成本很高。 每个替换操作可能需要复制大部分字符串。 如果输入长度很大并且嵌套很深，则总复杂度可能会成二次方。 

最大长度为`3 * 10^5`， 一个`O(n^2)`解决办法太慢了。 

### 最佳方法

 关键的观察结果是，从左到右扫描一次字符串时，可以增量地计算加法和减法。 

我们可以维护：

 - 运行结果
 - 当前正在建造的数量
 - 当前标志
 - 输入括号时记住状态的堆栈

 每当我们遇到一个`(`，我们保存当前结果和符号，因为括号内的表达式应该独立计算，然后合并回外部表达式。 

每当我们遇到一个`)`，我们完成对当前子表达式的求值并将其与之前保存的上下文结合起来。 

这使我们能够以线性复杂度一次性处理表达式。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 在评估括号后重复重建字符串 |
 | 最佳| O(n) | O(n) | 使用堆栈进行嵌套表达式的单遍 |

 ## 算法演练

 1.初始化四个变量：

 -`result`存储当前累计值
 -`number`存储当前正在解析的数字
 -`sign`存储当前数字是否应该加或减
 -`stack`输入括号时存储先前的计算状态
 2. 逐个字符地遍历字符串。 
3. 如果当前字符是数字，则递增地构建该数字。 

例如：```
"123"
```被处理为：```
1 -> 12 -> 123
```使用：```
number = number * 10 + int(char)
```4.如果角色是`+`或者`-`，通过应用当前符号来确定前一个数字：```
result += sign * number
```然后更新下一个数字的符号：

 -`+`方法`sign = 1`-`-`方法`sign = -1`最后重置`number`到`0`。 
5. 如果角色是`(`，我们正在开始一个新的子表达式。 

输入之前：

 - 将当前结果压入堆栈
 - 将当前符号压入堆栈

 然后重置：```
result = 0
sign = 1
```这为内部表达式创建了一个新的求值上下文。 
6. 如果角色是`)`，先完成当前数：```
result += sign * number
```然后从堆栈中检索前一个符号和结果：```
prev_sign = stack.pop()
prev_result = stack.pop()
```将它们结合起来：```
result = prev_result + prev_sign * result
```重置`number`到`0`。 
7. 忽略空格，因为它们不影响评估。 
8. 循环结束后，最后一个数字可能仍处于未应用状态。 添加它：```
result += sign * number
```9. 返回最终结果。 

### 为什么它有效

 该算法保持不变式`result`始终包含当前表达式范围的计算值，不包括未完成的值`number`。 

每当括号开始时，先前的计算状态就会保留在堆栈中。 当括号关闭时，内部表达式将被完全求值，并使用保存的符号和结果正确地合并到外部表达式中。 

由于每个字符都被处理一次，并且嵌套上下文是通过堆栈进行管理的，因此该算法可以正确计算任意嵌套的有效表达式。 

## Python 解决方案```python
class Solution:
    def calculate(self, s: str) -> int:
        result = 0
        number = 0
        sign = 1
        stack = []

        for char in s:
            if char.isdigit():
                number = number * 10 + int(char)

            elif char == '+':
                result += sign * number
                number = 0
                sign = 1

            elif char == '-':
                result += sign * number
                number = 0
                sign = -1

            elif char == '(':
                stack.append(result)
                stack.append(sign)

                result = 0
                sign = 1

            elif char == ')':
                result += sign * number
                number = 0

                prev_sign = stack.pop()
                prev_result = stack.pop()

                result = prev_result + prev_sign * result

        result += sign * number

        return result
```实现直接遵循算法。`number`在扫描连续数字字符时累积多位整数。 这避免了昂贵的子串操作。 

每当一个`+`或者`-`遇到时，先前解析的数字被提交到`result`使用当前的标志。 然后该标志将更新为下一个号码。 

每当新的括号表达式开始时，堆栈都会存储两条信息：

 - 括号前累加的结果
 - 应用于括号表达式的符号

 当到达右括号时，当前子表达式将完成并使用保存的上下文合并回外部表达式。 

循环后的最后一个加法处理表达式以数字而不是运算符或括号结尾的情况。 

## 解决方案```go
func calculate(s string) int {
	result := 0
	number := 0
	sign := 1
	stack := []int{}

	for _, char := range s {
		if char >= '0' && char <= '9' {
			number = number*10 + int(char-'0')

		} else if char == '+' {
			result += sign * number
			number = 0
			sign = 1

		} else if char == '-' {
			result += sign * number
			number = 0
			sign = -1

		} else if char == '(' {
			stack = append(stack, result)
			stack = append(stack, sign)

			result = 0
			sign = 1

		} else if char == ')' {
			result += sign * number
			number = 0

			prevSign := stack[len(stack)-1]
			stack = stack[:len(stack)-1]

			prevResult := stack[len(stack)-1]
			stack = stack[:len(stack)-1]

			result = prevResult + prevSign*result
		}
	}

	result += sign * number

	return result
}
```Go 实现与 Python 版本几乎相同。 主要区别在于堆栈的显式切片操作。 

Go没有Python的动态列表弹出操作，因此我们手动访问最后一个元素并收缩切片。 

数字转换也略有不同：```go
int(char - '0')
```将符文数字转换为其整数值。 

该问题保证所有值都适合 32 位有符号整数，而 Go 的`int`type 在 LeetCode 上安全地处理这个范围。

 ## 边缘情况

 ### 开头的一元减号

 表达式例如：```
"-1"
```可以很容易地破坏假设每个`-`是二元减法运算符。 在此实现中，符号变量自然地处理一元减号。 什么时候`-`出现在数字之前，符号变为`-1`，并且下一个解析的数字被应用负数。 

### 括号前的一元减号

 表达式如：```
"-(2+3)"
```是错误的另一个常见来源。 简单的实现可能无法将负号应用于整个子表达式。 

该解决方案通过在输入括号之前将当前符号压入堆栈来正确处理这种情况。 当子表达式完成时，存储的符号将与计算结果相乘。 

### 多位数

 独立处理数字的解析器会错误地计算：```
"123"
```作为单独的值`1`,`2`， 和`3`。 

该实现使用以下方式逐步构建数字：```
number = number * 10 + int(char)
```它正确地形成任意大的多位整数。 

### 深层嵌套括号

 具有许多嵌套括号的表达式可能会导致递归解决方案溢出调用堆栈。 

此实现使用显式堆栈数据结构而不是递归函数调用，因此它可以安全地处理问题约束内的深层嵌套表达式。
