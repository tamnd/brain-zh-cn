 ## 解决方案

 ## 问题理解

 该问题要求我们从单链表中删除每个值等于给定整数的节点`val`。 当所有匹配的节点被删除后，我们必须返回修改后的链表的头。 

链表是一种线性数据结构，其中每个节点存储一个值和对下一个节点的引用。 与数组不同，链表不支持直接索引，因此通常通过更改节点指针来进行修改。 

输入由两部分组成：

 -`head`，它指向链表的第一个节点
 -`val`，应从列表中删除的整数值

 输出应该是删除所有匹配节点后更新的链表的头。 

例如，如果列表是：```
1 -> 2 -> 6 -> 3 -> 4 -> 5 -> 6
```和`val = 6`，那么每个节点包含`6`必须删除，导致：```
1 -> 2 -> 3 -> 4 -> 5
```这些约束告诉我们有关该问题的几个重要信息：

 - 该列表最多可以包含`10^4`节点，因此解决方案理想情况下应该以线性时间运行。 
- 节点值是小整数，但这不会显着影响算法设计，因为我们仍然需要检查每个节点。 
- 列表可能为空，这意味着`head`可以是`None`在 Python 中或`nil`在围棋中。 

一些边缘情况尤其重要：

 - 该列表可能从一开始就是空的。 
- 可能需要删除所有节点。 
- 头节点本身可能需要删除。 
- Multiple consecutive nodes may contain the target value.
 - 没有节点可以包含目标值。 

当必须删除头节点时，幼稚的实现通常会失败，因为删除第一个节点会更改列表的起点。 正确的指针管理至关重要。 

## 方法

 A brute-force approach would repeatedly scan the linked list and remove one matching node at a time until no matching nodes remain. 每次遍历都会再次遍历列表，导致不必要的重复工作。 While this method eventually produces the correct answer, it is inefficient because the same nodes may be visited many times.

 A better solution comes from recognizing that we only need a single traversal. As we move through the list, we can immediately decide whether to keep or remove each node. 关键的挑战是安全地处理列表开头的删除。 To simplify this, we use a dummy node placed before the actual head.

 The dummy node acts as a stable predecessor for the head. This eliminates special-case logic when the first node must be deleted. 在遍历过程中，我们检查`current.next`而不是`current`，允许我们通过更改指针来删除节点，而不会失去对列表其余部分的访问。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 重复扫描列表并一次删除一个节点 |
 | 最佳| O(n) | O(1) | O(1) | 使用指针操作和虚拟节点进行单次遍历 |

 ## 算法演练

 1. 创建一个虚拟节点，其`next`指针引用列表的原始头。 这个虚拟节点简化了删除逻辑，因为每个真实节点现在都有一个前任节点，包括原始头。 
2. 初始化一个名为`current`到虚拟节点。 该指针将在列表中移动并在每一步检查下一个节点。 
3. 遍历列表 while`current.next`不是`None`。 我们检查下一个节点而不是当前节点，因为删除操作需要访问前一个节点。 
4.如果`current.next.val == val`，通过跳过节点来删除它：```
current.next = current.next.next
```这会更改指针，以便不需要的节点不再连接到列表。 
5. 如果下一个节点不包含目标值，则移动`current`向前继续遍历。 
6. 继续，直到到达列表末尾。 
7. 返回`dummy.next`，它指向已修改列表的更新头部。 

### 为什么它有效

 该算法保持了之前所有节点的不变性`current`已经被正确处理并且不包含可移除的值。 通过始终检查`current.next`，该算法可以安全地删除节点，而不会失去对剩余列表的访问。 虚拟节点保证即使是原始头也可以被统一移除，因此所有情况都得到一致的处理。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

class Solution:
    def removeElements(self, head: Optional[ListNode], val: int) -> Optional[ListNode]:
        dummy = ListNode(0)
        dummy.next = head
        
        current = dummy
        
        while current.next:
            if current.next.val == val:
                current.next = current.next.next
            else:
                current = current.next
        
        return dummy.next
```实现首先创建一个虚拟节点并将其附加到原始头之前。 这避免了对头部移除案例的特殊处理。 

这`current`指针从虚拟节点开始。 在遍历过程中，算法总是检查`current.next`。 这种设计很重要，因为删除一个节点需要修改前一个节点的`next`指针。 

当找到匹配节点时，算法通过分配来跳过它：```python
current.next = current.next.next
```这会将不需要的节点与链表断开。 

如果该节点应保留在链表中，则遍历指针将正常前进。 

最后该方法返回`dummy.next`，在所有删除完成后，它指向正确的头。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func removeElements(head *ListNode, val int) *ListNode {
    dummy := &ListNode{Next: head}
    
    current := dummy
    
    for current.Next != nil {
        if current.Next.Val == val {
            current.Next = current.Next.Next
        } else {
            current = current.Next
        }
    }
    
    return dummy.Next
}
```Go 实现遵循与 Python 版本相同的逻辑。 主要区别在于指针的使用和`nil`而不是`None`。 

虚拟节点是使用以下命令创建的：```go
dummy := &ListNode{Next: head}
```指针操作在 Go 中自然有效，因为链表是基于引用的结构。 除了虚拟节点之外，不需要额外的内存分配。 

不存在整数溢出问题，因为该算法仅执行指针操作和比较。

 ## 边缘情况

 当链表为空时，会出现一种重要的边缘情况。 幼稚的实现可能会尝试访问`head.val`立即，导致空引用错误。 在这个实现中，遍历条件检查`current.next`在访问任何节点字段之前，因此安全返回空列表`None`或者`nil`。 

当必须删除头节点本身时会发生另一个关键情况。 许多不正确的解决方案都会失败，因为它们在删除后丢失了对新头的引用。 虚拟节点通过确保实际头之前始终有一个稳定的前驱节点，优雅地解决了这个问题。 即使必须删除多个前导节点，算法也能继续正常工作。 

第三个重要情况是每个节点都包含目标值。 在这种情况下，会在不推进遍历指针的情况下发生重复删除。 此行为是有意为之，因为删除一个节点后，下一个节点可能也需要删除。 最终，所有节点都被跳过，并且`dummy.next`变成`None`，正确生成一个空列表。
