[LeetCode 第 232 题](https://leetcode.com/problems/implement-queue-using-stacks/)

 **难度：** 🟢简单
 **主题：** 堆栈、设计、队列

 ## 解决方案

 ## 问题理解

 该问题要求我们仅使用堆栈操作来实现队列。 队列遵循 FIFO（先进先出）原则。 第一个插入队列的元素必须是第一个移除的元素。 相比之下，堆栈遵循 LIFO（后进先出）原则，即首先删除最近插入的元素。 

我们必须设计一个`MyQueue`类的行为与普通队列完全相同，但内部仅使用堆栈。 所需的操作是：

 -`push(x)`在队列末尾插入一个元素
 -`pop()`删除并返回前面的元素
 -`peek()`返回前面的元素而不删除它
 -`empty()`检查队列是否包含任何元素

 重要的限制是我们只能使用标准的堆栈操作，例如推入顶部、从顶部弹出、检查顶部元素以及测试堆栈是否为空。 

示例中显示的输入表示对队列对象执行的一系列方法调用。 输出数组包含每个操作的返回值。 类似的操作`push()`返回`null`因为它们不产生价值，而`peek()`,`pop()`， 和`empty()`返回实际结果。 

约束非常小，最多 100 个操作，因此几乎任何合理的实现都会通过。 然而，后续特别要求摊销`O(1)`执行，才是问题的真正目标。 这意味着，尽管某些单独的操作有时可能需要更长的时间，但许多操作中每次操作的平均成本应保持不变。 

一些边缘情况很重要：

 - 通话`pop()`或者`peek()`当队列只有一个元素时
 - 连续表演多次`push()`任何操作之前`pop()`- 交替表演`push()`和`pop()`运营
 - 检查`empty()`删除所有元素后

 该问题保证了每个`pop()`和`peek()`调用是有效的，因此我们永远不需要处理空队列上的操作。 

## 方法

 ### 蛮力方法

 一个简单的解决方案使用单个堆栈，并在每次插入新值时重新排列元素。 

由于堆栈会删除最近插入的元素，因此最新的项目始终出现在顶部。 然而，队列需要最旧的元素在前面。 为了用一个堆栈模拟队列行为，我们可以在插入期间临时将所有元素移动到另一个堆栈中。 

该过程的工作原理如下：

 1. 将主堆栈中的每个元素移动到临时堆栈中。 
2. 将新元素压入主堆栈。 
3. 将所有内容从临时堆栈移回。 

重新排列后，最旧的元素最终位于主堆栈的顶部，这使得`pop()`和`peek()`才能正常工作。 

这种方法是正确的，因为它在每次插入后保留队列顺序。 然而，每个`push()`操作可能需要将所有现有元素移动两次，从而使得插入成本高昂。 

### 最佳方法

 最佳解决方案使用两个堆栈：

 -`input_stack`存储新推送的元素
 -`output_stack`提供弹出和查看的队列顺序访问

 关键点是反转元素两次可以恢复 FIFO 顺序。 

当元素被推入`input_stack`，它们以相对于队列的相反顺序存储。 当我们需要删除或检查前面的元素时，我们将从中转移所有元素`input_stack`进入`output_stack`。 这种反转使得最旧的插入元素出现在`output_stack`。 

转移后，我们继续使用`output_stack`为了未来`pop()`和`peek()`操作，直到再次变空。 

重要的优化是每个元素最多在堆栈之间移动一次。 因此，虽然转移操作有时可能会花费`O(n)`，许多操作中每次操作的平均成本变为`O(1)`摊销时间。

 ## 算法演练

 1.创建两个栈，命名为`input_stack`和`output_stack`。 

这`input_stack`用于所有传入元素。 这`output_stack`按队列顺序删除或查看元素时使用。 
2. 对于`push(x)`，将元素附加到`input_stack`。 

这个操作很简单，因为堆栈天然支持在恒定时间内在顶部插入。 
3.为了`pop()`和`peek()`,首先检查是否`output_stack`是空的。 

如果不为空，则前面的队列元素已经可用`output_stack`。 
4.如果`output_stack`为空，转移所有元素`input_stack`进入`output_stack`。 

此反转操作将插入顺序更改为队列顺序。 最旧插入的元素成为顶部元素`output_stack`。 
5. 传输完成后，进行所需操作`output_stack`。 

-`pop()`删除并返回顶部元素
 -`peek()`返回顶部元素而不删除它
 6. 对于`empty()`，检查两个堆栈是否为空。 

仅当堆栈均不包含元素时，队列才为空。 

### 为什么它有效

 该算法保持了一个重要的不变量：

 -`input_stack`存储新插入的元素
 -`output_stack`以正确的出队顺序存储元素

 每当`output_stack`变空，转移所有元素`input_stack`颠倒他们的顺序。 由于堆栈自然会颠倒顺序，因此最早插入的元素首先可访问，这与 FIFO 队列行为完全匹配。 

由于每个元素最多被推送和传输一次，因此许多操作的总工作量保持线性，从而摊销`O(1)`复杂。 

## Python 解决方案```python
class MyQueue:

    def __init__(self):
        self.input_stack = []
        self.output_stack = []

    def push(self, x: int) -> None:
        self.input_stack.append(x)

    def _transfer(self) -> None:
        while self.input_stack:
            self.output_stack.append(self.input_stack.pop())

    def pop(self) -> int:
        if not self.output_stack:
            self._transfer()

        return self.output_stack.pop()

    def peek(self) -> int:
        if not self.output_stack:
            self._transfer()

        return self.output_stack[-1]

    def empty(self) -> bool:
        return not self.input_stack and not self.output_stack

# Your MyQueue object will be instantiated and called as such:
# obj = MyQueue()
# obj.push(x)
# param_2 = obj.pop()
# param_3 = obj.peek()
# param_4 = obj.empty()
```该实现使用两个 Python 列表作为堆栈，因为列表在末尾支持高效的追加和弹出操作。 

构造函数初始化`input_stack`和`output_stack`。 这`push()`方法只是附加到`input_stack`，这始终是一个恒定时间操作。 

这`_transfer()`辅助方法将元素从`input_stack`到`output_stack`。 该方法仅在以下情况下被调用`output_stack`是空的，我们需要访问队列前端。 

两个都`pop()`和`peek()`首先确保`output_stack`包含元素。 如果没有，他们就会触发转移。 在那之后：

-`pop()`从中删除顶部元素`output_stack`-`peek()`读取顶部元素而不删除它

 的`empty()`方法检查两个堆栈是否为空。 如果任一堆栈包含元素，则队列仍然有数据。 

## 解决方案```go
type MyQueue struct {
	inputStack  []int
	outputStack []int
}

func Constructor() MyQueue {
	return MyQueue{
		inputStack:  []int{},
		outputStack: []int{},
	}
}

func (this *MyQueue) Push(x int) {
	this.inputStack = append(this.inputStack, x)
}

func (this *MyQueue) transfer() {
	for len(this.inputStack) > 0 {
		n := len(this.inputStack)

		value := this.inputStack[n-1]
		this.inputStack = this.inputStack[:n-1]

		this.outputStack = append(this.outputStack, value)
	}
}

func (this *MyQueue) Pop() int {
	if len(this.outputStack) == 0 {
		this.transfer()
	}

	n := len(this.outputStack)
	value := this.outputStack[n-1]
	this.outputStack = this.outputStack[:n-1]

	return value
}

func (this *MyQueue) Peek() int {
	if len(this.outputStack) == 0 {
		this.transfer()
	}

	return this.outputStack[len(this.outputStack)-1]
}

func (this *MyQueue) Empty() bool {
	return len(this.inputStack) == 0 && len(this.outputStack) == 0
}

/**
 * Your MyQueue object will be instantiated and called as such:
 * obj := Constructor();
 * obj.Push(x);
 * param_2 := obj.Pop();
 * param_3 := obj.Peek();
 * param_4 := obj.Empty();
 */
```Go 实现遵循与 Python 版本相同的逻辑，但使用切片而不是列表。 

Go 没有内置的堆栈类型，因此切片自然可以达到此目的。 追加到切片的行为就像压入堆栈，而删除最后一个元素则模拟弹出。 

与 Python 不同，Go 在删除元素时需要显式的切片操作。 要从堆栈中弹出，我们取出最后一个元素，然后使用切片语法缩小切片。 

不需要对整数溢出进行特殊处理，因为约束非常小。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | 摊销`O(1)`| 每个元素最多推送和传输一次 |
 | 空间|`O(n)`| 两个堆栈一起存储所有队列元素|

 尽管转移操作有时可能需要`O(n)`时间，每个元素仅从`input_stack`到`output_stack`一次。 在许多操作中，总工作量与插入元素的数量成正比。 因此，每个操作的摊余复杂度变为`O(1)`。 

空间复杂度为`O(n)`因为所有队列元素都必须存储在两个栈中。

 ## 边缘情况

 当队列仅包含单个元素时，会出现一种重要的边缘情况。 有缺陷的实现可能会在执行过程中意外删除该元素`peek()`或者之后无法正确更新内部状态`pop()`。 在这个实现中，`peek()`只读取顶部元素`output_stack`不删除它，同时`pop()`正确删除它。 移除后，两个堆栈都变空，所以`empty()`正确返回`True`。 

另一个重要的情况是连续执行多次`push()`任何操作之前`pop()`。 在这种情况下，所有元素都会累积在内部`input_stack`。 幼稚的实现可能会不必要地重复传输元素。 该解决方案通过延迟传输直到`output_stack`变空。 当第一个`pop()`或者`peek()`发生时，单个传输会恢复正确的队列顺序。 

第三种边缘情况涉及交替`push()`和`pop()`运营。 一些不正确的实现过于激进地传输元素或在重复转换期间丢失顺序。 此实现保留了正确性，因为元素已经在`output_stack`保持在那里直到耗尽，而新元素继续积累`input_stack`。 这种分离保证了旧元素总是在新元素之前被删除。 

最后一个微妙的边缘情况发生在`output_stack`多次删除后变为空，但是`input_stack`仍然包含新插入的元素。 该实现通过仅在必要时触发另一次传输来干净地处理此问题，确保队列顺序保持正确而无需冗余工作。
