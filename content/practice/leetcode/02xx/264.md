 ## 解决方案

 ## 问题理解

 该问题要求我们生成丑陋数字的序列并返回`n`该序列中的第一个值。 

丑数被定义为一个正整数，其唯一的质因数是`2`,`3`， 和`5`。 这意味着每个丑数都可以通过将先前的丑数乘以这三个素数之一来形成。 该序列开始于`1`，根据定义，这被认为是一个丑陋的数字。 

例如：

-`6`很丑因为`6 = 2 × 3`-`8`很丑因为`8 = 2 × 2 × 2`-`14`并不难看，因为它包含素因数`7`输入是单个整数`n`，代表丑数序列中的位置。 输出是`n`丑陋的数字按升序排列。 
约束条件`1 <= n <= 1690`很重要。 它告诉我们序列大小相对较小，这意味着预计算或动态编程方法是完全可行的。 然而，反复检查每个整数是否丑陋的简单暴力方法仍然会变得不必要的缓慢。 

有几种边缘情况值得立即认识：

 -`n = 1`应该返回`1`- 生成过程中可能会出现重复值，例如：

 -`6 = 2 × 3`-`6 = 3 × 2`- 生成的序列必须保持严格递增
 - 我们必须避免丢失丑陋的数字或插入重复的数字

 核心挑战是高效且按排序顺序生成丑陋的数字。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是逐个迭代正整数并确定每个数字是否丑陋。 

为了检查一个数字是否难看，我们反复将其除以`2`,`3`， 和`5`虽然可能。 如果最终结果变成`1`，那么该数字不包含其他素因数，因此很难看。 

例如：

-`30`- 除以`2`→`15`- 除以`3`→`5`- 除以`5`→`1`- 因此丑陋

 我们继续计算丑陋的数字，直到达到`n`第一个。 

这种方法是正确的，因为每个数字都经过明确验证。 然而，它的效率很低，因为我们检查了许多不难看的数字。 作为`n`随着增长，浪费的工作量变得越来越大。 

### 最优动态规划方法

 关键的见解是，每个丑数都是由前一个丑数乘以生成的`2`,`3`， 或者`5`。 

我们不检查每个整数，而是直接按排序顺序构建序列。 

假设我们已经知道丑陋的数字：```
1, 2, 3, 4, 5
```下一个丑陋的数字必须是以下之一：

 - 以前的丑数 × 2
 - 以前的丑数 × 3
 - 以前的丑数 × 5

 我们维护三个指针：

 - 一个代表下一个倍数`2`- 一个代表下一个倍数`3`- 一个代表下一个倍数`5`每一步：

 - 计算下一个候选人
 - 选择最小值
 - 将其附加到序列中
 - 前进产生所选值的任何指针

 这保证了排序顺序并有效避免重复。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 大约 O(n × k) | O(1) | O(1) | 单独检查每个整数是否丑陋 |
 | 最优动态规划| O(n) | O(n) | 直接按排序顺序构建难看的数字 |

 这里，`k`表示在暴力方法中进行因子检查时所需的划分数量。 

## 算法演练

 ### 最优动态规划算法

 1. 创建一个名为`ugly_numbers`尺寸的`n`。 

该数组按升序存储丑陋的数字。 将第一个值初始化为`1`因为序列总是以`1`。 
2.初始化三个指针：

 -`pointer2`-`pointer3`-`pointer5`这些指针指示接下来应该乘以之前生成的丑陋数字`2`,`3`， 或者`5`。 
3. 计算下一个候选者。 

在每次迭代时：

 -`next2 = ugly_numbers[pointer2] * 2`-`next3 = ugly_numbers[pointer3] * 3`-`next5 = ugly_numbers[pointer5] * 5`这些代表从每个质因数生成的下一个可能的丑数。 
4. 选择最小的候选者。 

下一个丑数必须是以下数字中的最小值：

 -`next2`-`next3`-`next5`将此最小值附加到序列中。 
5. 前进所有匹配的指针。 

如果所选值等于`next2`, 增量`pointer2`。 

如果它等于`next3`, 增量`pointer3`。 

如果它等于`next5`, 增量`pointer5`。 

这一步至关重要，因为同一个难看的数字可能会以多种方式产生。 

例子：```
6 = 2 × 3
6 = 3 × 2
```推进所有匹配的指针可以防止重复。 
6. 重复直到数组包含`n`丑陋的数字。 
7. 返回数组中的最终值。 

### 为什么它有效

 该算法保持不变式`ugly_numbers`总是排序的并且只包含有效的丑数。 

每个新生成的数字都来自于将现有的丑数乘以`2`,`3`， 或者`5`，所以每个产生的数字都肯定是丑陋的。 

因为我们总是选择最小的可用候选者，所以序列仍然按升序排序。 推进所有匹配的指针可确保跳过重复项，同时仍保持完整性。 

## Python 解决方案```python
class Solution:
    def nthUglyNumber(self, n: int) -> int:
        ugly_numbers = [0] * n
        ugly_numbers[0] = 1

        pointer2 = 0
        pointer3 = 0
        pointer5 = 0

        for index in range(1, n):
            next2 = ugly_numbers[pointer2] * 2
            next3 = ugly_numbers[pointer3] * 3
            next5 = ugly_numbers[pointer5] * 5

            next_ugly = min(next2, next3, next5)
            ugly_numbers[index] = next_ugly

            if next_ugly == next2:
                pointer2 += 1

            if next_ugly == next3:
                pointer3 += 1

            if next_ugly == next5:
                pointer5 += 1

        return ugly_numbers[-1]
```实现首先分配一个数组来存储丑陋的数字。 第一个元素被初始化为`1`，它构成了序列的基础。 

三个指针跟踪先前生成的丑陋数字接下来应该乘以`2`,`3`， 和`5`。 

在循环内部，算法计算三个候选值并选择其中的最小值。 这个最小值成为下一个丑陋的数字。 

实现中最重要的部分是指针前进逻辑。 多种的`if`使用语句代替`elif`因为几个候选人可能同时是平等的。 前进所有匹配的指针可以防止重复项进入序列。 

最后返回最后生成的值。 

## 解决方案```go
func nthUglyNumber(n int) int {
    uglyNumbers := make([]int, n)
    uglyNumbers[0] = 1

    pointer2 := 0
    pointer3 := 0
    pointer5 := 0

    for i := 1; i < n; i++ {
        next2 := uglyNumbers[pointer2] * 2
        next3 := uglyNumbers[pointer3] * 3
        next5 := uglyNumbers[pointer5] * 5

        nextUgly := min(next2, min(next3, next5))
        uglyNumbers[i] = nextUgly

        if nextUgly == next2 {
            pointer2++
        }

        if nextUgly == next3 {
            pointer3++
        }

        if nextUgly == next5 {
            pointer5++
        }
    }

    return uglyNumbers[n-1]
}

func min(a int, b int) int {
    if a < b {
        return a
    }

    return b
}
```Go 实现遵循与 Python 版本相同的逻辑。 由于 Go 没有提供内置的多个值的整数最小值函数，因此需要一个助手`min`添加了功能。 

切片用于动态存储丑数。 整数溢出不是问题，因为该问题保证结果适合 32 位有符号整数`n <= 1690`。 

指针前进逻辑再次使用单独的`if`语句来正确处理重复的候选值。

 ## 边缘情况

 ### 边缘情况 1：`n = 1`这是尽可能小的输入，如果实现假设生成必须始终发生，则很容易处理不当。 

该算法可以正确处理这个问题，因为数组是用`1`作为第一个丑陋的数字。 如果`n`是`1`，循环永远不会执行，方法立即返回`1`。 

### 边缘情况 2：重复生成

 一些难看的数字可以通过多个乘法路径产生。 

例如：```
6 = 2 × 3
6 = 3 × 2
```如果只有一个指针前进，则有缺陷的实现可能会在序列中插入重复项。 

此实现通过递增其候选者与所选难看数字相匹配的每个指针来避免重复。 

### 边缘情况 3：接近约束极限的大输入

 最大的输入是`1690`，这会产生相对较大的丑数。 

暴力实现可能会变得太慢，因为它浪费时间检查许多非难看的整数。 

动态编程方法仍然有效，因为它只直接生成有效的丑数。 即使在最大约束下，线性复杂度也能确保出色的性能。
