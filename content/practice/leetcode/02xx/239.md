 # LeetCode 239 - 滑动窗口最大值

 ## 问题理解

 问题给了我们一个整数数组`nums`和窗口大小`k`。 长度的滑动窗口`k`从数组的开头开始，一次向右移动一个位置。 对于该窗口的每个位置，我们必须确定该窗口内的最大值。 

例如，如果窗口大小是`3`，那么第一个窗口覆盖索引`[0, 1, 2]`，下一个窗口覆盖`[1, 2, 3]`，依此类推，直到窗口到达数组的末尾。 

输出应包含每个有效窗口位置的一个最大值。 由于有`n - k + 1`长度数组中的窗口`n`，结果数组也将有长度`n - k + 1`。 

这里的约束非常重要：

 -`nums.length`可以大到`10^5`-`k`也可以大到`10^5`这些限制立即告诉我们，低效的解决方案将不会通过。 重复扫描每个窗口的解决方案会花费太多时间。 

一个简单的实现会检查所有`k`每个窗口的元素。 由于大约有`n`windows，这种方法需要`O(n * k)`时间。 在最坏的情况下，这会变成`O(10^10)`，这太慢了。 

一些边缘情况很重要：

 -`k = 1`，每个元素都是它自己的窗口，所以答案就是原始数组。 
-`k = len(nums)`，只有一个窗口覆盖整个数组。 
- 包含重复值的数组。 
- 包含负数的数组。 
- 严格增加或严格减少数组，这可能会给低效的数据结构操作带来压力。 

该问题保证了`k`始终有效并且数组非空。 

## 方法

 ### 蛮力方法

 最简单的方法是独立评估每个滑动窗口。 

对于每个窗口位置：

 1. 提取`k`当前窗口中的元素。 
2. 找出其中的最大值。 
3. 将该最大值附加到结果中。 

这是有效的，因为每个窗口都被显式检查，因此计算出的最大值始终是正确的。 

然而，性能较差。 有`n - k + 1`窗口，每个窗口最多需要扫描`k`元素。 这导致`O(n * k)`时间复杂度。 

在给定的限制下，这种方法变得太慢。 

### 最优方法，单调双端队列

 关键的见解是，我们不需要每次窗口移动时都从头开始重新计算最大值。 

当窗口移动一个位置时：

 - 一个元素离开窗口。 
- 一个新元素进入窗口。 

我们不是平等地存储所有元素，而是只维护将来可能成为最大值的元素。 

单调双端队列有效地解决了这个问题。 

双端队列按其对应值的降序存储索引。 这意味着：

 - 双端队列的前面始终包含当前窗口的最大元素的索引。 
- 较大传入元素后面的较小元素将被删除，因为它们以后永远不会成为最大值。 

这允许每个元素最多添加和删除一次，从而产生线性时间解决方案。

## 算法演练

 ### 最优单调双端队列算法

 1. 创建一个空双端队列来存储索引，而不是值。 

我们存储索引是因为我们需要知道元素何时落在当前窗口之外。 
2. 使用索引迭代数组`i`。 

在每一步中，我们都会处理当前元素`nums[i]`。 
3. 如果索引位于当前窗口之外，则从双端队列的前面删除索引。 

当前窗口开始于`i - k + 1`。 任何小于此值的索引都不再有效，必须被丢弃。 
4. 删除双端队列后面对应值小于当前值的索引。 

如果`nums[i]`大于这些值，那些较小的元素永远不会成为任何未来窗口中的最大值，其中包括`nums[i]`。 
5. 将当前索引添加到双端队列的后面。 

双端队列仍按值的降序排列。 
6. 一旦第一个完整窗口形成，意味着`i >= k - 1`，记录最大值。 

最大值始终位于双端队列的前面，因为双端队列保持降序。 
7. 继续，直到处理完所有元素。 

### 为什么它有效

 双端队列始终按其值的降序维护索引。 因此，双端队列的前面始终是当前窗口中最大的元素。 

较大传入元素后面的任何较小元素都会被删除，因为它永远不会再次有用。 此外，当前窗口之外的索引将立即被丢弃。 

由于每个索引最多进入和离开双端队列一次，因此该算法保持高效，同时始终保留正确的最大值。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def maxSlidingWindow(self, nums: List[int], k: int) -> List[int]:
        window = deque()
        result = []

        for i in range(len(nums)):
            # Remove indices outside the current window
            while window and window[0] <= i - k:
                window.popleft()

            # Maintain decreasing order in deque
            while window and nums[window[-1]] < nums[i]:
                window.pop()

            # Add current index
            window.append(i)

            # Record maximum once window is complete
            if i >= k - 1:
                result.append(nums[window[0]])

        return result
```该实现使用Python的`collections.deque`因为它支持从两端高效插入和移除。 

双端队列存储索引而不是值。 这很重要，因为我们必须确定一个元素是否仍在滑动窗口内。 

第一个`while`循环删除不再属于当前窗口的过时索引。 

第二个`while`循环保持单调递减性质。 当前元素后面的任何较小的值都变得无用，因为当前元素将主导未来的窗口。 

插入当前索引后，双端队列的前面始终包含当前窗口的最大值。 

一旦形成第一个完整窗口，算法就会将最大值附加到结果数组中。 

## 解决方案```go
func maxSlidingWindow(nums []int, k int) []int {
    deque := []int{}
    result := []int{}

    for i := 0; i < len(nums); i++ {
        // Remove indices outside the current window
        if len(deque) > 0 && deque[0] <= i-k {
            deque = deque[1:]
        }

        // Maintain decreasing order
        for len(deque) > 0 && nums[deque[len(deque)-1]] < nums[i] {
            deque = deque[:len(deque)-1]
        }

        // Add current index
        deque = append(deque, i)

        // Record maximum once window is complete
        if i >= k-1 {
            result = append(result, nums[deque[0]])
        }
    }

    return result
}
```Go 实现遵循与 Python 版本相同的逻辑。 由于Go没有内置的双端队列结构，因此使用切片来模拟双端队列结构。 

存储索引而不是值的原因与 Python 中的窗口边界管理相同。 

Go 切片可以使用切片操作轻松地从前面或后面删除元素。 

整数溢出不是问题，因为问题约束完全在 Go 的整数范围内。

 ## 边缘情况

 ### 窗口大小等于一

 当`k = 1`，每个窗口只包含一个元素。 有缺陷的实现可能仍会执行不必​​要的双端队列操作或错误处理窗口边界。 

这个实现自然地处理了这种情况。 每个元素都成为其自身窗口的最大值，因此输出与输入数组完全匹配。 

### 严格递减数组

 按递减顺序，例如`[5,4,3,2,1]`，双端队列不断增长，因为没有传入值会删除之前的值。 

这种情况很重要，因为它测试算法是否正确地从双端队列的前面删除过期的索引。 该实现使用以下方法执行此操作：```
while window and window[0] <= i - k:
    window.popleft()
```如果没有这种逻辑，过时的最大值将被错误地保留。 

### 重复值

 具有重复值的数组可能会暴露单调队列实现中的细微错误。 

例如，`[7,7,7,7]`和`k=2`应该产生`[7,7,7]`。 

该实现仅删除严格较小的值：```
while window and nums[window[-1]] < nums[i]:
```双端队列中保留相同的值，从而保留正确的排序和窗口过期行为。 

### 窗口覆盖整个数组

 当`k = len(nums)`，只有一个有效窗口。 

该实现仍然可以正常工作，因为算法会处理所有元素并在第一个完整窗口完成时准确记录一个最大值。 

这验证了逻辑不假设存在多个窗口。
