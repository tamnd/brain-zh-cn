 # LeetCode 244 - 最短词距离 II

 ## 问题理解

 这个问题要求我们设计一个可重用的数据结构，它可以有效地回答固定字符串列表中单词之间重复的最短距离查询。 

我们得到了一系列单词，`wordsDict`，在初始化期间。 之后，我们必须反复回答询问：

 > 原始数组中两个不同单词之间的最小索引距离是多少？ 

两个单词之间的距离是使用它们在数组中位置之间的绝对差来测量的。 

例如，考虑：```
["practice", "makes", "perfect", "coding", "makes"]
```如果我们查询：```
shortest("coding", "practice")
```职位是：

 -`"coding"`→ 索引`3`-`"practice"`→ 索引`0`距离：```
|3 - 0| = 3
```如果我们查询：```
shortest("makes", "coding")
```这个词`"makes"`出现多次：```
index 1, index 4
```这个词`"coding"`出现在：```
index 3
```可能的距离：```
|1 - 3| = 2
|4 - 3| = 1
```最短距离是`1`。 

重要的观察是字典在初始化后永远不会改变。 我们可以对输入进行一次预处理并回答许多未来的查询。 这强烈建议采用基于预处理的解决方案。 

约束提供了额外的提示：

 -`wordsDict.length <= 3 * 10^4`- 至多`5000`打电话给`shortest`-`word1`和`word2`保证存在
 -`word1 != word2`为每个查询扫描整个数组的简单方法可能仍然在限制范围内工作，但效率低下并且忽略了数据结构的可重用性质。 由于我们可能会收到数千个查询，因此预处理变得值得。 

还有一些简化实施的重要保证。 我们永远不需要处理丢失的单词，因为这个问题保证两个查询单词都存在于`wordsDict`。 我们也永远不需要处理相同的单词，因为`word1 != word2`。 

然而，单词的重复出现是一个关键挑战。 幼稚的实现可能会意外地仅比较第一次出现的情况并错过实际的最短距离。 

## 方法

 ### 蛮力方法

 最直接的解决方案是扫描整个`wordsDict`每次都数组`shortest()`被称为。 

对于每个查询，我们维护最近的位置`word1`和`word2`遍历数组时。 每当我们遇到任何一个单词时，如果两个单词都已经出现过，我们就会更新它的索引并计算当前距离。 

这种方法是正确的，因为它会检查两个单词的每次出现并不断更新最小距离。 

然而，当进行多个查询时，这会变得低效。 每次查询都需要遍历整个length数组`n`。 

如果我们收到`q`查询：```
Total work = O(n × q)
```高达`5000`查询和`30000`换句话说，这种重复扫描就变得浪费了。 

### 最佳方法

 关键的见解是输入数组永远不会改变。 

我们可以对每个单词的位置进行一次预处理，而不是为每个查询重新扫描数组。 

我们构建一个哈希图：```
word -> list of indices
```例子：```
["practice", "makes", "perfect", "coding", "makes"]
```变成：```
{
    "practice": [0],
    "makes": [1, 4],
    "perfect": [2],
    "coding": [3]
}
```现在，对于如下查询：```
shortest("makes", "coding")
```我们只比较：```
[1, 4]
and
[3]
```由于两个列表都是按索引自然排序的，因此我们可以使用双指针技术来有效地找到最小绝对差。 

这与合并两个排序数组类似。 

每一步：

 - 比较当前位置
 - 更新最小距离
 - 移动较小索引的指针

 这避免了不必要的比较，并保证我们最终检查出最好的可能对。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 每个查询 O(n) | O(1) | O(1) | 扫描整个数组以查找每个查询 |
 | 最佳| O(n) 预处理 + O(k + m) 每个查询 | O(n) | 存储索引并使用两个指针 |

 在哪里：

-`n`= 总字数
 -`k`= 出现次数`word1`-`m`= 出现次数`word2`## 算法演练

 ### 最优算法

 1. 在初始化期间，创建一个哈希映射，其中每个单词都映射到它出现的所有索引的列表。 

例如：```
"makes" -> [1, 4]
```我们使用哈希映射是因为它提供了对任何单词的位置的恒定时间查找。 
2. 遍历一次输入数组。 

对于每个索引`i`和词`wordsDict[i]`, 附加`i`到哈希映射中的相应列表。 
3. 什么时候`shortest(word1, word2)`被调用，从哈希映射中检索两个排序的索引列表。 

例子：```
word1 = "makes"
word2 = "coding"

[1, 4]
[3]
```4.初始化两个指针：```
i = 0
j = 0
```这些指针跟踪我们在两个列表中的当前位置。 
5. 比较两个指针处的索引。 

计算：```
abs(list1[i] - list2[j])
```更新最小距离。 
6. 将指针移至较小的索引。 

如果：```
list1[i] < list2[j]
```增量`i`。 

否则，增加`j`。 

此步骤很重要，因为移动较大的值并不能减少差异。 为了可能找到更小的距离，我们必须推进更小的索引。 
7. 继续，直到一个指针到达其列表的末尾。 
8. 返回找到的最小距离。 

### 为什么它有效

 正确性依赖于两个索引列表都已排序的事实。 

在每一步中，较小的索引都是限制因素。 如果我们保持较小的指数不变并将较大的指数向前移动，则差异只能保持不变或增加。 因此，找到较小距离的唯一机会是将较小的指针向前移动。 

这种贪婪的性质保证了不会跳过任何最优对，并且算法总是找到真正的最小距离。 

## Python 解决方案```python
from collections import defaultdict
from typing import List

class WordDistance:

    def __init__(self, wordsDict: List[str]):
        self.word_positions = defaultdict(list)

        for index, word in enumerate(wordsDict):
            self.word_positions[word].append(index)

    def shortest(self, word1: str, word2: str) -> int:
        positions1 = self.word_positions[word1]
        positions2 = self.word_positions[word2]

        pointer1 = 0
        pointer2 = 0
        minimum_distance = float("inf")

        while pointer1 < len(positions1) and pointer2 < len(positions2):
            index1 = positions1[pointer1]
            index2 = positions2[pointer2]

            minimum_distance = min(
                minimum_distance,
                abs(index1 - index2)
            )

            if index1 < index2:
                pointer1 += 1
            else:
                pointer2 += 1

        return minimum_distance

# Your WordDistance object will be instantiated and called as such:
# obj = WordDistance(wordsDict)
# param_1 = obj.shortest(word1, word2)
```该实现首先在初始化期间预处理字典。 一个`defaultdict(list)`存储每个单词的每个出现索引。 因为我们从左到右扫描数组，所以索引会自动按排序顺序存储。 

里面`shortest()`，我们检索与查询词对应的两个索引列表。 

然后我们使用两个指针同时遍历两个排序列表。 在每一步中，我们都会计算当前距离并更新最小值。 

指针移动规则至关重要。 我们推进引用较小索引的指针，因为这样做是潜在减少差异的唯一方法。 

一旦用尽任一列表，就会考虑所有相关比较，并返回最小距离。 

## 解决方案```go
type WordDistance struct {
	wordPositions map[string][]int
}

func Constructor(wordsDict []string) WordDistance {
	wordPositions := make(map[string][]int)

	for index, word := range wordsDict {
		wordPositions[word] = append(
			wordPositions[word],
			index,
		)
	}

	return WordDistance{
		wordPositions: wordPositions,
	}
}

func (this *WordDistance) Shortest(word1 string, word2 string) int {
	positions1 := this.wordPositions[word1]
	positions2 := this.wordPositions[word2]

	pointer1 := 0
	pointer2 := 0
	minimumDistance := int(^uint(0) >> 1)

	for pointer1 < len(positions1) &&
		pointer2 < len(positions2) {

		index1 := positions1[pointer1]
		index2 := positions2[pointer2]

		distance := index1 - index2
		if distance < 0 {
			distance = -distance
		}

		if distance < minimumDistance {
			minimumDistance = distance
		}

		if index1 < index2 {
			pointer1++
		} else {
			pointer2++
		}
	}

	return minimumDistance
}

/**
 * Your WordDistance object will be instantiated and called as such:
 * obj := Constructor(wordsDict);
 * param_1 := obj.Shortest(word1, word2);
 */
```Go 实现遵循与 Python 版本相同的逻辑。 而不是一个`defaultdict`，我们使用一个`map[string][]int`。 

因为 Go 没有内置的整数无穷大值，所以我们初始化`minimumDistance`使用最大可能的整数：```go
int(^uint(0) >> 1)
```由于 Go 缺乏内置整数，我们还手动计算绝对值`abs()`功能。 

Go 中的切片使用自然增长`append()`，使它们成为存储单词位置的理想选择。

 ## 边缘情况

 ### 多次出现的单词

 错误的一个主要来源是假设每个单词只出现一次。 

例子：```
["a", "x", "a", "x", "a"]
```如果我们只比较第一次出现的情况：```
|0 - 1| = 1
```我们可能会意外地错过其他输入中较短的组合。 该实现通过存储所有位置并在每次出现时使用两指针扫描来避免此问题。 

### 非常频繁的查询

 由于该问题最多允许`5000`打电话给`shortest()`，重复扫描整个数组的效率很低。 

一个幼稚的实现会重复执行`O(n)`工作。 我们的预处理方法在初始化期间支付一次设置成本，然后使用预先计算的索引列表有效地回答查询。 

### 一个词只出现一次

 有些词可能只出现一次。 

例子：```
["apple", "banana", "orange"]
```查询时：```
shortest("banana", "orange")
```每个列表仅包含一个元素。 

两指针逻辑仍然可以自然地工作，因为它处理单元素列表而不需要任何特殊情况。 

### 不同位置的最接近匹配

 最短距离并不总是由第一次出现形成。 

例子：```
["a", "b", "c", "a", "b"]
```为了：```
shortest("a", "b")
```最好的答案是：```
|3 - 4| = 1
```不是：```
|0 - 1| = 1
```在更复杂的示例中，稍后发生的情况可能会更好。 两指针遍历保证了每个有希望的候选对都被考虑，同时避免不必要的比较。
