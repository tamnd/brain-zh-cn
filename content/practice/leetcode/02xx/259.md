[LeetCode 第 259 题](https://leetcode.com/problems/3sum-smaller/)

 **难度：** 🟡 中等
 **主题：** 数组、两个指针、二分查找、排序

 ## 解决方案

 ## 问题理解

 该问题要求我们计算有多少个不同的索引三元组`(i, j, k)`满足两个条件：

 1. 索引的排序使得`0 <= i < j < k < n`2. 对应值的总和严格小于给定值`target`换句话说，我们必须检查数组中三个不同元素的组合，并确定其中有多少组合产生的总和小于`target`。 

输入包括：

 - 整数数组`nums`- 一个整数`target`输出是一个表示有效三元组数量的整数。 

一个关键细节是我们通过索引位置而不是唯一值来计算三元组。 如果同一数字在不同位置多次出现，则每个有效索引组合单独计数。 

约束对于决定哪种算法实用很重要：

 -`n`可以大到`3500`- 暴力解决方案需要检查所有可能的三元组
 - 最坏情况下三胞胎的数量约为`n^3 / 6`为了`n = 3500`，三次算法变得太慢了。 因此，我们需要比以下更有效的东西`O(n^3)`。 

该数组还可能包含：

 - 负数
 - 正数
 - 重复值
 - 空输入

 该问题保证最终答案符合 32 位整数范围，因此我们不需要特殊的溢出处理。 

一些边缘情况很重要：

 - 少于三个元素的数组不能形成任何三元组
 - 重复的数字仍应算作不同的索引组合
 - 负值可以产生许多有效的三元组
 - 已经排序或反向排序的数组应该仍然可以正常工作
 - 必须有效地计算大量有效组合，而无需显式枚举每个三元组

 ## 方法

 ### 蛮力方法

 最直接的解决方案是尝试所有可能的三元组。 

我们可以使用三个嵌套循环：

 - 第一个循环选择索引`i`- 第二个循环选择索引`j`- 第三次循环选择索引`k`对于每个三元组，我们计算：```
nums[i] + nums[j] + nums[k]
```如果总和小于`target`，我们增加答案。 

这种方法保证是正确的，因为它明确地检查每个可能的有效三元组。 没有任何内容被跳过。 

然而，时间复杂度为`O(n^3)`，当`n`可以是`3500`。 

### 最优方法，排序+两个指针

 关键的观察是，对数组进行排序后，我们可以使用排序属性一次计算许多三元组。 

假设我们修复第一个元素`nums[i]`。 

然后我们想要找到对`(j, k)`这样：```
nums[i] + nums[j] + nums[k] < target
```因为数组是有序的：

 - 如果有特定的一对`(j, k)`作品，
 - 然后之间的每个索引`j`和`k`也适用于`j`例如，如果：```
nums[i] + nums[left] + nums[right] < target
```然后：```
nums[i] + nums[left] + nums[right - 1] < target
nums[i] + nums[left] + nums[right - 2] < target
...
```这意味着我们可以一步计算多个三元组，而不是单独检查它们。 

我们使用两个指针：

 -`left`之后开始`i`-`right`从数组末尾开始

 取决于当前总和：

 - 如果总和小于目标，则所有对`left`通过`right`有效
 - 否则，我们通过移动来减少总和`right`向左

 这降低了复杂性`O(n^3)`到`O(n^2)`。

 ## 算法演练

 ### 最优算法

 1. 按非降序对数组进行排序。 

排序至关重要，因为两指针策略取决于所排序的数组。 一旦排序，增加或减少指针可以预见地改变总和。 
2. 初始化变量`count = 0`。 

该变量存储有效三元组的总数。 
3. 使用索引迭代数组`i`从`0`到`n - 3`。 

我们对待`nums[i]`作为三元组的第一个元素。 
4. 对于每个`i`，初始化两个指针：

 -`left = i + 1`-`right = n - 1`这些指针搜索有效的第二个和第三个元素。 
5. 虽然`left < right`，计算当前总和：```
current_sum = nums[i] + nums[left] + nums[right]
```1.如果`current_sum < target`，然后之间的每个索引`left`和`right`形成一个有效的三元组`i`。 

由于数组已排序：```
nums[right] >= nums[right - 1] >= ...
```更换`right`任何较小的索引只会减少总和。 

因此，有效三元组的数量为：```
right - left
```将此金额添加到`count`。 

1. 移动`left`向右一步。 

我们已经计算了从当前开始的所有三元组`left`，所以我们继续寻找新的组合。 
2. 否则，如果总和太大，则移动`right`还剩一步。 

这会减少总和并可能创建有效的三元组。 
3. 继续，直到处理完所有可能性。 
4. 返回`count`。 

### 为什么它有效

 正确性取决于数组的排序顺序。 

什么时候：```
nums[i] + nums[left] + nums[right] < target
```之间的每个索引`left`和`right`也有效，因为替换`nums[right]`较小的元素不能增加总和。 

这使我们能够计算`right - left`一次计算三元组，不会遗漏或重复计算任何组合。 

每个有效的三元组最终只会被考虑一次，因为：

 -`i`唯一地固定第一个元素
 - 两指针扫描系统地探索所有有效的`(left, right)`对

 ## Python 解决方案```python
from typing import List

class Solution:
    def threeSumSmaller(self, nums: List[int], target: int) -> int:
        nums.sort()
        n = len(nums)
        count = 0

        for i in range(n - 2):
            left = i + 1
            right = n - 1

            while left < right:
                current_sum = nums[i] + nums[left] + nums[right]

                if current_sum < target:
                    count += right - left
                    left += 1
                else:
                    right -= 1

        return count
```实现首先对数组进行排序。 这使得接下来的两指针优化成为可能。 

外循环选择每个三元组的第一个元素。 由于我们总共需要三个元素，因此循环仅运行直到`n - 3`。 

对于每个固定索引`i`，两个指针搜索数组的剩余部分。 

变量`current_sum`存储当前三元组候选者的总和。 

当总和小于目标时，之间的所有仓位`left`和`right`保证可以工作，因为数组是排序的。 该代码没有单独检查每个，而是添加了`right - left`直接上答案。 

如果总和太大，唯一的减少方法就是移动`right`向左。 

该算法有效地计算所有有效的三元组，而无需显式枚举每个组合。 

## 解决方案```go
package main

import "sort"

func threeSumSmaller(nums []int, target int) int {
	sort.Ints(nums)

	n := len(nums)
	count := 0

	for i := 0; i < n-2; i++ {
		left := i + 1
		right := n - 1

		for left < right {
			currentSum := nums[i] + nums[left] + nums[right]

			if currentSum < target {
				count += right - left
				left++
			} else {
				right--
			}
		}
	}

	return count
}
```Go 的实现与 Python 解决方案非常相似。 

主要区别在于 Go 使用`sort.Ints(nums)`从标准库中对切片进行就位排序。 

Go 切片自然会处理空数组，因此对于边缘情况（例如元素少于三个的数组）不需要进行额外的检查。 

整数溢出不是问题，因为约束很小。 最大可能的三元组和完全在 Go 的范围内`int`范围。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n²) | 排序需要 O(n log n)，两指针扫描占主导地位，O(n²) |
 | 空间| O(1) 或 O(log n) | 仅使用常量额外变量，不包括排序内部 |

 外循环运行`n`次，并且对于每次迭代，两个指针最多在数组中移动一次。 由于每个指针仅向内移动，因此每次迭代的总工作量是线性的。 

这会产生总时间复杂度`O(n²)`。 

该算法本身仅使用几个变量。 根据语言和排序实现，排序可能需要内部对数堆栈空间。

 ## 边缘情况

 ### 元素少于三个的数组

 如果数组包含的数字少于三个，则不能存在三元组。 这是嵌套循环解决方案中一对一错误的常见来源。 

该实现自然地处理了这个问题，因为外循环：```
for i in range(n - 2):
```不执行时`n < 3`。 

### 重复值

 数组可能包含重复的数字，并且该问题通过索引位置而不是不同的值来计算三元组。 

例如：```
[-1, -1, -1, -1]
```包含多个有效的三元组，即使值重复。 

该实现正确地计算每个不同的索引组合，因为它从不跳过重复项。 

### 所有三胞胎均有效

 在某些输入中，几乎每个可能的三元组都满足该条件。 

例子：```
nums = [-5,-4,-3,-2,-1]
target = 100
```一个简单的解决方案仍然单独检查每个三元组。 

优化的解决方案通过使用以下方式一次计算多个三元组来有效地处理这个问题：```
count += right - left
```这可以防止不必要的重复工作并保留二次复杂性。 

### 没有有效的三元组

 有些数组根本不产生有效的三元组。 

例子：```
nums = [10,10,10]
target = 5
```该实现正确返回零，因为每个计算的总和都超过目标，导致`right`指针向内移动，直到搜索终止。
