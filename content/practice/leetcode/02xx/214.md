[LeetCode 第 214 题](https://leetcode.com/problems/shortest-palindrome/)

 **难度：** 🔴难
 **主题：** 字符串、滚动哈希、字符串匹配、哈希函数

 ## 解决方案

 ## 问题理解

 问题给出了一个字符串`s`并要求我们通过仅在字符串的开头添加字符来创建尽可能短的回文。 

回文是向前和向后读相同的字符串。 关键的限制是我们不允许在中间或末尾插入字符。 每个添加的字符必须出现在原始字符串之前。 

我们的目标不仅仅是制作任意回文串，而是尽可能制作最短的回文串。 

例如：

-`"aacecaaa"`已经几乎是一个回文了。 通过添加一个`'a'`在前面，我们得到`"aaacecaaa"`。 
-`"abcd"`没有大的回文前缀。 最好的选择是逆转`"bcd"`并将其放在前面，产生`"dcbabcd"`。 

最重要的观察是，我们只关心已经是回文字符串的最长前缀。 一旦我们找到了该前缀，剩下的后缀就必须镜像在前面。 

认为：

-`s = "abcd"`- 最长回文前缀=`"a"`- 剩余后缀=`"bcd"`为了使整个字符串对称，我们反转`"bcd"`进入`"dcb"`并在前面加上它：```
"dcb" + "abcd" = "dcbabcd"
```约束允许字符串达到`5 * 10^4`人物。 这立即告诉我们二次解可能会超时。 任何重复检查子字符串的回文属性的方法`O(n)`时间会变得太慢。 

重要的边缘情况包括：

 - 空字符串
 - 单字符串
 - 已经是回文的字符串
 - 没有长于一个字符的回文前缀的字符串
 - 非常大的输入，低效的子串操作变得昂贵

 输入保证仅小写英文字母，这简化了字符比较和哈希策略。 

## 方法

 ### 蛮力方法

 一种简单的方法是尝试字符串的每个前缀，从整个字符串开始并向前面收缩。 

对于每个前缀：

 1. 检查前缀是否为回文。 
2. 遇到的第一个回文前缀是最长的。 
3. 反转剩余的后缀并将其添加到前面。 

例如：```
s = "abcd"

Check:
"abcd" -> not palindrome
"abc"  -> not palindrome
"ab"   -> not palindrome
"a"    -> palindrome
```剩余后缀：```
"bcd"
```反转它：```
"dcb"
```结果：```
"dcbabcd"
```这是有效的，因为最短的解决方案始终保持最长的回文前缀不变。 

问题是性能。 每个回文检查的成本`O(n)`，我们可以对几乎每个前缀执行它。 这导致`O(n^2)`时间复杂度，对于`50,000`人物。 

### 最佳方法

 关键的见解是我们只需要找到最长的也是回文的前缀。 

这就变成了一个字符串匹配问题。 

我们可以使用 KMP 前缀函数的想法：

 1. 反转字符串。 
2. 构建组合字符串：```
s + "#" + reverse(s)
```1. 计算LPS数组，也称为前缀表。 

LPS 数组的最后一个值告诉我们最长前缀的长度`s`匹配后缀`reverse(s)`。 

该匹配结构完全对应于最长的回文前缀。 

一旦我们知道了长度：

 - 后面的所有内容都必须镜像到前面
 - 反转剩余后缀
 - 前置它

 这将复杂性降低到线性时间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 反复检查前缀是否有回文属性 |
 | 最佳| O(n) | O(n) | 使用KMP前缀表查找最长回文前缀 |

 ## 算法演练

 1. 将原字符串反转。 

如果：```
s = "aacecaaa"
```然后：```
reversed_s = "aaacecaa"
```我们需要这个，因为回文从前到后读起来都是一样的。 
2. 构建组合字符串。 

构造：```
combined = s + "#" + reversed_s
```例子：```
"aacecaaa#aaacecaa"
```分隔符`#`很重要，因为它可以防止原始字符串和反向字符串之间意外重叠。 
3. 计算KMP前缀表，也称为LPS数组。 

每个位置的LPS值代表：```
length of the longest proper prefix
which is also a suffix
```我们使用标准 KMP 预处理算法以线性时间进行计算。 
4. 读取最终的LPS 值。 

最后一个值告诉我们最长回文前缀的长度。 

认为：```
longest_prefix_length = 7
```然后：```
s[:7]
```已经是一个回文。 
5. 提取非回文后缀。 

回文前缀之后的所有内容都必须镜像：```
suffix = s[longest_prefix_length:]
```6. 反转后缀并将其添加到前面。 

例子：```
suffix = "bcd"
reverse = "dcb"
```最终结果：```
"dcb" + "abcd"
```### 为什么它有效

 KMP前缀表有效地找到最长的前缀`s`也显示为后缀`reverse(s)`。 

反转字符串中的后缀对应于原始字符串中的反转前缀。 当它们匹配时，前缀必须向前和向后读取相同，这意味着它是回文。 

通过保留最长的回文前缀并仅镜像剩余的后缀，我们保证了最短的回文。 

## Python 解决方案```python
class Solution:
    def shortestPalindrome(self, s: str) -> str:
        reversed_s = s[::-1]

        combined = s + "#" + reversed_s

        lps = [0] * len(combined)

        length = 0

        for i in range(1, len(combined)):
            while length > 0 and combined[i] != combined[length]:
                length = lps[length - 1]

            if combined[i] == combined[length]:
                length += 1
                lps[i] = length

        longest_palindromic_prefix = lps[-1]

        suffix = s[longest_palindromic_prefix:]

        return suffix[::-1] + s
```实现从反转原始字符串开始。 这个反转版本可以帮助我们识别匹配的前缀和后缀结构。 

接下来，代码构造组合字符串：```python
s + "#" + reversed_s
```分隔符确保匹配不会错误地跨越两个部分。 

这`lps`数组存储 KMP 前缀函数值。 变量`length`在迭代组合字符串时跟踪当前匹配的前缀长度。 

每当字符不匹配时，算法就会使用先前计算的 LPS 值进行回退，而不是从头开始。 这就是 KMP 具有线性性能的原因。 

构建完整的 LPS 数组后，最终值表示最长的回文前缀长度。 

该前缀之后的所有内容都是不匹配的后缀。 反转该后缀并将其放在前面会产生最短的回文。 

## 解决方案```go
func shortestPalindrome(s string) string {
	reversed := reverseString(s)

	combined := s + "#" + reversed

	lps := make([]int, len(combined))

	length := 0

	for i := 1; i < len(combined); i++ {
		for length > 0 && combined[i] != combined[length] {
			length = lps[length-1]
		}

		if combined[i] == combined[length] {
			length++
			lps[i] = length
		}
	}

	longestPrefix := lps[len(lps)-1]

	suffix := s[longestPrefix:]

	return reverseString(suffix) + s
}

func reverseString(s string) string {
	chars := []byte(s)

	left := 0
	right := len(chars) - 1

	for left < right {
		chars[left], chars[right] = chars[right], chars[left]
		left++
		right--
	}

	return string(chars)
}
```Go 实现遵循与 Python 版本相同的逻辑。 

区别之一是字符串反转。 Go 字符串是不可变的，因此我们在交换字符之前将字符串转换为字节切片。 

LPS 数组是使用创建的`make([]int, len(combined))`。 

由于问题仅包含小写英文字母，因此基于字节的索引是安全的并且避免了 Unicode 复杂性。

 ## 边缘情况

 空字符串是一种重要的边缘情况，因为许多字符串算法意外地假设至少存在一个字符。 在此实现中，组合字符串变得简单`"#"`，并且 LPS 阵列仍然可以正常工作。 该函数返回一个空字符串，无需特殊处理。 

如果算法错误地在前面添加了额外的字符，那么已经是回文的字符串也可能会导致细微的错误。 例如，`"abba"`应保持不变。 KMP 计算正确地将整个字符串识别为最长回文前缀，因此后缀变为空并且不添加任何内容。 

除了第一个字符之外没有有意义的回文前缀的字符串是另一个关键情况。 为了`"abcd"`， 仅有的`"a"`符合资格。 一些不正确的实现会意外地在字符串中的任何位置而不是专门在前缀处搜索回文子字符串。 由于组合字符串和 KMP 匹配的结构，此实现仅考虑前缀。 

非常大的字符串会同时强调运行时间和内存效率。 二次回文检查方法对于`50,000`人物。 基于线性 KMP 的方法可以有效地处理这些输入，因为每个字符仅处理固定次数。
