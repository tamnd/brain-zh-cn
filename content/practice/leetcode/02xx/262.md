[LeetCode 第 262 题](https://leetcode.com/problems/trips-and-users/)

 **难度：** 🔴难
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 此问题要求我们计算固定日期范围内出租车行程的每日取消率，特别是从`"2013-10-01"`到`"2013-10-03"`。 

我们有两个数据库表：

 -`Trips`，它存储有关每个出租车行程请求的信息
 -`Users`，它存储用户元数据，例如用户是否被禁止

 每个行程包含一个客户、一个司机、一个行程状态和请求日期。 重要的细节是客户端和驱动程序都由引用行中的 ID 表示。`Users`桌子。 

一天的取消率定义为：$$\text{Cancellation Rate} = \frac{\text{Number of canceled trips with unbanned users}} {\text{Total number of trips with unbanned users}}$$仅当满足以下条件时，一次旅行才算数：

 - 客户端未被禁止
 - 司机没有被禁止

 如果行程处于以下任一状态，则视为已取消：

 -`cancelled_by_driver`-`cancelled_by_client`有状态的旅行`completed`不是取消。 

输出应包含：

 - 每天一排
 - 这一天本身
 - 取消率四舍五入至小数点后两位

 该问题保证我们只需要考虑给定范围内至少有一个有效行程条目的日期。 

一个微妙但重要的细节是，被禁止的用户使整个行程的计算无效。 即使只有客户被禁止，或者只有司机被禁止，该行程也必须从分子和分母中排除。 

LeetCode 数据库问题的输入规模通常适中，但目标不是通过索引技巧获得原始性能。 相反，挑战在于在 SQL 中正确表达过滤、聚合和条件计数。 

有几种边缘情况很容易导致错误：

 - 涉及被禁止用户的旅行必须完全忽略
 - 只有取消的行程才计入分子
 - 已完成的行程仍计入分母
 - 取消率必须四舍五入至小数点后两位
 - 客户和司机都必须独立检查
 - 不应出现没有有效行程的日子

 ## 方法

 ### 蛮力方法

 暴力解决方案将单独处理每个行程并重复查询`Users`表来确定客户端和驱动程序是否被禁止。 

从概念上讲，该算法的工作原理如下：

 1. 迭代日期范围内的每一次行程。 
2. 每趟行程：

 - 查找客户`Users`- 查找驱动程序`Users`3. 如果任一用户被禁止，则跳过该行程。 
4. 否则：

 - 增加当天的总行程次数
 - 如果状态指示取消，则增加取消计数
 5. 处理完所有行程后，计算：$$\text{canceled} / \text{total}$$每一天。 

这会产生正确的答案，因为每次旅行都经过单独验证并正确分类。 

然而，这种方法效率低下，因为它会重复扫描或搜索`Users`每次旅行的表。 如果没有适当的连接或索引，随着数据集的增长，这可能会变得昂贵。 

### 最佳方法

 关键的见解是 SQL 是专门为关系过滤和聚合而设计的。 

我们可以：

 1. 加入`Trips`表与`Users`表两次：

 - 为客户提供一次
 - 给司机一次
 2.直接在查询中过滤掉被禁止的用户
 3. 按天对剩余行程进行分组
 4. 使用条件聚合来计算取消的行程

 重要的观察是取消计数自然可以表达为条件和：```
SUM(status != 'completed')
```或等价：```
SUM(CASE WHEN status != 'completed' THEN 1 ELSE 0 END)
```由于 SQL 非常有效地处理分组聚合，因此这种方法避免了重复扫描，并在过滤后的数据集上一次性计算所有内容。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(T × U) | O(D) | 每次出行都反复搜索用户|
 | 最佳| O(T + U) | O(D) | 高效使用联接和分组聚合 |

 这里：

-`T`是行程次数
 -`U`是用户数量
 -`D`是不同天数

 ## 算法演练

 ### 最优 SQL 算法

 1. 从`Trips`表，因为每个计算都是基于行程记录。 
2. 加入`Users`客户关系表。 这使我们能够访问客户端是否被禁止。 我们加入使用：```sql
Trips.client_id = Users.users_id
```3. 加入`Users`第二次表为驱动关系。 由于同一个表被使用两次，因此需要别名：

 - 客户的一个别名
 - 驱动程序的一个别名
 4. 过滤数据集，仅保留未禁止用户的行程：```sql
client.banned = 'No'
AND driver.banned = 'No'
```5. 将日期范围限制为：```sql
BETWEEN '2013-10-01' AND '2013-10-03'
```6. 将所有剩余行分组`request_at`。 这使我们能够独立计算每日统计数据。 
7. 对于每组：

 - 使用以下方法计算有效行程总数`COUNT(*)`- 使用条件聚合计算取消的行程
 8. 将取消的行程除以总行程来计算取消率。 
9. 使用以下方法将结果四舍五入到小数点后两位`ROUND()`。 
10. 返回日期和计算的取消率。 

### 为什么它有效

 该算法之所以有效，是因为每个行程在聚合之前都经过过滤。 这保证了只有涉及未禁止用户的行程才会参与统计。 

按天分组可以正确划分数据集，条件聚合可确保取消的行程与已完成的行程分开计数。 由于每个有效行程对分母仅贡献一次，并且每个取消的有效行程对分子仅贡献一次，因此计算出的比率在数学上是正确的。 

## Python 解决方案

 尽管这是通常使用 SQL 解决的数据库问题，但以下演示了 Python 中的等效逻辑。```python
from collections import defaultdict
from typing import List, Dict

class Solution:
    def cancellationRate(
        self,
        trips: List[Dict],
        users: List[Dict]
    ) -> List[Dict]:

        user_banned = {}

        for user in users:
            user_banned[user["users_id"]] = user["banned"]

        total_trips = defaultdict(int)
        cancelled_trips = defaultdict(int)

        for trip in trips:
            day = trip["request_at"]

            if not ("2013-10-01" <= day <= "2013-10-03"):
                continue

            client_ok = user_banned.get(trip["client_id"]) == "No"
            driver_ok = user_banned.get(trip["driver_id"]) == "No"

            if not (client_ok and driver_ok):
                continue

            total_trips[day] += 1

            if trip["status"] != "completed":
                cancelled_trips[day] += 1

        result = []

        for day in sorted(total_trips.keys()):
            rate = cancelled_trips[day] / total_trips[day]

            result.append({
                "Day": day,
                "Cancellation Rate": round(rate, 2)
            })

        return result
```实现首先从构建一个查找表开始`users_id`至禁止状态。 这允许在验证行程时进行恒定时间访问。 

然后维护两个哈希图：

 -`total_trips`跟踪每天的所有有效行程
 -`cancelled_trips`轨道每天取消有效行程

 每个行程均处理一次。 该算法首先检查日期是否在所需的范围内。 然后，它会验证客户端和驱动程序是否已被取消禁止。 

如果行程有效，当天的总计数器就会增加。 如果行程状态不是`completed`，取消的计数器也增加。 

最后，每天计算取消率，并四舍五入到小数点后两位，然后返回结果。 

## 解决方案```go
package main

import (
	"sort"
)

type Trip struct {
	ID        int
	ClientID  int
	DriverID  int
	CityID    int
	Status    string
	RequestAt string
}

type User struct {
	UsersID int
	Banned  string
	Role    string
}

type Result struct {
	Day              string
	CancellationRate float64
}

func cancellationRate(trips []Trip, users []User) []Result {
	userBanned := make(map[int]string)

	for _, user := range users {
		userBanned[user.UsersID] = user.Banned
	}

	totalTrips := make(map[string]int)
	cancelledTrips := make(map[string]int)

	for _, trip := range trips {
		day := trip.RequestAt

		if day < "2013-10-01" || day > "2013-10-03" {
			continue
		}

		clientOK := userBanned[trip.ClientID] == "No"
		driverOK := userBanned[trip.DriverID] == "No"

		if !(clientOK && driverOK) {
			continue
		}

		totalTrips[day]++

		if trip.Status != "completed" {
			cancelledTrips[day]++
		}
	}

	var days []string

	for day := range totalTrips {
		days = append(days, day)
	}

	sort.Strings(days)

	results := []Result{}

	for _, day := range days {
		rate := float64(cancelledTrips[day]) / float64(totalTrips[day])

		results = append(results, Result{
			Day:              day,
			CancellationRate: float64(int(rate*100+0.5)) / 100,
		})
	}

	return results
}
```Go 实现遵循与 Python 版本相同的逻辑，但显式使用映射来实现哈希表行为。 

一个显着的区别是四舍五入。 Go 没有与 Python 直接等效的语言`round(..., 2)`对于原始浮点计算中的小数格式，因此使用手动舍入：```go
float64(int(rate*100+0.5)) / 100
```Go 在除法时还需要显式类型转换以避免整数除法。 

## SQL 解决方案```sql
SELECT
    t.request_at AS Day,
    ROUND(
        AVG(
            CASE
                WHEN t.status = 'completed' THEN 0
                ELSE 1
            END
        ),
        2
    ) AS `Cancellation Rate`
FROM Trips t
JOIN Users c
    ON t.client_id = c.users_id
JOIN Users d
    ON t.driver_id = d.users_id
WHERE c.banned = 'No'
    AND d.banned = 'No'
    AND t.request_at BETWEEN '2013-10-01' AND '2013-10-03'
GROUP BY t.request_at;
```该解决方案使用了一个优雅的 SQL 技巧：

 -`completed`变成`0`- 取消的状态变为`1`直接取这些值的平均值计算：$$\frac{\text{canceled trips}}{\text{total trips}}$$这避免了编写单​​独的分子和分母计算。

from collections import defaultdict

def cancellation_rate(trips, users):
    user_banned = {
        user["users_id"]: user["banned"]
        for user in users
    }

    total = defaultdict(int)
    cancelled = defaultdict(int)

    for trip in trips:
        day = trip["request_at"]

        if not ("2013-10-01" <= day <= "2013-10-03"):
            continue

        if (
            user_banned[trip["client_id"]] != "No"
            or user_banned[trip["driver_id"]] != "No"
        ):
            continue

        total[day] += 1

        if trip["status"] != "completed":
            cancelled[day] += 1

    result = {}

    for day in total:
        result[day] = round(cancelled[day] / total[day], 2)

    return result

 ## 边缘情况

 ### 涉及被禁止用户的旅行

 最常见的错误之一是计算客户或司机被禁止的行程。 该问题明确指出两个用户都必须被取消禁止。 

有缺陷的实现可能只检查客户端或只检查驱动程序。 正确的解决方案在计算行程之前独立验证两者。 

### 无有效行程的天数

 一天可能包含行程，但所有行程都可能涉及被禁止的用户。 在这种情况下，这一天根本不应该出现在输出中。 

该实现自然会处理此问题，因为仅在处理有效行程后才将一天添加到聚合地图中。 

### 所有行程均取消

 如果当天所有有效行程均被取消，则取消率变为`1.00`。 

一些实现意外地执行整数除法并产生`1`或者`0`。 提供的实现显式使用浮点除法来避免此问题。 

### 没有取消的行程

 如果所有有效行程均已完成，则取消率应为`0.00`。 

条件聚合正确地生成零个已取消的行程，同时仍在分母中计算已完成的行程。 

### 混合取消类型

 两者：

 -`cancelled_by_driver`-`cancelled_by_client`必须算作取消。 

该实现通过处理每个非`completed`状态为已取消，自动包含这两种情况。
