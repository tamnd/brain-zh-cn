[LeetCode 第 210 题](https://leetcode.com/problems/course-schedule-ii/)

 **难度：** 🟡 中等
 **主题：** 深度优先搜索、广度优先搜索、图论、拓扑排序

 ## 解决方案

 ## 问题理解

 这个问题要求我们在给定课程之间先决关系的情况下确定完成课程的有效顺序。 

你被给予`numCourses`，它代表标记为的课程总数`0`到`numCourses - 1`。 您还会获得一个名为的列表`prerequisites`，其中每个条目`[a, b]`意味着课程`b`必须在课程之前完成`a`。 

在图术语中，这形成了**有向图**：

 - 每门课程都是一个节点。 
- 前提关系是有向边。 
- 如果`[a, b]`存在，我们画一条边`b → a`， 意义`b`必须先来`a`。 

目标是返回所有课程的**一个有效订单**，以满足每个先决条件要求。 如果存在多个有效订单，则返回其中任何一个都是可以接受的。 但是，如果由于依赖图中存在循环而不存在有效的排序，则我们必须返回一个空数组。 

例如，如果当然`1`取决于课程`0`， 然后`0`必须出现在输出排序中的较早位置。 有效答案：```
[[1,0],[2,0],[3,1],[3,2]]
```可能是：```
[0,1,2,3]
```或者：```
[0,2,1,3]
```因为两者都满足所有先决条件依赖性。 

这些约束对于选择有效的算法很重要：

 -`numCourses <= 2000`- 先决条件对的数量可以接近`numCourses * (numCourses - 1)`这意味着图可能变得相当密集。 重复检查排列的蛮力策略在计算上是不可行的。 相反，我们需要一种相对于节点和边的数量接近线性时间的算法。 

主要的边缘情况包括：

 - **无先决条件**，每门课程均可立即使用。 
- **循环**，完成所有课程变得不可能。 
- **断开的组件**，其中存在独立的课程组。 
- **没有依赖项和依赖项的课程**，它们仍然必须出现在结果中。 
- **多个有效答案**，应接受任何正确的排序。 

## 方法

 ### 蛮力方法

 暴力方法将尝试生成所有可能的课程排列，并检查每个排列是否满足所有先决条件约束。 

对于每个订单，我们可以验证是否每个先决条件`[a, b]`满足条件`b`出现在之前`a`。 第一个有效的订单将被返回。 

这种方法是正确的，因为它彻底搜索整个解决方案空间。 如果存在有效的排序，最终会找到它。 

然而，这个问题在计算上是不可行的，因为有`n!`可能的排列`n`课程。 即使对于相对较小的值`n`，这变得非常昂贵。 

例如：```
10! = 3,628,800
15! = 1,307,674,368,000
```自从`numCourses`可以达到`2000`，蛮力是完全不切实际的。 

### 关键见解

 重要的观察是，这个问题实际上要求**有向图的拓扑排序**。 

仅当图是**有向无环图 (DAG)** 时才存在拓扑排序。 如果存在循环，则没有有效的排序可以满足所有先决条件要求。 

我们可以使用**卡恩算法**有效地解决这个问题，这是一种基于广度优先搜索的拓扑排序技术。 

这个想法是：

 1. 计算每门课程有多少个先决条件，这称为**学位**。 
2. 任何具有学位的课程`0`可以立即服用。 
3. 一旦课程完成，通过减少依赖课程的入度来消除其输出依赖关系。 
4.新解锁课程上线。 
5. 继续，直到处理完所有课程。 

如果我们处理所有`numCourses`，我们找到了有效的排序。 否则，循环会阻止完成。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n! × m) | O(n! × m) | O(n) | 尝试每个订购并验证先决条件 |
 | 最优拓扑排序（卡恩算法）| O(V + E) | O(V + E) | 处理每门课程和先决条件一次 |

 这里：

-`V = numCourses`-`E = len(prerequisites)`## 算法演练

 1. **构建图形表示**

 创建一个邻接列表，其中每个课程都指向依赖于它的课程。 

如果`[a, b]`存在，那么我们添加：```
b → a
```这个方向很重要，因为完成`b`解锁`a`。 
2. **计算入度**

 创建一个名为的数组`in_degree`在哪里`in_degree[i]`存储多少先决条件课程`i`仍然需要。 

每个先决条件边都会增加目标节点的入度。 
3. **初始化队列**

 添加每门课程`in_degree == 0`进入队列。 

这些课程没有先决条件，因此可以立即学习。 
4. **使用 BFS 处理课程**

 反复从队列中删除课程。 

将其添加到结果排序中，因为它现在被视为已完成。 

对于每个相关课程：

 - 减少其入度`1`- 如果它的入度变为`0`,将其推入队列

 这模拟完成先决条件后解锁新课程。 
5. **检查周期**

 处理完成后，将结果大小与`numCourses`。 

- 如果所有课程均已处理，则退回订单。 
- 否则，存在循环，因此返回空列表。 

### 为什么它有效

 关键的不变性是，课程**仅当其所有先决条件都已得到处理**时才进入队列。 这保证了当我们将课程附加到最终排序时，每个所需的依赖项都已经出现在结果中的较早位置。 

如果存在循环，则循环中的任何节点都无法达到入度`0`，因此有些课程仍未处理。 检测到这种情况使我们能够正确返回一个空数组。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def findOrder(self, numCourses: int, prerequisites: List[List[int]]) -> List[int]:
        graph = [[] for _ in range(numCourses)]
        in_degree = [0] * numCourses

        # Build graph and calculate in-degrees
        for course, prereq in prerequisites:
            graph[prereq].append(course)
            in_degree[course] += 1

        # Add all courses with no prerequisites
        queue = deque()

        for course in range(numCourses):
            if in_degree[course] == 0:
                queue.append(course)

        order = []

        # Perform BFS topological sort
        while queue:
            current_course = queue.popleft()
            order.append(current_course)

            for neighbor in graph[current_course]:
                in_degree[neighbor] -= 1

                if in_degree[neighbor] == 0:
                    queue.append(neighbor)

        # Check if all courses were processed
        return order if len(order) == numCourses else []
```### 实现说明

 实现首先使用邻接表构建图。 由于每个先决条件对`[a, b]`方法`b`必须先来`a`，我们存储`a`里面`graph[b]`。 

同时，我们保持`in_degree`数组，用于计算每门课程剩余的先决条件数量。 

然后，我们初始化一个包含所有先决条件为零的课程的队列。 这些都可以立即被采取。 

BFS 循环反复从队列中删除课程并将其添加到最终排序中。 一旦课程完成，我们就会减少所有相关课程的入学位。 任何入度达到零的课程都会成为新的可用课程并进入队列。 

最后，我们验证是否每门课程都已处理。 如果结果包含少于`numCourses`项目中，一些课程被困在一个循环中，无法完成。 

## 解决方案```go
func findOrder(numCourses int, prerequisites [][]int) []int {
	graph := make([][]int, numCourses)
	inDegree := make([]int, numCourses)

	// Build graph and calculate in-degrees
	for _, prereq := range prerequisites {
		course := prereq[0]
		required := prereq[1]

		graph[required] = append(graph[required], course)
		inDegree[course]++
	}

	// Initialize queue with zero in-degree nodes
	queue := make([]int, 0)

	for course := 0; course < numCourses; course++ {
		if inDegree[course] == 0 {
			queue = append(queue, course)
		}
	}

	order := make([]int, 0, numCourses)
	index := 0

	// BFS topological sort
	for index < len(queue) {
		currentCourse := queue[index]
		index++

		order = append(order, currentCourse)

		for _, neighbor := range graph[currentCourse] {
			inDegree[neighbor]--

			if inDegree[neighbor] == 0 {
				queue = append(queue, neighbor)
			}
		}
	}

	// Cycle detection
	if len(order) != numCourses {
		return []int{}
	}

	return order
}
```### Go 特定的实现差异

 Go 解决方案遵循完全相同的算法，但在实现细节上略有不同。 

我们不使用双端队列结构，而是用切片和索引指针模拟队列。 这避免了重复从切片前面删除元素，这会导致效率低下。 

我们使用：```go
index := 0
```跟踪队列当前的前端。 

Go 切片是动态的，因此添加新解锁的课程非常简单。 返回循环的空结果是通过以下方式完成的：```
return []int{}
```而不是`nil`，这更符合 LeetCode 的预期。 

整数溢出不是问题，因为约束仍然在 Go 的整数限制内。

def is_valid_order(order, num_courses, prerequisites):
    if len(order) != num_courses:
        return False

    position = {course: i for i, course in enumerate(order)}

    for course, prereq in prerequisites:
        if position[prereq] > position[course]:
            return False

    return True

 ## 边缘情况

 ### 循环依赖

 循环是最重要的边缘情况，因为它使课程无法完成。 例如：```
0 → 1 → 0
```这两门课程都不能先修，因为每门课程都依赖于另一门课程。 幼稚的实现可能会永远循环或返回无效的排序。 我们的实施自然会检测到这一点，因为有些课程从未达到学位`0`，意味着最终结果长度变得小于`numCourses`。 

### 没有先决条件的课程

 如果没有先决条件关系，每门课程都可以立即学习。 脆弱的实现可能会意外地仅返回课程的子集或假设存在依赖关系。 由于我们最初将每个零入度课程排入队列，因此我们的算法正确返回所有课程。 

### 断开的组件

 课程图可以包含独立的课程组。 例如：```
0 → 1

2 → 3
```从单个节点开始的简单 DFS 可能会错过图表的整个部分。 我们的实现在队列初始化期间迭代所有课程，确保包含每个断开连接的组件。 

### 多个有效订单

 某些输入允许许多有效的计划。 例如：```
[[2,0],[2,1]]
```两个都：```
[0,1,2]
```和```
[1,0,2]
```是正确的。 我们的实施并不强制给出唯一的答案。 相反，它返回队列处理中自然出现的任何有效顺序，这完全满足问题要求。
