[LeetCode 第 242 题](https://leetcode.com/problems/valid-anagram/)

 **难度：** 🟢简单
 **主题：** 哈希表、字符串、排序

 ## 解决方案

 ## 问题理解

 该问题要求我们确定两个字符串是否是彼此的**字谜**。 

如果两个字符串包含**完全相同的字符且频率完全相同**，但可能顺序不同，则将它们视为字谜词。 换句话说，一个字符串可以重新排列以形成另一字符串。 

例如，`"anagram"`和`"nagaram"`是字谜词，因为两个字符串包含相同的字符：

 -`a`出现3次
 -`n`出现1次
 -`g`出现1次
 -`r`出现1次
 -`m`出现1次

 顺序不同，但字符数相同。 

另一方面，`"rat"`和`"car"`不是字谜，因为字符不同。 第一个字符串包含`r`,`a`， 和`t`，而第二个包含`c`,`a`， 和`r`。 

输入由两个字符串组成，`s`和`t`，预期输出是一个布尔值：

 - 返回`true`如果`t`是一个字谜词`s`- 返回`false`否则

 约束告诉我们两个字符串的长度都可以为`5 × 10⁴`人物。 这很重要，因为它表明我们应该避免低效的解决方案。 具有二次时间复杂度的算法，例如重复搜索字符，在最坏的情况下会太慢。 

另一个重要的细节是字符串仅包含**小写英文字母**。 由于只有 26 个可能的字符，我们可以利用这个限制来设计一个非常有效的解决方案。 

有几种边缘情况值得预先考虑。 如果字符串具有不同的长度，则它们不可能是字谜词，因为重新排列字符不会改变长度。 具有重复字符的字符串需要仔细计算频率，因为仅仅检查字符是否存在是不够的。 例如，`"aacc"`和`"ccac"`不是字谜，因为计数不同。 该问题还保证字符串非空且仅包含小写英文字母，从而简化了实现。 

## 方法

 ### 蛮力方法

 解决该问题的一个直接方法是对两个字符串进行排序并比较结果。 

道理很简单。 如果两个字符串是字谜词，那么在按字母顺序对它们的字符进行排序后，两个字符串将变得相同。 例如：

-`"anagram"`→`"aaagmnr"`-`"nagaram"`→`"aaagmnr"`由于排序后的版本匹配，因此字符串是字谜词。 

这种方法是正确的，因为排序消除了字符顺序的影响，只留下多组字符。 如果排序后的字符串不同，则至少有一个字符或频率必须不同。 

然而，分类的成本相对较高。 对长度的字符串进行排序`n`需要`O(n log n)`时间。 鉴于字符串最多可以包含`50,000`角色，我们可以做得更好。 

### 最优方法，字符频率计数

 关键的观察是字谜词必须包含**相同的字符频率**。 

我们可以计算每个字符在两个字符串中出现的次数，而不是排序。 如果计数完全匹配，则字符串是字谜词。 

因为问题只保证小写英文字母，所以我们可以使用长度为26的固定大小数组，其中每个索引代表一个字母：

 - 索引`0`→`'a'`- 指数`1`→`'b'`- ...
- 指数`25`→`'z'`我们同时迭代两个字符串：

 - 增加字符数`s`- 减少字符数`t`最后，如果所有计数都为零，则每个字符频率都完美匹配。 

这种方法速度更快，因为它避免了排序并且只扫描字符串一次。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n log n) | O(n log n) | O(n) | 对两个字符串进行排序并比较 |
 | 最佳| O(n) | O(1) | O(1) | 使用固定大小的数组计算字符频率 |

 ## 算法演练

 1.首先检查长度是否`s`和`t`是平等的。 

这是一个重要的优化，因为不同长度的字符串永远不可能是字谜词。 如果长度不同，立即返回`False`。 
2. 创建大小为 26 的频率数组。 

由于输入仅包含小写英文字母，因此固定大小的数组就足够了。 每个位置存储之间的计数差异`s`和`t`。 
3. 同时遍历两个字符串。 

对于每个索引`i`：

 - 增加计数器`s[i]`- 减少计数器`t[i]`这可以有效地跟踪两个字符串之间字符频率的差异。 
4.检查遍历后的频率数组。 

如果数组中的每个值都为零，则频率完全匹配，并且字符串是字谜词。 
5. 返回结果。 

- 如果所有计数均为零，则返回`True`- 否则，返回`False`### 为什么它有效

 该算法保持了频率数组表示之间的**字符数差异**的不变性`s`和`t`。 

每当一个角色出现在`s`，其计数增加。 每当相同的角色出现在`t`，其计数减少。 如果字符串是字谜词，则每个增量最终都会被匹配的减量取消，使所有值都等于零。 

如果有一个值非零，则某个字符在一个字符串中出现的次数多于另一个字符串，这意味着这些字符串不是字谜词。 

## Python 解决方案```python
class Solution:
    def isAnagram(self, s: str, t: str) -> bool:
        if len(s) != len(t):
            return False

        char_counts = [0] * 26

        for i in range(len(s)):
            char_counts[ord(s[i]) - ord('a')] += 1
            char_counts[ord(t[i]) - ord('a')] -= 1

        return all(count == 0 for count in char_counts)
```实现从长度检查开始。 如果字符串大小不同，我们立即返回`False`因为字谜词必须包含相同的字符总数。 

接下来，我们初始化一个名为`char_counts`有 26 个元素，全部设置为零。 每个索引对应一个小写英文字母。 

然后我们同时迭代两个字符串。 对于每一个角色`s`，我们增加其相应的计数器。 对于每一个角色`t`，我们减少其相应的计数器。 通过在同一循环中执行这两项操作，我们可以一次有效地计算频率差。 

最后，我们使用 Python 验证每个计数器是否为零`all()`功能。 如果每个值都为零，则字符串是字谜词。 否则，某些字符数会有所不同，我们将返回`False`。 

## 解决方案```go
func isAnagram(s string, t string) bool {
    if len(s) != len(t) {
        return false
    }

    charCounts := [26]int{}

    for i := 0; i < len(s); i++ {
        charCounts[s[i]-'a']++
        charCounts[t[i]-'a']--
    }

    for _, count := range charCounts {
        if count != 0 {
            return false
        }
    }

    return true
}
```Go 实现遵循与 Python 版本相同的逻辑。 我们使用 26 个整数的固定大小数组来代替列表。 

Go 字符串是 ASCII 字符的字节切片，因此索引为`s[i]`和`t[i]`在这里工作效率很高，因为问题保证了小写英文字母。 此问题不需要 Unicode 处理。 

与Python不同`all()`函数中，Go 需要一个显式循环来验证所有计数是否为零。 

不用担心整数溢出，因为最大字符串长度仅为`50,000`，这完全在 Go 整数类型的范围内。

 ## 边缘情况

 ### 不同的字符串长度

 当两个字符串具有不同长度时，会出现最重要的边缘情况之一，例如`"abc"`和`"abcc"`。 

幼稚的实现可能仍然尝试不必要地比较字符计数，浪费计算甚至导致索引问题。 由于字谜词必须包含完全相同的字符，不同的长度立即证明答案是`False`。 

该实现通过提前返回来正确处理此问题：```
if len(s) != len(t):
    return False
```### 不同频率的重复字符

 错误的另一个常见来源是错误地处理重复的字母。 例如，`"aacc"`和`"ccac"`包含相同的字母集，但计数不同。 

仅检查字符是否存在的简单解决方案将错误地返回`True`。 我们的频率计数方法避免了这个问题，因为每次出现都会影响总计数。 任何不匹配都会在频率数组中留下非零值。 

### 具有相同字符的字符串

 类似的情况`"aaa"`和`"aaa"`可能看起来微不足道，但它们验证重复的相同字符是否得到正确处理。 

一些不正确的实现会意外地覆盖计数而不是累积计数。 我们的方法适当地增加和减少频率，因此所有重复发生的情况都可以准确跟踪。 

### Unicode 跟进

 后续问题询问如何使解决方案适应 Unicode 字符。 

由于 Unicode 包含的字符远远超过 26 个，因此固定大小的数组不再实用。 相反，我们将使用 **哈希映射**（Python 中的字典，Go 中的映射）来动态计算频率。 

例如，在Python中：```python
from collections import Counter

def isAnagram(s: str, t: str) -> bool:
    return Counter(s) == Counter(t)
```这是有效的，因为哈希映射可以有效地存储任何 Unicode 字符的计数，无论字母大小如何。 时间复杂度不变`O(n)`，尽管空间复杂度变为`O(k)`， 在哪里`k`是不同字符的数量。
