 ## 解决方案

 ## 问题理解

 这个问题要求我们辨别其中是否存在“名人”。`n`聚会上的人。 名人有一个非常特殊的属性：

 - 每个人都认识这位名人。 
- 这位名人不认识其他人。 

我们没有直接得到整个关系图。 相反，我们只能通过 helper API 查询关系：```
knows(a, b)
```该函数返回`True`如果人`a`认识人`b`， 否则`False`。 

目标是实施：```
findCelebrity(n)
```返回：

 - 名人的标签（如果存在）
 -`-1`如果没有名人存在

 重要的细节是这是一个交互式问题。 尽管示例显示了矩阵表示，但实际的解决方案必须仅依赖于对`knows`。 

约束条件相对较小，`n <= 100`，所以即使是二次解也是可以接受的。 然而，后续引入了更严格的要求：我们是否最多可以使用`3 * n`API 调用？ 这强烈表明存在比彻底检查每一对更有效的策略。 

幼稚的实现很容易进行不必要的调用。 例如：

 - 很多人一开始可能看起来像名人。 
- 候选人可能仅不符合一项条件。 
- 一个认识别人的人永远不可能成为名人。 
- 一个连一个人都不认识的人不可能成为名人。 

该问题保证：

 -`graph[i][i] == 1`- 关系是确定性的
 - 最多有一位名人

 最终的保证很重要，因为它使我们能够积极淘汰候选人。 

## 方法

 ### 蛮力方法

 暴力解决方案单独检查每个人以确定他们是否满足名人条件。 

对于每个人`i`:

 1. 检查是否`i`认识其他人。 
2. 检查其他人是否知道`i`。 

如果两个条件都成立，那么`i`是名人。 

这是有效的，因为名人的定义是明确的并且易于直接验证。 然而，缺点是对于每个候选人，我们可能需要检查与其他每个人的关系。 

这导致`O(n^2)`API 调用。 

虽然`n <= 100`虽然这在计算上是可以接受的，但它不满足最小化 API 使用的后续要求。 

### 最佳解决方案的关键见解

 关键的观察结果是，单个`knows(a, b)`查询可以将一个人排除在名人考虑范围之外。 

考虑两个人：

 - 如果`a`知道`b`， 然后`a`不可能是名人。 
- 如果`a`不知道`b`， 然后`b`不可能是名人。 

无论哪种情况，都会淘汰一名候选人。 

这意味着我们可以在一次线性传递中识别出一位潜在的名人。 

我们维护一个候选变量：

 - 从人开始`0`。 
- 将当前候选人与其他所有人进行比较。 
- 如果候选人认识某人，该候选人将被取消资格并被替换。 

经过一轮之后，只剩下一位可能的名人。 

然而，成为最终候选人并不能自动保证名人地位。 我们还必须验证：

 - 候选人不认识其他人
 - 其他人都认识这位候选人

 这导致`O(n)`整体解决方案。

 ## 算法演练

 ### 最优候选淘汰算法

 1. 初始化一个候选变量为`0`。 

一开始，理论上任何人都可以成为名人。 
2. 遍历所有来自`1`到`n - 1`。 

对于每个人`i`， 问：```
knows(candidate, i)
```3. 如果现任候选人知道`i`，淘汰候选人。 

由于名人不认识任何人，当前的候选人不再是名人了。 

更新：```
candidate = i
```4. 如果当前候选人不知道`i`， 排除`i`。 

自从`candidate`不知道`i`， 人`i`不能成为名人，因为名人必须是每个人都知道的。 
5. 第一次通过后，只剩下一个可能的名人。 

这还不能证明候选人是有效的。 
6. 执行验证通过。 

对于其他每个人`i`：

- 如果`candidate`知道`i`， 返回`-1`- 如果`i`不知道`candidate`， 返回`-1`7. 如果所有检查均通过，则返回候选人。 

### 为什么它有效

 消除阶段保持一个重要的不变量：

 - 后加工人员`i`, 之前的每个人`i`除非当前的候选人可能已经被淘汰了。 

每次比较都会从考虑中剔除一个人。 由于名人只能存在一位，之后`n - 1`比较最多只能剩下一名候选人。 

验证阶段确保候选人完全满足两个名人属性。 

## Python 解决方案```python
# The knows API is already defined for you.
# return a bool, whether a knows b
# def knows(a: int, b: int) -> bool:

class Solution:
    def findCelebrity(self, n: int) -> int:
        candidate = 0

        # Step 1: Find a potential celebrity
        for person in range(1, n):
            if knows(candidate, person):
                candidate = person

        # Step 2: Verify the candidate
        for person in range(n):
            if person == candidate:
                continue

            # Celebrity should not know anyone
            if knows(candidate, person):
                return -1

            # Everyone should know the celebrity
            if not knows(person, candidate):
                return -1

        return candidate
```该实施遵循前面描述的确切的两阶段策略。 

第一个循环执行候选消除。 每当当前候选人认识另一个人时，该候选人就会被取消资格，因为名人不认识任何人。 这位新人成为迄今为止接受检查的唯一可能的名人。 

第一遍完成后，我们就只有一个潜在的名人了。 第二个循环仔细验证候选人。 

验证会独立检查两个名人的条件：

 - 候选人不得认识任何其他人
 - 其他所有人都必须认识该候选人

 如果任一条件失败一次，该函数将立即返回`-1`。 

否则，该候选人将被确认为名人。 

## 解决方案```go
/**
 * The knows API is already defined for you.
 *     knows := func(a int, b int) bool
 */
func solution(knows func(a int, b int) bool) func(n int) int {
    return func(n int) int {
        candidate := 0

        // Step 1: Find a potential celebrity
        for person := 1; person < n; person++ {
            if knows(candidate, person) {
                candidate = person
            }
        }

        // Step 2: Verify the candidate
        for person := 0; person < n; person++ {
            if person == candidate {
                continue
            }

            // Celebrity should not know anyone
            if knows(candidate, person) {
                return -1
            }

            // Everyone should know the celebrity
            if !knows(person, candidate) {
                return -1
            }
        }

        return candidate
    }
}
```Go 实现在结构上与 Python 版本相同。 

一个小小的区别是 Go 使用显式变量声明和循环语法。 由于所有值都适合标准整数范围，因此不必担心整数溢出。 

该解决方案使用恒定的额外空间，因为在整个执行过程中仅维护少数整数变量。

def find_celebrity_solver(graph):
    n = len(graph)

    def knows(a, b):
        return graph[a][b] == 1

    candidate = 0

    for person in range(1, n):
        if knows(candidate, person):
            candidate = person

    for person in range(n):
        if person == candidate:
            continue

        if knows(candidate, person):
            return -1

        if not knows(person, candidate):
            return -1

    return candidate

 ## 边缘情况

 当只有两个人时，就会出现一种重要的边缘情况。 在这种情况下，算法仍然必须正确确定一个人是否认识另一个人，同时保持自己未知。 小输入通常会暴露循环或验证逻辑中的差一错误。 该实现正确地处理了这个问题，因为消除和验证阶段自然地缩小到规模二，而不需要特殊处理。 

当最终候选人实际上不是名人时，就会出现另一个重要的边缘情况。 淘汰阶段仅保证所有其他候选人均已被排除，而不保证剩余候选人满足名人条件。 一个常见的错误是在第一次通过后立即返回候选者。 验证阶段通过明确检查两个名人属性来防止这种错误。 

第三个重要的边缘情况发生在候选人广为人知但也认识其他人时。 这样的人按照问题的定义是受欢迎的，但不是名人。 实现在验证过程中通过条件正确拒绝了这种情况：```
if knows(candidate, person):
    return -1
```另一种微妙的情况是，由于至少有一个人不认识候选人，所以没有人符合资格。 即使候选人谁都不认识，如果有人不认识他们，他们仍然不符合名人的定义。 第二个验证条件确保正确处理此场景。
