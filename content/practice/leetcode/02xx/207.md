[LeetCode 第 207 题](https://leetcode.com/problems/course-schedule/)

 **难度：** 🟡 中等
 **主题：** 深度优先搜索、广度优先搜索、图论、拓扑排序

 ## 解决方案

 ## 问题理解

 该问题将课程依赖性建模为有向图。 每个课程都表示为一个节点，每个前提关系表示为有向边。 

如果`prerequisites[i] = [a, b]`，这意味着当然`b`必须在课程之前完成`a`。 用图的术语来说，有一条有向边`b`到`a`。 

任务是确定是否有可能完成所有课程。 这相当于询问依赖图是否包含环。 

循环意味着存在循环依赖。 例如：

 - 课程 0 需要课程 1
 - 课程 1 需要课程 0

 在这种情况下，两门课程都不能先修，因此完成所有课程就变得不可能。 

输入包括：

 -`numCourses`，标记的课程总数`0`到`numCourses - 1`-`prerequisites`，先决关系列表

 预期输出是：

 -`true`如果所有课程最终都能完成
 -`false`如果至少存在一个循环依赖

 这些约束很重要，因为它们指导算法的选择：

 - 多达2000门课程
 - 多达 5000 个先决关系

 随着图的增长，暴力模拟会变得低效。 这些限制强烈建议使用图遍历算法，例如深度优先搜索 (DFS)、广度优先搜索 (BFS) 或拓扑排序。 

一些边缘情况很重要：

 - 没有任何先决条件，每门课程都可以立即完成
 - 两门课程之间的直接循环
 - 周期较长，涉及多个课程
 - 多个互不相连的课程组
 - 从未出现在先决条件列表中的课程
 - 许多课程都依赖于相同先决条件的图表

 该问题还保证所有先决条件对都是唯一的，因此重复的边不需要特殊处理。 

## 方法

 ### 蛮力方法

 一种简单的方法是反复搜索已满足先决条件的课程，将其删除，然后继续，直到所有课程均已处理完毕或无法取得任何进展。 

从概念上讲，其工作原理如下：

 - 扫描每门课程
 - 检查是否满足所有先决条件
 - 如果是这样，请将其标记为已完成
 - 重复直到没有新课程可以完成

 这种方法是正确的，因为它模拟了按有效顺序学习课程的实际过程。 如果在某个时刻没有课程可以修完，而仍然有未完成的课程，那么一定存在一个循环。 

然而，这种重复扫描变得低效。 在最坏的情况下，每次迭代都可能再次扫描所有课程和所有先决条件关系。 由于多达 2000 个路线和 5000 个边，重复工作变得不必要的昂贵。 

### 最佳方法

 关键的观察是，这个问题本质上是有向图中的循环检测问题。 

如果图没有循环，则存在有效的拓扑顺序，这意味着课程可以按某种顺序完成。 

检测循环的一种非常有效的方法是使用拓扑排序和广度优先搜索，通常称为卡恩算法。 

这个想法是：

 - 计算每门课程有多少个先决条件，这称为入度
 - 任何入度为0的课程都可以立即修读
 - 课程完成后，移除其出线边缘
 - 这可能会解锁额外的入度为0的课程
 - 继续，直到无法处理更多课程为止

 如果处理了所有课程，则该图是非循环的。 

如果某些课程仍未处理，则它们必定属于一个周期。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(V × E) | O(V + E) | 反复扫描先决条件以查找可用的课程 |
 | 最佳| O(V + E) | O(V + E) | 使用 BFS 拓扑排序和入度跟踪 |

 这里，`V`是课程数量，`E`是先决关系的数量。 

## 算法演练

 ### 最优算法，卡恩拓扑排序

 1. 构建表示该图的邻接表。 

对于每个先决条件对`[a, b]`，添加一条边`b`到`a`。 

这种结构使我们能够快速找到完成另一门课程后哪些课程可用。 
2. 创建入度数组。`indegree[i]`存储多少先决条件课程`i`仍然需要才可以采取。 

每次我们添加一条边`b -> a`, 增量`indegree[a]`。 
3. 初始化一个队列，其中包含所有入度为 0 的课程。 

这些课程没有先决条件，可以立即学习。 

队列是理想的选择，因为我们按照课程可用的顺序处理课程。 
4. 开始处理队列。 

从队列中删除一门课程并将其计为已完成。 

然后查看依赖它的所有相邻课程。 
5. 减少相邻路线的入度。 

完成当前课程满足每个邻居的一个先决条件。 

因此，将它们的入度减 1。 
6. 将新解锁的课程添加到队列中。 

如果邻居的入度变为 0，则意味着现在满足所有先决条件。 

将其推入队列以便稍后处理。 
7. 继续，直到队列变空。 

此时，可以：

 - 所有课程均已成功处理
 - 一些课程仍然陷入循环
 8. 比较已处理课程的数量`numCourses`。 

如果匹配，则返回`True`。 

否则，返回`False`。 

### 为什么它有效

 该算法保持不变，即只有满足所有先决条件的课程才能进入队列。 

在没有循环的图中，重复删除入度为 0 的节点最终会处理完每个节点。 这是有向无环图（也称为 DAG）的基本属性。 

如果存在循环，则循环内的每个节点将始终具有至少一个剩余先决条件。 因此，它们中的任何一个都不会达到入度 0，并且算法将提前终止，留下未处理的课程。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def canFinish(self, numCourses: int, prerequisites: List[List[int]]) -> bool:
        # Build adjacency list
        graph = [[] for _ in range(numCourses)]

        # indegree[i] = number of prerequisites for course i
        indegree = [0] * numCourses

        for course, prereq in prerequisites:
            graph[prereq].append(course)
            indegree[course] += 1

        # Start with courses that have no prerequisites
        queue = deque()

        for course in range(numCourses):
            if indegree[course] == 0:
                queue.append(course)

        completed_courses = 0

        while queue:
            current = queue.popleft()
            completed_courses += 1

            # Remove outgoing edges
            for neighbor in graph[current]:
                indegree[neighbor] -= 1

                # If all prerequisites are satisfied
                if indegree[neighbor] == 0:
                    queue.append(neighbor)

        return completed_courses == numCourses
```实现首先将图构造为邻接表。 每个索引代表一门课程，存储的列表包含依赖于它的课程。 

这`indegree`数组跟踪每门课程还剩下多少先决条件。 每个先决关系都会增加依赖过程的入度。 

队列存储当前所有可用的课程，即入度为0的课程。 

BFS 循环一一处理课程。 当一个路线完成时，通过减少相邻路线的入度来有效地移除所有传出边缘。 

每当邻居的入度变为 0 时，就意味着所有先决条件都已满足，因此该过程就可以进行处理。 

最后，算法检查已完成的课程数是否等于课程总数。 否则，有些课程就会陷入循环。 

## 解决方案```go
func canFinish(numCourses int, prerequisites [][]int) bool {
	graph := make([][]int, numCourses)
	indegree := make([]int, numCourses)

	// Build graph and indegree array
	for _, pair := range prerequisites {
		course := pair[0]
		prereq := pair[1]

		graph[prereq] = append(graph[prereq], course)
		indegree[course]++
	}

	// Queue for BFS
	queue := []int{}

	for course := 0; course < numCourses; course++ {
		if indegree[course] == 0 {
			queue = append(queue, course)
		}
	}

	completedCourses := 0

	for len(queue) > 0 {
		current := queue[0]
		queue = queue[1:]

		completedCourses++

		for _, neighbor := range graph[current] {
			indegree[neighbor]--

			if indegree[neighbor] == 0 {
				queue = append(queue, neighbor)
			}
		}
	}

	return completedCourses == numCourses
}
```Go 实现遵循与 Python 解决方案相同的算法结构。 

而不是Python的`deque`，Go 使用切片作为队列。 移除前面的元件是使用`queue = queue[1:]`。 

Go 切片的大小是动态调整的，使其适合邻接列表和 BFS 队列。 

不需要对整数溢出进行特殊处理，因为所有值都保持在 Go 的范围内`int`问题约束下的范围。 

Go 中的空切片的行为与 Python 中的空列表类似，因此不需要特殊的 nil 处理。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(V + E) | 每门课程和先决条件边缘都会处理一次 |
 | 空间| O(V + E) | 邻接表、入度数组和队列需要额外的存储 |

 图构建阶段处理每个先决条件一次。 BFS 遍历也最多访问每个节点和边一次。 

邻接表存储所有边，入度数组存储每个路线的一个值，并且在最坏情况下队列最多可以包含所有路线。

 ## 边缘情况

 ### 无先决条件

 常见的边缘情况是`prerequisites`是空的。 

在这种情况下，每个课程的入度都为0，可以立即进入队列。 算法正确处理所有课程并返回`True`。 

幼稚的实现有时会忘记正确初始化隔离节点，但此解决方案在构建初始队列时显式迭代所有课程。 

### 涉及多个课程的周期

 循环并不总是直接的两道循环。 较长的周期例如：```
0 -> 1 -> 2 -> 0
```用简单的逻辑很难检测到。 

此实现可以自然地处理此类情况，因为循环中的任何节点都无法达到入度 0。因此，BFS 遍历会提前停止，留下未处理的节点。 

### 断开连接的图形组件

 该图可能包含几个完全独立的课程组。 

例如：```
0 -> 1

2 -> 3
```有缺陷的实现可能只会从一个起点遍历并完全错过另一个组件。 

该解决方案通过首先将每个入度为 0 的路线插入队列来避免该问题，确保探索所有断开连接的组件。 

### 课程未出现在先决条件中

 有些课程可能永远不会出现在先决条件列表中。 

例如：```
numCourses = 5
prerequisites = [[1,0]]
```课程`2`,`3`， 和`4`是完全独立的。 

该算法可以正确处理这个问题，因为除非明确指定先决条件，否则每门课程都以入度 0 开始。 因此，独立课程可以正常处理。
