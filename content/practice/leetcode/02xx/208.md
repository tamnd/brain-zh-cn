[LeetCode 第 208 题](https://leetcode.com/problems/implement-trie-prefix-tree/)

 **难度：** 🟡 中等
 **主题：** 哈希表、字符串、设计、Trie

 ## 解决方案

 ## 问题理解

 该问题要求我们设计并实现一个 Trie，也称为前缀树。 Trie 是一种专门的树结构，用于存储字符串，使得基于前缀的操作非常高效。 

我们需要实现三个操作：

 -`insert(word)`在 Trie 中存储一个单词。 
-`search(word)`检查 Trie 中是否存在确切的单词。 
-`startsWith(prefix)`检查至少一个插入的单词是否以给定前缀开头。 

输入由 Trie 对象上的一系列方法调用组成。 每个操作都会修改或查询内部结构。 查询操作的输出是一个布尔结果，指示请求的单词或前缀是否存在。 

关键细节是该结构针对前缀匹配进行了优化。 与普通哈希集（检查前缀需要扫描许多字符串）不同，Trie 分层组织字符，以便共享前缀重用树中的相同路径。 

约束条件很重要：

 - 单词和前缀最长可达 2000 个字符。 
- 最多可以有`3 * 10^4`运营。 
- 所有字符均为小写英文字母。 

这些限制告诉我们，重复的字符串扫描必须是高效的。 反复将整个字符串与所有存储的单词进行比较的简单解决方案可能会变得非常慢。 由于只使用小写英文字母，每个节点最多有 26 个可能的子节点，这使得 Trie 节点紧凑且可预测。 

一些边缘情况很重要：

 - 即使完整的单词不存在，前缀也可能存在。 
- 一个单词也可以是另一个单词的前缀。 
- 多个插入的单词可能共享长前缀。 
- 搜索从未插入的单词应该返回`false`即使它的一部分存在。 
- 重新插入相同的单词不应破坏结构。 

例如，插入后`"apple"`:

 -`startsWith("app")`应该返回`true`-`search("app")`应该返回`false`这种区别是 Trie 设计背后的核心思想。 

## 方法

 ### 蛮力方法

 暴力解决方案会将所有插入的单词存储在列表或哈希集中。 

为了`insert`，我们只需将单词添加到集合中即可。 

为了`search`，我们检查确切的单词是否存在。 

为了`startsWith`，我们迭代每个存储的单词并检查是否有任何单词以给定的前缀开头。 

这种方法简单且正确，因为每个查询都会直接检查存储的单词。 然而，当存储许多单词时，前缀查询会变得低效。 如果有几千个字，每个字`startsWith`呼叫可能需要扫描所有这些。 

由于每个单词的长度最多可达 2000 个字符，因此重复的前缀比较可能会变得昂贵。 

### 最优 Trie 方法

 关键的见解是许多单词共享共同的前缀。 

例如：

-`"apple"`-`"app"`-`"application"`全部开始于`"app"`。 

我们可以在树结构中表示一次，而不是重复存储这些前缀。 每个节点对应一个字符，从根开始的路径形成单词。 

这允许我们逐字符处理查询：

 - 沿着路径插入或创建节点。 
- 搜索验证每个字符路径是否存在以及最终节点是否标记一个完整的单词。 
- 前缀检查只需要验证路径是否存在。 

这减少了从扫描所有单词到仅遍历查询字符串中的字符的工作。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 |`O(N * L)`用于前缀搜索 |`O(N * L)`| 扫描每个存储的单词 |
 | 最优特里树 |`O(L)`每次操作 |`O(N * L)`| 仅遍历查询字符 |

 这里：

-`N`是存储的单词数
 -`L`是单词或前缀的长度

 ## 算法演练

 ### Trie结构

 每个 Trie 节点存储：

 - 从字符到子节点的映射
 - 一个布尔标志，指示完整的单词是否在此节点结束

 例如，插入`"app"`和`"apple"`创建这个结构：```
root
 └── a
      └── p
           └── p (word ends here)
                └── l
                     └── e (word ends here)
```### 逐步算法

 1. 创建一个根节点，代表Trie的起点。 

根本身不存储字符。 它仅作为所有单词的入口点。 
2. 对于插入，从根开始遍历。 

对于单词中的每个字符：

 - 检查子节点是否已经存在。 
- 如果没有，则创建一个新节点。 
- 移动到子节点。 

处理完所有字符后，将最终节点标记为完整单词。 
3. 再次从根开始搜索。 

对于每个字符：

 - 如果字符路径不存在，则返回`false`。 
- 否则移动到下一个节点。 

处理完所有字符后，返回最终节点是否被标记为完整单词。 
4. 对于前缀检查，完全像搜索一样进行遍历。 

不同的是，我们不要求最终节点代表一个完整的单词。 我们只关心路径是否存在。 
5. 使用哈希图进行子存储。 

字典允许按字符有效地查找子节点。 由于每次查找大约是`O(1)`，总遍历时间仅与字符串长度成正比。 

### 为什么它有效

 Trie 维护每个插入的单词对应于从根开始的唯一路径的不变量。 每个节点代表由沿该路径的字符形成的前缀。 

因为插入创建了所有必需的节点，所以任何有效的前缀路径都将存在于树中。 确切的单词存在是由`is_end`标记，它将完整的单词与单纯的前缀区分开来。 

因此：

 - 如果可以遍历某个前缀的所有字符，则该前缀存在。 
- 如果遍历成功并且最终节点被标记为单词结尾，则完整单词存在。 

这保证了所有操作的正确性。 

## Python 解决方案```python
class TrieNode:
    def __init__(self):
        self.children: dict[str, "TrieNode"] = {}
        self.is_end = False

class Trie:

    def __init__(self):
        self.root = TrieNode()

    def insert(self, word: str) -> None:
        current = self.root

        for char in word:
            if char not in current.children:
                current.children[char] = TrieNode()

            current = current.children[char]

        current.is_end = True

    def search(self, word: str) -> bool:
        current = self.root

        for char in word:
            if char not in current.children:
                return False

            current = current.children[char]

        return current.is_end

    def startsWith(self, prefix: str) -> bool:
        current = self.root

        for char in prefix:
            if char not in current.children:
                return False

            current = current.children[char]

        return True

# Your Trie object will be instantiated and called as such:
# obj = Trie()
# obj.insert(word)
# param_2 = obj.search(word)
# param_3 = obj.startsWith(prefix)
```实施开始于`TrieNode`班级。 每个节点包含：

 -`children`，将字符映射到子节点的字典
 -`is_end`，一个布尔值，指示单词是否在此节点终止

 的`Trie`类存储单个根节点。 

这`insert`方法遍历单词的字符。 如果字符路径不存在，则创建一个新节点。 处理完整个单词后，最后一个节点被标记为有效的单词结尾。 

这`search`方法执行相同的遍历。 但是，如果缺少任何字符，则该单词不存在并且该方法返回`False`。 遍历完成后，该方法检查`is_end`以确保单词完全插入。 

这`startsWith`方法比较简单。 它仅验证前缀路径是否存在。 它不需要最终节点来标记一个完整的单词。 

使用字典可以提高字符查找的效率并保持实现的简洁。 

## 解决方案```go
package main

type TrieNode struct {
	children map[byte]*TrieNode
	isEnd    bool
}

type Trie struct {
	root *TrieNode
}

func Constructor() Trie {
	return Trie{
		root: &TrieNode{
			children: make(map[byte]*TrieNode),
		},
	}
}

func (this *Trie) Insert(word string) {
	current := this.root

	for i := 0; i < len(word); i++ {
		char := word[i]

		if _, exists := current.children[char]; !exists {
			current.children[char] = &TrieNode{
				children: make(map[byte]*TrieNode),
			}
		}

		current = current.children[char]
	}

	current.isEnd = true
}

func (this *Trie) Search(word string) bool {
	current := this.root

	for i := 0; i < len(word); i++ {
		char := word[i]

		if _, exists := current.children[char]; !exists {
			return false
		}

		current = current.children[char]
	}

	return current.isEnd
}

func (this *Trie) StartsWith(prefix string) bool {
	current := this.root

	for i := 0; i < len(prefix); i++ {
		char := prefix[i]

		if _, exists := current.children[char]; !exists {
			return false
		}

		current = current.children[char]
	}

	return true
}

/**
 * Your Trie object will be instantiated and called as such:
 * obj := Constructor();
 * obj.Insert(word);
 * param_2 := obj.Search(word);
 * param_3 := obj.StartsWith(prefix);
 */
```Go 实现遵循与 Python 版本相同的逻辑，但使用显式结构和指针。 

一些特定于 Go 的细节值得注意：

 - 的`children`字段实现为`map[byte]*TrieNode`。 
- 由于输入仅包含小写英文字母，因此按字节索引字符串是安全的。 
- 新的子地图必须使用初始化`make`。 
- 使用指针引用节点以避免不必要的复制。 

整体遍历逻辑保持不变。

 ## 边缘情况

 ### 前缀存在但单词不存在

 这是最重要的 Trie 边缘情况。 插入后`"apple"`, 前缀`"app"`在结构上存在于 Trie 中，但除非明确插入，否则它不应算作一个完整的单词。 

有错误的实现可能会错误地返回`True`为了`search("app")`只是因为遍历成功了。 这`is_end`flag 通过区分完整单词和中间前缀来防止这种错误。 

### 多个单词共享前缀

 诸如此类的话`"car"`,`"cart"`， 和`"care"`全部共享前缀`"car"`。 

简单的树实现可能会意外覆盖节点或无法保留现有路径。 Trie 可以正确处理这个问题，因为插入只会创建缺失的节点，并尽可能重用现有的节点。 

这允许许多单词在同一结构中有效共存。 

### 重复插入

 该问题并不禁止多次插入同一个单词。 

不正确的实现可能会创建重复的结构或损坏的状态。 在此解决方案中，重新插入单词只需遍历相同的路径并设置`is_end = True`再次。 由于该标志已经为真，因此 Trie 保持有效且不变。
