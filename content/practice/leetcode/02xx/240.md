 **难度：** 🟡 中等
 **主题：** 数组、二分查找、分而治之、矩阵

 ## 解决方案

 ## 问题理解

 该问题要求我们确定给定的整数是否`target`存在于一个`m x n`矩阵。 与完全未排序的矩阵不同，该矩阵有两个重要的排序保证：

 1. 每行从左到右按升序排序。 
2. 每列从上到下按升序排列。 

我们得到了矩阵和目标整数，我们必须返回`true`如果目标出现在矩阵中的任何位置，否则`false`。 

换句话说，这不仅仅是通过任意数字进行搜索。 该矩阵具有特殊的结构，使我们能够消除大部分搜索空间，而无需检查每个元素。 

例如，考虑这个矩阵：```
[
  [1,  4,  7, 11, 15],
  [2,  5,  8, 12, 19],
  [3,  6,  9, 16, 22],
  [10,13,14,17,24],
  [18,21,23,26,30]
]
```如果我们正在寻找`5`，答案是`true`因为这个数存在于矩阵中。 如果我们搜索`20`，答案是`false`因为它没有出现。 

这些约束告诉我们有关规模的重要信息：

 -`1 <= m, n <= 300`，这意味着矩阵最多可以包含`90,000`元素。 
- 矩阵值范围为`-10^9`到`10^9`，因此我们不能依赖小值优化，例如计数数组。 
- 行和列保证被排序。 

由于矩阵可能相当大，因此检查每个元素的简单解决方案在实践中仍然可能通过，但该问题明确要求有效的算法。 这强烈表明我们应该利用排序结构。 

预先识别一些边缘情况很重要。 矩阵可能只包含一个元素，因此实现必须正确处理`1 x 1`输入。 目标可能小于最小元素或大于最大元素，这应该很快会导致`false`。 矩阵也可以包含负数，因此算法不得假设为正数。 最后，由于行和列是独立排序的，因此如果将矩阵展平为单个数组，则矩阵不会进行全局排序，这意味着对整个矩阵的二分搜索无效。 

## 方法

 ### 蛮力方法

 最简单的解决方案是逐一检查矩阵中的每个元素，并将其与目标进行比较。 

我们迭代每一行，然后迭代该行中的每个数字。 如果我们遇到目标，我们会立即返回`true`。 如果我们扫描完整个矩阵而没有找到它，我们返回`false`。 

这种方法保证是正确的，因为它会检查目标可能存在的每个可能位置。 如果目标出现在任何地方，我们最终都会遇到它。 

然而，该解决方案忽略了矩阵的排序结构。 在最坏的情况下，我们会检查所有`m * n`元素。 高达`90,000`条目，当存在更好的方法时，这会不必要地昂贵。 

### 最佳方法，右上角搜索

 关键的见解来自于智能地使用矩阵排序。 

假设我们从矩阵的**右上角**开始。 

在任何位置`(row, col)`：

 - 下面的所有内容**大于或等于**当前值，因为列已排序。 
- 左边的所有内容都**小于或等于**当前值，因为行已排序。 

这给了我们一个强大的消除策略：

 - 如果当前值等于目标，我们就完成了。 
- 如果当前值大于目标，我们**向左**移动，因为下面的所有内容只会更大。 
- 如果当前值小于目标，我们**向下**，因为左边的所有内容只会更小。 

每次移动都会消除整行或整列的考虑。 

因为我们最多搬家`m`次向下和`n`向左移动 1 次，总功变为`O(m + n)`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(m × n) | O(1) | O(1) | 单独检查每个元素 |
 | 最佳| O(m + n) | O(1) | O(1) | 从右上角开始消除行或列 |

 ## 算法演练

 ### 最优算法

 1. 在矩阵的**右上角**初始化一个指针。 

我们选择这个位置是因为它为我们提供了方向信息。 从右上角开始，向左移动会减少值，向下移动会增加值。```
Start here
       ↓
[1, 4, 7,11,15]
[2, 5, 8,12,19]
[3, 6, 9,16,22]
```2. 将当前值与目标值进行比较。 

如果当前值等于目标值，则返回`true`立即，因为我们找到了所需的元素。 
3. 如果当前值大于目标值，则向左移动。 

由于该列是从上到下排序的，因此下面的每个数字都更大。 因此，整个当前列可以被丢弃。 
4. 如果当前值小于目标值，则向下移动。 

由于该行是从左到右排序的，因此左边的每个数字都较小。 因此，整个当前行可以被丢弃。 
5. 继续直到：

 - 我们找到目标并返回`true`- 我们移出矩阵边界并返回`false`出界意味着所有可行的位置都被淘汰。 

### 为什么它有效

 该算法之所以有效，是因为保持了不变性：在每一步中，剩余的搜索区域仍然包含目标可能存在的每个可能位置。 

当我们在看到大于目标的值后向左移动时，我们可以安全地消除整个列​​，因为下面的所有值都更大。 类似地，当我们在看到小于目标的值后向下移动时，我们可以安全地消除整行，因为左侧的所有值都较小。 由于每个决策都会删除不可能的候选者而不丢弃有效的可能性，因此算法保证找到目标（如果存在）。 

## Python 解决方案```python
from typing import List

class Solution:
    def searchMatrix(self, matrix: List[List[int]], target: int) -> bool:
        rows = len(matrix)
        cols = len(matrix[0])

        row = 0
        col = cols - 1

        while row < rows and col >= 0:
            current_value = matrix[row][col]

            if current_value == target:
                return True

            if current_value > target:
                col -= 1
            else:
                row += 1

        return False
```实现首先确定行数和列数。 由于问题保证了至少一行一列，所以我们可以安全地访问`matrix[0]`。 

我们通过设置初始化右上角的搜索位置`row = 0`和`col = cols - 1`。 

这`while`只要我们保持在矩阵边界内，循环就会继续。 在每次迭代中，我们检查`matrix[row][col]`。 

如果当前值等于目标值，我们立即返回`True`。 

如果当前值太大，我们递减`col`向左移动，因为下面的一切都更大，因此不可能。 

如果当前值太小，我们就增加`row`向下移动，因为左边的所有东西都较小，因此不可能。 

如果循环退出，则意味着所有有效搜索位置都已用尽，因此我们返回`False`。 

## 解决方案```go
func searchMatrix(matrix [][]int, target int) bool {
	rows := len(matrix)
	cols := len(matrix[0])

	row := 0
	col := cols - 1

	for row < rows && col >= 0 {
		currentValue := matrix[row][col]

		if currentValue == target {
			return true
		}

		if currentValue > target {
			col--
		} else {
			row++
		}
	}

	return false
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 我们计算矩阵维度，从右上角开始，根据比较结果重复消除行或列。 

Go 特有的一个小细节是切片的使用（`[][]int`）而不是列表。 由于该问题保证非空矩阵，因此访问`matrix[0]`安全，不需要额外的防护条件。 整数溢出不是问题，因为比较是直接执行的，并且矩阵值非常适合 Go 的整数范围。

 ## 边缘情况

 ### 单元素矩阵

 一个`1 x 1`矩阵是最小可能的有效输入。 这种情况可能会暴露索引错误或边界条件错误。 例如，循环条件不正确的实现可能会意外地立即移出界限。 我们的实现自然地处理了这个问题，因为搜索从唯一的元素开始并执行一次比较。 

### 目标超出矩阵范围

 如果目标小于最小元素或大于最大元素，朴素算法仍可能不必要地扫描矩阵的大部分内容。 例如：```
[
 [5, 6],
 [7, 8]
]
```正在寻找`1`或者`100`应该很快就会失败。 右上角的搜索自然会消除行或列，直到退出边界，正确返回`false`。 

### 单行或单列

 仅具有一行或一列的矩阵表现不同，因为移动变为一维。 当算法假设两个维度都大于一时，经常会出现错误。 在单行矩阵中，算法重复向左移动。 在单列矩阵中，它反复向下移动。 由于我们的循环条件显式检查边界，因此这两种情况都可以正确处理，无需特殊情况逻辑。 

### 负数和大值

 因为值的范围可以是`-10^9`到`10^9`，实现必须避免关于积极性或小范围的假设。 我们的解决方案仅依赖于比较，而不依赖于算术技巧或基于值大小的索引，因此无论数字大小或符号如何，它都可以正常工作。
