[LeetCode 第 254 题](https://leetcode.com/problems/factor-combinations/)

 **难度：** 🟡 中等
 **主题：** 回溯

 ## 解决方案

 ## 问题理解

 这个问题要求我们生成每一种独特的方式来表达数字`n`作为大于的整数的乘积`1`并且小于`n`。 

因子组合是一个整数列表，其乘积等于`n`。 组合内的顺序并不重要。 例如，对于`12`, 组合`[2, 6]`和`[6, 2]`代表相同的因式分解，因此结果中只能出现其中之一。 

输入是单个整数`n`，输出是列表的列表。 每个内部列表包含乘积等于的因子`n`。 

约束条件`1 <= n <= 10^7`很重要，因为它排除了对所有可能序列进行极其昂贵的暴力枚举。 然而，输入仍然足够小，使得带有修剪的递归回溯是有效的。 

有几种边缘情况需要尽早识别：

 - 如果`n = 1`，没有有效的因式分解，因为允许的因数必须在范围内`[2, n - 1]`。 
- 如果`n`是素数，结果为空，因为素数没有非平凡因子。 
——重复因素必须正确处理。 例如，`16`可以生产`[2,2,2,2]`,`[2,2,4]`,`[2,8]`， 和`[4,4]`。 
- 必须避免重复的组合。 该算法不应同时产生`[2,6]`和`[6,2]`。 

关键的挑战是有效地生成所有有效的组合，同时避免重复。 

## 方法

 ### 蛮力方法

 暴力策略会尝试所有可能的整数组合`2`到`n - 1`，检查他们的乘积是否等于`n`。 

例如，对于`n = 12`，我们可以尝试每种可能的序列，例如：

 -`[2,2,3]`-`[2,3,2]`-`[3,2,2]`-`[2,6]`-`[6,2]`然后我们会过滤掉无效或重复的组合。 

这是有效的，因为最终会探索每个有效的因式分解。 然而，由于候选序列的数量呈指数增长，因此效率极低。 大多数生成的组合不会相乘`n`，并且许多有效的因式分解以不同的顺序出现多次。 

即使对于中等大的值，蛮力方法也变得不切实际`n`。 

### 最优方法，通过因子剪枝回溯

 关键的见解是因素组合自然地形成递归结构。 

如果一个数字`n`可以被某个因数整除`f`，那么剩下的问题就变成寻找因子组合`n / f`。 

例如：

-`12 = 2 × 6`- 现在分解`6`-`6 = 2 × 3`这给出了`[2,2,3]`。 

另一个重要的观察结果是组合应该以非降序生成。 如果我们只允许未来因子大于或等于当前因子，我们就会自动避免重复。 

例如：

 - 允许`[2,6]`- 不允许`[6,2]`我们也只需要搜索因子`sqrt(current_number)`因为大于平方根的因子必须与已考虑的较小因子配对。 

这极大地减少了搜索空间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数，实践中大约为 O(2^n) | O(n) | 尝试许多无效和重复的组合 |
 | 最佳| 大约 O(k * sqrt(n)) | O(log n) 递归深度，不包括输出 | 使用递归因子分解和修剪 |

 ## 算法演练

 1. 初始化一个空的结果列表，用于存储所有有效的因子组合。 
2. 创建一个具有三个参数的递归回溯函数：

 -`remaining`，我们仍然需要对当前数字进行因式分解
 -`start_factor`，接下来我们可以使用的最小因子
 -`current_path`，当前正在构建的组合
 3. 在递归函数中，迭代所有可能的因素`start_factor`最多`sqrt(remaining)`。 
4. 对于每个候选因素：

 - 检查是否分裂`remaining`。 
- 如果`remaining % factor == 0`，那么它就是一个有效因子。 
5. 当找到有效因素时：

 - 将因子附加到当前路径。 
- 互补因素是`remaining // factor`。 
6. 至此，我们已经有了一个有效的因子组合：

 -`current_path + [complement]`- 将此组合添加到结果列表中。 
7. 继续递归探索更深层次的因式分解：

 - 调用递归函数`remaining // factor`- 使用`factor`再次作为新的最小允许因素
 - 这允许重复的因素，例如`[2,2,2,2]`8. 递归完成后，从路径中删除最后一个因素进行回溯并探索其他可能性。 
9. 继续，直到探索完所有因素。 

### 为什么它有效

 该算法保持了一个重要的不变量：因素`current_path`始终按非递减顺序排列。 

由于这个属性：

 - 每个有效组合仅生成一次。 
- 重复排列是不可能的。 
- 递归分解保证了每次因式分解`n`最终被探索出来。 

平方根界限确保我们永远不会错过任何因子对，因为每个较大的因子必须与之前检查过的较小因子配对。 

## Python 解决方案```python
from typing import List
import math

class Solution:
    def getFactors(self, n: int) -> List[List[int]]:
        result = []

        def backtrack(remaining: int, start_factor: int, path: List[int]) -> None:
            limit = int(math.sqrt(remaining)) + 1

            for factor in range(start_factor, limit):
                if remaining % factor == 0:
                    complement = remaining // factor

                    result.append(path + [factor, complement])

                    path.append(factor)
                    backtrack(complement, factor, path)
                    path.pop()

        backtrack(n, 2, [])

        return result
```在代码块之后，将实现的每个部分与递归策略连接起来是很有帮助的。 

这`result`列表存储搜索过程中发现的每个有效因素组合。 

这`backtrack`辅助函数执行递归探索。 这`remaining`参数表示仍需要分解的数字部分。 这`start_factor`参数强制执行非递减顺序，这可以防止重复。 这`path`list 存储当前的部分组合。 

循环最多只搜索`sqrt(remaining)`。 如果存在大于平方根的因子，则其配对的较小因子必须已被处理。 

每当找到有效因子时，算法就会立即使用互补因子构建完整的组合。 例如，如果`remaining = 12`和`factor = 2`，补集是`6`，生产`[2,6]`。 

然后，递归调用继续进一步分解补集。 这就是组合方式`[2,2,3]`被发现。 

这`path.pop()`声明是回溯步骤。 它恢复之前的状态，因此算法可以独立探索其他因素选择。 

## 解决方案```go
package main

import "math"

func getFactors(n int) [][]int {
	var result [][]int

	var backtrack func(remaining int, startFactor int, path []int)

	backtrack = func(remaining int, startFactor int, path []int) {
		limit := int(math.Sqrt(float64(remaining)))

		for factor := startFactor; factor <= limit; factor++ {
			if remaining%factor == 0 {
				complement := remaining / factor

				combination := append([]int{}, path...)
				combination = append(combination, factor, complement)
				result = append(result, combination)

				path = append(path, factor)
				backtrack(complement, factor, path)
				path = path[:len(path)-1]
			}
		}
	}

	backtrack(n, 2, []int{})

	return result
}
```Go 实现遵循与 Python 版本相同的递归逻辑，但有一些特定于语言的注意事项。 

Go 中的切片是对底层数组的引用，因此在存储组合时`result`，我们必须使用创建一个副本`append([]int{}, path...)`。 如果不进行复制，回溯期间的后续修改将破坏先前存储的结果。 

递归深度仍然很小，因为每个递归步骤至少将剩余值除以`2`。 

Go 还需要之间的显式转换`float64`和`int`使用时`math.Sqrt`。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | 大约 O(k * sqrt(n)) | 每个递归级别检查因子直至平方根 |
 | 空间| O(log n) 不包括输出 | 递归深度受重复除法的限制 |

 确切的运行时间取决于生成的因子组合的数量。 高度合数比质数产生更多的递归分支。 

递归深度是对数的，因为每个递归步骤都会将剩余值减少至少一个因子`2`。 输出本身可能包含许多组合，这是不可避免的，因为必须返回所有有效的分解。

 ## 边缘情况

 ### 输入等于 1

 当`n = 1`，没有有效因子，因为允许的因子范围是`[2, n - 1]`，这是空的。 一个幼稚的实现可能会意外地包括`[1]`或尝试无效的递归。 此实现正确返回一个空列表，因为初始因子循环永远不会执行。 

### 质数

 素数，例如`37`没有非平凡的因数。 某些实现错误地将数字本身包含为因子对。 该解决方案避免了该错误，因为搜索仅检查来自`2`通过`sqrt(n)`，并且仅当存在有效除数时才形成组合。 

### 重复因素

 像这样的数字`16`需要重复使用相同的因子：```
16 = 2 × 2 × 2 × 2
```一个常见的错误是因素出现一次后就无法重复使用。 此实现通过将当前因子作为下一个因子传递来避免该问题`start_factor`，允许重复选择，同时仍然防止重复排列。 

### 重复排列

 如果没有排序限制，该算法可以生成`[2,6]`和`[6,2]`。 此实现通过不允许递归调用使用小于当前因子的因子来强制执行非递减顺序。 因此，每个独特的组合只会出现一次。
