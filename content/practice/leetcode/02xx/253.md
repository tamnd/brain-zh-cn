 ## 解决方案

 ## 问题理解

 该问题为我们提供了会议间隔列表，其中每个间隔表示为`[start, end]`。 每个时间间隔描述了会议占用会议室的时间范围。 目标是确定所需的最少会议室数量，以便所有会议都能顺利举行而不会发生冲突。 

一个房间可以召开多个会议，只要时间不重叠即可。 如果一个会议恰好在另一个会议开始时结束，则可以重复使用同一房间，因为在这种情况下，时间间隔被视为不重叠。 

例如，如果我们有会议`[[0,30],[5,10],[15,20]]`, 会议`[0,30]`与两者重叠`[5,10]`和`[15,20]`。 时`5`，两个会议同时进行，这意味着至少需要两个房间。 

输入大小可以大到`10^4`间隔，这意味着低效的二次解可能会变得太慢。 间隔值本身可以很大，最多可达`10^6`，但这并不重要，因为我们主要关心排序和重叠关系。 

尽早识别一些边缘情况很重要：

 - 完全不重叠的会议应该只需要一个房间。 
- 完全重叠的会议需要与会议数量一样多的房间。 
- 触及界限的会议，例如`[1,5]`和`[5,10]`，应重复使用同一房间。 
- 不保证间隔被排序。 
- 总是至少有一个间隔。 

## 方法

 ### 蛮力方法

 一种简单的方法是将每个会议与其他会议进行比较，并确定每个时间点有多少会议重叠。 一种可能的实现是手动跟踪房间分配，并通过检查所有先前分配的会议来尝试将每个会议放入现有房间。 

这是有效的，因为每个重叠关系都被明确检查。 如果现有房间无法容纳会议，我们会分配一个新房间。 

然而，这种方法效率很低，因为对于每次会议，我们可能需要扫描所有当前分配的房间以及可能在其中的所有会议。 在最坏的情况下，这会导致二次时间复杂度。 

高达`10^4`会议、`O(n^2)`算法可能会变得太慢。 

### 最佳方法

 关键的观察结果是，我们只关心在任何时刻有多少会议同时处于活动状态。 

如果我们按时间顺序处理会议，我们就可以跟踪房间何时可用。 最好的方法是：

 1. 按开始时间对会议进行排序。 
2. 跟踪当前使用房间的最早结束的会议。 
3. 如果下一个会议在最早的会议结束之后或恰好在最早的会议结束时开始，则可以重复使用该房间。 
4. 否则，我们需要一个新房间。 

最小堆在这里是理想的，因为它有效地为我们提供了最早结束时间的会议。 

堆代表所有当前占用的房间。 它的大小随时告诉我们有多少房间正在使用。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 明确检查会议之间的重叠情况 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 使用排序和结束时间的最小堆 |

 ## 算法演练

 1. 按开始时间对所有会议间隔进行排序。 

排序可确保我们按时间顺序处理会议。 这使我们能够决定会议是否可以重复使用现有房间或需要一个新房间。 
2. 创建一个最小堆来存储会议结束时间。 

堆跟踪当前正在使用的房间。 最小的结束时间总是在顶部，它告诉我们哪个房间首先空闲。 
3. 将第一次会议的结束时间添加到堆中。 

第一次会议至少需要一个房间。 
4. 逐一迭代剩余的会议。 

对于每个会议，将其开始时间与堆中最小的结束时间进行比较。 
5. 如果会议在最早的会议结束之后或恰好在最早的会议结束时开始，请重复使用该房间。 

从堆中删除最早的结束时间，因为该会议已结束。 
6. 将当前会议的结束时间推入堆中。 

这会将房间标记为已占用，直到当前会议结束。 
7. 继续，直到处理完所有会议。 
8、堆的大小代表当前使用的房间数，达到的最大大小就是需要的最小房间数。 

在此实现中，处理所有间隔后的最终堆大小给出了正确的答案，因为我们仅在房间可用时才删除它们。 

### 为什么它有效

 该算法保持堆恰好包含当前占用房间的会议的结束时间这一不变式。 通过始终首先删除最早结束的会议，我们尽可能地重复使用房间。 由于在会议结束之前没有房间可以重复使用，并且我们总是选择最早可用的房间，因此该算法最大限度地减少了所需房间的总数。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def minMeetingRooms(self, intervals: List[List[int]]) -> int:
        if not intervals:
            return 0

        intervals.sort(key=lambda interval: interval[0])

        min_heap = []

        heapq.heappush(min_heap, intervals[0][1])

        for start, end in intervals[1:]:
            if start >= min_heap[0]:
                heapq.heappop(min_heap)

            heapq.heappush(min_heap, end)

        return len(min_heap)
```实现首先根据开始时间对间隔进行排序。 这保证了会议按时间顺序进行。 

名为的最小堆`min_heap`存储活动会议的结束时间。 最小结束时间始终在索引处可用`0`，使我们能够有效地确定哪个房间首先空闲。 

第一次会议始终需要一个房间，因此其结束时间会立即推入堆中。 

对于每个后续会议，我们将其开始时间与堆中最小的结束时间进行比较：

 - 如果开始时间大于或等于最早结束时间，则房间可以重用，因此我们弹出堆。 
- 无论重用还是分配，我们都会将当前会议的结束时间推入堆中。 

最后，堆大小等于所需的房间数。 

## 解决方案```go
package main

import (
	"container/heap"
	"sort"
)

type MinHeap []int

func (h MinHeap) Len() int {
	return len(h)
}

func (h MinHeap) Less(i, j int) bool {
	return h[i] < h[j]
}

func (h MinHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MinHeap) Push(x interface{}) {
	*h = append(*h, x.(int))
}

func (h *MinHeap) Pop() interface{} {
	old := *h
	n := len(old)
	item := old[n-1]
	*h = old[:n-1]
	return item
}

func minMeetingRooms(intervals [][]int) int {
	if len(intervals) == 0 {
		return 0
	}

	sort.Slice(intervals, func(i, j int) bool {
		return intervals[i][0] < intervals[j][0]
	})

	minHeap := &MinHeap{}
	heap.Init(minHeap)

	heap.Push(minHeap, intervals[0][1])

	for _, interval := range intervals[1:] {
		start := interval[0]
		end := interval[1]

		if start >= (*minHeap)[0] {
			heap.Pop(minHeap)
		}

		heap.Push(minHeap, end)
	}

	return minHeap.Len()
}
```Go 实现遵循与 Python 解决方案相同的逻辑，但需要使用显式堆实现`container/heap`包裹。 

Go 没有为整数提供内置的最小堆，因此我们定义了一个自定义的`MinHeap`类型实现所需的接口方法。 

与 Python 不同，Go 明确区分切片和堆操作。 我们使用指针接收器`Push`和`Pop`因为堆操作会修改底层切片。 

整数溢出不是问题，因为间隔值完全在 Go 的整数范围内。

 ## 边缘情况

 一种重要的边缘情况是完全触及其边界的会议，例如`[[1,5],[5,10]]`。 一个常见的错误是使用严格的大于比较而不是大于或等于。 如果实施检查`start > end`而不是`start >= end`，它错误地分配了额外的房间。 此解决方案可以正确地重用房间，因为它允许在上一个会议恰好在新会议的开始时间结束时重用。 

另一个重要的情况是所有会议完全重叠，例如`[[1,10],[2,9],[3,8]]`。 在这种情况下，每个会议都需要自己的房间，因为没有人可以重复使用现有的房间。 堆不断增长以包含所有活动会议，并且算法正确返回会议总数。 

未排序的输入也是错误的主要来源。 间隔可以按任意顺序到达，并且只有当按时间顺序处理会议时，重叠决策才能正确工作。 该实现在进行任何处理之前显式地按开始时间对间隔进行排序，从而确保正确性，无论输入顺序如何。 

最后一个微妙的边缘情况是一次会议。 某些实现错误地假设存在多个间隔，并且可能尝试访问不存在的元素。 该解决方案可以自然地处理这种情况，因为堆是使用第一个间隔初始化的，并且剩余间隔上的循环根本不执行。
