 **难度：** 🟡 中等
 **主题：** 数组、字符串、递归

 ## 解决方案

 ## 问题理解

 该问题要求我们生成给定长度的每个频闪数`n`。 

频闪数字是旋转 180 度后仍然有效的数字。 并非每个数字都在轮换下工作。 仅以下数字映射有效：

 | 原创| 旋转|
 | --- | --- |
 | 0 | 0 |
 | 1 | 1 |
 | 6 | 9 |
 | 8 | 8 |
 | 9 | 6 |

 例如，`"69"`变成`"96"`旋转后，它仍然是一个有效的数字。 相似地，`"88"`遗迹`"88"`。 

输入是单个整数`n`，表示我们必须生成的数字的确切长度。 输出是字符串列表，因为在递归期间某些生成的值可能在内部以零开头，并且字符串操作对于此问题更自然。 

约束足够小，可以生成所有有效的组合。 自从`n <= 14`，有效频闪图数的总数是可控的。 这强烈建议采用建设性的生成方法，而不是检查每个可能的数字。 

一些边缘情况很重要：

 - 数字不能有前导零，除非数字本身有长度`1`。 例如，`"00"`无效于`n = 2`。 
- 奇数长度的数字必须有一个映射到其自身的有效中间数字。 仅有的`0`,`1`， 和`8`满足这个条件。 
- 偶数长度的数字没有中心数字，因此每个位置必须对称配对。 
- 如果不小心处理，递归生成可能会意外地产生无效的最外层零。 

## 方法

 ### 蛮力方法

 暴力解决方案将精确地生成每个数字`n`数字并检查每一位是否是频闪图。 

为了验证一个数字，我们可以从两端向中心扫描，并确保每个数字对都属于有效的旋转映射。 例如，如果左边的数字是`6`，对应的右边数字一定是`9`。 

这种方法是正确的，因为它详尽地检查了每个候选人。 然而，它的效率极低。 有`10^n`可能的长度数`n`，即使对于中等值，它也会变得巨大`n`。 自从`n`可以大到`14`，蛮力是完全不切实际的。 

### 最优递归构造

 关键的观察结果是频闪数字是高度结构化的。 

我们可以直接仅构造有效的频闪数字，而不是生成每个可能的数字并过滤有效的数字。 

频闪数是从外向内对称构建的。 如果我们将一个数字放在左侧，则右侧将由旋转映射自动确定。 

例如：

 - 如果我们放置`6`在左边，我们必须放置`9`在右侧。 
- 如果我们放置`1`在左边，我们必须放置`1`在右侧。 

这自然会导致递归：

 - 首先构建较小的频闪图数。 
- 用有效的数字对包围它们。 
- 继续，直到达到所需的长度。 

这完全避免了生成无效的候选者。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(10^n × n) | O(10^n × n) | O(n) | 生成每个 n 位数字并验证每个 |
 | 最佳| O(5^(n/2)) | O(5^(n/2)) | O(5^(n/2)) | O(5^(n/2)) | 仅递归构造有效的频闪图数 |

 ## 算法演练

 ### 最优递归算法

 1. 定义所有有效的频闪数字对。 

我们存储以下对：```
('0', '0')
('1', '1')
('6', '9')
('8', '8')
('9', '6')
```这些代表唯一有效的外部数字组合。 
2. 创建递归辅助函数。 

辅助函数生成所有长度的频闪数`currentLength`。 

我们还跟踪原始目标长度，这样我们就可以避免最外层出现前导零。 
3. 定义基本案例。 

如果`currentLength == 0`， 返回`[""]`。 

这代表一个空中心并允许向外递归扩展。 

如果`currentLength == 1`， 返回`["0", "1", "8"]`。 

这些是单独旋转时唯一保持有效的数字。 
4. 递归地生成更小的频闪数。 

我们呼叫助手`currentLength - 2`。 

这会生成所有有效的内部部分。 
5. 使用有效对扩展每个较小的结果。 

对于每个内部字符串：

 - 添加`"0"`和`"0"`在它周围
 - 添加`"1"`和`"1"`在它周围
 - 添加`"6"`和`"9"`在它周围
 - 添加`"8"`和`"8"`在它周围
 - 添加`"9"`和`"6"`在它周围
 6. 防止出现前导零。 

构建最外层时，一定不要放置`"0"`在前面。 

我们使用以下方法检测这一点：```
if currentLength != originalLength
```内部递归层允许包含零，因为它们不是最终结果中的前导数字。 
7. 返回构造好的列表。 

处理完所有内部字符串和所有有效对后，助手将返回该长度的每个有效频闪数字。 

### 为什么它有效

 该算法之所以有效，是因为每个频闪数必须满足旋转对称性。 每个外部数字唯一地确定其镜像对应项。 通过首先递归地构建内部部分，然后用有效的数字对包围它，该算法保证每个生成的数字都是有效的。 由于在每个级别上都探索了每个可能的有效对，因此不会错过任何有效的频闪图数字。 

## Python 解决方案```python
from typing import List

class Solution:
    def findStrobogrammatic(self, n: int) -> List[str]:
        pairs = [
            ('0', '0'),
            ('1', '1'),
            ('6', '9'),
            ('8', '8'),
            ('9', '6')
        ]

        def build(current_length: int, target_length: int) -> List[str]:
            if current_length == 0:
                return [""]

            if current_length == 1:
                return ["0", "1", "8"]

            inner_numbers = build(current_length - 2, target_length)

            result = []

            for middle in inner_numbers:
                for left, right in pairs:
                    if current_length == target_length and left == '0':
                        continue

                    result.append(left + middle + right)

            return result

        return build(n, n)
```实现首先定义所有有效的频闪数字对。 这些对直接编码旋转对称规则。 

递归`build`函数生成给定长度的所有有效频闪图数。 参数`current_length`表示当前正在构建的大小，而`target_length`保留原始请求的大小。 

长度的基本情况`0`返回一个空字符串，在递归扩展期间充当中性中心。 长度的基本情况`1`返回唯一有效的自循环数字。 

对于较大的长度，该函数递归地生成所有较小的有效内部字符串。 然后，每个内部字符串都用每个有效的数字对包裹。 

防止出现前导零的条件至关重要。 我们只跳过`('0', '0')`构建最外层时配对。 内层仍可能安全地包含零。 

最后，该函数返回所有构造的字符串。 

## 解决方案```go
func findStrobogrammatic(n int) []string {
	pairs := [][]string{
		{"0", "0"},
		{"1", "1"},
		{"6", "9"},
		{"8", "8"},
		{"9", "6"},
	}

	var build func(int, int) []string

	build = func(currentLength int, targetLength int) []string {
		if currentLength == 0 {
			return []string{""}
		}

		if currentLength == 1 {
			return []string{"0", "1", "8"}
		}

		innerNumbers := build(currentLength-2, targetLength)

		result := []string{}

		for _, middle := range innerNumbers {
			for _, pair := range pairs {
				left := pair[0]
				right := pair[1]

				if currentLength == targetLength && left == "0" {
					continue
				}

				result = append(result, left+middle+right)
			}
		}

		return result
	}

	return build(n, n)
}
```Go 解决方案遵循与 Python 实现相同的递归结构。 切片用于动态存储生成的字符串。 

一个显着的区别是 Go 要求递归匿名函数显式函数变量声明。 这`build`函数先声明，后赋值。 

Go 字符串是不可变的，就像 Python 字符串一样，因此连接可以安全地创建新字符串。 

不存在整数溢出问题，因为该算法完全基于字符串而不是数字转换进行操作。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(5^(n/2)) | O(5^(n/2)) | 每个递归层最多分支为 5 个有效数字对 |
 | 空间| O(5^(n/2)) | O(5^(n/2)) | 需要存储所有生成的频闪图数 |

 递归深度最多为`n / 2`，因为每个步骤都会占据两个位置。 每个级别最多有 5 个分支选择。 因此，生成的字符串总数与`5^(n/2)`。 

空间复杂度由输出本身决定，因为必须存储和返回所有有效的频闪数字。

class Solution:
    def findStrobogrammatic(self, n: int) -> List[str]:
        pairs = [
            ('0', '0'),
            ('1', '1'),
            ('6', '9'),
            ('8', '8'),
            ('9', '6')
        ]

        def build(current_length: int, target_length: int) -> List[str]:

assert sorted(solution.findStrobogrammatic(1)) == ["0", "1", "8"]

# Example case for n = 2
assert sorted(solution.findStrobogrammatic(2)) == ["11", "69", "88", "96"]

# Small odd length
assert sorted(solution.findStrobogrammatic(3)) == sorted([
    "101", "111", "181",
    "609", "619", "689",
    "808", "818", "888",
    "906", "916", "986"

# Ensure no leading zeros for n > 1
result = solution.findStrobogrammatic(4)
assert all(not num.startswith("0") for num in result)

# Verify all generated numbers have correct length
result = solution.findStrobogrammatic(5)
assert all(len(num) == 5 for num in result)

# Verify rotational symmetry property
mapping = {
    '0': '0',
    '1': '1',
    '6': '9',
    '8': '8',
    '9': '6'
}

for number in solution.findStrobogrammatic(5):
    rotated = "".join(mapping[d] for d in reversed(number))
    assert rotated == number

# Boundary case: largest allowed n
result = solution.findStrobogrammatic(14)
assert all(len(num) == 14 for num in result)

 ## 边缘情况

 ### 个位数输入

 当`n = 1`，该数字仅包含一个中心数字。 许多实现错误地允许数字，例如`6`或者`9`位于中心，但这些数字相互旋转而不是它们自己。 仅有的`0`,`1`， 和`8`是有效的单位频闪图数字。 该实现在`current_length == 1`基本情况。 

### 前导零

 一个非常常见的错误是意外生成数字，例如`"00"`或者`"0110"`用于多位输入。 这些是无效的，因为标准数字表示不能以零开头。 该实现通过跳过`("0", "0")`仅在构造最外层时配对。 

### 奇数长度数字

 奇数长度的频闪图数字需要有效的中心数字。 一些递归解决方案错误地假设每个位置都必须配对，这对于奇数长度会失败。 该实现通过以下方式自然地处理这个问题`current_length == 1`基本情况，允许递归以单个有效的中间数字终止。 

### 大输入

 对于`n = 14`，生成的字符串数量变大。 暴力方法是完全不可行的，因为它会尝试检查数万亿的候选人。 递归构造方法仍然有效，因为它只生成有效的数字并避免不必要的计算。
