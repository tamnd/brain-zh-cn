 **难度：** 🟡 中等
 **主题：** 数组、哈希表、排序、计数

 ## 解决方案

 ## 问题理解

 该问题要求我们找到整数数组中出现次数超过的每个元素`⌊ n/3 ⌋`时间、地点`n`是数组的长度。 向下取整表示法意味着我们向下舍入到最接近的整数。 例如，如果数组长度为8，则`⌊ 8/3 ⌋ = 2`，所以我们要寻找出现次数超过 2 次的元素。 

输入是一个名为的整数数组`nums`。 输出应该是一个列表，其中包含频率超过阈值的所有值`n/3`。 返回元素的顺序并不重要。 

一个重要的观察是最多可以有两个这样的元素。 这是从简单的计数逻辑得出的。 如果存在三个不同的元素，每个元素出现的次数都超过`n/3`次，它们的总计数将超过`n`，这是不可能的。 

这些约束告诉我们一些重要的事情：

 - 该数组最多可以包含`5 * 10^4`元素，因此低效的二次解可能会变得太慢。 
- 值的范围可以是`-10^9`到`10^9`，这意味着我们不能依赖对按值索引的数组进行计数。 
- 后续明确要求线性时间和恒定的额外空间，这强烈表明需要一种专门的计数技术。 

一些边缘情况很重要：

 - 长度为 1 或 2 的数组，其中每个元素都可能符合条件。 
- 没有重复多数元素的数组。 
- 正好有两个元素超出的数组`n/3`。 
- 处理过程中候选值多次更改的数组。 
- 负整数和混合值。 

该问题保证输入数组非空，因此我们永远不需要处理空输入。 

## 方法

 ### 蛮力方法

 最直接的解决办法就是统计数组中每个数字出现的频率。 一种简单的方法是迭代每个元素，并通过再次扫描整个数组来计算它出现的次数。 

对于每个数字：

 - 遍历数组
 - 计算出现次数
 - 如果计数超过`n/3`，如果尚不存在，则将其添加到结果中

 这是有效的，因为它显式地计算了精确的频率。 然而，时间复杂度变为`O(n^2)`因为每个元素都可能触发数组的另一次完整遍历。 

稍微改进的暴力解决方案使用哈希图来存储频率。 这将时间复杂度降低到`O(n)`但需要`O(n)`额外的空间。 虽然对于基本问题来说可以接受，但是不能满足后续恒定额外空间的要求。 

### 最佳解决方案的关键见解

 关键的见解是最多可以有两个元素出现超过`n/3`次。 

这使我们能够适应博耶-摩尔投票算法。 最初的 Boyer-Moore 算法发现出现次数多于的多数元素`n/2`次使用一名候选人和一名计数器。 由于这个问题最多允许两个多数元素，我们认为：

 - 两个候选值
 - 两个柜台

 该算法的工作原理是相互抵消不同的元素。 每当我们遇到与任一候选值都不匹配且两个计数器均非零的新值时，我们都会递减两个计数器。 这有效地从考虑中消除了三个不同元素的一次出现。 

如果某个元素确实出现超过`n/3`有时，它无法通过此取消过程完全消除，因此它将作为最终候选者之一生存下来。 

第一次通过后，候选者只是潜在的答案。 我们必须执行第二遍来验证它们的实际频率。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 通过重复扫描数组来对每个元素进行计数 |
 | 最佳| O(n) | O(1) | O(1) | 具有两名候选人的 Boyer-Moore 投票算法 |

 ## 算法演练

 1. 初始化两个候选变量和两个计数器。 

由于最多可以有两个有效的多数元素，因此我们跟踪两个可能的候选者。 最初，两个计数器都为零，这意味着尚未选择任何候选人。 
2. 遍历数组一次以确定潜在的候选者。 

对于数组中的每个数字：

 - 如果该数字与第一个候选者匹配，则递增第一个计数器。 
- 否则，如果它与第二个候选匹配，则增加第二个计数器。 
- 否则，如果第一个计数器为零，则用当前数字替换第一个候选者并将其计数器设置为 1。 
- 否则，如果第二个计数器为零，则用当前数字替换第二个候选者，并将其计数器设置为一。 
- 否则，减少两个计数器。 

递减步骤是取消过程的核心。 它消除了由三种不同价值观组成的群体的影响。 
3. 核实候选人。 

第一次遍历之后，候选的只是可能的答案。 我们计算每个候选者实际出现在数组中的次数。 
4. 构建结果列表。 

添加频率超过的任何候选者`n/3`到结果。 

### 为什么它有效

 该算法依赖于这样一个事实：从数组中删除三个不同的元素无法消除出现次数超过的真正多数元素`n/3`次。 由于任何有效的多数元素出现得太频繁而无法完全取消，因此在取消过程后它必须保留为最终候选者之一。 第二遍通过验证实际频率来保证正确性。 

## Python 解决方案```python
from typing import List

class Solution:
    def majorityElement(self, nums: List[int]) -> List[int]:
        candidate1 = None
        candidate2 = None
        count1 = 0
        count2 = 0

        # First pass: find potential candidates
        for num in nums:
            if candidate1 == num:
                count1 += 1
            elif candidate2 == num:
                count2 += 1
            elif count1 == 0:
                candidate1 = num
                count1 = 1
            elif count2 == 0:
                candidate2 = num
                count2 = 1
            else:
                count1 -= 1
                count2 -= 1

        # Second pass: verify frequencies
        count1 = 0
        count2 = 0

        for num in nums:
            if num == candidate1:
                count1 += 1
            elif num == candidate2:
                count2 += 1

        result = []
        threshold = len(nums) // 3

        if count1 > threshold:
            result.append(candidate1)

        if count2 > threshold:
            result.append(candidate2)

        return result
```实施过程严格遵循博耶-摩尔多数投票策略。 

第一部分初始化两个候选变量及其计数器。 候选人开始为`None`因为尚未选择任何值。 

第一个循环执行候选选择阶段。 匹配的候选者增加其计数器，当计数器达到零时填充空的候选者槽，并且冲突的值同时减少两个计数器。 

第二阶段重置计数器并执行验证。 这是必要的，因为第一遍仅识别可能的多数元素，而不是保证的元素。 

最后，通过检查每个经过验证的候选者是否超过所需阈值来构建结果列表。 

## 解决方案```go
func majorityElement(nums []int) []int {
    var candidate1, candidate2 int
    count1, count2 := 0, 0

    // First pass: find potential candidates
    for _, num := range nums {
        if candidate1 == num {
            count1++
        } else if candidate2 == num {
            count2++
        } else if count1 == 0 {
            candidate1 = num
            count1 = 1
        } else if count2 == 0 {
            candidate2 = num
            count2 = 1
        } else {
            count1--
            count2--
        }
    }

    // Second pass: verify frequencies
    count1, count2 = 0, 0

    for _, num := range nums {
        if num == candidate1 {
            count1++
        } else if num == candidate2 {
            count2++
        }
    }

    result := []int{}
    threshold := len(nums) / 3

    if count1 > threshold {
        result = append(result, candidate1)
    }

    if count2 > threshold {
        result = append(result, candidate2)
    }

    return result
}
```Go 实现密切反映了 Python 逻辑。 由于Go不支持`None`，候选变量被初始化为零值，但这是安全的，因为计数器确定候选槽是否处于活动状态。 

结果列表使用了切片，整数除法在Go中很自然地进行了地板除法，这符合问题要求。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 两次线性遍历数组 |
 | 空间| O(1) | O(1) | 仅使用固定数量的变量 |

 该算法对数组执行两次完整的遍历。 第一个确定候选多数元素，第二个验证它们的频率。 由于两次遍历都是线性的，所以总体时间复杂度为`O(n)`。 

空间复杂度保持不变，因为我们只存储两个候选者、两个计数器和一个小的结果列表。 不使用与输入大小成比例的辅助数据结构。

 ## 边缘情况

 一种重要的边缘情况是非常小的数组。 当数组长度为1或2时，阈值`⌊ n/3 ⌋`变为零。 这意味着每个不同的元素都符合资格。 有缺陷的实现可能会错误地假设只存在一个答案或错误地处理候选初始化。 该算法自然地处理这个问题，因为验证步骤根据计算的阈值检查频率。 

另一个重要的情况是当没有元素出现超过`n/3`次。 例如，`[1,2,3,4]`没有有效答案。 候选选择阶段仍会产生一些候选，因为它必须维护两个可能的值，但第二次验证可防止返回错误结果。 

当候选项在遍历过程中反复变化时，就会出现第三种棘手的情况。 数组如`[1,2,3,1,2,1,1]`导致多次减量操作和候选替换。 不正确的实现可能会在取消期间丢失真正的多数元素。 Boyer-Moore 逻辑保证真正的多数元素在消除过程中幸存下来，并且验证通过准确地确认了最终答案。
