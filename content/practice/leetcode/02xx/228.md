 # LeetCode 228，总结范围

 ## 问题理解

 该问题为我们提供了一个由唯一整数组成的排序数组，并要求我们将连续值汇总为紧凑范围的字符串。 

范围表示连续的整数序列。 例如，数字`[4,5,6]`可以表示为`"4->6"`因为数组中存在 4 到 6 之间的每个整数。 单个隔离值，例如`7`应该简单地表示为`"7"`。 

重要的细节是输出必须恰好覆盖每个数字一次，不包括数组中不存在的数字。 由于输入已经排序并且不包含重复项，因此可以通过检查下一个数字是否比当前数字正好大 1 来识别连续范围。 

例如：

-`[0,1,2]`变成`"0->2"`-`[7]`变成`"7"`-`[4,5]`变成`"4->5"`输入数组可以为空，这意味着答案也应该是一个空列表。 

限制非常小，最多 20 个数字，但目标仍然是设计一个干净高效的解决方案。 排序和唯一的保证非常重要，因为它们大大简化了问题：

 - 由于数组是排序的，连续的数字总是相邻出现。 
- 由于值是唯一的，我们永远不需要担心重复项会干扰范围检测。 

一些边缘情况很重要：

 - 应该返回一个空数组`[]`。 
- 单个元素数组应返回仅包含该数字作为字符串的列表。 
- 每个数字都是连续的数组应该恰好产生一个范围。 
- 没有连续数字的数组应仅生成单个数字范围。 
- 负值也必须正确工作。 

## 方法

 ### 蛮力方法

 蛮力方法将尝试通过重复检查每个起点的每个可能的延续来构建范围。 对于每个数字，我们可以向前扫描直到序列中断，然后从下一个未使用的数字重新开始。 

这是有效的，因为输入是排序的，因此连续的数字会出现在一起。 然而，如果我们重复地重新扫描数组的某些部分或执行冗余比较，实现可能会变得低效。 

例如，如果我们从索引开始`i`，我们可以一直扫描到末尾来找到范围边界。 然后以后的迭代可能会再次重新访问许多相同的元素。 

尽管这个问题中的约束很小，但这种重复扫描的方式可能会导致较大输入中的二次行为。 

### 最佳方法

 关键的观察是每个数字只需要处理一次。 

由于数组已排序且唯一，因此当下一个数字不等于当前数字加一时，范围恰好结束。 

这意味着我们可以使用单遍从左到右扫描数组：

 - 记录当前范围的开始。 
- 继续前进，同时数字保持连续。 
- 一旦序列中断，最终确定当前范围字符串。 
- 从下一个数字开始一个新范围。 

这种方法很有效，因为每个元素仅被访问一次。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) 不包括输出 | 重复重新扫描数组的各个部分 |
 | 最佳| O(n) | O(1) 不包括输出 | 单次遍历数组 |

 ## 算法演练

 1. 创建一个空结果列表，用于存储最终范围字符串。 
2. 使用索引指针从左到右处理数组。 每次迭代都首先将当前数字标记为新范围的开始。 
3. 将当前值存储为`range_start`。 当我们尝试扩展范围时，该值将保持固定。 
4. 当下一个数字连续时，向前移动索引。 如果满足以下条件，两个数字是连续的：```
nums[i + 1] == nums[i] + 1
```只要这个条件成立，当前的范围就会持续下去。 
5. 当连续序列结束时，当前数字成为范围的末尾。 
6. 如果开始和结束是相同的值，则附加单个数字字符串，例如`"7"`。 
7. 否则，附加一个范围字符串，例如`"4->6"`。 
8. 从下一个未处理的数字开始继续扫描，直到处理完整个数组。 

### 为什么它有效

 该算法保持了每个处理过的元素恰好属于一个完整范围的不变性。 

由于该数组已排序且唯一，因此每个连续序列都显示为一个连续块。 内部循环扩展范围直到序列中断，保证产生的范围是最大的。 由于算法在开始下一个范围之前会前进到所有已处理的元素，因此不会跳过或重复任何数字。 

## Python 解决方案```python
from typing import List

class Solution:
    def summaryRanges(self, nums: List[int]) -> List[str]:
        result: List[str] = []
        n = len(nums)
        index = 0

        while index < n:
            range_start = nums[index]

            while (
                index + 1 < n
                and nums[index + 1] == nums[index] + 1
            ):
                index += 1

            range_end = nums[index]

            if range_start == range_end:
                result.append(str(range_start))
            else:
                result.append(f"{range_start}->{range_end}")

            index += 1

        return result
```实现首先初始化一个空结果列表和一个索引指针。 

外层`while`循环一次处理一个范围。 At the beginning of each iteration, the current value becomes the start of the range.

 The inner loop extends the range as long as consecutive numbers continue appearing. Since the array is sorted, consecutive values must appear immediately next to each other.

 After the loop finishes, the current index points to the final value in the range. The code then decides whether the range contains a single value or multiple values.

 If both ends are equal, the output format is just the number itself. 否则，范围的格式使用`"start->end"`。 

最后，索引向前移动，开始处理下一个范围。 

## 解决方案```go
package main

import "strconv"

func summaryRanges(nums []int) []string {
	result := []string{}
	n := len(nums)
	index := 0

	for index < n {
		rangeStart := nums[index]

		for index+1 < n && nums[index+1] == nums[index]+1 {
			index++
		}

		rangeEnd := nums[index]

		if rangeStart == rangeEnd {
			result = append(result, strconv.Itoa(rangeStart))
		} else {
			rangeString := strconv.Itoa(rangeStart) + "->" + strconv.Itoa(rangeEnd)
			result = append(result, rangeString)
		}

		index++
	}

	return result
}
```Go 实现遵循与 Python 解决方案完全相同的逻辑。 

一个显着的区别是字符串转换。 Go 需要`strconv.Itoa()`将整数转换为字符串。 

结果存储在字符串切片中。 空输入自然会返回空切片，因为循环永远不会执行。 

整数比较是安全的，因为约束符合 LeetCode 系统上 Go 的标准整数范围。

 ## 边缘情况

 ### 空数组

 如果假设至少存在一个元素，则空输入是实现最容易失败的地方之一。 

例如，访问`nums[0]`不检查数组长度会导致索引错误。 此实现避免了该问题，因为外循环仅在以下情况下执行`index < n`。 如果`n`为零，循环体永远不会运行，并且函数正确返回一个空列表。 

### 单元素数组

 当数组仅包含一个值时，算法必须返回单个数字字符串而不是范围格式。 

例如：```
[7] -> ["7"]
```一个常见的错误总是将输出格式化为`"start->end"`，这会错误地产生`"7->7"`。 在决定如何格式化结果之前，实现显式检查范围开始和范围结束是否相等。 

### 没有连续数字

 数组就像`[1,3,5,7]`根本不包含连续的对。 

在这种情况下，每个数字都应该成为自己单独的范围。 对于每个元素，内部循环都会立即停止，因为下一个数字永远不会等于当前数字加一。 

该实现自然会处理这个问题，因为每次迭代都会创建一个单元素范围。 

### 整个数组是一个范围

 数组就像`[1,2,3,4,5]`测试算法是否可以正确地将范围一直扩展到数组末尾。 

一个常见的错误是循环结束后未能最终确定最后一个范围。 此实现避免了该问题，因为范围是在内部循环结束后立即添加的，即使序列一直持续到最后一个元素。
