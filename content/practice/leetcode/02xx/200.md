 **难度：** 🟡 中等
 **主题：** 数组、深度优先搜索、广度优先搜索、并查找、矩阵

 ## 解决方案

 ## 问题理解

 该问题给了我们一个二维网格，其中每个单元格包含`'1'`或者`'0'`。 

一个单元格包含`'1'`代表土地，而一个单元格包含`'0'`代表水。 岛屿被定义为一组相连的陆地单元。 仅当两个陆地单元水平或垂直连接时才属于同一岛屿。 对角线连接不算数。 

我们的目标是计算网格中存在多少个独立的岛屿。 

例如，考虑这个网格：```
1 1 0
0 1 0
1 0 1
```左上角一组相连的陆地单元形成一个岛。 左下角的孤立陆地单元形成了另一个岛屿。 右下角的陆地单元形成了第三个岛屿。 因此答案是`3`。 

约束告诉我们网格的两个维度都可以大到`300 x 300`。 这意味着网格最多可以包含 90,000 个单元。 由于这个大小，我们需要一种能够有效处理每个单元的算法。 具有极高复杂性的解决方案是不切实际的。 

问题陈述中得出了几个重要的观察结果：

 - 网格保证只包含`'0'`和`'1'`- 从概念上讲，所有四个边缘都被水包围，因此我们不需要特殊的边缘包裹逻辑
 - 连接仅是水平和垂直的
 - 每个陆地单元都属于一个岛屿

 还有几种边缘情况可能会导致简单实现中的错误：

 - 只包含水的网格应该返回`0`- 只包含土地的网格应该返回`1`- 单细胞网格必须正确处理
 - 对角陆地单元不得视为相连
 - 如果访问的单元没有正确跟踪，大型连接的岛屿可能会导致重复遍历

 核心挑战是确定哪些陆地单元属于同一连接组件。 

## 方法

 ### 蛮力方法

 一种简单的方法是尝试将每个陆地单元与其他每个陆地单元进行比较，以确定它们是否属于同一个岛屿。 

对于每个`'1'`cell，我们可以反复向外搜索并手动维护分组。 然而，如果没有有效的遍历策略，算法可能会多次重新访问相同的单元格。 在最坏的情况下，这可能会导致过多的重复工作。 

例如，想象一个充满土地的网格。 每个新细胞都可能触发对已经探索过的区域的另一次大规模搜索。 这会导致不必要的计算和较差的可扩展性。 

虽然这种蛮力式的方法最终可以产生正确的答案，但对于接近约束极限的大型网格来说，它变得低效。 

### 最优方法，图遍历

 关键的见解是网格自然地形成了一个图形。 

每个陆地单元都是一个节点，水平或垂直相邻的陆地单元之间存在边。 岛只是该图中的一个连接组件。 

这意味着我们可以使用以下任一方法来解决问题：

 - 深度优先搜索，DFS
 - 广度优先搜索，BFS

 这个想法很简单：

 1. 迭代网格中的每个单元格。 
2. 当发现一个未访问过的陆地单元时，我们就发现了一个新岛屿。 
3. 从该单元开始 DFS 或 BFS 遍历。 
4. 将每个连接的陆地单元标记为已访问。 
5. 继续扫描网格。 

每个岛只计数一次，因为遍历后，属于该岛的所有单元都被标记为已访问。 

这种方法很有效，因为每个单元最多被处理一次。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O((m × n)²) | O(m × n) | 反复重新访问区域并执行冗余搜索 |
 | 最优 DFS/BFS | O(m × n) | O(m × n) | 在探索连接的组件时访问每个单元一次 |

 ## 算法演练

 ### DFS遍历策略

 我们将使用深度优先搜索来实现。 

1. 首先确定网格中的行数和列数。 遍历期间进行边界检查需要这些尺寸。 
2. 创建一个名为`island_count`初始化为`0`。 该变量跟踪已发现的不同岛屿的数量。 
3. 使用嵌套循环遍历网格中的每个单元格。 
4. 对于每个单元格，检查它是否包含土地（`'1'`）。 
5. 如果细胞含有水（`'0'`），跳过它，因为水不能属于岛屿。 
6. 如果单元格包含陆地，我们就发现了一个新岛屿。 增量`island_count`。 
7.从此单元格开始DFS遍历。 DFS 的目的是访问与当前岛屿相连的每个陆地单元。 
8.DFS内部：

 - 将当前单元格标记为已访问
 - 探索所有四个方向：

 - 向上
 - 向下
 - 左
 - 右
 9. 对于每个相邻小区：

 - 确保坐标保持在网格边界内
 - 仅当邻居也是陆地时才继续 DFS
 10. 为了避免重复访问单元格，将访问过的陆地单元格标记为水（`'0'`）。 这会直接修改网格并消除对单独访问矩阵的需要。 
11. DFS 完成后，整个岛屿就已处理完毕。 
12. 继续扫描网格中的剩余单元格，直到检查完每个位置。 

在最后，`island_count`包含岛屿总数。 

## Python 解决方案```python
from typing import List

class Solution:
    def numIslands(self, grid: List[List[str]]) -> int:
        if not grid or not grid[0]:
            return 0

        rows = len(grid)
        cols = len(grid[0])

        def dfs(row: int, col: int) -> None:
            if (
                row < 0
                or row >= rows
                or col < 0
                or col >= cols
                or grid[row][col] == "0"
            ):
                return

            grid[row][col] = "0"

            dfs(row - 1, col)
            dfs(row + 1, col)
            dfs(row, col - 1)
            dfs(row, col + 1)

        island_count = 0

        for row in range(rows):
            for col in range(cols):
                if grid[row][col] == "1":
                    island_count += 1
                    dfs(row, col)

        return island_count
```实现首先对空输入进行安全检查。 尽管约束保证了有效的维度，但防御性编程使解决方案更加稳健。 

嵌套的`dfs`函数执行递归遍历。 第一个条件检查坐标是否在网格之外或者当前单元格是否是水。 如果其中任何一个条件为真，则递归立即停止。 

当访问陆地单元时，它会从`'1'`到`'0'`。 这用作访问过的标记。 由于此修改，未来的遍历将不会再次处理相同的单元格。 

然后，DFS 递归地探索所有四个相邻方向。 

外部嵌套循环扫描整个网格。 每次遇到未访问过的陆地单元，都会发现一个新岛屿。 计数器增加，DFS 将整个连接的组件从未来的考虑中删除。 

这保证了每个岛都为最终答案贡献了一个增量。 

## 解决方案```go
func numIslands(grid [][]byte) int {
    if len(grid) == 0 || len(grid[0]) == 0 {
        return 0
    }

    rows := len(grid)
    cols := len(grid[0])

    var dfs func(int, int)

    dfs = func(row int, col int) {
        if row < 0 || row >= rows || col < 0 || col >= cols || grid[row][col] == '0' {
            return
        }

        grid[row][col] = '0'

        dfs(row-1, col)
        dfs(row+1, col)
        dfs(row, col-1)
        dfs(row, col+1)
    }

    islandCount := 0

    for row := 0; row < rows; row++ {
        for col := 0; col < cols; col++ {
            if grid[row][col] == '1' {
                islandCount++
                dfs(row, col)
            }
        }
    }

    return islandCount
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 一个显着的区别是 Go 使用`[][]byte`而不是`List[List[str]]`。 

递归 DFS 函数是使用函数变量声明的，因为递归匿名函数需要在 Go 中事先声明。 

访问过的单元格仍然通过替换直接标记在网格内`'1'`和`'0'`。 由于 Go 切片是类似引用的结构，因此 DFS 内部的修改会自动影响原始网格。 

整数溢出不是问题，因为最大单元数仅为 90,000。

```## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(m × n) | 每个单元格最多被访问一次 |
 | 空间| O(m × n) | 在最坏的情况下，递归 DFS 堆栈可能包含许多单元 |

 该算法对每个网格位置精确扫描一次。 尽管 DFS 递归地探索邻居，但在标记为已访问后不会重新访问任何单元。 因此，总工作量与细胞数量成正比。 

空间复杂度主要来自递归深度。 在最坏的情况下，例如网格完全充满土地，递归堆栈可能包含最多`m × n`来电。 

## 边缘情况

 ### 仅包含水的网格

 考虑这个输入：```
[
  ["0","0"],
  ["0","0"]
]
```有缺陷的实现可能会错误地增加岛屿计数器或尝试不必要的遍历。 

在此解决方案中，仅当单元格包含时才会触发 DFS`'1'`。 由于不存在土地，计数器仍然存在`0`。 

### 仅包含土地的网格

 考虑：```
[
  ["1","1"],
  ["1","1"]
]
```如果访问跟踪丢失，幼稚的实现可能会单独计算每个单元格。 

我们的 DFS 遍历标记了第一次探索期间访问过的每个连接的陆地单元。 结果，整个网格在一次 DFS 调用后被处理，产生正确的答案：`1`。 

### 对角线连接

 考虑：```
[
  ["1","0"],
  ["0","1"]
]
```这两个陆地单元对角接触，但根据问题规则并未连接。 

该实现仅探索四个方向：上、下、左、右。 对角邻居永远不会被遍历，因此算法正确地计算了两个独立的岛屿。 

### 单细胞网格

 考虑：```
[
  ["1"]
]
```或者```
[
  ["0"]
]
```小输入通常会暴露边界检查错误。 

DFS 边界条件正确处理网格外的坐标，即使网格仅包含一个元素，外部遍历也能工作。 因此，实现正确返回`1`或者`0`取决于单元格值。
