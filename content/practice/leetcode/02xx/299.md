[LeetCode 第 299 题](https://leetcode.com/problems/bulls-and-cows/)

 **难度：** 🟡 中等
 **主题：** 哈希表、字符串、计数

 ## 解决方案

 ## 问题理解

 问题给出两个字符串，`secret`和`guess`，表示两个长度相等的数字。 我们需要比较它们并返回格式提示`"xAyB"`。 

“牛”是一个在数值和位置上都匹配的数字。 例如，如果`secret[i] == guess[i]`，那么该数字贡献一头公牛。 

“cow”是两个字符串中都存在但出现在不同位置的数字。 重要的是，奶牛只计算在尚未计为公牛的数字中。 当存在重复数字时，此细节变得尤为重要。 

例如：

-`secret = "1807"`-`guess = "7810"`数字`8`在两个字符串中出现在相同的位置，因此它是一头公牛。 数字`7`,`1`， 和`0`两个字符串中都存在，但位置错了，所以它们是牛。 

输入约束相对较小，最多 1000 个字符，但问题仍然需要高效的线性时间解决方案。 由于字符串仅包含数字，因此我们可以利用固定大小的计数结构，而不是更昂贵的通用数据结构。 

最重要的挑战是正确处理重复的数字。 幼稚的实现可能会意外地像奶牛那样多次计算相同的数字。 考虑：

-`secret = "1123"`-`guess = "0111"`只有一头公牛，并且只有一头额外的牛`1`可以算作一头牛。 剩下的不匹配的`1`在`guess`不应该被计算在内，因为没有剩余的不匹配的`1`在`secret`。 

当所有数字都是公牛时，就会出现另一个重要的边缘情况，这意味着奶牛应该为零。 同样，如果没有数字匹配，则两个计数都应为零。 

该问题保证：

 - 两个字符串的长度相同
 - 长度至少为1
 - 输入仅包含数字

 这些保证简化了实现，因为我们永远不需要验证输入格式或处理不匹配的长度。 

## 方法

 ### 蛮力方法

 一种简单的方法是首先通过比较两个字符串中的相应位置来识别多头。 之后，对于每个不匹配的数字`guess`，我们可以搜索其中不匹配的数字`secret`查看该数字是否存在于其他地方。 

为了避免重复计算奶牛，我们需要一个辅助结构来跟踪其中的数字`secret`已经被使用了。 

这种方法可以正确工作，因为每个不匹配的数字`guess`明确检查剩余的不匹配数字`secret`。 然而，重复的搜索使得效率低下。 

在最坏的情况下，对于每个字符，我们可能会扫描几乎整个剩余字符串，从而导致时间复杂度呈二次方。 

### 最佳方法

 关键的观察是，在确定多头之后，我们实际上并不关心不匹配数字的位置。 我们只关心每个数字在不匹配的字符中出现了多少次。 

这自然暗示了一种计数方法。 

我们首先直接计算多头。 对于非多头头寸，我们使用数组或哈希图跟踪数字频率。 由于数字范围仅从`0`到`9`，长度为 10 的固定大小数组就足够了。 

一种优雅的优化是使用平衡计数技术一次性处理奶牛：

 - 如果一个数字来自`secret`以前需要`guess`，我们发现了一头牛。 
- 如果一个数字来自`guess`之前由`secret`，我们发现了一头牛。 

这使我们能够在一次遍历中计算公牛和奶牛。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 重复搜索不匹配的数字 |
 | 最佳 | O(n) | O(1) | O(1) | 使用数字频率计数 |

 ## 算法演练

 1.初始化两个计数器，`bulls`和`cows`，都从 0 开始。 
2. 创建一个大小为 10 并初始化为零的频率数组。 每个索引代表一个数字`0`到`9`。 
3. 使用单个循环同时遍历两个字符串。 
4. 在每个位置：

 - 如果`secret[i] == guess[i]`，那么这个数字就是牛。 增量`bulls`。 
- 否则，数字不匹配，可能会贡献给奶牛。 
5. 对于不匹配的数字：

 - 将两个字符转换为整数：

 -`s = int(secret[i])`-`g = int(guess[i])`6. 检查当前的秘密数字是否满足先前未匹配的猜测数字：

 - 如果`count[s] < 0`，这意味着该数字在迄今为止未匹配的猜测中出现的次数更多。 
- 因此，我们找到了一个匹配的放错位置的数字，所以增加`cows`。 
7. 检查当前猜测数字是否满足先前未匹配的秘密数字：

 - 如果`count[g] > 0`，表示该数字在迄今为止无法匹配的秘密数字中出现的次数较多。 
- 因此，增加`cows`。 
8.更新频率平衡：

 - 增量`count[s]`- 递减`count[g]`9. 处理完所有字符后，返回结果，格式为：```
"{bulls}A{cows}B"
```### 为什么它有效

 频率阵列保留了在中看到的不匹配数字之间的差异`secret`以及在中看到的不匹配的数字`guess`。 

- 正值表示额外出现的次数`secret`- 负值意味着额外出现`guess`每当处理一个新的不匹配数字解决了相反字符串中先前不匹配的出现时，我们就发现了一头有效的牛。 

由于每个不匹配的数字都恰好平衡一次，因此可以正确处理重复的数字，而不会出现过度计数。 

## Python 解决方案```python
class Solution:
    def getHint(self, secret: str, guess: str) -> str:
        bulls = 0
        cows = 0
        
        count = [0] * 10
        
        for s_char, g_char in zip(secret, guess):
            if s_char == g_char:
                bulls += 1
            else:
                s = int(s_char)
                g = int(g_char)
                
                if count[s] < 0:
                    cows += 1
                
                if count[g] > 0:
                    cows += 1
                
                count[s] += 1
                count[g] -= 1
        
        return f"{bulls}A{cows}B"
```该实现紧密遵循前面描述的算法。 

变量`bulls`和`cows`存储最终计数。 这`count`阵列跟踪来自不匹配数字之间的频率不平衡`secret`和`guess`。 

该循环使用同时处理两个字符串`zip`。 当字符完全匹配时，该数字立即被归类为公牛。 

对于不匹配的数字，代码会检查当前数字是否可以从相反的字符串中解决先前不匹配的情况。 这是让奶牛一次性计数的关键洞察力。 

频率更新发生在检查之后，因为我们想要与之前看到的不匹配的数字进行比较，而不是当前的数字。 

最后按照要求返回格式化后的字符串`"xAyB"`格式。 

## 解决方案```go
package main

import "fmt"

func getHint(secret string, guess string) string {
    bulls := 0
    cows := 0

    count := make([]int, 10)

    for i := 0; i < len(secret); i++ {
        if secret[i] == guess[i] {
            bulls++
        } else {
            s := int(secret[i] - '0')
            g := int(guess[i] - '0')

            if count[s] < 0 {
                cows++
            }

            if count[g] > 0 {
                cows++
            }

            count[s]++
            count[g]--
        }
    }

    return fmt.Sprintf("%dA%dB", bulls, cows)
}
```Go 实现与 Python 版本几乎相同，但存在一些特定于语言的差异。 

Go 字符串以字节为索引，因此使用以下方法执行数字转换：```go
int(secret[i] - '0')
```而不是Python的`int()`转换。 

频率数组是使用创建的`make([]int, 10)`，它自动将所有条目初始化为零。 

字符串格式化使用`fmt.Sprintf`而不是 Python f 字符串。 

由于约束很小并且数字值很小，因此整数溢出不是问题。

 ## 边缘情况

 一种重要的边缘情况涉及重复数字在`guess`比在`secret`。 例如：```
secret = "1123"
guess  = "1111"
```幼稚的实现可能会错误地计算出太多的奶牛，因为它看到多个匹配的数字。 频率平衡方法通过仅在另一侧确实存在不匹配的情况时才计算奶牛来防止这种情况。 

另一个重要的情况发生在每个数字都已经是牛的时候。 例如：```
secret = "1234"
guess  = "1234"
```在这种情况下，奶牛必须保持为零，因为奶牛仅在非牛数字中定义。 该实现自然地处理了这个问题，因为匹配位置完全绕过了频率逻辑。 

第三种微妙的情况是，所有匹配的都是牛，没有一个是公牛：```
secret = "1122"
guess  = "2211"
```每个数字都存在于两个字符串中，但出现在错误的位置。 某些实现由于重复处理而意外地少算或多算。 平衡数组方法将每个不匹配的数字正确匹配一次，产生`0A4B`。 

最终的边缘情况涉及尽可能小的输入长度：```
secret = "1"
guess  = "0"
```该算法仍然可以正常工作，因为循环结构和计数逻辑不依赖于大于 1 的字符串长度。
