 # LeetCode 233 - 数字一的个数

 ## 问题陈述

 给定一个非负整数`n`，我们必须数一下这个数字有多少次`1`出现在每个数字中`0`通过`n`，包含在内。 

重要的细节是我们没有计算有多少个数字包含该数字`1`。 相反，我们正在计算个体总数`1`整个范围内的数字。 

例如，如果`n = 13`，包含的数字`1`是：

-`1`-`10`-`11`-`12`-`13`总数`1`数字是：

 -`1`贡献 1
 -`10`贡献 1
 -`11`贡献 2
 -`12`贡献 1
 -`13`贡献 1

 所以答案是`6`。 

输入是单个整数`n`， 在哪里：```
0 <= n <= 10^9
```这个约束非常重要，因为它告诉我们迭代每个数字并直接计算数字可能会变得太慢。 暴力解决方案可能会处理十亿个数字，这是不切实际的。 

该问题保证输入是非负的，因此我们不需要处理负整数。 

一些边缘情况很重要：

 -`n = 0`，没有`1`根本没有数字。 
- 像这样的数字`9`，其中尚不存在多位逻辑。 
- 像这样的数字`10`，其中出现新的数字位置。 
- 像这样的数字`11`，其中多个`1`s 出现在相同的数字中。 
- 像这样的数字`100`,`1000`， 或者`10000`，其中数字边界发生变化。 
- 附近非常大的值`10^9`，其中效率非常重要。 

## 方法

 ### 蛮力方法

 最直接的解决方案是迭代每个整数`0`到`n`，将每个数字转换为字符串，并统计有多少个字符相等`'1'`。 

例如：

 - 转换`1`到`"1"`并计算出现一次。 
- 转变`11`到`"11"`并计算两次出现的次数。 
- 继续直到到达`n`。 

这种方法很容易理解，而且显然是正确的，因为它明确地检查每个数字的每一位数字。 

然而，对于大量输入来说，它太慢了。 如果`n = 10^9`，我们将处理十亿个数字，每次转换加上数字扫描都会花费额外的时间。 

### 最佳数学数字计数

 关键的见解是数字遵循重复的模式。 

我们可以计算该数字的次数，而不是单独检查每个数字`1`独立出现在每个小数点位置。 

考虑一下那些地方：

 - 来自`0`到`9`, 数字`1`出现一次。 
- 从`10`到`19`，它再次出现在个位上。 
- 每 10 个数字组成的区块恰好贡献一个`1`在那些人的位置上。 

现在考虑十位：

 - 来自`10`到`19`，十位数字是`1`为 10 个连续的数字。 
- 从`110`到`119`，相同的模式重复。 
- 每 100 个数字块贡献 10 次出现`1`在十位。 

这种重复结构允许我们以数学方式计算出现次数，而不是显式地迭代所有数字。 

对于每个数字位置：

 - 将数字分为高位数字、当前数字和低位数字。 
- 使用这些片段来确定有多少个完整周期`1`s 存在于该位置。 
- 根据当前数字添加部分贡献。 

这大大降低了复杂性。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n log n) | O(n log n) | O(1) | O(1) | 迭代每个数字并计算数字 |
 | 最佳| O(log n) | O(1) | O(1) | 以数学方式逐位计算贡献 |

 ## 算法演练

 我们一次处理一位数字的位置。 

假设我们正在检查由以下表示的位置`factor`。 

-`factor = 1`意思是一个地方
 -`factor = 10`表示十位
 -`factor = 100`意思是数百个地方

 对于每个位置，我们将数字分为三部分：

 -`higher`, 当前位置左边的数字
 -`current`, 当前位置的数字
 -`lower`, 当前位置右边的数字

 例如，如果：```
n = 31456
factor = 100
```然后：```
higher = 314
current = 5
lower = 56
```我们将这些值计算为：```
higher = n // (factor * 10)
current = (n // factor) % 10
lower = n % factor
```### 逐步算法

 1. 初始化`count = 0`和`factor = 1`。 
2. 虽然`factor <= n`，处理当前数字位置。 
3. 计算：

 -`higher`-`current`-`lower`4. 如果`current == 0`：

 数量`1`该职位贡献的是：```
higher * factor
```发生这种情况是因为只有完整的周期才会起作用。 
5. 如果`current == 1`：

 贡献变为：```
higher * factor + lower + 1
```完整的周期贡献`higher * factor`，部分循环贡献`lower + 1`。 
6. 如果`current > 1`：

 那么当前位置已经完成了另外一个完整的循环`1`s:```
(higher + 1) * factor
```7. 添加贡献`count`。 
8. 乘法`factor`经过`10`移动到下一个数字位置。 
9. 继续，直到处理完所有数字位置。 

### 为什么它有效

 每个小数位都遵循可预测的重复周期。 通过独立分析每个数字，我们可以准确确定有多少数字贡献了一个数字`1`在那个位置。 由于每次出现`1`恰好属于一位数字位置，将所有位置贡献相加即可正确得出总计数。 

## Python 解决方案```python
class Solution:
    def countDigitOne(self, n: int) -> int:
        count = 0
        factor = 1

        while factor <= n:
            higher = n // (factor * 10)
            current = (n // factor) % 10
            lower = n % factor

            if current == 0:
                count += higher * factor
            elif current == 1:
                count += higher * factor + lower + 1
            else:
                count += (higher + 1) * factor

            factor *= 10

        return count
```实现直接遵循数学观察。 

变量`factor`标识当前正在处理的数字位置。 开始于`1`意味着我们从那个地方开始。 

在循环内部，数字被划分为：

 -`higher`-`current`-`lower`这些组件决定了有多少完整周期和部分周期贡献`1`s 在当前位置。 

三个条件分支对应当前数字的三种可能状态：

 -`0`-`1`- 大于`1`每种情况都使用从数字循环行为导出的公式。 

最后我们乘以`factor`经过`10`移动到下一个数字位置。 

由于对于给定的约束，小数位数最多为 10，因此循环仅运行少量次数。 

## 解决方案```go
func countDigitOne(n int) int {
    count := 0
    factor := 1

    for factor <= n {
        higher := n / (factor * 10)
        current := (n / factor) % 10
        lower := n % factor

        if current == 0 {
            count += higher * factor
        } else if current == 1 {
            count += higher*factor + lower + 1
        } else {
            count += (higher + 1) * factor
        }

        factor *= 10
    }

    return count
}
```Go 实现与 Python 版本几乎相同，因为该算法仅依赖于整数运算。 

Go 使用显式变量声明`:=`，而 Python 使用动态类型。 

问题约束确保整数溢出对于标准 Go 来说不是问题`int`在 LeetCode 环境中。

 ## 边缘情况

 ### 边缘情况 1，`n = 0`这是可能的最小输入。 一个常见的错误是不小心计算数字`1`在数量上`0`itself or incorrectly entering the loop once.

 该实现正确处理了这个问题，因为循环条件：```
factor <= n
```立即失败，当`n = 0`。 

### 边缘情况 2，数字包含多个`1`s

 价值观如`11`,`111`， 或者`1111`很重要，因为同一个数字会多次出现该数字`1`。 

有缺陷的实现可能只计算数字是否包含`1`，而不是独立计算每个事件的发生。 

该算法避免了这种错误，因为它单独处理每个数字位置并独立地总结所有贡献。 

### 边缘情况 3，十的幂

 输入如`10`,`100`， 和`1000`是差一误差的常见来源。 

例如：```
n = 100
```必须正确计数：

 - 的`1`在`1`- 所有青少年号码
 - 的`1`在`100`公式为`current == 1`案件：```
higher * factor + lower + 1
```正确考虑部分循环贡献并防止丢失或重复计算边界值。 

### 边缘情况 4，非常大的输入

 该约束允许值达到`10^9`。 

暴力方法太慢了，因为它需要处理数十亿个数字。 

数学计数方法可有效扩展，因为它仅检查小数位，对于给定的约束最多迭代 10 次。
