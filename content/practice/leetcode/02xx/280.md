[LeetCode 第 280 题](https://leetcode.com/problems/wiggle-sort/)

 **难度：** 🟡 中等
 **主题：** 数组、贪婪、排序

 ## 解决方案

 ## 问题理解

 该问题要求我们重新排列一个整数数组，使其遵循一种称为摆动序列的特定交替模式。 

所需的关系是：

 -`nums[0] <= nums[1]`-`nums[1] >= nums[2]`-`nums[2] <= nums[3]`-`nums[3] >= nums[4]`- 等等。 

换句话说，这些值应该在谷值和峰值之间交替。 奇数索引处的元素应大于或等于其邻居，而偶数索引处的元素应小于或等于其邻居。 

输入是单个整数数组`nums`，任务是就地修改数组。 我们不会被要求返回一个新的数组。 

约束条件很重要：

 - 数组长度可以大到`5 * 10^4`- 值范围为`0`到`10^4`- 该问题保证至少一种有效的摆动排列始终存在

 因为输入可能相当大，`O(n^2)`解决方案将是低效的。 后续明确询问问题是否可以在线性时间内解决，这强烈暗示存在贪婪或单遍方法。 

尽早考虑几个边缘情况很重要：

 - 只有一个元素的数组已经有效
 - 具有重复值的数组仍必须满足非严格不等式
 - 已经摆动排序的数组应该保持有效
 - 严格增加或严格减少数组需要多次交换
 - 如果使用严格比较而不是非严格比较，相邻相等值很容易破坏不正确的实现

 保证有效答案始终存在可以简化问题，因为我们不需要检测不可能的配置。 

## 方法

 ### 蛮力方法

 一个简单的想法是首先对数组进行排序，然后将元素重新排列到交替的低位置和高位置。 

一种可能的实现是：

 1. 对数组进行排序
 2. 将较小和较大的两半交错
 3. 将值放置在交替的位置上

 排序可以更轻松地控制排序关系，因为数字已经全局排列。 排序后，我们可以有意放置元素，以使摆动条件成立。 

这是有效的，因为排序顺序提供了足够的结构来确保交替的峰和谷。 然而，排序需要`O(n log n)`时间，这比后续要求的最佳线性时间解要慢。 

对于给定的约束，该方法是可以接受的，但它不是最佳的。 

### 最优贪心法

 关键的观察是我们不需要对整个数组进行全局排序。 我们只需要每个相邻对都满足局部条件。 

对于每个索引：

 - 如果索引是奇数，我们需要`nums[i] >= nums[i - 1]`- 如果索引是偶数，我们需要`nums[i] <= nums[i - 1]`如果违反条件，则交换两个相邻元素会立即修复该局部关系。 

重要的见解是，贪婪地修复一对不会破坏之前对的有效性。 由于每次交换仅涉及相邻元素，因此早期的摆动关系仍然正确。 

这使我们能够通过从左到右的一次传递来解决问题。

 ## 算法演练

 ### 最优贪心算法

 1.从索引开始迭代数组`1`。 

在每一步中，我们都会检查之间的关系`nums[i]`和`nums[i - 1]`。 
2. 如果当前索引为奇数，请确保当前元素大于或等于前一个元素。 

所需条件是：```
nums[i] >= nums[i - 1]
```如果违反此条件，则交换两个元素。 
3. 如果当前索引为偶数，则确保当前元素小于或等于前一个元素。 

所需条件是：```
nums[i] <= nums[i - 1]
```如果违反此条件，则交换两个元素。 
4. 继续此过程直到数组末尾。 

每一步都会修复当前相邻对的摆动关系。 

### 为什么它有效

 该算法保持了索引之前的所有位置的不变性`i`已经满足摆动条件。 

处理索引时`i`，只有之间的关系`nums[i - 1]`和`nums[i]`可能无效。 如果我们交换它们，当前对将变得有效，而不会破坏先前的对。 

这是有效的，因为交换仅更改两个相邻元素的顺序，并且先前的关系仍然与摆动约束兼容。 

遍历结束时，每个相邻对都满足所需的交替不等式模式。 

## Python 解决方案```python
from typing import List

class Solution:
    def wiggleSort(self, nums: List[int]) -> None:
        """
        Do not return anything, modify nums in-place instead.
        """
        
        for i in range(1, len(nums)):
            
            # Odd index should be a peak
            if i % 2 == 1:
                if nums[i] < nums[i - 1]:
                    nums[i], nums[i - 1] = nums[i - 1], nums[i]
            
            # Even index should be a valley
            else:
                if nums[i] > nums[i - 1]:
                    nums[i], nums[i - 1] = nums[i - 1], nums[i]
```其实现完全遵循贪婪策略。 

循环从索引开始`1`因为每次比较都涉及前一个元素。 

对于奇数索引，当前值必须大于或等于前一个值。 如果不是，则交换两个元素。 

对于偶数索引，当前值必须小于或等于先前值。 同样，如果条件被违反，交换会立即修复它。 

该算法就地修改数组，满足问题要求并保持空间使用恒定。 

## 解决方案```go
func wiggleSort(nums []int) {
    
    for i := 1; i < len(nums); i++ {
        
        // Odd index should be a peak
        if i%2 == 1 {
            if nums[i] < nums[i-1] {
                nums[i], nums[i-1] = nums[i-1], nums[i]
            }

            // Even index should be a valley
            if nums[i] > nums[i-1] {
                nums[i], nums[i-1] = nums[i-1], nums[i]
            }
        }
    }
}
```Go 实现密切反映了 Python 逻辑。 

Go 切片是类似引用的结构，因此函数内部的修改会直接影响原始数组。 不需要额外的内存分配。 

与 Python 不同，Go 不需要显式类型提示，因为切片类型已在函数签名中指定。 

不存在整数溢出问题，因为该算法仅比较和交换值。

from typing import List

def is_wiggle(nums: List[int]) -> bool:
    for i in range(1, len(nums)):
        if i % 2 == 1:
            if nums[i] < nums[i - 1]:
                return False
        else:
            if nums[i] > nums[i - 1]:
                return False
    return True

class Solution:
    def wiggleSort(self, nums: List[int]) -> None:
        for i in range(1, len(nums)):
            if i % 2 == 1:
                if nums[i] < nums[i - 1]:
                    nums[i], nums[i - 1] = nums[i - 1], nums[i]
            else:
                if nums[i] > nums[i - 1]:
                    nums[i], nums[i - 1] = nums[i - 1], nums[i]

sol = Solution()

 ## 边缘情况

 ### 单元素数组

 仅包含一个元素的数组会自动进行摆动排序，因为没有需要验证的相邻关系。 

这种情况可能会导致假设至少存在两个元素的实现出现问题。 当前的实现自然地处理它，因为循环从索引处开始`1`，因此不会发生迭代。 

### 重复值

 具有重复值的数组很重要，因为条件使用非严格不等式。 

例如：```
[4,4,4,4]
```已经有效，因为：```
4 <= 4 >= 4 <= 4
```一个常见的错误是使用严格`<`和`>`不正确的比较，这将强制不必要的交换或错误地拒绝有效状态。 

该实现仅在违反所需的不等式时才通过交换来正确使用非严格逻辑。 

### 严格递增或递减数组

 输入如：```
[1,2,3,4,5,6]
```或者```
[6,5,4,3,2,1]
```需要多次局部修正。 

朴素的方法可能会尝试全局重新排列元素，但贪婪算法可以通过相邻交换有效地处理这些元素。 

每次迭代精确地修复一个局部违规，并且由于先前的位置仍然有效，因此算法在单遍中收敛。
