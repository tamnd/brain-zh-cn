[LeetCode 第 202 题](https://leetcode.com/problems/happy-number/)

 **难度：** 🟢简单
 **主题：** 哈希表、数学、两个指针

 ## 解决方案

 ## 问题理解

 这个问题要求我们判断给定的正整数是否`n`是一个**快乐的数字**。 

快乐数是通过重复的变换过程定义的。 从原始数字开始，我们反复将其替换为**其数字的平方和**。 最终，发生以下两件事之一：

 1. 数字变为`1`，在这种情况下，进程停止，并且该数字被认为是**快乐**。 
2. 序列进入一个永远不会达到的重复循环`1`，表示这个数字**不开心**。 

例如，如果`n = 19`：

 -`1² + 9² = 82`-`8² + 2² = 68`-`6² + 8² = 100`-`1² + 0² + 0² = 1`由于该过程达到`1`,`19`是一个快乐的数字。 

输入是单个整数`n`， 在哪里：

-`1 <= n <= 2³¹ - 1`输出应该是一个布尔值：

 -`true`如果`n`很高兴
 -`false`否则

 约束条件告诉我们`n`可以相当大，但仍然适合标准 32 位有符号整数。 然而，一个重要的观察结果是，重复对数字平方求和会导致数字迅速缩小。 即使非常大的数字最终也会变成相对较小的值。 

主要挑战是处理**周期**。 如果数字永远不会达到，一个幼稚的实现可能会永远改变这个数字`1`。 例如，`2`进入重复循环：`2 → 4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4`自从`4`再次出现时，该序列将永远重复。 

重要的边缘情况包括：

 -`n = 1`，这已经是一个令人高兴的数字了。 
- 很快陷入循环的数字，例如`2`。 
- 附近非常大的有效输入`2³¹ - 1`，它仍然必须有效终止。 

## 方法

 ### 蛮力方法

 强力解决方案重复计算平方数之和并无限期地继续，直到出现：

 - 数字变为`1`, 或
 - 我们以某种方式确定我们陷入了一个循环。 

问题是，如果不跟踪以前的状态，就没有可靠的方法来检测无限重复。 一个幼稚的实现可能会在不愉快的数字上永远循环。 

为了使暴力破解可行，我们可以维护一个或一组以前见过的值。 每次我们计算一个新数字时，我们都会检查它之前是否出现过。 如果是这样，我们就知道我们正处于一个循环中并且可以安全地返回`false`。 

这种方法是正确的，因为序列是确定性的。 一个数字总是恰好映射到下一个数字。 因此，重新访问以前的值可以保证重复。 

### 最佳解决方案的关键见解

 关键的观察结果是，这个问题从根本上来说是一个**循环检测问题**。 

我们可以使用**弗洛伊德循环检测算法**，也称为**乌龟和兔子**方法，而不是存储所有以前访问过的数字。 

这个想法是：

 - 缓慢的指针一次移动一个变换。 
- 快速指针一次移动两个变换。 

如果序列进入循环，则两个指针最终必须在该循环内相遇。 如果序列达到`1`，那么这个数字就是快乐的。 

这种方法避免了额外的内存，同时仍然可靠地检测循环。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(log n) | O(log n) | 使用哈希集来检测重复值 |
 | 最佳| O(log n) | O(1) | O(1) | 使用 Floyd 循环检测，无需额外存储 |

 尽管序列可以迭代多次，但值很快就会崩溃到一个小的有界范围内，使得实际运行时间非常小。 

## 算法演练

 我们将使用弗洛伊德循环检测算法。 

1. 创建一个辅助函数，用于计算数字的**数字的平方和**。 例如，`19`变成`1² + 9² = 82`。 这种转换是整个算法中重复的核心操作。 
2.初始化两个指针：

 -`slow = n`-`fast = n`两个指针都从相同的数字开始。 
3. 以不同的速度移动指针：

 -`slow`移动一步：`slow = next(slow)`-`fast`移动两步：`fast = next(next(fast))`以不同的速度移动使我们能够有效地检测周期。 
4. 继续循环直到`slow == fast`。 

有两种可能：

 - 如果两个指针相遇`1`，序列达到了幸福。 
- 如果它们在另一个值处相遇，则序列陷入循环。 
5、返回交汇点是否等于`1`。 

### 为什么它有效

 该算法之所以有效，是因为转换序列是确定性的。 每个数字恰好映射到下一个数字。 如果进程从未达到`1`，它最终必须重复先前的值，形成一个循环。 弗洛伊德的算法保证以不同速度移动的两个指针最终会在该周期内相遇。 因此：

 - 会议地点`1`表示这个数字是快乐的。 
- 在别处相遇意味着该号码陷入循环。 

## Python 解决方案```python
class Solution:
    def isHappy(self, n: int) -> bool:
        def get_next(number: int) -> int:
            total = 0

            while number > 0:
                digit = number % 10
                total += digit * digit
                number //= 10

            return total

        slow = n
        fast = n

        while True:
            slow = get_next(slow)
            fast = get_next(get_next(fast))

            if slow == fast:
                break

        return slow == 1
```实现从一个名为的辅助函数开始`get_next`，计算数字平方和。 我们不是将数字转换为字符串，而是使用数学方式提取数字`% 10`和整数除法`// 10`。 这避免了不必要的开销。 

我们初始化`slow`和`fast`指向起始数字的指针`n`。 

循环内部：

 -`slow`一次推进一项转变。 
-`fast`进步速度快了一倍。 

最终，出现以下两种结果之一：

 - 两个指针相交于`1`，意味着序列成功收敛。 
- 两个指针在其他地方相遇，这意味着我们检测到了一个循环。 

最终的返回语句检查集合点是否为`1`。 

## 解决方案```go
func isHappy(n int) bool {
	getNext := func(number int) int {
		total := 0

		for number > 0 {
			digit := number % 10
			total += digit * digit
			number /= 10
		}

		return total
	}

	slow := n
	fast := n

	for {
		slow = getNext(slow)
		fast = getNext(getNext(fast))

		if slow == fast {
			break
		}
	}

	return slow == 1
}
```Go 的实现与 Python 版本非常相似。 本地辅助函数计算下一个转换值。 

由于 Go 不支持像 Python 那样的嵌套命名函数，因此我们使用分配给的匿名函数`getNext`。 

整数溢出不是一个问题，因为与整数相比，数字平方和仍然非常小`int`范围。 即使是最大的有效输入也会很快减少到小得多的数字。 

与 Python 不同，Go 使用显式变量声明`for`循环而不是`while`。 

## 工作示例

 ### 示例 1：`n = 19`我们跟踪两个指针的移动。 

| 迭代| 慢| 快|
 | --- | --- | --- |
 | 开始| 19 | 19 19 | 19
 | 1 | 82 | 82 68 | 68
 | 2 | 68 | 68 1 |
 | 3 | 100 | 100 1 |
 | 4 | 1 | 1 |

 由于两个指针相遇于`1`，算法返回`true`。 

改造详情：

 -`19 → 82`-`82 → 68`-`68 → 100`-`100 → 1`### 示例 2：`n = 2`| 迭代| 慢| 快|
 | --- | --- | --- |
 | 开始| 2 | 2 |
 | 1 | 4 | 16 | 16
 | 2 | 16 | 16 58 | 58
 | 3 | 37 | 37 145 | 145
 | 4 | 58 | 58 20 |
 | 5 | 89 | 89 16 | 16
 | 6 | 145 | 145 58 | 58
 | 7 | 42 | 42 145 | 145
 | 8 | 20 | 20 |

 指针相遇于`20`， 不是`1`。 

这确认了序列进入了一个循环：`2 → 4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4`因此，答案是`false`。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(log n) | 每个转换都会处理数字 |
 | 空间| O(1) | O(1) | 仅使用了少数整数变量 |

 时间复杂度来自计算平方数之和。 处理一个数字需要`O(log n)`因为位数与`log n`。 

尽管该算法可能会迭代多次，但值会迅速缩小到一个小的有界范围内。 实际上，运行时间非常短并且实际上是恒定的。 

空间复杂度为`O(1)`因为弗洛伊德的循环检测避免存储访问过的状态。 只有`slow`,`fast`，并且需要辅助变量。

 ## 边缘情况

 ### 输入已经`1`最小的有效输入是`1`，这已经是一个令人高兴的数字了。 粗心的实现可能会不必要地进入循环逻辑或错误处理终止。 在这个解决方案中，两个指针很快收敛于`1`，算法正确返回`true`。 

### 立即进入循环的数字

 一些数字，例如`2`或者`4`，快速进入重复循环而不到达`1`。 没有循环检测的简单解决方案将永远运行。 Floyd 算法保证了检测，因为快指针最终会在重复周期内捕获慢指针。 

### 大输入值

 该约束允许的数字最大为`2³¹ - 1`。 有缺陷的实现可能会担心运行时间过长或整数溢出。 然而，对数字求和会迅速将数字缩小到更小的范围。 例如，即使是 10 位数字也无法产生非常大的数字平方和。 此实现可以安全地处理最大尺寸的输入，而不会出现性能问题。
