[LeetCode 第 297 题](https://leetcode.com/problems/serialize-and-deserialize-binary-tree/)

 **难度：** 🔴难
 **主题：** 字符串、树、深度优先搜索、广度优先搜索、设计、二叉树

 ## 解决方案

 ## 问题理解

 该问题要求我们为二叉树设计两个互补的操作：序列化和反序列化。 

序列化将二叉树转换为可以存储或传输的字符串表示形式。 反序列化执行相反的操作，从序列化的字符串重建完全相同的二叉树结构。 

重要的细节是重建的树必须与原始树完全匹配，包括节点值和结构。 具有相同值但排列不同的两棵树被视为不同的树。 

输入到`serialize`是二叉树的根节点。 输出必须是该树的字符串编码。 

输入到`deserialize`是之前生成的字符串`serialize`。 输出必须是重建的根节点。 

这个问题并不迫使我们使用 LeetCode 的类似数组的格式。 只要满足以下条件，任何编码方案都是有效的：

 - 每个有效的树都可以序列化
 - 该树稍后可以完美重建
 - 序列化和反序列化是互逆的

 约束条件很重要：

 - 该树最多可以包含`10^4`节点
 - 节点值范围为`-1000`到`1000`- The tree may be empty

 这些限制告诉我们几件事：

 - 算法必须高效，理想情况下是线性时间
 - 对于倾斜的树，递归深度可能会变大
 - The serialization format must preserve`null`孩子，否则结构信息就会丢失

 一个主要挑战是正确处理失踪儿童。 考虑这两棵树：```
    1          1
   /            \
  2              2
```如果我们仅按预序序列化节点值`1,2`，两棵树变得相同，这意味着反序列化变得不可能。 因此，空标记是必不可少的。 

几种边缘情况很容易破坏简单的实现：

 - 一棵空树
 - 完全倾斜的树
 - 具有重复值的树
 - 包含负数的树
 - 许多儿童失踪的树木

 该问题保证反序列化的输入字符串是由序列化器生成的，因此我们不需要验证格式错误的数据。 

## 方法

 ### 蛮力方法

 一个暴力的想法是将树逐级序列化为类似数组的结构，并将每个可能的位置存储在完整的二叉树布局中。 

例如，我们可以像分配堆一样分配索引：

 - 索引处的根`0`- 左孩子在`2i + 1`- 右孩子在`2i + 2`然后，我们将值存储到一个非常大的数组中，用空标记填充未使用的位置。 

这种方法之所以有效，是因为每个节点位置唯一标识树的结构。 在反序列化期间，可以根据索引关系重建子级。 

然而，这种方法对于倾斜的树来说变得极其浪费。 一棵树有高度`h`可能需要的空间成正比`2^h`，即使只有`h`节点确实存在。 

例如：```
1
 \
  2
   \
    3
```由于节点之间出现许多未使用的位置，因此数组表示呈指数增长。 

这使得暴力方法对于大型稀疏树来说不切实际。 

### 最佳方法

 关键的见解是，如果我们在遍历期间显式记录空子级，则不需要位置索引。 

前序遍历自然地捕获树结构：

 1.访问当前节点
 2. 序列化左子树
 3. 序列化右子树

 如果我们插入一个特殊的标记，例如`"N"`每当一个孩子失踪时，遍历就变得唯一可解码。 

例如：```
    1
   / \
  2   3
```预购序列化变为：```
1,2,N,N,3,N,N
```这是有效的，因为每个节点都做出贡献：

 - 它的价值
 - 它的整个左子树
 - 它的整个右子树

 在反序列化期间，我们以完全相同的顺序读取值。 每当我们遇到`"N"`，我们返回`None`。 否则，我们创建一个节点并递归地构建其左子节点和右子节点。 

这为我们提供了具有线性重建时间的紧凑线性表示。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^h) | O(2^h) | O(2^h) | O(2^h) | 完整树数组表示浪费稀疏树的空间 |
 | 最佳 | O(n) | O(n) | 使用空标记进行前序遍历可有效保留结构 |

 ## 算法演练

 ### 序列化

 1. 从根开始预序深度优先遍历。 
2. 如果当前节点是`None`，附加一个特殊标记，例如`"N"`到序列化输出。 这是必要的，因为失踪的孩子是树结构的一部分。 
3. 否则，将当前节点的值附加到输出。 
4. 递归序列化左子树。 
5. 递归序列化右子树。 
6. 使用逗号连接所有记录值以生成最终字符串。 

### 反序列化

 1、将序列化后的字符串用逗号分割，恢复遍历顺序。 
2. 维护一个跟踪当前正在处理的令牌的指针。 
3. 读取下一个标记。 
4. 如果令牌是`"N"`， 返回`None`。 这可以正确重建失踪儿童。 
5. 否则，使用整数值创建一个新的树节点。 
6. 递归构造左子树。 
7. 递归构造右子树。 
8. 返回重构后的节点。 

### 为什么它有效

 该算法之所以有效，是因为前序遍历定义了独特的递归结构：```
Node -> value + left subtree + right subtree
```每个空子级都被显式编码，因此不会丢失任何结构信息。 在反序列化过程中，令牌的消耗顺序与生成的顺序完全相同。 每个递归调用都会精确地重建最初在该位置序列化的子树。 

这在树和序列化字符串之间建立了一对一的映射。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode(object):
#     def __init__(self, x):
#         self.val = x
#         self.left = None
#         self.right = None

from typing import Optional

class Codec:

    def serialize(self, root: Optional['TreeNode']) -> str:
        """Encodes a tree to a single string."""

        values = []

        def dfs(node: Optional['TreeNode']) -> None:
            if node is None:
                values.append("N")
                return

            values.append(str(node.val))
            dfs(node.left)
            dfs(node.right)

        dfs(root)

        return ",".join(values)

    def deserialize(self, data: str) -> Optional['TreeNode']:
        """Decodes your encoded data to tree."""

        values = data.split(",")
        index = 0

        def dfs() -> Optional['TreeNode']:
            nonlocal index

            if values[index] == "N":
                index += 1
                return None

            node = TreeNode(int(values[index]))
            index += 1

            node.left = dfs()
            node.right = dfs()

            return node

        return dfs()

# Your Codec object will be instantiated and called as such:
# ser = Codec()
# deser = Codec()
# ans = deser.deserialize(ser.serialize(root))
```实现直接遵循前序遍历策略。 

这`serialize`方法使用辅助 DFS 函数。 每个真实节点都贡献其价值，每个缺失的子节点都贡献其价值`"N"`。 名单`values`有效积累代币，并且`",".join()`创建最终的序列化字符串。 

这`deserialize`方法递归地重建树。 这`index`变量充当令牌数组的共享指针。 每个递归调用恰好消耗一个子树所需的令牌。 

当令牌为`"N"`，子树为空，所以我们返回`None`。 否则，我们创建一个节点并按先序递归地重建其左子树和右子树。 

由于序列化和反序列化使用相同的遍历结构，因此重构是精确的。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */

import (
	"strconv"
	"strings"
)

type Codec struct {
    
}

func Constructor() Codec {
	return Codec{}
}

// Serializes a tree to a single string.
func (this *Codec) serialize(root *TreeNode) string {
	values := []string{}

	var dfs func(node *TreeNode)

	dfs = func(node *TreeNode) {
		if node == nil {
			values = append(values, "N")
			return
		}

		values = append(values, strconv.Itoa(node.Val))

		dfs(node.Left)
		dfs(node.Right)
	}

	dfs(root)

	return strings.Join(values, ",")
}

// Deserializes your encoded data to tree.
func (this *Codec) deserialize(data string) *TreeNode {
	values := strings.Split(data, ",")
	index := 0

	var dfs func() *TreeNode

	dfs = func() *TreeNode {
		if values[index] == "N" {
			index++
			return nil
		}

		val, _ := strconv.Atoi(values[index])
		index++

		node := &TreeNode{Val: val}

		node.Left = dfs()
		node.Right = dfs()

		return node
	}

	return dfs()
}

/**
 * Your Codec object will be instantiated and called as such:
 * ser := Constructor();
 * deser := Constructor();
 * data := ser.serialize(root);
 * ans := deser.deserialize(data);
 */
```Go 的实现与 Python 解决方案非常相似。 

Go 使用字符串切片来代替 Python 列表。 整数转换使用`strconv.Itoa`和`strconv.Atoi`。 

Go 的区别`nil`显式指针，自然映射到缺失的树子节点。 

递归 DFS 函数被实现为闭包，因此它们可以访问共享变量，例如`values`和`index`。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个节点和空标记仅处理一次 |
 | 空间| O(n) | 串行化输出和递归堆栈在一起需要线性空间 |

 序列化器访问每个节点一次，并为每个节点附加恒定数量的信息。 解串器还在重建树时处理每个令牌一次。 

递归堆栈深度取决于树的高度。 在完全倾斜的树的最坏情况下，递归深度变为`O(n)`。

 ## 边缘情况

 ### 空树

 一棵空树表示为`None`。 简单的序列化程序可能会返回一个空字符串，这可能会在反序列化期间产生歧义。 

此实现显式地将空树序列化为`"N"`。 反序列化过程中，遇到`"N"`立即返回`None`。 这保证了空树得到一致且明确的处理。 

### 高度倾斜的树

 一棵树可能只包含一侧的节点：```
1
 \
  2
   \
    3
```朴素的基于数组的表示浪费了此类输入的大量空间，因为概念完整树中出现了许多空位置。 

带空标记的预排序方法仅存储必要的信息，因此序列化大小与节点数量保持线性关系。 

### 具有重复值的树

 一些解决方案错误地假设节点值是唯一的，并尝试使用基于值的查找逻辑进行重建。 

这个问题不保证唯一性。 例如：```
    1
   / \
  1   1
```我们的实施从不依赖于独特性。 重建完全取决于遍历顺序加上空标记，因此重复值可以自然且正确地处理。 

### 稀疏的树，缺少内部子元素

 考虑：```
    1
   /
  2
   \
    3
```如果在序列化期间省略空子级，则结构将变得不明确。 

该实现使用以下方式记录每个失踪的孩子`"N"`，确保始终可以重建准确的原始结构。
