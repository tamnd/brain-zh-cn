[LeetCode 第 211 题](https://leetcode.com/problems/design-add-and-search-words-data-struct/)

 **难度：** 🟡 中等
 **主题：** 字符串、深度优先搜索、设计、Trie

 ## 解决方案

 ## 问题理解

 该问题要求我们设计一个有效支持两种操作的数据结构：

 1. 在结构中添加单词。 
2. 搜索单词，其中搜索模式可能包含通配符`'.'`。 

通配符`'.'`代表任何单个小写英文字母。 这意味着搜索查询并不总是精确的字符串匹配。 相反，它可能代表多个可能的字符串。 

例如，如果数据结构包含单词`"bad"`,`"dad"`， 和`"mad"`:

 - 寻找`"bad"`应该返回`true`- 寻找`".ad"`也应该返回`true`，因为点可以代表`'b'`,`'d'`， 或者`'m'`- 寻找`"b.."`应该返回`true`，因为这两个点可以代表任意两个字符

 输入操作是增量执行的。 单词会随着时间的推移而添加，以后的搜索必须考虑所有先前添加的单词。 

这些约束提供了有关问题规模的重要信息：

 - 每个单词之间的长度`1`和`25`- 最多有`10^4`业务总计
 - 搜索查询最多可以包含`2`通配符点

 这些限制表明，一个简单的解决方案在某些情况下可能仍然有效，但我们应该瞄准更具可扩展性的结构，以避免重复扫描所有存储的单词。 通配符行为强烈暗示基于前缀的遍历将是有用的。 

一些边缘情况很重要：

 - 添加任何单词之前进行搜索
 - 搜索不同长度的单词
 - 仅使用通配符进行搜索，例如`".."`或者`"..."`- 添加重复的单词
 - 通配符出现在查询的开头、中间或结尾
 - 在失败之前部分匹配许多单词的查询

 正确的实现必须区分前缀和完整单词。 例如，如果`"bad"`已添加，正在搜索`"ba"`仍应返回`false`。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是将所有添加的单词存储在列表或集合中。 执行搜索时：

 - 如果查询不包含点，我们可以直接检查集合中的成员资格
 - 如果查询包含点，我们会迭代每个存储的单词并逐个字符进行比较

 比较时：

 - 普通字符必须完全匹配
 - 点匹配任何字符
 - 字长必须相等

 这种方法是正确的，因为每个存储的单词都会根据模式进行检查，因此不会错过任何可能的匹配。 

然而，随着存储单词数量的增加，这会变得低效。 每次通配符搜索可能需要扫描所有存储的单词，并且每次比较的成本最多为单词长度。 

当有很多单词和很多通配符搜索时，最坏的情况会变得昂贵。 

### 最佳方法

 关键的观察结果是搜索是逐个字符进行的，并且许多单词共享共同的前缀。 

Trie，也称为前缀树，非常适合这种情况，因为：

 - 每个节点代表一个字符
 - 从根到叶子的路径代表单词
 - 共享前缀仅存储一次
 - 搜索自然地遵循字符位置

 对于普通字符，我们移动到相应的子节点。 

对于通配符点，我们递归地探索该位置的所有可能的子节点。 

这使我们能够避免完全扫描不相关的单词。 我们不检查每个存储的单词，而是只遍历可能与查询匹配的路径。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 |`O(N × L)`每个通配符搜索 |`O(N × L)`| 扫描所有单词并比较字符 |
 | 最优特里树 |`O(L)`平均，点上分支|`O(N × L)`| 使用 DFS 进行高效的基于前缀的遍历 |

 这里：

-`N`是存储的单词数
 -`L`是最大字长

 ## 算法演练

 ### Trie结构

 每个 Trie 节点存储：

 - 字符到子节点的映射
 - 一个布尔标志，指示节点是否标记完整单词的结尾

 ### 添加字操作

 1. 从根节点开始。 
2. 一次处理一个字符的单词。 
3. 对于每个字符：

 - 检查子节点是否已经存在。 
- 如果没有，则创建一个新的子节点。 
- 移动到该子节点。 
4、处理完最终字符后：

 - 将当前节点标记为有效单词的结尾。 

这种结构允许许多具有共享前缀的单词重用相同的节点。 

### 搜索操作

 1.从根节点和索引开始深度优先搜索`0`。 
2. 在每次递归调用时：

 - 如果当前索引等于字长：

 - 返回当前节点是否标记一个完整的单词。 
3. 读取当前字符。 
4. 如果字符是普通字母：

 - 检查对应的child是否存在。 
- 如果没有，请返回`false`。 
- 否则继续递归使用子节点和下一个索引。 
5. 如果角色是`'.'`:

 - 递归地尝试每个子节点。 
- 如果有任何递归调用返回`true`， 返回`true`。 
- 如果没有成功，则返回`false`。 
6. 最终结果表明是否至少有一条有效路径与查询匹配。 

### 为什么它有效

 Trie 保证每个根到节点的路径都对应于某个插入单词的前缀。 搜索过程中：

 - 精确字符将遍历限制为一条有效路径。 
- 通配符探索该位置的所有有效可能性。 

因为DFS探索了每一个可能的匹配分支并只返回`true`当匹配完整的存储单词时，算法既完整又正确。 

## Python 解决方案```python
class TrieNode:
    def __init__(self):
        self.children: dict[str, TrieNode] = {}
        self.is_word = False

class WordDictionary:

    def __init__(self):
        self.root = TrieNode()

    def addWord(self, word: str) -> None:
        current = self.root

        for char in word:
            if char not in current.children:
                current.children[char] = TrieNode()

            current = current.children[char]

        current.is_word = True

    def search(self, word: str) -> bool:

        def dfs(node: TrieNode, index: int) -> bool:
            if index == len(word):
                return node.is_word

            char = word[index]

            if char == ".":
                for child in node.children.values():
                    if dfs(child, index + 1):
                        return True
                return False

            if char not in node.children:
                return False

            return dfs(node.children[char], index + 1)

        return dfs(self.root, 0)

# Your WordDictionary object will be instantiated and called as such:
# obj = WordDictionary()
# obj.addWord(word)
# param_2 = obj.search(word)
```实施开始于`TrieNode`班级。 每个节点存储：

 -`children`，将字符映射到子节点的字典
 -`is_word`，表示一个完整的单词是否在此节点结束

 的`WordDictionary`构造函数初始化 Trie 根。 

这`addWord`方法迭代输入单词中的每个字符。 如果对应的子节点不存在，则创建一个。 处理完所有字符后，它将最终节点标记为有效的单词结尾。 

这`search`方法使用递归深度优先搜索。 

递归辅助函数`dfs(node, index)`代表问题：

 “后缀可以从`index`从这个 Trie 节点进行匹配？”

 如果当前字符是普通字母，则仅沿着一个子字符继续遍历。 

如果角色是`'.'`，算法递归地探索每个可能的子节点。 如果任何分支成功，则搜索成功。 

仅当满足以下条件时，递归才能成功终止：

 - 查询中的每个字符都已被处理
 - 最终节点代表一个完整的存储单词

 ## 解决方案```go
type TrieNode struct {
	children map[byte]*TrieNode
	isWord   bool
}

type WordDictionary struct {
	root *TrieNode
}

func Constructor() WordDictionary {
	return WordDictionary{
		root: &TrieNode{
			children: make(map[byte]*TrieNode),
		},
	}
}

func (this *WordDictionary) AddWord(word string) {
	current := this.root

	for i := 0; i < len(word); i++ {
		char := word[i]

		if _, exists := current.children[char]; !exists {
			current.children[char] = &TrieNode{
				children: make(map[byte]*TrieNode),
			}
		}

		current = current.children[char]
	}

	current.isWord = true
}

func (this *WordDictionary) Search(word string) bool {

	var dfs func(node *TrieNode, index int) bool

	dfs = func(node *TrieNode, index int) bool {
		if index == len(word) {
			return node.isWord
		}

		char := word[index]

		if char == '.' {
			for _, child := range node.children {
				if dfs(child, index+1) {
					return true
				}
			}
			return false
		}

		nextNode, exists := node.children[char]

		if !exists {
			return false
		}

		return dfs(nextNode, index+1)
	}

	return dfs(this.root, 0)
}

/**
 * Your WordDictionary object will be instantiated and called as such:
 * obj := Constructor();
 * obj.AddWord(word);
 * param_2 := obj.Search(word);
 */
```Go 实现遵循与 Python 版本相同的算法结构，但存在一些特定于语言的差异。 

Go 使用`map[byte]*TrieNode`而不是 Python 字典。 由于输入仅包含小写英文字母，因此使用`byte`是高效且充足的。 

Trie 节点使用指针，以便子节点的修改影响原始结构。 

递归 DFS 被实现为分配给变量的闭包。 这允许辅助函数递归地引用自身。 

与 Python 不同，Go 在访问映射条目时需要显式的存在性检查。 代码使用：```go
nextNode, exists := node.children[char]
```安全地确定子节点是否存在。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 |`O(L × 26^D)`最坏的情况| DFS 可以为每个点进行分支 |
 | 空间|`O(N × L)`| Trie 存储所有字符 |

 在哪里：

-`L`是单词长度
 -`D`是通配符点的数量
 -`N`是插入的单词数

 分支因子来自通配符搜索。 在最坏的情况下，每个点可能需要探索最多`26`子节点。 

不过，这个问题最多只能保证`2`搜索查询中的点，这使搜索在实践中保持高效。 

空间复杂度来自于存储 Trie 节点。 在最坏的情况下，没有前缀是共享的，因此每个字符都会创建一个新节点。

 ## 边缘情况

 ### 前缀存在但完整单词不存在

 当实现将前缀与完整单词混淆时，就会出现一个常见错误。 

例如，插入后`"bad"`，寻找`"ba"`应该返回`false`。 

Trie 在插入期间自然存储前缀，因此实现必须显式跟踪节点是否表示完整单词的结尾。 这就是为什么每个节点都包含`is_word`旗帜。 仅当最终节点有时搜索才会成功`is_word == True`。 

### 通配符分支爆炸

 通配符搜索可能会探索许多分支。 

例如：```
search("...")
```可以递归地探索许多组合。 

幼稚的实现可能会意外地重新访问不正确的状态，或者在找到有效匹配后未能尽早停止。 

DFS 实现通过以下方式正确处理此问题：

 - 探索每个子节点`'.'`- 一旦找到有效路径立即返回
 - 回归`false`仅当所有分支都失败时

 这样保证了正确性，同时避免了成功后不必要的遍历。 

### 空 Trie 搜索

 在插入任何单词之前进行搜索是另一个重要的边缘情况。 

例如：```
search("a")
search(".")
```都应该返回`false`。 

由于根节点最初没有子节点，因此在遍历过程中所有搜索都会立即失败。 该实现可以安全地处理此问题，无需特殊情况代码，因为丢失的子检查自然会返回`false`。
