[LeetCode 第 241 题](https://leetcode.com/problems/ Different-ways-to-add-parentheses/)

 **难度：** 🟡 中等
 **主题：** 数学、字符串、动态规划、递归、记忆

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个数学表达式，作为包含整数和算术运算符的字符串（`+`,`-`,`*`）。 我们被要求计算**所有可能的结果**，这些结果可以通过以每种有效方式插入括号来获得。 

关键细节是我们**不使用正常运算符优先级评估表达式**。 相反，我们考虑使用括号对运算进行分组的所有可能方法。 每个不同的分组可能会产生不同的结果，我们必须返回所有结果。 

例如，考虑表达式`"2-1-1"`。 

如果我们将其括起来：```
((2-1)-1)
```我们得到：```
0
```如果我们将其括起来：```
(2-(1-1))
```我们得到：```
2
```所以最终的答案是：```
[0, 2]
```输入包括：

 - 正整数来自`0`到`99`- 运营商：`+`,`-`， 和`*`- 表达式长度可达`20`输出应包含由不同括号产生的**所有可能的计算值**。 允许重复结果，因为不同的分组可以产生相同的数值。 

这些约束提供了几个重要的线索。 

首先，表达式长度比较小（`<= 20`）。 这强烈表明指数或递归方法可能是可以接受的。 

其次，返回结果的数量上限为`10^4`，这意味着搜索空间可以通过记忆进行管理。 

第三，数字可以有多个数字，因此我们不能假设每个字符都是一个独立的数字。 我们必须正确解析子字符串，例如`"12"`或者`"99"`。 

一些边缘情况值得预先识别。 

当表达式仅包含单个数字时，简单的实现可能会失败，因为没有可拆分的运算符。 例如，`"42"`应该返回`[42]`。 

另一个微妙的情况是重复的子表达式。 在递归分割过程中，相同的子串可能会被重新计算多次，从而产生严重的冗余。 例如，`"2*3-4*5"`反复评估`"4*5"`和`"2*3"`。 如果没有记忆，性能会迅速下降。 

最后，必须保留重复的输出。 如果两个不同的括号产生`-10`，这两种情况都应该保留在结果中。 

## 方法

 ### 暴力递归枚举

 最直接的方法是递归地尝试每个可能的运算符作为分裂点。 

对于表达式中的每个运算符：

 1. 将表达式拆分为左子表达式和右子表达式。 
2. 递归计算左侧所有可能的结果。 
3. 递归计算右侧所有可能的结果。 
4. 使用当前运算符将每个左结果与每个右结果组合。 

如果子字符串不包含运算符，则它只是一个数字，因此我们返回该值。 

这种方法是正确的，因为每个有效的括号都必须选择某个运算符作为最终运算。 通过递归探索所有运算符位置，我们枚举了每个可能的计算树。 

然而，该方法重复地重新计算相同的子问题。 考虑：```
2*3-4*5
```子串`"4*5"`可以从不同的递归路径多次求解。 由于递归分支增长迅速，重复工作变得昂贵。 

### 最佳方法，通过记忆进行分而治之

 关键的观察结果是这个问题有**重叠的子问题**。 

每当我们计算子字符串的所有可能值时，答案总是相同的。 我们可以缓存结果，而不是重复地重新计算。 

我们使用：

 - **分而治之**以围绕运算符拆分表达式。 
- **记忆**存储先前解决的子字符串的结果。 

递归结构自然地模拟了表达式括号：

 - 每个运算符代表计算树的一个可能的根。 
- 左右子表达式独立求解。 
- 结果成对组合。 

记忆化将指数重新计算转变为更高效的动态编程风格解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数，大约 O(2^n) 到 O(Cn) | O(Cn)| 重复重新计算相同的子字符串 |
 | 最佳| O(n × Cn) | O(n × Cn) | 记忆化可防止子表达式的重复计算 |

 这里，`Cn`指括号可能性的加泰罗尼亚数字风格增长。 

## 算法演练

 1. 创建一个递归辅助函数，该函数接受表达式的子字符串并返回该子字符串的所有可能的计算结果。 
2. 在计算任何内容之前，检查该子字符串是否已存在于记忆映射中。 如果存在，则立即返回缓存结果。 这避免了冗余的重新计算。 
3. 逐字符扫描子字符串。 
4. 每当操作员 (`+`,`-`,`*`) 找到，将表达式拆分为：

 - 左子串
 - 右子串
 5. 递归计算两半的所有可能结果。 
6. 将每个左结果与每个右结果组合：

 - 如果操作员是`+`，添加它们。 
- 如果操作员是`-`，减去它们。 
- 如果操作员是`*`，将它们相乘。 
7. 将每个计算值附加到结果列表中。 
8. 扫描完整个子串后，检查是否没有找到运算符。 如果是这样，则子字符串代表一个数字，因此将其转换为整数并将其作为单元素列表返回。 
9. 在返回之前将计算结果存储在记忆映射中。 
10. 使用完整表达式开始递归。 

### 为什么它有效

 该算法之所以有效，是因为每个有效的括号都有一个最后计算的运算符。 通过递归地选择每个运算符作为最终分割点，我们枚举了所有有效的计算树。 由于左半部分和右半部分是独立求解并彻底组合的，因此不会错过任何有效结果。 记忆化可以保持正确性，因为子字符串的值永远不会改变，因此重用缓存的结果始终是安全的。 

## Python 解决方案```python
from typing import List

class Solution:
    def diffWaysToCompute(self, expression: str) -> List[int]:
        memo = {}

        def compute(sub_expression: str) -> List[int]:
            if sub_expression in memo:
                return memo[sub_expression]

            results = []

            for index, char in enumerate(sub_expression):
                if char in "+-*":
                    left_results = compute(sub_expression[:index])
                    right_results = compute(sub_expression[index + 1:])

                    for left_value in left_results:
                        for right_value in right_results:
                            if char == "+":
                                results.append(left_value + right_value)
                            elif char == "-":
                                results.append(left_value - right_value)
                            else:
                                results.append(left_value * right_value)

            if not results:
                results.append(int(sub_expression))

            memo[sub_expression] = results
            return results

        return compute(expression)
```实施首先创建一个`memo`将子字符串映射到其计算结果的字典。 这用作我们的缓存。 

嵌套的`compute()`函数执行递归分而治之逻辑。 它接受一个子字符串并立即检查它是否已经被解决。 如果是，则返回缓存的结果。 

然后该函数扫描每个字符。 当遇到运算符时，它会递归地计算表达式的左侧和右侧部分。 

由于每一侧都可能产生多个可能的结果，因此我们使用嵌套循环来组合每一对。 这确保了所有有效的括号都被表示。 

如果未找到运算符，则子字符串必须是数字。 我们将其转换为整数并将其作为单元素列表返回。 

最后，我们在返回计算结果之前对其进行缓存，确保将来对同一子字符串的调用是恒定时间查找。 

## 解决方案```go
func diffWaysToCompute(expression string) []int {
	memo := make(map[string][]int)

	var compute func(string) []int

	compute = func(subExpression string) []int {
		if result, exists := memo[subExpression]; exists {
			return result
		}

		results := []int{}

		for i, ch := range subExpression {
			if ch == '+' || ch == '-' || ch == '*' {
				leftResults := compute(subExpression[:i])
				rightResults := compute(subExpression[i+1:])

				for _, leftValue := range leftResults {
					for _, rightValue := range rightResults {
						switch ch {
						case '+':
							results = append(results, leftValue+rightValue)
						case '-':
							results = append(results, leftValue-rightValue)
						case '*':
							results = append(results, leftValue*rightValue)
						}
					}
				}
			}
		}

		if len(results) == 0 {
			number := 0
			for _, ch := range subExpression {
				number = number*10 + int(ch-'0')
			}
			results = append(results, number)
		}

		memo[subExpression] = results
		return results
	}

	return compute(expression)
}
```Go 实现遵循与 Python 相同的递归记忆结构。 

一个显着的区别是数字解析。 我们不调用内置的转换助手，而是手动逐位构造整数。 这避免了额外的导入并保持解决方案的独立性。 

Go 切片自然地代表动态数组，因此结果是使用`append`。 记忆映射存储由子字符串作为键控的整数切片。 

与 Python 不同，Go 区分`nil`和空切片，但这里我们显式初始化`results := []int{}`因此行为仍然是可预测的。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n × Cn) | 每个子表达式求解一次，组合遵循加泰罗尼亚式增长 |
 | 空间| O(n × Cn) | 记忆存储加上递归调用堆栈和生成的结果 |

 主导因素是可能的括号数量，它遵循加泰罗尼亚数字的增长。 记忆化确保每个子字符串仅计算一次，从而消除重复递归。 由于仍必须生成每个有效结果，因此该算法无法避免组合输出大小。

 ## 边缘情况

 ### 表达式仅包含数字

 像这样的表达`"42"`没有运算符，这意味着没有任何东西可以递归拆分。 有错误的实现可能会返回空列表，因为没有发生递归分支。 

此实现通过检查是否遇到任何运算符来处理这种情况。 如果不存在，则子字符串直接转换为整数并作为单元素列表返回。 

### 多位数

 一个常见的错误是假设每个字符都是独立的操作数。 例如，`"12+34"`应解释为两个数字，而不是四个单独的数字。 

我们的实现避免了这个问题，因为递归拆分仅发生在运算符处。 如果子字符串不包含任何运算符，则整个子字符串将被解析为一个整数。 

### 重复结果

 不同的括号可能会产生相同的数值。 例如：```
"2*3*4"
```两个都：```
((2*3)*4)
```和```
(2*(3*4))
```生产`24`。 

有缺陷的实现可能会意外地使用集合删除重复项。 该解决方案有意将结果存储在列表中，完全按照问题的要求保留重复值。 

### 重复子表达式

 表达如`"2*3-4*5"`重复使用较小的段，例如`"4*5"`。 

如果没有记忆，这些子表达式将被重新计算多次，从而导致指数级的减速。 备忘录字典确保每个子字符串都被解决一次并随后重复使用。
