[LeetCode 第 294 题](https://leetcode.com/problems/flip-game-ii/)

 **难度：** 🟡 中等
 **主题：** 数学、动态规划、回溯、记忆、博弈论

 ## 解决方案

 ## 问题理解

 该问题描述了在仅由以下元素组成的字符串上进行的两人公平游戏`'+'`和`'-'`人物。 有效的移动包括选择任意一对连续的`"++"`字符并将它们翻转为`"--"`。 

玩家轮流轮流进行。 如果玩家在自己的回合中无法采取有效的行动，他们就会输掉游戏。 任务是确定在双方都发挥最佳的情况下，起始玩家是否可以取得胜利。 

输入是单个字符串`currentState`。 每个字符代表当前棋盘状态。 输出是一个布尔值：

 - 返回`true`如果第一个玩家有保证获胜的策略。 
- 返回`false`如果第二个玩家总能做出最佳反应并最终获胜。 

问题陈述中的关键词是“保证胜利”。 这意味着我们不是在寻找获胜序列是否偶然存在，而是在寻找当前玩家是否能够无论对手如何反应都强行获胜。 

这些约束提供了几个重要的见解：

 - 字符串长度最大可达 60。 
- 连续的不能超过20个`'+'`。 

对所有游戏状态进行简单的递归探索可能会变得极其昂贵，因为每次移动都会创建多个分支的可能性。 但连续的限制`'+'`序列在实践中极大地限制了实际博弈树的大小。 

立即识别几个边缘情况非常重要：

 - 没有的字符串`"++"`substrings 意味着不存在合法的移动，因此当前玩家立即失败。 
- 非常短的字符串，例如`"+"`或者`"-"`不能包含有效的动作。 
- 具有多个断开连接的字符串`"++"`区域创建分支递归状态。 
- 通过不同的移动顺序可以出现重复的状态，这使得记忆非常有价值。 

这个问题是带有记忆的递归博弈论的典型例子。 

## 方法

 ### 暴力回溯

 最直接的方法是递归地模拟每一个可能的动作。 

对于字符串中的每个位置，我们检查是否存在`"++"`一对。 如果有，我们将其翻转为`"--"`并根据结果状态递归判断对手是否可以获胜。 

博弈论的观察很简单：

 - 如果至少存在一招导致对手失败，则当前玩家获胜。 
- 如果每一步都可以让对手获胜，那么当前玩家就输了。 

这种递归公式是正确的，因为游戏是有限且确定的。 最终，每条路径都到达最终状态，不再有任何移动。 

然而，这种强力方法会多次重新计算相同的状态。 不同的移动顺序可以产生相同的棋盘配置，从而导致工作的指数级重复。 

由于这种重复计算，随着可能状态数量的增加，简单的递归变得太慢。 

### 最佳方法，带记忆的 DFS

 关键的观察结果是状态的结果仅取决于板配置本身。 

如果我们已经知道特定的字符串状态是赢还是输，我们就不需要再次计算它。 这自然会导致记忆。 

我们使用深度优先搜索来探索可能的移动，并且哈希图存储先前计算的结果：

 -`memo[state] = true`表示当前玩家可以从该状态强行获胜。 
-`memo[state] = false`意味着当前玩家以最佳玩法失败。 

这种优化极大地减少了重复计算，因为每个唯一状态仅评估一次。 

递归博弈论规则保持不变：

 - 如果任何举动导致对手处于失败状态，则当前状态为获胜。 
- 否则当前状态正在丢失。

 ## 算法演练

 1. 创建一个记忆映射来缓存之前计算的游戏状态。 

该备忘录可防止多次重新计算相同的板配置。 由于游戏状态经常重复，因此这种优化至关重要。 
2. 定义递归DFS 函数。 

该函数将当前棋盘状态作为输入，并返回当前玩家是否可以从该位置强制获胜。 
3. 检查当前状态是否已存在于备忘录映射中。 

如果之前已经计算过状态，则立即返回缓存的结果。 
4. 遍历字符串并搜索`"++"`对。 

每一个`"++"`对代表当前玩家可以做出的合法举动。 
5. 对于每个有效的移动，生成下一个状态。 

替换选定的`"++"`和`"--"`。 

例如：```
"++++" → "+--+"
```6. 递归地评估对手的位置。 

出手后，就轮到对手了。 如果递归调用返回`false`，表示对手从该状态开始就输了。 
7. 如果任何一步导致对手失败，则将当前状态标记为获胜。 

将结果存储在备忘录映射中并立即返回`true`。 
8. 如果所有可能的动作都让对手获胜，则将当前状态标记为失败。 

店铺`false`在备忘录中并将其返回。 

### 为什么它有效

 该算法依赖于确定性回合制游戏的极小极大属性。 

如果至少有一个合法的动作转变为对手的失败位置，则该位置为获胜位置。 如果每一个合法的举动都转变为对手的获胜位置，则该位置处于失败状态。 

由于每次递归调用都会根据此规则评估状态，并且记忆保证了计算结果的一致重用，因此算法可以正确确定起始玩家是否可以强制获胜。 

## Python 解决方案```python
class Solution:
    def canWin(self, currentState: str) -> bool:
        memo = {}

        def dfs(state: str) -> bool:
            if state in memo:
                return memo[state]

            for i in range(len(state) - 1):
                if state[i:i + 2] == "++":
                    next_state = state[:i] + "--" + state[i + 2:]

                    # If opponent loses, current player wins
                    if not dfs(next_state):
                        memo[state] = True
                        return True

            memo[state] = False
            return False

        return dfs(currentState)
```实现首先创建一个名为的字典`memo`。 这存储了先前计算的板状态结果。 

嵌套的`dfs`函数执行递归游戏状态评估。 它首先检查当前状态是否已存在于备忘录表中。 如果是，则立即返回缓存的结果。 

循环扫描字符串寻找`"++"`对。 每个有效对都代表一个合法的举动。 

当发现移动时，代码会构造一个新字符串，其中该对将翻转为`"--"`。 

递归调用评估对手是否可以从结果状态中获胜。 如果对手不能获胜，那么当前玩家已经找到了获胜的棋步，因此该函数存储`True`并立即返回。 

如果循环结束时没有找到获胜的棋步，则每一个可能的棋步都会导致对手获胜。 因此，国家正在失败，并且`False`存储在备忘录映射中。 

最终结果通过调用得到`dfs(currentState)`。 

## 解决方案```go
func canWin(currentState string) bool {
    memo := make(map[string]bool)
    visited := make(map[string]bool)

    var dfs func(string) bool

    dfs = func(state string) bool {
        if visited[state] {
            return memo[state]
        }

        visited[state] = true

        for i := 0; i < len(state)-1; i++ {
            if state[i:i+2] == "++" {
                nextState := state[:i] + "--" + state[i+2:]

                // If opponent loses, current player wins
                if !dfs(nextState) {
                    memo[state] = true
                    return true
                }
            }
        }

        memo[state] = false
        return false
    }

    return dfs(currentState)
}
```Go 实现遵循与 Python 版本相同的递归记忆结构。 

一个重要的区别是 Go 映射会自动返回零值。 自从`false`是一个有效的缓存结果，我们需要一个单独的`visited`地图来区分：

 - 尚未计算的状态
 - 已计算并评估为的状态`false`Go 中的字符串切片非常高效，因为字符串内部是不可变的字节切片。 由于输入仅包含 ASCII 字符，因此索引和切片在这里是安全的。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(S × n) | 每个唯一的状态都会被处理一次，并且每次处理都会扫描字符串 |
 | 空间| O(S)| 记忆化存储所有独特的状态|

 这里，`S`表示唯一可到达的游戏状态的数量。 

如果没有记忆，递归会重复探索相同的状态，导致指数爆炸。 通过记忆，每个状态只被评估一次，大大减少了冗余工作。 

递归深度最多与可能的翻转次数成正比，而翻转次数受字符串长度的限制。

 ## 边缘情况

 一种重要的边缘情况是当字符串不包含`"++"`根本没有子串。 例子包括`"+"`,`"--"`， 和`"+-+-"`。 幼稚的实现可能会错误地假设至少存在一个动作。 在提供的解决方案中，循环根本不会进入递归分支，并且状态被正确分类为丢失。 

另一个微妙的边缘情况涉及重叠的移动位置，例如`"+++"`。 有两种有效的移动：翻转前两个字符或翻转最后两个字符。 有缺陷的实现可能会因不正确地推进索引而意外地跳过重叠对。 该解决方案独立检查每对相邻的对，确保探索所有合法的举动。 

第三个重要情况是通过不同路径可到达的重复状态。 如果没有记忆化，递归树可能会呈指数级爆炸。 例如，较长的字符串，如`"++++++++"`产生许多重叠的子问题。 备忘录映射保证每个状态仅计算一次，防止冗余递归并确保可接受的性能。 

最后的边缘情况涉及断开的区域，例如`"++--++"`。 游戏有效地分为独立的部分，但递归搜索仍然可以自然地进行，因为每个生成的状态都完全代表棋盘配置。 不需要特殊情况逻辑。
