[LeetCode 第 290 题](https://leetcode.com/problems/word-pattern/)

 **难度：** 🟢简单
 **主题：** 哈希表、字符串

 ## 解决方案

 ## 问题理解

 该问题提供两个输入：模式字符串和空格分隔的单词字符串。 我们需要确定单词序列是否遵循与模式中的字符序列相同的结构。 

有效的匹配需要模式字符和单词之间的双射。 双射意味着映射在两个方向上进行：

 - 每个字符恰好映射到一个单词。 
- 每个单词恰好映射到一个字符。 

此条件比简单地检查每个字符是否始终映射到同一个单词更严格。 我们还必须确保两个不同的字符不会映射到同一个单词。 

例如，用模式`"abba"`和字符串`"dog cat cat dog"`：

 -`'a'`映射到`"dog"`-`'b'`映射到`"cat"`映射在两个方向上都是一致且唯一的，所以答案是`true`。 

然而，对于模式`"abba"`和字符串`"dog dog dog dog"`：

 -`'a'`将映射到`"dog"`-`'b'`也将映射到`"dog"`这违反了双射要求，因为两个不同的模式字符映射到同一个单词。 

限制相对较小。 模式长度最多为 300，字符串长度最多为 3000。这意味着即使效率较低的方法仍然可以足够快地运行，但该问题从根本上设计为测试正确的哈希映射使用和对双射的理解。 

一些边缘情况很重要：

 - 模式字符数可能不等于单词数。 
- 一个字符可能会出现多次，并且必须始终映射到同一个单词。 
- 不同的字符不得映射到同一个单词。 
- 输入保证格式有效，这意味着没有多余的空格并且每个单词都非空。 

这些保证简化了解析，因为用空格分割字符串总是会产生有效的单词。 

## 方法

 每次我们处理新的字符-单词对时，强力解决方案都可以重复扫描所有先前的映射。 对于每个位置，我们将检查当前字符之前是否与不同的单词相关联，或者当前单词之前是否与不同的字符相关联。 

这是有效的，因为每对都针对所有之前的对进行验证，确保一致性。 然而，重复扫描使得解决方案效率低下。 如果图案长度为`n`，我们可以将每一对与最多`n`较早的条目，产生二次时间复杂度。 

最佳解决方案的关键观察是我们需要在两个方向上进行恒定时间查找。 哈希映射非常适合此目的，因为它允许快速验证现有映射。 

我们维持：

 - 从模式字符到单词的映射
 - 从单词到模式字符的映射

 处理每一对时：

 - 如果该字符已存在于第一个映射中，则其映射的单词必须与当前单词匹配。 
- 如果该单词已存在于第二个映射中，则其映射字符必须与当前字符匹配。 

如果任一条件失败，则该模式无效。 

这种方法可确保在恒定时间内立即检查每个映射决策。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 重复扫描以前的映射以确保一致性 |
 | 最佳| O(n) | O(n) | 使用两个哈希映射进行恒定时间双向检查 |

 ## 算法演练

 1.分割输入字符串`s`进入单词列表。 

我们需要直接位置访问，因为每个模式字符恰好对应于同一索引处的一个单词。 
2. 将字数与模式长度进行比较。 

如果它们不同，则映射是不可能的。 每个字符必须准确映射到一个单词，因此计数必须匹配。 
3. 创建两个哈希图。 

第一个映射存储字符与单词的关系。 

第二个映射存储单词与字符的关系。 

两个映射是必要的，因为双射要求在两个方向上都起作用。 
4. 同时迭代模式和单词。 

在每个索引处：

 - 让`char`是当前模式字符。 
- 让`word`是当前单词。 
5. 检查字符到单词的映射。 

如果`char`地图中已存在：

 - 其存储的单词必须等于当前单词。 

否则：

 - 添加新的映射。 
6. 检查单词到字符的映射。 

如果`word`地图中已存在：

 - 其存储的字符必须等于当前字符。 

否则：

 - 添加新的映射。 
7. 如果发现不一致，请返回`False`立即地。 

没有必要继续，因为双射已经被违反。 
8. 如果整个迭代成功完成，则返回`True`。 

所有映射都是一致且唯一的。 

### 为什么它有效

 该算法在整个执行过程中保持不变：

 - 每个经过处理的模式字符都准确地映射到一个单词。 
- 每个处理过的单词都准确地映射到一个模式字符。 

因为每一步都会检查两个方向，所以无效的映射不会存在。 如果算法完成时没有检测到冲突，则保证映射是有效的双射。 

## Python 解决方案```python
class Solution:
    def wordPattern(self, pattern: str, s: str) -> bool:
        words = s.split()

        if len(pattern) != len(words):
            return False

        char_to_word = {}
        word_to_char = {}

        for char, word in zip(pattern, words):
            if char in char_to_word:
                if char_to_word[char] != word:
                    return False
            else:
                char_to_word[char] = word

            if word in word_to_char:
                if word_to_char[word] != char:
                    return False
            else:
                word_to_char[word] = char

        return True
```实现首先使用将字符串拆分为单词`split()`。 这会生成一个列表，其中每个单词都可以直接与模式字符匹配。 

长度比较是一个重要的提前退出条件。 如果计数不同，则不存在有效的一对一对应关系。 

然后创建两个字典：

 -`char_to_word`跟踪从模式字符到单词的映射。 
-`word_to_char`跟踪从单词到字符的映射。 

该循环使用同时处理两个序列`zip()`。 

对于每对：

 - 如果该字符已存在于字典中，我们将验证它是否映射到当前单词。 
- 如果没有，我们将创建映射。 

对于单词到字符的映射，反向重复相同的过程。 

如果发生任何不匹配，该函数立即返回`False`。 

如果循环成功完成，则所有映射都满足双射属性，因此函数返回`True`。 

## 解决方案```go
func wordPattern(pattern string, s string) bool {
    words := strings.Split(s, " ")

    if len(pattern) != len(words) {
        return false
    }

    charToWord := make(map[byte]string)
    wordToChar := make(map[string]byte)

    for i := 0; i < len(pattern); i++ {
        char := pattern[i]
        word := words[i]

        if mappedWord, exists := charToWord[char]; exists {
            if mappedWord != word {
                return false
            }
        } else {
            charToWord[char] = word
        }

        if mappedChar, exists := wordToChar[word]; exists {
            if mappedChar != char {
                return false
            }
        } else {
            wordToChar[word] = char
        }
    }

    return true
}
```Go 解决方案遵循与 Python 版本相同的逻辑，但使用 Go 映射而不是字典。 

一个显着的区别是模式字符的访问方式为`byte`值，因为输入仅包含小写英文字母。 这避免了不必要的符文处理。 

字符串被分割使用`strings.Split(s, " ")`，产生一段单词。 

Go 映射查找返回存储的值和指示键是否存在的布尔值。 这用于区分现有映射和新映射。 

不需要对 nil 值或整数溢出进行特殊处理，因为问题约束很小并且数据结构很简单。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个字符-单词对被处理一次 |
 | 空间| O(n) | 哈希映射最多可以存储 n 个唯一的映射 |

 该算法对模式和单词列表执行单次遍历。 每个哈希映射操作以平均恒定时间运行，因此总运行时间是线性的。 

空间使用也是线性的，因为在最坏的情况下，每个字符和每个单词都是唯一的并且必须存储在映射中。

 ## 边缘情况

 当单词数量与模式字符数量不同时，就会出现一种重要的边缘情况。 幼稚的实现可能会在检查长度之前开始构建映射，从而导致不正确的结果或索引错误。 该实现通过在处理任何映射之前执行立即长度比较来避免这种情况。 

另一个关键的边缘情况是两个不同的模式字符尝试映射到同一个单词。 例如，`"ab"`和`"dog dog"`应该返回`false`。 仅使用一个从字符到单词的哈希映射的解决方案将错误地接受这种情况。 从单词到字符的反向映射可以防止此问题。 

第三种边缘情况涉及不一致的重复字符映射。 例如，`"aaaa"`和`"dog cat cat dog"`应该会失败，因为相同的字符无法映射到多个单词。 每次角色重新出现时，该实现都会检查现有映射，以确保整个迭代过程中的一致性。 

微妙的边缘情况是尽可能小的有效输入，例如`"a"`和`"dog"`。 该算法自然地处理这一问题，因为映射仅存储一个有效的映射并成功完成。 

最后，具有所有唯一字符和所有唯一单词的输入仍必须满足双射规则。 类似的情况`"abc"`和`"dog cat fish"`验证实现是否正确处理完全不同的映射，而不依赖于重复的模式。
