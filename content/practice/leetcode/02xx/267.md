[LeetCode 第 267 题](https://leetcode.com/problems/palindrome-permutation-ii/)

 **难度：** 🟡 中等
 **主题：** 哈希表、字符串、回溯

 ## 解决方案

 ## 问题理解

 该问题要求我们生成每个唯一的回文，这些回文可以通过重新排列给定字符串的字符来形成。 

回文是向前和向后读相同的字符串。 例如，`"abba"`和`"racecar"`是回文。 任务不是确定原始字符串是否已经是回文。 相反，我们必须考虑字符的所有可能排列，并返回形成回文的每个不同排列。 

输入是单个字符串`s`仅由小写英文字母组成。 输出应该是所有唯一回文排列的列表。 如果无法形成回文，我们返回一个空列表。 

约束条件很重要：

 - 字符串长度最多为16
 - 字符仅限于小写英文字母

 16 的长度足够小，使得回溯是可行的，但又足够大，以至于暴力排列生成变得极其昂贵。 由于排列按阶乘增长，直接生成所有排列很快就会变得不切实际。 

最重要的观察是回文存在所需的条件：

 - 对于偶数长度的字符串，每个字符数必须是偶数
 - 对于奇数长度的字符串，恰好有一个字符可能具有奇数个数

 该性质来自回文的对称性。 左侧的每个字符都必须在右侧有一个匹配的字符，中间可能有一个字符除外。 

一些边缘情况尤其重要：

 - 具有多个奇数频率的字符串，例如`"abc"`, 不能形成任何回文
 - 具有单个字符的字符串应返回该字符本身
 - 如果不小心处理，具有重复字符的字符串可能会产生重复的排列
 - 像这样的字符串`"aaaa"`应该只产生一个回文，而不是多个相同的结果

 ## 方法

 ### 蛮力方法

 强力解决方案生成字符串的每个可能的排列，然后检查每个排列是否是回文。 

对于一个长度的字符串`n`， 有`n!`可能的排列。 对于每个排列，我们可以检查它是否是回文`O(n)`通过比较从两端到中心的字符来计算时间。 

这种方法是正确的，因为它详尽地检查了每种可能的安排。 如果存在回文排列，蛮力最终会找到它。 

然而，这种方法太慢了。 即使最大长度为 16，排列的数量也会变得非常大。 

此外，重复的字符会产生重复的排列，因此我们还需要一个集合来避免重复的输出。 

### 最佳方法

 关键的见解是回文完全由其前半部分决定。 

例如：

-`"abba"`是由`"ab"`-`"racecar"`是由`"rac"`加中间字符`"e"`我们不需要排列整个字符串，而只需要生成一半字符的唯一排列。 

该算法的工作原理如下：

 1. 统计字符频率
 2. 验证回文是否可能
 3. 使用构建半字符串`count // 2`每个字符的副本
 4. 生成这一半的所有独特排列
 5. 镜像可选中间字符周围的一半

 这极大地减少了搜索空间。 

例如：

-`"aabb"`变成半弦`"ab"`- 排列是`"ab"`和`"ba"`- 结果回文是`"abba"`和`"baab"`通过仅生成唯一的半排列，我们可以自动避免重复的完整回文。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n! × n) | O(n! × n) | O(n!) | 生成每个排列并检查每个排列 |
 | 最佳 | O((n/2)! × n) | O((n/2)! × n) | O((n/2)!) | O((n/2)!) | 仅生成一半字符串的唯一排列 |

 ## 算法演练

 1. 使用哈希映射计算每个字符的出现频率。 

我们需要频率信息，因为回文可行性完全取决于字符计数。 哈希映射允许恒定时间更新和查找。 
2. 计算有多少个字符出现奇数频率。 

一个回文最多可以包含一个奇数字符。 如果存在多个奇数，则立即返回一个空列表。 
3. 识别中间人物。 

如果一个字符的出现频率为奇数，则它必须出现在回文串的中心。 单独存储该字符。 
4. 构建半弦。 

对于每个具有频率的字符`count`， 添加`count // 2`复制到列表中。 这代表回文的左半部分。 

例子：

-`"aabbcc"`变成`"abc"`-`"aaaabb"`变成`"aab"`5. 对半串进行排序。 

排序允许我们在回溯期间跳过重复的排列。 
6. 使用回溯生成半串的所有唯一排列。 

递归期间：

 - 跟踪哪些字符已被使用
 - 通过检查相邻的相等字符来跳过重复项
 - 逐步构建排列
 7. 构造完整的回文。 

对于每个生成的一半：

 - 反转一半
 - 插入中间字符（如果存在）
 - 将所有内容连接在一起

 示例：

 - 一半：`"ab"`- 中间：`""`- 撤销：`"ba"`- 结果：`"abba"`8. 返回生成的回文列表。 

### 为什么它有效

 该算法之所以有效，是因为每个回文都是对称的。 一旦选择了左半部分，右半部分就通过镜像来唯一确定。 唯一剩下的自由度是可选的中间字符，它必须是唯一的奇数频率字符（如果存在）。 

通过恰好生成半串的每个唯一排列一次，我们就生成了每个有效回文串一次。 

## Python 解决方案```python
from typing import List
from collections import Counter

class Solution:
    def generatePalindromes(self, s: str) -> List[str]:
        frequency = Counter(s)

        odd_chars = [char for char, count in frequency.items() if count % 2 == 1]

        if len(odd_chars) > 1:
            return []

        middle = odd_chars[0] if odd_chars else ""

        half_chars = []

        for char, count in frequency.items():
            half_chars.extend(char * (count // 2))

        half_chars.sort()

        results = []
        used = [False] * len(half_chars)

        def backtrack(path: List[str]) -> None:
            if len(path) == len(half_chars):
                half = "".join(path)
                palindrome = half + middle + half[::-1]
                results.append(palindrome)
                return

            for i in range(len(half_chars)):
                if used[i]:
                    continue

                if i > 0 and half_chars[i] == half_chars[i - 1] and not used[i - 1]:
                    continue

                used[i] = True
                path.append(half_chars[i])

                backtrack(path)

                path.pop()
                used[i] = False

        backtrack([])

        return results
```该实现首先计算字符频率`Counter`。 这立即为我们提供了确定回文是否可能所需的信息。 

列表理解收集`odd_chars`识别所有具有奇数频率的字符。 如果存在多个，则该函数立即返回一个空列表，因为无法形成回文。 

变量`middle`存储单个奇数频率字符（如果存在）。 该字符将占据每个生成的回文的中心位置。 

这`half_chars`列表是通过取每个字符出现次数的一半来构建的。 由于回文数的右半部分是通过镜像自动确定的，因此我们只需要生成这半部分的排列即可。 

排序`half_chars`对于避免重复至关重要。 在回溯过程中，当前递归层中尚未使用的重复字符将被跳过。 

这`used`数组跟踪哪些字符已包含在当前排列路径中。 

当完整的半排列完成后，代码通过连接来构造回文：

 - 一半
 - 中间的角色
 - 反转的一半

 每个生成的回文都附加到`results`。 

## 解决方案```go
package main

import (
	"sort"
)

func generatePalindromes(s string) []string {
	frequency := make(map[rune]int)

	for _, ch := range s {
		frequency[ch]++
	}

	oddCount := 0
	middle := ""

	for ch, count := range frequency {
		if count%2 == 1 {
			oddCount++
			middle = string(ch)
		}
	}

	if oddCount > 1 {
		return []string{}
	}

	halfChars := []rune{}

	for ch, count := range frequency {
		for i := 0; i < count/2; i++ {
			halfChars = append(halfChars, ch)
		}
	}

	sort.Slice(halfChars, func(i, j int) bool {
		return halfChars[i] < halfChars[j]
	})

	results := []string{}
	used := make([]bool, len(halfChars))

	var backtrack func(path []rune)

	backtrack = func(path []rune) {
		if len(path) == len(halfChars) {
			half := string(path)

			reversed := []rune(half)
			for i, j := 0, len(reversed)-1; i < j; i, j = i+1, j-1 {
				reversed[i], reversed[j] = reversed[j], reversed[i]
			}

			palindrome := half + middle + string(reversed)
			results = append(results, palindrome)
			return
		}

		for i := 0; i < len(halfChars); i++ {
			if used[i] {
				continue
			}

			if i > 0 && halfChars[i] == halfChars[i-1] && !used[i-1] {
				continue
			}

			used[i] = true
			path = append(path, halfChars[i])

			backtrack(path)

			path = path[:len(path)-1]
			used[i] = false
		}
	}

	backtrack([]rune{})

	return results
}
```Go 实现遵循与 Python 版本相同的总体策略。 一个区别是显式使用`rune`回溯期间使用切片而不是字符串。 由于 Go 字符串是不可变的，因此使用符文切片对于增量构建来说更有效。 

另一个区别是手动反转半字符串，因为 Go 不提供 Python 风格的切片语法，例如`[::-1]`。 

当不可能存在回文时，该函数返回一个空切片，这符合 LeetCode 的预期。

 ## 边缘情况

 一种重要的边缘情况是输入包含多个奇数频率字符时。 例如，`"abc"`有 3 个奇数。 幼稚的实现可能仍会尝试排列生成，从而浪费计算时间。 实施的解决方案会立即检测到这种情况，并在任何回溯开始之前返回一个空列表。 

另一个关键的边缘情况是所有字符都相同，例如`"aaaa"`。 如果没有正确的重复处理，回溯可能会多次生成相同的半排列。 排序步骤与重复跳过条件相结合，确保只生成一个唯一的回文。 

第三个重要的情况是奇数长度回文，例如`"aabbc"`。 恰好一个字符可以出现奇数次，并且它必须占据中心位置。 该实现在生成排列之前隔离这个中间字符，保证每个构造的回文保持有效的对称性。 

一个微妙的边缘情况涉及半字符串中的重复字符。 例如，`"aaaabb"`产生半串`"aab"`。 如果重复跳过执行不正确，算法可能会生成重复的回文或意外地跳过有效的回文。 条件：```
if i > 0 and half_chars[i] == half_chars[i - 1] and not used[i - 1]:
```确保仅在同一递归层中跳过重复项，从而在消除重复工作的同时保持正确性。
