 **难度：** 🟡 中等
 **主题：** 树、深度优先搜索、二叉搜索树、二叉树

 ## 解决方案

 ## 问题理解

 这个问题要求我们找到给定节点的有序后继者`p`二叉搜索树（Binary Search Tree），缩写为 BST。 

BST 的中序遍历按排序顺序访问节点：

 1. 遍历左子树
 2.访问当前节点
 3. 遍历右子树

 因为 BST 保留了排序属性：

 - 左子树中的每个节点都小于当前节点
 - 右子树中的每个节点都大于当前节点

 中序遍历自然会产生按升序排列的值。 

节点的有序后继者`p`是紧随其后出现的节点`p`按照这个排序的遍历顺序。 更具体地说，它是最小值严格大于的节点`p.val`。 

输入包括：

 -`root`，BST的根节点
 -`p`，存在于树内部某处的节点

 输出应该是：

 - 的`TreeNode`代表继任者
 -`None`或者`nil`如果没有继任者

 约束告诉我们树最多可以包含`10^4`节点。 这个值足够大，如果存在更高效的基于 BST 的解决方案，我们应该避免不必要的昂贵操作。 

该问题还保证：

 - 所有节点值都是唯一的
 -`p`总是存在于树中

 这些保证简化了逻辑，因为我们永远不需要处理重复或丢失的目标节点。 

一些边缘情况很重要：

 -`p`可能是 BST 中最大的节点，在这种情况下不存在后继节点
 -`p`可能有一个右子树，这会改变后继者的查找方式
 -`p`可能没有右子树，需要我们在祖先中搜索
 - 树可能只包含一个节点

 当处理没有正确子节点的节点或错误地跟踪祖先候选时，幼稚的实现很容易失败。 

## 方法

 ### 蛮力方法

 暴力解决方案执行 BST 的完整有序遍历，并将所有访问过的节点存储在列表中。 

由于 BST 的中序遍历会按排序顺序生成节点，因此我们可以扫描结果列表并定位节点`p`。 列表中的下一个节点（如果存在）是有序后继节点。 

这种方法简单且易于推理，因为它直接模拟了有序后继的定义。 

该算法的工作原理如下：

 1. 进行中序DFS遍历
 2. 将节点存储在数组中
 3. 查找索引`p`4. 如果存在则返回下一个节点

 虽然正确，但该解决方案效率低下，因为即使可以使用 BST 属性更早地确定答案，它也会遍历整个树。 

### 最佳方法

 关键的观察结果是，BST 排序允许我们智能搜索，而不是遍历整个树。 

有两个重要案例：

 1.如果`p`有右子树，则后继节点为最左边的节点`p.right`2.如果`p`没有右子树，则后继者是其祖先之一

 当从根向`p`，每当我们从一个节点向左移动时，该节点就会成为潜在的后继节点，因为它大于`p`。 我们跟踪最小的此类候选人。 

这使我们能够找到继任者`O(h)`时间、地点`h`是树的高度。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 全序遍历和数组存储 |
 | 最佳| O(h) | O(1) | O(1) | 使用 BST 属性进行高效搜索 |

 这里，`h`是树的高度。 在平衡 BST 中，这变为`O(log n)`。 

## 算法演练

 ### 最优 BST 搜索算法

 1. 初始化一个名为`successor`作为`None`。 

该变量存储迄今为止找到的最佳候选继任者。 在遍历过程中的任意一点，它代表大于的最小节点`p.val`。 
2. 从根开始遍历。 

我们以类似于标准 BST 搜索逻辑的方式遍历 BST。 
3.比较`p.val`与当前节点的值。 

如果`p.val`小于当前节点的值，则当前节点可能是后继节点，因为它大于`p`。 
4. 更新`successor`并向左移动。 

因为我们希望最小值大于`p.val`，我们将当前节点存储为候选节点，并继续在左子树中搜索可能更小的有效后继节点。 
5. 否则，向右移动。 

如果`p.val`大于或等于当前节点的值，则后继节点不能位于左子树或当前节点本身中。 我们向右移动以搜索更大的值。 
6. 继续直到遍历结束。 

一旦遍历达到`None`，存储的`successor`是正确的答案。 

### 为什么它有效

 该算法保持一个不变量：

 -`successor`始终存储迄今为止遇到的最小节点，其值大于`p.val`每当我们从一个节点向左移动时，该节点就会成为有效的候选节点，因为它大于`p`。 向左移动会搜索更小的有效候选者。 

每当我们向右移动时，当前节点就不能成为后继节点，因为它的值太小。 

由于 BST 排序保证了结构化的值关系，因此该过程最终会找到大于的最小节点`p.val`，这正是有序后继定义。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, x):
#         self.val = x
#         self.left = None
#         self.right = None

from typing import Optional

class Solution:
    def inorderSuccessor(
        self,
        root: TreeNode,
        p: TreeNode
    ) -> Optional[TreeNode]:

        successor = None
        current = root

        while current:
            if p.val < current.val:
                successor = current
                current = current.left
            else:
                current = current.right

        return successor
```实现从初始化开始`successor`到`None`。 这处理不存在有效后继者的情况。 

变量`current`从根向下遍历 BST。 

每当`p.val < current.val`，当前节点成为候选后继节点，因为它大于`p`。 然而，左子树中仍然可能存在更小的有效后继者，因此算法存储候选者并向左移动。 

什么时候`p.val >= current.val`，当前节点不能成为后继节点。 因此，算法向右移动以搜索更大的值。 

循环继续，直到遍历到达空指针。 此时，最佳候选存储在`successor`被返回。 

这种实现避免了递归和辅助数据结构，从而导致持续的额外空间使用。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func inorderSuccessor(root *TreeNode, p *TreeNode) *TreeNode {
    var successor *TreeNode
    current := root

    for current != nil {
        if p.Val < current.Val {
            successor = current
            current = current.Left
        } else {
            current = current.Right
        }
    }

    return successor
}
```Go 实现密切反映了 Python 逻辑。 

而不是`None`, Go 使用`nil`指针。 变量`successor`被初始化为`nil`指针并在找到更好的候选者时更新。 

因为 Go 使用显式指针类型，所以所有树导航都通过`*TreeNode`参考。 

不需要特殊的整数溢出处理，因为节点值完全在 Go 的整数范围内。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`p`是 BST 中的最大值。 在这种情况下，没有节点具有更大的值，因此正确答案是`None`。 有缺陷的实现可能会意外返回最后访问的祖先。 此实现避免了该问题，因为`successor`仅当节点大于时才更新`p`遇到。 

另一个重要的情况是当`p`有一个右子树。 后继节点应该是该子树中最左边的节点。 迭代 BST 搜索自然会处理这个问题，因为遍历会继续进入右子树，并在向左移动时不断更新较小的有效候选者。 

第三个重要的边缘情况是高度倾斜的树。 例如，形状像链表的树可能会暴露递归实现中的递归深度问题。 该解决方案使用迭代遍历，因此完全避免了递归堆栈增长。 

当继任者是祖先而不是后代时，会出现第四种边缘情况。 例如，如果`p = 4`在树上`[5,3,7,2,4]`，后继者是`5`。 该算法通过在遍历向左移动时记住候选祖先来正确处理这个问题。
