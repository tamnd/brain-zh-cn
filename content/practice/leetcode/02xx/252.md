[LeetCode 第 252 题](https://leetcode.com/problems/meeting-rooms/)

 **难度：** 🟢简单
 **主题：** 数组、排序

 ## 解决方案

 ## 问题理解

 该问题提供了会议间隔列表，其中每个间隔表示为`[start, end]`。 每对描述会议的开始时间和结束时间。 任务是确定一个人是否可以参加每个会议而不会出现任何安排冲突。 

简单来说，我们需要检查两个会议的时间是否重叠。 如果存在重叠，则此人无法参加所有会议，并且该函数应返回`false`。 如果没有会议重叠，则该人可以参加所有会议，并且该函数应返回`true`。 

例如，考虑间隔`[[0,30],[5,10],[15,20]]`。 第一次会议从时间开始`0`到`30`，而第二次会议开始于`5`。 自从`5`发生在之前`30`，会议重叠，因此不可能同时参加。 因此，答案是`false`。 

这些约束提供了有关输入规模的重要信息：

 - 间隔的数量可以大到`10^4`- 会议时间为整数
 - 每个区间保证有`start < end`输入大小足够大，低效的二次解决方案可能会变得昂贵，特别是在最坏的情况下。 这强烈表明排序可能很有用，因为排序允许重叠间隔变得相邻并且易于有效比较。 

需要考虑一些重要的边缘情况：

 - 应返回空会议列表`true`，因为没有冲突。 
- 单一会议也应该回归`true`。 
- 接触但不重叠的会议，例如`[1,5]`和`[5,10]`，有效，因为第一次会议恰好在第二次会议开始时结束。 
- 必须正确检测多个重叠会议，即使它们最初在输入顺序中并不相邻。 
- 间隔到达时可能未排序，因此依赖原始顺序是不正确的。 

## 方法

 ### 蛮力方法

 最直接的解决方案是将每次会议与其他会议进行比较。 对于每对间隔，我们检查它们的时间范围是否重叠。 

如果出现以下情况，两次会议会重叠：

 - 第一个会议在第二个会议结束之前开始
 - 第二次会议在第一次会议结束之前开始

 如果发现任何重叠，我们立即返回`false`。 如果检查所有对没有发现冲突，我们返回`true`。 

这种方法之所以有效，是因为它明确地验证了每对可能的会议。 然而，它的效率很低，因为它执行冗余比较。 和`n`会议，大约有`n^2`配对进行检查。 

鉴于`n`可以大到`10^4`，这个二次解在最坏的情况下可能执行多达 1 亿次比较，这是不必要的昂贵。 

### 最佳方法

 关键的观察结果是，在按开始时间对间隔进行排序后，重叠的会议变得更容易检测。 

一旦间隔排序：

 - 任何重叠会议必须出现在另一个重叠会议旁边
 - 我们只需要将每个区间与前一个区间进行比较

 这是有效的，因为排序保证了时间顺序。 如果当前会议在上一个会议结束之前开始，则会议会重叠。 

这将问题从检查所有可能的对减少到排序后仅检查相邻间隔。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 比较每对间隔 |
 | 最佳| O(n log n) | O(n log n) | O(1) 或 O(log n) 取决于排序实现 | 对间隔进行排序，然后扫描一次以查找重叠 |

 ## 算法演练

 1. 按开始时间对间隔进行排序。 

排序是最重要的步骤，因为它将会议按时间顺序排列。 一旦排序，相邻会议之间必须出现任何重叠。 
2. 从第二次会议开始迭代排序的时间间隔。 

我们将每次会议与前一次会议进行比较。 由于会议按开始时间排序，因此这足以检测所有冲突。 
3. 对于每个间隔，将其开始时间与前一个间隔的结束时间进行比较。 

如果：$currentStart < previousEnd$然后会议重叠。 
4.如果发现重叠，立即返回`False`。 

一旦存在冲突就无需继续检查。 
5. 如果循环完成而没有检测到重叠，则返回`True`。 

这意味着每个会议在上一个会议结束后或恰好在上一个会议结束时开始。 

### 为什么它有效

 排序后，会议按开始时间递增进行排序。 如果日程表中的任何位置存在重叠，则至少有一个会议必须在上一个会议结束之前开始。 由于所有较早的会议均已在不晚于前一个会议结束，因此检查相邻时间间隔足以检测每个可能的冲突。 

## Python 解决方案```python
from typing import List

class Solution:
    def canAttendMeetings(self, intervals: List[List[int]]) -> bool:
        # Sort meetings by start time
        intervals.sort(key=lambda interval: interval[0])

        # Check adjacent meetings for overlap
        for i in range(1, len(intervals)):
            previous_end = intervals[i - 1][1]
            current_start = intervals[i][0]

            if current_start < previous_end:
                return False

        return True
```实现首先使用间隔的开始时间对间隔进行排序。 Python 内置的排序非常高效并且运行在`O(n log n)`时间。 

排序后，循环从索引处开始`1`因为每次比较都需要之前的间隔。 对于每次迭代：

 -`previous_end`存储先前会议的结束时间
 -`current_start`存储当前会议的开始时间

 如果当前会议在前一个会议结束之前开始，则会议重叠并且该函数立即返回`False`。 

如果循环完成而没有找到重叠，则所有会议都是兼容的，因此该函数返回`True`。 

## 解决方案```go
package main

import "sort"

func canAttendMeetings(intervals [][]int) bool {
    // Sort intervals by start time
    sort.Slice(intervals, func(i, j int) bool {
        return intervals[i][0] < intervals[j][0]
    })

    // Check adjacent intervals for overlap
    for i := 1; i < len(intervals); i++ {
        previousEnd := intervals[i-1][1]
        currentStart := intervals[i][0]

        if currentStart < previousEnd {
            return false
        }
    }

    return true
}
```Go 实现遵循与 Python 版本相同的逻辑。 主要区别在于 Go 使用`sort.Slice`使用自定义比较器函数对间隔进行排序。 

Go 切片可以安全地表示空输入，因此不需要对空或 nil 切片进行特殊处理。 整数溢出不是问题，因为问题约束完全在 Go 的整数范围内。

 ## 边缘情况

 一个重要的边缘情况是空的间隔列表。 一种幼稚的实现可能会假设至少存在一个间隔并意外访问无效索引。 在此解决方案中，循环从索引处开始`1`，因此空输入自然会跳过循环并正确返回`True`。 

另一个重要的例子是完全触及其边界的会议，例如`[1,5]`和`[5,10]`。 一些不正确的实现使用`<=`而不是`<`在检查重叠时，这会错误地将这些会议标记为冲突。 正确的条件是严格`<`，因为恰好在另一个会议结束时开始是有效的。 

第三个重要的边缘情况涉及未排序的输入。 例如，`[[7,10],[2,4]]`如果按原始顺序处理而不进行排序，则会出现冲突。 该算法首先显式地对间隔进行排序，确保比较按时间顺序进行并防止错误的重叠检测。 

当一个会议完全包含另一个会议时，就会出现第四种微妙的情况，例如`[[1,10],[2,3]]`。 一些简单的间隔检查无法正确处理遏制。 排序邻接方法可以自然地处理此问题，因为所包含的会议在较大的会议结束之前开始，从而立即触发重叠检测。
