[LeetCode 第 271 题](https://leetcode.com/problems/encode-and-decode-strings/)

 **难度：** 🟡 中等
 **主题：** 数组、字符串、设计

 ## 解决方案

 ## 问题理解

 该问题要求我们为字符串列表设计一个可逆编码系统。 我们需要两个函数：

 -`encode`，它将字符串列表转换为单个字符串
 -`decode`，它从该编码字符串重建原始列表

 重要的要求是转换必须是无损的。 经过编码和解码后，我们必须恢复准确的原始列表，包括空字符串和包含特殊字符的字符串。 

输入是字符串列表，其中：

 - 字符串数量范围从1到200
 - 每个字符串的长度可以从 0 到 200
 - 字符串可以包含 256 个 ASCII 字符中的任意一个

 最后一个约束非常重要，因为它意味着我们不能安全地假设任何字符都被保留。 例如，字符串可能包含逗号、竖线、冒号、散列、空格，甚至换行符。 因此，任何基于分隔符的简单方法都可能失败。 

预期输出为`decode`是准确的原始列表。 顺序必须保持不变，并且每个字符都必须准确保留。 

一个主要挑战是解码过程中的歧义。 假设我们只是用分隔符连接字符串，例如`"#"`：```
["ab", "c#d"] -> "ab#c#d"
```解码时，我们无法判断这是否代表：```
["ab", "c", "d"]
```或者```
["ab", "c#d"]
```约束足够小，以至于`O(total_characters)`解决方案已经足够了，但正确性才是真正的挑战。 

一些边缘情况尤其重要：

 - 空字符串，例如`[""]`- 多个空字符串，例如`["", "", ""]`- 包含类似分隔符的字符串
 - 包含数字的字符串
 - 很长的字符串
 - 仅包含一个字符串的列表

 正确的解决方案必须毫不含糊地处理所有这些问题。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是使用特殊的分隔符连接所有字符串。 

例如：```
["hello", "world"] -> "hello#world"
```解码会将编码字符串拆分为`"#"`。 

仅当分隔符从未出现在原始字符串中时，此方法才有效。 不幸的是，该问题明确指出字符串可以包含任何 ASCII 字符，因此不能保证分隔符是安全的。 

一种可能的强力改进是在连接之前转义特殊字符。 例如，每个`"#"`字符串内部可能会变成`"##"`。 虽然这可以工作，但它会变得混乱且容易出错，因为我们必须小心地转义和取消转义每个保留字符。 

因此，暴力方法是不可靠的并且不必要地复杂。 

### 最佳方法

 关键的见解是，我们不应该依赖字符串之间的分隔符，而应该在字符串本身之前显式存储每个字符串的长度。 

编码格式变为：```
<length>#<string>
```例如：```
["Hello", "World"]
```变成：```
5#Hello5#World
```现在解码是明确的：

 - 读取字符直到`"#"`确定长度
 - 将该长度转换为整数
 - 准确读取那么多字符作为下一个字符串
 - 重复直到编码字符串用完

 这是有效的，因为解码器总是确切地知道有多少字符属于下一个字符串，而不管字符串本身的内容如何。 

即使字符串包含`"#"`或数字，解码仍然正确，因为解析器使用长度前缀而不是在字符串数据内搜索分隔符。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 使用分隔符，当字符串包含分隔符时失败 |
 | 最佳 | O(n) | O(n) | 使用长度前缀编码，完全明确 |

 这里，`n`表示所有字符串中的字符总数。 

## 算法演练

 ### 编码

 1. 初始化一个空结果字符串。 

我们将逐步附加每个字符串的编码表示。 
2. 对于输入列表中的每个字符串，计算其长度。 

长度告诉解码器到底有多少个字符属于该字符串。 
3. 附加长度，后跟分隔符，例如`"#"`。 

例子：```
"Hello" -> "5#"
```分隔符在这里是安全的，因为它仅将数字长度与字符串有效负载本身分开。 
4. 将原始字符串紧跟在分隔符之后。 

例子：```
"5#" + "Hello" -> "5#Hello"
```5. 对所有字符串重复此过程。 
6. 返回最终的串联编码字符串。 

### 解码

 1. 初始化一个空的结果列表和一个从0开始的指针索引。 
2.从当前位置开始读取字符，直到到达`"#"`。 

这些字符代表下一个字符串的长度。 
3. 将提取的长度子串转换为整数。 
4. 将指针移过分隔符。 
5. 准确阅读`length`从当前位置开始的字符。 

该切片是原始字符串。 
6. 将提取的字符串附加到结果列表中。 
7. 使指针前进`length`。 
8. 重复此操作，直到指针到达编码字符串的末尾。 
9. 返回重构后的列表。 

### 为什么它有效

 该算法之所以有效，是因为每个编码字符串都包含显式边界信息。 解码器永远不会猜测字符串的结束位置。 相反，它读取存储的长度并提取恰好那么多的字符。 这保证了每个字符串都可以正确重建，即使它包含特殊字符、数字、分隔符或空内容。 

## Python 解决方案```python
from typing import List

class Codec:
    def encode(self, strs: List[str]) -> str:
        """Encodes a list of strings to a single string."""
        
        encoded_parts = []

        for string in strs:
            encoded_parts.append(f"{len(string)}#{string}")

        return "".join(encoded_parts)

    def decode(self, s: str) -> List[str]:
        """Decodes a single string to a list of strings."""
        
        decoded_strings = []
        index = 0

        while index < len(s):
            separator_index = index

            while s[separator_index] != "#":
                separator_index += 1

            string_length = int(s[index:separator_index])

            start_of_string = separator_index + 1
            end_of_string = start_of_string + string_length

            decoded_strings.append(s[start_of_string:end_of_string])

            index = end_of_string

        return decoded_strings

# Your Codec object will be instantiated and called as such:
# codec = Codec()
# codec.decode(codec.encode(strs))
```这`encode`方法迭代每个字符串并构造一个长度前缀的表示。 格式为：```python
length#content
```所有编码片段都存储在一个列表中，并在最后连接以提高效率。 

这`decode`方法使用基于指针的解析策略。 它首先扫描直到`"#"`提取数字长度。 一旦知道长度，它就会从编码字符串中精确地切掉那么多的字符。 

这种方法完全避免了歧义，因为解码取决于显式长度而不是嵌入在内容中的分隔符。 

## 解决方案```go
package main

import (
	"strconv"
	"strings"
)

type Codec struct {
    
}

// Encodes a list of strings to a single string.
func (codec *Codec) Encode(strs []string) string {
	var builder strings.Builder

	for _, str := range strs {
		builder.WriteString(strconv.Itoa(len(str)))
		builder.WriteString("#")
		builder.WriteString(str)
	}

	return builder.String()
}

// Decodes a single string to a list of strings.
func (codec *Codec) Decode(s string) []string {
	var result []string

	index := 0

	for index < len(s) {
		separatorIndex := index

		for s[separatorIndex] != '#' {
			separatorIndex++
		}

		length, _ := strconv.Atoi(s[index:separatorIndex])

		startOfString := separatorIndex + 1
		endOfString := startOfString + length

		result = append(result, s[startOfString:endOfString])

		index = endOfString
	}

	return result
}

// Your Codec object will be instantiated and called as such:
// var codec Codec
// codec.Decode(codec.Encode(strs));
```Go 解决方案遵循与 Python 实现相同的逻辑，但使用`strings.Builder`用于高效的字符串连接。 由于 Go 字符串是不可变的，因此重复连接`+`会产生不必要的分配。 

解码器使用与 Python 版本完全相同的索引算术。 Go 切片使提取子字符串变得简单。 

对于空字符串不需要特殊处理，因为长度为`0`自然地按照相同的逻辑工作。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个字符都会被处理固定次数 |

空间复杂度是线性的，因为编码表示和解码结果都需要与输入大小成比例的存储。

 ## 边缘情况

 ### 空字符串

 空字符串很棘手，因为它不会向编码的有效负载贡献任何字符。 简单的分隔符方法可能会忘记空值是否存在。 

此实现通过将空字符串编码为：```
0#
```解码时，解析出的长度为`0`，因此解码器提取零个字符并正确重建空字符串。 

### 包含分隔符的字符串

 错误的主要来源是包含分隔符本身的字符串。 例如：```
["abc#def"]
```基于分隔符的解决方案会错误地分割该字符串。 

长度前缀方法完全避免了这种情况，因为解码从不搜索有效负载内的分隔符。 一旦知道长度，解码器就会准确地读取那么多字符，无论其内容如何。 

### 连续的空字符串和非空字符串

 案例如下：```
["", "abc", "", "def"]
```可能会在解码过程中暴露指针管理错误。 不正确的索引更新可能会跳过字符串或产生相差一的错误。 

此实现使用精确的子字符串边界更新指针：```
index = end_of_string
```因此，每个编码段都被精确处理一次，即使使用连续的空条目也能确保正确的重建。
