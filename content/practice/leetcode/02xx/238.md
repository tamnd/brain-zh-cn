[LeetCode 第 238 题](https://leetcode.com/problems/product-of-array- except-self/)

 **难度：** 🟡 中等
 **主题：** 数组、前缀和

 ## 解决方案

 ## 问题理解

 问题给出一个整数数组`nums`，并且对于每个索引`i`，我们必须计算数组中每个元素的乘积，除了`nums[i]`。 

如果输入是：```
nums = [1,2,3,4]
```那么：

 - 对于索引`0`，我们乘以`2 * 3 * 4 = 24`- 对于索引`1`，我们乘以`1 * 3 * 4 = 12`- 对于索引`2`，我们乘以`1 * 2 * 4 = 8`- 对于索引`3`，我们乘以`1 * 2 * 3 = 6`所以结果就变成了：```
[24,12,8,6]
```重要的限制是我们**不允许使用除法**。 一个简单的想法可能是：

 1. 计算所有数字的乘积
 2.除以`nums[i]`但是，明确禁止分割。 即使允许除法，零也会使该方法变得棘手，因为除以零是未定义的。 

这些约束告诉我们一些重要的事情：

 -`nums.length`可以大到`10^5`- 因此，任何`O(n^2)`解决方案可能会太慢
 - 我们需要一个`O(n)`算法
 - 前缀和后缀的乘积适合 32 位整数，因此在预期解决方案中不存在溢出问题

 后续问我们是否可以解决这个问题`O(1)`额外的空间，不包括输出数组本身。 这强烈暗示我们应该重用输出数组而不是创建多个辅助数组。 

一些边缘情况尤其重要：

 - 包含零的数组
 - 包含多个零的数组
 - 负数
 - 非常小的数组，例如长度`2`幼稚的实现通常会在零处理上失败，特别是当它依赖于除法时。 

## 方法

 ### 蛮力方法

 最直接的解决方案是独立计算每个索引的答案。 

对于每个职位`i`：

 1. 初始化一个产品变量为`1`2. 迭代整个数组
 3. 将除`nums[i]`4. 存储结果

 这是有效的，因为我们明确地计算了问题所要求的内容。 但是，对于每个元素，我们都会再次扫描整个数组。 

如果数组有`n`要素：

 - 我们表演`n`通过
 - 每张通行证费用`O(n)`- 总复杂度变为`O(n^2)`和`n`最多`100000`，这种方法太慢了。 

### 最优前缀和后缀乘积方法

 关键的见解是对于每个索引`i`，答案可以分为两个独立的部分：```
product of elements to the left of i
*
product of elements to the right of i
```例如：```
nums = [1,2,3,4]
```对于索引`2`：```
left product  = 1 * 2 = 2
right product = 4
answer        = 2 * 4 = 8
```我们可以逐步构建它们，而不是重复地重新计算这些产品。 

我们首先计算前缀积：```
prefix[i] = product of all elements before i
```然后计算后缀积：```
suffix[i] = product of all elements after i
```最后：```
answer[i] = prefix[i] * suffix[i]
```我们可以通过将前缀乘积直接存储在输出数组中，然后在向后传递期间乘以后缀乘积来进一步优化空间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 重新计算每个索引的乘积 |
 | 最佳| O(n) | O(1) 额外空间 | 高效使用前缀和后缀产品 |

 ## 算法演练

 1. 创建输出数组`answer`尺寸的`n`，初始化为`1`。 

我们将使用这个数组首先存储前缀产品，然后用后缀产品更新它。 
2. 从左到右遍历数组，同时保持运行的前缀积。 

在每个索引处`i`：

 -`answer[i]`应包含之前所有元素的乘积`i`- 然后通过乘以更新运行前缀乘积`nums[i]`例子：```
nums = [1,2,3,4]
```前缀传递：```
answer = [1,1,2,6]
```3. 从右向左遍历数组，同时保持运行的后缀积。 

在每个索引处`i`：

 - 乘法`answer[i]`按当前后缀产品
 - 通过乘以更新后缀积`nums[i]`这将所有元素的贡献添加到右侧`i`。 
4. 返回最终结果`answer`大批。 

向后传递后，每个位置包含：```
product of left elements * product of right elements
```### 为什么它有效

 在第一遍的过程中，`answer[i]`将所有元素的乘积严格存储在索引左侧`i`。 

在第二遍期间，后缀变量将所有元素的乘积严格存储在索引右侧`i`。 

将这两个值相乘即可精确得出每个元素的乘积，除了`nums[i]`。 

因为每个元素要么对左乘积做出贡献，要么对右乘积做出贡献，而不会同时对两者做出贡献，因此每个索引的结果都是正确的。 

## Python 解决方案```python
from typing import List

class Solution:
    def productExceptSelf(self, nums: List[int]) -> List[int]:
        n = len(nums)
        
        answer = [1] * n
        
        prefix_product = 1
        for i in range(n):
            answer[i] = prefix_product
            prefix_product *= nums[i]
        
        suffix_product = 1
        for i in range(n - 1, -1, -1):
            answer[i] *= suffix_product
            suffix_product *= nums[i]
        
        return answer
```该实现对数组使用两次传递。 

第一个循环计算前缀乘积。 乘以之前`nums[i]`，当前的`prefix_product`表示左侧所有值的乘积`i`。 该值直接存储到`answer[i]`。 

存储后，我们通过与当前元素相乘来扩展前缀。 

第二个循环向后移动数组。 步步，`suffix_product`包含当前索引右侧所有元素的乘积。 

我们将现有的前缀值相乘`answer[i]`通过此后缀产品。 这将左右贡献结合成最终答案。 

由于输出数组本身被重用，因此我们避免分配单独的前缀和后缀数组。 

## 解决方案```go
func productExceptSelf(nums []int) []int {
	n := len(nums)

	answer := make([]int, n)

	for i := 0; i < n; i++ {
		answer[i] = 1
	}

	prefixProduct := 1
	for i := 0; i < n; i++ {
		answer[i] = prefixProduct
		prefixProduct *= nums[i]
	}

	suffixProduct := 1
	for i := n - 1; i >= 0; i-- {
		answer[i] *= suffixProduct
		suffixProduct *= nums[i]
	}

	return answer
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

使用创建切片`make([]int, n)`，并且每个位置被初始化为`1`。 

Go 切片的行为与动态数组类似，因此我们可以有效地更新值。 

整数溢出不是问题，因为该问题保证结果适合 32 位整数。 

与 Python 不同，Go 不会自动初始化切片`1`，因此我们在开始前缀计算之前显式填充数组。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 两次线性遍历数组 |
 | 空间| O(1) 额外空间 | Only a few variables are used besides the output array |

 The algorithm processes the array twice, once from left to right and once from right to left. Each pass touches every element exactly once, so the total runtime is linear.

 The only extra variables used are the prefix and suffix accumulators. Since the output array does not count toward extra space according to the problem statement, the solution satisfies the`O(1)`额外的空间要求。

 ## 边缘情况

 一种重要的边缘情况是数组恰好包含一个零。 在这种情况下，除了零的位置之外的每个位置都必须变成`0`，因为每个产品都包含零。 包含零的位置应等于所有非零元素的乘积。 基于除法的方法在这里经常失败，但前缀后缀方法可以自然地处理它，因为零只是通过前缀和后缀乘积传播。 

另一个关键的边缘情况是当数组包含多个零时。 如果至少有两个零，则除 self 之外的每个乘积都必须至少包含一个零，因此整个结果变为全零。 该算法会自动处理此问题，因为前缀和后缀累加器在遍历期间都会变为零。 

负数也很重要，因为符号变化很容易暴露逻辑错误。 例如：```
[-1,-2,-3,-4]
```产生：```
[-24,-12,-8,-6]
```前缀和后缀方法可以正常工作，因为乘法顺序和符号处理在整个两次传递过程中在数学上保持一致。 

最终的边缘情况是最小有效输入大小`2`。 由于只有两个元素，每个答案只是另一个元素。 该算法仍然可以正常工作，因为前缀和后缀传递自然会产生所需的产品，而不需要任何特殊处理。
