[LeetCode 第 237 题](https://leetcode.com/problems/delete-node-in-a-linked-list/)

 **难度：** 🟡 中等
 **主题：** 链接列表

 ## 解决方案

 ## 问题理解

 这个问题要求我们从单链表中删除一个节点，但有一个不寻常的限制：我们无权访问链表的头部。 相反，我们只获得了对应该删除的节点的引用。 

在正常的链表删除操作中，我们将遍历链表，直到找到目标节点之前的节点。 然后我们会更新它`next`跳过目标节点的指针。 然而，这种方法在这里是不可能的，因为我们无法访问列表的头部，因此无法找到前一个节点。 

输入包括：

 - 单链表。 
- 对该列表内节点的直接引用。 
- 保证给定的节点不是最后一个节点。 

预期的结果是节点的值从链表中消失，链表大小减一，并且所有剩余节点的顺序保持不变。 

例如：```
4 -> 5 -> 1 -> 9
```如果给定节点是包含`5`，最终列表应变为：```
4 -> 1 -> 9
```这些约束提供了几个重要的保证：

 - 该列表始终包含至少两个节点。 
- 要删除的节点始终有效并存在于列表中。 
- 要删除的节点永远不是尾节点。 
- 所有值都是唯一的。 

保证该节点不是尾节点是极其重要的。 由于我们无法访问前一个节点，因此唯一可行的策略取决于是否有可用的下一个节点。 

简单的实现可能会尝试从内存中物理删除当前节点，但如果不知道前一个节点，这是不可能的。 另一个常见的错误是忘记列表是单向链接的，这意味着我们无法向后遍历。 

关键的见解是我们实际上不需要删除当前节点本身。 相反，我们可以将当前节点转换为其后继节点，然后绕过后继节点。 

## 方法

 ### 蛮力方法

 传统的链表删除策略是从链表头开始，遍历直到到达目标节点的前一个节点，然后重新连接指针，从而跳过目标节点。 

例如：```
prev -> target -> next
```变成：```
prev -> next
```这是正确的，因为从单链表中删除一个节点基本上需要修改前一个节点的`next`指针。 

然而，这种方法在这个问题中是不可能的，因为我们没有获得对头节点的访问权限。 没有头，我们就无法遍历链表，也无法定位前一个节点。 

如果我们能够以某种方式访问​​头部，则强力遍历将需要线性时间。 

### 最佳方法

 关键的观察是，虽然我们无法删除当前节点本身，但我们可以用下一个节点的内容覆盖其内容。 

假设列表是：```
4 -> 5 -> 1 -> 9
```和`node`指向`5`。 

我们可以：

 1. 复制下一个节点的值（`1`) 进入当前节点。 
2. 重定向当前节点的`next`跳过下一个节点的指针。 

复制后：```
4 -> 1 -> 1 -> 9
```绕过下一个节点后：```
4 -> 1 -> 9
```实际上，具有价值的原始节点`5`从列表中消失。 

这是可行的，因为问题只关心最终的链表结构和值，而不是节点对象的实际内存标识。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(1) | O(1) | 需要访问头部，但在给定的限制下不可能 |
 | 最佳| O(1) | O(1) | O(1) | O(1) | 复制下一个节点数据并绕过下一个节点 |

 ## 算法演练

 1.使用访问下一个节点`node.next`。 

由于该问题保证给定节点不是尾节点，因此下一个节点始终存在。 
2. 将下一个节点的值复制到当前节点。 

这使得当前节点看起来与下一个节点相同。 
3.更新当前节点的`next`指针。 

放：```
node.next = node.next.next
```这会跳过原始的下一个节点，从而有效地将其从链表中删除。 
4. 链表现在的行为就像原始节点已被删除一样。 

即使原来的节点对象仍然存在于内存中，但其原来的值已经不存在于链表中，这就满足了问题要求。 

### 为什么它有效

 该算法之所以有效，是因为单链表中的每个节点都由两件事定义：

 - 其储值
 - 指向下一个节点的指针

 通过将下一个节点的值和指针复制到当前节点，我们使当前节点与其后继节点无法区分。 然后，通过绕过后继者，我们有效地将其从列表中删除。 由于原始值消失并且剩余顺序保持不变，因此删除在逻辑上是正确的。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, x):
#         self.val = x
#         self.next = None

from typing import Optional

class Solution:
    def deleteNode(self, node: "ListNode") -> None:
        """
        :type node: ListNode
        :rtype: void
        """

        node.val = node.next.val
        node.next = node.next.next
```实现故意非常短，因为整个技巧依赖于问题的特殊约束。 

第一行将下一个节点的值复制到当前节点。 完成此分配后，当前节点现在包含后继节点的值。```python
node.val = node.next.val
```第二行完全跳过下一个节点。```python
node.next = node.next.next
```这将从链接结构中删除后继者。 由于当前节点已经复制了后继节点的值，因此最终列表看起来就像原始节点已被删除一样。 

该算法就地修改列表并且不返回任何内容，以满足问题要求。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func deleteNode(node *ListNode) {
    node.Val = node.Next.Val
    node.Next = node.Next.Next
}
```Go 实现遵循与 Python 解决方案完全相同的逻辑。 

由于问题保证了`node.Next`始终存在，不需要进行 nil 检查。 该解决方案只是复制下一个节点的值并绕过下一个节点。 

与某些链表问题不同，这里不存在整数溢出、切片或动态数组的问题。 该解决方案仅操作指针。

 ## 边缘情况

 ### 删除最小有效列表中的节点

 允许的最小链表仅包含两个节点。 例如：```
1 -> 2
```删除第一个节点可能会暴露假设存在更长列表的实现中的错误。 该解决方案可以正确处理此问题，因为第一个节点只是复制第二个节点的值并绕过它，留下有效的单节点列表。 

### 删除尾部之前的节点

 考虑：```
7 -> 8 -> 9 -> 10
```正在删除`9`表示下一个节点是尾部。 一些不正确的实现可能会意外丢失尾部引用或创建循环。 此实现安全地复制`10`进入`9`节点，然后设置`next`到`None`，保留正确的列表终止。 

### 尝试删除尾节点

 这是最重要的概念边缘情况。 如果该节点是尾部，则不会有下一个节点可供复制。 该算法会失败，因为：```
node.next
```会是`None`。 

该问题明确保证这种情况永远不会发生，这就是恒定时间解决方案完全可能的原因。
