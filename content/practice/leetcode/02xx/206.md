 ## 解决方案

 ## 问题理解

 该问题要求我们反转单链表。 单链表是一个节点序列，其中每个节点存储一个值和一个指向序列中下一个节点的指针。 输入，`head`, 表示链表的第一个节点。 我们的任务是重新排列节点之间的连接，使列表的方向完全颠倒。 

例如，如果原始列表是：```
1 -> 2 -> 3 -> 4 -> 5
```反转后应该变成：```
5 -> 4 -> 3 -> 2 -> 1
```重要的细节是我们不会创建新的值列表。 相反，我们正在修改`next`现有节点的指针，以便每个链接都指向相反的方向。 

约束告诉我们列表可以包含以下任意位置`0`到`5000`节点。 这意味着列表可能为空，可能仅包含一个节点，也可能包含数千个节点。 由于输入大小相对适中，迭代和递归方法都是可行的。 然而，递归引入了额外的调用堆栈使用，因此迭代方法通常更节省空间。 

一些边缘情况很重要：

 - 列表可能为空（`head = None`）
 - 列表可能只包含一个节点
 - 列表可能包含两个节点，这是最小的非平凡反转
 - 实现必须正确地重新连接指针，而不会失去对其余节点的访问

 如果在保存下一个节点引用之前覆盖指针，则简单的实现很容易破坏列表。 

## 方法

 一种暴力方法是将所有节点值提取到一个数组中，反转该数组，然后重建链表或以相反的顺序覆盖节点值。 这是可行的，因为数组允许直接索引访问，使反转变得简单。 然而，这种方法使用与列表大小成比例的额外内存，这是不必要的，因为问题只需要指针操作。 

更优化的方法认识到反转链表只需要改变每个链表的方向`next`指针。 在遍历过程中的任何时刻，我们只需要知道三件事：

 - 当前正在处理的节点
 - 前一个节点，它应该成为新的`next`- 下一个节点，这样我们就不会失去对列表其余部分的访问

 通过仔细地按顺序更新这些指针，我们可以使用恒定的额外空间在一次传递中反转列表。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 将节点值或节点存储在数组中，然后重建或覆盖 |
 | 最佳| O(n) | O(1) | O(1) | 遍历期间就地反转指针 |

 ## 算法演练

 ### 迭代反转算法

 1.初始化两个指针，`previous`和`current`。`previous`开始为`None`因为反转列表的新尾部应该指向任何内容。`current`从原始头部开始，因为我们从列表的前面开始处理。 
2. 遍历链表 while`current`不是`None`。 

这个循环确保每个节点都被访问一次。 
3. 在修改指针之前保存下一个节点。 

既然我们即将改变`current.next`，我们必须首先将原来的下一个节点存储在一个临时变量中，通常称为`next_node`。 否则，我们将无法访问列表的其余部分。 
4. 反转指针方向。 

放：```
current.next = previous
```这改变了链接的方向，因此当前节点现在指向向后而不是向前。 
5. 向前移动两个指针。 

反转连接后：

 - 移动`previous`到`current`- 移动`current`到`next_node`这会推进遍历，同时保留列表的反转部分。 
6. 继续，直到处理完所有节点。 

什么时候`current`变成`None`，遍历完成并且`previous`指向反转列表的新头。 
7. 返回`previous`。 

自从`previous`结束于最后处理的节点，它代表反转列表的头。 

### 为什么它有效

 关键的不变量是在每次迭代之前：

 -`previous`指向列表中正确反转的部分
 -`current`指向下一个仍需要处理的节点

 每次迭代都会从未反转部分中删除一个节点，并将其附加到反转部分的前面。 由于每个节点只被处理一次，因此整个列表在遍历结束时会发生反转。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

from typing import Optional

class Solution:
    def reverseList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        previous = None
        current = head
        
        while current:
            next_node = current.next
            current.next = previous
            
            previous = current
            current = next_node
        
        return previous
```该实现直接遵循前面描述的迭代算法。 

变量`previous`跟踪列表中已反转部分的头部。 最初，它是`None`因为反转的列表是空的。 

变量`current`逐个节点遍历原始链表。 在每次迭代期间，算法首先保存`current.next`进入`next_node`。 这一步很关键，因为下一个指针即将被覆盖。 

该行：```python
current.next = previous
```反转指针的方向。 

反向链接后，两个遍历指针都向前移动。`previous`扩展反向列表，同时`current`前进到下一个未处理的节点。 

当遍历结束时，`previous`指向反转列表的新头，因此返回。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func reverseList(head *ListNode) *ListNode {
    var previous *ListNode = nil
    current := head

    for current != nil {
        nextNode := current.Next
        current.Next = previous

        previous = current
        current = nextNode
    }

    return previous
}
```Go 实现在逻辑和结构上与 Python 版本几乎相同。 

Go 使用`nil`而不是Python的`None`。 指针操作是显式的，因为链表节点是通过以下方式引用的`*ListNode`。 

不需要对整数溢出进行特殊处理，因为该算法仅操作指针，而不操作算术值。 

迭代结构保持不变：

 - 保存下一个节点
 - 反转指针
 - 高级遍历指针

 ## 边缘情况

 ### 空列表

 空列表意味着`head`是`None`。 这种情况很重要，因为尝试访问`head.next`不检查可能会导致运行时错误。 

该实现自然地处理这个问题，因为循环条件：```
while current:
```立即失败，当`current`是`None`。 然后函数返回`previous`，这也是`None`。 

### 单节点列表

 根据定义，仅包含一个节点的列表已被反转。 一些不正确的实现会在指针操作期间意外断开节点或创建循环。 

在这个实现中，单个节点的`next`指针被重新分配给`None`，它已经是了。 然后遍历正确终止并返回原始节点。 

### 丢失剩余列表

 链表反转中最常见的错误之一是覆盖`current.next`在保存对其余节点的引用之前。 

例如，这样做是错误的：```
current.next = previous
current = current.next
```将无法访问列表中未反转的部分。 

该实现通过首先存储来避免这种情况：```
next_node = current.next
```在更改任何指针之前。 这保证了反转后遍历可以安全地继续。
