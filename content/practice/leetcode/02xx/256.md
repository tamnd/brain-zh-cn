[LeetCode 第 256 题](https://leetcode.com/problems/paint-house/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划

 ## 解决方案

 ## 问题理解

 该问题给了我们一排房子，其中每栋房子都必须使用三种颜色中的一种进行涂漆：红色、蓝色或绿色。 输入以二维数组形式提供，名为`costs`， 在哪里`costs[i][j]`代表了油漆的成本`i-th`房子与`j-th`颜色。 

目标是粉刷每栋房子，同时满足一个重要的限制：相邻的两栋房子不能有相同的颜色。 在所有有效的绘画组合中，我们必须返回尽可能小的总成本。 

例如，如果房子`0`被漆成蓝色，然后是房子`1`也不能涂成蓝色。 此限制仅适用于相邻的房屋，不适用于相距较远的房屋。 

限制相对较小：

 - 最多有`100`房屋。 
- 每幅画的费用介于`1`和`20`。 
- 每所房子总是有三种颜色选择。 

尽管约束不是很大，但天真的暴力方法仍然会变得低效，因为每个房子都会引入三个分支选择。 这自然建议采用动态规划解决方案，因为一栋房子的最佳决策仅取决于前一栋房子。 

应考虑几个重要的边缘情况：

 - 一座独立屋，答案就是三项油漆费用中的最低费用。 
- 多个房屋中，一种颜色反复出现最便宜，但由于邻近限制而不能总是被选择。 
- 不同颜色的成本相等的输入，要求算法正确处理平局。 
- 非常小的数组，可能会暴露索引错误或不正确的初始化。 

该问题保证输入矩阵有效并且始终包含三列，因此我们不需要处理格式错误的输入。 

## 方法

 ### 暴力方法

 一个简单的解决方案是尝试所有可能的有效颜色组合。 

对于每栋房子，我们选择三种颜色中的一种，同时确保它与之前房子的颜色不同。 我们递归地探索每种有效的可能性，并计算每个完整绘画布置的总成本。 所有有效安排中的最小值就是答案。 

这种方法是正确的，因为它详尽地检查了每个有效的着色配置。 然而，它的效率很低，因为每个房子都会引入多个分支选择。 在最坏的情况下，组合总数呈指数增长。 

更具体地说，第一栋房子有`3`选择，随后的每个房子都有大约`2`有效的选择，因为它无法匹配以前的颜色。 这大约产生`3 × 2^(n-1)`组合。 

虽然`n <= 100`并不是巨大的，指数增长很快就变得不切实际。 

### 动态规划洞察

 关键的观察是，在决定如何粉刷当前房屋时，我们只关心用不同颜色粉刷以前的房屋的最低成本。 

假设我们要粉刷房子`i`红色的。 那么以前的房子一定是被漆成蓝色或绿色的。 因此：

 - 将当前房屋漆成红色的成本=

 当前红色成本+

 最小值（之前的蓝色总计，之前的绿色总计）

 同样的逻辑也适用于蓝色和绿色。 

该结构揭示了重叠的子问题：

 - 最低成本可达房屋`i`仅取决于住房的最低成本`i-1`。 

我们不会重复重新计算这些值，而是存储它们并逐步构建答案。 

这将解决方案从指数时间转换为线性时间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 递归探索所有有效的颜色分配 |
 | 最优动态规划| O(n) | O(1) | O(1) | 跟踪每种颜色的最低累积成本 |

 ## 算法演练

 1. 初始化三个变量，代表将以前的房子涂成红色、蓝色和绿色的最小累积成本。 

对于第一栋房子，这些价值只是油漆费用`costs[0]`。 
2. 逐一迭代剩余的房屋。 

对于每栋房子，计算三个新值：

 - 当前房屋漆成红色时的最低总成本。 
- 当前房屋漆成蓝色时的最低总成本。 
- 当前房屋漆成绿色时的最低总成本。 
3. 计算一种颜色的成本时，将当前绘画成本添加到之前其他两种颜色中的最小值。 

例如：

 - 当前红色成本 =

 当前红色涂装成本+

 最小值（之前的蓝色总计，之前的绿色总计）

 这强制执行了相邻房屋不能共享相同颜色的规则。 
4. 计算出新的总计后，用新计算的值替换以前的值。 

此时，变量代表当前房屋的最优累积成本。 
5. 继续此过程，直到处理完所有房屋。 
6. 在最终的房子之后，返回三个累积颜色总数中的最小值。 

这是粉刷所有房屋最便宜的有效方法。 

### 为什么它有效

 该算法保持了处理后的不变量`i`，每个存储值代表粉刷房屋的最小可能总成本`0`通过`i`, 有房子`i`涂上特定的颜色。 

因为每个转换只允许不同的相邻颜色，所以所有生成的状态仍然有效。 由于每个状态总是选择最小有效的先前配置，因此最终答案是全局最优的。 

## Python 解决方案```python
from typing import List

class Solution:
    def minCost(self, costs: List[List[int]]) -> int:
        if not costs:
            return 0

        red, blue, green = costs[0]

        for i in range(1, len(costs)):
            current_red = costs[i][0] + min(blue, green)
            current_blue = costs[i][1] + min(red, green)
            current_green = costs[i][2] + min(red, blue)

            red = current_red
            blue = current_blue
            green = current_green

        return min(red, blue, green)
```实现首先处理输入为空的边缘情况。 尽管限制条件保证了至少一所房屋，但防御性处理使功能更加强大。 

变量`red`,`blue`， 和`green`存储前一栋房子的最低累计成本。 

对于每个后续房屋，该算法计算三个新的总数：

 - 如果当前的房子被漆成红色，则之前的房子一定是蓝色或绿色的。 
- 如果当前的房子被漆成蓝色，则之前的房子一定是红色或绿色的。 
- 如果当前的房子被漆成绿色，则之前的房子一定是红色或蓝色。 

然后就地更新变量，这允许算法使用恒定的额外空间。 

最后，返回三个总数中最小的一个，因为最后一个房子可能以任何有效颜色结束。 

## 解决方案```go
func minCost(costs [][]int) int {
    if len(costs) == 0 {
        return 0
    }

    red := costs[0][0]
    blue := costs[0][1]
    green := costs[0][2]

    for i := 1; i < len(costs); i++ {
        currentRed := costs[i][0] + min(blue, green)
        currentBlue := costs[i][1] + min(red, green)
        currentGreen := costs[i][2] + min(red, blue)

        red = currentRed
        blue = currentBlue
        green = currentGreen
    }

    return min(red, min(blue, green))
}

func min(a int, b int) int {
    if a < b {
        return a
    }

    return b
}
```Go 实现遵循与 Python 版本相同的动态编程逻辑。 由于 Go 没有提供内置的`min`对于整数函数，定义了一个辅助函数。 

Go 切片自然地用于二维输入数组。 整数溢出不是问题，因为最大可能的成本非常小：

 - 每栋房屋的最高成本 =`20`- 最多房屋 =`100`- 最大总数=`2000`这完全符合 Go 的整数范围。

 ## 边缘情况

 ### 独栋别墅

 当只有一所房屋时，不存在邻接约束，因为没有相邻的房屋。 正确答案就是三项涂装成本中最小的一个。 

这种情况可能会暴露不正确的循环初始化或相差一错误。 该实现自然地处理它，因为循环从索引处开始`1`，因此不会发生迭代。 

### 重复最便宜的颜色

 一个常见的错误是贪婪地为每栋房子单独选择最便宜的颜色。 当相邻的房屋最终共享相同的颜色时，这种方法就会失败。 

例如：```
[[1,100,100],
 [1,100,100]]
```贪婪的方法可能会错误地选择红色两次。 动态编程解决方案避免了这种情况，因为每个状态转换都明确排除相同的先前颜色。 

### 不同颜色的成本相同

 当所有涂装成本相等时，存在多个最优解。 

例如：```
[[1,1,1],
 [1,1,1]]
```该算法在计算最小总成本时仍必须正确执行邻接约束。 

由于该解决方案始终仅使用有效的先前颜色来计算过渡，因此可以自然且正确地处理联系。 

### 空输入

 尽管官方的限制保证至少有一栋房子，但稳健的实现通常会防御性地处理空输入。 

返回`0`空数组可以防止运行时错误，并使函数在非 LeetCode 环境中更安全。
