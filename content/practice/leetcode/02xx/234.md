 ## 解决方案

 ## 问题理解

 该问题给了我们一个单链表的头，并询问存储在列表中的值序列是否形成回文。 

回文是向前和向后读取相同的序列。 例如，数组`[1,2,2,1]`是回文，因为反转它会产生相同的序列。 另一方面，`[1,2]`不是回文，因为向前和向后的顺序不同。 

输入是一个单链表，这意味着每个节点都包含一个值和一个指向下一个节点的指针。 与数组不同，链表不支持直接索引，因此我们无法轻松地同时比较两端的元素，除非使用额外的技术。 

预期输出是：

 -`true`如果链表值形成回文
 -`false`否则

 约束条件很重要：

 - 该列表包含之间`1`和`10^5`节点
 - 每个节点值都在`0`和`9`大的上限意味着我们应该避免不必要的昂贵操作。 一个`O(n^2)`对于大量输入来说，方法可能会变得太慢。 后续问题具体询问我们能否解决这个问题`O(n)`时间和`O(1)`额外的空间，这强烈表明预期的解决方案应该避免与输入大小成比例的辅助数据结构。 

一些边缘情况很重要：

 - 单节点列表始终是回文
 - 二节点列表可能是也可能不是回文
 - 奇数长度列表有一个不需要比较的中间元素
 - Even-length lists split evenly into two comparable halves
 - 由于列表是单向链接的，因此如果不反转部分结构或使用额外的内存，就不可能向后遍历

 理解如何有效地比较列表的前半部分和后半部分是这个问题的关键挑战。 

## 方法

 ### 蛮力方法

 The most straightforward solution is to copy all linked list values into an array. 一旦值存储在数组中，检查序列是否是回文就变得很简单，因为数组支持随机访问。 

我们遍历链表一次，将每个节点值追加到列表中，然后使用两个指针：

 - 一个指针从头开始
 - 另一个从最后开始

 我们一边向内走，一边反复比较价值观。 如果所有对应值都匹配，则该序列是回文。 

This approach is correct because the array preserves the exact order of the linked list values. 比较镜像位置直接验证序列向前和向后读取是否相同。 

然而，这种方法使用`O(n)`额外的空间，因为我们单独存储每个节点值。 后续明确询问我们是否可以做得更好。 

### 最佳方法

 关键的见解是我们实际上不需要存储整个列表。 相反，我们可以只反转链表的后半部分。 

该算法的工作原理如下：

 - 使用快指针和慢指针来查找列表的中间位置
 - Reverse the second half of the linked list
 - 逐个节点比较前半部分和反转的后半部分
 - If all values match, the list is a palindrome

 This works because reversing the second half allows us to traverse both halves in the same direction while comparing mirrored elements.

 快慢指针技术特别有用，因为：

 - 慢速指针一次前进一步
 - The fast pointer advances two steps at a time
 - 当快指针到达末尾时，慢指针在中间

 这给了我们一个`O(n)`时间解仅`O(1)`额外的空间，因为反转是就地完成的。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 将值复制到数组中并从两端进行比较 |
 | 最佳| O(n) | O(1) | O(1) | 就地反转链表的后半部分 |

 ## 算法演练

 1.初始化两个指针，`slow`和`fast`，都从列表的头部开始。 

这些指针的目的是有效地定位中间点。 这`slow`指针一次移动一个节点，而`fast`指针一次移动两个节点。 
2. 移动指针直到`fast`到达终点。 

At the end of this process:

- If the list length is odd,`slow`落在中间节点
 - 如果列表长度是偶数，`slow`下半场开始时落地

 这是有效的，因为快速指针移动距离的速度是原来的两倍。 
3. 反转链表的后半部分，从`slow`。 

反向遍历是必要的，因为单链表只允许向前遍历。 通过反转后半部分，我们可以顺序比较镜像元素。 

反转期间：

 - 维护`prev`,`current`， 和`next_node`- 重定向每个节点的`next`指针向后
 - 继续直到整个一半都反转
 4. 比较上半场和反转的下半场。 

使用两个指针：

 - 从原来的头部开始
 - 从相反半场的头部开始

 一一比较节点值。 

如果任何对不同，则返回`False`立即地。 
5. 如果所有比较都成功，则返回`True`。 

每个镜像对都匹配，因此链表是回文。 

### 为什么它有效

 该算法之所以有效，是因为反转后半部分将回文比较转换为同步前向遍历。 

对于回文：

 - 第一个节点必须等于最后一个节点
 - 第二个节点必须等于倒数第二个节点
 - 等等

 反转后半部分会将这些镜像节点置于相同的遍历方向，从而允许在线性时间内进行直接比较。 由于每个节点仅被访问固定次数，因此该算法保持高效。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

from typing import Optional

class Solution:
    def isPalindrome(self, head: Optional[ListNode]) -> bool:
        slow = head
        fast = head

        # Find the middle of the list
        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next

        # Reverse the second half
        prev = None
        current = slow

        while current:
            next_node = current.next
            current.next = prev
            prev = current
            current = next_node

        # Compare both halves
        left = head
        right = prev

        while right:
            if left.val != right.val:
                return False

            left = left.next
            right = right.next

        return True
```实现首先使用快慢指针技术定位中点。 这避免了需要单独计算长度。 

接下来，代码将后半部分反转。 这`prev`指针跟踪已经反转的部分，而`current`迭代剩余的节点。 每个节点的`next`指针向后重定向。 

After reversal, the list is effectively split into two forward-traversable halves:

 - 原来的前半部分
 - 下半场逆转

 The final comparison loop walks through both halves simultaneously. Since the reversed second half represents the mirrored order of the original list, matching values confirm the palindrome property.

 The comparison loop only needs to iterate through the second half because its length is never greater than the first half.

 ## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func isPalindrome(head *ListNode) bool {
    slow := head
    fast := head

    // Find middle
    for fast != nil && fast.Next != nil {
        slow = slow.Next
        fast = fast.Next.Next
    }

    // Reverse second half
    var prev *ListNode
    current := slow

    for current != nil {
        nextNode := current.Next
        current.Next = prev
        prev = current
        current = nextNode
    }

    // Compare halves
    left := head
    right := prev

    for right != nil {
        if left.Val != right.Val {
            return false
        }

        left = left.Next
        right = right.Next
    }

    return true
}
```Go 实现遵循与 Python 版本完全相同的算法结构。 

主要的语言特定差异是指针处理。 Go 使用显式`nil`检查和指针类型，例如`*ListNode`。 Go 中的变量声明也更加明确，尤其是反转期间的指针初始化。 

由于节点值是小整数，因此两种语言都不需要考虑整数溢出。

 ## 边缘情况

 ### 单节点列表

 仅包含一个节点的链表始终是回文，因为向前和向后读取它会产生相同的序列。 

如果实现假设存在多个节点，这种情况有时会导致与指针相关的错误。 在这个方案中，快慢指针循环立即退出，比较阶段自然成功。 

### 奇数长度列表

 奇数长度回文包含一个中间元素，没有镜像对应项。 例如：```
1 -> 2 -> 3 -> 2 -> 1
```价值`3`中间不需要比较。 

一个常见的错误是错误地处理中点，导致比较不一致。 此实现避免了该问题，因为反转开始于`slow`，比较循环只遍历相反的后半部分。 

### 偶数长度列表

 偶数长度列表干净地分成相等的两半：```
1 -> 2 -> 2 -> 1
```没有单个中间节点。 

不正确的中点计算很容易跳过节点或比较不匹配的对。 快慢指针策略正确定位`slow`下半场开始时，确保适当的逆转和比较。 

### 早期不匹配的非回文

 列表例如：```
1 -> 2
```一旦检测到不匹配，应立即终止。 

执行立即返回`False`在比较过程中进行比较，而不是继续进行不必要的遍历，这样在保持正确性的同时提高了效率。
