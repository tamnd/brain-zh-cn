[LeetCode 第 286 题](https://leetcode.com/problems/walls-and-gates/)

 **难度：** 🟡 中等
 **主题：** 数组、广度优先搜索、矩阵

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个二维网格，称为`rooms`，其中每个单元代表三种可能状态之一。 

值为`-1`代表无法穿过的墙壁或障碍物。 

值为`0`代表一个门。 

值为`2147483647`，这被称为`INF`，表示一个空房间，其到最近的门的距离尚未确定。 

任务是修改适当的网格，以便每个空房间都包含到其最近的门的距离。 距离是使用标准网格移动规则来测量的，这意味着我们可以在四个基本方向上一次移动一步：上、下、左、右。 

如果一个房间因为墙壁阻挡了所有可能的路径而无法到达任何门，则它必须保留`INF`。 

重要的细节是网格必须就地更新。 我们不应该返回一个新的矩阵。 

限制因素很重要：

 -`m`和`n`每个都可以大到`250`- 因此网格可能包含最多`62,500`细胞

 这个大小立即表明昂贵的重复遍历可能会变得太慢。 任何解决方案明显比`O(m * n)`在最坏的情况下可能会陷入困境。 

一些边缘情况很重要：

 - 网格可能根本不包含门，在这种情况下，每个空房间都会留下`INF`- 网格可能只包含墙
 - 网格可能包含完全被墙壁隔离的房间
 - 可能存在多个门，一个房间必须选择所有可到达的门中距离最短的一个
 - 网格可以小到`1 x 1`核心挑战是有效地找到从每个房间到最近的大门的最短距离，而无需重复重新计算路径。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是独立处理每个空房间。 

对于每个包含`INF`，我们可以运行广度优先搜索来定位最近的门。 由于 BFS 自然会逐层探索位置，因此遇到的第一个门将给出最短距离。 

这种方法是正确的，因为 BFS 保证了未加权网格中的最短路径距离。 

然而，问题是效率。 

假设有`k`空荡荡的房间。 对于每个房间，我们最终可能会遍历大部分网格。 在最坏的情况下：

 - 有`O(m * n)`空房间
 - 每个BFS花费`O(m * n)`这导致总的复杂性：```
O((m * n)^2)
```高达`62,500`细胞，这变得太昂贵了。 

### 最佳方法

 关键的观察是问题是可以逆转的。 

我们可以从所有的门同时启动 BFS 并向外扩展，而不是从每个空房间启动 BFS 并搜索门。 

这是可行的，因为 BFS 按距离递增的顺序探索位置。 

当在此多源 BFS 期间首次到达房间时，我们知道：

 - 已通过最近的登机口到达
 - 当前BFS层代表最短距离

 这将问题转化为网格的单次遍历。 

这个想法被称为多源 BFS，因为多个起点（所有门）最初都会插入队列中。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O((m * n)^2) | O((m * n)^2) | O(m * n) | 从每个空房间单独运行 BFS |
 | 最佳| O(m * n) | O(m * n) | 同时从所有门开始的多源 BFS |

 ## 算法演练

 1. 初始化一个队列，用于BFS遍历。 

BFS 是正确的选择，因为所有移动的成本相同。 BFS 保证我们第一次到达房间时，就找到了最短的距离。 
2. 扫描整个网格并将每个门添加到队列中。 

每个细胞都含有`0`成为 BFS 的起点。 这是关键的优化。 我们没有从房间里寻找大门，而是立即从所有大门向外扩散。 
3. 处理队列直至其变空。 

每个队列条目代表一个单元，其最短距离已知。 
4. 对于当前单元格，检查其四个相邻位置。 

四个有效方向是：

 - 向上
 - 向下
 - 左
 - 右
 5. 跳过无效的邻居。 

如果出现以下情况，则应忽略邻居：

 - 它在网格边界之外
 - 这是一堵墙
 - 它已经被分配了一个距离

 我们只想访问仍然等于的单元格`INF`。 
6.更新可到达的空房间。 

如果相邻小区是`INF`， 分配：```
rooms[next_row][next_col] = rooms[current_row][current_col] + 1
```这是有效的，因为当前单元已经存储了到门的最短距离。 
7. 将更新的房间添加到队列中。 

这使得BFS能够逐级继续向外扩展。 
8. 继续，直到处理完所有可到达的房间。 

任何从未到达的房间仍然存在`INF`，它正确地指示不存在通往门的路径。 

### 为什么它有效

 BFS 按照距起点距离递增的顺序探索单元格。 由于所有门最初都插入队列中，因此搜索同时从每个门均匀向外扩展。 

第一次访问某个房间时，保证从最近的大门通过最短的路径到达该房间。 任何替代路径都将具有相同或更大的长度，因此稍后将按 BFS 顺序进行处理。 

这个不变量保证了正确性。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def wallsAndGates(self, rooms: List[List[int]]) -> None:
        """
        Do not return anything, modify rooms in-place instead.
        """
        
        if not rooms or not rooms[0]:
            return
        
        rows = len(rooms)
        cols = len(rooms[0])
        
        queue = deque()
        
        # Add all gates to the queue
        for row in range(rows):
            for col in range(cols):
                if rooms[row][col] == 0:
                    queue.append((row, col))
        
        directions = [
            (1, 0),
            (-1, 0),
            (0, 1),
            (0, -1)
        ]
        
        # Multi-source BFS
        while queue:
            row, col = queue.popleft()
            
            for dr, dc in directions:
                next_row = row + dr
                next_col = col + dc
                
                # Skip invalid positions
                if (
                    next_row < 0
                    or next_row >= rows
                    or next_col < 0
                    or next_col >= cols
                ):
                    continue
                
                # Only process empty rooms
                if rooms[next_row][next_col] != 2147483647:
                    continue
                
                # Update distance
                rooms[next_row][next_col] = rooms[row][col] + 1
                
                # Continue BFS
                queue.append((next_row, next_col))
```该实现首先处理空网格的边缘情况。 

接下来，我们计算网格尺寸并使用创建队列`deque`，这提供了高效的`O(1)`从两端插入和删除。 

第一个嵌套循环扫描矩阵并将每个门插入队列中。 这将建立多源 BFS 设置。 

这`directions`列表集中了移动逻辑，因此邻居遍历保持简洁且可维护。 

在 BFS 循环内，我们从队列中删除一个单元并检查所有四个相邻单元。 

边界检查确保我们不会访问无效索引。 

我们只处理仍然等于的单元格`2147483647`。 此条件有两个目的：

 - 它识别未访问的空房间
 - 它可以防止重新访问已分配最短距离的单元格

 当找到有效房间时，我们将其距离指定为当前单元格的距离加一。 由于BFS逐级扩展，这就保证了最短路径。 

最后，更新的房间被推入队列，以便稍后可以探索其邻居。 

## 解决方案```go
func wallsAndGates(rooms [][]int) {
    if len(rooms) == 0 || len(rooms[0]) == 0 {
        return
    }

    rows := len(rooms)
    cols := len(rooms[0])

    type Cell struct {
        row int
        col int
    }

    queue := []Cell{}

    // Add all gates to the queue
    for r := 0; r < rows; r++ {
        for c := 0; c < cols; c++ {
            if rooms[r][c] == 0 {
                queue = append(queue, Cell{r, c})
            }
        }
    }

    directions := [][]int{
        {1, 0},
        {-1, 0},
        {0, 1},
        {0, -1},
    }

    front := 0

    // Multi-source BFS
    for front < len(queue) {
        current := queue[front]
        front++

        for _, dir := range directions {
            nextRow := current.row + dir[0]
            nextCol := current.col + dir[1]

            // Boundary check
            if nextRow < 0 ||
                nextRow >= rows ||
                nextCol < 0 ||
                nextCol >= cols {
                continue
            }

            // Only process empty rooms
            if rooms[nextRow][nextCol] != 2147483647 {
                continue
            }

            // Update distance
            rooms[nextRow][nextCol] = rooms[current.row][current.col] + 1

            // Continue BFS
            queue = append(queue, Cell{nextRow, nextCol})
        }
    }
}
```Go 实现遵循与 Python 版本相同的算法结构。 

一个显着的区别是队列管理。 该实现没有使用专用的双端队列结构，而是使用带有`front`指针。 这避免了昂贵的切片移位操作。 

Go 不提供元组，所以一个小`Cell`struct 用于存储坐标。 

该方案直接修改输入矩阵，就像Python版本一样。 

因为该问题保证距离小于`2147483647`，添加`1`在 BFS 期间不能在有效输入下溢出。

 ## 边缘情况

 ### 网格中没有门

 如果矩阵不包含门，则 BFS 队列开始为空。 由于对队列内容的假设，幼稚的实现可能会错误地修改房间或崩溃。 

这个实现自然地处理了这种情况。 由于没有门插入队列中，因此 BFS 循环永远不会执行，并且所有空房间仍然存在`INF`。 

### 房间完全被墙壁挡住

 有些房间可能被墙壁包围，因此无法到达任何大门。 

有缺陷的解决方案可能会意外地通过无效路径分配距离或覆盖无法到达的房间。 

此实现仅通过有效的 BFS 遍历来传播距离。 由于永远无法到达被封锁的房间，因此它们正确地保留在`INF`。 

### 多个门争夺同一个房间

 一个房间可以从多个不同距离的门到达。 

简单的重复搜索解决方案可能会多次重新计算距离，或者意外地用较长的距离覆盖较短的距离。 

多源 BFS 保证了正确性，因为 BFS 按距离递增的顺序探索单元。 第一次访问一个房间时，必须从最近的门通过最短的路径。 随后的较长路径将被忽略，因为房间不再`INF`。
