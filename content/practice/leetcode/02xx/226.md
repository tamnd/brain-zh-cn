[LeetCode 第 226 题](https://leetcode.com/problems/invert-binary-tree/)

 **难度：** 🟢简单
 **主题：** 树、深度优先搜索、广度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 该问题给出了二叉树的根节点，并要求我们反转该树。 反转二叉树意味着交换树中每个节点的左子节点和右子节点。 

例如，如果一个节点原来有：

 - 左孩子=`2`- 右孩子=`7`反转后变为：

 - 左孩子=`7`- 右孩子=`2`必须对树中的每个节点执行此操作，而不仅仅是根。 

输入表示为二叉树。 每个节点包含：

 - 整数值
 - 指向左孩子的指针/引用
 - 指向右子节点的指针/引用

 递归交换所有左子节点和右子节点后，输出应该是修改后的树的根。 

限制很小：

 - 树包含之间`0`和`100`节点。 
- 节点值范围为`-100`到`100`。 

由于树的大小很小，因此性能不是主要问题。 甚至一个`O(n)`遍历速度足够快。 重要的部分是正确地遍历每个节点一次并交换其子节点。 

一些边缘情况很重要：

 - 一棵空树（`root = []`）应该返回`None`或者`nil`。 
- 只有一个节点的树应该保持不变。 
- 高度不平衡的树，例如链表形状的树，必须仍然正常工作。 
- 递归解决方案必须处理`None`儿童指针安全。 

该问题保证输入是有效的二叉树，因此我们不需要验证树结构或处理循环。 

## 方法

 ### 蛮力方法

 思考这个问题的一种强力方法是创建一棵全新的树。 对于原始树中的每个节点，我们可以在新树中创建相应的节点，其中：

 - 新节点的左子节点是从原始节点的右子树构建的
 - 新节点的右子节点是从原始节点的左子树构建的

 这会产生原始树的完全反转的副本。 

这种方法是正确的，因为每个子树都是以其子树相反的方式重建的。 然而，它需要分配一个全新的树，这会使用不必要的额外内存。 由于该问题允许就地修改现有树，因此创建重复树效率低下。 

### 最佳方法

 关键的观察结果是反演纯粹是局部操作。 在每个节点，我们只需要交换两个指针：

 -`left`-`right`交换它们之后，我们递归地反转两个子树。 

由于每个节点都被访问一次并且每次交换都需要恒定的时间，因此该算法在线性时间内高效运行。 

这自然适合深度优先搜索遍历。 递归在这里特别干净，因为二叉树是递归定义的结构。 整棵树的反转取决于其左右子树的反转。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 构建一棵全新的倒置树 |
 | 最佳| O(n) | O(h) | 使用 DFS 递归交换子项 |

 这里：

-`n`是节点数
 -`h`是树的高度

 ## 算法演练

 ### 递归DFS算法

 1. 从根节点开始。 

根是树的入口点。 如果根是`None`，树是空的，所以我们立即返回`None`。 
2. 交换当前节点的左右子指针。 

这是核心反转步骤。 交换后：

 - 原来的左子树变成右子树
 - 原来的右子树变成左子树
 3. 递归地反转新的左子树。 

交换后，节点当前的左子节点原来是右子树。 我们递归地对其应用相同的反转过程。 
4. 递归地反转新的右子树。 

然后我们递归地处理另一个子树。 
5. 返回当前节点。 

一旦两个子树都反转，以当前节点为根的子树就完全反转。 

### 为什么它有效

 该算法之所以有效，是因为反转在每个节点都是独立的。 如果每个节点恰好交换其左子节点和右子节点一次，则整个树将成为镜像。 

递归不变量是：

 > 当`invertTree(node)`完成后，子树的根为`node`是完全颠倒的。 

基本情况正确处理空子树，递归调用确保每个子树都被完全处理。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

class Solution:
    def invertTree(self, root: Optional[TreeNode]) -> Optional[TreeNode]:
        if root is None:
            return None

        root.left, root.right = root.right, root.left

        self.invertTree(root.left)
        self.invertTree(root.right)

        return root
```实施从基本案例开始。 如果`root`是`None`，没有要反转的子树，因此函数立即返回。 

下一行执行实际的反转步骤：```python
root.left, root.right = root.right, root.left
```Python 元组赋值使得交换简洁且安全。 

交换后，该函数递归地处理两个子树。 因为子树已经被交换，所以递归调用对新定位的子树进行操作。 

最后返回根节点。 由于反转发生在适当的位置，因此返回相同的根引用就足够了。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func invertTree(root *TreeNode) *TreeNode {
    if root == nil {
        return nil
    }

    root.Left, root.Right = root.Right, root.Left

    invertTree(root.Left)
    invertTree(root.Right)

    return root
}
```Go 实现遵循与 Python 版本完全相同的递归逻辑。 

主要区别在于处理方式`nil`指针而不是Python的`None`。 Go 还对树节点使用显式结构指针。 

Go 中也支持元组赋值：```go
root.Left, root.Right = root.Right, root.Left
```这使得交换操作简洁并避免需要临时变量。 

因为节点数很少，所以递归深度不是这个问题的问题。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个节点都被访问一次 |
 | 空间| O(h) | 递归调用栈最多存储一条从根到叶的路径 |

 时间复杂度是线性的，因为每个节点仅执行恒定量的工作：

 - 一次交换
 - 两次递归调用

 空间复杂度取决于递归深度。 在平衡树中，高度为`O(log n)`。 在最坏的情况下，完全倾斜的树的高度`O(n)`。

 ## 边缘情况

 ### 空树

 一棵空树表示为`root = None`。 这是最简单的边缘情况，如果递归假设有效节点始终存在，则很容易错误处理。 

没有适当的基本情况，尝试访问`root.left`或者`root.right`会导致运行时错误。 

实现立即处理这个问题：```
if root is None:
    return None
```这也安全地终止了空子树的递归。 

### 单节点树

 一棵只有一个节点的树没有可以交换的子节点。 

有缺陷的实现可能会意外地错误地修改指针或不必要地递归。 

在此解决方案中，节点的子节点都是`None`，所以交换它们不会改变任何事情。 递归调用立即终止，因为两个子进程都是`None`。 

### 高度不平衡的树

 倾斜树的行为类似于链表：```
1
 \
  2
   \
    3
```这些情况很重要，因为递归深度等于树高。 

该算法仍然可以正常工作，因为每个节点独立地交换其子节点。 反转后，上面的树变成：```
    1
   /
  2
 /
3
```该实现自然会处理这个问题，因为递归遵循任何存在的子项。
