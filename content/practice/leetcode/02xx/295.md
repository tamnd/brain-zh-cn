[LeetCode 第 295 题](https://leetcode.com/problems/find-median-from-data-stream/)

 **难度：** 🔴难
 **主题：** 两个指针、设计、排序、堆（优先级队列）、数据流

 ## 解决方案

 ## 问题理解

 该问题要求我们设计一种数据结构，该结构可以连续地从流中接收整数，并且可以有效地返回迄今为止看到的所有数字的中位数。 

中位数定义为排序列表中的中间元素。 如果元素数量为奇数，则中位数是单个中间值。 如果元素个数为偶数，则中位数为中间两个值的平均值。 

例如：

 - 在`[2, 3, 4]`，中位数是`3`- 在`[2, 3]`，中位数是`(2 + 3) / 2 = 2.5`关键的挑战是数字是动态到达的。 我们没有预先获得整个数组。 相反，我们必须重复支持两个操作：

 -`addNum(num)`将新数字插入数据结构中
 -`findMedian()`返回任意时刻的当前中位数

 约束条件很重要：

 - 最多`5 * 10^4`操作可能会发生
 - 数字范围从`-10^5`到`10^5`这些限制立即排除了每次插入后重复对整个集合进行排序的低效方法。 虽然`50,000`运算量并不大，重复排序会产生不必要的开销。 

该问题保证了`findMedian()`永远不会在空结构上调用，因此我们不需要处理无效情况。 

一些边缘情况很重要：

 - 流可能包含负数
 - 重复值可能经常出现
 - 流可能会在大数字和小数字之间交替
 - 元素的数量可能会在奇数和偶数之间不断切换
 - 中位数可以是浮点值

 正确的实现必须在插入数字时有效地维护排序信息。 

## 方法

 ### 蛮力方法

 最直接的解决方案是将所有插入的数字存储在一个列表中。 每次`findMedian()`被调用后，我们对列表进行排序并计算中间值。 

这是有效的，因为排序可以保证中间元素的位置正确。 列表排序后：

 - 如果长度为奇数，则中位数为中心元素
 - 如果长度是偶数，中位数是中心两个元素的平均值

 然而，这种方法效率低下。 排序需要`O(n log n)`每次我们请求中位数的时间。 自从`findMedian()`可能会被调用多次，重复排序会变得昂贵。 

另一种暴力变体使用二进制插入将数字插入到排序列表中。 这改进了中值查找，但插入仍然有成本`O(n)`因为移动数组中的元素是昂贵的。 

主要问题是我们同时需要高效的插入和高效的中值检索。 

### 最佳方法，两个堆

 关键的观察结果是中位数仅取决于数据的中间部分，而不取决于完整的排序顺序。 

我们可以将数字分成两半：

 - 最大堆存储较小的一半
 - 最小堆存储较大的一半

 该结构可以直接访问下半部分的最大值和上半部分的最小值。 

堆保留以下属性：

 - 最大堆中的每个值都小于或等于最小堆中的每个值
 - 堆大小最多相差一
 - 当总计数为奇数时，最大堆可能包含一个额外元素

 有了这些不变量：

 - 如果总计数是奇数，则中位数是最大堆的顶部
 - 如果总计数是偶数，则中位数是两个堆顶的平均值

 这种方法很有效，因为堆插入和平衡每次`O(log n)`时间，而中值查找变成`O(1)`。

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |

 ## 算法演练

 1. 创建两个堆。 

第一个堆代表较小的一半数字。 由于Python只提供了最小堆，因此我们通过存储负值来模拟最大堆。 

第二个堆代表较大的一半，并使用正常的最小堆。 
2. 首先将新数字插入到最大堆中。 

我们最初假设新数字属于下半部分。 在 Python 中，这意味着推送`-num`进入最大堆。 
3. 恢复堆之间的排序。 

下半部分的最大数字不得超过上半部分的最小数字。 

插入最大堆后，将其最大的元素移动到最小堆中。 这保证了排序的正确性。 
4. 如有必要，重新平衡堆大小。 

最大堆最多可以比最小堆多包含一个元素。 

如果最小堆变大，则将其最小元素移回最大堆。 
5. 计算中位数。 

如果堆大小相等，则中位数是两个堆顶的平均值。 

如果最大堆有一个额外元素，则其顶部为中位数。 

### 为什么它有效

 该算法保持两个关键的不变量：

 - 最大堆中的所有值都小于或等于最小堆中的所有值
 - 堆大小最多相差一

 由于这些属性，中间元素或中间对始终位于堆顶。 这保证了中值计算始终正确，无需对完整数据集进行排序。 

## Python 解决方案```python
import heapq
from typing import List

class MedianFinder:

    def __init__(self):
        self.small = []  # max heap simulated with negative values
        self.large = []  # min heap

    def addNum(self, num: int) -> None:
        # Step 1: push into max heap
        heapq.heappush(self.small, -num)

        # Step 2: move the largest from small into large
        value = -heapq.heappop(self.small)
        heapq.heappush(self.large, value)

        # Step 3: rebalance sizes if needed
        if len(self.large) > len(self.small):
            value = heapq.heappop(self.large)
            heapq.heappush(self.small, -value)

    def findMedian(self) -> float:
        # Odd number of elements
        if len(self.small) > len(self.large):
            return float(-self.small[0])

        # Even number of elements
        return (-self.small[0] + self.large[0]) / 2.0

# Your MedianFinder object will be instantiated and called as such:
# obj = MedianFinder()
# obj.addNum(num)
# param_2 = obj.findMedian()
```该实现使用两个名为`small`和`large`。 

这`small`堆存储数字的下半部分。 自从Python的`heapq`仅支持最小堆，存储负值以模拟最大堆行为。 这允许下半部分的最大值仍然可以在索引处访问`0`。 

这`large`堆使用正常的最小堆行为存储上半部分。 

里面`addNum`，每个新值首先被推入`small`。 紧接着，最大值来自`small`被移入`large`。 这确保了所有元素`small`仍然小于或等于`large`。 

平衡步骤保证`small`两者的元素数量相同`large`或者恰好还有一个。 

这`findMedian`方法直接使用堆顶：

 - 如果总数为奇数，则中位数来自`small`- 如果总计数是偶数，则中位数是两个堆顶的平均值

 这种设计避免了重复排序，同时保持高效插入。 

## 解决方案```go
package main

import (
	"container/heap"
)

type MinHeap []int

func (h MinHeap) Len() int {
	return len(h)
}

func (h MinHeap) Less(i, j int) bool {
	return h[i] < h[j]
}

func (h MinHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MinHeap) Push(x interface{}) {
	*h = append(*h, x.(int))
}

func (h *MinHeap) Pop() interface{} {
	old := *h
	n := len(old)
	value := old[n-1]
	*h = old[:n-1]
	return value
}

type MaxHeap []int

func (h MaxHeap) Len() int {
	return len(h)
}

func (h MaxHeap) Less(i, j int) bool {
	return h[i] > h[j]
}

func (h MaxHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MaxHeap) Push(x interface{}) {
	*h = append(*h, x.(int))
}

func (h *MaxHeap) Pop() interface{} {
	old := *h
	n := len(old)
	value := old[n-1]
	*h = old[:n-1]
	return value
}

type MedianFinder struct {
	small *MaxHeap
	large *MinHeap
}

func Constructor() MedianFinder {
	small := &MaxHeap{}
	large := &MinHeap{}

	heap.Init(small)
	heap.Init(large)

	return MedianFinder{
		small: small,
		large: large,
	}
}

func (this *MedianFinder) AddNum(num int) {
	heap.Push(this.small, num)

	value := heap.Pop(this.small).(int)
	heap.Push(this.large, value)

	if this.large.Len() > this.small.Len() {
		value := heap.Pop(this.large).(int)
		heap.Push(this.small, value)
	}
}

func (this *MedianFinder) FindMedian() float64 {
	if this.small.Len() > this.large.Len() {
		return float64((*this.small)[0])
	}

	left := (*this.small)[0]
	right := (*this.large)[0]

	return float64(left+right) / 2.0
}

/**
 * Your MedianFinder object will be instantiated and called as such:
 * obj := Constructor();
 * obj.AddNum(num);
 * param_2 := obj.FindMedian();
 */
```Go 解决方案遵循与 Python 版本相同的逻辑结构，但需要显式堆实现，因为 Go 的`container/heap`包依赖于接口。 

分离`MinHeap`和`MaxHeap`类型已定义。 唯一有意义的区别是`Less`方法：

-`MinHeap`使用标准升序比较
 -`MaxHeap`反转比较以模拟最大堆行为

 与 Python 不同，Go 不支持在未实现所需接口方法的情况下对原始切片进行直接堆操作。 

中位数计算使用`float64`转换以避免整数除法。

 ## 边缘情况

 当数据结构中只有一个元素时，就会出现一种重要的边缘情况。 有错误的实现可能会错误地尝试对两个值进行平均或访问空堆。 该解决方案可以自然地处理这种情况，因为最大堆包含一个元素，而最小堆保持为空，因此中位数只是最大堆的顶部。 

另一个重要的情况涉及重复值。 一些平衡策略意外地依赖于严格的不平等，并且可能会在堆之间错误地放置相等的值。 此实现避免了该问题，因为它仅强制下半部分中的所有元素都小于或等于上半部分中的元素。 相同的值无需特殊处理即可正常工作。 

第三个关键边缘情况是大数和小数交替，例如`1000, -1000, 999, -999`。 当值剧烈波动时，糟糕的实现可能会变得不平衡或违反堆排序。 重新平衡步骤保证堆大小在每次插入后保持有效，而堆之间的传输保持排序的正确性。 

最后的边缘情况涉及偶数大小的集合，其中中位数是小数。 整数除法错误在 Go 和 Java 等语言中很常见。 两种实现都显式返回浮点结果，确保正确的值，例如`1.5`而不是像这样的截断整数`1`。
