[LeetCode 第 279 题](https://leetcode.com/problems/perfect-squares/)

 **难度：** 🟡 中等
 **主题：** 数学、动态规划、广度优先搜索

 ## 解决方案

 ## 问题理解

 该问题要求求和等于给定整数的完全平方数的最小数量`n`。 

完美的平方是一个可以写成的数字`x * x`对于某个整数`x`。 例子包括`1`,`4`,`9`,`16`， 和`25`。 任务不是列出所有可能的组合，而是确定形成目标值所需的最小完美平方数。 

例如，如果`n = 12`，一种有效的表示是：```
12 = 4 + 4 + 4
```这使用了三个完全平方数。 没有办法代表`12`仅使用一两个完全平方数，所以答案是`3`。 

输入由单个整数组成`n`，输出是一个整数，表示所需的完美平方的最小数量。 

约束条件是：```
1 <= n <= 10^4
```这告诉我们几件重要的事情。 首先，输入规模相对较小，这意味着多项式时间动态规划解决方案是实用的。 其次，指数强力递归可能仍然变得太慢，因为组合的数量快速增长。 第三，内存使用不是主要问题，因为数组的大小`10^4`是完全合理的。 

尽早识别一些边缘情况很重要：

 - 如果`n`本身是一个完美的正方形，答案应该是`1`。 
- 小值，例如`1`,`2`， 和`3`可能会在循环或数组初始化中暴露差一错误。 
- 需要多个重复方格的数字，例如`12 = 4 + 4 + 4`，测试算法是否正确允许重复使用同一个方块。 
- 可以多种方式表示的值要求算法选择最小计数而不是第一个有效组合。 

## 方法

 ### 暴力方法

 暴力解决方案将尝试所有可能的完美平方组合，其总和为`n`。 

递归的想法很简单。 对于目标值`remaining`，我们尝试减去每个小于或等于的完美平方`remaining`。 每个递归调用都会询问：```
What is the minimum number of squares needed for the smaller remainder?
```最终的答案是：```
1 + minimum(result of all recursive branches)
```这种方法是正确的，因为它探索了每一种可能的分解`n`成完美的正方形。 最终一定会遇到最优组合。 

然而，问题是许多子问题重复出现。 例如，当求解`12`，多个递归路径可以独立计算答案`8`,`4`， 或者`3`。 这造成了巨大的冗余。 

递归树呈指数增长，使得即使对于中等值的暴力方法也不切实际`n`。 

### 最优动态规划方法

 关键的观察结果是该问题具有最优子结构。 

假设我们已经知道所有小于的值所需的最小完美平方数`n`。 那么对于任意值`i`，我们可以计算：```
dp[i] = 1 + min(dp[i - square])
```对于每一个完美的正方形`square <= i`。 

这是有效的，因为选择一个正方形可以将问题简化为已经得到最佳解决的更小的子问题。 

动态编程通过将结果存储在数组中来避免重复计算。 每个子问题只解决一次，从而大大降低了复杂性。 

这本质上与经典硬币找零问题的结构相同，其中完美的正方形就像硬币面额一样。

 ## 算法演练

 ### 动态规划策略

 我们创建一个 DP 数组，其中：```
dp[i] = minimum number of perfect squares needed to form i
```最初，我们知道：```
dp[0] = 0
```因为零不需要数字。 

然后我们逐步计算答案`1`到`n`。 

### 分步过程

 1.创建一个大小为DP的数组`n + 1`。 

每个索引代表一个目标总和。 我们将每个值初始化为无穷大，因为我们希望最小化所使用的平方数。 
2. 设置基本情况。```
dp[0] = 0
```这意味着需要零个数字才能使值为零。 
3. 迭代每个目标值`1`到`n`。 

对于每个数字`i`，我们确定完美平方的最佳可能分解。 
4. 生成每个小于或等于的完美平方`i`。 

如果`j * j <= i`， 然后`j * j`是一个有效的正方形选择。 
5. 从较小的子问题过渡。 

对于每个正方形：```
dp[i] = min(dp[i], dp[i - square] + 1)
```这`+1`表示使用当前方块一次。 
6. 继续，直到填满整个 DP 表。 

由于首先计算较小的值，因此每个所需的子问题在需要时都已可用。 
7. 返回`dp[n]`。 

这包含原始目标所需的最小完美平方数。 

### 为什么它有效

 该算法之所以有效，是因为每个有效表示`i`必须以某个完全平方数结束`s`。 删除该方块会留下较小的值`i - s`。 如果`dp[i - s]`已经存储了较小值的最优解，那么`dp[i - s] + 1`代表一个有效的候选解决方案`i`。 

通过检查每个可能的完美平方并取最小值，该算法保证`dp[i]`成为最优答案。 

## Python 解决方案```python
class Solution:
    def numSquares(self, n: int) -> int:
        dp = [float('inf')] * (n + 1)
        dp[0] = 0

        for current in range(1, n + 1):
            square_root = 1

            while square_root * square_root <= current:
                square = square_root * square_root

                dp[current] = min(
                    dp[current],
                    dp[current - square] + 1
                )

                square_root += 1

        return dp[n]
```实施首先创建`dp`大批。 每个位置最初都包含无穷大，因为我们正在搜索最小数量的正方形。 基本情况`dp[0] = 0`确定不需要数字来形成零。 

外循环处理来自的每个目标值`1`通过`n`。 对于每个目标，内循环生成不超过当前值的所有有效完美平方。 

过渡步骤：```python
dp[current] = min(dp[current], dp[current - square] + 1)
```是算法的核心。 它检查使用当前平方是否可以改进已知的解决方案。 

由于 DP 表是按递增顺序填充的，因此每个较小的状态在需要之前就已被计算。 

最后，函数返回`dp[n]`，其中包含最佳答案。 

## 解决方案```go
func numSquares(n int) int {
	dp := make([]int, n+1)

	for i := 1; i <= n; i++ {
		dp[i] = n + 1
	}

	dp[0] = 0

	for current := 1; current <= n; current++ {
		for j := 1; j*j <= current; j++ {
			square := j * j

			if dp[current-square]+1 < dp[current] {
				dp[current] = dp[current-square] + 1
			}
		}
	}

	return dp[n]
}
```Go 实现遵循与 Python 版本相同的动态编程策略。 

一个显着的区别是初始化。 Go 没有内置的整数无穷大值，因此代码使用`n + 1`作为安全上限。 因为最糟糕的可能答案是`n`的副本`1`，任何大于`n`实际上表现得像无穷大。 

Go 中的切片是对数组的动态大小的引用，使它们成为 Python 列表的自然替代品。 整数溢出在这里不是一个问题，因为约束很小。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n * sqrt(n)) | O(n * sqrt(n)) | 对于每个数字`1`到`n`，我们迭代所有完美平方直到`sqrt(n)`|

因此，总运行时间变为：```
O(n * sqrt(n))
```内存使用量是线性的，因为 DP 数组包含`n + 1`条目。

 ## 边缘情况

 ### 案例 1：`n`已经是一个完美的正方形

 值例如`1`,`4`,`9`， 或者`16`应该立即给出一个答案`1`。 

这可能会暴露出错误，即算法不必要地将数字分解为更小的部分，而不是识别最佳直接解决方案。 该实现自然地处理了这个问题，因为当当前完全平方等于目标值时，转换变为：```
dp[i] = dp[0] + 1 = 1
```这是自动最优的。 

### 情况 2：输入非常小

 小值如`1`,`2`， 和`3`很重要，因为它们测试初始化​​的正确性和循环边界。 

没有正确设置`dp[0] = 0`，该算法无法正确构建更大的状态。 这些情况还验证了内循环正确包含平方`1`。 

### 情况 3：需要重复平方的数字

 有些值需要多次使用相同的完美平方。 例如：```
12 = 4 + 4 + 4
```有缺陷的实现可能会意外地限制每个方块只能使用一次，这会产生错误的答案。 DP 转换允许无限重用，因为每个状态都可以再次使用相同的平方从先前计算的状态重复转换。
