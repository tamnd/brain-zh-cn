[LeetCode 第 217 题](https://leetcode.com/problems/contains-duplicate/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表、排序

 ## 解决方案

 ## 问题理解

 问题给出一个整数数组`nums`并询问是否有任何数字出现多次。 如果至少有一个值重复，我们返回`true`。 如果每个值都只出现一次，我们返回`false`。 

输入是整数列表。 输出是一个布尔值，它回答一个简单的问题：数组是否包含重复项？ 

例如，在`[1,2,3,1]`，值`1`出现两次，所以答案是`true`。 在`[1,2,3,4]`，每个数字都是唯一的，所以答案是`false`。 

约束条件很重要：

 - 该数组最多可以包含`10^5`元素。 
- 值的范围可以是`-10^9`到`10^9`。 

数组大小为`100,000`意味着我们应该避免比较每对元素的算法，因为二次时间复杂度会变得太慢。 我们需要接近线性时间的东西。 

该问题保证数组至少包含一个元素，因此我们永远不需要处理空输入。 尽管如此，只有一个元素的数组仍然是一种重要的边缘情况，因为它们永远不能包含重复项。 

有几种情况可能会导致简单的实现失败：

 - 数组中出现的重复项相距较远，例如`[1,2,3,4,1]`- 负数，因为值不限于正整数
 - 每个元素都相同的数组，例如`[7,7,7,7]`- 非常大的阵列，低效的解决方案将会超时

 关键的挑战是有效地检测重复值。 

## 方法

 ### 蛮力方法

 最直接的解决方案是将每个元素与其他元素进行比较。 

对于每个索引`i`，我们检查所有后面的索引`j > i`。 如果`nums[i] == nums[j]`，我们立即返回`true`。 如果我们完成所有比较但没有找到匹配项，我们将返回`false`。 

这是有效的，因为每个可能的对都会被检查。 如果存在重复项，最终我们将比较两个相等的值。 

问题是效率。 和`n`元素，这种方法的执行大致如下：$$\frac{n(n-1)}{2}$$最坏情况下的比较。 

为了`n = 100,000`，这变得太慢了。 

### 最优方法，哈希集

 关键的观察是我们不需要重复扫描数组来检查某个值之前是否出现过。 相反，我们可以将之前看到的值存储在哈希集中。 

哈希集提供平均值`O(1)`查找时间。 当我们遍历数组时：

 - 如果当前数字已在集合中，则我们发现了重复项。 
- 否则，我们将数字添加到集合中并继续。 

这将总运行时间减少到线性时间，因为每个元素都被处理一次。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 比较每对元素 |
 | 最佳| O(n) | O(n) | 使用哈希集进行恒定时间查找 |

 ## 算法演练

 ### 使用哈希集的最优算法

 1. 创建一个名为的空哈希集`seen`。 

该集合将存储我们在扫描数组时已经遇到的所有数字。 
2. 迭代中的每个数字`nums`。 

我们从左到右一一处理元素。 
3. 对于当前号码，检查是否已存在`seen`。 

如果是，则意味着我们之前遇到过相同的值，因此该数组包含重复项。 返回`true`。 
4. 如果该号码不在集合中，则将其添加到`seen`。 

这记录了现在已遇到该号码。 
5. 继续，直到处理完所有元素。 

如果循环结束时没有找到任何重复值，则每个元素都是不同的。 
6. 返回`false`。 

### 为什么它有效

 该算法保持不变式`seen`准确包含先前在遍历中遇到的值。 

处理新号码时：

 - 如果它已经在`seen`，那么之前出现过相同的值，因此存在重复项。 
- 如果它不在`seen`，那么这是该值第一次出现。 

由于每个元素都会针对所有先前看到的值进行一次检查，因此算法可以正确检测重复项（无论何时存在）。 

## Python 解决方案```python
from typing import List

class Solution:
    def containsDuplicate(self, nums: List[int]) -> bool:
        seen = set()

        for number in nums:
            if number in seen:
                return True

            seen.add(number)

        return False
```实现首先创建一个名为的空集`seen`。 Python 集合是使用哈希表实现的，哈希表提供平均恒定时间插入和查找。 

该循环处理输入数组中的每个数字。 在将当前数字添加到集合之前，代码会检查它是否已存在于`seen`。 

如果该数字已经存在，该方法立即返回`True`因为发现了重复的。 

如果该数字不存在，则会将其添加到集合中，以便将来的迭代可以检测涉及该值的重复项。 

如果循环完成而没有提前返回，则不存在重复项，因此该方法返回`False`。 

## 解决方案```go
func containsDuplicate(nums []int) bool {
    seen := make(map[int]bool)

    for _, number := range nums {
        if seen[number] {
            return true
        }

        seen[number] = true
    }

    return false
}
```Go 没有内置的集合类型，因此实现使用带有布尔值的映射来模拟集合。 

键是数组中的整数，值表示该数字以前是否见过。 

与 Python 不同，Go 数组和切片是不同的类型。 该函数接受一个切片`[]int`，这是 LeetCode Go 问题中使用的标准表示。 

不存在整数溢出问题，因为该算法仅执行比较和哈希查找，而不执行算术运算。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个元素被处理一次 |
 | 空间| O(n) | 哈希集可以存储每个唯一元素 |

 运行时间是线性的，因为每个数组元素最多被检查一次并插入到哈希集中。 哈希表操作很平均`O(1)`。 

在最坏的情况下，空间复杂度是线性的，因为如果所有值都是唯一的，则集合存储所有`n`元素。

 ## 边缘情况

 ### 单元素数组

 只有一个元素的数组永远不会包含重复项，因为不可能出现第二次。 

有缺陷的实现可能会错误地假设至少存在两个元素并尝试进行无效比较。 哈希集方法可以自然地处理这个问题。 循环运行一次，将元素添加到集合中，然后返回`False`。 

### 重复出现较晚

 考虑像这样的输入`[1,2,3,4,5,1]`。 

错误地提前停止或无法跟踪所有先前元素的幼稚实现可能会错过重复项，因为重复值距离其第一次出现很远。 

哈希集解决方案正确存储了每个先前看到的值，因此最终的`1`立即被检测到。 

### 所有元素相同

 用于输入`[7,7,7,7]`，立即出现重复项。 

一些低效的实现可能会在找到重复项后继续扫描，从而不必要地浪费时间。 

此实现返回`True`一旦第二个`7`遇到，提供早期退出和最佳行为。
