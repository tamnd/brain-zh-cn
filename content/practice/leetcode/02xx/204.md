 ## 解决方案

 ## 问题理解

 该问题要求我们计算存在多少个严格小于给定整数的素数`n`。 

素数是大于的正整数`1`正好有两个除数：`1`和它本身。 素数的例子包括`2`,`3`,`5`,`7`， 和`11`。 像这样的数字`1`,`4`,`6`， 和`9`不是素数，因为它们的约数要么少于两个，要么多于两个。 

输入是单个整数`n`，输出应该是范围内素数的个数`[0, n)`，表示从以下位置开始的所有整数`0`最多但不包括`n`。 

例如，当`n = 10`, 小于的素数`10`是：

-`2`-`3`-`5`-`7`所以答案是`4`。 

约束条件很重要：

 -`0 <= n <= 5 * 10^6`这个上限非常大。 使用试除法单独检查每个数字的素数的解决方案在这种规模下会变得太慢。 我们需要一种能够同时有效识别许多素数的算法。 

一些边缘情况立即脱颖而出：

 -`n = 0`，没有数字可供检查，所以答案是`0`-`n = 1`，仍然没有素数
 -`n = 2`，以下范围`2`不包含素数
 - 非常大的值，例如`5,000,000`需要在运行时和内存使用方面都有效的算法

 该问题保证输入是非负整数，因此我们不需要处理无效的输入类型或负数。 

## 方法

 ### 蛮力方法

 最直接的方法是迭代每个数字`2`到`n - 1`并判断每个数是否是素数。 

要检查一个数字是否是素数，我们可以尝试将它除以以下每个整数`2`直到其平方根。 如果任何约数能整除该数，则该数不是素数。 否则，它就是素数。 

这种方法是正确的，因为每个合数至少有一个小于或等于其平方根的因子。 通过检查此时的整除性，我们可以准确地确定素数。 

然而，对于给定的约束，该方法变得太慢。 如果我们单独测试每个数字，总工作量的增长大约与以下因素成正比：```
n * sqrt(n)
```和`n`一样大`5,000,000`，这在计算上变得昂贵。 

### 最优方法，埃拉托斯特尼筛法

 关键的见解是，我们可以批量消除复合数字，而不是单独检查每个数字。 

如果一个数是素数，那么该数的每个倍数都必须是合数。 例如：

 - 的倍数`2`大于`2`不是素数
 - 的倍数`3`大于`3`不是素数
 - 的倍数`5`大于`5`不是素数

 埃拉托斯特尼筛法有效地利用了这一观察结果。 

我们创建一个布尔数组，其中每个索引代表该数字当前是否被视为素数。 最初，我们假设每个数字大于或等于`2`是素数。 然后：

 - 开始于`2`- 标记所有的倍数`2`作为复合材料
 - 移至下一个未标记的数字，`3`- 标记所有的倍数`3`- 继续这个过程

 到最后，所有剩余的未标记数字都是素数。 

额外的优化很重要：

 处理素数时`p`，我们开始标记`p * p`， 不是`2 * p`。 

为什么？ 

因为较小的倍数，例如`2 * p`,`3 * p`，等等，在处理较小的素数时已经被标记了。 

这大大减少了不必要的工作。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n√n) | O(n√n) | O(1) | O(1) | 独立检查每个数字的素数 |
 | 最佳| O(n log log n) | O(n log log n) | O(n) | 使用埃拉托斯特尼筛法有效消除复合物 |

 ## 算法演练

 1. 立即处理小边缘情况。 

如果`n <= 2`， 返回`0`因为没有小于的素数`2`。 
2. 创建一个布尔数组，名为`is_prime`。 

数组有长度`n`。 每个索引代表一个数字。 

最初：

 - 假设每个数字都是质数
 - 将所有条目设置为`True`- 明确标记`0`和`1`作为`False`因为它们不是素数
 3. 开始迭代`2`。 

对于每个数字`current`：

- 如果`is_prime[current]`是`True`， 然后`current`是素数
 - 我们现在消除所有倍数`current`4. 开始标记从以下位置开始的倍数`current * current`。 

这种优化之所以有效，是因为较小的倍数已经由较小的素数处理。 

例如，处理时`5`:

 -`10`已经被标记为`2`-`15`已经被标记为`3`-`20`已经被标记为`2`所以仍然需要标记的第一个新倍数是`25`。 
5. 将每个倍数标记为复合。 

迭代：```
current * current,
current * current + current,
current * current + 2 * current,
...
```设置每个相应的条目`is_prime`到`False`。 
6. 继续直到`current * current >= n`。 

一旦平方超过`n`，所有复合材料均已处理完毕。 
7. 清点所有剩余的`True`价值观。 

剩下的每一个`True`索引对应于一个素数。 

### 为什么它有效

 该算法依赖于合数的基本属性：

 每个合数至少有一个小于或等于其平方根的质因数。 

当我们处理每个质数并标记其所有倍数时，每个合数最终都会被标记为非质数。 素数本身永远不会被标记，因为它们没有更小的素因数。 

因此，最后仍然标记为素数的数字正是小于的素数`n`。 

## Python 解决方案```python
class Solution:
    def countPrimes(self, n: int) -> int:
        if n <= 2:
            return 0

        is_prime = [True] * n
        is_prime[0] = False
        is_prime[1] = False

        current = 2

        while current * current < n:
            if is_prime[current]:
                multiple = current * current

                while multiple < n:
                    is_prime[multiple] = False
                    multiple += current

            current += 1

        return sum(is_prime)
```实现从处理最小的输入开始。 任何小于或等于的值`2`不能包含比自身小的质数。 

接下来，`is_prime`数组已初始化。 每个位置代表当前是否认为相应的数字是质数。 

主循环继续进行`current * current < n`。 这个条件是足够的，因为任何大于平方根的合数都已经被标记为较小的因子。 

在循环内部，我们只处理仍然标记为质数的数字。 对于每个质数，我们将其所有倍数标记为非质数。 

标记过程开始于`current * current`，避免了多余的工作，提高了效率。 

最后，算法返回所有的计数`True`数组中的值，因为它们对应于素数。 

## 解决方案```go
func countPrimes(n int) int {
    if n <= 2 {
        return 0
    }

    isPrime := make([]bool, n)

    for i := 2; i < n; i++ {
        isPrime[i] = true
    }

    for current := 2; current*current < n; current++ {
        if isPrime[current] {
            for multiple := current * current; multiple < n; multiple += current {
                isPrime[multiple] = false
            }
        }
    }

    count := 0

    for i := 2; i < n; i++ {
        if isPrime[i] {
            count++
        }
    }

    return count
}
```Go 实现遵循与 Python 版本相同的算法结构。 

一个小的区别是切片初始化。 在 Go 中，布尔切片默认为`false`，所以我们明确地设置索引`2`继续到`true`。 

计数步骤也是使用循环手动执行的，因为 Go 没有提供与 Python 相同的内置功能`sum()`对于布尔值。 

整数溢出在这里不是问题，因为约束限制完全在 Go 的整数范围内。

 ## 边缘情况

 ### 边缘情况 1，`n <= 2`这是最重要的边界条件。 由于该问题要求素数严格小于`n`，当`n`是`0`,`1`， 或者`2`。 

一个常见的错误是不小心计数`2`本身当`n = 2`。 该实现通过立即返回来避免这种情况`0`每当`n <= 2`。 

### 边缘情况 2，开始标记于`2 * current`一个简单的筛子实现可能会开始标记来自`2 * current`。 虽然这仍然会产生正确的结果，但它执行了大量的冗余工作。 

例如，处理时`5`，值如`10`,`15`， 和`20`已经被更小的素数标记了。 

开始于`current * current`避免重复操作，对于实现最佳性能至关重要。 

### 边缘情况 3，附近有大量输入`5 * 10^6`对于非常大的值`n`，低效的素性测试变得太慢。 

筛子实现可以有效地处理大量输入，因为每个合数仅被标记有限次数。 布尔数组使用线性空间，在问题约束下这是可以接受的。 

这确保了解决方案即使在接近最大输入大小的情况下也能保持性能。
