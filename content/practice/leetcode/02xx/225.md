[LeetCode 第 225 题](https://leetcode.com/problems/implement-stack-using-queues/)

 **难度：** 🟢简单
 **主题：** 堆栈、设计、队列

 ## 解决方案

 ## 问题理解

 该问题要求我们在内部仅使用队列操作的同时实现堆栈数据结构。 堆栈遵循后进先出（LIFO）原则。 这意味着必须首先删除最近插入的元素。 相比之下，队列遵循先进先出（即 FIFO）原则，其中元素按照其进入的顺序离开。 

我们必须设计一个`MyStack`支持标准堆栈操作的类：

 -`push(x)`将一个元素插入到栈顶
 -`pop()`删除并返回顶部元素
 -`top()`返回当前顶部元素而不删除它
 -`empty()`检查堆栈是否包含任何元素

 挑战来自于我们只能使用队列操作的限制。 我们不能直接使用内置堆栈。 有效的队列操作是：

 - 插入后面
 - 从前面移除
 - 检查前面的元件
 - 检查尺寸
 - 检查是否为空

 LeetCode 中的输入表示为一系列方法调用。 例如：```
["MyStack", "push", "push", "top", "pop", "empty"]
[[], [1], [2], [], [], []]
```意思是：

 1. 创建一个新堆栈
 2. 推`1`3. 推`2`4. 读取顶部元素
 5.弹出顶部元素
 6.检查栈是否为空

 预期输出对应于每个操作的返回值。 

限制非常小。 最多执行 100 次操作。 这意味着效率并不是极其重要，但目标仍然是设计一个正确而优雅的解决方案，使用队列模拟堆栈行为。 

一个重要的保证是每一个`pop()`和`top()`通话有效。 我们永远不需要处理从空堆栈中弹出的问题。 

一些边缘情况很重要：

 - 只推入一个元素然后弹出它
 - 在弹出之前多次连续推送
 - 通话`top()`多次而不修改堆栈
 - 确保`empty()`正确反映所有元素被删除后的状态

 主要困难是在内部使用 FIFO 容器时保留 LIFO 行为。 

## 方法

 ### 蛮力方法

 用队列模拟堆栈的一种直接方法是按插入顺序维护所有元素，并且每当我们需要执行`pop()`或者`top()`，在两个队列之间重复移动元素，直到只有最后插入的元素仍可访问。 

例如，假设队列包含：```
1 -> 2 -> 3
```在哪里`3`是逻辑栈顶。 

为了弹出顶部元素，我们反复从第一个队列中出队并入队到第二个队列中，直到只剩下一个元素。 最后一个元素是栈顶。 

这是有效的，因为最后一个剩余元素正是最近插入的值。 删除它后，我们交换队列并继续。 

暴力方法是正确的，因为每次发生删除时它都会显式地重建堆栈行为。 然而，它的效率很低，因为每个`pop()`或者`top()`操作可能需要在队列之间移动几乎所有元素。 

### 最佳方法

 一个更优雅的解决方案是让队列在每次之后始终保持堆栈顺序`push()`。 

关键的观察是队列保留相对顺序，因此如果我们在插入后立即旋转队列，我们​​可以将最新的元素放在前面。 那么队列的前面总是代表栈顶。 

例如：```
Push 1
Queue: [1]

Push 2
Queue after insertion: [1, 2]
Rotate once:
Queue: [2, 1]

Push 3
Queue after insertion: [2, 1, 3]
Rotate twice:
Queue: [3, 2, 1]
```现在，队列前端的行为始终类似于堆栈的顶部。 

这使得`pop()`和`top()`非常简单，因为正确的元素总是在前面。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 推送：O(1)，弹出：O(n)，顶部：O(n) | O(n) | 删除期间在两个队列之间移动元素 |
 | 最佳| 推送：O(n)，弹出：O(1)，顶部：O(1) | O(n) | 每次插入后旋转队列，使顶部保持在前面 |

 ## 算法演练

 1. 初始化单个队列来存储栈元素。 

队列将始终将栈顶元素保持在最前面。 这允许直接访问`pop()`和`top()`运营。 
2. 当推送一个新元素时，将其插入到队列的末尾。 

此时，最新的元素在末尾，但堆栈要求它成为顶部。 
3. 插入后旋转队列。 

假设队列大小变为`k`插入后。 我们删除第一个`k - 1`元素一个一个地追加到队列中。 

这会将新插入的元素从后移动到前。 
4. 对于`pop()`，移除并返回前面的元素。 

由于循环步骤，队列前端始终是逻辑堆栈顶部。 
5. 对于`top()`，只需返回前面的元素而不删除它。 
6. 对于`empty()`，检查队列是否包含任何元素。 

### 为什么它有效

 核心不变量是队列前端始终存储当前的栈顶。 

每次之后`push()`，我们旋转队列，使新插入的元素移动到前面。 由于堆栈要求首先删除最近插入的元素，因此将最新值放在前面可确保正常的队列出列操作的行为与堆栈弹出完全相同。 

因为这个不变量在每次插入后都会被维护，所以所有未来的`pop()`和`top()`操作会自动产生正确的堆栈行为。 

## Python 解决方案```python
from collections import deque
from typing import Deque

class MyStack:

    def __init__(self):
        self.queue: Deque[int] = deque()

    def push(self, x: int) -> None:
        self.queue.append(x)

        # Rotate the queue so the new element becomes the front
        for _ in range(len(self.queue) - 1):
            self.queue.append(self.queue.popleft())

    def pop(self) -> int:
        return self.queue.popleft()

    def top(self) -> int:
        return self.queue[0]

    def empty(self) -> bool:
        return len(self.queue) == 0

# Your MyStack object will be instantiated and called as such:
# obj = MyStack()
# obj.push(x)
# param_2 = obj.pop()
# param_3 = obj.top()
# param_4 = obj.empty()
```该实现使用Python的`deque`从`collections`模块，因为它有效地支持两端的队列操作。 

里面`__init__`，我们创建一个存储所有堆栈元素的队列。 

这`push()`方法首先将新元素插入到队列的末尾。 由于该元素应该成为堆栈顶部，因此我们轮换其后面的所有旧元素。 循环执行`len(queue) - 1`次，每次将前一个前面的元素移到后面。 

这`pop()`方法从前面删除，因为队列前面始终代表堆栈顶部。 

这`top()`方法直接读取前面的元素，不修改队列。 

这`empty()`方法检查队列长度是否为零。 

此实现完全遵循算法演练中建立的不变量。 

## 解决方案```go
type MyStack struct {
    queue []int
}

func Constructor() MyStack {
    return MyStack{
        queue: []int{},
    }
}

func (this *MyStack) Push(x int) {
    this.queue = append(this.queue, x)

    // Rotate previous elements behind the new element
    size := len(this.queue)
    for i := 0; i < size-1; i++ {
        front := this.queue[0]
        this.queue = this.queue[1:]
        this.queue = append(this.queue, front)
    }
}

func (this *MyStack) Pop() int {
    top := this.queue[0]
    this.queue = this.queue[1:]
    return top
}

func (this *MyStack) Top() int {
    return this.queue[0]
}

func (this *MyStack) Empty() bool {
    return len(this.queue) == 0
}

/**
 * Your MyStack object will be instantiated and called as such:
 * obj := Constructor();
 * obj.Push(x);
 * param_2 := obj.Pop();
 * param_3 := obj.Top();
 * param_4 := obj.Empty();
 */
```Go 实现使用切片来模拟队列。 

追加到切片对应于在后面排队。 使用切片删除第一个元素：```go
this.queue = this.queue[1:]
```与Python不同`deque`，Go 切片内部不提供恒定时间的前端移除，因为元素是通过切片语义进行逻辑移位的。 然而，考虑到一些小的限制，这种实现是完全可以接受的。 

Go 在这里不需要显式处理整数溢出，因为所有值都非常小。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | 压入：O(n)，弹出：O(1)，顶部：O(1)，空：O(1) | Push 会旋转所有之前的元素 |
 | 空间| O(n) | 队列存储所有栈元素 |

 唯一昂贵的操作是`push()`。 插入新元素后，我们将旋转其后面的所有旧元素。 如果堆栈当前包含`n`元素，这需要`n - 1`队列操作。 

所有其他操作都是恒定时间，因为堆栈顶部始终存储在队列前面。 

空间复杂度是线性的，因为每个插入的元素都必须存储在队列中。

 ## 边缘情况

 一个重要的边缘情况是仅推送一个元素并立即弹出它。 许多不正确的实现在删除后会意外地留下陈旧的状态。 在这个实现中，当前面的元素被移除后，队列自然变空，所以`empty()`正确返回`True`。 

另一个重要的案例是重复调用`top()`没有弹出。 自从`top()`应该只检查堆栈而不修改它，不正确的实现可能会在读取元素时意外删除元素。 这里，`top()`直接访问队列前端而不改变队列结构，因此重复调用总是返回相同的值。 

第三种边缘情况涉及在发生任何弹出操作之前多次连续推送。 如果没有适当的队列旋转，最旧的元素将保留在前面，并且堆栈行为将被破坏。 每次插入后的轮换步骤可确保最新元素始终移到前面，无论顺序发生多少次推送，都保留正确的 LIFO 顺序。
