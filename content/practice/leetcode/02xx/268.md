 ## 解决方案

 ## 问题理解

 问题给出了一个数组`nums`含有`n`不同的整数。 每个数字都应该来自该范围`[0, n]`，这意味着实际上有`n + 1`总共可能的值。 由于数组只包含`n`数字，恰好缺少该范围中的一个值。 

任务是识别并返回丢失的号码。 

例如，如果`nums = [3,0,1]`，数组长度为`3`，所以有效范围是`[0,3]`。 出现的数字是`0`,`1`， 和`3`，因此缺失值是`2`。 

一个重要的细节是所有数字都是唯一的。 这种保证简化了问题，因为我们永远不需要处理重复或不明确的情况。 限制也比较小，`n <= 10^4`，因此多种方法是可行的。 然而，后续行动明确要求`O(n)`时间解与`O(1)`额外的空间，它引导我们走向基于数学或位操作的解决方案。 

需要考虑一些重要的边缘情况：

 - 缺失的号码可能是`0`，意味着序列开始于`1`。 
- 缺失的号码可能是`n`，意味着所有较小的值都存在。 
- 不保证数组已排序。 
- 重复扫描数组以查找每个可能数字的简单实现可能会变得低效。 

由于该数组恰好包含一个缺失值，并且每个其他数字都恰好出现一次，因此我们可以利用算术和或 XOR 运算的属性来有效地解决该问题。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每个数字`0`到`n`并判断数组中是否存在。 

一种方法是：

 - 对于范围内的每个候选编号`[0, n]`- 扫描整个阵列
 - 如果未找到候选人，则将其退回

 这是可行的，因为该问题恰好保证了一个缺失值。 最终，丢失的数字将是扫描期间唯一未遇到的值。 

然而，这种方法效率很低，因为对于每个`n + 1`可能的数字，我们可能会扫描最多`n`元素。 这会产生`O(n^2)`时间复杂度。 

稍微改进的暴力方法使用哈希集：

 - 将所有数字插入一组
 - 检查每个数字`0`到`n`- 返回第一个不在集合中的数字

 这将时间复杂度降低到`O(n)`但需要`O(n)`额外的空间。 

### 最佳方法

 最优解使用数学公式求第一个数之和`n`整数。 

关键的观察是：

 - 数字来自`0`到`n`总和应为：$0 + 1 + 2 + \dots + n = \frac{n(n+1)}{2}$如果我们计算这个预期总和并减去数组的实际总和，则差值必定是缺失的数字。 

例如：

 - 预计金额`n = 3`：$\frac{3(3+1)}{2} = 6$- 实际数组总和`[3,0,1]`是`4`- 缺少的号码是`6 - 4 = 2`这种方法是最佳的，因为：

 - 我们只迭代数组一次
 - 我们使用恒定的额外内存
 - 运行时间是线性的

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 重复扫描数组以查找每个可能的数字 |
 | 最佳 | O(n) | O(1) | O(1) | 使用预期总和减去实际总和 |

 ## 算法演练

 1. 确定值`n`通过获取数组的长度。 

该问题保证有效数字应来自范围`[0, n]`，所以数组长度直接告诉我们期望序列的上限。 
2. 计算所有整数的预期总和`0`到`n`。 

不要生成整个序列，而是使用算术级数公式：$\text{expectedSum} = \frac{n(n+1)}{2}$这给出了如果没有丢失任何数字则存在的总和。 
3. 计算数组中数字的实际总和。 

迭代`nums`并积累数值。 
4. 从预期金额中减去实际金额。 

由于除了一个数字之外的每个数字都只出现一次，因此所有共享值都会抵消，只留下缺失的数字。 
5.退回差额。 

### 为什么它有效

 该算法依赖于这样一个事实：数组包含来自`0`到`n`除了一个。 预期总和包括所有数字，而实际总和不包括一个值。 所以：$\text{missing} = \text{expectedSum} - \text{actualSum}$所有存在的数字实际上都被抵消，只留下缺失的值。 

## Python 解决方案```python
from typing import List

class Solution:
    def missingNumber(self, nums: List[int]) -> int:
        n = len(nums)

        expected_sum = n * (n + 1) // 2
        actual_sum = sum(nums)

        return expected_sum - actual_sum
```实现从计算开始`n`，它表示数组长度和预期范围内的最大可能值。 

接下来，代码计算所有数字的理论总和`0`到`n`使用算术公式。 整数除法`//`使用它是因为结果始终是整数。 

内置的`sum()`函数计算数组中实际存在的值的总和。 

最后，从预期总和中减去实际总和，分离出缺失的数字并直接返回。 

该解决方案很简洁，因为数学观察消除了对额外数据结构或嵌套循环的需要。 

## 解决方案```go
func missingNumber(nums []int) int {
    n := len(nums)

    expectedSum := n * (n + 1) / 2

    actualSum := 0
    for _, num := range nums {
        actualSum += num
    }

    return expectedSum - actualSum
}
```Go 实现遵循与 Python 版本相同的逻辑。 

Go 不需要使用内置求和函数，而是需要显式循环来累加数组值。 这`range`关键字有效地迭代切片。 

Go 整数足以满足给定的约束，因为最大可能的总和相对于整数限制很小。 自从`n <= 10^4`，溢出不是问题。 

尽管约束保证至少有一个元素，但空切片也可以自然地处理。

 ## 边缘情况

 当缺失的数字为`0`。 这很容易破坏假设序列总是以零开始的实现。 例如，与`nums = [1,2]`，预期范围是`[0,2]`，并且算法正确计算缺失值，因为预期总和仍包含零。 

另一个重要的情况是当缺失的数字是`n`，范围内的最大值。 例如，`nums = [0,1,2]`应该返回`3`。 有些实现意外地只迭代了`n - 1`并且没有考虑上限。 算术公式自然包括`n`，所以这个实现正确地处理了这种情况。 

第三种边缘情况是无序输入。 不保证数组已排序，因此依赖邻接比较而不排序的解决方案可能会失败。 基于和的方法与顺序无关，因为加法是可交换的。 无论数字是排序、颠倒还是随机排列，结果都是正确的。 

另一个微妙的情况是最小有效输入大小。 对于数组，例如`[0]`或者`[1]`，仅存在一个数字和一个缺失值。 该实现仍然有效，因为即使对于非常小的预期总和公式仍然有效`n`。
