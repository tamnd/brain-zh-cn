 **难度：** 🟡 中等
 **主题：** 数组、哈希表、字符串、设计

 ## 解决方案

 ## 问题理解

 这个问题要求我们设计一个数据结构来确定一个单词的缩写在给定的字典中是否唯一。 

缩写由三个部分定义：

 - 第一个角色
 - 第一个和最后一个字符之间的字符数
 - 最后一个角色

 例如：

 -`"dog"`变成`"d1g"`-`"internationalization"`变成`"i18n"`-`"it"`遗迹`"it"`因为长度小于或等于2的单词不会被缩短

 的`ValidWordAbbr`类是用单词字典初始化的。 初始化后，我们必须使用以下命令回答查询`isUnique(word)`。 

如果满足以下任一条件，则单词被视为唯一：

 - 字典中没有单词具有相同的缩写
 - 每个共享缩写的字典单词都是完全相同的单词

 第二个条件极其重要。 如果字典包含`"cake"`我们查询`"cake"`，答案应该还是`true`只要没有其他不同的单词共享该缩写`"c2e"`。 

输入大小给我们提供了重要的设计约束：

 - 最多`3 * 10^4`字典单词
 - 最多`5000`打电话给`isUnique`对于每个查询，对整个字典进行简单的扫描将变得昂贵。 由于缩写计算简单且经常重复，因此将字典预处理为基于哈希的结构是自然的优化。 

一些边缘情况很重要：

 - 字典中可能会出现重复的单词
 - 长度非常短的单词`1`或者`2`缩写为自己
 - 多个不同的单词可以映射到相同的缩写
 - 查询词可能已存在于字典中，也可能不存在

 正确处理重复项尤其重要。 如果`"deer"`出现多次，它仍应表现为与缩写相关的单个唯一单词`"d2r"`。 

## 方法

 ### 蛮力方法

 暴力解决方案存储整个字典，并且对于每个`isUnique(word)`查询，扫描所有字典单词。 

对于每个字典单词：

 1. 计算其缩写
 2. 计算查询词的缩写
 3. 缩写比较
 4. 如果缩写匹配但单词不同，则返回`false`如果扫描完成后没有找到冲突的单词，则返回`true`。 

这种方法是正确的，因为它直接实现了问题定义。 每个可能冲突的字典单词都会被明确检查。 

然而，这种解决方案效率低下，因为每个查询都需要扫描完整的字典。 高达`30000`词和`5000`查询时，最坏情况下运行时间会变得非常大。 

### 最佳方法

 关键的见解是，对独特性唯一重要的是以下之间的关系：

 - 缩写
 - 产生它的词组

 我们可以将所有缩写预处理成哈希映射，而不是重复扫描字典。 

对于每个缩写，我们存储映射到它的字典单词集。 

然后期间`isUnique(word)`：

 - 如果缩写在地图中不存在，则该词是唯一的
 - 如果缩写存在并且关联的集合仅包含相同的单词，则该单词是唯一的
 - 否则，它不是唯一的

 这将重复的昂贵扫描转换为恒定时间的哈希查找。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 每个查询 O(n) | O(n) | 每次查找都会扫描整个字典 |
 | 最佳| O(n) 预处理，O(1) 每个查询 | O(n) | 使用从缩写到单词集的哈希映射 |

 ## 算法演练

 ### 最优算法

 1. 创建一个计算单词缩写的辅助函数。 

如果字长小于或等于`2`，返回单词本身，因为短单词永远不会被压缩。 

否则构造：

 - 第一个字符
 - 中间字符的数量
 - 最后一个字符

 例如：

 -`"door"`→`"d2r"`-`"cake"`→`"c2e"`2. 在初始化期间，构建哈希映射，其中：

 - 键=缩写
 - 值 = 共享该缩写的单词集

 此预处理步骤按缩写对所有字典单词进行分组。 
3. 什么时候`isUnique(word)`被称为，计算单词的缩写。 
4. 检查哈希映射中是否存在该缩写。 

如果不存在，则字典中没有单词共享该缩写，因此返回`true`。 
5. 如果缩写存在，则检索关联的单词集。 
6. 仅当集合中恰好包含一个单词并且该单词等于查询单词时，该单词才是唯一的。 

此条件同时处理：

 - 重复的字典条目
 - 字典中已有的单词
 7. 否则返回`false`因为另一个不同的词共享该缩写。 

### 为什么它有效

 该算法之所以有效，是因为哈希图完全捕获了缩写词和字典单词之间的关系。 

对于任何查询的单词，只有具有相同缩写的单词才有可能违反唯一性。 地图让我们能够在恒定的时间内准确地访问这些单词。 

正确性不变量为：

 > 对于每个缩写，映射存储生成它的完整的一组不同的字典单词。 

因此，检查集合是否为空或仅包含查询的单词与问题定义完全匹配。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class ValidWordAbbr:

    def __init__(self, dictionary: List[str]):
        self.abbr_map = defaultdict(set)

        for word in dictionary:
            abbreviation = self._get_abbreviation(word)
            self.abbr_map[abbreviation].add(word)

    def _get_abbreviation(self, word: str) -> str:
        if len(word) <= 2:
            return word

        return word[0] + str(len(word) - 2) + word[-1]

    def isUnique(self, word: str) -> bool:
        abbreviation = self._get_abbreviation(word)

        if abbreviation not in self.abbr_map:
            return True

        matching_words = self.abbr_map[abbreviation]

        return matching_words == {word}

# Your ValidWordAbbr object will be instantiated and called as such:
# obj = ValidWordAbbr(dictionary)
# param_1 = obj.isUnique(word)
```实施从构建开始`abbr_map`，将每个缩写映射到产生它的单词集的字典。 

这`_get_abbreviation`helper 集中了缩写逻辑，因此它在初始化和查询处理中实现一致。 

使用`set`很重要，因为字典可能包含重复的单词。 我们只关心与缩写相关的不同单词。 

在`isUnique`，我们首先计算查询词的缩写。 如果缩写在地图中不存在，则该单词自动是唯一的。 

如果缩写存在，我们将关联的集合与`{word}`。 这是一种简洁而可靠的方法，可以验证查询的单词是否是唯一共享缩写的不同单词。 

## 解决方案```go
package main

type ValidWordAbbr struct {
	abbrMap map[string]map[string]bool
}

func Constructor(dictionary []string) ValidWordAbbr {
	abbrMap := make(map[string]map[string]bool)

	for _, word := range dictionary {
		abbr := getAbbreviation(word)

		if _, exists := abbrMap[abbr]; !exists {
			abbrMap[abbr] = make(map[string]bool)
		}

		abbrMap[abbr][word] = true
	}

	return ValidWordAbbr{
		abbrMap: abbrMap,
	}
}

func getAbbreviation(word string) string {
	if len(word) <= 2 {
		return word
	}

	return string(word[0]) +
		string(rune(len(word)-2+'0')) +
		string(word[len(word)-1])
}

func (this *ValidWordAbbr) IsUnique(word string) bool {
	abbr := getAbbreviation(word)

	words, exists := this.abbrMap[abbr]

	if !exists {
		return true
	}

	return len(words) == 1 && words[word]
}

/**
 * Your ValidWordAbbr object will be instantiated and called as such:
 * obj := Constructor(dictionary);
 * param_1 := obj.IsUnique(word);
 */
```One important Go-specific detail is the representation of sets. Go没有内置的集合类型，所以我们使用`map[string]bool`。 

另一个细节是缩写结构。 由于中间计数可能超过一位数，生产实现最好使用`strconv.Itoa(len(word) - 2)`而不是直接符文转换。 更强大的版本如下所示：```go
return string(word[0]) + strconv.Itoa(len(word)-2) + string(word[len(word)-1])
```这可以正确处理多位数计数，例如`"internationalization"`成为`"i18n"`。 

与Python不同`defaultdict`，Go 需要在插入之前显式地初始化映射。

 ## 边缘情况

 一种重要的边缘情况是重复的字典条目。 如果`"hello"`出现多次，我们不应该将其视为自相矛盾。 使用计数而不是不同单词的简单实现可能会错误地返回`false`。 使用集合自然地解决了这个问题，因为重复的插入会折叠成单个存储的单词。 

另一个重要的边缘情况涉及非常短的单词。 有长度的单词`1`或者`2`不按照正常规则缩写。 有缺陷的实现可能会错误地转换`"it"`进入`"i0t"`。 当长度小于或等于时，辅助函数显式返回原始单词不变`2`。 

当查询的单词已经存在于字典中时，会发生第三种微妙的情况。 例如，如果字典仅包含`"cake"`， 然后`isUnique("cake")`应该返回`true`。 该实现通过验证缩写的关联集是否完全等于来处理此问题`{word}`。 这确保了查询的单词是唯一共享缩写的不同单词。 

最后一个边缘情况涉及许多不同单词共享的缩写。 例如：```
deer → d2r
door → d2r
dear → d2r
```一种幼稚的解决方案可能会在找到一个匹配的单词后停止并错误地假设唯一性。 我们的实现存储了全套冲突单词，确保正确解释所有冲突。
