[LeetCode 第 213 题](https://leetcode.com/problems/house-robber-ii/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划

 ## 解决方案

 ## 问题理解

 这个问题是经典的“入室抢劫者”动态规划问题的一种变体，有一个重要的变化：房屋排列成“圆形”而不是直线。 

我们得到一个整数数组`nums`，其中每个元素代表房屋中可用的金额。 目标是确定在不触发警报系统的情况下，在一个晚上**可以抢劫的最大金额**。 

限制是**相邻的房屋不能同时被抢劫**。 如果相邻的两栋房屋遭到抢劫，就会向警方发出警报。 

在最初的入室抢劫问题中，房屋形成一条直线，这意味着只有紧邻的左右邻居才重要。 然而，这里的房屋形成**圆形排列**，这引入了额外的限制：

 - **第一栋房子和最后一栋房子也是邻居**。 
- 这意味着我们不能同时抢劫`nums[0]`和`nums[n - 1]`。 

输入包括：

 -`nums`，一个整数数组，其中：

 -`nums[i]`代表着里面的钱`i-th`房子。 
-`nums.length`介于`1`和`100`。 
- 每栋房屋包含之间`0`和`1000`美元。 

输出是一个整数，表示**在不违反邻接约束的情况下可以抢劫的最大金钱**。 

约束条件相对较小，仅达到`100`房屋，甚至意味着`O(n²)`解决方案在技术上可行。 然而，这个问题是为了测试动态规划推理而设计的，期望得到一个最优的线性解。 

预先考虑一些边缘情况很重要。 

如果只有**一栋房子**，那么就不用担心邻居了，我们就直接抢劫那栋房子。 

如果有**两栋房子**，由于它们在圈内相邻，我们只能抢其中一栋。 

另一个棘手的情况是由于圆形布局而发生的。 原始房屋抢劫者逻辑的天真实现可能会意外地抢劫第一座和最后一座房屋，这将违反规则。 正确处理这一问题是该问题的核心挑战。 

## 方法

 ### 蛮力方法

 暴力方法探索**每一个可能的房屋子集**并检查它是否形成有效的抢劫计划。 

对于每个房子，我们有两种选择：

 1. 抢夺。 
2. 跳过它。 

这将创建一个递归决策树，大致如下`2^n`的可能性。 在每一步中，我们都确保不会选择任何相邻的房屋，包括第一栋房屋和最后一座房屋之间的圆形邻接。 

此方法保证了正确性，因为它会详尽地评估每个有效的抢劫组合并返回最大总金额。 

然而，它太慢了。 由于每个房子的可能性数量都会增加一倍，因此运行时间会呈指数级增长，这使得它不切实际，因为`n`成长。 

### 最佳解决方案的关键见解

 关键的观察结果是，与最初的入室抢劫问题相比，圆形排列**仅产生一个额外的限制**：

 > 我们不能同时抢劫第一栋和最后一栋房子。 

这意味着每个有效的解决方案都属于以下两个类别之一：

 1. **排除第一栋房子**，让我们可以自由考虑最后一栋房子。 
2. **排除最后一间房子**，让我们可以自由考虑第一间房子。 

一旦我们做出这个选择，问题就变成了原来的**线性入室抢劫**问题。 

对于线性房屋街道，我们使用动态规划：

 对于每栋房子，我们决定：

 - 抢劫这所房子并将其价值添加到两所房子的最佳结果中。 
- 跳过这所房子并保留之前的最佳成绩。 

其递归式为：$$dp[i] = \max(dp[i-1], dp[i-2] + nums[i])$$我们不需要存储整个 DP 数组，而只需要前两个状态，从而将空间复杂度降低到`O(1)`。 

我们计算：

 - 最大抢劫额`nums[1:]`（先跳过）
 - 最大抢劫额`nums[:-1]`（跳过最后）

 然后取这两个结果中的最大值。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 递归探索每个有效的抢劫组合 |
 | 最佳| O(n) | O(1) | O(1) | 将圆分成两个线性强盗问题 |

 ## 算法演练

 1. **处理单屋边缘情况**

 如果`nums`仅包含一栋房屋，立即返回其价值。 因为没有邻居，所以抢劫从来不违反规定。 
2. **为线性版本定义辅助函数**

 创建一个辅助函数来解决直线房屋的原始盗屋问题。 

该函数跟踪两个值：

 -`prev_two`，两栋房子前的最佳金额。 
-`prev_one`，来自前一栋房屋的最佳金额。 

对于每栋房子，计算：```
current = max(prev_one, prev_two + house_value)
```这意味着：

 - 跳过当前房子并保留之前的最佳结果。 
- 抢夺当前的房子并将其添加到向后两个位置的最佳结果中。 
3. **解决两个有效场景**

 因为第一栋房子和最后一栋房子不能同时被抢劫，所以计算：

 - 从家里抢劫`0`到`n - 2`（不包括最后一个）
 - 从家里抢劫`1`到`n - 1`（排除第一个）

 现在，这些都是标准的线性入室抢劫问题。 
4. **返回更好的结果**

 取两种情况中的最大值。 

这保证了答案尊重循环约束，同时仍然最大化利润。 

### 为什么它有效

 每一个有效的抢劫计划都必须排除第一所房子或最后一所房子，因为抢劫这两所房子都是非法的。 通过独立解决这两种可能性，我们覆盖了所有有效的解决方案，没有重叠。 辅助函数使用动态规划正确计算线性排列的最佳抢劫金额，其中每个状态代表迄今为止可实现的最佳结果。 取两个线性情况中的最大值可以保证全局最优解。 

## Python 解决方案```python
from typing import List

class Solution:
    def rob(self, nums: List[int]) -> int:
        def rob_linear(houses: List[int]) -> int:
            prev_two = 0
            prev_one = 0

            for money in houses:
                current = max(prev_one, prev_two + money)
                prev_two = prev_one
                prev_one = current

            return prev_one

        if len(nums) == 1:
            return nums[0]

        exclude_last = rob_linear(nums[:-1])
        exclude_first = rob_linear(nums[1:])

        return max(exclude_last, exclude_first)
```实现首先定义一个辅助函数，`rob_linear`，它解决了一条直线房屋街道的标准入室抢劫问题。 

在这个助手中，我们避免使用完整的动态编程数组。 相反，我们只维护两个变量：

 -`prev_two`，代表两所房子之前的最佳结果。 
-`prev_one`，代表上一所房子之前的最好成绩。 

对于每栋房子，如果我们抢劫或跳过该房子，我们会计算出最好的结果。 变量`current`存储这个决定：```python
max(prev_one, prev_two + money)
```计算当前状态后，我们将变量向前移动，以便它们代表下一次迭代。 

在辅助函数之外，我们首先处理只有一栋房子的边缘情况。 

然后我们评估两个有效的循环场景：

 - 不包括最后使用的房屋`nums[:-1]`- 不包括第一间使用的房屋`nums[1:]`由于这些现在是线性排列，因此我们将辅助函数应用于两者并返回较大的结果。 

## 解决方案```go
func rob(nums []int) int {
	if len(nums) == 1 {
		return nums[0]
	}

	robLinear := func(houses []int) int {
		prevTwo := 0
		prevOne := 0

		for _, money := range houses {
			current := max(prevOne, prevTwo+money)
			prevTwo = prevOne
			prevOne = current
		}

		return prevOne
	}

	excludeLast := robLinear(nums[:len(nums)-1])
	excludeFirst := robLinear(nums[1:])

	return max(excludeLast, excludeFirst)
}

func max(a, b int) int {
	if a > b {
		return a
	}
	return b
}
```Go 实现遵循与 Python 版本相同的算法结构。 本地辅助函数，`robLinear`，使用恒定的额外空间解决问题的线性版本。 

Go 特有的一个区别是 Go 不提供内置的`max`整数函数，因此我们手动定义一个助手。 

切片用于创建两个有效的子问题：

 -`nums[:len(nums)-1]`不包括最后一个房子。 
-`nums[1:]`不包括第一套房子。 

由于该问题保证至少存在一栋房屋，因此我们只需要显式处理`len(nums) == 1`案件。 

Go 切片是底层数组的轻量级视图，因此创建子范围不会复制数据，从而使这种方法变得高效。

 ## 边缘情况

 ### 独栋别墅

 当`nums = [x]`，从技术上讲，第一个房子和最后一个房子是同一栋房子。 有缺陷的实现可能会尝试将问题分解为`nums[:-1]`和`nums[1:]`，产生空数组并返回`0`。 该实现显式检查`len(nums) == 1`并立即返还房屋价值。 

### 第一个和最后一个房子的冲突

 一个常见的错误是将原始的 House Robber 算法直接应用于圆形数组。 例如：```
[100, 1, 1, 100]
```线性解决方案会错误地选择两者`100`值`200`，但那些房子在圆圈中是相邻的。 通过解决两个单独的场景，排除第一个或最后一个房子，该实现避免了非法组合并正确返回`101`。 

### 两栋房子

 当恰好有两栋房子时，由于圆的缘故，两栋房子都是相邻的。 粗心的实现可能会意外地独立对待它们并对两个值求和。 相反，分割自然会变成：```
nums[:-1]
nums[1:]
```每个只包含一栋房子，算法正确返回两个值中的最大值。
