 **难度：** 🟡 中等
 **主题：** 数组、分而治之、排序、堆（优先级队列）、快速选择

 ## 解决方案

 ## 问题理解

 问题要求我们找到`kth`未排序整数数组中的最大元素。 重要的细节是我们正在寻找出现在`kth`如果数组按降序排序，则位置。 我们不是在寻找`kth`独特的价值。 

例如，考虑数组`[3,2,3,1,2,4,5,5,6]`和`k = 4`。 如果我们按降序对数组进行排序，我们会得到：```
[6,5,5,4,3,3,2,2,1]
```第四大元素是`4`。 

输入包括：

 -`nums`，可能包含重复值的整数数组
 -`k`，一个整数，表示我们想要的最大元素

 输出是一个整数，表示`kth`最大的元素。 

约束条件很重要：

 -`1 <= k <= nums.length <= 10^5`-`-10^4 <= nums[i] <= 10^4`数组大小为`10^5`意味着低效的算法可能会变得太慢。 诸如重复扫描阵列之类的二次解决方案无法很好地扩展。 该问题还明确询问我们是否可以在不对数组进行完全排序的情况下解决它，这强烈表明需要更有效的选择算法。 

一些边缘情况很重要：

 - 具有重复值的数组，因为`kth`最大基于排序位置，而不是独特性
 - 只有一个元素的数组
 - 情况`k = 1`，这意味着我们需要最大元素
 - 情况`k = len(nums)`，这意味着我们需要最小元素
 - 负数
 - 已经排序或反向排序的数组，这可能会暴露糟糕的主元选择策略的弱点

 ## 方法

 ### 蛮力方法

 最直接的解决方案是将数组按降序排序并返回索引处的元素`k - 1`。 

这是有效的，因为排序将每个元素放入其确切的排名位置。 排序后，将`kth`最大的元素可以立即访问。 

例如：```
nums = [3,2,1,5,6,4]
sorted descending = [6,5,4,3,2,1]
k = 2
answer = 5
```这种方法简单正确，但是对整个数组进行排序有成本`O(n log n)`时间。 由于该问题仅要求一个已排序的元素，因此对所有元素进行完全排序会做不必要的工作。 

### 最佳方法，快速选择

 关键的见解是我们不需要对整个数组进行排序。 我们只需要正确定位一个元素。 

Quickselect 基于与 Quicksort 相同的分区思想。 Quickselect 不会对两半进行递归排序，而是仅探索包含目标索引的一侧。 

该算法的工作原理如下：

 - 选择一个枢轴
 - 对数组进行分区：

 - 较大的元素位于一侧
 - 较小的元素在另一侧
 - 确定枢轴结束的位置
 - 如果枢轴恰好位于目标位置，则将其返回
 - 否则仅递归到一侧

 这将平均时间复杂度降低到`O(n)`因为每个分区操作都会消除大约一半的剩余搜索空间。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n log n) | O(n log n) | O(1) 或 O(n) 取决于排序 | 即使只需要一个元素，也对数组进行完全排序 |
 | 最优、快速选择 | 平均 O(n)，最差 O(n²) | O(1) 迭代或 O(log n) 递归 | 仅对数组的必要部分进行分区 |

 ## 算法演练

 我们将使用 Quickselect 来查找`kth`最大的元素。 

与其直接按降序思考，通常更容易将问题转换为按升序排序查找索引。 

如果数组长度是`n`， 然后：```
target index = n - k
```这对应于元素按升序占据的位置。 

### 逐步算法

 1. 转换`k`进入目标索引。 

如果数组长度是`n`，那么`kth`最大元素对应索引`n - k`按升序排列。 

例子：```
nums = [3,2,1,5,6,4]
n = 6
k = 2
target = 6 - 2 = 4
```2. 选择一个主元元素。 

从当前子数组中选择一个主元。 许多实现使用最右边的元素，因为它简化了分区。 
3. 围绕枢轴对阵列进行分区。 

重新排列元素以便：

 - 小于枢轴的元素位于左侧
 - 大于或等于主元的元素在右侧

 分区后，枢轴被放置到其最终排序位置。 
4. 将主元索引与目标索引进行比较。 

- 如果它们相等，我们就找到了答案
 - 如果枢轴索引小于目标，则搜索右侧
 - 如果枢轴索引大于目标，则搜索左侧
 5. 重复此操作，直到枢轴落在目标索引上。 

由于每个分区都缩小了搜索空间，因此算法收敛得很快。 

### 为什么它有效

 分区保证左侧的每个元素都小于主元，而右侧的每个元素都大于或等于。 因此，一旦枢轴落在索引处`p`，它正是出现在位置的元素`p`在完全排序的数组中。 

由于该算法反复将搜索空间缩小到目标索引，因此它最终将正确的元素放入其最终排序位置并返回。 

## Python 解决方案```python
from typing import List
import random

class Solution:
    def findKthLargest(self, nums: List[int], k: int) -> int:
        target = len(nums) - k

        def partition(left: int, right: int) -> int:
            pivot_index = random.randint(left, right)
            pivot_value = nums[pivot_index]

            nums[pivot_index], nums[right] = nums[right], nums[pivot_index]

            store_index = left

            for i in range(left, right):
                if nums[i] < pivot_value:
                    nums[i], nums[store_index] = nums[store_index], nums[i]
                    store_index += 1

            nums[store_index], nums[right] = nums[right], nums[store_index]

            return store_index

        left = 0
        right = len(nums) - 1

        while left <= right:
            pivot_index = partition(left, right)

            if pivot_index == target:
                return nums[pivot_index]
            elif pivot_index < target:
                left = pivot_index + 1
            else:
                right = pivot_index - 1

        return -1
```实现首先将问题从寻找`kth`查找索引处的元素的最大元素`len(nums) - k`按升序排列。 

这`partition`辅助函数执行核心快速选择操作。 选择随机主元来减少最坏情况性能的可能性。 枢轴暂时移动到子数组的末尾，因此分区变得更容易。 

该循环扫描子数组并将所有小于主元的元素移动到前面。 变量`store_index`跟踪下一个较小元素应放置的位置。 

分区完成后，枢轴被交换到正确的排序位置。 然后该函数返回主元的最终索引。 

主循环重复对数组进行分区并检查主元是否落在目标索引处。 根据结果​​，搜索空间会缩小到数组的左侧或右侧部分。 

一旦主元到达目标索引，算法就会停止，此时已经找到了正确的答案。 

## 解决方案```go
package main

import (
	"math/rand"
)

func findKthLargest(nums []int, k int) int {
	target := len(nums) - k

	var partition func(int, int) int

	partition = func(left int, right int) int {
		pivotIndex := rand.Intn(right-left+1) + left
		pivotValue := nums[pivotIndex]

		nums[pivotIndex], nums[right] = nums[right], nums[pivotIndex]

		storeIndex := left

		for i := left; i < right; i++ {
			if nums[i] < pivotValue {
				nums[i], nums[storeIndex] = nums[storeIndex], nums[i]
				storeIndex++
			}
		}

		nums[storeIndex], nums[right] = nums[right], nums[storeIndex]

		return storeIndex
	}

	left := 0
	right := len(nums) - 1

	for left <= right {
		pivotIndex := partition(left, right)

		if pivotIndex == target {
			return nums[pivotIndex]
		} else if pivotIndex < target {
			left = pivotIndex + 1
		} else {
			right = pivotIndex - 1
		}
	}

	return -1
}
```Go 的实现与 Python 版本非常相似。 Go 中的切片的行为与动态调整大小的数组类似，因此就地分区自然有效。 

一个显着的区别是随机数生成。 Go 使用`rand.Intn()`选择枢轴索引。 整数溢出在这里不是一个问题，因为约束足够小，可以轻松地适应 Go 的标准整数类型。 

该算法直接改变输入切片，就像 Python 实现改变输入列表一样。

 平均情况时间复杂度为`O(n)`因为每个分区操作都会丢弃大约一半的剩余元素。 这将创建类似于以下内容的重复：```
T(n) = T(n/2) + O(n)
```解析为线性时间。 

The worst case occurs when the pivot repeatedly ends up at one extreme, producing highly unbalanced partitions. Random pivot selection significantly reduces the likelihood of this scenario in practice.

 The algorithm uses constant extra space because all partitioning happens directly inside the input array.

 ## 边缘情况

 一种重要的边缘情况是包含许多重复值的数组。 由于问题要求`kth`按排序位置而不是不同值排列的最大元素，重复项必须保留在排名中。 错误的实现可能会在分区期间意外删除重复项或错误地处理相等的值。 当前的实现自然地保留了重复项，因为分区直接比较值而不进行重复数据删除。 

另一个重要的情况是当`k = 1`或者`k = len(nums)`。 这些分别对应于查找最大和最小元素。 相差一错误在这里很常见，因为目标索引转换使用`len(nums) - k`。 该实现通过将排名直接映射到升序索引空间来正确处理此问题。 

已经排序或反向排序的数组也可能有问题。 确定性枢轴策略（例如始终选择第一个元素）可能会将快速选择降级为最坏情况`O(n²)`这些输入的行为。 该实现通过选择随机主元来降低这种风险，这在概率上保持分区平衡。 

最后一种边缘情况涉及非常小的数组，尤其是长度为 1 的数组。 如果边界条件不正确，递归或迭代分区逻辑很容易失败。 该实现可以安全地处理这些情况，因为一旦主元到达唯一有效的索引，搜索循环就会立即终止。
