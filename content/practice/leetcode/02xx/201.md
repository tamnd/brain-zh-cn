[LeetCode 问题 201](https://leetcode.com/problems/bitwise-and-of-numbers-range/)

 **难度：** 🟡 中等
 **主题：** 位操作

 ## 解决方案

 ## 问题理解

 该问题要求我们计算包含范围内的每个整数的按位与`[left, right]`。 

例如，如果`left = 5`和`right = 7`，范围内的数字为：```
5 = 101
6 = 110
7 = 111
```对所有值应用按位 AND：```
101
110
111
---
100 = 4
```所以答案是`4`。 

输入由两个非负整数组成：

 -`left`，范围的开始
 -`right`, 范围的末尾

 输出是一个整数，表示它们之间每个数字的累积按位与。 

约束条件很重要：

 -`0 <= left <= right <= 2^31 - 1`这意味着范围可能非常大。 迭代每个数字的简单解决方案可能会处理数十亿个整数，这太慢了。 

关键的观察结果是，随着包含的数字越多，按位 AND 就会变得更小。 任何改变的位位置`0`到`1`或者`1`到`0`该范围内的任何地方最终都会成为`0`在最终的答案中。 

一些边缘情况很重要：

 - 当`left == right`，答案就是这个数字。 
- 当范围跨越二次方边界时，许多较高位变为零。 
- 什么时候`left = 0`，答案总是`0`因为 AND 与零产生零。 
- 非常大的范围经常会崩溃`0`很快，因为许多位在范围内波动。 

## 方法

 ### 蛮力方法

 最直接的方法就是迭代`left`到`right`并连续应用按位与。 

我们可以初始化：```
result = left
```然后对于每个数字`left + 1`到`right`：```
result &= current_number
```这是有效的，因为按位 AND 是关联的：```
(a & b) & c == a & (b & c)
```因此按顺序处理数字会产生正确的答案。 

然而，这种方法对于问题的限制来说太慢了。 如果范围跨越数十亿个数字，则该算法将需要数十亿次运算。 

### 最佳方法

 关键的见解是，最终结果仅保留共享的公共二进制前缀`left`和`right`。 

考虑：```
left  = 101101
right = 101111
```共享前缀是：```
101
```其余位在整个范围内变化。 任何变化的位最终都会变成`0`在 AND 过程中。 

因此，答案只是公共前缀后跟零。 

查找此公共前缀的一种优雅方法是：

 - 反复右移两个数字，直到它们相等
 - 计算执行了多少次轮班
 - 将公共值向左移动相同的量

 这会删除不同的后缀位并仅保留稳定的前缀。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(右 - 左) | O(1) | O(1) | 迭代范围 | 中的每个数字
 | 最佳| O(32) | O(1) | O(1) | 查找公共二进制前缀 |

 ## 算法演练

 1. 初始化一个名为`shift_count`到`0`。 

该计数器跟踪我们从两个数字的右侧删除了多少位。 
2. 比较`left`和`right`。 

如果它们已经相等，则它们已经共享相同的前缀并且不需要更多处理。 
3.同时`left != right`，将两个值右移一位。 

右移删除最低有效位。 我们继续删除位，直到两个数字变得相同。 

这是可行的，因为不同的后缀位无法在整个范围内进行 AND 运算。 
4. 增量`shift_count`每次轮班后。 

稍后我们需要此信息，以便我们可以将共享前缀恢复到其原始位置。 
5.一次`left == right`，我们找到了共同的前缀。 

此时，所有不同的位都已被丢弃。 
6. 将公共前缀左移`shift_count`。 

这会将前缀恢复到其原始位置，同时用零填充剩余位。 
7. 返回最终值。 

### 为什么它有效

 该算法依赖于范围内按位与的基本属性。 

如果任何位位置在范围内发生变化`[left, right]`，那么至少有一个数包含`0`在该位置，导致该位的最终 AND 结果变为`0`。 

只有在整个范围内保持相同的位才能生存。 这些位构成了公共二进制前缀`left`和`right`。 

通过右移删除不同的后缀位并随后恢复前缀，该算法可以准确计算在整个范围内保持稳定的位。 

## Python 解决方案```python
class Solution:
    def rangeBitwiseAnd(self, left: int, right: int) -> int:
        shift_count = 0

        while left != right:
            left >>= 1
            right >>= 1
            shift_count += 1

        return left << shift_count
```实现直接遵循算法。 

变量`shift_count`跟踪两个数字右移的次数。 

这`while`循环继续直到`left`和`right`变得平等。 每次迭代都会从右侧删除一个不同的位。 

一旦两个号码匹配，共享前缀就被隔离。 最后一行使用左移将该前缀恢复到其原始位位置。 

该解决方案仅使用恒定的额外空间，并且最多执行 31 到 32 次迭代，因为整数受 32 位限制。 

## 解决方案```go
func rangeBitwiseAnd(left int, right int) int {
    shiftCount := 0

    for left != right {
        left >>= 1
        right >>= 1
        shiftCount++
    }

    return left << shiftCount
}
```Go 实现与 Python 版本几乎相同。 

Go 使用显式变量声明`:=`，并且循环语法略有不同。 对于非负整数，位移位的行为方式相同。 

由于该问题保证值在 32 位整数限制内，因此在此实现中不存在溢出问题。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`left == right`。 在这种情况下，该范围仅包含一个数字，因此答案必须等于该数字本身。 一些不正确的实现会继续进行不必要的移动或意外地更改该值。 这个实现自然地处理这种情况，因为循环条件`left != right`立即失败。 

当范围包含零时，会发生另一种关键的边缘情况。 由于与零的按位“与”总是产生零，因此任何从零开始的范围都必须返回零。 暴力实现仍然有效，但浪费时间。 最佳实现会快速移动两个数字，直到它们变为零，从而正确生成结果。 

当范围跨越二次方边界时，会出现一个特别棘手的情况，例如`[31, 32]`。 以二进制表示：```
31 = 011111
32 = 100000
```没有前缀位保持稳定，因此答案为零。 许多简单的优化在这种转换上失败，因为它们没有正确考虑高位变化。 移位方法可以完美地处理这个问题，因为所有不同的位都会被删除，直到两个数字收敛到零。 

另一个微妙的边缘情况涉及非常大的范围。 例如：```
left = 1
right = 2147483647
```遍历每个数字是不可行的。 最佳算法仍然高效，因为它仅执行恒定数量的位移，与范围大小无关。
