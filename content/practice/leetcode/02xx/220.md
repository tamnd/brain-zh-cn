[LeetCode 第 220 题](https://leetcode.com/problems/contains-duplicate-iii/)

 **难度：** 🔴难
 **主题：** 数组、滑动窗口、排序、桶排序、有序集

 ## 解决方案

 ## 问题理解

 问题问是否存在一对不同的索引`(i, j)`在数组中，同时满足两个条件。 

第一个条件是关于索引距离：$$|i - j| \leq indexDiff$$这意味着数组中的两个元素必须相对靠近。 

第二个条件是关于值距离：$$|nums[i] - nums[j]| \leq valueDiff$$这意味着这些值本身在数值上也必须接近。 

我们需要返回`true`如果至少存在一对有效的。 否则，我们返回`false`。 

输入包括：

 -`nums`，一个整数数组，可能包含正数、负数和重复项。 
-`indexDiff`，这限制了索引之间的距离。 
-`valueDiff`，这限制了值的差异程度。 

限制条件很大：

 -`nums.length`可以达到`100000`- 值的范围可以是`-10^9`到`10^9`这些约束立即排除了二次解。 简单的成对比较需要检查：$$\frac{n(n-1)}{2}$$对，当`n = 100000`。 

另一个重要的观察是我们只关心索引窗口大小的元素`indexDiff`。 一旦某个元素变得比该距离更远，它就永远无法与当前元素组成有效的对。 

一些边缘情况很重要：

 -`valueDiff = 0`，这意味着我们正在滑动窗口内有效地寻找重复项。 
- 负数，因为整数除法的存储桶计算可能会变得棘手。 
- 非常大的正值和负值，这意味着在像 Go 这样的语言中必须小心处理溢出。 
- 具有重复值的数组出现在允许的索引范围之外。 
- 非常小的窗户，例如`indexDiff = 1`。 

## 方法

 ### 蛮力

 最简单的方法是检查每对有效的索引。 

对于每个索引`i`，我们检查每个索引`j`这样：$$i < j \leq i + indexDiff$$对于每一对，我们计算：$$|nums[i] - nums[j]|$$如果差异最多为`valueDiff`，我们返回`true`。 

这是有效的，因为它显式地检查满足索引约束的每个可能的候选对。 

然而，最坏的情况发生在`indexDiff`接近于`n`。 在这种情况下，我们可以比较几乎每一对元素，从而得出：$$O(n^2)$$时间复杂度。 

和`100000`元素，这变得不可行。 

### 最优方法，带滑动窗口的桶排序

 关键的见解是，如果两个数字最多相差`valueDiff`，那么他们必须：

 - 落入同一个桶中，或者
 - 落入相邻的桶中

 如果我们将存储桶大小定义为：$$bucketSize = valueDiff + 1$$为什么这有效？ 

假设每个桶覆盖一个宽度的数字区间`valueDiff + 1`。 

那么同一个桶内的任意两个数字最多相差`valueDiff`。 

例如，如果`valueDiff = 3`，则桶大小为`4`：

 - 桶 0 包含`[0,1,2,3]`- 桶 1 包含`[4,5,6,7]`同一桶内的任意两个值最多相差`3`。 

我们从左到右处理数组，同时只保留最后一个`indexDiff`我们的桶结构中的元素。 这会在有效索引上创建一个滑动窗口。 

对于每个数字：

 1. 计算其桶ID。 
2. 检查该桶是否已包含数字。 
3. 检查相邻的存储桶，因为接近的值可能跨越存储桶边界。 
4. 插入当前值。 
5. 移除离开滑动窗口的元件。 

这将问题简化为每个元素近似恒定的工作。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * indexDiff) 最坏情况 O(n²) | O(1) | O(1) | 直接检查每对符合条件的配对 |
 | 最佳| O(n) | O(indexDiff) | O(indexDiff) | 使用水桶和滑动窗|

 ## 算法演练

 ### 基于桶的最优滑动窗口算法

 1. 定义桶大小为`valueDiff + 1`。 

我们不能使用`valueDiff`直接因为当`valueDiff = 0`，桶大小将变为零，这是无效的。 使用`valueDiff + 1`保证正铲斗宽度。 
2. 创建一个名为的哈希图`buckets`。 

键是桶ID，值是该桶中实际存储的数量。 

在任何时刻，地图仅包含当前大小的滑动窗口内的元素`indexDiff`。 
3. 从左到右迭代数组。 

对于每个值`num`，计算其桶ID。 

存储桶 ID 为：$$bucketId = \left\lfloor \frac{num}{bucketSize} \right\rfloor$$必须小心负数，因为整数除法在不同语言中的表现不同。 
4. 检查当前桶是否已经包含数字。 

如果是，则现有数字和当前数字最多相差`valueDiff`。 

我们可以立即返回`true`。 
5. 检查相邻的桶。 

即使两个数字不在同一个桶中，如果它们位于桶边界附近，它们仍然可以满足值约束。 

因此，我们还研究：

 -`bucketId - 1`-`bucketId + 1`如果任一相邻桶存在并且绝对差最多为`valueDiff`， 返回`true`。 
6. 将当前号码插入其存储桶中。 

所有检查通过后，存储当前值。 
7、保养推拉窗。 

一旦窗口大小超过`indexDiff`，删除超出范围的元素。 

具体来说，在处理索引时`i`， 消除：$$nums[i - indexDiff]$$因为任何未来的元素都会违反它的索引约束。 
8. 如果循环结束时没有找到有效的对，则返回`false`。 

### 为什么它有效

 该算法保持了桶映射恰好包含索引在范围内的元素的不变性`indexDiff`当前位置。 

因为每个桶都跨越`valueDiff + 1`连续整数，同一桶内的任意两个数字最多相差`valueDiff`。 

任何跨越存储桶边界的有效对都必须位于相邻的存储桶中，因此检查相邻的存储桶就足够了。 

因此，每个有效的候选对都会被检查，并且没有无效的对可以错误地满足条件。 

## Python 解决方案```python
from typing import List

class Solution:
    def containsNearbyAlmostDuplicate(
        self,
        nums: List[int],
        indexDiff: int,
        valueDiff: int
    ) -> bool:

        bucket_size = valueDiff + 1
        buckets = {}

        for i, num in enumerate(nums):

            bucket_id = num // bucket_size

            # Same bucket
            if bucket_id in buckets:
                return True

            # Left neighbor bucket
            if (
                bucket_id - 1 in buckets and
                abs(num - buckets[bucket_id - 1]) <= valueDiff
            ):
                return True

            # Right neighbor bucket
            if (
                bucket_id + 1 in buckets and
                abs(num - buckets[bucket_id + 1]) <= valueDiff
            ):
                return True

            buckets[bucket_id] = num

            # Remove element outside sliding window
            if i >= indexDiff:
                old_num = nums[i - indexDiff]
                old_bucket_id = old_num // bucket_size
                del buckets[old_bucket_id]

        return False
```实现首先将存储桶大小计算为`valueDiff + 1`。 

这`buckets`字典每个桶最多存储一个值。 这是有效的，因为如果存储桶已经包含一个值，那么进入同一存储桶的任何新值都会自动满足所需的差异条件。 

对于每个元素，我们使用整数除法计算其存储桶 ID。 Python 的楼层划分正确处理负数，从而简化了实现。 

我们首先检查当前的存储桶。 然后我们检查相邻的桶，因为桶边界附近的值最多可能仍然不同`valueDiff`。 

如果没有找到匹配项，我们将当前数字插入到其存储桶中。 

最后一部分维护滑动窗口。 一旦窗口超过`indexDiff`，我们从桶中删除最旧的元素，以便所有剩余元素满足索引约束。 

## 解决方案```go
package main

import "math"

func containsNearbyAlmostDuplicate(nums []int, indexDiff int, valueDiff int) bool {
	bucketSize := int64(valueDiff) + 1
	buckets := make(map[int64]int64)

	getBucketID := func(num int64) int64 {
		if num >= 0 {
			return num / bucketSize
		}
		return ((num + 1) / bucketSize) - 1
	}

	for i, num := range nums {
		n := int64(num)
		bucketID := getBucketID(n)

		// Same bucket
		if _, exists := buckets[bucketID]; exists {
			return true
		}

		// Left neighbor
		if val, exists := buckets[bucketID-1]; exists {
			if math.Abs(float64(n-val)) <= float64(valueDiff) {
				return true
			}
		}

		// Right neighbor
		if val, exists := buckets[bucketID+1]; exists {
			if math.Abs(float64(n-val)) <= float64(valueDiff) {
				return true
			}
		}

		buckets[bucketID] = n

		// Remove old element outside window
		if i >= indexDiff {
			oldNum := int64(nums[i-indexDiff])
			oldBucketID := getBucketID(oldNum)
			delete(buckets, oldBucketID)
		}
	}

	return false
}
```Go 实现在结构上与 Python 解决方案相同，但有几个特定于语言的注意事项。 

Go 整数除法向零截断，而不是向负无穷大取整。 因此，负数需要在`getBucketID`辅助功能。 

所有算术运算均使用`int64`以避免在使用接近的值时溢出`10^9`。 

Go Map 用于存储桶，并且`delete`删除离开滑动窗口的元素。

 ## 边缘情况

 ###`valueDiff = 0`什么时候`valueDiff`为零，问题就相当于在滑动窗口内查找重复项。 

这种情况很容易处理不当，因为如果我们使用桶大小将变为零`valueDiff`直接地。 该实现通过定义以下内容来避免被零除错误：$$bucketSize = valueDiff + 1$$这保证了有效的铲斗宽度。 

### 负数

 负值可能会破坏简单的存储桶计算，因为整数除法在不同语言中的行为不同。 

Python 会自动降低负除法，这自然适用于存储桶分区。 Go 向零截断，因此该实现包括一个自定义辅助函数来正确模拟楼层划分行为。 

如果没有这种校正，桶边界附近的负值可能会被放入不正确的桶中。 

### 元素离开滑动窗口

 一个常见的错误是忘记删除旧元素，一旦它们比`indexDiff`离开。 

如果过时的元素保留在存储桶映射中，则算法可能会错误地匹配索引违反问题约束的元素。 

该实现删除了：```
nums[i - indexDiff]
```一旦窗口变得太大，确保每个存储的元素始终满足相对于当前索引的索引距离要求。
