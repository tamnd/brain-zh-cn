[LeetCode 第 739 题](https://leetcode.com/problems/daily-Temperatures/)

 **难度：** 🟡 中等
 **主题：** 数组、堆栈、单调堆栈

 ## 解决方案

 ## 问题理解

 问题给出了一个名为`temperatures`，其中每个元素代表特定日期记录的温度。 对于每一天，我们必须确定未来需要等待多少天才能出现更温暖的气温。 如果未来没有更高温度的一天，则该位置的答案应该是`0`。 

简单来说，对于每个索引`i`，我们想要找到第一个索引`j`这样：```
j > i and temperatures[j] > temperatures[i]
```存储在结果数组中位置处的值`i`那么应该是：```
j - i
```如果没有这样的`j`存在，结果依然存在`0`。 

例如，考虑：```
temperatures = [73,74,75,71,69,72,76,73]
```第一天，温度`73`，下一个较温暖的温度是`74`第二天，所以答案是`1`。 

适合有温度的日子`75`，下一个较温暖的温度是`76`，四天后发生，所以答案是`4`。 

约束条件很重要：```
1 <= temperatures.length <= 100000
30 <= temperatures[i] <= 100
```该数组最多可以包含`10^5`元素，这意味着低效的嵌套循环解决方案可能会变得太慢。 一个`O(n^2)`在最坏的情况下，算法可能需要数十亿次比较。 这强烈表明我们需要一个线性或近线性的解决方案。 

尽早识别一些边缘情况很重要：

 - 严格递减的数组，例如`[90,80,70]`，其中每个答案都是`0`- 严格递增的数组，例如`[30,40,50]`，其中除了最后一个之外的每个答案都是`1`- 重复的温度，例如`[70,70,70]`，其中相同的值不算更温暖
 - 单元素数组，其中答案必须始终是`[0]`该问题保证输入数组非空，并且所有温度都在一个小的有效范围内。 

## 方法

 ### 蛮力方法

 最直接的解决方案是每天独立检查并向前搜索，直到找到更温暖的温度。 

对于每个索引`i`，我们迭代所有未来的指数`j > i`。 一旦我们遇到温度大于`temperatures[i]`，我们存储`j - i`在答案数组中并停止搜索那一天。 

这种方法是正确的，因为它明确地按顺序检查未来每个可能的日子，确保找到第一个温暖的日子。 

然而，在最坏的情况下，性能很差。 考虑一个递减序列，例如：```
[100,99,98,97,...]
```对于第一个元素，我们几乎扫描整个数组。 对于第二个，我们再次扫描几乎整个剩余数组。 这种重复的工作导致了二次时间复杂度。 

高达`100000`元素，一个`O(n^2)`解决办法太慢了。 

### 最优方法，单调堆栈

 关键的观察是，在寻找下一个温暖的日子时，我们会反复将温度与未来值进行比较。 其中许多比较都是多余的。 

我们可以维护一堆尚未找到较温暖温度的索引，而不是重复向前扫描。 

堆栈保持温度递减的顺序。 这就是为什么该结构被称为单调递减堆栈。 

当我们处理每个温度时：

 - 如果当前温度高于堆栈顶部的温度，我们就为堆栈上的索引找到了下一个更温暖的日子。 
- 当当前温度较高时，我们会反复从堆栈中弹出。 
- 对于每个弹出的索引，答案变为当前索引和弹出的索引之间的差。 
- 解决所有较小的温度后，我们将当前索引压入堆栈。 

这是有效的，因为每个索引最多进入和离开堆栈一次，产生一个`O(n)`解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 每天向前扫描，直到找到更温暖的温度 |
 | 最佳| O(n) | O(n) | 使用单调递减堆栈来避免重复扫描 |

 ## 算法演练

 1. 创建一个用零初始化的结果数组。 

每个位置开始为`0`因为如果不存在更温暖的日子，答案应该保持不变`0`。 
2. 创建一个空堆栈来存储索引。 

我们存储指数而不是温度，因为我们最终需要计算天之间的距离。 
3. 从左到右迭代温度数组。 

在每一步中，当前索引代表相对于已存储在堆栈中的所有索引的未来一天。 
4. 当堆栈不为空且当前温度大于堆栈顶部索引处的温度时，解决该等待日。 

这意味着我们终于找到了存储在堆栈顶部的当天较温暖的温度。 
5. 从堆栈中弹出顶部索引。 

令这个弹出索引为`previous_index`。 
6. 计算等待时间。 

等待天数为：```
current_index - previous_index
```将此值存储在答案数组中。 
7. 当当前温度高于烟囱顶部时继续弹出。 

当前的一个温度可能会解决多个较早的日子。 
8. 将当前索引压入堆栈。 

这一天现在正在等待未来更温暖的气温。 
9. 处理完整个数组后，堆栈中仍然存在的任何索引都没有未来更温暖的一天。 

他们的答案仍然正确`0`。 

### 为什么它有效

 堆栈始终以温度递减的顺序维护索引。 堆栈中剩余的任何索引尚未遇到未来更温暖的温度。 

当出现较暖的气温时，它会立即解决最近未解决的较冷的一天。 由于索引是从左到右处理的，因此遇到的第一个较温暖的温度保证是正确的答案。 

每个索引推送一次、弹出一次，保证正确性和效率。 

## Python 解决方案```python
from typing import List

class Solution:
    def dailyTemperatures(self, temperatures: List[int]) -> List[int]:
        n = len(temperatures)

        # Result array initialized with 0
        answer = [0] * n

        # Stack stores indices
        stack = []

        for current_index, current_temp in enumerate(temperatures):

            # Resolve all colder previous temperatures
            while stack and current_temp > temperatures[stack[-1]]:
                previous_index = stack.pop()
                answer[previous_index] = current_index - previous_index

            # Current day waits for a warmer future day
            stack.append(current_index)

        return answer
```实现首先创建用零填充的结果数组。 这符合问题要求，因为未来温度没有升高的任何一天都应该保留`0`。 

堆栈存储索引而不是原始温度。 这很重要，因为最终答案需要指数之间的距离，而不仅仅是温度比较。 

该循环使用从左到右处理温度`enumerate`，给出当前指数和温度。 

在循环内部，`while`条件检查当前温度是否比堆栈顶部索引表示的温度高。 如果是，我们会弹出该索引，因为我们发现了下一个温暖的日子。 

等待时间的计算方法为：```python
current_index - previous_index
```解决所有较冷的温度后，当前索引被推入堆栈，以便未来的温度可以解决它。 

最后，仍然存在未解决的索引`0`，这已经是正确的，因为答案数组是用零初始化的。 

## 解决方案```go
func dailyTemperatures(temperatures []int) []int {
	n := len(temperatures)

	// Result array initialized with 0
	answer := make([]int, n)

	// Stack stores indices
	stack := []int{}

	for currentIndex, currentTemp := range temperatures {

		// Resolve all colder previous temperatures
		for len(stack) > 0 &&
			currentTemp > temperatures[stack[len(stack)-1]] {

			previousIndex := stack[len(stack)-1]
			stack = stack[:len(stack)-1]

			answer[previousIndex] = currentIndex - previousIndex
		}

		// Current day waits for a warmer future day
		stack = append(stack, currentIndex)
	}

	return answer
}
```Go 实现遵循与 Python 版本相同的逻辑。 主要区别在于堆栈管理。 

Go 没有内置的堆栈类型，因此使用切片来代替。 推送是通过`append`，弹出是通过切掉最后一个元素来执行的。 

结果切片使用以下方式初始化：```go
make([]int, n)
```它会自动用零填充它。 

不存在整数溢出问题，因为最大索引差异最多为`100000`，完全在 Go 的整数范围内。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个索引最多从堆栈中压入和弹出一次 |
 | 空间| O(n) | 在最坏的情况下，堆栈可能包含最多所有索引 |

 重要的观察是，尽管该算法包含嵌套`while`循环中，每个元素只能从堆栈中删除一次。 这意味着整个执行过程中堆栈操作的总数是线性的。 

在最坏的情况下，例如严格递减的数组，所有索引都保留在堆栈中，需要`O(n)`额外的空间。

 ## 边缘情况

 严格递减数组是最重要的边缘情况之一。 例如：```
[90,80,70,60]
```幼稚的实现可能会意外地搜索过去的数组边界或错误地重用以前的结果。 在单调堆栈解决方案中，每个索引都保留在堆栈中，因为不会出现更高的温度。 由于答案数组是用零初始化的，因此最终结果自动正确。 

相同的温度是错误的另一个常见来源。 考虑：```
[70,70,70]
```这个问题需要一个严格更高的温度，而不是相等的温度。 这意味着比较必须使用`>`而不是`>=`。 该实现正确地在堆栈中保持相同的温度，因为相同的值不满足较温暖的条件。 

单元素数组是可能的最小有效输入：```
[50]
```没有未来的一天可以比较，所以答案一定是`[0]`。 该算法自然地处理这个问题，因为循环运行一次，索引被推入堆栈，并且没有找到更温暖的日子。 

当前几天气温升高时，会出现另一种微妙的情况，例如：```
[75,74,73,80]
```什么时候`80`处理后，算法会重复从堆栈中弹出索引并更新所有相应的答案。 这`while`循环在这里是必不可少的。 仅使用单个`if`语句将无法正确解决所有未决的较冷温度。
