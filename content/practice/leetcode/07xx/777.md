[LeetCode 第 777 题](https://leetcode.com/problems/swap-adjacent-in-lr-string/)

 **难度：** 🟡 中等
 **主题：** 两个指针，字符串

 ## 解决方案

 ## 问题理解

 这个问题给了我们两个字符串，`start`和`result`，两者都只包含字符`'L'`,`'R'`， 和`'X'`。 我们被允许改变`start`仅使用两种移动的字符串：

 - 更换`"XL"`和`"LX"`- 代替`"RX"`和`"XR"`目的是确定是否可以转型`start`进入`result`在应用任意数量的这些有效动作之后。 

为了更清楚地理解问题，它有助于解释角色在运动方面的含义。 

人物`'L'`只能向左移动，因为唯一的规则涉及`'L'`是`"XL" → "LX"`。 这意味着`'L'`可以与一个交换`'X'`仅当`'X'`就在它的左边。 所以，`'L'`永远不能向右移动。 

同样，角色`'R'`只能向右移动，因为规则`"RX" → "XR"`允许`'R'`与一个交换`'X'`立即在其右侧。 所以，`'R'`永远不能向左移动。 

人物`'X'`充当空占位符。 它并不是真正自行移动，而是，`'L'`和`'R'`穿过这些空旷的空间。 

预期输出是一个布尔值：

 - 返回`True`如果`start`可以转化为`result`- 返回`False`否则

 ### 约束分析

 字符串的长度可以大到`10^4`，这很重要，因为它立即表明昂贵的基于搜索的方法不太可能有效地工作。 

由于两个字符串具有相同的长度并且仅包含三个可能的字符，因此我们应该寻求线性或接近线性的时间解决方案。 

对所有可能的移动进行简单的模拟很快就会变得不可行，因为可达状态的数量呈指数级增长。 

### 重要的边缘案例

 当以下顺序时，会出现一种重要的边缘情况：`'L'`和`'R'`之间有所不同`start`和`result`。 由于移动仅与`'X'`，非的相对顺序`'X'`角色永远不会改变。 如果顺序不同，则无法进行转换。 

另一个边缘情况是当`'L'`出现在更靠右的位置`result`比在`start`。 自从`'L'`只能向左移动，这样的变换是无效的。 

同样，一个`'R'`无法向左移动。 如果一个`'R'`出现在更左侧`result`比在`start`，转型必然失败。 

案件仅涉及`'X'`， 例如`"X"`到`"X"`，应该返回`True`因为不需要转换。 

## 方法

 ### 蛮力方法

 蛮力解决方案将模拟从`start`字符串并尝试最终达到`result`。 

这可以建模为图搜索问题，其中：

 - 每个字符串配置都是一个节点
 - 每个有效的变换都是一条边
 - 我们寻找是否`result`可达

 我们可以使用广度优先搜索（BFS）或深度优先搜索（DFS）。 在每个状态，我们扫描字符串并通过应用生成所有可能的下一个状态：

 -`"XL" → "LX"`-`"RX" → "XR"`这保证了正确性，因为我们最终会探索每个可到达的配置。 

然而，这种方法太慢了。 可能的中间状态的数量会随着字符串长度呈指数增长，这使得它不切实际`n = 10^4`。 

### 最优方法、两个指针和运动约束

 关键的见解是我们根本不需要模拟动作。 

相反，我们可以推断运动限制。 

首先，观察删除所有`'X'`两个字符串中的字符必须产生相同的序列`'L'`和`'R'`。 因为只有相邻的交换`'X'`被允许，`'L'`和`'R'`永远不能互相穿过或改变顺序。 

例如：```
start  = "RXXLRXRXL"
result = "XRLXXRRLX"
```去除`'X'`给出：```
"RLRRL"
"RLRRL"
```顺序匹配，因此转换仍然是可能的。 

接下来，我们验证运动有效性：

 -`'L'`只能向左移动，因此它的索引在`result`必须小于或等于其索引`start`-`'R'`只能向右移动，因此它的索引在`result`必须大于或等于其索引`start`我们可以使用两个跳过的指针来有效地检查这一点`'X'`并仅比较有意义的字符。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 指数| 指数| 使用 BFS 或 DFS 探索变换状态 |
 | 最佳| O(n) | O(1) | O(1) | 使用两个指针和移动约束 |

 ## 算法演练

 1.初始化两个指针，`i`为了`start`和`j`为了`result`。 

这些指针将在跳过时遍历两个字符串`'X'`字符因为`'X'`只代表空白，不影响排序。 
2. 全部跳过`'X'`两个字符串中的字符。 

尽管`start[i] == 'X'`, 增量`i`。 

尽管`result[j] == 'X'`, 增量`j`。 

这确保我们只比较有意义的字符，`'L'`和`'R'`。 
3. 检查两个指针​​是否到达末尾。 

如果两个指针同时耗尽，则字符串是兼容的并且可以进行转换。 

如果只有一个指针到达末尾，则字符串包含不同数量的非`'X'`角色，使转变变得不可能。 
4. 比较当前字符。 

如果`start[i] != result[j]`， 返回`False`。 

这保证了相对顺序`'L'`和`'R'`保持不变。 
5. 验证移动规则。 

如果角色是`'L'`， 查看：```
i >= j
```自从`'L'`只能向左移动，不能向右移动。 

如果角色是`'R'`， 查看：```
i <= j
```自从`'R'`只能向右移动，不能向左移动。 
6. 向前移动两个指针。 

两者都增加`i`和`j`并继续扫描。 
7. 继续，直到完全处理两个字符串。 

### 为什么它有效

 该算法依赖于两个不变量。 

首先，相对顺序`'L'`和`'R'`无法改变，因为掉期只涉及`'X'`。 因此，两个字符串必须包含相同的非序列`'X'`人物。 

二是移动方向受到限制。`'L'`只能向左移动，并且`'R'`只能向右移动。 通过在遍历期间验证索引关系，我们保证每个角色移动都是物理上可实现的。 

由于这些是移动规则施加的唯一限制，满足这两个条件保证了转换是可能的。 

## Python 解决方案```python
class Solution:
    def canTransform(self, start: str, result: str) -> bool:
        n = len(start)
        i = 0
        j = 0

        while i < n or j < n:
            while i < n and start[i] == 'X':
                i += 1

            while j < n and result[j] == 'X':
                j += 1

            if i == n and j == n:
                return True

            if i == n or j == n:
                return False

            if start[i] != result[j]:
                return False

            if start[i] == 'L' and i < j:
                return False

            if start[i] == 'R' and i > j:
                return False

            i += 1
            j += 1

        return True
```### 实现说明

 实现首先初始化两个指针，`i`和`j`，跟踪位置`start`和`result`。 

当任一指针保留在字符串内时，主循环将继续。 在比较字符之前，我们跳过所有`'X'`值，因为它们是占位符，对排序没有意义。 

跳过后`'X'`，我们处理终止案件。 如果两个指针同时到达末尾，则转换有效。 如果只有一个结尾，则字符串包含不同的非`'X'`结构。 

然后我们比较当前的字符。 如果它们不同，转型就不可能，因为`'L'`和`'R'`不能改变顺序。 

下一部分强制执行移动规则：

 -`'L'`一定不能向右移动，所以`i < j`无效
 -`'R'`不能向左移动，所以`i > j`无效

 最后，两个指针都向前移动以处理下一个有意义的字符。 

该实现直接镜像算法并以线性时间运行。 

## 解决方案```go
func canTransform(start string, result string) bool {
	n := len(start)
	i, j := 0, 0

	for i < n || j < n {
		for i < n && start[i] == 'X' {
			i++
		}

		for j < n && result[j] == 'X' {
			j++
		}

		if i == n && j == n {
			return true
		}

		if i == n || j == n {
			return false
		}

		if start[i] != result[j] {
			return false
		}

		if start[i] == 'L' && i < j {
			return false
		}

		if start[i] == 'R' && i > j {
			return false
		}

		i++
		j++
	}

	return true
}
```### Go 特定注释

 Go 实现遵循与 Python 版本相同的逻辑。 

由于 Go 字符串是字节可索引的，并且输入仅包含 ASCII 字符 (`'L'`,`'R'`,`'X'`), 直接索引`start[i]`安全高效。 

无需特殊处理`nil`值是必需的，因为 Go 中的字符串是不可变的值类型。 

整数溢出不是问题，因为索引仍然受`n ≤ 10^4`。

 ## 边缘情况

 ### 不同的非`X`字符顺序

 当出现一个微妙的错误时`start`和`result`包含相同的字符但顺序不同。 

例子：```
start  = "RL"
result = "LR"
```幼稚的实现可能会尝试模拟交换并意外地假设重新排序是可能的。 然而，由于交换仅发生在`'X'`,`'L'`和`'R'`永远不能互相穿越。 该实现捕获了这个问题，因为指针比较发现了不匹配的字符。 

### 非法方向移动

 另一个重要的情况发生在角色朝禁止的方向移动时。 

例子：```
start  = "LX"
result = "XL"
```这需要`'L'`向右移动，这是不可能的。 该算法通过索引条件来检测这一点：```
'L' requires i >= j
```如果`i < j`，我们立即返回`False`。 

同样的逻辑对称地适用于`'R'`，它绝不能向左移动。 

### 字符串仅包含`X`考虑：```
start  = "XXXX"
result = "XXXX"
```没有有意义的字符可供比较。 粗心的实现可能会由于指针耗尽或无效索引而失败。 

此实现安全地跳过所有`'X'`字符，同时到达两个字符串的末尾，并正确返回`True`。
