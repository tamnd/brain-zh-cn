[LeetCode 753 题](https://leetcode.com/problems/cracking-the-safe/)

 **难度：** 🔴难
 **主题：** 字符串、深度优先搜索、图论、欧拉电路

 ## 解决方案

 ## 问题理解

 这个问题要求我们生成**尽可能短的字符串**，以保证保险箱在键入时会在某个时刻解锁。 

安全密码准确无误`n`数字，每个数字可以是以下任意值`0`到`k - 1`。 保险箱不会立即验证整个输入的序列。 相反，在输入每个数字后，它会检查**最新的`n`digits** to see if they match the password.

 我们的目标是构造一个字符串，使得**每个可能的密码长度`n`作为连续子字符串在某处出现恰好一次或至少一次**。 由于正确的密码出现在最新的密码中，保险箱就会解锁。`n`数字，包括所有可能的密码，保证成功。 

挑战在于使这个序列尽可能短。 

例如，如果`n = 2`和`k = 2`，可能的密码是：

 -`"00"`-`"01"`-`"10"`-`"11"`一个简单的解决方案可能会将它们全部连接起来：```
00011011
```然而，这会不必要地重复许多数字。 由于允许重叠，我们可以重用后缀和前缀来压缩序列：```
01100
```其中包含每个可能的 2 位密码作为子字符串一次。 

这些约束提供了一个重要线索：

 -`1 <= n <= 4`-`1 <= k <= 10`-`k^n <= 4096`可能的密码的最大数量最多为`4096`，这强烈表明图遍历方法是可行的。 

一个重要的观察是我们必须包括**所有`k^n`可能的长度-`n`组合**，否则某些密码可能永远不会出现，并且保险箱将无法解锁。 

一些边缘情况很重要：

 -`n = 1`，其中每个数字本身就是一个密码。 
-`k = 1`，其中仅存在一位数字（`0`），这意味着无论何种情况都只能使用一个密码`n`。 
- 必须小心处理重叠的小值以避免重复状态。 
- 如果没有正确跟踪，重新访问节点可能会产生循环和无限递归。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试增量生成字符串并检查是否每个可能的密码长度`n`出现。 

我们可以重复附加数字并跟踪哪些`n`-length 子串已被看到。 在每一步中，我们都会尝试所有可能的下一个数字并回溯，直到出现每个组合。 

这是有效的，因为最终，详尽的搜索将找到有效的序列。 然而，搜索空间呈爆炸式增长。 每个位置都可以选择`k`数字，并且许多部分字符串会导致冗余状态。 

核心问题是暴力破解无法利用密码之间的重叠。 由于相邻的密码可能共享`n - 1`数字，重新计算等效状态变得非常昂贵。 

### 关键见解

 这个问题实际上要求我们构造一个包含所有可能长度的**最小长度序列-`n`作为子字符串**组合一次。 

这是一个经典的**De Bruijn 序列**问题。 

我们可以将问题建模为图表：

 - 每个节点代表一个`(n - 1)`- 数字序列。 
- 每条边代表附加一个数字，产生一个`n`- 数字密码。 

例如，与`n = 2`和`k = 2`:

 节点：```
0, 1
```边缘：```
0 -> 0  (00)
0 -> 1  (01)
1 -> 0  (10)
1 -> 1  (11)
```由于每个节点具有相等的入度和出度，因此形成**欧拉图**。 

最佳序列对应于**欧拉电路**，这意味着我们只遍历每条边一次。 每条边代表一个密码，因此访问所有边可确保每个密码恰好出现一次。 

我们可以使用 **Hierholzer 算法** 和深度优先搜索 (DFS) 来构建答案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(k^(k^n)) | O(k^(k^n)) | O(k^n) | O(k^n) | 彻底搜索可能的序列|
 | 最佳 | O(k^n) | O(k^n) | O(k^n) | O(k^n) | De Bruijn 图上的欧拉电路 |

 ## 算法演练

 ### 最优算法，通过 DFS 的欧拉电路

 1. **隐式处理图形表示**

 我们没有显式地构建图，而是将节点表示为长度的字符串`n - 1`。 

一个节点对应当前可扩展的后缀。 

例如，如果`n = 3`当前节点是`"01"`, 附加数字`"2"`形成密码`"012"`。 
2. **从全零节点开始**

 我们开始于：```
"0" * (n - 1)
```这是欧拉遍历的起始节点。 
3. **跟踪访问过的边缘**

 由于边代表密码，因此我们必须确保每个密码仅使用一次。 

我们将访问过的密码存储在哈希集中：```
visited = {password_strings}
```例子：```
"00", "01", "10", "11"
```4. **使用 Hierholzer 算法执行 DFS**

 在每个节点：

 - 尝试附加每个数字`0`到`k - 1`- 形成新的边缘：```
next_password = node + digit
```如果这条边还没有被访问过：

 - 标记已访问
 - 递归后缀：```
next_password[1:]
```这仅保留最后一个`n - 1`数字。 
5. **回溯时附加数字**

 Hierholzer 算法的关键见解是我们在**递归之后**添加数字，而不是之前。 

这保证了欧拉排序的正确构建。 

当递归返回时：```
answer.append(digit)
```6. **附加起始前缀**

 由于节点只存储`n - 1`数字，我们必须附加：```
"0" * (n - 1)
```最后完成序列。 
7. **返回最终字符串**

 将所有收集到的数字连接到答案中。 

### 为什么它有效

 该图恰好包含每个可能长度的密码的一条边`n`。 Hierholzer 的算法保证欧拉电路中的每条边都被精确地遍历一次。 由于每条边都对应一个唯一的密码，因此每个可能的密码在结果序列中作为子字符串仅出现一次。 

由于重叠是通过图遍历最大化的，因此生成的字符串具有最小长度：```
k^n + n - 1
```这被证明是最佳的。 

## Python 解决方案```python
class Solution:
    def crackSafe(self, n: int, k: int) -> str:
        start = "0" * (n - 1)
        visited: set[str] = set()
        sequence: list[str] = []

        def dfs(node: str) -> None:
            for digit in map(str, range(k)):
                edge = node + digit

                if edge not in visited:
                    visited.add(edge)
                    dfs(edge[1:])
                    sequence.append(digit)

        dfs(start)

        return "".join(sequence) + start
```### 实现说明

 我们首先将起始节点定义为`n - 1`零。 这代表初始图状态。 

这`visited`集合存储边而不是节点。 这种区别很重要，因为密码对应于图中的边，而不是顶点。 允许多次访问一个节点，但每个密码必须恰好出现一次。 

DFS 函数实现了 Hierholzer 算法。 对于每个可能的数字，我们通过将数字附加到当前节点来创建候选边。 如果边还没有被访问过，我们就递归到后缀状态。 

实现中最微妙的部分是在回溯期间附加数字。 这种反向构造确保了正确生成欧拉遍历。 

最后，我们附加起始前缀来重建完整的序列。 

## 解决方案```go
func crackSafe(n int, k int) string {
	start := ""
	for i := 0; i < n-1; i++ {
		start += "0"
	}

	visited := make(map[string]bool)
	var sequence []byte

	var dfs func(string)
	dfs = func(node string) {
		for digit := 0; digit < k; digit++ {
			edge := node + string(rune('0'+digit))

			if !visited[edge] {
				visited[edge] = true
				dfs(edge[1:])
				sequence = append(sequence, byte('0'+digit))
			}
		}
	}

	dfs(start)

	return string(sequence) + start
}
```### Go 特定注释

 Go 的实现与 Python 解决方案非常相似。 

一个`map[string]bool`使用Python代替`set`对于访问过的边缘。 这`sequence`被存储为`[]byte`用于高效附加和转换为字符串。 

使用以下方法处理数字转换：```
string(rune('0' + digit))
```自从`k <= 10`，数字保留在`'0'`到`'9'`，所以字符算术是安全的。 

Go 切片是可变的并且对于增量追加来说是高效的，使得`[]byte`构建结果的自然选择。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(k^n) | O(k^n) | 每个密码边缘都被访问一次 |

 该图准确包含`k^n`边，因为每个可能的密码都对应一个边。 DFS 访问每条边一次，给出密码数量的线性复杂度。

    def crackSafe(self, n: int, k: int) -> str:
        start = "0" * (n - 1)
        visited = set()
        sequence = []

        def dfs(node: str) -> None:
            for digit in map(str, range(k)):
                edge = node + digit

                if edge not in visited:
                    visited.add(edge)
                    dfs(edge[1:])
                    sequence.append(digit)

        dfs(start)

def verify(result: str, n: int, k: int) -> bool:
    passwords = {
        result[i:i+n]
        for i in range(len(result) - n + 1)
    }

    expected = {
        "".join(map(str, digits))
        for digits in __import__("itertools").product(
            range(k), repeat=n
        )
    }

    return passwords == expected

# Single digit passwords

 ## 边缘情况

 ### 案例 1,`n = 1`什么时候`n = 1`，没有`(n - 1)`后缀。 起始节点变成空字符串。 

这很容易引入错误，因为子字符串逻辑如下`edge[1:]`可能看起来不安全。 然而，切片工作正常，只是返回另一个空字符串，使 DFS 能够正常进行。 

例如：```
n = 1, k = 2
```该算法生成：```
10
```其中包含两个可能的密码。 

### 案例 2,`k = 1`当仅存在一位数字时，每个密码都必须完全由零组成。 

例如：```
n = 4, k = 1
```唯一有效的密码是：```
0000
```有缺陷的实现可能会无限递归，因为每个转换看起来都是相同的。 这`visited`边缘设置可防止重新访问相同的密码。 

### 案例 3，重复密码生成

 一个常见的错误是跟踪访问的**节点**而不是访问的**边缘**。 

在欧拉遍历中，节点可能会被多次重新访问。 重要的是每个密码只出现一次。 

例如：```
n = 2, k = 2
```节点`"0"`必须重新访问以生成两者：```
00
01
```仅跟踪节点会错误地跳过有效密码并产生不完整的序列。 通过跟踪边缘，实现保证了正确性。
