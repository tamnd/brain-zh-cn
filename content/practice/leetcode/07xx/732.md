 ## 解决方案

 ## 问题理解

 这个问题要求我们设计一个日历系统，支持添加时间间隔并报告迄今为止看到的最大重叠事件数。 

每次预订都表示为半开区间`[startTime, endTime)`。 这意味着该活动包括`startTime`但不包括`endTime`。 仅当两个事件共享某个非空时间范围时，它们才会重叠。 例如：

-`[10, 20)`和`[15, 25)`重叠自`15`到`20`-`[10, 20)`和`[20, 30)`不重叠，因为`20`被排除在第一个区间之外

 每次预订操作后，我们必须返回日历中任意位置同时重叠事件的最大数量。 

这句话`k-booking`意味着至少存在一个时刻`k`事件重叠。 我们的目标是持续跟踪最大的此类值。 

约束条件很重要：

 -`0 <= startTime < endTime <= 10^9`- 至多`400`预订

 时间范围非常大，所以我们无法构建按时间索引的数组。 然而，预订数量相对较少，这表明基于处理区间边界的算法是实用的。 

简单的实现可能会尝试检查每个时间单位的重叠计数，但坐标范围太大。 另一种幼稚的方法可能会反复将每个间隔与其他间隔进行比较，随着预订量的增长，这种方法会变得低效。 

重要的边缘情况包括：

 - 仅在端点处接触的间隔，例如`[10, 20)`和`[20, 30)`，它们不重叠
 - 许多完全重叠的间隔
 - 嵌套间隔
 - 稀疏间隔分布在非常大的时间戳上
 - 相同范围的重复预订

 该问题保证有效间隔，因为`startTime < endTime`。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是存储所有间隔，并在每次预订后从头开始重新计算最大重叠。 

一种方法是：

 1. 收集所有区间边界
 2. 对于每个独特的时间段，计算有多少个区间覆盖它
 3. 跟踪最大重叠计数

 另一种强力变体是离散化所有端点并手动扫描重叠部分。 

这是有效的，因为重叠计数从根本上是由间隔开始和结束边界决定的。 然而，每次预订后从头开始重新计算重叠变得效率低下。 

如果有`n`预订时，每次插入可能需要再次扫描所有间隔和所有端点，从而导致粗略的`O(n^2)`或者更糟糕的整体复杂性。 

### 最优方法，带差异图的扫描线

 关键的见解是可以使用差异数组的思想来表示间隔重叠。 

对于每次预订`[start, end)`：

- 添加`+1`在`start`- 添加`-1`在`end`当我们按排序顺序处理时间并维护运行的前缀和时：

 - 前缀和表示该时刻的活动间隔数
 - 最大前缀和就是答案

 该技术通常称为扫描线算法。 

我们没有明确地跟踪每个间隔重叠，而是只跟踪边界处的变化。 由于最多有`400`预订，边界点总数最多为`800`，使分拣和扫描变得高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 每次预订 O(n²) | O(n) | 重复重新计算重叠 |
 | 最佳| 每次预订 O(n log n) | O(n) | 使用具有有序边界变化的扫描线 |

 ## 算法演练

 ### 最优算法，带差异图的扫描线

 1. 初始化一个名为`timeline`。 

该映射存储活动事件计数在每个时间戳的变化情况。 

-`timeline[start] += 1`-`timeline[end] -= 1`该地图就像一个稀疏差异数组。 
2. 当新预订到达时，更新地图。 

对于间隔`[startTime, endTime)`:

 - 增加计数`startTime`- 减少计数`endTime`这意味着事件在以下时间激活`startTime`并停止活跃于`endTime`。 
3. 将所有时间戳按升序排序。 

我们必须按时间顺序处理时间点，因为重叠计数取决于随时间推移累积的变化。 
4. 执行前缀和扫描。 

维持：

-`current_overlap`，当前活动事件的数量
 -`max_overlap`，迄今为止看到的最高重叠

 对于每个时间戳：

 - 添加时间线更改`current_overlap`- 更新`max_overlap`5. 返回`max_overlap`。 

该值表示新预订后日历中任意位置同时活动间隔的最大数量。 

### 为什么它有效

 该算法之所以有效，是因为间隔重叠计数仅在间隔边界发生变化。 

添加`+1`在开始时间意味着间隔变为活动状态。 添加`-1`在结束时间意味着间隔停止活动。 当我们按排序顺序扫描时间时，运行前缀总和始终等于该时刻的活动间隔数。 

因此，扫描期间遇到的最大前缀和恰好是最大重叠计数。 

## Python 解决方案```python
from collections import defaultdict
from typing import DefaultDict

class MyCalendarThree:

    def __init__(self):
        self.timeline: DefaultDict[int, int] = defaultdict(int)

    def book(self, startTime: int, endTime: int) -> int:
        self.timeline[startTime] += 1
        self.timeline[endTime] -= 1

        current_overlap = 0
        max_overlap = 0

        for time in sorted(self.timeline):
            current_overlap += self.timeline[time]
            max_overlap = max(max_overlap, current_overlap)

        return max_overlap

# Your MyCalendarThree object will be instantiated and called as such:
# obj = MyCalendarThree()
# param_1 = obj.book(startTime,endTime)
```该实现严格遵循扫描线算法。 

构造函数初始化一个`defaultdict(int)`命名的`timeline`。 此结构存储每个时间戳的活动间隔计数的净变化。 

里面`book`，我们记录区间边界：

 -`+1`在`startTime`-`-1`在`endTime`更新地图后，我们按排序顺序扫描所有时间戳。 变量`current_overlap`存储当前有多少个间隔处于活动状态，而`max_overlap`存储扫描期间看到的最佳答案。 

由于时间戳的数量很少，因此对每个预订进行排序是可以接受的。 

## 解决方案```go
package main

import "sort"

type MyCalendarThree struct {
	timeline map[int]int
}

func Constructor() MyCalendarThree {
	return MyCalendarThree{
		timeline: make(map[int]int),
	}
}

func (this *MyCalendarThree) Book(startTime int, endTime int) int {
	this.timeline[startTime]++
	this.timeline[endTime]--

	times := make([]int, 0, len(this.timeline))

	for time := range this.timeline {
		times = append(times, time)
	}

	sort.Ints(times)

	currentOverlap := 0
	maxOverlap := 0

	for _, time := range times {
		currentOverlap += this.timeline[time]

		if currentOverlap > maxOverlap {
			maxOverlap = currentOverlap
		}
	}

	return maxOverlap
}

/**
 * Your MyCalendarThree object will be instantiated and called as such:
 * obj := Constructor();
 * param_1 := obj.Book(startTime,endTime);
 */
```Go 实现镜像了 Python 解决方案，但需要显式映射和切片处理。 

Go 映射是无序的，因此我们首先将所有时间戳收集到一个切片中，并使用`sort.Ints`。 

重叠计数逻辑是相同的。 整数溢出不是问题，因为最大重叠受到预订数量的限制，最多是`400`。

 ## 边缘情况

 ### 接触端点的间隔

 一个非常常见的错误是错误的处理`[10, 20)`和`[20, 30)`作为重叠。 

由于间隔是半开的，因此第一个间隔恰好在第二个间隔开始时结束。 该实现通过应用自然地处理这个问题`-1`在`20`和`+1`在`20`。 在扫描期间，前缀和正确地反映了间隔不同时重叠。 

### 多个相同的区间

 如果预订了许多相同的间隔，则重叠计数应继续增加。 

例如：```
[10, 20)
[10, 20)
[10, 20)
```差异图累加多个`+1`和`-1`在相同的时间戳发生变化。 扫描线正确计算重叠`1`,`2`， 和`3`。 

### 极大的时间值

 时间戳可以大到`10^9`。 

基于数组的简单解决方案是不可能的，因为分配与时间线大小成比例的内存将是巨大的。 扫描线方法完全避免了这个问题，因为它只存储实际出现在预订中的边界点。
