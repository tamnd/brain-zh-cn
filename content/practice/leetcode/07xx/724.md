[LeetCode 724 题](https://leetcode.com/problems/find-pivot-index/)

 **难度：** 🟢简单
 **主题：** 数组、前缀和

 ## 解决方案

 ## 问题理解

 该问题要求我们在数组中找到一个索引，使得严格位于该索引左侧的所有元素的总和等于严格位于该索引右侧的所有元素的总和。 

更正式地说，对于索引`i`:

 - 左总和 =`nums[0] + nums[1] + ... + nums[i - 1]`- 右和 =`nums[i + 1] + nums[i + 2] + ... + nums[n - 1]`我们必须返回这两个总和相等的最左边的索引。 如果不存在这样的索引，我们返回`-1`。 

输入是一个整数数组`nums`。 该数组可以包含正数、负数和零。 输出是表示主元索引的单个整数。 

限制相对较小：

 - 数组长度最多为`10^4`- 每个数字都介于`-1000`和`1000`尽管约束并不大，但它们足够大，以至于重复重新计算每个索引的总和可能会变得低效。 这表明我们应该尽可能避免嵌套循环。 

一些边缘情况很重要：

 - 索引处可能存在枢轴索引`0`，其中左边的总和自动`0`- 枢轴索引可能存在于最后一个索引处，其中正确的总和会自动生成`0`- 具有负值的数组仍然可以具有有效的主元
 - 应该返回只有一个元素的数组`0`，因为左右总和都是`0`- 可能存在多个主元索引，但我们必须返回最左边的一个

 了解这些细节很重要，因为幼稚的实现经常错误地处理边缘边界或不必要地重新计算总和。 

## 方法

 ### 蛮力方法

 最直接的解决方案是单独检查每个指标。 

对于每个索引`i`:

 1. 计算左边所有元素的总和
 2. 计算右侧所有元素的总和
 3. 比较两个总和
 4. 返回第一个相等的索引

 这种方法是正确的，因为它明确地检查问题定义对于每个可能的枢轴索引所需的条件。 

然而，问题是效率。 分别计算每个索引的左右总和需要重复扫描数组的部分内容。 如果数组有`n`元素，那么每个索引可能需要最多`O(n)`工作，导致总的复杂性`O(n^2)`。 

和`n = 10^4`，这在实践中仍然有效，但与我们可以实现的目标相比，它的速度不必要地慢。 

### 最优前缀和方法

 关键的观察是我们不需要重复地重新计算总和。 

如果我们已经知道：

 - 数组的总和
 - 左侧元素的运行总和

 然后我们就可以立即计算出正确的总和。 

认为：

-`left_sum`是索引之前元素的总和`i`-`total_sum`是整个数组的总和
 -`nums[i]`是当前元素

 然后：$$\text{right\_sum} = \text{total\_sum} - \text{left\_sum} - \text{nums[i]}$$所以枢轴条件变为：$$\text{left\_sum} = \text{total\_sum} - \text{left\_sum} - \text{nums[i]}$$这让我们可以在恒定时间内确定索引是否是主元。 

我们迭代数组一次，同时保持运行的左和。 这将总复杂度降低到`O(n)`。

 ## 算法演练

 ### 最优前缀和算法

 1. 计算数组的总和。 

这使我们能够确定右侧的总和，而无需重复重新计算。 
2. 初始化变量`left_sum = 0`。 

在处理任何索引之前，左侧没有元素，因此左侧总和从零开始。 
3. 使用索引迭代数组`i`。 

每一步，我们都对待`nums[i]`作为潜在的枢轴指数。 
4. 计算正确的总和。 

不用再次扫描数组，而是计算：$$\text{right\_sum} = \text{total\_sum} - \text{left\_sum} - \text{nums[i]}$$这会从总数中减去当前元素和所有左侧元素。 
5. 比较左右总和。 

如果它们相等，则索引`i`满足枢轴条件，因此返回`i`。 
6. 更新剩余的总和。 

将当前元素添加到`left_sum`在移动到下一个索引之前。 
7. 如果循环结束而没有找到枢轴，则返回`-1`。 

这意味着没有索引满足所需条件。 

### 为什么它有效

 该算法保持不变式`left_sum`始终等于严格位于当前索引之前的元素之和。 

在每个索引处：

 -`left_sum`正确表示左侧
 -`total_sum - left_sum - nums[i]`正确代表右侧

 由于使用精确的左右总和对每个索引进行一次检查，因此返回的第一个匹配索引保证是最左边的有效主元索引。 

## Python 解决方案```python
from typing import List

class Solution:
    def pivotIndex(self, nums: List[int]) -> int:
        total_sum = sum(nums)
        left_sum = 0

        for i, num in enumerate(nums):
            right_sum = total_sum - left_sum - num

            if left_sum == right_sum:
                return i

            left_sum += num

        return -1
```实现首先计算数组的总和。 这是至关重要的，因为它允许我们在迭代过程中以恒定的时间导出右侧的总和。 

变量`left_sum`跟踪当前索引之前元素的累积和。 最初，它为零，因为索引左侧没有元素`0`。 

在每次迭代期间：

 -`num`是当前元素
 -`right_sum`使用总和公式计算
 - 算法检查左右和是否匹配

 如果它们匹配，则立即返回当前索引，因为问题需要最左边的主元索引。 

如果没有，则将当前元素添加到`left_sum`以便下一次迭代具有正确的前缀和。 

如果处理整个数组后没有找到主元索引，则函数返回`-1`。 

## 解决方案```go
func pivotIndex(nums []int) int {
    totalSum := 0

    for _, num := range nums {
        totalSum += num
    }

    leftSum := 0

    for i, num := range nums {
        rightSum := totalSum - leftSum - num

        if leftSum == rightSum {
            return i
        }

        leftSum += num
    }

    return -1
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

一个区别是 Go 不提供内置的`sum()`函数用于切片，因此我们使用循环手动计算总和。 

该算法直接使用 Go 切片，这是对数组的轻量级引用。 没有分配额外的数组或前缀和结构，因此空间复杂度保持不变。 

整数溢出在这里不是一个问题，因为约束很小。 即使在最坏的情况下：$$10^4 \times 1000 = 10^7$$很容易适合 Go 的内部`int`类型。

 该算法对数组执行两次线性遍历：

 1. 一次计算总和
 2. 一次定位枢轴索引

 由于两次传递都是线性的，因此总时间复杂度为`O(n)`。 

不会创建额外的数组、哈希映射或辅助数据结构。 该算法仅存储少量整数变量，因此空间复杂度是恒定的。

 ## 边缘情况

 ### 在数组的开头旋转

 最左边的索引前面没有任何元素，因此左边的总和应视为零。 

如果实现错误地尝试访问索引之前的元素，这很容易导致错误`0`或者忘记空总和等于零。 

该实现自然地处理了这个问题，因为`left_sum`被初始化为`0`在迭代开始之前。 

### 在数组末尾旋转

 同样，最后一个索引后面没有元素，因此正确的总和应该为零。 

一些不正确的实现意外地将当前元素包含在右侧计算中或错误处理数组边界。 

该解决方案正确计算：$$\text{right\_sum} = \text{total\_sum} - \text{left\_sum} - \text{nums[i]}$$在最后一个索引处，该表达式自动变为零。 

### 负数数组

 负数很重要，因为不能保证总和单调增加。 

基于增加金额假设的天真的方法可能会失败。 例如：```
[-1, -1, -1, -1, -1, 0]
```仍然包含有效的主元索引。 

无论值是正数、负数还是零，前缀和方法都可以正常工作，因为它仅依赖于精确的算术相等。 

### 多个有效枢轴指数

 一个数组可以包含多个有效的主元索引。 该问题特别需要最左边的一个。 

例如：```
[0, 0, 0]
```从技术上讲，每个指数都是一个枢轴。 

该实现保证了正确的结果，因为它从左到右扫描并在找到第一个有效主元时立即返回。
