[LeetCode 第 764 题](https://leetcode.com/problems/largest-plus-sign/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划

 ## 解决方案

 ## 问题理解

 这个问题要求我们找到**最大的轴对齐加号**完全由`1`是在一个`n x n`二进制网格。 

最初，网格中的每个单元格都包含`1`。 然而，某些位置被标记为地雷，这意味着这些单元格包含`0`。 输入`mines`提供所有此类被阻止单元格的坐标。 

**顺序的加号`k`** 包括：

 - 中心单元包含`1`- 四臂向上、下、左、右方向延伸
 - 每条手臂必须有长度`k - 1`- 每个涉及的细胞必须包含`1`例如，订单的加号`3`意思是：

 - 一个中心单元
 - 两个连续`1`各个方向

 视觉上：```
    1
    1
1 1 1 1 1
    1
    1
```目标是返回网格中任何有效加号的**最大可能顺序**。 如果不存在有效的加号，则返回`0`。 

短语**轴对齐**意味着加号只能垂直和水平延伸，不能对角延伸。 

### 理解输入

 输入包括：

 -`n`: 方格的尺寸 (`n x n`）
 -`mines`：网格包含的坐标列表`0`例如：```
n = 5
mines = [[4,2]]
```这意味着：

 - 创建一个`5 x 5`网格充满了`1`s
 - 设置`grid[4][2] = 0`其他一切都仍然存在`1`。 

### 理解输出

 输出是一个整数，表示任何加号的**最大顺序**。 

假设最大加号有：

 - 中心 =`(2,2)`- 臂长=`1`然后：```
order = arm length + 1 = 2
```所以答案是`2`。 

### 约束告诉我们什么

 限制条件是：```
1 <= n <= 500
1 <= mines.length <= 5000
```最大可能的网格包含：```
500 × 500 = 250,000 cells
```这对于昂贵的重复扫描每个细胞来说太大了。 

从每个候选中心反复向外扩展的简单解决方案很容易变得太慢，特别是如果每​​次扩展都会花费成本`O(n)`并且对所有人重复`O(n²)`细胞。 

这强烈表明我们需要一个**高效的动态编程风格预处理解决方案**，最好是围绕`O(n²)`时间。 

### 重要的边缘案例

 一些边缘情况很容易破坏简单的实现。 

如果整个网格都被开采，则不存在加号。 例如：```
n = 1
mines = [[0,0]]
```答案一定是`0`。 

If there are no mines in a small grid:```
n = 1
mines = []
```唯一的单元格本身形成顺序的加号`1`。 

另一种棘手的情况是，当一个中锋看起来很有前途，但一个方向很早就被封锁时：```
1 1 1
1 1 0
1 1 1
```中心无法在所有四个方向上完全延伸，因此顺序受到最短臂的限制。 

关键的观察结果是**加号的顺序由所有四个方向中的最小臂长决定**。 

## 方法

 ### 蛮力方法

 蛮力的想法是将每个单元格视为加号的可能中心。 

对于每个候选单元格：

 1. 检查是否包含`1`2、逐级向外拓展
 3. 验证所有四个方向的距离相同
 4. 当一个方向碰到边界或地雷时停止
 5.记录最大有效订单

 例如，如果检查中心`(r,c)`：```
distance = 1:
up, down, left, right must all be 1

distance = 2:
same requirement
```该顺序成为最大成功扩展加一。 

这种方法是正确的，因为它明确验证了每个可能的加号。 然而，它的效率很低。 

有`O(n²)`中心，每个中心可以扩展到`O(n)`步骤。 每一步都会检查四个方向。 

这导致：```
O(n³)
```时间复杂度，对于`n = 500`。 

### 最佳解决方案的关键见解

 关键的观察是：

 > 加号的顺序为`(r,c)`等于最小连续数`1`所有四个方向均可使用。 

我们可以预处理方向信息，而不是从每个中心重复扩展。 

对于每个单元格，我们想知道：

 - 连续`1`向左
 - 连续`1`向右
 - 连续`1`向上
 - 连续`1`向下

 如果一个细胞有：```
left = 4
right = 3
up = 2
down = 5
```那么以那里为中心的最大加阶为：```
min(4,3,2,5) = 2
```我们可以使用网格上的四个方向扫描来有效地计算这些值。 

动态编程在这里效果很好，因为每个方向计数仅取决于该方向上紧邻的前一个单元。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n3) | O(n²) | 从每个中心向外扩展 |
 | 最佳| O(n²) | O(n²) | 使用动态规划的四向传递 |

 ## 算法演练

 ### 最优动态规划策略

 我们维护一个矩阵`dp`在哪里：```
dp[r][c]
```存储迄今为止看到的最小定向臂长度。 

最初，每个非我的单元格都以价值开始`n`。 

然后我们执行四遍。 

#### 1. 构建网格表示

 将矿井转换为哈希集。 

这允许恒定时间查找：```
(r, c) in mine_set
```而不是重复扫描`mines`。 

我们初始化：```
dp[n][n]
```有价值`n`。 

这个矩阵将会逐渐细化。 

#### 2. 从左到右传递

 对于每一行：

 - 连续计数`1`s
 - 重置为`0`在矿井

 示例：```
1 1 0 1 1
```变成：```
1 2 0 1 2
```我们更新：```
dp[r][c] = min(dp[r][c], count)
```我们使用`min`因为后面的通行证将进一步限制有效的加大小。 

#### 3. 从右到左传球

 反向重复该过程。 

例子：```
1 1 0 1 1
```变成：```
2 1 0 2 1
```再次更新：```
dp[r][c] = min(dp[r][c], count)
```现在每个细胞都知道它的水平限制。 

#### 4. 自上而下传递

 对于每一列：

 连续计数`1`s向下。 

示例栏：```
1
1
0
1
```变成：```
1
2
0
1
```更新`dp`具有最小值。 

#### 5. 自下而上传递

 垂直向上重复。 

最后一遍给每个单元格：```
minimum(left, right, up, down)
```该最小值直接等于以该处为中心的最大有效加阶。 

#### 6. 跟踪最大值

 当我们完成最后一遍时：```
answer = max(answer, dp[r][c])
```返回找到的最大订单。 

### 为什么它有效

 有效的加号要求手臂在所有四个方向上的伸展距离相等。 因此，限制因素始终是最短的臂。 

四个方向的传递准确计算有多少个连续的`1`s 存在于各个方向。 采取最低限度保证所有四个臂可以同时存在。 

由于每个单元格都是独立评估的并且每个方向计数都是准确的，因此该算法始终计算正确的最大加号。 

## Python 解决方案```python
from typing import List

class Solution:
    def orderOfLargestPlusSign(self, n: int, mines: List[List[int]]) -> int:
        mine_set = {(r, c) for r, c in mines}

        dp = [[n] * n for _ in range(n)]

        for row in range(n):
            count = 0
            for col in range(n):
                if (row, col) in mine_set:
                    count = 0
                else:
                    count += 1
                dp[row][col] = min(dp[row][col], count)

            count = 0
            for col in range(n - 1, -1, -1):
                if (row, col) in mine_set:
                    count = 0
                else:
                    count += 1
                dp[row][col] = min(dp[row][col], count)

        result = 0

        for col in range(n):
            count = 0
            for row in range(n):
                if (row, col) in mine_set:
                    count = 0
                else:
                    count += 1
                dp[row][col] = min(dp[row][col], count)

            count = 0
            for row in range(n - 1, -1, -1):
                if (row, col) in mine_set:
                    count = 0
                else:
                    count += 1
                dp[row][col] = min(dp[row][col], count)
                result = max(result, dp[row][col])

        return result
```实现从转换开始`mines`进入哈希集以进行恒定时间查找。 这避免了重复搜索地雷列表。 

这`dp`矩阵用值初始化`n`因为加号不能超过网格大小。 在每次定向传递期间，我们通过取最小值来细化这些值。 

前两行扫描计算左臂和右臂的长度。 第二对列扫描计算向上和向下的臂长。 

从下到上的传递还会更新最终答案，因为到那时，每个单元格都包含所有四个方向计数中的最小值。 

## 解决方案```go
func orderOfLargestPlusSign(n int, mines [][]int) int {
	mineSet := make(map[[2]int]bool)

	for _, mine := range mines {
		mineSet[[2]int{mine[0], mine[1]}] = true
	}

	dp := make([][]int, n)
	for i := 0; i < n; i++ {
		dp[i] = make([]int, n)
		for j := 0; j < n; j++ {
			dp[i][j] = n
		}
	}

	for row := 0; row < n; row++ {
		count := 0
		for col := 0; col < n; col++ {
			if mineSet[[2]int{row, col}] {
				count = 0
			} else {
				count++
			}

			if count < dp[row][col] {
				dp[row][col] = count
			}
		}

		count = 0
		for col := n - 1; col >= 0; col-- {
			if mineSet[[2]int{row, col}] {
				count = 0
			} else {
				count++
			}

			if count < dp[row][col] {
				dp[row][col] = count
			}
		}
	}

	result := 0

	for col := 0; col < n; col++ {
		count := 0
		for row := 0; row < n; row++ {
			if mineSet[[2]int{row, col}] {
				count = 0
			} else {
				count++
			}

			if count < dp[row][col] {
				dp[row][col] = count
			}
		}

		count = 0
		for row := n - 1; row >= 0; row-- {
			if mineSet[[2]int{row, col}] {
				count = 0
			} else {
				count++
			}

			if count < dp[row][col] {
				dp[row][col] = count
			}

			if dp[row][col] > result {
				result = dp[row][col]
			}
		}
	}

	return result
}
```Go 的实现与 Python 版本非常相似。 由于 Go 没有内置的哈希集，我们使用以下方法模拟一个：```go
map[[2]int]bool
```这`dp`matrix is represented using slices of slices. 整数溢出不是问题，因为所有值都在范围内`[0, 500]`。

 ## 边缘情况

 ### 单细胞网格

 当`n = 1`，网格仅包含一个位置。 如果没有开采，答案是`1`因为单个单元格算作顺序的加号`1`。 

如果该单元被开采，答案就变成`0`。 

这种情况经常会导致相差一的错误，因为臂长是`k - 1`, 意思是顺序`1`不需要扩展。 

### 中心被封锁

 网格在视觉上可能看起来能够支撑一个大的加号，但如果中心本身被开采，那么该加号是不可能的。 

例如：```
1 1 1
1 0 1
1 1 1
```该实现自然地处理了这个问题，因为方向计数重置为`0`在矿山，导致该中心没有做出任何贡献。 

### 一个方向成为瓶颈

 加号要求所有四个臂均等存在。 即使三个方向延伸得很远，单个方向被阻挡也会限制秩序。 

例子：```
1 1 1
1 1 0
1 1 1
```中锋因为右臂太短，无法形成更大的加分。 

该算法通过以下方式正确处理这个问题：```
min(left, right, up, down)
```这确保最短的臂决定有效的顺序。 

### 接近约束极限的大网格

 在`n = 500`，暴力扩张变得极其昂贵。 

动态编程方法仍然高效，因为每个单元仅被处理固定次数，从而确保算法在限制内轻松扩展。
