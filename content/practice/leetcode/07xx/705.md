[LeetCode 705 题](https://leetcode.com/problems/design-hashset/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表、链表、设计、哈希函数

 ## 解决方案

 ## 问题理解

 该问题要求我们设计自己的 HashSet 实现，而不使用任何内置的哈希表库（例如 Python 的哈希表库）`set`或者 Go 内置的地图类型作为主要解决方案的想法。 

HashSet 是一种存储唯一值的数据结构。 它支持三种操作：

 -`add(key)`，向集合中插入一个值
 -`remove(key)`，从集合中删除一个值（如果存在）
 -`contains(key)`，检查集合中是否存在某个值

 集合的重要属性是唯一性。 如果多次插入相同的值，它仍然应该只出现一次。 

LeetCode 中的输入表示为一系列操作。 每个操作都被调用`MyHashSet`对象，预期输出对应每个操作的返回值。 自从`add`和`remove`不返回任何内容，它们的输出是`null`。 仅有的`contains`返回一个布尔结果。 

这些限制足够小，许多解决方案在技术上都可以通过：

 -`0 <= key <= 10^6`- 至多`10^4`运营

 尽管限制并不大，但问题的目标是了解基于哈希的数据结构内部如何工作。 预期的解决方案是构建自定义哈希机制。 

一些重要的边缘情况立即脱颖而出：

 - 多次添加相同的密钥不应创建重复项
 - 删除不存在的密钥不应导致错误
 - 钥匙可以`0`- 钥匙可以大到`10^6`- 多个key可能会散列到同一个bucket，因此需要进行碰撞处理

 这些情况正是正确的哈希表设计如此重要的原因。 

## 方法

 ### 蛮力方法

 最简单的解决方案是将所有值存储在列表或数组中。 

为了`add`，我们首先扫描列表以检查该值是否已经存在。 如果它不存在，我们追加它。 

为了`contains`，我们线性搜索列表。 

为了`remove`，我们线性搜索直到找到该值，然后将其删除。 

这种方法很简单并且保证了正确性，因为每个操作都会显式检查所有存储的元素。 然而，它的效率很低，因为每个操作可能需要扫描整个集合。 

如果有`n`存储的元素，每次操作都需要`O(n)`最坏情况下的时间。 

### 最佳方法，用桶进行散列

 关键的观察是，我们可以通过使用哈希函数将值分配到存储桶中来显着减少查找时间。 

我们不是将所有元素存储在一个列表中，而是创建许多称为存储桶的较小列表。 

我们计算：```
bucket_index = key % bucket_count
```产生相同余数的所有键都进入同一个桶中。 

这意味着：

-`add`只在一个桶内搜索
 -`remove`只在一个桶内搜索
 -`contains`只在一个桶内搜索

 如果桶均匀分布，则每个桶都会保持非常小，从而使操作平均时间接近恒定时间。 

为了处理冲突（多个键映射到同一个存储桶），我们使用单独的链接。 每个存储桶只是一个列表，存储分配给该存储桶的所有键。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 每次操作 O(n) | O(n) | 存储所有值的单个列表 |
 | 最佳 | 每次操作平均 O(1) | O(n + 桶) | 使用单独的链接进行散列 |

 ## 算法演练

 ### 最优算法

 1. 创建固定数量的桶。 

我们初始化一个数组，其中每个位置代表一个桶。 每个存储桶本身都是一个列表，用于存储散列到该存储桶的密钥。 
2. 选择哈希函数。 

我们使用以下方法计算桶索引：```
key % bucket_count
```这可以将值相当均匀地分布在各个存储桶中。 
3. 实施`add(key)`。 

首先计算正确的桶索引。 然后查看该存储桶内部以查看该密钥是否已存在。 如果没有，请附加它。 

这保留了集合的唯一性。 
4. 实施`remove(key)`。 

计算存储桶索引并仅在该存储桶内进行搜索。 如果该密钥存在，请将其删除。 

如果密钥不存在，则不执行任何操作。 
5. 实施`contains(key)`。 

计算桶索引并检查该桶中是否存在该键。 

返回`True`如果找到，否则`False`。 

### 为什么它有效

 正确性来自于这样一个事实：每个键总是使用相同的哈希函数确定性地映射到恰好一个存储桶。 

每当我们添加、删除或搜索键时，我们都会计算相同的存储桶索引。 因此，如果集合中存在某个键，则它必须存在于该存储桶内。 

因为我们还在插入过程中防止重复，所以该结构始终表现得像一个有效的集合。 

## Python 解决方案```python
class MyHashSet:

    def __init__(self):
        self.bucket_count = 1000
        self.buckets = [[] for _ in range(self.bucket_count)]

    def _hash(self, key: int) -> int:
        return key % self.bucket_count

    def add(self, key: int) -> None:
        bucket_index = self._hash(key)
        bucket = self.buckets[bucket_index]

        if key not in bucket:
            bucket.append(key)

    def remove(self, key: int) -> None:
        bucket_index = self._hash(key)
        bucket = self.buckets[bucket_index]

        if key in bucket:
            bucket.remove(key)

    def contains(self, key: int) -> bool:
        bucket_index = self._hash(key)
        bucket = self.buckets[bucket_index]

        return key in bucket

# Your MyHashSet object will be instantiated and called as such:
# obj = MyHashSet()
# obj.add(key)
# obj.remove(key)
# param_3 = obj.contains(key)
```实施首先创建`1000`桶。 每个桶都是一个空列表。 

这`_hash`辅助方法使用模算术计算存储桶索引。 这确保每个键一致地映射到同一个存储桶。 

在`add`方法中，我们首先定位到key对应的bucket。 然后，我们在附加之前检查该密钥是否已经存在。 这保证了唯一性。 

这`remove`方法也首先找到正确的桶。 如果密钥存在，我们将其从该存储桶中删除。 

这`contains`方法只是检查密钥是否存在于其存储桶中。 

所有操作仅在单个存储桶内进行，而不是扫描整个数据集，这就是散列提高效率的原因。 

## 解决方案```go
type MyHashSet struct {
	buckets [][]int
	size    int
}

func Constructor() MyHashSet {
	size := 1000
	buckets := make([][]int, size)

	return MyHashSet{
		buckets: buckets,
		size:    size,
	}
}

func (this *MyHashSet) hash(key int) int {
	return key % this.size
}

func (this *MyHashSet) Add(key int) {
	index := this.hash(key)
	bucket := this.buckets[index]

	for _, value := range bucket {
		if value == key {
			return
		}
	}

	this.buckets[index] = append(this.buckets[index], key)
}

func (this *MyHashSet) Remove(key int) {
	index := this.hash(key)
	bucket := this.buckets[index]

	for i, value := range bucket {
		if value == key {
			this.buckets[index] = append(bucket[:i], bucket[i+1:]...)
			return
		}
	}
}

func (this *MyHashSet) Contains(key int) bool {
	index := this.hash(key)
	bucket := this.buckets[index]

	for _, value := range bucket {
		if value == key {
			return true
		}
	}

	return false
}

/**
 * Your MyHashSet object will be instantiated and called as such:
 * obj := Constructor();
 * obj.Add(key);
 * obj.Remove(key);
 * param_3 := obj.Contains(key);
 */
```Go 实现遵循与 Python 版本相同的总体策略，但存在一些特定于语言的差异。 

Go 没有 Python 风格的列表成员资格检查，例如`key in bucket`，所以我们手动迭代切片。 

从切片中删除元素需要使用以下命令重建切片：```go
append(bucket[:i], bucket[i+1:]...)
```Go 切片会自动管理动态调整大小，因此我们仍然可以有效地将元素添加到存储桶中。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(1) 平均 | 每个操作只搜索一个桶 |
 | 空间| O(n + 桶) | 键和桶数组的存储 |

 平均时间复杂度是恒定的，因为散列将元素分布在许多桶中。 在最坏的情况下，所有密钥可能会碰撞到同一个存储桶中，从而导致`O(n)`操作，但具有合理的存储桶数量和均匀分布的键，平均性能仍然接近`O(1)`。 

空间复杂度包括存储的键和桶数组本身。

 ## 边缘情况

 ### 多次添加相同的密钥

 集合实现中的一个常见错误是意外存储重复项。 如果`add(5)`被重复调用，该集合仍应仅包含一个实例`5`。 

我们的实现通过在附加密钥之前检查密钥是否已存在于存储桶中来防止这种情况发生。 

### 删除不存在的密钥

 如果`remove(key)`调用不存在的键时，实现不应抛出错误或修改不相关的数据。 

我们的解决方案首先安全地搜索桶。 如果钥匙不存在，则不会发生任何事情。 

### 哈希冲突

 不同的键可以产生相同的桶索引。 例如，与`1000`桶：```
1 % 1000 = 1
1001 % 1000 = 1
2001 % 1000 = 1
```当发生冲突时，有缺陷的实现可能会覆盖现有值。 

我们的解决方案使用单独的链接来处理冲突，这意味着每个存储桶在列表中存储多个值。 即使多个密钥散列到同一个存储桶，所有密钥仍然可以独立访问。
