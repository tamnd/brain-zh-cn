[LeetCode 745 题](https://leetcode.com/problems/prefix-and-suffix-search/)

 **难度：** 🔴难
 **主题：** 数组、哈希表、字符串、设计、Trie

 ## 解决方案

 ## 问题理解

 该问题要求我们设计一种数据结构，支持基于前缀和后缀的高效搜索。 

我们得到一个单词数组，其中每个单词都有一个基于其在数组中位置的隐式索引。 这`WordFilter`类必须支持两种操作：

 1. 使用单词列表进行初始化。 
2. 表格的查询`f(pref, suff)`。 

对于每个查询，我们必须找到满足以下条件的所有单词：

 - 以前缀开头`pref`- 以后缀结尾`suff`在所有匹配的单词中，我们必须返回最大的索引。 如果没有单词满足这两个条件，我们返回`-1`。 

重要的细节是最大的索引很重要。 如果多个单词匹配，我们不能简单地返回遇到的第一个单词。 

这些约束强烈影响预期的解决方案设计：

 - 最多`10^4`话
 - 每个单词长度最多`7`- 最多`10^4`查询

 较小的最大字长非常重要。 虽然可以有很多单词和很多查询，但每个单词都很短。 这表明生成前缀和后缀的组合实际上可能是实用的。 

扫描每个查询的所有单词的简单实现需要重复检查每个单词，当有很多查询时，这会变得昂贵。 

有几种边缘情况值得尽早识别：

 - 多个单词可以共享相同的前缀和后缀。 
- 不同索引处可能存在重复的单词。 
- 查询可能根本不匹配任何单词。 
- 前缀或后缀可以是整个单词。 
- 前缀和后缀长度可以独立变化。 
- 因为我们必须返回最大的索引，所以后面的单词应该覆盖前面的匹配项。 

该问题保证所有字符串只包含小写英文字母且长度至少`1`，这简化了实现，因为我们不需要处理空字符串。 

## 方法

 ### 蛮力方法

 最直接的解决方案是存储单词，并针对每个查询扫描整个列表。 

对于每个单词，我们检查：

 - 它开始于`pref`？ 
- 结尾是`suff`？ 

如果两个条件都成立，我们将使用当前索引更新答案。 由于我们需要最大的索引，因此我们要么扫描所有单词，要么从末尾向后扫描。 

这种方法是正确的，因为它明确地验证了每个可能的候选者。 然而，当查询数量变大时，它就会变得低效。 

假设有：

 -`N = 10^4`字
-`Q = 10^4`查询

 每个查询可能会扫描所有单词，导致大约`10^8`在最坏的情况下进行检查。 

即使每个单词都很短，重复扫描整个字典的成本也太高了。 

### 关键见解

 关键的观察是字长非常小，最多`7`。 

对于一个字的长度`L`，可能的前缀数为`L + 1`，并且可能的后缀数也是`L + 1`。 

自从`L <= 7`，每个单词最多有：$$8 \times 8 = 64$$前缀-后缀组合。 

That means instead of searching during queries, we can preprocess every possible`(prefix, suffix)`配对并存储与该配对关联的最大索引。 

然后每个查询就变成一个简单的哈希图查找。 

例如，对于`"apple"`我们生成：

 - 前缀：`"", "a", "ap", "app", "appl", "apple"`- 后缀：`"", "e", "le", "ple", "pple", "apple"`对于每个组合，我们存储：```
(prefix + "#" + suffix) -> index
```如果稍后另一个单词产生相同的键，我们将覆盖该值。 这会自动确保存储的索引是最大的索引。 

这将昂贵的查询时间工作转化为预处理工作。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(Q × N × L) | O(N) | 扫描每个查询的所有单词 |
 | 最佳 | O(N × L² + Q) | O(N × L²) | 预先计算所有前缀后缀对 |

 这里：

-`N`= 字数
 -`Q`= 查询数
 -`L`= 最大字长`7`因为`L`很小，二次预处理成本是完全可控的。 

## 算法演练

 ### 最优算法

 1. 创建一个映射组合的哈希映射`(prefix, suffix)`最大单词索引的键。 

我们使用哈希映射是因为它提供平均情况下的 O(1) 查找时间。 密钥可以构造为：```
prefix + "#" + suffix
```分隔符避免连接字符串之间出现歧义。 
2. 迭代每个单词及其索引。 

对于每个单词，我们希望生成所有可能的前缀和后缀组合。 
3. 生成所有可能的前缀。 

对于一个字的长度`L`，前缀是：```
word[:0], word[:1], ..., word[:L]
```4. 生成所有可能的后缀。 

同样，后缀是：```
word[L:], word[L-1:], ..., word[0:]
```5. 将每个前缀-后缀组合存储在哈希映射中。 

对于每对：```
key = prefix + "#" + suffix
```店铺：```
hashmap[key] = current_index
```如果该密钥已经存在，则覆盖它。 由于索引随着迭代而增加，因此存储的值自动成为最大的索引。 
6. 在查询过程中，构造相同的组合键。 

供查询`(pref, suff)`:```
key = pref + "#" + suff
```7. 如果存在则返回存储的值。 

如果钥匙丢失，返回`-1`。 

### 为什么它有效

 该算法之所以有效，是因为每个单词的每个可能的前缀后缀组合都被显式地预先计算和存储。 

对于任何查询`(pref, suff)`，如果存在满足这两个条件的单词，则对应的键必须已经存在于哈希映射中。 由于在预处理过程中后面的索引会覆盖前面的索引，因此可以保证存储的值是最大的有效索引。 

因此，每个查询都会准确返回所需的答案。 

## Python 解决方案```python
from typing import List

class WordFilter:

    def __init__(self, words: List[str]):
        self.lookup = {}

        for index, word in enumerate(words):
            length = len(word)

            for prefix_length in range(length + 1):
                prefix = word[:prefix_length]

                for suffix_start in range(length + 1):
                    suffix = word[suffix_start:]

                    key = prefix + "#" + suffix
                    self.lookup[key] = index

    def f(self, pref: str, suff: str) -> int:
        key = pref + "#" + suff
        return self.lookup.get(key, -1)

# Your WordFilter object will be instantiated and called as such:
# obj = WordFilter(words)
# param_1 = obj.f(pref, suff)
```实现首先创建一个名为的字典`lookup`。 该字典存储从组合前缀后缀键到索引的映射。 

在初始化期间，我们迭代每个单词并生成所有可能的前缀和后缀。 

对于每个组合，我们使用以下方法创建一个密钥：```python
prefix + "#" + suffix
```并存储当前索引。 

如果稍后出现相同的组合，则字典条目将被覆盖。 这样自然就保留了最大的索引。 

查询方法非常小，因为所有繁重的计算已经在预处理期间完成。 我们只需构建相同的密钥并返回存储的值（如果存在）。 

由于字典查找的平均时间复杂度为 O(1)，因此查询变得非常高效。 

## 解决方案```go
type WordFilter struct {
    lookup map[string]int
}

func Constructor(words []string) WordFilter {
    lookup := make(map[string]int)

    for index, word := range words {
        length := len(word)

        for prefixLength := 0; prefixLength <= length; prefixLength++ {
            prefix := word[:prefixLength]

            for suffixStart := 0; suffixStart <= length; suffixStart++ {
                suffix := word[suffixStart:]

                key := prefix + "#" + suffix
                lookup[key] = index
            }
        }
    }

    return WordFilter{
        lookup: lookup,
    }
}

func (this *WordFilter) F(pref string, suff string) int {
    key := pref + "#" + suff

    if value, exists := this.lookup[key]; exists {
        return value
    }

    return -1
}

/**
 * Your WordFilter object will be instantiated and called as such:
 * obj := Constructor(words);
 * param_1 := obj.F(pref, suff);
 */
```Go 实现遵循与 Python 版本相同的逻辑。 

主要区别在于 Go 需要使用以下方式显式映射初始化：```go
make(map[string]int)
```Go 中的映射查找返回两个值：```go
value, exists := map[key]
```这使我们能够区分丢失的密钥和存储的值`0`。 

Go 中的字符串切片工作效率很高，因为字符串是不可变的字节切片。 由于该问题仅保证小写英文字母，因此基于字节的切片是安全的。

from typing import List

class WordFilter:

    def __init__(self, words: List[str]):
        self.lookup = {}

        for index, word in enumerate(words):
            length = len(word)

            for prefix_length in range(length + 1):
                prefix = word[:prefix_length]

                for suffix_start in range(length + 1):
                    suffix = word[suffix_start:]

                    key = prefix + "#" + suffix
                    self.lookup[key] = index

    def f(self, pref: str, suff: str) -> int:
        return self.lookup.get(pref + "#" + suff, -1)

# Provided example
wf = WordFilter(["apple"])
assert wf.f("a", "e") == 0  # basic prefix and suffix match

# No matching suffix
wf = WordFilter(["apple"])
assert wf.f("a", "x") == -1  # suffix does not exist

# No matching prefix
wf = WordFilter(["apple"])
assert wf.f("z", "e") == -1  # prefix does not exist

# Entire word as prefix and suffix
wf = WordFilter(["apple"])
assert wf.f("apple", "apple") == 0  # exact full-word match

# Multiple words, largest index should win
wf = WordFilter(["apple", "ample", "addle"])
assert wf.f("a", "le") == 2  # multiple matches, largest index returned

# Duplicate words
wf = WordFilter(["test", "test"])
assert wf.f("te", "st") == 1  # later duplicate overwrites earlier

# Single-character words
wf = WordFilter(["a", "b", "c"])
assert wf.f("a", "a") == 0  # smallest valid word

# Prefix longer than any valid candidate
wf = WordFilter(["abc"])
assert wf.f("abcd", "c") == -1  # impossible prefix

# Suffix longer than any valid candidate
wf = WordFilter(["abc"])
assert wf.f("a", "abcd") == -1  # impossible suffix

# Multiple overlapping combinations
wf = WordFilter(["banana", "bandana", "ban"])
assert wf.f("ban", "na") == 1  # bandana has largest matching index

# Query with no valid combination
wf = WordFilter(["hello", "world"])
assert wf.f("he", "ld") == -1  # no word satisfies both

 ## 边缘情况

 ### 多个匹配词

 该问题的一个微妙方面是多个单词可能满足相同的前缀和后缀查询。 幼稚的实现可能会意外返回第一个匹配索引而不是最大的索引。 

例如：```
words = ["apple", "ample", "addle"]
```询问：```
("a", "le")
```匹配所有三个单词。 

该实现可以正确处理此问题，因为在预处理期间后面的索引会覆盖哈希图中较早的条目。 

### 重复的单词

 输入可能包含不同索引处的重复单词。 

例如：```
["test", "test"]
```两个单词生成相同的前缀后缀组合。 

如果实现避免覆盖现有条目，它将错误地返回索引`0`。 相反，哈希映射存储最新的索引，确保答案变为`1`。 

### 没有匹配的查询

 某些查询可能不对应于任何存储的组合。 

例如：```
f("abc", "xyz")
```如果实现直接索引到映射而不检查存在性，则可能会产生错误或不正确的默认值。 

使用：```
dict.get(key, -1)
```Python 中的显式存在检查和 Go 中的显式存在检查可保证不存在的组合正确返回`-1`。
