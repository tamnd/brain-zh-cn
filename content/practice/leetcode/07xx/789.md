 # LeetCode 789 - 逃脱幽灵

 ## 问题理解

 该问题发生在无限二维网格上。 你从坐标开始`(0, 0)`并想要到达一个名为`target`。 与此同时，数个鬼魂也从自己的起始位置开始在网格上移动。 

在每个回合中，你和每个鬼魂都可以：

 - 向北、向南、向东或向西移动一个单位
 - 留在原地

 所有动作同时发生。 

你的目标是确定你是否能保证在任何鬼魂抓住你之前到达目标。 重要的是，如果鬼魂与你同时到达相同的位置，你就输了。 这包括目标方格本身。 

输入包括：

 -`ghosts`，幽灵坐标列表
 -`target`,你想要到达的坐标

 输出应该是：

 -`true`如果逃脱总是可能的
 -`false`否则

 关键细节是鬼魂可以最佳地移动。 你不是在检查是否存在一些幸运路径。 相反，你必须确定无论鬼魂如何移动，你是否都能保证成功。 

由于移动仅限于基本方向，因此在两点之间移动所需的最小转弯数就是曼哈顿距离。 

为了一点`(x1, y1)`和`(x2, y2)`，曼哈顿距离为：$|x_1-x_2|+|y_1-y_2|$限制比较小，最多100个鬼，所以效率不难实现。 挑战在于认识到简化整个问题的数学观察。 

一些边缘情况很重要：

 - 鬼魂可能已经非常接近目标。 
- 多个鬼魂可以共享同一位置。 
- 幽灵与你同时到达目标意味着失败。 
- 即使幽灵不在你和目标之间，它仍然可能通过足够快的到达来阻止逃跑。 

## 方法

 ### 蛮力方法

 一种简单的方法是尝试模拟无限网格上的运动。 我们可以从玩家的位置执行广度优先搜索，同时跟踪幽灵的移动。 

这个想法是：

 1. 生成玩家可以移动到的所有可能的位置。 
2. 生成鬼魂可以到达的所有可能位置。 
3. 继续依次进行，直到：

 - 玩家安全到达目标，或者
 - 幽灵拦截玩家。 

这种方法在理论上是正确的，因为 BFS 按时间递增顺序探索状态。 然而，它变得不切实际，因为网格是无限的，并且可达状态的数量增长得非常快。 

即使进行了修剪，状态空间也会变得巨大，因为每个回合都会为玩家和幽灵引入许多新位置。 

### 关键见解

 关键的观察是实际路径并不重要。 只有最短到达时间很重要。 

由于除了基本方向外，移动不受限制，因此两点之间的最短旅行时间就是曼哈顿距离。 

您达到目标的最短时间是：$|x_t|+|y_t|$因为你开始于`(0,0)`。 

每个幽灵到达目标的最短时间是：$|x_i-x_t|+|y_i-y_t|$如果任何幽灵能够在小于或等于你到达时间的时间内到达目标，那么逃脱是不可能的。 

为什么？ 

因为鬼魂不需要追逐你的确切路径。 他们只需要在某处拦截你即可。 如果鬼魂能在你之前到达目标，那么它就可以在那里等待。 由于同时到达同一个格子就算失败，所以你无法逃脱。 

因此：

 - 如果每个鬼魂需要比你严格更多的回合才能到达目标，那么就可以保证逃脱。 
——否则的话，逃跑是不可能的。 

这将问题转化为简单的距离比较。

 | 最佳| O(n) | O(1) | O(1) | 比较曼哈顿与目标的距离 |

 ## 算法演练

 1. 计算到目标的最小距离。 

自从你开始于`(0,0)`，您的旅行时间是从起点到目标的曼哈顿距离。 
2. 迭代每个幽灵。 

对于每个幻影位置`(gx, gy)`，计算幽灵到目标的曼哈顿距离。 
3. 比较距离。 

如果鬼魂的距离小于或等于你的距离，立即返回`False`。 

这意味着幽灵可以在你之前或同时到达目标，这肯定会失败。 
4.检查完所有鬼魂。 

如果没有鬼魂能像你一样快地到达目标，则返回`True`。 

### 为什么它有效

 正确性依赖于曼哈顿距离，该距离代表到达网格上某个位置所需的最小转弯数。 由于你和鬼魂都以相同的速度和移动规则移动，因此只有相对到达时间才重要。 

如果幽灵能够在你之前到达目标，那么幽灵可以直接移动到那里并等待。 因此，逃跑就变得不可能了。 

如果每个幽灵都比你需要更多的转弯，那么在到达目标之前没有幽灵可以拦截你，因为任何拦截点都需要至少与到达目标本身一样多的行进时间。 

## Python 解决方案```python
from typing import List

class Solution:
    def escapeGhosts(self, ghosts: List[List[int]], target: List[int]) -> bool:
        player_distance = abs(target[0]) + abs(target[1])

        for ghost_x, ghost_y in ghosts:
            ghost_distance = (
                abs(ghost_x - target[0]) +
                abs(ghost_y - target[1])
            )

            if ghost_distance <= player_distance:
                return False

        return True
```该实现首先使用曼哈顿距离计算玩家到目标的最短旅行时间`(0,0)`。 

接下来，算法循环遍历每个幽灵。 对于每个幽灵，它会计算该幽灵到达目标的最短旅行时间。 

关键的比较是：```python
if ghost_distance <= player_distance:
```如果这个条件成立，鬼魂可以在玩家之前或与玩家同时到达目标，因此不可能逃脱。 

如果循环结束时没有找到这样的幽灵，该函数将返回`True`。 

该实现使用恒定的额外内存，因为它只存储几个整数变量。 

## 解决方案```go
func escapeGhosts(ghosts [][]int, target []int) bool {
    playerDistance := abs(target[0]) + abs(target[1])

    for _, ghost := range ghosts {
        ghostDistance :=
            abs(ghost[0]-target[0]) +
                abs(ghost[1]-target[1])

        if ghostDistance <= playerDistance {
            return false
        }
    }

    return true
}

func abs(x int) int {
    if x < 0 {
        return -x
    }
    return x
}
```Go 实现遵循与 Python 版本相同的逻辑。 由于 Go 没有提供内置的整数绝对值函数`int`, 一个帮手`abs`功能是手动实现的。 

该解决方案使用切片作为坐标数组，并使用`range`环形。 整数溢出不是问题，因为坐标的边界是`10^4`，使所有距离计算都能轻松地适合 Go 的范围`int`类型。

 ## 边缘情况

 当幽灵能够以与玩家完全相同的移动次数到达目标时，就会出现一种重要的边缘情况。 如果比较使用，这很容易处理不当`<`而不是`<=`。 该问题明确指出同时到达不算作逃逸，因此实现正确使用`<=`。 

另一个关键情况是当幽灵已经在目标位置开始时。 在这种情况下，幽灵的距离为零，这意味着无论移动策略如何，玩家都会自动失败。 该算法自然会处理这个问题，因为`0 <= player_distance`立即评估为真。 

负坐标也很重要，因为曼哈顿距离需要绝对值。 一个有缺陷的实现，会忘记`abs()`会对位于网格负区域的目标或幽灵产生不正确的距离。 所提供的解决方案始终使用绝对差，确保所有坐标范围的正确性。 

更微妙的边缘情况涉及多个幽灵共享同一位置。 由于每个重影都是独立评估的，因此重复项不需要任何特殊处理。 该算法只是检查每个幽灵到目标的距离并返回`False`一旦任何一个幽灵能够拦截玩家。
