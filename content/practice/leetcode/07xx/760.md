[LeetCode 760 题](https://leetcode.com/problems/find-anagram-mappings/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表

 ## 解决方案

 ## 问题理解

 该问题要求我们构建一个索引映射`nums1`到`nums2`， 在哪里`nums2`保证是一个字谜`nums1`。 由于字谜意味着相同的元素出现在两个数组中，但可能以不同的顺序，因此中的每个值`nums1`必须出现在某处`nums2`。 

对于每个元素`nums1[i]`，我们需要找到一个索引`j`在`nums2`这样：```
nums1[i] == nums2[j]
```输出是一个整数数组，称为`mapping`， 在哪里：```
mapping[i] = j
```这意味着位置上的元素`i`在`nums1`出现在位置`j`在`nums2`。 

一个重要的细节是允许重复。 这意味着一个值可以在两个数组中出现多次。 因为问题明确指出**任何有效答案都是可接受的**，所以我们不需要为重复值找到唯一或特定的映射。 我们只需要返回一个有效的索引对应关系即可。 

例如：```
nums1 = [12,28,46,32,50]
nums2 = [50,12,32,46,28]
```数量`12`出现在索引处`1`在`nums2`，所以结果的第一个元素是`1`。 相似地，`28`出现在索引处`4`,`46`出现在索引处`3`， 等等。 

限制很小：

 -`1 <= nums1.length <= 100`- 值范围为`0`到`10^5`-`nums2`保证是一个字谜`nums1`由于数组长度最多为`100`，即使是二次解也能轻松通过。 然而，这个问题自然适合哈希表解决方案，它为我们提供了线性时间复杂度。 

主要的边缘情况来自**重复的数字**。 如果存在重复项，则每个值仅存储一个索引的简单哈希映射可能会意外地多次重复使用同一索引。 由于问题接受任何有效答案，因此在许多情况下，每个数字存储一个有效索引就足够了，但如果需要，更强大的实现可以存储多个索引。 幸运的是，由于任何有效答案都会被接受，并且输入保证确保匹配频率，因此从值到一个索引的简单哈希映射可以正常工作。 

## 方法

 ### 蛮力方法

 最简单的方法是遍历每个元素`nums1`并在其中搜索它`nums2`。 

对于每一个`nums1[i]`，我们扫描所有元素`nums2`直到找到匹配的值。 一旦找到，我们记录它的索引。 

这种方法之所以有效是因为`nums2`保证包含来自的每个值`nums1`。 因此，每一次寻找最终都会成功。 

但这种方法会重复扫描第二个数组，导致不必要的重复工作。 对于中的每个元素`nums1`，我们可以检查所有`n`的元素`nums2`。 

由于有`n`中的元素`nums1`，总复杂度变为二次。 

### 最优方法，哈希图

 关键的观察是重复搜索是浪费的。 因为我们经常会问：```
"At what index does this value appear in nums2?"
```我们可以预处理`nums2`到哈希映射中。 

我们创建一个字典，其中：```
value -> index in nums2
```然后，而不是扫描`nums2`重复地，我们可以使用哈希表查找立即检索索引。 

构建哈希映射后，我们迭代`nums1`and append the corresponding mapped index for each value.

 这减少了查找时间`O(n)`到`O(1)`平均而言。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 扫描`nums2`对于中的每个元素`nums1`|
 | 最佳 | O(n) | O(n) | 使用哈希映射进行恒定时间索引查找 |

 ## 算法演练

 ### 最优算法

 1. 创建一个空的哈希映射，名为`index_map`。 

该映射将存储每个值的位置`nums2`。 使用哈希图的原因是它提供了平均`O(1)`查找时间，这比重复扫描数组要快得多。 
2. 遍历`nums2`并填充哈希图。 

对于每个索引`i`和价值`num`在`nums2`， 店铺：```
index_map[num] = i
```经过这一步，我们可以立即找到任意数字的索引`nums2`。 
3. 创建一个空结果数组，名为`mapping`。 

这个数组将保存最终的答案。 
4. 遍历`nums1`。 

对于每个数字`num`在`nums1`,查找其对应的索引`index_map`并将其附加到`mapping`。 
5. 返回`mapping`大批。 

### 为什么它有效

 正确性来自于保证`nums2`是一个字谜词`nums1`。 这意味着中的每个值`nums1`存在于`nums2`。 

哈希映射为每个数字存储一个有效的索引`nums2`。 因此，第二次遍历期间的每次查找都会成功。 由于每个映射索引对应相同的值，因此生成的映射满足问题定义。 

即使有重复项，任何有效的映射都会被接受，并且存储一个有效的匹配项就足以产生正确的答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def anagramMappings(self, nums1: List[int], nums2: List[int]) -> List[int]:
        index_map = {}

        for index, num in enumerate(nums2):
            index_map[num] = index

        mapping = []

        for num in nums1:
            mapping.append(index_map[num])

        return mapping
```实现首先构建一个名为的字典`index_map`。 我们迭代`nums2`使用`enumerate`，它给出了每个位置的索引和值。 每个数字都存储为键，而其索引则成为值。 

预处理后`nums2`，我们创建`mapping`列表。 然后我们迭代`nums1`并执行恒定时间查找`index_map`。 

因为字典已经包含每个数字的索引，所以我们只需将映射的索引附加到结果列表中即可。 

最后，我们返回完成的映射数组。 

## 解决方案```go
func anagramMappings(nums1 []int, nums2 []int) []int {
	indexMap := make(map[int]int)

	for index, num := range nums2 {
		indexMap[num] = index
	}

	mapping := make([]int, 0, len(nums1))

	for _, num := range nums1 {
		mapping = append(mapping, indexMap[num])
	}

	return mapping
}
```Go 实现遵循与 Python 版本相同的逻辑。 一个`map[int]int`用于存储值和索引之间的关系。 

Go 使用切片而不是 Python 列表。 我们初始化`mapping`容量等于的切片`len(nums1)`以避免附加时不必要的重新分配。 

不用担心整数溢出，因为所有值和索引都在 Go 的范围内`int`范围。 由于该问题保证了有效输入，因此我们不需要在查找之前检查某个键是否存在。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 一次构建哈希映射，一次构建结果 |
 | 空间| O(n) | 哈希映射最多存储`n`元素|

 该算法执行两次线性遍历。 第一次遍历构建哈希图`nums2`，第二次遍历使用恒定时间哈希查找构造答案。 由于哈希图访问是`O(1)`平均而言，总运行时间是线性的。 

额外的内存来自在哈希映射中存储索引，这需要与元素数量成比例的空间。

 ## 边缘情况

 一种重要的边缘情况是**重复值**。 例如：```
nums1 = [7,7,7]
nums2 = [7,7,7]
```幼稚的实现可能会担心为每个重复项分配唯一的索引。 但是，该问题明确允许任何有效答案，这意味着重复使用相同的有效索引是可以接受的。 由于我们的哈希映射存储了该数字的一次出现，因此该实现仍然返回正确的映射。 

另一种边缘情况是**最小输入大小**，其中两个数组都只包含一个元素。 例如：```
nums1 = [5]
nums2 = [5]
```这种情况可能会因索引错误或初始化错误而暴露。 我们的实现很自然地处理它，因为哈希映射包含一个条目，并且单次查找成功。 

第三种边缘情况是 **数组的值位于约束边界**，例如`0`和`100000`。 大的数值范围有时会导致低效的解决方案，例如分配按值索引的巨大数组。 我们的实现通过使用哈希映射来避免此问题，该映射仅存储实际出现的值。 

最后，一个重要的保证是`nums2`总是一个字谜`nums1`。 由于这种保证，我们永远不需要处理丢失的元素或无效的查找。 中的每个数字`nums1`保证存在于`nums2`，使哈希表访问安全。
