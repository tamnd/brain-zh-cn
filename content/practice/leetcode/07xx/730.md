[LeetCode 730 题](https://leetcode.com/problems/count- Different-palindromic-subsequences/)

 **难度：** 🔴难
 **主题：** 字符串、动态规划

 ## 解决方案

 ## 问题理解

 这个问题要求我们计算字符串中存在多少个不同的非空回文子序列。 

通过删除字符同时保留剩余字符的相对顺序来形成子序列。 与子字符串不同，子序列不需要是连续的。 

回文向前和向后读起来都是一样的。 

重要的细节是我们正在计算不同的回文子序列，而不是出现的总数。 如果同一个回文可以通过多种方式组成，则只需计算一次。 

例如，在`"bccb"`:

 -`"b"`是一个回文
 -`"c"`是一个回文
 -`"bb"`是一个回文
 -`"cc"`是一个回文
 -`"bcb"`是一个回文
 -`"bccb"`是一个回文

 尽管`"bcb"`可以由多个索引组合生成，只计算一次。 

输入大小可达`1000`，它足够大，以至于无法暴力生成所有子序列。 一个长度的字符串`1000`有`2^1000`子序列，这是一个天文数字。 

另一个重要的限制是字符被限制为`'a'`,`'b'`,`'c'`， 和`'d'`。 这种小的字母大小是我们可以使用基于字符的动态编程进行优化的一个主要暗示。 

答案可能会变得非常大，因此我们必须将其模数返回：```
10^9 + 7
```重要的边缘情况包括：

 - 只有一个字符的字符串
 - 所有字符都相同的字符串
 - 具有许多重复回文的字符串
 - 可以通过多种方式形成相同回文的字符串
 - 需要高效记忆或制表的大字符串

 最大的挑战是避免重复计数。 

## 方法

 ### 蛮力方法

 蛮力的想法很简单：

 1. 生成每个可能的子序列
 2. 检查每个子序列是否是回文
 3. 将有效的回文插入集合中
 4.返回集合的大小

 这是有效的，因为集合自然会删除重复项。 

然而，长度为的字符串的子序列的数量`n`是：```
2^n
```为了`n = 1000`，这是完全不可行的。 

即使回文检查需要线性时间，子序列的指数数量也会使该方法无法使用。 

### 最佳解决方案的关键见解

 关键的观察是我们不需要显式构造子序列。 

相反，我们可以对子串使用动态规划。 

定义：```
dp[i][j]
```作为子串内不同回文子序列的数量：```
s[i:j+1]
```困难的部分是正确处理重复项。 

认为：```
s[i] == s[j]
```那么中间子串内的每个回文都可能被这些匹配字符包裹。 

例如：```
middle palindrome = "c"
wrapping with 'b' gives "bcb"
```但是，当中间范围内存在相同的字符时，就会出现重复项。 

为了避免过度计算，我们找到：

 - 第一次出现`s[i]`里面`(i+1, j-1)`- 最后一次出现的`s[i]`里面`(i+1, j-1)`这创建了三种不同的情况：

 1. 里面没有匹配的字符
 2. 里面正好有一个匹配的字符
 3. 里面有多个匹配字符

 每种情况都需要不同的递归关系。 

这将问题转化为可管理的问题`O(n^2)`动态规划解决方案。 

## 方法比较

 ## 算法演练

 ### 第 1 步：定义 DP 状态

 我们创建一个 2D DP 表：```
dp[i][j]
```它表示以下中不同的非空回文子序列的数量：```
s[i:j+1]
```### 步骤 2：初始化单个字符

 每个字符本身就是一个回文。 

所以：```
dp[i][i] = 1
```为所有人`i`。 

### 步骤 3：按长度处理子字符串

 我们从短到长处理子字符串。 

这可以确保较小的子问题在较大的子问题依赖它们之前就已经得到解决。 

### 步骤 4：处理不同的边界字符

 如果：```
s[i] != s[j]
```然后我们结合以下结果：

 -`dp[i+1][j]`-`dp[i][j-1]`但减去：

 -`dp[i+1][j-1]`因为它被计算了两次。 

所以：```
dp[i][j] =
dp[i+1][j] + dp[i][j-1] - dp[i+1][j-1]
```### 步骤 5：处理匹配边界字符

 如果：```
s[i] == s[j]
```然后我们在区间内搜索匹配的字符。 

让：

-`left`是第一次出现`s[i]`里面`(i+1, j-1)`-`right`是最后一次出现

 现在有三种情况。 

####情况1：里面没有匹配的字符

 如果不存在匹配字符：```
left > right
```那么：

 - 所有中间回文都可以被包裹
 - 加`"s[i]"`本身
 - 加`"s[i]s[j]"`公式：```
dp[i][j] = 2 * dp[i+1][j-1] + 2
```#### 情况 2：内部恰好有一个匹配字符

 如果：```
left == right
```然后出现一个重复的回文。 

公式：```
dp[i][j] = 2 * dp[i+1][j-1] + 1
```#### 情况 3：内部有多个匹配字符

 如果：```
left < right
```那么里面已经算了很多回文了。 

我们减去重复的区域：```
dp[left+1][right-1]
```公式：```
dp[i][j] =
2 * dp[i+1][j-1] - dp[left+1][right-1]
```### 第 6 步：应用模数

 由于减法可能会产生负值，因此我们使用以下方法进行标准化：```
MOD = 10^9 + 7
```### 第 7 步：返回最终答案

 整个字符串的结果是：```
dp[0][n-1]
```### 为什么它有效

 DP 之所以有效，是因为每个回文子序列都属于以下两个类别之一：

 1. 排除至少一个边界字符
 2. 包含两个边界字符

 递归关系划分了这些可能性，而不会丢失或重复计算有效的回文。 使用仔细的重复处理`left`和`right`保证每个不同的回文都被精确计算一次。 

## Python 解决方案```python
class Solution:
    def countPalindromicSubsequences(self, s: str) -> int:
        MOD = 10**9 + 7
        n = len(s)

        dp = [[0] * n for _ in range(n)]

        for i in range(n):
            dp[i][i] = 1

        for length in range(2, n + 1):
            for i in range(n - length + 1):
                j = i + length - 1

                if s[i] != s[j]:
                    dp[i][j] = (
                        dp[i + 1][j]
                        + dp[i][j - 1]
                        - dp[i + 1][j - 1]
                    )
                else:
                    left = i + 1
                    right = j - 1

                    while left <= right and s[left] != s[i]:
                        left += 1

                    while left <= right and s[right] != s[i]:
                        right -= 1

                    if left > right:
                        dp[i][j] = 2 * dp[i + 1][j - 1] + 2
                    elif left == right:
                        dp[i][j] = 2 * dp[i + 1][j - 1] + 1
                    else:
                        dp[i][j] = (
                            2 * dp[i + 1][j - 1]
                            - dp[left + 1][right - 1]
                        )

                dp[i][j] %= MOD

        return dp[0][n - 1]
```该实现首先创建一个 2D DP 表，其中每个条目存储子串间隔的不同回文子序列的数量。 

对角线初始化为`1`因为每个字符都构成一个回文。 

外循环按长度递增的顺序处理子字符串。 这保证了所有较小的子问题在使用之前已经被计算。 

当边界字符不同时，实现应用标准的包含-排除原则。 我们结合删除任一边界的计数并减去重叠。 

当边界字符匹配时，实现向内搜索以查找重复的匹配字符。 这些搜索确定应使用哪个递推公式。 

每次计算后都会应用模运算，以保持值有界并防止负中间结果引起问题。 

最后，算法返回覆盖整个字符串的DP值。 

## 解决方案```go
func countPalindromicSubsequences(s string) int {
    const MOD int = 1000000007

    n := len(s)

    dp := make([][]int, n)
    for i := range dp {
        dp[i] = make([]int, n)
        dp[i][i] = 1
    }

    for length := 2; length <= n; length++ {
        for i := 0; i <= n-length; i++ {
            j := i + length - 1

            if s[i] != s[j] {
                dp[i][j] = dp[i+1][j] + dp[i][j-1] - dp[i+1][j-1]
            } else {
                left := i + 1
                right := j - 1

                for left <= right && s[left] != s[i] {
                    left++
                }

                for left <= right && s[right] != s[i] {
                    right--
                }

                if left > right {
                    dp[i][j] = 2*dp[i+1][j-1] + 2
                } else if left == right {
                    dp[i][j] = 2*dp[i+1][j-1] + 1
                } else {
                    dp[i][j] = 2*dp[i+1][j-1] - dp[left+1][right-1]
                }
            }

            dp[i][j] %= MOD

            if dp[i][j] < 0 {
                dp[i][j] += MOD
            }
        }
    }

    return dp[0][n-1]
}
```Go 实现遵循与 Python 版本相同的动态编程结构。 

Go 特定的一个重要细节是处理负模结果。 在围棋中，`%`保留被除数的符号，因此减法可能会留下负值。 我们明确添加`MOD`必要时。 

DP表是使用切片的切片来实现的。 自从`n <= 1000`， 这`O(n^2)`内存使用量是可以接受的。

 ## 边缘情况

 ### 单字符串

 像这样的字符串：```
"a"
```是最小的有效输入。 

一个常见的错误是忘记正确初始化基本 DP 状态。 如果`dp[i][i]`未初始化为`1`, all larger transitions become incorrect.

 该实现显式地将每个对角线单元初始化为`1`，保证计算单字符回文数。 

### 具有所有相同字符的字符串

 考虑：```
"aaaa"
```许多不同的子序列选择生成相同的回文。 

例如：

-`"a"`可以通过多种方式形成
 -`"aa"`可以通过多种方式形成

 简单的计数方法会大量过量计算重复项。 

该实现通过仔细定位重复的边界字符并在必要时减去已经计数的区域来避免这种情况。 

### 重叠的重复结构

 考虑：```
"abba"
```回文`"aba"`可以通过不同的子序列组合产生。 

如果没有正确的包含-排除逻辑，重复计数就不可避免。 

复发：```
dp[i+1][j] + dp[i][j-1] - dp[i+1][j-1]
```确保重叠区域只计算一次。 

### 减法期间的负值

 一些转换会减去大的重叠范围。 

如果没有模归一化，值可能会暂时变为负值。 

该实现在每次更新后应用模数，并且 Go 版本通过添加显式纠正负结果`MOD`。
