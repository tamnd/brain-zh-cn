[LeetCode 735 题](https://leetcode.com/problems/asteroid-collision/)

 **难度：** 🟡 中等
 **主题：** 数组、堆栈、模拟

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个整数列表，表示小行星在太空中沿直线移动。 每个整数包含两条信息：

 - 绝对值代表小行星的大小。 
- 符号代表方向：

 - 正数向右移动。 
- 负数向左移动。 

所有小行星都以相同的速度移动。 当两颗小行星相互靠近时，就会发生碰撞。 较小的小行星被摧毁。 如果两颗小行星大小相同，则两颗小行星都会被摧毁。 朝同一方向移动的小行星永远不会相撞。 

目标是在解决所有可能的碰撞后返回所有幸存小行星的最终状态。 

例如，在输入中`[5, 10, -5]`, 小行星`10`正在向右移动并且`-5`正在向左移动。 由于它们彼此靠近，因此它们发生碰撞。 小行星`10`之所以能生存下来，是因为它的尺寸更大。 小行星`5`从不与`10`因为两者都向右移动。 

约束告诉我们数组最多可以包含`10^4`小行星。 这意味着重复扫描数组并删除元素的低效模拟可能会变得太慢。 我们需要一种能够有效处理碰撞的解决方案，最好是在线性时间内处理。 

一些边缘情况很重要：

 - 可能会发生多次连续碰撞，例如`[10, 2, -5]`。 
- 同等大小的小行星会完全摧毁彼此，例如`[8, -8]`。 
- 朝同一方向移动的小行星永远不会相互作用。 
- 一颗大的负小行星可能会在停止之前摧毁许多较小的正小行星。 
- 阵列开头或结尾的小行星可能永远不会与任何物体相撞。 

一个关键的观察是，只有当向右移动的小行星出现在向左移动的小行星之前时，才会发生碰撞。 这意味着我们只需要考虑正数后面跟着负数的情况。 

## 方法

 ### 蛮力方法

 一种简单的方法是重复扫描阵列，寻找将发生碰撞的相邻小行星。 

每当我们找到一对左小行星向右移动而右小行星向左移动时，我们就根据规则解决碰撞：

 - 移除较小的小行星。 
- 如果尺寸相等，请将两者移除。 

修改数组后，我们重新开始扫描，因为现在可能会发生新的冲突。 

这种方法之所以有效，是因为它直接模拟物理过程。 然而，它的效率很低，因为重复从数组中删除元素的成本很高，而且相同的小行星可能会被多次访问。 

在最坏的情况下，每次碰撞可能需要移动许多元素，导致时间复杂度成二次方。 

### 最佳堆栈方法

 关键的见解是冲突只在以下之间发生：

 - 先前见过的向右移动的小行星
 - 以及当前向左移动的小行星

 这自然建议使用堆栈。 

该堆栈表示在处理先前的碰撞后仍然存活的小行星。 当我们遇到一颗新的小行星时：

 - 如果它向右移动，它就不会与较早的小行星相撞，因此我们将其推入堆栈。 
- 如果它向左移动，它可能会与堆栈中已有的向右移动的小行星相撞。 

我们反复将当前向左移动的小行星与堆栈顶部进行比较，直到发生以下情况之一：

 - 当前的小行星爆炸。 
- 堆栈小行星爆炸。 
- 两者都爆炸了。 
- 不可能再发生碰撞。 

这种方法非常有效，因为每颗小行星最多被推入和弹出一次。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) 或 O(n) | 反复扫描并修改数组 |
 | 最佳| O(n) | O(n) | 使用堆栈有效解决冲突 |

 ## 算法演练

 1. 初始化一个空堆栈。 

该堆栈将存储迄今为止幸存的小行星。 
2. 迭代输入数组中的每个小行星。 

我们从左到右处理小行星，因为它们在数组中的位置代表空间顺序。 
3. 如果当前小行星向右移动，则将其压入堆栈。 

向右移动的小行星不会与较早的小行星相撞，因为它们都位于其左侧。 
4. 如果当前小行星向左移动，请检查是否发生碰撞。 

仅当出现以下情况时才可能发生碰撞：

 - 堆栈不为空
 - 顶部的小行星正在向右移动
 - 当前小行星正在向左移动
 5. 比较碰撞期间小行星的大小。 

让：

-`top`成为堆栈中向右移动的小行星
 -`current`是向左移动的小行星

 有以下三种可能：

 - 如果`abs(current) > top`，堆栈小行星爆炸。 

移除堆栈小行星并继续检查是否有更多碰撞。 
- 如果`abs(current) == top`，两颗小行星都爆炸了。 

移除堆栈小行星并停止处理当前小行星。 
- 如果`abs(current) < top`，当前小行星爆炸。 

停止处理当前的小行星。 
6. 如果当前小行星在所有碰撞中都幸存下来，则将其推入堆栈。 
7. 处理完所有小行星后，返回堆栈。 

### 为什么它有效

 该堆栈始终以正确的顺序维护幸存的小行星。 任何未解决的碰撞都必须涉及当前向左移动的小行星和最近幸存的向右移动的小行星。 较早的小行星无法跳过较晚的小行星，因此解决与堆栈顶部的碰撞就足够了。 由于每个可能的冲突都会在相关时得到准确处理，因此最终堆栈代表正确的幸存配置。 

## Python 解决方案```python
from typing import List

class Solution:
    def asteroidCollision(self, asteroids: List[int]) -> List[int]:
        stack = []

        for asteroid in asteroids:
            alive = True

            while alive and asteroid < 0 and stack and stack[-1] > 0:
                if stack[-1] < -asteroid:
                    stack.pop()
                elif stack[-1] == -asteroid:
                    stack.pop()
                    alive = False
                else:
                    alive = False

            if alive:
                stack.append(asteroid)

        return stack
```该实现使用堆栈来存储幸存的小行星。 

外循环一次处理一颗小行星。 对于每颗小行星，变量`alive`追踪小行星在潜在碰撞后是否幸存。 

这`while`循环仅在可能发生冲突时运行。 这需要：

 - 当前向左移动的小行星
 - 堆栈顶部包含一颗向右移动的小行星

 循环内部：

 - 如果当前小行星较大，则移除堆栈小行星。 
- 如果两者相等，则两者都被摧毁。 
- 如果堆叠的小行星较大，则当前小行星被摧毁。 

如果当前小行星在所有碰撞中都幸存下来，则会将其添加到堆栈中。 

最后，堆栈按顺序包含最后幸存的小行星。 

## 解决方案```go
func asteroidCollision(asteroids []int) []int {
    stack := []int{}

    for _, asteroid := range asteroids {
        alive := true

        for alive && asteroid < 0 && len(stack) > 0 && stack[len(stack)-1] > 0 {
            top := stack[len(stack)-1]

            if top < -asteroid {
                stack = stack[:len(stack)-1]
            } else if top == -asteroid {
                stack = stack[:len(stack)-1]
                alive = false
            } else {
                alive = false
            }
        }

        if alive {
            stack = append(stack, asteroid)
        }
    }

    return stack
}
```Go 实现遵循与 Python 版本相同的逻辑。 

切片用作堆栈。 使用以下方式访问顶部元素`stack[len(stack)-1]`，并且弹出是通过切片完成的。 

Go 不会以影响该算法的方式区分空切片和 nil 切片，因此初始化为`[]int{}`就足够了。 

整数溢出不是问题，因为小行星的大小受以下限制`1000`。

 ## 边缘情况

 当多次碰撞依次发生时，就会出现一种重要的边缘情况。 例如，`[10, 2, -5]`需要小行星`-5`首先摧毁`2`然后再次碰撞`10`。 只检查每个小行星一次碰撞的简单实现在这里会失败。 基于堆栈的解决方案正确地继续循环处理碰撞，直到小行星爆炸或幸存。 

另一个棘手的情况是大小相同的小行星，例如`[8, -8]`。 两颗小行星都必须完全消失。 一些实现意外地留下了一颗小行星，因为它们没有单独处理相等的情况。 此实现显式检查相等性并删除两个小行星。 

第三个重要的边缘情况是不可能发生碰撞的情况，例如`[-2, -1, 1, 2]`。 即使正小行星和负小行星同时存在，它们也会相互远离，因为负小行星已经在左边了。 该算法仅通过检查向右移动的小行星何时在堆栈上以及当前小行星何时向左移动来正确避免碰撞。 

另一个微妙的边缘情况涉及一颗大型小行星摧毁许多较小的小行星，例如`[4, 3, 2, -10]`。 小行星`-10`必须反复碰撞，直到所有较小的向右移动的小行星被清除。 这`while`循环确保在继续之前完全处理该链式反应。 

最后，所有小行星朝同一方向移动的阵列根本不需要碰撞。 堆栈会自然地处理这个问题，因为碰撞条件永远不会被触发，因此所有小行星都保持不变。
