[LeetCode 第 717 题](https://leetcode.com/problems/1-bit-and-2-bit-characters/)

 **难度：** 🟢简单
 **主题：** 数组

 ## 解决方案

 ## 问题理解

 在这个问题中，我们给出了一个二进制数组，称为`bits`。 该数组表示使用以下规则的编码字符序列：

 - 一位字符由一个单独的字符表示`0`- 两位字符由以下任一表示`10`或者`11`该数组保证以`0`。 我们的任务是确定解码中的最终字符是否必须是一位字符。 

重要的细节是解码必须从左到右进行。 每当我们遇到：

 -`0`，它代表一个完整的一位字符
 -`1`，它必须与下一位组合形成一个两位字符

 我们不允许任意分割位。 编码规则唯一确定如何解析数组。 

例如，考虑：```
[1,0,0]
```前两位，`10`，形成一个两位字符。 其余`0`成为一位字符。 因此，答案是`true`。 

现在考虑：```
[1,1,1,0]
```前两位，`11`，形成一个两位字符。 其余`10`也形成一个两位字符。 最后一个`0`作为两位字符的一部分被消耗，所以答案是`false`。 

限制很小：

 -`1 <= bits.length <= 1000`- 每个值都是`0`或者`1`由于输入大小适中，因此即使线性扫描也绰绰有余。 

有几个重要的边缘情况需要考虑：

 - 单元素数组，例如`[0]`- 末尾之前的每个字符都是两位字符的数组
 - 包含长串的数组`1`决赛前`0`- 最终的情况`0`是一个的一部分`10`或者`11`一对

 该问题保证编码有效并且数组始终以`0`，这大大简化了逻辑。 

## 方法

 ### 蛮力方法

 暴力解决方案会将整个数组显式解码为字符。 

我们将从索引开始`0`并反复：

 - 如果当前位是`0`，记录一位字符并向前移动一位
 - 如果当前位是`1`，记录一个两位字符并向前移动两个位置

 最后，我们检查最终解码的字符是否是一位字符。 

这种方法是正确的，因为它直接遵循问题中所述的编码规则。 每个字符都按顺序解码，因此保证结果与预期的解释相匹配。 

然而，这个解决方案做了比必要的更多的工作，因为我们实际上不需要存储或构造解码的字符。 我们只关心最后一个字符是一位还是两位。 

### 最佳方法

 关键的观察是我们只需要模拟遍历，而不存储解码结果。 

我们可以使用索引扫描数组：

 - 如果我们看到`0`，向前迈出一步
 - 如果我们看到`1`，向前移动两步

 我们在最终位置之前停止并确定是否正好落在最后一个索引上。 

如果直接遍历到最后一个索引，则最后一个字符是一位字符。 

如果遍历跳过最后一个索引，则最终的索引`0`作为两位字符的一部分被消耗。 

这是有效的，因为编码是确定性的。 在每个位置，当前位唯一地确定必须消耗多少个位置。

 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 显式解码并存储字符 |
 | 最佳 | O(n) | O(1) | O(1) | 使用索引跳转模拟解码 |

 ## 算法演练

 1.初始化一个索引变量`i`到`0`。 
2. 继续处理`i`小于`len(bits) - 1`。 

我们故意在最终索引之前停止，因为我们想要确定最后一位是独立的还是被两位字符消耗。 
3. 在每一步中，检查`bits[i]`。 

- 如果`bits[i] == 0`，这代表一位字符，因此递增`i`经过`1`。 
- 如果`bits[i] == 1`，这必须代表两位字符的开始，因此递增`i`经过`2`。 
4. 循环结束后，检查是否`i == len(bits) - 1`。 

- 如果为 true，则遍历恰好落在最后一位，这意味着最后一个字符是一位字符。 
- 否则，最后一位将作为两位字符的一部分被消耗。 

### 为什么它有效

 该算法之所以有效，是因为编码规则是确定性的。 每一个`0`消耗一个位置，并且每个`1`消耗两个位置。 通过精确模拟此过程，索引始终指向下一个未解码字符的开头。 

如果遍历恰好在最后一个索引处停止，那么最后一个索引`0`尚未被消耗，必须代表一位字符。 如果遍历超出了最后一个索引，则最终的`0`已经作为两位字符的一部分被消耗。 

## Python 解决方案```python
from typing import List

class Solution:
    def isOneBitCharacter(self, bits: List[int]) -> bool:
        index = 0
        last_index = len(bits) - 1

        while index < last_index:
            if bits[index] == 0:
                index += 1
            else:
                index += 2

        return index == last_index
```该实现紧密遵循前面描述的算法。 

我们首先计算`last_index`，它表示数组中的最终位置。 这使得比较更容易阅读并避免重复调用`len(bits)`。 

这`while`循环处理字符，直到到达或通过最后一个位置。 循环内部：

 - A`0`将指针前进一个位置，因为它代表一位字符。 
- A`1`指针前进两个位置，因为它开始一个两位字符。 

解码完成后，我们返回指针是否正好停在最终索引处。 

该解决方案不分配额外的内存，仅使用几个整数变量，使其非常节省空间。 

## 解决方案```go
func isOneBitCharacter(bits []int) bool {
    index := 0
    lastIndex := len(bits) - 1

    for index < lastIndex {
        if bits[index] == 0 {
            index++
        } else {
            index += 2
        }
    }

    return index == lastIndex
}
```Go 实现几乎完全反映了 Python 解决方案。 

Go 中的切片已经提供了高效的索引访问，因此不需要额外的数据结构。 由于约束很小并且索引保持在整数限制内，因此不存在溢出问题。 

逻辑仍然相同：

 -`0`前进一位
 -`1`前进两个位置
 - 最终比较确定最后一位是否独立

 ## 边缘情况

 ### 单元素数组

 输入如下：```
[0]
```是最小可能的有效输入。 在检查两位字符时，粗心的实现可能会错误地尝试超出数组范围进行读取。 

这个实现自然地处理这种情况，因为循环条件`index < last_index`立即为假。 算法直接返回`True`自从单身以来`0`必须是一位字符。 

### 两位字符消耗最后的零

 考虑：```
[1,0]
```决赛`0`并不孤立。 相反，它形成两位字符`10`。 

有缺陷的实现可能会错误地假设每个以`0`具有一位最终字符。 我们的遍历避免了这个错误，因为索引在遇到前导后会跳跃两个位置`1`。 

### 连续领先

 输入如：```
[1,1,1,1,0]
```可能会很棘手，因为几个两位字符连续出现。 

简单的解决方案可能会导致解析边界错位。 此实现通过严格遵循从左到右的编码规则来避免歧义。 每当一个`1`遇到时，正好消耗两个位置，保证整个遍历过程中的正确对齐。
