[LeetCode 754 题](https://leetcode.com/problems/reach-a-number/)

 **难度：** 🟡 中等
 **主题：** 数学、二分查找

 ## 解决方案

 ## 问题理解

 该问题要求我们找到从位置 0 开始的无限数轴上到达特定位置所需的最少移动次数。每次移动`i`让你准确移动`i`步骤，向左或向右。 输入是单个整数`target`，可以是正值，也可以是负值，代表我们必须到达的位置。 输出是一个整数，表示最小移动次数。 

关键的限制是`target`可以非常大，最大可达±10^9，并且永远不会为零。 这消除了从目标开始的琐碎情况。 边缘情况包括负目标（与正目标对称）和需要翻转方向才能准确到达的目标。 

关键的观察是第一个的总和`n`自然数是`n*(n+1)/2`。 该问题可以重新定义为寻找最小的`n`这样这个总和（可能通过翻转一些动作来调整）等于`target`。 负目标通过对称性处理：解决方案与正值相同。 

## 方法

 暴力方法将尝试所有可能的左右移动序列，以增加移动计数，直到达到目标。 对于每个移动计数，它将生成所有`2^n`方向的组合，计算结果位置，并检查它是否与目标匹配。 虽然这种方法是正确的，但它完全不切实际，因为组合的数量呈指数级增长，特别是考虑到目标可能大至 10^9。 

最佳方法利用数学洞察力。 让`t`的绝对值`target`。 我们想要最小的`n`使得总和`1 + 2 + ... + n`至少是`t`和区别`(sum - t)`是均匀的。 这是因为翻转某些移动的方向会均匀地改变总和。 因此，我们迭代寻找第一个`n`其中累计和 ≥`t`和`(sum - t) % 2 == 0`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 生成所有移动和方向序列 |
 | 最佳 | O(√目标) | O(1) | O(1) | 使用自然数之和和奇偶校验来查找最小移动 |

 ## 算法演练

 1. 取绝对值`target`为了简化问题，因为向左或向右移动是对称的。 
2. 初始化`sum`到 0 和`n`到 0。这些变量跟踪移动的累积总和以及当前的移动数量。 
3.同时`sum`小于`target`或者`(sum - target)`为奇数，增量`n`并将其添加到`sum`。 这确保了我们有足够的动作来达到`target`如果需要的话，翻转动作可以准确地击中目标。 
4. 一旦循环退出，`n`是所需的最小移动次数。 
5. 返回`n`。 

为什么有效：第一个的总和`n`移动量随着`n`。 一旦总和超过`target`并且差异是偶数，翻转某些移动的方向会将总和调整为完全相等`target`。 这样就保证了正确性。 

## Python 解决方案```python
class Solution:
    def reachNumber(self, target: int) -> int:
        target = abs(target)
        n = 0
        total = 0
        while total < target or (total - target) % 2 != 0:
            n += 1
            total += n
        return n
```实现首先转换`target`以其绝对值来处理对称性。 然后，它迭代地对连续整数求和，同时检查总和是否达到或超过目标以及差值是否为偶数。 一旦满足这些条件，当前的移动计数`n`作为答案返回。 

## 解决方案```go
func reachNumber(target int) int {
    if target < 0 {
        target = -target
    }
    n := 0
    total := 0
    for total < target || (total-target)%2 != 0 {
        n++
        total += n
    }
    return n
}
```Go 实现镜像了 Python 版本，使用标准整数运算。 负目标转换为正目标，循环在检查奇偶校验条件时累加总和。

 ## 边缘情况

 **负目标：** 如果`target`为负数，算法取其绝对值。 这是正确的，因为左右移动是对称的。 

**奇偶调整的最小移动：** 有时累计总和超过目标，但差值是奇数。 这需要额外的移动，直到`(sum - target)`变得均匀以允许翻转移动。 这对于避免差一错误至关重要。 

**非常大的目标：** 目标最大可达 10^9。 该算法可以有效地处理这个问题，因为总和呈二次方增长，大约需要 √10^9 ≈ 31622 次迭代，这在实时情况下是可行的。 内存使用量保持不变。
