 **难度：** 🔴难
 **主题：** 数学

 ## 解决方案

 ## 问题理解

 问题问是否可以变换一个起点`(sx, sy)`到目标点`(tx, ty)`使用一组定义的操作。 具体来说，从一点来说`(x, y)`，您可以移动到`(x, x + y)`或者`(x + y, y)`。 输入`sx`,`sy`,`tx`， 和`ty`都是范围内的整数`[1, 10^9]`，这意味着解决方案必须有效地处理非常大的数字。 预期输出是一个布尔值：`true`如果可以达到`(tx, ty)`从`(sx, sy)`， 或者`false`否则。 

这些约束表明，由于可能的点呈指数增长，对所有可能的移动进行强力探索将是不可行的。 重要的边缘情况包括起点已经等于目标点的情况，或者一个坐标提前超过目标，导致目标无法到达的情况。 该问题保证正整数，因此零或负值不是问题。 

关键的挑战是推理增长`(x, y)`高效，无需枚举所有操作序列。 

## 方法

 蛮力方法将探索所有可能的移动序列`(sx, sy)`看看是否`(tx, ty)`是可达的。 这可以通过递归或 BFS 来实现，在每一步检查两种可能的移动。 虽然理论上是正确的，但这种方法在计算上是不可行的，因为点的数量呈指数增长，并且约束允许`tx`和`ty`达到`10^9`。 

最佳方法利用了一个关键观察结果：操作是可逆的。 具体来说，如果您考虑逆运算`(tx, ty)`，您可以通过减去另一个坐标来减少任一坐标，直到您可能达到`(sx, sy)`。 这可以使用模运算进一步优化。 如果`tx > ty`，唯一可能的前一步是`(tx - k*ty, ty)`对于某个整数`k`，同样如果`ty > tx`，上一步是`(tx, ty - k*tx)`。 我们继续这种减少，直到坐标小于起始坐标，此时我们可以确定目标是否可达。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(2^(tx+ty)) | O(2^(tx+ty)) | O(tx+ty) | 探索所有可能的序列，但对于大输入来说是不可行的 |
 | 最佳| O(log(max(tx, ty))) | O(log(max(tx, ty))) | O(1) | O(1) | 使用模数减少目标坐标，非常高效 |

 ## 算法演练

 1.从目标坐标开始`(tx, ty)`并将它们与`(sx, sy)`。 
2. 虽然`tx >= sx`和`ty >= sy`，执行以下操作：

 - 如果`tx == sx`和`ty == sy`， 返回`true`因为我们已经到达了起点。 
- 如果`tx > ty`， 减少`tx`使用`tx %= ty`。 这模拟了反向撤消加法操作。 
- 如果`ty > tx`， 减少`ty`使用`ty %= tx`。 
3. 循环结束后，检查一个坐标是否与起点匹配，并且另一个坐标是否可以通过重复添加到达：

 - 如果`tx == sx`，检查是否`(ty - sy) % sx == 0`。 
- 如果`ty == sy`，检查是否`(tx - sx) % sy == 0`。 
4. 如果这些条件都不满足，则返回`false`。 

**为什么有效：** 该算法之所以有效，是因为向前的每次移动都是相加的。 通过反向使用模运算，我们模拟一次撤消多个向前移动。 不变量是如果`(sx, sy)`可以达到`(tx, ty)`，然后通过取模的逆运算，我们最终会减少`(tx, ty)`到`(sx, sy)`。 

## Python 解决方案```python
class Solution:
    def reachingPoints(self, sx: int, sy: int, tx: int, ty: int) -> bool:
        while tx >= sx and ty >= sy:
            if tx == sx and ty == sy:
                return True
            if tx > ty:
                if ty > sy:
                    tx %= ty
                else:
                    return (tx - sx) % ty == 0
            else:
                if tx > sx:
                    ty %= tx
                else:
                    return (ty - sy) % tx == 0
        return False
```这个 Python 实现首先检查我们是否已经到达起点。 如果不是，它会减少较大的`tx`或者`ty`使用模来模拟反转向前移动。 当一个坐标与起点匹配但另一个坐标可能需要多次减法才能达到精确的起点时，会进行特殊处理。 

## 解决方案```go
func reachingPoints(sx int, sy int, tx int, ty int) bool {
    for tx >= sx && ty >= sy {
        if tx == sx && ty == sy {
            return true
        }
        if tx > ty {
            if ty > sy {
                tx %= ty
            } else {
                return (tx - sx) % ty == 0
            }
        } else {
            if tx > sx {
                ty %= tx
            } else {
                return (ty - sy) % tx == 0
            }
        }
    }
    return false
}
```Go 实现反映了 Python 逻辑。 整数除法和模运算的行为类似，因此逻辑是可以直接翻译的。 边缘情况的处理方式相同。 

## 工作示例

 **示例1：**`sx = 1, sy = 1, tx = 3, ty = 5`单步执行循环：

 | TX | 泰 | 行动|
 | ---| ---| ---|
 | 3 | 5 | ty > tx, tx == sx? 否，减少 ty %= tx → ty = 5 % 3 = 2 |
 | 3 | 2 | tx > ty, ty > sy? 是的，tx %= ty → tx = 3 % 2 = 1 |
 | 1 | 2 | ty > tx, tx == sx? 是的，检查 (ty - sy) % sx = (2-1)%1=0 → 返回 True |

 **示例2：**`sx = 1, sy = 1, tx = 2, ty = 2`| TX | 泰 | 行动|
 | ---| ---| ---|
 | 2 | 2 | tx == ty，对于模 → 减少 ty %= tx → ty = 0 | 都不匹配 sx 或 sy
 | 2 | 0 | tx >= sx && ty >= sy? 否 → 返回 False |

 **示例3：**`sx = 1, sy = 1, tx = 1, ty = 1`已经`tx == sx`和`ty == sy`→ 返回 True。

 ## 边缘情况

 一种边缘情况是起点等于目标。 该算法通过直接相等检查立即处理这个问题，返回`true`。 

另一种边缘情况是一个坐标固定，而另一个坐标明显更大，可能需要多次重复操作。 这是使用模运算来有效地模拟重复减法来处理的，避免了逐步迭代的需要。 

第三种边缘情况是当目标无法到达时，因为它不能表示为从头开始的添加的组合。 该算法通过用模减少坐标来正确识别这一点，并且如果循环在不满足起点或整除条件的情况下退出，它将返回`false`。 这可以防止大量误报。
