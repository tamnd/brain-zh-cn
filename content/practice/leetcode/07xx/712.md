[LeetCode 第 712 题](https://leetcode.com/problems/minimum-ascii-delete-sum-for-two-strings/)

 **难度：** 🟡 中等
 **主题：** 字符串、动态规划

 ## 解决方案

 ## 问题理解

 这个问题给了我们两个字符串，`s1`和`s2`，并要求我们通过从任一字符串中删除字符来使它们相等。 每个删除的字符都会将其 ASCII 值贡献给总成本。 我们的目标是最小化总删除成本。 

例如，如果我们删除字符`'s'`，我们添加`115`到总数，因为 ASCII 值`'s'`是`115`。 如果我们删除`'t'`，我们添加`116`。 

重要的细节是我们只允许删除字符。 我们无法插入、替换或重新排列字符。 执行删除后，两个字符串中剩余的字符必须形成完全相同的序列。 

这本质上是两个字符串的优化问题。 我们需要确定应保留哪些字符以及应删除哪些字符，以便生成的字符串匹配，同时最小化删除的 ASCII 值的总和。 

输入约束很重要：

 -`1 <= s1.length, s2.length <= 1000`- 字符串仅包含小写英文字母

 由于每个字符串的长度可达 1000，因此任何指数解都是不可行的。 二次动态规划解决方案是可以接受的，因为`1000 * 1000 = 1,000,000`，这是可以管理的。 

一些边缘情况很重要：

 - 两个字符串可能已经相等，这意味着答案是`0`。 
- 字符串可能根本不共享公共字符，这迫使我们删除两个字符串中的每个字符。 
- 一根绳子可能比另一根绳子长得多。 
- 可能存在多个有效的公共子序列，我们必须选择一个能够最小化删除成本的子序列，而不是简单地最大化长度。 

该问题与最长公共子序列问题密切相关，但我们不是最大化字符数，而是最小化使用 ASCII 值测量的删除成本。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试一切可能的方法从两个字符串中删除字符，并检查结果字符串是否相等。 

思考这个问题的一种方法是：

 - 生成每个子序列`s1`- 生成每个子序列`s2`- 比较所有子序列对
 - 对于每个匹配对，计算删除成本
 - 返回最低成本

 这是可行的，因为每个可能的最终相等字符串都会被考虑。 

然而，每个字符串的长度`n`有`2^n`子序列。 当长度达到 1000 时，这变得完全不可能。 即使对于长度为 20 的字符串，蛮力也已经是巨大的了。 

蛮力方法是正确的，因为它详尽地探索了每个有效的删除组合，但其指数时间复杂度使其无法使用。 

### 关键见解

 关键的观察是在每个位置`(i, j)`在这两个字符串中，我们只需要回答一个问题：

 制作后缀所需的最小删除成本是多少`s1[i:]`和`s2[j:]`平等的？ 

这自然会导致动态规划。 

对于两个字符：

 - 如果`s1[i] == s2[j]`，我们应该保留这两个字符，因为删除匹配的字符只会增加不必要的成本。 
- 否则，我们有两个选择：

 - 删除`s1[i]`- 删除`s2[j]`我们递归地选择更便宜的选项。 

这种重叠的子问题结构正是动态规划的设计目的。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^(m+n)) | O(2^(m+n)) | O(2^(m+n)) | O(2^(m+n)) | 尝试每个子序列组合 |
 | 最优动态规划| O(m * n) | O(m * n) | 存储后缀对的最小删除成本 |

 ## 算法演练

 ### 动态规划定义

 我们定义：`dp[i][j]`作为所需的最小 ASCII 删除总和：
 -`s1[i:]`-`s2[j:]`平等的。 

我们想要的答案是：`dp[0][0]`### 逐步算法

 1.创建一个大小的DP表`(m + 1) x (n + 1)`。 

这里：

-`m = len(s1)`-`n = len(s2)`额外的行和列可以干净地处理空后缀。 
2. 初始化最后一列。 

如果`s2`已耗尽，则所有剩余字符`s1`必须删除。 

所以：`dp[i][n] = ASCII sum of s1[i:]`3. 初始化最后一行。 

如果`s1`已耗尽，则所有剩余字符`s2`必须删除。 

所以：`dp[m][j] = ASCII sum of s2[j:]`4. 从右下角到左上角填充表格。 

我们向后处理，因为每个状态都取决于未来的状态。 
5. 对于每个位置`(i, j)`:

 如果字符匹配：

 -`s1[i] == s2[j]`那么这些字符就不需要删除。 

我们将答案重复用于下一个后缀：`dp[i][j] = dp[i+1][j+1]`6. 否则，我们考虑两种选择：

 - 删除`s1[i]`- 删除`s2[j]`费用为：

 -`ord(s1[i]) + dp[i+1][j]`-`ord(s2[j]) + dp[i][j+1]`我们选择最小值。 
7. 返回`dp[0][0]`。 

### 为什么它有效

 DP状态始终代表剩余后缀的最优最小删除成本。 每次不匹配时，算法都会探索仅有的两个有效操作，即从第一个字符串中删除或从第二个字符串中删除。 由于每个状态都使用已经计算出的最优子问题答案，因此通过动态规划最优子结构，最终结果是全局最优的。 

## Python 解决方案```python
class Solution:
    def minimumDeleteSum(self, s1: str, s2: str) -> int:
        m = len(s1)
        n = len(s2)

        dp = [[0] * (n + 1) for _ in range(m + 1)]

        # Fill last column
        for i in range(m - 1, -1, -1):
            dp[i][n] = dp[i + 1][n] + ord(s1[i])

        # Fill last row
        for j in range(n - 1, -1, -1):
            dp[m][j] = dp[m][j + 1] + ord(s2[j])

        # Fill DP table
        for i in range(m - 1, -1, -1):
            for j in range(n - 1, -1, -1):
                if s1[i] == s2[j]:
                    dp[i][j] = dp[i + 1][j + 1]
                else:
                    delete_s1 = ord(s1[i]) + dp[i + 1][j]
                    delete_s2 = ord(s2[j]) + dp[i][j + 1]

                    dp[i][j] = min(delete_s1, delete_s2)

        return dp[0][0]
```实现首先确定两个字符串的长度并分配 DP 表。 

最后一列初始化处理以下情况`s2`已经空了。 在这种情况下，每个剩余的字符`s1`必须删除，所以我们向后累加 ASCII 值。 

最后一行初始化执行对称操作`s2`。 

然后，嵌套循环以相反的顺序处理状态，以便在评估当前状态之前已经计算出所有所需的未来状态。 

当字符匹配时，我们保留它们，因为删除匹配的字符永远无法改善答案。 当字符不同时，我们计算从任一字符串中删除的成本并选择较小的值。 

最后，`dp[0][0]`包含完整字符串的最小删除总和。 

## 解决方案```go
func minimumDeleteSum(s1 string, s2 string) int {
    m := len(s1)
    n := len(s2)

    dp := make([][]int, m+1)

    for i := range dp {
        dp[i] = make([]int, n+1)
    }

    // Fill last column
    for i := m - 1; i >= 0; i-- {
        dp[i][n] = dp[i+1][n] + int(s1[i])
    }

    // Fill last row
    for j := n - 1; j >= 0; j-- {
        dp[m][j] = dp[m][j+1] + int(s2[j])
    }

    // Fill DP table
    for i := m - 1; i >= 0; i-- {
        for j := n - 1; j >= 0; j-- {
            if s1[i] == s2[j] {
                dp[i][j] = dp[i+1][j+1]
            } else {
                deleteS1 := int(s1[i]) + dp[i+1][j]
                deleteS2 := int(s2[j]) + dp[i][j+1]

                if deleteS1 < deleteS2 {
                    dp[i][j] = deleteS1
                } else {
                    dp[i][j] = deleteS2
                }
            }
        }
    }

    return dp[0][0]
}
```Go 实现遵循与 Python 解决方案完全相同的 DP 逻辑。 

一个重要的特定于语言的细节是 Go 字符串是 ASCII 字符的字节切片，因此`s1[i]`直接给出字节值。 将其转换为`int()`给出 ASCII 值。 

DP 表是使用嵌套切片创建的，因为 Go 不直接支持动态大小的多维数组。 

由于 ASCII 值和字符串长度都很小，因此不必担心整数溢出。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(m * n) | 每个 DP 状态都计算一次 |
 | 空间| O(m * n) | DP表存储所有后缀状态|

 该算法处理每对索引`(i, j)`正好一次。 由于有`m * n`在这种状态下，运行时间是二次的。 

空间复杂度也是二次的，因为我们存储了完整的 DP 表。 这可以优化为`O(n)`使用滚动数组，但完整表版本更易于理解和调试。

 ## 边缘情况

 当两个字符串已经相同时，就会出现一种重要的边缘情况。 在这种情况下，正确答案是`0`因为不需要删除。 如果错误的实现没有正确处理匹配的字符，它仍然可能会尝试不必要的删除。 DP 过渡`dp[i][j] = dp[i+1][j+1]`确保以零额外成本保留匹配的字符。 

当字符串根本不共享公共字符时，会发生另一种重要情况。 例如，`"abc"`和`"def"`没有重叠，因此必须删除两个字符串中的每个字符。 一些不正确的实现意外地假设至少存在一个公共子序列。 此实现正确地处理了这种情况，因为每个不匹配都会评估两个删除选择，直到删除所有字符。 

重复的字符是另一个微妙的边缘情况。 例如，`"aaaa"`和`"aa"`要求正好删除两个`'a'`人物。 贪婪的方法在这里可能会失败，因为选择错误的匹配位置可能会在以后产生不必要的删除。 动态规划通过系统地评估所有后缀组合并始终选择全局最优成本来避免此问题。 

最后的边缘情况涉及长度非常不同的字符串。 例如，`"a"`和`"abcdefghijklmnopqrstuvwxyz"`需要删除几乎整个较长的字符串。 当一个字符串耗尽时，基行和基列初始化通过累积剩余的 ASCII 值来正确处理这些情况。
