[LeetCode 第 719 题](https://leetcode.com/problems/find-k-th-smallest-pair-distance/)

 **难度：** 🔴难
 **主题：** 数组、两个指针、二分查找、排序

 ## 解决方案

 ## 问题理解

 这个问题要求我们找到`k`- 数组中每个可能的数字对之间的最小距离。 

对于任意一对`(a, b)`，距离定义为：$|a-b|$我们得到一个数组`nums`，我们必须考虑每一对`(nums[i], nums[j])`在哪里`i < j`。 对于每一对，我们计算两个值之间的绝对差。 收集所有对距离后，我们按升序对它们进行排序并返回`k`- 第最小的一个。 

例如，如果：```
nums = [1,3,1]
```这些对是：```
(1,3) -> 2
(1,1) -> 0
(3,1) -> 2
```排序后的距离变为：```
[0,2,2]
```所以第一个最小距离是`0`。 

约束条件很重要：

 -`2 <= n <= 10^4`-`0 <= nums[i] <= 10^6`对的总数可以是：$\frac{n(n-1)}{2}$什么时候`n = 10^4`，这大约是 5000 万对，对于在有效的解决方案中直接生成和排序来说太多了。 

这立即告诉我们，简单的暴力方法可能会超出时间或内存限制。 我们需要一种更有效的策略来避免显式构建所有对距离。 

一些边缘情况尤其重要：

 - 具有许多重复值的数组，因为距离`0`可能会出现很多次。 
- 所有数字都相同的数组。 
- 所有数字相距较远的数组。 
- 大型数组不可能生成所有对。 
- 答案是的情况`0`。 
- 答案是最大可能差异的情况。 

该问题保证有效的输入大小并保证`k`总是在可能对的总数之内。 

## 方法

 ### 蛮力方法

 最直接的解决方案是生成每一对`(i, j)`在哪里`i < j`，计算绝对差，将所有距离存储在数组中，对数组进行排序，然后返回`k - 1`索引元素。 

这是有效的，因为它实际上构建了对距离的完整列表，因此排序后我们可以直接访问所需的顺序统计量。 

然而，对的数量是：$\frac{n(n-1)}{2}$为了`n = 10^4`，这变成大约 5000 万个距离。 存储和排序如此多的值是非常昂贵的。 

因此，对于给定的约束，暴力解决方案变得不切实际。 

### 最佳方法

 关键的观察是我们实际上不需要生成所有对距离。 

相反，我们可以二分搜索答案本身。 

可能的最小距离是：```
0
```最大可能距离为：```
max(nums) - min(nums)
```假设我们猜测一些距离`mid`。 

然后我们可以问：```
How many pairs have distance <= mid?
```如果至少有`k`这样的对，那么答案一定是`<= mid`。 

否则，答案必须大于`mid`。 

这创建了一个单调属性：

 - 小距离阈值产生较少的有效对。 
- 较大的距离阈值会产生更多的有效对。 

由于这种单调行为，二分查找成为可能。 

剩下的挑战是有效地计算有多少对有距离`<= mid`。 

对数组进行排序后，我们可以使用滑动窗口/两指针技术：

 - 展开右侧指针。 
- 当距离变得太大时，移动左指针。 
- 对于每个右指针，计算存在多少个有效的左位置。 

这让我们可以在每个二分搜索步骤的线性时间内对对进行计数。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n² log n²) | O(n² log n²) | O(n²) | 生成并排序所有对距离 |
 | 最佳 | O(n log n + n log W) | O(n log n + n log W) | O(1) 额外 | 用两个指针对答案进行二分搜索 |

 这里，`W`是值的范围：```
max(nums) - min(nums)
```## 算法演练

 1. 对数组进行排序。 

排序至关重要，因为两指针计数技术依赖于有序值。 一旦排序，对距离就变得更容易推理，因为增加索引也会增加值。 
2. 定义二分查找范围。 

可能的最小距离是`0`。 

最大可能距离为：$\max(nums)-\min(nums)$我们在这个范围内进行二分查找。 
3.选择中距离`mid`。 

这代表一个候选答案。 
4. 计算有多少对有距离`<= mid`。 

使用两个指针：

 - 保持左指针`left`。 
- 迭代`right`从左到右。 
- 尽管：```
nums[right] - nums[left] > mid
```移动`left`向前。 

调整后各指标`left`和`right - 1`与形成有效对`right`。 

新的有效对的数量为：```
right - left
```5. 将计数与`k`。 

- 如果计数至少为`k`， 然后`mid`可能是答案，或者答案可能更小。 
- 否则，答案一定更大。 
6. 继续二分查找，直到搜索范围崩溃。 
7. 返回最终值。 

### 为什么它有效

 正确性取决于单调性。 

定义：```
f(d) = number of pairs with distance <= d
```作为`d`增加，`f(d)`永远不会减少。 

因此，存在一个边界，其中有效对的数量首先变为至少`k`。 该边界正是`k`-第最小对距离。 

二分查找正确地找到了这个边界。 

滑动窗口计数方法是正确的，因为排序后，如果：```
nums[right] - nums[left] <= mid
```然后之间的每个索引`left`和`right`也满足条件。 

## Python 解决方案```python
from typing import List

class Solution:
    def smallestDistancePair(self, nums: List[int], k: int) -> int:
        nums.sort()

        def count_pairs(max_distance: int) -> int:
            count = 0
            left = 0

            for right in range(len(nums)):
                while nums[right] - nums[left] > max_distance:
                    left += 1

                count += right - left

            return count

        low = 0
        high = nums[-1] - nums[0]

        while low < high:
            mid = (low + high) // 2

            if count_pairs(mid) >= k:
                high = mid
            else:
                low = mid + 1

        return low
```实现首先对数组进行排序。 这使得对距离随着索引的增加而表现得单调。 

嵌套的`count_pairs`函数计算有多少对的距离小于或等于给定阈值。 它使用带有两个指针的滑动窗口。 

这`right`指针在数组中扩展。 当距离变得过大时，`left`指针向前移动，直到窗口再次有效。 

对于每个`right`，每个索引来自`left`通过`right - 1`形成一个有效的对。 因此，我们添加`right - left`到计数。 

外部二分搜索重复测试候选距离。 如果存在足够的有效对，我们搜索更小的距离。 否则，我们会搜索更大的距离。 

最终，`low`收敛到计数至少为的最小距离`k`，这就是答案。 

## 解决方案```go
package main

import (
	"sort"
)

func smallestDistancePair(nums []int, k int) int {
	sort.Ints(nums)

	countPairs := func(maxDistance int) int {
		count := 0
		left := 0

		for right := 0; right < len(nums); right++ {
			for nums[right]-nums[left] > maxDistance {
				left++
			}

			count += right - left
		}

		return count
	}

	low := 0
	high := nums[len(nums)-1] - nums[0]

	for low < high {
		mid := (low + high) / 2

		if countPairs(mid) >= k {
			high = mid
		} else {
			low = mid + 1
		}
	}

	return low
}
```Go 实现遵循与 Python 版本相同的算法结构。 

Go 使用`sort.Ints(nums)`用于排序。 计数逻辑是通过匿名函数闭包实现的。 

这里不关心整数溢出，因为最大距离最多为`10^6`，完全在 Go 的整数范围内。 

直接使用切片，不需要额外分配大内存。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |

 排序步骤成本`O(n log n)`。 

二分查找在距离范围内进行`W`， 在哪里：$W=\max(nums)-\min(nums)$每次二分搜索迭代使用两个指针执行线性扫描，给出`O(n)`每次迭代的工作量。 

由于二分查找执行`O(log W)`迭代，总复杂度变为：$O(n\log n+n\log W)$该算法在排序实现之外使用恒定的额外内存。

 ## 边缘情况

 当许多元素相同时，就会出现一种重要的边缘情况。 在这种情况下，许多对距离变为`0`。 有缺陷的实现可能会错误地计算重复对或错误地处理滑动窗口边界。 该解决方案可以自然地处理重复项，因为排序后的相等值保持相邻，并且两指针计数逻辑正确地包含每个有效对。 

另一个重要的情况是数组只有两个元素。 恰好有一对可能的数字，因此答案必须是这两个数字之间的绝对差。 该实现可以正确处理此问题，因为二分搜索范围立即折叠到唯一有效的距离。 

第三个关键边缘情况涉及极大的值范围，例如`[0, 1000000]`。 即使数值范围很大，二分查找也仅在该范围内执行对数迭代。 因此，该算法保持高效并避免构建巨大的中间结构。 

第四种微妙的情况发生在`k`-第一个最小距离出现多次。 例如：```
[1,1,1,2]
```包含多个相同的距离。 二分查找正确找到累计对数至少达到的最小距离`k`。 这可确保正确处理重复项并返回准确的订单统计信息。
