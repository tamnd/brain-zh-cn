 # LeetCode 714，买卖股票并收取交易费的最佳时机

 ## 问题理解

 这个问题要求我们在连续几天的股票交易中最大化利润，其中每笔交易都会产生固定费用。 输入数组`prices`代表每天的股票价格，以及`fee`代表每笔完成的买卖交易收取的交易费用。 

我们可以完成任意数量的交易，但有一个重要的限制：我们一次不能持有超过一只股票。 这意味着在再次购买之前，我们必须首先出售我们目前拥有的股票。 

目标是计算处理所有天后的最大可能利润。 

例如，如果价格是`[1,3,2,8,4,9]`费用是`2`，一种有利可图的策略是：

 - 购买于`1`- 出售于`8`，利润=`8 - 1 - 2 = 5`- 购买于`4`- 出售于`9`，利润=`9 - 4 - 2 = 3`总利润变为`8`。 

约束条件很重要：

 -`prices.length`可以大到`5 * 10^4`- 价格和费用也可能很高
 - 二次或指数解无法及时完成

 这些限制强烈表明我们需要一种接近线性时间的算法。 

一些边缘情况很重要：

 - 单日意味着无法进行交易
 - 价格持续下降应该会产生利润`0`- 巨额交易费用可能导致交易无利可图
 - 由于费用原因，频繁的小额收益可能不值得
 - 价格波动很大，因此必须谨慎处理贪婪的当地决定

 该问题保证有效的非空输入和非负费用。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试所有可能的买卖操作序列。 

每天，我们都可以做出几个选择：

 - 购买股票
 - 出售股票
 - 跳过这一天

 这将创建一个决策树，其中每个状态都取决于：

 - 当前日期
 - 我们目前是否持有股票
 - 当前累计利润

 递归地探索所有可能性可以保证正确性，因为每个有效的交易序列都会被检查。 

然而，可能的状态数量呈指数增长。 每天都存在多个分支决策，导致大致`O(2^n)`最坏情况下的可能性。 

和`n`最多`50,000`，这种做法是完全不可行的。 

### 最优动态规划方法

 关键的观察是，在任何一天，我们只关心两种情况：

 1.当前不持有股票的最大利润
 2. 目前持有股票的最大利润

 我们不需要记住完整的交易历史记录。 对于这两个州来说，只有可实现的最佳利润才重要。 

这自然会导致动态规划。 

我们定义：

 -`cash`= 不持有股票时的最大利润
 -`hold`= 持有股票时的最大利润

 对于每个价格：

 - 我们可以保持目前的状态
 - 或通过购买或出售在状态之间转换

 这将问题压缩为恒定空间和线性时间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 探索每一种可能的交易顺序 |
 | 最优动态规划| O(n) | O(1) | O(1) | 仅跟踪持有和非持有状态 |

 ## 算法演练

 1. 初始化代表两种可能状态的两个变量。`cash`代表我们当前不持有股票时的最大利润。`hold`代表我们持有股票时的最大利润。 

最初：

-`cash = 0`，因为我们一开始没有利润，也没有库存
 -`hold = -prices[0]`，因为购买第一只股票需要花钱
 2. 从第二天开始迭代价格数组。 

对于每个价格，我们都会考虑这两种状态如何变化。 
3. 更新`cash`状态。 

如果我们今天没有库存，有两种可能性：

 - 昨天我们已经没有库存了，所以利润仍然存在`cash`- 我们今天出售，所以利润变成`hold + price - fee`所以：```
new_cash = max(cash, hold + price - fee)
```4. 更新`hold`状态。 

如果我们今天结束持有一只股票，有两种可能性：

 - 我们昨天已经持有股票了
 - 我们今天使用之前购买的`cash`所以：```
new_hold = max(hold, cash - price)
```5. 存储更新的值。 

我们必须使用临时变量，因为两次更新都取决于前一天的值。 
6. 继续，直到处理完所有日期。 
7. 返回`cash`。 

最后，最好的利润一定是在非持有状态，因为未售出的股票不算作已实现的利润。 

### 为什么它有效

 该算法在整个执行过程中保持正确的不变量：

 -`cash`在不持有库存的情况下，始终存储当天处理后可实现的最大利润
 -`hold`在持有一只股票的情况下，始终存储当天处理后可实现的最大利润

 每个有效的动作序列最终都会映射到这两种状态之一。 由于每次转换都考虑了所有合法的可能性并保持最好的结果，所以最终的`cash`价值必须是可实现的最优利润。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxProfit(self, prices: List[int], fee: int) -> int:
        cash = 0
        hold = -prices[0]

        for price in prices[1:]:
            new_cash = max(cash, hold + price - fee)
            new_hold = max(hold, cash - price)

            cash = new_cash
            hold = new_hold

        return cash
```该实现直接遵循动态编程状态转换。 

变量`cash`追踪不持有股票时可实现的最佳利润。 最初，它是`0`因为没有发生任何交易。 

变量`hold`跟踪持有股票时可实现的最佳利润。 购买第一只股票的利润为`-prices[0]`。 

对于每个后续价格：

 -`new_cash`评估今天卖出是否比继续没有股票更好
 -`new_hold`评估今天买入是否优于继续持有

 使用临时变量是因为两个转换都依赖于之前的值`cash`和`hold`。 

最后该方法返回`cash`，代表最大实现利润。 

## 解决方案```go
func maxProfit(prices []int, fee int) int {
    cash := 0
    hold := -prices[0]

    for i := 1; i < len(prices); i++ {
        price := prices[i]

        newCash := cash
        if hold+price-fee > newCash {
            newCash = hold + price - fee
        }

        newHold := hold
        if cash-price > newHold {
            newHold = cash - price
        }

        cash = newCash
        hold = newHold
    }

    return cash
}
```Go 实现密切反映了 Python 逻辑。 

Go 没有提供内置的`max`函数用于整数，因此使用显式比较。 

切片自然用于`prices`输入。 由于该问题保证至少有一个元素，因此访问`prices[0]`总是安全的。 

整数溢出不是问题，因为最大可能的利润仍然在 Go 的标准整数范围内。

 ## 边缘情况

 一种重要的边缘情况是数组仅包含一个价格。 由于交易需要买入和卖出，因此无法赚取利润。 幼稚的实现可能会错误地尝试事务或访问无效索引。 该解决方案可以自然地处理这种情况，因为循环结束了`prices[1:]`从不执行，并且该方法正确返回`0`。 

另一个关键的边缘情况是严格递减的价格序列，例如`[9,8,7,6,5]`。 尝试频繁交易的贪婪策略可能会意外地产生负利润。 动态编程转换可以防止这种情况发生，因为`cash`永远不会减少。 只有当可以提高利润时才会选择出售。 

第三个重要的情况发生在交易费用非常大的时候。 即使价格上涨，费用也可能消除所有收益。 例如，与价格`[1,3,2,5,4,7]`和费用`10`，每一次可能的交易都会产生非正利润。 该算法正确地避免了所有交易，因为卖出转换永远不会变得有利。 

另一个微妙的边缘情况涉及价格波动，持有更长时间比进行多次小额交易更有利可图。 该算法自然会处理这个问题，因为`hold`和`cash`始终保持全局最优状态，而不仅仅是局部最优决策。
