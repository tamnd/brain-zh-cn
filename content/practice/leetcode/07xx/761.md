[LeetCode 761 题](https://leetcode.com/problems/special-binary-string/)

 **难度：** 🔴难
 **主题：** 字符串、分而治之、排序

 ## 解决方案

 ## 问题理解

 该问题要求我们操作一个特殊的二进制字符串来生成按字典顺序排列的最大可能字符串。 **特殊的二进制字符串**有两个属性：它包含相同数量的`1`沙`0`s，以及字符串中每个点的数量`1`s 至少与`0`s。 这类似于格式良好的括号，其中`1`代表左括号并且`0`右括号。 

输入是一个字符串`s`保证是一个最大长度为 50 个字符的特殊二进制字符串。 输出应该是通过重复交换连续的特殊子字符串可以形成的最大字符串。 

约束告诉我们输入相对较小，因此递归或分而治之的解决方案是可行的。 该问题保证该字符串已经是特殊的，因此我们不需要验证它。 

关键边缘情况包括长度为 2 的字符串（可能的最小特殊字符串）和已经是最大词典形式的字符串，它们应该保持不变。 

## 方法

 暴力方法将生成连续特殊子字符串的所有可能序列并尝试每次交换。 这最终会产生最大的字符串，但效率极低，因为有效交换的数量随着字符串长度的增加而增长。 即使长度为 50，显式探索所有排列也是不可行的。 

最佳方法依赖于**分而治之的递归**。 关键的见解是每个特殊的二进制字符串都可以分解为更小的特殊子字符串。 一旦确定了这些顶级特殊子字符串，您就可以按字典顺序降序对每个子字符串进行递归排序。 通过连接已排序的子字符串，您可以获得最大的可能字符串。 这是有效的，因为连续特殊子字符串的交换仅影响它们的顺序，而不影响内部结构。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n!) | 生成连续特殊子串的所有交换，速度极慢 |
 | 最佳 | O(n^2) | O(n^2) | O(n) | 通过识别和递归排序顶级特殊子串来分而治之 |

 ## 算法演练

 1. 初始化一个`count`跟踪余额的变量`1`沙`0`s 和一个空列表`special_substrings`存储顶级特殊子字符串。 
2. 逐个字符地迭代字符串。 增量`count`为了`1`并递减`0`。 
3. 什么时候`count`返回零，从最后一个起始索引到当前索引的子串是顶级特殊子串。 
4. 对于每个顶级子字符串，删除外部`1`和`0`，递归地将算法应用于内部子字符串，然后再次将其包裹起来`1`和`0`。 
5. 收集所有递归处理过的子串，并按字典顺序降序排序。 
6. 连接排序后的子字符串并返回结果。 

**为什么有效：** 每个顶级特殊子字符串在可能的交换方面都是独立的，因此按降序对它们进行排序可以保证字典顺序上最大的字符串。 递归确保嵌套的特殊子字符串也是最大排序的。 

## Python 解决方案```python
class Solution:
    def makeLargestSpecial(self, s: str) -> str:
        special_substrings = []
        count = 0
        start = 0
        for i, char in enumerate(s):
            count += 1 if char == '1' else -1
            if count == 0:
                inner = self.makeLargestSpecial(s[start + 1:i])
                special_substrings.append('1' + inner + '0')
                start = i + 1
        special_substrings.sort(reverse=True)
        return ''.join(special_substrings)
```Python 解决方案迭代`s`识别顶级特殊子字符串。 对于每个，它递归地处理内部子字符串，将其包装为`1`和`0`，然后以相反的顺序对所有此类子字符串进行排序，以最大化词典编排价值。 

## 解决方案```go
import "sort"

func makeLargestSpecial(s string) string {
    var specialSubstrings []string
    count, start := 0, 0
    for i, char := range s {
        if char == '1' {
            count++
        } else {
            count--
        }
        if count == 0 {
            inner := makeLargestSpecial(s[start+1 : i])
            specialSubstrings = append(specialSubstrings, "1"+inner+"0")
            start = i + 1
        }
    }
    sort.Slice(specialSubstrings, func(i, j int) bool {
        return specialSubstrings[i] > specialSubstrings[j]
    })
    result := ""
    for _, sub := range specialSubstrings {
        result += sub
    }
    return result
}
```Go 解决方案反映了 Python 逻辑，使用`sort.Slice`使用自定义比较器按降序排序。 Go 中的切片处理取代了 Python 中的字符串切片，但递归和包装逻辑保持不变。

 ## 边缘情况

 1. **最小字符串长度（2个字符）**：最小的有效特殊字符串是`"10"`。 任何算法都必须正确处理它而没有索引错误。 Python 和 Go 解决方案都将其返回不变。 
2. **已经最大的字符串**：像这样的字符串`"111000"`不需要任何交换。 当原始字符串已经是字典顺序上最大的字符串时，递归排序会保留原始字符串。 
3. **深度嵌套的特殊子字符串**：诸如`"1101101000"`具有需要递归处理的嵌套子字符串。 正确的递归可确保在对顶级子字符串进行排序之前对每个嵌套级别进行最大排序。 这可以处理多层特殊字符串带来的复杂性。
