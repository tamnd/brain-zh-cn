[LeetCode 第 771 题](https://leetcode.com/problems/jewels-and-stones/)

 **难度：** 🟢简单
 **主题：** 哈希表、字符串

 ## 解决方案

 ## 问题理解

 在这个问题中，我们给出两个字符串，`jewels`和`stones`。 

字符串`jewels`代表所有被视为珠宝的宝石类型。 每个角色都是独特的宝石类型。 例如，如果`jewels = "aA"`，然后都是小写`'a'`和大写`'A'`是宝石类型。 

字符串`stones`代表我们目前拥有的所有宝石。 该字符串中的每个字符都对应于一块石头。 我们的任务是数数里面有多少块石头`stones`也存在于`jewels`。 

比较区分大小写。 这一点非常重要。 人物`'a'`不同于`'A'`，因此必须将它们视为单独的石材类型。 

预期输出是一个整数，表示宝石的数量。 

例如：

-`jewels = "aA"`-`stones = "aAAbbbb"`这些石头是：

 -`'a'`-> 宝石
 -`'A'`-> 宝石
 -`'A'`-> 宝石
 -`'b'`-> 不是宝石
 -`'b'`-> 不是宝石
 -`'b'`-> 不是宝石
 -`'b'`-> 不是宝石

 所以答案是`3`。 

限制非常小：

 -`1 <= jewels.length, stones.length <= 50`- 仅使用英文字母
 - 中的所有角色`jewels`是独一无二的

 由于输入量很小，即使是暴力解决方案也能足够高效地工作。 然而，这个问题的目的是引入使用基于散列的查找结构来进行更快的成员资格检查的想法。 

一些重要的边缘情况包括：

 - 没有石头是珠宝
 - 每块石头都是宝石
 - 混合大小写字母
 - 单字符输入
 - 重复宝石`stones`该问题保证了`jewels`包含独特的字符，这简化了查找逻辑，因为我们永远不需要处理重复的宝石定义。 

## 方法

 ### 蛮力方法

 最直接的解决方案是将每颗宝石与每颗宝石进行比较。 

对于中的每个字符`stones`，我们迭代中的所有字符`jewels`并检查它们是否匹配。 如果找到匹配项，我们就会增加答案计数器。 

之所以有效，是因为每颗宝石都根据每种可能的宝石类型进行了明确检查，保证了正确性。 

然而，这种方法执行了不必要的重复比较。 如果有`n`石头和`m`宝石类型，比较总数变为`O(n * m)`。 

尽管约束足够小，可以轻松通过，但这并不是解决问题的最有效方法。 

### 最佳方法

 关键的观察是我们反复问同样的问题：

 > “这种石头是宝石吗？”

 这是一个经典的成员查找问题，这正是哈希集的设计目的。 

我们可以将所有宝石角色放入一个集合中。 然后，对于每块石头`stones`，我们只需检查它是否存在于集合中。 

哈希集提供平均情况`O(1)`查找时间，因此整个解决方案与输入大小呈线性关系。 

这提高了整体复杂性`O(n * m)`到`O(n + m)`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * m) | O(1) | O(1) | 将每颗宝石与每颗宝石进行比较 |
 | 最佳| O(n + m) | O(米) | 使用哈希集进行恒定时间成员资格查找 |

 这里：

-`n = len(stones)`-`m = len(jewels)`## 算法演练

 ### 最优算法

 1. 创建一个包含所有字符的哈希集`jewels`。 

This allows us to quickly determine whether a stone type is a jewel. Hash sets are ideal because membership checks are very fast on average.
 2. 初始化一个计数器变量为`0`。 

该变量将存储在以下位置找到的宝石数量`stones`。 
3. 遍历每个字符`stones`。 

每个字符代表我们拥有的一块石头。 
4. 对于每颗宝石，检查它是否存在于珠宝组中。 

如果套装中出现石头字符，则意味着该石头是宝石。 
5. 如果宝石是宝石，则增加计数器。 

我们单独计算每个出现的石头，因为重复的石头是不同的石头。 
6. 处理完所有宝石后，返回柜台。 

最终计数代表宝石的总数。 

### 为什么它有效

 该算法之所以有效，是因为该集合完全包含有效的宝石类型。 每颗宝石都会对照这组宝石检查一次。 如果该宝石存在于该集合中，则它有助于得出答案。 由于所有宝石均经过处理且每一次宝石会员资格检查都是准确的，因此最终计数器保证等于宝石总数。 

## Python 解决方案```python
class Solution:
    def numJewelsInStones(self, jewels: str, stones: str) -> int:
        jewel_set = set(jewels)

        jewel_count = 0

        for stone in stones:
            if stone in jewel_set:
                jewel_count += 1

        return jewel_count
```实现从转换开始`jewels`成一个集合。 在 Python 中，集合成员资格检查非常高效，使其成为重复查找的理想结构。 

变量`jewel_count`记录我们遇到了多少宝石。 

然后我们迭代中的每个字符`stones`。 对于每块石头，我们检查它是否存在于`jewel_set`。 如果是，我们就增加计数器。 

最后，在处理完所有石头后，该方法返回总计数。 

该实现直接遵循前面描述的算法并保持清晰的可读性。 

## 解决方案```go
func numJewelsInStones(jewels string, stones string) int {
    jewelSet := make(map[rune]bool)

    for _, jewel := range jewels {
        jewelSet[jewel] = true
    }

    count := 0

    for _, stone := range stones {
        if jewelSet[stone] {
            count++
        }
    }

    return count
}
```在 Go 中，没有内置的集合类型，因此我们使用`map[rune]bool`。 

每个宝石字符都会插入到地图中，并带有值`true`。 然后我们迭代`stones`并检查每块石头是否存在于地图中。 

Go 实现使用`rune`迭代而不是字节索引。 虽然这个问题只包含英文字母，但对于 Go 中的字符串来说，迭代符文通常更安全、更惯用。 

不用担心整数溢出，因为最大可能的答案只是`50`。

 ## 边缘情况

 一种重要的边缘情况是区分大小写。 许多不正确的解决方案无意中将大写字母和小写字母视为等效。 例如，`'a'`和`'A'`必须被视为不同的石材类型。 该实现可以正确处理这个问题，因为 Python 和 Go 中的字符比较本质上是区分大小写的。 

另一个重要的边缘情况是没有宝石是珠宝。 在这种情况下，计数器应保持不变`0`整个执行过程中。 由于该算法仅在集合中存在成员资格时才增加计数器，因此实现自然可以正确处理这种情况。 

当每块石头都是宝石时，就会出现第三种重要的边缘情况。 在这种情况下，计数器在每次迭代时都会增加`stones`。 该实现正确地独立计算所有出现的次数，包括重复项。 

第四种微妙的边缘情况涉及内部重复的宝石`stones`。 例如，如果`jewels = "a"`和`stones = "aaaaa"`，答案应该是`5`， 不是`1`。 该算法单独处理每块石头，并增加每次匹配出现的计数，确保正确计算重复项。
