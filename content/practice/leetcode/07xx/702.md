 **难度：** 🟡 中等
 **主题：** 数组、二分搜索、交互

 ## 解决方案

 ## 问题理解

 这个问题要求我们在排序数组中搜索目标值，但有一个重要的限制：我们不知道数组的大小，并且无法直接访问数组。 

我们不是通过普通的数组索引来与数组交互`ArrayReader`界面。 唯一可用的操作是：```
reader.get(index)
```此方法以两种方式之一运行：

 1.如果`index`有效，它返回该位置存储的实际值。 
2.如果`index`超出数组范围，则返回`2^31 - 1`，它充当指示无效索引的哨兵值。 

目标是返回索引，其中`target`出现在隐藏的排序数组中。 如果目标不存在，我们返回`-1`。 

关键的挑战是传统的二分搜索需要知道搜索边界，特别是左索引和右索引。 由于数组大小未知，我们无法使用以下方式初始化二分搜索：```
left = 0
right = len(array) - 1
```相反，我们必须首先确定有效的搜索范围。 

这些约束告诉我们一些重要的事情：

 - 数组严格按递增顺序排序，这意味着可以使用二分查找。 
- 元素是唯一的，因此无需担心重复值。 
- 所需的运行时间是`O(log n)`，这意味着线性扫描从概念上来说太慢了。 
- 哨兵值`2^31 - 1`保证大于任何有效的数组元素，因为有效值位于`[-10^4, 10^4]`。 这使得越界检测变得可靠。 

一些边缘情况很重要：

 - 目标可能小于第一个元素。 
- 目标可能大于所有元素。 
- 目标可能不存在于数组内。 
- 数组只能包含一个元素。 
- 在搜索过程中，我们可能会反复遇到越界索引，我们的逻辑必须安全地处理这些问题。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是从索引开始`0`并反复调用：```
reader.get(i)
```我们继续检查值，直到发生以下两种情况之一：

 - 我们找到目标了。 
- 我们相遇`2^31 - 1`，这意味着我们超出了数组边界。 

因为数组是排序的，所以如果当前值大于目标值，我们也可以提前停止。 

这种方法之所以有效，是因为我们最终要么找到目标，要么证明它不存在。 然而，它可能需要扫描每个元素。 

它的运行时间是`O(n)`，这违反了问题的要求`O(log n)`复杂。 

### 最佳方法的关键见解

 挑战不是二分搜索本身，而是找到有效的搜索区间。 

由于数组大小未知，我们可以使用**指数扩展**动态发现上限。 

我们从一个小的搜索窗口开始：```
[0, 1]
```如果目标大于索引处的值`1`，我们将右边界加倍：```
[0,1] → [2,4] → [4,8] → [8,16]
```最终，发生以下两件事之一：

 - 我们遇到大于或等于目标的值。 
- 我们达到了越界哨兵值（`2^31 - 1`）。 

此时，我们知道目标（如果存在）必定位于已发现的区间内。 

然后我们在该范围内执行标准的二分搜索。 

这很有效，因为加倍呈指数增长，这意味着我们找到了一个合适的边界`O(log n)`时间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(1) | O(1) | 依次扫描索引，直到找到目标或边界 |
 | 最佳| O(log n) | O(1) | O(1) | 使用指数边界扩展，然后进行二分搜索 |

 ## 算法演练

 ### 最优算法

 1. 初始化搜索边界。 

从以下开始：```
left = 0
right = 1
```由于我们不知道数组大小，这给了我们一个小的初始窗口。 
2. 指数级扩大搜索范围。 

而值在`right`小于目标：```
reader.get(right) < target
```范围大小加倍：```
left = right
right *= 2
```此步骤有效地找到目标可能存在的区域。 
3. 在发现的范围内执行二分查找。 

一旦扩张停止，目标必须位于`left`和`right`，如果存在的话。 

运行正常的二分搜索：

 - 计算中间索引。 
- 使用读取中间值`reader.get(mid)`。 
- 如果值等于目标，则返回索引。 
- 如果该值小于目标，则向左移动边界。 
- 否则，向右移动边界。 
4.自动处理越界。 

自从`reader.get(i)`回报`2^31 - 1`对于无效索引，二分查找自然会将越界值视为极大的数字。 

所以：```
if value > target:
    right = mid - 1
```安全地缩小搜索范围。 
5. 返回`-1`如果搜索结束。 

如果二分查找穷尽区间而没有找到目标，则该目标不存在。 

### 为什么它有效

 该算法之所以有效，是因为指数扩展保证我们最终找到包含目标的区间（如果存在）。 由于数组是有序的，一旦`reader.get(right)`变得大于或等于目标，目标的任何有效出现都必须位于`left`和`right`。 

二分搜索是正确的，因为排序顺序不变式始终保持不变，并且越界索引的行为类似于无限大的值，从而防止无效访问破坏搜索逻辑。 

## Python 解决方案```python
# """
# This is ArrayReader's API interface.
# You should not implement it, or speculate about its implementation
# """
# class ArrayReader:
#     def get(self, index: int) -> int:

class Solution:
    def search(self, reader: 'ArrayReader', target: int) -> int:
        left = 0
        right = 1

        # Expand search boundary exponentially
        while reader.get(right) < target:
            left = right
            right *= 2

        # Standard binary search
        while left <= right:
            mid = left + (right - left) // 2
            value = reader.get(mid)

            if value == target:
                return mid

            if value < target:
                left = mid + 1
            else:
                right = mid - 1

        return -1
```实现完全遵循算法。 

第一部分发现适当的搜索间隔。 开始于`[0,1]`，范围加倍，直到目标不再大于处的值`right`。 这保证了目标（如果存在）位于间隔内。 

第二部分执行常规二分搜索。 使用以下方式获取中点值`reader.get(mid)`而不是直接索引。 由于越界访问返回非常大的哨兵值，因此它们自然会表现得像大于目标的值，并将搜索向左推。 

最后，如果没有找到匹配项，函数返回`-1`。 

## 解决方案```go
/**
 * // This is the ArrayReader's API interface.
 * // You should not implement it, or speculate about its implementation
 * type ArrayReader struct {
 * }
 *
 * func (this *ArrayReader) get(index int) int {}
 */

func search(reader ArrayReader, target int) int {
	left, right := 0, 1

	// Expand search boundary exponentially
	for reader.get(right) < target {
		left = right
		right *= 2
	}

	// Standard binary search
	for left <= right {
		mid := left + (right-left)/2
		value := reader.get(mid)

		if value == target {
			return mid
		}

		if value < target {
			left = mid + 1
		} else {
			right = mid - 1
		}
	}

	return -1
}
```Go 实现与 Python 版本几乎相同。 

一个小的实现细节是中点计算：```go
mid := left + (right-left)/2
```这可以避免潜在的整数溢出，这被认为是二分搜索实现中的最佳实践。 

由于 Go 没有`nil`对这个问题的关注和数组访问是通过抽象的`ArrayReader`，实现仍然很简单。

 ## 边缘情况

 ### 单元素数组

 当数组仅包含一个元素时，扩展可能会立即访问越界索引。 例如：```
[5]
```有目标`5`。 

呼唤`reader.get(1)`回报`2^31 - 1`，这会安全地停止扩展。 二分查找仍然正确检查索引`0`并返回答案。 

### 目标大于所有元素

 如果目标超过每个数组值，指数扩展可能会反复超出范围。 例如：```
[1, 2, 3]
target = 100
```最终，`reader.get(right)`返回哨兵值，该值大于目标值。 然后，二分搜索安全地消除无效区域并返回`-1`。 

### 目标小于第一个元素

 如果目标小于第一个元素，则扩展会立即停止，因为即使早期值也超过目标。 

例如：```
[10, 20, 30]
target = 5
```二分查找快速缩小范围并正确返回`-1`。 

### 二分搜索期间越界

 二分查找可能会检查实际数组大小之外的索引。 API 不会导致错误，而是返回`2^31 - 1`。 

由于这个哨兵值总是大于有效目标，算法自然会向左移动并避开无效区域，而不需要特殊的边界检查。
