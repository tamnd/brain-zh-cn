[LeetCode 700 题](https://leetcode.com/problems/search-in-a-binary-search-tree/)

 **难度：** 🟢简单
 **主题：** 树、二叉搜索树、二叉树

 ## 解决方案

 ## 问题理解

 此问题为我们提供了二叉搜索树（通常缩写为 BST）的根节点以及一个整数值`val`。 我们的目标是找到其值恰好等于的节点`val`并返回该节点。 由于问题要求我们返回以该节点为根的子树，因此返回节点本身就足够了，因为每个节点都已经包含对其子节点的引用。 

二叉搜索树有一个非常重要的属性：

 - 左子树中的每个值都小于当前节点的值
 - 右子树中的每个值都大于当前节点的值

 这种排序属性使我们能够高效地进行搜索。 

输入是一个树结构，表示为`root`，和一个整数`val`代表我们要寻找的目标。 预期输出是：

 - 其值等于的节点`val`-`null`或者`None`如果不存在这样的节点

 例如，如果树是：```
        4
       / \
      2   7
     / \
    1   3
```和`val = 2`，我们返回包含的节点`2`。 返回的节点代表这个子树：```
      2
     / \
    1   3
```约束告诉我们树包含`1`和`5000`节点。 这个值足够小，即使是完全遍历也可以在时间限制内完成，但 BST 属性允许我们比扫描每个节点做得更好。 

该问题保证输入树是有效的二叉搜索树。 这个保证极其重要，因为我们的优化解决方案完全依赖于 BST 排序规则。 

有几种边缘情况值得考虑：

 - 目标值可能不存在于树中的任何位置
 - 根本身可能包含目标值
 - 目标可能位于树深处
 - 树可能严重倾斜，表现得几乎像一个链表
 - 该树至少包含一个节点，因此`root`不保证是`None`，但处理`None`安全仍然是很好的防守练习

 ## 方法

 ### 蛮力方法

 最简单的解决方案是完全忽略 BST 属性并执行树的完整遍历。 我们可以使用深度优先搜索或广度优先搜索。 

该算法会逐一访问每个节点并将其值与`val`。 如果找到匹配项，我们立即返回该节点。 如果我们遍历完整棵树而没有找到值，我们就返回`None`。 

这种方法是正确的，因为它最终会检查树中的每个节点，因此如果该值存在，我们就保证能找到它。 

然而，这种解决方案浪费了BST结构。 即使当前节点的值准确地告诉我们应该搜索哪个方向，强力方法仍然会探索两个子树。 

### 最佳方法

 关键的见解是该树是二叉搜索树。 

在每个节点：

 - 如果`val`等于当前节点的值，我们找到了答案
 - 如果`val`越小，目标只能存在于左子树中
 - 如果`val`越大，目标只能存在于右子树中

 这意味着我们永远不需要搜索树的两侧。 在每一步中，我们都会消除一半的剩余搜索空间，类似于排序数组上的二分搜索。 

由于这一特性，我们只能从根向下遍历一条路径，直到找到目标或到达目标`None`节点。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(h) | 遍历整个树，无论 BST 排序如何 |
 | 最佳| O(h) | O(1) 迭代，O(h) 递归 | 使用 BST 属性仅搜索一个分支 |

 这里：

-`n`是节点数
 -`h`是树的高度

 在平衡 BST 中，`h = log n`。 在倾斜的 BST 中，`h = n`。 

## 算法演练

 ### 最优迭代 BST 搜索

 1. 从树的根节点开始。 

根是 BST 的入口点。 关于下一步移动到哪里的每个决定都取决于将目标值与当前节点进行比较。 
2. 将当前节点的值与`val`。 

有三种可能的情况：

 - 如果它们相等，我们找到目标节点并立即返回它。 
- 如果`val`越小，BST性质保证目标只能存在于左子树中。 
- 如果`val`越大，BST性质保证目标只能存在于右子树中。 
3. 移动到适当的子节点。 

根据比较：

 - 移至`current.left`如果`val < current.val`- 移至`current.right`如果`val > current.val`这消除了每一步剩余搜索空间的一半。 
4. 继续直到：

 - 找到目标节点
 - 当前节点变为`None`如果当前节点变成`None`，这意味着我们到达了一个死胡同，目标值在树中不存在。 
5. 返回`None`如果未找到该值。 

### 为什么它有效

 正确性直接来自 BST 不变量：

 - 每个左子树仅包含较小的值
 - 每个右子树只包含较大的值

 在每一步，算法都会丢弃不可能包含目标的整个子树。 由于我们只移动到目标可以合法存在的子树，因此我们永远不会错过正确的节点。 最终，我们要么找到该节点，要么确定不再存在有效路径。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional

class Solution:
    def searchBST(self, root: Optional[TreeNode], val: int) -> Optional[TreeNode]:
        current = root
        
        while current:
            if current.val == val:
                return current
            
            if val < current.val:
                current = current.left
            else:
                current = current.right
        
        return None
```该实现首先将根节点存储在名为的变量中`current`。 该变量在遍历期间跟踪我们当前的位置。 

这`while current:`只要我们仍然有一个有效的节点要检查，循环就会继续。 如果`current`变成`None`，我们知道搜索路径结束而没有找到目标。 

在循环内部，第一个条件检查当前节点是否已包含目标值。 如果是，我们立即返回该节点。 

如果目标小于当前节点的值，我们将向左移动，因为 BST 属性保证所有较小的值都位于左子树中。 

否则，我们向右移动，因为目标必须更大。 

如果循环结束后没有返回节点，则该值在 BST 中不存在，因此我们返回`None`。 

此实现是迭代的，这避免了递归调用堆栈开销并使辅助空间使用量最小化。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func searchBST(root *TreeNode, val int) *TreeNode {
    current := root

    for current != nil {
        if current.Val == val {
            return current
        }

        if val < current.Val {
            current = current.Left
        } else {
            current = current.Right
        }
    }

    return nil
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 主要的语言特定差异是 Go 使用`nil`而不是`None`。 

指针直接用于树节点，因此返回子树只是意味着返回指向匹配节点的指针。 

Go 不需要显式类型提示，因为编译器从声明中推断类型，例如`current := root`。 

由于节点值最多被限制为`10^7`，整数溢出不是 Go 标准整数类型的问题。 

## 工作示例

 ### 示例 1

 输入：```
root = [4,2,7,1,3]

```树：```

```逐步遍历：

 | 步骤| 当前节点| 比较| 行动|

      2
     / \
    1   3
```### 示例 2

 输入：```
root = [4,2,7,1,3]
val = 5
```树：```
        4
       / \
      2   7
     / \
    1   3
```逐步遍历：

 | 步骤| 当前节点| 比较| 行动|
 | --- | --- | --- | --- |
 | 1 | 4 | 5 > 4 | 5 > 4 向右移动|

 | 3 | 无 | 未找到目标 | 无返回 |

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(h) | 我们从根到叶最多遍历一条路径 |
 | 空间| O(1) | O(1) | 迭代解决方案使用恒定的额外内存 |

 时间复杂度取决于树的高度，因为该算法每一步仅遵循一个分支。 

在平衡 BST 中，高度是对数的，因此运行时间变为：```
O(log n)
```在最坏的情况下，当树完全倾斜时，高度变为：```
O(n)
```无论树大小如何，迭代实现都只存储几个变量，因此辅助空间复杂度是恒定的。

 ## 边缘情况

 一种重要的边缘情况是目标值存储在根本身中。 有错误的实现可能会不必要地继续遍历而不是立即返回。 在此解决方案中，相等性检查发生在任何移动之前，因此当匹配时立即返回根。 

另一个关键的边缘情况是当目标值不存在于树中时。 一些不正确的实现意外地取消引用`None`或者`nil`继续遍历节点。 一旦当前节点变为，此实现就会安全地终止循环`None`，然后返回`None`。 

倾斜的 BST 是另一个重要的场景。 形状像链表的树可以暴露递归解决方案中的递归深度问题。 由于此实现是迭代的，因此它可以安全地处理深度倾斜的树，而不会面临堆栈溢出的风险。 

当树仅包含一个节点时，会出现最后一种边缘情况。 该算法必须正确处理两种结果：单个节点要么与目标匹配，要么不匹配。 由于循环在遍历之前检查相等性，因此这两种情况都会自然处理，无需特殊情况逻辑。
