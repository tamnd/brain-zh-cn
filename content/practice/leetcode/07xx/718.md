 **难度：** 🟡 中等
 **主题：** 数组、二分查找、动态规划、滑动窗口、滚动哈希、哈希函数

 ## 解决方案

 ## 问题理解

 该问题要求我们找到两个输入数组中出现的最长连续子数组。 子数组与子序列不同，因为元素必须保持相邻。 这一区别极其重要，因为许多类似的问题都允许存在间隙，但这个问题却不允许。 

我们有两个整数数组，`nums1`和`nums2`。 我们的任务是确定两个数组中存在的连续序列的最大可能长度。 不需要返回实际的子数组，只需返回其长度。 

例如，考虑：```
nums1 = [1,2,3,2,1]
nums2 = [3,2,1,4,7]
```最长的共享连续子数组是：```
[3,2,1]
```它的长度是`3`，所以答案是`3`。 

限制相对较小：

 - 每个数组长度最多为`1000`- 值范围为`0`到`100`这些限制强烈表明`O(n^2)`动态规划解是可行的，因为`1000 * 1000 = 1,000,000`，这是可以管理的。 

需要考虑一些重要的边缘情况：

 - 具有所有相同值的数组
 - 没有公共元素的数组
 - 长度数组`1`- 创建重叠匹配区域的重复值
 - 最长匹配出现在数组末尾附近的情况

 幼稚的实现很容易因混淆子序列和子数组而犯错误。 另一个常见的错误是当元素停止匹配时无法重置状态。 

## 方法

 ### 蛮力方法

 蛮力解决方案检查每个可能的起始位置`nums1`针对每一个可能的起始位置`nums2`。 

对于每对起始索引`(i, j)`，当元素匹配时我们继续前进：```
nums1[i + k] == nums2[j + k]
```我们计算比赛持续的时间并更新全局最大值。 

这种方法是正确的，因为它显式地检查每个可能的对齐子数组对。 如果存在重复的子数组，蛮力方法最终将比较这些精确位置并测量其长度。 

然而，性能较差。 有`O(n * m)`起始对，每次比较最多可以扫描`O(min(n, m))`元素。 这会在最坏的情况下导致立方行为。 

### 最佳解决方案的关键见解

 重要的观察结果是，连续匹配的行为与最长公共子串问题类似。 

如果：```
nums1[i] == nums2[j]
```那么以这些位置结束的重复子数组的长度完全取决于之前的位置：```
dp[i][j] = dp[i-1][j-1] + 1
```否则：```
dp[i][j] = 0
```这是可行的，因为连续匹配需要相邻元素继续匹配。 一旦两个元素不同，连续的条纹就会立即中断。 

动态编程允许我们重用先前计算的匹配长度，而不是重复向前扫描。 

## 方法比较

 | 最优动态规划| O(n × m) | O(n × m) | 重用重叠子问题来有效计算匹配条纹 |

 ## 算法演练

 ### 最优动态规划算法

 1. 创建一个 2D DP 表，其中`dp[i][j]`表示结束于的最长公共子数组的长度`nums1[i-1]`和`nums2[j-1]`。 
2. 用零初始化表。 值为零表示当前元素不继续匹配的连续序列。 
3. 遍历每个索引`nums1`。 
4. 对于中的每个元素`nums1`，迭代中的每个索引`nums2`。 
5.比较当前元素：

 - 如果`nums1[i-1] == nums2[j-1]`，那么当前匹配子数组扩展了前一个对角线匹配：```
dp[i][j] = dp[i-1][j-1] + 1
```- 否则，连续匹配将中断：```
dp[i][j] = 0
```6. 更新每个DP信元后，如果当前值较大，则更新全局最大长度。 
7. 处理完整个表后，返回找到的最大值。 

### 为什么它有效

 DP 表维护了一个重要的不变量：```
dp[i][j]
```始终存储以这两个位置结束的最长公共连续子数组的确切长度。 

如果当前元素匹配，则扩展连续子数组的唯一方法是通过前一对索引。 因此，添加`1`到对角线值正确扩展匹配条纹。 

如果元素不同，连续性就会被破坏，因此该值必须重置为`0`。 

由于会检查每个可能的结束位置对，因此该算法保证找到全局最大重复子数组长度。 

## Python 解决方案```python
from typing import List

class Solution:
    def findLength(self, nums1: List[int], nums2: List[int]) -> int:
        n = len(nums1)
        m = len(nums2)

        dp = [[0] * (m + 1) for _ in range(n + 1)]

        max_length = 0

        for i in range(1, n + 1):
            for j in range(1, m + 1):
                if nums1[i - 1] == nums2[j - 1]:
                    dp[i][j] = dp[i - 1][j - 1] + 1
                    max_length = max(max_length, dp[i][j])

        return max_length
```实现首先确定两个数组的长度。 DP表尺寸`(n + 1) × (m + 1)`创建是为了简化边界处理。 额外的行和列消除了访问时进行特殊检查的需要`dp[i-1][j-1]`。 

嵌套循环迭代两个数组中的每对位置。 每当找到匹配值时，当前 DP 单元就会比对角前一个单元大 1。 

对角线依赖性至关重要，因为连续子数组只能从紧邻的前一个匹配位置延伸。 

变量`max_length`跟踪迄今为止看到的最大匹配子数组。 由于每个 DP 单元代表一个以这些索引结尾的有效重复子数组，因此所有单元中的最大值就是最终答案。 

## 解决方案```go
func findLength(nums1 []int, nums2 []int) int {
    n := len(nums1)
    m := len(nums2)

    dp := make([][]int, n+1)
    for i := range dp {
        dp[i] = make([]int, m+1)
    }

    maxLength := 0

    for i := 1; i <= n; i++ {
        for j := 1; j <= m; j++ {
            if nums1[i-1] == nums2[j-1] {
                dp[i][j] = dp[i-1][j-1] + 1

                if dp[i][j] > maxLength {
                    maxLength = dp[i][j]
                }
            }
        }
    }

    return maxLength
}
```Go 的实现与 Python 解决方案非常相似。 主要区别在于 2D DP 表的显式切片分配。 

Go 数组和切片会自动初始化为零，因此自然会保留不匹配的状态`0`。 

整数溢出不是问题，因为最大可能的答案只是`1000`。 

与 Python 不同，Go 不需要导入类型注释或辅助库。

 | 测量| 复杂性 | 说明|

 | 时间 | O(n × m) | 每对索引都被处理一次 |

 该算法在两个数组上使用嵌套循环，总共给出`n * m`州。 每个状态只执行恒定时间的工作。

 ## 边缘情况

 ### 没有公共元素的数组

 一个常见的错误是意外地将不相关的值视为部分匹配。 例如：```
nums1 = [1,2,3]
nums2 = [4,5,6]
```没有元素匹配，因此每个 DP 单元都保留`0`。 该实现自然地处理了这个问题，因为仅当当前元素相等时才会扩展值。 

### 具有所有相同值的数组

 考虑：```
nums1 = [0,0,0,0,0]
nums2 = [0,0,0,0,0]
```每一条对角线的延伸都在继续增长。 一些不正确的实现会错误地重置值或无法跟踪最长的条纹。 DP 递归正确地沿着对角线构建递增的值，直到答案达到整个数组长度。 

### 重复重叠模式

 案例如下：```
nums1 = [1,2,1,2,1]
nums2 = [1,2,1,2,3]
```可能会混淆简单的实现，因为多个潜在的匹配重叠。 DP 解决方案避免了歧义，因为每个状态严格表示以特定索引结尾的连续匹配。 这保证了重叠区域得到正确处理，而不会出现重复计算或跳过的可能性。
