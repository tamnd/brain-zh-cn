[LeetCode 第 768 题](https://leetcode.com/problems/max-chunks-to-make-sorted-ii/)

 **难度：** 🔴难
 **主题：** 数组、堆栈、贪婪、排序、单调堆栈

 ## 解决方案

 ## 问题理解

 该问题要求我们将数组划分为尽可能多的连续块，以便在对每个块独立排序并连接结果后，整个数组变得全局排序。 

关键细节是每个块必须保持连续。 分割后我们无法跨块边界重新排列元素。 定义块后，每个块都会单独排序，然后所有排序的块按其原始顺序连接起来。 

目标是最大化块的数量。 

例如，考虑：```
arr = [2,1,3,4,4]
```我们可以将其分为：```
[2,1], [3], [4], [4]
```对每个块进行排序给出：```
[1,2], [3], [4], [4]
```连接它们会产生：```
[1,2,3,4,4]
```这是完全排序的。 

由于数组可能包含重复项，因此挑战变得更加困难。 这是与 LeetCode 769 的主要区别，其中数组是以下的排列`0..n-1`。 在此问题中，值可能重复并且可能任意大。 

限制条件是：

 -`1 <= arr.length <= 2000`-`0 <= arr[i] <= 10^8`2000 的数组长度并不是很大，因此二次解可能会通过，但三次解可能会太慢。 重复项的存在意味着我们不能依赖索引值匹配技巧。 

一些边缘情况很重要：

 - 数组已经排序，其中每个元素都可以形成自己的块。 
- 数组按相反顺序排序，其中只能有一个块。 
- 具有许多重复项的数组，其中块边界变得微妙。 
- 局部排序看起来有效但如果分割不正确则全局排序会中断的数组。 
- 单元素数组，答案始终为 1。 

如果仅考虑本地比较而不是确保左侧块中的所有元素都小于或等于右侧块中的所有元素，幼稚的实现很容易失败。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试数组的所有可能的分区，并验证对每个块进行排序是否会产生全局排序的数组。 

对于长度的数组`n`， 有`2^(n-1)`在元素之间放置分隔符的可能方法。 对于每个分区：

 1. 将数组分割成块。 
2. 对每个块独立排序。 
3. 连接排序后的块。 
4. 将结果与原始数组的完全排序版本进行比较。 

这种方法是正确的，因为它详尽地检查了每个有效的分区配置。 如果任何分区有效，就会考虑它，并且可以跟踪最大块数。 

然而，这种方法在计算上是不可行的，因为分区的数量呈指数增长。 

### 最佳解决方案的关键见解

 索引之间的块边界`i`和`i+1`如果左侧的每个元素都小于或等于右侧的每个元素，则有效。 

这导致了一个非常重要的观察：

 如果：```
max(arr[0..i]) <= min(arr[i+1..n-1])
```那么我们可以在索引之后安全地分割`i`。 

为什么这有效？ 

对左边的 chunk 进行排序后，其最大值仍然位于 chunk 的末尾。 对正确的块进行排序后，其最小值仍将位于该块的开头。 因此，如果左块中的最大值不超过右块中的最小值，则串联保持全局排序。 

这建议采用前缀/后缀预处理策略：

 - 计算`prefix_max[i]`，从开始到索引的最大值`i`。 
- 计算`suffix_min[i]`, 索引的最小值`i`直到最后。 

那么每个有效的分割位置都满足：```
prefix_max[i] <= suffix_min[i+1]
```每一个这样的位置都会增加一个块。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n * n log n) | O(2^n * n log n) | O(n) | 尝试每个分区并通过排序进行验证 |
 | 最佳| O(n) | O(n) | 使用前缀最大值和后缀最小值 |

 ## 算法演练

 1. 创建一个`prefix_max`大批。 

对于每个索引`i`，存储从数组开头通过索引看到的最大值`i`。 

这告诉我们如果我们在之后进行分割，左边块中将出现的最大值`i`。 
2. 创建一个`suffix_min`大批。 

对于每个索引`i`，存储从索引中看到的最小值`i`穿过数组的末尾。 

这告诉我们如果我们之前进行分割，则会出现在正确块中的最小值`i`。 
3. 初始化第一个块计数。 

即使不可能进行分割，整个数组本身也会形成一个有效的块。 因此，我们从以下开始：```
chunks = 1
```4. 迭代所有可能的分割位置。 

对于每个索引`i`从`0`到`n-2`：

 - 左边的块是`arr[0..i]`- 正确的块是`arr[i+1..n-1]`如果：```
prefix_max[i] <= suffix_min[i+1]
```那么分裂是安全的。 
5. 只要存在有效的分割，就增加块计数。 

每个有效的分割都会创建一个额外的块。 
6. 返回最终的块计数。 

### 为什么它有效

 该算法依赖于左侧块中的每个元素必须小于或等于右侧块中的每个元素的不变量。`prefix_max[i]`表示潜在分裂左侧的最大元素。`suffix_min[i+1]`代表右侧最小的元素。 

如果：```
prefix_max[i] <= suffix_min[i+1]
```那么独立地对两个块进行排序就不能创建跨边界的反转。 因此，串联结果保持全局排序。 

由于该算法独立地检查每个可能的边界并计算所有有效的边界，因此它会产生最大可能数量的块。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxChunksToSorted(self, arr: List[int]) -> int:
        n = len(arr)

        prefix_max = [0] * n
        suffix_min = [0] * n

        prefix_max[0] = arr[0]
        for i in range(1, n):
            prefix_max[i] = max(prefix_max[i - 1], arr[i])

        suffix_min[n - 1] = arr[n - 1]
        for i in range(n - 2, -1, -1):
            suffix_min[i] = min(suffix_min[i + 1], arr[i])

        chunks = 1

        for i in range(n - 1):
            if prefix_max[i] <= suffix_min[i + 1]:
                chunks += 1

        return chunks
```该实现遵循算法演练中描述的确切策略。 

首先，分配两个辅助数组：

 -`prefix_max`-`suffix_min`这`prefix_max`数组是从左到右构建的。 每个位置存储迄今为止看到的最大值。 这允许恒定时间访问任何左侧分区中的最大值。 

这`suffix_min`数组是从右到左构建的。 每个位置存储从该索引开始的最小值。 这允许恒定时间访问任何右侧分区中的最小值。 

然后算法检查每个可能的分割位置。 如果左侧的最大值小于或等于右侧的最小值，则分割有效，并且块计数增加。 

该解决方案以线性时间运行，因为每个数组仅被遍历固定次数。 

## 解决方案```go
func maxChunksToSorted(arr []int) int {
	n := len(arr)

	prefixMax := make([]int, n)
	suffixMin := make([]int, n)

	prefixMax[0] = arr[0]
	for i := 1; i < n; i++ {
		if prefixMax[i-1] > arr[i] {
			prefixMax[i] = prefixMax[i-1]
		} else {
			prefixMax[i] = arr[i]
		}
	}

	suffixMin[n-1] = arr[n-1]
	for i := n - 2; i >= 0; i-- {
		if suffixMin[i+1] < arr[i] {
			suffixMin[i] = suffixMin[i+1]
		} else {
			suffixMin[i] = arr[i]
		}
	}

	chunks := 1

	for i := 0; i < n-1; i++ {
		if prefixMax[i] <= suffixMin[i+1] {
			chunks++
		}
	}

	return chunks
}
```Go 的实现与 Python 解决方案非常相似。 

Go 没有提供内置的`max`和`min`整数函数，因此在构造前缀和后缀数组时使用显式比较。 

切片是使用动态分配的`make`，并且整数溢出不是问题，因为约束完全适合 Go 的范围`int`现代系统的范围。 

该算法仍然在线性时间和线性空间中运行。

 ## 边缘情况

 ### 反向排序数组

 反向排序数组例如：```
[5,4,3,2,1]
```是一个重要的边缘情况，因为左侧的每个元素都比右侧的某些元素大。 幼稚的实现可能会根据本地顺序错误地进行分割。 

前缀/后缀方法可以正确处理此问题，因为前缀最大值始终保持不变`5`，同时保留每个后缀最小值`1`。 由于条件：```
prefix_max[i] <= suffix_min[i+1]
```永远不成立，不允许分裂。 

### 具有重复值的数组

 重复使得这个问题比简单的排列版本更加困难。 

例如：```
[2,2,2]
```每个分割都是有效的，因为跨块边界允许相同的值。 

实现正确使用`<=`而不是`<`。 这个细节很关键。 使用严格的不等式会错误地拒绝涉及相等值的有效块边界。 

### 单元素数组

 具有一个元素的数组根本没有分割位置，但整个数组本身仍然形成一个有效的块。 

该实现自然地处理了这个问题，因为：```
chunks = 1
```在检查分割位置之前初始化。 由于分割位置上的循环永远不会执行，因此该方法正确返回`1`。
