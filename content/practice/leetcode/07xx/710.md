 ## 解决方案

 ## 问题理解

 该问题要求我们设计一个数据结构，可以重复返回范围内的随机整数`[0, n - 1]`，同时排除出现在黑名单中的所有整数。 每个有效数字必须具有完全相同的被选择概率。 

挑战不仅仅是过滤数字。 关键要求是效率。 的价值`n`可以大到`10^9`，这意味着我们无法显式构建或存储整个有效数字范围。 同时黑名单最多可以包含`10^5`值，相对来说是可以管理的。 

幼稚的实现可能会重复生成随机数，直到找到未列入黑名单的随机数。 虽然这在概念上可行，但当黑名单很大时，它会变得低效。 想象一下几乎所有号码都被列入黑名单的情况。 该算法可能会进行多次重试才能找到有效值。 

该问题特别提到最小化对内置随机函数的调用。 这强烈表明理想的解决方案应该只需要每个随机调用一次`pick()`手术。 

输入包括：

 -`n`，范围的上限
 -`blacklist`，无法返回的唯一整数列表

 预期输出为`pick()`是均匀随机的有效数。 

这些约束告诉我们一些重要的事情：

 -`n`非常大，因此在整个范围内基于阵列的解决方案是不可能的
 -`blacklist.length`远小于`n`- 最多`2 * 10^4`打电话给`pick()`可能会发生，所以每次调用理想情况下应该是`O(1)`有几种重要的边缘情况：

 - 黑名单可能为空
 - 黑名单可能包含几乎所有号码
 - 列入黑名单的号码可能聚集在范围的开头或结尾
 -`n`即使黑名单很小，也可能非常大

 该问题保证黑名单值是唯一的且在范围内，从而简化了预处理。 

## 方法

 ### 蛮力方法

 最直接的想法是重复生成范围内的随机整数`[0, n - 1]`直到我们找到一个未被列入黑名单的人。 

为了支持快速黑名单查找，我们可以将所有列入黑名单的号码存储在一个哈希集中。 期间`pick()`，我们生成一个随机数并检查它是否存在于集合中。 如果是这样，我们再试一次。 

这种方法是正确的，因为每个生成的数字都是均匀随机的，并且我们只拒绝无效的选择。 最终，我们返回一个有效的数字。 

然而，当黑名单很大时，该解决方案可能变得极其低效。 假设只有一个有效数字存在。 在这种情况下，几乎每个随机调用都会失败，从而导致多次重试。 预期的运行时间变得很差，并且随机调用的数量变得过多。 

### 最佳方法

 关键的见解是我们实际上不需要从整个范围生成数字`[0, n - 1]`。 

假设黑名单包含`b`数字。 那么正好有`n - b`有效数字。 如果我们能够以某种方式将有效数字映射到一个紧凑的范围内，我们就可以仅从那个较小的空间生成随机值。 

定义：```
size = n - len(blacklist)
```我们只生成随机整数`[0, size - 1]`。 

现在考虑两种情况：

 - 如果这个范围内的号码没有被列入黑名单，我们可以直接返回。 
- 如果它被列入黑名单，我们将其重新映射到范围上部的某个有效号码。 

上限范围`[size, n - 1]`包含足够的未使用的有效数字来替换出现在较低范围内的所有黑名单值。 

这将问题转化为哈希图重新映射问题。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 |`pick(): O(expected retries)`|`O(b)`| 反复重试，直到找到有效号码 |
 | 最佳 |`O(b)`预处理,`O(1)`挑选|`O(b)`| 使用重映射来保证一次随机调用 |

 ## 算法演练

 ### 第 1 步：计算有效范围大小

 我们首先计算：```
size = n - len(blacklist)
```这告诉我们总共存在多少个有效数字。 

而不是从生成数字`[0, n - 1]`，我们只会生成数字`[0, size - 1]`。 

这保证了每个随机调用一次`pick()`。 

### 步骤 2：将列入黑名单的号码存储在集合中

 我们将所有黑名单值放入哈希集中。 

这允许在确定号码是否被列入黑名单时进行恒定时间查找。 

### 步骤 3：识别较低范围内的黑名单号码

 一些列入黑名单的号码可能已经位于上限范围内`[size, n - 1]`。 

这些并不重要，因为我们从来不会随机生成它们。 

唯一有问题的值是黑名单号码小于`size`，因为这些可能是随机选择的。 

必须重新映射这些值。 

### 步骤 4：查找替换值

 我们扫描范围的上部，从`size`。 

每当我们遇到不在黑名单中的号码时，我们都会用它来代替。 

对于每个列入黑名单的值`b < size`，我们创建：```
mapping[b] = replacement_value
```这保证了每个无效的下限值都映射到有效的上限值。 

### 步骤 5：生成随机数

 期间`pick()`:

 1. 生成随机整数`x`在`[0, size - 1]`2.如果`x`被重新映射，返回`mapping[x]`3.否则返回`x`这会在所有有效数字上产生完全均匀的分布。 

### 为什么它有效

 该算法之所以有效，是因为范围较低`[0, size - 1]`包含的位置数量与总体有效数量完全相同。 

此较低范围内的每个黑名单值都将替换为较高范围中的唯一有效值。 因此：

 - 每个随机索引恰好对应一个有效输出
 - 有效号码不能出现多次
 - 每个有效数字都有相同的概率

 这在随机选择和有效输出之间创建了一对一的对应关系。 

## Python 解决方案```python
import random
from typing import List

class Solution:

    def __init__(self, n: int, blacklist: List[int]):
        self.size = n - len(blacklist)
        blacklist_set = set(blacklist)

        self.mapping = {}

        candidate = self.size

        for blocked in blacklist:
            if blocked < self.size:
                while candidate in blacklist_set:
                    candidate += 1

                self.mapping[blocked] = candidate
                candidate += 1

    def pick(self) -> int:
        value = random.randint(0, self.size - 1)

        if value in self.mapping:
            return self.mapping[value]

        return value

# Your Solution object will be instantiated and called as such:
# obj = Solution(n, blacklist)
# param_1 = obj.pick()
```该实现首先计算有效整数的数量，存储在`self.size`。 该值决定随机生成期间使用的范围。 

将黑名单转换为一组，以进行高效的成员资格测试。 这很重要，因为我们反复检查候选替换值是否被列入黑名单。 

这`mapping`字典存储较低范围内黑名单号码的重新映射。 仅限小于以下的数字`self.size`需要重新映射，因为这些是唯一可以随机选择的数字。 

变量`candidate`扫描上限。 每当发现非黑名单号码时，它就会成为较低范围的黑名单值的替换目标。 

这`pick()`方法只执行一次随机调用。 如果生成的数字存在于重映射表中，则返回映射值。 否则，该号码本身已经有效。 

## 解决方案```go
package main

import (
	"math/rand"
)

type Solution struct {
	size    int
	mapping map[int]int
}

func Constructor(n int, blacklist []int) Solution {
	size := n - len(blacklist)

	blackSet := make(map[int]bool)
	for _, num := range blacklist {
		blackSet[num] = true
	}

	mapping := make(map[int]int)

	candidate := size

	for _, blocked := range blacklist {
		if blocked < size {
			for blackSet[candidate] {
				candidate++
			}

			mapping[blocked] = candidate
			candidate++
		}
	}

	return Solution{
		size:    size,
		mapping: mapping,
	}
}

func (this *Solution) Pick() int {
	value := rand.Intn(this.size)

	if mapped, exists := this.mapping[value]; exists {
		return mapped
	}

	return value
}

/**
 * Your Solution object will be instantiated and called as such:
 * obj := Constructor(n, blacklist);
 * param_1 := obj.Pick();
 */
```Go 实现遵循与 Python 版本相同的逻辑，但使用 Go 映射而不是 Python 字典和集合。 

Go 没有内置的集合类型，所以`map[int]bool`用于表示黑名单集合。 

随机生成用途`rand.Intn(this.size)`，它产生整数`[0, size)`。 

因为`n`至多是`10^9`, 标准围棋`int`值在 LeetCode 环境中就足够了。

 | 空间|`O(b)`| 哈希集和重映射表|

 预处理阶段迭代黑名单值并可能扫描较高范围的候选值。 然而，每个候选者最多被访问一次，因此总预处理与黑名单大小保持线性关系。 

这`pick()`操作执行一次随机生成和至多一次哈希图查找，从而提供恒定时间性能。

 ## 边缘情况

 当黑名单为空时，会出现一种重要的边缘情况。 在这种情况下，每个数字`[0, n - 1]`是有效的。 有缺陷的实现可能仍然会尝试不必要地重新映射逻辑。 当前的实现自然地处理了这个问题，因为映射表保持为空，并且直接返回每个随机值。 

当几乎所有号码都被列入黑名单时，就会出现另一个严重情况。 例如，`n = 4`和`blacklist = [0,1,2]`。 拒绝采样方法将变得极其低效，因为大多数随机值都会失败。 重新映射策略通过减小随机范围的大小来完全避免这种情况`1`，保证立即成功。 

当黑名单值已经完全位于上限范围内时，会出现第三种微妙的边缘情况。 例如，`n = 6`和`blacklist = [4,5]`。 由于随机生成仅发生在`[0,3]`，这些列入黑名单的值无论如何都不会出现。 该实现正确地跳过了对此类值的重新映射，从而避免了不必要的工作。 

错误的另一个潜在来源是重复映射。 如果不仔细选择替换值，两个列入黑名单的较低范围数字可能会映射到相同的有效值，从而破坏一致性。 该实施通过推进`candidate`指针仅向前并且从不重用替换值。 

最后，非常大的值`n`可能会诱使开发人员构建巨大的阵列。 自从`n`可能达到`10^9`，这样的解决方案将立即失效内存限制。 此实现仅存储与黑名单相关的信息，使内存与黑名单大小而不是整个范围成比例。
