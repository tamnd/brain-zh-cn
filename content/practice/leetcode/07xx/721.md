[LeetCode 721 题](https://leetcode.com/problems/accounts-merge/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、字符串、深度优先搜索、广度优先搜索、并查找、排序

 ## 解决方案

 ## 问题理解

 此问题要求我们根据共享电子邮件地址合并用户帐户。 每个帐户都表示为字符串列表。 第一个字符串是用户的姓名，其余每个字符串都是与该帐户关联的电子邮件地址。 

重要的细节是，如果两个帐户至少共享一个电子邮件地址，则它们属于同一个人。 这种关系是传递性的。 例如，如果账户 A 与账户 B 共享电子邮件，账户 B 与账户 C 共享电子邮件，则所有三个账户都属于同一个人，即使 A 和 C 不直接共享电子邮件。 

输出应将所有连接的帐户分组在一起。 每个合并帐户必须包含：

 1. 姓名
 2. 属于该人的所有唯一电子邮件
 3. 电子邮件按字典顺序排序

 最终合并帐户的顺序并不重要。 

限制相对较小：

 - 最多1000个帐户
 - 每个账户最多包含10个字符串
 - 电子邮件字符串很短

 尽管限制并不大，但每对帐户之间的天真比较仍然会变得低效，因为我们可能会重复扫描重叠的电子邮件列表。 

一个关键的观察结果是帐户形成了连接的组件。 每封电子邮件都可以被视为图表中的一个节点，帐户将电子邮件连接在一起。 一旦我们识别出相互关联的电子邮件组，我们就可以重建合并的帐户。 

一些边缘情况很重要：

 - 两个人可能有相同的名字，但完全无关
 - 一个帐户只能包含一封电子邮件
 - 多个帐户可以通过共享电子邮件间接链接在一起
 - 许多帐户中的重复电子邮件必须在输出中仅出现一次
 - 保证属于同一个人的所有合并账户具有相同的账户名

 ## 方法

 ### 蛮力方法

 一种强力解决方案会反复比较帐户，看看它们是否共享任何电子邮件地址。 

我们可以：

 1. 比较每对账户
 2. 如果两个帐户共享一封电子邮件，请将它们合并
 3. 重复直到无法再合并为止

 为了确定两个帐户是否重叠，我们需要比较它们的电子邮件集。 由于合并一对可能会与其他帐户产生新的重叠，因此我们可能需要多次传递。 

这种方法是正确的，因为最终所有连接的帐户都会合并到一组中。 然而，它的效率很低，因为重复的成对比较会产生大量的开销。 

如果有`N`帐户，每个帐户最多包含`K`电子邮件，仅成对比较的成本约为`O(N^2 * K)`或者在重复合并过程后更糟。 

### 最优方法，并查

 关键的见解是这个问题从根本上来说是关于连接的组件的。 

如果同一帐户中出现两封电子邮件，则它们属于同一连接组。 我们可以使用并查数据结构（也称为不相交集并集，DSU）直接连接电子邮件，而不是重复比较帐户。 

该过程变为：

 1. 将每封电子邮件视为一个节点
 2. 合并同一帐户内的所有电子邮件
 3.处理完所有账户后，同根的邮件属于同一个合并账户
 4. 按根对电子邮件进行分组
 5. 对电子邮件进行排序并构建最终答案

 Union-Find 在这里非常理想，因为它可以有效地处理动态分组和连接查询。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(N² × K) 或更差 | O(N × K) | 反复比较和合并账户|
 | 最佳 | O(E × α(E) + E log E) | O(E) | 使用 Union-Find 对关联的电子邮件进行高效分组 |

 这里：

-`N`= 账户数量
 -`K`= 每个帐户的最大电子邮件数
 -`E`= 电子邮件总数
 -`α(E)`= 反阿克曼函数，几乎恒定

 ## 算法演练

 ### 步骤 1：初始化并查结构

 我们创建两个哈希图：

 -`parent[email]`存储每封电子邮件的代表父级
 -`email_to_name[email]`存储每封电子邮件的所有者姓名

 每封电子邮件最初都成为其自己的父电子邮件。 

我们使用哈希映射，因为电子邮件是字符串，而不是整数索引。 

### 第 2 步：处理每个帐户

 对于每个帐户：

 1. 提取账户名
 2. 将第一封邮件作为基础邮件
 3. 将帐户中的所有其他电子邮件与基本电子邮件合并

 这会将同一帐户内的所有电子邮件连接到一个组件中。 

例如：```
["John", "a@mail.com", "b@mail.com", "c@mail.com"]
```创建工会：```
a <-> b
a <-> c
```经过这些操作后，所有三封电子邮件共享相同的根。 

### 步骤 3：在查找期间应用路径压缩

 的`find()`操作递归地定位电子邮件的根父级。 

路径压缩通过直接将节点附加到根来优化未来的查找。 

如果没有路径压缩，树会变得很高且效率低下。 

### 步骤 4：按根对电子邮件进行分组

 所有联合完成后：

 1. 遍历每封电子邮件
 2.找到它的根代表
 3. 将电子邮件添加到与该根对应的组中

 现在，每个组包含属于一个合并帐户的所有电子邮件。 

### 第 5 步：构建最终答案

 对于每个连接的组件：

 1. 按字典顺序对电子邮件进行排序
 2. 使用群组中的任意电子邮件检索帐户名
 3. 构建合并账户

 格式变为：```
[name, sorted_email_1, sorted_email_2, ...]
```### 为什么它有效

 Union-Find 保证所有直接或间接连接的电子邮件都属于同一组件。 由于每个帐户都会将其所有电子邮件合并在一起，因此任何共享电子邮件都会导致连接的帐户传递合并。 

因此，按最终根对电子邮件进行分组会准确地生成代表每个人的连接组件。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def accountsMerge(self, accounts: List[List[str]]) -> List[List[str]]:
        parent = {}
        email_to_name = {}

        def find(email: str) -> str:
            if parent[email] != email:
                parent[email] = find(parent[email])
            return parent[email]

        def union(email1: str, email2: str) -> None:
            root1 = find(email1)
            root2 = find(email2)

            if root1 != root2:
                parent[root2] = root1

        # Initialize parent pointers and map emails to names
        for account in accounts:
            name = account[0]

            for email in account[1:]:
                if email not in parent:
                    parent[email] = email

                email_to_name[email] = name

        # Union emails within the same account
        for account in accounts:
            first_email = account[1]

            for email in account[2:]:
                union(first_email, email)

        # Group emails by root parent
        groups = defaultdict(list)

        for email in parent:
            root = find(email)
            groups[root].append(email)

        # Build final result
        result = []

        for root_email, emails in groups.items():
            name = email_to_name[root_email]
            merged_account = [name] + sorted(emails)
            result.append(merged_account)

        return result
```实现首先初始化两个字典。 这`parent`字典存储并查结构，而`email_to_name`记住每个电子邮件属于哪个用户名。 

这`find()`函数实现路径压缩。 每当我们搜索根时，我们都会展平结构，以便将来的搜索变得更快。 

这`union()`功能通过将一个根附加到另一个根来合并两个连接的电子邮件组。 

第一个循环将每封电子邮件初始化为其自己的父级，并记录关联的帐户名称。 

第二个循环使用第一封电子邮件作为代表性锚点来合并同一帐户内的所有电子邮件。 

所有联合完成后，我们迭代每封电子邮件，并使用根父级对它们进行分组`defaultdict(list)`。 

最后，我们对每个组的电子邮件进行排序并添加帐户名称以创建最终的合并帐户结构。 

## 解决方案```go
package main

import (
	"sort"
)

func accountsMerge(accounts [][]string) [][]string {
	parent := make(map[string]string)
	emailToName := make(map[string]string)

	var find func(string) string

	find = func(email string) string {
		if parent[email] != email {
			parent[email] = find(parent[email])
		}
		return parent[email]
	}

	union := func(email1, email2 string) {
		root1 := find(email1)
		root2 := find(email2)

		if root1 != root2 {
			parent[root2] = root1
		}
	}

	// Initialize parent pointers
	for _, account := range accounts {
		name := account[0]

		for i := 1; i < len(account); i++ {
			email := account[i]

			if _, exists := parent[email]; !exists {
				parent[email] = email
			}

			emailToName[email] = name
		}
	}

	// Union emails within the same account
	for _, account := range accounts {
		firstEmail := account[1]

		for i := 2; i < len(account); i++ {
			union(firstEmail, account[i])
		}
	}

	// Group emails by root
	groups := make(map[string][]string)

	for email := range parent {
		root := find(email)
		groups[root] = append(groups[root], email)
	}

	// Build result
	result := [][]string{}

	for root, emails := range groups {
		sort.Strings(emails)

		account := []string{emailToName[root]}
		account = append(account, emails...)

		result = append(result, account)
	}

	return result
}
```Go 实现遵循与 Python 版本相同的逻辑，但使用 Go 映射和切片。 

Go 不像 Python 那样支持嵌套命名函数，因此`find`函数首先声明为变量，然后递归赋值。 

切片在分组和结果构造期间动态附加。 由于 Go 映射对于丢失的键返回零值，因此在初始化期间使用显式存在检查。 

整数溢出不是问题，因为问题规模很小并且算术不会显着增长。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(E × α(E) + E log E) | 并查运算几乎不变，排序占主导地位 |
 | 空间| O(E) | 父图、分组图和结果存储 |

 这里，`E`代表所有帐户的电子邮件总数。 

由于路径压缩，联合和查找操作实际上是恒定时间。 主要的额外成本来自于对每个合并组件内的电子邮件进行排序。 在所有组中，排序贡献高达`O(E log E)`总时间。 

空间复杂度是线性的，因为我们存储父指针、映射、分组电子邮件和最终输出。

 ## 边缘情况

 ### 相同的名字，不同的人

 两个不相关的用户可能共享相同的帐户名。 简单的解决方案可能会仅根据名称错误地合并它们。 

例如：```
["John", "a@mail.com"]
["John", "b@mail.com"]
```这些帐户必须保持独立，因为它们不共享电子邮件地址。 该实现正确地避免了此问题，因为连接完全基于电子邮件，而不是姓名。 

### 传递连接

 帐户可以通过中间帐户间接连接。 

例如：```
A shares with B
B shares with C
```即使A和C不直接重叠，他们仍然属于同一个人。 

Union-Find 自然会处理此问题，因为所有连接的电子邮件最终共享相同的根代表。 

### 单一电子邮件帐户

 有些帐户仅包含一个电子邮件地址。 在这些情况下，不会发生联合操作。 

有错误的实现可能会在分组期间意外地跳过这些帐户，因为没有发生合并。 

该解决方案在联合开始之前正确初始化父映射中的每封电子邮件，确保孤立的电子邮件仍然出现在最终结果中。
