[LeetCode 第 781 题](https://leetcode.com/problems/rabbits-in-forest/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、数学、贪心

 ## 解决方案

 ## 问题理解

 在这个问题中，每只兔子都会告诉我们有多少只其他兔子分享它的颜色。 输入数组`answers`包含这些回复。 如果兔子说`x`，这意味着正好有`x + 1`该颜色组的兔子总数，包括它自己。 

挑战在于我们不知道哪些兔子属于同一颜色组。 多只兔子可能描述同一组，或者它们可能属于不同的组，但恰好给出相同的答案。 我们的任务是计算可能存在的兔子的最小总数，同时仍然使所有答案保持一致。 

例如，如果两只兔子都回答`1`，它们可能属于相同尺寸的颜色组`2`。 然而，如果三只兔子回答`1`，它们不可能都属于同一组，因为一组兔子回答`1`总共只能容纳两只兔子。 因此，第三只兔子必须开始另一组大小`2`。 

约束相对较小，最多有 1000 个答案，但问题主要在于正确推理，而不是处理巨大的输入大小。 由于答案限制在 1000 以下，我们可以轻松地使用哈希图来计算频率。 

一些边缘情况很重要：

 - 兔子回答`0`之所以特别，是因为他们声称没有其他兔子与他们有相同的颜色，这意味着每只兔子都形成了一个独特的群体`1`。 
- 多只兔子给出相同的答案可能需要分成多个组。 
- 频率不是组大小的精确倍数是很棘手的，因为部分填充的组仍然需要分配整个组大小。 

关键的困难在于理解报告的计数描述的是群体大小，而不是直接的兔子计数。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试将兔子明确分配到可能的颜色组，同时确保所有答案保持一致。 对于每只兔子，我们都会尝试将其放入现有的兼容组中或创建一个新组。 

这种方法最终找到最小有效排列，因为它探索了所有可能的分组。 然而，可能的分配数量以组合方式增长。 即使对于适度的输入大小，搜索空间也会变得巨大，因为具有相同答案的兔子可以通过许多不同的方式进行划分。 

这使得暴力破解变得不切实际。 

### 最优贪心计数方法

 重要的观察是兔子回答`x`意味着组大小恰好为`x + 1`。 

认为：

-`x = 2`- 五只兔子回答`2`每个有效颜色组最多可以包含`3`回答的兔子`2`，因为组的总大小必须是`3`。 

因此：

 - 第一组使用 3 只兔子
 - 剩余 2 只兔子需要另一组 3 号兔子

 兔子贡献总数变为`6`。 

这意味着我们只需要频率计数。 

对于每个不同的答案`x`:

 - 团体人数为`x + 1`- 如果频率是`freq`- 所需组数为：$$\left\lceil \frac{freq}{x+1} \right\rceil$$各组贡献`x + 1`兔总。 

这种贪婪分组是最佳的，因为将尽可能多的兔子组合到同一个有效组中可以最大限度地减少组的总数。

 | 蛮力 | 指数| 指数| 尝试所有可能的小组作业 |
 | 最佳| O(n) | O(n) | 使用频率计数和贪婪分组 |

 ## 算法演练

 1. 创建一个哈希图来计算每个答案出现的次数。 

如果三只兔子回答`2`，我们存储：```
2 -> 3
```哈希图允许我们独立处理每个不同的答案。 
2. 迭代每个`(answer, frequency)`一对。 

对于兔子的回答`x`，隐含的组大小为：$$x + 1$$3. 确定需要多少组。 

如果频率超过组大小，则需要多个组。 

组数为：$$\left\lceil \frac{frequency}{groupSize} \right\rceil$$在代码中，这可以有效地计算为：```
(frequency + groupSize - 1) // groupSize
```4. 将各组贡献的兔子总数相加。 

每个小组的贡献准确无误`groupSize`兔子，即使不是所有兔子都回答。 

所以：```
total += groupsNeeded * groupSize
```5. 返回累计总数。 

### 为什么它有效

 该算法之所以有效，是因为给出相同答案的兔子只能属于一个固定大小的组。 为了最大限度地减少兔子总数，我们应该在创建另一个组之前将尽可能多的兔子放入每个有效组中。 这种贪婪的分组策略最大限度地减少了组的数量，从而最大限度地减少了兔子的总数。 

## Python 解决方案```python
from collections import Counter
from typing import List

class Solution:
    def numRabbits(self, answers: List[int]) -> int:
        frequency_map = Counter(answers)

        total_rabbits = 0

        for answer, frequency in frequency_map.items():
            group_size = answer + 1

            groups_needed = (frequency + group_size - 1) // group_size

            total_rabbits += groups_needed * group_size

        return total_rabbits
```实现首先使用构建频率图`Counter`。 这让我们可以一起处理相同的答案，而不是单独处理兔子。 

对于每个不同的答案：

 -`group_size`计算为`answer + 1`-`groups_needed`使用上限划分来确定需要多少个有效颜色组
 - 这些组贡献的兔子总数被添加到`total_rabbits`该算法从不显式构造颜色组。 相反，它以数学方式计算所需的最小组数。 

## 解决方案```go
func numRabbits(answers []int) int {
    frequencyMap := make(map[int]int)

    for _, answer := range answers {
        frequencyMap[answer]++
    }

    totalRabbits := 0

    for answer, frequency := range frequencyMap {
        groupSize := answer + 1

        groupsNeeded := (frequency + groupSize - 1) / groupSize

        totalRabbits += groupsNeeded * groupSize
    }

    return totalRabbits
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个`map[int]int`被用来代替`Counter`来跟踪频率。 Go 中的整数除法自然会向零截断，因此标准上限除法公式仍然可以正确工作。 

不存在溢出问题，因为在给定的约束下最大可能的答案数非常小。

 ## 边缘情况

 当兔子回答时，会出现一种重要的边缘情况`0`。 一只兔子回答`0`声称没有其他兔子有它的颜色。 因此，每只这样的兔子都必须属于一个独特的单兔群体。 一个常见的错误是意外地将多个分组`0`一起回答，这将违反条件。 该实现自然地处理了这个问题，因为计算出的组大小变为`1`。 

当兔子的数量不能完美地按组大小划分时，就会出现另一个棘手的情况。 例如，三只兔子回答`1`需要两组尺寸`2`，总共有四只兔子。 幼稚的实现可能会错误地仅计算输入中看到的兔子。 上限划分可确保部分填充的组仍分配所需的完整组大小。 

第三个重要的边缘情况是只有一只兔子给出非常大的答案，例如`[999]`。 尽管我们只观察到一只兔子，但那只兔子声称还有 999 只其他相同颜色的兔子。 该实现正确地创建了一个完整的大小组`1000`，确保与兔子的陈述一致。
