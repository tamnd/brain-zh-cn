 ## 解决方案

 ## 问题理解

 该问题要求我们计算给定列表中有多少单词是字符串的子序列`s`。 **子序列**是通过从字符串中删除零个或多个字符而不改变剩余字符的顺序而形成的。 例如，`"ace"`是一个子序列`"abcde"`因为我们可以删除`"b"`和`"d"`并保留`"a"`,`"c"`,`"e"`以正确的顺序。 

输入是：

 1.`s`- 长度可达的字符串`50,000`，仅包含小写字母。 
2.`words`- 字符串列表，每个字符串的长度不超过`50`，列表最多可以有`5,000`字。 

预期输出是字符串的数量`words`是的子序列`s`。 

关键约束建议逐个字符检查每个单词`s`（天真地）可能太慢，因为迭代`50,000`字符为`5,000`词是潜在的`250 million`运营。 我们需要一种减少重复扫描的方法`s`。 

重要的边缘情况包括空词、长于`s`，包含不存在于中的字符的单词`s`，以及重复的单词`words`。 

## 方法

 **暴力方法**是检查中的每个单词`words`看看它是否是一个子序列`s`通过迭代`s`并按顺序匹配字符。 这保证了正确性，但速度太慢，因为对于每个长度的单词`m`，我们可以扫描到`n`的字符`s`。 时间复杂度大致为`O(n * m * len(words))`，可以达到`O(50,000 * 50 * 5,000)`在最坏的情况下，这是不切实际的。 

**最佳方法**使用我们可以预处理的洞察力`s`以加快后续检查速度。 一种有效的策略是**按照他们正在等待的角色对单词进行存储**。 本质上，对于每个角色`s`，我们维护等待该字符的单词的迭代器列表。 当一个角色出现在`s`，我们推进所有相应的迭代器。 这样就可以避免扫描`s`每个词都重复一遍。 

这种方法将问题转化为线性扫描`s`具有高效的单词进度跟踪。 每个单词中的每个字符都被处理一次，从而提供更快的解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * m * k) | O(n * m * k) | O(1) | O(1) | 检查每个单词`s`依次； 对于大输入来说太慢|
 | 最优（迭代器桶）| O(n + 单词总数) | O(单词总数) | 使用队列跟踪每个单词等待下一个字符的进度 |

 ## 算法演练

 1. 初始化一个名为的字典（或列表数组）`waiting`映射每个字符`'a'`到`'z'`到迭代器列表。 每个迭代器对应一个等待其下一个字符出现的单词`s`。 
2. 填充`waiting`通过迭代中的每个单词`words`。 对于每个单词，获取其第一个字符并附加一个迭代器（或索引）来跟踪该单词的位置到相应的存储桶中`waiting`。 
3. 初始化计数器`count`为零。 这将跟踪有多少单词已完全匹配。 
4. 迭代每个字符`c`在`s`。 对于每个字符：

 1. 检索等待的迭代器列表`c`并将该存储桶重置为空。 
2. 对于列表中的每个迭代器：

 1. 前进到单词中的下一个字符。 
2.如果有下一个字符，则将其追加到对应的bucket中`waiting`。 
3. 如果没有下一个字符，则递增`count`因为这个词是完全匹配的。 
5. 返回`count`。 

**为什么有效：** 每个单词仅在遇到其预期字符时才会被处理`s`。 每个单词的每个字符只被考虑一次，因此所有子序列都被正确计数，而无需冗余扫描`s`。 

## Python 解决方案```python
from collections import defaultdict, deque
from typing import List

class Solution:
    def numMatchingSubseq(self, s: str, words: List[str]) -> int:
        waiting = defaultdict(deque)
        for word in words:
            waiting[word[0]].append(iter(word[1:]))
        
        count = 0
        for char in s:
            current_waiting = waiting[char]
            waiting[char] = deque()
            while current_waiting:
                it = current_waiting.popleft()
                nxt = next(it, None)
                if nxt is None:
                    count += 1
                else:
                    waiting[nxt].append(it)
        return count
```此实现首先创建从字符到等待该字符的单词迭代器的映射。 当我们扫描时`s`，我们推进迭代器。 如果迭代器没有下一个字符，我们将增加计数。 使用`deque`确保高效的从左侧弹出和追加操作。 

## 解决方案```go
package main

func numMatchingSubseq(s string, words []string) int {
	waiting := make(map[byte][]*WordIterator)
	for _, word := range words {
		it := &WordIterator{word: word, index: 1}
		waiting[word[0]] = append(waiting[word[0]], it)
	}

	count := 0
	for i := 0; i < len(s); i++ {
		c := s[i]
		current := waiting[c]
		waiting[c] = []*WordIterator{}
		for _, it := range current {
			if it.index == len(it.word) {
				count++
			} else {
				waiting[it.word[it.index]] = append(waiting[it.word[it.index]], &WordIterator{word: it.word, index: it.index + 1})
			}
		}
	}
	return count
}

type WordIterator struct {
	word  string
	index int
}
```在 Go 中，我们使用包含单词和要检查的下一个索引的结构来模拟迭代器。 这允许与 Python 迭代器类似的行为。 Go 切片用于队列，我们​​仔细管理索引以避免越界错误。

 ## 边缘情况

 一种边缘情况是当`s`是空的。 在这种情况下，任何非空字都不能成为子序列，算法会正确返回 0。 

另一个边缘情况是空字符串`words`。 根据子序列的定义，空字符串是任意字符串的子序列。 该算法会处理此问题，因为长度为 0 的迭代器会立即计入计数。 

第三种边缘情况涉及重复的字符或单词长于`s`。 该算法正确地跳过无法匹配的单词，因为迭代器永远不会完成，并且重复的字符`s`帮助
