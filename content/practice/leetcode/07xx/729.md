 **难度：** 🟡 中等
 **主题：** 数组、二分搜索、设计、线段树、有序集

 ## 解决方案

 ## 问题理解

 该问题要求我们设计一个日历系统，支持预订事件而不允许间隔重叠。 

每个事件都表示为半开区间`[startTime, endTime)`。 这意味着该活动包括`startTime`，但不包括`endTime`。 例如，间隔`[10, 20)`包含所有时间从`10`最多但不包括`20`。 

这种区别非常重要，因为以下两个事件`[10, 20)`和`[20, 30)`不要重叠。 第一个事件恰好在第二个事件开始的地方结束，因此它们都被允许。 

我们必须实现一个名为`MyCalendar`有两个操作：

 - 构造函数初始化日历。 
- 这`book(startTime, endTime)`方法尝试插入一个新事件。 

这`book`方法应该：

 - 返回`true`如果新活动不与任何先前预订的活动重叠。 
- 返回`false`如果新活动会造成重复预订。 
- 预订失败时保持日历不变。 

这些约束告诉我们一些重要的事情：

 -`0 <= start < end <= 10^9`- 至多`1000`打电话给`book`可能的时间值很大意味着我们无法创建按时间索引的时间线数组。 在该时间范围内进行直接模拟是不可能的。 

不过操作次数比较少，最多只有`1000`。 这意味着即使是`O(n)`每个预订的扫描是可以接受的，因为总工作量约为`1,000,000`最坏情况下的比较。 

最重要的边缘情况是：

 - 触及边界的事件，例如`[10, 20)`和`[20, 30)`，这是有效的。 
- 事件完全包含在另一个事件中。 
- 完全包含另一个事件的事件。 
- 附近非常大的时间值`10^9`。 
- 预订到空日历。 

正确理解区间重叠是解决问题的关键。 

## 方法

 ### 蛮力方法

 最简单的解决方案是将每个成功的预订存储在列表中。 每当收到新的预订请求时，我们都会将其与每个现有活动进行比较。 

如果满足以下条件，则两个区间重叠：```
start < existingEnd AND end > existingStart
```这一条件意味着间隔至少共享一个时刻。 

如果发现任何重叠，我们立即返回`false`。 否则，在检查所有现有预订后，我们添加新的间隔并返回`true`。 

这种方法是正确的，因为之前接受的每个预订都会单独检查。 如果没有与新活动重叠，则预订是安全的。 

虽然这个解决方案在技术上是蛮力的，但对于问题约束来说它已经足够快了，因为最多只有`1000`预订。 

### 更好的有序方法

 更优化的方法使事件按开始时间排序。 一旦对间隔进行排序，我们就不需要与每个事件进行比较。 

关键的观察是，在排序列表中，只有相邻间隔可以与新插入的间隔重叠。 

假设我们插入`[start, end)`转化为排序结构：

 - 前一个间隔必须在之前结束`start`- 下一个间隔必须在之后开始`end`如果这两个条件都成立，则其他地方不存在重叠。 

这减少了不必要的比较，并使解决方案更具可扩展性。 在具有平衡树或有序集的语言中，可以有效地执行插入和查找。 

对于 LeetCode 729，两种方法都可以顺利通过，但有序方法展示了更强的设计原则。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 每次预订 O(n) | O(n) | 与每个现有区间进行比较 |
 | 最佳| O(log n) 搜索 + O(n) 插入 | O(n) | 按排序顺序维护间隔 |

 ## 算法演练

 我们将使用按开始时间排序的间隔排序列表。 

### 第 1 步：按排序顺序存储间隔

 我们维护一个列表，其中每个间隔都按其开始时间排序。 

这种排序使我们能够有效地找到应插入新间隔的位置。 

### 第2步：找到插入位置

 预订时`[startTime, endTime)`，我们使用二分查找来确定区间属于排序列表中的位置。 

插入索引告诉我们：

 - 该索引之前的所有间隔都较早开始。 
- 该索引之后的所有间隔稍后开始。 

### 步骤 3：检查之前的时间间隔

 如果插入位置之前有一个间隔，我们检查它是否重叠。 

重叠条件为：```
previousEnd > startTime
```如果为 true，则预订失败。 

### 步骤 4：检查下一个间隔

 如果插入位置之后有一个间隔，我们检查：```
endTime > nextStart
```如果为 true，则预订会重叠并失败。 

### 步骤 5：插入间隔

 如果相邻区间都不重叠，则将该区间插入到排序列表中并返回`true`。 

### 为什么它有效

 由于间隔按排序顺序存储，因此任何重叠只能发生在插入位置周围的相邻间隔上。 

如果上一个间隔在新间隔开始之前结束，并且下一个间隔在新间隔结束之后开始，则由于排序顺序，每个其他间隔都会自动不重叠。 

这个不变量保证了正确性。 

## Python 解决方案```python
from bisect import bisect_left
from typing import List, Tuple

class MyCalendar:

    def __init__(self):
        self.events: List[Tuple[int, int]] = []

    def book(self, startTime: int, endTime: int) -> bool:
        index = bisect_left(self.events, (startTime, endTime))

        # Check previous interval
        if index > 0 and self.events[index - 1][1] > startTime:
            return False

        # Check next interval
        if index < len(self.events) and self.events[index][0] < endTime:
            return False

        self.events.insert(index, (startTime, endTime))
        return True
```该实现维护一个名为的排序列表`events`。 

这`bisect_left`函数执行二分搜索以找到新区间的正确插入索引。 由于在 Python 中元组是按字典顺序比较的，因此间隔自然是按其开始时间排序的。 

找到插入位置后，算法仅检查相邻间隔：

 - 前一个间隔可能会从左侧重叠。 
- 下一个间隔可能会从右侧重叠。 

如果不存在重叠，则将间隔插入到正确的位置，同时保留排序顺序。 

该解决方案直接遵循算法演练，有效避免扫描整个列表。 

## 解决方案```go
package main

import "sort"

type MyCalendar struct {
	events [][2]int
}

func Constructor() MyCalendar {
	return MyCalendar{
		events: make([][2]int, 0),
	}
}

func (this *MyCalendar) Book(startTime int, endTime int) bool {

	index := sort.Search(len(this.events), func(i int) bool {
		return this.events[i][0] >= startTime
	})

	// Check previous interval
	if index > 0 && this.events[index-1][1] > startTime {
		return false
	}

	// Check next interval
	if index < len(this.events) && this.events[index][0] < endTime {
		return false
	}

	this.events = append(this.events, [2]int{})

	copy(this.events[index+1:], this.events[index:])

	this.events[index] = [2]int{startTime, endTime}

	return true
}
```Go 解决方案遵循与 Python 实现相同的逻辑，但使用 Go 特定的构造。`sort.Search`执行二分查找来查找插入索引。 

由于Go切片不支持直接插入，我们首先使用以下命令扩展切片`append`，使用移位元素`copy`，然后将新的间隔放置在插入位置。 

Go 整数安全地处理约束范围，因为`10^9`符合标准`int`在 LeetCode 平台上输入。

 ## 边缘情况

 ### 边界接触区间

 最常见的错误之一是不正确地对待`[10, 20)`和`[20, 30)`作为重叠。 

由于区间是半开的，所以该值`20`只属于第二个区间。 实现通过检查正确处理此问题：```
previousEnd > startTime
```而不是：```
previousEnd >= startTime
```这种微妙的区别确保允许相邻的间隔。 

### 完全收容

 预订可能完全在另一个区间内，例如预订`[15, 20)`后`[10, 30)`已经存在。 

仅检查匹配开始时间的幼稚实现可能会错过这种情况。 重叠条件可以正确识别遏制，因为：```
30 > 15
```哪个信号正确重叠。 

### 在开头或结尾插入

 在排序列表的开头或末尾插入新区间时，不存在相邻区间。 

如果不仔细处理边界条件，这很容易导致索引越界错误。 

实现明确检查：```
if index > 0
```在访问上一个间隔之前，并且：```
if index < len(self.events)
```在访问下一个间隔之前。 

这保证了边缘插入的安全处理。
