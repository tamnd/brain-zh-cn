[LeetCode 第 778 题](https://leetcode.com/problems/swim-in-rising-water/)

 **难度：** 🔴难
 **主题：** 数组、二分搜索、深度优先搜索、广度优先搜索、联合查找、堆（优先级队列）、矩阵

 ## 解决方案

 ## 问题理解

 在这个问题中，我们给出了一个`n x n`网格，其中每个单元格包含代表其海拔的唯一整数。 雨开始下，水位随着时间的推移而上升。 随时`t`，您可以站在或穿过任何标高小于或等于的单元格`t`。 

你从左上角开始`(0, 0)`并想要到达右下角`(n - 1, n - 1)`。 只允许在四个基本方向上移动：上、下、左、右。 

重要的细节是运动本身不需要时间。 唯一重要的是当前的水位是否足够高，可以开辟一条道路。 因此，问题就变成：

 > 使得从起点到目的地存在连通路径的最小海拔阈值是多少？ 

输入是方阵，具有以下保证：

 -`1 <= n <= 50`，所以网格比较小。 
- 每个海拔值都是唯一的。 
- 海拔范围从`0`到`n^2 - 1`。 

唯一性保证很有用，因为它意味着标高形成严格的顺序。 没有两个单元同时可用。 

一些边缘情况很重要：

 - A`1 x 1`网格意味着起点已经是目的地。 
- 目的地可能需要等待非常大的海拔值。 
- 步数越少的路径不一定越好，因为答案取决于路径上的最大海拔，而不是路径长度。 
- 向较小相邻值的贪婪移动可能会失败，因为局部最优选择可能会导致稍后不可避免的大幅提升。 

关键的挑战是最小化沿有效路径遇到的最大海拔。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是模拟时间`0`向上并反复检查是否可达目的地。 

对于每一次`t`:

 1. 对所有单元格进行抬高处理`<= t`作为可遍历的。 
2. 运行 BFS 或 DFS`(0, 0)`。 
3. 如果可以到达目的地，则返回`t`。 

这是有效的，因为最终所有单元都会被淹没，从而保证可达性。 

然而，这种方法效率低下，因为我们可能会多次运行完整的图遍历。 由于海拔范围可达`n^2 - 1`，我们可能会执行`O(n^2)`搜索，每次成本`O(n^2)`。 

这导致总复杂度为`O(n^4)`，这是不必要的昂贵。 

### 关键见解

 重要的观察结果是，答案由沿所选路径遇到的最大海拔确定。 

假设我们穿过一条最高海拔为`k`。 然后：

 - 我们无法在时间之前走过这条路`k`。 
- 时间`k`，整个路径变得可用。 

那么问题就变成了：

 > 找到一条从起点到目的地的路径，使路径上的最大像元值最小化。 

这与 Dijkstra 算法极其相似。 

在标准 Dijkstra 中，路径成本是边权重之和。 在这里，路径成本是：```
maximum elevation seen so far
```我们总是希望扩展当前最佳可达状态，即迄今为止遇到的最大海拔最小的状态。 

最小堆非常适合于此。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n^4) | O(n^4) | O(n^2) | O(n^2) | 尝试每个时间值并运行 BFS/DFS |

 ## 算法演练

 ### 最优算法，Dijkstra 与最小堆

 1. 创建一个最小堆并插入起始单元`(0, 0)`。 

堆存储：

 - 到达此单元格所需的当前最大海拔高度
 - 行索引
 - 列索引

 最初，所需的时间很简单`grid[0][0]`。 
2. 维持`visited`集合或矩阵。 

一旦使用尽可能小的最大高程处理像元，我们就不需要重新访问它。 
3. 反复从堆中删除最小的元素。 

这为我们提供了当前可到达的位置以及所需的最低水位。 
4. 如果弹出的单元格是目的地，则返回其关联的高程值。 

因为我们总是按照所需时间的递增顺序处理状态，所以我们第一次到达目的地的时间保证是最佳的。 
5. 探索四个相邻的单元格。 

对于每个有效邻居：

 - 计算新的所需时间：```
max(current_time, neighbor_elevation)
```这代表沿途遇到的最高海拔。 
6. 将未访问的邻居推入堆中。 

即使邻居本身较低，由于较早的小区，路径可能已经需要更大的标高。 
7. 继续前进，直至到达目的地。 

### 为什么它有效

 该算法保持不变，即当一个单元从最小堆中删除时，我们已经找到了到达它所需的最小可能的最大海拔。 

这与 Dijkstra 算法中使用的正确性原理相同。 由于堆顺序保证首先处理成本较低的路径，因此我们第一次到达目的地时必须对应于全局最小最大海拔。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def swimInWater(self, grid: List[List[int]]) -> int:
        n = len(grid)

        directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

        min_heap = [(grid[0][0], 0, 0)]

        visited = [[False] * n for _ in range(n)]
        visited[0][0] = True

        while min_heap:
            current_time, row, col = heapq.heappop(min_heap)

            if row == n - 1 and col == n - 1:
                return current_time

            for dr, dc in directions:
                new_row = row + dr
                new_col = col + dc

                if (
                    0 <= new_row < n
                    and 0 <= new_col < n
                    and not visited[new_row][new_col]
                ):
                    visited[new_row][new_col] = True

                    next_time = max(
                        current_time,
                        grid[new_row][new_col]
                    )

                    heapq.heappush(
                        min_heap,
                        (next_time, new_row, new_col)
                    )

        return -1
```实现首先用起始单元初始化最小堆。 堆总是优先考虑需要最小水位的位置。 

这`visited`基质可防止不必要地重新访问细胞。 由于 Dijkstra 在第一次处理节点时保证了最优性，因此不需要重新访问。 

在主循环内，我们反复从堆中提取最佳候选者。 如果到达目的地，我们会立即返回相关时间，因为它保证是最短的。 

对于每个相邻单元格，我们使用以下方法计算新的路径成本：```python
max(current_time, grid[new_row][new_col])
```这捕获了迄今为止沿路径遇到的最高海拔。 

该算法继续按所需海拔的升序扩展状态，直到找到目的地。 

## 解决方案```go
package main

import (
	"container/heap"
)

type State struct {
	time int
	row  int
	col  int
}

type MinHeap []State

func (h MinHeap) Len() int {
	return len(h)
}

func (h MinHeap) Less(i, j int) bool {
	return h[i].time < h[j].time
}

func (h MinHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MinHeap) Push(x interface{}) {
	*h = append(*h, x.(State))
}

func (h *MinHeap) Pop() interface{} {
	old := *h
	n := len(old)

	item := old[n-1]

	*h = old[:n-1]

	return item
}

func swimInWater(grid [][]int) int {
	n := len(grid)

	directions := [][]int{
		{1, 0},
		{-1, 0},
		{0, 1},
		{0, -1},
	}

	visited := make([][]bool, n)

	for i := 0; i < n; i++ {
		visited[i] = make([]bool, n)
	}

	minHeap := &MinHeap{}
	heap.Init(minHeap)

	heap.Push(minHeap, State{
		time: grid[0][0],
		row:  0,
		col:  0,
	})

	visited[0][0] = true

	for minHeap.Len() > 0 {
		current := heap.Pop(minHeap).(State)

		if current.row == n-1 && current.col == n-1 {
			return current.time
		}

		for _, dir := range directions {
			newRow := current.row + dir[0]
			newCol := current.col + dir[1]

			if newRow >= 0 &&
				newRow < n &&
				newCol >= 0 &&
				newCol < n &&
				!visited[newRow][newCol] {

				visited[newRow][newCol] = true

				nextTime := current.time

				if grid[newRow][newCol] > nextTime {
					nextTime = grid[newRow][newCol]
				}

				heap.Push(minHeap, State{
					time: nextTime,
					row:  newRow,
					col:  newCol,
				})
			}
		}
	}

	return -1
}
```Go 的实现与 Python 解决方案非常相似。 由于 Go 没有提供内置的优先级队列，我们​​使用`container/heap`包裹。 

这`State`struct 存储当前所需的时间和坐标。 习俗`MinHeap`类型通过所需的接口方法定义堆行为。 

Go 切片用于`visited`矩阵和方向向量。 整数溢出不是问题，因为所有高程值都受以下限制`n^2`，这最多是`2500`。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n^2 log n) | O(n^2 log n) | 每个cell进入堆一次，堆操作成本`log(n^2)`|
 | 空间| O(n^2) | O(n^2) | 堆和访问矩阵最多存储所有单元 |

 网格包含`n^2`细胞。 每个单元最多被插入到堆中一次，因为我们在推送单元时标记了立即访问的单元。 

堆操作需要`O(log(n^2))`，这简化为`O(log n)`。 

因此，总复杂度变为：```
O(n^2 log n)
```空间复杂度主要由堆和访问矩阵决定。

    def swimInWater(self, grid: List[List[int]]) -> int:
        import heapq

        n = len(grid)

        heap = [(grid[0][0], 0, 0)]

        visited = [[False] * n for _ in range(n)]
        visited[0][0] = True

        directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

        while heap:
            time, row, col = heapq.heappop(heap)

            if row == n - 1 and col == n - 1:

            for dr, dc in directions:

                    0 <= nr < n

                    heapq.heappush(
                        heap,
                        (
                            max(time, grid[nr][nc]),
                            nr,
                            nc
                        )
                    )

        return -1

 ## 边缘情况

 一个重要的边缘情况是`1 x 1`网格。 在这种情况下，起始位置已经是目的地。 有缺陷的实现可能仍然会尝试不必要的遍历逻辑，或者由于缺少邻居而失败。 提供的实现自然地处理了这个问题，因为第一个堆弹出立即满足目标条件。 

当起始单元本身具有非常大的高程时，会发生另一个重要情况。 由于您开始站在该单元上，因此水位必须至少达到该高度才能进行任何移动。 一些不正确的解决方案忘记在最大高程计算中包含起始单元格。 我们的实现初始化堆`grid[0][0]`，保证正确性。 

当最短几何路径不是最佳路径时，就会发生第三种棘手的情况。 由于目标是最小化所遇到的最大海拔，因此如果可以避免大的海拔峰值，较长的路线可能仍然更好。 单独的广度优先搜索在这里会失败，因为 BFS 最小化了步数，而不是路径成本。 使用按所需标高排序的最小堆可确保算法始终优先考虑更安全的路径，而不是更短的路径。
