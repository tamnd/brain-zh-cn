[LeetCode 第 769 题](https://leetcode.com/problems/max-chunks-to-make-sorted/)

 **难度：** 🟡 中等
 **主题：** 数组、堆栈、贪婪、排序、单调堆栈

 ## 解决方案

 ## 问题理解

 这个问题要求我们确定可以将数组分割成的连续**块**的最大数量，以便对每个块进行单独排序并将它们连接起来得到一个完全排序的数组。 输入数组`arr`是整数的排列`0`到`n-1`，这意味着它只包含每个整数一次。 输出是一个整数，表示在此约束下可能存在的最大块数。 

需要注意的要点是数组元素是唯一的，值直接对应于它们在排序数组中的位置，以及数组长度`n`很小（最多 10 个）。 这些约束意味着我们可以依靠元素索引来推断分割是否有效，并且我们可以考虑迭代数组的方法，而不必担心过多的计算成本。 

需要注意的边缘情况包括已经排序的数组（每个元素可能是其自己的块）、按相反顺序排序的数组（可能只有一个块）以及具有单个元素的最小数组（通常是一个块）。 

## 方法

 **暴力方法**将尝试将数组的每个可能的分区分成块，单独对每个块进行排序，连接排序后的块，并检查结果是否等于排序后的数组。 这保证了正确性，因为它详尽地检查了所有可能的组合。 然而，这种方法的速度呈指数级缓慢，分区可能性的时间复杂度为 O(2^n)，并且排序有额外的开销，因此即使对于中等值也不切实际。`n`。 

**最佳方法**依赖于一个关键观察：当数组当前前缀中遇到的最大值等于该前缀的最后一个索引时，就会出现有效的分割点。 正式来说，如果`max(arr[0..i]) == i`，那么我们可以在索引之后进行分割`i`。 这是有效的，因为该数组包含来自的所有整数`0`到`n-1`。 当满足此条件时，当前块中的所有值正是排序到该位置所需的值，从而确保正确性。 我们可以使用简单的前缀最大值计算一次性解决该问题。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n * n log n) | O(2^n * n log n) | O(n) | 生成所有分区，对每个分区进行排序，检查连接 |
 | 最佳| O(n) | O(1) | O(1) | 单通道，轨道前缀最大值，当最大值等于索引时分割 |

 ## 算法演练

 1. 初始化变量`max_seen`跟踪迄今为止在数组中遇到的最大值和计数器`chunks`计算有效块。 
2. 从第一个元素到最后一个元素迭代数组。 
3. 对于每个元素`arr[i]`， 更新`max_seen`成为最大的`max_seen`和`arr[i]`。 
4. 如果`max_seen`等于当前索引`i`，增加`chunks`柜台。 这表明所有数字达到`i`正是应该占据排序数组的这部分的数字，因此我们可以在这里安全地拆分。 
5. 遍历数组后，返回总计`chunks`数数。 

**为什么它有效：** 关键的不变量是当`max_seen == i`，当前段包含连续范围内的所有整数`[0..i]`。 本地排序该段会将所有数字放置在正确的最终位置，确保正确性。 贪婪方法之所以有效，是因为我们仅在前缀按排序顺序自包含时才进行拆分，这会最大化块的数量。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxChunksToSorted(self, arr: List[int]) -> int:
        max_seen = 0
        chunks = 0
        for i, val in enumerate(arr):
            max_seen = max(max_seen, val)
            if max_seen == i:
                chunks += 1
        return chunks
```在这个实现中，`max_seen`跟踪迄今为止在数组中看到的最高值。 当我们遍历数组时，每当`max_seen`匹配当前索引`i`，这意味着该段中的所有元素正是形成排序子数组所需的元素，因此我们增加块计数。 这与算法演练完全匹配。 

## 解决方案```go
func maxChunksToSorted(arr []int) int {
    maxSeen := 0
    chunks := 0
    for i, val := range arr {
        if val > maxSeen {
            maxSeen = val
        }
        if maxSeen == i {
            chunks++
        }
    }
    return chunks
}
```在 Go 中，我们同样跟踪`maxSeen`并迭代使用`range`。 由于Go没有内置的`max`对于整数函数，我们使用简单的比较。 除此之外，逻辑与 Python 相同，并且切片无缝处理数组访问。

 ## 边缘情况

 第一个重要的边缘情况是单元素数组。 由于数组仅包含一个数字，因此算法通过检查正确地将其识别为一个块`max_seen == i`。 

第二个边缘情况是完全排序的数组。 每个元素都可以是自己的块，我们的前缀最大逻辑自然会递增`chunks`在每个索引处，因为`max_seen`将永远相等`i`。 

第三种边缘情况是反向排序数组，其中直到最后一个元素为止中间分割都是有效的。 该算法正确累加最大值而不增加`chunks`直到最后，产生一个块。 这确保了贪婪方法不会过早错误地分裂。
