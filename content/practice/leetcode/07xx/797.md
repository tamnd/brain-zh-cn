[LeetCode 第 797 题](https://leetcode.com/problems/all-paths-from-source-to-target/)

 **难度：** 🟡 中等
 **主题：** 回溯、深度优先搜索、广度优先搜索、图论

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个有向无环图，通常缩写为 DAG。 该图包含`n`节点标记为`0`到`n - 1`。 该图表示为邻接列表，其中`graph[i]`包含从节点可以直接到达的所有节点`i`。 

我们的任务是找到从节点开始的每条可能的路径`0`并在节点处结束`n - 1`。 每个路径应表示为节点值列表，最终答案是包含所有有效路径的列表。 

例如，如果图表是：```
0 -> 1 -> 3
 \-> 2 -> 3
```那么有效路径来自`0`到`3`是：```
[[0, 1, 3], [0, 2, 3]]
```该图保证是 DAG，这一点极其重要。 DAG 不包含循环，这意味着我们在向前遍历时永远无法无限地重新访问同一节点。 这种保证使我们能够安全地执行深度优先遍历，而不需要循环检测逻辑。 

限制相对较小：

 -`2 <= n <= 15`即使节点数量很少，可能的路径数量仍然可以呈指数增长。 在 DAG 中，许多不同的边组合可以创建许多有效的源到目标路径。 

来自约束的重要观察结果是：

 - 该图是有向的。 
- 该图没有循环。 
- 我们必须返回所有有效路径，而不仅仅是计算它们。 
- 答案大小本身可能是指数级的。 

有几种边缘情况值得考虑：

 - 从源到目标只有一条路径的图表。 
- 源直接连接到目标的图表。 
- 具有大量分支的图，产生许多有效路径。 
- 中间节点除了沿着有效路径之外没有传出边的图。 
- 由于图保证是 DAG，因此我们永远不需要处理由循环引起的无限递归。 

## 方法

 ### 蛮力方法

 最直接的想法是生成从节点开始的所有可能的路径`0`。 在每个节点，我们尝试每个传出边并继续递归，直到到达目标节点或用完边。 

这种蛮力的想法已经类似于深度优先搜索，因为我们必须探索每一条可能的路线。 由于问题明确要求所有路径，因此我们无法避免探索所有有效组合。 

幼稚的实现可能会在每次递归调用时重复复制整个路径，从而产生不必要的开销。 它还可能使用低效的遍历结构，从而增加内存使用量。 

暴力方法是正确的，因为从源开始的每条路径都是递归探索的，并且每次到达目标节点时我们都会记录当前路径。 

然而，DAG 中的路径总数可能是指数级的。 在最坏的情况下，我们可能需要枚举大量的有效路径。 

### 最佳解决方案的关键见解

 关键的见解是这个问题自然适合带有回溯的递归深度优先搜索。 

为什么？ 

因为每条路径都是增量构建的：

 - 从节点开始`0`- 选择一个邻居
 - 继续探索
 - 返回时撤消选择

 这与回溯模式完全匹配。 

由于该图是 DAG：

 - 我们从不重新访问循环中的节点
 - 递归DFS是安全的
 - 每个递归调用代表一个部分路径

 最佳解决方案在遍历期间维持单个可变路径。 我们不是在每一步都创建一个新的路径对象，而是：

 1.在当前路径添加节点
 2. 递归探索
 3.之后删除该节点

 这可以最大限度地减少不必要的复制，同时仍然正确生成所有有效路径。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n * n) | O(2^n * n) | O(2^n * n) | O(2^n * n) | 通过过多的路径复制生成所有可能的路径 |
 | 最优DFS+回溯| O(2^n * n) | O(2^n * n) | O(n) 不包括输出 | 带回溯的高效递归遍历 |

 输出本身可能包含指数级多的路径，因此没有算法可以从根本上避免最坏情况下的指数级工作。 

## 算法演练

 ### 最优DFS+回溯算法

 1. 初始化一个空结果列表，该列表将存储从源到目标的所有有效路径。 
2. 创建一个递归 DFS 函数，该函数接受：

 - 当前节点
 - 当前正在探索的路径
 3.从节点开始遍历`0`与初始路径`[0]`。 
4、DFS函数内部，首先检查当前节点是否为目标节点`n - 1`。 

如果是：

 - 将当前路径的副本附加到结果列表中。 
- 立即返回，因为此路径已完成。 
5. 否则，迭代当前节点的所有邻居。 
6. 对于每个邻居：

 - 将邻居添加到当前路径。 
- 从该邻居递归地继续 DFS。 
- 递归完成后，从路径中删除邻居。 

该删除步骤就是回溯步骤。 它将路径恢复到之前的状态，以便可以独立探索下一个邻居。 
7. 继续直到所有递归调用完成。 
8. 返回包含所有已发现路径的结果列表。 

### 为什么它有效

 该算法保持不变式`path`始终表示从源到当前 DFS 节点的确切节点序列。 

因为图是非循环的，所以递归遍历永远不可能无限循环。 从源到目标的每个可能的定向路径都被恰好探索一次。 每当遍历到达目标节点时，当前路径就是有效解并添加到结果中。 

回溯可确保在探索一个分支之后，在探索下一个分支之前正确恢复路径状态。 

## Python 解决方案```python
from typing import List

class Solution:
    def allPathsSourceTarget(self, graph: List[List[int]]) -> List[List[int]]:
        target = len(graph) - 1
        result = []

        def dfs(node: int, path: List[int]) -> None:
            if node == target:
                result.append(path[:])
                return

            for neighbor in graph[node]:
                path.append(neighbor)
                dfs(neighbor, path)
                path.pop()

        dfs(0, [0])

        return result
```实现从识别目标节点开始，目标节点始终是`n - 1`。 

这`result`list 存储遍历过程中发现的所有有效路径。 

递归`dfs`函数执行核心遍历逻辑。 这`path`变量包含当前从源到当前节点的遍历路线。 

当当前节点等于目标时，我们将当前路径的副本附加到结果列表中。 我们使用`path[:]`因为`path`是可变的，并且在回溯期间将继续变化。 

循环结束`graph[node]`探索每一个传出的边缘。 在递归之前，邻居被附加到路径中。 递归完成后，使用以下命令删除邻居`pop()`。 

这种追加-递归-弹出模式是标准的回溯结构。 

最后DFS从node开始`0`与初始路径`[0]`。 

## 解决方案```go
func allPathsSourceTarget(graph [][]int) [][]int {
	target := len(graph) - 1
	result := [][]int{}

	var dfs func(int, []int)

	dfs = func(node int, path []int) {
		if node == target {
			pathCopy := make([]int, len(path))
			copy(pathCopy, path)
			result = append(result, pathCopy)
			return
		}

		for _, neighbor := range graph[node] {
			path = append(path, neighbor)
			dfs(neighbor, path)
			path = path[:len(path)-1]
		}
	}

	dfs(0, []int{0})

	return result
}
```Go 实现遵循与 Python 版本相同的递归 DFS 和回溯策略。 

Go 特有的一个重要细节是切片复制。 Go 中的切片共享底层数组，因此我们必须在将完整路径附加到之前显式创建一个新切片`result`。 这是使用以下方法完成的：```go
pathCopy := make([]int, len(path))
copy(pathCopy, path)
```如果没有此副本，回溯期间的后续修改将改变先前存储的路径。 

Go 切片会动态调整大小，使其适合维护当前的遍历路径。 

由于节点值是小整数并且约束也很小，因此整数溢出不是问题。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(2^n * n) | O(2^n * n) | 路径数量可能是指数级的，每个路径复制成本为 O(n) |
 | 空间| O(n) 不包括输出 | 递归堆栈和当前路径长度以 n | 为界

 主导因素是 DAG 中有效路径的数量。 在最坏的情况下，DAG 可以包含指数级数量的源到目标路径。 

每个有效路径最终都必须复制到结果数组中，并且每次复制的成本与路径长度成正比。 因此，总运行时间变为：```
(number of paths) * (average path length)
```递归堆栈深度最多为`n`，因为该图是非循环的，并且任何节点都不能在单个路径中出现两次。 

输出存储本身不包含在辅助空间复杂度中，因为它是问题所需要的。

 ## 边缘情况

 ### 从源到目标的直接连接

 图可能包含来自节点的直接边`0`到节点`n - 1`。 

例子：```
[[1], []]
```如果算法假设至少存在一个中间节点，则很容易处理错误。 该实现自然地处理了这个问题，因为 DFS 立即到达目标并记录路径。 

### 只有一条有效路径的图

 一些 DAG 形成一个简单的链：```
0 -> 1 -> 2 -> 3
```根本没有分支。 有缺陷的实现可能会错误地依赖多个递归分支或错误处理路径复制。 递归 DFS 仍然可以正常工作，因为每个节点只有一个传出邻居。 

### 重分支产生许多路径

 DAG 可以包含许多重叠的分支，导致有效路径的数量呈指数增长。 

这既强调正确性又强调回溯行为。 如果递归后路径未正确恢复，路径可能会损坏或包含额外的节点。 

该实现通过始终使用以下方式来避免此问题：```
path.append(neighbor)
dfs(neighbor, path)
path.pop()
```这保证了每次递归探索后路径状态都能正确恢复。
