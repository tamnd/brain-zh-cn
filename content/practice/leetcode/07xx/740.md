[LeetCode 第 740 题](https://leetcode.com/problems/delete-and-earn/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、动态规划

 ## 解决方案

 ## 问题理解

 问题给了我们一个整数数组`nums`，并且我们希望通过重复删除元素来最大化获得的总点数。 

当我们删除一个号码时`x`，我们获得`x`点。 然而，删除`x`还强制删除所有出现的`x - 1`和`x + 1`。 这一限制是问题的核心挑战，因为选择一个值会阻止我们选择其相邻值。 

重要的细节是，删除单个数字不仅会影响一个相邻元素。 它全局删除相邻值的所有实例。 因此，删除的顺序并不重要，重要的是决定我们最终保留哪些值。 

例如，如果数组包含多个`3`s，然后取`3`多次可能比服用更好`2`沙`4`结合起来。 问题变成了相邻值之间的权衡。 

输入包括：

 - 整数数组`nums`- 每个值都介于`1`和`10^4`- 数组长度可以大到`2 * 10^4`输出是一个整数，表示可获得的最大点数。 

这些约束很重要，因为它们排除了指数解。 对所有删除组合的强力搜索很快就会变得不可行。 由于值范围限制为`10^4`，这表明按值对数字进行分组可能有用。 

一些边缘情况很重要：

 - 仅包含一个不同值的数组
 - 所有值都是连续的数组
 - 值之间差距较大的数组
 - 具有许多重复项的数组
 - 非常小的数组，例如长度`1`幼稚的实现可能会重复修改数组或递归地尝试每个可能的删除序列，这将非常慢。 

## 方法

 ### 蛮力方法

 暴力解决方案会尝试所有可能的删除顺序。 

在每一步中，我们都可以选择任何剩余的数字，获取其值，删除相邻值的所有实例，并递归计算未来可能的最佳分数。 然后我们会在所有选择中取最大值。 

这种方法是正确的，因为它探索了每个有效的操作序列。 最终，它找到了最佳的一个。 

然而，它太慢了。 可能状态的数量呈指数增长，因为每个不同的值都会产生分支选择。 即使有记忆，跟踪所有可能的剩余集合也会变得昂贵。 

这些限制使得这种方法不切实际。 

### 关键见解

 关键的观察是数字的确切位置并不重要。 只有每个值的总贡献才重要。 

假设数组包含：

 - 三个`2`s
 - 四个`3`s
 - 两个`4`s

 然后：

 - 拿走所有`2`的收入`6`- 拿走所有`3`的收入`12`- 拿走所有`4`的收入`8`如果我们选择价值`3`，我们无法选择`2`或者`4`。 

这将问题转化为与入室抢劫问题相同的经典动态规划模式。 

我们创建一个数组，其中：

 -`points[x] = x * frequency(x)`现在决定变成：

 - 取值`x`，然后跳过`x - 1`- 跳过值`x`这和决定是否抢劫相邻的房屋是一模一样的。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 递归尝试每个删除组合 |

 这里：

-`n`的长度是`nums`-`k`是最大值`nums`## 算法演练

 ### 最优动态规划算法

 1. 计算每个数字出现的次数。 

我们首先计算每个值的频率`nums`。 这使我们能够确定从每个不同数字可以获得的总分。 

例如：```
nums = [2,2,3,3,3,4]

frequency:
2 -> 2
3 -> 3
4 -> 1
```2. 构建点数组。 

对于每个值`x`，计算：```
points[x] = x * frequency[x]
```在上面的例子中：```
points[2] = 4
points[3] = 9
points[4] = 4
```这将问题从单个元素转换为分组值。 
3.应用动态规划。 

定义：```sql
dp[i] = maximum points obtainable using values from 0 to i
```在每个值`i`，我们有两个选择：

 - 跳过`i`- 拿`i`，这意味着我们不能采取`i - 1`所以：$dp[i]=\max(dp[i-1],\ dp[i-2]+points[i])$4. 初始化基本案例。 

我们需要递归的起始值。```
dp[0] = 0
dp[1] = points[1]
```5. 迭代所有可能的值。 

由于值的边界为`10^4`，我们迭代自`2`最多可达最大数量`nums`。 

对于每个值：

 -`dp[i - 1]`意味着我们跳过`i`-`dp[i - 2] + points[i]`意味着我们采取`i`6. 返回最终答案。 

结果存储在：```
dp[max_value]
```### 为什么它有效

 该算法之所以有效，是因为每个值仅与其直接邻居发生冲突。 

一旦数组转换为每个值的总点数，问题就相当于选择不相邻的数字以获得最大总和。 动态规划递归保证在每一步我们都考虑两种有效的可能性：

 - 不包括当前值
 - 包括当前值，同时排除其邻居值

 由于递归始终保持每个值的最佳可实现分数，因此最终答案是最佳的。 

## Python 解决方案```python
from typing import List

class Solution:
    def deleteAndEarn(self, nums: List[int]) -> int:
        max_value = max(nums)

        points = [0] * (max_value + 1)

        for num in nums:
            points[num] += num

        if max_value == 1:
            return points[1]

        dp = [0] * (max_value + 1)

        dp[0] = 0
        dp[1] = points[1]

        for value in range(2, max_value + 1):
            dp[value] = max(
                dp[value - 1],
                dp[value - 2] + points[value]
            )

        return dp[max_value]
```该实现首先查找输入数组中的最大值。 这决定了尺寸`points`和`dp`数组。 

这`points`数组存储每个数字可获得的总分。 我们不单独跟踪频率，而是直接累加值本身：```python
points[num] += num
```例如，如果`3`出现三次，则：```python
points[3] = 9
```这样就简化了后面的动态规划逻辑。 

特殊情况为`max_value == 1`防止越界问题并正确处理仅包含`1`s。 

这`dp`数组存储每个值的最佳可能分数。 复发比较：

 - 跳过当前值
 - 取当前值加上之前两个位置的最好成绩

 最后，算法返回最大值的最佳分数。 

## 解决方案```go
func deleteAndEarn(nums []int) int {
    maxValue := 0

    for _, num := range nums {
        if num > maxValue {
            maxValue = num
        }
    }

    points := make([]int, maxValue+1)

    for _, num := range nums {
        points[num] += num
    }

    if maxValue == 1 {
        return points[1]
    }

    dp := make([]int, maxValue+1)

    dp[0] = 0
    dp[1] = points[1]

    for value := 2; value <= maxValue; value++ {
        take := dp[value-2] + points[value]
        skip := dp[value-1]

        if take > skip {
            dp[value] = take
        } else {
            dp[value] = skip
        }
    }

    return dp[maxValue]
}
```Go 实现遵循与 Python 版本相同的逻辑。 

由于 Go 没有提供内置的`max`对于整数函数，我们使用手动比较值`if`陈述。 

切片用于`points`和`dp`数组。 Go 自动用零值初始化切片，这符合所需的行为。 

整数溢出不是问题，因为最大可能分数完全在 Go 的整数范围内。

 ## 边缘情况

 一种重要的边缘情况是数组仅包含一个不同的值，例如`[2,2,2,2]`。 有缺陷的实现可能仍会尝试不必要地应用邻接逻辑。 在这种情况下，正确的策略就是抓住每一次发生的情况。 该实现自然地处理了这个问题，因为动态编程递归将缺失的相邻值视为零。 

另一个重要的边缘情况是每个数字都是连续的，例如`[1,2,3,4,5]`。 这会产生最大数量的冲突，因为选择任何值都会阻塞其邻居。 贪婪策略可能会因为选择局部大值而不是全局最优组合而失败。 动态编程解决方案可以正确评估获取和跳过每个值。 

当值之间存在较大差距时会出现第三种边缘情况，例如`[1,3,5,7]`。 由于这些值都不相邻，因此可以将所有值放在一起。 一些实现错误地假设每个步骤都涉及冲突。 DP 公式正确地处理了这个问题，因为零点值只是简单地继承了先前的结果。 

另一个微妙的边缘情况是只包含`1`s。 由于重复引用`dp[i - 2]`，没有仔细初始化的实现可能会遇到索引错误。 显式处理`max_value == 1`确保此场景的正确性。
