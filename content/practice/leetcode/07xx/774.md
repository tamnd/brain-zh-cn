[LeetCode 774 题](https://leetcode.com/problems/minimize-max-distance-to-gas-station/)

 **难度：** 🔴难
 **主题：** 数组、二分查找

 ## 解决方案

 ## 问题理解

 该问题给了我们一个排序数组，称为`stations`，其中每个值表示现有加油站在一维 x 轴上的位置。 我们还得到一个整数`k`，代表我们可以添加多少个额外的加油站。 

准确插入后`k`当在任意实值位置新建加油站时，我们将惩罚定义为任何两个相邻加油站之间的最大距离。 我们的目标是最小化这个最大距离。 

换句话说，我们希望以这样的方式分布新的加油站：相邻加油站之间的最大间隙尽可能小。 

例如，假设有一个长度的间隙`10`两个现有车站之间。 如果我们在该间隔内放置一个新站，最好的安排是将间隙分成两段长度`5`。 如果我们放置两个新站，我们可以将间隔分成大约三个相等的部分`3.333`。 

约束条件很重要：

 -`stations.length <= 2000`-`k <= 10^6`- 站点位置可以大到`10^8`这些限制告诉我们几件事：

 - 二次或三次模拟方法可能会太慢。 
- 自从`k`可能非常大，我们无法天真地明确模拟每个可能的位置。 
- 答案是浮点数，问题接受范围内的答案`10^-6`，强烈建议对答案进行二分搜索。 

输入保证按严格递增顺序排序，因此我们不需要自己对数组进行排序。 

一些边缘情况很重要：

 - 站点之间的间隙非常大，可能需要插入许多新站点。 
- 非常大`k`，其中最佳最大距离变得非常小。 
- 间隔划分不均匀，需要仔细的舍入逻辑。 
- 二分搜索终止期间的浮点精度问题。 

## 方法

 ### 蛮力方法

 一个简单的想法是在当前最大的区间内重复放置一个新的加油站。 

对于每个插入：

 1. 找出距离最大的区间。 
2. 在该间隔的中间插入一个电台。 
3. 更新间隔长度。 
4. 重复`k`次。 

这种贪婪方法可以通过最大堆来实现。 每个间隔跟踪它被分成了多少块。 

虽然这种方法效果相当好并且通常会产生最佳答案，但当它出现时，其复杂性就会成为问题`k`非常大。 自从`k`可以达到`10^6`，为每个插入执行堆操作变得昂贵。 

蛮力模拟也侧重于直接构造排列，而实际问题只要求最小可能的最大距离。 这一观察导致了更好的策略。 

### 关键见解

 我们可以二分搜索答案，而不是构建站点的精确位置。 

假设我们猜测一个候选最大距离`D`。 

重要的问题变成：

 > 能否保证每个相邻距离最多为`D`最多使用`k`新站？ 

对于长度间隙`gap`：

- 如果`gap <= D`，不需要新站。 
- 否则，我们必须将间隙分成更小的部分。 

如果我们将间隙分成最大长度的段`D`，所需增设站数为：$$\left\lfloor \frac{gap}{D} \right\rfloor$$更准确地说：$$\text{required} = \left\lceil \frac{gap}{D} \right\rceil - 1$$这让我们可以有效地检查候选人是否`D`是可行的。 

因为可行性是单调的：

 - 如果距离`D`是可以实现的，那么任何更大的距离也是可以实现的。 
- 如果距离`D`是不可能实现的，那么任何更小的距离也是不可能的。 

这种单调属性使得二分搜索适用。

 ## 算法演练

 1. 计算连续加油站之间的所有相邻间隙。 

对于每对`stations[i]`和`stations[i+1]`， 计算：$$gap = stations[i+1] - stations[i]$$最大可能的惩罚不能超过现有的最大差距。 
2. 初始化二分查找范围。 

尽可能最小的惩罚方法`0`，而最大可能的惩罚是现有的最大差距。 

所以我们使用：

 -`left = 0`-`right = max_gap`3. 反复二分查找答案。 

在每次迭代时：$$mid = \frac{left + right}{2}$$这里，`mid`表示候选最大允许距离。 
4. 检查是否`mid`是可行的。 

对于每个间隙：

 - 确定需要多少个额外站点，以便每个段最多成为`mid`。 

间隙所需的站是：$$\left\lfloor \frac{gap}{mid} \right\rfloor$$当划分准确时要小心处理。 

更简单、更安全的实现是：$$\text{needed} += \text{int}(gap / mid)$$当完全整除时减一。 
5. 将所需站点总数与`k`。 

- 如果需要站`<= k`， 然后`mid`是可以实现的。 

- 尝试找到一个更小的答案。 
- 移动`right = mid`。 
- 否则：

-`mid`太小了。 
- 移动`left = mid`。 
6. 继续，直到搜索间隔变得足够小。 

由于答案内`10^-6`被接受，我们在以下情况停止：$$right - left < 10^{-6}$$7. 返回`right`或者`left`。 

终止时两个值实际上相同。 

### 为什么它有效

 该算法依赖于可行性的单调性。 

如果最大距离`D`最多可以使用`k`站，那么也可以实现任何更大的距离，因为放宽约束永远不会增加所需站的数量。 

二分搜索有效地利用这一特性来定位最小的可行距离。 可行性检查是正确的，因为将每个间隔分割成大小相等的段可以最小化该间隔的最大段长度。 

## Python 解决方案```python
from typing import List

class Solution:
    def minmaxGasDist(self, stations: List[int], k: int) -> float:
        def can_achieve(max_distance: float) -> bool:
            required_stations = 0

            for i in range(1, len(stations)):
                gap = stations[i] - stations[i - 1]

                additional = int(gap / max_distance)

                if gap % max_distance == 0:
                    additional -= 1

                required_stations += additional

                if required_stations > k:
                    return False

            return True

        left = 0.0
        right = 0.0

        for i in range(1, len(stations)):
            right = max(right, stations[i] - stations[i - 1])

        precision = 1e-6

        while right - left > precision:
            mid = (left + right) / 2

            if can_achieve(mid):
                right = mid
            else:
                left = mid

        return right
```实现首先定义一个名为的辅助函数`can_achieve`。 该函数确定是否可以使用最多来实现候选最大距离`k`额外的车站。 

对于每对相邻的站点，我们计算间隙长度。 然后，我们计算需要多少个额外站点才能确保没有路段超过候选距离。 

如果运行总计超过`k`，我们立即返回`False`，这提供了重要的优化。 

二分查找范围开始于`0.0`并延伸到现有的最大差距。 在每次迭代期间，我们测试中点：

 - 如果可行，我们缩小上限。 
- 否则，我们增加下限。 

一旦间隔变得小于则循环终止`10^-6`，满足精度要求。 

## 解决方案```go
package main

func minmaxGasDist(stations []int, k int) float64 {
	canAchieve := func(maxDistance float64) bool {
		requiredStations := 0

		for i := 1; i < len(stations); i++ {
			gap := float64(stations[i] - stations[i-1])

			additional := int(gap / maxDistance)

			if gap == float64(additional)*maxDistance {
				additional--
			}

			requiredStations += additional

			if requiredStations > k {
				return false
			}
		}

		return true
	}

	left := 0.0
	right := 0.0

	for i := 1; i < len(stations); i++ {
		gap := float64(stations[i] - stations[i-1])

		if gap > right {
			right = gap
		}
	}

	precision := 1e-6

	for right-left > precision {
		mid := (left + right) / 2.0

		if canAchieve(mid) {
			right = mid
		} else {
			left = mid
		}
	}

	return right
}
```Go 实现遵循与 Python 版本相同的逻辑。 由于 Go 严格区分整数和浮点值，因此显式`float64`算术过程中需要进行转换。 

关闭`canAchieve`捕获`stations`和`k`直接，避免需要额外的参数。 

与 Python 不同，Go 没有内置的任意精度浮点处理，因此我们依赖`float64`，这足以满足所需的精度。

    def minmaxGasDist(self, stations: List[int], k: int) -> float:
        def can_achieve(max_distance: float) -> bool:
            required_stations = 0

            for i in range(1, len(stations)):
                gap = stations[i] - stations[i - 1]

                additional = int(gap / max_distance)

                if gap % max_distance == 0:

                required_stations += additional

                right = mid
            else:
                left = mid

        return right

 ## 边缘情况

 当间隙完全除以候选最大距离时，就会出现一种重要的边缘情况。 例如，如果间隙是`10`候选距离为`5`，我们只需要一个额外的站，而不是两个。 使用普通整数除法的粗心实现可能会过度计算所需的站。 当除法精确时，实现通过减一来处理这个问题。 

另一个重要的边缘情况是极大的值`k`。 当可以插入很多站时，最优答案就变得很小。 如果停止条件不正确，这可能会暴露浮点精度问题或导致无限的二分搜索循环。 该实现使用的精度阈值是`10^-6`，匹配问题要求。 

第三种边缘情况涉及非常大的站点坐标，最多可达`10^8`。 整数算术本身仍然安全，但涉及浮点除法的计算必须小心处理。 两种实现在二分搜索和可行性检查期间一致使用浮点运算，防止溢出或截断问题。
