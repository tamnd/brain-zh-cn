[LeetCode 744 题](https://leetcode.com/problems/find-smallest-letter-greater-than-target/)

 **难度：** 🟢简单
 **主题：** 数组、二分查找

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个经过排序的小写英文字母数组和一个目标字符。 我们的任务是找到数组中按字典顺序严格大于目标字符的最小字符。 

字符的词典顺序就是字母顺序。 例如，`'f'`大于`'c'`， 和`'x'`大于`'m'`。 

一个重要的细节是环绕行为。 如果目标大于或等于数组中的每个字符，我们不会返回任何内容或无效值。 相反，我们返回数组中的第一个字符。 这有效地将数组视为循环数组。 

例如：

 - 如果`letters = ["c","f","j"]`和`target = "c"`，答案是`"f"`因为它是严格大于的最小字母`"c"`。 
- 如果`letters = ["x","x","y","y"]`和`target = "z"`，没有字符大于`"z"`，所以我们绕回并返回`"x"`。 

这些约束告诉我们一些重要的事情：

 - 数组已经按非降序排序。 
- 数组长度可以大到`10^4`。 
- 字符仅为小写英文字母。 
- 至少有两个不同的角色。 

排序的属性是关键的观察结果。 每当我们有一个排序数组并需要找到满足某些条件的第一个元素时，二分搜索就成为一个强有力的候选者。 

有几种边缘情况可能会在简单的实现中导致错误：

 - 目标可能比每个角色都小。 
- 目标可能比每​​个角色都大。 
- 目标可能会在数组中出现多次。 
- 数组可能包含许多重复的字母。 
- 答案可能需要环绕索引`0`。 

由于环绕规则，该问题保证始终存在有效答案。 

## 方法

 ### 蛮力方法

 最简单的解决方案是从左到右扫描数组并返回大于目标的第一个字符。 

由于数组已排序，因此第一个匹配字符自动成为最小的有效答案。 

如果我们完成扫描数组但从未找到大于目标的字符，则返回`letters[0]`。 

这种方法是正确的，因为它按升序明确检查每个字符。 满足条件的第一个字符一定是正确答案。 

然而，最坏情况的时间复杂度是线性的，`O(n)`，因为我们可能需要检查整个数组。 

### 最优方法，二分搜索

 重要的观察结果是数组是排序的。 

我们正在寻找第一个职位：```
letters[i] > target
```这正是二分搜索的设计目的。 

二分查找不是一一检查每个元素，而是反复将搜索空间减半。 每一步：

 - 如果`letters[mid] <= target`, then the answer must be to the right.
 - 否则，`letters[mid] > target`，所以这个位置可能就是答案，但左边可能有一个更小的有效字符。 

搜索完成后：

 - 如果我们找到有效位置，请将其返回。 
- 如果搜索超出了数组末尾，则回绕并返回`letters[0]`。 

这降低了时间复杂度`O(n)`到`O(log n)`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(1) | O(1) | 线性扫描直到找到大于目标 | 的字符
 | 最佳 | O(log n) | O(1) | O(1) | 使用二分查找来定位第一个有效字符 |

 ## 算法演练

 1.初始化两个指针，`left`和`right`。`left`开始于`0`， 和`right`开始于`len(letters) - 1`。 这些指针定义当前的搜索范围。 
2. 执行二分查找`left <= right`。 

在每次迭代时，计算：```
mid = (left + right) // 2
```这给出了当前搜索空间的中间索引。 
3.比较`letters[mid]`与目标。 

如果：```
letters[mid] <= target
```那么这个角色就不能成为答案，因为我们需要一个更伟大的角色。 

由于数组已排序，因此所有位于或之前的内容`mid`也没什么用，所以移动：```
left = mid + 1
```4. 否则，`letters[mid] > target`。 

这意味着当前字符是有效的候选答案。 

然而，左侧可能还有更小的有效字符，所以继续搜索：```
right = mid - 1
```5. 继续，直到搜索空间变空。 

在此刻，`left`表示大于目标的字符应出现的插入位置。 
6.处理环绕。 

如果`left == len(letters)`，表示数组中的每个字符都小于或等于目标值。 

在这种情况下，返回：```
letters[0]
```7. 否则，返回`letters[left]`。 

这是严格大于目标的最小字符。 

### 为什么它有效

 二分查找保持了之前的每个索引的不变性`left`包含小于或等于目标的字符，而任何潜在的答案必须位于或之后`left`。 

当搜索结束时，`left`正是包含大于目标字符的第一个位置。 如果这样的位置不存在，则环绕规则要求返回数组中的第一个字符。 

## Python 解决方案```python
from typing import List

class Solution:
    def nextGreatestLetter(self, letters: List[str], target: str) -> str:
        left = 0
        right = len(letters) - 1

        while left <= right:
            mid = (left + right) // 2

            if letters[mid] <= target:
                left = mid + 1
            else:
                right = mid - 1

        return letters[left % len(letters)]
```实现首先使用设置二分搜索边界`left`和`right`。 

在循环内部，我们计算中间索引并进行比较`letters[mid]`反对目标。 

当中间的字符小于或等于目标时，我们知道它不能是答案，因为问题需要严格更大的字符。 因此，我们丢弃左半部分，包括`mid`。 

当中间的字符大于目标时，它就成为潜在的答案。 但是，数组中较早的部分仍然可能存在较小的有效字符，因此我们继续搜索左半部分。 

循环结束后，`left`指向第一个有效位置。 表达式：```python
left % len(letters)
```自动处理环绕。 如果`left`等于数组长度，取模将其转换回`0`。 

## 解决方案```go
func nextGreatestLetter(letters []byte, target byte) byte {
    left := 0
    right := len(letters) - 1

    for left <= right {
        mid := left + (right-left)/2

        if letters[mid] <= target {
            left = mid + 1
        } else {
            right = mid - 1
        }
    }

    return letters[left%len(letters)]
}
```Go 实现遵循与 Python 版本完全相同的二分搜索逻辑。 

一个小的区别是计算`mid`:```go
mid := left + (right-left)/2
```这种形式避免了整数大小固定的语言中的整数溢出。 虽然对于这个问题规模而言，溢出不是问题，但在 Go 和其他系统语言中，它被认为是良好的二分搜索实践。 

Go 中也使用模运算来干净地处理环绕情况。

 ## 边缘情况

 ### 目标大于每个角色

 一个常见的错误是忘记了环绕行为。 

例如：```
letters = ["c","f","j"]
target = "z"
```没有大于的字符`"z"`，所以正确答案是`"c"`。 

该实现使用以下方式干净地处理了这个问题：```
letters[left % len(letters)]
```什么时候`left`等于数组长度，取模将其转换回索引`0`。 

### 重复字符

 该数组可能包含重复的值：```
letters = ["c","c","f","f","j"]
target = "c"
```有错误的实现可能会错误地返回`"c"`本身。 

条件：```
letters[mid] <= target
```确保跳过等于目标的所有字符，保证我们只返回严格更大的字符。 

### 目标小于所有字符

 考虑：```
letters = ["d","e","f"]
target = "a"
```答案应该是立即`"d"`。 

二分搜索自然会处理这个问题，因为每次比较都会将搜索向左侧移动，最终离开`left`在索引处`0`。 

### 非常小的数组

 最小数组大小为`2`。 

例如：```
letters = ["a","z"]
target = "a"
```由于不正确的循环条件或指针更新，某些实现在小型数组上失败。 

使用标准二分查找条件：```
while left <= right
```确保正确检查每个有效索引，即使在允许的最小输入大小中也是如此。
