[LeetCode 795 题](https://leetcode.com/problems/number-of-subarrays-with-bounded-maximum/)

 **难度：** 🟡 中等
 **主题：** 数组、两个指针

 ## 解决方案

 ## 问题理解

 该问题要求我们计算有多少个连续的非空子数组的最大元素位于包含范围内`[left, right]`。 

子数组是原始数组的连续段。 对于每个可能的子数组，我们查看它的最大值。 如果该最大值至少为`left`并且至多`right`，则该子数组被视为有效并有助于最终答案。 

例如，如果：```
nums = [2,1,4,3]
left = 2
right = 3
```然后：

-`[2]`有效，因为它的最大值是`2`-`[2,1]`有效，因为它的最大值是`2`-`[3]`有效，因为它的最大值是`3`-`[4]`无效，因为它的最大值是`4`，这超过了`right`目标是返回有效子数组的总数。 

约束条件很重要：

 -`nums.length`可以大到`100000`- 每个数字可以大到`10^9`这些限制立即告诉我们，具有二次复杂度的算法（例如显式检查每个子数组）可能会太慢。 由于有`O(n^2)`可能的子数组，我们需要更接近线性时间的东西。 

一些边缘情况尤其重要：

 - 每个值都大于的数组`right`- 每个值都小于的数组`left`- 包含许多有效重叠子数组的数组
 - 单元素数组
 - 大范围的值小于`left`，它可以扩展以前有效的子数组
 - 值大于`right`，这完全破坏了有效子数组的连续性

 正确的解决方案必须仔细有效地处理所有这些情况。 

## 方法

 ### 蛮力方法

 最直接的解决方案是生成每个可能的子数组并计算其最大值。 

对于每个起始索引`i`，我们将子数组向右扩展一次一个元素。 在扩展的同时，我们保持当前的最大值。 如果最大值落在里面`[left, right]`，我们增加答案。 

这种方法是正确的，因为它显式检查每个可能的子数组并直接验证问题条件。 

但是，长度数组中子数组的数量`n`是：```
n * (n + 1) / 2
```这是`O(n^2)`。 

和`n = 100000`，这变得太大了。 即使增量地维持最大值，该算法仍然需要二次时间。 

### 最佳方法

 关键的见解是我们不需要单独评估每个子数组。 

相反，我们可以计算每个索引处有多少个有效子数组。 

考虑从左到右扫描数组。 在每个位置：

 - 如果当前值大于`right`，那么此处结尾的子数组都不是有效的。 
- 如果当前值在`[left, right]`，那么从最后一个无效元素开始的每个子数组都变得有效。 
- 如果当前值小于`left`，那么它不能独立创建一个有效的子数组，但它可以扩展以前有效的子数组。 

为了使这项工作有效地进行，我们跟踪：

 -`last_invalid`，最近的索引，其中`nums[i] > right`-`last_valid`，最近的索引，其中`left <= nums[i] <= right`在每个位置：

 - 以当前索引结尾的有效子数组的数量等于：```
last_valid - last_invalid
```如果`last_valid > last_invalid`。 

这将问题转化为单个线性扫描。

 ## 算法演练

 ### 最优滑动窗口计数策略

 1.初始化三个变量：

 -`last_invalid = -1`-`last_valid = -1`-`answer = 0`

`last_invalid`存储超过该值的最新位置`right`。 任何跨越该索引的子数组都将变得无效。`last_valid`存储该值所在的最新位置`[left, right]`。 这可确保子数组至少包含一个可接受的最大值。 
2. 从左到右遍历数组。 
3. 对于每个索引`i`：

- 如果`nums[i] > right`， 更新：```
last_invalid = i
```因为这个值使得包含它的每个子数组都无效。 
4.如果`nums[i]`位于里面`[left, right]`， 更新：```
last_valid = i
```因为该元素可以作为以 结尾的子数组的有效最大值`i`。 
5. 计算有多少个有效子数组以索引结尾`i`。 

任意子数组：

 - 必须在之后开始`last_invalid`- 必须包括`last_valid`因此，有效起始位置的数量为：```
last_valid - last_invalid
```6. 如果该数量是正数，则将该数量添加到答案中。 
7. 继续，直到处理完整个数组。 
8. 返回最终答案。 

### 为什么它有效

 该算法保持了一个重要的不变量：

 - 每个以索引结尾的有效子数组`i`必须在最近的无效元素之后开始。 
- 每个有效子数组必须至少包含一个元素`[left, right]`。`last_invalid`保证我们永远不会包含大于的值`right`， 尽管`last_valid`保证子数组包含有效的最大候选者。 

区别`last_valid - last_invalid`精确计算以当前索引结尾的子数组的所有有效起始位置。 

因为每个子数组都只计算一次，所以该算法是正确的。 

## Python 解决方案```python
from typing import List

class Solution:
    def numSubarrayBoundedMax(self, nums: List[int], left: int, right: int) -> int:
        last_invalid = -1
        last_valid = -1
        total_subarrays = 0

        for index, value in enumerate(nums):
            if value > right:
                last_invalid = index

            if left <= value <= right:
                last_valid = index

            valid_count = last_valid - last_invalid

            if valid_count > 0:
                total_subarrays += valid_count

        return total_subarrays
```该实现遵循算法演练中描述的确切逻辑。`last_invalid`跟踪元素超出的最近位置`right`。 任何跨越此索引的子数组都会立即无效。`last_valid`跟踪元素落在可接受范围内的最新位置。 这确保子数组至少包含一个能够成为最大值的值。 

对于每个元素，我们计算：```python
last_valid - last_invalid
```这给出了以当前位置结束的有效子数组的数量。 

如果该数量为负数或零，则此处没有有效的子数组结束，因此不会添加任何内容。 

该算法仅对数组执行一次遍历并使用恒定的额外内存。 

## 解决方案```go
func numSubarrayBoundedMax(nums []int, left int, right int) int {
    lastInvalid := -1
    lastValid := -1
    totalSubarrays := 0

    for index, value := range nums {
        if value > right {
            lastInvalid = index
        }

        if value >= left && value <= right {
            lastValid = index
        }

        validCount := lastValid - lastInvalid

        if validCount > 0 {
            totalSubarrays += validCount
        }
    }

    return totalSubarrays
}
```Go 的实现与 Python 解决方案非常相似。 

Go 切片已经是对数组的动态引用，因此不需要对输入存储进行特殊处理。 

该问题保证最终答案适合 32 位整数，因此使用 Go 的标准`int`类型就足够了。 

与 Python 不同，Go 需要显式变量声明和使用`&&`而不是 Python 的链式比较。

 ## 边缘情况

 ### 包含大于的值的数组`right`值大于`right`特别重要，因为它们使包含它们的每个子数组无效。 一个常见的错误是在出现此类元素后无法完全重置计数逻辑。 

例如：```
nums = [2, 9, 2]
```价值`9`将数组分割成单独的有效区域。 该实现通过更新来处理这个问题`last_invalid`每当一个值超过`right`，确保没有计算与该索引相交的子数组。 

### 值小于的数组`left`数值如下`left`不能独立形成有效的子数组，但它们可以扩展现有的有效子数组。 

例如：```
nums = [2,1,1]
```子数组`[2,1]`和`[2,1,1]`仍然有效，因为还剩下最大值`2`。 

幼稚的实现可能会错误地丢弃这些子数组。 该算法可以正确处理这个问题，因为`last_valid`保持不变，直到出现另一个范围内的值。 

### 没有有效元素的数组

 如果每个值都低于`left`或以上`right`，答案应该是零。 

例如：```
nums = [1,1,1]
left = 2
right = 3
```没有子数组包含所需范围内的最大值。 

实现自然会处理这个问题，因为`last_valid`永远不会超越`last_invalid`，因此没有添加有效的子数组。
