[LeetCode 第 727 题](https://leetcode.com/problems/minimum-window-subsequence/)

 **难度：** 🔴难
 **主题：** 字符串、动态规划、滑动窗口

 ## 解决方案

 ## 问题理解

 这个问题要求我们找到最小的连续子串`s1`这样`s2`作为子序列出现在该子字符串内。 
AN 子序列不要求字符相邻，但它们必须以相同的相对顺序出现。 例如，`"bde"`是一个子序列`"bcde"`因为我们可以选择`'b'`， 然后`'d'`， 然后`'e'`同时维护秩序。 

重要的细节是答案本身必须是连续的子串`s1`，即使匹配的字符为`s2`该子字符串内不需要是连续的。 

我们有两个字符串：

 -`s1`，较大的源字符串
 -`s2`，目标子序列

 我们必须返回：

 - 最短子串`s1`其中包含`s2`作为子序列
 - 如果多个子字符串具有相同的最小长度，我们返回起始索引最小的一个
 - 如果不存在有效的子字符串，我们返回`""`考虑这个例子：```
s1 = "abcdebdde"
s2 = "bde"
```子串`"bcde"`有效是因为：

 -`'b'`比赛
 -`'d'`稍后出现
 -`'e'`稍后出现

 子串`"bdde"`也可以，但都有长度`4`， 和`"bcde"`出现得更早。 

约束条件很重要：

 -`s1.length <= 2 * 10^4`-`s2.length <= 100`这告诉我们：

 -`s1`可以相当大
 -`s2`相对较小

 完全二次或三次解`s1`可能会太慢。 然而，算法涉及`O(len(s1) * len(s2))`是合理的，因为`s2`很小。 

一些边缘情况很重要：

 -`s2`可能包含不存在的字符`s1`- 可能存在多个最小窗口
 - 最佳窗口可能会在接近结束时出现
 -`s2`可能已经等于一个精确的子串
 -`s2`可能需要跳过许多字符`s1`- 根本不存在有效的子序列

 简单的子字符串检查实现很容易变得太慢，因为有`O(n^2)`子串。 

## 方法

 ### 蛮力方法

 暴力解决方案考虑了每个可能的子串`s1`。 

对于每个子串：

 1.提取子串
 2. 检查是否`s2`是它的子序列
 3. 如果有效，将其长度与当前最佳答案进行比较

 检查是否`s2`是一个子序列，我们使用两个指针：

 - 一个指针扫描子串
 - 一键扫描`s2`每当字符匹配时，我们都会将`s2`指针。 

如果我们完成扫描`s2`，则该子串有效。 

这种方法是正确的，因为它明确地检查每个可能的候选窗口。 因此，它不会错过最佳答案。 

然而，它的效率极低。 

有`O(n^2)`子串，并且每个子序列检查可能需要`O(n)`时间。 这导致大约`O(n^3)`最坏情况下的复杂性，对于`n = 20,000`。 

### 最优方法，前向扫描+后向收缩

 关键的观察是，一旦我们发现在某个位置结束的有效子序列，我们就可以向后缩小窗口以找到该结束索引的最小可能起点。 

该算法分两个阶段重复工作：

 1. 正向扫描：

 - 找到完整的子序列匹配`s2`2. 向后扫描：

 - 向后移动以最小化窗口，同时保留子序列

 这避免了显式检查每个子字符串。 

重要的见解是，在找到有效的结束位置后，我们可以贪婪地缩小左边界而不失去有效性。 

因为`s2`很小，每次向前和向后扫描都是可管理的。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n3) | O(1) | O(1) | 显式检查每个子字符串 |
 | 最佳| O(n * m) | O(1) | O(1) | 使用前向子序列匹配和后向收缩 |

 这里：

-`n = len(s1)`-`m = len(s2)`## 算法演练

 ### 最优算法

 1. 初始化变量以跟踪迄今为止找到的最佳窗口。 

我们存储：

 -`best_start`-`best_length`最初，没有找到有效的窗口。 
2. 开始扫描`s1`从左到右。 

使用指针`i`为了`s1`。 
3. 每当`s1[i]`匹配第一个字符`s2`，尝试前向子序列匹配。 

我们使用：

 -`s1_idx`扫描`s1`-`s2_idx`扫描`s2`4. 继续前进`s1`。 

每当：```
s1[s1_idx] == s2[s2_idx]
```增量`s2_idx`。 
5. 如果`s2_idx`达到`len(s2)`，我们找到了一个有效的子序列。 

目前的`s1_idx - 1`成为有效窗口的结束位置。 
6. 执行向后收缩步骤。 

现在我们最小化窗口，同时保留子序列。 

放：

-`end = s1_idx - 1`-`s2_idx = len(s2) - 1`7. 向后移动`s1`。 

每当：```
s1[s1_idx] == s2[s2_idx]
```递减`s2_idx`。 

继续直到所有字符`s2`向后匹配。 
8. 最后向后移动后的位置成为最小起始索引。 

计算：

 -`start`-`window_length`9. 如果出现以下情况，请更新最佳答案：

 - 当前窗口较短
 - 或等长但更早
 10. 当前窗口启动后继续扫描。 

这样可以避免不必要的重复工作。 

### 为什么它有效

 前向扫描保证我们找到有效的子序列结束位置。 然后向后扫描贪婪地从左侧删除不必要的字符，同时仍然保留子序列顺序。 

因为后退步骤总是找到固定结束位置的最早可能的有效开始，所以每个发现的窗口都是局部最小的。 比较所有此类最小窗口可以保证全局最小答案。 

## Python 解决方案```python
class Solution:
    def minWindow(self, s1: str, s2: str) -> str:
        n = len(s1)
        m = len(s2)

        best_start = -1
        best_length = float("inf")

        i = 0

        while i < n:
            if s1[i] == s2[0]:
                s1_idx = i
                s2_idx = 0

                # Forward scan to match entire s2
                while s1_idx < n and s2_idx < m:
                    if s1[s1_idx] == s2[s2_idx]:
                        s2_idx += 1
                    s1_idx += 1

                # Entire subsequence matched
                if s2_idx == m:
                    end = s1_idx - 1

                    # Backward shrink
                    s2_idx = m - 1
                    s1_idx = end

                    while s2_idx >= 0:
                        if s1[s1_idx] == s2[s2_idx]:
                            s2_idx -= 1
                        s1_idx -= 1

                    start = s1_idx + 1
                    window_length = end - start + 1

                    if window_length < best_length:
                        best_length = window_length
                        best_start = start

                    # Restart from next position after start
                    i = start

            i += 1

        if best_start == -1:
            return ""

        return s1[best_start:best_start + best_length]
```实现直接遵循算法。 

外层循环扫描`s1`。 每当我们遇到与开头匹配的字符时`s2`，我们尝试构建一个完整的子序列。 

前向扫描搜索完全匹配的`s2`。 如果匹配成功，我们就知道当前端点创建了一个有效的窗口。 

向后收缩阶段最小化窗口。 从端点开始，我们向后遍历两个字符串，以删除左侧不必要的字符。 

一旦确定了最小有效开始，我们就会计算窗口大小并根据需要更新最佳答案。 

最后，我们继续扫描其他候选窗口。 

## 解决方案```go
func minWindow(s1 string, s2 string) string {
	n := len(s1)
	m := len(s2)

	bestStart := -1
	bestLength := n + 1

	i := 0

	for i < n {
		if s1[i] == s2[0] {
			s1Idx := i
			s2Idx := 0

			// Forward scan
			for s1Idx < n && s2Idx < m {
				if s1[s1Idx] == s2[s2Idx] {
					s2Idx++
				}
				s1Idx++
			}

			// Full subsequence matched
			if s2Idx == m {
				end := s1Idx - 1

				// Backward shrink
				s2Idx = m - 1
				s1Idx = end

				for s2Idx >= 0 {
					if s1[s1Idx] == s2[s2Idx] {
						s2Idx--
					}
					s1Idx--
				}

				start := s1Idx + 1
				windowLength := end - start + 1

				if windowLength < bestLength {
					bestLength = windowLength
					bestStart = start
				}

				i = start
			}
		}

		i++
	}

	if bestStart == -1 {
		return ""
	}

	return s1[bestStart : bestStart+bestLength]
}
```Go 的实现与 Python 版本非常相似。 

Go 中的字符串是字节索引的，这里可以正常工作，因为问题保证了小写英文字母。 

与 Python 不同，Go 不方便地提供整数的无穷大值，因此我们初始化`bestLength`使用`n + 1`，它比任何可能的有效窗口都大。 

在 Go 中返回一个空字符串很简单`""`。

 ## 边缘情况

 当不存在有效子序列时，会出现一种重要的边缘情况。 例如，如果`s2 = "z"`和`s1`不包含`'z'`，前向扫描永远不会成功完成。 有缺陷的实现可能会意外返回未初始化的子字符串或产生索引错误。 此实现可以安全地跟踪是否使用过找到有效的窗口`best_start == -1`。 

另一个重要的情况涉及重复字符`s2`。 考虑：```
s1 = "cnhczmccqouqadqtmjjzl"
s2 = "mm"
```该算法必须正确区分所需的两个`'m'`人物。 不正确的指针处理可能会意外地重复使用同一字符两次。 前向扫描保证每次匹配都正确地推进两个指针，从而保留子序列的顺序。 

第三个棘手的情况是相等长度的窗口之间的平局打破。 该问题需要返回最左边的最小长度窗口。 由于算法仅在找到严格较小的窗口时更新答案，因此第一个最小长度窗口自动保留为所选答案。 这正确地保留了最左边的优先级。 

当最佳窗口是整个字符串本身时，会出现另一种微妙的边缘情况。 例如：```
s1 = "abcde"
s2 = "ace"
```向后收缩阶段必须正确停止，而不会超出有效子序列的开头。 该实现使用向后匹配逻辑仔细地重建最小起始索引。
