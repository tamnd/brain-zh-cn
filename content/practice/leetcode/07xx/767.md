[LeetCode 767 题](https://leetcode.com/problems/reorganize-string/)

 **难度：** 🟡 中等
 **主题：** 哈希表、字符串、贪婪、排序、堆（优先级队列）、计数

 ## 解决方案

 ## 问题理解

 该问题要求我们重新排列给定字符串的字符`s`使得没有两个相邻的字符是相同的。 输入是一串长度在 1 到 500 之间的小写英文字母。输出应该是满足邻接约束的有效重新排列，或者如果不可能进行这样的排列，则输出应该是空字符串。 

关键点是某些字符串无法重新排列以满足这一条件，特别是当一个字符出现得太频繁时。 例如，如果最频繁出现的字符超过向上舍入的字符串长度的一半，则不可能在没有相邻重复项的情况下重新排列。 边缘情况包括具有所有相同字符的字符串、长度为 1 的字符串或多个字符具有相同最大频率的字符串。 

## 方法

 暴力方法是生成字符串的所有排列并检查每个排列以查看其是否满足邻接约束。 这保证了正确性，因为它探索了每一种可能的重新排列，但排列的数量随字符串长度呈阶乘增长，因此对于长度长达 500 的字符串不可行。 

最佳方法利用了我们可以以贪婪方式排列字符的观察结果，总是将最常见的剩余字符放置在接下来，但确保它与之前放置的字符不同。 为了在任何时刻有效地跟踪最频繁的字符，我们使用最大堆（优先级队列）。 通过弹出最高频率的字符，放置它，然后在必要时以减少的计数将其推回，我们可以确保序列有效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n) | 生成所有排列并检查邻接性 |
 | 最佳| O(n log k) | O(n log k) | O(k) | 使用带有 k 个唯一字母的最大堆，贪婪放置 |

 ## 算法演练

 1. 使用哈希映射计算字符串中每个字符的出现频率。 这有助于识别最常见的字符并支持堆操作。 
2. 初始化最大堆，其中元素为`(frequency, character)`对，其中频率被否定以模拟仅支持最小堆的语言中的最大堆。 
3. 初始化一个空结果列表以构建重新排列的字符串。 
4. 当堆不为空时，弹出剩余频率最高的字符。 
5. 如果先前放置的字符存在并且仍有剩余频率，则将其推回堆中。 
6. 将所选字符附加到结果中并减少其频率。 
7. 跟踪最后使用的字符以防止连续放置。 
8. 如果在任何步骤中，堆为空，但前一个字符仍有剩余频率，则返回空字符串，因为不存在有效的重新排列。 
9. 将结果列表转换为字符串并返回。 

为什么有效：这种贪婪策略确保我们始终放置剩余计数最高的角色，同时避免连续重复。 最大堆保证没有字符被饿死，并且对先前使用的字符的检查确保永远不会违反邻接规则。 

## Python 解决方案```python
import heapq
from collections import Counter

class Solution:
    def reorganizeString(self, s: str) -> str:
        freq_map = Counter(s)
        max_heap = [(-count, char) for char, count in freq_map.items()]
        heapq.heapify(max_heap)
        
        prev_count, prev_char = 0, ''
        result = []
        
        while max_heap:
            count, char = heapq.heappop(max_heap)
            result.append(char)
            if prev_count < 0:
                heapq.heappush(max_heap, (prev_count, prev_char))
            count += 1  # decrease count since heap stores negative
            prev_count, prev_char = count, char
        
        result_str = ''.join(result)
        if len(result_str) != len(s):
            return ""
        return result_str
```Python 实现首先对字符进行计数并使用负计数构建最大堆。 我们跟踪前一个字符以避免邻接冲突，并仅在安全时将其推回堆中。 循环继续，直到放置完所有字符。 最终的长度检查确保没有字符因邻接约束而未放置。 

## 解决方案```go
package main

import (
    "container/heap"
    "strings"
)

type CharHeap [][2]interface{} // [0]=count(int), [1]=char(byte)

func (h CharHeap) Len() int { return len(h) }
func (h CharHeap) Less(i, j int) bool { return h[i][0].(int) > h[j][0].(int) }
func (h CharHeap) Swap(i, j int) { h[i], h[j] = h[j], h[i] }
func (h *CharHeap) Push(x interface{}) { *h = append(*h, x.([2]interface{})) }
func (h *CharHeap) Pop() interface{} {
    old := *h
    n := len(old)
    x := old[n-1]
    *h = old[:n-1]
    return x
}

func reorganizeString(s string) string {
    freq := make(map[byte]int)
    for i := 0; i < len(s); i++ { freq[s[i]]++ }
    
    h := &CharHeap{}
    heap.Init(h)
    for char, count := range freq { heap.Push(h, [2]interface{}{count, char}) }
    
    var result strings.Builder
    var prevCount int
    var prevChar byte
    
    for h.Len() > 0 {
        item := heap.Pop(h).([2]interface{})
        count := item[0].(int)
        char := item[1].(byte)
        result.WriteByte(char)
        
        if prevCount > 0 { heap.Push(h, [2]interface{}{prevCount, prevChar}) }
        
        count--
        prevCount, prevChar = count, char
    }
    
    if result.Len() != len(s) { return "" }
    return result.String()
}
```Go 实现的主要区别在于堆和字符串构建的类型处理。 我们定义一个自定义堆类型来处理字符的优先级队列并使用`strings.Builder`用于高效的字符串连接。 通过检查最终字符串长度来类似地处理边缘情况。

 ## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n log k) | O(n log k) | 我们对n个字符中的每一个执行堆操作（push/pop），堆大小是k个唯一字符|

 ## 边缘情况

 一个关键的边缘情况是单个字符在字符串中占主导地位。 例如，“aaaaa”无法重新排列，并且实现正确返回空字符串。 另一个边缘情况是所有字符都不同，例如“abcdef”，它通常允许重新排列； 堆仍然正确输出有效的字符串。 第三种边缘情况是一个字符串，其中字符几乎均匀分布，但其中一个字符的出现略多于一半，例如“aaabc”。 该算法通过检测它无法再在不违反邻接性的情况下放置字符来处理它，并在必要时返回一个空字符串。 在所有情况下，堆和先前字符跟踪的组合确保了正确性。
