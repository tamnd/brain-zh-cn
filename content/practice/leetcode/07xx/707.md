 # LeetCode 707 - 设计链表

 ## 问题理解

 这个问题要求我们从头开始实现自己的链表数据结构，而不使用任何内置的链表库。 链表必须支持多种常见操作，例如检索特定索引处的值、在不同位置插入节点以及删除节点。 

该列表的索引为 0，这意味着第一个节点位于索引处`0`，第二个节点位于索引处`1`， 等等。 

我们需要执行以下操作：

 -`get(index)`返回存储在给定索引处的值
 -`addAtHead(val)`在开头插入一个新节点
 -`addAtTail(val)`在末尾插入一个新节点
 -`addAtIndex(index, val)`在指定索引之前插入一个节点
 -`deleteAtIndex(index)`删除指定索引处的节点

 这个问题的重要部分是在维护链表结构的同时正确处理指针操作。 

限制相当小，最多 2000 次操作。 这意味着性能要求不是极其严格，但我们仍然希望有一个干净、高效的实现。 

链表与数组不同，因为节点是通过引用而不是连续的内存位置连接的。 一旦我们到达正确的位置，这使得插入和删除变得高效，但是随机访问变得更慢，因为我们必须逐个节点遍历。 

一些边缘情况尤其重要：

 - 访问无效索引应该返回`-1`- 在大于当前大小的索引处插入应该不会执行任何操作
 - 在等于当前大小的索引处插入应附加到末尾
 - 从空列表中删除应该不会执行任何操作
 - 在许多实现中涉及头节点的操作需要特殊处理

 为了简化边缘情况处理，我们将使用虚拟头节点。 

## 方法

 ### 蛮力方法

 一种强力方法是将所有值内部存储在动态数组或 Python 列表中，并手动模拟链表操作。 

例如：

-`get(index)`会直接访问数组
 -`addAtHead(val)`将插入到位置`0`-`addAtTail(val)`将附加
 -`addAtIndex(index, val)`会移动元素以腾出空间
 -`deleteAtIndex(index)`删除后将向左移动元素

 这是正确的，因为数组可以表示有序序列。 然而，中间的插入和删除需要移动许多元素，这对于大输入来说效率很低。 

更重要的是，该问题明确要求我们设计一个链表实现，因此使用数组违背了练习的目的。 

### 最佳方法

 最佳方法是实现一个实际的单链表。 

每个节点存储：

 - 节点值
 - 指向下一个节点的指针

 我们还维护：

 - 虚拟头节点
 - 链表的当前大小

 虚拟头节点是一种常见的设计技术，可以简化插入和删除逻辑，因为每个真实节点总是有一个前驱节点。 

主要的见解是，一旦我们找到正确的位置，链表就擅长插入和删除。 由于我们只需要顺序遍历，所以单链表就足够了。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 每次插入/删除 O(n) | O(n) | 使用数组移位操作 |
 | 最佳 | 每次遍历操作 | O(n) O(n) | 真正的单链表实现 |

 ## 算法演练

 ### 数据结构设计

 我们定义一个`Node`结构包含：

 -`val`-`next`我们还维护：

 -`dummy`，一个虚拟头节点
 -`size`, 真实节点数

 ### 运营

 1.初始化链表

 创建一个虚拟节点，其`next`指针最初指向`None`。 将尺寸设置为`0`。 
2. 获取索引处的值

 首先验证索引。 如果索引为负数或者大于等于大小，则返回`-1`。 

否则，从以下位置开始遍历`dummy.next`并继续前进`index`次。 返回到达节点的值。 
3.添加在头部

 创建一个新节点。 

设置其`next`指向当前第一个节点的指针。 

更新`dummy.next`指向新节点。 

增加尺寸。 
4.添加在尾部

 遍历直至到达最终节点。 

将新节点附加到末尾。 

增加尺寸。 
5. 在索引处添加

 如果索引大于大小，则不执行任何操作。 

如果索引有效，则遍历到插入位置的前一个节点。 

通过仔细更新指针来插入新节点：

 -`newNode.next = prev.next`-`prev.next = newNode`增加尺寸。 
6. 删除索引处

 验证索引。 

遍历到目标节点的前一个节点。 

通过跳过目标节点来删除它：

 -`prev.next = prev.next.next`减小尺寸。 

### 为什么它有效

 链表始终维护有效的节点链，因为每次插入和删除都会一致地更新指针。 

虚拟头保证每个节点（包括真实头）都有一个前身。 这消除了头操作的特殊情况，并确保指针更新在所有操作中都是统一的。 

这`size`变量保证正确的边界检查，防止无效的内存访问并确保操作按照问题规范进行。 

## Python 解决方案```python
class Node:
    def __init__(self, val: int = 0, next_node=None):
        self.val = val
        self.next = next_node

class MyLinkedList:

    def __init__(self):
        self.dummy = Node()
        self.size = 0

    def get(self, index: int) -> int:
        if index < 0 or index >= self.size:
            return -1

        current = self.dummy.next

        for _ in range(index):
            current = current.next

        return current.val

    def addAtHead(self, val: int) -> None:
        self.addAtIndex(0, val)

    def addAtTail(self, val: int) -> None:
        self.addAtIndex(self.size, val)

    def addAtIndex(self, index: int, val: int) -> None:
        if index < 0 or index > self.size:
            return

        prev = self.dummy

        for _ in range(index):
            prev = prev.next

        new_node = Node(val)

        new_node.next = prev.next
        prev.next = new_node

        self.size += 1

    def deleteAtIndex(self, index: int) -> None:
        if index < 0 or index >= self.size:
            return

        prev = self.dummy

        for _ in range(index):
            prev = prev.next

        prev.next = prev.next.next

        self.size -= 1

# Your MyLinkedList object will be instantiated and called as such:
# obj = MyLinkedList()
# param_1 = obj.get(index)
# obj.addAtHead(val)
# obj.addAtTail(val)
# obj.addAtIndex(index,val)
# obj.deleteAtIndex(index)
```实施从一个单独的`Node`存储节点值和指向下一个节点的指针的类。 

这`MyLinkedList`构造函数初始化两个重要的成员：

 -`dummy`，这是虚拟头节点
 -`size`，跟踪真实节点的数量

 的`get`方法首先验证索引。 如果索引无效，则立即返回`-1`。 否则，从第一个真实节点开始遍历，直到到达请求的位置。 

这`addAtHead`和`addAtTail`方法重用`addAtIndex`，这避免了重复的插入逻辑。 

这`addAtIndex`方法遍历到插入前的前驱节点。 这很关键，因为单链表无法向后移动，因此我们需要前一个节点正确地重新连接指针。 

这`deleteAtIndex`方法类似地遍历前驱节点并绕过目标节点。 

使用虚拟节点极大地简化了插入和删除，因为前驱节点始终存在。 

## 解决方案```go
package main

type Node struct {
	val  int
	next *Node
}

type MyLinkedList struct {
	dummy *Node
	size  int
}

func Constructor() MyLinkedList {
	return MyLinkedList{
		dummy: &Node{},
		size:  0,
	}
}

func (this *MyLinkedList) Get(index int) int {
	if index < 0 || index >= this.size {
		return -1
	}

	current := this.dummy.next

	for i := 0; i < index; i++ {
		current = current.next
	}

	return current.val
}

func (this *MyLinkedList) AddAtHead(val int) {
	this.AddAtIndex(0, val)
}

func (this *MyLinkedList) AddAtTail(val int) {
	this.AddAtIndex(this.size, val)
}

func (this *MyLinkedList) AddAtIndex(index int, val int) {
	if index < 0 || index > this.size {
		return
	}

	prev := this.dummy

	for i := 0; i < index; i++ {
		prev = prev.next
	}

	newNode := &Node{
		val: val,
	}

	newNode.next = prev.next
	prev.next = newNode

	this.size++
}

func (this *MyLinkedList) DeleteAtIndex(index int) {
	if index < 0 || index >= this.size {
		return
	}

	prev := this.dummy

	for i := 0; i < index; i++ {
		prev = prev.next
	}

	prev.next = prev.next.next

	this.size--
}

/**
 * Your MyLinkedList object will be instantiated and called as such:
 * obj := Constructor()
 * param_1 := obj.Get(index)
 * obj.AddAtHead(val)
 * obj.AddAtTail(val)
 * obj.AddAtIndex(index,val)
 * obj.DeleteAtIndex(index)
 */
```Go 实现与 Python 解决方案非常相似，但有一些特定于语言的细节。 

Go 使用显式指针类型，例如`*Node`用于链接参考。 内存分配是使用处理的`&Node{}`。 

与 Python 不同，Go 没有`None`，所以我们使用`nil`对于缺少的指针。 

方法附于`MyLinkedList`struct 使用指针接收器，因此修改会影响原始链表实例。

 ## 边缘情况

 ### 访问无效索引

 链表实现中最常见的错误之一是无法正确验证索引。 如果`get()`使用有效范围之外的索引调用，遍历可以继续到`None`引用并导致运行时错误。 

此实现通过检查来防止这种情况：```
if index < 0 or index >= self.size:
    return -1
```这保证了仅对有效位置进行遍历。 

### 插入空列表

 空列表可能会很棘手，因为还没有真正的节点。 如果没有虚拟节点，在头部插入通常需要特殊的逻辑。 

虚拟节点消除了这种复杂性。 即使列表为空：```
dummy -> None
```插入通常只是重新连接指针：```
dummy -> newNode
```无需特殊处理。 

### 删除头节点

 删除第一个真实节点是指针错误的另一个常见来源。 在传统的单链表中，删除头通常需要重新分配头指针。 

由于此实现使用虚拟节点，因此第一个真实节点的前驱始终存在。 删除的工作方式与任何其他节点删除完全相同：```
prev.next = prev.next.next
```这使得逻辑简单且一致。
