[LeetCode 第 784 题](https://leetcode.com/problems/letter-case-permutation/)

 **难度：** 🟡 中等
 **主题：** 字符串、回溯、位操作

 ## 解决方案

 ## 问题理解

 该问题要求我们生成每个可能的字符串，这些字符串可以通过独立更改输入字符串中每个字母字符的大小写来形成。 

数字无法修改，因此它们在每个生成的结果中始终保持不变。 只有英文字母可以在小写和大写之间变化。 

例如，如果输入是`"a1b2"`，有两个字母，`'a'`和`'b'`。 每个字母都有两种可能的状态：

 - 小写
 - 大写

 这意味着组合总数为：$2^2 = 4$四个有效输出是：

 -`"a1b2"`-`"a1B2"`-`"A1b2"`-`"A1B2"`输入长度最多为12，比较小。 即使每个字符都是字母，最大排列数也是：$2^{12} = 4096$这足够小，显式生成所有组合是完全可行的。 

一个重要的观察是每个字母都代表一个二元选择：

 - 使用小写
 - 使用大写

 这自然意味着回溯或递归探索方法。 

一些边缘情况很重要：

 - 仅包含数字的字符串，例如`"123"`，应该返回一个结果，因为没有要修改的字母。 
- 仅包含字母的字符串会生成最大数量的组合。 
- 混合大写和小写输入应该仍然可以正常工作，因为每个字母始终可以转换为小写和大写。 
- 单字符字符串，例如`"a"`或者`"1"`仍应返回有效列表。 

该问题保证字符串只包含英文字母和数字，因此我们不需要处理特殊符号或Unicode字符。 

## 方法

 ### 蛮力方法

 蛮力策略会为字符串中的所有位置尝试大写和小写分配的所有可能组合，无论字符是数字还是字母。 

思考这个问题的一种方法是：

 - 假设字符串有长度`n`- 有潜在的`2^n`二元组合
 - 对于每个组合，决定每个位置是大写还是小写

 然而，这会浪费工作，因为数字实际上没有两种有效状态。 暴力方法仍然会迭代所有位掩码组合并重复处理永不改变的字符。 

该方法是正确的，因为它系统地探索了字符案例的每种可能的分配。 最终，每个有效排列都只出现一次。 

缺点是不必要的处理和不太清晰的逻辑。 

### 最优方法，回溯

 更好的方法是使用回溯，并且仅在当前字符是字母时才分支。 

关键的见解是：

 - 数字仅贡献一种选择
 - 字母恰好提供两个选择

 因此，我们不是探索无用的分支，而是逐个字符地递归构建字符串：

 - 如果当前字符是数字，则将其附加并继续。 
- 如果当前字符是字母：

 - 小写递归
 - 大写递归

 这避免了冗余工作并直接对问题的结构进行建模。 

回溯是一种自然的选择，因为我们在一系列选择下生成所有可能的组合。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n × 2^n) | O(n × 2^n) | O(n × 2^n) | O(n × 2^n) | 探索所有位掩码，无论字符是否为数字 |
 | 最佳| O(n × 2^L) | O(n × 2^L) | O(n × 2^L) | O(n × 2^L) | 仅在字母上分支，其中 L 是字母 |

 ## 算法演练

 ### 第 1 步：创建结果列表

 我们维护一个名为`result`存储所有生成的排列。 

每个完成的排列最终都会添加到这个列表中。 

### 步骤 2：定义回溯函数

 递归函数需要两条信息：

 - 字符串中的当前索引
 - 部分构造的字符串

 递归状态表示：

 >“从这个位置开始可以形成的所有有效排列。”

 ### 第 3 步：处理基本情况

 如果索引达到字符串的长度，则我们已经处理了每个字符。 

此时：

 - 当前路径形成完整的有效排列
 - 将其附加到结果列表中

 然后返回继续探索其他分支。 

### 步骤 4：处理数字

 如果当前字符是数字：

 - 附加它不变
 - 递归到下一个索引

 数字只创建一个分支，因为它们的值不能改变。 

### 第 5 步：处理信件

 如果当前字符是字母：

 - 使用小写递归一次
 - 使用大写递归一次

 这创建了生成每个有效排列的分支结构。 

### 第 6 步：继续，直到所有分支完成

 递归树最终会探索每种可能的字母大小写组合。 

递归完成后，结果列表包含所有有效字符串。 

### 为什么它有效

 该算法之所以有效，是因为每个字母都提供了两个独立的选择：小写或大写。 递归系统地探索每个字母的两种可能性，同时保留固定数字不变。 

在每个递归级别：

 - 1个角色位置已确定
 - 探索剩余位置的所有有效可能性

 由于每个有效选择都被探索一次，因此该算法会生成每个有效排列，而不会重复或遗漏。 

## Python 解决方案```python
from typing import List

class Solution:
    def letterCasePermutation(self, s: str) -> List[str]:
        result = []

        def backtrack(index: int, current: str) -> None:
            if index == len(s):
                result.append(current)
                return

            char = s[index]

            if char.isdigit():
                backtrack(index + 1, current + char)
            else:
                backtrack(index + 1, current + char.lower())
                backtrack(index + 1, current + char.upper())

        backtrack(0, "")
        return result
```实现首先创建一个空的`result`存储所有生成的排列的列表。 

嵌套的`backtrack`函数执行递归探索。 它接受：

 -`index`，输入字符串中的当前位置
 -`current`，部分构造的排列

 基本情况发生在`index == len(s)`。 这意味着每个字符都已被处理，因此构造的字符串是完整的并添加到结果列表中。 

对于每个递归步骤：

 - 如果字符是数字，则递归仅在一个分支上继续，因为数字不会改变。 
- 如果字符是字母，则递归分支为两条路径：

 - 小写版本
 - 大写版本

 递归树自然地生成所有有效的组合。 

最后算法从索引开始递归`0`带有一个空字符串。 

## 解决方案```go
func letterCasePermutation(s string) []string {
	var result []string

	var backtrack func(index int, current string)

	backtrack = func(index int, current string) {
		if index == len(s) {
			result = append(result, current)
			return
		}

		char := s[index]

		if char >= '0' && char <= '9' {
			backtrack(index+1, current+string(char))
		} else {
			lower := string(char | 32)
			upper := string(char &^ 32)

			backtrack(index+1, current+lower)
			backtrack(index+1, current+upper)
		}
	}

	backtrack(0, "")
	return result
}
```Go 解决方案遵循与 Python 版本相同的递归结构。 

一个显着的区别是字符大小写转换的处理方式。 该实现使用 ASCII 位操作，而不是重复调用内置字符串方法：

 -`char | 32`将字母转换为小写
 -`char &^ 32`将字母转换为大写

 这是可行的，因为英文字母遵循可预测的 ASCII 位模式。 

Go 字符串是不可变的，就像 Python 字符串一样，因此串联会在递归期间创建新字符串。 

结果切片开始为`nil`，这在 Go 中完全有效并且行为正确`append`。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n × 2^L) | O(n × 2^L) | 有`2^L`排列，每个排列需要最多`n`构建角色 |
 | 空间| O(n × 2^L) | O(n × 2^L) | 输出存储占主导地位，递归深度最多`n`|

 这里，`L`表示字符串中字母字符的数量。 

每个字母使生成的排列数量加倍。 由于每个生成的字符串都有长度`n`，构建和存储结果需要成比例的工作和内存。 

递归栈本身只需要`O(n)`空间，但输出列表主导了总内存使用量。

 ## 边缘情况

 ### 输入仅包含数字

 像这样的字符串`"12345"`假设每个角色创建两个分支，可以很容易地暴露实现中的错误。 

在这种情况下，正确答案恰好包含一个字符串，因为数字永远不会改变。 该实现通过在任何时候仅创建一个递归分支来正确处理这一问题`isdigit()`返回真。 

### 输入仅包含字母

 像这样的字符串`"abcd"`创建其长度的最大排列数。 

这很重要，因为递归树在每个字符处都会加倍。 该实现正确地探索每个位置的小写和大写分支，生成所有`2^n`的可能性。 

### 输入已包含大写字母

 输入如`"aB"`很重要，因为一些不正确的解决方案仅将小写字母转换为大写字母，而忽略现有的大写字母。 

该实现通过始终生成以下内容来避免此问题：

 -`char.lower()`-`char.upper()`无论输入的原始大小写如何，这都保证了正确性。 

### 单字符输入

 输入如`"a"`或者`"7"`是最小边界情况。 

这些案例验证了：

 - 递归正确终止
 - 基本情况正确附加完整的字符串
 - 不生成额外的排列

 该实现自然地处理这些问题，因为当索引达到字符串长度时，递归恰好停止。
