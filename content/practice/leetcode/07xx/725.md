[LeetCode 725 题](https://leetcode.com/problems/split-linked-list-in-parts/)

 **难度：** 🟡 中等
 **主题：** 链接列表

 ## 解决方案

 ## 问题理解

 该问题给出了一个单链表的头和一个整数`k`。 我们必须将链表精确地划分为`k`连续部分，同时保留节点的原始顺序。 

重要的要求是零件的尺寸应尽可能均匀。 这意味着：

 - 任意两个零件之间的尺寸差异最多为 1。 
- 较早的部分必须大于或等于较晚的部分。 

例如，如果链表有 10 个节点并且`k = 3`，那么理想的分布是：

 - 10 ÷ 3 = 每个部分 3 个节点
 - 剩余 1 个额外节点

 所以第一个`1`部分获得一个额外的节点：

 - 第 1 部分 → 4 个节点
 - 第 2 部分 → 3 个节点
 - 第 3 部分 → 3 个节点

 如果链表的节点数少于`k`，某些部分必须是`null`。 例如：

 - 3个节点
 -`k = 5`分裂变成：

 -`[1]`-`[2]`-`[3]`-`[]`-`[]`输入代表：

 -`head`，单链表的第一个节点
 -`k`，我们必须生产的零件数量

 输出是一个数组`k`链表头，其中每个条目都指向一个分割部分的开头。 

限制相对较小：

 - 最多1000个节点
 -`k`最多 50 个

 这意味着即使效率较低的方法仍然会通过，但问题从根本上来说是关于正确的链表操作和仔细的大小分布。 

一些边缘情况很重要：

 - 列表可能为空
 -`k`可能大于节点数
 - 列表长度可以除以`k`- 列表长度可能会留下余数
 - 我们必须通过设置正确终止每个分割`next = None`A naive implementation can easily forget to disconnect parts correctly, causing multiple returned parts to still point into later sections of the original list.

 ## 方法

 ### 蛮力方法

 一个简单的暴力解决方案首先将所有链表节点复制到一个数组中。 一旦节点存储在索引结构中，我们就可以计算每个部分的目标大小并相应地重新连接节点。 

该过程如下所示：

 1. 遍历链表并将每个节点存储在数组中。 
2. 计算：

 - 基础尺寸=`n // k`- 额外节点=`n % k`3. 将数组分成正确大小的组。 
4. 断开每个组的尾节点与下一组的连接。 

这种方法之所以有效，是因为数组提供直接索引，使分区变得容易。 

但是，此方法使用与节点数量成比例的额外内存。 由于链表已经可以直接遍历，所以不需要存储所有节点。 

### 最佳方法

 最佳解决方案避免将节点存储在辅助数组中。 

关键的观察是我们只需要两条信息：

 - 节点总数
 - 每个部分应包含多少个节点

 一旦我们知道总长度`n`，我们可以确定：

 - 每个部分至少得到`n // k`节点
 - 第一个`n % k`零件获得一个额外的节点

 计算完这些大小后，我们再次遍历链表并将其切成所需长度的段。 

这很有效，因为：

 - 每个节点仅被访问固定次数
 - 没有额外的存储空间`n`是必需的
 - 链表天然支持顺序分区

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(n) | 在分割之前将所有节点存储在数组中 |
 | 最佳| O(n) | O(1) | O(1) | 直接就地计算尺寸和分割 |

 ## 算法演练

 ### 最优算法

 1、遍历链表一次，统计节点总数。 

我们需要总长度，因为分割大小完全取决于总体存在的节点数量。 
2. 计算每个零件的基础尺寸。```
base_size = total_nodes // k
```每个部分必须至少包含这么多节点。 
3. Compute how many extra nodes remain.```
extra_nodes = total_nodes % k
```这些额外的节点被一一分配到前面的部分。 
4. 创建一个size的结果数组`k`。 

每个元素将存储一个链表部分的头。 
5. 再次开始遍历链表。 

对于每个部分：

 - 确定其大小：```
current_size = base_size + 1
```如果额外的节点仍然可用，否则：```
current_size = base_size
```6. 将当前节点记录为当前部分的头部。 

该节点成为分割段的起点。 
7. 前进`current_size - 1`次。 

这使我们处于当前部分的末尾。 
8. 从剩余列表中断开当前部分。 

节省：```
next_part = current.next
```然后剪切：```
current.next = None
```9. 继续处理剩余的节点。 

移动：```
current = next_part
```10.重复直到所有`k`零件已创建。 

### 为什么它有效

 该算法保证了正确性，因为：

 - 每个节点都属于一个部分
 - 零件按原始顺序连续创建
 - 每个部分接收：

 -`base_size`- 或者`base_size + 1`- 只有第一个`extra_nodes`零件尺寸较大

 因此：

 - 尺寸差异永远不会超过一
 - 早期的部分永远不会比后来的部分小
 - 所有节点都只包含一次

 ## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

from typing import List, Optional

class Solution:
    def splitListToParts(
        self,
        head: Optional[ListNode],
        k: int
    ) -> List[Optional[ListNode]]:
        
        # Count total nodes
        total_nodes = 0
        current = head
        
        while current:
            total_nodes += 1
            current = current.next
        
        # Determine base size and extra nodes
        base_size = total_nodes // k
        extra_nodes = total_nodes % k
        
        result = []
        current = head
        
        for i in range(k):
            part_head = current
            current_part_size = base_size
            
            # Earlier parts get one extra node
            if i < extra_nodes:
                current_part_size += 1
            
            # Move to the tail of current part
            for _ in range(current_part_size - 1):
                if current:
                    current = current.next
            
            # Disconnect current part
            if current:
                next_part = current.next
                current.next = None
                current = next_part
            
            result.append(part_head)
        
        return result
```实现首先计算链表中的节点数。 这是必要的，因为节点的分布取决于总大小。 

获得总计数后，算法计算：

 -`base_size`，每个部分接收的最小节点数
 -`extra_nodes`，应接收一个附加节点的零件数量

 主循环完全运行`k`次，因为我们必须始终准确返回`k`零件，即使有些是空的。 

对于每次迭代：

 -`part_head`存储当前段的开头
 -`current_part_size`确定有多少个节点属于该部分
 - 遍历前进到该段的尾节点
 - 尾部通过设置断开`current.next = None`断开连接的段将附加到结果数组中。 

如果节点数少于`k`，一些迭代自然会产生`None`零件因为`current`变成`None`。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func splitListToParts(head *ListNode, k int) []*ListNode {
    
    // Count total nodes
    totalNodes := 0
    current := head
    
    for current != nil {
        totalNodes++
        current = current.Next
    }
    
    baseSize := totalNodes / k
    extraNodes := totalNodes % k
    
    result := make([]*ListNode, 0, k)
    current = head
    
    for i := 0; i < k; i++ {
        
        partHead := current
        currentPartSize := baseSize
        
        if i < extraNodes {
            currentPartSize++
        }
        
        // Move to tail of current part
        for j := 0; j < currentPartSize-1; j++ {
            if current != nil {
                current = current.Next
            }
        }
        
        // Disconnect current part
        if current != nil {
            nextPart := current.Next
            current.Next = nil
            current = nextPart
        }
        
        result = append(result, partHead)
    }
    
    return result
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一些 Go 的具体细节值得注意：

 -`nil`被用来代替`None`- 切片用于存储结果
 - 整数除法自动截断为零
 - 指针操作是显式的`*ListNode`由于约束很小，因此不必担心整数溢出。

 ## 边缘情况

 ### 空链表

 如果`head`是`None`，链表包含零个节点。 如果实现假设至少存在一个节点，这种情况很容易导致错误。 

该算法自然地处理这个问题，因为：

 -`total_nodes`变成`0`- 每个零件尺寸都变成`0`- 每次迭代都会追加`None`结果正确包含`k`空零件。 

### 零件多于节点

 当`k > n`，某些部分必须为空。 

一个常见的错误是意外地创建了少于`k`部分或在后续部分中错误地分配节点。 

该实现通过始终精确迭代来解决这个问题`k`次。 当所有节点都耗尽后，`current`变成`None`，其余部分作为空列表附加。 

### 正确断开零件

 一个微妙的错误是忘记切断相邻部件之间的连接。 

例如：```
[1,2,3,4]
```如果第一部分应该是`[1,2]`但我们从未设置过：```
current.next = None
```那么第一个返回的部分仍然指向`[3,4]`。 

该实现在断开当前尾节点之前显式存储下一个段头。 这保证了每个返回的部分都是一个独立的链表段。
