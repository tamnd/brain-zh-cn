 # 樱桃拾音器 - LeetCode 741

 ## 问题理解

 这个问题要求我们在方形网格上进行两次旅行时收集尽可能多的樱桃。 

第一次旅行从左上角开始`(0, 0)`并移动到右下角`(n - 1, n - 1)`只使用向右或向下的移动。 到达目的地后，我们必须仅使用向左或向上的移动返回起点。 

网格包含三种单元：

 -`0`表示单元格为空并且可以遍历。 
-`1`表示细胞内含有可采集的樱桃。 
-`-1`means the cell contains a thorn and cannot be traversed.

 当樱桃被拿起一次后，它就会从网格中消失。 This means the same cherry cannot be collected twice.

 目标是计算两次旅行中可以收集到的樱桃的最大总数。 如果从起点到目的地不存在有效路径，则答案必须是`0`。 

At first glance, this looks like a pathfinding problem with two separate traversals. 然而，独立优化前向和后向行程是行不通的，因为在第一次行程期间做出的选择会改变第二次行程的电网状态。 

约束条件很重要：

 -`n`可以大到`50`- 网格最多有`2500`细胞

 单纯的穷举搜索成本太高，因为可能路径的数量呈指数级增长。 

一些边缘情况很重要：

 - 目的地可能因荆棘而无法到达。 
- 起始或目标单元格可能包含樱桃。 
- 两次旅行可能会严重重叠。 
- 多条最优路径可以共享小区。 
- 当两次遍历访问同一个单元格时，我们必须避免重复计算樱桃。 

最重要的概念洞察是，向前和向后的旅行可以转化为两个人从`(0, 0)`到`(n - 1, n - 1)`同时地。 

## 方法

 ### 蛮力方法

 暴力解决方案尝试从起点到目的地的每条可能的路径，然后对于每条这样的路径，修改网格并尝试每条可能的返回路径。 

一条路径从`(0, 0)`到`(n - 1, n - 1)`恰好包含`2n - 2`移动，每一步都有两种选择，要么向右，要么向下。 这将创建指数数量的可能路径。 

对于每条前进道路，我们需要：

 1.模拟采摘樱桃。 
2.修改网格。 
3.探索每条有效的返回路径。 
4. 追踪樱桃的最大总数。 

这种方法是正确的，因为它检查了前进和后退旅程的所有可能组合。 然而，它很快在计算上变得不可行。 

为了`n = 50`，路径的数量是天文数字。 

### 最佳解决方案的关键见解

 主要见解是，向前旅行和向后旅行可以建模为两个人同时从起点步行到目的地。 

为什么这有效？ 

- 前进的旅程仅使用向右和向下的移动。 
- 回程仅使用向左和向上的移动。 
- 如果我们反转回程，它也会成为使用向右和向下移动从起点到目的地的路径。 

现在我们可以将问题视为：

 > 两名旅客出发时间为`(0,0)`并且两者都朝着`(n-1,n-1)`同时地。 

每一步：

 - 每个旅行者向右或向下移动。 
- 两名旅行者的总步数相同。 
- 如果两者都落在同一个单元格上，我们只计算樱桃一次。 

这种转换消除了复杂的“修改行程之间的网格”问题。 

状态变为：

 - 旅行者1的位置：`(r1, c1)`- 旅行者2的位置：`(r2, c2)`由于两个旅行者走了相同的步数：```
r1 + c1 = r2 + c2
```这使我们能够从其他坐标导出一个坐标并减少 DP 状态维数。 

然后，我们使用带有记忆功能的动态编程来计算每个州可收集的最大樱桃数。

 ## 算法演练

 ### 第 1 步：重新定义问题

 不要考虑一个人前进和后退，而要考虑两个人从`(0,0)`并走向`(n-1,n-1)`同时地。 

每移动一步，总步数就会增加一。 

### 步骤 2：定义 DP 状态

 让：```
dp(r1, c1, r2)
```代表在以下情况下可收集的最大樱桃数：

 - 旅客 1 位于`(r1, c1)`- 旅行者 2 号位于`(r2, c2)`由于两位旅行者走了相同的步数：```
r1 + c1 = r2 + c2
```我们可以计算：```
c2 = r1 + c1 - r2
```这将状态空间从 4 维减少到 3 维。 

### 步骤 3：处理无效状态

 如果满足以下条件，则状态无效：

 - 任何坐标都超出网格范围
 - 任一旅行者降落在刺细胞上

 对于无效状态，返回负无穷大，以便在最大值计算中永远不会选择它们。 

### 步骤 4：处理目的地

 如果两位旅客都到达`(n-1, n-1)`，返回该单元格的值。 

这是基本情况。 

### 第 5 步：收集樱桃

 在每个状态：

 - 在钢丝圈1的位置添加樱桃
 - 在钢丝圈2的位置添加樱桃
 - 如果两个旅客都在同一个牢房内，则仅计数一次

 ### 第 6 步：探索四种可能的移动组合

 每个旅行者都可以向右或向下移动。 

这将创建四种组合：

 1. 向下，向下
 2. 下、右
 3. 右、下
 4. 对对对

 在这些递归调用中取最大结果。 

### 第 7 步：记住结果

 许多状态在递归期间重复。 

使用记忆来缓存每个状态的结果，以便每个状态仅计算一次。 

### 步骤 8：返回最终答案

 如果不存在有效路径，则递归可能返回负值。 

在这种情况下，返回`0`。 

否则，返回计算出的最大值。 

### 为什么它有效

 该算法之所以有效，是因为每个有效的前向和后向行程对完全对应于两个同时的前向遍历。 DP 状态在相同步数后完全捕获两个旅行者的位置。 通过探索所有移动组合并记忆结果，该算法保证每对有效路径都被恰好考虑一次。 仅对共享单元进行一次计数就可以正确模拟樱桃去除行为。 

## Python 解决方案```python
from typing import List
from functools import lru_cache

class Solution:
    def cherryPickup(self, grid: List[List[int]]) -> int:
        n = len(grid)

        @lru_cache(None)
        def dp(r1: int, c1: int, r2: int) -> int:
            c2 = r1 + c1 - r2

            # Out of bounds
            if (
                r1 >= n or c1 >= n or
                r2 >= n or c2 >= n
            ):
                return float('-inf')

            # Thorn cell
            if (
                grid[r1][c1] == -1 or
                grid[r2][c2] == -1
            ):
                return float('-inf')

            # Reached destination
            if r1 == n - 1 and c1 == n - 1:
                return grid[r1][c1]

            cherries = grid[r1][c1]

            # Avoid double counting
            if (r1, c1) != (r2, c2):
                cherries += grid[r2][c2]

            best_next = max(
                dp(r1 + 1, c1, r2 + 1),  # down, down
                dp(r1 + 1, c1, r2),      # down, right
                dp(r1, c1 + 1, r2 + 1),  # right, down
                dp(r1, c1 + 1, r2)       # right, right
            )

            cherries += best_next

            return cherries

        result = dp(0, 0, 0)

        return max(0, result)
```实现首先定义一个记忆递归函数`dp`。 

该状态使用三个坐标，因为第四个坐标可以从所采取的步数总数中得出。 这显着减少了状态空间。 

该函数的第一部分检查状态是否有效。 如果旅行者出界或落在荆棘上，则该状态是不可能的并返回负无穷大。 

基本情况发生在旅行者 1 到达目的地时。 由于两个旅行者总是走相同的步数，因此旅行者 2 也必须在那里。 

然后代码从两个位置收集樱桃。 如果两个旅行者占据同一个牢房，则樱桃仅计算一次。 

接下来，算法递归地探索所有四种移动组合并选择最大的未来值。 

最后，该函数返回当前的樱桃以及未来的最佳结果。 

外部函数开始递归`(0,0)`对于双方旅行者来说，并确保负面结果变成`0`。 

## 解决方案```go
package main

import "math"

func cherryPickup(grid [][]int) int {
	n := len(grid)

	type State struct {
		r1 int
		c1 int
		r2 int
	}

	memo := make(map[State]int)

	var dp func(int, int, int) int

	dp = func(r1, c1, r2 int) int {
		c2 := r1 + c1 - r2

		// Out of bounds
		if r1 >= n || c1 >= n || r2 >= n || c2 >= n {
			return math.MinInt32
		}

		// Thorn cells
		if grid[r1][c1] == -1 || grid[r2][c2] == -1 {
			return math.MinInt32
		}

		// Destination
		if r1 == n-1 && c1 == n-1 {
			return grid[r1][c1]
		}

		state := State{r1, c1, r2}

		if val, exists := memo[state]; exists {
			return val
		}

		cherries := grid[r1][c1]

		// Avoid double counting
		if r1 != r2 || c1 != c2 {
			cherries += grid[r2][c2]
		}

		bestNext := max(
			dp(r1+1, c1, r2+1),
			dp(r1+1, c1, r2),
			dp(r1, c1+1, r2+1),
			dp(r1, c1+1, r2),
		)

		cherries += bestNext

		memo[state] = cherries

		return cherries
	}

	result := dp(0, 0, 0)

	if result < 0 {
		return 0
	}

	return result
}

func max(values ...int) int {
	best := values[0]

	for _, v := range values {
		if v > best {
			best = v
		}
	}

	return best
}
```Go 实现遵循与 Python 解决方案相同的算法结构。 由于 Go 不提供像 Python 那样的内置记忆化装饰器`lru_cache`，我们明确维护一个由自定义键控的哈希映射`State`结构。 

负无穷大用以下方式表示`math.MinInt32`。 

Go 切片是引用类型，因此网格可以高效传递而无需复制。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n3) | 有 O(n³) 个独特的 DP 状态，每个状态处理一次 |
 | 空间| O(n3) | 记忆存储 O(n³) 状态 |

 状态空间由三个自变量组成：

 -`r1`-`c1`-`r2`每个范围从`0`到`n-1`。 

第四个坐标是通过数学推导得出的，这将复杂性从 O(n⁴) 降低到 O(n3)。 

每个状态在恒定时间内计算四个转换，因此总运行时间仍然是 O(n³)。

from functools import lru_cache

class Solution:
    def cherryPickup(self, grid: List[List[int]]) -> int:
        n = len(grid)

        @lru_cache(None)
        def dp(r1: int, c1: int, r2: int) -> int:
            c2 = r1 + c1 - r2

            if (
                r1 >= n or c1 >= n or
                r2 >= n or c2 >= n
            ):
                return float('-inf')

            if (
                grid[r1][c1] == -1 or
                grid[r2][c2] == -1

                return float('-inf')

            if r1 == n - 1 and c1 == n - 1:
                return grid[r1][c1]

            cherries = grid[r1][c1]

            if (r1, c1) != (r2, c2):

            cherries += max(
                dp(r1 + 1, c1, r2 + 1),
                dp(r1 + 1, c1, r2),
                dp(r1, c1 + 1, r2 + 1),
                dp(r1, c1 + 1, r2)
            )

            return cherries

        return max(0, dp(0, 0, 0))

 ## 边缘情况

 ### 完全封锁的路径

 网格中可能包含荆棘位置，导致无法到达目的地。 幼稚的实现可能仍会尝试计算部分路径或意外返回负值。 

此实现通过针对无效状态返回负无穷大来处理阻塞路径。 如果所有可能的转换都无效，则最终答案变为否定，外部函数将其转换为`0`。 

### 两个旅行者在同一个牢房

 在同时穿越期间，两个旅行者可能同时降落在同一个单元格上。 如果不小心处理，算法就会把樱桃数两次。 

实现明确检查：```
if (r1, c1) != (r2, c2):
```这保证了共享单元仅贡献一次。 

### 单细胞网格

 当`n = 1`，起点和目的地是同一个单元格。 简单的递归解决方案可能会处理不当，因为没有发生任何移动。 

当到达目的地时，基本情况立即返回单元格值，这可以正确处理单个单元格输入。 

### 严重路径重叠

 有时，最佳策略需要两次遍历以重用许多相同的单元格。 试图独立地最大化第一次行程的贪婪方法常常在这里失败。 

同时遍历 DP 模型自然会正确重叠，因为两个旅行者是一起优化而不是独立优化。
