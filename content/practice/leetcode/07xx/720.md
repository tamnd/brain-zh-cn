 # LeetCode 720，字典中最长的单词

 ## 问题理解

 这个问题给了我们一组小写英语单词，并要求我们找到可以使用同一字典中的其他单词一次构造一个字符的最长单词。 

更具体地说，假设我们有一个候选词，例如`"world"`。 为了使这个单词有效，通过从末尾删除字符形成的每个前缀也必须存在于字典中：

 -`"w"`-`"wo"`-`"wor"`-`"worl"`-`"world"`所有这些都必须出现在输入数组中。 

问题不在于要求整体最长的单词。 相反，它要求整个前缀链也存在于字典中的最长单词。 

如果多个单词满足条件并且具有相同的最大长度，我们返回字典顺序最小的一个。 字典顺序意味着正常的字典顺序，所以`"apple"`出现在之前`"apply"`因为`'e' < 'y'`。 

输入包括：

 -`words`，小写字符串数组
 - 每个单词长度介于`1`和`30`- 字数最多为`1000`限制相对较小，这意味着有多种方法是可行的。 然而，我们仍然需要一个高效、干净的解决方案。 

一个重要的细节是前缀本身必须是字典中的完整单词。 存在于另一个单词内部的子串并不重要。 只有前缀链才重要。 

考虑几个边缘情况很重要：

 - 一个单词可能没有其必需的前缀而存在
 - 可能存在多个最长的候选者
 - 字典可能只包含一个字母的单词
 - 没有比长度更长的有效链`1`可能存在
 - 单词可能以任意顺序出现

 例如：```
["banana", "ban", "ba", "b"]
```虽然`"banana"`存在，它是无效的，因为像这样的前缀`"bana"`和`"banan"`不存在。 

该问题保证所有单词只包含小写英文字母，从而简化了比较和存储。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是单独检查每个单词并验证其所有前缀是否都存在于字典中。 

我们可以首先将所有单词放入一个哈希集中，以便进行高效查找。 然后，对于每个单词：

 1. 根据长度生成每个前缀`1`最多`len(word) - 1`2. 检查每个前缀是否存在于集合中
 3. 如果每个前缀都存在，则该单词有效
 4. 跟踪迄今为止找到的最佳有效单词

 这种方法可以正常工作，因为当一个单词的所有前缀都存在时，它就是有效的。 

然而，该方法会重复重建许多单词的前缀。 虽然在这些限制下仍然可以接受，但我们可以改进解决方案的组织和优雅。 

### 最佳解决方案的关键见解

 关键的观察是，只有当单词的直接前导前缀已经有效时，该单词才有效。 

例如：

-`"ap"`有效，如果`"a"`存在
 -`"app"`有效，如果`"ap"`有效
 -`"appl"`有效，如果`"app"`有效

 这自然建议按排序顺序处理单词。 

如果我们按字典顺序对单词进行排序，较短的前缀会出现在较长的扩展名之前：```
"a", "ap", "app", "appl", "apple"
```我们可以维护一组有效的可构建单词：

 - 单字词自动有效
 - 较长的单词有效，如果`word[:-1]`已存在于有效集合中

 这避免了重复检查每个前缀。 相反，每个单词只检查其直接前一个单词。

 ## 算法演练

 ### 最优算法

 1. 按字典顺序对单词进行排序。 

排序可确保较短的前缀先于依赖于它们的较长单词进行处理。 例如，`"app"`将出现在之前`"apple"`。 
2. 创建一个名为`buildable`。 

该集合存储可以一次成功构造一个字符的所有单词。 
3.初始化一个空字符串`answer`。 

该变量跟踪迄今为止找到的最佳有效单词。 
4. 按排序顺序迭代每个单词。 

对于每个单词，确定它是否可以由较小的有效单词构建。 
5. 如果字长为`1`，它是自动可构建的。 

单字符单词没有更小的前缀需要验证。 
6. 否则，检查是否`word[:-1]`存在于`buildable`。 

这是有效的，因为如果立即前缀是可构建的，那么所有较早的前缀也必须已经有效。 
7. 如果该词有效：

 - 添加到`buildable`- 比较一下`answer`- 更新`answer`如果：

 - 这个词更长，或者
 - 该单词具有相同的长度，但按字典顺序较小
 8.处理完所有单词后，返回`answer`。 

### 为什么它有效

 该算法保持了内部每个单词的不变性`buildable`可以从其他有效单词一次构造一个字符。 

因为单词是按排序顺序处理的，所以当我们评估一个单词时`"apple"`，其所需的前身`"appl"`已经被处理了。 如果`"appl"`是可构建的，那么通过归纳，所有早期的前缀也是可构建的。 

因此，仅检查`word[:-1]`足以保证整个前缀链存在。 

## Python 解决方案```python
from typing import List

class Solution:
    def longestWord(self, words: List[str]) -> str:
        words.sort()

        buildable = set()
        answer = ""

        for word in words:
            if len(word) == 1 or word[:-1] in buildable:
                buildable.add(word)

                if len(word) > len(answer):
                    answer = word

        return answer
```该实现首先按字典顺序对输入列表进行排序。 这种顺序很重要，因为前缀自然出现在其较长的扩展名之前。 

这`buildable`set 存储所有满足构造规则的单词。 每当我们处理一个单词时，我们都会检查它是否有效：

 - 单字词始终有效
 - 较长的单词需要其直接前缀已存在于`buildable`一旦确认某个单词有效，我们就把它插入到集合中。 

这`answer`变量跟踪迄今为止遇到的最长有效单词。 由于数组预先按字典顺序排序，因此关系会自动偏向较小的字典顺序单词。 因此我们只需要更新`answer`当我们找到一个严格更长的单词时。 

这创建了一个简洁高效的解决方案。 

## 解决方案```go
package main

import (
	"sort"
)

func longestWord(words []string) string {
	sort.Strings(words)

	buildable := make(map[string]bool)
	answer := ""

	for _, word := range words {
		if len(word) == 1 || buildable[word[:len(word)-1]] {
			buildable[word] = true

			if len(word) > len(answer) {
				answer = word
			}
		}
	}

	return answer
}
```Go 实现遵循与 Python 版本相同的逻辑。 

主要区别在于 Go 使用`map[string]bool`而不是 Python 集。 表达式：```go
buildable[word[:len(word)-1]]
```检查前缀是否已存在。 

Go 字符串支持按索引切片，这样可以轻松提取立即前缀。 

由于输入约束很小，因此不必担心整数溢出或内存使用过多。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n log n + n × m) | O(n log n + n × m) | 最初排序占主导地位，然后每个单词执行一次前缀查找 |
 | 空间| O(n) | 可构建集存储有效单词 |

 排序步骤成本`O(n log n)`。 

排序后，每个单词执行：

 - 1个子串操作
 - 一次哈希查找
 - 可能是一次插入

 每个子串操作的成本高达`O(m)`在哪里`m`是最大字长。 

因此，总的加工成本为`O(n × m)`排序后。 

辅助空间为`O(n)`因为集合可以存储每个单词。

 ## 边缘情况

 ### 没有完整前缀链的单词

 一个非常常见的错误是仅检查某些前缀是否存在而不是要求所有前缀。 

例如：```
["banana", "ban", "ba", "b"]
```这个词`"banana"`无效，因为前缀如`"bana"`和`"banan"`不存在。 

该实现通过要求避免此错误`word[:-1]`已经可以建造了。 由于可构建性逐渐传播，因此保证每个较早的前缀也存在。 

### 词典平局打破

 当多个有效单词共享相同的最大长度时，会出现另一种棘手的情况。 

例如：```
["apple", "apply"]
```两者都可能有效，但问题需要字典顺序较小的单词。 

在处理之前按字典顺序对数组进行排序自然可以保证这种行为。 自从`"apple"`出现在之前`"apply"`，并且我们仅在找到严格更长的单词时才替换答案，`"apple"`仍然是最终答案。 

### 缺少一个字符前缀

 一个单词可能看起来几乎有效，但由于缺少一个前缀而失败。 

例子：```
["a", "ap", "apple"]
```这个词`"apple"`需要`"appl"`存在，但它不存在。 

幼稚的实现可能会错误地认为较早的前缀就足够了。 我们的解决方案正确检查直接前导前缀：```
word[:-1]
```自从`"appl"`缺席，`"apple"`立即被拒绝。
