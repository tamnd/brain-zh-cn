 # LeetCode 765 - 情侣牵手

 ## 问题理解

 这个问题给了我们用数组表示的一排座位`row`，其中每个值都是当前坐在该座位上的人的 ID。 该行包含`2n`人，意味着确实有`n`情侣。 

这对夫妇以非常具体的方式预先定义：

 - 人`0`与`1`- 人`2`与`3`- 人`4`与`5`- 等等

 换句话说，对于任何人来说`x`，他们的伙伴可以直接计算：

 - 如果`x`是偶数，他们的伙伴是`x + 1`- 如果`x`很奇怪，他们的搭档是`x - 1`一个方便的数学观察是：```
partner = x ^ 1
```因为在一对的两个成员之间切换最后一个二进制位。 

目标是确定所需的最少交换次数，以便每对夫妇坐在相邻的座位上。 交换可以交换行中的任意两个人，无论他们当前的位置如何。 

重要的细节是座位位置成对分组：

 - 座位`(0,1)`形成一张沙发
 - 座位`(2,3)`形成另一个沙发
 - 座位`(4,5)`形成另一个沙发

 对于每对相邻的座位，我们希望坐在那里的两个人属于同一对夫妇。 

限制相对较小：

 -`2 <= n <= 30`- 最大行大小仅`60`尽管输入大小足够小，许多解决方案都可以通过，但问题本质上是关于识别结构并应用干净的贪婪或基于图形的策略。 

一些边缘情况很重要：

 - 该行可能已经完美排列，需要零交换。 
- 多对情侣可能会周期性地错位，需要小心交换顺序。 
- 随机交换的幼稚策略很容易执行不必要的操作。 
- 由于所有元素都是唯一的，我们永远不需要处理重复或歧义。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试探索所有可能的交换顺序，直到所有夫妇都坐在一起。 

在每一步中，我们可以：

 1. 找到一对不包含有效情侣的相邻座位。 
2. 尝试将其中一个人与其他所有可能的人交换。 
3. 递归地继续，直到排列生效。 
4. 跟踪所见的最小交换量。 

这种方法是正确的，因为它探索所有有效的交换序列并最终找到最佳的交换序列。 

然而，可能的座位安排数量呈阶数增长。 即使对于相对较小的输入，搜索空间也会变得巨大。 回溯和剪枝可能会在一定程度上减少搜索量，但与最优贪心解相比仍然不切实际。 

### 最优贪心法

 关键的见解是每个座位对都可以以贪婪的方式独立固定。 

假设我们看座位`(i, i+1)`：

- 人`row[i]`已经固定到位。 
- 我们确切地知道他们的合作伙伴应该是谁。 
- 如果合作伙伴尚未到达`row[i+1]`，那么最优的举动就是将正确的伙伴交换到座位上`i+1`。 

为什么这总是最佳的？ 

因为每一个有效的最终安排都必须在旁边放置正确的合作伙伴`row[i]`。 执行该交换会立即永久解决当前对，而不会产生其他问题。 

为了提高交换效率，我们维护一个从人员 ID 到其当前座位索引的哈希映射。 这使我们能够在恒定的时间内找到任何合作伙伴。 

这将问题转化为简单的贪婪模拟。

 ## 算法演练

 ### 贪心+哈希图算法

 1. 创建一个名为的哈希图`position`。 

该地图存储每个人的当前座位索引。 例如：```
position[person] = index
```我们使用它是因为我们经常需要快速找到一个人的伴侣。 
2. 一次遍历一排两个座位。 

由于情侣必须占据相邻座位，因此我们处理索引：```
0, 2, 4, 6, ...
```每次迭代处理一张沙发。 
3. 假设坐在沙发上的第一个人是：```
first_person = row[i]
```4. 计算出他们的正确搭档。 

由于偶数是连续整数：```
partner = first_person ^ 1
```示例：```
0 ^ 1 = 1
1 ^ 1 = 0
2 ^ 1 = 3
3 ^ 1 = 2
```5. 检查伙伴是否已经坐在他们旁边。 

如果：```
row[i + 1] == partner
```那么这个沙发已经是正确的，所以继续。 
6. 否则，执行一次交换。 

我们知道合伙人最终必须就位`i + 1`。 

使用哈希映射来定位伙伴：```
partner_index = position[partner]
```交换：```
row[i + 1], row[partner_index] = row[partner_index], row[i + 1]
```7. 更新哈希图。 

交换后，被移动的人有新的索引，因此更新两个条目`position`。 
8. 增加交换计数器。 

每次修正都需要一次交换。 
9. 继续，直到处理完所有沙发。 

### 为什么它有效

 该算法保持了每个处理过的沙发都是永久正确的不变性。 

当我们处理座位时`(i, i+1)`， 人`row[i]`最终必须在任何有效的解决方案中与他们的合作伙伴坐在一起。 将正确的搭档直接换到座位上`i+1`立即通过一次必要的交换来修复那张沙发。 

由于修复一张沙发永远不会破坏之前固定的沙发，因此贪婪策略总是产生最少数量的交换。 

## Python 解决方案```python
from typing import List

class Solution:
    def minSwapsCouples(self, row: List[int]) -> int:
        n = len(row)

        # Map each person to their current seat index
        position = {}

        for index, person in enumerate(row):
            position[person] = index

        swaps = 0

        # Process each couch
        for i in range(0, n, 2):
            first_person = row[i]
            partner = first_person ^ 1

            # Already seated correctly
            if row[i + 1] == partner:
                continue

            # Find where the partner currently sits
            partner_index = position[partner]

            # Person currently sitting beside first_person
            second_person = row[i + 1]

            # Swap partner into the correct position
            row[i + 1], row[partner_index] = (
                row[partner_index],
                row[i + 1],
            )

            # Update positions after swap
            position[partner] = i + 1
            position[second_person] = partner_index

            swaps += 1

        return swaps
```实现首先构建`position`字典，它允许恒定时间查找任何人的座位索引。 如果没有这种结构，每次交换都需要扫描数组，从而增加了复杂性`O(n^2)`。 

主循环一次前进两个座位，因为每对相邻的座位代表一张沙发。 对于每个沙发，算法使用 XOR 运算计算正确的伙伴。 

如果沙发已经正确，则循环立即继续。 否则，从哈希映射中检索伙伴的当前位置，并执行交换以将伙伴放置到正确的相邻座位上。 

交换后，字典必须仔细更新，因为两个人交换了位置。 未能维护准确的索引将导致算法后期的不正确查找。 

最后返回交换的总数。 

## 解决方案```go
func minSwapsCouples(row []int) int {
	n := len(row)

	// Map person -> current index
	position := make(map[int]int)

	for i, person := range row {
		position[person] = i
	}

	swaps := 0

	for i := 0; i < n; i += 2 {
		firstPerson := row[i]
		partner := firstPerson ^ 1

		// Already correct
		if row[i+1] == partner {
			continue
		}

		partnerIndex := position[partner]
		secondPerson := row[i+1]

		// Swap
		row[i+1], row[partnerIndex] =
			row[partnerIndex], row[i+1]

		// Update indices
		position[partner] = i + 1
		position[secondPerson] = partnerIndex

		swaps++
	}

	return swaps
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 主要区别在于 Go 使用`map[int]int`用于索引跟踪和显式变量声明。 

Go 切片是类似引用的结构，因此交换直接修改底层数组。 整数溢出不是问题，因为约束非常小。

 ## 边缘情况

 ### 已经正确的座位

 当每对夫妇已经坐在一起时，就会出现一个重要的边缘情况。 如果在交换之前没有正确验证邻接性，有缺陷的实现可能仍然会执行不必​​要的交换。 

例如：```
[0,1,2,3,4,5]
```该实现通过立即检查来处理此问题：```
if row[i + 1] == partner:
    continue
```除非当前沙发无效，否则不会发生交换。 

### 情侣倒序

 另一个微妙的情况是情侣坐在一起但内部颠倒过来：```
[1,0,3,2]
```幼稚的实现可能会错误地假设较小的 ID 必须排在第一位。 

XOR 伙伴计算完全避免了这个问题，因为：```
1 ^ 1 = 0
3 ^ 1 = 2
```该算法只关心正确的伙伴是否相邻，而不关心配对中的顺序。 

### 循环错位

 当几对夫妇形成错误放置的循环时，会出现更困难的情况：```
[0,2,4,1,3,5]
```在这里，多对情侣互相干扰。 糟糕的贪婪策略可能会执行额外的交换。 

该实施工作正常，因为每次交换都永久固定了一张沙发。 之前修复过的沙发再也不会损坏，保证了最少的更换。 

### 最小有效输入

 最小输入大小为：```
n = 2
```例子：```
[0,2,1,3]
```该算法仍然有效，因为循环一次只处理一对沙发，并且从不访问数组边界之外的索引。
