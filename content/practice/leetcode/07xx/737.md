[LeetCode 第 737 题](https://leetcode.com/problems/sentence-similarity-ii/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、字符串、深度优先搜索、广度优先搜索、并查找

 ## 解决方案

 ## 问题理解

 这个问题要求我们根据单词之间的一组相似关系来确定两个句子是否被认为相似。 

每个句子都表示为一个字符串数组，其中每个字符串都是一个单词。 我们还得到了一个单词对列表，其中每对都表明这两个单词是相似的。 

重要的细节是相似性不仅限于直接关系。 该关系是传递的。 如果`"great"`类似于`"good"`和`"good"`类似于`"fine"`， 然后`"great"`也类似于`"fine"`。 

这意味着相似关系形成了连接词组。 同一连接组内的任何两个单词都被认为是相似的。 

该题要求我们逐字比较两个句子：

 - 句子的字数必须相同。 
- 对于每个索引`i`,`sentence1[i]`必须：

 - 完全等于`sentence2[i]`, 或
 - 属于同一相似组。 

如果每个对应的单词对都满足这个条件，我们返回`true`。 否则，我们返回`false`。 

约束条件很重要：

 - 句子长度可达`1000`- 最多可以有`2000`相似对

 这些值足够大，以至于从头开始重复搜索图表以进行每个单词比较可能会变得低效。 我们需要一种能够有效地将连接的单词组合在一起的解决方案。 

有几个重要的边缘情况：

 - 句子的长度可能不同，这立即使它们不相似。 
- 有些单词可能不会出现在`similarPairs`根本不。 
- 一个单词总是与其自身相似，即使它从未出现在任何配对中。 
- 相似链可能很长，例如`a -> b -> c -> d`。 
- 图表可能包含断开连接的组件。 
- 相似图中可能存在循环。 

正确的解决方案必须正确处理所有这些情况。 

## 方法

 ### 蛮力方法

 最直接的方法是将相似对视为无向图。 

每个单词都成为一个节点，每个相似对在两个单词之间创建一条边。 

对于两个句子中同一索引处的每一对单词：

 1. 如果两个词相等，则继续。 
2. 否则，从第一个单词开始执行DFS或BFS，看看是否可以通过传递相似关系到达第二个单词。 

这种方法是正确的，因为图遍历探索了每一个可能的相似链。 

然而，它的效率很低，因为我们可能会重复遍历图表的相同部分来进行许多单词比较。 在最坏的情况下，每次查找都可以扫描整个图。 

### 最优方法，并集查找

 关键的见解是相似性形成了连接的组件。 

如果两个词属于同一个连通分量，则它们是相似的。 这正是并集查找（也称为不相交集并集）旨在有效解决的问题类型。 

我们不是重复搜索图，而是预处理所有相似对：

 - 每个单词都以自己的集合开始。 
- 每对`(a, b)`，我们联合他们的集合。 
- 处理完所有对后，同一连接组件中的单词共享相同的代表父代。 

那么比较单词就变得简单了：

 - 如果单词相同，则它们相似。 
- 否则，检查它们是否属于同一个并集。 

使用路径压缩和按等级并集使操作的时间几乎恒定。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n × (V + E)) | O(n × (V + E)) | O(V + E) | 对每个单词比较重复 DFS/BFS |
 | 最佳| O((V + E) × α(V)) | O(V) | 使用 Union Find 预处理连通分量 |

 这里：

-`n`是句子长度
 -`V`是唯一单词的数量
 -`E`是相似对的数量
 -`α(V)`是阿克曼反函数，它实际上是常数

 ## 算法演练

 ### 第 1 步：检查句子长度

 第一个要求是句子必须包含相同数量的单词。 

如果长度不同，我们立即返回`False`因为没有办法逐个位置地匹配单词。 

### 步骤 2：初始化并查结构

 我们创建两个哈希图：

 -`parent[word]`存储单词的代表父代
 -`rank[word]`存储用于平衡并集的近似树深度

 我们使用哈希映射是因为节点是字符串，而不是整数。 

### 步骤 3：为每个单词创建集合

 当我们处理相似对时，我们确保每个遇到的单词都存在于并集查找结构中。 

最初：

 - 每个词都是它自己的父母
 - 每个词都有排名`0`这意味着每个单词都以独立的连接组件开始。 

### 步骤 4：联合相似词

 对于每对`(a, b)`:

 1. 找到根父级`a`2. 找到根父级`b`3. 如果根不同，则合并集合

 我们使用：

 - 期间路径压缩`find`- 期间按等级联合`union`这些优化使树变浅并且操作快速。 

### 步骤 5：比较对应的句子单词

 现在我们同时迭代这两个句子。 

对于每对`(word1, word2)`:

 1. 如果两个词相等，则继续
 2. 如果任一单词不存在于并查结构中，则它们不能相似
 3. 否则，比较它们的根父母
 4. 如果根不同，则返回`False`如果所有位置都通过检查，则返回`True`。 

### 为什么它有效

 并查找保证所有传递连接的单词最终都出现在同一个连接组件中。 

如果两个单词可以通过任何相似关系链连接起来，则重复的并集操作最终会将它们置于同一根父级下。 

因此：

 - 相同的词根意味着单词相似
 - 不同的根意味着不存在相似路径

 这个不变量保证了正确性。 

## Python 解决方案```python
from typing import List

class Solution:
    def areSentencesSimilarTwo(
        self,
        sentence1: List[str],
        sentence2: List[str],
        similarPairs: List[List[str]]
    ) -> bool:

        if len(sentence1) != len(sentence2):
            return False

        parent = {}
        rank = {}

        def find(word: str) -> str:
            if parent[word] != word:
                parent[word] = find(parent[word])
            return parent[word]

        def union(word1: str, word2: str) -> None:
            root1 = find(word1)
            root2 = find(word2)

            if root1 == root2:
                return

            if rank[root1] < rank[root2]:
                parent[root1] = root2
            elif rank[root1] > rank[root2]:
                parent[root2] = root1
            else:
                parent[root2] = root1
                rank[root1] += 1

        def add_word(word: str) -> None:
            if word not in parent:
                parent[word] = word
                rank[word] = 0

        for word1, word2 in similarPairs:
            add_word(word1)
            add_word(word2)
            union(word1, word2)

        for word1, word2 in zip(sentence1, sentence2):
            if word1 == word2:
                continue

            if word1 not in parent or word2 not in parent:
                return False

            if find(word1) != find(word2):
                return False

        return True
```实现首先检查两个句子是否具有相同的长度。 这就满足了问题的第一个要求。 

这`parent`字典存储并查找父关系，而`rank`字典有助于在联合操作期间保持树平衡。 

这`find`函数定位单词的词根代表。 通过将每个访问的节点直接更新到根来应用路径压缩，从而加快未来的查找速度。 

这`union`函数合并两个连接的组件。 按等级联合可确保较小的树附着在较大的树下，从而最小化树的高度。 

这`add_word`helper 确保在联合操作发生之前数据结构中存在每个遇到的单词。 

处理完所有相似对后，代码会比较两个句子中的相应单词。 相同的单词会自动被视为相似。 否则，两个单词必须存在于并查找结构中并且共享相同的根父项。 

如果任何比较失败，函数返回`False`。 如果所有比较都成功，则返回`True`。 

## 解决方案```go
func areSentencesSimilarTwo(sentence1 []string, sentence2 []string, similarPairs [][]string) bool {
	if len(sentence1) != len(sentence2) {
		return false
	}

	parent := make(map[string]string)
	rank := make(map[string]int)

	var find func(string) string

	find = func(word string) string {
		if parent[word] != word {
			parent[word] = find(parent[word])
		}
		return parent[word]
	}

	addWord := func(word string) {
		if _, exists := parent[word]; !exists {
			parent[word] = word
			rank[word] = 0
		}
	}

	union := func(word1 string, word2 string) {
		root1 := find(word1)
		root2 := find(word2)

		if root1 == root2 {
			return
		}

		if rank[root1] < rank[root2] {
			parent[root1] = root2
		} else if rank[root1] > rank[root2] {
			parent[root2] = root1
		} else {
			parent[root2] = root1
			rank[root1]++
		}
	}

	for _, pair := range similarPairs {
		word1 := pair[0]
		word2 := pair[1]

		addWord(word1)
		addWord(word2)

		union(word1, word2)
	}

	for i := 0; i < len(sentence1); i++ {
		word1 := sentence1[i]
		word2 := sentence2[i]

		if word1 == word2 {
			continue
		}

		_, exists1 := parent[word1]
		_, exists2 := parent[word2]

		if !exists1 || !exists2 {
			return false
		}

		if find(word1) != find(word2) {
			return false
		}
	}

	return true
}
```Go 实现遵循与 Python 版本相同的逻辑，但使用 Go 映射而不是字典。 

因为 Go 不支持像 Python 那样的嵌套命名函数，`find`函数首先被声明为变量，以便它可以递归地引用自身。 

Go 映射自然地处理字符串键的动态插入，使它们非常适合存储 Union Find 父关系。 

不存在整数溢出问题，因为排名值仍然非常小。

 ## 边缘情况

 ### 不同的句子长度

 如果句子包含不同数量的单词，它们永远不会相似，因为比较是基于位置的。 

幼稚的实现可能会尝试仅比较重叠位置，从而产生不正确的结果。 

该实现通过早期长度检查立即处理这个问题：```
if len(sentence1) != len(sentence2):
    return False
```### 相似对中缺少的单词

 有些词可能永远不会出现在`similarPairs`。 

例如：```
sentence1 = ["a"]
sentence2 = ["b"]
similarPairs = []
```自从`"a"`和`"b"`不同且不存在相似关系，则答案一定是`False`。 

在尝试根比较之前，实现会正确检查两个单词是否存在于并集查找结构中。 

### 长传递链

 相似性可能需要很多中间连接：```
a → b → c → d → e → f
```天真的直接比较会失败，因为`"a"`和`"f"`不直接连接。 

Union Find 正确地将所有连接的单词合并到一个组件中，因此这两个单词最终共享相同的根父项。 

### 循环相似关系

 该图可能包含循环：```
a ↔ b
b ↔ c
c ↔ a
```如果实施不正确，递归图遍历有时会无限地重新访问节点。 

联合查找自然可以安全地处理循环，因为联合操作只是检测两个节点何时已经属于同一集合。
