[LeetCode 第 734 题](https://leetcode.com/problems/sentence-similarity/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表、字符串

 ## 解决方案

 ## 问题理解

 该问题给了我们两个句子，其中每个句子都表示为单词数组。 我们还得到了一个单词对列表，定义了哪些单词被认为是相似的。 

我们的任务是根据以下规则判断两个句子是否相似：

 1. 句子中的单词数量必须相同。 
2. 在每个索引处`i`，这个词`sentence1[i]`必须：

 - 完全等于`sentence2[i]`, 或
 - 出现在相似的一对中`similarPairs`。 

一个重要的细节是相似性是不可传递的。 如果`"great"`类似于`"fine"`和`"fine"`类似于`"excellent"`，这并不意味着`"great"`类似于`"excellent"`。 

另一个重要的细节是相似性是对称的。 如果`"great"`类似于`"fine"`， 然后`"fine"`也应该被认为类似于`"great"`。 

限制相对较小：

 - 每句话最多 1000 个单词
 - 多达 1000 个相似对

 这些限制足够小，即使是效率较低的解决方案也可以通过，但我们仍然应该以有效的实施为目标。 

一些边缘情况很重要：

 - 两个句子的长度可能不同，在这种情况下答案是立即的`false`。 
- 一个单词总是与其自身相似，即使它没有出现在`similarPairs`。 
- 相似性列表可能为空。 
- 相似性不具有传递性，因此我们必须仅检查直接配对关系。 
- 相似的对是不同的，因此我们不需要处理重复的条目。 

## 方法

 ### 蛮力方法

 一种直接的方法是逐字比较两个句子。 对于每一对单词，我们都会扫描整个单词`similarPairs`数组来查看该对是否存在。 

对于每个位置`i`:

 - 如果两个单词相同，则继续。 
- 否则，迭代所有对`similarPairs`。 
- 检查是否：

 -`(word1, word2)`存在，或者
 -`(word2, word1)`存在。 
- 如果没有找到匹配对，则返回`false`。 

这种方法是正确的，因为它明确地检查每个允许的相似关系。 然而，它的效率很低，因为对于每个单词位置，我们可能会扫描整个相似性列表。 

如果：

-`n`是句子长度
 -`m`是相似对的数量

 那么时间复杂度就变成了`O(n * m)`。 

当约束达到 1000 时，这仍然可以轻松通过，但我们可以做得更好。 

### 最佳方法

 关键的观察是重复线性搜索`similarPairs`是不必要的。 我们可以将所有相似关系预处理成哈希集，以进行恒定时间查找。 

我们使用元组将每一对存储在一个集合中，例如：```
("great", "fine")
```由于相似性是对称的，因此我们插入两个方向：```
("great", "fine")
("fine", "great")
```现在，当比较两个词时：

 - 如果单词相等，它们自动相似。 
- 否则，我们只需检查该元组是否存在于哈希集中。 

哈希集查找是`O(1)`平均而言，这将总复杂度降低到`O(n + m)`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * m) | O(1) | O(1) | 扫描每个相似对以进行每个单词比较 |
 | 最佳| O(n + m) | O(米) | 使用哈希集进行恒定时间相似性查找 |

 ## 算法演练

 1.首先检查两个句子的长度是否相同。 

如果长度不同，根据问题定义，句子不可能相似，所以立即返回`false`。 
2. 创建一个哈希集来存储相似关系。 

对于每对`[a, b]`在`similarPairs`， 插入：

-`(a, b)`-`(b, a)`我们插入两个方向，因为相似性是对称的。 
3. 同时迭代两个句子。 

对于每个索引`i`：

- 让`word1 = sentence1[i]`- 让`word2 = sentence2[i]`4. 检查单词是否相同。 

如果`word1 == word2`，继续下一个位置，因为一个单词总是与其自身相似。 
5. 否则，检查是否`(word1, word2)`存在于哈希集中。 

如果不存在，则单词不相似，所以返回`false`。 
6. 如果所有单词对都通过相似性检查，则返回`true`。 

### 为什么它有效

 该算法之所以有效，是因为每个有效的相似关系都明确存储在哈希集中。 对于两个句子中的每个对应单词对，我们验证仅有的两个允许条件之一：

 - 单词相同，或者
 - 该对存在相似关系。 

由于该问题明确指出相似性不可传递，因此仅检查直接关系正是问题所需要的。 

## Python 解决方案```python
from typing import List

class Solution:
    def areSentencesSimilar(
        self,
        sentence1: List[str],
        sentence2: List[str],
        similarPairs: List[List[str]]
    ) -> bool:
        
        if len(sentence1) != len(sentence2):
            return False

        similar_set = set()

        for word1, word2 in similarPairs:
            similar_set.add((word1, word2))
            similar_set.add((word2, word1))

        for word1, word2 in zip(sentence1, sentence2):
            if word1 == word2:
                continue

            if (word1, word2) not in similar_set:
                return False

        return True
```实现首先检查句子长度，因为不同的长度会自动使相似性失效。 

接下来，我们构建一个包含所有有效相似关系的哈希集。 我们插入每对的两个方向以使查找对称。 

主循环使用`zip()`同时迭代两个句子。 对于每个单词对：

 - 如果单词相同，我们立即继续。 
- 否则，我们检查哈希集中是否存在该对。 

如果任何对未通过检查，该函数立即返回`False`。 如果循环成功完成，所有单词对都是相似的，所以我们返回`True`。 

## 解决方案```go
func areSentencesSimilar(sentence1 []string, sentence2 []string, similarPairs [][]string) bool {
	if len(sentence1) != len(sentence2) {
		return false
	}

	similarSet := make(map[string]bool)

	for _, pair := range similarPairs {
		word1 := pair[0]
		word2 := pair[1]

		similarSet[word1+"#"+word2] = true
		similarSet[word2+"#"+word1] = true
	}

	for i := 0; i < len(sentence1); i++ {
		word1 := sentence1[i]
		word2 := sentence2[i]

		if word1 == word2 {
			continue
		}

		key := word1 + "#" + word2

		if !similarSet[key] {
			return false
		}
	}

	return true
}
```在 Go 中，元组不像 Python 那样方便地存在，因此我们使用分隔符将每一对编码为单个字符串键，例如`"#"`。 

Go 版本遵循完全相同的逻辑：

 - 检查句子长度
 - 存储两个相似方向
 - 比较相应的单词
 - 返回`false`失败后立即

 Go 映射天然支持恒定时间平均查找，使得性能与 Python 解决方案相当。

 ## 边缘情况

 ### 不同的句子长度

 如果两个句子包含不同数量的单词，则它们不可能相似，因为相似性是按位置定义的。 

一个常见的错误是试图比较单词直到一个句子结束。 这会错误地忽略不匹配的尾随单词。 该实现通过在任何其他处理之前检查长度来防止这种情况。 

### 不存在于相似对中的单词

 有些词可能永远不会出现在`similarPairs`。 That does not automatically make them invalid because a word is always similar to itself.

 例如：```
sentence1 = ["leetcode"]
sentence2 = ["leetcode"]
```即使相似性列表为空，答案仍然应该是`true`。 

The implementation handles this correctly using the equality check:```
if word1 == word2:
    continue
```### 非传递关系

 这是最重要的逻辑边缘情况。 

认为：```
"a" ~ "b"
"b" ~ "c"
```问题明确指出`"a"`不一定类似于`"c"`。 

一个常见的错误是使用并查找或图连接，这会错误地将相似性视为传递性。 

该实现通过仅检查哈希集中的直接对成员资格来完全避免此问题。
