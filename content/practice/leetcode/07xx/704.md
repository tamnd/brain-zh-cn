 # LeetCode 704，二分查找

 ## 问题理解

 这个问题给了我们一个有序的整数数组，名为`nums`和一个名为的目标整数`target`。 该数组按升序排序，这意味着每个元素都小于其后面的元素。 我们必须判断目标值是否存在于数组中。 如果是，我们返回它的索引。 如果没有，我们返回`-1`。 

重要的要求是算法必须运行在`O(log n)`时间复杂度。 这立即排除了任何从头到尾线性扫描数组的解决方案，因为线性扫描需要`O(n)`最坏情况下的时间。 

输入包括：

 -`nums`，唯一整数的排序数组
 -`target`，我们要定位的整数

 输出是：

 - 索引`target`如果它存在于`nums`-`-1`如果目标不存在

 约束足够小，许多方法在技术上都可行，但所需的对数复杂性强烈暗示预期的解决方案是二分搜索。 

这些约束还保证了几个有用的属性：

 - 数组已经排序
 - 所有值都是唯一的
 - 数组至少包含一个元素

 由于数组已排序并且包含唯一值，因此我们可以在每次比较后安全地消除一半的剩余搜索空间。 

一些重要的边缘情况包括具有单个元素的数组、小于最小元素的目标、大于最大元素的目标以及有效值之间不存在的目标。 幼稚的实现很容易在更新边界时犯一个错误，特别是当只剩下一两个元素时。 

## 方法

 ### 蛮力方法

 最简单的解决方案是从左到右迭代数组并将每个元素与目标进行比较。 

如果我们找到目标，我们会立即返回其索引。 如果我们到达数组末尾但没有找到它，我们返回`-1`。 

这种方法是正确的，因为它会检查目标可能出现的每个可能位置。 然而，它的效率很低，因为在最坏的情况下我们可能需要检查所有`n`元素。 

由于问题明确要求`O(log n)`由于运行时复杂性，暴力方法是不可接受的。 

### 最优方法，二分搜索

 关键的观察结果是数组已排序。 

当我们检查中间元素时：

 - 如果中间元素等于目标，我们就完成了。 
- 如果目标小于中间元素，则目标只能存在于左半部分。 
- 如果目标大于中间元素，则目标只能存在于右半部分。 

因为我们在每次比较后消除了一半的剩余搜索空间，所以运行时间变成对数。 

这种重复的减半过程正是二分搜索的设计目的。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(1) | O(1) | 按顺序扫描每个元素 |
 | 最佳 | O(log n) | O(1) | O(1) | 二分查找反复将搜索空间减半 |

 ## 算法演练

 1.初始化两个指针：

 -`left = 0`-`right = len(nums) - 1`这些指针代表当前的搜索范围。 
2.继续搜索`left <= right`。 

这一情况意味着仍然至少有一个有效元素需要检查。 
3. 使用以下方法计算中间索引：```
mid = (left + right) // 2
```中间元素将当前搜索范围分为两半。 
4. 比较`nums[mid]`和`target`。 

- 如果相等，则返回`mid`因为我们找到了目标。 
- 如果`target < nums[mid]`，移动右边界：```
right = mid - 1
```目标必须在左半区。 
- 否则，移动左边界：```
left = mid + 1
```目标必须在右半区。 
5. 如果循环结束，则目标在数组中不存在。 

返回`-1`。 

### 为什么它有效

 该算法保持不变性，即如果目标存在，则它必须位于当前范围内`[left, right]`。 

每一步都会检查中间元素。 由于数组已排序，因此可以安全地丢弃整个搜索空间的一半。 搜索间隔变得越来越小，直到找到目标或没有有效范围为止。 

由于每次迭代范围大小大致减半，因此该算法在对数时间内完成。 

## Python 解决方案```python
from typing import List

class Solution:
    def search(self, nums: List[int], target: int) -> int:
        left = 0
        right = len(nums) - 1

        while left <= right:
            mid = (left + right) // 2

            if nums[mid] == target:
                return mid

            if target < nums[mid]:
                right = mid - 1
            else:
                left = mid + 1

        return -1
```实现首先使用定义搜索边界`left`和`right`。 

这`while left <= right`循环确保只要剩余有效间隔，我们就继续搜索。 

在循环内部，我们计算中间索引并将该位置的值与目标进行比较。 

如果中间值与目标匹配，我们立即返回索引。 

如果目标较小，我们通过移动目标来缩小搜索空间`right`边界向左。 如果目标更大，我们就移动`left`边界向右。 

最终，要么找到目标，要么区间变空。 当区间为空时，目标不存在，因此函数返回`-1`。 

## 解决方案```go
func search(nums []int, target int) int {
    left := 0
    right := len(nums) - 1

    for left <= right {
        mid := left + (right-left)/2

        if nums[mid] == target {
            return mid
        }

        if target < nums[mid] {
            right = mid - 1
        } else {
            left = mid + 1
        }
    }

    return -1
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

一个小的区别是中间指数的计算：```go
mid := left + (right-left)/2
```这种形式避免了整数具有固定大小的语言中潜在的整数溢出。 虽然对于给定的约束，溢出不是问题，但这在许多二分搜索实现中被认为是最佳实践。 

Go 切片是数组的动态视图，因此我们直接使用切片`nums`。 不需要额外的内存分配。 

## 工作示例

 ### 示例 1```
Input: nums = [-1,0,3,5,9,12], target = 9
```| 迭代 | 左| 对| 中| 数字[中] | 行动|
 | ---| ---| ---| ---| ---| ---|
 | 1 | 0 | 5 | 2 | 3 | 目标较大，向左移动至 3 |
 | 2 | 3 | 5 | 4 | 9 | 找到目标 |

 算法返回`4`。 

### 示例 2```
Input: nums = [-1,0,3,5,9,12], target = 2
```| 迭代 | 左| 对| 中| 数字[中] | 行动|
 | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | 5 | 2 | 3 | 目标较小，向右移动到 1 |
 | 2 | 0 | 1 | 0 | -1 | 目标较大，向左移动至 1 |
 | 3 | 1 | 1 | 1 | 0 | 目标较大，向左移动 2 |

 现在`left = 2`和`right = 1`。 

自从`left > right`，搜索空间为空，因此算法返回`-1`。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(log n) | 每次迭代搜索空间减半 |
 | 空间| O(1) | O(1) | 仅使用了几个变量 |

 运行时间是对数的，因为每次比较都会从考虑中删除一半的剩余元素。 开始于`n`元素，仅在一次迭代之后`n/2`留下来，那么`n/4`， 等等。 

空间复杂度是恒定的，因为没有创建与输入大小成比例的附加数据结构。
