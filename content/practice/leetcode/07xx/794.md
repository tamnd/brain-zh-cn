[LeetCode 第 794 题](https://leetcode.com/problems/valid-tic-tac-toe-state/)

 **难度：** 🟡 中等
 **主题：** 数组、矩阵

 ## 解决方案

 ## 问题理解

 这个问题要求我们确定给定的 Tic-Tac-Toe 棋盘配置是否可以在遵循所有官方规则的真实游戏中发生。 

输入是一个`3 x 3`board 表示为三个字符串的数组。 字符串中的每个字符可以是：

 -`'X'`，代表玩家 X 采取的行动
 -`'O'`，代表玩家 O 的一步棋
 -`' '`，代表一个空正方形

 The game rules matter because not every arrangement of X and O pieces is reachable during legal gameplay. We must verify whether the board could have been produced by alternating turns starting from an empty board.

 几个重要的规则限制了有效状态：

 1. 玩家 X 总是先行动。 
2. 玩家轮流进行。 
3. 移动只能放入空单元格中。 
4. The game immediately ends when either player gets three in a row.
 5. 比赛结束后不得再移动。 

输出应该是`true`如果棋盘可以在某些有效的游戏中存在，否则`false`。 

限制非常小。 该板始终包含 9 个电池，因此效率不是问题。 即使是暴力解决方案也是可行的。 然而，挑战在于正确推理所有游戏规则和边缘情况。 

一些边缘情况尤其重要：

 - O 的步数比 X 多的棋盘，这是不可能的，因为 X 首先开始。 
- X 比 O 多一步的棋盘。 
- 两名玩家同时拥有获胜线的棋盘。 
- 在某人已经获胜后，玩家继续进行行动的棋盘。 
- 一名玩家拥有多条获胜线的棋盘，如果在最后一步创建，则仍然有效。 

该问题保证了棋盘尺寸始终有效，因此我们只需要验证游戏玩法的一致性。 

## 方法

 ### 蛮力方法

 蛮力方法是从空棋盘模拟每一种可能的井字棋游戏并存储所有可到达的状态。 然后，对于输入板，我们只需检查它是否存在于生成的状态中。 

由于 Tic-Tac-Toe 的状态空间非常小，这实际上在计算上是可行的。 我们可以递归地生成所有合法的动作，在玩家获胜时停止，并收集每个可到达的配置。 

这种方法是正确的，因为它明确地模拟了每个有效的游戏序列。 如果某个板出现在生成集中，则它必须是可合法访问的。 

然而，对于如此小的逻辑验证问题，该方法不必要地复杂。 它需要递归、状态序列化和维护访问集。 实现变得比必要的更大并且更难以推理。 

### 最优逻辑验证方法

 关键的观察结果是，有效的 Tic-Tac-Toe 棋盘必须满足直接从游戏规则导出的几个数学和结构属性。 

我们可以使用以下条件验证棋盘，而不是模拟每个游戏：

 1. X 的步数必须与 O 相同，或者正好多 1。 
2. 如果 X 获胜，则 X 必须多走一步。 
3. 如果 O 获胜，则 X 和 O 的步数必须相同。 
4. 两名玩家不能同时获胜。 

这些规则充分描述了所有有效的董事会状态。 

一旦我们计算出 X 和 O 的移动次数并确定任一玩家是否有获胜线，验证就变得简单了。

 | --- | --- | --- | --- |
 | 蛮力 | O(3^9) | O(3^9) | O(3^9) | O(3^9) | 递归生成所有可到达的棋盘状态 |
 | 最佳| O(1) | O(1) | O(1) | O(1) | 使用移动计数和获胜条件验证棋盘 |

 ## 算法演练

 1. 计算棋盘上 X 和 O 的移动次数。 

由于 X 总是先移动，而玩家轮流轮流移动，因此 X 的移动次数必须等于 O 的移动次数，或者恰好比 O 的移动次数多出 1。 

所以：

-`o_count > x_count`无效
 -`x_count > o_count + 1`无效
 2. 创建一个辅助函数来确定玩家是否获胜。 

如果玩家占据以下位置，则获胜：

 - 任意行
 - 任何列
 - 任一对角线

 辅助函数检查所有 8 个可能的获胜线。 
3.判断X是否获胜。 

如果 X 有获胜线，那么 X 一定已经下了最后一步。 由于 X 总是先移动，这意味着：```
x_count == o_count + 1
```如果此条件不成立，则该板无效。 
4.判断O是否获胜。 

如果 O 有获胜线，那么 O 一定已经做出了最后一步。 所以：```
x_count == o_count
```否则，该板无效。 
5. 检查两位玩家是否同时有获胜线。 

这在合法游戏中永远不会发生，因为游戏在第一次获胜后立即停止。 

因此，如果双方都获胜，则返回`false`。 
6. 如果所有检查都通过，则返回`true`。 

### 为什么它有效

 该算法之所以有效，是因为井字棋具有严格的结构约束，这些约束源于交替回合和获胜后立即终止游戏。 

移动计数规则确保回合顺序的一致性。 获胜条件确保最后一步属于创建获胜线的玩家。 同时获胜检查保证胜利后比赛无法继续。 

总之，这些条件完全表征了每个有效的 Tic-Tac-Toe 状态。 

## Python 解决方案```python
from typing import List

class Solution:
    def validTicTacToe(self, board: List[str]) -> bool:
        x_count = 0
        o_count = 0

        for row in board:
            for cell in row:
                if cell == 'X':
                    x_count += 1
                elif cell == 'O':
                    o_count += 1

        # X always goes first
        if o_count > x_count:
            return False

        # X can have at most one extra move
        if x_count > o_count + 1:
            return False

        def has_won(player: str) -> bool:
            # Check rows
            for row in range(3):
                if all(board[row][col] == player for col in range(3)):
                    return True

            # Check columns
            for col in range(3):
                if all(board[row][col] == player for row in range(3)):
                    return True

            # Check diagonals
            if all(board[i][i] == player for i in range(3)):
                return True

            if all(board[i][2 - i] == player for i in range(3)):
                return True

            return False

        x_wins = has_won('X')
        o_wins = has_won('O')

        # Both players cannot win
        if x_wins and o_wins:
            return False

        # If X wins, X must have one more move
        if x_wins and x_count != o_count + 1:
            return False

        # If O wins, counts must be equal
        if o_wins and x_count != o_count:
            return False

        return True
```实现首先对所有 X 和 O 移动进行计数。 这使我们能够验证轮次排序是否可行。 

接下来，`has_won`助手检查每条获胜线。 由于 Tic-Tac-Toe 只有八种可能的获胜模式，因此该函数仍然非常小且高效。 

计算后`x_wins`和`o_wins`，该算法使用源自游戏机制的逻辑规则来验证棋盘。 

该实现直接反映了算法演练的推理，这使得验证正确性变得容易。 

## 解决方案```go
func validTicTacToe(board []string) bool {
    xCount := 0
    oCount := 0

    for _, row := range board {
        for _, cell := range row {
            if cell == 'X' {
                xCount++
            } else if cell == 'O' {
                oCount++
            }
        }
    }

    // X always moves first
    if oCount > xCount {
        return false
    }

    // X can have at most one extra move
    if xCount > oCount+1 {
        return false
    }

    hasWon := func(player byte) bool {
        // Rows
        for row := 0; row < 3; row++ {
            if board[row][0] == player &&
                board[row][1] == player &&
                board[row][2] == player {
                return true
            }
        }

        // Columns
        for col := 0; col < 3; col++ {
            if board[0][col] == player &&
                board[1][col] == player &&
                board[2][col] == player {
                return true
            }
        }

        // Main diagonal
        if board[0][0] == player &&
            board[1][1] == player &&
            board[2][2] == player {
            return true
        }

        // Anti-diagonal
        if board[0][2] == player &&
            board[1][1] == player &&
            board[2][0] == player {
            return true
        }

        return false
    }

    xWins := hasWon('X')
    oWins := hasWon('O')

    // Both players cannot win
    if xWins && oWins {
        return false
    }

    // If X wins, X must have one extra move
    if xWins && xCount != oCount+1 {
        return false
    }

    // If O wins, move counts must match
    if oWins && xCount != oCount {
        return false
    }

    return true
}
```Go 实现遵循与 Python 版本相同的逻辑。 一个小区别是 Go 中的字符串以字节为索引，因此辅助函数接受`byte`而不是字符串字符。 

由于板大小是固定的，因此无需担心整数溢出或内存使用。

 ## 边缘情况

 ### 两名玩家同时获胜

 在合法的井字游戏中，X 和 O 都有获胜线的棋盘是不可能的。 游戏在第一个获胜动作后立即停止，因此第二个玩家永远不会再有机会创造自己的胜利。 

例如：```
["XXX",
 "OOO",
 "   "]
```仅检查某人是否获胜的幼稚实现可能会错误地接受此棋盘。 该实现明确拒绝两个状态`x_wins`和`o_wins`是真的。 

### 无效的移动计数

 由于 X 总是开始并且玩家轮流轮流，因此移动次数受到严格限制。 

无效状态的示例包括：```
["OO ",
 "   ",
 "   "]
```和```
["XXX",
 "   ",
 "   "]
```第一个有太多的 O 动作，而第二个有太多的 X 动作而没有足够的 O 响应。 

该实现使用以下方法处理此问题：```
if o_count > x_count:
    return False

if x_count > o_count + 1:
    return False
```### 回合数不正确的获胜玩家

 当一个玩家获胜但移动计数表明另一个玩家随后移动时，就会出现一个微妙的错误。 

例子：```
["XXX",
 "OOO",
 "X  "]
```即使只有一名玩家获胜，移动计数也可能与胜利的时间相矛盾。 

如果 X 获胜，X 一定已经下了最后一步，因此 X 一定比 O 多一步。 

如果 O 获胜，则两个计数必须匹配。 

该实现在计算获胜状态后直接强制执行这些条件。
