[LeetCode 第 799 题](https://leetcode.com/problems/champagne-tower/)

 **难度：** 🟡 中等
 **主题：** 动态规划

 ## 解决方案

 ## 问题理解

 该问题要求我们模拟将香槟倒入玻璃杯金字塔中的过程。 每个玻璃杯只能容纳一杯香槟，玻璃杯中多余的香槟会均匀地流到紧邻其下方的两个玻璃杯中。 我们给定一个非负整数`poured`代表倒入顶部玻璃杯中的杯子总数，我们需要确定行中特定玻璃杯的装满量`query_row`和列`query_glass`。 行和眼镜的索引为 0，因此`(0, 0)`是最上面的玻璃。 

输入`poured`可以大到 10^9，而我们需要查询的最大行是 99，这表明单独模拟所有杯子的解决方案效率很低。 输出是一个浮点数，表示目标玻璃杯中所装杯子的比例，上限为 1.0，因为玻璃杯不能容纳多个杯子。 边缘情况包括倒零个杯子、查询顶部玻璃杯、查询可能仅接收到部分溢出的玻璃杯，以及查询行之前的所有玻璃杯可能已满的非常大的倒水。 

## 方法

 蛮力方法将模拟将每个杯子一个接一个地倒出，将溢出传播到每一行。 虽然它会给出正确的结果，但对于较大的值来说效率很低`poured`因为每个杯子可能影响最多`query_row`行，使其不切实际`poured = 10^9`。 

最佳方法使用动态规划。 我们可以维护一个二维数组（或三角形数组），其中`dp[i][j]`存储行中玻璃杯中的香槟数量`i`和列`j`。 我们用倒入的量初始化顶部玻璃。 然后，对于每一个超过 1 杯的玻璃杯，我们计算出多余的部分并将其平均分配到下面的两个玻璃杯中。 这使我们能够计算任何玻璃杯中的准确含量，而无需单独模拟每个杯子。 我们只需要传播多余的部分，使得这种方法高效且易于实现。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(倒入 * query_row^2) | O(查询行^2) | 模拟每个杯子； 对于大的浇注值来说太慢|
 | 最佳| O(查询行^2) | O(查询行^2) | 动态规划； 只会传播多余的 |

 ## 算法演练

 1. 创建二维数组`dp`大小为 100x100，用零初始化。 每个细胞`dp[i][j]`代表香槟的数量`j`的第 玻璃`i`扔。 
2. 设置`dp[0][0]`至总计`poured`数量。 
3. 迭代每一行`i`从 0 到`query_row`。 对于每个玻璃杯`j`在行中`i`，检查是否`dp[i][j]`超过 1。如果超过，则将超出部分计算为`dp[i][j] - 1`。 
4. 将多余的一半分配到左下方的玻璃上`dp[i+1][j]`一半到右下的玻璃`dp[i+1][j+1]`。 目前的玻璃杯仅保留 1 个杯子。 
5. 填充所有行后`query_row`，金额在`dp[query_row][query_glass]`代表查询的玻璃杯有多满。 使用将值限制为 1.0`min(1.0, dp[query_row][query_glass])`。 
6. 返回结果。 

**工作原理**： DP 表可确保每个玻璃杯仅包含到达其的实际数量的香槟。 通过仅传播溢出，该算法尊重香槟流下的物理行为，并且不会多计数或少计数分布。 

## Python 解决方案```python
class Solution:
    def champagneTower(self, poured: int, query_row: int, query_glass: int) -> float:
        dp = [[0.0] * 100 for _ in range(100)]
        dp[0][0] = float(poured)
        
        for i in range(query_row + 1):
            for j in range(i + 1):
                if dp[i][j] > 1.0:
                    excess = dp[i][j] - 1.0
                    dp[i][j] = 1.0
                    dp[i+1][j] += excess / 2.0
                    dp[i+1][j+1] += excess / 2.0
        
        return min(1.0, dp[query_row][query_glass])
```该实现初始化一个 100x100 DP 表，因为最大行为 99。双循环将多余的香槟从每个玻璃杯传播到下一行。 通过将每个玻璃杯的上限设置为 1.0，该算法可以防止装满。 最后，我们返回 1.0 中的最小值和所查询玻璃杯中的数量。 

## 解决方案```go
func champagneTower(poured int, query_row int, query_glass int) float64 {
    dp := make([][]float64, 100)
    for i := range dp {
        dp[i] = make([]float64, 100)
    }
    dp[0][0] = float64(poured)
    
    for i := 0; i <= query_row; i++ {
        for j := 0; j <= i; j++ {
            if dp[i][j] > 1.0 {
                excess := dp[i][j] - 1.0
                dp[i][j] = 1.0
                dp[i+1][j] += excess / 2.0
                dp[i+1][j+1] += excess / 2.0
            }
        }
    }
    
    if dp[query_row][query_glass] > 1.0 {
        return 1.0
    }
    return dp[query_row][query_glass]
}
```在 Go 中，我们显式创建一个大小为 100x100 的 2D 切片。 该逻辑反映了 Python 实现。 由于 Go 不会自动限制浮点值，因此我们检查最终的玻璃杯并在必要时返回 1.0。 

## 工作示例

 **示例1**：`poured = 1, query_row = 1, query_glass = 1`步骤一：`dp[0][0] = 1`第二步：不要过量`dp[0][0]`，所以没有传播

 步骤3：`dp[1][1] = 0`输出：0.0

 **示例2**：`poured = 2, query_row = 1, query_glass = 1`步骤一：`dp[0][0] = 2`步骤2：`dp[0][0]`超过1，超出=1

 第三步：传播：`dp[1][0] += 0.5`,`dp[1][1] += 0.5`第4步：`dp[1][1] = 0.5`输出：0.5

 **示例3**：`poured = 100000009, query_row = 33, query_glass = 17`第 1 步：由于倾倒量较大，第 33 排之前的所有玻璃杯都将装满

 步骤2：`dp[33][17] = 1`输出：1.0

 ## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(查询行^2) | 直到 query_row 的行中的每个玻璃杯都会被访问一次 |
 | 空间| O(查询行^2) | DP 表存储每杯香槟的量 |

 该算法避免了对每个倒出的杯子进行迭代，而是仅依赖于分配溢出的杯子。 由于最大行数为 99，因此该表最多有 100x100 个条目，使得该解决方案即使对于最大的浇注也可行。
