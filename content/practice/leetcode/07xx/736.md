[LeetCode 736 题](https://leetcode.com/problems/parse-lisp-expression/)

 **难度：** 🔴难
 **主题：** 哈希表、字符串、堆栈、递归

 ## 解决方案

 ## 问题理解

 该问题要求我们计算一个表示为字符串的类似 Lisp 的表达式。 表达式可以包含整数、变量和三个特殊运算：`let`,`add`， 和`mult`。 

表达式的计算结果为单个整数值。 挑战不是算术本身，而是正确处理嵌套作用域和变量阴影。 

一个`let`表达式引入变量赋值。 这些分配按顺序处理，并且每个分配对同一区域内的后续表达式可见`let`。 变量也可以隐藏外部变量。 这意味着内部作用域中定义的变量会暂时覆盖外部作用域中同名的变量。 

例如：```
(let x 2 (mult x (let x 3 y 4 (add x y))))
```里面里面里面`let`,`x`变成`3`，即使外部`x = 2`已经存在。 所以：```
(add x y) = 3 + 4 = 7
(mult x 7) = 2 * 7 = 14
```输入始终是有效的表达式，并且保证正确解析每个变量引用。 这种保证简化了错误处理，因为我们永远不需要处理格式错误的语法或未定义的变量。 

限制相对较小：

 - 表达式长度最多为`2000`- 可以嵌套表达式
 - 变量范围可以深度重叠

 重复复制环境或重新解析子字符串的简单解析器可能会变得低效。 因此，我们需要一个能够增量解析字符串并有效维护范围的解决方案。 

一些边缘情况很重要：

 - 变量隐藏外部值的嵌套范围
 - 内部顺序分配`let`- 负整数
 - 仅包含单个整数的表达式
 - 仅包含变量查找的表达式
 - 深度嵌套的递归表达式

 输入在语法上保证是正确的，这意味着我们可以完全专注于评估逻辑。 

## 方法

 ### 蛮力方法

 强力解决方案将重复解析子字符串并为每个嵌套表达式构造全新的变量环境。 

对于每个`let`表达式，我们可以：

 1.复制当前范围图
 2. 申请作业
 3. 递归计算最终表达式

 类似地，每个递归调用都可能为标记和嵌套表达式创建新的子字符串。 

这种方法之所以有效，是因为每次递归计算都会看到变量环境的正确快照。 但是，在每个嵌套范围复制整个哈希映射的成本非常高，尤其是当表达式深度嵌套时。 

重复的子字符串创建也会增加开销，因为字符串切片和重新解析可能会多次重新访问相同的字符。 

### 最佳方法

 关键的见解是 Lisp 表达式自然地形成递归结构，并且作用域的行为类似于堆栈。 

我们不复制整个环境，而是维护：

 - 解析字符串的指针
 - 从变量名称到值堆栈的哈希映射

 当进入新的作用域时，我们将新的变量值压入堆栈。 当离开瞄准镜时，我们将它们弹出。 这与词法作用域行为完全匹配。 

例如：```
x = 2
(let x 3 ...)
```堆栈为`x`变成：```
[2, 3]
```当内部作用域结束时，我们弹出`3`并恢复`2`。 

这样可以实现有效的范围管理，而无需重复复制大型地图。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n²) | 重复环境复制和子串解析 |
 | 最佳| O(n) | O(n) | 具有作用域堆栈的单遍递归解析器 |

 ## 算法演练

 1. 维护表达式字符串的全局解析索引。 

我们不是重复创建子字符串，而是在原始字符串中移动指针。 每次递归调用都从当前位置继续解析。 
2. 使用哈希映射，其中每个变量映射到一个值堆栈。 

这种结构自然地模拟了嵌套范围。 最近的分配始终是活动值。 
3. 定义递归`parse()`功能。 

此函数从当前索引开始计算表达式并返回其整数值。 
4. 如果当前字符不是`'('`，解析：

 - 一个整数
 - 变量名

 如果它是一个变量，则返回堆栈顶部的值。 
5. 如果当前字符是`'('`，解析一个操作。 

跳过`'('`，然后读取操作名称：

 -`add`-`mult`-`let`6. 对于`add`:

 - 解析第一个表达式
 - 解析第二个表达式
 - 返回他们的总和
 7. 对于`mult`:

 - 解析第一个表达式
 - 解析第二个表达式
 - 退回他们的产品
 8.为了`let`:

 按顺序处理令牌。 

每次迭代可以是：

 - 变量赋值对
 - 最终表达
 9. 对于每个变量赋值：

 - 解析变量名
 - 解析指定的表达式
 - 将值压入该变量的堆栈
 - 记录变量，以便我们稍后可以弹出它
 10. 一旦达到最终表达式：

 - 评估一下
 - 弹出此范围内引入的所有变量
 - 返回结果
 11. 继续递归，直到计算出整个表达式。 

### 为什么它有效

 正确性来自于为每个变量维护一堆值。 堆栈的顶部始终代表最里面的可见范围。 输入范围会推送值，离开范围则会弹出值。 由于递归解析遵循表达式的精确嵌套结构，因此变量可见性始终符合 Lisp 作用域规则。 

## Python 解决方案```python
from collections import defaultdict
from typing import DefaultDict, List

class Solution:
    def evaluate(self, expression: str) -> int:
        index = 0
        scope: DefaultDict[str, List[int]] = defaultdict(list)

        def parse() -> int:
            nonlocal index

            # Integer or variable
            if expression[index] != '(':
                if expression[index] == '-' or expression[index].isdigit():
                    start = index

                    if expression[index] == '-':
                        index += 1

                    while index < len(expression) and expression[index].isdigit():
                        index += 1

                    return int(expression[start:index])

                start = index

                while (
                    index < len(expression)
                    and expression[index] not in [' ', ')']
                ):
                    index += 1

                variable = expression[start:index]
                return scope[variable][-1]

            # Skip '('
            index += 1

            start = index

            while expression[index] != ' ':
                index += 1

            operation = expression[start:index]
            index += 1

            if operation == "add":
                first = parse()
                index += 1
                second = parse()
                index += 1
                return first + second

            if operation == "mult":
                first = parse()
                index += 1
                second = parse()
                index += 1
                return first * second

            # let expression
            assigned_variables = []

            while True:
                if expression[index] == '(':
                    result = parse()
                    break

                start = index

                while (
                    index < len(expression)
                    and expression[index] not in [' ', ')']
                ):
                    index += 1

                token = expression[start:index]

                # Final expression
                if expression[index] == ')':
                    result = scope[token][-1]
                    break

                index += 1

                # Detect final expression instead of assignment
                if (
                    expression[index] == '('
                    or expression[index] == '-'
                    or expression[index].isdigit()
                ):
                    result = parse()
                    break

                value = parse()
                scope[token].append(value)
                assigned_variables.append(token)

                if expression[index] == ' ':
                    index += 1

            for variable in assigned_variables:
                scope[variable].pop()

            index += 1
            return result

        return parse()
```该实现围绕递归下降解析进行。 

这`index`变量全局跟踪当前解析位置。 这避免了重复创建子字符串并启用真正的单遍解析器。 

这`scope`哈希映射存储变量值的堆栈。 由于嵌套作用域，每个变量可能有多个活动绑定。 

这`parse()`函数计算当前索引处的一个表达式。 

如果表达式不是以`'('`，它必须是：

 - 一个整数
 - 变量引用

 直接解析整数。 通过读取堆栈顶部的值来解析变量。 

对于复合表达式，解析器首先读取操作名称。 

这`add`和`mult`运算很简单，因为它们总是包含两个表达式。 

这`let`操作更加复杂，因为它混合了赋值和最终表达式。 解析器按顺序处理标记，直到检测到最终表达式。 

每个分配的变量都会被记录下来，以便稍后在退出时可以正确删除其范围`let`。 

这个实现完全符合 Lisp 作用域规则。 

## 解决方案```go
package main

import (
	"strconv"
)

func evaluate(expression string) int {
	index := 0
	scope := map[string][]int{}

	var parse func() int

	parse = func() int {
		// Integer or variable
		if expression[index] != '(' {
			// Integer
			if expression[index] == '-' || (expression[index] >= '0' && expression[index] <= '9') {
				start := index

				if expression[index] == '-' {
					index++
				}

				for index < len(expression) &&
					expression[index] >= '0' &&
					expression[index] <= '9' {
					index++
				}

				value, _ := strconv.Atoi(expression[start:index])
				return value
			}

			// Variable
			start := index

			for index < len(expression) &&
				expression[index] != ' ' &&
				expression[index] != ')' {
				index++
			}

			variable := expression[start:index]
			values := scope[variable]
			return values[len(values)-1]
		}

		// Skip '('
		index++

		start := index

		for expression[index] != ' ' {
			index++
		}

		operation := expression[start:index]
		index++

		if operation == "add" {
			first := parse()
			index++
			second := parse()
			index++

			return first + second
		}

		if operation == "mult" {
			first := parse()
			index++
			second := parse()
			index++

			return first * second
		}

		// let expression
		assigned := []string{}
		var result int

		for {
			if expression[index] == '(' {
				result = parse()
				break
			}

			start := index

			for index < len(expression) &&
				expression[index] != ' ' &&
				expression[index] != ')' {
				index++
			}

			token := expression[start:index]

			// Final variable expression
			if expression[index] == ')' {
				values := scope[token]
				result = values[len(values)-1]
				break
			}

			index++

			// Final expression
			if expression[index] == '(' ||
				expression[index] == '-' ||
				(expression[index] >= '0' && expression[index] <= '9') {
				result = parse()
				break
			}

			value := parse()

			scope[token] = append(scope[token], value)
			assigned = append(assigned, token)

			if expression[index] == ' ' {
				index++
			}
		}

		for _, variable := range assigned {
			values := scope[variable]
			scope[variable] = values[:len(values)-1]
		}

		index++
		return result
	}

	return parse()
}
```Go 实现与 Python 版本非常相似，但一些特定于语言的细节有所不同。 

Go 没有 Python 的`defaultdict`，因此范围图是使用手动初始化的`map[string][]int`。 

切片操作自然支持堆栈行为。 追加会推送值，切片会删除顶部值。 

整数解析用途`strconv.Atoi`。 

与 Python 不同，Go 需要显式字符比较来进行数字检查。 

Go 整数在这里是安全的，因为该问题保证所有中间值都在 32 位有符号整数范围内。

 ## 边缘情况

 一种重要的边缘情况是跨嵌套作用域的变量阴影。 表达式如：```
(let x 1 (let x 2 x))
```如果范围恢复处理不当，很容易产生不正确的结果。 幼稚的实现可能会永久覆盖外部值。 对每个变量使用堆栈可以干净地解决这个问题，因为内部值会被推送并随后自动弹出。 

另一个棘手的情况是单个内的顺序分配`let`表达。 在：```
(let x 1 y (add x 2) y)
```分配给`y`必须看到已经分配的值`x`。 因此，按顺序处理作业至关重要。 该实现在移动到下一个标记之前立即评估并存储每个分配。 

负整数也很容易被错误处理。 由于变量名包含小写字母和数字，因此前导`-`明确表示一个整数。 解析器显式检查`'-'`在数字解析之前，确保正确解释负值。 

最后一个微妙的边缘情况是区分 a 的最终表达式`let`和另一个作业对。 实现通过检查令牌后面的内容来确定这一点。 如果下一个组件表示表达式而不是变量赋值，则解析将切换为直接计算最终表达式。
