 **难度：** 🟢简单
 **主题：** 数学

 ## 解决方案

 ## 问题理解

 该问题要求我们找到给定范围内的所有数字`[left, right]`满足自整数的定义。 

自整数有两个重要的性质：

 1. 数字中的每一位数字都必须整除该数字。 
2. 号码不能包含数字`0`。 

例如，考虑数字`128`。 

-`128 % 1 == 0`-`128 % 2 == 0`-`128 % 8 == 0`由于所有数字均整除该数字并且没有一个数字为零，`128`是一个有效的自整数。 

现在考虑`120`。 

- 数字`0`出现在号码中。 
- 除以零无效。 

所以，`120`不是自整数。 

输入由两个整数组成：

 -`left`, 范围的开始
 -`right`, 范围的末尾

 输出应该是一个列表，其中包含之间的每个自分数字`left`和`right`，包含在内。 

限制相对较小：

 -`1 <= left <= right <= 10^4`这告诉我们几个重要的事情：

 - 最大的数字最多为 5 位。 
- 我们需要检查的整数总数最多为`10^4`。 
- 简单的逐位模拟就足够高效了。 

关键边缘情况涉及等于零的数字和不能整除数字的数字。 另一个微妙的情况是个位数。 每个非零个位数都会自动自整除，因为任何数字都会将自己整除。 

## 方法

 ### 蛮力方法

 最直接的解决方案是迭代每个整数`left`到`right`并判断其是否自分裂。 

对于每个数字：

 - 一次提取每个数字。 
- 如果任何数字为零，请立即拒绝该号码。 
- 否则，检查原始数字是否能被该数字整除。 
- 如果所有数字都通过了整除性测试，则将该数字添加到结果列表中。 

这种方法是正确的，因为它直接实现了自除数的数学定义。 

尽管这在技术上是蛮力的，但约束足够小，在实践中表现得非常好。 每个数字最多包含 5 位数字，因此每个数字的工作量很小。 

### 最佳方法的关键见解

 重要的观察是我们永远不需要昂贵的操作或高级数据结构。 

每个数字都可以使用模数除法和整数除法的简单数字提取来独立验证：

 -`digit = n % 10`-`n //= 10`这使我们能够有效地处理数字，而无需将数字转换为字符串。 

因此，最佳解决方案仍然是范围扫描，但具有高效的数字处理能力，并在发现坏数字时提前终止。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n * d) | O(1) | O(1) | 直接检查每个数字的每一位数字 |
 | 最佳| O(n * d) | O(1) | O(1) | 使用高效的数字提取和早期拒绝 |

 这里：

-`n = right - left + 1`-`d = number of digits`，最多 5 个

 自从`d`受一个非常小的常数限制，解在范围大小上实际上是线性的。 

## 算法演练

 1、初始化一个空的结果列表来存储所有自分数。 
2. 迭代其中的每个整数`left`到`right`，包含在内。 每个号码都会被独立检查。 
3. 对于当前数字，存储原始值的副本，因为我们将在提取数字时修改另一个变量。 
4. 使用模运算重复提取最后一位数字：```
digit = current % 10
```这给出了该数字的最右边的数字。 
5. 检查该位是否为零。 自除数不能包含零，因为除以零是未定义的。 如果数字为零，则立即拒绝该数字。 
6. 检查原数是否能被数字整除：```
original % digit == 0
```如果这个条件对于一位数字不成立，则该数字不是自整除的。 
7. 使用整数除法删除最后一位数字：```
current //= 10
```这会将算法移至下一个数字。 
8. 继续，直到处理完所有数字。 
9. 如果每个数字都通过了检查，则将该数字附加到结果列表中。 
10. 检查完范围内的所有数字后，返回结果列表。 

### 为什么它有效

 该算法准确地检查问题定义所需的两个条件：

 - 任何数字都不能为零。 
- 每个数字必须整除原来的数字。 

每个数字只检查一次。 如果任何数字违反任一条件，该号码将立即被拒绝。 因此，每个接受的数字都保证是自整除的，并且该范围内的每个自整除的数字都将包含在输出中。 

## Python 解决方案```python
from typing import List

class Solution:
    def selfDividingNumbers(self, left: int, right: int) -> List[int]:
        def is_self_dividing(number: int) -> bool:
            current = number

            while current > 0:
                digit = current % 10

                if digit == 0 or number % digit != 0:
                    return False

                current //= 10

            return True

        result = []

        for number in range(left, right + 1):
            if is_self_dividing(number):
                result.append(number)

        return result
```实现从一个名为的辅助函数开始`is_self_dividing`。 该函数封装了验证单个数字的逻辑。 

变量`current`用于数字提取，以便原始`number`保持不变。 这很重要，因为整除性检查必须始终使用原始值。 

里面的`while`环形：

-`current % 10`提取最后一位数字。 
- 条件`digit == 0`拒绝包含零的数字。 
- 条件`number % digit != 0`拒绝不能均匀划分的数字。 

如果任一条件失败，函数立即返回`False`。 这种提前退出提高了效率，因为一旦确定发生故障，就没有理由检查剩余的数字。 

线路`current //= 10`删除已处理的数字。 

如果循环成功完成，所有数字都满足要求，因此函数返回`True`。 

main 方法遍历整个范围并将有效数字附加到`result`列表。 

## 解决方案```go
func selfDividingNumbers(left int, right int) []int {
    isSelfDividing := func(number int) bool {
        current := number

        for current > 0 {
            digit := current % 10

            if digit == 0 || number%digit != 0 {
                return false
            }

            current /= 10
        }

        return true
    }

    result := []int{}

    for number := left; number <= right; number++ {
        if isSelfDividing(number) {
            result = append(result, number)
        }
    }

    return result
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

本地辅助函数用于保持验证逻辑的干净和可重用。 数字的提取使用`% 10`并使用删除`/= 10`。 

结果存储在初始化为空切片的切片中：```go
result := []int{}
```这确保函数返回一个空切片而不是`nil`如果没有数字符合条件。 

整数溢出不是问题，因为约束非常小，值限制为`10^4`。

 ## 边缘情况

 一种重要的边缘情况是包含数字零的数字。 这是最常见的错误来源，因为除以零是未定义的。 直接执行的简单实现`number % digit`如果不首先检查零将会崩溃或引发异常。 该实现通过在尝试整除之前立即拒绝任何等于零的数字来避免这种情况。 

另一个重要的边缘情况是个位数。 每个数字都来自`1`通过`9`是自动自整除的，因为每个数字都可以均匀地整除自己。 某些实现意外地使这种情况变得过于复杂，但数字处理循环自然会正确处理它，而无需任何特殊逻辑。 

第三个重要的边缘情况是只有一位数字无法整除的数字。 例如，`26`失败是因为`26 % 6 != 0`。 一旦发现失败的数字，实现就会尽早正确退出。 这样可以防止不必要的工作并确保正确性，即使只有一位数字使号码无效。 

第四个微妙的边缘情况涉及重复的数字，例如`22`或者`55`。 即使数字重复，该算法也会独立处理每个数字。 这保证了数字的每次出现都满足整除性要求。 

最后，边界值接近`10^4`很重要，因为它们产生最大可能的位数。 该实现仍然可以有效地工作，因为每个数字仅包含少数数字，因此数字处理循环仍然非常小。
