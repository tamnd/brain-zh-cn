[LeetCode 第 779 题](https://leetcode.com/problems/k-th-symbol-in-grammar/)

 **难度：** 🟡 中等
 **主题：** 数学、位操作、递归

 ## 解决方案

 ## 问题理解

 该问题定义了一个逐行增长的特殊二进制语法序列。 第一行仅包含一个值：```
0
```后面的每一行都是使用以下规则从前一行生成的：

 - 替换每个`0`和`01`- 替换每个`1`和`10`这意味着行的演变如下：```
Row 1: 0
Row 2: 01
Row 3: 0110
Row 4: 01101001
```我们有两个整数：

 -`n`，行号，使用从 1 开始的索引
 -`k`，该行内的位置，也使用基于 1 的索引

 任务是返回位置的值`k`在行中`n`。 

限制相对较小：

 -`1 <= n <= 30`-`1 <= k <= 2^n - 1`重要的细节是行大小每次都会加倍。 排`n`包含`2^(n-1)`元素。 虽然`n`仅取决于`30`，直接构造行变得效率低下，因为最后一行可能包含数亿个字符。 

对于较大的值，显式构建字符串的简单实现会消耗太多内存和时间。`n`。 

一些边缘情况很重要：

 -`n = 1, k = 1`，最小可能的输入
 - 靠近行中间的位置，因为递归结构在那里发生变化
 - 大值`n`，其中暴力构造变得不可行
 - 情况`k`指的是从翻转的父值生成的符号

 该问题保证了`k`对于给定的行始终有效，因此我们永远不需要处理越界索引。 

## 方法

 ### 蛮力方法

 最直接的解决方案是从前一行逐字生成每一行。 

我们从以下开始：```
0
```然后重复应用转换规则：

 -`0 -> 01`-`1 -> 10`例如：```
0
01
0110
01101001
```生成行后`n`，我们返回`(k - 1)`第 个字符。 

这种方法是正确的，因为它遵循问题陈述中描述的确切过程。 然而，它很快就会变得低效，因为每行的大小都会增加一倍。 

行的长度`n`是：```
2^(n - 1)
```为了`n = 30`，这超过 5 亿个字符，对于显式构造来说太大了。 

### 最佳方法

 关键的观察结果是每个符号都来自前一行中的父符号。 

每个符号恰好生成两个子符号：

 | 家长 | 儿童 |
 | ---| ---|
 | 0 | 0 1 |
 | 1 | 1 0 | 1 0

 注意一个重要的模式：

 - 左孩子总是与父母相同
 - 正确的孩子总是与父母相反

 这允许我们向后追踪行的任何位置`1`。 

如果我们知道当前位置是左孩子还是右孩子，我们就可以判断该值是否发生变化。 

另一个重要的见解是，答案取决于追溯到根时发生的翻转次数`0`。 

一个非常优雅的数学观察出现了：

 - 每次我们移动到右孩子时，位就会翻转
 - 翻转次数等于`1`位在`(k - 1)`- 如果设置的位数为偶数，则结果为`0`- 如果设置的位数为奇数，则结果为`1`这产生了使用位操作的极其有效的解决方案。

 ## 算法演练

 ### 最佳位操作算法

 1. 观察第一个符号始终是`0`。 

随后的每个符号都是通过从该原始值进行一系列翻转而产生的。 
2. 将位置转换为从零开始的索引。 

而不是与`k`, 与`k - 1`。 

这自然地与二进制表示和父子关系保持一致。 
3. 计算设置位的数量`(k - 1)`。 

每个设置的位对应于在遍历期间移入右子节点。 

右子节点翻转该值。 
4. 判断翻转次数是偶数还是奇数。 

- 偶数次翻转意味着价值仍然存在`0`- 奇数次翻转意味着该值变为`1`5. 返回设置的位数的奇偶校验。 

在代码中：```
return bin(k - 1).count("1") % 2
```### 为什么它有效

 该语法形成二叉树结构，其中：

 - 左孩子保留父母的价值
 - 右子节点翻转父节点的值

 的二进制表示`(k - 1)`编码从根到目标位置的路径。 每一个`1`bit 表示采取右分支，将符号翻转一次。 

因此，最终的值完全取决于向右移动的次数是偶数还是奇数。 

## Python 解决方案```python
class Solution:
    def kthGrammar(self, n: int, k: int) -> int:
        return bin(k - 1).count("1") % 2
```该实现有意简洁，因为数学观察完全消除了递归或模拟的需要。 

表达式`k - 1`将位置转换为从零开始的索引，这与二进制遍历逻辑自然对齐。`bin(k - 1)`将数字转换为二进制字符串。`.count("1")`计算存在多少个设置位。 每个设置位代表语法生成过程中的一次翻转。 

最后，`% 2`确定翻转次数是奇数还是偶数。 

- 即使翻转也会产生`0`- 奇怪的翻转产生`1`参数`n`不直接使用，因为位置的值`k`仅取决于编码的翻转模式`k - 1`。 约束保证`k`对行有效`n`。 

## 解决方案```go
func kthGrammar(n int, k int) int {
    k--

    count := 0

    for k > 0 {
        count += k & 1
        k >>= 1
    }

    return count % 2
}
```Go 实现使用按位运算手动计算设置位，而不是转换为二进制字符串。 

表达式`k & 1`检查是否设置了最低有效位。`k >>= 1`将数字右移一位以继续处理。 

这种方法避免了字符串分配并保持完全恒定的空间。 

Go 整数足以满足问题约束，因为涉及的最大值完全在 32 位整数范围内。

 ## 边缘情况

 ### 尽可能最小的输入

 最小的有效输入是：```
n = 1, k = 1
```这种情况很重要，因为没有可以递归到的父行。 如果没有正确处理基本情况，许多递归实现都会失败。 

我们的实现自然会处理这个问题，因为：```
k - 1 = 0
```设置位数为零，因此结果正确`0`。 

### 最大有效头寸

 最大可能的有效位置出现在以下位置附近：```
n = 30
k = 2^(29)
```暴力解决方案会尝试构建巨大的字符串，这会消耗过多的内存和时间。 

最佳解决方案永远不会构造行。 它只检查位`k`，因此即使在最大约束下，性能仍然保持高效。 

### 多次翻转产生的位置

 有些位置涉及多次右子遍历，导致多次翻转。 

例如：```
k = 8
k - 1 = 7
binary = 111
```有 3 个设置位，意味着 3 次翻转：```
0 -> 1 -> 0 -> 1
```不正确的实现可能只考虑最近的翻转，而不是翻转的总奇偶校验。 

我们的实现正确地计算所有设置位并计算奇偶校验，保证正确的最终值。
