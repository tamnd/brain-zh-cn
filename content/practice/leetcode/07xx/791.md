 # LeetCode 791，自定义排序字符串

 ## 问题理解

 这个问题给了我们两个字符串，`order`和`s`。 

字符串`order`定义自定义字符顺序。 与正常的字母顺序不同，其中的字符`order`准确指定字符之间应如何确定优先级。 中的每个角色`order`是唯一的，这意味着不存在冲突或重复的优先级。 

字符串`s`包含我们必须重新排列的字符。 我们的目标是排列字符`s`这样任何出现在`order`遵循由以下定义的相同相对顺序`order`。 

例如，如果`order = "cba"`， 然后：

-`'c'`必须出现在之前`'b'`-`'b'`必须出现在之前`'a'`中的任意字符`s`那些没有出现在`order`可以放置在最终字符串中的任何位置。 

重要的细节是，该问题仅需要存在于中的字符的相对顺序`order`。 之外的字符`order`不受限制。 

限制很小：

 -`order.length <= 26`-`s.length <= 200`由于仅涉及小写英文字母，因此可能的不同字符总数非常有限。 这意味着我们可以轻松地使用哈希映射、计数数组，甚至排序方法，而无需担心性能问题。 

一些边缘情况很重要：

 - 中的人物`s`可能不存在于`order`-`s`可能包含重复字符
 -`order`可能包含从未出现过的字符`s`-`order`只能包含一个字符
 - 中的所有角色`s`可能在外面`order`该问题保证了中的所有字符`order`是独一无二的，这简化了实施，因为我们永远不需要解决相互冲突的优先事项。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是重复扫描`s`并按照指定的顺序构建结果`order`。 

我们可以处理每个字符`order`，对于每个这样的字符，扫描`s`收集所有匹配的事件。 之后，我们执行另一次遍历`s`附加不存在于的字符`order`。 

这是有效的，因为：

 - 人物来自`order`以正确的相对顺序附加
 - 角色不在`order`之后添加

 然而，这种方法会重复扫描字符串。 如果`order`有长度`m`和`s`有长度`n`，然后重复扫描导致`O(m * n)`时间复杂度。 

尽管约束足够小，可以通过，但这并不是最有效或最优雅的解决方案。 

### 最佳方法

 关键的见解是我们只关心字符频率。 

而不是重复扫描`s`，我们可以先统计每个字符出现的次数。 然后：

 1. 迭代`order`2. 追加每个字符的次数与它在中出现的次数相同`s`3. 之后添加剩余的字符

 这避免了冗余扫描并在线性时间内产生答案。 

哈希映射在这里是理想的选择，因为：

 - 我们需要快速频率查找
 - 字符用作键
 - 频率计数自然地用字典建模

 ## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(m × n) | O(n) | 反复扫描`s`对于每个字符`order`|
 | 最佳| O(m + n) | O(1) 或 O(k) | 使用频率计数直接构建 |

 这里：

-`m = len(order)`-`n = len(s)`-`k`是不同字符的数量，最多 26 个

 ## 算法演练

 ### 最优算法

 1. 为所有字符创建频率图`s`。 

我们计算每个字符出现的次数，因为最终的字符串必须保留每次出现的情况。 
2. 初始化一个空的结果列表。 

使用列表比重复字符串连接更有效，因为字符串在 Python 中是不可变的。 
3. 遍历每个字符`order`。 

对于每个角色：

 - 检查它出现了多少次`s`- 将该字符附加到结果中多次
 - 之后删除或重置其计数

 这保证了所有有序字符以正确的相对顺序出现。 
4. 迭代频率图中的剩余字符。 

这些是未出现在`order`。 

根据其出现频率附加每个剩余字符。 
5. 将结果列表连接成字符串并返回。 

### 为什么它有效

 该算法之所以有效，是因为其中的每个字符`order`按照所需的确切顺序依次处理。 由于字符的所有出现都是在移动到下一个有序字符之前添加的，因此满足相对排序约束。 

不存在的字符`order`没有限制，因此之后附加它们仍然会产生有效的答案。 

每个角色都来自`s`包含的次数与最初出现的次数完全相同，确保结果是有效的排列`s`。 

## Python 解决方案```python
from collections import Counter

class Solution:
    def customSortString(self, order: str, s: str) -> str:
        frequency = Counter(s)
        result = []

        for char in order:
            if char in frequency:
                result.append(char * frequency[char])
                del frequency[char]

        for char, count in frequency.items():
            result.append(char * count)

        return "".join(result)
```实施开始于使用`Counter`来自Python的`collections`计算字符频率的模块`s`。 

这`result`list 有效地存储部分字符串片段。 该代码不是逐一附加字符，而是附加重复的字符串，例如`"c" * 3`，既简单又高效。 

第一个循环根据自定义顺序处理字符。 如果频率图中存在某个字符，则立即附加所有出现的字符。 

处理完有序字符后，频率图中的剩余条目对应于在`order`。 由于这些字符没有顺序限制，因此它们可以按任何顺序附加。 

最后，`"".join(result)`将所有片段组合成最终字符串。 

## 解决方案```go
func customSortString(order string, s string) string {
	frequency := make(map[rune]int)

	for _, ch := range s {
		frequency[ch]++
	}

	result := make([]rune, 0)

	for _, ch := range order {
		count, exists := frequency[ch]

		if exists {
			for i := 0; i < count; i++ {
				result = append(result, ch)
			}

			delete(frequency, ch)
		}
	}

	for ch, count := range frequency {
		for i := 0; i < count; i++ {
			result = append(result, ch)
		}
	}

	return string(result)
}
```Go 解决方案遵循与 Python 实现相同的逻辑。 

一个`map[rune]int`存储字符频率。 由于 Go 字符串是 UTF-8 编码的，因此迭代`range`产生`rune`值安全。 

结果是使用符文切片构建的，因为 Go 中重复的字符串连接效率很低。 构建完成后，符文切片将被转换回字符串。 

与Python不同`Counter`，Go 需要手动递增并从映射中显式删除。

 ## 边缘情况

 ### 中的字符`s`不存在于`order`错误的一个常见来源是忘记自定义排序字符串中未出现的字符。 

例如：```
order = "abc"
s = "abcdxyz"
```该问题仅限制了相对顺序`'a'`,`'b'`， 和`'c'`。 角色如`'d'`,`'x'`,`'y'`， 和`'z'`可能出现在任何地方。 

该实现通过在处理后将这些字符保留在频率图中来正确处理此问题`order`，然后附加它们。 

### 重复字符

 另一个重要的情况是重复字符。 

例如：```
order = "cba"
s = "aaabbbccc"
```幼稚的实现可能会意外地只附加每个字符的一次出现。 

频率图保证了正确性，因为每个字符都是根据其存储的计数精确附加的。 

### 订单包含未使用的字符

 的`order`字符串可能包含从未出现过的字符`s`。 

例如：```
order = "xyzabc"
s = "aabbcc"
```人物`'x'`,`'y'`， 和`'z'`是无关紧要的，因为它们没有出现在`s`。 

该实现安全地跳过它们，因为频率图查找根本失败，导致结果没有添加。
