 **难度：** 🟡 中等
 **主题：** 数组、二分查找、滑动窗口、前缀和

 ## 解决方案

 ## 问题理解

 该问题要求我们计算给定数组中有多少个连续子数组的乘积严格小于目标值`k`。 

子数组是数组的连续部分。 例如，在数组中`[10, 5, 2, 6]`，子数组`[5, 2]`有效，因为这些元素连续出现，而`[10, 2]`不是有效的子数组，因为元素是分开的。 

输入包括：

 -`nums`，正整数数组
 -`k`，整数阈值

 对于每个可能的连续子数组，我们计算其中所有元素的乘积。 如果该产品严格小于`k`，子数组对最终计数有贡献。 

重要的细节是条件严格小于`k`，不小于或等于`k`。 

约束很重要，因为它们决定哪些算法可行：

 -`nums.length`可以大到`3 * 10^4`- 每个元素都是正数，介于`1`和`1000`-`k`可以大到`10^6`显式检查每个子数组的简单算法需要二次时间，当数组长度接近 30,000 时，时间会变得太慢。 

一个非常重要的属性是所有数字都是正数。 这完全改变了产品在扩大或缩小窗口时的行为：

 - 乘以一个新的正数只能增加或维持乘积
 - 除以移除的正数只能减少或维持乘积

 这种单调行为使得滑动窗口技术成为可能。 

一些边缘情况很重要：

 - 如果`k <= 1`，答案总是`0`，因为中的每个元素`nums`至少是`1`，所以每个子阵列产品至少是`1`- 包含许多的数组`1`s 可以产生大量有效的子数组
 - 大型产品可能会暂时超出`k`，需要反复缩小窗口
 - 单元素子数组也必须计算在内

 ## 方法

 ### 蛮力方法

 最直接的解决方案是生成每个可能的子数组并计算其乘积。 

对于每个起始索引`i`，我们将子数组向右扩展一次一个元素：

 - 从产品开始`1`- 乘以`nums[j]`对于每个结束索引`j >= i`- 如果产品小于`k`，增加答案

 这种方法是正确的，因为它明确地检查每个连续子数组一次。 

但是，长度数组中子数组的数量`n`是：$$\frac{n(n+1)}{2}$$这是`O(n^2)`。 

和`n = 30000`，这变得太慢了。 

### 最优滑动窗口方法

 关键的观察结果是所有因素都是积极的。 

假设我们维护一个窗口`[left, right]`其产品小于`k`。 

如果我们通过移动来扩展窗口`right`向前看，乘积只会增加，因为所有值都是正数。 

如果产品变得太大，我们可以通过移动来恢复有效性`left`从产品中转发并划分出元素。 

关键的见解是这样的：

 如果当前窗口`[left, right]`产品小于`k`，然后每个子数组结束于`right`并从之间的任意位置开始`left`和`right`也是有效的。 

例如，如果：```
[left ... right]
```有效，那么这些也有效：```
[right]
[right-1 ... right]
[right-2 ... right]
...
[left ... right]
```这样的子数组的数量是：```
right - left + 1
```这允许我们一次计算许多有效的子数组，而不是单独检查它们。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 显式检查每个子数组 |
 | 最佳 | O(n) | O(1) | O(1) | 使用左边界缩小的滑动窗口 |

 ## 算法演练

 ### 第 1 步：处理特殊情况`k <= 1`由于中的每个元素`nums`至少是`1`，每个子阵列乘积也至少`1`。 

这意味着没有子数组可以满足：$$\text{product} < k$$什么时候`k <= 1`。 

于是我们立即返回`0`。 

### 步骤2：初始化滑动窗口

 我们维持：

 -`left`, 窗口的左边界
 -`product`，窗口内所有元素的乘积
 -`count`，到目前为止找到的有效子数组的总数

 最初：

 -`left = 0`-`product = 1`-`count = 0`### 步骤 3：向右展开窗口

 我们使用以下方法迭代数组`right`。 

对于每个新元素：

 - 将其乘以当前的乘积
 - 窗口现在变成`[left, right]`### 步骤 4：当产品太大时缩小窗口

 如果产品变得大于或等于`k`，当前窗口无效。 

我们反复强调：

 - 划分出来`nums[left]`- 移动`left`向右一步

 直至产品再次有效。 

由于所有数字都是正数，因此缩小窗口总是会减小或维持乘积。 

### 步骤 5：计算以 结尾的有效子数组`right`一旦窗口再次有效，每个以`right`并开始之间`left`和`right`是有效的。 

这样的子数组的数量是：$$right - left + 1$$我们将此值添加到答案中。 

### 步骤 6：继续，直到数组耗尽

 我们对每个职位重复这个过程`right`。 

在最后，`count`包含有效子数组的总数。 

### 为什么它有效

 该算法保持了当前窗口的不变性`[left, right]`产品始终严格小于`k`。 

因为所有值都是正数，所以从左侧删除元素只能减少乘积。 因此，一旦窗口再次有效，该窗口内的每个较小的后缀也有效。 

对于固定的`right`，该算法精确计算所有以`right`，并且没有子数组被计算多次。 这样就保证了正确性。 

## Python 解决方案```python
from typing import List

class Solution:
    def numSubarrayProductLessThanK(self, nums: List[int], k: int) -> int:
        if k <= 1:
            return 0

        left = 0
        product = 1
        count = 0

        for right in range(len(nums)):
            product *= nums[right]

            while product >= k:
                product //= nums[left]
                left += 1

            count += right - left + 1

        return count
```实施从关键边缘情况检查开始`k <= 1`。 如果没有这个条件，滑动窗口逻辑就会失败，因为不可能存在有效的子数组。 

变量`product`存储当前窗口产品。 作为`right`指针扩大窗口，新值乘以乘积。 

当产品失效时，`while`循环从左侧缩小窗口，直到乘积再次严格小于`k`。 

恢复有效性后，表达式：```python
right - left + 1
```计算所有以索引结尾的有效子数组`right`。 

该算法绝不会在不必要的情况下重新访问元素。 每个元素进入窗口一次，离开窗口一次，这就是总运行时间是线性的。 

## 解决方案```go
func numSubarrayProductLessThanK(nums []int, k int) int {
    if k <= 1 {
        return 0
    }

    left := 0
    product := 1
    count := 0

    for right := 0; right < len(nums); right++ {
        product *= nums[right]

        for product >= k {
            product /= nums[left]
            left++
        }

        count += right - left + 1
    }

    return count
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

一个重要的细节是整数除法。 由于每个被除法的值之前都已乘以乘积，因此整数除法仍然是精确的。 

Go 切片已经是类似引用的结构，因此不需要额外的复制。 

这些约束保证标准整数算术足以解决这个问题。

 ## 边缘情况

 ### 案例 1：`k <= 1`这是整个问题中最重要的边缘情况。 

由于所有数字都是正整数并且至少`1`，每个子阵列乘积也至少`1`。 

因此，当`k`是`0`或者`1`，不能存在有效的子数组。 

一个常见的错误是忘记这个条件，这可能导致错误计数或无限收缩循环。 实现立即处理这个问题：```
if k <= 1:
    return 0
```### 情况 2：单元素数组

 如果算法假设窗口较大，则仅包含一个元素的数组很容易被错误处理。 

例如：```
nums = [5], k = 10
```单个子数组`[5]`是有效的。 

滑动窗口自然可以处理这个问题，因为窗口大小可以保持不变`1`，以及公式：```
right - left + 1
```正确评估为`1`。 

### 案例3：多次超标的产品`k`某些输入需要连续多次缩小窗口。 

例子：```
nums = [2,3,4]
k = 10
```当产品变成`24`, removing only one element may still leave the product too large.

 这`while`循环是必不可少的，因为它会继续收缩，直到恢复不变式：```
while product >= k:
    product //= nums[left]
    left += 1
```如果没有循环，算法将错误地计算无效子数组。
