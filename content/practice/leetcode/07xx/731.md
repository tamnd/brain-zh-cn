 ## 解决方案

 ## 问题理解

 该问题要求我们设计一个日历系统，该系统支持预订时间间隔，同时执行一个重要规则：三个事件不能同时覆盖任何时间点。 

每个事件都表示为半开区间`[startTime, endTime)`。 这意味着该活动包括`startTime`但不包括`endTime`。 例如，间隔`[10, 20)`和`[20, 30)`因为时间不重叠`20`只属于第二个区间。 

这`book(startTime, endTime)`方法应该尝试将新事件插入日历中。 如果添加此事件会创建三个事件重叠的任何时间范围，则必须拒绝预订并且日历状态必须保持不变。 否则，预订成功。 

约束条件很重要：

 -`0 <= start < end <= 10^9`- 至多`1000`预订电话

 非常大的时间范围告诉我们不能使用按时间索引的数组。 然而，操作数量相对较少，最多只有 1000 个，这意味着`O(n^2)`风格解决方案是可以接受的。 

关键的一点是允许双重预订，但不允许三次预订。 这意味着我们必须仔细跟踪两个事件已经重叠的区域。 如果新活动与这些区域中的任何一个相交，它将立即创建三重预订。 

一些边缘情况很重要：

 - 相邻的间隔，例如`[10, 20)`和`[20, 30)`不应重叠。 
- 预订可以分别与多个现有活动重叠，而无需创建三重预订。 
- 与已经重复预订的区域重叠哪怕一点点的预订都必须被拒绝。 
- 失败的预订不得修改内部状态。 

## 方法

 ### 蛮力方法

 一种简单的方法是存储每个预订间隔，并针对每个新预订，计算每个相关段有多少事件重叠。 

一种方法是：

 1. 临时添加新的间隔。 
2. 收集所有起点和终点。 
3. 浏览时间线，计算活动间隔。 
4. 如果重叠次数超过 2 次，则拒绝预订。 

这是有效的，因为扫描线可以准确计算每个时间点同时发生的事件的数量。 

然而，每次预订后从头开始重新计算重叠计数的效率很低。 如果有`n`预订时，每次插入可能需要检查所有现有间隔和所有边界点。 在许多操作中，这会变得不必要的昂贵。 

### 最佳方法

 关键的见解是，只有当新的间隔与已经双重预订的区域重叠时，才会发生三次预订。 

我们维护两个单独的列表：

 -`bookings`, 所有成功预订的区间
 -`overlaps`, 所有已重复预订的间隔

 当新事件到来时：

 1.首先检查是否与任意区间相交`overlaps`。 

- 如果是，该预订将创建三重预订，因此请拒绝。 
2. 否则，将新间隔与所有现有预订进行比较。 

- 任何交叉路口都会成为新的双重预订间隔，因此将其存储在`overlaps`。 
3. 最后，将新的间隔添加到`bookings`。 

这有效是因为`overlaps`精确地表示已经覆盖两次的每个时间范围。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 每次预订 O(n²) | O(n) | 重复重新计算重叠计数 |
 | 最佳| 每次预订 O(n) | O(n) | 直接跟踪重复预订的间隔 |

 ## 算法演练

 1. 初始化两个列表：

 -`bookings`，存储每个成功预订的间隔
 -`overlaps`，存储两个预订已经重叠的间隔
 2. 新预订时`[startTime, endTime)`到达时，首先对照中的每个间隔检查它`overlaps`。 
3. 两个区间重叠，如果：```
startTime < existingEnd AND endTime > existingStart
```此条件确保存在非空共享区域。 
4. 如果新预订与以下任何时间间隔相交`overlaps`，立即返回`False`。 

- 该重叠区域已被两个事件覆盖。 
- 添加另一个活动将创建三次预订。 
5. 如果没有发生三次预订，则将新间隔与中的每个现有间隔进行比较`bookings`。 
6. 对于发现的每个重叠：

 - 计算交集：```
overlapStart = max(startTime, existingStart)
overlapEnd = min(endTime, existingEnd)
```- 将此交叉点添加到`overlaps`。 
- 这个新创建的区域现在已被双重预订。 
7. 处理完所有现有预订后，将新间隔附加到`bookings`。 
8. 返回`True`因为预订成功了。 

### 为什么它有效

 不变的是`overlaps`始终包含当前预订两次的每个区域。 在接受新预订之前，我们会验证其不与任何此类区域相交。 因此，任何接受的预订都不会产生三重重叠。 由于每个新形成的双重预订区域都被添加到`overlaps`，每次成功插入后，不变式仍然成立。 

## Python 解决方案```python
class MyCalendarTwo:

    def __init__(self):
        self.bookings = []
        self.overlaps = []

    def book(self, startTime: int, endTime: int) -> bool:

        # Check for triple booking
        for overlap_start, overlap_end in self.overlaps:
            if startTime < overlap_end and endTime > overlap_start:
                return False

        # Record newly created double bookings
        for booked_start, booked_end in self.bookings:
            if startTime < booked_end and endTime > booked_start:
                self.overlaps.append((
                    max(startTime, booked_start),
                    min(endTime, booked_end)
                ))

        # Add the booking
        self.bookings.append((startTime, endTime))

        return True
```实现直接遵循前面描述的算法。 

构造函数初始化两个列表。 这`bookings`列表存储所有接受的事件，而`overlaps`列出已预订两次的商店区域。 

里面的`book`方法中，第一个循环检查新间隔是否与任何双重预订区域相交。 如果存在这样的交集，该方法立即返回`False`因为接受预订会造成三重重叠。 

第二个循环计算由传入间隔创建的所有新的双重预订区域。 对于与现有预订的每次重叠，交叉点间隔都会添加到`overlaps`。 

最后，预订本身被附加到`bookings`，该方法返回`True`。 

半开区间的使用自然由重叠条件处理：```python
startTime < existingEnd and endTime > existingStart
```这正确地将触摸间隔视为不重叠。 

## 解决方案```go
type MyCalendarTwo struct {
	bookings [][2]int
	overlaps [][2]int
}

func Constructor() MyCalendarTwo {
	return MyCalendarTwo{
		bookings: make([][2]int, 0),
		overlaps: make([][2]int, 0),
	}
}

func (this *MyCalendarTwo) Book(startTime int, endTime int) bool {

	// Check for triple booking
	for _, interval := range this.overlaps {
		overlapStart := interval[0]
		overlapEnd := interval[1]

		if startTime < overlapEnd && endTime > overlapStart {
			return false
		}
	}

	// Record new double bookings
	for _, interval := range this.bookings {
		bookedStart := interval[0]
		bookedEnd := interval[1]

		if startTime < bookedEnd && endTime > bookedStart {

			newOverlap := [2]int{
				max(startTime, bookedStart),
				min(endTime, bookedEnd),
			}

			this.overlaps = append(this.overlaps, newOverlap)
		}
	}

	// Add booking
	this.bookings = append(this.bookings, [2]int{startTime, endTime})

	return true
}

func max(a int, b int) int {
	if a > b {
		return a
	}
	return b
}

func min(a int, b int) int {
	if a < b {
		return a
	}
	return b
}
```Go 的实现与 Python 版本非常相似。 由于 Go 没有元组，因此间隔存储为固定大小的数组`[2]int`。 

切片`bookings`和`overlaps`随着预订的增加而动态增长。 辅助函数`max`和`min`显式实现是因为 Go 不提供内置整数版本。 

由于约束很小，因此使用线性扫描切片就完全足够了。

 ## 边缘情况

 一种重要的边缘情况是相邻间隔，例如`[10, 20)`和`[20, 30)`。 幼稚的实现可能会错误地将它们视为重叠，因为端点接触。 正确的重叠条件使用严格的不等式：```
start < existingEnd AND end > existingStart
```这确保接触边界不被视为重叠。 

当多个重叠独立存在时，会出现另一种严重情况。 例如，预订可能会重叠一个区域中的一个事件和不同区域中的另一事件，而无需创建三重预订。 该实现可以正确处理此问题，因为它仅跟踪实际的双重预订间隔，而不仅仅是全局重叠事件的数量。 

第三个微妙的情况是插入失败。 如果预订会产生三重重叠，则日历状态必须保持不变。 该实现保证了这一点，因为它在修改之前检查所有现有的双重预订间隔`bookings`或者`overlaps`。 因此，被拒绝的预订永远不会部分更新内部状态。
