 # LeetCode 755 - 倒水

 ## 问题理解

 这个问题要求我们模拟水滴倒在一维地形上时的行为。 地形由数组表示`heights`，其中每个元素描述该位置的列的高度。 

我们还得到：

 -`volume`, 倾倒的水滴数量
 -`k`，每个水滴最初着陆的索引

 每个液滴的行为都是独立的，并且在沉降之前遵循严格的运动规则。 

液滴从索引处开始`k`。 从那里：

 1.它首先尝试向左移动。 
2. 如果向左移动最终会导致高度降低，则继续向左移动。 
3. 如果向左不起作用，它会尝试向右移动。 
4. 如果两个方向都没有导致更低的位置，则保持在当前位置。 

关键细节是“最终倒下”这句话。 液滴可以在平坦的地形上移动，同时寻找较低的位置。 它不会立即停止在第一个等高位置。 相反，它会继续探索，直到找到较低的水平或遇到较高的障碍。 

某个位置的“级别”是指：```
terrain height + accumulated water
```由于水会随着时间的推移而积累，因此每个水滴沉降后有效高度都会发生变化。 

输出是最终状态`heights`倾倒所有液滴后阵列。 修改后的阵列隐式包含水，因为每个沉降的水滴都会增加其静止位置的高度。 

限制相对较小：

 -`heights.length <= 100`-`volume <= 2000`这些限制强烈表明直接模拟是可以接受的。 我们不需要先进的优化技术或复杂的数据结构。 使用嵌套循环进行的仔细模拟将在限制内舒适地运行。 

一些边缘情况很重要：

 - 完全平坦的地形
 - 严格增加或减少地形
 - 多个等高山谷
 - 水被困在墙之间
 - 水反复沉降在源头指标处的情况
 - 水滴在落下之前可以经过相同高度的情况

 如果太早停止移动或者没有正确地将左移动优先于右移动，那么幼稚的实现很容易失败。 

## 方法

 ### 蛮力方法

 蛮力的想法是以一种极其字面的方式模拟每个水滴的每一种可能的运动。 

对于每个液滴：

 1.从索引开始`k`2. 反复尝试一次向左移动一步
 3. 如果发现更低的位置，则继续该位置
 4. 否则重新启动`k`并在右侧尝试相同的过程
 5.最后沉淀液滴

 这种方法是正确的，因为它完全遵循问题陈述中的运动规则。 每个液滴独立地寻找有效的静止位置。 

然而，实施不当的强力解决方案可能会不必要地重复扫描阵列的大部分。 如果我们过于频繁地重新启动搜索或模拟运动效率低下，我们最终可能会陷入多余的工作。 

尽管约束足够小，许多暴力实现都可以通过，但我们仍然可以更干净、更高效地组织模拟。 

### 最佳模拟方法

 关键的观察结果是，根据运动优先级，液滴总是落在最佳可到达位置：

 1. 最远有效左下降
 2. 否则最远有效的右下降
 3.否则当前位置

 我们可以直接搜索最佳的静止位置，而不是通过复杂的状态跟踪逐个单元地模拟液滴。 

对于左侧搜索：

 - 向左移动，同时高度不增加
 - 跟踪遇到的最低位置
 - 如果多个位置的最小高度相同，则选择最左边的一个

 如果不存在有效的左下位置，则在右侧执行对称搜索。 

这是有效的，因为水滴只关心最终到达较低的水平，而不关心确切的物理路径。 

实现变得更加清晰：

 - 向左扫描以找到最佳的左侧休息点
 - 如果找到，请将水放在那里
 - 否则向右扫描
 - 否则将水置于`k`由于数组大小非常小，因此这种直接模拟既高效又易于推理。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(体积 × n²) | O(1) | O(1) | 通过冗余重新扫描非常真实地模拟运动 |
 | 最佳 | O(体积×n) | O(1) | O(1) | 高效定向扫描直接找到正确的休息位置 |

 ## 算法演练

 1. 使用给定的初始化模拟`heights`大批。 

阵列本身将存储地形和积水。 每次液滴沉降时，我们都会增加该位置的高度。 
2. 独立处理每个水滴。 

由于每个液滴都会改变未来液滴的地形，因此我们必须按顺序模拟它们。 
3.先尝试向左移动。 

从索引开始`k`并在地形不增加的情况下向左扫描。 

具体来说，继续向左移动，同时：```
heights[i - 1] <= heights[i]
```在此扫描期间，跟踪遇到的最小高度的位置。 
4. 如果存在左下位置，则将液滴放置在那里。 

液滴更喜欢最左边的有效下降。 一旦我们确定了最佳的左侧位置，就增加其高度并移动到下一个液滴。 
5. 如果向左移动失败，请在右侧尝试相同的过程。 

当地形不增加时向右扫描：```
heights[i + 1] <= heights[i]
```再次跟踪遇到的最小高度的位置。 
6. 如果存在右下位置，则将液滴放置在那里。 

增加所选位置的高度。 
7. 如果两个方向都没有产生较低的位置，则稳定在`k`。 

这意味着液滴最终不能向任一方向落下。 
8. 重复此操作，直至处理完所有液滴。 
9.返回修改后的内容`heights`大批。 

### 为什么它有效

 该算法之所以有效，是因为它准确地反映了问题陈述中定义的运动优先级。 

液滴仅移动通过不高于其当前水平的位置。 在遍历这些位置时，它会搜索严格较低的级别。 始终首先执行左侧搜索，这保留了所需的优先级规则。 

跟踪最小可到达高度可确保液滴落在正确的最终位置。 由于每个液滴都会立即更新地形，因此未来的液滴会看到正确的有效高度。 

## Python 解决方案```python
from typing import List

class Solution:
    def pourWater(self, heights: List[int], volume: int, k: int) -> List[int]:
        n = len(heights)

        for _ in range(volume):
            position = k

            # Try moving left
            best = k
            i = k

            while i > 0 and heights[i - 1] <= heights[i]:
                if heights[i - 1] < heights[best]:
                    best = i - 1
                i -= 1

            if best != k:
                heights[best] += 1
                continue

            # Try moving right
            best = k
            i = k

            while i < n - 1 and heights[i + 1] <= heights[i]:
                if heights[i + 1] < heights[best]:
                    best = i + 1
                i += 1

            if best != k:
                heights[best] += 1
                continue

            # Stay at k
            heights[k] += 1

        return heights
```实现直接遵循算法结构。 

外环独立处理每个水滴。 由于地形在每个液滴后都会发生变化，因此需要顺序模拟。 

左侧扫描开始于`k`并在下一个位置不更高时移动。 在遍历过程中，算法会跟踪最低的可到达位置。 如果找到较低的位置，液滴会立即沉淀在那里，因为向左移动的优先级高于向右移动。 

如果左侧搜索失败，则算法在右侧执行相同的逻辑。 

最后，如果两个方向均不包含较低的可达到水平，则液滴将停留在原始索引处`k`。 

该解决方案修改了`heights`阵列就位，自然代表地形和积水。 

## 解决方案```go
func pourWater(heights []int, volume int, k int) []int {
	n := len(heights)

	for v := 0; v < volume; v++ {

		// Try moving left
		best := k
		i := k

		for i > 0 && heights[i-1] <= heights[i] {
			if heights[i-1] < heights[best] {
				best = i - 1
			}
			i--
		}

		if best != k {
			heights[best]++
			continue
		}

		// Try moving right
		best = k
		i = k

		for i < n-1 && heights[i+1] <= heights[i] {
			if heights[i+1] < heights[best] {
				best = i + 1
			}
			i++
		}

		if best != k {
			heights[best]++
			continue
		}

		// Stay at k
		heights[k]++
	}

	return heights
}
```Go 实现几乎完全反映了 Python 逻辑。 

Go 切片是引用类型，因此修改`heights`直接更新底层数组。 无需额外复印。 

整数溢出不是问题，因为约束非常小。 添加所有水后的最大可能高度仍然在 Go 的整数范围内。 

该实现使用迭代循环而不是递归，因此不存在堆栈深度问题。

 ## 边缘情况

 ### 完全平坦的地形

 平坦的地形，例如：```
[2,2,2,2]
```可以轻松暴露运动逻辑中的错误。 幼稚的实现可能会错误地允许液滴无限期地漂移或选择错误的方向。 

该问题表明，只要有可能，就首选向左移动。 我们的实现正确地处理了这个问题，始终首先扫描左侧，如果不存在左下位置，则仅扫描右侧。 

### 高墙之间的深谷

 考虑：```
[10,1,10]
```水反复沉降在中心，因为两侧都没有提供较低的可达到的水位。 一些不正确的解决方案试图均匀地分布水或模拟流体平衡，这在本问题中是不允许的。 

我们的实现独立地处理每个液滴，并为每个液滴精确地增加一列，从而精确匹配问题要求。 

### 跨越同等高度的运动

 一个微妙的情况是：```
[3,2,2,3]
```水滴在最终落下之前可能需要经过相同的高度。 不正确的实现通常会在遇到等高位置时立即停止。 

我们的扫描条件：```
heights[next] <= heights[current]
```允许遍历平坦区域，同时仍然搜索较低的位置，这正确地实现了“最终落下”规则。
