 # LeetCode 746 - 爬楼梯的最低成本

 ## 问题理解

 这个问题给了我们一个名为`cost`，其中每个元素代表踏上特定楼梯的成本。 如果`cost[i]`等于`10`，这意味着踩楼梯`i`需要付费`10`。 

从任何楼梯上，我们都可以向上移动一级或两级。 目标是花费尽可能少的钱到达楼梯的“顶部”。 

一个重要的细节是 top 不是数组中的实际索引。 如果数组有长度`n`，那么顶部被认为刚好超出索引`n - 1`。 您可以从最后一个楼梯或倒数第二个楼梯到达顶部。 

另一个关键细节是我们可以从索引开始`0`或索引`1`。 这意味着我们不一定要支付第一层楼梯的费用。 我们可以自由选择更便宜的起始策略。 

例如，与：```
cost = [10, 15, 20]
```我们可以：

 - 从索引开始`0`， 支付`10`，然后移至索引`2`， 支付`20`， 全部的`30`- 从索引开始`1`， 支付`15`，然后直接跳到顶部，总计`15`因此最小成本为`15`。 

限制相对较小：

 -`2 <= cost.length <= 1000`-`0 <= cost[i] <= 999`数组长度为`1000`对于动态编程解决方案来说足够小，但又足够大，以至于指数暴力递归会变得太慢。 

尽早识别一些边缘情况很重要：

 - 数组只能包含两个元素，这是最小的有效输入。 
- 成本可以为零，这意味着某些楼梯实际上是免费的。 
- 最便宜的路径可以使用两步跳跃来跳过昂贵的楼梯。 
- 总是选择更便宜的直接步骤的贪婪策略并不总是在全球范围内有效。 

这个问题从根本上讲是关于在重用重叠子问题的解决方案的同时做出最优决策，这是动态规划的经典指标。 

## 方法

 ### 蛮力方法

 蛮力解决方案会尝试从起始位置到顶部的所有可能路径。 

在每个楼梯上，我们有两种选择：

 1. 移动一步
 2.移动两步

 我们递归地计算两种可能性的最小总成本，并取较小的结果。 

例如，从楼梯`i`:```sql
minimum cost from i =
cost[i] + min(
    minimum cost from i + 1,
    minimum cost from i + 2
)
```由于相同的子问题被重新计算多次，因此递归树呈指数增长。 靠近起点的楼梯会重复重新计算同一后续楼梯的结果。 

尽管这种方法可以产生正确的答案，但随着输入的增加，它的效率会变得很低。 

### 最优动态规划方法

 关键的观察是到达楼梯的最小成本`i`仅取决于前两级楼梯的最低成本。 

如果我们定义：```
dp[i] = minimum cost to reach stair i
```然后：```
dp[i] = cost[i] + min(dp[i - 1], dp[i - 2])
```这是有效的，因为到达楼梯的唯一方法`i`是：

 - 从楼梯`i - 1`- 从楼梯`i - 2`我们不再重复重新计算子问题，而是计算每个状态一次并存储它。 

更好的优化是可能的，因为我们只需要前两个值。 我们可以用两个变量替换整个 DP 数组，将空间复杂度降低到常量空间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 递归探索所有可能的路径 |
 | 最佳 | O(n) | O(1) | O(1) | 使用滚动变量进行动态规划 |

 ## 算法演练

 1. 将前两个楼梯作为基本案例处理。 

到达楼梯的最低成本`0`简直就是`cost[0]`，因为踩到它需要支付该金额。 

同样，到达楼梯的最小成本`1`是`cost[1]`。 
2. 创建两个变量来存储之前的DP状态。 

我们使用：

 -`first`以最小的成本到达楼梯`i - 2`-`second`以最小的成本到达楼梯`i - 1`这避免了分配整个 DP 阵列。 
3. 从索引开始迭代楼梯`2`。 

对于每一个楼梯`i`， 计算：```
current = cost[i] + min(first, second)
```这是到达楼梯最便宜的方式`i`。 
4. 向前移动滚动变量。 

计算后`current`:

 -`first`变成`second`-`second`变成`current`这为下一次迭代准备变量。 
5. 返回最后两个状态中的最小值。 

顶部位于最后一个楼梯之外，因此我们可以从以下任一处到达：

 - 最后一个楼梯
 - 倒数第二个楼梯

 因此，答案是：```
min(first, second)
```### 为什么它有效

 该算法之所以有效，是因为每个楼梯只能从前两个楼梯之一到达。 通过存储到达每个楼梯的最小成本，我们确保未来的每个计算都建立在已经最优的解决方案的基础上。 

这在整个迭代过程中创建了一个不变量：

 -`first`始终存储到达楼梯的最低成本`i - 2`-`second`始终存储到达楼梯的最低成本`i - 1`使用这些最优子问题解可以保证计算结果是全局最优的。 

## Python 解决方案```python
from typing import List

class Solution:
    def minCostClimbingStairs(self, cost: List[int]) -> int:
        first = cost[0]
        second = cost[1]

        for i in range(2, len(cost)):
            current = cost[i] + min(first, second)
            first = second
            second = current

        return min(first, second)
```实施首先初始化前两个楼梯的成本。 这些充当动态编程转换的基本状态。 

循环从索引处开始`2`因为前两个状态是已知的。 对于每个楼梯，我们计算到达该楼梯所需的最低总成本。 

表达式：```python
cost[i] + min(first, second)
```表示当前楼梯的成本加上之前两条可能路径中较便宜的一条。 

计算当前状态后，滚动变量将被更新，以便它们继续代表前两个 DP 状态。 

最后，我们返回最后两个可到达楼梯之间较小的值，因为可以从任一楼梯到达顶部。 

## 解决方案```go
func minCostClimbingStairs(cost []int) int {
    first := cost[0]
    second := cost[1]

    for i := 2; i < len(cost); i++ {
        current := cost[i]

        if first < second {
            current += first
        } else {
            current += second
        }

        first = second
        second = current
    }

    if first < second {
        return first
    }

    return second
}
```Go 实现遵循与 Python 版本相同的动态编程逻辑。 

Go 没有提供内置的`min`旧标准库版本中的整数函数，因此实现使用显式比较`if`声明。 

Go 中的切片已经携带了它们的长度信息，因此迭代楼梯很简单，使用`len(cost)`。 

整数溢出不是问题，因为最大可能的总成本完全在 Go 的整数范围内：```go
1000 stairs × maximum cost 999 = 999000
```## 工作示例

 ## 边缘情况

 一种重要的边缘情况是最小的有效输入大小，其中数组仅包含两个楼梯。 由于我们可以从任一楼梯开始，因此答案就是两个成本中较小的一个。 一些不正确的实现意外地假设至少存在三个元素并尝试建立无效索引。 我们的实现自然地处理了这个问题，因为当数组长度为 2 时循环永远不会执行。 

另一个重要的边缘案例涉及零成本楼梯。 例如：```
[0, 1, 0, 1]
```最佳解决方案可以跳过所有可能的昂贵楼梯，并且总体上无需支付任何费用。 总是一次移动一步的贪婪实现在这里可能会失败。 动态规划解决方案正确地探索了一步和两步转换。 

当应该策略性地跳过昂贵的楼梯时，就会出现第三个重要的边缘情况。 考虑：```
[1, 100, 1, 100, 1]
```最佳路径反复跳过昂贵的楼梯。 选择局部最便宜的下一步行动的天真贪婪策略可能会做出错误的决定，因为稍微昂贵的立即选择可能会导致稍后更便宜的总路径。 动态规划通过计算全局最优子问题解决方案来避免这个问题。 

最后的边缘情况是最大输入大小。 和`1000`楼梯，由于递归调用呈指数增长，递归蛮力变得不切实际。 迭代 DP 解决方案对每个楼梯处理一次，即使在约束极限下也能确保出色的性能。
