[LeetCode 743 题](https://leetcode.com/problems/network-delay-time/)

 **难度：** 🟡 中等
 **主题：** 深度优先搜索、广度优先搜索、图论、堆（优先级队列）、最短路径

 ## 解决方案

 ## 问题理解

 该问题对有向加权图进行建模。 每个节点代表网络中的一台计算机，每个有向边代表信号从一个节点传播到另一个节点所需的时间。 

输入`times`包含以下格式的边：```
(ui, vi, wi)
```在哪里：

-`ui`是源节点
 -`vi`是目的节点
 -`wi`出行时间是从`ui`到`vi`该图是有向的，这意味着信号可以从`ui`到`vi`，但不一定是相反的方向。 

我们开始从节点发送信号`k`。 任务是确定图中每个节点接收信号需要多长时间。 由于信号可以通过中间节点传播，因此我们实际上正在寻找从`k`to every other node.

 如果每个节点都是可达的，则答案是所有节点之间的最大最短路径距离。 这是因为最后接收到信号的节点决定了总延迟时间。 

如果至少一个节点无法从`k`，那么信号永远不会到达整个网络，所以我们返回`-1`。 

约束条件很重要：

 -`n <= 100`，所以图比较小
 -`times.length <= 6000`，这意味着图仍然可以相当密集
 - 边权重非负，`0 <= wi <= 100`非负边权重是关键的观察结果。 每当我们需要图中具有非负权重的最短路径时，Dijkstra 算法就变得很自然。 

一些边缘情况很重要：

 - 某些节点可能与起始节点断开连接
 - 图表可能包含循环
 - 边权重可能为零
 - 图中可能只有一个节点
 - 起始节点可能没有出边

 该问题保证同一对节点之间不存在重复的有向边，从而简化了图的构造。 

## 方法

 ### 蛮力方法

 强力解决方案将反复松弛每条边，直到找不到更短的距离。 这本质上是贝尔曼-福特算法。 

我们将到起始节点的距离初始化为`0`并将所有其他节点视为无穷大。 然后我们重复扫描所有边缘并尝试改善距离。 

对于每一个边缘`(u, v, w)`:```
distance[v] = min(distance[v], distance[u] + w)
```至多之后`n - 1`通过，保证计算出所有最短路径。 

这种方法是正确的，因为两个节点之间的最短路径最多可以包含`n - 1`edges. 反复松弛最终会在图中传播最佳距离。 

然而，该解决方案效率低下，因为即使大多数距离已经稳定，它也会重复处理所有边缘。 

### 最佳方法

 关键的见解是所有边权重都是非负的。 这允许我们使用 Dijkstra 算法。 

Dijkstra 算法总是首先扩展当前最近的未访问节点。 一旦一个节点从距离最小的优先级队列中删除，我们就知道它的最短路径已经确定。 

为了有效地检索下一个最近的节点，我们使用最小堆，也称为优先级队列。 

该算法的工作原理如下：

 1. 构建图的邻接列表表示
 2. 存储已知的最短距离`k`3. 使用按当前距离排序的最小堆
 4. 重复处理已知距离最小的节点
 5. 放松所有出边

 这避免了对整个边缘列表不必要的重复扫描，并显着提高了性能。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(V × E) | O(V) | 贝尔曼-福特式重复边缘松弛|
 | 最佳 | O((V + E) log V) | O(V + E) | Dijkstra 与邻接表和最小堆 |

 ## 算法演练

 1. 根据输入边构建邻接表。 

我们将边列表转换为图形表示，其中每个节点映射到其传出邻居。 这允许在算法期间有效地遍历相邻节点。 

结构示例：```
graph[2] = [(1, 1), (3, 1)]
```这意味着节点`2`有边缘：

 -`2 -> 1`有重量`1`-`2 -> 3`有重量`1`2. 初始化最短距离数组。 

我们存储已知的最短时间`k`到每个节点。 

最初：

-`distance[k] = 0`- 所有其他距离均为无穷大

 无穷大表示尚未到达的节点。 
3. 创建最小堆优先级队列。 

每个堆条目存储：```
(current_distance, node)
```堆确保我们总是接下来处理具有最小已知距离的节点。 
4. 开始处理堆中的节点。 

重复删除距离最小的节点。 

如果弹出的距离已经大于存储的最短距离，我们会跳过它，因为之前已经发现了更好的路径。 
5. 放松所有出边。 

对于每个邻居：```
new_distance = current_distance + edge_weight
```如果这个新路径比当前已知的距离短，则更新它并将新状态推入堆中。 
6. 继续，直到堆变空。 

至此，所有可达的最短路径都已确定。 
7. 计算最终答案。 

如果任意节点仍有无限距离，则返回`-1`。 

否则，返回距离数组中的最大值，因为最后一个接收信号的节点决定了总延迟时间。 

### 为什么它有效

 Dijkstra 算法依赖于边权重非负的特性。 当一个节点从最小堆中删除时，保证在所有未处理的节点中具有最小可能的最短路径距离。 

因为任何未来的路径只会添加非负权重，所以后面的路径不能为该节点产生更小的距离。 因此，每个最终确定的距离都是正确的。 

通过以距离递增的顺序反复松弛边缘，该算法计算出真正的最短路径`k`到每个可到达的节点。 

## Python 解决方案```python
from typing import List
import heapq
from collections import defaultdict

class Solution:
    def networkDelayTime(self, times: List[List[int]], n: int, k: int) -> int:
        graph = defaultdict(list)

        # Build adjacency list
        for source, target, weight in times:
            graph[source].append((target, weight))

        # Initialize distances
        distances = [float("inf")] * (n + 1)
        distances[k] = 0

        # Min-heap: (distance, node)
        min_heap = [(0, k)]

        while min_heap:
            current_distance, node = heapq.heappop(min_heap)

            # Skip outdated heap entries
            if current_distance > distances[node]:
                continue

            # Relax neighboring edges
            for neighbor, weight in graph[node]:
                new_distance = current_distance + weight

                if new_distance < distances[neighbor]:
                    distances[neighbor] = new_distance
                    heapq.heappush(
                        min_heap,
                        (new_distance, neighbor)
                    )

        max_distance = max(distances[1:])

        return max_distance if max_distance != float("inf") else -1
```实现首先使用构造邻接表`defaultdict(list)`。 这种表示允许有效地访问节点的所有传出边。 

这`distances`数组存储距源节点的最短已知距离`k`到每个其他节点。 指数`0`未使用，因为该图使用从 1 开始的索引。 

最小堆初始化为`(0, k)`因为起始节点到自身的距离为零。 

在主循环内，我们重复弹出已知距离最小的节点。 如果弹出的值已过时，这意味着已经发现了更短的路径，我们将跳过对其进行处理。 

对于每个邻居，我们计算一条候选较短路径。 如果候选者改进了现有的最短距离，我们就会更新数组并将新状态推入堆中。 

最后，我们检查是否到达每个节点。 如果任何距离仍然无穷大，我们返回`-1`。 否则，最大最短路径距离就是总的网络延迟时间。 

## 解决方案```go
package main

import (
	"container/heap"
	"math"
)

type Pair struct {
	node     int
	distance int
}

type MinHeap []Pair

func (h MinHeap) Len() int {
	return len(h)
}

func (h MinHeap) Less(i, j int) bool {
	return h[i].distance < h[j].distance
}

func (h MinHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MinHeap) Push(x interface{}) {
	*h = append(*h, x.(Pair))
}

func (h *MinHeap) Pop() interface{} {
	old := *h
	n := len(old)
	item := old[n-1]
	*h = old[:n-1]
	return item
}

func networkDelayTime(times [][]int, n int, k int) int {
	graph := make(map[int][][]int)

	// Build adjacency list
	for _, edge := range times {
		u := edge[0]
		v := edge[1]
		w := edge[2]

		graph[u] = append(graph[u], []int{v, w})
	}

	// Initialize distances
	distances := make([]int, n+1)

	for i := 1; i <= n; i++ {
		distances[i] = math.MaxInt32
	}

	distances[k] = 0

	minHeap := &MinHeap{}
	heap.Init(minHeap)

	heap.Push(minHeap, Pair{
		node:     k,
		distance: 0,
	})

	for minHeap.Len() > 0 {
		current := heap.Pop(minHeap).(Pair)

		node := current.node
		currentDistance := current.distance

		// Skip outdated entries
		if currentDistance > distances[node] {
			continue
		}

		// Relax neighbors
		for _, neighbor := range graph[node] {
			nextNode := neighbor[0]
			weight := neighbor[1]

			newDistance := currentDistance + weight

			if newDistance < distances[nextNode] {
				distances[nextNode] = newDistance

				heap.Push(minHeap, Pair{
					node:     nextNode,
					distance: newDistance,
				})
			}
		}
	}

	maxDistance := 0

	for i := 1; i <= n; i++ {
		if distances[i] == math.MaxInt32 {
			return -1
		}

		if distances[i] > maxDistance {
			maxDistance = distances[i]
		}
	}

	return maxDistance
}
```Go 实现遵循与 Python 解决方案相同的逻辑，但 Go 不提供内置的优先级队列。 相反，我们实施`heap.Interface`从`container/heap`包裹。 

邻接列表使用从节点 ID 到邻居权重对切片的映射。 

Go 没有整数的无穷大值，所以`math.MaxInt32`用作不可到达节点的哨兵。 

与 Python 中的元组比较行为不同`heapq`，Go 要求通过显式定义堆排序`Less`方法。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O((V + E) log V) | 每个堆操作花费log V，边缘松弛一次 |

出于时间复杂度的考虑，每个节点可能会被多次插入到堆中，但是每次堆操作都有成本`O(log V)`。 由于每条边最多可以触发一次成功的松弛，因此整体复杂性变为`O((V + E) log V)`。

 ## 边缘情况

 当某些节点无法从起始节点到达时，就会出现一种重要的边缘情况。 幼稚的实现可能会错误地返回最大可达距离，而不检查是否每个节点都被访问过。 在此实现中，不可达节点保留无穷大的距离值。 算法完成后，我们显式检查无穷大并返回`-1`如果从未到达任何节点。 

另一个重要的边缘情况涉及零权重边缘。 一些最短路径实现假设严格为正权重，但这个问题允许权重等于零。 Dijkstra 的算法仍然可以正确工作，因为权重仍然是非负的。 该实现在边缘松弛期间正确处理零成本转换。 

包含循环的图表是错误的另一个常见来源。 如果不小心处理，算法可能会无限期地重复访问节点。 优先级队列方法避免了这个问题，因为我们只处理改进的距离。 使用以下方法跳过过时的堆条目：```
if current_distance > distances[node]:
    continue
```这确保了正确性并防止不必要的处理。 

最终的边缘情况是可能的最小图，其中`n = 1`。 在这种情况下，起始节点已经有信号，所以正确答案是`0`。 由于距离数组初始化`distances[k] = 0`，实现自然会正确处理这种情况。
