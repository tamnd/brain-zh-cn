 ## 解决方案

 ## 问题理解

 这个问题要求我们设计一个动态跟踪数轴上的间隔的数据结构。 跟踪的间隔表示为半开间隔，这意味着`[left, right)`包括每个值`x`这样`left <= x < right`。 

数据结构必须支持三种操作：

 -`addRange(left, right)`标记每个值`[left, right)`如跟踪的那样。 
-`queryRange(left, right)`检查中的每个值是否`[left, right)`目前已被追踪。 
-`removeRange(left, right)`删除对每个值的跟踪`[left, right)`。 

重要的细节是间隔代表实数的连续范围，而不仅仅是整数。 这意味着我们不能简单地离散化范围，除非我们使用坐标压缩或更高级的结构。 

限制因素很重要：

 - 值可以大到`10^9`- 最多`10^4`执行操作

 直接布尔数组是不可能的，因为坐标范围很大。 我们需要一个只存储有意义的区间而不是每个单独的点的结构。 

核心挑战是有效地维持重叠间隔。 操作可能部分重叠现有范围、完全重叠或将它们分割成更小的部分。 

例如：

 - 添加`[10, 20)`然后添加`[15, 25)`应该合并到`[10, 25)`- 删除`[14, 16)`从`[10, 20)`应该将间隔分为：

 -`[10, 14)`-`[16, 20)`一些边缘情况很重要：

 - 相邻的间隔，例如`[1, 5)`和`[5, 10)`应该干净地合并，因为它们一起形成连续的覆盖。 
- 删除中间部分可能会将一个间隔分成两部分。 
- 查询部分覆盖的区间必须返回`false`。 
- 多个重叠的添加和删除必须保持一致的间隔边界。 

由于数轴稀疏且运算相对有限，因此仅存储合并的不相交区间是关键见解。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试跟踪范围内的每个单独点。 一种可能的实现将使用包含所有跟踪整数的集合。 

例如：

-`addRange(10, 20)`插入整数`10`通过`19`-`removeRange(14, 16)`删除`14`和`15`-`queryRange(10, 14)`检查所有整数是否存在

 这种方法适用于仅整数的解释，但问题明确定义了实数的范围。 更重要的是，坐标范围达到`10^9`，使得显式存储变得不可能。 

即使我们忽略实数问题而只考虑整数，添加一个长度范围`10^9`需要大量的内存和时间。 

因此，暴力破解是行不通的。 

### 最佳方法

 关键的观察是操作数量很少，但坐标范围很大。 我们不存储每个点，而是仅存储合并的不相交区间。 

数据结构维护一个不重叠间隔的排序列表：```
[(1, 5), (10, 20), (30, 40)]
```每当我们添加一个范围时：

 - 合并重叠或相邻的间隔
 - 保留排序顺序
 - 保持不重叠的结构

 每当我们删除一个范围时：

 - 修剪部分重叠的间隔
 - 如有必要，分割间隔
 - 删除完全覆盖的间隔

 查询变得高效，因为我们只需要定位一个区间是否完全覆盖查询范围。 

这种间隔合并策略极大地降低了存储需求并保持操作高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 每次操作 O(范围大小) | O（范围大小）| 坐标不可能达到`10^9`|
 | 最佳 | 每次操作 O(n) | O(n) | 仅存储合并的不相交间隔 |

 这里，`n`是存储的间隔数。 

## 算法演练

 我们维护一个名为的排序列表`intervals`，其中每个区间表示为`[start, end)`。 

例子：```
[(1, 5), (10, 20), (30, 40)]
```间隔始终为：

 - 按起始值排序
 - 不重叠
 - 最大程度地合并

 ### addRange（左，右）

 1. 创建一个新的结果列表。 
2. 从左到右遍历现有区间。 
3. 复制之前结束的所有间隔`left`因为它们不重叠。 
4. 对于重叠间隔：

 - 展开`left`到最小的开始
 - 展开`right`到最大极限
 - 这会将所有相交间隔合并为一个更大的间隔。 
5. 插入合并的区间。 
6. 合并后附加剩余间隔。 

这保证了重叠间隔成为单个连续间隔。 

### 查询范围（左、右）

 1. 按排序顺序遍历区间。 
2. 找到第一个末尾大于的区间`left`。 
3. 如果该区间也满足：

 -`start <= left`-`end >= right`那么整个查询范围就被覆盖了。 
4.否则返回`false`。 

由于区间是不重叠且已排序的，因此只有一个区间可能包含查询范围。 

### 删除范围（左，右）

 1. 遍历所有区间。 
2. 对于完全超出去除范围的间隔：

 - 保持它们不变。 
3. 对于重叠间隔：

 - 保留左侧不重叠的部分（如果存在）。 
- 保留右侧的不重叠部分（如果存在）。 

例如：```
Existing: [10, 20)
Remove:   [14, 16)

Result:
[10, 14)
[16, 20)
```这可能会将一个间隔分成两部分。 

### 为什么它有效

 不变的是区间列表始终保持不变：

 - 已排序
 - 不重叠
 - 最大程度地合并

 每个操作都保留这个不变量。 

由于重叠间隔在插入过程中立即合并，并且删除会仔细修剪重叠区域，因此该结构始终准确地表示数轴的跟踪区域。 

查询是正确的，因为任何覆盖范围都必须完全位于一个合并区间内。 

## Python 解决方案```python
from typing import List

class RangeModule:

    def __init__(self):
        self.intervals: List[List[int]] = []

    def addRange(self, left: int, right: int) -> None:
        merged = []
        i = 0
        n = len(self.intervals)

        while i < n and self.intervals[i][1] < left:
            merged.append(self.intervals[i])
            i += 1

        while i < n and self.intervals[i][0] <= right:
            left = min(left, self.intervals[i][0])
            right = max(right, self.intervals[i][1])
            i += 1

        merged.append([left, right])

        while i < n:
            merged.append(self.intervals[i])
            i += 1

        self.intervals = merged

    def queryRange(self, left: int, right: int) -> bool:
        for start, end in self.intervals:
            if start <= left and end >= right:
                return True

            if start > left:
                return False

        return False

    def removeRange(self, left: int, right: int) -> None:
        updated = []

        for start, end in self.intervals:
            if end <= left or start >= right:
                updated.append([start, end])
            else:
                if start < left:
                    updated.append([start, left])

                if end > right:
                    updated.append([right, end])

        self.intervals = updated
```该实现将间隔存储在排序列表中。 

这`addRange`方法执行区间合并。 首先，它完全复制插入范围之前的间隔。 然后它将每个重叠区间合并为一个更大的区间。 最后它附加所有剩余的间隔。 

这`queryRange`方法按顺序扫描间隔。 由于间隔是经过排序且不重叠的，因此只有一个间隔可能完全包含查询范围。 

这`removeRange`方法重建间隔列表。 适当修剪重叠间隔。 如果删除发生在某个间隔的中间，则该间隔将分为两个较小的间隔。 

该实现在每次操作后保持间隔列表标准化。 

## 解决方案```go
package main

type RangeModule struct {
	intervals [][]int
}

func Constructor() RangeModule {
	return RangeModule{
		intervals: [][]int{},
	}
}

func (this *RangeModule) AddRange(left int, right int) {
	merged := [][]int{}
	i := 0
	n := len(this.intervals)

	for i < n && this.intervals[i][1] < left {
		merged = append(merged, this.intervals[i])
		i++
	}

	for i < n && this.intervals[i][0] <= right {
		if this.intervals[i][0] < left {
			left = this.intervals[i][0]
		}

		if this.intervals[i][1] > right {
			right = this.intervals[i][1]
		}

		i++
	}

	merged = append(merged, []int{left, right})

	for i < n {
		merged = append(merged, this.intervals[i])
		i++
	}

	this.intervals = merged
}

func (this *RangeModule) QueryRange(left int, right int) bool {
	for _, interval := range this.intervals {
		start := interval[0]
		end := interval[1]

		if start <= left && end >= right {
			return true
		}

		if start > left {
			return false
		}
	}

	return false
}

func (this *RangeModule) RemoveRange(left int, right int) {
	updated := [][]int{}

	for _, interval := range this.intervals {
		start := interval[0]
		end := interval[1]

		if end <= left || start >= right {
			updated = append(updated, interval)
		} else {
			if start < left {
				updated = append(updated, []int{start, left})
			}

			if end > right {
				updated = append(updated, []int{right, end})
			}
		}
	}

	this.intervals = updated
}
```Go 实现遵循与 Python 版本相同的逻辑。 切片用于动态存储间隔。 

与 Python 列表不同，Go 切片需要显式追加和手动处理嵌套切片。 整数溢出不是问题，因为最大坐标只是`10^9`，它很适合 Go 的内部`int`。 

合并、查询和分割间隔的逻辑保持相同。

 ## 边缘情况

 ### 删除分割间隔的范围

 当移除范围完全位于现有区间内时，就会出现一种特别棘手的情况。 

例子：```
Tracked: [1, 10)
Remove:  [4, 6)
```有缺陷的实现可能会意外删除整个间隔或保留重叠部分。 正确的结果是：```
[1, 4)
[6, 10)
```该实现通过分别保留左侧和右侧不重叠的段来处理此问题。 

### 相邻间隔

 因为区间是半开的，`[1, 5)`和`[5, 10)`一起代表连续覆盖。 

一个常见的错误是未能合并相邻的间隔。 这可能会破坏如下查询：```
queryRange(1, 10)
```即使整个区域都被覆盖。 

每当出现以下情况时，实现都会合并间隔：```
interval_start <= right
```它正确地结合了触摸间隔。 

### 跨间隙查询

 假设我们有：```
[1, 5)
[7, 10)
```然后：```
queryRange(1, 10)
```必须返回`false`。 

有缺陷的实现可能会在概念上错误地组合多个间隔。 但是，查询必须通过单个合并间隔验证连续覆盖范围。 

由于该结构始终维护最大合并间隔，因此任何间隙都会自动导致查询失败。
