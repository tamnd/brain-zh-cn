 ## 解决方案

 ## 问题理解

 该问题要求我们找到小于或等于给定数字的最大整数`n`，使其数字单调递增。 

当每个数字都小于或等于其后面的数字时，数字具有单调递增数字。 例如：

-`1234`是单调增加的，因为`1 <= 2 <= 3 <= 4`-`11239`也是单调递增的，因为允许相邻数字相等
 -`332`不是单调增加，因为`3 > 2`输入是单个整数`n`， 在哪里：$0 \le n \le 10^9$这个约束告诉我们该数字最多有 10 位数字，因此输入大小非常小。 然而，我们仍然需要一种高效的算法，而不是逐一检查每个数字。 

输出应该是满足两个条件的最大数：

 1. 小于或等于`n`2.其数字是单调递增的

 关键的挑战是更改一位数字也会强制更改后面的数字。 例如：

-`332`- 发生违规的原因是`3 > 2`- 减少第二个`3`到`2`给出`322`- 但`322`仍然违反单调性，因为`3 > 2`- 正确答案是`299`这种级联效应是问题的核心难点。 

一些边缘情况很重要：

 - 数字已经单调增加，例如`1234`- 具有重复数字的数字，例如`111`- 减少一位数字会产生新的左侧违规的号码
 - 包含零的数字，例如`10`- 个位数，始终有效

 该问题保证输入是非负整数，因此我们永远不需要处理无效的输入类型或负值。 

## 方法

 ### 蛮力方法

 最直接的方法是从`n`并不断减少该数字，直到找到数字单调递增的数字。 

对于每个候选人编号：

 1.将其转换为字符串
 2. 检查每个相邻对是否满足`digit[i] <= digit[i+1]`3.如果有效，则返回
 4.否则递减并继续

 这种方法是正确的，因为我们从最大到最小检查数字，因此遇到的第一个有效数字必定是答案。 

然而，这可能非常慢。 考虑一个大输入，其中许多连续数字无效。 在最坏的情况下，我们可能会检查很大范围的值。 

例如：

-`1000000000`- 在达到有效的单调数之前，我们可能需要多次递减

 尽管输入的数字量很小，但数字范围足够大，暴力破解是不切实际的。 

### 最优贪心法

 关键的观察是，当一个数字违反单调性时，我们应该减少有问题的数字并使其右侧的所有数字尽可能大。 

假设我们有：```
332
```在这一点上`3 > 2`，我们知道第二个`3`必须减少。 如果我们将其减少到`2`，最大可能的后缀变为全部`9`s:```
329
```但现在第一个`3`大于`2`，所以我们必须重复：```
299
```这表明了一种贪婪策略：

 - 从右到左扫描数字
 - 每当一个数字大于它后面的数字时：

 - 将当前数字减1
 - 将以下所有数字设置为`9`为什么这有效？ 

因为一旦我们减少一个数字，最大化结果数字的最佳方法是使后面的每个数字尽可能大，同时保持单调性。 自从`9`是最大的数字，将后缀填充为`9`s 产生最大的有效数。 

从右到左扫描很重要，因为减少一位数字可能会与其前面的数字产生新的违规。

## 算法演练

 1. 将整数转换为数字列表。 

我们使用可变结构，因为数字在处理过程中可能需要修改。 
2. 从右向左开始扫描。 

我们将每个数字与其后面的数字进行比较。 如果当前数字大于下一个数字，则违反了单调性。 
3. 当发现违规时，将当前位数减1。 

例如：```
332
```在索引 1 处：```
3 > 2
```所以我们减少第二位数字：```
322
```4. 记录右侧数字应变为的位置`9`。 

减少一位数字后，我们希望剩余的后缀在保持有效的情况下尽可能大。 

所以：```
322 -> 299
```5. 继续向左扫描。 

减少一位数可能会造成另一次违规。 

例子：```
299
```现在第一个`3`大于`2`，所以我们必须再次减少。 
6. 扫描完成后，将记录位置后面的所有数字替换为`9`。 

这使得最终值最大化。 
7. 将数字列表转换回整数并返回。 

### 为什么它有效

 该算法保持不变性，即每当修复违规时，所得前缀就会成为小于原始数字的最大可能有效前缀。 将后缀设置为`9`s guarantees the maximum possible number under that prefix. Because we process from right to left, any cascading violations are also corrected. Therefore the final number is both monotone increasing and as large as possible.

 ## Python 解决方案```python
class Solution:
    def monotoneIncreasingDigits(self, n: int) -> int:
        digits = list(str(n))
        marker = len(digits)

        for i in range(len(digits) - 1, 0, -1):
            if digits[i - 1] > digits[i]:
                digits[i - 1] = str(int(digits[i - 1]) - 1)
                marker = i

        for i in range(marker, len(digits)):
            digits[i] = '9'

        return int("".join(digits))
```实现首先将数字转换为字符串数字列表。 这允许直接修改各个位置。 

变量`marker`存储第一个索引，其中右侧的数字最终应变为`9`。 最初，它被设置为数组的末尾，因为尚未发现违规情况。 

循环从右向左扫描。 每当一个数字大于它后面的数字时，就会违反单调性。 当前数字减一，并且更新标记。 

从右到左的方向至关重要，因为减少数字可能会与其前面的数字产生新的冲突。 

修复所有违规行为后，每个数字`marker`向前替换为`9`。 这会最大化结果数，同时确保其保持小于或等于原始输入。 

最后，将数字列表重新连接回字符串并转换为整数。 

## 解决方案```go
func monotoneIncreasingDigits(n int) int {
    digits := []byte(fmt.Sprintf("%d", n))
    marker := len(digits)

    for i := len(digits) - 1; i > 0; i-- {
        if digits[i-1] > digits[i] {
            digits[i-1]--
            marker = i
        }
    }

    for i := marker; i < len(digits); i++ {
        digits[i] = '9'
    }

    result := 0
    for _, ch := range digits {
        result = result*10 + int(ch-'0')
    }

    return result
}
```Go 实现遵循与 Python 版本相同的逻辑。 

使用字节切片是因为 Go 中的字符串是不可变的。 每个数字都以其 ASCII 字节表示形式存储，从而提高就地更新的效率。 

Go 中的自减操作特别简单，因为数字字符在 ASCII 中是连续的：```go
digits[i-1]--
```修改后，数字将手动重建为整数，而不是使用解析实用程序。 

与 Python 不同，Go 需要显式整数重构，并且不提供直接的可变字符串操作。

 ## 边缘情况

 一种重要的边缘情况是已经单调递增的数字。 例如，`1234`应保持不变。 粗心的实现可能会不必要地修改数字或错误地将尾随数字设置为`9`。 此实现避免了这种情况，因为标记仅在检测到违规时才会更改。 

另一个重要案例是连锁违规行为。 考虑`332`。 减少第二个数字会与其前面的数字产生新的违规。 从左到右的方法在这里通常会失败，因为它无法轻松地重新访问较早的数字。 从右到左扫描自然可以正确处理级联更新。 

第三个重要的边缘情况是在较大数字后面包含零的数字，例如`10`或者`1000`。 减少前导数字可能会在内部产生前导零。 例如：```
10 -> 09
```该实现可以安全地处理此问题，因为将最终字符串转换回整数会自动删除前导零。 

第四个微妙的边缘情况是违规之前重复的数字，例如`111110`。 决赛时`0`遇到这种情况时，多个较早的数字可能需要间接调整。 贪心传播过程正确地将数字转换为`99999`，这是最大的有效答案。
