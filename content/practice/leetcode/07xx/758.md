 **难度：** 🟡 中等
 **主题：** 数组、哈希表、字符串、Trie、字符串匹配

 ## 解决方案

 ## 问题理解

 这个问题给了我们两个输入：一个名为的字符串数组`words`，和一个目标字符串`s`。 每个单词的每次出现`words`里面`s`必须通过将该子字符串包围起来来变成粗体`<b>`和`</b>`标签。 

重要的要求是我们必须使用尽可能少的标签数量。 这意味着重叠或相邻的粗体区域应合并为单个粗体段，而不是创建多个嵌套或单独的标签。 

例如，如果`words = ["ab", "bc"]`和`s = "aabcd"`， 然后：

-`"ab"`出现在索引处`1`-`"bc"`出现在索引处`2`这些匹配在角色上重叠`'b'`，因此我们不是生成单独的粗体区域，而是将它们组合成一个连续的区域来覆盖`"abc"`。 

最终结果变成：```
a<b>abc</b>d
```限制相对较小：

 -`s.length <= 500`-`words.length <= 50`-`words[i].length <= 10`这些限制告诉我们，即使效率较低的字符串匹配解决方案仍然可以在时间限制内顺利工作。 我们不需要像 Aho-Corasick 或后缀自动机这样的高级算法。 精心实施的扫描解决方案就足够了。 

一些边缘情况很重要：

 - 多个单词可能会重叠。 
- 多个单词可以直接相邻，但仍应合并为一个粗体部分。 
- 有些词可能出现多次。 
- 有些词可能永远不会出现。 
-`words`可以为空。 
- 整个字符串可能会变成粗体。 
- 单字符匹配可能会产生许多需要合并的小区间。 

当正确处理重叠和邻接时，特别是在决定放置开始和结束标记的位置时，幼稚的实现通常会失败。 

## 方法

 ### 蛮力方法

 蛮力的想法是生成每个匹配的子串间隔，然后重复合并重叠的间隔。 

对于其中的每一个词`words`，我们扫描每个可能的起始位置`s`。 每当我们找到匹配项时，我们都会存储其间隔`[start, end]`。 

收集所有间隔后，我们对它们进行排序并合并重叠或相邻的间隔。 最后，我们通过在合并范围周围插入粗体标签来重建字符串。 

这种方法是正确的，因为每次出现都被明确发现并表示为一个区间。 合并间隔保证使用最少数量的粗体标签。 

然而，该方法执行了不必要的间隔管理和重复的子串检查。 虽然对于给定的约束仍然可以接受，但它不够优雅，而且比必要的稍微复杂一些。 

### 最佳方法

 关键的观察是我们实际上不需要显式存储间隔。 相反，我们只需要知道每个字符位置是否应该加粗。 

我们创建一个布尔数组`bold`在哪里：```
bold[i] = True
```意味着性格`s[i]`属于粗体区域。 

我们扫描每个位置`s`并检查是否有单词从那里开始。 每当找到匹配项时，我们都会将所有覆盖的位置标记为粗体。 

处理完所有匹配项后，构造最终字符串就变得很简单：

 - 开始一个`<b>`每当我们进入粗体区域时标记。 
- 结束于`</b>`每当我们离开一个大胆的区域时。 

这自然会合并重叠和相邻的匹配，因为连续的`True`位置形成一个连续的粗线段。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(W × N × L + K log K) | O(W × N × L + K log K) | O(K) | 存储和合并间隔 |
 | 最佳 | O(宽 × 氮 × 长) | O(N) | 使用布尔标记数组 |
 | | | | |

 在哪里：

-`N`= 的长度`s`-`W`= 字数
 -`L`= 最大字长
 -`K`= 匹配间隔的数量

 ## 算法演练

 ### 第 1 步：创建粗体标记数组

 我们创建一个名为的布尔数组`bold`长度等于`len(s)`。 

最初，每个值都是`False`因为还没有字符被标记为粗体。```
bold = [False] * len(s)
```该数组最终将准确地告诉我们哪些字符属于粗体标签。 

### 第 2 步：找到每个匹配的单词

 对于每个起始索引`i`在字符串中：

 1.检查每一个单词`words`2.判断单词是否从position开始匹配`i`3. 如果匹配，则将所有被覆盖的字符位置标记为粗体

 例如：```
s = "aabcd"
word = "ab"
```如果`"ab"`从索引开始`1`， 然后：```
bold[1] = True
bold[2] = True
```这将子字符串匹配转换为简单的位置标记。 

### 步骤 3：构建结果字符串

 现在我们逐个字符地遍历字符串。 

在每个位置：

 - 如果当前位置是粗体且前一个位置不是粗体，则插入`<b>`- 追加当前字符
 - 如果当前位置是粗体而下一个位置不是粗体，则插入`</b>`这可以确保：

 - 重叠区域成为一段
 - 相邻区域也会自然合并
 - 标签最少

 ### 步骤 4：返回最终字符串

 将所有收集到的片段连接在一起并返回最终的格式化字符串。 

### 为什么它有效

 该算法之所以有效，是因为每个匹配的子字符串都将其覆盖的所有字符标记为粗体。 处理完所有单词后，`bold`数组精确地表示所有匹配间隔的并集。 

重建字符串时，连续`True`区域精确对应于最大粗体段。 由于重叠和相邻的间隔会产生一个连续的序列`True`值时，算法会自动生成最小数量的粗体标签。 

## Python 解决方案```python
from typing import List

class Solution:
    def boldWords(self, words: List[str], s: str) -> str:
        n = len(s)
        bold = [False] * n

        # Mark bold positions
        for i in range(n):
            for word in words:
                if s.startswith(word, i):
                    for j in range(i, i + len(word)):
                        bold[j] = True

        result = []

        for i in range(n):
            # Start bold section
            if bold[i] and (i == 0 or not bold[i - 1]):
                result.append("<b>")

            result.append(s[i])

            # End bold section
            if bold[i] and (i == n - 1 or not bold[i + 1]):
                result.append("</b>")

        return "".join(result)
```实现首先分配`bold`大批。 每个位置直接对应于输入字符串中的一个字符。 

嵌套循环执行子字符串匹配。 方法`s.startswith(word, i)`检查是否`word`从索引开始`i`。 如果是这样，每个被覆盖的位置都会变成粗体。 

处理完所有匹配后，第二次遍历将重建最终答案。 打开和关闭标签的逻辑完全取决于粗体和非粗体状态之间的转换。 

输入粗体区域时会出现开始标记：```python
bold[i] and not bold[i - 1]
```离开时会出现一个结束标签：```python
bold[i] and not bold[i + 1]
```这保证了连续的粗体范围恰好接收一对标签。 

## 解决方案```go
func boldWords(words []string, s string) string {
	n := len(s)
	bold := make([]bool, n)

	// Mark bold positions
	for i := 0; i < n; i++ {
		for _, word := range words {
			wordLen := len(word)

			if i+wordLen <= n && s[i:i+wordLen] == word {
				for j := i; j < i+wordLen; j++ {
					bold[j] = true
				}
			}
		}
	}

	result := make([]byte, 0)

	for i := 0; i < n; i++ {
		// Start bold section
		if bold[i] && (i == 0 || !bold[i-1]) {
			result = append(result, []byte("<b>")...)
		}

		result = append(result, s[i])

		// End bold section
		if bold[i] && (i == n-1 || !bold[i+1]) {
			result = append(result, []byte("</b>")...)
		}
	}

	return string(result)
}
```Go 实现遵循与 Python 版本相同的总体策略。 

一个显着的区别是子字符串处理。 在 Go 中，子字符串提取使用切片：```go
s[i:i+wordLen]
```在切片之前，我们必须验证：```go
i + wordLen <= n
```以避免出界恐慌。 

为了提高效率，结果字符串是使用字节切片构建的，因为 Go 中重复的字符串连接可能会变得昂贵。

 ## 边缘情况

 当多个匹配重叠时，会出现一种重要的边缘情况。 例如：```
words = ["ab", "bc"]
s = "abc"
```字符上的间隔重叠`'b'`。 有缺陷的实现可能会创建嵌套标签，例如：```
<b>ab<b>bc</b>
```这是无效的。 布尔标记方法完全避免了这种情况，因为重叠间隔只会产生一个连续的粗体区域。 

另一个重要的情况是相邻间隔。 考虑：```
words = ["ab", "cd"]
s = "abcd"
```虽然火柴不重叠，但它们直接接触。 该问题需要最少的标签，因此正确的结果是：```
<b>abcd</b>
```而不是：```
<b>ab</b><b>cd</b>
```因为该算法合并连续的`True`值自然地，相邻区域自动成为一段。 

当根本没有单词匹配时，就会发生第三种边缘情况。 例如：```
words = ["x"]
s = "abc"
```在这种情况下，每个条目`bold`遗迹`False`，重建阶段简单地返回原始字符串不变。 不添加不必要的标签。 

最后一个微妙的情况是整个字符串变为粗体。 在这种情况下，算法会在开头正确插入一个开始标记，在末尾正确插入一个结束标记，因为第一个和最后一个位置是在边界检查中明确处理的。
