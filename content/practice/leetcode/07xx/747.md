[LeetCode 747 题](https://leetcode.com/problems/largest-number-at-least-twice-of-others/)

 **难度：** 🟢简单
 **主题：** 数组、排序

 ## 解决方案

 ## 问题理解

 问题给了我们一个整数数组`nums`其中最大值保证是唯一的。 我们的任务是确定这个最大的数字是否至少是数组中其他每个数字的两倍。 如果满足该条件，我们返回最大元素的索引。 否则，我们返回`-1`。 

简单来说，我们需要确定最大值并验证所有剩余值不大于它的一半。 由于最大值是唯一的，因此我们永远不需要担心最大元素的关系。 

输入是长度在 2 到 50 之间的整数数组。每个值都在 0 到 100 之间。这些约束非常小，这意味着即使效率较低的解决方案仍然可以在限制内舒适地运行。 然而，目标仍然是设计一个干净且最佳的解决方案。 

输出是一个整数，表示：

 - 主要元素的索引，意味着至少是其他元素两倍的最大元素
 - 或`-1`如果不存在这样的元素

 立即识别几个边缘情况非常重要。 

仅包含两个元素的数组是最小的有效输入大小，因此算法必须正确地仅比较一对。 包含零的数组也可能很棘手，因为任何正数至少是零的两倍。 当第二大数非常接近最大值时，会发生另一个重要情况。 例如，在`[1,2,3,4]`，最大值`4`不是至少两次`3`，所以答案是`-1`。 

保证最大元素是唯一的显着简化了逻辑，因为我们只需将最大值与第二大值进行比较。 如果最大值至少是第二大值的两倍，那么它也会自动至少是每个较小值的两倍。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是检查每个元素并检查它是否满足所有其他元素的条件。 

首先，我们确定最大的元素及其索引。 然后，对于数组中的每个其他数字，我们验证是否：```
largest >= 2 * current_number
```如果任何比较失败，我们立即返回`-1`。 否则，在检查所有元素后，我们返回最大数字的索引。 

这种方法是正确的，因为它显式验证了数组中每个元素所需的条件。 然而，它执行不必要的重复比较。 对于每个候选最大值，我们可能会与所有其他元素进行比较。 

尽管约束足够小，可以在实践中有效地发挥作用，但我们可以在概念上做得更好。 

### 最佳方法

 关键的观察是我们只需要比较最大元素和第二大元素。 

如果最大值至少是第二大值的两倍，那么它也必须至少是每个较小数字的两倍。 因此，我们可以在跟踪时一次性解决问题，而不是反复比较所有元素：

 - 最大数量
 - 最大数字的索引
 - 第二大数字

 遍历完成后，我们只需检查是否：```
largest >= 2 * second_largest
```这将解决方案减少为具有恒定额外空间的线性时间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 反复将最大值与其他所有元素进行比较 |
 | 最佳 | O(n) | O(1) | O(1) | 一次性跟踪最大和第二大的值 |

 ## 算法演练

 1. 初始化变量以跟踪最大值、第二最大值和最大值的索引。 

我们需要这三个信息，因为最终的决定仅取决于最大元素和第二大元素之间的关系。 
2. 遍历数组一次。 

遍历时，将每个数与当前最大值进行比较。 
3. 如果当前数字大于最大值，则更新两个跟踪变量。 

旧的最大值成为第二大值，当前数字成为新的最大值。 我们还存储它的索引。 
4. 否则，如果当前数字大于当前第二大值，则更新第二大值。 

这确保了我们始终保持迄今为止看到的两个最大数字。 
5. 处理完所有元素后，检查最大值是否至少是第二大值的两倍。 

如果：```
largest >= 2 * second_largest
```然后返回最大值的存储索引。 
6.否则返回`-1`。 

### 为什么它有效

 该算法在每次迭代后保持不变：

 -`largest`存储迄今为止看到的最大值
 -`second_largest`存储迄今为止看到的第二高值

 遍历结束时，这些值对于整个数组来说都是正确的。 由于所有其他数字都小于或等于第二大数字，因此仅针对第二大数字验证条件足以保证所有元素的条件。 

## Python 解决方案```python
from typing import List

class Solution:
    def dominantIndex(self, nums: List[int]) -> int:
        largest = -1
        second_largest = -1
        largest_index = -1

        for index, value in enumerate(nums):
            if value > largest:
                second_largest = largest
                largest = value
                largest_index = index
            elif value > second_largest:
                second_largest = value

        if largest >= 2 * second_largest:
            return largest_index

        return -1
```实现首先初始化三个跟踪变量。`largest`存储迄今为止遇到的最大值，`second_largest`存储第二高的值，并且`largest_index`记住最大值的位置。 

循环遍历数组一次使用`enumerate`，它同时提供索引和值。 

每当找到新的最大值时，先前的最大值就会成为第二大的值。 然后当前值成为新的最大值，并记录其索引。 

如果当前值不是最大但仍然大于当前第二大值，我们只更新`second_largest`。 

循环结束后，代码检查主导条件是否成立。 如果最大数字至少是第二大数字的两倍，则返回存储的索引。 否则，函数返回`-1`。 

## 解决方案```go
func dominantIndex(nums []int) int {
    largest := -1
    secondLargest := -1
    largestIndex := -1

    for index, value := range nums {
        if value > largest {
            secondLargest = largest
            largest = value
            largestIndex = index
        } else if value > secondLargest {
            secondLargest = value
        }
    }

    if largest >= 2*secondLargest {
        return largestIndex
    }

    return -1
}
```Go 实现遵循与 Python 版本相同的逻辑。 Go 使用`range`在检索索引和值的同时迭代切片。 

由于问题约束保证非负整数，因此初始化`largest`和`secondLargest`到`-1`是安全的。 

与 Python 不同，Go 不需要显式类型提示，因为变量类型是自动推断的。 整数溢出在这里不是问题，因为值最多限制为 100。

 ## 边缘情况

 当最大值正好是第二最大值的两倍时，就会出现一种重要的边缘情况。 例如，在`[2,1]`或者`[8,4,2,1]`，条件仍然应该成功，因为问题说“至少两次”，而不是“严格大于两次”。 一个常见的错误是使用`>`而不是`>=`。 该实现通过以下条件正确处理此问题：```
largest >= 2 * second_largest
```另一个重要的情况涉及包含许多零的数组。 例如，`[0,0,0,1]`应该返回索引`1`因为任何正数至少是零的两倍。 错误初始化跟踪变量或错误处理零比较的算法可能会失败。 初始化为`-1`避免了这个问题，因为所有数组值都是非负的。 

当第二最大值非常接近最大值时，会出现第三种边缘情况。 例如，`[5,3]`或者`[1,2,3,4]`应该返回`-1`。 一些不正确的实现仅将最大值与元素子集进行比较，或者无法正确跟踪第二大值。 该解决方案在整个遍历过程中明确维护正确的第二大值，确保最终验证准确。
