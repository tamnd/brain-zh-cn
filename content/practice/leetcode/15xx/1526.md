 **难度：** 🔴难
 **主题：** 数组、动态规划、堆栈、贪婪、单调堆栈

 ## 解决方案

 ## 问题理解

 该问题给了我们一个目标数组，并要求我们从全零数组开始构建它。 唯一允许的操作是选择任何连续的子数组并将该子数组中的每个元素恰好递增 1。 

目标是确定将零数组转换为目标数组所需的此类操作的最少数量。 

例如，如果目标是`[1,2,3,2,1]`，我们可以将数组视为高度的景观。 每个操作都会在某个连续区域上添加一个水平层。 挑战是使用尽可能少的层数来覆盖景观。 

输入包括：

 - 整数数组`target`- 每个值代表该位置所需的最终高度

 输出是：

 - 表示所需增量操作的最小数量的单个整数

 约束条件很重要：

 -`target.length`可以大到`100000`- 每个`target[i]`也可以大到`100000`这些限制立即排除了昂贵的二次或三次算法。 我们需要一种以线性时间或接近线性时间运行的算法。 

一个重要的观察是每个操作都会影响一个连续的段。 这意味着当高度从左到右增加时，我们需要额外的操作来创建额外的高度。 然而，当高度降低时，我们不需要删除任何东西，因为操作只会增加值。 先前创建的层可以简单地停止延伸。 

重要的边缘情况包括：

 - 只有一个元素的数组
 - 严格增加数组
 - 严格递减数组
 - 所有值都相同的平面数组
 - 大的交替上升和下降

 该问题保证：

 - 每个值都是正值
 - 答案适合 32 位整数
 - 数组非空

 这些保证简化了实现，因为我们永远不需要处理负数或空输入。 

## 方法

 ### 蛮力方法

 暴力策略会尝试模拟实际操作。 

一种可能的方法是：

 1. 查找值仍低于目标的连续范围
 2. 增加这些范围
 3. 重复直到构建的数组与目标匹配

 例如，与`[1,2,3]`：

 - 增量`[0..2]`- 增量`[1..2]`- 增量`[2..2]`这最终是可行的，但重复扫描和修改数组效率极低。 

另一种强力解释是递归地分割间隔并尝试手动构建层。 这类似于绘画问题，我们反复确定最小高度并减去图层。 

虽然这些方法在逻辑上是正确的，但对于大小的数组来说它们变得太慢`100000`。 

### 关键见解

 关键的观察是，只有当高度与之前的位置相比增加时，我们才需要新的操作。 

假设我们从左到右处理数组。 

- 如果`target[i] <= target[i-1]`，该位置不需要额外的操作`i`- 如果`target[i] > target[i-1]`，我们必须开始`target[i] - target[i-1]`新业务

 为什么？ 

因为业务可以向前延伸到相邻的区域。 先前索引中已构建的任何高度都可以免费延续到当前索引中。 只有额外的高度才需要新的操作。 

这将问题转化为一个非常简单的贪心公式：$$\text{answer} = target[0] + \sum_{i=1}^{n-1} \max(0, target[i] - target[i-1])$$这适用于线性时间和恒定的额外空间。 

尽管该问题将单调堆栈列为主题，但仅贪婪观察就足够且最优。

 ## 算法演练

 1. 初始化答案`target[0]`。 

第一个元素从零开始，所以我们需要`target[0]`运营来打造其高度。 
2.从索引开始遍历数组`1`到`n - 1`。 

在每个位置，将当前值与先前值进行比较。 
3.如果`target[i] > target[i - 1]`，将差异添加到答案中。 

这种差异代表了无法从左侧延伸的新层。 
4.如果`target[i] <= target[i - 1]`，什么也不做。 

先前位置的现有操作可以简单地停止在当前点或继续通过它。 
5. 返回累计答案。 

### 为什么它有效

 每个增量操作都会在某个连续间隔上创建一个水平层。 

从左向右移动时：

 - 任何先前创建的图层都可以继续到下一个位置
 - 因此，先前存在的高度不需要新的操作
 - 只有高于前一个位置的额外高度才需要开始新的间隔

 通过对所有正增长进行求和，我们可以准确计算出所需的最少新操作数量。 

这种贪婪策略是最优的，因为每一个额外的高度增加单位都必须来自新开始的操作。 

## Python 解决方案```python
from typing import List

class Solution:
    def minNumberOperations(self, target: List[int]) -> int:
        operations = target[0]

        for i in range(1, len(target)):
            if target[i] > target[i - 1]:
                operations += target[i] - target[i - 1]

        return operations
```实现直接遵循贪婪观察。 

我们初始化`operations`与第一个元素，因为数组从全零开始。 构建第一列正好需要那么多操作。 

接下来，我们迭代剩余的元素。 

每当当前高度超过之前的高度时，我们就会将差值添加到答案中。 这表示达到附加高度所需的新开始增量操作的数量。 

如果当前高度小于或等于，则不需要新的操作，因为现有层可以自然终止。 

该算法仅使用一次遍历数组和恒定的额外内存。 

## 解决方案```go
func minNumberOperations(target []int) int {
    operations := target[0]

    for i := 1; i < len(target); i++ {
        if target[i] > target[i-1] {
            operations += target[i] - target[i-1]
        }
    }

    return operations
}
```Go 实现密切反映了 Python 逻辑。 

Go 切片已经提供了高效的索引访问，因此不需要额外的数据结构。 

由于问题保证答案符合 32 位整数，因此使用 Go 的默认值`int`类型就足够了。 

与 Python 不同，Go 不需要对函数签名之外的切片进行显式类型导入或注释。

 ## 边缘情况

 一个重要的边缘情况是严格递增的数组，例如`[1,2,3,4,5]`。 幼稚的实现可能会错误地尝试过于积极地重用以前的操作。 事实上，每次增加都需要额外的操作。 该实现通过添加相邻元素之间的每个正差来处理这个问题。 

另一个重要的情况是严格递减的数组，例如`[5,4,3,2,1]`。 看起来每个索引都需要额外的操作，但所有必需的层都已经较早开始，并且可以简单地逐渐终止。 当当前值小于前一个值时，该算法正确地避免添加任何内容。 

第三个关键情况是大平坦高原，例如`[7,7,7,7]`。 不正确的实现可能会多次重复计算相同的高度。 贪婪解决方案可以正确处理这个问题，因为相邻值相等会产生零差，因此不会添加额外的操作。 

最后一个微妙的情况涉及交替的峰和谷，例如`[1,5,2,6,3]`。 这些模式测试算法是否正确区分可重用层和真正的新层。 通过仅考虑正增长，实现可以准确计算必要的新操作，同时尽可能重用以前的工作。
