 # LeetCode 1562 - 查找最新的 M 号组

 ## 问题理解

 这个问题给了我们一个排列数组`arr`包含来自的整数`1`到`n`， 在哪里`n`是我们正在构建的二进制字符串的大小。 最初，二进制字符串仅包含零。 在每一步中，我们恰好翻转一个位置`0`到`1`，按照指定的顺序`arr`。 

关键要求是确定**最新步骤**，其中至少存在一组连续的`1`s 的长度是 **恰好**`m`。 

一组 1 表示最大连续段`1`s。 该组无法向左或向右扩展，因为已到达字符串的边界或`0`出现。 

例如，如果二进制字符串是：```
111011
```有效的组是：```
["111", "11"]
```中间`0`将各个组分开，因此我们独立对待它们。 

挑战来自于二进制字符串随着时间的推移而演变的事实。 在每一步中，翻转一位可以合并相邻组、分割有效组的有效计数或创建全新的组。 我们不是简单地检查最终的字符串，我们必须确定**构造过程中的最新时刻**，当一组大小完全一致时`m`存在。 

输入约束很重要：

 -`n == arr.length`-`1 <= m <= n <= 10^5`-`arr`是以下数字的排列`1`到`n`自从`n`可以大到`100,000`，一个比粗略更糟糕的算法`O(n log n)`存在超时风险。 每次翻转后重复扫描整个字符串的简单模拟会太慢。 

一些边缘情况值得预先关注。 如果`m == n`，那么唯一可能的组大小`n`当所有位都变为时出现在最后`1`。 如果没有组大小`m`无论形式如何，我们都必须回归`-1`。 另一个微妙的情况发生在一组大小`m`暂时存在，但后来由于与邻近群体合并而消失。 由于我们想要**最新**步骤，因此我们必须不断更新答案，而不是在第一次出现时停止。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是逐步模拟二进制字符串。 

在每一步中，我们将指定的位置翻转到`1`，然后扫描整个二进制字符串以识别所有连续的组`1`s。 如果任何组的大小完全相同`m`，我们将答案更新为当前步骤。 

这种方法是正确的，因为它直接对问题陈述进行建模。 每次修改后，我们都会检查完整状态并检查是否存在有效的组。 

然而，性能较差。 由于有`n`步骤并且每个步骤可能需要扫描整个二进制字符串的长度`n`，总复杂度变为`O(n²)`。 

和`n = 100,000`，这大约需要`10^10`在最坏的情况下，操作速度太慢了。 

### 最佳解决方案的关键见解

 关键的观察是，翻转一点只会影响紧邻该位置的组。 

假设我们翻转位置`x`从`0`到`1`。 

只有三个部分很重要：

 - 该组结束于`x - 1`- 该组开始于`x + 1`- 翻转后形成的新合并组`x`二进制字符串中的其他所有内容都保持不变。 

我们可以使用**边界长度数组**来有效地维护连续组的长度，而不是重新扫描整个数组。 

这个想法是仅在其边界处存储每个组的大小。 如果一个组跨越`left`到`right`， 然后：```
length[left] = group_size
length[right] = group_size
```中间位置并不重要。 

当我们翻转一个新位置时：

 1. 检查相邻左组的大小。 
2. 检查相邻右侧组的大小。 
3. 将它们合并为一个更大的部分。 
4. 仅更新新边界。 
5. 记录有多少组的大小`m`目前存在。 

这避免了重新扫描二进制字符串，并允许我们在恒定时间内处理每个步骤。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 |`O(n²)`|`O(n)`| 模拟字符串并在每一步后扫描所有组 |
 | 最佳 |`O(n)`|`O(n)`| 保持边界处的段长度并跟踪大小组`m`|

 ## 算法演练

 我们使用一个名为`length`尺寸的`n + 2`。 

额外的填充可以防止访问邻居时进行越界检查。 

任何时刻：```
length[i]
```存储连续组的长度，如果`i`是一个群边界。 

我们还维护：```
count_m
```它跟踪有多少组的大小`m`目前存在。 

最后：```
result
```存储此类组存在的最新步骤。 

### 逐步算法

 1. 初始化一个`length`大小数组`n + 2`充满了零。 

零表示该位置尚未翻转到`1`。 
2.初始化：```
result = -1
count_m = 0
```3. 迭代`arr`。 

在步骤`i`， 让：```
pos = arr[i]
```4. 查找相邻组的大小。 

左邻组长度为：```
left_size = length[pos - 1]
```右邻组长度为：```
right_size = length[pos + 1]
```这些值告诉我们相邻组是否已经存在。 
5.合并前，删除旧的size组`m`。 

如果：```
left_size == m
```那么合并后该有效组就会消失。 

同样对于：```
right_size == m
```6. 计算合并后的组大小。 

新的段大小变为：```
merged_size = left_size + right_size + 1
```7. 更新边界。 

新的细分市场涵盖：```
left_boundary = pos - left_size
right_boundary = pos + right_size
```店铺：```
length[left_boundary] = merged_size
length[right_boundary] = merged_size
```8. 如果新合并的段有大小`m`, 增量`count_m`。 
9.如果`count_m > 0`， 更新：```
result = current_step
```10.处理完所有步骤后，返回`result`。 

### 为什么它有效

 该算法保持了每个连续组的不变性`1`s 在两个边界处存储其正确的大小。 

每当翻转一个新位时，只有紧邻的组可以改变。 通过仅更新那些受影响的边界，我们可以保持正确性，而无需重新扫描整个字符串。 

这`count_m`变量始终反映有多少个有效组的大小`m`目前存在。 因此，每当`count_m > 0`，我们知道当前步骤包含一个有效的组，并且存储最新的此类步骤可以保证正确的答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def findLatestStep(self, arr: List[int], m: int) -> int:
        n = len(arr)

        if m == n:
            return n

        length = [0] * (n + 2)
        count_m = 0
        result = -1

        for step, position in enumerate(arr, 1):
            left_size = length[position - 1]
            right_size = length[position + 1]

            merged_size = left_size + right_size + 1

            left_boundary = position - left_size
            right_boundary = position + right_size

            length[left_boundary] = merged_size
            length[right_boundary] = merged_size

            if left_size == m:
                count_m -= 1

            if right_size == m:
                count_m -= 1

            if merged_size == m:
                count_m += 1

            if count_m > 0:
                result = step

        return result
```实现首先处理一个有用的边缘情况：```python
if m == n:
    return n
```如果所需的组大小等于数组总长度，则在翻转每个位置后，将出现唯一可能的有效组。 

这`length`数组仅在边界处存储段大小。 在每一步中，我们都会检查新翻转位置周围的相邻组长度。 

左右段大小在恒定时间内检索：```python
left_size = length[position - 1]
right_size = length[position + 1]
```这些代表将与当前位置合并的任何相邻组。 

然后我们计算合并组的大小并确定其边界。 

关键细节正在更新`count_m`。 任意大小的相邻组`m`合并后就会消失，因此我们在创建新的合并组之前减少计数。 如果合并组本身有大小`m`，我们增加计数。 

最后，每当`count_m > 0`，我们更新`result`因为当前步骤至少包含一组有效的大小`m`。 

## 解决方案```go
func findLatestStep(arr []int, m int) int {
	n := len(arr)

	if m == n {
		return n
	}

	length := make([]int, n+2)
	countM := 0
	result := -1

	for step, position := range arr {
		leftSize := length[position-1]
		rightSize := length[position+1]

		mergedSize := leftSize + rightSize + 1

		leftBoundary := position - leftSize
		rightBoundary := position + rightSize

		length[leftBoundary] = mergedSize
		length[rightBoundary] = mergedSize

		if leftSize == m {
			countM--
		}

		if rightSize == m {
			countM--
		}

		if mergedSize == m {
			countM++
		}

		if countM > 0 {
			result = step + 1
		}
	}

	return result
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个区别是迭代期间的索引。 自从Go的`range`循环开始于`0`，我们使用以下方法存储答案：```go
step + 1
```以匹配问题的单索引步骤编号。 

这`length`切片初始化为大小`n + 2`，提供与 Python 版本完全相同的安全边界填充。 

这里不存在整数溢出问题，因为值永远不会超过`n`，这最多是`100,000`。

 ## 边缘情况

 ### 案例 1：`m == n`当目标组大小等于整个数组长度时，只有一个可能的有效时刻，即所有位置都变为时的最后一步`1`。 

如果算法仅依赖于本地合并逻辑，这种情况很容易被误处理。 实现明确检查：```
if m == n:
    return n
```这保证了正确性并避免了不必要的处理。 

### 情况2：有效组暂时存在

 一组大小`m`可能会出现并随后因合并而消失。 

例如：```
arr = [2,1]
m = 1
```第 1 步创建：```
01
```其中包含一个 size-1 组。 

第 2 步创建：```
11
```从而将其删除。 

有错误的实现可能会返回第一次出现的情况或仅检查最终配置。 我们的实施更新`result`每当`count_m > 0`，确保我们捕获**最新**有效步骤。 

### 情况 3：合并破坏多个有效组

 有时，新翻转的位会合并两个大小相同的相邻组`m`。 

例如：```
left group = size m
right group = size m
```合并后两个有效组同时消失。 

幼稚的实现可能会忘记将计数递减两次。 我们的算法正确地处理了这个问题：```
if left_size == m:
    count_m -= 1

if right_size == m:
    count_m -= 1
```这保证了`count_m`始终准确地反映当前有效组的数量。
