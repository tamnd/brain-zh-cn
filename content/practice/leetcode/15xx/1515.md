[LeetCode 问题 1515](https://leetcode.com/problems/best-position-for-a-service-centre/)

 **难度：** 🔴难
 **主题：** 数组、数学、几何、随机

 ## 解决方案

 ## 问题理解

 该问题要求我们在二维地图上找到服务中心的最佳位置，以使从中心到所有客户的总欧几里得距离最小。 我们以列表的形式给出客户的坐标`positions`，其中每个元素都是一个 2 元素列表`[x, y]`。 目标是返回距某点的欧氏距离的最小总和`[xcentre, ycentre]`到所有给定的客户位置。 

输入约束是适度的：最多 50 个客户位置，每个位置的坐标在 0 到 100 之间。这排除了极端优化的需要，但它也表明，如果不小心实施，简单的强力网格搜索可能会太慢。 该解决方案还必须提供以下精度`1e-5`，因此任何迭代近似都必须小心收敛。 

重要的边缘情况包括当所有客户都位于同一位置时（中心应与该点重合）、当客户在一个区域中形成一条线或一簇时，以及当客户广泛分布在允许的坐标空间中时。 

## 方法

 强力方法涉及在所有客户坐标的边界矩形内搜索 2D 平面上的每个可能的点。 对于每个候选点，我们将计算到所有客户的距离总和并跟踪最小值。 这保证了正确性，但复杂性太高：即使在 100x100 网格上将坐标离散到 0.01 精度，也会产生 1000 万个候选点，每个候选点乘以 50 次距离计算也是令人望而却步的。 

关键的见解是欧几里德距离之和在二维空间中形成凸函数。 凸性允许我们使用梯度下降或迭代优化技术来有效地逼近最小值。 在这个问题中，**魏斯菲尔德算法**或**模拟退火/爬山**的变体效果很好。 我们将中心初始化为所有点的平均值，并迭代地将其稍微朝减少总距离的方向移动，一旦变化小于阈值就停止。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O((范围/精度)^2 * n) | O(1) | O(1) | 枚举精细网格上所有可能的点； 太慢了|
 | 梯度下降/迭代优化| O(n * 迭代) | O(1) | O(1) | 使用凸性； 从质心开始并迭代改进 |

 ## 算法演练

 1. 通过平均所有客户坐标来计算中心的初始估计。 这给出了一个合理的起点。 
2. 定义一个步长（学习率）来控制每次迭代中中心移动的距离。 
3. 计算类似梯度的方向：对于 x 和 y 的小扰动，计算沿该方向稍微移动是否会减少总距离。 
4. 向减小距离的方向移动中心。 
5. 逐渐减小步长以细化近似值并避免超出最小值。 
6. 重复步骤 3-5，直到总距离的改进小于一个小阈值（例如 1e-6），表明收敛。 

**为什么有效**：因为欧几里德距离之和是凸的，所以任何局部最小值都是全局最小值。 迭代过程使中心在每一步都更接近最佳点，确保通过足够的迭代和衰减的步长收敛到全局最小值。 

## Python 解决方案```python
from typing import List
import math

class Solution:
    def getMinDistSum(self, positions: List[List[int]]) -> float:
        n = len(positions)
        # Start from centroid
        x = sum(p[0] for p in positions) / n
        y = sum(p[1] for p in positions) / n
        
        step = 1.0
        eps = 1e-6
        while step > eps:
            best_dx, best_dy = 0.0, 0.0
            curr_dist = sum(math.hypot(x - px, y - py) for px, py in positions)
            for dx, dy in [(step, 0), (-step, 0), (0, step), (0, -step)]:
                new_x, new_y = x + dx, y + dy
                new_dist = sum(math.hypot(new_x - px, new_y - py) for px, py in positions)
                if new_dist < curr_dist:
                    curr_dist = new_dist
                    best_dx, best_dy = dx, dy
            if best_dx == 0 and best_dy == 0:
                step /= 2
            else:
                x += best_dx
                y += best_dy
        return curr_dist
```此代码初始化所有客户位置质心的服务中心。 它迭代地探索四个基本方向的小移动，保持减少总距离的移动。 如果没有移动改善距离，则步长减半以优化搜索。 这一直持续到步长非常小，确保收敛到精确的近似值。 

## 解决方案```go
import (
    "math"
)

func getMinDistSum(positions [][]int) float64 {
    n := len(positions)
    x, y := 0.0, 0.0
    for _, p := range positions {
        x += float64(p[0])
        y += float64(p[1])
    }
    x /= float64(n)
    y /= float64(n)
    
    step := 1.0
    eps := 1e-6
    
    for step > eps {
        bestDX, bestDY := 0.0, 0.0
        currDist := 0.0
        for _, p := range positions {
            dx := x - float64(p[0])
            dy := y - float64(p[1])
            currDist += math.Hypot(dx, dy)
        }
        moves := [][2]float64{{step,0},{-step,0},{0,step},{0,-step}}
        for _, m := range moves {
            newX, newY := x+m[0], y+m[1]
            newDist := 0.0
            for _, p := range positions {
                dx := newX - float64(p[0])
                dy := newY - float64(p[1])
                newDist += math.Hypot(dx, dy)
            }
            if newDist < currDist {
                currDist = newDist
                bestDX, bestDY = m[0], m[1]
            }
        }
        if bestDX == 0 && bestDY == 0 {
            step /= 2
        } else {
            x += bestDX
            y += bestDY
        }
    }
    total := 0.0
    for _, p := range positions {
        total += math.Hypot(x-float64(p[0]), y-float64(p[1]))
    }
    return total
}
```Go 实现反映了 Python 逻辑。 Float64用于精度，切片代表客户坐标。 在浮点运算中对距离求和时要小心。 

## 工作示例

 **示例1：**`positions = [[0,1],[1,0],[1,2],[2,1]]`从质心开始：`(0+1+1+2)/4 = 1, (1+0+2+1)/4 = 1`。 到所有点的总距离正好是 4，并且没有小的移动会进一步减少它。 算法立即收敛。 

**示例2：**`positions = [[1,1],[3,3]]`质心：`(1+3)/2 = 2, (1+3)/2 = 2`。 到第一个的距离：sqrt((2-1)^2 + (2-1)^2) = sqrt(2)。 到第二个的距离：sqrt((2-3)^2 + (2-3)^2) = sqrt(2)。 总计 = 2.82843，这是最小值。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n * 迭代) | 每次迭代计算到所有 n 个点的距离； 迭代次数很小且步长呈指数衰减 |
 | 空间| O(1) | O(1) | 仅存储少数变量，与输入大小无关 |

 由于 n 较小（<=50）并且收敛通常在几百次迭代内发生，因此时间复杂度是可以接受的。
