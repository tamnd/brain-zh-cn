 # LeetCode 1512 - 好对的数量

 ## 问题理解

 问题给了我们一个整数数组`nums`并要求我们计算有多少对索引`(i, j)`满足两个条件：

 1.`nums[i] == nums[j]`2.`i < j`这样的配对被称为“好配对”。 

简单来说，我们需要计算同一个值多次出现的次数，并确定这些重复出现可以形成多少个唯一索引对。 

例如，如果一个数字出现三次，则它形成以下对：

 - 第一与第二
 - 第一与第三
 - 第二与第三

 从而产生`3`好对。 

输入数组长度最多为`100`，并且每个值也介于`1`和`100`。 这些限制非常小，这意味着即使是暴力解决方案也可以在时间限制内起作用。 然而，该问题旨在测试对使用哈希图有效计数频率的理解。 

一个重要的细节是，货币对基于指数，而不仅仅是基于值。 即使两个值相同，它们也仅在其位置不同且顺序不同时才计数`i < j`。 

预先考虑一些边缘情况很重要。 应返回具有所有唯一值的数组`0`因为不存在相等的对。 所有值都相同的数组会产生最大数量的好对。 长度数组`1`还生产`0`因为一对需要两个不同的索引。 该问题保证了有效的输入大小，因此我们不需要处理空数组。 

## 方法

 ### 暴力方法

 最直接的解决方案是检查每一个可能的索引对`(i, j)`在哪里`i < j`。 

对于每一对，我们比较`nums[i]`和`nums[j]`。 如果它们相等，我们就增加答案。 

这是有效的，因为每个可能的对都被检查一次，保证了正确性。 

然而，这种方法需要嵌套循环。 如果数组长度是`n`，那么总的比较次数大约为：$$\frac{n(n-1)}{2}$$这导致`O(n²)`时间复杂度。 

尽管约束足够小，可以通过，但我们可以使用频率计数做得更好。 

### 最优方法，哈希图频率计数

 关键的观察是，当我们再次遇到一个数字时，之前每次出现的相同数字都会与当前索引形成一个新的好对。 

假设我们从左到右处理数组。 

如果我们已经看到了这个数字`1`三次，然后下一次`1`恰好形成三个新的好对，每个较早出现的一对。 

这意味着我们不需要单独与每个早期元素进行比较。 相反，我们只需要知道到目前为止每个数字出现了多少次。 

哈希映射非常适合此目的，因为它允许恒定时间频率查找和更新。 

当我们遍历数组时：

 - 查询当前数字出现了多少次
 - 将计数添加到答案中
 - 增加存储的频率

 这会将解从二次时间转换为线性时间。

 ## 算法演练

 1. 初始化变量`good_pairs`到`0`。 

该变量存储迄今为止找到的有效对的总数。 
2. 创建一个名为的空哈希映射`frequency`。 

哈希映射存储遍历数组时每个数字已经出现的次数。 
3. 迭代中的每个数字`nums`。 

我们从左到右处理数组，以便每个先前看到的出现自动满足`i < j`。 
4. 对于当前的数字，检查它之前出现过多少次。 

如果该号码已经出现过`k`次，那么当前的事件恰好形成`k`新的好对。 
5.将此计数添加到`good_pairs`。 

这会逐渐累积所有有效对。 
6. 增加哈希图中当前数字的频率。 

这为未来的元素准备了地图。 
7.处理完整个数组后，返回`good_pairs`。 

### 为什么它有效

 该算法保持频率图始终包含当前索引之前看到的元素计数的不变量。 

处理索引处的元素时`j`，每个较早出现的相同值恰好对应于一对有效的`(i, j)`在哪里`i < j`。 

由于该算法将先前出现的次数直接添加到答案中，因此每个有效对都只计算一次，并且不会计算无效对。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def numIdenticalPairs(self, nums: List[int]) -> int:
        frequency = defaultdict(int)
        good_pairs = 0

        for num in nums:
            good_pairs += frequency[num]
            frequency[num] += 1

        return good_pairs
```实现首先创建一个名为的哈希图`frequency`。 一个`defaultdict(int)`使用时，缺失的键会自动以值开头`0`。 

变量`good_pairs`存储有效对的运行总数。 

当算法迭代每个数字时，它首先将该数字的当前频率添加到答案中。 这是有效的，因为每个较早的出现都与当前索引形成一个新的对。 

对这些对进行计数后，数字的频率会增加，以便将来的元素可以与其配对。 

遍历完成后返回最终答案。 

## 解决方案```go
func numIdenticalPairs(nums []int) int {
    frequency := make(map[int]int)
    goodPairs := 0

    for _, num := range nums {
        goodPairs += frequency[num]
        frequency[num]++
    }

    return goodPairs
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

Go 映射会自动返回缺失键的零值，因此在读取之前不需要特殊的初始化`frequency[num]`。 

由于约束很小，因此不必担心整数溢出。 标准`int`值就足够了。

 | 空间| O(n) | 哈希映射最多可以存储 n 个不同的值 |

 该算法对数组执行一次遍历。 每个哈希图查找和更新操作都需要平均恒定时间，从而提供总体线性运行时间。 

额外的空间取决于数组中存在多少个唯一数字。 在最坏的情况下，每个元素都是不同的，因此哈希映射存储`n`条目。

 ## 边缘情况

 一种重要的边缘情况是仅包含唯一元素的数组。 在这种情况下，每次频率查找都会返回零，因此不会将任何对添加到答案中。 该实现自然地处理了这个问题，因为哈希映射开始时为空，并且仅在处理每个元素后递增计数。 

另一个重要的情况是所有元素都相同。 这会产生尽可能多的好对。 例如，四个相同的数字产生六对。 该算法可以正确处理此问题，因为每个新出现的情况都会将所有先前出现的情况添加到答案中。 

第三种边缘情况是只有一个元素的数组。 由于一对需要两个不同的索引，因此答案必须为零。 该实现正确地返回零，因为循环执行一次，插入之前的频率为零，并且没有添加任何对。
