[LeetCode 1532 题](https://leetcode.com/problems/the-most-recent- Three-orders/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 此问题要求我们从数据库中检索**每个客户的最近三个订单**。 如果客户的订单少于三个，我们应该退回他们的所有订单。 

我们有两张表：

 的`Customers`表包含客户信息。 每个客户都有独特的`customer_id`以及相应的`name`。 

这`Orders`表存储客户购买的商品。 每个订单都有一个独特的`order_id`， 一个`order_date`， 这`customer_id`谁放置了它，以及`cost`。 该问题保证**每个客户每天最多有一个订单**，这简化了订购，因为每个客户没有重复的日期。 

目标是返回一个结果表，其中包含：

 -`customer_name`-`customer_id`-`order_id`-`order_date`但是，我们仅包含**每个客户最近的三个订单**。 

输出必须遵循严格的排序规则：

 1. 排序依据`customer_name`按升序排列。 
2. 如果名字相同，则排序`customer_id`按升序排列。 
3. 如果仍然平局，则排序`order_date`按降序排列。 

关键的挑战是我们不是简单地对整个表进行排序。 我们必须首先确定**每个客户组中最近的前三个订单**。 

这是一个经典的**分组前 K 问题**，我们需要对每个客户的行进行独立排名，并仅保留排名最高的行。 

一个重要的观察结果是，SQL 数据库是为这种通过**窗口函数**进行分组排名而设计的，特别是`ROW_NUMBER()`。 

一些重要的边缘情况值得尽早识别：

 - 客户的订单可能**少于三个**，在这种情况下，所有订单都必须退回。 
- 客户可能有**恰好三个订单**，在这种情况下，每个订单都会被退回。 
- 客户可能有**超过三个订单**，要求我们仅丢弃最早的订单。 
- 多个客户可以共享相同的名称，因此排序依据`customer_id`变得有必要打破联系。 
- 由于该问题保证每个客户每天一个订单，因此订购`order_date DESC`足以确定新近度。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是独立处理每个客户。 

我们可以先加入`Customers`和`Orders`表，然后对于每个客户：

 1. 检索他们的所有订单。 
2. 对这些订单进行排序`order_date`按降序排列。 
3. 保留前三个条目。 
4. 将所有结果合并在一起。 
5. 执行最终所需的排序。 

这种方法会产生正确的答案，因为它显式地计算每个客户的最近三个订单。 

然而，缺点是效率。 如果我们重复地逐个客户地扫描和排序订单，就会引入不必要的重复工作。 在大数据集中，重复过滤`Orders`表变得昂贵。 

### 最优方法，窗函数排序

 关键的见解是我们需要计算**每个客户组内的排名**。 

SQL 不是一次处理一个客户，而是通过窗口函数提供了一种自然的机制。 

我们可以通过以下方式对行进行分区`customer_id`并根据`order_date DESC`。 

使用：```
ROW_NUMBER() OVER (
    PARTITION BY customer_id
    ORDER BY order_date DESC
)
```每个客户的订单都会收到排名：

 -`1`= 最新订单
 -`2`= 第二最新的
 -`3`= 第三个最新的
 - 等等

 排名完成后，我们只需过滤其中的行`rank <= 3`。 

这避免了 SQL 之外的重复扫描和排序逻辑。 数据库引擎在内部有效地处理分区和排序。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n log n) | O(n log n) | O(n) | 手动对订单进行分组并按客户进行排序 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 使用 SQL 窗口函数对每个客户进行排名 |

 虽然这两种方法都涉及排序，但最佳解决方案利用数据库执行引擎并干净高效地表达逻辑。 

## 算法演练

 1. 加入`Customers`和`Orders`表使用`customer_id`。 

这使我们能够访问同一数据集中的客户名称和订单信息。 由于最终输出需要客户名称，因此连接是必要的。 
2. 按客户划分订单。 

我们独立对待每个客户，因为该问题要求**每个客户**的最新订单，而不是全局订单。 
3. 对每个客户组内的订单进行排序。 

使用`ROW_NUMBER()`和：

-`PARTITION BY customer_id`-`ORDER BY order_date DESC`这分配了排名`1`到最新的顺序，排名`2`到第二个最新的，依此类推。 
4. 只保留前三个订单。 

过滤指定行号小于或等于的行`3`。 

订单少于三个的客户自然保持有效，因为他们的所有行都满足条件。 
5. 应用最终排序。 

使用以下方法对最终结果进行排序：

 -`customer_name ASC`-`customer_id ASC`-`order_date DESC`### 为什么它有效

 正确性来自于以下事实：`ROW_NUMBER()`在每个客户分区内建立精确的订单排序。 由于行按日期降序排列，因此排名`1`始终对应于最新的顺序、排名`2`到第二个最新的，并排名`3`到第三个最近的。 通过过滤排名小于或等于`3`，我们保证每个客户只贡献他们的三个最新订单，同时保留订单较少的客户。 

## Python 解决方案

 LeetCode 数据库问题使用 SQL 而不是可执行的 Python。 下面是正确的 MySQL 解决方案。```python
# This problem is solved using SQL, not Python.
# Equivalent SQL query:

"""
WITH ranked_orders AS (
    SELECT
        c.name AS customer_name,
        c.customer_id,
        o.order_id,
        o.order_date,
        ROW_NUMBER() OVER (
            PARTITION BY o.customer_id
            ORDER BY o.order_date DESC
        ) AS rn
    FROM Customers c
    JOIN Orders o
        ON c.customer_id = o.customer_id
)

SELECT
    customer_name,
    customer_id,
    order_id,
    order_date
FROM ranked_orders
WHERE rn <= 3
ORDER BY
    customer_name ASC,
    customer_id ASC,
    order_date DESC;
"""
```解决方案从加入开始`Customers`和`Orders`以便每个订单都与相应的客户名称配对。 

接下来，一个名为的公共表表达式`ranked_orders`使用以下方法计算每个订单的排名`ROW_NUMBER()`。 分区可确保为每个客户独立重置排名。 日期降序排列可确保较新的订单收到较小的排名值。 

排名后，外部查询会筛选行以仅保留每个客户的前三个订单。 

最后，根据问题陈述的确切要求对结果进行排序。

 ## 边缘情况

 ### 订单少于三个的客户

 一个客户可能只有一两个订单。 幼稚的实现可能错误地要求每个客户恰好三行或引入空占位符。 排名方法可以自然地处理这个问题，因为所有行的排名都小于或等于`3`，因此每个订单都会被保留。 

### 订单超过三个的客户

 这是初级过滤的情况。 容易出现错误的实现可能会意外保留最旧的三个订单而不是最新的三个订单。 订购方式`order_date DESC`确保排名`1`始终是最新的订单，使过滤器正确。 

### 多个客户同名

 该问题明确要求排序`customer_name`， 然后`customer_id`。 如果两个客户具有相同的姓名，则仅依赖姓名字段会产生不稳定的排序。 包括`customer_id ASC`保证确定性结果。 

### 没有订单的客户

 有些客户可能存在于`Customers`但从未出现在`Orders`。 由于问题要求客户订单，因此此类客户不应出现在输出中。 使用内`JOIN`自然将他们排除在外。 

### 跟进，最新`n`订单

 该解决方案很容易推广。 而不是过滤：```
WHERE rn <= 3
```我们只需替换`3`带参数`n`：```
WHERE rn <= n
```排名机制保持不变，使得该方法可适用于任意数量的近期订单。
