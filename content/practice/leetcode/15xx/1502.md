[LeetCode 问题 1502](https://leetcode.com/problems/can-make-arithmetic-progression-from-sequence/)

 **难度：** 🟢简单
 **主题：** 数组、排序

 ## 解决方案

 ## 问题理解

 该问题要求我们确定是否可以重新排列给定数组的元素，以便它们形成算术级数。 

算术级数是每对连续元素之间的差异相同的序列。 例如，`[1, 3, 5, 7]`是一个算术级数，因为每个相邻的差值都是`2`。 相似地，`[10, 7, 4, 1]`也是一个算术级数，因为每个相邻的差值都是`-3`。 

这个问题的重要细节是**我们可以重新排列数组**。 原始顺序并不重要。 我们只需要检查是否存在满足算术级数条件的元素排序。 

输入是一个整数数组`arr`，输出是一个布尔值：

 - 返回`true`数组是否可以重新排序为等差级数。 
- 返回`false`否则。 

这些约束告诉我们一些重要的事情：

 - 数组长度介于`2`和`1000`，相对较小。 
- 值范围为`-10^6`到`10^6`，意味着负数是可能的。 
- 由于数组大小适中，`O(n log n)`排序解决方案是完全可以接受的。 

一个关键的观察是，如果一个数组可以重新排列成算术级数，那么**对数组进行排序就会揭示唯一有效的递增排列**。 一旦排序，每个相邻的差异必须相同。 即使只有一点不同，重新排列也无法修复它。 

一些边缘情况值得预先考虑。 如果公差为零，具有重复值的数组仍然可以形成算术级数，例如`[5, 5, 5]`。 负数应该自然起作用，因为在排序之前差异也可能是负数。 长度数组`2`总是形成算术级数，因为任何两个数字都定义了一个常数差。 另一个重要的情况是当值显示无序时，例如`[3, 5, 1]`，其中排序使进展变得明显。 

## 方法

 ### 蛮力方法

 暴力方法会尝试数组的所有可能的重新排列，并检查任何排序是否形成算术级数。 

对于每个排列，我们将计算前两个元素之间的差异，然后验证每个连续对是否具有相同的差异。 如果我们找到一种有效的安排，我们就会返回`true`。 否则，在检查所有排列后，我们返回`false`。 

这种方法是正确的，因为它详尽地探索了每种可能的顺序。 如果存在等差数列，则其中一种排列必须与其匹配。 

然而，这种方法非常昂贵。 大小的数组`n`有`n!`排列，增长速度极快。 即使对于中等值`n`，这在计算上变得不可行。 

### 最佳方法

 关键的见解是，如果一个序列可以形成等差数列，那么**其排序顺序也必须是等差数列**。 

为什么这是真的？ 在任何算术级数中，数字都是均匀分布的。 排序只是按升序排列它们，保持相邻项之间的恒定间隙。 因此，我们只需要：

 1. 对数组进行排序。 
2. 计算前两个元素之间的差异。 
3. 验证每个相邻对是否具有相同的差异。 

如果每个差异都匹配，则返回`true`。 否则，返回`false`。 

排序极大地降低了阶乘时间的复杂性`O(n log n)`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n! × n) | O(n! × n) | O(n) | 尝试每种排列并验证算术级数 |
 | 最佳 | O(n log n) | O(n log n) | O(1) 或 O(log n) | 对数组进行排序并检查相邻差异 |

 ## 算法演练

 ### 最优算法

 1. 将数组按升序排序。 

排序是必要的，因为任何有效的算术级数都具有自然的有序形式。 如果数组可以重新排列成级数，则其排序顺序必须具有恒定的差异。 
2. 计算预期公差。 

排序后，计算：$$difference = arr[1] - arr[0]$$这成为所有相邻元素之间的预期间距。 
3. 遍历已排序的数组。 

从索引开始`2`并比较每个相邻的差异：$$arr[i] - arr[i - 1]$$与预期相反`difference`。 
4. 返回`false`如果发生任何不匹配。 

单个不一致的间隙意味着该序列不能形成算术级数。 
5. 返回`true`完成遍历后。 

如果每个连续的差异都匹配，则排序序列是算术级数，这意味着存在某种重新排列。 

### 为什么它有效

 正确性依赖于这样一个事实：算术级数是由有序项之间的恒定差异唯一确定的。 如果可以将数组重新排列成这样的序列，则对这些元素进行排序可以保留间距，同时按升序放置它们。 因此，检查排序顺序中的相邻差异足以确定是否存在有效的级数。 

## Python 解决方案```python
from typing import List

class Solution:
    def canMakeArithmeticProgression(self, arr: List[int]) -> bool:
        arr.sort()

        common_difference = arr[1] - arr[0]

        for index in range(2, len(arr)):
            current_difference = arr[index] - arr[index - 1]

            if current_difference != common_difference:
                return False

        return True
```实现首先使用对输入数组进行排序`arr.sort()`。 这确保了数字按升序排列，从而可以轻松检查连续元素之间的间距是否一致。 

接下来，代码使用前两个元素计算预期的公差。 这个值成为以后所有比较的基准。 

循环从索引处开始`2`因为第一个差异已经成立。 对于每个位置，实现都会计算当前元素与前一个元素之间的差异。 如果差值与预期值不匹配，函数立即返回`False`。 

如果循环结束时没有发现任何不一致，则所有相邻的差异都是相同的，这意味着该序列形成一个算术级数。 然后函数返回`True`。 

## 解决方案```go
package main

import "sort"

func canMakeArithmeticProgression(arr []int) bool {
	sort.Ints(arr)

	commonDifference := arr[1] - arr[0]

	for i := 2; i < len(arr); i++ {
		currentDifference := arr[i] - arr[i-1]

		if currentDifference != commonDifference {
			return false
		}
	}

	return true
}
```Go 实现遵循与 Python 版本相同的逻辑。 该数组使用排序`sort.Ints()`，将切片排序到位。 

Go 的一个具体细节是切片是类似引用的结构，因此排序会直接修改输入切片。 这在 LeetCode 中是可以接受的，因为允许输入突变。 

整数溢出在这里不是一个问题，因为给定约束内的值之间的差异仍然适合 Go 的范围`int`类型。

 ## 边缘情况

 ### 只有两个元素的数组

 任意长度的数组`2`自动形成算术级数，因为只需要考虑一个差异。 幼稚的实现可能会使这种情况变得过于复杂，或者意外地访问越界索引。 这个实现自然地处理它，因为循环从索引处开始`2`，这意味着除了计算初始差异之外不需要进行比较。 

### 具有重复数字的数组

 重复值可能很棘手，因为如果公差为零，重复的数字只能形成算术级数。 例如，`[5,5,5]`是有效的，同时`[1,1,2]`不是。 排序后，实现只需检查所有相邻差异是否匹配，从而正确区分有效和无效的重复模式。 

### 无序输入

 输入可以按任意顺序到达，例如`[3,5,1]`。 在不重新排列的情况下检查差异的幼稚实现将错误地返回`false`。 通过首先排序，该实现保证它评估唯一有意义的有序排列，从而确保无论输入顺序如何都正确。
