[LeetCode 问题 1523](https://leetcode.com/problems/count-odd-numbers-in-an-interval-range/)

 **难度：** 🟢简单
 **主题：** 数学

 ## 解决方案

 ## 问题理解

 该问题给出两个非负整数，`low`和`high`，表示区间的包含边界。 我们需要确定这两个值之间存在多少个奇整数，包括两个端点。 

如果一个整数不能被 2 整除，则该整数是奇数。奇数的示例包括`1`,`3`,`5`， 和`7`。 偶数的例子有`0`,`2`,`4`， 和`6`。 

输入包括：

 -`low`, 区间的起始值
 -`high`, 区间的结束值

 输出应该是一个整数，表示范围内奇数的计数`[low, high]`。 

例如：

 - 如果`low = 3`和`high = 7`，区间内的数字为`3, 4, 5, 6, 7`。 奇数是`3, 5, 7`，所以答案是`3`。 
- 如果`low = 8`和`high = 10`，数字是`8, 9, 10`。 仅有的`9`是奇数，所以答案是`1`。 

约束条件很重要：

 -`0 <= low <= high <= 10^9`这告诉我们这个间隔可以非常大。 迭代该范围内每个数字的解决方案可能需要多达十亿次迭代，这对于如此简单的计数问题来说效率很低。 这些约束强烈表明我们应该在常数时间内以数学方式得出答案。 

需要考虑一些重要的边缘情况：

 - 两个数字都是偶数
 - 两个数字都是奇数
 - 一个端点是奇数，另一个端点是偶数
 - 区间恰好包含一个数字
 - 间隔开始于`0`- 附近范围非常大`10^9`正确的实现必须一致地处理所有这些情况。 

## 方法

 ### 蛮力方法

 最直接的解决方案是迭代每个整数`low`到`high`并检查每个数字是否为奇数。 

一个数是奇数，如果`number % 2 == 1`。 我们可以维护一个计数器，并在遇到奇数时递增它。 

这种方法是正确的，因为它明确检查间隔中的每个值并精确计算奇数。 然而，对于大范围来说，它的效率很低。 如果区间包含数百万或数十亿个数字，则迭代所有这些数字会变得不必要的缓慢。 

由于问题约束允许值高达`10^9`, we should avoid linear iteration.

 ### Optimal Mathematical Approach

 关键的观察是奇数和偶数交替。 

In any consecutive sequence of integers:

 - 大约一半是奇数
 - 大约一半是偶数

 我们可以直接根据区间的大小来确定答案。 

首先，计算范围内的整数总数：$$\text{count} = high - low + 1$$现在考虑两种情况：

 - 如果间隔长度是偶数，则正好有一半的数字是奇数。 
- 如果间隔长度为奇数，则奇偶校验`low`判断是否有多余的奇数。 

一个更简单的公式是：

 - 计算`(high - low) // 2`- 添加`1`如果任一端点安排保证了额外的奇数

 一个非常优雅的公式是：$$\frac{high + 1}{2} - \frac{low}{2}$$使用整数除法。 

另一种直观的方法是：

 - 总数=`high - low + 1`- 基数奇数 =`total // 2`- 如果总数为奇数且`low`奇怪，再加一个

 这给出了一个`O(1)`无需迭代的解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(最高价 - 最低价 + 1) | O(1) | O(1) | 迭代每个数字并检查奇偶性 |
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 使用奇数和偶数的数学属性 |

 ## 算法演练

 ### 最优算法

 1. 使用以下方法计算区间内的整数总数：$$total = high - low + 1$$这给出了范围的包含大小。 
2. 计算奇数的基数：$$odd\_count = total // 2$$由于奇数和偶数交替出现，因此在任何均匀大小的区间中，一半的数字是奇数。 
3. 检查间隔长度是否为奇数。 

如果`total % 2 == 1`，有一个额外的数字不能均匀配对。 
4. 如果间隔长度为奇数，则判断多余的数是否为奇数。 

由于序列交替奇偶校验，因此额外的数字具有与以下相同的奇偶校验：`low`。 

因此：

 - 如果`low`是奇数，加`1`- 否则，什么也不做
 5. 返回最终计数。 

### 为什么它有效

 奇数和偶数在连续整数中完美交替。 每对相邻的数字恰好包含一个奇数。 因此，对于偶数长度的区间，正好有一半的数字是奇数。 对于奇数长度的间隔，有一个附加数字，其奇偶性与起始值的奇偶性匹配。 这保证了公式始终产生正确的计数。 

## Python 解决方案```python
class Solution:
    def countOdds(self, low: int, high: int) -> int:
        total_numbers = high - low + 1
        odd_count = total_numbers // 2

        if total_numbers % 2 == 1 and low % 2 == 1:
            odd_count += 1

        return odd_count
```该实现首先使用计算间隔的大小`high - low + 1`。 这`+1`是必要的，因为范围是包容性的。 

接下来，代码计算`total_numbers // 2`。 这给出了所有完整奇偶对中奇数值的数量。 

如果间隔长度为奇数，则有一个数字保持未配对状态。 该额外数字的奇偶校验与`low`，因为当我们移动连续的整数时，奇偶校验会交替变化。 因此，当两个条件都成立时：

 - 间隔长度为奇数
 -`low`很奇怪

 我们在结果中添加一个额外的奇数。 

最后，该函数返回计算出的计数。 

## 解决方案```go
func countOdds(low int, high int) int {
    totalNumbers := high - low + 1
    oddCount := totalNumbers / 2

    if totalNumbers%2 == 1 && low%2 == 1 {
        oddCount++
    }

    return oddCount
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

一个小的语言差异是 Go 在除法时自动使用整数除法，所以`totalNumbers / 2`已经截断为零。 

由于问题的约束最多为`10^9`, 标准围棋`int`值是完全安全的，不存在溢出风险。

 ## 边缘情况

 ### 单元素区间

 当`low == high`，该区间恰好包含一个数字。 如果包含范围计算不正确，这很容易暴露相差一的错误。 

例如：```
low = 1, high = 1
```该实现正确处理了这个问题，因为：$$total = high - low + 1 = 1$$然后逻辑正确地检查该单个值是否为奇数。 

### 两个端点都是偶数

 两个端点均为偶数的区间可能会很棘手，因为区间长度可能仍然是奇数。 

例如：```
low = 8, high = 10
```区间长度为`3`，但只有一个数是奇数。 该实现正确地处理了这个问题，因为当间隔长度为奇数时，额外的数字与奇偶校验相匹配`low`。 自从`low`为偶数，不添加额外的奇数。 

### 非常大的范围

 约束允许值高达`10^9`，这使得暴力迭代变得不切实际。 

例如：```
low = 0, high = 1000000000
```一个简单的循环需要超过十亿次迭代。 数学解决方案完全避免了迭代，并且仅使用算术运算来计算结果，即使对于最大可能的输入也能保持高效。
