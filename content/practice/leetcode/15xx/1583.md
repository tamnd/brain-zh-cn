[LeetCode 1583 题](https://leetcode.com/problems/count-unhappy-friends/)

 **难度：** 🟡 中等
 **主题：** 数组、模拟

 ## 解决方案

 ## 问题理解

 在这个问题中，我们给出`n`朋友们，在哪里`n`总是均匀的。 每个朋友都按照偏好顺序对所有其他朋友进行排名。 某人出现在某人的偏好列表中的时间越早，该人的偏好程度就越高。 

我们还得到了最终的配对安排。 每个人都与另外一个人配对。 

目标是确定有多少朋友对其指定的合作伙伴“不满意”。 

一个朋友`x`如果有另一个朋友就会变得不高兴`u`这样：

 1.`x`更喜欢`u`超过他们目前的合作伙伴`y`2.`u`也更喜欢`x`超过`u`目前的合作伙伴`v`这个定义很重要，因为不幸本质上是相互的。 这还不够`x`去更喜欢别人。 其他人也一定更喜欢`x`over their own assigned partner.

 输入包括：

 -`n`, 好友数量
 -`preferences`， 在哪里`preferences[i]`是该朋友的有序列表`i`更喜欢
 -`pairs`，其中包含最终的配对安排

 输出是一个整数，表示不开心的朋友的数量。 

这些约束告诉我们一些重要的事情：

 -`n <= 500`，所以一个`O(n^2)`解决方案是完全可以接受的
 - 每个偏好列表都有长度`n - 1`- 偏好是独特且完整的
 - 每个人都属于一对

 这些保证显着简化了实现，因为我们永远不需要处理无效或不完整的配对。 

一些边缘情况很重要：

 - 尽可能最小的输入，`n = 2`，不快乐是不可能的
 - 每个人都不高兴的情况
 - 没有人不高兴的情况
 - 一个人比自己的伴侣更喜欢许多其他人的情况，但这些偏好都不是相互的
 - 偏好排名查找必须高效的情况，否则重复扫描会变得昂贵

 ## 方法

 ### 蛮力方法

 一个简单的解决方案是直接模拟不快乐的定义。 

对于每个人`x`：

 1.找到他们现在的伴侣`y`2. 遍历所有其他人`u`3. 检查是否`x`更喜欢`u`超过`y`4. 如果有，找到`u`的伙伴`v`5. 检查是否`u`更喜欢`x`超过`v`如果两个条件都成立，那么`x`很不高兴。 

简单的暴力解决方案的主要问题是偏好比较。 如果我们重复扫描偏好列表以确定排名顺序，则每次查找都会花费`O(n)`时间。 由于我们已经迭代了人和潜在的首选朋友，这创建了一个`O(n^3)`解决方案。 

虽然`n = 500`并不是很大，立方复杂度不必要地昂贵。 

### 最佳方法

 关键的观察结果是偏好比较非常频繁地发生。 

我们反复需要回答这样的问题：

 > 是否人`x`更喜欢`u`超过`y`？ 

我们可以预处理排名位置，而不是每次都扫描偏好列表。 

我们创建一个`rank[x][u]`表其中：

 - 较小的值意味着较高的偏好
 -`rank[x][u]`给出的位置`u`在`x`的偏好列表

 那么偏好比较就变成：```
rank[x][u] < rank[x][y]
```这是一个`O(1)`手术。 

我们还建立了一个`partner`数组，这样我们就可以立即确定每个人的指定伙伴。 

预处理后：

 - 我们迭代每个人
 - 仅检查他们比当前伴侣更喜欢的人
 - 确定偏好是否是相互的

 这将整体复杂性降低到`O(n^2)`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n3) | O(n) | 反复扫描偏好列表以进行排名检查 |
 | 最佳 | O(n²) | O(n²) | 使用预先计算的排名表进行恒定时间比较 |

 ## 算法演练

 1. 创建一个`partner`大小数组`n`。 

该数组存储每个人当前的合作伙伴。 如果`[a, b]`出现在`pairs`， 然后：

-`partner[a] = b`-`partner[b] = a`这允许恒定时间的伙伴查找。 
2. 构建排名矩阵。 

我们创造：```
rank[x][u]
```其中存储了多少人`x`喜欢一个人`u`。 

较低的值代表较强的偏好。 

例如：```
preferences[0] = [2, 1, 3]
```变成：```
rank[0][2] = 0
rank[0][1] = 1
rank[0][3] = 2
```这种预处理允许即时偏好比较。 
3. 遍历每个人`x`。 

为每个人确定其指定的合作伙伴`y`。 
4.检查每个人`x`更喜欢超过`y`。 

由于偏好是有序的，我们可以遍历`preferences[x]`从一开始直到我们到达`y`。 

之前的每一个人`y`是某人`x`比指定的合作伙伴更喜欢。 
5. 对于每个首选人员`u`，确定偏好是否是相互的。 

让：```
v = partner[u]
```如果：```
rank[u][x] < rank[u][v]
```然后`u`也更喜欢`x`超过他们现在的合作伙伴。 

在此刻，`x`很不高兴。 
6. 数数不快乐的人。 

一旦我们找到一个有效的`u`，我们增加答案并停止检查更多候选者`x`。 

### 为什么它有效

 该算法直接实现了不开心朋友的正式定义。 

对于每个人`x`，我们精确地检查了那些`x`比指定的合作伙伴更喜欢。 对于每一位这样的候选人`u`，我们验证是否`u`也更喜欢`x`超过`u`自己的伙伴。 

如果两个条件都成立，那么`x`satisfies the problem definition of unhappiness.

 由于排名矩阵正确地表示了所有偏好顺序，因此每次比较都是准确的。 由于每一个可能的合格候选人都会被检查，所以不会错过任何一个不高兴的朋友。 

## Python 解决方案```python
from typing import List

class Solution:
    def unhappyFriends(
        self,
        n: int,
        preferences: List[List[int]],
        pairs: List[List[int]]
    ) -> int:

        # partner[x] = current partner of x
        partner = [0] * n

        for x, y in pairs:
            partner[x] = y
            partner[y] = x

        # rank[x][u] = preference order of u for x
        # smaller value means higher preference
        rank = [[0] * n for _ in range(n)]

        for person in range(n):
            for position, friend in enumerate(preferences[person]):
                rank[person][friend] = position

        unhappy_count = 0

        for x in range(n):
            y = partner[x]

            # Check everyone x prefers more than y
            for u in preferences[x]:

                # Once we reach y, everyone after y is less preferred
                if u == y:
                    break

                v = partner[u]

                # u prefers x over current partner v
                if rank[u][x] < rank[u][v]:
                    unhappy_count += 1
                    break

        return unhappy_count
```实现首先构建`partner`数组，这样我们就可以立即确定任何人的指定合作伙伴。 

Next, the`rank`matrix is built. 此预处理步骤是解决方案的主要优化。 我们不是重复扫描首选项列表，而是将首选项查找转换为恒定时间数组访问。 

主循环独立处理每个人。 For a given person`x`，我们迭代他们的偏好列表，直到遇到他们当前的合作伙伴`y`。 因为偏好列表是从最偏好到最不偏好排序的，所以之前的每个人`y`是某人`x`更喜欢更多。 

对于每位候选人`u`，我们检索`u`的伙伴`v`并检查是否`u`行列`x`高于`v`。 如果这个条件为真，`x`不高兴，我们立即增加结果。 

这`break`陈述很重要，因为问题只问一个人是否不快乐，而不是问他们不快乐有多少不同的原因。 

## 解决方案```go
func unhappyFriends(n int, preferences [][]int, pairs [][]int) int {

	partner := make([]int, n)

	for _, pair := range pairs {
		x := pair[0]
		y := pair[1]

		partner[x] = y
		partner[y] = x
	}

	// rank[x][u] = preference order of u for x
	rank := make([][]int, n)

	for i := 0; i < n; i++ {
		rank[i] = make([]int, n)

		for pos, friend := range preferences[i] {
			rank[i][friend] = pos
		}
	}

	unhappyCount := 0

	for x := 0; x < n; x++ {

		y := partner[x]

		for _, u := range preferences[x] {

			// Stop once current partner is reached
			if u == y {
				break
			}

			v := partner[u]

			// u prefers x over v
			if rank[u][x] < rank[u][v] {
				unhappyCount++
				break
			}
		}
	}

	return unhappyCount
}
```Go 实现遵循与 Python 版本相同的逻辑。 使用切片而不是动态 Python 列表。 由于 Go 数组的大小是固定的，因此切片提供了必要的灵活性。 

不存在整数溢出问题，因为所有值都很小并且受以下限制`n <= 500`。 

排名矩阵使用嵌套逐行显式初始化`make`来电。

class Solution:
    def unhappyFriends(self, n: int, preferences: List[List[int]], pairs: List[List[int]]) -> int:

        partner = [0] * n

        for x, y in pairs:
            partner[x] = y
            partner[y] = x

        rank = [[0] * n for _ in range(n)]

        for person in range(n):
            for pos, friend in enumerate(preferences[person]):
                rank[person][friend] = pos

        unhappy = 0

        for x in range(n):
            y = partner[x]

            for u in preferences[x]:
                if u == y:
                    break

                v = partner[u]

                if rank[u][x] < rank[u][v]:
                    unhappy += 1
                    break

        return unhappy

 ## 边缘情况

 ### 最小输入大小

 当`n = 2`，只有一种可能的配对。 两个人都没有可供比较的替代候选人，所以不快乐是不可能的。 

有缺陷的实现可能会错误地尝试访问不存在的首选项条目或假设有可用的替代选择。 当前的实现自然地处理这个问题，因为偏好循环立即到达指定的伙伴并退出。 

### 每个人都不高兴

 每个人都有可能同时感到不快乐。 这强调了算法是否正确地独立评估每个人。 

一个常见的错误是在发现一个不开心的人后过早地停止外循环。 该实现通过仅中断当前人员的内部循环来避免这种情况。 

### 偏好排名查找

 如果不进行排名预处理，重复扫描偏好列表可能会变得低效且容易出错。 

例如，确定是否：```
u prefers x over v
```需要比较内部的相对位置`u`的偏好列表。 

排名矩阵保证了恒定的时间比较，并避免了重复列表扫描时可能出现的微妙索引错误。
