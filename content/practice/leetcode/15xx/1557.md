[LeetCode 问题 1557](https://leetcode.com/problems/minimum-number-of-vertices-to-reach-all-nodes/)

 **难度：** 🟡 中等
 **主题：** 图论

 ## 解决方案

 ## 问题理解

 问题是要求我们识别有向无环图 (DAG) 中的**最小顶点集**，以便从这些顶点中的任何一个开始，图中的所有其他节点都是可到达的。 换句话说，我们想要能够通过有向路径“覆盖”整个图的最小节点集合。 

输入由一个整数组成`n`表示标记为的顶点数`0`到`n-1`，和一个数组`edges`其中每个元素`[fromi, toi]`表示有向边`fromi`到`toi`。 输出是一个顶点列表，该列表形成可到达所有其他节点的最小集合。 

约束表明该图最多可以有`10^5`节点和最多`10^5`边缘。 这意味着任何解在时间上都必须是**线性或接近线性**，因为二次解太慢。 

重要的观察结果和边缘情况包括：

 1. 没有传入边的节点必须包含在结果中，因为没有其他节点可以到达它们。 
2. 不一定需要包含具有传入边的节点，因为它们可能可以从其他节点到达。 
3. 该图保证是 DAG，因此没有循环，简化了可达性考虑。 
4. 保证存在唯一解。 

由于输入大小较大，尝试检查每个顶点子集的可达性的简单方法将失败。 

## 方法

 强力方法将涉及考虑顶点的每个子集并执行可达性检查（通过 BFS 或 DFS）以查看是否覆盖所有节点。 虽然这是正确的，但它**慢**且不切实际`n`最多`10^5`。 

最佳解决方案的关键观察是节点**仅在没有传入边**时才需要包含在集合中。 如果一个节点至少有一个入边，则它已经可以从其他节点到达，因此它不需要成为最小集的一部分。 因此，问题就简化为**找到所有入度为0的节点**。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n * (n + m)) | O(2^n * (n + m)) | O(n + m) | 检查所有顶点子集并执行可达性检查； 不切实际|
 | 最佳 | O(n + m) | O(n) | 查找所有入度为0的节点； 边缘上的线性扫描就足够了 |

 ## 算法演练

 1.初始化一个数组或集合`has_incoming`尺寸的`n`跟踪哪些节点有传入边。 
2. 迭代边列表。 对于每条边`[fromi, toi]`， 标记`toi`通过设置有一个传入边缘`has_incoming[toi] = True`。 
3.处理完所有边后，迭代所有节点`0`到`n-1`。 收集所有节点`i`在哪里`has_incoming[i]`是`False`。 
4. 返回该集合作为结果。 这些节点没有传入边，并且是所有节点均可到达的最小集合。 

工作原理：在 DAG 中，任何具有传入边的节点都可以从其他节点到达。 没有传入边的节点是必须包含在起始集中的唯一候选节点。 通过收集所有此类节点，我们确保了保证所有节点可达性的最小集合。 

## Python 解决方案```python
from typing import List

class Solution:
    def findSmallestSetOfVertices(self, n: int, edges: List[List[int]]) -> List[int]:
        has_incoming = [False] * n
        for from_node, to_node in edges:
            has_incoming[to_node] = True
        
        result = [node for node in range(n) if not has_incoming[node]]
        return result
```Python 实现初始化一个布尔列表来标记具有传入边的节点。 然后它循环所有边并设置相应的条目。 最后，列表理解收集没有传入边的所有节点并返回它们。 

## 解决方案```go
func findSmallestSetOfVertices(n int, edges [][]int) []int {
    hasIncoming := make([]bool, n)
    for _, edge := range edges {
        from, to := edge[0], edge[1]
        hasIncoming[to] = true
    }
    
    result := []int{}
    for node := 0; node < n; node++ {
        if !hasIncoming[node] {
            result = append(result, node)
        }
    }
    return result
}
```Go 版本反映了 Python 逻辑，使用布尔切片来跟踪传入的边缘。 标准切片用于存储结果，附加没有传入边的节点。

 -`[0,1]`→`has_incoming[1] = True`-`[2,1]`→`has_incoming[1] = True`-`[3,1]`→`has_incoming[1] = True`-`[1,4]`→`has_incoming[4] = True`-`[2,4]`→`has_incoming[4] = True`3.决赛`has_incoming = [False, True, False, False, True]`4.没有入边的节点：`[0,2,3]`→ 结果`[0,2,3]`## 复杂度分析

 ## 边缘情况

 首先，只有两个节点的**最小图**确保算法正确识别没有传入边的单个源节点。 这可以防止数组索引中出现差一错误。 

其次，**线性链**测试该解决方案不会过度选择节点。 即使所有节点在技术上都可以按顺序访问，也只有第一个节点应该出现在结果中。 

第三，**多个独立根**检查算法是否正确识别没有传入边的多个节点。 它确保收集步骤处理多个源，而不是在找到一个源后停止。 这些节点中的每一个对于覆盖所有可到达的节点都是必不可少的。 该实现通过迭代来处理这些`has_incoming`数组并收集所有`False`条目。
