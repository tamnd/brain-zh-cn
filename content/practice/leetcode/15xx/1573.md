 # LeetCode 1573 - 分割字符串的多种方法

 ## 问题理解

 该问题给了我们一个二进制字符串`s`，表示字符串仅包含字符`'0'`和`'1'`。 我们必须将此字符串拆分为三个非空部分：

 -`s1`-`s2`-`s3`这三个部分必须连接回原始字符串：```
s1 + s2 + s3 = s
```目标是计算有多少种不同的方式可以放置两个分割点，以便所有三个结果子字符串包含相同数量的`'1'`人物。 

分割是通过在字符串中选择两个剪切位置来定义的。 由于所有三个子字符串都必须非空，因此不能将剪切放在最开头或最末尾。 

例如，如果：```
s = "10101"
```一种有效的分割是：```
"1|01|01"
```每个子串恰好包含一个`'1'`，所以这个分割是有效的。 

约束条件很重要：

 - 字符串长度可以大到`10^5`- 尝试每一个可能的分割对的暴力解决方案会太慢
 - 我们需要一个接近线性时间的算法

 关键的挑战是有效地计算有效的分割位置，而无需显式地重复构建子字符串。 

一些边缘情况尤其重要：

 - 该字符串可能不包含`'1'`根本没有字符
 - 总数`'1'`字符不能被 3 整除
 - 1 组之间大量的 0 可以创建多个有效的分割位置
 - 答案可能会变得非常大，所以我们必须将其模数返回`10^9 + 7`该问题保证：

 - 字符串长度至少为3
 - 每个角色都是`'0'`或者`'1'`## 方法

 ### 蛮力方法

 一种简单的方法是尝试每对可能的分割位置。 

假设字符串长度为`n`。 我们可以放置：

 - 索引后的第一个分割`i`- 索引后的第二次分割`j`在哪里：```
0 <= i < j < n - 1
```对于每对分割位置：

 1.构造三个子串
 2. 数数`'1'`每个子串中的字符
 3. 检查三个计数是否相等
 4. 如果有效则增加答案

 这是有效的，因为它显式地检查每个可能的有效分区。 

然而，复杂性变得太大：

 - 有`O(n^2)`可能的分裂对
 - 重复计数可能会产生成本`O(n)`即使前缀和将子串计数减少到`O(1)`，总复杂度仍然是`O(n^2)`，这对于`n = 10^5`。 

### 最佳方法

 关键的观察结果是，总数`'1'`字符完全决定是否可以进行有效的分割。 

让：```
totalOnes = total number of '1' characters
```如果`totalOnes`不能被3整除，那么三个部分不可能包含相同数量的1。 

如果：```
totalOnes % 3 != 0
```答案是立即`0`。 

否则，每个子字符串必须包含：```
target = totalOnes / 3
```那些。 

下一个重要的见解是我们不需要单独测试所有分割位置。 

相反，我们找到：

 - 第一组和第二组之间的边界
 - 第二组和第三组之间的边界

 这些边界之间的零创建多个有效的分割选择。 

如果有：

 -`a`第一次分裂的选择
 -`b`第二次分裂的选择

 那么有效分区的总数为：```
a * b
```这使我们能够在线性时间内解决问题。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) 或 O(n) | 尝试每一对分体位置 |
 | 最佳 | O(n) | O(n) | 使用 1 的位置来有效地计算有效的分割范围 |

 ## 算法演练

 ### 最优算法

 1. 统计总数量`'1'`字符串中的字符。 

这决定了是否可以进行均等分割。 
2. 如果 1 的总数不能被 3 整除，则返回`0`。 

由于每个子字符串必须包含相同数量的 1，因此必须能被 3 整除。 
3. 处理字符串不包含数字的特殊情况。 

如果所有字符都是`'0'`，那么每个分割都会自动满足条件，因为每个子字符串都包含零个。 

假设字符串长度为`n`。 

我们需要在其中选择两个分割位置`n - 1`可能的差距。 

路数为：$\binom{n-1}{2}=\frac{(n-1)(n-2)}{2}$4. 否则，计算：```
target = totalOnes / 3
```每个子串必须准确包含`target`那些。 
5. 记录索引，其中`'1'`出现。 

例如：```
s = "10101"
indices = [0, 2, 4]
```6. 确定分割边界。 

第一个分区必须在`target`- 第一个和下一个之前。 

选择的数量由以下之间的零决定：

 - 的`target`第一个
 - 的`(target + 1)`第一个
 7. 同样，使用以下公式计算第二次分割的选择数：

 - 的`(2 * target)`第一个
 - 的`(2 * target + 1)`第一个
 8. 将两个计数相乘。 

如果：```
firstChoices = x
secondChoices = y
```然后：```
answer = x * y
```9. 返回模数答案`10^9 + 7`。 

### 为什么它有效

 有效的分割要求每个子字符串包含完全相同数量的 1。 一旦 1 的总数可以被 3 整除，这些 1 的位置就唯一地确定了分区可能发生的位置。 

唯一的灵活性来自关键组之间的零。 放置在这些零范围内的任何分割都会保留所需的计数。 因此，有效分割的总数等于第一和第二分区边界的选择数量的乘积。 

## Python 解决方案```python
class Solution:
    def numWays(self, s: str) -> int:
        MOD = 10**9 + 7
        n = len(s)

        ones_positions = []

        for index, char in enumerate(s):
            if char == '1':
                ones_positions.append(index)

        total_ones = len(ones_positions)

        if total_ones % 3 != 0:
            return 0

        if total_ones == 0:
            return ((n - 1) * (n - 2) // 2) % MOD

        target = total_ones // 3

        first_gap = (
            ones_positions[target] -
            ones_positions[target - 1]
        )

        second_gap = (
            ones_positions[2 * target] -
            ones_positions[2 * target - 1]
        )

        return (first_gap * second_gap) % MOD
```实现首先收集每个的索引`'1'`在字符串中。 这使我们能够直接了解群体之间的界限。 

接下来，我们计算 1 的总数。 如果这个值不能被三整除，我们立即返回`0`。 

字符串仅包含零的特殊情况将单独处理。 在这种情况下，每个分割都是有效的，因此我们计算从可用间隙中选择两个分割位置的方法数量。 

对于一般情况，我们计算每个子字符串中必须出现多少个。 然后，我们确定关键边界之间的零间隙。 

价值：```python
ones_positions[target] - ones_positions[target - 1]
```表示第一次分割的有效位置数。 

相似地：```python
ones_positions[2 * target] - ones_positions[2 * target - 1]
```表示第二次分割的有效位置数。 

将这些值相乘即可得到有效分区的总数。 

## 解决方案```go
func numWays(s string) int {
    const MOD int = 1e9 + 7

    n := len(s)
    onesPositions := []int{}

    for i, ch := range s {
        if ch == '1' {
            onesPositions = append(onesPositions, i)
        }
    }

    totalOnes := len(onesPositions)

    if totalOnes%3 != 0 {
        return 0
    }

    if totalOnes == 0 {
        return ((n - 1) * (n - 2) / 2) % MOD
    }

    target := totalOnes / 3

    firstGap := onesPositions[target] - onesPositions[target-1]

    secondGap := onesPositions[2*target] - onesPositions[2*target-1]

    return (firstGap * secondGap) % MOD
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 主要区别在于语法和切片处理。 

Go 使用切片来存储 1 的位置。 整数算术在这里是安全的，因为在模数减少之前最大答案符合标准整数限制。 

与 Python 不同，Go 没有自动大整数处理，但对于常规整数运算来说，约束仍然足够小。

 ## 边缘情况

 ### 所有字符均为零

 这是最重要的特殊情况。 如果字符串不包含`'1'`字符，那么每个分割都会自动满足条件，因为所有三个子字符串都包含零。 

一个常见的错误是忘记了多个分割组合是可能的，即使所有子字符串在一次计数上都是相同的。 该实现使用组合公式正确地处理了这个问题：$\binom{n-1}{2}$### 总个数不能被三整除

 如果总数不能均匀地分为三组，则不存在有效的分割。 

幼稚的实现可能仍会尝试搜索分区，从而浪费时间或产生错误的答案。 解决方案立即返回`0`在这种情况下。 

### 之间的大零间隙

 考虑一个像这样的字符串：```
"1000010000100001"
```可能有许多有效的位置可以分割，因为 1 组之间的零可以属于任一相邻子串。 

有缺陷的实现可能只对每个边界计算一个分割位置。 正确的方法是通过测量关键指标之间的距离来计算这些零间隙内所有可能的切割。
