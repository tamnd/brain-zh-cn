[LeetCode 问题 1584](https://leetcode.com/problems/min-cost-to-connect-all-points/)

 **难度：** 🟡 中等
 **主题：** 数组、并查集、图论、最小生成树

 ## 解决方案

 ## 问题理解

 这个问题要求我们以尽可能小的总成本连接二维平面上的所有给定点。 每个点都表示为一对坐标`[x, y]`。 连接两点的成本定义为其曼哈顿距离：$$|x_i - x_j| + |y_i - y_j|$$目标是确保每个点都直接或间接连接，同时最小化总连接成本。 

该声明还指出，每对点之间必须存在一条简单路径。 该条件描述了树结构。 在图论中，一个没有循环的连通图`n - 1`边称为生成树。 由于我们想要最小的总边成本，因此这成为一个经典的最小生成树问题。 

我们可以将问题视为构建完整的加权图：

 - 每个点都是一个节点
 - 每对点都有一条边
 - 边权重是这些点之间的曼哈顿距离

 然后我们必须找到该图的最小生成树。 

约束条件很重要：

 - 最多`1000`点
 - 坐标可以很大，可以是正数，也可以是负数
 - 所有点都是不同的

 一个完整的图表`1000`点包含：$$\frac{1000 \times 999}{2} = 499500$$可能的边缘。 这虽然很大，但对于高效的 MST 算法（例如 Prim 或 Kruskal 算法）来说仍然可以管理。 

一些边缘情况很重要：

 - 单点不需要连接，所以答案是`0`- 点可能有负坐标，因此必须小心处理绝对差异
 - 多个边可以具有相同的权重
 - 如果循环管理不正确，简单的递归图遍历可能会变得低效
 - 如果不小心处理，显式生成所有边可能会消耗大量内存

 ## 方法

 ### 蛮力方法

 蛮力思想是生成所有可能的连接点的方式，然后以最小的总成本选择有效的连接结构。 

为了`n`点，边的子集数量呈指数级增长。 我们需要检查每个子集是否形成有效的生成树，然后计算其总权重。 这很快在计算上变得不可能。 

另一种不太极端的暴力方法是：

 1. 生成所有成对边
 2. 对它们进行排序
 3. 尝试边的组合，直到找到最小有效生成树

 即使这样也变得不可行，因为边缘组合的数量呈爆炸式增长。 

尽管蛮力通过穷举探索可能性来保证正确性，但它无法处理`1000`在合理的时间限制内获得积分。 

### 最佳方法

 关键的观察结果是，这正是一个最小生成树问题。 

最小生成树连接所有节点：

 - 准确使用`n - 1`边缘
 - 无循环
 - 具有最小的总边缘重量

 两种经典算法可以有效解决 MST 问题：

 - 克鲁斯卡尔算法
 - 普里姆算法

 对于这个问题，Prim 算法特别有吸引力，因为我们不需要显式存储所有边。 由于图是完整的，存储所有成对边将需要近 500,000 条边。 

相反，Prim 的算法会增量地生长树：

 - 从一点开始
 - 重复连接最近的未访问点
 - 跟踪每个点的最小已知连接成本

 这避免了显式构建完整图，同时仍然实现正确的最小成本。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |

 ## 算法演练

 我们使用 Prim 算法来构建最小生成树。 

### 第 1 步：初始化跟踪结构

 我们维护三个主要信息：

 -`visited[i]`, 是否点`i`已经添加到MST中
 -`min_distance[i]`，已知最便宜的连接点成本`i`-`total_cost`，运行 MST 成本

 最初：

 - 从点开始`0`- 将其连接成本设置为`0`- 将所有其他点的成本设置为无穷大

 这意味着点`0`被选为起始节点。 

### 步骤2：反复选择最便宜的未访问过的点

 在每次迭代时：

 1. 寻找连接成本最小的未访问点
 2.添加到MST中
 3. 将其成本添加到`total_cost`这个贪心步骤是Prim算法的核心。 

所选点保证是当前树的最便宜的有效扩展。 

### 步骤 3：更新相邻连接成本

 将新点添加到 MST 后：

 1. 计算到每个未访问点的曼哈顿距离
 2. 如果这个新距离小于当前已知的最小成本，则更新它

 此步骤持续保持与正在生长的树的尽可能最便宜的连接。 

### 步骤 4：继续，直到所有点都连接起来

 我们准确地重复这个过程`n`次。 

访问完所有点后：

 - 每个点都属于MST
 - 正是如此`n - 1`连接被有效选择
 - 总成本最小化

 ### 为什么它有效

 Prim 算法之所以有效，是因为最小生成树的割性质。 

在每一步中，算法都会选择将当前树连接到未访问节点的最小权重边。 这种贪婪的选择总是安全的，因为任何 MST 都必须包含穿过这种切割的最便宜的边。 

通过重复应用该规则，算法构造出全局最优的最小生成树。 

## Python 解决方案```python
from typing import List

class Solution:
    def minCostConnectPoints(self, points: List[List[int]]) -> int:
        n = len(points)

        if n == 1:
            return 0

        visited = [False] * n
        min_distance = [float("inf")] * n

        min_distance[0] = 0
        total_cost = 0

        for _ in range(n):
            current = -1

            for i in range(n):
                if not visited[i]:
                    if current == -1 or min_distance[i] < min_distance[current]:
                        current = i

            visited[current] = True
            total_cost += min_distance[current]

            x1, y1 = points[current]

            for neighbor in range(n):
                if not visited[neighbor]:
                    x2, y2 = points[neighbor]

                    distance = abs(x1 - x2) + abs(y1 - y2)

                    if distance < min_distance[neighbor]:
                        min_distance[neighbor] = distance

        return total_cost
```其实现直接遵循 Prim 算法。 

这`visited`数组跟踪哪些点已经是 MST 的一部分。 这可以防止循环并确保每个点仅添加一次。 

这`min_distance`数组存储每个点的最小已知连接成本。 最初，除了起点之外，所有值都是无穷大，起点具有成本`0`。 

在外循环内部，我们搜索连接成本最小的未访问点。 该点成为下一个 MST 节点。 

选择该点后，我们计算从该点到每个剩余未访问点的曼哈顿距离。 如果新发现的连接比之前已知的成本便宜，我们会更新`min_distance`。 

在该过程结束时，`total_cost`包含最小生成树的权重。 

## 解决方案```go
package main

import "math"

func minCostConnectPoints(points [][]int) int {
	n := len(points)

	if n == 1 {
		return 0
	}

	visited := make([]bool, n)
	minDistance := make([]int, n)

	for i := 0; i < n; i++ {
		minDistance[i] = math.MaxInt32
	}

	minDistance[0] = 0
	totalCost := 0

	for i := 0; i < n; i++ {
		current := -1

		for j := 0; j < n; j++ {
			if !visited[j] {
				if current == -1 || minDistance[j] < minDistance[current] {
					current = j
				}
			}
		}

		visited[current] = true
		totalCost += minDistance[current]

		x1, y1 := points[current][0], points[current][1]

		for neighbor := 0; neighbor < n; neighbor++ {
			if !visited[neighbor] {
				x2, y2 := points[neighbor][0], points[neighbor][1]

				distance := abs(x1-x2) + abs(y1-y2)

				if distance < minDistance[neighbor] {
					minDistance[neighbor] = distance
				}
			}
		}
	}

	return totalCost
}

func abs(x int) int {
	if x < 0 {
		return -x
	}
	return x
}
```Go 的实现与 Python 解决方案非常相似。 

Go 没有提供内置的整数绝对值函数，因此我们定义了一个助手`abs`功能。 

使用切片而不是 Python 列表。 这`math.MaxInt32`常量将距离初始化为一个非常大的值。 

由于 Go 整数对于给定的约束来说足够大，因此整数溢出在这里不是问题。

 ## 边缘情况

 ### 单点

 如果输入仅包含一个点，则不需要边，因为图已连接。 

如果算法假设至少存在一条边，这种情况很容易引起问题。 该实现通过立即返回来处理这个问题`0`什么时候`n == 1`。 

### 负坐标

 坐标可能为负数，因此曼哈顿距离计算必须正确使用绝对值。 

不正确的实现可能会意外地直接减去坐标而不应用`abs`，产生无效的负距离。 两种解决方案都明确计算：$$|x_1 - x_2| + |y_1 - y_2|$$无论坐标符号如何，都可以保证正确性。 

### 大坐标值

 坐标可能大到`10^6`。 

这意味着曼哈顿的距离可能会变得相当大。 使用小整数类型的实现可能会溢出。 Python 整数根据需要自动扩展，而 Go 的标准`int`type 在 LeetCode 平台上安全地处理这些值。 

### 密集完整图

 每个点都可以连接到其他每个点，从而为最大输入大小生成近 500,000 条边。 

存储所有边的朴素邻接列表会消耗不必要的内存。 所选的 Prim 算法实现按需计算距离，而不是存储整个图，从而保持空间复杂度呈线性。
