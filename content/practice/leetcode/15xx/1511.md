[LeetCode 问题 1511](https://leetcode.com/problems/customer-order-Frequency/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 此问题要求我们识别在 2020 年 6 月和 7 月连续两个月内持续支出至少 100 美元的客户。我们有三个表：`Customers`，其中列出了客户详细信息；`Product`，其中列出了产品及其价格； 和`Orders`，记录客户的所有购买情况以及数量和日期。 

输入代表交易数据，输出应该是一个列表`customer_id`和`name`对于所有符合标准的客户。 重要的是，该问题仅涉及 2020 年 6 月和 7 月的订单。客户在这两个月中的累计支出必须达到至少 100 美元。 在一个月内消费足够而另一个月消费不足的客户不应包括在内。 

边缘情况包括在某一个月内没有下任何订单的客户、恰好花费了钱的客户$100, and customers who had multiple orders across the months that sum to just above or below $100. 输入被假定为中等大小，因为它涉及 SQL 数据库表，并且没有给出对订单或产品数量的明确约束。 

## 方法

 暴力方法需要分别计算每个客户每个月的总支出，然后检查两个总支出是否达到 100 美元的阈值。 这可以使用多个子查询或通过加入`Orders`和`Product`表并每月汇总。 虽然正确，但这种方法可能很冗长且效率较低，因为它需要重复扫描订单。 

最佳方法利用 SQL 聚合和条件过滤。 通过加入`Orders`和`Product`计算每个订单的支出（`quantity * price`) 并分组`customer_id`和月份，我们可以直接筛选每个月达到阈值的客户。 最后，计算符合条件的月份可确保仅返回在这两个月份都满足要求的客户。 这种方法减少了不必要的扫描并避免了多个子查询。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 分别汇总每月订单，然后合并结果 |
 | 最佳 | O(n) | O(n) | 具有条件过滤和 HAVING 子句的单一聚合 |

 ## 算法演练

 1. 加入`Orders`表与`Product`桌上`product_id`将每个订单的支出计算为`quantity * price`。 这使我们能够直接计算每个订单的总支出。 
2. 过滤订单，仅包含符合以下条件的订单：`order_date`2020年6月或7月。我们只关心这两个月。 
3. 对结果进行分组`customer_id`以及订单月份。 对于每个组，计算支出总和。 
4. 使用`HAVING`条款仅保留总支出至少为 100 美元的月份组。 这确保我们只考虑每个客户的合格月份。 
5. 对于每个客户，计算符合条件的月份数。 仅保留计数等于 2 的客户，这意味着客户在 6 月和 7 月都达到了 100 美元的门槛。 
6. 将生成的客户 ID 与`Customers`表来检索客户名称。 
7. 返回最终结果集`customer_id`和`name`。 

工作原理：通过对每个客户每月的订单进行分组并根据总支出进行筛选，该算法可保证仅选择在这两个月内满足每月支出阈值的客户。 计算符合条件的月份可确保不会错过任何月份。 

## Python 解决方案```python
# This is a SQL problem; the Python solution is represented as an executable SQL query.

sql = """
SELECT c.customer_id, c.name
FROM Customers c
JOIN (
    SELECT customer_id
    FROM Orders o
    JOIN Product p ON o.product_id = p.product_id
    WHERE o.order_date BETWEEN '2020-06-01' AND '2020-07-31'
    GROUP BY customer_id, MONTH(o.order_date)
    HAVING SUM(o.quantity * p.price) >= 100
) AS qualified_orders
ON c.customer_id = qualified_orders.customer_id
GROUP BY c.customer_id, c.name
HAVING COUNT(DISTINCT MONTH(qualified_orders.order_date)) = 2;
"""
```说明：查询首先连接`Orders`和`Product`计算每个订单的支出。 过滤到 2020 年 6 月和 7 月可确保忽略不相关的订单。 聚合依据`customer_id`月份允许对每个客户每月的支出进行求和。 这`HAVING SUM(...) >= 100`只保留那些有足够支出的月份。 最后，计算不同的月份并仅保留这两个月份都满足阈值的客户即可得到所需的结果。 

## 解决方案```go
// As this is a SQL problem, the Go solution executes SQL queries using a database connection
package main

import (
    "database/sql"
    _ "github.com/go-sql-driver/mysql"
    "fmt"
)

func CustomerOrderFrequency(db *sql.DB) {
    query := `
    SELECT c.customer_id, c.name
    FROM Customers c
    JOIN (
        SELECT customer_id, MONTH(order_date) AS order_month
        FROM Orders o
        JOIN Product p ON o.product_id = p.product_id
        WHERE o.order_date BETWEEN '2020-06-01' AND '2020-07-31'
        GROUP BY customer_id, MONTH(o.order_date)
        HAVING SUM(o.quantity * p.price) >= 100
    ) AS qualified_orders
    ON c.customer_id = qualified_orders.customer_id
    GROUP BY c.customer_id, c.name
    HAVING COUNT(DISTINCT qualified_orders.order_month) = 2;
    `
    rows, err := db.Query(query)
    if err != nil {
        panic(err)
    }
    defer rows.Close()

    for rows.Next() {
        var id int
        var name string
        rows.Scan(&id, &name)
        fmt.Println(id, name)
    }
}
```Go特定注释：查询执行使用标准`database/sql`包裹。`rows.Scan`检索`customer_id`和`name`为每一位合格的客户。 不需要额外的 Go 数据结构，因为查询处理所有聚合和过滤。

 | 测量 | 复杂性 | 说明|
