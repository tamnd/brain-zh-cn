 # LeetCode 1577，数字的平方等于两个数字的乘积的方法数

 ## 问题理解

 该问题给了我们两个整数数组，`nums1`和`nums2`。 我们必须计算满足两个数学关系之一的有效三元组的数量。 

在以下情况下存在类型 1 三元组：

 - 我们从中选择一个元素`nums1`- 我们从中选择两个不同的元素`nums2`- 从中选择的元素的平方`nums1`等于从中选择的两个元素的乘积`nums2`正式：$$nums1[i]^2 = nums2[j] \times nums2[k]$$在哪里：$$0 \le i < nums1.length$$

$$0 \le j < k < nums2.length$$2 型三元组是对称的：

 - 我们从中选择一个元素`nums2`- 我们从中选择两个不同的元素`nums1`- 从中选择的元素的平方`nums2`等于从中选择的两个元素的乘积`nums1`正式：$$nums2[i]^2 = nums1[j] \times nums1[k]$$最终答案是有效类型 1 和类型 2 三元组的总数。 

约束条件很重要：

 - 每个数组最多可以包含 1000 个元素
 - 值可以大到$10^5$由于数组相对较小，$O(n^2)$解决方案是可以接受的。 然而，朴素的三次解变得太慢，因为检查每个可能的三元组将需要大约$10^9$最坏情况下的操作。 

一些边缘情况很重要：

 - 数组可能包含许多重复值
 - 多对可以生产相同的产品
 - 值的平方会产生很大的数字，因此在 Go 等语言中必须考虑整数溢出
 - 每个值都可能相同，这会创建许多有效的组合
 - 某些数组可能会产生零个有效三元组

 关键的挑战是有效地计算乘积等于目标平方值的对。 

## 方法

 ### 蛮力方法

 最直接的解决方案是显式生成每个可能的三元组。 

对于中的每个元素`nums1`，我们计算它的平方。 然后我们迭代每一对`nums2`并检查他们的乘积是否等于平方。 之后，我们以相反的方向对 2 型三元组重复相同的过程。 

这种方法是正确的，因为它详尽地检查了问题陈述定义的每个有效组合。 

然而，复杂性太大。 

如果两个数组都有长度$n$，那么：

 - 对于一个数组中的每个元素，我们检查另一个数组中的每一对
 - 有$O(n^2)$对
 - 对所有元素重复此操作给出$O(n^3)$和$n = 1000$，这变得不切实际。 

### 最佳方法

 重要的观察是，我们不需要为每个目标方块重复重新计算配对积。 

相反，对于固定目标值：$$target = x^2$$我们可以有效地计算另一个数组中有多少对相乘`target`。 

我们使用哈希映射来存储扫描数组时先前看到的数字的频率。 

对于每个当前值`num`：

- 如果`target % num == 0`，那么互补值必须是：$$complement = target / num$$- 如果我们已经看到了`complement`，那么它的每次出现都与当前数字形成有效对

 这将配对计数转换为$O(n)$每个目标值的过程。 

由于我们对两个数组中的每个元素都重复此操作，因此总复杂度变为$O(n^2)$，这对于约束来说足够有效。

 ## 算法演练

 ### 第 1 步：定义辅助函数

 我们创建一个辅助函数：

 - 将一个数组作为平方值的来源
 - 将另一个数组作为配对产品的来源
 - 计算它们之间所有有效的三元组

 这避免了重复的逻辑。 

### 步骤 2：迭代第一个数组中的每个值

 对于每个值`value`在第一个数组中：$$target = value \times value$$该目标是我们需要使用第二个数组中的对来查找的产品。 

### 步骤 3：使用频率哈希图

 我们从左到右扫描第二个数组。 

哈希映射存储每个数字已经出现的次数。 

例子：```
frequency[num] += 1
```这使我们能够立即确定存在多少有效补集。 

### 第四步：检查当前数字是否可以组成有效的对

 对于每个数字`num`在第二个数组中：

 - 如果`target % num != 0`，则不存在整数补数
 - 否则：$$complement = target // num$$如果`complement`已经出现在频率图中，则每次出现都形成有效对。 

我们添加：```
count += frequency[complement]
```### 步骤 5：更新频率图

 检查补码后，我们将当前数字记录在哈希映射中。 

这种排序确保我们只计算对一次并维护：$$j < k$$### 步骤 6：计算两种三元组类型

 我们计算：

 - 类型 1 三元组，通过对元素进行平方`nums1`- 通过对元素进行平方来输入 2 三元组`nums2`最终答案是两个计数的总和。 

### 为什么它有效

 对于每个平方目标值，算法会系统地计算乘积等于该目标的所有对。 

频率图保证：

 - 每个有效对只计算一次
 - 正确处理重复值
 - 配对排序满足所需的索引约束

 由于每个可能的有效对都是通过补码匹配来检查的，因此该算法会计算所有有效的三元组，而不会遗漏或重复。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def numTriplets(self, nums1: List[int], nums2: List[int]) -> int:
        
        def count_triplets(source: List[int], target_array: List[int]) -> int:
            total = 0

            for value in source:
                target = value * value
                frequency = defaultdict(int)

                for num in target_array:
                    if target % num == 0:
                        complement = target // num
                        total += frequency[complement]

                    frequency[num] += 1

            return total

        return count_triplets(nums1, nums2) + count_triplets(nums2, nums1)
```实现直接遵循算法。 

辅助函数`count_triplets`处理一个计数方向。 它接收：

 -`source`，其元素为平方
 -`target_array`，我们在其中搜索配对产品

 对于每一个值`source`，我们计算目标平方。 

一个`defaultdict(int)`存储扫描时已经遇到的数字的频率`target_array`。 

对于每个当前数字：

 - 我们检查它是否均匀地划分了目标
 - 如果是，我们计算补集
 - 每个以前见过的补集都会贡献有效的对

 检查后更新频率图，以便对仅计数一次。 

最后，我们调用助手两次来计算类型 1 和类型 2 三元组。 

## 解决方案```go
package main

func numTriplets(nums1 []int, nums2 []int) int {

	countTriplets := func(source []int, targetArray []int) int {
		total := 0

		for _, value := range source {
			target := int64(value) * int64(value)

			frequency := make(map[int64]int)

			for _, num := range targetArray {
				current := int64(num)

				if target%current == 0 {
					complement := target / current

					if count, exists := frequency[complement]; exists {
						total += count
					}
				}

				frequency[current]++
			}
		}

		return total
	}

	return countTriplets(nums1, nums2) + countTriplets(nums2, nums1)
}
```Go 实现在结构上与 Python 解决方案相同。 

最重要的 Go 特定细节是整数溢出处理。 由于值可以大到$10^5$，平方产生的值高达$10^{10}$，超出 32 位整数范围。 

为避免溢出：```go
target := int64(value) * int64(value)
```所有与产品相关的计算都使用`int64`。 

哈希映射使用：```go
map[int64]int
```确保补码查找期间数字类型的一致性。 

Go 切片自然地处理空数组，尽管问题约束保证数组至少包含一个元素。

 ## 边缘情况

 ### 具有许多重复值的数组

 重复值是计数错误的最常见来源。 例如：```
nums1 = [1,1]
nums2 = [1,1,1]
```幼稚的实现可能会意外地少算或多算重复的组合。 

频率图自然地处理重复项，因为它存储每个补码已经出现的次数。 每个事件的出现都会单独影响总计数。 

### 非常大的数字

 值可以大到：$$10^5$$平方产生：$$10^{10}$$这超出了 32 位整数范围。 

Go 实现明确使用`int64`对于所有涉及平方值的乘法和除法。 这保证了正确性而不会溢出。 

Python 整数自动扩展为任意精度，因此不需要特殊处理。 

### 数组太小而无法成对

 如果一个数组只有一个元素，则不能由它形成任何对。 

例子：```
nums1 = [2]
nums2 = [3]
```由于有效的三元组需要乘积对有两个不同的索引，因此答案必须为零。 

该算法自然会处理这个问题，因为频率图永远不会积累足够的值来创建有效的对。
