 ## 解决方案

 ## 问题理解

 该问题给了我们一个方阵`mat`尺寸的`n x n`。 方阵意味着行数和列数相同。 我们必须计算属于两条对角线之一的所有元素的总和。 

主对角线包含行索引和列索引相等的元素：```
mat[i][i]
```例如，在一个`3 x 3`矩阵，主对角线位置为：```
(0,0), (1,1), (2,2)
```次对角线包含行索引和列索引总计为的元素`n - 1`：```
mat[i][n - 1 - i]
```对于一个`3 x 3`矩阵，次对角线位置为：```
(0,2), (1,1), (2,0)
```重要的细节是，如果一个元素属于两条对角线，则它只能被计算一次。 这种情况仅发生在奇数维度的矩阵中，其中中心元素位于两条对角线上。 

输入是表示矩阵的二维整数数组。 输出是一个表示总对角线和的整数。 

限制相对较小：```
1 <= n <= 100
1 <= mat[i][j] <= 100
```由于矩阵大小最多为`100 x 100`，甚至一个`O(n²)`解决方案足够快。 然而，对角线的结构允许我们通过直接遍历做得更好。 

一些边缘情况很重要：

 - A`1 x 1`矩阵仅包含一个元素，该元素属于两条对角线。 只能计算一次。 
- 奇数大小的矩阵具有共享的中心元素。 
- 偶数大小的矩阵没有重叠的对角线。 
- 幼稚的实现可能会意外地重复计算中心元素。 

## 方法

 ### 蛮力方法

 一种简单的方法是迭代矩阵中的每个元素并确定它是否属于任一对角线。 

对于每个职位`(i, j)`：

 - 它属于主对角线如果`i == j`- 它属于次对角线如果`i + j == n - 1`如果任一条件为真，我们会将值添加到答案中。 

这种方法是正确的，因为每个矩阵元素都被检查一次，并且我们只包含位于一条或两条对角线上的值。 

时间复杂度为`O(n²)`因为我们扫描整个矩阵。 虽然这对于给定的约束是可以接受的，但这是不必要的，因为只有`2n`职位是相关的。 

### 最佳方法

 关键的观察是我们永远不需要检查整个矩阵。 对角线位置可以直接计算。 

对于每一行`i`：

 - 主对角线元素是`mat[i][i]`- 次对角线元素是`mat[i][n - 1 - i]`我们可以在所有行的单个循环中添加这两个值。 

然而，对于奇数大小的矩阵，中心元素出现在两条对角线上。 为了避免重复计算，我们在循环后减去一次中心元素。 

这将遍历减少到仅`n`迭代。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 扫描每个矩阵单元并检查对角线条件 |
 | 最佳 | O(n) | O(1) | O(1) | 仅直接访问对角线元素 |

 ## 算法演练

 1. 初始化变量`total_sum`到`0`。 

该变量存储所有对角元素的运行总计。 
2.确定矩阵大小`n`。 

由于矩阵是方阵，`n = len(mat)`给出行数和列数。 
3. 迭代每行索引`i`从`0`到`n - 1`。 

在每次迭代期间：

 - 添加主对角线值：```
mat[i][i]
```- 添加次对角线值：```
mat[i][n - 1 - i]
```4. 检查矩阵大小是否为奇数。 

如果`n`是奇数，则中心元素属于两条对角线，并且被计数了两次。 
5. 减去中心元素一次。 

中心索引为：```
n // 2
```所以我们减去：```
mat[n // 2][n // 2]
```6. 返回`total_sum`。 

### 为什么它有效

 对于每一行`i`，正好有一个主对角线元素和一个次对角线元素。 该算法直接访问所有这些位置，因此包括每个对角线元素。 

在奇数大小的矩阵中，中心元素同时满足两个对角线条件。 由于该算法独立地添加两条对角线，因此中心被计算两次。 减去一次即可恢复正确的总数。 

因此，该算法总是产生正确的对角线和。 

## Python 解决方案```python
from typing import List

class Solution:
    def diagonalSum(self, mat: List[List[int]]) -> int:
        n = len(mat)
        total_sum = 0

        for i in range(n):
            total_sum += mat[i][i]
            total_sum += mat[i][n - 1 - i]

        if n % 2 == 1:
            center = n // 2
            total_sum -= mat[center][center]

        return total_sum
```实现首先确定矩阵大小`n`。 一个名为`total_sum`存储运行答案。 

循环遍历每个行索引`i`。 在每次迭代期间，代码直接访问两个对角线位置：```python
mat[i][i]
```和```python
mat[i][n - 1 - i]
```这避免了扫描不必要的细胞。 

循环之后，实现检查是否`n`很奇怪。 如果是，则中心元素被添加两次，因为两个对角线公式都指向同一位置。 代码减去该值一次以纠正结果。 

最后，该方法返回计算出的总和。 

## 解决方案```go
func diagonalSum(mat [][]int) int {
    n := len(mat)
    totalSum := 0

    for i := 0; i < n; i++ {
        totalSum += mat[i][i]
        totalSum += mat[i][n-1-i]
    }

    if n%2 == 1 {
        center := n / 2
        totalSum -= mat[center][center]
    }

    return totalSum
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 切片用于表示矩阵，索引的工作原理类似。 

不存在整数溢出问题，因为最大可能的总和非常小：```go
2 * 100 * 100 = 20000
```很容易适合 Go 的`int`类型。 

Go 不需要显式处理空矩阵，因为约束保证`n >= 1`。

 ## 边缘情况

 一个重要的边缘情况是大小矩阵`1 x 1`。 在这种情况下，唯一的元素同时属于两条对角线。 粗心的实现可能会添加两次并返回错误的结果。 该解决方案可以正确处理这种情况，因为当矩阵大小为奇数时，它会减去一次中心元素。 

另一个重要的边缘情况是奇数大小的矩阵，例如`3 x 3`或者`5 x 5`。 这些矩阵始终包含两个对角线共享的中心元素。 如果不进行特殊处理，该中心将被重复计算。 该实现显式检查是否`n`是奇数并删除重复的贡献。 

偶数大小的矩阵也很重要，因为它们不包含重叠的对角线。 不正确的实现可能总是减去中心值，而不管奇偶校验如何。 该解决方案通过仅减去当`n % 2 == 1`。 

最后的边缘情况涉及非对角值较大或分散注意力的矩阵。 条件不正确的强力实现可能会意外地包含非对角线元素。 这种实现完全避免了这种风险，因为它直接计算对角线索引而不是检查每个矩阵位置。
