[LeetCode 问题 1506](https://leetcode.com/problems/find-root-of-n-ary-tree/)

 **难度：** 🟡 中等
 **主题：** 哈希表、位操作、树、深度优先搜索

 ## 解决方案

 ## 问题理解

 该问题以任意顺序给出 N 叉树的每个节点，并要求我们确定哪个节点是树的根。 

N 叉树是每个节点可以有零个或多个子节点的树。 每个节点都包含一个唯一的整数值和一个子节点列表。 重要的细节是，输入并不是以从根开始的传统树结构形式给出的。 相反，我们只收到一个包含随机顺序的所有节点对象的数组。 

任务是识别并返回作为根的一个节点。 

树本身的结构已经通过`children`参考。 唯一缺少的信息是哪个节点应被视为树的入口点。 

约束条件很重要：

 - 最多可以有`5 * 10^4`节点。 
- 每个节点值都是唯一的。 
- 输入始终形​​成有效的树。 

这些约束立即排除了低效的重复遍历。 对于大输入来说，二次解可能会变得太慢。 

树的关键属性有助于简化问题：

 - 除根之外的每个节点都作为另一个节点的子节点仅出现一次。 
- 根永远不会以任何人的孩子的身份出现。 

该观察结果是最佳解决方案的基础。 

一些边缘情况很重要：

 - 一棵只包含一个节点的树。 在这种情况下，该节点既是根节点又是唯一节点。 
- 节点以完全随机的顺序到达。 我们不能假设第一个节点是根。 
- 深或宽的树木。 无论形状如何，算法都必须有效。 
- 具有空子列表的节点。 叶节点仍应被正确处理。 

该问题保证了节点值的唯一性和树的有效性，因此我们不需要处理格式错误的输入或重复的值。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是检查每个节点并确定它是否曾经作为另一个节点的子节点出现。 

我们可以遍历数组中的所有节点。 对于每个候选节点，我们扫描每个其他节点的子节点列表以查看候选节点是否显示为子节点。 如果它从未作为子项出现，那么它一定是根。 

这是可行的，因为在一棵树中，每个非根节点只有一个父节点。 因此，每个非根节点都出现在另一个节点内部的某个位置`children`列表。 

蛮力算法是正确的，但效率低下。 假设有`n`节点，每个节点可能包含许多子节点。 重复扫描整个结构以查找每个候选者可能会导致二次时间复杂度。 

高达`50,000`节点，这种方法变得太慢了。 

### 最佳方法

 关键的观察结果是，每个非根节点作为子节点只出现一次，而根节点从不作为子节点出现。 

我们可以处理树一次并将所有子节点记录在哈希集中，而不是重复搜索。 

算法变为：

 1. 将每个子节点添加到集合中。 
2. 再次迭代所有节点。 
3. 子集中未找到的节点为根节点。 

这将问题转化为简单的成员资格查找问题。 

还有一个后续要求不断的额外空间。 巧妙的数学观察在这里有所帮助：

 - 对所有节点值求和。 
- 减去每个子值。 
- 剩余值必须是根值。 

因为每个非根值都被加一次并减一次，所以只剩下根。 

但是，由于我们仍然需要将剩余值映射回相应的节点对象，因此我们对节点执行最后一次扫描。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 反复寻找亲子关系|

 ## 算法演练

 哈希集方法是最清晰且最普遍接受的解决方案。 

1. 创建一个名为的空哈希集`children_set`。 

该集合将包含作为子节点出现在树中某处的每个节点。 
2. 遍历输入数组中的每个节点。 

对于每个节点，迭代其`children`列表。 
3.将各个子节点添加到`children_set`。 

由于每个非根节点只有一个父节点，因此所有非根节点最终都会出现在该集合中。 
4. 再次遍历输入数组。 

对于每个节点，检查它是否存在于`children_set`。 
5. 返回集合中第一个未找到的节点。 

该节点从未作为子节点出现，因此它一定是根节点。 
6. 如果没有找到节点，则返回`None`。 

这种情况永远不应该发生，因为该问题保证了树的有效。 

### 为什么它有效

 正确性依赖于树的基本属性：

 - 除根节点外，每个节点都只有一个父节点。 
- 因此，每个非根节点都出现在某些父节点中`children`列表。 
- 根没有父项，因此它永远不会显示为子项。 

通过收集所有子节点，我们有效地隔离了每个非根节点。 该集合之外唯一剩余的节点是根。 

## Python 解决方案```python
from typing import List, Optional

"""
# Definition for a Node.
class Node:
    def __init__(self, val: Optional[int] = None, children: Optional[List['Node']] = None):
        self.val = val
        self.children = children if children is not None else []
"""

class Solution:
    def findRoot(self, tree: List['Node']) -> 'Node':
        children_set = set()

        # Collect all child nodes
        for node in tree:
            for child in node.children:
                children_set.add(child)

        # The node that never appears as a child is the root
        for node in tree:
            if node not in children_set:
                return node

        return None
```实现直接遵循算法。 

首先，我们创建一个名为的哈希集`children_set`。 该集合存储对树中某处显示为子节点的每个节点的引用。 

接下来，我们迭代输入数组中的每个节点。 对于每个节点，我们遍历它的`children`列出并将每个子节点插入到集合中。 

在此预处理阶段之后，保证每个非根节点都存在于集合内。 

然后我们对原始节点列表执行第二次遍历。 第一个节点不存在于`children_set`作为根返回。 

决赛`return None`从技术上讲，对于有效输入来说是不必要的，但它使函数在语法上保持完整。 

## 解决方案```go
/**
 * Definition for a Node.
 * type Node struct {
 *     Val int
 *     Children []*Node
 * }
 */

func findRoot(tree []*Node) *Node {
    childrenSet := make(map[*Node]bool)

    // Collect all child nodes
    for _, node := range tree {
        for _, child := range node.Children {
            childrenSet[child] = true
        }
    }

    // Find the node that never appears as a child
    for _, node := range tree {
        if !childrenSet[node] {
            return node
        }
    }

    return nil
}
```Go 实现在结构上与 Python 版本相同。 

而不是Python内置的`set`, Go 使用`map[*Node]bool`模拟设定行为。 

节点引用用作映射键，这很自然，因为指针标识唯一标识每个节点对象。 

该函数返回`nil`if no root is found, although valid problem constraints guarantee that a root always exists.

### 示例 2

 输入：```
[1,null,2,3,4,5,null,null,6,7,null,8,null,9,10,null,null,11,null,12,null,13,null,null,14]
```树要大得多，但应用相同的逻辑。 

### 步骤1：添加所有子节点

 当我们遍历树时：

 -`2, 3, 4, 5`成为孩子
 -`6, 7`成为孩子
 -`8`变成一个孩子
 -`9, 10`成为孩子
 -`11, 12, 13`成为孩子
 -`14`变成一个孩子

 最终，除了`1`出现在子集中。 

### 第 2 步：查找丢失的节点

 扫描原始节点列表时：

 - 每个节点除了`1`存在于子集中。 
-`1`集合中不存在。 

所以，`1`是根。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个节点和子关系都被处理一次 |
 | 空间| O(n) | 子集可能包含所有非根节点 |

 该算法是线性的，因为每个节点被访问的次数是恒定的。 在构建子集时，树中的每个边都会被处理一次。 

辅助空间来自存储哈希集中的所有子节点。 在最坏的情况下，该集合包含`n - 1`节点。 

后续的恒定空间方案可以将辅助空间减少到`O(1)`通过使用算术取消，但哈希集版本更简单、更直观。

 ## 边缘情况

 ### 单节点树

 只有一个节点的树是最小的有效输入。 由于该节点没有父节点也没有子节点，因此子节点集保持为空。 在第二遍期间，在集合中未找到该节点，并作为根正确返回。 

有缺陷的实现可能会错误地假设至少存在一种父子关系。 

### 任意输入顺序

 输入数组被明确指定为任意顺序。 根可能出现在数组的开头、中间或末尾。 

假设第一个节点是根的简单解决方案将立即失败。 所实现的算法完全避免了这个问题，因为它仅根据结构关系来确定根。 

### 深度或高度不平衡的树

 有些树可能类似于链表，其中每个节点只有一个子节点。 如果不小心实现，递归方法可能会在某些语言中面临堆栈溢出的风险。 

哈希集解决方案是纯迭代的，无论树的形状如何，都会统一处理节点，因此它可以安全地处理深层树。 

### 具有空子列表的节点

 叶子节点包含空`children`列表。 该实现自然会处理这个问题，因为迭代空列表只是不执行任何操作。 

叶子不需要特殊情况逻辑。
