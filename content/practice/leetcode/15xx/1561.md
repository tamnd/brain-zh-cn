 # LeetCode 1561 - 您可以获得的最大金币数量

 ## 问题理解

 问题给了我们一个名为`piles`，其中每个元素代表一堆硬币的数量。 数组的长度总是可以被整除`3`，这意味着正好有`3n`一些整数的堆`n`。 

每轮都会选择三堆。 这三堆当中：

 - 爱丽丝总是拿走最大的一堆。 
- 你拿第二大堆。 
- 鲍勃拿走最小的一堆。 

这个过程一直持续到所有桩都被使用为止。 

目标是最大化您收集的硬币总数。 

关键细节是我们可以在每个步骤中选择任意三堆。 桩不需要相邻，我们可以策略性地安排分组。 由于爱丽丝总是拿走所选择的三元组中最大的一堆，所以我们不能直接为自己保留最大的一堆。 然而，我们仍然可以构建选择，以便我们始终将大堆作为第二大选择。 

约束条件很重要：

 -`piles.length`可以大到`10^5`- 每堆最多可容纳`10^4`硬币

 由于输入量很大，指数或二次模拟方法并不实用。 我们需要一种高效的算法，理想情况下仅以排序为主。 

一些边缘情况值得注意：

 - 最小的有效输入只有`3`桩。 
- 许多堆可能包含相同的值。 
- 数组可能已经排序或反向排序。 
- 接近约束限制的极大值应该仍然有效。 
- 如果不考虑到爱丽丝总是拿走最大的一堆，那么天真的贪婪分组策略可能会失败。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试一切可能的方法将桩分成三组，然后模拟选择。 

对于每个分组：

 1. Alice 拿走最大的一堆。 
2. 你取第二个最大值。 
3. Bob 取最小值。 

我们将计算您的总数并保留所有可能安排中的最大值。 

这种方法是正确的，因为它探索了每种可能的配置，保证找到最佳排列。 

然而，对于给定的约束，这在计算上是不可能的。 分区方式的数量`3n`成三元组的项目增长得非常快。 即使对于相对较小的输入，组合的数量也会变得巨大。 

因此，蛮力仅在概念上有用，在实践中没有用处。 

### 最优贪心法

 关键的见解来自于了解如何最大化您收到的堆。 

将堆按升序排序后：

 - 爱丽丝总是会拿走剩下的最大的一堆。 
- 鲍勃应该尽可能收到剩余的最小堆。 
- 您应该收到爱丽丝选择后的第二大堆。 

为了实现这一目标，我们配对：

 - 爱丽丝最大的一堆
 - 我们自己的第二大堆
 - 给鲍勃的最小的一堆

 这个策略在鲍勃身上浪费了最小的一堆，同时为我们自己保留了大堆。 

排序后，我们可以重复：

 - 跳过最大的一堆，爱丽丝拿走它
 - 为我们自己拿下第二大堆
 - 忽略鲍勃的最小一堆

 这会产生最大可能的总数。

 ## 算法演练

 1. 将数组按升序排序。 

排序使我们能够有效地推断出剩余的最小和最大的堆。 排序后，最大的堆位于数组的末尾。 
2. 观察最佳分配模式。 

每三人一组：

 - 爱丽丝应该拿走当前最大的一堆。 
- 你应该拿第二大的一堆。 
- 鲍勃应该拿走剩下的最小的一堆。 

这可以最大限度地减少鲍勃造成的浪费，同时最大限度地提高您的收益。 
3. 初始化指针。 

让：

-`left = 0`，指向剩余的最小堆
 -`right = len(piles) - 2`，指向剩余的第二大堆

 我们开始于`len(piles) - 2`因为最后最大的一堆实际上是为爱丽丝保留的。 
4. 重复`n`次。 

由于有`3n`桩，正好有`n`回合。 

每轮：

 - 添加`piles[right]`给你的答案
 - 移动`right`还剩两个位置
 - 移动`left`右边一个位置

 搬家`right`通过两次跳过：

 - 一堆给爱丽丝
 - 给自己一堆

 搬家`left`减 1 为鲍勃移除最小的一堆。 
5. 返回累计答案。 

### 为什么它有效

 贪婪策略之所以有效，是因为鲍勃总是收到每个三元组中最小的一堆，因此最小值对您的分数没有任何贡献。 因此，最佳策略是牺牲最小的堆给鲍勃，同时为自己保留尽可能大的第二大值。 

排序后，每个最佳分组都可以重新排列成这种模式，而不会减少您的总数。 因此，从右侧贪婪地选择每隔一堆就能保证最大可实现的总和。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxCoins(self, piles: List[int]) -> int:
        piles.sort()

        total = 0
        left = 0
        right = len(piles) - 2
        rounds = len(piles) // 3

        for _ in range(rounds):
            total += piles[right]

            left += 1
            right -= 2

        return total
```该实现首先对数组进行排序，以便可以轻松访问最小和最大的堆。 

变量`total`存储您收集的硬币数量。 这`right`指针从第二大元素开始，因为假定最大元素在每一轮中都指向 Alice。 这`left`指针跟踪将发送给 Bob 的最小剩余堆。 

循环完全运行`n`时间、地点`n = len(piles) // 3`。 在每次迭代期间：

 -`piles[right]`已添加到您的总数中。 
-`right -= 2`跳过爱丽丝的一堆和你选择的一堆。 
-`left += 1`移除鲍勃的最小一堆。 

在最后，`total`包含您可以获得的最大数量的硬币。 

## 解决方案```go
package main

import (
	"sort"
)

func maxCoins(piles []int) int {
	sort.Ints(piles)

	total := 0
	right := len(piles) - 2
	rounds := len(piles) / 3

	for i := 0; i < rounds; i++ {
		total += piles[right]
		right -= 2
	}

	return total
}
```Go 实现遵循与 Python 版本完全相同的贪婪逻辑。 

标准库函数`sort.Ints()`按升序对切片进行排序。 由于 Go 切片是对数组的可变引用，因此排序发生在适当的位置。 

与 Python 不同，Go 不需要单独的`left`指针，因为我们从不直接访问最小的元素。 我们只需要跟踪我们收集的堆的位置。 

整数溢出不是问题，因为最大可能的答案完全适合 Go 的内部`int`给定约束下的类型。

 ## 边缘情况

 一种重要的边缘情况是尽可能最小的输入大小，其中正好有三堆。 在这种情况下，只有一轮。 有缺陷的实现可能会错误地移动指针或假设存在多个迭代。 当前的实现自然地处理了这个问题，因为循环只运行一次。 

当所有桩尺寸相同时，会发生另一个重要情况。 由于每堆都有相同的值，因此有许多同样有效的分组。 一些实现意外地依赖于严格的不等式或特殊的排序假设。 基于排序的贪婪方法可以正确工作，因为每个第二大堆仍然具有相同的值。 

第三种边缘情况涉及已经按降序排序的数组。 如果实现假设升序而没有显式排序，则逻辑完全失败。 通过始终首先对输入进行排序，该算法保证了指针策略在正确排序的序列上运行。 

最后一个重要的情况涉及接近最大约束大小的非常大的数组。 重复删除元素或通过昂贵的操作模拟三元组的低效方法可能会变得太慢。 此实现仅排序一次，然后执行简单的线性遍历，即使对于允许的最大输入也非常高效。
