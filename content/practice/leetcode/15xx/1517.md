[LeetCode 问题 1517](https://leetcode.com/problems/find-users-with-valid-e-mails/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 这个问题要求我们查询一个名为`Users`并仅返回与根据非常特定的格式认为电子邮件地址**有效**的用户相对应的行。 

中的每一行`Users`表包含三列：

 -`user_id`，每个用户的唯一整数标识符
 -`name`, 用户名
 -`mail`, 用户的电子邮件地址

 任务是过滤表并仅返回那些用户`mail`字段满足有效性规则。 

有效的电子邮件由两部分组成：

 1. **前缀名称**，出现在`@`象征。 
2. 一个**域**，必须准确无误`@leetcode.com`。 

前缀名称有严格的要求：

 - **必须以字母**开头，可以是大写或小写。 
- 第一个字符之后，可能包含：

 - 字母（`a-z`,`A-Z`）
 - 数字（`0-9`）
 - 下划线（`_`）
- 时期 （`.`）
 - 破折号（`-`）

 域名要求同样严格：

 - 电子邮件必须以**完全**结尾`@leetcode.com`。 

这意味着像这样的地址`abc@gmail.com`无效，因为域名错误，地址如`.john@leetcode.com`无效，因为前缀不是以字母开头。 

预期的输出只是过滤后的表，其中包含电子邮件与这些规则匹配的所有行。 顺序并不重要。 

由于这是一个数据库问题，最自然的方法是使用**与正则表达式的模式匹配**，因为验证规则本质上是字符串模式规范。 

### 重要的边缘案例

 有几种情况很容易在简单的实现中导致错误。 

电子邮件可能完全缺少域，例如`jonathanisgreat`。 简单的子字符串检查将无法验证完整的结构。 

前缀可能包含无效符号，例如`#`,`%`，或空格。 例如，`quarz#2020@leetcode.com`无效，因为`#`不是允许的字符。 

前缀可能以无效字符开头。 例如，`.shapo@leetcode.com`即使前缀后面允许使用句点也是无效的。 

域必须完全匹配。 像这样的地址`user@gmail.com`或者`user@leetcode.co`不得接受。 

该问题保证了`user_id`是唯一的，因此不需要重复的行处理。 

## 方法

 ### 蛮力方法

 暴力解决方案将手动逐个字符地检查每封电子邮件。 

对于每一行，我们可以：

 1. 验证字符串是否恰好包含 1`@`。 
2. 将电子邮件拆分为前缀和域。 
3. 检查域是否等于`leetcode.com`。 
4. 验证前缀以字母开头。 
5. 迭代每个剩余的字符以确保每个字符都属于允许的集合。 

这种方法是正确的，因为它明确地一一检查每条规则。 然而，它变得冗长且容易出错。 手动实现字符串解析逻辑会增加复杂性，并使查询更难以阅读和维护。 

在 SQL 中，这尤其尴尬，因为逐字符验证不是关系数据库的强项。 

### 最佳方法

 关键的观察是整个验证规则可以自然地表达为**正则表达式**。 

我们想要一个强制执行以下内容的模式：

 - 字符串的开头
 - 第一个字符是一个字母
 - 其余前缀字符为字母、数字、`_`,`.`， 或者`-`- 精确的域名`@leetcode.com`- 字符串结尾

 对应的正则表达式是：```
^[A-Za-z][A-Za-z0-9_.-]*@leetcode\.com$
```让我们来分解一下：

 -`^`表示字符串的开始。 
-`[A-Za-z]`确保第一个字符是字母。 
-`[A-Za-z0-9_.-]*`之后允许零个或多个有效字符。 
-`@leetcode\.com`强制执行精确的域。 
-`$`表示字符串结束。 

然后我们可以使用 SQL 的正则表达式匹配功能`REGEXP`。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(N × M) | O(1) | O(1) | 手动验证每封电子邮件的每个字符 |
 | 最佳| O(N × M) | O(1) | O(1) | 使用正则表达式匹配，更干净、更可维护 |

 这里：

-`N`是行数`Users`-`M`是平均电子邮件长度

 尽管这两种方法具有相似的理论复杂性，但正则表达式解决方案对于 SQL 来说明显更简单且更实用。 

## 算法演练

 ### 最优算法

 1. 读取每一行`Users`桌子。 

我们需要检查每个用户的电子邮件，因为有效性完全取决于电子邮件的内容`mail`柱子。 
2. 应用正则表达式匹配`mail`柱子。 

正则表达式模式是：```
^[A-Za-z][A-Za-z0-9_.-]*@leetcode\.com$
```这可确保前缀以字母开头，之后仅包含有效字符，并以所需的确切域结尾。 
3. 仅保留匹配的行。 

如果电子邮件满足正则表达式，则该行将包含在结果集中。 否则，它将被丢弃。 
4. 返回过滤后的表。 

该问题允许结果按任意顺序排列，因此无需排序。 

### 为什么它有效

 正确性来自于正则表达式编码**完全按照问题陈述中描述的规则**这一事实。 

第一个字符约束由以下方式强制执行`[A-Za-z]`，允许的字符集由`[A-Za-z0-9_.-]*`，并且所需的域由以下命令强制执行`@leetcode\.com`。 锚点`^`和`$`保证整个字符串必须与模式匹配，防止部分匹配或多余字符。 

因此，当且仅当行的电子邮件有效时，才会包含该行。 

## Python 解决方案

 虽然这是一个数据库问题，并且 LeetCode 需要 SQL，但下面是一个 Python 等效实现，可以清楚地演示逻辑。```python
import re
from typing import List

class Solution:
    def findValidEmails(self, users: List[dict]) -> List[dict]:
        pattern = re.compile(
            r'^[A-Za-z][A-Za-z0-9_.-]*@leetcode\.com$'
        )

        valid_users = []

        for user in users:
            email = user["mail"]

            if pattern.match(email):
                valid_users.append(user)

        return valid_users
```实现从编译正则表达式模式开始。 这提高了效率，因为正则表达式引擎不需要重新解析每封电子邮件的模式。 

然后，我们迭代每个用户记录并提取`mail`场地。 如果电子邮件与正则表达式模式匹配，则用户将被添加到结果列表中。 

最后返回过滤后的列表。 

对于实际的LeetCode提交，SQL查询是：```python
SELECT *
FROM Users
WHERE mail REGEXP '^[A-Za-z][A-Za-z0-9_.-]*@leetcode\\.com$';
```此查询直接应用正则表达式条件来过滤有效的电子邮件。 

## 解决方案

 下面是一个反映 Python 逻辑的 Go 实现。```go
package main

import "regexp"

func findValidEmails(users []map[string]string) []map[string]string {
	pattern := regexp.MustCompile(
		`^[A-Za-z][A-Za-z0-9_.-]*@leetcode\.com$`,
	)

	validUsers := []map[string]string{}

	for _, user := range users {
		email := user["mail"]

		if pattern.MatchString(email) {
			validUsers = append(validUsers, user)
		}
	}

	return validUsers
}
```Go 版本使用`regexp`打包并编译正则表达式一次使用`regexp.MustCompile`。 

与 Python 不同，Go 使用切片而不是列表。 我们初始化一个空切片`validUsers`并在迭代时附加匹配的用户。 

这里不存在整数溢出问题，因为我们只处理字符串。 类似地，nil 处理也很简单，因为空结果只是返回一个空切片。 

对于实际的LeetCode数据库提交，使用SQL：```go
SELECT *
FROM Users
WHERE mail REGEXP '^[A-Za-z][A-Za-z0-9_.-]*@leetcode\\.com$';

 ## 边缘情况

 一种重要的边缘情况是以无效字符开头的前缀。 由于句点、下划线和破折号允许在前缀中稍后出现，因此很容易在开头意外地允许使用它们。 例如，`.john@leetcode.com`应该是无效的。 我们的正则表达式通过明确要求第一个字符匹配来处理这个问题`[A-Za-z]`。 

另一个重要的边缘情况是无效域。 一个幼稚的实现可能只检查字符串是否包含`"leetcode.com"`某处。 这将错误地允许诸如`abc@gmailleetcode.com`。 我们的实现强制执行确切的后缀`@leetcode\.com`并将模式锚定到字符串的末尾。 

第三种边缘情况涉及前缀内的非法特殊字符。 字符如`#`,`%`，或不允许有空格。 由于正则表达式明确将有效字符限制为`[A-Za-z0-9_.-]`，任何意外的符号都会自动导致匹配失败。 

最后，包含多个的格式错误的电子邮件`@`符号或缺失的域会被正确拒绝，因为整个字符串必须从头到尾匹配所需的格式。
