[LeetCode 问题 1538](https://leetcode.com/problems/guess-the-majority-in-a-hidden-array/)

 **难度：** 🟡 中等
 **主题：** 数组、数学、交互

 ## 解决方案

 ## 问题理解

 这个问题是一个交互问题。 我们不直接接收实际的二进制数组。 相反，我们只能通过以下方式收集信息：`ArrayReader`API。 

隐藏数组`nums`仅包含`0`和`1`。 我们的目标是确定哪个值出现得更频繁，并返回包含该多数值的任何索引。 如果数量`0`沙`1`s 相等，我们必须返回`-1`。 

检查数组的唯一方法是通过以下函数：```
query(a, b, c, d)
```该函数比较四个不同的索引并返回：

 -`4`如果所有四个值都相同
 -`2`如果正好三个值相同且一个不同
 -`0`如果有两个`0`和两个`1`s

 重要的观察结果是，查询结果仅取决于所选的四个索引中有多少个相等的值。 我们从不直接了解实际值。 

数组长度可以大到`10^5`，并且我们最多限制为`2 * n`查询。 这立即排除了任何重复比较大型子集或尝试详尽推论的解决方案。 

因此，挑战不是传统的多数投票，而是仅使用这些 4 元素查询重建索引之间的相对平等关系。 

一些边缘情况尤其重要：

 - 该数组可以包含相同数量的`0`沙`1`s，在这种情况下我们必须返回`-1`。 
- 多数值只能比少数值多出现一次。 
- 前几个元素可能并不全部属于同一组。 
- 因为我们永远不知道一个元素是否实际上是`0`或者`1`，我们只需要将索引分类为“与索引0相同”或“与索引0不同”。 

关键的见解是我们不需要实际值。 我们只需要将索引划分为两个等价类。 

## 方法

 ### 蛮力方法

 一种简单的方法是尝试重建整个隐藏数组。 

对于每个索引，我们可以发出涉及已知位置的多个查询，并推断当前元素是否与另一个元素匹配。 最终，我们可以导出相对于参考元素的每一位值。 

这种方法是正确的，因为足够仔细选择的查询可以确定两个索引是否包含相同的值。 一旦所有指数都被分类，频率计数就变得简单了。 

但是，强力实现可能需要每个索引进行许多冗余查询。 由于查询预算仅为`2 * n`，任何对每个元素使用明显超过常量查询的策略都将超出限制。 

例如，比较每对索引需要`O(n^2)`查询，这是不可能的`n = 10^5`。 

### 最佳方法

 最优解以前四个指标为参考框架。 

核心观察是：

 如果替换查询中的一个索引不会更改查询结果，则替换的元素必须与新元素具有相同的值。 

假设我们计算：```
base = query(0, 1, 2, 3)
```现在来一个索引`i >= 4`， 比较：```
query(1, 2, 3, i)
```两个查询之间的唯一区别是索引`0`被替换为`i`。 

- 如果结果保持不变，那么`nums[i] == nums[0]`- 否则，`nums[i] != nums[0]`这使我们能够对每个相对于索引的索引进行分类`0`每个索引仅使用一个查询。 

前四个索引需要特殊处理，因为我们无法查询重复的索引。 对于它们中的每一个，我们用索引替换该特定索引`4`并与基本查询进行比较。 

将所有索引分为两组后，我们简单地比较它们的大小：

 - 较大的团体获胜
 - 尺寸相同意味着平局

 ## 算法演练

 1. 首先，使用前四个索引计算基线查询：```
base = query(0, 1, 2, 3)
```这建立了一个参考模式。 
2. 创建两个计数器：

 - 一组包含等于`nums[0]`- 另一组包含不同于`nums[0]`最初：

-`same_count = 1`-`different_count = 0`-`same_index = 0`-`different_index = -1`3. 工艺指标`4`通过`n - 1`。 

对于每个索引`i`，计算：```
query(1, 2, 3, i)
```此查询与基线的不同之处仅在于替换了索引`0`和`i`。 

- 如果结果等于`base`， 然后`nums[i] == nums[0]`- 否则，`nums[i] != nums[0]`更新适当的计数器并存储代表性索引。 
4. 处理索引`1`,`2`， 和`3`分别地。 

对于每个索引，将其替换为索引`4`：

- 比较`query(0, 2, 3, 4)`反对`base`对于索引`1`- 比较`query(0, 1, 3, 4)`反对`base`对于索引`2`- 比较`query(0, 1, 2, 4)`反对`base`对于索引`3`如果结果发生变化，则替换后的索引与索引不同`0`。 
5. 所有指标分类后，比较组大小。 

- 如果计数相等，则返回`-1`- 否则，返回较大组中的任何代表性索引

 ### 为什么它有效

 每个查询比较恰好隔离一个已更改的元素。 由于其他三个索引保持固定，因此查询结果更改的唯一原因是替换元素的值与删除的元素不同。 

因此，每次比较都正确确定索引是否与索引属于同一值组`0`。 由于数组仅包含两个可能的值，因此以这种方式分区索引完全确定了多数组。 

## Python 解决方案```python
# """
# This is the ArrayReader's API interface.
# You should not implement it, or speculate about its implementation
# """
# class ArrayReader(object):
#     def query(self, a: int, b: int, c: int, d: int) -> int:
#         pass
#
#     def length(self) -> int:
#         pass

class Solution:
    def guessMajority(self, reader: 'ArrayReader') -> int:
        n = reader.length()

        base = reader.query(0, 1, 2, 3)

        same_count = 1
        diff_count = 0

        same_index = 0
        diff_index = -1

        # Process indices 4 to n - 1
        for i in range(4, n):
            current = reader.query(1, 2, 3, i)

            if current == base:
                same_count += 1
                same_index = i
            else:
                diff_count += 1
                diff_index = i

        # Check index 1
        if reader.query(0, 2, 3, 4) == base:
            same_count += 1
            same_index = 1
        else:
            diff_count += 1
            diff_index = 1

        # Check index 2
        if reader.query(0, 1, 3, 4) == base:
            same_count += 1
            same_index = 2
        else:
            diff_count += 1
            diff_index = 2

        # Check index 3
        if reader.query(0, 1, 2, 4) == base:
            same_count += 1
            same_index = 3
        else:
            diff_count += 1
            diff_index = 3

        if same_count == diff_count:
            return -1

        if same_count > diff_count:
            return same_index

        return diff_index
```实现首先为索引建立基线查询结果`(0,1,2,3)`。 以后的每个查询都被设计为与此基线仅相差一个索引。 

索引循环`4`和超越比较`query(1,2,3,i)`与基线。 由于只有索引`0`被替换，匹配结果意味着相等的值。 

指数`1`,`2`， 和`3`需要特殊处理，因为查询 API 需要不同的索引。 通过用索引替换特定索引来测试它们中的每一个`4`。 

最后，该算法比较两个分区大小并返回较大组中的代表性索引。 

## 解决方案```go
/**
 * // This is the ArrayReader's API interface.
 * // You should not implement it, or speculate about its implementation
 * type ArrayReader struct {
 * }
 *
 * // Compares 4 different elements in the array
 * func (this *ArrayReader) query(a, b, c, d int) int {}
 *
 * // Returns the length of the array
 * func (this *ArrayReader) length() int {}
 */

func guessMajority(reader *ArrayReader) int {
	n := reader.length()

	base := reader.query(0, 1, 2, 3)

	sameCount := 1
	diffCount := 0

	sameIndex := 0
	diffIndex := -1

	// Process indices 4 to n - 1
	for i := 4; i < n; i++ {
		current := reader.query(1, 2, 3, i)

		if current == base {
			sameCount++
			sameIndex = i
		} else {
			diffCount++
			diffIndex = i
		}
	}

	// Check index 1
	if reader.query(0, 2, 3, 4) == base {
		sameCount++
		sameIndex = 1
	} else {
		diffCount++
		diffIndex = 1
	}

	// Check index 2
	if reader.query(0, 1, 3, 4) == base {
		sameCount++
		sameIndex = 2
	} else {
		diffCount++
		diffIndex = 2
	}

	// Check index 3
	if reader.query(0, 1, 2, 4) == base {
		sameCount++
		sameIndex = 3
	} else {
		diffCount++
		diffIndex = 3
	}

	if sameCount == diffCount {
		return -1
	}

	if sameCount > diffCount {
		return sameIndex
	}

	return diffIndex
}
```Go 实现密切反映了 Python 逻辑。 由于 Go 使用显式变量声明并且缺乏 Python 的动态类型，因此所有计数器和索引都保持为整数。 

不存在溢出问题，因为计数永远不会超过`10^5`。 该解决方案还使用恒定的辅助空间，因为不需要切片或贴图。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个索引都通过恒定数量的查询进行处理 |
 | 空间| O(1) | O(1) | 仅存储少量计数器和索引 |

 该算法执行一次基线查询，对来自的每个索引执行一次查询`4`到`n-1`，以及三个额外的索引查询`1`,`2`， 和`3`。 

总计为：```
1 + (n - 4) + 3 = n
```查询，这远远低于`2 * n`限制。 

不使用与输入大小成比例的辅助数据结构。

 ## 边缘情况

 ### 零和一之间的关系

 当数组包含完全相同数量的`0`沙`1`s。 

有缺陷的实现可能总是返回其中一个组而不仔细检查相等性。 该解决方案明确比较`same_count`和`diff_count`最后返回`-1`当他们匹配时。 

### 所有元素相同

 如果数组中的每个元素都相同，则每个比较查询都将与基线查询匹配。 

这可能会暴露实现中的错误，这些错误会错误地初始化计数或无法正确更新代表性索引。 在这里，所有索引都正确累积到“相同”组中，并且返回任何有效索引。 

### 仅以一种元素占多数

 数组例如：```
[1,0,1,0,1]
```很容易处理不当，因为单个分类错误会改变最终答案。 

该解决方案避免了歧义，因为每次比较都精确地隔离了一个被替换的元素。 每个指标相对于指标独立分类`0`，即使在余量很小的情况下也能保证准确的计数。
