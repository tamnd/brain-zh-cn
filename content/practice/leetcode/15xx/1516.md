[LeetCode 第 1516 题](https://leetcode.com/problems/move-sub-tree-of-n-ary-tree/)

 **难度：** 🔴难
 **主题：** 树、深度优先搜索

 ## 解决方案

 ## 问题理解

 该问题要求我们通过将一个子树移动到另一个节点下来修改 N 叉树的结构。 每个节点都包含唯一的值，并且每个节点可以有任意数量的子节点。 

我们得到：

 -`root`，N叉树的根节点
 -`p`，我们要移动的子树的根
 -`q`，应该成为新父节点的节点`p`操作是：

 - 删除`p`来自其当前父级
 - 附上`p`作为最后一个孩子`q`乍一看，这听起来很简单，但困难在于它们之间的关系`p`和`q`。 

存在三种可能的结构关系：

 1.`q`位于以`p`2.`p`位于以`q`3. 两个节点都不在对方的子树内

 情况 2 和 3 是简单的树重新附加操作。 我们分离`p`来自其父级并将其附加到`q.children`。 
案例 1 是棘手的部分。 的`q`已经在里面了`p`的子树，然后简单地附加`p`在下面`q`会创建一个循环，这对于树来说是无效的。 为了避免这种情况，我们必须首先断开连接`q`在移动之前从其当前父级`p`。 

限制相对较小：

 - 最多1000个节点
 - 所有节点值都是唯一的

 因为树很小，`O(n)`基于遍历的解决方案是完全可以接受的。 

一些边缘情况很重要：

 -`p`可能已经是`q`-`p`可能是根
 -`q`可能在里面`p`的子树
 -`p`和`q`可能属于不相关的分支
 - 删除和重新连接节点绝不能创建循环

 幼稚的实现常常会失败`q`在里面`p`的子树，因为正确地重新连接树需要仔细处理父关系。 

## 方法

 ### 蛮力方法

 每当我们需要结构信息时，强力解决方案都会重复遍历树。 

例如：

 - 遍历树找到父级`p`- 再次遍历找到父级`q`- 再次遍历判断是否`q`位于里面`p`的子树
 - 之后进行修改

 这是可行的，因为树很小，但它执行了不必要的重复遍历。 

主要缺点是每个操作都需要额外的 DFS 搜索。 尽管总复杂度仍然可以接受`n <= 1000`，实现变得重复并且更难以推理。 

### 最佳方法

 关键的见解是，如果我们知道每个节点的父节点，树修改就会变得容易得多。 

我们可以执行一次 DFS 遍历并构建：

 - 家长地图：`child -> parent`- 使用 DFS 的祖先关系检查器

 一旦我们知道了父关系，子树移动就变成了本地指针更新的序列。 

关键的观察是：

 - 如果`q`不在里面`p`的子树，我们可以安全地分离`p`并将其附加在下面`q`- 如果`q`在里面`p`的子树，我们必须首先分离`q`在附加之前从其当前父级`p`在下面`q`这可以防止循环并保留树的连接性。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 多次重复遍历|
 | 最佳| O(n) | O(n) | 单一 DFS 加上恒定时间结构更新 |

 ## 算法演练

 ### 第 1 步：建立父参考

 我们从根和存储执行 DFS 遍历：```
parent[child] = current_node
```这使我们能够快速：

 - 从父节点中删除节点
 - 在恒定时间内找到任何节点的父节点

 如果没有父引用，删除子树将需要另一次遍历。 

### 步骤 2：检查是否`q`在里面`p`的子树

 我们运行 DFS 从`p`。 

如果我们遇到`q`， 然后`q`属于`p`的子树。 

这决定了我们正在处理哪种结构案例。 

### 第 3 步：处理简单情况

 如果`q`不在里面`p`的子树：

 1. 删除`p`来自其当前父级
 2. 追加`p`到`q.children`这可以安全地移动子树，而不会影响树的有效性。 

### 第 4 步：处理循环案例

 如果`q`在里面`p`的子树：

 1. 查找`q`的当前父母
 2. 删除`q`来自那个父母
 3. 删除`p`来自其父级如果`p`不是根
 4. 附加`p`在下面`q`5. 附加`q`进入原来占据的位置`p`这可以正确地重新连接树，同时避免循环。 

如果`p`是原来的根，那么`q`成为新的根。 

### 步骤 5：返回正确的根

 通常，根保持不变。 

然而，当`p`是根并且`q`属于它的子树，`q`成为新的根。 

### 为什么它有效

 该算法保留了树的定义属性：

 - 除根节点外的每个节点都只有一个父节点
 - 结构保持连接
 - 没有引入循环

 唯一危险的情况是附着`p`在其后代之一的领导下。 首先断开连接`q`从它的原始父级开始，我们打破了否则会形成循环的危险路径。 

因为每次修改都是有效的树边替换，所以生成的结构始终是有效的 N 叉树。 

## Python 解决方案```python
"""
# Definition for a Node.
class Node:
    def __init__(self, val: Optional[int] = None, children: Optional[List['Node']] = None):
        self.val = val
        self.children = children if children is not None else []
"""

from typing import Optional, List

class Solution:
    def moveSubTree(self, root: 'Node', p: 'Node', q: 'Node') -> 'Node':

        parent = {}

        def build_parent(node: 'Node') -> None:
            for child in node.children:
                parent[child] = node
                build_parent(child)

        build_parent(root)

        # If p is already a direct child of q
        if p in q.children:
            return root

        def contains(node: 'Node', target: 'Node') -> bool:
            if node == target:
                return True

            for child in node.children:
                if contains(child, target):
                    return True

            return False

        q_in_p_subtree = contains(p, q)

        p_parent = parent.get(p)
        q_parent = parent.get(q)

        def remove_child(par: 'Node', child: 'Node') -> None:
            par.children.remove(child)

        if not q_in_p_subtree:
            # Case 2 or 3
            if p_parent:
                remove_child(p_parent, p)

            q.children.append(p)
            return root

        # Case 1

        # Remove q from its current parent
        if q_parent:
            remove_child(q_parent, q)

        # Remove p from its current parent
        if p_parent:
            p_index = p_parent.children.index(p)
            remove_child(p_parent, p)

            # Replace p with q
            p_parent.children.insert(p_index, q)

        # Attach p under q
        q.children.append(p)

        # If p was root, q becomes new root
        if root == p:
            return q

        return root
```实现首先使用 DFS 构建父映射。 这提供了对每个节点的父节点的恒定时间访问。 

接下来，解决方案检查是否`p`已经是`q`。 在这种情况下，树已经满足所需的结构，因此不需要进行任何更改。 

辅助函数`contains`确定是否`q`属于`p`的子树。 这种区别至关重要，因为它告诉我们是否移动`p`直接会形成一个循环。 

对于正常情况，实现只需删除`p`从其当前父级并将其附加到`q.children`。 

对于困难的情况`q`位于里面`p`的子树，代码小心地重新连接树：

 -`q`与其当前父级分离
 -`p`从其父级中删除
 -`q`取代`p`在老父母的孩子名单中
 -`p`成为的孩子`q`这样可以保留连接性，同时避免循环。 

## 解决方案```go
/**
 * Definition for a Node.
 * type Node struct {
 *     Val int
 *     Children []*Node
 * }
 */

func moveSubTree(root *Node, p *Node, q *Node) *Node {

	parent := make(map[*Node]*Node)

	var buildParent func(*Node)

	buildParent = func(node *Node) {
		for _, child := range node.Children {
			parent[child] = node
			buildParent(child)
		}
	}

	buildParent(root)

	// If p is already a direct child of q
	for _, child := range q.Children {
		if child == p {
			return root
		}
	}

	var contains func(*Node, *Node) bool

	contains = func(node *Node, target *Node) bool {
		if node == target {
			return true
		}

		for _, child := range node.Children {
			if contains(child, target) {
				return true
			}
		}

		return false
	}

	qInPSubtree := contains(p, q)

	pParent := parent[p]
	qParent := parent[q]

	removeChild := func(par *Node, child *Node) {
		for i, c := range par.Children {
			if c == child {
				par.Children = append(par.Children[:i], par.Children[i+1:]...)
				return
			}
		}
	}

	if !qInPSubtree {

		if pParent != nil {
			removeChild(pParent, p)
		}

		q.Children = append(q.Children, p)

		return root
	}

	// Case 1

	if qParent != nil {
		removeChild(qParent, q)
	}

	if pParent != nil {

		pIndex := 0

		for i, child := range pParent.Children {
			if child == p {
				pIndex = i
				break
			}
		}

		removeChild(pParent, p)

		left := append([]*Node{}, pParent.Children[:pIndex]...)
		left = append(left, q)
		left = append(left, pParent.Children[pIndex:]...)

		pParent.Children = left
	}

	q.Children = append(q.Children, p)

	if root == p {
		return q
	}

	return root
}
```Go 实现遵循与 Python 解决方案相同的算法结构。 

一个重要的区别是切片操作。 Go 切片不支持像 Python 列表那样直接删除，因此删除子切片需要使用以下命令重建切片`append`。 

另一个区别是地图的使用。 父映射使用指针作为键：```go
map[*Node]*Node
```这允许使用节点标识进行恒定时间父级查找。 

Go 也需要明确的`nil`检查而不是 Python 的真实检查。

 ## 边缘情况

 ### 将根移到其后代之一之下

 这是问题中最难的情况。 如果我们直接将根附加到其后代之一下，则树将包含一个循环。 

例如：```
1
└── 2
    └── 3
```移动`1`在下面`3`无需断开连接`3`首先会产生：```
1 -> 2 -> 3 -> 1
```该实现通过首先删除来避免这种情况`q`在附加之前从其父级`p`在它下面。 

###`p`已经是一个孩子`q`幼稚的实现可能会不必要地删除并重新插入节点，从而可能会更改子级排序或引入微妙的错误。 

该解决方案明确检查：```
if p in q.children:
    return root
```这保证了当树已经满足要求时不会发生结构变化。 

### 在不相关的分支之间移动

 当两个节点都不在另一个节点的子树内时，该操作的行为应类似于标准子树移动。 

这里的主要风险是忘记分离`p`来自其旧父级，这会错误地将子树附加在两个位置。 

该实施安全地删除`p`在将其附加到之前`q.children`，确保每个节点仍然只有一个父节点。
