[LeetCode 第 1539 题](https://leetcode.com/problems/kth-missing-positive-number/)

 **难度：** 🟢简单
 **主题：** 数组、二分查找

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个严格递增的正整数数组，`arr`，和一个整数`k`。 该数组不一定包含每个正整数。 从以下位置开始的自然序列中缺少一些数字`1`。 

我们的任务是确定`kth`未出现在数组中的正整数。 

例如，如果数组是`[2,3,4,7,11]`，则缺失的正整数为：`1, 5, 6, 8, 9, 10, 12, ...`第 5 个缺失的数字是`9`，所以答案是`9`。 

重要的细节是数组已经按照严格的升序排序。 此属性使我们能够推断出给定索引之前丢失了多少数字，从而形成有效的二分搜索解决方案。 

限制相对较小：

 -`arr.length <= 1000`-`arr[i] <= 1000`-`k <= 1000`在这些限制内，简单的线性扫描已经可以很好地工作。 然而，后续行动明确询问我们是否可以做得更好`O(n)`，这强烈暗示需要采用二分搜索方法。 

一些边缘情况很重要：

 - 缺失的数字可能在第一个数组元素之前开始。 例如，如果`arr = [5,6,7]`， 然后`1,2,3,4`全部失踪。 
- 第 k 个缺失的数字可能超出数组的最后一个元素。 例如，`arr = [1,2,3,4]`,`k = 2`给出答案`6`。 
- 数组可能已经开始于`1`，这意味着最初没有缺失的数字。 
- 数组长度可以小至`1`，因此实现必须正确处理非常小的输入。 

## 方法

 ### 蛮力方法

 最直接的解决方案是模拟从开始的正整数序列`1`。 

我们维持：

 - 指向数组的指针
 - 正在检查当前号码
 - 一个计数器，显示我们看到了多少个缺失的数字

 对于每个正整数：

 - 如果它与当前数组元素匹配，我们将数组指针向前移动。 
- 否则，该数字丢失，因此我们增加丢失的计数器。 
- 一旦丢失计数器达到`k`，我们返回当前数字。 

这是有效的，因为我们显式地按升序检查数字并准确计算数组中不存在的值。 

尽管正确，但这种方法并不是最佳的，因为它可能需要逐一扫描许多整数。 

### 最佳观察

 关键的见解是我们可以确定任何数组索引之前缺少多少个数字。 

假设我们在索引处`i`。 

如果没有丢失数字，则索引处的值`i`应该是：```
i + 1
```因为数组是零索引的。 

相反，实际值是：```
arr[i]
```因此，索引之前缺失的整数的数量`i`是：```
arr[i] - (i + 1)
```例如：

 | 索引 | 价值| 预计 | 缺失计数 |
 | --- | --- | --- | --- |
 | 0 | 2 | 1 | 1 |
 | 1 | 3 | 2 | 1 |
 | 2 | 4 | 3 | 1 |
 | 3 | 7 | 4 | 3 |

 该缺失计数单调增加，这使得二分查找成为可能。 

我们可以二分查找第一个索引，其中缺失整数的数量至少为`k`。

 ## 算法演练

 ### 最优二分查找算法

 1. 为索引之前缺失整数的数量定义一个辅助概念`i`。 

公式为：```
missing(i) = arr[i] - (i + 1)
```这告诉我们之前有多少个正整数缺失`arr[i]`。 
2. 初始化二分查找边界。 

放：

-`left = 0`-`right = len(arr) - 1`我们将搜索缺失计数至少达到的第一个位置`k`。 
3. 执行二分查找。 

尽管`left <= right`：

 - 计算`mid`- 计算`missing = arr[mid] - (mid + 1)`如果`missing < k`，那么第 k 个缺失的数字必须位于更右侧，因此移动：```
left = mid + 1
```否则，此时已经缺少足够的数字，因此请移动：```
right = mid - 1
```4. 解释最终立场。 

二分查找后：

 -`left`表示有多少个数组元素小于第 k 个缺失数。 
- 答案变成：```
left + k
```5. 返回结果。 

### 为什么它有效

 二分查找之所以有效，是因为缺少计数：```
arr[i] - (i + 1)
```是单调递增的。 

随着数组值变大，跳过的整数数量只能保持不变或增加。 这种单调性保证了二分查找能够正确定位缺失计数最先到达的边界`k`。 

一旦我们知道答案之前出现了多少个数组元素，公式：```
left + k
```正确地重建第 k 个缺失的正整数。 

## Python 解决方案```python
from typing import List

class Solution:
    def findKthPositive(self, arr: List[int], k: int) -> int:
        left = 0
        right = len(arr) - 1

        while left <= right:
            mid = (left + right) // 2

            missing_count = arr[mid] - (mid + 1)

            if missing_count < k:
                left = mid + 1
            else:
                right = mid - 1

        return left + k
```实现首先在数组索引上设置标准二分搜索边界。 

在循环内部，我们计算中点并确定之前丢失了多少个正整数`arr[mid]`。 

如果少于`k`到目前为止，数字缺失，那么答案必须出现在该索引之后，因此我们将左边界向前移动。 

否则，第 k 个缺失的数字要么在这个位置，要么更早，所以我们将右边界向后移动。 

循环结束后，`left`表示出现在第 k 个缺失数字之前的数组元素的数量。 添加`k`给出了确切的答案。 

该解决方案仅使用恒定的额外内存并执行对数时间搜索。 

## 解决方案```go
func findKthPositive(arr []int, k int) int {
	left := 0
	right := len(arr) - 1

	for left <= right {
		mid := left + (right-left)/2

		missingCount := arr[mid] - (mid + 1)

		if missingCount < k {
			left = mid + 1
		} else {
			right = mid - 1
		}
	}

	return left + k
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

Go 中的切片已经提供了高效的索引访问，因此不需要额外的数据结构。 

中点计算使用：```go
left + (right-left)/2
```这是标准的溢出安全二分搜索模式，尽管在这些约束下溢出不是问题。 

该算法使用恒定的额外空间并自然地处理所有边缘情况。

 ## 边缘情况

 当缺失的数字在第一个数组元素之前开始时，就会出现一个重要的边缘情况。 例如，与`arr = [5,6,7]`, 数字`1,2,3,4`全部失踪。 仅检查数组内部间隙的简单实现可能会忽略这些缺失的前缀值。 二分搜索解决方案可以自然地处理这个问题，因为缺失计数公式可以正确捕获每个索引之前缺失的数字数量。 

当第 k 个缺失数字超出数组末尾时，会发生另一个关键边缘情况。 例如，`arr = [1,2,3,4]`和`k = 2`产生答案`6`。 有些实现在完成扫描阵列后会错误地停止。 公式`left + k`需要时自动超出数组边界。 

第三种边缘情况涉及非常小的数组，尤其是长度为 1 的数组。 例如：

-`arr = [1]`,`k = 1`-`arr = [2]`,`k = 1`这些情况可能会暴露缺失计数计算中的差一错误。 公式：```
arr[i] - (i + 1)
```仔细考虑从零开始的索引，即使输入最少也能确保正确的结果。
