[LeetCode 问题 1525](https://leetcode.com/problems/number-of-good-ways-to-split-a-string/)

 **难度：** 🟡 中等
 **主题：** 哈希表、字符串、动态编程、位操作

 ## 解决方案

 ## 问题理解

 该问题要求我们计算有多少种方法可以将字符串拆分为两个非空部分，以使两个部分包含相同数量的不同字符。 

两个相邻字符之间发生分割。 对于一个长度的字符串`n`，正好有`n - 1`可能的分割位置，因为双方都必须保持非空。 

对于每个分割：

 - 左子字符串由从开头到分割点的字符组成。 
- 右侧子字符串由其余字符组成。 
- 如果左侧唯一字母的数量等于右侧唯一字母的数量，则认为分割是好的。 

例如，考虑字符串`"aacaba"`：

 - 分裂后`"aac"`给出：

 - 左：`"aac"`→ 不同的字母是`{a, c}`→ 计数 = 2
 - 右：`"aba"`→ 不同的字母是`{a, b}`→ 计数 = 2
 - 由于双方都有相同数量的不同角色，因此这是一个很好的分割。 

约束条件很重要：

 -`1 <= s.length <= 10^5`- 字符串仅包含小写英文字母。 

长度为`10^5`立即告诉我们二次解可能会超时。 任何重复扫描子字符串或从头开始重新计算不同字符计数的方法都太慢。 我们需要一个线性或近线性的解决方案。 

有几种边缘情况值得考虑：

 - 非常短的字符串，例如`"a"`无法产生任何有效的分割，因为两边都必须非空。 
- 所有字符都相同的字符串，例如`"aaaa"`，产生许多有效的分割，因为两边总是包含一个不同的字符。 
- 每个字符都是唯一的字符串，例如`"abcd"`，需要小心处理，因为不同的计数变化很快。 
- 开头或结尾附近的分割必须仍保留非空子字符串。 

该问题仅保证小写英文字母，这意味着如果需要，我们可以使用大小为 26 的紧凑频率数组，而不是更大的哈希结构。 

## 方法

 ### 蛮力方法

 最直接的解决办法就是尝试每一个可能的分割位置。 

对于每个分割：

 1. 构建左子串。 
2. 构建正确的子串。 
3. 计算每个子字符串中不同字符的数量。 
4. 比较计数。 
5. 如果相等，则增加答案。 

为了计算不同的字符，我们可以使用一个集合。 

例如：```
left_distinct = len(set(s[:i]))
right_distinct = len(set(s[i:]))
```这是正确的，因为集合会自动删除重复项，从而为我们提供唯一字符的数量。 

然而，这种方法效率低下。 有`O(n)`分割位置，每个分割可能需要扫描最多`O(n)`用于构建集合的字符。 总复杂度变为`O(n^2)`。 

和`n = 10^5`，二次解太慢了。 

### 关键见解

 重要的观察结果是，当我们将分割点从左向右移动时，不同字符数会逐渐变化。 

我们可以维护：

 - 左侧的不同字符数
 - 右侧的不同字符数

 我们在动态更新这些计数的同时处理一次字符串。 

策略是：

 - 最初，所有字符都属于右侧。 
- 当我们从左向右移动时，字符会从右侧转移到左侧。 
- 我们跟踪双方的字符频率。 
- 每当不同计数变得相等时，我们就找到了一个很好的分割。 

这将问题转化为线性时间解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 重新计算每个分割的不同计数 |
 | 最佳 | O(n) | O(1) | O(1) | 使用频率数组维持滚动不同计数 |

 ## 算法演练

 1. 创建右侧的频率数组。 

最初，整个字符串属于右子字符串。 我们计算字符串中每个字符的出现频率。 

我们还计算当前出现在右侧的不同字符的数量。 
2. 为左侧创建一个空频率数组。 

开始时，左子串不包含任何字符，因此所有频率均为零，并且非重复计数为零。 
3. 从左到右迭代字符串，在最后一个字符之前停止。 

我们在最后一个字符之前停止，因为两个子字符串必须保持非空。 
4. 将当前字符从右向左移动。 

对于每个字符：

 - 增加左侧频率数组中的计数。 
- 减少其在正确频率数组中的计数。 
5. 仔细更新非重复计数。 

对于左侧：

 - 如果字符数变为`1`，这个角色第一次出现在左边。 
- 增加左侧不同计数。 

对于右侧：

 - 如果字符数变为`0`，右侧不再存在该角色。 
- 减少正确的非重复计数。 
6. 比较不同的计数。 

如果两侧不同字符的数量相等，则增加答案。 
7. 继续，直到处理完所有有效的分割位置。 

### 为什么它有效

 在每次迭代中，算法都会保持一个不变量：

 - 左侧频率数组准确表示左侧子字符串中的字符。 
- 右侧频率数组准确表示右侧子字符串中的字符。 
- 不同的计数器始终等于其各自子字符串中的唯一字符的数量。 

因为每个分割位置都被精确处理一次并且数据结构被正确更新，所以每个好的分割都被精确地计数一次。 

## Python 解决方案```python
class Solution:
    def numSplits(self, s: str) -> int:
        right_freq = [0] * 26
        
        for ch in s:
            right_freq[ord(ch) - ord('a')] += 1
        
        right_distinct = 0
        
        for count in right_freq:
            if count > 0:
                right_distinct += 1
        
        left_freq = [0] * 26
        left_distinct = 0
        good_splits = 0
        
        for i in range(len(s) - 1):
            index = ord(s[i]) - ord('a')
            
            left_freq[index] += 1
            if left_freq[index] == 1:
                left_distinct += 1
            
            right_freq[index] -= 1
            if right_freq[index] == 0:
                right_distinct -= 1
            
            if left_distinct == right_distinct:
                good_splits += 1
        
        return good_splits
```该实现首先计算整个字符串中每个字符的频率。 由于整个字符串最初属于右侧子字符串，因此这些计数将填充`right_freq`大批。 

接下来，我们计算`right_distinct`，它跟踪右侧当前存在多少个独特字符。 

左边开始是空的，所以`left_freq`包含全零并且`left_distinct`从零开始。 

循环处理每个可能的分割位置。 每走一步，就有一个角色从右向左移动。 该算法仅在必要时更新两个频率阵列并调整不同的计数器。 

关键的优化是不同计数是增量更新的，而不是从头开始重新计算。 

最后，每当左右不同计数匹配时，该分割就被视为良好。 

## 解决方案```go
func numSplits(s string) int {
    rightFreq := make([]int, 26)

    for _, ch := range s {
        rightFreq[ch-'a']++
    }

    rightDistinct := 0

    for _, count := range rightFreq {
        if count > 0 {
            rightDistinct++
        }
    }

    leftFreq := make([]int, 26)
    leftDistinct := 0
    goodSplits := 0

    for i := 0; i < len(s)-1; i++ {
        index := s[i] - 'a'

        leftFreq[index]++
        if leftFreq[index] == 1 {
            leftDistinct++
        }

        rightFreq[index]--
        if rightFreq[index] == 0 {
            rightDistinct--
        }

        if leftDistinct == rightDistinct {
            goodSplits++
        }
    }

    return goodSplits
}
```Go 的实现与 Python 解决方案非常相似。 

Go 使用长度为 26 的整数切片来存储字符频率，而不是 Python 列表。 

字符索引是使用字节算术执行的：```go
index := s[i] - 'a'
```由于输入仅包含小写英文字母，因此字节索引安全且高效。 

Go 在这里不需要对整数溢出进行特殊处理，因为所有计数都保持在字符串长度的范围内。

 ## 边缘情况

 一个重要的边缘情况是长度为 1 的字符串，例如`"a"`。 由于有效的分割需要两个非空子字符串，因此不存在合法的分割位置。 粗心的实现可能会意外地处理无效的分割或产生索引错误。 该实现通过仅迭代最多来避免这种情况`len(s) - 1`。 

另一个重要的情况是所有字符都相同，例如`"aaaaaa"`。 在这种情况下，无论分割发生在何处，双方始终只包含一个不同的字符。 某些实现会错误地多计数或少计数，因为当计数保持正值时，它们会错误地处理频率更新。 仅当频率超过阈值时，该解决方案才能正确更新不同计数`0 -> 1`或者`1 -> 0`。 

当所有字符都不同时，就会出现第三种棘手的情况，例如`"abcdef"`。 左边不同字符的数量每一步都会增加，而右边的字符数量每一步都会减少。 相差一的错误在这里很常见，因为分割位置必须使两边都非空。 该实现通过在最终字符之前停止来正确处理此问题。 

另一个微妙的边缘情况涉及重复的转换，例如`"abcabc"`。 字符重复出现在分割的两侧。 幼稚的实现可能会过早错误地减少不同计数。 通过使用精确的频率跟踪，该算法仅在字符从一侧完全消失时减少不同计数。
