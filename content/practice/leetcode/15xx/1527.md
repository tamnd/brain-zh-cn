[LeetCode 问题 1527](https://leetcode.com/problems/ Patients-with-a-condition/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题要求我们查询数据库表`Patients`并返回 I 型糖尿病患者的记录。 每个患者记录包括`patient_id`,`patient_name`，和一个`conditions`柱子。 这`conditions`列可以包含零个或多个由空格分隔的条件代码。 如果**任何病情代码以前缀开头，则患者患有 I 型糖尿病`DIAB1`**。 

简单来说，任务是扫描每个患者的`conditions`字符串，检查是否至少有一个单词以`DIAB1`，如果是，则将该患者包含在输出中。 输出应包含与输入表相同的列，并且可以按任何顺序返回。 

重要的限制包括`patient_id`是独一无二的并且`conditions`可能为空。 要考虑的边缘情况包括没有任何病症的患者、其病症包含类似前缀的患者，例如`DIAB2`，以及单个字符串中的多个条件。 

## 方法

 蛮力方法将涉及分割每个患者的`conditions`字符串成单个单词并检查每个单词以查看它是否以`DIAB1`。 虽然简单，但这需要扫描每个患者的每个单词，并且如果数据集很大，效率可能会很低。 

最佳方法是利用 SQL 字符串函数。 具体来说，使用`LIKE`使用通配符可以让我们检测是否`DIAB1`出现在字符串中单词的开头。 通过在条件字符串之前和之后包含空格（或单独处理边缘位置），我们可以安全地匹配`DIAB1`在任何单词的开头，无需手动拆分字符串。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * m) | O(1) | O(1) | 单独扫描每位患者和每个病情词 |
 | 最佳 | O(n) | O(1) | O(1) | 使用 SQL 模式匹配 LIKE 来查找`DIAB1`前缀代码 |

 ## 算法演练

 1. 选择列`patient_id`,`patient_name`， 和`conditions`从`Patients`桌子。 
2.使用SQL`WHERE`子句仅过滤包含以下内容的行`DIAB1`在单词的开头`conditions`。 
3. 确保我们匹配`DIAB1`在字边界处，我们可以在条件字符串前面/追加一个空格，或者使用带有通配符和空格字符的 SQL 模式。 
4. 返回过滤后的行。 

为什么有效：每一位患者`conditions`包括一个以以下开头的单词`DIAB1`将满足`LIKE`条件，因此查询正确捕获所有 I 型糖尿病患者。 没有任何匹配代码的患者将被自动排除。 

## Python 解决方案```python
# Python solution using SQL execution context
import sqlite3
from typing import List, Tuple

def patients_with_diabetes(conn: sqlite3.Connection) -> List[Tuple[int, str, str]]:
    query = """
    SELECT patient_id, patient_name, conditions
    FROM Patients
    WHERE ' ' || conditions || ' ' LIKE '% DIAB1%' 
    """
    cursor = conn.cursor()
    cursor.execute(query)
    return cursor.fetchall()
```说明：我们在前面和后面添加一个空格`conditions`以便处理字符串开头或结尾的匹配。 这`LIKE '% DIAB1%'`确保`DIAB1`位于单词的开头。 该函数执行查询并返回所有匹配的行。 

## 解决方案```go
package main

import (
    "database/sql"
    _ "github.com/mattn/go-sqlite3"
)

func PatientsWithDiabetes(db *sql.DB) ([][3]string, error) {
    query := `
        SELECT patient_id, patient_name, conditions
        FROM Patients
        WHERE ' ' || conditions || ' ' LIKE '% DIAB1%'
    `
    rows, err := db.Query(query)
    if err != nil {
        return nil, err
    }
    defer rows.Close()

    var result [][3]string
    for rows.Next() {
        var id int
        var name, cond string
        if err := rows.Scan(&id, &name, &cond); err != nil {
            return nil, err
        }
        result = append(result, [3]string{string(rune(id)), name, cond})
    }
    return result, nil
}
```说明：Go 使用相同的 SQL 逻辑。 我们使用`db.Query`要执行查询，请迭代行，将值扫描到变量中，并将它们附加到结果切片中。 整数 ID 被转换为字符串，以便在切片中进行统一的输出处理。 

## 工作示例

 输入示例：```
+------------+--------------+--------------+
| patient_id | patient_name | conditions   |
+------------+--------------+--------------+
| 1          | Daniel       | YFEV COUGH   |
| 2          | Alice        |              |
| 3          | Bob          | DIAB100 MYOP |
| 4          | George       | ACNE DIAB100 |
| 5          | Alain        | DIAB201      |
+------------+--------------+--------------+
```步骤1：检查每个患者的病情字符串：

 - 丹尼尔：`YFEV COUGH`→ 没有单词开头`DIAB1`→ 排除。 
- 爱丽丝：``→空→排除。 
- 鲍勃：`DIAB100 MYOP`→`DIAB100`开始于`DIAB1`→ 包括。 
- 乔治：`ACNE DIAB100`→`DIAB100`开始于`DIAB1`→ 包括。 
- 阿兰：`DIAB201`→ 开始于`DIAB2`→ 排除。 

输出：```
+------------+--------------+--------------+
| patient_id | patient_name | conditions   |
+------------+--------------+--------------+
| 3          | Bob          | DIAB100 MYOP |
| 4          | George       | ACNE DIAB100 | 
+------------+--------------+--------------+
```## 复杂度分析

 ## 边缘情况

 一个边缘情况是空的`conditions`柱子。 如果不小心处理，`LIKE`查询可能会失败或包含不需要的行。 前置和附加空格可确保空字符串不匹配`DIAB1`。 

另一个边缘情况是条件代码，例如`DIAB12XYZ`相对`DIAB2`。 该算法仅正确匹配以以下开头的代码`DIAB1`因为`LIKE '% DIAB1%'`在单词边界强制使用前缀。 

第三种边缘情况是一个字符串中有多个条件，例如，`ACNE DIAB100 MYOP`。 算法正确识别`DIAB100`其中包括患者，展示了针对多词条件的鲁棒性。
