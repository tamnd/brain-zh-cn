[LeetCode 问题 1541](https://leetcode.com/problems/minimum-insertions-to-balance-a-parentheses-string/)

 **难度：** 🟡 中等
 **主题：** 字符串、堆栈、贪婪

 ## 解决方案

 ## 问题理解

 这个问题要求我们使用最少的插入次数将括号字符串转换为一种特殊的平衡括号字符串。 

与标准括号平衡问题不同，该问题对平衡的定义不同。 每个左括号`'('`必须与两个连续的右括号精确匹配`'))'`。 

这意味着：

 - 一个`'('`需要两个`')'`- 两个右括号必须连续出现
 - 左括号必须出现在其匹配之前`'))'`例如：

-`"())"`是平衡的，因为`'('`与`'))'`-`"(())))"`是平衡的，因为两者`'('`字符正确匹配
 -`"(()))"`不平衡，因为第一个`'('`只有一个`')'`与它配对

 输入是一个字符串`s`只含有`'('`和`')'`。 我们可以在字符串中的任何位置插入额外的括号。 目标是根据上述特殊规则计算使字符串平衡所需的最小插入次数。 

约束条件很重要：

 -`1 <= s.length <= 10^5`- 仅有的`'('`和`')'`出现

 由于输入大小可能高达十万个字符，因此任何比线性时间更差的算法都可能太慢。 这立即排除了昂贵的递归或强力搜索解决方案。 

一些边缘情况尤其重要：

 - 以以下开头的字符串`')'`- 具有奇数个连续的字符串`')'`- 以不匹配结尾的字符串`'('`- 字符串在哪里`')'`字符不成对出现
 - 完全不平衡的琴弦，例如`"))))"`或者`"(((("`幼稚的实现很容易错误地处理单个`')'`出现而不是必需的`'))'`。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试生成所有可能的有效插入组合并检查生成的字符串是否变得平衡。 

一种可能的策略是：

 - 在每个位置，尝试插入`'('`或者`')'`- 递归地继续构建修改后的字符串
 - 验证最终字符串是否满足平衡规则
 - 跟踪所有有效结构中的最小插入次数

 这是有效的，因为它最终会探索每一种可能的插入排列，保证找到最佳答案。 

然而，这种方法是完全不切实际的。 可能的插入组合的数量随着字符串长度呈指数增长。 即使很小的输入也会产生巨大的搜索空间。 

此外，重复验证余额会进一步增加开销。 

输入尺寸高达`10^5`，暴力是不可能的。 

### 最优贪心法

 关键的见解是我们实际上不需要构建最终的平衡字符串。 我们只需要计算需要插入多少次即可。 

我们可以在跟踪时从左到右处理字符串：

 - 还需要多少个右括号
 - 已经进行了多少次插入

 每个`'('`正好需要两个`')'`，所以每次我们遇到`'('`，我们将所需的右括号数量增加`2`。 

当我们遇到`')'`，我们将所需的结束计数减少`1`。 

棘手的部分是右括号必须成对出现。 如果我们需要奇数个右括号，那就意味着单个`')'`缺少它的伙伴。 在这种情况下，我们插入一个`')'`立即地。 

同样，如果我们遇到一个`')'`当没有左括号可用时，我们必须插入一个`'('`。 

这种贪婪策略之所以有效，是因为每次修正都是在尽可能早的时刻进行的，从而防止未来的不一致变得更大。

 | 最优贪心 | O(n) | O(1) | O(1) | 扫描时跟踪所需的右括号 |

 ## 算法演练

 1.初始化两个变量：

 -`insertions`，它计算我们插入的字符数
 -`needed`，它跟踪仍需要多少个右括号
 2. 从左到右逐个字符地遍历字符串。 
3. 如果当前字符是`'('`：

 - 这个左括号需要两个右括号
 - 增加`needed`经过`2`4.增加后`needed`，检查是否`needed`很奇怪。 

- 平衡结构需要右括号成对出现
 - 如果`needed`变得奇数，意味着无与伦比`')'`已经存在
 - 插入一个`')'`- 增量`insertions`- 减少`needed`经过`1`5. 如果当前字符是`')'`：

- 减少`needed`经过`1`因为已经提供了一个必需的右括号
 6. 如果`needed`变为负数：

 - 这意味着我们遇到了一个右括号而没有匹配的左括号
 - 插入一个`'('`- 增量`insertions`- 放`needed`到`1`- 我们将其设置为`1`因为插入的`'('`需要两个`')'`，并且其中一个已经被当前角色消耗掉
 7. 继续处理，直到扫描完整个字符串。 
8. 遍历结束后：

 - 一些左括号可能仍然无法匹配
 - 变量`needed`准确地告诉我们有多少`')'`仍必须插入
 - 返回`insertions + needed`### 为什么它有效

 该算法保持一个不变量`needed`始终表示完成有效平衡结构所需的右​​括号的确切数量。 

每当结构变得无效时：

 - 一个奇怪的`needed`值表示不完整`'))'`一对
 - 阴性`needed`值表示缺失`'('`该算法立即以尽可能少的插入修复每个违规。 由于每次修正都是局部最优且不可避免的，因此插入的总数是全局最小的。 

## Python 解决方案```python
class Solution:
    def minInsertions(self, s: str) -> int:
        insertions = 0
        needed = 0

        for char in s:
            if char == '(':
                needed += 2

                if needed % 2 == 1:
                    insertions += 1
                    needed -= 1
            else:
                needed -= 1

                if needed < 0:
                    insertions += 1
                    needed = 1

        return insertions + needed
```其实现直接遵循前面描述的贪心算法。 

变量`insertions`存储我们在处理过程中人为添加的字符数。 

变量`needed`跟踪仍需要多少个右括号。 

当遇到`'('`，我们增加`needed`经过`2`因为每个左括号都需要两个右括号。 

如果`needed`两个相加后变为奇数，表示当前有一个悬空单`')'`某处。 我们立即插入一个额外的`')'`来完成这对。 

加工时`')'`，我们减少`needed`因为现在出现了一个必需的右括号。 

如果`needed`变为负数，没有匹配`'('`。 我们插入一个`'('`并重置`needed`到`1`。 

最后，处理整个字符串后，剩余的`needed`value 表示不匹配的所需右括号，因此我们将其直接添加到答案中。 

## 解决方案```go
func minInsertions(s string) int {
    insertions := 0
    needed := 0

    for _, char := range s {
        if char == '(' {
            needed += 2

            if needed%2 == 1 {
                insertions++
                needed--
            }
        } else {
            needed--

            if needed < 0 {
                insertions++
                needed = 1
            }
        }
    }

    return insertions + needed
}
```Go 实现几乎完全反映了 Python 逻辑。 

一个区别是 Go 使用以下方式迭代字符`range`，这会产生`rune`价值观。 由于输入仅包含 ASCII 括号，因此直接与`'('`和`')'`正常工作。 

不需要特殊的溢出处理，因为最大插入次数与输入长度成正比，很容易符合 Go 的整数范围。

 ## 边缘情况

 当字符串开头时会出现一种重要的边缘情况`')'`。 由于每个关闭序列必须对应于前一个`'('`, 领先的`')'`立即无效。 有缺陷的实现可能会错误地将计数器递减为负值而不修复结构。 此实现检测`needed < 0`并插入一个匹配的`'('`立即地。 

另一个棘手的情况发生在单个`')'`出现时没有其伙伴。 由于每次关闭都必须是连续的一部分`'))'`，所需右括号的奇数个表示不完整的一对。 该实现通过检查是否`needed`处理后变成奇数`'('`，然后插入一个`')'`立即地。 

最后一个重要的边缘情况是无与伦比的`'('`。 例如，`"((("`需要六个右括号。 一些实现错误地假设遍历结束时的平衡。 该解决方案正确地保留了剩余所需的计数`needed`并将其添加到最终答案中。 

一个微妙的边缘情况是空字符串。 虽然官方限制是从长度开始的`1`，健壮的实现仍应正确处理空输入。 由于循环永远不会执行，因此两个计数器都保持为零并且该方法正确返回`0`。
