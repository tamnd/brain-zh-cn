[LeetCode 问题 1545](https://leetcode.com/problems/find-kth-bit-in-nth-binary-string/)

 **难度：** 🟡 中等
 **主题：** 字符串、递归、模拟

 ## 解决方案

 ## 问题理解

 该问题定义了一个递归构造的二进制字符串序列：

 -`S1 = "0"`-`Si = Si-1 + "1" + reverse(invert(Si-1))`对于每个新级别，我们采用前一个字符串，追加`"1"`，然后附加前一个字符串的反转和位反转版本。 

任务是返回`kth`字符串中的位`Sn`。 

为了清楚地理解其构造，请考虑序列如何增长：

 -`S1 = "0"`-`S2 = "011"`-`S3 = "0111001"`-`S4 = "011100110110001"`每个字符串的大小大约加倍，再加上一个额外的字符。 更具体地说：$$|S_n| = 2^n - 1$$输入包括：

 -`n`，它决定了我们正在使用哪个递归字符串
 -`k`，它指定我们需要返回的位的 1 索引位置

 输出是单个字符，或者`"0"`或者`"1"`。 

约束足够小，甚至生成完整的字符串在技术上也是可能的：$$1 \le n \le 20$$最大长度为：$$2^{20} - 1 \approx 10^6$$所以暴力破解是可行的，但问题是为了测试递归结构的识别而不是简单的模拟。 

一些边缘情况很重要：

 - 当`n = 1`，该字符串仅包含一个字符。 
- 什么时候`k`正好指向中间的字符，答案总是`"1"`为了`n > 1`。 
- 什么时候`k`位于镜像的后半部分，我们必须小心地反转索引并反转结果位。 
- 由于索引是从 1 开始的，因此相差一错误很常见。 

## 方法

 ### 暴力构建

 最直接的方法是显式构建每个字符串`S1`最多`Sn`。 

对于每次迭代：

 1. 取出前一个字符串。 
2. 反转每一位。 
3. 将倒置的字符串反转。 
4. 连接：

 - 原始字符串
 -`"1"`- 反转的倒置字符串

 施工后`Sn`, 返回索引处的字符`k - 1`。 

这是有效的，因为它遵循问题陈述中的精确递归定义。 

然而，这种方法会重复复制字符串并执行反转。 虽然对于给定的约束仍然可以接受，但它不是最优雅的解决方案，并且使用了不必要的内存。 

### 递归观察

 关键的见解是我们永远不需要构造整个字符串。 

每个字符串都有以下结构：$$S_n = S_{n-1} + "1" + reverse(invert(S_{n-1}))$$中间位置始终是：$$mid = 2^{n-1}$$这给出了三种情况：

 1.如果`k == mid`，答案是`"1"`。 
2.如果`k < mid`，答案与`kth`一点`S(n-1)`。 
3.如果`k > mid`，答案来自于反转的倒半部分的镜像位置。 

镜像索引为：$$mirrored = length - k + 1$$由于后半部分被反转，我们递归地计算镜像位并翻转它。 

这将问题简化为递归分而治之，而无需构造字符串。

 | 蛮力 | O(2^n) | O(2^n) | O(2^n) | O(2^n) | 显式构造完整字符串 |
 | 最佳 | O(n) | O(n) | 使用递归结构和镜像索引 |

 ## 算法演练

 1. 计算总长度`Sn`。 

长度为`Sn`是：$$2^n - 1$$这使我们能够确定中间位置。 
2. 找到中间索引。 

中间的字符始终位于：$$mid = \frac{length + 1}{2}$$这个位置总是包含`"1"`。 
3. 检查是否`k`是中间位置。 

如果`k == mid`，立即返回`"1"`。 
4. 处理左半部分。 

如果`k < mid`，请求的位完全位于内部`S(n-1)`。 

所以：$$findKthBit(n, k) = findKthBit(n-1, k)$$5. 处理右半部分。 

如果`k > mid`，该位属于：$$reverse(invert(S_{n-1}))$$因为字符串被反转，所以我们将索引映射回原来的左半部分。 

镜像位置为：$$mirrored = length - k + 1$$6. 递归计算镜像位。 

右半部分被反转，因此在计算镜像位后我们将其翻转：

 -`"0"`变成`"1"`-`"1"`变成`"0"`7. 继续递归直到到达基本情况。 

最小的字符串是：$$S_1 = "0"$$所以当`n == 1`， 返回`"0"`。 

### 为什么它有效

 递归结构`Sn`保证每个位置属于：

 - 左边的副本`S(n-1)`- 中间`"1"`- 的反向反转副本`S(n-1)`The mirrored index transformation correctly maps positions from the reversed second half back into the original first half. Since the second half is also inverted, flipping the recursively computed bit produces the correct answer.

 ## Python 解决方案```python
class Solution:
    def findKthBit(self, n: int, k: int) -> str:
        if n == 1:
            return "0"

        length = (1 << n) - 1
        mid = (length + 1) // 2

        if k == mid:
            return "1"

        if k < mid:
            return self.findKthBit(n - 1, k)

        mirrored_index = length - k + 1
        bit = self.findKthBit(n - 1, mirrored_index)

        return "1" if bit == "0" else "0"
```该实现直接遵循算法讨论中的递归观察。 

底壳手柄`S1`，其中仅包含`"0"`。 

表达式：```python
(1 << n) - 1
```使用位移位有效地计算长度。 

确定了中间位置，以便我们可以将字符串分成三个结构区域。 

如果`k`位于左半部分，递归继续不变。 

如果`k`位于右半部分，代码计算镜像索引：```python
mirrored_index = length - k + 1
```这会将反转的部分映射回原来的左半部分。 递归找到镜像位后，代码在返回之前将其反转。 

因为每次递归调用都会减少`n`如果增加 1，递归深度最多为 20。 

## 解决方案```go
func findKthBit(n int, k int) byte {
	if n == 1 {
		return '0'
	}

	length := (1 << n) - 1
	mid := (length + 1) / 2

	if k == mid {
		return '1'
	}

	if k < mid {
		return findKthBit(n-1, k)
	}

	mirroredIndex := length - k + 1
	bit := findKthBit(n-1, mirroredIndex)

	if bit == '0' {
		return '1'
	}

	return '0'
}
```Go 实现几乎完全反映了 Python 逻辑。 

主要区别在于 Go 返回一个`byte`而不是字符串字符。 因此，该函数使用字符文字，例如`'0'`和`'1'`。 

在 Go 中，位移位自然地适用于整数：```go
(1 << n) - 1
```自从`n <= 20`，整数溢出从来都不是问题。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`n = 1`。 在这种情况下，整个递归结构消失，因为字符串只是`"0"`。 递归实现可能会意外地递归到下面`n = 1`如果基本情况没有正确处理。 该实现显式检查`n == 1`首先并立即返回`"0"`。 

另一个重要的情况发生在`k`等于精确的中间位置。 每个生成的字符串都有一个中心`"1"`施工时插入。 如果在递归之前没有处理这种情况，算法可能会错误地递归到其中的一半并产生错误的答案。 该实现计算中间索引并返回`"1"`立即当`k == mid`。 

第三种微妙的边缘情况发生在`k`在于逆转的下半场。 由于该区域既是反向的又是反向的，因此在计算镜像索引时，实现经常会出现相差一的错误。 公式：$$mirrored = length - k + 1$$使用基于 1 的索引正确地将位置从右半部分映射回左半部分。 递归后，该位恰好反转一次，从而保留了正确性。 

最后的边缘情况涉及非常大的`n`， 例如`n = 20`。 构造完整的字符串在技术上仍然是可行的，但递归解决方案必须确保递归深度仍然是可管理的。 由于该算法每一级只进行一次递归调用，因此最大递归深度仅为 20，这在 Python 和 Go 中都是完全安全的。
