[LeetCode 问题 1566](https://leetcode.com/problems/detect-pattern-of-length-m-repeated-k-or-more-times/)

 **难度：** 🟢简单
 **主题：** 数组、枚举

 ## 解决方案

 ## 问题理解

 问题给了我们一个整数数组`arr`和两个整数，`m`和`k`。 我们需要判断是否存在长度为连续的子数组`m`至少连续重复`k`次。 

仅当满足以下条件时，模式才被视为有效：

 - 重复的片段是连续的
 - 每个重复段都有精确的长度`m`- 重复不会错误地重叠
 - 图案至少出现`k`连续几次

 例如，如果`m = 2`模式是`[1, 2]`，然后有效重复`k = 3`看起来像：```
[1,2][1,2][1,2]
```对应于：```
[1,2,1,2,1,2]
```问题要求我们返回`true`如果数组中的任何位置存在这样的重复模式，否则返回`false`。 

限制非常小：

 -`arr.length <= 100`-`m <= 100`-`k <= 100`由于数组尺寸很小，因此即使效率较低的解决方案也可以通过。 然而，我们仍然想编写一个干净且最佳的解决方案。 

一个重要的观察是重复序列必须恰好占据`m * k`连续职位。 如果起始位置没有足够的剩余元素，我们可以提前停止检查。 

有几种边缘情况需要记住：

 - 模式长度为的数组`1`- 整个数组都是一个重复值的情况
 - 重复几乎有效但接近结束时中断的情况
 - 情况`m * k > len(arr)`，这使得有效模式不可能立即出现
 - 看起来重叠的模式实际上并不是连续的重复

 ## 方法

 ### 蛮力方法

 暴力解决方案会尝试数组中每个可能的起始索引。 对于每个起始索引，它提取长度的候选模式`m`，然后检查下一个是否`k - 1`长度段`m`与该模式相同。 

例如：```
arr = [1,2,1,2,1,2]
m = 2
k = 3
```从索引开始`0`，候选模式为：```
[1,2]
```然后我们比较：```
arr[2:4] == [1,2]
arr[4:6] == [1,2]
```如果所有比较都匹配，我们返回`true`。 

这种方法是正确的，因为它明确验证了每个可能的重复模式。 但是，它会重复比较整个子数组，这会带来不必要的工作。 

### 最佳方法

 关键的观察是连续重复的长度块`m`意味着：```
arr[i] == arr[i + m]
```对于重复结构内的每个匹配位置。 

我们可以直接比较元素，而不是重复地切片和比较整个子数组。 

我们扫描数组并计算有多少个连续位置满足：```
arr[i] == arr[i + m]
```每一次成功的比较都意味着该模式会继续出现一个匹配元素。 

如果我们积累`m * (k - 1)`连续成功匹配，那么我们就找到了长度的模式`m`重复`k`次。 

这是有效的，因为：

 - 重复的大小块`m`- 重复`k`次
 - 准确要求`m * (k - 1)`匹配偏移比较

 该解决方案更简单、更高效。

 ## 算法演练

 ### 最优算法

 1. 初始化一个名为`matched`到`0`。 

该计数器跟踪有多少个连续位置满足：```
arr[i] == arr[i + m]
```2. 从索引处迭代数组`0`到`len(arr) - m - 1`。 

我们停在`len(arr) - m - 1`因为我们比较`arr[i]`和`arr[i + m]`。 
3. 对于每个索引`i`， 比较：```
arr[i] == arr[i + m]
```4. 如果值匹配：

 - 增量`matched`经过`1`- 这意味着重复的模式继续
 5. 如果值不匹配：

 - 重置`matched`到`0`- 连续重复已被打破
 6.更新后`matched`，检查是否：```
matched == m * (k - 1)
```如果为真，我们已经找到足够的连续匹配位置来确认重复的模式`k`次。 
7. 返回`true`如果发现这种模式，请立即。 
8. 如果循环未成功完成，则返回`false`。 

### 为什么它有效

 如果一个图案的长度`m`连续重复`k`次，那么一个块中的每个元素必须等于下一个块中的相应元素。 

这意味着：```
arr[i] == arr[i + m]
```必须适用于重复区域内的所有位置。 

总共有`k`重复的块精确地创建`m * (k - 1)`需要进行匹配比较。 因此，一旦我们观察到许多连续的匹配，我们就知道存在有效的重复模式。 

## Python 解决方案```python
from typing import List

class Solution:
    def containsPattern(self, arr: List[int], m: int, k: int) -> bool:
        matched = 0

        for i in range(len(arr) - m):
            if arr[i] == arr[i + m]:
                matched += 1
            else:
                matched = 0

            if matched == m * (k - 1):
                return True

        return False
```实现直接遵循最优算法。 

变量`matched`存储到目前为止我们已经看到的连续偏移匹配数。 每次成功的比较`arr[i]`和`arr[i + m]`表示重复的结构又继续了一步。 

当发生不匹配时，重复链就会被破坏，所以我们重置`matched`回到`0`。 

条件：```python
matched == m * (k - 1)
```检测我们何时积累了足够的连续匹配以保证有效的重复模式。 

该解决方案使用恒定的额外内存，并且仅扫描数组一次。 

## 解决方案```go
func containsPattern(arr []int, m int, k int) bool {
    matched := 0

    for i := 0; i < len(arr)-m; i++ {
        if arr[i] == arr[i+m] {
            matched++
        } else {
            matched = 0
        }

        if matched == m*(k-1) {
            return true
        }
    }

    return false
}
```Go 实现密切反映了 Python 逻辑。 

Go 切片已经提供了高效的索引访问，因此不需要额外的数据结构。 整数溢出不是问题，因为所有约束都非常小。 

算法保持不变`matched`计数器并执行相同的偏移比较策略。

 ## 边缘情况

 ### Pattern Length Equals 1

 当`m = 1`，问题简化为检查相同的值是否至少连续出现`k`次。 

例如：```
[4,4,4,4]
```和`k = 3`。 

有缺陷的实现可能会使这种情况变得过于复杂或错误地处理计数。 我们的解决方案自然可以处理它，因为比较变成：```
arr[i] == arr[i + 1]
```它正确跟踪连续的相等值。 

### 数组太短而无法重复

 如果：```
m * k > len(arr)
```那么就不可能存在有效的重复模式。 

例如：```
arr = [1,2]
m = 2
k = 2
```我们总共需要四个元素，但只有两个。 

我们的实现会自动处理这个问题，因为永远无法达到所需的连续匹配数。 

### 部分比赛迟到

 考虑：```
[1,2,1,2,1,3]
```和：```
m = 2
k = 3
```该序列看起来接近有效，因为前两次重复匹配。 然而，最后一个元素打破了这种模式。 

幼稚的实现可能会在观察到一些重复后错误地提前停止。 我们的解决方案正确地要求：```
m * (k - 1)
```返回前连续比赛`true`。 

### 重叠但无效的模式

 考虑：```
[1,1,1]
m = 2
k = 2
```尽管值重复，但长度为 2 的模式不存在有效的非重叠重复。 

所需的结构需要：```
[1,1][1,1]
```这需要四个要素。 

我们的实现正确地避免了误报，因为永远无法实现必要数量的偏移匹配。
