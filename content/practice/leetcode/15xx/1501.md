 ## 解决方案

 ## 问题理解

 这是一个 SQL 数据库问题，我们需要识别**平均通话时长严格大于全球平均通话时长**的国家/地区。 

该数据库由三个表组成：

 - 的`Person`表存储有关人员的信息，包括他们的独特信息`id`和`phone_number`。 
- 这`Country`表映射a`country_code`到一个国家名称。 
- 这`Calls`表存储电话呼叫，其中每行包含呼叫者、被呼叫者和呼叫持续时间。 

问题的棘手部分是了解**一次通话如何对一个国家的统计数据做出贡献**。 

如果**呼叫者或被呼叫者来自某个国家/地区**，则该呼叫就属于该国家/地区。 换句话说，每次通话都会影响两个参与国家的平均持续时间。 例如，如果摩洛哥用户呼叫以色列用户，则该时长为摩洛哥贡献一次，为以色列贡献一次。 

电话号码格式为我们提供了国家/地区代码：```
xxx-yyyyyyy
```前三位数字（`xxx`) 代表国家代码。 我们必须将此前缀与`Country.country_code`确定一个人的国家。 

预期输出是一个包含一列的表：```
country
```此列应包括平均通话时长**严格大于**所有通话的全球平均时长**的每个国家/地区。 

一个重要的细节是，全局平均值是根据系统中的所有通话记录计算得出的。`Calls`表，而每个国家/地区的平均值包括涉及该国家/地区人员的每个呼叫。 

因为这是一个数据库问题，所以真正的挑战是用 SQL 清晰地表达逻辑，而不是针对大型算法约束进行优化。 我们希望避免不必要的复杂连接，而是构建查询，以便国家/地区级别的聚合变得简单。 

一些边缘情况很重要：

 - 一个国家可能根本没有电话。 这些国家不应该出现，因为没有国家平均水平可供比较。 
- 多个人可能属于同一个国家，他们的通话必须全部汇总在一起。 
- 重复的行可以存在于`Calls`，这意味着我们必须独立处理每一行而不是重复数据删除。 
- 通话计入双方参与者的国家/地区，因此我们不能只考虑呼叫方或被叫方。 

## 方法

 ### 蛮力方法

 强力解决方案将手动确定每个人的国家/地区，然后迭代所有呼叫。 对于每次通话，我们都会识别两个参与者所在的国家/地区，将持续时间附加到每个国家/地区的集合中，然后计算平均值。 

从概念上讲，该过程将如下所示：

 1. 从每个人的电话号码中提取其国家/地区代码。 
2. 将代码与`Country`桌子。 
3. 迭代每个调用。 
4. 将通话时长添加到呼叫者和被呼叫者的国家/地区。 
5. 计算每个国家的平均值。 
6. 将每个国家的平均值与全球平均值进行比较。 

这种方法是正确的，因为每个呼叫都会被处理一次，并为所有相关国家做出贡献。 然而，在 SQL 中按程序实现这一点会很尴尬且效率低下。 SQL 是为基于集合的聚合而设计的，因此无需手动模拟循环。 

### 最佳方法的关键见解

 关键的观察结果是**每个呼叫都应该代表两次**，一次代表呼叫者所在的国家/地区，一次代表被呼叫者所在的国家/地区。 

我们可以将数据转换成一个统一的表，而不是手动处理调用：```
(country, duration)
```我们可以通过以下方式做到这一点：

 - 加入`Calls.caller_id`和`Person.id`- 加入`Calls.callee_id`和`Person.id`- 提取电话号码的前三位数字以确定国家/地区
 - 使用以下方式结合调用者和被调用者的贡献`UNION ALL`一旦我们有了扁平化的数据集，计算国家/地区平均值就变得很简单`GROUP BY`。 

可以使用以下方法独立计算全局平均值：```
AVG(duration)
```然后我们简单地过滤掉平均水平超过全球平均水平的国家。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(P + C) | O(P + C) | 手动模拟映射和聚合 |
 | 最佳 | O(P + C) | O(C)| 高效使用 SQL 连接和聚合 |

 这里：

-`P`= 人数
 -`C`= 通话记录数

 ## 算法演练

 1. 首先，计算每个人到其国家/地区的映射。 

我们提取前三个字符`phone_number`使用`LEFT(phone_number, 3)`并将它们与`Country.country_code`。 
2. 接下来，创建扁平化呼叫数据集。 

对于每个呼叫，为呼叫者所在国家/地区创建一条记录，并为被呼叫者所在国家/地区创建一条记录。 这可确保参与通话的每个国家/地区都能在通话期间获得积分。 
3. 使用组合调用者和被调用者的贡献`UNION ALL`。 

我们使用`UNION ALL`而不是`UNION`因为必须保留重复的调用。 该问题明确指出可能存在重复行。 
4. 按国家/地区对扁平化数据集进行分组。 

计算：```
AVG(duration)
```对于每个国家。 
5. 计算全球平均值。 

这很简单：```sql
SELECT AVG(duration)
FROM Calls
```6. 过滤国家。 

仅保留符合以下条件的国家/地区：```
country_avg > global_avg
```7. 返回生成的国家/地区名称。 

### 为什么它有效

 该算法之所以有效，是因为每个参与国家/地区的每个呼叫都只计算一次。 通过将每次调用复制到调用者和被调用者的贡献中，我们确保国家/地区级别的平均值与问题定义相匹配。 由于全局平均值是直接根据原始调用表计算的，因此比较在数学上是准确的。

### MySQL解决方案```sql
SELECT
    country
FROM (
    SELECT
        c.name AS country,
        AVG(t.duration) AS avg_duration
    FROM (
        SELECT
            caller_id AS person_id,
            duration
        FROM Calls

        UNION ALL

        SELECT
            callee_id AS person_id,
            duration
        FROM Calls
    ) t
    JOIN Person p
        ON t.person_id = p.id
    JOIN Country c
        ON LEFT(p.phone_number, 3) = c.country_code
    GROUP BY c.name
) country_avg
WHERE avg_duration > (
    SELECT AVG(duration)
    FROM Calls
);
```查询首先将呼叫表展平为基于参与者的表示形式。 每个调用都表示两次，一次为调用者，一次为被调用者，使用`UNION ALL`。 

之后，我们将每个参与者与`Person`表获取电话号码并提取国家代码。 该国家/地区代码与`Country`桌子。 

一旦我们有`(country, duration)`对，按国家/地区分组使我们能够计算特定于国家/地区的平均通话时长。 

最后，子查询计算全球平均持续时间，并且我们过滤平均时间严格更长的国家/地区。

 ## 边缘情况

 ### 没有电话的国家

 一些国家在`Country`表可能永远不会参与任何调用。 一个简单的解决方案可能会意外地将它们包含在`NULL`平均或除以零。 我们的实现自然排除了它们，因为只有出现在加入的呼叫数据集中的国家/地区才会被分组。 

### 重复通话记录

 的`Calls`表可能包含重复的行。 使用`UNION`而不是`UNION ALL`会错误地删除重复项并扭曲平均值。 该实现明确使用`UNION ALL`，确保每一行独立贡献。 

### 同一国家/地区内的通话

 如果呼叫者和被呼叫者都属于同一国家/地区，则该国家/地区的持续时间必须计算两次，因为两个参与者都来自该国家/地区。 一个常见的错误是只计算一次。 由于我们分别扩展调用者和被调用者，因此查询正确地贡献了这两个条目。 

### 严格更大的比较

 该要求规定，国家平均水平必须**严格高于**全球平均水平。 使用`>=`会错误地包括平均数与全球平均数完全匹配的国家。 该实现正确地使用了`>`操作员。
