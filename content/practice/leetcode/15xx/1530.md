 # LeetCode 1530 - 良好叶节点对的数量

 ## 问题理解

 这个问题给了我们二叉树的根和一个整数`distance`。 我们需要计算有多少对叶子节点满足特定条件：两个叶子之间的最短路径必须小于或等于`distance`。 

叶节点是没有左子节点和右子节点的节点。 

树中两个节点之间的最短路径是沿着连接它们的唯一路径的边数。 由于树不包含循环，因此每对节点之间只有一条路径。 

例如，假设两个叶子共享同一个父代。 他们之间的路径是：

 - 从第一片叶子到父代
 - 然后向下到第二片叶子

 该路径长度是`2`。 

输入包括：

 -`root`，二叉树的根节点
 -`distance`, 两片叶子之间允许的最大距离

 输出是一个整数，表示良好叶子对的数量。 

约束条件很重要：

 - 树最多包含`2^10 = 1024`节点
 -`distance <= 10`较小的最大距离是实现有效解决方案的关键观察结果。 尽管树可能包含许多叶子，但我们只关心叶子距离`10`，这使我们能够在遍历过程中保持紧凑的距离信息。 

有几种边缘情况可能会导致简单实现中出现问题：

 - 只有一个节点的树没有一对叶子，所以答案是`0`- 高度不平衡的树木可能会产生很长的路径
 - 多个叶子可能完全存在于一棵子树中
 - 即使遍历处理许多递归调用，叶子对也只能计数一次
 - 距离必须计算边，而不是节点

 该问题保证了一个有效的二叉树并保证`distance >= 1`。 

## 方法

 ### 蛮力方法

 最直接的解决方案是首先收集所有叶子节点，然后计算每对叶子之间的最短距离。 

一种方法是：

 1. 遍历树并存储所有叶子节点。 
2. 对于每对叶子：

 - 找出它们之间的距离。 
- 如果距离最大`distance`，增加答案。 

为了有效地计算距离，我们可以：

 - 构建父指针，
 - 从一片叶子运行 BFS 到另一片叶子，
 - 或计算最低共同祖先。 

这种方法是正确的，因为每对叶子都被明确检查。 

然而，它变得低效，因为：

 - 如果有`L`叶子，我们必须检查`O(L^2)`对。 
- 计算每个距离可能需要`O(N)`时间。 

在最坏的情况下，总复杂度变为`O(L^2 * N)`。 

虽然这里的限制比较小，但是这种做法做了不必要的重复工作。 

### 最优 DFS + 距离聚合方法

 关键的见解是，我们实际上并不需要全球范围内每对叶子之间的距离。 

相反，在执行后序 DFS 遍历时，每个子树可以返回有关其叶节点距当前节点多远的信息。 

对于每个节点：

 - 递归地收集距左子树的叶子距离
 - 递归地收集距右子树的叶子距离
 - 将它们组合起来计算通过当前节点的有效对
 - 返回更新后的向上距离

 这是有效的，因为两个叶子之间的每条最短路径都经过它们的最低共同祖先。 当处理一个节点时，我们可以确定路径经过该节点的所有有效对。 

自从`distance <= 10`，每个子树只需要存储少量的距离，使得解决方案高效。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(L² × N) | O(N) | 显式检查每对叶子 |
 | 最优 DFS | O(N × D²) | O(H + D) | 自下而上聚合叶距离 |

 这里：

-`N`是节点数
 -`L`是叶子的数量
 -`D`是`distance`-`H`是树的高度

 因为`distance <= 10`,`D²`实际上是恒定的。 

## 算法演练

 ### 步骤 1：执行后序 DFS 遍历

 我们在父级之前处理子级，因为父级需要有关与两个子树的叶子距离的信息。 

每个递归调用都会返回从当前节点到该子树内所有叶节点的距离列表。 

### 步骤2：处理叶节点情况

 如果当前节点是叶子节点：

 - 返回`[1]`价值`1`意思是：

 - 来自当前节点的父节点，
 - 这片叶子正好在一个边缘之外。 

该约定简化了向上传播。 

### 步骤 3：递归收集左右子树距离

 对于非叶节点：

 - 递归地收集距左子节点的叶子距离
 - 递归地收集距右子节点的叶子距离

 例如：```
left_distances  = [2, 3]
right_distances = [1]
```这意味着：

 - 左子树包含距离较远的叶子`2`和`3`- 右子树包含远处的一片叶子`1`所有距离都是从当前节点开始测量的。 

### 步骤 4：计算有效的跨子树对

 每对包含：

 - 左子树的一片叶子
 - 右子树的一片叶子

 形成一条经过当前节点的路径。 

对于每个组合：```
left_distance + right_distance
```如果总和小于或等于`distance`，这是一对好搭档。 

### 第 5 步：为父母建立距离

 家长需要更新距离。 

每个子树距离增加`1`因为向上移动会增加一个优势。 

所以我们创建：```
new_distance = old_distance + 1
```我们只保持距离严格小于`distance`，因为较大的值永远不能参与未来的有效对。 

### 步骤 6：返回更新后的距离列表

 递归函数向上返回新列表。 

最终，根完成对所有子树的处理，并且全局答案包含好对的总数。 

### 为什么它有效

 每对叶节点都有一个唯一的最低公共祖先。 当 DFS 处理该祖先时，一个叶子出现在左子树列表中，另一个叶子出现在右子树列表中。 

该算法对所有此类组合仅检查一次，因此每个有效对都被计算一次且仅计算一次。 

返回的距离列表始终正确地表示距当前节点的叶子距离，这在整个递归过程中保持了正确性。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional, List

class Solution:
    def countPairs(self, root: Optional[TreeNode], distance: int) -> int:
        good_pairs = 0

        def dfs(node: Optional[TreeNode]) -> List[int]:
            nonlocal good_pairs

            if not node:
                return []

            # Leaf node
            if not node.left and not node.right:
                return [1]

            left_distances = dfs(node.left)
            right_distances = dfs(node.right)

            # Count valid pairs
            for left_distance in left_distances:
                for right_distance in right_distances:
                    if left_distance + right_distance <= distance:
                        good_pairs += 1

            # Build distances for parent
            current_distances = []

            for dist in left_distances:
                if dist + 1 < distance:
                    current_distances.append(dist + 1)

            for dist in right_distances:
                if dist + 1 < distance:
                    current_distances.append(dist + 1)

            return current_distances

        dfs(root)

        return good_pairs
```该实现遵循前面描述的精确递归策略。 

这`dfs()`函数返回距当前节点的叶子距离列表。 

基本情况是：

 -`None`节点返回一个空列表
 - 叶节点返回`[1]`对于内部节点，递归收集距两个子树的距离。 

嵌套循环将每个左子树叶子与每个右子树叶子进行比较。 如果它们的组合路径长度在允许的限制内，则全局计数器增加。 

对对进行计数后，该函数为父对象准备距离值。 每个距离都会增加一，因为父级距离更远。 

已经太大的距离会被提前丢弃，因为它们永远无法形成有效的未来对。 

最后，递归在根结束并返回累积的答案。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */

func countPairs(root *TreeNode, distance int) int {
    goodPairs := 0

    var dfs func(node *TreeNode) []int

    dfs = func(node *TreeNode) []int {
        if node == nil {
            return []int{}
        }

        // Leaf node
        if node.Left == nil && node.Right == nil {
            return []int{1}
        }

        leftDistances := dfs(node.Left)
        rightDistances := dfs(node.Right)

        // Count valid pairs
        for _, leftDist := range leftDistances {
            for _, rightDist := range rightDistances {
                if leftDist+rightDist <= distance {
                    goodPairs++
                }
            }
        }

        currentDistances := []int{}

        // Prepare distances for parent
        for _, dist := range leftDistances {
            if dist+1 < distance {
                currentDistances = append(currentDistances, dist+1)
            }
        }

        for _, dist := range rightDistances {
            if dist+1 < distance {
                currentDistances = append(currentDistances, dist+1)
            }
        }

        return currentDistances
    }

    dfs(root)

    return goodPairs
}
```Go 实现密切反映了 Python 逻辑。 

Go 使用整数切片，而不是 Python 列表。 Go 中的递归闭包需要先声明函数变量，然后分配实现。 

Nil 处理是明确的`node == nil`。 

由于约束很小，标准整数运算是完全安全的，并且不存在溢出问题。

 ## 边缘情况

 ### 单节点树

 仅包含一个节点的树只有一个叶子，因此不可能有一对。 

这种情况很容易导致不正确的实现意外地计算不存在的对或错误处理递归。 

该实现自然地处理了这个问题，因为 DFS 返回`[1]`对于单叶，但没有节点组合左右子树距离。 

### 极度倾斜的树

 一棵形状像链表的树在最深层只包含一个叶子。 

递归树算法有时假设存在分支，这可能导致错误的对计数或无效的索引。 

该解决方案可以安全地处理此问题，因为空子树返回空列表，并且不会发生跨子树比较。 

### 距离恰好等于极限

 条件是：```
distance_between_leaves <= distance
```实现有时会错误地使用严格的不等式。 

该解决方案正确使用：```
if left_distance + right_distance <= distance:
```因此恰好在阈值处的对被计数。 

### 大距离向上传播

 如果大于允许限制的距离继续向上传播，不必要的工作就会积累，逻辑就会变得更难以推理。 

实现会尽早修剪这些值：```
if dist + 1 < distance:
```这保证了只有潜在有用的距离才能继续递归。
