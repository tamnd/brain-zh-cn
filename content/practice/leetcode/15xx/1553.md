 # LeetCode 1553 - 吃 N 个橙子的最少天数

 ## 问题理解

 这个问题要求我们计算准确吃饭所需的最少天数`n`橙子，给出每天可以执行的三种可能的操作。 

在任何一天，我们都可以选择以下操作之一：

 1. 只吃一个橙子。 
2. 如果当前橙子的数量能被`2`，吃一半。 
3. 如果当前橙子的数量能被`3`，吃掉三分之二。 

目标是减少橙子的数量`n`下降到`0`使用尽可能少的天数。 

重要的细节是，第二个和第三个操作仅当当前橙色计数可以整除时才可用`2`或者`3`分别。 这意味着我们经常需要花几天时间吃单个橙子，只是为了使数字可以整除，然后才能应用更大的归约操作。 

输入由单个整数组成`n`，代表橙子的起始数量。 产出是完成所有橙子所需的最少天数。 

约束非常重要：```
1 <= n <= 2 * 10^9
```这个上限是巨大的。 任何尝试按顺序模拟每个状态或从中构建动态编程表的解决方案`1`到`n`会太慢并且占用大量内存。 

该问题保证了`n`总是至少`1`，所以我们永远不需要处理负值或无效输入。 

一些边缘情况尤其重要：

 - 非常小的值，例如`n = 1`,`n = 2`， 和`n = 3`- 已经可以整除的数字`2`或者`3`- 需要多次单橙色运算才能整除的数字
 - 附近非常大的值`2 * 10^9`- 除以的情况`2`比除以更糟糕`3`，或反之亦然

 天真的贪婪策略可能会失败，因为局部最优决策并不总是导致全局最小天数。 

## 方法

 ### 蛮力方法

 暴力解决方案将探索每一个可能的有效操作序列。 来自一个州`n`，我们可以递归地尝试：

 - 吃一个橙子
 - 如果能被`2`， 吃`n / 2`- 如果能被`3`， 吃`2 * (n / 3)`然后我们会在所有可能的路径中取最小的结果。 

这种方法是正确的，因为它详尽地检查了每个有效的操作序列，因此不会错过最佳解决方案。 

然而，问题是许多状态被重复重新计算。 例如，不同的递归路径最终可能达到相同的剩余橙色计数。 如果没有优化，递归树会呈指数增长。 

对于较大的值，例如`10^9`，这种方法变得完全不可行。 

### 最佳解决方案的关键见解

 最重要的观察是，唯一有意义的大幅减少来自除以`2`或者`3`。 

假设我们想除以`2`， 但`n`不能被整除`2`。 使其可分割的唯一方法就是花费`n % 2`吃单个橙子的日子。 

同样，如果我们想除以`3`，我们首先需要花费`n % 3`吃单个橙子的日子。 

这会导致重复出现：```
minDays(n) =
1 + min(
    (n % 2) + minDays(n // 2),
    (n % 3) + minDays(n // 3)
)
```额外的`1`代表我们执行除法运算本身的那一天。 

这大大减少了我们需要计算的状态数量，因为每个递归步骤都显着减少了问题的大小。 

记忆化使我们能够存储之前计算的结果并避免重复工作。

 ## 算法演练

 1.定义递归函数`dfs(n)`返回需要吃饭的最少天数`n`橙子。 
2. 首先处理基本情况。 

- 如果`n <= 1`， 返回`n`。 
-`0`橙子需要`0`天。 
-`1`橙色需要`1`天。 
3.考虑制作`n`可除以`2`。 

如果`n`不能被整除`2`，我们必须花费`n % 2`一次吃一个橙子的日子。 之后，我们可以再花一天的时间来执行除以 2 的运算。 

总成本变为：```
(n % 2) + 1 + dfs(n // 2)
```4.考虑制作`n`可除以`3`。 

同样，我们花费`n % 3`几天吃一个橙子，然后一天进行除以 3 运算。 

总成本变为：```
(n % 3) + 1 + dfs(n // 3)
```5. 取两个选项中的最小值。 

我们选择总天数较少的路径。 
6. 将计算结果存储在记忆缓存中。 

这确保每个状态只解决一次。 
7. 返回缓存结果。 

### 为什么它有效

 该算法之所以有效，是因为每个最优策略最终都会使用除以来减少数量`2`或除以`3`。 任何额外的单橙色运算仅用于使数字可整除。 

该算法没有探索单个橙色移除的所有可能序列，而是直接计算达到可整除状态所需的最小数量。 这将许多冗余状态压缩为单个转换。 

记忆化保证了每个不同的值`n`解决一次，防止指数重新计算。 

## Python 解决方案```python
class Solution:
    def minDays(self, n: int) -> int:
        memo = {}

        def dfs(remaining: int) -> int:
            if remaining <= 1:
                return remaining

            if remaining in memo:
                return memo[remaining]

            divide_by_2 = (remaining % 2) + 1 + dfs(remaining // 2)
            divide_by_3 = (remaining % 3) + 1 + dfs(remaining // 3)

            memo[remaining] = min(divide_by_2, divide_by_3)
            return memo[remaining]

        return dfs(n)
```该实现使用名为的递归辅助函数`dfs`。 

底壳手柄`0`和`1`直接地。 这些是最小可能的状态并终止递归。 

字典`memo`存储先前计算的结果。 在求解状态之前，算法会检查该状态是否已存在于缓存中。 

表达式：```python
(remaining % 2) + 1 + dfs(remaining // 2)
```代表：

 - 使该数字能够整除所需的天数`2`- 师部行动一天
 - 简化问题的递归解决方案

 同样的逻辑适用于除以`3`。 

最后，算法存储并返回两个选择中的最小值。 

## 解决方案```go
func makeMemo() map[int]int {
    return map[int]int{}
}

func min(a, b int) int {
    if a < b {
        return a
    }
    return b
}

func minDays(n int) int {
    memo := makeMemo()

    var dfs func(int) int

    dfs = func(remaining int) int {
        if remaining <= 1 {
            return remaining
        }

        if value, exists := memo[remaining]; exists {
            return value
        }

        divideBy2 := (remaining % 2) + 1 + dfs(remaining/2)
        divideBy3 := (remaining % 3) + 1 + dfs(remaining/3)

        memo[remaining] = min(divideBy2, divideBy3)

        return memo[remaining]
    }

    return dfs(n)
}
```Go 解决方案遵循与 Python 版本相同的递归记忆方法。 

一个`map[int]int`用于记忆，因为 Go 不提供内置的记忆实用程序。 

使用以下方法将递归函数声明为闭包：```go
var dfs func(int) int
```这允许函数递归地引用自身。 

整数溢出不是问题，因为最大值只是`2 * 10^9`，它很适合 Go 的`int`在 LeetCode 系统上打字。 

与 Python 字典不同，Go 映射需要使用以下方式进行显式存在检查：```go
value, exists := memo[key]
```## 工作示例

 ## 边缘情况

 一个重要的边缘情况是当`n = 1`。 粗心的实现可能会不必要地继续递归或错误地处理基本条件。 解决方案正确返回`1`立即，因为正好需要一天时间才能吃完最后一个橙子。 

另一个关键的边缘情况发生在`n`已经可以被整除`2`或者`3`。 在这些情况下，模成本变为零，允许算法立即执行大的归约操作。 实现自然会处理这个问题，因为`n % 2`或者`n % 3`评估为`0`。 

更微妙的边缘情况涉及不能被任何一个整除的数字`2`或者`3`， 例如`n = 5`或者`n = 7`。 天真的贪婪解决方案可能会选择错误的调整路径。 递归记忆解决方案通过评估两种可能性并选择最小的总成本来避免这个问题。 

极大的输入，例如`2 * 10^9`是另一个重要的边缘情况。 传统的自下而上的动态编程解决方案需要大量的内存和运行时间。 记忆递归解决方案仍然有效，因为它只探索通过重复除法生成的状态的一个非常小的子集。
