[LeetCode 问题 1509](https://leetcode.com/problems/minimum-difference- Between-largest-and-smallest-value-in- Three-moves/)

 **难度：** 🟡 中等
 **主题：** 数组、贪婪、排序

 ## 解决方案

 ## 问题理解

 问题给了我们一个整数数组`nums`，并且我们最多可以执行三个动作。 在每次移动中，我们可以选择任何元素并将其更改为我们想要的任何值。 在进行最多三个修改后，我们必须最小化数组中剩余的最大值和最小值之间的差异。 

换句话说，我们希望最终数组的值尽可能紧密地分组。 输出是以下值的最小可能值：$$\text{max(nums)} - \text{min(nums)}$$最多更改三个元素后。 

输入数组最多可以包含$10^5$元素，因此解决方案必须是有效的。 二次或指数解对于约束来说太慢了。 值本身的范围可能是$-10^9$到$10^9$，但数字的大小并不重要，因为我们只是对它们进行比较和排序。 

一个重要的观察是，将元素更改为任何值可以有效地让我们“删除”有问题的极端值。 由于我们最多可以执行三个移动，因此我们可以从排序数组的任一端消除最多三个异常值。 

一些边缘情况很重要：

 - 如果数组的长度小于或等于 4，我们可以修改除 1 之外的每个元素，使所有数字相等。 因此答案总是`0`。 
- 排序后仍必须正确处理具有重复值的数组。 
- 负值不会引入特殊逻辑，因为排序仍然正常工作。 
- 大型阵列需要$O(n \log n)$或更好的解决方案。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试最多修改三个元素的每种可能组合，然后确定分配给这些元素的最佳值。 

从概念上讲，这是可行的，因为每个可能的有效配置都被探索了。 然而，这在计算上很快变得不可行。 

如果数组有大小$n$，选择三个元素已经需要：$$O(n^3)$$组合。 对于每种组合，我们还需要重新计算所得的最小值和最大值，从而增加额外的开销。 

和$n = 10^5$，这样的方法不可能在时间限制内运行。 

### 最佳解决方案的关键见解

 关键的观察是只有最小和最大值才重要。 

假设数组已排序：$$a_0 \le a_1 \le a_2 \le \dots \le a_{n-1}$$由于我们最多可以修改三个元素，因此最优策略必须从极端中删除元素。 

花费这三招的方式只有四种：

 1. 删除最大的三个元素
 2. 删除两个最大的和一个最小的
 3. 删除一个最大的和两个最小的
 4. 删除三个最小的元素

 排序后，每个场景对应保留一个连续的中间段。 

由此产生的差异是：$$a_{n-4} - a_0$$

$$a_{n-3} - a_1$$

$$a_{n-2} - a_2$$

$$a_{n-1} - a_3$$这四种可能性中最小的一个就是答案。 

因为我们只排序一次并评估四种情况，所以该算法是高效的。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^3)$或者更糟|$O(1)$| 尝试组合元素来修改 |
 | 最佳 |$O(n \log n)$|$O(1)$或者$O(\log n)$取决于排序 | 排序一次，评估四种可能性 |

 ## 算法演练

 1、首先检查数组长度是否小于等于4。 

如果最多有四个元素，我们可以更改足够的元素以使整个数组相等。 因此，最小差异为`0`。 
2. 按非降序对数组进行排序。 

排序使我们能够直接推断出最小值和最大值。 一旦排序，唯一重要的值就在边界附近。 
3. 用一个非常大的数字初始化答案。 

我们将计算四种可能情况之间的最小差异。 
4. 评估删除三个最大元素的情况。 

这意味着剩余的有效范围是`nums[0]`到`nums[n-4]`。 

不同之处：$$nums[n-4] - nums[0]$$5. 评估删除两个最大元素和一个最小元素。 

剩余范围：$$nums[1] \text{ to } nums[n-3]$$不同之处：$$nums[n-3] - nums[1]$$6. 评估删除一个最大元素和两个最小元素。 

剩余范围：$$nums[2] \text{ to } nums[n-2]$$不同之处：$$nums[n-2] - nums[2]$$7. 评估删除三个最小元素的情况。 

剩余范围：$$nums[3] \text{ to } nums[n-1]$$不同之处：$$nums[n-1] - nums[3]$$8. 返回所有四个差异中的最小值。 

### 为什么它有效

 排序后，任何最佳解决方案都必须仅消除数组末尾的元素。 更改内部元素无法像更改极值那样有效地减少全局最小值或最大值。 

由于我们正好有三个可用的移动，唯一的可能性是将这些移动分配在最小和最大的元素之间。 这四种场景耗尽了两端三个移除的所有有效分布，保证计算出的最小差值是最优的。 

## Python 解决方案```python
from typing import List

class Solution:
    def minDifference(self, nums: List[int]) -> int:
        n = len(nums)

        if n <= 4:
            return 0

        nums.sort()

        answer = float("inf")

        for left_removed in range(4):
            right_removed = 3 - left_removed

            current_difference = (
                nums[n - 1 - right_removed] -
                nums[left_removed]
            )

            answer = min(answer, current_difference)

        return answer
```实现首先检查数组是否包含四个或更少的元素。 在这种情况下，我们总是可以在三步之内使每个值相等，所以结果是立即的`0`。 

接下来，对数组进行排序。 排序是关键步骤，因为它允许算法仅关注边界值而不是任意位置。 

该循环迭代四种可能的移除分布。 变量`left_removed`表示有多少个最小元素被有效丢弃，而`right_removed`表示有多少个最大的元素被丢弃。 

对于每种配置，我们计算新的有效最大值和最小值之间的差异。 这种差异最小的就是最终的答案。 

实现很简洁，因为数学观察将问题简化为仅评估四种情况。 

## 解决方案```go
package main

import (
	"math"
	"sort"
)

func minDifference(nums []int) int {
	n := len(nums)

	if n <= 4 {
		return 0
	}

	sort.Ints(nums)

	answer := math.MaxInt32

	for leftRemoved := 0; leftRemoved < 4; leftRemoved++ {
		rightRemoved := 3 - leftRemoved

		currentDifference := nums[n-1-rightRemoved] - nums[leftRemoved]

		if currentDifference < answer {
			answer = currentDifference
		}
	}

	return answer
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 主要区别在于 Go 需要显式导入排序和整数常量。`sort.Ints(nums)`将切片排序到位。 循环结构与 Python 版本完全一致。 

Go 切片是引用类型，因此排序会直接修改原始切片。 整数溢出在这里不是问题，因为问题约束在 Go 中安全地适合`int`在现代系统上键入。

 ## 边缘情况

 当数组长度小于或等于四时，会出现一种重要的边缘情况。 由于我们最多可以执行三个移动，因此我们始终可以更改足够的元素以使每个值都相同。 盲目访问索引的幼稚实现，例如`nums[n-4]`小数组会崩溃。 该实现通过返回来避免这种情况`0`对于大小为 4 或更小的数组，立即执行。 

另一个关键的边缘情况涉及重复值。 数组如`[1,1,1,1,1]`最小差异已经为零。 一些不正确的解决方案可能仍然会尝试不必要的修改或在排序后错误地处理相等的元素。 当前的实现自然有效，因为计算出的差异保持为零。 

负值也很重要。 由于该问题允许值小至$-10^9$，算法不得假设为正值。 正确排序对负数进行排序，并且减法仍然会产生适当的范围差。 例如，`[-10,-5,0,5,10]`的处理方式与纯正数组完全相同。 

最后一个微妙的情况是，最佳解决方案从两端而不是一侧删除元素。 例如，在`[1,5,0,10,14]`，最好的答案来自于删除一个最小值和两个最大值。 仅考虑删除三个最大或三个最小值的解决方案将会失败。 评估所有四个分布可以保证正确性。
