[LeetCode 问题 1567](https://leetcode.com/problems/maximum-length-of-subarray-with-positive-product/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划、贪心

 ## 解决方案

 ## 问题理解

 该问题要求我们找到元素乘积严格为正的最长连续子数组的长度。 

我们得到一个整数数组`nums`，可能包含正数、负数和零。 子数组必须由原始数组中的连续元素组成。 在所有可能的子数组中，我们需要确定每个元素相乘产生正值的最大长度。 

关键的观察是，确切的产品价值并不重要。 我们只关心产品是正面还是负面。 这大大简化了问题，因为乘积的符号完全取决于负值的数量：

 - 偶数个负数产生正积。 
- 奇数个负数产生负积。 
- 任何包含的子数组`0`有产品`0`，这不是积极的。 

约束条件很重要：

 -`nums.length`可以大到`10^5`- 值本身可以很大，最多`10^9`在大小上

 由于数组可以包含十万个元素，因此任何慢于线性或近线性时间的解决方案都可能会超时。 此外，直接计算乘积是不必要的，而且有潜在的危险，因为乘法在某些语言中可能会溢出。 由于只有标志很重要，因此我们应该跟踪积极性和消极性，而不是实际的产品价值。 

一些边缘情况很重要：

 - 包含许多零的数组，因为零将数组分成独立的段
 - 仅包含负数的数组
 - 最佳答案出现在中间的数组
 - 具有交替符号的数组
 - 单元素数组，尤其是`[0]`,`[1]`， 和`[-1]`重复计算每个子数组的乘积的简单实现会太慢。 

## 方法

 ### 蛮力方法

 强力解决方案会检查每个可能的子数组。 对于每个起始索引，我们一次扩展子数组一个元素并计算乘积是否为正。 

有`O(n^2)`可能的子数组。 如果我们显式地将每个子数组的值相乘，复杂性会变得更糟。 即使我们通过仅跟踪符号进行优化，我们仍然必须检查所有子数组。 

暴力法是正确的，因为它详尽地评估每个候选子数组并记录最大有效长度。 然而，随着`n = 10^5`， 一个`O(n^2)`解决方案太慢了。 

### 最优动态规划/贪婪观察

 重要的见解是，在每个位置，我们只需要知道：

 - 以此索引结尾且积为正的最长子数组的长度
 - 以此索引结尾且积为负的最长子数组的长度

 我们可以从左到右处理数组。 

对于每个数字：

 - 正数保留符号
 - 负数翻转符号
 - 归零重置一切

 这导致了一种仅使用两个变量的非常紧凑的动态规划方法。 

如果：

-`positive_len`= 最长正积子数组在此结束
 -`negative_len`= 最长的负积子数组在此结束

 然后我们可以在恒定时间内更新每个元素的这些值。 

这给出了线性时间解。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 检查每个可能的子数组 |
 | 最佳 | O(n) | O(1) | O(1) | 动态跟踪正负子数组长度 |

 ## 算法演练

 1.初始化三个变量：

 -`positive_len = 0`-`negative_len = 0`-`max_length = 0`

`positive_len`表示以当前索引结尾且积为正的最长子数组。`negative_len`表示以当前索引结尾且积为负的最长子数组。 
2. 从左到右迭代数组中的每个数字。 
3. 如果当前数字为正数：

 - 任何现有的正积子数组在附加此数字后仍然为正。 
- 任何现有的负积子数组在附加此数字后仍然为负。 

所以：

-`positive_len += 1`-`negative_len = negative_len + 1`如果`negative_len > 0`4. 如果当前数字为负数：

 - 附加负数会翻转符号。 
- 先前的正积子数组变为负数。 
- 先前的负积子数组变为正数。 

由于这两个值都取决于之前的状态，因此在更新之前将它们暂时存储。 

然后：

-`positive_len = previous_negative_len + 1`如果先前的负数存在
 -`negative_len = previous_positive_len + 1`5. 如果当前数字为零：

 - 任何包含零的子数组的乘积为零。 
- 没有有效的子数组可以继续跨越零。 

重置：

-`positive_len = 0`-`negative_len = 0`6.处理完每个元素后，更新：

 -`max_length = max(max_length, positive_len)`7.循环结束后，返回`max_length`。 

### 为什么它有效

 在每个索引处，该算法都会维护以该位置结束的最长正积和负积子数组的精确长度。 这些值完全捕获了有关先前元素的所有必要信息，因为乘积的符号仅取决于负数的奇偶校验。 由于每次更新都会根据当前数字的符号正确地转换先前的状态，因此该算法始终保持正确的子问题解决方案并最终找到全局最大值。 

## Python 解决方案```python
from typing import List

class Solution:
    def getMaxLen(self, nums: List[int]) -> int:
        positive_len = 0
        negative_len = 0
        max_length = 0

        for num in nums:
            if num > 0:
                positive_len += 1

                if negative_len > 0:
                    negative_len += 1

            elif num < 0:
                previous_positive = positive_len
                previous_negative = negative_len

                if previous_negative > 0:
                    positive_len = previous_negative + 1
                else:
                    positive_len = 0

                negative_len = previous_positive + 1

            else:
                positive_len = 0
                negative_len = 0

            max_length = max(max_length, positive_len)

        return max_length
```实现直接遵循前面描述的算法。 

变量`positive_len`和`negative_len`存储当前位置的动态编程状态。 我们不使用数组，而是只保留最新的值，因为每次更新仅依赖于前一个索引。 

处理正数时，符号不会改变。 正序列会变长，负序列如果已经存在也会延长。 

处理负数时，符号会翻转。 由于这两个值都取决于先前的状态，因此使用临时变量来避免在两次更新完成之前覆盖信息。 

当遇到零时，两种状态都会重置，因为包含零的子数组不能具有正积。 

变量`max_length`持续跟踪迄今为止发现的最佳正积子阵列。 

## 解决方案```go
func getMaxLen(nums []int) int {
    positiveLen := 0
    negativeLen := 0
    maxLength := 0

    for _, num := range nums {
        if num > 0 {
            positiveLen++

            if negativeLen > 0 {
                negativeLen++
            }

        } else if num < 0 {
            previousPositive := positiveLen
            previousNegative := negativeLen

            if previousNegative > 0 {
                positiveLen = previousNegative + 1
            } else {
                positiveLen = 0
            }

            negativeLen = previousPositive + 1

        } else {
            positiveLen = 0
            negativeLen = 0
        }

        if positiveLen > maxLength {
            maxLength = positiveLen
        }
    }

    return maxLength
}
```Go 实现密切反映了 Python 逻辑。 

Go 使用显式整数变量而不是 Python 的动态类型整数。 整数溢出不是问题，因为我们从不计算实际的乘积，只计算长度。 

该函数直接对切片进行操作，切片是对数组的有效引用。 由于该算法使用恒定的额外空间，因此不需要额外的分配。

 该算法从左到右扫描数组一次。 每次更新都需要恒定的时间，因此总运行时间随着输入大小线性增长。 

不需要辅助数组、堆栈或哈希图。 该解决方案仅存储少量整数，从而提供恒定的额外空间使用。

 ## 边缘情况

 一种重要的边缘情况是包含零的数组。 由于任何涉及零的乘积都会变为零，因此有效子数组不能跨越零。 一个常见的错误是在遇到零后忘记完全重置状态变量。 此实现正确地重置了两者`positive_len`和`negative_len`每当出现零时就为零。 

另一个重要的情况是具有奇数个负值的数组。 例如，`[-1, -2, -3]`总体具有负乘积，但较小的子阵列可能仍具有正乘积。 仅检查整个段的总奇偶校验的简单方法将会失败。 动态编程方法连续跟踪正状态和负状态，因此它可以正确识别最佳的有效子阵列。 

第三种边缘情况涉及当不存在先前的负积子数组时出现负数。 在这种情况下，无法立即形成新的正积子阵列。 实施仔细检查是否`previous_negative > 0`在延伸到积极状态之前。 如果没有这个条件，算法可能会错误地创建不存在的子数组。 

第四个微妙的情况是单元素数组。 数组就像`[1]`,`[-1]`， 和`[0]`测试当数组长度最小时初始化和更新是否正常工作。 该算法自然地处理这些问题，因为状态转换即使对于一次迭代也是有效的。
