 # LeetCode 1599 - 操作百年轮的最大利润

 ## 问题理解

 该问题要求我们模拟百年轮的运行，并确定实现最大可能利润所需的最小旋转次数。 

摩天轮有四个吊篮，每个吊篮旋转一圈最多可容纳四人。 顾客按规定时间准时到达`customers`大批。 具体来说，`customers[i]`代表在该时间之前到达的顾客数量`i-th`旋转。 

每次旋转时：

 - 最多四位等候乘客可以登机。 
- 每个登机的顾客都会产生`boardingCost`美元的收入。 
- 转动轮子的成本`runningCost`美元。 

目标是确定总利润变得尽可能大的轮转次数。 如果轮子永远不会产生正利润，我们就返回`-1`。 

重要的细节是，无法立即登机的乘客必须等待未来的轮换。 此外，一旦我们停止运营轮子，卸载乘客所需的任何剩余旋转都被视为免费，不会影响利润。 

输入约束很重要：

 -`customers.length`可以大到`10^5`- 每个`customers[i]`至多是`50`这告诉我们解决方案必须是高效的、理想的线性时间。 二次或重度嵌套的模拟会太慢。 

一些边缘情况很重要：

 - 利润可能永远不会变为正数。 
- 处理整个输入数组后，可能仍有顾客在等待。 
- 某些轮换可能登机人数少于四人。 
- 当无人登机时运行方向盘可能会减少利润。 
- 最佳停止点可能出现在为所有顾客提供服务之前。 

正确的实施必须仔细跟踪等待的客户、总利润以及利润最大化的轮换次数。 

## 方法

 ### 蛮力方法

 蛮力方法将尝试独立模拟每个可能的停止点。 

对于每个可能的旋转次数：

 1. 从头开始模拟车轮操作。 
2. 跟踪等待的顾客。 
3. 计算累计收入和成本。 
4. 记录该停止点的利润。 
5. 返回实现最大利润的最小旋转次数。 

这种方法是正确的，因为它明确地评估了每个可能的操作持续时间。 然而，它会从头开始重复地重新计算相同的模拟状态。 

如果有`n`旋转，并且每个候选停止点都需要另一个完整的模拟，总复杂度变为二次。 

和`n`最多`10^5`， 一个`O(n^2)`解决方案太慢了。 

### 最佳模拟方法

 关键的见解是我们不需要为每个可能的停止点重新启动模拟。 

利润逐步增长：

 - 每次轮换都会改变利润：`boarded * boardingCost - runningCost`因此我们可以一次处理一个旋转，同时持续维护：

 - 等待的顾客
 - 当前利润
 - 迄今为止看到的最大利润
 - 发生最大利润的轮换计数

 即使在处理完所有到达后，我们可能仍然有等待的顾客，因此模拟必须继续下去，直到队列变空。 

这产生了一个简单的线性时间模拟。

 ## 算法演练

 ### 第 1 步：初始化跟踪变量

 我们在整个模拟过程中维护几个变量：

 -`waiting_customers`跟踪有多少乘客仍在等待登机。 
-`current_profit`存储迄今为止的累计利润。 
-`max_profit`门店利润最高。 
-`best_rotation`存储出现最大利润时的轮换计数。 
-`rotation_count`跟踪执行的总旋转次数。 

最初：

 - 没有顾客在等待
 - 利润为零
 - 最大利润为零
 - 最佳轮换是`-1`我们使用`-1`因为如果利润永远不会变成正数，答案一定是`-1`。 

### 第 2 步：处理新来的客户

 对于每个旋转索引：

 1. 将新到达的顾客添加到等待队列中。 
2. 最多可容纳四位顾客。 
3. 减去运行成本。 
4.增加寄宿收入。 
5. 如有必要，更新最大利润。 

登机人数为：```
min(4, waiting_customers)
```因为每次旋转最多可以承载四个人。 

### 第 3 步：在所有人员到达后继续轮换

 处理完输入数组后，客户可能仍在等待。 

我们继续旋转，同时：```
waiting_customers > 0
```每次额外轮换最多可容纳四名剩余客户，并以完全相同的方式更新利润。 

### 第 4 步：跟踪最佳利润

 每次旋转后：

 - 如果`current_profit > max_profit`- 更新`max_profit`- 将当前轮换计数存储为答案

 该问题要求实现最大利润的最小旋转次数，因此我们仅在利润变得严格更大时进行更新。 

###第五步：返回结果

 如果最大利润从未变为正数，则返回`-1`。 

否则，返回存储的旋转计数。 

### 为什么它有效

 该算法之所以有效，是因为利润仅通过局部轮换事件发生变化。 每个可能的操作持续时间都对应于模拟的某个前缀。 通过在每次轮换后立即评估利润，我们检查每个可能的停止点一次。 

由于我们总是记录实现新的最大利润的第一个旋转次数，因此存储的答案保证是产生该最大值的最小旋转次数。 

## Python 解决方案```python
from typing import List

class Solution:
    def minOperationsMaxProfit(
        self,
        customers: List[int],
        boardingCost: int,
        runningCost: int
    ) -> int:
        
        waiting_customers = 0
        current_profit = 0
        max_profit = 0
        
        best_rotation = -1
        rotation_count = 0
        
        index = 0
        n = len(customers)
        
        while index < n or waiting_customers > 0:
            
            if index < n:
                waiting_customers += customers[index]
            
            boarded = min(4, waiting_customers)
            waiting_customers -= boarded
            
            rotation_count += 1
            
            current_profit += boarded * boardingCost
            current_profit -= runningCost
            
            if current_profit > max_profit:
                max_profit = current_profit
                best_rotation = rotation_count
            
            index += 1
        
        return best_rotation
```实现直接遵循模拟过程。 

变量`waiting_customers`存储当前队列大小。 在每次迭代时，如果输入数组中仍有元素，则添加新到达的元素。 

然后，我们确定当前轮换期间可以登机的人数。 由于吊篮容量为四，我们使用：```python
boarded = min(4, waiting_customers)
```登机后：

 - 队列减少
 - 旋转次数增加
 - 应用收入和运营成本

 当前利润与迄今为止最好的利润进行了比较。 如果当前值更大，我们更新两者`max_profit`和`best_rotation`。 

循环条件尤其重要：```python
while index < n or waiting_customers > 0:
```这确保了即使在处理完所有到达的货物后，只要客户仍在等待，我们就可以继续运营。 

最后，如果利润从未变为正值，`best_rotation`遗迹`-1`，符合问题要求。 

## 解决方案```go
func minOperationsMaxProfit(customers []int, boardingCost int, runningCost int) int {
    waitingCustomers := 0
    currentProfit := 0
    maxProfit := 0

    bestRotation := -1
    rotationCount := 0

    index := 0
    n := len(customers)

    for index < n || waitingCustomers > 0 {

        if index < n {
            waitingCustomers += customers[index]
        }

        boarded := waitingCustomers
        if boarded > 4 {
            boarded = 4
        }

        waitingCustomers -= boarded

        rotationCount++

        currentProfit += boarded * boardingCost
        currentProfit -= runningCost

        if currentProfit > maxProfit {
            maxProfit = currentProfit
            bestRotation = rotationCount
        }

        index++
    }

    return bestRotation
}
```Go 实现密切反映了 Python 逻辑。 

由于 Go 没有提供内置的`min`对于整数函数，我们使用条件检查手动计算登机计数。 

所有值都安全地保持在 Go 的标准整数范围内，因为约束相对较小。 不需要特殊的溢出处理。 

循环条件与 Python 版本相同，并确保剩余的排队客户得到完全处理。

 ## 边缘情况

 ### 利润永远不会变成正值

 当运营成本相对于寄宿收入而言过高时，就会出现一种棘手的情况。 即使顾客继续登机，摩天轮也可能持续亏损。 

例如：```
customers = [3,4,0,5,1]
boardingCost = 1
runningCost = 92
```有缺陷的实现可能会错误地返回最终旋转计数而不是`-1`。 

此实现通过初始化避免了该问题：```
best_rotation = -1
```并且仅在利润严格为正数时才更新。 

### 输入结束后剩余客户

 另一个重要的情况是当所有到达处理完毕后客户仍在等待。 

例如：```
customers = [50]
```即使数组只包含一个条目，轮子也必须继续旋转，直到所有等待的顾客都得到服务。 

循环条件：```
while index < n or waiting_customers > 0
```确保这些剩余的客户得到正确处理。 

### 部分吊船旋转

 当可用客户少于四个时，可能会发生微妙的错误。 

例如：```
customers = [1,1,1]
```不正确的实施可能会假设每个有利可图的轮换恰好有四个人。 

相反，该解决方案正确计算：```
boarded = min(4, waiting_customers)
```它可以自然地处理部分装满的吊船并确保准确的利润计算。
