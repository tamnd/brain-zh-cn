 ## 解决方案

 # LeetCode 1548，图中最相似的路径

 ## 问题理解

 该问题为我们提供了一个无向连通图，其中每个节点代表一个城市，每个城市都有一个三个字母的名称。 我们还得到了一个目标名称序列，称为`targetPath`。 

我们的目标是构建一条穿过图表的有效路径，以便：

 1. 路径长度恰好等于`targetPath`2.路径中连续的城市必须有道路连接
 3. 所选路径上城市名称的顺序应尽可能类似于`targetPath`相似度是使用简化形式的编辑距离来测量的。 在每个位置：

 - 如果所选城市的名称等于`targetPath[i]`，成本为`0`- 否则，费用为`1`总编辑距离就是不匹配位置的数量。 

我们必须返回节点索引的实际序列，以最小化总不匹配计数。 

例如，假设：

 -`targetPath = ["ATL", "DXB", "HND", "LAX"]`我们选择对应的节点：

 -`["ATL", "LAX", "HND", "LAX"]`那么失配计数为：

 | 职位| 目标| 选择| 匹配？ |
 | --- | --- | --- | --- |
 | 0 | 亚特兰大 | 亚特兰大 | 是的 |
 | 1 | DXB | 洛杉矶国际机场 | 没有 |
 | 2 | HND | HND | 是的 |
 | 3 | 洛杉矶国际机场 | 洛杉矶国际机场 | 是的 |

 总编辑距离 = 1。 

该图保证是连通的，这意味着总是至少有一条任意所需长度的有效路径，因为我们可以多次重新访问节点。 

约束条件很重要：

 -`n <= 100`-`targetPath.length <= 100`这些限制对于位置和节点的动态规划来说足够小。 

对所有路径进行简单的暴力枚举将会呈指数级爆炸，因为每一步都可能分支到许多邻近的城市。 

重要的边缘情况包括：

 - 多个城市可以使用相同的名称
 - 最优路径可能会多次重访节点
 - 图可能是密集的或稀疏的
 - 没有一个城市名称与目标完全匹配
 - 可能存在多个最佳答案

 该问题允许返回任何最小成本路径。 

## 方法

 ### 蛮力方法

 强力解决方案将生成每个可能的有效长度路径`len(targetPath)`。 

从每个节点开始：

 1. 递归尝试每个相邻节点
 2. 构建所需长度的所有可能路径
 3. 计算每条路径的不匹配计数
 4.返回最小的一个

 这是有效的，因为它详尽地检查了所有有效的可能性。 

然而，它太慢了。 

如果平均度为`d`目标长度是`m`，则路径数大约为：$$O(n \cdot d^{m-1})$$和`m = 100`，这变得完全不可行。 

### 最优动态规划方法

 关键的观察结果是该问题具有重叠的子问题。 

假设我们定义：

 -`dp[i][city]`= 构造长度有效路径的最小编辑距离`i + 1`结束于`city`要计算此状态：

 - 我们考虑之前的每一个邻近城市
 - 从之前的最佳状态过渡
 - 添加当前位置的不匹配成本

 这将问题转化为最短路径风格的动态规划：

 - 路径位置
 - 当前节点

 我们还存储父指针，以便之后可以重建最终路径。 

这减少了多项式时间的指数搜索。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * d^(m-1)) | O(n * d^(m-1)) | O(米) | 枚举所有可能的路径 |
 | 最佳DP | O(m * (n + m_edges)) 或 O(m * m_edges) | O(m * n) | 位置和节点的动态规划|

 在哪里：

-`m = len(targetPath)`-`m_edges = roads.length`## 算法演练

 ### 第 1 步：构建图表

 将道路列表转换为邻接列表。 

这允许在 DP 转换期间进行有效的邻居遍历。 

对于每一条路`[u, v]`：

- 添加`v`到`u`的邻接表
 - 添加`u`到`v`的邻接表

 由于该图是无向的，因此两个方向都很重要。 

### 步骤 2：定义 DP 状态

 让：$$dp[i][city]$$表示有效路径的最小失配成本：

 - 使用第一个`i + 1`职位
 - 结束于`city`我们还维护：$$parent[i][city]$$其中存储了之前的城市用于达到此最佳状态的情况。 

这对于稍后重建最终路径是必要的。 

### 步骤 3：初始化第一层

 在位置`0`，我们可以从任何城市开始。 

成本是：

 -`0`如果`names[city] == targetPath[0]`- 否则`1`所以：$$dp[0][city] = \begin{cases} 0 & \text{if names[city] matches targetPath[0]} \\ 1 & \text{otherwise} \end{cases}$$### 步骤 4：执行状态转换

 对于每个位置`i`从`1`到`m - 1`：

 对于每个当前城市`curr`：

 1. 计算失配成本：

 -`0`如果名字匹配
 -`1`否则
 2. 尝试每一个邻近城市`prev`3. 候选成本变为：$$dp[i-1][prev] + mismatch$$1. 取所有有效前驱中的最小值
 2. 存储两者：

 - 最低成本
 - 前身城市

 ### 第 5 步：找到最佳最终城市

 填写DP表后：

 - 检查最后位置的所有城市
 - 选择成本最低的城市

 这给出了最佳路径的端点。 

### 第 6 步：重建路径

 使用`parent`表：

 1.从最好结局的城市开始
 2.逐个位置向后移动一个位置
 3.恢复之前所有的城市
 4. 反转结果

 重建的序列就是最优路径。 

### 为什么它有效

 DP 状态保证每个状态存储以特定城市和位置结束的路径的最小可能的不匹配成本。 

每个长度有效的路径`i + 1`结束于`curr`必须来自某个邻近城市`i - 1`。 通过考虑所有这些邻居并选择最小的转移成本，我们确保了最佳的子结构。 

由于所有状态都经过优化计算，并且每个转换都被考虑一次，因此最终的重构路径必须具有最小编辑距离。 

## Python 解决方案```python
from typing import List

class Solution:
    def mostSimilar(
        self,
        n: int,
        roads: List[List[int]],
        names: List[str],
        targetPath: List[str]
    ) -> List[int]:

        target_length = len(targetPath)

        # Build adjacency list
        graph = [[] for _ in range(n)]

        for u, v in roads:
            graph[u].append(v)
            graph[v].append(u)

        INF = float('inf')

        # dp[i][city] = minimum cost to reach city at position i
        dp = [[INF] * n for _ in range(target_length)]

        # parent[i][city] = previous city used
        parent = [[-1] * n for _ in range(target_length)]

        # Initialize first position
        for city in range(n):
            dp[0][city] = 0 if names[city] == targetPath[0] else 1

        # Fill DP table
        for i in range(1, target_length):

            for curr_city in range(n):

                mismatch_cost = (
                    0
                    if names[curr_city] == targetPath[i]
                    else 1
                )

                for prev_city in graph[curr_city]:

                    candidate = (
                        dp[i - 1][prev_city]
                        + mismatch_cost
                    )

                    if candidate < dp[i][curr_city]:
                        dp[i][curr_city] = candidate
                        parent[i][curr_city] = prev_city

        # Find best ending city
        end_city = 0

        for city in range(1, n):
            if dp[target_length - 1][city] < dp[target_length - 1][end_city]:
                end_city = city

        # Reconstruct path
        path = [0] * target_length

        current = end_city

        for i in range(target_length - 1, -1, -1):
            path[i] = current
            current = parent[i][current]

        return path
```实现首先构建图的邻接列表表示。 这很重要，因为 DP 转换依赖于快速枚举邻近城市。 

这`dp`表存储每个位置和结束城市的最小失配成本。 最初，每个值都设置为无穷大，以便任何有效的候选值都成为改进。 

由于路径可能从任何城市开始，因此第一 DP 层是独立初始化的。 

对于每个后续位置，算法都会评估通过道路可到达的所有可能的前驱城市。 每个转换都会添加`0`或者`1`取决于当前城市的名称是否与目标单词匹配。 

每当发现更好的转换时，就会更新 DP 值和相应的父指针。 

处理完所有状态后，算法在最后一层选择成本最小的城市，并使用父表重建路径。 

## 解决方案```go
package main

import "math"

func mostSimilar(n int, roads [][]int, names []string, targetPath []string) []int {

	targetLength := len(targetPath)

	// Build adjacency list
	graph := make([][]int, n)

	for _, road := range roads {
		u := road[0]
		v := road[1]

		graph[u] = append(graph[u], v)
		graph[v] = append(graph[v], u)
	}

	inf := math.MaxInt32

	// dp[i][city] = minimum cost
	dp := make([][]int, targetLength)

	// parent[i][city] = previous city
	parent := make([][]int, targetLength)

	for i := 0; i < targetLength; i++ {
		dp[i] = make([]int, n)
		parent[i] = make([]int, n)

		for city := 0; city < n; city++ {
			dp[i][city] = inf
			parent[i][city] = -1
		}
	}

	// Initialize first row
	for city := 0; city < n; city++ {
		if names[city] == targetPath[0] {
			dp[0][city] = 0
		} else {
			dp[0][city] = 1
		}
	}

	// Fill DP
	for i := 1; i < targetLength; i++ {

		for currCity := 0; currCity < n; currCity++ {

			mismatchCost := 1

			if names[currCity] == targetPath[i] {
				mismatchCost = 0
			}

			for _, prevCity := range graph[currCity] {

				candidate := dp[i-1][prevCity] + mismatchCost

				if candidate < dp[i][currCity] {
					dp[i][currCity] = candidate
					parent[i][currCity] = prevCity
				}
			}
		}
	}

	// Find best ending city
	endCity := 0

	for city := 1; city < n; city++ {
		if dp[targetLength-1][city] < dp[targetLength-1][endCity] {
			endCity = city
		}
	}

	// Reconstruct path
	path := make([]int, targetLength)

	current := endCity

	for i := targetLength - 1; i >= 0; i-- {
		path[i] = current
		current = parent[i][current]
	}

	return path
}
```Go 实现遵循与 Python 解决方案相同的 DP 逻辑。 

切片用于邻接表和DP表。 由于 Go 没有内置的整数无穷大值，`math.MaxInt32`被用作一个大的哨兵值。 

父指针被初始化为`-1`表示没有前任。 

Go 数组和切片自动初始化为零，因此仅对于无穷大值和父状态才需要显式初始化。

 ## 边缘情况

 当没有城市名称与任何目标字符串匹配时，就会出现一种重要的边缘情况。 在这种情况下，每个位置都会贡献不匹配成本`1`。 幼稚的实现可能会错误地假设至少存在一个匹配节点，并且无法正确初始化状态。 此实现可以自然地处理这种情况，因为不匹配成本是为每个节点独立计算的。 

另一个棘手的情况是多个城市同名。 该算法不能简单地将名称映射到唯一节点。 相反，DP 州按实际城市索引而不是城市名称进行索引。 这确保了即使名称相同，不同的图形位置仍然可以区分。 

第三个重要的边缘情况涉及重复的节点访问。 由于允许重游，最优路径可能会在少数城市之间来回多次。 一些图算法错误地将节点标记为全局访问，这会错误地消除有效的解决方案。 此实现从不使用访问集，因此完全支持重复遍历。 

第四个微妙的边缘情况是路径重建。 如果在 DP 转换期间未正确存储父指针，则算法可能会计算出正确的最小成本，但无法恢复实际路径。 专注的`parent`表确保记住每个最佳转换并可以在以后准确地重建。
