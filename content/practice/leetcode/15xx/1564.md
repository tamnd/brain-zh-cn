[LeetCode 问题 1564](https://leetcode.com/problems/put-boxes-into-the-warehouse-i/)

 **难度：** 🟡 中等
 **主题：** 数组、贪婪、排序

 ## 解决方案

 ## 问题理解

 该问题给了我们两个数组：

 -`boxes`，其中每个值代表盒子的高度
 -`warehouse`，其中每个值代表仓库中房间的高度

 每个盒子都有宽度`1`，并且每个仓库房间也有宽度`1`。 箱子不能堆叠，因此每个房间最多可容纳一个箱子。 

重要的限制是箱子如何在仓库中移动。 盒子只能从左侧插入并向右推。 如果盒子遇到高度小于盒子高度的房间，则盒子在进入该房间之前停止。 由于盒子挡住了路径，它后面的每个盒子也无法进一步移动。 

这意味着放置在仓库深处的盒子必须能够穿过它之前的每个房间。 

目标是最大限度地增加仓库中可放置的箱子数量。 

一个重要的观察是，房间的有效高度不仅仅是其自身的高度。 一个盒子必须首先穿过之前的所有房间。 因此，该位置的可用高度`i`实际上是：```
min(warehouse[0], warehouse[1], ..., warehouse[i])
```如果任何较早的房间较短，则该较早的房间将成为每个较晚房间的瓶颈。 

限制条件很大：

 - 最多`10^5`盒子
 - 最多`10^5`仓库房间

 这立即告诉我们二次方法会太慢。 我们需要一个接近的算法`O(n log n)`或更好。 

一些边缘情况很重要：

 - 第一个仓库房间可能非常小，限制了后面的每个房间。 
- 箱子的数量可能多于房间的数量。 
- 许多盒子可能太高，无法放置在任何地方。 
- 仓库高度可能急剧下降，造成瓶颈。 
- 最佳放置可能需要首先使用较小的盒子。 

## 方法

 ### 蛮力方法

 一个简单的方法是尝试每一种可能的放置策略。 

一种可能的暴力想法是：

 1. 对于每个盒子，尝试将其放入尽可能深的房间。 
2. 检查箱子是否可以穿过之前的所有房间。 
3. 将房间标记为已占用。 
4. 对所有排列或贪婪选择重复此操作。 

这最终会找到正确的答案，因为它探索了有效的位置。 然而，它的效率极低。 

即使是扫描仓库中每个箱子的简化蛮力策略也需要反复检查房间的可达性和占用率。 高达`10^5`元素，重复扫描变得非常昂贵。 

主要问题是幼稚的布局决策很容易变得次优。 太早放置的大盒子可能会挡住本来可以装在里面更深处的小盒子。 

### 关键见解

 关键的见解是每个仓库位置都受到从左侧遇到的最小高度的限制。 

例如：```
warehouse = [5, 3, 4, 2]
effective  = [5, 3, 3, 2]
```尽管房间`2`有高度`4`, 一个盒子比`3`永远无法到达它，因为房间`1`挡住了道路。 

一旦我们将仓库预处理到这些有效高度，问题就变得简单多了。 

然后，我们按升序对箱子进行排序，并贪婪地尝试将最小的箱子放入最狭窄的可用仓库空间中。 

为什么这有效？ 

- 小房间仅可容纳小箱子。 
- 大房间可容纳小型和大型箱子。 
- 因此，我们应尽可能为较大的箱子预留较大的房间。 

这是经典的贪婪匹配策略。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(m × n) 到指数，具体取决于策略 | O(1) 到 O(m) | 重复放置检查变得太慢|
 | 最佳 | O(m log m + n) | O(m log m + n) | O(1) 额外，不包括排序 | 对箱子进行排序并贪婪地匹配有效仓库高度 |

 这里，`m = len(boxes)`和`n = len(warehouse)`。 

## 算法演练

 1. 预处理仓库高度。 

从左到右遍历仓库。 对于每个房间，将其高度替换为迄今为止看到的最小高度。 

这将仓库转变为有效的可达高度。 

例子：```
warehouse = [5,3,4,2]
effective = [5,3,3,2]
```此步骤是必要的，因为盒子必须经过所有较早的房间才能到达较晚的房间。 
2. 按升序对框进行排序。 

较小的盒子更灵活，可以容纳更多的房间。 排序允许我们首先贪婪地将盒子放入最小的可用空间中。 
3.从右向左开始填充仓库。 

最右边的房间通常是最受限制的，因为它们的有效高度受到所有早期房间的限制。 

我们使用：

 -`box_index`跟踪当前最小的未使用框
 - 从右到左遍历仓库房间
 4. 对于每个仓库房间：

 - 如果当前盒子适合，请将其放置并移动到下一个盒子。 
- 如果不适合，请跳过该房间，因为较大的盒子也无法容纳。 
5. 继续直至：

 - 所有房间均已处理，或
 - 所有盒子都已放置
 6. 返回放置的盒子数量。 

### 为什么它有效

 该算法之所以有效，是因为仓库约束在预处理后创建了单调结构。 

一旦计算出有效高度，将较小的盒子放置在较小的空间中始终是最佳选择。 如果一个小房间闲置，而一个较大的房间占用一个小盒子，我们以后可能无法放置一个较大的盒子。 通过从最小的可进入位置到更大的位置处理房间，并始终使用最小的配件盒，我们最大限度地提高了成功放置的总数。 

这种贪婪的策略永远不会在不必要的小盒子上浪费大容量。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxBoxesInWarehouse(self, boxes: List[int], warehouse: List[int]) -> int:
        # Step 1: preprocess warehouse heights
        for i in range(1, len(warehouse)):
            warehouse[i] = min(warehouse[i], warehouse[i - 1])

        # Step 2: sort boxes
        boxes.sort()

        box_index = 0
        placed_boxes = 0

        # Step 3: fill warehouse from right to left
        for room_index in range(len(warehouse) - 1, -1, -1):
            if box_index < len(boxes) and boxes[box_index] <= warehouse[room_index]:
                placed_boxes += 1
                box_index += 1

        return placed_boxes
```实施首先将仓库转换为其有效高度。 每个房间都成为从左侧到目前为止看到的最小值。 这对实际的可访问性约束进行了建模。 

接下来，这些框按升序排序。 这使得算法可以贪婪地将剩余的最小盒子放入每个可用房间中。 

然后算法从右到左迭代仓库。 最右边的房间通常是最受限制的，因为它们的有效高度包括之前的所有瓶颈。 

每当当前最小的盒子适合当前房间时，算法就会放置它并前进到下一个盒子。 如果盒子不适合，则跳过该房间，因为没有更大的盒子可以容纳。 

最后返回成功放置盒子的总数。 

## 解决方案```go
package main

import "sort"

func maxBoxesInWarehouse(boxes []int, warehouse []int) int {
	// Step 1: preprocess warehouse heights
	for i := 1; i < len(warehouse); i++ {
		if warehouse[i] > warehouse[i-1] {
			warehouse[i] = warehouse[i-1]
		}
	}

	// Step 2: sort boxes
	sort.Ints(boxes)

	boxIndex := 0
	placedBoxes := 0

	// Step 3: fill warehouse from right to left
	for roomIndex := len(warehouse) - 1; roomIndex >= 0; roomIndex-- {
		if boxIndex < len(boxes) && boxes[boxIndex] <= warehouse[roomIndex] {
			placedBoxes++
			boxIndex++
		}
	}

	return placedBoxes
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个显着的区别是 Go 不提供内置的`min`旧标准库版本中的整数函数，因此预处理步骤使用手动比较。 

直接使用Go切片，并进行排序`sort.Ints`。 

由于所有值都在`10^9`, 标准围棋`int`值完全不受溢出问题的影响。

 ## 边缘情况

 当第一个仓库房间非常小时，就会出现一个重要的边缘情况。 由于每个箱子都必须经过第一个房间，因此该房间成为整个仓库的瓶颈。 例如：```
warehouse = [1, 100, 100, 100]
```尽管后来的房间很大，但只有盒子的高度`1`完全可以进仓库。 预处理步骤正确地将仓库转换为：```
[1,1,1,1]
```这确保算法正确处理此限制。 

当盒子多于房间时，就会出现另一个重要的边缘情况。 由于每个房间只能包含一个盒子，因此答案永远不能超过房间的数量。 贪心算法自然会处理这个问题，因为它只会遍历房间一次，并且每个房间最多放置一个盒子。 

第三个棘手的情况涉及超大盒子与较小盒子的混合。 考虑：```
boxes = [100,1,1]
warehouse = [2,2,2]
```幼稚的策略可能会浪费时间尝试先放置超大的盒子。 通过按升序对盒子进行排序，该算法会优先考虑实际可以容纳的较小盒子，从而最大化放置的总数。 

当仓库高度在小房间之后向上波动时，会发生另一种微妙的边缘情况：```
warehouse = [5,2,6,7]
```尽管后来的房间显得很大，但房间的高度`2`阻止访问。 预处理步骤将其转换为：```
[5,2,2,2]
```它正确地模拟了每个房间的真实可达容量。
