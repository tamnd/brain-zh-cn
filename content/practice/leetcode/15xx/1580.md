[LeetCode 问题 1580](https://leetcode.com/problems/put-boxes-into-the-warehouse-ii/)

 **难度：** 🟡 中等
 **主题：** 数组、贪婪、排序

 ## 解决方案

 ## 问题理解

 在这个问题中，我们有两个数组：

 -`boxes`，其中每个值代表盒子的高度
 -`warehouse`，其中每个值代表仓库中房间的高度

 每个盒子都有宽度`1`，并且每个仓库房间也有宽度`1`。 盒子不能堆叠，这意味着每个房间最多可以容纳一个盒子。 

问题的重要部分是运动限制。 盒子可以从仓库的左侧或右侧插入。 然而，当盒子向内移动时，如果遇到一个比盒子本身短的房间，它就无法越过那个房间。 这意味着盒子停在阻挡室之前。 

目标是最大限度地增加可以成功放入仓库的箱子数量。 

一个关键的观察结果是，实际房间高度并不总是有效的可用高度。 例如，如果我们从左侧推动一个盒子，那么沿路径遇到的最小高度决定了该盒子是否可以到达某个房间。 同样，当从右侧推动时，限制因素是从右侧看到的最小高度。 

限制条件很大：

 - 最多`10^5`盒子
 - 最多`10^5`仓库房间
 - 高度可以大到`10^9`这些限制立即排除了指数或重型模拟方法。 我们需要一个接近的算法`O(n log n)`或更好。 

一些边缘情况很重要：

 - 仓库可能包含非常小的瓶颈房间，限制了移动。 
- 箱子的数量可能多于房间的数量。 
- 非常大的盒子可能永远无法放在任何地方。 
- 由于允许从两侧插入，因此即使一个方向被阻挡，也可以到达房间。 
- 预处理后，多个房间实际上可以具有相同的可用高度。 

## 方法

 ### 蛮力方法

 一个幼稚的解决方案会尝试所有可能的放置策略。 

思考这个问题的一种方法是：

 1. 以不同的顺序尝试盒子。 
2. 对于每个框，尝试从左侧或右侧插入。 
3. 模拟在仓库中的移动。 
4. 将房间标记为已占用。 
5. 跟踪成功插入框的最大数量。 

这种暴力策略的成本极其高昂，因为：

 - 盒装订单数量较多。 
- 每次插入可能需要扫描仓库。 
- 选择左或右会使分支的可能性加倍。 

即使没有预处理的简化贪婪模拟仍然需要重复扫描仓库中的每个盒子，从而导致`O(n^2)`行为。 

和`10^5`元素，这样的方法太慢了。 

### 关键见解

 核心观点是每个仓库位置的有效容量取决于两侧的可达性。 

对于一个房间`i`：

 - 从左边开始，可以到达的最高盒子受到最小房间高度的限制`0`到`i`- 从右侧开始，受到最低房间高度的限制`i`到`n - 1`由于我们可以从任一侧插入，因此房间的可用高度`i`变成：```
max(left_min[i], right_min[i])
```该值表示可以放入该房间的最大盒子。 

一旦我们计算出这些有效的房间容量，问题就变成了：

 > 将尽可能多的盒子匹配到盒子高度 <= 房间容量的房间中。 

现在这是一个经典的贪婪匹配问题。 

我们排序：

 - 框按升序排列
 - 有效房间容量按升序排列

 然后我们贪婪地将剩余的最小的盒子放入可以容纳它的最小的房间中。 

这种贪婪策略是最优的，因为使用更大的空间来容纳更小的盒子会不必要地浪费容量。

 ## 算法演练

 1. 计算左侧最小数组。 

创建一个数组`left_min`在哪里：```sql
left_min[i] = minimum warehouse height from 0 to i
```这代表可以到达房间的最高盒子`i`从左侧进入时。 
2. 计算正确的最小数组。 

创建一个数组`right_min`在哪里：```sql
right_min[i] = minimum warehouse height from i to n - 1
```这代表可以到达房间的最高盒子`i`从右侧进入时。 
3. 计算有效房间容量。 

对于每个房间`i`：```
effective[i] = max(left_min[i], right_min[i])
```由于箱子可以从任意一侧进入，因此我们选择更容易进入的位置。 
4. 对盒子进行分类。 

种类`boxes`按升序排列，因此我们首先放置较小的盒子。 
5. 对有效房间容量进行排序。 

按升序对有效容量进行排序。 
6. 贪婪地将盒子与房间匹配。 

使用两个指针：

 - 一个用于盒子
 - 一间房间

 如果当前盒子适合当前房间：

 - 放置它
 - 向前移动两个指针

 否则：

 - 仅向前移动房间指针即可找到更大的房间
 7. 返回匹配框的数量。 

### 为什么它有效

 预处理正确地计算了可以从任一侧到达每个房间的最大可能的盒子。 

经过这种转变，问题就减少到最大化盒子和房间容量之间的匹配。 

对两个数组进行排序并贪婪地匹配尽可能小的有效对是最佳的，因为它为更大的盒子保留了更大的空间。 这是区间和赋值匹配问题中使用的标准贪心证明。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxBoxesInWarehouse(self, boxes: List[int], warehouse: List[int]) -> int:
        n = len(warehouse)

        left_min = [0] * n
        right_min = [0] * n

        left_min[0] = warehouse[0]
        for i in range(1, n):
            left_min[i] = min(left_min[i - 1], warehouse[i])

        right_min[n - 1] = warehouse[n - 1]
        for i in range(n - 2, -1, -1):
            right_min[i] = min(right_min[i + 1], warehouse[i])

        effective = [
            max(left_min[i], right_min[i])
            for i in range(n)
        ]

        boxes.sort()
        effective.sort()

        box_index = 0
        room_index = 0

        placed = 0

        while box_index < len(boxes) and room_index < n:
            if boxes[box_index] <= effective[room_index]:
                placed += 1
                box_index += 1
                room_index += 1
            else:
                room_index += 1

        return placed
```实现首先从两个方向预处理仓库。`left_min[i]`跟踪从左侧移动到房间时遇到的最小高度`i`。 相似地，`right_min[i]`跟踪从右侧遇到的最小高度。 

对于每个房间，我们计算这两个值的最大值，因为盒子可以从任一方向进入。 

经过预处理后，仓库被转换为独立容量列表。 到那时，问题就变成了贪婪匹配问题。 

两个数组都经过排序，以便首先匹配较小的框。 这可以防止在小盒子上浪费大容量的房间。 

两指针匹配循环有效地计算最大有效位置。 

## 解决方案```go
package main

import "sort"

func maxBoxesInWarehouse(boxes []int, warehouse []int) int {
	n := len(warehouse)

	leftMin := make([]int, n)
	rightMin := make([]int, n)

	leftMin[0] = warehouse[0]
	for i := 1; i < n; i++ {
		if leftMin[i-1] < warehouse[i] {
			leftMin[i] = leftMin[i-1]
		} else {
			leftMin[i] = warehouse[i]
		}
	}

	rightMin[n-1] = warehouse[n-1]
	for i := n - 2; i >= 0; i-- {
		if rightMin[i+1] < warehouse[i] {
			rightMin[i] = rightMin[i+1]
		} else {
			rightMin[i] = warehouse[i]
		}
	}

	effective := make([]int, n)

	for i := 0; i < n; i++ {
		if leftMin[i] > rightMin[i] {
			effective[i] = leftMin[i]
		} else {
			effective[i] = rightMin[i]
		}
	}

	sort.Ints(boxes)
	sort.Ints(effective)

	boxIndex := 0
	roomIndex := 0
	placed := 0

	for boxIndex < len(boxes) && roomIndex < n {
		if boxes[boxIndex] <= effective[roomIndex] {
			placed++
			boxIndex++
			roomIndex++
		} else {
			roomIndex++
		}
	}

	return placed
}
```Go 实现密切反映了 Python 逻辑。 

Go 没有提供内置的`min`和`max`整数函数，因此使用显式比较。 

切片的大小是动态调整的，其行为与 Python 列表类似。 该算法使用`sort.Ints`用于对两个数组进行排序。 

整数溢出不是问题，因为该算法仅执行比较，而不执行涉及大和或乘积的算术运算。

 ## 边缘情况

 当仓库中间有一个非常小的瓶颈房间时，就会出现一种重要的边缘情况。 例如：```
warehouse = [5,1,5]
```天真的方法可能会错误地假设中心房间完全阻止了两侧的通道。 然而，由于箱子可以从任意一侧进入，因此外部房间仍然可以独立使用。 使用左右最小数组的预处理可以正确捕获此行为。 

另一个重要的情况是盒子多于房间的情况。 由于每个房间只能容纳一个盒子，所以答案永远不能超过仓库房间的数量。 贪婪匹配自然会处理这个问题，因为一旦所有房间都用完，匹配就会停止。 

当输入中大框出现在小框之前时，就会出现第三种棘手的情况。 如果不进行排序，贪婪策略可能会提前浪费大容量的房间并减少放置的总数。 排序可确保先放置较小的盒子，从而为稍后放置较大的盒子保留灵活性。 

最后的边缘情况涉及对于每个房间来说都太大的盒子。 在这种情况下，匹配循环只是跳过房间直到耗尽，并且算法正确返回`0`如果不存在有效的展示位置。
