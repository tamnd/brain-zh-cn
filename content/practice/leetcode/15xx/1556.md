[LeetCode 第 1556 题](https://leetcode.com/problems/thousand-separator/)

 **难度：** 🟢简单
 **主题：** 字符串

 ## 解决方案

 ## 问题理解

 该问题要求我们格式化一个非负整数，以便每组三个数字之间用点分隔（`.`），从数字的右侧开始。 

例如，数字`1234567`应该成为`"1.234.567"`因为数字被分组为：

 -`1`-`234`-`567`输入是单个整数`n`，并且输出必须是该整数的字符串表示形式，并插入了适当的分隔符。 

限制很小：

 -`0 <= n <= 2^31 - 1`这告诉我们几个重要的事情：

 - 输入始终适合标准 32 位有符号整数。 
- 最大数字最多为 10 位。 
- 性能不是问题，因为输入大小很小。 
- 简单的基于字符串的解决方案是完全可以接受的。 

有几个重要的边缘情况需要考虑。 

第一个边缘情况是`0`。 如果不正确地处理组中的数字，粗心的实现可能会返回空字符串。 正确答案很简单`"0"`。 

另一种边缘情况是数字少于四位数，例如`7`或者`987`。 这些数字不应包含任何点，因为它们没有千位组。 

我们还需要正确处理位数不是三的倍数的数字。 例如：

-`1234`变成`"1.234"`-`12345`变成`"12.345"`最左边的组可能包含一位或两位数字，而所有其余组只包含三位数字。 

## 方法

 ### 蛮力方法

 暴力式解决方案将使用取模和除法运算重复从数字中提取数字。 

这个想法是：

 1. 使用重复取最后一位数字`n % 10`2. 建立三位数组
 3. 在组之间插入点
 4. 将最终结果反转，因为数字是从右向左提取的

 这种方法之所以有效，是因为每个十进制数字都可以单独处理，并且将数字以三个为一组进行分组自然符合格式要求。 

然而，对于这个问题，该方法不必要地复杂。 手动管理数字组会引入额外的簿记，包括：

 - 计算数字
 - 处理部分组
 - 反转中间字符串
 - 小心放置分隔符

 尽管约束很小并且该方法仍然足够快，但它比必要的更容易出错。 

### 最佳方法

 关键的观察是数字可以首先转换为字符串。 一旦我们有了字符串形式，问题就变成了简单的字符串格式化。 

我们以三个字符为一组从右到左处理数字。 每次我们收集到三位数字时，我们都会在下一组数字之前插入一个点。 

这很有效，因为：

 - 字符串切片很简单
 - 三组自然地表示为子串
 - 我们避免手动数字提取和反转复杂性

 该算法简单、可读且高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(d) | O(d) | 使用模和除法一一提取数字 |
 | 最佳 | O(d) | O(d) | 从右侧使用字符串切片和分组 |

 这里，`d`表示整数中的位数。 

## 算法演练

 1. 转换整数`n`成字符串。 

这使我们能够直接处理数字字符，而不是重复使用算术运算。 字符串操作更简单，并且不易因格式问题而出错。 
2. 创建一个空列表来存储数字组。 

每组最多包含三位数字。 使用列表非常高效，因为附加组的速度很快。 
3. 从字符串末尾开始，以三为步向左移动。 

由于从右侧开始每三位数字插入千位分隔符，因此从右到左的处理自然符合格式化规则。 
4. 提取长度为三的子串。 

对于每次迭代：

 - 取出子字符串`max(0, i - 3)`到`i`- 将该子字符串附加到组列表中

 最左边的组可能包含少于三位的数字，这是由切片边界自动处理的。 
5. 反转组列表。 

由于组是从右到左收集的，因此反转可以恢复正确的从左到右的顺序。 
6. 使用以下方式加入所有群组`"."`。 

这会产生最终的格式化字符串。 

### 为什么它有效

 该算法之所以有效，是因为十进制数从最右边的数字开始被分成三位数的块。 通过以三步从字符串末尾进行迭代，每个提取的子字符串完全对应于一个有效的千组。 反转收集的组可恢复原始顺序，并用点将它们连接起来产生所需的格式。 

## Python 解决方案```python
class Solution:
    def thousandSeparator(self, n: int) -> str:
        digits = str(n)
        groups = []

        for i in range(len(digits), 0, -3):
            start = max(0, i - 3)
            groups.append(digits[start:i])

        groups.reverse()

        return ".".join(groups)
```实现首先将整数转换为名为的字符串`digits`。 这使得直接对字符组进行切片变得容易。 

这`groups`list 存储最多三位数字的块。 循环从字符串的末尾开始，一次向后移动三个位置。 

对于每次迭代：

 -`start`标记当前组的开始
 -`digits[start:i]`提取子字符串
 - 子字符串被附加到`groups`由于组是从右到左收集的，因此列表随后会颠倒过来。 

最后，`".".join(groups)`将所有组组合成所需的格式化字符串。 

## 解决方案```go
package main

import (
	"strings"
)

func thousandSeparator(n int) string {
	digits := []byte(string(rune(n + '0')))

	if n >= 10 {
		digits = []byte{}
		numStr := strconv.Itoa(n)

		for i := len(numStr); i > 0; i -= 3 {
			start := i - 3
			if start < 0 {
				start = 0
			}

			digits = append([]byte(numStr[start:i]), append([]byte("."), digits...)...)
		}

		if digits[0] == '.' {
			digits = digits[1:]
		}

		return string(digits)
	}

	return string(digits)
}
```下面显示了一个更干净、更惯用的 Go 实现。```go
package main

import (
	"strconv"
	"strings"
)

func thousandSeparator(n int) string {
	numStr := strconv.Itoa(n)
	groups := []string{}

	for i := len(numStr); i > 0; i -= 3 {
		start := i - 3
		if start < 0 {
			start = 0
		}

		groups = append(groups, numStr[start:i])
	}

	for left, right := 0, len(groups)-1; left < right; left, right = left+1, right-1 {
		groups[left], groups[right] = groups[right], groups[left]
	}

	return strings.Join(groups, ".")
}
```Go 版本遵循与 Python 实现相同的逻辑。 

一些特定于 Go 的细节值得注意：

 -`strconv.Itoa`将整数转换为字符串。 
- 字符串切片存储在`groups`。 
- Go 没有提供内置的切片反向函数，因此我们使用两个指针手动交换元素。 
-`strings.Join`使用组合组`"."`。 

由于限制很小，因此无需担心格式化期间的内存使用或溢出。

 ## 边缘情况

 一个重要的边缘情况是值`0`。 某些重复将数字除以十的实现可能会意外地完全跳过处理并返回空字符串。 在此实现中，将整数转换为字符串立即保证`"0"`已正确处理。 

另一个重要的边缘情况是恰好三位数字的数字，例如`999`。 有缺陷的实现可能会错误地插入前导分隔符并产生`".999"`。 由于该算法仅在分组完成后才在组之间插入分隔符，因此不会出现不必要的分隔符。 

第三种边缘情况是位数不能被三整除的数字，例如`12345`。 最左边的组仅包含两位数字，而所有其他组都包含三位数。 切片逻辑自然地通过使用来处理这个问题`max(0, i - 3)`对于组边界，确保第一组可以更短，而无需特殊情况逻辑。 

最终的边缘情况是最大允许值，`2147483647`。 这验证了该实现是否正确处理多个分隔符和更大的数字计数，而没有溢出或格式错误。 由于该算法对字符串进行操作，因此一旦转换完成，整数大小就不会产生额外的复杂性。
