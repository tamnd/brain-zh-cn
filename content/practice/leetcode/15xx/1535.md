[LeetCode 问题 1535](https://leetcode.com/problems/find-the-winner-of-an-array-game/)

 **难度：** 🟡 中等
 **主题：** 数组、模拟

 ## 解决方案

 ## 问题理解

 该问题描述了在**不同整数**数组上进行的竞争性游戏。 在每一轮中，仅比较前两个元素。 较大的数字获胜，并留在数组的前面，而较小的数字则移至末尾。 重复此过程，直到一个数字达到**`k`连续获胜**。 

简单来说，我们反复比较当前的冠军，它位于索引处`0`，对阵索引处的下一个挑战者`1`。 如果冠军再次获胜，其连胜纪录将会增加。 如果挑战者更大，则挑战者将成为新的冠军并开始新的连胜`1`。 

输入包括：

 -`arr`，不同整数的数组。 
-`k`，结束游戏所需的连续胜利次数。 

预期输出是最终达到的整数`k`连续获胜。 

这些约束很重要，因为它们强烈影响我们能够负担的解决方案类型：

 -`arr.length`可以大到`10^5`，这意味着任何二次模拟都会太慢。 
-`k`可以大到`10^9`，如果我们逐字模拟直到`k`获胜。 
- 所有整数都是不同的，这保证了比较期间没有联系。 
- 问题保证总会有赢家。 

从约束中观察到的一个关键是`k`可以比数组大小大得多。 由于数组中最大的数字一旦到达前面就永远不会输，所以最终它一定会成为胜利者。 这种见解有助于我们避免模拟数十亿轮。 

需要记住的一些重要的边缘情况包括：

 - 当`k`非常大，比`arr.length`，因为简单的模拟可能会运行太长时间。 
- 当最大元素已经在开始时，因为它可能会立即主导游戏。 
- 多次更换冠军后出现获胜者时，需要仔细跟踪连续胜利。 
- 非常小的数组，例如长度`2`，其中较大的元素总是获胜。 

## 方法

 ### 蛮力方法

 一个简单的想法是完全按照描述来模拟游戏。 我们反复比较前两个元素，将较大的元素保留在前面，将较小的元素移到后面，并跟踪连续的胜利。 

这种方法是正确的，因为它完全遵循问题陈述。 最终，一个元素将实现`k`连续获胜，模拟结束。 

然而，当以下情况时，此方法变得不切实际：`k`非常大。 自从`k`可以达到`10^9`，我们可能需要在终止之前模拟数十亿轮。 尽管游戏具有重复结构，但暴力方法并没有利用它，从而使其速度太慢。 

### 最佳方法，冠军追踪

 关键的见解是我们**实际上不需要模拟整个队列移动**。 

注意游戏过程中发生的事情：

 - 每次比较的获胜者都保持在前面。 
- 失败者离开并变得与当前的连胜无关。 
- 最终，**数组中最大的元素**必须到达前面。 
- 一旦最大的元素到达前面，它就永远不会再输，因为所有元素都是不同的。 

这意味着我们可以一次性处理数组，同时保持**当前冠军**及其**连续获胜次数**。 

我们将冠军与每个新元素进行比较：

 - 如果冠军更大，则赢得另一轮。 
- 如果挑战者更大，则挑战者将成为新的冠军并连续获胜`1`。 
- 一旦连胜达到`k`，我们将冠军归来。 

如果没有元素达到`k`遍历时获胜，那么最大元素一定就是答案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(k) | O(n) | 准确模拟队列，时太慢`k`是巨大的|
 | 最佳 | O(n) | O(1) | O(1) | 无需完全模拟即可追踪当前冠军 |

 ## 算法演练

 1. 将当前冠军初始化为数组的第一个元素。 

第一个元素自然以冠军开始，因为游戏总是以`arr[0]`相对`arr[1]`。 
2. 初始化连续获胜计数器`0`。 

该变量跟踪当前冠军连续获胜的回合数。 
3. 从索引开始迭代数组`1`。 

每个元素都充当当前冠军的下一个挑战者。 
4. 比较冠军和挑战者。 

- 如果冠军更大，则增加连续获胜计数器，因为冠军赢得了另一轮比赛。 
- 如果挑战者更大，则将冠军更新为挑战者并将获胜计数器重置为`1`，因为新冠军刚刚赢得了第一轮比赛。 
5、每次比较后，检查冠军是否达到`k`连续获胜。 

如果是这样，请立即归还冠军，因为游戏将在此时结束。 
6. 如果循环结束而没有人到达`k`获胜，回归冠军。 

在这个阶段，冠军必须是阵中最大的元素，永远不能输。 

### 为什么它有效

 核心不变量是变量`champion`处理每次比较后始终表示当前的前面元素。 实际游戏中的每一轮都会将当前冠军与下一个挑战者进行比较，这与我们的迭代顺序完全匹配。 

因为所有元素都是不同的，所以最大元素永远不会丢失。 因此，如果没有数字达到`k`在遍历过程中获胜，最大元素最终必须永远占据主导地位。 由于我们的冠军最终将成为最大元素，因此返回它是正确的。 

## Python 解决方案```python
from typing import List

class Solution:
    def getWinner(self, arr: List[int], k: int) -> int:
        champion = arr[0]
        consecutive_wins = 0

        for i in range(1, len(arr)):
            challenger = arr[i]

            if champion > challenger:
                consecutive_wins += 1
            else:
                champion = challenger
                consecutive_wins = 1

            if consecutive_wins >= k:
                return champion

        return champion
```实现首先将第一个元素指定为当前元素`champion`和设置`consecutive_wins`到`0`。 

然后，我们迭代数组的其余部分，将每个元素视为挑战者。 如果冠军更大，它会继续获胜并且连胜次数会增加。 否则，挑战者将取代冠军并开始新的连胜`1`。 

每次比较后，我们都会检查冠军是否达到了目标`k`获胜。 如果有，我们立即返回。 

如果循环结束但未到达`k`，此时的冠军一定是数组中最大的元素，保证最终获胜。 

## 解决方案```go
func getWinner(arr []int, k int) int {
	champion := arr[0]
	consecutiveWins := 0

	for i := 1; i < len(arr); i++ {
		challenger := arr[i]

		if champion > challenger {
			consecutiveWins++
		} else {
			champion = challenger
			consecutiveWins = 1
		}

		if consecutiveWins >= k {
			return champion
		}
	}

	return champion
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 由于该问题保证了一个至少包含两个元素的有效数组，因此我们可以安全地访问`arr[0]`无需额外检查。 

Go 切片直接使用，整数溢出不是问题，因为值完全在 Go 的整数范围内。 不需要额外的数据结构，因此实现在内存使用方面保持不变。

 ## 边缘情况

 当 ** 时会出现一种重要的边缘情况`k`远大于数组长度**，如`k = 10^9`。 简单的模拟可能会尝试数十亿轮，从而导致超出时间限制的错误。 我们的实现完全避免了这种情况，因为它只扫描数组一次。 最大元素一旦成为冠军，就保证永远获胜。 

当**最大的元素已经出现在数组的开头**时，会发生另一种边缘情况。 在这种情况下，第一个元素可能会立即累积胜利而无需被替换。 该实现自然地处理了这个问题，因为冠军保持不变并且其连胜次数增加，直到`k`已达到。 

第三个重要的边缘情况发生在**多个冠军变更过早发生**时，例如像这样的递增数组`[1,2,3,4,5]`。 有缺陷的实现可能无法在更换冠军后重置连续获胜计数器。 我们的解决方案正确地将连胜重置为`1`每当新冠军赢得第一场比赛时。 

最后，**最小数组大小为`2`**值得关注。 由于只有两个数字，较大的数字总是立即获胜并永远持续获胜。 该实现工作正常，因为单一比较建立了适当的冠军。
