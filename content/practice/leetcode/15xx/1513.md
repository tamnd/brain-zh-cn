[LeetCode 问题 1513](https://leetcode.com/problems/number-of-substrings-with-only-1s/)

 **难度：** 🟡 中等
 **主题：** 数学、字符串

 ## 解决方案

 ## 问题理解

 问题给出一个二进制字符串`s`，仅由字符组成`'0'`和`'1'`。 我们必须计算有多少个子串仅包含`'1'`人物。 

子字符串是字符串的连续部分。 例如，在字符串中`"111"`，有效子串完全由`'1'`是：

-`"1"`在索引 0 处
 -`"1"`在索引 1 处
 -`"1"`at index 2
 -`"11"`从索引 0 到 1
 -`"11"`从索引 1 到 2
 -`"111"`从索引 0 到 2

 这总共给出了 6 个子串。 

输出应该是此类子串的总数，模`10^9 + 7`。 取模是必要的，因为当字符串长度接近最大约束时，子字符串的数量可能会变得非常大。 

约束条件`1 <= s.length <= 10^5`告诉我们输入可能非常大。 任何直接检查所有可能的子字符串的解决方案都可能太慢。 由于字符串长度`n`有`O(n^2)`子串，我们需要一种更有效的方法。 

一些边缘情况很重要：

 - 一个字符串只包含`'0'`字符应返回 0。 
- 一个字符串只包含`'1'`字符应该计算每个可能的子字符串。 
- 交替模式，例如`"101010"`创建许多有效的小团体。 
- 长时间连续运行`'1'`字符可以产生非常大的计数，因此需要模运算。 

## 方法

 ### 蛮力方法

 最直接的解决方案是生成每个可能的子字符串并检查其中的所有字符是否都是`'1'`。 

对于每个起始索引`i`，我们可以尝试每个结束索引`j`，形成子串`s[i:j+1]`。 然后我们扫描子字符串以验证它是否只包含`'1'`。 

这种方法是正确的，因为它显式地检查每个子字符串并精确计算满足条件的子字符串。 

然而，对于给定的约束来说它太慢了。 有`O(n^2)`子字符串，检查每个子字符串可能需要`O(n)`时间。 这导致最坏情况的复杂性`O(n^3)`。 

即使进行了优化，子字符串枚举方法仍然至少是`O(n^2)`，这对于`n = 10^5`。 

### 最佳方法

 关键的观察是连续运行`'1'`字符可以用数学方法计算。 

假设我们遇到一个连续的块`'1'`字符长度`k`。 

例如：

-`"1"`贡献 1 个子串
 -`"11"`贡献3个子串
 -`"111"`贡献6个子串
 -`"1111"`贡献 10 个子串

 模式是：$$1 + 2 + 3 + \dots + k = \frac{k(k+1)}{2}$$我们不需要单独检查每个子串，而是只需要识别连续的子串组`'1'`人物。 

对于每个长度`k`，我们添加：$$\frac{k(k+1)}{2}$$到答案。 

由于我们只扫描字符串一次，这给出了`O(n)`解决方案。

 ## 算法演练

 1. 初始化变量`current_ones`跟踪当前连续的连续`'1'`人物。 
2. 初始化变量`total_substrings`存储最终答案。 
3. 逐个字符地遍历字符串。 
4. 如果当前字符是`'1'`, 增量`current_ones`因为连胜还在继续。 
5.每次我们延长一段时间`'1'`，我们获得以当前位置结尾的附加有效子字符串。 具体来说，如果条纹长度变为`k`，那么正好`k`有效子字符串在此位置结束。 
6. 添加`current_ones`到`total_substrings`。 
7. 如果当前字符是`'0'`， 重置`current_ones`为 0，因为连胜被打破。 
8. 应用模数`10^9 + 7`堆积时防止溢出。 
9. 处理完整个字符串后，返回结果。 

### 为什么它有效

 在每一个位置上，`current_ones`代表连续的个数`'1'`以该索引结尾的字符。 

如果条纹长度为`k`，那么正好有`k`在此位置结束的子字符串仅包含`'1'`:

 - 最后一个角色单独
 - 最后两个字符
 - 最后三个字符
 - ...
 - 整个连胜

 通过添加`current_ones`在每一步中，我们都会对每个有效子字符串进行一次计数。 

## Python 解决方案```python
class Solution:
    def numSub(self, s: str) -> int:
        MOD = 10**9 + 7

        current_ones = 0
        total_substrings = 0

        for char in s:
            if char == '1':
                current_ones += 1
                total_substrings += current_ones
            else:
                current_ones = 0

            total_substrings %= MOD

        return total_substrings
```该实现维护两个运行变量。`current_ones`存储当前连续序列的长度`'1'`人物。 每当一个`'1'`遇到时，连胜增加一分。 

关键的见解是，一条长度`k`准确贡献`k`以当前索引结尾的新子字符串。 因此，我们立即添加`current_ones`至总数。 

当一个`'0'`出现，条纹被打破，所以`current_ones`重置为 0。 

在累加期间应用模运算以将值保持在界限内。 

## 解决方案```go
func numSub(s string) int {
    const MOD int = 1000000007

    currentOnes := 0
    totalSubstrings := 0

    for _, char := range s {
        if char == '1' {
            currentOnes++
            totalSubstrings += currentOnes
        } else {
            currentOnes = 0
        }

        totalSubstrings %= MOD
    }

    return totalSubstrings
}
```Go 实现遵循与 Python 版本相同的逻辑。 

Go 使用显式整数声明，模常量被定义为整数常量。 由于结果可能会变大，因此在累加期间应用模可以防止溢出问题。 

该循环使用 Go 的字符迭代`range`字符串的语法。

 ## 边缘情况

 一个重要的边缘情况是仅包含零的字符串，例如`"00000"`。 有缺陷的实现可能会意外地计算空子字符串或无法正确重置连续运行次数。 In this implementation, every`'0'`立即重置`current_ones`为 0，确保不计算无效子字符串。 

另一个关键情况是只包含 1 的字符串，例如`"111111"`。 这将创建给定长度的最大数量的有效子字符串。 实现正确累加算术级数`1 + 2 + 3 + ... + n`，等于`n(n+1)/2`。 

第三个重要的边缘情况是交替字符，例如`"101010"`。 这里，每个有效子字符串的长度都是 1。一些实现错误地合并了分隔的字符串。 此解决方案避免了该问题，因为每当出现条纹计数器时，条纹计数器就会立即重置`'0'`遇到。 

最后一个重要的情况是最大输入大小，尤其是当字符串完全由 1 组成时。 子字符串的数量变得非常大，因此未能应用模运算可能会导致某些语言溢出。 该实现在累加过程中应用模数，即使对于最大允许输入也能确保正确性。
