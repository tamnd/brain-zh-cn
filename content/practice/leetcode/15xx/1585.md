[LeetCode 问题 1585](https://leetcode.com/problems/check-if-string-is-transformable-with-substring-sort-operations/)

 **难度：** 🔴难
 **主题：** 字符串、贪婪、排序

 ## 解决方案

 ## 问题理解

 这个问题问我们是否可以转换一位数字字符串，`s`，进入另一个数字字符串，`t`，使用特殊操作。 在一次操作中，我们选择任意非空连续子串`s`并按升序对该子字符串进行排序。 

重要的细节是，对子字符串进行排序只会将较小的数字向左移动，将较大的数字向右移动。 数字永远不能“跳过”位于其前面的较小数字，除非该较小数字也移动。 这会创建排序约束来确定转换是否可能。 

给定两个长度相等且仅由数字组成的字符串`'0'`通过`'9'`。 我们必须回来`true`如果某些子串排序操作序列可以转换`s`进入`t`，否则返回`false`。 

限制条件很大：

 -`1 <= n <= 10^5`- 仅使用数字

 由于输入大小可以达到十万个字符，因此任何指数或二次模拟方法都会太慢。 我们需要一个近线性时间的解决方案。 

有几个重要的观察结果和边缘情况：

 - 两个字符串必须包含相同的多组数字。 如果一位数字出现多次`t`比在`s`，转型是不可能的。 
- 数字不能任意交叉较小的数字。 例如，改造`"12345"`进入`"12435"`是不可能的，因为数字`'4'`需要向左移动过去`'3'`。 
- 重复的数字必须小心处理。 我们需要跟踪出现次数的确切使用顺序。 
- 由于数字仅限于`0`通过`9`，我们可以有效地维护每个数字的位置信息。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试模拟所有可能的子字符串排序操作并搜索可转换的序列`s`进入`t`。 

一种可能的实现是使用 BFS：

 1.从字符串开始`s`2. 通过对每个可能的子串进行排序，生成所有可获得的字符串
 3. 继续探索，直到`t`被发现或用尽所有可能性

 这种方法在理论上是正确的，因为它探索了整个可达状态空间。 如果`t`是可达的，BFS最终会找到它。 

然而，对于给定的约束，这是完全不切实际的。 一个长度的字符串`n`有`O(n^2)`子串，每次操作都可以生成一个新的串状态。 可到达状态的数量呈爆炸性增长，这使得即使对于小输入也是不可行的。 

### 关键见解

 我们不是模拟操作，而是分析子字符串排序实际上允许什么。 

按升序对子字符串进行排序可以让较小的数字向左移动。 但是，数字不能向左移动超过当前出现在其前面的较小数字。 

假设我们要放置数字`d`从`s`进入下一个所需位置`t`。 

在使用此事件之前`d`，我们必须确保没有更小的数字仍在等待`s`出现早于此`d`。 如果存在这样一个更小的数字，那么`d`永远无法跨越它，使转变变得不可能。 

这导致了贪婪的位置策略：

 - 将每个数字的位置存储在`s`- 过程`t`从左到右
 - 对于每个目标数字`d`，使用最早未出现的`d`从`s`- 在使用它之前，检查是否有任何较小的数字仍然有未使用的出现位置较早

 如果是的话，转型是不可能的。 

如果没有，我们可以安全地使用这个事件。 

因为数字只是`0`通过`9`，检查较小的数字是一项持续的工作。

 ## 算法演练

 1. 为每个数字创建一个队列`0`到`9`。 

每个队列存储该数字出现的所有索引`s`。 我们按升序存储它们，因为我们总是希望首先使用最早出现的事件。 
2.遍历字符串`s`。 

对于每个角色`s[i]`, 附加索引`i`到该数字对应的队列。 
3. 处理目标字符串`t`从左到右。 

对于每个数字`d`在`t`，我们尝试将其与最早未使用的出现进行匹配`d`从`s`。 
4. 检查是否为数字`d`仍有未使用的事件可用。 

如果队列为`d`为空，那么`t`需要出现更多次`d`比`s`包含。 返回`false`。 
5.让`current_index`是最早未使用的出现`d`。 

这是我们要移动到下一个目标位置的位置。 
6. 检查所有较小的数字。 

对于每个数字`smaller`从`0`到`d - 1`：

 - 如果那个较小的数字仍然有未使用的出现
 - 其最早未使用的位置是之前`current_index`那么转变是不可能的。 

这意味着当前数字需要跨过一个较小的数字才能向左移动，而子串排序无法实现这一点。 
7. 如果不存在阻塞的较小数字，则消耗该事件。 

从数字中删除前面的索引`d`的队列并继续处理。 
8. 如果所有数字都在`t`处理成功，返回`true`。 

### 为什么它有效

 该算法保持了这样一个不变性：数字的消耗顺序与所有有效排序操作后必须出现的相对顺序相同。 

在排序过程中，较大的数字可以自由向右移动，但它不能向左移动仍出现在原始字符串较早位置的较小数字。 通过检查是否有任何较小的未使用数字阻挡了当前数字，我们准确地捕获了使转换不可能的唯一条件。 

因为我们总是消耗每个数字最早出现的位置，所以贪婪策略保留了所有未来的可能性，并且永远不会跳过有效的配置。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def isTransformable(self, s: str, t: str) -> bool:
        positions = [deque() for _ in range(10)]

        for index, char in enumerate(s):
            digit = int(char)
            positions[digit].append(index)

        for char in t:
            digit = int(char)

            if not positions[digit]:
                return False

            current_index = positions[digit][0]

            for smaller_digit in range(digit):
                if positions[smaller_digit]:
                    if positions[smaller_digit][0] < current_index:
                        return False

            positions[digit].popleft()

        return True
```该实现首先创建十个队列，每个队列对应一个数字`0`到`9`。 每个队列存储该数字出现的位置`s`。 

当我们迭代时`s`，我们将索引附加到适当的队列中。 由于索引是按顺序添加的，因此每个队列自然保持排序。 

接下来我们处理`t`逐个字符。 对于每个数字，我们检索最早未使用的出现次数`s`。 

在消耗该事件之前，我们验证没有更小的数字仍然具有较早未使用的位置。 如果存在这样一个较小的数字，那么当前数字就不能通过子串排序合法地移到它前面。 

如果检查通过，我们将从队列中删除已使用的事件并继续。 

如果每个字符都处理成功，则转换有效。 

## 解决方案```go
func isTransformable(s string, t string) bool {
	positions := make([][]int, 10)

	for i, ch := range s {
		digit := int(ch - '0')
		positions[digit] = append(positions[digit], i)
	}

	pointers := make([]int, 10)

	for _, ch := range t {
		digit := int(ch - '0')

		if pointers[digit] >= len(positions[digit]) {
			return false
		}

		currentIndex := positions[digit][pointers[digit]]

		for smaller := 0; smaller < digit; smaller++ {
			if pointers[smaller] < len(positions[smaller]) {
				if positions[smaller][pointers[smaller]] < currentIndex {
					return false
				}
			}
		}

		pointers[digit]++
	}

	return true
}
```Go 实现使用切片而不是双端队列。 由于 Go 切片不支持有效的前部删除，因此我们为每个数字保留一个指针，指示下一个未使用的出现。 

这避免了重复的切片移位操作并保留整体线性复杂性。 

不存在整数溢出问题，因为索引的边界为`10^5`。

 ## 边缘情况

 当字符串包含重复数字时，会出现一种重要的边缘情况。 幼稚的实现可能只比较数字的数量，而忽略多次出现之间的排序约束。 例如，必须以正确的顺序消耗同一数字的不同副本。 基于队列的方法通过始终使用最早未使用的事件来自然地处理这个问题。 

另一个棘手的情况是当较大的数字需要向左移动到较小的数字时。 这是问题的中心不可能性条件。 在`"12345"`到`"12435"`, 数字`'4'`需要穿越`'3'`，这不能通过升序子字符串排序来实现。 该算法通过检查早期未使用的较小数字来显式检测到这一点。 

第三种边缘情况涉及已经相等的字符串。 一些解决方案错误地尝试不必要的转换或使逻辑过于复杂。 在此实现中，匹配的数字只是从队列中毫无问题地消耗掉，并且算法正确返回`true`。 

最后一个重要的情况是一个字符串比另一个字符串包含更多出现的数字。 尽管问题保证长度相等，但数字频率可能不同。 如果处理过程中所需的数字队列变空，算法立即返回`false`，正确识别不匹配。
