[LeetCode 问题 1536](https://leetcode.com/problems/minimum-swaps-to-arrange-a-binary-grid/)

 **难度：** 🟡 中等
 **主题：** 数组、贪婪、矩阵

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个`n x n`二进制矩阵称为`grid`。 每个单元格包含`0`或者`1`。 我们可以执行交换两个相邻行的操作。 目标是使用最少数量的相邻行交换将矩阵转换为有效的配置。 

如果主对角线上方的每个单元格都包含，则网格被认为是有效的`0`。 

对于一个`n x n`矩阵，主对角线由位置组成：

 -`(0,0)`-`(1,1)`-`(2,2)`- ...
 -`(n-1,n-1)`每个位置`(i, j)`在哪里`j > i`位于主对角线上方，并且所有这些位置必须成为`0`。 

例如，在一个`3 x 3`矩阵：```
x 0 0
x x 0
x x x
```只有对角线上方的单元格才重要。 下面或对角线上的值可以是`0`或者`1`。 

重要的观察是这一行`i`必须至少以`n - 1 - i`尾随零。 这是因为对角线位置右侧的所有列都必须为零。 

例如：

 - 行`0`至少需要`n - 1`尾随零
 - 行`1`至少需要`n - 2`尾随零
 - 行`2`至少需要`n - 3`尾随零
 - ...
 - 行`n - 1`至少需要`0`尾随零

 限制相对较小：

 -`1 <= n <= 200`这意味着`O(n^2)`甚至`O(n^3)`解决方案是可以接受的。 然而，指数暴力搜索会太慢。 

一些边缘情况很重要：

 - 网格可能已经有效，需要`0`互换。 
- 可能无法将行重新排列成有效的顺序。 
- 多行可能具有相同的尾随零计数。 
- 所需的行可能仅存在于当前位置下方很远的位置，从而强制进行许多相邻的交换。 

该问题保证矩阵是方阵并且仅包含二进制值。 

## 方法

 ### 蛮力方法

 强力策略将尝试相邻行交换的所有可能序列，直到找到有效网格或用尽所有可能性。 

思考这个问题的一种方法是将其视为最短路径问题：

 - 每个矩阵配置都是一个状态。 
- 交换相邻行会生成相邻状态。 
- 广度优先搜索理论上可以找到最小交换。 

这种做法是正确的，因为 BFS 保证了最短的交换次数。 然而，可能的行排列数为`n!`，即使对于中等强度的情况来说，这也会变得天文数字般大`n`。 

为了`n = 200`，这种做法是完全不可行的。 

### 最优贪心法

 关键的见解是确切的行内容并不重要。 重要的是每行包含多少个尾随零。 

假设我们计算：```
trailingZeros[i] = number of zeros at the end of row i
```然后行`i`最终安排必须满足：```
trailingZeros[i] >= n - 1 - i
```我们从上到下处理行。 

在位置`i`，我们向下搜索具有足够尾随零的第一行。 一旦找到，我们就使用相邻的交换将该行向上冒泡。 

为什么这种贪婪的选择是最优的？ 

因为相邻的交换成本恰好是向上移动的距离。 选择最近的有效行可以最大限度地减少本地交换，并且任何有效的排列都必须在该位置放置一些符合条件的行。 

这将问题转化为简单的贪婪模拟。

 | 蛮力 | O(n!) | O(n!) | 探索所有行排列 |

 ## 算法演练

 1. 计算每行尾随零的数量。 

对于每一行，从右向左扫描，直到遇到第一行`1`。 计算末尾出现了多少个零。 

例子：```
[1,0,0,0] -> 3 trailing zeros
[1,1,0,0] -> 2 trailing zeros
[1,1,1,1] -> 0 trailing zeros
```2. 将这些计数存储在一个名为的数组中`trailingZeros`。 

例子：```
trailingZeros = [2,1,0]
```3. 从上到下处理每个目标行位置。 

对于行索引`i`，所需尾随零的数量为：```
required = n - 1 - i
```4. 从行向下搜索`i`直到找到尾随零计数满足要求的第一行。```
trailingZeros[j] >= required
```5. 如果不存在该行，则返回`-1`。 

这意味着网格永远不会变得有效。 
6. 否则，将该行向上冒泡。 

移动行`j`向上至位置`i`使用相邻的交换。 每次向上移动都会花费一次掉期。 

在此过程中，交换相邻条目`trailingZeros`数组也是如此。 
7. 将执行的交换次数添加到答案中。 
8. 继续，直到处理完所有行。 
9. 返回总交换计数。 

### 为什么它有效

 对于每个行位置，我们必须放置一些满足所需尾随零计数的行。 选择最近的有效行可以最大限度地减少当前位置所需的交换次数。 由于交换仅影响行顺序并且不会更改尾随零计数，因此贪婪地修复较早的行永远不会损害未来的可能性。 因此，该算法总是产生最小数量的相邻交换。 

## Python 解决方案```python
from typing import List

class Solution:
    def minSwaps(self, grid: List[List[int]]) -> int:
        n = len(grid)

        # Compute trailing zero counts
        trailing_zeros = []

        for row in grid:
            count = 0

            for value in reversed(row):
                if value == 0:
                    count += 1
                else:
                    break

            trailing_zeros.append(count)

        swaps = 0

        # Process each row position
        for i in range(n):
            required = n - 1 - i

            # Find first row that satisfies requirement
            j = i

            while j < n and trailing_zeros[j] < required:
                j += 1

            # Impossible to satisfy this row
            if j == n:
                return -1

            # Bubble row upward
            while j > i:
                trailing_zeros[j], trailing_zeros[j - 1] = (
                    trailing_zeros[j - 1],
                    trailing_zeros[j],
                )

                swaps += 1
                j -= 1

        return swaps
```该实现首先计算每行的尾随零计数。 由于只有后缀零对于满足对角线条件很重要，因此在此预处理步骤之后不再需要实际的矩阵内容。 

主循环处理每个目标行位置。 对于职位`i`，该算法确定需要多少个尾随零。 

然后向下搜索满足条件的第一行。 如果不存在这样的行，该函数立即返回`-1`。 

一旦找到合适的行，该实现就会重复交换该行中的相邻条目`trailing_zeros`数组，直到该行到达正确的位置。 每个交换完全对应于实际矩阵中的一个相邻行交换。 

最后累积并返还掉期总数。 

## 解决方案```go
func minSwaps(grid [][]int) int {
	n := len(grid)

	// Compute trailing zero counts
	trailingZeros := make([]int, n)

	for i := 0; i < n; i++ {
		count := 0

		for j := n - 1; j >= 0; j-- {
			if grid[i][j] == 0 {
				count++
			} else {
				break
			}
		}

		trailingZeros[i] = count
	}

	swaps := 0

	// Process each row position
	for i := 0; i < n; i++ {
		required := n - 1 - i

		j := i

		// Find first valid row
		for j < n && trailingZeros[j] < required {
			j++
		}

		// Impossible case
		if j == n {
			return -1
		}

		// Bubble row upward
		for j > i {
			trailingZeros[j], trailingZeros[j-1] =
				trailingZeros[j-1], trailingZeros[j]

			swaps++
			j--
		}
	}

	return swaps
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

切片用于存储尾随零计数。 由于 Go 不支持在内部对数组进行 Python 风格的元组交换，因此交换操作是使用多重赋值显式编写的。 

整数溢出不是问题，因为最大交换次数受以下限制`n²`， 和`n <= 200`。

 ## 边缘情况

 一种重要的边缘情况是网格已经有效。 在这种情况下，每一行都已经满足其位置的尾随零要求。 有缺陷的实现可能仍然会执行不必​​要的交换。 该解决方案正确地避免了额外的工作，因为每行在搜索阶段都会立即满足条件。 

另一个关键的边缘情况是没有行可以满足所需的位置。 例如，如果第一行需要三个尾随零，但每一行只有一个尾随零，则任何交换序列都无法使网格有效。 该实现通过向下搜索并返回来检测这一点`-1`如果没有找到有效行。 

第三个重要的边缘情况涉及具有相同尾随零计数的行。 多行可能满足相同的要求，并且选择错误的一行可能会不必要地增加交换。 贪心策略总是选择最近的有效行，保证相邻交换的数量最少。 

当存在有效行但远低于当前位置时，会出现最终边缘情况。 在这种情况下，可能需要许多相邻的交换。 该实现通过一次将行向上冒泡一个位置，同时准确地计算交换来正确处理这一问题。
