[LeetCode 1563 题](https://leetcode.com/problems/stone-game-v/)

 **难度：** 🔴难
 **主题：** 数组、数学、动态规划、博弈论

 ## 解决方案

 ## 问题理解

 在这个游戏中，我们得到一个数组`stoneValue`其中每个元素代表石头的价值。 石头排成一排，爱丽丝反复将当前排分成两个非空的连续部分。 

Alice 选择分割点后，Bob 比较左右部分的总和：

 - 如果一侧的总和较大，则鲍勃会丢弃总和较大的一侧。 
- 爱丽丝获得的分数等于剩余边的总和。 
- 如果双方的金额相等，Alice 可以选择剩下哪一方。 

游戏在剩余的子数组上递归地继续，直到只剩下一颗棋子。 由于单个石子无法进一步分裂，游戏就此结束。 

目标是计算 Alice 在表现最佳的情况下可以获得的最大总分。 

输入是一个整数数组`stoneValue`，输出是表示最佳可达到分数的单个整数。 

约束条件很重要：

 -`1 <= n <= 500`-`1 <= stoneValue[i] <= 10^6`的值相对较小`n`表明间隔内的动态规划是可行的。 然而，对每个可能的分割进行简单递归仍然会变得极其昂贵，因为每个子数组可能分支到许多递归状态。 

一些边缘情况很重要：

 - 一颗石头产生分数`0`因为不可能有分裂。 
- 具有所有相等值的数组可以创建许多平局情况，其中 Alice 选择更好的延续。 
- 高度不平衡的阵列可能会迫使 Bob 重复丢弃大的部分。 
- 大值需要仔细处理总和，但标准 64 位整数就足够了。 

## 方法

 ### 蛮力方法

 最直接的解决办法就是递归模拟。 

对于每个子数组`[l, r]`，我们尝试每一个可能的分割点`k`：

 - 左边部分是`[l, k]`- 右边的部分是`[k+1, r]`我们计算两个总和：

 -`leftSum`-`rightSum`然后我们遵循规则：

 - 如果`leftSum < rightSum`，爱丽丝保持左侧并获得收益`leftSum`。 
- 如果`rightSum < leftSum`，爱丽丝保持右侧并获得收益`rightSum`。 
- 如果相等，Alice 选择更好的递归选项。 

递归探索所有可能的未来决策并返回可达到的最大分数。 

这种方法是正确的，因为它明确地评估每个合法的游戏序列。 但是，它会重复重新计算相同的子问题。 由于每个间隔可能会被多次重新访问，因此复杂性呈指数级增长。 

### 最佳解决方案的关键见解

 博弈自然会形成重叠的子问题。 

重要的观察是未来的结果仅取决于当前的时间间隔`[l, r]`。 因此，我们可以定义一个动态规划状态：

 -`dp[l][r]`= 从子数组中可获得的最大分数`stoneValue[l:r+1]`对于每个间隔，我们尝试所有分割位置并计算最佳可能得分。 

为了有效地计算子数组和，我们使用前缀和：$$\text{sum}(l,r) = prefix[r+1] - prefix[l]$$这减少了总和计算`O(n)`到`O(1)`。 

由于有`O(n^2)`间隔和每个间隔尝试`O(n)`分割点，总复杂度变为`O(n^3)`，这是可以接受的`n <= 500`。

 ## 算法演练

 1. 创建一个前缀和数组，以便可以在恒定时间内计算子数组和。 

如果`prefix[i]`存储第一个的总和`i`元素，那么：$$\text{sum}(l,r)=prefix[r+1]-prefix[l]$$这是必要的，因为每个间隔都会检查许多分割点。 
2.定义递归DP函数`solve(left, right)`。 

该函数返回 Alice 可以从子数组中获得的最大分数`[left, right]`。 
3. 处理基本情况。 

如果`left == right`，只剩下一块石头，因此不可能进一步移动。 返回`0`。 
4. Try every possible split point.

 对于每个`mid`之间`left`和`right - 1`：

 - 左间隔是`[left, mid]`- 正确的间隔是`[mid + 1, right]`5. 使用前缀和计算两边的和。 

让：

-`left_sum`-`right_sum`6. 应用游戏规则。 

如果`left_sum < right_sum`，鲍勃丢弃右侧，因此爱丽丝获得：$$left\_sum + solve(left, mid)$$如果`right_sum < left_sum`，爱丽丝获得：$$right\_sum + solve(mid+1, right)$$如果总和相等，爱丽丝会选择更好的延续：$$left\_sum + \max(solve(left, mid), solve(mid+1, right))$$7. 取所有分割位置中的最大值。 

这确保了 Alice 始终选择最佳分割。 
8. 记住结果。 

由于相同的间隔重复出现，缓存避免了冗余计算。 

### 为什么它有效

 DP 状态完全捕获了游戏状态，因为剩余的可玩棋子始终是连续的区间。 每一个合法的举动都对应于在该区间内选择一个分割点。 通过评估所有分割并递归求解所得的剩余间隔，该算法探索每个最佳策略。 记忆化保证每个区间只被解决一次。 

## Python 解决方案```python
from typing import List
from functools import lru_cache

class Solution:
    def stoneGameV(self, stoneValue: List[int]) -> int:
        n = len(stoneValue)

        prefix = [0] * (n + 1)

        for i in range(n):
            prefix[i + 1] = prefix[i] + stoneValue[i]

        def range_sum(left: int, right: int) -> int:
            return prefix[right + 1] - prefix[left]

        @lru_cache(None)
        def solve(left: int, right: int) -> int:
            if left == right:
                return 0

            best = 0

            for mid in range(left, right):
                left_sum = range_sum(left, mid)
                right_sum = range_sum(mid + 1, right)

                if left_sum < right_sum:
                    best = max(
                        best,
                        left_sum + solve(left, mid)
                    )
                elif right_sum < left_sum:
                    best = max(
                        best,
                        right_sum + solve(mid + 1, right)
                    )
                else:
                    best = max(
                        best,
                        left_sum + max(
                            solve(left, mid),
                            solve(mid + 1, right)
                        )
                    )

            return best

        return solve(0, n - 1)
```实现首先构建一个前缀和数组。 这允许以恒定时间检索任何间隔总和，这一点至关重要，因为每个 DP 状态都会评估许多分割点。 

这`range_sum`helper 使用前缀数组有效地计算子数组和。 

递归`solve(left, right)`函数表示从特定区间可获得的最大分数。 这`@lru_cache`装饰器会记住结果，因此每个间隔仅计算一次。 

在递归内部，每个有效的分割位置都会被测试。 根据左右总和的比较，代码遵循确切的游戏规则。 所有分组中可达到的最佳分数存储在`best`。 

最后，该解决方案返回整个数组的结果。 

## 解决方案```go
package main

func stoneGameV(stoneValue []int) int {
	n := len(stoneValue)

	prefix := make([]int, n+1)

	for i := 0; i < n; i++ {
		prefix[i+1] = prefix[i] + stoneValue[i]
	}

	rangeSum := func(left, right int) int {
		return prefix[right+1] - prefix[left]
	}

	dp := make([][]int, n)
	visited := make([][]bool, n)

	for i := 0; i < n; i++ {
		dp[i] = make([]int, n)
		visited[i] = make([]bool, n)
	}

	var solve func(int, int) int

	solve = func(left, right int) int {
		if left == right {
			return 0
		}

		if visited[left][right] {
			return dp[left][right]
		}

		visited[left][right] = true

		best := 0

		for mid := left; mid < right; mid++ {
			leftSum := rangeSum(left, mid)
			rightSum := rangeSum(mid+1, right)

			if leftSum < rightSum {
				candidate := leftSum + solve(left, mid)
				if candidate > best {
					best = candidate
				}
			} else if rightSum < leftSum {
				candidate := rightSum + solve(mid+1, right)
				if candidate > best {
					best = candidate
				}
			} else {
				leftOption := solve(left, mid)
				rightOption := solve(mid+1, right)

				if rightOption > leftOption {
					leftOption = rightOption
				}

				candidate := leftSum + leftOption

				if candidate > best {
					best = candidate
				}
			}
		}

		dp[left][right] = best
		return best
	}

	return solve(0, n-1)
}
```Go 实现遵循与 Python 版本相同的逻辑，但使用显式记忆表而不是装饰器。 

这`visited`矩阵跟踪 DP 状态是否已被计算。 这可以避免歧义，因为合法的答案可能是`0`。 

Go 切片用于 DP 和前缀数组。 整数溢出不是问题，因为最大可能的总分完全符合 Go 的标准`int`在 LeetCode 环境中。

 ## 边缘情况

 ### 单石

 恰好包含一颗石头的数组是最小的合法输入。 由于规则要求分成两个非空部分，因此不能进行任何移动。 有缺陷的实现可能会尝试递归，或者错误地返回石头值本身。 实现通过基本情况正确处理了这个问题`left == right`，返回`0`。 

### 等分总和

 当左右总和相等时，Alice 可以选择任一侧继续。 这是错误的一个重要来源，因为某些实现错误地仅选择一个分支。 该解决方案明确评估两种递归可能性并取最大值。 

### 高度不平衡的数组

 数组如`[1,100,1]`可以迫使 Bob 在分割后丢弃几乎整个数组。 不正确的实现可能会意外地递归到丢弃的一侧。 该算法仔细遵循规则，并且仅递归到较小和的一侧。 

### 大值

 每颗宝石的价值可能有那么大`10^6`，可能有 500 颗石头。 因此总和会变得​​很大。 将前缀和与整数运算结合使用可以避免重复重新计算，并安全地处理正常整数范围内的大总数。
