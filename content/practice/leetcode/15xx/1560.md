[LeetCode 问题 1560](https://leetcode.com/problems/most-visited-sector-in-a-circular-track/)

 **难度：** 🟢简单
 **主题：** 数组、模拟

 ## 解决方案

 ## 问题理解

 在这个问题中，我们给出了一个圆形轨道，分为`n`扇区，编号自`1`到`n`。 一名马拉松运动员按照递增的数字顺序绕这条跑道移动，并在扇区之后`n`，跑步者回绕到扇区`1`。 

输入数组`rounds`描述马拉松比赛中的回合顺序。 每对连续的值代表跑步者走过的路径：

 - 跑步者开始于`rounds[i - 1]`- 跑步者以`rounds[i]`移动时，经过的每个扇区都被视为已访问，包括每轮的结束扇区。 

任务是确定在整个马拉松比赛中哪些区域被访问次数最多。 结果必须按升序返回。 

限制非常小：

 -`2 <= n <= 100`-`1 <= m <= 100`这意味着即使直接模拟方法也是可行的，因为遍历的扇区总数是有限的。 然而，这个问题包含一个非常重要的观察结果，使我们能够更优雅地解决它。 

问题的一个微妙方面是如何计算访问量。 跑步者以循环顺序连续向前移动，因此从扇区过渡`4`到部门`1`在大小的轨道上`4`表示跑步者穿过扇区`4`然后换行到`1`。 

一些边缘情况很重要：

 - 路径可能会多次环绕圆形边界。 
- 起始扇区和结束扇区可能会产生交叉的范围`n`。 
- 每个部门都可能受到同等的访问。 
- 答案可能只包含一个扇区。 
- 由于马拉松是连续的，简单的计数实现可能会意外地对回合边界处的扇区进行双重计数。 

该问题保证了连续值`rounds`是不同的，所以每一轮都涉及实际的移动。 

## 方法

 ### 暴力模拟

 最直接的解决方案是完全按照描述模拟整个马拉松。 

我们维护一个频率数组，其中`count[i]`存储多少次扇区`i`已被访问过。 开始于`rounds[0]`，我们模拟围绕圆形轨道的每一步，直到到达下一个目的地扇区。 

对于每个动作：

 - 增加当前扇区的访问次数
 - 移动到下一个扇区
 - 包裹来自`n`回到`1`必要时

 处理完所有轮次后，我们找到最大频率并返回与其匹配的所有扇区。 

这种方法是正确的，因为它确实遵循了声明中给出的移动规则。 然而，它执行了不必要的工作，因为该问题具有隐藏的数学结构。 

### 最佳解决方案的关键见解

 重要的观察结果是，访问量最大的区段始终是马拉松起始区段和最终结束区段之间遇到的区段，以递增的循环顺序移动。 

为什么会出现这种情况？ 

在赛道上的每一整圈中，每个区域都会被访问一次。 因此，完整的周期对所有部门的贡献相同，并且不会影响访问量最大的部门。 

唯一接受一次额外访问的扇区是最后部分航段中经过的扇区，来自：

 -`rounds[0]`到`rounds[-1]`如果起始扇区小于或等于结束扇区，则答案很简单：```
[start, start + 1, ..., end]
```否则，路径会环绕：```
[start, ..., n, 1, ..., end]
```这提供了一个非常紧凑和优雅的解决方案。

 ## 算法演练

 ### 最优算法

 1. 确定起始扇区和结束扇区。 

马拉松比赛开始于`rounds[0]`并结束于`rounds[-1]`。 这两个值确定接收额外访问计数的扇区。 
2. 检查遍历是否环绕圆形边界。 

如果`start <= end`，路径是正常的递增范围，没有回绕。 

如果`start > end`，遍历扇区`n`并再次从扇区继续`1`。 
3. 构建非包装案例的答案。 

什么时候`start <= end`，区间内的每个扇区：```
start to end
```获得最大访问量。 
4. 构建包装盒的答案。 

当发生回绕时，访问最多的扇区是：```
start to n
followed by
1 to end
```5. 按升序返回扇区。 

所需的输出格式已经与上述构造生成的顺序相匹配。 

### 为什么它有效

 轨道上的每一次完整旋转都会为每个扇区带来一次访问，因此所有扇区都会收到相同的基线访问次数。 

唯一的区别来自于马拉松的不完整部分，该部分开始于`rounds[0]`并结束于`rounds[-1]`。 这些部门会增加一次访问量，使其成为整体访问量最大的部门。 

## Python 解决方案```python
from typing import List

class Solution:
    def mostVisited(self, n: int, rounds: List[int]) -> List[int]:
        start = rounds[0]
        end = rounds[-1]

        if start <= end:
            return list(range(start, end + 1))

        return list(range(start, n + 1)) + list(range(1, end + 1))
```该实现首先提取起始和结束扇区。 

如果起始扇区小于或等于结束扇区，则答案就是它们之间的连续范围。 

否则，遍历将围绕圆形边界进行。 在这种情况下，我们结合两个范围：

 -`start`通过`n`-`1`通过`end`代码直接反映了算法讨论中的数学观察，这使得实现极其简洁。 

## 解决方案```go
func mostVisited(n int, rounds []int) []int {
    start := rounds[0]
    end := rounds[len(rounds)-1]

    result := []int{}

    if start <= end {
        for i := start; i <= end; i++ {
            result = append(result, i)
        }
        return result
    }

    for i := start; i <= n; i++ {
        result = append(result, i)
    }

    for i := 1; i <= end; i++ {
        result = append(result, i)
    }

    return result
}
```Go 实现遵循与 Python 版本相同的逻辑。 

由于 Go 没有内置的 Python 等价物`range`，我们使用循环手动将值附加到结果切片中。 

不用担心整数溢出，因为约束非常小。 该解决方案动态地使用切片，这自然可以处理可变的输出大小。

 ## 边缘情况

 当路径环绕圆形边界时，会出现一种重要的边缘情况。 例如，如果遍历从扇区开始`5`并结束于扇区`2`，幼稚的实现可能会错误地假设范围为空，因为`5 > 2`。 正确的解释是跑步者从`5`到`n`，然后继续从`1`到`2`。 该实现通过将答案结构分成两个范围来处理这个问题。 

当每个部门的访问量相同时，就会出现另一个重要情况。 当起始扇区为`1`最后的扇区是`n`。 在这种情况下，每个扇区都位于最终遍历区间内，因此答案包括所有扇区。 该实现自然地使用标准的非环绕范围构造来处理这个问题。 

第三种边缘情况是答案仅包含一个扇区。 例如，两个扇区之间的重复振荡可能使得只有一个扇区获得额外的访问计数。 该实现正确地返回一个单元素数组，因为范围构造仍然有效，即使`start == end`。 

最后，非常小的值`n`， 例如`n = 2`，可以暴露循环遍历逻辑中的差一错误。 由于该解决方案纯粹依赖于区间构造而不是手动模拟，因此它避免了许多常见的边界错误。
