[LeetCode 问题 1570](https://leetcode.com/problems/dot-product-of-two-sparse-vectors/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、两个指针、设计

 ## 解决方案

 ## 问题理解

 这个问题要求我们有效地计算两个稀疏向量之间的点积。 

法向量只是一个数字数组。 两个向量的点积是通过将相应元素相乘并对结果求和来计算的。 对于两个向量`a`和`b`相同长度：$$a \cdot b = \sum_{i=0}^{n-1} a[i] \times b[i]$$这里重要的细节是向量是稀疏的。 稀疏向量主要包含零值。 由于乘以零对最终总和没有任何贡献，因此显式存储每个元素会浪费内存和计算时间。 

因此，我们的目标不仅是计算正确的点积，而且还要为稀疏数据有效地设计数据结构。 

该类必须支持两种操作：

 1. 从输入数组构造稀疏向量。 
2. 计算两个稀疏向量之间的点积。 

约束告诉我们向量长度可以大到`10^5`。 对于单个操作来说，对每个索引进行强力扫描在技术上仍然是可行的，但问题的关键在于优化稀疏性。 如果大多数条目为零，我们应该避免存储或处理它们。 

输入保证两个向量具有相同的长度并且所有值都是非负整数。 

一些边缘情况很重要：

 - 向量可能包含全零。 
- 只有少数位置可能是非零的。 
- 非零位置可能根本不重叠。 
- 一个向量可能比另一个向量稀疏得多。 
- 大矢量大小需要内存高效的存储。 

存储所有元素的简单实现会浪费空间并忽略稀疏性的关键属性。 

## 方法

 ### 蛮力方法

 最简单的解决方案是存储整个数组并通过迭代每个索引来计算点积。 

对于每个位置`i`, 乘以`nums1[i] * nums2[i]`并将其添加到答案中。 

这种方法很简单并且总是正确的，因为它直接遵循点积的数学定义。 

然而，当大多数条目为零时，此方法会进行不必要的工作。 稀疏向量可能只包含少数非零元素，但强力解决方案仍然可以处理所有`n`指数。 

它还浪费内存，因为零被显式存储，即使它们对计算没有任何贡献。 

### 最佳方法

 关键的观察是只有非零值的索引才重要。 

我们不存储整个数组，而是只存储：

 - 索引
 - 该索引处的非零值

 例如：```
[0, 0, 5, 0, 2]
```可以存储为：```
[(2, 5), (4, 2)]
```现在，在计算点积时，我们只需要将索引匹配的值相乘即可。 

有两种常见的方法可以做到这一点：

 - 哈希图查找
 - 排序索引列表上的两个指针

 由于索引在构造过程中自然地按排序顺序出现，因此两指针技术非常有效。 

我们按顺序存储非零元素`(index, value)`对。 在点积计算期间：

 - 如果两个指针指向相同的索引，则将值相乘并移动两个指针。 
- 否则，用较小的索引前进指针。 

这完全避免了处理零条目。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 存储所有元素并扫描整个向量 |
 | 最佳 | O(k1 + k2) | O(k1 + k2) | O(k) | 仅存储非零值，其中`k`是非零条目的数量 |

 这里：

-`n`是向量长度
 -`k1`和`k2`是每个向量中非零条目的数量

 对于稀疏数据，`k1`和`k2`通常比`n`。 

## 算法演练

 ### 最优算法

 1. 在向量构造期间，迭代输入数组。 
2. 对于每个非零值，存储一对`(index, value)`在一个列表中。 
3. 完全跳过所有零值，因为它们不影响点积。 
4. 要计算点积，请初始化两个指针：

 -`i`对于第一个向量
 -`j`对于第二个向量
 5. 比较两个指针处的索引。 
6. 如果索引相等：

 - 乘以相应的值
 - 将产品添加到答案中
 - 向前移动两个指针
 7. 如果第一个索引较小：

 - 移动指针`i`前进
 - 这是有效的，因为索引已排序，因此较小的索引不能稍后出现在第二个向量中
 8. 如果第二个索引更小：

 - 移动指针`j`前进
 9. 继续，直到一个指针到达其列表的末尾。 
10. 返回累计金额。 

### 为什么它有效

 该算法之所以有效，是因为点积仅取决于匹配索引。 

通过仅存储非零条目，我们消除了涉及零的不必要的操作。 由于存储的索引是排序的，因此双指针技术保证每个匹配索引都被恰好找到一次。 

不会跳过任何有效的贡献，也不会执行错误的乘法。 

## Python 解决方案```python
from typing import List

class SparseVector:
    def __init__(self, nums: List[int]):
        self.values = []

        for index, value in enumerate(nums):
            if value != 0:
                self.values.append((index, value))

    # Return the dotProduct of two sparse vectors
    def dotProduct(self, vec: 'SparseVector') -> int:
        pointer1 = 0
        pointer2 = 0
        result = 0

        while pointer1 < len(self.values) and pointer2 < len(vec.values):
            index1, value1 = self.values[pointer1]
            index2, value2 = vec.values[pointer2]

            if index1 == index2:
                result += value1 * value2
                pointer1 += 1
                pointer2 += 1
            elif index1 < index2:
                pointer1 += 1
            else:
                pointer2 += 1

        return result

# Your SparseVector object will be instantiated and called as such:
# v1 = SparseVector(nums1)
# v2 = SparseVector(nums2)
# ans = v1.dotProduct(v2)
```构造函数扫描输入数组一次并仅存储非零条目。 每个存储的元素都表示为包含其索引和值的元组。 

这`dotProduct`方法使用两个指针，因为两个列表都是按索引自然排序的。 这允许有效匹配而不需要额外的哈希映射。 

只要索引匹配，相应的值就会影响最终的点积。 如果索引不同，则较小的索引会前进，因为它无法匹配另一个向量中任何未来较大的索引。 

这种实现避免了不必要的零值处理，并且对于稀疏数据非常有效。 

## 解决方案```go
type Pair struct {
	index int
	value int
}

type SparseVector struct {
	values []Pair
}

func Constructor(nums []int) SparseVector {
	vector := SparseVector{
		values: []Pair{},
	}

	for index, value := range nums {
		if value != 0 {
			vector.values = append(vector.values, Pair{
				index: index,
				value: value,
			})
		}
	}

	return vector
}

// Return the dotProduct of two sparse vectors
func (this *SparseVector) dotProduct(vec SparseVector) int {
	pointer1 := 0
	pointer2 := 0
	result := 0

	for pointer1 < len(this.values) && pointer2 < len(vec.values) {
		pair1 := this.values[pointer1]
		pair2 := vec.values[pointer2]

		if pair1.index == pair2.index {
			result += pair1.value * pair2.value
			pointer1++
			pointer2++
		} else if pair1.index < pair2.index {
			pointer1++
		} else {
			pointer2++
		}
	}

	return result
}

/**
 * Your SparseVector object will be instantiated and called as such:
 * v1 := Constructor(nums1)
 * v2 := Constructor(nums2)
 * ans := v1.dotProduct(v2)
 */
```Go 实现遵循与 Python 版本相同的逻辑。 由于 Go 没有元组，因此有一个自定义`Pair`struct 用于存储索引值对。 

切片用于有效地存储非零条目。 点积计算再次依赖于两指针技术。 

在给定的约束下，整数溢出不是问题，因为最大可能的结果完全适合 Go 的范围`int`类型。

当向量稀疏时，这使得该解决方案明显优于密集向量方法。

 ## 边缘情况

 ### 两个向量都只包含零

 错误的常见来源是处理不存在非零元素的向量。 在这种情况下，稀疏表示变成空列表。 

如果实现假设至少存在一个存储条目，则可能会发生指针访问错误。 该解决方案可以自然地处理这种情况，因为当两个列表都为空时 while 循环立即终止。 

### 没有重叠的非零索引

 两个向量可能各自包含非零值，但没有一个索引匹配。 

例如：```
[1,0,0]
[0,2,0]
```有缺陷的实现可能会意外地将不相关的值相乘。 两指针技术通过仅在索引相同时将值相乘来避免这种情况。 

### 一个向量比另一个向量密集得多

 后续问题专门询问只有一个向量稀疏的场景。 

例如：```
[0,0,0,5,0]
[1,2,3,4,5]
```当前的实现仍然高效执行，因为它仅迭代稀疏向量的存储的非零条目。 即使另一个向量包含许多非零值，与盲目扫描每个索引相比，该算法仍然有效。
