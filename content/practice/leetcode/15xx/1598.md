[LeetCode 1598 题](https://leetcode.com/problems/crawler-log-folder/)

 **难度：** 🟢简单
 **主题：** 数组、字符串、堆栈

 ## 解决方案

 ## 问题理解

 在这个问题中，我们正在模拟文件系统内的导航。 系统从主文件夹开始，并为我们提供了一系列文件夹导航操作。 每个操作都会以三种方式之一更改当前目录。 

操作`"../"`表示向上移动到父目录。 然而，如果我们已经在主文件夹中，我们就不能再更高了，所以我们留在原地。 

操作`"./"`表示保留在当前文件夹中。 它不会更改目录深度。 

任何形式的操作`"x/"`意味着移入名为的子文件夹`x`。 该问题保证了此类文件夹始终存在，因此我们不需要验证文件夹名称或处理无效导航。 

目标是确定有多少`"../"`处理完所有操作后，需要返回主文件夹。 换句话说，我们需要在模拟所有命令后计算当前文件夹深度。 

输入是一个字符串数组，称为`logs`。 每个字符串代表一个导航操作。 输出是一个整数，表示返回根目录所需的父文件夹移动的最小次数。 

限制很小：

 -`1 <= logs.length <= 1000`- 每个日志字符串的长度介于`2`和`10`由于输入大小适中，即使效率较低的方法也可以工作，但问题显然是为简单的线性扫描而设计的。 

一些边缘情况很重要：

 - 多个`"../"`已经在根文件夹中的操作永远不会使深度为负值。 
-`"./"`操作根本不应该改变状态。 
- 连续的子文件夹操作增加了嵌套深度。 
- 最终深度本身就是答案，因为每个`"../"`将深度减少一倍。 

## 方法

 ### 蛮力方法

 暴力方法将使用一堆文件夹名称显式模拟文件系统路径。 

每当我们遇到像这样的子文件夹时`"d1/"`，我们将文件夹名称压入堆栈。 当我们遇到`"../"`，如果堆栈不为空，我们就从堆栈中弹出。 当我们遇到`"./"`，我们什么都不做。 

最后，堆栈的大小代表当前目录深度，也是返回根目录所需的操作次数。 

这种方法是正确的，因为堆栈准确地模拟了文件夹层次结构。 每个子文件夹操作都会添加一级，每个父文件夹操作都会删除一级。 

但是，存储实际的文件夹名称是不必要的，因为问题只要求深度，而不要求完整路径。 

### 最佳方法

 关键的观察是我们只关心当前的深度，而不是文件夹本身的名称。 

我们可以简单地保留一个名为的整型变量，而不是维护一堆文件夹名称`depth`。 

-`"x/"`增加深度`1`-`"../"`深度减少`1`，但绝不会低于`0`-`"./"`留下深度不变

 处理完所有操作后，`depth`直接代表返回主文件夹所需的步骤数。 

这种方法更简单，并且使用恒定的额外空间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(n) | 使用堆栈来存储文件夹名称 |
 | 最佳 | O(n) | O(1) | O(1) | 仅跟踪当前深度 |

 ## 算法演练

 1. 初始化变量`depth`到`0`。 

该变量表示我们当前相对于主文件夹的深度。 
2. 迭代每个操作`logs`。 

我们按照操作发生的顺序一一处理它们。 
3. 如果操作是`"../"`:

 - 检查是否`depth > 0`- 如果为真，则递减`depth`经过`1`我们不能移动到主文件夹之上，因此深度永远不允许变为负数。 
4. 如果操作是`"./"`:

 - 什么都不做

 此操作意味着停留在同一目录中。 
5. 否则，该操作必须是子文件夹移动，例如`"d1/"`:

 - 增量`depth`经过`1`移入子文件夹会增加嵌套深度。 
6. 处理完所有操作后，返回`depth`。 

每个`"../"`操作将深度减少了 1，因此当前深度等于返回根所需的最小操作数。 

### 为什么它有效

 该算法保持不变式`depth`始终等于距主文件夹的当前距离。 

- 输入子文件夹会将该距离增加一。 
- 移动到父文件夹会将其减一，除非已经位于根文件夹。 
- 保留在同一文件夹中不会使其保持不变。 

因为每次操作都会更新`depth`完全按照文件夹导航规则，最终值为`depth`正是`"../"`返回主文件夹所需的操作。 

## Python 解决方案```python
from typing import List

class Solution:
    def minOperations(self, logs: List[str]) -> int:
        depth = 0

        for operation in logs:
            if operation == "../":
                if depth > 0:
                    depth -= 1
            elif operation == "./":
                continue
            else:
                depth += 1

        return depth
```实现从初始化开始`depth`为零，因为我们从主文件夹开始。 

该循环一次处理一个日志条目。 如果操作是`"../"`，我们尝试向上移动。 我们首先检查是否`depth`避免超出根目录是肯定的。 

如果操作是`"./"`，我们只需继续，因为当前文件夹没有更改。 

所有剩余操作都是子文件夹移动，例如`"d1/"`或者`"abc/"`。 在这些情况下，我们增加`depth`因为我们将文件系统更深入一层。 

最后，函数返回`depth`，表示返回主文件夹所需的父文件夹操作数。 

## 解决方案```go
func minOperations(logs []string) int {
    depth := 0

    for _, operation := range logs {
        if operation == "../" {
            if depth > 0 {
                depth--
            }
        } else if operation == "./" {
            continue
        } else {
            depth++
        }
    }

    return depth
}
```Go 实现遵循与 Python 版本相同的逻辑。 主要区别在于语法。 

Go 使用一个`for _, operation := range logs`循环遍历切片。 这`depth`变量是一个初始化为零的整数。 

不需要对整数溢出进行特殊处理，因为约束非常小。 该实现也不需要切片或堆栈，因为只有当前深度很重要。

 ## 边缘情况

 ### 在根重复父操作

 当日志包含多个时，会出现一个重要的边缘情况`"../"`已经在主文件夹中的操作。 

例如：```
["../", "../", "../"]
```幼稚的实现可能允许深度变为负值，这将错误地表示移动到根目录之上。 该问题明确指出这是不允许的。 

该实现通过递减来正确处理这个问题`depth`仅当`depth > 0`。 

### 仅当前目录操作

 另一个边缘情况是当每个操作都是`"./"`。 

例如：```
["./", "./", "./"]
```这些操作根本不应该影响目录深度。 有缺陷的实现可能会意外地将它们计为移动操作。 

该解决方案正确地完全忽略了这些操作。 

### 在子目录和父目录之间交替

 重复进入和退出文件夹的顺序可能会暴露状态管理中的逻辑错误。 

例如：```
["d1/", "../", "d2/", "../"]
```最终正确答案是`0`因为每个子文件夹移动都会通过父文件夹移动来平衡。 

该实现自然地处理了这个问题，因为`depth`根据导航规则对称增加和减少。
