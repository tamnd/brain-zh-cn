 # LeetCode 1593 - 将字符串拆分为最大数量的唯一子字符串

 ## 问题理解

 这个问题要求我们将一个字符串分割成尽可能多的子字符串，使得每个子字符串都是唯一的。 子字符串必须是原始字符串的连续部分，并且按顺序组合时，它们必须准确地重建原始字符串。 

关键要求是唯一性。 一旦子字符串已在当前拆分中使用，它就不能再次出现。 目标不是找到所有有效的分割，而是最大化我们可以创建的唯一子字符串的数量。 

例如，考虑字符串`"ababccc"`。 一种有效的分割是：```
["a", "b", "ab", "c", "cc"]
```所有子字符串都是唯一的，它们一起形成原始字符串。 答案是`5`因为在满足所有约束的同时不可能创建超过五个唯一的子字符串。 

输入由单个字符串组成`s`仅包含小写英文字母。 字符串长度最多为`16`，这一点极其重要。 如此小的长度强烈表明基于指数或回溯的解决方案是可以接受的。 具有这么小的约束的问题通常是为了递归探索可能性而设计的。 

输出是一个整数，表示可实现的唯一子字符串的最大数量。 

尽早识别几个边缘情况很重要：

 - 包含所有相同字符的字符串，例如`"aaaa"`，严格限制唯一分割的数量，因为不允许重复的单字符子字符串。 
- 非常短的字符串，例如 length`1`，只有一个可能的答案。 
- 具有许多不同字符的字符串，例如`"abcdef"`，通常可以拆分为所有单个字符子字符串。 
- 贪婪的分裂并不总是有效。 首先选择最短的子串可能会阻止未来的有效分割。 

因为可能需要探索每一个可能的分区，所以这个问题自然会导致回溯和剪枝。 

## 方法

 ### 蛮力方法

 暴力解决方案生成所有可能的方法来分割字符串，并检查所有生成的子字符串是否唯一。 

一个长度的字符串`n`有`n - 1`可能的分割位置。 每个位置可以包含剪切，也可以不包含剪切，这意味着有`2^(n-1)`总体上可能的分区。 

对于每个分区，我们将：

 1. 构造所有子串。 
2. 将它们插入一组。 
3. 验证是否存在重复项。 
4. 跟踪找到的唯一子字符串的最大数量。 

这种方法是正确的，因为它检查了每种可能的拆分配置。 然而，它变得低效，因为它会重复重建分区并在事后执行重复检查。 

### 最优方法，回溯与剪枝

 更好的解决方案是使用回溯和哈希集相结合。 

我们不是先生成所有分区然后再验证，而是增量地构建分割。 在每个位置，我们都会尝试从当前索引开始的所有可能的子字符串。 如果子字符串尚未使用，我们将其添加到集合中并继续递归。 

关键的优化是修剪。 假设我们已经找到了一个解决方案`best`唯一的子串。 如果当前所选子串的数量加上剩余字符的数量不可能超过`best`，那么继续这个分支是没有意义的。 

这种修剪极大地减少了搜索空间。 

因为最大字符串长度仅为`16`，这种递归探索在实践中足够快。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n * n) | O(2^n * n) | O(n) | 生成每个分区并随后验证唯一性 |
 | 最佳 | 最坏情况 O(2^n) | O(n) | 通过修剪和增量唯一性检查进行回溯 |

 ## 算法演练

 1. 初始化一个名为的哈希集`used_substrings`。 

该集合存储当前在活动分割路径中选择的所有子字符串。 使用哈希集可以进行恒定时间的唯一性检查。 
2. 维护一个名为的全局或外部变量`max_count`。 

该变量跟踪迄今为止找到的最佳答案。 
3. 创建一个递归回溯函数，获取字符串中的当前索引。 

该函数表示当前索引之前的所有内容都已被拆分为唯一子字符串的状态。 
4. 如果当前索引到达字符串末尾，则更新`max_count`。 

到达终点意味着我们形成了完整有效的分裂。 
5. 在进一步探索之前，先进行修剪。 

如果：```
current_unique_count + remaining_characters <= max_count
```那么即使是最好的延续也无法改善答案。 在这种情况下，请停止探索该分支。 
6. 尝试从当前索引开始的每个可能的子字符串。 

对于每个结束位置：

 - 提取子字符串。 
- 检查它是否已经存在于`used_substrings`。 
7. 如果子字符串是唯一的：

 - 将其添加到集合中。 
- 递归处理剩余的后缀。 
- 之后将其删除以正确回溯。 
8. 继续探索，直到检查完所有有效分区。 

### 为什么它有效

 该算法系统地探索字符串的每个有效分区，同时在构造过程中立即强制执行唯一性。 因为在每个位置都会考虑每个可能的子串选择，所以不会错过任何有效的解决方案。 剪枝条件仅消除可证明无法改善当前最佳答案的分支，因此保留了正确性。 

## Python 解决方案```python
class Solution:
    def maxUniqueSplit(self, s: str) -> int:
        used_substrings = set()
        max_count = 0
        n = len(s)

        def backtrack(start: int) -> None:
            nonlocal max_count

            # Complete valid split
            if start == n:
                max_count = max(max_count, len(used_substrings))
                return

            # Pruning
            if len(used_substrings) + (n - start) <= max_count:
                return

            # Try all possible substrings
            for end in range(start + 1, n + 1):
                substring = s[start:end]

                if substring not in used_substrings:
                    used_substrings.add(substring)
                    backtrack(end)
                    used_substrings.remove(substring)

        backtrack(0)
        return max_count
```实现首先创建一个名为`used_substrings`，它跟踪当前分割中已包含的子字符串。 

递归`backtrack`函数从左到右处理字符串。 参数`start`表示下一个仍需要分区的索引。 

什么时候`start == n`，整个字符串已成功拆分为唯一的子字符串。 此时，算法会更新`max_count`。 

修剪条件对于效率很重要。 即使每个剩余的字符都成为其自己唯一的子字符串，如果总数仍然不超过，则分支无法改进当前的最佳答案`max_count`。 

循环探索从以下位置开始的每个子字符串`start`。 如果子字符串尚未被使用，则将其暂时添加到集合中，继续递归，然后删除子字符串以恢复之前的状态。 

这种添加-递归-删除模式是回溯算法的标准结构。 

## 解决方案```go
func maxUniqueSplit(s string) int {
    usedSubstrings := make(map[string]bool)
    maxCount := 0
    n := len(s)

    var backtrack func(int)

    backtrack = func(start int) {
        // Complete valid split
        if start == n {
            if len(usedSubstrings) > maxCount {
                maxCount = len(usedSubstrings)
            }
            return
        }

        // Pruning
        if len(usedSubstrings)+(n-start) <= maxCount {
            return
        }

        // Try all possible substrings
        for end := start + 1; end <= n; end++ {
            substring := s[start:end]

            if !usedSubstrings[substring] {
                usedSubstrings[substring] = true
                backtrack(end)
                delete(usedSubstrings, substring)
            }
        }
    }

    backtrack(0)
    return maxCount
}
```Go 解决方案遵循与 Python 版本相同的逻辑。 Go 不使用集合，而是使用`map[string]bool`跟踪使用的子字符串。 

Go 使用字节索引对字符串进行切片，这里可以正常工作，因为问题只保证小写英文字母。 不存在 Unicode 复杂性。 

递归函数是使用函数变量声明的，因为 Go 需要显式递归闭包声明。 

整数溢出不是问题，因为最大答案最多是`16`。

 ## 边缘情况

 ### 单字符串

 一个字符串，例如`"a"`是最小的有效输入。 唯一可能的分割是字符串本身，所以答案必须是`1`。 

这种情况可能会暴露递归终止逻辑中的错误。 该实现可以正确处理它，因为递归在选择单个子字符串后立即到达末尾。 

### 所有字符都相同

 考虑`"aaaa"`。 

天真的贪婪方法可能会尝试分为：```
["a", "a", "a", "a"]
```然而，这违反了唯一性要求。 

回溯解决方案正确地探索更大的子串，例如`"aa"`或者`"aaa"`并找到最佳的有效分割。 

### 最大长度输入

 最大字符串长度为`16`， 例如：```
"abcdefghijklmnop"
```因为存在许多有效分区，所以这会创建很大的搜索空间。 

修剪优化在这里变得很重要。 如果不进行剪枝，即使已经找到了强大的解决方案，仍然会探索不必要的递归分支。 

该实现可以安全地处理这种情况，因为递归深度仍然很小，并且修剪条件消除了许多不可能的分支。
