[LeetCode 1591 题](https://leetcode.com/problems/strange-printer-ii/)

 **难度：** 🔴难
 **主题：** 数组、图论、拓扑排序、矩阵

 ## 解决方案

 ## 问题理解

 在这个问题中，我们给出了一个最终的彩色矩阵，称为`targetGrid`。 我们需要确定一个奇怪的打印机是否可以在两个不寻常的限制下产生这个网格。 

打印机的工作原理如下：

 首先，在一次操作期间，它可以仅使用一种颜色打印实心矩形区域。 该矩形内的每个单元格都会变成该颜色，无论以前是什么颜色。 

其次，一旦在打印操作中使用了某种颜色，以后就不能再次使用该颜色。 

重要的结果是每种颜色只能打印一次，并且打印必须是单个矩形。 

挑战在于矩形可能会重叠。 稍后的打印操作可能会覆盖先前矩形的部分内容。 因此，即使颜色在最终网格中以非矩形形状出现，它也可能仍然有效，因为某些单元格可能已被覆盖。 

例如，假设颜色`1`最初打印一个覆盖整个网格的大矩形，然后上色`2`在里面打印一个较小的矩形。 最终呈现的颜色`1`看起来像一个边框而不是一个矩形，但这仍然是可以实现的。 

输入是一个`m x n`矩阵其中：

 -`m`是行数
 -`n`是列数
 - 每个值代表一种颜色

 任务是返回：

 -`true`某些有效矩形打印序列是否可以生成目标网格
 -`false`否则

 限制虽小但并非微不足道：

 -`1 <= m, n <= 60`- 颜色范围从`1`到`60`由于最多有`60`不同的颜色、基于图形的解决方案变得实用。 

一些边缘情况很重要：

 一种颜色只能出现一次，这意味着它的矩形只是一个单元格。 

颜色的边界矩形可能包含其他颜色。 这意味着其他颜色必须是稍后打印的。 

颜色依赖性之间的循环使打印变得不可能。 例如：```
1 2
2 1
```颜色`1`需要`2`稍后打印，但颜色`2`还要求`1`稍后打印。 这就产生了矛盾。 

另一个微妙的情况是当颜色在最终网格中出现断开时。 仅此一点并不会使配置无效，因为被覆盖的区域可以解释这些间隙。 

## 方法

 ### 蛮力方法

 一种简单的方法是重复搜索当前可见单元格形成有效矩形的颜色。 如果存在这种颜色，我们可以想象最后打印它，将其从网格中删除，然后递归地继续。 

该过程的工作原理如下：

 - 对于每个剩余的颜色，计算包含所有可见单元格的最小矩形。 
- 检查该矩形内的每个未删除的单元格是否是：

 - 相同的颜色，或者
 - 已经删除
 - 如果有效，删除该颜色并重复。 

此方法是正确的，因为如果一种颜色可以最后打印，则其矩形中仍然可见的所有单元格都必须属于该颜色。 

然而，重复扫描整个网格中的每种颜色的成本很高。 在最坏的情况下，我们可能会多次重复处理相同的细胞。 

### 最佳方法

 关键的见解是打印顺序创建了颜色之间的依赖关系。 

假设颜色`A`有一个包含颜色单元格的边界矩形`B`。 

这意味着：

 -`A`的矩形必须之前已经打印过`B`- 否则`A`会覆盖`B`所以：```
A -> B
```这成为一个有向图问题。 

我们：

 1. 计算每种颜色的边界矩形。 
2. 检查每个矩形。 
3. 如果该矩形内出现另一种颜色，则创建依赖边。 
4. 进行拓扑排序。 
5. 如果所有颜色都可以拓扑排序，则网格是可打印的。 
6. 如果存在循环，则无法打印。 

这将问题转化为有向图中的循环检测。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O((mn)^2) | O((mn)^2) | O(1) | O(1) | 反复扫描并删除可打印的颜色 |
 | 最佳 | O(mn + C^2) | O(mn + C^2) | O(C^2) | O(C^2) | 构建依赖图并使用拓扑排序 |

 这里，`C`最多是颜色数`60`。 

## 算法演练

 ### 第 1 步：计算边界矩形

 对于每种颜色，确定：

 - minimum row
 - maximum row
 - minimum column
 - maximum column

 它们定义了包含所有出现的颜色的最小矩形。 

我们使用四个数组，因为颜色仅限于`1..60`，使直接索引变得高效。 

### 第 2 步：构建依赖关系图

 对于每种颜色：

 1. 遍历其边界矩形内的每个单元格。 
2. 如果该矩形内出现不同的颜色：

 - 当前颜色必须在其他颜色之前打印
 - 添加有向边

 例如：```
1 1 1
1 2 1
1 1 1
```颜色`1`的矩形包含颜色`2`。 

所以：```
1 -> 2
```意义`1`必须提前打印。 

我们还维护拓扑排序的入度计数。 

### 步骤 3：执行拓扑排序

 我们使用卡恩算法。 

1. 插入每个颜色的入度`0`进入队列。 
2. 反复从队列中删除颜色。 
3. 减少其邻居的入度。 
4. 如果邻居达到入度`0`，将其添加到队列中。 

计算处理了多少种颜色。 

### 步骤 4：检查周期

 如果处理了所有颜色，则依赖图是非循环的。 

这意味着存在有效的打印订单。 

否则会出现循环，无法打印。 

### 为什么它有效

 关键不变量是：

 如果颜色`A`的矩形包含颜色`B`， 然后`A`必须先打印`B`。 

依赖关系图捕获了每一个这样的需求。 任何有效的打印序列必须满足所有有向边。 因此，当图形是非循环时，目标网格是可以精确打印的。 拓扑排序确定这种排序是否存在。 

## Python 解决方案```python
from typing import List
from collections import deque

class Solution:
    def isPrintable(self, targetGrid: List[List[int]]) -> bool:
        rows = len(targetGrid)
        cols = len(targetGrid[0])

        MAX_COLOR = 61

        top = [rows] * MAX_COLOR
        bottom = [-1] * MAX_COLOR
        left = [cols] * MAX_COLOR
        right = [-1] * MAX_COLOR

        used_colors = set()

        # Compute bounding rectangles
        for r in range(rows):
            for c in range(cols):
                color = targetGrid[r][c]
                used_colors.add(color)

                top[color] = min(top[color], r)
                bottom[color] = max(bottom[color], r)
                left[color] = min(left[color], c)
                right[color] = max(right[color], c)

        # Build graph
        graph = [set() for _ in range(MAX_COLOR)]
        indegree = [0] * MAX_COLOR

        for color in used_colors:
            for r in range(top[color], bottom[color] + 1):
                for c in range(left[color], right[color] + 1):
                    other = targetGrid[r][c]

                    if other != color and other not in graph[color]:
                        graph[color].add(other)
                        indegree[other] += 1

        # Topological sort
        queue = deque()

        for color in used_colors:
            if indegree[color] == 0:
                queue.append(color)

        processed = 0

        while queue:
            color = queue.popleft()
            processed += 1

            for neighbor in graph[color]:
                indegree[neighbor] -= 1

                if indegree[neighbor] == 0:
                    queue.append(neighbor)

        return processed == len(used_colors)
```该实现首先扫描一次网格以计算每种颜色的边界矩形。 由于颜色有限`60`，固定大小的数组比哈希映射更有效。 

知道矩形后，代码将构建依赖图。 对于每种颜色，它都会检查该颜色矩形内的所有单元格。 如果那里出现另一种颜色，则当前颜色一定是之前打印过的。 

该图使用集合来避免重复的边。 如果没有集合，重复出现相同的依赖关系将错误地增加入度计数。 

最后，卡恩的拓扑排序算法判断图是否包含环。 如果每种颜色都可以处理，那么网格就可以打印。 

## 解决方案```go
package main

func isPrintable(targetGrid [][]int) bool {
	rows := len(targetGrid)
	cols := len(targetGrid[0])

	const MAX_COLOR = 61

	top := make([]int, MAX_COLOR)
	bottom := make([]int, MAX_COLOR)
	left := make([]int, MAX_COLOR)
	right := make([]int, MAX_COLOR)

	for i := 0; i < MAX_COLOR; i++ {
		top[i] = rows
		left[i] = cols
		bottom[i] = -1
		right[i] = -1
	}

	used := make([]bool, MAX_COLOR)

	// Compute bounding rectangles
	for r := 0; r < rows; r++ {
		for c := 0; c < cols; c++ {
			color := targetGrid[r][c]
			used[color] = true

			if r < top[color] {
				top[color] = r
			}
			if r > bottom[color] {
				bottom[color] = r
			}
			if c < left[color] {
				left[color] = c
			}
			if c > right[color] {
				right[color] = c
			}
		}
	}

	graph := make([]map[int]bool, MAX_COLOR)
	for i := 0; i < MAX_COLOR; i++ {
		graph[i] = make(map[int]bool)
	}

	indegree := make([]int, MAX_COLOR)

	// Build dependency graph
	for color := 1; color < MAX_COLOR; color++ {
		if !used[color] {
			continue
		}

		for r := top[color]; r <= bottom[color]; r++ {
			for c := left[color]; c <= right[color]; c++ {
				other := targetGrid[r][c]

				if other != color && !graph[color][other] {
					graph[color][other] = true
					indegree[other]++
				}
			}
		}
	}

	// Topological sort
	queue := []int{}

	for color := 1; color < MAX_COLOR; color++ {
		if used[color] && indegree[color] == 0 {
			queue = append(queue, color)
		}
	}

	processed := 0

	for len(queue) > 0 {
		color := queue[0]
		queue = queue[1:]

		processed++

		for neighbor := range graph[color] {
			indegree[neighbor]--

			if indegree[neighbor] == 0 {
				queue = append(queue, neighbor)
			}
		}
	}

	totalColors := 0
	for color := 1; color < MAX_COLOR; color++ {
		if used[color] {
			totalColors++
		}
	}

	return processed == totalColors
}
```Go 实现遵循与 Python 版本相同的逻辑。 一个显着的区别是使用`map[int]bool`表示邻接集，因为 Go 没有内置的集合类型。 

拓扑排序的队列是使用切片来实现的。 由于颜色数量最多为`60`，切片移位的开销可以忽略不计。 

整数溢出不是问题，因为所有计数仍然很小。

 ## 边缘情况

 一个重要的边缘情况是当一种颜色出现在断开的区域中时。 天真的解决方案可能会错误地假设每种颜色必须已经在最终网格中形成一个矩形。 这是不正确的，因为后面的打印可能会覆盖前面矩形的部分。 该实现通过使用边界矩形和依赖性分析而不是形状验证来正确处理此问题。 

另一个关键的边缘情况是循环重叠。 如果两种颜色都出现在另一种颜色的边界矩形内，则两种颜色都需要在另一种颜色之前打印，这是不可能的。 拓扑排序自然会检测到这种情况，因为某些节点永远不会达到零入度。 

当一种颜色只出现一次时，就会出现第三种微妙的边缘情况。 它的边界矩形退化为单个单元格。 某些实现意外地假设矩形具有正的宽度和高度，从而导致索引错误。 此实现可以正确处理单单元格矩形，因为所有循环都是包容性的，并且即使在顶部等于底部或左侧等于右侧时也能工作。
