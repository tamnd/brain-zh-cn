 **难度：** 🔴难

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个整数的排列`1`到`n`，然后我们按照数字在数组中出现的确切顺序将数字插入到最初为空的二叉搜索树 (BST) 中。 

BST 具有以下性质：

 - 小于当前节点的值转到左子树。 
- 大于当前节点的值转到右子树。 

插入顺序很重要，因为它决定了树的形状。 

我们需要计算有多少次不同的数组重新排序会产生与原始数组完全相同的 BST 结构。 原始排序本身不应计入最终答案，这就是我们最后减一的原因。 

例如：```
nums = [3,4,5,1,2]
```形成的 BST 为：```
        3
       / \
      1   4
       \   \
        2   5
```任何以保留此结构的方式插入元素的重新排序数组都是有效的。 

约束条件很重要：

 -`n <= 1000`- 所有元素都是不同的
 - 答案可能变得非常大

 自从`n`达到 1000 时，无法进行强力排列生成，因为`1000!`是一个天文数字。 我们需要一种组合计数策略，而不是显式生成排列。 

一些边缘情况很重要：

 - 已经形成完全倾斜的 BST 的数组，例如`[1,2,3,4]`- 非常小的数组，例如`[1]`或者`[2,1]`- 平衡树，可以进行多次重新排序
 - 深度递归分区可以创建大量组合计数

 该问题保证所有数字都是不同的，这简化了 BST 构造，因为没有重复处理规则。 

## 方法

 ### 蛮力方法

 强力解决方案将生成数组的每个排列，并检查将该排列插入到 BST 中是否会产生与原始数组相同的树结构。 

该过程如下所示：

 1. 构建原始 BST`nums`。 
2. 生成所有排列`nums`。 
3. 对于每个排列：

 - 构建 BST。 
- 与原始 BST 进行比较。 
4. 计算匹配排列。 
5. 减一以排除原始排序。 

这种方法是正确的，因为它明确地检查每个可能的顺序。 然而，这是完全不可行的。 

为了`n = 1000`，排列数为：```
1000!
```这远远超出了任何可计算的极限。 

我们需要一种方法来以数学方式计算有效的重新排序而不枚举它们。 

### 关键见解

 关键的观察是，一旦根固定，相对排序约束在左子树和右子树之间就变得独立。 

Suppose the root is`r`。 

- 所有值小于`r`must appear in the left subtree.
 - 所有值都大于`r`必须出现在右子树中。 

左子树元素只能影响左子树结构。 

右子树元素只能影响右子树结构。 

因此：

 1. 递归地计算左子树的有效重新排序。 
2. 递归地计算右子树的有效重新排序。 
3. 计算有多少种方式可以交错左子树和右子树插入序列，同时保留其内部相对顺序。 

最后一部分是一个组合问题。 

如果：

 - 左子树有`L`元素
 - 右子树有`R`元素

 那么交错它们的方式数量是：$\binom{L+R}{L}$因为我们选择哪些位置属于左子树。 

递归公式变为：$f(nums)=\binom{L+R}{L}\times f(left)\times f(right)$这将问题转化为组合数学的分治问题。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n! * n) | O(n! * n) | O(n) | 生成所有排列并重建 BST |

 ## 算法演练

 1. 使用帕斯卡三角形预先计算所有二项式系数。 

在递归过程中我们需要反复组合。 自从`n <= 1000`，我们可以预先计算：$\binom{n}{k}$对于所有有效的`n`和`k`。 

帕斯卡的恒等式是：$\binom{n}{k}=\binom{n-1}{k-1}+\binom{n-1}{k}$这允许高效的动态编程构造。 
2. 定义递归函数。 

递归函数接收表示子树插入顺序的数组。 
3. 处理基本情况。 

如果子树的元素少于 3 个，则只有一种有效排序。 

- 空子树
 - 单节点
 - 有一个孩子的根

 这些情况都不允许进行替代重新排序。 
4. 将元素拆分为左子树和右子树。 

第一个元素始终是根。 

每个较小的值都会进入左侧数组。 

每个较大的值都会进入正确的数组。 
5. 递归计算子树计数。 

计算：

 - 左子树的重新排序次数
 - 右子树的重新排序次数
 6. 计算交错计数。 

如果左子树有`L`节点和右子树有`R`节点，我们可以将它们合并到：$\binom{L+R}{L}$方式同时保留内部顺序。 
7. 将所有内容相乘。 

总方式：$\binom{L+R}{L}\times leftWays\times rightWays$8. 返回最终答案减一。 

递归包括原始排序本身，因此在返回之前减一。 

### 为什么它有效

 该算法之所以有效，是因为 BST 插入仅取决于每个子树内的相对顺序。 

一旦根被修复：

 - 左子树值必须保持相同的相对顺序以保留左子树结构。 
- 右子树值必须保持相同的相对顺序以保留右子树结构。 

唯一的自由来自于交错的左子树和右子树插入。 这种交错的数量正是二项式系数。 由于左子树和右子树结构是独立的，因此将计数相乘即可得出有效重新排序的总数。 

## Python 解决方案```python
from typing import List

class Solution:
    def numOfWays(self, nums: List[int]) -> int:
        MOD = 10**9 + 7
        n = len(nums)

        # Precompute combinations using Pascal's Triangle
        comb = [[0] * (n + 1) for _ in range(n + 1)]

        for i in range(n + 1):
            comb[i][0] = 1
            comb[i][i] = 1

        for i in range(2, n + 1):
            for j in range(1, i):
                comb[i][j] = (comb[i - 1][j - 1] + comb[i - 1][j]) % MOD

        def count_ways(arr: List[int]) -> int:
            if len(arr) < 3:
                return 1

            root = arr[0]

            left_subtree = []
            right_subtree = []

            for value in arr[1:]:
                if value < root:
                    left_subtree.append(value)
                else:
                    right_subtree.append(value)

            left_ways = count_ways(left_subtree)
            right_ways = count_ways(right_subtree)

            left_size = len(left_subtree)
            right_size = len(right_subtree)

            interleavings = comb[left_size + right_size][left_size]

            return (
                interleavings
                * left_ways
                * right_ways
            ) % MOD

        return (count_ways(nums) - 1) % MOD
```该实现首先使用帕斯卡三角形预先计算二项式系数。 这避免了在递归期间重复重新计算组合。 

递归辅助函数`count_ways`一次处理一个子树。 第一个值成为根，其余元素被划分为左子树和右子树插入序列。 

递归独立地计算每个子树的有效重新排序的数量。 然后，代码计算这些子树序列可以以多少种方式交织，同时保留其内部顺序。 

最后，结果减一，因为原始排序不应该被计算在内。 

## 解决方案```go
package main

func numOfWays(nums []int) int {
	const MOD int = 1_000_000_007

	n := len(nums)

	// Precompute combinations
	comb := make([][]int, n+1)
	for i := 0; i <= n; i++ {
		comb[i] = make([]int, n+1)
		comb[i][0] = 1
		comb[i][i] = 1
	}

	for i := 2; i <= n; i++ {
		for j := 1; j < i; j++ {
			comb[i][j] = (comb[i-1][j-1] + comb[i-1][j]) % MOD
		}
	}

	var countWays func([]int) int

	countWays = func(arr []int) int {
		if len(arr) < 3 {
			return 1
		}

		root := arr[0]

		left := []int{}
		right := []int{}

		for _, value := range arr[1:] {
			if value < root {
				left = append(left, value)
			} else {
				right = append(right, value)
			}
		}

		leftWays := countWays(left)
		rightWays := countWays(right)

		leftSize := len(left)
		rightSize := len(right)

		interleavings := comb[leftSize+rightSize][leftSize]

		result := int(
			(int64(interleavings) *
				int64(leftWays) %
				int64(MOD) *
				int64(rightWays)) % int64(MOD),
		)

		return result
	}

	return (countWays(nums) - 1 + MOD) % MOD
}
```Go 实现与 Python 版本非常相似，但有一些特定于语言的注意事项。 

Go 整数在乘法过程中可能会溢出，因此中间乘积被转换为`int64`在应用模运算之前。 

切片用于表示子树插入顺序。 由于切片是动态的，因此附加左子树和右子树值很简单。 

最后的减法使用：```go
(countWays(nums) - 1 + MOD) % MOD
```以避免模减后出现负值。

from typing import List

class Solution:
    def numOfWays(self, nums: List[int]) -> int:
        MOD = 10**9 + 7
        n = len(nums)

        comb = [[0] * (n + 1) for _ in range(n + 1)]

        for i in range(n + 1):
            comb[i][0] = 1
            comb[i][i] = 1

        for i in range(2, n + 1):
            for j in range(1, i):
                comb[i][j] = (comb[i - 1][j - 1] + comb[i - 1][j]) % MOD

        def count_ways(arr: List[int]) -> int:
            if len(arr) < 3:
                return 1

            root = arr[0]

            left = [x for x in arr[1:] if x < root]
            right = [x for x in arr[1:] if x > root]

            left_ways = count_ways(left)
            right_ways = count_ways(right)

            return (
                comb[len(left) + len(right)][len(left)]
                * left_ways
                * right_ways
            ) % MOD

        return (count_ways(nums) - 1) % MOD

 ## 边缘情况

 完全倾斜的 BST 是最重要的边缘情况之一。 数组就像`[1,2,3,4,5]`创建一棵树，其中每个节点只有一个右子节点。 在这种情况下，只有一个有效的广告订单。 任何偏差都会立即改变树结构。 该实现自然地处理了这个问题，因为一个子树始终为空，使得每个递归级别的组合计数等于 1。 

非常小的数组是错误的另一个常见来源。 长度为 1 或 2 的数组不能产生替代的重新排序。 递归基本情况：```
if len(arr) < 3:
    return 1
```通过认识到这样的小树只有一种可能的排序，正确地处理了这些情况。 

平衡 BST 会产生极大的组合计数。 例如，具有许多节点的完美平衡树可以生成大量有效的重新排序。 如果没有模运算，就会发生整数溢出。 两种实现都适用模数`10^9 + 7`在所有计算中保持值有界。 

另一个微妙的边缘情况是模减法。 由于我们在最后减一以排除原始排序，因此如果不小心处理，结果可能会变为负值。 Go 实现显式添加了`MOD`申请之前`% MOD`以保证非负结果。
