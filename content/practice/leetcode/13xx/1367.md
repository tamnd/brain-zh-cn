[LeetCode 问题 1367](https://leetcode.com/problems/linked-list-in-binary-tree/)

 **难度：** 🟡 中等
 **主题：** 链表、树、深度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 该问题询问链表是否显示为二叉树内的连续向下路径。 该路径不需要从树的根部开始，但是一旦开始，它必须仅通过子指针向下移动，每一步向左或向右移动。 

链表表示为`head`，二叉树表示为`root`。 我们需要确定是否存在某个树节点，使得从该节点沿着向下的路径精确地产生链表中的值序列。 

向下的路径意味着：

 - 您可以从树中的任何节点开始
 - 在每一步，您可以移动到左孩子或右孩子
 - 你无法向上移动
 - 路径上的值必须按顺序匹配链表

 例如，如果链表是：```
4 -> 2 -> 8
```然后我们需要找到一个有值的树节点`4`，后跟包含的子路径`2`，后跟包含的子路径`8`。 

约束条件很重要：

 - 二叉树最多有2500个节点
 - 链表最多有100个节点

 这些限制足够小，使得递归深度优先搜索解决方案完全可行。 我们不需要像 KMP 这样的高级字符串匹配算法，尽管这样的解决方案是可能的。 

一些边缘情况很重要：

 - 匹配路径可以从树中的任何位置开始，而不仅仅是根
 - 多个节点可以共享相同的值，所以我们必须探索所有的可能性
 - 部分匹配可能会中途失败，需要回溯
 - 链表只能包含一个节点
 - 树可能包含许多重复值，导致许多递归分支
 - 有效路径在遍历过程中可能会在左右子节点之间切换

 该问题保证树和链表都至少包含一个节点。 

## 方法

 ### 蛮力方法

 最直接的方法是将每个树节点视为可能的起点。 对于每个节点，我们尝试使用递归向下匹配链表。 

该算法分两层工作：

 1.遍历树中的每个节点
 2. 对于每个节点，递归检查链表是否匹配从该节点开始的向下路径

 匹配函数比较：

 - 当前树节点值
 - 当前链表节点值

 如果它们匹配，则递归地继续到左子节点和右子节点。 

这种方法是正确的，因为每个可能的起始位置都会被探索，并且每个可能的向下路径都会被检查。 

缺点是可能会发生许多重叠的递归检查。 在最坏的情况下，每个树节点都可能尝试匹配几乎整个链表。 

不过，由于约束相对较小，这个解决方案对于 LeetCode 来说已经足够高效了。 

### 最佳方法的关键见解

 重要的观察是，问题自然地分为两个递归任务：

 - 寻找起点
 - 验证匹配的路径

 我们没有显式地构造所有可能的路径，而是在遍历树时直接执行递归匹配。 

在每个树节点：

 - 要么这个节点开始链表路径
 - 或者匹配路径存在于左子树中的某个位置
 - 或者匹配路径存在于右子树中的某个位置

 这种递归分解使实现保持干净并避免不必要的路径存储。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(N × M) | O(H + M) | 尝试匹配每个树节点的链表 |
 | 最佳 | O(N × M) | O(H + M) | 具有递归路径匹配的 DFS |

 这里：

-`N`= 树节点数
 -`M`= 链表节点数
 -`H`= 树的高度

 尽管两种方法具有相同的渐近复杂性，但递归 DFS 公式是最简洁、最实用的解决方案。 

## 算法演练

 1. 创建辅助函数`matchPath(listNode, treeNode)`。 

该函数检查链表是否从`listNode`匹配从以下位置开始的向下树路径`treeNode`。 
2.处理里面的base case`matchPath`。 

如果`listNode`变成`None`，我们成功匹配了整个链表，所以返回`True`。 

如果`treeNode`变成`None`在列表结束之前，路径失败，因此返回`False`。 
3. 比较当前值。 

如果`listNode.val != treeNode.val`，当前路径无法继续，所以返回`False`。 
4. 继续递归。 

如果值匹配，则递归地尝试将下一个链表节点与以下任一节点进行匹配：

 -`treeNode.left`-`treeNode.right`如果任一成功，则返回`True`。 
5. 使用主递归创建另一个 DFS 函数。 

该函数遍历树中的每个节点并将每个节点视为潜在的起始位置。 
6. 在每个树节点：

 - 尝试使用完整路径匹配`matchPath`- 如果失败，则递归搜索左子树
 - 如果失败，则递归搜索右子树
 7. 如果任一递归分支成功，则返回`True`。 
8. 如果探索整棵树没有成功，则返回`False`。 

### 为什么它有效

 该算法是正确的，因为每个树节点都被视为潜在的起点，并且对于每个起点，递归地探索每条有效的向下路径。 

递归不变量是：

 -`matchPath(listNode, treeNode)`回报`True`当且仅当链表开始于`listNode`完全匹配一些从以下位置开始的向下路径`treeNode`。 

由于外部 DFS 检查所有可能的起始节点，因此不会错过任何有效路径。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional

class Solution:
    def isSubPath(
        self,
        head: Optional[ListNode],
        root: Optional[TreeNode]
    ) -> bool:

        def match_path(
            list_node: Optional[ListNode],
            tree_node: Optional[TreeNode]
        ) -> bool:

            if list_node is None:
                return True

            if tree_node is None:
                return False

            if list_node.val != tree_node.val:
                return False

            return (
                match_path(list_node.next, tree_node.left)
                or
                match_path(list_node.next, tree_node.right)
            )

        if root is None:
            return False

        return (
            match_path(head, root)
            or
            self.isSubPath(head, root.left)
            or
            self.isSubPath(head, root.right)
        )
```该实现包含两个递归层。 

这`match_path`辅助函数验证链表是否可以从当前树节点继续。 它首先检查列表是否已被完全消耗。 如果是的话，比赛就成功了。 如果树路径结束得太早，则匹配失败。 

确认值相等后，递归会继续到两个子树，因为路径可能会经过任一子树。 

外递归对整棵树执行 DFS 遍历。 每个节点都成为链表的潜在起始位置。 

最终的返回语句结合了所有三种可能性：

 - 路径从当前节点开始
 - 路径存在于左子树中的某个位置
 - 该路径存在于右子树中的某个位置

 这直接反映了问题的递归结构。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */

/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */

func isSubPath(head *ListNode, root *TreeNode) bool {

    var matchPath func(*ListNode, *TreeNode) bool

    matchPath = func(listNode *ListNode, treeNode *TreeNode) bool {

        if listNode == nil {
            return true
        }

        if treeNode == nil {
            return false
        }

        if listNode.Val != treeNode.Val {
            return false
        }

        return matchPath(listNode.Next, treeNode.Left) ||
            matchPath(listNode.Next, treeNode.Right)
    }

    if root == nil {
        return false
    }

    return matchPath(head, root) ||
        isSubPath(head, root.Left) ||
        isSubPath(head, root.Right)
}
```Go 的实现与 Python 版本非常相似。 

主要区别在于 Go 使用显式指针类型和`nil`检查而不是Python的`None`。 

递归辅助函数是使用函数变量实现的，因此它们可以递归地引用自身。 

由于节点值是小整数，因此不必担心整数溢出。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(N × M) | 每个树节点可能会尝试匹配整个链表 |
 | 空间| O(H + M) | 树遍历和路径匹配的递归调用堆栈 |

 最坏的情况发生在许多树节点与链表头共享相同的值时。 在这种情况下，算法会重复尝试长部分匹配。 

递归深度受以下限制：

 - 树高`H`- 链表长度`M`因此辅助空间完全来自递归。

 ## 边缘情况

 ### 链表仅包含一个节点

 单节点链表是一种重要的边缘情况，因为算法应该在找到任何匹配的树节点后立即成功。 一些不正确的实现假设路径必须继续向下并且不必要地失败。 

这个实现自然地处理了这种情况。 一旦节点值匹配，递归调用就会收到`list_node.next == None`，立即返回`True`。 

### 多个树节点共享相同的值

 重复值可以创建许多可能的起点和重叠的递归搜索。 在一次失败的尝试后停止搜索的幼稚实现可能会错误地返回`False`。 

该解决方案正确地独立探索每个树节点作为起始位置。 即使一条路径中途失败，递归也会继续搜索树中的其他位置。 

### 部分匹配失败

 当链表部分匹配但最终发散时，就会出现一个常见的错误。 例如：```
List: 1 -> 2 -> 3
Tree path: 1 -> 2 -> 4
```不正确的实现可能会过早地接受部分匹配。 

此实现避免了该问题，因为仅当链表指针变为`None`。 链表中的每个节点必须按顺序完全匹配。
