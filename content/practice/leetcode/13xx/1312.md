 # LeetCode 1312 - 生成字符串回文的最少插入步骤

 ## 问题理解

 问题给了我们一个字符串`s`并询问将字符串转换为回文所需的**最小插入操作次数**。 在单个操作中，我们可以在字符串中的任何位置**插入任何小写英文字符。 插入的字符不必与现有字符匹配，我们可以自由地在开头、中间或结尾插入。 

回文是从左到右和从右到左读相同的字符串。 例子包括`"racecar"`,`"abba"`， 和`"zzazz"`。 目标不是返回结果回文本身，而只是返回使给定字符串成为回文的**所需的最小插入次数**。 

为了更清楚地理解任务，请考虑字符串`"mbadm"`。 该字符串当前不是回文，因为字符彼此不对称镜像。 但是，通过插入两个字符，我们可以将其转换为`"mbdadbm"`或者`"mdbabdm"`。 由于这可以通过两次插入来完成，并且没有解决方案需要更少的操作，所以答案是`2`。 

输入由单个字符串组成`s`， 在哪里：

-`1 <= s.length <= 500`-`s`仅包含小写英文字母

 最大字符串长度为`500`很重要，因为它强烈建议二次时间动态规划解决方案，`O(n²)`，是可行的，而指数方法会太慢。 

有几种边缘情况值得尽早考虑：

 - **已经是回文**的字符串，例如`"zzazz"`，应该返回`0`。 
- **单字符字符串**始终是回文，因此需要`0`插入。 
- 具有**所有唯一字符**的字符串，例如`"abc"`，可能需要多次插入。 
- 字符重复但对称性较差的字符串，例如`"leetcode"`，仍可能需要多次插入。 
- 非常长的字符串接近极限`500`字符需要有效的算法，因为暴力破解在计算上是不可行的。 

该问题保证了有效的小写输入和非空字符串，因此我们不需要处理无效或空输入。 

## 方法

 ### 蛮力方法

 解决这个问题的一个简单方法是递归地尝试在每个可能的位置插入每个可能的字符，并检查结果字符串是否成为回文。 对于字符之间的每个不匹配，我们可以分支到多个递归可能性并尝试所有插入组合。 

例如，如果左右两端的字符不匹配，我们可以尝试：

 1. 将左侧字符插入右侧附近。 
2. 在左侧附近插入右侧字符。 
3. 递归地探索两种可能性。 

最终，我们将生成每一种可能的有效转换，并选择需要最少插入的转换。 

这种方法是正确的，因为它探索了插入可能性的整个搜索空间。 然而，它太慢了。 可能的插入组合的数量呈指数级增长，使得字符串达到最大长度是不切实际的`500`。 

记忆递归方法可以减少重复工作，但更好的洞察力使我们能够制定干净的动态编程解决方案。 

### 关键见解

 与其考虑**插入什么**，不如考虑**我们可以保留什么**。 

回文是对称的。 因此，如果我们能够识别出**已经是回文的最长子序列**，我们只需要在剩余部分周围插入字符即可。 

这一观察将问题转化为：

 > 最少插入次数 = 字符串长度 - 最长回文子序列 (LPS) 的长度

 为什么这有效？ 

假设字符串有长度`n`最长回文子序列的长度为`L`。 

子序列已经形成回文的对称核心。 该子序列之外的每个剩余字符都必须通过插入相应的字符来匹配。 因此，我们准确地需要`n - L`插入。 

现在问题变成：

 > 我们如何有效地计算最长回文子序列？ 

一个有用的技巧是：

 > 最长回文子序列`s`等于之间的最长公共子序列 (LCS)`s`和`reverse(s)`。 

因此，我们可以使用 LCS 的经典动态规划来解决这个问题。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(2ⁿ) 或更糟 | O(n) 递归 | 递归尝试多种插入组合 |
 | 最优动态规划| O(n²) | O(n²) | 使用 LCS 计算最长回文子序列 |

 ## 算法演练

 我们将计算原始字符串与其反转版本之间的**最长公共子序列（LCS）**。 

### 步骤 1：反转字符串

 创建字符串的反向副本。 

如果：```
s = "mbadm"
```然后：```
reversed_s = "mdabm"
```任何回文子序列在两个字符串中都以相同的顺序出现。 

### 步骤2：创建DP表

 我们创建一个`dp`表其中：```
dp[i][j]
```表示以下之间的**最长公共子序列**的长度：```
s[:i]
```和：```
reversed_s[:j]
```桌子尺寸为：```
(n + 1) x (n + 1)
```我们使用额外的行和列初始化为`0`简化边界条件。 

### 第 3 步：填写表格

 迭代两个字符串。 

如果字符匹配：```
s[i - 1] == reversed_s[j - 1]
```我们扩展子序列：```
dp[i][j] = dp[i - 1][j - 1] + 1
```如果字符不匹配：```
dp[i][j] = max(
    dp[i - 1][j],
    dp[i][j - 1]
)
```这确保了我们保持迄今为止发现的最佳子序列长度。 

### 步骤 4：获取最长回文子序列

 填表后：```
dp[n][n]
```包含最长回文子序列的长度。 

### 步骤 5：计算最小插入次数

 最后：```
answer = n - longest_palindromic_subsequence
```这给出了所需的最小插入次数。 

### 为什么它有效

 关键的不变量是`dp[i][j]`始终存储原始字符串和反转字符串的前缀之间的最佳公共子序列的长度。 

由于回文向前和向后读取的方式相同，因此任何回文子序列都会出现在字符串及其反向中。 因此，该字符串及其逆序的LCS正是最长回文子序列。 

一旦我们知道已经存在的最大对称部分，则必须通过插入来镜像每个剩余的不匹配字符。 因此：```
minimum insertions = n - LPS
```保证正确性。 

## Python 解决方案```python
class Solution:
    def minInsertions(self, s: str) -> int:
        n = len(s)
        reversed_s = s[::-1]

        dp = [[0] * (n + 1) for _ in range(n + 1)]

        for i in range(1, n + 1):
            for j in range(1, n + 1):
                if s[i - 1] == reversed_s[j - 1]:
                    dp[i][j] = dp[i - 1][j - 1] + 1
                else:
                    dp[i][j] = max(
                        dp[i - 1][j],
                        dp[i][j - 1]
                    )

        longest_palindromic_subsequence = dp[n][n]

        return n - longest_palindromic_subsequence
```实现首先计算字符串的反转版本。 由于我们想要最长的回文子序列，因此我们将问题转换为原始字符串与其反向字符串之间的 LCS 计算。 

然后，我们创建一个动态编程表，其中每个单元存储两个前缀的 LCS 长度。 初始化为零的额外行和列使边界处理更容易，因为空前缀自然具有子序列长度`0`。 

嵌套循环对字符进行一一比较。 当字符匹配时，我们从对角单元格扩展一个有效的子序列。 当它们不同时，我们继承从原始字符串或反转字符串中删除字符的最佳结果。 

表格完成后，`dp[n][n]`存储最长的回文子序列长度。 从原始长度中减去该值即可得出所需的最少插入次数。 

## 解决方案```go
func minInsertions(s string) int {
	n := len(s)

	reversed := reverseString(s)

	dp := make([][]int, n+1)
	for i := range dp {
		dp[i] = make([]int, n+1)
	}

	for i := 1; i <= n; i++ {
		for j := 1; j <= n; j++ {
			if s[i-1] == reversed[j-1] {
				dp[i][j] = dp[i-1][j-1] + 1
			} else {
				dp[i][j] = max(
					dp[i-1][j],
					dp[i][j-1],
				)
			}
		}
	}

	longestPalindromicSubsequence := dp[n][n]

	return n - longestPalindromicSubsequence
}

func reverseString(s string) string {
	bytes := []byte(s)

	left := 0
	right := len(bytes) - 1

	for left < right {
		bytes[left], bytes[right] =
			bytes[right], bytes[left]

		left++
		right--
	}

	return string(bytes)
}

func max(a, b int) int {
	if a > b {
		return a
	}
	return b
}
```Go 实现遵循与 Python 版本相同的动态编程结构。 由于 Go 不提供内置的字符串反转，因此我们实现了一个辅助函数来反转字节切片。 

与 Python 列表不同，Go 需要使用显式分配二维切片`make`。 我们单独初始化每一行。 

整数溢出不是问题，因为最大 DP 值最多为`500`，它很容易适合 Go 的内部`int`类型。 

由于保证输入非空且包含小写英文字母，因此我们不需要额外的输入验证。

 ## 边缘情况

 ### 单字符串

 一个长度的字符串`1`始终是回文，因为它向前和向后读起来相同。 如果没有正确处理简单的基本情况，幼稚的实现可能会意外地过度计算插入次数。 我们的实现自然地处理这个问题，因为最长的回文子序列是字符本身，产生：```
1 - 1 = 0
```### 已经是回文字符串

 输入如`"racecar"`或者`"zzazz"`应该返回`0`。 某些实现会错误地插入不必要的字符，因为它们只检查本地不匹配。 由于我们的解决方案计算全局最长回文子序列，因此整个字符串成为子序列，不会产生插入。 

### 完全非回文结构

 字符串像`"abcd"`不包含重复字符并且对称性非常弱。 天真的贪婪策略可能会失败，因为选择本地插入可能会产生次优结果。 我们的动态规划方法评估所有子序列的可能性并正确确定：```
LPS = 1
```所以：```
4 - 1 = 3
```需要插入。 

### 具有多种选择的重复字符

 字符串像`"banana"`很棘手，因为存在几个有效的回文子序列。 贪心的方法可能会选择局部有吸引力的匹配，而错过最佳答案。 动态编程通过探索每个前缀组合并始终保留全局最佳子序列长度来避免此问题。
