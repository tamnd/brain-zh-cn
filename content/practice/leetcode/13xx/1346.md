[LeetCode 第 1346 题](https://leetcode.com/problems/check-if-n-and-its-double-exist/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表、两个指针、二分查找、排序

 ## 解决方案

 ## 问题理解

 问题给出一个整数数组`arr`并询问是否存在两个不同的索引`i`和`j`这样：```
arr[i] == 2 * arr[j]
```简单来说，我们需要确定数组中的一个数字是否恰好是同一数组中另一个数字的两倍。 

索引必须不同，这意味着我们不能使用同一个元素两次，除非它在数组中出现多次。 例如，如果数组包含两个零，则一个零可以被视为另一个零的双倍，因为：```
0 == 2 * 0
```输入是一个整数数组，其中可能包括：

 - 正数
 - 负数
 - 零

 预期输出是一个布尔值：

 -`true`如果存在这样的一对
 -`false`否则

 限制相对较小：```
2 <= arr.length <= 500
-1000 <= arr[i] <= 1000
```由于数组大小最多为 500，即使是`O(n^2)`暴力解决方案在实践中是可以接受的。 然而，该问题旨在鼓励使用哈希集识别更有效的基于查找的方法。 

一些边缘情况很重要：

 - 包含零的数组，尤其是多个零
 - 负数，因为负值加倍仍然有效
 - 重复值
 - 尺寸为 2 的非常小的数组
 - 双精度数出现在原始值之前的情况

 幼稚的实现很容易错误地处理零或假设较小的值总是首先出现。 

## 方法

 ### 蛮力方法

 最直接的解决方案是比较每对索引`(i, j)`在哪里`i != j`。 

For each pair, we check:```
arr[i] == 2 * arr[j]
```如果我们找到有效的一对，我们立即返回`true`。 如果检查了所有对但没有一个满足条件，我们返回`false`。 

这种方法是正确的，因为它详尽地检查了两种不同元素的每种可能的组合。 由于该问题仅询问是否存在至少一对有效的对，因此完整的搜索可以保证正确性。 

然而，该方法需要嵌套循环，导致时间复杂度为二次方。 虽然约束足够小，这仍然有效，但它不是最有效的方法。 

### 最优哈希集方法

 关键的观察是对于每个数字`x`，我们只需要知道是否：

 -`2 * x`已经存在
 -`x / 2`已经存在，当`x`是偶数

 哈希集允许恒定时间平均查找操作。 

当我们迭代数组时，我们将之前看到的数字存储在一个集合中。 对于每个当前数字：

 - 如果它的双精度数已经存在于集合中，我们找到了一个有效的对
 - 如果它是偶数并且它的一半已经存在于集合中，我们也找到了一个有效的对

 这是有效的，因为关系可以以任一顺序出现在数组中。 较大的值可能出现在较小的值之前，反之亦然。 

使用哈希集可以降低时间复杂度`O(n^2)`到`O(n)`平均而言。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 比较每对元素 |
 | 最佳| O(n) | O(n) | 使用哈希集进行恒定时间查找 |

 ## 算法演练

 1. 创建一个名为的空哈希集`seen`。 

该集合将存储我们已经处理过的数字。 选择哈希集是因为它提供了平均值`O(1)`查找时间。 
2. 迭代每个数字`num`在数组中。 

我们一次处理一个元素，并检查匹配值是否已经出现在较早的位置。 
3. 检查是否`num * 2`存在于集合中。 

如果是，那么我们之前遇到过一个数字，其 double 是当前值关系。 
4. 检查是否`num`是偶数并且是否`num // 2`存在于集合中。 

这可以处理逆序情况，即较小的数字出现较早。 我们只检查偶数的一半，因为整数加倍总是产生偶数结果。 
5. 如果任一条件为 true，则返回`True`。 

我们发现两个不同的元素满足条件。 
6. 将当前号码添加到集合中。 

未来的元素现在可以与该值进行比较。 
7. 如果循环结束时没有找到有效的对，则返回`False`。 

### 为什么它有效

 该算法保持不变式`seen`包含所有先前处理过的数字。 

对于每个当前数字`x`，如果满足以下任一条件，则存在有效对：```
2 * x
```已经出现，或者：```
x / 2
```已经出现的时候`x`是均匀的。 

由于每个元素都会针对所有先前看到的值进行一次检查，因此最终会检测到每个有效对。 因此，算法总是会产生正确的答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def checkIfExist(self, arr: List[int]) -> bool:
        seen = set()

        for num in arr:
            if (num * 2) in seen:
                return True

            if num % 2 == 0 and (num // 2) in seen:
                return True

            seen.add(num)

        return False
```实现首先创建一个名为的空集`seen`。 该集合存储所有先前处理的数字。 

该循环仅迭代数组中的每个元素一次。 对于每个数字，代码都会执行两次检查。 

第一个检查确定集合中是否已存在当前数字的双倍。 这捕获了较大值较早出现的情况。 

第二个检查确定当前数量的一半是否已经存在。 由于只有偶数可以是整数的双精度数，因此代码首先检查`num % 2 == 0`。 

如果任一条件成功，该函数立即返回`True`。 

如果未找到匹配项，则将当前数字插入到集合中，以便后面的元素可以与其进行比较。 

如果循环完成时未找到任何有效对，则函数返回`False`。 

## 解决方案```go
func checkIfExist(arr []int) bool {
    seen := make(map[int]bool)

    for _, num := range arr {
        if seen[num*2] {
            return true
        }

        if num%2 == 0 && seen[num/2] {
            return true
        }

        seen[num] = true
    }

    return false
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 由于 Go 没有内置的集合类型，因此`map[int]bool`用于模拟哈希集。 

查找操作平均时间保持恒定。 

Go 中的整数除法在这里表现正确，因为代码只检查`num/2`什么时候`num`是均匀的。 因此，不会丢失任何小数值。 

没有特殊的 nil 处理要求，因为迭代空切片是安全的，尽管该问题保证至少有两个元素。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个元素都通过常量时间集查找处理一次 |
 | 空间| O(n) | 哈希集可以存储所有数组元素 |

 该算法对数组执行单次遍历。 每次迭代仅执行恒定时间操作：哈希查找和插入。 

在最坏的情况下，不存在有效的对，因此每个元素都存储在集合中。 因此，空间复杂度与输入的大小成线性关系。

 ## 边缘情况

 一种重要的边缘情况涉及零。 自从：```
0 == 2 * 0
```两个零构成有效对。 有缺陷的实现可能会通过阻止相等值的比较而意外地拒绝这种情况。 该算法可以正确处理它，因为第一个零被添加到集合中，第二个零立即检测到它的一半和双倍已经存在。 

另一个重要的边缘情况涉及负数。 某些实现错误地假设加倍关系仅适用于正整数。 然而：```
-4 == 2 * -2
```是完全有效的。 哈希集方法将负值与正值完全相同，因此逻辑无需修改即可保持正确。 

当较大的数字出现在较小的数字之前时，就会出现第三种棘手的情况。 例如：```
[10, 5]
```如果我们只检查是否`2 * num`如果存在得更早，我们就会怀念这种关系。 该算法还通过检查集合中是否已存在当前偶数的一半来避免此问题。 

另一个微妙的情况涉及不为零的重复值。 例如：```
[1, 1, 1]
```尽管存在重复项，但它们都不是彼此的双倍。 算法正确返回`False`因为双重条件和有效一半条件都不满足。
