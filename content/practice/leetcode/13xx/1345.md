 **主题：** 数组、哈希表、广度优先搜索

 ## 解决方案

 ## 问题理解

 问题是在给定特定的移动规则的情况下，要求从第一个索引开始到达整数数组的最后一个索引所需的最少步数。 您可以移至下一个索引（`i + 1`), 前一个索引 (`i - 1`)，或任何其他索引`j`其中该值等于`arr[i]`。 本质上，您正在浏览一个图表，其中每个索引都是一个节点，并且相邻索引和具有相同值的索引之间存在边。 

输入，`arr`，是长度最大为 50,000 的整数数组，值范围为 -10^8 到 10^8。 输出是一个整数，表示到达最后一个索引的最小步数。 

约束意味着检查每个可能的跳转序列的简单解决方案会太慢，因为潜在路径的数量随着数组的长度呈指数增长。 边缘情况包括长度为 1 的数组、所有元素都相同的数组以及重复值间隔很宽的数组，如果处理不当，可能会导致不必要的重复跳转。 

## 方法

 暴力方法将涉及递归地探索每个索引的所有可能的跳转，直到到达最后一个索引。 这保证了正确性，因为它会探索每条路径，但由于大小为 50,000 的数组的路径数量呈指数级增长，因此这是不可行的。 

更有效解决方案的关键见解是将数组视为隐式图，其中每个索引都是连接到的节点`i+1`,`i-1`，以及具有相同值的所有其他指数。 然后，问题就简化为在未加权图中查找最短路径，这正是广度优先搜索（BFS）的设计目的。 为了进一步优化，在访问具有特定值的所有索引后，我们可以从映射中删除该值，以避免不必要的重复工作。

 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 递归探索所有路径，对于大型数组来说太慢 |
 | 最优 BFS | O(n) | O(n) | 在图上使用 BFS，其中节点是索引，边是跳跃，通过删除访问的值组进行优化 |

 ## 算法演练

 1. 创建从每个值到该值出现的所有索引的映射。 这允许 O(1) 访问相同值的所有跳转。 
2. 使用起始索引初始化 BFS 队列`0`和一个访问集以避免重新访问索引。 
3. 初始化计步器`0`。 
4. 当队列不为空时：

 1. 对于当前BFS级别的每个索引，检查它是否是最后一个索引。 如果是，则返回步数。 
2.添加邻居`i-1`和`i+1`如果它们在范围内并且未被访问过，则将其放入队列。 
3. 如果其他索引没有被访问过，则将所有具有相同值的索引添加到队列中。 
4. 从映射中删除当前值，以避免稍后重新访问这些索引。 
5. 处理完每个级别后递增计步器。 
6. 继续，直到到达最后一个索引。 BFS 保证第一次到达最后一个索引时，是通过最短路径。 

**为什么有效**：BFS 逐级探索节点，保证第一次到达节点时是通过从一开始的最短路径。 通过将节点标记为已访问并删除已处理的值组，我们可以避免循环和冗余工作。 

## Python 解决方案```python
from collections import deque, defaultdict
from typing import List

class Solution:
    def minJumps(self, arr: List[int]) -> int:
        if len(arr) == 1:
            return 0

        # Map each value to all indices where it occurs
        value_to_indices = defaultdict(list)
        for i, val in enumerate(arr):
            value_to_indices[val].append(i)

        queue = deque([0])
        visited = set([0])
        steps = 0

        while queue:
            for _ in range(len(queue)):
                current = queue.popleft()
                if current == len(arr) - 1:
                    return steps

                # Check neighbors
                neighbors = [current - 1, current + 1] + value_to_indices.get(arr[current], [])
                for neighbor in neighbors:
                    if 0 <= neighbor < len(arr) and neighbor not in visited:
                        visited.add(neighbor)
                        queue.append(neighbor)

                # Clear the list to prevent future redundant jumps
                value_to_indices[arr[current]] = []

            steps += 1

        return -1
```该实现首先构建值到索引的映射，以便 O(1) 访问相同值跳转。 BFS 确保第一次到达最后一个索引时是通过最少的步骤。 访问后清除每个值的映射可以避免未来不必要的迭代。 

## 解决方案```go
package main

func minJumps(arr []int) int {
    n := len(arr)
    if n == 1 {
        return 0
    }

    valueToIndices := make(map[int][]int)
    for i, val := range arr {
        valueToIndices[val] = append(valueToIndices[val], i)
    }

    queue := []int{0}
    visited := make([]bool, n)
    visited[0] = true
    steps := 0

    for len(queue) > 0 {
        nextQueue := []int{}
        for _, current := range queue {
            if current == n-1 {
                return steps
            }

            neighbors := []int{current - 1, current + 1}
            neighbors = append(neighbors, valueToIndices[arr[current]]...)

            for _, neighbor := range neighbors {
                if neighbor >= 0 && neighbor < n && !visited[neighbor] {
                    visited[neighbor] = true
                    nextQueue = append(nextQueue, neighbor)
                }
            }

            valueToIndices[arr[current]] = nil
        }
        queue = nextQueue
        steps++
    }

    return -1
}
```在 Go 中，切片用作 BFS 队列，布尔切片跟踪访问过的索引。 清除映射中的切片可防止冗余跳转，类似于 Python 解决方案。 

## 工作示例

 **示例1**：`arr = [100,-23,-23,404,100,23,23,23,3,404]`0级：`[0]`→ 步数 = 0

 1 级：`[1, 4]`→ 从 0 跳转到 1 或 4

 2 级：`[2, 3, 5]`→ 从4跳到3

 3级：`[9]`→ 从3跳到9，最后一个索引到达

 **示例2**：`arr = [7]`0级：`[0]`→ 开始是最后一个索引 → 步骤 = 0

 **示例3**：`arr = [7,6,9,6,9,6,9,7]`0级：`[0]`→ 步数 = 0

 1 级：`[7]`→ 使用值 7 直接跳转到最后一个索引 → 步骤 = 1

 ## 边缘情况

 **单元素数组**：如果数组只有一个元素，则最少步骤为`0`。 BFS 通过检查起始索引来自动处理这个问题。 

**所有元素都相同**：如果数组包含相同的值，则简单的 BFS 可以在相同值的索引之间重复跳转。 首次使用后清除映射可确保我们只考虑这些跳转一次。 

**具有遥远重复项的大型数组**：对于具有相距较远的重复值的数组，重要的是不要重新访问已处理的数据
