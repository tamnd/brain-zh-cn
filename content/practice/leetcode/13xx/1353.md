[LeetCode 问题 1353](https://leetcode.com/problems/maximum-number-of-events-that-can-be-attended/)

 **难度：** 🟡 中等
 **主题：** 数组、贪婪、排序、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个事件列表，其中每个事件都表示为一对`[startDay, endDay]`。 在此范围内的任何一天都可以参加活动。 目标是参加尽可能多的活动，但每天只能参加一场活动。 

换句话说，每个事件占用一个灵活的间隔而不是固定的时隙。 我们可以自由地为每个活动选择确切的一天，只要这一天位于其开始日和结束日之间即可。 由于多个活动可能会在同一天重叠，因此我们必须仔细决定每天参加哪个活动，以最大限度地提高总数。 

例如，如果我们有一个事件`[1, 3]`，我们可以在第 1 天、第 2 天或第 3 天参加。一旦我们为该活动选择了某一天，该天就不能用于其他活动。 

输入尺寸很大：

 - 最多`10^5`事件
 - 天数也可以延长至`10^5`这些限制立即排除了效率极低的方法。 任何具有二次复杂度的算法，例如反复检查每天的每个事件，都会太慢。 

该问题保证：

 - 每个事件都有两个整数
 -`startDay <= endDay`- 所有数值均为正值

 尽早识别几个边缘情况很重要：

 - 多个事件可能具有相同的范围
 - 许多活动可能在同一天严重重叠
 - 有些活动可能只持续一天，例如`[5, 5]`- 活动的开始时间可能相距很远，从而在日历中造成间隙
 - 大量活动可能会在同一天结束

 如果幼稚的策略过早地贪婪地参与持续时间较长的事件，并稍后阻止较短的紧急事件，那么它很容易失败。 

## 方法

 ### 蛮力方法

 暴力策略会尝试逐个处理事件，并将每个事件分配给其时间间隔中最早的可用日期。 

一种可能的实现是：

 1. 按开始日期对事件进行排序。 
2. 对于每个事件，每天扫描`startDay`到`endDay`。 
3. 如果发现未使用的日期，请在当天参加活动。 
4. 将这一天标记为已占用。 

这是有效的，因为每个活动都试图在其范围内申请一个有效的免费日。 

然而，当间隔很大时，这种方法会变得太慢。 在最坏的情况下：

 - 有`10^5`事件
 - 每个事件跨越`10^5`天

 这可能导致`O(N * D)`工作，可以接近`10^10`运营。 

这远远超出了可接受的限度。 

### 最佳解决方案背后的关键见解

 关键的观察是，当某一天有多个活动可用时，我们应该参加最早结束的活动。 

为什么？ 

因为结束日期较早的事件更加紧急。 如果我们推迟它们，它们可能会过期并且以后无法参加。 结束日期较晚的活动更加灵活，通常可以安排在未来。 

这自然会导致贪婪策略：

 - 按时间顺序处理日期
 - 添加当天开始的所有事件
 - 在可用的活动中，始终参加结束日期最短的活动

 为了有效地检索最早结束日期的事件，我们使用最小堆。 

堆存储当前可用事件的结束日期。 

排序和优先级队列的这种组合使我们能够始终做出局部最优决策，同时保持效率。

 ## 算法演练

 ### 最优贪心+最小堆算法

 1. 按开始日期对所有事件进行排序。 

按时间顺序处理事件使我们能够准确地知道事件何时可用。 排序后，我们可以迭代几天并逐步添加事件纳入考虑范围。 
2. 维护一个包含当前可用事件的结束日期的最小堆。 

堆代表以下所有事件：

 - 已经开始了
 - 尚未过期
 - 没有参加过

 堆中的最小值对应于最早结束的事件。 
3. 日复一日地迭代。 

我们从最早的相关日期开始模拟日历。 
4. 添加开始日期等于当天的所有事件。 

这些活动从今天开始就可以参加，因此我们将它们的结束日期推入堆中。 
5. 从堆中删除过期事件。 

任何结束日期早于当天的活动都无法再参加。 这些事件必须被丢弃。 
6. 如果可能的话，参加一项活动。 

如果堆不为空，则从堆中弹出最小的结束日。 

这对应于参加最快到期的活动。 

增加答案计数。 
7. 继续，直到处理完所有事件并且堆变空。 

到那时，就没有更多可以参加的活动了。 

### 为什么它有效

 贪婪的选择始终是最佳选择，因为参加最早结束日期的活动可以为未来几天保留最大的灵活性。 

假设我们参加了一项较晚结束的活动，而跳过了一项较早结束的活动。 较晚结束的活动仍有可能在未来某一天参加，但较早结束的活动可能会永久过期。 因此，优先考虑较早的截止日期永远不会减少最佳答案。 

这是一个经典的区间调度贪婪论证。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def maxEvents(self, events: List[List[int]]) -> int:
        events.sort()

        min_heap = []
        event_index = 0
        attended = 0

        max_day = max(end for _, end in events)

        for day in range(1, max_day + 1):

            while event_index < len(events) and events[event_index][0] == day:
                heapq.heappush(min_heap, events[event_index][1])
                event_index += 1

            while min_heap and min_heap[0] < day:
                heapq.heappop(min_heap)

            if min_heap:
                heapq.heappop(min_heap)
                attended += 1

        return attended
```实施首先按开始日期对事件进行排序。 这确保了事件在可用时被准确地引入堆中。 

这`min_heap`存储活动事件的结束日期。 蟒蛇的`heapq`模块提供了高效的最小优先级队列实现。 

变量`event_index`跟踪哪些事件已插入堆中。 随着时间的推移，新的可用事件被推入堆中。 

在参加某一天的活动之前，过期的活动将被删除。 任何结束日期早于当前日期的活动都不再有效。 

如果至少剩余一个有效事件，算法将通过从堆中弹出来参与具有最小结束日的事件。 

参加活动的次数累计在`attended`。 

## 解决方案```go
package main

import (
	"container/heap"
	"sort"
)

type MinHeap []int

func (h MinHeap) Len() int {
	return len(h)
}

func (h MinHeap) Less(i, j int) bool {
	return h[i] < h[j]
}

func (h MinHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MinHeap) Push(x interface{}) {
	*h = append(*h, x.(int))
}

func (h *MinHeap) Pop() interface{} {
	old := *h
	n := len(old)
	value := old[n-1]
	*h = old[:n-1]
	return value
}

func maxEvents(events [][]int) int {
	sort.Slice(events, func(i, j int) bool {
		return events[i][0] < events[j][0]
	})

	maxDay := 0
	for _, event := range events {
		if event[1] > maxDay {
			maxDay = event[1]
		}
	}

	minHeap := &MinHeap{}
	heap.Init(minHeap)

	eventIndex := 0
	attended := 0

	for day := 1; day <= maxDay; day++ {

		for eventIndex < len(events) && events[eventIndex][0] == day {
			heap.Push(minHeap, events[eventIndex][1])
			eventIndex++
		}

		for minHeap.Len() > 0 && (*minHeap)[0] < day {
			heap.Pop(minHeap)
		}

		if minHeap.Len() > 0 {
			heap.Pop(minHeap)
			attended++
		}
	}

	return attended
}
```Go 实现遵循与 Python 版本相同的算法结构。 主要区别在于 Go 没有为整数提供内置的堆抽象，因此我们实现`heap.Interface`。 

堆存储事件结束日期与 Python 中完全相同。 由于所有约束都完全符合 Go 的标准`int`类型，整数溢出不是这里的问题。 

Go 切片的大小是动态调整的，使它们成为堆实现的自然支持结构。

 ## 边缘情况

 ### 具有相同范围的多个事件

 A common source of bugs occurs when many events share exactly the same start and end days. 例如：```
[[1,2],[1,2],[1,2]]
```Only two events can actually be attended because there are only two available days. A naive implementation may accidentally overcount if it does not correctly mark days as used.

 The heap-based solution handles this naturally by allowing only one event to be popped and attended per day.

 ### 仅持续一天的活动

 Events such as`[5,5]`限制非常严格，因为它们只能在同一天参加。 

如果算法将它们推迟，哪怕是短暂的，它们也会立即过期。 

贪婪策略优先考虑最早结束的日期，这确保在必要时先参加这些单日活动，然后再参加更灵活的活动。 

### 大重叠间隔

 考虑许多事件，例如：```
[[1,100000],[1,100000],[1,100000]]
```暴力方法可能会浪费大量时间反复扫描。 

堆解决方案完全避免了重新扫描间隔。 每个事件插入一次，移除一次，保持高效`O(N log N)`即使在最大限制下也能保证性能。
