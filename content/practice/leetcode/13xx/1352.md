[LeetCode 问题 1352](https://leetcode.com/problems/product-of-the-last-k-numbers/)

 **难度：** 🟡 中等
 **主题：** 数组、数学、设计、数据流、前缀和

 ## 解决方案

 ## 问题理解

 这个问题要求我们设计一个数据结构，能够连续处理整数流，并且支持查询最后一个整数的乘积`k`插入的数字。 

这`ProductOfNumbers`类以空序列开始。 每次`add(num)`被调用时，一个新的整数被附加到流中。 之后，`getProduct(k)`必须返回最近的乘法结果`k`数字。 

例如，如果流当前包含：```
[3, 0, 2, 5, 4]
```然后：

-`getProduct(2)`回报`5 × 4 = 20`-`getProduct(3)`回报`2 × 5 × 4 = 40`-`getProduct(4)`回报`0 × 2 × 5 × 4 = 0`挑战在于流是动态增长的，并且查询可能会频繁发生。 幼稚的实现可以通过迭代上一次来每次重新计算乘积`k`数字，但后续明确询问是否可以进行这两种操作`O(1)`。 

约束条件很重要：

 - 至多`4 × 10⁴`拨打电话至`add`和`getProduct`。 
- 每个`num`介于`0`和`100`。 
- 任何连续子数组的乘积都适合 32 位整数。 

最大的挑战是处理`0`。 与零相乘会重置乘积，这意味着除非仔细处理零，否则简单的前缀乘积除法技术将不起作用。 

一些重要的边缘情况立即脱颖而出：

 - **零出现在流中**：任何包含该零的产品系列都会变成`0`。 
- **连续零**：必须正确处理多次重置。 
- **`k`跨越最近的零**：如果查询范围内存在零，则答案必须是`0`。 
- **小流**：问题保证`k`总是有效的，这意味着至少有`k`可用的号码。 

## 方法

 ### 蛮力方法

 最直接的解决方案是将所有插入的数字存储在一个列表中，并在任何时候手动计算乘积`getProduct(k)`被称为。 

什么时候`add(num)`被调用时，我们只需将数字附加到数组中即可。 

什么时候`getProduct(k)`被要求时，我们向后迭代最后一个`k`元素并将它们相乘。 

这是有效的，因为它根据所涉及的确切数字显式地计算所需的乘积。 由于乘法具有关联性，因此迭代范围可以保证得到正确的结果。 

然而，这种方法变得低效，因为每个查询都需要`O(k)`时间。 自从`k`可以大到`4 × 10⁴`，重复查询可能会变得昂贵。 

### 最佳方法，为产品添加归零前缀

 关键的观察结果是，在重叠范围内重复乘法是浪费的。 

我们可以维护**前缀产品**，而不是重复地重新计算产品。 通常，如果：```
prefix[i] = product of first i elements
```那么最后的产品`k`数字可以计算为：```
prefix[n] / prefix[n-k]
```这提供了恒定时间范围的产品检索。 

然而，零使事情变得复杂，因为除以包含零的前缀是不可能的。 我们的见解是，每当`0`出现，每个跨越零的产品必须是`0`，所以我们可以**重置前缀数组**。 

我们维护一个前缀产品列表，开头为`1`作为哨兵：```
[1]
```对于非零数：```
prefix.append(prefix[-1] * num)
```对于零：```
prefix = [1]
```然后在回答的时候`getProduct(k)`：

- 如果`k >= len(prefix)`，这意味着查询跨越零，所以返回`0`。 
- 否则：```
prefix[-1] // prefix[-1-k]
```这适用于`O(1)`两项操作的时间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 |`O(k)`每个查询 |`O(n)`| 最后存储流并相乘`k`每次的数字 |
 | 最佳 |`O(1)`每次操作 |`O(n)`| 使用前缀产品并在零后重置 |

 ## 算法演练

 1. 用哨兵值初始化前缀产品列表`1`。 

该哨兵简化了除法计算，并避免了从序列开头计算乘积时的边缘情况。 

例子：```
prefix = [1]
```2. 什么时候`add(num)`被调用，检查是否`num`为零。 

如果`num == 0`，重置前缀数组：```
prefix = [1]
```这实际上会忘记零之前的所有内容，因为任何跨越零的范围都必须计算为`0`。 
3.如果`num`不为零，则附加累积乘积。 

计算：```
prefix.append(prefix[-1] * num)
```例子：```
stream: [2,5,4]

prefix:
[1]
[1,2]
[1,2,10]
[1,2,10,40]
```4. 什么时候`getProduct(k)`被调用，确定范围是否跨越零。 

如果：```
k >= len(prefix)
```那么请求的范围包括零，因此返回：```
0
```5. 否则，使用前缀乘积除法来计算乘积。 

公式：```
prefix[-1] // prefix[-1-k]
```例子：```
prefix = [1,2,10,40]

getProduct(2)

= 40 // 2
= 20
```### 为什么它有效

 核心不变量是`prefix[i]`始终存储自最近的零以来所有数字的乘积。 因此，对于不跨越零的任何有效范围，前缀乘积的划分正确地隔离了所请求的后缀乘积。 

如果请求的范围跨越零，则前缀数组长度会变得太短，因为它在零之后被重置。 检测这种情况`k >= len(prefix)`保证我们正确返回`0`。 

## Python 解决方案```python
class ProductOfNumbers:

    def __init__(self):
        self.prefix_products: list[int] = [1]

    def add(self, num: int) -> None:
        if num == 0:
            self.prefix_products = [1]
        else:
            new_product = self.prefix_products[-1] * num
            self.prefix_products.append(new_product)

    def getProduct(self, k: int) -> int:
        if k >= len(self.prefix_products):
            return 0

        return (
            self.prefix_products[-1]
            // self.prefix_products[-1 - k]
        )

# Your ProductOfNumbers object will be instantiated and called as such:
# obj = ProductOfNumbers()
# obj.add(num)
# param_2 = obj.getProduct(k)
```该实现使用一个名为`prefix_products`。 该列表开头为`1`，作为哨兵值来简化除法。 

在`add`，如果来电号码为零，则列表被重置。 此重置至关重要，因为任何跨越此零的产品都必须变为零，因此以前的产品不再有用。 

对于非零值，将附加累积乘积。 由于乘法是累积的，这为我们提供了后缀乘积的紧凑表示。 

在`getProduct`，我们首先检查是否`k`超过可用的前缀历史记录。 如果是，则请求的范围必须跨越零，因此我们返回`0`。 否则，我们将最新的累积乘积除以查询范围之前的乘积。 

## 解决方案```go
type ProductOfNumbers struct {
	prefixProducts []int
}

func Constructor() ProductOfNumbers {
	return ProductOfNumbers{
		prefixProducts: []int{1},
	}
}

func (this *ProductOfNumbers) Add(num int) {
	if num == 0 {
		this.prefixProducts = []int{1}
		return
	}

	newProduct := this.prefixProducts[len(this.prefixProducts)-1] * num
	this.prefixProducts = append(this.prefixProducts, newProduct)
}

func (this *ProductOfNumbers) GetProduct(k int) int {
	if k >= len(this.prefixProducts) {
		return 0
	}

	lastIndex := len(this.prefixProducts) - 1

	return this.prefixProducts[lastIndex] /
		this.prefixProducts[lastIndex-k]
}

/**
 * Your ProductOfNumbers object will be instantiated and called as such:
 * obj := Constructor();
 * obj.Add(num);
 * param_2 := obj.GetProduct(k);
 */
```Go 实现遵循与 Python 版本完全相同的逻辑，但使用切片来存储前缀乘积。 

Go 使用的不是 Python 的动态列表操作`append()`来生长切片。 零后的重置是通过分配完成的：```go
[]int{1}
```Go 整数除法的行为完全符合此处的需要，因为所有存储的乘积都是早期前缀值的精确倍数，因此不会发生舍入问题。

 ## 边缘情况

 ### 查询范围包括零

 错误的一个主要来源是当请求的范围跨越零时。 简单的前缀除法方法会失败，因为涉及零的除法是无效的。 

例如：```
[3, 0, 2, 5]
getProduct(3)
```答案一定是`0`因为范围包括`0`。 该实现通过在插入零时重置前缀数组来正确处理此问题。 既然零之前的历史消失了，`k >= len(prefix_products)`检测到这种情况并返回`0`。 

### 连续零

 如果重置处理不当，连续多个零可能会产生微妙的错误。 

例子：```
[0, 0, 5]
```该实现只是在每次出现零时重置前缀数组：```
[1]
[1]
[1,5]
```这确保查询行为正确，无需特殊情况逻辑。 

### 查询整个有效范围

 假设流包含：```
[2, 3, 4]
```呼叫：```
getProduct(3)
```应该返回所有数字的乘积。 如果没有哨兵值，索引处理就容易出错。 通过存储初始`1`，计算变为：```
24 // 1 = 24
```它自然地工作并避免边界错误。
