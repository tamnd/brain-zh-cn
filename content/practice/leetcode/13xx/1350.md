[LeetCode 问题 1350](https://leetcode.com/problems/students-with-invalid-departments/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 此问题要求我们识别在系登记处不再存在的大学系就读的学生。 

我们有两个数据库表。 这`Departments`表存储有效的大学系，其中每个系都有唯一的`id`和一个`name`。 这`Students`表存储学生记录，每个学生都有一个唯一的`id`, 一个`name`，和一个`department_id`表明他们属于哪个部门。 

任务是找到所有符合以下条件的学生`department_id`不对应于任何现有部门`Departments`桌子。 换句话说，我们需要识别缺少参考部门记录的学生。 

这本质上是一个引用完整性问题。 通常情况下，学生的`department_id`应该指向一个有效的部门。 但是，由于院系可能已被删除或不再存在，一些学生可能会引用无效的院系 ID。 我们只需要返回那些学生。 

预期输出包含`id`和`name`拥有无效院系的所有学生。 The order of the result does not matter, meaning any ordering is accepted.

 从模式中我们知道`id`is the primary key in both tables, so department IDs are unique and student IDs are unique. 由于该问题被归类为简单数据库问题，因此输入大小可能是可控的，但我们仍然应该以高效查询为目标。 

有几个边缘情况需要考虑。 If every student's department exists, the result should be empty. 如果`Departments`表本身是空的，那么每个学生都会因为不存在院系而变得无效。 另一种情况是，当多个学生引用同一个缺失的部门时，在这种情况下，所有学生都应该出现在输出中。 该问题保证了有效的表结构和主键，因此我们不需要处理格式错误的数据或重复的部门ID。 

## 方法

 ### 蛮力方法

 解决这个问题的一个直接方法是手动检查每个学生的每个部门。 

对于每一个学生来说`Students`表，我们扫描整个`Departments`table to see whether a matching department ID exists. If no matching department is found, we include that student in the result.

 This approach is correct because it explicitly verifies whether each student's department exists. However, it is inefficient because for every student, we potentially scan every department. 如果有`S`学生和`D`部门，这会导致嵌套扫描。 

用 SQL 术语来说，这类似于通过完整扫描重复检查成员资格，而不是使用联接或索引查找机制。 

### 最佳解决方案的关键见解

 关键的观察是，这从根本上来说是两个表之间的匹配问题。 SQL 数据库旨在使用联接有效地处理这些关系。 

我们想要确定哪些学生`department_id`中**没有匹配的行**`Departments`。 一个`LEFT JOIN`非常适合这种情况。 

与一个`LEFT JOIN`，我们保留每个学生的记录并尝试将其与部门相匹配。 如果不存在匹配的部门，则加入的部门字段将变为`NULL`。 然后我们可以过滤缺少部门的行。 

另一种优雅的选择是使用`NOT IN`， 但`LEFT JOIN`往往更清晰并避免陷阱`NULL`在 SQL 中处理。

 | --- | --- | --- | --- |
 | 蛮力 | O(S × D) | O(1) | O(1) | 将每个学生与每个院系进行比较 |
 | 最佳| O(S + D) | O(1) 额外 | 使用`LEFT JOIN`有效地发现缺失的部门|

 ## 算法演练

 ### 使用 LEFT JOIN 的最优算法

 1. 从`Students`表，因为必须检查每个学生的有效性。 
2. 执行`LEFT JOIN`之间`Students`和`Departments`使用条件：`Students.department_id = Departments.id`此步骤尝试将每个学生的院系与现有院系进行匹配。 
3.因为我们使用`LEFT JOIN`，即使不存在匹配的部门，所有学生仍保留在结果中。 
4. 对于不存在院系的学生，加入的院系`Departments`列将包含`NULL`。 
5. 使用以下方法过滤结果：`Departments.id IS NULL`这个条件确保我们只保留部门查找失败的学生。 
6. 仅选择所需的列：`Students.id`和`Students.name`因为问题只需要这些字段。 

### 为什么它有效

 正确性来自于行为`LEFT JOIN`。 每个学生行都会被保留，并且仅当部门存在时才会附加匹配的部门信息。 如果未找到匹配项，SQL 将使用以下内容填充部门列`NULL`。 因此，过滤`Departments.id IS NULL`准确识别部门参考无效的学生。 

## Python 解决方案

 LeetCode 数据库问题使用 SQL 而不是可执行的 Python。 以下查询是完整的 LeetCode 可提交解决方案。```python
SELECT s.id, s.name
FROM Students s
LEFT JOIN Departments d
ON s.department_id = d.id
WHERE d.id IS NULL;
```该查询以`Students`表，因为每个学生都必须检查。 一个`LEFT JOIN`尝试匹配每个学生的`department_id`有部门记录。 如果部门存在，则该行包含有效的部门信息。 如果不存在部门，则部门列变为`NULL`。 

这`WHERE d.id IS NULL`条件筛选结果以仅包含院系不存在的学生。 最后，我们只选择学生的`id`和`name`，它与所需的输出格式匹配。

 ## 边缘情况

 ### 每个学生都有一个有效的部门

 如果全部`department_id`值存在于`Departments`， 这`LEFT JOIN`成功为每个学生找到匹配项。 结果，没有行有`NULL`部门值，并且查询正确返回空结果集。 

### 部门表为空

 如果根本没有院系，则每个学生的院系参考都将无效。 期间`LEFT JOIN`，每个部门栏变成`NULL`，因此所有学生都包含在结果中。 这个案例很容易打破部门总是存在的天真的假设。 

### 多个学生引用同一个缺失的部门

 几个学生可能共享同一个无效的`department_id`。 有缺陷的实现可能会意外地按部门而不是按学生删除重复的结果。 我们的查询在学生级别运行，这意味着每个受影响的学生都会独立出现在输出中，这符合问题要求。 

### 没有学生存在

 如果`Students`表为空，连接没有要处理的行。 查询自然会返回一个空结果集，无需特殊情况处理。 这表明该解决方案可以优雅地处理最小的输入大小。
