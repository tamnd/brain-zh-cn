 # LeetCode 1343 - 大小为 K 且平均值大于或等于阈值的子数组的数量

 ## 问题理解

 这个问题要求我们计算有多少个连续的长度子数组`k`平均值大于或等于给定值`threshold`。 

输入包括：

 - 整数数组`arr`- 一个整数`k`，表示每个子数组的固定大小
 - 一个整数`threshold`子数组是数组的连续部分。 对于每个可能的长度精确的子数组`k`，我们计算其平均值并检查该平均值是否至少为`threshold`。 

最终的答案只是合格子数组的数量。 

例如，假设：```
arr = [2,2,2,2,5,5,5,8]
k = 3
threshold = 4
```大小为 3 的可能子数组为：```
[2,2,2]
[2,2,2]
[2,2,5]
[2,5,5]
[5,5,5]
[5,5,8]
```其中，后三项的平均值大于或等于 4，因此答案为 3。 

约束条件很重要：

 -`arr.length`可以大到`100000`- 每个值最多可达`10000`这些限制立即表明低效的解决方案可能会超时。 特别是，对于大输入来说，从头开始重新计算每个子数组的总和会太慢。 

还有一些值得考虑的边缘情况：

 - 当`k = 1`，每个单独的元素形成一个有效的子数组。 
- 什么时候`k = arr.length`，只有一个可能的子数组。 
- 当没有子数组满足条件时，答案应为 0。 
- 当每个子数组都满足条件时，答案应等于窗口总数。 
- 平均值不保证是整数，因此错误地使用整数除法可能会引入错误。 

一个重要的观察是我们实际上不需要直接计算平均值。 自从：```
average = sum / k
```条件：```
average >= threshold
```相当于：```
sum >= threshold * k
```这种转换完全避免了浮点运算。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每个可能的大小子数组`k`。 

对于每个起始索引：

 1. 计算下一个的总和`k`元素。 
2.除以`k`计算平均值。 
3. 比较平均值`threshold`。 
4. 如果满足条件，则增加答案。 

这种方法是正确的，因为它显式检查每个有效的子数组。 

然而，它的效率很低。 如果有`n`元素，那么大约有`n - k + 1`子数组。 计算每个子数组的总和需要`O(k)`工作。 

这导致总的复杂性：```
O((n - k + 1) * k)
```在最坏的情况下，这会变成`O(n * k)`，可以逼近`10^10`大投入的操作。 

### 最优滑动窗口方法

 关键的观察结果是连续的子数组严重重叠。 

考虑这些窗口：```
[2,2,2]
[2,2,5]
```第二个窗口与第一个窗口的不同之处在于：

 - 删除最左边的元素
 - 添加一个新的最右边元素

 我们可以维护一个运行窗口总和，而不是每次都重新计算整个总和。 

这正是滑动窗口技术的设计目的。 

该算法的工作原理是：

 1. 计算第一个窗口的总和。 
2. 检查是否满足条件。 
3. 将窗口一次滑动一个位置：

 - 减去输出元素
 - 添加传入元素
 4. 重复此过程，直到处理完所有窗口。 

这将复杂性降低到线性时间。

 ## 算法演练

 ### 最优滑动窗口算法

 1. 计算所需的最小窗口总和。 

而不是检查：```
average >= threshold
```我们检查：```
sum >= threshold * k
```这避免了浮点运算，并使比较更简单、更快。 
2. 计算第一个的总和`k`元素。 

这会初始化第一个滑动窗口。 
3. 检查第一个窗口是否满足条件。 

如果当前窗口总和至少是所需的总和，则增加答案。 
4. 将窗口滑过阵列。 

对于每个新职位：

 - 删除离开窗口的元素
 - 添加进入窗口的新元素

 这会在恒定时间内更新窗口总和。 
5. 更新窗口总和后，再次检查条件。 

如果更新后的窗口满足阈值要求，则增加答案。 
6. 继续，直到窗口到达数组末尾。 
7. 返回总计数。 

### 为什么它有效

 滑动窗口始终准确地表示一个大小连续的子数组`k`。 

当窗口向右移动一步时：

 - 一个元素离开
 - 加入一个新元素

 更新运行总和始终保留当前窗口的准确总和。 由于每个可能的窗口大小`k`仅处理一次，并且每个合格窗口都会增加计数，最终答案是正确的。 

## Python 解决方案```python
from typing import List

class Solution:
    def numOfSubarrays(self, arr: List[int], k: int, threshold: int) -> int:
        required_sum = k * threshold
        
        window_sum = sum(arr[:k])
        count = 0
        
        if window_sum >= required_sum:
            count += 1
        
        for right in range(k, len(arr)):
            window_sum += arr[right]
            window_sum -= arr[right - k]
            
            if window_sum >= required_sum:
                count += 1
        
        return count
```实现首先使用以下方法将平均值比较转换为总和比较：```python
required_sum = k * threshold
```这完全避免了浮点运算。 

接下来，代码使用以下方法计算第一个窗口的总和：```python
window_sum = sum(arr[:k])
```这建立了初始滑动窗口。 

然后算法检查第一个窗口是否满足条件。 

主循环从索引处开始`k`，它代表进入窗口的第一个新元素。 对于每次迭代：```python
window_sum += arr[right]
window_sum -= arr[right - k]
```第一条语句添加新的传入元素。 第二个从前一个窗口中删除传出元素。 

这使得窗口大小精确地固定在`k`。 

更新总和后，算法检查当前窗口是否合格并相应地增加答案。 

最后返回总计数。 

## 解决方案```go
func numOfSubarrays(arr []int, k int, threshold int) int {
    requiredSum := k * threshold

    windowSum := 0

    for i := 0; i < k; i++ {
        windowSum += arr[i]
    }

    count := 0

    if windowSum >= requiredSum {
        count++
    }

    for right := k; right < len(arr); right++ {
        windowSum += arr[right]
        windowSum -= arr[right-k]

        if windowSum >= requiredSum {
            count++
        }
    }

    return count
}
```Go 实现遵循与 Python 版本完全相同的滑动窗口逻辑。 

一个小小的区别是 Go 没有提供内置的`sum()`函数用于切片，因此初始窗口总和是使用循环手动计算的。 

整数溢出在这里不是一个问题，因为：```go
maximum possible window sum = 100000 * 10000 = 10^9
```它安全地适合 32 位有符号整数。 去的`int`类型就足够了。 

该实现使用恒定的额外内存并一次性处理数组。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`k = 1`。 在这种情况下，每个单独的元素都会形成自己的子数组。 有缺陷的实现可能会错误地假设窗口始终包含多个元素。 滑动窗口解决方案自然地处理了这个问题，因为窗口大小在整个执行过程中始终保持为一。 

另一个重要的情况发生在`k = arr.length`。 这里，只存在一个子数组，即整个数组本身。 某些实现意外地尝试超出有效范围或错误处理初始化。 此实现正确计算第一个窗口，并且简单地跳过滑动循环，因为没有附加窗口。 

一个微妙的边缘情况涉及非整数的平均值。 例如：```
sum = 10
k = 3
average = 3.333...
```使用整数除法可能会产生不正确的结果。 此实现通过将条件转换为以下方式完全避免了除法：```
sum >= threshold * k
```这保证了数学上正确的比较，而不会出现浮点精度问题。 

另一种极端情况是没有窗户符合条件。 在这种情况下，计数变量在整个执行过程中应保持为零。 由于实现仅在满足条件时增加计数，因此它自然可以正确处理这种情况。 

最后，非常大的输入可能会暴露低效解决方案中的性能问题。 由于该算法仅处理每个元素一次并使用恒定的额外内存，因此即使在最大约束大小为`100000`元素。
