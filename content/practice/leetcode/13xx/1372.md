[LeetCode 问题 1372](https://leetcode.com/problems/longest-zigzag-path-in-a-binary-tree/)

 **难度：** 🟡 中等
 **主题：** 动态规划、树、深度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 在这个问题中，我们给出了二叉树的根节点，我们需要找到树内任何位置存在的最长 ZigZag 路径的长度。 

ZigZag 路径在每一步都会交替方向。 如果我们从一个节点向左移动，那么下一步必须向右移动。 如果我们向右移动，那么下一步必须向左移动。 路径可以从树中的任何节点开始，并且初始方向也可以自由选择。 

ZigZag 路径的长度定义为经过的边数，相当于访问的节点数减一。 因此，单个节点本身的 ZigZag 长度为`0`。 

输入是标准二叉树。 每个节点可能有一个左子节点、一个右子节点、两者都有或都没有。 输出是一个整数，表示可以在树中任何位置形成的最大 ZigZag 长度。 

约束条件很重要：

 - 该树最多可以包含`5 * 10^4`节点。 
- 这意味着我们无法承受重复遍历树的大部分的算法。 
- 一个`O(n^2)`在高度不平衡的树上，解决方案可能会超时。 
- 因此，我们需要一种能够高效处理每个节点的解决方案，最好一次处理。 

一些边缘情况尤其重要：

 - 应返回仅包含一个节点的树`0`。 
- 一棵完全倾斜的树，其中每个节点在同一方向上只有一个子节点，产生的最大 ZigZag 长度为`1`。 
- 左右交替链应正确累积长之字折线路径。 
- 最佳路径不一定从根开始，因此算法必须将每个节点视为潜在的起点。 

## 方法

 ### 蛮力方法

 蛮力的想法是将每个节点视为潜在的起点。 对于每个节点，我们尝试两次遍历：

 - 从向左移动开始
 - 从向右移动开始

 从那里开始，我们通过交替方向递归地继续 ZigZag 模式，直到路径不再继续。 

这种方法是正确的，因为它明确地探索树中的每个有效之字折线路径。 由于考虑了每一个可能的起始节点和每一个初始方向，最终将找到最长的路径。 

然而，性能较差。 假设树是高度不平衡的，类似于链表。 从每个节点，我们可以遍历几乎整个剩余的树。 由于有`n`起始节点，这导致大约`O(n^2)`在最坏的情况下工作。 

高达`50,000`节点，这太慢了。 

### 最佳深度优先搜索方法

 关键的观察结果是，节点处的 ZigZag 状态可以完全描述为：

 - 当前节点
 - 用于到达该节点的方向
 - 当前之字折线长度

 这意味着我们可以执行一次 DFS 遍历，同时将当前状态向前推进。 

在每个节点：

 - 如果我们向左移动，那么下一步一定是向右移动
 - 如果我们向右移动，那么下一步必须向左移动

 我们递归地继续有效的 ZigZag 扩展，同时在必要时从子级重新启动新路径。 

由于每个节点仅处理一次且工作量恒定，因此整个算法变得线性。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(h) | 从每个节点开始新的遍历 |
 | 最优 DFS | O(n) | O(h) | 携带 ZigZag 状态的单次 DFS 遍历 |

 这里，`h`代表树的高度。 

## 算法演练

 1. 创建一个名为`max_length`存储迄今为止发现的最长之字折线路径。 
2. 定义具有三个参数的 DFS 辅助函数：

 - 当前节点
 - 当前之字折线长度
 - 先前移动的方向
 3. 如果当前节点是`None`，立即停止递归，因为不存在进一步的路径。 
4. 更新`max_length`使用当前之字折线长度。 这确保了每条有效路径都有助于最终答案。 
5. 如果之前的移动是向左移动，则：

 - 继续之字折线需要向右移动
 - 向右移动将当前长度增加`1`- 向左移动将重新启动锯齿形调整浪长度`1`6. 同样，如果前一步是向右移动：

 - 继续需要向左移动
 - 向左移动将当前长度增加`1`- 向右移动会重新开始路径`1`7. 从根开始两次初始 DFS 遍历：

 - 假设第一步向左移动
 - 假设第一步走对了
 8、DFS完成后，返回`max_length`。 

### 为什么它有效

 该算法之所以有效，是因为在 DFS 遍历期间表示了每个有效的 ZigZag 路径。 在每个节点，递归正确地维持交替模式是继续还是重置。 由于在两个方向上下文中每条边都被探索一次，因此保证能发现最大之字折线长度。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional

class Solution:
    def longestZigZag(self, root: Optional[TreeNode]) -> int:
        max_length = 0

        def dfs(node: Optional[TreeNode], direction: str, length: int) -> None:
            nonlocal max_length

            if not node:
                return

            max_length = max(max_length, length)

            if direction == "left":
                dfs(node.right, "right", length + 1)
                dfs(node.left, "left", 1)
            else:
                dfs(node.left, "left", length + 1)
                dfs(node.right, "right", 1)

        dfs(root.left, "left", 1)
        dfs(root.right, "right", 1)

        return max_length
```该实现使用递归 DFS 辅助函数来维护当前之字折线状态。 

这`direction`参数表示到达当前节点的方向。 这决定了哪个子节点继续 ZigZag 模式。 

当满足交替规则时，当前长度加一。 当重复相同方向时，路径实际上从子节点重新开始，因此长度重置为`1`。 

全局变量`max_length`在每次 DFS 调用期间都会更新。 这确保算法跟踪树中任何位置遇到的最佳路径。 

遍历从两者开始`root.left`和`root.right`因为 ZigZag 路径必须从一条边开始，而不是从一个独立的根节点开始。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func longestZigZag(root *TreeNode) int {
    maxLength := 0

    var dfs func(node *TreeNode, direction string, length int)

    dfs = func(node *TreeNode, direction string, length int) {
        if node == nil {
            return
        }

        if length > maxLength {
            maxLength = length
        }

        if direction == "left" {
            dfs(node.Right, "right", length+1)
            dfs(node.Left, "left", 1)
        } else {
            dfs(node.Left, "left", length+1)
            dfs(node.Right, "right", 1)
        }
    }

    if root.Left != nil {
        dfs(root.Left, "left", 1)
    }

    if root.Right != nil {
        dfs(root.Right, "right", 1)
    }

    return maxLength
}
```Go 实现遵循与 Python 版本相同的逻辑，但对其进行了调整以适应 Go 语法和语义。 

Go 使用`nil`而不是`None`，并且递归是使用内部函数变量声明来实现的。 由于 Go 不直接支持嵌套命名函数，因此 DFS 助手在赋值之前被声明为变量。 

该算法安全地使用整数，因为最大可能的 ZigZag 长度受到节点数量的限制，这远远低于 Go 的整数限制。

 | ---| ---| ---|
 | 时间 | O(n) | 每个节点都会被访问固定次数 |

 DFS 遍历针对每个方向上下文对每个节点处理一次，但这仍然导致线性总工作。 递归深度取决于树的高度。 在倾斜树的最坏情况下，高度变为`O(n)`。

 ## 边缘情况

 单节点树是最小的有效输入。 由于没有边，锯齿形调整浪长度必须为`0`。 错误地计算节点而不是边缘的实现可能会错误地返回`1`。 此解决方案避免了该问题，因为 DFS 仅在遍历边缘后才开始。 

完全倾斜的树是另一个重要的边缘情况。 例如，如果每个节点只有一个左子节点，那么在一次移动后就不可能改变方向。 幼稚的实现可能会继续错误地计算连续的左移动。 该算法通过在同一方向重复时重置路径长度来正确处理这种情况。 

当最长之字折线路径不是从根开始时，会出现另一种棘手的情况。 一些不正确的解决方案仅探索从根节点开始的路径，这会错过树中更深处的最佳路径。 此实现自然会处理所有可能的起始位置，因为每个递归调用都可以从其子节点重新启动 ZigZag 计数。 

一棵高度不平衡的树，最多可达`50,000`节点也很重要。 递归解决方案存在深度递归堆栈的风险。 该算法仍然满足所需的渐近复杂度，仅处理每个节点一次，同时保持线性运行时间。
