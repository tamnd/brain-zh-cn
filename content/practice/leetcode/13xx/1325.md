[LeetCode 问题 1325](https://leetcode.com/problems/delete-leaves-with-a-given-value/)

 **难度：** 🟡 中等
 **主题：** 树、深度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 这个问题要求我们重复地从二叉树中删除叶子节点，如果它们的值与给定的匹配`target`。 

**叶节点**是没有子节点的节点，这意味着它的子节点`left`和`right`指针是`null`（或者`None`在Python中）。 乍一看，任务可能看起来很简单：遍历树并删除每个值等于的叶子`target`。 然而，有一个重要的并发症。 

删除一个叶节点可以创建**新的叶节点**。 如果父节点因删除而丢失所有子节点，则该父节点本身可能会成为叶子。 如果该父母的价值也等于`target`，也必须删除。 此过程递归地继续，直到不再有合格的叶节点剩余。 

输入包括：

 -`root`，二叉树的根
 -`target`, 一个整数值

 预期输出是执行所有可能的删除后修改后的二叉树的根。 

例如，假设我们删除一个目标值叶子。 它的父母可能会突然失去孩子。 如果该父级也具有目标值，则现在也必须将其删除。 这种级联效应意味着我们不能简单地在单个自上而下的传递中删除节点。 

这些约束告诉我们有关该问题的几个重要信息：

 - 树包含之间`1`和`3000`节点。 
- 节点值和`target`之间`1`和`1000`。 

一棵树的大小为`3000`是适中的。 尽管递归深度仍应从概念上考虑，但该值足够小，使得递归深度优先遍历在大多数语言中都是可行的。 由于我们可能需要在修改子节点后重新访问父节点，因此后序遍历自然适合这个问题。 

一些边缘情况很重要：

 - 根本身最终可能会被删除，这意味着答案变成`None`或者`nil`。 
- 目标值节点链可能会反复向上崩溃。 
- 具有目标值的节点不应该被删除，除非它是叶子。 
- 只有在删除其子节点后，节点才可以变为可移动。 

这些情况使得天真的自上而下删除很容易出错。 

## 方法

 ### 蛮力方法

 一种简单的方法是重复扫描整棵树，寻找可移动的叶子。 

在每一遍中，我们遍历树并删除任何值等于的叶节点`target`。 完整遍历后，我们检查是否发生删除。 如果发生删除，我们会重复整个过程，因为可能已经形成新的可移动叶子。 

这种方法是正确的，因为最终每个新创建的目标值叶子都会在以后的遍历中被发现。 由于树的节点数量有限，因此该过程必须终止。 

然而，这种方法效率低下。 在最坏的情况下，我们每次遍历可能只删除一个节点。 如果树有`n`节点，我们最终可以遍历树`n`次，导致二次复杂度。 

例如，考虑一棵倾斜树，其中每个节点都等于`target`。 我们首先删除底部的叶子，然后它的父节点变得可移动，然后是下一个父节点，依此类推。 这创造了`O(n)`遍历，每次成本`O(n)`。 

### 最优方法，后序 DFS

 关键的见解是，是否应删除节点完全取决于其子节点的最终状态。 

如果两个子节点都已被处理并删除，则当前节点可能会成为叶子。 因此，我们应该在处理父级之前**处理子级。 

这自然意味着**后序深度优先遍历**：

 1. 递归处理左子树。 
2. 递归处理右子树。 
3. 决定是否保留当前节点。 

递归更新两个子项后，我们检查：

 - 当前节点是叶子节点吗？ 
- 它的值是否相等`target`？ 

如果两个条件都为真，我们通过返回来删除该节点`None`（`nil`在围棋中）。 否则，我们返回节点本身。 

这种方法只访问每个节点一次，从而提高效率。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(h) | 反复遍历树，直到没有删除发生 |
 | 最佳 | O(n) | O(h) | 单后序DFS遍历|

 这里：

-`n`是节点数。 
-`h`是树的高度。 

## 算法演练

 ### 最优后序 DFS 算法

 1. 从根开始递归DFS遍历。 

在决定当前节点是否应该保留之前，我们需要有关子节点更新状态的信息。 这就是为什么递归是理想的。 
2. 递归处理左孩子。 

调用递归函数`node.left`。 结果表示所有有效删除后更新的左子树。 
3. 递归处理右孩子。 

做同样的事情`node.right`。 同样，这可确保首先完成所有子项删除。 
4. 更新当前节点的子指针。 

将递归结果赋回：

 -`node.left = processed_left`-`node.right = processed_right`这确保删除的节点成为`None`。 
5. 检查是否删除当前节点。 

仅当满足以下条件时，节点才可移除：

 -`node.val == target`-`node.left is None`-`node.right is None`第二个和第三个条件保证该节点当前是叶子。 
6. 删除可移动节点。 

如果该节点符合删除条件，则返回`None`。 

返回`None`有效地从其父节点中删除该节点。 
7. 保留有效节点。 

如果该节点应该保留，则返回该节点本身。 
8. 返回处理后的根。 

DFS 完成后，返回的根可能未更改、部分修改或完全删除。 

### 为什么它有效

 正确性依赖于后序不变量：

 **在决定是否删除一个节点之前，它的两棵子树都已经被完全处理了。**

 因为子节点首先被最终确定，所以我们知道当前节点在删除后是否已成为叶子。 这保证了每个可移动节点都被恰好检测到一次，包括仅在其子节点消失后才变得可移动的节点。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional

class Solution:
    def removeLeafNodes(
        self,
        root: Optional[TreeNode],
        target: int
    ) -> Optional[TreeNode]:

        def dfs(node: Optional[TreeNode]) -> Optional[TreeNode]:
            if not node:
                return None

            node.left = dfs(node.left)
            node.right = dfs(node.right)

            if (
                node.val == target
                and node.left is None
                and node.right is None
            ):
                return None

            return node

        return dfs(root)
```该实现完全遵循后序 DFS 策略。 

嵌套的`dfs`函数一次处理一个节点。 底壳手柄`None`立即返回节点`None`。 

递归调用首先处理左子树和右子树。 它们的返回值被重新分配给`node.left`和`node.right`，确保正确删除任何已删除的子节点。 

处理完两个子节点后，节点检查它是否已成为目标值叶节点。 如果是这样，返回`None`从树中删除节点。 

最后，`dfs(root)`返回更新的树根，它本身可能会被删除。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func removeLeafNodes(root *TreeNode, target int) *TreeNode {
    var dfs func(node *TreeNode) *TreeNode

    dfs = func(node *TreeNode) *TreeNode {
        if node == nil {
            return nil
        }

        node.Left = dfs(node.Left)
        node.Right = dfs(node.Right)

        if node.Val == target &&
            node.Left == nil &&
            node.Right == nil {
            return nil
        }

        return node
    }

    return dfs(root)
}
```Go 的实现与 Python 版本非常相似。 

主要的语言特定差异是使用`nil`而不是`None`。 由于 Go 使用指针作为树节点，因此删除节点仅意味着返回`nil`。 

Go 还要求在分配匿名函数之前显式声明递归函数变量，这就是原因：```go
var dfs func(node *TreeNode) *TreeNode
```出现在函数定义之前。 

这里不存在整数溢出问题，因为节点值非常小。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个节点都被访问一次 |

 该算法执行单次 DFS 遍历。 每个节点都被处理一次，并且递归内的每个操作都需要恒定的时间。 

空间复杂度完全来自递归深度。 在平衡树中，高度约为`O(log n)`。 在最坏情况的倾斜树中，高度变为`O(n)`。

 ## 边缘情况

 ### 根节点被删除

 当根本身变得可移动时，就会发生一种微妙的情况。 例如：```
root = [1]
target = 1
```根已经是叶子并且与目标匹配，因此整棵树消失了。 有缺陷的实现可能会忘记返回`None`作为最终答案。 这个实现很自然地处理它，因为递归函数返回`None`， 和`dfs(root)`成为最终结果。 

### 向上级联删除

 目标值节点链可以触发重复删除。 

例子：```
1
|
2
|
2
|
2
```首先删除底部节点。 这导致它的父母变成一片叶子，然后被移除，继续向上。 自上而下的遍历经常会错过这一点，因为它过早地检查父母。 后序遍历保证了正确性，因为只有在子项最终确定后才会评估父项。 

### 目标值内部节点应保留

 一个节点等于`target`如果仍有子项，则不应将其删除。 

例子：```
    2
   /
  3
```根值等于目标，但不是叶子。 粗心的实施可能会立即将其删除。 该解决方案在删除之前显式检查两个子指针，确保仅删除叶子。 

### 没有匹配目标叶子的树

 如果没有叶子与目标匹配，则树应保持不变。 

例子：```
    5
   / \
  3   8
```和`target = 2`。 

该算法仍然遍历每个节点，但不会发生删除。 由于每个节点返回自身不变，因此原始结构被准确地保留。
