[LeetCode 问题 1359](https://leetcode.com/problems/count-all-valid-pickup-and-delivery-options/)

 **难度：** 🔴难
 **主题：** 数学、动态规划、组合学

 ## 解决方案

 ## 问题理解

 这个问题要求我们计算执行取货和送货的有效序列的数量`n`订单。 每个订单均包含一次取货`Pi`和送货`Di`，关键限制是任何订单的交货必须在其相应的提货**之后**发生。 输入是单个整数`n`表示订单数，输出为有效序列总数模`10^9 + 7`以防止整数溢出。 

例如，如果`n = 1`，唯一有效的序列是`(P1, D1)`。 如果`n = 2`，有 6 个有效序列，如问题陈述中所列举的那样。 限制因素`1 <= n <= 500`表明序列的数量增长得非常快，并且暴力排列方法是不可行的，因为可能的序列的数量是`(2n)!`。 

重要的边缘情况包括最小输入`n = 1`答案是微不足道的，并且输入很大，例如`n = 500`，其中不进行模运算而直接计算阶乘会溢出标准整数类型。 该问题保证了`n`是正数并且有合理的界限，因此我们不需要处理零阶或负阶。 

## 方法

 蛮力方法将生成所有排列`2n`元素`(P1, D1, ..., Pn, Dn)`并过滤掉违反提货后交货约束的序列。 虽然这是正确的，但复杂性是`O((2n)!)`，这对于`n`小到10个就更不用说了`n = 500`。 

最佳方法利用组合学和动态规划。 关键的见解是递归的：如果我们已经知道有效序列的数量`n-1`订单，我们可以计算有效序列的数量`n`通过考虑可以插入新的取货和交货的位置来订购。 为了`n`订单，有`2n-1`在取货后插入新订单的交货位置，给出重现：```
f(n) = f(n-1) * n * (2n-1)
```这里，`f(n-1)`是序列数`n-1`订单，`n`占新皮卡数量，以及`(2n-1)`占相应交割的有效持仓数量。 递归可以迭代地实现，以避免深度递归。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O((2n)!) | O((2n)!) | O(2n) | O(2n) | 生成所有排列并过滤无效序列 |
 | 最佳 | O(n) | O(1) | O(1) | 使用递推关系的迭代组合公式|

 ## 算法演练

 1. 初始化变量`result`到 1。这将存储有效序列的总数模`10^9 + 7`。 
2. 设置模常数`MOD = 10**9 + 7`。 
3. 迭代`i`从 2 到`n`（包括）。 对于每个`i`， 更新`result`使用公式：```
result = result * i * (2*i - 1) % MOD
```此公式将先前的序列数乘以插入新拾音器的位置数 (`i`）以及相应交割的仓位数量（`2*i - 1`），同时在每一步取模以防止溢出。 
4. 返回`result`。 

**为什么有效：** 该公式确保对于每个新订单，取货都可以放置在`i`位置并且交货可以在提货后放置在任何有效位置。 通过建立从`n = 1`，递归计算所有有效序列，而无需显式生成它们。 

## Python 解决方案```python
class Solution:
    def countOrders(self, n: int) -> int:
        MOD = 10**9 + 7
        result = 1
        for i in range(2, n + 1):
            result = result * i * (2 * i - 1) % MOD
        return result
```在此 Python 实现中，`result`初始化为 1，表示平凡序列`n = 1`。 该循环迭代地将结果乘以拾取器的新位置数`i`和交货`(2*i - 1)`同时保持结果模数`10^9 + 7`以防止整数溢出。 循环完成后返回最终结果。 

## 解决方案```go
func countOrders(n int) int {
    const MOD int = 1e9 + 7
    result := 1
    for i := 2; i <= n; i++ {
        result = result * i % MOD
        result = result * (2*i - 1) % MOD
    }
    return result
}
```在 Go 中，我们明确使用`const MOD int = 1e9 + 7`。 迭代计算反映了 Python 版本，在每次乘法时应用模数以防止整数溢出。 Go 需要仔细注意整数类型，但是由于`result`总是一个`int`，它无需额外的类型转换即可处理计算。 

## 工作示例

 **示例 1：n = 1**

 初始`result = 1`。 没有循环迭代，因为`range(2, 2)`是空的。 返回`1`。 

**示例 2：n = 2**

 初始`result = 1`。 

迭代 i = 2：`result = 1 * 2 * (2*2 - 1) % MOD = 1 * 2 * 3 = 6`。 返回`6`。 

**示例 3：n = 3**

 初始`result = 1`。 

迭代 i = 2：`result = 1 * 2 * 3 = 6`迭代 i = 3：`result = 6 * 3 * 5 = 90`返回`90`。

 ## 边缘情况

 一种边缘情况是`n = 1`，最小可能的输入。 函数正确返回`1`因为循环不执行，并且初始值处理这种情况。 

另一个边缘情况是`n`在其上限，`500`。 在这里，类似阶乘的中间值可以超出正常的整数限制，但模算术可确保值保持在安全范围内而不会溢出。 

第三种潜在的边缘情况是`n`足够大，以至于在没有自动大整数的语言中，乘法可能会暂时超过 64 位整数限制。 Python 和 Go 解决方案都在每次乘法后应用模来防止此问题，从而确保正确性和效率。
