[LeetCode 第 1397 题](https://leetcode.com/problems/find-all-good-strings/)

 **难度：** 🔴难
 **主题：** 字符串、动态规划、字符串匹配

 ## 解决方案

 ## 问题理解

 该问题要求我们计算有多少个字符串的长度`n`同时满足三个条件：

 1. 字符串按字典顺序必须大于或等于`s1`2. 字符串按字典顺序必须小于或等于`s2`3. 字符串中不能包含`evil`作为任意位置的子字符串

 结果可能会变得非常大，因此我们将其取模返回`10^9 + 7`。 

词典比较的工作方式与词典排序的工作方式相同。 例如：

-`"abc" < "abd"`-`"baa" > "azz"`输入包括：

 -`n`，每个生成字符串所需的长度
 -`s1`，字典序下界
 -`s2`，字典序上界
 -`evil`, 禁止子串

 我们必须计算之间的每个有效字符串`s1`和`s2`包含但不包含`evil`。 

约束是选择正确算法的最重要线索：

 -`n`可以大到`500`-`evil.length`可以达到`50`暴力枚举所有可能的字符串是不可能的，因为有`26^500`最坏情况下可能出现的字符串。 甚至生成之间的所有字符串`s1`和`s2`是一个天文数字。 

该问题结合了几个先进的思想：

 - 数字DP样式边界约束
 - 字符串匹配
 - 具有记忆功能的动态编程
 - KMP前缀功能，用于高效的子串跟踪

 一些边缘情况很重要：

 -`evil`可能会立即出现在开头
 -`evil`可能与自身重叠，需要仔细的前缀处理
 -`s1`和`s2`可能非常接近
 - 范围内的每个可能的字符串都可能无效
 -`evil`可能有长度`1`，使得过滤特别具有限制性

 该问题保证：

 -`s1 <= s2`- 所有字符串仅包含小写英文字母
 - 两个边界已经有长度`n`这使我们能够完全专注于约束字符串的生成。 

## 方法

 ### 蛮力方法

 暴力解决方案将生成之间的每个字符串`s1`和`s2`，然后检查每个字符串是否包含`evil`。 

为了检查包含性，我们可以使用普通的子字符串搜索。 由于每个生成的字符串都有长度`n`，检查一串成本`O(n)`。 

然而，候选字符串的数量是巨大的。 在最坏的情况下有`26^n`的可能性。 

为了`n = 500`，暴力破解是完全行不通的。 

即使我们使用 KMP 优化了子字符串检查，生成本身仍然是不可能的。 

### 关键见解

 关键的观察是我们永远不需要显式地构造所有字符串。 

相反，我们可以使用动态编程逐个字符地构建字符串。 

在每个位置，未来的可能性仅取决于：

 - 当前指数
 - 我们是否仍受制于下限
 - 我们是否仍然受制于上限
 - 多少`evil`已经匹配成功

 最后一个组成部分至关重要。 

认为`evil = "abab"`。 

如果我们生成的字符串的当前后缀是`"aba"`，然后添加`'b'`将完成禁止的子字符串。 因此，我们需要有效跟踪部分匹配。 

这正是 KMP 前缀功能所提供的。 

我们结合：

 - 用于词典编排限制的数字 DP
 - 用于禁止子串跟踪的 KMP 自动机

 这创建了一个对于约束来说足够有效的紧凑状态空间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(26^n × n) | O(26^n × n) | O(n) | 生成所有候选字符串并检查每个字符串`evil`|
 | 最佳 | O(n × m × 26 × 4) | O(n × m × 4) | 具有 KMP 自动机和字典范围的 DP |

 这里：

-`n = len(s1)`-`m = len(evil)`## 算法演练

 ### 第 1 步：构建 KMP 前缀表

 我们首先计算 KMP 最长前缀后缀数组`evil`。 

对于每个职位`i`,`lps[i]`存储最长的适当前缀的长度`evil[:i+1]`这也是一个后缀。 

这使我们能够在添加新字符时在部分匹配之间有效地转换。 

例如，如果：```
evil = "abab"
```然后：```
lps = [0, 0, 1, 2]
```该表可以防止我们每次发生不匹配时都从头开始匹配。 

### 步骤 2：定义 DP 状态

 我们定义一个记忆化的 DFS：```
dfs(position, matched, tightLow, tightHigh)
```在哪里：

-`position`是字符串中的当前索引
 -`matched`是有多少个字符`evil`当前匹配
 -`tightLow`指示我们是否仍然匹配前缀`s1`-`tightHigh`指示我们是否仍然匹配前缀`s2`这个状态完全决定了以后所有的选择。 

### 步骤 3：处理禁止状态

 如果：```
matched == len(evil)
```那么我们已经形成了`evil`。 

该路径无效，贡献`0`。 

### 步骤 4：处理完整的字符串

 如果：```
position == n
```然后我们成功构建了一个没有匹配的有效字符串`evil`。 

返回`1`。 

### 步骤 5：确定允许的字符范围

 在每个位置，有效字符范围取决于边界约束。 

如果`tightLow`为 true 时，允许的最小字符为：```
s1[position]
```否则就是`'a'`。 

同样：

 - 如果`tightHigh`为真，最大值为`s2[position]`- 否则最大值是`'z'`### 第 6 步：尝试每一个可能的角色

 对于每个候选字符：

 1.更新KMP匹配状态
 2. 更新下限紧度
 3.更新上限紧度
 4. 递归

 KMP 转换的工作原理如下：

 - 当存在不匹配时，使用`lps`- 如果当前字符匹配，则增加匹配长度

 这有效地维护了子串匹配信息。 

### 第 7 步：记住结果

 许多州重复。 

记忆化确保每个状态被计算一次。 

如果没有记忆，递归仍然会呈指数级爆炸。 

### 为什么它有效

 该算法之所以有效，是因为 DP 状态捕获了确定未来有效字符串所需的每条信息。 

KMP 状态保证我们始终知道添加未来的角色是否可以完成`evil`。 严格的边界标志保证每个生成的字符串都保留在`[s1, s2]`。 

由于每个递归调用都会一次性探索所有有效的下一个字符，并且立即丢弃无效状态，因此该算法会精确计算所有好的字符串。 

## Python 解决方案```python
from functools import lru_cache
from typing import List

class Solution:
    def findGoodStrings(self, n: int, s1: str, s2: str, evil: str) -> int:
        MOD = 10**9 + 7
        m = len(evil)

        # Build KMP LPS array
        lps = [0] * m
        length = 0

        for i in range(1, m):
            while length > 0 and evil[i] != evil[length]:
                length = lps[length - 1]

            if evil[i] == evil[length]:
                length += 1
                lps[i] = length

        @lru_cache(None)
        def dfs(pos: int, matched: int, tight_low: bool, tight_high: bool) -> int:
            # Found forbidden substring
            if matched == m:
                return 0

            # Successfully built valid string
            if pos == n:
                return 1

            low_char = s1[pos] if tight_low else 'a'
            high_char = s2[pos] if tight_high else 'z'

            total = 0

            for code in range(ord(low_char), ord(high_char) + 1):
                ch = chr(code)

                # KMP transition
                next_match = matched

                while next_match > 0 and evil[next_match] != ch:
                    next_match = lps[next_match - 1]

                if evil[next_match] == ch:
                    next_match += 1

                next_tight_low = tight_low and (ch == low_char)
                next_tight_high = tight_high and (ch == high_char)

                total += dfs(
                    pos + 1,
                    next_match,
                    next_tight_low,
                    next_tight_high
                )

                total %= MOD

            return total

        return dfs(0, 0, True, True)
```实现首先构建 KMP 前缀表`evil`。 这可以在 DP 转换期间实现高效的子串跟踪。 

递归函数`dfs`代表主要的动态规划逻辑。 

参数捕获：

 - 当前指数
 - 当前部分匹配长度
 - 下限状态
 - 上限状态

 在每个位置，代码根据边界约束计算允许的字符范围。 

对于每个候选字符，KMP 自动机都会更新匹配的前缀长度。 如果完全匹配`evil`到达时，该递归路径立即变得无效。 

记忆通过`lru_cache`确保重复状态仅计算一次。 

每次加法后都会应用模运算以防止溢出。 

## 解决方案```go
package main

func findGoodStrings(n int, s1 string, s2 string, evil string) int {
	const MOD int = 1_000_000_007

	m := len(evil)

	// Build KMP LPS array
	lps := make([]int, m)

	length := 0
	for i := 1; i < m; i++ {
		for length > 0 && evil[i] != evil[length] {
			length = lps[length-1]
		}

		if evil[i] == evil[length] {
			length++
			lps[i] = length
		}
	}

	type State struct {
		pos        int
		matched    int
		tightLow   bool
		tightHigh  bool
	}

	memo := make(map[State]int)

	var dfs func(int, int, bool, bool) int

	dfs = func(pos int, matched int, tightLow bool, tightHigh bool) int {
		if matched == m {
			return 0
		}

		if pos == n {
			return 1
		}

		state := State{pos, matched, tightLow, tightHigh}

		if val, ok := memo[state]; ok {
			return val
		}

		lowChar := byte('a')
		highChar := byte('z')

		if tightLow {
			lowChar = s1[pos]
		}

		if tightHigh {
			highChar = s2[pos]
		}

		total := 0

		for ch := lowChar; ch <= highChar; ch++ {
			nextMatch := matched

			for nextMatch > 0 && evil[nextMatch] != ch {
				nextMatch = lps[nextMatch-1]
			}

			if evil[nextMatch] == ch {
				nextMatch++
			}

			nextTightLow := tightLow && (ch == lowChar)
			nextTightHigh := tightHigh && (ch == highChar)

			total += dfs(
				pos+1,
				nextMatch,
				nextTightLow,
				nextTightHigh,
			)

			total %= MOD
		}

		memo[state] = total
		return total
	}

	return dfs(0, 0, true, true)
}
```Go 实现遵循与 Python 版本相同的逻辑，但使用显式`map[State]int`用于记忆。 

由于 Go 没有像 Python 那样的内置记忆递归装饰器`lru_cache`，我们定义一个自定义`State`结构体作为映射键。 

布尔值直接包含在记忆状态中。 

取模运算在 Go 中尤其重要，因为累加时更容易遇到整数溢出。

 ## 边缘情况

 ### 邪恶作为前缀出现

 考虑：```
s1 = "leetcode"
s2 = "leetgoes"
evil = "leet"
```每个有效的候选人都以`"leet"`。 

一个幼稚的解决方案可能会在检测无效性之前继续探索更深层次的递归。 KMP 状态在处理第四个字符后立即达到完全匹配，导致 DP 提前终止该分支。 

这可以防止浪费计算。 

### 重叠的禁止模式

 考虑：```
evil = "abab"
```假设当前生成的后缀为：```
"aba"
```如果下一个字符是`'b'`，出现禁止子串。 

然而，在部分不匹配之后，我们不能简单地将匹配重置为零，因为重叠很重要。 

KMP 前缀表在部分匹配之间正确转换，确保高效、正确地处理重叠结构。 

### 非常严格的界限

 考虑：```
s1 = "abc"
s2 = "abc"
```只有一个可能的字符串。 

一个常见的错误是过早错误地放松边界约束。 

这`tightLow`和`tightHigh`标志保证如果当前前缀仍然与边界匹配，则未来的字符仍然受到适当的约束。 

这可以确保精确范围的情况正常工作。
