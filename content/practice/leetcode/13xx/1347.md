[LeetCode 问题 1347](https://leetcode.com/problems/minimum-number-of-steps-to-make-two-strings-anagram/)

 **难度：** 🟡 中等
 **主题：** 哈希表、字符串、计数

 ## 解决方案

 ## 问题理解

 该问题要求我们确定转换字符串所需的最少字符替换数`t`转换为字符串的字谜词`s`。 

如果两个字符串包含完全相同且频率相同的字符（无论顺序如何），则它们是字谜词。 由于保证两个字符串具有相同的长度，因此我们永远不需要插入或删除字符。 唯一允许的操作是替换其中的一个字符`t`与另一个角色。 

关键的观察是我们不关心角色位置。 我们只关心每个字符在两个字符串中出现的次数。 

例如，考虑：```
s = "bab"
t = "aba"
```频率计数为：```
s: a -> 1, b -> 2
t: a -> 2, b -> 1
```细绳`t`有一个额外的`'a'`并且缺少一个`'b'`。 更换一个`'a'`和`'b'`解决了不平衡问题，所以答案是`1`。 

约束条件很重要：

 -`1 <= s.length <= 5 * 10^4`- 只出现小写英文字母

 输入大小足够大，低效方法（尤其是基于阶乘或二次重排的方法）会太慢。 然而，字母大小固定为 26 个小写字母，这强烈建议采用基于计数或频率的解决方案。 

一些重要的边缘情况包括：

 - 字符串已经是字谜词，因此不需要替换。 
- 一个字符串包含与另一个字符串完全不同的字符。 
- 非常小的输入，例如长度的字符串`1`。 
- 具有重复字符的大量输入，其中高效计数变得很重要。 

该问题保证两个字符串具有相同的长度并且仅包含小写英文字母，因此我们不需要处理不匹配的长度或无效字符。 

## 方法

 ### 蛮力方法

 解决该问题的一种简单方法是重复搜索两个字符串之间不匹配的字符并模拟替换。 

一种可能的暴力策略是：

 1.统计字符出现的频率`s`。 
2. 遍历`t`。 
3. 如果一个字符在`t`存在于所需的频率`s`，使用它。 
4. 否则，标记为更换。 

更糟糕的强力解释将涉及生成排列或尝试所有可能的替换组合，直到形成字谜。 由于字符串长度`n`有`n!`排列，这很快在计算上变得不可能。 

即使更实用的暴力变体仍然涉及重复搜索和更新，这可能会导致`O(n^2)`行为。 

尽管这些方法最终找到了正确的答案，但它们的成本不必要地高，因为问题仅取决于字符频率。 

### 最佳方法

 最佳解决方案是使用字符计数。 

重要的见解是：

 - 每个出现次数过多的角色`t`最终必须被替换。 
- 每个角色都缺失了`t`相比`s`需要更换。 
- 这两个数量始终相等，因为字符串具有相同的长度。 

我们可以计算每个字符在两个字符串中出现的次数并比较频率。 

对于每个角色：```
missing = frequency_in_s - frequency_in_t
```如果这个值是正数，那么`t`缺少该角色的许多副本，我们必须执行许多替换。 

由于只有 26 个小写字母，因此这种比较非常有效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) 或更糟 | O(1) 到 O(n) | 重复搜索或模拟替换 |
 | 最佳| O(n) | O(1) | O(1) | 使用 26 个小写字母的频率计数 |

 ## 算法演练

 ### 最优频率计数算法

 1.为所有字符创建一个频率计数器`s`。 

这个计数器告诉我们每个字符应该在最终的字谜中出现多少次。 
2. 为所有字符创建另一个频率计数器`t`。 

这个计数器告诉我们当前的状态`t`。 
3. 比较所有 26 个小写字母的出现频率。 

对于每个字符：

 - 如果`s`包含的副本数多于`t`， 然后`t`缺少一些事件。 
- 每次缺失都需要更换一次。 
4. 对所有正差异求和。 

具体来说：```
answer += max(0, count_s - count_t)
```5. 返回累计总数。 

### 为什么它有效

 该算法之所以有效，是因为字谜词需要相同的字符频率。 

如果`t`与相比缺少一定数量的字符`s`，每个缺失的字符必须通过替换操作来创建。 由于每次替换都会同时删除一个额外的字符并创建一个缺失的字符，因此缺失字符的总数恰好等于所需的最小操作数。 

## Python 解决方案```python
class Solution:
    def minSteps(self, s: str, t: str) -> int:
        s_count = [0] * 26
        t_count = [0] * 26

        for char in s:
            s_count[ord(char) - ord('a')] += 1

        for char in t:
            t_count[ord(char) - ord('a')] += 1

        steps = 0

        for i in range(26):
            if s_count[i] > t_count[i]:
                steps += s_count[i] - t_count[i]

        return steps
```该实现使用两个长度为 26 的固定大小数组来存储字符频率。 

第一个循环计算字符数`s`。 每个字符都转换为之间的索引`0`和`25`使用 ASCII 算术。 

第二个循环计算字符数`t`以同样的方式。 

构建两个频率数组后，算法会比较相应的计数。 每当`s`包含的字符出现次数多于`t`，差异表示必须通过替换引入的缺失字符。 

最终的答案是所有这些赤字的总和。 

由于字母表大小是固定的，因此比较循环始终恰好运行 26 次。 

## 解决方案```go
func minSteps(s string, t string) int {
    sCount := make([]int, 26)
    tCount := make([]int, 26)

    for _, ch := range s {
        sCount[ch-'a']++
    }

    for _, ch := range t {
        tCount[ch-'a']++
    }

    steps := 0

    for i := 0; i < 26; i++ {
        if sCount[i] > tCount[i] {
            steps += sCount[i] - tCount[i]
        }
    }

    return steps
}
```Go 实现遵循与 Python 版本相同的逻辑。 

Go 使用大小为 26 的整数切片，而不是 Python 列表。字符被处理为符文，索引是使用`'a'`偏移量。 

不用担心整数溢出，因为最大字符串长度仅为`5 * 10^4`。 

Go 切片会自动使用零值进行初始化，因此不需要对频率数组进行额外设置。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个字符串都被遍历一次 |
 | 空间| O(1) | O(1) | 频率数组始终包含 26 个元素 |

 该算法仅处理两个字符串中的每个字符一次，从而产生线性时间复杂度。 

空间复杂度是恒定的，因为频率数组永远不会随着输入大小而增长。 无论字符串包含 10 个字符还是 50,000 个字符，该算法仅存储 26 个小写英文字母的计数。

 ## 边缘情况

 ### 字符串已经形成字谜

 一种重要的边缘情况发生在以下情况：`s`和`t`已经包含相同的字符频率。 

例如：```
s = "listen"
t = "silent"
```有缺陷的实现可能会错误地计算位置差异并得出需要替换的结论。 然而，问题只关心频率计数，而不关心顺序。 

基于频率的解决方案可以正确处理此问题，因为所有字符计数都匹配，产生的结果为`0`。 

### 完全不同的字符串

 另一个重要的情况是每个角色都不同。 

例子：```
s = "aaa"
t = "bbb"
```在这里，三个`'b'`中的字符`t`必须替换为`'a'`。 

尝试贪婪地匹配字符的简单实现可能会变得不必要的复杂。 计数方法立即检测到`t`缺少三个`'a'`字符，所以答案是`3`。 

### 大量重复的大量输入

 考虑接近最大约束大小的输入：```
s = "a" repeated 50,000 times
t = "b" repeated 50,000 times
```重复搜索或修改字符串的低效算法可能会变得太慢。 

最佳解决方案仍然有效，因为它只执行：

 - 一次通过`s`- 一次通过`t`- 超过 26 个字符的一个固定大小比较循环

 即使对于最大的有效输入，这也保证了出色的性能。
