[LeetCode 第 1308 题](https://leetcode.com/problems/running-total-for- different-genders/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 问题是要求我们计算比赛中不同日期每个性别的累积分数。 输入是一个表`Scores`有柱子`player_name`,`gender`,`day`， 和`score_points`。 每行代表玩家在特定日期的得分。 主键是组合`(gender, day)`，这意味着每个性别每天都有独特的条目。 

预期输出是一个表格，对于每个性别，按时间顺序列出每天以及该性别截至该天的累积总分。 排序很重要：结果必须首先按性别分组，然后按天升序排序。 

限制和影响：评分表没有天数差距； 该数据集可能有多个玩家在同一天得分。 边缘情况包括单项性别、同一天有多名玩家以及附加分数为零的日子。 

## 方法

 ### 蛮力

 一种简单的方法是首先按性别对所有行进行分组，然后针对每个性别对天数进行排序，最后迭代排序的天数以计算累计总数。 这将涉及对数据的多次传递：一次用于分组，一次用于排序，另一次用于求和。 虽然正确，但如果表有很多条目，则效率可能会很低，因为重复聚合和排序的成本很高。 

### 最佳

 关键的见解是 SQL 提供了窗口函数来有效地处理运行总计。 首先汇总每天和每个性别的分数，然后使用`SUM()`窗函数与`PARTITION BY gender ORDER BY day`我们可以一次性计算累积总数。 这种方法避免了应用程序代码中的显式迭代求和，并利用数据库引擎进行优化。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n log n) | O(n log n) | O(n) | 按性别分组、按天排序、迭代计算累计总数 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 按性别每天汇总，然后对分区行使用窗口函数 SUM |

 ## 算法演练

 1. **每日总分**：将`Scores`表格依据`gender`和`day`总结所有个人`score_points`对于同一天的玩家。 这可确保同一天的多个分数合并为一个值。 
2. **计算运行总计**：使用窗口函数`SUM(score_points) OVER (PARTITION BY gender ORDER BY day)`计算每个性别的累积分数。 这保持了一个不变量：每天的累积总和等于该性别之前所有每日总和的总和。 
3. **对结果进行排序**：最后，对结果进行排序`gender`和`day`按升序排列以满足输出要求。 

为什么有效：首先聚合可以防止重复计算，并且使用窗口函数可以确保累计总数尊重性别和时间顺序。 这保证了正确性，同时利用数据库效率。 

## Python 解决方案```python
import sqlite3
from typing import List, Tuple

def running_total_scores() -> List[Tuple[str, str, int]]:
    conn = sqlite3.connect(':memory:')
    cursor = conn.cursor()
    
    cursor.execute('''
        CREATE TABLE Scores (
            player_name TEXT,
            gender TEXT,
            day DATE,
            score_points INTEGER
        )
    ''')
    
    # Assuming table is populated beforehand
    
    cursor.execute('''
        WITH DailyTotals AS (
            SELECT gender, day, SUM(score_points) AS total_points
            FROM Scores
            GROUP BY gender, day
        )
        SELECT gender, day,
               SUM(total_points) OVER (PARTITION BY gender ORDER BY day) AS total
        FROM DailyTotals
        ORDER BY gender, day
    ''')
    
    result = cursor.fetchall()
    conn.close()
    return result
```该实现首先创建用于演示目的的表，并假设该表已填充。 它使用通用表表达式 (CTE)`DailyTotals`每天汇总每个性别的分数。 然后，窗口函数`SUM() OVER (PARTITION BY gender ORDER BY day)`按时间顺序计算每个性别的运行总计。 

## 解决方案```go
package main

import (
    "database/sql"
    _ "github.com/mattn/go-sqlite3"
    "fmt"
)

func runningTotalScores(db *sql.DB) ([][3]interface{}, error) {
    query := `
        WITH DailyTotals AS (
            SELECT gender, day, SUM(score_points) AS total_points
            FROM Scores
            GROUP BY gender, day
        )
        SELECT gender, day,
               SUM(total_points) OVER (PARTITION BY gender ORDER BY day) AS total
        FROM DailyTotals
        ORDER BY gender, day;
    `
    
    rows, err := db.Query(query)
    if err != nil {
        return nil, err
    }
    defer rows.Close()
    
    var results [][3]interface{}
    for rows.Next() {
        var gender string
        var day string
        var total int
        if err := rows.Scan(&gender, &day, &total); err != nil {
            return nil, err
        }
        results = append(results, [3]interface{}{gender, day, total})
    }
    return results, nil
}

func main() {
    db, _ := sql.Open("sqlite3", ":memory:")
    defer db.Close()
    // Assume Scores table is populated
    results, _ := runningTotalScores(db)
    fmt.Println(results)
}
```在Go中，我们使用相同的CTE和窗口函数逻辑查询数据库。 区别在于处理`sql.Rows`并扫描变量。 Go 需要对数据库操作进行显式错误处理。

 ## 边缘情况

 **单一性别**：如果所有行都属于一种性别，则该算法仍然可以正确计算运行总计，因为窗口函数按性别进行分区并简单地忽略丢失的分区。 

**同一天多次参赛**：在计算总得分之前，必须对同一天的多名玩家得分进行求和。 聚合确保不会发生重复计算。 

**非连续天数**：如果天数不连续，则累计总和仍然有效，因为运行总计按天排序并且不假定连续日期。 缺失的天数根本不会出现在输出中，这符合问题要求。
