[LeetCode 问题 1365](https://leetcode.com/problems/how-many-numbers-are-smaller-than-the-current-number/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表、排序、计数排序

 ## 解决方案

 ## 问题理解

 该问题要求我们确定对于数组中的每个元素，同一数组中有多少个元素严格小于它。 换句话说，对于一个元素`nums[i]`，我们计算所有元素`nums[j]`这样`nums[j] < nums[i]`和`j != i`。 输入是一个整数列表`nums`长度在 2 到 500 之间，每个元素保证在 0 到 100 之间（包含 0 和 100）。 输出是一个相同长度的数组，其中每个位置包含与该索引对应的较小数字的计数。 

这些约束为我们提供了有关潜在优化的关键信息。 由于数字有界（0 到 100）并且数组长度相对较小，因此利用频率计数或排序的解决方案可能非常高效。 重要的边缘情况包括具有重复值的数组、所有元素都相同的数组以及具有升序或降序排列的数组。 正确处理重复项至关重要，因为不应计算等于当前数量的元素。 

## 方法

 ### 蛮力

 最简单的方法是使用嵌套循环。 对于每个元素`nums[i]`，再次迭代数组以计算有多少个数字小于`nums[i]`。 这保证了正确的结果，因为它显式地比较每一对，但效率低下。 最大数组长度为 500 时，结果为`O(n^2)`比较，这对于小型数组来说是可以接受的，但在实践中可能会很慢。 

### 最佳方法

 关键的观察结果是数字限制在 0-100 范围内。 这使我们能够使用类似计数排序的方法。 首先，我们创建一个频率数组`count`大小为 101 来记录每个数字出现的次数。 然后，通过计算该频率数组的前缀和，我们可以确定，对于任何数字`x`, 有多少个数字严格小于`x`。 该方法完全避免了输入数组上的嵌套循环，并将时间复杂度降低到`O(n + k)`， 在哪里`k`是 101，固定数字范围。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n^2) | O(n^2) | O(1) | O(1) | 将每个元素与其他所有元素进行比较 |
 | 最佳 | O(n + k) | O(k) | 使用频率计数和前缀和 (k = 101) |

 ## 算法演练

 1.初始化频率数组`count`大小为 101，全为零。 这将存储每个数字出现的次数`nums`。 
2. 迭代`nums`, 递增`count[num]`对于每个元素`num`。 这一步之后，`count[i]`代表频率`i`在`nums`。 
3. 转换`count`到前缀和数组中。 迭代自`1`到`100`并更新`count[i]`到`count[i] + count[i - 1]`。 此后，`count[i]`告诉我们有多少个数字`nums`小于或等于`i`。 
4. 迭代`nums`再次构建结果数组。 对于每个`num`， 如果`num`是`0`，没有更小的数字，所以追加`0`。 否则，附加`count[num - 1]`，这给出了严格小于的数字计数`num`。 
5. 返回结果数组。 

该算法之所以有效，是因为前缀和捕获了达到特定值的元素的累积数量。 通过适当的减法，我们可以精确地得到严格小于每个数字的元素的数量。 

## Python 解决方案```python
from typing import List

class Solution:
    def smallerNumbersThanCurrent(self, nums: List[int]) -> List[int]:
        count = [0] * 101
        
        # Count the frequency of each number
        for num in nums:
            count[num] += 1
        
        # Compute prefix sums
        for i in range(1, 101):
            count[i] += count[i - 1]
        
        result = []
        for num in nums:
            if num == 0:
                result.append(0)
            else:
                result.append(count[num - 1])
        
        return result
```Python 解决方案首先构建一个频率数组来跟踪每个数字出现的频率。 接下来，它计算累积和，将频率转换为小于或等于每个索引的数字计数。 最后通过查找构造结果`count[num - 1]`对于每个数字，这直接产生较小元素的数量。 

## 解决方案```go
func smallerNumbersThanCurrent(nums []int) []int {
    count := make([]int, 101)
    
    // Count the frequency of each number
    for _, num := range nums {
        count[num]++
    }
    
    // Compute prefix sums
    for i := 1; i <= 100; i++ {
        count[i] += count[i - 1]
    }
    
    result := make([]int, len(nums))
    for i, num := range nums {
        if num == 0 {
            result[i] = 0
        } else {
            result[i] = count[num - 1]
        }
    }
    
    return result
}
```Go 解决方案反映了 Python 逻辑，其中`make([]int, 101)`创建频率数组。 前缀和和结果数组构造遵循相同的方法。 处理`num == 0`确保我们避免索引`-1`。 

## 工作示例

 示例：`nums = [8,1,2,2,3]`| 步骤| 计数数组（部分）| 说明|
 | ---| ---| ---|
 | 初始计数 | [0,0,0,0,0,0,...] | 全零 |
 | 计算频率 | [0,1,2,1,0,0,...,1] | 1 出现一次、2 出现两次、3 出现一次、8 出现一次 |
 | 前缀和 | [0,1,3,4,4,4,...,5] | count[i] = 数字 <= i |
 | 构建结果 | [4,0,1,1,3] | 对于 8 → count[7]=4，对于 1 → count[0]=0，对于 2 → count[1]=1，等等 |

 这显示了前缀和如何允许 O(1) 查找较小元素的数量。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n + k) | 计算频率 O(n)，前缀和 O(k)，其中 k=101，最终迭代 O(n) |

 自从`k=101`是常数，该算法实际上是线性的`n`。

 ## 边缘情况

 一种边缘情况是所有数字都相同。 该算法对所有位置都正确返回零，因为没有数字小于任何其他数字。 另一个边缘情况是当`nums`包含最小或最大的可能值，即 0 和 100。前缀和数组可以处理这个问题而不会超出范围。 第三种边缘情况是当数组包含多个散布有唯一数字的重复项时。 前缀和确保每个数字正确地只计算严格较小的数字，而不是相等的数字。 这些边缘情况表明该算法可以正确处理边界、重复项和统一数组。
