 # LeetCode 1313，解压缩游程编码列表

 ## 问题理解

 这个问题要求我们重建一个使用简单游程编码格式压缩的数组。 

输入数组`nums`始终包含偶数个元素。 每两个连续的元素形成一对：

 - 第一个值代表频率，称为`freq`- 第二个值代表一个数字，称为`val`对于每对`[freq, val]`，我们必须创建一个包含`freq`的副本`val`。 生成所有子数组后，我们以相同的顺序将它们连接在一起以生成最终的解压缩列表。 

例如，如果我们看到一对`[3, 4]`，这意味着我们应该生成：```
[4, 4, 4]
```如果整个输入是：```
[1,2,3,4]
```然后：

-`[1,2]`变成`[2]`-`[3,4]`变成`[4,4,4]`将它们结合起来可以得到：```
[2,4,4,4]
```限制非常小：

 -`nums.length <= 100`- 每个值都介于`1`和`100`这告诉我们，效率并不是主要问题。 即使是简单的模拟方法也可以轻松地在时间限制内完成。 

该问题还保证：

 - 数组长度为偶数
 - 每个频率都是正的
 - 每个值都是正值

 由于这些保证，我们不需要处理格式错误的输入，例如丢失对或零频率。 

仍有一些边缘情况值得考虑：

 - 频率为`1`，这意味着只应添加一份副本
 - 具有相同值的多个连续对
 - 两个元素的最小可能输入大小
 - 相对于约束的频率非常大，这可能会暴露不正确的循环逻辑或索引错误

 ## 方法

 ### 蛮力方法

 暴力方法直接遵循问题陈述。 

我们一次迭代数组两个元素。 对于每对：```
[freq, val]
```我们反复追加`val`准确地放入结果数组中`freq`次。 

这种方法是正确的，因为它实际上完全按照问题中的描述执行解压缩。 

尽管此方法使用嵌套循环，但约束足够小，性能完全可以接受。 附加元素的总数受最终解压缩数组大小的限制。 

### 最佳方法

 最佳方法在概念上类似，但我们可以使用列表或切片扩展操作一次附加多个副本，而不是在内循环中一次附加一个值。 

关键的观察结果是，每一对独立地贡献一个连续的重复值块。 由于最终的答案只是这些块的串联，因此我们可以有效地生成每个块并直接附加它。 

在Python中，我们可以使用：```
[val] * freq
```有效地创造重复价值。 

在 Go 中，我们通常使用循环，因为切片不支持像 Python 列表那样的直接乘法。 

尽管渐近复杂度保持不变，但实现变得更清晰、更容易理解。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n + k) | O(k) | 使用嵌套循环一次附加一个值 |
 | 最佳| O(n + k) | O(k) | 直接构建重复块并将它们连接起来 |

 这里：

-`n`的长度是`nums`-`k`是解压输出数组的大小

 ## 算法演练

 1. 初始化一个空结果数组，用于存储解压后的值。 
2. 以两步遍历输入数组，因为每一对元素代表一个编码块。 
3. 对于每次迭代：

 - 阅读`freq = nums[i]`- 读`val = nums[i + 1]`4. 生成`freq`的副本`val`。 

- 在Python中，这可以通过以下方式完成：```
[val] * freq
```- 在 Go 中，我们附加`val`在循环内重复进行。 
5. 将生成的值附加到结果数组中。 
6. 继续处理，直到处理完所有对。 
7. 返回最终解压后的数组。 

### 为什么它有效

 输入中的每一相邻对唯一地定义解压缩数组的一个连续段。 该算法按从左到右的顺序处理对并精确附加`freq`的副本`val`对于每一对。 由于每个段均正确生成并按原始顺序连接，因此最终数组与所需的解压缩输出完全匹配。 

## Python 解决方案```python
from typing import List

class Solution:
    def decompressRLElist(self, nums: List[int]) -> List[int]:
        result = []

        for i in range(0, len(nums), 2):
            freq = nums[i]
            val = nums[i + 1]

            result.extend([val] * freq)

        return result
```实现首先创建一个名为的空列表`result`，它将存储解压后的数字。 

循环遍历`nums`步长为`2`因为每一对元素形成一个编码单元。 在每次迭代时：

 -`freq`存储该值应出现的次数
 -`val`存储要重复的实际数字

 表达式：```python
[val] * freq
```创建一个临时列表，其中包含`freq`的副本`val`。 

这`extend()`方法立即将所有这些值附加到结果列表中。 处理完所有对后，返回完整的解压列表。 

## 解决方案```go
func decompressRLElist(nums []int) []int {
    result := []int{}

    for i := 0; i < len(nums); i += 2 {
        freq := nums[i]
        val := nums[i+1]

        for j := 0; j < freq; j++ {
            result = append(result, val)
        }
    }

    return result
}
```Go 实现遵循与 Python 版本相同的逻辑。 由于 Go 切片不支持像 Python 列表那样的乘法，因此我们使用内部循环重复附加值。 

Go 切片会根据需要自动调整大小`append`，使它们自然适合解决这个问题。 

不存在整数溢出问题，因为根据约束，所有值都非常小。

 ## 边缘情况

 一种重要的边缘情况是最小输入大小，例如：```
[1,5]
```这种情况仅包含一个频率值对。 某些实现意外地假设存在多个对或错误地处理循环边界。 我们的实现以两步安全地迭代，甚至可以正确处理一对。 

另一个重要的边缘情况是当频率等于`1`。 例如：```
[1,9]
```这可能会暴露循环中的差一错误。 如果循环错误地运行零次或两次，输出立即变得不正确。 我们的实现使用列表乘法或精确执行的循环`freq`次，保证添加一份。 

第三个重要的边缘情况是不同对之间的重复值，例如：```
[2,3,1,3]
```解压后的输出应变为：```
[3,3,3]
```有缺陷的实现可能会意外地错误地合并频率或覆盖早期的值。 我们的算法独立处理每一对并按顺序附加结果，保留正确的顺序和计数。 

另一个微妙的边缘情况涉及接近约束极限的较大频率，例如：```
[100,1]
```这测试实现是否正确处理多次重复插入。 由于约束很小并且算法将值直接附加到结果列表中，因此它可以毫无问题地处理这些情况。
