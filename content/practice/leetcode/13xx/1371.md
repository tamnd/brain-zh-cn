 # LeetCode 1371 - 找到包含偶数个元音的最长子串

 ## 问题理解

 这个问题要求我们找到每个元音出现偶数次的最长连续子串的长度。 我们关心的元音是：

 -`a`-`e`-`i`-`o`-`u`元音可能出现零次，零被视为偶数。 因此，完全没有元音的子串是有效的。 

输入是一个字符串`s`仅由小写英文字母组成。 我们必须返回满足条件的子字符串的最大可能长度。 

重要的细节是我们只关心每个元音出现的次数是偶数还是奇数。 除了其奇偶性之外，确切的计数并不重要。 

例如，如果子字符串包含：

 -`e`两次
 -`i`四次
 -`o`零次

 那么这些元音是有效的，因为所有计数都是偶数。 

限制条件很大：

 -`1 <= s.length <= 5 * 10^5`这立即告诉我们二次算法可能会超时。 一个`O(n^2)`在最坏的情况下，解决方案将需要检查数十亿个子字符串。 我们需要一个线性或近线性的解决方案。 

一些边缘情况很重要：

 - 根本没有元音的字符串，例如`"bcbcbc"`，应该返回整个字符串长度。 
- 除单个辅音之外不存在非空有效子字符串的字符串。 
- 重复切换元音奇偶性，其中元音出现多次。 
- 投入非常大，效率至关重要。 
- 前缀本身可能已经满足条件。 

该问题只保证小写英文字母，因此我们不需要处理大写字符或非字母符号。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每个可能的子字符串。 

对于每个子串：

 1. 计算每个元音的出现次数。 
2. 检查每个元音数是否为偶数。 
3. 如果有效，则更新最大长度。 

一个天真的实现会生成所有`O(n^2)`子串，并且计算每个子串内的元音需要`O(n)`时间，导致`O(n^3)`复杂。 

我们可以使用前缀频率数组稍微改进这一点，这样每个子串检查就变成`O(1)`，将总复杂度降低到`O(n^2)`。 然而，随着`n = 5 * 10^5`， 甚至`O(n^2)`太慢了。 

蛮力方法是正确的，因为它显式检查每个可能的子字符串，但对于输入大小来说并不实用。 

### 最佳方法

 关键的见解是我们只关心每个元音计数是偶数还是奇数。 

每个元音可以有两种状态：

 - 甚至
 - 奇数

 有五个元音，因此可能的奇偶校验状态总数为：$$2^5 = 32$$我们可以使用 5 位位掩码来表示奇偶校验状态：

 - 位 0 为`a`- 位 1 为`e`- 位 2 为`i`- 位 3 为`o`- 位 4 为`u`当我们扫描字符串时：

 - 遇到元音会切换其相应位
 - 辅音保持状态不变

 如果相同的位掩码出现在两个不同的索引处，则它们之间的子串对于所有元音都有偶数计数。 

为什么？ 

因为奇偶校验的变化抵消了。 如果索引处的前缀奇偶校验状态`i`等于索引处的前缀奇偶校验状态`j`，然后是子串`(i+1 ... j)`每个元音必须包含偶数个。 

这将问题转化为寻找两个相同前缀状态之间的最大距离。 

我们存储每个状态首次出现的最早索引。 每当我们再次看到相同的状态时，我们就会计算子串长度。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) 或 O(n) | 显式检查每个子字符串 |
 | 最佳 | O(n) | O(1) | O(1) | 使用位掩码奇偶校验状态和前缀跟踪 |

 ## 算法演练

 1. 创建一个名为的位掩码变量`state`，初始设置为`0`。 

一个状态`0`表示当前所有元音都有偶数计数。 
2. 创建一个名为的哈希图`first_seen`。 

该映射存储每个奇偶校验状态出现的最早索引。 

初始化它：```
{0: -1}
```这处理有效子字符串从索引开始的情况`0`。 
3. 定义从元音到位位置的映射。 

例如：

-`a -> 0`-`e -> 1`-`i -> 2`-`o -> 3`-`u -> 4`4. 逐个字符地遍历字符串。 
5. 对于每个字符：

 - 如果它是元音，则使用 XOR 切换其相应位。 
- 如果是辅音，则不执行任何操作。 

例子：```
state ^= (1 << vowel_index)
```6.更新状态后：

 - 如果此状态之前出现过，则计算从第一次出现到当前索引的子字符串长度。 
- 否则，将当前索引存储为该状态的第一次出现。 
7. 记录找到的最大子字符串长度。 
8.返回处理整个字符串后的最大长度。 

### 为什么它有效

 该算法依赖于前缀奇偶校验状态。 

假设两个前缀具有相同的奇偶校验状态。 这意味着每个元音在这两个位置之间都改变了偶数次奇偶性。 因此，它们之间的子串包含所有元音的偶数个。 

通过存储每个状态最早出现的时间，每当相同状态再次出现时，我们就最大化子串长度。 

由于只有 32 种可能的状态，该算法仍然非常高效。 

## Python 解决方案```python
class Solution:
    def findTheLongestSubstring(self, s: str) -> int:
        vowel_to_bit = {
            'a': 0,
            'e': 1,
            'i': 2,
            'o': 3,
            'u': 4
        }

        first_seen = {0: -1}

        state = 0
        max_length = 0

        for index, char in enumerate(s):
            if char in vowel_to_bit:
                bit_position = vowel_to_bit[char]
                state ^= (1 << bit_position)

            if state in first_seen:
                current_length = index - first_seen[state]
                max_length = max(max_length, current_length)
            else:
                first_seen[state] = index

        return max_length
```该实现首先创建元音与其相应位位置之间的映射。 这使我们能够使用位操作有效地切换奇偶校验信息。 

这`first_seen`字典记录每个奇偶校验状态出现的最早索引。 我们初始化状态`0`在索引处`-1`因为空前缀使所有元音出现偶数次。 

当我们迭代字符串时，只要遇到元音，我们就会更新奇偶校验状态。 使用 XOR 是因为它自然地在两者之间切换一点`0`和`1`。 

如果当前状态之前出现过，则前一次出现和当前位置之间的子串对于每个元音都有偶数。 我们计算它的长度并更新答案。 

如果该状态以前从未出现过，我们存储当前索引。 我们只存储第一次出现的位置，因为较早的位置会产生更长的子字符串。 

## 解决方案```go
func findTheLongestSubstring(s string) int {
    vowelToBit := map[byte]int{
        'a': 0,
        'e': 1,
        'i': 2,
        'o': 3,
        'u': 4,
    }

    firstSeen := map[int]int{
        0: -1,
    }

    state := 0
    maxLength := 0

    for i := 0; i < len(s); i++ {
        ch := s[i]

        if bit, exists := vowelToBit[ch]; exists {
            state ^= (1 << bit)
        }

        if firstIndex, exists := firstSeen[state]; exists {
            currentLength := i - firstIndex

            if currentLength > maxLength {
                maxLength = currentLength
            }
        } else {
            firstSeen[state] = i
        }
    }

    return maxLength
}
```Go 实现遵循与 Python 版本相同的逻辑。 一个`map[int]int`用于存储每个奇偶校验状态的第一次出现。 

由于 Go 字符串是 ASCII 字符的字节数组，因此我们直接使用`s[i]`。 这是高效且安全的，因为输入仅包含小写英文字母。 

奇偶校验状态存储为整数位掩码，XOR 切换元音奇偶校验与 Python 解决方案中完全相同。

 ## 边缘情况

 ### 没有元音的字符串

 像这样的字符串`"bcbcbc"`根本不包含元音。 由于零是偶数，因此整个字符串都是有效的。 

如果实现假设元音必须至少出现一次，这种情况可能会导致错误。 我们的解决方案可以自然地处理它，因为奇偶校验状态永远不会改变`0`，因此整个字符串成为最长的有效子串。 

### 从索引 0 开始的子字符串

 考虑`"aa"`。 

有效的子字符串从字符串的开头开始。 没有初始化：```
first_seen = {0: -1}
```该算法将无法检测本身有效的前缀。 

使用`-1`表示字符串开始之前的空前缀，允许正确的长度计算。 

### 重复出现的状态

 一个状态可能在整个字符串中出现多次。 为了正确性，我们必须只存储第一次出现的情况。 

例如，如果一个状态首先出现在索引处`2`然后在索引处`10`，然后重新出现在索引处`15`，使用最早的索引会产生最长的可能子字符串。 

如果我们覆盖早期的索引，我们将错误地计算较短的子字符串，并可能错过最佳答案。
