[LeetCode 问题 1364](https://leetcode.com/problems/number-of-trusted-contacts-of-a-customer/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 这个问题要求我们分析客户、他们的联系人和发票之间的关系。 我们得到了三张表：`Customers`,`Contacts`， 和`Invoices`。 这`Customers`表通过以下方式标识每个客户`customer_id`以及他们的姓名和电子邮件。 这`Contacts`表包含每个客户的联系人列表，其中`user_id`指的是客户以及按姓名和电子邮件列出的每个联系人。 这`Invoices`表列出了通过以下方式链接到客户的发票`user_id`连同发票价格。 

任务是为每张发票生成客户名称、发票价格、客户拥有的联系人数量以及“可信联系人”数量（其电子邮件也存在于邮件中）`Customers`表，表明该联系人也是客户。 输出应按以下顺序排序`invoice_id`。 

需要注意的要点是，联系人可能不作为客户存在，客户可以有零个联系人，并且`Contacts`确保没有重复`(user_id, contact_email)`条目。 数据集可能有同一客户的多张发票，解决方案必须正确处理该问题。 

边缘情况包括没有联系人的客户、非注册客户的联系人以及单个客户的多张发票。 

## 方法

 蛮力方法将加入`Invoices`表到`Customers`表来获取名称，然后对于每张发票，迭代客户的联系人并计算该发票中存在多少个发票`Customers`桌子。 虽然概念上很简单，但这涉及到每个发票的重复子查询或联接，如果表很大，这可能会很昂贵。 

最佳方法是有效地使用 SQL 连接和聚合。 我们首先加入`Invoices`到`Customers`获取客户姓名。 然后我们离开加入`Contacts`来统计所有联系人的数量。 对于可信联系人，我们从以下位置进行另一个左连接`Contacts`到`Customers`在电子邮件字段中查看哪些联系人也是客户。 我们汇总使用`COUNT`和`COUNT(DISTINCT)`分组时按`invoice_id`,`customer_name`， 和`price`。 这种方法避免了多次扫描并利用 SQL 基于集合的操作来提高效率。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(I * C) | O(1) | O(1) | 迭代发票，扫描联系人和客户 |
 | 最佳 | O(I + C + K) | O(I + C + K) | O(C + K) | 使用连接和聚合； 表格的单次扫描|

 ## 算法演练

 1. 从加入开始`Invoices`和`Customers`在`user_id = customer_id`得到`customer_name`每张发票。 
2. 左连接`Contacts`在`user_id = customer_id`包括用于计数的联系信息。 
3. 左连接`Customers`再次开启`Contacts.contact_email = Customers.email`以确定哪些联系人是可信的。 
4. 分组依据`invoice_id`,`customer_name`， 和`price`以允许聚合。 
5. 使用以下方法计算联系人总数`COUNT(Contacts.contact_email)`并使用以下方法计算可信联系人的数量`COUNT(Customers.customer_id)`（仅当联系人是注册客户时才为非空）。 
6. 对结果进行排序`invoice_id`。 

这是可行的，因为 SQL 聚合可以确保我们准确地计算出我们想要的关系。 左联接使我们能够包含零联系人的客户，通过电子邮件进行匹配可确保正确识别可信联系人。 

## Python 解决方案```python
class Solution:
    def trustedContacts(self):
        query = """
        SELECT 
            i.invoice_id,
            c.customer_name,
            i.price,
            COUNT(ct.contact_email) AS contacts_cnt,
            COUNT(c2.customer_id) AS trusted_contacts_cnt
        FROM Invoices i
        JOIN Customers c ON i.user_id = c.customer_id
        LEFT JOIN Contacts ct ON i.user_id = ct.user_id
        LEFT JOIN Customers c2 ON ct.contact_email = c2.email
        GROUP BY i.invoice_id, c.customer_name, i.price
        ORDER BY i.invoice_id
        """
        return query
```该 SQL 查询被封装在 Python 方法中，以匹配典型的 LeetCode SQL 问题存根。 第一个连接将发票连接到客户以获取姓名。 第一个左连接包含联系人，第二个左连接检查哪些联系人是可信的。 聚合对联系人总数和可信联系人进行计数，最终排序确保输出按发票 ID 排序。 

## 解决方案```go

        i.invoice_id,
        c.customer_name,
        i.price,

    LEFT JOIN Customers c2 ON ct.contact_email = c2.email
    GROUP BY i.invoice_id, c.customer_name, i.price
    ORDER BY i.invoice_id;
    `
}

## 工作示例

 对于第一张发票`77`链接到爱丽丝：

 3. 可信联系人 → 无
 4. 结果 →`55, John, 500, 0, 0`对所有发票重复此过程，根据要求生成输出。

 ## 边缘情况

 第一个边缘情况是零接触的客户。 没有左连接的简单连接可能会完全排除这些客户。 该解决方案使用左连接来处理此问题，将空值正确计数为零。 

第二个边缘情况是非客户的联系人。 简单的内部连接会将这些排除在计数之外。 该解决方案无论如何都会对联系人进行计数，并且仅在存在客户匹配时才对可信联系人进行计数。 

第三种边缘情况是单个客户的多张发票。 汇总必须按发票进行，而不是按客户进行。 分组依据`invoice_id`即使客户出现多次，也确保每张发票都得到独立处理。
