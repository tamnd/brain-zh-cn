[LeetCode 第 1319 题](https://leetcode.com/problems/number-of-operations-to-make-network-connected/)

 **难度：** 🟡 中等
 **主题：** 深度优先搜索、广度优先搜索、并查找、图论

 ## 解决方案

 ## 问题理解

 该问题将计算机网络建模为无向图。 每台计算机都是一个节点，每条以太网电缆都是连接两个节点的边缘。 目标是确定使整个网络完全连接所需的最少电缆重新布线数量。 

如果每台计算机都可以直接或通过中间计算机到达其他所有计算机，则网络被视为完全连接。 重要的细节是我们可以移除现有的电缆并将其重新连接到其他地方。 换句话说，如果一个连接的组件内部存在冗余连接，则这些电缆可能会被重新用于连接单独的断开连接的组件。 

输入包括：

 -`n`，标记为的计算机数量`0`到`n - 1`-`connections`，其中每个条目`[a, b]`代表计算机之间的双向电缆`a`和`b`输出应该是连接整个网络所需的最小电缆移动次数。 如果不可能，我们就返回`-1`。 

约束很重要，因为它们指导算法的选择：

 -`n`可以大到`10^5`- 连接数也可以达到`10^5`这立即排除了具有二次复杂度的昂贵图算法。 我们需要一个近线性的解决方案。 

问题中还隐藏着一个关键的图论观察。 连通图与`n`节点至少需要`n - 1`边缘。 如果电缆总数少于`n - 1`，那么无论电缆如何重新排列，从数学上来说都不可能连接所有计算机。 

一些边缘情况很重要：

 - 电缆太少的网络，例如`n = 6`并且只有`4`连接
 - 多个断开连接的组件
 - 已连接的网络
 - 没有直接连接的孤立节点
 - 包含冗余循环的网络，其中一些边缘可以安全地移除和重用

 该问题保证了没有重复连接，也没有自循环，从而简化了实现。 

## 方法

 ### 蛮力方法

 强力策略将尝试模拟断开的组件之间的电缆拆除和重新连接。 人们可以重复搜索冗余边，删除一个，然后重新连接两个断开的组，直到图形连接或没有剩余电缆为止。 

为了确定每次操作后的连通性，我们可能会在图上重复运行 DFS 或 BFS。 由于每个操作都会更改图结构，因此必须多次重新计算连通性检查。 

这种方法是正确的，因为它明确地模拟了允许的操作。 然而，它的效率极低。 重复的图遍历与重复的重新连接尝试相结合很容易导致二次或更糟糕的复杂性，这对于`10^5`节点。 

### 最佳方法

 关键的见解是我们实际上不需要模拟电缆运动。 

假设网络有`k`连接的组件。 要将所有组件连接到一个连接的网络中，我们需要准确地`k - 1`电缆。 这是因为每个操作都可以将两个组件合并在一起。 

现在考虑备用电缆。 组件中的任何循环都包含冗余边。 这些多余的边缘可以被提取并在其他地方重复使用。 

我们可以使用更简单的数学条件，而不是显式地计算冗余边：

 - 一个连通图`n`节点至少需要`n - 1`边缘。 
- 如果图表已经至少有`n - 1`总边缘，那么总体上就有足够的电缆来连接所有组件。 

所以算法就变成了：

 1. 检查总连接数是否至少为`n - 1`2. 计算连接组件的数量
 3. 返回`components - 1`我们可以使用以下任一方法有效地计算连接的组件：

 - 深度优先搜索/广度优先搜索
 - 并查

 联合查找对于大型图尤其有效，因为它支持接近恒定时间的合并和查找操作。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) 或更糟 | O(n) | 反复模拟重新接线和连接检查 |
 | 最佳| O(n + m) | O(n) | 使用 Union-Find 或 DFS 计算连通分量 |

 这里，`m`代表连接数。 

## 算法演练

 ### 基于并查的算法

 1、首先检查线缆数量是否充足。 

连通图与`n`节点至少需要`n - 1`边缘。 如果`len(connections) < n - 1`，立即返回`-1`。 
2. 初始化并查数据结构。 

每台计算机最初都属于其自己的独立组件。 我们创造：

 - A`parent`数组，其中每个节点都是其自己的父节点
 - A`rank`或者`size`优化联合的数组
 3. 处理每个连接。 

对于每条边`[a, b]`，执行并集运算`a`和`b`。 

如果两台计算机已经属于同一组件，则边缘是多余的。 我们实际上不需要单独存储冗余边缘，因为边缘计数条件已经保证存在足够的备用电缆。 
4. 计算连通分量。 

并查结构中的每个唯一的根代表一个连接的组件。 
5. 计算答案。 

如果有`k`连接的组件，我们正好需要`k - 1`连接它们的操作。 

### 为什么它有效

 每个操作可以恰好连接两个断开连接的组件。 因此，减少`k`组件集成到一个连接的网络中总是需要`k - 1`运营。 

该图表还必须包含足够的电缆总数。 由于连通图与`n`节点至少需要`n - 1`边缘，边缘越少，任务就不可能完成。 

并查找正确地将属于同一连接组件的所有节点分组，因此对组件进行计数可以给出所需合并的确切数量。 

## Python 解决方案```python
from typing import List

class Solution:
    def makeConnected(self, n: int, connections: List[List[int]]) -> int:
        if len(connections) < n - 1:
            return -1

        parent = list(range(n))
        rank = [0] * n

        def find(node: int) -> int:
            if parent[node] != node:
                parent[node] = find(parent[node])
            return parent[node]

        def union(a: int, b: int) -> bool:
            root_a = find(a)
            root_b = find(b)

            if root_a == root_b:
                return False

            if rank[root_a] < rank[root_b]:
                parent[root_a] = root_b
            elif rank[root_a] > rank[root_b]:
                parent[root_b] = root_a
            else:
                parent[root_b] = root_a
                rank[root_a] += 1

            return True

        components = n

        for a, b in connections:
            if union(a, b):
                components -= 1

        return components - 1
```实施从关键的可行性检查开始。 如果连接数小于`n - 1`，函数立即返回`-1`因为连通图不能存在太少的边。 

这`parent`数组存储每个节点的代表父节点。 最初，每个节点都是其自己的父节点，因为每台计算机都作为独立组件启动。 

这`find`函数执行路径压缩。 每当我们搜索节点的根时，我们都会递归地压缩路径，以便将来的查找变得更快。 

这`union`函数合并两个组件。 如果两个节点已经共享相同的根，则边缘是冗余的并且不会发生合并。 否则，按等级并集会使树变浅，从而提高效率。 

变量`components`开始于`n`因为每个节点最初都是断开连接的。 每一次成功的联合都会使组件数量减少一个。 

最后，答案是`components - 1`，表示合并所有剩余断开连接的组所需的操作数。 

## 解决方案```go
func makeConnected(n int, connections [][]int) int {
	if len(connections) < n-1 {
		return -1
	}

	parent := make([]int, n)
	rank := make([]int, n)

	for i := 0; i < n; i++ {
		parent[i] = i
	}

	var find func(int) int

	find = func(node int) int {
		if parent[node] != node {
			parent[node] = find(parent[node])
		}
		return parent[node]
	}

	union := func(a int, b int) bool {
		rootA := find(a)
		rootB := find(b)

		if rootA == rootB {
			return false
		}

		if rank[rootA] < rank[rootB] {
			parent[rootA] = rootB
		} else if rank[rootA] > rank[rootB] {
			parent[rootB] = rootA
		} else {
			parent[rootB] = rootA
			rank[rootA]++
		}

		return true
	}

	components := n

	for _, connection := range connections {
		if union(connection[0], connection[1]) {
			components--
		}
	}

	return components - 1
}
```Go 实现遵循与 Python 版本相同的算法结构。 切片用于`parent`和`rank`数组。 递归路径压缩是使用闭包实现的`find`。 

Go 不像 Python 那样支持嵌套命名函数，因此两者都使用闭包`find`和`union`。 

整数溢出不是问题，因为所有值都保持在 Go 的标准整数范围内。

 ## 边缘情况

 ### 电缆总数不足

 当图形总体上不包含足够的边时，就会出现最重要的边缘情况之一。 连通图与`n`节点必须至少包含`n - 1`边缘。 如果此条件失败，则无论进行多少重新连线都无法使图形连接起来。 

例如：```
n = 6
connections = 4 edges
```即使每条边都完美放置，六个节点也无法形成只有四个边的连通图。 实现立即处理这个问题：```
if len(connections) < n - 1:
    return -1
```这种提前退出避免了不必要的计算。 

### 已连接网络

 另一个重要的情况是图已经完全连接。 在这种情况下，答案应该是`0`因为不需要重新布线操作。 

例如：```
n = 5
connections = [[0,1],[1,2],[2,3],[3,4]]
```并查结构将所有节点合并为一个组件。 由于最终的组件数量变为`1`，算法返回：```
1 - 1 = 0
```### 多个隔离组件

 图表可能包含多个断开连接的组以及孤立的节点。 如果组件计数不正确，这些情况很容易导致错误。 

例如：```
n = 6
connections = [[0,1],[2,3]]
```这里我们有四个组成部分：

 -`{0,1}`-`{2,3}`-`{4}`-`{5}`该算法通过并查根跟踪正确计算所有组件。 由于四个组件需要三次合并，因此算法返回：```
4 - 1 = 3
```前提是有足够的备用电缆。
