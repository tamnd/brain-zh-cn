 **难度：** 🟡 中等
 **主题：** 哈希表、字符串、二分搜索、设计、排序、有序集

 ## 解决方案

 ## 问题理解

 问题是要求我们设计一个系统，该系统可以按时间戳跟踪推文，并允许查询特定时间间隔内的推文数量，并根据频率（分钟、小时或天）进行划分。 具体来说，我们需要实现一个`TweetCounts`具有两个操作的类：记录推文并检索每个频率的推文计数。 

输入包括`tweetName`字符串和时间戳（以秒为单位）。 查询时，我们会得到频率、推文名称以及开始和结束时间。 输出应该是一个整数列表，其中每个整数表示指定频率的一个“时间块”中的推文数量。 时间块是连续的、不重叠的间隔，用于划分给定的时间块`[startTime, endTime]`。 如果总周期没有除以块大小，则最后一个块可能会更短。 

约束告诉我们时间戳可以非常大（`0 <= time <= 10^9`）但查询的周期差异比较小（`0 <= endTime - startTime <= 10^4`）。 对 API 的调用最多为 10^4 次，这意味着效率很重要，但我们不需要处理数百万次极其频繁的操作。 

边缘情况包括查询没有推文的时间段、在同一时间戳记录多条推文以及最后一个块比标准频率短。 

## 方法

 **蛮力方法：**一种简单的方法是将所有推文存储在一个简单的列表中，并在查询时迭代该列表以计算属于每个时间块的推文。 这是正确的，但效率低下。 为了`n`记录的推文和`k`块，这种方法有`O(n * k)`每个查询的时间复杂度，如果存在许多推文，则可能会太慢。 

**最佳方法：** 更有效的方法利用`hash map`存储每个推文名称的时间戳，以**排序顺序**维护时间戳。 查询时，我们可以使用**二分查找**来快速定位到时间戳范围内`[startTime, endTime]`。 然后，我们仅迭代相关的时间戳并按时间块对它们进行计数。 这避免了迭代所有推文，并确保仅处理相关时期的时间戳。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 每个查询 O(n * k) | O(n) | 迭代每个查询的所有推文 |
 | 最佳| 每个查询 O(log n + m) | O(n) | 使用hashmap+排序列表+二分查找；`m`是查询范围内的推文数量 |

 ## 算法演练

 1. 初始化一个`TweetCounts`具有将推文名称映射到时间戳的**排序列表**的字典的对象。 
2. 什么时候`recordTweet`被调用，将时间戳附加到该推文名称的列表中。 按排序顺序插入或查询时延迟排序。 
3. 在`getTweetCountsPerFrequency`，确定`chunkSize`基于`freq`范围 （`minute = 60`,`hour = 3600`,`day = 86400`）。 
4. 使用二分查找查找时间戳列表中最左边和最右边的索引`[startTime, endTime]`。 
5. 初始化一个长度为零的数组，其长度等于块的数量：`(endTime - startTime) // chunkSize + 1`。 
6. 迭代相关时间戳并计算相应的块索引：`(timestamp - startTime) // chunkSize`。 增加该块的计数。 
7. 返回计数数组。 

**为什么有效：** 每个时间戳都使用整数除法精确映射到一个块。 二分搜索确保我们只迭代查询范围内的时间戳，从而保持效率。 排序列表保证块计算是正确的。 

## Python 解决方案```python
from typing import List
from collections import defaultdict
import bisect

class TweetCounts:

    def __init__(self):
        self.tweets = defaultdict(list)

    def recordTweet(self, tweetName: str, time: int) -> None:
        bisect.insort(self.tweets[tweetName], time)

    def getTweetCountsPerFrequency(self, freq: str, tweetName: str, startTime: int, endTime: int) -> List[int]:
        if freq == "minute":
            chunkSize = 60
        elif freq == "hour":
            chunkSize = 3600
        elif freq == "day":
            chunkSize = 86400
        else:
            raise ValueError("Invalid frequency")

        timestamps = self.tweets.get(tweetName, [])
        left = bisect.bisect_left(timestamps, startTime)
        right = bisect.bisect_right(timestamps, endTime)
        relevant_times = timestamps[left:right]

        num_chunks = (endTime - startTime) // chunkSize + 1
        counts = [0] * num_chunks

        for time in relevant_times:
            index = (time - startTime) // chunkSize
            counts[index] += 1

        return counts
```Python 实现使用`defaultdict`存储推文时间戳的列表。`bisect.insort`按排序顺序维护列表，并通过二分搜索`bisect_left`和`bisect_right`有效缩小相关时间戳的范围。 使用整数除法对每个块进行计数非常简单。 

## 解决方案```go
package main

import (
	"sort"
)

type TweetCounts struct {
	tweets map[string][]int
}

func Constructor() TweetCounts {
	return TweetCounts{
		tweets: make(map[string][]int),
	}
}

func (this *TweetCounts) RecordTweet(tweetName string, time int) {
	arr := this.tweets[tweetName]
	i := sort.SearchInts(arr, time)
	arr = append(arr, 0)
	copy(arr[i+1:], arr[i:])
	arr[i] = time
	this.tweets[tweetName] = arr
}

func (this *TweetCounts) GetTweetCountsPerFrequency(freq string, tweetName string, startTime int, endTime int) []int {
	var chunkSize int
	switch freq {
	case "minute":
		chunkSize = 60
	case "hour":
		chunkSize = 3600
	case "day":
		chunkSize = 86400
	default:
		panic("invalid frequency")
	}

	timestamps, ok := this.tweets[tweetName]
	if !ok {
		return []int{}
	}

	left := sort.Search(len(timestamps), func(i int) bool { return timestamps[i] >= startTime })
	right := sort.Search(len(timestamps), func(i int) bool { return timestamps[i] > endTime })

	relevant := timestamps[left:right]
	numChunks := (endTime - startTime)/chunkSize + 1
	counts := make([]int, numChunks)

	for _, t := range relevant {
		index := (t - startTime) / chunkSize
		counts[index]++
	}

	return counts
}
```在 Go 中，我们手动为每条推文维护一个排序切片。`sort.SearchInts`用于插入时间戳和二进制搜索。 切片操作可确保保留排序顺序。 

## 工作示例

 ### 示例 1

 操作：`recordTweet("tweet3", 0)`,`recordTweet("tweet3", 60)`,`recordTweet("tweet3", 10)`,`getTweetCountsPerFrequency("minute","tweet3",0,59)`- 录制后：`tweet3`时间戳：`[0,10,60]`- 查询分钟块`[0,59]`：

 - 块 0：`[0,59]`→ 时间戳`0,10`→ 数2
 - 输出：`[2]`### 示例 2

 查询：`getTweetCountsPerFrequency("minute","tweet3",0,60)`- 块：`[0,59]`和`[60,60]`- 相关时间戳：`[0,10,60]`- 块映射：

 - 0 → 0//60 = 0
 - 10 → 10//60 = 0
 - 60 → 60//60 = 1
 - 计数：`[2,1]`### 示例 3

 查询：`getTweetCountsPerFrequency("hour","tweet3",0,210)`后`recordTweet("tweet3",120)`- 时间戳：`[0,10,60,120]`- 块：`[0,210]`（单个块）
 - 数量：4

 ## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间（记录推文）| O(n) | 使用 bisect/shift 插入排序列表的成本为 O(n) |
 | 时间 (getTweetCountsPerFrequency) | O(log n + m) | 二分查找 O(log n) + 迭代范围内的 m 个时间戳 |
 | 空间| O(n) | 存储所有推文的所有时间戳 |

 效率的提高来自于将迭代限制为每个查询的相关时间戳，并且二分搜索减少了不必要的扫描。
