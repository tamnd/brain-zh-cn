[LeetCode 第 1388 题](https://leetcode.com/problems/pizza-with-3n-slices/)

 **难度：** 🔴难
 **主题：** 数组、动态规划、贪婪、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 在这个问题中，我们给出了一个圆形披萨，分为`3n`切片。 每个切片都有一个由数组表示的大小`slices`，其中值按顺时针顺序列出。 

您重复执行以下过程：

 1. 您选择任何剩余的切片。 
2. Alice 立即从您选择的切片中逆时针直接取出切片。 
3. Bob 立即从您选择的切片中顺时针直接取出切片。 

这一直持续到没有切片为止。 

因为每一轮都会去除三片，而披萨最初包含`3n`切片，你最终会选择准确的`n`切片。 

目标是最大化您个人挑选的切片的总大小。 

最重要的观察是，每当您选择一个切片时，它的两个相邻切片就会变得不可用。 这意味着您选择的切片永远不能相邻。 由于披萨是圆形的，所以第一片和最后一片也是相邻的。 

那么问题就变成了：

 > 准确选择`n`来自长度循环数组的不相邻切片`3n`使得它们的总和最大化。 

约束条件很重要：

 -`slices.length <= 500`- 每个切片值最多为`1000`对所有组合进行强力搜索会太慢，因为可能的选择数量呈指数级增长。 相对较小的输入大小表明需要动态规划解决方案。 

有几种边缘情况很容易破坏简单的实现：

 - 由于披萨是圆形的，选择第一片可以防止选择最后一片。 
- 我们必须准确选择`n`切片，不能少。 
- 贪婪选择不起作用，因为大切片可能会阻止附近多个有价值的选择。 
- 具有重复值的数组可以创建许多看起来等效的选择，但仍然需要仔细优化。 

该问题保证：

 - 数组长度始终能被 3 整除。 
- 每个切片大小都是正值。 
- 总是至少有一个有效的解决方案。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试切片的每个可能的子集并检查是否：

 1. 完全正确`n`选择切片。 
2. 没有两个选定的切片在圆形排列中相邻。 

对于每个有效子集，我们计算总和并保留最大值。 

这种方法是正确的，因为它明确地检查每个可能的有效选择。 然而，这在计算上是不可行的。 

如果数组包含`m = 3n`元素，则有`2^m`子集。 和`m = 500`，这变得天文数字般大。 

即使进行了修剪，搜索空间仍然呈指数级增长。 

### 最优动态规划方法

 关键的见解是这个问题本质上是经典问题的变体：

 > 圆形数组中不相邻元素的最大和`k`选择。 

圆形邻接是主要的并发症。 在线性数组中，动态编程很简单，因为只有相邻索引很重要。 

为了处理循环结构，我们将问题分成两个独立的线性情况：

 1. 排除第一个切片。 
2. 排除最后一个切片。 

为什么这有效？ 

在圆形数组中，不能同时选择第一个和最后一个元素。 因此，每个有效的解决方案都必须属于以下两个类别之一：

 - 不使用第一个切片的解决方案。 
- 不使用最后一个切片的解决方案。 

对于每个线性情况，我们求解：

 > 准确挑选`n`总和最大的非相邻元素。 

我们在以下情况下使用动态规划：

 -`dp[i][j]`表示使用第一个可获得的最大总和`i`精确选择元素`j`切片。 

对于每个职位，我们可以：

 - 跳过当前切片。 
- 获取当前切片，这迫使我们跳过前一个切片。 

这产生了有效的多项式时间解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(2^(3n)) | O(2^(3n)) | O(3n) | O(3n) | 尝试每个可能的子集 |
 | 最佳 | O(n^2) | O(n^2) | O(n^2) | O(n^2) | 两种线性情况下的动态规划 |

 ## 算法演练

 ### 第 1 步：确定我们必须挑选多少片

 如果披萨中含有`3n`切片，那么我们最终将准确选择：```
k = len(slices) // 3
```该值在整个问题中都是固定的。 

### 步骤 2：将循环问题转换为两个线性问题

 因为披萨是圆形的，所以第一片和最后一片是相邻的。 

我们不能同时选择两者。 

所以我们解决两个不同的情况：

 1.使用索引中的切片`0`到`n-2`2. 使用索引中的切片`1`到`n-1`然后我们取最大的结果。 

这保证了每个有效的解决方案都被考虑一次。 

### 步骤 3：定义 DP 状态

 对于线性阵列`arr`， 定义：```
dp[i][j]
```如：

 > 使用第一个可获得的最大总和`i`精确选择元素`j`不相邻的切片。 

尺寸为：

 -`i`范围从`0`到`len(arr)`-`j`范围从`0`到`k`### 步骤 4：状态之间的转换

 在每个位置，我们都有两种选择。 

#### 选项 1：跳过当前切片

 如果我们不获取当前切片：```
dp[i][j] = dp[i-1][j]
```#### 选项 2：获取当前切片

 如果我们获取当前切片：

 - 我们增加它的价值。 
- 我们必须跳过上一个切片。 

所以：```
dp[i][j] = dp[i-2][j-1] + arr[i-1]
```我们采取这两个选择中的最大值。 

### 步骤 5：填写 DP 表

 我们迭代所有索引和所有可能的选择计数。 

必须注意边界情况，其中`i < 2`。 

### 第 6 步：解决两种情况

 计算：

 - 不包括最后一片的最佳结果
 - 不包括第一片的最佳结果

 返回较大的值。 

### 为什么它有效

 动态规划递归保证了最优性，因为位置的每个有效解决方案`i`必须包含当前切片或排除它。 

如果我们包含它，邻接规则会迫使我们跳过前一个切片，将问题简化为以`i-2`。 

如果我们排除它，问题就会简化为以`i-1`。 

由于循环约束仅影响第一个切片和最后一个切片之间的关系，因此分成两个线性情况可以完全捕获所有有效的可能性。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxSizeSlices(self, slices: List[int]) -> int:
        choose = len(slices) // 3

        def solve(arr: List[int]) -> int:
            n = len(arr)

            dp = [[0] * (choose + 1) for _ in range(n + 1)]

            for i in range(1, n + 1):
                for j in range(1, choose + 1):
                    # Skip current slice
                    dp[i][j] = dp[i - 1][j]

                    # Take current slice
                    current = arr[i - 1]

                    if i >= 2:
                        dp[i][j] = max(
                            dp[i][j],
                            dp[i - 2][j - 1] + current
                        )
                    else:
                        dp[i][j] = max(
                            dp[i][j],
                            current
                        )

            return dp[n][choose]

        # Case 1: exclude last slice
        case1 = solve(slices[:-1])

        # Case 2: exclude first slice
        case2 = solve(slices[1:])

        return max(case1, case2)
```实现首先计算我们必须选择多少个切片。 由于披萨中含有`3n`切片，我们必须准确选择`n`切片。 

辅助函数`solve()`处理问题的线性版本。 它接收一个普通数组，其中第一个和最后一个元素不再相邻。 

DP 表存储每个前缀长度和每个可能的所选切片数量的最佳可能总和。 

对于每个位置：

 - 我们首先假设我们跳过当前切片。 
- 那么我们考虑接受它。 

如果我们获取当前切片，则必须向后移动两个位置，因为相邻切片不能同时被选择。 

最后我们分别解决两种循环情况：

 - 不包括最后一片
 - 排除第一片

 这两个结果中的最大值就是最终答案。 

## 解决方案```go
func maxSizeSlices(slices []int) int {
	choose := len(slices) / 3

	max := func(a, b int) int {
		if a > b {
			return a
		}
		return b
	}

	solve := func(arr []int) int {
		n := len(arr)

		dp := make([][]int, n+1)
		for i := range dp {
			dp[i] = make([]int, choose+1)
		}

		for i := 1; i <= n; i++ {
			for j := 1; j <= choose; j++ {
				// Skip current slice
				dp[i][j] = dp[i-1][j]

				// Take current slice
				current := arr[i-1]

				if i >= 2 {
					dp[i][j] = max(
						dp[i][j],
						dp[i-2][j-1]+current,
					)
				} else {
					dp[i][j] = max(
						dp[i][j],
						current,
					)
				}
			}
		}

		return dp[n][choose]
	}

	case1 := solve(slices[:len(slices)-1])
	case2 := solve(slices[1:])

	return max(case1, case2)
}
```Go 实现遵循与 Python 版本相同的逻辑。 

主要区别在于显式切片和内存管理。 DP 表是使用嵌套切片创建的。 

Go 没有提供内置的`max`函数用于整数，因此手动定义辅助函数。 

由于所有值都很小，并且最大可能总和正好在 32 位整数范围内，因此标准`int`算术就足够了。

 ## 边缘情况

 当数组仅包含三个切片时，会出现一种重要的边缘情况。 在这种情况下，我们可以只选择一个切片。 因为披萨是圆形的，所以每一片都与另外两片相邻，所以答案就是最大元素。 实现通过 DP 转换自然地处理这个问题。 

当最佳解决方案包括靠近数组两端的切片时，会出现另一个棘手的情况。 由于披萨是圆形的，所以第一片和最后一片不能同时选择。 一个幼稚的线性 DP 会错误地允许这种情况。 该实现通过将问题分为两个单独的线性情况来避免这种情况，一个不包括第一个切片，一个不包括最后一个。 

包含许多相等值的数组也可能导致贪婪方法中的微妙错误。 例如，过早选择局部较大的值可能会不必要地阻止未来的选择。 动态规划正确评估所有可能性并保证全局最优答案。 

最后一个重要的边缘情况涉及非常大的切片值。 由于值可能达到`1000`数组长度可以是`500`，该实现必须安全地处理总计大约`500000`。 Python 整数和 Go 整数都可以轻松支持此范围，而不会出现溢出问题。
