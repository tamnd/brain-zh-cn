 **难度：** 🟡 中等
 **主题：** 数组、动态规划、二叉索引树、线段树

 ## 解决方案

 ## 问题理解

 该问题要求我们计算一行中由三名士兵组成的有效队伍的数量`n`士兵，每个士兵都有独特的评级。 一个有效的团队由三个指标组成`(i, j, k)`使得收视率严格增加（`rating[i] < rating[j] < rating[k]`) 或严格递减 (`rating[i] > rating[j] > rating[k]`） 和`0 <= i < j < k < n`。 

输入是代表士兵等级的整数列表。 输出是一个表示有效团队数量的整数。 限制表明士兵数量`n`最多可达 1000，每个评级在 1 到 100,000 之间都是唯一的。 

主要观察结果包括评级的独特性简化了比较，并且评级的规模适中`n`允许二次算法。 边缘情况包括最小的输入（`n=3`）、已排序的序列（全部递增或递减）以及不允许有效团队的序列。 

## 方法

 **暴力方法**很简单：生成所有可能的三元组`(i, j, k)`并计算那些满足递增或递减条件的数。 这保证了正确性，因为它会检查每个组合。 然而，它具有立方时间复杂度（`O(n^3)`）这对于`n = 1000`因为它会导致多达 10 亿次迭代。 

**最佳方法**使用我们可以将每个士兵视为三元组的中间成员的见解`(i, j, k)`。 对于每个`rating[j]`，我们计算其左侧有多少个较小和较大的评级（`i < j`）及其右侧（`k > j`）。 队伍数量不断增加`rating[j]`中间是左侧较小评级和右侧较大评级的乘积。 同样，减少的球队数量是左侧评分较大和右侧评分较小的乘积。 为大家总结一下`j`产生有效团队的总数。 这将复杂性降低到`O(n^2)`和`O(1)`额外的空间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n^3) | O(n^3) | O(1) | O(1) | 检查所有三元组`(i, j, k)`|
 | 最佳 | O(n^2) | O(n^2) | O(1) | O(1) | 计算每个中间元素向左/向右的较小/较大元素 |

 ## 算法演练

 1. 初始化变量`count`存储有效团队的数量。 
2. 迭代每个士兵索引`j`从`0`到`n-1`将其视为三元组的中间元素。 
3.对于当前`rating[j]`，初始化四个计数器：`left_smaller`,`left_larger`,`right_smaller`， 和`right_larger`。 
4. 循环所有索引`i`少于`j`数数`left_smaller`（评分低于`rating[j]`） 和`left_larger`（评级大于`rating[j]`）。 
5. 循环所有索引`k`大于`j`数数`right_smaller`（评分低于`rating[j]`） 和`right_larger`（评级大于`rating[j]`）。 
6. 计算有效团队的数量`rating[j]`作为中间：

 - 增加：`left_smaller * right_larger`- 减少：`left_larger * right_smaller`7. 将两者添加到`count`。 
8.所有迭代结束后，返回`count`。 

**为什么有效**：每个有效的三元组都有一个中间元素。 通过计算每个中间元素可能的左右候选者，我们可以有效地枚举所有有效的团队，而无需进行冗余检查。 

## Python 解决方案```python
from typing import List

class Solution:
    def numTeams(self, rating: List[int]) -> int:
        n = len(rating)
        count = 0
        
        for j in range(n):
            left_smaller = left_larger = right_smaller = right_larger = 0
            
            for i in range(j):
                if rating[i] < rating[j]:
                    left_smaller += 1
                elif rating[i] > rating[j]:
                    left_larger += 1
            
            for k in range(j+1, n):
                if rating[k] < rating[j]:
                    right_smaller += 1
                elif rating[k] > rating[j]:
                    right_larger += 1
            
            count += left_smaller * right_larger + left_larger * right_smaller
        
        return count
```实现按照算法一步步进行。 对于被视为三元组中间的每个元素，它会计算左侧和右侧有多少个较小和较大的元素。 有效团队总数是使用适当计数的乘积来计算的。 不需要额外的数据结构。 

## 解决方案```go
func numTeams(rating []int) int {
    n := len(rating)
    count := 0
    
    for j := 0; j < n; j++ {
        leftSmaller, leftLarger, rightSmaller, rightLarger := 0, 0, 0, 0
        
        for i := 0; i < j; i++ {
            if rating[i] < rating[j] {
                leftSmaller++
            } else if rating[i] > rating[j] {
                leftLarger++
            }
        }
        
        for k := j + 1; k < n; k++ {
            if rating[k] < rating[j] {
                rightSmaller++
            } else if rating[k] > rating[j] {
                rightLarger++
            }
        }
        
        count += leftSmaller*rightLarger + leftLarger*rightSmaller
    }
    
    return count
}
```Go 实现反映了 Python 解决方案。 主要区别在于语法：显式变量声明和切片索引。 由于 Go 没有`List`或者`len()`像Python这样的方法，我们使用`len(rating)`和标准整数算术。 考虑到限制，溢出不是问题。
