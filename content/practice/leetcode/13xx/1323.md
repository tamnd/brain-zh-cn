[LeetCode 第 1323 题](https://leetcode.com/problems/maximum-69-number/)

 **难度：** 🟢简单
 **主题：** 数学、贪心

 ## 解决方案

 ## 问题理解

 问题给了我们一个正整数`num`仅包含数字`6`和`9`。 我们可以更改**最多一位数字**，其中`6`可以成为一个`9`，或一个`9`可以成为一个`6`。 我们的目标是在进行零次或一次修改后返回**可能的最大数字**。 

简单来说，我们希望通过策略性地选择是否翻转一位数字来最大化数字。 由于数字仅限于`6`和`9`，决定变得很简单：改变`6`进入一个`9`增加值，同时改变`9`进入一个`6`减少它。 因此，任何有用的改变都必须涉及转换`6`进入一个`9`。 

数字的位置很重要，因为数字是有位置的。 靠近前面的数字比靠近末尾的数字对总值的贡献更大。 例如，更改最左边的`6`在`9669`增加千位，这比更改后面的数字具有更大的影响。 

限制非常小：

 -`1 <= num <= 10^4`-`num`仅包含数字`6`和`9`这告诉我们该数字最多有 5 位数字，因此即使是低效的解决方案也能在限制范围内发挥作用。 然而，访谈和算法设置的目标是确定最优雅和最佳的方法。 

有几个重要的边缘情况需要考虑：

 - 该数字可能已经完全包含`9`s，例如`9999`。 在这种情况下，任何更改都会减少数量，因此正确的答案是不进行更改。 
- 该号码只能包含一位数字，例如`6`或者`9`。 
- 多种的`6`s 可能存在，但只能更改一位数字。 由于前面的数字更重要，因此更改**第一个`6`从左边开始**始终是最佳选择。 
- 问题保证输入仅包含`6`和`9`，所以我们不需要对其他数字进行额外的验证。 

## 方法

 ### 蛮力方法

 强力解决方案会尝试一次更改每个数字并计算结果数字。 对于每个位置，我们将翻转数字（`6 ↔ 9`）并记录获得的最大值。 

例如，与`9669`，我们可以生成：

 - 改变索引`0`:`6669`- 改变索引`1`:`9969`- 改变索引`2`:`9699`- 改变索引`3`:`9666`我们也会考虑不做任何改变。 所有可能性中最大的值就是答案。 

这种方法是正确的，因为它详尽地检查了每个有效的修改。 然而，它执行了不必要的工作，因为我们可以通过数学方式推断哪种修改是最好的。 

### 最优贪心法

 关键的见解是改变`6`到一个`9`总是增加数字，同时改变`9`到一个`6`总是减少它。 因此，我们永远不应该改变`9`。 

下一个观察结果是，由于位值的原因，前面的数字比后面的数字更重要。 千位的变化比十位的变化更有价值。 

这意味着最好的策略很简单：

 1. 从左到右扫描号码。 
2. 找到**第一个`6`**。 
3. 将其更改为`9`。 
4. 立即返回结果。 

如果没有`6`存在，数量已经是最大的。 

这是一种贪婪策略，因为我们做出局部最佳选择，改变最重要的`6`，并且该决策保证了全局最优结果。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(d²) | O(d) | 尝试翻转每个数字并计算最大结果 |
 | 最佳 | O(d) | O(d) | 改变第一个`6`到`9`并停止|

 这里，`d`表示中的位数`num`。 

## 算法演练

 ### 最优贪心算法

 1. 将整数转换为字符串或字符列表，以便可以轻松修改各个数字。 由于整数在数字级别是不可变的，因此使用字符串可以简化操作。 
2. 从左到右遍历数字。 我们沿着这个方向扫描，因为前面的数字对整体数值的贡献更大。 
3. 检查当前数字是否为`6`。 第一个`6`遇到的是最有价值修改的位置。 
4. 如果`6`找到，替换为`9`。 由于只允许更改一项，因此请立即停止搜索。 
5. 将修改后的数字序列转换回整数并返回。 
6. 如果没有`6`扫描完成后存在，则返回原始数字不变，因为它已经是最大可能值。 

### 为什么它有效

 正确性取决于位置值。 改变一个`6`到一个`9`将数字增加与其位值成比例的量。 一个`6`处于较重要地位的人的贡献多于处于较不重要地位的人的贡献。 因此，修改**最左边`6`** 产生最大可能的增长。 自从改变任何`9`减少数量，并且只允许改变一次，这种贪婪的选择总是最优的。 

## Python 解决方案```python
class Solution:
    def maximum69Number(self, num: int) -> int:
        digits = list(str(num))

        for index in range(len(digits)):
            if digits[index] == "6":
                digits[index] = "9"
                break

        return int("".join(digits))
```实现首先将整数转换为字符列表。 这允许我们直接修改数字，因为字符串在 Python 中是不可变的。 

然后我们从左到右迭代数字。 当我们遇到第一个`6`，我们将其替换为`9`并立即停止循环使用`break`。 提前停止很重要，因为只允许进行一次修改，并且第一个修改`6`给出最大增益。 

最后，我们将修改后的数字重新连接回字符串，并将其转换为整数，然后返回结果。 

## 解决方案```go
func maximum69Number(num int) int {
	digits := []byte(fmt.Sprintf("%d", num))

	for i := 0; i < len(digits); i++ {
		if digits[i] == '6' {
			digits[i] = '9'
			break
		}
	}

	result := 0
	for _, digit := range digits {
		result = result*10 + int(digit-'0')
	}

	return result
}
```Go 实现遵循与 Python 解决方案相同的贪婪逻辑。 由于 Go 字符串是不可变的，因此我们将数字转换为字节切片以进行就地修改。 

一个实现细节是 Go 需要显式整数重构。 修改数字后，我们通过迭代字节切片并应用以 10 为基数的累加来手动重建整数。 

与Python不同的是，这里不需要担心整数溢出，因为最大输入仅为`10^4`。

 ## 边缘情况

 一种重要的边缘情况是当数字已经仅包含`9`s，例如`9999`。 粗心的实现可能总是会强制数字翻转并意外地将值减小到更小的值。 我们的实现正确地处理了这个问题，因为它只在找到一个数字时才修改一个数字`6`。 如果不存在，则原样返回原始号码。 

另一个重要的情况是单位数字输入，例如`6`或者`9`。 由于只有一位数字，因此算法在不依赖多次迭代的情况下仍必须正确运行。 为了`6`，则直接变为`9`。 为了`9`，不做任何改变。 

当多个`6`s 存在，例如`6666`。 一个幼稚的实现可能会尝试改变所有`6`或选择错误的一个。 我们的贪婪逻辑正确地只改变了**第一个**`6`，因为它具有最高的位置价值并产生最大可能的增长。 

最后，考虑以下情况：`6`出现在接近尾声的地方，例如`9996`。 该算法扫描所有领先的`9`s 并最终更新最后一位数字。 这证实了该解决方案可以正确处理早期和后期修改。
