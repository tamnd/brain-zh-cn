[LeetCode 1311 题](https://leetcode.com/problems/get-watched-videos-by-your-friends/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、广度优先搜索、图论、排序

 ## 解决方案

 ## 问题理解

 该问题将社交网络建模为无向图。 每个人都由一个整数 ID 表示`0`到`n - 1`。 这`friends`数组描述了图形连接，而`watchedVideos[i]`包含人员观看的视频列表`i`。 

目标是找到与起始人恰好有一定友谊距离的人观看的所有视频。 

友谊距离是使用图中的最短路径定义的：

 - 距离`1`意思是直接朋友
 - 距离`2`意思是朋友的朋友
 - 距离`k`表示从起始人开始的最短路径恰好是的所有人`k`在识别出目标级别的所有人员后，我们收集他们观看的每个视频并计算频率。 最终结果必须排序：

 1. 按频率升序排列
 2. 如果频率相等，则按字母升序排列

 该图保证是无向的，因为如果`friends[i]`包含`j`， 然后`friends[j]`还包含`i`。 

限制相对较小：

 -`n <= 100`- 每个人最多可以观看`100`视频

 这些限制强烈表明，诸如广度优先搜索之类的图遍历解决方案是合适且足够高效的。 

一些边缘情况很重要：

 - 同一级别多人可以观看同一个视频
 - 频率相同的视频必须按字母顺序排序
 - 友谊图中存在循环，因此必须防止重新访问节点
 - 只有达到确切目标级别的人才能贡献视频
 - 除非可以通过更长的路径再次到达，否则永远不应该计算起始人员，而 BFS 通过访问跟踪自然会阻止这种情况

 ## 方法

 ### 蛮力方法

 强力解决方案将尝试单独计算起始者与其他每个人之间的距离。 

一种可能的方法是：

 1. 对于图中的每个人：

 - 运行搜索以确定最短距离`id`2. 收集距离相等的人`level`3.统计他们观看的所有视频
 4.根据问题规则对结果进行排序

 这种方法是正确的，因为最短路径计算保证我们准确地识别所需的友谊级别。 

然而，它的效率很低，因为我们重复遍历每个人的图。 如果我们从源为每个目标节点单独运行 BFS，工作就会变得不必要的重复。 

由于该图是未加权的，因此来自起始节点的单个 BFS 已经同时计算到所有节点的最短距离。 

### 最佳方法

 关键的观察结果是，广度优先搜索自然地逐层探索未加权的图。 

当BFS从给定开始时`id`:

 - 第一个 BFS 层包含远处的所有节点`1`- 第二个 BFS 层包含远处的所有节点`2`- 等等

 因此，恰好经过`level`BFS扩展后，队列中恰好包含最短路径距离等于目标级别的人。 

一旦这些人被识别出来：

 1. 使用哈希图统计他们观看的视频
 2. 视频排序依据：

 - 频率上升
 - 字典顺序升序

 这避免了重复的最短路径计算，并在一次遍历中有效地处理图。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n × (n + e)) | O(n × (n + e)) | O(n) | 对多个节点重复运行图遍历 |
 | 最佳| O(n + e + v log v) | O(n + e + v log v) | O(n + v) | 单次BFS遍历，然后对唯一的视频进行排序 |

 这里：

-`n`= 人数
 -`e`= 友谊边的数量
 -`v`= 在目标级别收集的唯一视频数量

 ## 算法演练

 1. 初始化一个BFS队列，并放置起始人`id`在里面。 

BFS 是理想的，因为它按照最短路径距离的递增顺序探索节点。 
2. 维持`visited`放。 

由于友谊图可能包含循环，因此我们必须避免重复回访。 
3.逐级进行BFS，直至达到目标距离。 

对于每个 BFS 层：

 - 处理当前队列中的所有节点
 - 将未访问过的朋友添加到队列中
 - 将新发现的朋友标记为已访问

 处理完一层后，队列中的所有节点都属于下一个友谊级别。 
4. 正好之后`level`扩展后，队列包含所有处于所需距离的人。 

这些是唯一应该计算观看视频的人。 
5. 创建视频频率图。 

遍历队列中剩余的每个人：

 - 对于每个观看的视频：

 - 增加其在哈希图中的计数
 6. 对视频进行排序。 

排序标准是：

 - 首先降低频率
 - 当频率相同时，按字母顺序排列较小的名称

 在 Python 中，这可以通过以下方式完成：```
sorted(freq.keys(), key=lambda x: (freq[x], x))
```7. 返回排序后的视频名称列表。 

### 为什么它有效

 广度优先搜索保证按照距起始节点的最短路径距离的递增顺序来探索节点。 因此，经过精确处理后`level`BFS层，队列中剩余的节点正是距离最近的人`id`等于`level`。 

由于我们仅对这些人的视频进行计数，然后根据所需的规则进行排序，因此算法始终会产生正确的输出。 

## Python 解决方案```python
from collections import deque, defaultdict
from typing import List

class Solution:
    def watchedVideosByFriends(
        self,
        watchedVideos: List[List[str]],
        friends: List[List[int]],
        id: int,
        level: int
    ) -> List[str]:

        queue = deque([id])
        visited = set([id])

        current_level = 0

        while queue and current_level < level:
            level_size = len(queue)

            for _ in range(level_size):
                person = queue.popleft()

                for friend in friends[person]:
                    if friend not in visited:
                        visited.add(friend)
                        queue.append(friend)

            current_level += 1

        frequency = defaultdict(int)

        for person in queue:
            for video in watchedVideos[person]:
                frequency[video] += 1

        return sorted(frequency.keys(), key=lambda video: (frequency[video], video))
```The implementation begins by initializing a BFS queue with the starting person. 一个`visited`set 可以防止重访人员并陷入图表循环中。 

BFS 循环一直运行，直到达到所需的友谊级别。 每次迭代只处理一个 BFS 层。 这是使用完成的`level_size`，它捕获有多少个节点属于当前距离级别。 

一旦 BFS 完成，队列中就只包含目标级别的人员。 他们观看的视频是使用`defaultdict(int)`频率图。 

最后，使用问题所需的顺序对结果进行排序。 元组`(frequency[video], video)`确保频率优先，而字母顺序则解决了联系问题。 

## 解决方案```go
package main

import (
	"sort"
)

func watchedVideosByFriends(
	watchedVideos [][]string,
	friends [][]int,
	id int,
	level int,
) []string {

	queue := []int{id}
	visited := make(map[int]bool)
	visited[id] = true

	currentLevel := 0

	for len(queue) > 0 && currentLevel < level {
		levelSize := len(queue)
		nextQueue := []int{}

		for i := 0; i < levelSize; i++ {
			person := queue[i]

			for _, friend := range friends[person] {
				if !visited[friend] {
					visited[friend] = true
					nextQueue = append(nextQueue, friend)
				}
			}
		}

		queue = nextQueue
		currentLevel++
	}

	frequency := make(map[string]int)

	for _, person := range queue {
		for _, video := range watchedVideos[person] {
			frequency[video]++
		}
	}

	result := []string{}

	for video := range frequency {
		result = append(result, video)
	}

	sort.Slice(result, func(i, j int) bool {
		if frequency[result[i]] == frequency[result[j]] {
			return result[i] < result[j]
		}
		return frequency[result[i]] < frequency[result[j]]
	})

	return result
}
```Go 解决方案遵循与 Python 版本相同的 BFS 策略。 

一个显着的区别是队列管理。 该实现没有使用专用的双端队列结构，而是创建了一个`nextQueue`下一个 BFS 层的切片。 

频率图使用`map[string]int`，它会自动将缺失的键默认为`0`。 

排序是使用处理的`sort.Slice`，其中比较器实现所需的两级排序：

 1. 频率上升
 2. 按字母升序排列

 Go 切片自然地代表动态数组，使其适用于 BFS 队列和最终结果列表。

 ## 边缘情况

 当友谊图包含循环时，就会出现一种重要的边缘情况。 没有一个`visited`设置后，BFS 可能会重复访问同一个人，并可能进入无限循环。 该实现通过在发现时立即将每个人标记为已访问来避免这种情况。 

另一个微妙的情况涉及具有相同频率的视频。 该问题需要在计数平局时按字母顺序排序。 仅按频率排序的简单实现会失败这些情况。 该解决方案使用元组显式排序`(frequency, video_name)`以保证正确的二次排序。 

当同一个人存在多个友谊路径时，就会发生第三个重要的边缘情况。 由于该问题使用最短路径距离定义级别，因此人应该仅出现在距起始节点的最小距离处。 BFS 自然地保证了这一特性，因为节点首先是在尽可能短的距离处发现的，并且访问集可以防止以后通过更长的路径重新发现。
