[LeetCode 第 1376 题](https://leetcode.com/problems/time-needed-to-inform-all-employees/)

 **难度：** 🟡 中等
 **主题：** 树、深度优先搜索、广度优先搜索

 ## 解决方案

 ## 问题理解

 该问题要求我们计算一条紧急信息从公司负责人开始在公司层次结构中传播所需的总时间。 每个员工都有一名直接经理，形成了以公司领导为根基的树形结构。 这`manager`数组指定每个员工的直接经理，其中`manager[headID] = -1`表示根。 每个员工还有一个相关的`informTime`代表该员工通知其所有直接下属需要多长时间。 

输入包括：`n`，员工人数；`headID`，公司负责人的唯一ID；`manager`，一个数组，其中`manager[i]`是员工的直接经理`i`; 和`informTime`，一个数组，其中`informTime[i]`是时间雇员`i`需要通知他们的下属。 输出是一个整数，表示消息到达所有员工的总时间。 

约束表明`n`可以达到`10^5`，这排除了过度遍历每个节点的低效解决方案。 这`informTime`如果员工没有下属，则可以为零。 输入保证所有员工都可以从头部到达，因此我们不需要处理断开连接的节点。 重要的边缘情况包括单个员工（`n = 1`）或所有员工的零`informTime`。 

## 方法

 蛮力方法将从头部开始递归或迭代地模拟传播。 对于每个员工，我们都会添加该员工的`informTime`到达下属的总时间。 这可以正常工作，但如果实施不当，可能会效率低下，因为如果在没有缓存或适当的树遍历的情况下多次遍历节点，则可能会发生重复计算。 

最佳方法利用树结构。 首先，建立一个将每个经理映射到其直接下属的邻接列表。 然后，从头开始执行深度优先搜索（DFS）或广度优先搜索（BFS），累积到达每个节点的时间。 DFS 特别方便，因为从根到叶的最长路径决定了总通知时间。 也可以使用 BFS，维护一个队列`(employeeID, accumulatedTime)`对。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n^2) | O(n^2) | O(n) | 无需预先计算下级的递归传播可以多次重新访问节点。 |
 | 最佳 | O(n) | O(n) | 构建邻接表并进行DFS/BFS传播时间； 每个节点访问一次。 |

 ## 算法演练

 1. 创建一个空的邻接表`tree`将每个经理与其直接下属进行映射。 
2. 迭代`manager`大批。 对于每位员工`i`， 如果`manager[i] != -1`, 附加`i`到`tree[manager[i]]`。 
3.定义DFS函数`dfs(employeeID)`返回通知所有下属所需的总时间`employeeID`。 
4. 对于每个下属`tree[employeeID]`,递归调用`dfs(subordinate)`并记录最长返回时间。 
5.返回当前员工的总和`informTime[employeeID]`以及下属之间的最大时间。 
6. 打电话`dfs(headID)`计算通知所有员工所需的总时间。 

为什么它有效：这是有效的，因为总时间是由从头部到任何叶子员工的最长路径决定的。 DFS 确保评估所有路径，并通过在每一步取最大值，我们捕获信息传播的关键路径。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def numOfMinutes(self, n: int, headID: int, manager: List[int], informTime: List[int]) -> int:
        tree = defaultdict(list)
        for employeeID, mgr in enumerate(manager):
            if mgr != -1:
                tree[mgr].append(employeeID)
        
        def dfs(empID: int) -> int:
            if empID not in tree:
                return 0
            max_sub_time = 0
            for sub in tree[empID]:
                max_sub_time = max(max_sub_time, dfs(sub))
            return informTime[empID] + max_sub_time
        
        return dfs(headID)
```这个Python解决方案首先构建一个`tree`每个经理都映射到他们的直接下属列表的字典。 这`dfs`函数递归计算通知所有下属所需的最长时间。 对于叶子员工来说，`dfs`返回 0，有效处理基本情况。 然后，该解决方案返回从`headID`。 

## 解决方案```go
package main

func numOfMinutes(n int, headID int, manager []int, informTime []int) int {
    tree := make(map[int][]int)
    for empID, mgr := range manager {
        if mgr != -1 {
            tree[mgr] = append(tree[mgr], empID)
        }
    }
    
    var dfs func(int) int
    dfs = func(empID int) int {
        maxSubTime := 0
        for _, sub := range tree[empID] {
            if subTime := dfs(sub); subTime > maxSubTime {
                maxSubTime = subTime
            }
        }
        return informTime[empID] + maxSubTime
    }
    
    return dfs(headID)
}
```在 Go 中，我们使用`map[int][]int`来表示邻接表。 递归`dfs`函数计算下属之间的最大时间，类似于Python版本。 该实现避免了显式的 nil 检查，因为`range`在 Go 中，超过一个空切片是安全的。 

## 工作示例

 **示例1：**```
n = 1, headID = 0, manager = [-1], informTime = [0]
```首领没有下属。 DFS 立即返回 0。 输出为0。 

**示例2：**```
n = 6, headID = 2, manager = [2,2,-1,2,2,2], informTime = [0,0,1,0,0,0]
```邻接表是`{2: [0,1,3,4,5]}`。 head 2 的 DFS 计算 DFS(0)、DFS(1)、DFS(3)、DFS(4)、DFS(5) 中的最大值，所有这些都返回 0。加上 informTime[2] = 1，总数为 1。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 在 DFS 期间，每个员工都会被拜访一次。 |
 | 空间| O(n) | 邻接表和递归栈各自最多可以存储n个元素。 |

 因为每个员工只处理一次，并且我们只存储树结构和递归堆栈，所以该解决方案对于大型`n`最多 10^5。

 ## 边缘情况

 一种边缘情况是当`n = 1`。 该解决方案必须正确返回 0，而不尝试任何递归调用或超出主管员工的访问。 当一些员工有`informTime = 0`，代表叶子。 DFS 基本情况确保这些节点返回 0。第三种边缘情况是深度嵌套的层次结构，例如单条长度链`n`，这可能会强调递归深度。 Python 和 Go 解决方案都处理这个问题，因为递归堆栈随深度线性增长，这在典型的堆栈限制内是可以接受的`n ≤ 10^5`。
