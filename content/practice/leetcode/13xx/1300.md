[LeetCode 第 1300 题](https://leetcode.com/problems/sum-of-mutated-array-closest-to-target/)

 **难度：** 🟡 中等
 **主题：** 数组、二分查找、排序

 ## 解决方案

 ## 问题理解

 问题给了我们一个整数数组`arr`和一个整数`target`。 我们可以选择一个值`x`，然后修改数组，使每个元素都大于`x`恰好变成`x`。 较小的元素保持不变。 

在此突变之后，我们计算修改后的数组的总和。 我们的目标是找到整数`x`这使得这个总和尽可能接近`target`。 

如果两个不同的值与目标产生相同的绝对差，我们必须返回较小的值。 

例如，如果：```
arr = [4,9,3]
target = 10
```我们选择`x = 3`， 然后：```
[4,9,3] -> [3,3,3]
sum = 9
```如果我们选择`x = 4`， 然后：```
[4,9,3] -> [4,4,3]
sum = 11
```两个都`9`和`11`是距离`1`远离`10`，但由于关系需要较小的值，所以答案是`3`。 

一个重要的细节是答案不需要已经存在于数组中。 我们可以自由选择任何整数值。 

限制条件是：

 -`1 <= arr.length <= 10^4`-`1 <= arr[i], target <= 10^5`这些限制告诉我们几件事：

 - 数组最多可以包含一万个元素，因此二次解可能会变得太慢。 
- 数组值和目标值有合理的界限，这使得对可能的突变值进行二分搜索变得实用。 
- 由于所有数字都是正整数，因此随着所选值的增加，变异总和的行为是单调的。 这种单调行为是最佳解决方案的关键见解。 

一些边缘情况很重要：

 - 目标可能已经等于原始数组总和。 
- 目标可能小于数组中的每个元素。 
- 目标可能大于原始总和，这意味着不需要突变。 
- 多个值可能会产生同样接近的和，我们必须正确返回较小的那个。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是尝试每个可能的突变值`0`直到数组中的最大元素。 

对于每个候选值：

 1. 通过用候选本身替换每个大于候选的元素来创建变异数组。 
2. 计算变异总和。 
3. 比较与目标的距离。 
4. 跟踪产生最小差异的值。 

这是有效的，因为它详尽地检查了每一个可能的答案。 

然而，时间复杂度变得昂贵。 如果数组的最大值为`10^5`，然后我们重新计算每个候选者的数组和，复杂度变为：```
O(max(arr) * n)
```在最坏的情况下：```
10^5 * 10^4 = 10^9
```这太慢了。 

### 最佳解决方案的关键见解

 关键的观察结果是，随着突变值的增加，突变总和单调变化。 

如果所选值增加：

 - 更多元素保留其原始值。 
- 替换后的值变大。 
- 因此，所得总和永远不会减少。 

这种单调行为意味着我们可以二分搜索找到最佳突变值。 

为了有效地计算变异总和：

 1. 对数组进行排序。 
2. 构建前缀和数组。 
3. 对于任意候选值`x`，使用二分查找查找第一个大于的元素`x`。 
4. 该索引之前的元素保持不变。 
5. 该索引之后的元素贡献`x`每个。 

这使得每个总和计算能够高效地完成。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(最大(arr) * n) | O(1) | O(1) | 测试每个可能的突变值 |
 | 最佳 | O(n log n + log(max(arr)) * log n) | O(n log n + log(max(arr)) * log n) | O(n) | 使用排序、前缀和和二分搜索 |

 ## 算法演练

 ### 最优算法

 1. 将数组按升序排序。 

排序可以帮助我们快速确定哪些元素将被给定的突变值替换。 排序后，所有大于候选值的元素连续出现在末尾。 
2. 构建前缀和数组。 

前缀总和数组允许我们在常数时间内计算任何前缀的总和。 如果`prefix[i]`存储第一个的总和`i`元素，那么可以有效地检索未更改元素的总和。 
3. 定义一个辅助函数来计算候选值的变异总和。 

对于候选值`x`:

 - 使用二分查找查找第一个索引`arr[index] > x`。 
- 该索引之前的元素保持不变。 
- 从该索引开始的元素变为`x`。 

变异后的总和变为：```
unchanged_sum + x * replaced_count
```4. 对答案空间进行二分查找。 

突变值的范围可以是`0`到`max(arr)`。 

对于每个中点：

 - 计算变异总和。 
- 如果总和小于目标，则向右移动。 
- 否则，向左移动。 

这是有效的，因为突变总和随着突变值单调增加。 
5. 二分查找完成后，评估附近的候选者。 

二分搜索识别总和与目标相交的边界，但最接近的答案可能是该边界的任一侧。 

比较：

-`left`-`left - 1`选择绝对差值较小的那个。 
6. 应用平局决胜规则。 

如果两个值产生相同的差值，则返回较小的值。 

### 为什么它有效

 变异总和是所选变异值的单调函数。 增加突变值永远不会减少最终的总和。 由于这种单调性，二分搜索正确地将搜索空间缩小到最佳答案。 

前缀和确保每个候选评估是有效的，而相邻候选之间的最终比较保证返回最接近的可能值。 

## Python 解决方案```python
from bisect import bisect_right
from typing import List

class Solution:
    def findBestValue(self, arr: List[int], target: int) -> int:
        arr.sort()
        n = len(arr)

        prefix = [0] * (n + 1)

        for i in range(n):
            prefix[i + 1] = prefix[i] + arr[i]

        def mutated_sum(value: int) -> int:
            index = bisect_right(arr, value)

            unchanged = prefix[index]
            replaced_count = n - index

            return unchanged + value * replaced_count

        left = 0
        right = arr[-1]

        while left < right:
            mid = (left + right) // 2

            if mutated_sum(mid) < target:
                left = mid + 1
            else:
                right = mid

        sum1 = mutated_sum(left)
        sum2 = mutated_sum(left - 1)

        if abs(sum2 - target) <= abs(sum1 - target):
            return left - 1

        return left
```该实现首先对数组进行排序，以便所有大于候选突变值的值一起出现在末尾。 

接下来，构建前缀和数组。 前缀和数组允许恒定时间检索未更改元素的总和。 

这`mutated_sum`辅助函数计算所选突变值的结果数组总和。 它使用`bisect_right`找出有多少元素保持不变。 该位置之后的所有内容都将成为突变值。 

主要的二分搜索对可能的突变值进行操作`0`到数组中的最大元素。 由于变异和单调增加，二分搜索有效地定位目标附近的转变点。 

最后，双方`left`和`left - 1`被检查，因为精确最接近的值可能位于二分搜索边界的任一侧。 当差异相等时，通过优先选择较小的值来自然地处理平局打破规则。 

## 解决方案```go
package main

import "sort"

func findBestValue(arr []int, target int) int {
	sort.Ints(arr)

	n := len(arr)

	prefix := make([]int, n+1)

	for i := 0; i < n; i++ {
		prefix[i+1] = prefix[i] + arr[i]
	}

	mutatedSum := func(value int) int {
		index := sort.Search(len(arr), func(i int) bool {
			return arr[i] > value
		})

		unchanged := prefix[index]
		replacedCount := n - index

		return unchanged + value*replacedCount
	}

	left := 0
	right := arr[n-1]

	for left < right {
		mid := (left + right) / 2

		if mutatedSum(mid) < target {
			left = mid + 1
		} else {
			right = mid
		}
	}

	sum1 := mutatedSum(left)
	sum2 := mutatedSum(left - 1)

	if abs(sum2-target) <= abs(sum1-target) {
		return left - 1
	}

	return left
}

func abs(x int) int {
	if x < 0 {
		return -x
	}

	return x
}
```Go 解决方案遵循与 Python 版本相同的算法结构。 

而不是`bisect_right`, Go 使用`sort.Search`找到第一个大于候选值的元素。 

直接使用切片，前缀和存储在长度为整数的切片中`n + 1`。 

在给定的约束下，整数溢出不是问题，因为最大可能的总和是：```go
10^4 * 10^5 = 10^9
```可以安全地放入 Go 中`int`在 LeetCode 平台上输入。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n log n + log(max(arr)) * log n) | O(n log n + log(max(arr)) * log n) | 排序最初占主导地位，每个二分搜索步骤执行另一个二分搜索 |
 | 空间| O(n) | 前缀和数组需要线性额外空间 |

 排序步骤成本`O(n log n)`。 

外部二分搜索运行的值来自`0`到`max(arr)`，这需要`O(log(max(arr)))`迭代。 

每次迭代都会使用对排序数组进行二分搜索来计算变异总和，`O(log n)`。 

因此，总复杂度为：```
O(n log n + log(max(arr)) * log n)
```额外的空间来自前缀和数组。

class Solution:
    def findBestValue(self, arr: List[int], target: int) -> int:
        from bisect import bisect_right

        arr.sort()
        n = len(arr)

        prefix = [0] * (n + 1)

        for i in range(n):
            prefix[i + 1] = prefix[i] + arr[i]

            else:
                right = mid

        if abs(mutated_sum(left - 1) - target) <= abs(mutated_sum(left) - target):
            return left - 1

        return left

 ## 边缘情况

 当目标大于原始数组总和时，就会出现一种重要的边缘情况。 在这种情况下，任何突变都不能增加总和，因为突变只会减少值。 因此，最佳答案是最大数组值，这使数组保持不变。 该实现自然地处理了这个问题，因为二分搜索最终收敛到最大可能的突变值。 

当目标非常小时，甚至小于数组长度时，会发生另一个重要情况。 由于所有元素都是正的，因此最佳突变值可能会变为零。 许多不正确的实现假设突变值必须为正，但问题允许为零。 二分查找在搜索空间中正确地包含零。 

平局决胜是另一个微妙的错误来源。 两个相邻的突变值可能会产生与目标距离相等的总和。 该问题明确要求返回较小的值。 该实现通过检查两者来处理这个问题`left`和`left - 1`，然后使用`<=`比较差异时，较小的值获胜。 

最后的边缘情况涉及包含许多重复元素的数组。 如果辅助函数无法正确识别大于变异阈值的第一个值，二分搜索边界可能会变得棘手。 使用`bisect_right`在Python和`sort.Search`Go 确保正确处理重复项，并且所有小于或等于突变阈值的值保持不变。
