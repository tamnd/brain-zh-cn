 # LeetCode 1341 - 电影分级

 ## 问题理解

 此问题适用于三个关系数据库表：`Movies`,`Users`， 和`MovieRating`。 目标是生成恰好包含两行的结果。 

第一行应包含对电影数量最多的用户的姓名。 如果多个用户对相同的电影最大数量进行评分，我们必须选择字典顺序较小的名称。 字典排序意味着标准字典排序，所以`"Daniel"`出现在之前`"Monica"`。 

第二行应包含 2020 年 2 月期间平均评分最高的电影标题。同样，按字典顺序断开关系，因此如果两部电影具有相同的平均评分，则会选择按字母顺序排列较小的标题。 

这`MovieRating`表充当用户和电影之间的连接。 每行代表一个用户在特定日期对一部电影提交的评分。 

重要的细节是第二个查询仅考虑其评级`created_at`日期在 2020 年 2 月以内。计算平均值时，必须忽略该月以外的评级。 

该问题保证了`(movie_id, user_id)`是唯一的，这意味着用户不能多次评价同一部电影。 这简化了聚合，因为每个评级行都是不同的。 

错误的常见来源是领带处理。 许多不正确的解决方案正确计算最大计数或平均值，但在出现平局时无法应用字典顺序。 另一个常见问题是错误地过滤二月日期。 最安全的方法是使用日期范围`'2020-02-01'`到`'2020-02-29'`或使用基于月份的过滤器。 

由于这是一个 SQL 数据库问题，性能约束通常由数据库引擎处理，但我们仍然需要一个高效的查询结构，以避免不必要的嵌套扫描。 

## 方法

 ### 蛮力方法

 暴力方法将使用多个嵌套查询手动计算所有内容。 

对于第一个要求，我们可以迭代每个用户并通过扫描整个用户来计算他们提交的评分数`MovieRating`每个用户的表。 收集所有计数后，我们将确定最大计数并按字典顺序解决关系。 

对于第二个要求，我们可以迭代每部电影并扫描所有评分以计算 2020 年 2 月的平均值。计算所有平均值后，我们将选择最大平均值并再次按字典顺序解析关系。 

这种方法在逻辑上是正确的，因为它显式地计算了每个所需的统计数据。 然而，它对相同的表执行重复扫描，对于大型数据集变得效率低下。 

### 最佳方法

 关键的观察结果是 SQL 数据库针对聚合操作进行了优化，例如`COUNT`,`AVG`,`GROUP BY`， 和`ORDER BY`。 

我们可以使用分组聚合查询，而不是重复扫描表：

 1. 加入`Users`和`MovieRating`，按用户名分组，计算评分，然后排序：

 - 递减计数
 - 升序名称
 2. 加入`Movies`和`MovieRating`，过滤 2020 年 2 月的行，按电影标题分组，计算平均值，然后排序：

 - 平均下降
 - 升序标题

 最后，使用组合两个结果`UNION ALL`。 

该解决方案非常高效，因为聚合发生在每个需求的单个分组传递中。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(U × R + M × R) | O(U × R + M × R) | O(U + M) | 重复扫描每个用户和电影的评分表 |
 | 最佳| O(R log R) | O(R log R) | O(R)| 高效使用 SQL 聚合和排序 |

 这里：

-`R`= 中的行数`MovieRating`-`U`= 用户数量
 -`M`= 电影数量

 ## 算法演练

 1. 首先解决第一个要求，找到评分最高的用户。 
2. 加入`Users`表与`MovieRating`使用`user_id`。 这样可以访问用户名及其评级。 
3. 按用户名对连接的行进行分组。 现在，每个组代表一个用户提交的所有评分。 
4. 使用`COUNT(*)`计算每个用户提交的评分数。 
5. 对分组结果进行排序：

 - 降序计数，因为我们想要最大数量的评分
 - 名称升序，因为关系必须使用字典顺序
 6. 使用`LIMIT 1`仅选择最佳结果。 
7. 接下来，解决第二个要求，找到 2020 年 2 月平均评分最高的电影。 
8. 加入`Movies`和`MovieRating`使用`movie_id`。 
9. 过滤行，以便仅保留 2020 年 2 月期间创建的评级。 
10. 按电影标题对剩余行进行分组。 
11. 使用`AVG(rating)`计算每部电影二月份的平均评分。 
12. 对分组结果进行排序：

 - 平均降序
 - 标题升序

 1. 使用`LIMIT 1`仅保留所需的电影。 
2. 使用组合两个单行输出`UNION ALL`。 

### 为什么它有效

 正确性来自于 SQL 聚合语义。`GROUP BY`保证同一实体的所有行都一起处理。`COUNT(*)`准确计算每个用户的总评分，同时`AVG(rating)`准确计算过滤月份的电影平均值。 

排序规则直接编码了问题的平局要求：

 - 首先递减数值
 - 升序词典价值第二

 由于这种排序，排序后的第一行始终是正确答案。 

## SQL 解决方案```sql
(
    SELECT u.name AS results
    FROM Users u
    JOIN MovieRating mr
        ON u.user_id = mr.user_id
    GROUP BY u.user_id, u.name
    ORDER BY COUNT(*) DESC, u.name ASC
    LIMIT 1
)

UNION ALL

(
    SELECT m.title AS results
    FROM Movies m
    JOIN MovieRating mr
        ON m.movie_id = mr.movie_id
    WHERE mr.created_at >= '2020-02-01'
      AND mr.created_at < '2020-03-01'
    GROUP BY m.movie_id, m.title
    ORDER BY AVG(mr.rating) DESC, m.title ASC
    LIMIT 1
);
```## 实施演练

 第一个子查询连接`Users`和`MovieRating`这样每个评级都与一个用户名相关联。 按用户分组后，`COUNT(*)`衡量每个用户评分的电影数量。 

这`ORDER BY COUNT(*) DESC`条款确保具有更多评级的用户首先出现。 二次排序`u.name ASC`按字母顺序解决关系。`LIMIT 1`提取单个所需用户。 

第二个子查询连接`Movies`和`MovieRating`。 这`WHERE`子句仅将行限制为 2020 年 2 月评级。 

分组的行使用以下方式聚合`AVG(mr.rating)`。 按平均评分降序排序可确保评分最高的电影首先出现，而标题升序则按字典顺序解决关系。 

最后，`UNION ALL`将两个单行结果连接成所需的输出格式。

 ## 边缘情况

 ### 多个用户之间的联系

 一个非常常见的错误是当多个用户具有相同数量的评分时返回任意用户。 除非明确指定，否则 SQL 引擎不保证确定性排序。 此实现使用以下方法正确处理该问题：```
ORDER BY COUNT(*) DESC, u.name ASC
```这保证了在平局期间选择字典顺序最小的名称。 

### 多部电影之间的平局

 当 2020 年 2 月期间两部或更多电影具有相同的平均评分时，会出现另一种微妙的情况。如果没有辅助排序条件，结果可能是不确定的。 

该实现使用以下方法正确解决了这个问题：```
ORDER BY AVG(mr.rating) DESC, m.title ASC
```这确保了稳定且正确的领带处理。 

### 2020 年 2 月以外的收视率

 在计算平均值时，很容易意外地包含一月或三月的评分。 这会产生不正确的结果。 

该实现通过明确的日期范围过滤器来防止这种情况：```
WHERE mr.created_at >= '2020-02-01'
  AND mr.created_at < '2020-03-01'
```这包括每年二月的日期，但不包括所有其他月份。 

### 没有二月评级的电影

 有些电影可能只在 2020 年 2 月之后才有收视率。这些电影根本不应该参与平均计算。 

由于查询在分组之前过滤行，因此没有二月份评级的电影永远不会进入聚合阶段，这自然会产生正确的行为。
