[LeetCode 1355 题](https://leetcode.com/problems/activity-participants/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题要求我们分析不同活动的参与计数，并仅返回所有活动中参与者计数既不是最高也不是最低的活动。 

我们有两个数据库表：

 的`Friends`表记录了哪个朋友参加了哪个活动。 每行代表一位朋友和一项活动。 

这`Activities`表包含所有活动的列表。 

关键的观察结果是，列出的每项活动`Activities`保证出现在`Friends`，这意味着每项活动至少有一个参与者。 这种保证简化了解决方案，因为我们不需要处理零参与者的活动。 

任务是计算有多少朋友参与每项活动，确定：

 - 最大参与者人数
 - 最低参与人数

 然后返回计数严格位于这两个值之间的所有活动。 

For the sample input:

 | Activity | Participants |
 | ---| ---|
 | Eating | 3 |
 | 唱歌| 2 |
 | Horse Riding | 1 |

 最大计数为`3`，最小计数为`1`，并且仅`Singing`计数既不是最大值也不是最小值。 

一个重要的细节是多个活动可能共享相同的最大或最小计数。 必须排除每个具有最大计数的活动，并且还必须排除每个具有最小计数的活动。 

输出可以按任何顺序返回，因此除非明确请求，否则不需要排序。 

因为这是一个 SQL 数据库问题，所以主要挑战是使用 SQL 操作构建正确的聚合和过滤逻辑，例如：

 -`GROUP BY`- 聚合函数，例如`COUNT`- 子查询或公用表表达式
 - 基于计算聚合的过滤

 一些边缘情况很重要：

 - 如果所有活动的参与者数量相同，则每个活动同时是最大值和最小值，因此结果为空。 
- 多项活动可以实现最大程度的参与。 
- 多项活动可能会影响最低参与度。 
- 可能只有两个不同的参与计数，在这种情况下，没有活动符合资格。 
- 由于每项活动都出现在`Friends`，我们永远不需要处理空计数或缺失连接。 

## 方法

 ### 蛮力方法

 一种简单的方法是计算每个活动的参与者计数，存储这些计数，然后重复将每个活动与所有其他活动进行比较，以确定它是否具有最大或最小计数。 

该过程如下所示：

 1. 统计每项活动的参与者。 
2. For each activity:

 - 扫描所有其他活动以确定其计数是否为最大值。 
- 再次扫描所有其他活动以确定其计数是否为最小值。 
3. 仅当两者都不是时才包括该活动。 

这是有效的，因为每个活动都会与其他活动进行明确比较，从而保证正确识别最大和最小计数。 

然而，这种方法效率低下，因为`n`活动中，每个活动都可能将自己与所有其他活动进行比较，从而导致二次行为。 

### 最佳方法

 更好的解决方案是基于聚合。 

关键的见解是我们只需要三条信息：

 1. 每项活动的参与人数
 2. 全球最大参与人数
 3. 全球最低参与人数

 一旦我们知道了这些值，过滤就变得简单了。 

我们首先将`Friends`按活动和计算计数列出的表。 然后我们计算这些分组结果的最大和最小计数。 最后，我们仅返回计数不等于任一极端的活动。 

这种方法避免了重复比较并且只执行一次聚合。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 反复将每项活动与所有其他活动进行比较 |
 | 最佳 | O(n) | O(n) | 使用一次聚合，然后高效过滤 |

 ## 算法演练

 1. 分组`Friends`表格依据`activity`。 

我们需要知道每个活动有多少参与者。 使用`GROUP BY activity`允许 SQL 将同一活动的所有行收集在一起。 
2. 计算每组的参与者人数。 

使用`COUNT(*)`，我们计算参与每项活动的好友数量。 

中间结果示例：

 | 活动 | 碳纳米管|
 | ---| ---|
 | 吃| 3 |
 | 唱歌| 2 |
 | 骑马| 1 |
 3. 确定最大参与者人数。 

我们申请`MAX(cnt)`超过分组计数。 在上面的例子中，最大值是`3`。 
4. 确定最低参与者人数。 

我们申请`MIN(cnt)`超过分组计数。 在上面的例子中，最小值是`1`。 
5. 过滤计数既不是最大也不是最小的活动。 

我们只保留以下行：```
cnt != max_cnt AND cnt != min_cnt
```6. 返回活动名称。 

最终结果仅包含符合资格的活动。 

### 为什么它有效

 该算法之所以有效，是因为每项活动都被精确分配了一个参与计数。 全局最大和最小计数完全定义了必须排除哪些活动。 任何计数不同于两个极端的活动必然严格位于它们之间，因此它满足问题要求。 

## Python 解决方案

 虽然这是一个数据库问题，但 LeetCode 数据库解决方案是用 SQL 编写的。 为了完整起见，以下表示以 Python 字符串形式嵌入的正确 SQL 解决方案。```python
class Solution:
    def activityParticipants(self):
        return """
        WITH activity_counts AS (
            SELECT
                activity,
                COUNT(*) AS participant_count
            FROM Friends
            GROUP BY activity
        )
        SELECT activity
        FROM activity_counts
        WHERE participant_count NOT IN (
            (SELECT MAX(participant_count) FROM activity_counts),
            (SELECT MIN(participant_count) FROM activity_counts)
        );
        """
```该解决方案首先创建一个名为的公用表表达式`activity_counts`。 该中间结果将每个活动及其参与者计数存储在一起。 

接下来，外部查询过滤行。 这`MAX`和`MIN`子查询计算聚合表中的最大和最小参与计数。 

最后，`NOT IN`条件会删除计数与任一极端匹配的所有活动。 

使用公用表表达式可以提高可读性，因为聚合逻辑仅写入一次。

 ## 边缘情况

 当所有活动的参与者数量完全相同时，就会出现一种重要的边缘情况。 在这种情况下，最小和最大计数是相同的。 由于每个活动同时匹配这两个值，因此必须排除所有活动。 如果粗心的实现仅检查一个条件，则可能会错误地返回每个活动。 

另一个重要的情况是多个活动共享最大或最小计数。 例如，两项活动可能都有 5 名参与者，而另外两项活动可能都有 1 名参与者。 解决方案必须排除所有与极端相关的活动，而不仅仅是其中之一。 使用`NOT IN`根据计算出的最大值和最小值自然可以处理这种情况。 

当只有两个不同的参与计数时，会出现第三种边缘情况。 例如，活动可能有计数`{1, 1, 5, 5}`。 在这种情况下，每个活动要么是最小值，要么是最大值，因此结果为空。 过滤条件正确删除所有行。 

最后一个微妙的情况是确保每个活动都存在于`Friends`桌子。 问题保证了这个属性，所以我们不需要外连接或空处理。 如果没有这种保证，零参与者的活动将需要特殊处理。
