[LeetCode 1335 题](https://leetcode.com/problems/minimum-difficulty-of-a-job-schedule/)

 **难度：** 🔴难
 **主题：** 数组、动态规划

 ## 解决方案

 ## 问题理解

 问题给了我们一个数组`jobDifficulty`，其中每个元素代表工作的难度。 作业必须按顺序完成，这意味着您无法重新排列它们。 如果你想工作`i`，那么它之前的每一项工作都必须已经完成。 

我们必须将所有工作准确地划分为`d`连续的组，其中每组代表一天内完成的工作。 每天必须至少包含一项工作。 

单日的难度定义为当天分配的所有作业中最大的作业难度。 总进度难度是所有每日难度的总和`d`天。 

我们的目标是尽量减少总的困难。 

例如，如果：```
jobDifficulty = [6,5,4,3,2,1]
d = 2
```一种有效的时间表是：

 - 第一天：`[6,5,4,3,2]`, 难度 =`6`- 第 2 天：`[1]`, 难度 =`1`总难度=`6 + 1 = 7`这是最佳的。 

约束条件很重要：

 -`jobDifficulty.length <= 300`-`d <= 10`的值相对较小`d`强烈建议动态规划。 暴力分区解决方案将呈指数级增长并且变得不可行。 

一个重要的观察结果是，如果工作数量小于天数，则答案是不可能的。 由于每天必须至少包含一项工作，因此我们无法安排`n`工作跨越超过`n`天。 

重要的边缘情况包括：

 -`len(jobDifficulty) < d`, 不可能的时间表
 -`d == 1`，所有工作必须在一天内完成
 -`d == len(jobDifficulty)`, 每天正好一份工作
 - 具有重复值的数组
 - 最佳分区不明显的数组

 ## 方法

 ### 蛮力

 暴力解决方案尝试一切可能的方法将作业划分为`d`连续的组。 

在每个位置，我们都可以决定当天的结束位置，并递归地解决剩余天数的剩余工作。 对于每个分区，我们计算：

 - 当天的最大难度
 - 剩余天数的最佳难度

 然后我们对所有可能性取最小值。 

这种方法是正确的，因为它探索了每个有效的时间表。 然而，分区的数量呈指数增长。 即使省略了记忆，解决方案对于`n = 300`。 

### 动态规划

 关键的见解是许多递归状态会重复。 

假设我们定义：

 -`dp[i][day]`= 从索引开始安排作业的最小难度`i`准确地使用`day`剩余天数

 从给定的状态开始，我们尝试当天的所有有效结局。 在扩大当前工作岗位的同时，我们保持运行最大难度。 

过渡变为：```
dp[i][day] =
    min over j:
        max(jobDifficulty[i..j]) + dp[j+1][day-1]
```这避免了重新计算重叠的子问题。 

自从：

-`n <= 300`-`d <= 10`一个`O(n² × d)`解决方案足够有效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 递归地探索每个分区 |
 | 最佳DP | O(d × n²) | O(d × n²) | O(d × n) | 记忆或表格动态规划|

 ## 算法演练

 1. 首先检查调度是否可行。 

如果作业数量小于天数，则返回`-1`。 每天必须至少包含一项工作。 
2. 定义DP状态。 

让：```
dp(day, index)
```表示从以下位置开始安排作业所需的最低难度`index`准确地使用`day`剩余天数。 
3. 处理基本情况。 

如果只剩下一天，那么所有剩余的工作都必须在这一天完成。 

难度变为：```
max(jobDifficulty[index:])
```4. 尝试当天的所有有效分区。 

假设当天结束于位置`j`。 

然后：

 - 当日难度为最大值`jobDifficulty[index:j+1]`- 剩余成本为`dp(day - 1, j + 1)`我们计算：```
current_max + remaining_cost
```并最小化所有选择。 
5. 确保未来有足够的就业机会。 

如果有`remaining_days`离开后，我们必须在剩下的每一天至少离开一份工作。 

因此，分区循环只会达到：```
n - remaining_days
```6. 使用记忆法。 

许多状态在递归期间重复。 缓存计算状态可防止指数重新计算。 
7. 返回以下问题的答案：```
dp(d, 0)
```### 为什么它有效

 该算法之所以有效，是因为每个有效的调度都可以表示为一系列分区边界。 对于每个状态，我们详尽地考虑当天的每个有效端点，同时以最佳方式递归解决剩余的子问题。 

递归满足最优子结构：

 - 最优完整调度必须包含其后缀子问题的最优调度。 

记忆化保证每个状态只解决一次。 

## Python 解决方案```python
from typing import List
from functools import lru_cache

class Solution:
    def minDifficulty(self, jobDifficulty: List[int], d: int) -> int:
        n = len(jobDifficulty)

        if n < d:
            return -1

        @lru_cache(None)
        def dp(index: int, days_left: int) -> int:
            if days_left == 1:
                return max(jobDifficulty[index:])

            current_max = 0
            best = float("inf")

            # Leave at least one job for each remaining day
            for j in range(index, n - days_left + 1):
                current_max = max(current_max, jobDifficulty[j])

                next_cost = dp(j + 1, days_left - 1)

                best = min(best, current_max + next_cost)

            return best

        return dp(0, d)
```实现首先检查调度是否可行。 如果作业数量少于天数，该函数立即返回`-1`。 

递归函数`dp(index, days_left)`代表从开始的最小进度难度`index`和`days_left`剩余天数。 

基本情况发生在只剩下一天的时候。 在这种情况下，所有剩余作业必须一起完成，因此难度就是最大剩余作业难度。 

在转换循环中，我们逐渐将当前日期从`index`到`j`。 变量`current_max`跟踪迄今为止遇到的最大难度，从而避免重复重新计算最大值。 

对于每个可能的分区，我们递归地计算剩余作业的最佳难度，并将其与当天的难度相结合。 

记忆通过`@lru_cache`确保每个状态仅计算一次。 

## 解决方案```go
package main

import "math"

func minDifficulty(jobDifficulty []int, d int) int {
	n := len(jobDifficulty)

	if n < d {
		return -1
	}

	memo := make([][]int, n)

	for i := 0; i < n; i++ {
		memo[i] = make([]int, d+1)

		for j := 0; j <= d; j++ {
			memo[i][j] = -1
		}
	}

	var dp func(int, int) int

	dp = func(index int, daysLeft int) int {
		if daysLeft == 1 {
			maxVal := 0

			for i := index; i < n; i++ {
				if jobDifficulty[i] > maxVal {
					maxVal = jobDifficulty[i]
				}
			}

			return maxVal
		}

		if memo[index][daysLeft] != -1 {
			return memo[index][daysLeft]
		}

		currentMax := 0
		best := math.MaxInt32

		for j := index; j <= n-daysLeft; j++ {
			if jobDifficulty[j] > currentMax {
				currentMax = jobDifficulty[j]
			}

			nextCost := dp(j+1, daysLeft-1)

			if currentMax+nextCost < best {
				best = currentMax + nextCost
			}
		}

		memo[index][daysLeft] = best
		return best
	}

	return dp(0, d)
}
```Go 实现遵循与 Python 版本相同的递归动态编程结构。 

由于 Go 不提供像 Python 那样的内置记忆化装饰器`lru_cache`，我们显式分配一个初始化为的 2D 备忘录表`-1`。 

递归闭包`dp`将计算出的状态存储在`memo[index][daysLeft]`。 

直接使用Go切片而不是Python列表。 整数溢出在这里不是问题，因为最大可能的答案受以下限制：```go
1000 × 300 = 300000
```它很容易适合 32 位整数。

 ## 边缘情况

 当工作数量少于几天时，就会出现一种重要的边缘情况。 由于每天必须至少包含一项工作，因此安排时间变得不可能。 幼稚的实现可能仍会尝试递归或 DP 构造并产生无效状态。 实现立即处理这个问题：```
if n < d:
    return -1
```另一个重要的情况是只剩下一天的时间。 在这种情况下，所有剩余的工作必须一起完成。 一个常见的错误是继续不必要的递归或进一步分区。 该实现通过返回以下内容正确地将剩余时间折叠到一天中：```
max(jobDifficulty[index:])
```第三个棘手的情况发生在`d == len(jobDifficulty)`。 每天必须恰好收到一份工作，因此答案就成为所有工作困难的总和。 一些不正确的实现意外地允许空天或无效分区。 该解决方案中的循环边界保证了未来有足够的作业：```
for j in range(index, n - days_left + 1):
```此约束确保每个递归分支都对应于有效的调度。
