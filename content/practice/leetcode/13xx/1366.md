[LeetCode 1366 题](https://leetcode.com/problems/rank-teams-by-votes/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、字符串、排序、计数

 ## 解决方案

 ## 问题理解

 该问题描述了一个基于投票的排名系统，其中每个投票者对所有团队从最好到最差进行排名。 每个投票都表示为一个字符串，其中索引处的字符`0`是排名最高的队伍，索引处的角色`1`是排名第二的球队，依此类推。 

最终排名是根据各个职位的投票数按字典顺序确定的。 首先，我们比较每个团队获得了多少第一名选票。 获得第一名票数越多的球队排名越高。 如果两支球队打成平手，我们会比较他们第二名的得票数。 如果仍然平局，我们将继续比较第三名的计数、第四名的计数，依此类推，直到打破平局。 

如果所有位置票数相同，则最终的决胜局将按字母顺序排列。 

输入是一个数组`votes`，其中：

 - 每个字符串包含所有参赛队伍一次
 - 每张投票的长度相同
 - 队伍以大写英文字母代表
 - 由于只使用大写字母，因此最多有 26 支球队

 输出应该是一个字符串，其中包含从最高排名到最低排名排序的所有团队。 

这些约束很重要，因为它们指导实施策略：

 -`votes.length <= 1000`-`votes[i].length <= 26`由于最多有 26 支球队，因此我们可以为每支球队存储完整的位置频率数组。 甚至一个`O(26^2 log 26)`风格解决方案非常有效。 

一些边缘情况很重要：

 - 只有一名投票者存在，在这种情况下，答案就是那次投票。 
- 多个团队在每个位置上的投票分布可能相同。 
- 球队可能会在几个位置上打成平手，然后最终出现分歧。 
- 完整的关系必须回归到字母顺序。 
- 团队数量可以少至 1 人。 

如果仅比较第一名选票或者不能正确处理按字母顺序打破平局，那么幼稚的实现很容易失败。 

## 方法

 ### 蛮力方法

 强力解决方案将通过扫描所有选票并计算每次比较期间每个团队在每个位置出现的次数来重复比较每对团队。 

例如，在比较团队时`A`和团队`B`，我们可以：

 1. 通过扫描所有选票来计算两队的第一名选票
 2. 如果平局，计算第二名选票
 3. 继续，直到解决平局
 4. 在排序过程中对每一对重复此过程

 这种方法是正确的，因为它在每次比较时都直接遵循排名规则。 

然而，它的效率很低，因为相同的计数会被重新计算很多次。 排序需要多次比较，每次比较都会重复扫描所有选票。 

### 最佳方法

 关键的观察是，立场票数永远不会改变。 我们可以对所有投票统计数据进行一次预处理，而不是重复地重新计算它们。 

对于每个团队，我们存储：

 - 第一名票数
 - 第二名票数
 - 第三名票数
 - 等等

 然后我们使用这些预先计算的统计数据对团队进行排序。 

例如：

 | 团队| 第一 | 第二 | 第三 |
 | ---| ---| ---| ---|
 | 一个 | 5 | 0 | 0 |
 | 乙| 0 | 2 | 3 |
 | C | 0 | 3 | 2 |

 现在排序变得简单了：

 - 比较第一名的数量
 - 如果平局，比较第二名的数量
 - 继续遍历所有位置
 - 最后按字母顺序比较

 这很有效，因为最多有 26 个团队。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(V × T² × log T × T) | O(1) | O(1) | 在排序过程中重复重新计算选票计数 |
 | 最佳 | O(V × T + T log T) | O(T²) | 预先计算位置频率一次 |

 在哪里：

-`V`= 票数
 -`T`= 团队数量

 自从`T <= 26`，最优方法非常快。 

## 算法演练

 1、从第一轮投票开始确定参赛队伍数量。 

每次投票都包含所有团队，所以`len(votes[0])`给出参赛队伍的总数。 
2. 为每个团队创建一个频率表。 

我们使用哈希映射，其中：

 - 关键=团队性格
 - 值 = 位置计数数组

 示例：```
{
    'A': [5, 0, 0],
    'B': [0, 2, 3],
    'C': [0, 3, 2]
}
```每个指数代表一个排名位置。 
3. 处理每一次投票。 

对于每个投票字符串：

 - 遍历每个位置
 - 增加该团队相应的位置计数器

 示例：

 投票`"ACB"`方法：

-`A`获得一张第一名选票
 -`C`获得一张二等票
 -`B`获得第三名选票
 4. 将所有团队提取到可排序列表中。 

我们需要一个团队角色列表，因为我们将根据排名规则对他们进行排序。 
5. 使用自定义比较键对团队进行排序。 

团队应按以下顺序排序：

 - 最高的第一名票数
 - 第二名票数最高
 - 最高第三名票数
 - 继续所有职位
 - 如果仍然相同，则按字母顺序排列

 在Python中，我们可以通过对计数求反来实现位置降序。 

排序键示例：```
(-count1, -count2, -count3, team_letter)
```6. 将排序好的队伍加入到最终的队伍中。 

排序后，将字符连接到结果中。 

### 为什么它有效

 该算法之所以有效，是因为排名规则定义了位置投票计数的字典顺序比较。 

每个团队都由一个向量表示：```
[first_place_votes, second_place_votes, third_place_votes, ...]
```按这些向量的字典顺序对团队进行排序与​​问题定义完全匹配。 如果两个向量相同，则按字母顺序排序可提供最终的确定性决胜局。 

由于每张选票都对正确的位置计数器贡献一次，因此预先计算的统计数据是准确的，并且保证排序顺序与所需的排名系统相匹配。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def rankTeams(self, votes: List[str]) -> str:
        if not votes:
            return ""

        team_count = len(votes[0])

        rank_counts = defaultdict(lambda: [0] * team_count)

        for vote in votes:
            for position, team in enumerate(vote):
                rank_counts[team][position] += 1

        teams = list(votes[0])

        teams.sort(
            key=lambda team: (
                [-count for count in rank_counts[team]],
                team
            )
        )

        return "".join(teams)
```实现首先处理输入为空的边缘情况。 尽管约束保证了至少一票，但这种防御性检查使该功能更加安全。 

我们使用第一次投票来确定团队数量。 由于每次投票只包含所有球队一次，因此这为所有位置计数数组提供了正确的大小。 

这`defaultdict`存储每个团队的排名统计数据。 每个团队映射到一个列表，其中索引`i`存储该团队出现在该位置的次数`i`。 

在处理投票时，我们迭代每个字符并增加适当的位置计数器。 

预处理后，我们创建一个团队列表`votes[0]`。 这是有效的，因为每个团队都会出现在每次投票中。 

自定义排序键是解决方案中最重要的部分。 我们对计数求反，以便较大的计数按升序排列出现在较早的位置。 团队角色本身会附加到键上，以强制按字母顺序排列完整的关系。 

最后，我们将排序后的团队加入到答案字符串中。 

## 解决方案```go
package main

import (
	"sort"
)

func rankTeams(votes []string) string {
	if len(votes) == 0 {
		return ""
	}

	teamCount := len(votes[0])

	rankCounts := make(map[byte][]int)

	for i := 0; i < teamCount; i++ {
		team := votes[0][i]
		rankCounts[team] = make([]int, teamCount)
	}

	for _, vote := range votes {
		for position := 0; position < teamCount; position++ {
			team := vote[position]
			rankCounts[team][position]++
		}
	}

	teams := []byte(votes[0])

	sort.Slice(teams, func(i, j int) bool {
		teamA := teams[i]
		teamB := teams[j]

		for position := 0; position < teamCount; position++ {
			if rankCounts[teamA][position] != rankCounts[teamB][position] {
				return rankCounts[teamA][position] > rankCounts[teamB][position]
			}
		}

		return teamA < teamB
	})

	return string(teams)
}
```Go解决方案遵循与Python版本相同的算法结构，但实现细节略有不同。 

Go 不像 Python 那样方便地支持基于自定义元组的排序键，因此我们使用`sort.Slice`具有比较器功能。 比较器手动一一检查位置投票计数。 

投票统计数据存储在`map[byte][]int`因为团队标识符是大写 ASCII 字符。 

Go 切片是可变的，因此排序直接发生在`teams`片。 

不存在整数溢出问题，因为投票数最多为 1000。

 ## 边缘情况

 ### 团队之间完成平局

 当两个或更多团队在每个排名位置获得相同的计数时，就会出现一个特别棘手的情况。 在这种情况下，问题需要按字母顺序排序作为最终的决胜局。 

例如：```
["ABC", "BCA", "CAB"]
```每个团队将获得一张第一名选票、一张第二名选票和一张第三名选票。 

有缺陷的实现可能会根据排序稳定性产生不一致的排序。 我们的实现明确地将团队字母附加到排序键，保证确定性的字母顺序。 

### 只有一票存在

 当只有一名投票者时，结果应该与该投票完全匹配，因为不需要聚合或冲突解决。 

例子：```
["ZMNAGU"]
```粗心的实施可能会不必要地对团队进行重新排序或错误地处理缺失的计数。 我们的频率计算自然可以解决这个问题，因为每个团队在各自的位置上只收到一票。 

### 在较深位置打破平局

 有些球队可能会在几个排名级别上保持平局，然后最终有所不同。 

例子：```
["ABC", "ACB"]
```两个都`B`和`C`有：

 - 第一名票为零
 - 一张二等票
 - 一张第三名选票

 但根据其他选票，平局可能会延伸到许多职位。 

仅检查第一名或第二名选票的错误实现将会失败。 我们的比较器按顺序检查所有排名位置，确保整个排名向量的词典比较正确。
