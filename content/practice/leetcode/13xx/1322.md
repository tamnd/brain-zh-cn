 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 # 问题理解

 这个问题要求我们计算存储在数据库中的每个广告的点击率，缩写为CTR。`Ads`桌子。 

该表包含三列：

 | 专栏 | 意义|
 | --- | --- |
 |`ad_id`| 广告标识符|
 |`user_id`| 与广告交互的用户的标识符 |
 |`action`| 交互类型，要么`Clicked`,`Viewed`， 或者`Ignored`|

 点击率公式为：$$CTR = \frac{\text{number of clicks}}{\text{number of clicks} + \text{number of views}} \times 100$$重要的细节是`Ignored`行动完全被排除在分母之外。 仅有的`Clicked`和`Viewed`操作有助于点击率计算。 

输出应包含：

 | 专栏 | 意义|
 | --- | --- |
 |`ad_id`| 广告ID |
 |`ctr`| 点击率四舍五入至小数点后两位 |

 最终结果必须按以下顺序排序：

 1.`ctr`按降序排列
 2.`ad_id`如果两个广告具有相同的点击率，则按升序排列

 当广告仅具有`Ignored`行动。 在那种情况下：

 - 点击次数 = 0
 - 观看次数 = 0
 - 分母 = 0

 问题指定 CTR 应变为`0.00`而不是导致除零错误。 

输入保证`(ad_id, user_id)`是唯一的，这意味着同一用户不能为同一广告记录多个操作。 

由于这是一个数据库问题，因此首要任务是聚合。 我们需要对行进行分组`ad_id`，对不同的操作类型进行计数，计算百分比，对其进行适当舍入，并对结果进行排序。 

# 方法

 ## 蛮力方法

 暴力方法将独立处理每个广告。 

对于每一个独特的`ad_id`，我们可以再次扫描整个表并计数：

 - 有多少行`action = 'Clicked'`- 有多少行`action = 'Viewed'`收集这些计数后，我们计算：$$CTR = \frac{clicked}{clicked + viewed} \times 100$$如果分母为零，我们返回`0`。 

这种方法是正确的，因为它显式地计算每个广告所需的计数。 然而，它的效率很低，因为对于每个广告，我们都会重复扫描整个表。 

如果有：

 -`n`行
 -`k`独特的广告

 那么复杂度大约变为`O(n × k)`。 

## 最佳方法

 关键的观察是所有必需的信息都可以在单个分组聚合中计算。 

我们不是重新扫描表中的每个广告，而是按以下条件对行进行分组：`ad_id`并使用条件聚合：

 - 使用条件表达式计算点击次数
 - 使用条件表达式计算观看次数
 - 直接从这些聚合计算点击率

 SQL 数据库针对分组和聚合进行了优化，因此该解决方案既简单又高效。 

我们还使用：

 -`ROUND(..., 2)`保留两位小数
 -`IFNULL`或条件逻辑以避免被零除

 ## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n × k) | O(n × k) | O(1) | O(1) | 重复扫描表格中的每个广告 |
 | 最佳| O(n) | O(k) | 使用 SQL 进行单分组聚合 |

 # 算法演练

 1. 对所有行进行分组`ad_id`。 

这使我们能够独立处理每个广告，同时逻辑上只扫描一次表。 
2.统计每个广告的点击次数。 

我们使用条件聚合，例如：```
SUM(action = 'Clicked')
```每个匹配的行都有贡献`1`，以及所有其他人的贡献`0`。 
3. 统计每个广告的观看次数。 

同样，我们使用：```
SUM(action = 'Viewed')
```4. 计算分母。 

分母是：```
clicks + views
```被忽视的行为被有意排除。 
5. 处理被零除的情况。 

有些广告可能只包含被忽略的操作。 在这种情况下：```
clicks + views = 0
```我们返回`0.00`而不是除以零。 
6. 计算点击率百分比。 

公式变为：```
clicks * 100 / (clicks + views)
```7. 将结果四舍五入到小数点后两位。 

我们使用：```
ROUND(value, 2)
```8. 对结果进行排序。 

输出必须按以下顺序排序：

 -`ctr DESC`-`ad_id ASC`## 为什么它有效

 该算法之所以有效，是因为点击率仅取决于每个广告的两个数量：

 - 总点击次数
 - 总浏览次数

 分组依据`ad_id`保证同一广告的所有行都聚合在一起。 条件总和仅正确计算相关操作。 由于分子和分母均排除了忽略的操作，因此计算公式与问题陈述中给出的定义完全匹配。 

# Python 解决方案```python
# Write your MySQL query statement below

SELECT
    ad_id,
    ROUND(
        IFNULL(
            SUM(action = 'Clicked') * 100.0 /
            (SUM(action = 'Clicked') + SUM(action = 'Viewed')),
            0
        ),
        2
    ) AS ctr
FROM Ads
GROUP BY ad_id
ORDER BY ctr DESC, ad_id ASC;
```查询首先使用以下命令对所有记录进行分组`GROUP BY ad_id`。 这确保每个广告在最终结果中恰好出现一次。 

表达式：```python
SUM(action = 'Clicked')
```和```python
SUM(action = 'Viewed')
```执行条件聚合。 在 MySQL 中，布尔表达式的计算结果为`1`对于真实和`0`如果为 false，则对它们求和即可得到匹配行的计数。 

点击率公式将点击次数乘以`100.0`强制浮点除法而不是整数除法。 

这`IFNULL`包装器处理分母变为零的情况。 如果没有这种保护措施，除以零将会返回`NULL`。 查询将此类情况转换为`0`。 

最后，`ROUND(..., 2)`确保结果符合所需的格式。

 # 边缘情况

 ## 仅包含被忽略操作的广告

 这是问题中最重要的边缘情况。 如果广告仅包含被忽略的交互，则点击次数和观看次数均为零。 幼稚的实现可能会尝试除以零并产生错误或`NULL`。 

该解决方案使用安全地处理这个问题`IFNULL`，将未定义的结果转换为`0.00`。 

## 没有浏览量但有点击量的广告

 广告可能只包含点击的操作。 在这种情况下：$$CTR = \frac{clicks}{clicks} \times 100 = 100$$一些不正确的实现错误地除以总行数，包括忽略的操作。 查询正确排除了被忽略的操作并生成`100.00`。 

## 具有相同点击率值的广告

 两个广告在舍入后可以具有相同的 CTR 值。 该问题需要使用升序来解决关系`ad_id`。 

该查询明确包括：```
ORDER BY ctr DESC, ad_id ASC
```这保证了确定性和正确的排序。 

## 浮点精度

 CTR 值通常会产生重复的小数，例如`66.6666...`。 如果没有显式舍入，输出可能与预期格式不完全匹配。 

实现使用：```
ROUND(value, 2)
```确保每个结果都按要求精确包含两位小数。
