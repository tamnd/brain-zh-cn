[LeetCode 问题 1389](https://leetcode.com/problems/create-target-array-in-the-given-order/)

 **难度：** 🟢简单
 **主题：** 数组、模拟

 ## 解决方案

 ## 问题理解

 这个问题要求我们建立一个新的数组，名为`target`通过遵循一系列插入操作。 我们有两个数组，`nums`和`index`，其中两个数组具有相同的长度。 在每个位置`i`，值`nums[i]`必须插入到`target`数组位于位置`index[i]`。 

重要的细节是，插入意味着将元素放置在指定位置并将任何现有元素向右移动。 这与分配或替换不同。 如果该索引处已经有元素，它们不会被覆盖，而是移动一步以腾出空间。 

我们从左到右处理数组。 最初，`target`是空的。 在每一步中，我们都会读取这对`(nums[i], index[i])`，将数字插入到需要的位置，继续，直到处理完所有元素。 

输入包括：

 -`nums`，包含要插入的值的整数数组。 
-`index`，包含插入位置的整数数组。 

预期的输出就是最终的结果`target`按顺序执行每个插入操作后的数组。 

限制相对较小：

 - 两个数组的长度最多为`100`-`nums.length == index.length`-`0 <= index[i] <= i`条件`0 <= index[i] <= i`非常重要，因为它保证每个插入都是有效的。 在步骤`i`， 这`target`数组已经完全包含`i`元素，表示之间的插入索引`0`和`i`总是合法的。 

由于输入大小很小，因此我们不需要高度复杂的优化。 即使二次解也是完全可以接受的`n <= 100`。 

一些边缘情况值得注意。 最小的可能输入仅包含一个元素，这意味着算法应该正确初始化并返回一个单元素数组。 当索引处重复发生插入时会发生另一个重要情况`0`，迫使所有现有元素每次都向右移动。 类似地，在当前结束位置插入的行为类似于普通的追加操作。 该问题保证永远不会发生无效索引，因此我们不需要超出标准插入行为的边界检查。 

## 方法

 ### 蛮力方法

 解决该问题的一个直接方法是使用数组手动模拟插入。 

对于每个`(nums[i], index[i])`对，我们通过移动之后的每个元素来在所需位置创建空间`index[i]`向右一个位置。 一旦有可用空间，我们就放置`nums[i]`到正确的位置。 

这种方法是正确的，因为它直接遵循问题陈述。 每次插入都会完全按照描述修改目标数组。 

然而，移动元件是昂贵的。 在最坏的情况下，如果每次插入都发生在数组开头附近，我们可能会为每个操作移动几乎所有现有元素。 由于有`n`插入并且每次插入可能需要最多`O(n)`变化，总时间复杂度变为`O(n²)`。 

### 最佳方法

 关键的观察是大多数编程语言已经提供动态数组插入功能。 

我们可以简单地维护一个不断增长的元素，而不是手动移动元素`target`使用内置操作直接列出和插入元素：

 - 在Python中，使用`list.insert(index, value)`- 在 Go 中，使用切片操作`append`尽管插入仍然会在内部移动元素，但这种方法更简单、更干净，并且对于给定的约束非常有效。 

由于在最坏的情况下插入动态数组仍然需要移动元素，所以时间复杂度仍然存在`O(n²)`。 然而，鉴于`n <= 100`，这已经足够了。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 每次插入时手动移动元素 |
 | 最佳 | O(n²) | O(n) | 使用动态数组插入操作 |

 ## 算法演练

 1. 初始化一个空数组，名为`target`。 
2. 迭代两者`nums`和`index`从左到右使用相同的索引`i`。 这个顺序很重要，因为该问题明确要求按顺序处理插入。 
3. 在每一步中，检索：

 -`nums[i]`，要插入的值
 -`index[i]`，应该插入的位置
 4. 插入`nums[i]`进入`target`在位置`index[i]`。 该位置或该位置之后已存在的任何元素都会自动向右移动一位。 
5. 继续，直到处理完所有元素。 
6.返回填写完毕的`target`大批。 

### 为什么它有效

 该算法之所以有效，是因为它准确地模拟了问题陈述中描述的过程。 处理完第一条后`i`元素, 的`target`数组始终代表正确的中间状态。 每次插入都会保留先前操作建立的顺序，同时将新元素放置在所需的位置。 由于我们按顺序处理所有插入，因此最终结果必须与预期的目标数组匹配。 

## Python 解决方案```python
from typing import List

class Solution:
    def createTargetArray(self, nums: List[int], index: List[int]) -> List[int]:
        target = []

        for i in range(len(nums)):
            target.insert(index[i], nums[i])

        return target
```实现首先创建一个名为的空列表`target`。 

然后我们迭代每个索引`nums`和`index`。 由于保证两个数组具有相同的长度，因此我们可以安全地对两个数组使用相同的循环索引。 

对于每个职位`i`，我们称`target.insert(index[i], nums[i])`。 蟒蛇的`insert`方法会自动将元素放置在请求的位置，并在必要时将现有元素向右移动。 

最后，所有插入完成后，我们返回`target`。 

该实现紧密反映了算法并直接对问题陈述进行建模，使其易于理解和验证。 

## 解决方案```go
func createTargetArray(nums []int, index []int) []int {
	target := make([]int, 0)

	for i := 0; i < len(nums); i++ {
		pos := index[i]

		target = append(target[:pos],
			append([]int{nums[i]}, target[pos:]...)...)
	}

	return target
}
```Go 实现使用切片操作，因为 Go 切片不提供像 Python 列表那样的内置插入方法。 

在位置插入一个元素`pos`，我们将切片分为两部分：

 -`target[:pos]`, 插入点之前的元素
 -`target[pos:]`, 插入点及其之后的元素

 然后我们构造一个新切片，其中`nums[i]`放置在这两个部分之间`append`。 

与 Python 不同，Go 需要显式的切片操作来模拟插入行为。 由于这个问题中的整数很小并且数组大小很小，因此不存在整数溢出的问题。 另外，返回一个空切片与`nil`这里并不重要，因为该函数总是构建并返回一个有效的切片。

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n²) | 每个插入可能会移动到`n`元素|
 | 空间| O(n) | 目标数组存储所有`n`元素|

 时间复杂度为`O(n²)`因为插入到数组的中间或前面需要移动现有元素。 在最坏的情况下，每次插入都发生在索引处`0`，大致产生`1 + 2 + ... + n`运营。 

空间复杂度为`O(n)`因为我们存储的结果目标数组恰好包含`n`元素。 不使用与输入大小成比例的附加数据结构。

 ## 边缘情况

 ### 单元素输入

 最小的有效输入仅包含一个数字。 有缺陷的实现可能会意外地错误处理初始化或返回空结果。 我们的实现自然地处理了这个问题，因为循环运行一次并将单个值插入到最初为空的数组中。 

### 前面重复插入

 输入如`index = [0,0,0,0]`强制将每个新元素插入到开头。 这是错误的常见来源，因为现有元素每次都必须正确移动。 Python 和 Go 中的内置插入逻辑可确保正确处理移位。 

### 在末尾插入

 当`index[i] == len(target)`，该操作的行为类似于追加到数组。 某些实现错误地以不同方式对待插入和追加，或者引入越界错误。 由于该问题保证了有效的索引，因此以当前大小插入始终是安全的，并且两种实现都正确支持这种情况。 

### 重复的数字

 该问题不需要值`nums`是独一无二的。 有缺陷的解决方案可能会在操纵头寸时意外地依赖价值的唯一性。 我们的方法仅取决于插入顺序和索引，因此重复值的处理不会出现问题。
