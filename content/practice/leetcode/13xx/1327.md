[LeetCode 问题 1327](https://leetcode.com/problems/list-the-products-ordered-in-a-period/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题要求我们列出在 **2020 年 2 月** 订购的所有产品，总数量至少为 100 件。 我们有两张表：`Products`和`Orders`。 这`Products`表包含有关每个产品的元数据，包括其独特的`product_id`和`product_name`。 这`Orders`表记录了每个产品的订单`product_id`，订单日期（`order_date`) 和数量 (`unit`）。 

我们预计仅**汇总** 2020 年 2 月每种产品的订购总数，过滤总数达到或超过 100 件的产品，并返回其`product_name`以及计算出的总和。 结果中的行顺序并不重要。 

限制和影响包括同一产品在不同日期甚至同一日期的多个订单必须正确求和，并且某些产品在 2020 年 2 月可能没有任何订单。边缘情况包括恰好有 100 个单位的产品、有 2 月份以外订单的产品或零订单的产品。 解决方案必须正确处理这些问题。 

## 方法

 **暴力方法**需要扫描整个`Orders`表，按月份和年份手动过滤，按以下方式对订单进行分组`product_id`，并对单位求和。 然后，对于每个产品，我们将加入`Products`表来得到`product_name`并按 100 个单位的阈值进行过滤。 虽然这是正确的，但它不必要地冗长，并且对于大型表来说，如果在 SQL 之外（例如，在应用程序代码中）完成，效率可能会很低。 

**最佳解决方案**直接利用 SQL 聚合函数。 通过筛选 2020 年 2 月的订单`WHERE`子句，分组依据`product_id`，对单位求和，应用`HAVING`用于过滤总和≥100的子句，最后加入`Products`要得到`product_name`，我们通过单个 SQL 查询有效地获得了正确的结果。 这种方法使用数据库引擎的优化和索引，使其适合大型数据集。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) 扫描 + 手动聚合 | 分组 O(p) | 在应用程序代码中完成过滤和求和 |
 | 最佳| SQL 中的 O(n) 扫描 + O(p) 聚合 | 分组 O(p) | 高效使用 SQL 聚合、过滤和连接 |

 这里，`n`是行数`Orders`和`p`是产品的数量。 

## 算法演练

 1. 过滤`Orders`表仅包含其中的行`order_date`是在 2020 年 2 月。这确保我们只考虑该期间的相关订单。 
2. 对筛选后的订单进行分组`product_id`。 这使我们能够计算每种产品的总单位数。 
3. 计算总和`unit`对于每个产品组。 这给出了目标期间内订购的总量。 
4. 申请`HAVING`子句仅保留总和大于或等于 100 的组。这会过滤掉销量不足的产品。 
5. 将生成的分组表与`Products`表使用`product_id`得到`product_name`。 
6. 选择`product_name`和汇总的`unit`作为最终输出。 

**为什么有效：** 该算法确保仅考虑 2020 年 2 月内的订单，并且聚合计算每个产品的正确总数。 这`HAVING`子句保证只包含满足阈值的产品，而连接则确保产品名称与其总数正确匹配。 

## Python 解决方案```python
# There is no Python "execution" for pure SQL problems on LeetCode,
# but we provide a template that would work in a database execution context.
# This is written as a string to submit as SQL in Python context.

sql_query = """
SELECT 
    p.product_name,
    SUM(o.unit) AS unit
FROM 
    Orders o
JOIN 
    Products p
ON 
    o.product_id = p.product_id
WHERE 
    o.order_date >= '2020-02-01' AND o.order_date < '2020-03-01'
GROUP BY 
    o.product_id, p.product_name
HAVING 
    SUM(o.unit) >= 100
"""
```**说明：** 此 SQL 查询首先使用日期比较过滤 2020 年 2 月的订单。 然后它分组`product_id`和`product_name`，计算每个产品的总单位数，并使用过滤器`HAVING`仅保留至少 100 件的产品。 连接可确保我们检索到正确的产品名称。

 ## 边缘情况

 **二月份没有订单：**有些产品可能在其他月份有订单，但二月份没有订单。 查询按日期范围进行过滤，因此这些产品被正确排除。 

**恰好 100 单位：**`HAVING SUM(unit) >= 100`确保包含正好 100 件的产品。 这种边界检查可以防止差一错误。 

**同一天同一产品的多个订单：** 该算法将对所有订单进行求和，无论订单中是否有重复的订单`Orders`桌子。 通过分组依据`product_id`，甚至一天内重复的订单也能正确聚合。 

**具有空值的订单：** 由于模式确保`unit`是一个整数并且`product_id`是有效的外键，不应为空。 如果发生这种情况，SQL 将根据设置跳过或出错，但 LeetCode 的约束保证有效输入。
