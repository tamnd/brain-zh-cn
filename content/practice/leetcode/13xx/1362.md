[LeetCode 1362 题](https://leetcode.com/problems/closest-divisors/)

 **难度：** 🟡 中等
 **主题：** 数学

 ## 解决方案

 ## 问题理解

 问题给了我们一个整数`num`，并要求我们找到**两个整数，其乘积等于`num + 1`或者`num + 2`**，使得两个整数之间的绝对差值尽可能小。 

简单来说，我们正在寻找一个因子对`num + 1`或者`num + 2`，并且在所有有效对中，我们想要值最接近的对。 

例如，如果`num = 8`， 然后：

-`num + 1 = 9`，其除数包括`(1,9)`和`(3,3)`-`num + 2 = 10`，其除数包括`(1,10)`和`(2,5)`自从`(3,3)`有一个差异`0`，它小于`(2,5)`，答案是`[3,3]`。 

输入由单个整数组成`num`。 输出应该是一对整数，其乘法等于`num + 1`或者`num + 2`。 顺序并不重要，所以`[25,5]`和`[5,25]`都是有效的。 

约束条件很重要：

 -`1 <= num <= 10^9`一种简单的算法，检查每个除数`num`会太慢，因为`num`最大可达十亿。 这强烈表明我们需要更多的数学观察来减少搜索空间。 

除数的一个重要属性是**一个数字的最接近的因子对总是接近其平方根**。 这一观察结果将是有效解决方案的关键。 

还有一些重要的边缘情况：

 - 非常小的数字，例如`num = 1`， 在哪里`num + 1 = 2`和`num + 2 = 3`，都是素数。 
- 附近的大值`10^9`，其中低效的除数搜索会超时。 
- 一名候选人（`num + 1`) 是质数，而另一个 (`num + 2`) 具有良好的因式分解。 
- 完全平方数，其中最佳答案可能具有相等的约数，例如`(3,3)`为了`9`。 

该问题保证了`num >= 1`，所以我们永远不需要处理零或负值。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是检查两者的每个可能的除数`num + 1`和`num + 2`。 

对于每个目标数：

 1. 迭代所有整数`1`到号码本身。 
2. 检查整数是否能整除目标。 
3. 如果是，则计算配对除数。 
4. 跟踪绝对差值最小的对。 

处理完两个数字后，返回最好的一对。 

这种方法之所以有效，是因为它详尽地检查了每个有效因子对。 由于检查了每个除数，因此肯定会找到最接近的对。 

然而，这种方法对于约束来说太慢了`10^9`。 在最坏的情况下，迭代到数字本身需要大约十亿次操作，这是不切实际的。 

### 最佳方法

 关键的数学见解是**一个数字的最接近的除数对总是最接近其平方根**。 

假设一个数字`n`有约数`(a, b)`在哪里：$$a \times b = n$$如果`a`和`b`靠得很近，它们必须都靠得很近`√n`。 

例如：

-`36 → (6,6)`靠近`√36 = 6`-`40 → (5,8)`靠近`√40 ≈ 6.3`而不是检查所有除数`1`向上，我们可以：

 1. 从`⌊√n⌋`2. 向下移动直到找到除数
 3. 立即归还该对

 为什么这有效？ 因为平方根下方遇到的第一个除数会自动生成最接近的可能对。 

由于我们只检查数字到平方根，所以运行时间变成`O(√n)`而不是`O(n)`。 

我们对两者重复此过程`num + 1`和`num + 2`，然后选择差异较小的一对。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(1) | O(1) | 检查每个可能的除数 |
 | 最佳 | O(√n) | O(√n) | O(1) | O(1) | 从平方根开始并快速找到最接近的因子对 |

 ## 算法演练

 1. 计算两个候选数：`num + 1`和`num + 2`。 
2. 创建一个辅助函数，查找给定数字最接近的除数对`n`。 
3. 在辅助函数内，计算`⌊√n⌋`。 这是理想的起点，因为最接近的除数对位于平方根附近。 
4. 从平方根向下迭代`1`。 
5. 对于每个候选除数`d`，检查是否`n % d == 0`。 
6. 一旦找到有效的除数：

 - 将配对除数设置为`n // d`- 返回`[d, n // d]`我们可以立即停止，因为从平方根向下找到的第一个除数保证了最小差异。 
7. 为两者运行辅助函数`num + 1`和`num + 2`。 
8. 比较两个结果对的绝对差异。 
9. 返回差异较小的对。 

### 为什么它有效

 正确性来自于因子对的数学性质。 对于一个号码`n`，当一个因子远离时，因子对之间的距离变得更远`√n`。 因此，最接近的除数`√n`产生最小的绝对差值。 通过从平方根向下搜索并在第一个有效除数处停止，我们保证找到最接近的除数对。 对两者重复此操作`num + 1`和`num + 2`，然后选择较小的差异，保证最终答案的正确。 

## Python 解决方案```python
from typing import List
import math

class Solution:
    def closestDivisors(self, num: int) -> List[int]:
        def find_closest_pair(n: int) -> List[int]:
            root = int(math.sqrt(n))

            for divisor in range(root, 0, -1):
                if n % divisor == 0:
                    return [divisor, n // divisor]

            return [1, n]

        pair1 = find_closest_pair(num + 1)
        pair2 = find_closest_pair(num + 2)

        diff1 = abs(pair1[0] - pair1[1])
        diff2 = abs(pair2[0] - pair2[1])

        return pair1 if diff1 <= diff2 else pair2
```实现首先定义一个辅助函数，`find_closest_pair`，计算给定数字的最接近的除数对。 

在这个助手中，我们首先计算整数平方根`n`。 从这一点开始很重要，因为最接近平方根的除数对保证具有最小的差异。 

然后我们从平方根向下迭代。 我们第一次找到一个能整除的除数`n`，我们立即返回这对`[divisor, n // divisor]`。 由于我们首先从最佳区域进行搜索，因此后面的配对不可能更接近。 

回到主方法，我们评估两个候选值，`num + 1`和`num + 2`。 我们计算每一对之间的差异并返回绝对差距较小的一个。 

辅助函数中的回退 return 语句在技术上是不必要的，因为每个正整数都可以被整除`1`，但它保持了功能结构的完整性。 

## 解决方案```go
package main

import "math"

func closestDivisors(num int) []int {
	findClosestPair := func(n int) []int {
		root := int(math.Sqrt(float64(n)))

		for divisor := root; divisor >= 1; divisor-- {
			if n%divisor == 0 {
				return []int{divisor, n / divisor}
			}
		}

		return []int{1, n}
	}

	pair1 := findClosestPair(num + 1)
	pair2 := findClosestPair(num + 2)

	diff1 := abs(pair1[0] - pair1[1])
	diff2 := abs(pair2[0] - pair2[1])

	if diff1 <= diff2 {
		return pair1
	}

	return pair2
}

func abs(x int) int {
	if x < 0 {
		return -x
	}
	return x
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 由于 Go 没有内置的整数绝对值函数，因此我们实现了一个小辅助函数`abs`。 

平方根计算使用`math.Sqrt`，这需要将整数转换为`float64`，然后将结果转换回`int`。 

切片用于返回除数对，因为 Go 没有像 Python 那样的轻量级列表类型。 该算法仍然使用恒定的额外空间，因为只分配了几个整数和微小的切片。

 ## 边缘情况

 ### 非常小的输入

 当`num = 1`，我们评估`2`和`3`，两者都是素数。 唯一有效的除数对是`(1,2)`和`(1,3)`。 有缺陷的实现可能会假设除数大于`1`总是存在，但我们的算法安全地回退到`1`向下搜索后。 

### 完全平方候选者

 如果其中之一`num + 1`或者`num + 2`是完全平方数，最优对可能具有相等的约数。 例如，`num = 8`给出`9 = 3 × 3`。 由于相同的数字有差异`0`，这自动是最优的。 从平方根开始确保我们立即找到这种情况。 

### 接近约束极限的大数

 对于接近的输入`10^9`，暴力方法变得不可行。 搜索每个除数直到数字本身会花费太长时间。 我们的实现仅检查数字到平方根，这将最大迭代限制为大约`31,623`，保持性能高效。 

### 素数或近素数

 有时两者兼而有之`num + 1`和`num + 2`可能有很少的约数。 例如，如果一个候选者是素数，则唯一有效的分解是`(1,n)`。 该算法仍然表现正确，因为它最终达到`1`，保证有效的除数对。
