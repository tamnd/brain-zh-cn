 # LeetCode 1368 - 在网格中创建至少一条有效路径的最低成本

 ## 问题理解

 这个问题给了我们一个二维网格，其中每个单元格都包含一个方向符号。 该标志告诉我们下一步应该移动到哪个相邻单元格。 四个可能的方向是：

 -`1`意味着向右移动
 -`2`意味着向左移动
 -`3`意味着向下移动
 -`4`意味着向上移动

 我们总是从左上角开始`(0, 0)`并希望最终到达右下角`(m - 1, n - 1)`。 

重要的细节是我们可以修改任何单元格的方向，并且每次修改都会花费`1`。 一个单元只能修改一次，但由于我们只关心构建单个有效路径，因此该限制不会产生额外的复杂性。 

目标是确定所需的最小总修改成本，以便从起始单元格到目标单元格至少存在一条有效路径。 

如果我们沿着单元格当前的箭头方向移动，则认为移动是自由的。 如果我们想朝不同的方向前进，就必须付出代价`1`更改该箭头。 

这自然就变成了最短路径问题：

 - 每个网格单元都是一个节点
 - 从一个单元格移动到相邻单元格是一种边缘
 - 边缘成本为：

 -`0`如果移动遵循现有箭头
 -`1`如果我们必须修改箭头

 我们必须找到最小总成本路径`(0, 0)`到`(m - 1, n - 1)`。 

约束条件很重要：

 -`m, n <= 100`- 最大细胞数为`10,000`对所有可能的箭头修改进行强力搜索是完全不可行的，因为每个单元格都有多种可能的状态。 我们需要一种高效的图最短路径算法。 

一些边缘情况很重要：

 - 有效路径可能已经存在，答案是`0`- 箭头可能指向网格之外
 - 最佳路径可能会在概念上重新访问区域，但最短路径算法可以防止不必要的重复工作
 - A`1 x 1`网格已经在目的地开始，所以答案是`0`## 方法

 ### 蛮力方法

 暴力解决方案将尝试箭头修改的所有可能组合并检查是否存在有效路径。 

对于每个单元格，理论上我们可以选择四个方向之一。 由于有`m * n`单元格，可能的配置数量变为：$$4^{m \times n}$$对于每个配置，我们都会模拟从左上角到右下角单元格是否存在有效路径。 

这种方法是正确的，因为它详尽地探索了所有可能的箭头分配，保证最终找到最小成本的有效配置。 

然而，计算上不可能达到`100 x 100`。 即使是小得多的网格也已经产生了天文数字数量的状态。 

### 最佳方法，0-1 BFS

 关键的见解是，这并不是真正的网格修改问题。 这是一个只有两种可能的边权重的最短路径问题：

 -`0`如果我们沿着当前的箭头前进
 -`1`如果我们改变箭头

 每当所有边权重都是`0`或者`1`，我们可以使用一种专门的最短路径算法，称为 **0-1 BFS**。 

0-1 BFS 背后的想法是：

 - 使用双端队列代替优先队列
 - 如果搬到邻居需要费用`0`,将其推到前面
 - 如果搬到邻居需要费用`1`，把它推到后面

 这保证了单元按照总成本递增的顺序进行处理，类似于 Dijkstra 算法，但效率更高。 

每个单元被视为一个图节点，每个相邻的移动代表一条具有成本的边`0`或者`1`。 

由于每个节点和边仅处理有限次数，因此即使对于最大的约束，该算法也能高效运行。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(4^(m*n)) | O(4^(m*n)) | O(m*n) | 尝试所有可能的箭头修改 |
 | 最优，0-1 BFS | O(m*n) | O(m*n) | 使用边缘权重为 0 或 1 的双端队列 |

 ## 算法演练

 ### 第 1 步：定义方向映射

 我们将每个方向数映射到其相应的运动：

 | 方向 | 运动 |
 | ---| ---|
 | 1 | 正确的`(0, 1)`|
 | 2 | 左边`(0, -1)`|
 | 3 | 向下`(1, 0)`|
 | 4 | 向上`(-1, 0)`|

 这让我们可以轻松比较移动是否遵循现有箭头。 

### 步骤 2：初始化距离矩阵

 我们创建一个`distance`矩阵其中：

 -`distance[r][c]`存储到达小区所需的最低成本`(r, c)`最初：

 - 所有值都是无穷大
 -`distance[0][0] = 0`该矩阵可以防止不必要的重访，从而降低成本。 

### 步骤 3：初始化双端队列

 我们使用双端队列来实现 0-1 BFS。 

双端队列最初包含：```
(0, 0)
```代表起始单元格。 

### 步骤 4：处理双端队列中的单元

 当双端队列不为空时：

 1. 拆下前面的电池
 2. 探索所有四个相邻方向
 3. 确定移动成本：

 -`0`如果移动与当前箭头匹配
 -`1`否则
 4. 计算新的总成本
 5. 如果新的成本改善了邻居的距离：

 - 更新距离
 - 推送至：

 - 前面如果成本是`0`- 如果成本是则返回`1`### 第 5 步：继续直至到达目的地

 因为 0-1 BFS 按递增成本顺序处理状态，所以我们第一次确定目标成本时，就保证它是最优的。 

最终的答案是：```
distance[m - 1][n - 1]
```### 为什么它有效

 该算法将网格建模为一个图表，其中每个动作都有权重`0`或者`1`。 0-1 BFS是专门为此类图设计的，保证节点按照最短距离的非递减顺序进行处理。 

每当找到通往单元的更好路径时，双端队列放置都会确保更早地处理更便宜的状态。 因此，一旦算法完成，每个单元格记录的距离就是可能的最小修改成本。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def minCost(self, grid: List[List[int]]) -> int:
        rows = len(grid)
        cols = len(grid[0])

        directions = {
            1: (0, 1),    # right
            2: (0, -1),   # left
            3: (1, 0),    # down
            4: (-1, 0)    # up
        }

        distance = [[float('inf')] * cols for _ in range(rows)]
        distance[0][0] = 0

        deque_01 = deque([(0, 0)])

        while deque_01:
            row, col = deque_01.popleft()

            current_cost = distance[row][col]

            for direction_value, (dr, dc) in directions.items():
                next_row = row + dr
                next_col = col + dc

                if not (0 <= next_row < rows and 0 <= next_col < cols):
                    continue

                extra_cost = 0 if grid[row][col] == direction_value else 1

                new_cost = current_cost + extra_cost

                if new_cost < distance[next_row][next_col]:
                    distance[next_row][next_col] = new_cost

                    if extra_cost == 0:
                        deque_01.appendleft((next_row, next_col))
                    else:
                        deque_01.append((next_row, next_col))

        return distance[rows - 1][cols - 1]
```该实现首先存储网格尺寸并构建方向映射。 此映射将每个箭头值转换为其相应的行和列移动。 

这`distance`矩阵存储到达每个单元格所需的最小修改成本。 最初，所有单元格都设置为无穷大，因为除非另有证明，否则它们无法到达。 

双端队列是0-1 BFS的核心结构。 无需额外成本即可到达的单元被推到前面，而需要修改的单元被推到后面。 这种排序确保始终首先探索成本较低的路径。 

对于每个弹出的单元格，算法会检查所有四个可能的方向。 如果所选的移动与当前单元格的箭头匹配，则移动成本`0`。 否则搬家费用`1`因为我们必须修改标志。 

每当找到到邻居的更便宜的路径时，就会更新距离并将邻居插入到双端队列中的适当位置。 

最后，该算法返回为右下单元格存储的最小成本。 

## 解决方案```go
package main

import "container/list"

func minCost(grid [][]int) int {
	rows := len(grid)
	cols := len(grid[0])

	directions := [][]int{
		{},
		{0, 1},   // right
		{0, -1},  // left
		{1, 0},   // down
		{-1, 0},  // up
	}

	const INF = int(1e9)

	distance := make([][]int, rows)
	for i := range distance {
		distance[i] = make([]int, cols)
		for j := range distance[i] {
			distance[i][j] = INF
		}
	}

	type State struct {
		row int
		col int
	}

	deque := list.New()

	distance[0][0] = 0
	deque.PushFront(State{0, 0})

	for deque.Len() > 0 {
		front := deque.Front()
		current := front.Value.(State)
		deque.Remove(front)

		row := current.row
		col := current.col

		currentCost := distance[row][col]

		for direction := 1; direction <= 4; direction++ {
			dr := directions[direction][0]
			dc := directions[direction][1]

			nextRow := row + dr
			nextCol := col + dc

			if nextRow < 0 || nextRow >= rows || nextCol < 0 || nextCol >= cols {
				continue
			}

			extraCost := 1
			if grid[row][col] == direction {
				extraCost = 0
			}

			newCost := currentCost + extraCost

			if newCost < distance[nextRow][nextCol] {
				distance[nextRow][nextCol] = newCost

				if extraCost == 0 {
					deque.PushFront(State{nextRow, nextCol})
				} else {
					deque.PushBack(State{nextRow, nextCol})
				}
			}
		}
	}

	return distance[rows-1][cols-1]
}
```Go 实现遵循与 Python 版本完全相同的逻辑，但使用 Go 的`container/list`包来实现 0-1 BFS 所需的双端队列。 

定制`State`struct 存储行和列坐标。 距离矩阵使用嵌套切片进行初始化。 

由于 Go 不直接为整数提供无穷大值，因此一个大常数`INF`被用来代替。 

其余的实现与 Python 解决方案密切相关。

from typing import List

class Solution:
    def minCost(self, grid: List[List[int]]) -> int:
        from collections import deque

        rows = len(grid)
        cols = len(grid[0])

        directions = {
            1: (0, 1),
            2: (0, -1),
            3: (1, 0),
            4: (-1, 0)
        }

        distance = [[float('inf')] * cols for _ in range(rows)]
        distance[0][0] = 0

        dq = deque([(0, 0)])

        while dq:
            row, col = dq.popleft()

            for direction, (dr, dc) in directions.items():
                nr = row + dr
                nc = col + dc

                if not (0 <= nr < rows and 0 <= nc < cols):
                    continue

                extra = 0 if grid[row][col] == direction else 1
                new_cost = distance[row][col] + extra

                if new_cost < distance[nr][nc]:
                    distance[nr][nc] = new_cost

                    if extra == 0:
                        dq.appendleft((nr, nc))
                    else:
                        dq.append((nr, nc))

        return distance[-1][-1]

 ## 边缘情况

 ### 单细胞网格

 一个`1 x 1`网格是一种特殊情况，因为起点和目的地是同一个单元格。 不需要移动，所以答案必须始终是`0`。 

幼稚的实现有时会尝试不必要的遍历逻辑或失败，因为没有有效的邻居。 此实现可以自然地处理这种情况，因为起始距离被初始化为`0`，算法立即返回该值。 

### 箭头指向网格之外

 某些单元格可能包含超出网格边界的箭头。 这些方向对于遍历来说实际上是无用的。 

有缺陷的实现可能会尝试无效的数组访问。 该解决方案在探索邻居之前安全地检查边界，防止超出范围的错误。 

### 多个可能的路径

 到达目的地的方式可能有多种，改装成本也不同。 

始终遵循现有箭头的贪婪策略可能会失败，因为短期昂贵的修改可能会带来更便宜的整体路线。 

0-1 BFS 按递增成本顺序正确评估所有可达状态，保证找到全局最小修改成本。
