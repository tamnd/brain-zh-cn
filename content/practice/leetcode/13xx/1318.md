[LeetCode 第 1318 题](https://leetcode.com/problems/minimum-flips-to-make-a-or-b-equal-to-c/)

 **难度：** 🟡 中等
 **主题：** 位操作

 ## 解决方案

 ## 问题理解

 该问题给了我们三个正整数，`a`,`b`， 和`c`。 我们可以翻转其中的各个位`a`或者`b`。 翻转意味着稍微改变`0`到`1`或来自`1`到`0`。 

我们的目标是执行最少数量的位翻转，以便：```
(a OR b) == c
```OR 运算是逐位进行的。 对于每个位位置：

 -`0 OR 0 = 0`-`0 OR 1 = 1`-`1 OR 0 = 1`-`1 OR 1 = 1`这意味着对于每个位位置，结果位`(a OR b)`必须与中的相应位完全匹配`c`。 

重要的观察是每个位位置完全独立于其他位置。 针对一位做出的决定不会影响任何其他位。 因此，我们可以一次一位地处理整数。 

限制条件是：```
1 <= a, b, c <= 10^9
```自从`10^9`适合 30 位以内，我们只需要检查大约 30 到 31 位位置。 这立即表明位操作解决方案将非常有效。 

有几个重要的边缘情况需要考虑：

 - 当`(a OR b)`已经等于`c`，答案应该是`0`。 
- 有点进去的时候`c`是`0`，两个对应位`a`和`b`必须成为`0`。 如果目前两者都`1`，我们需要两次翻转。 
- 有点进去的时候`c`是`1`，至少有一个对应位`a`或者`b`必须是`1`。 如果目前两者都`0`，我们需要翻转一次。 
- 附近的大值`10^9`仍然只需要检查固定数量的位。 

## 方法

 ### 蛮力方法

 蛮力方法会尝试所有可能的翻转组合`a`和`b`直到找到一个配置：```
(a OR b) == c
```对于每个位位置，有多种可能性：

 - 保持该位不变
 - 将钻头翻转进去`a`- 将钻头翻转进去`b`- 翻转两个位

 如果大约有 30 位，则可能的配置数量将呈指数级增长。 探索每一种组合在计算上是不可行的。 

虽然蛮力最终会产生正确的答案，因为它探索了所有可能性，但对于给定的约束来说它太慢了。 

### 最优逐位贪心法

 关键的见解是“或”在每个位位置上独立运行。 

对于每一位：

 - 如果目标位在`c`是`1`，我们只需要至少一位`a`或者`b`成为`1`。 
- 如果目标位在`c`是`0`，两个位都在`a`和`b`必须是`0`。 

这意味着我们可以独立确定每个位所需的最小翻转次数并将它们相加。 

对于单个位位置：

 - 如果`c_bit == 1`- 如果有的话`a_bit`或者`b_bit`已经是`1`，无需翻转。 
- 否则，只需翻转一次。 
- 如果`c_bit == 0`- 任何`1`位在`a`或者`b`必须翻转到`0`。 
- 这可能需要零次、一次或两次翻转。 

由于我们只检查每个位一次，因此该算法非常有效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(4^B) | O(4^B) | O(1) | O(1) | 尝试 B 位上所有可能的翻转组合 |
 | 最佳| O(B) | O(1) | O(1) | 使用位操作独立处理每个位 |

 这里，`B`是位数，对于给定的约束大约为 30。 

## 算法演练

 1. 初始化变量`flips`到`0`。 
2. 处理位`a`,`b`， 和`c`一次一个位置。 
3. 使用以下方法提取每个数字的最低有效位：```
a_bit = a & 1
b_bit = b & 1
c_bit = c & 1
```4. 如果`c_bit`是`1`，那么该位置的 OR 结果也一定是`1`。 

- 如果有的话`a_bit`或者`b_bit`已经是`1`，无需执行任何操作。 
- 如果两者都是`0`，我们必须翻转一位`0`到`1`。 
- 添加`1`到`flips`在这种情况下。 
5.如果`c_bit`是`0`，那么两者`a_bit`和`b_bit`必须成为`0`。 

- 如果`a_bit`是`1`，必须翻转。 
- 如果`b_bit`是`1`，也必须翻转。 
- 添加`a_bit + b_bit`到`flips`。 
6. 将所有三个数字右移一位：```
a >>= 1
b >>= 1
c >>= 1
```7. 继续，直到处理完所有位。 
8.返回累计值`flips`。 

### 为什么它有效

 该算法之所以有效，是因为“或”运算对于每个位位置都是独立的。 一位所需的最小翻转不会影响任何其他位。 因此，单独计算每个位的最佳答案并对结果求和即可产生全局最小翻转次数。 

## Python 解决方案```python
class Solution:
    def minFlips(self, a: int, b: int, c: int) -> int:
        flips = 0

        while a > 0 or b > 0 or c > 0:
            a_bit = a & 1
            b_bit = b & 1
            c_bit = c & 1

            if c_bit == 1:
                if a_bit == 0 and b_bit == 0:
                    flips += 1
            else:
                flips += a_bit + b_bit

            a >>= 1
            b >>= 1
            c >>= 1

        return flips
```实现直接遵循算法。 

变量`flips`存储所需位更改的总数。 

在循环内部，我们使用按位与从每个数字中提取当前最低有效位`1`。 这隔离了当前位的位置。 

什么时候`c_bit`是`1`，我们验证是否至少有一个`a_bit`或者`b_bit`已经是`1`。 如果两者都是`0`，需要翻转一次。 

什么时候`c_bit`是`0`， 每一个`1`咬进去`a`或者`b`必须被删除。 自从`a_bit`和`b_bit`是`0`或者`1`，直接将它们相加即可得出该位置所需的确切翻转次数。 

最后，右移将下一位移动到最低有效位置进行处理。 

## 解决方案```go
func minFlips(a int, b int, c int) int {
    flips := 0

    for a > 0 || b > 0 || c > 0 {
        aBit := a & 1
        bBit := b & 1
        cBit := c & 1

        if cBit == 1 {
            if aBit == 0 && bBit == 0 {
                flips++
            }
        } else {
            flips += aBit + bBit
        }

        a >>= 1
        b >>= 1
        c >>= 1
    }

    return flips
}
```Go 实现与 Python 版本几乎相同。 

Go 使用显式变量声明`:=`，循环条件使用 Go 的布尔语法`||`。 

整数溢出不是一个问题，因为输入约束相对于 Go 的整数容量来说很小。

 ## 边缘情况

 当两者都存在时，就会出现一种重要的边缘情况`a`和`b`包含一个`1`一会儿`c`包含一个`0`位在同一位置。 一个常见的错误是将其算作一次翻转，因为 OR 结果已经是`1`。 然而，这两个位必须成为`0`，所以需要翻转两次。 该实现通过添加正确处理这个问题`a_bit + b_bit`。 

另一个重要的情况是当双方`a`和`b`包含`0`位同时`c`包含一个`1`少量。 在这种情况下，只需翻转一次就足够了，因为两个数字中只有一个需要`1`少量。 该算法正确地将答案加一。 

第三种边缘情况涉及已经满足条件的输入`(a OR b) == c`。 如果某些实现没有仔细区分翻转，它们可能会意外地过度计数翻转。`c_bit == 0`和`c_bit == 1`案例。 该解决方案不执行不必要的操作并正确返回`0`。 

最后，由于该算法仅处理单个位，因此可以有效地处理接近上限的大整数。 由于只需检查大约 30 位，因此运行时间实际上保持不变。
