 # LeetCode 1380 - 矩阵中的幸运数字

 ## 问题理解

 这个问题要求我们识别给定矩阵中的所有**幸运数字**。 

幸运数字被定义为同时满足**两个条件**的值：

 1. 必须是**该行中的最小值**
 2.它必须是**其列中的最大值**

 我们被赋予了一个`m x n`矩阵，其中每个元素都是**不同的**，这意味着没有两个数字是相同的。 目标是返回每个符合幸运数字资格的元素。 结果可以以**任何顺序**返回。 

让我们用更简单的术语重述这个问题。 

对于矩阵中的每个元素，我们要确定它是否是其行中所有数字中最小的数字，也是其列中所有数字中最大的数字。 如果两个条件都成立，我们将其包含在结果中。 

例如，考虑这个矩阵：```
[
  [3, 7, 8],
  [9, 11, 13],
  [15, 16, 17]
]
```每行的最小值为：```
3, 9, 15
```每列的最大值为：```
15, 16, 17
```两组中唯一出现的数字是`15`，所以它是唯一的幸运数字。 

这些约束告诉我们有关输入大小的一些有用的信息：

 -`1 <= m, n <= 50`，所以矩阵相对较小。 
- 矩阵值是不同的，这简化了推理，因为我们永远不需要处理关系。 
- 值范围可达`10^5`，但它们的大小并不重要，因为我们只是比较它们。 

由于矩阵大小最多为`50 x 50`，即使是适度昂贵的方法也可以发挥作用。 然而，我们仍然想要一个干净、高效的解决方案。 

一些边缘情况值得预先考虑。 

一个矩阵可能只包含一个元素。 在这种情况下，单个数字自动成为行最小值和列最大值，因此必须返回它。 

矩阵可能只有一行或一列。 在单行中，幸运数字必须是行最小值和列最大值。 在单列中，幸运数字必须是列最大值和行最小值。 

该问题保证所有数字都是不同的，因此我们永远不需要担心重复的最小值或最大值导致歧义。 

## 方法

 ### 蛮力方法

 最直接的方法是单独检查每个单元。 

对于每个元素`matrix[i][j]`，我们可以：

 1. 扫描整行`i`验证该元素是否为最小值。 
2. 扫描整列`j`验证该元素是否为最大值。 
3. 如果两个条件都成立，请将其添加到答案中。 

这种方法很简单并且保证是正确的，因为每个候选者都根据问题定义进行了明确的验证。 

然而，它执行了不必要的重复工作。 对于每个单元格，我们重复扫描与之前检查严重重叠的行和列。 

如果有`m`行和`n`列，每个单元格需要`O(m + n)`工作，并且有`m × n`细胞。 这导致总的复杂性：```
O(m × n × (m + n))
```尽管限制足够小，可以通过，但我们可以做得更好。 

### 最佳方法

 关键的观察是幸运数字必须属于这组**两个**：

 - **行最小值**的集合
 - **列最大值**的集合

 我们可以预先计算这些信息，而不是重复检查每个候选者。 

我们首先计算每一行的最小值。 然后我们计算每列的最大值。 

一旦我们有了这两个集合，任何出现在这两个集合中的数字都是幸运数字。 

集合在这里很有用，因为它允许恒定时间的成员资格检查。 

这避免了冗余扫描，并使解决方案更干净、更高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(m × n × (m + n)) | O(m × n × (m + n)) | O(1) | O(1) | 通过重新扫描行和列来检查每个元素 |
 | 最佳 | O(m × n) | O(m + n) | 预先计算行最小值和列最大值 |

 ## 算法演练

 1. 计算每行的最小值。 

遍历每一行并找到其最小元素。 将所有行最小值存储在一个集合中。 我们使用集合是因为​​稍后我们需要快速的成员资格检查。 
2. 计算每列的最大值。 

对于每个列索引，扫描所有行并确定该列中的最大元素。 将这些值存储在另一组中。 
3.寻找共同点。 

迭代行最小集合并检查每个值是否也存在于列最大集合中。 
4. 将匹配项添加到结果中。 

两个集合中出现的任何数字都满足幸运数字定义，因此将其添加到结果列表中。 
5. 返回结果。 

由于该问题接受任何顺序，因此我们可以直接返回收集到的值。 

### 为什么它有效

 幸运数字必须同时满足两个独立的属性：行最小值和列最大值。 通过计算行最小值的完整集合和列最大值的完整集合，我们保证每个有效的幸运数字都出现在这两个集合中。 同样，出现在两个集合中的任何值都必然满足幸运数字的精确定义。 因此，这两个集合的交集正是正确的答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def luckyNumbers(self, matrix: List[List[int]]) -> List[int]:
        row_mins = {min(row) for row in matrix}

        rows = len(matrix)
        cols = len(matrix[0])

        col_maxes = set()

        for col in range(cols):
            max_value = matrix[0][col]

            for row in range(1, rows):
                max_value = max(max_value, matrix[row][col])

            col_maxes.add(max_value)

        return [num for num in row_mins if num in col_maxes]
```该实现严格遵循上述算法。 

首先，我们使用集合理解计算每行的最小元素：```python
row_mins = {min(row) for row in matrix}
```这为我们提供了满足第一个要求的所有候选人。 

接下来，我们确定每列的最大元素。 由于 Python 矩阵表示为嵌套列表，因此我们逐列迭代并扫描行以计算最大值。 

我们将所有列最大值存储在一个集合中，以进行有效的成员资格检查。 

最后，我们使用列表理解隐式计算交集：```python
[num for num in row_mins if num in col_maxes]
```包含的每个数字都满足两个必需的条件。 

## 解决方案```go
func luckyNumbers(matrix [][]int) []int {
	rows := len(matrix)
	cols := len(matrix[0])

	rowMins := make(map[int]bool)

	for _, row := range matrix {
		minValue := row[0]

		for _, value := range row {
			if value < minValue {
				minValue = value
			}
		}

		rowMins[minValue] = true
	}

	colMaxes := make(map[int]bool)

	for col := 0; col < cols; col++ {
		maxValue := matrix[0][col]

		for row := 1; row < rows; row++ {
			if matrix[row][col] > maxValue {
				maxValue = matrix[row][col]
			}
		}

		colMaxes[maxValue] = true
	}

	result := []int{}

	for num := range rowMins {
		if colMaxes[num] {
			result = append(result, num)
		}
	}

	return result
}
```Go 的实现与 Python 解决方案非常相似。 由于 Go 没有内置的集合类型，我们使用以下方法模拟集合`map[int]bool`。 

行最小值和列最大值存储为映射键，允许恒定时间查找。 

与 Python 不同，Go 需要显式循环来计算最小值和最大值。 我们还在附加结果之前显式初始化切片。 

整数溢出在这里不是问题，因为矩阵值的边界为`10^5`，它很适合 Go 的整数范围。

 ## 边缘情况

 ### 单元素矩阵

 一个`1 x 1`矩阵是最简单的输入。 由于不存在其他元素，单独值自动成为其行中的最小值和列中的最大值。 幼稚的实现可能会意外地错误地处理索引假设，但这种实现很自然，因为行最小值和列最大值集都包含相同的值。 

### 单行或单列

 当矩阵只有一行时，幸运数字必须是行最小值，因为只有当下面不存在更大的值时，每个元素才会自动成为其自己列的列最大值。 类似地，在单列矩阵中，幸运数字成为该列中的最大元素，同时也是其行中的最小值。 该算法无需特殊逻辑即可处理这两种情况。 

### 不存在幸运数字

 尽管许多示例包含一个幸运数字，但某些矩阵可能不包含一个。 不正确的实现可能会假设总会有结果。 在这里，如果行最小值和列最大值之间的交集为空，则算法仅返回一个空列表。 

### 独特的价值保证

 该问题保证所有数字都是不同的。 这可以避免在确定最小值和最大值时出现歧义。 我们的实现并不严重依赖这种保证，但它确保不存在可能使幸运数字的推理复杂化的联系。
