[LeetCode 第 1326 题](https://leetcode.com/problems/minimum-number-of-taps-to-open-to-water-a-garden/)

 **难度：** 🔴难
 **主题：** 数组、动态规划、贪心

 ## 解决方案

 ## 问题理解

 该问题描述了一个从位置延伸的一维花园`0`定位`n`。 在每个整数位置`i`，周围有一个水龙头可以浇水。 具体来说，如果点击`i`打开后，它覆盖了区间：$$[i - ranges[i],\ i + ranges[i]]$$目标是确定所需的最少水龙头数量，以便花园中的每个点`0`通过`n`被至少一个水龙头覆盖。 

这从根本上来说是一个区间覆盖问题。 每次点击都会在数轴上创建一个区间，我们希望选择能够完全覆盖的最小数量的区间`[0, n]`。 

输入包括：

 - 一个整数`n`，代表花园长度。 
- 一个数组`ranges`尺寸的`n + 1`。 
- 每个`ranges[i]`指示轻击的距离`i`可以向左、向右喷射。 

输出应该是：

 - 覆盖整个花园所需的最少水龙头数量。 
-`-1`如果不可能完全覆盖。 

约束条件很重要：

 -`n <= 10^4`-`ranges[i] <= 100`自从`n`适度大时，指数或二次强力解决方案可能会变得太慢。 我们需要接近线性时间的东西。 

一些边缘情况尤其重要：

 - 所有水龙头的范围可能为零，从而无法覆盖。 
- 一个水龙头可能已经覆盖整个花园。 
- 间隔之间可能存在间隙。 
- 多次点击可能会严重重叠。 
- 某些间隔可能会超出`0`或者`n`，这是可以接受的，应该简单地从逻辑上限制。 

关键的挑战是在保证连续覆盖的同时最大限度地减少所选间隔的数量。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试所有抽头组合并检查所选组是否覆盖整个间隔`[0, n]`。 

对于每个抽头子集：

 1. 计算覆盖的区间。 
2. 合并重叠的区间。 
3. 检查是否`[0, n]`已完全覆盖。 
4. 跟踪所用的最少敲击次数。 

这种方法是正确的，因为它详尽地探索了所有可能的选择。 然而，这在计算上是不可行的。 

有`2^(n+1)`抽头的可能子集。 即使对于相对较小的值`n`，这变得天文数字般大。 

稍微改进的蛮力方法可能会在一定时间间隔内使用动态规划，但即使这样仍然可能变得二次或更糟。 

### 关键见解

 这个问题等价于经典的“覆盖线段的最小间隔”问题，可以贪心求解。 

重要的观察是：

 对于每个起始位置，我们只关心覆盖范围最远的水龙头。 

这将问题转化为与 Jump Game II 问题非常相似的问题。 

我们对间隔进行预处理，以便：

 -`max_reach[left]`存储从位置可到达的最远右端点`left`。 

然后我们贪婪地扩大覆盖范围：

 - 在每一步中，我们选择尽可能远地扩展当前可达边界的间隔。 
- 当我们耗尽当前的覆盖范围时，我们必须打开另一个水龙头。 

这种贪婪策略之所以有效，是因为选择最远的区间总是能保留最优解。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n * n) | O(2^n * n) | O(n) | 尝试每个水龙头子集 |
 | 最优贪心 | O(n) | O(n) | 将间隔转换为跳跃游戏风格的覆盖范围 |

 ## 算法演练

 ### 第 1 步：将拍子转换为间隔

 每次点击`i`涵盖：$$[i - ranges[i],\ i + ranges[i]]$$我们计算：

 -`left = max(0, i - ranges[i])`-`right = min(n, i + ranges[i])`这给出了花园边界内的有效间隔。 

### 第 2 步：构建最远到达阵列

 我们创建一个数组：```
max_reach[left]
```对于每个间隔`[left, right]`，我们存储：```
max_reach[left] = max(max_reach[left], right)
```这意味着：

 - 从位置开始`left`,
 - 我们可以获得的最远覆盖范围是`right`。 

### 步骤3：执行贪婪区间扩展

 我们现在迭代`0`到`n`。 

我们维护三个变量：

 -`taps_used`-`current_end`-`farthest`它们的含义是：

 -`current_end`是当前选定的抽头覆盖的边界。 
-`farthest`是扫描当前间隔内的位置时可到达的最远边界。 
-`taps_used`计算我们打开了多少个水龙头。 

### 步骤 4：扩展最远可达边界

 在每个位置`i`：```
farthest = max(farthest, max_reach[i])
```这模拟了考虑开始于或之前的所有间隔`i`。 

### 步骤 5：检测不可能的覆盖范围

 如果：```
i > farthest
```那么没有区间可以覆盖位置`i`。 

在这种情况下，返回`-1`。 

### 步骤 6：必要时打开新水龙头

 每当我们到达：```
i == current_end
```我们已经用尽了之前选择的水龙头的覆盖范围。 

我们必须：

 1. 打开另一个水龙头。 
2. 扩大覆盖范围`farthest`。 

所以：```
taps_used += 1
current_end = farthest
```### 步骤 7：覆盖范围达到后完成`n`立刻`current_end >= n`，整个花园都被覆盖了。 

返回`taps_used`。 

### 为什么它有效

 贪心策略总是选择当前所有可用区间中覆盖范围扩展最远的区间。 

在任何时候，延迟选择都无法改进解决方案，因为在当前边界之前开始的所有间隔都是已知的。 选择影响最远的一项可以最大限度地提高未来的灵活性并最大限度地减少选择的数量。 

这与 Jump Game II 和最小区间覆盖问题中使用的正确性论证相同。 

## Python 解决方案```python
from typing import List

class Solution:
    def minTaps(self, n: int, ranges: List[int]) -> int:
        max_reach = [0] * (n + 1)

        # Convert taps into interval coverage
        for i in range(n + 1):
            left = max(0, i - ranges[i])
            right = min(n, i + ranges[i])

            max_reach[left] = max(max_reach[left], right)

        taps_used = 0
        current_end = 0
        farthest = 0

        for i in range(n + 1):
            if i > farthest:
                return -1

            farthest = max(farthest, max_reach[i])

            if i == current_end:
                if current_end != n:
                    taps_used += 1
                    current_end = farthest

                    if current_end >= n:
                        return taps_used

        return 0 if n == 0 else -1
```实现首先将每个抽头转换为一个间隔。 我们不是单独存储每个区间，而是将信息压缩为`max_reach`，其中每个索引表示距左边界可到达的最远点。 

贪婪遍历类似于Jump Game II 中的广度扩展。 在扫描当前覆盖范围内的位置时，我们不断更新`farthest`。 

当我们到达当前覆盖间隔的边缘时，我们被迫激活另一个水龙头。 在那一刻，我们将覆盖范围扩大到迄今为止发现的尽可能最好的最远边界。 

如果在任何时候当前指数超过`farthest`，这意味着覆盖范围存在差距，花园无法充分浇水。 

## 解决方案```go
func minTaps(n int, ranges []int) int {
    maxReach := make([]int, n+1)

    // Convert taps into intervals
    for i := 0; i <= n; i++ {
        left := i - ranges[i]
        if left < 0 {
            left = 0
        }

        right := i + ranges[i]
        if right > n {
            right = n
        }

        if right > maxReach[left] {
            maxReach[left] = right
        }
    }

    tapsUsed := 0
    currentEnd := 0
    farthest := 0

    for i := 0; i <= n; i++ {
        if i > farthest {
            return -1
        }

        if maxReach[i] > farthest {
            farthest = maxReach[i]
        }

        if i == currentEnd {
            if currentEnd != n {
                tapsUsed++
                currentEnd = farthest

                if currentEnd >= n {
                    return tapsUsed
                }
            }
        }
    }

    if n == 0 {
        return 0
    }

    return -1
}
```Go 实现遵循与 Python 版本完全相同的贪婪逻辑。 

使用切片而不是 Python 列表。 整数溢出不是问题，因为所有值都保持在很小的范围内。 由于 Go 没有内置`max`，使用手动执行比较`if`声明。

 ## 边缘情况

 当没有水龙头可以覆盖花园的开头时，就会出现一种重要的边缘情况。 例如：```
n = 5
ranges = [0,0,0,0,0,5]
```即使最后的点击覆盖了左边很远的地方，它也只到达了位置`0`如果它的间隔实际上延伸到那里。 如果开始时存在任何未覆盖的间隙，算法会检测到它，因为当前索引最终会变得大于`farthest`。 

另一个关键情况是单个水龙头覆盖整个花园。 例如：```
n = 5
ranges = [5,0,0,0,0,0]
```该算法自然地处理这个问题，因为第一个间隔直接将覆盖范围扩展到`n`，轻轻一按即可立即返回。 

第三个重要的情况涉及断开的间隔。 假设区间覆盖`[0,2]`和`[4,5]`但没有什么可以掩盖位置`3`。 幼稚的实现可能会在不检查连续性的情况下错误地计算间隔。 该解决方案明确验证：```
i > farthest
```这保证了覆盖范围没有差距。 

最后，严重重叠的间隔有时会混淆过早选择间隔的贪婪实现。 该算法通过延迟抽头激活直到当前覆盖边界耗尽来避免该问题，从而确保始终选择最远的可能扩展。
