 # LeetCode 1334 - 找到阈值距离内邻居数量最少的城市

 ## 问题理解

 这个问题为我们提供了一个加权无向图，其中每个节点代表一个城市，每条边代表两个城市之间具有出行成本的双向道路。 我们还被赋予了`distanceThreshold`，它是我们允许旅行的距离的上限。 

目标是确定哪个城市可以到达**最少数量的其他城市**，使得到这些城市的最短路径距离**小于或等于**`distanceThreshold`。 

如果多个城市具有相同的最小可达邻居数量，我们必须返回具有**最大城市索引**的城市。 

换句话说，对于每个城市，我们需要回答以下问题：

 > “在总距离不超过阈值的情况下，该城市可以使用最短路线到达多少个其他城市？”

 一旦我们知道每个城市的计数，我们就会选择计数最少的城市。 如果存在平局，我们选择指数较大的城市。 

输入包括：

 -`n`，标记的城市数量`0`到`n - 1`-`edges`，其中每个条目`[u, v, w]`表示城市之间有一条双向道路`u`和城市`v`有重量`w`-`distanceThreshold`，最大允许的最短路径距离

 预期输出是代表所选城市的单个整数。 

这些约束提供了关于哪种算法合适的重要线索。 自从`n <= 100`，图形相对较小。 甚至一个`O(n³)`解决方案是可以接受的，因为：

 [
 100^3 = 1,000,000
 ]

 在现代编程环境中可以轻松管理一百万次操作。 这强烈表明像 **Floyd-Warshall** 这样的全对最短路径算法是一个很好的选择。 

有几个重要的边缘情况需要预先考虑。 

该图可能未完全连接，这意味着某些城市无法从其他城市到达。 我们必须避免计算无法到达的城市。 

一些城市在阈值内可能有零个可达邻居。 幼稚的实现可能会意外地计算自身或错误地处理无限距离。 

多个城市可以具有相同的最小可达计数，并且该问题明确要求在这种情况下返回具有**最大索引**的城市。 

该问题保证所有边都是不同的并且权重为正，这意味着我们不需要处理重复边或负循环。 

## 方法

 ### 蛮力方法

 解决该问题的一个直接方法是独立计算每个城市的最短路径。 

对于每个城市，我们可以运行最短路径算法（例如 Dijkstra 算法）来确定到每个其他城市的最短距离。 一旦我们知道了这些距离，我们就可以计算出有多少个城市可以到达`distanceThreshold`。 

对每个城市重复此过程后，我们比较计数并根据平局规则选择答案。 

这种方法是正确的，因为 Dijkstra 保证了具有正权重的图的最短路径距离，并且该问题中的边权重始终为正。 

然而，重复运行最短路径计算会带来不必要的重复工作。 虽然对于给定的约束仍然可以接受，但它并不是最干净的解决方案`n`非常小。 

### 最佳解决方案的关键见解

 关键的观察是，我们需要**每对城市**之间的最短距离，而不仅仅是一个来源。 

因为`n <= 100`，我们可以使用 **Floyd-Warshall 算法** 有效地计算所有对的最短路径。 

Floyd-Warshall 的工作原理是逐步允许最短路径中的中间节点。 最初，唯一已知的距离是直接边缘。 然后，一次引入一个城市作为每对城市之间可能的中间站。 

过渡是：

 [
 dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])
 ]

 这意味着：

 - 当前最短路径`i`到`j`已经是最优的
 - 或者穿过城市`k`产生更短的路线

 处理完所有中间城市后，矩阵包含每对之间的最短路径距离。 

然后我们简单地计算每个城市可以到达多少个城市在阈值内并应用打破平局的规则。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力（从每个节点运行 Dijkstra）| O(n × (E log n)) | O(n × (E log n)) | O(n + E) | 分别计算每个城市的最短路径 |
 | 最优（弗洛伊德-沃歇尔）| O(n3) | O(n²) | 小型高效`n`，直接计算所有对的最短路径 |

 ## 算法演练

 ### 最优算法，Floyd-Warshall

 1. **初始化距离矩阵**

 创建一个`n × n`矩阵称为`dist`。 

将每个值设置为无穷大，因为我们最初假设城市无法到达。 

放`dist[i][i] = 0`对于每个城市，因为城市到其自身的距离始终为零。 
2. **填充直接边缘距离**

 迭代`edges`。 

对于每一条路`[u, v, weight]`， 更新：```
dist[u][v] = weight
dist[v][u] = weight
```由于该图是无向的，因此我们更新两个方向。 
3. **运行弗洛伊德·沃歇尔**

 使用三个嵌套循环。 

外环选择中间城市`k`。 

对于每对`(i, j)`，判断是否经过`k`给出更短的路径：```
dist[i][j] = min(
    dist[i][j],
    dist[i][k] + dist[k][j]
)
```这逐渐改进了所有最短路径估计。 
4. **统计可到达的城市**

 对于每个城市`i`, 数一下有多少个城市`j`满足：```
dist[i][j] <= distanceThreshold
```排除城市本身。 
5. **追踪最佳城市**

 维护：

 -`min_reachable`，迄今为止发现的最小可达计数
 -`result_city`, 城市指数

 如果某个城市的计数较少，请更新答案。 

如果计数与当前最小值持平，则选择较大的城市索引。 

### 为什么它有效

 Floyd-Warshall 保证处理后的中间城市`k`，仅使用城市的所有最短路径`0...k`因为中间值是正确的。 

当每个城市被处理为中间节点时，矩阵包含每对城市之间的全局最短距离。 

由于我们统计了最短路径距离在阈值内的城市，并应用了所需的平局规则，因此最终结果保证是正确的。 

## Python 解决方案```python
from typing import List

class Solution:
    def findTheCity(
        self,
        n: int,
        edges: List[List[int]],
        distanceThreshold: int
    ) -> int:
        INF = float("inf")

        # Initialize distance matrix
        dist = [[INF] * n for _ in range(n)]

        # Distance to self is always 0
        for i in range(n):
            dist[i][i] = 0

        # Add direct edges
        for u, v, weight in edges:
            dist[u][v] = weight
            dist[v][u] = weight

        # Floyd-Warshall algorithm
        for k in range(n):
            for i in range(n):
                for j in range(n):
                    if dist[i][k] + dist[k][j] < dist[i][j]:
                        dist[i][j] = dist[i][k] + dist[k][j]

        min_reachable = float("inf")
        result_city = -1

        # Count reachable cities
        for city in range(n):
            reachable_count = 0

            for neighbor in range(n):
                if (
                    city != neighbor
                    and dist[city][neighbor] <= distanceThreshold
                ):
                    reachable_count += 1

            # Tie-breaking favors larger city index
            if reachable_count <= min_reachable:
                min_reachable = reachable_count
                result_city = city

        return result_city
```实现首先创建一个初始化为无穷大的距离矩阵。 无穷大代表当前无法到达的城市。 

对角线值设置为零，因为每个城市与其自身的距离为零。 

接下来，将直接道路信息插入到矩阵中。 由于道路是双向的，因此两个方向都会更新。 

Floyd-Warshall 阶段使用三个嵌套循环。 最外层循环选择中间城市`k`，而内部循环检查每对城市`(i, j)`。 如果旅行经过`k`缩短路径，更新矩阵条目。 

一旦最短路径完成，我们就会迭代每个城市并计算有多少个城市落在阈值距离内。 

使用以下方法可以优雅地处理平局决胜逻辑：```python
if reachable_count <= min_reachable:
```使用`<=`而不是`<`确保关系自动有利于较大的城市指数。 

## 解决方案```go
func findTheCity(n int, edges [][]int, distanceThreshold int) int {
	const INF = int(1e9)

	// Initialize distance matrix
	dist := make([][]int, n)
	for i := 0; i < n; i++ {
		dist[i] = make([]int, n)

		for j := 0; j < n; j++ {
			if i == j {
				dist[i][j] = 0
			} else {
				dist[i][j] = INF
			}
		}
	}

	// Add direct edges
	for _, edge := range edges {
		u, v, weight := edge[0], edge[1], edge[2]
		dist[u][v] = weight
		dist[v][u] = weight
	}

	// Floyd-Warshall algorithm
	for k := 0; k < n; k++ {
		for i := 0; i < n; i++ {
			for j := 0; j < n; j++ {
				if dist[i][k]+dist[k][j] < dist[i][j] {
					dist[i][j] =
						dist[i][k] + dist[k][j]
				}
			}
		}
	}

	minReachable := INF
	resultCity := -1

	// Count reachable cities
	for city := 0; city < n; city++ {
		reachableCount := 0

		for neighbor := 0; neighbor < n; neighbor++ {
			if city != neighbor &&
				dist[city][neighbor] <= distanceThreshold {
				reachableCount++
			}
		}

		// Tie-breaking favors larger index
		if reachableCount <= minReachable {
			minReachable = reachableCount
			resultCity = city
		}
	}

	return resultCity
}
```Go 实现遵循与 Python 版本完全相同的逻辑，但使用切片而不是嵌套列表。 

Go 没有内置的整数无穷大值，因此我们定义一个足够大的常量（`1e9`) 来表示无法到达的距离。 

由于边权重和阈值的边界为`10^4`， 和`n <= 100`，整数溢出不是这个哨兵值的问题。 

通过使用打破平局逻辑保持相同`<=`，确保在联系期间选择较大的城市索引。

 ## 边缘情况

 当多个城市具有相同的最小可达计数时，就会出现一种重要的边缘情况。 这很容易处理不当，因为许多实现自然会选择遇到的第一个最小值。 该问题明确要求返回具有**最大索引**的城市。 我们的实现通过使用以下方法正确处理这个问题：```
if reachable_count <= min_reachable:
```使用`<=`意味着关系会覆盖之前的答案，自然有利于较大的城市指数。 

另一个边缘情况是断开连接的图。 有些城市可能永远无法从其他城市到达，因为不存在路径。 如果解决方案错误地初始化距离或不正确地处理无穷大，则可能会意外地计算出无法到达的城市。 我们的实现通过将无法到达的路径初始化为无穷远并仅计算小于或等于的距离来避免这种情况`distanceThreshold`。 

当阈值极小时，会出现第三种重要的边缘情况。 在某些情况下，一个城市可能无法到达任何其他城市。 有缺陷的实现可能会错误地将城市本身视为可达。 我们使用以下方法明确排除自计数：```
city != neighbor
```这保证了仅计算不同的邻近城市。 

最后的边缘情况涉及间接路径比直接路径短。 例如，城市`A`可以直接连接到城市`C`有成本`10`， 尽管`A -> B -> C`仅成本`4`。 只考虑直接道路的幼稚实施将会失败。 Floyd-Warshall 保证发现所有间接最短路径并将其正确纳入最终距离。
