[LeetCode 1398 题](https://leetcode.com/problems/customers-who-bought-products-a-and-b-but-not-c/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题要求我们识别符合特定购买模式的客户。 我们有两张表：`Customers`和`Orders`。 这`Customers`表包含唯一的`customer_id`以及相应的`customer_name`。 这`Orders`表记录购买情况`order_id`,`customer_id`， 和`product_name`。 

我们的任务是找到**同时购买了产品“A”和产品“B”**但**没有购买产品“C”**的客户。 这对于向这些客户推荐产品“C”非常重要。 输出应返回`customer_id`和`customer_name`此类客户的数量，按`customer_id`。 

这些约束表明客户可能有多个订单，包括多个产品，并且`customer_id`唯一标识客户。 要考虑的边缘情况包括未购买任何产品的客户、仅购买“A”或“B”之一的客户以及购买所有三种产品（包括“C”）的客户。 

## 方法

 ### 暴力方法

 蛮力方法涉及加入`Customers`和`Orders`表格并单独检查每个客户的购买情况。 对于每个客户，我们将枚举他们的所有产品，检查“A”和“B”是否存在，并确认“C”不存在。 虽然这可行，但效率可能很低，因为它需要扫描`Orders`每个客户的表，导致数据多次传递。 

### 最佳方法

 最佳方法的关键观察是我们可以**按客户汇总订单**并使用条件逻辑来计算“A”、“B”和“C”的购买量。 如果计数显示客户至少购买了 1 个“A”和 1 个“B”，以及 0 个“C”，则该客户符合资格。 这使用了单次扫描`Orders`表格分组依据`customer_id`并且效率更高。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n*m) | O(n) | 单独检查每个客户，扫描所有订单 |
 | 最佳 | O(n) | O(k) | 按 customer_id 聚合订单并使用条件计数 |

 这里，`n`是订单数量，并且`k`是客户数量。 

## 算法演练

 1. **加入客户和订单**：首先加入`Customers`表与`Orders`桌子上`customer_id`将每次购买与客户相关联。 
2. **按客户分组**：按以下方式聚合订单`customer_id`这样每个客户就成为一行进行评价。 
3. **统计有条件购买**：对于每个客户群，统计“A”和“B”是否至少出现一次，并确保“C”出现零次。 
4. **过滤**：只保留满足购买“A”和“B”的客户，而不保留购买“C”的客户。 
5. **选择结果**：返回`customer_id`和`customer_name`已筛选客户的数量，排序依据`customer_id`。 

**为什么有效：** 通过对每个客户的订单进行分组并有条件地计算购买量，我们确保对客户购买的所有产品进行有效评估。 使用聚合可以保证每个客户只被考虑一次，从而保持正确性。 

## Python 解决方案```python
class Solution:
    def customersWhoBoughtABNotC(self, customers: 'List[dict]', orders: 'List[dict]') -> 'List[dict]':
        from collections import defaultdict

        purchase_map = defaultdict(set)
        for order in orders:
            purchase_map[order['customer_id']].add(order['product_name'])

        result = []
        for customer in customers:
            cid = customer['customer_id']
            products = purchase_map.get(cid, set())
            if 'A' in products and 'B' in products and 'C' not in products:
                result.append({'customer_id': cid, 'customer_name': customer['customer_name']})

        return sorted(result, key=lambda x: x['customer_id'])
```**实现演练：** 我们首先构建一个映射每个的字典`customer_id`他们购买的一组产品。 这确保了产品成员资格的 O(1) 查找。 然后，我们迭代`Customers`表中，检查“A”、“B”和“C”的条件，并收集符合条件的客户。 最后，我们对结果进行排序`customer_id`。 

## 解决方案```go
package main

type Customer struct {
    CustomerID   int
    CustomerName string
}

type Order struct {
    OrderID     int
    CustomerID  int
    ProductName string
}

func CustomersWhoBoughtABNotC(customers []Customer, orders []Order) []Customer {
    purchaseMap := make(map[int]map[string]bool)

    for _, order := range orders {
        if purchaseMap[order.CustomerID] == nil {
            purchaseMap[order.CustomerID] = make(map[string]bool)
        }
        purchaseMap[order.CustomerID][order.ProductName] = true
    }

    var result []Customer
    for _, customer := range customers {
        products, exists := purchaseMap[customer.CustomerID]
        if !exists {
            continue
        }
        if products["A"] && products["B"] && !products["C"] {
            result = append(result, customer)
        }
    }

    // Sort by CustomerID
    for i := 0; i < len(result)-1; i++ {
        for j := i + 1; j < len(result); j++ {
            if result[i].CustomerID > result[j].CustomerID {
                result[i], result[j] = result[j], result[i]
            }
        }
    }

    return result
}
```**Go-具体说明：** 我们使用地图来存储每个客户的购买情况。 布尔值指示是否已购买产品。 Go 没有内置的结构排序功能，没有实现`sort.Interface`，因此为了清晰起见，使用了简单的冒泡排序。 

## 工作示例

 **输入示例：**```
Customers: [{1, "Daniel"}, {2, "Diana"}, {3, "Elizabeth"}, {4, "Jhon"}]
Orders: [
    {10, 1, "A"}, {20, 1, "B"}, {30, 1, "D"}, {40, 1, "C"},
    {50, 2, "A"}, {60, 3, "A"}, {70, 3, "B"}, {80, 3, "D"},
    {90, 4, "C"}
]
```**步骤执行：**

 1. 构建`purchase_map`:

 | 客户 ID | 产品 |
 | ---| ---|
 | 1 | {A，B，C，D}|
 | 2 | {A}|
 | 3 | {A，B，D}|
 | 4 | {C}|

 1. 迭代客户：

 - 客户 1：已排除 C →
 - 顾客2：缺少B→排除
 - 客户 3：有 A、B，没有 C → 包括
 - 客户 4：缺少 A 和 B → 排除

 1. 排序结果 → 客户 3（“伊丽莎白”）。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n + k log k) | O(n + k log k) | O(n) 扫描订单，O(k log k) 排序客户，其中 k 是合格客户 |
 | 空间| O(n) | 将 customer_id 映射到购买的产品的字典的 O(n) |

 该算法有效地扫描订单一次，并使用字典进行快速成员资格检查，避免多次扫描或连接。
