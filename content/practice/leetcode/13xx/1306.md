 # LeetCode 1306 - 跳跃游戏 III

 ## 问题理解

 该问题为我们提供了一个非负整数数组和一个起始索引。 从任何位置`i`，我们可以向前跳到`i + arr[i]`或向后至`i - arr[i]`。 目标是确定是否有可能最终找到任何值为`0`。 

重要的细节是跳跃完全由当前指数的值决定。 如果我们在索引处`i`，我们不会选择任意距离。 相反，我们必须准确地移动`arr[i]`向左或向右迈出一步。 

数组本身可以被视为一个图表。 每个索引代表一个节点，每个节点最多有两个出边：

 - 一侧边缘`i + arr[i]`- 一侧边缘`i - arr[i]`问题是是否存在从起始节点到包含该值的任何节点的路径`0`。 

约束条件很重要：

 - 数组长度可以大到`5 * 10^4`- 每个值都保证在数组范围内
 - 起始索引有效

 由于输入量很大，我们需要一个以线性时间运行的算法。 指数探索会太慢。 

这个问题的最大危险之一是循环。 考虑一个数组，其中索引在彼此之间反复来回跳转。 不跟踪访问索引的简单递归实现可能会进入无限递归或重复处理相同的状态。 

另一个重要的边缘情况是当起始索引已经包含`0`。 在这种情况下，答案应该是`true`。 

该问题还保证所有数字都是非负的，这简化了移动逻辑，因为跳跃距离永远不会是负数。 

## 方法

 ### 蛮力方法

 蛮力的想法是递归地尝试从当前索引开始的每一个可能的跳转。 在每个位置，我们分为两种可能性：

 - 向左跳
 - 向右跳

 如果任一路径最终到达`0`，我们返回`true`。 

这种方法在概念上很简单，因为它直接探索每条可达路径。 然而，在不记住先前访问过的索引的情况下，该算法可以无限次地重新访问相同的位置。 

例如，假设索引`2`跳转到`5`，和索引`5`跳回到`2`。 一个简单的 DFS 会永远循环。 

即使我们人为地停止递归深度，重复计算的次数也会变得巨大。 重复探索相同的状态，导致指数行为。 

### 最佳方法

 关键的观察是每个索引只需要处理一次。 

这本质上是一个图遍历问题。 每个数组索引就像一个图节点，有效的跳转形成图的边。 我们只关心是否存在到包含以下内容的节点的路径`0`。 

标准的图遍历算法（例如 DFS 或 BFS）在这里可以完美地工作。 关键的优化是保持`visited`设置这样我们就不会多次处理同一个索引。 

一旦索引被探索过，再次探索它就不能产生新的信息。 这将问题从指数探索转换为线性探索。 

我们可以使用：

 - 使用递归或堆栈的深度优先搜索
 - 使用队列的广度优先搜索

 两者都实现了相同的渐近复杂度。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 探索重复状态并可能在没有保护的情况下无限递归 |
 | 最优 DFS/BFS | O(n) | O(n) | 每个索引最多访问一次 |

 ## 算法演练

 ### 最优DFS算法

 1. 创建一个`visited`设置跟踪我们已经探索过的指数。 
2. 从给定开始一次DFS遍历`start`指数。 
3. 在每个索引处，首先检查是否越界。 如果是，则返回`false`因为数组之外的跳转是无效的。 
4. 检查索引是否已被访问过。 如果是，则返回`false`因为重新访问相同的索引只会重复以前的工作。 
5. 将当前索引标记为已访问。 
6. 检查是否`arr[index] == 0`。 如果为 true，则我们成功到达了有效目的地，因此返回`true`。 
7. 计算两个可能的下一个索引：

 -`index + arr[index]`-`index - arr[index]`8. 递归地探索两种可能性。 
9. 如果任一递归调用返回`true`, 传播`true`向上。 
10. 如果两条路径均未达到零，则返回`false`。 

### 为什么它有效

 该算法之所以有效，是因为它系统地探索每个可达索引一次。 这`visited`set 保证循环不会导致无限递归或重复工作。 由于每次合法的跳跃都会被探索，因此如果存在通往零的路径，则遍历最终会找到它。 相反，如果遍历结束时没有找到零，则不存在可达路径。 

## Python 解决方案```python
from typing import List

class Solution:
    def canReach(self, arr: List[int], start: int) -> bool:
        visited = set()

        def dfs(index: int) -> bool:
            if index < 0 or index >= len(arr):
                return False

            if index in visited:
                return False

            visited.add(index)

            if arr[index] == 0:
                return True

            jump = arr[index]

            return dfs(index + jump) or dfs(index - jump)

        return dfs(start)
```实施首先创建一个`visited`放。 这可以防止循环并确保每个索引最多处理一次。 

嵌套的`dfs`函数执行图遍历。 前两项检查处理无效状态：

 - 越界索引
 - 以前访问过的索引

 在确认当前索引有效且未被访问后，我们将其标记为已探索。 

接下来，该实现检查当前值是否为零。 如果是这样，我们立即返回`True`。 

否则，我们计算跳跃距离并递归地探索两个可能的目的地。 逻辑性`or`运算符很重要，因为我们只需要一条成功的路径。 

最后，从DFS开始的结果`start`被返回。 

## 解决方案```go
func canReach(arr []int, start int) bool {
    visited := make([]bool, len(arr))

    var dfs func(int) bool

    dfs = func(index int) bool {
        if index < 0 || index >= len(arr) {
            return false
        }

        if visited[index] {
            return false
        }

        visited[index] = true

        if arr[index] == 0 {
            return true
        }

        jump := arr[index]

        return dfs(index+jump) || dfs(index-jump)
    }

    return dfs(start)
}
```Go 实现遵循与 Python 版本相同的逻辑。 它不使用哈希集，而是使用名为的布尔切片`visited`，这在 Go 中更有效，因为索引是连续的整数。 

Go 还要求在分配函数体之前显式声明递归函数变量。 除了语法差异之外，遍历逻辑是相同的。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每个索引最多被访问一次 |
 | 空间| O(n) | 被访问的结构和递归堆栈都可能增长到大小 n |

 该算法是线性的，因为一旦访问了索引，就不会再对其进行处理。 因此，每个边缘探索每个节点最多发生一次。 递归堆栈的深度可以与可达索引的数量一样深，这给出了线性空间复杂度。

 ## 边缘情况

 当起始索引已包含时，会出现一种重要的边缘情况`0`。 粗心的实现可能会继续不必要地探索邻居，甚至会失败，因为不可能进行跳跃。 此实现通过检查立即处理案例`if arr[index] == 0`。 

另一个关键的边缘情况涉及循环。 例如，两个索引可以在彼此之间重复地来回跳转。 如果没有访问过的结构，递归DFS将进入无限递归。 这`visited`set 保证每个索引仅被探索一次。 

当跳转超出数组边界时，会出现第三种边缘情况。 由于负索引和超出数组长度的索引无效，因此实现在处理索引之前显式检查边界。 这可以防止运行时错误并确保无效路径安全终止。
