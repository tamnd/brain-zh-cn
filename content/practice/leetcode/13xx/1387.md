[LeetCode 问题 1387](https://leetcode.com/problems/sort-integers-by-the-power-value/)

 **难度：** 🟡 中等
 **主题：** 动态规划、记忆、排序

 ## 解决方案

 ## 问题理解

 这个问题要求我们根据称为“幂值”的特殊度量对整数进行排名。 一个数字的幂值是通过重复应用 Collat​​z 变换规则来确定的，直到该数字变为`1`。 

规则是：

 - 如果数字是偶数，则除以`2`- 如果数字是奇数，则将其替换为`3 * x + 1`功率值只是达到所需的变换次数`1`。 

例如：

-`3 → 10 → 5 → 16 → 8 → 4 → 2 → 1`- 该序列包含`7`跃迁，所以功率值`3`是`7`输入由三个整数组成：

 -`lo`，区间的下界
 -`hi`，区间的上限
 -`k`, 排序后我们想要的位置

 我们必须考虑范围内的每个整数`[lo, hi]`，计算其幂值，然后根据两个规则对数字进行排序：

 1.功率值较小者优先
 2. 如果两个数字的幂值相同，则较小的数字在前

 排序后，我们返回`kth`按排序顺序排列的数字。 

限制相对较小：

 -`1 <= lo <= hi <= 1000`- 至多`1000`数字存在于范围内

 这告诉我们，我们不需要极其先进的优化技术。 然而，针对许多重叠值重复重新计算 Collat​​z 序列仍然效率低下。 不同序列中的许多数字最终会收敛到相同的中间值，因此记忆成为一种自然的优化。 

一个重要的保证是范围内的每个数字最终都会达到`1`。 这避免了无限循环并确保功率计算始终终止。 

一些边缘情况很重要：

 - 仅包含一个数字的范围
 - 多个号码共享相同的功率值
 - 非常小的数字，例如`1`- 大型 Collat​​z 链，其中中间值变得比`1000`最后一点尤其重要，因为虽然输入范围很小，但 Collat​​z 序列可能会暂时增长到远远超出原始区间。 

## 方法

 ### 蛮力方法

 最直接的解决方案是独立计算区间内每个数字的幂值。 

对于每个整数`x`在`[lo, hi]`:

 1. 逐步模拟Collatz过程
 2. 统计需要多少次操作才能达到`1`3. 商店`(power_value, number)`对
 4. 对列表进行排序
 5. 返回`kth`数量

 这种方法是正确的，因为它显式地计算每个数字的精确幂值并根据问题规则进行排序。 

然而，它执行了大量的重复工作。 不同的序列常常严重重叠。 例如：

-`12 → 6 → 3 → 10 → ...`-`13 → 40 → 20 → 10 → ...`两个序列最终都达到`10`，这意味着剩余的计算是重复的。 

如果没有缓存，相同的功率值可能会被重新计算多次。 

### 最佳方法，记忆与排序

 关键的观察结果是 Collatz 序列广泛重叠。 

如果我们已经知道某个数字的幂值`y`，然后是另一个数的幂值`x`转变为`y`可以立即计算：

 -`power(x) = 1 + power(y)`这自然意味着记忆。 

我们使用哈希图来缓存先前计算的功率值。 每当我们遇到一个幂值已知的数字时，我们就会停止递归并重用缓存的结果。 

这极大地减少了冗余计算，因为每个中间数仅处理一次。 

通过记忆计算出所有功率值后，我们对间隔进行排序并返回`kth`元素。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n × m) | O(n) | 重复重新计算许多 Collat​​z 链 |
 | 最佳 | O(n log n + U) | O(n log n + U) | O(U) | 使用记忆法避免重复计算 |

 这里：

-`n = hi - lo + 1`-`m`是平均 Collatz 序列长度
 -`U`是遇到的唯一中间值的数量

 ## 算法演练

 ### 第 1 步：创建记忆图

 我们初始化一个存储已经计算出的功率值的哈希图。 

我们从以下开始：```
memo = {1: 0}
```这意味着功率值`1`是`0`因为它已经等于`1`。 

这个记忆图允许我们有效地重用以前的计算。 

### 步骤 2：定义递归幂函数

 我们创建一个递归函数`power(x)`。 

该函数的工作原理如下：

 1.如果`x`备忘录映射中已存在，返回缓存值
 2.否则：

 - 如果`x`是偶数，递归计算`power(x // 2)`- 如果`x`为奇数，递归计算`power(3 * x + 1)`3. 添加`1`代表当前的变换
 4. 将结果存储在备忘录映射中
 5. 返回计算值

 这种递归结构反映了 Collatz 过程的精确定义。 

### 第 3 步：构建数字数组

 我们生成所有整数`lo`到`hi`。 

对于每个数字，我们使用记忆函数计算其幂值。 

### 步骤 4：对数字进行排序

 我们使用自定义排序键进行排序：```
key = (power_value, number)
```这保证：

 - 较小的功率值首先出现
 - 平局被整数值本身打破

 ### 步骤 5：返回第 k 个元素

 由于索引是从零开始的，所以答案是：```
numbers[k - 1]
```### 为什么它有效

 该算法之所以有效，是因为递归函数完全遵循问题中定义的 Collatz 变换规则。 记忆不会改变正确性，它只是避免重新计算。 

排序步骤使用问题陈述所需的精确排序：

 1.主键、幂值
 2. 辅助键，整数值

 因此，保证结果顺序与所需的排序顺序相匹配，并选择`kth`元素返回正确答案。 

## Python 解决方案```python
class Solution:
    def getKth(self, lo: int, hi: int, k: int) -> int:
        memo = {1: 0}

        def power(x: int) -> int:
            if x in memo:
                return memo[x]

            if x % 2 == 0:
                memo[x] = 1 + power(x // 2)
            else:
                memo[x] = 1 + power(3 * x + 1)

            return memo[x]

        numbers = list(range(lo, hi + 1))

        numbers.sort(key=lambda num: (power(num), num))

        return numbers[k - 1]
```实现首先用基本情况初始化记忆字典`1: 0`。 

嵌套的`power()`函数递归计算任何整数的幂值。 在执行任何操作之前，它会检查该值是否已存在于缓存中。 如果是，它立即返回存储的答案。 

如果数字是偶数，则该函数递归计算`x // 2`。 如果是奇数，它计算的幂值`3 * x + 1`。 在这两种情况下，`1`为当前转换步骤添加。 

计算完所有功率值后，代码生成间隔`[lo, hi]`并使用元组排序键对其进行排序：```python
(power(num), num)
```Python 元组比较会自动正确处理平局打破规则。 

最后，代码返回`k - 1`索引元素，因为 Python 列表使用从零开始的索引。 

## 解决方案```go
package main

import "sort"

func getKth(lo int, hi int, k int) int {
	memo := map[int]int{
		1: 0,
	}

	var power func(int) int

	power = func(x int) int {
		if val, exists := memo[x]; exists {
			return val
		}

		if x%2 == 0 {
			memo[x] = 1 + power(x/2)
		} else {
			memo[x] = 1 + power(3*x+1)
		}

		return memo[x]
	}

	numbers := make([]int, 0)

	for i := lo; i <= hi; i++ {
		numbers = append(numbers, i)
	}

	sort.Slice(numbers, func(i, j int) bool {
		pi := power(numbers[i])
		pj := power(numbers[j])

		if pi == pj {
			return numbers[i] < numbers[j]
		}

		return pi < pj
	})

	return numbers[k-1]
}
```Go 实现遵循与 Python 版本相同的算法结构。 

一个`map[int]int`用于记忆。 Go 不直接支持嵌套命名函数，因此递归函数是使用函数变量声明的：```go
var power func(int) int
```排序是使用实现的`sort.Slice`带有自定义比较器。 

与 Python 元组比较不同，Go 需要显式比较逻辑来处理平局。 

Go 整数对于问题约束来说足够大，因此整数溢出不是这里的问题。

 ## 边缘情况

 当区间仅包含单个数字时，会出现一种重要的边缘情况。 例如：```
lo = hi = 5
```在这种情况下，不需要实际排序，因为只存在一个元素。 有缺陷的实现可能会错误地假设多个元素始终存在。 当前的实现自然地处理了这个问题，因为生成的列表仅包含一个值，并且对单个元素列表进行排序是有效的。 

另一个重要的边缘情况涉及权力值的联系。 例如：```
12 and 13 both have power value 9
```如果实现仅按功率值排序，则根据排序算法，相对顺序可能会变得不一致。 该问题明确要求通过数值本身来打破联系。 该实现使用以下方法解决了这个问题：```
(power(num), num)
```这保证了稳定且正确的排序。 

第三个重要的边缘情况是中间 Collat​​z 值可能会变得比原始范围大得多。 即使输入最多`1000`，序列可能会暂时增长到更大的数量。 假设所有值都保持在原始范围内的简单解决方案可能会失败或分配的存储空间不足。 记忆字典动态存储任何遇到的整数，因此实现可以正确处理大的中间值，而无需假设其大小。
