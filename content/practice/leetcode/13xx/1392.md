[LeetCode 第 1392 题](https://leetcode.com/problems/longest-happy-prefix/)

 **难度：** 🔴难
 **主题：** 字符串、滚动哈希、字符串匹配、哈希函数

 ## 解决方案

 ## 问题理解

 该问题要求我们找到既是给定字符串的前缀又是后缀的最长子字符串`s`，同时还确保子字符串不等于整个字符串本身。 

前缀是从索引开始的子字符串`0`，而后缀是以字符串的最后一个索引结尾的子字符串。 重要的限制是我们不能使用整个字符串作为前缀和后缀。 前缀必须正确，这意味着它的长度必须严格小于字符串的长度。 

例如，在字符串中`"ababab"`:

 - 前缀是：`"a"`,`"ab"`,`"aba"`,`"abab"`,`"ababa"`- 后缀是：`"b"`,`"ab"`,`"bab"`,`"abab"`,`"babab"`最长匹配值为`"abab"`。 

输入由单个字符串组成`s`仅包含小写英文字母。 长度可以大到`10^5`，这立即告诉我们二次算法可能会太慢。 任何逐个字符重复比较大子字符串的方法都可能超出时间限制。 

预期输出是最长的快乐前缀。 如果不存在这样的非空前缀，我们返回空字符串`""`。 

一些边缘情况很重要：

 - 长度的字符串`1`永远不能有非空的 happy 前缀，因为唯一的前缀是整个字符串本身。 
- 没有重复边框结构的字符串，例如`"abcd"`，应该返回`""`。 
- Strings with repeated patterns, such as`"aaaaa"`或者`"ababab"`，可以有重叠的前缀和后缀匹配。 
- 明确允许重叠，这意味着前缀和后缀不需要占用字符串的单独区域。 

大的约束强烈表明我们需要一个线性时间字符串匹配算法。 

## 方法

 ### 蛮力方法

 最直接的解决方案是从最长到最短检查每个可能的前缀，并确定它是否也是后缀。 

假设字符串长度为`n`。 我们可以迭代所有可能的前缀长度`n - 1`下降到`1`。 对于每个长度`k`，我们比较：

 -`s[:k]`-`s[n-k:]`如果它们相等，我们立即返回该前缀，因为我们正在从最长到最短进行检查。 

这种方法是正确的，因为它详尽地检查每个有效候选者并返回具有最大长度的第一个有效匹配。 

然而，性能较差。 每个子串比较可以取`O(k)`时间，我们可以在几乎所有可能的长度上执行此操作。 在最坏的情况下，这会变成`O(n^2)`。 

和`n = 10^5`，二次复杂度太慢。 

### 最优方法，KMP 前缀函数

 关键的见解是，这个问题正是 KMP 字符串匹配预处理步骤旨在解决的问题。 

KMP 算法计算前缀表，也称为 LPS 数组，其中：

 -`lps[i]`存储最长的适当前缀的长度`s[:i+1]`这也是该子字符串的后缀。 

计算整个字符串的 LPS 数组后：

 -`lps[n - 1]`给出整个字符串的最长快乐前缀的长度.

 这是有效的，因为最终的 LPS 值已经代表了最长的正确前缀，它也是整个字符串的后缀。 

主要优点是 LPS 数组是使用先前计算的信息在线性时间内计算的，避免了从头开始的重复比较。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 直接检查每个前缀和后缀对 |
 | 最优、KMP 前缀功能 | O(n) | O(n) | 高效使用前缀匹配信息 |

 ## 算法演练

 ### 使用 KMP 前缀函数的最优算法

 1. 创建数组`lps`长度`n`，用零初始化。 

这`lps[i]`value 将表示最长的正确前缀的长度，也是子字符串的后缀`s[:i+1]`。 
2. 维护一个变量`length`。 

该变量在构建 LPS 表时跟踪当前最长的前缀-后缀匹配。 
3.从索引开始迭代`1`。 

第一个字符不能有正确的前缀，所以`lps[0]`总是`0`。 
4. 比较`s[i]`和`s[length]`。 

如果它们匹配，我们可以将当前的前缀后缀匹配扩展一个字符。 

- 增量`length`- 放`lps[i] = length`- 移至下一个索引
 5. 小心处理不匹配的情况。 

如果字符不匹配：

 - 如果`length > 0`， 减少`length`到`lps[length - 1]`- 这使用之前计算的信息而不是从零重新开始

 我们继续尝试更小的有效前缀长度，直到：

 - 找到匹配项，或者
 -`length`变成`0`6. 如果`length == 0`并且字符仍然不匹配：

 - 设置`lps[i] = 0`- 移至下一个索引
 7. 处理整个字符串后：

 -`lps[n - 1]`包含最长快乐前缀的长度
 8.返回子字符串：

 -`s[:lps[n - 1]]`### 为什么它有效

 LPS 数组保持不变式，即每个计算值都表示对应子字符串的最长有效前缀后缀匹配。 当发生不匹配时，该算法不会从头开始重新计算，而是重用之前计算的存储在 LPS 数组中的边界信息。 这保证了每个字符仅被处理恒定次数，从而产生正确的线性时间解决方案。 

## Python 解决方案```python
class Solution:
    def longestPrefix(self, s: str) -> str:
        n = len(s)

        lps = [0] * n
        length = 0
        i = 1

        while i < n:
            if s[i] == s[length]:
                length += 1
                lps[i] = length
                i += 1
            else:
                if length > 0:
                    length = lps[length - 1]
                else:
                    lps[i] = 0
                    i += 1

        longest_length = lps[-1]
        return s[:longest_length]
```实现从初始化开始`lps`带零的数组。 该数组存储字符串每个前缀的前缀-后缀匹配长度。 

变量`length`跟踪当前边框大小。 在迭代过程中，我们比较当前字符`s[i]`与前缀中的下一个预期字符，`s[length]`。 

当字符匹配时，我们将边界扩展一并将新的长度记录在`lps[i]`。 

当字符不匹配时，我们不会立即从头开始。 相反，我们使用先前计算的 LPS 值缩小候选边界。 这是使算法呈线性的关键优化。 

在最后，`lps[-1]`存储整个字符串的最长快乐前缀长度，然后返回相应的子字符串。 

## 解决方案```go
func longestPrefix(s string) string {
	n := len(s)

	lps := make([]int, n)
	length := 0
	i := 1

	for i < n {
		if s[i] == s[length] {
			length++
			lps[i] = length
			i++
		} else {
			if length > 0 {
				length = lps[length-1]
			} else {
				lps[i] = 0
				i++
			}
		}
	}

	longestLength := lps[n-1]
	return s[:longestLength]
}
```Go 实现遵循与 Python 版本相同的逻辑。 由于Go字符串是字节可索引的，并且问题保证小写英文字母，因此直接索引是安全高效的。 

这`make([]int, n)`调用初始化 LPS 数组。 空字符串会被自然处理，因为约束保证`n >= 1`。 

与 Python 切片不同，Go 子字符串操作还会在原始字符串数据上创建切片，从而提高最终子字符串提取的效率。

 ## 边缘情况

 ### 单字符串

 一个长度的字符串`1`不能有非空的 happy 前缀，因为唯一的前缀是整个字符串本身，这是不允许的。 这种情况很容易在忘记“正确前缀”要求的实现中产生相差一的错误。 该算法自然地处理这个问题，因为第一个字符的 LPS 值始终是`0`。 

### 没有匹配前缀和后缀的字符串

 输入如`"abcd"`根本不包含重复结构。 幼稚的实现可能会意外返回整个字符串或错误地匹配部分子字符串。 KMP 前缀表正确地将所有条目保留为`0`，导致答案为空字符串。 

### 高度重复的字符串

 字符串如`"aaaaaa"`很重要，因为许多前缀长度同时有效。 糟糕的实现可能会重复比较相同的字符并导致性能下降。 LPS 回退机制可防止冗余工作并保持运行时线性。 

### Overlapping Prefix and Suffix

 该问题明确允许重叠匹配。 例如，`"ababab"`有`"abab"`作为前缀和后缀，即使区域在字符串内重叠。 一些不正确的解决方案假设前缀和后缀必须不相交。 KMP 方法自然支持重叠，因为它只比较逻辑上的位置，而不是物理上分离的范围。
