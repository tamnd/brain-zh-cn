[LeetCode 问题 1369](https://leetcode.com/problems/get-the-second-most-recent-activity/)

 **难度：** 🔴难
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题给了我们一个名为`UserActivity`存储不同用户的活动时段。 每行包含四个字段：

 | 专栏 | 意义|
 | ---| ---|
 |`username`| 执行该活动的用户 |
 |`activity`| 活动名称|
 |`startDate`| 活动何时开始 |
 |`endDate`| 活动结束时 |

 单个用户可能有多个活动记录，并且这些记录按日期按时间顺序排序。 重要的细节是用户不能同时执行多个活动，这意味着同一用户的活动间隔不会重叠。 

任务是返回每个用户的第二个最近的活动。 “最新”由最新确定`endDate`。 

此要求创建了两种情况：

 1. 如果用户至少有两个活动，我们返回其活动`endDate`是第二大。 
2. 如果用户只有一项活动，我们将返回该活动。 

结果应包含完整行：

 -`username`-`activity`-`startDate`-`endDate`输出行的顺序并不重要。 

主要挑战是正确识别每个用户的第二个最近的活动，同时当用户只有一行时仍然返回唯一的活动。 

一个重要的观察是，这从根本上来说是群体内部的排名问题。 每个用户形成一个单独的组，我们需要根据新近度对他们的活动进行排名。 

有几种边缘情况很容易导致错误：

 - 一个用户可能只有一项活动。 
- 多个用户可能有不同数量的活动。 
- 表中可能存在重复的行。 
- 我们必须返回完整的行，而不仅仅是日期。 
- 我们必须对每个用户的活动进行独立排名。 

因为这是一个 SQL 排名问题，所以窗口函数特别适合这里。 

## 方法

 ### 蛮力方法

 强力解决方案将独立处理每个用户。 

对于每个不同的用户，我们可以：

 1. 收集属于该用户的所有活动行。 
2. 对这些行进行排序`endDate`下降。 
3. 如果用户有多个活动，则返回第二行。 
4. 否则，返回第一行。 

这种方法在逻辑上是正确的，因为排序直接为我们提供了从最近到最近的活动。 

然而，当在 SQL 中手动实现时，此方法会变得效率低下，因为它可能需要为每个用户重复子查询或自联接。 如果没有窗口函数，表达排名逻辑就会变得冗长且计算成本高昂。 

### 最佳方法

 关键的见解是这个问题可以使用 SQL 窗口函数自然地解决。 

我们可以使用以下方法为其用户组内的每个活动分配排名：```
ROW_NUMBER() OVER (
    PARTITION BY username
    ORDER BY endDate DESC
)
```这给出：

 - 排名`1`对于最近的活动
 - 排名`2`对于第二个最近的活动
 - 等等

 同时，我们还计算每个用户有多少活动：```
COUNT(*) OVER (PARTITION BY username)
```这使我们能够区分具有一项活动的用户和具有多项活动的用户。 

那么过滤规则就变成：

 - 返回行，其中`rank = 2`- 或返回行`count = 1`这以干净、高效的方式准确地产生了所需的结果。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n log n) | O(n log n) | O(n) | 为每个用户单独排序活动 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 使用 SQL 窗口函数进行排名 |

 ## 算法演练

 1. 首先，对表进行分区`username`。 

这确保了每个用户的活动都是独立处理的。 一个用户的排名不应影响另一用户。 
2. 在每个用户分区内，按以下方式对活动进行排序`endDate`下降。 

最新的活动应该首先出现。 这种排序使我们能够识别最近和第二最近的活动。 
3. 使用以下命令为每个活动分配行号`ROW_NUMBER()`。 

行号变为：

 -`1`→ 最近的
 -`2`→ 第二个最近的
 -`3+`→ 旧活动
 4. 计算每个用户的活动总数`COUNT(*) OVER (...)`。 

这有助于检测仅进行一项活动的用户。 
5. 过滤行。 

我们保留：

 - 行在哪里`row_number = 2`- 总活动计数为的行`1`6. 返回所需的列。 

最终结果包含原始活动行信息。 

### 为什么它有效

 该算法之所以有效，是因为窗口函数独立处理每个用户内的行，同时保留原始行。 

按降序排序`endDate`保证排名`1`始终是最新的活动。 因此，排名`2`必须是第二个最近的活动。 

额外的计数检查可确保仅进行一项活动的用户仍包含在结果中。 

这两个条件加在一起，完全符合问题的要求。 

## Python 解决方案```python
# Write your MySQL query statement below

SELECT
    username,
    activity,
    startDate,
    endDate
FROM (
    SELECT
        username,
        activity,
        startDate,
        endDate,
        ROW_NUMBER() OVER (
            PARTITION BY username
            ORDER BY endDate DESC
        ) AS row_num,
        COUNT(*) OVER (
            PARTITION BY username
        ) AS activity_count
    FROM UserActivity
) AS ranked_activities
WHERE row_num = 2
   OR activity_count = 1;
```该查询首先创建一个名为的派生表`ranked_activities`。 

在该子查询内，计算两个窗口函数。 

第一个窗口函数使用`ROW_NUMBER()`按降序排列每个用户的活动`endDate`。 这标识了每个活动的相对新近度。 

第二个窗口函数使用`COUNT(*)`确定每个用户总共有多少活动。 

计算这些值后，外部查询会过滤这些行。 如果用户有多个活动，则仅显示具有`row_num = 2`幸存下来。 如果用户只有一项活动，则包含该行，因为`activity_count = 1`。 

这种方法简洁、高效，并且直接对问题需求进行建模。

 ## 边缘情况

 ### 仅进行一项活动的用户

 一个常见的错误是仅过滤`row_num = 2`。 这样做会排除只进行一项活动的用户。 

例如：

 | 用户名 | 活动 | 结束日期 |
 | ---| ---| ---|
 | 鲍勃 | 旅游 | 2020-02-18 |

 Bob 没有第二个最近的活动，因此问题需要返回他唯一的活动。 

该实现还通过检查来处理此问题：```
activity_count = 1
```这保证了单一活动用户被包括在内。 

### 有很多活动的用户

 另一个可能的问题是错误地选择了最旧或最近的活动，而不是第二个最近的活动。 

例如：

 | 活动 | 结束日期 |
 | ---| ---|
 | 一个 | 2020-01-01 |
 | 乙| 2020-02-01 |
 | C | 2020-03-01 |
 | d | 2020-04-01 |

 正确答案是`C`， 不是`D`或者`B`。 

降序结合`ROW_NUMBER()`保证排名`2`与第二个最近的活动完全对应。 

### 重复行

 该表可能包含重复的行。 假设唯一性的幼稚实现可能会表现出不可预测的行为。 

例如：

 | 用户名 | 活动 | 结束日期 |
 | ---| ---| ---|
 | 爱丽丝| 旅游 | 2020-02-28 |
 | 爱丽丝| 旅游 | 2020-02-28 |

 窗口函数仍然一致地分配行号，并且查询仍然有效，因为排名纯粹基于排序规则。 

因此，该实现可以自然地处理重复项，而不需要特殊的重复数据删除逻辑。
