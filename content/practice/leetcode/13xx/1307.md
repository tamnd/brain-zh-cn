[LeetCode 第 1307 题](https://leetcode.com/problems/verbal-arithmetic-puzzle/)

 **难度：** 🔴难
 **主题：** 数组、数学、字符串、回溯

 ## 解决方案

 ## 问题理解

 该问题在方程的左侧给出了单词的集合，在右侧给出了单个结果单词。 每个不同的大写字母必须分配一个唯一的数字`0`到`9`。 将每个字母替换为指定的数字后，左侧单词表示的数值之和必须与结果单词表示的数值精确相加。 

例如，如果我们映射：

 -`S -> 9`-`E -> 5`-`N -> 6`-`D -> 7`然后`"SEND"`变成`9567`。 

挑战在于确定是否存在至少一个同时满足所有约束的有效数字分配。 

重要的限制是：

 - 不同的字母必须映射到不同的数字。 
- 多位单词的前导字符无法映射到`0`。 
- 至多`10`整体上出现不同的字母。 

最后的约束极其重要。 由于只有十位数字可用，因此任何解决方案都必须仔细搜索作业。 简单的暴力方法仍然可能变得非常昂贵，因为即使`10! = 3,628,800`在考虑验证成本之前就可以进行分配。 

另一个关键的观察结果是，这本质上是一个逐列算术难题，就像手动加法一样。 我们可以从右到左逐位验证加法，而不是先构建完整的数字。 

一些边缘情况尤其重要：

 - 主角无法成为`0`，即使这样做可以满足算术要求。 
- 由于进位传播，结果字可能比由一位数字组合的所有输入字长。 
- 有些谜题包含的字母少于十个，但仍然没有有效的作业。 
- 多个单词可以向同一列贡献数字。 
- 进位处理至关重要，因为进位传播中的错误会导致错误的解决方案。 

## 方法

 ### 蛮力方法

 暴力解决方案收集所有不同的字母，并使用数字排列尝试每个可能的数字分配`0-9`。 

对于每个作业：

 1. 确保没有前导字母映射到`0`2. 将每个单词转换成其数值
 3. 计算左侧单词的总和
 4. 与数值进行比较`result`这种方法是正确的，因为它详尽地检查了每个可能的有效映射。 如果存在有效的分配，暴力最终会找到它。 

然而，在最坏的情况下它太慢了。 对于多达十个唯一字符，该算法可能需要评估近`10!`作业。 此外，每次赋值都需要重复重建多个整数。 

### 最佳解决方案的关键见解

 关键的观察是算术从右到左逐列进行。 

我们可以在构造分配时逐步验证约束，而不是先分配所有数字然后再验证。 

假设我们像手动加法一样处理方程：```
  SEND
+ MORE
------
 MONEY
```从最右边的列开始：```
D + E = Y
```然后：```
N + R + carry = E
```在每一列，我们只需要与进位保持局部一致性。 

这可以实现积极的修剪：

 - 如果部分赋值已经违反算术，我们立即停止探索该分支。 
- 我们从不构建无效的完整作业。 
- 进位传播自然会限制未来的选择。 

这将问题转化为有效的回溯搜索。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(10! × k) | O(10! × k) | O(10) | 尝试每个数字排列并随后验证 |
 | 最佳| O(10!) 最坏情况，大量修剪 | O(10) | 按列回溯尽早消除无效状态 |

 这里，`k`表示构建和验证数字的成本。 

## 算法演练

 ### 第 1 步：颠倒单词

 我们处理从最低有效数字到最高有效数字的加法，因此反转每个单词可以使索引更容易。 

例如：```
SEND -> DNES
MORE -> EROM
MONEY -> YENOM
```现在索引`0`对应于个位。 

### 第 2 步：跟踪角色分配

 我们维持：

 - 从字符到数字的映射
 - 一个布尔数组，指示哪些数字已被使用

 这确保了有效地执行唯一性约束。 

哈希映射是理想的，因为字符查找和更新是恒定时间。 

### 第 3 步：确定主角

 多位单词的任何前导字符都不能映射到`0`。 

我们将这些字符存储在一个集合中，以便我们可以在回溯期间快速拒绝无效的分配。 

### 步骤 4：逐列处理

 我们递归地处理：

 - 当前列索引
 - 该列中的当前单词索引
 - 当前持有值

 在每一列：

 - 将左侧单词中的所有数字相加
 - 与结果字中所需的数字进行比较

 这准确地反映了基本加法。 

### 步骤 5：处理指定的字符

 如果一个字符已经有数字分配：

 - 直接使用该数字
 - 继续递归

 不需要额外的分支。 

### 步骤 6：尝试使用可能的数字来查找未分配的字符

 如果未分配字符：

 1. 迭代数字`0-9`2. 跳过已经使用的数字
 3. 跳过`0`对于主角
 4. Tentatively assign the digit
 5. 更深层次的递归
 6. Backtrack if necessary

 回溯系统地探索所有有效的可能性。 

### Step 7: Validate the Result Column

After summing all left-side digits in a column:```
expected_digit = total % 10
new_carry = total // 10
```结果字符必须等于`expected_digit`。 

如果没有，则该分支是不可能的，并且会立即被修剪。 

### 第 8 步：移至下一列

 验证列后：

 - 前进到下一栏
 - 传递结转

 递归继续进行，直到处理完所有列。 

### 步骤 9：最终验证

 处理完所有列后：

 - 只有最终的进位是，谜题才能解决`0`否则，算术不完整。 

### 为什么它有效

 该算法保持严格的不变量：

 > 每个处理的列都满足当前分配下的有效算术。 

由于递归仅在每列局部正确时才会进行，因此任何完成的赋值都会自动满足全局的整个方程。 由于搜索系统地探索了所有有效的分配，因此该算法既正确又完整。 

## Python 解决方案```python
from typing import List

class Solution:
    def isSolvable(self, words: List[str], result: str) -> bool:
        reversed_words = [word[::-1] for word in words]
        reversed_result = result[::-1]

        leading_chars = set()

        for word in words:
            if len(word) > 1:
                leading_chars.add(word[0])

        if len(result) > 1:
            leading_chars.add(result[0])

        char_to_digit = {}
        used_digits = [False] * 10

        max_len = max(len(result), max(len(word) for word in words))

        def backtrack(column: int, row: int, current_sum: int) -> bool:
            if column == max_len:
                return current_sum == 0

            if row == len(reversed_words):
                result_char = (
                    reversed_result[column]
                    if column < len(reversed_result)
                    else None
                )

                digit = current_sum % 10
                carry = current_sum // 10

                if result_char in char_to_digit:
                    if char_to_digit[result_char] != digit:
                        return False

                    return backtrack(column + 1, 0, carry)

                if used_digits[digit]:
                    return False

                if digit == 0 and result_char in leading_chars:
                    return False

                char_to_digit[result_char] = digit
                used_digits[digit] = True

                if backtrack(column + 1, 0, carry):
                    return True

                del char_to_digit[result_char]
                used_digits[digit] = False

                return False

            if column >= len(reversed_words[row]):
                return backtrack(column, row + 1, current_sum)

            current_char = reversed_words[row][column]

            if current_char in char_to_digit:
                return backtrack(
                    column,
                    row + 1,
                    current_sum + char_to_digit[current_char]
                )

            for digit in range(10):
                if used_digits[digit]:
                    continue

                if digit == 0 and current_char in leading_chars:
                    continue

                char_to_digit[current_char] = digit
                used_digits[digit] = True

                if backtrack(
                    column,
                    row + 1,
                    current_sum + digit
                ):
                    return True

                del char_to_digit[current_char]
                used_digits[digit] = False

            return False

        return backtrack(0, 0, 0)
```该实现遵循前面描述的精确的按列递归策略。 

首先将单词和结果反转，以便索引`0`对应于最低有效数字。 这简化了遍历，因为算术加法自然是从右向左进行的。 

这`leading_chars`set 可以防止多位数字以零开头的非法赋值。 

递归`backtrack`函数有三个参数：

 -`column`, 当前数字列
 -`row`，我们当前正在该列中处理哪个单词
 -`current_sum`，包括进位在内的累计金额

 当当前列中的所有单词都已处理完毕后，算法将验证相应的结果数字。 如果数字分配不一致，则立即修剪分支。 

通过尝试所有未使用的数字来探索未分配的字符。 递归返回后，分配被撤消，因此可以干净地探索替代可能性。 

仅当处理完所有列并且没有剩余进位时，递归才能成功终止。 

## 解决方案```go
package main

func isSolvable(words []string, result string) bool {
	reversedWords := make([][]byte, len(words))

	maxLen := len(result)

	for i, word := range words {
		reversedWords[i] = reverse(word)

		if len(word) > maxLen {
			maxLen = len(word)
		}
	}

	reversedResult := reverse(result)

	leadingChars := make(map[byte]bool)

	for _, word := range words {
		if len(word) > 1 {
			leadingChars[word[0]] = true
		}
	}

	if len(result) > 1 {
		leadingChars[result[0]] = true
	}

	charToDigit := make(map[byte]int)
	usedDigits := make([]bool, 10)

	var backtrack func(column, row, currentSum int) bool

	backtrack = func(column, row, currentSum int) bool {
		if column == maxLen {
			return currentSum == 0
		}

		if row == len(reversedWords) {
			if column >= len(reversedResult) {
				return false
			}

			resultChar := reversedResult[column]

			digit := currentSum % 10
			carry := currentSum / 10

			if assignedDigit, exists := charToDigit[resultChar]; exists {
				if assignedDigit != digit {
					return false
				}

				return backtrack(column+1, 0, carry)
			}

			if usedDigits[digit] {
				return false
			}

			if digit == 0 && leadingChars[resultChar] {
				return false
			}

			charToDigit[resultChar] = digit
			usedDigits[digit] = true

			if backtrack(column+1, 0, carry) {
				return true
			}

			delete(charToDigit, resultChar)
			usedDigits[digit] = false

			return false
		}

		if column >= len(reversedWords[row]) {
			return backtrack(column, row+1, currentSum)
		}

		currentChar := reversedWords[row][column]

		if assignedDigit, exists := charToDigit[currentChar]; exists {
			return backtrack(
				column,
				row+1,
				currentSum+assignedDigit,
			)
		}

		for digit := 0; digit <= 9; digit++ {
			if usedDigits[digit] {
				continue
			}

			if digit == 0 && leadingChars[currentChar] {
				continue
			}

			charToDigit[currentChar] = digit
			usedDigits[digit] = true

			if backtrack(
				column,
				row+1,
				currentSum+digit,
			) {
				return true
			}

			delete(charToDigit, currentChar)
			usedDigits[digit] = false
		}

		return false
	}

	return backtrack(0, 0, 0)
}

func reverse(s string) []byte {
	n := len(s)
	reversed := make([]byte, n)

	for i := 0; i < n; i++ {
		reversed[i] = s[n-1-i]
	}

	return reversed
}
```Go 实现与 Python 版本非常相似，但一些特定于语言的细节有所不同。 

Go 没有内置的哈希集，所以`map[byte]bool`用于前导字符集。 

字符分配使用存储`map[byte]int`。 由于 Go 区分缺失键和零值，因此代码使用二值映射查找形式：```go
value, exists := map[key]
```回溯清理用途`delete()`干净地删除分配。 

字符串被转换为反向字节切片，因为索引字节比重复切片字符串更高效、更方便。 

整数溢出不是问题，因为由于问题限制，最大进位仍然很小。

 ## 边缘情况

 ### 领先零违规

 一个非常常见的错误是意外地允许主角映射到`0`。 

例如：```
SEND -> 0123
```这是无效的，因为数字不能包含前导零。 

该实现通过存储集合中的所有前导字符并拒绝此类字符接收数字的任何分配来防止这种情况发生`0`。 

### 跨多列进行传播

 有些谜题需要进位连续传播到许多列。 

例如：```
999 + 1 = 1000
```在口头算术形式中，类似的进位链很常见。 不正确的进位处理会导致细微的算术错误。 

递归算法显式计算：```
digit = total % 10
carry = total // 10
```对于每一列，确保进位正确传播。 

### 重复字符

 一个字母可能会在不同的单词和列中多次出现。 

例如：```
AA + BB = CC
```每次出现相同的字符必须始终映射到相同的数字。 

该实现使用以下方式保证一致性`char_to_digit`地图。 一旦角色收到数字分配，所有未来的出现都会自动重复使用该确切的数字。
