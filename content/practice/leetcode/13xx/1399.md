[LeetCode 第 1399 题](https://leetcode.com/problems/count-largest-group/)

 **难度：** 🟢简单
 **主题：** 哈希表、数学、计数

 ## 解决方案

 ## 问题理解

 该问题要求我们将所有整数分组`1`到`n`基于它们的数字之和。 每个数字都属于一组，通过将其所有十进制数字加在一起来确定。 

例如：

-`14`有数字和`1 + 4 = 5`-`5`还有数字和`5`所以这两个数字属于同一组。 

另一方面：

-`13`有数字和`4`-`3`有数字和`3`所以他们属于不同的群体。 

组成所有组后，我们必须确定哪个组的规模最大。 然后我们返回有多少个组具有该最大大小。 

例如，如果组有大小：```
2, 2, 2, 2, 1, 1, 1
```那么最大尺寸是`2`，并且有`4`具有该大小的组，所以答案是`4`。 

输入由单个整数组成`n`， 在哪里：```
1 <= n <= 10^4
```这个限制相对较小。 即使是迭代每个数字并单独计算数字总和的简单解决方案也能在时间限制内顺利运行。 

问题的重要部分是正确地对数字进行分组和跟踪频率。 

一些重要的边缘情况包括：

 -`n = 1`，其中只有一组。 
- 小值，例如`n = 2`，其中每个组都有大小`1`。 
- 多个组并列以获得最大尺寸的值。 
- 只有一组具有最大大小的值。 
- 具有多个数字的数字，其中数字和计算必须正确工作。 

因为上限只有`10^4`，效率不是主要问题，但我们仍然应该设计一个干净且最佳的计数解决方案。 

## 方法

 ### 蛮力方法

 最直接的方法是明确地构建每个组。 

对于每个数字`1`到`n`:

 1. 计算数字和。 
2. 将数字存储在与该数字和对应的列表中。 
3. 处理完所有数字后，检查所有组。 
4. 找出最大组人数。 
5. 计算有多少组具有该大小。 

这种方法是正确的，因为每个数字都根据其数字和准确地分配到一组。 处理完所有数字后，分组准确地反映了问题定义。 

然而，没有必要将每个数字都存储在列表中。 该问题只要求每个组的大小，而不要求实际内容。 

### 最佳方法

 我们不存储完整的组，而是只存储属于每个数字和的数字的计数。 

关键的观察是，在对它们进行分组后，我们永远不需要实际的数字。 我们只关心：

 - 每组有多大
 - 有多少组共享最大大小

 所以我们可以使用哈希映射：```
digit_sum -> frequency
```对于每个数字：

 1. 计算其数字和。 
2. 增加相应的频率。 

处理完所有数字后：

 1. 找出最大频率。 
2. 计算有多少个频率等于该最大值。 

这减少了内存使用并保持实现简单。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n × d) | O(n) | 存储完整的数字组 |
 | 最佳 | O(n × d) | O(1) | O(1) | 仅存储组计数 |

 这里，`d`表示数字中的位数。 自从`n <= 10^4`,`d`至多是`5`。 

## 算法演练

 1. 创建哈希映射来存储组大小。 

键是数字总和，值是有多少个数字属于该组。 
2. 遍历其中的每个数字`1`到`n`。 

每个数字必须准确地分配给一组。 
3. 计算当前数字的数字和。 

使用模重复提取最后一位数字`% 10`，将其添加到运行总计中，然后使用整数除法删除最后一位数字`// 10`。 
4. 增加该数字和的频率。 

如果之前没有出现过数字和，则将其计数初始化为`0`第一的。 
5. 处理完所有数字后，确定最大的组大小。 

这只是哈希图中的最大值。 
6. 计算有多少个组具有该最大大小。 

迭代所有频率并计算有多少频率等于最大值。 
7. 返回最终计数。 

### 为什么它有效

 每个数字都来自`1`到`n`根据其数字和准确地分配给一组。 哈希映射准确地记录了每个组的大小，因为每次出现都会使正确的频率恰好增加一次。 

处理完所有数字后，最大频率对应于最大组大小。 计算有多少组共享此最大值即可给出所需的答案。 

因此，该算法总是产生正确的结果。 

## Python 解决方案```python
class Solution:
    def countLargestGroup(self, n: int) -> int:
        def digit_sum(num: int) -> int:
            total = 0

            while num > 0:
                total += num % 10
                num //= 10

            return total

        group_count = {}

        for num in range(1, n + 1):
            current_sum = digit_sum(num)

            if current_sum not in group_count:
                group_count[current_sum] = 0

            group_count[current_sum] += 1

        largest_size = max(group_count.values())

        answer = 0

        for size in group_count.values():
            if size == largest_size:
                answer += 1

        return answer
```实现首先定义一个名为的辅助函数`digit_sum`。 此函数使用重复的模数和整数除法运算来计算给定数字的数字总和。 

接下来是字典`group_count`存储有多少个数字属于每个数字和组。 

循环从`1`到`n`每个数字只处理一次。 对于每个数字，我们计算其数字和并增加字典中相应的频率。 

处理完所有数字后，`max(group_count.values())`找到最大的组大小。 

最后，另一个循环计算有多少个组具有该大小并返回结果。 

该实现直接遵循前面描述的算法，并且仅使用问题所需的信息。 

## 解决方案```go
func countLargestGroup(n int) int {
    digitSum := func(num int) int {
        total := 0

        for num > 0 {
            total += num % 10
            num /= 10
        }

        return total
    }

    groupCount := make(map[int]int)

    for num := 1; num <= n; num++ {
        currentSum := digitSum(num)
        groupCount[currentSum]++
    }

    largestSize := 0

    for _, size := range groupCount {
        if size > largestSize {
            largestSize = size
        }
    }

    answer := 0

    for _, size := range groupCount {
        if size == largestSize {
            answer++
        }
    }

    return answer
}
```Go 的实现与 Python 解决方案非常相似。 

主要区别在于 Go 使用`map[int]int`而不是 Python 字典。 Go 映射会自动返回缺失键的零值，因此我们可以直接递增：```go
groupCount[currentSum]++
```而不检查密钥是否已经存在。 

数字和助手是作为分配给的匿名函数实现的`digitSum`。 

由于所有值都很小并且`n <= 10^4`，整数溢出不是问题。

自从`n <= 10^4`，最大位数仅为`5`，使算法有效地线性化。 

空间复杂度在技术上是恒定的，因为最大可能的数字和非常小。 即使是为了`9999`，数字和仅为`36`，因此组的数量仍然是有界的。

 ## 边缘情况

 一个重要的边缘情况是尽可能最小的输入，`n = 1`。 在这种情况下，只有一个数字，因此只有一组。 有错误的实现可能会错误地初始化计数器或在计算最大频率时失败。 这种实现很自然地处理它，因为字典将恰好包含一个具有频率的条目`1`。 

当每个组的大小相同时，会发生另一个重要的情况，例如`n = 2`。 在这里，两个组都只包含一个元素。 某些实现错误地返回最大组的大小，而不是具有该大小的组的数量。 该解决方案显式地计算有多少组与最大频率匹配，因此它返回正确的结果。 

第三种边缘情况涉及跨越数字边界的转换，例如从`9`到`10`。 数字和变化自`9`到`1`，这意味着实现必须正确处理多位数字。 辅助函数会重复提取数字，直到数字变为零，因此可以正确处理任意位数的数字。 

另一个微妙的边缘情况是靠近上限约束的大值，例如`10000`。 该实现仍然高效，因为每个数字的数字和计算量非常小，并且可能的数字和的数量受到严格限制。 这可以防止内存过度增长或性能下降。
