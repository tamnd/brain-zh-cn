[LeetCode 问题 1375](https://leetcode.com/problems/number-of-times-binary-string-is-prefix-aligned/)

 **难度：** 🟡 中等
 **主题：** 数组

 ## 解决方案

 ## 问题理解

 该问题要求我们确定二进制字符串在一系列位翻转期间变为**前缀对齐**的次数。 我们从一个长度的二进制字符串开始`n`所有位都在哪里`0`。 我们得到了一份清单`flips`长度`n`，它表示位翻转的顺序`0`到`1`。 二进制字符串在步骤中**前缀对齐**`i`如果第一个`i`位都是`1`和所有剩余的位是`0`。 

输入`flips`是**1索引**，意思是`flips[i]`指从 1 开始的位位置。该数组是以下排列`[1, n]`，因此每个索引将被翻转一次。 预期输出是一个整数，表示字符串前缀对齐的步骤数。 

限制因素`1 <= n <= 5 * 10^4`意味着 O(n²) 的解决方案太慢了。 自从`flips`保证是一个排列，我们不必处理重复或无效的索引，从而简化了逻辑。 关键的边缘情况包括小型数组、仅在最末尾发生前缀对齐的数组以及间歇性多次发生对齐的数组。 

## 方法

 **暴力方法**将模拟二进制字符串。 每次翻转后，我们检查是否是第一个`i`位都是`1`和所有其他人都是`0`。 这涉及到在每一步迭代字符串，这会导致 O(n²) 时间复杂度。 这是正确的，但对于大型企业来说效率低下`n`。 

**最佳方法**依赖于一个关键观察：如果在步骤`i`，**到目前为止翻转的最大索引**等于`i`。 这是有效的，因为对于第一个`i`位全为 1，我们必须翻转所有索引`1`到`i`恰好一次，并且任何大于的索引`i`还不能翻转。 通过跟踪最大翻转索引并将其与当前步数进行比较，我们可以在 O(n) 时间内确定对齐情况。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 模拟字符串并在每一步检查前缀对齐 |
 | 最佳 | O(n) | O(1) | O(1) | 跟踪最大翻转索引； 与步数比较 |

 ## 算法演练

 1.初始化两个变量：`max_flipped = 0`跟踪迄今为止翻转的最大索引以及`prefix_count = 0`计算前缀对齐的状态。 
2. 迭代数组`flips`带有循环索引`i`从 1 到`n`。 
3. 对于每个`flips[i]`， 更新`max_flipped`成为最大的`max_flipped`和`flips[i]`。 
4.更新后`max_flipped`，检查是否`max_flipped == i`。 如果是这样，则增加`prefix_count`。 
5. 继续循环，直到处理完所有翻转。 
6. 返回`prefix_count`作为二进制字符串前缀对齐的次数。 

**为什么有效：** 在步骤中`i`，如果到目前为止翻转的最大索引等于`i`，这保证了所有索引`1`通过`i`恰好被翻转一次（因为排列中没有间隙），这正是字符串前缀对齐的条件。 

## Python 解决方案```python
from typing import List

class Solution:
    def numTimesAllBlue(self, flips: List[int]) -> int:
        max_flipped = 0
        prefix_count = 0
        
        for i, flip in enumerate(flips, start=1):
            max_flipped = max(max_flipped, flip)
            if max_flipped == i:
                prefix_count += 1
        
        return prefix_count
```在此 Python 实现中，我们循环`flips`同时跟踪最大翻转索引`max_flipped`。 循环索引`i`为 1 索引以匹配问题描述。 每次`max_flipped`等于`i`，我们增加`prefix_count`。 最后，该函数返回总计数。 

## 解决方案```go
func numTimesAllBlue(flips []int) int {
    maxFlipped := 0
    prefixCount := 0
    
    for i, flip := range flips {
        step := i + 1
        if flip > maxFlipped {
            maxFlipped = flip
        }
        if maxFlipped == step {
            prefixCount++
        }
    }
    
    return prefixCount
}
```在 Go 中，我们使用标准的 for 循环`flips`片。 由于 Go 切片是 0 索引的，我们计算`step := i + 1`与 1 索引逻辑保持一致。 这`maxFlipped`变量跟踪迄今为止翻转的最大索引，并且`prefixCount`计算前缀对齐的步数。

 ## 边缘情况

 第一个边缘情况是当`n = 1`。 在这里，单次翻转总是会产生前缀对齐的字符串。 该实现自然地处理了这个问题，因为`max_flipped`将等于`i`在第一次迭代中。 

当第一次翻转是最大索引时，会出现第二种边缘情况。 最大翻转索引可能会超过当前步数，因此在翻转足够的较小索引之前不会发生前缀对齐。 我们的算法仅通过检查来解释这一点`max_flipped == i`。 

第三种边缘情况是翻转按递增顺序进行。 每一步都会生成一个前缀对齐的字符串。 该算法正确地计算了每个步骤，因为`max_flipped`总是等于`i`。 这表明该解决方案可以推广到稀疏排列和顺序排列。
