[LeetCode 问题 1309](https://leetcode.com/problems/decrypt-string-from-alphabet-to-integer-mapping/)

 **难度：** 🟢简单
 **主题：** 字符串

 ## 解决方案

 ## 问题理解

 该问题给了我们一个包含数字的字符串和`'#'`特点。 该字符串使用特殊的映射规则对小写英文字母进行编码。 

映射以两种不同的方式工作：

 - 数字`'1'`通过`'9'`代表字母`'a'`通过`'i'`- 两位数字后跟`'#'`， 从`"10#"`通过`"26#"`, 代表字母`'j'`通过`'z'`我们的任务是解码整个字符串并返回相应的明文字符串。 

例如，编码后的字符串`"10#11#12"`应该变成：

 -`"10#"`→`'j'`-`"11#"`→`'k'`-`"1"`→`'a'`-`"2"`→`'b'`所以最终的答案是`"jkab"`。 

重要的观察是编码是唯一可解码的。 该问题保证每个输入字符串都是有效的并且只有一种解释。 这意味着我们永远不需要在多种解码可能性之间进行猜测。 

输入长度最大可达1000个字符，相对较小。 即使是低效的解决方案也可能会通过，但我们仍然应该以干净的线性时间解决方案为目标。 

幼稚的实现很容易在解析过程中犯错误`"10#"`通过`"26#"`。 由于单位数和两位数形式都存在，我们必须仔细区分：

 -`"1"`意义`'a'`-`"10#"`意义`'j'`这`'#'`字符是关键信号，表明前两位数字应一起视为单个数字。 

一些重要的边缘情况包括：

 - 仅包含单位数字映射的字符串
 - 字符串仅包含`'#'`基于映射
 - 两种形式同时出现的混合编码
 - 连续`'#'`图案
 - 输入接近最大长度

 因为保证输入有效，所以我们不需要处理格式错误的情况，例如`"27#"`或流浪`'#'`人物。 

## 方法

 ### 蛮力方法

 暴力解决方案将通过重复检查每个可能的子字符串并检查它是否形成有效的编码来尝试重建解码的字符串。 

在每个位置，我们可以尝试：

 - 一位数解码
 - 以以下结尾的三字符解码`'#'`这种方法之所以有效，是因为每个有效的编码都对应于这两种格式之一。 

然而，真正的强力递归实现可能会反复重新计算重叠的子问题。 例如，当从位置解码时`i`，我们可能会多次重复解码相同的后缀。 

尽管输入大小足够小，甚至可以通过记忆来通过，但对于具有简单线性解析策略的问题来说，它引入了不必要的复杂性。 

### 最佳方法

 关键的见解是每个多位编码总是以`'#'`。 

这意味着我们可以从左到右或从右到左处理字符串，同时确定当前段是否是：

 - 一位数字映射
 - 两位数字映射，后跟`'#'`一个特别干净的策略是从右向左扫描。 

为什么这有帮助？ 

向后扫描时：

 - 如果我们遇到`'#'`，我们立即知道前两个数字属于一起
 - 否则，当前数字代表一个独立字符

 这完全消除了歧义，并允许我们一次性解码字符串。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 反复探索解码可能性|
 | 最佳| O(n) | O(n) | 使用单遍解析`'#'`标记|

 ## 算法演练

 1. 初始化一个空列表来存储解码后的字符。 

我们使用列表是因为重复附加字符是有效的。 最后，我们可以将列表连接成一个字符串。 
2. 从末尾向开头开始扫描字符串。 

向后处理使解析逻辑更简单，因为每个`'#'`直接告诉我们前两个数字属于一起。 
3. 在每个位置，检查当前字符是否为`'#'`。 

如果是的话：

 - 读取前两位数字
 - 将它们转换为整数
 - 将整数映射到其对应的字符
 - 指针向后移动 3 个位置
 4. 如果当前字符不是`'#'`，将其视为一位数字映射。 

将数字转换为整数并将其映射到相应的小写字母。 
5. 将每个解码的字符附加到结果列表中。 

由于我们向后扫描，因此按相反的顺序收集字符。 
6. 反转最后的结果列表。 

这将恢复解码字符串的原始从左到右顺序。 
7. 将字符连接成最终字符串并返回。 

### 为什么它有效

 该算法之所以有效，是因为编码格式明确。 

每两位数字映射必须以`'#'`，所以每当我们遇到`'#'`，我们确切地知道如何解释前两位数字。 任何不关联的数字`'#'`必须表示单个数字映射。 

通过从右到左处理字符串，我们总是知道是消耗一个字符还是三个字符。 这保证了每个编码段都被正确解码一次。 

## Python 解决方案```python
class Solution:
    def freqAlphabets(self, s: str) -> str:
        decoded_chars = []
        index = len(s) - 1

        while index >= 0:
            if s[index] == '#':
                number = int(s[index - 2:index])
                decoded_chars.append(chr(ord('a') + number - 1))
                index -= 3
            else:
                number = int(s[index])
                decoded_chars.append(chr(ord('a') + number - 1))
                index -= 1

        return ''.join(reversed(decoded_chars))
```该实现遵循算法演练中的确切逻辑。 

我们首先创建一个名为的空列表`decoded_chars`。 当我们处理字符串时，它会存储解码后的字母。 

变量`index`从字符串的末尾开始。 我们向后移动输入，因为这使得处理`'#'`模式简单明了。 

在循环中，我们检查当前字符是否是`'#'`。 

如果是，我们使用切片提取前两位数字：```python
s[index - 2:index]
```这给了我们对应于字母的两位数字`'j'`通过`'z'`。 

我们使用以下方法将数值转换为字符：```python
chr(ord('a') + number - 1)
```这从 ASCII 值转移`'a'`到所需的字符。 

如果当前字符不是`'#'`，那么它一定是一位数映射。 我们直接使用相同的字符转换公式对其进行解码。 

由于向后扫描时会附加字符，因此在加入最终字符串之前，解码列表会在末尾反转。 

## 解决方案```go
func freqAlphabets(s string) string {
    decoded := make([]byte, 0)
    index := len(s) - 1

    for index >= 0 {
        if s[index] == '#' {
            number := int(s[index-2]-'0')*10 + int(s[index-1]-'0')
            decoded = append(decoded, byte('a'+number-1))
            index -= 3
        } else {
            number := int(s[index] - '0')
            decoded = append(decoded, byte('a'+number-1))
            index--
        }
    }

    // Reverse the result
    for left, right := 0, len(decoded)-1; left < right; left, right = left+1, right-1 {
        decoded[left], decoded[right] = decoded[right], decoded[left]
    }

    return string(decoded)
}
```Go 实现遵循与 Python 版本相同的总体策略。 

一个显着的区别是 Go 字符串是基于字节的，因此我们使用`[]byte`切片以有效地构建结果。 

而不是子字符串解析`int()`，我们使用字符算术手动计算两位数：```go
int(s[index-2]-'0')*10 + int(s[index-1]-'0')
```由于解码后的字符以相反的顺序附加，因此我们在将字节切片转换回字符串之前手动反转字节切片。 

不存在整数溢出问题，因为最大可能值仅为 26。

 ## 边缘情况

 一种重要的边缘情况是当输入仅包含单位数字映射时，例如`"123456789"`。 有缺陷的实现可能会错误地尝试将数字分组在一起，即使没有尾随`'#'`。 此实现通过仅将数字视为两位数字编码来避免该问题`'#'`明确存在。 

另一个重要的案例是连续的`'#'`编码，例如`"10#11#12#"`。 当使用三个字符组时，前向解析实现可能会意外地跳过字符或未对齐索引。 通过向后扫描，此实现始终准确地知道何时消耗三个字符，从而防止索引处理错误。 

第三种边缘情况是最小输入大小，例如`"1"`。 某些实现可能会错误地假设在检查之前始终至少有三个可用字符`'#'`。 该解决方案可以安全地处理单个字符输入，因为它只访问`index - 2`当当前字符实际上是`'#'`，并且该问题保证有效的格式。
