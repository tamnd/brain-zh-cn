[LeetCode 第 1393 题](https://leetcode.com/problems/capital-gainloss/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 的`Stocks`表记录股票交易活动。 每行代表一个`Buy`或者`Sell`特定股票在特定日期的操作，以及交易价格。 

该表包含四列：

 | 专栏 | 意义|
 | ---| ---|
 |`stock_name`| 股票名称|
 |`operation`| 任何一个`'Buy'`或者`'Sell'`|
 |`operation_day`| 交易发生当天|
 |`price`| 成交价 |

 该问题要求我们计算每只股票的总资本收益或损失。 

当股票的出售价格高于购买价格时，就会产生资本收益：```
gain = sell_price - buy_price
```当股票的出售价格低于购买价格时，就会发生资本损失：```
loss = sell_price - buy_price
```每只股票可以多次买卖。 股票的最终答案是所有交易中所有收益和损失的总和。 

问题陈述中的重要保证是每个`Buy`有一个匹配的未来`Sell`，以及每一个`Sell`之前有对应的`Buy`。 这意味着交易始终有效且平衡。 

预期输出包含：

 | 专栏 | 意义|
 | ---| ---|
 |`stock_name`| 股票名称|
 |`capital_gain_loss`| 总损益|

 输出顺序并不重要。 

一个关键的观察结果是，每次买入都会减少利润，而每次卖出都会增加利润。 因为所有交易都是正确配对的，所以我们实际上不需要明确地将买入和卖出一一匹配。 我们可以简单地减去买入价并加上卖出价。 

一些重要的边缘情况包括只有一对买入/卖出的股票、具有多次盈利和亏损交易的股票以及总结果为负的股票。 问题中的保证确保我们永远不会遇到不匹配的操作。 

## 方法

 ### 蛮力方法

 一个简单的解决方案将明确地将每个`Buy`与其对应的操作`Sell`手术。 

对于每只股票，我们可以按以下方式对操作进行排序`operation_day`，然后模拟交易过程。 每当我们遇到一个`Buy`，我们存储它的价格。 当我们后来遇到一个`Sell`，我们计算：```
sell_price - buy_price
```并将其添加到运行总计中。 

这种方法之所以有效，是因为该问题保证了操作随着时间的推移是平衡的并且逻辑上有序的。 

然而，这种方法引入了不必要的簿记。 我们需要额外的逻辑来跟踪未完成的买入并将其与卖出配对。 虽然对于小型数据集来说仍然可以接受，但它比必要的更复杂。 

### 最佳方法

 关键的见解是，每笔交易的积极或消极贡献仅取决于操作类型。 

对于股票：

 - A`Buy`经营减少利润总额
 - A`Sell`经营增加利润总额

 因此，我们可以计算：```
capital_gain_loss =
SUM(sell prices) - SUM(buy prices)
```这极大地简化了解决方案。 

在 SQL 中，这可以使用`CASE`表达：```
SUM(
    CASE
        WHEN operation = 'Sell' THEN price
        ELSE -price
    END
)
```然后我们分组`stock_name`。 

这种方法更简单、更干净、更高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n log n) | O(n log n) | O(n) | 需要排序和显式交易配对 |
 | 最佳 | O(n) | O(1) | O(1) | 直接添加卖出并减去买入 |

 ## 算法演练

 1. 读取每一行`Stocks`桌子。 
2. For every operation, determine whether it contributes positively or negatively to the final profit.

 - 如果操作是`'Sell'`，添加价格。 
- 如果操作是`'Buy'`，减去价格。 
3. 对所有行进行分组`stock_name`以便每只股票积累自己的总利润或损失。 
4. 使用聚合`SUM()`函数来计算每只股票的最终价值。 
5. 返回结果表，其中包含：

 -`stock_name`-`capital_gain_loss`### 为什么它有效

 每笔完成的交易都包含一笔买入和一笔卖出：```
profit = sell_price - buy_price
```将所有卖出量相加并减去所有买入量所产生的结果与单独计算每笔交易然后将它们加在一起的结果完全相同。 因为该问题保证了有效的买入/卖出配对，所以这个不变量始终成立。 

## Python 解决方案```python
# Write your MySQL query statement below

SELECT
    stock_name,
    SUM(
        CASE
            WHEN operation = 'Sell' THEN price
            ELSE -price
        END
    ) AS capital_gain_loss
FROM Stocks
GROUP BY stock_name;
```该解决方案使用 SQL 聚合来计算每只股票的最终利润。 

这`CASE`表达式将每笔交易转换为正贡献或负贡献：

 -`Sell`贡献`+price`-`Buy`贡献`-price`这`SUM()`函数独立地累积每只股票的这些贡献。 

最后，`GROUP BY stock_name`确保每只股票收到自己计算的资本收益或损失。 

该实现很紧凑，因为买卖之间的数学关系消除了显式交易匹配的需要。

 ## 边缘情况

 ### 只有一个交易对的股票

 一只股票可能只有一个`Buy`和一个`Sell`。 这是最简单的有效场景，但是使事务跟踪过于复杂的实现仍然会引入错误。 SQL 解决方案自然地处理这个问题，因为它只是减去买入价格并加上卖出价格。 

### 总资本损失

 一些股票总体上可能会产生负面结果。 例如，以 30,000 买入并以 7,000 卖出的结果`-23,000`。 错误地假设利润始终为正的实施在这里将会失败。 聚合方法正确地保留了负总数。 

### 多个独立交易周期

 一只股票可以多次买卖。 幼稚的实现可能会意外地覆盖以前的利润而不是累积它们。 因为该解决方案使用`SUM()`，每笔交易都独立地对最终答案做出贡献。 

### 交易以任意行顺序出现

 不保证表中的行按天排序。 暴力模拟可能需要首先进行排序操作。 最佳解决方案根本不依赖于排序，因为无论行顺序如何，对销售求和并减去购买都会产生相同的最终结果。
