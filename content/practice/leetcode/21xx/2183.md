[LeetCode 问题 2183](https://leetcode.com/problems/count-array-pairs-divisible-by-k/)

 **难度：** 🔴难
 **主题：** 数组、哈希表、数学、计数、数论

 ## 解决方案

 ## 问题理解

 问题给了我们一个整数数组`nums`和一个整数`k`。 我们必须计算有多少个索引对`(i, j)`满足两个条件：

 1.`i < j`2.`nums[i] * nums[j]`可以整除`k`换句话说，对于数组中的每一对不同元素，我们检查它们的乘积是否包含整除所需的所有素因数`k`。 

输入尺寸很大：

 -`nums.length`可以达到`10^5`-`nums[i]`和`k`也可以达到`10^5`这些限制立即告诉我们，直接检查每一对可能会太慢。 二次算法最多需要大约`10^10`在最坏的情况下进行配对检查，这远远超出了可接受的限度。 

重要的数学观察是整除`k`仅取决于每个数字如何贡献因素`k`。 我们不需要完整的乘积值，我们只需要足够的信息来确定两个数字的组合因子是否涵盖了所有因子`k`。 

一些重要的边缘情况包括：

 -`k = 1`，其中每对都是有效的，因为每个整数都可以被 1 整除。 
- 没有一对可以满足条件的数组。 
- 每对都满足条件的数组。 
- 重复值，可以创建许多有效的组合。 
- 具有大值的大型数组，其中效率变得至关重要。 

该问题保证所有数字都是正整数，因此我们不需要担心负数或零。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每一个可能的对`(i, j)`。 

对于每对：

 1. 计算`nums[i] * nums[j]`2. 检查乘积是否能整除`k`3. 如果是，则增加答案

 这是有效的，因为它明确地测试了问题所需的确切条件。 

但时间复杂度太大。 和`n = 10^5`，对的数量大约为：$$\frac{n(n-1)}{2}$$这是关于`5 * 10^9`最坏情况下的比较。 这太慢了。 

### 最佳方法的关键见解

 我们可以关注最大公约数，而不是查看完整的乘积。 

对于每个数字`x`，计算：$$g = \gcd(x, k)$$这告诉我们哪些因素`k`已经由以下人员贡献`x`。 

假设我们已经处理了另一个具有 gcd 值的数字`g2`。 

我们想要：$$x \cdot y \equiv 0 \pmod{k}$$这相当于：$$k \mid (x \cdot y)$$使用 gcd 属性，我们只需要检查是否：$$g \cdot g2$$包含所有因素`k`， 意义：$$(g \cdot g2) \bmod k = 0$$这极大地减少了问题的规模，因为 gcd 值被限制为`k`，不是任意整数。 

我们可以将之前看到的 gcd 值的计数存储在哈希映射中，并有效地计算有效匹配。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 直接检查每对 |
 | 最佳| O(n × d) | O(d) | 使用 gcd 分组和除数兼容性 |

 这里，`d`是遇到的不同 gcd 值的数量，它受到以下除数数量的限制`k`。 

## 算法演练

 1. 初始化一个名为的哈希图`gcd_count`。 

该映射存储了之前有多少个数字产生了每个 gcd 值`k`。 
2. 将答案变量初始化为`0`。 

这将累积有效对的数量。 
3. 迭代每个数字`num`在`nums`。 

对于当前数字，计算：$$current\_gcd = \gcd(num, k)$$这代表了以下因素`k`贡献者`num`。 
4. 将当前 gcd 与所有先前看到的 gcd 值进行比较。 

对于每个存储的 gcd 值`previous_gcd`，检查是否：$$(current\_gcd \times previous\_gcd) \bmod k = 0$$如果为真，则任何具有 gcd 的数字`previous_gcd`与当前数字形成有效对。 
5. 将匹配 gcd 值的计数添加到答案中。 

由于哈希图存储频率，因此我们可以一次添加所有匹配对。 
6. 将当前的gcd插入到hash映射中。 

增加其频率，以便将来的数字可以与其配对。 
7. 继续，直到处理完所有号码。 
8. 返回累计答案。 

### 为什么它有效

 对于任何数字`x`，值`gcd(x, k)`准确捕捉哪些因素`k`存在于`x`。 

如果两个数有 gcd 值`g1`和`g2`，那么他们的乘积可以除以`k`正是当综合因素`g1`和`g2`涵盖了所有素因数`k`。 

因此，检查：$$(g1 \times g2) \bmod k = 0$$正确判断原乘积是否可以整除`k`。 

由于在处理后面的元素时，每对都只计算一次，因此算法会产生正确的答案。 

## Python 解决方案```python
from typing import List
from collections import defaultdict
from math import gcd

class Solution:
    def countPairs(self, nums: List[int], k: int) -> int:
        gcd_count = defaultdict(int)
        answer = 0

        for num in nums:
            current_gcd = gcd(num, k)

            for previous_gcd, frequency in gcd_count.items():
                if (current_gcd * previous_gcd) % k == 0:
                    answer += frequency

            gcd_count[current_gcd] += 1

        return answer
```实现直接遵循算法。 

这`gcd_count`哈希映射存储先前遇到的 gcd 值的频率。 这允许高效计数，因为多个较早的数字可能共享相同的 gcd。 

对于每个数字：

 1. 我们计算它的 gcd`k`2.我们测试与之前所有gcd组的兼容性
 3. 我们在答案中添加匹配频率
 4.我们存储当前的gcd以供将来处理

 表达式：```python
(current_gcd * previous_gcd) % k == 0
```是决定两个数字是否构成有效对的关键数学条件。 

使用`defaultdict(int)`简化了频率管理，因为丢失的密钥会自动从零开始。 

## 解决方案```go
package main

import "math"

func gcd(a int, b int) int {
	for b != 0 {
		a, b = b, a%b
	}
	return a
}

func countPairs(nums []int, k int) int64 {
	gcdCount := make(map[int]int64)
	var answer int64 = 0

	for _, num := range nums {
		currentGCD := gcd(num, k)

		for previousGCD, frequency := range gcdCount {
			if (currentGCD*previousGCD)%k == 0 {
				answer += frequency
			}
		}

		gcdCount[currentGCD]++
	}

	return answer
}

func main() {
	_ = math.MaxInt
}
```Go 解决方案密切反映了 Python 实现。 

一个重要的区别是使用`int64`的答案和频率计数。 有效对的数量可以超出 32 位整数的范围，因为最大对数量为：$$\frac{10^5 \times 99999}{2}$$这大约是`5 * 10^9`。 

gcd 辅助函数使用标准欧几里得算法。 

Go 映射需要显式的存在处理，但由于增加缺失的整数键默认为零，因此实现仍然简洁。

 ## 边缘情况

 ### 案例 1：`k = 1`什么时候`k = 1`，每个整数都可以被 1 整除。因此，每个可能的对都是有效的。 

有缺陷的实现可能会使整除逻辑过于复杂或意外地跳过对。 在此解决方案中，每个 gcd 都变为 1，并且：$$(1 \times 1) \bmod 1 = 0$$所以所有对都被正确计数。 

### 情况 2：单元素数组

 如果数组仅包含一个元素，则不会存在有效的对，因为对需要两个不同的索引。 

该实现自然会处理这个问题，因为循环在插入第一个元素之前从未找到任何先前存储的 gcd 值。 

### 情况 3：单个数字不能被整除`k`一些有效对仅在两个数字结合其因子时才会出现。 

例如：```
nums = [2, 3]
k = 6
```两者都不`2`也不`3`可以整除`6`， 但：$$2 \times 3 = 6$$它可以被整除`6`。 

一种简单的优化，仅检查可被单独整除的数字`k`会在这里失败。 基于 gcd 的方法正确地认识到：$$\gcd(2,6)=2$$和$$\gcd(3,6)=3$$和：$$2 \times 3 \equiv 0 \pmod{6}$$所以这对被计算在内。 

### 情况 4：许多重复值

 具有许多重复数字的数组可以创建大量有效对。 

例如：```
nums = [2,2,2,2,2]
k = 2
```每对都是有效的。 

频率图通过存储计数而不是独立处理重复值来有效地处理重复项。 这可以防止不必要的重复工作并保持算法的效率。
