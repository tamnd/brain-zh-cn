[LeetCode 第 2130 题](https://leetcode.com/problems/maximum-twin-sum-of-a-linked-list/)

 **难度：** 🟡 中等
 **主题：** 链表、两个指针、堆栈

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个具有偶数个节点的单链表。 对于索引处的每个节点`i`，索引处有对应的孪生节点`n - 1 - i`， 在哪里`n`是列表中的节点总数。 

我们将孪生和定义为：

 -`node[i].val + node[n - 1 - i].val`我们的任务是计算所有有效双胞胎中的最大双胞胎和。 

例如，在列表中：```
[5,4,2,1]
```这些对是：

 -`5 + 1 = 6`-`4 + 2 = 6`所以答案是`6`。 

重要的细节是该列表是单向链接的。 与数组不同，我们无法直接访问最后一个元素或有效地向后移动。 这个限制使得这个问题变得有趣。 

限制条件很大：

 - 最多`10^5`节点
 - 节点值高达`10^5`因此，任何比线性或近线性时间更差的解决方案都可能太慢。 我们还需要仔细考虑内存的使用情况。 

该问题保证：

 - 列表长度始终是偶数
 - 至少有2个节点
 - 每个节点包含一个正整数

 这些保证简化了实现，因为我们永远不需要处理奇数长度列表或空列表。 

一些边缘情况很重要：

 - 只有两个节点的列表
 - 所有双胞胎的总和相等
 - 非常大的节点值
 - 清单很大，低效方法变得太慢
 - 最大孪生和出现在中间而不是末端的情况

 ## 方法

 ### 蛮力方法

 最直接的想法是首先将所有链表值复制到一个数组中。 

一旦我们有了数组，访问双节点就变得很容易，因为数组支持随机索引。 对于每个索引`i`在数组的前半部分，我们计算：```
values[i] + values[n - 1 - i]
```我们记录遇到的最大总和。 

这种方法很简单并且可以正确工作，因为数组保留了链表节点的原始顺序。 

然而，尽管该解决方案对于问题约束来说已经可以接受，但它使用与列表大小成比例的额外内存。 

不转换为数组的真正朴素的暴力方法将重复扫描链表以找到每个位置的匹配孪生节点。 这将需要嵌套遍历并导致二次时间复杂度，这对于`10^5`nodes.

 ### 最佳方法

 关键的见解是我们只需要比较列表两端的节点。 

由于单链表不能向后移动，我们可以通过将链表的后半部分反转来解决这个问题。 

The high-level idea is:

 1. 使用慢指针和快指针来查找列表的中间位置。 
2. 反转下半场。 
3. 同时移动两半。 
4. 计算孪生和并跟踪最大值。 

After reversal:

 - 上半场正常进行。 
- 逆转的下半场现在也按照我们需要的顺序前进。 

这将问题转化为两个链表之间的简单线性比较。 

因为我们就地反转列表，所以我们实现了持续的额外空间使用。

 ## 算法演练

 ### 最佳就地反转算法

 1. Use two pointers,`slow`和`fast`，从头部开始。 

移动：

-`slow`一步
 -`fast`分两步

 当`fast`到达终点，`slow`将指向下半场开始。 
2. 反转链表的后半部分。 

使用标准链表反转技术：

 - 轨道`prev`- 店铺`next_node`- 指针一一反转

 逆转之后，下半场现在从末端向中间进行。 
3.初始化两个指针：

 -`first_half`在原来的头
 -`second_half`在逆转的下半场开始时
 4. 同时移动两半。 

每一步：

 - 计算孪生和
 - 更新最大总和
 - 向前移动两个指针
 5. 返回找到的最大孪生和。 

### 为什么它有效

 慢指针和快指针技术保证我们将列表精确地分成两半，因为列表长度始终是偶数。 

反转后半部分，按遍历顺序对齐相应的孪生节点：```
Original:
1 -> 2 -> 3 -> 4

Second half reversed:
4 -> 3
```现在：

-`1`与`4`-`2`与`3`这与问题中定义的孪生关系完全匹配。 由于每对双胞胎都会检查一次，并且我们会跟踪最大值，因此算法总是会产生正确的答案。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

from typing import Optional

class Solution:
    def pairSum(self, head: Optional[ListNode]) -> int:
        slow = head
        fast = head

        # Find the middle of the list
        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next

        # Reverse the second half
        prev = None
        current = slow

        while current:
            next_node = current.next
            current.next = prev
            prev = current
            current = next_node

        # Compute maximum twin sum
        max_sum = 0
        first_half = head
        second_half = prev

        while second_half:
            twin_sum = first_half.val + second_half.val
            max_sum = max(max_sum, twin_sum)

            first_half = first_half.next
            second_half = second_half.next

        return max_sum
```实现首先使用经典的慢速和快速指针技术定位中点。 因为列表长度保证是偶数，所以`slow`指针恰好在下半场开始时结束。 

接下来，下半场原地逆转。 变量`prev`,`current`， 和`next_node`用于安全地反转指针方向，而不会失去对其余节点的访问。 

反转后，列表结构允许从左到右同时遍历孪生节点。 一个指针从原来的头部开始，另一个指针从反转的后半部分开始。 

每次迭代都会计算一个孪生和并更新运行最大值。 

处理完所有孪生对后，算法结束。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func pairSum(head *ListNode) int {
    slow := head
    fast := head

    // Find middle of the list
    for fast != nil && fast.Next != nil {
        slow = slow.Next
        fast = fast.Next.Next
    }

    // Reverse second half
    var prev *ListNode
    current := slow

    for current != nil {
        nextNode := current.Next
        current.Next = prev
        prev = current
        current = nextNode
    }

    // Compute maximum twin sum
    maxSum := 0
    firstHalf := head
    secondHalf := prev

    for secondHalf != nil {
        twinSum := firstHalf.Val + secondHalf.Val

        if twinSum > maxSum {
            maxSum = twinSum
        }

        firstHalf = firstHalf.Next
        secondHalf = secondHalf.Next
    }

    return maxSum
}
```Go 实现遵循与 Python 解决方案相同的算法结构。 

一个区别是指针处理。 在 Go 中，链表节点是使用显式指针进行操作的，因此反转列表需要仔细重新分配`Next`参考。 

Go 也没有提供内置的`max`函数用于整数，因此最大值是使用手动更新的`if`陈述。 

由于节点值最多为`10^5`，整数溢出不是 Go 标准的问题`int`类型。

 ## 边缘情况

 ### 最小尺寸列表

 最小的有效输入恰好包含两个节点。 在这种情况下，只有一对双胞胎。 假设至少四个节点的算法可能会失败或错误地处理中点逻辑。 

该实现自然地处理了这个问题，因为慢速和快速指针遍历仍然可以正常工作，并且反转单节点后半部分是有效的。 

### 大节点值

 节点值可以大到`100000`。 如果某个实现在某些语言中使用了不适当的数字类型，则溢出可能会成为一个问题。 

提供的 Python 和 Go 实现可以安全地处理这些值，因为所得的总和完全在支持的整数范围内。 

### 不在末尾的最大双和

 一个常见的错误是假设第一个和最后一个节点总是产生最大的孪生和。 

例如：```
[1,10,20,30]
```双和是：```
1 + 30 = 31
10 + 20 = 30
```在其他情况下，内部对可能更大。 该实现正确地评估每对双胞胎，而不是依赖于有关排序的假设。 

### 反转指针错误

 链表反转很容易出错，因为修改指针可能会意外断开节点或创建循环。 

该实现通过始终存储来避免这种情况`next_node`改变之前`current.next`。 这保证了列表的剩余部分在反转期间永远不会丢失。
