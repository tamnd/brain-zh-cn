[LeetCode 问题 2113](https://leetcode.com/problems/elements-in-array-after-removing-and-replacing-elements/)

 **难度：** 🟡 中等
 **主题：** 数组

 ## 解决方案

 ## 问题理解

 该问题描述了一个连续经历重复的两阶段过程的阵列。 

分钟`0`，数组不变。 接下来的每一分钟，最左边的元素都会被删除，直到数组变空。 一旦数组为空，元素就会按照删除的顺序一一添加回数组末尾。 当原始阵列完全恢复后，整个过程将永远重复。 

例如，如果：```
nums = [0,1,2]
```状态序列变为：```
Minute 0: [0,1,2]
Minute 1: [1,2]
Minute 2: [2]
Minute 3: []
Minute 4: [0]
Minute 5: [0,1]
Minute 6: [0,1,2]
Minute 7: [1,2]
...
```每个查询包含两个整数：```
[time, index]
```对于给定的一分钟`time`，我们必须确定该数组在该时刻的样子。 如果`index`存在于当前数组中，我们返回该位置的值。 否则，我们返回`-1`。 

重要的观察结果是阵列状态循环重复。 如果原数组有长度`m`，那么：

 - 删除所有元素需要`m`分钟。 
- 重新添加所有元素需要另一个`m`分钟。 

Therefore, the process repeats every`2 * m`分钟。 

对于数组本身来说，约束很小：```
1 <= nums.length <= 100
```但查询的数量可能很大：```
1 <= queries.length <= 100000
```这告诉我们，我们无法独立模拟每个查询的每分钟过程。 相反，我们需要一种直接的数学方法来随时确定数组状态。 

一些边缘情况尤其重要：

 - 长度数组`1`- 全空状态下的查询
 - 精确地在循环边界进行查询
 - 具有非常大时间值的查询
 - 请求索引大于当前数组大小的查询

 该问题保证：```
0 <= indexj < nums.length
```因此，查询的索引相对于原始数组始终有效，尽管它在查询时可能不存在。 

## 方法

 ### 蛮力方法

 一种直接的方法是逐分钟地模拟该过程。 

我们可以重复维护当前的数组状态：

 1. 删除最左边的元素，直到数组变空。 
2. Append removed elements back in order.
 3. Repeat forever.

 对于每个查询，我们都会模拟数组直到请求的时间，然后检查查询的索引。 

这种方法是正确的，因为它完全遵循问题的规则。 然而，它的效率很低，因为查询时间可能长达`100000`，并且最多可以有`100000`查询。 

如果我们对每个查询进行独立模拟，复杂性就会变得太大。 

### 最佳方法

 关键的见解是该过程是完全周期性的。 

如果原数组长度为`m`，那么：

 - 收缩阶段持续`m`分钟。 
- 重建阶段还将持续`m`分钟。 

因此，整个过程每重复一次：```
2 * m
```分钟。 

我们可以使用模运算来减少每次查询时间，而不是每分钟进行模拟：```
phase = time % (2 * m)
```现在我们只需要分析数组在一个周期内的位置即可。 

有两种情况：

 1. 移除阶段，`phase < m`2.重建阶段，`phase >= m`在移除阶段：```
Current array = nums[phase:]
```因为第一个`phase`元素已被删除。 

在重建阶段：```
added = phase - m
Current array = nums[:added]
```因为第一个`added`元素已恢复。 

一旦我们知道当前的数组大小和映射，回答查询就变成常数时间。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(q × t) | O(米) | 模拟每个查询的每一分钟 |
 | 最佳| O(q) | O(1) | O(1) | 使用循环周期和直接索引 |

 这里：

-`q`is the number of queries
 -`t`是最大查询时间
 -`m`是`nums.length`## 算法演练

 1.计算原始数组长度`m`。 

整个过程取决于数组大小，因为一个完整的周期包括删除所有`m`元素，然后恢复所有`m`元素。 
2. 计算周期长度。 

一个完整的循环需要：```
cycle = 2 * m
```3. 独立处理每个查询。 

由于查询不会相互影响，因此我们可以一次回答一个。 
4.将查询时间减少到单个周期。 

计算：```
phase = time % cycle
```这告诉我们我们在重复模式中的位置。 
5. 确定我们是处于拆除阶段还是重建阶段。 

如果：```
phase < m
```然后我们正在删除元素。 

否则，我们将重建数组。 
6. 处理移除阶段。 

移除后`phase`前面的元素：```
current array = nums[phase:]
```当前大小变为：```
size = m - phase
```如果查询的索引超出此大小，则返回`-1`。 

否则：```
answer = nums[phase + index]
```7. 处理重建阶段。 

计算：```
restored = phase - m
```这意味着第一个`restored`元素已被添加回来。 

当前数组变为：```
nums[:restored]
```如果查询的索引超出此大小，则返回`-1`。 

否则：```
answer = nums[index]
```8. 将每个答案存储在结果数组中。 
9. 返回最终答案。 

### 为什么它有效

 该算法之所以有效，是因为数组的演化是完全确定性的和周期性的。 每个循环恰好在之后重复`2 * m`分钟。 在一个周期内，移除阶段总是对应原数组的后缀，重建阶段总是对应原数组的前缀。 通过直接计算查询属于哪个阶段，我们可以确定正确的值，而无需模拟。 

## Python 解决方案```python
from typing import List

class Solution:
    def elementInNums(self, nums: List[int], queries: List[List[int]]) -> List[int]:
        n = len(nums)
        cycle_length = 2 * n

        answers = []

        for time, index in queries:
            phase = time % cycle_length

            # Removal phase
            if phase < n:
                current_size = n - phase

                if index >= current_size:
                    answers.append(-1)
                else:
                    answers.append(nums[phase + index])

            # Rebuilding phase
            else:
                restored = phase - n
                current_size = restored

                if index >= current_size:
                    answers.append(-1)
                else:
                    answers.append(nums[index])

        return answers
```实现首先计算原始数组长度和总循环长度。 由于该过程每次都会重复`2 * n`分钟，使用模运算可以减少每次查询时间。 

对于每个查询，代码确定当前时刻是属于删除阶段还是重建阶段。 

在移除阶段，首先`phase`元素已被删除，因此剩余数组从`nums[phase]`。 如果请求的索引超过当前大小，则答案是`-1`。 否则，正确的元素位于`nums[phase + index]`。 

在重建阶段，数组由第一个组成`restored`原始数组的元素。 同样，在检索值之前会根据当前大小检查索引。 

该解决方案在恒定时间内独立处理每个查询。 

## 解决方案```go
func elementInNums(nums []int, queries [][]int) []int {
	n := len(nums)
	cycleLength := 2 * n

	answers := make([]int, 0, len(queries))

	for _, query := range queries {
		time := query[0]
		index := query[1]

		phase := time % cycleLength

		// Removal phase
		if phase < n {
			currentSize := n - phase

			if index >= currentSize {
				answers = append(answers, -1)
			} else {
				answers = append(answers, nums[phase+index])
			}
		} else {
			// Rebuilding phase
			restored := phase - n
			currentSize := restored

			if index >= currentSize {
				answers = append(answers, -1)
			} else {
				answers = append(answers, nums[index])
			}
		}
	}

	return answers
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 由于 Go 切片已经在恒定时间内提供索引访问，因此不需要额外的数据结构。 

一个小的实现细节是，结果切片的容量是预先分配的，其容量等于查询的数量，这避免了追加期间的重复重新分配。 

整数溢出不是问题，因为所有值都在 Go 的标准整数范围内。

 ## 边缘情况

 一个重要的边缘情况是长度数组`1`。 在这种情况下，循环每分钟在满数组和空数组之间交替。 许多不正确的实现意外地错误地处理了重建阶段，因为数组在变空后立即返回。 该实现通过模运算和相位检测自然地处理这个问题。 

当数组完全为空时，会出现另一个关键的边缘情况。 这恰好发生在几分钟内`n`每个周期内。 在此期间，每个查询的索引都必须返回`-1`。 该实现正确地将当前大小计算为零，导致所有索引都无法通过边界检查。 

较长的查询时间也很重要。 自从`timej`可以大到`100000`，直接模拟该过程效率低下。 该实现通过减少每个时间值以周期长度为模来完全避免这个问题。 无论时间有多大，这都保证了高效的恒定时间处理。 

最后一个微妙的情况是查询的索引存在于原始数组中但不存在于当前数组状态中。 例如：```
nums = [1,2,3]
time = 2
current array = [3]
```在这种状态下，只有索引`0`存在。 索引查询`1`或者`2`必须返回`-1`。 该实现在访问元素之前显式检查当前数组大小，防止无效索引并确保正确性。
