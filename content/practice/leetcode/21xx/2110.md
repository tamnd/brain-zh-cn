 ## 解决方案

 ## 问题理解

 这个问题要求我们计算股票价格数组中的所有“平滑下降期”。 平滑下降期被定义为连续的几天序列，其中股票价格**每天精确地下跌 1**，但第一天除外，它始终被算作长度为 1 的有效周期。本质上，每一天都算作长度为 1 的周期，并且连续价格之间的差异恰好为 1 的任何连续天序列都会贡献额外的周期。 

输入`prices`是一个大小最大为 100,000 的整数数组，每个价格在 1 到 100,000 之间。 预期输出是一个整数，表示平滑下降周期的总数。 

来自约束的关键见解包括数组可能很大，因此检查所有子数组的简单 O(n²) 解决方案将太慢。 此外，所有值都是正整数，因此我们不需要处理负价格。 

重要的边缘情况包括长度为 1 的数组、价格恒定的数组以及没有连续天数恰好减少 1 的数组。 

## 方法

 ### 蛮力

 强力方法将涉及检查每个可能的连续子阵列并验证它是否是平滑下降周期。 对于每个起始索引`i`，我们将向右扩展，同时连续元素之间的差恰好为 1，计算所有有效子数组。 这种方法保证了正确性，但对于大型数组来说太慢，因为它的时间复杂度为 O(n²)。 

### 最佳

 最佳解决方案的关键观察是平滑下降周期是连续的序列，并且序列长度中的周期数`k`由第一个的总和给出`k`整数。 我们可以迭代该数组一次，而不是枚举所有子数组，从而维护当前下降长度的运行计数。 对于每一天，如果`prices[i-1] - prices[i] == 1`，我们扩展当前序列； 否则，我们重置序列。 在每一步中，当天结束的平滑下降周期的数量等于当前序列的长度。 将这些计数相加即可得出周期总数。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 显式检查所有子数组 |
 | 最佳| O(n) | O(1) | O(1) | 单程，保持当前下降长度 |

 ## 算法演练

 1. 初始化`total_periods`为 0 以存储平滑下降周期的累积计数。 
2. 初始化`current_length`到 1，代表第一天结束的下降周期长度。 
3. 从索引 1 到 n-1 迭代数组。 
4. 对于每个索引`i`，检查是否`prices[i-1] - prices[i] == 1`。 

- 如果为真，则增加`current_length`1.
 - 否则，重置`current_length`到 1，因为下降期已经结束。 
5. 添加`current_length`到`total_periods`在每次迭代中，因为每天都会作为多个周期的结束做出贡献。 
6. 返回`total_periods`迭代完成后。 

为什么有效：该算法之所以有效，是因为每天结束的下降周期数恰好等于当前下降序列的长度。 添加这些计数可确保对所有子数组进行有效计数，而无需显式枚举它们。 

## Python 解决方案```python
from typing import List

class Solution:
    def getDescentPeriods(self, prices: List[int]) -> int:
        total_periods = 1  # first day is always a period
        current_length = 1
        
        for i in range(1, len(prices)):
            if prices[i-1] - prices[i] == 1:
                current_length += 1
            else:
                current_length = 1
            total_periods += current_length
        
        return total_periods
```在此 Python 实现中，我们首先将第一天计算为有效期限。 当我们遍历数组时，`current_length`跟踪当前平滑下降的长度。 每次我们移动到第二天，如果差值为 1，我们要么延长序列，如果不是 1，则重置序列。 添加`current_length`到`total_periods`确保对当天结束的所有子数组进行计数。 

## 解决方案```go
func getDescentPeriods(prices []int) int64 {
    totalPeriods := int64(1) // first day is always a period
    currentLength := 1
    
    for i := 1; i < len(prices); i++ {
        if prices[i-1] - prices[i] == 1 {
            currentLength++
        } else {
            currentLength = 1
        }
        totalPeriods += int64(currentLength)
    }
    
    return totalPeriods
}
```在Go中，我们需要使用`int64`以避免大型数组和计数的整数溢出。 逻辑反映了 Python 实现，迭代数组并更新`currentLength`和`totalPeriods`因此。

 ## 边缘情况

 一个重要的边缘情况是长度为 1 的数组。该算法正确地将其计为一个平滑下降周期。 另一个边缘情况是严格递增的数组，它应该只计算单日周期； 算法重置`current_length`每次，正确处理这个问题。 第三种边缘情况是具有长降序序列的大数组； 使用`int64`在 Go 中，可以防止大和的整数溢出，而在 Python 中，任意精度整数可以本地处理它。 具有重复数字的数组也需要正确重置，这是通过检查来管理的`prices[i-1] - prices[i] == 1`。
