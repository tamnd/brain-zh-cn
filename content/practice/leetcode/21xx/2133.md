[LeetCode 问题 2133](https://leetcode.com/problems/check-if-every-row-and-column-contains-all-numbers/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表、矩阵

 ## 解决方案

 ## 问题理解

 在这个问题中，我们给出了一个`n x n`矩阵，其中每个值都保证在`1`和`n`。 如果矩阵的每一行都包含来自的所有整数，则矩阵被认为是有效的`1`通过`n`恰好一次，并且每列还包含来自`1`通过`n`正好一次。 

另一种思考方式是每行和每列必须形成数字的完整排列`1`到`n`。 如果行或列中有任何数字缺失、重复或错误替换，则矩阵无效。 

输入是方阵：

 -`matrix[i][j]`代表行的值`i`和列`j`-`n`是行数和列数

 预期输出是：

 -`true`如果每一行和每一列都包含来自的所有整数`1`到`n`-`false`否则

 限制相对较小：

 -`1 <= n <= 100`- 每个元素都已保证在有效范围内`1`到`n`这些限制告诉我们一些重要的事情：

 - 我们不需要担心无效的数字范围
 - 安`O(n^2)`甚至`O(n^3)`解决方案是可以接受的，因为`n`至多是`100`- 简单性和正确性比大量优化更重要

 一个重要的观察是，重复项自动意味着缺失值，因为每一行和每一列都必须准确包含`n`一组大小中的数字`n`。 

一些可能导致错误的边缘情况包括：

 - 具有重复数字的行
 - 具有重复数字的列
 - 大小矩阵`1 x 1`- 行单独有效，但列无效
 - 遍历后期失败的列

 该问题保证所有值都在`1`和`n`，所以我们只需要验证唯一性和完整性即可。 

## 方法

 ### 蛮力方法

 蛮力方法根据预期集独立检查每一行和每一列`{1, 2, ..., n}`。 

对于每一行：

 1. 创建频率计数或集合
 2.插入所有行值
 3. 验证每个数字是否来自`1`到`n`只存在一次

 然后对每一列重复相同的过程。 

这种方法是正确的，因为当且仅当所有行和列都包含所需的完整数字集时，矩阵才有效。 

一个非常幼稚的暴力实现可能会重复扫描行和列来单独验证每个数字。 例如，对于每一行和每个数字`1`到`n`，我们可以搜索整行来查看该数字是否存在。 这会产生不必要的重复工作。 

尽管这仍然在限制范围内有效，但效率较低且不太优雅。 

### 最佳方法

 更好的方法使用哈希集来验证单次遍历中的行和列。 

对于每一行：

 - 创建一个集合
 - 插入所有行值
 - 如果设定的尺寸不是`n`, 存在重复项

 对于每一列：

 - 创建另一组
 - 插入所有列值
 - 如果设定的尺寸不是`n`, 存在重复项

 因为值保证位于`1`到`n`, 一组大小`n`自动意味着每个所需的数字恰好出现一次。 

关键的见解是唯一性加上有效范围意味着完整性。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n3) | O(1) | O(1) | 重复扫描行和列以查找每个预期的数字 |
 | 最佳| O(n²) | O(n) | 使用哈希集有效地验证行和列 |

 ## 算法演练

 1.确定矩阵大小`n`。 

由于矩阵是方阵，因此行数也是列数。 
2. 迭代每行索引`i`。 

对于每一行，创建一个名为的空集`row_values`。 该集跟踪当前行中出现的数字。 
3. 迭代每个列索引`j`行内。 

插入`matrix[i][j]`进入`row_values`。 
4. 处理完行后，检查设置的大小。 

如果大小不等于`n`，则某个数字重复而另一个数字丢失。 返回`False`。 
5. 对色谱柱重复相同的过程。 

对于每个列索引`j`，创建一个新集合，名为`column_values`。 
6. 遍历当前列的所有行。 

插入`matrix[i][j]`进入`column_values`。 
7. 验证列集大小。 

如果大小不等于`n`，该列无效。 返回`False`。 
8. 如果所有行和列都通过验证，则返回`True`。 

### 为什么它有效

 矩阵中的每个值都保证在`1`和`n`。 因此，如果行或列恰好包含`n`唯一值，它必须包含来自`1`到`n`。 

该算法检查每一行和每一列的此属性。 如果任何行或列违反条件，则矩阵无效。 否则，矩阵满足有效性的定义。 

## Python 解决方案```python
from typing import List

class Solution:
    def checkValid(self, matrix: List[List[int]]) -> bool:
        n = len(matrix)

        # Check every row
        for row in matrix:
            if len(set(row)) != n:
                return False

        # Check every column
        for col in range(n):
            column_values = set()

            for row in range(n):
                column_values.add(matrix[row][col])

            if len(column_values) != n:
                return False

        return True
```实现首先将矩阵大小存储在`n`。 

第一个循环验证每一行。 将行转换为集合会自动删除重复项。 如果结果集大小小于`n`，然后某个值多次出现。 

第二部分验证列。 由于列不是直接存储为列表，因此我们通过遍历固定列索引的所有行来手动构建临时集。 

如果任何行或列验证失败，该函数立即返回`False`。 这种提前退出可以避免不必要的工作。 

如果算法成功完成所有检查，则矩阵满足所需条件并且函数返回`True`。 

## 解决方案```go
func checkValid(matrix [][]int) bool {
	n := len(matrix)

	// Check rows
	for i := 0; i < n; i++ {
		rowSet := make(map[int]bool)

		for j := 0; j < n; j++ {
			rowSet[matrix[i][j]] = true
		}

		if len(rowSet) != n {
			return false
		}
	}

	// Check columns
	for j := 0; j < n; j++ {
		colSet := make(map[int]bool)

		for i := 0; i < n; i++ {
			colSet[matrix[i][j]] = true
		}

		if len(colSet) != n {
			return false
		}
	}

	return true
}
```Go 实现遵循与 Python 版本相同的逻辑，但使用`map[int]bool`模拟哈希集。 

Go 没有内置的集合类型，因此将键插入映射并检查映射长度是标准方法。 

由于所有整数都很小且在约束范围内，因此不必担心整数溢出。 

切片自然地用于矩阵遍历，并且不需要对空或零矩阵进行特殊处理，因为该问题保证了有效的输入维度。

 | 测量| 复杂性 | 说明|

 ## 边缘情况

 一个`1 x 1`矩阵是最小的可能输入。 由于唯一允许的值为`1`，如果矩阵包含该数字，则该矩阵自动有效。 某些实现意外地使这种情况变得过于复杂，但是基于集合的方法可以自然地处理它，因为行集和列集都有大小`1`。 

另一个重要的边缘情况是行单独有效但列无效。 例如：```
[
  [1, 2],
  [1, 2]
]
```每行包含两个必需的数字，但列包含重复项。 仅验证行的实现将错误地返回`True`。 该算法通过分别验证行和列来避免此错误。 

当重复项出现在遍历的后期时，就会出现第三种重要情况。 例如，在矩阵末尾附近出现故障之前，前几行和前几列可能是正确的。 实现正确地继续验证，直到检查完每一行和每一列，除非较早的失败允许立即返回。 

另一个微妙的情况是重复值与有效范围保证相结合。 因为值保证位于`1`和`n`，仅检查设置的大小就足够了。 如果约束允许任意整数，我们还需要显式验证每个数字是否属于所需的范围。
