[LeetCode 第 2140 题](https://leetcode.com/problems/solving-questions-with-brainpower/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划

 ## 解决方案

 ## 问题理解

 问题给了我们一个名为`questions`，其中每个元素包含两个整数：

 -`questions[i][0]`代表如果我们解决问题所获得的分数`i`-`questions[i][1]`代表解决问题后必须跳过多少后续问题`i`我们必须按照从左到右的顺序处理问题。 在每个位置，我们都有两种选择：

 1. 跳过当前问题并转到下一个问题
 2. 解决当前问题，获得分数，并跳过下一个`brainpoweri`问题

 目标是最大化获得的积分总数。 

重要的细节是，解决一个问题会影响未来的选择。 一旦我们解决了问题`i`，我们不能考虑下一个`brainpoweri`根本没有问题。 这创建了一个依赖结构，其中每个决策都会影响可以到达的未来状态。 

例如，如果我们解决问题`i`其脑力值为`k`，那么下一个可用问题就变成：```
i + k + 1
```这里的约束非常重要：

 -`questions.length`可以大到`10^5`- 每个积分值和脑力值也可以大到`10^5`这些约束立即告诉我们指数解是不可能的。 由于每个问题都会引入两个选择，因此简单的递归解决方案将探索最多`2^n`的可能性，这太慢了。 

该问题结构强烈建议采用动态规划，因为：

 - 存在重叠的子问题
 - 每个决策都取决于未来的最优决策
 - 我们希望选择的价值最大化

 一些边缘情况很重要：

 - 问题可能会跳过数组末尾
 - 最佳策略可能涉及跳过高点问题以实现更好的未来组合
 - 该数组可能只包含一个问题
 - 每个脑力值都可能很大，迫使跳远
 - 最佳答案可能超过 32 位整数范围，尤其是在 Go 中

 该问题保证了有效的输入大小和正值，因此我们不需要处理格式错误的输入或负点。 

## 方法

 ### 蛮力方法

 暴力解决方案会尝试所有可能的决策组合。 

对于每个问题，我们递归地分为两种可能性：

 - 跳过这个问题
 - 解决问题

 如果我们解决了这个问题，我们会在跳过所需数量的问题后从下一个有效索引递归地继续。 

这种方法是正确的，因为它探索了每个合法的决策序列并返回其中的最大总分。 

然而，问题是状态的数量呈指数级增长。 每个问题都会引入两个可能的分支，因此递归路径总数大约可以达到`2^n`。 

和`n = 100000`，这种做法是完全不可行的。 

此外，许多子问题会重复出现。 例如，多个决策路径可能最终到达相同的问题索引，导致相同的计算一遍又一遍地重复。 

### 最优动态规划方法

 关键的观察是，未来仅取决于当前指数。 

假设我们定义：```sql
dp[i] = maximum points obtainable starting from question i
```在提问时`i`，我们又有两个选择：

 1. 跳过这个问题：```
dp[i + 1]
```2.解答问题：```
points[i] + dp[i + brainpower[i] + 1]
```最佳答案就是这两个选择中的最大值。 

这种递归使我们能够有效地计算解决方案。 

由于每个状态仅取决于未来状态，因此我们可以从右到左处理数组。 当我们计算时`dp[i]`，所有所需的未来值都是已知的。 

这将指数递归转换为线性时间动态规划解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 递归探索每个可能的决策序列 |
 | 最优动态规划| O(n) | O(n) | 使用自底向上 DP 计算每个状态一次 |

 ## 算法演练

 1.创建一个大小为DP的数组`n + 1`。 

我们使用：```sql
dp[i] = maximum points obtainable starting from index i
```额外的插槽`dp[n]`代表没有问题的基本情况。 
2. 初始化基本情况。 

当我们超越最后一个问题时，就无法再获得积分：```
dp[n] = 0
```3. 从右到左迭代问题。 

我们处理的索引来自：```
n - 1 down to 0
```我们倒退是因为每个状态都取决于未来的状态。 
4. 计算跳过当前问题的结果。 

如果我们跳过问题`i`，我们简单地转向下一个问题：```
skip = dp[i + 1]
```5. 计算解决当前问题的结果。 

如果我们解决问题`i`，我们赚取积分并向前跳跃：```
next_index = i + brainpower + 1
```总计变为：```
solve = points + dp[next_index]
```如果`next_index`超过`n`，我们只需使用`0`。 
6. 保存更好的选择。 

最优结果从`i`是：```
dp[i] = max(skip, solve)
```7. 返回`dp[0]`。 

这代表从第一个问题开始可以获得的最高分。 

### 为什么它有效

 动态规划递归之所以有效，是因为每个有效策略都从索引开始`i`必须从以下两个操作之一开始：

 - 跳过当前问题
 - 解决当前问题

 这些选择完全划分了所有可能的有效策略。 自从`dp[i]`存储每个未来索引的最优值，选择这两个选项之间的最大值保证最优性。 

向后遍历确保每当我们计算`dp[i]`，所有所需的未来状态都已正确计算。 

## Python 解决方案```python
from typing import List

class Solution:
    def mostPoints(self, questions: List[List[int]]) -> int:
        n = len(questions)

        dp = [0] * (n + 1)

        for i in range(n - 1, -1, -1):
            points, brainpower = questions[i]

            next_index = i + brainpower + 1

            solve = points
            if next_index < n:
                solve += dp[next_index]

            skip = dp[i + 1]

            dp[i] = max(solve, skip)

        return dp[0]
```实现首先创建一个 DP 数组，其中`dp[i]`存储从问题开始可获得的最大分数`i`。 

循环从右到左处理问题。 这个顺序很重要，因为每个状态都取决于未来的状态。 

对于每个问题，代码都会计算两种可能性：

 - 解决问题
 - 跳过问题

 解决问题时，我们在应用脑力跳跃后计算下一个有效索引。 如果该索引仍在范围内，我们将添加之前从该位置计算的 DP 值。 

然后，该算法会比较两个选择并存储更好的结果。 

最后，`dp[0]`包含从第一个问题开始的最佳答案。 

## 解决方案```go
func mostPoints(questions [][]int) int64 {
    n := len(questions)

    dp := make([]int64, n+1)

    for i := n - 1; i >= 0; i-- {
        points := int64(questions[i][0])
        brainpower := questions[i][1]

        nextIndex := i + brainpower + 1

        solve := points
        if nextIndex < n {
            solve += dp[nextIndex]
        }

        skip := dp[i+1]

        if solve > skip {
            dp[i] = solve
        } else {
            dp[i] = skip
        }
    }

    return dp[0]
}
```Go 实现遵循与 Python 版本完全相同的动态编程逻辑。 

主要区别在于整数处理。 由于总分可能变得非常大，我们使用`int64`用于 DP 数组和所有分数计算。 

Go 切片使用以下方式初始化`make`，并且我们使用手动计算最大值`if`声明，因为 Go 没有提供内置的`max`整数函数。

 ## 边缘情况

 当解决问题跳过数组末尾时，就会出现一种重要的边缘情况。 例如：```
[[5, 100]]
```如果我们解决唯一的问题，下一个有效索引将远远大于数组大小。 有缺陷的实现可能会尝试越界访问。 我们的解决方案通过检查是否安全地处理这个问题`next_index < n`在访问 DP 阵列之前。 

另一个重要的边缘情况是跳过高价值问题会产生更好的整体结果。 总是选择最大直接点的贪婪策略在以下情况下会失败：```
[[10,2],[100,1],[100,1]]
```解决第一个问题会阻碍获得更好的未来组合。 动态规划正确评估两种可能性并选择全局最优答案。 

第三个重要的边缘情况涉及非常大的总分。 由于积分可以达到`10^5`并且可能有`10^5`题目中，总分可能会超出32位整数范围。 Go 实现明确使用`int64`以避免溢出问题。 

当脑力值为零时，会发生另一种微妙的情况：```
[[5,0],[10,0],[15,0]]
```在这种情况下，解决问题并不强制跳过任何未来的问题。 实现正确计算：```
next_index = i + 0 + 1
```通常，这只是前进到下一个问题。
