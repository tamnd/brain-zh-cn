[LeetCode 第 2188 题](https://leetcode.com/problems/minimum-time-to-finish-the-race/)

 **难度：** 🔴难
 **主题：** 数组、动态规划

 ## 解决方案

 ## 问题理解

 该问题要求我们找到完成一场比赛的最短总时间`numLaps`使用一组轮胎进行圈数，其中每个轮胎都有两个参数：基本单圈时间`fi`和一个乘数`ri`。 轮胎完成连续几圈所需的时间根据以下公式呈几何增长`fi * ri^(x-1)`为`x`第 圈。 每圈结束后，您可以继续使用相同的轮胎（由于乘数，下一圈的速度会变慢）或更换为新轮胎，需付费`changeTime`切换秒数。 您可以选择任何轮胎来启动，并且每种轮胎类型都有无限供应。 

输入是：

 -`tires`：整数的二维列表，其中每个子列表`[fi, ri]`描述轮胎的单圈性能。 
-`changeTime`：更换轮胎所需的整数秒数。 
-`numLaps`：比赛的总圈数。 

考虑到最佳轮胎选择和切换，预期输出是一个整数，表示完成所有圈的最短时间。 

约束揭示了重要的属性：

 -`1 <= tires.length <= 10^5`表示可能有多种轮胎类型。 
-`1 <= fi, changeTime <= 10^5`和`2 <= ri <= 10^5`表明单圈时间和乘数可能很大。 
-`1 <= numLaps <= 1000`相对较小，这表明我们可以预先计算或使用 DP 来计算圈数。 

边缘情况包括极高的乘数，这使得继续使用相同的轮胎成本极高，或者非常高的更换时间，阻碍了频繁更换轮胎。 轮胎有`ri = 1`会很特别，因为继续使用同一个轮胎不会增加单圈时间。 

## 方法

 蛮力方法将尝试所有可能的轮胎选择顺序`numLaps`圈数。 对于每一圈，您可以继续使用当前轮胎或切换到任何其他轮胎。 这保证了正确的答案，但序列的数量呈指数增长`numLaps`和轮胎的数量，使其不可行。 

关键的见解是连续几圈使用轮胎的成本呈几何级数增长。 因此，我们可以预先计算每个轮胎完成任务的最短时间`k`连续跑几圈而不改变，继续时停止变得比改变更昂贵。 此后，问题简化为经典的圈数动态规划问题，其中对于每一圈，我们决定使用新轮胎执行的最佳连续圈数。 

这使我们能够处理大型`tires`通过仅关注连续圈的“最佳序列”，然后使用 DP 计算最小总时间，可以有效地排列阵列。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O((#轮胎)^numLaps) | O(圈数) | 尝试所有轮胎选择顺序； 不可行 |
 | 最佳| O(numLaps * maxConsecLaps + #tires * maxConsecLaps) | O(numLaps * maxConsecLaps + #tires * maxConsecLaps) | O(numLaps + maxConsecLaps) | O(numLaps + maxConsecLaps) | 预先计算每个轮胎的最小连续圈速并在圈数上使用 DP |

 ## 算法演练

 1. **预先计算最小连续圈速**：对于每个轮胎`[fi, ri]`，计算连续圈的累积圈速，直到下一圈超过`fi + changeTime`（因为切换更便宜）。 存储 1 圈、2 圈……的最短时间`maxConsecLaps`。 
2. **构建全局最小连续圈数表**：对于每个`k`连续圈数，找出所有轮胎连续跑完这些圈数的最短时间。 这捕获了您无需更改即可完成的最佳“部分”。 
3. **动态规划迭代**：初始化一个DP数组`dp[i]`代表完成的最短时间`i`圈数。 放`dp[0] = 0`。 每圈`i`从 1 到`numLaps`，考虑所有可能的段长度`k`（从 1 到`maxConsecLaps`），并更新`dp[i]`作为`dp[i] = min(dp[i], dp[i-k] + bestTimeForK[k] + changeTime)`如果`i != k`或者只是`bestTimeForK[k]`如果从第 1 圈开始。 
4. **返回结果**：`dp[numLaps]`给出完成所有圈的最短时间。 

**为什么有效**：通过预先计算每个轮胎连续圈数的最佳序列，我们可以避免在每一圈都探索每个轮胎。 DP 确保对于每个圈数，我们都会考虑之前所有可能的路段，从而保证总时间最少。 

## Python 解决方案```python
from typing import List
import math

class Solution:
    def minimumFinishTime(self, tires: List[List[int]], changeTime: int, numLaps: int) -> int:
        maxConsecLaps = 0
        bestTimeForK = []

        # Step 1: precompute minimal consecutive lap times for each tire
        temp_times = []
        for f, r in tires:
            laps = []
            time = f
            total = 0
            while total + time <= f + changeTime:
                total += time
                laps.append(total)
                time *= r
            temp_times.append(laps)
            maxConsecLaps = max(maxConsecLaps, len(laps))

        # Step 2: global best times for k consecutive laps
        bestTimeForK = [math.inf] * (maxConsecLaps + 1)
        for laps in temp_times:
            for k, t in enumerate(laps, 1):
                bestTimeForK[k] = min(bestTimeForK[k], t)

        # Step 3: DP over total laps
        dp = [math.inf] * (numLaps + 1)
        dp[0] = 0
        for i in range(1, numLaps + 1):
            for k in range(1, min(i, maxConsecLaps) + 1):
                if i == k:
                    dp[i] = min(dp[i], bestTimeForK[k])
                else:
                    dp[i] = min(dp[i], dp[i-k] + changeTime + bestTimeForK[k])

        return dp[numLaps]
```该实现首先计算每个轮胎的所有可行的连续圈数，直到继续比切换更糟糕。 然后，它构建了一个最佳时间的全局表`k`圈数。 最后，它使用 DP 数组来迭代构建最小总时间。 

## 解决方案```go
import (
    "math"
)

func minimumFinishTime(tires [][]int, changeTime int, numLaps int) int {
    maxConsecLaps := 0
    tempTimes := [][]int{}

    // Step 1: precompute consecutive lap times per tire
    for _, tire := range tires {
        f, r := tire[0], tire[1]
        laps := []int{}
        time := f
        total := 0
        for total + time <= f + changeTime {
            total += time
            laps = append(laps, total)
            time *= r
            if time > 1e12 { // prevent overflow
                break
            }
        }
        tempTimes = append(tempTimes, laps)
        if len(laps) > maxConsecLaps {
            maxConsecLaps = len(laps)
        }
    }

    // Step 2: global best times for k consecutive laps
    bestTimeForK := make([]int, maxConsecLaps + 1)
    for i := 1; i <= maxConsecLaps; i++ {
        bestTimeForK[i] = math.MaxInt64
    }

    for _, laps := range tempTimes {
        for k, t := range laps {
            if bestTimeForK[k+1] > t {
                bestTimeForK[k+1] = t
            }
        }
    }

    // Step 3: DP over laps
    dp := make([]int, numLaps + 1)
    for i := 1; i <= numLaps; i++ {
        dp[i] = math.MaxInt64
        for k := 1; k <= i && k <= maxConsecLaps; k++ {
            if i == k {
                if dp[i] > bestTimeForK[k] {
                    dp[i] = bestTimeForK[k]
                }
            } else {
                if dp[i] > dp[i-k] + changeTime + bestTimeForK[k] {
                    dp[i] = dp[i-k] + changeTime + bestTimeForK[k]
                }
            }
        }
    }

    return dp[numLaps]
}
```在 Go 中，在大数相乘时要小心处理潜在的整数溢出。 逻辑与 Python 版本非常相似，用切片替换了列表。
