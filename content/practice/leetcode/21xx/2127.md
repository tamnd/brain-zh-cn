[LeetCode 问题 2127](https://leetcode.com/problems/maximum-employees-to-be-invited-to-a-meeting/)

 **难度：** 🔴难
 **主题：** 数组、动态规划、深度优先搜索、图论、拓扑排序

 ## 解决方案

 ## 问题理解

 此问题描述了一群员工围坐在圆桌周围。 每个员工都有一个最喜欢的同事，由数组表示`favorite`， 在哪里`favorite[i]`是员工本人`i`想坐在旁边。 

只有当员工能够坐在圆桌旁与自己喜欢的员工直接相邻的位置时，员工才会参加会议。 由于桌子是圆形的，因此每个人恰好有两个邻居。 

目标是确定可以邀请的最大员工数量，同时仍然满足每个人的邻接要求。 

输入形成一个有向图：

 - 每个员工都是一个节点。 
- 每个员工都指向他们最喜欢的另一名员工。 

因为每个节点都有一个出边，所以该图由有向循环组成，其中树馈送到这些循环中。 

约束条件很重要：

 -`n`可以大到`100000`- 暴力搜索座位是不可能的
 - 我们需要一个接近线性时间的算法

 有两个关键的结构观察：

 1、大的有向循环可以直接形成有效的圆形座位排列。 
2. 彼此最喜欢的配对，长度周期`2`，行为不同，因为链条可以连接到该对的两侧。 

了解这两种情况是解决问题的核心。 

几种边缘情况很容易破坏简单的实现：

 - 包含一个大循环的图表
 - 多个断开循环
 - 具有长传入链的两节点循环
 - 深链进入循环
 - 员工不属于最优配置

 该问题保证：

 - 没有员工最喜欢自己
 - 每个节点都只有一个出边
 - 该图始终由循环和传入树组成

 ## 方法

 ### 蛮力方法

 强力解决方案将尝试生成员工子集并测试所有可能的圆形座位。 

对于每个子集：

 1. 生成所有排列
 2. 将员工安排在桌子周围
 3. 检查每个员工是否坐在他们最喜欢的旁边

 这是有效的，因为它明确地验证了每一个可能的有效安排。 

然而，其复杂性是灾难性的。 为了`n = 100000`，连枚举子集都是不可能的，更不用说排列了。 

该问题需要利用图结构而不是直接搜索座位安排。 

### 关键见解

 由于每个员工都指向一个最喜欢的点，因此该图是一个函数图。 

函数图由以下部分组成：

 - 定向循环
 - 树木融入这些循环

 只有两种配置可以得出最佳答案：

 1.单周期长度大于`2`2.多对相互喜爱的配对，长度循环`2`，每个都用最长的传入链扩展

 为什么周期有长度`2`特别的？ 

假设员工`a`和`b`互相喜欢：```
a <-> b
```它们可以坐在一起，并且额外的链条可以连接到任一侧：```
chain -> a <-> b <- chain
```这对于较大的自行车来说是不可能的，因为与自行车成员相邻的每个座位都已经被占用。 

因此：

 - 对于长度周期`>= 3`，只有周期本身才算数
 - 对于长度周期`2`，我们可以将最长的传入链添加到每个节点中

 最终的答案是：```
max(
    largest_cycle_length,
    sum_of_all_extended_two_cycles
)
```## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n) | 显式尝试所有座位 |
 | 最佳| O(n) | O(n) | 使用图结构和拓扑剪枝 |

 ## 算法演练

 ### 第 1 步：构建入度数组

 对于每一位员工`i`:```
favorite[i] -> target
```增加 的入度`target`。 

入度告诉我们有多少个员工指向每个人。 

我们需要这个来进行拓扑修剪。 

### 步骤 2：计算最长的传入链

 我们使用卡恩算法执行拓扑排序。 

有学位的员工`0`不能属于循环，因此它们必须是通向循环的链的一部分。 

我们逐层处理这些节点。 

对于每位员工：```
next_employee = favorite[current]
```我们更新：```
longest_chain[next_employee] =
    max(longest_chain[next_employee],
        longest_chain[current] + 1)
```这计算进入每个节点的最大链长度。 

### 步骤3：删除非循环节点

 处理节点时：

 - 减少入度
 - 将新的零入度节点推入队列

 最后：

 - 有入度的节点`> 0`属于循环
 - 有入度的节点`0`被修剪掉

 这完全隔离了所有周期。 

### 步骤 4：遍历循环

 现在迭代所有剩余的循环节点。 

对于每个未访问的周期：

 1. 遍历循环
 2. 数一下它的大小

 有两种情况。 

#### 情况 A：周期长度为 2

 假设：```
a <-> b
```那么贡献就是：```
longest_chain[a] + longest_chain[b]
```因为双方都可以接受传入的链。 

将此贡献添加到总的两个周期答案中。 

#### 情况 B：周期长度 >= 3

 只有循环本身可以参与。 

更新：```
largest_cycle = max(largest_cycle, cycle_length)
```###第五步：返回最终答案

 最佳安排是：

 - 一大周期
 - 所有扩展两个周期的总和

 返回：```
max(largest_cycle, two_cycle_total)
```### 为什么它有效

 每个节点要么属于一个循环，要么属于通向循环的树。 

长度周期`>= 3`已经消耗了所有邻接位置，因此无法附加额外的链。 

长度周期`2`为每个员工留下一个空闲的一侧，允许添加每侧最长的传入链。 

该算法正确地分离了这两个结构并计算每个结构的最佳可能贡献。 

由于每个节点在剪枝期间和循环检测期间只处理一次，因此结果既正确又高效。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def maximumInvitations(self, favorite: List[int]) -> int:
        n = len(favorite)

        indegree = [0] * n

        for person in favorite:
            indegree[person] += 1

        longest_chain = [1] * n

        queue = deque()

        for i in range(n):
            if indegree[i] == 0:
                queue.append(i)

        while queue:
            current = queue.popleft()

            next_person = favorite[current]

            longest_chain[next_person] = max(
                longest_chain[next_person],
                longest_chain[current] + 1
            )

            indegree[next_person] -= 1

            if indegree[next_person] == 0:
                queue.append(next_person)

        visited = [False] * n

        largest_cycle = 0
        two_cycle_total = 0

        for i in range(n):
            if indegree[i] > 0 and not visited[i]:
                cycle_length = 0
                current = i

                while not visited[current]:
                    visited[current] = True
                    current = favorite[current]
                    cycle_length += 1

                if cycle_length == 2:
                    a = i
                    b = favorite[i]

                    two_cycle_total += (
                        longest_chain[a] + longest_chain[b]
                    )
                else:
                    largest_cycle = max(
                        largest_cycle,
                        cycle_length
                    )

        return max(largest_cycle, two_cycle_total)
```实现首先计算所有员工的入度。 由于每位员工都指出了自己最喜欢的一项，因此这很简单。 

这`longest_chain`数组存储以每个节点结束的最大链长度。 每个节点最初贡献长度`1`，代表自己。 

卡恩算法删除所有非循环节点。 在删除节点时，算法会在图中向前传播链长度。 

剪枝完成后，只有循环节点保留正入度。 

第二阶段遍历剩余的周期。 该算法区分：

 - 两节点循环
 - 更大的周期

 对于双节点循环，添加进入两个节点的最长链。 对于较大的周期，只有周期长度本身起作用。 

最后，该算法返回以下值中的较大者：

 - 最大周期
 - 所有扩展两个周期的总贡献

 ## 解决方案```go
package main

func maximumInvitations(favorite []int) int {
	n := len(favorite)

	indegree := make([]int, n)

	for _, person := range favorite {
		indegree[person]++
	}

	longestChain := make([]int, n)

	for i := 0; i < n; i++ {
		longestChain[i] = 1
	}

	queue := make([]int, 0)

	for i := 0; i < n; i++ {
		if indegree[i] == 0 {
			queue = append(queue, i)
		}
	}

	head := 0

	for head < len(queue) {
		current := queue[head]
		head++

		nextPerson := favorite[current]

		if longestChain[current]+1 > longestChain[nextPerson] {
			longestChain[nextPerson] =
				longestChain[current] + 1
		}

		indegree[nextPerson]--

		if indegree[nextPerson] == 0 {
			queue = append(queue, nextPerson)
		}
	}

	visited := make([]bool, n)

	largestCycle := 0
	twoCycleTotal := 0

	for i := 0; i < n; i++ {
		if indegree[i] > 0 && !visited[i] {

			cycleLength := 0
			current := i

			for !visited[current] {
				visited[current] = true
				current = favorite[current]
				cycleLength++
			}

			if cycleLength == 2 {
				a := i
				b := favorite[i]

				twoCycleTotal +=
					longestChain[a] + longestChain[b]
			} else {
				if cycleLength > largestCycle {
					largestCycle = cycleLength
				}
			}
		}
	}

	if largestCycle > twoCycleTotal {
		return largestCycle
	}

	return twoCycleTotal
}
```Go 实现遵循与 Python 版本相同的逻辑。 

该队列不是使用双端队列，而是使用具有移动头索引的切片来实现。 这避免了昂贵的前部拆除。 

Go 切片的大小是动态调整的，使其适合队列模拟。 

不存在整数溢出问题，因为最大答案最多是`100000`。

 ## 边缘情况

 ### 具有多个传入链的两节点循环

 一个常见的错误是在两个周期中错误地将多个链附加到同一节点。 

考虑：```
favorite = [1,0,0,0]
```雇员`2`和`3`两者都指向员工`0`。 

只能挂一根链子，因为员工`0`在相互对之外只有一个空闲的相邻座位。 

该实现正确地仅保留最长的传入链，使用：```
max(existing, new_chain)
```### 大循环不能接受额外的链

 另一个常见的错误是试图将链条连接到比`2`。 

例如：```
0 -> 1 -> 2 -> 0
3 -> 1
```员工`3`无法添加，因为每个循环成员已经使用了循环内的两个相邻座位。 

该实现通过仅计算大小周期的周期长度来处理此问题`>= 3`。 

### 多个断开连接的组件

 该图可能包含几个独立的组件。 

例子：```
[1,0,3,2]
```这包含两个独立的双周期。 

有缺陷的实现可能只处理一个连接的组件。 

该解决方案迭代所有节点并独立处理每个剩余周期，确保包含所有有效贡献。
