[LeetCode 第 2178 题](https://leetcode.com/problems/maximum-split-of-positive-even-integers/)

 **难度：** 🟡 中等
 **主题：** 数学、回溯、贪心

 ## 解决方案

 ## 问题理解

 问题是要求我们输入一个整数`finalSum`并将其拆分为最大数量的唯一正偶数，使得它们的总和等于`finalSum`。 A **unique positive even integer** means each number in the split must be even, greater than zero, and cannot be repeated. 如果不存在有效的分割（例如，当`finalSum`是奇数），我们返回一个空列表。 

输入`finalSum`范围从`1`到`10^10`，这意味着任何解决方案都必须高效，并且不能依赖于对所有子集的强力探索。 输出是一个整数列表，表示最大化整数数量的分割。 边缘情况包括：`finalSum`是奇数（没有有效的分割），当`finalSum`非常小（比如`2`），或者当`finalSum`刚好大到足以包含许多小偶数。 

## 方法

 暴力方法将尝试生成正偶数的所有组合并检查哪些总和相等`finalSum`，然后返回长度最大的组合。 这在理论上是可行的，但对于大量数字来说在计算上是不可行的，因为组合的数量呈指数增长。 

最佳解决方案的关键观察是，为了最大化整数的数量，我们应该从最小的可能正偶数开始（`2`）并继续添加下一个偶数（`4`,`6`,`8`, ...) 直到运行总和超过或匹配`finalSum`。 如果运行总和超过`finalSum`，我们可以调整分割中的最后一个数字来补偿差异，确保总和等于`finalSum`同时保持所有数字的唯一性。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 指数 O(2^(finalSum/2)) | O(n) | 生成偶数的所有可能组合并检查和 |
 | 最佳| O(sqrt(最终和)) | O(sqrt(最终和)) | 使用从 2 开始的连续偶数的贪婪方法 |

 ## 算法演练

 1. 检查是否`finalSum`很奇怪。 如果是，则立即返回一个空列表，因为偶数之和不能产生奇数总数。 
2.初始化一个空列表`split`将数字存储在拆分中。 
3. 从最小的正偶数开始`2`和一个变量`current`握住它。 
4. 虽然`finalSum`大于或等于`current`, 附加`current`到`split`并从中减去它`finalSum`。 然后递增`current`经过`2`得到下一个偶数。 
5.循环结束后，是否还有剩余`finalSum > 0`，它表示达到原始目标总和所需的差值。 将这个剩余数添加到最后一个数字中`split`调整总和，同时保持所有数字唯一。 
6. 返回列表`split`。 

**为什么有效：** 贪心方法之所以有效，是因为从最小的偶数开始可以最大化分割中的整数数量。 将剩余数添加到最后一个数字可以保持唯一性，同时确保总和等于`finalSum`。 

## Python 解决方案```python
from typing import List

class Solution:
    def maximumEvenSplit(self, finalSum: int) -> List[int]:
        if finalSum % 2 != 0:
            return []
        
        split = []
        current = 2
        
        while finalSum >= current:
            split.append(current)
            finalSum -= current
            current += 2
        
        if finalSum > 0:
            split[-1] += finalSum
        
        return split
```代码首先检查是否`finalSum`是奇数，如果是则返回一个空列表。 然后，它使用贪心循环将连续的偶数添加到`split`列表。 如果还有剩余，则将其添加到最后一个元素以维持总和。 该解决方案可有效处理所有有效的边缘情况。 

## 解决方案```go
func maximumEvenSplit(finalSum int64) []int64 {
    if finalSum%2 != 0 {
        return []int64{}
    }

    split := []int64{}
    current := int64(2)

    for finalSum >= current {
        split = append(split, current)
        finalSum -= current
        current += 2
    }

    if finalSum > 0 {
        split[len(split)-1] += finalSum
    }

    return split
}
```在 Go 中，算法遵循相同的贪心策略。 我们处理`int64`对于大笔款项。 切片`split`当我们附加偶数时动态增长。 任何剩余的`finalSum`添加到最后一个元素以达到精确的目标总和。 

## 工作示例

 **示例1：**`finalSum = 12`迭代步骤：

 | 当前| 分裂| 剩余最终金额 |
 | ---| ---| ---|
 | 2 | [2] | 10 | 10
 | 4 | [2,4]| 6 |
 | 6 | [2,4,6]| 0 |

 没有剩余，返回`[2,4,6]`。 

**示例2：**`finalSum = 7`由于 7 是奇数，因此返回`[]`。 

**示例3：**`finalSum = 28`迭代步骤：

 | 当前| 分裂| 剩余最终金额 |
 | ---| ---| ---|
 | 2 | [2] | 26 | 26
 | 4 | [2,4]| 22 | 22
 | 6 | [2,4,6]| 16 | 16
 | 8 | [2,4,6,8] | 8 |

 剩下的是`8`，添加到最后一个元素：`[2,4,6,16]`。 

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(sqrt(最终和)) | 我们迭代连续偶数直到大约 sqrt(finalSum) 以获得求和公式 n(n+1) ≤ FinalSum |
 | 空间| O(sqrt(最终和)) | 拆分列表存储每个选定的偶数整数，这也是 O(sqrt(finalSum)) |

 推理来自以下事实：第一个的总和`n`偶数大致是二次的，因此迭代次数与 的平方根成正比`finalSum`。

 ## 边缘情况

 一个重要的边缘情况是当`finalSum`是**奇怪**。 正偶数之和不能等于奇数。 该实现立即返回一个空列表。 

另一个边缘情况是当`finalSum`恰好是**一个小偶数**，就像`2`。 贪心循环只运行一次，正确返回`[2]`。 

第三种边缘情况是当`finalSum`**大**，连续数字相加后的剩余部分必须追加到最后一个元素。 该算法通过调整最后一个数字来正确处理这个问题，确保总和的唯一性和正确性。
