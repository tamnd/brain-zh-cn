[LeetCode 第 2190 题](https://leetcode.com/problems/most-frequent-number-following-key-in-an-array/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表、计数

 ## 解决方案

 ## 问题理解

 该问题要求我们找到紧随给定值之后出现**最频繁的整数`key`数组中的值**。 

更具体地说，我们得到一个整数数组`nums`和一个整数`key`，保证存在于数组中。 我们需要检查每一次出现的情况`key`在`nums`。 每当我们发现`key`在索引处`i`，我们看下一个元素，`nums[i + 1]`，因为该问题将“目标”定义为直接跟随的数字`key`。 

对于后面的每个不同的数字`key`，我们计算它在这个位置出现的次数。 最后，我们返回计数最高的数字。 该问题保证了答案是唯一的，这意味着最常见的目标永远不会有联系。 

例如，考虑：```
nums = [1,100,200,1,100]
key = 1
```数量`1`出现在索引处`0`和`3`。 查看每次出现后立即出现的元素：

 -`nums[1] = 100`-`nums[4] = 100`数量`100`之后出现两次`1`，使其成为最常见的目标。 

限制相对较小：

 -`2 <= nums.length <= 1000`-`1 <= nums[i] <= 1000`由于最大数组大小仅为`1000`，即使是二次解在技术上也是可行的。 然而，这个问题自然适合线性扫描，使我们能够有效地获得最优解。 

一个重要的细节是我们只检查索引`nums.length - 2`，因为我们必须始终检查`nums[i + 1]`。 如果`key`出现在最后一个索引处，没有后续数字可供计数。 该问题保证了答案是唯一的，因此我们不需要实现平局打破逻辑。 

重要的边缘情况包括重复出现`key`、连续的键以及同一目标多次出现的数组`key`。 例如，在`[2,2,2,2,3]`和`key = 2`, 目标`2`重复跟随自身，这可能会暴露幼稚实现中的索引错误。 

## 方法

 ### 蛮力方法

 一种简单的暴力方法是首先识别每个唯一的数字`nums`，然后，对于每个可能的目标，扫描整个数组以计算它紧随其后的次数`key`。 

对于每个不同的值`target`，我们将迭代数组并计算索引`i`在哪里：```
nums[i] == key
nums[i + 1] == target
```在计算所有可能目标的计数后，我们返回频率最高的目标。 

这种方法是正确的，因为它明确地评估每个有效目标并根据问题定义准确地计算出现次数。 然而，它的效率很低，因为我们重复扫描数组中的每个候选目标。 

如果有`n`元素和最多`n`独特的目标，这会导致最坏情况的时间复杂度`O(n²)`。 

### 最佳方法，带有哈希图的单遍

 关键的观察是我们不需要单独评估每个目标。 

相反，我们可以一次性处理该数组。 每次我们遇到`key`，我们立即查看下一个元素并增加其在哈希图中的频率计数。 

在更新频率的同时，我们还可以跟踪迄今为止看到的最频繁的目标。 这避免了需要第二次通过频率图。 

哈希映射是理想的，因为它平均允许恒定时间的更新和查找。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 重复扫描数组中的每个目标 |
 | 最佳| O(n) | O(n) | 使用哈希图进行计数的单遍 |

 ## 算法演练

 1. 创建一个空的哈希映射，名为`frequency_count`。 

该地图存储每个目标数字紧随其后出现的次数`key`。 
2.初始化两个变量：

 -`most_frequent_target`存储当前的最佳答案
 -`highest_frequency`存储迄今为止看到的最大计数

 这些有助于我们避免在计数结束后再次扫描地图。 
3. 从索引处迭代数组`0`到`len(nums) - 2`。 

我们停在`len(nums) - 2`因为我们总是需要安全地访问`nums[i + 1]`。 
4. 在每个索引处，检查是否`nums[i] == key`。 

如果当前值不等于`key`， 继续前行。 
5. 什么时候`nums[i] == key`，检查下一个值：```
target = nums[i + 1]
```该值是一个有效的目标，因为它紧随其后`key`。 
6. 更新哈希图中目标的频率。 

将其计数加一。 
7. 将更新后的计数与`highest_frequency`。 

如果新的频率更大，则更新：

 -`highest_frequency`-`most_frequent_target`8.循环完成后，返回`most_frequent_target`。 

### 为什么它有效

 该算法之所以有效，是因为每个有效的目标出现都会被精确计数一次。 每当`key`出现在索引处`i`，算法立即记录`nums[i + 1]`，这正是问题要求我们衡量的。 

哈希图为遇到的每个目标维护准确的频率计数。 由于我们不断跟踪频率最高的目标，因此最终存储的答案必须是问题所保证的唯一最频繁的目标。 

## Python 解决方案```python
from typing import List

class Solution:
    def mostFrequent(self, nums: List[int], key: int) -> int:
        frequency_count = {}

        most_frequent_target = -1
        highest_frequency = 0

        for index in range(len(nums) - 1):
            if nums[index] == key:
                target = nums[index + 1]
                frequency_count[target] = (
                    frequency_count.get(target, 0) + 1
                )

                if frequency_count[target] > highest_frequency:
                    highest_frequency = frequency_count[target]
                    most_frequent_target = target

        return most_frequent_target
```该实现遵循前面描述的确切算法。 

我们首先创建一个字典，名为`frequency_count`存储每个目标出现的次数`key`。 Python字典提供平均值`O(1)`插入和查找时间，使它们成为频率计数的理想选择。 

然后我们初始化`most_frequent_target`和`highest_frequency`。 这些变量使我们能够在处理数组时动态地维护最佳答案。 

循环仅迭代至`len(nums) - 1`，确保`nums[index + 1]`始终有效。 每当当前元素等于`key`，我们检索以下数字并增加其频率计数。 

更新计数后，我们将其与当前最大频率进行比较。 如果这个目标现在有更大的计数，它就成为新的答案。 

最后，我们在完成扫描后返回存储的结果。 

## 解决方案```go
func mostFrequent(nums []int, key int) int {
	frequencyCount := make(map[int]int)

	mostFrequentTarget := -1
	highestFrequency := 0

	for i := 0; i < len(nums)-1; i++ {
		if nums[i] == key {
			target := nums[i+1]
			frequencyCount[target]++

			if frequencyCount[target] > highestFrequency {
				highestFrequency = frequencyCount[target]
				mostFrequentTarget = target
			}
		}
	}

	return mostFrequentTarget
}
```Go 实现遵循与 Python 版本相同的逻辑。 我们不使用字典，而是使用`map[int]int`来计算频率。 

Go 映射会自动返回缺失键的零值，因此递增：```go
frequencyCount[target]++
```即使当`target`以前没见过。 

不存在整数溢出问题，因为最大计数受以下限制`nums.length`，这最多是`1000`。 由于 Go 中的切片会动态跟踪长度，因此我们只能安全地迭代直到`len(nums) - 1`以避免越界访问。

 ## 边缘情况

 ### 连续出现`key`一个棘手的情况发生时`key`连续出现多次，例如：```
nums = [2,2,2,2,3]
```这里，`2`反复跟随自己。 有缺陷的实现可能会意外地跳过重叠的匹配或错误地移动索引。 我们的实现独立检查每个索引，因此每个有效的出现都会被正确计数。 

###`key`只出现一次

 如果`key`只发生一次，例如：```
nums = [10,20,30,40,50]
key = 30
```可能的目标只有一个，`40`。 该算法仍然有效，因为第一个有效目标立即成为最常见的结果。 

###`key`靠近数组末尾

 一个重要的边界条件是检查时避免越界访问`nums[i + 1]`。 由于该算法仅迭代至`len(nums) - 2`，它从不尝试访问无效索引。 这保证了安全，即使`key`出现在数组末尾附近。 

### 目标等于`key`有时后面的数字`key`是一样的`key`本身：```
nums = [7,7,7,8]
key = 7
```该算法自然地处理这个问题，因为它只是计算出现在的任何值`nums[i + 1]`，无论是否匹配`key`。 这避免了特殊情况逻辑并保持实现简单和正确。
