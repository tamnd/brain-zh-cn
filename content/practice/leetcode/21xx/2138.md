 # LeetCode 2138 - 将字符串分成大小为 k 的组

 ## 问题理解

 该问题要求我们将一个字符串分成连续的组，其中每个组必须恰好包含`k`人物。 

我们从左到右处理字符串。 第一个`k`第一组的字符，下一组的字符`k`字符组成第二组，依此类推。 原始字符串中的每个字符都必须恰好属于一个组。 

唯一的麻烦发生在最后一组。 如果剩余字符数小于`k`，我们必须附加字符`fill`足够的时间使最后一组达到规模`k`。 

输入包括：

 -`s`, 原始字符串
 -`k`，每组所需的大小
 -`fill`，如有必要，用于填充最后一组的单个字符

 输出是一个字符串数组，其中每个字符串的长度完全相同`k`。 

例如，如果：```
s = "abcdefghij"
k = 3
fill = "x"
```我们像这样分割字符串：```
abc | def | ghi | j
```最后一段只包含一个字符，所以我们附加两个`'x'`人物：```
jxx
```最终答案变成：```
["abc", "def", "ghi", "jxx"]
```限制非常小：

 -`s.length <= 100`-`k <= 100`这告诉我们性能并不是主要问题。 即使是简单的模拟也很容易满足限制。 然而，我们仍然希望有一个干净、高效的实施。 

有几个重要的边缘情况需要记住：

 - 字符串长度可能已被整除`k`，意味着不需要填充。 
- 该字符串可能包含少于`k`字符总数。 
-`k`可能等于`1`，这意味着每个角色都成为自己的群体。 
- 最后一组可能需要多个填充字符。 

正确的解决方案必须一致地处理所有这些情况。 

## 方法

 ### 蛮力方法

 强力解决方案可以逐个字符地重复构建每个组。 

我们可以使用索引迭代字符串，手动追加到`k`字符放入临时字符串中，如果我们在达到大小之前用完字符`k`，继续追加`fill`直到该组达到所需的大小。 

这种方法是正确的，因为它完全按照问题陈述中的描述明确地模拟了分组过程。 

然而，实现变得不必要地冗长。 我们最终手动管理许多条件：

 - 跟踪当前组大小
 - 检查是否到达字符串末尾
 - 单独附加填充字符

 尽管限制很小，但该方法过于复杂。 

### 最佳方法

 关键的观察是字符串已经可以直接切成大小块`k`。 

我们可以按大小的步长迭代字符串，而不是逐个字符地构建组`k`:

 - 从索引中提取子字符串`i`到`i + k`- 如果子串长度小于`k`,追加足够的`fill`人物
 - 将已完成的组添加到答案列表中

 这种方法更加简单、清晰，并且自然地匹配问题的结构。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 逐个字符手动构建每个组 |
 | 最佳| O(n) | O(n) | 使用子字符串切片和简单的填充逻辑 |

 ## 算法演练

 ### 最优算法

 1. 初始化一个空结果列表，用于存储所有组。 
2. 使用步长大小迭代字符串`k`。 

这确保每次迭代只处理一组。 
3. 对于每个起始索引`i`，提取子字符串：```
s[i:i+k]
```This gives the current group candidate.
 4. 检查提取的子串长度是否小于`k`。 

仅当字符串长度不能被整除时，才会在最后一组发生这种情况`k`。 
5. 如果该组太短，计算缺少多少个字符：```
k - len(group)
```6. 附加`fill`性格，很多次。 
7. 将完成的组添加到结果列表中。 
8. 处理完所有组后，返回结果列表。 

### 为什么它有效

 该算法以不重叠的大小块处理字符串`k`。 每个字符都属于一个块，因为循环前进`k`每次迭代。 如果最终块不完整，则填充可确保其大小准确无误`k`。 因此，产生的组满足问题陈述中的所有条件。 

## Python 解决方案```python
from typing import List

class Solution:
    def divideString(self, s: str, k: int, fill: str) -> List[str]:
        groups = []

        for i in range(0, len(s), k):
            group = s[i:i + k]

            if len(group) < k:
                group += fill * (k - len(group))

            groups.append(group)

        return groups
```实现首先创建一个名为的空列表`groups`，存储最终答案。 

该循环使用以下方式迭代字符串：```python
range(0, len(s), k)
```步长大小`k`保证每次迭代都从新组的开头开始。 

表达式：```python
s[i:i + k]
```提取最多`k`从当前位置开始的字符。 

如果提取的子串短于`k`，代码附加了足够的副本`fill`来完成小组。 

最后，将每个完成的组添加到结果列表中，并在处理完所有组后返回列表。 

## 解决方案```go
func divideString(s string, k int, fill byte) []string {
    result := []string{}

    for i := 0; i < len(s); i += k {
        end := i + k

        if end > len(s) {
            end = len(s)
        }

        group := s[i:end]

        for len(group) < k {
            group += string(fill)
        }

        result = append(result, group)
    }

    return result
}
```Go 实现遵循与 Python 解决方案相同的逻辑，但存在一些特定于语言的差异。 

Go 不支持超出数组边界的 Python 风格切片，因此我们使用以下方法显式限制结束索引：```go
if end > len(s) {
    end = len(s)
}
```这`fill`参数是一个`byte`，所以我们在连接之前将其转换为字符串：```go
string(fill)
```结果存储在字符串切片中，该字符串切片随着组的添加而动态增长。

 ## 边缘情况

 ### 字符串长度已被 k 整除

 错误的一个常见来源是意外添加填充，即使最终组已经完全包含`k`人物。 

例如：```
s = "abcdef"
k = 3
```这些组应该简单地是：```
["abc", "def"]
```该实现正确地避免了填充，因为它仅在以下情况下附加填充字符：```
len(group) < k
```### 字符串短于 k

 当整个字符串小于所需的组大小时，会出现另一个重要的边缘情况。 

例如：```
s = "a"
k = 4
fill = "x"
```正确的结果是：```
["axxx"]
```该实现自然地处理了这个问题，因为循环仍然提取一个子字符串，然后填充它直到其长度达到`k`。 

### k 等于 1

 当`k = 1`，每个角色都形成自己的群体。 

例如：```
s = "abc"
k = 1
```输出变为：```
["a", "b", "c"]
```这种情况可能会暴露实现中的错误，错误地假设组包含多个字符。 循环中的步长变为`1`，因此每个字符都被单独处理，这可以正常工作。 

### 需要多个填充字符

 最后一组可能需要多个填充字符。 

例如：```
s = "abcde"
k = 4
fill = "z"
```最后一组开始为：```
"e"
```并且必须成为：```
"ezzz"
```该实现使用以下方法计算丢失字符的确切数量：```
k - len(group)
```这保证了添加正确数量的填充。
