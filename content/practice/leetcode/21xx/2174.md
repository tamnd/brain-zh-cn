[LeetCode 问题 2174](https://leetcode.com/problems/remove-all-ones-with-row-and-column-flips-ii/)

 **难度：** 🟡 中等
 **主题：** 数组、位操作、广度优先搜索、矩阵

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个`m x n`二元矩阵，其中每个单元格包含`0`或者`1`。 我们的目标是消除所有`1`使用最少的操作数。 

一个操作只能对一个cell进行`(i, j)`目前包含一个`1`。 一旦我们选择了这样一个单元格，我们立即设置行中的每个单元格`i`以及列中的每个单元格`j`到`0`。 

这很重要，因为该操作同时影响整行和整列。 所选单元格充当操作的“锚点”，但效果会在两个维度上传播。 

输出应该是使整个矩阵变为全零所需的最少运算次数。 

约束条件是有效解决该问题的关键：

 -`1 <= m, n <= 15`-`1 <= m * n <= 15`尽管矩阵维度可以单独大到`15`，细胞总数最多为`15`。 这是一个非常强烈的暗示，我们应该考虑将整个矩阵表示为位掩码。 

由于最多有`15`单元格中，可能的矩阵状态总数最多为：```
2^15 = 32768
```对于使用 BFS 或记忆 DFS 进行详尽的状态探索来说，这个值足够小。 

一些边缘情况很重要：

 - 矩阵可能已经包含全零，在这种情况下答案是`0`。 
- 一个矩阵只能包含一个`1`，这仅需要一次操作。 
- 不同的操作顺序可能会产生不同的步数，因此贪心策略是不可靠的。 
- 执行一项操作可以删除许多`1`一次，特别是在密集矩阵中。 
- 由于只允许对当前等于的单元格进行操作`1`，我们不能任意选择任何行和列的组合。 

这些观察自然地引导我们进行状态空间搜索。 

## 方法

 ### 蛮力方法

 朴素的暴力策略会从当前矩阵状态递归地尝试每一个可能的有效操作。 

每一步：

 1. 扫描矩阵中包含的所有单元格`1`。 
2. 对于每个这样的单元，模拟操作。 
3. 对结果矩阵进行递归。 
4. 跟踪所有可能性中的最少操作数。 

这种方法是正确的，因为它探索了所有可能的操作序列。 最终，它会发现最佳序列。 

然而，问题是许多矩阵状态通过不同的操作顺序重复。 在不记住先前计算的状态的情况下，递归树呈指数增长并执行大量冗余工作。 

尽管州总数仅为`2^15`，朴素递归可能会多次重新访问相同的状态。 

### 关键见解

 关键的观察是整个矩阵可以表示为位掩码，因为最多有`15`细胞。 

每个独特的矩阵配置都成为图中的一个节点：

 - 一个节点代表一个矩阵状态。 
- 边沿表示执行一项有效操作。 

由于每个操作具有相同的成本，因此可以使用广度优先搜索找到从初始状态到全零状态的最短路径。 

BFS 在这里是理想的选择，因为：

 - 每次操作的成本准确`1`。 
- BFS 保证我们第一次达到全零状态时需要最少的操作次数。 
- 状态总数足够小，可以进行详尽的探索。 

我们还通过存储访问过的状态来避免重复工作。

 ## 算法演练

 ### 步骤 1：将矩阵编码为位掩码

 我们将矩阵展平为单个整数。 

对于每个单元格：

 - 如果`grid[i][j] == 1`，我们设置掩码中相应的位。 
- 如果是的话`0`，该位保持未设置状态。 

例如：```
grid = [
  [1,0],
  [1,1]
]
```可以变成：```
bit positions:
0 1
2 3

mask = 1101₂
```使用位掩码可以使状态转换变得极​​其高效。 

### 步骤2：初始化BFS

 我们从初始掩码开始 BFS。 

我们维持：

 - 队列存储`(state, steps)`- 已访问的集合以避免再次访问状态

 目标状态很简单：```
0
```因为所有位被清除意味着所有矩阵单元都为零。 

### 步骤 3：处理每个 BFS 状态

 对于当前掩码：

 1.如果口罩是`0`，返回当前步数。 
2. 否则，检查矩阵中的每个单元格。 

对于每个单元格`(i, j)`：

 - 检查其位是否已设置。 
- 如果没有设置，我们无法在那里执行操作。 
- 如果设置，则模拟操作。 

### 步骤 4：模拟操作

 选择时`(i, j)`：

 - 行中的每一位`i`变成`0`- 列中的每一位`j`变成`0`我们通过清除这些位来创建一个新的掩码。 

这是通过位运算有效完成的。 

### 步骤 5：将新状态推入 BFS

 如果生成的掩码尚未被访问过：

 - 标记已访问
 - 将其推入队列`steps + 1`因为 BFS 是逐级探索状态的，所以我们第一次到达状态时`0`保证是最优的。 

### 为什么它有效

 BFS 探索所有可达的状态`k`在探索需要的状态之前进行操作`k + 1`运营。 状态图中的每条边都具有相同的权重，因为每个操作只花费一步。 因此，BFS 第一次达到全零状态时，必须使用尽可能少的操作数。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def removeOnes(self, grid: List[List[int]]) -> int:
        m = len(grid)
        n = len(grid[0])

        initial_mask = 0

        for i in range(m):
            for j in range(n):
                if grid[i][j] == 1:
                    bit = i * n + j
                    initial_mask |= (1 << bit)

        queue = deque([(initial_mask, 0)])
        visited = {initial_mask}

        while queue:
            mask, steps = queue.popleft()

            if mask == 0:
                return steps

            for i in range(m):
                for j in range(n):
                    bit = i * n + j

                    if not (mask & (1 << bit)):
                        continue

                    next_mask = mask

                    # Clear entire row i
                    for col in range(n):
                        row_bit = i * n + col
                        next_mask &= ~(1 << row_bit)

                    # Clear entire column j
                    for row in range(m):
                        col_bit = row * n + j
                        next_mask &= ~(1 << col_bit)

                    if next_mask not in visited:
                        visited.add(next_mask)
                        queue.append((next_mask, steps + 1))

        return -1
```实现首先将矩阵转换为紧凑的整数位掩码。 每个矩阵单元映射到一位位置。 这允许整个矩阵状态适合单个整数，因为最多有十五个单元。 

BFS 队列存储成对的`(mask, steps)`， 在哪里`mask`代表当前的矩阵配置和`steps`代表使用了多少次操作来达到它。 

对于每个状态，算法都会检查每个单元格。 如果设置了相应的位，则意味着该单元当前包含一个`1`，因此它是一个有效的操作目标。 

为了模拟该操作，代码会清除所选行和列中的所有位。 位清除是使用以下命令执行的：```python
next_mask &= ~(1 << position)
```这有效地将细胞从矩阵状态中移除。 

访问集确保每个状态最多被处理一次。 由于 BFS 按递增的操作顺序处理状态，因此我们第一次遇到全零状态时保证是最优的。 

## 解决方案```go
package main

import "container/list"

func removeOnes(grid [][]int) int {
	m := len(grid)
	n := len(grid[0])

	initialMask := 0

	for i := 0; i < m; i++ {
		for j := 0; j < n; j++ {
			if grid[i][j] == 1 {
				bit := i*n + j
				initialMask |= (1 << bit)
			}
		}
	}

	type State struct {
		mask  int
		steps int
	}

	queue := list.New()
	queue.PushBack(State{initialMask, 0})

	visited := map[int]bool{
		initialMask: true,
	}

	for queue.Len() > 0 {
		front := queue.Front()
		queue.Remove(front)

		current := front.Value.(State)
		mask := current.mask
		steps := current.steps

		if mask == 0 {
			return steps
		}

		for i := 0; i < m; i++ {
			for j := 0; j < n; j++ {
				bit := i*n + j

				if (mask & (1 << bit)) == 0 {
					continue
				}

				nextMask := mask

				// Clear row i
				for col := 0; col < n; col++ {
					rowBit := i*n + col
					nextMask &= ^(1 << rowBit)
				}

				// Clear column j
				for row := 0; row < m; row++ {
					colBit := row*n + j
					nextMask &= ^(1 << colBit)
				}

				if !visited[nextMask] {
					visited[nextMask] = true
					queue.PushBack(State{nextMask, steps + 1})
				}
			}
		}
	}

	return -1
}
```Go 实现遵循与 Python 版本完全相同的 BFS 策略。 

一个显着的区别是位清除语法。 在 Go 中，表达式：```go
nextMask &= ^(1 << position)
```用来代替Python的`~`。 

BFS队列的实现使用`container/list`，因为Go不提供内置的双端队列结构。 所访问的结构使用`map[int]bool`。 

因为最大状态数只有`32768`，常规整数类型完全足够，并且不存在溢出问题。

    def removeOnes(self, grid: List[List[int]]) -> int:
        from collections import deque

        m = len(grid)
        n = len(grid[0])

        initial_mask = 0

        for i in range(m):
            for j in range(n):
                if grid[i][j]:
                    initial_mask |= (1 << (i * n + j))

        queue = deque([(initial_mask, 0)])
        visited = {initial_mask}

                    if next_mask not in visited:

        return -1

 ## 边缘情况

 一种重要的边缘情况是当矩阵已经不包含`1`s。 粗心的实现可能仍然会进入 BFS 循环并尝试不必要的处理。 在此解决方案中，初始掩码变为`0`，BFS立即返回`0`运营。 

另一个重要的边缘情况是只有一行或一列的矩阵。 在这些情况下，单个操作可能会清除所有剩余的`1`因为所选的行或列覆盖了整个矩阵维度。 该实现自然地处理了这个问题，因为行和列的清除逻辑是完全通用的。 

第三个微妙的边缘情况已断开连接`1`无法有效地一起删除的内容。 贪婪策略经常在这里失败，因为选择局部最佳操作可能不会最小化全局操作计数。 BFS 通过逐级探索所有可能的操作序列来避免这个问题，保证最优性。 

最后的边缘情况涉及通过不同操作顺序达到的重复状态。 如果没有访问集，算法将重复访问相同的掩码并变得极其低效。 访问集确保每个状态只处理一次。
