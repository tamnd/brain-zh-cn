[LeetCode 第 2198 题](https://leetcode.com/problems/number-of-single-divisor-triplets/)

 **难度：** 🟡 中等
 **主题：** 数组、计数、枚举

 ## 解决方案

 ## 问题理解

 该问题要求我们计算有多少个不同索引的有序三元组`(i, j, k)`满足非常具体的整除条件。 

对于每个三元组，我们计算：$$\text{sum} = nums[i] + nums[j] + nums[k]$$如果该总和可以被三个参与值之一整除，则认为三元组有效：

 -`nums[i]`-`nums[j]`-`nums[k]`索引必须全部不同，这意味着即使值相等，我们也不能多次重复使用同一数组位置。 

一个重要的细节是，该问题计算的是有序三元组，而不是无序组合。 这意味着`(0,1,2)`和`(2,1,0)`被视为不同的三元组。 如果值组合有效，则相应索引的每个有效排列都会分别对答案做出贡献。 

输入尺寸很大：

 -`nums.length`可以达到`10^5`-`nums[i]`至多是`100`这个约束是整个问题的关键观察点。 虽然数组本身很大，但是取值范围却极小。 我们不应该根据指数来思考，而应该根据值的频率来思考。 

一些边缘情况很重要：

 - 具有许多重复项的数组，例如`[1,2,2]`- 所有值都相同的数组
 - 两个或所有三个值相等的三元组
 - 值等于`1`，因为每个整数都可以被`1`- 无法进行强力枚举的大型数组

 有界值范围强烈建议使用计数和基于频率的枚举，而不是迭代所有索引三元组。 

## 方法

 ### 蛮力方法

 最直接的解决方案是尝试每一个可能的不同索引的三元组。 

对于每一个三元组`(i, j, k)`：

 1. 计算总和。 
2. 检查总和能否整除`nums[i]`。 
3. 检查总和是否能整除`nums[j]`。 
4. 检查总和能否整除`nums[k]`。 
5. 计算有多少个整除性检查成功。 
6. 如果恰好有一个成功，则增加答案。 

这是有效的，因为它确实遵循了问题的定义。 

然而，时间复杂度太大了。 有：$$O(n^3)$$可能的三胞胎，以及`n`可以是`100000`。 三次解是完全不可行的。 

### 关键见解

 关键的观察是每个数字都介于`1`和`100`。 

这意味着只有`100`整个数组中不同的可能值。 

我们可以迭代值组合，而不是迭代索引：$$(a, b, c)$$其中每个值都介于`1`和`100`。 

最多有：$$100^3 = 1,000,000$$价值三元组，这是可以管理的。 

对于每个值三元组：

 1. 检查是否`a + b + c`可以被其中之一整除。 
2. 使用频率计数计算有多少个索引三元组可以生成此值组合。 
3. 添加适当数量的排列。 

这改变了一个不可能的`O(n^3)`将解决方案转化为实用的常数有界计数解决方案。

 ## 算法演练

 ### 第 1 步：计算频率

 创建频率数组或哈希图来存储每个值出现的次数。 

由于值仅介于`1`和`100`，固定大小的数组是理想的。 

例如：```
nums = [1,2,2]
```产生：```
freq[1] = 1
freq[2] = 2
```这使我们能够计算任何值组合可能有多少个索引选择。 

### 步骤 2：枚举所有值三元组

 迭代所有可能的值：```sql
a from 1 to 100
b from 1 to 100
c from 1 to 100
```跳过任何频率为零的值。 

现阶段我们考虑的是价值组合，而不是实际指数。 

### 步骤 3：检查整除条件

 计算：$$s = a + b + c$$现在数一下其中有多少个是`s`：

 -`s % a == 0`-`s % b == 0`-`s % c == 0`如果只有一个条件为真，则三元组有效。 

### 步骤 4：计算存在多少个索引三元组

 现在确定有多少个不同的索引三元组对应于`(a,b,c)`。 

共有三种情况。 

#### 情况 1：所有值都不同

 如果：```
a != b != c
```那么有序索引三元组的数量是：$$freq[a] \times freq[b] \times freq[c]$$因为每个选择的索引都是自动不同的。 

### 情况 2：两个值相等

 假设：```
a == b != c
```然后我们必须选择两个不同的价值指数`a`。 

计数变为：$$freq[a] \times (freq[a]-1) \times freq[c]$$相同的逻辑适用于其他平等模式。 

### 情况 3：所有值都相等

 如果：```
a == b == c
```我们需要三个不同的索引：$$freq[a] \times (freq[a]-1) \times (freq[a]-2)$$### 步骤 5：添加计数

 将所有有效的有序三元组计数添加到最终答案中。 

因为我们已经在迭代有序值三元组`(a,b,c)`，排列自然也包括在内。 

## 为什么它有效

 该算法之所以有效，是因为每个有效的有序索引三元组恰好对应于一个有序值三元组`(a,b,c)`。 

可整除性测试仅取决于值，而不取决于指数本身。 因此，我们可以对每个值组合评估一次有效性，然后乘以实现该组合的索引排列的数量。 

由于频率公式正确地计算了所有相等模式的不同索引选择，因此每个有效的三元组只计算一次。 

## Python 解决方案```python
from typing import List

class Solution:
    def singleDivisorTriplet(self, nums: List[int]) -> int:
        freq = [0] * 101
        
        for num in nums:
            freq[num] += 1
        
        answer = 0
        
        for a in range(1, 101):
            if freq[a] == 0:
                continue
                
            for b in range(1, 101):
                if freq[b] == 0:
                    continue
                    
                for c in range(1, 101):
                    if freq[c] == 0:
                        continue
                    
                    total = a + b + c
                    
                    divisible_count = 0
                    
                    if total % a == 0:
                        divisible_count += 1
                    if total % b == 0:
                        divisible_count += 1
                    if total % c == 0:
                        divisible_count += 1
                    
                    if divisible_count != 1:
                        continue
                    
                    if a == b == c:
                        if freq[a] >= 3:
                            answer += (
                                freq[a]
                                * (freq[a] - 1)
                                * (freq[a] - 2)
                            )
                    
                    elif a == b:
                        if freq[a] >= 2:
                            answer += (
                                freq[a]
                                * (freq[a] - 1)
                                * freq[c]
                            )
                    
                    elif a == c:
                        if freq[a] >= 2:
                            answer += (
                                freq[a]
                                * (freq[a] - 1)
                                * freq[b]
                            )
                    
                    elif b == c:
                        if freq[b] >= 2:
                            answer += (
                                freq[a]
                                * freq[b]
                                * (freq[b] - 1)
                            )
                    
                    else:
                        answer += freq[a] * freq[b] * freq[c]
        
        return answer
```该实现首先为所有可能的值构建一个频率数组`1`到`100`。 这将问题从基于索引的枚举转换为基于值的计数。 

三个嵌套循环枚举每个有序值三元组`(a,b,c)`。 由于值范围是固定的且很小，因此这足够有效。 

对于每个三元组，代码计算总和并计算三个值中有多少个值除以该总和。 仅保留恰好满足一个除数条件的组合。 

下一部分确定有多少个实际索引三元组对应于当前值组合。 该实现仔细地分别处理了三种相等情况：

 - 一切平等
 - 正好两个相等
 - 全部不同

 这确保索引保持不同，同时保留有序排列。 

最后，将计算出的计数添加到运行总计中。 

## 解决方案```go
func singleDivisorTriplet(nums []int) int64 {
    freq := make([]int64, 101)

    for _, num := range nums {
        freq[num]++
    }

    var answer int64 = 0

    for a := 1; a <= 100; a++ {
        if freq[a] == 0 {
            continue
        }

        for b := 1; b <= 100; b++ {
            if freq[b] == 0 {
                continue
            }

            for c := 1; c <= 100; c++ {
                if freq[c] == 0 {
                    continue
                }

                total := a + b + c

                divisibleCount := 0

                if total%a == 0 {
                    divisibleCount++
                }

                if total%b == 0 {
                    divisibleCount++
                }

                if total%c == 0 {
                    divisibleCount++
                }

                if divisibleCount != 1 {
                    continue
                }

                if a == b && b == c {
                    if freq[a] >= 3 {
                        answer += freq[a] *
                            (freq[a] - 1) *
                            (freq[a] - 2)
                    }

                } else if a == b {
                    if freq[a] >= 2 {
                        answer += freq[a] *
                            (freq[a] - 1) *
                            freq[c]
                    }

                } else if a == c {
                    if freq[a] >= 2 {
                        answer += freq[a] *
                            (freq[a] - 1) *
                            freq[b]
                    }

                } else if b == c {
                    if freq[b] >= 2 {
                        answer += freq[a] *
                            freq[b] *
                            (freq[b] - 1)
                    }

                } else {
                    answer += freq[a] * freq[b] * freq[c]
                }
            }
        }
    }

    return answer
}
```Go 版本遵循与 Python 实现相同的逻辑。 一个重要的区别是该函数返回`int64`，所以频率数组和答案变量也使用`int64`以避免乘法期间溢出。 

Go 数组和切片会自动用零值初始化，这简化了频率计数。

 ## 边缘情况

 ### 所有值都相等

 像这样的数组：```
[1,1,1]
```是常见的错误来源，因为每个除数检查的行为都是相同的。 如果仅检查至少一个除数是否有效，则幼稚的实现可能会意外地将其视为有效。 该问题特别需要一个除数。 

该实现通过计算成功的整除性检查的数量并要求计数完全相等来正确处理此问题`1`。 

### 具有不同索引的重复值

 数组例如：```
[1,2,2]
```需要小心处理，因为相同的值仍然可能来自不同的索引。 一个常见的错误是低估排列或未能强制执行不同的索引。 

该实现明确使用排列式计数公式：$$freq[x] \times (freq[x]-1)$$当需要两个相等的值时。 这保证了选择不同的索引。 

### 值 1

 价值`1`很特殊，因为每个整数都可以被整除`1`。 

这意味着任何包含多个的三元组`1`s 很容易违反“恰好一个除数”规则。 例如：```
[1,1,2]
```产生总和`4`，可被两者整除`1`和`2`。 

该实现通过独立检查每个位置的整除性并计算成功的数量来避免错误，而不是仅根据值假设整除性行为。
