[LeetCode 第 2179 题](https://leetcode.com/problems/count-good-triplets-in-an-array/)

 **难度：** 🔴难
 **主题：** 数组、二分查找、分而治之、二叉索引树、线段树、归并排序、有序集

 ## 解决方案

 ## 问题理解

 在这个问题中，我们有两个数组，`nums1`和`nums2`，每个包含来自的每个整数`0`到`n - 1`正好一次。 换句话说，两个数组都是同一组值的排列。 

我们需要数一下有多少个三胞胎`(x, y, z)`同时满足两个数组中的排序条件。 

要使三元组被视为“好”，必须满足以下条件：

 - 在`nums1`，位置`x`必须先来`y`，以及位置`y`必须先来`z`- 在`nums2`，同样的顺序也必须成立

 正式：

 -`pos1[x] < pos1[y] < pos1[z]`-`pos2[x] < pos2[y] < pos2[z]`重要的细节是三元组由值组成，而不是索引。 我们正在比较这些值出现在两个数组中的位置。 

限制条件很大：

 -`n`可以大到`100000`- 所有三元组的暴力枚举需要大约检查`n^3`组合

 自从`100000^3`是一个天文数字，任何三次甚至二次解都太慢。 这强烈表明我们需要一种使用高级数据结构的有效计数技术，例如：

 - 二叉索引树
 - 线段树
 - 有序统计
 - 合并排序计数

 另一个重要的观察是两个数组都是排列。 这意味着每个值在每个数组中只出现一次。 因此，我们可以将一个数组中的值映射到另一个数组中的位置，将问题转换为单个数组上的订单计数问题。 

一些重要的边缘情况：

 - 已经具有相同顺序的数组，每个递增的三元组都是有效的
 - 数组的顺序几乎相反，存在很少或零个三元组
 - 最小有效输入大小`n = 3`- 性能变得至关重要的大量输入
 - 一个中间元素有很多有效的左侧元素但右侧元素很少的情况，反之亦然

 排列保证简化了许多实现细节，因为我们永远不需要处理重复项。 

## 方法

 ### 蛮力

 最直接的方法是枚举每一个可能的三元组`(x, y, z)`并验证它是否在两个数组中按升序出现。 

我们可以先构建两个位置图：

 -`pos1[value] = index in nums1`-`pos2[value] = index in nums2`然后，对于三个不同值的每个组合，我们检查：```
pos1[x] < pos1[y] < pos1[z]
and
pos2[x] < pos2[y] < pos2[z]
```如果两个条件都成立，我们就增加答案。 

这是有效的，因为它直接遵循问题定义。 然而，有`O(n^3)`三胞胎，这对于`n = 100000`。 

### 关键见解

 重要的观察是我们只关心相对顺序。 

假设我们将每个值映射到`nums1`到它的位置`nums2`。 

例子：```
nums1 = [2,0,1,3]
nums2 = [0,1,2,3]
```职位于`nums2`：```
0 -> 0
1 -> 1
2 -> 2
3 -> 3
```转换`nums1`：```
[2,0,1,3]
 ->
[2,0,1,3]
```现在问题变成：

 计算此变换后的数组中长度为 3 的递增子序列。 

为什么这有效？ 

- 顺序为`nums1`已经通过迭代转换后的数组来修复
 - 如果转换后的数组中的索引增加，则相应的值也会以递增的顺序出现在`nums2`现在我们可以将每个元素处理为三元组的中间元素：

 - 计算其左侧有多少个较小的元素
 - 计算其右侧有多少个较大的元素
 - 将两个计数相乘

 这可以通过二叉索引树有效地完成`O(n log n)`时间。

 ## 算法演练

 ### 第 1 步：构建位置映射

 创建一个数组`position_in_nums2`在哪里：```
position_in_nums2[value] = index of value in nums2
```这使我们能够立即确定每个值出现在的位置`nums2`。 

例如：```
nums2 = [4,1,0,2,3]

position_in_nums2:
0 -> 2
1 -> 1
2 -> 3
3 -> 4
4 -> 0
```### 步骤 2：转换 nums1

 替换中的每个值`nums1`其地位在`nums2`。 

例子：```
nums1 = [4,0,1,3,2]

transformed:
[0,2,1,4,3]
```现在问题变成：

 计算此变换后的数组中长度为 3 的递增子序列。 

为什么？ 

因为：

 - 转换后的数组中的索引顺序已经代表了`nums1`- 变换后的数组内的值的增加表示顺序的增加`nums2`### 步骤 3：计算左侧较小的元素

 我们从左到右处理转换后的数组。 

对于每个位置`i`，我们想要：```
left_smaller[i]
=
number of previous elements smaller than transformed[i]
```我们使用二叉索引树来维护先前看到的值的频率。 

对于每个值：

 1.查询出现了多少个较小的值
 2. 存储结果
 3. 将当前值插入BIT

 二叉索引树支持：

 - 前缀和查询`O(log n)`- 点更新于`O(log n)`### 步骤 4：计算右侧较大的元素

 现在从右向左处理。 

对于每个位置`i`，我们想要：```
right_larger[i]
=
number of later elements larger than transformed[i]
```再次使用二叉索引树。 

每一步：

 1、查询已经插入的元素有多少个更大
 2. 存储结果
 3. 插入当前值

 ### 步骤 5：合并计数

 将每个位置视为三元组的中间元素。 

如果：

-`left_smaller[i] = a`-`right_larger[i] = b`然后有：```
a * b
```好的三胞胎以位置为中心`i`。 

所有位置的总和。 

## 为什么它有效

 转换后的数组表示元素的顺序`nums2`同时保留订单`nums1`。 

转换后的数组中长度为 3 的递增子序列恰好对应于两个数组中按递增顺序出现的三个值。 

对于每个中间元素：

 - 任何有效的左元素必须更小
 - 任何有效的右侧元素必须更大

 每对这样的选择都会形成一个唯一的有效三元组，因此将计数相乘即可得出以该位置为中心的三元组的确切数量。 

## Python 解决方案```python
from typing import List

class BIT:
    def __init__(self, size: int):
        self.size = size
        self.tree = [0] * (size + 1)

    def update(self, index: int, delta: int) -> None:
        index += 1

        while index <= self.size:
            self.tree[index] += delta
            index += index & -index

    def query(self, index: int) -> int:
        index += 1
        result = 0

        while index > 0:
            result += self.tree[index]
            index -= index & -index

        return result

class Solution:
    def goodTriplets(self, nums1: List[int], nums2: List[int]) -> int:
        n = len(nums1)

        position_in_nums2 = [0] * n

        for index, value in enumerate(nums2):
            position_in_nums2[value] = index

        transformed = [position_in_nums2[value] for value in nums1]

        left_smaller = [0] * n
        bit = BIT(n)

        for i in range(n):
            value = transformed[i]

            left_smaller[i] = bit.query(value - 1)
            bit.update(value, 1)

        right_larger = [0] * n
        bit = BIT(n)

        for i in range(n - 1, -1, -1):
            value = transformed[i]

            total_seen = bit.query(n - 1)
            smaller_or_equal = bit.query(value)

            right_larger[i] = total_seen - smaller_or_equal

            bit.update(value, 1)

        answer = 0

        for i in range(n):
            answer += left_smaller[i] * right_larger[i]

        return answer
```实现首先构建一个位置查找表`nums2`。 由于两个数组都是排列，因此每个值都只有一个位置。 

接下来，代码进行改造`nums1`到里面的位置数组`nums2`。 这将原始问题简化为计算长度为 3 的递增子序列。 

的`BIT`类实现二叉索引树，也称为芬威克树。 它支持高效的前缀和查询以及对数时间内的点更新。 

第一遍计算`left_smaller`。 对于每个元素，BIT 存储所有先前看到的值。 查询`value - 1`告诉我们当前元素之前出现了多少个较小的元素。 

第二遍计算`right_larger`。 我们从右向左遍历并维护另一个包含已在右侧看到的元素的 BIT。 区别：```python
total_seen - smaller_or_equal
```给出右侧严格较大元素的数量.

 最后，每个索引都被视为三元组的中间元素。 将有效的左选择和右选择的数量相乘即可得出该位置的总贡献。 

## 解决方案```go
package main

type BIT struct {
	tree []int
	size int
}

func NewBIT(size int) *BIT {
	return &BIT{
		tree: make([]int, size+1),
		size: size,
	}
}

func (b *BIT) Update(index int, delta int) {
	index++

	for index <= b.size {
		b.tree[index] += delta
		index += index & -index
	}
}

func (b *BIT) Query(index int) int {
	index++

	result := 0

	for index > 0 {
		result += b.tree[index]
		index -= index & -index
	}

	return result
}

func goodTriplets(nums1 []int, nums2 []int) int64 {
	n := len(nums1)

	positionInNums2 := make([]int, n)

	for index, value := range nums2 {
		positionInNums2[value] = index
	}

	transformed := make([]int, n)

	for i, value := range nums1 {
		transformed[i] = positionInNums2[value]
	}

	leftSmaller := make([]int, n)
	bit := NewBIT(n)

	for i := 0; i < n; i++ {
		value := transformed[i]

		leftSmaller[i] = bit.Query(value - 1)
		bit.Update(value, 1)
	}

	rightLarger := make([]int, n)
	bit = NewBIT(n)

	for i := n - 1; i >= 0; i-- {
		value := transformed[i]

		totalSeen := bit.Query(n - 1)
		smallerOrEqual := bit.Query(value)

		rightLarger[i] = totalSeen - smallerOrEqual

		bit.Update(value, 1)
	}

	var answer int64 = 0

	for i := 0; i < n; i++ {
		answer += int64(leftSmaller[i] * rightLarger[i])
	}

	return answer
}
```Go 实现遵循与 Python 版本相同的算法结构。 

一个重要的区别是返回类型。 问题需要返回`int64`因为三元组的数量可能超出 32 位整数的范围。 

二叉索引树被实现为具有更新和前缀查询方法的结构。 使用 Go 切片代替 Python 列表，但逻辑保持不变。 

另一个细节是累积最终答案时的显式整数转换：```go
answer += int64(leftSmaller[i] * rightLarger[i])
```如果没有这种转换，某些平台上可能会发生整数溢出。

 ## 边缘情况

 当两个数组相同且严格递增时，就会出现一种重要的边缘情况。 在这种情况下，三个索引的每种可能的组合都会形成一个有效的三元组。 这可以产生非常大的答案，特别是对于大的`n`。 该实现正确处理了这个问题，因为二叉索引树有效地计算了所有递增子序列，并且 Go 解决方案使用`int64`以避免溢出。 

另一个重要的情况是当阵列相对于彼此有效反转时。 例如：```
nums1 = [0,1,2]
nums2 = [2,1,0]
```在这种情况下，不存在递增三元组，因为一个数组中的每个排序在另一个数组中都会递减。 该实现自然地处理了这个问题，因为转换后的数组不包含长度为 3 的递增子序列，导致所有贡献变为零。 

微妙的边缘情况涉及中间元素，左侧有许多较小的值，但右侧没有较大的值，反之亦然。 由于该算法将两个计数相乘，因此任何缺失的一侧都正确地产生零贡献。 这可以防止对无效的部分三元组进行计数。 

另一个潜在的错误来源是二元索引树内的一个索引。 该实现通过在更新和查询之前递增索引，在内部小心地将基于零的数组索引转换为基于一的 BIT 索引。 这可以确保正确计算所有值的前缀和`0`到`n - 1`。
