[LeetCode 问题 2141](https://leetcode.com/problems/maximum-running-time-of-n-computers/)

 **难度：** 🔴难
 **主题：** 数组、二分搜索、贪心、排序

 ## 解决方案

 ## 问题理解

 问题是要求我们确定**最大分钟数`n`计算机可以使用一组给定的电池同时运行**。 每个电池在几分钟内都有固定的能量，您最初可以为**每台计算机分配最多一个电池**。 之后，您可以在任意整数时刻在计算机之间自由更换电池，并且每个电池只能贡献其总运行时间。 目标是**最大化所有同时运行的计算机的运行时间**。 

输入由一个整数组成`n`表示计算机和数组的数量`batteries`在哪里`batteries[i]`是持续时间`i-th`电池可以提供。 输出是一个整数，表示所有计算机可以同时供电的最长时间。 

约束表明`n`可以达到`10^5`电池容量高达`10^9`。 这表明任何尝试电池分配的所有可能排列或逐步模拟时间的解决方案都将太慢。 我们还知道电池的数量至少与计算机的数量一样多。 

需要考虑的边缘情况包括：

 1. 所有电池都是平等的。 
2.电池比电脑还多。 
3. 电池容量差异较大，例如：`[1,1,1,1000000000]`。 
4.只有一台电脑（`n = 1`） 或者`n`等于电池的数量。 

## 方法

 **暴力方法：**

 一个简单的解决方案是每分钟模拟计算机，在电池耗尽时始终为每台计算机选择最大的可用电池。 这保证了正确性，但速度太慢，因为总运行时间可能达到所有电池的总和，最多可达`10^14`对于给定的约束。 每分钟迭代是不可行的。 

**最佳方法：**

 关键的见解是我们可以**考虑总电池容量和每台计算机的目标运行时间**。 如果我们假设所有计算机都运行`T`分钟，所有电池的总和必须至少`n * T`。 运行时间大于的电池`T`可以简单地提供`T`每分钟几分钟，较小的电池可以提供完整的运行时间。 利用这个观察结果，我们可以使用**二分搜索**`T`找到最大可能的运行时间。 

1.设置搜索范围从`1`到`sum(batteries) // n`。 
2. 检查候选运行时是否`mid`可以通过求和来实现`min(b, mid)`对于所有电池并验证它至少是`n * mid`。 
3. 相应地调整二分查找。 

这种方法保证在相对于电池总和的对数时间内得到答案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(总和(电池)) | O(1) | O(1) | 所有计算机的逐分钟模拟|
 | 最佳| O(m log(S)) | O(1) | O(1) | 最大运行时间的二分查找`T`， 在哪里`m = len(batteries)`和`S = sum(batteries)`|

 ## 算法演练

 1. **初始化搜索范围：** 计算所有电池容量的总和。 放`left = 1`和`right = sum(batteries) // n`。 
2. **二分查找循环：** While`left <= right`， 计算`mid = (left + right) // 2`。 
3. **可行性检查：** 对于每个电池，计算`min(b, mid)`并对它们进行总结。 这代表电池对目标运行时间的贡献程度`mid`。 
4. **调整界限：** 如果总和至少为`n * mid`， 然后`mid`是可以实现的。 移动`left = mid + 1`尝试更长的运行时间。 否则，设置`right = mid - 1`。 
5. **返回结果：** 二分查找结束后，`right`包含可实现的最大运行时间。 

**为什么有效：**

 二分搜索之所以有效，是因为总运行时间是单调递增的：如果`T`是可以实现的，任何小于`T`也是可以实现的。 可行性检查可确保我们不会超出可用的总电池容量。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxRunTime(self, n: int, batteries: List[int]) -> int:
        total = sum(batteries)
        left, right = 1, total // n
        
        def can_run(target: int) -> bool:
            return sum(min(b, target) for b in batteries) >= n * target
        
        while left <= right:
            mid = (left + right) // 2
            if can_run(mid):
                left = mid + 1
            else:
                right = mid - 1
        
        return right
```**说明：**

 该代码计算电池总容量并使用二分搜索找到最大运行时间`right`。 这`can_run`函数评估是否可以通过将每个电池限制在`target`会议记录并对贡献进行总结。 这可以有效地检查可行性，而无需逐分钟进行模拟。 

## 解决方案```go
func maxRunTime(n int, batteries []int) int64 {
    var total int64
    for _, b := range batteries {
        total += int64(b)
    }
    
    left, right := int64(1), total/int64(n)
    
    canRun := func(target int64) bool {
        var sum int64
        for _, b := range batteries {
            if int64(b) > target {
                sum += target
            } else {
                sum += int64(b)
            }
        }
        return sum >= int64(n)*target
    }
    
    for left <= right {
        mid := (left + right) / 2
        if canRun(mid) {
            left = mid + 1
        } else {
            right = mid - 1
        }
    }
    
    return right
}
```**去注意：**

 我们使用`int64`以避免溢出，因为总和可能超过`10^14`。 二分搜索逻辑反映了 Python 版本。 主要区别在于显式类型转换和安全处理大金额。 

## 工作示例

 **示例1：**`n = 2, batteries = [3,3,3]`1.`total = 9`,`left = 1`,`right = 4`。 
2.二分查找`mid = 2`。 总和`min(b, 2)`= 2+2+2=6 ≥ 4 → 可行 → 左 = 3。 
3.`mid = 3`。 和 = 3+3+3=9 ≥ 6 → 可行 → 左 = 4。 
4.`mid = 4`。 和 = 3+3+3=9 < 8 → 不可行 → 对 = 3。 
5. 返回`right = 4`。 

**示例2：**`n = 2, batteries = [1,1,1,1]`1.`total = 4`,`left = 1`,`right = 2`。 
2.`mid = 1`。 和 = 1+1+1+1=4 ≥ 2 → 可行 → 左 = 2。 
3.`mid = 2`。 总和 = min(1,2)+min(1,2)+min(1,2)+min(1,2)=4 ≥ 4 → 可行 → left = 3。 
4. 返回`right = 2`。 

## 复杂度分析

 | 测量| 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(m log(S)) | 对总和范围进行二分搜索`m = len(batteries)`和总和`S = sum(batteries)`。 每次检查的时间复杂度为 O(m)。 |
 | 空间| O(1) | O(1) | 仅使用二分搜索和求和的变量，不需要额外的结构。 |

 即使对于上限约束，时间复杂度也是有效的（`m = 10^5`） 因为`log(S)`大约为 44`S ~ 10^14`。
