[LeetCode 问题 2165](https://leetcode.com/problems/smallest-value-of-the-rearranged-number/)

 **难度：** 🟡 中等
 **主题：** 数学、排序

 ## 解决方案

 ## 问题理解

 在这个问题中，我们给定一个整数`num`，可以是正数、负数或零。 我们的目标是重新排列其数字，使结果数字尽可能小，同时保留原始符号。 

重要的细节是标志不能改变。 如果该数字为正数，则重新排列后的数字也必须保持为正数。 如果数字为负数，则重新排列后的数字必须保持负数。 

该问题还表明结果数字不能包含前导零。 这意味着对于正数，我们不能将`0`在重新排列的数字的开头。 例如，重新排列`310`进入`013`无效，因为整数不允许在其表示形式中出现前导零。 

对于负数，解释略有不同。 由于负数越大，数值越小，因此我们实际上希望最大化绝对值。 例如：

-`-7650 < -6705`- 所以`-7650`被认为较小

 这意味着：

 - 正数的数字应按升序排列
 - 负数应按降序排列

 限制相对较小：

 -`-10^15 <= num <= 10^15`一个有大小的数字`10^15`包括符号在内最​​多有 16 位数字，因此输入大小很小。 这意味着对数字进行排序是完全可行的。 

一些重要的边缘情况包括：

 - 包含许多零的数字，例如`100200`- 数量已经很少了
 - 负数
 - 价值`0`- 含有重复数字的数字
 - 最小数字为正数`0`当正确处理前导零时，幼稚的实现很容易失败。 

## 方法

 ### 蛮力方法

 强力解决方案将生成每个可能的数字排列，将每个排列转换为有效数字，过滤掉带有前导零的排列，然后选择最小有效值。 

例如，对于`310`，我们将生成：

 -`013`-`031`-`103`-`130`-`301`-`310`然后我们丢弃无效的前导零数字并选择最小的剩余值。 

这种方法是正确的，因为它明确地检查了每种可能的安排。 然而，它在计算上是不切实际的，因为排列的数量呈阶乘增长。 

如果号码有`n`数字，有`n!`排列。 即使只有 15 位数字，这也是一个天文数字。 

### 最佳方法

 关键的观察是我们不需要尝试每一种排列。 我们只需要构建字典顺序上最小的有效排列。 

对于正数：

 - 按升序对数字进行排序
 - 将第一个非零数字移到前面
 - 紧随其后放置所有零
 - 附加剩余的数字

 这保证了没有前导零的最小可能正数。 

对于负数：

 - 按降序对数字进行排序
 - 建立尽可能最大的绝对值
 - 重新应用负号

 这是有效的，因为在负数中，较大的量级对应于较小的值。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n! × n) | O(n! × n) | O(n!) | 生成所有数字排列 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 使用排序和贪婪数字放置 |

 ## 算法演练

 ### 正数情况

 1. 将数字转换为数字字符列表。 

这使得对各个数字进行排序和重新排列变得容易。 
2. 按升序对数字进行排序。 

较小的数字应该更早出现，因为我们想要尽可能小的值。 
3. 小心处理前导零。 

排序后，前面可能会出现零。 前导零无效，因此我们找到第一个非零数字并将其移至开头。 
4. 保留所有剩余数字的升序。 

一旦第一个数字被固定为最小的非零数字，其余数字应保持排序以最小化总数。 
5. 将重新排列的数字列表转换回整数。 

### 负数情况

 1. 取绝对值去掉负号。 
2. 将数字转换为列表。 
3. 按降序排列数字。 

对于负数，绝对值越大，最终数字越小。 
4. 将数字连接成一个数字。 
5. 重新应用负号。 

### 特殊情况：零

 如果输入是`0`，结果很简单`0`。 

## 为什么它有效

 对于正数，将最小的非零数字放在前面可以保证最小的有效前导数字。 将剩余数字保持升序排列可以最小化每个后续位置。 

对于负数，最大化绝对值会产生数值上最小的负数，因为数值越大，负值越大。 

这些贪婪的选择总是最优的，因为数字位置根据位值独立贡献。 

## Python 解决方案```python
class Solution:
    def smallestNumber(self, num: int) -> int:
        if num == 0:
            return 0

        # Negative number case
        if num < 0:
            digits = list(str(-num))
            digits.sort(reverse=True)

            return -int("".join(digits))

        # Positive number case
        digits = list(str(num))
        digits.sort()

        # Find first non-zero digit
        first_non_zero = 0
        while digits[first_non_zero] == '0':
            first_non_zero += 1

        # Place smallest non-zero digit first
        digits[0], digits[first_non_zero] = (
            digits[first_non_zero],
            digits[0],
        )

        return int("".join(digits))
```实现从处理最简单的特殊情况开始，`0`。 

对于负数，代码将绝对值转换为数字，按降序对它们进行排序，将它们重新连接在一起，然后重新应用负号。 

对于正数，数字按升序排序。 由于前面可能出现零，因此算法会扫描第一个非零数字并将其交换到前导位置。 这保留了尽可能小的排列，同时避免了前导零。 

最后，将数字连接起来并转换回整数。 

## 解决方案```go
package main

import (
	"sort"
	"strconv"
)

func smallestNumber(num int64) int64 {
	if num == 0 {
		return 0
	}

	// Negative number case
	if num < 0 {
		digits := []byte(strconv.FormatInt(-num, 10))

		sort.Slice(digits, func(i, j int) bool {
			return digits[i] > digits[j]
		})

		value, _ := strconv.ParseInt(string(digits), 10, 64)
		return -value
	}

	// Positive number case
	digits := []byte(strconv.FormatInt(num, 10))

	sort.Slice(digits, func(i, j int) bool {
		return digits[i] < digits[j]
	})

	// Find first non-zero digit
	firstNonZero := 0
	for digits[firstNonZero] == '0' {
		firstNonZero++
	}

	// Swap into front position
	digits[0], digits[firstNonZero] =
		digits[firstNonZero], digits[0]

	value, _ := strconv.ParseInt(string(digits), 10, 64)

	return value
}
```Go 解决方案遵循与 Python 实现相同的逻辑。 

一个重要的区别是 Go 使用`[]byte`有效地操纵字符。 排序是使用实现的`sort.Slice`，允许自定义比较函数。 

最终的数字是使用重建的`strconv.ParseInt`。 

因为约束条件仅限于`10^15`，所有结果都安全地放入其中`int64`。

 ## 边缘情况

 ### 排序后带前导零的正数

 对包含零的正数进行排序时，会出现一个非常常见的错误。 例如，排序`310`直接生产`013`，这是无效的，因为整数不能包含前导零。 

该实现通过定位第一个非零数字并将其交换到前面的位置来修复此问题。 

### 负数

 负数反转了优化逻辑。 对于正数，我们最小化绝对值，但对于负数，我们最大化它。 

例如：

-`-7650 < -5067`总是按升序排序的幼稚解决方案在这里会失败。 该实现正确地按负输入的降序对数字进行排序。 

### 输入等于零

 数量`0`是一种特殊情况，因为它只有一位数字，不需要重新排列。 

如果没有明确处理这种情况，某些实现可能会尝试不必要的数字处理。 解决方案立即返回`0`。 

### 具有重复数字的数字

 重复的数字有时会暴露交换逻辑或排序假设中的错误。 

例如：```
11111
```所有排列都是相同的，因此输出应保持不变。 

该实现自然地处理了这个问题，因为对重复的数字进行排序不会错误地改变它们的排列。
