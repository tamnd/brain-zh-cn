 # LeetCode 2104 - 子数组范围之和

 ## 问题理解

 问题给了我们一个整数数组`nums`，并要求我们计算每个可能的非空连续子数组的范围之和。 

子数组的范围定义为：```
maximum element - minimum element
```对于每个可能的子数组，我们计算其范围，然后将所有这些范围加在一起。 

例如，如果：```
nums = [1,2,3]
```子数组是：```
[1]       -> range = 0
[2]       -> range = 0
[3]       -> range = 0
[1,2]     -> range = 1
[2,3]     -> range = 1
[1,2,3]   -> range = 2
```最终的答案是：```
0 + 0 + 0 + 1 + 1 + 2 = 4
```输入数组可以包含正整数和负整数。 数组长度最多为`1000`，这意味着对于原始约束，二次解是可以接受的，但后续明确要求`O(n)`解决方案。 

关键的挑战是子数组的数量是`O(n²)`。 如果我们分别计算每个子数组的最小值和最大值，则总复杂度可以变为`O(n³)`，这是低效的。 

一些边缘情况很重要：

 - 具有所有相等值的数组，因为每个子数组范围都变为`0`- 包含负数的数组
 - 具有重复值的数组，因为单调堆栈逻辑必须小心避免重复计算
 - 非常小的数组，例如长度`1`- 严格增加或严格减少数组，因为它们会产生极端的堆栈行为

 该问题保证：

 -`nums`是非空的
 - 值适合有符号 32 位整数
 - 最终答案可能超出32位整数范围，因此需要更大的整数类型

 ## 方法

 ### 蛮力方法

 最直接的解决方案是枚举每个子数组。 

对于每个起始索引，我们一次扩展子数组一个元素，同时保持当前的最小值和最大值。 当前子数组的范围是：```
current_max - current_min
```我们将此值添加到答案中。 

简单的暴力解决方案将独立地重新计算每个子数组的最小值和最大值，从而导致`O(n³)`复杂。 然而，我们可以通过在扩展子数组的同时增量更新运行最小值和最大值来稍微优化。 这将复杂性降低到`O(n²)`。 

这是有效的，因为每个子数组都被检查一次，并且它的范围被正确计算。 

虽然`O(n²)`对于给定的约束，它不满足线性时间的后续要求。 

### 使用单调堆栈的最佳方法

 关键的见解是：```
sum of subarray ranges
=
(sum of all subarray maximums)
-
(sum of all subarray minimums)
```我们不是单独评估每个子数组，而是计算每个元素的贡献量：

 - 最大
 - 最低限度

 对于特定元素`nums[i]`，我们确定：

 - 有多少子数组使用它作为最大值
 - 有多少子数组使用它作为最小值

 如果一个元素出现在`k`子数组，那么它对最大和的总贡献为：```
nums[i] * k
```对于最小值也是如此。 

为了有效地计算这些，我们使用单调堆栈来查找：

 - 上一个较少的元素
 - 下一个较少的元素
 - 上一个更大的元素
 - 下一个更大的元素

 这些边界决定了在保持当前元素为最小值或最大值的同时可以向左和向右扩展多少个子数组。 

这将问题转化为线性时间贡献计数问题。

 ## 算法演练

 ### 步骤 1：将问题转化为贡献计数

 不要直接计算每个子数组范围，而是将公式重写为：```
sum(maximums) - sum(minimums)
```这使我们能够独立处理最大贡献和最小贡献。 

### 第 2 步：计算最低贡献

 对于每个索引`i`, 确定有多少个子数组`nums[i]`作为它们的最小值。 

我们需要两个边界：

 1. 左边最近的较小元素
 2. 右边最接近的较小或相等的元素

 这些边界确保正确处理重复项，而不会重复计算。 

如果：```
left = distance to previous smaller
right = distance to next smaller-or-equal
```然后是子数组的数量，其中`nums[i]`最小值为：```
left * right
```它的贡献变为：```
nums[i] * left * right
```我们使用单调递增堆栈来有效地计算这些边界。 

### 步骤 3：计算最大贡献

 对最大值重复相同的过程。 

现在我们使用：

 - 前一个更大的元素
 - 下一个大于或等于的元素

 我们维护一个单调递减的堆栈。 

再次：```
count = left * right
```贡献：```
nums[i] * left * right
```### 步骤 4：计算最终答案

 最终的答案是：```
total_maximum_contribution - total_minimum_contribution
```### 为什么它有效

 每个子数组恰好有一个最大值和一个最小值。 我们不是直接枚举子数组，而是计算每个元素占主导地位的最大或最小值有多少个子数组。 

单调堆栈保证对于每个元素，我们都能正确识别其保持最小值或最大值的最大间隔。 将有效左侧选择的数量乘以有效右侧选择的数量即可得出该元素贡献的子数组的确切数量。 

由于每个子数组对最大总和仅贡献一次，对最小总和仅贡献一次，因此减去总数即可得出正确答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def subArrayRanges(self, nums: List[int]) -> int:
        n = len(nums)

        def sum_subarray_mins() -> int:
            stack = []
            result = 0

            for i in range(n + 1):
                current = nums[i] if i < n else float('-inf')

                while stack and nums[stack[-1]] > current:
                    mid = stack.pop()

                    left = mid - (stack[-1] if stack else -1)
                    right = i - mid

                    result += nums[mid] * left * right

                stack.append(i)

            return result

        def sum_subarray_maxs() -> int:
            stack = []
            result = 0

            for i in range(n + 1):
                current = nums[i] if i < n else float('inf')

                while stack and nums[stack[-1]] < current:
                    mid = stack.pop()

                    left = mid - (stack[-1] if stack else -1)
                    right = i - mid

                    result += nums[mid] * left * right

                stack.append(i)

            return result

        return sum_subarray_maxs() - sum_subarray_mins()
```该实现将计算分为两个辅助函数：

 -`sum_subarray_mins`-`sum_subarray_maxs`每个助手在充当最小值或最大值时计算所有元素的总贡献。 

堆栈存储索引而不是值，因为我们需要位置之间的距离。 堆栈保持单调顺序：

 - 增加最低订单
 - 减少最大值的顺序

 哨兵迭代`n`将所有剩余元素强制移出堆栈，以便处理它们的贡献。 

当索引弹出时：```python
left = mid - previous_index
right = next_index - mid
```该元素占主导地位的子数组的数量为：```python
left * right
```贡献公式：```python
nums[mid] * left * right
```将元素在所有有效子数组中的总效果相加。 

最后，用最大贡献总和减去最小贡献总和得出答案。 

## 解决方案```go
func subArrayRanges(nums []int) int64 {
	n := len(nums)

	sumSubarrayMins := func() int64 {
		stack := []int{}
		var result int64 = 0

		for i := 0; i <= n; i++ {
			current := -(1 << 60)

			if i < n {
				current = nums[i]
			}

			for len(stack) > 0 && nums[stack[len(stack)-1]] > current {
				mid := stack[len(stack)-1]
				stack = stack[:len(stack)-1]

				leftBoundary := -1
				if len(stack) > 0 {
					leftBoundary = stack[len(stack)-1]
				}

				left := mid - leftBoundary
				right := i - mid

				result += int64(nums[mid]) * int64(left) * int64(right)
			}

			stack = append(stack, i)
		}

		return result
	}

	sumSubarrayMaxs := func() int64 {
		stack := []int{}
		var result int64 = 0

		for i := 0; i <= n; i++ {
			current := 1 << 60

			if i < n {
				current = nums[i]
			}

			for len(stack) > 0 && nums[stack[len(stack)-1]] < current {
				mid := stack[len(stack)-1]
				stack = stack[:len(stack)-1]

				leftBoundary := -1
				if len(stack) > 0 {
					leftBoundary = stack[len(stack)-1]
				}

				left := mid - leftBoundary
				right := i - mid

				result += int64(nums[mid]) * int64(left) * int64(right)
			}

			stack = append(stack, i)
		}

		return result
	}

	return sumSubarrayMaxs() - sumSubarrayMins()
}

一个重要的区别是整数处理。 结果可能超出 32 位整数范围，因此函数返回`int64`，并且所有贡献计算都显式转换为`int64`。 

Go 不提供内置的整数无穷大值，因此需要手动选择大的哨兵值：```go
-(1 << 60)
1 << 60
```切片用作具有追加和截断操作的堆栈。

 ## 边缘情况

 ### 单元素数组

 如果数组仅包含一个元素，则唯一的子数组就是该元素本身。 由于最小值和最大值相等，因此范围始终为零。 

这很容易导致堆栈边界计算中出现相差一的错误。 该实现可以正确处理它，因为：```
left = 1
right = 1
```并且最大和最小贡献相互抵消。 

### 具有重复值的数组

 重复值是单调堆栈问题中最容易出错的部分之一。 

如果双方都使用严格的比较，有些子数组可能会被计算多次。 如果两者都使用非严格比较，则某些子数组可能永远不会被计算在内。 

该实现仔细地混合了严格和非严格比较，因此每个子数组都被精确地分配给一个代表元素。 

这保证了正确性而不会重复计算。 

### 严格递增或递减数组

 单调数组产生尽可能深的堆栈行为。 

例如：```
[1,2,3,4,5]
```创建一个连续增加的堆栈以进行最少的计算。 

设计不当的算法可能会退化为二次行为。 然而，在此实现中，每个索引仍仅推送和弹出一次，因此总复杂度保持线性。 

### 负数

 由于范围取决于最大值和最小值之间的差异，因此必须小心处理负数。 

例如：```
[-3,-2,-1]
```仍然具有正范围，因为：```
max - min
```仍然积极。 

该算法可以正确工作，因为它从不依赖于正性，仅依赖于元素之间的相对顺序。
