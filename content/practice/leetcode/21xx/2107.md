 # LeetCode 2107 - 分享 K 颗糖果后独特口味的数量

 ## 问题理解

 问题给了我们一个整数数组`candies`，其中每个值代表糖果的味道。 我们必须准确地给出`k`连续给我们妹妹糖果。 删除那些之后`k`糖果，剩下的糖果我们自己留着。 

我们的目标是最大限度地增加我们所拥有的不同糖果口味的数量。 

换句话说，我们选择一个长度为的连续子数组`k`删除，并且我们希望该窗口之外的剩余元素包含尽可能多的唯一值。 

例如，如果：```
candies = [1,2,2,3,4,3]
k = 3
```我们删除子数组`[2,2,3]`，那么剩下的糖果是：```
[1,4,3]
```其余的独特口味是`{1,3,4}`，所以答案是`3`。 

约束条件很重要：

 -`candies.length`可以大到`10^5`- 糖果口味也可以大到`10^5`这立即告诉我们，`O(n^2)`解决方案可能会超时。 我们需要一种以线性时间或接近线性时间运行的算法。 

有几个重要的边缘情况：

 -`k = 0`，这意味着我们什么也不放弃
 -`k = n`，这意味着我们赠送所有糖果
 - 具有所有相同口味的阵列
 - 每种口味都是独一无二的阵列
 - 空数组

 该问题保证了`0 <= k <= candies.length`，所以我们永远不需要处理无效的窗口大小。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是尝试每个可能的连续大小块`k`。 

对于每个可能的窗口：

 1. 从概念上删除该窗口
 2. 搭建一套剩余的糖果
 3.数数独特的味道
 4. 追踪最大结果

 这是有效的，因为我们明确评估了要分享的每一个有效的糖果选择。 

然而，这种方法太慢了。 

如果数组有长度`n`， 有`O(n)`可能的窗口。 对于每个窗口，重建剩余的集合可能需要`O(n)`时间。 这导致了整体的复杂性`O(n^2)`。 

和`n = 100000`，这不切实际。 

### 最优滑动窗口方法

 关键的观察是，我们可以动态地维护频率计数，而不是重复重建剩余的糖果。 

以不同的方式思考这个问题：

 - 最初，我们拥有所有糖果
 - 然后我们滑动一个大小的窗口`k`- 窗内的糖果被赠送
 - 窗外的糖果仍然是我们的

 我们可以维护一个代表我们当前保留的糖果的频率图。 

最初：

 - 频率图包含所有糖果的计数
 - 地图中的键数等于我们当前拥有的独特风味的数量

 随着共享窗口的滑动：

 - 进入窗口的糖果将从我们的收藏中删除
 - 离开窗户的糖果被添加回我们的收藏中

 这使我们能够在每步恒定时间内更新答案。 

因为每个糖果只被处理几次，所以整个算法变得线性。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 为每个窗口重建剩余的风格 |
 | 最佳| O(n) | O(n) | 使用带有频率计数的滑动窗口 |

 ## 算法演练

 1. 创建一个频率图，其中包含整个数组中每种糖果口味的计数。 

这代表了我们在分享任何东西之前最初保留的所有糖果。 
2. 计算独特风味的初始数量。 

这只是频率图中键的数量。 
3.特殊情况处理`k == 0`。 

如果我们不赠送任何糖果，答案就是不同口味的总数。 
4.开始滑动一个大小的窗口`k`穿过阵列。 

窗户代表与姐姐分享的糖果。 
5. 对于进入窗口的每个糖果：

 - 减少频率图中的计数
 - 如果其计数变为零，请将其从地图上完全删除

 这反映出我们不再拥有共享窗口之外的那种味道。 
6. 一旦窗口达到尺寸`k`，计算剩余的独特口味的数量。 

由于地图上只包含我们仍然保留的糖果，因此此时的答案很简单：```
len(frequency_map)
```7.更新最大答案。 
8. 向前移动窗口之前：

 - 添加回当前窗口最左边的糖果
 - 增加其在地图中的出现频率

 这反映了在糖果离开共享段后收回其所有权。 
9. 继续，直到处理完所有窗口。 

### 为什么它有效

 滑动窗口始终代表正在共享的确切糖果。 频率图总是代表我们在窗外仍然拥有的糖果。 

由于当糖果进入或离开窗口时地图会一致更新，因此地图中的键数始终等于我们当前保留的独特口味的数量。 

通过检查每个有效窗口一次，我们保证最大记录值是最佳答案。 

## Python 解决方案```python
from typing import List
from collections import Counter

class Solution:
    def shareCandies(self, candies: List[int], k: int) -> int:
        frequency = Counter(candies)

        if k == 0:
            return len(frequency)

        max_unique = 0
        left = 0

        for right in range(len(candies)):
            flavor = candies[right]

            frequency[flavor] -= 1

            if frequency[flavor] == 0:
                del frequency[flavor]

            if right - left + 1 == k:
                max_unique = max(max_unique, len(frequency))

                left_flavor = candies[left]
                frequency[left_flavor] = frequency.get(left_flavor, 0) + 1

                left += 1

        return max_unique
```实施首先构建一个`Counter`包含每种糖果口味的频率。 这代表当前拥有的所有糖果。 

如果`k == 0`，没有共享糖果，因此我们立即返回不同口味的数量。 

滑动窗口是使用两个指针控制的：

 -`left`-`right`作为`right`指针展开窗口，相应的糖果将从频率图中删除，因为它现在是共享的。 

每当频率变为零时，风味就会从地图上完全删除。 这保持`len(frequency)`等于我们仍然拥有的不同口味的数量。 

一旦窗口大小变得精确`k`，我们使用当前剩余的独特口味数量更新答案。 

在继续之前，我们将窗口左侧的糖果恢复到地图中，因为它在下一次迭代中将不再被共享。 

这保证了整个滑动过程中正确的状态维护。 

## 解决方案```go
func shareCandies(candies []int, k int) int {
	frequency := make(map[int]int)

	for _, candy := range candies {
		frequency[candy]++
	}

	if k == 0 {
		return len(frequency)
	}

	maxUnique := 0
	left := 0

	for right := 0; right < len(candies); right++ {
		flavor := candies[right]

		frequency[flavor]--

		if frequency[flavor] == 0 {
			delete(frequency, flavor)
		}

		if right-left+1 == k {
			if len(frequency) > maxUnique {
				maxUnique = len(frequency)
			}

			leftFlavor := candies[left]
			frequency[leftFlavor]++

			left++
		}
	}

	return maxUnique
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

一个`map[int]int`用来代替Python的`Counter`。 由于 Go 映射会针对丢失的键自动返回零值，因此增加恢复的频率非常简单。 

这`delete`函数删除计数达到零的口味，确保`len(frequency)`准确跟踪剩余独特口味的数量。 

不需要对整数溢出进行特殊处理，因为所有值都保持在 Go 的整数范围内。

 该算法是线性的，因为每个数组元素都会被处理固定次数。 哈希图中更新、插入、删除的频率都是平均的`O(1)`运营。 

空间复杂度取决于不同糖果口味的数量。 在最坏的情况下，每种糖果都有不同的味道，因此地图会存储`n`条目。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`k = 0`。 在这种情况下，没有共享糖果，因此答案应该只是原始数组中不同口味的总数。 有缺陷的实现可能仍会尝试滑动窗口逻辑并意外删除元素。 该实现通过在窗口处理开始之前提前返回来避免这种情况。 

另一个关键的边缘情况是`k = len(candies)`。 在这里，每一块糖都分给姐姐了，我们连糖都没有了。 因此正确答案是`0`。 滑动窗口自然会处理这个问题，因为一旦整个数组进入窗口，频率图就会变空。 

具有所有相同口味的数组是另一个常见的错误来源。 例如：```
[1,1,1,1]
```即使除去一些糖果后，剩下的糖果仍然只含有一种独特的味道。 不正确的实现可能会将总计数与不同计数混淆。 使用频率图并仅对图键进行计数可确保正确性。 

空输入数组也值得关注。 由于没有糖果，所以答案一定是`0`。 该实现自然地处理了这个问题，因为频率图开始为空并且不会发生滑动。 

最后，具有完全不同风味的阵列需要小心处理。 删除任何窗口都会减少剩余独特风味的数量，其数量恰好等于删除元素的数量。 滑动窗口正确地捕获了这一点，因为去除风味后频率立即降至零。
