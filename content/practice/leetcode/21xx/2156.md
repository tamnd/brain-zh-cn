[LeetCode 问题 2156](https://leetcode.com/problems/find-substring-with-given-hash-value/)

 **难度：** 🔴难
 **主题：** 字符串、滑动窗口、滚动哈希、哈希函数

 ## 解决方案

 ## 问题理解

 这道题要求我们找到长度最早的子串`k`其多项式滚动哈希等于给定的目标值。 

哈希函数定义为：$$hash(s, p, m) = \left( \sum_{i=0}^{k-1} val(s[i]) \cdot p^i \right) \bmod m$$在哪里：

-`val('a') = 1`-`val('b') = 2`- ...
 -`val('z') = 26`对于长度为的子串`k`，第一个字符贡献乘数`p^0`，第二个与`p^1`， 等等。 

输入包括：

 -`s`, 完整的字符串
 -`power`，多项式哈希的基数
 -`modulo`，用于保持值有界的模数
 -`k`, 子串长度
 -`hashValue`，我们要匹配的目标哈希

 输出必须是length的第一个子串`k`其哈希值等于`hashValue`。 

重要的细节是“第一”二字。 多个子字符串可能会产生相同的哈希值，但我们必须返回起始索引最小的那个。 

约束足够大，独立地重新计算每个子字符串的哈希会太慢：

 -`s.length`可以达到`2 * 10^4`-`power`和`modulo`可以大到`10^9`这强烈建议使用滚动哈希技术，我们在滑动字符串时有效地更新哈希值。 

有几种边缘情况值得注意：

 -`k`可能等于整个字符串长度，这意味着只有一个候选子字符串。 
-`modulo`可能非常小，产生很多碰撞。 
- 可能存在多个有效子串，因此我们必须小心保留最早的一个。 
- 大值`power`和`modulo`始终需要模块化算术以避免溢出并保持正确性。 
- 因为公式中的幂从左到右增加，所以标准的从左到右滚动哈希更新变得很尴尬。 反转遍历方向大大简化了实现。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每个长度的子串`k`。 

对于每个子串：

 1. 从头开始计算其哈希值。 
2. 将结果与`hashValue`。 
3. 返回第一个匹配的子串。 

为了计算一个子字符串的哈希值，我们计算：$$val(s[0]) \cdot p^0 + val(s[1]) \cdot p^1 + \dots + val(s[k-1]) \cdot p^{k-1}$$这需要`O(k)`每个子串的时间。 

由于大约有`n - k + 1`子串，总复杂度变为：$$O((n-k+1) \cdot k)$$在最坏的情况下，这会变成`O(nk)`，当两者都时太慢`n`和`k`很大。 

### 最优方法，反向滚动哈希

 关键的见解是连续的子字符串哈希是高度相关的。 

我们可以使用滚动哈希在恒定时间内更新先前的哈希，而不是独立地重新计算每个哈希。 

然而，哈希公式使用从左到右递增的幂：$$val(s[i]) \cdot p^0, val(s[i+1]) \cdot p^1, \dots$$这使得正常的从左到右滑动窗口变得不方便。 

诀窍是从右到左处理字符串。 

假设我们在向后移动时维护当前窗口的哈希值。 然后：

 - 在前面添加一个新字符变成乘法`power`- 删除尾随字符会减去其加权贡献

 这将问题转化为干净的滚动哈希更新。 

当我们从右向左移动时：

 - 每个窗口哈希值都可以计算`O(1)`- 总运行时间变为线性

 因为我们从右向左遍历，所以每次找到有效的子字符串时，我们都会覆盖答案索引。 最终存储的索引将自动成为最左边的有效子字符串。

 ## 算法演练

 ### 最优反向滚动哈希算法

 1. 初始化滚动哈希、幂乘数和答案索引的变量。 

滚动哈希在从右向左遍历时存储当前窗口的哈希。 乘数商店`power^k mod modulo`，从窗口中删除字符时需要它。 
2. 预计算`power^k mod modulo`。 

该值表示离开滑动窗口的角色的权重。 我们将在哈希更新期间使用它。 
3. 从右向左遍历字符串。 

我们从末尾开始处理字符，因为哈希定义与向后遍历自然对齐。 
4. 将当前字符添加到滚动哈希中。 

如果当前哈希是：$$H$$然后在前置字符之后`c`，新的哈希值变为：$$(H \cdot power + val(c)) \bmod modulo$$这会将所有现有字符移高一个幂并插入带有指数的新字符`0`。 
5. 删除退出窗口的字符。 

一旦窗口大小超过`k`，我们删除了尾随的字符贡献。 

即将离任的角色贡献：$$val(outgoing) \cdot power^k$$所以我们减去它的模`modulo`。 
6. 当窗口大小正好达到`k`，将滚动哈希与`hashValue`。 

如果匹配，则记录当前的起始索引。 

由于我们向后遍历，因此后面的匹配对应于原始字符串中较早的子字符串。 
7、遍历结束后，返回从记录的index开始的子串，长度为`k`。 

### 为什么它有效

 滚动哈希不变量是在每一步，维护的哈希等于当前长度的哈希 -`k`根据问题定义的窗口。 

从右到左的处理确保每个新添加的字符自然地接收指数`0`，而现有字符通过乘以转换为更高的指数`power`。 

因为每次更新都精确地反映多项式哈希结构，所以每个计算的滚动哈希都是正确的。 由于我们在向左移动时覆盖答案，因此最终记录的子串保证是第一个有效子串。 

## Python 解决方案```python
class Solution:
    def subStrHash(
        self,
        s: str,
        power: int,
        modulo: int,
        k: int,
        hashValue: int
    ) -> str:

        n = len(s)

        current_hash = 0
        power_k = pow(power, k, modulo)

        answer_index = 0

        for i in range(n - 1, -1, -1):

            char_value = ord(s[i]) - ord('a') + 1

            current_hash = (
                current_hash * power + char_value
            ) % modulo

            if i + k < n:
                outgoing_value = ord(s[i + k]) - ord('a') + 1

                current_hash = (
                    current_hash
                    - outgoing_value * power_k
                ) % modulo

            if n - i >= k and current_hash == hashValue:
                answer_index = i

        return s[answer_index:answer_index + k]
```实现首先初始化滚动哈希和预计算`power^k mod modulo`。 

循环从右向左遍历字符串。 使用以下命令将每个新字符插入到滚动哈希中：$$newHash = (oldHash \cdot power + val(c)) \bmod modulo$$这正确地将所有现有权力向上转移。 

一旦窗口超出尺寸`k`，通过减去来删除传出字符：$$val(outgoing) \cdot power^k$$模运算可确保值保持在范围内，并正确处理负的中间结果。 

每当窗口大小变得精确时`k`，该算法将滚动哈希与`hashValue`。 如果它们匹配，则当前索引成为候选答案。 

由于遍历是向后进行的，因此最终存储的索引对应于最左边的有效子串。 

## 解决方案```go
func subStrHash(s string, power int, modulo int, k int, hashValue int) string {
	n := len(s)

	currentHash := 0
	answerIndex := 0

	powerK := 1
	for i := 0; i < k; i++ {
		powerK = (powerK * power) % modulo
	}

	for i := n - 1; i >= 0; i-- {
		charValue := int(s[i]-'a') + 1

		currentHash = (currentHash*power + charValue) % modulo

		if i+k < n {
			outgoingValue := int(s[i+k]-'a') + 1

			currentHash = (
				currentHash -
					(outgoingValue*powerK)%modulo +
					modulo,
			) % modulo
		}

		if n-i >= k && currentHash == hashValue {
			answerIndex = i
		}
	}

	return s[answerIndex : answerIndex+k]
}
```Go 实现遵循与 Python 解决方案相同的逻辑，但需要一些特定于语言的注意事项。 

Go 没有像 Python 那样提供内置的模幂函数`pow(base, exp, mod)`， 所以`power^k mod modulo`使用迭代乘法手动计算。 

Go 的模运算符减法后会产生负结果，因此我们显式添加`modulo`申请之前`% modulo`再次：```go
(currentHash - value + modulo) % modulo
```这保证了哈希值保持非负值。 

Go 中的字符串切片使用字节索引，这里可以正常工作，因为输入仅包含小写英文字母。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`k`等于整个字符串的长度。 在这种情况下，只有一个可能的子字符串，并且滚动哈希必须正确处理单个窗口，而不尝试删除传出字符。 该实现自然会处理这个问题，因为删除条件仅在以下情况下激活：`i + k < n`。 

另一个微妙的情况是多个子字符串产生相同的哈希值。 幼稚的实现可能会返回遇到的最后一个匹配项，而不是第一个匹配项。 由于该解决方案从右向左遍历并在找到匹配项时覆盖答案索引，因此最终记录的索引始终对应于最早的有效子字符串。 

第三个重要情况涉及非常小的模值。 小模数会产生许多哈希冲突，并且还会在减法过程中产生负中间值。 该实现在每次操作后都会仔细地应用模算术，即使减法暂时产生负数也能确保正确性。 

第四种边缘情况涉及`k = 1`。 对于单字符窗口，滚动哈希有效地减少到字符值模`modulo`。 一些滚动哈希实现意外地采用了更大的窗口并错误地处理了删除逻辑。 在这里，相同的统一逻辑适用于所有窗口大小，包括单字符子字符串。
