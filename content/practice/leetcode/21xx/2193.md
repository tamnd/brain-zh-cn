 # LeetCode 2193 - 形成回文的最少移动次数

 ## 问题理解

 这个问题要求我们使用最少数量的相邻交换将给定的字符串转换为回文。 

回文是向前和向后读相同的字符串。 例如，`"abba"`和`"racecar"`是回文。 

唯一允许的操作是交换两个相邻的字符。 每个相邻的交换都算作一次移动。 我们的目标是确定将字符串重新排列成任何有效回文所需的最少移动次数。 

输入是一个字符串`s`仅包含小写英文字母。 该问题保证字符串总是可以重新排列成回文。 这种保证很重要，因为并非每个字符串都可以形成回文。 例如，`"abc"`不能成为回文，因为多个字符具有奇数频率。 

约束条件`1 <= s.length <= 2000`告诉我们几件重要的事情：

 - 绳子相对较小，但并不小。 
- 指数或阶乘的强力解决方案是不可能的。 
- 一个`O(n^2)`解决方案是可以接受的，因为`2000^2 = 4,000,000`，这是可以管理的。 
- 我们应该避免不必要的立方行为。 

有几个重要的边缘情况：

 - 已经是回文的字符串，例如`"abba"`或者`"racecar"`，应该返回`0`。 
- 恰好有一个不匹配的中间字符的字符串，例如`"mamad"`，需要小心处理，因为不匹配的字符最终属于中心。 
- 匹配字符相距较远的字符串可能需要多次交换。 
- 非常短的字符串，例如长度`1`总是要求`0`移动。 

关键的挑战是最大限度地减少相邻交换，同时正确配对从两端向内的匹配字符。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试所有可能的相邻交换序列，直到形成回文，然后返回所有可能性中交换的最小数量。 

一种可能的实现可以在所有可达字符串状态上使用 BFS。 每个状态代表一个字符串配置，每个边代表一个相邻的交换。 

这种方法理论上是正确的，因为 BFS 保证了未加权图中的最短路径。 因此，达到的第一个回文将使用最少的交换次数。 

然而，这种方法是完全不切实际的。 一个长度的字符串`n`最多可以有`n!`排列，每个状态通过交换生成许多相邻状态。 搜索空间呈爆炸式增长。 

即使对于中等长度的字符串，这在计算上也是不可能的。 

### 最优贪婪两指针方法

 关键的见解是我们可以贪婪地从外向内构建回文。 

回文需要在对称位置匹配字符。 因此：

 - 最左边的字符最终必须与右侧的某个相同字符匹配。 
- 如果我们找到匹配的字符，我们可以使用相邻的交换将其移动到位。 
- 所需的交换次数正是其必须行驶的距离。 

我们使用两个指针：

 -`left`从头开始。 
-`right`从最后开始。 

对于每个`left`位置：

 1. 搜索自`right`向后查找匹配的字符。 
2. 如果找到匹配项，则将该字符向`right`使用相邻交换的位置。 
3. 如果不存在匹配项，则位于`left`必须是回文中唯一的中间字符。 我们将其向中心移动一步，稍后再试。 

这种贪婪策略之所以有效，是因为：

 - 首先配对外部字符始终是最佳选择。 
- 相邻交换具有附加成本。 
- 延迟有效的外部配对永远不会减少交换总数。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n! × n) | O(n! × n) | O(n!) | 探索所有可达排列 |
 | 最优贪心二指针 | O(n²) | O(n) | 贪婪地匹配两端的字符 |

 ## 算法演练

 1. 将字符串转换为可变字符数组。 

字符串在 Python 和 Go 中是不可变的，因此使用数组或切片可以使交换更容易。 
2. 初始化两个指针。 

放：

-`left = 0`-`right = n - 1`这些指针代表我们想要匹配的当前外部位置。 
3. 搜索匹配的字符。 

开始于`right`，向后移动直到找到等于的字符`chars[left]`。 

这会识别当前左侧角色的最佳匹配伙伴。 
4. 处理不匹配的中间字符大小写。 

如果搜索达到`left`本身，右侧不存在匹配字符。 

这意味着当前字符必须成为回文的中心字符。 

由于它属于中间，因此将其向右交换一位并将移动计数加一。 

暂时不要移动指针，因为该字符尚未处于其最终位置。 
5. 将匹配的字符移动到位。 

如果在位置找到匹配项`matchIndex`，反复与下一个字符交换，直到到达位置`right`。 

每个相邻的交换花费一次移动。 
6. 将这对锁定到位。 

一旦匹配字符到达位置`right`，我们成功地形成了一对对称对。 

增量`left`并减少`right`。 
7. 继续，直到指针相遇。 

什么时候`left >= right`，回文就完成了。 
8. 返回总移动次数。 

### 为什么它有效

 该算法保持了每个已处理的外部对已经处于其最佳最终位置的不变性。 

在每一步中，我们都会贪婪地将最左边的不匹配字符与右侧最近的有效匹配字符配对。 任何有效的回文最终都必须以某种方式将这些字符配对，并且将所选匹配直接移动到位可以最大限度地减少所需的相邻交换。 

如果不存在匹配，则该角色一定是唯一的中心角色，因此逐渐向内移动是不可避免的。 

由于每个操作都是局部最优的，并且不会中断之前完成的对，因此交换总数是全局最小的。 

## Python 解决方案```python
class Solution:
    def minMovesToMakePalindrome(self, s: str) -> int:
        chars = list(s)
        left = 0
        right = len(chars) - 1
        moves = 0

        while left < right:
            match_index = right

            while match_index > left and chars[match_index] != chars[left]:
                match_index -= 1

            if match_index == left:
                chars[left], chars[left + 1] = chars[left + 1], chars[left]
                moves += 1
            else:
                while match_index < right:
                    chars[match_index], chars[match_index + 1] = (
                        chars[match_index + 1],
                        chars[match_index],
                    )
                    moves += 1
                    match_index += 1

                left += 1
                right -= 1

        return moves
```其实现紧密遵循贪婪两指针策略。 

我们首先将字符串转换为字符列表，因为列表有效地支持就地交换。 

这`left`和`right`指针跟踪我们想要匹配的当前位置。 对于每次迭代，我们向后搜索`right`找到匹配的字符`chars[left]`。 

如果不存在匹配字符，则当前字符必须成为回文的中间字符。 我们通过与邻居交换它来将其向中心移动一步。 

如果存在匹配，我们会重复执行相邻交换，以将匹配字符冒泡到正确的位置`right`位置。 每次交换都会增加移动计数器。 

一旦这对固定下来，我们就向内移动并重复这个过程。 

最终形成所有对，并返回总移动计数。 

## 解决方案```go
func minMovesToMakePalindrome(s string) int {
	chars := []byte(s)

	left := 0
	right := len(chars) - 1
	moves := 0

	for left < right {
		matchIndex := right

		for matchIndex > left && chars[matchIndex] != chars[left] {
			matchIndex--
		}

		if matchIndex == left {
			chars[left], chars[left+1] = chars[left+1], chars[left]
			moves++
		} else {
			for matchIndex < right {
				chars[matchIndex], chars[matchIndex+1] =
					chars[matchIndex+1], chars[matchIndex]

				moves++
				matchIndex++
			}

			left++
			right--
		}
	}

	return moves
}
```Go 实现与 Python 版本几乎相同。 

我们不使用 Python 列表，而是使用`[]byte`切片是因为 Go 字符串是不可变的。 对于小写英文字母来说，直接交换字节是高效且自然的。 

Go 在这里不需要对整数溢出进行特殊处理，因为最大交换次数完全在标准整数的范围内。 

交换逻辑和指针移动与 Python 中完全相同。

 ## 边缘情况

 ### 单字符串

 长度为 1 的字符串已经是回文，因为它在两个方向上读取相同。 当尝试搜索匹配字符时，幼稚的实现可能会意外地执行不必要的操作或产生索引错误。 

这个实现自然地处理这种情况，因为循环条件`left < right`立即为假。 

### 独特的中间角色

 奇数长度回文仅包含一个频率为奇数的字符。 例如，在`"mamad"`, 字符`'d'`最终必须占据中心位置。 

这是错误的常见来源，因为找不到该角色的匹配伙伴。 当向后搜索达到时，实现会检测到这种情况`left`本身。 该算法不会强迫一对不存在的字符，而是将字符朝中心一步交换。 

### 已经是回文字符串

 字符串像`"abba"`或者`"racecar"`应该返回零步。 

即使配对已经匹配，一些不正确的贪婪实现也会继续执行不必要的交换。 此实现避免了该问题，因为匹配的字符会立即被接受而无需额外的工作，并且指针只是向内移动。
