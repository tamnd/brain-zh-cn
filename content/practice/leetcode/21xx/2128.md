[LeetCode 问题 2128](https://leetcode.com/problems/remove-all-ones-with-row-and-column-flips/)

 **难度：** 🟡 中等
 **主题：** 数组、数学、位操作、矩阵

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个`m x n`二进制矩阵命名为`grid`，其中每个单元格包含`0`或者`1`。 我们可以执行两种操作：

 1. 翻转整行
 2. 翻转整列

 翻转意味着改变每一个`0`进入`1`和每一个`1`进入`0`。 

我们的目标是确定在执行任意次数的行和列翻转后是否可以将整个矩阵转换为全零。 

一个非常重要的细节是行和列翻转可以以任何顺序和任意次数应用。 由于翻转同一行或列两次会取消该效果，因此每行和每列实际上只有两种状态：翻转或未翻转。 

限制条件是：

 -`1 <= m, n <= 300`- 每个单元格要么`0`或者`1`由于矩阵最多可以包含`300 x 300 = 90,000`对于细胞来说，对所有翻转组合进行指数探索是完全不可行的。 我们需要一个大致在多项式时间内运行的解决方案。 

关键的挑战是了解哪些类型的矩阵实际上可以转换为全零。 某些矩阵具有隐藏的一致性属性，使之成为可能，而其他矩阵则无论翻转顺序如何，从根本上都无法修复。 

一些边缘情况很重要：

 - 已经包含全零的矩阵应立即返回`true`- 单单元矩阵总是有效，因为我们可以根据需要翻转它的行或列
 - 某些行与第一行部分匹配且部分不同的矩阵无法求解
 - 必须正确处理矩形矩阵，而不仅仅是方阵

 ## 方法

 ### 蛮力方法

 强力解决方案将尝试行翻转和列翻转的所有可能组合。 

有`m`行和`n`列。 每一项都可以翻转或不翻转，因此有：$$2^m \times 2^n = 2^{m+n}$$可能的测试状态。 

对于每种组合，我们都会模拟所有翻转并检查最终矩阵是否仅包含零。 

这种方法是正确的，因为它详尽地探索了每个可能的操作序列。 如果存在有效的配置，暴力破解最终会找到它。 

然而，这种方法太慢了。 和`m = n = 300`，组合的数量变得天文数字：$$2^{600}$$这是完全不可行的。 

### 关键见解

 重要的观察是每一行必须是：

 - 完全等于第一行
 - 与第一行正好相反

 为什么？ 

假设我们决定翻转哪些列，以便第一行变为全零。 

对于每一列：

 - 如果`grid[0][j] == 1`，我们翻转列`j`- 否则，我们不会翻转它

 这些列翻转后，每一行都会根据其与第一行的关系进行变换。 

如果另一行与第一行相同，则它也变为全零。 

如果另一行是第一行的按位反转，则它变为全 1，然后单行翻转将其转换为全 0。 

但是，如果一行在某些位置与第一行不同而在其他位置匹配，则在列翻转后，它会变成包含零和一的混合行。 单行翻转无法解决这个问题。 

因此，每一行都必须满足以下条件之一：$$grid[i][j] = grid[0][j]$$对于所有列，或者$$grid[i][j] \ne grid[0][j]$$对于所有列。 

这导致了一个非常干净的线性时间解决方案。

 ## 算法演练

 1. 将第一行存储为参考模式。 

整个矩阵的可行性取决于其他每一行与该行的关系。 
2. 迭代剩余的每一行。 

对于每一行，判断它是否是：

 - 与第一行相同，或者
 - 第一行的精确倒数
 3. 将当前行中的每个元素与第一行中的相应元素进行比较。 

当前行和第一行之间的关系必须在整行中保持一致。 
4. 使用第一列确定预期的关系。 

如果：$$grid[i][0] == grid[0][0]$$那么整行必须与第一行匹配。 

否则，整行必须相对于第一行反转。 
5. 对于每一列`j`，验证一致性。 

必须满足以下条件：$$grid[i][j] \oplus grid[i][0] = grid[0][j] \oplus grid[0][0]$$该表达式检查是否保留了相等或不等关系。 
6、如发现不符，立即返回`false`。 

这意味着该行相对于第一行既不相同也不倒置。 
7. 如果所有行都满足条件，则返回`true`。 

### 为什么它有效

 该算法之所以有效，是因为列翻转对每一行的影响均等。 一旦我们决定如何将第一行转换为全零，其他所有行都将完全确定。 

与第一行匹配的行在同一列翻转后变为全零。 

与第一行相反的行变为全 1，然后可以通过一次行翻转来修复。 

任何部分匹配和部分反转的行都会成为混合行，无法通过单行翻转将其转换为全零。 因此，这样的矩阵是不可能的。 

## Python 解决方案```python
from typing import List

class Solution:
    def removeOnes(self, grid: List[List[int]]) -> bool:
        rows = len(grid)
        cols = len(grid[0])

        for row in range(rows):
            for col in range(cols):
                if (
                    grid[row][col] ^ grid[row][0]
                ) != (
                    grid[0][col] ^ grid[0][0]
                ):
                    return False

        return True
```实现直接遵循算法的数学观察。 

外循环遍历每一行，而内循环检查每一列。 

异或表达式：```python
grid[row][col] ^ grid[row][0]
```捕获当前单元格是否与其行的第一个元素匹配。 

相似地：```python
grid[0][col] ^ grid[0][0]
```捕获第一行中的相应元素是否与第一行的第一个元素匹配。 

如果这些关系不同，则当前行相对于第一行既不相同也不倒置，因此无法求解矩阵。 

算法立即返回`False`当发现此类违规行为时。 否则，在检查所有单元格后，它返回`True`。 

## 解决方案```go
func removeOnes(grid [][]int) bool {
    rows := len(grid)
    cols := len(grid[0])

    for row := 0; row < rows; row++ {
        for col := 0; col < cols; col++ {
            if (grid[row][col]^grid[row][0]) !=
                (grid[0][col]^grid[0][0]) {
                return false
            }
        }
    }

    return true
}
```Go 实现与 Python 版本几乎相同。 

Go 使用`^`类似于 Python 的按位异或运算符。 由于所有值都是二进制的 (`0`或者`1`)，XOR 清楚地表达了两个值是否相等或不同。 

不需要对整数溢出进行特殊处理，因为所有操作仅涉及小整数。 该矩阵使用切片的切片来表示，这自然支持矩形维度。

 ## 边缘情况

 一个重要的边缘情况是仅包含单个单元格的矩阵。 幼稚的实现可能会使逻辑过于复杂，或者意外地假设至少存在两行或两列。 事实上，两者`[[0]]`和`[[1]]`总是可以解决的，因为我们要么什么都不做，要么翻转行或列一次。 该实现自然地处理了这个问题，因为 XOR 比较对于`1 x 1`矩阵。 

另一个重要的边缘情况是只有一行或只有一列的矩阵。 在这些情况下，每种配置都是可解的，因为各个列或行始终可以独立翻转以消除所有配置。 执行正确返回`True`因为每一行都与第一行基本相同或相反。 

当一行与第一行部分匹配且部分不同于第一行时，会出现特别棘手的边缘情况。 例如：```
[
    [1,0,1],
    [1,1,0]
]
```第二行相对于第一行既不相同也不完全颠倒。 在进行任何序列的列翻转之后，该行仍将包含零和一的混合，因此不可能通过单行翻转消除所有的。 XOR 一致性检查会立即检测到这一点。 

另一个微妙的边缘情况涉及多行中的重复模式。 一些不正确的解决方案尝试贪婪地翻转行或列，并且可能意外地依赖于操作顺序。 这里使用的数学不变量完全避免了这个问题，因为它检查决定可解性的结构属性，独立于任何特定的翻转序列。
