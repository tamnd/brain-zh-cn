[LeetCode 问题 2124](https://leetcode.com/problems/check-if-all-as-appears-before-all-bs/)

 **难度：** 🟢简单
 **主题：** 字符串

 ## 解决方案

 ## 问题理解

 问题给了我们一个字符串`s`仅包含两个可能的字符，`'a'`和`'b'`。 我们必须确定是否每个`'a'`出现在每个之前`'b'`。 

另一种思考需求的方式是：一旦我们遇到`'b'`，我们永远不应该看到另一个`'a'`稍后在字符串中。 如果一个`'a'`出现在 a 之后`'b'`，违反了排序规则，答案必须是`false`。 

例如：

-`"aaabbb"`是有效的，因为所有`'a'`字符先行，然后是所有字符`'b'`人物。 
-`"abab"`无效，因为看到后`'b'`在索引 1 处，我们稍后遇到另一个`'a'`在索引 2 处。 
-`"bbb"`有效，因为没有`'a'`根本没有字符，所以条件基本满足。 

限制非常小：

 -`1 <= s.length <= 100`- 该字符串仅包含`'a'`和`'b'`由于输入大小很小，几乎任何简单的解决方案都可以高效运行。 尽管如此，设计一个干净的线性时间算法还是很有用的。 

重要的边缘情况包括：

 - 字符串仅包含`'a'`- 字符串仅包含`'b'`- 单字符字符串
 - 过渡自`'a'`到`'b'`恰好一次，有效
 - 任何情况的发生`'a'`经过一个`'b'`，它必须立即失败

 ## 方法

 ### 蛮力方法

 暴力解决方案检查字符串中的每一对位置。 对于每个`'b'`，我们扫描所有后面的字符以验证它们都不是`'a'`。 

例如，如果我们位于索引处`i`和`s[i] == 'b'`，我们检查每一个`j > i`。 如果我们有一天发现`s[j] == 'a'`，我们返回`false`。 

这种做法是正确的，因为它直接验证了问题的定义。 但是，它会重复扫描字符串的重叠部分，从而导致效率低下。 

尽管约束足够小，仍然可以通过，但我们可以通过一次传递做得更好。 

### 最佳方法

 关键的观察是，当且仅当我们从未遇到过字符串时，该字符串才是有效的`'a'`看到一个`'b'`。 

我们可以从左到右扫描一次字符串，同时维护一个布尔标志，指示是否`'b'`已经出现了。 

- 如果我们看到`'b'`，我们设置了标志。 
- 如果我们稍后看到`'a'`虽然标志已经设置，但排序无效，我们返回`false`。 

如果我们在没有违反规则的情况下完成扫描，我们返回`true`。 

这在线性时间内工作并使用恒定的额外空间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 检查每个`'b'`反对所有后来的角色|
 | 最佳| O(n) | O(1) | O(1) | 带标志的单次从左到右扫描 |

 ## 算法演练

 1. 初始化一个名为的布尔变量`seen_b`作为`False`。 

这个变量跟踪我们是否已经遇到过`'b'`扫描字符串时。 
2. 从左到右遍历字符串。 

我们按顺序处理每个字符，因为问题取决于相对顺序。 
3. 如果当前字符是`'b'`， 放`seen_b = True`。 

一次`'b'`出现后，每个剩余的字符也必须是`'b'`。 
4. 如果当前字符是`'a'`和`seen_b`已经是`True`， 返回`False`。 

这意味着`'a'`出现后`'b'`，违反了所需的顺序。 
5. 如果循环完成没有返回`False`， 返回`True`。 

这意味着没有发现无效的排序。 

### 为什么它有效

 该算法在遇到第一个之前保持不变`'b'`， 两个都`'a'`和`'b'`是可以接受的。 然而，在遇到一个`'b'`，仅附加`'b'`允许使用字符。 此刻`'a'`出现在 a 之后`'b'`，违反了条件。 由于该算法对每个字符都检查此规则一次，因此它可以正确确定字符串是否满足所需的排序。 

## Python 解决方案```python
class Solution:
    def checkString(self, s: str) -> bool:
        seen_b = False

        for char in s:
            if char == 'b':
                seen_b = True
            elif seen_b:
                return False

        return True
```该实现遵循算法演练中的确切逻辑。 

变量`seen_b`记录是否`'b'`已经出现在扫描中。 我们遍历字符串中的每个字符：

 - 如果角色是`'b'`，我们更新标志。 
- 如果角色是`'a'`尽管`seen_b`已经是`True`，我们立即返回`False`。 

如果循环结束时未发现无效排序，则函数返回`True`。 

此实现简洁、易于阅读并且最适合该问题。 

## 解决方案```go
func checkString(s string) bool {
    seenB := false

    for _, ch := range s {
        if ch == 'b' {
            seenB = true
        } else if seenB {
            return false
        }
    }

    return true
}
```Go 的实现与 Python 解决方案非常相似。 

变量`seenB`跟踪是否`'b'`已经出现了。 该循环使用 Go 的字符串迭代`range`句法。 由于字符串仅包含 ASCII 字符，因此处理符文值非常简单。 

不需要对空字符串进行特殊处理，因为约束保证字符串长度至少为 1。

 ## 边缘情况

 一个重要的边缘情况是只包含`'a'`字符，例如`"aaa"`。 有缺陷的实现可能会错误地期望至少一个`'b'`出现。 事实上，条件是满足的，因为没有`'b'`违反顺序的字符。 该算法自然地处理这个问题，因为`seen_b`永远不会成为`True`。 

另一个重要的情况是一个字符串只包含`'b'`字符，例如`"bbb"`。 由于没有`'a'`任何之后的字符`'b'`，该字符串有效。 实现正确地处理了这个问题，因为看到了额外的`'b'`角色永远不会触发失败。 

一个特别棘手的边缘情况是当字符串切换回`'a'`经过一个`'b'`， 例如`"abaa"`或者`"ba"`。 这正是算法旨在检测的无效条件。 一次`seen_b`变成`True`, 稍后`'a'`立即导致函数返回`False`。 

最终的边缘情况是可能的最小输入大小，例如`"a"`或者`"b"`。 由于约束允许长度为 1 的字符串，因此算法必须正确处理这些最小输入。 即使循环只执行一次，单遍扫描也能正常工作。
