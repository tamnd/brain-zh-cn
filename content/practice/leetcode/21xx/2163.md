[LeetCode 问题 2163](https://leetcode.com/problems/minimum-difference-in-sums-after-removal-of-elements/)

 **难度：** 🔴难
 **主题：** 数组、动态规划、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 该数组恰好包含`3 * n`元素。 我们必须准确地删除`n`元素，离开`2 * n`后面的元素。 其余元素保持其原始相对顺序，因为我们正在删除子序列，而不是重新排列数组。 

去除后剩余的`2 * n`元素被分成两个连续的组：

 - 第一个`n`其余元素有助于`sumfirst`- 下一个`n`其余元素有助于`sumsecond`我们的目标是尽量减少：$$sumfirst - sumsecond$$这意味着我们希望前半部分尽可能小，后半部分尽可能大。 

一个非常重要的观察结果是，两组之间的分割发生在原始数组的中间部分的某个位置。 第一组必须来自数组的左侧，而第二组必须来自右侧。 

限制条件很大：

 -`n`可以大到`10^5`- 因此总数组大小可以达到`3 * 10^5`这立即告诉我们指数或二次解是不可能的。 我们需要一些接近的东西`O(n log n)`。 

另一个重要的细节是所有数字都是正数。 这会影响我们如何推理最小化和最大化总和。 

几种边缘情况很容易破坏简单的实现：

 - 非常小的阵列，例如`n = 1`- 所有值都相等的数组
 - 严格增加或减少数组
 - 最佳移除涉及左侧和右侧部分的元素的情况
 - 在某些语言中，大值可能会溢出 32 位整数

 该问题保证：

 - 数组长度总是能被3整除
 - 每个元素都是积极的
 - 有效的删除始终存在

 ## 方法

 ### 蛮力方法

 强力解决方案将尝试所有可能的大小子序列`n`删除。 

删除这些元素后，我们将：

 1.构造剩余数组
 2.将其分成相等的两半
 3. 计算差异
 4. 追踪最小结果

 这是有效的，因为它详尽地探索了每一个有效的删除。 

然而可供选择的方式有很多`n`元素来自`3n`元素是：$$\binom{3n}{n}$$这会呈指数增长，即使对于中等值也变得完全不可行`n`。 

例如，当`n = 20`，可能性的数量已经是巨大的。 

### 关键见解

 与其直接考虑删除的元素，不如考虑保留哪些元素更容易。 

假设我们选择一个分割点`i`。 

- 第一组`n`元素必须从前缀中选择`nums[0...i]`- 第二组`n`元素必须从后缀中选择`nums[i+1...]`最小化：$$sumfirst - sumsecond$$我们需要：

 - The minimum possible sum of`n`前缀中的元素
 - 最大可能的总和`n`后缀中的元素

 这自然表明基于堆的优化。 

我们预先计算：

 -`leftMin[i]`= 最小可能总和`n`元素选自`nums[0...i]`-`rightMax[i]`= 最大可能总和`n`元素选自`nums[i...end]`然后可以在恒定时间内评估每个有效的分割：$$leftMin[i] - rightMax[i+1]$$挑战在于有效维护：

 - 最小的`n`到目前为止看到的元素
 - 最大的`n`到目前为止看到的元素

 堆非常适合于此。

 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 尝试每个删除子序列 |
 | 最佳| O(n log n) | O(n log n) | O(n) | 使用堆来维护最佳前缀和后缀总和 |

 ## 算法演练

 1.让`m = len(nums)`和`n = m // 3`。 

我们将构建两个数组：

 -`leftMin`-`rightMax`2. 计算`leftMin`。 

我们从左到右扫描，同时保持最小的可能总和`n`元素。 

我们使用最大堆是因为我们想保留最小的`n`数字。 

逻辑是：

 - 将每个数字添加到堆中
 - 将其添加到运行总和中
 - 如果堆大小超过`n`, 去掉最大的元素
 - 一旦堆大小变得精确`n`，记录总和

 堆总是包含最小的`n`到目前为止遇到的值。 
3. 计算`rightMax`。 

我们从右向左扫描，同时保持最大可能的精确总和`n`元素。 

我们使用最小堆是因为我们想保留最大的堆`n`数字。 

逻辑是：

 - 将每个数字添加到堆中
 - 将其添加到运行总和中
 - 如果堆大小超过`n`, 删除最小的元素
 - 一旦堆大小变得精确`n`，记录总和

 堆总是包含最大的`n`到目前为止遇到的值。 
4. 尝试每个有效的分割点。 

上半部分必须在索引之间的某个位置结束：$$n - 1 \text{ through } 2n - 1$$对于每个分割：

 - 上半场使用`leftMin[i]`- 下半场使用`rightMax[i + 1]`计算：$$leftMin[i] - rightMax[i+1]$$跟踪最小值。 
5. 返回最小差异。 

### 为什么它有效

 对于每个可能的分割位置，算法独立计算：

 - 左侧可达到的最小总和
 - 右侧可达到的最大金额

 因为这些对于该拆分来说是最佳的，所以它们的差异对于该拆分也是最佳的。 评估所有有效的分割可以保证我们找到全局最小差异。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def minimumDifference(self, nums: List[int]) -> int:
        total_length = len(nums)
        n = total_length // 3

        left_min = [0] * total_length
        right_max = [0] * total_length

        # Compute minimum sums for prefixes
        max_heap = []
        current_sum = 0

        for i in range(total_length):
            value = nums[i]

            heapq.heappush(max_heap, -value)
            current_sum += value

            if len(max_heap) > n:
                removed = -heapq.heappop(max_heap)
                current_sum -= removed

            if len(max_heap) == n:
                left_min[i] = current_sum

        # Compute maximum sums for suffixes
        min_heap = []
        current_sum = 0

        for i in range(total_length - 1, -1, -1):
            value = nums[i]

            heapq.heappush(min_heap, value)
            current_sum += value

            if len(min_heap) > n:
                removed = heapq.heappop(min_heap)
                current_sum -= removed

            if len(min_heap) == n:
                right_max[i] = current_sum

        answer = float("inf")

        for i in range(n - 1, 2 * n):
            difference = left_min[i] - right_max[i + 1]
            answer = min(answer, difference)

        return answer
```该实现紧密遵循前面描述的算法。 

第一个循环计算`left_min`。 在 Python 中使用负值模拟最大堆，因为 Python 的`heapq`只提供最小堆。 每一步，堆都存储最小的`n`来自前缀的值。 

第二个循环计算`right_max`。 这里我们使用普通的最小堆。 每当堆超过大小时`n`，我们删除最小值，以便堆始终包含最大的值`n`来自后缀的值。 

最后，我们迭代所有合法的分割位置并计算最佳左总和与最佳右总和之间的差异。 

## 解决方案```go
package main

import (
	"container/heap"
	"math"
)

type MaxHeap []int

func (h MaxHeap) Len() int {
	return len(h)
}

func (h MaxHeap) Less(i, j int) bool {
	return h[i] > h[j]
}

func (h MaxHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MaxHeap) Push(x interface{}) {
	*h = append(*h, x.(int))
}

func (h *MaxHeap) Pop() interface{} {
	old := *h
	n := len(old)
	value := old[n-1]
	*h = old[:n-1]
	return value
}

type MinHeap []int

func (h MinHeap) Len() int {
	return len(h)
}

func (h MinHeap) Less(i, j int) bool {
	return h[i] < h[j]
}

func (h MinHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MinHeap) Push(x interface{}) {
	*h = append(*h, x.(int))
}

func (h *MinHeap) Pop() interface{} {
	old := *h
	n := len(old)
	value := old[n-1]
	*h = old[:n-1]
	return value
}

func minimumDifference(nums []int) int64 {
	totalLength := len(nums)
	n := totalLength / 3

	leftMin := make([]int64, totalLength)
	rightMax := make([]int64, totalLength)

	maxHeap := &MaxHeap{}
	heap.Init(maxHeap)

	var currentSum int64 = 0

	for i := 0; i < totalLength; i++ {
		value := nums[i]

		heap.Push(maxHeap, value)
		currentSum += int64(value)

		if maxHeap.Len() > n {
			removed := heap.Pop(maxHeap).(int)
			currentSum -= int64(removed)
		}

		if maxHeap.Len() == n {
			leftMin[i] = currentSum
		}
	}

	minHeap := &MinHeap{}
	heap.Init(minHeap)

	currentSum = 0

	for i := totalLength - 1; i >= 0; i-- {
		value := nums[i]

		heap.Push(minHeap, value)
		currentSum += int64(value)

		if minHeap.Len() > n {
			removed := heap.Pop(minHeap).(int)
			currentSum -= int64(removed)
		}

		if minHeap.Len() == n {
			rightMax[i] = currentSum
		}
	}

	answer := int64(math.MaxInt64)

	for i := n - 1; i < 2*n; i++ {
		difference := leftMin[i] - rightMax[i+1]

		if difference < answer {
			answer = difference
		}
	}

	return answer
}
```Go 实现使用自定义堆类型，因为 Go 的`container/heap`包需要显式的接口实现。 

与 Python 不同，Go 不支持自动大整数，因此我们使用`int64`所有总和和最终答案以避免溢出。 

其余逻辑完全反映了 Python 解决方案。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`n = 1`。 在这种情况下，数组只包含三个元素，我们正好删除一个。 有缺陷的实现可能会错误地处理分割边界，因为剩余的每一半中只有一个有效元素。 该算法自然地处理了这个问题，因为有效的分割范围变得非常小，并且堆逻辑仍然正常工作。 

另一个重要的情况是所有值都相同。 在这样的数组中，每次可能的删除都会产生相同的总和。 一些贪婪方法意外地依赖于严格的不等式，并且可能会在重复时表现不正确。 由于基于堆的解决方案始终准确地保持`n`无论元素是否重复，它都会安全地处理重复值。 

第三个关键边缘情况是极大的元素值。 由于每个数都可以达到`10^5`并且最多可以有`3 * 10^5`元素，总和可能变得非常大。 在 Go 中，使用标准`int`不小心可能会在某些系统上溢出。 因此，该实现使用`int64`所有金额和最终答案。 

当最佳删除同时使用数组左右部分的元素时，会发生另一种微妙的情况。 幼稚的方法可能会错误地假设删除的元素形成一个连续的块。 基于堆的解决方案不会做出这种假设，因为它独立评估所有有效的前缀和后缀组合。
