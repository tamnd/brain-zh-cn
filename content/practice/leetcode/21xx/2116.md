[LeetCode 问题 2116](https://leetcode.com/problems/check-if-a-parentheses-string-can-be-valid/)

 **难度：** 🟡 中等
 **主题：** 字符串、堆栈、贪婪

 ## 解决方案

 ## 问题理解

 该问题询问给定的括号字符串在一定的约束下是否可以转换为有效的括号序列。 

我们有两个字符串：

 -`s`，仅包含`'('`和`')'`-`locked`，仅包含`'0'`和`'1'`两个字符串的长度相同`n`。 

在每个索引处：

 - 如果`locked[i] == '1'`， 然后`s[i]`是固定的，不能改变。 
- 如果`locked[i] == '0'`， 然后`s[i]`是灵活的，可以成为`'('`或者`')'`。 

目标是确定我们是否可以为所有未锁定的位置赋值，以便最终的字符串成为有效的括号字符串。 

有效的括号字符串必须满足两个重要条件：

 1. 左括号和右括号的总数必须相等。 
2. 从左向右扫描时，右括号不得超过左括号。 

例如：

-`"()"`是有效的。 
-`"(())"`是有效的。 
-`"(()"`无效，因为一个左括号不匹配。 
-`")("`无效，因为字符串以右括号开头。 

约束条件很重要：

 -`n`可以大到`10^5`- 这立即排除了指数或大量回溯解决方案。 
- 我们需要一个接近的算法`O(n)`时间。 

有几个重要的边缘情况：

 - 如果长度为奇数，则自动给出答案`false`，因为有效的括号字符串必须包含相同数量的`'('`和`')'`。 
- 开头附近有许多锁定右括号的字符串可能会立即失败。 
- 靠近末尾处有许多锁定左括号的字符串也可能会失败。 
- 当长度为偶数时，完全解锁的字符串总是可解的。 
- 仅从左到右扫描的天真的贪婪策略是不够的，因为我们还必须确保字符串后面存在足够的右括号。 

核心挑战是在尊重锁定位置的同时平衡灵活性。 

## 方法

 ### 蛮力方法

 蛮力方法会尝试所有可能的分配来解锁位置。 

假设有`k`解锁索引。 每个解锁的角色都可以独立成为`'('`或者`')'`，所以有：$2^k$可能要测试的字符串。 

对于每个生成的字符串，我们可以使用标准堆栈或计数器方法验证它是否形成合法的括号序列。 

这种方法是正确的，因为它探索了每种可能的配置。 如果存在任何有效的配置，暴力破解最终会找到它。 

然而，这在计算上是不可行的。 

在最坏的情况下：

 -`k = n`-`n = 10^5`这导致指数级的复杂性，在时间限制内不可能执行。 

### 最优贪心法

 关键的观察是我们不需要显式构造最终的字符串。 

相反，我们只需要确定是否可以进行有效的分配。 

有效的括号字符串有两个方向要求：

 1. 从左到右扫描时，我们不能有太多`')'`。 
2. 从右向左扫描时，我们不能有太多`'('`。 

解锁的字符很灵活，可以暂时补偿我们当前需要的任何括号类型。 

这导致使用两次传递的贪婪验证策略：

 - 从左到右传递确保存在足够的左括号。 
- 从右到左传递确保存在足够的右括号。 

如果两次传递都成功，则存在有效的分配。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(2^k × n) | O(2^k × n) | O(n) | 尝试解锁位置的每项任务 |
 | 最佳| O(n) | O(1) | O(1) | 使用两次贪婪扫描来验证可行性 |

 ## 算法演练

 ### 第 1 步：检查字符串长度

 有效的括号字符串必须包含相同数量的左括号和右括号。 

因此，总长度必须是偶数。 

如果`n`为奇数，立即返回`false`。 

### 步骤 2：从左到右验证

 我们从左到右扫描并跟踪有多少个左括号可能可用。 

我们维护一个名为`balance`。 

在每个索引处：

 - 如果角色已解锁（`locked[i] == '0'`），我们将其视为潜在的`'('`。 
- 如果角色已被锁定`'('`，有积极贡献。 
- 否则，它是一个锁定的`')'`，它消耗一个可用的左括号。 

更新规则变为：

 - 灵活或`'('`→`balance += 1`- 锁定`')'`→`balance -= 1`如果`balance`一旦变成负数，那么在存在足够的空位之前就有太多的右括号。 

在这种情况下，返回`false`。 

### 步骤 3：从右到左验证

 现在我们从右到左执行对称检查。 

这次我们确保可以存在足够的右括号。 

再次维护一个名为`balance`。 

在每个索引处：

 - 如果角色已解锁，则将其视为潜在角色`')'`。 
- 如果角色已被锁定`')'`，有积极贡献。 
- 否则，它是一个锁定的`'('`，它消耗一个可用的右括号。 

更新规则变为：

 - 灵活或`')'`→`balance += 1`- 锁定`'('`→`balance -= 1`如果`balance`变成负数，左括号太多，后面无法匹配。 

返回`false`。 

### 第 4 步：返回 True

 如果两个方向检查都成功，则存在有效分配。 

返回`true`。 

### 为什么它有效

 该算法保持可行性不变量。 

在从左到右扫描期间，我们保证每个前缀都可能包含足够的左括号来平衡所有遇到的右括号。 

在从右到左扫描期间，我们保证每个后缀都可能包含足够的右括号来平衡所有遇到的左括号。 

如果两个条件同时成立，则至少存在一个满足有效括号字符串规则的灵活位置分配。 

## Python 解决方案```python
class Solution:
    def canBeValid(self, s: str, locked: str) -> bool:
        n = len(s)

        # Valid parentheses strings must have even length
        if n % 2 == 1:
            return False

        # Left-to-right pass
        balance = 0

        for i in range(n):
            if locked[i] == '0' or s[i] == '(':
                balance += 1
            else:
                balance -= 1

            if balance < 0:
                return False

        # Right-to-left pass
        balance = 0

        for i in range(n - 1, -1, -1):
            if locked[i] == '0' or s[i] == ')':
                balance += 1
            else:
                balance -= 1

            if balance < 0:
                return False

        return True
```实现从奇偶校验开始，因为奇数长度的字符串永远不会变得有效。 

第一个循环执行从左到右的验证。 灵活的角色被乐观地视为`'('`因为左括号有助于防止右括号导致的过早不平衡。 

每当锁定时`')'`出现后，余额会减少，因为它必须消耗先前可用的左括号。 

如果余额变为负数，则任何分配都无法修复无效前缀。 

第二个循环反映了相反的逻辑。 灵活职位现在被视为`')'`因为我们要确保所有左括号都存在足够的右括号。 

如果任一扫描失败，该函数立即返回`False`。 

如果两次扫描均成功完成，则可以将字符串转换为有效的括号序列。 

## 解决方案```go
func canBeValid(s string, locked string) bool {
	n := len(s)

	// Valid parentheses strings must have even length
	if n%2 == 1 {
		return false
	}

	// Left-to-right pass
	balance := 0

	for i := 0; i < n; i++ {
		if locked[i] == '0' || s[i] == '(' {
			balance++
		} else {
			balance--
		}

		if balance < 0 {
			return false
		}
	}

	// Right-to-left pass
	balance = 0

	for i := n - 1; i >= 0; i-- {
		if locked[i] == '0' || s[i] == ')' {
			balance++
		} else {
			balance--
		}

		if balance < 0 {
			return false
		}
	}

	return true
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

Go 中的字符串是可字节索引的，因此访问`s[i]`和`locked[i]`效率很高，因为输入仅包含 ASCII 字符。 

不需要额外的数据结构，因此该实现保持恒定的辅助空间使用。

 ## 边缘情况

 ### 奇数长度字符串

 有效的括号字符串必须包含相同数量的左括号和右括号。 因此，它的总长度必须始终是偶数。 

这是错误的常见来源，因为开发人员可能会不必要地开始复杂的验证逻辑。 

实现立即处理这个问题：```
if n % 2 == 1:
    return False
```这可以防止浪费计算并保证正确性。 

### 过多的右括号过早

 考虑：```
s = "))(("
locked = "1100"
```前两个字符被锁定在右括号中。 

尽管后面的位置很灵活，但没有有效的赋值可以修复无效的前缀，因为有效的括号字符串永远不能以不匹配的开头`')'`。 

当余额变为负数时，从左到右的扫描会捕捉到这一点。 

### 迟到的左括号过多

 考虑：```
s = "(()("
locked = "1111"
```前缀结构在正向扫描期间显得有效，但最后的左括号永远无法匹配。 

简单的单遍解决方案会错误地接受这种情况。 

反向扫描通过确保每个后缀中存在足够的右括号来防止此错误。 

### 完全灵活的弦

 考虑：```
s = "))))"
locked = "0000"
```尽管原始字符串看起来无效，但每个位置都是可变的。 

该算法正确地识别出可以重新分配灵活位置以形成`"()()"`或者`"(())"`。 

这说明了为什么我们必须推理可能性而不是当前的文字字符。
