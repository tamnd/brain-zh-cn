[LeetCode 问题 2106](https://leetcode.com/problems/maximum-fruits-harvested-after-at-most-k-steps/)

 **难度：** 🔴难
 **主题：** 数组、二分查找、滑动窗口、前缀和

 ## 解决方案

 ## 问题理解

 在这个问题中，我们给出了放置在无限一维数轴上的几个水果堆。 每堆都由一个位置和该位置可用的水果数量表示。 输入数组`fruits`已经按位置排序，并且每个位置都是唯一的。 

你从位置开始`startPos`，您可以沿 x 轴向左或向右行走。 移动一单位需要一步，最多可以使用`k`总步数。 每当你访问一个有水果的位置时，你就会自动收获那里的所有水果。 

目标是确定在步数限制内可以收获的最大水果总数。 

重要的细节是移动成本取决于所采取的路径。 如果您只朝一个方向移动，则成本只是移动的距离。 但是，如果您向两个方向移动，则总距离取决于您先访问哪一侧。 

例如：

 - 先向左，然后向右：

 - 成本=`(startPos - left) + (right - left)`- 先向右走，再向左走：

 - 成本=`(right - startPos) + (right - left)`这些可以简化为：

 -`min(2 * leftDistance + rightDistance, leftDistance + 2 * rightDistance)`在哪里：

-`leftDistance = startPos - left`-`rightDistance = right - startPos`限制条件很大：

 -`fruits.length`可以达到`100000`- 职位最多可达`200000`这立即告诉我们任何二次解都会太慢。 我们需要接近线性时间的东西。 

一些边缘情况很重要：

 -`k = 0`，这意味着我们只能在以下位置收集水果`startPos`- 所有的水果都太远而无法到达
 - 所有可触及的水果完全位于一侧
 - 最佳路线需要改变方向一次
 - 起始位置本身可能包含水果

 位置排序这一事实极其重要，因为它可以实现高效的滑动窗口技术。 

## 方法

 ### 蛮力方法

 暴力解决方案将考虑水果位置的每个可能的间隔，并确定是否可以在范围内收集它`k`步骤。 

假设我们从索引中选择一个区间`i`索引`j`。 由于水果已排序，因此此间隔表示收集位置之间的每个水果：

 -`left = fruits[i][0]`-`right = fruits[j][0]`我们计算从以下位置开始覆盖此间隔所需的最小步行成本`startPos`。 如果成本在`k`，我们将区间内的所有水果相加并更新答案。 

问题是有`O(n^2)`可能的间隔。 即使前缀和将区间总和减少到`O(1)`，总复杂度仍然是`O(n^2)`，这对于`n = 100000`。 

### 最佳方法

 关键的观察结果是有效的水果位置在数轴上形成一个连续的区间。 

如果我们维持一个滑动窗口`[left, right]`，我们可以有效地确定该区间内的所有水果是否可以在`k`步骤。 

因为位置是排序的：

 - 扩大右边界只会增加旅行成本
 - 如果窗口失效，将左边界向右移动可以恢复有效性

 这种单调行为使得滑动窗口成为可能。 

我们还在窗口内维护水果的运行总和，使我们能够在恒定时间内计算间隔总计。 

唯一的挑战是正确计算当前间隔的最小移动成本。 

对于跨越位置的窗口：

 -`L = fruits[left][0]`-`R = fruits[right][0]`所需的最少步骤是：```
min(
    2 * (startPos - L) + (R - startPos),
    (startPos - L) + 2 * (R - startPos)
)
```这个公式代表：

 - 先向左走，然后向右走
 - 先向右走，然后向左走

 我们选择更便宜的路线。 

由于每个索引最多进入和离开滑动窗口一次，因此解决方案以线性时间运行。

 ## 算法演练

 1.初始化两个指针：

 -`left = 0`- 迭代`right`从`0`到`n - 1`2. 维护当前窗口内水果的运行总和：

 - 每当`right`展开，添加`fruits[right][1]`- 每当`left`缩小、减去`fruits[left][1]`3. 对于每个窗口`[left, right]`，计算：

 -`leftPos = fruits[left][0]`-`rightPos = fruits[right][0]`4. 确定在当前时间间隔内收集所有水果所需的最少步骤。 

有两种可能的遍历策略：

 - 先向左走，然后向右扫
 - 先向右走，然后向左扫

 计算：```
leftDistance = max(0, startPos - leftPos)
rightDistance = max(0, rightPos - startPos)
```然后：```
stepsNeeded =
    min(
        2 * leftDistance + rightDistance,
        leftDistance + 2 * rightDistance
    )
```5. 如果`stepsNeeded > k`，窗口无效。 

从左侧缩小窗口，直到它再次有效。 
6. 获得有效窗口后，使用当前水果总和更新答案。 
7. 继续，直到处理完所有位置。 

### 为什么它有效

 滑动窗口之所以有效，是因为水果位置已排序。 扩大右边界只能增加行程范围，而不能减少行程范围。 因此，一旦窗口失效，将左边界向右移动是恢复有效性的唯一方法。 

运动公式正确地计算了穿越该区间的最便宜的方式，因为任何最佳路线最多改变方向一次。 该算法检查两种可能的顺序并取最小值。 

由于每个有效解都对应于某个连续的区间，并且每个区间都被滑动窗口检查一次，因此该算法总是能找到最佳答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxTotalFruits(self, fruits: List[List[int]], startPos: int, k: int) -> int:
        left = 0
        current_sum = 0
        best = 0

        for right in range(len(fruits)):
            current_sum += fruits[right][1]

            while left <= right:
                left_pos = fruits[left][0]
                right_pos = fruits[right][0]

                left_distance = max(0, startPos - left_pos)
                right_distance = max(0, right_pos - startPos)

                steps_needed = min(
                    2 * left_distance + right_distance,
                    left_distance + 2 * right_distance
                )

                if steps_needed <= k:
                    break

                current_sum -= fruits[left][1]
                left += 1

            best = max(best, current_sum)

        return best
```该实现使用经典的滑动窗口结构。 

变量`current_sum`存储当前窗口内的水果总数。 作为`right`指针展开，我们添加新包含的水果数量。 

内部`while`循环确保窗口保持有效。 如果移动成本超过`k`，我们反复从左侧移除水果堆，直到间隔再次可达。 

运动计算是解决方案的核心。 我们计算相对于最左边和最右边位置的距离`startPos`，然后评估两种可能的遍历顺序。 

Finally, after each valid window is established, we update the global maximum.

 ## 解决方案```go
package main

func max(a, b int) int {
	if a > b {
		return a
	}
	return b
}

func min(a, b int) int {
	if a < b {
		return a
	}
	return b
}

func maxTotalFruits(fruits [][]int, startPos int, k int) int {
	left := 0
	currentSum := 0
	best := 0

	for right := 0; right < len(fruits); right++ {
		currentSum += fruits[right][1]

		for left <= right {
			leftPos := fruits[left][0]
			rightPos := fruits[right][0]

			leftDistance := max(0, startPos-leftPos)
			rightDistance := max(0, rightPos-startPos)

			stepsNeeded := min(
				2*leftDistance+rightDistance,
				leftDistance+2*rightDistance,
			)

			if stepsNeeded <= k {
				break
			}

			currentSum -= fruits[left][1]
			left++
		}

		best = max(best, currentSum)
	}

	return best
}

因为 Go 没有提供内置的`min`和`max`对于整数的帮助器，我们定义了小的实用函数。 

切片自然地用于`fruits`数组，整数溢出不是问题，因为最大水果总数保持在 Go 的标准整数范围内。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`k = 0`。 在这种情况下，玩家根本无法移动，所以唯一可以收获的水果就是那些恰好位于`startPos`。 粗心的实现可能仍然会尝试扩大窗口或错误地计算附近的水果。 该解决方案可以自然地处理这种情况，因为任何需要正向移动的间隔都会立即变得无效。 

另一个重要的边缘情况是所有水果都完全超出可到达范围。 例如，如果每个水果堆的距离都大于`k`离开一步，正确答案是`0`。 滑动窗口正确地缩小无效间隔直到它们消失，确保不会计算到无法到达的水果。 

当最佳解决方案需要改变方向一次时，会出现更微妙的边缘情况。 许多不正确的解决方案都假设运动应该只发生在一个方向上。 然而，某些输入需要先向左移动，然后向右移动，反之亦然，以最大化总收获。 移动公式明确评估两种遍历顺序，并始终选择成本较低的一种。 

另一个棘手的情况是当水果两边都存在时`startPos`，但是访问两个极端都超出了步数预算。 滑动窗口自然会从一侧删除位置，直到间隔再次变得可行，从而确保只有有效范围才能对答案做出贡献。
