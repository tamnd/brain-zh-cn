 # LeetCode 2172 - 数组的最大与和

 ## 问题理解

 该问题要求我们将一组整数分配到编号槽中，以最大化基于按位与运算的评分函数。 

我们得到：

 - 整数数组`nums`- 多个插槽，`numSlots`- 每个插槽的编号为`1`到`numSlots`- 每个槽最多可以包含两个数字

 对于放入槽中的每个数字，我们获得的分数等于：```
number AND slot_number
```最终得分是每个已放置号码的所有这些值的总和。 

目标是确定最大可能的 AND 总和。 

重要的细节是槽号本身参与 AND 运算。 这意味着不同的号码根据分配到的插槽而受益不同。 

例如：```
5 AND 3 = 1
5 AND 5 = 5
5 AND 2 = 0
```因此，放置策略非常重要。 

约束条件极其重要：

 -`numSlots <= 9`- 每个槽位最多可容纳两个数字
 - 因此总容量最多为`18`-`nums.length <= 18`虽然`18`虽然很小，但如果天真地探索的话，可能的任务数量仍然是巨大的。 这强烈表明具有记忆或位掩码动态编程的指数算法是有意的。 

中的值`nums`也很小：```
1 <= nums[i] <= 15
```然而，实际值不如赋值结构重要。 

有几个边缘情况值得注意：

 - 某些插槽可能仍为空
 - 多个数字可能具有相同的值
 -`numSlots`可以大于必要的
 - 某个数字在某些时段可能会产生零贡献
 - 由于每个插槽最多容纳两个号码，因此容量管理至关重要

 该问题保证：```
2 * numSlots >= n
```所以总是有足够的总容量来放置每个数字。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是尝试将每个数字放入每个槽中的所有可能位置。 

对于每个数字，我们可以：

 - 尝试将其放入插槽中`1`- 尝试将其放入插槽中`2`- 继续直到插槽`numSlots`- 跳过已经包含两个数字的插槽

 我们将递归地生成所有有效分配并计算每个配置的总 AND 和。 

这种方法是正确的，因为它探索了每一种法律安排，因此找到的最大值必定是最优的。 

不幸的是，它太慢了。 

每个数字可能会进入许多插槽，大致产生：```
O(numSlots^n)
```最坏情况下的状态。 

和：```
n <= 18
numSlots <= 9
```这将变得天文数字般巨大。 

### 关键见解

 关键的观察是问题的状态可以使用位掩码紧凑地表示。 

由于每个槽可以容纳两个数字，因此我们可以将问题视为具有：```
2 * numSlots
```个人立场。 

例如，如果：```
numSlots = 3
```那么我们有六个可分配的位置：```
slot 1 -> positions 0,1
slot 2 -> positions 2,3
slot 3 -> positions 4,5
```现在问题变成：

 - 将每个数字分配到一个未使用的位置
 - 每对位置对应一个槽位

 这将问题转化为经典的位掩码 DP 问题。 

我们定义：```
mask = which positions are already occupied
```从设置的位数`mask`，我们知道：

 - 已经放置了多少号码
 - 哪个号码来自`nums`我们目前正在分配

 这避免了存储显式的槽内容。 

可能的掩码数量为：```
2^(2 * numSlots)
```最多：```
2^18 = 262144
```这是可以管理的。

 ## 算法演练

 ### 步骤 1：将插槽容量表示为位置

 每个槽可以包含两个数字。 

不要直接跟踪槽内容，而是创建：```
2 * numSlots
```虚拟职位。 

例子：```
slot 1 -> positions 0 and 1
slot 2 -> positions 2 and 3
slot 3 -> positions 4 and 5
```位置的槽位号`p`是：```
(p // 2) + 1
```这种表示方式使得容量处理变得极其简单。 

### 步骤 2：定义 DP 状态

 我们使用位掩码：```
mask
```其中：

 - 位`i`是`1`如果位置`i`被占用
 - 位`i`是`0`如果位置`i`是免费的

 设置位的数量告诉我们已经分配了多少个数字。 

如果：```
used = popcount(mask)
```那么下一个要放置的数字是：```
nums[used]
```### 步骤 3：定义转换

 对于每个未使用的位置：

 - 确定其槽位号
 - 计算贡献：```
nums[used] & slot_number
```- 创建新的掩模并占据该位置
 - 递归计算未来的最佳分数

 过渡公式：```
dp(mask) =
max(
    (nums[idx] & slot) + dp(next_mask)
)
```### 步骤 4：基本情况

 如果所有号码都已分配：```
idx == len(nums)
```那么就不能再添加更多分数了。 

返回：```
0
```### 第 5 步：记住结果

 许多面具被反复重新审视。 

将计算出的答案存储在记忆缓存中，以便每个掩码仅求解一次。 

这极大地减少了指数重新计算。 

### 为什么它有效

 DP 之所以有效，是因为每个有效分配都恰好对应于掩码中占用位置的一个序列。 该掩码完全捕获了继续优化过程所需的状态。 

在每一步中，算法都会考虑下一个数字的所有有效位置，并选择最大化的位置：```
current contribution + optimal future contribution
```由于所有未来状态都是通过递归和记忆来最优解决的，因此最终答案是全局最优的。 

## Python 解决方案```python
from typing import List
from functools import lru_cache

class Solution:
    def maximumANDSum(self, nums: List[int], numSlots: int) -> int:
        total_positions = 2 * numSlots
        n = len(nums)

        @lru_cache(None)
        def dp(mask: int) -> int:
            idx = mask.bit_count()

            if idx == n:
                return 0

            best = 0

            for pos in range(total_positions):
                if (mask & (1 << pos)) == 0:
                    slot = (pos // 2) + 1

                    candidate = (
                        (nums[idx] & slot)
                        + dp(mask | (1 << pos))
                    )

                    best = max(best, candidate)

            return best

        return dp(0)
```实施过程首先将老虎机系统转换为虚拟位置。 由于每个槽可以包含两个数字，因此正好有`2 * numSlots`可分配的职位。 

递归函数`dp(mask)`表示填充由 表示的位置后可实现的最大 AND 总和`mask`。 

表达式：```python
mask.bit_count()
```告诉我们已经放置了多少个号码。 这直接决定了来自哪个数字`nums`接下来应该分配。 

对于每个未使用的位置：```python
if (mask & (1 << pos)) == 0
```我们使用以下方法计算其槽号：```python
slot = (pos // 2) + 1
```然后我们评估将当前数字分配给该插槽的贡献。 

记忆至关重要。 如果没有缓存，相同的掩码将被重复重新计算，从而导致指数爆炸。 

递归从以下开始：```python
dp(0)
```代表空赋值状态。 

## 解决方案```go
func maximumANDSum(nums []int, numSlots int) int {
	totalPositions := 2 * numSlots
	n := len(nums)

	memo := make(map[int]int)

	var bitCount func(int) int
	bitCount = func(x int) int {
		count := 0
		for x > 0 {
			count += x & 1
			x >>= 1
		}
		return count
	}

	var dp func(int) int

	dp = func(mask int) int {
		if val, exists := memo[mask]; exists {
			return val
		}

		idx := bitCount(mask)

		if idx == n {
			return 0
		}

		best := 0

		for pos := 0; pos < totalPositions; pos++ {
			if (mask & (1 << pos)) == 0 {
				slot := (pos / 2) + 1

				candidate := (nums[idx] & slot) + dp(mask|(1<<pos))

				if candidate > best {
					best = candidate
				}
			}
		}

		memo[mask] = best
		return best
	}

	return dp(0)
}
```Go 实现遵循与 Python 版本相同的逻辑。 

Go 不提供内置的`bit_count()`整数的方法与 Python 的方法相同，因此我们实现了一个辅助函数来手动计算设置的位。 

记忆结构是使用以下方式实现的：```go
map[int]int
```其中键是位掩码状态，值是从该状态开始的最佳分数。 

由于最高分较小且约束条件有限，因此标准`int`值完全不会溢出。

 ## 边缘情况

 当许多插槽未使用时会出现一种重要的边缘情况。 由于该问题仅限制最大容量，并不要求每个槽都包含数字，因此最优解可能会故意将许多槽留空。 DP 自然地处理这个问题，因为它只为现有号码分配位置，而从不强制完全占用。 

当某些分配贡献为零时，会出现另一种微妙的情况。 例如：```
8 AND 1 = 0
```贪心算法可能会错误地假设每个位置都应该最大化即时贡献。 然而，有时，将一个数字放入较低的得分位置可以让另一个数字稍后获得更高的分数。 民主党通过探索所有可能性来避免这个问题。 

第三个重要的边缘情况涉及重复的数字。 如果许多值相同，则简单的递归实现可能会多次冗余地重新计算等效状态。 记忆化通过缓存每个位掩码状态的结果来防止这种情况，确保每个配置仅被解决一次。 

最后，最大约束大小本身就是一个重要的边缘情况。 高达`18`分配，暴力递归变得不可行。 位掩码 DP 成功是因为状态空间的上限大约为`262144`掩码，在典型的 LeetCode 限制内是可以管理的。
