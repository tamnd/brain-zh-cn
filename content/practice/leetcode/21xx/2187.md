[LeetCode 问题 2187](https://leetcode.com/problems/minimum-time-to-complete-trips/)

 **难度：** 🟡 中等
 **主题：** 数组、二分查找

 ## 解决方案

 ## 问题理解

 该问题要求我们确定公交车队集体完成给定次数的行程所需的**最短时间**。 车队中的每辆公交车都有自己的固定行程持续时间，用数组表示`time`。 公交车**独立且连续运行**，这意味着公交车可以在完成当前行程后立即开始下一次行程。 

输入由一个数组组成`time`整数，其中`time[i]`代表公交车所需时间`i`完成**一次旅行**，以及一个整数`totalTrips`，代表所有公交车必须完成的行程总数。 输出是一个整数，表示所有公交车完成的行程总和至少所需的最小时间量`totalTrips`。 

约束表明`time.length`可以达到$10^5$个人行程时间和总行程最多可达$10^7$。 这表明由于时间复杂性，对每次旅行进行**简单的模拟**是不可行的。 相反，我们需要一种有效的算法来避免单独迭代每个可能的行程。 

需要考虑的重要边缘情况包括：

 - 只有一辆巴士可用。 
-`totalTrips`非常小（例如 1）。 
- 多辆巴士的行程时间相同。 
- 非常大`totalTrips`混合了快速和慢速巴士。 

这些边缘情况对简单的实现和整数处理提出了挑战。 

## 方法

 **蛮力方法**将增量模拟时间，在每个时间单位计算每辆公交车已完成的行程次数，直到总行程达到`totalTrips`。 虽然这保证了正确性，但它**太慢**。 如果最快的公共​​汽车的时间为 1 并且`totalTrips`是$10^7$，这个方法会迭代$10^7$次，这是不可接受的。 

**更好的解决方案**的关键观察是公交车在给定时间完成的行程总数`t`简直就是`t // time[i]`。 这使我们能够计算所有公交车的总行程**无需模拟**。 由于总行程是**时间的非递减函数**，我们可以应用**二分搜索**来找到最短时间`t`使得行程总和至少为`totalTrips`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(总行程 * n) | O(1) | O(1) | 增量模拟每个时间单位并计算行程 |
 | 最优（二分搜索）| O(n log(maxTime * 总行程)) | O(1) | O(1) | 利用行程随时间不递减的性质来二分查找最小时间 |

 ## 算法演练

 1. 确定二分查找的搜索空间。 最短可能时间为 1（或最短跳闸时间），最长可能时间为`min(time) * totalTrips`因为如果用最快的巴士来完成所有行程，就需要这么长时间。 
2. 初始化`left`作为 1 和`right`作为`min(time) * totalTrips`。 
3.同时`left < right`，计算中间点`mid = left + (right - left) // 2`。 
4.计算该时刻完成的总行程`mid`作为总和`mid // time[i]`每辆巴士`i`。 
5. 如果总行程为`mid`大于或等于`totalTrips`， 更新`right = mid`。 否则，设置`left = mid + 1`。 
6. 当循环终止时，`left`（或者`right`）将保留完成至少所需的**最短时间**`totalTrips`。 

**为什么有效：** 行程总数是时间的非减函数。 通过对可能的时间执行二分搜索，我们可以有效地找到满足条件的最小时间。 维持的不变量是`left`总是指向可能满足条件的时间，并且`right`总是指向一个绝对满足它的时间。 

## Python 解决方案```python
from typing import List

class Solution:
    def minimumTime(self, time: List[int], totalTrips: int) -> int:
        left, right = 1, min(time) * totalTrips
        
        while left < right:
            mid = left + (right - left) // 2
            trips = sum(mid // t for t in time)
            
            if trips >= totalTrips:
                right = mid
            else:
                left = mid + 1
                
        return left
```Python 代码使用最快的总线乘以来初始化搜索范围`totalTrips`。 在每次迭代中，它计算可达到的行程数`mid`并缩小搜索空间。 循环终止时`left`等于最小可行时间。 

## 解决方案```go
func minimumTime(time []int, totalTrips int) int64 {
    minTime := time[0]
    for _, t := range time {
        if t < minTime {
            minTime = t
        }
    }

    left, right := int64(1), int64(minTime)*int64(totalTrips)

    for left < right {
        mid := left + (right-left)/2
        var trips int64 = 0
        for _, t := range time {
            trips += mid / int64(t)
        }
        if trips >= int64(totalTrips) {
            right = mid
        } else {
            left = mid + 1
        }
    }
    return left
}
```由于类型处理，Go 实现略有不同。 我们使用`int64`防止乘法时溢出`minTime`经过`totalTrips`。 二分查找逻辑是相同的。
