[LeetCode 问题 2144](https://leetcode.com/problems/minimum-cost-of-buying-candies-with-discount/)

 **难度：** 🟢简单
 **主题：** 数组、贪婪、排序

 ## 解决方案

 ## 问题理解

 这个问题要求我们在特殊折扣规则下最小化购买糖果时花费的总金额。 

每购买两颗糖果，我们可以免费额外获得一颗糖果。 然而，免费糖果的价格必须小于或等于购买的两种糖果中较便宜的一个。 

输入是一个 0 索引的整数数组`cost`，其中每个值代表糖果的价格。 我们必须获得数组中的每一种糖果，要么通过付费，要么通过折扣规则作为免费糖果获得。 

目标是计算获得所有糖果所需的最低总金额。 

限制很小：

 - 数组长度最多为`100`- 每颗糖果的成本介于`1`和`100`这些约束意味着即使相对低效的方法也可以通过，但问题本质上是一个贪婪优化问题，并且存在一个非常干净的最优策略。 

重要的观察是，免费糖果应该尽可能昂贵，因为每一份免费糖果都会直接减少我们支付的金额。 不过，免费糖果仍然必须满足折扣条件。 

一些边缘情况很重要：

 - 少于三颗糖果的阵列根本无法使用折扣。 
- 长度不能被三整除的数组将留下一两颗必须始终支付的糖果。 
- 多个糖果可能具有相同的值，因此实现不能依赖于唯一性。 
- 如果昂贵的糖果被非法用作免费糖果，那么幼稚的分组策略可能会失败。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试一切可能的方法将糖果分成三组，其中购买两颗糖果，并且免费获得一颗符合条件的糖果。 

对于每个分组，我们将验证免费糖果是否满足条件：

 -`free <= min(bought1, bought2)`然后我们将计算支付的总成本并保留所有有效安排中的最小值。 

这是有效的，因为它详尽地探索了所有可能的购买组合，保证找到最佳答案。 

然而，可能的分组数量增长得非常快。 即使对于中等大小的数组，排列和分区的数量也会变得巨大。 由于约束允许最多`100`糖果，蛮力是完全不切实际的。 

### 最优贪心法

 关键的见解是，免费糖果应该始终是一组三种昂贵糖果中最便宜的糖果。 

为了最大限度地节省：

 1. 将糖果按降序排列。 
2. 三人一组加工糖果。 
3. 对于每个组：

 - 支付前两颗糖果的费用。 
- 免费获得第三颗糖果。 

为什么这有效？ 

假设我们有糖果从最大到最小排序：```
9, 7, 6, 5, 2, 2
```如果我们买`9`和`7`， 然后`6`可以合法地免费，因为：```
6 <= min(9, 7)
```自从`6`是第三大糖果，免费提供最大可能的折扣。 

任何较小的糖果都会浪费潜在的节省。 

这种贪婪策略总是在保持有效性条件的同时最大化免费糖果的价值。

 | 最佳 | O(n log n) | O(n log n) | O(1) 或 O(n) 取决于排序 | 降序排序，跳过每三个糖果 |

 ## 算法演练

 1. 排序`cost`数组按降序排列。 

我们首先想要最贵的糖果，因为免费的糖果应该尽可能贵。 排序使我们能够贪婪地形成最优组。 
2. 初始化变量`total_cost = 0`。 

该变量将累计我们实际支付的总金额。 
3. 使用索引迭代已排序的数组。 

糖果按三组进行加工：

 - 第一个糖果，已付费
 - 第二颗糖果，付费
 - 第三颗糖果，免费
 4.将每组的第一颗和第二颗糖果添加到`total_cost`。 

由于这些是购买的糖果，因此它们构成了总付款。 
5. 跳过每组中的第三颗糖果。 

第三颗糖果成为折扣规则下的免费糖果。 
6. 继续，直到处理完所有糖果。 

如果最后剩下的糖果少于三颗，则必须全部购买。 

### 为什么它有效

 按降序排序后，每第三颗糖果都小于或等于前两颗糖果。 因此，它始终满足折扣条件。 

选择每组中第三大糖果免费可以最大限度地提高折扣金额。 任何替代安排都可以：

 - 生产较小的免费糖果，减少储蓄，或
 - 违反折扣规则。 

因此，贪心策略是最优的。 

## Python 解决方案```python
from typing import List

class Solution:
    def minimumCost(self, cost: List[int]) -> int:
        cost.sort(reverse=True)

        total_cost = 0

        for i in range(len(cost)):
            # Every third candy is free
            if i % 3 != 2:
                total_cost += cost[i]

        return total_cost
```该实现首先按降序对糖果进行排序。 这保证了每组三颗糖果都是从最大到最小排序的。 

循环按索引处理每个糖果。 糖果指数：

 -`0`,`1`已付款
 -`2`是免费的
 -`3`,`4`已付款
 -`5`是免费的

 此模式每三个元素重复一次。 

条件：```python
if i % 3 != 2:
```意思是：

 - 添加糖果成本，除非它是一组中的第三颗糖果。 

最终的结果就是购买所有糖果所需的最低金额。 

## 解决方案```go
package main

import "sort"

func minimumCost(cost []int) int {
	sort.Slice(cost, func(i, j int) bool {
		return cost[i] > cost[j]
	})

	totalCost := 0

	for i := 0; i < len(cost); i++ {
		// Every third candy is free
		if i%3 != 2 {
			totalCost += cost[i]
		}
	}

	return totalCost
}
```Go 解决方案遵循与 Python 实现完全相同的贪婪策略。 

主要区别在于排序语法。 Go 使用`sort.Slice`使用自定义比较器按降序对切片进行排序。 

Go 切片的行为与动态数组类似，因此对于空或小输入不需要特殊处理。 整数溢出也不是问题，因为最大可能的总和很小：```go
100 candies * 100 cost = 10,000
```很容易适合 Go 的内部`int`类型。

 ## 边缘情况

 当数组包含的糖果少于三颗时，就会出现一种重要的边缘情况。 在这种情况下，永远无法获得免费糖果，因为折扣需要先购买两颗糖果。 有缺陷的实现可能会错误地尝试跳过糖果。 当前的解决方案可以自然地处理这个问题，因为没有索引满足`i % 3 == 2`。 

另一个重要的边缘情况是糖果的数量不能被三整除。 例如，有四颗或五颗糖果，最后的一两颗糖果不能形成完整的折扣组。 该算法正确地对所有剩余糖果进行收费，因为只有三分之一的糖果被跳过。 

第三个极端情况涉及重复的糖果价格。 一些实现错误地假设唯一值或依赖于严格的不平等。 然而，折扣规则允许免费糖果与更便宜的购买糖果相同。 即使许多糖果价格相同，排序和分组也能正常工作。 

最后一个微妙的情况是，最便宜的糖果与原始订单中的昂贵糖果混合在一起。 由于该算法首先对数组进行排序，因此它不依赖于原始排列。 这保证了最大的合格糖果始终被选择为免费糖果，从而最大限度地节省费用。
