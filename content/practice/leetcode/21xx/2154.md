 # LeetCode 2154 - 不断将找到的值乘以二

 ## 问题理解

 这个问题要求我们在整数数组中重复搜索一个值，并在找到该值时将该值加倍。 我们从整数开始`original`。 如果该数字存在于数组中的任何位置`nums`，我们将其乘以二并使用新值重复该过程。 一旦数组中不再存在当前值，该过程就会停止。 

输入由两部分组成。 第一个输入，`nums`，是一个整数数组。 第二个输入，`original`，是我们反复搜索的起始数字。 预期输出是最终值`original`执行完所有有效的加倍后。 

例如，如果`original = 3`并且该数组包含`3`，然后我们将值更新为`6`。 如果数组还包含`6`，我们再次更新为`12`。 如果数组包含`12`，我们继续`24`。 一旦数组中缺少当前值，该过程就会停止。 

限制相对较小：

 -`1 <= nums.length <= 1000`-`1 <= nums[i], original <= 1000`这些限制告诉我们，即使是简单的解决方案也能有效地发挥作用。 然而，该问题对于练习查找优化和模拟技术仍然有用。 

一些重要的观察立即浮现出来：

 - 数组可能包含重复项，但重复项不会改变行为，因为我们只关心一个值是否至少存在一次。 
- 如果数组包含如下链，则加倍过程可能会连续持续多次`2 -> 4 -> 8 -> 16`。 
- 的价值`original`可以成长超越`1000`在执行期间，即使初始输入是有限的。 
- 如果数组中不存在起始值，我们立即返回原始值不变。 

## 方法

 ### 蛮力方法

 最直接的解决办法就是反复扫描整个数组，检查当前值是否存在`original`存在。 

该算法的工作原理如下：

 1. 线性搜索数组`original`。 
2. 如果找到，则加倍`original`。 
3. 使用新值重复扫描。 
4. 一旦找不到值就停止。 

这种方法是正确的，因为每次迭代都完全遵循问题陈述中给出的规则。 然而，每次查找都需要遍历整个数组。 

在最坏的情况下，如果双链很长，我们会重复执行线性扫描。 尽管约束足够小，该解决方案仍然可以通过，但与基于哈希的查找方法相比，它的效率较低。 

### 最佳方法

 关键的观察是我们只需要快速的成员资格检查。 我们不关心数组内的元素顺序、频率或位置。 因此，哈希集是理想的数据结构。 

通过存储来自的所有数字`nums`在一个集合中，我们可以检查一个值是否存在于平均值中`O(1)`时间而不是`O(n)`时间。 

改进后的算法变为：

 1. 转换`nums`到一个哈希集中。 
2. 虽然`original`存在于集合中：

 - 加倍。 
3. 返回最终值。 

这可以有效地工作，因为每次查找平均时间都是恒定的。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n × k) | O(n × k) | O(1) | O(1) | 重复扫描数组中每个加倍的值 |
 | 最佳| O(n + k) | O(n) | 使用哈希集进行恒定时间查找 |

 这里，`n`是数组的长度，`k`是成功加倍的次数。 

## 算法演练

 1. 根据输入数组创建哈希集。 

我们存储每个数字`nums`在集合内，因为集合提供非常快速的成员资格测试。 我们可以立即确定某个值是否存在，而不是重复扫描数组。 
2. 从给定值开始`original`。 

该值代表我们当前正在搜索的数字。 
3. 检查当前值是否存在于集合中。 

如果存在，问题会指示我们将其乘以二。 然后我们使用更新后的值继续搜索。 
4. 重复该过程，直到该值丢失。 

一旦在集合中找不到当前值，进程就会终止，因为问题陈述明确要求停止。 
5. 返回最终值。 

该值表示加倍序列中未出现在数组中的第一个数字。 

### 为什么它有效

 该算法保持不变式`original`始终表示必须根据问题规则检查的当前值。 在每一步中，如果该值存在于数组中，我们就将其加倍一次并继续。 如果它不存在，我们立即停止。 由于该算法精确地反映了所需的过程，并通过集合使用准确的成员资格检查，因此保证返回的值是正确的。 

## Python 解决方案```python
from typing import List

class Solution:
    def findFinalValue(self, nums: List[int], original: int) -> int:
        values = set(nums)

        while original in values:
            original *= 2

        return original
```实现从转换开始`nums`进入一个名为`values`。 此预处理步骤允许在整个算法中快速进行存在性检查。 

这`while`循环反复检查当前值是否`original`存在于集合内部。 如果是这样，我们使用以下方法将值加倍`original *= 2`。 

一旦集合中不再存在该值，循环就会终止，函数将返回最终结果。 

实现直接遵循算法演练并保持简洁，因为问题逻辑本身很简单。 

## 解决方案```go
func findFinalValue(nums []int, original int) int {
    values := make(map[int]bool)

    for _, num := range nums {
        values[num] = true
    }

    for values[original] {
        original *= 2
    }

    return original
}
```Go 实现使用带有布尔值的映射来模拟哈希集，因为 Go 不提供内置的集合类型。 

地图存储每个数字`nums`作为钥匙。 然后执行成员资格检查`values[original]`。 

与 Python 不同，Go 需要显式创建映射`make`。 否则，两个解决方案之间的整体逻辑是相同的。 

整数溢出在这里不是一个问题，因为约束很小并且加倍链受到可用数组值的限制。

 ## 边缘情况

 当初始值`original`数组中根本不存在。 粗心的实现可能仍会尝试不必要的处理或意外修改该值。 当前的实现可以自然地处理这个问题，因为`while`循环条件立即失败，原始值不变地返回。 

另一个重要的情况涉及数组中的重复数字。 例如，`nums = [2,2,2]`。 问题只问一个数字是否存在，而不是问它出现了多少次。 错误地跟踪频率的简单实现可能会使逻辑过于复杂。 使用集合可以避免此问题，因为重复项会自动折叠为单个条目。 

第三种边缘情况是长双链，例如`[2,4,8,16,32]`。 重复扫描数组的低效实现可能会多次执行不必要的工作。 哈希集解决方案可以有效地处理这个问题，因为无论链长如何，每次查找都保持恒定的时间。 

最后一个微妙的边缘情况是当加倍的值超过原始输入约束时。 例如，从`1000`可能会产生`2000`。 该实现正确处理了这个问题，因为该算法对最终值没有限制，并且 Python 和 Go 都可以安全地存储此大小的整数。
