[LeetCode 问题 2155](https://leetcode.com/problems/all-divisions-with-the-highest-score-of-a-binary-array/)

 **难度：** 🟡 中等
 **主题：** 数组

 ## 解决方案

 ## 问题理解

 问题给了我们一个二进制数组`nums`，意味着每个元素都是`0`或者`1`。 我们可以在任意索引处划分数组`i`在哪里`0 <= i <= n`，该划分创建了两个部分：

 - 左侧部分包含索引中的元素`0`到`i - 1`- 右侧部分包含索引中的元素`i`到`n - 1`划分点本身是在元素之间，而不是在元素上。 因为`i`可以是`0`或者`n`，一侧允许为空。 

对于每个分区索引`i`，我们计算一个分数，定义为：

 - 数量`0`s 在左边部分
 - 加上数量`1`s 在正确的部分

 目标是找到达到最高可能分数的每个划分索引。 

输入大小可以大到`10^5`，它立即告诉我们二次解可能会太慢。 重复扫描数组中的每个划分点的解决方案的性能会很差。 我们需要更接近线性时间的东西。 

一些边缘情况很重要：

 - 按索引除法`0`，左侧为空
 - 按索引除法`n`，右侧为空
 - 数组仅包含`0`s
 - 数组仅包含`1`s
 - 多个划分点产生相同的最高分数

 该问题保证数组仅包含二进制值，这大大简化了计数逻辑。 

## 方法

 ### 蛮力方法

 一个简单的方法是尝试每个可能的除法索引`0`到`n`。 

对于每个部门：

 - 数数有多少个`0`s 存在于左侧
 - 数数有多少个`1`s 存在于右侧
 - 计算分数
 - 追踪最高分和相应指数

 这种方法是正确的，因为它明确地评估每个有效的划分。 然而，对于每个除法索引，我们可能会再次扫描数组的大部分。 

如果数组长度是`n`，那么：

 - 有`n + 1`划分点
 - 每个部门可能需要最多`O(n)`工作

 这导致`O(n^2)`时间复杂度，对于`n = 10^5`。 

### 最优前缀计数方法

 关键的观察结果是，相邻划分点仅因从右侧移动到左侧的一个元素而不同。 

假设我们将除法索引从`i`到`i + 1`：

- 如果`nums[i] == 0`，则左侧多加一个零
 - 如果`nums[i] == 1`，那么右侧就损失一一

 我们可以在扫描一次数组时保持运行计数，而不是从头开始重新计算计数。 

我们首先数一下有多少个`1`s 存在于整个数组中。 这代表了分区索引的分数`0`，因为：

 - 左侧为零`0`s
 - 右侧包含所有原件`1`s

 然后我们扫描数组：

 - 当遇到一个`0`，增加左零计数
 - 当遇到一个`1`, 减少右一计数

 在每一步中，在恒定的时间内有效地计算当前分数。 

这将问题转化为线性扫描。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 重新计算每个除法的计数 |
 | 最佳| O(n) | O(1) 不包括输出 | 扫描一次时保持运行计数 |

 ## 算法演练

 1. 统计总数量`1`s 在数组中。 

该值表示当划分索引为时右分区中最初存在的个数`0`。 
2.初始化两个变量：

 -`left_zeros = 0`-`right_ones = total number of ones`在划分索引处`0`，得分为：`left_zeros + right_ones`3.初始化：

 -`max_score`-`result`从除法索引开始`0`作为当前的最佳人选。 
4. 从左到右迭代数组。 

在位置`i`, 元素`nums[i]`从右分区移动到左分区。 
5. 根据当前元素更新计数。 

- 如果该值为`0`, 增量`left_zeros`- 如果该值为`1`, 递减`right_ones`6. 计算划分指数的分数`i + 1`。 

处理元素后的划分`i`对应于将剪切紧接在该元素之后。 
7. 将分数与当前最高分数进行比较。 

- 如果分数较大，则重置答案列表
 - 如果分数等于最大值，则附加分区索引
 8. 继续，直到处理完所有划分点。 
9. 返回最佳划分索引列表。 

### 为什么它有效

 该算法保持一个不变量：

 -`left_zeros`始终等于左侧分区中零的数量
 -`right_ones`始终等于右侧分区中的个数

 由于当一个元素跨越划分边界时，每个步骤都会正确更新这些计数，因此每个计算的分数都是准确的。 由于所有划分索引都被评估一次，因此该算法保证找到具有最大分数的所有索引。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxScoreIndices(self, nums: List[int]) -> List[int]:
        right_ones = sum(nums)
        left_zeros = 0

        max_score = right_ones
        result = [0]

        for i, value in enumerate(nums):
            if value == 0:
                left_zeros += 1
            else:
                right_ones -= 1

            current_score = left_zeros + right_ones
            division_index = i + 1

            if current_score > max_score:
                max_score = current_score
                result = [division_index]
            elif current_score == max_score:
                result.append(division_index)

        return result
```实施首先计算所有`1`s 在数组中使用`sum(nums)`。 由于数组是二进制的，因此对数组求和可以直接得出 1 的总数。 

变量`left_zeros`和`right_ones`代表分数公式的两部分。 最初，左侧分区是空的，所以`left_zeros`开始于`0`。 右边的分区最初包含整个数组，所以`right_ones`从总数开始。 

该算法使用划分索引初始化最佳分数`0`。 这避免了以后的特殊情况逻辑。 

该循环只对每个元素处理一次。 更新计数后，算法会计算当前元素之后紧邻的除法对应的分数，这就是除法索引为的原因`i + 1`。 

每当发现更大的分数时，结果列表就会重置。 当找到相等分数时，附加划分索引。 

该算法仅对每个元素执行恒定的工作，从而提供线性运行时间。 

## 解决方案```go
func maxScoreIndices(nums []int) []int {
	rightOnes := 0

	for _, value := range nums {
		rightOnes += value
	}

	leftZeros := 0
	maxScore := rightOnes
	result := []int{0}

	for i, value := range nums {
		if value == 0 {
			leftZeros++
		} else {
			rightOnes--
		}

		currentScore := leftZeros + rightOnes
		divisionIndex := i + 1

		if currentScore > maxScore {
			maxScore = currentScore
			result = []int{divisionIndex}
		} else if currentScore == maxScore {
			result = append(result, divisionIndex)
		}
	}

	return result
}
```Go 实现遵循与 Python 版本相同的逻辑。 

Go 中的切片自然地通过以下方式处理动态结果存储`append`。 由于问题约束对于标准整数运算来说足够小，因此不存在整数溢出问题。 

与 Python 不同，Go 不提供直接内置的`sum`函数用于切片，因此通过循环手动计算切片总数。 

返回的切片永远不会`nil`因为除法索引`0`始终有效并最初包含在内。

 ## 边缘情况

 当数组仅包含零时，会出现一种重要的边缘情况。 在这种情况下，每个向右移动的除法都会增加左侧零的数量，而右侧1的数量始终保持为零。 因此最佳答案是除法索引`n`。 有缺陷的实现可能会忘记评估最后一个元素之后的最终划分点。 此实现自然可以处理它，因为每次迭代都会评估除法索引`i + 1`。 

另一个重要的边缘情况是仅包含 1 的数组。 这里，索引处的初始划分`0`已经具有最大可能分数，因为正确的分区包含数组中的每个分数。 随着划分向右移动，分数严格下降。 某些实现在评估后面的位置之前会意外地覆盖最初的最佳分数。 该解决方案使用除法索引显式初始化答案`0`，保证正确性。 

第三个重要的边缘情况涉及多个最佳划分点。 例如，`[1,0]`在分区索引处产生相同的最高分数`0`和`2`。 不正确的解决方案可能只保留一个最佳索引，而不是所有有效索引。 每当当前分数等于最大分数时，此实现就会正确附加索引。 

另一个微妙的边缘情况是最小的有效输入大小，其中`n = 1`。 在只有一个元素的情况下，仍然有两个有效的划分点：元素之前和元素之后。 该算法正确地计算了两者，因为它初始化了除法`0`在进入循环并评估除法之前`1`在第一次迭代期间。
