 # LeetCode 2121 - 相同元素之间的间隔

 ## 问题陈述

 给定一个 0 索引的整数数组`arr`。 对于每个索引`i`，您必须计算之间的距离总和`i`和所有其他索引`j`在哪里`arr[i] == arr[j]`。 

两个索引之间的距离是它们位置的绝对差：$$|i - j|$$结果应该是一个数组`intervals`在哪里：

-`intervals[i]`等于距索引的距离之和`i`到包含相同值的所有其他索引。 

如果一个值在数组中只出现一次，那么它的区间和为`0`因为没有其他匹配的索引。 

挑战在于数组大小可以大到`10^5`，因此低效的成对比较解决方案将会超时。 

## 问题理解

 输入数组表示放置在特定索引处的值。 对于每个位置，我们只对包含完全相同值的其他位置感兴趣。 

假设数组是：```
[2,1,3,1,2,3,3]
```对于索引`2`，值为`3`。 其他出现的情况`3`处于指数`5`和`6`。 索引的答案`2`是：$$|2 - 5| + |2 - 6| = 3 + 4 = 7$$必须对每个位置进行计算。 

约束条件很重要：

 -`n`可以是`100000`- 所有对的简单嵌套循环将需要最多`10^10`最坏情况下的比较

 这太慢了，所以我们需要一个更有效的策略。 

一些边缘情况很重要：

 - 每个元素都是唯一的数组
 - 所有元素都相同的数组
 - 大组重复值
 - 值仅出现两次
 - Go 中需要 64 位整数的非常大的区间和

 该问题保证：

 - 数组非空
 - 值为正整数
 - 数组长度符合内存限制

 ## 方法

 ### 蛮力方法

 最直接的解决方案是将每个指标与其他每个指标进行比较。 

对于每个位置`i`：

 1. 迭代所有索引`j`2.如果`arr[i] == arr[j]`和`i != j`3.添加`|i - j|`到答案

 这是有效的，因为它显式地计算每个所需的间隔。 

但时间复杂度极差。 对于每个索引，我们再次扫描整个数组，生成一个`O(n^2)`解决方案。 

和`n = 100000`，这变得不可行。 

### 最佳方法

 关键的观察是具有相同值的指数可以组合在一起。 

例如：```
Value 3 appears at indices [2,5,6]
```我们可以使用前缀和有效地处理整个组，而不是重复地重新计算距离。 

考虑一个索引列表：```
positions = [p0, p1, p2, ..., pk]
```对于一个职位`positions[i]`，我们想要：```
sum of distances to all positions on the left
+
sum of distances to all positions on the right
```由于索引是自然排序的，因此我们可以在每个索引的恒定时间内使用算术和前缀和来计算这些总和。 

这将总复杂度降低到线性时间。

 ## 算法演练

 ### 第 1 步：按值对索引进行分组

 创建一个哈希映射，其中：

 - 键=数组值
 - 值 = 该值出现的索引列表

 示例：```
arr = [2,1,3,1,2,3,3]

groups = {
    2: [0,4],
    1: [1,3],
    3: [2,5,6]
}
```这使我们能够独立处理每个重复值。 

### 步骤 2：初始化结果数组

 创建一个长度为结果的数组`n`用零初始化。```
result = [0] * n
```每个条目最终将包含该索引的区间总和。 

### 步骤 3：处理每个组

 对于每个索引列表：```
positions = [p0, p1, p2, ..., pk]
```有效计算区间总和。 

### 步骤 4：构建前缀和

 在位置上创建一个运行前缀和数组。 

例如：```
positions = [2,5,6]

prefix = [2,7,13]
```这允许快速范围总和计算。 

### 步骤 5：计算左贡献

 对于索引`i`：```
left_distance =
positions[i] * i - sum(left positions)
```为什么这有效：

 如果当前位置是`x`，并且有`i`其之前的位置：```
(x - p0) + (x - p1) + ... + (x - p(i-1))
=
i*x - sum(previous positions)
```### 步骤 6：计算正确贡献

 同样：```
right_distance =
sum(right positions) - positions[i] * right_count
```这计算：```
(p(i+1) - x) + (p(i+2) - x) + ...
```### 第 7 步：存储最终答案

 添加两个贡献：```
result[positions[i]] = left_distance + right_distance
```对每个组重复一次。 

### 为什么它有效

 对于每个值，所有匹配的索引都会自然排序，因为我们从左到右遍历数组。 

对于固定索引，每个距离可以分为：

 - 到左侧索引的距离
 - 到右侧索引的距离

 前缀和允许在恒定时间内计算这两个量。 

由于每个索引都属于一组并且只处理一次，因此该算法可以正确且高效地计算所有区间总和。 

## Python 解决方案```python
from collections import defaultdict
from typing import List

class Solution:
    def getDistances(self, arr: List[int]) -> List[int]:
        index_groups = defaultdict(list)

        for index, value in enumerate(arr):
            index_groups[value].append(index)

        result = [0] * len(arr)

        for positions in index_groups.values():
            size = len(positions)

            prefix = [0] * size
            prefix[0] = positions[0]

            for i in range(1, size):
                prefix[i] = prefix[i - 1] + positions[i]

            total_sum = prefix[-1]

            for i, position in enumerate(positions):
                left_sum = prefix[i - 1] if i > 0 else 0
                left_count = i

                right_sum = total_sum - prefix[i]
                right_count = size - i - 1

                left_distance = position * left_count - left_sum
                right_distance = right_sum - position * right_count

                result[position] = left_distance + right_distance

        return result
```实现首先根据所有索引的值使用`defaultdict`。 

每个值都映射到它出现的位置的排序列表。 

接下来，对于每个组，我们构建一个前缀和数组。 前缀和可以实现索引范围内总和的恒定时间计算。 

对于组中的每个位置：

 - 左侧贡献衡量与早期指数的距离
 - 正确的贡献衡量与后续指数的距离

 这些贡献是通过数学计算的，而不是迭代所有匹配的索引。 

最后，计算出的区间和直接存储在结果数组中。 

## 解决方案```go
func getDistances(arr []int) []int64 {
	indexGroups := make(map[int][]int)

	for index, value := range arr {
		indexGroups[value] = append(indexGroups[value], index)
	}

	result := make([]int64, len(arr))

	for _, positions := range indexGroups {
		size := len(positions)

		prefix := make([]int64, size)
		prefix[0] = int64(positions[0])

		for i := 1; i < size; i++ {
			prefix[i] = prefix[i-1] + int64(positions[i])
		}

		totalSum := prefix[size-1]

		for i, position := range positions {
			var leftSum int64
			if i > 0 {
				leftSum = prefix[i-1]
			}

			leftCount := int64(i)

			rightSum := totalSum - prefix[i]
			rightCount := int64(size - i - 1)

			leftDistance := int64(position)*leftCount - leftSum
			rightDistance := rightSum - int64(position)*rightCount

			result[position] = leftDistance + rightDistance
		}
	}

	return result
}
```Go 实现遵循与 Python 版本相同的算法结构。 

主要区别在于整数处理。 由于区间和可能超出 32 位整数的范围，因此结果数组和前缀和使用`int64`。 

切片用于动态索引分组，Go 映射提供高效的值到索引列表存储。

 ## 边缘情况

 ### 单元素数组

 如果数组仅包含一个元素，则没有其他匹配索引。 幼稚的实现可能会意外地尝试无效的前缀计算或超出范围的访问。 

该实现自然地处理这个问题，因为分组位置列表有大小`1`，产生的左右贡献等于`0`。 

### 所有元素都是独特的

 当每个值恰好出现一次时，每个间隔总和应该是`0`。 

某些实现错误地尝试不必要的计算或假设每组至少两个位置。 

这里，每一组只包含一个索引，因此左右计数都会自动变为零。 

### 所有元素相同

 这是一个重要的压力案例，因为每个指数都会对其他指数产生影响。 

暴力解决方案在这里变得非常慢，因为它计算所有成对距离。 

优化的解决方案仍然以线性时间运行，因为它使用前缀和处理一次排序索引列表。 

### 大区间和

 对于具有许多重复项的大型数组，间隔总计可能会超过 32 位整数限制。 

Go 实现明确使用`int64`对于：

 - 前缀和
 - 距离计算
 - 最终结果

 这可以防止整数溢出并确保最大约束的正确性。
