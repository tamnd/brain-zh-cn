 # LeetCode 2147 - 划分长走廊的多种方法

 ## 问题理解

 走廊表示为一个字符串，其中每个字符是`'S'`一个座位或`'P'`对于一株植物来说。 我们已经在走廊的两端设置了固定的隔板，并且我们可以选择在相邻位置之间放置额外的隔板。 

目标是将走廊分成几个部分，使每个部分恰好包含两个座位。 植物不会影响有效性，因为一个部分可能包含任意数量的植物。 挑战在于确定在满足此条件的同时我们可以通过多少种不同的方式放置分隔线。 

分隔符只能放置在两个索引之间。 如果至少一个分隔器位置不同，则两种布置被视为不同。 

约束条件很重要：

 - 走廊长度可以大到`10^5`- 对所有分隔线位置的强力探索将是指数级的
 - 我们需要一个高效的线性时间解决方案

 有几个重要的边缘情况：

 - 如果座位总数是奇数，则不可能将走廊分成恰好两个座位的组
 - 如果座位数为零，则不存在有效分区
 - 如果正好有两个座位，则只有一个有效的排列，不需要额外的隔板
 - 座椅对之间的长距离植物创造了多个有效的分隔位置

 关键的观察结果是，隔板放置自由度仅存在于连续的两个座位组之间。 

## 方法

 ### 蛮力方法

 强力解决方案将考虑位置之间所有可能的分隔线放置。 由于每个间隙可以包含分隔符或不包含分隔符，因此有`2^(n-1)`可能的分频器配置。 

对于每种配置，我们将扫描所有结果部分并计算座位数。 如果每个区域恰好包含两个座位，我们就认为该安排有效。 

这种方法是正确的，因为它明确地检查每个可能的分隔线排列。 然而，对于`n = 10^5`。 

### 最佳观察

 重要的见解是，各个部分是由座位分组决定的。 

假设座位位置为：```
S S ... S S ... S S
```每个有效部分必须恰好包含两个座位。 因此：

 - 前两个座位必须属于第一部分
 - 接下来的两个座位必须属于第二部分
 - 等等

 唯一的灵活性来自于座椅组之间的植物。 

如果有`k`位于一个区域的第二个座位和下一个区域的第一个座位之间的位置，那么我们有`k`可能的分隔线放置位置。 

最终答案成为所有此类间隙计数的乘积。

 ## 算法演练

 1. 统计走廊里的座位总数。 
2. 如果座位数为零或奇数，立即返回`0`，因为我们无法形成恰好包含两个座位的部分。 
3. 从左向右穿过走廊，同时跟踪遇到的座位。 
4. 每次我们完成一对座位后，我们就开始寻找下一组座位。 
5. 计算当前完成的对与下一个座位之间的植物数量。 
6. 假设有`gap`两个连续座位组之间可能的分隔位置。 将运行答案乘以`gap`。 
7. 继续，直到整个走廊都处理完毕。 
8. 返回模数答案`10^9 + 7`。 

### 为什么它有效

 每个有效部分必须恰好包含两个座位，因此座位分组是完全确定的。 唯一的选择发生在相邻的座位组之间。 组之间的每个植物间隙都会产生额外的分隔位置。 由于不同组之间的选择是独立的，因此有效排列的总数是所有间隙计数的乘积。 

## Python 解决方案```python
class Solution:
    def numberOfWays(self, corridor: str) -> int:
        MOD = 10**9 + 7
        
        total_seats = corridor.count('S')
        
        if total_seats == 0 or total_seats % 2 == 1:
            return 0
        
        answer = 1
        seat_count = 0
        plant_count = 0
        
        for char in corridor:
            if char == 'S':
                seat_count += 1
                
                if seat_count > 2 and seat_count % 2 == 1:
                    answer = (answer * (plant_count + 1)) % MOD
                    plant_count = 0
            else:
                if seat_count % 2 == 0 and seat_count != 0:
                    plant_count += 1
        
        return answer
```实施从计算席位开始。 如果计数无效，即零或奇数，则该函数立即返回`0`。 

变量`seat_count`跟踪到目前为止遇到的座位数量。 每一个完成的对都会在下一对开始之前创建一个潜在的边界。 

变量`plant_count`记录连续座位组之间出现的植物数量。 如果有`k`植物，有`k + 1`分隔线位置。 

每当我们遇到新对的第一个座位时，我们将答案乘以`(plant_count + 1)`并重置植物计数器。 

乘法时采用取模运算，避免溢出，满足问题要求。 

## 解决方案```go
func numberOfWays(corridor string) int {
    const MOD int = 1e9 + 7

    totalSeats := 0
    for _, ch := range corridor {
        if ch == 'S' {
            totalSeats++
        }
    }

    if totalSeats == 0 || totalSeats%2 == 1 {
        return 0
    }

    answer := 1
    seatCount := 0
    plantCount := 0

    for _, ch := range corridor {
        if ch == 'S' {
            seatCount++

            if seatCount > 2 && seatCount%2 == 1 {
                answer = (answer * (plantCount + 1)) % MOD
                plantCount = 0
            }
        } else {
            if seatCount%2 == 0 && seatCount != 0 {
                plantCount++
            }
        }
    }

    return answer
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 由于 Go 没有 Python 的任意精度整数，因此模运算在乘法过程中尤其重要。 

字符串迭代使用`range`，这会产生符文。 由于输入仅包含 ASCII 字符，因此直接符文比较就足够了。 

某些 Go 问题中出现的结果切片处理复杂性与此无关，因为该函数返回单个整数。

# LeetCode 2150 - 查找数组中所有孤独的数字

 ## 问题理解

 我们得到一个整数数组`nums`。 如果两个条件同时成立，则认为一个数字是孤独的：

 1. 该数字在数组中只出现一次。 
2. 都不是它的近邻，意思是`x - 1`也不`x + 1`，出现在数组中的任何位置。 

任务是返回满足这两个条件的所有数字。 输出顺序并不重要。 

约束允许最多`10^5`元素，因此解决方案必须是有效的。 重复扫描数组寻找邻居的二次解会太慢。 

一些边缘情况很重要：

 - 重复的价值观永远不会孤独
 - 连续的值彼此无效
 - 单元素数组总是产生一个孤独的数字
 - 值可能大到`10^6`，因此直接索引数组是可能的，但哈希映射更干净、更灵活

 核心挑战是有效地检查频率和邻居的存在。 

## 方法

 ### 蛮力方法

 强力解决方案将单独检查每个数字。 

对于每个元素：

 1. 统计它在数组中出现的次数
 2. 再次扫描数组，检查是否`x - 1`或者`x + 1`存在

 这保证了正确性，因为每个孤独条件都经过明确验证。 

然而，每个元素可能需要完整的数组扫描，导致`O(n^2)`时间复杂度。 

### 最佳观察

 关键的见解是我们只需要快速访问：

 - 每个数字出现的频率
 - 相邻号码是否存在

 哈希映射自然地支持在恒定的平均时间内执行这两种操作。 

我们首先构建频率图。 然后，对于每个不同的数字：

 - 它的频率必须等于`1`-`x - 1`一定不存在
 -`x + 1`一定不存在

 这将重复扫描转换为恒定时间查找。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2) | O(n^2) | O(1) | O(1) | 重复扫描数组|
 | 最佳 | O(n) | O(n) | 使用频率哈希图 |

 ## 算法演练

 1. 创建一个名为的哈希图`frequency`。 
2. 遍历数组一次并统计每个数字出现的次数。 
3. 初始化一个空的结果列表。 
4. 再次遍历数组中的数字。 
5. 对于每个数字`x`，检查三个条件：

 1.`frequency[x] == 1`2.`x - 1`不在地图上
 3.`x + 1`不在地图上
 6. 如果所有条件都为真，则附加`x`到结果。 
7. 返回结果列表。 

### 为什么它有效

 频率图存储有关元素出现和邻居存在的完整信息。 当一个数字的计数为 1 并且不存在相邻值时，它就是孤独的。 由于该算法精确检查每个数字的这些条件，因此包括所有孤独数字并排除所有非孤独数字。 

## Python 解决方案```python
from typing import List
from collections import Counter

class Solution:
    def findLonely(self, nums: List[int]) -> List[int]:
        frequency = Counter(nums)
        
        lonely_numbers = []
        
        for num in nums:
            if (
                frequency[num] == 1
                and (num - 1) not in frequency
                and (num + 1) not in frequency
            ):
                lonely_numbers.append(num)
        
        return lonely_numbers
```实现首先使用构建频率表`Counter`。 这提供了对出现次数的恒定时间访问。 

第二个循环根据孤独条件评估每个数字。 因为字典成员资格检查是平均的`O(1)`，整体算法保持线性。 

结果列表存储所有有效的孤独数字并在最后返回。 

## 解决方案```go
func findLonely(nums []int) []int {
    frequency := make(map[int]int)

    for _, num := range nums {
        frequency[num]++
    }

    result := []int{}

    for _, num := range nums {
        if frequency[num] == 1 {
            _, hasPrev := frequency[num-1]
            _, hasNext := frequency[num+1]

            if !hasPrev && !hasNext {
                result = append(result, num)
            }
        }
    }

    return result
}
```Go 解决方案使用从整数到计数的映射。 成员资格检查是使用逗号-ok 习惯用法执行的。 

切片使用动态扩展`append`。 与 Python 的字典不同，Go 在确定邻居值是否存在时需要显式的存在检查。

 ## 边缘情况

 当所有元素都是重复时，就会出现一种重要的边缘情况，例如`[1,1,1]`。 如果仅检查邻居，则有缺陷的实现可能会错误地包含一次出现。 该解决方案通过要求频率恰好等于 1 来正确拒绝所有重复项。 

另一种微妙的情况发生在连续值上，例如`[4,5]`。 这两个数字都出现一次，但都不是孤立的，因为每个数字都有一个相邻的邻居。 该实现显式检查两者`x - 1`和`x + 1`。 

第三个重要的情况是单元素数组。 由于该数字出现一次并且不存在相邻值，因此它一定是孤独的。 频率图可以正确处理缺失的邻居，因此该实现自然会返回单个值。
