[LeetCode 问题 2148](https://leetcode.com/problems/count-elements-with-strictly-smaller-and-greater-elements/)

 **难度：** 🟢简单
 **主题：** 数组、排序、计数

 ## 解决方案

 ## 问题理解

 问题给了我们一个整数数组`nums`并要求我们计算有多少元素满足特定的条件。 

对于一个元素`nums[i]`要进行计数，必须存在：

 - 数组中至少有一个元素严格小于`nums[i]`- 数组中至少有一个元素严格大于`nums[i]`也就是说，该元素不能是数组中的最小值，也不能是数组中的最大值。 

输入是整数列表，输出是表示有多少元素满足此要求的单个整数。 

例如，在数组中`[11,7,2,15]`：

 -`2`是最小值，所以它没有严格更小的元素
 -`15`是最大值，因此它没有严格更大的元素
 -`7`和`11`两者在数组中的某个位置都有较小和较大的值

 因此，答案是`2`。 

限制很小：

 -`1 <= nums.length <= 100`-`-10^5 <= nums[i] <= 10^5`由于数组大小最多为 100，即使是`O(n^2)`解决方案将足够快。 然而，这个问题有一个更简单、更有效的观察，从而产生线性时间解决方案。 

一些重要的边缘情况值得尽早识别：

 - 只有一个元素的数组不能包含任何有效元素。 
- 所有值都相等的数组也会产生`0`。 
- 不应计算重复的最小值或重复的最大值。 
- 如果重复的中间值同时存在较小值和较大值，则应全部计算在内。 

例如：

-`[1]`回报`0`-`[5,5,5]`回报`0`-`[1,2,2,3]`回报`2`，因为两者`2`s 有资格

 ## 方法

 ### 蛮力方法

 最直接的解决方案是单独检查每个元素并检查是否存在：

 - 另一个比它小的元素
 - 另一个比它大的元素

 对于每个元素`nums[i]`，我们再次扫描整个数组并跟踪是否找到了这两个条件。 如果两者都满意，我们就增加答案。 

这种方法是正确的，因为它明确验证了每个元素的问题定义。 但是，它对数组执行嵌套迭代。 

由于有`n`元素，每个元素可以扫描所有`n`再次元素，总复杂度变为`O(n^2)`。 

虽然这是可以接受的`n <= 100`，它不是最干净或最优的解决方案。 

### 最佳方法

 关键的观察是，当且仅当一个元素都不是时，该元素才是有效的：

 - 数组中的最小值
 - 也不是数组中的最大值

 为什么这是真的？ 

- 如果一个元素等于最小值，则不能存在严格更小的元素。 
- 如果某个元素等于最大值，则不能存在严格更大的元素。 
- 每个严格位于最小值和最大值之间的值都会自动满足这两个条件。 

所以问题就简化为：

 1. 求最小值。 
2. 找到最大值。 
3. 严格计算它们之间有多少个元素。 

这给出了一个简单的线性时间解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 对照所有其他元素检查每个元素 |
 | 最佳 | O(n) | O(1) | O(1) | 严格计算最小和最大之间的元素 |

 ## 算法演练

 ### 最优算法

 1.初始化两个变量，`minimum_value`和`maximum_value`，使用数组中的最小值和最大值。 

我们可以使用内置操作来有效地计算这些，例如`min(nums)`和`max(nums)`。 
2.初始化一个计数器变量`count`到`0`。 

这个变量将存储我们找到的有效元素的数量。 
3. 迭代中的每个元素`nums`。 

对于每个数字：

 - 检查是否严格大于`minimum_value`- 检查是否严格小于`maximum_value`4. 如果两个条件都成立，则增加`count`。 

这意味着当前元素在数组中的某处至少有一个较小的元素和至少一个较大的元素。 
5.处理完所有元素后，返回`count`。 

### 为什么它有效

 该算法依赖于一个简单的不变量：

 - 等于全局最小值的每个元素都缺少严格更小的值。 
- 每个等于全局最大值的元素都缺乏严格更大的值。 
- 严格来说，它们之间的每个元素都自动具有两者。 

由于该算法精确地计算了最小值和最大值之间的元素，因此它精确地计算了问题所需的有效元素。 

## Python 解决方案```python
from typing import List

class Solution:
    def countElements(self, nums: List[int]) -> int:
        minimum_value = min(nums)
        maximum_value = max(nums)

        count = 0

        for number in nums:
            if minimum_value < number < maximum_value:
                count += 1

        return count
```该实现首先计算数组中的最小值和最大值。 这两个值定义了有效元素的边界。 

接下来，代码迭代数组中的每个数字。 对于每个值，它会检查该数字是否严格位于最小值和最大值之间。 

如果是，则计数器递增。 

最后，该函数返回总计数。 

该实现使用恒定的额外空间，并且在计算最小值和最大值后仅执行一次遍历。 

## 解决方案```go
func countElements(nums []int) int {
    minimumValue := nums[0]
    maximumValue := nums[0]

    for _, number := range nums {
        if number < minimumValue {
            minimumValue = number
        }

        if number > maximumValue {
            maximumValue = number
        }
    }

    count := 0

    for _, number := range nums {
        if number > minimumValue && number < maximumValue {
            count++
        }
    }

    return count
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

由于 Go 没有提供内置的`min()`和`max()`对于切片函数，我们使用循环手动计算最小值和最大值。 

约束足够小，因此不必担心整数溢出。 该函数还安全地处理长度数组`1`，因为初始最小值和最大值都是从`nums[0]`。

 ## 边缘情况

 ### 只有一个元素的数组

 像这样的数组`[7]`不能包含任何有效元素，因为数组中根本没有其他值。 

如果没有正确执行这两个条件，幼稚的实现可能会意外地对单个元素进行计数。 当前的实现可以正确处理这个问题，因为最小值和最大值都是`7`，所以没有数字满足：```
minimum_value < number < maximum_value
```### 所有元素都相等

 考虑`[4,4,4,4]`。 

每个元素同时是最小值和最大值。 由于该问题需要严格更小和严格更大的元素，因此这些值都不符合条件。 

执行正确返回`0`因为没有元素严格位于最小值和最大值之间。 

### 重复的最小值或最大值

 考虑`[1,1,2,3,3]`。 

重复的`1`s 不应被计算在内，因为不存在严格小于的值`1`。 同样，重复的`3`s 不应被计算在内，因为不存在严格大于的值`3`。 

如果错误的实现仅检查不同索引的存在而不是严格不同的值，则它可能会错误地计算重复项。 

当前的解决方案通过直接与全局最小值和最大值进行比较，完全避免了这个问题。
