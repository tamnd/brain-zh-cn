[LeetCode 问题 2146](https://leetcode.com/problems/k-highest-ranked-items-within-a-price-range/)

 **难度：** 🟡 中等
 **主题：** 数组、广度优先搜索、排序、堆（优先级队列）、矩阵

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个代表商店布局的二维网格。 网格中的每个单元格都具有以下三种含义之一：

 -`0`表示单元格被墙挡住，无法穿过。 
-`1`表示单元格是空的并且可以穿过。 
- 任何大于的值`1`代表一个物品，其价值也是其价格。 

我们还得到：

 - 起始位置`start = [row, col]`- 有效的价格范围`pricing = [low, high]`- 一个整数`k`任务是找到顶部的位置`k`满足价格范围条件的商品，并根据多种规则对它们进行排名。 

排名优先级为：

 1.距起始单元的距离更短
 2. 价格更低
 3. 较小的行索引
 4. 较小的列索引

 该距离被定义为仅使用通过非壁细胞的上、下、左、右移动的最短路径长度。 

输出必须包含按排序顺序排列的所选项目的坐标。 

一个非常重要的细节是我们不仅仅是搜索附近的小区。 我们必须搜索价格在范围内的可到达的项目单元格`[low, high]`。 由于移动成本是均匀的，最短路径距离自然建议广度优先搜索。 

这些约束告诉我们一些重要的事情：

 -`m * n <= 10^5`，所以细胞总数最多为十万个。 
- 此大小对于从头开始重复运行最短路径搜索来说太大。 
- 因为所有边的权重相等，所以 BFS 是这里的最佳最短路径算法。 
- 我们必须尽可能避免对整个网格进行不必要的排序。 

一些边缘情况很重要：

 - 起始单元格本身可能包含有效项目。 
- 由于墙壁的原因，某些物品可能无法到达。 
- 可能少于`k`有效的可达项目。 
- 多个商品可能具有相同的距离和价格，需要行和列打破平局。 
- 网格可能包含大型开放区域，因此高效的访问跟踪至关重要。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试计算从起始位置到每个可到达单元格的最短路径。 一种方法是：

 1. 对于网格中的每个单元格：

 - 如果单元格包含价格范围内的有效商品：

 - 从起始位置运行 BFS 来计算其最短距离。 
2. 存储所有可到达的有效项目。 
3、按照排名规则进行排序。 
4.返回第一个`k`。 

这是可行的，因为 BFS 可以正确计算未加权网格中的最短路径。 

然而，这种方法效率极低。 如果有`O(m * n)`候选项，每个 BFS 取`O(m * n)`，则总复杂度变为：$$O((m \cdot n)^2)$$高达`10^5`细胞，这太慢了。 

### 最佳方法

 关键的观察结果是我们不需要多次运行 BFS。 

单个 BFS 从`start`已经计算出到每个可到达单元格的最短距离。 在这次遍历过程中：

 - 我们按照距离递增的顺序发现细胞。 
- 我们可以立即检查单元格是否包含有效项目。 
- 我们收集所有有效项目及其排名属性。 

BFS 完成后，我们根据以下条件对收集的项目进行排序：

 1. 距离
 2. 价格
 3. 行
 4. 专栏

 然后我们返回第一个`k`。 

这将昂贵的重复最短路径计算减少为一次遍历。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O((m × n)²) | O(m × n) | 为多个单元单独运行 BFS |
 | 最佳 | O(m × n + r log r) | O(m × n + r log r) | O(m × n) | 单次BFS，然后排序可达有效项 |

 这里，`r`是价格范围内可到达的商品数量。 

## 算法演练

 1.从起始位置开始初始化BFS遍历。 

我们使用队列是因为 BFS 逐级探索单元格，这自然会给出未加权网格中的最短路径距离。 
2. 创建一个访问矩阵。 

这可以防止多次重新访问同一单元，从而避免无限循环和冗余工作。 
3. 以距离开始BFS`0`。 

每个队列条目存储：

 - 行
 - 专栏
 - 距起点的距离
 4. 当队列不为空时：

 从队列中删除前面的单元格。 
5. 检查当前单元格是否包含有效项目。 

有效的项目必须：

 - 具有介于`low`和`high`- 触手可及

 如果有效，则存储：

 - 距离
 - 价格
 - 行
 - 专栏
 6. 探索所有四个相邻方向。 

对于每个邻居：

 - 确保它留在网格内
 - 确保它不是墙（`0`）
 - 确保它未被访问过

 如果有效：

 - 马克访问过
 - 推入队列，距离+1
 7. BFS完成后，对收集到的项目进行排序。 

Python 元组排序或 Go 自定义排序可以直接强制执行：

 - 距离上升
 - 价格上涨
 - 行升序
 - 列升序
 8. 提取第一个`k`坐标。 

如果少于`k`项目存在，返回所有项目。 

### 为什么它有效

 BFS 保证我们第一次到达某个单元时，就找到了它距起点的最短距离。 因此，每个收集项目的距离都是正确的。 

收集所有可达的有效项目后，按照所需的排名标准进行排序，与问题定义完全匹配。 由于排序顺序直接实现了排名规则，因此保证返回的列表是正确的。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def highestRankedKItems(
        self,
        grid: List[List[int]],
        pricing: List[int],
        start: List[int],
        k: int
    ) -> List[List[int]]:

        rows = len(grid)
        cols = len(grid[0])

        low, high = pricing

        visited = [[False] * cols for _ in range(rows)]

        queue = deque()
        start_row, start_col = start

        queue.append((start_row, start_col, 0))
        visited[start_row][start_col] = True

        items = []

        directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

        while queue:
            row, col, dist = queue.popleft()

            price = grid[row][col]

            if low <= price <= high:
                items.append((dist, price, row, col))

            for dr, dc in directions:
                new_row = row + dr
                new_col = col + dc

                if (
                    0 <= new_row < rows
                    and 0 <= new_col < cols
                    and not visited[new_row][new_col]
                    and grid[new_row][new_col] != 0
                ):
                    visited[new_row][new_col] = True
                    queue.append((new_row, new_col, dist + 1))

        items.sort()

        result = []

        for i in range(min(k, len(items))):
            result.append([items[i][2], items[i][3]])

        return result
```实现首先初始化 BFS 结构，包括队列和访问矩阵。 队列存储坐标以及当前最短距离。 

在遍历过程中，每个可到达的非壁单元都被访问一次。 每当单元格的值落在所需的定价范围内时，其排名信息就会存储为元组。 

元组排序在 Python 中非常方便，因为元组是按字典顺序比较的。 这意味着：```python
(dist, price, row, col)
```根据问题所需的确切排序规则自动排序。 

排序后，我们提取第一个`k`坐标并返回它们。 

## 解决方案```go
package main

import (
	"sort"
)

func highestRankedKItems(grid [][]int, pricing []int, start []int, k int) [][]int {
	rows := len(grid)
	cols := len(grid[0])

	low := pricing[0]
	high := pricing[1]

	type Node struct {
		row  int
		col  int
		dist int
	}

	queue := []Node{{start[0], start[1], 0}}

	visited := make([][]bool, rows)
	for i := range visited {
		visited[i] = make([]bool, cols)
	}

	visited[start[0]][start[1]] = true

	type Item struct {
		dist  int
		price int
		row   int
		col   int
	}

	items := []Item{}

	directions := [][]int{
		{1, 0},
		{-1, 0},
		{0, 1},
		{0, -1},
	}

	head := 0

	for head < len(queue) {
		current := queue[head]
		head++

		row := current.row
		col := current.col
		dist := current.dist

		price := grid[row][col]

		if low <= price && price <= high {
			items = append(items, Item{
				dist:  dist,
				price: price,
				row:   row,
				col:   col,
			})
		}

		for _, dir := range directions {
			newRow := row + dir[0]
			newCol := col + dir[1]

			if newRow >= 0 &&
				newRow < rows &&
				newCol >= 0 &&
				newCol < cols &&
				!visited[newRow][newCol] &&
				grid[newRow][newCol] != 0 {

				visited[newRow][newCol] = true

				queue = append(queue, Node{
					row:  newRow,
					col:  newCol,
					dist: dist + 1,
				})
			}
		}
	}

	sort.Slice(items, func(i, j int) bool {
		if items[i].dist != items[j].dist {
			return items[i].dist < items[j].dist
		}

		if items[i].price != items[j].price {
			return items[i].price < items[j].price
		}

		if items[i].row != items[j].row {
			return items[i].row < items[j].row
		}

		return items[i].col < items[j].col
	})

	limit := k
	if len(items) < k {
		limit = len(items)
	}

	result := make([][]int, 0, limit)

	for i := 0; i < limit; i++ {
		result = append(result, []int{
			items[i].row,
			items[i].col,
		})
	}

	return result
}
```Go 实现遵循与 Python 版本相同的 BFS 逻辑。 

一个显着的区别是队列处理。 我们不会重复删除切片的第一个元素（这样效率很低），而是维护一个`head`在切片中前进的索引。 

排序还需要自定义比较器，因为 Go 不像 Python 那样提供自动元组比较。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(m × n + r log r) | O(m × n + r log r) | BFS 访问每个单元一次，对可达项目进行排序的成本为 O(r log r) |

    def highestRankedKItems(
        self,
        grid: List[List[int]],
        pricing: List[int],
        start: List[int],
        k: int
    ) -> List[List[int]]:

        from collections import deque

        rows = len(grid)
        cols = len(grid[0])

        low, high = pricing

        visited = [[False] * cols for _ in range(rows)]

        queue = deque([(start[0], start[1], 0)])
        visited[start[0]][start[1]] = True

        items = []

        directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

        while queue:
            row, col, dist = queue.popleft()

            if low <= grid[row][col] <= high:

 ## 边缘情况

 当起始单元格本身包含有效项时，就会出现一种重要的边缘情况。 有缺陷的实现可能只检查相邻单元格而忘记处理起始位置。 在此解决方案中，起始单元会立即插入 BFS 队列，并像其他单元一样进行处理，因此如果其价格位于有效范围内，它就会被正确包含在内。 

另一个重要的边缘情况涉及无法访问的项目。 某些项目单元在技术上可能满足定价要求，但由于墙壁阻挡了所有可能的路径而无法到达。 由于 BFS 仅遍历非墙可达单元，因此无法访问的项目永远不会被访问，因此永远不会添加到结果列表中。 

第三个微妙的边缘情况涉及排名关系。 多个商品可能具有相同的距离，甚至相同的价格。 在这种情况下，行和列的顺序变得至关重要。 该实现通过将排名信息存储在精确反映所需排名顺序的可排序元组或结构化比较器中来避免错误：`(distance, price, row, column)`。 

最后的边缘情况发生在以下情况：`k`超过有效可达项目的数量。 两种实现都不会尝试访问不存在的元素，而是使用以下方法安全地返回所有可用项目`min(k, len(items))`Python 中或 Go 中的调整限制。
