[LeetCode 问题 2189](https://leetcode.com/problems/number-of-ways-to-build-house-of-cards/)

 **难度：** 🟡 中等
 **主题：** 数学、动态规划

 ## 解决方案

 ## 问题理解

 问题是要求我们准确地计算建造纸牌屋的不同方法的数量`n`牌。 每个房子由一排或多排三角形组成，这些三角形是通过将两张牌倾斜在一起而形成的，水平牌放置在相邻三角形之间。 规则强制要求较高的三角形行必须位于下面一行的水平卡片上，并且三角形在每行中从左到右放置。 如果两个房子中任何一行的牌数不同，则两个房子是不同的。 

输入`n`是 1 到 500 之间的整数，表示可用卡的总数。 输出是所有有效排列的计数`n`牌。 小输入，例如`n = 2`或者`n = 4`是测试最小和不可行结构的边缘情况。 这些约束表明，简单的组合方法可能太慢，需要动态规划或数学解决方案。 

重要的边缘情况包括`n = 2`（形成单个三角形的最少卡片），`n = 4`（不足以形成下一行），以及更大的值，例如`n = 500`效率至关重要的地方。 

## 方法

 蛮力方法将尝试枚举可以形成的行和三角形的所有可能组合`n`牌。 对于每个可能的第一行，您将递归地尝试所有有效的方法来使用剩余的卡构建剩余的行。 虽然这种方法最终会产生正确的答案，但由于可能性呈指数增长，因此在计算上是不可行的。 和`n`达到 500 时，递归将花费非常长的时间。 

最佳方法依赖于动态规划。 关键的观察是一排所需的卡片数量`k`三角形遵循以下公式`row_cards = 3*k - 1`（每个三角形两张卡加上每对之间一张水平卡）。 房屋的累计卡牌张数`1 + 2 + ... + h`每行的三角形形成严格递增的序列。 通过使用一维 DP 数组，其中`dp[i]`精确计算建造房屋的方法数量`i`卡，我们迭代每个可能的行大小并更新 DP 数组。 这避免了冗余计算并有效地计算任何问题的答案`n`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 所有行组合的递归枚举，对于 n = 500 来说太慢 |
 | 动态规划| O(n * sqrt(n)) | O(n * sqrt(n)) | O(n) | DP 迭代可能的行大小和卡片数量，对于 n ≤ 500 有效 |

 ## 算法演练

 1. 计算每行三角形所需的卡片数量。 为了`k`三角形，一行需要`3*k - 1`牌。 生成可以容纳的所有可能的行大小`n`牌。 
2.初始化一个DP数组`dp`尺寸的`n + 1`全为零。`dp[i]`将存储使用精确建造房屋的方法数量`i`牌。 
3. 设置基本情况`dp[0] = 1`，代表用零卡建造房屋（空结构）的一种方法。 
4. 迭代每行大小`cards_needed`。 对于每个`cards_needed`, 向后迭代`n`下降到`cards_needed`, 更新`dp[i] += dp[i - cards_needed]`。 这确保每个组合仅计数一次。 
5. 处理完所有行大小后，`dp[n]`包含精确使用的不同房屋的数量`n`牌。 
6. 返回`dp[n]`作为最终结果。 

**为什么有效**：每个行大小对应一个有效的行配置。 通过从较少数量的卡片迭代构建，DP 确保所有行组合的总和为`n`只计算一次。 向后迭代可防止重复计算同一行多次重复使用的情况。 

## Python 解决方案```python
class Solution:
    def houseOfCards(self, n: int) -> int:
        # Precompute the number of cards needed for each row
        row_cards = []
        k = 1
        while True:
            cards_needed = 3 * k - 1
            if cards_needed > n:
                break
            row_cards.append(cards_needed)
            k += 1

        # Initialize DP array
        dp = [0] * (n + 1)
        dp[0] = 1  # Base case: 1 way to use 0 cards

        # Fill DP table
        for cards in row_cards:
            for i in range(n, cards - 1, -1):
                dp[i] += dp[i - cards]

        return dp[n]
```Python 实现首先预先计算所有可能的行大小，然后使用自下而上的动态编程方法来计算组合。 向后迭代可确保每次求和计算时只考虑每行一次。 

## 解决方案```go
func houseOfCards(n int) int {
    // Precompute row sizes
    rowCards := []int{}
    for k := 1; ; k++ {
        cardsNeeded := 3*k - 1
        if cardsNeeded > n {
            break
        }
        rowCards = append(rowCards, cardsNeeded)
    }

    // Initialize DP array
    dp := make([]int, n+1)
    dp[0] = 1

    // Fill DP table
    for _, cards := range rowCards {
        for i := n; i >= cards; i-- {
            dp[i] += dp[i-cards]
        }
    }

    return dp[n]
}
```Go 版本镜像了 Python 解决方案，使用切片和向后迭代来填充 DP 数组。 逻辑是相同的，只是仔细处理切片索引。 

## 工作示例

 **示例 1：n = 16**

 可能的行大小：`[2, 5, 8, 11, 14]`| 我（卡片）| dp[i] 更新 |
 | ---| ---|
 | 2 | dp[2] = dp[0] + dp[2] = 1 |
 | 5 | dp[5] = dp[0] + dp[5] = 1, dp[7] = dp[2] + dp[7] = 1 |
 | 8 | dp[8] = dp[0] + dp[8] = 1、dp[10] = dp[2] + dp[10] = 1、dp[13] = dp[5] + dp[13] = 1、dp[16] = dp[8] + dp[16] = 1 + 上一个=1 => 2 |`dp[16] = 2`，正如预期的那样。 

**示例 2：n = 2**

 行大小：`[2]`

`dp[2] = dp[0] + dp[2] = 1`输出=1

 **示例 3：n = 4**

 行大小：`[2]`

`dp[4] = dp[2] + dp[4] = 1 + 0 = 1`但这在第二行中使用的卡片较少，因此只有完整 4 张卡片的有效结构才是 0。因此输出 = 0

 ## 边缘情况

 **边缘情况 1：最少牌数 (n = 1)**

 单张牌不能组成任何三角形。 DP 正确返回 0，因为没有适合的行大小。 

**边缘情况 2：精确的单行匹配 (n = 2, n = 5, n = 8)**

 该算法可以正确计算总卡片数与一行或多行完全匹配的配置。 向后迭代可确保正确的累积。 

**边缘情况 3：大 n (n = 500)**

 由于 O(n * sqrt(n)) 复杂性，DP 方法可以有效扩展，避免递归或组合爆炸。 所有中间和都在 DP 阵列中进行跟踪，不会重复。 

这确保了整个过程的正确性
