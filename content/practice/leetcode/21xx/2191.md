[LeetCode 问题 2191](https://leetcode.com/problems/sort-the-jumbled-numbers/)

 **难度：** 🟡 中等
 **主题：** 数组、排序

 ## 解决方案

 ## 问题理解

 该问题要求我们根据**自定义数字映射**而不是它们的自然数值对整数数组进行排序。 从 0 到 9 的每个数字都有一个映射值，在`mapping`数组，以及中的每个数字`nums`可以通过根据此映射替换每个数字来“转换”。 关键是排序必须使用这些转换后的值进行比较，但原始数字本身仍保留在结果中。 此外，如果两个数字映射到相同的转换值，则必须保留它们在输入中的相对顺序，这使得这是一个**稳定排序**问题。 

例如，如果`mapping[3] = 0`， 任何`3`在一个数字中变成`0`在映射值中。 如果两个数字映射到相同的值，则它们的原始顺序为`nums`被保留。 

约束告诉我们数组`mapping`始终有 10 个唯一数字，并且`nums`最多可包含 30,000 个元素，每个元素最多不到 10 亿个。 这意味着算法需要高效，但不需要对非常大的数字进行极端优化，因为 Python 和 Go 自然地处理大整数。 

重要的边缘情况包括转换后映射到前导零的数字、映射后相同的数字以及接近 10^9 的非常大的数字。 

## 方法

 **暴力方法**很简单：对于每个数字，计算其映射值，然后使用标准排序函数根据这些映射值对数字进行排序。 虽然正确，但这种方法可能效率稍低，因为如果不缓存，它需要多次重新计算映射值，并且处理大量数字可能会因字符串转换而带来较小的开销。 

**最佳方法**利用带有预先计算的映射值的**稳定排序**。 通过将每个数字转换为其映射值一次并存储一个元组`(mapped_value, original_number)`，我们可以根据映射值对数组进行排序，并按排序顺序检索原始数字。 这确保了稳定性，无需额外处理，并避免重复的映射计算。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n log n * d) | O(n log n * d) | O(n) | 在比较过程中动态计算映射值，每个数字可能多次计算，其中`d`是最大数中的位数 |
 | 最佳| O(n log n * d) | O(n log n * d) | O(n) | 预先计算所有数字的映射值，使用稳定排序对它们进行排序，然后提取原始数字 |

 ## 算法演练

 1. **预先计算映射值**：对于中的每个数字`nums`，将其转换为字符串并替换每个数字`i`和`mapping[i]`。 将映射的字符串转换回整数。 这可确保正确处理带有前导零的数字。 
2. **将映射值与原始数字配对**：创建元组列表`(mapped_value, original_number)`对于每个数字`nums`。 这使我们能够根据映射值进行排序，同时保持原始数字不变。 
3. **稳定排序**：对元组列表进行排序`mapped_value`。 使用稳定的排序算法来保留具有相等映射值的数字的相对顺序。 
4. **提取排序后的原始数字**：排序后，从每个元组中提取第二个元素，得到最终结果。 

**为什么有效**：每个数字只转换一次，并且排序仅基于转换后的值。 稳定性确保保留具有相同映射值的数字的相对顺序，满足所有问题约束。 

## Python 解决方案```python
from typing import List

class Solution:
    def sortJumbled(self, mapping: List[int], nums: List[int]) -> List[int]:
        def get_mapped_value(num: int) -> int:
            mapped_digits = ''.join(str(mapping[int(digit)]) for digit in str(num))
            return int(mapped_digits)
        
        # Pair each number with its mapped value
        mapped_pairs = [(get_mapped_value(num), num) for num in nums]
        
        # Stable sort based on mapped value
        mapped_pairs.sort(key=lambda x: x[0])
        
        # Extract the original numbers in the new order
        return [num for _, num in mapped_pairs]
```功能`get_mapped_value`通过迭代其数字将每个整数转换为其映射值。 然后，我们形成将映射值与原始数字配对的元组。 使用对这些元组进行排序`sort`使用密钥可确保稳定的排序。 最后，我们只提取结果的原始数字。 

## 解决方案```go
import (
	"sort"
	"strconv"
)

func sortJumbled(mapping []int, nums []int) []int {
	type pair struct {
		mapped int
		original int
	}
	
	getMappedValue := func(num int) int {
		numStr := strconv.Itoa(num)
		mappedStr := ""
		for _, c := range numStr {
			digit := int(c - '0')
			mappedStr += strconv.Itoa(mapping[digit])
		}
		mappedVal, _ := strconv.Atoi(mappedStr)
		return mappedVal
	}
	
	pairs := make([]pair, len(nums))
	for i, num := range nums {
		pairs[i] = pair{getMappedValue(num), num}
	}
	
	sort.SliceStable(pairs, func(i, j int) bool {
		return pairs[i].mapped < pairs[j].mapped
	})
	
	result := make([]int, len(nums))
	for i, p := range pairs {
		result[i] = p.original
	}
	return result
}
```在 Go 中，我们使用自定义结构体`pair`存储映射值和原始值。`strconv`函数处理字符串转换。`sort.SliceStable`确保稳定性。 该逻辑反映了 Python 解决方案，适用于 Go 的类型系统和字符串处理。

 | ---| ---| ---|
 | 789 | 789 789 | 789 恒等映射|
 | 456 | 456 456 | 456 恒等映射|
 | 123 | 123 123 | 123 恒等映射|

 排序后：`[123,456,789]`。

 ## 边缘情况

 一种重要的边缘情况是映射到**前导零**的数字。 例如，如果 3 映射到 0，则数字 38 变为 07。转换回整数会删除前导零，与其他数字进行比较是正确的。 

另一个边缘情况是**具有相同映射值的数字**。 稳定性在这里至关重要； 像 338 和 38 这样都映射到 7 的数字必须保持其原始输入顺序。 该算法通过使用稳定排序来实现这一点。 

第三种边缘情况是**单元素数组**。 该算法必须正确处理只有一个数字的数组，并按原样返回它而不会出现错误。 映射功能仍然有效，但排序不起作用。 

这些边缘情况通过整数转换（删除前导零）、稳定排序和正确的元组/对表示在解决方案中直接处理。
