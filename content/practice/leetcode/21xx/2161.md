 **难度：** 🟡 中等
 **主题：** 数组、两个指针、模拟

 ## 解决方案

 ## 问题理解

 这个问题要求我们围绕给定的值重新排列数组`pivot`值，同时保留某些组内的相对顺序。 

我们得到一个整数数组`nums`和一个整数`pivot`。 目标是将数组重新组织为三个连续的部分：

 1.所有小于的元素`pivot`2. 所有元素都等于`pivot`3.所有大于的元素`pivot`重要的细节是，对于小于枢轴的元素和大于枢轴的元素，重新排列必须是稳定的。 稳定性是指如果两个元素最初以某种顺序出现，那么它们在重新排列后必须保持相同的顺序。 

例如，如果小于主元的元素在原始数组中显示为：```
9, 5, 3
```那么它们必须完全按照最终答案中的顺序出现。 我们不能将它们重新排序为：```
3, 5, 9
```同样的规则适用于大于主元的元素。 

这些约束告诉我们一些重要的事情：

 - 数组长度可以大到`10^5`- 值可能为负
 - 保证枢轴存在于数组中

 由于数组可能非常大，因此低效的二次解会太慢。 我们需要一个线性或近线性的解决方案。 

有几种边缘情况值得尽早考虑：

 - 每个元素都等于主元的数组
 - 所有元素都小于主元的数组
 - 所有元素都大于主元的数组
 - 包含许多重复主值的数组
 - 包含负数的数组
 - 长度数组`1`该问题保证了数组中存在主元，因此我们永远不需要处理主元不存在的情况。 

## 方法

 ### 蛮力方法

 蛮力策略会尝试通过交换或移动元素来重复将元素移动到正确的区域。 

一种可能的实现是：

 - 从左到右扫描数组
 - 每当一个元素小于枢轴时，将其向前移动
 - 每当一个元素大于枢轴时，将其向后移动
 - 小心地移动元素以保持相对顺序

 这种方法可以产生正确的答案，因为它在保持稳定性的同时明确构建了所需的排序。 

然而，在重复插入或移位期间保持相对顺序的成本很高。 每次插入可能需要移动许多元素，导致最坏情况的时间复杂度为`O(n^2)`。 

和`n`最多`100000`，二次行为变得太慢。 

### 最佳方法

 关键的观察结果是最终的数组只是三个稳定组的串联：

 1. 小于主元的元素
 2. 等于主元的元素
 3. 大于主元的元素

 我们实际上并不需要复杂的就地重排。 相反，我们可以执行线性扫描并将元素收集到单独的列表中。 

因为我们从左到右遍历原始数组，所以每个组内的相对顺序会自动保留。 

最后，我们将三个列表连接在一起以产生最终答案。 

这种方法既简单又有效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 使用重复的移位或插入操作 |
 | 最佳| O(n) | O(n) | 使用三个临时列表的稳定分区|

 ## 算法演练

 ### 最优算法

 1. 创建三个空列表：

 -`less`-`equal`-`greater`这些列表将根据元素与枢轴的关系来存储元素。 
2. 从左到右遍历数组。 

按原始顺序处理元素至关重要，因为该问题需要稳定的排序。 
3. 对于每个元素：

 - 如果该值小于主元，则将其附加到`less`- 如果该值等于主元，则将其附加到`equal`- 如果该值大于主元，则将其附加到`greater`4.处理完所有元素后：

 - 按以下顺序连接列表：

 -`less + equal + greater`5. 返回结果数组。 

### 为什么它有效

 该算法在遍历过程中保持一个简单的不变量：

 -`less`包含所有先前看到的小于主元的元素，按原始顺序排列
 -`equal`包含所有以前看到的枢轴值，按原始顺序排列
 -`greater`包含所有先前看到的大于枢轴的元素，按原始顺序排列

 由于元素按照遇到的顺序附加，因此会自动保持稳定性。 连接这三个组就产生了所需的最终排列。 

## Python 解决方案```python
from typing import List

class Solution:
    def pivotArray(self, nums: List[int], pivot: int) -> List[int]:
        less = []
        equal = []
        greater = []

        for value in nums:
            if value < pivot:
                less.append(value)
            elif value == pivot:
                equal.append(value)
            else:
                greater.append(value)

        return less + equal + greater
```实现直接遵循前面描述的算法。 

我们首先初始化三个列表来表示最终数组的三个所需区域。 

接下来，我们迭代`nums`正好一次。 对于每个值，我们将其与主元进行比较并将其附加到适当的列表中。 由于追加会保留插入顺序，因此会自动保持稳定性。 

最后，我们将三个列表连接在一起并返回结果。 

代码很简洁，因为Python列表操作天然支持这种类型的稳定分区。 

## 解决方案```go
func pivotArray(nums []int, pivot int) []int {
    less := []int{}
    equal := []int{}
    greater := []int{}

    for _, value := range nums {
        if value < pivot {
            less = append(less, value)
        } else if value == pivot {
            equal = append(equal, value)
        } else {
            greater = append(greater, value)
        }
    }

    result := []int{}
    result = append(result, less...)
    result = append(result, equal...)
    result = append(result, greater...)

    return result
}
```Go 实现在概念上与 Python 版本相同。 

一个小的区别是 Go 不支持使用`+`切片运算符。 相反，我们使用重复的`append`使用可变参数切片扩展语法进行操作：```go
append(result, less...)
```Go 切片可以根据需要动态调整大小，这使得它们非常适合解决这个问题。 

不存在整数溢出问题，因为我们只比较和复制值。

 ## 边缘情况

 当每个元素都等于主元时，就会出现一种重要的边缘情况。 在这种情况下，数组应该保持不变。 有缺陷的实现可能会意外地重新排序元素或错误处理空分区。 我们的实现自然地处理了这个问题，因为所有值都被附加到`equal`列表，而其他列表保持为空。 

另一个重要的情况是所有元素完全属于枢轴的一侧。 例如：```
nums = [1,2,3]
pivot = 10
```在这里，每个元素都小于主元。 某些实现可能会错误地假设所有三个组都包含值。 我们的解决方案可以正常工作，因为空列表可以安全地连接。 

第三个重要的边缘情况涉及保持稳定性。 考虑：```
nums = [8,6,7,5,3,0,9]
pivot = 5
```大于主元的元素最初显示为：```
8,6,7,9
```不稳定的分区算法可能会意外地对它们重新排序。 我们的实现保留了它们的顺序，因为元素在从左到右的遍历过程中按顺序附加。 

另一个微妙的情况涉及整个数组中出现重复的主元值。 例如：```
nums = [5,1,5,2,5,3]
```最终的安排必须将所有主元值放在一起，同时保留非主元组的顺序。 三列表方法自动保证了这一点。
