[LeetCode 第 2166 题](https://leetcode.com/problems/design-bitset/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、字符串、设计

 ## 解决方案

 ## 问题理解

 这个问题要求我们设计一个自定义的 Bitset 数据结构，它能够有效地支持多种操作。 位集只是一个二进制值序列，其中每个位置存储`0`或者`1`。 

我们在初始化期间被赋予固定大小，并且最初每个位都设置为`0`。 之后，该类必须支持修改或查询位集的操作。 

操作是：

 -`fix(idx)`设置索引处的位`idx`到`1`-`unfix(idx)`设置索引处的位`idx`到`0`-`flip()`反转结构中的每一位
 -`all()`检查每一位是否是`1`-`one()`检查是否至少有一位是`1`-`count()`返回当前有多少位`1`-`toString()`以字符串形式返回完整的位集

 问题的重要部分不仅是正确性，而且是效率。 约束允许最多`10^5`操作，这意味着简单的实现很容易变得太慢。 

一个特别危险的操作是`flip()`。 如果我们每次都物理地反转每一位`flip()`被调用，那么每次翻转花费`O(n)`。 由于可能存在多次翻转，这可能会导致`O(n * operations)`复杂性，对于约束而言成本太高。 

该问题还保证了`toString()`最多被调用 5 次。 这非常重要，因为生成整个字符串表示自然会花费`O(n)`，并且该问题有意限制这种昂贵操作发生的频率。 

一些边缘情况很重要：

 - 通话`fix()`在已经存在的一点上`1`- 通话`unfix()`在已经存在的一点上`0`- 多次连续`flip()`运营
 - 大小的位集`1`- 所有位都变成的情况`1`或者所有位都变成`0`- 确保翻转后计数保持正确

 关键的挑战是设计数据结构，以便所有频繁操作都能在恒定时间内运行。 

## 方法

 ### 蛮力方法

 最直接的解决方案是将位集存储为字符或整数数组，并逐字执行每个操作。 

例如：

-`fix(idx)`直接将值设置为`idx`到`1`-`unfix(idx)`直接设置为`0`-`flip()`迭代整个数组并切换每一位
 -`all()`扫描整个数组寻找`0`-`one()`扫描一个`1`-`count()`每次调用时都会计算所有1
 -`toString()`将数组连接成字符串

 这种方法很简单并且显然是正确的，因为每个操作都直接操纵位集的实际状态。 

然而，性能较差。 类似的操作`flip()`,`all()`,`one()`， 和`count()`可能都需要遍历整个数组。 高达`10^5`操作，这变得太慢了。 

### 最佳解决方案的关键见解

 关键的观察是，我们实际上不需要在物理上翻转每一位`flip()`被称为。 

相反，我们可以维护：

 - 原始存储位
 - 一个布尔标志，指示位集是否逻辑翻转
 - 当前有多少位的运行计数`1`这种惰性翻转策略允许`flip()`成为一个`O(1)`手术。 

例如：

 - 假设存储的数组是`"01010"`- 如果`flipped = false`，逻辑位集是`"01010"`- 如果`flipped = true`，逻辑位集变为`"10101"`我们在翻转过程中从不物理修改每个元素。 我们只切换标志。 

每当我们访问一个位时，我们都会根据翻转标志来解释它。 

这个想法极大地提高了性能，因为：

 -`flip()`变为常数时间
 -`all()`,`one()`， 和`count()`使用维护计数变为常数时间
 - 仅`toString()`需要遍历整个数组

 自从`toString()`最多被调用5次，这是完全可以接受的。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 最坏情况下每个操作的 O(n) | O(n) | 频繁地物理翻转和扫描整个阵列 |
 | 最佳| 对于大多数操作，O(1)，对于 O(n)`toString()`| O(n) | 使用延迟翻转并维护个数 |

 ## 算法演练

 1. 使用位数组初始化位集，全部设置为`0`。 

我们将这些位存储在列表或切片中。 我们还维护：

 -`flipped`, 一个布尔值，指示逻辑状态是否反转
 -`ones`，当前逻辑数`1`位
 -`size`，总位数
 2. 什么时候`fix(idx)`被调用，确定当前逻辑值`idx`。 

由于翻转，存储的位可能与逻辑位不匹配。 如果：

-`flipped == false`，存储的位是实际位
 -`flipped == true`，逻辑位反转

 如果逻辑位已经是`1`，什么也不做。 

否则，修改存储的值，使逻辑位变为`1`，并增加`ones`。 
3. 什么时候`unfix(idx)`被调用，再次确定逻辑值。 

如果逻辑位已经是`0`，什么也不做。 

否则，修改存储的值，使逻辑位变为`0`，并递减`ones`。 
4. 什么时候`flip()`被调用时，不迭代数组。 

相反：

 - 切换`flipped`旗帜
 - 更新`ones`到`size - ones`这是有效的，因为每个`1`变成`0`，以及每一个`0`变成`1`。 
5. 对于`all()`，只需检查是否`ones == size`。 

由于我们始终保持正确的计数，因此无需扫描。 
6. 对于`one()`，检查是否`ones > 0`。 
7. 对于`count()`， 返回`ones`。 
8.为了`toString()`，构建每一位的逻辑表示。 

遍历存储的数组并根据以下值解释每个值`flipped`旗帜。 

### 为什么它有效

 核心不变量是存储的数组与`flipped`flag 始终唯一地确定逻辑位集。 

如果`flipped == false`，逻辑值等于存储值。 

如果`flipped == true`，逻辑值等于存储值的倒数。 

此外，`ones`变量总是跟踪逻辑的数量`1`位。 每个操作都会一致地更新此计数，因此查询操作永远不需要扫描整个结构。 

由于每次操作后都会保留这些不变量，因此实现是正确的。 

## Python 解决方案```python
class Bitset:

    def __init__(self, size: int):
        self.bits = [0] * size
        self.size = size
        self.flipped = False
        self.ones = 0

    def fix(self, idx: int) -> None:
        current = self.bits[idx]

        logical_value = current ^ self.flipped

        if logical_value == 1:
            return

        self.bits[idx] ^= 1
        self.ones += 1

    def unfix(self, idx: int) -> None:
        current = self.bits[idx]

        logical_value = current ^ self.flipped

        if logical_value == 0:
            return

        self.bits[idx] ^= 1
        self.ones -= 1

    def flip(self) -> None:
        self.flipped = not self.flipped
        self.ones = self.size - self.ones

    def all(self) -> bool:
        return self.ones == self.size

    def one(self) -> bool:
        return self.ones > 0

    def count(self) -> int:
        return self.ones

    def toString(self) -> str:
        result = []

        for bit in self.bits:
            logical_bit = bit ^ self.flipped
            result.append(str(logical_bit))

        return "".join(result)
```该实现将原始位存储在`self.bits`。 这些位并不总是可见的逻辑位，因为结构可能会翻转。 

这`flipped`布尔值跟踪整个位集是否逻辑反转。 我们不是在翻转过程中物理地改变每一位，而是使用 XOR 动态地解释每一位。 

表达式：```python
bit ^ self.flipped
```计算逻辑值：

 - 如果`flipped`是`False`, XOR 不改变任何内容
 - 如果`flipped`是`True`, XOR 反转该位

 的`fix()`和`unfix()`方法首先确定当前逻辑值。 他们仅在需要真正更改时才修改该位。 这可以防止错误更新`ones`柜台。 

这`flip()`操作非常高效，因为它仅切换布尔值并以数学方式重新计算 1 的数量。 

这`toString()`方法是唯一遍历整个数组的操作，这是可以接受的，因为该问题保证很少调用它。 

## 解决方案```go
package main

import "strings"

type Bitset struct {
	bits     []int
	size     int
	flipped  bool
	ones     int
}

func Constructor(size int) Bitset {
	return Bitset{
		bits:    make([]int, size),
		size:    size,
		flipped: false,
		ones:    0,
	}
}

func (this *Bitset) Fix(idx int) {
	logicalValue := this.bits[idx]

	if this.flipped {
		logicalValue ^= 1
	}

	if logicalValue == 1 {
		return
	}

	this.bits[idx] ^= 1
	this.ones++
}

func (this *Bitset) Unfix(idx int) {
	logicalValue := this.bits[idx]

	if this.flipped {
		logicalValue ^= 1
	}

	if logicalValue == 0 {
		return
	}

	this.bits[idx] ^= 1
	this.ones--
}

func (this *Bitset) Flip() {
	this.flipped = !this.flipped
	this.ones = this.size - this.ones
}

func (this *Bitset) All() bool {
	return this.ones == this.size
}

func (this *Bitset) One() bool {
	return this.ones > 0
}

func (this *Bitset) Count() int {
	return this.ones
}

func (this *Bitset) ToString() string {
	var builder strings.Builder

	for _, bit := range this.bits {
		logicalBit := bit

		if this.flipped {
			logicalBit ^= 1
		}

		if logicalBit == 1 {
			builder.WriteByte('1')
		} else {
			builder.WriteByte('0')
		}
	}

	return builder.String()
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

一个显着的区别是字符串结构。 在 Go 中，重复的字符串连接效率很低，因为字符串是不可变的。 所以，`strings.Builder`用于有效构建最终的位集字符串。 

位存储使用`[]int`为了简单起见。 由于仅`0`和`1`已存储，这已经足够了。 

Go 还需要用于修改结构的方法的显式指针接收器。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`fix()`被调用在逻辑上已经存在的位上`1`。 幼稚的实现可能会再次增加计数，从而产生不正确的结果。 该解决方案通过首先计算该位的逻辑值并在不需要更改时立即返回来避免这种情况。 

另一个微妙的情况涉及重复`flip()`运营。 如果实现每次都物理地翻转所有位，则性能会显着降低。 此外，如果计数未正确更新，重复反转很容易引入错误。 惰性翻转方法通过切换单个布尔值并重新计算计数来干净地处理这个问题`size - ones`。 

第三个重要的边缘情况是位集大小为`1`。 小型结构通常会暴露隐藏在较大示例中的索引或逻辑错误。 即使对于单个位，该实现也能正确工作，因为所有操作都依赖于一致的逻辑解释而不是关于大小的假设。 

另一个棘手的情况发生在`unfix()`翻转后调用。 存储的位可能看起来是`0`，但逻辑上它可以代表`1`因为位集被翻转了。 该实现始终在决定是否需要修改之前计算逻辑值，从而确保正确性，无论之前发生了多少次翻转。
