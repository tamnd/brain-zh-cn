[LeetCode 问题 2137](https://leetcode.com/problems/pour-water- Between-buckets-to-make-water-levels-equal/)

 **难度：** 🟡 中等
 **主题：** 数组、二分查找

 ## 解决方案

 ## 问题理解

 这个问题要求我们平衡一系列水桶中的水位，同时考虑溢出损失。 每个桶最初包含一些在数组中给出的水量`buckets`，每次我们将水从一个桶倒入另一个桶时，水的百分比，`loss`，丢失了。 目标是确定在最佳重新分配水后所有水桶可以达到的**最大可能水位**。 

输入`buckets`是表示每个桶中水的加仑数的整数列表。 这`loss`是 0 到 99 之间的整数，表示每次倾倒操作期间水损失的百分比。 输出是一个浮点数，表示所有桶的最大均衡水位，精确到`10^-5`。 

约束表明最多可以有`10^5`桶，每个桶最多包含`10^5`加仑。 这种规模使得任何模拟每个人的方法都不切实际。 要考虑的边缘情况包括所有已经相等的水桶、零损失、最大损失以及水量为零的水桶。 

## 方法

 ### 蛮力

 暴力方法将涉及模拟桶之间每一次可能的倾倒。 对于每一对水桶，将水从多的水桶倒到少的水桶中，计算损失，直到所有水桶平衡。 这种方法在概念上是正确的，但效率低下：它需要潜在的`O(n^2)`每次迭代的操作数，可能需要多次迭代才能收敛。 考虑到约束条件（`n`最多`10^5`），这太慢了。 

### 最佳方法

 最佳解决方案依赖于**最终水位的二分搜索**。 我们不是直接模拟浇注，而是测试候选水位`target`并检查考虑到桶数和损失是否可以实现。 

关键的见解是对于每个存储桶：

 - 如果桶里的水多于`target`，它可以提供`excess = bucket - target`加仑。 
- 如果桶里的水少于`target`，它需要`deficit = target - bucket`加仑以达到目标。 
- 因为倾倒会损失一定比例的水，`deficit / (1 - loss/100)`是我们需要从其他桶中提取以满足这一赤字的实际金额。 

如果超额总额大于或等于有效赤字总额，则可以实现目标水平。 这允许我们在水位范围内使用二分搜索`[0, max(buckets)]`精度为`1e-6`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n^2 * 迭代) | O(1) | O(1) | 模拟每次浇注； 对于大 n 来说太慢 |
 | 最佳| O(n * log(max_bucket / precision)) | O(n * log(max_bucket / precision)) | O(1) | O(1) | 水位二分查找； 每张支票进行线性扫描|

 ## 算法演练

 1. 初始化搜索范围`low = 0`和`high = max(buckets)`。 
2. 设置`precision = 1e-6`用于停止标准。 
3.同时`high - low > precision`，执行二分查找：

 1. 计算`mid = (low + high) / 2`作为候选目标水位。 
2. 初始化`excess = 0`和`required = 0`。 
3. 对于每个桶：

 - 如果`bucket > mid`， 添加`bucket - mid`到`excess`。 
- 如果`bucket < mid`， 添加`(mid - bucket) / (1 - loss / 100)`到`required`。 
4.如果`excess >= required`,`mid`是可以实现的； 放`low = mid`。 
5. 否则，`mid`太高； 放`high = mid`。 
4. 收敛后，`low`是可达到的最高水位。 

**为什么它有效**

 这是有效的，因为条件`excess >= required`确保在考虑损失后可重新分配的总水量足以实现目标。 由于单调性，二分搜索有效地缩小了最大可行值，并保证收敛：如果目标是可实现的，则任何较小的目标也是可实现的。 

## Python 解决方案```python
from typing import List

class Solution:
    def equalizeWater(self, buckets: List[int], loss: int) -> float:
        low, high = 0.0, max(buckets)
        precision = 1e-6
        factor = 1 - loss / 100.0

        while high - low > precision:
            mid = (low + high) / 2.0
            excess, required = 0.0, 0.0
            for water in buckets:
                if water > mid:
                    excess += water - mid
                else:
                    required += (mid - water) / factor
            if excess >= required:
                low = mid
            else:
                high = mid

        return low
```**解释**

 我们定义二分查找范围从0到最大桶水。 对于每位候选人`mid`，我们计算总数`excess`可倒入的水量和总量`required`水到达`mid`跨所有桶。 我们调整`low`和`high`根据候选目标是否可行，在范围内时停止`1e-6`。 然后该函数返回可达到的最大水位。 

## 解决方案```go
func equalizeWater(buckets []int, loss int) float64 {
    low, high := 0.0, 0.0
    for _, water := range buckets {
        if float64(water) > high {
            high = float64(water)
        }
    }

    precision := 1e-6
    factor := 1.0 - float64(loss)/100.0

    for high - low > precision {
        mid := (low + high) / 2.0
        excess, required := 0.0, 0.0
        for _, water := range buckets {
            w := float64(water)
            if w > mid {
                excess += w - mid
            } else {
                required += (mid - w) / factor
            }
        }
        if excess >= required {
            low = mid
        } else {
            high = mid
        }
    }

    return low
}
```**解释**

 Go 实现反映了 Python 逻辑，将整数转换为浮点数以精确处理算术。 循环继续，直到搜索范围小于`1e-6`，确保答案满足所需的精度。 

## 工作示例

 ### 示例 1

 输入：`buckets = [1,2,7], loss = 80`二分查找候选`mid = 2.0`:

 | 桶| 多余/必需|
 | --- | --- |
 | 1 | 所需 = (2-1)/0.2 = 5 |
 | 2 | 所需 = (2-2)/0.2 = 0 |
 | 7 | 多余 = 7-2 = 5 |

 多余 >= 必需 → 5 >= 5，可行。 输出=2.0

 ### 示例 2

 输入：`buckets = [2,4,6], loss = 50`候选人`mid = 3.5`:

 | 桶| 多余/必需|
 | --- | --- |
 | 2 | 所需 = (3.5-2)/0.5 = 3 |
 | 4 | 过剩 = 4-3.5 = 0.5 |
 | 6 | 过剩 = 6-3.5 = 2.5 |

 多余=0.5+2.5=3，需要=3→可行。 输出=3.5

 ### 示例 3

 输入：`buckets = [3,3,3,3], loss = 40`所有桶都已相等 → 最大级别 = 3.0
