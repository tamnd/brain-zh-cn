[LeetCode 问题 2101](https://leetcode.com/problems/detonate-the-maximum-bombs/)

 **难度：** 🟡 中等
 **主题：** 数组、数学、深度优先搜索、广度优先搜索、图论、几何

 ## 解决方案

 # 问题理解

 在这个问题中，每个炸弹都由三个整数表示：它的 x 坐标、y 坐标和爆炸半径。 如果炸弹爆炸，其中心位于该半径内或边界上的所有其他炸弹也会爆炸。 那些新爆炸的炸弹可以继续触发更多的炸弹，产生连锁反应。 

任务是确定在开始时手动触发一枚炸弹可以引爆的最大炸弹数量。 

重要的细节是爆炸是定向的。 如果炸弹`A`可以到达炸弹`B`，这并不自动意味着炸弹`B`可以到达炸弹`A`。 一枚半径较大的炸弹可能会触发另一枚半径较小的炸弹，但反之则不可能。 

我们可以将其视为有向图问题：

 - 每个炸弹都是一个节点。 
- 炸弹有一个定向边缘`i`轰炸`j`如果炸弹`j`位于炸弹爆炸半径内`i`。 

一旦图表建立起来，问题就变成了：

 > 对于每个节点，计算从该节点可到达的节点数量，然后返回最大可到达计数。 

限制相对较小：

 -`1 <= bombs.length <= 100`- 坐标和半径可以大到`10^5`由于最多有 100 枚炸弹，`O(n^2)`甚至`O(n^3)`解决方案是完全可以接受的。 

一个重要的实现细节是避免浮点运算。 为了确定一颗炸弹是否可以到达另一颗炸弹，我们比较距离的平方而不是计算平方根：$$(x_1 - x_2)^2 + (y_1 - y_2)^2 \le r^2$$

$(x_1-x_2)^2+(y_1-y_2)^2\le r^2$这避免了精度问题并且效率更高。 

一些边缘情况很重要：

 - 一枚炸弹应该返回`1`。 
- 炸弹可能完全重叠。 
- 任何其他炸弹都无法到达任何炸弹。 
- 爆炸链可能很长且间接。 
- 如果整数类型太小，大坐标值可能会导致某些语言溢出。 

该问题保证了有效的输入大小和正半径，因此我们不需要处理格式错误的数据。 

# 方法

 ## 蛮力方法

 最直接的方法是从每颗炸弹开始模拟爆炸过程。 

对于每个起始炸弹：

 1. 确定哪些炸弹是可以直接到达的。 
2. 引爆那些炸弹。 
3.继续扩大连锁反应，直到没有新的炸弹爆炸。 
4. 计算引爆了多少枚炸弹。 

简单的实现可能会在模拟过程中重复扫描每个炸弹对，而不是预先计算关系。 这可以正确工作，因为每种可能的链式反应都被探索了，但它会执行不必​​要的重复计算。 

蛮力方法是正确的，因为它详尽地模拟了从每个炸弹开始的所有可能的爆炸。 然而，在遍历过程中反复重新计算几何可达性是低效的。 

## 关键见解

 关键的观察是，炸弹之间的可达性在模拟过程中没有改变。 是否弹`i`可以引爆炸弹`j`仅取决于它们的位置和半径。 

因此，我们可以先构建一个有向图：

 - 节点`i`代表炸弹`i`- 定向边`i -> j`如果炸弹存在`i`可以引爆炸弹`j`构造图后，问题就简化为标准的图遍历问题。 从每个节点运行 DFS 或 BFS 来计算可访问的节点数量。 

由于最多只有 100 个炸弹，因此构建包含所有配对比较的图表非常高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n3) | O(n) | 在每次遍历期间重新计算可达性 |
 | 最佳| O(n²) | O(n²) | 预计算一次图，然后从每个节点运行 DFS/BFS |

 # 算法演练

 1. 创建表示有向图的邻接表。 

对于每对炸弹`(i, j)`,判断是否炸弹`i`可以引爆炸弹`j`。 

让：

-`(xi, yi)`成为炸弹的中心`i`-`ri`是炸弹的半径`i`-`(xj, yj)`成为炸弹的中心`j`计算平方距离：$$(x_i - x_j)^2 + (y_i - y_j)^2$$如果该值小于或等于`ri²`，然后添加一条有向边`i`到`j`。 

1. 构建图表后，迭代每个炸弹作为可能的起点。 
2. 对于每个起始炸弹，执行深度优先搜索。 

DFS 探索通过连锁反应可到达的每一颗炸弹。 

使用一个`visited`设置以避免多次处理同一炸弹。 这可以防止循环图中的无限循环。 
3. DFS期间：

 - 将当前炸弹标记为已访问。 
- 递归访问所有尚未访问过的邻居。 
4. DFS完成后，访问集的大小代表该起始炸弹引爆的炸弹总数。 
5. 跟踪所有起始炸弹的最大值。 
6. 返回最大引爆计数。 

## 为什么它有效

 该图准确地模拟了所有直接爆炸关系。 远离炸弹的道路`A`轰炸`B`意味着存在最终引爆的有效连锁反应`B`。 

DFS 精确地探索从有向图中的起始节点可到达的炸弹集合。 因此，从每个炸弹运行 DFS 可以正确计算从该炸弹开始引爆的炸弹数量。 取所有起始炸弹的最大值即可给出最佳答案。 

# Python 解决方案```python
from typing import List

class Solution:
    def maximumDetonation(self, bombs: List[List[int]]) -> int:
        n = len(bombs)

        # Build directed graph
        graph = [[] for _ in range(n)]

        for i in range(n):
            xi, yi, ri = bombs[i]

            for j in range(n):
                if i == j:
                    continue

                xj, yj, _ = bombs[j]

                dx = xi - xj
                dy = yi - yj

                distance_squared = dx * dx + dy * dy

                if distance_squared <= ri * ri:
                    graph[i].append(j)

        def dfs(node: int, visited: set[int]) -> int:
            visited.add(node)

            for neighbor in graph[node]:
                if neighbor not in visited:
                    dfs(neighbor, visited)

            return len(visited)

        max_detonated = 0

        for start in range(n):
            visited = set()
            detonated_count = dfs(start, visited)
            max_detonated = max(max_detonated, detonated_count)

        return max_detonated
```实现从构造有向图开始。 每个索引对应一个炸弹，每个邻接表存储从它可以直接到达的炸弹。 

嵌套循环比较每对炸弹。 该代码不使用带平方根的欧几里得距离，而是比较平方值。 这避免了浮点运算并提高了数值安全性。 

DFS 函数递归地探索当前节点可到达的所有炸弹。 这`visited`set 确保每个炸弹仅计数一次，即使存在循环。 

最后，该算法从每个炸弹开始运行 DFS 并记录最大的可达计数。 

# 解决方案```go
func maximumDetonation(bombs [][]int) int {
	n := len(bombs)

	graph := make([][]int, n)

	// Build directed graph
	for i := 0; i < n; i++ {
		xi, yi, ri := bombs[i][0], bombs[i][1], bombs[i][2]

		for j := 0; j < n; j++ {
			if i == j {
				continue
			}

			xj, yj := bombs[j][0], bombs[j][1]

			dx := int64(xi - xj)
			dy := int64(yi - yj)

			distanceSquared := dx*dx + dy*dy
			radiusSquared := int64(ri) * int64(ri)

			if distanceSquared <= radiusSquared {
				graph[i] = append(graph[i], j)
			}
		}
	}

	var dfs func(int, []bool) int

	dfs = func(node int, visited []bool) int {
		visited[node] = true

		count := 1

		for _, neighbor := range graph[node] {
			if !visited[neighbor] {
				count += dfs(neighbor, visited)
			}
		}

		return count
	}

	maxDetonated := 0

	for start := 0; start < n; start++ {
		visited := make([]bool, n)

		detonatedCount := dfs(start, visited)

		if detonatedCount > maxDetonated {
			maxDetonated = detonatedCount
		}
	}

	return maxDetonated
}
```Go 实现遵循与 Python 解决方案相同的算法结构，但有一些特定于语言的注意事项。 

如果大的平方值存储在标准中，Go 整数可能会溢出`int`某些系统上的算术。 为了避免这种情况，该实现将坐标差和半径值转换为`int64`在平方之前。 

Go 没有使用 Python 集合，而是使用布尔切片来表示访问的结构。 由于炸弹指数范围为`0`到`n-1`，布尔数组高效且简单。 

DFS函数通过递归累加计数返回可到达的炸弹总数。

 # 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n²) | 构建图表需要比较每个炸弹对，DFS 遍历在一起仍然是 O(n²) |
 | 空间| O(n²) | 最坏情况邻接表存储每个有向边 |

 图构建阶段将每对炸弹进行一次比较，其成本`O(n²)`。 

每次DFS遍历最多访问次数`n`最多节点和遍历`n²`整体边缘。 自从`n <= 100`，从每个节点执行 DFS 仍然高效。 

邻接表最多可以包含`n * (n - 1)`在最坏的情况下有向边，导致`O(n²)`空间使用情况。

 # 边缘情况

 ## 单弹

 当输入仅包含一颗炸弹时，答案必须是`1`因为引爆那颗炸弹只会影响它自己。 

这种情况可能会暴露图遍历实现中的错误，这些错误假设至少存在一个传出边。 当前的实现自然地处理了这个问题，因为 DFS 在探索邻居之前访问起始节点。 

## 精确边界可达性

 即使目标正好位于其爆炸半径的边缘，一枚炸弹也应该引爆另一枚炸弹。 

这就是实现使用以下内容的原因：$$distance^2 \le radius^2$$而不是严格的小于比较。 

不包含等式将错误地拒绝有效的爆炸。 

## 循环爆炸链

 炸弹可能会形成循环。 例如：```
0 -> 1
1 -> 2
2 -> 0
```如果没有访问过的结构，DFS 将无限递归。 

该实现通过在进入 DFS 后立即将炸弹标记为已访问来避免这种情况。 每个炸弹每次遍历仅处理一次。 

## 大坐标值

 坐标和半径可以大到`100000`。 在某些语言中，对这些值进行平方可能会超出 32 位整数限制。 

Go 解决方案明确使用`int64`距离和半径平方之前的算术。 这可以防止溢出并保证正确的几何比较。
