[LeetCode 问题 2105](https://leetcode.com/problems/watering-plants-ii/)

 **难度：** 🟡 中等
 **主题：** 数组、两个指针、模拟

 ## 解决方案

 ## 问题理解

 在这个问题中，我们有一排植物，其中每棵植物都需要一定量的水。 爱丽丝和鲍勃两个人从阵列的两端同时给植物浇水。 

Alice 从左侧索引处开始`0`并向右移动。 鲍勃从右侧索引处开始`n - 1`并向左移动。 每个人都有自己的喷壶，喷壶的最大容量是固定的。 最初，两个罐子都完全满了。 

对于他们遇到的每一株植物，他们必须通过一个动作给它充分浇水。 如果罐子里的剩余水不足，他们需要在给植物浇水之前补充水。 补充会立即发生，但每次补充都必须进行计数。 

目标是计算爱丽丝和鲍勃浇灌所有植物所需的补充总数。 

当两个指针在同一工厂相遇时，问题的有趣部分就会出现。 在那种情况下：

 - 当前剩余水较多的人为植物浇水。 
- 如果两者的量相同，爱丽丝就给它浇水。 

输入包括：

 -`plants`，一个数组，其中`plants[i]`是植物所需的水量`i`-`capacityA`, 爱丽丝的喷壶容量
 -`capacityB`, 鲍勃的喷壶容量

 输出是一个整数，表示所需的最小补充次数。 

约束条件很重要：

 -`n`可以大到`10^5`- 水容量和植物需求可能非常大
 - 保证每个植物的需水量都适合两个喷壶

 这些约束立即排除了不必要的昂贵模拟或重复重新计算。 我们需要一个线性时间解。 

一些边缘情况很重要：

 - 一株植物，只有爱丽丝或鲍勃其中一人浇水
 - 两者同时到达中间工厂的情况
 - 一个或两个必须在浇水前立即补充水的情况
 - 根本不需要补充的情况
 - 每一步都需要补充的情况

 由于植物从两端都被处理一次，因此该问题强烈建议采用双指针模拟方法。 

## 方法

 ### 蛮力方法

 强力模拟可以明确地模拟时间的流逝，并反复确定每个时刻哪个人给哪个植物浇水。 

我们可以为 Alice 和 Bob 维护不同的状态，单独模拟每个浇水操作，并反复比较位置和剩余容量。 虽然这在概念上可行，但它引入了不必要的复杂性。 植物总是按照确定的顺序浇水，并且没有分支或回溯。 

另一种低效的变化是反复重新计算剩余容量或维护跟踪浇水事件的额外结构。 这些方法最终仍然会处理每个工厂，但会带来不必要的开销。 

蛮力方法是正确的，因为它遵循问题陈述的确切规则。 然而，它比必要的更复杂，并且可能会引入超出线性时间的额外处理。 

### 最佳方法

 关键的观察结果是浇水顺序是完全预先确定的：

 - 爱丽丝总是从左向右移动
 - 鲍勃总是从右向左移动
 - 每株植物只浇一次水

 这意味着我们可以使用两个指针来处理数组：

 -`left`为了爱丽丝
 -`right`给鲍勃

 我们还维护：

 - 爱丽丝剩余的水
 - 鲍勃剩余的水
 - 总补充次数

 每一步：

 - 爱丽丝手柄`plants[left]`- 鲍勃手柄`plants[right]`如果任何一个人缺水，他们都会先补充水。 

唯一的特殊情况发生在`left == right`，这意味着两者都到达同一工厂。 那时，我们只需选择剩余水较多的人即可。 如果两者都不够，则需要补充一次。 

这会导致干净的`O(n)`具有恒定额外空间的模拟。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) 到 O(n²) 取决于实现 | O(1) 到 O(n) | 模拟浇水，带来不必要的开销 |
 | 最佳| O(n) | O(1) | O(1) | 两指针模拟处理每个植物一次 |

 ## 算法演练

 1.初始化两个指针：

 -`left = 0`-`right = n - 1`爱丽丝将从左侧处理植物，而鲍勃将从右侧处理植物。 
2. 初始化剩余水量：

 -`waterA = capacityA`-`waterB = capacityB`两个喷壶开始完全装满。 
3. 初始化计数器`refills = 0`。 

该变量跟踪执行的补充总数。 
4. 继续处理`left < right`。 

这意味着爱丽丝和鲍勃仍在浇灌不同的植物。 
5. 对于爱丽丝：

 - 如果`waterA < plants[left]`，她无法完全浇灌当前的植物。 
- 增量`refills`- 重置`waterA = capacityA`- 从中减去植物需求`waterA`6.对于鲍勃：

 - 如果`waterB < plants[right]`，他必须先补充。 
- 增量`refills`- 重置`waterB = capacityB`- 从中减去植物需求`waterB`7. 将两个指针向内移动：

 -`left += 1`-`right -= 1`8. 循环结束后，检查是否`left == right`。 

这意味着中间的一株植物仍然没有浇水。 
9. 确定谁给中间的植物浇水：

 - 如果`waterA >= waterB`，爱丽丝尝试一下
 - 否则鲍勃会尝试
 10、如果被选中者剩余水量不足：

 - 增量`refills`11. 返回`refills`。 

### 为什么它有效

 该算法之所以有效，是因为浇水顺序是固定且确定的。 根据指针位置，每一株植物都被准确地分配给一个人。 在每一步中，算法都会保持当前区域之外的所有植物的不变性`[left, right]`范围已正确浇水，并添加了所需的最少补充量。 

中间工厂逻辑正确地遵循问题陈述中的平局打破规则。 由于每个植物都被处理一次，并且每次补充都会在必要时精确计数，因此最终的补充计数是正确的。 

## Python 解决方案```python
from typing import List

class Solution:
    def minimumRefill(self, plants: List[int], capacityA: int, capacityB: int) -> int:
        left = 0
        right = len(plants) - 1

        waterA = capacityA
        waterB = capacityB

        refills = 0

        while left < right:
            if waterA < plants[left]:
                refills += 1
                waterA = capacityA

            waterA -= plants[left]

            if waterB < plants[right]:
                refills += 1
                waterB = capacityB

            waterB -= plants[right]

            left += 1
            right -= 1

        if left == right:
            remaining = max(waterA, waterB)

            if remaining < plants[left]:
                refills += 1

        return refills
```该实现直接遵循前面描述的两指针模拟。 

变量`left`和`right`跟踪 Alice 和 Bob 目前负责哪些植物。 变量`waterA`和`waterB`将剩余的水储存在每个喷壶中。 

在主循环中，我们首先检查 Alice 是否有足够的水供当前左边的植物使用。 如果没有，我们就算一次补充，并将她的罐子恢复到满容量。 给植物浇水后，我们减去所需的量。 

鲍勃从另一方遵循完全相同的逻辑。 

处理完两种植物后，指针向内移动。 

决赛`if left == right`当数组长度为奇数时，块处理中间植物。 根据问题规则，剩余水较多的人负责处理植物。 如果该人仍然缺乏足够的水，则需要补充一次。 

该算法只处理每个植物一次，这保证了线性时间复杂度。 

## 解决方案```go
func minimumRefill(plants []int, capacityA int, capacityB int) int {
	left := 0
	right := len(plants) - 1

	waterA := capacityA
	waterB := capacityB

	refills := 0

	for left < right {
		if waterA < plants[left] {
			refills++
			waterA = capacityA
		}

		waterA -= plants[left]

		if waterB < plants[right] {
			refills++
			waterB = capacityB
		}

		waterB -= plants[right]

		left++
		right--
	}

	if left == right {
		remaining := waterA
		if waterB > remaining {
			remaining = waterB
		}

		if remaining < plants[left] {
			refills++
		}
	}

	return refills
}
```Go 的实现与 Python 解决方案非常相似。 

Go 不提供内置的`max`函数为整数，因此我们手动计算中间工厂情况下较大的剩余水量。 

该解决方案仅使用原始整数变量和切片索引，因此内存使用量保持不变。 整数溢出不是一个问题，因为 Go 的`int`类型可以轻松处理给定的约束。

    def minimumRefill(self, plants: List[int], capacityA: int, capacityB: int) -> int:
        left = 0
        right = len(plants) - 1

        waterB = capacityB

 ## 边缘情况

 ### 单株

 当阵列仅包含一株植物时，爱丽丝和鲍勃会同时到达该植物。 一个常见的错误是试图让两者独立处理同一植物，这会重复计算浇水或补充。 

该实现通过立即退出主循环并单独处理中间工厂来正确处理此问题。 它比较剩余的水量并根据问题规则选择正确的人。 

### 精确容量匹配

 当喷壶中所含的量正好满足植物所需的量时，可能会出现微妙的错误。 一些不正确的实现使用`<=`而不是`<`检查补充情况时，造成不必要的补充。 

该解决方案正确检查：```
if waterA < plants[left]:
```这意味着仅当剩余水严重不足时才会进行补充。 

### 奇数植物

 当`n`奇怪的是，爱丽丝和鲍勃最终在同一个中间工厂相遇。 不正确的解决方案有时会导致双方都浇水或忘记应用打破平局规则。 

此实现显式处理主循环之后的中间工厂。 它选择剩余水较多的人，如果两人的水相同，则自动选择爱丽丝，因为`max(waterA, waterB)`符合问题要求。
