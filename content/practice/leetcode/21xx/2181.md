[LeetCode 问题 2181](https://leetcode.com/problems/merge-nodes-in- Between-zeros/)

 **难度：** 🟡 中等
 **主题：** 链表、模拟

 ## 解决方案

 ## 问题理解

 该问题给了我们一个单链表，其中的值分组在`0`节点。 该列表始​​终以`0`并以`0`，并且不存在两个连续的零。 两个零之间的每个非零节点序列代表一个组。 

我们的任务是用一个节点替换每个组，该节点的值等于该组中所有值的总和。 生成的链表应仅包含这些求和节点，并删除所有零节点。 

例如，考虑以下列表：```
0 -> 3 -> 1 -> 0 -> 4 -> 5 -> 2 -> 0
```第一组位于第一个和第二个零之间：```
3 + 1 = 4
```第二组位于第二个和第三个零之间：```
4 + 5 + 2 = 11
```所以最终的链表就变成了：```
4 -> 11
```约束很重要，因为列表可能包含最多`2 * 10^5`节点。 这意味着我们需要一个能够在线性时间内有效处理列表的解决方案。 任何重复遍历列表的各个部分或执行昂贵的复制操作的解决方案都可能变得太慢。 

该问题还提供了几个简化实现的保证：

 - 列表总是以`0`- 列表总是以`0`- 没有连续的零
 - 每组至少包含一个非零值

 这些保证意味着我们永远不需要处理空组，并且每当我们在累加值后遇到零时，我们就知道我们已经完成了一个有效的段。 

一些重要的边缘情况包括：

 - 仅包含一组的列表
 - 包含单个值的组
 - 非常大的列表，包含许多组
 - 金额较大的团体
 - 连续的小段可能会暴露链表操作中的指针错误

 幼稚的实现很容易因错误地重新连接节点或意外地将边界零包含在总和中而犯错误。 

## 方法

 ### 蛮力方法

 一种简单的方法是首先将链表中的所有值提取到数组中。 一旦我们有了数组表示，我们就可以迭代它并计算零之间的总和。 生成所有总和后，我们可以构建一个包含这些值的全新链表。 

这是可行的，因为数组比链表更容易处理。 当我们遇到零时，我们可以顺序扫描这些值并识别组边界。 

然而，这种方法并不是最佳的，因为它需要与列表大小成正比的额外内存。 我们将所有节点值存储在辅助数组中，然后为答案分配另一个链表。 

虽然时间复杂度仍然是线性的，但是额外的内存使用是不必要的，因为可以在遍历原始链表的同时直接解决问题。 

### 最佳方法

 关键的观察是我们在遍历链表时只需要一个运行和。 每当我们遇到一个`0`，我们知道当前段已经结束，我们可以将累加和作为新节点追加到结果列表中。 

我们不是将列表转换为另一种数据结构，而是一次性处理节点。 

我们维持：

 - 当前段的运行总和
 - 用于构建结果列表的指针
 - 用于扫描输入列表的遍历指针

 每当我们遇到非零值时，我们都会将其添加到运行总和中。 每当我们在处理一个段后遇到零时，我们都会创建一个包含累积和的新节点，并重置下一个段的运行总和。 

这种方法很有效，因为每个节点都被访问一次。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(n) | 将链表转换为数组、计算总和、重建列表 |
 | 最佳| O(n) | O(1) 辅助空间 | 带运行段和的单次遍历 |

 ## 算法演练

 1. 从紧接初始零之后的节点开始遍历，因为保证第一个节点是`0`并且不贡献任何金额。 
2. 为结果链表创建一个虚拟节点。 使用虚拟节点可以简化添加新节点的过程，因为我们不需要对第一个结果节点进行特殊处理。 
3. 维护一个名为`current_sum`，初始化为`0`。 该变量存储两个零之间的值的运行总和。 
4. 一次遍历链表一个节点。 
5. 如果当前节点包含非零值，则将其添加到`current_sum`。 这意味着我们仍在当前段内。 
6. 如果当前节点包含`0`，表示当前段已经结束。 创建一个有值的新节点`current_sum`并将其附加到结果列表中。 
7. 重置`current_sum`回到`0`因为下一段从这个零开始。 
8. 继续遍历，直到到达链表末尾。 
9. 返回`dummy.next`，它指向合并结果列表的实际头部。 

### 为什么它有效

 该算法保持不变式`current_sum`始终等于自最近的零以来遇到的所有非零节点的总和。 每当出现另一个零时，整个段都已被处理，因此累加的和是正确的并且可以安全地附加到结果列表中。 由于每个节点都属于一个段，并且每个段都以零结尾，因此所有组都只被处理一次。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

class Solution:
    def mergeNodes(self, head: Optional[ListNode]) -> Optional[ListNode]:
        dummy = ListNode(0)
        tail = dummy

        current = head.next
        current_sum = 0

        while current:
            if current.val == 0:
                tail.next = ListNode(current_sum)
                tail = tail.next
                current_sum = 0
            else:
                current_sum += current.val

            current = current.next

        return dummy.next
```实现首先创建一个虚拟节点，作为结果列表的起点。 这避免了对第一次插入的特殊处理。 

遍历开始于`head.next`因为第一个节点始终为零并且不属于任何段。 

变量`current_sum`存储当前段的累计和。 遍历过程中：

 - 非零节点对运行总和有贡献
 - 零节点标记段的结尾

 每当遇到零时，包含累加和的新节点就会附加到结果列表中。 然后为下一段重置运行总和。 

最后该方法返回`dummy.next`，它跳过虚拟节点并直接指向第一个合并节点。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func mergeNodes(head *ListNode) *ListNode {
    dummy := &ListNode{}
    tail := dummy

    current := head.Next
    currentSum := 0

    for current != nil {
        if current.Val == 0 {
            tail.Next = &ListNode{Val: currentSum}
            tail = tail.Next
            currentSum = 0
        } else {
            currentSum += current.Val
        }

        current = current.Next
    }

    return dummy.Next
}
```Go 实现遵循与 Python 版本相同的逻辑。 主要区别来自 Go 的显式指针处理和结构语法。 

在围棋中：

 -`nil`被用来代替`None`- 使用以下命令创建新节点`&ListNode{}`- 使用大写名称访问结构字段，例如`Val`和`Next`该算法仍然执行单次遍历，同时维持运行段总和。

 ## 边缘情况

 一个重要的边缘情况是仅包含单个组的列表，例如：```
0 -> 5 -> 5 -> 0
```有缺陷的实现可能会错误地假设有多个组或无法附加最终总和。 此实现正确处理最后的零并在终止前附加累加和。 

另一个重要的边缘情况是每个组只包含一个值：```
0 -> 1 -> 0 -> 2 -> 0 -> 3 -> 0
```这种情况很有用，因为它验证了算法不会意外跳过段或将相邻组合并在一起。 由于运行总和在每个零后都会重置，因此每个值都成为结果列表中自己的节点。 

第三个重要的边缘情况涉及一个非常大的列表中的许多小组。 高达`2 * 10^5`节点，低效的算法可能会成为问题。 由于该解决方案对每个节点只处理一次并且仅使用恒定的辅助内存，因此即使对于最大输入大小，它也可以有效地扩展。 

另一个微妙的边缘情况是确保边界零永远不会包含在总和中。 由于该算法仅在以下情况下添加值：`current.val != 0`，零纯粹充当分隔符，从不影响计算的总数。
