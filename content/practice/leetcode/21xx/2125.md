 # LeetCode 2125 - 银行中激光束的数量

 ## 问题理解

 该问题将银行平面图描述为二进制矩阵，由字符串数组表示。 每一行对应银行中的一行，字符串中的每个字符代表一个单元格。 一个`'1'`意味着该牢房内安装了安全装置，而`'0'`意味着单元格是空的。 

如果两个设备位于不同的行并且它们之间的每一行根本不包含任何设备，则它们之间存在激光束。 换句话说，激光束只能连接连续非空行的器件。 如果存在任何包含至少一个设备的中间行，则连接无法跳过它。 

关键的观察结果是，如果两个非空行相对于包含设备的行是连续的，则上行中的每个设备都连接到下行中的每个设备。 如果一行包含`a`devices 和下一个非空行包含`b`设备，然后他们贡献`a * b`激光束。 

输入大小限制很重要。 行数和列数均可高达 500。这意味着单元格总数可达 250,000 个。 涉及成对设备比较的二次或三次解决方案可能会变得不必要的昂贵，而对所有单元的线性扫描是完全合理的。 

有几个边缘情况需要考虑。 只有一个非空行的组不能产生任何光束，因为光束需要不同行上的设备。 完全用零填充的行必须被忽略，因为它们破坏了非空行之间的连续性。 另一个重要的情况发生在每行都为空时，它应该正确返回零。 该问题保证每个字符都是`'0'`或者`'1'`，因此不需要额外的输入验证。 

## 方法

 ### 蛮力方法

 一个简单的暴力解决方案将首先识别矩阵中的每个安全设备，然后检查位于不同行的每对设备。 对于每一对，我们将检查它们之间的所有行是否为空。 如果是，我们算一束。 

这种方法是正确的，因为它直接遵循问题定义。 每个可能的设备对都会被独立评估，并且中间行会根据需要进行准确验证。 

然而，这种方法效率低下。 如果设备较多，则设备对的数量会快速增长。 在最坏的情况下，几乎每个单元都可能包含一个设备，从而导致大量的比较和中间行的重复扫描。 

### 最佳方法

 重要的见解是梁仅存在于连续的非空行之间。 假设一个非空行有`a`设备和下一个非空行有`b`设备。 第一行中的每个设备都连接到第二行中的每个设备，从而准确产生`a * b`横梁。 

仅包含零的行不直接参与。 它们只是分隔行，并且因为问题明确允许光束穿过完全空的行，所以我们只需要记住最近的非空行。 

这意味着我们可以逐行处理矩阵。 对于每一行，计算它包含的设备数量。 如果该行非空，则将其设备计数乘以前一个非空行的设备计数，并将结果添加到答案中。 

这将问题简化为通过矩阵的单次传递。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(m² × n²) | O(m × n) | 比较设备对并检查中间行 |
 | 最佳| O(m × n) | O(1) | O(1) | 逐行计数设备 |

 ## 算法演练

 1. 初始化变量`previous_devices`存储最近的非空行中的设备数量。 
2.初始化另一个变量`total_beams`存储最终答案。 
3. 迭代存储库中的每一行。 
4. 对于当前行，统计有多少个`'1'`字符出现。 这给出了该行中的设备数量。 
5. 如果当前行包含零个设备，则完全跳过它。 空行不会创建或终止梁。 
6. 如果该行非空，则将当前设备计数乘以`previous_devices`。 这表示当前行和前一个非空行之间的所有可能的光束。 
7.将此产品添加到`total_beams`。 
8. 更新`previous_devices`到当前行的设备计数。 
9. 继续，直到处理完所有行。 
10. 返回`total_beams`。 

### 为什么它有效

 该算法之所以有效，是因为梁只能存在于连续的非空行之间。 任何非空行都会阻止梁进一步向下延伸。 因此，当处理一行时，唯一有效的梁连接来自紧邻的前一个非空行。 正确乘以设备计数可以计算这两行之间的所有成对连接。 

## Python 解决方案```python
from typing import List

class Solution:
    def numberOfBeams(self, bank: List[str]) -> int:
        previous_devices = 0
        total_beams = 0

        for row in bank:
            current_devices = row.count('1')

            if current_devices == 0:
                continue

            total_beams += previous_devices * current_devices
            previous_devices = current_devices

        return total_beams
```实现直接遵循算法。 变量`previous_devices`跟踪迄今为止遇到的最后一个非空行中的设备数量。 对于每一行，`row.count('1')`确定该行中存在多少个设备。 

如果一行为空，则忽略该行，因为空行不会影响波束形成。 当一行包含设备时，使用乘法计算与前一个非空行形成的波束数量。 将这些光束添加到总数后，当前行将成为新的参考行。 

该解决方案对矩阵执行单次扫描，并且仅使用恒定的额外内存。 

## 解决方案```go
func numberOfBeams(bank []string) int {
    previousDevices := 0
    totalBeams := 0

    for _, row := range bank {
        currentDevices := 0

        for _, cell := range row {
            if cell == '1' {
                currentDevices++
            }
        }

        if currentDevices == 0 {
            continue
        }

        totalBeams += previousDevices * currentDevices
        previousDevices = currentDevices
    }

    return totalBeams
}
```Go 实现遵循与 Python 版本相同的逻辑。 由于 Go 字符串可以通过 rune 进行迭代，因此内部循环会单独检查每个字符。 整数溢出不是问题，因为对于给定的约束，最大可能的答案完全符合 Go 的标准整数范围。 

与 Python 不同，Go 不提供内置的`count`方法用于字符串，因此设备计数是在嵌套循环内手动执行的。

 ## 边缘情况

 当存储区仅包含空行时，会出现一种重要的边缘情况。 在这种情况下，矩阵中的任何位置都不存在任何设备，因此不可能形成任何光束。 有缺陷的实现可能会错误地尝试连接空行或假设至少存在一个设备。 当前的实现自然地处理了这个问题，因为具有零个设备的行被完全跳过。 

当恰好有一个非空行时，会发生另一种重要情况。 由于梁需要不同行上的设备，因此答案必须为零。 该实现正确地处理了这个问题，因为`previous_devices`从零开始，因此第一个非空行不贡献任何光束。 

第三种棘手的情况涉及两个非空行之间的多个空行。 看起来距离很重要，但问题只需要中间行不包含任何设备。 该实现正确地忽略所有空行并直接连接连续的非空行，无论有多少空行将它们分开。 

当两个连续的非空行包含许多设备时，就会出现最后的边缘情况。 在这种情况下，第一行中的每个设备都连接到第二行中的每个设备，产生很大的乘法贡献。 该算法使用以下方法正确计算此值`previous_devices * current_devices`，确保所有成对光束都被精确计数一次。
