[LeetCode 问题 2143](https://leetcode.com/problems/choose-numbers-from-two-arrays-in-range/)

 **难度：** 🔴难
 **主题：** 数组、动态规划

 ## 解决方案

 # 问题理解

 在这个问题中，我们有两个数组，`nums1`和`nums2`, 两者的长度`n`。 对于每个索引`i`，我们必须选择一个值，要么`nums1[i]`或者`nums2[i]`，当考虑子数组范围时`[l, r]`。 

目标是计算存在多少种不同的方法来选择连续范围内的值，以便：

 - 所有选择值的总和`nums1`等于所有选定值的总和`nums2`。 
- 所选范围内的每个索引都贡献一个数字。 
- 不同的选择模式算作不同的平衡范围，即使范围边界相同。 

重新解释该问题的一个有用方法是：

 - 如果我们选择`nums1[i]`，我们添加`nums1[i]`到左侧。 
- 如果我们选择`nums2[i]`，我们添加`nums2[i]`到右侧。 

我们希望双方的最终总分能够匹配。 

另一种等效的解释是跟踪运行差异：

 - 选择`nums1[i]`增加差异`nums1[i]`- 选择`nums2[i]`减少差异`nums2[i]`如果最终差异变为，则范围是平衡的`0`。 

约束条件很重要：

 -`n <= 100`-`nums1[i], nums2[i] <= 100`由于值相对较小，因此总的可能总差是有界的。 最大可能的绝对差为：$$100 \times 100 = 10000$$这强烈表明针对可能差异的动态规划解决方案是可行的。 

一些边缘情况很重要：

 - 单元素范围，其中任一值为`0`- 多种方式在同一范围内达到平衡
 - 所有值均为零的范围
 - 不存在平衡范围的情况
 - 计算期间的负运行差异

 枚举所有子数组的所有可能选择的简单实现将呈指数爆炸，因为每个位置都有两个选择。 

# 方法

 ## 蛮力方法

 暴力解决方案考虑每个可能的子数组`[l, r]`。 

对于每个子数组：

 1. 列举所有可能的选择方式`nums1[i]`和`nums2[i]`2. 计算两个和
 3. 检查总和是否相等

 如果子数组有长度`k`，那么它有`2^k`可能的选择模式。 

在所有子数组中，总复杂度变得非常大：$$\sum_{k=1}^{n} (n-k+1)\cdot 2^k$$这是指数级的并且完全不可行`n = 100`。 

暴力方法是正确的，因为它显式检查每个可能的有效配置，但速度太慢。 

## 关键见解

 关键的观察是我们只关心两个总和之间的差异。 

定义：

 - 选择`nums1[i]`贡献`+nums1[i]`- 选择`nums2[i]`贡献`-nums2[i]`那么平衡范围就是一个序列，其总差等于`0`。 

这将问题转化为关于可能的差值的动态规划问题。 

对于每个结束索引`r`，我们维持：

 -`dp[diff] = number of ways`构建以以下结尾的子数组`r`其当前差值是`diff`在索引处`i`，每个现有状态都可以通过两种方式转换：

 - 添加`nums1[i]`- 减法`nums2[i]`我们还在每个索引处启动新的子数组。 

由于总的可能差异范围由`[-10000, 10000]`，DP 状态的数量仍然可控。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 |$O(n^2 \cdot 2^n)$|$O(1)$| 枚举每个子数组和每个选择模式 |
 | 最佳 |$O(n \cdot S)$|$O(S)$| 对可能的差异进行动态规划，其中$S$是差值范围 |

 这里：$$S = 20001$$因为差异范围从`-10000`到`10000`。 

# 算法演练

 ## 最优动态规划算法

 1.定义哈希图`dp`其中：

 - 键 = 当前差异
 - 值 = 实现以前一个索引结尾的子数组的差异的方法数量
 2. 将答案初始化为`0`。 
3. 迭代每个索引`i`。 
4. 创建新的哈希图`next_dp`。 
5. 在索引处开始新的子数组`i`。 

有两种可能的选择：

 - 选择`nums1[i]`, 产生差异`+nums1[i]`- 选择`nums2[i]`, 产生差异`-nums2[i]`更新`next_dp`因此。 
6. 扩展所有先前跟踪的子数组。 

对于每一个`(diff, count)`在`dp`：

 - 选择`nums1[i]`创建：$$diff + nums1[i]$$- 选择`nums2[i]`创建：$$diff - nums2[i]$$将计数添加到`next_dp`。 
7. 任何结果差值等于的状态`0`表示以索引结束的平衡范围`i`。 

添加`next_dp[0]`到答案。 
8. 更换`dp`和`next_dp`。 
9. 继续，直到处理完所有索引。 
10. 返回模数答案$10^9 + 7$。 

## 为什么它有效

 DP 不变量为：

 -`dp[d]`存储构造以当前位置结束的连续子数组的不同方法的数量，其总和等于`d`。 

每个以索引结尾的子数组`i`要么：

 - 开始于`i`- 或者扩展一个以以下结尾的子数组`i - 1`这些转变详尽地涵盖了这两种可能性。 

当子数组的差变为`0`，所以计算有差异的状态`0`正确计算所有平衡范围。 

# Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def countSubranges(self, nums1: List[int], nums2: List[int]) -> int:
        MOD = 10**9 + 7
        
        dp = defaultdict(int)
        answer = 0
        
        for a, b in zip(nums1, nums2):
            next_dp = defaultdict(int)
            
            # Start new subarrays
            next_dp[a] = (next_dp[a] + 1) % MOD
            next_dp[-b] = (next_dp[-b] + 1) % MOD
            
            # Extend previous subarrays
            for diff, count in dp.items():
                next_dp[diff + a] = (
                    next_dp[diff + a] + count
                ) % MOD
                
                next_dp[diff - b] = (
                    next_dp[diff - b] + count
                ) % MOD
            
            answer = (answer + next_dp[0]) % MOD
            
            dp = next_dp
        
        return answer
```该实现使用哈希映射，其中键表示总差，值表示获得这些差的方法数。 

对于每个索引，我们构建一个新的 DP 图，称为`next_dp`。 该映射存储以当前位置结束的所有子数组。 

第一次更新对应于在当前索引处开始新的子数组。 选择`nums1[i]`贡献积极的差异，同时选择`nums2[i]`贡献负差异。 

接下来，我们通过附加当前索引来扩展之前跟踪的每个子数组。 每个先前的状态都会分支成两个新的状态。 

处理完所有转换后，`next_dp[0]`包含以当前索引结尾的平衡子数组的数量。 我们将其添加到全局答案中。 

最后，我们通过分配继续前进`dp = next_dp`。 

# 解决方案```go
package main

func countSubranges(nums1 []int, nums2 []int) int {
	const MOD int = 1_000_000_007

	dp := map[int]int{}
	answer := 0

	for i := 0; i < len(nums1); i++ {
		a := nums1[i]
		b := nums2[i]

		nextDP := map[int]int{}

		// Start new subarrays
		nextDP[a] = (nextDP[a] + 1) % MOD
		nextDP[-b] = (nextDP[-b] + 1) % MOD

		// Extend previous subarrays
		for diff, count := range dp {
			newDiff1 := diff + a
			newDiff2 := diff - b

			nextDP[newDiff1] = (nextDP[newDiff1] + count) % MOD
			nextDP[newDiff2] = (nextDP[newDiff2] + count) % MOD
		}

		answer = (answer + nextDP[0]) % MOD

		dp = nextDP
	}

	return answer
}
```Go 实现遵循与 Python 解决方案完全相同的 DP 结构。 

由于Go没有Python的`defaultdict`，使用常规地图。 缺少的键默认为`0`，这自然支持累加逻辑。 

所有加法均以模进行`1_000_000_007`避免溢出并满足问题要求。

 # 边缘情况

 ## 包含零的数组

 零尤其重要，因为从一侧选择零可能会立即创建一个平衡范围。 

例如：```
nums1 = [0]
nums2 = [0]
```两种选择独立产生差异`0`，因此有两个有效的平衡范围。 

该实现正确地处理了这个问题，因为两个转换都是单独插入到 DP 映射中的。 

## 相同索引处的相同值

 一个常见的错误是假设如果`nums1[i] == nums2[i]`，然后选择其中之一会自动创建平衡。 

这是不正确的，因为只有一侧收到该值。 

例如：```
nums1 = [5]
nums2 = [5]
```可能的差异是：

 -`+5`-`-5`两者都不等于零。 

DP 公式自然地通过显式跟踪带符号的差异来处理这个问题。 

## 多种方式产生相同的差异

 不同的选择路径可能会导致相同的差值。 

例如：```
nums1 = [0,1]
nums2 = [1,0]
```几种不同的配置以差异结束`0`。 

有错误的实现可能会覆盖计数而不是累积它们。 

该解决方案通过对 DP 映射内的计数求和来避免这种情况：```
next_dp[new_diff] += count
```这保证了所有不同的配置都被正确计数。
