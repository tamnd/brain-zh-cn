[LeetCode 问题 2186](https://leetcode.com/problems/minimum-number-of-steps-to-make-two-strings-anagram-ii/)

 **难度：** 🟡 中等
 **主题：** 哈希表、字符串、计数

 ## 解决方案

 ## 问题理解

 该问题要求我们找到生成两个字符串所需的最少步骤，`s`和`t`，彼此的字谜。 字谜词意味着两个字符串必须包含具有相同频率的完全相同的字符，尽管它们的顺序可能不同。 在此问题中，“步骤”允许将**任何字符**附加到任一字符串。 实际上，我们只能添加字符，而不能删除它们，因此挑战是有效平衡两个字符串之间的字符数。 

输入由两个非空小写英文字符串组成，每个字符串最多 200,000 个字符。 输出是一个整数，表示所需的最少步骤数。 这些限制意味着检查每个字符排列或组合的简单算法是不可行的，我们需要一种随字符串长度线性缩放的方法。 

重要的边缘情况包括已经是字谜的字符串、没有共同字符的完全不相交的字符串以及非常短的字符串（长度为 1），这可能会给计数逻辑带来压力。 该问题保证非空字符串，因此我们不需要处理空输入。 

## 方法

 一种暴力方法是尝试所有可能的方法来添加字符以匹配两个字符串。 对于每个字符，我们可以尝试通过重复附加到出现次数较少的字符串来平衡计数。 这种方法在概念上是正确的，但它太慢了，因为它需要模拟所有可能的添加，导致指数时间复杂度。 

最佳解决方案的关键观察是我们不需要模拟附加字符。 相反，我们可以计算两个字符串中每个字符的频率并计算差异。 对于在一个字符串中出现次数多于另一个字符串的任何字符，必须将差异添加到另一个字符串以平衡它。 将所有字符之间的差异相加即可得出最少的步骤数。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(?)，指数 | O(1) | O(1) | 尝试所有附加组合，对于大字符串不可行 |
 | 最佳| O(n + m) | O(26) | 计算字符频率并计算差异 |

 ## 算法演练

 1. 初始化两个大小为 26 的频率数组，每个字符串一个。 每个索引对应一个小写字母（'a' = 0，'z' = 25）。 
2. 迭代字符串`s`并增加每个字符的计数`s`的频率阵列。 
3. 迭代字符串`t`并增加每个字符的计数`t`的频率阵列。 
4. 初始化变量`steps`到 0。这将跟踪所需的步骤总数。 
5. 循环遍历所有 26 个字母。 对于每个字母，计算之间的绝对差`s`和`t`频率。 将此差异添加到`steps`。 
6. 返回`steps`作为所需的最少步骤数。 

**为什么有效**：频率数组代表每个字符的确切计数。 绝对差直接给出了需要附加的字符数以平衡两个字符串之间的该字符。 对所有字符求和可以保证最少的步骤，因为每个额外的字符必须单独添加，并且不会浪费任何步骤。 

## Python 解决方案```python
class Solution:
    def minSteps(self, s: str, t: str) -> int:
        freq_s = [0] * 26
        freq_t = [0] * 26

        for char in s:
            freq_s[ord(char) - ord('a')] += 1
        for char in t:
            freq_t[ord(char) - ord('a')] += 1

        steps = 0
        for i in range(26):
            steps += abs(freq_s[i] - freq_t[i])

        return steps
```在这个实现中，`freq_s`和`freq_t`计算每个字母出现的次数`s`和`t`。 超过 26 个字母的循环计算计数的总差，这对应于所需追加操作的最小数量。 使用`ord(char) - ord('a')`有效地将每个字符映射到正确的索引。 

## 解决方案```go
func minSteps(s string, t string) int {
    freqS := [26]int{}
    freqT := [26]int{}

    for i := 0; i < len(s); i++ {
        freqS[s[i]-'a']++
    }
    for i := 0; i < len(t); i++ {
        freqT[t[i]-'a']++
    }

    steps := 0
    for i := 0; i < 26; i++ {
        if freqS[i] > freqT[i] {
            steps += freqS[i] - freqT[i]
        } else {
            steps += freqT[i] - freqS[i]
        }
    }

    return steps
}
```Go 版本使用固定大小的数组而不是切片来提高效率。 我们迭代字符串字节而不是符文，因为输入保证是小写英文字母。 计算绝对差异是手动完成的，因为 Go 没有内置的`abs`整数函数。

 ## 边缘情况

 一种边缘情况是两个字符串都已经是字谜词。 该算法自然地处理这个问题，因为计数的绝对差将全部为零，从而导致零步长。 

第二种边缘情况是字符串不共享公共字符。 差值之和将等于两个字符串的总长度，确保算法正确计算最大步数。 

第三种边缘情况是某些字母重复率很高的字符串，例如`"aaaaaa"`与`"a"`。 频率数组正确捕获了差异，并且仅计算最少数量的追加操作以平衡计数。 这可以避免在计算重复字符时出现任何相差一的错误。
