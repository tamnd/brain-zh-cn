[LeetCode 第 2139 题](https://leetcode.com/problems/minimum-moves-to-reach-target-score/)

 **难度：** 🟡 中等
 **主题：** 数学、贪心

 ## 解决方案

 ## 问题理解

 该问题要求我们对整数进行变换`1`化为整数`target`使用最少的移动次数。 在每一步中，我们都可以执行以下两种操作之一：

 1. 将当前数字增加`1`2. 将当前数字加倍

 重要的限制是加倍运算最多只能使用`maxDoubles`次。 增量操作没有限制。 

输入由两个整数组成：

 -`target`，我们想要达到的值
 -`maxDoubles`，允许使用加倍运算的最大次数

 输出是一个整数，表示达到目标所需的最小移动次数`target`开始于`1`。 

约束条件很重要：

 -`target`可以大到`10^9`-`maxDoubles`最多可以是`100`对所有值进行简单的广度优先搜索或动态规划解决方案`1`到`target`当`target`非常大。 我们需要一种在对数时间而不是线性时间下工作的方法。 

一个关键的观察结果是，加倍非常强大，因为它增加值的速度比递增快得多。 因此，最佳解决方案应该在节省步数时策略性地使用加倍。 

一些边缘情况很重要：

 - 当`maxDoubles = 0`，我们只能递增，所以答案很简单`target - 1`- 什么时候`target = 1`，我们已经达到了目标，所以答案是`0`- 当逆向处理时目标变成奇数时，我们不能直接减半，所以必须先减一
 - 当我们用完加倍运算时，剩余的距离必须完全用增量覆盖

 ## 方法

 ### 蛮力方法

 一个简单的想法是将问题建模为最短路径搜索。 开始于`1`，我们可以重复生成下一个状态：

 -`x + 1`-`2 * x`，如果我们还有剩余的双打

 我们可以使用广度优先搜索，因为每个操作只花费一次移动。 

这种方法是正确的，因为 BFS 保证我们第一次到达`target`，我们使用了最少的操作数。 

然而，对于给定的限制，这种方法太慢了。 搜索空间可能会变得非常大，因为`target`可能最多`10^9`。 甚至存储访问过的状态也变得不切实际。 

另一种强力的可能性是递归回溯或状态动态编程`(currentValue, remainingDoubles)`，但这对于大型目标来说也是不可行的。 

### 最优贪心法

 关键的见解是从`target`到`1`比向上建造要容易得多。 

而不是问：

 > “我们如何构建`target`从`1`？”

 我们问：

 >“我们如何减少`target`回到`1`？”

 反过来：

 - 增量变为减量
 - Double 变为除以`2`这种反向视角导致了贪婪策略：

 - 如果当前目标是偶数并且我们仍然可以进行加倍运算，则除以`2`始终是最佳的，因为它减少数量的速度比重复递减快得多。 
- 如果当前目标是奇数，我们必须减去`1`首先因为奇数不能被整除`2`。 
- 如果我们用完加倍运算，唯一剩下的选择就是递减，直到达到`1`。 

这种方法很有效，因为每次除以`2`大大减少了数量，导致复杂性达到对数。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(目标) 或更差 | O（目标）| 探索许多状态，对于大目标来说不可行 |
 | 最优贪心 | O(对数目标) | O(1) | O(1) | 使用除法贪婪地向后工作 |

 ## 算法演练

 1. 初始化变量`moves`到`0`。 
2. 虽然`target`大于`1`而我们还有剩余的双打，反复降低目标。 
3.如果`target`是偶数，除以`2`。 

这对应于反转加倍操作。 由于除法会迅速缩小数量，因此在可用时总是有益的。 
4.如果`target`是奇数，减去`1`。 

奇数不能被整除`2`，所以我们首先必须使其均匀。 
5. 每次操作后，增加移动计数器。 
6. 减少`maxDoubles`每当我们执行除法时`2`，因为这对应于向前消耗一次加倍操作。 
7. 最终，要么：

 -`target`变成`1`, 或
 - 我们用完了加倍运算
 8. 如果我们用完了双打并且`target`仍然大于`1`，唯一可能的移动是递减。 自从从`target`到`1`准确地要求`target - 1`递减，直接将其添加到答案中。 
9. 返回总移动次数。 

### 为什么它有效

 贪心选择是最优的，因为除以`2`通过单次操作即可最大程度地降低价值。 只要除法可用，延迟它只需要稍后进行额外的减量操作。 

当数字是奇数时，必须减一，因为不可能除法。 因此，每一个贪心步骤都是强制的或严格最优的，保证了最少的移动次数。 

## Python 解决方案```python
class Solution:
    def minMoves(self, target: int, maxDoubles: int) -> int:
        moves = 0

        while target > 1 and maxDoubles > 0:
            if target % 2 == 0:
                target //= 2
                maxDoubles -= 1
            else:
                target -= 1

            moves += 1

        if target > 1:
            moves += target - 1

        return moves
```实现直接遵循反向贪婪策略。 

变量`moves`跟踪执行的操作总数。 

这`while`只要两个条件成立，循环就会继续：

 -`target > 1`- 我们仍然可以进行加倍操作

 循环内部：

 - 如果目标是偶数，我们除以`2`并消耗一次加倍运算。 
- 如果目标是奇数，我们减去`1`使其均匀。 

每个动作都算作一次移动。 

循环结束后，我们的目标可能仍然大于`1`。 此时，不再有加倍操作，因此唯一可能的操作是重复递减。 我们不是单独模拟每个减量，而是添加`target - 1`直接地。 

最后，该函数返回累积的移动计数。 

## 解决方案```go
func minMoves(target int, maxDoubles int) int {
    moves := 0

    for target > 1 && maxDoubles > 0 {
        if target%2 == 0 {
            target /= 2
            maxDoubles--
        } else {
            target--
        }

        moves++
    }

    if target > 1 {
        moves += target - 1
    }

    return moves
}
```Go 的实现与 Python 解决方案非常相似。 

Go 对整数类型自动使用整数除法，所以`target /= 2`行为完全符合预期。 

不需要对溢出进行特殊处理，因为约束完全在 Go 的标准整数范围内。 

该算法使用恒定的额外内存，因为仅维护少数整数变量。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`maxDoubles = 0`。 在这种情况下，逆过程中不可能进行除法运算，这意味着唯一有效的操作是重复递减。 一个幼稚的实现可能仍然会尝试不必要的循环逻辑，但是这个解决方案立即落到最后添加`target - 1`。 

另一个关键的边缘情况是`target = 1`。 既然我们已经开始于`1`，答案应该是`0`。 某些实现意外地执行了额外的操作或进入不必要的循环。 该解决方案避免了这种情况，因为主循环条件需要`target > 1`。 

奇怪的目标是错误的另一个常见来源。 奇数不能被整除`2`，因此必须先减去一个。 忘记此详细信息可能会产生不正确的移动计数或无效状态。 该实现在划分之前显式检查奇偶校验。 

当加倍操作在到达之前用完时，会发生最后一个微妙的情况`1`。 此时，递减是唯一剩下的选择。 该算法不是逐一模拟每个减量，而是添加`target - 1`直接，这在保持效率的同时保留了正确性。
