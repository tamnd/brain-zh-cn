[LeetCode 第 2199 题](https://leetcode.com/problems/finding-the-topic-of-each-post/)

 **难度：** 🔴难
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题给了我们两个数据库表，`Keywords`和`Posts`。 

这`Keywords`表将单词映射到主题 ID。 单个主题可以有多个与其关联的单词，并且单个单词可以属于多个主题。 例如，这个词`"football"`可能代表主题`1`，而另一个词如`"war"`可能代表主题`3`。 

这`Posts`表包含社交媒体帖子。 每个帖子都有独特之处`post_id`和一个`content`细绳。 

我们的目标是确定哪些主题适用于每篇文章。 

如果帖子内容中至少出现一个与该主题关联的关键字，则该主题适用于该帖子。 匹配必须满足两个重要条件：

 1. 匹配不区分大小写。 
2. 匹配必须使用完整的单词，而不是子字符串。 

第二条规则极其重要。 例如：

-`"war"`比赛`"war"`-`"war"`不匹配`"warning"`-`"vaccine"`不匹配`"vaccinated"`确定帖子的所有匹配主题后：

 - 如果没有主题匹配，则返回`"Ambiguous!"`- 否则，返回匹配的主题ID，按升序排序并用逗号连接

 输出每篇文章包含一行：

 | 帖子 ID | 主题 |
 | ---| ---|
 | 帖子 ID | 匹配的主题或`"Ambiguous!"`|

 该问题本质上是 SQL 内部的文本匹配问题。 我们需要将每个帖子与每个关键字进行比较，同时尊重单词边界和不区分大小写。 

重要的边缘情况是：

 - 不同的大小写，例如`"WAR"`与`"war"`- 多个关键字映射到同一主题
 - 一个关键词属于多个主题
 - 防止子字符串匹配，例如`"war"`里面`"warning"`- 没有匹配关键字的帖子
 - 同一主题的多个匹配关键字导致主题 ID 重复

 这些限制强烈表明需要仔细的字符串规范化和精确的单词匹配。 

## 方法

 ### 蛮力方法

 最直接的方法是将每个帖子与每个关键字进行比较。 

对于每个帖子：

 1.将帖子内容转换为小写。 
2. 将内容拆分成单词。 
3. 对于每个关键字：

 - 将关键字转换为小写。 
- 检查帖子中的单词集中是否存在该关键字。 
4. 收集所有匹配的主题ID。 
5. 删除重复项。 
6. 对主题 ID 进行排序。 
7. 生成最终的字符串。 

这种方法是正确的，因为它明确地检查每个帖子的每个可能的关键字。 由于我们只接受标记化帖子中的完整单词，因此可以避免子字符串问题。 

然而，当帖子和关键字数量变大时，这种方法就会变得昂贵。 如果有：

 -`P`帖子
 -`K`关键词
 -`L`每个帖子的平均字数

 那么算法大致执行`P * K`比较。 

### 最佳方法

 关键的见解是单词查找应该是恒定的时间。 

我们可以对关键词进行预处理，而不是重复扫描关键词`Keywords`表转换为哈希映射：```
word -> set of topic IDs
```例子：```
football -> {1}
handball -> {1}
war -> {3}
vaccine -> {2}
```然后对于每个帖子：

 1. 将内容标准化为小写。 
2. 将其分解为单词。 
3. 对于帖子中的每个单词：

 - 检查哈希映射中是否存在。 
- 如果是，则将所有关联的主题 ID 添加到结果集中。 
4. 将集合转换为所需的输出格式。 

这避免了重复扫描每个帖子的整个关键字列表。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(P × K × L) | O(P × K × L) | O(L) | 将每个关键字与每个帖子进行比较 |
 | 最佳| O(K + 帖子总字数) | O(K) | 哈希图可实现恒定时间关键字查找 |

 ## 算法演练

 ### 第 1 步，标准化关键词

 创建一个哈希映射，其中：

 - 关键是小写关键字
 - 该值是与该关键字关联的一组主题 ID

 示例：```
"football" -> {1}
"war" -> {3}
```我们使用小写键，因此匹配不区分大小写。 

### 第 2 步，处理每个帖子

 对于每个帖子：

 1. 将全部内容转换为小写。 
2. 将内容按空格分割成单独的单词。 

这保证了只检查完整的单词。 

### 第 3 步，找到匹配的主题

 初始化一个空集，名为`matched_topics`。 

对于帖子中的每一个字：

 - 检查该词是否存在于关键词图中。 
- 如果存在：

 - 将所有对应的主题ID添加到`matched_topics`。 

使用集合是因为：

 - 多个关键字可能映射到同一主题
 - 相同的关键词可能会出现多次
 - 我们必须避免重复的主题ID

 ### 步骤 4，构建输出字符串

 如果`matched_topics`为空：```
"Ambiguous!"
```否则：

 1.对主题ID进行数字排序
 2. 将它们转换为字符串
 3. 用逗号将它们连接起来

 示例：```
{3, 1} -> "1,3"
```### 步骤5，返回结果

 为每个帖子返回一个输出行。 

### 为什么它有效

 该算法之所以有效，是因为每个帖子单词都会根据完整的有效关键字集进行检查。 由于帖子被标记为精确的单词，因此不会发生子字符串匹配。 哈希映射保证每个关键词查找准确高效，而集合则保证主题ID唯一。 排序可确保最终输出格式符合问题要求。 

## Python 解决方案```python
from collections import defaultdict
from typing import List

class Solution:
    def findTopic(self, keywords: List[List[str]], posts: List[List[str]]) -> List[List[str]]:
        word_to_topics = defaultdict(set)

        # Build keyword mapping
        for topic_id, word in keywords:
            word_to_topics[word.lower()].add(topic_id)

        result = []

        # Process each post
        for post_id, content in posts:
            matched_topics = set()

            words = content.lower().split()

            for word in words:
                if word in word_to_topics:
                    matched_topics.update(word_to_topics[word])

            if matched_topics:
                topic_string = ",".join(
                    str(topic_id)
                    for topic_id in sorted(matched_topics)
                )
            else:
                topic_string = "Ambiguous!"

            result.append([post_id, topic_string])

        return result
```实现首先构建一个名为的字典`word_to_topics`。 该字典将每个小写关键字映射到与其关联的主题 ID 集。 

使用`defaultdict(set)`简化了插入，因为我们可以直接添加主题 ID，而无需检查 key 是否已存在。 

接下来，我们独立处理每个帖子。 

内容转换为小写并使用以下命令分割成单词`.split()`。 由于问题保证内容只包含英文字母和空格，所以简单的空格分割就足够了。 

对于帖子中的每个单词，我们检查该单词是否存在于关键字词典中。 如果是，我们将所有关联的主题 ID 合并到`matched_topics`。 

处理完整个帖子后：

 - 如果集合为空，则结果为`"Ambiguous!"`- 否则，我们对主题 ID 进行排序并将它们连接到所需的逗号分隔字符串中

 最后，我们附加`[post_id, topic_string]`配对进入答案列表。 

## 解决方案```go
package main

import (
	"sort"
	"strconv"
	"strings"
)

type Solution struct{}

func (s Solution) findTopic(keywords [][]string, posts [][]string) [][]string {
	wordToTopics := make(map[string]map[int]bool)

	// Build keyword mapping
	for _, row := range keywords {
		topicID, _ := strconv.Atoi(row[0])
		word := strings.ToLower(row[1])

		if _, exists := wordToTopics[word]; !exists {
			wordToTopics[word] = make(map[int]bool)
		}

		wordToTopics[word][topicID] = true
	}

	result := [][]string{}

	// Process posts
	for _, row := range posts {
		postID := row[0]
		content := strings.ToLower(row[1])

		words := strings.Fields(content)

		matchedTopics := make(map[int]bool)

		for _, word := range words {
			if topics, exists := wordToTopics[word]; exists {
				for topicID := range topics {
					matchedTopics[topicID] = true
				}
			}
		}

		if len(matchedTopics) == 0 {
			result = append(result, []string{postID, "Ambiguous!"})
			continue
		}

		topicList := []int{}

		for topicID := range matchedTopics {
			topicList = append(topicList, topicID)
		}

		sort.Ints(topicList)

		topicStrings := []string{}

		for _, topicID := range topicList {
			topicStrings = append(topicStrings, strconv.Itoa(topicID))
		}

		result = append(result, []string{
			postID,
			strings.Join(topicStrings, ","),
		})
	}

	return result
}
```Go 实现遵循与 Python 解决方案相同的整体结构，但有一些特定于语言的细节。 

Go 没有内置的集合类型，因此带有布尔值的映射用于模拟集合：```go
map[int]bool
```同样，关键字映射使用嵌套映射：```go
map[string]map[int]bool
```这`strings.Fields()`使用函数代替`split()`因为它会自动干净地处理空格标记化。 

由于 Go 无法直接对映射键进行排序，因此在排序之前会将主题 ID 收集到一个切片中。 

与 Python 不同，Go 需要使用显式字符串和整数转换`strconv`包裹。

空间使用主要来自存储关键字映射和主题集。

 ## 边缘情况

 ### 子串冲突

 最危险的错误之一是使用子字符串匹配而不是精确的单词匹配。 

例如：```
keyword = "war"
post = "warning"
```使用子字符串搜索的简单实现会错误匹配`"war"`里面`"warning"`。 

该解决方案通过将帖子拆分为完整的单词并执行精确的哈希映射查找来避免该问题。 

### 多个关键字映射到同一主题

 一篇文章可能包含属于同一主题的多个关键字。 

例子：```
Topic 1:
- football
- handball
```包含这两个词的帖子仍应生成：```
"1"
```不是：```
"1,1"
```该实现使用集合来保证唯一性。 

### 一个关键字映射到多个主题

 同一关键词可能属于多个主题。 

例子：```
football -> topic 1
football -> topic 2
```什么时候`"football"`出现在帖子中，必须包含两个主题。 

哈希映射为每个关键字存储一组主题 ID，因此可以正确收集所有关联的主题。 

### 没有匹配关键字的帖子

 有些帖子可能根本不包含任何关键字。 

在这种情况下，结果一定是：```
"Ambiguous!"
```该实现通过在处理所有单词后检查主题集是否为空来处理此问题。 

### 混合大小写

 关键字和帖子内容可以使用任意大小写：```
"WAR"
"War"
"war"
```所有比较均针对小写字符串执行，无论大小写，都能保证一致的匹配。
