 **难度：** 🟡 中等

 ## 解决方案

 ## 问题理解

 这个问题要求我们模拟在微波炉中输入烹饪时间的过程，同时最小化总的手指移动和按钮按下成本。 

微波炉最多接受四位数字。 在内部，微波炉将这些数字解释为以下形式的四位数字字符串：$$MMSS$$前两位数字代表分钟，后两位数字代表秒。 总的烹饪时间为：$$60 \times \text{minutes} + \text{seconds}$$一个重要的细节是，当输入的数字少于四位时，微波炉会自动在前面添加前导零。 例如：

 - 进入`76`变成`0076`- 进入`960`变成`0960`微波炉不要求秒部分小于59。例如：

 -`0960`意思是9分60秒
 - 这相当于 10 分钟

 我们得到：

 -`startAt`，手指最初停留的数字
 -`moveCost`，移动到另一个数字的疲劳成本
 -`pushCost`，按下当前数字的疲劳成本
 -`targetSeconds`，我们想要的确切烹饪时间

 目标是计算输入一些准确表示的有效数字序列所需的最小总疲劳成本`targetSeconds`。 

限制相对较小：

 -`targetSeconds <= 6039`- 微波炉最多支持`99:99`这告诉我们对可能的分钟和秒组合进行强力枚举是可行的。 我们不需要先进的优化技术或大规模动态规划。 

一些边缘情况很重要：

 - 多个`(minutes, seconds)`成对的可以代表相同的总时间。 
- 秒数可能超过 59。 
- 键入时省略前导零。 
- 重复按同一数字不需要移动。 
- 最便宜的表示可能不是最自然的。 
- 某些表示可能需要更少的数字，从而减少移动和推送成本。 

例如，`600`秒可以输入为：

 -`1000`-`0960`-`960`都代表相同的时间，但它们的成本不同。 

## 方法

 ### 蛮力方法

 一个简单的解决方案会生成长度为 1 到 4 的每个可能的数字序列，将每个序列解释为微波时间，并检查它是否等于`targetSeconds`。 

有：$$10 + 100 + 1000 + 10000$$可能的序列，大约有 11,110 个候选序列。 

对于每位候选人：

 1. 将其标准化为四位数。 
2. 提取分钟和秒。 
3. 计算总烹饪时间。 
4.如果匹配`targetSeconds`，计算打字成本。 
5. 保持最低限度。 

这种方法是正确的，因为它检查每个有效的输入序列。 然而，它不必要地昂贵和尴尬，因为许多序列映射到相同的时间表示。 

### 最佳观察

 关键的见解是烹饪时间完全由以下因素决定：$$60 \times m + s = targetSeconds$$在哪里：

-`0 <= m <= 99`-`0 <= s <= 99`我们可以直接枚举有效的数字序列，而不是生成所有数字序列`(minutes, seconds)`对。 

对于给定的目标时间，只有几个有意义的候选者：

 - 标准分解：$$m = targetSeconds // 60$$

$$s = targetSeconds \% 60$$- 借用一分钟得到的另一个等价分解：$$m - 1,\ s + 60$$因为允许的秒数最多为 99，所以两者都可能有效。 

对于每个有效的表示：

 1. 构建最小数字字符串。 
2. 模拟运动和按压。 
3. 计算总成本。 
4. 返回最小值。 

这极大地减少了搜索空间。

 | --- | --- | --- | --- |
 | 蛮力 | O(10^4) | O(10^4) | O(1) | O(1) | 枚举每个可能的数字序列 |
 | 最佳| O(1) | O(1) | O(1) | O(1) | 只检查一些有效的分钟-秒表示 |

 ## 算法演练

 1. 计算默认的分秒表示。 

我们首先计算：$$minutes = targetSeconds // 60$$和：$$seconds = targetSeconds \% 60$$这是正常的时间转换。 
2. 生成所有有效的表示。 

时间可能有多种等效形式，因为秒可能超过 59。 

例如：$$600 = 10:00 = 09:60$$因此我们检查：

 -`(minutes, seconds)`-`(minutes - 1, seconds + 60)`只要两者都保持在微波限制范围内。 
3. 将每个表示形式转换为数字序列。 

每个`(m, s)`对变为：$$\text{formatted as } MMSS$$然后我们删除前导零，因为用户输入的数字可能少于四位。 

例子：

-`10:00`变成`"1000"`-`09:60`变成`"960"`4. 模拟手指运动。 

我们跟踪当前手指位置。 

对于每个数字：

 - 如果手指已经放在该数字上：

 - 只需付费`pushCost`- 否则：

 - 支付`moveCost`- 然后付款`pushCost`5. 跟踪最低成本。 

在所有有效表示中，返回最小的计算成本。 

### 为什么它有效

 每个有效的微波条目都对应于一些`(minutes, seconds)`配对满足：$$60m + s = targetSeconds$$唯一可能的替代表示方式是在分钟和秒之间重新分配 60 秒。 由于秒不能超过 99，因此最多存在两个有效分解。 

通过评估每个有效的分解并计算其确切的打字成本，该算法保证找到最小的可能成本。 

## Python 解决方案```python
class Solution:
    def minCostSetTime(
        self,
        startAt: int,
        moveCost: int,
        pushCost: int,
        targetSeconds: int
    ) -> int:

        def typing_cost(sequence: str) -> int:
            current = startAt
            total = 0

            for ch in sequence:
                digit = int(ch)

                if digit != current:
                    total += moveCost

                total += pushCost
                current = digit

            return total

        def build_sequence(minutes: int, seconds: int) -> str:
            sequence = f"{minutes:02d}{seconds:02d}"
            sequence = sequence.lstrip('0')

            return sequence if sequence else "0"

        answer = float('inf')

        minute = targetSeconds // 60
        second = targetSeconds % 60

        candidates = []

        if 0 <= minute <= 99 and 0 <= second <= 99:
            candidates.append((minute, second))

        if minute > 0 and second + 60 <= 99:
            candidates.append((minute - 1, second + 60))

        for m, s in candidates:
            sequence = build_sequence(m, s)
            answer = min(answer, typing_cost(sequence))

        return answer
```该解决方案将问题分为两个逻辑辅助函数。 

这`typing_cost`函数模拟实际的按钮按下。 它会跟踪手指位置并仅在更改数字时应用移动成本。 每次按下按钮都会产生`pushCost`。 

这`build_sequence`函数将微波条目格式化为四位数字并删除前导零。 这会产生最短的有效输入序列。 

主逻辑计算标准时间分解和将1分钟变为60秒得到的替代分解。 每个有效候选者都会被独立评估，并返回最小成本。 

## 解决方案```go
package main

import (
	"fmt"
	"math"
	"strings"
)

func minCostSetTime(startAt int, moveCost int, pushCost int, targetSeconds int) int {

	typingCost := func(sequence string) int {
		current := startAt
		total := 0

		for _, ch := range sequence {
			digit := int(ch - '0')

			if digit != current {
				total += moveCost
			}

			total += pushCost
			current = digit
		}

		return total
	}

	buildSequence := func(minutes int, seconds int) string {
		sequence := fmt.Sprintf("%02d%02d", minutes, seconds)
		sequence = strings.TrimLeft(sequence, "0")

		if sequence == "" {
			return "0"
		}

		return sequence
	}

	answer := math.MaxInt32

	minute := targetSeconds / 60
	second := targetSeconds % 60

	candidates := [][]int{}

	if minute >= 0 && minute <= 99 && second >= 0 && second <= 99 {
		candidates = append(candidates, []int{minute, second})
	}

	if minute > 0 && second+60 <= 99 {
		candidates = append(candidates, []int{minute - 1, second + 60})
	}

	for _, candidate := range candidates {
		m := candidate[0]
		s := candidate[1]

		sequence := buildSequence(m, s)
		cost := typingCost(sequence)

		if cost < answer {
			answer = cost
		}
	}

	return answer
}
```Go 实现遵循与 Python 版本相同的结构。 

一个区别是 Go 没有与 Python 相同的内置字符串修剪方法`lstrip`， 所以`strings.TrimLeft`被用来代替。 

Go 还需要显式处理大的初始值，所以`math.MaxInt32`用于初始化答案。 

由于 Go 自然不支持嵌套元组，因此候选对存储为整数切片。

 ## 边缘情况

 ### 多个有效表示

 一个目标时间可能有多个有效时间`(minutes, seconds)`表示。 例如：$$600 = 10:00 = 09:60$$仅考虑标准分秒转换的幼稚实现可能会错过更便宜的序列。 只要有效，实现就会显式检查这两种分解。 

### 前导零

 微波炉允许少于四位数字，因为前导零会自动添加到前面。 例如：```
8 -> 0008
```有缺陷的实现可能会错误地强制输入四位数并超出计算成本。 该解决方案在模拟打字之前删除前导零。 

### 重复数字

 当连续数字相同时，手指不动。 例如：```
111
```仅推送成本应添加在第一位数字之后。 该实现在收取移动成本之前将当前手指位置与下一个数字进行比较。 

### 大于 59 的秒

 与标准时钟不同，微波炉接受最多 99 秒。输入如下：```
0960
```有效并代表 600 秒。 简单的时间格式化实现可能会拒绝这些情况。 该解决方案有意允许全范围内的秒数`[0, 99]`。
