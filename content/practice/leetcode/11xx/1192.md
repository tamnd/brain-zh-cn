 # LeetCode 1192 - 网络中的关键连接

 ## 问题理解

 这个问题为我们提供了一个表示服务器网络的无向图。 每个服务器由一个整数标识`0`到`n - 1`，以及每对`[a, b]`在`connections`表示服务器之间的双向边缘`a`和服务器`b`。 

该图是连接的，这意味着每个服务器都可以通过某种路径到达其他服务器。 我们的目标是识别所有_关键连接_。 

如果删除该边缘会断开部分网络的连接，则该连接被认为是关键的。 在图论中，这样的边称为“桥”。 如果删除一条边会增加图中连通分量的数量，则该边就是一座桥。 

例如，考虑这个图：```
0 --- 1 --- 3
 \   /
   2
```所形成的三角形为`0`,`1`， 和`2`有冗余路径。 删除三角形内的任何边仍然会留下通过另一条路线连接的节点。 然而，节点`3`仅通过边缘连接`[1,3]`。 删除该边会隔离节点`3`， 所以`[1,3]`是一个关键的连接。 

约束条件很重要：

 -`n`可以大到`10^5`- 边的数量也可以大到`10^5`这些限制立即排除了昂贵的图重新计算方法。 任何比粗略更糟糕的算法`O(n + m)`在哪里`m`是可能超时的边数。 

该图有几个保证：

 - 无自循环
 - 没有重复的边缘
 - 图形已连接

 这些保证简化了实现，因为我们不需要处理断开连接的组件或重复的邻接条目。 

一些边缘情况很重要：

 - 只有两个节点和一条边的图，该边始终是关键的。 
- 包含循环的图、循环内的边从来都不是关键的，因为存在替代路径。 
- 树结构，每条边都很关键，因为删除任何边都会断开图的连接。 
- 由窄桥连接的密集循环区域，仅应返回桥边缘。 

## 方法

 ### 蛮力方法

 蛮力方法在概念上很简单。 

对于图中的每条边：

 1. 暂时去除边缘。 
2. 从任意节点运行 DFS 或 BFS。 
3. 检查所有节点是否仍然可达。 
4. 如果不是，则移除的边缘至关重要。 
5. 恢复边缘并继续。 

这是有效的，因为关键连接的定义正是图在删除该边后是否断开。 

然而，性能却很差。 

假设有`m`边缘。 对于每条边，我们执行图遍历成本计算`O(n + m)`。 因此总复杂度变为：```
O(m × (n + m))
```两者都有`n`和`m`最多`10^5`，这太慢了。 

### 最优方法，Tarjan 桥算法

 关键的见解是我们不需要独立地重新计算每个边缘的连接性。 

相反，我们可以在单次 DFS 遍历期间分析该图。 

重要的观察是：

 如果节点可以通过后边缘到达其祖先之一，则通向该节点的边缘并不重要，因为存在备用路径。 

为了有效地捕获这一点，我们为每个节点维护两个值：

 -`discovery[node]`- 第一次看到节点时的 DFS 访问顺序。 
-`low[node]`- 最多使用一个后沿从该节点或其后代可到达的最早发现时间。 

如果在DFS期间我们遍历：```
u -> v
```然后确定：```
low[v] > discovery[u]
```那么没有替代路线`v`或其子树回到`u`或任何祖先`u`。 

这意味着边缘`[u,v]`是一座桥梁，因此它是一个关键的连接。 

该算法称为 Tarjan 寻桥算法，以线性时间运行。

 ## 算法演练

 ### 第 1 步：构建邻接表

 由于图是无向的，所以每条边`[u,v]`是在两个方向上添加的。 

我们使用邻接列表，因为它提供了高效的遍历，并且使用与边数成比例的内存。 

### 步骤2：初始化DFS簿记数组

 我们维持：

 -`discovery[node]`- 存储第一次访问节点的时间。 
- 初始化为`-1`对于未访问的节点。 
-`low[node]`- 存储最早可到达的发现时间。 

我们还维护着全球`time`每当第一次访问节点时计数器就会增加。 

### 第三步：开始DFS遍历

 我们从节点开始DFS`0`。 

DFS 期间：

 - 用当前时间戳标记节点。 
- 设置两者`discovery[node]`和`low[node]`最初为相同的值。 
- 探索所有邻居。 

### 步骤 4：跳过父边

 在无向图中，每条边出现两次。 

当从`u`到`v`，我们不想立即重新访问`u`从`v`并错误地将其视为后缘。 

因此，如果邻居是 DFS 父级，我们会跳过该邻居。 

### 步骤 5：处理未访问的邻居

 如果邻居`v`尚未访问过：

 1. 递归到`v`2、递归返回后：

 - 更新：```
low[u] = min(low[u], low[v])
```这会向上传播最早的可到达祖先。 

### 第 6 步：检测桥接

 处理完子项后`v`， 查看：```
low[v] > discovery[u]
```如果为真：

 -`v`无法到达`u`或任何祖先`u`- 去除边缘`[u,v]`断开图表的连接

 因此`[u,v]`是一个关键的连接。 

### 步骤 7：处理后边缘

 如果邻居`v`已被访问且不是父级：```
low[u] = min(low[u], discovery[v])
```这意味着`u`找到了一条回到更早祖先的道路。 

### 为什么它有效

 该算法之所以有效，是因为`low[node]`精确捕获从该节点的 DFS 子树可到达的最早祖先。 

如果子树的根为`v`无法到达任何祖先`u`，那么该子树与图的其余部分之间的唯一连接是边`[u,v]`。 

因此，删除该边会断开图的连接，使其成为一座桥梁。 

相反，如果存在后边缘，则存在替代路由并且该边缘并不重要。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def criticalConnections(self, n: int, connections: List[List[int]]) -> List[List[int]]:
        graph = defaultdict(list)

        for u, v in connections:
            graph[u].append(v)
            graph[v].append(u)

        discovery = [-1] * n
        low = [-1] * n
        time = 0
        bridges = []

        def dfs(node: int, parent: int) -> None:
            nonlocal time

            discovery[node] = time
            low[node] = time
            time += 1

            for neighbor in graph[node]:
                if neighbor == parent:
                    continue

                if discovery[neighbor] == -1:
                    dfs(neighbor, node)

                    low[node] = min(low[node], low[neighbor])

                    if low[neighbor] > discovery[node]:
                        bridges.append([node, neighbor])
                else:
                    low[node] = min(low[node], discovery[neighbor])

        dfs(0, -1)

        return bridges
```实现首先构建图的邻接列表表示。 由于该图是无向的，因此每条边都在两个方向上插入。 

这`discovery`数组跟踪 DFS 期间首次访问每个节点的时间。 这`low`数组跟踪节点子树中最早可到达的发现时间。 

DFS 函数执行核心逻辑。 

进入节点时：

 - 分配当前的DFS时间戳
 - 初始化两者`discovery`和`low`- 增加全局时间计数器

 对于每个邻居：

 - 跳过父边
 - 如果邻居未被访问：

 - 递归
 - 向上传播低链接值
 - 检查边缘是否是桥
 - 否则：

 - 使用已经访问过的祖先更新低链接

 最后，算法返回所有检测到的桥边缘。 

## 解决方案```go
package main

func criticalConnections(n int, connections [][]int) [][]int {
	graph := make([][]int, n)

	for _, edge := range connections {
		u, v := edge[0], edge[1]
		graph[u] = append(graph[u], v)
		graph[v] = append(graph[v], u)
	}

	discovery := make([]int, n)
	low := make([]int, n)

	for i := 0; i < n; i++ {
		discovery[i] = -1
	}

	time := 0
	result := [][]int{}

	var dfs func(int, int)

	dfs = func(node int, parent int) {
		discovery[node] = time
		low[node] = time
		time++

		for _, neighbor := range graph[node] {
			if neighbor == parent {
				continue
			}

			if discovery[neighbor] == -1 {
				dfs(neighbor, node)

				if low[neighbor] < low[node] {
					low[node] = low[neighbor]
				}

				if low[neighbor] > discovery[node] {
					result = append(result, []int{node, neighbor})
				}
			} else {
				if discovery[neighbor] < low[node] {
					low[node] = discovery[neighbor]
				}
			}
		}
	}

	dfs(0, -1)

	return result
}
```Go 实现遵循与 Python 版本相同的算法结构。 

一些特定于 Go 的细节值得注意：

 - 切片用于邻接列表和结果存储。 
- 数组用零值初始化，因此我们显式填充`discovery`和`-1`来表示未访问过的节点。 
- Go不直接支持嵌套命名函数，所以我们定义`dfs`在分配递归实现之前作为函数变量。 
- 整数溢出不是问题，因为时间戳永远不会超过`10^5`。

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n + m) | 每个节点和边都被处理一次 |

 DFS 遍历只访问每个节点一次。 每个无向边都会检查两次，每次从每个端点检查一次。 因此，总运行时间与图的大小成线性关系。 

邻接表需要`O(n + m)`空间。 发现和低阵列需要`O(n)`，递归栈可以达到`O(n)`最坏情况下的深度。

 ## 边缘情况

 ### 树结构

 树不包含循环，这意味着每条边都是连接图的两个区域的唯一路径。 

这是错误的常见来源，因为算法必须正确地将每条边识别为桥。 该实现自然地处理了这个问题，因为没有子树可以通过后边缘到达祖先，导致每个边缘都满足：```
low[child] > discovery[parent]
```### 全循环图

 在每个节点都属于一个循环的图中，没有边应该是关键的。 

如果幼稚的实现错误地处理后边缘或父跳过逻辑，则可能会错误地对边缘进行分类。 算法正确更新`low`每当遇到已经访问过的祖先时，都会返回值，从而保留备用路线的存在。 

### 长线性链条

 形状像链表的图可以创建尽可能深的 DFS 递归深度。 

这很重要，因为递归深度可能会变大`n = 10^5`。 从算法上来说，该解决方案仍然是正确的，但在 Python 中，这可能会在某些环境中面临递归深度限制的风险。 LeetCode的环境一般都支持递归DFS来解决这个问题，但在生产系统中可以考虑迭代DFS或递归限制调整。
