[LeetCode 第 1190 题](https://leetcode.com/problems/reverse-substrings- Between-each-pair-of-parentheses/)

 **难度：** 🟡 中等
 **主题：** 字符串、堆栈

 ## 解决方案

 ## 问题理解

 问题给了我们一个字符串`s`包含小写英文字母和平衡括号。 我们的任务是从最里面的一对开始，重复反转每对匹配的括号内包含的子字符串。 所有反转完成后，我们必须返回不带任何括号的最终字符串。 

重要的细节是嵌套括号很重要。 当一对括号存在于另一对括号内时，在处理外部子字符串之前必须反转内部子字符串。 这意味着转换是从最深的嵌套级别向外发生的。 

例如，考虑：```
(u(love)i)
```最里面的子串是：```
(love)
```反转它给出：```
(u(evol)i)
```现在外括号包含：```
uevoli
```反转得到：```
iloveu
```最终答案删除了所有括号。 

输入大小最多为 2000 个字符。 这个值足够小，甚至一些二次解也可以通过，但重复的子串重建仍然会变得低效和混乱。 由于括号保证是平衡的，所以我们永远不需要担心无效的表达式或不匹配的括号。 

一些边缘情况很重要：

 - 根本没有括号的字符串，例如`"abc"`，应该简单地返回`"abc"`。 
- 深度嵌套的括号可能会暴露低效的反转策略。 
- 空括号，例如`"()"`产生一个空子字符串并且不应该破坏逻辑。 
- 多个相邻的带括号的部分必须分别单独处理。 
- 嵌套反转可以以令人惊讶的方式恢复原始顺序，因此必须仔细处理顺序。 

## 方法

 ### 蛮力方法

 一种简单的方法是重复找到最里面的一对括号，反转其中的子字符串，用反转的子字符串替换整个括号部分，然后继续，直到没有括号为止。 

实现这一点的一种方法是：

 1. 从左到右扫描字符串。 
2.每当右括号`)`找到后，向后搜索其匹配的左括号`(`。 
3.提取里面的子串。 
4. 反转。 
5. 重建不带括号的字符串。 
6. 重新开始扫描。 

这是可行的，因为反转最里面的子字符串首先符合问题要求。 然而，每次替换都会创建一个新字符串，并且重复扫描该字符串会变得昂贵。 

在最坏的情况下，每个反转操作几乎触及整个字符串，并且可能有许多嵌套对。 这导致了二次时间复杂度。 

### 最佳方法

 关键的见解是括号定义了遍历的方向变化。 

我们可以使用堆栈预处理匹配的括号位置，而不是重复重建子字符串。 一旦我们知道哪些括号相互匹配，我们就可以模拟遍历字符串。 

巧妙的技巧是：

 - 通常，我们从左向右移动。 
- 当我们遇到括号时，我们跳转到它匹配的括号并反转遍历方向。 
- 因为方向变化自然地模拟子串反转，所以我们从不显式反转子串。 

这产生了一个优雅的线性时间解决方案。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 重复子串重建和重新扫描|
 | 最佳| O(n) | O(n) | 使用匹配的括号索引和定向遍历 |

 ## 算法演练

 ### 第 1 步：使用堆栈匹配括号

 我们首先预处理字符串以确定哪些括号属于一起。 

我们使用堆栈来存储左括号的索引。 

当我们扫描字符串时：

 - 如果我们看到`'('`，我们将其索引压入堆栈。 
- 如果我们看到`')'`，我们弹出最近的开盘指数。 
- 这两个索引形成匹配对。 

我们将映射存储在字典或数组中：```
partner[left_index] = right_index
partner[right_index] = left_index
```这允许匹配括号之间的恒定时间跳跃。 

### 步骤 2：遍历字符串

 我们现在模拟通过绳子的运动。 

我们维持：

 -`index`，当前位置
 -`direction`， 任何一个`1`从左到右或`-1`从右到左

 最初：```
index = 0
direction = 1
```### 步骤 3：处理每个字符

 当指数保持在界限内时：

 - 如果当前字符是字母：

 - 将其附加到结果中。 
- 使用当前方向移动到下一个位置。 
- 如果当前字符是括号：

 - 使用映射跳转到其匹配的括号。 
- 反转运行方向。 
——朝着新的方向更进一步。 

方向反转是关键的想法。 它自然地模拟子字符串反转，而无需显式反转任何子字符串。 

### 第 4 步：构建最终结果

 由于括号永远不会附加到结果中，因此最终字符串会自动排除它们。 

我们连接所有收集到的字符并返回最终的字符串。 

### 为什么它有效

 每当遍历进入括号内的部分时，方向就会翻转。 这意味着该部分内的字符将以相反的顺序访问。 如果遇到另一个嵌套括号，方向会再次翻转，恢复嵌套部分内的原始方向。 这些交替的方向变化准确地再现了所需的最内层第一反转行为。 

由于在遍历过程中每个字符最多被访问一次，因此该算法有效地产生正确的反转输出。 

## Python 解决方案```python
class Solution:
    def reverseParentheses(self, s: str) -> str:
        n = len(s)

        pair = {}
        stack = []

        # Match parentheses
        for index, char in enumerate(s):
            if char == '(':
                stack.append(index)
            elif char == ')':
                opening_index = stack.pop()

                pair[opening_index] = index
                pair[index] = opening_index

        result = []

        index = 0
        direction = 1

        while 0 <= index < n:
            if s[index] == '(' or s[index] == ')':
                index = pair[index]
                direction *= -1
            else:
                result.append(s[index])

            index += direction

        return ''.join(result)
```实现首先对括号关系进行预处理。 这`stack`存储左括号的索引。 每当遇到右括号时，我们都会弹出匹配的左括号并记录两个方向的关系。 

第二阶段进行定向遍历。 

这`index`变量跟踪我们当前的位置，而`direction`决定我们是从左到右还是从右到左移动。 

当我们遇到普通字符时，我们将其直接附加到结果中。 

当我们遇到括号时，我们跳转到它的匹配伙伴并反转遍历方向。 这有效地模拟了反转所包含的子字符串，而无需实际创建反转的子字符串。 

最后，我们将收集到的字符加入到最终的答案中。 

## 解决方案```go
func reverseParentheses(s string) string {
	n := len(s)

	pair := make(map[int]int)
	stack := []int{}

	// Match parentheses
	for i, ch := range s {
		if ch == '(' {
			stack = append(stack, i)
		} else if ch == ')' {
			openingIndex := stack[len(stack)-1]
			stack = stack[:len(stack)-1]

			pair[openingIndex] = i
			pair[i] = openingIndex
		}
	}

	result := []byte{}

	index := 0
	direction := 1

	for index >= 0 && index < n {
		if s[index] == '(' || s[index] == ')' {
			index = pair[index]
			direction *= -1
		} else {
			result = append(result, s[index])
		}

		index += direction
	}

	return string(result)
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

一个`map[int]int`存储匹配的括号索引，而切片用作堆栈。 

结果是使用a累积的`[]byte`，这对于 Go 中的字符串构造非常有效。 由于输入仅包含 ASCII 小写字母和括号，因此基于字节的处理是完全安全的。 

与 Python 列表不同，Go 切片需要使用切片语法手动删除顶部堆栈元素：```go
stack = stack[:len(stack)-1]
```不需要对整数溢出进行特殊处理，因为索引保留在字符串长度限制内。

 ## 边缘情况

 一个重要的边缘情况是根本没有括号的字符串，例如`"abc"`。 有缺陷的实现可能会假设每个字符串至少包含一个带括号的部分，并且会不必要地失败。 在此实现中，遍历只是将每个字符直接附加到结果中，因为不会发生方向变化。 

另一个关键情况是空括号：```
()
```一些基于子字符串的方法意外地产生索引错误或尝试对空范围进行无效反转。 在此解决方案中，遍历只是跳过匹配的括号并反转方向，而不附加任何字符，从而正确生成空字符串。 

深层嵌套的括号是错误的另一个常见来源。 例如：```
((abc))
```内部反转产生`"cba"`，而外部反转则恢复原来的顺序`"abc"`。 以错误顺序反转子字符串的实现在这里通常会失败。 定向遍历方法可以自然地处理嵌套，因为每对括号只翻转遍历方向一次。 

最后一个棘手的情况涉及括号外带有字符的相邻嵌套部分，例如：```
a(bc)d
```该算法必须保留括号外的字符，同时仅反转所包含的子字符串。 由于遍历仅改变匹配对内部的方向，因此外部字符会自动保留在其原始位置。
