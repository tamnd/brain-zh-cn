 **难度：** 🔴难
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 这个问题要求我们确定，对于市场系统中的每个用户，他们销售的第二件商品的品牌是否与他们最喜欢的品牌相匹配。 

该数据库包含三个表：

 - 的`Users`表存储用户信息，包括他们的`favorite_brand`。 
- 这`Orders`表记录采购和销售。 每个订单包括一个`seller_id`,`item_id`， 和`order_date`。 
- 这`Items`表映射每个`item_id`对其`item_brand`。 

对于每个用户，我们必须识别**他们按时间顺序出售的第二件商品**，确定该商品的品牌，并将其与用户最喜欢的品牌进行比较。 

如果第二个售出商品的品牌与最喜欢的品牌相匹配，则输出应包含`"yes"`。 否则，它应该包含`"no"`。 

一个非常重要的要求是，销售**少于两件物品**的用户必须仍然出现在结果中，并且他们的答案必须是`"no"`。 

结果应包含：

 -`seller_id`，对应用户的ID
 -`2nd_item_fav_brand`，这是`"yes"`或者`"no"`该问题保证**没有卖家在同一天销售超过一件商品**。 此保证很重要，因为我们需要按日期确定“第二个”售出商品。 由于同一卖家不可能在同一天进行多次销售，因此按`order_date`是充分且确定的。 

主要挑战是有效地识别**每个卖家的第二次销售**，然后将已售商品的品牌与卖家最喜欢的品牌进行比较。 

一些边缘情况很容易导致简单的实现失败：

 - 用户可能有**零销售额**，但仍然必须出现`"no"`。 
- 用户可能**恰好有一笔销售**，这也会导致`"no"`。 
- 第二个出售的商品可能存在，但其品牌可能**不匹配**最喜欢的品牌。 
- 某些用户可能有很多销售，需要仔细订购以确保正确选择第二件商品。 
- 由于每个用户都必须出现在结果中，所以我们不能从`Orders`独自的。 我们必须使用没有订单的用户`LEFT JOIN`。 

## 方法

 ### 蛮力方法

 暴力解决方案将单独处理每个用户。 

对于每个用户，我们可以查询他们是卖家的所有订单，对这些订单进行排序`order_date`，然后检查是否存在第二次销售。 如果是，我们将检索相应商品的品牌并将其与用户最喜欢的品牌进行比较。 

这是有效的，因为对每个用户的所有销售进行显式排序可以保证我们可以正确识别第二个销售的商品。 

然而，这种方法效率低下。 如果我们重复地为每个用户单独扫描和排序订单，我们最终会执行多余的工作。 在数据库系统中，对每个用户的数据进行重复分组和排序成本高昂且扩展性差。 

相反，我们希望有一种方法可以一次性对全球所有销售进行排名，并直接识别每个卖家的第二次销售。 

### 关键见解

 关键的观察是，我们只关心每个卖家的**第二次销售**。 

这自然建议使用**窗口函数**，特别是`ROW_NUMBER()`。 

我们可以通过以下方式划分订单`seller_id`并排序`order_date`。 这为每笔销售分配了顺序排名：

 - 排名`1`= 第一件售出的商品
 - 排名`2`= 第二件售出商品
 - 排名`3+`= 后来出售的物品

 排名完成后，我们只需要其中的行`rank = 2`。 

找到第二个售出的商品后，我们将其加入`Items`要检索品牌，请将其与用户的品牌进行比较`favorite_brand`，并输出`"yes"`或者`"no"`。 

由于每个用户都必须出现在结果中，因此我们使用`LEFT JOIN`从`Users`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(U × O log O) | O(U × O log O) | O(O)| 独立排序每个卖家的订单 |
 | 最佳| O(O log O) | O(O log O) | O(O)| 用途`ROW_NUMBER()`对销售额进行一次排名 |

 在哪里：

-`U`= 用户数量
 -`O`= 订单数量

 ## 算法演练

 ### 使用窗口函数的最优算法

 1. **按时间顺序对每个卖家的订单进行排名**

 使用`ROW_NUMBER()`划分为`seller_id`并按以下顺序订购`order_date`。 

这会为每个卖家的销售历史记录创建一个排名。 

示例：

 | 卖家 ID | 订单日期 | 项目 ID | 等级 |
 | ---| ---| ---| ---|
 | 2 | 2019-08-01 | 4 | 1 |
 | 2 | 2019-08-04 | 1 | 2 |
 | 4 | 2019-08-04 | 1 | 1 |
 | 4 | 2019-08-05 | 2 | 2 |
 2. **仅筛选第二次销售**

 排序后，仅保留其中的行`rank = 2`。 

这些行代表每个卖家的第二个售出商品。 
3. **加入`Items`**

使用`item_id`检索`item_brand`。 

这为我们提供了卖家第二个售出商品的品牌。 
4. **加入`Users`**

 执行一个`LEFT JOIN`从`Users`确保所有用户都留在结果中，即使是那些没有二次销售的用户。 
5. **比较品牌**

 使用条件表达式：

 - 如果第二件售出商品的品牌等于`favorite_brand`， 返回`"yes"`- 否则，返回`"no"`### 为什么它有效

 正确性来自于提供的保证`ROW_NUMBER()`。 由于每个卖家的订单都是按`order_date`, 具有排名的行`2`始终是卖家的第二次销售。 该问题保证卖家每天最多有一笔销售，因此订单是明确的。 通过将第二个售出商品的品牌与最喜欢的品牌进行比较，我们可以准确地生产出所需的输出。 没有二次销售的用户自然会产生`"no"`因为`LEFT JOIN`。 

## Python 解决方案

 由于这是一个数据库问题，Python 提交只是在所需方法内返回的 SQL 查询。```
from typing import Any

class Solution:
    def marketAnalysis(self) -> str:
        return """
        WITH ranked_orders AS (
            SELECT
                seller_id,
                item_id,
                ROW_NUMBER() OVER (
                    PARTITION BY seller_id
                    ORDER BY order_date
                ) AS sale_rank
            FROM Orders
        )
        SELECT
            u.user_id AS seller_id,
            CASE
                WHEN i.item_brand = u.favorite_brand
                THEN 'yes'
                ELSE 'no'
            END AS 2nd_item_fav_brand
        FROM Users u
        LEFT JOIN ranked_orders r
            ON u.user_id = r.seller_id
            AND r.sale_rank = 2
        LEFT JOIN Items i
            ON r.item_id = i.item_id
        """
```该查询首先创建一个名为的公用表表达式`ranked_orders`。 此 CTE 使用以下方式为每个卖家的订单分配一个序列号`ROW_NUMBER()`。 划分方式为`seller_id`确保每个卖家获得独立排名，同时按`order_date`保证时间顺序。 

接下来，主要查询从`Users`。 这很重要，因为每个用户都必须出现在最终输出中，即使他们什么也没卖出去。 

一个`LEFT JOIN`将用户与其排名第二的销售联系起来。 将连接条件限制为`sale_rank = 2`确保我们只检索第二个售出的商品。 

其他`LEFT JOIN`连接到`Items`这样我们就可以检索已售商品的品牌。 

最后，一个`CASE`语句将第二个项目的品牌与用户最喜欢的品牌进行比较。 如果它们匹配，我们输出`"yes"`。 否则，包括错过第二次销售，我们输出`"no"`。

 ## 边缘情况

 ### 没有销售的用户

 一个常见的错误是从以下位置开始查询`Orders`。 这样做会排除从未出售过任何东西的用户。 由于问题明确要求所有用户都出现在输出中，因此实现从`Users`和用途`LEFT JOIN`。 这保证了没有销售的用户仍然出现并正确接收`"no"`。 

### 恰好进行过一次销售的用户

 仅售出一件商品的卖家没有第二次销售可供比较。 幼稚的实现可能会意外地比较第一个项目。 通过显式过滤`sale_rank = 2`，查询避免了这个错误。 缺少第二个销售产品`NULL`，落入`"no"`的分支`CASE`表达。 

### 正确的时间顺序

 如果卖家在同一天发生多次销售，那么确定第二件商品可能会变得不明确。 幸运的是，这个问题保证没有卖家每天销售超过一件商品。 这意味着排序依据`order_date`单独使用总是会产生唯一且正确的排序，用于识别第二个售出的商品。
