[LeetCode 第 1142 题](https://leetcode.com/problems/user-activity-for-the-past-30-days-ii/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 此问题要求我们计算在特定 30 天内的**每个用户的平均会话数**`2019-07-27`。 中的每一行`Activity`表表示用户在特定日期的会话中执行的活动。 单个会话可以有多个活动，并且表可能包含重复的行。 **仅当会话在 30 天窗口内至少有一项活动**时才算作平均值。 

输入表有四列：`user_id`,`session_id`,`activity_date`， 和`activity_type`。 这`activity_type`是一个 ENUM，表示打开或结束会话、滚动或发送消息等操作。 输出是一个数字，四舍五入到小数点后两位，表示 30 天内每个用户的平均不同会话数。 

需要注意的限制是每个会话只属于一个用户，并且活动可能会重复。 简单地计算行数的简单解决方案是不正确的，因为单个会话可能有多个活动和重复项，因此我们必须**计算每个用户的不同会话**。 

重要的边缘情况包括在此期间没有会话的用户、具有多个会话的用户以及不应增加计数的重复行。 

## 方法

 暴力方法是迭代每个用户，然后针对每个用户迭代其所有活动，检查活动是否在 30 天的窗口内，跟踪所有会话 ID，删除重复项，最后计算平均值。 这可行，但需要对数据集进行多次扫描，如果表很大，这可能会很昂贵。 

最佳解决方案的关键观察是我们不需要检查单个活动类型或手动处理重复项。 通过使用按日期过滤的 SQL 查询，选择不同的`user_id`和`session_id`, 分组依据`user_id`，计算每个用户的会话数，然后对这些计数进行平均**，我们可以一次性有效地计算出所需的结果。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(N^2) | O(N^2) | O(N) | 手动迭代每个用户和会话，对于大型数据集来说速度很慢 |
 | 最佳 | O(N) | O(U) | 使用 SQL DISTINCT、GROUP BY 和 AVG 计算单个查询中的结果 |

 ## 算法演练

 1. 过滤`Activity`表仅包含其中的行`activity_date`介于`2019-06-28`和`2019-07-27`包容性。 这可确保我们只考虑过去 30 天。 
2. 选择**不同的组合**`user_id`和`session_id`从同一会话中删除重复项和多个活动行。 
3. 将产生的不同会话分组`user_id`计算每个用户的会话数。 
4. 计算所有用户的**这些会话计数的平均值**。 
5. 根据要求将最终平均值四舍五入至小数点后两位。 

这是有效的，因为在过滤和重复数据删除之后，每个用户的每个会话都会被精确计数一次。 按用户聚合并取平均值，然后给出每个用户的正确平均会话数。 

## Python 解决方案```python
# This is a LeetCode database problem, so the solution is SQL-based.
# For completeness, here is how it would look in a Python DB API context:

import sqlite3

def average_sessions_per_user(conn) -> float:
    query = """
        SELECT ROUND(AVG(session_count), 2) AS average_sessions_per_user
        FROM (
            SELECT user_id, COUNT(DISTINCT session_id) AS session_count
            FROM Activity
            WHERE activity_date BETWEEN DATE('2019-07-27', '-29 DAY') AND '2019-07-27'
            GROUP BY user_id
        ) AS user_sessions;
    """
    cursor = conn.cursor()
    cursor.execute(query)
    result = cursor.fetchone()
    return result[0]
```该实现会过滤过去 30 天内的活动，对每个用户的会话进行重复数据删除，对它们进行计数，然后对计数进行平均。 内部子查询生成一个表，其中每个用户一行显示其会话计数，外部查询计算四舍五入到小数点后两位的平均值。 

## 解决方案```go
// In Go, this would typically be executed using a database/sql connection

import (
    "database/sql"
    _ "github.com/go-sql-driver/mysql"
    "fmt"
)

func AverageSessionsPerUser(db *sql.DB) (float64, error) {
    query := `
        SELECT ROUND(AVG(session_count), 2) AS average_sessions_per_user
        FROM (
            SELECT user_id, COUNT(DISTINCT session_id) AS session_count
            FROM Activity
            WHERE activity_date BETWEEN DATE_SUB('2019-07-27', INTERVAL 29 DAY) AND '2019-07-27'
            GROUP BY user_id
        ) AS user_sessions;
    `
    var avg float64
    err := db.QueryRow(query).Scan(&avg)
    if err != nil {
        return 0, err
    }
    return avg, nil
}
```在 Go 中，SQL 逻辑保持不变。 唯一的区别是 Go 特定的数据库连接处理、错误检查以及将结果扫描到变量中。 舍入由 SQL 处理。 

## 工作示例

 使用问题陈述中的示例：

 | 用户 ID | 会话 ID | 活动日期 |
 | ---| ---| ---|
 | 1 | 1 | 2019-07-20 |
 | 2 | 4 | 2019-07-20 |
 | 3 | 2 | 2019-07-21 |
 | 3 | 5 | 2019-07-21 |
 | 4 | 3 | 2019-06-25 |

 1. 过滤30天窗口内的活动：排除`user 4`。 
2. 选择不同的`user_id`和`session_id`：用户 1 → 1 个会话，用户 2 → 1 个会话，用户 3 → 2 个会话。 
3. 计算平均值：`(1 + 1 + 2)/3 = 1.33`。 

最终输出是`1.33`。

 ## 边缘情况

 一个重要的边缘情况是用户**过去 30 天内没有会话**。 该算法必须将此类用户排除在平均值之外，这是通过按日期过滤后进行分组来自然处理的。 

另一个边缘情况是同一会话的**重复活动行**。 简单的计数可能会超出会话数。 使用`COUNT(DISTINCT session_id)`确保每个用户的每个会话仅计数一次。 

第三种边缘情况是**会话跨越 30 天期限**，例如在该期限之前开始并在该期限内结束。 仅应计算该期间内至少有一项活动的会话，这是通过在重复数据删除之前按日期过滤活动来正确处理的。
