 ## 解决方案

 ## 问题理解

 问题是在一排石堆上玩的两人回合制游戏。 每堆都有正数的石子，玩家轮流从剩余堆的**开始**处取出石子。 每个回合，玩家最多可以占用`2 * M`桩，哪里`M`从 1 开始并更新为`max(M, X)`每次移动后，与`X`是该回合中取出的桩数。 每个玩家的目标是最大化他们收集的石头总数。 

输入`piles`是一个整数数组，表示每堆石子的数量。 输出是如果爱丽丝和鲍勃都发挥最佳状态，爱丽丝（第一个玩家）可以获得的最大石头数量。 约束条件（`1 <= piles.length <= 100`和`1 <= piles[i] <= 10^4`）表明我们需要一个有效的解决方案，因为对所有可能性的简单递归模拟可能会组合爆炸。 

重要的边缘情况包括具有单堆的阵列、具有两堆的阵列以及最后一堆具有非常高的石头值的情况，这可能会显着影响最优策略。 

## 方法

 暴力方法是递归地模拟 Alice 可以做出的所有可能的选择，对于每个选择递归地模拟 Bob 的最佳响应，并继续下去，直到所有桩都被取出。 这保证了正确性，因为我们探索所有可能的游戏路径，但由于每一步的指数分支，特别是最坏情况下的 O(2^(n)) 复杂度，它的速度非常慢。 这对于 100 堆的输入限制是不可行的。 

最佳解决方案的关键见解是使用具有记忆功能的动态编程。 由于游戏完全由桩数组中的当前索引和当前值决定`M`，我们可以定义一个状态`(i, M)`并存储从该状态开始的最佳移动结果。 使用**前缀和**，我们可以快速计算在一个范围内取出的石子的总和，而无需重新计算。 这减少了冗余计算并为我们提供了多项式时间解。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 递归模拟所有选择，无需记忆。 指数分支。 |
 | 最佳 | O(n^2 * n) = O(n^3) | O(n^2 * n) = O(n^3) | O(n^2) | O(n^2) | 使用具有状态（索引，M）和前缀和的记忆来有效地计算最大石头。 |

 ## 算法演练

 1. 计算后缀和数组`suffix[i]`在哪里`suffix[i]`是堆中石子的总数`i`到最后。 这使我们能够快速计算玩家拿走第一颗棋子时剩余的棋子总数`X`来自索引的桩`i`。 
2. 定义递归函数`dp(i, M)`返回当前玩家可以从堆开始收集的最大石头数`i`与电流`M`。 
3. 在`dp(i, M)`，考虑采取的所有选择`X`堆在哪里`1 <= X <= min(2*M, n-i)`。 对于每个选择，当前玩家都会获得`suffix[i] - suffix[i+X]`石头。 
4. 然后，对手将从剩余的石堆中最佳地收集石子，这些石子由`dp(i+X, max(M, X))`。 为了最大化当前玩家的增益，从剩余棋子总数中减去对手的最佳增益。 
5. 记住结果`dp(i, M)`以避免冗余计算。 返回存储的值（如果存在）。 
6. 打电话`dp(0, 1)`获得爱丽丝可以收集的最大石头。 

为什么它有效：不变的是在任何状态`(i, M)`，函数`dp(i, M)`假设双方都处于最佳状态，返回当前玩家的最佳可能结果。 记忆化确保每个状态仅计算一次，因此所有重叠的子问题都得到有效解决。 

## Python 解决方案```python
from typing import List

class Solution:
    def stoneGameII(self, piles: List[int]) -> int:
        n = len(piles)
        suffix = [0] * (n + 1)
        for i in range(n - 1, -1, -1):
            suffix[i] = piles[i] + suffix[i + 1]
        
        memo = {}
        
        def dp(i: int, M: int) -> int:
            if i >= n:
                return 0
            if (i, M) in memo:
                return memo[(i, M)]
            
            max_stones = 0
            for X in range(1, min(2 * M, n - i) + 1):
                opponent = dp(i + X, max(M, X))
                max_stones = max(max_stones, suffix[i] - opponent)
            
            memo[(i, M)] = max_stones
            return max_stones
        
        return dp(0, 1)
```此实现计算后缀和数组以快速获取剩余的石头总数。 递归`dp`函数迭代可能的移动`X`并递归地评估对手的最佳反应，并记住结果以防止重复计算。 最后的电话`dp(0, 1)`代表爱丽丝从第一堆开始`M = 1`。 

## 解决方案```go
func stoneGameII(piles []int) int {
    n := len(piles)
    suffix := make([]int, n+1)
    for i := n-1; i >= 0; i-- {
        suffix[i] = piles[i] + suffix[i+1]
    }
    
    memo := make(map[[2]int]int)
    
    var dp func(int, int) int
    dp = func(i int, M int) int {
        if i >= n {
            return 0
        }
        key := [2]int{i, M}
        if val, ok := memo[key]; ok {
            return val
        }
        
        maxStones := 0
        for X := 1; X <= 2*M && i+X <= n; X++ {
            opponent := dp(i+X, max(M, X))
            maxStones = max(maxStones, suffix[i]-opponent)
        }
        memo[key] = maxStones
        return maxStones
    }
    
    return dp(0, 1)
}

func max(a, b int) int {
    if a > b { return a }
    return b
}
```在 Go 中，我们使用`map`和`[2]int`代表的键`(i, M)`。 其他方面的逻辑与 Python 版本相同。 这`max`函数是显式实现的，因为 Go 没有内置的整数函数。

 | 时间 | O(n^3) | O(n^3) | 对于每个索引 i（n 个可能性）和 M（最多 n），我们尝试最多 2*M = O(n) 个选择，结果为 O(n^3)。 |
