[LeetCode 第 1195 题](https://leetcode.com/problems/fizz-buzz-multithreaded/)

 **难度：** 🟡 中等
 **主题：** 并发

 ## 解决方案

 ## 问题理解

 该问题要求我们协调四个独立的线程，以便它们按照以下顺序共同打印正确的 Fizz Buzz 序列：`1`到`n`。 

与经典的单线程 Fizz Buzz 问题不同，此版本引入了并发性。 每个线程只负责一类输出：

 - 的`fizz()`线印`"fizz"`对于能被`3`但不是`5`- 这`buzz()`线印`"buzz"`对于能被`5`但不是`3`- 这`fizzbuzz()`线印`"fizzbuzz"`对于可以被两者整除的数字`3`和`5`- 这`number()`线程打印普通整数

 挑战不在于确定打印什么，逻辑很简单。 真正的挑战是同步。 由于所有四个方法同时执行，我们必须保证：

 1. 每个数字来自`1`到`n`只处理一次
 2.正确的线程处理每个数字
 3. 输出以正确的顺序出现
 4. 没有发生竞争条件
 5. 线程不会死锁或永远旋转

 输入是单个整数`n`，表示序列的长度。 预期输出是标准 Fizz Buzz 序列，最多可达`n`。 

约束很小，`1 <= n <= 50`，所以性能不是主要关心的问题。 正确的同步是核心难点。 尽管输入大小很小，但简单的并发解决方案很容易产生错误的排序、重复的输出或死锁。 

一些边缘情况很重要：

 -`n = 1`，只有数字线程应该运行
 -`n = 3`，fizz 线程必须恰好激活一次
 -`n = 5`，嗡嗡声线程必须恰好激活一次
 -`n = 15`，fizzbuzz线程必须优先于fizz和buzz
 - 能被两者整除的数字`3`和`5`特别重要，因为不正确的条件排序可能会导致`"fizz"`或者`"buzz"`打印而不是`"fizzbuzz"`正确的实现必须仔细协调对共享当前号码的访问。 

## 方法

 ### 蛮力方法

 强力解决方案将连续让所有四个线程循环检查当前数字，直到其中一个线程可以执行操作。 

例如，每个线程可以重复：

 - 检查共享计数器
 - 判断当前值是否属于它
 - 打印（如果适用）
 - 增加计数器

 这在逻辑上是有效的，因为最终正确的线程将处理每个数字。 然而，它效率低且同步性差。 

最大的问题是忙着等待。 线程不断消耗 CPU 周期，同时反复检查它们是否应该运行。 即使没有轮到他们，他们也会保持活跃并进行投票。 

此外，如果没有适当的同步原语，竞争条件就可能出现：

 - 多个线程可以同时读取相同的值
 - 线程可能会错误地增加计数器
 - 输出顺序可能会中断

 锁可以部分解决这些问题，但繁忙循环仍然浪费 CPU 时间。 

### 最佳方法

 更好的解决方案使用条件变量和共享锁。 

关键的一点是，一次只能有一个线程继续运行，而其他线程则有效地休眠，直到需要它们为止。 

我们维持：

 - 共享整数`current`- 保护共享状态的互斥锁
 - 线程协调的条件变量

 每个线程：

 1. 获取锁
 2. 等待当前号码属于它
 3. 打印输出
 4. 增加共享计数器
 5.通知所有等待线程

 条件变量在这里是理想的选择，因为它们允许线程阻塞而不浪费 CPU 资源。 当当前数字发生变化时，所有线程都会唤醒并重新检查是否应该继续进行。 

这保证了正确性并避免忙等待。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n * t) | O(1) | O(1) | 线程重复轮询共享计数器|
 | 最佳 | O(n) | O(1) | O(1) | 使用条件变量进行高效同步 |

 这里，`t`表示因忙等待而导致的重复轮询迭代。 

## 算法演练

 1. 初始化一个共享计数器，名为`current`有价值`1`。 

该计数器代表序列中应处理的下一个数字。 
2. 创建互斥锁。 

多个线程会访问和修改`current`，因此必须保护所有读取和写入以避免竞争条件。 
3. 创建与锁关联的条件变量。 

条件变量允许线程休眠直到状态改变。 
4. 在`fizz()`方法，重复等待直到：

 -`current`可以整除`3`-`current`不能被整除`5`一旦条件成立：

 - 打印`"fizz"`- 增量`current`- 通知所有等待线程
 5. 在`buzz()`方法，重复等待直到：

 -`current`可以整除`5`-`current`不能被整除`3`一旦有效：

 - 打印`"buzz"`- 增量`current`- 通知所有等待线程
 6. 在`fizzbuzz()`方法，重复等待直到：

 -`current`可以被两者整除`3`和`5`然后：

 - 打印`"fizzbuzz"`- 增量`current`- 通知所有等待线程
 7. 在`number()`方法，重复等待直到：

 -`current`不能被整除`3`-`current`不能被整除`5`然后：

 - 打印号码
 - 增量`current`- 通知所有等待线程
 8.每个线程退出一次`current > n`。 

在退出之前，通知所有线程，这样就不会出现永远阻塞的线程。 

### 为什么它有效

 关键的不变量是只有一个线程有资格处理任何给定的值`current`。 

由于所有访问都发生在共享锁下，因此只有一个线程可以修改`current`一次。 处理完一个数字后，负责的线程递增`current`并唤醒所有等待线程。 然后下一个正确的线程继续。 

自从`current`每个输出只增加一次，每个数字都按顺序处理一次。 

## Python 解决方案```python
from threading import Condition
from typing import Callable

class FizzBuzz:
    def __init__(self, n: int):
        self.n = n
        self.current = 1
        self.condition = Condition()

    # printFizz() outputs "fizz"
    def fizz(self, printFizz: 'Callable[[], None]') -> None:
        while True:
            with self.condition:
                while (
                    self.current <= self.n and
                    not (
                        self.current % 3 == 0 and
                        self.current % 5 != 0
                    )
                ):
                    self.condition.wait()

                if self.current > self.n:
                    self.condition.notify_all()
                    return

                printFizz()
                self.current += 1
                self.condition.notify_all()

    # printBuzz() outputs "buzz"
    def buzz(self, printBuzz: 'Callable[[], None]') -> None:
        while True:
            with self.condition:
                while (
                    self.current <= self.n and
                    not (
                        self.current % 5 == 0 and
                        self.current % 3 != 0
                    )
                ):
                    self.condition.wait()

                if self.current > self.n:
                    self.condition.notify_all()
                    return

                printBuzz()
                self.current += 1
                self.condition.notify_all()

    # printFizzBuzz() outputs "fizzbuzz"
    def fizzbuzz(self, printFizzBuzz: 'Callable[[], None]') -> None:
        while True:
            with self.condition:
                while (
                    self.current <= self.n and
                    not (
                        self.current % 3 == 0 and
                        self.current % 5 == 0
                    )
                ):
                    self.condition.wait()

                if self.current > self.n:
                    self.condition.notify_all()
                    return

                printFizzBuzz()
                self.current += 1
                self.condition.notify_all()

    # printNumber(x) outputs "x", where x is an integer.
    def number(self, printNumber: 'Callable[[int], None]') -> None:
        while True:
            with self.condition:
                while (
                    self.current <= self.n and
                    not (
                        self.current % 3 != 0 and
                        self.current % 5 != 0
                    )
                ):
                    self.condition.wait()

                if self.current > self.n:
                    self.condition.notify_all()
                    return

                printNumber(self.current)
                self.current += 1
                self.condition.notify_all()
```实现首先初始化三个共享组件：

 -`n`，上限
 -`current`, 下一个要处理的数字
 -`condition`，它结合了锁和等待机制

 每种方法都遵循相同的结构。 

外层`while True`循环使线程保持活动状态，直到处理完所有数字。 

在条件块内，线程反复检查当前数字是否属于它。 如果没有，它会调用`wait()`，它会有效地释放锁并挂起线程。 

一旦被唤醒，线程将重新检查条件，因为另一个线程可能首先修改了共享状态。 

如果`current > n`，线程在通知所有等待线程后干净退出。 

否则，线程执行其输出操作，递增`current`，并使用唤醒每个等待线程`notify_all()`。 

使用`notify_all()`很重要，因为下一个有效线程取决于新值`current`，并且我们不知道接下来应该运行哪个线程。 

## 解决方案```go
package main

import (
	"sync"
)

type FizzBuzz struct {
	n       int
	current int
	cond    *sync.Cond
}

func Constructor(n int) *FizzBuzz {
	return &FizzBuzz{
		n:       n,
		current: 1,
		cond:    sync.NewCond(&sync.Mutex{}),
	}
}

// printFizz() outputs "fizz"
func (fb *FizzBuzz) Fizz(printFizz func()) {
	for {
		fb.cond.L.Lock()

		for fb.current <= fb.n &&
			!(fb.current%3 == 0 && fb.current%5 != 0) {
			fb.cond.Wait()
		}

		if fb.current > fb.n {
			fb.cond.Broadcast()
			fb.cond.L.Unlock()
			return
		}

		printFizz()
		fb.current++
		fb.cond.Broadcast()

		fb.cond.L.Unlock()
	}
}

// printBuzz() outputs "buzz"
func (fb *FizzBuzz) Buzz(printBuzz func()) {
	for {
		fb.cond.L.Lock()

		for fb.current <= fb.n &&
			!(fb.current%5 == 0 && fb.current%3 != 0) {
			fb.cond.Wait()
		}

		if fb.current > fb.n {
			fb.cond.Broadcast()
			fb.cond.L.Unlock()
			return
		}

		printBuzz()
		fb.current++
		fb.cond.Broadcast()

		fb.cond.L.Unlock()
	}
}

// printFizzBuzz() outputs "fizzbuzz"
func (fb *FizzBuzz) FizzBuzz(printFizzBuzz func()) {
	for {
		fb.cond.L.Lock()

		for fb.current <= fb.n &&
			!(fb.current%3 == 0 && fb.current%5 == 0) {
			fb.cond.Wait()
		}

		if fb.current > fb.n {
			fb.cond.Broadcast()
			fb.cond.L.Unlock()
			return
		}

		printFizzBuzz()
		fb.current++
		fb.cond.Broadcast()

		fb.cond.L.Unlock()
	}
}

// printNumber(x) outputs "x", where x is an integer.
func (fb *FizzBuzz) Number(printNumber func(int)) {
	for {
		fb.cond.L.Lock()

		for fb.current <= fb.n &&
			!(fb.current%3 != 0 && fb.current%5 != 0) {
			fb.cond.Wait()
		}

		if fb.current > fb.n {
			fb.cond.Broadcast()
			fb.cond.L.Unlock()
			return
		}

		printNumber(fb.current)
		fb.current++
		fb.cond.Broadcast()

		fb.cond.L.Unlock()
	}
}
```Go 解决方案与 Python 版本非常相似，但使用了 Go 的`sync.Cond`类型以进行同步。 

一个重要的区别是显式的锁管理。 在 Go 中，我们手动调用：```go
fb.cond.L.Lock()
fb.cond.L.Unlock()
```而 Python 使用以下命令自动处理锁获取`with`陈述。 

Go 还使用`Broadcast()`而不是`notify_all()`。 

由于约束非常小，因此在任一实现中都不需要考虑整数溢出。

 ## 边缘情况

 ### 可被 3 和 5 整除的数字

 这是最重要的正确性边缘情况。 一个幼稚的实现可以通过以下方式检查整除性`3`在检查两者的整除性之前`3`和`5`。 这会错误地打印`"fizz"`而不是`"fizzbuzz"`对于像这样的值`15`和`30`。 

该实现通过给出来避免这种情况`fizzbuzz()`线程自身的独占条件：```
current % 3 == 0 and current % 5 == 0
```没有其他线程接受这些值。 

### n 的小值

 当`n`非常小，有些线程可能根本不会执行它们的打印函数。 

例如：

-`n = 1`，仅打印编号线程
 -`n = 2`、嘶嘶声、嗡嗡声和嘶嘶声永远不会激活

 不正确的实现可能会使不活动的线程永远阻塞。 该解决方案通过在每次返回之前广播通知来正确处理终止。 

### 线程唤醒顺序

 条件变量可以按任意顺序唤醒线程。 首先唤醒的线程不一定是当前编号的正确线程。 

此实现通过始终重新检查 a 内的条件来安全地处理该情况`while`环形：```
while condition_not_met:
    wait()
```此模式可防止由于虚假唤醒或调度竞争而导致的错误执行。
