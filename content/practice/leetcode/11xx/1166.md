[LeetCode 第 1166 题](https://leetcode.com/problems/design-file-system/)

 **难度：** 🟡 中等
 **主题：** 哈希表、字符串、设计、Trie

 ## 解决方案

 ## 问题理解

 这个问题要求我们设计一个简化的文件系统，支持两种操作：

 1. 创建具有关联整数值的新路径。 
2. 检索存储在路径中的值。 

路径的行为类似于真实操作系统中的目录结构。 每条路径都由用 分隔的组件组成`/`。 

例如：

-`/leet`-`/leet/code`是有效路径。 

关键规则是只有当其父路径已经存在时才能创建路径。 

例如：

 - 创造`/leet`有效，因为它是顶级路径。 
- 创造`/leet/code`仅当以下情况下才有效`/leet`已经存在。 
- 创造`/c/d`失败如果`/c`不存在。 

这`createPath(path, value)`操作应：

 - 返回`true`如果路径创建成功。 
- 返回`false`如果：

 - 路径已经存在，或者
 - 父路径不存在。 

这`get(path)`操作应：

 - 返回与路径关联的值（如果存在）。 
- 返回`-1`如果路径不存在。 

限制相对较小：

 - 路径长度最多为 100。 
- 至多`10^4`执行操作。 

这些限制意味着我们不需要极其高级的优化，但我们仍然需要高效的查找和插入。 由于操作基本上基于精确的路径匹配，因此哈希映射是自然的选择。 

一些边缘情况很重要：

 - 尝试创建一条已经存在的路径。 
- 尝试在其父路径存在之前创建嵌套路径。 
- 正确处理顶级路径。 
- 回归`-1`对于不存在的路径。 
- 确保`/`本身不被视为有效路径。 

该问题保证所有提供的路径在语法上都是有效的，因此我们不需要执行路径格式验证。 

## 方法

 ### 蛮力方法

 暴力解决方案可以将所有创建的路径存储在列表中`(path, value)`对。 每次我们打电话`createPath`，我们会：

 1. 扫描整个列表，检查该路径是否已存在。 
2. 计算父路径。 
3. 再次扫描列表以确定父项是否存在。 

相似地，`get(path)`将线性扫描列表以找到匹配的路径。 

这种方法是正确的，因为每个操作都会明确检查所需的条件。 然而，它的效率很低，因为每次查找都需要线性扫描。 

如果有`n`存储的路径，每个操作变成`O(n)`。 

由于最多可以有`10^4`操作时，重复的线性扫描是不必要的且效率低下。 

### 最佳方法

 关键的观察是每个操作都需要快速的精确路径查找。 

这使得哈希图成为理想的选择。 

我们可以存储：```
path -> value
```在字典或哈希映射中。 

然后：

 - 检查路径是否存在变为`O(1)`平均时间。 
- 检索一个值变成`O(1)`平均时间。 
- 验证父级是否存在也变为`O(1)`平均时间。 

唯一的额外工作是从字符串中提取父路径。 

例如：```
/leet/code
```有父级：```
/leet
```我们可以使用字符串操作找到它。 

这为我们提供了一个高效且干净的解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 每次操作 O(n) | O(n) | 每次查找都使用线性扫描 |
 | 最佳| 每次操作平均 O(1) | O(n) | 使用哈希映射进行直接路径查找 |

 ## 算法演练

 ### 最优算法

 1. 初始化一个名为的哈希图`paths`。 

该映射存储每个有效路径及其关联值。 

例子：```
{
    "/leet": 1,
    "/leet/code": 2
}
```2. 什么时候`createPath(path, value)`调用时，首先检查路径是否已经存在。 

如果是，则返回`false`因为不允许重复创建。 
3. 计算父路径。 

例如：```
path = "/leet/code"
parent = "/leet"
```我们可以通过定位最后一个来找到父级`/`。 
4. 如果父项不为空，请验证它是否存在于哈希图中。 

这确保了层次结构的正确性。 

示例：

 -`/leet/code`需要`/leet`-`/a/b/c`需要`/a/b`5. 如果父级不存在，则返回`false`。 
6. 否则，将新路径及其值插入到哈希映射中。 
7. 返回`true`表示创建成功。 
8.为了`get(path)`，只需返回：

 - 如果路径存在则存储的值
 -`-1`否则

 ### 为什么它有效

 该算法保持每个存储路径都有一个有效的父链的不变量。 

仅在以下情况下插入路径：

 - 它尚不存在，并且
 - 它的父级已经存在。 

由于每次插入都会保留此属性，因此文件系统结构始终保持有效。 哈希图保证了高效的检索和存在性检查。 

## Python 解决方案```python
class FileSystem:

    def __init__(self):
        self.paths = {}

    def createPath(self, path: str, value: int) -> bool:
        # Path already exists
        if path in self.paths:
            return False

        # Find parent path
        last_slash_index = path.rfind("/")
        parent = path[:last_slash_index]

        # Parent must exist unless this is a top-level path
        if parent and parent not in self.paths:
            return False

        self.paths[path] = value
        return True

    def get(self, path: str) -> int:
        return self.paths.get(path, -1)

# Your FileSystem object will be instantiated and called as such:
# obj = FileSystem()
# param_1 = obj.createPath(path, value)
# param_2 = obj.get(path)
```该实现使用一个名为的字典`paths`存储每个创建的路径及其值。 

里面`createPath`，第一个检查可以防止重复创建。 如果路径已经存在，我们立即返回`False`。 

接下来，代码使用计算父路径`rfind("/")`，它找到字符串中的最后一个斜杠。 该斜杠之前的所有内容都成为父级。 

例如：```python
"/leet/code"
```变成：```python
parent = "/leet"
```如果父字符串非空，我们验证它是否已经存在于字典中。 如果不存在，创建就会失败。 

否则，路径将被插入到字典中并且该方法返回`True`。 

这`get`方法使用Python的字典`.get()`方法返回存储的值或`-1`如果路径不存在。 

## 解决方案```go
package main

import "strings"

type FileSystem struct {
	paths map[string]int
}

func Constructor() FileSystem {
	return FileSystem{
		paths: make(map[string]int),
	}
}

func (this *FileSystem) CreatePath(path string, value int) bool {
	// Path already exists
	if _, exists := this.paths[path]; exists {
		return false
	}

	// Find parent path
	lastSlashIndex := strings.LastIndex(path, "/")
	parent := path[:lastSlashIndex]

	// Parent must exist unless top-level path
	if parent != "" {
		if _, exists := this.paths[parent]; !exists {
			return false
		}
	}

	this.paths[path] = value
	return true
}

func (this *FileSystem) Get(path string) int {
	if value, exists := this.paths[path]; exists {
		return value
	}

	return -1
}

/**
 * Your FileSystem object will be instantiated and called as such:
 * obj := Constructor()
 * param_1 := obj.CreatePath(path, value)
 * param_2 := obj.Get(path)
 */
```Go 实现遵循与 Python 版本相同的逻辑，但使用`map[string]int`用于存储。 

Go 在访问映射时需要显式的存在检查。 因此，代码使用：```go
value, exists := map[key]
```区分丢失的条目和存储的零值。 

这`strings.LastIndex`函数用于在计算父路径时查找最后的斜杠。

 ## 边缘情况

 ### 创建已经存在的路径

 一个常见的错误是意外覆盖现有路径的值。 

例如：```
createPath("/a", 1)
createPath("/a", 2)
```第二次调用一定会失败。 

实现立即处理这个问题：```
if path in self.paths:
    return False
```这保留了路径不能重新创建的规则。 

### 创建没有父级的嵌套路径

 当尝试在其父路径存在之前创建深度嵌套路径时，会出现另一个重要的边缘情况。 

例子：```
createPath("/a/b", 1)
```什么时候`/a`不存在。 

幼稚的实现可能会错误地允许这种插入。 

该解决方案显式提取父路径并在插入之前检查其是否存在。 

### 检索不存在的路径

 的`get`方法必须返回`-1`对于丢失的路径。 

例如：```
get("/missing")
```不应引发异常或返回任意默认值。 

该实现使用字典查找默认值安全地处理这个问题：```
return self.paths.get(path, -1)
```这保证了所有不存在的路径的正确行为。 

### 正确处理顶级路径

 顶级路径例如：```
/a
```没有父母。 

有缺陷的实现可能错误地需要空字符串`""`作为父母而存在。 

该解决方案通过检查来避免此问题：```
if parent and parent not in self.paths:
```如果`parent`为空，则跳过存在检查，允许创建有效的顶级路径。
