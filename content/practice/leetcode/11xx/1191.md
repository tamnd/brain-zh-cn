 # LeetCode 1186 - 一次删除的最大子数组和

 ## 问题理解

 该问题要求我们在允许从所选子数组中删除最多一个元素时找到连续子数组的最大可能总和。 

重要的细节是，删除后生成的子数组必须仍包含至少一个元素。 这意味着我们不能删除每个元素并返回`0`除非数组本身包含一个有效的非空子数组，其总和`0`。 

输入是一个整数数组`arr`，其中可能包含正数、负数或零。 在选择性地删除一个元素后，我们需要返回可实现的最大子数组总和。 

使用 Kadane 算法解决的标准最大子数组问题仅考虑不删除的连续段。 这个问题通过允许一次删除扩展了这个想法，这显着改变了状态转换。 

约束条件很重要：

 - 数组长度可以大到`10^5`- 每个元素的范围可以是`-10^4`到`10^4`这些限制立即排除了昂贵的方法，例如显式检查每个子数组。 任何比粗略更糟糕的解决方案`O(n)`或者`O(n log n)`可能太慢了。 

一些边缘情况尤其重要：

 - 包含所有负数的数组
 - 删除无益的数组
 - 删除大负数可产生最佳结果的数组
 - 单元素数组
 - 包含零的数组

 例如，如果输入是`[-1, -1, -1]`，答案是`-1`， 不是`0`，因为删除唯一选定的元素会留下一个空的子数组，这是不允许的。 

## 方法

 ### 蛮力方法

 强力解决方案将检查每个可能的子数组。 对于每个子数组，我们可以：

 - 保留所有元素
 - 从该子数组中删除一个元素

 然后我们将计算结果总和并跟踪最大值。 

假设数组有长度`n`。 有`O(n^2)`子数组。 对于每个子数组，尝试每一个可能的删除都会花费另一个`O(n)`。 计算总和会天真地增加额外的开销。 

这产生了接近的整体复杂性`O(n^3)`， 或者`O(n^2)`具有前缀和优化。 甚至`O(n^2)`太慢了`n = 10^5`。 

蛮力方法是正确的，因为它明确地检查每一个有效的可能性，但它在计算上是不切实际的。 

### 最优动态规划方法

 关键的见解是，对于每个索引，我们只需要知道两件事：

 - 以当前索引结束且没有任何删除的最大子数组总和
 - 以当前索引结束且已使用一次删除的最大子数组总和

 这创建了一个自然的动态规划公式。 

让：

-`no_delete`表示以当前位置结束且没有删除的最佳子数组
 -`one_delete`表示一次删除后以当前位置结束的最佳子数组

 对于每个新元素：

 - 我们要么扩展前一个子数组
 - 或者开始一个新的子数组
 - 或者删除当前元素

 这使我们能够一次性处理数组。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n2) 到 O(n3) | O(1) | O(1) | 检查所有子数组和删除 |
 | 最优动态规划| O(n) | O(1) | O(1) | 跟踪删除和不删除的最佳状态 |

 ## 算法演练

 1. 初始化两个动态编程状态。`no_delete`存储以当前索引结尾的最大子数组总和，而不删除任何内容。`one_delete`存储以当前索引结尾的最大子数组总和，其中已使用了一次删除。 
2. 使用第一个元素启动两个状态。 

最初：

-`no_delete = arr[0]`-`one_delete = 0`我们还初始化全局答案`arr[0]`。 
3. 从索引开始迭代数组`1`。 

对于每个元素`arr[i]`，我们计算更新的状态。 
4. 更新`one_delete`状态。 

有两种可能：

 - 删除当前元素，即取前一个元素`no_delete`- 保留当前元素并扩展先前已删除状态的子数组

 因此：```
one_delete = max(no_delete_previous, one_delete_previous + arr[i])
```5. 更新`no_delete`状态。 

这与 Kadane 的算法相同。 

要么：

 - 在当前元素处开始一个新的子数组
 - 扩展前一个子数组

 所以：```
no_delete = max(arr[i], no_delete_previous + arr[i])
```6.更新全局答案。 

在每一步中，最佳答案可能来自任一州。 
7. 继续，直到阵列完全处理完毕。 

### 为什么它有效

 该算法之所以有效，是因为每个有效子数组都以索引结尾`i`恰好属于以下两类之一：

 - 未使用删除功能
 - 已使用一次删除

 递归关系耗尽了这些状态之间的所有有效转换。 由于每个状态始终存储其类别的最优值，因此最终答案保证是最优的。 

## Python 解决方案```python
from typing import List

class Solution:
    def maximumSum(self, arr: List[int]) -> int:
        no_delete = arr[0]
        one_delete = 0
        best_sum = arr[0]

        for i in range(1, len(arr)):
            current = arr[i]

            new_one_delete = max(no_delete, one_delete + current)
            new_no_delete = max(current, no_delete + current)

            one_delete = new_one_delete
            no_delete = new_no_delete

            best_sum = max(best_sum, no_delete, one_delete)

        return best_sum
```实现直接遵循动态规划公式。 

变量`no_delete`表示以当前索引结尾且未删除的最佳子数组。 这是标准的 Kadane 逻辑。 

变量`one_delete`表示在删除之前或当前位置处的一个元素后，以当前索引结尾的最佳子数组。 

在循环内部，我们首先计算新的删除状态值，因为它取决于先前迭代的值。 然后我们更新未删除的状态。 

每次迭代后都会更新全局最大值，因为最佳子数组可能在数组中的任何位置结束。 

该解决方案使用恒定的额外空间，因为只需要先前的状态值。 

## 解决方案```go
func maximumSum(arr []int) int {
    noDelete := arr[0]
    oneDelete := 0
    bestSum := arr[0]

    for i := 1; i < len(arr); i++ {
        current := arr[i]

        newOneDelete := max(noDelete, oneDelete+current)
        newNoDelete := max(current, noDelete+current)

        oneDelete = newOneDelete
        noDelete = newNoDelete

        bestSum = max(bestSum, max(noDelete, oneDelete))
    }

    return bestSum
}

func max(a, b int) int {
    if a > b {
        return a
    }
    return b
}
```Go 的实现与 Python 版本非常相似。 

Go 没有提供内置的`max`整数函数，因此我们手动定义一个。 

由于这些约束很适合 Go 的范围`int`范围，溢出在这里不是问题。 

该算法仅使用几个整数变量，因此内存使用量保持不变。

 ## 边缘情况

 一种重要的边缘情况是仅包含负数的数组。 幼稚的实现可能会错误地返回`0`通过删除所有元素。 但是，该问题明确要求生成的子数组保持非空。 该实现通过初始化答案来避免此错误`arr[0]`而不是`0`。 

另一个重要的情况是单元素数组。 由于没有有效的方法可以删除唯一元素同时保持子数组非空，因此答案必须只是该元素本身。 该算法自然会处理这个问题，因为循环永远不会执行并且返回初始值。 

当删除无益时，就会出现第三种边缘情况。 例如，在`[1, 2, 3]`，删除任何元素都会减少总和。 该算法正确地保持正常的Kadane状态并允许最优答案来自非删除路径。 

# LeetCode 1191 - K-串联最大和

 ## 问题理解

 这个问题要求我们计算重复数组后的最大子数组和`k`次。 

如果：```
arr = [1, 2]
k = 3
```那么结果数组就变成：```
[1, 2, 1, 2, 1, 2]
```我们必须在这个重复数组中找到最大可能的连续子数组和。 

与上一个问题不同，这个问题允许子数组为空。 这意味着最小可能的答案是`0`。 

答案可能会变得非常大，因此我们必须将其模数返回：```
10^9 + 7
```限制条件很大：

 -`arr.length`最多`10^5`-`k`最多`10^5`显式构造重复数组的成本太高，因为它的大小可能达到`10^10`。 

挑战在于以数学方式推理重复的结构，而不是物理地构建阵列。 

重要的边缘情况包括：

 - 全部为负值的数组
 - 非常大`k`- 总和为正数的数组
 - 总和为零或负数的数组
 - 最优子数组跨越多个副本的情况

 ## 方法

 ### 蛮力方法

 暴力方法将显式构建长度的串联数组`n * k`，然后对其运行 Kadane 算法。 

这是可行的，因为 Kadane 的算法正确地计算了最大子数组和。 

然而，这种方法对于大型企业来说是不可能的`k`。 如果两者都`n`和`k`是`10^5`，构造的数组将包含`10^10`元素。 

内存和运行时间成本是完全不可行的。 

### 最优动态规划和前缀后缀洞察

 关键的观察是，除非总数组和为正，否则最佳子数组最多可以以有意义的方式跨越两个副本。 

主要有两种情况：

 - 如果数组总和为非正数，除了考虑两个串联之外，添加更多副本没有任何帮助。 
- 如果数组总和为正，则中间副本完全有助于最佳答案。 

因此，最佳结果可以表示为：```
max_prefix_sum + max_suffix_sum + (k - 2) * total_sum
```什么时候`total_sum > 0`。 

我们只需要对最多两个串联副本使用 Kadane 算法。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n × k) | O(n × k) | O(n × k) | O(n × k) | 显式构造重复数组 |
 | 最佳| O(n) | O(1) | O(1) | 使用 Kadane 加上前缀/后缀推理 |

 ## 算法演练

 1. 计算数组的总和。 

这决定了添加额外副本是否有益。 
2. 在数组的两个串联副本上运行 Kadane 算法。 

我们最多只需要两个副本，因为任何跨边界子数组都必须以一个副本开始并以另一个副本结束。 
3.如果`k == 1`，从一份副本中返回 Kadane 结果。 

不存在额外的串联。 
4. 如果数组总和为正，则额外的中间副本会增加结果。 

在这种情况下：```
answer = max_two_copy_sum + (k - 2) * total_sum
```5. 如果总和为非正数，则再多副本也无济于事。 

答案很简单，就是两个副本内的最大子数组之和。 
6. 由于允许空子数组，因此确保结果至少为`0`。 
7. 返回模数结果`10^9 + 7`。 

### 为什么它有效

 重复结构中的任何最大子数组：

 - 完全位于一份副本内
 - 跨越副本之间的一个边界
 - 或跨越多个副本

 如果总和为正，则包括完整的中间副本总是会增加总数。 否则，添加更多副本只会减少或保留总和。 

这完全表征了最佳解决方案。 

## Python 解决方案```python
from typing import List

class Solution:
    def kConcatenationMaxSum(self, arr: List[int], k: int) -> int:
        MOD = 10**9 + 7

        def kadane(nums: List[int]) -> int:
            current = 0
            best = 0

            for value in nums:
                current = max(0, current + value)
                best = max(best, current)

            return best

        total_sum = sum(arr)

        if k == 1:
            return kadane(arr) % MOD

        double_array = arr * 2
        best_two = kadane(double_array)

        if total_sum > 0:
            result = best_two + (k - 2) * total_sum
        else:
            result = best_two

        return result % MOD
```实现首先将 Kadane 的算法修改为允许空子数组。 这就是为什么运行总和永远不会低于`0`。 

我们计算数组总和，因为它决定了额外的副本是否有积极贡献。 

为了`k > 1`，我们在数组的两个副本上运行 Kadane。 这捕获了每个可能的交叉子阵列配置。 

如果总和为正，则每个完全包含的中间副本都会增加结果，因此我们添加`(k - 2) * total_sum`。 

最后，我们在返回之前应用模运算。 

## 解决方案```go
func kConcatenationMaxSum(arr []int, k int) int {
    const MOD int = 1000000007

    kadane := func(nums []int) int {
        current := 0
        best := 0

        for _, value := range nums {
            current = max(0, current+value)
            best = max(best, current)
        }

        return best
    }

    totalSum := 0
    for _, value := range arr {
        totalSum += value
    }

    if k == 1 {
        return kadane(arr) % MOD
    }

    doubleArray := append(arr, arr...)
    bestTwo := kadane(doubleArray)

    result := bestTwo

    if totalSum > 0 {
        result += (k - 2) * totalSum
    }

    return result % MOD
}

func max(a, b int) int {
    if a > b {
        return a
    }
    return b
}
```Go 实现遵循与 Python 版本相同的逻辑。 

切片自然地用于连接`append(arr, arr...)`。 

使用 Go 标准时，在给定的约束下，整数溢出不是问题`int`在现代系统上键入。 

模运算仅在最后应用，因为中间值保持安全界限。

 ## 边缘情况

 一种重要的边缘情况是仅包含负数的数组。 由于允许空子数组，因此正确答案变为`0`。 强制使用非空子数组的标准 Kadane 实现将错误地返回负值。 该实现通过在运行总和变为负数时将其重置为零来避免这种情况。 

当数组总和为正时，会出现另一个重要情况。 在这种情况下，额外的副本会有意义地增加答案，因为每个完整的重复块都会做出积极的贡献。 实现显式地处理这个问题`(k - 2) * total_sum`学期。 

第三个边缘情况是非常大的值`k`。 直接构造重复数组会导致内存耗尽和运行时间不可接受。 该实现通过仅考虑最多两个副本并对剩余的重复使用数学推理来完全避免这种情况。
