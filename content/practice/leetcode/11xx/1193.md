[LeetCode 第 1193 题](https://leetcode.com/problems/monthly-transactions-i/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 问题是要求我们生成按月份和国家分组的交易汇总统计数据`Transactions`桌子。 表中的每一行代表一个事务并包含以下列：`id`（主键），`country`（细绳），`state`（枚举`approved`或者`declined`),`amount`（整数），以及`trans_date`（日期）。 

对于月份和国家/地区的每个组合，我们需要计算六个值：月份本身、国家/地区、交易总数（`trans_count`），批准的交易数量（`approved_count`），所有交易的总金额（`trans_total_amount`），以及仅已批准交易的总金额（`approved_total_amount`）。 月份源自`trans_date`在`YYYY-MM`格式。 

约束相对简单：该表每个月和每个国家可能有多行，`state`列严格限于“已批准”或“已拒绝”，并且`amount`是一个整数。 重要的是，该问题允许以任意顺序返回结果，因此我们无需担心排序问题。 需要考虑的边缘情况包括没有批准交易的月份、一个月内只有一笔交易的国家以及仅交易被拒绝的月份。 

## 方法

 暴力方法需要以程序方式手动迭代所有交易，累积每个月和每个国家/地区的计数和总和。 虽然这会产生正确的结果，但它在 SQL 中不可扩展或不符合习惯。 SQL 提供了聚合函数和分组运算符，对于此任务来说更加高效且更具表现力。 

最佳方法利用 SQL`GROUP BY`子句根据派生月份聚合行（`DATE_FORMAT(trans_date, '%Y-%m')`）和国家。 标准聚合函数`COUNT`和`SUM`用于计算交易总数和总金额。 条件聚合`CASE`用于计算批准的交易及其金额。 此方法非常高效，因为它仅扫描表一次并在一次传递中计算所有所需的聚合。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n*m) | O(n*m) | 手动迭代所有交易并以程序方式累积价值。 |
 | 最佳 | O(n) | O(k) | 使用SQL`GROUP BY`和聚合函数来计算单个查询中的结果，其中`k`是不同月份-国家组合的数量。 |

 ## 算法演练

 1. 从中提取月份`trans_date`列于`YYYY-MM`格式。 这可以通过使用来实现`DATE_FORMAT`MySQL 中的函数或`TO_CHAR`在 PostgreSQL 中。 
2. 按派生月份和日期对交易进行分组`country`列使用`GROUP BY`。 
3. 对于每个组，统计所有交易，得到`trans_count`。 
4. 使用条件聚合仅对满足条件的交易进行计数`state = 'approved'`要得到`approved_count`。 
5. 求和`amount`获取所有交易的列`trans_total_amount`。 
6. 使用条件聚合`SUM(CASE WHEN state = 'approved' THEN amount ELSE 0 END)`计算`approved_total_amount`。 
7. 选择所有聚合列并返回结果。 

为什么它有效：`GROUP BY`条款确保特定月份和国家/地区的所有交易都汇总在一起。 条件聚合确保只有批准的交易才有助于批准的计数和总和。 这种方法保证了正确性，同时最大限度地减少了表扫描。 

## Python 解决方案

 虽然这是一个 SQL 问题，但我们可以演示如何使用带有数据库连接的 Python 执行查询：```python
import sqlite3

query = """
SELECT
    strftime('%Y-%m', trans_date) AS month,
    country,
    COUNT(*) AS trans_count,
    SUM(CASE WHEN state = 'approved' THEN 1 ELSE 0 END) AS approved_count,
    SUM(amount) AS trans_total_amount,
    SUM(CASE WHEN state = 'approved' THEN amount ELSE 0 END) AS approved_total_amount
FROM Transactions
GROUP BY month, country
"""

# Example Python usage
conn = sqlite3.connect('transactions.db')
cursor = conn.cursor()
cursor.execute(query)
results = cursor.fetchall()
for row in results:
    print(row)
```此代码连接到 SQLite 数据库、执行 SQL 查询并获取所有聚合结果。 条件聚合是使用以下实现的`CASE WHEN`声明。 

## 解决方案```go
package main

import (
    "database/sql"
    _ "github.com/go-sql-driver/mysql"
    "fmt"
)

func main() {
    db, err := sql.Open("mysql", "user:password@tcp(127.0.0.1:3306)/dbname")
    if err != nil {
        panic(err)
    }
    defer db.Close()

    query := `
    SELECT
        DATE_FORMAT(trans_date, '%Y-%m') AS month,
        country,
        COUNT(*) AS trans_count,
        SUM(CASE WHEN state = 'approved' THEN 1 ELSE 0 END) AS approved_count,
        SUM(amount) AS trans_total_amount,
        SUM(CASE WHEN state = 'approved' THEN amount ELSE 0 END) AS approved_total_amount
    FROM Transactions
    GROUP BY month, country
    `

    rows, err := db.Query(query)
    if err != nil {
        panic(err)
    }
    defer rows.Close()

    for rows.Next() {
        var month, country string
        var transCount, approvedCount, transTotal, approvedTotal int
        err := rows.Scan(&month, &country, &transCount, &approvedCount, &transTotal, &approvedTotal)
        if err != nil {
            panic(err)
        }
        fmt.Println(month, country, transCount, approvedCount, transTotal, approvedTotal)
    }
}
```Go 实现在连接数据库和扫描结果的语法上略有不同。 条件聚合的工作方式与 Python/SQL 中的相同。

 ## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|

 ## 边缘情况

 首先，考虑所有交易都被拒绝的月份。 已批准交易的天真金额可能会错误地包含被拒绝的金额； 使用条件聚合可确保只有批准的交易才会做出贡献。 

其次，具有单笔交易的月份仍应出现在结果集中。 聚合逻辑确保即使一组中只有一行，也能正确计数。 

第三，如果我们只按月分组，同一月份的多个国家可能会错误地汇总在一起。 按月份和国家/地区分组可确保每个国家/地区每月获得自己的聚合行，从而保持数据准确性。
