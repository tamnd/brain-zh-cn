[LeetCode 问题 1167](https://leetcode.com/problems/minimum-cost-to-connect-sticks/)

 **难度：** 🟡 中等
 **主题：** 数组、贪婪、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 该问题给了我们一个正整数数组，称为`sticks`，其中每个值代表一根棍子的长度。 我们可以反复将任意两根木棍连接在一起。 如果我们将木棍与长度连接起来`x`和`y`, 运行成本`x + y`，所得的棒的长度`x + y`。 

目标是继续组合棍子，直到只剩下一根棍子，同时最大限度地减少所有操作所支付的总成本。 

这很重要，因为每根新创建的棍子都可以在未来的组合中再次使用。 这意味着大的中间棒可能会导致总成本成倍增加。 正因为如此，我们组合木棍的顺序直接影响到最终的答案。 

例如，假设我们有棍子`[1, 2, 100]`。 

如果我们结合`1 + 2 = 3`第一：

 - 到目前为止的成本 =`3`- 剩余的木棍 =`[3, 100]`- 最终合并成本=`103`- 总计 =`106`如果我们结合`100 + 2 = 102`第一：

 - 到目前为止的成本 =`102`- 剩余的木棍 =`[102, 1]`- 最终合并成本=`103`- 总计 =`205`第一次订购要便宜得多。 

限制条件是：

 -`1 <= sticks.length <= 10^4`-`1 <= sticks[i] <= 10^4`该数组最多可以包含一万个元素，因此每次操作后重复对整个数组进行排序会变得低效。 我们需要一种解决方案，能够在每一步中有效地检索最小的可用木棍。 

一些边缘情况很重要：

 - 单根棍子，例如`[5]`，应该返回`0`因为不需要合并。 
- 许多相同的值，例如`[1,1,1,1]`，应该仍然可以正常工作。 
- 非常不平衡的输入，例如`[1,1,1,10000]`，可以暴露低效或不正确的贪婪选择。 
- 大型数组需要比重复完全排序更好的算法。 

## 方法

 ### 蛮力方法

 蛮力策略将尝试所有可能的方法来组合棍子并计算每个可能的合并顺序的总成本。 由于每个步骤都允许多种选择，因此可能的合并序列的数量增长得非常快。 

例如，与`n`棍子：

 - 第一步，我们选择 2 根棍子`n`- 在下一步中，我们选择 2 根棍子`n - 1`- 这种分支一直持续到只剩下一根棍子

 This produces a combinatorial explosion. 即使对于相对较小的输入，可能的合并顺序的数量也会变得巨大。 

尽管这种方法保证了最佳答案，因为它检查了每种可能性，但对于以下情况来说这是完全不切实际的：`n = 10^4`。 

Another slightly better brute force method would repeatedly:

 1. 对数组进行排序
 2. 取两根最小的木棍
 3.合并它们
 4. 将合并后的棒插回阵列中
 5.再次排序

 This works correctly because it follows the optimal greedy strategy, but repeatedly sorting is inefficient.

 ### 关键见解

 The crucial observation is that we should always combine the two smallest sticks first.

 为什么？ 

每个合并的棍子都可以参与未来的合并。 If we create a large stick too early, that large value gets added repeatedly in later operations, increasing the total cost significantly.

 This problem is structurally identical to the classic Huffman coding greedy strategy. Combining the two smallest values minimizes the future contribution of large sums.

 To efficiently retrieve the two smallest sticks repeatedly, we use a min heap, also called a priority queue.

 最小堆允许：

 - 删除最小的元素`O(log n)`- 插入一个新元素`O(log n)`- 最初构建堆`O(n)`这使得整个算法对于问题约束足够高效。

 | 最佳堆解决方案 | O(n log n) | O(n log n) | O(n) | 使用最小堆始终访问最小的棒 |

 ## 算法演练

 1. 处理数组仅包含一根棍子的边缘情况。 

如果只有一根棍子，则不需要合并，所以答案是`0`。 
2. 将输入数组转换为最小堆。 

A min heap always keeps the smallest element at the top. This allows us to efficiently retrieve the two smallest sticks at every step.
 3. 初始化一个名为`total_cost`到`0`。 

该变量累积所有操作的总合并成本。 
4. 当堆中包含多于一根木棍时重复此操作。 

只要还有多根棍子，我们仍然需要额外的合并。 
5. 从一堆木棍中取出两根最小的木棍。 

这些是接下来要合并的最佳棍棒，因为选择最小的一对可以最大限度地减少未来的成本。 
6. 计算它们的合并成本。 

如果两根棍子是`a`和`b`， 然后：`merged = a + b`7. 将合并成本添加到`total_cost`。 

每个合并操作都直接影响最终的答案。 
8. 将合并的棒推回到堆中。 

新形成的棒可能会参与未来的合并，因此它必须保持可用。 
9. 继续，直到只剩下一根棍子。 

至此，所有的棍子都已连接成一根棍子了。 
10. 返回`total_cost`。 

### 为什么它有效

 贪婪策略之所以有效，是因为每个合并的棍子都可以在未来的操作中重复使用。 因此，较小的棍棒对未来成本的影响应尽可能小。 

通过始终首先组合两根最小的木棍，我们可以最大限度地减少中间木棍长度的增长。 任何提前合并更大棒的替代策略都会增加未来的合并成本。 

此属性与霍夫曼编码中使用的推理相同，其中重复组合最小权重会产生最小总加权路径长度。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def connectSticks(self, sticks: List[int]) -> int:
        if len(sticks) <= 1:
            return 0

        heapq.heapify(sticks)

        total_cost = 0

        while len(sticks) > 1:
            first = heapq.heappop(sticks)
            second = heapq.heappop(sticks)

            merged = first + second
            total_cost += merged

            heapq.heappush(sticks, merged)

        return total_cost
```实现从处理最简单的边缘情况开始。 如果只有一根棍子，函数立即返回`0`。 

下一个，`heapq.heapify(sticks)`在线性时间内将列表转换为有效的最小堆。 这比逐个插入元素更有效。 

变量`total_cost`跟踪累积合并成本。 

在循环内部，该算法使用以下方法重复删除两个最小的木棍`heapq.heappop`。 它们的总和变为：

 - 当前操作的成本
 - 新形成的棒的长度

 使用以下命令将合并的棒插入回堆中`heapq.heappush`，允许它参与未来的合并。 

循环继续，直到只剩下一根棍子，这意味着所有棍子都已连接。 

## 解决方案```go
package main

import (
	"container/heap"
)

type MinHeap []int

func (h MinHeap) Len() int {
	return len(h)
}

func (h MinHeap) Less(i, j int) bool {
	return h[i] < h[j]
}

func (h MinHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MinHeap) Push(x interface{}) {
	*h = append(*h, x.(int))
}

func (h *MinHeap) Pop() interface{} {
	old := *h
	n := len(old)

	value := old[n-1]
	*h = old[:n-1]

	return value
}

func connectSticks(sticks []int) int {
	if len(sticks) <= 1 {
		return 0
	}

	h := MinHeap(sticks)
	heap.Init(&h)

	totalCost := 0

	for h.Len() > 1 {
		first := heap.Pop(&h).(int)
		second := heap.Pop(&h).(int)

		merged := first + second
		totalCost += merged

		heap.Push(&h, merged)
	}

	return totalCost
}
```Go 实现使用`container/heap`包，它需要定义一个自定义堆类型来实现`heap.Interface`。 

与 Python 不同，Go 不直接为整数提供内置的最小堆，因此我们定义：

 -`Len`-`Less`-`Swap`-`Push`-`Pop`该算法的逻辑与 Python 版本保持相同。 

Go 切片是动态的，因此堆操作会就地修改底层切片。 整数溢出在这里不是一个问题，因为约束将总数保持在 Go 的整数范围内。

 ## 边缘情况

 ### 单棍

 输入如`[5]`很重要，因为不需要合并操作。 粗心的实现可能仍然会尝试堆操作，并在尝试弹出两个元素时失败。 

实现立即处理这个问题：```
if len(sticks) <= 1:
    return 0
```这保证了尽可能最小的输入的安全执行。 

### 许多相等的值

 输入如`[1,1,1,1]`可能会暴露堆处理或合并排序假设中的错误。 由于许多值是相同的，因此算法仍然必须正确维护堆结构和累积成本。 

最小堆自然地处理重复值，无需任何特殊逻辑，确保正确的行为。 

### 价值观高度不平衡

 输入如`[1,1,1,10000]`展示了为什么贪婪策略很重要。 过早组合大棒会大大增加未来的成本。 

该实现始终首先提取两个最小的棍子，确保大值在必要时保持不变。 这最大限度地减少了大额中间金额的重复贡献。 

### 大输入量

 该问题最多允许`10^4`棍子。 每次合并后重复对数组进行排序的简单解决方案会变得低效。 

使用最小堆保证高效`O(log n)`插入和删除，允许算法在约束范围内轻松扩展。
