[LeetCode 第 1196 题](https://leetcode.com/problems/how-many-apples-can-you-put-into-the-basket/)

 **难度：** 🟢简单
 **主题：** 数组、贪婪、排序

 ## 解决方案

 ## 问题理解

 这个问题要求我们确定一个最大承载能力为 5000 单位重量的篮子里可以装多少个苹果。 我们得到一个数组`weight`其中每个元素代表单个苹果的重量。 目标是在不超过篮子重量限制的情况下最大限度地增加放入篮子中的苹果数量。 

换句话说，我们想要计算苹果的最大子集，使得它们的权重总和不超过 5000。输出是表示该最大计数的单个整数。 

这些约束提供了重要信息：苹果的数量最多可达 103 个，每个苹果的重量最多可达 103 个。这告诉我们，我们正在处理较小的输入大小，因此时间复杂度高达 O(n log n) 或 O(n²) 的算法是可以接受的。 该问题保证所有权重均为正整数，并且至少有一个苹果，因此我们不需要处理空数组。 

重要的边缘情况包括所有苹果都非常轻、所有苹果都非常重或重量总和恰好为 5000 的混合。另一种边缘情况是单个苹果超过篮子容量时。 

## 方法

 蛮力方法是考虑苹果的每个子集，计算它们的总重量，并跟踪不超过 5000 个的苹果的最大数量。这保证了正确性，因为它会检查每个组合，但这是不切实际的，因为有 2^n 个可能的子集。 对于 n = 103，这是一个天文数字。 

更高效解决方案的关键洞察是贪婪：较轻的苹果消耗较少的容量，因此我们可以从最小的重量开始容纳更多的苹果。 对数组进行排序并按升序迭代它可以让我们对苹果进行计数，直到添加下一个苹果将超出篮子的容量。 这是有效的，因为首先添加较重的苹果可能会阻止我们稍后添加更轻的苹果，而首先添加较轻的苹果可以最大化计数。

 | 最优（贪心 + 排序）| O(n log n) | O(n log n) | O(1) | O(1) | 对重量进行排序并从最轻的开始采摘苹果，直到达到容量 |

 ## 算法演练

 1. 排序`weight`按升序排列，以便首先考虑最轻的苹果。 这确保了我们在不超过篮子容量的情况下最大限度地增加苹果的数量。 
2.初始化两个变量：`total_weight`跟踪篮子中的累计重量并`count`跟踪添加的苹果数量。 
3. 迭代排序后的权重。 对于每个苹果：

 - 检查是否将苹果的重量添加到`total_weight`将超过5000。 
- 如果不是，请将重量添加到`total_weight`并增加`count`。 
- 如果超过限制，请停止迭代，因为任何后续的苹果都会更重并且无法容纳。 
4. 返回`count`作为篮子中可以容纳的最大苹果数量。 

为什么有效：排序可确保我们始终首先挑选最小的可用苹果。 这保证了在每一步中，只有当总重量保持在容量范围内时，我们才会添加苹果。 一旦我们无法容纳一个苹果，排序顺序中的其他苹果就无法容纳，因此停止是正确的。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxNumberOfApples(self, weight: List[int]) -> int:
        weight.sort()
        total_weight = 0
        count = 0
        
        for w in weight:
            if total_weight + w > 5000:
                break
            total_weight += w
            count += 1
        
        return count
```实现首先对权重列表进行排序。 我们维持`total_weight`和`count`跟踪篮子状态。 对于每个苹果，我们都会检查它是否合适。 如果是，我们将其包含在内并更新运行总计和计数。 如果没有，我们就会停止，因为后续的苹果都无法容纳。 最后，我们返回总数。 

## 解决方案```go
import "sort"

func maxNumberOfApples(weight []int) int {
    sort.Ints(weight)
    totalWeight := 0
    count := 0
    
    for _, w := range weight {
        if totalWeight + w > 5000 {
            break
        }
        totalWeight += w
        count++
    }
    
    return count
}
```Go 版本遵循与 Python 相同的逻辑。 我们使用`sort.Ints`对切​​片和变量进行排序`totalWeight`和`count`跟踪苹果的运行重量和数量。 循环会迭代排序后的切片，一旦添加的苹果超过 5000 个，循环就会中断。Go 特定的考虑因素包括使用切片，它是 nil 安全的，并且由于约束，整数加法在这里是安全的。 

## 工作示例

 **示例1：权重= [100,200,150,1000]**

 1. 排序：[100, 150, 200, 1000]
 2.总重量=0，计数=0
 3.加100：total_weight = 100，count = 1
 4.加150：total_weight = 250，count = 2
 5. 添加 200：total_weight = 450，count = 3
 6.加1000：total_weight = 1450，count = 4
 7. 不再吃苹果了。 返回 4

 **示例2：权重 = [900,950,800,1000,700,800]**

 1. 排序：[700, 800, 800, 900, 950, 1000]
 2.总重量=0，计数=0
 3.添加700：total_weight = 700，count = 1
 4.添加800：total_weight = 1500，count = 2
 5.添加800：total_weight = 2300，count = 3
 6. 添加 900：total_weight = 3200，count = 4
 7. 添加 950：total_weight = 4150，count = 5
 8. 接下来苹果1000将超过5000，停止。 返回5

 ## 边缘情况

 一种极端情况是单个苹果超出篮子容量，例如，`[6000]`。 我们的实现正确返回 0，因为检查`total_weight + w > 5000`阻止添加它。 

另一种极端情况是所有苹果都非常轻，例如`[1]*5000`。 在这里，贪婪算法将迭代所有苹果并正确地将所有 5000 个苹果算作拟合。 

第三种边缘情况是总重量恰好为 5000，例如，`[2000,1500,1500]`。 该算法将按顺序包含苹果，直到总数达到 5000，并在不超过它的情况下停止，返回最大可能计数。 

这涵盖了边界、最小和最大选择场景，确保典型和极端输入的正确性。
