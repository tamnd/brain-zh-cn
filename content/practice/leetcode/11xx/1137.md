 # LeetCode 1137，第 N 个 Tribonacci 数

 ## 问题理解

 该问题要求我们计算`n`Tribonacci 序列中的第 - 个数字。 

Tribonacci 序列与 Fibonacci 序列非常相似，不同之处在于，Tribonacci 序列不是将前两个数字相加，而是通过将前三个数字相加来形成每个值。 

该序列定义为：

 -`T0 = 0`-`T1 = 1`-`T2 = 1`对于之后的每个值：$T_{n+3}=T_n+T_{n+1}+T_{n+2}$输入由单个整数组成`n`，表示我们需要返回的 Tribonacci 数的索引。 输出的值为`Tn`。 

例如：

-`n = 4`- 序列变为：`0, 1, 1, 2, 4`- 所以，`T4 = 4`限制非常小：

 -`0 <= n <= 37`- 结果始终适合 32 位有符号整数

 这些限制告诉我们一些重要的事情：

 - 指数递归在技术上可能会通过，因为`n`很小。 
- 然而，该问题是为了教授动态编程或记忆而设计的。 
- 高效的线性解决方案是简单且首选的。 
- 整数溢出在 Python 中不是问题，在 Go 中也是安全的，因为答案在 32 位整数范围内。 

有几个重要的边缘情况：

 -`n = 0`，我们必须返回`0`-`n = 1`，我们必须返回`1`-`n = 2`，我们必须返回`1`这些基本情况至关重要，因为递归关系仅适用于大于或等于的值`3`。 立即开始递归计算而不处理这些情况的简单实现可能会产生不正确的结果或索引错误。 

## 方法

 ### 蛮力递归方法

 最直接的方法是完全按照书面形式实现递归关系。 

对于每个`n`，我们递归计算：

 -`tribonacci(n - 1)`-`tribonacci(n - 2)`-`tribonacci(n - 3)`并将它们加在一起。 

这种方法在数学上是正确的，因为它直接遵循问题定义。 然而，它的效率极低，因为相同的子问题被重新计算很多次。 

例如，计算`tribonacci(25)`反复重新计算值，例如`tribonacci(20)`和`tribonacci(18)`反复。 

递归树呈指数增长，使得该解决方案变得不必要的缓慢。 

### 最优动态规划方法

 关键的观察结果是每个 Tribonacci 数仅取决于前三个值。 

这意味着我们根本不需要递归。 我们可以自下而上迭代地构建序列。 

在任何一步，我们只需要记住：

 - 前第三个值
 - 前第二个值
 - 之前的第一个值

 使用这三个变量，我们可以在常数时间内计算下一个 Tribonacci 数。 

这将解决方案转换为具有恒定额外内存的简单线性迭代。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(3^n) | O(3^n) | O(n) | 递归重新计算导致指数增长 |
 | 最佳 | O(n) | O(1) | O(1) | 使用三变量的迭代动态规划 |

 ## 算法演练

 ### 最优迭代动态规划算法

 1. 首先，直接处理基础案例。 

如果`n`是：

-`0`， 返回`0`-`1`或者`2`， 返回`1`这些值是由问题明确定义的。 
2. 初始化三个变量来表示最新的 Tribonacci 数。 

我们从以下开始：

 -`first = 0`-`second = 1`-`third = 1`这些对应于：

 -`T0`-`T1`-`T2`3. 迭代自`3`最多`n`。 

对于每个位置：

 - 计算下一个 Tribonacci 值：`next_value = first + second + third`4. 将窗口向前移动。 

计算出新值后：

 -`first`变成`second`-`second`变成`third`-`third`变成`next_value`这保持了变量始终代表最近的三个 Tribonacci 数的不变性。 
5.循环结束后，返回`third`。 

那时，`third`商店`Tn`。 

### 为什么它有效

 该算法在每次迭代时维护一个包含最后三个 Tribonacci 值的滑动窗口。 

最初：

-`first = T0`-`second = T1`-`third = T2`在每次迭代期间，我们计算：

 -`next_value = T(n-3) + T(n-2) + T(n-1)`这与 Tribonacci 递归定义完全匹配。 

向前移动变量后，不变量在下一次迭代中保持不变。 由于递归关系在每一步都正确应用，因此最终值存储在`third`保证是正确的`Tn`。 

## Python 解决方案```
class Solution:
    def tribonacci(self, n: int) -> int:
        if n == 0:
            return 0
        
        if n == 1 or n == 2:
            return 1
        
        first, second, third = 0, 1, 1
        
        for _ in range(3, n + 1):
            next_value = first + second + third
            first = second
            second = third
            third = next_value
        
        return third
```实现首先直接处理三个基本情况。 这避免了不必要的迭代并确保最小输入的正确性。 

变量`first`,`second`， 和`third`存储三个最近的 Tribonacci 数字。 最初，他们代表`T0`,`T1`， 和`T2`。 

循环运行自`3`通过`n`，包含在内。 在每次迭代期间，下一个 Tribonacci 数是通过将前三个值相加来计算的。 

计算后`next_value`，变量向前移动，以便它们继续代表最近的三个序列值。 

在循环结束时，`third`包含答案。 

## 解决方案```
func tribonacci(n int) int {
    if n == 0 {
        return 0
    }

    if n == 1 || n == 2 {
        return 1
    }

    first, second, third := 0, 1, 1

    for i := 3; i <= n; i++ {
        nextValue := first + second + third
        first = second
        second = third
        third = nextValue
    }

    return third
}
```Go 实现遵循与 Python 解决方案完全相同的逻辑。 

一个小区别是 Go 需要使用显式变量声明`:=`。 

无需担心整数溢出，因为该问题保证结果符合 32 位有符号整数范围。 去的`int`type 安全地处理这些值。 

与 Python 不同，Go 不支持以完全相同的灵活方式进行元组赋值，因此变量是单独更新的。

 ## 边缘情况

 ### 边缘情况 1，`n = 0`这是最小的有效输入。 如果实现假设序列始终以正值开始，则很容易导致错误。 

该实现显式检查`n == 0`并立即返回`0`，避免任何不必要的计算或不正确的索引逻辑。 

### 边缘情况 2，`n = 1`或者`n = 2`这些值很特殊，因为它们是预定义的基本情况，并且不是由递归关系生成的。 

盲目进入循环而不处理这些情况的解决方案可能会错误地计算值或访问无效的先前状态。 

该实现通过返回直接处理这两种情况`1`。 

### 边缘情况 3，最大输入`n = 37`虽然输入范围很小，但值增长很快。 

递归暴力解决方案仍然会执行大量重复计算。 虽然从技术上来说它可以通过这个限制，但它效率低且扩展性差。 

迭代动态规划解决方案在使用恒定内存的同时，可以在线性时间内有效地处理最大输入。
