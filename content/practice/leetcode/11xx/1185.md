 # LeetCode 1185 - 星期几

 ## 问题理解

 该问题要求我们确定一周中的哪一天对应于给定的日历日期。 

输入由三个整数组成：

 -`day`, 代表该月内的日期
 -`month`，代表从 1 到 12 的月份数
 -`year`, 代表年份

 我们必须以字符串形式返回正确的工作日名称。 可能的输出是：

 -`"Sunday"`-`"Monday"`-`"Tuesday"`-`"Wednesday"`-`"Thursday"`-`"Friday"`-`"Saturday"`这个问题提供了一个重要的参考点：

 > 1971 年 1 月 1 日是星期五。 

此参考日期允许我们通过计算自已知起点以来已经过去的天数来计算任何较晚日期的工作日。 

限制相对较小：

 - 保证日期有效
 - 年份范围为`1971`到`2100`由于日期范围仅限于 130 年左右，因此性能并不是主要问题。 即使解决方案需要一天一天地迭代，仍然可以运行得足够快。 然而，我们仍然可以设计一个干净高效的数学解决方案。 

一些边缘情况很重要：

 - 必须正确处理闰年
 - 闰年二月从 28 天变为 29 天
 - 年初或年末的日期可能会出现一个错误
 - 世纪年需要正确的闰年处理，尽管在此范围内只有 2000 年很重要
 - 参考日期本身 1971 年 1 月 1 日应直接映射到星期五

 该问题保证所有日期都是有效的，因此我们不需要执行输入验证。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是从 1971 年 1 月 1 日开始逐日模拟日历。 

我们知道 1971 年 1 月 1 日是星期五。 我们可以一次一天地重复推进，直到达到目标日期。 每前进一天，我们也会前进一个工作日指数。 

为了实施这种方法，我们将：

 1. 开始于`(1, 1, 1971)`2. 不断增加日期
 3. 跟踪工作日指数模 7
 4. 一旦达到目标日期就停止

 这是有效的，因为工作日每 7 天重复一次，并且提前一个日历日总是将工作日提前一位。 

尽管正确，但这种方法在概念上效率低下，因为它单独模拟每个中间日期。 对于大范围，这会变得不必要的昂贵。 

### 最优数学计数方法

 我们可以计算参考日期和目标日期之间的总天数，而不是模拟每个日期转换。 

关键的观察是：

 - 每个正常年份贡献365天
 - 闰年贡献 366 天
 - 每个月贡献已知的天数

 如果我们计算自 1971 年 1 月 1 日以来经过的总天数，则：

 -`0`过去的天数是指星期五
 -`1`经过一天意味着星期六
 -`2`过去的天数是指星期日
 - 等等

 由于工作日每 7 天重复一次，因此我们只需要：```
total_days % 7
```这会将绝对天数转换为工作日索引。 

算法变为：

 1. 计算目标年份之前的所有完整年份
 2. 统计目标月份之前的所有完整月份
 3. 添加当天偏移量
 4. 使用模运算确定工作日

 该解决方案简单、高效且易于推理。

 ## 算法演练

 ### 第 1 步：存储工作日名称

 我们按顺序创建一个工作日名称数组：```
["Friday", "Saturday", "Sunday", "Monday", "Tuesday", "Wednesday", "Thursday"]
```指数`0`对应于 1971 年 1 月 1 日。 

### 第 2 步：定义月份长度

 我们存储正常年份每个月的天数：```
[31,28,31,30,31,30,31,31,30,31,30,31]
```闰年 2 月可能会变成 29 天。 

### 步骤 3：创建闰年助手

 如果满足以下条件，一年就是闰年：

 - 能被 400 整除，或者
 - 能被4整除但不能被100整除

 这遵循公历规则。 

辅助函数使我们能够正确计算二月的天数。 

### 步骤 4：计算全年贡献的天数

 我们迭代自`1971`最多`year - 1`。 

每年：

 - 添加`365`- 如果是闰年则增加一天

 在此步骤结束时，我们知道距离目标年份开始已经过去了多少天。 

### 步骤 5：计算整月贡献的天数

 我们迭代目标月份之前的所有月份。 

每个月：

 - 添加相应的天数
 - 如果月份是闰年的二月，则增加一天

 现在我们知道距离目标月份开始还有多少天。 

### 步骤 6：添加当月天数

 我们添加：```
day - 1
```我们减一是因为当天本身不应该完全提前工作日计数。 

例如：

 - 1 月 1 日应贡献零额外经过天数
 - 1 月 2 日应该贡献一天

 ### 步骤 7：计算工作日

 我们计算：```
weekday_index = total_days % 7
```然后返回：```
weekdays[weekday_index]
```### 为什么它有效

 该算法之所以有效，是因为每个日历日都将工作日向前推进一位。 通过计算从已知参考日期算起经过的确切天数，我们可以使用模 7 算术确定工作日。 

闰年计算可保证二月提供正确的天数。 由于我们计算了所有整年、所有整月以及当月内的偏移量，因此计算出的总数准确地代表了自 1971 年 1 月 1 日以来经过的天数。 

## Python 解决方案```python
class Solution:
    def dayOfTheWeek(self, day: int, month: int, year: int) -> str:
        weekdays = [
            "Friday",
            "Saturday",
            "Sunday",
            "Monday",
            "Tuesday",
            "Wednesday",
            "Thursday"
        ]

        month_days = [31, 28, 31, 30, 31, 30,
                      31, 31, 30, 31, 30, 31]

        def is_leap(y: int) -> bool:
            return (y % 400 == 0) or (y % 4 == 0 and y % 100 != 0)

        total_days = 0

        # Add days for complete years
        for current_year in range(1971, year):
            total_days += 365
            if is_leap(current_year):
                total_days += 1

        # Add days for complete months
        for current_month in range(1, month):
            total_days += month_days[current_month - 1]

            if current_month == 2 and is_leap(year):
                total_days += 1

        # Add days within current month
        total_days += day - 1

        return weekdays[total_days % 7]
```该实现首先以相对于参考日期的确切顺序存储工作日名称。 自 1971 年 1 月 1 日为星期五以来，指数`0`映射到`"Friday"`。 

这`month_days`数组存储非闰年每个月的标准天数。 2 月份的调整是单独处理的，以保持逻辑清晰。 

这`is_leap`helper 封装了公历闰年规则。 这避免了在整个解决方案中重复闰年逻辑。 

第一个循环累积目标年份之前所有完全完成年份的天数。 每年贡献 365 或 366 天。 

第二个循环累积目标月份之前所有完全完成的月份的天数。 如果当前年份是闰年且月份是二月，则添加一天。 

最后，`day - 1`添加是因为该月的第一天贡献了零经过天数。 

模运算将总的经过天数转换为工作日索引。 

## 解决方案```go
func dayOfTheWeek(day int, month int, year int) string {
    weekdays := []string{
        "Friday",
        "Saturday",
        "Sunday",
        "Monday",
        "Tuesday",
        "Wednesday",
        "Thursday",
    }

    monthDays := []int{
        31, 28, 31, 30, 31, 30,
        31, 31, 30, 31, 30, 31,
    }

    isLeap := func(y int) bool {
        return (y%400 == 0) || (y%4 == 0 && y%100 != 0)
    }

    totalDays := 0

    // Add days for complete years
    for currentYear := 1971; currentYear < year; currentYear++ {
        totalDays += 365

        if isLeap(currentYear) {
            totalDays++
        }
    }

    // Add days for complete months
    for currentMonth := 1; currentMonth < month; currentMonth++ {
        totalDays += monthDays[currentMonth-1]

        if currentMonth == 2 && isLeap(year) {
            totalDays++
        }
    }

    // Add days within current month
    totalDays += day - 1

    return weekdays[totalDays%7]
}
```Go 实现遵循与 Python 解决方案相同的逻辑结构。 

Go 使用切片而不是 Python 列表，但索引行为是等效的。 闰年助手作为分配给的匿名函数实现`isLeap`。 

由于约束非常小，因此不必担心整数溢出。 标准围棋`int`值对于所涉及的天数来说绰绰有余。 

不需要对 nil 值进行特殊处理，因为保证输入有效。

 ## 边缘情况

 ### 闰年二月

 闰年是日历问题中最常见的错误来源。 二月通常有 28 天，但闰年会额外增加一天。 忘记此调整会导致该年的所有后续工作日计算变得不正确。 

此实现使用以下方法处理该问题`is_leap`辅助功能。 每当在闰年期间处理二月时，总计数就会增加一天。 

### 参考日期对齐

 在计算经过的天数时，很容易引入相差一的错误。 例如，错误地添加`day`而不是`day - 1`会将每个答案移动一个工作日。 

该实现谨慎地将 1971 年 1 月 1 日视为零逝去天数。 这确保了参考工作日`"Friday"`正确映射到索引`0`。 

### 闰年规则

 许多实现错误地假设每年能被 4 整除的年份都是闰年。 这一规则在像 1900 年这样的世纪年中不起作用，除非能被 400 整除，否则这些世纪年不是闰年。 

该解决方案使用完整的格里高利规则：```
(y % 400 == 0) or (y % 4 == 0 and y % 100 != 0)
```这可以正确处理 2000 年，这是一个闰年，因为它可以被 400 整除。
