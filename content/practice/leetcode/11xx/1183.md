 # LeetCode 1183，最大个数

 ## 问题理解

 该问题给了我们一个二元矩阵`M`有尺寸`height x width`。 矩阵中的每个单元格必须包含`0`或者`1`。 

有一个重要的限制：

 每个大小的平方子矩阵`sideLength x sideLength`最多可能包含`maxOnes`单元格等于`1`。 

我们的目标是构造这样一个矩阵，同时最大化整个矩阵中的总数。 

换句话说，我们想要放置尽可能多的`1`尽可能在全球范围内，同时确保每个地方`sideLength x sideLength`窗口尊重限制。 

输出是在这些约束下可实现的最大数量。 

限制相对较小：

 -`width, height <= 100`-`sideLength <= 100`这告诉我们多项式解是可以接受的，但对所有矩阵进行暴力破解是不可能的，因为二进制矩阵的数量是指数级的。 

关键的挑战是理解每个方形子矩阵的局部限制如何影响子矩阵的全局排列。 

一些边缘情况很重要：

 -`maxOnes = 0`，每个单元格都必须为零。 
-`sideLength = 1`，每个单独的单元形成一个子矩阵，因此整个矩阵最多可以包含`maxOnes`每个细胞。 
-`maxOnes = sideLength * sideLength`，实际上没有任何限制，因此整个矩阵可以用 1 填充。 
- 非方形尺寸，例如`width = 100`,`height = 1`，其中重复模式的行为不同。 
- 非常小的矩阵，其中重复图案部分重叠矩阵边界。 

## 方法

 ### 蛮力方法

 一种简单的方法会尝试尝试所有可能的二进制矩阵并验证是否每个`sideLength x sideLength`子矩阵满足条件。 

对于每个矩阵：

 1. 列举所有可能的情况`sideLength x sideLength`窗户。 
2. 数一下里面有多少个。 
3. 如果任何窗口超过则拒绝矩阵`maxOnes`。 
4. 否则，计算总数并保留最大值。 

这种方法是正确的，因为它显式检查每个有效配置。 

然而，这在计算上是不可能的。 一个矩阵`width * height`细胞具有：$$2^{(width \cdot height)}$$可能的配置。 

甚至一个`10 x 10`矩阵已经有：$$2^{100}$$的可能性，这是完全不可行的。 

我们需要避免探索单个矩阵的结构观察。 

### 关键见解

 关键的观察是，限制仅取决于位置模`sideLength`。 

考虑大小的重复模式：$$sideLength \times sideLength$$任何细胞`(r, c)`所属图案位置：$$(r \bmod sideLength,\ c \bmod sideLength)$$每一个`sideLength x sideLength`子矩阵恰好包含每个模式位置的一次出现。 

这意味着：

 - 如果我们选择基本形态内的一些位置`1`,
 - 然后在矩阵中重复该模式可以保证每个`sideLength x sideLength`正方形正好包含那么多。 

因此：

 - 我们最多只需要选择`maxOnes`基本形态内的位置。 
- 不同的图案位置在完整矩阵中出现的次数不同。 
- 为了最大化总数，我们应该选择重复最频繁的位置。 

那么问题就变成了：

 1. 计算每个模式位置在矩阵中出现的次数。 
2. 选择`maxOnes`最大频率。 
3. 对它们求和。 

这将一个困难的组合优化问题转化为计数和排序问题。

 ## 算法演练

 ### 第 1 步，了解重复模式

 任何细胞`(r, c)`可以映射到基本模式位置：$$(r \bmod sideLength,\ c \bmod sideLength)$$确切地说有：$$sideLength^2$$不同的图案位置。 

每一个`sideLength x sideLength`子矩阵包含每个模式位置的一个副本。 

因此，如果我们放置`k`基本模式内的那些，每个有效的方块也将恰好包含`k`那些。 

所以我们最多可以选择`maxOnes`基本模式中的位置。 

### 步骤2，计算每个模式位置的频率

 对于每个图案行`r`:$$rowCount = \left\lfloor \frac{height}{sideLength} \right\rfloor$$如果余数覆盖该行，则再加一次出现。 

对于每个模式列同样如此`c`:$$colCount = \left\lfloor \frac{width}{sideLength} \right\rfloor$$如果余数覆盖该列，则再加一次出现。 

职位出场总数`(r, c)`是：$$rowCount \times colCount$$这告诉我们有多少矩阵单元变成`1`如果我们选择该图案位置。 

### 步骤 3，存储所有频率

 我们计算所有的频率：$$sideLength^2$$位置并将它们存储在列表中。 

### 步骤 4，选择最大频率

 因为我们可能只激活`maxOnes`位置，我们按降序对频率进行排序，并取最大的`maxOnes`价值观。 

### 步骤5，返回总和

 所选频率的总和等于矩阵中可能出现的最大频率数。 

## 为什么它有效

 每个`sideLength x sideLength`子矩阵恰好包含每个模位置的一个副本。 因此，选择一组模位置唯一地确定每个方格包含多少个。 

因为每个选择的位置对总数量都有独立的贡献，所以最佳策略是贪婪的：始终选择重复次数最多的位置。 

这保证了最大全局数量，同时尊重局部约束。 

## Python 解决方案```python
class Solution:
    def maximumNumberOfOnes(
        self,
        width: int,
        height: int,
        sideLength: int,
        maxOnes: int
    ) -> int:

        frequencies = []

        for r in range(sideLength):
            row_count = height // sideLength
            if r < height % sideLength:
                row_count += 1

            for c in range(sideLength):
                col_count = width // sideLength
                if c < width % sideLength:
                    col_count += 1

                frequencies.append(row_count * col_count)

        frequencies.sort(reverse=True)

        return sum(frequencies[:maxOnes])
```实现直接遵循数学观察。 

外循环迭代基础内部的每个位置`sideLength x sideLength`图案。 

对于每个行位置，我们计算有多少实际矩阵行映射到该模类。 同样的逻辑也适用于列。 

将这些计数相乘即可得出该图案位置表示的矩阵单元的数量。 

所有频率都收集到一个列表中并按降序排序。 因为我们最多可以选择`maxOnes`模式位置，最佳答案只是最大的总和`maxOnes`频率。 

实现很简洁，因为问题完全简化为计算重复次数。 

## 解决方案```go
package main

import "sort"

func maximumNumberOfOnes(width int, height int, sideLength int, maxOnes int) int {
	frequencies := []int{}

	for r := 0; r < sideLength; r++ {
		rowCount := height / sideLength
		if r < height%sideLength {
			rowCount++
		}

		for c := 0; c < sideLength; c++ {
			colCount := width / sideLength
			if c < width%sideLength {
				colCount++
			}

			frequencies = append(frequencies, rowCount*colCount)
		}
	}

	sort.Sort(sort.Reverse(sort.IntSlice(frequencies)))

	answer := 0

	for i := 0; i < maxOnes; i++ {
		answer += frequencies[i]
	}

	return answer
}
```Go 的实现与 Python 解决方案非常相似。 

主要区别在于 Go 需要显式的切片管理和排序实用程序`sort`包裹。 

整数溢出不是问题，因为最大可能的答案是：$$100 \times 100 = 10000$$很容易适合 Go 的内部`int`类型。

 ## 边缘情况

 ### maxOnes 等于 0

 如果`maxOnes = 0`，那么没有`sideLength x sideLength`square 可以包含任何一个。 由于每个矩阵单元都属于某个这样的正方形，因此整个矩阵必须为零。 

有缺陷的实现可能仍会尝试选择频率或意外地包含一个位置。 此实现可以自然地处理这种情况，因为：```
sum(frequencies[:0])
```正确评估为`0`。 

### 边长等于一

 当`sideLength = 1`，每个单独的细胞形成一个`1 x 1`子矩阵。 

这意味着：

 - 如果`maxOnes = 0`，所有单元格必须为零。 
- 如果`maxOnes = 1`，所有单元格都可以是一个。 

这种情况很容易在概念上处理错误，因为重复模式仅包含一个位置。 模计数逻辑仍然可以正常工作，因为每个单元都映射到相同的模式坐标。 

### 矩阵尺寸不能被边长整除

 考虑：```
width = 8
height = 9
sideLength = 3
```一些模数位置比其他模数位置出现得更频繁，因为矩阵没有均匀地划分为重复块。 

幼稚的实现可能会假设每个模式位置出现的频率相同，这会产生错误的答案。 

该实现仔细计算：```
height // sideLength
height % sideLength
```对于列也类似，确保额外的行和列在最早的模类之间正确分配。
