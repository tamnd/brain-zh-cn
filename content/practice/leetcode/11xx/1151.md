[LeetCode 第 1151 题](https://leetcode.com/problems/minimum-swaps-to-group-all-1s-together/)

 **难度：** 🟡 中等
 **主题：** 数组、滑动窗口

 ## 解决方案

 ## 问题理解

 这个问题要求我们确定将所有数据分组所需的最小交换次数`1`将二进制数组中的 s 放入一个连续的块中。 该块可以出现在数组中的任何位置，只要所有`1`s 最终相邻。 

输入是一个二进制数组`data`，意味着每个元素都是`0`或者`1`。 交换意味着交换两个元素的位置。 重要的观察是，我们不需要保留元素的原始顺序，只需使所有元素`1`s一起出现。 

假设数组包含`k`那些。 在最终的安排中，所有`k`必须占据一些连续的长度子数组`k`。 因此，真正的问题变成：

 > 在所有长度的子数组中`k`，哪一个已经包含最多`1`是？ 

如果一个窗口的长度`k`已经包含了很多`1`s，那么只有当前占据的剩余位置`0`s，需要通过交换来修复。 既然每一次都错位了`0`可以与一个交换`1`在窗口之外，该窗口所需的交换次数等于其内部零的数量。 

约束条件很重要：

 -`1 <= data.length <= 10^5`这立即表明`O(n^2)`对于大输入来说，解决方案将太慢。 我们需要一个线性或接近线性的算法。 

有几个重要的边缘情况：

 - 没有的数组`1`根本没有
 - 恰好只有一个的数组`1`- 所有元素都已存在的数组`1`- 最佳分组窗口出现在中间的数组
 - 交替排列的数组`0`沙`1`s

 通过独立检查每个可能的分组配置，幼稚的实现很容易变得低效。 

## 方法

 ### 蛮力方法

 蛮力的想法是首先计算有多少`1`s存在于数组中，调用这个值`k`。 然后我们检查每个可能的长度子数组`k`。 

对于每个窗口，我们计算它包含多少个零。 由于窗口内的每个零最终都必须成为`1`，零的数量直接等于该窗口所需的交换数量。 

我们对每个可能的窗口进行计算并返回最小值。 

这种方法是正确的，因为任何有效的最终安排都必须将所有`1`s 在一个连续的大小块内`k`。 

但是，如果我们从头开始重新计算每个窗口的零数量，复杂度将变为：

 - 有`O(n)`窗户
 - 每个窗口占用`O(k)`扫描时间

 这导致`O(n * k)`复杂性，可能会降级为`O(n^2)`在最坏的情况下。 

和`n = 10^5`，这太慢了。 

### 最优方法，滑动窗口

 关键的观察结果是相邻的窗口严重重叠。 

如果我们已经知道了`1`s 在一个窗口内，则当窗口滑动一个位置时：

 - 一个元素离开窗口
 - 一个新元素进入窗口

 我们可以在恒定时间内增量更新计数，而不是重新计数所有内容。 

这是一个经典的滑动窗口问题。 

该算法的工作原理如下：

 1. 统计总数量`1`s，称之为`window_size`2.使用该尺寸的推拉窗
 3. 追踪数量`1`s 在当前窗口内
 4. 最大化数量`1`位于任何窗口内
 5. 答案变为：```
window_size - maximum_ones_in_window
```这是有效的，因为每个缺失`1`窗口内对应于必须交换的零。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) | O(1) | 独立地对每个窗口进行计数 |
 | 最佳 | O(n) | O(1) | O(1) | 使用滑动窗口高效更新计数 |

 ## 算法演练

 1. 统计总数量`1`s 在数组中。 

该值确定目标连续块的大小。 如果有`k`，那么最终分组的部分必须有长度`k`。 
2、小案件及早处理。 

如果数组包含`0`或者`1`那些，不需要交换，因为它们已经分组了。 
3. 构建初始窗口。 

创建一个覆盖第一个窗口的窗口`k`元素。 数数有多少个`1`s 位于该窗口内。 
4. 跟踪迄今为止看到的最佳窗口。 

存储最大数量`1`在任何大小的窗口中都可以找到`k`。 
5. 将窗口滑过阵列。 

对于每个步骤：

 - 如果是，则从计数中删除最左边的元素`1`- 添加新的最右边元素（如果是）`1`- 更新最大计数

 这避免了每次都重新扫描整个窗口。 
6. 计算答案。 

如果最佳窗口包含`max_ones`1，则窗口内的剩余位置为零。 

所以：```
swaps = k - max_ones
```### 为什么它有效

 每个有效的最终安排必须将所有`1`s 在一个连续的长度块内`k`， 在哪里`k`是总数。 

对于任何这样的块：

 - 职位已包含`1`是正确的
 - 职位包含`0`必须由块外的替换

 因此，所需交换的数量等于所选窗口内零的数量。 

因此，最小化交换相当于最大化交换数量`1`s 已经存在于一个大小的窗口中`k`。 

## Python 解决方案```python
from typing import List

class Solution:
    def minSwaps(self, data: List[int]) -> int:
        total_ones = sum(data)

        if total_ones <= 1:
            return 0

        current_ones = sum(data[:total_ones])
        max_ones = current_ones

        left = 0

        for right in range(total_ones, len(data)):
            current_ones += data[right]
            current_ones -= data[left]
            left += 1

            max_ones = max(max_ones, current_ones)

        return total_ones - max_ones
```实现首先计算总数量`1`s 在数组中。 这决定了所需的窗口大小，因为所有窗口最终都必须占据该长度的连续段。 

如果有零个或一个，则立即给出答案`0`因为不需要交换。 

接下来，代码计算第一个大小窗口内的个数`total_ones`。 这会初始化两个`current_ones`和`max_ones`。 

然后滑动窗口在阵列上一次移动一步。 每次移动都会通过减去离开窗口的元素并添加新进入的元素来在恒定时间内更新计数。 

每张幻灯片之后，算法都会更新`max_ones`如果当前窗口包含的窗口数量多于之前看到的窗口数量。 

最后，答案计算如下：```python
total_ones - max_ones
```因为那些缺失的值恰好对应于必须交换的零。 

## 解决方案```go
func minSwaps(data []int) int {
	totalOnes := 0

	for _, value := range data {
		totalOnes += value
	}

	if totalOnes <= 1 {
		return 0
	}

	currentOnes := 0

	for i := 0; i < totalOnes; i++ {
		currentOnes += data[i]
	}

	maxOnes := currentOnes
	left := 0

	for right := totalOnes; right < len(data); right++ {
		currentOnes += data[right]
		currentOnes -= data[left]
		left++

		if currentOnes > maxOnes {
			maxOnes = currentOnes
		}
	}

	return totalOnes - maxOnes
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

Go 没有内置 Python`sum()`函数用于切片，因此实现显式循环遍历数组来计数。 

所有值都适合标准 Go`int`范围，因为最大数组大小仅为`10^5`，因此整数溢出不是问题。 

该算法使用恒定的额外内存并就地更新滑动窗口。

 ## 边缘情况

 当数组不包含任何内容时，就会出现一种重要的边缘情况`1`根本没有。 在这种情况下，没有什么可以组合在一起，所以正确的答案是`0`。 有缺陷的实现可能会错误地创建大小为零的窗口或尝试无效的索引操作。 此实现可以安全地处理该情况，因为它立即返回`0`什么时候`total_ones <= 1`。 

另一个重要的边缘情况是当数组恰好包含一个时`1`。 由于单个元素已经被简单地分组，因此不需要交换。 如果没有显式处理，某些实现可能仍会尝试不必要的滑动窗口操作。 提前返回完全避免了这个问题。 

当所有元素都已经存在时，就会出现第三种重要的边缘情况`1`。 在这种情况下，整个数组已经是一个连续的块。 滑动窗口大小等于整个数组长度，窗口内的最大个数等于总个数。 因此，计算结果自然为零。 

具有交替值的数组，例如`[1,0,1,0,1,0,1]`是另一个常见的错误来源，因为许多窗口包含相似的计数。 有缺陷的实现可能会在移动窗口时错误地更新滑动计数。 该算法通过在每次幻灯片期间一致地减去传出值并添加传入值来避免这种情况。
