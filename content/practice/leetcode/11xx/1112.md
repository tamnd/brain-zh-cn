 # LeetCode 1112 - 每个学生的最高成绩

 ## 问题理解

 该问题给了我们一个名为`Enrollments`。 每行代表一名学生正在学习一门课程并获得该课程的成绩。 

该表包含三列：

 | 专栏 | 意义|
 | ---| ---|
 |`student_id`| 学生的唯一标识符 |
 |`course_id`| 课程的唯一标识符 |
 |`grade`| 学生在该课程中的成绩 |

 组合`(student_id, course_id)`保证是唯一的，这意味着学生不能在同一门课程中出现多次。 

任务是为每个学生找到他们取得最高成绩的课程。 输出应包含：

 -`student_id`-`course_id`-`grade`有一条重要的打破平局规则。 如果一个学生有多门课程的最高成绩相同，我们必须选择成绩最小的课程`course_id`。 

最后，结果必须按以下顺序排序：`student_id`按升序排列。 

该问题从根本上来说是一个具有打破平局逻辑的分组最大查询。 我们对行进行分组`student_id`，找到每个组内的最高成绩，然后使用最小课程 ID 解决平局问题。 

一些边缘情况很重要：

 - 一名学生可能只有一门课程。 
- 一名学生可能有多个具有相同最高成绩的课程。 
- 成绩保证不为空。 
- 多个学生可能有相同的成绩，但比较始终是每个学生独立进行的。 
- 最小的`course_id`规则很容易忘记，如果处理不仔细，可能会导致错误的结果。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是独立处理每个学生。 

对于每个学生，我们可以扫描所有注册行并跟踪：

 - 迄今为止看到的最高等级
 - 与该年级相关的课程

 每当我们遇到：

 - 更大的等级，我们更新答案
 - 同等等级，较小`course_id`，我们也更新答案

 这种方法是正确的，因为属于学生的每一行都会被检查，保证最终选择最好的有效课程。 

然而，如果简单地实施，这可能会变得低效。 假设有`n`行和`m`学生。 重新扫描每个学生的整个表格会导致`O(n * m)`时间复杂度，这是不必要的昂贵。 

### 最佳方法

 关键的观察是我们可以通过一次分组传递来解决问题。 

对于每个学生，我们只需要维持当前最好的入学情况：

 - 最高等级
 - 出现平局时最小的课程 ID

 这意味着我们可以只处理每一行一次，同时维护一个由`student_id`。 

对于每个注册：

 - 如果成绩高于存储的最佳成绩，则替换存储的结果
 - 如果成绩相等且课程ID较小，则替换存储的结果
 - 否则，忽略该行

 这将复杂性降低到线性时间。 

在 SQL 中，这个问题通常使用窗口函数来解决，例如`ROW_NUMBER()`具有自定义订购规则。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n * m) | O(米) | 反复扫描每个学生的入学情况|
 | 最佳 | O(n) | O(米) | 使用分组或排名的单遍 |

 ## 算法演练

 ### 使用窗口函数的最佳 SQL 算法

 1. 按以下方式对行进行分区`student_id`。 

这会将属于同一学生的所有注册分组在一起，以便可以对它们进行独立排名。 
2. 在每个学生分区中，按以下方式对行进行排序：

 -`grade`按降序排列
 -`course_id`按升序排列

 以这种方式排序可以保证：

 - 最高等级首先出现
 - 关系由最小的课程 ID 解决
 3. 使用`ROW_NUMBER()`为分区内的每一行分配排名。 

每个学生的最佳课程将获得排名`1`。 
4. 仅选择其中的行`row_number = 1`。 

这些行代表每个学生的最终答案。 
5. 对最终输出进行排序`student_id`。 

### 为什么它有效

 排序标准强制执行问题所需的确切优先级规则：

 - 等级较高者优先
 - 对于同等成绩，首选较小的课程 ID

 因为`ROW_NUMBER()`分配等级`1`到排序后的第一行，所选行保证是该学生的正确答案。 

## Python 解决方案

 尽管这是一个数据库问题，但 LeetCode 数据库解释通常受益于显示等效的算法逻辑。 以下 Python 解决方案以编程方式演示了相同的想法。```python
from typing import List, Tuple

class Solution:
    def highestGrade(self, enrollments: List[Tuple[int, int, int]]) -> List[Tuple[int, int, int]]:
        best = {}

        for student_id, course_id, grade in enrollments:
            if student_id not in best:
                best[student_id] = (course_id, grade)
                continue

            current_course, current_grade = best[student_id]

            if grade > current_grade:
                best[student_id] = (course_id, grade)
            elif grade == current_grade and course_id < current_course:
                best[student_id] = (course_id, grade)

        result = []

        for student_id in sorted(best.keys()):
            course_id, grade = best[student_id]
            result.append((student_id, course_id, grade))

        return result
```该实现使用名为的字典`best`其中：

 - 关键是`student_id`- 该值存储当前最好的值`(course_id, grade)`在处理每个注册时，算法会将其与该学生存储的最佳结果进行比较。 

如果新成绩较大，则替换存储的结果。 

如果成绩相同，算法会检查平局规则并保留较小的课程 ID。 

处理完所有行后，结果按学生 ID 排序并返回。 

## 解决方案```go
package main

import (
	"sort"
)

type Enrollment struct {
	StudentID int
	CourseID  int
	Grade     int
}

func highestGrade(enrollments []Enrollment) []Enrollment {
	best := make(map[int]Enrollment)

	for _, enrollment := range enrollments {
		current, exists := best[enrollment.StudentID]

		if !exists {
			best[enrollment.StudentID] = enrollment
			continue
		}

		if enrollment.Grade > current.Grade {
			best[enrollment.StudentID] = enrollment
		} else if enrollment.Grade == current.Grade &&
			enrollment.CourseID < current.CourseID {
			best[enrollment.StudentID] = enrollment
		}
	}

	studentIDs := make([]int, 0, len(best))

	for studentID := range best {
		studentIDs = append(studentIDs, studentID)
	}

	sort.Ints(studentIDs)

	result := make([]Enrollment, 0, len(studentIDs))

	for _, studentID := range studentIDs {
		result = append(result, best[studentID])
	}

	return result
}
```Go 实现遵循与 Python 版本相同的逻辑。 

地图用于存储每个学生的最佳入学情况。 Go 在读取映射时需要明确的存在性检查，因此代码使用`exists`布尔值。 

最终的输出顺序是通过将学生 ID 提取到切片中并在构建结果之前对其进行排序来实现的。 

由于所有值都是整数并且约束很小，因此整数溢出在这里不是问题。

 ## 边缘情况

 当一名学生只有一次注册时，就会出现一种重要的边缘情况。 有缺陷的实现可能会假设每个学生存在多行，并意外地跳过这些学生。 此实现在学生第一次出现时正确初始化学生的最佳结果。 

另一个重要的情况是多门课程具有相同的最高成绩。 如果没有明确的平局打破逻辑，所选课程可能取决于迭代顺序，这是不正确的。 该实现通过显式选择较小的来处理这个问题`course_id`每当成绩相同时。 

当注册未按学生或年级排序时，就会出现第三种边缘情况。 一些不正确的解决方案假设行以有用的顺序到达。 此实现根本不依赖于排序，因为每一行都独立地与当前最佳结果进行比较。 

一个微妙的错误来源是过于激进地替换结果。 例如，如果学生已经有成绩`95`当然`2`，遇到另一个`95`当然`5`不应该取代答案。 该实现在更新存储值之前仔细检查这两个条件。
