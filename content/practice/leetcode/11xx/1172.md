[LeetCode 第 1172 题](https://leetcode.com/problems/dinner-plate-stacks/)

 **难度：** 🔴难
 **主题：** 哈希表、堆栈、设计、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 该问题要求我们设计一种数据结构，其行为类似于无限行堆栈，其中每个堆栈具有相同的固定容量。 

我们不使用单个堆栈，而是维护许多从左到右开始索引的堆栈`0`。 操作受到特定规则的约束：

 当我们`push(val)`，我们必须将值放入未满的最左边的堆栈中。 

当我们`pop()`，我们必须从最右边的非空堆栈中删除并返回顶部元素。 

当我们`popAtStack(index)`，我们从特定堆栈中删除并返回顶部元素`index`。 

如果弹出操作不存在有效元素，我们返回`-1`。 

棘手的部分是，堆栈可能会在中间部分变空`popAtStack`。 未来的推送需要在右侧创建新堆栈之前重用那些较早的堆栈。 

例如，如果容量是`2`我们有：```
Stack 0: [1]
Stack 1: [3,4]
Stack 2: [5]
```然后是未来`push(20)`必须进入堆栈`0`，因为它是最左边有可用空间的堆栈。 

限制条件很大：```
At most 2 * 10^5 operations
```这立即告诉我们，每次操作期间的线性扫描都会太慢。 重复扫描所有堆栈的简单实现会退化为二次行为。 

一些边缘情况很重要：

 如果所有栈都是空的，`pop()`必须返回`-1`。 

如果`popAtStack(index)`引用一个空的或不存在的堆栈，它必须返回`-1`。 

从最右边的堆栈弹出后，尾随的空堆栈应该有效消失，否则将来`pop()`操作可能会浪费时间扫描许多空堆栈。 

弹出后再次变为非满的堆栈必须符合将来的推送条件。 

因此，挑战在于有效地维护两件事：

 1. 最左边有可用空间的堆栈。 
2. 最右边的堆栈有元素。 

## 方法

 ### 蛮力方法

 最简单的解决方案是维护一个堆栈列表并在需要时直接扫描它。 

为了`push(val)`，我们从左到右扫描，直到找到大小小于容量的堆栈。 如果不存在，我们创建一个新堆栈。 

为了`pop()`，我们从右向左扫描，直到找到非空堆栈。 

为了`popAtStack(index)`，如果可能的话，我们直接从该堆栈中弹出。 

这种方法是正确的，因为它直接遵循问题的规则。 然而，它的效率很低。 

假设我们反复从中间堆栈中弹出元素，从而产生空洞。 未来的每次推送可能需要扫描许多堆栈才能找到可用的插槽。 相似地，`pop()`最后可能会重复扫描许多空堆栈。 

在最坏的情况下，每个操作都会变成`O(n)`， 在哪里`n`是堆栈的数量。 高达`2 * 10^5`操作，这变得太慢了。 

### 最佳方法

 关键的观察是我们反复需要两个特殊位置：

 1.最左边的非全栈。 
2.最右边的非空栈。 

我们可以有效地维护这些，而不是每次都扫描。 

我们使用：

 1. 动态堆栈数组。 
2. 最小堆，存储未满的堆栈索引。 

堆允许我们快速检索可用容量最小的索引。 

对于最右边的非空堆栈，我们维护 stacks 数组本身，并在必要时从末尾延迟删除空堆栈。 

重要的技巧是惰性清理。 

即使堆栈再次变满后，堆栈索引也可能保留在堆内。 我们不会主动删除无效的堆条目，而是在它们出现在堆顶部时将其丢弃。 

这提供了高效的操作：

 -`push`:`O(log n)`-`pop`: 摊销`O(1)`-`popAtStack`:`O(log n)`## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 每次操作 O(n) | O(n) | 重复扫描堆栈 |
 | 最佳| 每次操作 O(log n) | O(n) | 使用堆作为最左边的可用堆栈 |

 ## 算法演练

 1.初始化三个字段：

 -`capacity`，每个堆栈的最大大小。 
-`stacks`，包含所有堆栈数组的列表。 
-`available`，一个最小堆，存储未满的堆栈索引。 
2. 期间`push(val)`，首先清理无效的堆条目。 

堆中的一些索引可能指的是：

 - 不再存在的堆栈
 - 已经满的堆栈

 当堆顶无效时，将其删除。 
3. 如果清理后堆变空，则表明不存在具有可用空间的现有堆栈。 

最后创建一个新堆栈：```
stacks.append([])
```将其索引推入堆中，因为它最初有空间。 
4. 堆中最小的索引是最左边的可用堆栈。 

将值推入该堆栈。 
5. 插入后，如果堆栈已满，则从堆中删除其索引。 

这确保了未来的推送会跳过整个堆栈。 
6.期间`popAtStack(index)`，首先验证：

 - 索引存在
 - 堆栈不为空

 如果无效，返回`-1`。 
7. 从指定堆栈中弹出顶部值。 
8. 如果堆栈在弹出之前已满，则现在有可用空间。 

将其索引推入堆中。 
9. 出栈后，重复删除尾部的空栈`stacks`。 

这使得最右边的非空堆栈可以有效地访问。 
10.期间`pop()`，首先从末尾删除尾随的空堆栈。 
11. 如果没有剩余堆栈，则返回`-1`。 
12. 否则，执行`popAtStack`在最后一个堆栈上。 

### 为什么它有效

 核心不变量是：

 - 堆始终包含可能具有可用容量的索引。 
- 右侧`stacks`永远不会包含不必要的尾随空堆栈。 

堆保证我们总是推入最左边的非完整堆栈，因为它是按索引排序的最小堆。 

删除尾随的空堆栈可以保证最后一个堆栈`stacks`始终是最右边的非空堆栈。 

总之，这些属性完全符合问题的要求。 

## Python 解决方案```python
from typing import List
import heapq

class DinnerPlates:

    def __init__(self, capacity: int):
        self.capacity = capacity
        self.stacks: List[List[int]] = []
        self.available: List[int] = []

    def push(self, val: int) -> None:
        while self.available:
            index = self.available[0]

            if index >= len(self.stacks):
                heapq.heappop(self.available)
            elif len(self.stacks[index]) == self.capacity:
                heapq.heappop(self.available)
            else:
                break

        if not self.available:
            self.stacks.append([])
            heapq.heappush(self.available, len(self.stacks) - 1)

        index = self.available[0]
        self.stacks[index].append(val)

        if len(self.stacks[index]) == self.capacity:
            heapq.heappop(self.available)

    def pop(self) -> int:
        while self.stacks and not self.stacks[-1]:
            self.stacks.pop()

        if not self.stacks:
            return -1

        return self.popAtStack(len(self.stacks) - 1)

    def popAtStack(self, index: int) -> int:
        if index < 0 or index >= len(self.stacks):
            return -1

        if not self.stacks[index]:
            return -1

        was_full = len(self.stacks[index]) == self.capacity

        value = self.stacks[index].pop()

        if was_full:
            heapq.heappush(self.available, index)

        while self.stacks and not self.stacks[-1]:
            self.stacks.pop()

        return value
```实现严格遵循算法。 

这`stacks`list 显式存储每个堆栈。 每个堆栈本身只是一个 Python 列表。 

这`available`最小堆存储可能仍有空间的候选堆栈索引。 由于堆条目可能会随着时间的推移而变得陈旧，`push`操作在使用堆顶之前执行延迟清理。 

这`push`方法要么重用最左边的非完整堆栈，要么在必要时创建一个新堆栈。 

这`pop`方法在访问最右边的非空堆栈之前删除尾随的空堆栈。 

这`popAtStack`方法处理直接索引弹出，同时如果堆栈再次未满，还将堆栈索引恢复到堆。 

重复清理尾随空堆栈可确保未来高效`pop()`运营。 

## 解决方案```go
package main

import (
	"container/heap"
)

type MinHeap []int

func (h MinHeap) Len() int {
	return len(h)
}

func (h MinHeap) Less(i, j int) bool {
	return h[i] < h[j]
}

func (h MinHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MinHeap) Push(x interface{}) {
	*h = append(*h, x.(int))
}

func (h *MinHeap) Pop() interface{} {
	old := *h
	n := len(old)
	val := old[n-1]
	*h = old[:n-1]
	return val
}

type DinnerPlates struct {
	capacity int
	stacks   [][]int
	available MinHeap
}

func Constructor(capacity int) DinnerPlates {
	h := MinHeap{}
	heap.Init(&h)

	return DinnerPlates{
		capacity: capacity,
		stacks:   [][]int{},
		available: h,
	}
}

func (this *DinnerPlates) Push(val int) {
	for this.available.Len() > 0 {
		index := this.available[0]

		if index >= len(this.stacks) {
			heap.Pop(&this.available)
		} else if len(this.stacks[index]) == this.capacity {
			heap.Pop(&this.available)
		} else {
			break
		}
	}

	if this.available.Len() == 0 {
		this.stacks = append(this.stacks, []int{})
		heap.Push(&this.available, len(this.stacks)-1)
	}

	index := this.available[0]
	this.stacks[index] = append(this.stacks[index], val)

	if len(this.stacks[index]) == this.capacity {
		heap.Pop(&this.available)
	}
}

func (this *DinnerPlates) Pop() int {
	for len(this.stacks) > 0 && len(this.stacks[len(this.stacks)-1]) == 0 {
		this.stacks = this.stacks[:len(this.stacks)-1]
	}

	if len(this.stacks) == 0 {
		return -1
	}

	return this.PopAtStack(len(this.stacks) - 1)
}

func (this *DinnerPlates) PopAtStack(index int) int {
	if index < 0 || index >= len(this.stacks) {
		return -1
	}

	if len(this.stacks[index]) == 0 {
		return -1
	}

	wasFull := len(this.stacks[index]) == this.capacity

	stack := this.stacks[index]
	value := stack[len(stack)-1]

	this.stacks[index] = stack[:len(stack)-1]

	if wasFull {
		heap.Push(&this.available, index)
	}

	for len(this.stacks) > 0 &&
		len(this.stacks[len(this.stacks)-1]) == 0 {
		this.stacks = this.stacks[:len(this.stacks)-1]
	}

	return value
}
```Go 版本遵循与 Python 实现相同的逻辑，但 Go 需要使用显式堆实现`container/heap`包裹。 

堆栈使用切片的切片来表示：```go
[][]int
```与Python内置的不同`heapq`，Go需要实现堆接口方法，例如`Len`,`Less`,`Swap`,`Push`， 和`Pop`。 

切片操作大量用于堆栈压入和弹出行为。

 ## 边缘情况

 当多次出栈操作后所有堆栈都变空时，就会出现一种重要的边缘情况。 幼稚的实现可能会在数组末尾留下许多空堆栈，从而导致未来`pop()`重复扫描无用堆栈的操作。 此实现不断删除尾随的空堆栈，确保最右边的堆栈始终有意义。 

另一种微妙的情况发生在`popAtStack`在中间创建一个洞。 未来的推送必须在右侧创建新堆栈之前重用该堆栈。 最小堆保证始终首先选择最小的可用索引。 

第三个棘手的情况涉及陈旧的堆条目。 假设一个堆栈索引被添加到堆中，因为它变得未满，但后来在该堆条目被删除之前再次变满。 如果不进行清理，未来的推送可能会错误地瞄准整个堆栈。 该实现使用惰性删除解决了这个问题，在每次推送操作之前重复丢弃无效的堆条目。
