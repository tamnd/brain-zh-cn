[LeetCode 第 1129 题](https://leetcode.com/problems/shortest-path-with-alternating-colors/)

 **难度：** 🟡 中等
 **主题：** 广度优先搜索、图论

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个有向图`n`节点标记为`0`到`n - 1`。 图中的每条边都有一种颜色，红色或蓝色。 该图使用两个单独的边列表表示：

 -`redEdges`，包含所有红色有向边
 -`blueEdges`，包含所有蓝色有向边

 我们需要计算从节点开始的最短路径`0`到每个其他节点，但有一个附加约束：路径中的连续边必须交替颜色。 

这意味着：

 - 如果前一个边缘是红色，则下一个边缘必须是蓝色
 - 如果前一个边缘是蓝色，则下一个边缘必须是红色

 路径长度是使用的边数。 

输出是一个数组`answer`在哪里：

-`answer[i]`是从节点开始的最短有效交替颜色路径的长度`0`到节点`i`- 如果不存在有效路径，则该值应该是`-1`一个非常重要的细节是起始节点没有传入边，因此第一个边可以是红色或蓝色。 

限制相对较小：

 -`n <= 100`- 至多`400`红色边缘和`400`蓝色边缘

 这些限制表明，诸如广度优先搜索之类的图遍历算法已经足够高效。 

该图可能包含：

 - 自循环
 - 平行边缘
 - 周期

 如果未正确跟踪访问的状态，这些特征很容易创建无限遍历循环。 

这个问题的关键微妙之处在于，使用不同的最后边缘颜色到达同一节点代表不同的状态。 例如：

 - 到达节点`3`通过红边
 - 到达节点`3`通过蓝色边缘

 这些并不等同，因为它们影响接下来可以采用哪些边。 

仅跟踪访问过的节点的幼稚实现将错误地修剪有效路径。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试探索从节点开始的所有可能的交替颜色路径`0`。 

一种可能的实现将使用深度优先搜索并递归地尝试每个有效的交替边缘序列。 对于每个节点，我们可以跟踪迄今为止发现的最短有效路径。 

这种方法是正确的，因为它最终枚举了每个交替路径配置。 然而，在具有循环和许多分支可能性的图中，它变得极其低效。 

由于该图可能包含循环和重复状态，因此可能的交替路径的数量可以呈指数增长。 即使进行了剪枝，DFS 也会反复探索冗余状态。 

因此，暴力方法是不切实际的。 

### 最佳方法

 关键的观察结果是，这本质上是未加权图上的最短路径问题。 

每当我们需要未加权图中的最短边数时，广度优先搜索通常是正确的工具，因为 BFS 逐级探索节点。 

然而，我们必须稍微重新定义“国家”的含义。 

通常，BFS 状态仅包含：```
(node)
```但在这里，未来移动的合法性取决于先前使用的边的颜色。 

因此，真实状态变为：```
(node, last_edge_color)
```这使我们能够区分：

 - 到达节点`u`通过红边
 - 到达节点`u`通过蓝色边缘

 从一个州：```
(node, RED)
```我们只能遍历蓝色边缘。 

从：```
(node, BLUE)
```我们只能遍历红色边缘。 

BFS 保证我们第一次到达某个状态时，就找到了到达该状态的最短路径。

 ## 算法演练

 1. 构建两个邻接表，一个用于红边，一个用于蓝边。 

我们通过颜色分隔边，因为遍历规则取决于前一个边的颜色。 这使得仅检索允许的下一个边缘变得容易。 
2. 初始化结果数组。 

从以下开始：```
result = [-1] * n
```到节点的最短距离`0`总是`0`。 
3. 初始化BFS队列。 

由于第一步可能会使用任一颜色，因此我们以两种状态开始 BFS：

 -`(0, RED)`-`(0, BLUE)`这些代表我们当前处于节点`0`，并且下一条边必须是相反的颜色。 
4. 维护一个已访问集。 

访问的状态必须包括：

 - 当前节点
 - 先前的边缘颜色

 否则，我们可能会错误地跳过有效的替代路径。 
5. 执行水平顺序 BFS。 

BFS 自然地按长度递增的顺序探索路径。 

对于每个州：

 - 如果前一条边是红色，则探索蓝色邻居
 - 如果前一条边是蓝色，则探索红色邻居
 6. 更新最短距离。 

我们第一次遇到节点时保证是最短的交替路径长度，因为 BFS 按距离递增的顺序处理状态。 
7. 继续，直到队列变空。 

任何仍被标记的节点`-1`在交替颜色约束下是无法到达的。 

### 为什么它有效

 广度优先搜索保证了未加权图中的最短路径，因为节点是逐级探索的。 

通过扩展 BFS 状态以包含之前的边缘颜色，我们可以正确地对交替约束进行建模。 每个 BFS 层对应于相等长度的路径，因此第一次到达节点表示到达该节点的最短交替路径。 

## Python 解决方案```
from collections import deque, defaultdict
from typing import List

class Solution:
    def shortestAlternatingPaths(
        self,
        n: int,
        redEdges: List[List[int]],
        blueEdges: List[List[int]]
    ) -> List[int]:

        RED = 0
        BLUE = 1

        red_graph = defaultdict(list)
        blue_graph = defaultdict(list)

        for src, dst in redEdges:
            red_graph[src].append(dst)

        for src, dst in blueEdges:
            blue_graph[src].append(dst)

        result = [-1] * n
        result[0] = 0

        queue = deque([
            (0, RED),
            (0, BLUE)
        ])

        visited = {
            (0, RED),
            (0, BLUE)
        }

        distance = 0

        while queue:

            level_size = len(queue)

            for _ in range(level_size):

                node, prev_color = queue.popleft()

                if result[node] == -1:
                    result[node] = distance

                if prev_color == RED:
                    next_neighbors = blue_graph[node]
                    next_color = BLUE
                else:
                    next_neighbors = red_graph[node]
                    next_color = RED

                for neighbor in next_neighbors:

                    state = (neighbor, next_color)

                    if state in visited:
                        continue

                    visited.add(state)
                    queue.append(state)

            distance += 1

        return result
```实现首先构建两个邻接表：

 -`red_graph`-`blue_graph`按颜色分隔图可以简化遍历，因为我们可以根据先前使用的边缘颜色直接选择正确的邻居列表。 

BFS队列存储元组：```
(node, previous_color)
```这是至关重要的，因为使用不同的传入边缘颜色到达同一节点会产生不同的未来可能性。 

队列在节点处用两种颜色初始化`0`。 这有效地允许第一个真实边缘为红色或蓝色。 

这`visited`set 可以防止重新访问相同的状态并避免循环图中的无限循环。 

BFS 逐级进行。 每个BFS级别对应路径长度`distance`。 

对于每个州：

 - 如果前一条边是红色的，我们只能遍历蓝色边
 - 如果前一条边是蓝色的，我们只能遍历红色边

 每当第一次发现一个节点时，我们都会记录它的最短距离。 

## 解决方案```
package main

import "container/list"

func shortestAlternatingPaths(n int, redEdges [][]int, blueEdges [][]int) []int {

	const (
		RED  = 0
		BLUE = 1
	)

	redGraph := make([][]int, n)
	blueGraph := make([][]int, n)

	for _, edge := range redEdges {
		src, dst := edge[0], edge[1]
		redGraph[src] = append(redGraph[src], dst)
	}

	for _, edge := range blueEdges {
		src, dst := edge[0], edge[1]
		blueGraph[src] = append(blueGraph[src], dst)
	}

	result := make([]int, n)

	for i := range result {
		result[i] = -1
	}

	result[0] = 0

	type State struct {
		node      int
		prevColor int
	}

	queue := list.New()

	queue.PushBack(State{0, RED})
	queue.PushBack(State{0, BLUE})

	visited := make(map[[2]int]bool)

	visited[[2]int{0, RED}] = true
	visited[[2]int{0, BLUE}] = true

	distance := 0

	for queue.Len() > 0 {

		levelSize := queue.Len()

		for i := 0; i < levelSize; i++ {

			front := queue.Front()
			queue.Remove(front)

			current := front.Value.(State)

			node := current.node
			prevColor := current.prevColor

			if result[node] == -1 {
				result[node] = distance
			}

			var neighbors []int
			var nextColor int

			if prevColor == RED {
				neighbors = blueGraph[node]
				nextColor = BLUE
			} else {
				neighbors = redGraph[node]
				nextColor = RED
			}

			for _, neighbor := range neighbors {

				stateKey := [2]int{neighbor, nextColor}

				if visited[stateKey] {
					continue
				}

				visited[stateKey] = true

				queue.PushBack(State{
					node:      neighbor,
					prevColor: nextColor,
				})
			}
		}

		distance++
	}

	return result
}
```Go 实现密切反映了 Python 逻辑。 

Go 没有使用 Python 元组，而是使用`State`存储 BFS 状态信息的结构体。 

队列是使用以下方式实现的`container/list`，它为 BFS 遍历提供了高效的前端移除。 

Go 没有像 Python 那样的原生元组哈希，因此访问的状态使用以下方式存储：```
map[[2]int]bool
```其中数组包含：```
[node, color]
```这提供了访问状态的高效且紧凑的表示。

 ## 边缘情况

 一种重要的边缘情况是仅包含一种颜色的边缘的图。 例如，如果每条边都是红色的，那么比一条边长的路径就变得不可能，因为需要交替颜色。 忽略颜色约束的幼稚 BFS 可能会错误地继续遍历。 该实现通过在每个步骤后显式切换所需的边缘颜色来正确处理此问题。 

另一个关键的边缘情况涉及循环和自循环。 考虑一个具有返回自身的边的节点或两个节点之间的红蓝循环。 如果不使用节点和颜色来跟踪访问过的状态，BFS 可能会无限期地重新访问状态。 该实现通过存储来避免这种情况`(node, color)`访问集中的对。 

当使用不同的传入颜色可到达同一节点时，会出现第三种微妙的边缘情况。 到达节点`u`通过红色边缘并不等于通过蓝色边缘到达它，因为下一个有效的移动不同。 仅按节点索引的简单访问数组会错误地丢弃有效的未来路径。 该解决方案正确地将这些视为单独的 BFS 状态。 

最后的边缘情况是起始节点本身。 由于最初没有使用任何边，因此第一步可以合法地使用任一颜色。 该实现通过插入两个初始 BFS 状态来处理此问题：```
(0, RED)
(0, BLUE)
```这有效地模拟了允许红色或蓝色作为路径中的第一个实际边缘。
