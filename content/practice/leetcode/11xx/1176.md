[LeetCode 第 1176 题](https://leetcode.com/problems/diet-plan-performance/)

 **难度：** 🟢简单
 **主题：** 数组、滑动窗口

 ## 解决方案

 ## 问题理解

 问题是要求我们根据卡路里消耗来模拟节食者在几天内的表现。 输入是一个数组`calories`在哪里`calories[i]`代表一天消耗的卡路里数`i`。 我们还给出了三个整数：`k`,`lower`， 和`upper`。 对于每个连续序列`k`天，我们计算总热量`T`。 评分规则很简单：如果`T < lower`，节食者减1分； 如果`T > upper`，他们获得 1 分； 否则，积分不变。 目标是在评估所有可能的连续长度序列后计算总分`k`。 

约束表明`k`总是至少为 1，最多为卡路里数组的长度，其本身可以达到`10^5`。 每个卡路里计数都是非负的，并且以 20,000 为界。 这`lower`和`upper`阈值也是非负的并且`lower`不会超过`upper`。 这表明该解决方案必须有效地处理大型数组，而重新计算所有子数组之和的强力方法可能太慢。 要考虑的边缘情况包括非常小的数组，`k`等于数组长度、所有元素都相等的序列以及所有子数组恰好位于`lower`或者`upper`阈值。 

## 方法

 蛮力方法涉及迭代每个可能的长度子数组`k`并计算其总和。 计算总和后，将其与`lower`和`upper`相应地调整点。 虽然这种方法简单且正确，但效率低下，因为计算长度的总和`k`每个起始索引的子数组`i`需要 O(k) 时间。 对于 n 个元素，这会导致 O(n*k) 时间复杂度，对于 n 高达 100,000 来说这太慢了。 

优化的关键观察是我们可以维持长度的运行总和`k`使用滑动窗口。 我们不是从头开始重新计算每个子数组的总和，而是初始化第一个子数组的总和`k`元素，然后将窗口一次滑动一个元素：减去离开窗口的元素并添加进入窗口的元素。 这使得每次求和计算都可以在 O(1) 时间内完成，从而将整体复杂度降低到 O(n)。 该技术之所以适用，是因为连续子数组重叠显着，因此重用以前的计算非常有效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n*k) | O(1) | O(1) | 独立计算每个子数组的总和 |
 | 最佳| O(n) | O(1) | O(1) | 连续求和的滑动窗口方法 |

 ## 算法演练

 1.初始化两个变量：`points`为 0 以跟踪分数，并且`window_sum`为 0 来存储当前窗口大小的总和`k`。 
2. 计算第一个的总和`k`元素并将其存储在`window_sum`。 比较`window_sum`到`lower`和`upper`并调整`points`根据规则。 
3. 从索引开始在数组中滑动窗口`k`到最后。 对于进入窗口的每个新元素，将其添加到`window_sum`并减去离开窗口的元素（即`calories[i-k]`）。 
4.更新后`window_sum`，将其与`lower`和`upper`。 如果`window_sum < lower`, 递减`points`1. 如果`window_sum > upper`, 增量`points`1. 否则，什么也不做。 
5. 继续，直到窗口到达数组末尾。 
6. 返回最终结果`points`价值。 

为什么它有效：在每一步，窗口总和准确地表示`k`连续几天。 滑动窗口确保每个可能的长度子数组`k`只评估一次。 分数根据题目规则更新，所以最终`points`值保证是正确的。 

## Python 解决方案```python
from typing import List

class Solution:
    def dietPlanPerformance(self, calories: List[int], k: int, lower: int, upper: int) -> int:
        points = 0
        window_sum = sum(calories[:k])
        
        if window_sum < lower:
            points -= 1
        elif window_sum > upper:
            points += 1
        
        for i in range(k, len(calories)):
            window_sum += calories[i] - calories[i - k]
            if window_sum < lower:
                points -= 1
            elif window_sum > upper:
                points += 1
        
        return points
```该实现初始化了`points`计数器并计算第一个的初始总和`k`天。 然后它在数组中滑动窗口，在 O(1) 时间内更新每个新位置的总和。 每次窗口更新后立即调整分数，确保最终分数准确反映所有长度的子数组`k`。 

## 解决方案```go
func dietPlanPerformance(calories []int, k int, lower int, upper int) int {
    points := 0
    windowSum := 0
    
    for i := 0; i < k; i++ {
        windowSum += calories[i]
    }
    
    if windowSum < lower {
        points--
    } else if windowSum > upper {
        points++
    }
    
    for i := k; i < len(calories); i++ {
        windowSum += calories[i] - calories[i-k]
        if windowSum < lower {
            points--
        } else if windowSum > upper {
            points++
        }
    }
    
    return points
}
```Go 实现镜像了 Python 版本。 Go 处理切片的方式与 Python 列表类似，因此滑动窗口逻辑是相同的。 没有关于 nil 切片的问题，因为问题保证了`k >= 1`。 由于限制，整数溢出不是问题`calories[i]`和`k`。

 | 测量 | 复杂性 | 说明|
