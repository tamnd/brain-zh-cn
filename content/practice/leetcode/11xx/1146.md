[LeetCode 第 1146 题](https://leetcode.com/problems/snapshot-array/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、二分搜索、设计

 ## 解决方案

 ## 问题理解

 这个问题要求我们实现一个`SnapshotArray`，一种数据结构，其行为类似于数组，但也允许随时拍摄其状态快照并检索特定快照中任何元素的值。 具体来说，数据结构需要支持三种操作：`set(index, val)`,`snap()`， 和`get(index, snap_id)`。 最初，数组的所有元素均为零。 当我们打电话时`snap()`，它返回一个唯一的`snap_id`标识数组的当前状态。 之后，`get(index, snap_id)`允许我们查询拍摄快照时该索引的值是什么。 

输入表示 SnapshotArray 的命令和参数。 输出代表一个`snap_id`（为了`snap`）或特定快照的特定索引处的值（对于`get`）。 约束告诉我们，数组可以相当大（最多 50,000 个元素），并且操作数量也最多可以达到 50,000 个。 这意味着为每个快照存储阵列的完整副本的简单解决方案将太慢并且占用大量内存。 

重要的边缘情况包括多个`set`在 a 之前对同一索引进行操作`snap`,`get`调用在查询索引处没有更改的快照，并查询第一个快照。 该问题保证了有效的索引和`snap_id`s，所以我们不需要处理越界错误。 

## 方法

 暴力方法将涉及每次存储数组的完整副本`snap()`被称为。 这保证了正确性，因为我们可以直接返回任何快照中任何索引的值，但它的速度非常慢并且消耗 O(n * m) 内存，其中 n 是数组长度，m 是快照数量。 对于最大约束，这可能会在内存中使用数十亿个整数。 

最佳解决方案利用了大多数元素在连续快照之间不会发生变化的观察结果。 我们可以存储每个索引的更改历史记录，而不是存储每个快照的完整数组。 我们维护一个列表`(snap_id, value)`每个索引对。 什么时候`get`被调用，我们在更改列表中执行二分搜索以查找最大的`snap_id`不超过要求的一项。 这减少了内存使用并允许高效检索。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 每次快照 O(n)，每次获取 O(1) | O(n * m) | 存储每个快照的完整阵列 |
 | 最佳 | 每次获取 O(log s)，每次设置/捕捉 O(1) | O(n + k) | 仅存储每个索引的更改； 使用二分搜索进行查询 |

 这里，s是特定索引的快照数量，k是更改总数。 

## 算法演练

 1. 初始化一个列表列表，其中每个元素对应于数组中的一个索引。 每个索引包含一个列表`(snap_id, value)`对。 最初，所有列表都包含`(0, 0)`来表示起始值。 
2. 维持`current_snap_id`计数器从 0 开始。该计数器每次增加 1`snap()`被称为。 
3.为了`set(index, val)`, 附加`(current_snap_id, val)`到该索引的列表，但前提是最后记录的`snap_id`不等于`current_snap_id`以避免重复输入。 
4. 对于`snap()`，返回当前的`snap_id`并将计数器加 1。 
5. 对于`get(index, snap_id)`，在更改列表中对指定索引执行二分查找以查找最大的`snap_id`小于或等于要求的`snap_id`。 返回对应的值。 

这种方法之所以有效，是因为列表`(snap_id, value)`每个索引的对总是按以下顺序排序`snap_id`。 通过仅存储更改，我们可以显着减少内存使用量。 二分查找保证每个的查找时间为 O(log s)`get`。 

## Python 解决方案```python
from bisect import bisect_right

class SnapshotArray:

    def __init__(self, length: int):
        self.data = [[(0, 0)] for _ in range(length)]
        self.snap_id = 0

    def set(self, index: int, val: int) -> None:
        if self.data[index][-1][0] == self.snap_id:
            self.data[index][-1] = (self.snap_id, val)
        else:
            self.data[index].append((self.snap_id, val))

    def snap(self) -> int:
        current = self.snap_id
        self.snap_id += 1
        return current

    def get(self, index: int, snap_id: int) -> int:
        arr = self.data[index]
        i = bisect_right(arr, (snap_id, float('inf'))) - 1
        return arr[i][1]
```在这个实现中，`data`存储每个索引的历史记录。 这`set`方法避免了相同的重复条目`snap_id`。 这`snap`方法返回当前`snap_id`并增加它。 这`get`方法用途`bisect_right`有效地定位正确的快照。 

## 解决方案```go
import "sort"

type pair struct {
    snapID int
    val    int
}

type SnapshotArray struct {
    data   [][]pair
    snapID int
}

func Constructor(length int) SnapshotArray {
    data := make([][]pair, length)
    for i := 0; i < length; i++ {
        data[i] = []pair{{0, 0}}
    }
    return SnapshotArray{data: data, snapID: 0}
}

func (this *SnapshotArray) Set(index int, val int) {
    arr := this.data[index]
    if arr[len(arr)-1].snapID == this.snapID {
        arr[len(arr)-1].val = val
    } else {
        this.data[index] = append(arr, pair{this.snapID, val})
    }
}

func (this *SnapshotArray) Snap() int {
    current := this.snapID
    this.snapID++
    return current
}

func (this *SnapshotArray) Get(index int, snap_id int) int {
    arr := this.data[index]
    i := sort.Search(len(arr), func(i int) bool { return arr[i].snapID > snap_id })
    return arr[i-1].val
}
```在 Go 中，我们使用`pair`结构体来存储`(snapID, val)`对于每个索引。`sort.Search`相当于Python的`bisect_right`。 我们小心地处理切片，确保不修改现有快照。 

## 工作示例

 对于输入`["SnapshotArray","set","snap","set","get"]`有参数`[[3],[0,5],[],[0,6],[0,0]]`:

 | 运营| 快照 ID | 数据状态 |
 | ---| ---| ---|
 | 快照数组(3) | 0 | [[(0,0)]、[(0,0)]、[(0,0)]] |
 | 设置(0,5) | 0 | [[(0,5)]、[(0,0)]、[(0,0)]] |
 | 快照（）| 0 | [[(0,5)]、[(0,0)]、[(0,0)]] |
 | 设置 (0,6) | 1 | [[(0,5),(1,6)], [(0,0)], [(0,0)]] |
 | 得到(0,0) | 0 | 返回 5（索引 0 的最大 snap_id ≤ 0 为 0）|

 ## 复杂度分析

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | 每次获取 O(log s)，每次设置/捕捉 O(1) | 对变更列表进行二分查找以获取； set 和 snap 是常数 |
 | 空间| O(n + k) | 存储初始状态以及所有更改； n 是数组长度，k 是集合操作总数 |

 原因是每个索引仅存储更改，而不存储完整数组。 二分查找可确保高效查找。
