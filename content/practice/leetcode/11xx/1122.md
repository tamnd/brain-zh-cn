[LeetCode 第 1122 题](https://leetcode.com/problems/relative-sort-array/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表、排序、计数排序

 ## 解决方案

 ## 问题理解

 这个问题要求我们排序`arr1`，但不是普通的升序或降序。 相反，排序顺序部分由另一个数组决定，`arr2`。 

关键要求是出现在的每个数字`arr2`必须出现在`arr1`以完全相同的相对顺序。 如果一个数字多次出现`arr1`，它的所有出现应该按照定义的顺序分组在一起`arr2`。 

例如，如果`arr2 = [2,1,4,3,9,6]`，那么所有`2`进入`arr1`必须首先出现，然后是所有`1`s，则所有`4`s，则所有`3`s，等等。 出现的次数必须保持不变。 

将出现的所有数字放入后`arr2`, 中的任何剩余数字`arr1`未列出的`arr2`应按正常升序附加到末尾。 

输入由两个整数数组组成：

 -`arr1`，我们必须重新排列数组。 
-`arr2`，它定义了自定义排序。 

该问题保证了几个重要的性质。 中的每个元素`arr2`是不同的，意味着排序数组中不会出现重复项。 另外，中的每个元素`arr2`保证存在于`arr1`，所以我们永远不需要担心缺失值。 

限制相对较小：

 - 两个数组最多有`1000`元素。 
- 值的范围介于`0`和`1000`。 

这些限制表明，即使是效率较低的方法也可能会通过，但有机会利用小值范围来获得更清洁、更有效的解决方案。 

一些边缘情况值得尽早识别。`arr1`可能包含许多重复值，因此频率跟踪很重要。`arr2`可能涵盖几乎所有`arr1`，只留下一些剩余元素进行排序。 在另一种情况下，`arr2`可能只覆盖一小部分`arr1`，这意味着许多元素需要按升序附加。 我们还需要正确处理不在其中的重复值`arr2`。 

## 方法

 ### 蛮力方法

 一个简单的方法是反复扫描`arr1`对于每个数字`arr2`。 

对于每个数字`arr2`，我们遍历`arr1`并将所有匹配元素收集到结果中。 处理完每个值后`arr2`，我们扫描`arr1`再次收集不存在的元素`arr2`，对这些剩余的内容进行排序，然后附加它们。 

这是有效的，因为它明确强制执行由`arr2`。 每个匹配的元素都按所需的顺序聚集，所有剩余的数字分别排序。 

然而，这种方法会执行不必​​要的重复扫描`arr1`。 如果`arr2`有长度`m`和`arr1`有长度`n`，我们可以扫描整个数组`m`次，导致`O(n × m)`时间复杂度。 虽然对于给定的约束是可以接受的，但与可能的情况相比，它的效率较低。 

### 最佳解决方案的关键见解

 重要的观察是我们只关心每个数字出现的次数。 

由于值被限制在范围内`[0, 1000]`，我们可以统计其中每个数字出现的频率`arr1`。 一旦我们知道每个值出现了多少次，构建答案就变得很简单。 

我们首先处理数字`arr2`命令。 对于每个数字，我们将其附加到结果中的次数取决于其频率所指示的次数。 

之后，我们迭代所有可能的值`0`到`1000`。 任何剩余频率对应于未包含在中的数字`arr2`，然后我们按升序附加它们。 

这种方法避免了重复扫描并自然地保留了所需的顺序。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n × m + n log n) | O(n × m + n log n) | O(n) | 反复扫描`arr1`，然后对剩菜进行分类 |
 | 最佳 | O(n + k) | O(k) | 使用计数排序思想，其中`k = 1001`|

 这里，`n = len(arr1)`和`k = 1001`，最大可能值范围。 

## 算法演练

 1.创建大小为的频率数组`1001`，初始化为`0`。 由于值保证介于`0`和`1000`，我们可以直接使用每个值作为索引。 
2. 遍历`arr1`并计算每个数字出现的次数。 对于每个数字`x`, 增量`frequency[x]`。 
3. 初始化一个空结果数组。 
4. 处理每个数字`arr2`为了。 对于每个数字：

 - 查找其频率。 
- 将该数字附加到结果中多次。 
- 将其频率重置为`0`所以以后就不再处理了。 
5. 迭代每个值`0`到`1000`。 

- 如果一个值仍然具有正频率，则意味着它不存在于`arr2`。 
- 根据计数将其附加到结果中。 
6. 返回完成的结果数组。 

### 为什么它有效

 该算法之所以有效，是因为它将元素分为两类。 出现在的数字`arr2`首先发出，并且完全按照由`arr2`。 它们的多样性通过频率计数得以保留。 任何不在其中的数字`arr2`保留在频率阵列中，并稍后按递增的数字顺序发射。 由于每个元素都完全按照问题规则进行处理，因此保证了最终数组的正确性。 

## Python 解决方案```python
from typing import List

class Solution:
    def relativeSortArray(self, arr1: List[int], arr2: List[int]) -> List[int]:
        frequency = [0] * 1001

        # Count occurrences of each number
        for number in arr1:
            frequency[number] += 1

        result = []

        # Add numbers according to arr2 order
        for number in arr2:
            result.extend([number] * frequency[number])
            frequency[number] = 0

        # Add remaining numbers in ascending order
        for number in range(1001):
            if frequency[number] > 0:
                result.extend([number] * frequency[number])

        return result
```实现首先创建一个固定大小的频率数组。 因为约束将值限制为`0`通过`1000`，直接索引到数组比使用哈希映射更有效。 

第一个循环计算每个数字出现的次数`arr1`。 这将问题从重新排列元素转变为根据频率重建它们。 

第二个循环处理`arr2`按照所需的确切顺序。 对于每个数字，我们根据其计数将其附加多次。 将频率重置为`0`确保它不会在最后的上升过程中意外再次出现。 

最后，我们迭代自`0`到`1000`。 任何剩余的频率代表未包含在其中的数字`arr2`，因此按升序附加它们可以满足问题的第二个要求。 

## 解决方案```go
func relativeSortArray(arr1 []int, arr2 []int) []int {
	frequency := make([]int, 1001)

	// Count occurrences of each number
	for _, num := range arr1 {
		frequency[num]++
	}

	result := make([]int, 0, len(arr1))

	// Add numbers according to arr2 order
	for _, num := range arr2 {
		for frequency[num] > 0 {
			result = append(result, num)
			frequency[num]--
		}
	}

	// Add remaining numbers in ascending order
	for num := 0; num <= 1000; num++ {
		for frequency[num] > 0 {
			result = append(result, num)
			frequency[num]--
		}
	}

	return result
}
```Go 实现遵循与 Python 版本相同的逻辑，但在一些实现细节上有所不同。 由于 Go 不支持 Python 风格的列表乘法，因此使用循环添加重复元素。 结果切片已预先分配容量`len(arr1)`以减少重新分配。 因为整数仍然非常小并且受到约束的限制，所以整数溢出不是问题。

 ## 边缘情况

 当其中的每个元素都出现时，就会出现一个重要的边缘情况`arr1`已经代表在`arr2`。 在这种情况下，没有剩余元素需要排序。 有缺陷的实现可能会意外地重复值或附加不必要的元素。 此实现通过将频率重置为来避免该问题`0`处理完每个`arr2`值，确保以后不会重新添加任何内容。 

另一个重要的情况是当`arr1`包含许多重复值，尤其是中列出的数字的重复项`arr2`。 由于该问题需要保留多重性，因此忘记计算出现次数会产生错误的结果。 频率数组保证每个值添加的次数与其最初出现的次数完全相同。 

第三种边缘情况涉及允许范围边界处的值，特别是`0`和`1000`。 由于该算法使用频率数组索引，因此很容易出现相差一的错误。 该实现分配大小为的频率数组`1001`并包含迭代`0`到`1000`，确保安全正确地处理所有有效值。
