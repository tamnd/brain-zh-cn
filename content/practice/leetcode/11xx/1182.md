[LeetCode 第 1182 题](https://leetcode.com/problems/shortest-distance-to-target-color/)

 **难度：** 🟡 中等
 **主题：** 数组、二分查找、动态规划

 ## 解决方案

 ## 问题理解

 问题给了我们一个名为`colors`，其中每个位置包含三个可能值之一：`1`,`2`， 或者`3`。 每个值代表分配给该索引的颜色。 

我们还得到了一个查询列表。 每个查询包含两个整数：

 -`i`，起始索引
 -`c`，我们想要找到的目标颜色

 对于每个查询，我们必须确定索引之间的最小距离`i`以及数组中值等于的任何位置`c`。 

使用绝对指数差来测量距离：$$|i - j|$$在哪里`j`是一个索引，使得：$$colors[j] = c$$如果目标颜色不存在于数组中的任何位置，则该查询的答案是`-1`。 

例如，如果：```
colors = [1,1,2,1,3,2,2,3,3]
```查询是：```
[1,3]
```然后我们从索引开始`1`并搜索最近的`3`。 最接近的`3`出现在索引处`4`，所以距离为：$$|1 - 4| = 3$$约束条件很重要：

 -`colors.length`可以大到`5 * 10^4`-`queries.length`也可以大到`5 * 10^4`扫描整个数组以查找每个查询的简单解决方案可能需要：$$5 \times 10^4 \times 5 \times 10^4 = 2.5 \times 10^9$$在最坏的情况下，操作速度太慢了。 

只有三种可能的颜色这一事实强烈暗示预处理可以帮助我们有效地回答查询。 

一些边缘情况很重要：

 - 目标颜色可能根本不存在
 - 查询的索引本身可能已经包含目标颜色
 - 最接近的匹配颜色可能出现在左侧或右侧
 - 可能存在多次出现相同的颜色
 - 数组可能只包含一种不同的颜色

 正确的解决方案必须有效地处理所有这些问题。 

## 方法

 ### 蛮力方法

 最直接的方法是独立处理每个查询。 

对于每个查询`[i, c]`，我们扫描整个`colors`数组并查找值等于的索引`c`。 对于每个匹配索引，我们计算距离`i`并跟踪最小值。 

这种方法是正确的，因为它明确检查目标颜色的每个可能的候选位置。 由于计算了所有有效位置之间的最小距离，因此保证了结果的准确性。 

然而，这种方法效率低下。 如果有`n`元素和`q`查询，那么在最坏的情况下，我们对每个查询执行数组的完整扫描。 

复杂度变为：$$O(n \times q)$$两个值可能等于`5 * 10^4`，这太慢了。 

### 最佳方法，二分搜索预处理

 关键的观察是数组本身永远不会改变。 仅查询发生变化。 

我们可以预处理每种颜色的位置，而不是重复扫描数组。 

我们存储：

 - 所有包含颜色的索引`1`- 所有包含颜色的索引`2`- 所有包含颜色的索引`3`例如：```
colors = [1,1,2,1,3,2,2,3,3]
```变成：```
1 -> [0,1,3]
2 -> [2,5,6]
3 -> [4,7,8]
```现在每个查询变成：

 - 检索颜色位置的排序列表`c`- 使用二分查找来定位最接近索引的位置`i`由于位置自然地按排序顺序存储，二分搜索使我们能够有效地找到最近的候选者。 

对于每个查询，我们只需要检查：

 - 第一个位置大于或等于`i`- 紧接其之前的位置

 这两个中的一个必须包含最接近的事件。 

这减少了查询时间`O(n)`到`O(log n)`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n × q) | O(1) | O(1) | 扫描整个数组以查找每个查询 |
 | 最佳| O(n + q log n) | O(n + q log n) | O(n) | 使用二分搜索预处理索引并回答查询 |

 ## 算法演练

 1. 创建从每种颜色到该颜色出现的索引列表的映射。 

我们迭代通过`colors`数组一次。 对于每个索引，我们将索引附加到相应的颜色列表中。 

例子：```
colors = [1,1,2,1,3,2,2,3,3]
```产生：```
1 -> [0,1,3]
2 -> [2,5,6]
3 -> [4,7,8]
```这些列表会自动排序，因为我们从左到右遍历数组。 
2. 独立处理每个查询。 

对于查询`[i, c]`,检索颜色对应的索引列表`c`。 
3.处理颜色不存在的情况。 

如果列表为空，则追加`-1`到答案列表，因为不存在有效位置。 
4.使用二分查找来定位索引的插入位置`i`。 

我们使用二分搜索来查找位置列表中大于或等于的第一个索引`i`。 

认为：```
positions = [4,7,8]
i = 6
```二分查找返回位置`1`，对应值`7`。 
5. 检查右边的候选人。 

如果插入索引有效，则计算：```
abs(positions[idx] - i)
```6. 检查左边的候选人。 

最近的出现位置也可能紧邻插入点之前。 

如果`idx > 0`，计算：```
abs(positions[idx - 1] - i)
```7. 取有效距离的最小值。 

最近的出现必须是这两个邻居之一，因为列表已排序。 
8. 将结果附加到答案列表中。 
9. 处理完所有查询后，返回完整的结果列表。 

### 为什么它有效

 预处理步骤按排序顺序存储每种颜色的所有出现情况。 二分搜索确定查询索引在该排序顺序中适合的确切位置。 由于左侧的所有位置都较小，而右侧的所有位置都较大，因此最近的有效出现位置必须是插入位置或紧邻的前一个位置。 检查两者可确保找到最小可能距离。 

## Python 解决方案```python
from bisect import bisect_left
from collections import defaultdict
from typing import List

class Solution:
    def shortestDistanceColor(self, colors: List[int], queries: List[List[int]]) -> List[int]:
        color_positions = defaultdict(list)

        for index, color in enumerate(colors):
            color_positions[color].append(index)

        result = []

        for index, target_color in queries:
            positions = color_positions[target_color]

            if not positions:
                result.append(-1)
                continue

            insert_pos = bisect_left(positions, index)

            min_distance = float("inf")

            if insert_pos < len(positions):
                min_distance = min(
                    min_distance,
                    abs(positions[insert_pos] - index)
                )

            if insert_pos > 0:
                min_distance = min(
                    min_distance,
                    abs(positions[insert_pos - 1] - index)
                )

            result.append(min_distance)

        return result
```该实现首先构建一个字典，其中每种颜色映射到该颜色出现的索引列表。 由于数组是从左到右遍历的，因此索引会自动按排序顺序存储。 

对于每个查询，算法都会检索与目标颜色关联的位置列表。 如果列表为空，则数组中不存在目标颜色，因此`-1`立即附加。 

这`bisect_left`函数对已排序的位置列表执行二分搜索。 它返回可以插入查询索引的第一个位置，同时保留排序顺序。 

最接近的出现只能是：

 - 插入位置的元素
 - 紧邻其之前的元素

 该代码仔细检查两个候选者，同时确保索引保持在范围内。 

最小有效距离被附加到结果列表中，并在处理完所有查询后返回最终答案。 

## 解决方案```go
package main

import (
	"math"
	"sort"
)

func shortestDistanceColor(colors []int, queries [][]int) []int {
	colorPositions := make(map[int][]int)

	for index, color := range colors {
		colorPositions[color] = append(colorPositions[color], index)
	}

	result := make([]int, 0, len(queries))

	for _, query := range queries {
		index := query[0]
		targetColor := query[1]

		positions := colorPositions[targetColor]

		if len(positions) == 0 {
			result = append(result, -1)
			continue
		}

		insertPos := sort.SearchInts(positions, index)

		minDistance := math.MaxInt32

		if insertPos < len(positions) {
			distance := positions[insertPos] - index
			if distance < minDistance {
				minDistance = distance
			}
		}

		if insertPos > 0 {
			distance := index - positions[insertPos-1]
			if distance < minDistance {
				minDistance = distance
			}
		}

		result = append(result, minDistance)
	}

	return result
}
```Go 实现遵循与 Python 版本相同的算法结构。 

而不是Python的`bisect_left`, Go 使用`sort.SearchInts`，它对排序后的切片执行二分搜索。 

Go 切片自然地处理位置列表的动态存储。 由于索引始终为非负值并且受数组大小限制，因此这里不必担心整数溢出。 

实现使用`math.MaxInt32`作为最小距离的初始哨兵值。

 ## 边缘情况

 ### 目标颜色不存在

 当查询的颜色从未出现在数组中时，就会出现一个非常重要的边缘情况。 

例子：```
colors = [1,2]
query = [0,3]
```如果实现盲目地执行二分搜索而不检查位置列表是否为空，则可能会产生索引错误或不正确的答案。 

该解决方案通过检查来安全地处理这个问题：```
if not positions:
    result.append(-1)
```在任何二分查找发生之前。 

### 查询索引已包含目标颜色

 另一个重要的情况是当查询的索引本身已经具有所需的颜色时。 

例子：```
colors = [1,2,3]
query = [1,2]
```正确答案是`0`。 

二分搜索自然可以处理这个问题，因为插入位置直接指向查询的索引。 计算出的距离变为：```
abs(1 - 1) = 0
```这是可能的最小距离。 

### 最接近的匹配仅出现在一侧

 有时，最近的出现仅存在于左侧或仅存在于右侧。 

例子：```
positions = [2,5,8]
query index = 1
```没有有效的左候选人。 

相似地：```
positions = [2,5,8]
query index = 10
```没有有效的合适候选人。 

在这些情况下，不正确的实现通常会因越界访问而失败。 

该解决方案显式检查边界：```
if insert_pos < len(positions):
```和：```
if insert_pos > 0:
```在访问候选人之前，请确保这两种情况的正确性。
