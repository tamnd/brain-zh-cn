 # LeetCode 1110 - 删除节点并返回森林

 ## 问题理解

 这个问题给了我们二叉树的根和必须从树中删除的节点值列表。 树中的每个节点值都是唯一的，这很重要，因为这意味着我们可以直接通过值来识别节点而不会产生歧义。 

当一个节点被删除时，它就从树中完全删除了。 它的父级失去了与它的连接。 但是，被删除节点的子节点不会自动删除，除非它们的值也出现在`to_delete`。 如果这些孩子仍然有效，他们就会成为森林中的新根。 

最终的输出不是单个树，而是断开连接的树的集合。 这个集合称为森林。 在所有删除完成后，我们必须返回每个剩余树的根节点。 

例如，考虑这棵树：```
        1
      /   \
     2     3
    / \   / \
   4   5 6   7
```如果我们删除节点`3`和`5`:

 - 节点`3`被删除。 
- 它的孩子`6`和`7`没有被删除，所以它们成为新的根。 
- 节点`5`被删除。 
- 节点`1`保留原始树的根。 

由此产生的森林包含：```
    1         6       7
   /
  2
 /
4
```限制相对较小：

 - 至多`1000`节点
 - 节点值介于`1`和`1000`- 价值观不同

 由于树体较小，`O(n)`或者`O(n log n)`解决方案绰绰有余。 然而，我们仍然需要有效的遍历，因为重复搜索删除列表可能会变得不必要的昂贵。 

一些边缘情况很重要：

 - 根本身可能被删除。 
- 每个节点都可以被删除。 
- 不能删除任何节点。 
- 已删除的节点可能有幸存的子节点，这些子节点必须成为新的根。 
- 叶节点可以被删除。 
- 树可能高度不平衡。 

该问题保证了唯一的节点值，从而允许使用哈希集进行有效的查找。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是处理每个值`to_delete`一次一个。 对于每个删除值，我们可以遍历整个树来找到该节点及其父节点，断开该节点的连接，然后确定其子节点是否应该成为新的根。 

这是有效的，因为最终每个标记为删除的节点都会被正确删除。 然而，低效率来自于重复扫描树。 

如果有`n`节点和`d`删除值，我们最终可能会遍历树`d`次。 在最坏的情况下：

 -`n = 1000`-`d = 1000`这导致`O(n * d)`复杂度，变成`O(n²)`在最坏的情况下。 

尽管约束足够小，这仍然可以通过，但由于树结构在重复删除过程中会发生变化，因此正确实现效率低下且更加复杂。 

### 最佳方法

 关键的见解是删除自然适合后序树遍历。 

当决定是否删除一个节点时，我们首先需要知道它的子节点发生了什么。 如果删除了一个子节点，则当前节点指向该子节点的指针应变为`None`。 这意味着孩子必须在父母之前得到处理。 

这正是后序遍历的作用：

 1. 处理左子树
 2. 处理右子树
 3. 处理当前节点

 我们还使用哈希集`to_delete`所以会员资格检查是`O(1)`。 

DFS 期间：

 - 首先递归处理子项。 
- 递归后更新子指针。 
- 如果当前节点应该被删除：

 - 将幸存的孩子添加到森林中。 
- 返回`None`给家长。 
- 否则返回当前节点。 

最后，如果原来的根不被删除，它必须被包含在森林中。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(h) | 重复遍历树以进行每次删除 |
 | 最佳 | O(n) | O(h + d) | 带有哈希集查找的单次 DFS 遍历 |

 这里：

-`n`是节点数
 -`h`是树高
 -`d`的大小是`to_delete`## 算法演练

 1. 转换`to_delete`到一个哈希集中。 

我们需要经常检查一个节点是否应该被删除。 哈希集给出平均值`O(1)`查找时间，这比重复扫描列表要快得多。 
2. 创建一个名为的空结果列表`forest`。 

该列表存储删除后所有剩余树的根。 
3. 定义递归DFS 函数。 

DFS 函数处理子树并返回删除后更新的根。 
4. 递归处理左孩子。 

返回值可能是：

 - 原始子节点（如果存活）
 -`None`如果孩子被删除

 我们将这个返回值分配回`node.left`。 
5. 递归处理右孩子。 

相同的逻辑适用于右子树。 
6. 检查是否删除当前节点。 

如果`node.val`存在于删除集中：

 - 任何幸存的左孩子都会成为新的森林根。 
- 任何幸存的右孩子都会成为新的森林根。 
- 返回`None`所以父节点断开这个节点的连接。 
7. 如果当前节点未被删除，则返回节点本身。 

这保留了子树连接。 
8.用DFS处理原始根。 

返回的值告诉我们原始根是否存活。 
9. 如果根存活下来，将其添加到森林中。 

由于它没有父级，因此它仍然是有效的树根。 
10. 返回森林列表。 

### 为什么它有效

 该算法之所以有效，是因为后序遍历保证了子级在评估其父级之前已得到完全处理。 当我们决定是否删除节点时，我们已经知道：

 - 哪些孩子幸存下来
 - 哪些孩子被移除
 - 哪些孩子应该成为新根

 返回`None`从树中干净地删除已删除的节点，同时将幸存的子节点添加到森林中可以正确保留所有断开的子树。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

class Solution:
    def delNodes(self, root: Optional[TreeNode], to_delete: List[int]) -> List[TreeNode]:
        delete_set = set(to_delete)
        forest = []

        def dfs(node: Optional[TreeNode]) -> Optional[TreeNode]:
            if not node:
                return None

            node.left = dfs(node.left)
            node.right = dfs(node.right)

            if node.val in delete_set:
                if node.left:
                    forest.append(node.left)

                if node.right:
                    forest.append(node.right)

                return None

            return node

        root = dfs(root)

        if root:
            forest.append(root)

        return forest
```实现从转换开始`to_delete`到一个集合中以进行有效的查找。 这可以防止遍历过程中重复的线性搜索。 

递归`dfs`函数处理所有子树处理。 基本情况返回`None`当节点为空时。 

递归调用首先处理左子树和右子树。 它们的返回值被重新分配回`node.left`和`node.right`。 这很重要，因为删除的子项会返回`None`，有效地断开他们与父母的联系。 

处理完子节点后，算法检查是否应删除当前节点。 

如果必须删除节点：

 - 幸存的孩子被添加到森林中，因为他们成为独立的树木。 
- 函数返回`None`，向父节点发送信号以断开此节点的连接。 

如果节点存活，则原样返回。 

最后，DFS 完成后，仅当原始根仍然存在时才将其添加到林中。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func delNodes(root *TreeNode, to_delete []int) []*TreeNode {
    deleteSet := make(map[int]bool)

    for _, val := range to_delete {
        deleteSet[val] = true
    }

    forest := []*TreeNode{}

    var dfs func(node *TreeNode) *TreeNode

    dfs = func(node *TreeNode) *TreeNode {
        if node == nil {
            return nil
        }

        node.Left = dfs(node.Left)
        node.Right = dfs(node.Right)

        if deleteSet[node.Val] {
            if node.Left != nil {
                forest = append(forest, node.Left)
            }

            if node.Right != nil {
                forest = append(forest, node.Right)
            }

            return nil
        }

        return node
    }

    root = dfs(root)

    if root != nil {
        forest = append(forest, root)
    }

    return forest
}
```Go 实现遵循与 Python 版本相同的递归逻辑。 

Go 使用的不是 Python 集，而是`map[int]bool`用于恒定时间的成员资格检查。 

Go 使用`nil`而不是Python的`None`。 返回`nil`from DFS 断开已删除节点与其父节点的连接。 

切片使用动态扩展`append`，这就是林列表的维护方式。 

由于约束很小，因此递归深度在典型的 Go 堆栈限制内是安全的。

 ## 边缘情况

 ### 删除根节点

 当必须删除根本身时，就会出现最重要的边缘情况之一。 幼稚的实现可能会意外地失去对其余子树的访问。 

例如：```
    1
   / \
  2   3
```如果`1`被删除，那么`2`和`3`必须在森林里成为独立的根。 

该实现正确地处理了这个问题，因为当处理删除的节点时，任何幸存的子节点都会在返回之前立即添加到森林中`None`。 

### 删除每个节点

 当所有节点都被删除时，会出现另一个棘手的情况。 

例子：```
root = [1,2,3]
to_delete = [1,2,3]
```最后的森林应该是空的。 

有缺陷的实现可能会意外保留对已删除根的引用或将已删除节点追加到结果列表中。 

此解决方案避免了该问题，因为只有幸存的节点才会添加到林中。 由于每个 DFS 调用都会返回`None`，没有剩余节点。 

### 高度不平衡的树

 倾斜树的行为更像是链表：```
1
 \
  2
   \
    3
     \
      4
```如果递归后没有仔细更新子引用，递归树算法有时会在倾斜结构上失败。 

此实现正确地重新连接子树，因为每个递归调用都会返回更新的子树根。 无论子进程存活还是被删除，父进程始终会收到正确的更新指针。
