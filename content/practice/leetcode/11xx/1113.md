[LeetCode 第 1113 题](https://leetcode.com/problems/reported-posts/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 问题是要求我们确定**昨天**报告的帖子数量，并按报告原因分组。 我们被赋予了一个`Actions`表，其中每行代表用户对帖子执行的操作，操作类型记录在`action`列和可选的额外信息`extra`柱子。 在此背景下，一个`report`行动可能包括一个原因`extra`例如“垃圾邮件”或“种族主义”。 问题指定“今天”是`2019-07-05`，所以“昨天”指的是`2019-07-04`。 

输入表可能有多行用于同一帖子、同一用户或同一操作，这意味着存在重复项。 我们只关心`report`操作并需要计算每个操作有多少个报告`report_reason`在`2019-07-04`。 输出应该是一个包含两列的表：`report_reason`和`report_count`，仅包括至少一份报告的原因。 

要点和约束包括：表可能有重复项、同一帖子可能因同一原因有多个报告，以及`extra`对于除以下之外的操作，列可能为 NULL`report`。 要考虑的边缘情况包括同一用户出于同一原因多次报告的帖子、没有报告的天数以及多个报告原因。 

## 方法

 **暴力方法**是扫描整个`Actions`表，过滤行，其中`action = 'report'`和`action_date = '2019-07-04'`，并按原因手动聚合计数，例如使用 Python 字典或 SQL 分组依据。 这种方法可以正常工作，但如果表非常大，则扫描每一行然后在应用程序代码中进行处理的效率低于让数据库处理分组的效率。 

**最佳方法**利用 SQL 聚合：直接在 SQL 中过滤`report`目标日期的操作，分组依据`extra`（原因），并计算每组的行数。 这避免了手动聚合，减少了内存使用，并有效地使用数据库索引`action_date`或者`action`。 关键的见解是 SQL`GROUP BY`和`COUNT`自然地正确处理重复和聚合。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(r) | 迭代表中的所有行并根据原因手动计数 |
 | 最佳 | O(n) | O(r) | SQL GROUP BY 有效地处理过滤和计数，其中 n 是行数，r 是唯一原因的数量 |

 ## 算法演练

 1. 确定目标日期，相对于固定日期是昨天`2019-07-05`。 这是`2019-07-04`。 
2. 过滤`Actions`表仅选择其中的行`action = 'report'`和`action_date = '2019-07-04'`。 
3. 对筛选后的行进行分组`extra`，代表报告原因。 
4.对于每组，统计行数得到`report_count`。 
5. 返回一个表`report_reason`和`report_count`，仅包括至少一份报告的原因。 

**为什么有效：** 分组依据`extra`确保出于同一原因的所有报告都被统计在一起。 首先过滤可确保我们只计算相关报告。 使用 COUNT 保证我们可以处理每个用户的多个报告或正确发布。 

## Python 解决方案```python
import pandas as pd

class Solution:
    def reportedPosts(self, actions: pd.DataFrame) -> pd.DataFrame:
        # Step 1: Define yesterday's date
        yesterday = '2019-07-04'
        
        # Step 2: Filter rows where action is 'report' and date is yesterday
        reports = actions[(actions['action'] == 'report') & (actions['action_date'] == yesterday)]
        
        # Step 3: Group by report reason (extra) and count
        result = reports.groupby('extra').size().reset_index(name='report_count')
        
        # Step 4: Rename column to match expected output
        result.rename(columns={'extra': 'report_reason'}, inplace=True)
        
        return result
```Python 解决方案使用 Pandas 进行表操作。 首先，它过滤目标日期并`report`行动。 然后，`groupby('extra')`按报告原因汇总计数。 生成的 DataFrame 被重命名以匹配预期的输出列。 这直接在Python中实现了最优的类SQL聚合逻辑。 

## 解决方案```go
package main

import (
	"database/sql"
	"fmt"
)

func reportedPosts(db *sql.DB) ([]map[string]interface{}, error) {
	yesterday := "2019-07-04"
	query := `
		SELECT extra AS report_reason, COUNT(*) AS report_count
		FROM Actions
		WHERE action = 'report' AND action_date = ?
		GROUP BY extra
	`
	rows, err := db.Query(query, yesterday)
	if err != nil {
		return nil, err
	}
	defer rows.Close()

	var results []map[string]interface{}
	for rows.Next() {
		var reason string
		var count int
		if err := rows.Scan(&reason, &count); err != nil {
			return nil, err
		}
		results = append(results, map[string]interface{}{
			"report_reason": reason,
			"report_count":  count,
		})
	}
	return results, nil
}
```在 Go 中，我们直接对数据库执行 SQL 查询。 我们使用参数化查询来安全地按昨天的日期进行过滤。 这`rows.Scan`函数将 SQL 列映射到 Go 变量，为了灵活性，我们将结果存储在映射切片中。 Go 自动处理 SQL NULL，并且`COUNT(*)`确保我们正确计算重复项。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 我们扫描一次表格来过滤报告，然后按原因分组 |
