[LeetCode 第 1181 题](https://leetcode.com/problems/before-and-after-puzzle/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、字符串、排序

 ## 解决方案

 ## 问题理解

 该问题给了我们一个短语数组，其中每个短语都是由小写英文字母和空格组成的字符串。 每个短语的格式都正确，这意味着没有前导或尾随空格，也没有连续的空格。 

我们必须通过组合两个不同的短语来生成所有可能的“之前和之后”谜题。 当第一个短语的最后一个单词与第二个短语的第一个单词完全相同时，就会发生有效的合并。 

假设我们有：```
"writing code"
"code rocks"
```第一个短语的最后一个单词是`"code"`第二个短语的第一个单词也是`"code"`。 由于它们匹配，我们将它们合并为：```
"writing code rocks"
```重叠的单词在最终结果中只出现一次。 

顺序很重要。 如果短语`A`可以合并成短语`B`，这并不自动意味着`B`可以合并到`A`。 我们必须考虑每个有序对`(i, j)`在哪里`i != j`。 

最终答案必须满足两个附加要求：

 - 所有生成的谜题必须是不同的
 - 输出必须按字典顺序排序

 限制相对较小：

 - 最多 100 个短语
 - 每个短语长度最多100个字符

 这些限制告诉我们`O(n^2)`比较方法是完全可以接受的，因为`100^2 = 10,000`，它很小。 

一些边缘情况很重要：

 - 可能存在多个相同的短语
 - 不同的短语对可能会生成相同的合并结果
 - 允许使用单词短语
 - 一个短语只能与不同索引处的另一个短语合并，即使文本相同
 - 某些短语可能参与多次合并
 - 某些短语可能根本不参与任何合并

 简单的实现很容易在连接过程中产生重复项或错误地复制重叠的单词。 

## 方法

 ### 蛮力方法

 暴力解决方案检查每对有序短语`(i, j)`在哪里`i != j`。 

对于每对：

 1. 提取最后一个单词`phrases[i]`2. 提取第一个单词`phrases[j]`3.比较它们
 4. 如果匹配，则构建合并短语
 5. 将合并的短语插入集合中以删除重复项

 处理完所有对后，将集合转换为排序列表。 

这种方法是正确的，因为它明确地检查每个可能的有效配对。 由于该问题需要考虑所有有序对，因此详尽的检查保证不会遗漏有效的合并。 

缺点是我们反复分割短语并反复比较许多没有机会匹配的对。 

### 改进解决方案的关键见解

 重要的观察是短语仅在以下情况下才重要：

 - 他们的最后一个单词与另一个短语的第一个单词匹配

 我们可以按短语的第一个单词对短语进行分组，而不是盲目地比较每一对。 

我们构建一个哈希图：```
first_word -> list of phrase indices
```然后，对于每个短语：

 1. 提取最后一个单词
 2. 查找第一个单词与最后一个单词匹配的所有短语
 3. 仅为那些候选者生成合并

 这避免了不必要的比较，并使逻辑更清晰且更具可扩展性。 

尽管渐近复杂度仍然接近`O(n^2)`在最坏的情况下，哈希映射显着减少了实践中的浪费工作。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n² * L) | O(k) | 直接检查每对 |
 | 最佳| 最坏情况 | O(n² * L) O(n + k) | 使用哈希映射仅检查相关匹配项 |

 这里：

-`n`是短语的数量
 -`L`是平均短语长度
 -`k`是生成的不同谜题的数量

 ## 算法演练

 1. 创建一个哈希映射，按第一个单词对短语索引进行分组。 

对于每个短语，将其拆分为单词并提取第一个单词。 将短语索引存储在其中：```
first_word_map[first_word]
```这允许快速查找可能跟随另一个短语的所有短语。 
2. 创建一个空集来存储生成的谜题。 

集合会自动删除重复项，这是必需的，因为不同的短语对可能会产生相同的合并结果。 
3. 将每个短语作为第一个短语进行迭代。 

对于每个短语：

 - 把它分成单词
 - 提取最后一个单词
 4. 使用最后一个单词查找候选第二个短语。 

如果哈希图中存在最后一个单词，则与该单词关联的所有短语都是潜在匹配。 
5. 对于每个候选第二个短语：

 - 跳过索引相等的情况，因为`i != j`- 仔细合并短语

 假设：```
phrase1 = "writing code"
phrase2 = "code rocks"
```我们不希望：```
"writing code code rocks"
```相反，我们从第二个短语中删除重复的第一个单词，并仅附加剩余的后缀。 
6. 将合并的短语插入结果集中。 
7. 处理完所有短语后：

 - 将集合转换为列表
 - 按字典顺序排序
 - 返回排序后的列表

 ### 为什么它有效

 该算法之所以有效，是因为每个有效的谜题都必须满足一个条件：```
last_word(phrase1) == first_word(phrase2)
```哈希映射保证我们有效地找到满足此条件的每个短语。 由于每个有效的有序对都只被考虑一次，因此不会错过任何有效的谜题。 使用集合可以保证删除重复项。 最后，排序产生所需的字典顺序。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def beforeAndAfterPuzzles(self, phrases: List[str]) -> List[str]:
        first_word_map = defaultdict(list)

        # Map first word -> indices of phrases
        for index, phrase in enumerate(phrases):
            words = phrase.split()
            first_word = words[0]
            first_word_map[first_word].append(index)

        results = set()

        # Try every phrase as the first phrase
        for i, phrase1 in enumerate(phrases):
            words1 = phrase1.split()
            last_word = words1[-1]

            # Find phrases whose first word matches
            for j in first_word_map.get(last_word, []):
                if i == j:
                    continue

                phrase2 = phrases[j]
                words2 = phrase2.split()

                # Merge while avoiding duplicate overlap word
                merged = phrase1 + phrase2[len(words2[0]):]

                results.add(merged)

        return sorted(results)
```该实现首先构建一个哈希映射，该哈希映射根据短语索引的第一个单词对其进行分组。 此预处理步骤可实现稍后的高效查找。 

主循环将每个短语视为合并中潜在的第一个短语。 对于每个短语，我们提取其最后一个单词，并使用哈希映射来查找第一个单词匹配的候选第二个短语。 

合并操作很微妙。 我们没有从分割词中手动重建第二个短语，而是重复使用字符串切片：```python
phrase2[len(words2[0]):]
```这会从第二个短语中删除重叠的第一个单词，同时保留剩余单词之前的前导空格。 

例如：```python
phrase2 = "code rocks"
words2[0] = "code"
phrase2[4:] = " rocks"
```直接附加此后缀会创建正确的合并结果。 

该集合保证了唯一性，并且最终的排序转换满足字典顺序要求。 

## 解决方案```go
package main

import (
	"sort"
	"strings"
)

func beforeAndAfterPuzzles(phrases []string) []string {
	firstWordMap := make(map[string][]int)

	// Map first word -> indices
	for i, phrase := range phrases {
		words := strings.Split(phrase, " ")
		firstWord := words[0]
		firstWordMap[firstWord] = append(firstWordMap[firstWord], i)
	}

	results := make(map[string]bool)

	// Try every phrase as the first phrase
	for i, phrase1 := range phrases {
		words1 := strings.Split(phrase1, " ")
		lastWord := words1[len(words1)-1]

		candidates, exists := firstWordMap[lastWord]
		if !exists {
			continue
		}

		for _, j := range candidates {
			if i == j {
				continue
			}

			phrase2 := phrases[j]
			words2 := strings.Split(phrase2, " ")

			merged := phrase1 + phrase2[len(words2[0]):]
			results[merged] = true
		}
	}

	answer := make([]string, 0, len(results))

	for phrase := range results {
		answer = append(answer, phrase)
	}

	sort.Strings(answer)

	return answer
}
```Go 解决方案遵循与 Python 实现相同的算法结构。 

一个`map[string][]int`用于首字查找表。 由于 Go 没有内置的集合类型，因此使用以下方法实现唯一性：```go
map[string]bool
```字符串切片的工作方式与 Python 类似，因为 Go 字符串是字节切片。 由于该问题仅保证小写英文字母和空格，因此字节索引是安全的并且不存在 Unicode 问题。 

最终结果被收集到一个切片中并使用排序`sort.Strings`。

 ## 边缘情况

 当多个短语对生成相同的合并短语时，会出现一种重要的边缘情况。 例如：```
["a", "a"]
```两个都`(0,1)`和`(1,0)`产生`"a"`。 使用列表的简单实现会在最终答案中产生重复项。 此实现使用一个集合，它自动保证唯一性。 

另一个重要的边缘情况涉及单词短语。 考虑：```
["a", "a"]
```合并时，重叠的单词完全消耗掉第二个短语。 如果字符串连接实施不正确，可能会出现多余的空格或重复的单词。 切片方法正确地附加一个空后缀并生成`"a"`。 

第三个棘手的情况涉及具有不同索引的重复短语：```
["ab ba", "ba ab", "ab ba"]
```即使短语文本重复，索引仍然不同。 问题只是禁止`i == j`，内容不相同。 该实现正确地允许不同索引之间的合并，同时防止自合并。 

当根本不存在有效匹配时，就会出现最后的边缘情况。 在这种情况下，算法应该返回一个空列表而不是`None`或未排序的结构。 由于结果集只是保持为空，因此对其进行转换和排序自然会返回一个空列表。
