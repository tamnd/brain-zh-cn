 # LeetCode 1124 - 最长的良好表现间隔

 ## 问题理解

 问题给了我们一个数组`hours`，其中每个元素代表员工在特定日期的工作小时数。 如果员工工作**严格超过 8 小时**，一天就会被归类为**累**。 否则，这一天就被认为是**不累**。 

我们被要求找到**最长的连续间隔**，其中疲劳天数严格大于不疲劳天数。 换句话说，对于任意子数组`hours`，我们希望值的计数大于`8`超过小于或等于的值的计数`8`。 

思考这个问题的一个有用方法是将数组转换为评分系统。 每一天的劳累都在贡献`+1`，每一天不劳累的贡献`-1`。 一旦我们进行了这种转换，任务就变成了找到总和为**严格正**的最长子数组。 

例如：```
hours = [9,9,6,0,6,6,9]

Transformed:
[+1,+1,-1,-1,-1,-1,+1]
```间隔`[9,9,6]`变成：```
+1 +1 -1 = +1
```由于总和为正，因此该区间表现良好。 

约束条件告诉我们：

 -`1 <= hours.length <= 10^4`-`0 <= hours[i] <= 16`输入大小适中。 一个`O(n²)`在最坏的情况下解决方案可能太慢，因为`10^4² = 10^8`操作，这对于 LeetCode 时间限制来说通常太昂贵。 这强烈表明我们应该以`O(n)`或者`O(n log n)`解决方案。 

预先识别一些边缘情况很重要。 如果整天都不累的话答案应该是`0`因为任何间隔都不可能比不累的日子更累。 如果整天都累的话，整个数组都有效。 长度数组`1`还需要小心处理，因为一天可能会也可能不会成为表现良好的间隔。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每个可能的子数组并确定它是否形成性能良好的区间。 

我们首先对数组进行改造，让疲惫的日子变得`+1`不劳累的日子就变成了`-1`。 然后，对于每个可能的起始索引，我们迭代每个结束索引并计算子数组和。 如果总和为正，我们更新最大间隔长度。 

一个简单的实现会重新计算每个子数组的总和，从而导致`O(n³)`时间复杂度。 我们可以使用前缀和稍微改进这一点，允许在恒定时间内计算子数组和。 这将复杂性降低到`O(n²)`。 

尽管正确，但这种方法对于`n = 10^4`。 

### 最优方法，前缀和+最早出现哈希图

 关键的见解来自观察转换后的数组。 

每天转换后：

 -`hours[i] > 8`→`+1`-`hours[i] <= 8`→`-1`我们想要总和为**正**的最长子数组。 

让`prefixSum[i]`表示达到索引的累积分数`i`。 

如果在某个索引处前缀和已经为正，则从数组开头到当前索引的间隔自动有效。 

如果前缀和不是正数，我们需要找到一个更早的前缀和，该前缀和正好小`1`。 

为什么`prefix - 1`？ 

假设当前前缀和为`curr`。 

我们想要：```
curr - previousPrefix > 0
```这意味着：```
previousPrefix < curr
```由于前缀和仅改变`±1`，最早的有效候选者变为`curr - 1`。 

为了有效地找到这一点，我们将每个前缀和的**第一次出现**存储在哈希映射中。 保留最早出现的情况很重要，因为它可以最大化间隔长度。 

这给了我们一个线性时间的解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(n) | 使用前缀和来计算每个子数组 |
 | 最佳| O(n) | O(n) | 与最早出现的哈希映射的前缀和 |

 ## 算法演练

 1. 初始化运行前缀和`score = 0`, 一个变量`maxLength = 0`，和一个哈希图`firstSeen`。 
2. 从左到右遍历数组。 
3. 每天：

 - 如果`hours[i] > 8`， 添加`1`到分数。 
- 否则，减去`1`。 
4. 如果分数变为正数，则索引的整个区间`0`到`i`是有效的。 更新：```
maxLength = i + 1
```5. 如果以前从未见过该分数，则将其第一次出现存储在哈希映射中。 我们只存储最早出现的事件，因为较早的索引会产生较长的间隔。 
6. 如果分数不为正，请检查是否`score - 1`存在于哈希映射中。 

如果是，则意味着存在一个较早的前缀和，允许间隔和变为正值。 

计算：```
intervalLength = i - firstSeen[score - 1]
```更新最大答案。 
7. 继续，直到处理完所有元素。 
8. 返回`maxLength`。 

### 为什么它有效

 该算法依赖于前缀和。 索引之间的子数组和`l`和`r`等于：```
prefix[r] - prefix[l - 1]
```我们需要这种差异严格为正。 因此，我们搜索小于当前前缀和的最早的前一个前缀和。 因为前缀和仅改变`±1`, 检查`score - 1`就足够了。 通过存储每个前缀和的最早出现，我们保证每个端点的最长可能间隔。 

## Python 解决方案```python
from typing import List

class Solution:
    def longestWPI(self, hours: List[int]) -> int:
        first_seen = {}
        score = 0
        max_length = 0

        for index, hour in enumerate(hours):
            if hour > 8:
                score += 1
            else:
                score -= 1

            if score > 0:
                max_length = index + 1
            else:
                if score - 1 in first_seen:
                    max_length = max(
                        max_length,
                        index - first_seen[score - 1]
                    )

            if score not in first_seen:
                first_seen[score] = index

        return max_length
```该实现首先初始化一个名为的哈希图`first_seen`，它存储每个前缀分数出现的最早索引。 

当我们迭代数组时，每天都会贡献或者`+1`或者`-1`跑步分数取决于是否累。 

如果分数变为正数，则从数组开头到当前位置的间隔立即有效，因此我们更新最大长度。 

当分数为非正数时，我们检查是否`score - 1`之前已经出现过。 如果有，则最早出现的事件与当前索引之间的间隔必须为正数。 我们相应地更新答案。 

最后，我们仅在之前未见过的情况下存储分数。 保留最早出现的情况可确保最大间隔长度。 

## 解决方案```go
func longestWPI(hours []int) int {
	firstSeen := make(map[int]int)
	score := 0
	maxLength := 0

	for index, hour := range hours {
		if hour > 8 {
			score++
		} else {
			score--
		}

		if score > 0 {
			maxLength = index + 1
		} else {
			if firstIndex, exists := firstSeen[score-1]; exists {
				length := index - firstIndex
				if length > maxLength {
					maxLength = length
				}
			}
		}

		if _, exists := firstSeen[score]; !exists {
			firstSeen[score] = index
		}
	}

	return maxLength
}
```Go 实现遵循与 Python 解决方案完全相同的逻辑。 一个`map[int]int`用于存储每个前缀分数最早出现的时间。 

Go 切片天然处理动态数组，因此迭代逻辑没有区别。 整数溢出在这里不是一个问题，因为分数只能在`-n`和`n`， 在哪里`n <= 10^4`。 

与 Python 字典不同，Go 映射需要使用二值赋值模式进行显式存在检查：```go
value, exists := map[key]
```这在检查时都使用`score - 1`以及存储最早出现的前缀和时。

 ## 边缘情况

 ### 每一天都不累

 输入如下：```
[6,6,6,6]
```不包含劳累的日子。 每个变换后的值都变成`-1`，意味着每个前缀和都是负数。 一个幼稚的实现可能会意外地计算出相同的疲劳天数和不疲劳天数的间隔，但问题需要**严格更多**的疲劳天数。 执行正确返回`0`因为不存在正区间。 

### 每一天都很累

 对于输入：```
[9,9,9]
```每个变换后的值都变成`+1`。 由于运行分数始终保持正值，因此算法不断更新`maxLength`，最终返回整个数组长度。 

### 小时等于 8

 一个微妙的边缘情况是：```
[8,9,8]
```条件**严格大于8**，意思是`8`**不**累。 一个常见的错误是治疗`8`使用起来很累`>= 8`。 实现明确检查：```
hour > 8
```这保证了正确的分类。 

### 前缀和开始为负然后恢复

 考虑：```
[6,6,9,9,9]
```前缀和最初变为负值，然后最终变为正值。 天真的贪婪方法可能会失败，因为最佳间隔是在早期的负数日之后开始的。 通过存储最早出现的前缀和，即使恢复发生较晚，算法也能正确找到最长的有效间隔。
