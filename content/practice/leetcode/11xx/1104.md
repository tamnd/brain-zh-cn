[LeetCode 问题 1104](https://leetcode.com/problems/path-in-zigzag-labelled-binary-tree/)

 **难度：** 🟡 中等
 **主题：** 数学、树、二叉树

 ## 解决方案

 ## 问题理解

 该问题描述了一个无限二叉树，其中节点通常逐级排列，但标签的分配方式有所不同。 在标准二叉树中，每个级别中的节点从左到右进行标记。 这里，标签根据行号交替方向。 

奇数行（例如第 1 行、第 3 行和第 5 行）从左到右进行标记。 偶数行（例如第 2 行和第 4 行）从右到左进行标记。 

例如：

 - 第 1 行：`1`- 第 2 行：`3, 2`- 第 3 行：`4, 5, 6, 7`- 第 4 行：`15, 14, 13, 12, 11, 10, 9, 8`输入是单个整数`label`，表示此锯齿形标记树中某处节点的值。 任务是返回从根节点（`1`) 到该目标节点。 

例如，如果`label = 14`，答案是`[1, 3, 4, 14]`，因为锯齿形树中的父关系从节点引出`14`到`4`， 然后`3`，最后`1`。 

约束条件`1 <= label <= 10^6`告诉我们树的深度相当小。 由于每行的大小加倍，即使一百万也只能达到大约 20 个级别（`2^20 ≈ 10^6`）。 这强烈表明基于树高的对数解是合适的。 

预先识别一些边缘情况很重要。 最小可能的输入是`label = 1`，应该返回`[1]`立即地。 行边界附近的标签（例如 2 的幂）可能很棘手，因为之字形排序在行转换处精确翻转。 另一个微妙的情况涉及锯齿形标签和正常二叉树位置之间的转换，因为直接除以二并不总是在反向行中产生正确的父代。 

## 方法

 ### 蛮力方法

 强力解决方案将逐层显式构建树，直到到达目标标签。 由于树在从左到右和从右到左标记之间交替，因此需要仔细生成每个级别。 

在构建了足够的树以包含目标节点之后，我们可以在构建结构时维护父指针，并通过从目标追溯到根来重建路径。 

这种方法是正确的，因为它模拟了问题中描述的确切结构。 每个节点和父关系都被明确表示。 

然而，这种解决方案效率低下且不必要。 由于树呈指数增长，因此将所有节点构建为`10^6`标签既浪费时间又浪费内存。 我们只需要一条路径，而不是整棵树。 

### 最佳方法的关键见解

 关键的观察是完全二叉树中的父子关系已经很好理解了。 挑战只是锯齿形标签。 

如果我们临时将锯齿形标签转换为正常的从左到右二叉树中的等效标签，那么使用整数除以二即可轻松找到父级。 

对于任意行：

 - 最小标签为`2^(row-1)`- 最大标签为`2^row - 1`如果行反转，则可以使用以下方法将标签镜像到其正常位置：$$\text{normal} = \text{rowMin} + \text{rowMax} - \text{zigzag}$$同样，当向上移动到父级时，我们可以重复镜像并除以二。 

我们不构造树，而是简单地从目标节点向后计算到根，以数学方式计算每个父节点。

 ## 算法演练

 1. 确定目标标签的当前行。 

自行`r`包含来自的标签`2^(r-1)`到`2^r - 1`，我们重复加倍，直到找到包含的行`label`。 
2. 初始化一个空的结果列表。 

我们将构建从目标节点向上到根的路径，然后在最后反转它。 
3. 将当前标签添加到结果中。 

在每一步中，当前节点都属于从根到目标的路径。 
4. 计算当前行的镜像标签。 

由于锯齿形行交替方向，我们计算普通二叉树中的等效标签：$$mirrored = rowMin + rowMax - label$$这给出了标签在标准从左到右树中的逻辑位置。 
5. 在普通树中找到父级。 

一旦镜像，父级就很简单：$$parent = mirrored // 2$$6. 移至上一行。 

找到父级后，递减行号并重复直到到达根。 
7. 反转收集的路径。 

由于我们自下而上构建了路径，因此反转给出了目标顺序所需的根。 

### 为什么它有效

 重要的不变性是，在每一步中，我们在计算父级之前，都将 zigzag 标签正确映射到标准二叉树中的等效位置。 由于二叉树父关系是确定性的（`node // 2`），并且镜像变换保留行内的结构位置，每个计算的祖先都是正确的。 重复这个过程最终到达根，产生精确的路径。 

## Python 解决方案```python
from typing import List

class Solution:
    def pathInZigZagTree(self, label: int) -> List[int]:
        path = []

        # Find the row containing the label
        row = 1
        while (1 << row) <= label:
            row += 1

        current = label

        while current >= 1:
            path.append(current)

            row_min = 1 << (row - 1)
            row_max = (1 << row) - 1

            # Mirror the current label into normal ordering
            mirrored = row_min + row_max - current

            # Move to parent
            current = mirrored // 2
            row -= 1

        return path[::-1]
```该实现首先确定哪一行包含目标标签。 由于行的大小加倍，因此 2 的幂通过位移位使计算变得简单。 

接下来，算法重复向上向根移动。 在每次迭代期间，当前标签都会添加到路径中。 行边界是使用 2 的幂计算的，这使我们可以确定正常二叉树排列中的镜像标签。 

镜像后，整数除以二得到父节点。 循环继续直到到达根。 由于路径是从目标到根收集的，因此在最后反转列表会产生正确的顺序。 

## 解决方案```go
func pathInZigZagTree(label int) []int {
	path := []int{}

	// Find row containing label
	row := 1
	for (1 << row) <= label {
		row++
	}

	current := label

	for current >= 1 {
		path = append(path, current)

		rowMin := 1 << (row - 1)
		rowMax := (1 << row) - 1

		// Mirror into normal ordering
		mirrored := rowMin + rowMax - current

		// Move to parent
		current = mirrored / 2
		row--
	}

	// Reverse path
	left, right := 0, len(path)-1
	for left < right {
		path[left], path[right] = path[right], path[left]
		left++
		right--
	}

	return path
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 由于 Go 没有为切片提供内置的反转函数，因此使用两个指针交换手动反转结果切片。 

整数算术在这里是安全的，因为最大标签仅`10^6`，远低于整数溢出限制。 永远不会返回空切片，因为该问题保证`label >= 1`。

 ## 边缘情况

 ### 根节点 (`label = 1`）

 这是最小的可能输入，表示路径中只有根的树。 有缺陷的实现可能会错误地尝试父计算并产生额外的值。 这个实现自然地处理它，因为循环运行一次，附加`1`，计算父项`0`，并终止。 

### 行边界处的标签

 价值观如`8`,`15`， 和`16`正好位于标签方向改变的行边界处。 这些是偏一误差的常见来源，因为行最小值和最大值在转换时的计算方式不同。 通过显式计算`row_min = 2^(row-1)`和`row_max = 2^row - 1`，实现始终正确地处理边界。 

### 反转行

 偶数行以相反的顺序标记，这意味着天真的`label // 2`父计算将失败。 例如，节点`14`没有父母`7`。 相反，它必须首先镜像到其标准二叉树位置。 该实现通过在计算父值之前始终转换为镜像值来避免此错误。
