[LeetCode 1164 题](https://leetcode.com/problems/product-price-at-a-given-date/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 问题提供了一个名为`Products`，其中每行代表特定日期产品的价格更新。 这些列是：

 | 专栏 | 意义|
 | ---| ---|
 |`product_id`| 产品的标识符 |
 |`new_price`| 分配给产品的新价格|
 |`change_date`| 新价格生效日期 |

 这对`(product_id, change_date)`保证是唯一的，这意味着产品每天最多可以有一次价格更新。 

最初，在进行任何更新之前，每个产品的默认价格为`10`。 

目标是确定当天每种产品的价格`2019-08-16`。 

这意味着对于每个产品：

 - 如果产品在当天或之前发生过一次或多次价格变动`2019-08-16`，我们必须使用最近的此类更改。 
- 如果产品之前或之后没有价格变动`2019-08-16`，则其价格仍为初始值`10`。 

输出应包含表中任何位置出现的每种产品及其有效价格`2019-08-16`。 

重要的细节是我们并不是在寻找最新的总体价格。 我们只关心目标日期之前的最新价格。 之后的任何更改`2019-08-16`必须被忽略。 

一些边缘情况很重要：

 - 产品可能仅在之后才有更新`2019-08-16`。 这样的话，它的价格应该还是`10`。 
- 产品在目标日期之前可能有多次更新。 我们必须选择最新的一个。 
- 产品可能有准确的更新`2019-08-16`，应该包括在内。 
- 不同的产品可能有完全不同的更新历史。 

这从根本上来说是一个“截止日期之前的最新记录”数据库查询问题。 

## 方法

 ### 蛮力方法

 一种简单的方法是独立处理每个产品。 

对于每一个不同的`product_id`，我们可以扫描属于该产品的所有行并识别最新的`change_date`小于或等于`2019-08-16`。 一旦找到，我们就返回对应的`new_price`。 如果不存在这样的行，我们返回`10`。 

这是有效的，因为它明确地检查每个可能的价格变化并直接应用问题定义。 

然而，这种方法变得效率低下，因为每个产品可能需要重复扫描许多行。 如果有`n`行和`m`不同的产品，最坏情况的复杂性可以接近`O(m * n)`。 

在大型数据集中，重复重新扫描表的成本是不必要的。 

### 最佳方法

 关键的观察是我们只需要之前或之后的最新价格更新`2019-08-16`对于每个产品。 

这自然建议按产品对行进行分组并选择最大有效值`change_date`。 

最佳 SQL 解决方案使用：

 - 计算最新有效的子查询`change_date`对于每个产品
 - 连接回原始表以检索关联的`new_price`- 后备值`10`对于没有任何合格更新的产品

 这可以避免重复扫描并有效利用 SQL 聚合。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(m * n) | O(1) | O(1) | 重复扫描每个产品的行 |
 | 最佳| O(n) | O(n) | 使用分组和联接来有效地查找最新的有效价格 |

 ## 算法演练

 1. 首先，识别表中存在的所有不同产品。 

这是必要的，因为每个产品都必须出现在最终输出中，即使它之前从未有过合格的价格更新`2019-08-16`。 
2. 查找每种产品的最新有效价格更新。 

我们过滤行`change_date <= '2019-08-16'`。 

然后，对于每个产品，我们计算最大值`change_date`。 

这为我们提供了在目标日期之前或当天至少进行过一项有效更改的每件产品的最新适用更新。 
3. 将结果连接回原始表。 

聚合步骤仅提供日期。 我们还需要相应的`new_price`。 

通过加入两者：

 -`product_id`-`change_date`我们检索包含有效价格的确切行。 
4. 处理没有合格更新的产品。 

某些产品可能仅在之后才有更新`2019-08-16`。 

这些产品不会出现在聚合结果中。 

对于这种情况，我们使用默认初始价格`10`。 
5. 返回最终结果`(product_id, price)`对。 

该问题允许以任意顺序返回行。 

### 为什么它有效

 该算法依赖于一个简单的不变量：

 对于每种产品，某个日期的正确价格取决于该日期或之前发生的最新价格更新。 

通过显式选择最大有效`change_date`，我们保证不存在以后适用的更新。 返回来检索相应的价格可确保我们返回准确的有效值。 

没有合格更新的产品正确保留初始默认价格`10`。 

## Python 解决方案```python
class Solution:
    def productPrices(self, products: List[List]):
        import pandas as pd

        products_df = pd.DataFrame(
            products,
            columns=["product_id", "new_price", "change_date"]
        )

        target_date = "2019-08-16"

        latest_changes = (
            products_df[products_df["change_date"] <= target_date]
            .groupby("product_id")["change_date"]
            .max()
            .reset_index()
        )

        latest_prices = latest_changes.merge(
            products_df,
            on=["product_id", "change_date"],
            how="left"
        )[["product_id", "new_price"]]

        latest_prices.rename(columns={"new_price": "price"}, inplace=True)

        all_products = products_df[["product_id"]].drop_duplicates()

        result = all_products.merge(
            latest_prices,
            on="product_id",
            how="left"
        )

        result["price"] = result["price"].fillna(10).astype(int)

        return result
```该解决方案首先将输入转换为 pandas DataFrame，以便分组和连接操作变得简单。 

接下来，代码过滤其行`change_date`小于或等于目标日期。 这消除了不相关的未来价格更新。 

这`groupby(...).max()`操作计算每个产品的最新有效日期。 至此，我们确切地知道哪个更新应决定产品的价格。 

合并操作将这些日期与其对应的日期重新连接起来`new_price`价值观。 

重命名后`new_price`到`price`，该解决方案构建了所有不同产品的列表。 这很重要，因为没有合格更新的产品仍然需要出现在结果中。 

最后，左连接将所有产品与计算出的价格结合起来。 缺失值替换为`10`，代表默认初始价格。 

## 解决方案```go
func productPrices(products [][]interface{}) *DataFrame {
	type ProductRecord struct {
		ProductID int
		NewPrice  int
		ChangeDate string
	}

	records := []ProductRecord{}

	for _, row := range products {
		record := ProductRecord{
			ProductID: row[0].(int),
			NewPrice: row[1].(int),
			ChangeDate: row[2].(string),
		}
		records = append(records, record)
	}

	targetDate := "2019-08-16"

	latestDate := make(map[int]string)

	for _, record := range records {
		if record.ChangeDate <= targetDate {
			if current, exists := latestDate[record.ProductID]; !exists || record.ChangeDate > current {
				latestDate[record.ProductID] = record.ChangeDate
			}
		}
	}

	priceMap := make(map[int]int)

	for _, record := range records {
		if latest, exists := latestDate[record.ProductID]; exists &&
			record.ChangeDate == latest {
			priceMap[record.ProductID] = record.NewPrice
		}
	}

	allProducts := make(map[int]bool)

	for _, record := range records {
		allProducts[record.ProductID] = true
	}

	result := []map[string]interface{}{}

	for productID := range allProducts {
		price := 10

		if value, exists := priceMap[productID]; exists {
			price = value
		}

		result = append(result, map[string]interface{}{
			"product_id": productID,
			"price":      price,
		})
	}

	return CreateDataFrame(result)
}
```Go 实现遵循与 Python 版本相同的逻辑结构，但使用显式映射而不是 DataFrame 操作。 

这`latestDate`地图存储每个产品的最近有效更新日期。 

这`priceMap`地图存储相应的有效价格。 

最后，每个不同的产品都会添加到输出中，默认为`10`如果不存在有效的更新。 

由于日期字符串位于`YYYY-MM-DD`格式，字典字符串比较可以正确地按时间顺序排序。

def compute_prices(products):
    from collections import defaultdict

    latest = {}

    for product_id, new_price, change_date in products:
        if change_date <= "2019-08-16":
            if (
                product_id not in latest or
                change_date > latest[product_id][0]
            ):
                latest[product_id] = (change_date, new_price)

    result = {}

    for product_id, _, _ in products:
        result[product_id] = 10

    for product_id, (_, price) in latest.items():
        result[product_id] = price

    return result

 ## 边缘情况

 当产品仅在目标日期之后更新时，就会出现一种重要的边缘情况。 幼稚的实现可能会意外地完全排除该产品，因为在截止之前不存在有效的更新。 正确的行为是返回默认价格`10`。 该实现通过首先收集所有不同的产品，然后用以下内容填充缺失的价格来处理此问题`10`。 

另一个重要的边缘情况是产品在目标日期之前有多次更新。 该算法必须选择最近的有效更新，而不是遇到的第一个更新。 这就是为什么分组步骤使用最大值`change_date`对于每个产品。 

第三个重要的边缘情况是当产品恰好改变价格时`2019-08-16`。 该问题明确要求提供该日期的价格，因此必须包括当天发生的更新。 实现使用`<= '2019-08-16'`而不是`< '2019-08-16'`，确保截止日期本身被认为是有效的。 

最后一个微妙的边缘情况涉及具有较早和较晚更新的产品。 该算法必须忽略所有未来的更改，即使它们是最新的总体更改。 通过在分组之前过滤行，该实现保证只有历史上有效的更新才会影响结果。
