[LeetCode 第 1138 题](https://leetcode.com/problems/alphabet-board-path/)

 **难度：** 🟡 中等
 **主题：** 哈希表、字符串

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个特殊的字母板，并要求我们生成拼写目标字符串所需的最短移动序列。 该板包含按行排列的小写英文字母：```
abcde
fghij
klmno
pqrst
uvwxy
z
```我们总是从位置开始`(0, 0)`，对应于字符`'a'`。 从棋盘上的任何有效位置，我们可以移动：

 - 与`'U'`- 打倒`'D'`- 左边有`'L'`- 正确地与`'R'`达到所需的字符后，我们追加`'!'`指示选择该字符。 

目标是产生一个运动序列来拼写给定的`target`使用最少移动次数的字符串。 

输入由一个字符串组成`target`，仅包含小写英文字母。 输出是一个字符串，表示拼写目标所需的移动指令和选择操作。 

限制相对较小：

 -`1 <= target.length <= 100`- 仅使用小写英文字母。 

由于只有 26 个可能的字母，并且目标长度最多为 100，因此效率不是主要问题。 然而，正确性很棘手，因为棋盘是不规则的。 除最后一行外的每一行都有五列，但最后一行仅包含`'z'`。 

这种不规则的形状引入了一个重要的边缘情况。 人物`'z'`独自坐在`(5, 0)`，意思是像这样的位置`(5, 1)`或者`(5, 2)`不存在。 幼稚的移动策略可能会意外地尝试移动到无效的单元格中。 

例如：

 - 移动**至`'z'`** 需要谨慎，因为我们必须避免进入不存在的单元格。 
- 搬**自`'z'`** 也需要小心，因为我们应该先向上移动，然后再向右移动。 
- 连续重复的字符仍应附加`'!'`无需不必要的移动。 

该问题保证所有目标字符都是有效的小写字母，因此我们永远不需要处理无效输入。 

## 方法

 ### 蛮力方法

 强力解决方案会将棋盘视为图形，并为每个字符转换使用最短路径算法，例如广度优先搜索 (BFS)。 

对于每个目标字符：

 1. 从当前位置开始。 
2. 运行 BFS 寻找到下一个字符的最短路径。 
3. 记录动作顺序。 
4. 追加`'!'`。 

由于电路板仅包含 26 个单元，因此 BFS 在实践中总是很快。 每次转换都会搜索所有可到达的单元格，直到找到目的地。 

这种方法是正确的，因为 BFS 保证了未加权图中的最短路径。 然而，它是不必要的复杂。 棋盘结构是固定的并且非常小，这意味着我们可以直接计算位置之间的移动而无需图形遍历。 

### 最佳方法

 关键的观察是每个角色在棋盘上都有一个固定的坐标。 由于移动成本只是曼哈顿移动，因此我们可以直接计算如何在两个坐标之间移动。 

对于每个目标字符：

 1. 确定棋盘坐标。 
2. 计算与当前位置的行差和列差。 
3、直接生成运动指令。 

重要的见解是处理`'z'`安全。 

因为`'z'`是第 5 行中唯一的字符，我们必须优先考虑移动顺序：

 - 离开时**向右上方移动**`'z'`- 进入时先向左移动再向下移动**`'z'`一个可靠的策略是：

 1. **向上**
 2. 向**左移动**
 3. **向下移动**
 4. 向右移动**

 这种顺序保证我们永远不会输入无效的单元格。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n × 26) | O(26) | 为每个角色转换运行 BFS |
 | 最佳 | O(n) | O(1) | O(1) | 谨慎订购直接坐标移动 |

 这里，`n`的长度是`target`。 

## 算法演练

 ### 最优算法

 1. 创建从每个字母到其对应位置的映射`(row, column)`协调板上。 

由于字母布局是固定的，我们可以用数学方法计算坐标。 对于一个角色`c`:

 -`index = ord(c) - ord('a')`-`row = index // 5`-`col = index % 5`这样可以立即访问每个字母的位置。 
2. 从位置开始`'a'`，即`(0, 0)`。 

我们将当前光标位置保持为`(current_row, current_col)`。 
3. 处理每个字符`target`。 

对于每个目标字符，检索其目标坐标。 
4. 首先垂直向上移动。 

如果目标行小于当前行，则追加`'U'`反复。 

当离开时这一点尤其重要`'z'`。 
5. 向左水平移动第二个。 

如果目标列较小，则附加`'L'`。 

这可以防止在定位时意外进入无效单元格`'z'`。 
6. 垂直向下移动第三个。 

如果目标行较大，则追加`'D'`。 
7. 最后向右水平移动。 

如果目标列较大，则追加`'R'`。 
8. 追加`'!'`到达角色后。 

这记录了选择该字母。 
9. 更新当前位置。 

选择角色后，将其作为下一次转换的新起点。 

### 为什么它有效

 该算法始终会生成有效的最短路径，因为每次移动都会直接减少到目标坐标的曼哈顿距离。 由于不会发生不必要的移动，因此路径长度最短。 

移动顺序确保了正确性`'z'`。 通过在向下和向右之前向上和向左移动，我们永远不会尝试进入最后一行中不存在的单元格。 这个不变量保证所有中间位置都是有效的。 

## Python 解决方案```python
class Solution:
    def alphabetBoardPath(self, target: str) -> str:
        result: list[str] = []

        current_row, current_col = 0, 0

        for char in target:
            index = ord(char) - ord('a')
            target_row = index // 5
            target_col = index % 5

            # Move up first
            while current_row > target_row:
                result.append('U')
                current_row -= 1

            # Move left second
            while current_col > target_col:
                result.append('L')
                current_col -= 1

            # Move down third
            while current_row < target_row:
                result.append('D')
                current_row += 1

            # Move right last
            while current_col < target_col:
                result.append('R')
                current_col += 1

            result.append('!')

        return ''.join(result)
```实现完全遵循算法。 我们维护当前光标位置并以数学方式计算每个字符的目标位置。 

我们没有明确地存储棋盘，而是利用字母表的可预测布局。 由于字母是按顺序排列的，整数除法和取模立即提供坐标。 

移动顺序是最重要的实现细节。 我们总是处理：

 1. 向上
 2. 左
 3. 向下
 4. 右

 这保证了周围的安全导航`'z'`。 

结果是使用字符列表构建的并在末尾连接。 这比重复字符串连接更可取，因为 Python 字符串是不可变的，并且重复连接会创建不必要的中间字符串。 

## 解决方案```go
func alphabetBoardPath(target string) string {
	var result []byte

	currentRow, currentCol := 0, 0

	for _, ch := range target {
		index := int(ch - 'a')
		targetRow := index / 5
		targetCol := index % 5

		// Move up first
		for currentRow > targetRow {
			result = append(result, 'U')
			currentRow--
		}

		// Move left second
		for currentCol > targetCol {
			result = append(result, 'L')
			currentCol--
		}

		// Move down third
		for currentRow < targetRow {
			result = append(result, 'D')
			currentRow++
		}

		// Move right last
		for currentCol < targetCol {
			result = append(result, 'R')
			currentCol++
		}

		result = append(result, '!')
	}

	return string(result)
}
```Go 实现密切反映了 Python 逻辑。 

一个区别是 Go 使用`[]byte`用于高效字符串构造的切片。 由于 Go 中的字符串是不可变的，因此重复连接字符串的效率会很低。 附加字节并在最后转换一次是惯用的方法。 

Go 还使用符文迭代`for _, ch := range target`，即使只存在小写英文字母，也确保字符处理是安全的。 

不需要特殊的溢出处理，因为坐标仍然非常小。

 ## 边缘情况

 ### 移至`'z'`这封信`'z'`是唯一的，因为它单独位于第 5 行。在向左移动之前向下移动的粗心实现可能会尝试访问无效单元格，例如`(5, 2)`。 

例如，从`'e'`到`'z'`必须先向左移动，然后才向下移动。 我们的移动顺序通过始终在向下移动之前执行向左移动来防止无效转换。 

### 搬自`'z'`离开`'z'`引入了相反的问题。 如果我们仍在第 5 行时向右移动，我们将立即进入无效位置。 

例如，从`'z'`到`'d'`应该先向上移动，然后向右移动。 由于该算法总是在向右移动之前处理向上移动，因此这种情况自然有效。 

### 重复字符

 重复的字符，例如`"ee"`或者`"zz"`假设总是需要移动的实现可能会处理不当。 

在我们的实现中，如果当前位置已经与目标位置匹配，则不会执行任何移动循环。 我们只需附加`'!'`，再次正确选择相同的角色，无需额外的移动。
