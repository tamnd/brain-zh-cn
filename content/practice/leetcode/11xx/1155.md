[LeetCode 第 1155 题](https://leetcode.com/problems/number-of-dice-rolls-with-target-sum/)

 **难度：** 🟡 中等
 **主题：** 动态规划

 ## 解决方案

 ## 问题理解

 问题给了我们`n`相同的骰子，每个骰子的面编号为`1`到`k`。 我们全部滚动`n`骰子并想要计算有多少个不同的掷骰序列产生的总和等于`target`。 

重要的细节是顺序很重要。 例如，当掷两个六面骰子并瞄准总和时`7`，结果`(1, 6)`和`(6, 1)`被认为是不同的方式。 我们计算的不是组合，而是骰子掷出的有序序列。 

输入包括：

 -`n`, 骰子数量
 -`k`, 每个骰子上的面数
 -`target`, 所需的总和

 输出应该是有效滚动序列的总数，其值总计为`target`。 

由于可能结果的数量可能变得非常大，因此必须以模数返回答案`10^9 + 7`。 这是组合数学和动态规划问题中的常见要求，以防止整数溢出并保持值的可管理性。 

约束条件很重要：

 -`1 <= n, k <= 30`-`1 <= target <= 1000`一个简单的解决方案是尝试所有可能的滚动顺序。 由于每个骰子都有`k`选择，序列总数为`k^n`。 在最坏的情况下，就会变成`30^30`，这是一个天文数字，完全不可行。 

这些约束强烈表明我们需要一个动态规划解决方案。 

一些边缘情况很重要：

 - 目标可能无法实现。 例如，与`n = 2`，最小总和为`2`最大总和是`2 * k`。 任何超出此范围的目标都应该返回`0`。 
- 等于最小或最大可能总和的目标通常只有一种有效的排列。 
- 大值`n`,`k`， 和`target`需要仔细优化以避免运行时间过长。 
- 中间计数变得非常大，因此必须一致地应用模算术。 

## 方法

 ### 蛮力方法

 最直接的解决方案是生成每个可能的掷骰子序列，并计算有多少个序列之和为`target`。 

我们可以将其视为递归搜索：

 - 对于每个骰子，尝试每个面值`1`到`k`- 跟踪运行总和
 - 一次全部`n`使用骰子，检查总和是否等于`target`这种方法是正确的，因为它明确地探索了每个有效的掷骰序列，并准确计算总数与目标匹配的掷骰序列。 

然而，运行时间很糟糕。 每个模具介绍`k`分支选择，因此递归路径总数为`k^n`。 

对于最大约束：$$30^{30}$$这是完全不切实际的。 

### 最优动态规划方法

 关键的观察结果是许多子问题重复出现。 

假设我们已经知道：

 - 有多少种求和方法`s`- 准确地使用`d`骰子

 然后，为了计算用更多的骰子获得更大总和的方法的数量，我们可以扩展之前的结果。 

这自然会导致动态规划。 

我们定义：$$dp[d][s]$$作为实现总和的方法数量`s`准确地使用`d`骰子。 

计算这个：

 - 尝试所有可能的面值`1`到`k`- 如果当前骰子显示`face`，那么之前的骰子一定已经形成：$$s - face$$所以递归式变为：$dp[d][s]=\sum_{face=1}^{k} dp[d-1][s-face]$这避免了重复地重新计算相同的状态。 

因为每个状态仅取决于前一行，所以我们可以将空间从完整的二维表优化为两个一维数组。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(k^n) | O(k^n) | O(n) | 递归尝试每个可能的滚动顺序 |
 | 最优动态规划| O(n * 目标 * k) | O（目标）| 使用以前的状态增量构建解决方案 |

 ## 算法演练

 1. 创建一个常量`MOD = 10^9 + 7`。 

可能的滚动序列的数量增长得非常快，因此每次加法都必须取模`MOD`。 
2. 初始化DP阵列。 

我们使用一维数组`dp`在哪里：$$dp[s]$$代表求和的方法数`s`使用当前已处理骰子的数量。 
3. 设置基本情况。 

在掷骰子之前，有一种方法可以计算总和`0`:$dp[0]=1$所有其他金额最初都有`0`方式。 

1. 一次处理一颗骰子。 

对于每个骰子：

 - 创建一个新的数组`next_dp`- 该数组将存储新骰子数量的结果
 2. 对于每个可能的当前总和：

 如果`dp[current_sum]`是非零，尝试每个面值`1`到`k`。 
3. 更新下一个状态。 

如果当前骰子显示`face`，则新的总和变为：$new\_sum=current\_sum+face$添加之前状态的路数：$next\_dp[new\_sum]+=dp[current\_sum]$每次加法后应用模。 

1. 更换旧的 DP 阵列。 

处理完当前骰子的所有总和和面值后，分配：```
dp = next_dp
```1. 返回结果。 

毕竟`n`骰子经过处理，答案是：```
dp[target]
```### 为什么它有效

 该算法之所以有效，是因为每个有效的掷骰子序列都可以增量构建。 

对于每个骰子，我们考虑所有可能的面值并扩展所有先前可达到的总和。 由于每个状态代表与固定数量的骰子形成和的确切方式数，并且每次转换对应于添加一个合法的骰子值，因此 DP 表对每个有效序列恰好计数一次。 

## Python 解决方案```python
class Solution:
    def numRollsToTarget(self, n: int, k: int, target: int) -> int:
        MOD = 10**9 + 7

        # Impossible target
        if target < n or target > n * k:
            return 0

        dp = [0] * (target + 1)
        dp[0] = 1

        for _ in range(n):
            next_dp = [0] * (target + 1)

            for current_sum in range(target + 1):
                if dp[current_sum] == 0:
                    continue

                for face in range(1, k + 1):
                    new_sum = current_sum + face

                    if new_sum > target:
                        break

                    next_dp[new_sum] = (
                        next_dp[new_sum] + dp[current_sum]
                    ) % MOD

            dp = next_dp

        return dp[target]
```实施从早期的不可能性检查开始。 如果目标小于最小可实现总和或大于最大可实现总和，则函数立即返回`0`。 

这`dp`数组存储使用到目前为止处理的骰子形成每个总和的方法数。 最初，仅求和`0`零骰子是可能的。 

对于每个骰子，都有一个新数组`next_dp`被创建。 这可以防止覆盖当前迭代仍需要的状态。 

嵌套循环迭代：

 - 当前可达到的每笔金额
 - 每种可能的面值

 每当形成新的有效总和时，计数就会累积到`next_dp`。 

加法后立即应用模算术以保持数字有界。 

在每次模具迭代结束时，`dp`被替换为`next_dp`，推动民主党前进。 

## 解决方案```go
func numRollsToTarget(n int, k int, target int) int {
	const MOD int = 1000000007

	// Impossible target
	if target < n || target > n*k {
		return 0
	}

	dp := make([]int, target+1)
	dp[0] = 1

	for dice := 0; dice < n; dice++ {
		nextDP := make([]int, target+1)

		for currentSum := 0; currentSum <= target; currentSum++ {
			if dp[currentSum] == 0 {
				continue
			}

			for face := 1; face <= k; face++ {
				newSum := currentSum + face

				if newSum > target {
					break
				}

				nextDP[newSum] =
					(nextDP[newSum] + dp[currentSum]) % MOD
			}
		}

		dp = nextDP
	}

	return dp[target]
}
```Go 实现遵循与 Python 版本完全相同的动态编程逻辑。 

使用切片而不是 Python 列表。 由于 Go 整数是固定宽度的，因此求模运算对于避免累加过程中的溢出尤为重要。 

与 Python 不同，Go 默认不支持任意精度整数，因此在整个计算过程中使用模是必不可少的。

 ## 边缘情况

 当目标小于可实现的最小总和时，就会出现一种重要的边缘情况。 由于每个骰子至少贡献`1`，最小可能总和`n`骰子是`n`。 如果`target < n`，没有有效的滚动序列。 该实现会立即处理此问题并提前返回。 

当目标超过可实现的最大总和时，就会出现另一个重要的边缘情况。 由于每个骰子最多贡献`k`，最大可能的总数是`n * k`。 任何比这个更大的目标都是不可能的。 如果没有这种检查，算法仍然可以正确运行，但会浪费时间处理永远无法达到的状态。 

第三个重要的边缘情况涉及可能性边界上的求和。 例如，当目标等于最小可能总和时，只有一种有效的排列：每个骰子必须显示`1`。 同样，当目标等于最大可能总和时，每个骰子都必须显示`k`。 这些情况可能会暴露 DP 实现中的索引或转换错误，但递归自然会正确处理它们。 

另一个微妙的边缘情况涉及大量中间计数。 即使模数归约后最终答案符合正常整数范围，中间值也可能变得巨大。 在每次更新期间应用模数可防止溢出并保持计算效率。 

最后，仔细处理 DP 状态更新至关重要。 在迭代过程中重复使用相同的数组会意外地混合当前和先前骰子计数的状态。 使用单独的`next_dp`array 保证每次转换仅使用动态编程过程的前一层的结果。
