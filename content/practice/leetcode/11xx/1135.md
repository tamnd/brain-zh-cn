[LeetCode 问题 1135](https://leetcode.com/problems/connecting-cities-with-minimum-cost/)

 **难度：** 🟡 中等
 **主题：** 并查找、图论、堆（优先级队列）、最小生成树

 ## 解决方案

 ## 问题理解

 这个问题要求我们连接`n`使用一组可能的双向连接将城市聚集在一起。 每个连接都有成本，我们的目标是连接每个城市，同时最小化总成本。 

更正式地，我们得到：

 - 一个整数`n`，代表标记为的城市`1`到`n`- 一份清单`connections`，其中每个元素是`[x, y, cost]`-`x`和`y`是两个城市
 -`cost`是在它们之间修建道路所需的价格

 我们必须选择这些连接的某个子集，以便：

 1. 每个城市都可以从其他城市到达
 2、总成本尽可能小

 如果无法连接所有城市，我们会返回`-1`。 

这是一个经典的图问题。 我们可以想到：

 - 城市作为图节点
 - 连接作为加权边

 任务变成寻找最小生成树，通常缩写为 MST。 

生成树是边的子集：

 - 连接所有顶点
 - 不包含循环
 - 准确使用`n - 1`边缘

 最小生成树是具有最小可能总边权的生成树。 

约束条件很重要：

 -`n <= 10^4`-`connections.length <= 10^4`这些限制对于指数或强力子集生成方法来说太大了。 我们需要一个近线性或`O(E log E)`解，其中`E`是边的数量。 

一些重要的边缘情况包括：

 - 图表已断开连接，这意味着某些城市永远无法到达
 - 同一对城市之间存在多条边
 - 成本可以为零
 - 可能已经有`n - 1`边缘
 - 可能有许多冗余边产生循环

 正确的解决方案必须有效地确定以下两者：

 1、是否所有城市都能连通
 2. 最低总连接成本是多少

 ## 方法

 ### 蛮力方法

 暴力解决方案将尝试每个可能的边子集，并确定该子集是否连接所有城市。 

对于每个子集，我们将：

 1. 仅使用这些边构建图
 2.检查所有城市是否连通
 3. 计算总成本
 4. 跟踪最低有效成本

 这种方法是正确的，因为它检查了每种可能的边组合，保证最终找到最小有效解决方案。 

然而，这在计算上是不可行的。 

如果有`E`边，则有`2^E`可能的子集。 高达`10^4`边缘，子集的数量变得非常大。 

即使检查每个子集的连接性也会增加额外的成本，使得这种方法完全不切实际。 

### 最优方法，带有并查的 Kruskal 算法

 关键的见解是我们不需要测试每个子集。 

这个问题正是最小生成树问题，克鲁斯卡尔算法可以有效地解决它。 

克鲁斯卡尔算法的工作原理是：

 1. 按成本对所有边进行排序
 2. 反复取不形成环的最便宜的边

 为了有效地确定添加边是否会产生循环，我们使用并查数据结构，也称为不相交集并集，缩写为 DSU。 

Union-Find 支持两种高效操作：

 -`find(x)`确定节点属于哪个连接组件
 -`union(x, y)`如果两个组件不同，则合并它们

 如果两个城市已经在同一个组件中，在它们之间添加另一条边会创建一个循环，所以我们跳过它。 

这种贪婪策略之所以有效，是因为最小生成树属性保证了在每一步选择最便宜的安全边都会产生最佳结果。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(2^E * (V + E)) | O(2^E * (V + E)) | O(V + E) | 尝试边缘的每个子集 |
 | 最优、Kruskal + 联合查找 | O(E 日志 E) | O(V) | 高效MST建设|

 ## 算法演练

 ### 第 1 步：按成本对所有连接进行排序

 我们首先按连接成本的升序对边进行排序。 

这确保我们始终首先考虑最便宜的可用边缘。 由于我们想要最低的总成本，因此尽早选择更便宜的边缘至关重要。 

### 步骤 2：初始化并查结构

 我们创建了一个并查数据结构，最初每个城市都属于自己的组件。 

在此阶段：

 - 每个城市都已断开连接
 - 每个城市的父母就是它自己

 我们还初始化：

 -`total_cost = 0`-`edges_used = 0`### 步骤 3：按排序顺序处理边

 我们迭代每条边`[city1, city2, cost]`。 

对于每条边：

 1. 找到根父级`city1`2. 找到根父级`city2`3. 如果根不同：

 - 边缘连接两个独立的组件
 - 将边添加到 MST
 - 合并两个组件
 - 将成本添加到`total_cost`- 增量`edges_used`如果根相同：

 - 城市已经互联
 - 添加这条边会形成一个循环
 - 我们跳过它

 ### 第 4 步：一旦完成就停止`n - 1`边缘

 生成树为`n`节点总是包含精确的`n - 1`边缘。 

一旦达到这个计数，所有城市都已连接，我们可以停止处理进一步的边缘。 

### 第 5 步：验证连接

 处理完所有边后：

 - 如果`edges_used == n - 1`，我们成功连接了所有城市
 - 否则，图表已断开连接，因此我们返回`-1`### 为什么它有效

 克鲁斯卡尔算法依赖于最小生成树的割性质。 

在每一步中，算法都会选择连接两个先前断开连接的组件的最便宜的边。 这保证了我们永远不会错过更便宜的有效解决方案。 

并查可确保有效避免循环，因此生成的结构仍然是树。 

因为我们总是选择最小的安全边，所以最终的生成树具有最小可能的总成本。 

## Python 解决方案```python
from typing import List

class Solution:
    def minimumCost(self, n: int, connections: List[List[int]]) -> int:
        parent = list(range(n + 1))
        rank = [0] * (n + 1)

        def find(city: int) -> int:
            if parent[city] != city:
                parent[city] = find(parent[city])
            return parent[city]

        def union(city1: int, city2: int) -> bool:
            root1 = find(city1)
            root2 = find(city2)

            if root1 == root2:
                return False

            if rank[root1] < rank[root2]:
                parent[root1] = root2
            elif rank[root1] > rank[root2]:
                parent[root2] = root1
            else:
                parent[root2] = root1
                rank[root1] += 1

            return True

        connections.sort(key=lambda edge: edge[2])

        total_cost = 0
        edges_used = 0

        for city1, city2, cost in connections:
            if union(city1, city2):
                total_cost += cost
                edges_used += 1

                if edges_used == n - 1:
                    return total_cost

        return -1
```实现首先创建并查结构。 

这`parent`数组跟踪每个城市的代表父级。 最初，每个城市都是自己的父城市，因为没有城市相互连接。 

这`rank`数组有助于保持并查树平衡。 这可以通过防止树过深来提高性能。 

这`find`函数使用路径压缩。 每当我们搜索城市的根时，我们都会更新中间节点以直接指向根。 这显着加快了未来的运营速度。 

这`union`如果两个组件不同，函数会合并它们。 如果城市已经共享相同的根，则函数返回`False`，表明添加边会创建一个循环。 

接下来，连接按边成本排序。 这是克鲁斯卡尔算法的核心要求。 

然后我们迭代排序的边。 每当一条边成功连接两个先前断开连接的组件时，我们：

 - 将其成本添加到答案中
 - 增加使用的边数

 一旦我们使用`n - 1`边，我们知道我们已经形成了一棵生成树，所以我们立即返回结果。 

如果循环在添加足够的边之前完成，则图将断开连接，我们返回`-1`。 

## 解决方案```go
package main

import "sort"

func minimumCost(n int, connections [][]int) int {
	parent := make([]int, n+1)
	rank := make([]int, n+1)

	for i := 1; i <= n; i++ {
		parent[i] = i
	}

	var find func(int) int

	find = func(city int) int {
		if parent[city] != city {
			parent[city] = find(parent[city])
		}
		return parent[city]
	}

	union := func(city1, city2 int) bool {
		root1 := find(city1)
		root2 := find(city2)

		if root1 == root2 {
			return false
		}

		if rank[root1] < rank[root2] {
			parent[root1] = root2
		} else if rank[root1] > rank[root2] {
			parent[root2] = root1
		} else {
			parent[root2] = root1
			rank[root1]++
		}

		return true
	}

	sort.Slice(connections, func(i, j int) bool {
		return connections[i][2] < connections[j][2]
	})

	totalCost := 0
	edgesUsed := 0

	for _, edge := range connections {
		city1 := edge[0]
		city2 := edge[1]
		cost := edge[2]

		if union(city1, city2) {
			totalCost += cost
			edgesUsed++

			if edgesUsed == n-1 {
				return totalCost
			}
		}
	}

	return -1
}
```Go 的实现与 Python 版本非常相似。 

Go 不支持像 Python 那样的嵌套命名函数，所以`find`在赋值之前声明为函数变量。 

切片用于两者`parent`和`rank`。 科学城标签开始于`1`，数组分配了大小`n + 1`。 

排序步骤使用`sort.Slice`，允许自定义比较逻辑。 

整数溢出在这里不是一个问题，因为最大可能的成本仍然安全地在 Go 的范围内`int`给定约束下的范围。

 | 测量| 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(E 日志 E) | 排序边在运行时占据主导地位
 | 空间| O(V) | 并查数组存储父级和等级 |

 最昂贵的操作是排序`connections`数组，它需要`O(E log E)`时间。 

由于路径压缩和按等级并集，并查找操作非常高效。 从技术上讲，它们的摊余复杂性几乎是恒定的`O(alpha(V))`， 在哪里`alpha`是阿克曼反函数。 

自从`alpha(V)`生长极其缓慢，在实践中被视为恒定。 

空间使用主要来自于`parent`和`rank`数组，每个数组的大小`n + 1`。

 ## 边缘情况

 ### 断开连接的图

 当图表无法完全连接所有城市时，就会出现一种主要的边缘情况。 

例如：```
n = 4
connections = [[1,2,1],[3,4,1]]
```有两个独立的组件，它们之间没有桥梁。 

有缺陷的实现可能会错误地返回所有边的总和。 然而，有效的生成树必须准确包含`n - 1`边缘。 

我们的实施轨迹`edges_used`，并且仅返回总成本`n - 1`边缘已成功添加。 

否则，它返回`-1`。 

### 带循环的图

 当多个边创建循环时会发生另一个重要情况。 

例子：```
[[1,2,1],[2,3,2],[1,3,3]]
```简单的实现可能包括所有三个边缘，从而创建一个循环并不必要地增加总成本。 

Union-Find 通过在添加边之前检查两个城市是否已属于同一连接组件来防止此问题。 

如果它们已经连接，则跳过该边。 

### 单一城市

 当`n = 1`，不需要边，因为单个城市已经与其自身相连。 

这种情况很容易导致差一错误。 

我们的实现自然地处理它：

 -`n - 1 = 0`- 没有处理任何边缘
 - 最低成本正确`0`### 多个等成本边

 有时，几条边具有相同的权重。 

例子：```
[[1,2,1],[2,3,1],[1,3,1]]
```MST 在这种情况下并不是唯一的。 

克鲁斯卡尔算法仍然可以正常工作，因为任何最小成本的有效生成树都是可以接受的。 等价边之间的排序顺序不影响正确性。
