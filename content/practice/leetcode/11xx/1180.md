[LeetCode 第 1180 题](https://leetcode.com/problems/count-substrings-with-only-one-distinct-letter/)

 **难度：** 🟢简单
 **主题：** 数学、字符串

 ## 解决方案

 ## 问题理解

 该问题要求我们计算给定字符串中有多少个子字符串仅包含一个不同的字符。 

子字符串是字符串的连续部分。 例如，在字符串中`"aaaba"`, 子串`"aaa"`有效，因为每个字符都是`'a'`。 子串`"aab"`无效，因为它包含两者`'a'`和`'b'`。 

输入是单个字符串`s`仅由小写英文字母组成。 字符串的长度介于`1`和`1000`。 

预期输出是一个整数，表示所有字符都相同的子字符串总数。 

关键的观察是同一字符的连续组会生成许多有效的子字符串。 例如：

-`"a"`贡献`1`-`"aa"`贡献`3`因为有效的子字符串是：

 -`"a"`在索引 0 处
 -`"a"`在索引 1 处
 -`"aa"`-`"aaa"`贡献`6`一般来说，一个连续的长度块`n`贡献：$1+2+3+\cdots+n=\frac{n(n+1)}{2}$这个问题足够小，甚至二次解也能起作用，因为`n <= 1000`，但字符串的结构允许简单的线性时间解决方案。 

一些重要的边缘情况包括：

 - 只有一个字符的字符串，例如`"a"`- 所有字符都相同的字符串，例如`"aaaaa"`- 每个字符都不同的字符串，例如`"abcde"`- 交替字符，例如`"ababab"`这些情况可能会暴露不正确的计数逻辑或相差一错误。 

## 方法

 ### 蛮力方法

 暴力解决方案考虑每个可能的子字符串并检查它是否只包含一个不同的字符。 

有`O(n^2)`长度字符串中可能的子字符串`n`。 对于每个子字符串，我们可以扫描其字符或将它们放入一个集合中，以确定所有字符是否相同。 

例如，对于`"aaaba"`:

 -`"a"`有效
 -`"aa"`有效
 -`"aaa"`有效
 -`"aaab"`无效，因为它包含`'a'`和`'b'`这种方法是正确的，因为它显式验证每个子字符串。 然而，它变得低效，因为检查每个子字符串需要重复工作。 

如果子字符串验证需要`O(n)`随着时间的推移，整体复杂度变为`O(n^3)`。 

### 最佳方法

 关键的见解是有效的子字符串完全来自相同字符的连续运行。 

例如：

-`"aaa"`包含：

 - 3个长度为1的子串
 - 2 个长度为 2 的子串
 - 1 个长度为 3 的子串

 总计：$\frac{3(3+1)}{2}=6$我们不是单独检查每个子字符串，而是处理字符串一次并识别连续的字符组。 

对于每组长度`k`，我们添加：$\frac{k(k+1)}{2}$这避免了重复工作并产生线性时间解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n3) | O(1) 或 O(n) | 枚举所有子字符串并检查每个子字符串 |
 | 最佳| O(n) | O(1) | O(1) | 计算连续角色运行的贡献 |

 ## 算法演练

 1. 初始化变量`total_substrings`存储最终答案。 
2. 初始化变量`current_run_length`到`1`因为第一个字符总是以长度 1 开始。 
3.从index开始遍历字符串`1`。 
4. 对于每个字符，将其与前一个字符进行比较。 

- 如果它们相同，则通过增加来延长当前运行`current_run_length`。 
- 如果不同，则上次运行已结束。 
5. 当运行结束时，使用以下方法计算运行贡献了多少个有效子字符串：$\frac{k(k+1)}{2}$在哪里`k`是游程长度。 

1. 将此值添加到答案中。 
2. 重置`current_run_length`到`1`为新角色运行。 
3. 循环结束后，处理最终运行，因为它尚未添加到答案中。 
4. 返回累计总数。 

### 为什么它有效

 每个有效的子字符串必须完全由相同的字符组成。 因此，每个有效子字符串完全属于一组连续的相同字符。 

一段长度`k`包含：

 -`k`长度为 1 的子串
 -`k - 1`长度为 2 的子串
 -`k - 2`长度为 3 的子串
 - ...
 -`1`长度子串`k`总数为：$k+(k-1)+(k-2)+\cdots+1=\frac{k(k+1)}{2}$由于该算法只对每次运行处理一次并计算该运行中的所有子字符串，因此它对每个有效子字符串只计算一次。 

## Python 解决方案```python
class Solution:
    def countLetters(self, s: str) -> int:
        total_substrings = 0
        current_run_length = 1

        for index in range(1, len(s)):
            if s[index] == s[index - 1]:
                current_run_length += 1
            else:
                total_substrings += (
                    current_run_length * (current_run_length + 1)
                ) // 2
                current_run_length = 1

        total_substrings += (
            current_run_length * (current_run_length + 1)
        ) // 2

        return total_substrings
```实现首先初始化答案累加器和当前字符运行的长度。 

循环从索引开始`1`因为每个字符都会与前一个字符进行比较。 如果当前字符与前一个字符匹配，则继续运行并且运行长度增加。 

当字符不同时，当前运行结束。 该算法使用算术级数公式计算该运行所贡献的有效子串的数量，并将其添加到总数中。 

处理结束的运行后，算法将运行长度重置为`1`因为当前角色开始新的运行。 

遍历完成后，还需要处理最终的运行。 这就是为什么在循环之后最后一次应用该公式的原因。 

然后该方法返回总计数。 

## 解决方案```go
func countLetters(s string) int {
    totalSubstrings := 0
    currentRunLength := 1

    for i := 1; i < len(s); i++ {
        if s[i] == s[i-1] {
            currentRunLength++
        } else {
            totalSubstrings += currentRunLength * (currentRunLength + 1) / 2
            currentRunLength = 1
        }
    }

    totalSubstrings += currentRunLength * (currentRunLength + 1) / 2

    return totalSubstrings
}
```Go 实现遵循与 Python 版本相同的逻辑。 

由于输入长度最多为`1000`，整数溢出不是问题，因为最大答案是：$\frac{1000\times1001}{2}=500500$很容易适合 Go 的内部`int`类型。 

Go字符串是字节索引的，输入只包含小写英文字母，所以直接用`s[i]`是完全安全的。

 ## 边缘情况

 单字符串是最小的有效输入。 很容易误操作初始化和返回`0`而不是`1`。 此实现从运行长度开始`1`，确保单个角色正确贡献。 

每个字符都相同的字符串可能会暴露不正确的运行结束逻辑。 例如，`"aaaa"`包含许多重叠的子串。 有些实现忘记处理循环后的最终运行。 该解决方案在遍历完成后显式添加最后一次运行的贡献。 

交替字符，例如`"ababab"`可以揭示不连续的相等字符被错误地分组在一起的错误。 该算法仅在相邻字符相等时才扩展运行，因此单独处理单独出现的字符。 

具有不同大小的多次运行的字符串，例如`"aabbbcc"`，测试算法是否在每个边界后正确重置游程长度。 实施重置`current_run_length`到`1`处理完成的运行后立即进行，确保每个组都独立计数。
