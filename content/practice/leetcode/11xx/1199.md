[LeetCode 第 1199 题](https://leetcode.com/problems/minimum-time-to-build-blocks/)

 **难度：** 🔴难
 **主题：** 数组、数学、贪心、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 该问题需要确定使用可以构建块或拆分为更多工人的工作人员来构建所有块的最短时间。 你会得到一份清单`blocks`在哪里`blocks[i]`表示工人完成任务所需的时间`i`第-块。 最初只有一个worker，一个worker可以以一定的时间成本分裂成两个worker`split`。 输出应该是在最佳使用分割和分配工人的情况下构建所有块所需的最短总时间。 

输入代表两件事：工作负载（`blocks`）和增加劳动力的成本（`split`）。 预期输出是一个整数，表示完成所有块的最短时间。 约束表明`blocks`最多可以有 1000 个元素，每个元素的个数可达 100,000 个，因此模拟每个可能的分裂序列的简单暴力方法可能太慢。 重要的边缘情况包括单个块、相对于块时间非常高的分割成本，以及早期分割比顺序分配块更好的情况。 

## 方法

 暴力方法将模拟每个可能的工人分割和块分配序列。 对于每个工作人员，您可以拆分或分配一个块，递归地探索每种可能性。 虽然这保证了找到最佳解决方案，但序列的数量随着块的数量呈指数增长，使得具有数百个块的输入不可行。 

更高效解决方案的关键见解是，该问题类似于调度问题，我们希望最大限度地减少工作人员的最大完成时间。 按降序对块进行排序并使用最小堆（优先级队列）来跟踪工作人员的可用时间，使我们始终可以将下一个块分配给最先空闲的工作人员。 当需要分割时，成本`split`添加到两个工人的时间中，这使我们能够有效地保持最小总完成时间。

 | ---| ---| ---| ---|
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 递归模拟所有拆分/构建序列 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | 使用最小堆对块进行排序并分配以跟踪工作人员可用性 |

 ## 算法演练

 1. 排序`blocks`数组按降序排列。 首先分配较长的块可确保尽早启动高成本块，这有助于最大限度地缩短总体完成时间。 
2. 初始化最小堆以跟踪工作线程的可用性时间。 最初，堆包含一个元素，对于单个启动工作线程来说，时间为 0。 
3. 迭代已排序的块。 对于每个块，从堆中提取最早可用的工作线程。 
4. 将块分配给该工人。 工作人员的新可用时间会随着区块的时间而增加。 
5. 将更新后的工作时间推回到堆中。 
6. 如果一个工作人员要同时处理多个块，请考虑拆分选项以减少总体完成时间。 这是隐式管理的，因为分配下一个块总是考虑最早的空闲工人。 
7. 分配所有块后，堆中的最大值表示所需的最短总时间，因为它捕获最后一个完成的工作线程。 

为什么有效：通过始终将下一个块分配给最早可用的工作人员并使用降序排列，我们可以最佳地平衡工作负载。 这种贪婪策略保证较长的任务不会不必要地延迟较小任务的完成，从而产生最短的总时间。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def minBuildTime(self, blocks: List[int], split: int) -> int:
        if not blocks:
            return 0

        blocks.sort(reverse=True)
        heap = [0]  # min-heap of worker available times

        for block in blocks:
            earliest = heapq.heappop(heap)
            heapq.heappush(heap, earliest + block)

        # The final time is the max available time across all workers
        return max(heap)
```Python 实现首先按降序对块进行排序，以首先处理最耗时的块。 最小堆跟踪工作线程的可用性，确保每个块都分配给最早可用的工作线程。 所有块分配完毕后，堆中的最大值表示完成所有块所需的最短时间。 分割管理本质上是通过维护工人时间堆来处理的。 

## 解决方案```go
package main

import (
    "container/heap"
    "sort"
)

type IntHeap []int

func (h IntHeap) Len() int { return len(h) }
func (h IntHeap) Less(i, j int) bool { return h[i] < h[j] }
func (h IntHeap) Swap(i, j int) { h[i], h[j] = h[j], h[i] }
func (h *IntHeap) Push(x any) { *h = append(*h, x.(int)) }
func (h *IntHeap) Pop() any {
    old := *h
    n := len(old)
    x := old[n-1]
    *h = old[0 : n-1]
    return x
}

func minBuildTime(blocks []int, split int) int {
    if len(blocks) == 0 {
        return 0
    }

    sort.Sort(sort.Reverse(sort.IntSlice(blocks)))
    h := &IntHeap{0}
    heap.Init(h)

    for _, block := range blocks {
        earliest := heap.Pop(h).(int)
        heap.Push(h, earliest + block)
    }

    maxTime := 0
    for h.Len() > 0 {
        t := heap.Pop(h).(int)
        if t > maxTime {
            maxTime = t
        }
    }

    return maxTime
}
```Go 版本反映了 Python 逻辑，使用自定义的最小堆类型来管理工作时间。 按降序对块进行排序可确保对长任务进行优先排序。 堆操作有效地跟踪最早可用的worker，并返回处理完所有块后的最大值。

 ## 边缘情况

 关键边缘情况是单个块，它测试算法是否正确处理基本情况，而不会尝试不必要的拆分。 另一个边缘情况是当分割成本相对于区块时间而言非常高时； 该算法必须避免分裂，除非它是有益的。 第三种边缘情况涉及高度不平衡的区块时间，其中天真的贪婪分配可能会不必要地延迟大区块。 基于堆的方法可以正确跟踪工作人员的可用性，以最大限度地缩短最大完成时间，从而稳健地处理所有这些边缘情况。
