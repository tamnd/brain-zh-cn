[LeetCode 问题 1153](https://leetcode.com/problems/string-transforms-into-another-string/)

 **难度：** 🔴难
 **主题：** 哈希表、字符串、图论

 ## 解决方案

 ## 问题理解

 这个问题给了我们两个字符串，`str1`和`str2`，保证具有相同的长度。 我们想确定是否可以转型`str1`进入`str2`使用一系列字符转换操作。 

单个转换操作的工作原理如下：

 - 选择一个角色`str1`- 用另一个小写英文字母替换该字符的每个出现位置

 重要的细节是替换同时影响所有发生的情况。 我们不能有选择地仅替换某些出现的字符。 

例如，如果当前字符串是`"aabcc"`我们转换`'a'`到`'c'`，整个字符串变成`"ccbcc"`因为每一个`'a'`立刻改变。 

目标是确定这些操作是否存在某种序列，可以将整个字符串精确地转换为`str2`。 

约束条件很重要：

 - 两个字符串的长度可达`10^4`- 仅使用小写英文字母
 - 只有 26 个可能的字符

 小字母表大小是实现高效解决方案的关键观察结果。 

该操作的一个关键属性是一致性。 如果出现一次`'a'`在`str1`映射到`'c'`在`str2`，那么每次出现`'a'`还必须映射到`'c'`。 否则，转换是不可能的，因为转换总是同时影响字符的所有副本。 

例如：

-`"aa"`→`"bc"`是不可能的
 - 第一个`'a'`需要成为`'b'`- 第二个`'a'`需要成为`'c'`- 单个角色无法映射到两个不同的目标

 另一个微妙的边缘情况涉及循环。 考虑：

-`"ab"`→`"ba"`乍一看，这似乎是可能的，因为：

 -`'a'`映射到`'b'`-`'b'`映射到`'a'`然而，这会造成一个循环。 如果我们转换`'a'`到`'b'`首先，我们失去了辨别原创的能力`'b'`转换后的字符。 为了打破这样的循环，我们需要一个暂时未使用的角色。 

由于只有 26 个小写字母，如果目标字符串中已使用所有 26 个字符，则没有多余的临时字符可用于中断循环。 

该问题保证：

 - 字符串长度相等
 - 仅限小写英文字母
 - 非空字符串

 这些保证简化了实现，因为我们不需要处理无效输入。 

## 方法

 ### 蛮力方法

 蛮力策略将尝试模拟每个可能的转换序列。 

我们可以将问题建模为图搜索，其中：

 - 每个节点代表当前的字符串状态
 - 每个边沿代表一次有效的转换操作

 开始于`str1`，我们将尝试所有可能的字符替换并搜索路径`str2`。 

这种方法在理论上是正确的，因为它探索了所有可能的转换序列。 如果存在有效序列，穷举搜索最终将找到它。 

然而，可能的状态数量是巨大的。 对于每个步骤：

 - 我们最多可以选择 26 个字符
 - 每个都可以转换成26个可能的目标
 - 字符串的长度可达`10^4`状态空间呈指数级增长，这使得这完全不可行。 

蛮力方法失败是因为搜索空间太大。 

### 最佳方法

 关键的见解是，实际的操作顺序不如字符之间的映射关系重要。 

假设我们检查字符串中的相应位置：

 - 如果`str1[i] = 'a'`和`str2[i] = 'c'`- 然后每个`'a'`在`str1`最终必须成为`'c'`这将创建一个确定性映射：

 - 一个源角色必须恰好映射到一个目标角色

 如果我们发现：

 -`'a' -> 'b'`- 以及之后`'a' -> 'c'`那么立即转变是不可能的。 

一旦验证了映射一致性，唯一剩下的问题就是周期。 

一个循环如：

 -`'a' -> 'b'`-`'b' -> 'a'`需要一个未使用的临时角色才能安全地中断。 

如果`str2`已使用全部 26 个字母，没有可用的备用字符。 在这种情况下：

 - 任何不平凡的循环都会使转变变得不可能

 幸运的是，我们甚至不需要显式地检测循环。 

一个值得注意的观察是：

 - 如果`str1 != str2`- 和`str2`使用全部 26 个字符
 - 那么转型是不可能的

 为什么？ 

因为任何更改最终都需要临时存储以避免覆盖信息，但不存在未使用的字符。 

所以最终的条件是：

 1.字符映射必须一致
 2. 要么：

 -`str1 == str2`， 或者
-`str2`使用少于 26 个不同的字母

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 指数| 指数| 探索所有可能的转换顺序 |
 | 最佳| O(n) | O(1) | O(1) | 使用映射一致性和循环观察|

 ## 算法演练

 1.首先检查是否`str1`和`str2`已经相同。 

如果相等，则不需要转换，所以我们立即返回`true`。 
2. 创建哈希映射来存储字符映射。 

密钥将是来自的一个字符`str1`，其值为对应的字符`str2`。 

这可确保每个源字符一致地映射到一个目标字符。 
3. 同时迭代两个字符串。 

对于每个索引`i`：

- 让`source = str1[i]`- 让`target = str2[i]`4. 检查是否`source`映射中已存在。 

- 如果不存在，则插入映射：

 -`source -> target`- 如果已存在，请验证存储的目标是否与当前目标匹配。 
5. 如果现有映射与当前目标冲突，则返回`false`。 

示例：

 - 早些时候我们看到`'a' -> 'b'`- 现在我们看到了`'a' -> 'c'`这是不可能的，因为一次转换操作不能产生两个不同的字符。 
6. 处理完所有字符后，计算有多少个不同的字符出现在`str2`。 

我们为此使用集合，因为集合会自动删除重复项。 
7. 如果`str2`包含少于 26 个不同字符，返回`true`。 

这意味着至少有一个未使用的字符可用作解析周期的临时存储。 
8. 否则，返回`false`。 

如果使用了全部 26 个字符并且字符串不相等，则无法安全地解析循环。 

### 为什么它有效

 该算法之所以有效，是因为每个有效的转换都会产生一致的字符映射。 由于转换同时影响所有出现的情况，因此单个源字符无法映射到多个目标。 

一旦保证了映射一致性，唯一剩下的障碍就是循环依赖。 如果存在至少一个未使用的临时字符，则始终可以解决循环问题。 因此，少于 26 个不同的目标字符可以保证只要映射一致就可以进行转换。 

## Python 解决方案```python
class Solution:
    def canConvert(self, str1: str, str2: str) -> bool:
        if str1 == str2:
            return True

        char_map = {}

        for source_char, target_char in zip(str1, str2):
            if source_char in char_map:
                if char_map[source_char] != target_char:
                    return False
            else:
                char_map[source_char] = target_char

        return len(set(str2)) < 26
```实施从早期的平等检查开始。 如果两个字符串已经相同，则无需任何操作，因此立即得到答案`True`。 

接下来，我们创建`char_map`，它存储每个源字符所需的转换。 

该循环使用以下方法逐个位置处理两个字符串`zip`。 对于每个字符对：

 - 如果源字符已经有映射，我们将验证一致性。 
- 如果映射冲突，我们返回`False`。 
- 否则，我们记录映射。 

验证映射规则后，代码检查有多少个不同的字符出现在`str2`。 

如果使用的唯一字符少于 26 个，则至少存在一个备用字符，从而可以安全地解析循环转换。 

如果使用所有 26 个字母，则转换是不可能的，除非字符串已经相同（我们之前处理过）。 

## 解决方案```go
func canConvert(str1 string, str2 string) bool {
    if str1 == str2 {
        return true
    }

    charMap := make(map[byte]byte)

    for i := 0; i < len(str1); i++ {
        sourceChar := str1[i]
        targetChar := str2[i]

        if mappedChar, exists := charMap[sourceChar]; exists {
            if mappedChar != targetChar {
                return false
            }
        } else {
            charMap[sourceChar] = targetChar
        }
    }

    distinctChars := make(map[byte]bool)

    for i := 0; i < len(str2); i++ {
        distinctChars[str2[i]] = true
    }

    return len(distinctChars) < 26
}
```Go 实现遵循与 Python 版本相同的逻辑。 

主要区别在于 Go 字符串被索引为字节数组，因为输入仅包含小写英文字母。 这避免了任何 Unicode 复杂性。 

映射存储使用`map[byte]byte`，并且不同字符计数是使用实现的`map[byte]bool`。 

Go 没有内置的集合类型，因此布尔映射可以作为集合的替代。

 ## 边缘情况

 ### 字符串已经相等

 如果`str1`和`str2`相同，答案总是`true`因为允许零操作。 

这种边缘情况很重要，因为即使使用了所有 26 个字母，也不需要进行任何转换。 仅检查不同字符计数的幼稚实现可能会错误地返回`false`。 

该实现通过立即提前返回来处理此问题：```
if str1 == str2:
    return True
```### 一个字符映射到多个目标

 考虑：```
str1 = "aa"
str2 = "bc"
```第一个`'a'`需要成为`'b'`，而第二个`'a'`需要成为`'c'`。 

这是不可能的，因为转换同时影响所有发生的事件。 

该实现通过将映射存储在哈希映射中并在每次相同的源字符再次出现时验证一致性来检测这一点。 

### 完整字母循环

 考虑：```
str1 = "abcdefghijklmnopqrstuvwxyz"
str2 = "bcdefghijklmnopqrstuvwxyza"
```这就形成了一个完整的26个字符的循环。 

为了安全地执行转换，我们需要一个临时未使用的字符，但所有 26 个小写字母已经存在于`str2`。 

如果没有多余的存储空间，信息将在转换过程中被覆盖。 

实现通过检查正确处理此问题：```
len(set(str2)) < 26
```如果使用了全部 26 个字符并且字符串不相同，则答案必须是`false`。
