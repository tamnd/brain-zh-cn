[LeetCode 第 1170 题](https://leetcode.com/problems/compare-strings-by-Frequency-of-the-smallest-character/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、字符串、二分查找、排序

 ## 解决方案

 ## 问题理解

 问题定义了一个函数`f(s)`对于非空字符串`s`。 此函数返回字符串中字典顺序最小字符的频率。 

例如：

-`f("dcce") = 2`- 最小的字符是`'c'`-`'c'`出现2次

 我们有两个数组：

 -`queries`，包含查询字符串
 -`words`，包含参考字符串

 对于每个查询字符串`queries[i]`，我们必须计算有多少个字符串`W`在`words`满足：$$f(queries[i]) < f(W)$$结果应该是一个整数数组，其中每个位置包含相应查询的计数。 

问题的重要部分是我们没有直接比较字符串。 我们只比较函数产生的频率值`f`。 

限制相对较小：

 - 最多 2000 个查询
 - 最多 2000 字
 - 最大字符串长度仅为 10

 这些限制允许采用多种方法，包括暴力破解。 然而，使用排序和二分搜索的更优化方法明显更干净且更具可扩展性。 

一个关键的观察结果是，最大可能频率仅为 10，因为字符串的长度最多为 10。即便如此，标准最优解决方案使用排序加二分搜索，这可以很好地概括并展示重要的算法模式。 

一些边缘情况很重要：

 - 每个字符都相同的字符串，例如`"aaaa"`- 最小字符仅出现一次的字符串
 - 多个单词产生相同的频率
 - 大于所有词频的查询
 - 小于所有词频的查询

 该问题保证所有字符串都是非空的并且只包含小写英文字母，因此我们永远不需要处理空字符串或无效字符。 

## 方法

 ### 蛮力方法

 最直接的解决办法是：

 1. 计算`f(s)`对于每个查询。 
2. 计算`f(w)`对于每一个字。 
3.对于每个查询频率，扫描所有词频并统计有多少个较大。 

这种方法是正确的，因为它显式检查问题陈述所需的每个有效比较。 

计算`f(s)`:

 - 找到字符串中最小的字符。 
- 数一下它出现了多少次。 

如果有`Q`查询和`W`换句话说，暴力比较阶段需要`O(Q × W)`时间。 

考虑到限制，这个解决方案在实践中实际上是可以接受的：$$2000 \times 2000 = 4,000,000$$然而，我们可以在概念上做得更好。 

### 最佳方法

 关键的见解是我们反复问同一类型的问题：

 > 有多少词频大于给定的查询频率？ 

我们不必每次都扫描所有词频，而是可以：

 1. 预先计算所有词频。 
2. 对它们进行排序。 
3. 对每个查询使用二分搜索。 

排序后，二分查找可以快速找到词频严格大于查询频率的第一个位置。 

如果该索引是`idx`， 然后：$$\text{answer} = \text{len(words)} - idx$$这将重复的线性扫描转换为对数搜索。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(Q × W + QL + WL) | O(W) | 直接将每个查询与每个单词进行比较 |
 | 最佳| O(W log W + Q log W + QL + WL) | O(W log W + Q log W + QL + WL) | O(W) | 使用排序和二分搜索进行高效查找 |

 这里：

-`Q`= 查询数
 -`W`= 字数
 -`L`= 最大字符串长度，最多 10

 ## 算法演练

 1. 定义辅助函数`frequency(s)`计算`f(s)`。 

该函数查找字符串中按字典顺序最小的字符并计算它出现的次数。 由于字符串非常短，因此简单的扫描就足够了。 
2. 计算所有单词的频率。 

对于中的每个字符串`words`，计算其频率值并将其存储在列表中。 

例子：```
words = ["a", "aa", "aaa", "aaaa"]
frequencies = [1, 2, 3, 4]
```3.对词频进行排序。 

排序可以实现二分查找。 排序后，所有较大的频率都会出现在任何给定位置的右侧。 
4. 独立处理每个查询。 

对于每个查询：

 - 计算其频率。 
- 使用二分查找查找第一个严格大于查询频率的词频。 
5. 计算较大频率的数量。 

如果二分查找返回索引`idx`，那么来自的每个元素`idx`向前更大。 

所以：```
count = len(word_frequencies) - idx
```6. 存储每个查询的结果。 

将计算出的计数附加到答案数组中。 

### 为什么它有效

 排序后的词频数组保持了一个不变量，即某个位置右侧的所有频率都大于或等于当前值。 

二分查找找到第一个位置：$$f(word) > f(query)$$该索引之后的每个频率也满足该条件。 因此，从总字数中减去索引就可以得到所需的计数。 

## Python 解决方案```python
from typing import List
from bisect import bisect_right

class Solution:
    def numSmallerByFrequency(self, queries: List[str], words: List[str]) -> List[int]:
        
        def frequency(s: str) -> int:
            smallest_char = min(s)
            return s.count(smallest_char)

        word_frequencies = [frequency(word) for word in words]
        word_frequencies.sort()

        result = []

        for query in queries:
            query_frequency = frequency(query)

            index = bisect_right(word_frequencies, query_frequency)

            result.append(len(word_frequencies) - index)

        return result
```辅助函数`frequency`直接实现定义`f(s)`从问题陈述中。 它首先使用确定最小的字符`min(s)`然后计算它出现的次数。 

接下来，该解决方案预先计算所有频率`words`并对它们进行排序。 此预处理步骤至关重要，因为它允许稍后进行高效的二分搜索。 

对于每个查询，代码都会计算其频率并使用`bisect_right`在所有小于或等于查询频率的值之后找到插入点。 这给出了包含严格更大频率的第一个索引。 

最后，有效单词数计算如下：```python
len(word_frequencies) - index
```这是有效的，因为插入点右侧的每个值都严格更大。 

## 解决方案```go
package main

import (
	"sort"
)

func numSmallerByFrequency(queries []string, words []string) []int {

	frequency := func(s string) int {
		smallest := byte('z')

		for i := 0; i < len(s); i++ {
			if s[i] < smallest {
				smallest = s[i]
			}
		}

		count := 0

		for i := 0; i < len(s); i++ {
			if s[i] == smallest {
				count++
			}
		}

		return count
	}

	wordFrequencies := make([]int, len(words))

	for i, word := range words {
		wordFrequencies[i] = frequency(word)
	}

	sort.Ints(wordFrequencies)

	result := make([]int, len(queries))

	for i, query := range queries {

		queryFrequency := frequency(query)

		index := sort.Search(
			len(wordFrequencies),
			func(j int) bool {
				return wordFrequencies[j] > queryFrequency
			},
		)

		result[i] = len(wordFrequencies) - index
	}

	return result
}
```Go 实现遵循与 Python 解决方案相同的算法结构。 

而不是Python的`bisect_right`, Go 使用`sort.Search`。 搜索条件找到词频严格大于查询频率的第一个索引。 

Go 字符串是字节索引的，这在这里工作得很好，因为输入只包含小写英文字母。 

该实现始终使用切片，并且没有特殊处理`nil`是必需的，因为空切片的行为正确`len`。

 ## 边缘情况

 当查询频率大于每个词频时，就会出现一种重要的边缘情况。 在这种情况下，二分查找会返回数组的长度，因为不存在更大的值。 实现正确计算：```
len(word_frequencies) - len(word_frequencies) = 0
```这会产生预期的答案。 

另一个重要的边缘情况是当许多词频等于查询频率时。 该问题需要严格更高的频率，而不是大于或等于。 使用`bisect_right`在Python和`>`Go 中的条件确保在计算较大值之前正确跳过所有相等值。 

第三种边缘情况涉及每个字符都相同的字符串，例如`"aaaa"`或者`"bbbb"`。 在这些情况下，最小字符频率等于整个字符串长度。 辅助函数自然地处理这个问题，因为`min(s)`返回重复的字符并`count()`返回完整长度。 

当最小的字符多次出现但不是字符串中的第一个字符时，就会出现微妙的边缘情况。 例如：```
"dcce"
```最小的字符是`'c'`， 不是`'d'`。 有缺陷的实现可能会错误地计算第一个字符或假设排序顺序。 辅助函数在计数之前显式计算最小字符，这保证了无论字符排列如何的正确性。
