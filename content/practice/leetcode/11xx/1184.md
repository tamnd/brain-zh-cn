[LeetCode 1184 题](https://leetcode.com/problems/distance- Between-bus-stops/)

 **难度：** 🟢简单
 **主题：** 数组

 ## 解决方案

 ## 问题理解

 在这个问题中，我们给出了一条循环巴士路线`n`停靠站编号为`0`到`n - 1`。 数组`distance`描述相邻站点之间的距离。 具体来说，`distance[i]`表示距车站的距离`i`停止`(i + 1) % n`。 

由于路线是环形的，因此巴士可以在任意两个站点之间沿两个可能的方向行驶：

 - 顺时针
 - 逆时针方向

 任务是计算两个点之间的最短距离`start`停止并且`destination`停止。 

例如，如果：```
distance = [1,2,3,4]
```那么：

 - 距离`0 -> 1`是`1`- 距离`1 -> 2`是`2`- 距离`2 -> 3`是`3`- 距离`3 -> 0`是`4`如果我们想从车站出发`0`停止`2`，有两条路线：

 - 顺时针：`0 -> 1 -> 2`，总距离`1 + 2 = 3`- 逆时针：`0 -> 3 -> 2`，总距离`4 + 3 = 7`因此最短距离是`3`。 

限制相对较小：

 -`n <= 10^4`- 每个距离值最多为`10^4`这告诉我们，即使是`O(n)`解决方案足够快。 输入大小不够大，不需要高级优化技术。 

有几个重要的边缘情况需要记住：

 -`start`可能大于`destination`-`start`和`destination`可能是相邻的
 - 最短路径实际上可能是逆时针路线
 - 某些距离可能是`0`- 总路线可能只包含一站

 该问题保证所有停止索引都是有效的，并且`distance`数组长度与停靠点数量匹配。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是显式模拟双向行驶。 

我们可以：

 1. 顺时针移动`start`到`destination`, 累积距离
 2. 逆时针移动`start`到`destination`, 累积距离
 3. 返回较小的总数

 这种方法是正确的，因为路线是环形的，这意味着任意两个站点之间恰好有两条唯一的路径。 

尽管这可行，但实现可能会变得有点混乱，因为逆时针遍历需要仔细的模块化算术和环绕处理。 

运行时间仍然是线性的，因为每次遍历最多接触`n`停止。 

### 最佳方法

 关键的观察结果是，两个路径距离之和始终等于圆的总周长。 

我们可以：

 1. 计算沿一个方向的距离
 2.计算整个圆的总距离
 3. 推导相反方向距离为：```
total_distance - forward_distance
```然后我们简单地返回两者中的最小值。 

额外的简化是为了确保：```
start <= destination
```这使我们能够使用简单的范围总和来计算前进距离。 

这种方法简洁、高效且易于推理。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(1) | O(1) | 直接模拟顺时针和逆时针遍历 |
 | 最佳| O(n) | O(1) | O(1) | 计算一条路径并使用总和导出另一条路径 |

 ## 算法演练

 1. 首先，确保`start`小于或等于`destination`。 

这种标准化简化了遍历逻辑。 如果`start > destination`，我们交换它们。 交换后，顺时针路线从`start`到`destination`对应于连续子数组：```
distance[start:destination]
```2. 计算绕圆的总距离。 

我们将所有值相加`distance`大批。 这代表了路线的完整圆周。 
3. 计算顺时针距离。 

我们将与索引的所有距离相加`start`最多但不包括`destination`。 

这给出了直接向前穿过阵列时的距离。 
4. 计算逆时针距离。 

由于整圈距离已知，所以对向路线距离为：```
total_distance - clockwise_distance
```5. 返回较小的值。 

最短路径必须是两个可能方向之一，因此我们返回：```
min(clockwise_distance, counterclockwise_distance)
```### 为什么它有效

 环形路线始终在两个站点之间提供两条不同的路径。 每条边都属于这两条路径之一。 所以：```
clockwise_distance + counterclockwise_distance = total_circle_distance
```通过计算一条路径并从总数中减去，我们可以准确地获得另一条路径。 取最小值保证最短的有效路径。 

## Python 解决方案```python
from typing import List

class Solution:
    def distanceBetweenBusStops(self, distance: List[int], start: int, destination: int) -> int:
        if start > destination:
            start, destination = destination, start

        clockwise_distance = sum(distance[start:destination])
        total_distance = sum(distance)

        counterclockwise_distance = total_distance - clockwise_distance

        return min(clockwise_distance, counterclockwise_distance)
```实现首先对索引进行标准化，以便`start <= destination`。 这允许将顺时针路径直接表示为数组的连续切片。 

接下来，代码使用以下方法计算顺时针距离：```python
sum(distance[start:destination])
```这是有效的，因为每个元素代表连续停靠点之间的边缘。 

然后使用以下公式计算总圆距离`sum(distance)`。 

由于逆时针路径包含所有剩余的边，因此它的距离很简单：```python
total_distance - clockwise_distance
```最后，该算法返回两个可能路径长度中较小的一个。 

## 解决方案```go
func distanceBetweenBusStops(distance []int, start int, destination int) int {
    if start > destination {
        start, destination = destination, start
    }

    clockwiseDistance := 0
    totalDistance := 0

    for i, d := range distance {
        totalDistance += d

        if i >= start && i < destination {
            clockwiseDistance += d
        }
    }

    counterclockwiseDistance := totalDistance - clockwiseDistance

    if clockwiseDistance < counterclockwiseDistance {
        return clockwiseDistance
    }

    return counterclockwiseDistance
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 由于 Go 不提供像 Python 那样的内置切片求和实用程序`sum()`，该实现在单个循环内计算两个总计。 

Go 切片是基于引用的，但这个问题只需要读取值，因此不存在突变问题。 整数溢出不是问题，因为最大可能的总距离完全在 Go 的范围内`int`范围。

 ## 边缘情况

 ### 起点和目的地相同

 如果`start == destination`，最短距离应该是`0`因为不需要旅行。 

有缺陷的实现可能会意外地遍历整个圆并返回总距离。 在此解决方案中，切片：```
distance[start:destination]
```变空，产生顺时针距离`0`，这正确地得出最终答案`0`。 

### 起始索引大于目标索引

 例如：```
start = 3
destination = 1
```如果没有标准化，计算顺时针路径就会变得很尴尬，因为遍历会绕到数组的末尾。 

该实现通过在以下情况下交换值来避免这种复杂性：`start > destination`。 这将问题转化为简单的连续范围和。 

### 最短路径是逆时针方向

 一个常见的错误是假设直接向前遍历始终是最佳的。 

例如：```
distance = [1,2,3,4]
start = 0
destination = 3
```顺时针方向的路线是：```
1 + 2 + 3 = 6
```但逆时针路线只有：```
4
```该算法通过显式比较两种可能的路线距离来正确处理此问题。
