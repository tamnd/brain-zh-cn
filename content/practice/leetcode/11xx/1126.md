 # LeetCode 1126 - 活跃企业

 ## 问题理解

 该问题给了我们一个名为`Events`。 每行代表特定业务发生某种类型事件的次数。 

该表包含三列：

 | 专栏 | 意义|
 | ---| ---|
 |`business_id`| 企业的标识符|
 |`event_type`| 活动类别 |
 |`occurrences`| 该事件发生的次数 |

 这对`(business_id, event_type)`是唯一的，这意味着企业对于给定的事件类型只能有一行。 

关键概念是事件类型的平均活动的定义。 对于每一个不同的`event_type`，我们计算平均值`occurrences`包含该事件的所有企业。 

计算出这些平均值后，我们必须确定哪些企业被认为是活跃的。 如果一个企业有不止一种事件类型且其自己的事件类型是活跃的`occurrences`值严格大于该事件类型的平均值。 

输出应仅包含`business_id`活跃企业的价值观。 

举个例子：

 | 业务_id | 事件类型 | 事件 |
 | ---| ---| ---|
 | 1 | 评论 | 7 |
 | 3 | 评论 | 3 |

 平均值为`reviews`是：$$(7 + 3) / 2 = 5$$商业`1`有`7`，大于`5`，因此这算作一种合格事件类型。 

我们对每种事件类型重复此过程，并计算每个企业超过平均值的事件类别数。如果计数大于 1，则该企业属于结果。 

问题约束没有明确列出，但由于这是一个 SQL/数据库问题，因此预期的解决方案应该避免不必要的重复扫描表。 高效的聚合和分组操作非常重要。 

一些边缘情况很重要：

 - 企业可能仅在一种事件类型上超过平均水平，但这还不够。 
- 企业可能有多种事件类型，但没有一个高于平均水平。 
- 事件平均值可能是小数值，因此比较必须正确处理小数。 
- 等于平均水平的企业不符合资格，因为比较严格来说更大。 
- 某些事件类型可能仅针对一项业务出现。 在这种情况下，平均值等于该企业的价值，因此它不能超过平均值。 

## 方法

 ### 蛮力方法

 强力解决方案将在检查每个业务时重复计算每个事件类型的平均值。 

对于表中的每一行：

 1. 扫描整个表以计算该行的平均值`event_type`。 
2. 比较行的`occurrences`对照计算出的平均值。 
3. 跟踪每个企业超出平均水平的事件类型数量。 
4. 返回数量超过1个的商家。 

此方法是正确的，因为每一行都会与其事件类型的真实平均值进行比较。 然而，它的效率很低，因为相同的平均值被重新计算了很多次。 

如果有`n`行，并且每一行都需要再次全表扫描，时间复杂度变为`O(n²)`。 

### 最佳方法

 关键的观察结果是每个`event_type`只需要计算一次。 

而不是重复重新计算平均值：

 1. 首先计算每种事件类型的平均发生次数。 
2. 将这些平均值与原始表连接起来。 
3.统计每项业务超过相应事件平均值的次数。 
4. 仅保留数量大于 1 的企业。 

这将重复的工作转化为少量的聚合操作。 

在 SQL 中，这很自然地用以下方式表达：

 - 用于计算平均值的分组子查询或公共表表达式 (CTE)。 
- 平均值和原始表之间的连接。 
- 第二个分组步骤，用于计算每个企业的合格事件类型。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n²) | O(1) 或 O(n) | 重复重新计算平均值 |
 | 最佳| O(n) | O(k) | 计算每个事件的平均值一次，其中`k`是事件类型的数量 |

 ## 算法演练

 1. 计算每个事件的平均出现次数`event_type`。 

我们对行进行分组`event_type`并计算：$$AVG(occurrences)$$这会生成一个小的派生表，其中每个事件类型都与其平均活动相关联。 
2. 将平均值连接回原始值`Events`桌子。 

对于每个原始行，我们现在知道：

 - 企业发生的事件
 - 该事件类型的平均发生次数

 这允许直接比较。 
3. 过滤业务超出平均水平的行。 

我们只让行满足：```
occurrences > avg_occurrences
```这可以识别业务表现高于平均水平的事件类型。 
4. 对筛选后的行进行分组`business_id`。 

剩余的每一行代表一种合格的事件类型。 分组使我们能够计算每个企业有多少合格事件类型。 
5. 仅保留拥有超过一种合格活动类型的企业。 

我们申请：```
HAVING COUNT(*) > 1
```这些都是问题所需要的活跃业务。 

### 为什么它有效

 该算法之所以有效，是因为每个事件类型平均值只计算一次，然后一致地用于参与该事件类别的所有企业。 

过滤行后，其中`occurrences`超过相应的平均值，则剩余的每一行代表该企业的一种有效的合格事件类型。 对每个业务的行进行计数可以直接给出业务高于平均水平的事件类型的数量。 最终条件`COUNT(*) > 1`完全符合活跃业务的定义。 

## Python 解决方案```
from typing import List
import pandas as pd

def active_businesses(events: pd.DataFrame) -> pd.DataFrame:
    event_averages = (
        events.groupby("event_type")["occurrences"]
        .mean()
        .reset_index(name="avg_occurrences")
    )

    merged = events.merge(event_averages, on="event_type")

    above_average = merged[
        merged["occurrences"] > merged["avg_occurrences"]
    ]

    result = (
        above_average.groupby("business_id")
        .size()
        .reset_index(name="count")
    )

    result = result[result["count"] > 1]

    return result[["business_id"]]
```实现严格遵循算法。 

第一部分使用以下方法计算每种事件类型的平均发生次数`groupby`和`mean`。 这将创建一个临时表，其中每个事件类型包含一行。 

接下来，代码将这些平均值合并回原始数据帧。 合并后，每行包含对应事件类型的业务发生次数和平均发生次数。 

过滤步骤仅保留业务发生次数严格大于平均值的行。 

过滤后，代码按以下方式对行进行分组`business_id`并计算每个企业有多少合格事件类型。 

最后，仅返回具有超过一种合格事件类型的企业。 

## 解决方案```
package main

import "database/sql"

func activeBusinesses(db *sql.DB) (*sql.Rows, error) {
	query := `
	WITH event_avg AS (
		SELECT
			event_type,
			AVG(occurrences) AS avg_occurrences
		FROM Events
		GROUP BY event_type
	)
	SELECT
		e.business_id
	FROM Events e
	JOIN event_avg a
		ON e.event_type = a.event_type
	WHERE e.occurrences > a.avg_occurrences
	GROUP BY e.business_id
	HAVING COUNT(*) > 1
	`

	return db.Query(query)
}
```Go 解决方案与 Python 解决方案不同，因为 LeetCode 数据库问题本质上是 SQL 问题。 在 Go 中，逻辑直接嵌入到 SQL 查询中。 

名为的公用表表达式`event_avg`计算每种事件类型的平均发生次数。 然后，查询将这些平均值与原始表连接起来，过滤高于平均值的行，按业务进行分组，并应用`HAVING COUNT(*) > 1`健康）状况。 

由于 SQL 在内部处理聚合，因此不需要额外的特定于 Go 的数据结构。

 ## 边缘情况

 ### 事件发生率等于平均值

 一个常见的错误是使用`>=`而不是`>`。 该问题明确要求出现次数严格大于平均值。 

例如，如果某个事件类型出现两次并带有值`[5, 5]`，平均值为`5`，并且这两家企业都不符合资格。 实现正确使用：```
occurrences > avg_occurrences
```其中排除相等的值。 

### 仅包含一项业务的事件类型

 如果某一事件类型仅针对一个企业出现，则平均值等于该企业自身的发生次数。 由于没有任何值可以严格大于其自身，因此该事件类型永远不会有助于使业务活跃。 

实现自然会处理这个问题，因为比较会自动失败。 

### 仅在一个类别中获得商业资格

 该问题需要不止一种合格事件类型。 幼稚的实施可能会错误地包括具有一项合格赛事的企业。 

分组和过滤步骤：```
HAVING COUNT(*) > 1
```确保仅返回超过至少两种事件类型平均值的企业。 

### 分数平均值

 平均值不保证为整数。 例如：$$(3 + 12) / 2 = 7.5$$使用整数除法的实现可能会错误地截断值并产生错误的比较。 

SQL`AVG()`函数和 Pandas`mean()`函数都保留小数精度，因此实现可以正确处理小数平均值。
