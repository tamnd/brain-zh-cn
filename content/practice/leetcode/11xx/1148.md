[LeetCode 第 1148 题](https://leetcode.com/problems/article-views-i/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 问题是要求我们识别所有至少查看过自己的一篇文章的作者。 输入是数据库表`Views`其中包含有关文章、作者、查看者以及查看文章的日期的信息。 每行表示单个查看事件，并且可能存在重复行，这意味着同一查看者可能会在同一日期针对同一篇文章多次出现。 

输出应该是包含单列的表`id`，代表`author_id`看过自己文章的人。 该输出必须按升序排序。 关键的限制是，当作者查看自己的文章时，会被指示`author_id`匹配`viewer_id`。 重复的行不应影响输出，这意味着每个作者只应出现一次。 

重要的边缘情况包括没有作者查看自己的文章、同一作者-查看者对存在多个重复项或所有作者仅查看其他人的文章的情况。 该问题保证了`author_id`和`viewer_id`是整数并且`Views`表可能包含重复的条目。 

## 方法

 蛮力方法是迭代所有行，并针对每个作者，检查是否存在任何行`author_id`等于`viewer_id`。 我们可以维护一个集合来存储满足这个条件的作者以避免重复。 这种方法是正确的，因为它直接检查每一行的条件。 然而，手动迭代所有行可能不是最有效的，尤其是对于大型数据集，因为我们对每一行执行比较，而没有利用 SQL 的内置过滤和分组功能。 

最佳方法是使用 SQL`SELECT DISTINCT`查询`WHERE`直接过滤行 where 的子句`author_id = viewer_id`。 使用`DISTINCT`确保重复的条目不会出现在输出中，并且`ORDER BY`保证升序。 这种方法利用数据库引擎的优化过滤和排序，即使对于大型数据集也非常高效。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(n) | 迭代所有行，如果作者查看自己的文章，则将其存储在一组中 |
 | 最佳 | O(n log n) | O(n log n) | O(n) | SQL 引擎高效处理过滤、重复数据删除和排序 |

 ## 算法演练

 1. 首先查询`Views`行表，其中`author_id`等于`viewer_id`。 这确保我们只考虑作者查看自己文章的视图。 
2. 使用`DISTINCT`消除重复行，其中同一作者可能会在同一篇文章或日期中多次出现。 
3. 对结果集进行排序`author_id`s 按升序排列使用`ORDER BY`。 
4. 将排序后的集合作为单列结果表返回，其中列名为`id`。 

这是有效的，因为条件`author_id = viewer_id`这正是作者查看自己文章的定义。 使用`DISTINCT`确保重复的视图记录不会导致输出中出现重复的条目。 排序可确保输出与问题所需的顺序相匹配。 

## Python 解决方案```python

import sqlite3
from typing import List, Tuple

def authors_who_viewed_their_own_articles(views: List[Tuple[int, int, int, str]]) -> List[int]:
    result_set = set()
    for article_id, author_id, viewer_id, view_date in views:
        if author_id == viewer_id:
            result_set.add(author_id)
    return sorted(result_set)
```在此 Python 实现中，我们迭代每个视图记录，检查作者是否查看了自己的文章，并将符合条件的作者存储在一个集合中以避免重复。 最后，我们返回一个排序列表。 

## 解决方案```go
package main

import (
    "sort"
)

func authorsWhoViewedOwnArticles(views [][]interface{}) []int {
    authorSet := make(map[int]struct{})
    for _, view := range views {
        authorID := view[1].(int)
        viewerID := view[2].(int)
        if authorID == viewerID {
            authorSet[authorID] = struct{}{}
        }
    }
    result := make([]int, 0, len(authorSet))
    for id := range authorSet {
        result = append(result, id)
    }
    sort.Ints(result)
    return result
}
```在Go中，我们使用地图来模拟一个集合，存储查看自己文章的作者。 收集所有相关作者后，我们将地图键转换为切片并在返回之前对其进行排序。 这种方法反映了 Python 解决方案，但使用了 Go 特定的构造。 

## 工作示例

 对于示例输入：```
Views table:
+------------+-----------+-----------+------------+
| article_id | author_id | viewer_id | view_date  |
+------------+-----------+-----------+------------+
| 1          | 3         | 5         | 2019-08-01 |
| 1          | 3         | 6         | 2019-08-02 |
| 2          | 7         | 7         | 2019-08-01 |
| 2          | 7         | 6         | 2019-08-02 |
| 4          | 7         | 1         | 2019-07-22 |
| 3          | 4         | 4         | 2019-07-21 |
| 3          | 4         | 4         | 2019-07-21 |
+------------+-----------+-----------+------------+
```迭代和检查：

 1. 第 1 行：作者 3 ≠ 观看者 5 → 跳过
 2. 第 2 行：作者 3 ≠ 观看者 6 → 跳过
 3. 第 3 行：作者 7 = 观看者 7 → 添加 7
 4. 第 4 行：作者 7 ≠ 观看者 6 → 跳过
 5. 第 5 行：作者 7 ≠ 观看者 1 → 跳过
 6. 第 6 行：作者 4 = 查看者 4 → 添加 4
 7. 第 7 行：作者 4 = 观看者 4 → 已在集合中，跳过

 最终集合：{4, 7}，已排序 → [4, 7]

 ## 边缘情况

 一个边缘情况是空的`Views`桌子。 该函数必须返回一个空列表，因为没有要检查的作者。 

另一个边缘情况是所有行都包含从未查看过自己文章的作者的视图。 不检查的幼稚实现`author_id = viewer_id`可能会错误地包含作者。 

第三种边缘情况是同一作者-查看者对有多个重复行。 实现必须避免多次返回同一作者。 使用集合或 SQL`DISTINCT`确保正确处理此问题。
