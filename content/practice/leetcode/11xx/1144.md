[LeetCode 第 1144 题](https://leetcode.com/problems/decrease-elements-to-make-array-zigzag/)

 **难度：** 🟡 中等
 **主题：** 数组、贪心

 ## 解决方案

 ## 问题理解

 问题给出一个整数数组`nums`并且只允许一种类型的操作，将任何元素减少`1`。 我们可以根据需要对任何元素执行此操作多次。 

我们的目标是将数组转变为移动次数最少的锯齿形数组。 

锯齿形数组可以遵循两种有效模式之一：

 1. 即使指数也是峰值：`nums[0] > nums[1] < nums[2] > nums[3] < nums[4] ...`2. 奇数指数是峰值：`nums[0] < nums[1] > nums[2] < nums[3] > nums[4] ...`我们可以自由选择需要较少总减少的模式。 

重要的细节是我们只能减少值。 永远不允许增加元素。 这个限制完全改变了策略，因为如果一个元素相对于它的邻居太小，我们就不能提高它，我们必须减少周围的值。 

输入尺寸相对较小：

 -`1 <= nums.length <= 1000`-`1 <= nums[i] <= 1000`这些限制告诉我们，即使`O(n^2)`解决方案可能会通过，但我们仍然应该以干净的线性解决方案为目标。 

一个关键的观察结果是，每个位置仅取决于其直接邻居。 一个元素是否满足锯齿形要求可以通过与相邻值进行比较来局部确定。 

一些边缘情况很重要：

 - 长度数组`1`已经是锯齿形数组，因为没有相邻元素违反该模式。 
- 具有相等相邻值的数组需要减少，因为需要严格的不等式。 
- 边界元素只有一个邻居，因此比较必须仔细处理缺失的左或右邻居。 
- 大值是无害的，因为我们只执行算术差异。 

## 方法

 ### 蛮力方法

 蛮力策略将尝试通过重复调整元素直到满足所有不等式来模拟两种锯齿形图案。 

例如，我们可以重复扫描数组，每当一个位置违反 zigzag 条件时，就减少违规元素，直到条件有效。 我们将分别为以下目的执行此操作：

 - 甚至指数作为峰值
 - 奇数指数作为峰值

 这最终会产生一个有效的锯齿形数组，因为减小值总是可以修复违规问题。 

然而，这种方法效率低下，因为一次一步地重复递减元素可能需要多次操作。 由于值可以大到`1000`，模拟可能会执行不必​​要的重复工作。 

关键的低效率是我们实际上不需要单独模拟每个减量。 我们可以直接计算出每个位置需要多少减少。 

### 最优贪心法

 重要的见解是，一旦我们决定哪个奇偶性应包含山谷，就可以独立处理每个位置。 

假设我们想要索引`i`成为一个山谷。 那么它必须满足：```
nums[i] < left neighbor
nums[i] < right neighbor
```因为我们只允许减少值，所以保证这一点的唯一方法就是减少`nums[i]`本身。 

使`nums[i]`严格小于两个邻居，其最大允许值变为：```
min(left neighbor, right neighbor) - 1
```如果`nums[i]`已经比两个邻居都小了，不需要做任何工作。 

否则，所需的减少量为：```
nums[i] - (minNeighbor - 1)
```我们对每个山谷位置独立计算。 

我们评估两种情况：

 1. 即使指数也是低谷
 2. 奇数指数是山谷

 两种情况的总成本最小就是答案。 

这是有效的，因为每个山谷调整都是局部的，不会干扰其他山谷。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n * 最大(nums)) | O(1) | O(1) | 重复模拟递减 |
 | 最佳 | O(n) | O(1) | O(1) | 直接计算所需的减少量 |

 ## 算法演练

 1. 创建一个辅助函数，用于计算当所选奇偶性代表谷位置时所需的总移动量。 
2. 对于每个索引`i`与选定的奇偶校验：

 - 找到左邻居（如果存在）。 
- 找到正确的邻居（如果存在）。 
- 计算最小邻居值。 
3. 由于当前元素必须严格小于两个邻居元素，因此最大有效值为：```
minNeighbor - 1
```4. 如果`nums[i]`已经小于两个邻居，不需要移动。 
5. 否则，计算需要减少多少：```
nums[i] - (minNeighbor - 1)
```6. 将此值添加到运行总计中。 
7. 对所有谷位置重复此操作。 
8. 运行助手两次：

 - 一旦偶数指数为谷
 - 一次以奇数指数作为山谷
 9. 返回较小的结果。 

### 为什么它有效

 对于任何有效的锯齿形配置，一个奇偶校验必须包含所有波谷。 山谷只需要比其相邻的邻居小，因此其所需的调整仅取决于局部比较。 

由于减少一个谷值并不会使另一谷值要求无效，因此每个位置都可以独立优化。 因此，计算每个山谷所​​需的最小减少量会产生全局最小移动次数。 

## Python 解决方案```python
from typing import List

class Solution:
    def movesToMakeZigzag(self, nums: List[int]) -> int:
        n = len(nums)

        def calculate_moves(valley_parity: int) -> int:
            moves = 0

            for i in range(valley_parity, n, 2):
                left = nums[i - 1] if i > 0 else float('inf')
                right = nums[i + 1] if i + 1 < n else float('inf')

                min_neighbor = min(left, right)

                needed = max(0, nums[i] - (min_neighbor - 1))
                moves += needed

            return moves

        return min(calculate_moves(0), calculate_moves(1))
```实现直接遵循贪婪观察。 

辅助函数`calculate_moves`评估一种锯齿形配置。 参数`valley_parity`确定哪些指数应成为山谷。 

对于每个山谷位置，代码都会检索左右邻居。 缺失的邻居被视为正无穷大，因此边界元素仅与实际存在的邻居进行比较。 

最小相邻值决定当前元素的最大合法值。 如果当前元素已经有效，`max(0, ...)`确保不添加不必要的动作。 

最后，该算法计算两种可能的锯齿形图案的总成本并返回较小的一个。 

## 解决方案```go
func movesToMakeZigzag(nums []int) int {
	n := len(nums)

	calculateMoves := func(valleyParity int) int {
		moves := 0

		for i := valleyParity; i < n; i += 2 {
			left := 1 << 30
			right := 1 << 30

			if i > 0 {
				left = nums[i-1]
			}

			if i+1 < n {
				right = nums[i+1]
			}

			minNeighbor := left
			if right < minNeighbor {
				minNeighbor = right
			}

			needed := nums[i] - (minNeighbor - 1)
			if needed > 0 {
				moves += needed
			}
		}

		return moves
	}

	evenValleys := calculateMoves(0)
	oddValleys := calculateMoves(1)

	if evenValleys < oddValleys {
		return evenValleys
	}

	return oddValleys
}
```Go 实现密切反映了 Python 逻辑。 

由于 Go 没有内置的整数无穷大值，因此非常大的数字 (`1 << 30`) 用于丢失邻居。 

其余逻辑保持不变：

 - 评估两种奇偶校验配置
 - 本地计算所需的减少量
 - 返回最小总移动次数

 整数溢出不是问题，因为在问题约束下所有值仍然很小。

 ## 边缘情况

 一种重要的边缘情况是只有一个元素的数组。 由于没有相邻元素，数组自动满足两个 zigzag 定义。 粗心的实现可能会尝试无效的邻居访问。 该解决方案可以安全地处理这种情况，因为缺失的邻居被视为无穷大。 

另一个重要的情况是包含相等相邻值的数组，例如`[2,2,2]`。 Zigzag 要求使用严格的不等式，因此不允许相等。 该实现正确地计算了需要多少减量才能使一侧严格变小，方法是使用`minNeighbor - 1`。 

边界位置也很容易处理不当，因为它们只有一个邻居而不是两个。 例如，索引`0`没有左邻居，最后一个索引没有右邻居。 该算法通过为不存在的邻居分配无限值来干净地处理这个问题，确保只有真正的邻居影响减少计算。
