[LeetCode 第 1132 题](https://leetcode.com/problems/reported-posts-ii/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题要求我们计算被报告为垃圾邮件后被删除的帖子的平均每日百分比。 我们有两张表：`Actions`和`Removals`。 这`Actions`表记录用户与帖子的交互，包括查看、喜欢、分享、报告和其他反应。 这`extra`列包含有关操作的可选信息，例如报告的原因。 这`Removals`表格列出了已删除的帖子及其删除日期。 

关键要求是**仅关注具有以下内容的报告：`extra = 'spam'`**。 对于每天至少发生一个垃圾邮件报告的情况，我们计算最终被删除的报告帖子的百分比（我们不关心它们何时被删除，只关心它们是否出现在`Removals`桌子）。 最后，我们计算这些每日百分比的**平均值**，并将结果四舍五入到小数点后两位。 

边缘情况包括没有发生垃圾邮件报告的日子（这些应被忽略）、同一天同一帖子的多次报告（应计为单个帖子）以及已报告但从未删除的帖子（应计入当天删除百分比的 0%）。 

## 方法

 ### 蛮力方法

 一种简单的方法是每天迭代，提取所有报告为垃圾邮件的帖子，然后检查每个帖子是否存在于`Removals`桌子。 然后我们将计算当天的百分比，最后计算所有天的平均值。 虽然这种方法是正确的，但它涉及每天重复扫描两个表，这对于大型数据集来说可能非常昂贵。 

### 最佳方法

 最佳方法有效地利用 SQL 聚合。 首先，我们每天识别所有独特的垃圾邮件报告帖子。 接下来，我们使用一个`LEFT JOIN`到`Removals`以确定哪些帖子被删除。 我们通过计算删除的帖子占当天报告的帖子总数来计算每日百分比。 最后，我们取这些每日百分比的平均值。 这种方法通过使用聚合和连接来避免嵌套循环和重复扫描。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(D * P) | O(P)| 每天和每个帖子迭代，对于大表来说昂贵 |
 | 最佳| O(N) | O(N) | 使用SQL聚合和连接，每个表扫描一次 |

 ## 算法演练

 1. 过滤`Actions`表仅包含其中的行`action = 'report'`和`extra = 'spam'`。 这将提供所有垃圾邮件报告。 
2. 选择不同的`(action_date, post_id)`配对以删除同一帖子在同一天被多次报道的重复项。 
3. 将此结果与`Removals`桌上`post_id`使用`LEFT JOIN`。 这使我们能够确定哪些举报的帖子被删除。 
4. 分组依据`action_date`计算每天唯一报告帖子的总数和已删除的帖子数。 
5. 计算每日去除百分比为`(removed_posts / total_reported_posts) * 100`。 
6. 取所有每日百分比的平均值。 
7. 将结果四舍五入至小数点后两位。 

**为什么有效：** 通过按天汇总并仅考虑每天的独特帖子，我们确保每日百分比是准确的。 这`LEFT JOIN`确保未删除的帖子计入分母而不计入分子。 对这些每日百分比进行平均即可得出所需的最终结果。 

## Python 解决方案```python
import sqlite3

def average_daily_percent(connection: sqlite3.Connection) -> float:
    query = """
    WITH spam_reports AS (
        SELECT DISTINCT action_date, post_id
        FROM Actions
        WHERE action = 'report' AND extra = 'spam'
    ),
    daily_counts AS (
        SELECT 
            s.action_date,
            COUNT(s.post_id) AS total_reported,
            COUNT(r.post_id) AS removed_count
        FROM spam_reports s
        LEFT JOIN Removals r
        ON s.post_id = r.post_id
        GROUP BY s.action_date
    )
    SELECT ROUND(AVG(removed_count * 100.0 / total_reported), 2) AS average_daily_percent
    FROM daily_counts;
    """
    cursor = connection.cursor()
    cursor.execute(query)
    result = cursor.fetchone()[0]
    return result
```**说明：** 首先，`spam_reports`每天过滤并删除重复的垃圾邮件报告。`daily_counts`汇总每日总数和删除的计数。 最后，外部查询计算全天删除帖子的平均百分比。 

## 解决方案```go
import (
    "database/sql"
    _ "github.com/mattn/go-sqlite3"
    "fmt"
)

func AverageDailyPercent(db *sql.DB) (float64, error) {
    query := `
    WITH spam_reports AS (
        SELECT DISTINCT action_date, post_id
        FROM Actions
        WHERE action = 'report' AND extra = 'spam'
    ),
    daily_counts AS (
        SELECT 
            s.action_date,
            COUNT(s.post_id) AS total_reported,
            COUNT(r.post_id) AS removed_count
        FROM spam_reports s
        LEFT JOIN Removals r
        ON s.post_id = r.post_id
        GROUP BY s.action_date
    )
    SELECT ROUND(AVG(removed_count * 100.0 / total_reported), 2) AS average_daily_percent
    FROM daily_counts;
    `
    var result float64
    err := db.QueryRow(query).Scan(&result)
    if err != nil {
        return 0, err
    }
    return result, nil
}
```**Go 特定说明：** Go 在查询 SQL 时需要显式错误处理。 这`ROUND`函数的工作方式与 Python/SQL 中的相同。`QueryRow().Scan()`提取单个浮点结果。 

## 工作示例

 **示例1：**`Actions`过滤垃圾邮件报告的表格：```
2019-07-02: post 3
2019-07-04: post 2, post 4
```

`Removals`桌子：```
post 2 -> removed
post 3 -> removed
```每日清除百分比：```
2019-07-02: 1/1 = 100%
2019-07-04: 1/2 = 50%
```每日平均百分比 = (100 + 50) / 2 = 75.00

 ## 边缘情况

 **边缘情况 1：同一天每个帖子有多个报告**

 同一帖子可能会在同一天被多次举报。 如果没有重复数据删除，报告的总计数​​将会夸大，导致每日百分比低于应有的水平。 使用`SELECT DISTINCT`确保每个帖子每天只计算一次。 

**边缘案例 2：没有垃圾邮件报告的日子**

 在计算平均值时必须忽略没有垃圾邮件报告的天数。 否则，他们就会人为地降低平均值。 我们的`daily_counts`CTE 自动忽略没有条目的日期。 

**边缘情况 3：帖子被报告为垃圾邮件但从未删除**

 从未被删除的帖子应该对分母有所贡献，但对分子没有贡献。 使用`LEFT JOIN`确保已删除的帖子被计入在内，而未删除的帖子则不计入`removed_count`。 

该解决方案可以正确处理所有指定的边缘情况，确保准确计算每日百分比和总体百分比。
