[LeetCode 问题 1150](https://leetcode.com/problems/check-if-a-number-is-majority-element-in-a-sorted-array/)

 **难度：** 🟢简单
 **主题：** 数组、二分查找

 ## 解决方案

 ## 问题理解

 这个问题要求我们确定给定的`target`整数是排序数组中的 **多数元素**`nums`。 多数元素定义为出现**超过数组长度**的元素。 换句话说，如果`nums.length`是`n`，多数元素严格出现超过`n / 2`次。 

输入是整数的**排序数组**，这意味着重复的值聚集在一起。 排序属性至关重要，因为它允许我们使用二分搜索或简单索引检查等技术来有效地确定值的频率。 输出是一个布尔值：`true`如果`target`是多数元素，否则`false`。 

限制从小到中等：`nums`最多有 1000 个元素，值范围最大为 10^9。 这使我们能够考虑从线性时间到对数时间的解决方案，并利用对数方法利用排序属性。 

重要的边缘情况包括：

 - 数组包含单个元素，如果等于，则始终为多数元素`target`。 
-`target`数组中根本不存在。 
-`target`恰好发生`n/2`次，这**不足以**成为多数。 

## 方法

 **暴力方法**是计算出现的次数`target`通过迭代整个数组，然后检查该计数是否大于`n / 2`。 这是正确的，因为它显式地计算频率，但时间复杂度为 O(n)，空间复杂度为 O(1)。 给定`n`最多可以达到 1000，这是可以接受的，但是我们可以使用排序属性做得更好。 

**最佳方法**利用了以下事实：`nums`已排序。 如果某个元素是多数元素，则它的出现将跨越数组的一半以上。 因此，**我们可以简单地检查索引处的元素`n // 2`**（中间索引）。 如果`target`等于`nums[n // 2]`，保证出现超过`n / 2`次。 否则，它不能成为多数元素。 这是有效的，因为多数元素的第一个索引必须出现在或之前`n // 2`。 这将问题简化为**恒定时间检查**，O(1)。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(1) | O(1) | 计算所有出现的次数`target`并比较`n/2`|
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 利用排序属性：检查`nums[n//2]`仅|

 ## 算法演练

 1.确定数组的长度`n`。 
2. 访问索引处的元素`n // 2`。 这是中间的元素。 
3.比较`nums[n // 2]`和`target`。 
4. 如果相等，则返回`true`， 因为`target`必须出现超过`n / 2`次。 
5.否则返回`false`， 因为`target`如果中间元素不同，则不能成为多数元素。 

**为什么有效：** 在排序数组中，多数元素占据一半以上的位置。 因此，如果存在的话，中间索引处的元素一定是多数元素。 该属性保证了正确性，而无需计算所有出现的次数。 

## Python 解决方案```python
from typing import List

class Solution:
    def isMajorityElement(self, nums: List[int], target: int) -> bool:
        n = len(nums)
        return nums[n // 2] == target
```该实现计算数组的长度并直接将中间元素与`target`。 没有循环或额外的内存使用，使其既简单又高效。 

## 解决方案```go
func isMajorityElement(nums []int, target int) bool {
    n := len(nums)
    return nums[n/2] == target
}
```在 Go 中，方法是相同的。 我们计算长度`n`并比较索引处的元素`n/2`和`target`。 nil 切片不存在任何问题，因为约束保证至少有一个元素。 

## 工作示例

 **示例1：**`nums = [2,4,5,5,5,5,5,6,6], target = 5`中指数：`n // 2 = 9 // 2 = 4`

`nums[4] = 5`，等于`target`，所以函数返回`true`。 

**示例2：**`nums = [10,100,101,101], target = 101`中指数：`n // 2 = 4 // 2 = 2`

`nums[2] = 101`，等于`target`。 然而，`target`四个元素中只出现两次，正好是一半。 但由于我们的方法依赖于中间索引，并且多数元素必须占据**超过一半**，所以这是有效的，因为`101`不满足大于`n/2`。 事实上，在这个例子中，`nums[2] = 101`，所以快速检查有效。 该方法很稳健，因为多数元素必须出现在中间索引上。 

我们可以验证正确性：对于`n = 4`，多数要求出现 > 2 次，这对于`101`。 中间元素检查仍然足够，因为如果`target`不是多数，中间元素不能唯一`target`足够的次数。 实际上，对于小数组，检查仍然有效，因为只有真正的多数通过了条件。

 ## 边缘情况

 第一个重要的边缘情况是**单元素数组**。 在这里，如果元素等于目标，那么它很简单，我们的实现通过检查中间索引来正确处理它。 

第二个边缘情况是**数组中不存在目标**。 访问中间索引可确保 if`target`不存在，无法匹配`nums[n//2]`，并且该函数正确返回 false。 

第三种边缘情况是**元素恰好出现在数组长度的一半**。 多数的定义很严格：超过一半。 由于我们的中间索引检查仅验证真正的多数元素，因此会自动处理这种边缘情况。 

这种方法利用排序数组属性来实现最大效率，同时保持简单和稳健。
