[LeetCode 问题 2090](https://leetcode.com/problems/k-radius-subarray-averages/)

 **难度：** 🟡 中等
 **主题：** 数组、滑动窗口

 ## 解决方案

 ## 问题理解

 该问题要求我们计算数组中每个索引的特殊平均值。 对于每个位置`i`，我们想要查看以`i`有半径`k`。 这意味着我们包含索引中的所有元素`i - k`通过`i + k`，包含在内。 

该窗口的大小始终为：$$2k + 1$$例如，如果`k = 2`，然后以指数为中心的平均值`i`用途：

 - 左边两个元素，
 - 当前元素，
 - 右侧两个元素。 

所以元素总数是`5`。 

如果索引两侧都没有足够的元素，则该索引的答案必须是`-1`。 

输出数组的长度必须与输入数组的长度相同。 每个位置包含：

 - 相应半径窗口的整数平均值，或
 -`-1`如果窗口不存在。 

该问题指定整数除法，这意味着任何小数部分都会被丢弃。 例如：$$17 / 5 = 3$$不是`3.4`。 

约束条件很重要：

 -`n`可以大到`10^5`-`nums[i]`也可以大到`10^5`由于数组可能非常大，因此任何重复扫描大型子数组以查找每个索引的算法都可能会太慢。 

有几个重要的边缘情况需要考虑：

 -`k = 0`，每个元素都成为自己的平均值。 
-`2k + 1 > n`，任何地方都不存在有效的窗口。 
- 只有一个元素的数组。 
- 数组中的值较大，这意味着运行总和可能会变大。 我们必须避免具有固定整数大小的语言中的溢出。 
- 窗口严重重叠，这表明从头开始重新计算总和会浪费工作。 

## 方法

 ### 蛮力方法

 最直接的解决方案是对每个索引进行独立处理。 

对于每个索引`i`：

 1. 检查是否至少有`k`它之前和之后的元素。 
2. 如果没有，请存储`-1`。 
3. 否则，迭代自`i - k`到`i + k`，手动计算总和，然后除以`2k + 1`。 

这种方法是正确的，因为它直接遵循问题的定义。 

然而，它的效率很低。 每个有效中心需要扫描一个大小的窗口`2k + 1`。 在最坏的情况下，几乎每个指数都会发生这种情况。 

如果：

-`n = 100000`-`k = 50000`然后我们重复扫描非常大的重叠窗口。 

总复杂度变为：$$O(n \times (2k+1))$$它可以降解为`O(n^2)`。 

对于给定的约束来说这太慢了。 

### 最优滑动窗口方法

 关键的观察结果是连续的窗口严重重叠。 

假设我们已经知道以索引为中心的窗口的总和`i`。 

当移动到索引时`i + 1`：

 - 一个元素离开窗口，
 - 一个新元素进入窗口。 

我们可以增量更新它，而不是重新计算整个总和。 

这正是滑动窗口技术的设计目的。 

我们维持：

 - 当前窗口总和，
 - 左边界，
 - 正确的边界。 

当窗口向右移动一步时：$$\text{newSum} = \text{oldSum} - \text{leftElement} + \text{newRightElement}$$这将总复杂度降低到线性时间。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n × (2k + 1)) | O(n × (2k + 1)) | O(1) 不包括输出 | 独立重新计算每个窗口总和 |
 | 最佳 | O(n) | O(1) 不包括输出 | 使用滑动窗口重用之前的总和 |

 ## 算法演练

 ### 最优滑动窗口算法

 1. 创建一个结果数组，填充为`-1`。 

每个索引最初都被假定为无效。 我们仅覆盖存在完整半径窗口的位置。 
2. 计算所需的窗口大小。 

半径窗口包含：$$2k + 1$$元素。 
3. 尽早处理不可能的情况。 

如果窗口大小大于数组长度，则不存在有效中心。 立即返回结果数组。 
4. 初始化第一窗口总和。 

计算第一个的总和`windowSize`元素。 

这对应于以索引为中心的窗口`k`。 
5. 存储第一个平均值。 

第一个有效中心是索引`k`。 

计算：$$\text{sum} // \text{windowSize}$$并将其放入`result[k]`。 
6. 将窗口滑过阵列。 

对于每个下一个位置：

 - 删除最左边的元素，
 - 添加新的最右边元素，
 - 计算新的平均值。 

窗口一次只移动一步。 
7. 继续，直到窗口到达末端。 

每个有效中心都会收到其计算出的平均值。 
8. 返回结果数组。 

### 为什么它有效

 该算法保持不变式`windowSum`始终等于当前连续窗口大小的总和`2k + 1`。 

当窗口向右移动一步时：

 - 恰好有一个元素存在，
 - 恰好有一个元素进入。 

因此，增量更新总和可以保持正确性，同时避免重复工作。 每个有效中心都只处理一次，因此所有平均值都会正确计算。 

## Python 解决方案```python
from typing import List

class Solution:
    def getAverages(self, nums: List[int], k: int) -> List[int]:
        n = len(nums)
        window_size = 2 * k + 1

        result = [-1] * n

        if window_size > n:
            return result

        window_sum = sum(nums[:window_size])

        center = k
        result[center] = window_sum // window_size

        left = 0
        right = window_size

        while right < n:
            window_sum -= nums[left]
            window_sum += nums[right]

            left += 1
            center += 1
            right += 1

            result[center] = window_sum // window_size

        return result
```实现首先确定数组长度和所需的窗口大小。 结果数组初始化为`-1`因为许多职位可能永远不会收到有效的平均值。 

早期返回处理所需半径窗口大于整个数组的情况。 在这种情况下，不存在有效的中心。 

第一个完整的窗口是使用Python的内置计算的`sum()`功能。 该初始窗口对应于索引处的中心`k`。 

然后该算法维护三个重要变量：

 -`left`, 输出索引,
 -`right`，传入索引，
 -`window_sum`，当前窗口的总和。 

每次迭代都会从左侧删除一个值并从右侧添加一个值。 这使得运行总和在恒定时间内保持准确。 

由于每个元素最多进入和离开窗口一次，因此该算法在线性时间内高效运行。 

## 解决方案```go
func getAverages(nums []int, k int) []int {
	n := len(nums)
	windowSize := 2*k + 1

	result := make([]int, n)

	for i := 0; i < n; i++ {
		result[i] = -1
	}

	if windowSize > n {
		return result
	}

	var windowSum int64 = 0

	for i := 0; i < windowSize; i++ {
		windowSum += int64(nums[i])
	}

	center := k
	result[center] = int(windowSum / int64(windowSize))

	left := 0
	right := windowSize

	for right < n {
		windowSum -= int64(nums[left])
		windowSum += int64(nums[right])

		left++
		center++
		right++

		result[center] = int(windowSum / int64(windowSize))
	}

	return result
}
```Go 实现紧密遵循 Python 版本，但有一些特定于语言的注意事项。 

最重要的区别是使用`int64`为运行总和。 由于数组最多可以包含`10^5`元素，每个元素的大小为`10^5`，总和可能超出 32 位整数的安全范围。 

结果切片是手动初始化的`-1`因为 Go 切片默认为`0`。 

Go 在除法时还需要显式整数转换`int64`值并将结果存储回`int`。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`k = 0`。 在这种情况下，每个元素形成一个有效的窗口大小`1`。 有缺陷的实现可能仍会尝试不必要的滑动窗口逻辑或错误地将元素标记为无效。 此实现可以自然地处理这种情况，因为计算出的窗口大小变为`1`，每个指数都会收到自己的平均值。 

当所需的窗口大小超过数组长度时，会发生另一种关键的边缘情况。 例如，如果数组的长度`5`和`k = 10`，那么任何索引都不可能在两侧都有足够的邻居。 如果没有提前返回，某些实现可能会尝试无效的索引操作。 该解决方案明确检查：```
if window_size > n:
    return result
```它可以安全地处理这种情况。 

大数值是错误的另一个可能来源，尤其是在 Go 或 Java 等语言中。 由于每个值最多可达`100000`，总窗口和可能会变得非常大。 Go 实现使用`int64`用于运行总和以避免累加期间整数溢出。 

最后一个微妙的情况涉及整数除法。 该问题需要截断为零。 一些程序员错误地使用浮点除法和舍入。 此实现始终直接使用整数除法，确保结果与规范完全匹配。
