[LeetCode 2015 问题](https://leetcode.com/problems/average-height-of-buildings-in-each-segment/)

 **难度：** 🟡 中等
 **主题：** 数组、排序、堆（优先级队列）、前缀和

 ## 解决方案

 ## 问题理解

 该问题将一条街道描述为一条数轴，每栋建筑物占据半闭区间`[start, end)`具有固定的高度。 多栋建筑物可能会重叠，对于街道上至少一栋建筑物覆盖的每个点，我们希望计算所有活动建筑物的平均高度。 

结果必须表示为非重叠段的最小数量。 每个段应包含一个连续范围，其中平均高度保持不变。 

重要的细节是建筑物使用半开间隔。 建筑物起始于`x`活跃于`x`，而建筑物结束于`x`在那里不再活跃。 这会影响当多个建筑物在同一坐标处开始或结束时事件的处理方式。 

例如：```
[1,4,2]
[3,9,4]
```之间`1`和`3`, 仅高度`2`存在。 

之间`3`和`4`，两座建筑物重叠，因此平均值变为：```
(2 + 4) / 2 = 3
```之间`4`和`9`, 仅高度`4`遗迹。 

限制条件很大：

 - 最多`10^5`建筑物
 - 坐标高达`10^8`这立即告诉我们，我们无法模拟数轴上的每个坐标。 坐标太大而且稀疏。 相反，我们需要一种基于事件或扫描线的方法，仅处理发生变化的位置。 

输出可以按任何顺序返回，但大多数实现自然会按排序顺序生成段。 

一些边缘情况很重要：

 - 多个建筑物可以在同一坐标处开始或结束。 
- 不同的重叠配置仍可能产生相同的平均值，从而允许相邻段合并。 
- 建筑物之间的空间隙不得出现在输出中。 
- 平均值必须使用整数除法。 
- 具有相同平均值的连续分段应合并为一个较大的分段。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是尝试评估街道上的每个坐标并确定哪些建筑物覆盖该点。 

对于每个位置：

 1. 找到那里所有活跃的建筑物。 
2. 计算平均高度。 
3. 在平均值保持不变的情况下延长段。 

这种方法是正确的，因为它显式地计算每个位置的答案。 然而，这是完全不切实际的，因为坐标可以达到`10^8`。 

即使我们压缩坐标并独立检查每个间隔，对每个间隔的所有建筑物进行简单扫描仍然太慢。 

假设有`n`建筑物和`m`唯一的坐标。 强力坐标压缩解决方案可能需要：```
O(n * m)
```在最坏的情况下，`m`是`2n`，导致`O(n^2)`复杂。 

和`10^5`建筑物，这是不可行的。 

### 关键见解

 平均值仅在建筑物边界发生变化。 

在两个连续的事件坐标之间，活动建筑物集永远不会改变。 因此：

 - 总高度总和保持不变。 
- 活跃建筑物数量保持不变。 
- 平均值保持不变。 

这意味着我们只需要处理建筑物开始或结束的位置。 

我们可以使用扫线算法：

 - 当我们到达建筑物的起点时添加建筑物的高度。 
- 当我们到达终点时，移除建筑物的高度。 
- 维护：

 - 总活动高度总和
 - 活跃建筑物数量

 对于连续事件位置之间的每个间隔，我们计算：```
average = total_height // active_count
```然后我们将具有相同平均值的相邻区间合并。

 ## 算法演练

 1. 为所有建筑物边界创建事件列表。 

对于每栋建筑`[start, end, height]`：

 - 添加一个事件`start`表明建筑物已启用。 
- 添加一个事件`end`表明该建筑物变为非活动状态。 

我们存储：```
(position, height_change, count_change)
```具体来说：```
start -> (+height, +1)
end   -> (-height, -1)
```2. 按位置对所有事件进行排序。 

这使我们能够按顺序从左到右处理街道。 
3.维护运行状态变量。 

我们追踪：

 -`current_height_sum`-`current_count`这些代表在坐标处处理事件后立即出现的活动建筑物。 
4. 处理连续事件位置之间的间隔。 

假设之前的坐标是`prev_x`当前坐标是`x`。 

活跃的建筑配置在整个过程中保持不变：```
[prev_x, x)
```所以：```
average = current_height_sum // current_count
```如果`current_count > 0`。 
5. 跳过空白区域。 

如果`current_count == 0`，在该时间间隔内没有活动的建筑物，因此我们不会在结果中添加任何内容。 
6. 合并具有相同平均值的相邻段。 

如果最后记录的片段：```
[a, prev_x, avg]
```与当前间隔具有相同的平均值并且直接相邻，我们将其扩展：```
[a, x, avg]
```而不是创建一个新的段。 
7. 记录间隔后，处理坐标处的所有事件`x`。 

更新：```
current_height_sum += height_change
current_count += count_change
```8. 继续，直到处理完所有事件位置。 

### 为什么它有效

 关键的不变量是在任何两个连续的事件坐标之间，活动建筑物集永远不会改变。 由于活动集是恒定的，因此总高度和建筑物数量都保持恒定，这意味着在整个时间间隔内平均高度也是恒定的。 

由于该算法按排序顺序处理所有建筑物边界，并在建筑物开始或结束时准确更新活动集，因此每个间隔都会收到正确的平均值。 合并相邻的平均平均段可以保证输出段的数量最少。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def averageHeightOfBuildings(self, buildings: List[List[int]]) -> List[List[int]]:
        events = defaultdict(lambda: [0, 0])

        for start, end, height in buildings:
            events[start][0] += height
            events[start][1] += 1

            events[end][0] -= height
            events[end][1] -= 1

        positions = sorted(events.keys())

        result = []

        current_height_sum = 0
        current_count = 0

        for i in range(len(positions) - 1):
            x = positions[i]

            height_delta, count_delta = events[x]

            current_height_sum += height_delta
            current_count += count_delta

            next_x = positions[i + 1]

            if current_count == 0:
                continue

            average = current_height_sum // current_count

            if (
                result
                and result[-1][1] == x
                and result[-1][2] == average
            ):
                result[-1][1] = next_x
            else:
                result.append([x, next_x, average])

        return result
```实施从构建事件映射开始。 每个坐标存储两个累积值：

 - 总高度的变化
 - 活跃建筑数量的变化

 使用字典可以有效地合并以同一坐标开始或结束的多个建筑物。 

对所有坐标进行排序后，算法从左到右扫描。 在每个坐标处：

 1. 应用所有建筑开始/结束更新。 
2. 计算延伸到下一个坐标的间隔。 
3. 如果没有建筑物处于活动状态，则跳过该时间间隔。 
4. 计算整数平均值。 
5. 如果可能的话，与前一个片段合并。 

合并逻辑很重要，因为即使活动构建集发生变化，连续的间隔也可能产生相同的平均值。 

例如：```python
[1,3) average = 2
[3,5) average = 2
```这些必须成为：```python
[1,5) average = 2
```该解决方案在问题限制内有效运行。 

## 解决方案```go
package main

import "sort"

func averageHeightOfBuildings(buildings [][]int) [][]int {
	type Event struct {
		heightDelta int
		countDelta  int
	}

	events := map[int]Event{}

	for _, b := range buildings {
		start, end, height := b[0], b[1], b[2]

		e1 := events[start]
		e1.heightDelta += height
		e1.countDelta += 1
		events[start] = e1

		e2 := events[end]
		e2.heightDelta -= height
		e2.countDelta -= 1
		events[end] = e2
	}

	positions := make([]int, 0, len(events))
	for pos := range events {
		positions = append(positions, pos)
	}

	sort.Ints(positions)

	result := [][]int{}

	currentHeightSum := 0
	currentCount := 0

	for i := 0; i < len(positions)-1; i++ {
		x := positions[i]

		event := events[x]

		currentHeightSum += event.heightDelta
		currentCount += event.countDelta

		nextX := positions[i+1]

		if currentCount == 0 {
			continue
		}

		average := currentHeightSum / currentCount

		if len(result) > 0 &&
			result[len(result)-1][1] == x &&
			result[len(result)-1][2] == average {

			result[len(result)-1][1] = nextX
		} else {
			result = append(result, []int{x, nextX, average})
		}
	}

	return result
}
```Go 实现遵循与 Python 解决方案相同的扫描线逻辑。 

结构体用于干净地存储事件增量。 由于 Go 映射返回结构的副本，因此我们检索该结构，修改它，然后将其写回到映射中。 

切片用于最终结果。 Go中的整数除法自然符合问题要求。 

因为坐标值可以达到`10^8`和高度可达`10^5`, 标准围棋`int`在 LeetCode 的 64 位环境下是安全的。

 ## 边缘情况

 当多个建筑物在同一坐标处开始和结束时，就会出现一种重要的边缘情况。 不正确的事件排序很容易产生无效的间隔或错误的平均值。 该实现通过在处理到下一个坐标的间隔之前聚合同一坐标处的所有更新来避免此问题。 这确保了活动集对于半开区间语义始终是正确的。 

当不同的活动建筑配置产生相同的平均值时，就会出现另一种微妙的情况。 例如：```
[1,3): average = 2
[3,5): average = 2
```即使活动建筑物的位置发生了变化`3`，最终输出应将这些间隔合并为一个片段。 该实现显式检查前一段是否恰好在当前段的开始处结束以及平均值是否匹配。 

第三个重要的边缘情况是建筑物之间的空白空间。 街道表示必须排除没有建筑物的区域。 在扫描期间，如果活动建筑物计数变为零，则实现会完全跳过该间隔。 这可以防止无效段，例如：```
[start, end, 0]
```从出现在结果中。 

最后的边缘情况涉及非常大的坐标。 由于坐标可以达到`10^8`，任何逐坐标模拟都会失败。 扫描线方法仅处理事件边界，使得算法可扩展，而与坐标大小无关。
