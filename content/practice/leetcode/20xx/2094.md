[LeetCode 问题 2094](https://leetcode.com/problems/finding-3-digit-even-numbers/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表、递归、排序、枚举

 ## 解决方案

 ## 问题理解

 问题给了我们一个名为`digits`，其中每个元素都是来自的单个十进制数字`0`到`9`。 我们必须使用该数组中的三个元素来构建有效的三位数整数。 

重要的细节是每个数字只能使用它在输入中出现的次数。 例如，如果数组仅包含一个`2`，那么我们就不能建立一个像这样的数字`222`。 如果数组包含三个`2`s，那么这样的数字就有效了。 

生成的数字必须满足三个条件：

 1. 必须恰好包含三位数字。 
2. 不能以`0`，因为三位数整数中不允许有前导零。 
3. 必须是偶数，即最后一位数字必须是`0`,`2`,`4`,`6`， 或者`8`。 

任务是按升序返回所有唯一的有效数字。 

限制相对较小：

 -`3 <= digits.length <= 100`-`0 <= digits[i] <= 9`尽管输入数组最多可以包含 100 个元素，但只有 10 个可能的数字值。 这是一个非常重要的观察结果，因为它使我们能够根据数字频率来思考，而不是担心大的输入大小。 

一些边缘情况很重要：

 - 仅包含奇数位的数组，不会产生有效的偶数。 
- 包含许多零的数组，其中前导零处理变得至关重要。 
- 具有重复项的数组，我们必须避免重复的结果。 
- 有效数字需要重复数字的情况，这意味着必须正确处理频率计数。 
- 所有数字都相同的输入。 

简单的实现很容易犯错误：

 - 允许像这样的数字`012`- 重复使用数字的次数超过可用次数
 - 返回重复的数字
 - 忘记对结果进行排序

 ## 方法

 ### 蛮力方法

 最直接的解决方案是从数组中生成三个索引的所有可能选择，并从中形成数字。 

我们可以使用三个嵌套循环：

 - 第一个循环选择百位数字
 - 第二个循环选择十位数字
 - 第三次循环选择个位数字

 对于每个索引三元组：

 - 确保所有索引都不同
 - 拒绝带有前导零的数字
 - 拒绝奇数
 - 将有效数字添加到集合中以避免重复

 这种方法是正确的，因为它明确地检查可以从数组形成的每个可能的三位数排列。 

但时间复杂度较高。 由于数组长度最大可达 100，因此三个嵌套循环最多需要`100^3 = 1,000,000`迭代。 虽然对于给定的约束来说这仍然是可以管理的，但它并不优雅并且执行不必要的重复工作。 

### 最佳方法

 更好的解决方案利用了这样一个事实：只有 900 个可能的三位数，从`100`到`999`。 

我们可以反转这个过程，而不是从数字生成数字：

 - 枚举每三位偶数
 - 检查输入中是否存在构建该数字所需的数字

 要有效地做到这一点：

 1. 计算输入中每个数字的出现频率。 
2. 迭代所有偶数`100`到`998`。 
3. 提取百位、十位和个位数字。 
4. 检查输入是否包含足够的每个数字副本。 

这很有效，因为：

 - 即使是三位数也只有 450 个。 
- 频率检查是恒定时间。 
- 结果自然排序，因为我们按升序迭代。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n3) | O(k) | 生成所有索引组合并使用 set | 删除重复项
 | 最佳| O(n + 900) | O(1) | O(1) | 枚举有效候选者并检查数字频率 |

 ## 算法演练

 ### 最优算法

 1. 创建一个大小为 10 的频率数组。 

由于数字范围仅从`0`到`9`，我们存储每个数字出现的次数。 例如，如果输入是`[2,2,8]`， 然后：

-`count[2] = 2`-`count[8] = 1`这允许持续时间可用性检查。 
2. 遍历其中的每个偶数`100`到`998`。 

我们增加`2`因为只有偶数才有效。 
3. 提取当前号码的三位数。 

对于一个号码`num`：

 - 百位数：`num // 100`- 十位数：`(num // 10) % 10`- 个位数字：`num % 10`4. 计算每个数字需要多少次。 

有些数字重复使用数字。 例如：

-`288`需要一个`2`和两个`8`s。 
-`222`需要三个`2`s。 

我们构建另一个代表当前数字的频率数组。 
5. 将所需频率与可用频率进行比较。 

如果每个所需的数字计数小于或等于输入数组中的可用计数，则该数字有效。 
6. 将有效号码添加到结果列表中。 

因为我们按升序迭代，所以结果列表已经排序。 
7. 检查完所有号码后返回结果列表。 

### 为什么它有效

 该算法对每个可能的三位数偶数仅检查一次。 仅当输入提供了每个所需数字的足够副本时，才会包含数字。 由于每个有效数字必须是三位数偶数，并且每个这样的候选数字都经过测试，因此该算法保证包含所有有效答案，并且结果中不会出现无效答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def findEvenNumbers(self, digits: List[int]) -> List[int]:
        digit_count = [0] * 10

        for digit in digits:
            digit_count[digit] += 1

        result = []

        for num in range(100, 1000, 2):
            hundreds = num // 100
            tens = (num // 10) % 10
            ones = num % 10

            needed = [0] * 10
            needed[hundreds] += 1
            needed[tens] += 1
            needed[ones] += 1

            valid = True

            for digit in range(10):
                if needed[digit] > digit_count[digit]:
                    valid = False
                    break

            if valid:
                result.append(num)

        return result
```实现首先构建一个名为的频率数组`digit_count`。 该数组记录每个数字在输入中出现的次数。 

接下来，该算法使用以下方法迭代所有三位数偶数：```python
for num in range(100, 1000, 2):
```走过`2`保证每个候选数都是偶数。 

对于每个候选数字，代码使用整数算术提取百位、十位和个位数字。 第二个频率阵列名为`needed`跟踪每个数字需要多少次才能形成当前数字。 

然后算法比较`needed`反对`digit_count`。 如果任何数字被要求的次数多于可用的次数，则该候选人将被拒绝。 

否则，该数字将附加到结果列表中。 

由于数字是按升序检查的，因此最终列表会自动排序。 

## 解决方案```go
func findEvenNumbers(digits []int) []int {
    digitCount := make([]int, 10)

    for _, digit := range digits {
        digitCount[digit]++
    }

    result := []int{}

    for num := 100; num < 1000; num += 2 {
        hundreds := num / 100
        tens := (num / 10) % 10
        ones := num % 10

        needed := make([]int, 10)
        needed[hundreds]++
        needed[tens]++
        needed[ones]++

        valid := true

        for digit := 0; digit < 10; digit++ {
            if needed[digit] > digitCount[digit] {
                valid = false
                break
            }
        }

        if valid {
            result = append(result, num)
        }
    }

    return result
}
```Go 实现遵循与 Python 版本相同的逻辑。 

频率数组使用切片而不是 Python 列表。 结果切片使用动态扩展`append`。 

Go 在这里不需要对整数溢出进行特殊处理，因为所有值都保持在标准整数范围内。 

如果不存在有效数字，自然会返回空结果切片。

 ## 边缘情况

 ### 输入仅包含奇数位

 像这样的输入`[3,5,7]`不能形成任何偶数，因为每个生成的数字的最后一位也将是奇数。 

如果错误的实现忘记强制执行偶数要求，则仍可能产生输出。 此实现通过仅迭代偶数候选数来避免该问题。 

### 领先零的情况

 输入如`[0,1,2]`可以形成`102`和`120`，但无法形成`012`。 

这是直接生成排列时常见的错误来源。 该实现会自动处理这个问题，因为它只检查来自`100`到`999`，这意味着每个候选人都已经有一个有效的百位数字。 

### 重复数字要求

 像这样的输入`[2,8,8]`应该允许`288`但不是`888`。 

挑战在于确保数字的重复使用次数不会超过可用次数。 频率比较保证了正确性，因为每个候选数必须满足：```
needed[digit] <= available[digit]
```对于每个数字`0`到`9`。 

### 来自不同索引选择的重复数字

 有输入`[2,2,8]`，不同的索引组合可以产生相同的数字，例如`228`。 

强力排列方法可能会意外地多次添加重复项。 最佳解决方案完全避免了这个问题，因为每个候选数字只检查一次。
