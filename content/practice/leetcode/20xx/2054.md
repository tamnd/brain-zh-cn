[LeetCode 问题 2054](https://leetcode.com/problems/two-best-non-overlapping-events/)

 **难度：** 🟡 中等
 **主题：** 数组、二分查找、动态规划、排序、堆（优先级队列）

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个事件列表，其中每个事件表示为：```
[startTime, endTime, value]
```每个事件占用一个包含时间间隔`startTime`到`endTime`。 如果我们参加该活动，我们将获得`value`点。 

我们最多可以参加两项活动，但所选择的活动不得重叠。 由于间隔是包含在内的，因此如果一个事件恰好在另一个事件结束时开始，则两个事件会发生冲突。 换句话说：

 - 如果活动在某个时间结束`t`- 下一个活动必须在指定时间开始`t + 1`或稍后

 目标是最大化从最多两个非重叠事件收集的总价值。 

输入尺寸很大：

 - 最多`10^5`事件
 - 时间值可以大到`10^9`这些约束立即排除了任何直接以二次时间检查所有事件对的算法。 

一些重要的观察结果：

 - 如果一项事件能够产生最大值，我们可以只选择该事件。 
- 多个事件可以共享相同的开始或结束时间。 
- 因为间隔是包含在内的，所以事件在时间结束`5`不能与另一个开始配对`5`。 
- 大坐标范围意味着我们无法使用时间轴模拟或按时间索引的前缀数组。 

核心挑战是为每个事件有效地找到严格在其结束时间之后开始的最佳兼容事件。 

## 方法

 ### 蛮力方法

 最直接的解决方案是尝试每对可能的事件。 

对于每个事件`i`，我们将其与其他所有事件进行比较`j`：

 - 检查两个事件是否重叠
 - 如果它们不重叠，则计算`value[i] + value[j]`- 也可以考虑只参加一项活动

 这保证了正确性，因为每个有效组合都会被检查。 

然而，时间复杂度太大了。 

和`n = 10^5`，检查所有对需要：```
O(n^2) = 10^10
```在最坏的情况下进行操作，这是不可行的。 

### 关键见解

 重要的观察是，一旦事件按开始时间排序，我们就可以使用二分搜索有效地搜索下一个兼容事件。 

假设我们当前正在考虑事件：```
[start, end, value]
```我们想要快速找到：```
the first event whose start time > end
```如果我们已经知道从每个未来位置开始可用的最大事件值，那么我们可以立即计算：```
current value + best compatible future value
```这导致了一个有效的策略：

 1. 按开始时间排序事件
 2.构建后缀最大数组
 3. 使用二分查找来定位下一个不重叠的事件

 这将复杂性降低到`O(n log n)`。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |

 ## 算法演练

 ### 最优算法

 1. 按开始时间对所有事件进行排序。 

排序使我们能够有效地对未来兼容事件进行二分搜索。 排序后，所有候选未来事件都显示在当前事件的右侧。 
2. 将所有开始时间提取到一个单独的数组中。 

该数组支持二分搜索。 对于每个事件，我们希望找到第一个开始时间严格大于当前事件结束时间的事件。 
3.构建后缀最大数组。 

让：```
suffixMax[i]
```表示索引中所有事件中的最大事件值`i`到最后。 

这意味着一旦我们找到下一个兼容事件索引，我们就可以立即知道未来可能的最佳事件值。 
4. 迭代每个事件。 

对于每个事件：

 - 将其视为第一个选择的事件
 - 使用二分搜索来查找第一个兼容的未来事件
 - 将当前价值与最佳未来价值相结合
 - 更新全局最大值
 5. 还可以考虑只参加一项活动。 

由于我们最多可以选择两个事件，而不是恰好两个，因此最佳答案可能由单个高价值事件组成。 

### 为什么它有效

 该算法之所以有效，是因为对于每个事件，我们都会间接考虑所有有效的第二个事件候选者。 

二分搜索保证我们找到最早的不重叠的未来事件。 由于后缀最大数组存储从该点开始的最佳值，因此我们不需要单独扫描每个未来事件。 

因此，可以有效地评估每个有效的两事件组合，并找到最大可能值。 

## Python 解决方案```python
from bisect import bisect_right
from typing import List

class Solution:
    def maxTwoEvents(self, events: List[List[int]]) -> int:
        # Sort events by start time
        events.sort(key=lambda event: event[0])

        n = len(events)

        # Store all start times separately for binary search
        start_times = [event[0] for event in events]

        # suffix_max[i] = maximum event value from i to end
        suffix_max = [0] * n
        suffix_max[-1] = events[-1][2]

        for i in range(n - 2, -1, -1):
            suffix_max[i] = max(suffix_max[i + 1], events[i][2])

        answer = 0

        for i in range(n):
            start, end, value = events[i]

            # Find first event with start time > end
            next_index = bisect_right(start_times, end)

            current_total = value

            # Add best compatible future event if it exists
            if next_index < n:
                current_total += suffix_max[next_index]

            answer = max(answer, current_total)

        return answer
```实现首先根据事件的开始时间对事件进行排序。 这种排序至关重要，因为二分查找需要排序的数据。 

接下来我们建立一个单独的`start_times`大批。 为了提高效率和清晰度，我们不会在二分搜索期间重复提取开始时间，而是将它们存储一次。 

这`suffix_max`然后从右到左构建数组。 每个位置存储从该索引开始可用的最大值。 这允许恒定时间查找最佳的未来事件。 

对于每个事件，我们使用`bisect_right`查找开始时间严格大于当前事件结束时间的第一个事件。 这正确地处理了包含间隔规则。 

如果存在兼容的未来事件，我们将当前事件的值与最佳未来值相结合`suffix_max`。 否则，我们只考虑当前事件。 

返回所有可能性中的最大值。 

## 解决方案```go
package main

import (
	"sort"
)

func maxTwoEvents(events [][]int) int {
	// Sort by start time
	sort.Slice(events, func(i, j int) bool {
		return events[i][0] < events[j][0]
	})

	n := len(events)

	// Extract start times
	startTimes := make([]int, n)
	for i := 0; i < n; i++ {
		startTimes[i] = events[i][0]
	}

	// Build suffix maximum array
	suffixMax := make([]int, n)
	suffixMax[n-1] = events[n-1][2]

	for i := n - 2; i >= 0; i-- {
		if suffixMax[i+1] > events[i][2] {
			suffixMax[i] = suffixMax[i+1]
		} else {
			suffixMax[i] = events[i][2]
		}
	}

	answer := 0

	for i := 0; i < n; i++ {
		end := events[i][1]
		value := events[i][2]

		// Find first index with start time > end
		nextIndex := sort.Search(n, func(j int) bool {
			return startTimes[j] > end
		})

		currentTotal := value

		if nextIndex < n {
			currentTotal += suffixMax[nextIndex]
		}

		if currentTotal > answer {
			answer = currentTotal
		}
	}

	return answer
}
```Go 解决方案遵循与 Python 版本相同的算法结构。 

而不是Python的`bisect_right`, Go 使用`sort.Search`执行二分查找。 搜索条件查找第一个开始时间严格大于当前事件的结束时间。 

Go 切片自然会处理动态数组，因此这里不需要对空结构进行特殊处理，因为约束保证至少有两个事件。 

所有算术都可以安全地适合 Go 的范围`int`在问题约束下键入。

 ## 边缘情况

 ### 触及边界的事件

 错误的一个非常常见的来源是误解包含间隔规则。 

例如：```
[1,2] and [2,3]
```这些事件重叠，因为其中一个事件恰好在另一个事件开始时结束。 

幼稚的实现可能会错误地允许这两个事件。 我们的解决方案通过搜索来避免这种情况：```
start_time > current_end
```而不是：```
start_time >= current_end
```使用`bisect_right`正确执行此规则。 

### 最佳解决方案仅使用一个事件

 该问题允许最多选择两个事件，而不是恰好两个。 

考虑：```
[[1,10,100],[2,3,5],[4,5,6]]
```最优答案是`100`，仅使用第一个事件。 

我们的实现自然会处理这个问题，因为在有选择地添加第二个兼容事件之前，每个事件都会被单独评估。 

### 所有事件重叠

 如果每个事件都与其他事件重叠，则无法选择任何对。 

例子：```
[[1,5,1],[1,5,2],[1,5,3]]
```正确答案就是最大单个事件值。 

二分搜索将无法找到兼容的未来事件，因此算法正确地回退到仅考虑单个事件。
