[LeetCode 问题 2091](https://leetcode.com/problems/removing-minimum-and-maximum-from-array/)

 **难度：** 🟡 中等
 **主题：** 数组，贪婪

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个由 0 索引的不同整数组成的数组。 在这些整数中，恰好有一个值是数组中的最小元素，恰好有一个值是数组中的最大元素。 任务是使用尽可能少的删除来删除这两个元素。 

删除操作受到很大限制。 我们只能从以下任一位置删除元素：

 - 阵列的前面
 - 阵列的背面

 我们不能直接从中间删除元素。 每次删除都会缩小数组，其余元素也会相应移动。 

目标是计算所需的最小删除次数，以便从数组中删除最小和最大元素。 

这些约束告诉我们一些重要的事情：

 - 该数组最多可以包含`10^5`元素，因此低效的强力模拟方法可能会变得太慢。 
- 所有数字都是不同的，这保证只有一个最小值和一个最大值。 
- 值可以是负数、正数或零，但只有它们的相对顺序才重要。 

一个重要的细节是，删除一个元素也可能会移动另一个元素相对于数组末端的位置。 因为删除只能发生在前面或后面，所以问题本质上是选择最便宜的方式来暴露和删除两个目标元素。 

一些边缘情况很重要：

 - 数组只能包含一个元素。 在这种情况下，单个元素既是最小值又是最大值。 
- 最小值和最大值可能都在前面附近。 
- 最小值和最大值可能都在后面附近。 
- 一个可能靠近前面，另一个可能靠近后面。 
- 最小索引可能出现在最大索引之后，因此仔细的索引标准化有助于简化计算。 

## 方法

 ### 蛮力方法

 暴力策略会尝试从正面和背面模拟每一个可能的删除序列。 在每一步中，我们可以选择任一侧并继续，直到最小和最大元素都被删除。 

这种方法是正确的，因为它探索了所有可能的有效删除序列，因此最终找到了最少的操作数。 

然而，这种方法变得极其低效。 每次删除都会产生两种分支的可能性，导致状态数量呈指数增长。 即使使用记忆功能，对于大小高达`10^5`。 

由于删除规则是高度结构化的，因此我们可以通过直接分析位置而不是模拟删除来做得更好。 

### 最优贪婪观察

 关键的见解是只有最小和最大元素的位置才重要。 

认为：

-`minIndex`是最小元素的位置
 -`maxIndex`是最大元素的位置

 只有三种有意义的策略：

 1. 从前面拆下两者。 
2. 从背面取下两者。 
3. 从前面拆下一个，从后面拆下另一个。 

没有其他策略可以胜过这些，因为删除仅发生在数组边界。 

为了简化推理，我们首先对索引进行重新排序，以便：

 -`left = min(minIndex, maxIndex)`-`right = max(minIndex, maxIndex)`现在三种可能的成本变为：

 1. 从前面拆下两者：

 - 需要`right + 1`删除。 
2. 从背面拆下两者：

 - 需要`n - left`删除。 
3. 从每一侧取下一个：

 - 删除最多`left`从前面。 
- 删除最多`right`从后面。 
- 删除总数：`left + 1 + (n - right)`这三个值中的最小值就是答案。 

这在线性时间内有效，因为我们只扫描数组一次来定位最小和最大元素。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 模拟所有删除序列 |
 | 最佳 | O(n) | O(1) | O(1) | 使用指数分析并仅评估三种情况 |

 ## 算法演练

 1. 遍历数组一次，找到最小和最大元素的索引。 

扫描期间：

 - 跟踪最小值及其索引。 
- 跟踪最大值及其索引。 
2. 对指标进行标准化。 

让：

-`left = min(minIndex, maxIndex)`-`right = max(minIndex, maxIndex)`这保证了`left <= right`，简化了后面的计算。 
3. 计算从前面移除两个元素的成本。 

如果我们重复从前面删除，我们必须继续下去，直到删除更远的目标元素。 

自从`right`离前面较远：

 - 需要删除=`right + 1`4. 计算从后面移除两个元件的成本。 

如果我们从后面重复删除，就必须继续下去，直到距离后面较远的目标元素被删除为止。 

自从`left`离后面较远：

 - 需要删除=`n - left`5. 计算混合策略。 

删除：

 - 前方左侧目标
 - 从后面的正确目标

 成本：

 - 前面删除=`left + 1`- 向后删除=`n - right`全部的：

-`left + 1 + (n - right)`6. 返回三个计算成本中的最小值。 

### 为什么它有效

 每个有效的解决方案最终都必须删除两个目标索引。 由于删除只能从数组末尾发生，因此唯一有意义的可能性是：

 - 两者均从正面移除
 - 均从背面移除
 - 从每一侧移除一个

 该算法评估每种情况的确切成本并选择最小的一种。 由于这些情况耗尽了所有最佳可能性，因此保证其中的最小值就是正确答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def minimumDeletions(self, nums: List[int]) -> int:
        n = len(nums)

        min_index = 0
        max_index = 0

        for i in range(n):
            if nums[i] < nums[min_index]:
                min_index = i

            if nums[i] > nums[max_index]:
                max_index = i

        left = min(min_index, max_index)
        right = max(min_index, max_index)

        remove_front = right + 1
        remove_back = n - left
        remove_both_sides = (left + 1) + (n - right)

        return min(remove_front, remove_back, remove_both_sides)
```该实现首先扫描一次数组以定位最小和最大元素的索引。 该算法在迭代数组时维护两个索引，而不是排序或使用额外的数据结构。 

找到索引后，代码将它们标准化为`left`和`right`。 这使得后面的公式保持一致，无论最小值出现在最大值之前还是之后。 

下一节计算三种可能的删除策略：

 - 从前面删除所有内容，直到两者都被删除
 - 从后面删除所有内容，直到两者都被删除
 - 结合正面和背面删除

 最后，返回这三种可能性中的最小值。 

该实现使用恒定的额外内存，并且仅对数组​​执行一次传递。 

## 解决方案```go
func minimumDeletions(nums []int) int {
	n := len(nums)

	minIndex := 0
	maxIndex := 0

	for i := 0; i < n; i++ {
		if nums[i] < nums[minIndex] {
			minIndex = i
		}

		if nums[i] > nums[maxIndex] {
			maxIndex = i
		}
	}

	left := min(minIndex, maxIndex)
	right := max(minIndex, maxIndex)

	removeFront := right + 1
	removeBack := n - left
	removeBothSides := (left + 1) + (n - right)

	return min(removeFront, min(removeBack, removeBothSides))
}

func min(a, b int) int {
	if a < b {
		return a
	}
	return b
}

func max(a, b int) int {
	if a > b {
		return a
	}
	return b
}
```Go 实现遵循与 Python 解决方案完全相同的逻辑。 由于 Go 没有提供内置的`min`和`max`整数函数，辅助函数是手动定义的。 

该解决方案仅使用整数运算，因此在给定的约束下不存在溢出问题。 直接使用切片，不进行任何复制，保持空间复杂度不变。

 ## 边缘情况

 ### 单元素数组

 当数组仅包含一个元素时，该元素同时是最小值和最大值。 有缺陷的实现可能会错误地计算两次删除，因为它独立地处理最小值和最大值。 

该实现自然地处理了这个问题，因为两个索引都变成了`0`，并且计算出的策略中的最小值是正确的`1`。 

### 两端的最小值和最大值

 考虑一个像这样的数组：```
[1, 2, 3, 4, 5]
```最小值在前面，最大值在后面。 仅从一侧删除的简单策略需要删除整个数组。 

混合策略正确地识别出从前面删除一个元素和从后面删除一个元素仅花费成本`2`。 

### 最小值出现在最大值之后

 不保证最小索引小于最大索引。 例如：```
[10, 3, 2, 1]
```这里：

 - 最大索引 =`0`- 最小指数 =`3`如果不标准化指数，公式可能会变得容易出错且不一致。 

该实现通过引入以下内容解决了这个问题：```
left = min(min_index, max_index)
right = max(min_index, max_index)
```这保证了一致的排序并简化了所有后续计算。 

### 两个目标都在同一侧附近

 考虑：```
[1, 5, 4, 3, 2]
```最小值和最大值都在前面附近。 有缺陷的实现可能总是会考虑混合删除，即使是不必要的。 

该算法显式计算所有三种可能性并选择最小的一种，确保自动选择最佳同边策略。
