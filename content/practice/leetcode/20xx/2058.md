[LeetCode 问题 2058](https://leetcode.com/problems/find-the-minimum-and-maximum-number-of-nodes- Between-ritic-points/)

 **难度：** 🟡 中等
 **主题：** 链接列表

 ## 解决方案

 ## 问题理解

 该问题给了我们一个单链表，并要求我们识别它的所有关键点。 临界点是局部最大值或局部最小值的节点。 

如果一个节点的值严格大于其前一个节点和下一个节点，则该节点被视为局部最大值。 类似地，如果一个节点的值严格小于其两个相邻节点，则该节点被视为局部最小值。 

因为定义取决于前一个节点和下一个节点，所以链表的第一个和最后一个节点永远不可能是临界点。 

任务不仅是检测关键点，还要计算两个距离：

 - 任意两个不同临界点之间的最小距离
 - 任意两个不同临界点之间的最大距离

 距离是使用链表中的节点位置来测量的，从索引开始`1`在示例中。 

如果链表包含的临界点少于两个，则没有足够的点来形成一对，因此答案必须是`[-1, -1]`。 

输入大小可以大到`10^5`节点。 这个约束立即告诉我们，我们需要一个线性时间解。 任何具有二次行为的算法都会太慢。 

一个重要的细节是比较严格更大和严格更小。 相等的相邻值不符合临界点的条件。 例如，在序列中`[2,2,2]`，没有一个节点是临界点。 

有几种边缘情况很容易导致错误：

 - 少于三个节点的列表不能包含任何关键点
 - 必须返回只有一个关键点的列表`[-1, -1]`- 连续的临界点可能产生的最小距离为`1`- 重复的值可以防止节点成为关键节点
 - 决不能考虑第一个和最后一个节点，即使它们相对于单个邻居显得极端

 在设计算法之前，清楚地了解这些条件至关重要。 

## 方法

 ### 蛮力方法

 一个简单的暴力解决方案将首先遍历链表并将所有关键点的位置收集到一个数组中。 

收集所有关键点索引后，我们可以比较每对关键点以计算最小和最大距离。 

例如，如果临界点位于以下位置：```
[3, 5, 6, 10]
```我们可以检查所有对：

 -`(3,5)`-`(3,6)`-`(3,10)`-`(5,6)`-`(5,10)`-`(6,10)`对于每一对，我们计算距离并更新最小值和最大值。 

这种方法是正确的，因为它明确地检查每对可能的关键点。 然而，如果有`k`临界点，成对比较需要`O(k^2)`时间。 在最坏的情况下，几乎每个节点都可能是关键点，使得复杂性大约`O(n^2)`。 

自从`n`可以是`10^5`，二次行为的成本太高。 

### 最佳方法

 关键的观察是我们不需要比较每对关键点。 

对于最小距离，最小间隙总是出现在按位置顺序连续的两个临界点之间。 如果非连续点之间的间隙较小，那么中间临界点将产生更小的连续间隙。 

对于最大距离，我们只需要第一个临界点和最后一个临界点之间的距离。 

这一观察使我们能够一次性处理链表：

 - 遍历时检测关键点
 - 追踪第一个临界点
 - 追踪之前的临界点
 - 不断更新最小距离
 - 使用当前临界点和第一个临界点计算最大距离

 这将复杂性降低到线性时间和恒定的额外空间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 存储所有关键点并比较每一对 |
 | 最佳 | O(n) | O(1) | O(1) | 单次遍历，只追踪必要位置 |

 ## 算法演练

 1. 初始化遍历指针。 

我们在遍历时使用了三个节点：

 -`prev`, 前一个节点
 -`curr`，当前节点
 -`curr.next`, 下一个节点

 这允许我们确定当前节点是局部最大值还是局部最小值。 
2. 跟踪节点位置。 

由于距离取决于节点索引，因此我们维护一个位置计数器。 当前节点开始于位置`2`因为第一个节点不可能是关键的。 
3. 检测关键点。 

对于每个节点，我们检查：

 - 局部最大值：```
curr.val > prev.val AND curr.val > curr.next.val
```- 局部最小值：```
curr.val < prev.val AND curr.val < curr.next.val
```如果任一条件为真，则当前节点是临界点。 
4. 存储第一个临界点。 

第一个临界点很重要，因为最大距离最终将是：```
last_critical_position - first_critical_position
```当遇到第一个临界点时，我们保存它的位置。 
5. 更新最小距离。 

每次我们找到一个新的临界点时，我们都会将其与之前的临界点进行比较。```
current_position - previous_critical_position
```这是可行的，因为连续的关键点之间必须出现尽可能最小的间隙。 
6. 更新最大距离。 

对于第一个临界点之后的每个临界点，我们计算：```
current_position - first_critical_position
```这不断扩大了最大可能的跨度。 
7. 继续遍历。 

将所有指针向前移动一个节点并递增位置计数器。 
8. 返回结果。 

如果存在少于两个临界点，则返回：```
[-1, -1]
```否则，返回：```
[minimum_distance, maximum_distance]
```### 为什么它有效

 该算法之所以有效，是因为它保留了计算两个所需距离所需的准确信息。 

对于最小距离，只有连续的临界点才重要。 任何非连续对必须至少有一个中间临界点，使其距离大于或等于某个连续对。 

对于最大距离，最远的可能对始终是第一个和最后一个临界点。 

通过处理列表一次并维护这些不变量，该算法保证了线性时间内的正确结果。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

from typing import List, Optional

class Solution:
    def nodesBetweenCriticalPoints(
        self,
        head: Optional[ListNode]
    ) -> List[int]:

        prev = head
        curr = head.next

        position = 2

        first_critical = -1
        previous_critical = -1

        min_distance = float("inf")
        max_distance = -1

        while curr and curr.next:

            is_local_max = (
                curr.val > prev.val and
                curr.val > curr.next.val
            )

            is_local_min = (
                curr.val < prev.val and
                curr.val < curr.next.val
            )

            if is_local_max or is_local_min:

                if first_critical == -1:
                    first_critical = position
                else:
                    min_distance = min(
                        min_distance,
                        position - previous_critical
                    )

                    max_distance = (
                        position - first_critical
                    )

                previous_critical = position

            prev = curr
            curr = curr.next
            position += 1

        if max_distance == -1:
            return [-1, -1]

        return [min_distance, max_distance]
```该实现紧密遵循前面描述的算法。 

我们维护两个遍历指针，`prev`和`curr`，这样我们就可以将当前节点与两个邻居进行比较。 由于链表是单链的，所以这种滚动窗口的方法是必要的。 

这`position`变量跟踪当前节点索引。 我们开始于`2`因为当前节点最初指向列表中的第二个节点。 

每当我们检测到一个临界点时，我们都会判断它是否是第一个遇到的临界点。 如果它是第一个，我们只需存储它的位置。 

对于以后的每个关键点，我们都会更新：

 -`min_distance`利用与前一个临界点的差距
 -`max_distance`利用与第一个临界点的差距

 变量`previous_critical`在每个关键点之后更新，以便可以正确进行下一次比较。 

最后，如果`max_distance`仍然是`-1`，那么找到的临界点少于两个，所以所需的答案是`[-1, -1]`。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func nodesBetweenCriticalPoints(head *ListNode) []int {

    prev := head
    curr := head.Next

    position := 2

    firstCritical := -1
    previousCritical := -1

    minDistance := int(1e9)
    maxDistance := -1

    for curr != nil && curr.Next != nil {

        isLocalMax :=
            curr.Val > prev.Val &&
                curr.Val > curr.Next.Val

        isLocalMin :=
            curr.Val < prev.Val &&
                curr.Val < curr.Next.Val

        if isLocalMax || isLocalMin {

            if firstCritical == -1 {
                firstCritical = position
            } else {

                distance := position - previousCritical

                if distance < minDistance {
                    minDistance = distance
                }

                maxDistance = position - firstCritical
            }

            previousCritical = position
        }

        prev = curr
        curr = curr.Next
        position++
    }

    if maxDistance == -1 {
        return []int{-1, -1}
    }

    return []int{minDistance, maxDistance}
}
```Go 的实现非常接近地反映了 Python 的逻辑。 

而不是Python的`float("inf")`，我们初始化`minDistance`具有非常大的整数值。 

Go 需要显式的`nil`遍历时检查，因此循环条件变为：```go
for curr != nil && curr.Next != nil
```切片用于返回值，因为 Go 没有 Python 风格的列表。 

这里不关心整数溢出，因为最大节点数仅为`10^5`。

 ## 边缘情况

 ### 节点少于三个的列表

 一个节点只有同时具有前一个和下一个邻居时才可能是关键的。 因此，长度列表`1`或者`2`永远不能包含临界点。 

如果实现假设邻居始终存在，这种情况很容易导致指针访问错误。 解决方案中的遍历循环通过要求两者来避免这种情况`curr`和`curr.next`在处理之前存在。 

### 只有一个临界点

 链表有可能恰好包含一个临界点。 例如：```
[1,3,2]
```中间节点是局部最大值，但没有第二个临界点可以形成一对。 

幼稚的实现可能会错误地返回涉及未初始化值的距离。 该解决方案通过仅在遇到第二个临界点后更新距离来防止这种情况发生。 

### 重复的邻居值

 该问题需要严格的不平等。 

例如：```
[1,2,2,1]
```两者都不`2`是一个临界点，因为两者都不严格大于两个邻居。 

这种边缘情况很重要，因为使用`>=`或者`<=`一不小心就会产生错误的结果。 该实现明确使用严格比较：```
>
<
```这保证了正确的行为。
