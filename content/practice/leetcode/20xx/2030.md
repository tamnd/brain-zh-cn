[LeetCode 2030 题](https://leetcode.com/problems/smallest-k-length-subsequence-with-occurrences-of-a-letter/)

 **难度：** 🔴难
 **主题：** 字符串、堆栈、贪婪、单调堆栈

 ## 解决方案

 ## 问题理解

 该问题要求我们构造长度按字典顺序最小的子序列`k`从字符串中`s`，同时确保特定字符，`letter`, 至少出现`repetition`结果子序列中的次数。 

子序列保留原始字符串中字符的相对顺序，但可以跳过字符。 例如，从`"leetcode"`，子序列`"ecde"`有效，因为这些字符按顺序出现。 

关键的挑战是我们同时优化两个约束：

 1. 子序列的长度必须精确`k`2. 子序列必须至少包含`repetition`的副本`letter`在所有有效的子序列中，我们想要字典顺序最小的一个。 词典顺序与词典顺序的工作方式相同。 字符串中较早的较小字符始终是首选。 

约束条件很重要：

 -`k`可以大到`5 * 10^4`-`s.length`还可以`5 * 10^4`这立即告诉我们子序列的指数或二次生成是不可能的。 我们需要一个线性或接近线性的算法。 

有几种棘手的情况很容易导致错误：

 - 删除太多副本`letter`同时尝试使序列按字典顺序变小
 - 太早填写子序列，没有为以后所需的字母留下空间
 - 由于堆栈条件不正确而保留不必要的大字符
 - 每个字符都是所需字母的情况
 - 情况`k == len(s)`，意味着没有任何东西可以被删除

 该问题保证了`letter`至少出现`repetition`次在`s`，因此总存在有效的解。 

## 方法

 ### 蛮力方法

 最直接的解决方案是生成每个长度的子序列`k`，然后仅过滤那些至少包含`repetition`的副本`letter`。 在剩下的候选者中，我们返回字典顺序最小的一个。 

这是有效的，因为它显式地检查每个可能的有效子序列。 

然而，长度的子序列的数量`k`是：$$\binom{n}{k}$$这个数字呈指数级增长。 为了`n = 50000`，暴力破解是完全行不通的。 

即使对于小得多的输入，生成所有子序列也已经超出了时间限制。 

### 关键见解

 重要的观察是，字典顺序最小的子序列问题通常使用单调堆栈来解决。 

对于每个字符，我们希望删除较大的先前字符，如果这样做会产生较小的词典结果。 

然而，与标准单调堆栈问题不同，我们还有两个额外的约束：

 1. 最终的子序列长度必须恰好为`k`2. 我们必须保留足够的副本`letter`所以我们不能贪婪地弹出角色，除非我们知道：

 - 我们还有足够的剩余字符来达到长度`k`- 我们还有足够的剩余`letter`满足的字符`repetition`这将问题转化为约束贪婪堆栈问题。 

堆栈始终存储迄今为止构建的最佳子序列。

 ## 算法演练

 ### 第 1 步：计算剩余的必填字母

 在处理之前，统计出现了多少次`letter`存在于字符串中。 

这有助于我们确定删除某个文件是否安全`letter`稍后从堆栈中。```
remaining_letter = total count of letter in s
```我们还跟踪：```
letters_in_stack = number of letter currently in stack
```### 步骤 2：一一处理字符

 我们从左到右迭代字符串。 

对于每个字符：

 - 我们尝试从堆栈末尾删除较大的字符
 - 但前提是这样做仍然可以在以后提供有效的解决方案

 ### 第 3 步：决定是否弹出

 当堆栈不为空时，我们检查是否应删除顶部字符。 

如果所有条件都成立，我们就会弹出：

 1.当前字符小于栈顶
 2.出栈后，我们仍然可以构建一个长度的子序列`k`3.如果弹出的字符是`letter`，稍后保留足够的副本

 第二个条件是：```
len(stack) - 1 + remaining_characters >= k
```这确保了我们稍后仍然可以填充子序列。 

第三个条件防止删除太多必需的字母。 

### 第四步：决定是否推送

 弹出较大的字符后，我们决定是否添加当前字符。 

仅当堆栈长度仍小于时我们才推送`k`。 

那么我们处理两种情况：

 #### 情况 A：当前字符是`letter`我们总是更喜欢添加它，因为我们至少需要`repetition`副本。 

#### 情况 B：当前字符不是`letter`仅当仍有足够的剩余位置可容纳所需字母时，我们才能添加它。 

具体来说：```
remaining_slots_after_push >= needed_letters
```在哪里：```
needed_letters = repetition - letters_in_stack
```这可以防止我们过早地用非字母字符填充堆栈。 

### 步骤 5：更新剩余计数

 处理完当前字符后，如果该字符等于，则减少剩余字母的计数`letter`。 

这可以保证未来决策的准确性。 

### 为什么它有效

 该算法保持贪婪不变量：

 - 堆栈始终是迄今为止按字典顺序可能的最小有效部分子序列。 

每当可以安全地删除较大的字符时，我们都会立即删除它，因为较小的较早字符总是会改善字典顺序。 

安全条件保证：

 - 我们永远不会失去达到长度的能力`k`- 我们永远不会失去满足所需数量的能力`letter`事件

 因此，最终的堆栈既有效又按字典顺序最小。 

## Python 解决方案```python
class Solution:
    def smallestSubsequence(self, s: str, k: int, letter: str, repetition: int) -> str:
        total_letters_remaining = s.count(letter)

        stack = []
        letters_in_stack = 0

        n = len(s)

        for i, ch in enumerate(s):
            # Try to make lexicographically smaller result
            while (
                stack
                and stack[-1] > ch
                and len(stack) - 1 + (n - i) >= k
            ):
                # If popping a required letter, ensure enough remain
                if stack[-1] == letter:
                    if letters_in_stack - 1 + total_letters_remaining < repetition:
                        break
                    letters_in_stack -= 1

                stack.pop()

            # Decide whether to push current character
            if len(stack) < k:
                if ch == letter:
                    stack.append(ch)
                    letters_in_stack += 1
                else:
                    # Ensure enough room remains for required letters
                    remaining_slots = k - len(stack)
                    needed_letters = repetition - letters_in_stack

                    if remaining_slots > needed_letters:
                        stack.append(ch)

            # Update remaining letters count
            if ch == letter:
                total_letters_remaining -= 1

        return "".join(stack)
```该实现完全遵循贪婪单调堆栈策略。 

变量`total_letters_remaining`跟踪字符串的未处理部分中仍然存在多少所需的字母。 这允许在从堆栈中删除字符时做出安全的决定。 

堆栈本身存储当前最佳候选子序列。 

这`while`循环负责词典优化。 只要这样做仍然允许有效的最终子序列，就会删除较大的字符。 

条件：```python
len(stack) - 1 + (n - i) >= k
```确保即使在弹出之后，仍然有足够的总字符数来达到长度`k`。 

添加非字母字符时，算法会为非字母字符的强制副本保留足够的未来位置`letter`。 

这一行很关键：```python
if remaining_slots > needed_letters:
```如果没有它，堆栈可能会在包含足够的所需字母之前就已满。 

最后，堆栈被连接到最终的答案字符串中。 

## 解决方案```go
func smallestSubsequence(s string, k int, letter byte, repetition int) string {
	totalLettersRemaining := 0
	for i := 0; i < len(s); i++ {
		if s[i] == letter {
			totalLettersRemaining++
		}
	}

	stack := make([]byte, 0)
	lettersInStack := 0
	n := len(s)

	for i := 0; i < n; i++ {
		ch := s[i]

		for len(stack) > 0 &&
			stack[len(stack)-1] > ch &&
			len(stack)-1+(n-i) >= k {

			top := stack[len(stack)-1]

			if top == letter {
				if lettersInStack-1+totalLettersRemaining < repetition {
					break
				}
				lettersInStack--
			}

			stack = stack[:len(stack)-1]
		}

		if len(stack) < k {
			if ch == letter {
				stack = append(stack, ch)
				lettersInStack++
			} else {
				remainingSlots := k - len(stack)
				neededLetters := repetition - lettersInStack

				if remainingSlots > neededLetters {
					stack = append(stack, ch)
				}
			}
		}

		if ch == letter {
			totalLettersRemaining--
		}
	}

	return string(stack)
}
```Go 实现密切反映了 Python 逻辑。 

Go 使用字节片作为堆栈，而不是 Python 列表。 

从堆栈中弹出是使用切片截断实现的：```go
stack = stack[:len(stack)-1]
```Go 中的字符串是不可变的，因此使用字节切片对于堆栈操作更有效。 

不存在整数溢出问题，因为所有值都保持在正常整数范围内。

 ## 边缘情况

 ### 边缘情况 1：所有字符都是必需的字母

 考虑：```
s = "aaaaa"
k = 3
letter = "a"
repetition = 3
```每个字符都必须包含在所需的字母类别中。 有缺陷的实现可能会在优化字典顺序时意外弹出太多字母。 

该解决方案通过检查来防止这种情况发生：```
letters_in_stack - 1 + remaining_letters >= repetition
```在弹出所需的字母之前。 

### 边缘情况 2：所需字母仅出现在接近尾部的位置

 考虑：```
s = "zzzzzaaa"
k = 5
repetition = 3
```如果算法过早贪婪地用非字母字符填充堆栈，则将没有足够的空间来容纳所需的字符。`a`稍后的字符。 

该实现通过验证明确保留未来位置：```
remaining_slots > needed_letters
```在添加非字母字符之前。 

### 边缘情况 3：无法删除任何字符

 考虑：```
s = "abcde"
k = 5
```子序列必须等于原始字符串。 

即使没有足够的剩余字符来重新填充子序列，有缺陷的实现也可能会错误地弹出字符。 

条件：```
len(stack) - 1 + remaining_characters >= k
```保证仅当重建仍然可能时才会发生弹出。
