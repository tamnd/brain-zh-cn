[LeetCode 2088 题](https://leetcode.com/problems/count-fertile-pyramids-in-a-land/)

 **难度：** 🔴难
 **主题：** 数组、动态规划、矩阵

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个二进制矩阵，其中每个单元代表一块土地。 值为`1`意味着土地肥沃，而`0`意思是贫瘠。 我们需要计算完全由受精细胞形成的每个有效金字塔图和反金字塔图。 

正常的金字塔指向下方。 它的顶点是顶部单元格，下面的每一行在左侧和右侧都扩展一个单元格。 例如，金字塔的高度`3`看起来像这样：```
  1
 111
11111
```倒金字塔指向上方。 它的顶点是底部单元格，上面的每一行都类似地向外扩展。 

重要的细节是高度必须大于`1`。 单个受精细胞不被视为金字塔。 

输入尺寸很大：

 -`m, n <= 1000`-`m * n <= 100000`这告诉我们任何算法都比粗略地更糟糕`O(m * n)`或者`O(m * n * log n)`可能会挣扎。 天真地检查每个可能的金字塔的暴力解决方案太慢了。 

有几个重要的边缘情况：

 - 网格完全充满`0`s，答案是`0`- 非常小的网格，例如`1 x n`或者`m x 1`，其中不存在金字塔，因为金字塔需要扩展
 - 大型完全肥沃的网格，其中存在许多重叠的金字塔
 - 边界附近的细胞，金字塔无法完全展开
 - 肥沃和贫瘠的混合模式打破了原本有效的金字塔

 该问题保证网格尺寸有效并且每个值都是`0`或者`1`。 

## 方法

 ### 蛮力方法

 蛮力的想法是将每个受精细胞视为可能的顶点，并尝试逐层生长金字塔。 

对于普通金字塔：

 1.从单元格开始`(r, c)`2. 尝试高度`2`， 然后`3`，等等
 3. 对于每个高度，验证每个所需的单元都存在并且可以生育
 4. 当任何所需的单元格贫瘠或超出网格时停止

 我们对逆金字塔重复相同的过程。 

这种方法是正确的，因为它明确验证了问题陈述中每个可能的金字塔定义。 然而，它非常昂贵。 

假设我们有一个完全肥沃的网格。 对于每个单元格，我们可能会尝试很多高度，而每个高度都需要扫描整个行段。 在最坏的情况下，这大约变成：```
O(m * n * min(m, n)^2)
```这对于`100000`细胞。 

### 最优动态规划方法

 关键的见解是金字塔的高度`h`只有当较小的金字塔已经存在于其正下方时，它才能存在。 

考虑一个向下的金字塔，根部为`(r, c)`。 

至少身高`2`：

 - 当前细胞必须是可生育的
 - 以下三个支撑位置也必须支撑金字塔：

 -`(r + 1, c - 1)`-`(r + 1, c)`-`(r + 1, c + 1)`这创建了一种自然的动态编程关系。 

我们不是重复检查每个单元格，而是计算每个位置可能的最大金字塔高度。 

如果：```
dp[r][c] = maximum extra levels below apex
```然后：```
dp[r][c] = 1 + min(
    dp[r + 1][c - 1],
    dp[r + 1][c],
    dp[r + 1][c + 1]
)
```对于受精细胞。 

中的每个值`dp[r][c]`直接贡献了那么多金字塔：

 -`1`表示高度`2`-`2`意味着高度`2`和`3`- 等等

 我们运行这个 DP 两次：

 1. 普通金字塔自下而上
 2. 自上而下的逆金字塔

 这将复杂性降低到线性时间。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |

 ## 算法演练

 ### 步骤 1：定义 DP 含义

 我们创建一个 DP 表，其中：```
dp[r][c]
```存储可以扩展多少个附加层`(r, c)`。 

例如：

-`0`意味着金字塔的高度不大于`1`-`1`意思是金字塔的高度`2`-`2`意思是金字塔的高度`2`和`3`这种表示方式让我们可以直接计算有效的金字塔。 

### 步骤 2：向下计数金字塔

 我们从下到上处理行，因为金字塔取决于它下面的行。 

对于每一个受精细胞`(r, c)`：

 - 如果任何支撑子位置无效，金字塔将无法增长
 - 否则：```
dp[r][c] =
1 + min(
    dp[r+1][c-1],
    dp[r+1][c],
    dp[r+1][c+1]
)
```最小值很重要，因为最短的支撑分支限制了总高度。 

每个计算值都直接贡献于答案。 

### 步骤 3：计算倒金字塔

 我们反过来重复同样的想法。 

现在我们从上到下处理，因为逆金字塔依赖于上面的行。 

过渡：```
dp[r][c] =
1 + min(
    dp[r-1][c-1],
    dp[r-1][c],
    dp[r-1][c+1]
)
```同样，每个 DP 值都直接影响总计数。 

### 步骤 4：返回总计数

 最终的答案是：```
downward pyramids + inverse pyramids
```### 为什么它有效

 DP 递归之所以有效，是因为高度金字塔`h`当且仅当所有三个支撑位置至少可以形成高度金字塔时才存在`h - 1`。 

最小支撑高度确定以当前单元为中心的最大可能金字塔。 由于每个较小的高度也是有效的，因此每个 DP 值直接计算有多少金字塔源自该顶点。 

这保证了每个有效的金字塔都被精确地计数一次。 

## Python 解决方案```python
from typing import List

class Solution:
    def countPyramids(self, grid: List[List[int]]) -> int:
        rows = len(grid)
        cols = len(grid[0])

        def count_downward() -> int:
            dp = [[0] * cols for _ in range(rows)]
            pyramids = 0

            for r in range(rows - 2, -1, -1):
                for c in range(1, cols - 1):
                    if grid[r][c] == 1:
                        if (
                            grid[r + 1][c - 1] == 1
                            and grid[r + 1][c] == 1
                            and grid[r + 1][c + 1] == 1
                        ):
                            dp[r][c] = 1 + min(
                                dp[r + 1][c - 1],
                                dp[r + 1][c],
                                dp[r + 1][c + 1],
                            )

                            pyramids += dp[r][c]

            return pyramids

        def count_upward() -> int:
            dp = [[0] * cols for _ in range(rows)]
            pyramids = 0

            for r in range(1, rows):
                for c in range(1, cols - 1):
                    if grid[r][c] == 1:
                        if (
                            grid[r - 1][c - 1] == 1
                            and grid[r - 1][c] == 1
                            and grid[r - 1][c + 1] == 1
                        ):
                            dp[r][c] = 1 + min(
                                dp[r - 1][c - 1],
                                dp[r - 1][c],
                                dp[r - 1][c + 1],
                            )

                            pyramids += dp[r][c]

            return pyramids

        return count_downward() + count_upward()
```该实现将向下和向上金字塔计数分为两个辅助函数。 这使逻辑保持干净和对称。 

每个助手分配一个 DP 表，初始化为`0`。 值为`0`意味着该位置不存在大于单个单元格的有效金字塔。 

对于向下金字塔，我们从倒数第二行向上迭代，因为每个状态都取决于下面的行。 我们只处理内部柱，因为金字塔不能从边缘扩展。 

每当可育细胞下方具有所有三个支持可育细胞时，我们就使用三个支持 DP 状态中的最小值来计算其 DP 值。 

除了遍历方向发生变化之外，逆金字塔重用相同的结构。 

最后，将两个计数相加。 

## 解决方案```go
func countPyramids(grid [][]int) int {
	rows := len(grid)
	cols := len(grid[0])

	countDownward := func() int {
		dp := make([][]int, rows)
		for i := range dp {
			dp[i] = make([]int, cols)
		}

		total := 0

		for r := rows - 2; r >= 0; r-- {
			for c := 1; c < cols-1; c++ {
				if grid[r][c] == 1 &&
					grid[r+1][c-1] == 1 &&
					grid[r+1][c] == 1 &&
					grid[r+1][c+1] == 1 {

					minVal := dp[r+1][c-1]

					if dp[r+1][c] < minVal {
						minVal = dp[r+1][c]
					}

					if dp[r+1][c+1] < minVal {
						minVal = dp[r+1][c+1]
					}

					dp[r][c] = 1 + minVal
					total += dp[r][c]
				}
			}
		}

		return total
	}

	countUpward := func() int {
		dp := make([][]int, rows)
		for i := range dp {
			dp[i] = make([]int, cols)
		}

		total := 0

		for r := 1; r < rows; r++ {
			for c := 1; c < cols-1; c++ {
				if grid[r][c] == 1 &&
					grid[r-1][c-1] == 1 &&
					grid[r-1][c] == 1 &&
					grid[r-1][c+1] == 1 {

					minVal := dp[r-1][c-1]

					if dp[r-1][c] < minVal {
						minVal = dp[r-1][c]
					}

					if dp[r-1][c+1] < minVal {
						minVal = dp[r-1][c+1]
					}

					dp[r][c] = 1 + minVal
					total += dp[r][c]
				}
			}
		}

		return total
	}

	return countDownward() + countUpward()
}
```Go 实现密切反映了 Python 逻辑。 由于 Go 没有提供内置的`min`对于整数函数，我们手动计算三个子状态中的最小值。 

切片用于 DP 表，所有值自动默认为零。 

不存在整数溢出问题，因为金字塔的最大数量受到网格大小约束的限制。

 ## 边缘情况

 一个非常重要的边缘情况是只有一行或一列的网格。 金字塔需要水平扩展和多行，因此此类网格永远不能包含有效的金字塔。 幼稚的实现可能会意外地将单个单元格算作金字塔。 此实现避免了这种情况，因为 DP 转换仅在所有三个支持小区都存在时发生。 

另一个重要的情况是当肥沃区域被贫瘠细胞中断时。 例如，一个几乎完整的金字塔只有一个`0`支撑结构中的部分不应计算在内。 DP 转换在扩展金字塔之前显式检查所有三个支持单元，因此损坏的结构立即终止。 

边界处理是错误的另一个常见来源。 最左边和最右边列上的单元格不能作为金字塔中心，因为扩展会离开网格。 该实现仅安全地迭代列`1`通过`cols - 2`，防止越界访问和无效金字塔构建。 

最后一个微妙的情况是重叠的金字塔。 一个大金字塔内包含几个较小的金字塔。 DP值自然会同时计算所有有效高度。 例如，如果`dp[r][c] = 3`，这意味着三个不同的金字塔源自该顶点。 这可确保不会遗漏任何有效结构。
