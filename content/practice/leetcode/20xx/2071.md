[LeetCode 问题 2071](https://leetcode.com/problems/maximum-number-of-tasks-you-can-assign/)

 **难度：** 🔴难
 **主题：** 数组、两个指针、二分查找、贪婪、队列、排序、单调队列

 ## 解决方案

 ## 问题理解

 这个问题要求我们最大化一组工作人员可以完成的任务数量，其中每个工作人员最多可以执行一项任务。 

每个任务都有一个所需的强度值，每个工人都有一个当前的强度值。 如果工人的力量至少与任务要求一样大，则可以完成任务。 

我们还得到了数量有限的神奇药丸。 可以给工人服用一颗药丸，暂时增加他们的力量，固定数量称为`strength`。 每个工人最多可以领取一颗药丸。 

目标是确定可以成功分配的最大任务数。 

输入包括：

 -`tasks[i]`，所需的强度`i`任务
 -`workers[j]`, 的强度`j`第 工人
 -`pills`, 可用药丸的数量
 -`strength`, 药丸增加的额外力量

 输出是一个整数，表示可以完成的最大任务数。 

约束条件非常重要：

 - 最多`5 * 10^4`任务和工人
 - 强度值高达`10^9`这些限制立即排除了指数或阶乘分配方法。 我们需要一些接近的东西`O(n log n)`。 

一些边缘情况很重要：

 - 任务可能比工人多
 - 有些任务即使使用药物也可能无法完成
 - 可能根本不需要药丸
 - 工作人员和任务可以包含重复值
 - 看起来局部最优的贪婪分配可能会阻止未来的分配

 主要的挑战是决定何时使用药物以及哪些工人应该接受药物。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试每一种可能的工人分配任务以及每一种可能的方式来分发药丸。 

对于每项任务，我们可以尝试：

 - 分配一名不带药的工人
 - 指派一名工人携带药丸
 - 跳过任务

 这保证了正确性，因为每个有效的分配配置都会被探索。 

然而，可能的分配数量以组合方式增长。 即使对于中等大小的输入，状态的数量也会变得巨大。 

例如：

 - 单独选择工人-任务配对类似于二分匹配排列
 - 药丸的使用引入了额外的分支

 最坏的情况实际上会呈指数增长。 

高达`50,000`元素，这是完全不可行的。 

### 关键见解

 重要的观察是我们不需要立即确定确切的分配。 相反，我们可以二分查找答案。 

假设我们问：

 >“我们能否准确地完成`k`任务？”

 如果我们能够有效地回答这个问题，那么我们就可以二分查找最大可行值`k`。 

这是可行的，因为可行性是单调的：

 - 如果`k`任务是可能的，那么任何较小的数量也是可能的
 - 如果`k`任务是不可能的，那么任何更大的数字都是不可能的

 剩下的挑战是有效地实施可行性检查。 

为了最大限度地取得成功，我们应该：

 - 从最简单到最难对任务进行排序
 - 从最弱到最强对工人进行排序
 - 尝试在选定的任务中分配最困难的任务`k`- 仅在必要时使用药物

 贪婪策略之所以有效，是因为：

 - 应该保留坚强的工人来完成艰巨的任务
 - 仅在不可避免时才应使用药物
 - 在有能力使用药丸的工人中，我们应该使用最弱的合适的药丸

 双端队列使我们能够有效地管理每项任务的候选工作人员。

 ## 算法演练

 ### 1. 对任务和工人进行排序

 我们按升序对两个数组进行排序。 

这有帮助，因为：

 - 较容易的任务通常应该交给较弱的工人
 - 更艰巨的任务应该留给更强大的工人

 排序后：

 -`tasks[0]`是最简单的任务
 -`tasks[-1]`是最艰巨的任务
 - 对于工人来说也是如此

 ### 2.二分查找答案

 我们对可以分配的最大任务数进行二分搜索。 

搜索范围为：

 - 最小值：`0`- 最大限度：`min(len(tasks), len(workers))`对于每个中点`k`，我们检查是否可以准确分配`k`任务。 

如果可行：

 - 尝试更大的值

 否则：

 - 尝试较小的值

 ### 3. k 个任务的可行性检查

 检查可行性：

 - 采取`k`最简单的任务
 - 采取`k`最强大的工人

 为什么？ 

如果即使是最强大的工人也无法完成最简单的工作`k`任务，那么任何分配都不起作用。 

### 4. 按照从最难到最简单的顺序处理任务

 我们以相反的顺序迭代选定的任务。 

对于每个任务：

 - 将所有可以用丸完成它的工人添加到双端队列中

 条件：```
worker + strength >= task
```这些工人是潜在的候选人。 

### 5. 贪心赋值

 对于当前任务：

 - 如果最强的可用工人可以在不使用药丸的情况下完成任务，请使用他们
 - 否则，使用可以用药丸完成任务的最弱工人

 这是关键的贪心步骤。 

为什么？ 

如果工作人员已经可以自然完成任务，那么使用药丸就会浪费资源。 

如果需要采取避孕措施，我们会使用最弱的可行工人来保留更强大的工人以完成后续任务。 

### 6. 跟踪药丸使用情况

 每当工人需要服药时：

 - 减少剩余药丸的数量

 如果药丸呈阴性：

 - 可行性立即失败

 ### 7. 继续，直到分配完所有任务

 如果全部`k`任务分配成功：

 - 返回`True`否则：

 - 返回`False`### 为什么它有效

 正确性依赖于贪婪交换论证。 

对于剩下的最困难的任务：

 - 使用最强大的可用工人而不使用药丸始终是最佳选择
 - 如果需要避孕药，使用最弱的可行工人可以为未来更困难的任务保留更强大的工人

 由于任务是从最难到最简单的顺序处理的，因此未来的任务只会变得更容易。 因此，保留更强大的工人永远不会有坏处。 

二分搜索之所以有效，是因为可行性是单调的。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def maxTaskAssign(
        self,
        tasks: List[int],
        workers: List[int],
        pills: int,
        strength: int
    ) -> int:

        tasks.sort()
        workers.sort()

        n = len(tasks)
        m = len(workers)

        def can_assign(k: int) -> bool:
            available = deque()
            worker_index = m - k
            remaining_pills = pills

            for task_index in range(k - 1, -1, -1):
                current_task = tasks[task_index]

                while (
                    worker_index < m and
                    workers[worker_index] + strength >= current_task
                ):
                    available.append(workers[worker_index])
                    worker_index += 1

                if not available:
                    return False

                if available[-1] >= current_task:
                    available.pop()
                else:
                    if remaining_pills == 0:
                        return False

                    remaining_pills -= 1
                    available.popleft()

            return True

        left = 0
        right = min(n, m)

        while left < right:
            mid = (left + right + 1) // 2

            if can_assign(mid):
                left = mid
            else:
                right = mid - 1

        return left
```实现首先对两个数组进行排序。 这使得后面使用的贪婪排序策略成为可能。 

这`can_assign`helper 确定是否准确`k`任务可以完成。 

在这个助手里面：

 - 我们考虑`k`最简单的任务
 - 我们使用`k`最强大的工人

 双端队列存储能够使用药丸处理当前任务的工人。 

当我们从更困难的任务转向更容易的任务时：

 - 更多工人有资格
 - 工作人员按排序顺序插入双端队列中

 对于每个任务：

 - 如果最强大的工人能自然地做到这一点，我们就使用他们
 - 否则，我们会在最弱的可行工人身上花费一颗药丸

 最后，二分查找重复调用可行性检查器，直到找到最大有效值。 

## 解决方案```go
package main

import (
	"container/list"
	"sort"
)

func maxTaskAssign(tasks []int, workers []int, pills int, strength int) int {
	sort.Ints(tasks)
	sort.Ints(workers)

	n := len(tasks)
	m := len(workers)

	canAssign := func(k int) bool {
		deque := list.New()

		workerIndex := m - k
		remainingPills := pills

		for taskIndex := k - 1; taskIndex >= 0; taskIndex-- {
			currentTask := tasks[taskIndex]

			for workerIndex < m &&
				workers[workerIndex]+strength >= currentTask {

				deque.PushBack(workers[workerIndex])
				workerIndex++
			}

			if deque.Len() == 0 {
				return false
			}

			back := deque.Back().Value.(int)

			if back >= currentTask {
				deque.Remove(deque.Back())
			} else {
				if remainingPills == 0 {
					return false
				}

				remainingPills--
				deque.Remove(deque.Front())
			}
		}

		return true
	}

	left := 0
	right := n

	if m < right {
		right = m
	}

	for left < right {
		mid := (left + right + 1) / 2

		if canAssign(mid) {
			left = mid
		} else {
			right = mid - 1
		}
	}

	return left
}
```Go 实现遵循与 Python 版本相同的算法结构。 

一个显着的区别是双端队列处理。 Python提供了`collections.deque`，而 Go 使用`container/list`模拟双端队列。 

另一个区别是从链表检索值时的类型断言：```go
deque.Back().Value.(int)
```由于所有强度值都符合 32 位整数限制，因此标准 Go`int`LeetCode 上的算术是安全的。

 ## 边缘情况

 当即使使用药物也无法完成任务时，就会出现一种重要的边缘情况。 例如：```
tasks = [100]
workers = [1]
pills = 1
strength = 5
```幼稚的实现可能会错误地假设拥有药物总是可以保证至少一项任务。 可行性检查正确地拒绝了工人，因为：```
1 + 5 < 100
```双端队列保持为空，函数立即返回`False`。 

另一个重要的情况是，当药物没有任何益处时，因为`strength = 0`。 在这种情况下，药丸应该充当无用的资源。 一些实现意外地不必要地消耗了药丸，或者即使没有发生任何改善，也以不同的方式对待增强的工人。 该解决方案仅在工人无法自然完成任务时使用药丸，因此保留了正确性。 

重复值也很重要。 多项任务和工人可能具有相同的优势。 一些贪婪的实现会失败，因为它们依赖于唯一性假设或不稳定的顺序。 由于该算法完全适用于排序数组和相对比较，因此可以自然且正确地处理重复项。 

当一个强壮的工人可以完成一项简单的任务，而一个较弱的工人需要服用药物时，就会出现一种微妙的边缘情况。 一个糟糕的贪婪选择可能会提前浪费强大的工人，并在以后留下不可能的艰巨任务。 从最难到最简单的顺序处理任务可以避免这个问题，因为困难的任务首先被优先考虑。
