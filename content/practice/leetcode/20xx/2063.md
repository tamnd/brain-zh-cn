[LeetCode 问题 2063](https://leetcode.com/problems/vowels-of-all-substrings/)

 **难度：** 🟡 中等
 **主题：** 数学、字符串、动态规划、组合学

 ## 解决方案

 ## 问题理解

 该问题要求我们计算给定字符串的每个可能子字符串中出现的元音总数。 

子字符串是任何连续的字符序列。 对于一个长度的字符串`n`， 有`n * (n + 1) / 2`总子串。 对于每个子字符串，我们计算它包含多少个元音，然后将所有这些计数加在一起。 

元音是小写英文字母：```
a, e, i, o, u
```输入是单个字符串`word`仅由小写英文字母组成。 输出是一个整数，表示所有子串中元音的总贡献。 

约束条件很重要：

 -`1 <= word.length <= 10^5`一个长度的字符串`100000`可以生成大约`5 * 10^9`子字符串太多，无法直接枚举。 这立即告诉我们，任何显式生成子字符串的强力方法都会太慢。 

另一个重要细节是答案可能超过 32 位有符号整数。 这意味着我们必须使用更大的整数类型：

 - Python自动处理大整数
 - 在Go中，我们应该使用`int64`有几种边缘情况值得尽早识别：

 - 没有元音的字符串，例如`"ltcd"`，应该返回`0`- 每个字符都是元音的字符串会产生非常大的总数
 - 单字符字符串应该仍然可以正常工作
 - 非常大的输入需要高效的线性时间解决方案
 - 重复的元音可以在重叠的子串中多次贡献

 关键的挑战是避免显式子串生成，同时仍然正确计算所有元音出现的次数。 

## 方法

 ### 蛮力方法

 最直接的解决方案是生成每个可能的子串并计算每个子串包含多少个元音。 

对于每个起始索引`i`，我们可以将子字符串扩展到每个结束索引`j`, 形成`word[i:j+1]`。 然后我们计算该子字符串内的元音并将结果添加到最终答案中。 

这种方法是正确的，因为它确实遵循了问题的定义。 每个子串都被检查一次，并且直接计算其中的元音数量。 

然而，性能极差。 

有`O(n^2)`子串。 计算每个子串内的元音需要花费`O(n)`时间，导致总复杂度为`O(n^3)`。 

即使进行了诸如前缀和之类的优化，最好的暴力式解决方案仍然需要迭代所有子字符串，从而导致`O(n^2)`时间。 自从`n`可以是`100000`, this is still far too slow.

 ### 最佳方法

 关键的见解是我们不需要单独生成子字符串。 

相反，我们可以确定有多少子串包含每个元音字符。 

Suppose a vowel appears at index`i`。 

要形成包含该字符的子字符串：

 - 子字符串可以从任意索引处开始`0`到`i`- 子字符串可以在任意索引处结束`i`到`n - 1`因此：

 - 可能的起始位置数 =`i + 1`- 可能的结束位置数 =`n - i`所以包含该字符的子串总数为：$(i+1)(n-i)$每个子串都准确贡献`1`元音从该特定字符开始计数。 

因此，每当我们遇到元音时，我们只需添加：$(i+1)(n-i)$到答案。 

这将问题转化为简单的线性扫描。

 ## 算法演练

 1. 初始化变量`total_vowels`存储最终答案。 
2. 创建一个包含所有元音的集合：```
{'a', 'e', 'i', 'o', 'u'}
```集合允许恒定时间的成员资格检查。 
3. 使用索引迭代字符串`i`和性格`ch`。 
4. 对于每个字符，检查它是否是元音。 
5. 如果该字符是元音，则计算有多少个子串包含该字符。 

子串：

 - 可以从索引的任何地方开始`0`通过`i`- 可以从索引处的任何地方结束`i`通过`n - 1`所以：```
contribution = (i + 1) * (n - i)
```6. 将此贡献添加到`total_vowels`。 
7. 继续，直到处理完整个字符串。 
8. 返回`total_vowels`。 

### 为什么它有效

 每个子串贡献都可以按字符位置分解。 

对于索引处的元音`i`，每个包含索引的子串`i`恰好贡献了该字符的一个元音计数。 这样的子串的数量正好是：$(i+1)(n-i)$通过对每个元音位置的该值求和，我们将每个子串中的每个元音出现次数恰好计数一次。 没有遗漏任何子串，也没有重复计算贡献。 

## Python 解决方案```python
class Solution:
    def countVowels(self, word: str) -> int:
        n = len(word)
        vowels = {'a', 'e', 'i', 'o', 'u'}

        total_vowels = 0

        for index, char in enumerate(word):
            if char in vowels:
                total_vowels += (index + 1) * (n - index)

        return total_vowels
```实现首先将字符串长度存储在`n`，因为我们在贡献计算期间重复使用它。 

创建一组元音是为了进行有效的成员资格测试。 使用集合可确保每次查找以平均恒定时间运行。 

然后该算法使用一次扫描字符串`enumerate`，它提供索引和字符。 

每当当前字符是元音时，我们就会计算有多少个子串包含该位置。 表达式：```python
(index + 1) * (n - index)
```计算包含该字符的子字符串的所有有效开始和结束组合。 

该贡献直接添加到`total_vowels`。 

最后返回累积的答案。 

由于 Python 整数自动扩展为任意精度，因此不需要特殊的溢出处理。 

## 解决方案```go
func countVowels(word string) int64 {
    n := len(word)

    vowels := map[byte]bool{
        'a': true,
        'e': true,
        'i': true,
        'o': true,
        'u': true,
    }

    var totalVowels int64 = 0

    for i := 0; i < n; i++ {
        if vowels[word[i]] {
            totalVowels += int64(i+1) * int64(n-i)
        }
    }

    return totalVowels
}
```Go 解决方案遵循与 Python 版本相同的逻辑。 

一个重要的区别是整数处理。 由于答案可能超出 32 位整数限制，因此我们明确使用`int64`对于结果和乘法期间。 

该字符串直接使用索引`word[i]`，它返回一个`byte`。 因此，元音查找图也使用`byte`键。 

Go 没有 Python 的任意精度整数，因此在算术运算期间需要仔细进行类型转换。

 ## 边缘情况

 ### 没有元音的字符串

 一个字符串，例如`"ltcd"`根本不包含元音。 有缺陷的实现可能会意外地计算辅音或错误地处理空贡献计算。 

此实现可以自然地处理这种情况，因为仅当当前字符属于元音集时才会添加贡献。 如果没有找到元音，则总数仍为`0`。 

### 每个字符都是元音的字符串

 输入如`"aaaaa"`产生非常大的总数，因为每个字符都贡献许多子字符串。 这可能会暴露具有固定宽度整数的语言中的整数溢出问题。 

Python 解决方案使用任意精度整数自动处理此问题。 Go 实现明确使用`int64`安全地存储大值。 

### 非常大的输入

 最大输入大小为`100000`。 任何显式生成子字符串的方法都会超时或消耗过多的内存。 

此实现完全避免了子字符串构造。 它一次性处理字符串，并且仅使用恒定的额外空间，即使在最大约束下也能保持高效。 

### 单字符串

 单字符字符串是最小的有效输入，很容易因差一错误而被错误处理。 

例如：

-`"a"`应该返回`1`-`"b"`应该返回`0`贡献公式：$(i+1)(n-i)$即使在以下情况下也能正常工作`n = 1`，因此这些边缘情况会被自动处理。
