 **难度：** 🟡 中等
 **主题：** 字符串、二分查找、滑动窗口、前缀和

 ## 解决方案

 ## 问题理解

 这个问题要求我们最大化真/假考试答案中相同答案的连续块的长度。 输入字符串`answerKey`仅包含两个字符，`'T'`和`'F'`，代表每个问题的答案。 我们还得到一个整数`k`，它代表我们允许进行的最大修改次数。 

修改意味着将任何字符更改为`'T'`或者`'F'`。 由于只有两个可能的字符，因此每次修改都会在需要时有效地将一个字符翻转为相反的值。 

目标是在执行最多之后确定最大可能的连续相同字符数`k`变化。 

例如，如果我们有`"TFFT"`和`k = 1`，我们可以改变一个`'T'`进入`'F'`并获得`"FFFT"`或者`"TFFF"`。 无论哪种情况，最长的连续块的长度`3`。 

约束条件很重要：

 -`1 <= n <= 5 * 10^4`- 该字符串仅包含`'T'`和`'F'`-`1 <= k <= n`输入大小可能高达五万个字符，这立即告诉我们二次算法可能会太慢。 一个`O(n^2)`在最坏的情况下，方法可能需要数十亿次操作，因此我们需要线性或接近线性的解决方案。 

一些边缘情况很重要：

 - 整个字符串可能已经包含相同的字符。 
-`k`可能大到足以改变每个相反的角色。 
- 最佳答案可能是将角色变成`'T'`或进入`'F'`，所以我们必须考虑这两种可能性。 
- 非常小的输入，例如长度`1`仍必须正常工作。 
- 长交替图案，例如`"TFTFTFTF"`可以暴露窗口管理逻辑中的错误。 

## 方法

 ### 蛮力方法

 一种直接的方法是检查每个可能的子字符串并确定它是否可以转换为所有`'T'`或全部`'F'`最多使用`k`变化。 

对于每个起始索引，我们一次扩展子字符串一个字符。 在扩展的同时，我们计算有多少`'T'`和`'F'`字符存在于当前子字符串内。 如果两个字符之间的较小计数最多为，则子字符串可以变得完全相同`k`。 

例如：

 - 子串`"TFFT"`包含：

 -`2` `'T'`-`2` `'F'`- 我们需要翻转较小的组，这会花费`2`运营。 

如果该成本小于或等于`k`，子串有效。 

这种方法是正确的，因为它检查每个可能的子串并直接验证它是否满足条件。 然而，它太慢了，因为有`O(n^2)`子串，每个子串可能需要额外的工作来评估。 

和`n = 50,000`，这变得不切实际。 

### 最优滑动窗口方法

 关键的观察是我们不需要独立评估每个子串。 

假设我们想找到可以成为所有的最长子串`'T'`。 这意味着子字符串最多可以包含`k` `'F'`字符，因为这些是我们需要翻转的字符。 

同样，如果我们希望子串全部变成`'F'`，那么它最多可能包含`k` `'T'`人物。 

这立即表明了滑动窗口策略。 

我们维护一个窗口`[left, right]`并将其向右展开。 在窗口内，我们计算需要翻转的字符数量。 如果数量超过`k`，窗口无效，因此我们将左边界向前移动，直到窗口再次有效。 

由于每个字符最多进入和离开窗口一次，因此该算法以线性时间运行。 

我们运行滑动窗口两次：

 1. 最长的窗口可转化为所有`'T'`2. 最长窗口可转化为所有`'F'`答案是两个结果中的最大值。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 单独检查每个子字符串 |
 | 最优滑动窗口| O(n) | O(1) | O(1) | 动态扩大和缩小有效窗口 |

 ## 算法演练

 ### 第 1 步：定义辅助函数

 我们创建一个辅助函数，用于计算可以转换为所选目标字符的最长有效子字符串。 

例如：

 - 目标`'T'`意味着我们最多可以容忍`k` `'F'`人物。 
- 目标`'F'`意味着我们最多可以容忍`k` `'T'`人物。 

### 步骤2：初始化滑动窗口

 我们维持：

 -`left`, 窗口的左边界
 -`max_length`，迄今为止看到的最佳答案
 -`changes_needed`，窗口内与目标不匹配的字符数

 最初：

 -`left = 0`-`changes_needed = 0`### 步骤 3：展开窗口

 我们迭代`right`从`0`到`n - 1`。 

每当`answerKey[right]`不等于目标字符，我们递增`changes_needed`。 

这意味着当前窗口需要再进行一次修改。 

### 步骤4：如果无效则缩小窗口

 如果`changes_needed > k`，在允许的操作范围内，当前窗口无法转换为目标字符。 

我们反复搬家`left`向前直到窗口再次有效。 

每当被删除的角色做出贡献时`changes_needed`，我们递减计数器。 

### 第 5 步：更新最佳答案

 恢复有效性后，当前窗口满足约束。 

我们计算：```
window_length = right - left + 1
```并更新`max_length`。 

### 第 6 步：求解两个字符

 我们运行辅助函数两次：

 - 一旦瞄准`'T'`- 一旦瞄准`'F'`最终的答案是两个结果中较大的一个。 

### 为什么它有效

 滑动窗口始终保持以当前结束的最大有效窗口`right`指数。 

如果一个窗口最多需要`k`修改为完全成为一个角色。 每当窗口变得无效时，从左侧缩小就可以保证恢复有效性，因为删除字符只能减少所需的更改次数。 

由于在扩展过程中考虑了每个有效的候选窗口，并且没有跳过更大的有效窗口，因此算法正确地找到了最大可能的长度。 

## Python 解决方案```python
class Solution:
    def maxConsecutiveAnswers(self, answerKey: str, k: int) -> int:
        def longest_window(target: str) -> int:
            left = 0
            changes_needed = 0
            max_length = 0

            for right in range(len(answerKey)):
                if answerKey[right] != target:
                    changes_needed += 1

                while changes_needed > k:
                    if answerKey[left] != target:
                        changes_needed -= 1
                    left += 1

                max_length = max(max_length, right - left + 1)

            return max_length

        return max(longest_window('T'), longest_window('F'))
```实现直接遵循滑动窗口策略。 

辅助函数`longest_window`计算可以完全等于所选目标字符的最长子字符串。 变量`changes_needed`跟踪当前窗口内有多少字符与目标不同。 

作为`right`指针扩展窗口，我们包含新字符并在必要时更新不匹配计数。 

每当不匹配计数超过`k`，窗口失效。 然后我们移动`left`指针向前移动，直到所需更改的数量再次处于允许的限制内。 

在每一步中，当前窗口表示以当前结尾的最大有效子串`right`位置，所以我们更新`max_length`。 

最后，我们计算两个可能的目标字符的最佳结果并返回较大的值。 

## 解决方案```go
func maxConsecutiveAnswers(answerKey string, k int) int {
    longestWindow := func(target byte) int {
        left := 0
        changesNeeded := 0
        maxLength := 0

        for right := 0; right < len(answerKey); right++ {
            if answerKey[right] != target {
                changesNeeded++
            }

            for changesNeeded > k {
                if answerKey[left] != target {
                    changesNeeded--
                }
                left++
            }

            windowLength := right - left + 1
            if windowLength > maxLength {
                maxLength = windowLength
            }
        }

        return maxLength
    }

    tResult := longestWindow('T')
    fResult := longestWindow('F')

    if tResult > fResult {
        return tResult
    }

    return fResult
}
```Go 的实现与 Python 解决方案非常相似。 

一个显着的区别是 Go 字符串以字节为索引，因此目标参数使用类型`byte`而不是字符串字符。 由于输入仅包含 ASCII 字符`'T'`和`'F'`，字节索引是完全安全高效的。 

Go 不提供内置的`max`函数用于整数，因此比较是手动编写的。 

不需要额外的切片或映射，保持内存使用恒定。

 ## 边缘情况

 当字符串已包含所有相同的字符时，就会出现一种重要的边缘情况。 例如，`"TTTTTT"`根本不需要任何修改。 有缺陷的实现可能仍然会尝试不必要的收缩或错误地计算修改。 滑动窗口解决方案可以自然地处理这个问题，因为`changes_needed`永远不会超过`k`，因此窗口只是扩展到整个字符串。 

另一个关键情况是交替模式，例如`"TFTFTFTF"`。 这些输入经常会暴露窗口维护中的错误，因为不匹配计数经常变化。 实现通过递增来正确处理这个问题`changes_needed`每当非目标字符进入窗口时，每当该字符离开窗口时，它就会递减。 

第三个重要的边缘情况发生在`k`足够大以转换整个字符串。 例如，如果`answerKey = "TFTF"`和`k = 4`，每个字符都可以转换为相同的值。 该算法正确地将窗口扩展到完整字符串长度，因为不匹配计数永远不会超过允许的限制。 

另一个微妙的情况涉及窗口的反复缩小。 考虑`"TFFFTT"`和`k = 1`。 随着窗口的扩展，它最终会包含太多不匹配项，并且必须重复移动`left`指针向前。 不正确的实现有时只缩小一次，而不是继续直到窗口再次有效。 这`while changes_needed > k`循环在继续之前通过完全恢复有效性来保证正确性。
