[LeetCode 问题 2059](https://leetcode.com/problems/minimum-operations-to-convert-number/)

 **难度：** 🟡 中等
 **主题：** 数组、广度优先搜索

 ## 解决方案

 ## 问题理解

 该问题要求我们使用最少的运算次数将起始整数转换为目标整数。 在每一步中，我们可以选择任意数字`nums`数组并对当前值应用三个操作之一：

 - 添加
 - 减法
 - 按位异或

 当前值存储在变量中`x`，最初等于`start`。 

有一个非常重要的限制。 只有当当前值保持在范围内时，我们才可以继续执行操作`[0, 1000]`。 但是，即使操作将值移动到此范围之外，它仍然被视为有效。 不同之处在于，一旦该值超出`[0, 1000]`，该过程立即停止，并且不能执行进一步的操作。 

目标是确定达到目标所需的最少操作次数`goal`。 如果不可能，我们就返回`-1`。 

输入包括：

 -`nums`，不同整数的数组
 -`start`，初始值
 -`goal`, 期望的目标值

 输出是一个整数，表示所需的最小操作数。 

这些约束揭示了一个重要的细节。 虽然`goal`和值`nums`可能非常大，我们可以继续探索的唯一值是之间的整数`0`和`1000`。 这意味着可搜索的状态空间实际上非常小，只有 1001 个可能的可重用状态。 

这强烈建议将问题建模为图遍历问题。 

一些边缘情况很重要：

 - 目标可能位于室外`[0, 1000]`- 中间状态可能超出有效范围
 - 异或运算可以显着改变值
 - 如果我们不跟踪访问值，某些状态可能会无限重复
 - 需要最短的操作顺序，而不是任何顺序

 由于该问题要求未加权状态图中的操作数量最少，因此广度优先搜索是自然的解决方案。 

## 方法

 ### 蛮力方法

 暴力解决方案将在每一步递归地尝试所有可能的操作。 

从一个值`x`，我们可以生成：

 -`x + nums[i]`-`x - nums[i]`-`x ^ nums[i]`对于每个索引`i`。 

这将探索所有可能的操作序列，直到：

 - 我们到达`goal`- 我们超出了一些任意的递归深度

 这种方法在理论上是正确的，因为它最终探索了所有可能的路径。 然而，这在计算上是不可行的，因为可能的序列数量呈指数增长。 

另一个主要问题是重复状态。 例如，我们可能会在两个数字之间反复移动：```
5 -> 7 -> 5 -> 7
```如果没有记忆或访问跟踪，递归可能永远不会有效终止。 

### 关键见解

 重要的观察是只有范围内的值`[0, 1000]`可以产生更多的状态。 

这意味着整个可搜索图最多包含 1001 个可重用节点。 

每个有效数字代表一个图节点。 从每个节点，我们可以使用三个允许的操作转换到新数字。 

由于每个操作的成本相等，一步到位，广度优先搜索保证我们第一次达到目标时所需的操作次数最少。 

BFS 是理想的，因为：

 - 它逐级探索状态
 - 第一次访问一个州使用最短路径
 - 可搜索的状态空间很小

 ## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 探索所有无需高效剪枝的操作序列 |
 | 最优 BFS | O(1000 × n) | O(1000) | 最多探索一次每个有效状态 |

 这里，`n`是`len(nums)`。 

## 算法演练

 1. 为广度优先搜索创建队列。 

BFS 逐级处理状态，这自然对应于执行的操作数。 
2. 创建一个`visited`放。 

由于状态可以重复，我们必须避免多次重新访问相同的值。 否则，循环可能会导致无限处理。 
3.将起始值插入到带有距离的队列中`0`。 

队列存储对：```
(current_value, operations_used)
```4. 当队列不为空时，移除最前面的状态。 

这给了我们用最少的操作数可以到达的下一个状态。 
5. 对于每一个数字`nums`，生成三个可能的下一个状态：

 -`current + num`-`current - num`-`current ^ num`6. 如果任何生成的值等于`goal`，立即返回：```
operations + 1
```BFS 保证这是最短的可能路径。 
7. 否则，如果生成的值在`[0, 1000]`并且尚未被访问过：

 - 标记已访问
 - 将其添加到队列中

 只有这些值才能继续生成未来的状态。 
8.如果BFS完成后没有找到`goal`， 返回`-1`。 

### 为什么它有效

 广度优先搜索探索所有可达的状态`k`在探索需要的状态之前进行操作`k + 1`运营。 因此，我们第一次遇到`goal`，我们找到了最少的操作次数。 

访问集保证每个可重用状态最多处理一次，从而防止循环和冗余工作。 

## Python 解决方案```python
from collections import deque
from typing import List

class Solution:
    def minimumOperations(self, nums: List[int], start: int, goal: int) -> int:
        queue = deque([(start, 0)])
        visited = {start}

        while queue:
            current, steps = queue.popleft()

            for num in nums:
                next_values = [
                    current + num,
                    current - num,
                    current ^ num
                ]

                for next_value in next_values:
                    if next_value == goal:
                        return steps + 1

                    if 0 <= next_value <= 1000 and next_value not in visited:
                        visited.add(next_value)
                        queue.append((next_value, steps + 1))

        return -1
```实现首先使用起始值和使用的零操作初始化 BFS 队列。 

一个`visited`set 用于防止多次处理相同的状态。 因为只有在以下范围内的值`[0, 1000]`可能会继续生成新的状态，仅存储和探索这些值。 

在 BFS 循环内，我们从队列中删除当前状态，并使用加法、减法和异或运算生成所有可能的下一个值。 

如果任何生成的值等于`goal`，我们立即返回当前距离加一。 这是可行的，因为 BFS 保证最短路径。 

如果生成的值仍在有效探索范围内并且之前未被访问过，则将其添加到队列中以供将来处理。 

如果队列在未到达目标的情况下变空，则不存在有效序列，因此我们返回`-1`。 

## 解决方案```go
package main

func minimumOperations(nums []int, start int, goal int) int {
	type State struct {
		value int
		steps int
	}

	queue := []State{{start, 0}}
	visited := make(map[int]bool)
	visited[start] = true

	for len(queue) > 0 {
		current := queue[0]
		queue = queue[1:]

		for _, num := range nums {
			nextValues := []int{
				current.value + num,
				current.value - num,
				current.value ^ num,
			}

			for _, nextValue := range nextValues {
				if nextValue == goal {
					return current.steps + 1
				}

				if nextValue >= 0 && nextValue <= 1000 && !visited[nextValue] {
					visited[nextValue] = true
					queue = append(queue, State{
						value: nextValue,
						steps: current.steps + 1,
					})
				}
			}
		}
	}

	return -1
}
```Go 实现遵循与 Python 版本相同的 BFS 策略。 

由于Go没有提供内置的双端队列，因此队列是使用切片来实现的。 我们通过切片从前面删除元素：```go
queue = queue[1:]
```这`visited`结构是使用一个实现的`map[int]bool`。 

Go 整数足以解决这个问题，因为约束安全地符合标准整数范围。

 ## 边缘情况

 当目标位于有效探索范围之外时，会出现一种重要的边缘情况`[0,1000]`。 幼稚的实现可能会立即错误地拒绝此类状态。 然而，该问题明确允许最终操作移出范围。 BFS 正确检查生成的值是否等于`goal`在对未来勘探实施范围限制之前。 

另一个棘手的情况涉及循环。 例如，操作可以在相同的几个值之间重复交替。 如果没有访问集，算法可以无限期地处理相同的状态。 该实现通过在第一次遇到每个可重用状态时将其标记为已访问来防止这种情况发生。 

当不存在解决方案时，就会出现第三种重要的边缘情况。 有些目标根本上是无法访问的，因为允许的操作无法生成它们。 BFS 很自然地通过探索所有可达状态来处理这种情况。 如果队列最终变空，算法将正确返回`-1`。 

第四个微妙的情况涉及异或运算。 XOR 可能会产生与算术运算截然不同的不直观的转换。 仅基于数字距离的贪婪方法在这里会严重失败。 BFS 完全避免了这个问题，因为它按照操作计数的顺序系统地探索每个可达状态。
