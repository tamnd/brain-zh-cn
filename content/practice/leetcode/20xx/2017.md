 # LeetCode 2017 - 网格游戏

 ## 问题理解

 这个问题给了我们一个`2 x n`网格，其中每个单元格包含一定数量的点。 两个机器人相继穿过这个网格。 两个机器人都从左上角开始`(0, 0)`并且必须到达右下角`(1, n - 1)`。 

移动规则非常严格。 机器人只能移动：

 - 对了，从`(r, c)`到`(r, c + 1)`- 向下，从`(r, c)`到`(r + 1, c)`由于网格只有两行，因此每个有效路径都有一个非常重要的属性：每个机器人在顶行向右移动几次，然后向下移动一次，然后在底行继续向右移动。 

第一个机器人首先移动并收集沿其路径的所有点。 然后将第一个机器人访问的每个单元设置为`0`。 之后，第二个机器人在修改后的网格上移动并从剩余的单元格中收集点。 

两个机器人的目标是相反的：

 - 第一个机器人想要最小化第二个机器人的最终得分。 
- 第二个机器人想要最大化自己的分数。 

如果两个机器人都表现最佳，我们必须确定第二个机器人获得的分数。 

约束条件很重要：

 -`n`可以大到`5 * 10^4`- 每个单元格值最多可达`10^5`这意味着总和可能会变得非常大，因此我们必须在 Go 等语言中使用 64 位整数。 这些限制也使得暴力枚举所有可能的路径变得不切实际。 

一个重要的观察是，由于网格只有两行，因此第一个机器人的路径完全由它从顶行向下移动到底行的列决定。 

一些边缘情况很重要：

 -`n = 1`，两个机器人被迫走上同一条路径。 
- 非常大的值，在某些语言中可能出现整数溢出。 
- 最优策略局部不明显的情况，因为第一个机器人正在最小化第二个机器人的最大可能剩余分数。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试第一个机器人可以向下移动的所有可能的列。 对于每个这样的选择，我们在第一个机器人清除其路径后模拟结果网格。 然后我们计算第二个机器人在修改后的网格上可以获得的最大分数。 

由于网格只有两行，因此正好有`n`第一个机器人可能的转折点。 对于每个转折点，我们可以通过再次扫描行来重新计算网格上的剩余总和。 

这种方法之所以有效，是因为它明确检查第一个机器人的每个有效策略，并计算第二个机器人产生的最佳响应。 然而，如果简单地实施，每次模拟都会花费`O(n)`，我们这样做`n`次，导致`O(n^2)`复杂。 

和`n = 5 * 10^4`，二次时间太慢。 

### 最佳方法

 关键的见解是，一旦第一个机器人选择了一列`c`在向下移动的地方，剩余的网格具有非常可预测的结构。 

假设第一个机器人：

 - 从列沿顶行移动`0`到`c`- 在列处向下移动`c`- 从列沿底部行移动`c`到`n - 1`发生这种情况后：

 - 顶行中的剩余单元格只是右侧的列`c`- 底行中的剩余单元格仅是左侧的列`c`第二个机器人只能有效地从这两个区域之一收集点：

 - 其余的右上角部分
 - 或剩余的左下部分

 因此，如果第一个机器人在柱处转弯`c`，第二个机器人的得分变为：```
max(
    remaining sum in top row after c,
    remaining sum in bottom row before c
)
```第一个机器人想要最小化这个值。 

这将问题转化为前缀/后缀和优化问题。 

我们维持：

 -`topRemaining`, 顶行的后缀和
 -`bottomCollected`，底行的前缀和

 当我们迭代每个可能的转动列时，我们计算：```
secondRobot = max(topRemaining, bottomCollected)
```然后我们在所有选择中最小化这一点。 

这给出了一个`O(n)`解决方案。

 ## 算法演练

 1. 计算顶行的总和。 

这表示在第一个机器人开始移除单元之前顶行仍然可用的点。 
2. 初始化两个运行值。 

-`topRemaining`从顶行总和开始。 
-`bottomCollected`开始为`0`。 

这些代表：

 - 转折点右侧顶行中剩余的点。 
- 转折点左侧底行累积的分数。 
3. 迭代每一列`c`。 

处理柱`c`作为第一个机器人向下移动的点。 
4. 删除当前顶行单元格`topRemaining`。 

自从第一个机器人访问以来`(0, c)`，第二个机器人将无法使用该单元。 
5. 计算第二个机器人的最佳得分。 

第二个机器人选择哪一方得分更多：

 - 右上角剩余部分
 - 左下累积部分

 所以：```
secondRobot = max(topRemaining, bottomCollected)
```6.更新答案。 

第一个机器人想要最小化第二个机器人的得分：```
answer = min(answer, secondRobot)
```7. 将当前底行单元格添加到`bottomCollected`。 

考虑列后`c`，未来的转折点将使这个底部单元可供第二个机器人使用。 
8. 继续，直到处理完所有列。 
9. 返回找到的最小值。 

### 为什么它有效

 适用于任何旋转柱`c`，第一个机器人移除：

 - 所有顶行单元格来自`0`通过`c`- 所有底行单元格来自`c`通过`n - 1`这恰好留下了两个可能有点的区域：

 - 顶行之后`c`- 底行之前`c`第二个机器人只能最大化这些区域之一，因此其最佳得分是两个总和中的最大值。 由于第一个机器人选择最小化该值的转折点，因此检查所有转折点可以保证最佳答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def gridGame(self, grid: List[List[int]]) -> int:
        n = len(grid[0])

        top_remaining = sum(grid[0])
        bottom_collected = 0

        answer = float("inf")

        for col in range(n):
            top_remaining -= grid[0][col]

            second_robot = max(top_remaining, bottom_collected)

            answer = min(answer, second_robot)

            bottom_collected += grid[1][col]

        return answer
```该实现首先计算顶行的总和。 这使我们能够在从左向右移动时动态跟踪剩余的顶行点。 

在循环内部，我们首先减去当前顶行值，因为第一个机器人在当前列转动时会消耗该单元格。 

接下来，我们计算第二个机器人的最佳得分。 第二个机器人选择包含更多点的剩余区域，因此我们取最大值：

 -`top_remaining`-`bottom_collected`然后，我们最小化总体答案，因为第一个机器人试图降低第二个机器人的最大可达到分数。 

最后，我们将当前底行值添加到`bottom_collected`，为下一次迭代做准备。 

该算法仅使用几个变量，并且每列只处理一次。 

## 解决方案```go
func gridGame(grid [][]int) int64 {
    n := len(grid[0])

    var topRemaining int64
    for _, value := range grid[0] {
        topRemaining += int64(value)
    }

    var bottomCollected int64
    answer := topRemaining

    for col := 0; col < n; col++ {
        topRemaining -= int64(grid[0][col])

        secondRobot := max(topRemaining, bottomCollected)

        answer = min(answer, secondRobot)

        bottomCollected += int64(grid[1][col])
    }

    return answer
}

func max(a, b int64) int64 {
    if a > b {
        return a
    }
    return b
}

func min(a, b int64) int64 {
    if a < b {
        return a
    }
    return b
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 最重要的区别是整数处理。 

由于网格值可能很大并且总和可能超过 32 位整数限制，因此所有运行总和都存储为`int64`。 

Go 不提供内置泛型`min`和`max`整数函数，因此辅助函数是显式实现的。

 ## 边缘情况

 一个重要的边缘情况是当`n = 1`。 在这种情况下，只有一列，因此两个机器人都被迫遵循完全相同的路径。 第一个机器人立即收集所有细胞，不给第二个机器人留下任何细胞。 该实现自然地处理了这个问题，因为`topRemaining`变成`0`在进行任何比较之前。 

另一个重要的边缘情况涉及非常大的网格值。 由于每个单元格最多可以包含`10^5`点，并且可能有`5 * 10^4`列，总和可能会变得非常大。 具有固定宽度整数的语言，例如 Go，必须使用`int64`以避免溢出。 提供的 Go 解决方案将所有值显式转换为`int64`。 

当最佳转折点接近网格的开头或结尾时，会出现第三种重要的边缘情况。 天真的贪婪推理可能会错误地假设机器人应该均匀地平衡两侧。 然而，一些网格高度倾斜，使得极端转折点成为最佳选择。 该算法正确检查每个可能的转动列，确保始终找到真正的最小值。 

当其余两个区域包含相等的总和时，会出现第四种微妙的边缘情况。 在这种情况下，第二个机器人可以达到任一值，但结果保持不变，因为我们只关心可获得的最大分数。 该算法通过以下方式自动处理此问题`max(topRemaining, bottomCollected)`计算。
