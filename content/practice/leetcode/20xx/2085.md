 # LeetCode 2085，统计出现过一次的常用单词

 ## 问题理解

 这个问题给了我们两个字符串数组，`words1`和`words2`。 我们的任务是计算有多少字符串在两个数组中只出现一次。 

关键细节是一个单词只有在以下情况下才符合条件：

 1. 它只出现一次`words1`2. 它只出现一次`words2`如果任一数组多次包含该单词，则该单词不算数。 

例如，考虑：```
words1 = ["leetcode","is","amazing","as","is"]
words2 = ["amazing","leetcode","is"]
```这个词`"leetcode"`在两个数组中都出现一次，因此很重要。 

这个词`"amazing"`在两个数组中也都出现一次，因此很重要。 

这个词`"is"`出现两次`words1`，所以即使它出现在`words2`，不算数。 

每个输入数组最多可以包含 1000 个单词，每个单词最多可以包含 30 个小写英文字母。 这些限制足够小，许多方法都可以在实践中发挥作用，但问题本质上是如何有效地计算频率。 

重要的观察是，问题不在于询问单词是否仅存在于两个数组中。 它特别需要频率计数。 这意味着我们必须跟踪每个单词在每个数组中出现的次数。 

一些边缘情况很重要：

 - 一个单词可以存在于一个数组中，但不能存在于另一个数组中。 
- 一个单词可能在一个数组中出现多次，而在另一个数组中出现一次。 
- 所有单词都可能不同。 
- 所有单词都可以重复多次。 
- 每个数组只能包含一个元素。 

重复扫描数组以获取计数的简单实现可能会变得不必要的缓慢，特别是如果对每个单词都重复扫描的话。 

## 方法

 ### 蛮力方法

 暴力解决方案检查每个唯一的单词并手动计算它在两个数组中出现的次数。 

一种方法是：

 1. 遍历每个单词`words1`2. 计算它出现的次数`words1`3. 计算它出现的次数`words2`4. 如果两个数都等于 1，则增加答案

 计数操作本身需要重复扫描数组。 由于每次查找可能需要线性时间，因此总复杂度变为二次。 

这种方法是正确的，因为它明确地验证了问题所需的确切频率条件。 然而，由于相同的计数工作重复多次，因此效率低下。 

### 最佳方法

 更好的解决方案使用哈希映射（Python 中也称为字典或 Go 中的映射）来存储词频。 

关键的见解是频率计数正是哈希图的设计目的。 我们可以对每个数组进行一次预处理并存储每个单词出现的次数，而不是重复扫描数组。 

构建两个频率图后：

 - 检查第一张地图中的每个单词
 - 如果它的频率在两张图中都是 1，则计数它

 这减少了重复工作并提供了有效的线性时间解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n × m + n²) | O(n × m + n²) | O(1) | O(1) | 重复扫描数组以计算出现次数 |
 | 最佳 | O(n + m) | O(n + m) | 使用哈希映射进行频率计数 |

 这里，`n`的长度是`words1`和`m`的长度是`words2`。 

## 算法演练

 1. 创建哈希映射`words1`。 

该映射将每个单词存储为键，并将其出现次数存储为值。 例如：```
{"leetcode": 1, "is": 2, "amazing": 1, "as": 1}
```使用哈希映射允许恒定的平均时间频率更新。 
2. 创建另一个哈希映射`words2`。 

这对第二个阵列执行相同的频率计数。 
3. 初始化一个名为`common_count`至 0。 

该变量存储在两个数组中仅出现一次的有效单词的数量。 
4. 迭代第一个频率图中的键。 

对于每个单词：

 - 检查是否计入`words1`等于 1
 - 检查是否计入`words2`也等于 1

 如果两个条件都成立，则增加`common_count`。 
5. 返回`common_count`。 

处理完所有单词后，变量包含最终答案。 

### 为什么它有效

 该算法之所以有效，是因为频率图存储了两个数组中每个单词的准确出现次数。 当且仅当一个单词在两个映射中存储的频率都等于 1 时，它才满足问题条件。 由于在预处理过程中每个词频都被正确计算，因此保证了最终计数的正确性。 

## Python 解决方案```python
from typing import List
from collections import Counter

class Solution:
    def countWords(self, words1: List[str], words2: List[str]) -> int:
        frequency1 = Counter(words1)
        frequency2 = Counter(words2)

        common_count = 0

        for word in frequency1:
            if frequency1[word] == 1 and frequency2[word] == 1:
                common_count += 1

        return common_count
```实施从导入开始`Counter`来自Python的`collections`模块。`Counter`自动从单词列表构建频率图。`frequency1`存储计数`words1`， 尽管`frequency2`存储计数`words2`。 

变量`common_count`跟踪找到了多少有效单词。 

循环遍历中的每个唯一单词`frequency1`。 对于每个单词，代码检查两个映射中的计数是否等于 1。 如果是这样，答案就会增加。 

最后，该方法返回总计数。 

该实现直接遵循前面描述的算法，并使用Python内置的数据结构来保持代码简洁高效。 

## 解决方案```go
func countWords(words1 []string, words2 []string) int {
	frequency1 := make(map[string]int)
	frequency2 := make(map[string]int)

	for _, word := range words1 {
		frequency1[word]++
	}

	for _, word := range words2 {
		frequency2[word]++
	}

	commonCount := 0

	for word, count := range frequency1 {
		if count == 1 && frequency2[word] == 1 {
			commonCount++
		}
	}

	return commonCount
}
```Go 实现使用`map[string]int`来存储词频。 

与Python不同`Counter`，Go 在标准库中没有提供自动频率计数实用程序，因此计数是使用循环手动构建的。 

在 Go 映射中查找不存在的键会自动返回该类型的零值，即`0`对于整数。 这使得条件：```go
frequency2[word] == 1
```即使该词不存在于`frequency2`。 

对于空切片不需要特殊处理，因为循环自然会正确处理它们。

 ## 边缘情况

 当一个单词在一个数组中多次出现但在另一个数组中只出现一次时，就会出现一种重要的边缘情况。 有缺陷的实现可能会错误地计算这样的单词，因为它存在于两个数组中。 例如：```
words1 = ["a", "a"]
words2 = ["a"]
```正确答案是`0`， 因为`"a"`不恰好出现一次`words1`。 频率图方法通过显式检查这两个计数来正确处理此问题。 

另一个重要的边缘情况是数组根本不包含重叠单词。 例如：```
words1 = ["x", "y"]
words2 = ["a", "b"]
```假设存在匹配键的简单实现可能会失败或产生不正确的结果。 在 Python 和 Go 中，缺失的键可以安全地计算为`0`，因此实现正确返回`0`。 

当每个单词都是唯一的并且在两个数组之间共享时，就会出现第三种边缘情况。 例如：```
words1 = ["a", "b", "c"]
words2 = ["a", "b", "c"]
```在这种情况下，每个词都应该很重要。 该实现正确识别了所有三个单词，因为每个单词都有频率`1`在两张地图中。 

最后的边缘情况涉及最小尺寸的数组。 这些约束允许数组仅包含一个元素。 例如：```
words1 = ["hello"]
words2 = ["hello"]
```该实现自然地处理了这个问题，因为每个频率图仅包含一个条目，并且比较逻辑保持不变。
