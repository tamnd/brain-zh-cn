[LeetCode 2007 问题](https://leetcode.com/problems/find-original-array-from-doubled-array/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、贪心、排序

 ## 解决方案

 ## 问题理解

 问题给了我们一个名为`changed`，据说是从另一个名为的数组创建的`original`。 

转换过程是这样的：

 1. 取出每个数字`original`。 
2.附加其双倍值，含义`2 * x`。 
3. 将所有数字混在一起。 

例如，如果：```
original = [1, 3, 4]
```那么加倍后的值为：```
[2, 6, 8]
```合并和洗牌后：```
changed = [1, 3, 4, 2, 6, 8]
```我们的任务是重建并返回原始数组。 

如果不存在有效的原始数组，我们必须返回一个空数组。 

一个非常重要的观察是，原始数组中的每个值都必须在数组中的其他位置有一个匹配的双倍值。 这意味着：

 - 如果是一个数字`x`出现`k`原始数组中的次，
 - 然后是号码`2 * x`还必须至少出现`k`次在`changed`。 

限制条件很大：

 -`changed.length`可以达到`10^5`- 值也可以高达`10^5`这些限制立即排除了昂贵的二次方法。 我们需要一些接近的东西`O(n log n)`或更好。 

另一个重要的细节是长度`changed`必须是均匀的。 由于每个原始元素都为最终数组贡献了两个数字，因此有效的双倍数组始终包含偶数个元素。 

有几种棘手的边缘情况：

 - 奇数长度的数组自动无效。 
- 号码`0`很特殊，因为加倍零仍然会得到零。 零必须出现偶数次。 
- 重复会使匹配变得复杂。 
- 错误顺序的贪婪匹配可能会失败。 例如，如果我们在小值之前处理大值，我们可能会消耗稍后需要的数字。 

关键的挑战是将每个数字与其双精度数配对，而不会意外地重复使用元素。 

## 方法

 ### 蛮力方法

 一个简单的暴力策略会尝试重复：

 1. 选择一个号码。 
2. 在数组中的其他位置搜索其加倍后的值。 
3. 如果发现两个号码，请将其删除。 
4. 继续，直到处理完所有元素。 

从概念上讲，这是可行的，因为每个原始值都必须与其加倍的对应值配对。 

然而，这种方法效率低下，因为重复搜索和删除数组中的元素成本很高。 

如果我们使用列表结构并对每个元素执行线性搜索，则复杂度约为`O(n^2)`。 

和`n`最多`100000`，这太慢了。 

### 最佳方法

 关键的见解是匹配必须按排序顺序进行。 

假设我们首先处理较小的数字：

 - 如果我们遇到`x`,
 - 然后我们尝试保留一次`2 * x`。 

这是有效的，因为较小的值应该在较大的值消耗它们之前声明它们的双精度。 

例如：```
[1,2,2,4]
```如果我们处理`2`前`1`，我们可能会错误地使用`4`太早并失去正确配对的能力。 

排序可以避免这个问题。 

我们使用频率图来跟踪每个数字仍有多少可用副本。 

算法变为：

 1. 对数组进行排序。 
2. 计算频率。 
3. 对于按排序顺序的每个数字：

 - 如果没有剩余，请跳过它。 
- 如果其双精度数不存在，则返回`[]`。 
- 否则：

 - 将数字添加到原始数组中。 
- 减少数字及其双倍的计数。 

这种贪婪策略是正确的，因为较小的值总是首先确保其所需的双打。

 ## 算法演练

 1、首先检查长度是否`changed`很奇怪。 

有效的双倍数组所包含的元素数量必须是原始数组的两倍。 因此，元素总数必须是偶数。 

如果长度为奇数，则立即返回一个空数组。 
2. 将数组按升序排序。 

排序至关重要，因为我们希望先处理较小的值，然后再处理较大的值。 这保证了当我们尝试将一个数字与其双精度数匹配时，较小的数字首先要求较大的数字。 
3. 构建频率图。 

我们使用哈希映射，其中：```
frequency[value] = remaining occurrences
```这允许恒定时间的查找和更新操作。 
4. 迭代已排序的数组。 

对于每个数字`num`：

 - 如果其频率已经为零，则意味着该值已在之前的配对中使用过，因此请跳过它。 
- 否则，尝试查找`num * 2`。 
5. 检查是否存在翻倍的值。 

如果：```
frequency[num * 2] == 0
```那么不存在有效的配对，因此返回一个空数组。 
6. 形成有效对。 

由于两个值都存在：

 - 添加`num`到答案。 
- 减少数量`num`。 
- 减少数量`num * 2`。 
7. 继续，直到处理完所有号码。 

如果该过程成功完成，则返回构造的原始数组。 

### 为什么它有效

 正确性依赖于按排序顺序处理数字。 

每个数字必须恰好与一个加倍的值配对。 通过首先处理较小的数字，我们保证较大的数字不会被不正确的匹配过早地消耗掉。 

频率图确保每个元素仅使用一次。 

如果在任何时候所需的双精度不可用，则该数组不可能表示有效的双精度数组。 

## Python 解决方案```python
from collections import Counter
from typing import List

class Solution:
    def findOriginalArray(self, changed: List[int]) -> List[int]:
        n = len(changed)

        if n % 2 == 1:
            return []

        changed.sort()

        frequency = Counter(changed)
        original = []

        for num in changed:
            if frequency[num] == 0:
                continue

            doubled = num * 2

            if frequency[doubled] == 0:
                return []

            original.append(num)

            frequency[num] -= 1
            frequency[doubled] -= 1

        return original
```实现首先检查数组长度是否为奇数。 如果是这样，该函数立即返回一个空列表，因为有效的双倍数组必须包含对。 

接下来，对数组进行排序。 这是最重要的步骤之一，因为它保证较小的值在其双精度之前被处理。 

一个`Counter`然后创建来跟踪每个值有多少个副本未使用。 

迭代期间：

 - 如果某个值已被消耗，则跳过该值。 
- 否则，算法将搜索其加倍的值。 
- 如果无法获得双倍值，则无法重建。 
- 如果存在加倍值，则两个频率都会降低，并将当前数字添加到答案中。 

一旦处理完每个有效对，算法就会结束。 

## 解决方案```go
package main

import "sort"

func findOriginalArray(changed []int) []int {
	n := len(changed)

	if n%2 == 1 {
		return []int{}
	}

	sort.Ints(changed)

	frequency := make(map[int]int)

	for _, num := range changed {
		frequency[num]++
	}

	original := make([]int, 0, n/2)

	for _, num := range changed {
		if frequency[num] == 0 {
			continue
		}

		doubled := num * 2

		if frequency[doubled] == 0 {
			return []int{}
		}

		original = append(original, num)

		frequency[num]--
		frequency[doubled]--
	}

	return original
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个`map[int]int`用来代替Python的`Counter`。 排序是使用完成的`sort.Ints`。 

一个小区别是 Go 返回一个空切片：```go
[]int{}
```而不是Python的`[]`。 

整数溢出在这里不是一个问题，因为值的边界是`10^5`，因此加倍仍然安全地保持在 Go 的整数范围内。

 ## 边缘情况

 ### 奇数长度数组

 如果数组长度为奇数，则无法重建，因为每个原始元素恰好为双倍数组贡献了两个元素。 

幼稚的实现可能仍会尝试匹配并浪费计算时间。 该解决方案立即在恒定时间内拒绝奇数长度数组。 

### 零值

 零是一种特殊情况，因为：```
0 * 2 = 0
```这意味着零必须与另一个零配对。 

奇数个零是无效的。 基于频率的方法自然可以处理这个问题，因为每个配对都会消耗两个零。 

### 重复的数字

 重复的值很容易破坏不正确的贪婪方法。 

考虑：```
[2,4,4,8]
```正确的原始数组是：```
[2,4]
```频率图正确跟踪剩余可用副本的数量，确保每次出现都精确匹配一次。 

### 重叠的配对关系

 有些数字既可以作为原始值，也可以作为加倍值。 

例如：```
[1,2,2,4]
```这里：

-`1`与`2`- 其他`2`与`4`按排序顺序进行处理至关重要。 如果首先处理较大的数字，则有效的较小数字配对可能会被意外破坏。
