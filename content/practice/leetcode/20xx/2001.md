 # LeetCode 2001 - 可互换矩形对的数量

 ## 问题理解

 这个问题要求我们计算有多少对矩形是可以互换的。 每个矩形由两个整数表示，`width`和`height`。 如果两个矩形的宽高比完全相同，则认为它们可以互换。 

用数学术语来说，矩形`i`和`j`在以下情况下可以互换：$$\frac{width_i}{height_i} = \frac{width_j}{height_j}$$重要的细节是这个比较使用实数除法，而不是整数除法。 例如，比率`4/8`,`3/6`， 和`10/20`都等于`0.5`，所以所有这些矩形都属于同一个可互换组。 

输入是一个二维数组，称为`rectangles`，其中每个元素包含两个整数：

 -`rectangles[i][0]`代表宽度
 -`rectangles[i][1]`代表高度

 输出应该是有效对的总数`(i, j)`这样`i < j`并且两个矩形具有相同的比例。 

约束在这里非常重要：

 - 矩形的数量可以大到`10^5`- 宽度和高度也可以达到`10^5`这些限制立即告诉我们二次解不会有效地工作。 一个`O(n^2)`方法需要将每个矩形与其他每个矩形进行比较，这可能会导致大约`10^10`最坏情况下的比较。 

另一个微妙的问题是比率表示。 直接使用浮点数会带来精度问题。 例如，由于舍入行为，两个数学上相等的比率可能不会产生相同的浮点表示。 更安全的方法是使用最大公约数 (GCD) 将每个比率减少为其最简单的分数形式。 

一些边缘情况值得预先考虑。 许多矩形可能具有相同的比例，这可以产生大量的对。 矩形也可能具有完全独特的比率，导致有效对为零。 另一个重要的情况是当宽度和高度很大但仍然可以简化为相同的简化分数时。 

## 方法

 ### 蛮力方法

 最直接的解决方案是比较每对矩形。 

对于每个矩形`i`，我们将它与每个矩形进行比较`j > i`。 我们计算两个比率并检查它们是否相等。 如果它们相等，我们就增加答案。 

这种方法是正确的，因为它明确地检查每个可能的对，因此不会错过任何有效的对。 

然而，时间复杂度为`O(n^2)`。 高达`100000`矩形，这变得太慢了。 即使经过优化的实现也无法在典型的 LeetCode 时间限制内处理数十亿次比较。 

另一个问题是浮点比较。 直接比较小数比可能会导致精度错误。 

### 最佳哈希映射方法

 关键的观察是具有相同缩小比例的矩形属于同一组。 

例如：

-`4/8`减少到`1/2`-`10/20`减少到`1/2`-`15/30`减少到`1/2`我们可以使用 GCD 将每个比率标准化为其简化分数形式，而不是直接比较每一对。 

当我们一张一张地处理矩形时：

 - 我们计算减少的比率
 - 我们计算这个比例已经出现了多少次
 - 之前的每个出现都与当前矩形形成一个新的可互换对

 哈希图使我们能够有效地跟踪比率频率。 

这将解从二次时间转换为线性时间。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|

 ## 算法演练

 1. 创建一个名为的哈希图`ratio_count`。 

键将表示减少的比率，存储为元组`(reduced_width, reduced_height)`。 该值将表示已经看到了多少个具有该比例的矩形。 
2. 初始化变量`pairs`到`0`。 

该变量存储可互换对的总数。 
3. 迭代输入数组中的每个矩形。 

对于每个矩形，提取其宽度和高度。 
4. 计算宽度和高度的最大公约数。 

GCD 允许我们将分数简化为最简单的形式。 

例如：

-`(4, 8)`变成`(1, 2)`-`(10, 20)`变成`(1, 2)`5. 将宽度和高度除以 GCD。 

这会产生归一化比率表示。 
6. 使用缩减对作为哈希映射键。 

由于所有等效比率都减少为同一对，这保证了分组的一致性。 
7. 检查该比例已经出现了多少次。 

假设比例已经出现`k`以前有过几次。 那么当前的矩形正好形成`k`新的可互换对。 
8. 添加`k`到答案。 

每个具有相同比率的先前矩形都与当前矩形配对。 
9. 增加哈希图中当前比率的频率。 

这确保了未来的矩形可以与它配对。 
10. 继续，直到处理完所有矩形。 
11. 返回总对数。 

### 为什么它有效

 该算法之所以有效，是因为每个可互换的对必须共享相同的缩减比率。 通过将每个宽度-高度对简化为规范形式，所有等效矩形都映射到相同的哈希映射键。 

当处理一个矩形时，哈希映射已经包含了具有相同比例的较早矩形的数量。 这些矩形中的每一个都与当前矩形形成一对有效的矩形。 由于在处理后面的矩形时，每一对都被计算一次，因此最终的答案是正确的。 

## Python 解决方案```python
from typing import List
from collections import defaultdict
from math import gcd

class Solution:
    def interchangeableRectangles(self, rectangles: List[List[int]]) -> int:
        ratio_count = defaultdict(int)
        pairs = 0

        for width, height in rectangles:
            divisor = gcd(width, height)

            reduced_width = width // divisor
            reduced_height = height // divisor

            ratio = (reduced_width, reduced_height)

            pairs += ratio_count[ratio]

            ratio_count[ratio] += 1

        return pairs
```解决方案从导入开始`defaultdict`和`gcd`。 哈希图存储每个缩减比率出现的次数。 

对于每个矩形，我们计算 GCD 并将比率简化为最简单的形式。 使用元组可确保比率如`1/2`和`2/4`表示相同。 

在更新地图之前，我们将当前频率添加到答案中。 这会计算所有先前看到的具有相同比例的矩形。 

最后，我们增加比率频率，以便未来的矩形可以与当前的矩形配对。 

## 解决方案```go
package main

func gcd(a int, b int) int {
	for b != 0 {
		a, b = b, a%b
	}
	return a
}

func interchangeableRectangles(rectangles [][]int) int64 {
	ratioCount := make(map[[2]int]int64)

	var pairs int64 = 0

	for _, rectangle := range rectangles {
		width := rectangle[0]
		height := rectangle[1]

		divisor := gcd(width, height)

		reducedWidth := width / divisor
		reducedHeight := height / divisor

		ratio := [2]int{reducedWidth, reducedHeight}

		pairs += ratioCount[ratio]

		ratioCount[ratio]++
	}

	return pairs
}
```Go 解决方案遵循与 Python 实现相同的逻辑。 由于 Go 没有元组作为映射键，因此固定大小的数组`[2]int`被用来代替。 

返回类型是`int64`因为对的数量可能会变得非常大。 在最坏的情况下，如果全部`100000`矩形具有相同的比例，对的数量为：$$\frac{100000 \times 99999}{2}$$这超出了 32 位整数的范围。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个矩形被处理一次 |
 | 空间| O(n) | 哈希映射最多可以存储 n 个唯一的比率 |

 该算法对每个矩形执行恒定的工作。 GCD 计算速度非常快，并且受到相对于输入值的对数复杂度的限制，对于给定的约束，它实际上是恒定的。 

哈希映射为每个不同的比率存储一个条目。 在最坏的情况下，每个矩形都有唯一的比例，因此空间使用量呈线性。 

## 测试用例```python
from typing import List

class Solution:
    def interchangeableRectangles(self, rectangles: List[List[int]]) -> int:
        from collections import defaultdict
        from math import gcd

        ratio_count = defaultdict(int)
        pairs = 0

        for width, height in rectangles:
            divisor = gcd(width, height)
            ratio = (width // divisor, height // divisor)

            pairs += ratio_count[ratio]
            ratio_count[ratio] += 1

        return pairs

solution = Solution()

assert solution.interchangeableRectangles(
    [[4,8],[3,6],[10,20],[15,30]]
) == 6  # all rectangles share the same ratio

assert solution.interchangeableRectangles(
    [[4,5],[7,8]]
) == 0  # no interchangeable rectangles

assert solution.interchangeableRectangles(
    [[2,4],[4,8],[6,12],[3,5]]
) == 3  # three rectangles share ratio 1/2

assert solution.interchangeableRectangles(
    [[1,1]]
) == 0  # single rectangle cannot form a pair

assert solution.interchangeableRectangles(
    [[1,2],[2,4]]
) == 1  # exactly one valid pair

assert solution.interchangeableRectangles(
    [[1,2],[2,4],[3,6],[4,8]]
) == 6  # four rectangles produce six pairs

assert solution.interchangeableRectangles(
    [[100000,50000],[2,1]]
) == 1  # large values with same reduced ratio

assert solution.interchangeableRectangles(
    [[1,3],[2,6],[4,12],[5,15]]
) == 6  # all reduce to 1/3

assert solution.interchangeableRectangles(
    [[1,2],[2,3],[3,4],[4,5]]
) == 0  # every ratio is unique

 ## 边缘情况

 当所有矩形具有相同的比率时，就会出现一种重要的边缘情况。 在这种情况下，根据组合公式，对的数量增长得非常快`n * (n - 1) / 2`。 使用 32 位整数的简单实现可能会溢出。 Go解决方案正确使用`int64`以避免这个问题。 

另一个重要的情况涉及数学上相等但表示方式不同的比率。 例如，`2/4`,`3/6`， 和`50/100`都描述了相同的比率。 直接使用原始宽度和高度值的解决方案将无法将它们组合在一起。 使用 GCD 减少每个比率可以保证正确的标准化。 

第三种边缘情况是每个矩形都有唯一的比例。 在这种情况下，正确答案是零。 该实现自然地处理了这个问题，因为每个比率在哈希图中只出现一次，因此在处理每个新矩形时不存在先前的匹配矩形。
