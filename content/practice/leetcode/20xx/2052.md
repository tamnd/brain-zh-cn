[LeetCode 问题 2052](https://leetcode.com/problems/minimum-cost-to-separate-sentence-into-rows/)

 **难度：** 🟡 中等
 **主题：** 字符串、动态规划

 ## 解决方案

 ## 问题理解

 这个问题要求我们将一个句子格式化为多行，使得每行的长度最多`k`。 该句子由用空格分隔的单词组成，并且单词不能跨行拆分。 我们只能在单词之间插入换行符。 

目标不仅仅是最小化行数。 相反，除了最后一行之外的每一行都会根据未使用的空间产生惩罚。 如果一行有长度`n`，则其成本为：$(k-n)^2$总成本是除最后一行之外的所有行的这些惩罚的总和。 

这本质上是一个文本对齐优化问题。 我们想要决定在哪里放置换行符，以便有效地打包较早的行，因为大量未使用的空间会产生较大的二次损失。 

输入包括：

 -`sentence`, 由单个空格分隔的小写单词字符串
 -`k`, 允许的最大行长度

 产出是可实现的最小总成本。 

约束条件很重要：

 -`sentence.length <= 5000`-`k <= 5000`- 每个单词的长度最多为`k`这些限制立即表明指数搜索是不可能的。 由于可能有数千个单词，我们需要一个多项式时间的解决方案。 

一些边缘情况很重要：

 - 只包含一个单词的句子应该返回`0`，因为最后一行是空闲的。 
- 长度完全匹配的行`k`贡献零成本。 
- 最后一行绝不能对答案有贡献。 
- 某些单词分组可能会超过`k`，并且必须拒绝这些组合。 
- 由于惩罚是二次的，留下大量未使用的间隙是非常昂贵的，这意味着贪婪的选择并不总是最优的。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试一切可能的方法在单词之间放置换行符。 

假设有`n`字。 在每对相邻的单词之间，我们可以放置换行符，也可以不放置换行符。 这会创建：$2^{n-1}$可能的布局。 

对于每个布局，我们都会：

 1. 构造所有行
 2. 验证每行长度最多为`k`3. 计算总成本
 4. 跟踪最小值

 这种方法是正确的，因为它检查了每个有效的排列，但在计算上是不可行的。 即使是几百个字，布局的数量也会变得巨大。 

### 关键见解

 重要的观察结果是该问题具有最优子结构。 

假设我们决定的话`i`通过`j`形成当前行。 一旦决定确定，剩下的问题就独立了：

 - 我们只需要从 开始的单词的最小成本`j + 1`这自然会导致动态规划。 

我们定义：

 -`dp[i]`= 从索引开始排列单词的最小成本`i`对于每个起始位置`i`，我们尝试将当前行扩展到每个可能的结束位置`j`而行长度保持在`k`。 

如果`j`还不是最后一句话，我们加上行惩罚：$(k-\text{rowLength})^2$如果`j`是最终决定，额外费用是`0`。 

这将指数搜索转换为多项式时间解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 尝试所有可能的换行符配置 |
 | 最优动态规划| O(n²) | O(n) | 计算每个单词后缀的最小成本 |

 ## 算法演练

 1. 将句子分成单独的单词。 

我们首先将句子转换为单词数组，因为决策是在单词边界做出的。 
2. 预先计算字长。 

由于行长度计算频繁发生，存储字长度可以避免重复调用`len()`。 
3. 定义DP状态。 

让`dp[i]`表示从索引开始排列单词所需的最小成本`i`。 

最终的答案将是`dp[0]`。 
4. 初始化DP阵列。 

我们创建一个大小的数组`n + 1`。 

-`dp[n] = 0`- 这表示所有单词放置后的空后缀。 
5. 从右到左处理单词。 

对于每个起始索引`i`，我们尝试每一个可能的结束索引`j`。 
6. 增量构建当前行。 

同时延伸自`i`到`j`，维持：

 - 单词的总字符长度
 - 单词之间的空格数

 行长度变为：$\text{rowLength}=\text{sumOfWordLengths}+(j-i)$因为有`j - i`单词之间的空格。 

1.行数超过时停止`k`。 

如果行长度大于`k`，进一步的扩展只会增加长度，所以我们早点休息。 
2. 计算转换成本。 

如果`j`最后一句话是：

 - 额外费用=`0`否则：$(k-\text{rowLength})^2$1. 更新DP值。 

其递归式为：$dp[i]=\min(dp[i],\text{cost}+dp[j+1])$1. 返回`dp[0]`。 

这表示整个句子的最小总成本。 

### 为什么它有效

 该算法之所以有效，是因为每个有效的排列都以包含单词的第一行开始`i`通过`j`。 一旦选择了该行，剩下的问题就与应用于从以下位置开始的后缀的问题完全相同：`j + 1`。 

动态规划保证了最优性，因为：

 - 考虑每个可能的有效第一行
 - 每个子问题都被最优地解决一次
 - 递归正确地结合了最优子结构

 因此，`dp[0]`是可能的最小总成本。 

## Python 解决方案```python
class Solution:
    def minimumCost(self, sentence: str, k: int) -> int:
        words = sentence.split()
        n = len(words)

        word_lengths = [len(word) for word in words]

        INF = float('inf')
        dp = [INF] * (n + 1)

        dp[n] = 0

        for i in range(n - 1, -1, -1):
            current_length = 0

            for j in range(i, n):
                current_length += word_lengths[j]

                row_length = current_length + (j - i)

                if row_length > k:
                    break

                if j == n - 1:
                    cost = 0
                else:
                    remaining_spaces = k - row_length
                    cost = remaining_spaces * remaining_spaces

                dp[i] = min(dp[i], cost + dp[j + 1])

        return dp[0]
```实现首先将句子分割成单词并存储它们的长度。 此预处理简化了稍后的行长度计算。 

DP 数组存储单词列表中每个后缀的最小成本。`dp[n]`被初始化为`0`因为安排任何文字不需要任何成本。 

外循环向后迭代单词。 对于每个起始索引`i`，内循环尝试所有可能的结束索引`j`。 

随着行的扩展，代码逐渐更新`current_length`。 实际的行长度还包括单词之间的空格，这就是为什么`(j - i)`已添加。 

如果行超过`k`，循环提前终止，因为添加更多单词永远不会减少行长度。 

最后一行贡献零成本，这是通过检查是否`j == n - 1`。 

否则，计算二次罚分并将其与剩余后缀的最优解相结合。 

最后，`dp[0]`包含整个句子的最小总成本。 

## 解决方案```go
package main

import "math"

func minimumCost(sentence string, k int) int {
	words := splitWords(sentence)
	n := len(words)

	wordLengths := make([]int, n)
	for i, word := range words {
		wordLengths[i] = len(word)
	}

	dp := make([]int, n+1)

	for i := 0; i < n; i++ {
		dp[i] = math.MaxInt
	}

	dp[n] = 0

	for i := n - 1; i >= 0; i-- {
		currentLength := 0

		for j := i; j < n; j++ {
			currentLength += wordLengths[j]

			rowLength := currentLength + (j - i)

			if rowLength > k {
				break
			}

			cost := 0

			if j != n-1 {
				remainingSpaces := k - rowLength
				cost = remainingSpaces * remainingSpaces
			}

			if cost+dp[j+1] < dp[i] {
				dp[i] = cost + dp[j+1]
			}
		}
	}

	return dp[0]
}

func splitWords(sentence string) []string {
	words := []string{}
	start := 0

	for i := 0; i <= len(sentence); i++ {
		if i == len(sentence) || sentence[i] == ' ' {
			words = append(words, sentence[start:i])
			start = i + 1
		}
	}

	return words
}
```Go 实现遵循与 Python 版本相同的动态编程策略。 

一个显着的区别是 Go 不提供内置的`split()`方法与 Python 的字符串分割行为相同，无需导入`strings`。 为了保持实现的独立性，一个小的辅助函数手动将句子解析为单词。 

DP阵列使用`math.MaxInt`作为初始大值而不是 Python 的`float('inf')`。 

所有计算都安全地适合 Go 内部`int`类型，因为最大可能成本完全在给定约束的整数限制内。

 ## 边缘情况

 一种重要的边缘情况是句子仅包含一个单词。 由于最后一行不影响成本，因此答案必须始终是`0`无论剩余多少未使用的空间。 粗心的实现可能会错误地将二次罚分应用于唯一的行。 此实现通过在当前行到达最终单词时分配零成本来避免该错误。 

当字长恰好等于`k`。 在这种情况下，该单词完美地填充一行并且贡献零惩罚。 某些实现错误地拒绝长度等于的行`k`通过使用`>=`而不是`>`。 该解决方案正确地允许长度恰好为的行`k`。 

第三个棘手的情况涉及仅在添加空格后才超出限制的单词组合。 例如，两个短单词可能单独适合，但一旦包含强制分隔空格，该行就会变得太长。 该实现正确地将行长度计算为字长加上字之间空格数的总和。 

最后一个微妙的边缘情况是最后一行的处理。 由于最后一行是空闲的，因此最佳布置可能会故意在那里留下额外的未使用空间，以减少早期的惩罚。 总是紧密打包行的贪婪策略可能会失败，因为它们忽略了此属性。 动态编程解决方案正确评估所有有效的行结尾并自然地处理这种权衡。
