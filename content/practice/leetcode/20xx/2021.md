[LeetCode 2021 题](https://leetcode.com/problems/brightest-position-on-street/)

 **难度：** 🟡 中等
 **主题：** 数组、排序、前缀和、有序集

 ## 解决方案

 ## 问题理解

 问题要求我们找到一条笔直的街道上被最多路灯照亮的位置，称为它的**亮度**。 街道被表示为一条数轴，每个路灯都以一对的形式给出`[positioni, rangei]`，它定义了间隔`[positioni - rangei, positioni + rangei]`灯照亮，包括两端。 某个位置的**亮度**只是间隔覆盖该位置的所有灯的数量。 如果多个位置具有相同的最大亮度，则应返回最小的位置。 

输入是一个二维整数数组，最多可达`10^5`灯，位置和范围可以是非常大的整数（最多`10^8`的大小）。 这使得检查数轴上每个整数的简单方法变得不可行。 相反，我们必须依赖一种不会明确迭代每个可能位置的方法。 

要考虑的边缘情况包括零范围灯（仅照亮其确切位置）、重叠范围、负位置以及多个位置共享相同亮度的可能性。 输入保证至少存在一盏灯。 

## 方法

 **暴力方法**会迭代整个数轴，为每个位置计算覆盖它的灯的数量。 这在原则上是正确的，但不可行，因为位置的范围可以是`-10^8`到`10^8`，导致 O(N * max_range) 运行时间，这对于给定的约束来说太慢了。 

**最佳方法**依赖于亮度仅在灯间隔的起点和终点变化的观察。 如果我们将间隔的开始视为 +1 事件，将间隔结束后的位置视为 -1 事件，我们可以对所有这些事件进行排序并模拟亮度的运行总和。 最大运行总计对应于最亮的位置。 这种方法很有效，因为它只考虑亮度变化的位置，而不是数轴上的每个位置。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(N * R) | O(1) | O(1) | 统计所有灯范围内每个位置的亮度； 对于大范围来说太慢。 |
 | 最佳| O(N log N) | O(N log N) | O(N) | 在间隔端点使用扫描线/前缀和事件； 高效且可扩展。 |

 ## 算法演练

 1.初始化一个空列表`events`存储亮度变化。 
2. 对于每盏灯`[pos, rng]`,计算区间`[start, end] = [pos - rng, pos + rng]`。 
3. 对于每个间隔，添加两个事件：`(start, +1)`和`(end + 1, -1)`。 这`+1`标志着照明的开始，并且`-1`标记照明结束后的第一个位置。 
4. 排序`events`按位置列出。 如果多个事件发生在同一位置，顺序并不重要，因为我们将按顺序处理它们。 
5. 初始化`current_brightness = 0`和`max_brightness = 0`。 同时初始化`brightest_position`到一个大的哨兵值。 
6. 迭代每个`(position, delta)`在`events`：

- 更新`current_brightness += delta`。 
- 如果`current_brightness > max_brightness`， 更新`max_brightness = current_brightness`并设置`brightest_position = position`。 
- 如果`current_brightness == max_brightness`, 保持较小的`brightest_position`。 
7. 返回`brightest_position`。 

**为什么有效：** 该算法有效是因为亮度仅在间隔开始点和结束点发生变化。 通过按顺序跟踪这些事件，我们可以准确捕获所有亮度变化，而无需检查每个位置，从而确保正确性和效率。 

## Python 解决方案```python
from typing import List

class Solution:
    def brightestPosition(self, lights: List[List[int]]) -> int:
        events = []
        for pos, rng in lights:
            start, end = pos - rng, pos + rng
            events.append((start, 1))
            events.append((end + 1, -1))
        
        events.sort()
        
        current_brightness = 0
        max_brightness = 0
        brightest_position = float('inf')
        
        for position, delta in events:
            current_brightness += delta
            if current_brightness > max_brightness:
                max_brightness = current_brightness
                brightest_position = position
            elif current_brightness == max_brightness:
                brightest_position = min(brightest_position, position)
        
        return brightest_position
```该实现首先将每个灯的范围转换为开始和结束事件。 对事件进行排序可确保我们按顺序处理位置，并使用运行总计（`current_brightness`）使我们能够有效地跟踪哪个位置具有最大数量的重叠灯。 

## 解决方案```go
import "sort"

func brightestPosition(lights [][]int) int {
    type Event struct {
        pos   int
        delta int
    }
    
    events := make([]Event, 0, 2*len(lights))
    
    for _, lamp := range lights {
        start := lamp[0] - lamp[1]
        end := lamp[0] + lamp[1]
        events = append(events, Event{start, 1})
        events = append(events, Event{end + 1, -1})
    }
    
    sort.Slice(events, func(i, j int) bool {
        return events[i].pos < events[j].pos
    })
    
    currentBrightness := 0
    maxBrightness := 0
    brightestPosition := int(1e18)
    
    for _, e := range events {
        currentBrightness += e.delta
        if currentBrightness > maxBrightness {
            maxBrightness = currentBrightness
            brightestPosition = e.pos
        } else if currentBrightness == maxBrightness {
            if e.pos < brightestPosition {
                brightestPosition = e.pos
            }
        }
    }
    
    return brightestPosition
}
```Go 版本反映了 Python 方法。 Go 需要事件的显式结构类型，并且排序是通过`sort.Slice`。 大哨兵值用于`brightestPosition`以确保比较正确。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(N log N) | O(N log N) | 对 2N 个事件进行排序在运行时占据主导地位，迭代事件的时间复杂度为 O(N)。 |
