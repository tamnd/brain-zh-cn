[LeetCode 问题 2087](https://leetcode.com/problems/minimum-cost-homecoming-of-a-robot-in-a-grid/)

 **难度：** 🟡 中等
 **主题：** 数组，贪婪

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个位于二维网格上的机器人。 机器人开始于`startPos = [startrow, startcol]`并想要达到`homePos = [homerow, homecol]`。 机器人可以一次沿四个方向移动一个单元：上、下、左、右。 

与每次移动具有相同成本的标准最短路径问题不同，这里的成本取决于机器人进入的行或列。 

如果机器人垂直移动（向上或向下），则成本由目标行决定：

 - 进入行`r`成本`rowCosts[r]`如果机器人水平移动（向左或向右），则成本由目标列决定：

 - 进入专栏`c`成本`colCosts[c]`任务是计算机器人从起始位置移动到起始位置所需的最小总成本。 

一个重要的细节是移动成本仅取决于输入的行或列，而不取决于方向本身。 进入行`5`无论机器人来自行还是行，成本都相同`4`或行`6`。 

限制条件很大：

 -`m, n <= 10^5`这立即告诉我们，探索许多路径或在网格上使用全图遍历的算法是不切实际的。 即使显式存储整个网格也可能变得昂贵。 

另一个重要的观察结果是没有阻塞的细胞或障碍物。 机器人始终可以直接朝目的地移动。 由于每次移动都会使行或列恰好改变 1，因此机器人最终必须执行：

 -`abs(homerow - startrow)`垂直移动
 -`abs(homecol - startcol)`水平移动

 这些移动的顺序可能会有所不同，但输入的行和列的集合是固定的。 

一些重要的边缘情况包括：

 - 机器人已经在家里启动了，所以答案应该是`0`- 移动可能仅垂直或仅水平发生
 - 成本可能包含零
 - 机器人可能需要向上或向左移动，而不仅仅是向下或向右移动
 - 非常大的网格需要高效的线性解决方案

 ## 方法

 ### 蛮力方法

 强力解决方案会将网格视为加权图。 每个单元成为一个节点，移动到相邻单元会创建边，其成本由目标行或列决定。 

然后我们可以应用最短路径算法，例如 Dijkstra 算法。 

这种方法是正确的，因为 Dijkstra 保证了具有非负边权重的图中的最小路径成本。 

然而，对于问题限制而言，该解决方案过于昂贵。 网格最多可以包含：$$10^5 \times 10^5 = 10^{10}$$理论上来说，细胞是完全不可能表示或遍历的。 

尽管实际测试用例在实践中较小，但约束清楚地表明基于图的最短路径方法不是有意的。 

### 关键见解

 关键的观察结果是，不存在任何障碍，也没有可以降低成本的替代加权路线。 

从行移动`startrow`到`homerow`，机器人必须恰好进入每个中间行一次。 没有办法避免支付这些行成本。 

同样，从列移动`startcol`到`homecol`，机器人必须恰好进入每个中间列一次。 

由于垂直和水平移动成本是独立的，因此总的最小成本很简单：

 - 所有所需行输入成本的总和
 - 加上所有必需的列输入成本的总和

 运动顺序并不重要。 

这将问题从图最短路径问题转变为简单的范围求和问题。

 ## 算法演练

 1. 提取起始行和列`startPos`，以及目标行和列`homePos`。 
2. 初始化变量`total_cost`到`0`。 这将累积最低的旅行费用。 
3. 首先处理垂直运动。 

如果机器人需要向下移动，则迭代`startrow + 1`通过`homerow`，将每个对应的`rowCosts[r]`。 

如果机器人需要向上移动，则迭代`startrow - 1`向下穿过`homerow`，再次添加每个`rowCosts[r]`。 

我们不包括起始行，因为仅在输入行时才支付费用。 
4. 类似地处理水平移动。 

如果向右移动，则从`startcol + 1`通过`homecol`，添加`colCosts[c]`。 

如果向左移动，则从`startcol - 1`向下穿过`homecol`，添加`colCosts[c]`。 
5.返回累计值`total_cost`。 

### 为什么它有效

 机器人无法传送或跳过行和列。 从起始位置到起始位置的每条路径都必须输入完全相同的一组所需行和列。 

由于每个所需的行和列都会产生固定的不可避免的成本，因此每个有效路径都具有相同的总成本。 因此，简单地将这些强制性成本相加就可以得到最小的可能答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def minCost(
        self,
        startPos: List[int],
        homePos: List[int],
        rowCosts: List[int],
        colCosts: List[int]
    ) -> int:
        start_row, start_col = startPos
        home_row, home_col = homePos

        total_cost = 0

        # Move vertically
        if start_row < home_row:
            for row in range(start_row + 1, home_row + 1):
                total_cost += rowCosts[row]
        else:
            for row in range(start_row - 1, home_row - 1, -1):
                total_cost += rowCosts[row]

        # Move horizontally
        if start_col < home_col:
            for col in range(start_col + 1, home_col + 1):
                total_cost += colCosts[col]
        else:
            for col in range(start_col - 1, home_col - 1, -1):
                total_cost += colCosts[col]

        return total_cost
```实现直接遵循算法。 

首先，代码从输入数组中提取行和列坐标。 这提高了可读性并避免了以后重复的索引操作。 

变量`total_cost`存储所有所需移动成本的运行总和。 

垂直运动部分决定机器人是向上还是向下运动。 根据方向，代码会迭代机器人输入的所有行并添加其相关成本。 

水平移动部分的工作方式与柱相同。 

请注意，循环总是从距离当前位置一步开始，因为机器人不会为其已经占用的行或列付费。 仅当输入新行或新列时才需要支付费用。 

最后返回累计总数。 

## 解决方案```go
func minCost(startPos []int, homePos []int, rowCosts []int, colCosts []int) int {
    startRow, startCol := startPos[0], startPos[1]
    homeRow, homeCol := homePos[0], homePos[1]

    totalCost := 0

    // Move vertically
    if startRow < homeRow {
        for row := startRow + 1; row <= homeRow; row++ {
            totalCost += rowCosts[row]
        }
    } else {
        for row := startRow - 1; row >= homeRow; row-- {
            totalCost += rowCosts[row]
        }
    }

    // Move horizontally
    if startCol < homeCol {
        for col := startCol + 1; col <= homeCol; col++ {
            totalCost += colCosts[col]
        }
    } else {
        for col := startCol - 1; col >= homeCol; col-- {
            totalCost += colCosts[col]
        }
    }

    return totalCost
}
```Go 实现密切反映了 Python 逻辑。 

Go切片直接用于`startPos`,`homePos`,`rowCosts`， 和`colCosts`。 由于 Go 整数足以满足问题约束，因此不需要特殊的溢出处理。 

循环根据方向明确以递增或递减顺序移动。 这使实现变得简单并避免需要辅助函数。 

与 Python 不同，Go 不直接支持反向范围，因此递减循环是手动编写的`row--`和`col--`。

 ## 边缘情况

 当机器人已经从其起始位置启动时，就会出现一种重要的边缘情况。 在这种情况下，不会发生任何移动，因此不应增加成本。 有缺陷的实现可能会意外地包含起始行或列的成本。 此实现通过始终从当前位置开始迭代来避免这种情况。 

另一个重要的情况是向上或向左移动。 许多实现仅正确处理递增索引。 反向遍历需要仔细的循环边界，特别是在像 Go 这样的语言中，反向范围是手动的。 该实现显式地分别处理两个移动方向，确保正确性。 

第三种边缘情况涉及零成本。 某些行或列可能有成本`0`，这意味着进入它们是免费的。 该算法通常只是将这些值相加，因此零成本移动自然可以进行，无需任何特殊处理。 

最后一种微妙的边缘情况是仅在一维发生运动时。 例如，机器人可能只需要在同一列中垂直移动。 该实现可以正确处理此问题，因为当起始列和目标列相等时，水平循环将变为空。
