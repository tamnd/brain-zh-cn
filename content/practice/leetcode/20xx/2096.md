[LeetCode 问题 2096](https://leetcode.com/problems/step-by-step-directions-from-a-binary-tree-node-to-another/)

 **难度：** 🟡 中等
 **主题：** 字符串、树、深度优先搜索、二叉树

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个二叉树，其中每个节点都包含一个唯一的值`1`到`n`。 我们还给出了两个节点值：

 -`startValue`，路径开始的节点
 -`destValue`，路径必须结束的节点

 我们必须返回从起始节点移动到目标节点所需的最短方向序列。 

输出字符串可能只包含三个字符：

 -`'L'`表示从一个节点移动到其左子节点
 -`'R'`表示从一个节点移动到其右子节点
 -`'U'`表示从节点移动到其父节点

 因为该结构是一棵树，所以任何两个节点之间都只有一条唯一的路径。 这意味着最短路径也是唯一确定的。 

主要挑战是将两个节点之间的关系转换为方向字符串。 从一个节点直接遍历到另一个节点是很困难的，因为树节点不包含父指针。 然而，二叉树自然支持根到节点的遍历，并且该观察会得出最优解决方案。 

约束条件很重要：

 - 树最多可以包含`10^5`节点
 - 节点值是唯一的
 - 保证两个目标节点都存在
 -`startValue != destValue`由于树可能非常大，任何比线性时间更差的算法都有超时的风险。 多次重复遍历或重建路径效率很低。 我们需要一种能够在一次传递或少量恒定次数的传递中有效处理树的方法。 

一些边缘情况很重要：

 - 一个节点可能是另一个节点的祖先
 - 根可以是起点或目的地
 - 该路径可能只需要向上移动
 - 该路径可能只需要向下移动
 - 最低的共同祖先可能在树的深处

 正确的实现必须一致地处理所有这些情况。 

## 方法

 ### 蛮力方法

 强力解决方案首先将树转换为无向图。 每个节点都会连接到：

 - 它的左孩子
 - 它的右孩子
 - 它的父级

 构建此图后，我们可以运行广度优先搜索`startValue`直到我们到达`destValue`。 

在探索邻居时，我们将存储两者：

 - 前一个节点
 - 用于到达下一个节点的方向

 一旦找到目的地，我们就可以通过 BFS 父地图回溯来重建最短路径。 

这是可行的，因为 BFS 保证了未加权图中的最短路径。 

然而，这种方法有缺点：

 - 我们必须首先遍历整棵树来建立父关系
 - 我们需要额外的图形结构
 - BFS 为每个节点存储额外的状态
 - 实施比必要的更复杂

 尽管渐近复杂度仍然是线性的，但额外的内存开销和图转换是不必要的，因为树已经具有我们可以直接利用的强大的层次结构。 

### 最佳方法

 关键的观察结果是，两个树节点之间的最短路径总是经过它们的最低公共祖先，通常缩写为 LCA。 

我们可以：

 1.找到从root到的路径`startValue`2.找到从root到的路径`destValue`3. 删除两个路径中的公共前缀

 共享前缀表示从根到LCA的路径。 

删除公共前缀后：

 - 起始路径中的每个剩余步骤必须成为`'U'`- 剩余的目标路径已包含正确的`'L'`和`'R'`方向

 这将问题转化为干净路径比较问题。 

例如：

 - 根启动：`"LLR"`- 根到目的地：`"LRR"`常用前缀：`"L"`剩余：

 - 开始后缀：`"LR"`- 目的地后缀：`"RR"`从起点移动到目的地：

 - 上升两次：`"UU"`- 然后遵循目的地后缀：`"RR"`结果：`"UURR"`这种方法很优雅，因为树路径自然地编码祖先关系。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(n) | 构建图并在节点之间运行 BFS |
 | 最佳| O(n) | O(n) | 查找根到节点的路径并删除公共前缀 |

 ## 算法演练

 1. 从根开始执行深度优先搜索以查找路径`startValue`。 

穿越时：

 - 追加`'L'`当向左移动时
 - 追加`'R'`向右移动时

 如果找到目标，则停止递归并保留构造的路径。 
2. 执行另一次深度优先搜索以查找从根到`destValue`。 

这会产生另一个序列`'L'`和`'R'`方向。 
3. 从头开始​​逐个字符比较两条路径。 

匹配前缀对应于从根向下到最低公共祖先的共享路由。 
4. 当路径分岔时停止。 

那时：

 - 起始路径的剩余部分表示起始节点低于 LCA 多远
 - 目的地路径的剩余部分表示如何从LCA到达目的地
 5. 将起始路径中剩余的每个方向替换为`'U'`。 

每剩下一步都意味着我们必须向上迈向 LCA。 
6. 附加剩余的目标后缀。 

这些方向已经描述了从 LCA 到目的地的正确向下遍历。 
7. 返回最终的组合字符串。 

### 为什么它有效

 树中的每条路径都是独一无二的。 根到起始路径和根到目标路径共享相同的前缀，直到最低公共祖先。 一旦路径分岔，从起始节点移动到目的地的唯一方法是：

 - 从起始节点向上移动到LCA
 - 然后从LCA向下移动到目的地

 将剩余的开始后缀替换为`'U'`操作并附加剩余的目的地后缀精确地重建了这条唯一的最短路径。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional

class Solution:
    def getDirections(
        self,
        root: Optional[TreeNode],
        startValue: int,
        destValue: int
    ) -> str:

        def find_path(node: Optional[TreeNode], target: int, path: list[str]) -> bool:
            if not node:
                return False

            if node.val == target:
                return True

            path.append("L")
            if find_path(node.left, target, path):
                return True
            path.pop()

            path.append("R")
            if find_path(node.right, target, path):
                return True
            path.pop()

            return False

        start_path = []
        dest_path = []

        find_path(root, startValue, start_path)
        find_path(root, destValue, dest_path)

        common_length = 0

        while (
            common_length < len(start_path)
            and common_length < len(dest_path)
            and start_path[common_length] == dest_path[common_length]
        ):
            common_length += 1

        up_moves = "U" * (len(start_path) - common_length)
        down_moves = "".join(dest_path[common_length:])

        return up_moves + down_moves
```实现从一个名为的辅助 DFS 函数开始`find_path`。 该函数搜索目标节点，同时从根开始构建路径。 

这`path`列表的作用类似于递归堆栈。 在向左移动之前，算法附加`'L'`。 在向右移动之前，它会附加`'R'`。 如果分支不包含目标，则使用以下命令删除最后一个方向`pop()`。 这是经典的回溯。 

一旦找到目标节点，函数立即返回`True`，保留成功的路径。 

收集根到节点的路径后，算法计算它们的公共前缀的长度。 这隐含地标识了最低共同祖先。 

其余方向在`start_path`变为向上运动，表示为`'U'`。 

剩下的后缀为`dest_path`已经是从 LCA 到目的地的正确下行路线。 

最后，将两个部分连接起来并返回。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func getDirections(root *TreeNode, startValue int, destValue int) string {

	var findPath func(node *TreeNode, target int, path *[]byte) bool

	findPath = func(node *TreeNode, target int, path *[]byte) bool {
		if node == nil {
			return false
		}

		if node.Val == target {
			return true
		}

		*path = append(*path, 'L')
		if findPath(node.Left, target, path) {
			return true
		}
		*path = (*path)[:len(*path)-1]

		*path = append(*path, 'R')
		if findPath(node.Right, target, path) {
			return true
		}
		*path = (*path)[:len(*path)-1]

		return false
	}

	startPath := []byte{}
	destPath := []byte{}

	findPath(root, startValue, &startPath)
	findPath(root, destValue, &destPath)

	commonLength := 0

	for commonLength < len(startPath) &&
		commonLength < len(destPath) &&
		startPath[commonLength] == destPath[commonLength] {

		commonLength++
	}

	result := make([]byte, 0)

	for i := commonLength; i < len(startPath); i++ {
		result = append(result, 'U')
	}

	result = append(result, destPath[commonLength:]...)

	return string(result)
}
```Go 实现遵循与 Python 版本相同的算法结构，但有一些特定于语言的细节。 

Go 没有可变字符串，因此路径存储为`[]byte`切片。 这允许高效的追加和回溯操作。 

辅助 DFS 接收指向切片的指针，因此递归调用可以直接修改共享路径。 

回溯是通过使用以下方法缩小切片来实现的：```go
*path = (*path)[:len(*path)-1]
```最终结果是使用另一个字节切片增量构建的，并在最后转换为字符串。 

因为最大路径长度最多为`n`，这个问题不存在整数溢出问题。

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 每次DFS遍历可能访问每个节点一次|
 | 空间| O(n) | 递归调用堆栈和存储路径可能会增长到树高 |

 该算法执行两次 DFS 遍历，每个目标节点一次。 在最坏的情况下，每次遍历只访问每个节点一次，从而导致线性时间复杂度。 

空间复杂度来自递归深度和存储的路径数组。 在高度不平衡的树中，递归堆栈可能达到`O(n)`深度。 存储的路径最多还可以包含`O(n)`方向。

 ## 边缘情况

 当目标节点是起始节点的祖先时，会出现一种重要的边缘情况。 在这种情况下，正确答案仅包含`'U'`人物。 有缺陷的实现可能会在到达祖先后错误地尝试额外的向下移动。 该解决方案可以自然地处理这种情况，因为在删除公共前缀后目标后缀变为空。 

当起始节点是目标节点的祖先时，会发生另一种关键情况。 这里，不需要向上移动。 该算法仅正确生成剩余的目标后缀，因为公共前缀之后的起始后缀的长度为零。 

高度不平衡的树也很重要。 如果树类似于链表，则递归 DFS 深度可以变为`O(n)`。 尽管递归深度变大，但该算法仍然保持正确，因为每个节点每次遍历仅访问一次。 这符合理论上最坏情况的空间复杂度。 

当最低共同祖先是根本身时，就会出现最后一个微妙的情况。 在这种情况下，根到节点的路径立即分叉，因此公共前缀长度为零。 该算法正确地将整个起始路径转换为向上移动，然后附加整个目标路径。
