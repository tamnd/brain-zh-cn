 **难度：** 🟡 中等

 ## 解决方案

 ## 问题理解

 这个问题要求我们设计一个非常简单的银行系统，支持三种操作：

 1. 两个账户之间转账
 2. 将钱存入账户
 3. 从账户提款

 银行包含`n`帐户编号自`1`到`n`。 每个帐户的初始余额在名为 0 索引的数组中给出`balance`， 在哪里：

-`balance[0]`对应账户`1`-`balance[1]`对应账户`2`- 等等

 重要的细节是帐号编号是从 1 开始的，而存储余额的数组是从 0 开始的。 这种不匹配是实现错误的一个非常常见的来源。 

每个操作在修改余额之前都必须验证交易。 

如果满足以下条件，则交易被视为有效：

 - 每个引用的帐号都存在，这意味着它介于`1`和`n`- 任何提现或转账金额均不超过源账户当前余额

 如果交易有效，则更新余额并且该方法返回`true`。 否则，不会发生任何变化并且该方法返回`false`。 

这些约束告诉我们一些重要的事情：

 - 最多可以有`10^5`账户
 - 每笔余额和交易金额可大至`10^12`- 最多`10^4`可以执行操作

 非常大的资金限制意味着我们必须使用 64 位整数类型：

 - Python 整数自动支持大值
 - Go必须使用`int64`操作数量相对较少，但理想情况下每个操作仍应在恒定时间内运行。 

一些边缘情况很重要：

 - 尝试访问外部帐号`[1, n]`- 提取的金额超过可用金额
 - 从无效帐户转入或转入无效帐户
 - 准确转移当前余额
 - 存款或取款`0`- 安全处理巨额余额

 该问题保证输入本身遵循类型约束，因此我们无需担心格式错误的输入格式。 

## 方法

 ### 蛮力方法

 简单的实现可能会将帐户存储在帐户对象列表中，并在每次操作发生时线性搜索帐户。 

例如：

 - 要转账，请扫描整个结构以找到 account1
 - 再次扫描找到account2
 - 然后执行验证和更新

 这种方法是正确的，因为每个操作最终都会找到所需的帐户并相应地更新余额。 

然而，线性搜索是不必要的，因为帐号已经是连续的并且直接映射到数组索引。 

如果每个操作需要扫描最多`n`帐户，时间复杂度变为`O(n)`每次操作。 高达`10^4`运营和`10^5`帐户，这变得低效。 

### 最佳方法

 关键的观察结果是帐号直接映射到余额数组中的位置。 

自：

 - 账户`1`映射到索引`0`- 帐户`2`映射到索引`1`- 帐户`k`映射到索引`k - 1`我们可以使用数组索引立即访问任何帐户余额。 

这允许所有操作在恒定时间内运行：

 - 验证索引
 - 如有必要，请检查是否有足够的资金
 - 直接更新余额

 除了余额数组本身之外，不需要额外的数据结构。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 每次操作 O(n) | O(n) | 线性搜索账户|
 | 最佳| 每次操作 O(1) | O(n) | 直接数组索引 |

 ## 算法演练

 ### 最优算法

 1. 将余额数组存储在`Bank`目的。 

该数组代表所有帐户的当前状态。 由于帐号是连续的，我们可以使用以下命令直接将帐号映射到数组索引`account - 1`。 
2. 为帐号创建辅助验证检查。 

在执行任何操作之前，请验证帐号是否介于`1`和`n`。 无效的帐户访问应立即返回`false`。 
3. 对于存款：

 - 验证帐户
 - 将钱直接添加到余额中
 - 返回`true`存款永远不会因为资金不足而失败，因为资金只是被添加。 
4. 提款：

 - 验证帐户
 - 检查余额是否至少为请求的金额
 - 如果没有，请返回`false`- 否则减去金额并返回`true`5. 转账：

 - 验证两个帐户
 - 检查源账户是否有足够的资金
 - 如果没有，请返回`false`- 否则从发送者中减去并添加到接收者中
 6. 始终仅在验证成功后修改余额。 

这确保失败的交易不会部分更新银行状态。 

### 为什么它有效

 该算法之所以有效，是因为余额数组始终存储每个帐户的当前正确余额。 每个操作在进行任何修改之前都会首先验证其先决条件。 

在整个执行过程中保持的不变量是：

 > 每次成功交易后，余额数组始终反映所有帐户的正确状态。 

由于所有更新都是在验证后自动完成的，因此无效交易永远不会破坏银行状态。 

## Python 解决方案```python
from typing import List

class Bank:

    def __init__(self, balance: List[int]):
        self.balance = balance
        self.n = len(balance)

    def is_valid_account(self, account: int) -> bool:
        return 1 <= account <= self.n

    def transfer(self, account1: int, account2: int, money: int) -> bool:
        if not self.is_valid_account(account1):
            return False

        if not self.is_valid_account(account2):
            return False

        sender_index = account1 - 1
        receiver_index = account2 - 1

        if self.balance[sender_index] < money:
            return False

        self.balance[sender_index] -= money
        self.balance[receiver_index] += money

        return True

    def deposit(self, account: int, money: int) -> bool:
        if not self.is_valid_account(account):
            return False

        index = account - 1
        self.balance[index] += money

        return True

    def withdraw(self, account: int, money: int) -> bool:
        if not self.is_valid_account(account):
            return False

        index = account - 1

        if self.balance[index] < money:
            return False

        self.balance[index] -= money

        return True

# Your Bank object will be instantiated and called as such:
# obj = Bank(balance)
# param_1 = obj.transfer(account1, account2, money)
# param_2 = obj.deposit(account, money)
# param_3 = obj.withdraw(account, money)
```该实现将余额直接存储在类中，并将帐户总数保存在`self.n`。 

辅助方法`is_valid_account`集中帐户验证逻辑。 这可以避免在整个代码中重复相同的范围检查，并使实现更加清晰。 

这`transfer`方法首先验证两个帐户。 然后，它将从 1 开始的帐号转换为从 0 开始的数组索引。 只有在确认足够的资金后才会修改余额。 

这`deposit`方法是最简单的操作，因为它只需要验证帐户即可添加资金。 

这`withdraw`方法验证帐户并在减去金额之前检查是否存在足够的余额。 

所有操作都在恒定时间内运行，因为数组访问是`O(1)`。 

## 解决方案```go
type Bank struct {
	balance []int64
	n       int
}

func Constructor(balance []int64) Bank {
	return Bank{
		balance: balance,
		n:       len(balance),
	}
}

func (this *Bank) isValidAccount(account int) bool {
	return account >= 1 && account <= this.n
}

func (this *Bank) Transfer(account1 int, account2 int, money int64) bool {
	if !this.isValidAccount(account1) {
		return false
	}

	if !this.isValidAccount(account2) {
		return false
	}

	senderIndex := account1 - 1
	receiverIndex := account2 - 1

	if this.balance[senderIndex] < money {
		return false
	}

	this.balance[senderIndex] -= money
	this.balance[receiverIndex] += money

	return true
}

func (this *Bank) Deposit(account int, money int64) bool {
	if !this.isValidAccount(account) {
		return false
	}

	index := account - 1
	this.balance[index] += money

	return true
}

func (this *Bank) Withdraw(account int, money int64) bool {
	if !this.isValidAccount(account) {
		return false
	}

	index := account - 1

	if this.balance[index] < money {
		return false
	}

	this.balance[index] -= money

	return true
}

 * Your Bank object will be instantiated and called as such:
 * obj := Constructor(balance);
 * param_1 := obj.Transfer(account1, account2, money);
 * param_2 := obj.Deposit(account, money);
 * param_3 := obj.Withdraw(account, money);
 */
```Go 实现与 Python 版本非常相似，但有几个特定于语言的细节值得注意。 

平衡片使用`int64`因为交易金额可以大到`10^12`，这可能超出正常 32 位整数的范围。 

Go 不隐式支持类型之外的方法，因此验证助手被实现为名为的接收器方法`isValidAccount`。 

Go 中的切片已经提供了高效的动态数组行为，因此不需要额外的结构。

 ## 边缘情况

 ### 无效帐号

 最容易犯的错误之一就是忘记账户的编号是从`1`到`n`，而数组使用的索引来自`0`到`n - 1`。 

例如，帐户`0`和帐户`n + 1`即使它们可能意外映射到有缺陷的实现中的数组位置，也是无效的。 

该解决方案通过在执行任何操作之前验证每个帐户来避免此问题。 

### 资金不足

 如果账户余额小于请求的金额，转账或提现就会失败。 

这尤其重要，因为部分更新会破坏银行状态。 例如，在验证之前减去资金可能会产生负余额。 

该实现首先检查余额充足性，仅在验证成功后更新余额。 

### 巨大的货币价值

 余额和交易金额可以大到`10^12`。 

在许多语言中使用 32 位整数类型会发生溢出。 Go 实现明确使用`int64`，而 Python 自动支持任意大小的整数。 

即使对于最大的有效输入，这也保证了正确性。
