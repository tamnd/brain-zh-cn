 **难度：** 🟡 中等
 **主题：** 数组、哈希表、二分查找、设计、线段树

 ## 解决方案

 ## 问题理解

 该问题要求我们设计一种能够有效回答子数组频率查询的数据结构。 

我们得到一个整数数组`arr`，并且我们需要支持以下形式的重复查询：

 - 给定`left`,`right`， 和`value`- 返回多少次`value`出现在子数组中`arr[left...right]`重要的细节是数据结构被构建一次，但被查询多次。 约束允许最多`10^5`数组中的元素最多`10^5`查询，它立即告诉我们，天真的每个查询扫描太慢了。 

例如，假设：```
arr = [12, 33, 4, 56, 22, 2, 34, 33, 22, 12, 34, 56]
```如果我们查询：```
query(1, 2, 4)
```我们检查子数组：```
[33, 4]
```价值`4`出现一次，所以答案是`1`。 

这些约束揭示了几个重要的属性：

 - 数组是静态的，这意味着它在构造后永远不会改变。 
- 我们只需要回答只读频率查询。 
- 查询性能比更新性能更重要，因为没有更新。 
- 值的范围是`10^4`，但指数上升至`10^5`。 

这些观察结果强烈建议对数组进行预处理，以便查询变得更快。 

一些边缘情况很重要：

 - 查询的值可能不存在于数组中的任何位置。 
- 查询的范围可能只包含一个元素。 
- 所有元素可以是相同的。 
- 查询的值可能多次出现在查询范围之外，但不会出现在查询范围之内。 
- 查询范围可能跨越整个数组。 

正确的解决方案必须有效地处理所有这些问题。 

## 方法

 ### 蛮力方法

 最直接的解决方案是扫描每个查询的子数组。 

对于每个查询：

 1. 从索引迭代`left`索引`right`2. 计算有多少个元素相等`value`3.返回计数

 这种方法是正确的，因为它通过检查每个相关元素来直接计算频率。 

然而，对于给定的限制来说，它太慢了。 

如果数组长度是`10^5`我们还有`10^5`查询，那么在最坏的情况下，每个查询几乎扫描整个数组。 

这导致：```
O(n * q) = O(10^10)
```操作，这是不可行的。 

### 最佳方法

 关键的观察是我们不需要重复扫描数组。 

相反，我们可以预处理数组并为每个不同的值存储该值出现的索引的排序列表。 

例如：```
arr = [12, 33, 4, 56, 22, 2, 34, 33]
```我们可以建立：```
12 -> [0]
33 -> [1, 7]
4  -> [2]
56 -> [3]
22 -> [4]
2  -> [5]
34 -> [6]
```现在考虑查询：```
query(1, 7, 33)
```我们已经知道了所有的位置`33`：```
[1, 7]
```我们只需要计算有多少个指数属于`[1, 7]`。 

因为索引列表是排序的，所以我们可以使用二分搜索：

 - 找到第一个索引>=`left`- 找到第一个索引>`right`- 他们的差异给出了计数

 这将每个查询从线性时间转换为对数时间。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 每个查询 O(n) | O(1) | O(1) | 每次扫描整个查询范围 |
 | 最佳 | 每个查询 O(log k) | O(n) | 存储排序索引列表并使用二分搜索 |

 这里，`k`是查询值出现的次数。 

## 算法演练

 ### 第 1 步：构建从值到索引的映射

 在初始化期间，迭代数组。 

对于每个元素：

 - 使用值作为哈希映射中的键
 - 将当前索引附加到该值的列表中

 例如：```
arr = [1, 3, 1, 2, 1]
```生产：```
1 -> [0, 2, 4]
3 -> [1]
2 -> [3]
```列表会自动排序，因为我们从左到右处理数组。 

### 第 2 步：处理查询

 假设我们收到：```
query(left, right, value)
```首先检查是否`value`存在于地图中。 

如果不存在则返回`0`。 

否则，检索该值的排序索引列表。 

例子：```
value = 1
indices = [0, 2, 4]
```### 步骤 3：找到左边界

 使用二分查找来定位第一个位置`indices`其中索引大于或等于`left`。 

这给出了有效范围的开始。 

### 步骤 4：找到正确的边界

 使用另一个二分查找来定位第一个位置`indices`其中索引大于`right`。 

这给出了紧邻有效范围之后的位置。 

### 步骤 5：计算频率

 有效出现的次数为：```
right_position - left_position
```因为这两个位置之间的所有索引都位于查询范围内。 

### 为什么它有效

 对于每个值，我们按排序顺序存储所有出现索引。 

二分查找正确识别：

 - 查询范围内的第一次出现
 - 查询范围后的第一次出现

 这两个边界之间的每个索引都必须属于该区间`[left, right]`，并且每个有效的出现都只包含一次。 

因此，两个二分搜索位置之间的差异等于确切的频率。 

## Python 解决方案```python
from collections import defaultdict
from bisect import bisect_left, bisect_right
from typing import List

class RangeFreqQuery:

    def __init__(self, arr: List[int]):
        self.positions = defaultdict(list)

        for index, value in enumerate(arr):
            self.positions[value].append(index)

    def query(self, left: int, right: int, value: int) -> int:
        if value not in self.positions:
            return 0

        indices = self.positions[value]

        left_pos = bisect_left(indices, left)
        right_pos = bisect_right(indices, right)

        return right_pos - left_pos

# Your RangeFreqQuery object will be instantiated and called as such:
# obj = RangeFreqQuery(arr)
# param_1 = obj.query(left,right,value)
```实现首先构建一个名为`positions`。 

每个键都是数组中的一个值，其对应的值是该数字出现的所有索引的列表。 

因为我们以递增的索引顺序迭代数组，所以每个列表都会自动排序。 

在查询过程中，我们首先检查请求的值是否存在于映射中。 如果没有，频率立即`0`。 

否则，我们检索排序后的索引列表并使用：

 -`bisect_left`找到第一个大于或等于的索引`left`-`bisect_right`找到第一个大于的索引`right`这些位置之间的差异给出了区间内出现的次数。 

这是有效的，因为二分搜索可以有效地计算有多少排序索引落在一个范围内。 

## 解决方案```go
package main

import "sort"

type RangeFreqQuery struct {
	positions map[int][]int
}

func Constructor(arr []int) RangeFreqQuery {
	rfq := RangeFreqQuery{
		positions: make(map[int][]int),
	}

	for index, value := range arr {
		rfq.positions[value] = append(rfq.positions[value], index)
	}

	return rfq
}

func (this *RangeFreqQuery) Query(left int, right int, value int) int {
	indices, exists := this.positions[value]

	if !exists {
		return 0
	}

	leftPos := sort.SearchInts(indices, left)
	rightPos := sort.Search(len(indices), func(i int) bool {
		return indices[i] > right
	})

	return rightPos - leftPos
}

/**
 * Your RangeFreqQuery object will be instantiated and called as such:
 * obj := Constructor(arr);
 * param_1 := obj.Query(left,right,value);
 */
```Go 解决方案遵循与 Python 版本相同的算法结构。 

而不是Python的`bisect`模块，Go 使用：

 -`sort.SearchInts`对于下界
 -`sort.Search`具有上限的自定义条件

 Go 映射自然支持切片作为值，从而可以轻松存储出现索引。 

由于数组索引是按顺序附加的，因此切片会自动保持排序，从而允许二分搜索正常工作。

from collections import defaultdict
from bisect import bisect_left, bisect_right

class RangeFreqQuery:

    def __init__(self, arr):
        self.positions = defaultdict(list)

        for index, value in enumerate(arr):
            self.positions[value].append(index)

    def query(self, left, right, value):
        if value not in self.positions:
            return 0

        indices = self.positions[value]

        return (
            bisect_right(indices, right)
            - bisect_left(indices, left)
        )

 ## 边缘情况

 ### 查询不存在的值

 错误的常见来源是尝试对索引列表进行二分搜索以查找从未出现在数组中的值。 

例如：```
arr = [1, 2, 3]
query(0, 2, 10)
```如果实现盲目地访问映射，可能会导致错误或不正确的行为。 

该解决方案通过检查来安全地处理这个问题：```
if value not in self.positions:
    return 0
```这保证了缺失值的正确性。 

### 单元素范围

 范围在哪里`left == right`可以暴露相差一的错误。 

例子：```
arr = [5]
query(0, 0, 5)
```正确答案是`1`。 

使用`bisect_left`和`bisect_right`仔细保留包含边界，确保正确计算单个有效索引。 

### 值出现在范围之外但不在范围之内

 当值存在于数组中但不在请求的间隔内时，会发生另一种微妙的情况。 

例子：```
arr = [1, 2, 3, 1]
query(1, 2, 1)
```价值`1`存在于全球但不存在于内部`[1, 2]`。 

二分搜索正确地仅隔离请求范围内的索引，产生`0`而不是统计全球范围内发生的所有事件。
