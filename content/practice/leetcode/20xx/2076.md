[LeetCode 问题 2076](https://leetcode.com/problems/process-restricted-friend-requests/)

 **难度：** 🔴难
 **主题：** 并查集、图论

 ## 解决方案

 ## 问题理解

 该问题模拟了具有好友限制的社交网络。 我们被给予`n`被标记为来自`0`到`n - 1`。 最初，没有人与其他人有联系。 随着时间的推移，好友请求一一到达，每个请求都必须立即处理。 

重要的细节是友谊是可传递的。 如果人`A`是朋友`B`， 和`B`是朋友`C`， 然后`A`和`C`被视为间接关联。 因此，每个接受的友谊请求都会将两个社交群体合并在一起。 

这`restrictions`数组定义了永远不允许进入同一个连接的友谊组的人。 甚至间接连接也是被禁止的。 例如，如果`[0, 1]`是一个限制，那么任何接受的友谊序列都会使`0`和`1`在同一连通分量中必须被拒绝。 

这`requests`数组包含按顺序处理的友谊请求。 对于每个请求`[u, v]`，我们必须确定接受友谊是否会违反任何限制。 如果没有，我们接受请求并永久合并他们的组。 否则，我们将拒绝它。 

输出是一个布尔数组，其中：

 -`true`表示请求被接受
 -`false`表示请求被拒绝

 限制相对较小：

 -`n <= 1000`-`restrictions.length <= 1000`-`requests.length <= 1000`这些界限足够小，以至于`O(R * Q)`样式解决方案是可以接受的，其中：

 -`R`是限制的数量
 -`Q`是请求数

 然而，为每个请求从头开始重新计算连接仍然会产生不必要的昂贵费用。 

一些边缘情况很重要：

 - 两个人可能已经属于同一个友谊团体。 在这种情况下，请求自动有效，因为它不会改变任何内容。 
- 限制可能会通过多次合并而间接违反，而不仅仅是通过直接友谊。 
- 多个限制可能涉及相同的人或团体。 
- 拒绝一项请求不得影响以后的请求。 
- 限制是对称的。 如果`[a, b]`存在，那么`a`无法连接到`b`， 和`b`无法连接到`a`。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是显式维护友谊图并为每个请求运行图遍历。 

对于每个请求`[u, v]`：

 1.暂时添加友情缘。 
2. 对于每一个限制`[x, y]`，检查是否`x`和`y`使用 DFS 或 BFS 建立连接。 
3. 如果违反任何限制，则删除临时边缘并拒绝请求。 
4. 否则，保持优势并接受请求。 

这是有效的，因为它在每次请求后直接验证结果图是否满足所有约束。 

然而，这种方法效率低下。 每个请求可能需要多次图遍历，并且每次遍历都可以访问整个图。 高达`1000`请求和`1000`限制，重复的连接搜索变得昂贵。 

### 最佳方法

 关键的观察是我们只关心连接的组件，而不关心它们内部的确切图形结构。 

这自然建议使用并查数据结构，也称为不相交集并集 (DSU)。 

Union-Find 有效地维护相互联系的人群。 它支持：

 - 查找一个人属于哪个群体
 - 将两个组合并在一起

 对于每个友谊请求`[u, v]`：

 1. 寻找根源`u`和`v`。 
2. 检查每项限制`[x, y]`。 
3. 如果合并这两个组会放置`x`和`y`进入同一组件，拒绝请求。 
4. 否则，合并两个组。 

关键的见解是限制仅在组件级别重要。 我们不需要追踪个人的友谊路径。 

因为约束很小，所以扫描每个请求的所有限制是完全可行的。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(Q × R × (N + E)) | O(Q × R × (N + E)) | O(N + E) | 每次请求后重复图遍历 |
 | 最佳 | O(Q × R × α(N)) | O(Q × R × α(N)) | O(N) | 使用 Union-Find 高效跟踪连接的组件 |

 这里：

-`Q`= 请求数
 -`R`= 限制数量
 -`α(N)`= 反阿克曼函数，有效常数

 ## 算法演练

 1. 初始化一个并查结构，每个人都从自己的组开始。 
2.维护两个数组：

 -`parent[i]`，它存储人的代表`i`-`rank[i]`或者`size[i]`，这有助于在联合期间保持树平衡
 3. 对于每个好友请求`[u, v]`，找到它们当前的组件根：

 -`rootU = find(u)`-`rootV = find(v)`4. 如果两个人已经属于同一个组件，则请求自动有效：

 - 接受请求
 - 追加`true`到答案
 - 继续下一个请求
 5. 否则，测试合并这两个组件是否会违反任何限制。 
6. 对于每一个限制`[x, y]`：

 - 计算：

 -`rootX = find(x)`-`rootY = find(y)`- 如果发生以下情况，则发生违规：

 -`rootX == rootU`和`rootY == rootV`- 或者
-`rootX == rootV`和`rootY == rootU`7. 如果违反任何限制：

 - 拒绝请求
 - 追加`false`- 不要合并组件
 8. 如果不违反限制：

 - 合并两个组件
 - 追加`true`9. 继续按顺序处理请求。 

### 为什么它有效

 Union-Find 始终维护由接受的友谊请求形成的精确连接组件。 在接受新请求之前，我们验证合并后没有限制对会出现在同一组件内。 由于每个接受的请求都保留所有限制，并且拒绝的请求不会更改结构，因此在整个算法中不变式仍然成立。 

## Python 解决方案```python
from typing import List

class Solution:
    def friendRequests(
        self,
        n: int,
        restrictions: List[List[int]],
        requests: List[List[int]]
    ) -> List[bool]:

        parent = list(range(n))
        rank = [0] * n

        def find(x: int) -> int:
            if parent[x] != x:
                parent[x] = find(parent[x])
            return parent[x]

        def union(x: int, y: int) -> None:
            root_x = find(x)
            root_y = find(y)

            if root_x == root_y:
                return

            if rank[root_x] < rank[root_y]:
                parent[root_x] = root_y
            elif rank[root_x] > rank[root_y]:
                parent[root_y] = root_x
            else:
                parent[root_y] = root_x
                rank[root_x] += 1

        result = []

        for u, v in requests:
            root_u = find(u)
            root_v = find(v)

            if root_u == root_v:
                result.append(True)
                continue

            can_merge = True

            for x, y in restrictions:
                root_x = find(x)
                root_y = find(y)

                violates = (
                    (root_x == root_u and root_y == root_v)
                    or
                    (root_x == root_v and root_y == root_u)
                )

                if violates:
                    can_merge = False
                    break

            if can_merge:
                union(u, v)
                result.append(True)
            else:
                result.append(False)

        return result
```实现首先初始化并查结构。 每个人最初都属于自己的组成部分，所以`parent[i] = i`。 

这`find`函数执行路径压缩。 每当发生查找时，这种优化都会使树的结构变平，从而使未来的操作更快。 

这`union`函数使用按等级并集来合并两个组件。 较小的树木附着在较大的树木下方，以保持结构较浅。 

对于每个请求，我们首先确定两个人是否已经连接。 如果是，则该请求将被自动接受，因为它不会引入新的连接。 

否则，我们扫描每个限制对。 我们检查一个受限制人员是否属于第一个组件，另一个受限制人员是否属于第二个组件。 如果是这样，合并组件将违反限制。 

如果没有限制阻止合并，我们将执行并集并接受请求。 

## 解决方案```go
package main

func friendRequests(n int, restrictions [][]int, requests [][]int) []bool {
	parent := make([]int, n)
	rank := make([]int, n)

	for i := 0; i < n; i++ {
		parent[i] = i
	}

	var find func(int) int

	find = func(x int) int {
		if parent[x] != x {
			parent[x] = find(parent[x])
		}
		return parent[x]
	}

	union := func(x, y int) {
		rootX := find(x)
		rootY := find(y)

		if rootX == rootY {
			return
		}

		if rank[rootX] < rank[rootY] {
			parent[rootX] = rootY
		} else if rank[rootX] > rank[rootY] {
			parent[rootY] = rootX
		} else {
			parent[rootY] = rootX
			rank[rootX]++
		}
	}

	result := make([]bool, 0, len(requests))

	for _, request := range requests {
		u := request[0]
		v := request[1]

		rootU := find(u)
		rootV := find(v)

		if rootU == rootV {
			result = append(result, true)
			continue
		}

		canMerge := true

		for _, restriction := range restrictions {
			x := restriction[0]
			y := restriction[1]

			rootX := find(x)
			rootY := find(y)

			violates := (rootX == rootU && rootY == rootV) ||
				(rootX == rootV && rootY == rootU)

			if violates {
				canMerge = false
				break
			}
		}

		if canMerge {
			union(u, v)
			result = append(result, true)
		} else {
			result = append(result, false)
		}
	}

	return result
}
```Go 实现遵循与 Python 版本相同的逻辑。 切片用于`parent`,`rank`， 和`result`数组。 

Go 不支持像 Python 那样的嵌套命名函数，所以`find`在赋值之前声明为函数变量以允许递归。 

该实现使用路径压缩和按等级并集，与 Python 中完全相同。 由于所有值都适合标准整数范围，因此不需担心溢出。

 ## 边缘情况

 当两个人在请求到达之前已经建立连接时，就会出现一种重要的边缘情况。 幼稚的实现可能会不必要地重新检查限制或意外拒绝请求。 在此问题中，此类请求必须始终成功，因为它不会引入新的连接。 该实现通过在扫描限制之前检查两个用户是否已经共享相同的根来处理此问题。 

另一个关键的边缘情况涉及间接违反限制。 两个受限制的人可能不会直接连接，但一系列接受的请求最终可以将他们放入同一个组件中。 基于图表的心理模型有助于说明这一点。 例如，如果`0`连接到`2`，以及后来`2`连接到`1`， 然后`0`和`1`成为间接连接。 并查结构正确地捕获了这一点，因为连接组件的所有成员共享相同的根。 

第三种边缘情况涉及拒绝的请求。 当请求违反限制时，友谊网络必须保持不变。 有缺陷的实现可能会在意识到请求无效之前部分修改联合查找结构。 此实现通过在调用之前执行所有限制检查来避免该问题`union`。 

另一个微妙的情况是涉及相同组件的多重限制。 单个合并可能会同时违反多个限制。 该实现在合并之前扫描每个限制，确保在结构更改之前检测到任何无效合并。
