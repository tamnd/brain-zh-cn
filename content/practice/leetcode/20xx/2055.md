[LeetCode 问题 2055](https://leetcode.com/problems/plates- Between-candles/)

 **难度：** 🟡 中等
 **主题：** 数组、字符串、二分查找、前缀和

 ## 解决方案

 ## 问题理解

 问题给了我们一个字符串`s`由两个字符组成：

 -`'*'`代表一个盘子
 -`'|'`代表一根蜡烛

 我们还给出了多个查询，其中每个查询指定一个子字符串`s`使用索引`[left, right]`。 

对于每个查询，我们必须计算该子串内的两根蜡烛之间有多少个板块。 

重要的细节是，只有满足以下条件，车牌才算数：

 - 子串中左侧至少有一根蜡烛
 - 子串右侧至少有一根蜡烛

 这意味着查询范围内最外面的蜡烛线之外的板块不计算在内。 

例如，考虑：```
s = "**|**|***|"
```供查询`[2, 9]`，子串为：```
|**|***|
```计算的板块是位于该子串中第一根和最后一根蜡烛之间的所有板块。 

约束条件非常重要：

 -`s.length`可以达到`100000`-`queries.length`也可以达到`100000`逐个字符扫描每个查询的简单解决方案会太慢。 在最坏的情况下，这需要：```
100000 * 100000 = 10^10
```操作，这是不可行的。 

因此，该问题强烈建议对字符串进行预处理，以便可以有效地回答每个查询。 

一些边缘情况很重要：

 - 查询可能根本不包含蜡烛
 - 一个查询可能只包含一根蜡烛
 - 可能存在蜡烛，但它们之间没有盘子
 - 第一根蜡烛之前或最后一根蜡烛之后的板块不应计算在内
 - 子串边界可能已经在蜡烛上开始或结束

 正确的解决方案必须仔细处理所有这些情况。 

## 方法

 ### 蛮力方法

 最直接的方法是独立处理每个查询。 

对于每个查询：

 1.提取子串`s[left:right+1]`2. 找到子串中的第一根蜡烛
 3. 找到子串中的最后一根蜡烛
 4. 数两根蜡烛之间的盘子

 这种方法是正确的，因为它直接遵循问题定义。 

然而，运行时间太昂贵了。 在最坏的情况下，每个查询都会扫描整个字符串，产生：

 -`O(n)`每个查询的工作量
 -`O(n * q)`总运行时间

 两者都有`n`和`q`最多`100000`，这变得太慢了。 

### 最佳方法

 关键的观察是查询是独立的，但字符串永远不会改变。 

这意味着我们可以对有用信息进行一次预处理，然后将其重复用于所有查询。 

我们使用三个预处理数组：

 1.`prefix_plates`-`prefix_plates[i]`存储索引之前出现的车牌数量`i`- 这允许快速范围计数
 2.`nearest_left_candle`- 对于每个索引，将最接近的蜡烛存储在左侧或左侧
 3.`nearest_right_candle`- 对于每个索引，将最接近的蜡烛存储在右侧或右侧

 对于每个查询：

 - 找到范围内的第一根有效蜡烛
 - 找到范围内最后一个有效的蜡烛
 - 使用前缀和来计算它们之间的车牌数量

 然后可以在恒定时间内回答每个查询。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n × q) | O(1) | O(1) | 独立扫描每个子字符串 |
 | 最佳 | O(n + q) | O(n) | 使用前缀和和最近蜡烛预处理 |

 ## 算法演练

 1. 构建车牌的前缀和数组。 

我们创建一个数组`prefix_plates`在哪里：```
prefix_plates[i + 1]
```存储的数量`'*'`中的字符`s[0:i]`。 

这使我们能够使用减法立即对任何范围内的板进行计数。 
2. 构建最近的左侧蜡烛阵列。 

从左向右遍历。 

跟踪最近的蜡烛位置。 

对于每个索引：

 - 如果角色是蜡烛，则更新最新的蜡烛位置
 - 将该位置存储在`nearest_left_candle[i]`3. 构建最近的右侧蜡烛阵列。 

从右向左遍历。 

跟踪迄今为止看到的最近的蜡烛。 

对于每个索引：

 - 如果角色是蜡烛，则更新最新的蜡烛位置
 - 将该位置存储在`nearest_right_candle[i]`4. 处理每个查询。 

供查询`[left, right]`：

 - 找到范围内的第一根蜡烛：```
start = nearest_right_candle[left]
```- 找到范围内的最后一根蜡烛：```
end = nearest_left_candle[right]
```5. 验证蜡烛位置。 

如果：

 - 任一蜡烛都不存在
 - 或`start >= end`那么不存在有效的封闭板，所以答案是`0`。 
6. 数一下蜡烛之间的盘子。 

使用前缀和：```
plates = prefix_plates[end] - prefix_plates[start]
```这严格计算两个蜡烛位置之间的所有板块。 

### 为什么它有效

 该算法之所以有效，是因为每个有效的板块必须位于两根蜡烛之间。 

对于查询，左边界蜡烛必须是范围内的第一根蜡烛，右边界蜡烛必须是范围内的最后一个蜡烛。 

这两个蜡烛之外的任何板块都不能满足问题条件。 

前缀总和数组在恒定时间内正确计算任意两个索引之间的板块，并且最近的蜡烛数组保证我们快速找到每个查询的有效蜡烛边界。 

## Python 解决方案```python
from typing import List

class Solution:
    def platesBetweenCandles(self, s: str, queries: List[List[int]]) -> List[int]:
        n = len(s)

        # Prefix sum of plates
        prefix_plates = [0] * (n + 1)

        for i in range(n):
            prefix_plates[i + 1] = prefix_plates[i]
            if s[i] == '*':
                prefix_plates[i + 1] += 1

        # Nearest candle on the left
        nearest_left_candle = [-1] * n
        last_candle = -1

        for i in range(n):
            if s[i] == '|':
                last_candle = i
            nearest_left_candle[i] = last_candle

        # Nearest candle on the right
        nearest_right_candle = [-1] * n
        last_candle = -1

        for i in range(n - 1, -1, -1):
            if s[i] == '|':
                last_candle = i
            nearest_right_candle[i] = last_candle

        # Answer queries
        result = []

        for left, right in queries:
            start = nearest_right_candle[left]
            end = nearest_left_candle[right]

            if start == -1 or end == -1 or start >= end:
                result.append(0)
            else:
                plates = prefix_plates[end] - prefix_plates[start]
                result.append(plates)

        return result
```实现直接遵循预处理策略。 

第一个循环构造前缀和数组。 每个条目存储迄今为止遇到的累计车牌数量。 

第二个循环计算每个位置左侧最近的蜡烛。 这允许查询快速定位左边界内最右边的有效蜡烛。 

第三个循环计算每个位置右侧最近的蜡烛。 这允许查询快速定位右边界内最左边的有效蜡烛。 

最后，每个查询都会在恒定时间内得到处理。 该算法找到蜡烛边界并使用前缀和来计算封闭板的数量。 

## 解决方案```go
func platesBetweenCandles(s string, queries [][]int) []int {
	n := len(s)

	// Prefix sum of plates
	prefixPlates := make([]int, n+1)

	for i := 0; i < n; i++ {
		prefixPlates[i+1] = prefixPlates[i]
		if s[i] == '*' {
			prefixPlates[i+1]++
		}
	}

	// Nearest candle on the left
	nearestLeft := make([]int, n)
	lastCandle := -1

	for i := 0; i < n; i++ {
		if s[i] == '|' {
			lastCandle = i
		}
		nearestLeft[i] = lastCandle
	}

	// Nearest candle on the right
	nearestRight := make([]int, n)
	lastCandle = -1

	for i := n - 1; i >= 0; i-- {
		if s[i] == '|' {
			lastCandle = i
		}
		nearestRight[i] = lastCandle
	}

	// Process queries
	result := make([]int, 0, len(queries))

	for _, query := range queries {
		left := query[0]
		right := query[1]

		start := nearestRight[left]
		end := nearestLeft[right]

		if start == -1 || end == -1 || start >= end {
			result = append(result, 0)
		} else {
			plates := prefixPlates[end] - prefixPlates[start]
			result = append(result, plates)
		}
	}

	return result
}
```Go 的实现与 Python 解决方案非常相似。 

切片用于所有预处理数组。 由于约束保证值能够轻松地落在标准整数范围内，因此常规`int`值就足够了。 

与 Python 列表不同，Go 切片需要使用显式分配`make`。 否则，整体逻辑是相同的。

 ## 边缘情况

 ### 没有蜡烛的查询

 子串可能只包含盘子而根本不包含蜡烛。 

例如：```
s = "*****"
query = [0, 4]
```由于没有蜡烛边界，因此蜡烛之间不可能包含任何板。 

处理这种情况是因为最近的蜡烛数组返回`-1`，并且执行立即返回`0`。 

### 仅使用一根蜡烛的查询

 子串可能只包含一根蜡烛。 

例如：```
s = "***|***"
query = [0, 6]
```即使存在蜡烛，板仍然不能被包围，因为需要两个蜡烛边界。 

实现检测到这一点是因为计算的`start`和`end`位置要么匹配要么产生`start >= end`。 

### 外蜡烛外的板

 最容易犯的错误之一是不小心计算了位于有效蜡烛边界之外的板块。 

例如：```
s = "**|**|**"
query = [0, 7]
```只有蜡烛之间的两个盘子才算数。 第一个蜡烛之前和最后一个蜡烛之后的板块必须被忽略。 

该实现通过首先定位内部蜡烛边界，然后使用前缀和仅严格计算这些位置之间的板块来正确处理此问题。
