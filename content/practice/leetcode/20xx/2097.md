 # LeetCode 2097 - 有效的配对排列

 ## 问题理解

 这个问题给了我们一个有向对的列表，其中每对`[starti, endi]`表示一条有向边`starti`到`endi`。 我们必须重新排列所有对，以便相邻对正确连接。 

更具体地说，如果安排是：```
[a, b], [c, d], [e, f]
```那么它必须满足：```
b == c
d == e
```换句话说，一对的结尾必须等于下一对的开头。 

重要的细节是每对必须仅使用一次。 我们不允许跳过边缘或重复使用它们。 

该问题保证至少存在一种有效的排列。 这种保证非常重要，因为它意味着由这些有向边形成的图始终具有欧拉路径。 

我们可以将问题重新解释为图问题：

 - 每个唯一的数字都是一个节点。 
- 每对`[u, v]`是一条有向边`u`到`v`。 
- 我们需要找到边的顺序，以便连续的边正确连接。 
- 由于每条边必须仅使用一次，因此这成为有向图中的欧拉路径问题。 

限制条件很大：

 - 最多`10^5`对
 - 节点值高达`10^9`这些限制立即排除了暴力排列方法。 阶乘时间解决方案是不可能的。 我们需要线性或近线性图算法。 

有几个边缘情况值得注意：

 - 图表可能包含循环。 
- 多个边可以通过同一节点连接。 
- 有效的排列可以从出度恰好比入度大一的节点开始。 
- 在欧拉电路情况下，每个节点可能具有相等的入度和出度。 
- 节点值很大，因此按节点值索引的数组不实用。 我们需要哈希图。 

保证存在有效的安排意味着我们不需要处理不可能的情况。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试每对可能的排序，并检查连续对是否正确连接。 

为了`n`对，有`n!`可能的排列。 对于每个排列，我们将验证是否：```
pairs[i - 1][1] == pairs[i][0]
```对于每一个相邻的对。 

这种方法是正确的，因为它最终会检查每一种可能的排列，因此必须找到一个有效的排列（如果存在）。 

然而，其复杂性是灾难性的。 即使是为了`n = 15`，阶乘增长变得不可行。 由于约束允许最多`10^5`配对的话，暴力破解是完全不可能的。 

### 最佳方法

 关键的观察结果是，这正是有向图中欧拉路径的定义。 

欧拉路径是每条边都只使用一次的路径。 

每对都是一条边：```
[start, end]
```以及所需的链接条件：```
previous_end == next_start
```这正是图遍历中边的连接方式。 

这意味着我们可以使用 Hierholzer 算法来解决该问题，该算法在线性时间内构造一条欧拉路径。 

该算法的工作原理是：

 1. 建立邻接表。 
2. 跟踪入度和出度。 
3.找到正确的起始节点。 
4.在消耗边的同时执行DFS。 
5、反转遍历结果。 

因为每条边都被访问一次，所以解决方案运行在`O(n)`时间。

 ## 算法演练

 ### 第 1 步：构建图表

 我们创建一个邻接表，其中：```
graph[u] = list of destination nodes
```每对`[u, v]`变为有向边`u`到`v`。 

同时，我们跟踪：

 -`outdegree[u] += 1`-`indegree[v] += 1`我们使用哈希映射，因为节点值可以大到`10^9`。 

### 步骤2：找到起始节点

 对于有向欧拉路径：

 - 一个节点可能有：```
outdegree = indegree + 1
```该节点必须是开始。 

- 一个节点可能有：```
indegree = outdegree + 1
```这个节点一定是终点。 

- 所有其他节点必须具有相同的入度和出度。 

如果没有节点具有额外的出度，则该图形成欧拉回路，并且我们可以从具有出边的任意位置开始。 

### 步骤 3：执行 Hierholzer 的 DFS

 我们从起始节点开始进行DFS。 

当当前节点仍然有传出边时：

 1. 从邻接表中删除一条边。 
2. 递归地 DFS 进入邻居。 

一旦节点没有剩余的出边，我们将其附加到路径中。 

这会产生逆序的欧拉遍历。 

### 步骤 4：反转路径

 DFS 以逆欧拉顺序记录节点，因为只有在耗尽所有传出边后才会添加节点。 

所以我们反转收集的路径。 

### 步骤 5：将节点转换为边

 假设最终的节点顺序为：```
[a, b, c, d]
```那么边缘排列就变成：```
[a, b]
[b, c]
[c, d]
```这将重建所需的对排序。 

### 为什么它有效

 Hierholzer 算法保证每条边都只使用一次。 由于边仅在所有传出边都耗尽后才附加到最终路径，因此遍历自然地将循环缝合在一起形成一个有效的欧拉路径。 

因为该问题保证存在有效的排列，所以该图始终满足欧拉路径条件。 因此，该算法始终会产生所有对的有效排序。 

## Python 解决方案```python
from collections import defaultdict
from typing import List

class Solution:
    def validArrangement(self, pairs: List[List[int]]) -> List[List[int]]:
        graph = defaultdict(list)
        indegree = defaultdict(int)
        outdegree = defaultdict(int)

        # Build graph and degree counts
        for start, end in pairs:
            graph[start].append(end)
            outdegree[start] += 1
            indegree[end] += 1

        # Find starting node
        start_node = pairs[0][0]

        for node in outdegree:
            if outdegree[node] == indegree[node] + 1:
                start_node = node
                break

        path = []

        # Hierholzer DFS
        def dfs(node: int) -> None:
            while graph[node]:
                next_node = graph[node].pop()
                dfs(next_node)

            path.append(node)

        dfs(start_node)

        path.reverse()

        # Convert node path into edge path
        result = []

        for i in range(len(path) - 1):
            result.append([path[i], path[i + 1]])

        return result
```实现首先构建邻接表和度计数器。 每对贡献一个传出边缘`start`和一个传入边缘`end`。 

接下来，我们确定欧拉路径起始节点。 如果一个节点有一个额外的出边，那么它一定是起点。 否则，我们可以安全地从第一对的起始值开始，因为该图形成了一个电路。 

DFS 函数实现了 Hierholzer 算法。 每条边都从邻接列表中删除一次，使用`pop()`。 一旦节点没有剩余的出边，它就会被添加到路径中。 

DFS完成后，由于回溯过程中记录了节点，因此节点顺序会颠倒。 

最后，我们通过将相邻节点对转换为有向边来重建边序列。 

## 解决方案```go
package main

func validArrangement(pairs [][]int) [][]int {
	graph := make(map[int][]int)
	indegree := make(map[int]int)
	outdegree := make(map[int]int)

	// Build graph
	for _, pair := range pairs {
		start := pair[0]
		end := pair[1]

		graph[start] = append(graph[start], end)
		outdegree[start]++
		indegree[end]++
	}

	// Find starting node
	startNode := pairs[0][0]

	for node := range outdegree {
		if outdegree[node] == indegree[node]+1 {
			startNode = node
			break
		}
	}

	path := []int{}

	var dfs func(int)

	dfs = func(node int) {
		for len(graph[node]) > 0 {
			lastIndex := len(graph[node]) - 1
			nextNode := graph[node][lastIndex]

			graph[node] = graph[node][:lastIndex]

			dfs(nextNode)
		}

		path = append(path, node)
	}

	dfs(startNode)

	// Reverse path
	for left, right := 0, len(path)-1; left < right; left, right = left+1, right-1 {
		path[left], path[right] = path[right], path[left]
	}

	// Build result edges
	result := [][]int{}

	for i := 0; i < len(path)-1; i++ {
		result = append(result, []int{path[i], path[i+1]})
	}

	return result
}
```Go 解决方案遵循与 Python 版本相同的逻辑。 使用地图代替字典来进行邻接列表和度跟踪。 

切片自然支持类似堆栈的行为，因此我们使用切片截断从每个邻接列表的末尾删除边缘。 

Go 在这里不需要特殊的溢出处理，因为所有节点值都安全地适合标准整数。

 ## 边缘情况

 ### 欧拉回路而不是欧拉路径

 在某些图中，每个节点具有相等的入度和出度。 在这种情况下，不存在具有额外出度的唯一起始节点。 

有缺陷的实现可能无法选择有效的起始节点。 当不存在特殊的起始节点时，我们的实现通过默认第一对的起始节点来处理这个问题。 

### 深度嵌套循环

 图可能包含多个互连的循环。 过早记录节点的幼稚 DFS 可能会产生无效的排列或丢失边缘。 

Hierholzer 算法专门解决了这个问题，即在所有传出边都用完之后，仅在回溯期间附加节点。 这保证了正确的循环缝合。 

### 大稀疏节点值

 节点值可以大到`10^9`。 使用直接按节点值索引的数组会浪费大量内存或完全失败。 

我们的解决方案使用哈希映射（`defaultdict`在Python和`map`Go 中），它有效地支持稀疏大整数，而不需要坐标压缩。
