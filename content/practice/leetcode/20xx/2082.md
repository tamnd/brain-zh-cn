[LeetCode 问题 2082](https://leetcode.com/problems/the-number-of-rich-customers/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题给了我们一个名为`Store`。 表中的每一行代表开具给客户的一张账单。 该表包含三列：

 -`bill_id`，唯一标识账单
 -`customer_id`，它标识与账单关联的客户
 -`amount`，存储账单金额

 我们需要确定有多少不同客户的至少一张账单金额严格大于`500`。 

重要的细节是我们计算的是客户，而不是账单。 客户可能有多个合格账单，但在最终答案中只应计算一次。 

例如，如果客户`1`有金额账单`549`和`834`，他们仍然只贡献`1`因为问题要求的是客户数量，而不是合格账单的数量。 

预期输出是一行，其中一列名为`rich_count`，其中包含满足条件的不同客户的总数。 

由于这是一个数据库问题，因此主要挑战是正确过滤行并避免重复的客户计数。 

一些重要的边缘情况包括：

 - 一位顾客可能有很多以上账单`500`，但仍必须只计算一次。 
- 有些客户可能根本没有合格的账单。 
- 账单金额等于`500`不应计数，因为条件严格大于`500`。 
- 该表可能仅包含不合格的账单，在这种情况下，结果应为`0`。 

由于该任务只需要过滤和统计唯一客户，因此可以通过简单的 SQL 查询高效地实施该解决方案。 

## 方法

 ### 蛮力方法

 从概念上讲，强力方法将逐行处理每一行，并手动跟踪哪些客户至少有一张合格的账单。 

我们可以遍历表中的所有记录，检查是否`amount > 500`，并将合格的客户 ID 存储在临时集合中。 扫描整个表后，我们将计算收集到的唯一客户 ID 的数量。 

这种方法是正确的，因为每张账单都会被检查，并且每个合格的客户都会被明确跟踪。 然而，在 SQL 中手动实现这一点是不必要的，因为关系数据库已经提供了用于过滤和非重复计数的优化操作。 

### 最佳方法

 关键的观察是，我们只关心账单金额超过的特定客户`500`。 

SQL提供了两个完全符合问题要求的内置操作：

 -`WHERE amount > 500`仅过滤符合条件的账单。 
-`COUNT(DISTINCT customer_id)`确保每个客户都被精确计数一次。 

这使得整个问题可以通过一个简洁的查询来解决。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 扫描所有行并手动跟踪唯一客户 |
 | 最佳 | O(n) | 内部 O(1) 或 O(k) | 使用 SQL 过滤和非重复计数 |

 这里，`n`是行数`Store`表，以及`k`是不同合格客户的数量。 

## 算法演练

 1. 扫描所有行`Store`桌子。 
2. 对于每一行，检查是否`amount`严格大于`500`。 
3.忽略金额小于或等于的行`500`因为他们不满足条件。 
4. 从剩余行中提取`customer_id`价值观。 
5. 删除重复项，以便每个客户仅计算一次，即使他们有多个合格账单。 
6. 计算剩余的不同客户 ID 的数量。 
7.使用列名返回结果`rich_count`。 

### 为什么它有效

 该算法之所以有效，是因为每个合格的账单都会被考虑一次。 通过过滤`amount > 500`，我们确保只留下有效的账单。 通过申请`DISTINCT`到`customer_id`，我们保证每个合格客户仅对最终答案贡献一次计数，无论他们有多少合格账单。 

## Python 解决方案

 LeetCode 数据库问题使用 SQL 而不是可执行的 Python 代码。 以下查询是完整的正确解决方案。```python
SELECT COUNT(DISTINCT customer_id) AS rich_count
FROM Store
WHERE amount > 500;
```该查询首先使用以下内容过滤表`WHERE amount > 500`健康）状况。 仅限金额严格大于的账单`500`保持。 

下一个，`COUNT(DISTINCT customer_id)`计算这些筛选行中出现的唯一客户数量。 这可确保拥有多张合格账单的客户仅被计算一次。 

最后返回结果以及所需的列名`rich_count`。 

## 解决方案

 LeetCode 数据库问题不需要 Go 代码，因为平台需要 SQL 查询提交。 等效的 SQL 解决方案如下所示。```go
SELECT COUNT(DISTINCT customer_id) AS rich_count
FROM Store
WHERE amount > 500;
```这个问题没有 Go 特定的实现细节，因为该解决方案纯粹基于 SQL。

 ## 边缘情况

 当客户的多张账单大于`500`。 简单地对符合条件的行进行计数的简单实现会过多地计算客户数量。 使用`COUNT(DISTINCT customer_id)`通过确保每个客户仅贡献一次计数来防止此问题。 

另一个重要的边缘情况是账单金额恰好是`500`。 该条件明确规定严格大于`500`，所以金额等于`500`不得符合资格。 查询使用正确处理此问题`amount > 500`而不是`>= 500`。 

当根本没有客户符合条件时，就会出现第三种边缘情况。 在这种情况下，过滤后的结果集将变为空。 SQL 聚合函数仍然返回有效结果，因此`COUNT(DISTINCT customer_id)`正确返回`0`。 

最后一个边缘情况是空表。 即使`Store`表不包含行，查询仍然正确执行并返回`0`因为没有合格的客户可供计算。
