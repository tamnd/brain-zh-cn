[LeetCode Problem 2072](https://leetcode.com/problems/the-winner-university/)

 **难度：** 🟢简单
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题给了我们两个数据库表，`NewYork`和`California`。 每个表包含大学学生的考试成绩。 每行代表一个学生，由唯一的标识符标识`student_id`，连同他们的`score`。 

竞争规则很简单。 如果学生的分数大于或等于`90`。 优秀学生较多的大学获胜。 

输出必须恰好包含一行，其中有一列名为`winner`。 可能的结果是：

 -`"New York University"`如果纽约有更多优秀的学生
 -`"California University"`如果加州有更多优秀的学生
 -`"No Winner"`如果两所大学都有相同数量的优秀学生

 问题本质上是要求我们：

 1. 统计一下有多少学生`NewYork`分数大于或等于`90`2. 数一下有多少学生`California`分数大于或等于`90`3. 比较两个计数
 4. 根据比较返回正确的获胜者字符串

 约束很小而且很简单，因为这是一个 SQL Easy 问题。 表之间没有连接，同一个表中没有重复的学生 ID，也没有复杂的过滤逻辑。 重要的观察是我们只关心分数是否至少`90`，而不是分数本身的确切值。 

有几个边缘情况需要考虑。 一所大学的优秀学生可能为零，而另一所大学则有一些。 两所大学的优秀学生都可能为零，这应该会产生`"No Winner"`。 另一个重要的情况是，即使两所大学的总成绩相差很大，但优秀学生的数量相同。 仅计算得分至少的学生数量`90`很重要。 

## 方法

 ### 蛮力方法

 蛮力的想法是手动扫描两个表中的每一行，并使用程序逻辑跟踪优秀学生的数量。 

从概念上讲，我们会：

 1. 遍历每一行`NewYork`2. 每当发生时增加一个计数器`score >= 90`3. 重复相同的过程`California`4. 比较两个计数器
 5. 返回适当的获胜者字符串

 这种做法是正确的，因为它明确地评价了每一个学生，准确地统计了所有优秀的学生。 

然而，在SQL中，手动模拟迭代是不必要的，而且效率低下。 SQL 是为基于集合的操作而设计的，因此过程计数会比聚合函数更加冗长且不够优雅。 

### 最佳方法

 最佳解决方案使用带有条件计数的 SQL 聚合。 

关键的见解是我们只需要两个数字：

 - 优秀学生人数`NewYork`- 优秀学生人数`California`SQL 聚合函数，例如`COUNT`与条件逻辑相结合使我们能够在单个查询中有效地计算这些计数。 

获得这两个计数后，我们可以使用`CASE`表达式来确定获胜者。 

这种方法是最佳的，因为 SQL 数据库针对计数和过滤等聚合操作进行了高度优化。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(N + M) | O(1) | O(1) | 手动迭代两个表 |
 | 最佳| O(N + M) | O(1) | O(1) | 使用 SQL 聚合和条件逻辑 |

 这里，`N`是行数`NewYork`， 和`M`是行数`California`。 

## 算法演练

 1. 统计全校优秀学生人数`NewYork`通过检查有多少行满足表`score >= 90`。 
2. 统计全班优秀学生人数`California`表使用相同的条件。 
3. 使用 a 比较两个计数`CASE`陈述。 
4. 如果纽约的计数更大，则返回`"New York University"`。 
5. 如果加州的计数更大，则返回`"California University"`。 
6.否则返回`"No Winner"`因为比赛以平局结束。 

### 为什么它有效

 该算法之所以有效，是因为比赛获胜者完全取决于至少得分的学生数量`90`。 通过精确统计每个表中的学生人数并比较总数，我们直接执行问题陈述中描述的竞赛规则。 由于每个学生只被评估一次，因此计数是准确的，并且比较总是产生正确的结果。 

## Python 解决方案

 尽管这是针对 SQL 的数据库问题，但以下 Python 实现以编程方式演示了相同的逻辑。```python
from typing import List

class Solution:
    def findWinner(
        self,
        new_york_scores: List[int],
        california_scores: List[int]
    ) -> str:
        new_york_excellent = sum(
            score >= 90 for score in new_york_scores
        )

        california_excellent = sum(
            score >= 90 for score in california_scores
        )

        if new_york_excellent > california_excellent:
            return "New York University"

        if california_excellent > new_york_excellent:
            return "California University"

        return "No Winner"
```实施首先对两校的优秀学生进行统计。 在 Python 中，布尔表达式计算结果为整数，其中`True`等于`1`和`False`等于`0`。 这允许`sum(score >= 90 for score in scores)`直接统计优秀学生。 

计算完两个计数后，代码将它们与简单的条件语句进行比较，并返回正确的获胜者字符串。 

对于实际的 LeetCode 数据库提交，SQL 解决方案如下所示：```python
SELECT
    CASE
        WHEN ny_count > ca_count THEN 'New York University'
        WHEN ca_count > ny_count THEN 'California University'
        ELSE 'No Winner'
    END AS winner
FROM
(
    SELECT
        (SELECT COUNT(*)
         FROM NewYork
         WHERE score >= 90) AS ny_count,

        (SELECT COUNT(*)
         FROM California
         WHERE score >= 90) AS ca_count
) counts;
```此 SQL 查询使用子查询计算两个计数，然后使用`CASE`表达。 

## 解决方案```go
package main

func findWinner(newYorkScores []int, californiaScores []int) string {
	newYorkExcellent := 0
	for _, score := range newYorkScores {
		if score >= 90 {
			newYorkExcellent++
		}
	}

	californiaExcellent := 0
	for _, score := range californiaScores {
		if score >= 90 {
			californiaExcellent++
		}
	}

	if newYorkExcellent > californiaExcellent {
		return "New York University"
	}

	if californiaExcellent > newYorkExcellent {
		return "California University"
	}

	return "No Winner"
}
```Go 实现遵循与 Python 版本相同的逻辑。 Go 不使用 Python 的布尔求和快捷方式，而是在分数大于或等于时显式增加计数器`90`。 

Go不支持隐式布尔到整数的转换，因此需要手动计数。 否则，算法和复杂性保持不变。

 ## 边缘情况

 当两所大学的优秀学生都为零时，就会出现一种重要的边缘情况。 幼稚的实施可能会错误地假设至少一所大学必须获胜。 然而，问题清楚地表明，相等的计数会导致`"No Winner"`。 该实现自然地处理了这个问题，因为两个计数器都保持为零并且执行最终的返回语句。 

另一个关键的边缘情况是边界分数`90`。 由于定义说学生得分`90% or more`都非常优秀，比较必须使用`>= 90`而不是`> 90`。 使用错误的比较运算符会错误地排除具有完全正确的学生`90`。 

第三种边缘情况涉及相同数量的优秀学生，尽管总成绩差异很大。 例如，一所大学可能有许多低于以下的高分`90`，而另一个的分数正好高出一个`90`。 只有优秀学生的数量才重要。 该实现正确地忽略了以下所有分数`90`并仅比较合格的计数。 

最后的边缘情况是空输入数据集。 尽管数据库版本通常保证行存在，但如果两个输入都为空，则算法仍然可以正确运行。 两个优秀学生的数量都归零，产生`"No Winner"`安全无错误。
