[LeetCode 问题 2044](https://leetcode.com/problems/count-number-of-maximum-bitwise-or-subsets/)

 **难度：** 🟡 中等
 **主题：** 数组、回溯、位操作、枚举

 ## 解决方案

 ## 问题理解

 该问题要求我们检查给定数组的每个可能的非空子集`nums`并计算每个子集的按位或值。 在所有这些 OR 值中，我们需要确定最大可能值，然后计算有多少个不同的子集产生该最大值。 

通过选择元素的任意组合来形成子集，同时通过索引保留其原始身份。 这意味着即使两个元素具有相同的数值，选择不同的索引也会产生不同的子集。 例如，在`[2,2,2]`，每个非空子集被认为是不同的，因为所选位置不同。 

按位或运算将位组合在一起，使得结果中的每一位变成`1`如果至少有一个操作数设置了该位。 由于 OR 运算仅添加位而不会删除它们，因此向子集中添加更多元素只能维持或增加 OR 值。 

输入是一个整数数组`nums`，输出是一个整数，表示其 OR 等于可实现的最大 OR 值的非空子集的数量。 

约束条件很重要：

 -`1 <= nums.length <= 16`-`1 <= nums[i] <= 10^5`数组长度非常小。 最多有 16 个元素，子集总数为：$$2^{16} = 65536$$这足够小，可以枚举所有子集。 该观察结果强烈影响解决方案的设计。 

一些边缘情况很重要：

 - 所有元素都相同的数组，例如`[2,2,2]`- 单个元素已等于最大 OR 的数组
 - 只有大组合才能达到最大 OR 的数组
 - 长度为1的数组
 - 包含重叠位与完全不同位的数组

 该问题保证所有数字都是正整数，因此我们永远不需要处理空数组或负位行为。 

## 方法

 ### 蛮力方法

 最直接的解决方案是显式生成每个非空子集，计算其按位或，跟踪遇到的最大或，并计算有多少子集实现它。 

由于有`2^n`子集，我们可以使用位掩码来表示每个子集`1`到`(1 << n) - 1`。 

对于每个子集：

 1. 初始化一个 OR 值`0`2. 检查掩码中的每个位位置
 3. 如果该位被设置，则在 OR 计算中包括相应的元素
 4. 将生成的 OR 与当前最大值进行比较
 5.相应更新答案

 这种方法是正确的，因为它只检查每个可能的子集一次。 

时间复杂度为：$$O(n \cdot 2^n)$$因为每个`2^n`子集可以检查所有`n`元素。 

给定`n <= 16`，这其实是可以接受的。 然而，我们可以使用回溯来更优雅地构建解决方案。 

### 最优回溯方法

 关键的见解是子集生成自然地形成决策树。 

对于每个元素，我们只有两种选择：

 - 将其包含在当前子集中
 - 将其从当前子集中排除

 这种递归结构使我们能够使用深度优先搜索有效地探索所有子集。 

另一个重要的观察结果是最大 OR 值只是数组中所有元素的 OR 值。 由于 OR 仅累加位，因此使用每个元素都会产生最大可能的 OR。 

所以算法就变成了：

 1. 使用所有元素计算目标最大 OR
 2.使用DFS生成每个子集
 3. 递归时跟踪当前的OR
 4. 每当子集的 OR 等于目标时，增加答案

 这避免了重复地从头开始重新计算子集 OR 值。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n × 2^n) | O(n × 2^n) | O(1) | O(1) | 使用位掩码枚举所有子集 |
 | 最佳| O(2^n) | O(2^n) | O(n) | 使用增量 OR 计算进行回溯 |

 ## 算法演练

 ### 步骤 1：计算最大可能的 OR

 首先，计算数组中所有数字的或。```
target_or = nums[0] | nums[1] | ... | nums[n-1]
```这是有效的，因为 OR 运算仅添加位。 使用每个数字可以保证最大可能的 OR 值。 

### 步骤 2：定义递归 DFS 函数

 DFS函数需要两个参数：

 1.`index`，表示数组中的当前位置
 2.`current_or`，表示当前选择的子集的OR值

 在每一步中，我们决定是否包含或排除当前元素。 

### 第 3 步：处理基本情况

 当`index == len(nums)`，我们已经完成了一个子集的构建。 

此时：

 - 如果`current_or == target_or`，增加答案
 - 否则，忽略该子集

 ### 步骤 4：探索 Include 分支

 我们在包含当前数字后递归地继续。```
dfs(index + 1, current_or | nums[index])
```这会立即更新 OR 值。 

### 步骤 5：探索排除分支

 我们还递归地继续，不包括当前数字。```
dfs(index + 1, current_or)
```这会保留现有的 OR 值。 

### 第 6 步：返回最终计数

 DFS 探索整个递归树后，累积计数器包含 OR 等于最大可能 OR 的子集数量。 

### 为什么它有效

 递归只探索每个可能的子集一次，因为每个元素独立地有两个选择：包含或排除。 递归期间维护的 OR 值始终等于当前所选元素的 OR。 由于目标 OR 是可实现的最大 OR，因此计算 OR 等于该目标的子集会产生正确的答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def countMaxOrSubsets(self, nums: List[int]) -> int:
        target_or = 0
        
        for num in nums:
            target_or |= num
        
        count = 0
        n = len(nums)
        
        def dfs(index: int, current_or: int) -> None:
            nonlocal count
            
            if index == n:
                if current_or == target_or:
                    count += 1
                return
            
            # Include current element
            dfs(index + 1, current_or | nums[index])
            
            # Exclude current element
            dfs(index + 1, current_or)
        
        dfs(0, 0)
        
        return count
```解决方案从计算开始`target_or`，它表示任何子集可实现的最大 OR。 这是通过对数组中的所有元素进行“或”运算来完成的。 

递归`dfs`然后函数探索子集决策树。 参数`index`跟踪我们当前正在考虑的元素，同时`current_or`存储到目前为止所选子集的 OR 值。 

当递归到达数组末尾时，算法检查构造的子集是否达到最大 OR。 如果是这样，它就会增加计数器。 

每个元素的递归分支为两条路径：

 - 一个分支包含该元素
 - 另一个排除它

 这保证了所有子集的完整枚举。 

由于 OR 值是增量更新的，因此实现避免了重建子集或重复重新计算 OR 值。 

## 解决方案```go
func countMaxOrSubsets(nums []int) int {
	targetOr := 0

	for _, num := range nums {
		targetOr |= num
	}

	count := 0
	n := len(nums)

	var dfs func(index int, currentOr int)

	dfs = func(index int, currentOr int) {
		if index == n {
			if currentOr == targetOr {
				count++
			}
			return
		}

		// Include current element
		dfs(index+1, currentOr|nums[index])

		// Exclude current element
		dfs(index+1, currentOr)
	}

	dfs(0, 0)

	return count
}
```Go 实现遵循与 Python 解决方案相同的递归结构。 DFS 函数使用闭包，因此它可以访问`count`,`targetOr`， 和`nums`直接地。 

Go 整数可以安全地处理约束，因为 OR 值保持在 32 位整数限制内。 

与 Python 不同，Go 不支持`nonlocal`，所以递归闭包更新了外部`count`直接变量。

 ## 边缘情况

 ### 单元素数组

 当数组仅包含一个数字时，只有一个非空子集。 粗心的实现可能会意外地包含空子集或错误处理递归终止。 当前的实现仅正确计算包含该元素的子集。 

### 具有重复值的数组

 输入如`[2,2,2]`如果按值而不是按索引处理子集，则很容易发生错误处理。 该问题通过选定的位置定义子集，因此所有七个非空子集都是不同的。 递归方法自然可以处理这个问题，因为每个索引决策都是独立处理的。 

### 提前达到最大值 OR

 有时，在处理所有元素之前，子集就达到最大 OR。 例如，在`[7,1,2]`，子集`[7]`已经达到目标了。 不正确的优化可能会提前停止递归并错过其他有效的超集，例如`[7,1]`和`[7,2]`。 即使在达到目标 OR 后，实现也会继续探索所有分支，确保正确计算每个有效子集。
