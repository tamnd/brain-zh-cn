[LeetCode 问题 2073](https://leetcode.com/problems/time-needed-to-buy-tickets/)

 **难度：** 🟢简单
 **主题：** 数组、队列、模拟

 ## 解决方案

 ## 问题理解

 这个问题描述了一个队列`n`人，每个人都想买一定数量的票。 输入是一个数组`tickets`在哪里`tickets[i]`代表有多少张票`i-th`人想要。 这个过程就像现实生活中的队列一样：每个人一次购买**一张票**，每张票恰好需要**1秒**，如果他们仍然需要更多票，他们就会移到**队伍的末尾**。 一旦一个人买完了所有的票，他们就会离开队列。 

该问题具体询问该人员在该职位上花费的总时间`k`（0-索引）完成购买所有门票。 的位置`k`**固定在初始数组**中，但是当人们移动到行尾时，`k`将相对于队列的前面移动。 

约束表明`n`和`tickets[i]`很小（`<= 100`），因此直接模拟的方法是可行的。 重要的边缘情况包括当人在`k`当他们在前面时，当他们在后面时，当他们只需要一张票时，当他们需要多达100张票时。 

## 方法

 **暴力方法**是完全按照描述模拟队列。 我们按顺序遍历队列，将每个人的票数减 1，如果仍有票，则将他们移到后面。 我们继续直到索引处的人`k`已经买了他们所有的票。 这可以正常工作，但涉及重复移动队列中的人员，这在重复列表操作方面可能效率低下。 和`n`最多 100 个，票数最多 100 个，这是可以接受的，但不够优雅。 

**最佳方法**利用了一个关键观察结果：人所花费的时间`k`由他们参加多少**整轮**决定。具体来说，每个人`i`队列中的内容将为总时间贡献 **min(tickets[i], Tickets[k]) 秒**。 如果`i`位于**之后`k`**，他们贡献 **min(tickets[i], Tickets[k]-1) 秒**，因为人`k`在他们最后一张票之后结束，所以人们之后`k`在最后一轮不会增加加时赛。 这避免了完全模拟队列并给出了简单的 O(n) 解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * max(门票[i])) | O(n) | 一步步模拟队列|
 | 最佳 | O(n) | O(1) | O(1) | 使用基于回合的每人直接计数 |

 ## 算法演练

 1. 初始化`time = 0`。 该变量将跟踪人员所需的累积秒数`k`。 
2. 迭代每个人`i`在队列中从`0`到`n-1`。 
3.如果人`i`**之前或之后`k`**， 添加`min(tickets[i], tickets[k])`到`time`。 这包括所有完整回合和最后部分回合`k`。 
4.如果人`i`**之后`k`**， 添加`min(tickets[i], tickets[k]-1)`到`time`。 他们只参加之前的几轮比赛`k`完成了最后一张票。 
5. 返回`time`作为所需的总时间。 

**为什么有效：** 每个人对总时间的贡献最多为`tickets[k]`，除了之后的人`k`只参加之前几轮的人`k`买了最后一张票。 将这些贡献相加即可得出所需的确切秒数，而无需模拟队列。 

## Python 解决方案```python
from typing import List

class Solution:
    def timeRequiredToBuy(self, tickets: List[int], k: int) -> int:
        total_time = 0
        for i, t in enumerate(tickets):
            if i <= k:
                total_time += min(t, tickets[k])
            else:
                total_time += min(t, tickets[k] - 1)
        return total_time
```在此 Python 实现中，我们循环遍历`tickets`大批。 如果一个人处于或之前`k`，他们将购买所有轮次的门票，包括最后一轮`k`。 People after`k`只参加之前的回合`k`'s last ticket. 使用`min()`确保我们不会多计捐款。 决赛`total_time`被返回。 

## 解决方案```go
func timeRequiredToBuy(tickets []int, k int) int {
    totalTime := 0
    for i, t := range tickets {
        if i <= k {
            if t < tickets[k] {
                totalTime += t
            } else {
                totalTime += tickets[k]
            }
        } else {
            if t < tickets[k]-1 {
                totalTime += t
            } else {
                totalTime += tickets[k] - 1
            }
        }
    }
    return totalTime
}
```In Go, we follow the same logic as Python. 我们避免不必要的切片或队列，直接累加总秒数。 Go 没有`min`function for integers in the standard library, so we use explicit conditionals.

 使用最佳方法：

 0 号人想要 5 张票。 索引0之后的人贡献最多`min(tickets[i], tickets[0]-1)`=`min(tickets[i], 4)`：

 - i=0 → 分钟(5,5) = 5

 ## 边缘情况

 一种边缘情况是当队列中只有一个人时。 该算法正确返回他们想要的票数，因为`min(tickets[i], tickets[k])`计算票数本身。
