[LeetCode 2006 题](https://leetcode.com/problems/count-number-of-pairs-with-absolute-difference-k/)

 **难度：** 🟢简单
 **主题：** 数组、哈希表、计数

 ## 解决方案

 ## 问题理解

 问题给了我们一个整数数组`nums`和一个整数`k`。 我们需要计算有多少对索引`(i, j)`满足两个条件：

 1.`i < j`2.`|nums[i] - nums[j]| == k`符号`|x|`代表的绝对值`x`，表示两个数字之间的距离，无论方向如何。 例如，两者`3 - 1`和`1 - 3`的绝对差异为`2`。 

输入数组可以包含重复值，并且每个有效的索引对必须单独计数。 这很重要，因为相同的数值可以出现在多个位置。 例如，在`[1,2,2,1]`和`k = 1`，答案是`4`因为每个`1`可以与每个配对`2`。 

限制相对较小：

 -`1 <= nums.length <= 200`-`1 <= nums[i] <= 100`-`1 <= k <= 99`这些限制告诉我们几件事：

 - 该阵列足够小，即使是`O(n^2)`暴力解决方案会轻松通过。 
- 这些值也限制在一个小范围内。 
- 自从`k >= 1`，我们永远不需要计算具有相同值的对。 

尽管暴力破解在这里是可以接受的，但这个问题仍然是使用哈希图练习频率计数的好机会。 

一些重要的边缘情况包括：

 - 具有重复数字的数组，因为多个索引组合可能会产生相同的值对。 
- 不存在有效对的数组。 
- 每个元素都可以与多个其他元素配对的数组。 
- 非常小的数组，例如长度`1`，答案必须始终是`0`。 

## 方法

 ### 暴力方法

 最直接的解决方案是检查每一个可能的索引对`(i, j)`在哪里`i < j`。 

对于每对：

 1. 计算`abs(nums[i] - nums[j])`2. 如果结果等于`k`，增加答案。 

这种方法是正确的，因为它明确地对每个可能的对进行了一次评估。 由于没有跳过任何对，因此每个有效对都会被计数。 

然而，时间复杂度为`O(n^2)`因为我们使用了两个嵌套循环。 对于长度的数组`n`，大约有`n * (n - 1) / 2`配对进行检查。 

和`n <= 200`，这仍然是完全可以接受的，但是我们可以在概念上做得更好。 

### 最佳哈希映射方法

 关键的观察是对于当前的数字`x`，我们只关心我们是否已经看到：

 -`x - k`-`x + k`如果先前处理的数字中存在任何一个，则这些先前的值与`x`。 

我们可以维护一个频率图来存储每个数字到目前为止出现的次数。 

当我们遍历数组时：

 - 先前看到的值的数量等于`x - k`直接贡献于答案。 
- 先前看到的值的数量等于`x + k`也直接有助于答案。 

对这些匹配进行计数后，我们将当前数量记录在频率图中。 

这是有效的，因为我们从左到右处理数组，确保每个计数的对自动满足`i < j`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 |`O(n^2)`|`O(1)`| 直接检查每个可能的对 |
 | 最佳|`O(n)`|`O(n)`| 使用哈希映射来计算之前看到的值 |

 ## 算法演练

 ### 最优哈希图算法

 1. 初始化变量`pair_count`到`0`。 

该变量存储迄今为止找到的有效对的总数。 
2. 创建一个名为的空哈希映射`frequency`。 

地图将存储每个数字在数组中较早出现的次数。 
3. 迭代每个数字`num`在`nums`。 

我们从左到右处理数组，以便已存储在映射中的所有值都对应于较早的索引。 
4. 检查是否`num - k`存在于地图中。 

如果是这样，那么之前的每一次出现`num - k`与当前形成有效对`num`。 

添加`frequency[num - k]`到`pair_count`。 
5. 检查是否`num + k`存在于地图中。 

如果是这样，那么之前的每一次出现`num + k`也与当前形成有效对`num`。 

添加`frequency[num + k]`到`pair_count`。 
6. 将当前号码插入地图中。 

增量`frequency[num]`经过`1`。 
7.处理完所有元素后，返回`pair_count`。 

### 为什么它有效

 该算法保持频率图仅包含出现在当前索引之前的元素的计数的不变量。 

对于每个当前值`num`，任何较早的值等于`num - k`或者`num + k`满足：```
|num - previous_value| == k
```由于在处理第二个元素时对每对进行精确计数，因此每个有效对仅计数一次。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def countKDifference(self, nums: List[int], k: int) -> int:
        frequency = defaultdict(int)
        pair_count = 0

        for num in nums:
            pair_count += frequency[num - k]
            pair_count += frequency[num + k]

            frequency[num] += 1

        return pair_count
```实现使用`defaultdict(int)`所以丢失的钥匙会自动返回`0`。 这消除了显式存在检查的需要。 

变量`frequency`存储每个数字在数组中较早出现的次数。 对于每个当前数字，我们立即计算有多少个先前数字精确地相差`k`。 

操作顺序很重要。 我们首先计算匹配的先前值，然后将当前值插入到映射中。 这保证了我们永远不会将元素与其自身配对，并确保所有计数的对满足`i < j`。 

最后，该函数返回累积的对计数。 

## 解决方案```go
func countKDifference(nums []int, k int) int {
    frequency := make(map[int]int)
    pairCount := 0

    for _, num := range nums {
        pairCount += frequency[num-k]
        pairCount += frequency[num+k]

        frequency[num]++
    }

    return pairCount
}
```Go 实现遵循与 Python 版本相同的逻辑。 

Go 映射返回缺失键的零值，因此访问`frequency[num-k]`即使密钥不存在也是安全的。 

与 Python 不同，Go 不需要特殊的`defaultdict`结构，因为整数映射查找自然默认为`0`。 

这里不存在整数溢出问题，因为在给定约束的情况下，最大对数很小。

 ## 边缘情况

 一种重要的边缘情况是仅包含一个元素的数组。 由于有效的对需要两个不同的索引，因此答案必须始终是`0`。 该实现自然地处理了这个问题，因为循环从未找到任何先前见过的匹配值。 

另一个重要的情况涉及许多重复值。 例如，`[2,2,2,3,3]`和`k = 1`应该产生`6`有效对，因为每个`2`可以与每个配对`3`。 幼稚的实现可能会意外地只计算唯一值对而不是索引对。 频率图方法通过存储出现次数来正确计算所有组合。 

当不存在有效对时，会出现第三种边缘情况。 例如，`[1,3]`和`k = 3`没有绝对差等于的对`3`。 该算法可以安全地处理这个问题，因为丢失的哈希映射条目会造成影响`0`到答案。 

另一个微妙的情况是输入顺序。 有效对可以按升序、降序或混合顺序出现。 由于该算法同时检查`num - k`和`num + k`，无论较早的数字大于还是小于当前的数字，它都能正确识别对。
