 # LeetCode 2005 - 斐波那契树的子树删除游戏

 ## 问题理解

 该问题定义了一种特殊的二叉树，称为斐波那契树。 该结构是递归的：

 -`order(0)`是一棵空树。 
-`order(1)`是单个节点。 
-`order(n)`有：

 - 根节点，
 - 左子树等于`order(n - 2)`,
 - 右子树等于`order(n - 1)`。 

两个玩家，爱丽丝和鲍勃，轮流轮流。 爱丽丝总是先开始。 

在每一回合中，玩家选择当前树中的任何节点并删除该节点及其整个子树。 然而，有一条至关重要的规则：

 - 被迫移除根的玩家立即失败。 

这完全改变了游戏规则。 通常在公平的游戏中，走最后一步的棋会获胜，但在这里删除根就是失败的一步。 因此，两名玩家都试图避免陷入只有根部可移动的境地。 

输入是单个整数`n`，代表斐波那契树的顺序。 输出应该是：

 -`true`如果爱丽丝能够以最佳发挥赢得胜利，
 -`false`如果鲍勃能够以最佳发挥取得胜利。 

约束条件`1 <= n <= 100`相对较小，这强烈表明动态规划或递归博弈论解决方案是合适的。 我们不需要先进的优化技术。 

一些边缘情况非常重要：

 -`n = 1`，这棵树只包含根，所以爱丽丝立刻就输了。 
- 小值，例如`n = 2`和`n = 3`帮助建立复发行为。 
- 因为树是递归定义的，所以自然会出现重复的子问题。 
- 游戏结果仅取决于子树的顺序，而不取决于确切的节点标识。 

关键的挑战是确定一个位置在最佳玩法下是赢还是输。 

## 方法

 ### 蛮力方法

 强力解决方案将显式构造斐波那契树并递归模拟每个可能的移动。 

对于每个游戏状态：

 1. 枚举除根之外的每个可移动节点。 
2. 删除该子树。 
3. 从结果位置递归判断对手是赢还是输。 
4. 如果任何一步导致对手输，则当前状态为赢。 

这种方法是正确的，因为它直接遵循公正组合博弈中最优游戏的定义。 

然而，可能的游戏状态的数量增长得非常快。 斐波那契树本身的大小呈指数级增长。 重复重新计算相同的子树状态变得不可行。 

即使对于中等`n`，显式模拟变得过于昂贵。 

### 关键见解

 重要的观察是斐波那契树中的每个子树本身都是某个较小阶的斐波那契树。 

这意味着游戏状态可以仅由顺序来表示`n`。 

让：

-`win[n] = true`如果轮到的玩家可以强行获胜`order(n)`。 

现在考虑哪些动作是可能的。 

在`order(n)`：

 - 左子树是`order(n - 2)`,
 - 右子树是`order(n - 1)`。 

删除子树可以有效地将游戏转变为较小的独立斐波那契子树游戏的组合。 

这成为经典的斯普拉格-格伦迪风格的公正游戏。 

关键的模式很快就出现了：

 -`n = 1`正在失去，
 - 每一个较大的斐波那契树都会获胜。 

为什么？ 

因为玩家总是可以以这样的方式删除子树，从而使对手收到失败的配置。 

仔细分析递归后，我们发现：

 - 仅`n = 1`正在失去，
 - 全部`n >= 2`正在获胜。 

因此，整个问题就简化为一个非常简单的情况。

 ## 算法演练

 ### 最优算法

 1. 检查是否`n == 1`。 

如果树只有一个节点，则第一个玩家被迫立即删除根。 根据规则，该玩家输了。 
2.如果`n >= 2`， 返回`true`。 

对于每个至少为 2 阶的斐波那契树，第一个玩家总是可以删除使对手处于失败状态的子树。 
3. 返回结果。 

### 为什么它有效

 失基状态为`order(1)`。 

对于任何更大的斐波那契树：

 - 存在至少一棵可移动的非根子树，
 - 删除该子树会给对手留下相当于失败位置的配置。 

通过归纳，所有阶数大于 1 的树都成为获胜位置。 

所以：

-`order(1)`正在失去，
 - 每个`order(n)`为了`n >= 2`正在获胜。 

## Python 解决方案```python
class Solution:
    def findGameWinner(self, n: int) -> bool:
        return n != 1
```该实现直接对博弈论结果进行编码。 

如果`n == 1`，爱丽丝输了，因为她必须立即除去根。 

对于每个较大的斐波那契树，爱丽丝都有获胜的举动，因此函数返回`True`。 

解决方案故意是最小的，因为数学分析完全简化了问题。 

## 解决方案```go
func findGameWinner(n int) bool {
    return n != 1
}
```Go 实现在逻辑上与 Python 版本相同。 

Go直接使用内置的boolean类型，所以表达式`n != 1`已经计算出所需的返回值。 

不需要对溢出或内存管理进行特殊处理，因为该解决方案仅使用常量空间并执行单个比较。

 ## 边缘情况

 ### 单节点树

 最重要的边缘情况是`n = 1`。 

该树仅包含根节点，因此当前玩家没有其他选择。 由于消除根本原因会导致立即失败，因此第一个玩家就失败了。 

许多不正确的实现意外地将其视为获胜状态，因为从技术上讲，玩家进行了最后一步。 该问题使用相反的失败条件。 

### 小型递归结构

 类似的情况`n = 2`和`n = 3`很重要，因为它们建立了获胜模式。 

如果错误地理解了失败条件，则幼稚的递归实现可能会错误地评估这些状态。 

该实现可以正确处理这些，因为数学特征直接识别所有`n >= 2`作为胜利。 

### 最大约束

 该约束允许值达到`100`。 

由于子树呈指数增长，强力递归模拟可能变得极其昂贵。 

最佳实现完全避免了递归，并且无论输入大小如何都在恒定时间内工作。
