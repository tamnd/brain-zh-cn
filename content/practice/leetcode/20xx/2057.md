[LeetCode 问题 2057](https://leetcode.com/problems/smallest-index-with-equal-value/)

 **难度：** 🟢简单
 **主题：** 数组

 ## 解决方案

 ## 问题理解

 该问题给了我们一个 0 索引的整数数组`nums`。 我们必须找到最小的索引`i`这样：$$i \bmod 10 = nums[i]$$表达式`i mod 10`表示当`i`除以`10`。 

我们被要求扫描数组并确定是否有任何索引满足此条件。 如果多个索引满足它，我们必须返回最小的一个。 如果没有索引满足条件，我们返回`-1`。 

输入数组包含介于`0`和`9`，包含在内。 数组长度最多为`100`，因此输入尺寸非常小。 这立即表明简单的线性扫描就足够了。 

例如，考虑：```
nums = [4,3,2,1]
```我们检查每个索引：

 -`0 % 10 = 0`，不等于`4`-`1 % 10 = 1`，不等于`3`-`2 % 10 = 2`，等于`2`由于索引`2`是第一个有效索引，我们返回`2`。 

重要的细节是我们必须返回最小的有效索引。 这意味着当我们在从左到右的遍历过程中找到匹配的索引时，我们可以立即停止。 

这些约束还保证：

 - 数组始终至少有一个元素。 
- 每个值都已在范围内`0`到`9`。 
- 数组足够小，即使是低效的方法也可以通过。 

重要的边缘情况包括：

 - 第一个索引已满足条件的数组。 
- 没有索引满足条件的数组。 
- 具有多个有效索引的数组，我们必须返回最小的一个。 
- 数组长度大于`10`，因为索引大于`9`在模下环绕`10`。 

## 方法

 ### 蛮力方法

 暴力解决方案很简单。 我们迭代每个索引`i`在数组中并计算`i % 10`。 然后我们将该值与`nums[i]`。 

如果它们匹配，我们立即返回`i`因为我们是从左到右扫描，所以第一个匹配自动是最小的有效索引。 

如果我们完成扫描整个数组而没有找到匹配项，则返回`-1`。 

这种方法保证有效，因为它显式检查每个可能的候选索引。 

虽然这被称为暴力方法，但它已经足够高效了，因为数组大小最多为`100`。 

### 最佳方法

 最佳方法实际上是相同的线性扫描策略。 

关键的观察是该问题只需要独立检查每个索引。 不需要额外的数据结构、预处理、排序或动态编程。 

因为我们只需要第一个有效索引，所以一旦找到匹配项就可以立即停止。 这为我们提供了一个高效的单通道解决方案。

 ## 算法演练

 1.从索引开始迭代数组`0`。 
2. 对于每个索引`i`，计算余数`i % 10`。 
3. 将计算值与`nums[i]`。 
4. 如果相等，立即返回`i`。 

这是有效的，因为我们从左到右扫描，因此第一个匹配保证是最小的有效索引。 
5. 如果循环结束时没有找到任何有效索引，则返回`-1`。 

### 为什么它有效

 该算法之所以有效，是因为它只检查每个可能的索引一次。 由于遍历顺序是从最小索引到最大索引，因此遇到的第一个匹配索引一定是最小的有效答案。 如果没有索引满足条件，则返回`-1`是正确的，因为每个候选人都已经经过测试。 

## Python 解决方案```python
from typing import List

class Solution:
    def smallestEqual(self, nums: List[int]) -> int:
        for index, value in enumerate(nums):
            if index % 10 == value:
                return index
        
        return -1
```解决方案使用Python的`enumerate()`函数同时迭代索引和值。 

对于每个位置：

 -`index % 10`计算索引除以的余数`10`- 结果与当前数组值进行比较

 如果它们匹配，该函数立即返回当前索引，因为它是迄今为止遇到的最小有效索引。 

如果循环完成但没有返回，则说明不存在有效索引，因此函数返回`-1`。 

该实现直接反映了前面描述的算法，并且仅使用恒定的额外空间。 

## 解决方案```go
func smallestEqual(nums []int) int {
    for index, value := range nums {
        if index%10 == value {
            return index
        }
    }

    return -1
}
```Go 实现遵循与 Python 版本相同的逻辑。 

这`range`循环提供切片中每个元素的索引和值。 我们计算`index % 10`并与当前值进行比较。 

Go 切片已经安全地处理动态长度，并且不存在溢出问题，因为约束非常小。 不需要额外的内存分配。

 ## 边缘情况

 一个重要的边缘情况是第一个索引满足条件时。 例如，在`[0,1,2]`， 指数`0`已经匹配，因为`0 % 10 = 0`。 延迟返回或错误扫描的错误实现可能会错过返回最小有效索引的要求。 当前的实现通过在找到第一个匹配项后立即返回来避免这种情况。 

另一个重要的边缘情况是没有索引满足条件时。 在`[1,2,3,4,5,6,7,8,9,0]`，每次比较都失败。 某些实现可能会意外返回最后检查的索引或未初始化的值。 该解决方案正确返回`-1`仅在完全完成扫描后。 

第三种边缘情况涉及索引大于`9`。 因为比较使用的是模`10`，索引值环绕。 例如，索引`15`有`15 % 10 = 5`。 不正确的实现可能会比较原始索引而不是模结果。 当前的实现显式计算`index % 10`每次，确保所有有效输入大小的正确性。 

最后的边缘情况是单元素数组。 数组如`[0]`和`[5]`测试实现是否正确处理最小输入大小。 由于循环自然处理长度的数组`1`，无需任何特殊处理即可实现。
