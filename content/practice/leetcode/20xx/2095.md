[LeetCode 问题 2095](https://leetcode.com/problems/delete-the-middle-node-of-a-linked-list/)

 **难度：** 🟡 中等
 **主题：** 链表、两个指针

 ## 解决方案

 ## 问题理解

 该问题给了我们一个单链表的头，并要求我们删除中间节点。 中间节点的定义是基于0的索引。 如果列表中有`n`节点，那么中间节点就是索引处的节点`⌊n / 2⌋`。 

例如：

 - 如果列表长度为`1`，中间索引为`0`- 如果列表长度为`4`，中间索引为`2`- 如果列表长度为`7`，中间索引为`3`删除该节点后，我们必须返回修改后的链表的头。 

单链表只允许从头到尾单向遍历。 由于每个节点只知道下一个节点，因此删除节点需要访问紧邻其之前的节点。 在设计算法时这个细节变得很重要。 

约束告诉我们链表最多可以包含`10^5`节点。 这意味着解决方案必须高效。 一个`O(n)`解决方案是理想的，而对于大输入来说，速度明显慢的东西可能会成为问题。 

一些边缘情况很重要：

 - 仅包含一个节点的列表。 删除中间节点意味着链表变空，所以我们返回`None`。 
- 包含两个节点的列表。 中间的索引是`1`，因此必须删除第二个节点。 
- 偶数长度列表。 该问题将中间明确定义为`⌊n / 2⌋`，这意味着两个中心节点中的第二个被删除。 
- 非常大的列表。 如果可能的话，算法应该避免不必要的额外内存或重复遍历。 

## 方法

 ### 蛮力方法

 一种直接的方法是首先统计链表中节点的总数。 一旦我们知道了长度`n`，我们可以将中间索引计算为`n // 2`。 

找到中间索引后，我们再次遍历链表，直到到达中间节点之前的节点。 然后我们更新它的`next`跳过中间节点的指针。 

这种方法是正确的，因为：

 1、第一次遍历准确确定列表大小。 
2、中间指标公式与问题定义相符。 
3. 第二次遍历找到中间节点的前驱，这样我们就可以安全地删除它。 

尽管该解决方案对于约束条件足够有效，但它需要两次遍历列表。 

### 最佳方法

 更好的解决方案使用快慢指针技术。 

关键的见解是，如果一个指针的移动速度是另一个指针的两倍，那么当快指针到达列表末尾时，慢指针将位于列表的中间。 

我们维持：

 -`slow`，一次移动一步
 -`fast`，一次移动两步
 -`prev`，它跟踪之前的节点`slow`当遍历结束时：

 -`slow`指向中间节点
 -`prev`指向中间之前的节点

 然后我们可以通过设置删除中间节点：```
prev.next = slow.next
```这种方法在一次遍历中完成任务并使用恒定的额外空间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n) | O(1) | O(1) | 两次遍历链表 |
 | 最佳| O(n) | O(1) | O(1) | 使用快慢指针的单次遍历 |

 ## 算法演练

 1. 首先处理单节点边缘情况。 

如果`head.next`是`None`，则列表仅包含一个节点。 删除中间节点留下空列表，因此返回`None`。 
2. 初始化三个指针。 

放：

-`slow = head`-`fast = head`-`prev = None`这`slow`指针最终会到达中间节点。 这`fast`指针移动速度加快两倍。 这`prev`指针跟踪紧邻之前的节点`slow`。 
3. 遍历链表。 

继续，同时两个`fast`和`fast.next`存在：

 - 移动`prev`到`slow`- 移动`slow`向前迈出一步
 - 移动`fast`前进两步
 4. 识别中间节点。 

当循环结束时：

 -`slow`指向中间节点
 -`prev`指向中间之前的节点
 5.删除中间节点。 

更新：```
prev.next = slow.next
```这将从链表中删除中间节点。 
6. 返回修改后的列表头。 

由于除了单节点情况外，头本身没有改变，因此返回`head`。 

### 为什么它有效

 慢速指针每前进一个节点，快指针就前进两个节点。 因此，当快指针到达链表末尾时，慢指针正好走了一半的距离，将其放置在中间节点。 自从`prev`总是落后一步`slow`，它提供了对删除后重新连接列表所需的节点的直接访问。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

class Solution:
    def deleteMiddle(self, head: Optional[ListNode]) -> Optional[ListNode]:
        # If there is only one node, deleting the middle leaves an empty list
        if head.next is None:
            return None

        slow = head
        fast = head
        prev = None

        # Find the middle node
        while fast and fast.next:
            prev = slow
            slow = slow.next
            fast = fast.next.next

        # Remove the middle node
        prev.next = slow.next

        return head
```该实现首先处理列表仅包含一个节点的特殊情况。 由于该节点也是中间节点，因此正确的结果是一个空列表。 

接下来，算法初始化`slow`,`fast`， 和`prev`指针。 遍历过程中，`slow`一次前进一个节点，同时`fast`一次前进两个节点。 这保证了`slow`当循环结束时到达中间。 

这`prev`指针在移动前更新`slow`，确保它始终指向中间节点之前的节点。 一旦识别出中间节点，算法就会通过重新连接来删除它`prev.next`到之后的节点`slow`。 

最后返回修改后的头。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func deleteMiddle(head *ListNode) *ListNode {
    // Single node case
    if head.Next == nil {
        return nil
    }

    slow := head
    fast := head
    var prev *ListNode = nil

    // Find the middle node
    for fast != nil && fast.Next != nil {
        prev = slow
        slow = slow.Next
        fast = fast.Next.Next
    }

    // Delete the middle node
    prev.Next = slow.Next

    return head
}
```Go 实现遵循与 Python 版本相同的逻辑。 主要区别是显式指针处理`*ListNode`。 

Go 使用`nil`而不是Python的`None`。 遍历循环检查两者`fast != nil`和`fast.Next != nil`在推进指针之前避免取消引用 nil 指针。 

因为 Go 中的链表已经是基于引用的结构，所以修改`prev.Next`直接更新原来的列表。

 ## 边缘情况

 单节点链表是最重要的边缘情况。 在这种情况下，唯一的节点也是中间节点。 一个常见的错误是尝试访问`prev.next`什么时候`prev`仍然是`None`。 该实现通过显式检查是否`head.next`是`None`在开始遍历并立即返回之前`None`。 

二节点链表是另一个微妙的情况。 由于中间索引是`1`，必须删除第二个节点。 一些不正确的实现意外地删除了第一个节点，因为它们错误地处理了偶数长度列表。 快慢指针的做法自然而然地`slow`在第二个节点上，确保正确删除。 

偶数长度的链表也会导致差一错误。 该问题将中间定义为`⌊n / 2⌋`，这意味着第二个中间节点应该被删除。 遍历逻辑保证了这种行为，因为慢指针在每次快指针移动后都会前进，导致它在奇数和偶数列表长度上都稳定在正确的中间位置。
