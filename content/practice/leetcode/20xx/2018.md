[LeetCode 2018 题](https://leetcode.com/problems/check-if-word-can-be-placed-in-crossword/)

 **难度：** 🟡 中等
 **主题：** 数组、矩阵、枚举

 ## 解决方案

 ## 问题理解

 这个问题要求我们确定给定的单词是否可以合法地放入填字游戏板中，同时遵守填字游戏放置规则。 

输入由一个称为 的 2D 矩阵组成`board`，其中每个单元格可以包含三个可能值之一：

 -`'#'`，代表无法使用的阻塞单元。 
-`' '`，表示可以接受任何字符的空单元格。 
- 一个小写英文字母，代表预填字母，必须与单词对应的字母匹配。 

我们还得到了一个字符串`word`，任务是返回`true`如果该单词可以放置在填字游戏中的某个位置，否则返回`false`。 

这个词可以放在四个方向：

 1.从左到右
 2.从右到左
 3.从上到下
 4.从下到上

 但是，仅当满足所有填字游戏约束时，放置才有效。 

首先，单词不能与任何单词重叠`'#'`细胞。 其次，该单词占据的每个棋盘单元必须已经包含匹配的字母或为空（`' '`）。 第三，该单词必须完全适合可用的片段。 这意味着该词不能成为更大开放空间的一部分。 对于水平放置，单词之前和之后的单元格必须位于板外或被`'#'`。 同样，对于垂直放置，正上方和正下方的单元格必须被阻挡或出界。 

约束在这里很重要。 自从`m * n ≤ 2 * 10^5`，董事会可能会变得相当大。 这告诉我们，重复扫描棋盘以查找每个可能位置的低效强力搜索可能会变得太慢。 我们需要一个相对于电路板尺寸大约以线性时间运行的解决方案。 

一些边缘情况很容易导致简单的实现失败。 一个单词可能只能以相反的顺序排列，这意味着我们必须同时考虑向前和向后的方向。 黑板上现有的字母可能部分匹配该单词并部分阻止它。 一个段可能具有正确的长度，但由于相邻的单元未被阻塞而失败。 也有一些情况，一个单词看起来适合水平放置，但只能垂直放置，反之亦然。 

一个重要的保证是字长永远不会超过`max(m, n)`，这意味着理论上它可以容纳在至少一行或一列中。 

## 方法

 ### 蛮力方法

 强力解决方案会尝试将单词从每个单元格开始向所有四个方向放置。 对于每个起点，我们将检查是否：

 - 这个词保持在界限之内。 
- 不`'#'`遇到细胞。 
- 现有字母匹配。 
- 周围边界条件有效。 

这种方法是正确的，因为它明确检查每个可能的合法位置。 

然而，它的效率很低。 假设董事会有`m × n`单元格和字长是`k`。 对于每个单元格，我们尝试最多四个方向，每个验证成本`O(k)`。 这导致时间复杂度为`O(m × n × k)`。 

尽管这在实践中对于某些输入仍然可能通过，但它执行了不必要的重复工作，因为许多放置由于段边界而立即失败。 

### 最佳方法

 关键的见解是有效的放置必须发生在由`'#'`。 

我们可以扫描行和列并只考虑最大开放段，而不是在每个方向上测试每个起始单元。 有效的放置必须恰好占据长度等于字长的段。 

例如，考虑一行：```
# a _ c #
```开路段是`"a c"`两个之间`'#'`人物。 如果它的长度与单词长度匹配，我们只需要检查该单词是否与该段匹配，无论是向前还是向后。 

这一观察极大地简化了问题。 我们处理每行和列一次，提取之间的段`'#'`，并仅验证相关片段。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(m × n × k) | O(m × n × k) | O(1) | O(1) | 尝试每个起始单元格和方向 |
 | 最佳| O(m × n) | O(1) | O(1) | 扫描一次段并验证精确匹配 |

 ## 算法演练

 ### 最优算法

 1. 定义一个辅助函数来检查片段是否可以与单词匹配。 

助手接收一个字符序列并确定该单词是否可以完全匹配。 段长度必须等于字长度。 然后，对于每个位置，棋盘角色必须是`' '`或匹配相应的单词字符。 
2. 还要检查颠倒的单词。 

由于这个词可以在两个方向放置，我们测试两个方向`word`和`word[::-1]`。 
3. 扫描每一行。 

对于每一行，将其分成连续的段，由`'#'`。 每个部分代表一个可能容纳单词的最大开放空间。 
4. 验证行段。 

如果段长度等于单词长度，则测试它是否与正向或反向单词匹配。 
5. 扫描每一列。 

垂直重复相同的过程。 不是行，而是逐列构造段。 
6. 如果找到有效的位置，请提前返回。 

一旦我们发现一个合法的位置，我们就会返回`True`。 
7. 如果没有段有效，则返回`False`。 

### 为什么它有效

 该算法之所以有效，是因为每个有效的单词位置都必须占据一个不间断的非连续段。`'#'`细胞。 通过仅扫描这些最大段，我们保证自动满足边界条件。 由于我们测试正向和反向方向并验证每个字符兼容性规则，因此每个合法位置都会被检查一次。 

## Python 解决方案```python
from typing import List

class Solution:
    def placeWordInCrossword(self, board: List[List[str]], word: str) -> bool:
        rows = len(board)
        cols = len(board[0])
        reversed_word = word[::-1]

        def matches(segment: List[str], candidate: str) -> bool:
            if len(segment) != len(candidate):
                return False

            for board_char, word_char in zip(segment, candidate):
                if board_char != ' ' and board_char != word_char:
                    return False

            return True

        def check_line(line: List[str]) -> bool:
            start = 0
            length = len(line)

            while start < length:
                while start < length and line[start] == '#':
                    start += 1

                end = start
                while end < length and line[end] != '#':
                    end += 1

                segment = line[start:end]

                if (
                    matches(segment, word)
                    or matches(segment, reversed_word)
                ):
                    return True

                start = end

            return False

        for row in board:
            if check_line(row):
                return True

        for col in range(cols):
            column = [board[row][col] for row in range(rows)]

            if check_line(column):
                return True

        return False
```该实现被组织为两个辅助函数。 

这`matches()`函数检查一个段是否可以容纳一个候选词。 它首先验证相等的长度，因为填字游戏规则需要精确拟合。 然后它对字符进行一一比较。 如果棋盘字符为空（`' '`) 或已经等于所需的字母。 

这`check_line()`函数处理行或列。 它扫描之间的连续区域`'#'`字符并提取片段。 每个片段都会针对原始单词及其反义词进行测试。 

主函数首先检查每一行。 如果不存在有效的水平放置，它将构造每一列并垂直执行相同的逻辑。 当找到有效的展示位置时，搜索立即终止。 

## 解决方案```go
func placeWordInCrossword(board [][]byte, word string) bool {
	rows := len(board)
	cols := len(board[0])
	reversedWord := reverse(word)

	matches := func(segment []byte, candidate string) bool {
		if len(segment) != len(candidate) {
			return false
		}

		for i := 0; i < len(candidate); i++ {
			if segment[i] != ' ' && segment[i] != candidate[i] {
				return false
			}
		}

		return true
	}

	checkLine := func(line []byte) bool {
		start := 0
		n := len(line)

		for start < n {
			for start < n && line[start] == '#' {
				start++
			}

			end := start
			for end < n && line[end] != '#' {
				end++
			}

			segment := line[start:end]

			if matches(segment, word) || matches(segment, reversedWord) {
				return true
			}

			start = end
		}

		return false
	}

	for _, row := range board {
		if checkLine(row) {
			return true
		}
	}

	for col := 0; col < cols; col++ {
		column := make([]byte, rows)

		for row := 0; row < rows; row++ {
			column[row] = board[row][col]
		}

		if checkLine(column) {
			return true
		}
	}

	return false
}

func reverse(s string) string {
	bytes := []byte(s)

	left, right := 0, len(bytes)-1
	for left < right {
		bytes[left], bytes[right] = bytes[right], bytes[left]
		left++
		right--
	}

	return string(bytes)
}
```Go 实现遵循与 Python 版本相同的算法结构。 由于 Go 字符串是不可变的，因此使用辅助函数通过将其转换为字节切片来有效地反转单词。 

列是使用临时显式构造的`[]byte`因为 Go 不为 2D 切片提供方便的列访问。 否则，逻辑保持不变。 

这里不存在整数溢出问题，因为约束完全在 Go 的标准整数范围内。

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|

 ## 边缘情况

 ### 单词仅适合反向

 一个常见的错误是忘记单词可以从右到左或从下到上放置。 例如，某个段可能因以下原因而失败`"abc"`但成功了`"cba"`。 该实现通过始终检查两者来避免此问题`word`和`word[::-1]`。 

### 段比单词大

 幼稚的实现可能会意外地允许将单词放置在更大的开放空间内。 例如：```
[ ' ', ' ', ' ' ]
```用词`"ab"`。 

此放置无效，因为仍然存在相邻的开放单元。 我们的算法通过要求段长度完全等于字长度来防止这种情况。 

### 现有字母冲突

 黑板上可能已经包含与单词部分重叠的字母。 例如：```
[a, b, c]
```用词`"abd"`。 

尽管前两个字母匹配，但最终位置会发生冲突。 这`matches()`函数显式验证每个字符，拒绝预填充字母与所需字母不同的位置。
