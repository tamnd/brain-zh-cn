[LeetCode 2013 题](https://leetcode.com/problems/detect-squares/)

 **难度：** 🟡 中等
 **主题：** 数组、哈希表、设计、计数、数据流

 ## 解决方案

 ## 问题理解

 该问题呈现了 2D 平面中的点流，并要求我们设计一种有效支持两种操作的数据结构：添加点和计算平方。 **add** 操作将一个点插入到数据结构中，**count** 操作计算使用查询点和已存储的任意三个点可以形成的轴对齐正方形的数量。 **轴对齐正方形**定义为边平行或垂直于 x 轴和 y 轴的正方形，这意味着其顶点的坐标沿轴遵循严格的模式。 

输入由整数点组成`[x, y]`在哪里`0 <= x, y <= 1000`。 允许重复点，这意味着同一坐标可能有多个实例，并且在形成正方形时每个实例单独计数。 输出是一个整数，表示使用查询点和三个先前添加的点形成轴对齐正方形的不同方法的数量。 

限制 - 最多 3000 次调用`add`和`count`-建议为每个计数操作迭代所有可能的三元组点的简单暴力解决方案可能会太慢。 边缘情况包括对没有潜在正方形伙伴的点、重复点以及边长为零的正方形（这些正方形无效，因为面积必须为正）的查询。 

## 方法

 ### 蛮力方法

 暴力方法涉及将所有添加的点存储在列表中。 对于一个`count`查询时，我们将迭代存储列表中三个点的所有组合，并检查它们是否与查询点形成一个正方形。 为了验证正方形，我们将计算所有成对距离，并确保边有两个相等的距离，对角线有一个较长的距离。 这种方法原则上可行，但每个查询的 **时间复杂度为 O(n^3)**，其中`n`是点的数量，这对于 3000 次操作来说是不可接受的，因为在最坏的情况下可能会导致超过 270 亿次迭代。 

### 最佳方法

 关键的见解是我们只计算**轴对齐的正方形**，这意味着边是严格水平或垂直的。 这使我们能够利用哈希图来存储点的频率以进行有效的查找。 对于查询点`(x, y)`，轴对齐正方形的其他三个顶点必须位于相同的 x 或 y 坐标上：

 1. 正方形的边与轴平行，所以如果一个顶点`(x, y)`，相反的顶点必须是`(x + side_length, y + side_length)`或类似的变体。 
2. 通过仅迭代与查询点共享相同 x 或 y 坐标的点，我们大大减少了搜索空间。 
3. 我们维护一个**地图的地图**，其中外部地图以 x 坐标为键控，内部地图对 y 坐标的出现次数进行计数，从而能够以 O(1) 的速度查找特定位置的点。 

这将计数查询减少到 **O(n)** 其中`n`是沿与查询相同的 x 坐标的点的数量，添加一个点的时间为 **O(1)**。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 每个查询 O(n^3) | O(n) | 迭代所有三元组来检查方块，太慢 |
 | 最佳| 每次查询 O(n)，每次添加 O(1) | O(n) | 使用 hashmap 来计数点，利用轴对齐来提高效率 |

 ## 算法演练

 1. **初始化数据结构**：创建字典`points_count`其中每个键都是一个 x 坐标，值是将 y 坐标映射到其计数的另一个字典。 
2. **添加操作**：添加点时`(x, y)`, 增量`points_count[x][y]`1. 如果`x`或者`y`地图中不存在，请初始化它们。 
3. **计数操作**：对于一个查询点`(x, y)`：

 - 初始化一个变量`total_squares = 0`。 
- 迭代所有 x 坐标`col_x`在`points_count`在哪里`col_x != x`。 
- 对于每个候选 x 坐标，计算潜在正方形的边长`side = col_x - x`。 
- 检查两个可能的 y 坐标`(y + side)`和`(y - side)`用于形成一个正方形。 
- 对于每个候选顶点，将形成正方形的其他三个点的计数与`(x, y)`并添加到`total_squares`。 
4. **返回结果**：迭代完所有候选后，返回`total_squares`。 

**为什么有效**：该算法利用轴对齐正方形的属性。 通过仅迭代不同 x 坐标上的点并检查相应的 y 坐标，我们确保所有方块都被恰好考虑一次，通过存储的计数考虑重复点。 

## Python 解决方案```python
from collections import defaultdict
from typing import List

class DetectSquares:

    def __init__(self):
        self.points_count = defaultdict(lambda: defaultdict(int))

    def add(self, point: List[int]) -> None:
        x, y = point
        self.points_count[x][y] += 1

    def count(self, point: List[int]) -> int:
        x, y = point
        total_squares = 0
        if x not in self.points_count:
            return 0
        for col_x, y_map in self.points_count.items():
            if col_x == x:
                continue
            side_length = col_x - x
            # Check for squares above and below the query point
            for delta_y in [side_length, -side_length]:
                y2 = y + delta_y
                if y2 in y_map:
                    count1 = self.points_count[x].get(y, 0)
                    count2 = y_map[y]
                    count3 = y_map[y2]
                    total_squares += count1 * count2 * count3
        return total_squares
```**解释**：`add`函数更新嵌套字典中每个点的计数。 这`count`函数迭代其他顶点的可能的 x 坐标，计算边长，并检查相应的 y 坐标是否存在以确保轴对齐的正方形。 将计数相乘可以正确处理重复点。 

## 解决方案```go
type DetectSquares struct {
	pointsCount map[int]map[int]int
}

func Constructor() DetectSquares {
	return DetectSquares{pointsCount: make(map[int]map[int]int)}
}

func (this *DetectSquares) Add(point []int) {
	x, y := point[0], point[1]
	if this.pointsCount[x] == nil {
		this.pointsCount[x] = make(map[int]int)
	}
	this.pointsCount[x][y]++
}

func (this *DetectSquares) Count(point []int) int {
	x, y := point[0], point[1]
	total := 0
	for colX, yMap := range this.pointsCount {
		if colX == x {
			continue
		}
		side := colX - x
		for _, deltaY := range []int{side, -side} {
			y2 := y + deltaY
			if count, ok := yMap[y2]; ok {
				total += this.pointsCount[x][y] * yMap[y] * count
			}
		}
	}
	return total
}
```**Go 特定注释**：嵌套映射模仿 Python`defaultdict`。 无检查可确保安全的地图操作。 计数的乘法处理重复项。

 ## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间（添加）| O(1) | O(1) | 在 hashmap 中插入是常数时间 |
 | 时间（计数）| O(n) | 迭代地图中的所有 x 坐标 |
 | 空间| O(n) | 存储所有添加点的计数 |

 时间复杂度为`count`高效，因为它不需要检查三个点的所有组合； 它仅沿着对齐的轴检查相关候选者。
