[LeetCode 问题 2074](https://leetcode.com/problems/reverse-nodes-in-even-length-groups/)

 **难度：** 🟡 中等
 **主题：** 链接列表

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个单链表，并要求我们处理大小遵循自然数序列的组中的节点：

 - 第 1 组包含 1 个节点
 - 第 2 组包含 2 个节点
 - 第 3 组包含 3 个节点
 - 第 4 组包含 4 个节点
 - 等等

 但是，该列表可能会在组达到其预期大小之前结束。 因此，最终的组可能比预期的要小。 

对于每个组，我们必须确定其实际长度。 如果组长度是偶数，我们反转该组内的节点。 如果组长度是奇数，我们保持组不变。 

重要的细节是只有单个组内的节点被反转。 组之间的相对顺序必须保持不变。 

例如，考虑：```
[5,2,6,3,9,1,7,3,8,4]
```这些团体变成：```
[5]
[2,6]
[3,9,1]
[7,3,8,4]
```长度为 2 和 4 的组是偶数，因此我们只反转这些组：```
[5]
[6,2]
[3,9,1]
[4,8,3,7]
```最终结果：```
[5,6,2,3,9,1,4,8,3,7]
```约束允许最多`10^5`节点，这意味着我们需要一个有效的线性时间解决方案。 任何重复遍历列表的大部分或执行昂贵的数组操作的方法都可能变得太慢。 

一些边缘情况尤其重要：

 - 只有一个节点的列表
 - 最终组的规模小于预期
 - 多个连续的偶数长度组
 - 最后一组长度相等但仍需要逆转
 - 大小为 1 的组，永远不应该颠倒，因为 1 是奇数

 因为这是一个链表问题，所以仔细的指针操作至关重要。 反转后不正确的重新连接很容易破坏列表结构。 

## 方法

 ### 蛮力方法

 一种简单的方法是首先将所有链表值复制到一个数组中。 

一旦我们有了数组，我们就可以按索引范围处理组：

 1.确定当前组边界
 2、检查组长是否均匀
 3. 如果需要的话，反转对应的子数组
 4.处理完所有组后，从修改后的数组重建链表

 这是可行的，因为数组使反转范围变得非常容易。 然而，这种方法使用与节点数量成比例的额外内存。 

虽然时间复杂度总体上保持线性，但额外的内存使用是不必要的，因为问题可以直接在链表本身上解决。 

### 最佳方法

 最佳解决方案是就地操作链表。 

关键的见解是我们只需要反转实际大小为偶数的组。 在遍历列表时，我们可以：

 1、判断当前组的实际长度
 2. 如果组大小为偶数，则反转该组
 3. 将反转的部分重新连接回主列表
 4.继续处理下一组

 这避免了将列表转换为另一种数据结构，并且仅使用恒定的额外空间。 

挑战在于仔细的指针管理：

 - 我们必须知道当前组从哪里开始
 - 我们必须知道结局在哪里
 - 我们必须保留组之后的节点
 - 反转后，必须重新正确连接所有部件

 由于每个节点仅被访问恒定次数，因此该算法在线性时间内高效运行。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 转换为数组、反转范围、重建列表 |
 | 最佳 | O(n) | O(1) | O(1) | 直接在链表中反转偶数组 |

 ## 算法演练

 1. 创建一个指向链表头部的虚拟节点。 

虚拟节点简化了指针处理，尤其是在列表开头附近反转组时。 
2. 维护一个名为`prev_group_tail`。 

该指针始终表示当前组之前的节点。 
3. 从团体规模开始`1`。 

预期的组大小按顺序增加`1, 2, 3, 4, ...`。 
4. 向前遍历，确定当前组的实际大小。 

由于列表可能提前结束，因此实际组大小可能小于预期大小。 
5. 存储：

 - 组的第一个节点
 - 紧接在该组之后的节点

 这些参考对于稍后重新连接列表是必需的。 
6. 检查实际组长是否均匀。 

如果人数为奇数，则保持该组不变并继续前进。 
7. 如果组长度均匀，则将组反转到位。 

使用标准链表反转技术：

 - 维护`prev`和`curr`- 一次反转一个节点的指针
 - 一旦整个组逆转就停止
 8. 将颠倒的组重新连接回列表中。 

逆转后：

 - 原来的团头变成了团尾
 - 原团尾成为新团头

 我们重新连接：

 -`prev_group_tail.next`到新的头
 - 下一组的新尾巴
 9. 移动`prev_group_tail`到已处理组的末尾。 

这为下一次迭代的算法做好了准备。 
10. 将预期组大小增加 1 并继续，直到处理完所有节点。 

### 为什么它有效

 该算法始终一次只处理一个连续的组。 在修改任何指针之前，它会识别组的边界并保留与列表其余部分的连接。 

如果组大小为奇数，则列表结构保持不变。 

如果组大小是偶数，则仅反转组内的节点将保留所有其他节点的相对顺序。 由于算法在反转后正确地重新连接了前一组和下一组，因此链表在整个执行过程中保持有效。 

由于每个节点都属于一个组并被处理一次，因此最终列表正确反映了所有所需的反转。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

class Solution:
    def reverseEvenLengthGroups(self, head: Optional[ListNode]) -> Optional[ListNode]:
        dummy = ListNode(0)
        dummy.next = head
        
        prev_group_tail = dummy
        group_size = 1
        
        while prev_group_tail.next:
            group_head = prev_group_tail.next
            
            # Find actual group length
            current = group_head
            actual_length = 0
            
            while current and actual_length < group_size:
                current = current.next
                actual_length += 1
            
            next_group_head = current
            
            # Reverse if group length is even
            if actual_length % 2 == 0:
                prev = next_group_head
                curr = group_head
                
                for _ in range(actual_length):
                    temp = curr.next
                    curr.next = prev
                    prev = curr
                    curr = temp
                
                prev_group_tail.next = prev
                prev_group_tail = group_head
            
            else:
                for _ in range(actual_length):
                    prev_group_tail = prev_group_tail.next
            
            group_size += 1
        
        return dummy.next
```实现首先创建一个虚拟节点。 当第一个可逆组出现在列表前面附近时，这可以避免特殊处理。 

变量`prev_group_tail`始终指向当前组之前的节点。 这使得处理组后重新连接变得简单。 

为了确定实际的组长度，算法遍历`group_size`节点或直到列表结束。 这可以正确处理不完整的最终组。 

如果组长度是偶数，则算法执行就地链表反转。 变量`prev`从组后面的节点开始，以便反转组的尾部在反转期间自动重新连接到列表的其余部分。 

逆转后：

 -`prev`成为新的集团负责人
 -`group_head`成为新的群尾

 然后指针重新正确连接。 

如果组长度是奇数，则不会发生逆转，算法只是前进`prev_group_tail`整个集团。 

最后，下一次迭代的组大小会增加。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func reverseEvenLengthGroups(head *ListNode) *ListNode {
    dummy := &ListNode{Next: head}
    
    prevGroupTail := dummy
    groupSize := 1
    
    for prevGroupTail.Next != nil {
        groupHead := prevGroupTail.Next
        
        // Find actual group length
        current := groupHead
        actualLength := 0
        
        for current != nil && actualLength < groupSize {
            current = current.Next
            actualLength++
        }
        
        nextGroupHead := current
        
        // Reverse if even length
        if actualLength%2 == 0 {
            prev := nextGroupHead
            curr := groupHead
            
            for i := 0; i < actualLength; i++ {
                temp := curr.Next
                curr.Next = prev
                prev = curr
                curr = temp
            }
            
            prevGroupTail.Next = prev
            prevGroupTail = groupHead
            
        } else {
            for i := 0; i < actualLength; i++ {
                prevGroupTail = prevGroupTail.Next
            }
        }
        
        groupSize++
    }
    
    return dummy.Next
}
```Go 实现遵循与 Python 版本相同的逻辑，但使用 Go 指针语法。 

一些实施细节值得注意：

 - Go 使用`nil`而不是Python的`None`- 指针操作是显式的`*ListNode`- 反转循环使用标准`for`使用整数计数器循环
 - 没有分配额外的切片或数组，因此算法保持恒定的额外空间使用

 因为节点值被限制为`10^5`，整数溢出在 Go 中不是一个问题。

 ## 边缘情况

 ### 单节点列表

 仅包含一个节点的列表是最小的有效输入。 第一组的长度为 1，为奇数，因此不应发生反转。 

这种情况可能会暴露指针遍历假设存在其他节点的错误。 该实现可以安全地处理它，因为遍历循环在处理第一个节点后立即停止。 

### 最终不完整组

 最终组包含的节点可能少于其预期大小。 例如：```
[1,2,3,4,5]
```目标群体是：```
1
2
3
```但最后组只剩下两个节点。 

有缺陷的实现可能会错误地假设组大小始终是预期大小而不是实际剩余大小。 该解决方案在决定是否反转之前明确计算可用节点的实际数量。 

### 连续偶数长度反转

 某些输入包含多个紧密相连的偶数组。 不正确的重连逻辑很容易丢失节点或产生环路。 

例如：```
[1,1,0,6,5]
```第二组和第三组大小相等，需要逆转。 

该实现通过始终保留以下内容来避免指针损坏：

 - 组之前的节点
 - 组后的节点
 - 原组长

 这保证了每次反转操作后正确的重新连接。
