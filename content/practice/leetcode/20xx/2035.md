[LeetCode 问题 2035](https://leetcode.com/problems/partition-array-into-two-arrays-to-minimize-sum-difference/)

 **难度：** 🔴难
 **主题：** 数组、两个指针、二分查找、动态规划、位操作、排序、有序集、位掩码

 ## 解决方案

 ## 问题理解

 问题给出了一个数组`nums`确切地包含`2 * n`整数。 我们必须将这些整数分为两个单独的组，每个组恰好包含`n`元素。 形成两组后，我们计算每组的总和并测量这些总和之间的绝对差。 

我们的目标是最小化这种绝对差异。 

更正式地说，如果这两个组是：

 - A 组总和`sumA`- B 组总和`sumB`那么我们要最小化：$$|sumA - sumB|$$一个重要的细节是两个组必须完全包含`n`元素。 这个限制阻止我们简单地贪婪地平衡总和。 

输入大小足够小，可以建议采用指数技术，但又足够大，无法对所有分区进行暴力破解。 

限制条件是：

 -`1 <= n <= 15`-`nums.length == 2 * n`这意味着最大数组长度仅为`30`，但是有多种可能的选择方式`15`元素来自`30`是：$$\binom{30}{15} \approx 155,117,520$$直接尝试每个分区会太慢。 

数组中的值也可能是负数，这意味着仅基于正和的技术（例如通过 sum 索引的经典子集和 DP）变得很困难，因为和的范围可以跨越很大的负值和正值。 

一些边缘情况很重要：

 - 包含负值的数组
 - 最佳差异为零的数组
 - 只有两个元素的数组
 - 所有值都相同的数组
 - 数组的一侧必须有意包含较大的正值和负值以平衡总数

 该问题保证有效分区始终存在，因为数组大小始终是偶数。 

## 方法

 ### 蛮力

 暴力解法尝试一切可能的方法来选择`n`元素来自于`2n`元素。 

对于每个选择：

 1. 计算所选子集的总和。 
2. 计算剩余元素的总和。 
3. 计算绝对差值。 
4. 跟踪最小值。 

这保证了正确性，因为每个有效分区都会被检查。 

然而，子集的数量是巨大的。 

可供选择的方式数量`n`元素来自`2n`是：$$\binom{2n}{n}$$为了`n = 15`，这有超过 1.55 亿种可能性。 

即使每个评估都非常快，迭代所有组合也会超出时间限制。 

### 关键见解

 关键的观察是`n <= 15`，这使得中间相遇策略变得可行。 

而不是处理所有`30`元素放在一起，我们将数组分成两半：

 - 左半尺寸`n`- 右半尺寸`n`然后我们独立地枚举每一半的子集和。 

对于每个子集，我们存储：

 - 选择了多少个元素
 - 结果总和

 之后，我们将左半部分和右半部分的子集组合起来，使得所选元素的总数等于`n`。 

这大大降低了复杂性，因为：

 - 每半场最多有`2^15 = 32768`子集
 - 枚举所有子集变得易于管理

 剩下的挑战是有效地找到互补的总和，以最小化最终的差异。 排序和二分搜索有效地解决了这个问题。

 ## 算法演练

 ### 第 1 步：计算总和

 首先计算：```
totalSum = sum(nums)
```如果一个分区有总和`chosenSum`，那么另一个分区的总和为：```
totalSum - chosenSum
```由此产生的差异变为：$$|chosenSum - (totalSum - chosenSum)|$$简化为：$$|2 \cdot chosenSum - totalSum|$$所以问题就变成了精确地找到一个子集`n`总和尽可能接近于的元素：$$\frac{totalSum}{2}$$### 步骤 2：将数组分成两半

 将数组分为：```
left = nums[:n]
right = nums[n:]
```每半部分恰好包含`n`元素。 

### 步骤 3：枚举每一半的所有子集和

 对于每个子集掩码`0`到`2^n - 1`:

 1. 计算有多少个元素被选中。 
2. 计算子集和。 

存储按子集大小分组的总和。 

结构示例：```
leftSums[k] = all subset sums using k elements
rightSums[k] = all subset sums using k elements
```这个组织很重要，因为最终的分区必须准确包含`n`元素总数。 

如果我们选择`k`左半部分的元素，那么我们必须选择`n-k`右半部分的元素。 

### 步骤 4：对右半部分和进行排序

 对于每个子集大小：```
rightSums[k].sort()
```排序允许稍后进行二分搜索。 

### 步骤 5：尝试每个左边的子集

 对于每个左子集总和：

 - 假设它使用`k`元素
 - 那么我们需要`n-k`右半部分的元素

 让：```
leftSum = current left subset sum
```选择的总和变为：```
leftSum + rightSum
```我们希望这个值尽可能接近：$$\frac{totalSum}{2}$$重新排列：```
target = totalSum / 2 - leftSum
```现在里面进行二分查找`rightSums[n-k]`找到最接近的值`target`。 

### 步骤 6：更新最小差异

 对于每位候选人：```
chosen = leftSum + rightSum
difference = abs(totalSum - 2 * chosen)
```更新全局最小值。 

### 为什么它有效

 该算法间接检查每个有效分区。 

原始数组的每个子集都可以表示为：

 - 左半部分的一些子集
 - 右半部分的一些子集

 通过根据子集大小对总和进行分组，我们保证最终的组合子集恰好包含`n`元素。 

二分搜索确保我们有效地找到最小化最终差异的互补子集和。 

由于考虑了每个有效分区并全局跟踪最小差异，因此该算法始终返回最佳答案。 

## Python 解决方案```python
from typing import List
from collections import defaultdict
import bisect

class Solution:
    def minimumDifference(self, nums: List[int]) -> int:
        n = len(nums) // 2
        
        left = nums[:n]
        right = nums[n:]
        
        left_sums = defaultdict(list)
        right_sums = defaultdict(list)
        
        # Generate all subset sums for left half
        for mask in range(1 << n):
            count = 0
            subset_sum = 0
            
            for i in range(n):
                if mask & (1 << i):
                    count += 1
                    subset_sum += left[i]
            
            left_sums[count].append(subset_sum)
        
        # Generate all subset sums for right half
        for mask in range(1 << n):
            count = 0
            subset_sum = 0
            
            for i in range(n):
                if mask & (1 << i):
                    count += 1
                    subset_sum += right[i]
            
            right_sums[count].append(subset_sum)
        
        # Sort right sums for binary search
        for count in right_sums:
            right_sums[count].sort()
        
        total_sum = sum(nums)
        answer = float("inf")
        
        # Combine left and right subsets
        for left_count in left_sums:
            right_count = n - left_count
            
            right_list = right_sums[right_count]
            
            for left_sum in left_sums[left_count]:
                target = total_sum / 2 - left_sum
                
                idx = bisect.bisect_left(right_list, target)
                
                # Check candidate at idx
                if idx < len(right_list):
                    chosen_sum = left_sum + right_list[idx]
                    diff = abs(total_sum - 2 * chosen_sum)
                    answer = min(answer, diff)
                
                # Check candidate before idx
                if idx > 0:
                    chosen_sum = left_sum + right_list[idx - 1]
                    diff = abs(total_sum - 2 * chosen_sum)
                    answer = min(answer, diff)
        
        return answer
```实施直接遵循中间相遇策略。 

该阵列被分成两半。 对于每一半，使用位掩码枚举每个可能的子集。 子集大小和子集总和同时计算。 

总和按子集大小分组，因为最终选择的子集必须准确包含`n`元素总数。 

生成子集和后，对右半列表进行排序。 这使得二分搜索能够找到最佳互补子集和。 

对于每个左子集总和，该算法从右侧计算理想目标值，这将使组合总和尽可能接近总数组总和的一半。 

二分搜索可以有效地识别最近的候选者。 由于精确最接近的值可能位于插入位置或紧邻其之前，因此会检查这两个位置。 

最小绝对差值在整个过程中不断更新。 

## 解决方案```go
package main

import (
	"math"
	"sort"
)

func minimumDifference(nums []int) int {
	n := len(nums) / 2

	left := nums[:n]
	right := nums[n:]

	leftSums := make([][]int, n+1)
	rightSums := make([][]int, n+1)

	// Generate subset sums for left half
	for mask := 0; mask < (1 << n); mask++ {
		count := 0
		sum := 0

		for i := 0; i < n; i++ {
			if mask&(1<<i) != 0 {
				count++
				sum += left[i]
			}
		}

		leftSums[count] = append(leftSums[count], sum)
	}

	// Generate subset sums for right half
	for mask := 0; mask < (1 << n); mask++ {
		count := 0
		sum := 0

		for i := 0; i < n; i++ {
			if mask&(1<<i) != 0 {
				count++
				sum += right[i]
			}
		}

		rightSums[count] = append(rightSums[count], sum)
	}

	// Sort right side sums
	for i := 0; i <= n; i++ {
		sort.Ints(rightSums[i])
	}

	totalSum := 0
	for _, num := range nums {
		totalSum += num
	}

	answer := math.MaxInt32

	for leftCount := 0; leftCount <= n; leftCount++ {
		rightCount := n - leftCount

		rightList := rightSums[rightCount]

		for _, leftSum := range leftSums[leftCount] {
			target := float64(totalSum)/2.0 - float64(leftSum)

			idx := sort.Search(len(rightList), func(i int) bool {
				return float64(rightList[i]) >= target
			})

			// Check idx
			if idx < len(rightList) {
				chosenSum := leftSum + rightList[idx]
				diff := abs(totalSum - 2*chosenSum)

				if diff < answer {
					answer = diff
				}
			}

			// Check idx - 1
			if idx > 0 {
				chosenSum := leftSum + rightList[idx-1]
				diff := abs(totalSum - 2*chosenSum)

				if diff < answer {
					answer = diff
				}
			}
		}
	}

	return answer
}

func abs(x int) int {
	if x < 0 {
		return -x
	}
	return x
}
```Go 的实现与 Python 版本非常相似。 

Go 不使用字典，而是使用切片的切片：```go
[][]int
```其中索引`k`准确地存储所有子集和`k`元素。 

二分查找是使用以下方法实现的`sort.Search`，它返回满足条件的第一个索引。 

Go 没有提供内置的整数绝对值函数，因此自定义`abs`包括助手。 

所有计算都安全地适合 32 位整数，因为最大可能的总和为：$$30 \times 10^7 = 3 \times 10^8$$它仍然在 Go 的整数范围内。

 ## 边缘情况

 ### 负数数组

 负数使得传统的子集和动态编程变得困难，因为和范围可能变得非常大并且包含负索引。 

例如：```
[-5, -2, 7, 10]
```按 sum 索引的简单 DP 需要偏移量处理和潜在的巨大内存。 

中间相遇方法完全避免了这种情况，因为它直接存储实际的子集总和而不是通过它们进行索引。 

### 完美平衡的分区

 有时最佳答案恰好为零。 

例子：```
[2,-1,0,4,-2,-9]
```两个分区的总和可以为`-3`。 

该实现正确地处理了这个问题，因为它搜索最接近的总和`totalSum / 2`。 如果存在完全匹配，二分查找会找到它并且答案为零。 

### 最小输入大小

 当`n = 1`，该数组仅包含两个元素。 

例子：```
[-36, 36]
```该算法仍然可以正确工作，因为每一半只包含一个元素，并且子集枚举自然地处理大小的子集`0`和`1`。 

无需特殊情况处理。 

### 大幅度值

 这些值可以大到：```
10^7
```最多有`30`数字。 

该实现避免了溢出问题，因为最大绝对总和为：$$30 \times 10^7 = 3 \times 10^8$$它安全地适合 Python 和 Go 中的标准整数范围。
