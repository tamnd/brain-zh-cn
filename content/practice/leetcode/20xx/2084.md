[LeetCode 问题 2084](https://leetcode.com/problems/drop-type-1-orders-for-customers-with-type-0-orders/)

 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 在这个问题中，我们有一个名为`Orders`。 每行代表一个订单并包含三列：

 -`order_id`, 订单的唯一标识符
 -`customer_id`, 下订单的客户
 -`order_type`，这是`0`或者`1`任务是根据特定业务规则返回表的过滤版本：

 - 如果客户至少有一个订单`order_type = 0`，然后该客户的所有订单`order_type = 1`必须排除。 
- 如果客户没有任何类型`0`订单，那么他们的所有订单都应该包括在内。 

重要的细节是过滤决策是根据客户而不是单独的订单做出的。 我们首先判断客户是否有任何类型`0`订单，然后决定保留哪些行。 

输出可以按任何顺序返回，这意味着我们不需要`ORDER BY`除非我们为了可读性而需要一个子句。 

输入表可能包含每个客户的多个订单，并且客户可以有：

 - 仅类型`0`订单
 - 仅类型`1`订单
 - 两者的混合

 约束没有明确说明，但这是一个标准的 SQL 过滤问题，效率仍然很重要。 对于大型数据集来说，重复扫描表中每一行的简单解决方案可能会变得昂贵。 目标是识别客户类型`0`有效地排序，然后根据该信息过滤行。 

一些边缘情况很重要：

 - 仅有类型的客户`1`订单应包含所有行。 
- 具有两种类型的客户`0`并输入`1`订单应该只保留类型`0`行。 
- 具有多种类型的客户`0`订单应保留所有这些。 
- 无论订单类型如何，只有一个订单的客户仍应得到正确处理。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是单独检查每个订单并确定同一客户是否有任何类型`0`订单。 

对于表中的每一行：

 1. 再次扫描整个表。 
2. 检查是否存在其他相同的行`customer_id`和`order_type = 0`。 
3. 如果存在这样一行：

 - 仅保留当前行`order_type`是`0`4. 否则：

 - 无论类型如何都保留行

 这种方法是正确的，因为每一行都独立验证其客户是否属于“具有类型 0 订单”类别。 

但是，性能很差，因为每一行都可能需要对表进行另一次完整扫描。 如果有`n`行，这导致`O(n²)`工作。 

### 最佳方法

 关键的观察是重要的信息是客户是否至少有一种类型`0`命令。 

我们可以使用子查询或公用表表达式计算一次，而不是重复搜索此信息。 

最优策略是：

 1. 识别所有至少具有一种类型的客户`0`命令。 
2. 保留：

 - 所有类型`0`行
 - 类型`1`仅适用于不属于该组的客户的行

 这将重复的查找转换为单个预处理步骤。 SQL 使用以下方法有效地处理这个问题`IN`,`NOT IN`,`EXISTS`，或加入。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 重复扫描表中的每一行 |
 | 最佳 | O(n) | O(n) | 预先计算客户的类型`0`订单|

 ## 算法演练

 ### 最优 SQL 算法

 1. 首先，确定所有至少有一个订单类型的客户`0`。 

我们可以使用子查询来做到这一点：```sql
SELECT customer_id
FROM Orders
WHERE order_type = 0
```这将创建一组客户，其类型`1`必须删除订单。 
2. 接下来，扫描所有行`Orders`桌子。 

对于每一行，我们决定是否保留它。 
3. 如果该行有`order_type = 0`，永远保留它。 

问题陈述明确指出了该类型`0`订单必须保留。 
4. 如果该行有`order_type = 1`，仅当客户不在具有类型的客户集中时才保留它`0`订单。 

这可以确保具有混合订单类型的客户丢失其类型`1`行。 
5. 返回过滤后的行。 

由于结果可以按任何顺序返回，因此不需要排序。 

### 为什么它有效

 该算法之所以有效，是因为每个客户都属于以下两类之一：

 - 至少具有一种类型的客户`0`订单
 - 没有任何类型的客户`0`订单

 对于第一类，只需键入`0`行有效。 对于第二类，所有行均有效。 过滤条件与这些规则完全匹配，因此每个保留的行都是正确的，而每个删除的行都是无效的。 

## Python 解决方案

 尽管这是一个数据库问题，但以下 Python 实现以编程方式演示了等效逻辑。```python
from typing import List

class Solution:
    def filterOrders(self, orders: List[List[int]]) -> List[List[int]]:
        customers_with_type_zero = set()

        for order_id, customer_id, order_type in orders:
            if order_type == 0:
                customers_with_type_zero.add(customer_id)

        result = []

        for order_id, customer_id, order_type in orders:
            if order_type == 0:
                result.append([order_id, customer_id, order_type])
            elif customer_id not in customers_with_type_zero:
                result.append([order_id, customer_id, order_type])

        return result
```实现直接遵循最优算法。 

第一个循环标识至少具有一种类型的所有客户`0`命令。 一条蟒蛇`set`使用是因为成员资格检查非常快，通常`O(1)`。 

第二个循环构建最终答案。 如果订单类型为`0`，它始终包含在内。 如果订单类型为`1`，仅当客户未出现在集合中时才包含在内。 

这准确地反映了 SQL 过滤逻辑。 

## 解决方案```go
package main

type Solution struct{}

func (s Solution) FilterOrders(orders [][]int) [][]int {
	customersWithTypeZero := make(map[int]bool)

	for _, order := range orders {
		customerID := order[1]
		orderType := order[2]

		if orderType == 0 {
			customersWithTypeZero[customerID] = true
		}
	}

	result := [][]int{}

	for _, order := range orders {
		customerID := order[1]
		orderType := order[2]

		if orderType == 0 {
			result = append(result, order)
		} else if !customersWithTypeZero[customerID] {
			result = append(result, order)
		}
	}

	return result
}
```Go 实现遵循与 Python 版本相同的两遍策略。 

一个`map[int]bool`用于存储有类型的客户`0`订单。 Go 映射提供类似于 Python 集的高效查找性能。 

切片用于存储结果。 由于 Go 没有 Python 风格的动态列表，`append`用于在找到有效订单时增加切片。 

这里不存在整数溢出问题，因为操作仅涉及比较和查找。 

## SQL 解决方案```sql
SELECT *
FROM Orders
WHERE order_type = 0
   OR customer_id NOT IN (
       SELECT customer_id
       FROM Orders
       WHERE order_type = 0
   );
```该查询的工作原理是保留：

 - 每行在哪里`order_type = 0`- 属于从未出现在子查询结果中的客户的行

 子查询标识至少具有一种类型的所有客户`0`命令。

 ## 边缘情况

 ### 仅类型的客户`1`订单

 一个常见的错误是意外删除所有类型`1`全局行。 过滤规则仅适用于同时具有以下类型的客户`0`订单。 

例如：```
(31, 4, 1)
(32, 4, 1)
```顾客`4`没有类型`0`订单，因此两行都必须保留。 该实现正确处理了这个问题，因为客户`4`从不进入`customers_with_type_zero`放。 

### 具有两种订单类型的客户

 这是问题的核心边缘情况。 

例如：```
(11, 2, 0)
(12, 2, 1)
```曾经的客户`2`被识别为具有类型`0`订单，每种类型`1`必须排除该客户的订单。 该实现正确地仅删除了类型`1`行同时保留类型`0`。 

### 多种类型`0`订单

 一个客户可能有多种类型`0`订单：```
(1,1,0)
(2,1,0)
```如果将问题视为重复数据删除，则有错误的实现可能会意外地只保留其中一个。 但是，该问题需要返回所有有效行。 由于该算法单独过滤行并且不会折叠重复项，因此每种类型`0`行被保留。 

### 清空输入表

 尽管约束中未显示，但稳健的解决方案应该优雅地处理空表。 

如果输入不包含任何行，则集合保持为空，结果列表也保持为空。 该算法自然会返回空结果，无需特殊处理。
