[LeetCode 问题 2048](https://leetcode.com/problems/next-greater-numerically-balanced-number/)

 **难度：** 🟡 中等
 **主题：** 哈希表、数学、回溯、计数、枚举

 ## 解决方案

 ## 问题理解

 该问题要求我们找到严格大于的最小整数`n`使得数量在数量上是平衡的。 

当数字中出现的每个数字与其值出现的次数完全相同时，该数字在数字上是平衡的。 例如：

-`22`是平衡的，因为数字`2`准确地出现`2`次。 
-`1333`是平衡的，因为：

 - 数字`1`出现一次
 - 数字`3`出现三次
 -`122`不平衡，因为数字`1`出现一次，这是正确的，但是数字`2`只出现两次，这也是正确的，所以实际上`122`是平衡的。 
-`1022`不平衡，因为数字`0`出现一次，但平衡数需要数字`0`出现零次。 

输入由单个整数组成`n`，并且我们必须返回严格大于它的最小平衡数。 

约束条件是：```
0 <= n <= 10^6
```这个上限相对较小。 由于数字平衡的数字很少见，这强烈表明我们可以：

 1. 枚举数字并测试它们
 2. 提前生成所有有效平衡数

 一个重要的观察是，在此约束下平衡数不能任意大。 自从`n <= 10^6`，答案也将仍然相当小。 

一些边缘情况很重要：

 -`n = 0`，最小的答案是`1`- 包含零的数字永远无法平衡，除非零出现零次
 - 数字重复且与位数不匹配的号码必须被拒绝
 - 答案必须严格大于`n`，不大于或等于
 - 非常接近上限的值仍然具有较小的有效答案空间

 ## 方法

 ### 蛮力方法

 最直接的方法就是从`n + 1`并逐一测试每个数字，直到找到一个数字平衡的数字。 

对于每个候选人编号：

 1. 统计每个数字出现的次数
 2. 验证每个数字`d`准确地出现`d`次
 3. 如果有效，返回号码

 这种方法是正确的，因为它按升序检查每个整数，因此遇到的第一个有效数字必须是最小的有效答案。 

然而，该解决方案效率低下，因为许多数字被不必要地检查。 即使约束只是`10^6`，对许多候选人重复执行数字计数仍然可能是一种浪费。 

### 最佳方法

 关键的见解是，数量上平衡的数字极其罕见。 

平衡数完全由它所包含的数字决定。 例如：

 - 如果是数字`2`存在，它必须恰好出现两次
 - 如果是数字`5`存在，它必须恰好出现五次

 这意味着可能的平衡数总数非常小。 

我们可以：

 1. 使用回溯生成所有可能的数值平衡数
 2. 将它们存储在列表中
 3. 对列表进行排序
 4. 找到大于的最小数`n`由于搜索空间很小，因此这种方法更快、更干净。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(k * d) | O(d) | 检查之后的每个数字`n`， 在哪里`d`是位数 |
 | 最佳| O(M log M) 预处理 + O(M) 查询 | O(M)| 仅生成有效的平衡数 |

 这里：

-`k`是检查的候选人数量
 -`d`是位数
 -`M`是平衡数的总数，这个数很小

 ## 算法演练

 ### 第 1 步：生成有效数字集

 平衡数只能包含数字`1`通过`9`。 

对于包含的每个数字：

 - 数字`d`必须准确出现`d`次

 示例：

 - 选择数字`2`贡献`"22"`- 选择数字`1`和`3`贡献`"1333"`我们使用回溯来尝试所有数字子集。 

### 步骤 2：构建数字多重集

 对于每个选定的数字组合：

 - 附加数字`d`确切地`d`次

 示例：```
Digits chosen: [1, 3]
Constructed multiset: "1333"
```### 步骤 3：生成所有独特的排列

 数字的排列很重要。 

例如：```
1333
3133
3313
3331
```都是不同的平衡数。 

我们使用回溯生成所有独特的排列。 

### 步骤 4：将排列转换为整数

 每个排列都会转换为整数并添加到结果集中。 

使用集合可以防止重复。 

### 步骤 5：对所有平衡数字进行排序

 生成完成后：

 - 将集合转换为排序列表

 这允许有效地查找下一个更大的数字。 

### 步骤 6：找到大于的最小数`n`遍历已排序的列表并返回第一个大于的值`n`。 

由于列表是有序的，这保证了最小的有效答案。 

### 为什么它有效

 该算法之所以有效，是因为每个数值平衡的数字都必须满足严格的频率规则：```
digit d appears exactly d times
```回溯过程系统地生成每种可能的有效数字组合以及这些数字的每种排列。 由于所有平衡的数字都包含在内并且最终列表已排序，因此第一个大于的数字`n`保证是正确答案。 

## Python 解决方案```python
class Solution:
    def nextBeautifulNumber(self, n: int) -> int:
        balanced_numbers = set()

        def generate_digit_sets(start_digit, current_digits):
            if current_digits:
                chars = []

                for digit in current_digits:
                    chars.extend([str(digit)] * digit)

                used = [False] * len(chars)

                def generate_permutations(path):
                    if len(path) == len(chars):
                        balanced_numbers.add(int("".join(path)))
                        return

                    seen = set()

                    for i in range(len(chars)):
                        if used[i]:
                            continue

                        if chars[i] in seen:
                            continue

                        seen.add(chars[i])

                        used[i] = True
                        path.append(chars[i])

                        generate_permutations(path)

                        path.pop()
                        used[i] = False

                generate_permutations([])

            for digit in range(start_digit, 8):
                current_digits.append(digit)
                generate_digit_sets(digit + 1, current_digits)
                current_digits.pop()

        generate_digit_sets(1, [])

        sorted_numbers = sorted(balanced_numbers)

        for number in sorted_numbers:
            if number > n:
                return number

        return -1
```该解决方案首先使用递归回溯生成所有平衡数。 

这`generate_digit_sets`函数决定平衡数中将出现哪些数字。 如果数字`d`被选择，它必须准确地出现`d`次。 

构造数字多重集后，算法生成所有唯一的排列。 这`seen`set 可以防止由重复数字引起的重复排列。 

每个有效排列都被转换为整数并插入到`balanced_numbers`。 

一旦生成完成，集合就会被排序。 然后该算法扫描排序列表并返回严格大于的第一个值`n`。 

由于平衡数总数较少，预处理效率较高。 

## 解决方案```go
package main

import (
	"sort"
	"strconv"
)

func nextBeautifulNumber(n int) int {
	balancedNumbers := map[int]bool{}

	var generateDigitSets func(int, []int)

	generateDigitSets = func(startDigit int, currentDigits []int) {
		if len(currentDigits) > 0 {
			chars := []byte{}

			for _, digit := range currentDigits {
				for i := 0; i < digit; i++ {
					chars = append(chars, byte('0'+digit))
				}
			}

			used := make([]bool, len(chars))

			var generatePermutations func([]byte)

			generatePermutations = func(path []byte) {
				if len(path) == len(chars) {
					value, _ := strconv.Atoi(string(path))
					balancedNumbers[value] = true
					return
				}

				seen := map[byte]bool{}

				for i := 0; i < len(chars); i++ {
					if used[i] {
						continue
					}

					if seen[chars[i]] {
						continue
					}

					seen[chars[i]] = true

					used[i] = true
					path = append(path, chars[i])

					generatePermutations(path)

					path = path[:len(path)-1]
					used[i] = false
				}
			}

			generatePermutations([]byte{})
		}

		for digit := startDigit; digit <= 7; digit++ {
			currentDigits = append(currentDigits, digit)

			generateDigitSets(digit+1, currentDigits)

			currentDigits = currentDigits[:len(currentDigits)-1]
		}
	}

	generateDigitSets(1, []int{})

	numbers := []int{}

	for value := range balancedNumbers {
		numbers = append(numbers, value)
	}

	sort.Ints(numbers)

	for _, value := range numbers {
		if value > n {
			return value
		}
	}

	return -1
}
```Go 实现遵循与 Python 版本相同的递归结构。 

一个`map[int]bool`使用而不是 Python 集。 字节切片用于在排列生成期间进行有效的字符操作。 

由于 Go 不提供内置的排列助手，因此递归回溯是手动实现的。 在回溯期间仔细处理切片大小调整以正确恢复状态。 

整数溢出不是问题，因为所有生成的数字都保持在 Go 的整数范围内。

 ## 边缘情况

 一个重要的边缘情况是当`n = 0`。 自从`1`本身在数字上是平衡的，因为数字`1`只出现一次，正确答案是`1`。 有缺陷的实现可能会错误地跳过单位数平衡数字。 

另一个棘手的情况是输入本身已经平衡。 例如：```
n = 22
```答案不能是`22`因为这个问题需要严格更大的值。 该实现通过扫描第一个满足以下条件的数字来正确处理此问题：```
number > n
```而不是`>=`。 

第三个重要的边缘情况涉及零。 任何包含数字的数字`0`除非零恰好出现零次，否则无效，而一旦它存在于数字中，这是不可能的。 例如：```
1022
```不平衡，因为数字`0`出现一次。 生成方法自然避免了这个问题，因为数字`0`施工期间从不包括在内。 

另一个微妙的情况是重复排列。 例如，多重集：```
3331
```包含重复的数字。 如果没有重复预防，排列回溯将重复产生许多相同的排列。 这`seen`设置在排列递归内部可以防止重复工作并确保效率。
