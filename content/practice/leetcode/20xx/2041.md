 **难度：** 🟡 中等
 **主题：** 数据库

 ## 解决方案

 ## 问题理解

 该问题给了我们两个数据库表，`Candidates`和`Rounds`，共同描述求职者的面试表现。 

这`Candidates`表中每个候选者包含一行。 每行包括候选人的唯一 ID、姓名、经验年限以及与该候选人相关的面试 ID。 

这`Rounds`表包含个人面试轮次的分数。 每次面试可以有多轮，每行存储特定面试的一轮分数。 

目标是返回`candidate_id`满足这两个条件的候选人的价值观：

 1.他们至少有`2`多年的经验。 
2. 各轮面试的所有分数总和严格大于`15`。 

这意味着我们必须结合两个表中的信息。 这`Candidates`表告诉我们候选人是谁以及他们有多少年的经验，而`Rounds`表格告诉我们他们在面试过程中的表现如何。 

重要的关系是：

 -`Candidates.interview_id = Rounds.interview_id`对于每个候选人，我们需要计算属于其面试的所有面试轮次的总分，然后根据经验要求和分数要求筛选候选人。 

输出应仅包含一列：```
candidate_id
```结果可以按任何顺序返回。 

该问题保证：

 -`candidate_id`是独一无二的`Candidates`。 
-`(interview_id, round_id)`是独一无二的`Rounds`。 

这意味着同一轮面试组合不会有重复的轮次条目。 

一个重要的边缘情况是当候选人有足够的经验但他们的总分恰好是`15`。 由于条件是“严格大于15”，因此此类候选人不得包括在内。 

另一个重要的情况是，当候选人的面试分数很高但低于`2`多年的经验。 他们也必须被排除在外。 

我们还需要正确处理多轮面试，因为总分是各轮面试的总分。 

## 方法

 ### 蛮力方法

 一种直接的方法是逐一处理每个候选并重复扫描`Rounds`表来计算该候选人的面试总分数。 

对于每位候选人：

 1. 检查是否`years_of_exp >= 2`。 
2. 如果是，则迭代整个`Rounds`桌子。 
3. 将所有分数相加`interview_id`与候选人的面试相符。 
4. 如果总分大于`15`，将候选人包含在结果中。 

这种方法是正确的，因为它明确计算每个候选人所需的总分并直接应用过滤条件。 

然而，它的效率很低，因为`Rounds`为每个候选人重复扫描表。 如果有`N`候选人和`M`循环记录，总工作量变为`O(N × M)`。 

对于大型数据集，重复重新扫描圆桌的成本是不必要的。 

### 最佳方法

 关键的观察结果是，许多考生可能需要访问分数，因此反复重新计算总数是浪费的。 

相反，我们应该使用 SQL 聚合函数聚合一次面试分数。 

我们可以：

 1. 加入`Candidates`和`Rounds`使用`interview_id`。 
2. 按候选对行进行分组。 
3. 使用以下方法计算每个候选人的分数总和`SUM(score)`。 
4. 使用以下方法筛选候选人：

 -`years_of_exp >= 2`-`SUM(score) > 15`这种方法非常高效，因为在聚合期间每行仅处理一次。 

在 SQL 中，聚合和过滤正是这样的`GROUP BY`和`HAVING`设计用于。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(N × M) | O(1) | O(1) | 反复扫描圆桌以查找每位候选人 |
 | 最佳| O(N + M) | O(N) | 使用聚合来计算面试总数一次 |

 ## 算法演练

 1. 首先加入`Candidates`表与`Rounds`使用共享表`interview_id`柱子。 这使我们能够访问同一中间数据集中的候选信息和回合分数。 
2. 按候选对连接的行进行分组。 由于每个候选人可能有多轮面试，分组允许我们汇总属于同一候选人的所有分数。 
3. 使用以下方法计算每位候选人的面试总分`SUM(score)`。 这给出了所有面试轮次的综合分数。 
4. 应用经验过滤器，仅保留具有以下特征的候选人`years_of_exp`至少是`2`。 
5. 使用分数过滤器应用`HAVING`子句仅保留总分严格大于的组`15`。 
6. 返回`candidate_id`筛选结果中的列。 

### 为什么它有效

 该算法之所以有效，是因为按候选人分组可确保在计算总分之前将属于同一面试的每一轮面试收集在一起。 这`SUM(score)`运算正确计算出综合面试成绩，过滤条件直接执行问题陈述中的要求。 

## Python 解决方案```python
# Write your MySQL query statement below

SELECT c.candidate_id
FROM Candidates c
JOIN Rounds r
ON c.interview_id = r.interview_id
WHERE c.years_of_exp >= 2
GROUP BY c.candidate_id
HAVING SUM(r.score) > 15;
```该解决方案首先连接两个表`interview_id`，它将每位候选人与其所有面试轮次联系起来。 

这`WHERE`子句过滤掉在聚合发生之前没有至少两年经验的候选人。 这减少了不必要的处理。 

下一个，`GROUP BY c.candidate_id`将属于同一候选者的所有轮行收集到一组中。 

这`HAVING`然后使用子句根据聚合总分来过滤组。 我们使用`HAVING`而不是`WHERE`因为聚合函数如`SUM()`分组后进行评价。 

最后，查询仅返回`candidate_id`满足这两个条件的值。 

## 解决方案```go

 ## 边缘情况

 一个重要的边缘情况是候选人的面试总分恰好是`15`。 由于要求规定分数必须严格大于`15`，候选人总共正好`15`不得出现在输出中。 使用`HAVING SUM(score) > 15`正确执行此规则。 

另一个重要的情况是候选人面试表现出色但经验不足。 例如，某候选人的总分为`30`但仅`1`仍必须排除一年的经验。 这`WHERE c.years_of_exp >= 2`条件确保这些候选者在分组之前被过滤掉。 

第三种边缘情况涉及多轮面试。 幼稚的实现可能会意外地只考虑一轮得分，而不是对所有轮次进行求和。 按候选人分组并使用`SUM(score)`保证每一轮都正确地贡献于最终总数。
