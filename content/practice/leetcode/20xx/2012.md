[LeetCode 2012 问题](https://leetcode.com/problems/sum-of-beauty-in-the-array/)

 **难度：** 🟡 中等
 **主题：** 数组

 ## 解决方案

 ## 问题理解

 该问题要求我们计算数组中每个元素的“美观”分数`nums`，不包括第一个和最后一个元素。 具体来说，对于每个索引`i`在范围内`1 <= i <= nums.length - 2`，之美`nums[i]`由两个条件决定：

 1. **美女2：**`nums[i]`严格大于其左侧的每个元素并严格小于其右侧的每个元素。 
2. **美女1：** 如果上述条件不成立，但是`nums[i]`大于紧邻的左邻居并小于紧邻的右邻居。 
3. **美丽 0：** 如果两个条件都不成立。 

最终结果是所有这些美丽分数的总和。 

输入是一个至少包含 3 个元素的整数数组，每个元素介于 1 到 100,000 之间。 输出是一个代表总体美感的整数。 问题约束表明，将每个元素与左右所有其他元素进行比较的强力方法可能会太慢，特别是对于大小高达`10^5`。 

要考虑的边缘情况包括严格递增或递减数组、所有元素都相等的数组以及仅第一个或最后一个元素为极值的数组。 该问题保证至少三个元素，因此我们不必处理空数组或单元素数组。 

## 方法

 蛮力方法涉及迭代每个有效索引`i`检查左右每个元素，看看是否满足 beauty-2 条件。 如果没有，我们检查直接邻居的 beauty-1。 虽然正确，但效率低下，因为它需要潜在的检查`O(n)`每个索引两侧的元素`i`，给出总体`O(n^2)`时间复杂度。 

最佳解决方案的关键在于，我们可以预先计算数组来存储每个索引的**左侧最大元素**和**右侧最小元素**。 这允许对 beauty-2 条件进行恒定时间检查。 检查近邻的 beauty-1 已经`O(1)`。 使用这种方法可以将时间复杂度降低到`O(n)`。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n^2) | O(n^2) | O(1) | O(1) | 将每个元素与左侧和右侧的所有元素进行比较 |
 | 最佳 | O(n) | O(n) | 预先计算左最大和右最小数组以进行恒定时间检查 |

 ## 算法演练

 1.初始化两个数组，`left_max`和`right_min`, 两者的长度`n`。`left_max[i]`将存储索引左侧所有元素中的最大值`i`， 和`right_min[i]`将存储索引右侧所有元素中的最小值`i`。 
2. 填充`left_max`通过从左到右迭代，更新`left_max[i] = max(left_max[i - 1], nums[i - 1])`。 这确保了`left_max[i]`始终保留索引之前的最大值`i`。 
3. 填充`right_min`通过从右向左迭代，更新`right_min[i] = min(right_min[i + 1], nums[i + 1])`。 这确保了`right_min[i]`始终保留索引后的最小值`i`。 
4. 初始化变量`total_beauty = 0`。 
5. 迭代所有索引`i`从`1`到`n - 2`。 对于每个`i`、查看美容条件：

 - 如果`left_max[i] < nums[i] < right_min[i]`, 增量`total_beauty`2.
 - 否则如果`nums[i - 1] < nums[i] < nums[i + 1]`, 增量`total_beauty`1.
 6. 返回`total_beauty`。 

**为什么有效：** 预先计算 left-max 和 right-min 数组可确保我们在恒定时间内了解索引两侧的极值，从而使我们能够有效地检查 beauty-2 条件。 beauty-1 条件直接与直接邻居进行检查，因此算法可以正确计算美度分数的总和。 

## Python 解决方案```python
from typing import List

class Solution:
    def sumOfBeauties(self, nums: List[int]) -> int:
        n = len(nums)
        if n < 3:
            return 0

        left_max = [0] * n
        right_min = [0] * n

        left_max[0] = float('-inf')
        for i in range(1, n):
            left_max[i] = max(left_max[i - 1], nums[i - 1])

        right_min[-1] = float('inf')
        for i in range(n - 2, -1, -1):
            right_min[i] = min(right_min[i + 1], nums[i + 1])

        total_beauty = 0
        for i in range(1, n - 1):
            if left_max[i] < nums[i] < right_min[i]:
                total_beauty += 2
            elif nums[i - 1] < nums[i] < nums[i + 1]:
                total_beauty += 1

        return total_beauty
```**实现说明：**我们首先计算`left_max`和`right_min`数组来存储预先计算的极值，然后迭代数组检查两个美丽条件。 使用`float('-inf')`和`float('inf')`在边缘避免索引错误。 数组上的迭代会累积总的美观分数。 

## 解决方案```go
func sumOfBeauties(nums []int) int {
    n := len(nums)
    if n < 3 {
        return 0
    }

    leftMax := make([]int, n)
    rightMin := make([]int, n)

    leftMax[0] = -1 << 31
    for i := 1; i < n; i++ {
        if nums[i-1] > leftMax[i-1] {
            leftMax[i] = nums[i-1]
        } else {
            leftMax[i] = leftMax[i-1]
        }
    }

    rightMin[n-1] = 1 << 31 - 1
    for i := n - 2; i >= 0; i-- {
        if nums[i+1] < rightMin[i+1] {
            rightMin[i] = nums[i+1]
        } else {
            rightMin[i] = rightMin[i+1]
        }
    }

    totalBeauty := 0
    for i := 1; i < n-1; i++ {
        if leftMax[i] < nums[i] && nums[i] < rightMin[i] {
            totalBeauty += 2
        } else if nums[i-1] < nums[i] && nums[i] < nums[i+1] {
            totalBeauty += 1
        }
    }

    return totalBeauty
}
```**Go 特定注释：** Go 使用切片而不是列表。 整数边界设置使用`-1 << 31`对于负无穷大和`1 << 31 - 1`为正无穷大。 循环和条件逻辑遵循标准 Go 语法。 

## 工作示例

 **示例1：**`nums = [1,2,3]`-`left_max = [-inf, 1, 2]`-`right_min = [2, 3, inf]`- 索引 1：`left_max[1] = 1 < 2 < 3 = right_min[1]`→ 美丽=2
 - 总美丽=2

 **示例2：**`nums = [2,4,6,4]`-`left_max = [-inf, 2, 4, 6]`-`right_min = [4, 4, 4, inf]`- 索引 1：`left_max[1] = 2 < 4 < 4 = right_min[1]`→ 失败，检查邻居：`2 < 4 < 6`→ 美丽=1
 - 索引 2：`left_max[2] = 4 < 6 < 4 = right_min[2]`→ 失败，检查邻居：`4 < 6 < 4`→ 失败 → 美丽 = 0
 - 总美丽=1

 **示例3：**`nums = [3,2,1]`-`left_max = [-inf, 3, 3]`-`right_min = [2, 1, inf]`- 索引 1：`3 < 2 < 1`→ 假，`3 < 2 < 1`→ 假
 - 总美丽= 0

 ## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | ---| ---| ---|
 | 时间 | O(n) | 在 left_max、right_min 计算和美感求和过程中，每个元素都会被访问固定次数 |
 | 空间| O(n) | 附加阵列`left_max`和`right_min`大小为 n |

 由于预先计算的数组，空间复杂度是线性的，但时间复杂度是线性的，因为每个数组仅遍历一次。
