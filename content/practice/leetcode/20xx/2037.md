[LeetCode 2037 题](https://leetcode.com/problems/minimum-number-of-moves-to-seat-everyone/)

 **难度：** 🟢简单
 **主题：** 数组、贪婪、排序、计数排序

 ## 解决方案

 ## 问题理解

 该问题要求我们为学生分配座位，使得每个学生恰好占据一个座位，并且没有两个学生共用同一个座位。 每个学生都可以在数轴上向左或向右移动，每移动一个位置就花费一次移动。 目标是尽量减少让每个人就座所需的移动总数。 

输入由两个整数数组组成：

 -`seats`， 在哪里`seats[i]`代表的位置`i-th`座位。 
-`students`， 在哪里`students[j]`代表的位置`j-th`学生。 

两个数组的长度相同`n`，这意味着学生数量与座位数量完全相同。 由于每个座位最终都必须被占用，并且每个学生都必须坐在某个地方，因此问题就变成了找到学生和座位之间的最佳分配以最小化总移动成本。 

预期输出是一个整数，表示每个学生占据唯一座位所需的最小移动总数。 

限制相对较小：

 -`1 <= n <= 100`-`1 <= seats[i], students[j] <= 100`这些限制告诉我们两件重要的事情。 首先，元素的数量很少，这意味着即使是效率较低的方法在实践中仍然可以发挥作用。 其次，位置限制在`1`和`100`，这暗示计数排序等技术也可能是可行的。 

问题的一个重要方面是多个座位或多个学生可能从同一位置开始。 例如，位置可能有两个座位`2`或多个学生站在一起。 假设独特位置的幼稚实现可能会失败。 幸运的是，该问题保证学生人数等于座位数，因此有效的作业始终存在。 

一些边缘情况值得预先考虑。 如果所有学生都已就座，则答案应为`0`。 必须正确处理座位或学生的重复位置。 在所有学生都远离座位的情况下，仍然应该有效地计算最小值。 由于位置总是正且小，所以我们不需要担心负坐标或溢出问题。 

## 方法

 ### 蛮力方法

 蛮力方法会尝试将学生分配到座位的所有可能的分配方式，并计算每种安排的总移动成本。 由于每个学生都可能坐在任何座位上，这成为一个排列问题。 

对于每个座位分配排列，我们计算：$$\sum |student_i - assignedSeat_i|$$然后我们返回所有可能分配中的最小值。 

这种方法保证是正确的，因为它详尽地检查每个有效配对并选择总移动成本最小的配对。 

然而，缺点是性能。 有`n!`可能的任务。 即使对于中等值`n`，阶乘增长变得不可行。 和`n = 100`，这种做法是完全不可能的。 

### 最优贪心法

 关键的见解是，当我们对数组进行排序并对相应元素进行配对时，可以实现最小的移动成本。 

为什么排序有帮助？ 

想象一下座位和学生沿着数轴排列。 如果我们以任意顺序将学生和座位配对，路径可能会交叉，从而产生不必要的移动。 例如：```
Seats:     [1, 5]
Students:  [4, 2]
```如果我们分配：```
4 → 1
2 → 5
```总成本变为：```
|4 - 1| + |2 - 5| = 3 + 3 = 6
```但排序后：```
Seats:     [1, 5]
Students:  [2, 4]
```我们配对：```
2 → 1
4 → 5
```给予：```
|2 - 1| + |4 - 5| = 1 + 1 = 2
```排序将附近的学生与附近的座位对齐，防止低效的交叉作业。 

由于排序在运行时占据主导地位，因此该解决方案运行效率很高。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n!) | O(n) | 尝试每一种可能的学生座位分配 |
 | 最佳| O(n log n) | O(n log n) | O(1) 或 O(n) | 对两个数组进行排序并配对相应的位置 |

 ## 算法演练

 1. 排序`seats`数组按升序排列。 

排序确保座位按从左到右的顺序进行处理。 附近的座位变得相邻，这有助于构建最佳分配。 
2. 排序`students`数组按升序排列。 

这会将学生按照与座位相同的顺序从左到右对齐。 
3. 初始化变量`total_moves`到`0`。 

该变量累计所需的移动总数。 
4. 同时迭代两个数组。 

由于两个数组均已排序且长度相等，因此将索引处的学生配对`i`座位位于索引处`i`。 
5. 计算每对的移动成本。 

对于每个索引：```
abs(seats[i] - students[i])
```将此值添加到`total_moves`。 
6. 返回`total_moves`。 

处理完每个学生座位对后，累加的总和代表最小的总移动成本。 

### 为什么它有效

 正确性来自于数轴上的贪婪匹配属性。 排序后，匹配`i-th`最小的学生`i-th`最小的座位可以避免交叉分配。 任何交叉分配都可以交换以减少或维持总成本，而不会增加它。 因此，排序匹配总是产生最优的最小成本排列。 

## Python 解决方案```python
from typing import List

class Solution:
    def minMovesToSeat(self, seats: List[int], students: List[int]) -> int:
        seats.sort()
        students.sort()

        total_moves = 0

        for seat_position, student_position in zip(seats, students):
            total_moves += abs(seat_position - student_position)

        return total_moves
```实现完全遵循算法。 

首先，两个数组都按升序排序。 这一步至关重要，因为它确保附近的学生与附近的座位相匹配。 

下一个，`total_moves`被初始化以存储移动成本的运行总和。 

这`zip()`函数用于同时迭代两个已排序的数组。 在每次迭代中，我们计算学生位置和座位位置之间的绝对差。 该值表示该学生所需的移动次数。 

最后，将累积结果作为所需的最小移动次数返回。 

## 解决方案```go
package main

import "sort"

func minMovesToSeat(seats []int, students []int) int {
	sort.Ints(seats)
	sort.Ints(students)

	totalMoves := 0

	for i := 0; i < len(seats); i++ {
		diff := seats[i] - students[i]

		if diff < 0 {
			diff = -diff
		}

		totalMoves += diff
	}

	return totalMoves
}
```Go 的实现与 Python 方法非常相似。 主要区别在于排序，它使用`sort.Ints()`。 

Go 不提供内置的`abs()`函数用于整数，因此我们通过检查差值是否为负来手动计算绝对值。 

由于约束非常小并且值的边界为`100`，整数溢出不是问题。 空切片也是自然处理的，尽管该问题保证至少一个座位和一名学生。

 ## 边缘情况

 当所有学生都已就座时，就会出现一种重要的边缘情况。 例如：```
seats = [1,2,3]
students = [1,2,3]
```有缺陷的实施可能会不必要地重新安排任务并增加移动成本。 排序保留了自然对齐，并且每个绝对差值都变为零。 

另一个重要的情况是重复的座位位置或重复的学生位置。 例如：```
seats = [2,2,6,6]
students = [1,3,2,6]
```某些实现错误地假定唯一值，并且可能会覆盖分配或使用无效的匹配逻辑。 由于该算法仅依赖于排序顺序，因此自然会处理重复项，无需任何特殊逻辑。 

第三个重要的边缘情况涉及高度不平衡的距离：```
seats = [100]
students = [1]
```答案很简单，就是绝对差异，`99`。 由于移动成本基于距离，因此该实现可以通过使用正确处理大间隙`abs(seat - student)`。 

最后，未排序的输入很容易导致幼稚的实现失败。 考虑：```
seats = [10,1]
students = [2,9]
```在不排序的情况下，按索引配对给出：```
|10 - 2| + |1 - 9| = 16
```排序后：```
|1 - 2| + |10 - 9| = 2
```排序可以保证最优分配。
