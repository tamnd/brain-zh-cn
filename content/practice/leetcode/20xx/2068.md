[LeetCode 问题 2068](https://leetcode.com/problems/check-whether-two-strings-are-almost-equivalent/)

 **难度：** 🟢简单
 **主题：** 哈希表、字符串、计数

 ## 解决方案

 ## 问题理解

 该问题要求我们根据每个小写英文字母出现的频率来判断两个字符串是否“几乎等价”。 

我们有两个字符串，`word1`和`word2`，两者长度相同。 对于每个角色`'a'`到`'z'`，我们比较该字符在每个字符串中出现的次数。 如果每个字母的频率绝对差最多为`3`，字符串被认为几乎是等效的。 否则，他们就不是。 

例如，假设一个字符串包含四次出现`'a'`而另一个包含零次出现的`'a'`。 区别在于`4`，超出了允许的限制`3`，所以答案是`false`。 

输入约束很小：

 - 每个字符串长度介于`1`和`100`- 仅使用小写英文字母

 这些限制告诉我们一些重要的事情：

 - 字母大小固定为 26 个字母
 - 我们不需要复杂的优化
 - 频率计数是自然的解决方案
 - 即使是低效的方法也可能会通过，但我们仍然想要最干净和最可扩展的实施

 一个重要的细节是我们必须检查来自`'a'`到`'z'`，甚至是未出现在一个或两个字符串中的字母。 缺失的字母仍然会造成频率差异。 例如：

-`"aaaa"`与`"bccb"`- 频率`'a'`是`4`与`0`- 区别是`4`- 结果是`false`一些值得考虑的边缘情况是：

 - 长度的字符串`1`- 完全相同的字符串
 - 一个字母仅出现在一个字符串中的字符串
 - 差异完全等于`3`，仍然应该返回`true`- 差异大于`3`，应该返回`false`由于字母表是固定的且很小，因此频率数组是理想的选择。 

## 方法

 ### 蛮力方法

 强力解决方案将分别重复计算每个字母的字符频率。 

对于每个角色`'a'`到`'z'`，我们可以扫描两个字符串并计算该字符出现的次数。 然后我们比较计数。 如果任何差异超过`3`，我们返回`false`。 

这是有效的，因为它直接遵循问题定义。 每个字符频率都经过独立检查。 

然而，这种方法效率低下，因为它会重复扫描字符串。 如果字符串长度为`n`，我们扫描两个字符串中的每一个 26 个字母，复杂度就变成了`O(26 × n)`。 虽然对于小的约束仍然可以接受，但它执行了不必要的重复工作。 

### 最佳方法

 关键的观察是我们只需要每个字母出现一次的频率。 

我们可以一次性构建频率计数，而不是重复扫描字符串。 由于只有26个小写英文字母，所以我们可以使用两个大小为26的数组。 

我们对两个字符串进行一次迭代：

 - 增加每个字符的计数`word1`- 增加每个字符的计数`word2`构建频率数组后，我们比较每个字母的计数。 如果任何绝对差值超过`3`，我们返回`false`。 否则，我们返回`true`。 

该方案高效、简单，直接匹配问题需求。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(26 × n) | O(26 × n) | O(1) | O(1) | 重复扫描字符串中的每个字母 |
 | 最佳| O(n + 26) | O(1) | O(1) | 使用固定大小数组的频率计数 |

 ## 算法演练

 1. 创建两个大小为 26 的数组，并用零初始化。 

这些数组存储字符频率`word1`和`word2`。 指数`0`代表`'a'`， 指数`1`代表`'b'`， 等等。 
2. 遍历两个字符串一次。 

对于每一个角色`word1`，使用以下方法计算其数组索引：```
ord(char) - ord('a')
```增加相应的频率计数。 

做同样的事`word2`。 
3. 比较所有 26 个字母的频率。 

对于每个索引`0`到`25`，计算两个频率阵列之间的绝对差。 
4. 如果差异超过`3`，立即返回`false`。 

这意味着字符串几乎不相等。 
5. 如果所有差异最多为`3`， 返回`true`。 

这确认了字符串满足问题条件。 

### 为什么它有效

 该算法之所以有效，是因为它显式计算了两个字符串中每个小写字母的准确频率。 由于几乎等同的定义完全取决于这些频率差异，因此检查所有 26 个字母可以保证正确性。 如果每个差异最多为`3`，字符串满足条件。 即使有一个字母违反了限制，字符串也几乎不相等。 

## Python 解决方案```python
class Solution:
    def checkAlmostEquivalent(self, word1: str, word2: str) -> bool:
        frequency1 = [0] * 26
        frequency2 = [0] * 26

        for char in word1:
            index = ord(char) - ord('a')
            frequency1[index] += 1

        for char in word2:
            index = ord(char) - ord('a')
            frequency2[index] += 1

        for i in range(26):
            if abs(frequency1[i] - frequency2[i]) > 3:
                return False

        return True
```该实现首先创建两个大小为 26 的频率数组。由于输入仅包含小写英文字母，因此每个字母直接映射到一个索引。 

第一个循环计算字符出现次数`word1`。 第二个循环执行相同的操作`word2`。 

构建两个频率数组后，最后一个循环逐个字母地比较频率。 这`abs()`函数计算计数之间的绝对差。 

如果任何差异超过`3`，函数立即返回`False`。 否则，检查完所有字母后，返回`True`。 

该实现完全遵循前面描述的算法，并且在线性时间内有效地解决了问题。 

## 解决方案```go
func checkAlmostEquivalent(word1 string, word2 string) bool {
    frequency1 := make([]int, 26)
    frequency2 := make([]int, 26)

    for _, char := range word1 {
        index := char - 'a'
        frequency1[index]++
    }

    for _, char := range word2 {
        index := char - 'a'
        frequency2[index]++
    }

    for i := 0; i < 26; i++ {
        difference := frequency1[i] - frequency2[i]

        if difference < 0 {
            difference = -difference
        }

        if difference > 3 {
            return false
        }
    }

    return true
}
```Go 解决方案遵循与 Python 版本相同的逻辑。 

Go 使用使用以下命令创建的整数切片，而不是 Python 列表`make([]int, 26)`。 

Go 标准库中没有提供内置的无需转换的整数绝对值函数，因此代码手动将负差值转换为正值。 

由于字母表大小是固定的，因此内存使用量保持不变。

 ## 边缘情况

 一种重要的边缘情况是频率差恰好为`3`。 问题陈述指出差异必须是“至多 3”，因此差异恰好为`3`是有效的。 一个常见的错误是意外使用`>= 3`而不是`> 3`。 该实现仅正确检查大于的差异`3`。 

另一种重要的边缘情况是某个字符仅出现在一个字符串中。 例如，`"aaaa"`和`"bbbb"`包含完全不同的字符。 丢失的字符仍必须被视为具有频率`0`。 频率数组方法自然可以处理这个问题，因为每个字母都有一个初始化为零的条目。 

第三种边缘情况是非常小的输入，例如长度的字符串`1`。 这些案例验证了该算法不依赖于较长的字符串或多次出现。 由于该解决方案只是计算频率并进行比较，因此即使对于最小的有效输入，它也能正常工作。
