[LeetCode 问题 2065](https://leetcode.com/problems/maximum-path-quality-of-a-graph/)

 **难度：** 🔴难
 **主题：** 数组、回溯、图论

 ## 解决方案

 ## 问题理解

 我们得到一个无向加权图，其中每个节点都有一个关联值。 如果满足以下条件，则路径被视为有效：

 1.从节点开始`0`2. 结束于节点`0`3、总行程时间不超过`maxTime`重要的细节是节点可能会被多次重新访问，但每个节点的值仅对路径质量做出一次贡献。 

目标是在所有有效路径中找到最大可能的路径质量。 

输入包括：

 -`values[i]`，分配给节点的值`i`-`edges[j] = [u, v, t]`，表示节点之间的无向边`u`和`v`与旅行时间`t`-`maxTime`, 允许的最大总行程时间

 该图可以包含循环，并且允许重新访问节点。 由于我们只计算一次唯一的节点值，因此我们必须仔细跟踪节点是否已经对总分做出了贡献。 

这些约束提供了几个重要的观察结果：

 -`maxTime <= 100`- 每条边至少有权重`10`- 每个节点最多有度数`4`这些限制非常重要。 即使图表可能包含最多`1000`节点，最大路径长度自然是有限的，因为每条边的遍历成本至少`10`。 这意味着任何有效路径最多可以包含大约`10`边遍历。 

这使得详尽的深度优先搜索变得可行。 

一些边缘情况很重要：

 - 图表可能会断开连接
 - 某些节点可能永远无法访问`maxTime`- 最优路径可能会多次重访节点
 - 返回节点`0`是强制性的
 - 一条超越的道路`maxTime`即使它具有很高的价值也是无效的
 - 节点`0`可能有价值`0`，但仍算作已访问

 ## 方法

 ### 蛮力方法

 蛮力的想法是生成从节点开始的所有可能的路径`0`，跟踪经过的时间，以及每当我们返回节点时`0`，用收集到的总唯一节点值更新答案。 

对于每个递归步骤：

 - 尝试每个相邻节点
 - 添加旅行时间
 - 如果没有超过时间限制则继续探索
 - 维护一组访问过的节点以避免重复计算节点值

 这种方法是正确的，因为它探索了每条有效路径。 

然而，简单的蛮力变得极其昂贵，因为图可能包含循环，这意味着可能的路径数量随着路径长度呈指数增长。 

没有仔细修剪和利用小`maxTime`，这种方法在一般图表中会太慢。 

### 关键见解

 关键的观察是`maxTime`非常小。 

由于每条边至少需要`10`秒：

 - 最大递归深度有界
 - 每个节点最多有`4`邻居
 - 有效的搜索空间变得易于管理

 这允许我们使用带有回溯的深度优先搜索。 

我们维持：

 - 当前节点
 - 当前经过的时间
 - 当前累积质量
 - 访问节点的频率计数

 频率计数很重要，因为允许重新访问节点。 我们仅在节点第一次出现在当前路径中时添加节点的值。 

每当DFS返回节点时`0`，我们更新全局答案。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | 指数| O(路径长度) | 在不利用约束的情况下探索所有可能的路径 |
 | 最优DFS+回溯| O(4^(最大时间/10)) | O(n + 最大时间/10) | 可行，因为深度自然是有限的 |

 ## 算法演练

 1. 为图构建邻接表。 

由于该图是无向的，因此每条边都在两个方向上插入。 邻接列表允许有效遍历相邻节点。 
2. 初始化频率数组。 

我们使用`visited_count[node]`跟踪节点在当前路径中出现的次数。 

这比布尔访问数组更好，因为允许重新访问节点。 
3.从节点启动DFS`0`。 

最初：

 - 当前节点 =`0`- 当前时间 =`0`- 当前质量 =`values[0]`4. 在每个DFS状态下，检查当前节点是否为`0`。 

如果是这样，则当前路径有效，因为：

 - 开始于`0`- 目前结束于`0`- 时间已经保证在限制之内

 更新全局答案。 
5. 探索所有相邻节点。 

对于每个邻居：

 - 计算新的经过时间
 - 如果超过则跳过移动`maxTime`6. 判断邻居是否贡献新的价值。 

如果`visited_count[neighbor] == 0`，这是当前路径中的第一次访问，所以添加`values[neighbor]`。 

否则，不添加任何内容。 
7. 应用移动。 

增量：

 -`visited_count[neighbor]`- 当前质量（如果适用）
 8. 递归到邻居。 

继续探索更深层次的路径。 
9. 递归后回溯。 

递减`visited_count[neighbor]`因此其他 DFS 分支的状态可以正确恢复。 

### 为什么它有效

 DFS 探索每条有效路径，其总时间不超过`maxTime`。 由于每个递归状态都完全代表当前路径配置，并且回溯可以正确恢复先前的状态，因此每个可行路径都会根据需要进行精确检查。 

频率跟踪保证每个节点在每条路径上最多贡献一次其值，这与问题定义相匹配。 

因为每当我们返回节点时答案都会更新`0`，该算法考虑所有有效路径，因此找到最大可能的质量。 

## Python 解决方案```python
from typing import List
from collections import defaultdict

class Solution:
    def maximalPathQuality(self, values: List[int], edges: List[List[int]], maxTime: int) -> int:
        graph = defaultdict(list)

        for u, v, t in edges:
            graph[u].append((v, t))
            graph[v].append((u, t))

        n = len(values)
        visited_count = [0] * n

        answer = values[0]
        visited_count[0] = 1

        def dfs(node: int, current_time: int, current_quality: int) -> None:
            nonlocal answer

            if node == 0:
                answer = max(answer, current_quality)

            for neighbor, travel_time in graph[node]:
                next_time = current_time + travel_time

                if next_time > maxTime:
                    continue

                first_visit = visited_count[neighbor] == 0

                visited_count[neighbor] += 1

                added_value = values[neighbor] if first_visit else 0

                dfs(
                    neighbor,
                    next_time,
                    current_quality + added_value
                )

                visited_count[neighbor] -= 1

        dfs(0, 0, values[0])

        return answer
```实现首先构建图的邻接列表表示。 由于该图是无向的，因此每条边都在两个方向上添加。 

这`visited_count`array 跟踪每个节点在当前 DFS 路径中出现的次数。 这很重要，因为允许重新访问节点，但节点值只能计算一次。 

DFS 函数维护三个状态：

 - 当前节点
 - 经过的时间
 - 当前质量

 每当 DFS 到达节点时`0`，当前路径有效，因此我们更新答案。 

对于每个相邻节点，我们首先检查采用该边是否会超过`maxTime`。 如果是，我们立即跳过该分支。 

变量`first_visit`确定节点的值是否应添加到质量中。 递归完成后，我们减少访问计数以恢复之前的状态以进行回溯。 

## 解决方案```go
package main

func maximalPathQuality(values []int, edges [][]int, maxTime int) int {
	type Edge struct {
		to   int
		time int
	}

	n := len(values)

	graph := make([][]Edge, n)

	for _, edge := range edges {
		u := edge[0]
		v := edge[1]
		t := edge[2]

		graph[u] = append(graph[u], Edge{v, t})
		graph[v] = append(graph[v], Edge{u, t})
	}

	visitedCount := make([]int, n)

	answer := values[0]
	visitedCount[0] = 1

	var dfs func(node int, currentTime int, currentQuality int)

	dfs = func(node int, currentTime int, currentQuality int) {
		if node == 0 && currentQuality > answer {
			answer = currentQuality
		}

		for _, edge := range graph[node] {
			nextNode := edge.to
			nextTime := currentTime + edge.time

			if nextTime > maxTime {
				continue
			}

			firstVisit := visitedCount[nextNode] == 0

			visitedCount[nextNode]++

			addedValue := 0
			if firstVisit {
				addedValue = values[nextNode]
			}

			dfs(
				nextNode,
				nextTime,
				currentQuality+addedValue,
			)

			visitedCount[nextNode]--
		}
	}

	dfs(0, 0, values[0])

	return answer
}
```Go 实现遵循与 Python 版本相同的 DFS 和回溯策略。 

几个特定于 Go 的细节值得注意：

 - 定制`Edge`struct 用于邻接表
 - 使用切片而不是动态 Python 列表
 - 递归DFS被声明为函数变量，因此它可以递归引用自身
 - 整数溢出不是问题，因为最大可能的质量完全适合 Go 的整数范围

 ## 边缘情况

 ### 单节点图

 如果图仅包含节点`0`，算法应该立即返回`values[0]`。 

如果实现假设边始终存在或仅在遍历期间更新答案，则这很容易导致错误。 我们的解决方案正确地初始化了答案`values[0]`在 DFS 开始之前。 

### 重新访问节点

 错误的一个主要来源是重复计算节点值。 

例如，类似的路径：```
0 → 1 → 0 → 1 → 0
```应该只计算节点`1`一次。 

使用频率数组而不是布尔访问数组允许重新访问，同时仍然确保仅在第一次访问期间添加值。 

### 无法返回节点 0 的路径

 某些路径可能会收集较大的值总计但无法返回节点`0`在期限内。 

幼稚的实现可能会错误地计算此类路径。 

我们的算法仅在当前节点恰好是时才更新答案`0`，确保每个记录的解决方案根据问题定义都是有效的。
