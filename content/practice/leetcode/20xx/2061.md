[LeetCode 问题 2061](https://leetcode.com/problems/number-of-spaces-cleaning-robot-cleaned/)

 **难度：** 🟡 中等
 **主题：** 数组、矩阵、模拟

 ## 解决方案

 ## 问题理解

 在这个问题中，我们给出一个二维二元矩阵，称为`room`。 每个单元格代表房间中的一个位置：

 -`0`表示该空间是空的并且可以清洁。 
-`1`表示空间内有物体，无法进入。 

清洁机器人从左上角启动`(0, 0)`，并且该问题保证该起始位置始终为空。 

机器人最初面向右侧。 它遵循非常严格的移动规则：

 1. 只要下一个单元格有效且为空，就沿当前方向前进。 
2. 如果下一步行动是：

 - 走出房间边界，或者
 - 击中物体（`1`),

 那么机器人就不会向前移动。 相反，它会顺时针旋转 90 度并再次尝试。 

机器人永远持续下去。 它所访问的每一个空白空间都会被清理干净。 

任务是返回在机器人无限执行过程中被清理的独特空间的总数。 

重要的细节是机器人可能会进入一个循环。 由于机器人无限期地运行，最终它的状态必须重复。 一旦重复完全相同的状态，机器人将永远继续保持相同的行为，因此在该点之后将不会清洁新的空间。 

限制条件是：

 -`1 <= m, n <= 300`- 网格最多可以包含`90,000`细胞。 
- 机器人可以多次重访细胞。 

这些限制告诉我们，我们需要有效的模拟。 单纯的无限模拟是不可能的，因为机器人永远不会自行停止。 

一些边缘情况很重要：

 - 一间只有一间牢房的房间。 
- 机器人立即被困的房间。 
- 没有障碍物的房间。 
- 机器人重新访问同一单元但方向不同的情况，因为方向影响未来的运动。 
- 大房间，无需循环检测的重复模拟将永远运行。 

## 方法

 ### 蛮力方法

 最直接的想法是无限期地模拟机器人，同时跟踪已清洁的细胞。 

每一步：

 - 将当前单元标记为已清洁。 
- 尝试前进。 
- 如果被阻挡，请顺时针旋转。 

这种方法的问题是机器人永远不会自行终止。 由于机器人会永远运行，因此除非我们检测到重复，否则模拟也会永远运行。 

简单的暴力实现可能会尝试在任意数量的移动后停止，但这并不可靠，因为不同的房间在进入循环之前可能需要非常不同的步骤数量。 

因此，没有循环检测的纯暴力破解是不实用的。 

### 关键见解

 关键的观察是机器人的未来行为完全取决于其当前状态：

 - 当前行
 - 当前列
 - 当前方向

 如果机器人达到了完全相同的高度`(row, column, direction)`同样，未来的动作序列将永远重复。 

这意味着我们只需要进行模拟，直到重新访问之前看到的状态。 

因为有：

 -`m * n`可能的职位
 -`4`可能的方向

 最多有`4 * m * n`独特的状态。 

一旦所有可达状态都耗尽，就必须发生一个循环。 

这将无限模拟问题转化为有限模拟问题。

 ## 算法演练

 ### 第 1 步：定义方向

 机器人顺时针旋转，因此我们按顺序存储四个方向：

 - 右
 - 向下
 - 左
 - 向上

 我们可以将它们表示为：```
directions = [(0,1), (1,0), (0,-1), (-1,0)]
```方向索引决定了机器人面向的方向。 

### 第 2 步：跟踪访问过的状态

 我们创建一个名为`visited_states`。 

每个状态包含：

 - 行
 - 专栏
 - 方向

 例如：```
(row, col, direction)
```这是必要的，因为以不同的方向访问同一个单元格的情况是不一样的。 根据方向的不同，机器人的行为可能有所不同。 

### 第 3 步：跟踪已清洁的细胞

 我们还维护一个名为`cleaned`。 

每次机器人访问一个空单元格时，我们都会将其添加到该集合中。 

最后，答案很简单：```
len(cleaned)
```### 第 4 步：模拟运动

 在每次迭代时：

 1. 检查当前状态是否已经被看到。 
2. 如果是，则停止仿真，因为机器人已进入循环。 
3.否则：

 - 添加状态到`visited_states`- 将当前单元格添加到`cleaned`然后计算下一个位置。 

### 步骤 5：处理移动或转动

 如果下一个位置：

 - 超出界限，或者
 - 包含障碍物，

 然后顺时针旋转：```
direction = (direction + 1) % 4
```否则，移至下一个单元格。 

###第六步：返回结果

 一旦出现重复状态，就无法清洁新的细胞。 

返回：```
len(cleaned)
```### 为什么它有效

 该算法之所以有效，是因为机器人是确定性的。 在相同的立场和方向下，它未来总会做出相同的决定。 

因此，一旦某个状态重复，整个未来的执行也会重复。 在那之后就再也无法到达任何看不见的细胞了。 

由于可能的状态有限，因此模拟最终必须终止。 

## Python 解决方案```python
from typing import List, Set, Tuple

class Solution:
    def numberOfCleanRooms(self, room: List[List[int]]) -> int:
        rows = len(room)
        cols = len(room[0])

        # Right, Down, Left, Up
        directions = [(0, 1), (1, 0), (0, -1), (-1, 0)]

        row = 0
        col = 0
        direction = 0

        visited_states: Set[Tuple[int, int, int]] = set()
        cleaned: Set[Tuple[int, int]] = set()

        while (row, col, direction) not in visited_states:
            visited_states.add((row, col, direction))
            cleaned.add((row, col))

            dr, dc = directions[direction]
            next_row = row + dr
            next_col = col + dc

            # Turn clockwise if blocked
            if (
                next_row < 0
                or next_row >= rows
                or next_col < 0
                or next_col >= cols
                or room[next_row][next_col] == 1
            ):
                direction = (direction + 1) % 4
            else:
                row = next_row
                col = next_col

        return len(cleaned)
```该实现严格遵循前面描述的模拟过程。 

首先，我们按顺时针顺序存储四个方向。 这允许使用简单的模运算进行旋转。 

变量`row`,`col`， 和`direction`代表机器人当前的状态。 

维护两套：

 -`visited_states`曲目`(row, col, direction)`-`cleaned`追踪独特的清洁细胞

 循环继续，直到出现重复状态。 

循环内部：

 1. 记录当前状态。 
2. 当前单元被标记为已清洁。 
3. 根据方向计算下一个位置。 
4. 如果无法移动，机器人顺时针旋转。 
5. 否则，机器人向前前进。 

最后，尺寸`cleaned`设置被返回。 

## 解决方案```go
func numberOfCleanRooms(room [][]int) int {
	rows := len(room)
	cols := len(room[0])

	// Right, Down, Left, Up
	directions := [][]int{
		{0, 1},
		{1, 0},
		{0, -1},
		{-1, 0},
	}

	row, col, direction := 0, 0, 0

	visitedStates := make(map[[3]int]bool)
	cleaned := make(map[[2]int]bool)

	for !visitedStates[[3]int{row, col, direction}] {
		visitedStates[[3]int{row, col, direction}] = true
		cleaned[[2]int{row, col}] = true

		dr := directions[direction][0]
		dc := directions[direction][1]

		nextRow := row + dr
		nextCol := col + dc

		if nextRow < 0 ||
			nextRow >= rows ||
			nextCol < 0 ||
			nextCol >= cols ||
			room[nextRow][nextCol] == 1 {

			direction = (direction + 1) % 4
		} else {
			row = nextRow
			col = nextCol
		}
	}

	return len(cleaned)
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

主要区别在于 Go 没有内置的元组类型，因此使用固定大小的数组作为映射键：

 -`[3]int`对于机器人状态
 -`[2]int`用于清洁的细胞

 Go 映射自然支持这些固定大小的数组作为可哈希键，使它们成为 Python 元组的干净替代品。 

不需要特殊的溢出处理，因为所有索引都保留在网格边界内。

 ## 边缘情况

 ### 单人牢房

 一个`1 x 1`room 是尽可能小的输入。 机器人开始于`(0,0)`并且不能向任何方向移动，因为每次移动都会触及边界。 

有缺陷的实现可能会意外地永远循环而没有检测到重复的方向状态。 我们的实现正确存储`(row, col, direction)`状态，因此在循环所有四个方向后，会检测到重复状态。 

### 以不同方向重新访问同一牢房

 一个非常常见的错误是只跟踪访问过的位置而不是完整的状态。 

例如，机器人可能会重新访问`(2,3)`同时面向不同的方向。 该配置的未来走势可能会完全不同。 

我们的实现通过存储以下内容来避免此错误：```
(row, col, direction)
```而不是仅仅`(row, col)`。 

### 完全开放网格

 在空网格中，机器人不一定会访问每个单元格。 

例如，在一个`3 x 3`在空房间中，机器人只穿过周边而不会进入中心。 

每个空单元都被清理的天真假设是不正确的。 我们的模拟遵循精确的移动规则，因此只计算真正访问过的单元格。
