[LeetCode 问题 2093](https://leetcode.com/problems/minimum-cost-to-reach-city-with-discounts/)

 **难度：** 🟡 中等
 **主题：** 图论、堆（优先级队列）、最短路径

 ## 解决方案

 ## 问题理解

 该问题描述了一个加权无向图，其中每个城市都是一个节点，每条高速公路都是具有相关通行费成本的边。 目标是从城市出发`0`到城市`n - 1`同时最大限度地减少总旅行成本。 

特殊之处在于折扣的存在。 高速公路行驶可享受折扣，减少高速公路通行费`toll`到`toll // 2`，使用整数除法。 每个折扣只能使用一次，每次高速公路行驶最多可使用一次折扣。 

输入包括：

 -`n`, 城市总数
 -`highways`，其中每个条目`[u, v, toll]`代表城市之间的双向边缘`u`和`v`-`discounts`, 可用折扣数量

 输出应该是从城市出发所需的最低总成本`0`到城市`n - 1`。 如果不存在路径，结果应该是`-1`。 

约束很重要，因为它们指导算法的选择：

 -`n <= 1000`-`highways.length <= 1000`-`discounts <= 500`具有 1000 个节点和 1000 个边的图相对稀疏。 然而，折扣维度显着增加了状态空间。 忽略折扣的朴素最短路径算法将不起作用，因为最佳路径不仅取决于当前城市，还取决于已经使用了多少折扣。 

一些边缘情况很重要：

 - 目的地可能无法到达。 
- 可能有零折扣。 
- 如果有策略地使用折扣，具有更多优势的路径可能会变得更便宜。 
- 尽早使用折扣并不总是最佳的。 
- 通行费可以为零。 
- 如果不同的折扣次数产生不同的费用，则可能需要多次访问同一城市。 

由于状态取决于位置和剩余折扣使用情况，因此该问题自然成为扩展状态图上的最短路径问题。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试枚举从城市出发的所有可能路径`0`到城市`n - 1`，同时还尝试在所经过的高速公路上使用各种可能的折扣组合。 

对于每条路径，我们可以通过决定哪些边获得折扣来计算可实现的最小成本。 由于每次边遍历都有两种可能性，折扣或不折扣，因此组合的数量呈指数级增长。 

这种方法是正确的，因为它最终会检查所有有效的可能性。 然而，它太慢了。 该图可能包含循环，并且路径的数量可能会变得巨大。 即使我们将自己限制在简单的路径上，可能的路径数量也会随着节点数量呈指数级增长。 

对于给定的约束，蛮力策略在计算上是不可行的。 

### 关键见解

 关键的观察结果是最佳状态由两条信息决定：

 1.当前所在城市
 2. 已使用折扣次数

 到达同一城市时剩余折扣数量不同可能会导致未来成本完全不同。 因此，我们不能使用传统的单距离Dijkstra算法。 

相反，我们对待`(city, discounts_used)`作为一个独特的状态。 

这将问题转化为扩展图上的最短路径问题：

 - 原始图节点变为分层状态
 - 每层对应已使用的折扣数量

 来自一个州`(u, d)`：

 - 我们可以正常旅行到`(v, d)`有成本`toll`- 如果`d < discounts`，我们可以使用折扣并前往`(v, d + 1)`有成本`toll // 2`所有边权重均保持非负，这意味着 Dijkstra 算法仍然适用。

 ## 算法演练

 1. 为图构建邻接表。 

由于高速公路是双向的，每条边`[u, v, toll]`是在两个方向上添加的。 邻接列表允许有效的邻居遍历。 
2. 创建距离表。 

定义：```
dist[city][used_discounts]
```这存储了达到目标所需的最低成本`city`准确使用后`used_discounts`折扣。 

将所有值初始化为无穷大。 
3. 初始化启动状态。 

我们从城市开始`0`有成本`0`并且没有使用任何折扣。```
dist[0][0] = 0
```4. 对 Dijkstra 算法使用优先级队列。 

每个堆条目包含：```
(current_cost, city, discounts_used)
```堆总是首先处理当前最便宜的可达状态。 
5. 堆中的进程状态。 

弹出最低成本状态。 

如果该状态已经比记录的距离差，则跳过它。 这是标准的 Dijkstra 优化。 
6. 不使用折扣探索邻居。 

对于每个邻近城市：```
new_cost = current_cost + toll
```如果这有所改善`dist[next_city][discounts_used]`，更新它并将新状态推入堆中。 
7.利用折扣探索邻居。 

如果还有折扣：```
discounted_cost = current_cost + toll // 2
```这将转换为：```
(next_city, discounts_used + 1)
```如果新路径更好，则再次更新距离表。 
8. 继续，直到堆为空。 

由于 Dijkstra 保证最短优先处理，因此最终确定了到达每个状态的第一条最佳路线。 
9. 计算答案。 

可以使用不同数量的折扣到达目的地城市。 

因此，最终的答案是：```
min(dist[n - 1])
```如果所有值保持无穷大，则返回`-1`。 

### 为什么它有效

 Dijkstra 算法之所以有效，是因为所有边权重都是非负的，即使在应用折扣之后也是如此。 

扩展的状态图正确地模拟了每个有效的情况。 状态唯一地捕获位置和折扣使用历史记录。 每个合法的运动都对应于这个扩展图中的一条边。 

由于 Dijkstra 总是处理当前最便宜的未处理状态，一旦一个状态被最终确定，它的最短距离就保证是最优的。 

因此，该算法正确地计算了可实现的最小旅行成本。 

## Python 解决方案```python
from typing import List
import heapq

class Solution:
    def minimumCost(self, n: int, highways: List[List[int]], discounts: int) -> int:
        graph = [[] for _ in range(n)]

        for u, v, toll in highways:
            graph[u].append((v, toll))
            graph[v].append((u, toll))

        INF = float("inf")

        dist = [[INF] * (discounts + 1) for _ in range(n)]
        dist[0][0] = 0

        min_heap = [(0, 0, 0)]
        # (cost, city, discounts_used)

        while min_heap:
            current_cost, city, used = heapq.heappop(min_heap)

            if current_cost > dist[city][used]:
                continue

            for neighbor, toll in graph[city]:
                # Travel without discount
                normal_cost = current_cost + toll

                if normal_cost < dist[neighbor][used]:
                    dist[neighbor][used] = normal_cost
                    heapq.heappush(
                        min_heap,
                        (normal_cost, neighbor, used)
                    )

                # Travel with discount
                if used < discounts:
                    discounted_cost = current_cost + toll // 2

                    if discounted_cost < dist[neighbor][used + 1]:
                        dist[neighbor][used + 1] = discounted_cost
                        heapq.heappush(
                            min_heap,
                            (discounted_cost, neighbor, used + 1)
                        )

        answer = min(dist[n - 1])

        return answer if answer != INF else -1
```实现首先构建图的邻接列表表示。 由于高速公路是双向的，因此每条边都会插入两次。 

这`dist`表是解决方案中最重要的结构。 它不是为每个城市仅存储一个最佳距离，而是为每个可能使用的折扣数量存储一个距离。 这是必要的，因为以不同的剩余折扣到达同一城市会创造不同的未来机会。 

优先级队列驱动 Dijkstra 算法。 每个状态包括累计成本、当前城市以及已消费的折扣数量。 

对于每个相邻边，代码探索两个转换：

 - 正常出行
 - 使用折扣旅行

 如果其中任何一个产生比之前已知的更好的状态，则更新距离表并将状态推入堆中。 

最后，算法检查目的地城市所有可能的折扣使用情况并返回最小值。 

## 解决方案```go
package main

import (
	"container/heap"
	"math"
)

type State struct {
	cost int
	city int
	used int
}

type PriorityQueue []State

func (pq PriorityQueue) Len() int {
	return len(pq)
}

func (pq PriorityQueue) Less(i, j int) bool {
	return pq[i].cost < pq[j].cost
}

func (pq PriorityQueue) Swap(i, j int) {
	pq[i], pq[j] = pq[j], pq[i]
}

func (pq *PriorityQueue) Push(x interface{}) {
	*pq = append(*pq, x.(State))
}

func (pq *PriorityQueue) Pop() interface{} {
	old := *pq
	n := len(old)
	item := old[n-1]
	*pq = old[:n-1]
	return item
}

func minimumCost(n int, highways [][]int, discounts int) int {
	graph := make([][][2]int, n)

	for _, edge := range highways {
		u := edge[0]
		v := edge[1]
		toll := edge[2]

		graph[u] = append(graph[u], [2]int{v, toll})
		graph[v] = append(graph[v], [2]int{u, toll})
	}

	inf := math.MaxInt

	dist := make([][]int, n)
	for i := 0; i < n; i++ {
		dist[i] = make([]int, discounts+1)

		for j := 0; j <= discounts; j++ {
			dist[i][j] = inf
		}
	}

	dist[0][0] = 0

	pq := &PriorityQueue{}
	heap.Init(pq)

	heap.Push(pq, State{
		cost: 0,
		city: 0,
		used: 0,
	})

	for pq.Len() > 0 {
		current := heap.Pop(pq).(State)

		currentCost := current.cost
		city := current.city
		used := current.used

		if currentCost > dist[city][used] {
			continue
		}

		for _, edge := range graph[city] {
			neighbor := edge[0]
			toll := edge[1]

			// Without discount
			normalCost := currentCost + toll

			if normalCost < dist[neighbor][used] {
				dist[neighbor][used] = normalCost

				heap.Push(pq, State{
					cost: normalCost,
					city: neighbor,
					used: used,
				})
			}

			// With discount
			if used < discounts {
				discountedCost := currentCost + toll/2

				if discountedCost < dist[neighbor][used+1] {
					dist[neighbor][used+1] = discountedCost

					heap.Push(pq, State{
						cost: discountedCost,
						city: neighbor,
						used: used + 1,
					})
				}
			}
		}
	}

	answer := inf

	for d := 0; d <= discounts; d++ {
		if dist[n-1][d] < answer {
			answer = dist[n-1][d]
		}
	}

	if answer == inf {
		return -1
	}

	return answer
}
```Go 实现遵循与 Python 版本相同的算法结构，但需要使用手动优先级队列实现`container/heap`包裹。 

邻接表将对存储为固定大小的数组`[2]int`，其中第一个元素是邻居，第二个元素是通行费。 

Go 不直接为整数提供无穷大值，所以`math.MaxInt`被用作初始不可达距离。 

因为 Go 的堆接口适用于`interface{}`，在推送和弹出操作期间需要显式类型断言。

class Solution:
    def minimumCost(self, n: int, highways: List[List[int]], discounts: int) -> int:
        import heapq

        graph = [[] for _ in range(n)]

        for u, v, toll in highways:
            graph[u].append((v, toll))
            graph[v].append((u, toll))

        INF = float("inf")

        dist = [[INF] * (discounts + 1) for _ in range(n)]
        dist[0][0] = 0

        heap = [(0, 0, 0)]

        while heap:
            cost, city, used = heapq.heappop(heap)

            if cost > dist[city][used]:

            for nxt, toll in graph[city]:
                # No discount
                if cost + toll < dist[nxt][used]:

                        heapq.heappush(
                            heap,
                            (discounted, nxt, used + 1)
                        )

        ans = min(dist[n - 1])

        return ans if ans != INF else -1

 ## 边缘情况

 一种重要的边缘情况是图断开连接。 幼稚的实现可能会假设每个城市都是可达的，但这并不能得到保证。 在这种情况下，目的地国家的距离仍然无穷大。 该实现正确检测到这一点并返回`-1`。 

当最佳路径中可用折扣多于有用边缘时，就会出现另一个重要的边缘情况。 该算法并不强制使用所有折扣。 相反，它独立跟踪所有可能的折扣计数，并在目的地选择其中的最小值。 

一个微妙的边缘情况涉及以不同的折扣次数多次重游同一城市。 传统的最短路径实现（每个城市仅存储一个距离）在这里会失败。 例如，在使用所有折扣后以便宜的价格到达某个城市实际上可能比以稍高的价格到达该城市但保留折扣供以后使用更糟糕。 扩展状态表示可以正确处理这个问题。 

最后的边缘情况涉及通行费为零。 由于零的整数除法仍然为零，因此折扣应用没有任何改变。 该实现自然地处理了这个问题，因为 Dijkstra 算法支持非负边缘权重，包括零。
