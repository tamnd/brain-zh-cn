[LeetCode 2070 题](https://leetcode.com/problems/most-beautiful-item-for-each-query/)

 **难度：** 🟡 中等
 **主题：** 数组、二分查找、排序

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个项目列表，其中每个项目都有两个属性：

 -`price`-`beauty`每个条目看起来像：```
items[i] = [pricei, beautyi]
```我们还得到了一个查询列表。 对于每个查询值`queries[j]`，我们必须确定：

 > 在所有价格小于或等于查询值的商品中，颜值最高的是什么？ 

如果没有商品满足价格条件，则该查询的答案是`0`。 

结果应该是一个数组，其中每个位置对应于匹配查询的答案。 

例如，假设我们有：```
items = [[1,2],[2,4],[5,6]]
queries = [2,4]
```供查询`2`，我们可以选择有价格的商品`1`和`2`，所以最大的美感是`4`。 

供查询`4`，我们仍然无法使用标价为`5`，这样就保留了最大的美感`4`。 

约束条件极其重要：

 - 最多`10^5`项目
 - 最多`10^5`查询
 - 价格和美丽可以大到`10^9`这些限制立即告诉我们，简单的嵌套循环解决方案将太慢。 时间复杂度约为的解决方案`O(n * q)`可能需要最多`10^10`在最坏的情况下进行操作，这是不可行的。 

该问题还允许：

 - 多个商品价格相同
 - 具有相同美感的多个物品
 - 查询量小于每件商品的价格
 - 查询量大于每件商品的价格

 这些边缘情况很重要，因为它们影响我们如何有效地进行预处理和搜索。 

## 方法

 ### 蛮力方法

 最直接的解决方案是独立处理每个查询。 

对于每个查询：

 1. 迭代所有项目。 
2. 检查是否`price <= query`。 
3.追踪有效物品中最大的美丽。 

这是有效的，因为它直接实现了问题定义。 每件符合条件的物品都会经过检查，因此保证发现的最大美丽是正确的。 

然而，对于大输入来说，性能是不可接受的。 

如果有：

 -`n`项目
-`m`查询

 然后我们执行`n * m`比较。 

两个值都达到`10^5`，这变得太大了。 

### 最佳解决方案的关键见解

 重要的观察是查询只关心：

 > 所有物品中最美丽的，但价格有一定限制。 

这建议排序。 

如果我们按价格对物品进行排序，那么随着价格的上涨，我们可以保持运行的最大美感。 

例如：```
items = [[1,2],[2,4],[3,5],[5,6]]
```预处理后：

 | 价格| 迄今为止最好的美容|
 | ---| ---|
 | 1 | 2 |
 | 2 | 4 |
 | 3 | 5 |
 | 5 | 6 |

 现在每个查询变成：

 > 找到最右边的商品，其价格为`<= query`。 

使用二分搜索可以有效地完成此操作。 

一旦我们找到该位置，预先计算的运行最大值立即给出答案。 

这将问题从重复扫描转化为：

 - 一个排序步骤
 - 一次预处理
 - 每个查询一次二分搜索

 这对于约束来说足够有效。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | ---| ---| ---| ---|
 | 蛮力 | O(n × m) | O(1) | O(1) | 扫描每个查询的每个项目 |

 ## 算法演练

 ### 最优算法

 1. 按价格对所有商品进行排序。 

这使我们能够按价格递增的顺序处理商品。 二分查找还需要排序数据。 
2. 构建两个数组：

 -`prices`，包含排序价格
 -`max_beauty`， 在哪里`max_beauty[i]`存储从索引中看到的最大美感`0`通过`i`例如：```
items = [[1,2],[2,4],[3,2],[5,6]]
```预处理后：```
prices = [1,2,3,5]
max_beauty = [2,4,4,6]
```请注意，尽管美丽有代价`3`只是`2`，迄今为止最美的还是`4`。 
3. 对于每个查询，执行二分搜索`prices`。 

我们想要最右边的索引，其中：```
prices[index] <= query
```蟒蛇的`bisect_right`或 Go 的`sort.Search`可以有效地找到这个位置。 
4. 如果不存在有效索引，则返回`0`。 

当查询小于最小商品价格时会发生这种情况。 
5.否则返回`max_beauty[index]`。 

自从`max_beauty[index]`已经存储了所有有效价格中最好的美丽，这是正确的答案。 

### 为什么它有效

 正确性依赖于一个简单的不变量：

 > 经过预处理后，`max_beauty[i]`始终等于指数为 的所有项目中的最大美度`0`到`i`。 

因为商品是按价格排序的，所以前面的每个索引`i`价格小于或等于`prices[i]`。 

二分搜索找到查询的最大有效价格位置。 然后，前缀最大数组立即提供所有符合条件的项目中最好的美感。 

因此，每个查询都会得到正确回答。 

## Python 解决方案```python
from bisect import bisect_right
from typing import List

class Solution:
    def maximumBeauty(self, items: List[List[int]], queries: List[int]) -> List[int]:
        # Sort items by price
        items.sort()

        prices = []
        max_beauty = []

        current_max = 0

        # Build prefix maximum beauty array
        for price, beauty in items:
            current_max = max(current_max, beauty)

            prices.append(price)
            max_beauty.append(current_max)

        answers = []

        # Answer each query using binary search
        for query in queries:
            index = bisect_right(prices, query) - 1

            if index >= 0:
                answers.append(max_beauty[index])
            else:
                answers.append(0)

        return answers
```实现从排序开始`items`按价格。 Python 自动按字典顺序对对进行排序，因此直接排序可以正常工作。 

接下来，代码构建两个数组：

 -`prices`-`max_beauty`变量`current_max`在迭代排序的项目时跟踪迄今为止遇到的最佳美感。 

对于每个项目：```python
current_max = max(current_max, beauty)
```这确保了`max_beauty[i]`存储迄今为止所有价格中最好的美丽。 

对于查询，该解决方案使用：```python
bisect_right(prices, query)
```这将返回所有小于或等于查询的值之后的插入位置。 减一给出最大有效价格的索引。 

如果指数变为负数，则没有商品是买得起的，所以答案是`0`。 

否则，前缀最大数组会立即提供答案。 

## 解决方案```go
package main

import "sort"

func maximumBeauty(items [][]int, queries []int) []int {
	sort.Slice(items, func(i, j int) bool {
		return items[i][0] < items[j][0]
	})

	prices := make([]int, len(items))
	maxBeauty := make([]int, len(items))

	currentMax := 0

	for i, item := range items {
		price := item[0]
		beauty := item[1]

		if beauty > currentMax {
			currentMax = beauty
		}

		prices[i] = price
		maxBeauty[i] = currentMax
	}

	result := make([]int, len(queries))

	for i, query := range queries {
		index := sort.Search(len(prices), func(j int) bool {
			return prices[j] > query
		}) - 1

		if index >= 0 {
			result[i] = maxBeauty[index]
		} else {
			result[i] = 0
		}
	}

	return result
}
```Go 实现遵循与 Python 解决方案相同的算法结构。 

主要区别在于二分搜索语法。 Go 使用：```go
sort.Search
```它返回条件成立的第一个位置。 我们搜索第一个大于查询的价格，然后减去一以获得最后一个有效价格。 

使用 Go 切片代替 Python 列表，但预处理逻辑保持不变。 

整数溢出不是问题，因为问题约束完全符合 Go 的标准`int`在 LeetCode 系统上打字。

 ## 边缘情况

 ### 查询量小于每个商品的价格

 如果查询值小于最低商品价格，则没有商品是买得起的。 

这是错误的常见来源，因为二分搜索可能会返回位置`0`，减一产生`-1`。 

实现明确检查：```
if index >= 0
```如果没有，则返回`0`。 

### 多个商品价格相同

 该问题允许重复价格。 

例如：```
[[1,2],[1,5],[1,3]]
```幼稚的实现可能会意外地停止在第一个匹配价格，而不是考虑所有项目。 

使用`bisect_right`确保我们找到该价格的最后一次出现。 前缀最大数组可以保证返回最好的美感。 

### 美容价值下降

 不保证物品会越来越美观。 

例如：```
[[1,10],[2,3],[3,5]]
```如果我们只存储原始美丽值，则查询`2`会错误地返回`3`而不是`10`。 

前缀最大预处理通过确保：```
max_beauty[i]
```永远储存着迄今为止所见过的最好的美丽。 

### 大输入尺寸

 高达`10^5`项目和查询，低效的解决方案很快就会超时。 

优化方法通过结合排序和二分查找来避免重复扫描。 即使在最大限制下，这也可以使运行时间保持在可接受的范围内。
