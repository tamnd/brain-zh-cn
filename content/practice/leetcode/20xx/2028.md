 ## 解决方案

 ## 问题理解

 该问题为我们提供了一些掷骰子的结果，并要求我们重建丢失的结果。 

我们一共有`n + m`标准 6 面骰子的卷。 从这些卷中：

 -`m`值是已知的并存储在数组中`rolls`-`n`值缺失
 - 全部的平均值`n + m`卷正是`mean`我们的任务是返回任何长度有效的数组`n`其值介于`1`和`6`，使得整套卷的平均值恰好变为`mean`。 

由于平均值是已知的，我们可以计算所有滚动在一起必须具有的总和。 

如果：

 - 总卷数 =`n + m`- 期望平均值=`mean`然后：$$\text{required total sum} = (n + m) \times mean$$我们已经知道观察到的滚动的总和：$$\text{observed sum} = \sum rolls$$因此，缺失的卷数总计必须为：$$\text{missing sum} = \text{required total sum} - \text{observed sum}$$挑战在于确定是否有可能将这个缺失的总和准确地分配给`n`掷骰子，每个值必须保持在有效的骰子范围内`[1, 6]`。 

约束条件很重要：

 -`1 <= n, m <= 10^5`- 每个滚动值介于`1`和`6`这些限制立即排除了指数或强力搜索方法。 我们需要一个线性时间的解决方案。 

一些边缘情况尤其重要：

 - 所需的缺失金额可能太小。 因为每个骰子至少`1`，最小可能的缺失总和是`n`。 
- 所需的缺失金额可能太大。 因为每个骰子最多`6`，最大可能缺失总和为`6 * n`。 
- 缺失的总和可能在有效范围内，但分配不正确可能会在有效范围之外产生无效值`[1, 6]`。 

该问题保证如果存在多个有效答案，我们可能会返回其中任何一个。 

## 方法

 ### 蛮力方法

 暴力解决方案会尝试所有可能的组合`n`掷骰子。 

每个缺失的卷可以采用六个值之一：$$1, 2, 3, 4, 5, 6$$所以组合总数为：$$6^n$$对于每个组合，我们将计算总和并检查平均值是否与所需的平均值匹配。 

这种方法是正确的，因为它详尽地探索了缺失卷的每一种可能的有效分配。 如果存在解决方案，蛮力最终会找到它。 

然而，对于给定的约束，该方法变得完全不可行。 自从`n`可以大到`10^5`， 甚至`6^{20}`已经是天文数字了，不可能进行彻底的搜索。 

### 最佳方法

 关键的观察是，我们实际上并不关心值的确切排列，只关心所需的总和是否可以分布在`n`骰子。 

我们可以直接构造一个有效的答案，而不是通过组合进行搜索。 

首先，计算总缺失和：$$\text{missing sum} = (n + m) \times mean - \sum rolls$$现在我们检查可行性：

 - 最小可能总和`n`骰子 =`n`- 最大可能总和`n`骰子 =`6n`如果缺失的总和超出该范围，则不存在解。 

否则，我们可以贪婪地构建答案。 

一种简单的策略是：

 - 开始每一个缺失的卷`1`- 这使用了一个基本总和`n`- 将剩余的金额分配到骰子上
 - 每个骰子最多可以收到`5`加分，因为最大值是`6`这保证了所有值都保持有效。 

因为我们只遍历数组一次，所以解决方案以线性时间运行。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |

 ## 算法演练

 1. 计算观察到的滚动的总和。 

我们首先计算：```
observed_sum = sum(rolls)
```这告诉我们已知的掷骰子已经存在多少贡献。 
2. 计算所需的总和。 

由于所有卷的平均值必须等于`mean`:```
total_sum = (n + len(rolls)) * mean
```3. 计算缺失的总和。 

缺失的卷必须贡献：```
missing_sum = total_sum - observed_sum
```4. 检查缺失的总和是否可行。 

每个缺失的骰子必须介于`1`和`6`。 

因此：

 - 最小可能缺失总和 =`n`- 最大可能缺失总和 =`6 * n`如果：```
missing_sum < n
```或者```
missing_sum > 6 * n
```那么不存在有效的解决方案，因此我们返回一个空数组。 
5. 将所有缺失的卷初始化为`1`。 

这保证了所有值都是有效的，并为我们提供了可能的最小总和：```
result = [1] * n
```6. 计算还需要分配多少额外金额。 

由于我们已经分配了`1`到每个位置：```
remaining = missing_sum - n
```7. 贪婪地分配剩余的金额。 

遍历数组并向每个骰子添加尽可能多的内容。 

每个骰子最多可以接收`5`额外加分是因为：```
current value = 1
maximum value = 6
```所以：```
add = min(5, remaining)
```然后：```
result[i] += add
remaining -= add
```8. 返回构造好的数组。 

一旦剩余量变为零，数组就满足所有约束。 

### 为什么它有效

 该算法之所以有效，是因为它在构建值的同时始终保持有效的骰子边界。 

从全部开始可保证最小可行配置。 剩余的金额代表必须分配的额外价值。 由于每个骰子最多可以再增加 5 点，因此贪婪地分配永远不会违反 6 点的上限。 

可行性检查可确保所需金额位于可实现的范围内。 因此，如果检查通过，贪婪构造总是会成功。 

## Python 解决方案```python
from typing import List

class Solution:
    def missingRolls(self, rolls: List[int], mean: int, n: int) -> List[int]:
        observed_sum = sum(rolls)
        total_rolls = len(rolls) + n
        required_total = total_rolls * mean

        missing_sum = required_total - observed_sum

        if missing_sum < n or missing_sum > 6 * n:
            return []

        result = [1] * n
        remaining = missing_sum - n

        for i in range(n):
            if remaining == 0:
                break

            extra = min(5, remaining)
            result[i] += extra
            remaining -= extra

        return result
```实现直接遵循前面描述的算法。 

首先，我们使用 Python 的内置函数计算观察到的总和`sum()`功能。 然后我们根据所需的平均值计算所需的总和。 

变量`missing_sum`代表缺失的骰子必须贡献多少总价值。 

可行性检查至关重要。 如果缺失的总和小于`n`，甚至将所有骰子分配为`1`将超出目标。 如果缺失的总和大于`6 * n`，甚至将所有骰子分配为`6`还不够。 

确认可行性后，代码将每个丢失的芯片初始化为`1`。 这保证了所有值从一开始就有效。 

然后贪婪地分配剩余的金额。 每个骰子最多可以吸收`5`在达到最大值之前的额外积分`6`。 

一旦所有剩余价值被分配，循环就会提前停止。 

## 解决方案```go
func missingRolls(rolls []int, mean int, n int) []int {
    observedSum := 0
    for _, value := range rolls {
        observedSum += value
    }

    totalRolls := len(rolls) + n
    requiredTotal := totalRolls * mean

    missingSum := requiredTotal - observedSum

    if missingSum < n || missingSum > 6*n {
        return []int{}
    }

    result := make([]int, n)

    for i := 0; i < n; i++ {
        result[i] = 1
    }

    remaining := missingSum - n

    for i := 0; i < n && remaining > 0; i++ {
        extra := remaining
        if extra > 5 {
            extra = 5
        }

        result[i] += extra
        remaining -= extra
    }

    return result
}
```Go 实现遵循与 Python 版本相同的逻辑。 

一个小小的区别是 Go 需要显式初始化切片。 我们使用以下命令创建结果切片`make([]int, n)`并手动将每个元素分配给`1`。 

当不存在解时，该函数返回一个空切片`[]int{}`。 

整数溢出不是问题，因为最大可能的总和是：$$(10^5 + 10^5) \times 6 = 1.2 \times 10^6$$它安全地适合 Go 的整数类型。

 ## 边缘情况

 当缺失总和小于`n`。 因为每个骰子必须至少`1`，最小可能的总数`n`骰子正是`n`。 任何更小的目标总和都是不可能的。 跳过此可行性检查的简单实现可能会意外地产生零或负值。 

当缺失总和超过时，会出现另一个重要的边缘情况`6 * n`。 即使每一个缺失的骰子都等于`6`，总数仍然太小。 如果没有此验证步骤，实现可能会错误地生成大于`6`，违反问题约束。 

第三个重要的边缘情况涉及接近的大输入大小`10^5`。 由于时间复杂性或堆栈限制，递归或暴力方法可能会失败。 所实现的解决方案完全避免了递归，仅通过线性遍历来处理数据，即使在最大约束下也能保持高效。 

当剩余的额外总和在到达数组末尾之前变为零时，会出现微妙的边缘情况。 在这种情况下，剩余的骰子应该保持在`1`。 该实现自然地处理了这个问题，因为所有位置都从`1`，一旦不需要分配额外的值，循环就会提前退出。
