[LeetCode 问题 2064](https://leetcode.com/problems/minimized-maximum-of-products-distributed-to-any-store/)

 **难度：** 🟡 中等
 **主题：** 数组、二分搜索、贪婪

 ## 解决方案

 ## 问题理解

 问题给了我们`n`零售店和一系列`quantities`，其中每个元素代表特定产品类型存在多少个产品。 

重要的限制是单个商店只能包含一种产品类型的产品。 但是，产品类型可能会分布在多个商店中。 我们的目标是分销所有产品，同时最大限度地减少分配给任何单个商店的最大产品数量。 

换句话说，假设最终答案是`x`。 这意味着任何商店都不得持有超过`x`产品。 我们需要确定最小的可能值`x`这样每个产品仍然可以合法分销。 

例如，如果产品类型有`11`物品，我们决定任何商店都不能容纳超过`3`项，那么该产品类型将需要：$$\lceil 11 / 3 \rceil = 4$$商店，因为每个商店最多可以容纳`3`那种类型的。 

输入包括：

 -`n`, 可用商店总数
 -`quantities`， 在哪里`quantities[i]`是计数`i-th`产品类型

 输出是一个整数，即每个商店的最小可能最大负载。 

约束条件很重要：

 -`1 <= m <= n <= 10^5`-`1 <= quantities[i] <= 10^5`产品类型和商店的数量都可以多达`100000`，所以任何算法都比粗略地更糟糕`O(m log k)`可能会太慢，其中`k`是最大数量值。 

一些边缘情况很重要：

 - 只有一家商店存在，因此所有产品都必须进入该商店。 
- 产品类型可能比其他类型大得多。 
- 如果商店很少，则最佳答案可能等于最大数量。 
- 如果有很多商店可用，答案可能会很小。 
- 计算上限值时很容易出现整数除法错误。 

## 方法

 ### 蛮力方法

 一个简单的想法是尝试每一个可能的值`x`从`1`最多`max(quantities)`。 

对于每位候选人`x`，我们计算需要多少个商店。 如果产品类型包含`q`物品，每个商店最多可以持有`x`，则需要的店铺数量为：$$\lceil q / x \rceil$$我们对所有产品类型进行了总结。 如果所需商店总数小于或等于`n`， 然后`x`是可行的。 

这种方法是正确的，因为它明确地检查每个可能的答案并返回最小的可行答案。 

然而，它太慢了。 如果最大数量是`100000`，那么我们可以执行`100000`检查，每个检查都会扫描整个数组。 

这导致：$$O(m \times \max(quantities))$$这对于约束来说太昂贵了。 

### 最优方法，对答案进行二分搜索

 关键的观察是可行性是单调的。 

如果一个值`x`有效，那么每个更大的值也有效。 

例如：

 - 如果商店最多能容纳`5`产品和分销是可能的，
 - 然后允许商店持有`6`,`7`，或者更多的产品也是可能的。 

这种单调性质使得该问题非常适合二分搜索。 

我们对答案范围进行二分查找：

 - 最低可能答案：`1`- 最大可能答案：`max(quantities)`对于每个中点`mid`，我们确定分配是否可行。 

检查可行性：

 - 对于每个数量`q`,
 - 计算所需的商店：$$\lceil q / mid \rceil$$- 对这些值求和。 
- 如果需要的商店总数是`<= n`， 然后`mid`是可行的。 

使用二分搜索极大地降低了复杂性。

 ## 算法演练

 1. 初始化二分查找边界。 

最小可能的答案是`1`因为如果存在产品，商店必须至少拥有一种产品。 

最大可能的答案是`max(quantities)`因为理论上一家商店可以容纳整个产品类型。 
2. 开始二分查找`left < right`。 

在每次迭代时，计算：```
mid = (left + right) // 2
```这`mid`表示每个商店的候选最大产品数量。 
3. 检查是否`mid`是可行的。 

对于每个数量`q`，如果没有商店可以超过，计算需要多少个商店`mid`产品。 

公式为：$$\lceil q / mid \rceil$$在整数算术中，这变成：```
(q + mid - 1) // mid
```4. 对所有产品类型所需的商店进行求和。 

如果所需商店总数小于或等于`n`，那么候选人`mid`是可行的。 

这意味着我们可以用更小的最大值做得更好。 

移动右边界：```
right = mid
```5. 否则，`mid`太小了。 

我们需要的商店数量超出了可用商店数量，因此增加允许的最大值：```
left = mid + 1
```6. 继续，直到搜索空间崩溃。 

什么时候`left == right`，我们找到了最小可行值。 

### 为什么它有效

 该算法依赖于可行性的单调性。 

如果最大存储负载`x`足够了，那么任何更大的值也足够了，因为更大的容量只能减少所需的存储数量。 

二分搜索正确地识别出这个单调搜索空间中的最小可行值。 

## Python 解决方案```python
from typing import List

class Solution:
    def minimizedMaximum(self, n: int, quantities: List[int]) -> int:
        left = 1
        right = max(quantities)

        while left < right:
            mid = (left + right) // 2

            required_stores = 0

            for quantity in quantities:
                required_stores += (quantity + mid - 1) // mid

            if required_stores <= n:
                right = mid
            else:
                left = mid + 1

        return left
```实现首先定义二分搜索范围。 下界是`1`，上限为最大产品数量。 

在二分搜索循环内，代码评估是否`mid`是可行的。 变量`required_stores`累计需要多少家商店，如果没有商店可能超过`mid`产品。 

上限划分公式：```python
(quantity + mid - 1) // mid
```确保在不使用浮点运算的情况下正确向上舍入。 

如果所需商店总数在`n`，算法通过更新将搜索范围缩小到较小的值`right`。 

否则，候选者太小，因此算法会增加下界。 

最终，两个指针都收敛到最小的可行答案。 

## 解决方案```go
func minimizedMaximum(n int, quantities []int) int {
	left := 1
	right := 0

	for _, quantity := range quantities {
		if quantity > right {
			right = quantity
		}
	}

	for left < right {
		mid := left + (right-left)/2

		requiredStores := 0

		for _, quantity := range quantities {
			requiredStores += (quantity + mid - 1) / mid
		}

		if requiredStores <= n {
			right = mid
		} else {
			left = mid + 1
		}
	}

	return left
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

一个小的区别是中点的计算：```go
mid := left + (right-left)/2
```这种形式避免了潜在的整数溢出，尽管在给定的约束下溢出实际上是不可能的。 

Go 使用切片来`quantities`，并且整数除法已经向零截断，使得上限除法公式自然起作用。

 ## 边缘情况

 当只有一家商店时，就会出现一种重要的边缘情况。 在这种情况下，所有产品必须分配到同一家商店，这意味着答案必须等于最大数量。 即使不存在其他商店，有缺陷的实现也可能会错误地尝试进一步拆分产品。 二分搜索正确地处理了这个问题，因为每个较小的候选者都变得不可行。 

另一个重要的情况是当有许多额外的商店可用时。 例如，如果`n`远大于产品总数，最优答案可能变为`1`。 一些实现意外地假设每个商店都必须包含产品，这是错误的。 该问题明确允许空商店，并且该解决方案自然支持该行为。 

第三个棘手的情况涉及天花板划分。 假设我们有`11`产品和限制`3`每家商店。 使用普通整数除法：```
11 // 3 = 3
```会错误地建议只需要三个商店。 实际上，需要四个商店，因为其余的仍然需要存储。 该实现使用以下方法避免了此错误：```
(quantity + mid - 1) // mid
```它使用整数算术正确计算上限除法。 

当一种产品类型主导所有其他产品类型时，就会出现另一种微妙的边缘情况。 例如：```
quantities = [99999, 1]
```商店很少。 该算法仍然有效，因为可行性仅取决于所需商店的总数，无论数量多么不均匀。
