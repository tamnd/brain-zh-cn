 # LeetCode 2089，排序数组后查找目标索引

 ## 问题理解

 问题给了我们一个整数数组`nums`和一个整数`target`。 我们必须按非降序对数组进行排序，然后返回值等于的每个索引`target`。 

目标索引只是一个索引`i`这样：$nums[i] = target$重要的细节是，索引必须在对数组排序后返回，而不是基于原始顺序。 

例如，如果：```
nums = [1,2,5,2,3]
target = 2
```排序后：```
[1,2,2,3,5]
```价值`2`出现在索引处`1`和`2`，所以答案是：```
[1,2]
```输入数组长度最多为`100`，并且每个值也介于`1`和`100`。 这些限制非常小，这意味着即使是简单的排序解决方案也是完全可以接受的。 

输出必须包含按升序排列的所有有效索引。 由于数组已排序，因此从左到右扫描时索引自然会按升序排列。 

需要考虑一些重要的边缘情况：

 - 目标可能根本不存在于数组中，在这种情况下我们返回一个空列表。 
- 数组中的每个元素都可能等于目标，这意味着每个索引都成为答案的一部分。 
- 目标只能出现一次。 
- 数组可能已经排序或完全未排序，但我们的算法在所有情况下都必须正确运行。 

## 方法

 ### 蛮力方法

 最直接的解决办法是：

 1. 对数组进行排序。 
2. 迭代已排序的数组。 
3. 收集每个值等于的索引`target`。 

这种方法之所以有效，是因为排序将所有相等的值放在一起，从而可以轻松识别目标的每次出现。 

尽管这个解决方案很简单，但对于问题约束来说它已经足够有效了。 数组大小很小，因此排序成本非常低。 

### 更好的观察

 我们可以稍微改进推理，而无需显式依赖排序的数组值本身。 

排序后：

 - 每个小于的数字`target`将出现在目标之前。 
- 每次出现`target`会连续出现。 

因此：

 - 第一个目标索引等于小于的数字的数量`target`。 
- 目标索引的数量等于等于的数字计数`target`。 

如果：```
smaller = count of numbers < target
equal = count of numbers == target
```那么答案就变成了：```
[smaller, smaller + 1, ..., smaller + equal - 1]
```这完全避免了排序并在线性时间内产生答案。

 ## 算法演练

 ### 最优算法

 1. 初始化两个计数器：

 -`smaller_count`，计算严格小于的数字`target`-`equal_count`, 计算等于的数字`target`2. 从左到右遍历数组一次。 
3. 对于每个数字：

 - 如果数字小于`target`, 增量`smaller_count`。 
- 如果数量等于`target`, 增量`equal_count`。 
4. 处理数组后：

 - 排序数组中的第一个目标索引是`smaller_count`。 
- 既然有`equal_count`目标的副本，索引将是：```
smaller_count
smaller_count + 1
...
smaller_count + equal_count - 1
```1. 使用此范围的索引构建结果列表。 
2. 返回结果列表。 

### 为什么它有效

 对所有小于的值进行排序`target`在每次出现之前`target`。 因此，元素数量小于`target`直接确定第一目标位置。 

由于所有相等的值在排序后变得连续，因此目标正好占据`equal_count`位置从`smaller_count`。 这保证了构造的索引列表与以下索引完全匹配`target`在已排序的数组中。 

## Python 解决方案```python
from typing import List

class Solution:
    def targetIndices(self, nums: List[int], target: int) -> List[int]:
        smaller_count = 0
        equal_count = 0

        for num in nums:
            if num < target:
                smaller_count += 1
            elif num == target:
                equal_count += 1

        return list(range(smaller_count, smaller_count + equal_count))
```实现首先初始化两个计数器。 第一个计数器跟踪有多少数字严格小于目标，而第二个计数器跟踪有多少数字等于目标。 

该循环只对每个数字处理一次。 使用`elif`确保等于目标的数字不会被视为较小的数字。 

遍历完成后，我们确切地知道目标块在排序数组中的起始位置以及长度。 这`range`调用生成每个有效的目标索引，并将其转换为列表生成所需的返回类型。 

如果目标不存在，`equal_count`变成`0`，并且范围为空，正确返回空列表。 

## 解决方案```go
func targetIndices(nums []int, target int) []int {
	smallerCount := 0
	equalCount := 0

	for _, num := range nums {
		if num < target {
			smallerCount++
		} else if num == target {
			equalCount++
		}
	}

	result := make([]int, 0, equalCount)

	for i := 0; i < equalCount; i++ {
		result = append(result, smallerCount+i)
	}

	return result
}
```Go 解决方案遵循与 Python 版本完全相同的逻辑。 由于 Go 没有像 Python 那样的内置范围到列表转换，因此我们显式创建一个切片并手动附加每个索引。 

结果切片用容量初始化`equalCount`，这避免了追加期间不必要的重新分配。 

如果目标没有出现在数组中，`equalCount`变成`0`，并且该函数正确返回一个空切片。

 ## 边缘情况

 ### 目标不存在

 错误的一个常见来源是忘记处理目标从未出现的情况。 在这种情况下，`equal_count`遗迹`0`。 

例如：```
nums = [1,2,3]
target = 4
```生成的范围变为：```
range(3, 3)
```它正确地生成一个空列表。 

### 所有元素都等于目标

 如果每个值都等于目标，则没有值小于目标。 

例如：```
nums = [2,2,2]
target = 2
```这里：```
smaller_count = 0
equal_count = 3
```算法正确生成：```
[0,1,2]
```这验证了该实现是否正确处理从索引开始的连续目标位置`0`。 

### 目标仅出现一次

 单一出现的情况可能会暴露范围生成中的逐一错误。 

例如：```
nums = [5,1,3]
target = 3
```计数后：```
smaller_count = 1
equal_count = 1
```生成的索引变为：```
range(1, 2)
```哪个正确地产生`[1]`。 

这证实了范围构造中的上限得到了正确处理。
