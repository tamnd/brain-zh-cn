 # LeetCode 87 - 打乱字符串

 ## 问题理解

 这个问题要求我们确定是否可以使用特定的递归加扰过程将一个字符串转换为另一个字符串。 

我们有两个字符串，`s1`和`s2`，并且保证它们具有相同的长度。 加扰过程递归地进行。 在每一步中，我们都可以将字符串拆分为两个非空部分，可以选择交换这些部分，然后递归地将相同的过程应用于两半。 

关键的挑战是加扰并不是简单地任意重新排序字符。 这种转换必须由重复的二进制分裂和可选的交换产生。 这意味着某些具有相同字符的字符串仍然不是有效的扰乱。 

例如，`"great"`可以成为`"rgeat"`通过递归分区和选择性交换。 然而，`"abcde"`不能成为`"caebd"`即使两者包含完全相同的字母。 

输入包括：

 -`s1`, 原始字符串
 -`s2`, 目标字符串

 预期输出是：

 -`true`如果`s2`可以从生成`s1`通过递归置乱
 -`false`否则

 约束条件很重要：

 -`1 <= s1.length <= 30`- 字符串仅包含小写英文字母。 
-`s1.length == s2.length`相对较小的最大长度`30`强烈建议指数强力搜索在概念上是可能的，但必须进行大量优化才能在时间限制内通过。 由于递归分割会产生许多重叠的子问题，因此动态编程或记忆化成为强有力的候选者。 

有几个重要的边缘情况需要预先考虑。 

如果两个字符串相同，则立即得到答案`true`，因为不需要加扰。 

如果字符串包含不同的字符频率，则答案必须是`false`。 打乱只会重新排列结构，不会改变字符。 

单字符字符串是另一个重要的情况。 如果两个字符都匹配，则答案是`true`; 否则，就是`false`。 

简单的实现也可能会在重复字符上失败，例如`"aabb"`和`"abab"`，其中许多递归分区看起来相似。 记忆对于避免重复重新计算相同的子问题是必要的。 

## 方法

 ### 暴力递归搜索

 最直接的方法是递归地模拟加扰过程。 

在每次递归调用时，我们都会尝试每个可能的分割位置。 假设当前子串的长度`n`。 我们可以在每个索引处将其拆分`1`到`n - 1`。 

对于每个分割，我们测试两种可能性：

 1. 不交换：

 - 左侧部分`s1`匹配左侧部分`s2`- 右侧部分`s1`匹配正确的部分`s2`2、交换：

 - 左侧部分`s1`匹配正确的部分`s2`- 右侧部分`s1`匹配左侧部分`s2`如果任何分区递归地工作，则字符串是有效的扰乱。 

这种方法是正确的，因为它完全按照加扰规则定义的方式探索每种可能的递归拆分和交换决策。 

不幸的是，它非常慢。 相同的子串组合被重复重新计算，产生大量重叠。 即使对于中等长度的字符串，递归状态的数量也会呈爆炸性增长。 

### 最优方法，记忆化动态规划

 关键的见解是递归子问题经常重复。 

假设我们已经确定是否`"great"`可以闯入`"rgeat"`。 如果这种精确比较在递归中再次出现得更深，则重新计算它是浪费的。 

我们可以使用由以下键控的缓存来记忆结果`(substring1, substring2)`。 

另一个主要优化是字符频率修剪。 

在尝试递归分区之前，我们会比较字符数。 如果两个子字符串不包含相同的字母多重集，则不可能进行置乱，我们可以立即返回`false`。 

这种修剪极大地减少了搜索空间。 

由此产生的算法成为自上而下的动态规划解决方案：

 - 递归测试所有分割位置。 
- 缓存重复状态的结果。 
- 使用字符频率检查修剪不可能的分支。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数，大约为 O(2^n * n!) | O(n) 递归 | 反复探索所有拆分/交换的可能性 |
 | 最佳| O(n⁴) | O(n3) | 记忆化避免重复劳动，剪枝提高效率 |

 ## 算法演练

 ### 最优算法，记忆 DFS

 1. **检查字符串是否已经相等**

 如果当前两个子串相同，则立即返回`true`。 

这很重要，因为相同的子串不需要加扰并且允许递归快速终止。 
2. **检查字符频率**

 在探索递归拆分之前，请验证两个子字符串包含相同的字符。 

由于加扰永远不会改变字符数，因此不匹配的频率肯定会导致失败。 

例如：

-`"abc"`和`"abd"`→ 不可能
 -`"great"`和`"rgeat"`→ 还是有可能的
 3. **检查记忆结果**

 使用缓存来存储先前计算的状态。 

关键是`(substring1, substring2)`。 

如果我们已经解决了这个子问题，则立即返回缓存的答案。 
4. **尝试每个分体位置**

 对于长度为的子串`n`，尝试在索引处拆分：`1`通过`n - 1`对于每个分割索引`i`，测试两种有效的打乱可能性。 
5. **情况1，无交换**

 在同一索引处拆分两个字符串：```
s1 = left1 + right1
s2 = left2 + right2
```递归检查：```
left1 matches left2
AND
right1 matches right2
```6. **情况2，互换**

 斯普利特`s2`不同的是：```
s1 = left1 + right1
s2 = right2 + left2
```递归检查：```
left1 matches right2
AND
right1 matches left2
```7. **将结果存储在记忆表中**

 如果任一情况成功，则缓存`true`。 

否则，在测试所有拆分后，缓存`false`。 
8. **返回最终答案**

 递归最终解决是否`s2`是一个有效的打乱`s1`。 

### 为什么它有效

 该算法是正确的，因为它完全反映了加扰的递归定义。 

每个有效的打乱必须来自某个分割位置，并且保留或交换子顺序。 通过测试每一种分割和两种结构的可能性，我们详尽地探索了所有合法的争夺转换。 

记忆不会改变正确性。 它只能防止重新计算相同的子问题。 字符频率修剪也是安全的，因为加扰会保留字符计数，这意味着任何不匹配都会导致成功不可能。 

## Python 解决方案```python
from functools import lru_cache
from collections import Counter

class Solution:
    def isScramble(self, s1: str, s2: str) -> bool:
        if len(s1) != len(s2):
            return False

        @lru_cache(maxsize=None)
        def dfs(str1: str, str2: str) -> bool:
            # Exact match
            if str1 == str2:
                return True

            # Character frequency pruning
            if Counter(str1) != Counter(str2):
                return False

            n = len(str1)

            # Try every split point
            for split_index in range(1, n):
                # Case 1: No swap
                no_swap = (
                    dfs(str1[:split_index], str2[:split_index])
                    and dfs(str1[split_index:], str2[split_index:])
                )

                if no_swap:
                    return True

                # Case 2: Swap
                swap = (
                    dfs(str1[:split_index], str2[n - split_index:])
                    and dfs(str1[split_index:], str2[:n - split_index])
                )

                if swap:
                    return True

            return False

        return dfs(s1, s2)
```为了安全起见，实现从长度检查开始，尽管问题保证了相等的长度。 

递归辅助函数`dfs()`代表核心动态规划状态。 它回答了这个问题：

 > 可以`str2`通过扰乱形成`str1`？ 

这`@lru_cache`装饰器自动记住结果。 这可以防止重新计算重复的子串对。 

首先进行相等性检查，因为精确匹配是非常有效的扰乱。 

接下来是字符频率修剪步骤，使用`Counter`。 这会尽早消除不可能的分支。 

该循环尝试每个可能的分割索引。 对于每个分割，我们测试两个有效的递归结构：

 - 保持顺序不变
 - 交换左右分区

 如果任一递归分支成功，我们立即返回`True`。 

如果没有分割，子串就不能互相打乱，所以我们返回`False`。 

## 解决方案```go
func isScramble(s1 string, s2 string) bool {
	if len(s1) != len(s2) {
		return false
	}

	memo := make(map[string]bool)
	visited := make(map[string]bool)

	var dfs func(string, string) bool

	dfs = func(str1 string, str2 string) bool {
		key := str1 + "#" + str2

		if visited[key] {
			return memo[key]
		}

		visited[key] = true

		// Exact match
		if str1 == str2 {
			memo[key] = true
			return true
		}

		// Character frequency pruning
		count := [26]int{}

		for i := 0; i < len(str1); i++ {
			count[str1[i]-'a']++
			count[str2[i]-'a']--
		}

		for _, value := range count {
			if value != 0 {
				memo[key] = false
				return false
			}
		}

		n := len(str1)

		// Try every split
		for splitIndex := 1; splitIndex < n; splitIndex++ {

			// Case 1: No swap
			if dfs(str1[:splitIndex], str2[:splitIndex]) &&
				dfs(str1[splitIndex:], str2[splitIndex:]) {
				memo[key] = true
				return true
			}

			// Case 2: Swap
			if dfs(str1[:splitIndex], str2[n-splitIndex:]) &&
				dfs(str1[splitIndex:], str2[:n-splitIndex]) {
				memo[key] = true
				return true
			}
		}

		memo[key] = false
		return false
	}

	return dfs(s1, s2)
}
```Go 实现遵循与 Python 相同的递归结构，但使用映射进行记忆。 

由于 Go 没有内置的记忆化装饰器，例如`lru_cache`，我们使用两个映射手动管理缓存：

 -`memo`存储计算结果
 -`visited`跟踪状态是否已被评估

 而不是`Counter`, Go 使用长度固定的频率数组`26`，这对于小写英文字母更有效。 

Go 中的字符串切片可以有效地处理子字符串，使递归变得简单。 

整数溢出不是问题，因为所有值在约束范围内仍然非常小。

 ## 边缘情况

 ### 单字符串

 最小有效输入长度为`1`。 

例如：```
s1 = "a"
s2 = "a"
```有错误的实现可能仍会尝试递归拆分，这会失败，因为不存在拆分。 我们的实现通过立即检查相等性来避免这种情况。 如果字符串匹配，我们返回`true`没有递归。 

### 相同字符但乱序结构无效

 具有相同字符数的两个字符串并不能保证成功。 

例子：```
s1 = "abcde"
s2 = "caebd"
```仅基于排序或频率比较的简单解决方案将错误地返回`true`。 

我们的递归拆分检查确保转换遵循有效的加扰规则，而不仅仅是字符重新排列。 

### 重复字符

 重复的字符会产生许多重复的递归状态。 

例子：```
s1 = "aabb"
s2 = "abab"
```如果没有记忆，递归可能会重复重新计算相同的子串关系，从而导致严重的性能问题。 

记忆缓存确保每个子串对都被解决一次，从而防止指数爆炸。 

### 相同的字符串

 有时不需要加扰。 

例子：```
s1 = "great"
s2 = "great"
```如果没有等式捷径，算法将不必要地递归地探索每个分割。 

我们的实施立即返回`true`当子串相等时，大大提高效率。
