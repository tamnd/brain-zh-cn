[LeetCode 第 7 题](https://leetcode.com/problems/reverse-integer/)

 **难度：** 🟡 中等
 **主题：** 数学

 ## 解决方案

 ## 问题理解

 该问题要求我们反转有符号 32 位整数的数字。 给定一个整数`x`，我们必须返回一个新的整数，其数字以相反的顺序出现，同时保留符号。 

例如，如果输入是`123`，反转数字产生`321`。 如果输入是`-123`，反转后的结果变为`-321`。 反转后的数字中的前导零不应出现在最终答案中，因此反转`120`产生`21`， 不是`021`。 

最重要的约束是要求最终结果必须保持在有符号的 32 位整数范围内：

 - 最小值：`-2^31 = -2147483648`- 最大值：`2^31 - 1 = 2147483647`如果反转后的整数超出这个范围，我们必须返回`0`。 

另一个关键限制是环境不允许存储 64 位整数。 这意味着我们不能先安全地反转该数字，然后再检查它是否溢出。 我们必须在溢出发生之前检测到它。 

输入保证已经适合 32 位有符号整数范围，因此我们只需要担心反转过程本身的溢出问题。 

一些边缘情况很重要：

 - 负数必须保留其符号。 
- 以零结尾的数字在反转后会丢失前导零。 
- 反转后非常大的数字可能会溢出。 
- 零应该简单地返回零。 
- 最小 32 位整数特别棘手，因为它的反转形式会溢出。 

## 方法

 ### 蛮力方法

 一种简单的方法是将整数转换为字符串，反转字符串，然后将其转换回整数。 

例如：

 - 转换`123`到`"123"`- 将其反转为`"321"`- 转换回整数`321`对于负数，我们可以暂时去掉符号，反转数字，然后再恢复符号。 

这种方法在许多情况下都能正确工作并且易于实施。 然而，它违反了问题的精神，因为该问题特别强调整数操作和溢出处理，而不依赖于更大的整数存储。 

此外，在具有固定宽度整数的语言中，在我们验证结果之前，将反转的数字转换回整数可能已经溢出。 

### 最优数学方法

 更好的方法是使用算术运算逐位反转整数。 

关键的见解是我们可以反复：

 1. 使用模提取最后一位数字。 
2. 使用整数除法删除最后一位数字。 
3. 将提取的数字附加到反转的数字上。 

例如：

-`123 % 10 = 3`-`123 // 10 = 12`- 逐步建立反向数字。 

关键的挑战是溢出检测。 

在添加数字之前，我们检查是否将当前反转的数字乘以`10`将超出 32 位整数限制。 这使我们能够在溢出发生之前安全地避免溢出。 

这种方法满足所有约束并且仅使用恒定的额外空间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(d) | O(d) | 使用字符串转换，其中`d`是位数 |
 | 最佳 | O(d) | O(1) | O(1) | 通过溢出检查以数学方式反转数字 |

 ## 算法演练

 1. 初始化变量`reversed_num`到`0`。 该变量将存储逐步反转的整数。 
2. 定义 32 位整数边界：

 -`INT_MAX = 2147483647`-`INT_MIN = -2147483648`3. 重复同时`x`不为零。 
4. 使用模提取最后一位数字：

 -`digit = x % 10`5. 删除最后一位数字`x`使用整数除法：

 -`x = x // 10`6. 在Python中，负模的行为与其他一些语言不同，因此我们适当调整负数：

 - 如果`digit > 7`, 减去`10`从`digit`并添加`1`回到`x`。 
7. 更新前`reversed_num`，检查是否乘以`10`会溢出：

 - 如果`reversed_num > INT_MAX // 10`，就会发生溢出。 
- 如果`reversed_num == INT_MAX // 10`和`digit > 7`，就会发生溢出。 
- 同样检查负溢出的下限。 
8. 如果发生溢出，立即返回`0`。 
9. 否则，安全地附加数字：

 -`reversed_num = reversed_num * 10 + digit`10. 继续，直到处理完所有数字。 
11. 返回`reversed_num`。 

### 为什么它有效

 在每次迭代中，算法都会从原始数字中删除一位数字，并将其附加到反转数字的正确位置。 不变的是`reversed_num`始终包含迄今为止处理的数字的正确反转版本。 

溢出检查保证我们永远不会创建超出 32 位有符号整数范围的值。 由于每个数字都只处理一次，因此如果符合界限，则最终结果是正确反转的整数，否则`0`。 

## Python 解决方案```python
class Solution:
    def reverse(self, x: int) -> int:
        INT_MAX = 2147483647
        INT_MIN = -2147483648

        reversed_num = 0

        while x != 0:
            digit = x % 10
            x = x // 10

            # Adjust for Python's modulo behavior with negatives
            if digit > 7:
                digit -= 10
                x += 1

            # Check positive overflow
            if (
                reversed_num > INT_MAX // 10 or
                (reversed_num == INT_MAX // 10 and digit > 7)
            ):
                return 0

            # Check negative overflow
            if (
                reversed_num < INT_MIN // 10 or
                (reversed_num == INT_MIN // 10 and digit < -8)
            ):
                return 0

            reversed_num = reversed_num * 10 + digit

        return reversed_num
```实现首先定义 32 位整数边界。 这些常数在整个算法中使用，以确保反转的值永远不会超过有效限制。 

变量`reversed_num`存储反转的整数，因为它是逐位构造的。 

在循环内，使用模运算提取最后一位数字。 然后使用整数除法缩短原始数字。 

Python 处理负除法和取模的方式与 C++ 或 Java 等语言不同。 具体来说，Python 的模运算符总是产生非负余数。 调整步骤纠正此行为，以便数字提取与负整数的预期数学行为相匹配。 

在添加新数字之前`reversed_num`，代码检查是否乘以`10`并且附加数字将超出允许的整数范围。 如果是，该函数立即返回`0`。 

最后，将该数字附加到反转的数字上，并继续该过程，直到处理完所有数字。 

## 解决方案```go
func reverse(x int) int {
	const INT_MAX = 2147483647
	const INT_MIN = -2147483648

	reversedNum := 0

	for x != 0 {
		digit := x % 10
		x /= 10

		// Check positive overflow
		if reversedNum > INT_MAX/10 ||
			(reversedNum == INT_MAX/10 && digit > 7) {
			return 0
		}

		// Check negative overflow
		if reversedNum < INT_MIN/10 ||
			(reversedNum == INT_MIN/10 && digit < -8) {
			return 0
		}

		reversedNum = reversedNum*10 + digit
	}

	return reversedNum
}
```Go 的实现稍微简单一些，因为 Go 的整数除法和负数的取模行为已经与所需的零截断相匹配。 因此，Python 中所需的额外调整逻辑是不必要的。 

溢出处理遵循与 Python 解决方案完全相同的逻辑。 由于 Go 整数是固定宽度的，因此在乘法之前进行检查对于避免无效值至关重要。

 ## 边缘情况

 一种重要的边缘情况是以零结尾的数字，例如`120`。 幼稚的实现可能会错误地保留反转结果中的前导零，并产生类似的结果`021`。 由于整数不存储前导零，因此正确的结果很简单`21`。 这个实现自然地处理了这个问题，因为乘以`10`添加数字会自动跳过无关紧要的前导零。 

另一个关键的边缘情况是整数溢出。 例如，倒车`1534236469`产生`9646324351`，超过了 32 位有符号整数最大值。 如果在乘法和加法之前没有执行溢出检查，程序可能会产生不正确的值或内部溢出。 该实现通过在更新之前检查边界来防止这种情况发生`reversed_num`。 

负数也是错误的常见来源，因为不同编程语言的取模和除法行为有所不同。 具体来说，在 Python 中，负模结果与 Go 或 Java 等语言不同。 调整逻辑确保数字提取对于负输入表现正确，从而允许算法为以下情况生成准确的反转值`-123`。 

最小 32 位整数，`-2147483648`，是另一个微妙的情况。 其反转后的值超出了有效的整数范围。 溢出检测逻辑正确识别此条件并返回`0`在溢出发生之前。
