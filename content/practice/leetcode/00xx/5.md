 ## 解决方案

 # 最长回文子串

 该问题要求我们找到给定字符串中最长的回文子串。 回文是向前和向后读取相同的序列。 子字符串必须是连续的，这意味着字符必须在原始字符串中彼此相邻出现。 

例如，在字符串中`"babad"`, 子串`"bab"`和`"aba"`都是长度为 3 的回文，因此其中一个都是有效答案。 在字符串中`"cbbd"`，最长的回文子串是`"bb"`。 

输入是单个字符串`s`，输出是另一个字符串，表示在其中找到的最长回文子串`s`。 

约束条件很重要：

 - 字符串长度在 1 到 1000 之间。 
- 字符串仅包含数字和英文字母。 

最大长度为 1000 意味着一种极其缓慢的解决方案（例如检查每个可能的子字符串并独立验证每个子字符串）可能在某些语言中仍然有效，但并不理想。 我们应该以更高效的方式为目标。 

一些边缘情况很重要：

 - 只有一个字符的字符串，例如`"a"`，已经是一个回文。 
- 每个字符都相同的字符串，例如`"aaaa"`，应该返回整个字符串。 
- 没有重复字符的字符串，例如`"abcde"`，应该返回任何单个字符。 
- 偶数长度回文，例如`"abba"`，需要特殊处理，因为它们的中心位于两个字符之间。 
- 奇数长度回文，例如`"racecar"`，有一个中心角色。 

## 方法

 ### 蛮力方法

 暴力解决方案生成每个可能的子串并检查每个子串是否是回文。 

一个长度的字符串`n`大约有`n²`子串。 对于每个子串，我们可以通过从两端向内比较字符来检查它是否是回文。 回文检查本身需要`O(n)`最坏情况下的时间。 

这给出了总体复杂度`O(n³)`。 

蛮力方法是正确的，因为它详尽地检查了每个可能的子串并跟踪找到的最长的有效回文。 然而，随着输入大小的增加，它变得低效。 

### 最优方法，围绕中心展开

 关键的观察是每个回文都有一个中心。 

对于奇数长度回文，中心是单个字符：```
racecar
   ^
```对于偶数长度的回文，中心位于两个字符之间：```
abba
 ^^
```Instead of checking every substring independently, we can expand outward from every possible center and stop as soon as the characters no longer match.

 由于有`n`可能的奇数中心和`n - 1`甚至可能是中心，我们最多执行`2n - 1`扩展。 每次扩展最多可能需要`O(n)`最坏情况下的时间，总体复杂度为`O(n²)`。 

这比暴力解决方案要快得多，并且在限制范围内可以轻松工作。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n3) | O(1) | O(1) | 生成每个子字符串并单独检查每个回文 |
 | 最佳 | O(n²) | O(1) | O(1) | 从每个可能的回文中心向外扩展 |

 1. 初始化变量以跟踪迄今为止找到的最佳回文。 

我们存储处理过程中发现的最长回文的起始索引和结束索引。 
2. 迭代字符串中的每个索引。 

每个字符都可以作为奇数长度回文的中心。 此外，相邻字符之间的每个间隙都可以充当偶数长度回文的中心。 
3. 围绕奇数长度中心展开。 

从两个指针位于同一索引处开始。 当左右字符匹配并保持在边界内时，继续向外扩展。 
4. 围绕等长中心展开。 

从当前索引处的左指针开始，从下一个索引处开始右指针。 再次，在字符匹配时继续扩展。 
5. 将发现的回文长度与当前最佳长度进行比较。 

如果新的回文更长，则更新存储的边界。 
6. 继续，直到所有中心均已处理完毕。 

一旦探索完每个中心，存储的子串边界就代表最长的回文。 
7. 使用保存的索引返回子字符串。 

### 为什么它有效

 每个回文必须有一个中心。 通过从每个可能的中心向外扩展，该算法保证最终会考虑字符串中的每个有效回文。 由于我们总是跟踪迄今为止找到的最长回文子串，因此最终结果必定是最长的回文子串。 

## Python 解决方案```python
class Solution:
    def longestPalindrome(self, s: str) -> str:
        if len(s) < 2:
            return s

        start = 0
        end = 0

        def expand(left: int, right: int) -> tuple[int, int]:
            while left >= 0 and right < len(s) and s[left] == s[right]:
                left -= 1
                right += 1

            return left + 1, right - 1

        for i in range(len(s)):
            # Odd-length palindrome
            left1, right1 = expand(i, i)

            # Even-length palindrome
            left2, right2 = expand(i, i + 1)

            if right1 - left1 > end - start:
                start, end = left1, right1

            if right2 - left2 > end - start:
                start, end = left2, right2

        return s[start:end + 1]
```实施从一个小的优化开始。 如果字符串长度小于2，则字符串本身已经是最长的回文。 

这`expand`辅助函数执行核心逻辑。 它接收两个代表潜在回文中心的索引。 当两侧的字符匹配时，它会向外扩展。 

当循环停止时，指针已经移动了一步，因此函数返回`left + 1`和`right - 1`恢复有效的回文边界。 

在主循环内，我们为每个索引处理两种情况：

 - 使用奇数长度回文`(i, i)`- 使用偶数长度回文`(i, i + 1)`每次扩展后，我们将所得回文长度与当前最佳回文长度进行比较。 如果新的回文更长，我们更新存储的索引。 

最后，我们使用 Python 切片返回子字符串。 

## 解决方案```go
func longestPalindrome(s string) string {
    if len(s) < 2 {
        return s
    }

    start := 0
    end := 0

    expand := func(left int, right int) (int, int) {
        for left >= 0 && right < len(s) && s[left] == s[right] {
            left--
            right++
        }

        return left + 1, right - 1
    }

    for i := 0; i < len(s); i++ {
        // Odd-length palindrome
        left1, right1 := expand(i, i)

        // Even-length palindrome
        left2, right2 := expand(i, i+1)

        if right1-left1 > end-start {
            start = left1
            end = right1
        }

        if right2-left2 > end-start {
            start = left2
            end = right2
        }
    }

    return s[start : end+1]
}
```Go 的实现与 Python 解决方案非常相似。 一个重要的区别是字符串切片语法。 在 Go 中，使用以下命令返回子字符串`s[start : end+1]`。 

Go 字符串是不可变的字节切片，因此索引直接对字节进行操作。 由于该问题仅保证英文字母和数字，因此字节索引在这里是安全的。 如果允许使用 Unicode 字符，则需要符文转换。

 ## 边缘情况

 ### 单字符串

 仅包含一个字符的字符串通常是回文。 幼稚的实现有时会失败，因为它们假设至少存在两个字符用于扩展。 此实现立即处理该情况：```
if len(s) < 2:
    return s
```### 偶数回文

 许多不正确的解决方案仅围绕单个字符中心展开，这会错过诸如`"abba"`或者`"cbbd"`。 

此实现显式检查以下两项：```
expand(i, i)
expand(i, i + 1)
```第二个扩展正确处理位于字符之间的中心。 

### 具有重复字符的字符串

 输入如`"aaaaaa"`可能会导致许多相同字符的重复扩展。 某些实现意外地过早终止或无法正确更新最长回文。 

由于此解决方案在字符匹配时完全扩展，并且始终在更新结果之前比较长度，因此它会正确返回整个字符串。 

### 不存在长回文

 对于像这样的字符串`"abcdef"`，每个回文的长度都是 1。如果没有找到更大的回文，某些实现会错误地返回空字符串。 

该解决方案将结果边界初始化为第一个字符，确保至少一个有效的回文始终存在。
