[LeetCode 第 41 题](https://leetcode.com/problems/first-missing-positive/)

 **难度：** 🔴难
 **主题：** 数组、哈希表

 ## 解决方案

 ## 问题理解

 该问题要求我们找到没有出现在未排序整数数组中的最小正整数。 

关键细节是我们只关心从以下位置开始的正整数`1`。 负数、零和非常大的正数是无关的，除非它们影响较小正整数的放置。 

例如：

 - 在`[1,2,0]`, 数字`1`和`2`存在，所以最小的缺失正数是`3`。 
- 在`[3,4,-1,1]`, 数量`1`存在但是`2`没有，所以答案是`2`。 
- 在`[7,8,9,11,12]`, 数量`1`本身缺失，所以答案是`1`。 

约束条件极其重要：

 - 数组长度可以大到`10^5`- 解决方案必须运行在`O(n)`时间
 - 解决方案必须使用`O(1)`辅助空间

 这些限制立即消除了许多直接的方法。 例如，排序需要`O(n log n)`时间，按照严格要求来说太慢了。 使用哈希集可以实现`O(n)`时间，但需要`O(n)`额外的空间，这也违反了要求。 

一个重要的观察是对于长度的数组`n`，答案必须在范围内`[1, n + 1]`。 

为什么？ 

- 如果每个数字来自`1`到`n`存在，那么答案是`n + 1`- 否则，某些数字`[1, n]`is missing

 这意味着数字小于或等于`0`，并且数字大于`n`，可以安全地忽略，因为它们不会影响最终答案。 

一些边缘情况很重要：

 - 仅包含负数的数组
 - 数组丢失`1`- 包含重复项的数组
 - 数组已经包含来自的所有数字`1`到`n`- 包含非常大的不相关值的数组

 挑战在于就地重新排列数组，以便将每个值放置在其逻辑所属的位置。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是反复检查是否`1`存在，那么是否`2`存在，那么`3`， 等等。 

对于每个候选数字，我们扫描整个数组来寻找它。 第一个未找到的数字就是答案。 

这是可行的，因为最终我们必须遇到一个丢失的正整数。 

但时间复杂度太大。 在最坏的情况下，对于长度的数组`n`，我们可以扫描数组`n`次，导致`O(n^2)`复杂。 

另一种常见的强力改进是使用哈希集：

 - 将每个数字插入一组
 - 开始于`1`- 返回集合中未找到的第一个数字

 这样就达到了`O(n)`时间，但需要`O(n)`额外的空间，违反了问题的约束。 

### 最佳解决方案的关键见解

 关键的见解是每个正整数`x`在范围内`[1, n]`属于索引`x - 1`。 

例如：

-`1`应该在索引处`0`-`2`应该在索引处`1`-`3`应该在索引处`2`如果我们重新排列数组，以便将每个有效数字放置到正确的位置，那么我们可以随后扫描数组：

 - 如果`nums[i] != i + 1`， 然后`i + 1`失踪了
 - 如果每个位置都是正确的，那么答案是`n + 1`这种技术之所以有效，是因为数组本身就像一个哈希图，使我们能够实现恒定的辅助空间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 重复扫描数组中的每个正整数 |
 | 最佳 | O(n) | O(1) | O(1) | 将每个数字放入正确的索引位置 |

 ## 算法演练

 ### 最佳就地循环放置算法

 1. 从左到右迭代数组。 

对于每个位置`i`，检查当前值`nums[i]`。 
2. 判断当前数字是否属于数组中的某个位置。 

仅当满足以下条件时，数字才有用：

 - 这是积极的
 - 小于或等于`n`此范围之外的数字不会影响最小的缺失阳性。 
3. 计算当前值的正确位置。 

如果当前值为`x`，那么它的正确索引是：$\text{target index} = x - 1$4. 将当前数字交换到正确的位置。 

假设我们在索引处`i`其值为`x`。 

如果：

-`1 <= x <= n`-`nums[x - 1] != x`然后交换：```
nums[i] <-> nums[x - 1]
```这个地方`x`到它所属的位置。 
5. 继续交换，直到当前位置稳定。 

交换后，新值为`nums[i]`也可能属于其他地方。 因此，我们继续处理相同的索引，直到：

 - 该值无效
 - 该值已经位于正确的位置
 - 重复会创建无限交换循环
 6. 放置阶段完成后，再次扫描阵列。 

在索引处`i`：

- 如果`nums[i] != i + 1`- 然后`i + 1`是最小的缺失阳性
 7. 如果每个位置都正确，则返回`n + 1`。 

这意味着所有整数`1`通过`n`存在。 

### 为什么它有效

 该算法保持不变性，即只要有可能，每个有效数字`x`已移至索引`x - 1`。 

重排阶段后：

 - 如果是一个数字`k`存在于数组中，它将被放置在索引处`k - 1`- 因此，该属性失败的第一个索引直接标识丢失的正整数

 由于每次交换都至少将一个数字放入其最终位置，因此整个算法的交换总数是线性的。 

## Python 解决方案```python
from typing import List

class Solution:
    def firstMissingPositive(self, nums: List[int]) -> int:
        n = len(nums)

        i = 0
        while i < n:
            current = nums[i]
            correct_index = current - 1

            if (
                1 <= current <= n
                and nums[correct_index] != current
            ):
                nums[i], nums[correct_index] = (
                    nums[correct_index],
                    nums[i],
                )
            else:
                i += 1

        for i in range(n):
            if nums[i] != i + 1:
                return i + 1

        return n + 1
```该实现遵循前面描述的确切算法。 

首先，我们将数组长度存储在`n`。 这有助于确定哪些值是相关的。 仅限范围内的数字`[1, n]`可能会影响答案。 

这`while`循环执行就地放置过程。 与标准不同`for`在循环中，我们并不总是立即推进索引，因为在交换之后，当前索引处新到达的值可能也需要重新定位。 

对于每个值：

 - 我们使用以下方法计算其预期位置`current - 1`- 我们检查该值是否有效
 - 我们确保不会交换重复项

 如果该值属于其他位置，我们将其交换到正确的位置。 

一旦每个有效数字都被正确定位，第二个循环就会从左到右扫描数组。 第一个地点是`nums[i] != i + 1`揭示缺失的正整数。 

如果不存在不匹配，则来自的所有数字`1`通过`n`存在，所以答案一定是`n + 1`。 

## 解决方案```go
func firstMissingPositive(nums []int) int {
	n := len(nums)

	i := 0
	for i < n {
		current := nums[i]
		correctIndex := current - 1

		if current >= 1 &&
			current <= n &&
			nums[correctIndex] != current {

			nums[i], nums[correctIndex] =
				nums[correctIndex], nums[i]
		} else {
			i++
		}
	}

	for i := 0; i < n; i++ {
		if nums[i] != i+1 {
			return i + 1
		}
	}

	return n + 1
}
```Go 的实现非常接近地反映了 Python 的逻辑。 

一些特定于 Go 的细节值得注意：

 - Go 切片是类似引用的结构，因此修改会自动就地进行。 
- 无需担心整数溢出，因为所有操作都涉及数组范围内的索引和比较。 
- Go 中的多重赋值语法允许干净的就地交换，无需临时变量。 
- 空切片是自然处理的，因为循环根本不执行。

 ## 边缘情况

 一种重要的边缘情况是当数组不包含`1`。 

例如：```
[2,3,4]
```最小的缺失阳性必须立即被`1`。 仅查找现有数字之间差距的简单实现可能会错误地返回另一个值。 该算法自然地处理这个问题，因为索引`0`预计将包含`1`。 在最终扫描期间，立即检测到不匹配。 

另一个关键的边缘情况涉及重复值。 

例如：```
[1,1]
```如果不仔细处理重复项，交换过程可能会进入无限循环，因为两个位置包含相同的值。 条件：```
nums[correct_index] != current
```防止不必要的交换并保证进度。 

当值超出有用范围时，就会出现第三种重要的边缘情况。 

例如：```
[-10, 100, 200]
```这些数字不会影响最小的缺失正数，因为对于长度的数组`n`，只有数字在`[1, n]`事情。 该实现在放置阶段安全地忽略这些值。 

另一个微妙的情况是当数组已经包含来自`1`通过`n`。 

例如：```
[1,2,3,4]
```在这种情况下，答案不在数组范围内，而是`n + 1`。 在扫描没有发现不匹配的情况后，最终的 return 语句正确处理了这种情况。
