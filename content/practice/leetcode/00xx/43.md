[LeetCode 第 43 题](https://leetcode.com/problems/multiply-strings/)

 **难度：** 🟡 中等
 **主题：** 数学、字符串、模拟

 ## 解决方案

 ## 问题理解

 该问题要求我们将两个非负整数相乘，其中每个整数以字符串而不是数字类型的形式提供。 结果还必须以字符串形式返回。 重要的限制是我们不能直接将字符串转换为整数或使用任何内置的大整数库。 

换句话说，我们必须手动模拟乘法过程，就像人类在纸上执行乘法一样。 

输入`num1`和`num2`是仅包含数字字符的字符串`'0'`到`'9'`。 它们的长度可以长达 200 个字符，这意味着所表示的数字可能远远大于标准整数类型可以安全存储的数字。 例如，200 位数字无法容纳在 Python、Go、Java 或 C++ 中的普通 64 位整数类型中。 

输出应该是乘积的精确十进制表示形式，不带前导零，除非答案本身是`"0"`。 

这些约束告诉我们一些重要的事情：

 - 我们不能依赖整数转换，因为数字可能超出标准数字限制。 
- 由于每个字符串最多可以包含 200 个数字，因此二次复杂度的算法是可以接受的，因为`200 × 200 = 40,000`运营是可管理的。 
- 保证输入仅包含有效数字。 
- 除特殊情况外，输入将不包含前导零`"0"`。 

有几种边缘情况很容易在简单的实现中导致错误。 

如果任一输入是`"0"`，答案必须立即是`"0"`。 忘记这一点会产生类似的输出`"0000"`。 

进位处理是另一个常见的错误来源。 在乘法期间，中间值可能超过 9，因此进位必须正确地跨位置传播。 

结果数组中的前导零也会产生问题。 由于乘法过程经常会产生未使用的前导位置，因此我们必须在构建最终字符串之前去除它们。 

最后，不同的数字对可能会导致结果中的相同位置。 正确的实现必须正确累积这些值而不是覆盖它们。 

## 方法

 ### 蛮力方法

 一个简单的暴力解决方案可以非常字面地模拟小学乘法。 对于每一个数字`num1`，我们将它与中的每个数字相乘`num2`，创建部分乘积字符串，根据位置附加适当数量的尾随零，然后使用自定义字符串添加函数将这些部分乘积重复添加在一起。 

这种方法是正确的，因为它准确地反映了传统的乘法。 每个数字贡献其加权值，对所有部分乘积求和得出最终答案。 

然而，这种方法效率低下，因为重复的字符串添加会变得昂贵。 每个部分乘积可能需要遍历先前积累的结果的大部分。 随着数字变大，重复构造和添加字符串会产生不必要的开销。 

### 最佳方法

 关键的见解是我们实际上不需要构建单独的部分产品。 相反，我们可以直接将乘法贡献累加到结果数组中。 

将两个长度相乘时`m`和`n`，乘积的最大可能位数为`m + n`。 例如：

-`99 × 99 = 9801`，其中有`2 + 2 = 4`数字
 -`123 × 456 = 56088`，其中最多有`3 + 3 = 6`数字

 因此我们可以分配一个大小的数组`m + n`直接存储数字贡献。 

如果数字位于`i`和`j`相乘，他们的贡献属于附近位置`i + j + 1`在结果数组中。 这反映了手动乘法中位值的工作方式。 

我们不构建临时字符串，而是不断累积值并就地传播进位。 这避免了重复的字符串相加，并给出了干净的二次时间解。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(m × n + n 加法) | O(m + n) | 构建部分产品并重复添加字符串 |
 | 最佳 | O(m × n) | O(m + n) | 直接将乘积累加到结果数组中 |

 ## 算法演练

 1. 首先，处理任一输入为的特殊情况`"0"`。 在这种情况下，产品立即`"0"`。 
2.让`m`的长度为`num1`和`n`的长度为`num2`。 创建一个大小为结果的数组`m + n`，用零初始化。 该数组将存储最终产品的各个数字。 
3. 从右向左遍历两个字符串。 我们从最低有效位到最高有效位处理数字，因为乘法自然会将进位传播到更有效的位置。 
4. 对于每对数字：

 - 将字符数字转换为整数。 
- 将它们相乘。 
- 确定该产品在结果数组中的贡献位置。 

如果索引是`i`和`j`，那么：

 - 个位转到位置`i + j + 1`- 进位到达位置`i + j`5. 将乘法结果与已存储的当前值相加`result[i + j + 1]`。 这很重要，因为多个数字对可能会导致同一位置。 
6. 将个位存储在`result[i + j + 1]`使用模 10。 
7. 添加进位值`result[i + j]`使用整数除以 10。 
8. 处理完所有数字对后，结果数组包含完整的数字，但可能以前导零开头。 
9. 在构建最终字符串时跳过所有前导零。 
10. 将剩余的数字转换为字符并将它们连接成最终的答案字符串。 

### 为什么它有效

 该算法之所以有效，是因为它精确地模拟了位置十进制乘法。 

将位置上的两位数字相乘时`i`和`j`，他们的贡献属于小数点后位`i + j + 1`相对于最终结果。 每个乘法贡献都被累积到正确的位置，并且进位立即传播。 

由于每对数字都被处理一次并且所有进位都被保留，因此最终的数组代表了乘积的正确十进制扩展。 

## Python 解决方案```python
class Solution:
    def multiply(self, num1: str, num2: str) -> str:
        if num1 == "0" or num2 == "0":
            return "0"

        m = len(num1)
        n = len(num2)

        result = [0] * (m + n)

        for i in range(m - 1, -1, -1):
            for j in range(n - 1, -1, -1):
                digit1 = ord(num1[i]) - ord('0')
                digit2 = ord(num2[j]) - ord('0')

                product = digit1 * digit2

                position_low = i + j + 1
                position_high = i + j

                total = product + result[position_low]

                result[position_low] = total % 10
                result[position_high] += total // 10

        start = 0
        while start < len(result) and result[start] == 0:
            start += 1

        return ''.join(str(digit) for digit in result[start:])
```实施从重要的零检查开始。 这可以避免不必要的工作并保证正确的格式，例如`"0" × "52"`。 

这`result`数组分配了大小`m + n`因为乘积的最大位数不能超过这个值。 

嵌套循环从右向左迭代，以便乘法从最低有效数字向更高有效数字进行，就像手动算术一样。 

对于每个数字对，代码计算乘法结果并确定结果数组中的正确位置。 已经存储在目标位置的当前值被包括在内，因为先前的乘法可能较早地在那里做出了贡献。 

模运算提取当前数字，而整数除法计算进位。 进位被累积到下一个更高的位置。 

最后，在构造最终字符串之前会跳过前导零。 

## 解决方案```go
func multiply(num1 string, num2 string) string {
    if num1 == "0" || num2 == "0" {
        return "0"
    }

    m := len(num1)
    n := len(num2)

    result := make([]int, m+n)

    for i := m - 1; i >= 0; i-- {
        for j := n - 1; j >= 0; j-- {
            digit1 := int(num1[i] - '0')
            digit2 := int(num2[j] - '0')

            product := digit1 * digit2

            positionLow := i + j + 1
            positionHigh := i + j

            total := product + result[positionLow]

            result[positionLow] = total % 10
            result[positionHigh] += total / 10
        }
    }

    start := 0
    for start < len(result) && result[start] == 0 {
        start++
    }

    bytes := make([]byte, 0)

    for i := start; i < len(result); i++ {
        bytes = append(bytes, byte(result[i]+'0'))
    }

    return string(bytes)
}
```Go 实现遵循与 Python 版本相同的逻辑，但存在一些特定于语言的差异。 

Go 字符串内部是字节切片，因此数字提取使用如下表达式`num1[i] - '0'`。 

Go 使用使用以下命令创建的整数切片，而不是 Python 列表`make([]int, m+n)`。 

由于 Go 在整数集合上没有直接等效于 Python 的字符串连接，因此该解决方案构造一个字节切片并在最后将其转换为字符串。 

Go 整数在这里就足够了，因为最大的中间乘法仅为`9 × 9 + carry`，它很容易符合标准整数范围。

 ## 边缘情况

 当任一输入为`"0"`。 如果没有特殊检查，该算法可能会产生如下输出`"0000"`处理结果数组后。 该实现通过立即返回来避免这种情况`"0"`在执行任何乘法之前。 

另一个棘手的情况涉及级联进位，例如乘法`"999"`经过`"999"`。 中间位置可以暂时超过9倍。 有缺陷的实现可能会覆盖值而不是正确地累积它们。 该解决方案总是在分成数字和进位分量之前添加到现有的位置值中，以确保进位传播保持正确。 

结果数组中的前导零是错误的另一个常见来源。 由于数组大小固定为`m + n`，并不总是使用最重要的位置。 例如，`"12" × "12"`产生`"144"`，但数组最初有四位数字的空间。 该实现在构造最终答案字符串之前正确地跳过未使用的前导零。 

最后一个微妙的案例涉及增加位数的产品，例如`"25" × "4" = "100"`。 不正确的搬运处理可能会产生`"00"`或者`"0100"`。 该算法可以正确处理这个问题，因为在每个乘法步骤中进位都会传播到更高的位置。
