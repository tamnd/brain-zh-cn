[LeetCode 第 39 题](https://leetcode.com/problems/combination-sum/)

 **难度：** 🟡 中等
 **主题：** 数组、回溯

 ## 解决方案

 ## 问题理解

 这个问题要求我们从给定的数字中生成每种可能的唯一数字组合`candidates`数组，使得所选数字的总和等于`target`。 

问题陈述中有几个重要的细节：

 - 中的每个数字`candidates`是独特的。 
- 每个号码可以无限次使用。 
- 输出应仅包含唯一的组合。 
- 组合内的顺序并不重要。 

例如，如果`candidates = [2,3,6,7]`和`target = 7`， 然后`[2,2,3]`有效，因为：

 -`2 + 2 + 3 = 7`-`2`可以多次重复使用

 然而，`[3,2,2]`不会被视为不同的答案，因为它包含具有相同频率的相同数字。 

输入包括：

 - 整数数组`candidates`- 目标整数`target`预期输出是一个列表列表，其中每个内部列表代表一个有效组合，其总和等于目标。 

限制相对较小：

 -`candidates.length <= 30`-`target <= 40`这些约束强烈表明指数或回溯解决方案是可以接受的。 由于目标很小并且有效组合的数量保证保持在 150 以下，因此通过修剪进行穷举搜索是实用的。 

一些边缘情况很重要：

 - 不存在有效的组合，例如`candidates = [2]`和`target = 1`- 候选人直接等于目标
 - 一名候选人可以多次重复使用
 - 如果不仔细控制顺序，多个路径可能会生成相同的组合

 主要挑战是生成所有有效组合，同时避免重复。 

## 方法

 ### 蛮力方法

 朴素的暴力策略会尝试所有可能的候选选择序列，并检查总和是否等于目标。 

对于每个递归步骤，我们可以再次选择任何候选者并继续构建组合，直到：

 - 总和恰好成为目标
 - 总和超过目标

 该方法最终找到所有有效的组合，因为它探索了每种可能的构造。 

然而，这种方法有一个大问题。 它生成相同组合的重复排列。 

例如：

-`[2,2,3]`-`[2,3,2]`-`[3,2,2]`所有这些都代表相同的逻辑组合，但强力将它们视为单独的路径。 

为了删除重复项，我们需要额外的数据结构，例如排序和哈希集，这会显着增加开销。 

搜索空间也会呈指数增长，因为每个递归调用都可以分支为多个附加调用。 

### 最优回溯方法

 关键的见解是组合不关心顺序。 

如果我们确保递归探索仅在候选列表中向前移动，我们自然会避免重复排列。 

例如：

 - 我们允许`[2,2,3]`- 我们绝不允许倒退来生成`[3,2,2]`这将问题转化为经典的回溯搜索。 

在每个递归步骤：

 - 选择当前候选人
 - 如果我们想重用它，请保持相同的索引
 - 跳过时向前移动

 这保证了唯一性，同时仍然探索每个有效的组合。 

由于目标很小，剪枝极其有效：

 - 如果当前总和超过目标，立即停止
 - 如果剩余目标变为零，记录当前组合

 这使得回溯成为理想的解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^目标) 到 O(n^目标) | O（目标）| 探索所有可能的序列，生成重复项 |
 | 最优回溯| O(N^(T/M)) | O(N^(T/M)) | O（目标）| 高效剪枝，避免重复 |

 在哪里：

-`N`= 候选人人数
 -`T`= 目标
 -`M`= 最小候选值

 ## 算法演练

 ### 最优回溯算法

 1. 初始化一个空结果列表，用于存储所有有效组合。 
2. 创建一个递归回溯函数，该函数接受：

 - 当前索引在`candidates`- 剩余目标值
 - 当前正在构建的组合
 3. 如果剩余目标变为`0`，当前组合有效。 

- 将当前组合复制到结果列表中。 
- 立即返回，因为不需要更多号码。 
4. 如果剩余目标变为负数，则停止探索这条路径。 

- 该分支永远无法产生有效的组合。 
5. 从当前索引开始迭代候选对象。 

- 从当前索引开始可以防止生成重复的排列。 
- 这保证了组合保持非递减顺序。 
6. 将当前候选添加到组合中。 
7、递归调用回溯函数：

 - 再次通过相同的索引，因为候选可以无限次地重复使用。 
- 从剩余目标中减去候选值。 
8. 递归完成后，从组合中删除最后一个元素。 

- 这是“回溯”步骤。 
- 在探索下一个可能性之前它会恢复之前的状态。 
9. 继续探索所有剩余的候选者。 

### 为什么它有效

 该算法系统地探索每个有效组合，同时强制执行固定的排序约束。 由于递归仅在候选列表中向前移动，因此永远不会发生重复排列。 最终会探索每个有效的组合，因为每个候选组合都可以重复包含或跳过。 修剪可确保无效路径提前终止。 

## Python 解决方案```python
from typing import List

class Solution:
    def combinationSum(self, candidates: List[int], target: int) -> List[List[int]]:
        result = []
        current_combination = []

        def backtrack(start_index: int, remaining: int) -> None:
            if remaining == 0:
                result.append(current_combination[:])
                return

            if remaining < 0:
                return

            for index in range(start_index, len(candidates)):
                candidate = candidates[index]

                current_combination.append(candidate)

                backtrack(index, remaining - candidate)

                current_combination.pop()

        backtrack(0, target)

        return result
```实现首先初始化两个列表：

 -`result`存储所有有效组合
 -`current_combination`跟踪活动的递归路径

 嵌套的`backtrack`函数执行递归探索。 

参数`start_index`确保组合以一致的顺序生成。 这是防止重复的机制。 

参数`remaining`跟踪还需要多少价值才能达到目标。 

什么时候`remaining == 0`，已构建有效的组合。 当前组合的副本将添加到结果列表中。 

什么时候`remaining < 0`，当前路径是不可能的，递归立即停止。 

循环从以下位置开始迭代`start_index`，不是来自`0`。 这非常重要，因为它可以防止重新访问较早的候选者并生成重复的排列。 

递归调用使用`backtrack(index, remaining - candidate)`而不是`index + 1`因为同一个号码可能会被重复使用多次。 

递归完成后，使用以下命令删除最后一个元素`pop()`。 这会在探索另一个分支之前恢复之前的递归状态。 

## 解决方案```go
func combinationSum(candidates []int, target int) [][]int {
    var result [][]int
    var currentCombination []int

    var backtrack func(startIndex int, remaining int)

    backtrack = func(startIndex int, remaining int) {
        if remaining == 0 {
            combinationCopy := make([]int, len(currentCombination))
            copy(combinationCopy, currentCombination)

            result = append(result, combinationCopy)
            return
        }

        if remaining < 0 {
            return
        }

        for index := startIndex; index < len(candidates); index++ {
            candidate := candidates[index]

            currentCombination = append(currentCombination, candidate)

            backtrack(index, remaining-candidate)

            currentCombination = currentCombination[:len(currentCombination)-1]
        }
    }

    backtrack(0, target)

    return result
}
```Go 实现遵循与 Python 解决方案相同的递归结构。 

Go 特有的一个重要细节是在将切片存储到结果中之前复制它们。 切片是对底层数组的引用，因此直接附加`currentCombination`会导致未来的修改影响存储的结果。 

为了避免这种情况，该实现创建了`combinationCopy`并在附加之前复制切片内容。 

Go 还使用切片重新切片进行回溯：```go
currentCombination = currentCombination[:len(currentCombination)-1]
```与 Python 不同，Go 没有使用切片语法的自动列表复制功能，例如`[:]`，如此明确`copy()`使用是必要的。

 ## 边缘情况

 当不存在有效组合时，就会出现一种重要的边缘情况。 例如，`candidates = [2]`和`target = 1`。 幼稚的实现可能会无限递归或错误地返回部分组合。 该解决方案可以安全地处理这种情况，因为只要剩余目标变为负数，递归就会立即停止。 

另一个重要的边缘情况是当单个候选者直接等于目标时。 例如，`candidates = [7]`和`target = 7`。 某些实现由于不正确的递归顺序或过早的修剪而意外地跳过直接匹配。 当剩余目标达到零时，此实现可以正确检测解决方案。 

第三个关键边缘情况涉及重复使用单个号码。 例如，`candidates = [1]`和`target = 5`。 由于数字可以无限次地重复使用，因此递归必须允许重新访问相同的索引。 该实现通过递归调用来实现`backtrack(index, remaining - candidate)`而不是前进到下一个索引。 

另一个微妙的边缘情况是重复排列生成。 如果没有仔细的排序约束，该算法可以产生`[2,3,2]`和`[3,2,2]`。 该实现通过仅探索当前索引向前的候选者来完全避免这种情况，保证组合保持一致的顺序。
