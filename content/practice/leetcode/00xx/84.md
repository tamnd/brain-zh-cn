 # LeetCode 84 - 直方图中最大的矩形

 ## 问题理解

 这个问题要求我们找到直方图中可以形成的最大矩形区域。 直方图表示为称为的整数数组`heights`，其中每个整数描述条形的高度，并且每个条形的宽度恰好为`1`。 

目标是确定使用一个或多个相邻条形可以形成的任何矩形的最大可能面积。 矩形不需要跨越整个直方图。 相反，它可以延伸到任何连续的条形范围，但其高度受到该范围内最短的条形的限制。 

例如，如果我们有：```
heights = [2,1,5,6,2,3]
```我们可以考虑酒吧`[5,6]`。 由于该段中的最短高度是`5`，我们可以创建一个高度的矩形`5`和宽度`2`，生产面积：```
5 × 2 = 10
```结果这是直方图中最大的矩形。 

输入是一个整数数组，其中：

 -`heights[i]`代表的高度`i-th`酒吧。 
- 每个条都有宽度`1`。 
- 条块彼此相邻放置，没有间隙。 

预期输出是表示可能的最大矩形面积的单个整数。 

约束条件很重要：```
1 <= heights.length <= 10^5
0 <= heights[i] <= 10^4
```数组大小可以大到`100,000`，它立即告诉我们昂贵的嵌套循环方法可能太慢。 一个`O(n²)`或者`O(n³)`解决方案存在因大量输入而超时的风险。 这强烈表明我们需要一个线性或近线性的解决方案。 

一些边缘情况可能会导致幼稚的实现失败。 高度增加、高度减小或重复相等高度的直方图表现不同，并且经常揭示逻辑错误。 包含零的数组也很重要，因为高度为`0`有效地打破了一个矩形。 仅包含一个条形的直方图是另一种特殊情况，其中答案只是该条形的高度。 

该问题保证输入数组非空且包含非负整数，因此我们永远不需要处理无效输入或负高度。 

## 方法

 ### 蛮力方法

 解决此问题的一个直接方法是检查每个可能的连续条形子数组。 

对于每个起始索引，我们可以向右扩展，同时跟踪迄今为止遇到的最小高度。 由于矩形高度受到范围内最小条形的限制，因此每个线段的面积变为：```
minimum height × width
```我们计算所有可能的范围并跟踪最大面积。 

这种方法之所以有效，是因为它显式地检查每个有效的矩形。 由于评估了每个可能的连续区域，因此找到的最大面积必须是正确的。 

然而，对于给定的约束来说它太慢了。 有`O(n²)`可能的间隔，虽然我们可以优化最小跟踪以避免重新计算，但整体复杂性仍然变得`O(n²)`。 和`n = 100,000`，这是不切实际的。 

### 最优方法，单调递增堆栈

 关键的见解是，对于每个柱，我们想要确定：

 - 它可以向左延伸多远
 - 它可以向右延伸多远

 在遇到较短的酒吧之前。 

如果我们知道这些边界，我们就可以计算出最大矩形，其中该条是限制高度。 

对于索引处的柱`i`：```
area = height[i] × width
```在哪里：```
width = right_boundary - left_boundary - 1
```我们使用**单调递增堆栈**，而不是显式地向左和向右搜索每个柱，这将是昂贵的。 

堆栈按高度递增的顺序存储条形索引。 每当我们遇到较短的条时，我们就知道堆栈中较高的条无法进一步延伸。 这为我们提供了足够的信息来立即计算它们的最大矩形。 

这是高效的，因为每个元素最多被压入和弹出一次，从而给出`O(n)`解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 检查每个连续范围并计算矩形区域 |
 | 最佳| O(n) | O(n) | 单调递增堆栈对每个条处理一次 |

 ## 算法演练

 ### 使用单调堆栈的最优算法

 1.初始化一个空栈和一个变量`max_area = 0`。 

该堆栈将以高度递增的顺序存储直方图条的索引。 我们存储索引而不是值，因为我们需要位置来稍后计算宽度。 
2. 迭代直方图中的所有条形。 

对于每个条形，将其高度与堆栈顶部的条形进行比较。 
3. 保持堆栈的递增性质。 

如果当前柱高于或等于堆栈顶部，则将其索引压入堆栈。 

这保留了增加的高度顺序。 
4. 当出现较短的条时，弹出较高的条。 

如果当前高度小于堆栈顶部条形的高度，我们就知道较高的条形不能继续超出此点。 

我们反复从堆栈中弹出并计算面积。 
5. 计算弹出条的矩形。 

弹出后：

 - 当前索引给出了正确的边界。 
- 新的堆栈顶部给出了左边界。 
- 如果堆栈变空，则矩形将延伸到开头。 

宽度变为：```
width = current_index - stack[-1] - 1
```或者：```
width = current_index
```如果堆栈为空。 

然后计算：```
area = popped_height × width
```更新`max_area`。 
6. 继续处理，直到检查完所有条形。 
7. 添加哨兵值。 

为了确保处理所有剩余的条形，请附加虚拟高度`0`在最后。 This forces the stack to empty naturally.
 8. 返回`max_area`。 

### 为什么它有效

 关键的不变量是堆栈始终包含按高度递增顺序的条形索引。 当出现较短的条形时，我们立即知道必须删除的每个较高条形的正确边界。 由于堆栈还保留有关先前较小元素的信息，因此我们也自动知道左边界。 

每个条形都作为矩形的潜在限制高度被处理一次，确保永远不会错过最大矩形。 

## Python 解决方案```python
from typing import List

class Solution:
    def largestRectangleArea(self, heights: List[int]) -> int:
        stack = []
        max_area = 0

        # Add sentinel height to process remaining bars
        heights.append(0)

        for index, height in enumerate(heights):
            while stack and heights[stack[-1]] > height:
                top_index = stack.pop()
                current_height = heights[top_index]

                if stack:
                    width = index - stack[-1] - 1
                else:
                    width = index

                area = current_height * width
                max_area = max(max_area, area)

            stack.append(index)

        return max_area
```该实现首先初始化一个空堆栈和一个变量来跟踪最大区域。 

哨兵值`0`被附加到数组中。 这是一个优雅的技巧，可确保堆栈中所有剩余的条在最后都得到处理，而不需要单独的清理逻辑。 

在迭代期间，堆栈保持不断增加的高度。 每当当前条形比堆栈顶部短时，我们就会重复弹出更高的条形，因为它们无法再进一步延伸。 

对于每个弹出的条形图，当前索引充当右边界。 新的堆栈顶部给出了左边界。 这使我们能够计算宽度，从而计算面积。 

处理完必要的弹出操作后，当前索引将添加到堆栈中，以便递增顺序属性保持不变。 

最后返回最大矩形面积。 

## 解决方案```go
func largestRectangleArea(heights []int) int {
	stack := []int{}
	maxArea := 0

	// Add sentinel value
	heights = append(heights, 0)

	for i, height := range heights {
		for len(stack) > 0 && heights[stack[len(stack)-1]] > height {
			topIndex := stack[len(stack)-1]
			stack = stack[:len(stack)-1]

			currentHeight := heights[topIndex]

			var width int
			if len(stack) > 0 {
				width = i - stack[len(stack)-1] - 1
			} else {
				width = i
			}

			area := currentHeight * width
			if area > maxArea {
				maxArea = area
			}
		}

		stack = append(stack, i)
	}

	return maxArea
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 主要区别在于堆栈处理。 在 Go 中，切片用作堆栈，其中`append()`用于推送操作和弹出操作的切片。 

Go 没有内置 Python`max()`函数，因此最大面积更新是通过显式比较来执行的。 

无需特别担心整数溢出，因为最大可能的矩形区域为：```go
10^5 × 10^4 = 10^9
```适合 Go 的内部`int`类型。

 ## 边缘情况

 ### 单条直方图

 仅包含一个条形的直方图，例如：```
[5]
```如果实现假设存在多个边界，则很容易出现错误处理。 由于只有一个可能的矩形，因此答案就是高度本身。 该算法自然地处理这个问题，因为哨兵值强制弹出并评估单个条。 

### 严格增加高度

 输入如下：```
[1,2,3,4,5]
```很棘手，因为在主迭代期间没有计算任何矩形。 每个条都被简单地推入堆栈。 如果没有适当的清理，算法将完全错过答案。 

哨兵`0`通过在最后触发所有剩余的小节来解决这个问题。 

### 严格降低高度

 对于输入：```
[5,4,3,2,1]
```每个新的柱都会立即弹出。 这可能会暴露宽度计算中的错误，因为边界变化很快。 

该实现通过在每次弹出后使用新的堆栈顶部来正确计算宽度。 这保证了左边界始终准确。 

### 零高度直方图

 输入如下：```
[2,0,2]
```包含一个零高度条，可有效地将直方图分成单独的部分。 

该算法自然地处理这个问题，因为高度`0`强制弹出所有较高的条形，防止矩形错误地跨越零。
