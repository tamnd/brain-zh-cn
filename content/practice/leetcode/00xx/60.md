 # LeetCode 60，排列序列

 ## 问题理解

 问题给了我们来自的数字`1`到`n`，并要求我们找到`kth`当所有可能的排列按字典顺序排序时进行排列。 

例如，当`n = 3`，数字是：```
[1, 2, 3]
```所有排列按排序顺序为：```
123
132
213
231
312
321
```如果`k = 3`，答案是`"213"`因为这是该排序中的第三个排列。 

重要的细节是排列是按字典顺序排序的，这意味着它们像字符串或字典单词一样排序。 

输入包括：

 -`n`, 的位数`1`到`n`-`k`，所需排列的位置，使用从 1 开始的索引

 输出是一个字符串，表示`kth`排列。 

限制很小：

 -`1 <= n <= 9`-`1 <= k <= n!`自从`n`至多是`9`，最大排列数为：```
9! = 362880
```这个值足够小，以至于暴力破解在技术上是可行的，但与直接的数学构造相比仍然效率低下。 

一些边缘情况很重要：

 -`k = 1`，我们应该返回最小的排列
 -`k = n!`，我们应该返回最大的排列
 -`n = 1`，只有一种可能的排列
 - 正确处理基于 1 的索引至关重要，许多实现都会失败，因为阶乘索引自然适用于基于 0 的索引

 ## 方法

 ### 蛮力方法

 一个简单的解决方案是生成数字的每个排列`1`通过`n`，按字典顺序对它们进行排序，然后返回`kth`一。 

这是有效的，因为生成所有排列可以保证目标排列将出现在列表中的某个位置。 

例如，与`n = 4`，我们可以：

 1.生成全部`24`排列
 2. 对它们进行排序
 3. 返回索引处的排列`k - 1`虽然正确，但这种方法变得低效，因为排列的数量呈阶乘增长。 

时间复杂度变得非常大：```
O(n! * n)
```发生这种情况是因为：

 - 有`n!`排列
 - 每个排列包含`n`人物
 - 排序也会增加额外的开销

 虽然`n <= 9`虽然暴力破解在技术上可行，但它不是一个优雅或最佳的解决方案。 

### 最优方法，阶乘数系统

 关键的见解是排列遵循可预测的块结构。 

认为`n = 4`。 

有：```
4! = 24
```总排列。 

如果我们修复第一个数字：

 - 所有排列以`1`占据第一`3! = 6`职位
 - 所有排列以`2`占据下一个`6`- 所有排列以`3`占据下一个`6`- 所有排列以`4`占领决赛`6`这意味着我们可以直接使用阶乘确定每个数字，而无需生成所有排列。 

每一步：

 - 计算每个剩余数字贡献多少个排列
 - 确定哪个块包含目标排列
 - 选择该数字
 - 将其从可用数字中删除
 - 继续剩下的位置

 该技术本质上是转换`k`进入基于阶乘的位置系统。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n! * n) | O(n! * n) | O(n! * n) | O(n! * n) | 显式生成每个排列 |
 | 最佳 | O(n²) | O(n) | 直接使用阶乘数学构造答案 |

 ## 算法演练

 ### 最优算法

 1. 创建可用数字列表`1`到`n`。 

例如，如果`n = 4`：```
digits = [1, 2, 3, 4]
```这些是我们仍然可以放入排列中的数字。 
2. 预先计算阶乘值。 

我们需要阶乘，因为排列被分为不同大小的块：```
(remaining_digits - 1)!
```为了`n = 4`：```
0! = 1
1! = 1
2! = 2
3! = 6
4! = 24
```3. 转换`k`从基于 1 的索引到基于 0 的索引。 

这一点非常重要。 

阶乘索引自然地与零索引一起工作。 

所以我们这样做：```
k = k - 1
```4. 确定第一位数字。 

假设我们有`n = 4`和`k = 9`。 

转换为零索引后：```
k = 8
```每个第一位数字块包含：```
3! = 6
```排列。 

计算：```
index = k // 6 = 1
```这意味着我们选择索引处的数字`1`在：```
[1, 2, 3, 4]
```这是`2`。 
5. 删除所选数字。 

选择后`2`：```
digits = [1, 3, 4]
```6. 更新`k`。 

我们只关心所选块内的位置。 

计算：```
k = k % 6
```变成：```
k = 2
```7. 对其余位置重复该过程。 

现在每个块大小变为：```
2! = 2
```继续选择数字，直到没有数字为止。 
8. 将所有选定的数字连接到最终的字符串中。 

### 为什么它有效

 该算法之所以有效，是因为按字典顺序排列的排列被划分为由阶乘确定的大小相等的块。 

对于任何职位：

 - 每个剩余的数字都准确贡献`(remaining_positions)!`排列
 - 整数除法识别哪个块包含目标排列
 - 模数确定该块内的相对位置

 通过反复缩小搜索空间，算法构建了精确的`kth`直接排列，不会产生不必要的排列。 

## Python 解决方案```python
class Solution:
    def getPermutation(self, n: int, k: int) -> str:
        # Precompute factorials
        factorial = [1] * (n + 1)
        
        for i in range(1, n + 1):
            factorial[i] = factorial[i - 1] * i
        
        # Available digits
        digits = [str(i) for i in range(1, n + 1)]
        
        # Convert to 0-based indexing
        k -= 1
        
        result = []
        
        # Build permutation
        for remaining in range(n, 0, -1):
            block_size = factorial[remaining - 1]
            
            index = k // block_size
            
            result.append(digits[index])
            
            digits.pop(index)
            
            k %= block_size
        
        return "".join(result)
```实现从预先计算阶乘值开始。 这允许在排列构造期间恒定时间查找块大小。 

这`digits`list 存储所有当前可用但尚未在排列中使用的数字。 

转换：```python
k -= 1
```是必不可少的，因为阶乘块索引本质上是从零开始的。 

主循环一次处理一位数字位置。 对于每个位置：

 -`block_size`确定每个候选数字有多少个排列
 -`index`识别哪个数字块包含目标排列
 - 所选数字附加到结果中
 - 该数字已被删除，因此无法重复使用
 -`k`减少到所选块内的偏移量

 最后，所有数字都连接到答案字符串中。 

## 解决方案```go
func getPermutation(n int, k int) string {
	// Precompute factorials
	factorial := make([]int, n+1)
	factorial[0] = 1

	for i := 1; i <= n; i++ {
		factorial[i] = factorial[i-1] * i
	}

	// Available digits
	digits := make([]byte, n)

	for i := 0; i < n; i++ {
		digits[i] = byte('1' + i)
	}

	// Convert to 0-based indexing
	k--

	result := make([]byte, 0, n)

	// Build permutation
	for remaining := n; remaining >= 1; remaining-- {
		blockSize := factorial[remaining-1]

		index := k / blockSize

		result = append(result, digits[index])

		// Remove used digit
		digits = append(digits[:index], digits[index+1:]...)

		k %= blockSize
	}

	return string(result)
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

一个`[]byte`使用切片而不是字符串是因为在 Go 中字节对于字符操作非常有效。 

删除数字使用切片串联：```go
digits = append(digits[:index], digits[index+1:]...)
```自从`n <= 9`，整数溢出不是一个问题，因为`9!`轻松安装在标准 Go 中`int`。

= O(n²)
```自从`n <= 9`，这在实践中非常有效。

 ## 边缘情况

 ### 边缘情况 1，`n = 1`当只有一个数时，只存在一种排列。```
Input: n = 1, k = 1
Output: "1"
```某些实现错误地假设存在多个阶乘级别，并且可能会产生索引错误。 此实现可以自然地处理这种情况，因为循环运行一次并选择唯一可用的数字。 

### 边缘情况 2，`k = 1`第一个排列应始终是字典顺序上最小的排列。 

例如：```
n = 4, k = 1
```应该产生：```
"1234"
```转换为零索引后，`k = 0`，所以每个块选择都会选择索引`0`。 因此，该算法总是选择最小的剩余数字。 

### 边缘情况 3，`k = n!`最终的排列应该始终是字典顺序上最大的排列。 

例如：```
n = 4, k = 24
```应该产生：```
"4321"
```如果索引转换不正确，这种情况很容易处理错误。 因为实现转换`k`在处理之前将索引归零，阶乘除法正确地选择每个级别的最终块。 

### 边缘情况 4，相差一错误

 这个问题特别容易出现索引错误，因为：

 - 输入`k`是从 1 开始的
 - 阶乘分组逻辑自然是从0开始的

 没有：```
k -= 1
```该算法始终会选择不正确的块。 

实现显式转换`k`在处理之前，完全消除这个问题。
