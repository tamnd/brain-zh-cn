[LeetCode 第 33 题](https://leetcode.com/problems/search-in-rotated-sorted-array/)

 **难度：** 🟡 中等
 **主题：** 数组、二分查找

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个最初按升序排序的数组，但可能在某个枢轴点进行了旋转。 旋转意味着已排序数组的某些前缀被移动到末尾，同时保留元素的相对顺序。 

例如，排序后的数组：```
[0,1,2,4,5,6,7]
```可以旋转为：```
[4,5,6,7,0,1,2]
```重要的细节是数组仍然包含两个单独排序的部分。 旋转引入了一个“断点”，其中大值后面跟着小值。 

我们还获得了一个目标值，并且必须返回目标在数组中出现的索引。 如果目标不存在，我们返回`-1`。 

挑战不仅仅是找到目标。 挑战在于满足所需的运行时复杂性`O(log n)`。 线性扫描可以正常工作，但需要`O(n)`时间。 该问题特别需要对数解，强烈建议采用二分搜索。 

这些约束告诉我们一些重要的事情：

 - 数组长度至少为 1，因此我们永远不会收到空数组。 
- 所有元素都是不同的，这一点非常重要，因为它保证我们可以在二分查找过程中确定数组的哪一边是排序的。 
- 数组最初是排序的，这意味着二分搜索所需的大部分结构仍然存在。 
- 所需的运行时间是`O(log n)`, meaning we must discard half the search space at every step.

 一些边缘情况很重要：

 - 阵列实际上可能根本没有旋转。 
- 数组只能包含一个元素。 
- 目标可能不存在于数组中。 
- The rotation point may appear near the beginning or end.
 - 目标可能位于旋转枢轴的任一侧。 

简单的二分查找会失败，因为数组没有全局排序。 However, one side of the current search range is always sorted, and that observation is the key to the optimal solution.

 ## 方法

 ### 蛮力方法

 The simplest approach is to iterate through the array from left to right and compare every element against the target.

 If we find the target, we return its index immediately. If we reach the end without finding it, we return`-1`。 

这种方法是正确的，因为它会检查目标可能出现的每个可能位置。 由于该问题保证不同的值，因此第一个匹配是唯一的匹配。 

然而，该解决方案在最坏的情况下需要扫描整个阵列。 如果目标不存在或位于末尾附近，我们将检查所有元素。 

因为运行时间是`O(n)`，这不满足所需的对数复杂度。 

### 最佳二分搜索方法

 关键的观察是，尽管数组被旋转，但当前搜索区间的至少一半始终是排序的。 

在二分查找期间：

 - 我们计算中间指数。 
- 必须对这些范围之一进行排序：

 -`left -> mid`-`mid -> right`一旦我们确定了排序的一半，我们就可以确定目标是否位于该范围内。 

如果目标属于已排序的一半，我们将继续在那里搜索。 否则，我们搜索另一半。 

这保留了二分搜索的对数行为，因为每次迭代都会消除一半的剩余搜索空间。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(1) | O(1) | 按顺序扫描每个元素 |
 | 最佳| O(log n) | O(1) | O(1) | 使用排序半检测的修改二分搜索 |

 ## 算法演练

 1.初始化两个指针，`left`和`right`，代表当前的搜索边界。 

最初：

-`left = 0`-`right = len(nums) - 1`这些指针定义了我们当前正在搜索的数组部分。 
2.继续搜索`left <= right`。 

此条件确保仍然有剩余的候选元素。 
3. 计算中间索引：```
mid = (left + right) // 2
```中间的元素是当前的候选者。 
4. 如果`nums[mid] == target`， 返回`mid`。 

我们找到了目标，所以搜索完成了。 
5. 确定哪一半已排序。 

由于该数组包含不同的值并且源自已排序的数组，因此至少一侧必须保持排序。 

我们检查：```
if nums[left] <= nums[mid]:
```如果为 true，则对左半部分进行排序。 

否则，对右半部分进行排序。 
6. 如果左半部分已排序，则判断目标是否位于其中。 

如果满足以下条件，则目标属于左半部分：```
nums[left] <= target < nums[mid]
```如果这个条件成立，则丢弃右半部分：```
right = mid - 1
```否则，丢弃左半部分：```
left = mid + 1
```7. 如果右半部分已排序，则判断目标是否在其中。 

如果满足以下条件，则目标属于右半部分：```
nums[mid] < target <= nums[right]
```如果为真：```
left = mid + 1
```否则：```
right = mid - 1
```8. 如果循环结束而没有返回，则目标不存在。 

返回`-1`。 

### 为什么它有效

 该算法之所以有效，是因为每次迭代都能保证数组的一侧正确排序。 由于目标只能属于该排序区间的内部或外部，因此我们每次都可以安全地丢弃剩余搜索空间的一半。 

这保留了二分搜索的核心不变量：每次迭代之后，目标（如果存在）必须仍然位于更新的搜索边界内。 

由于每次迭代搜索间隔缩小一半，因此运行时间保持不变`O(log n)`。 

## Python 解决方案```python
from typing import List

class Solution:
    def search(self, nums: List[int], target: int) -> int:
        left = 0
        right = len(nums) - 1

        while left <= right:
            mid = (left + right) // 2

            if nums[mid] == target:
                return mid

            # Left half is sorted
            if nums[left] <= nums[mid]:
                if nums[left] <= target < nums[mid]:
                    right = mid - 1
                else:
                    left = mid + 1

            # Right half is sorted
            else:
                if nums[mid] < target <= nums[right]:
                    left = mid + 1
                else:
                    right = mid - 1

        return -1
```该实现首先初始化两个代表当前搜索间隔的指针。 

在循环内部，我们计算中间索引并立即检查中间元素是否与目标匹配。 这与普通的二分查找相同。 

重要的区别将出现在下一节中。 由于数组是旋转的，我们不能直接将目标与中间值进行比较。 相反，我们首先确定哪一半已排序。 

条件：```python
nums[left] <= nums[mid]
```告诉我们左半部分是否已排序。 如果为真，我们然后检查目标是否落在该排序区间内。 

如果目标属于那里，我们将移动`right`指针向内。 否则，我们丢弃左半部分并继续搜索右半部分。 

当右半部分排序时，应用相反的逻辑。 

最终，要么找到目标，要么搜索区间变空。 

## 解决方案```go
func search(nums []int, target int) int {
    left := 0
    right := len(nums) - 1

    for left <= right {
        mid := left + (right-left)/2

        if nums[mid] == target {
            return mid
        }

        // Left half is sorted
        if nums[left] <= nums[mid] {
            if nums[left] <= target && target < nums[mid] {
                right = mid - 1
            } else {
                left = mid + 1
            }
        } else {
            // Right half is sorted
            if nums[mid] < target && target <= nums[right] {
                left = mid + 1
            } else {
                right = mid - 1
            }
        }
    }

    return -1
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

一个小的实现细节是中间索引的计算：```go
mid := left + (right-left)/2
```这可以避免潜在的整数溢出：```go
(left + right) / 2
```尽管在这个问题的限制下溢出实际上是不可能的，但这种模式被认为是 Go 和许多其他语言的最佳实践。 

直接使用Go切片，不需要额外分配内存。

 ## 边缘情况

 ### 单元素数组

 单元素数组是可能的最小有效输入。 如果二分查找循环条件不正确，这种情况很容易误处理。 

例如：```
nums = [1], target = 0
```该实现正确处理了这个问题，因为循环仍然执行一次`left == right == mid`。 检查单个元素后，指针适当移动并且循环干净地终止。 

### 未旋转的数组

 该数组可能已经完全排序，根本没有旋转。 

例如：```
[1,2,3,4,5]
```在这种情况下，条件：```
nums[left] <= nums[mid]
```通常保持为真，这意味着该算法的行为与普通的二分搜索完全相同。 不需要特殊情况逻辑。 

### 旋转轴附近的目标

 旋转枢轴是顺序突然改变的位置。 靠近此边界的目标是错误的常见来源，因为天真的比较可能会错误地丢弃错误的一半。 

例如：```
nums = [4,5,6,7,0,1,2]
target = 0
```该实现可以安全地处理这个问题，因为它从不假设整个数组已排序。 相反，它会识别当前已排序的一半，并检查目标是否属于该特定区间。 

### 目标不存在

 如果目标不存在，算法最终必须消除整个搜索范围并返回`-1`。 

例如：```
nums = [4,5,6,7,0,1,2]
target = 3
```该实现保证终止，因为每次迭代都会严格缩小搜索间隔。 最终，`left`变得大于`right`，表明目标不能存在于数组中。
