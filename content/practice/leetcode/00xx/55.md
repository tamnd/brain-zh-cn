 # LeetCode 55 - 跳跃游戏

 ## 问题理解

 问题给了我们一个整数数组`nums`，其中每个值代表我们可以从该位置向前跳跃的最大距离。 

你总是从索引开始`0`。 来自索引`i`，您可以在之间跳跃任意距离`1`和`nums[i]`，只要保持在数组的范围内即可。 

目标是确定是否有可能最终到达数组的最后一个索引。 

例如，如果`nums = [2,3,1,1,4]`，那么：

 - 来自索引`0`，你可以跳`1`或者`2`步骤。 
- 跳转到索引`1`就足够了，因为`nums[1] = 3`，这可以达到最终索引。 

答案是`true`。 

另一方面，如果`nums = [3,2,1,0,4]`，每条路径最终都落在索引处`3`，其中跳跃长度为`0`。 一旦到达该位置，就无法再向前移动，因此最后一个索引将变得无法到达。 

约束条件很重要：

 -`1 <= nums.length <= 10^4`-`0 <= nums[i] <= 10^5`该数组最多可以包含一万个元素，因此对所有可能的跳转路径进行指数探索会太慢。 我们需要接近线性时间的东西。 

有几个重要的边缘情况需要考虑：

 - 长度数组`1`， 例如`[0]`。 您已经从最后一个索引开始，所以答案是自动的`true`。 
- 中间包含零的数组。 如果没有更早的跳转可以绕过零，那么零可以完全阻止进度。 
- 非常大的跳跃值。 大于剩余距离的值仍应视为成功到达终点。 
- 几乎可以到达终点但在终点前被困的情况。 

该问题保证所有数字都是非负的，因此我们永远不需要考虑向后移动。 

## 方法

 ### 蛮力方法

 最直接的想法是递归地尝试从每个位置的每个可能的跳转。 

来自索引`i`，我们可以尝试大小的跳跃：

 -`1`-`2`-`3`- ...
 -`nums[i]`对于每次跳转，我们递归地检查该路径是否最终能够到达终点。 

这是有效的，因为它探索了每一个可能的有效跳跃序列。 如果有任何路径到达最终索引，则答案是`true`。 

问题在于可能的路径数量呈指数增长。 许多职位都会被反复重新计算。 例如，不同的跳转序列可能到达相同的索引，导致相同的递归工作一次又一次地发生。 

输入大小可达`10^4`，这种方法变得不切实际。 

### 最优贪心法

 关键的观察是我们实际上不需要知道跳跃的确切顺序。 

相反，我们只需要知道当前可以到达的最远索引。 

当我们从左到右扫描数组时：

 - 如果当前索引超出了最远可到达的位置，那么我们就会陷入困境，无法继续。 
- 否则，我们使用以下方法更新最远可达索引：$\text{farthest} = \max(\text{farthest},\ i + nums[i])$这种贪婪策略之所以有效，是因为可访问范围内的任何索引都可以以某种方式访问​​。 我们不关心如何到达那里，只关心它是否可达。 

一旦最远可达索引达到或超过最后一个位置，我们就知道答案是`true`。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 递归探索所有可能的跳转路径 |
 | 最优贪心 | O(n) | O(1) | O(1) | 扫描一次即可追踪最远可达位置 |

 ## 算法演练

 1. 初始化一个名为`farthest`到`0`。 

该变量代表我们当前可以到达的最远索引。 
2. 使用索引迭代数组`i`。 

在每一步中，我们都会检查当前位置本身是否可达。 
3.如果`i > farthest`， 返回`False`。 

这意味着当前指数超出了我们的最大可达范围。 既然我们连这个指标都无法立足，那么进一步的进步是不可能的。 
4. 否则，更新最远可达索引。 

计算：$\text{farthest} = \max(\text{farthest},\ i + nums[i])$如果当前位置允许更远的跳跃，这会扩展我们的可达范围。 
5. 如果`farthest >= len(nums) - 1`， 返回`True`。 

一旦最后一个索引变得可达，我们就可以立即停止。 
6. 如果循环完成且没有卡住，则返回`True`。 

成功处理每个可达索引意味着可以到达最后一个位置。 

### 为什么它有效

 该算法保持了一个重要的不变量：

 - 处理索引前`i`, 每个索引达到`farthest`是可达的。 

如果我们曾经遇到过`i > farthest`，那么存在一个我们无法跨越的差距，这意味着所有未来的位置也无法到达。 

如果我们继续延长`farthest`，那么每个新覆盖的位置都变得可到达。 由于该算法始终跟踪最大可到达边界，因此达到或超过最后一个索引可以保证成功。 

## Python 解决方案```python
from typing import List

class Solution:
    def canJump(self, nums: List[int]) -> bool:
        farthest = 0
        last_index = len(nums) - 1

        for index, jump_length in enumerate(nums):
            if index > farthest:
                return False

            farthest = max(farthest, index + jump_length)

            if farthest >= last_index:
                return True

        return True
```实现直接遵循贪婪策略。 

变量`farthest`存储迄今为止发现的最大可到达位置。 

该循环迭代每个索引和相应的跳转长度。 在进行任何更新之前，代码会检查当前索引是否可达。 如果不是，函数立即返回`False`。 

如果索引可达，则算法使用当前跳跃能力更新最远可达位置。 

当最后一个索引可达时，将使用早期返回。 这避免了大量输入带来的不必要的工作。 

决赛`return True`处理循环自然完成的情况，例如长度数组`1`。 

## 解决方案```go
func canJump(nums []int) bool {
    farthest := 0
    lastIndex := len(nums) - 1

    for index, jumpLength := range nums {
        if index > farthest {
            return false
        }

        if index+jumpLength > farthest {
            farthest = index + jumpLength
        }

        if farthest >= lastIndex {
            return true
        }
    }

    return true
}
```Go 实现与 Python 版本几乎相同。 

Go 切片已经跟踪它们的长度，所以我们计算`lastIndex`使用`len(nums) - 1`。 

而不是使用Python的内置`max`功能，Go版本在更新前会进行手动比较`farthest`。 

整数溢出在这里不是一个问题，因为约束足够小，可以安全地符合 Go 的标准`int`类型。

 ## 边缘情况

 ### 单元素数组

 像这样的输入`[0]`很容易处理不当。 

由于第一个索引也是最后一个索引，因此正确答案是立即`true`。 根本不需要跳跃。 

该实现自然地处理了这个问题，因为`last_index`变成`0`，并且初始可达范围已经包含索引`0`。 

### 零阻塞进度

 数组如`[3,2,1,0,4]`很重要，因为它们暴露了关于始终成功前进的错误假设。 

一个幼稚的实现可能只检查一些早期的跳跃是否在本地足够大，而没有意识到每条路径最终都被困在零处。 

贪心算法正确地检测到了这一点，因为最终当前索引变得大于`farthest`，证明渐进是不可能的。 

### 大跳跃值

 类似的情况`[10,0,0,0]`测试实现是否正确处理超出剩余距离的跳转。 

一些不正确的解决方案试图精确地落在最终索引上，这是不必要的。 

该算法仅检查最远可达索引是否大于或等于最后一个位置，因此超大跳转可以正常工作。 

### 可达到的零值

 并非每个零都会导致失败。 

例如，`[2,0,1]`仍然是可解的，因为索引`0`可以直接跳转到最后一个位置。 

该实现不会特殊对待零。 它只是跟踪全局可达范围，自然可以正确处理无害零和阻塞零。
