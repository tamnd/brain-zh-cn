 # LeetCode 1，二和

 ## 问题理解

 该问题给了我们一个名为的整数数组`nums`和另一个整数称为`target`。 我们的任务是在数组中找到两个不同的元素，其总和等于`target`，然后返回它们的索引。 

重要的细节是输出必须包含索引，而不是值本身。 例如，如果数字`2`和`7`加起来为`9`，我们必须返回`[0, 1]`因为这些是数组中数字的位置。 

该问题还保证只有一个有效的解决方案。 这种保证简化了实现，因为我们不需要处理不存在答案或可能存在多个答案的情况。 

约束条件`2 <= nums.length <= 10^4`告诉我们数组可以变得相当大。 具有嵌套循环的二次解决方案在技术上仍将针对此输入大小运行，但后续问题明确要求比`O(n^2)`时间复杂度。 这强烈表明我们应该使用更有效的查找结构。 

数组和目标内的值可以是负数、正数或零。 因此，我们不能依赖排序假设或积极性属性。 

一些边缘情况很重要：

 - 相同的值可能会出现多次，例如`[3,3]`。 
- 正确的对可能涉及负数。 
- 答案可能出现在数组的开头或结尾附近。 
- 我们不允许使用同一个元素两次，这意味着一个索引不能重复使用。 
- 由于仅存在一个解决方案，因此一旦找到该对，算法就可以立即安全地返回。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每对可能的数字。 

我们可以使用两个嵌套循环。 外循环选择第一个数字，内循环检查其后的每个数字。 对于每一对，我们计算总和并将其与`target`。 

如果总和与目标匹配，我们返回两个索引。 

这种方法是正确的，因为它详尽地检查了所有有效对。 由于考虑了所有可能的组合，最终会找到正确的答案。 

然而，这种方法对于大型数组来说效率较低。 如果数组有`n`元素，那么我们可能需要检查大约`n^2 / 2`对。 这给出了时间复杂度`O(n^2)`。 

### 最佳哈希映射方法

 关键的观察是对于每个数字`x`，我们已经知道完成目标所需的数量：$x + y = target$重新排列给出：$y = target - x⟦PROTECT_13⟧a⟦PROTECT_14⟧g$而不是搜索整个数组`y`，我们可以将以前见过的数字存储在哈希图中。 

当我们遍历数组时：

 - 我们计算补码`target - current_number`。 
- 我们检查哈希映射中是否已存在该补集。 
- 如果是的话，我们立即找到答案。 
- 否则，我们存储当前数字及其索引以供将来查找。 

哈希图提供平均值`O(1)`查找时间，允许整个算法以线性时间运行。

 | 最佳 |`O(n)`|`O(n)`| 使用哈希映射进行恒定时间补码查找 |

 ## 算法演练

 1. 创建一个空的哈希映射，名为`seen_numbers`。 

哈希映射将数字存储为键，将其索引存储为值。 这允许快速查找以确定所需的补集是否已经出现在数组的较早位置。 
2. 使用索引和值迭代数组。 

在每一步中，我们处理一个数字并确定它是否可以与之前看到的数字形成目标和。 
3. 计算补码。 

对于当前号码`num`， 计算：$complement = target - num$这是完成该对所需的精确值。 
4. 检查哈希图中是否存在补集。 

如果补码已经存储，那么我们之前遇到过一个与当前数字配对以产生目标和的数字。 
5. 返回存储的索引和当前索引。 

由于该问题保证只有一个有效答案，因此一旦找到，我们就可以立即返回该对。 
6. 如果未找到补集，则将当前数字和索引存储在哈希映射中。 

这使当前值可以作为未来数字的补充。 

### 为什么它有效

 该算法保持哈希映射包含当前位置之前遇到的所有数字及其索引的不变式。 

处理数字时`num`，我们计算达到目标所需的精确值。 如果该值已存在于哈希映射中，那么我们就知道已找到有效的对。 

因为每个元素都被处理一次，并且因为保证存在正确的解决方案，所以算法总是返回正确的对。 

## Python 解决方案```python
from typing import List

class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        seen_numbers = {}

        for index, num in enumerate(nums):
            complement = target - num

            if complement in seen_numbers:
                return [seen_numbers[complement], index]

            seen_numbers[num] = index

        return []
```实现首先创建一个名为的空字典`seen_numbers`。 在Python中，字典提供平均值`O(1)`查找和插入时间，使它们成为解决此问题的理想选择。 

这`enumerate()`使用函数以便我们可以在迭代期间访问当前索引和值。 

对于每个数字，代码都会计算达到目标所需的补数。 然后它检查该补集是否已经被看到。 

如果补集存在于字典中，则存储的索引和当前索引形成答案，因此该函数立即返回它们。 

如果补集不存在，则将当前数字和索引插入到字典中，以便将来的元素可以使用它们。 

决赛`return []`从技术上讲是不必要的，因为问题保证了有效的答案，但包含它会使函数在语法上完整且具有防御性。 

## 解决方案```go
func twoSum(nums []int, target int) []int {
    seenNumbers := make(map[int]int)

    for index, num := range nums {
        complement := target - num

        if previousIndex, exists := seenNumbers[complement]; exists {
            return []int{previousIndex, index}
        }

        seenNumbers[num] = index
    }

    return []int{}
}
```The Go implementation follows the exact same algorithmic logic as the Python version.

 使用 Go 地图代替 Python 字典。 语法：```go
previousIndex, exists := seenNumbers[complement]
```检索存储的值和指示该键是否存在的布尔值。 

该解决方案返回包含两个索引的整数切片。 

这里整数溢出不是问题，因为约束安全地符合 LeetCode 平台上 Go 的标准整数范围。

 ## 边缘情况

 ### 重复值

 当正确答案两次使用相同的数值时，就会出现一个重要的边缘情况，例如`[3,3]`有目标`6`。 

有缺陷的实现可能会意外地重复使用同一个索引两次。 该解决方案避免了该问题，因为它仅在将当前元素插入哈希映射之前检查先前看到的元素。 因此，这两个索引始终不同。 

### 负数

 一些解决方案错误地假设所有数字都是正数，并尝试基于排序或提前停止进行优化。 

例如：```
nums = [-1, -2, -3, -4, -5]
target = -8
```哈希映射方法自然适用于负数，因为它仅依赖于算术减法和恒定时间查找。 

### 同一数字多次出现

 考虑：```
nums = [5,5,1]
target = 10
```该算法正确地存储了第一个`5`在哈希映射中。 当第二个`5`被处理后，补码`5`已经存在，所以正确的对`[0,1]`被返回。 

这说明了为什么插入顺序很重要。 在插入当前值之前，我们必须检查补码。 

### 接近数组末尾的解决方案

 一些不正确的实现过早停止或对答案出现的位置做出假设。 

例如：```
nums = [1,2,3,4,9]
target = 13
```正确的对位于数组的末尾。 由于该算法按顺序处理每个元素直到找到匹配项，因此它可以正确处理这种情况。
