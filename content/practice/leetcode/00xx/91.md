[LeetCode 第 91 题](https://leetcode.com/problems/decode-ways/)

 **难度：** 🟡 中等
 **主题：** 字符串、动态规划

 ## 解决方案

 ## 问题理解

 该问题要求我们确定使用映射将数字字符串解码为字母的不同有效方式有多少种：

 -`"1"`→`'A'`-`"2"`→`'B'`- ...
 -`"26"`→`'Z'`输入是一个字符串`s`仅包含数字。 每个数字或数字对可以代表一个字母，如果它在之间形成有效的数字`1`和`26`。 我们的任务是计算整个字符串的有效解码组合总数。 

关键的挑战是可能存在多种解释。 例如，`"12"`可以分为：

 -`"1"`+`"2"`→`"AB"`-`"12"`→`"L"`所以答案是`2`。 

然而，并非每一次分割都是有效的。 数字`'0'`会造成复杂性，因为它无法自行解码。 例如：

-`"10"`是有效的，因为`"10"`映射到`'J'`-`"20"`是有效的，因为`"20"`映射到`'T'`-`"06"`无效，因为`"06"`是不允许的，只能`"6"`有效

 预期输出是解码整个字符串的有效方法总数。 如果不存在有效的解码，我们返回`0`。 

约束条件很重要：

 -`1 <= s.length <= 100`- 答案适合 32 位整数

 100 的长度足够小，使得多项式时间解决方案有效，但又足够大，以至于指数暴力法变得不切实际。 这强烈建议采用动态规划解决方案。 

一些边缘情况值得预先关注。 开头为的字符串`'0'`立即无效，因为没有字母映射到零。 连续的零或格式错误的组合，例如`"30"`和`"100"`可以使部分或全部解码无效。 单字符字符串也需要仔细处理，因为它们可能有效也可能无效，具体取决于数字是否为零。 

## 方法

 ### 蛮力方法

 暴力解决方案将递归地尝试所有可能的方法来分割字符串。 

在每个位置，我们最多有两种选择：

 1. 解码一位数字，如果它形成有效数字`1`到`9`2. 解码两个数字，如果它们构成有效数字`10`到`26`例如，与`"226"`：

- 拿`"2"`→ 递归`"26"`- 拿`"22"`→ 递归`"6"`这自然会形成一个递归树，其中会探索每个有效的分割。 

蛮力方法是正确的，因为它系统地考虑了每一个可能的解码路径并计算所有有效结果。 然而，它执行了大量的重复工作。 

例如，不同的递归路径可能会重复求解字符串的相同后缀。 在`"1111"`, 子串`"11"`被重新计算多次。 这种重叠的子问题结构导致指数增长。 

由于每个位置可能分支为两个递归调用，因此最坏情况的时间复杂度变为指数，大约为`O(2^n)`，这对于`n = 100`。 

### 最佳解决方案的关键见解

 重要的观察是，一个位置的解码方式的数量仅取决于后面位置的解码计数。 

认为`dp[i]`表示对从索引开始的子字符串进行解码的方法数`i`。 

在索引处`i`，我们可以：

 - 使用一位数字，如果`s[i] != '0'`- 使用两位数字，如果`s[i:i+2]`形成一个有效的数字`10`和`26`这会导致复发：```
dp[i] =
    dp[i+1]                    if one-digit decode is valid
  + dp[i+2]                    if two-digit decode is valid
```由于每个子问题仅取决于接下来的两个位置，因此动态规划消除了重复计算并将复杂度降低到线性时间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 |`O(2^n)`|`O(n)`| 递归探索所有解码可能性，重复工作效率低下 |
 | 最优动态规划|`O(n)`|`O(1)`| 使用以前的结果来避免重新计算 |

 ## 算法演练

 最优解使用恒定空间的动态规划。 

1. 处理无效的启动条件。 

如果字符串开头为`'0'`， 返回`0`立即地。 没有从零开始的有效解码。 
2. 定义DP状态的含义。 

让`dp[i]`表示对从索引开始的子字符串进行解码的方法数`i`。 

由于我们只需要前两个状态，因此我们可以优化空间并仅存储两个变量而不是整个数组。 
3. 初始化基本情况。 

我们定义：

 -`next1 = 1`，代表`dp[n]`-`next2 = 0`，代表`dp[n+1]`空字符串只有一个有效的解码，这有助于自然终止递归。 
4. 从右向左遍历字符串。 

我们从末尾开始处理字符，因为`dp[i]`取决于`dp[i+1]`和`dp[i+2]`。 
5. 处理当前数字。 

如果`s[i] == '0'`，从这个位置开始解码的方法有零种，因为零不能单独存在。 

否则：

 - 开始于`current = next1`，这意味着我们解码一位数字。 
6. 检查两位解码是否有效。 

如果`i + 1 < n`和形成的数字`s[i:i+2]`位于之间`10`和`26`，然后添加`next2`到当前计数。 
7. 移动变量。 

计算当前结果后：

 -`next2 = next1`-`next1 = current`这为下一次迭代准备了值。 
8. 返回结果。 

处理完整个字符串后，`next1`包含解码完整字符串的方法数。 

### 为什么它有效

 该算法之所以有效，是因为索引处的每个有效解码`i`必须以一位有效数字或一位有效两位数开头。 这些是编码规则允许的唯一可能性。 

递归保证了正确性，因为它只计算所有有效分解一次：

 -`dp[i+1]`选择一位数字后计算解码次数
 -`dp[i+2]`选择两位数字后计算解码次数

 由于每个有效路径必须以这些选择之一开始，并且无效选择贡献为零，因此动态编程状态始终表示每个后缀的有效解码的确切数量。 

## Python 解决方案```python
class Solution:
    def numDecodings(self, s: str) -> int:
        n = len(s)

        next_one = 1
        next_two = 0

        for i in range(n - 1, -1, -1):
            if s[i] == '0':
                current = 0
            else:
                current = next_one

                if (
                    i + 1 < n
                    and (
                        s[i] == '1'
                        or (s[i] == '2' and s[i + 1] <= '6')
                    )
                ):
                    current += next_two

            next_two = next_one
            next_one = current

        return next_one
```该实现从右到左处理字符串。 这个方向很重要，因为每个位置都取决于未来的解码计数。 

变量`next_one`和`next_two`存储相当于`dp[i+1]`和`dp[i+2]`。 这消除了对整个 DP 阵列的需要，并将空间复杂度降低到恒定空间。 

当当前字符为`'0'`，结果立即`0`因为零不能被独立解码。 否则，我们从一位数解码计数开始，分配`current = next_one`。 

两位数验证检查当前数字和下一个数字是否构成介于`10`和`26`。 该解决方案不是将子字符串转换为整数，而是执行直接字符比较，这稍微更有效。 

计算当前状态后，滚动变量将被更新，以便下一次迭代可以访问正确的未来值。 

## 解决方案```go
func numDecodings(s string) int {
	n := len(s)

	nextOne := 1
	nextTwo := 0

	for i := n - 1; i >= 0; i-- {
		current := 0

		if s[i] != '0' {
			current = nextOne

			if i+1 < n &&
				(s[i] == '1' ||
					(s[i] == '2' && s[i+1] <= '6')) {
				current += nextTwo
			}
		}

		nextTwo = nextOne
		nextOne = current
	}

	return nextOne
}
```Go 实现遵循与 Python 版本相同的逻辑。 由于 Go 中的字符串是字节切片，因此可以使用`s[i]`返回一个字节，使字符比较变得简单。 

不需要对空输入进行特殊处理，因为约束保证至少有一个字符。 整数溢出也不是问题，因为该问题保证答案适合 32 位整数。

 ## 边缘情况

 ### 前导零

 输入如`"06"`或者`"012"`无效，因为没有字母本身对应于零。 幼稚的实现可能会意外解释`"06"`作为`"6"`，这是不正确的。 

该实现通过分配自然地处理这个问题`current = 0`每当`s[i] == '0'`。 这可以防止无效路径参与计数。 

### 字符串中间的零

 类似的情况`"10"`和`"101"`很棘手，因为零只能作为一部分出现`"10"`或者`"20"`。 

为了`"101"`：

 -`"10"`有效
 -`"01"`无效

 该实现仅正确验证之间的合法两位数组合`10`和`26`，确保仅在正确配对时才计算零。 

### 无效的两位数

 字符串如`"27"`或者`"30"`可能会产生误导。 

-`"26"`有效，因为它映射到`'Z'`-`"27"`不是有效的对，因为`27 > 26`-`"30"`无效，因为零不能单独存在并且`"30"`未映射

 该实现使用以下方式仔细检查两位数的有效性：```
s[i] == '1' or (s[i] == '2' and s[i + 1] <= '6')
```这保证了只有有效的编码才对总计数有贡献。 

### 非常长的输入

 对于接近长度的输入，递归暴力解决方案将变得极其缓慢`100`因为指数重新计算。 

动态编程实现通过解决每个位置一次来完全避免这个问题，即使对于最大允许的输入大小也能确保高效执行。
