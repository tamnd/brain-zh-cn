 # LeetCode 52，N-Queens II

 ## 问题陈述

 n 皇后拼图要求我们放置`n`皇后区`n x n`棋盘上没有两个皇后可以互相攻击。 在国际象棋中，皇后可以水平、垂直和对角移动。 这意味着任何两个共享同一行、同一列或同一对角线的皇后都会互相攻击，这是不允许的。 

输入由单个整数组成`n`, which represents both the number of queens and the dimensions of the board. 任务不是返回实际的板配置，而是返回有效排列的总数。 

例如，当`n = 4`，有两种不同的方法可以将四个皇后安全地放置在一个`4 x 4`木板。 因此，答案是`2`。 

限制相对较小：```
1 <= n <= 9
```虽然`n`至多是`9`，搜索空间增长得非常快，因为每一行都可能分支为许多列选择。 简单的暴力解决方案将变得极其昂贵。 这强烈表明尽早修剪无效状态至关重要。 

应立即考虑几个重要的边缘情况：

 - 当`n = 1`，板上包含一个单元格，因此只有一个有效的布局。 
- 小值，例如`n = 2`和`n = 3`根本没有有效的解决方案。 
- 较大的值需要有效的冲突检查，因为在深度递归探索期间重复板扫描的成本很高。 

## 问题理解

 关键的观察是每一行必须恰好包含一个皇后。 如果我们逐行处理棋盘，那么我们只需要决定当前行将皇后放置在哪一列即可。 

假设我们从上到下逐行放置皇后。 一旦我们将皇后放在前面的行中，下一个皇后就不能使用：

 - 任何列已经被另一位皇后占据
 - 任何已被占用的对角线

 如果以下表达式之一相等，则两个皇后共享对角线：

 -`row - col`-`row + col`这个属性使我们能够使用集合有效地跟踪受攻击的对角线。 

目标是计算所有有效配置，而不是构造或返回它们。 

## 方法

 ### 蛮力方法

 暴力解决方案会尝试将皇后放置在棋盘上每个可能的单元格组合中，然后验证该排列是否有效。 

一种可能的暴力策略是：

 - 生成所有可能的位置`n`棋盘上的皇后
 - 对于每种排列，扫描棋盘以确定是否有皇后互相攻击

 这种方法是正确的，因为它最终会检查每种可能的配置。 然而，它的效率极低。 

一个`n x n`董事会有`n²`细胞。 选择`n`这些细胞的皇后位置导致了大量的组合。 此外，验证每个配置需要跨行、列和对角线重复扫描。 

即使我们通过强制每行只有一个皇后来稍微改进，我们仍然探索`n!`可能的列排列。 其中许多很早就失效了，但是暴力并不能有效地修剪它们。 

### 最优回溯方法

 更好的解决方案使用回溯和修剪。 

我们不是生成完整的板并随后进行验证，而是增量地构建配置。 一旦皇后位置变得无效，我们就停止探索该分支。 

核心见解是，当逐行放置皇后时：

 - 每个递归调用只处理一行
 - 我们只需要测试一列或对角线是否已经被占用
 - 无效状态可以立即被拒绝

 我们维护三组：

 -`columns`跟踪占用的列
 -`diagonals`轨道占用主对角线使用`row - col`-`anti_diagonals`跟踪占用的反对角线使用`row + col`这允许在恒定时间内检测冲突。 

由于无效分支会被尽早修剪，因此搜索速度比暴力搜索要快得多。

 ## 算法演练

 1.初始化三个空集：

 -`columns`存储已经包含皇后的列
 -`diagonals`存储值`row - col`-`anti_diagonals`存储值`row + col`2. 从 row 开始启动递归回溯函数`0`。 
3. 对于当前行，迭代每一列`0`到`n - 1`。 
4. 对于每个候选人职位`(row, col)`，计算：

 -`diagonal = row - col`-`anti_diagonal = row + col`5. 检查是否：

 -`col`已经存在于`columns`-`diagonal`已经存在于`diagonals`-`anti_diagonal`已经存在于`anti_diagonals`如果这些条件中的任何一个为真，则将皇后放在这里会产生冲突，因此请跳过此位置。 
6. 如果职位有效：

 - 将列和对角线添加到各自的集合中
 - 递归处理下一行
 7. 如果递归达到`row == n`，这意味着皇后已成功放置在所有行中。 增加解决方案计数器。 
8. 探索分支后，从所有集合中删除当前位置。 这是回溯步骤，它恢复棋盘状态，以便探索其他可能性。 
9. 继续探索，直到处理完所有行和列。 

### 为什么它有效

 该算法维护一个重要的不变量：在处理一行之前，所有先前放置的皇后都保证不冲突。 

每个递归调用仅尝试保留此不变量的放置。 由于每个有效排列都被探索一次并且每个无效排列都被立即修剪，因此该算法正确地计算了所有不同的解决方案。 

## Python 解决方案```python
class Solution:
    def totalNQueens(self, n: int) -> int:
        columns = set()
        diagonals = set()
        anti_diagonals = set()

        solutions = 0

        def backtrack(row: int) -> None:
            nonlocal solutions

            if row == n:
                solutions += 1
                return

            for col in range(n):
                diagonal = row - col
                anti_diagonal = row + col

                if (
                    col in columns or
                    diagonal in diagonals or
                    anti_diagonal in anti_diagonals
                ):
                    continue

                columns.add(col)
                diagonals.add(diagonal)
                anti_diagonals.add(anti_diagonal)

                backtrack(row + 1)

                columns.remove(col)
                diagonals.remove(diagonal)
                anti_diagonals.remove(anti_diagonal)

        backtrack(0)

        return solutions
```实现直接遵循递归回溯策略。 

这三组提供恒定时间冲突检测。 这比反复扫描板子的效率要高得多。 

嵌套的`backtrack`函数一次处理一行。 如果`row == n`，则皇后已成功放置在每一行中，因此已找到有效的解决方案。 

对于当前行中的每一列，该算法计算两个对角线标识符：```python
diagonal = row - col
anti_diagonal = row + col
```这些值唯一地标识了整个板上的对角线。 

如果放置有效，则在递归探索下一行之前，会将皇后的列和对角线添加到集合中。 

递归完成后，使用以下命令恢复集合`remove`。 这是回溯的本质，算法暂时做出选择，探索所有后果，然后撤消该选择，以便测试其他可能性。 

## 解决方案```go
func totalNQueens(n int) int {
    columns := make(map[int]bool)
    diagonals := make(map[int]bool)
    antiDiagonals := make(map[int]bool)

    solutions := 0

    var backtrack func(int)

    backtrack = func(row int) {
        if row == n {
            solutions++
            return
        }

        for col := 0; col < n; col++ {
            diagonal := row - col
            antiDiagonal := row + col

            if columns[col] || diagonals[diagonal] || antiDiagonals[antiDiagonal] {
                continue
            }

            columns[col] = true
            diagonals[diagonal] = true
            antiDiagonals[antiDiagonal] = true

            backtrack(row + 1)

            delete(columns, col)
            delete(diagonals, diagonal)
            delete(antiDiagonals, antiDiagonal)
        }
    }

    backtrack(0)

    return solutions
}
```Go 实现密切反映了 Python 逻辑。 由于 Go 没有内置的集合类型，因此使用带有布尔值的映射来代替。 

回溯状态恢复用途`delete`递归完成后从映射中删除条目。 

整数溢出不是问题，因为解决方案的最大数量`n <= 9`轻松融入 Go 中`int`类型。

 ## 边缘情况

 ### 边缘情况 1，`n = 1`这是可能的最小输入。 幼稚的实现可能会意外返回`0`因为它假设有效的配置需要多个皇后。 

该实现自然地处理了这个问题，因为递归搜索成功放置了一个皇后并立即到达基本情况`row == n`。 

### 边缘情况 2，`n = 2`和`n = 3`这些电路板尺寸没有有效的解决方案。 不正确的实现有时会错误地将部分展示位置视为有效。 

回溯方法正确地探索每种可能的配置，并且仅在成功填充所有行时才增加解决方案计数器。 由于不存在有效的排列，因此结果保持不变`0`。 

### 边缘情况 3，对角线碰撞

 对角线冲突是 N 皇后解决方案中最常见的错误来源。 许多不正确的实现仅检查行和列。 

该解决方案使用两个不同的对角线标识符：```
row - col
row + col
```任何共享这些值之一的皇后都在同一条对角线上。 这保证了恒定时间对角线冲突检测，并确保立即拒绝无效布局。 

### 边缘情况 4，回溯状态恢复

 递归解决方案中的一个常见错误是忘记在递归返回后删除状态。 这会导致一个分支的放置错误地影响后续分支。 

此实现在每次递归调用后显式地从所有跟踪集中删除条目：```
columns.remove(col)
diagonals.remove(diagonal)
anti_diagonals.remove(anti_diagonal)
```这保证了每个递归分支都以正确的板状态开始。
