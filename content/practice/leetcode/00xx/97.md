[LeetCode 第 97 题](https://leetcode.com/problems/interleaving-string/)

 **难度：** 🟡 中等
 **主题：** 字符串、动态规划

 ## 解决方案

 ## 问题理解

 这个问题要求我们判断一个字符串是否`s3`可以通过**交错**另外两个字符串来形成，`s1`和`s2`。 

交错意味着我们将来自的字符组合起来`s1`和`s2`同时保留**每个原始字符串中字符的相对顺序**。 我们可以以任何模式在两个字符串之间交替，但我们不能重新排列任一字符串内的字符。 

例如，如果：```
s1 = "abc"
s2 = "def"
```然后：```
"adbcef"
```是有效的，因为顺序`"abc"`保持完整并且顺序`"def"`也保持原样。 

然而：```
"aedbcf"
```无效，因为字符的相对顺序`"def"`已经改变了。 

输入由三个字符串组成：

 -`s1`，第一个源字符串
 -`s2`，第二个源字符串
 -`s3`，我们要验证的目标字符串

 预期输出是一个布尔值：

 -`true`如果`s3`可以通过交错形成`s1`和`s2`-`false`否则

 一个关键的观察是，剧中的每个角色`s3`必须来自任一`s1`或者`s2`，并且两个字符串中的所有字符都必须仅使用一次。 这立即给了我们一个重要的验证步骤：```
len(s1) + len(s2) == len(s3)
```如果长度不相加，则不可能进行交错。 

限制相对较小：```
0 <= s1.length, s2.length <= 100
0 <= s3.length <= 200
```这些约束表明，在最坏的情况下，指数暴力搜索会太慢，但具有二次复杂度的动态规划解决方案是实用的。 

一些边缘情况值得预先关注。 一种重要的情况是一个或两个字符串都为空。 如果`s1`为空，那么`s3`必须完全等于`s2`，反之亦然。 当角色频繁重复时会发生另一个棘手的情况，例如`"aaa"`和`"aaa"`。 天真的贪婪策略很容易做出错误的选择，因为可能暂时存在多个有效路径，但只有其中一些路径会导致有效的最终答案。 我们还必须处理长度匹配但排序约束使得交织不可能的情况。 

## 方法

 ### 蛮力方法

 一个简单的想法是递归地尝试一切可能的方法来构建`s3`。 

在任何位置`s3`，我们可以：

 - 从中取出下一个字符`s1`，如果匹配
 - 从中取出下一个字符`s2`，如果匹配

 这自然会创建一个分支递归树。 

假设我们处于指数`(i, j)`在`s1`和`s2`。 既然我们已经消费了`i + j`字符，下一个字符`s3`是：```
k = i + j
```如果：```
s1[i] == s3[k]
```我们递归地尝试前进`i`。 

同样，如果：```
s2[j] == s3[k]
```我们递归地尝试前进`j`。 

蛮力方法是正确的，因为它探索了每一种有效的交错可能性。 如果任何路径成功消耗所有字符，则答案是`true`。 

然而，这种方法变得极其缓慢，因为许多状态会重复。 相同`(i, j)`可以通过不同的路径达到组合，从而导致指数重新计算。 

例如，重复的字符如：```
s1 = "aaa"
s2 = "aaa"
```创建许多重叠的递归分支。 

### 最佳解决方案的关键见解

 主要观察结果是该问题具有**重叠的子问题**。 

问题的状态可以通过以下方式完整描述：```
(i, j)
```在哪里：

-`i`字符已取自`s1`-`j`字符已取自`s2`自从：```
k = i + j
```的位置在`s3`是自动确定的。 

如果我们已经知道是否状态`(i, j)`可以构成剩余的后缀`s3`，我们不应该再次重新计算它。 

这自然会导致**动态编程**。 

我们定义：```
dp[i][j]
```意思是：

 > 是否为第一`i`的字符`s1`首先`j`的字符`s2`可以形成第一个`i + j`的字符`s3`。 

我们不是重复地重新计算可能性，而是逐步构建答案。 

由于每个状态仅取决于前一行和当前行，因此我们可以将内存使用优化为：```
O(s2.length)
```从而满足后续要求。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^(m+n)) | O(2^(m+n)) | O(m+n) | 递归尝试每个交错 |
 | 最优动态规划| O(m × n) | O(n) | 使用 DP 和滚动阵列优化 |

 在哪里：

-`m = len(s1)`-`n = len(s2)`## 算法演练

 我们将使用**一维动态规划数组**来实现最佳空间复杂度。 

1.首先检查长度是否匹配。 

如果：```
len(s1) + len(s2) != len(s3)
```然后返回`False`立即，因为交错是不可能的。 
2. 创建DP阵列。 

让：```
dp[j]
```代表是否：```
s1[:i] and s2[:j]
```可以形成：```
s3[:i+j]
```我们只需要一行，因为每个状态取决于：

 - 当前行的左值
 - 前一行的同一列值
 3. 初始化基本情况。 

从以下开始：```
dp[0] = True
```因为两个空字符串组成一个空字符串。 
4. 填充第一行。 

这对应于仅使用`s2`。 

如果字符继续匹配：```
s2[j-1] == s3[j-1]
```然后更新：```
dp[j]
```5. 迭代`s1`。 

对于中的每个字符`s1`， 更新：```
dp[0]
```因为该列意味着仅使用`s1`。 
6. 更新每个DP状态。 

对于每一个`(i, j)`：

 我们可以通过两种方式达到这种状态：

 来自`s1`：```
dp[j] and s1[i-1] == s3[i+j-1]
```这意味着我们在前一行中已经有效。 

从`s2`：```
dp[j-1] and s2[j-1] == s3[i+j-1]
```这意味着我们从左侧延伸。 

将它们结合起来：```
dp[j] = from_s1 or from_s2
```7. 返回最终答案。 

最后一个单元格：```
dp[len(s2)]
```告诉我们完整的交织是否可能。 

### 为什么它有效

 不变量是：

 >`dp[j]`总是表示前缀是否`s1[:i]`和`s2[:j]`可以形成`s3[:i+j]`。 

每个有效的交错必须以以下字符结尾`s1`或来自的字符`s2`。 DP 转换检查两种可能性并以归纳方式保留正确性。 由于每个子问题都只解决一次，因此我们避免了冗余工作，同时仍然考虑所有有效的交错。 

## Python 解决方案```python
class Solution:
    def isInterleave(self, s1: str, s2: str, s3: str) -> bool:
        m, n = len(s1), len(s2)

        if m + n != len(s3):
            return False

        dp = [False] * (n + 1)
        dp[0] = True

        # Initialize first row using only s2
        for j in range(1, n + 1):
            dp[j] = dp[j - 1] and s2[j - 1] == s3[j - 1]

        # Fill DP table
        for i in range(1, m + 1):
            # Update first column using only s1
            dp[0] = dp[0] and s1[i - 1] == s3[i - 1]

            for j in range(1, n + 1):
                target_index = i + j - 1

                from_s1 = (
                    dp[j]
                    and s1[i - 1] == s3[target_index]
                )

                from_s2 = (
                    dp[j - 1]
                    and s2[j - 1] == s3[target_index]
                )

                dp[j] = from_s1 or from_s2

        return dp[n]
```该实现从长度检查开始，因为不匹配的总长度使得交织变得不可能。 

这`dp`数组存储动态规划表的当前行。 最初，`dp[0] = True`因为空前缀匹配很简单。 

通过检查是否初始化第一行`s2`独自可以建立的开始`s3`。 

然后我们迭代`s1`，逐行。 对于每一行，`dp[0]`被更新以表示是否`s1`单独形成相应的前缀`s3`。 

对于每个内部状态，我们检查两种可能的转换：

 - 延伸自`s1`- 延伸自`s2`如果任一路径有效，则状态变为`True`。 

在最后，`dp[n]`表示所有字符是否来自`s1`和`s2`成功形成`s3`。 

## 解决方案```go
func isInterleave(s1 string, s2 string, s3 string) bool {
	m, n := len(s1), len(s2)

	if m+n != len(s3) {
		return false
	}

	dp := make([]bool, n+1)
	dp[0] = true

	// Initialize first row using only s2
	for j := 1; j <= n; j++ {
		dp[j] = dp[j-1] && s2[j-1] == s3[j-1]
	}

	// Fill DP table
	for i := 1; i <= m; i++ {
		// Update first column using only s1
		dp[0] = dp[0] && s1[i-1] == s3[i-1]

		for j := 1; j <= n; j++ {
			targetIndex := i + j - 1

			fromS1 := dp[j] &&
				s1[i-1] == s3[targetIndex]

			fromS2 := dp[j-1] &&
				s2[j-1] == s3[targetIndex]

			dp[j] = fromS1 || fromS2
		}
	}

	return dp[n]
}
```Go 的实现与 Python 版本非常相似。 由于 Go 字符串是字节可索引的，并且输入仅由小写英文字母组成，因此直接索引是安全且高效的。 

与 Python 不同，Go 需要使用以下方式显式分配切片：```go
make([]bool, n+1)
```无需特殊处理`nil`需要值，因为空字符串的长度自然为零并且循环行为正确。 

## 工作示例

 ### 示例 1```
s1 = "aabcc"
s2 = "dbbca"
s3 = "aadbbcbcac"
```我们在每一行之后跟踪 DP 数组。 

初始状态：

 | j | 0 | 1 | 2 | 3 | 4 | 5 |
 | --- | --- | --- | --- | --- | --- | --- |
 | DP | T | F | F | F | F | F |

 加工后`"a"`从`s1`：

 | DP | T | F | F | F | F | F |

 加工后`"aa"`：

 | DP | T | T | T | T | T | F |

 After processing more characters, valid paths continue surviving.

 最终状态：

 | DP | F | F | T | F | T | T |

 自从：```
dp[5] = True
```答案是：```
true
```### 示例 2```
s1 = "aabcc"
s2 = "dbbca"
s3 = "aadbbbaccc"
```DP 转换最终会失败，因为无法维持字符顺序。 

最终状态：```
dp[5] = False
```结果：```
false
```### 示例 3```
s1 = ""
s2 = ""
s3 = ""
```长度检查：```
0 + 0 = 0
```初始化：```
dp = [True]
```没有循环执行。 

最终答案：```
True
```## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(m × n) | 每一个`(i, j)`状态计算一次 |
 | 空间| O(n) | 仅存储一个 DP 行 |

 在哪里：```
m = len(s1)
n = len(s2)
```该算法仅处理每个前缀组合一次。 由于有`m × n`状态，运行时间是二次的。 内存优化之所以有效，是因为每个状态仅取决于当前行和前一行，从而允许我们重用单个数组。

 ## 边缘情况

 ### 空字符串

 一个或多个输入字符串可能为空。 如果实现假设两个源字符串都包含字符，则这种情况很容易处理不当。 

例如：```
s1 = ""
s2 = "abc"
s3 = "abc"
```该实现自然地处理了这个问题，因为 DP 初始化仅使用填充第一行`s2`。 Similarly, when both strings are empty,`dp[0] = True`正确返回`True`。 

### 长度不匹配

 如果：```
len(s1) + len(s2) != len(s3)
```那么无论字符排列如何，交织都是不可能的。 

这种提前退出可以防止不必要的计算，并避免稍后在 DP 转换中出现微妙的索引错误。 

例子：```
s1 = "abc"
s2 = "def"
s3 = "abcdefg"
```由于长度不匹配，函数立即返回`False`。 

### 重复字符

 重复的字符可以欺骗贪婪的解决方案。 

例子：```
s1 = "aaa"
s2 = "aaa"
s3 = "aaaaaa"
```在很多岗位上，两人`s1`和`s2`包含匹配的字符。 贪心算法可能会选择错误并随后陷入困境。 

动态编程解决方案通过隐式探索两种可能性并存储有效状态来避免此问题，确保不会过早丢弃正确的路径。 

### 违反订单保护行为

 字符可能全部存在于`s3`，但里面的顺序`s1`或者`s2`可能会被打破。 

例子：```
s1 = "abc"
s2 = "def"
s3 = "aedbcf"
```虽然每个字符只出现一次，但出现的顺序`"def"`被侵犯。 DP 转换规则可防止无效序列，因为每个字符必须与相应源字符串中正确的下一个字符匹配。
