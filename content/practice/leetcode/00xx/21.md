[LeetCode 第 21 题](https://leetcode.com/problems/merge-two-sorted-lists/)

 **难度：** 🟢简单
 **主题：** 链表、递归

 ## 解决方案

 ## 问题理解

 该问题要求我们将两个已经排序的单链表合并为一个新的排序链表。 重要的细节是我们没有为合并结果创建全新的节点。 相反，我们通过重新连接现有节点来重用它们`next`指针。 

每个输入列表均按非降序排序。 这意味着值可以重复，并且每个节点的值都小于或等于其后面的节点的值。 

例如：

-`list1 = [1,2,4]`-`list2 = [1,3,4]`两个列表均单独排序。 合并的结果还必须保持排序：

 -`[1,1,2,3,4,4]`输入代表两个单链表的头。 每个节点包含：

 - 一个值，`val`- 指向下一个节点的指针，`next`输出应该是合并链表的头节点。 

约束非常小，两个列表中总共最多有 50 个节点。 正因为如此，几乎任何合理的算法都会运行得足够快。 尽管如此，这个问题仍然很重要，因为它教授了许多更困难的问题中使用的基本链表模式，特别是链表上的合并排序。 

一些边缘情况立即很重要：

 - 一个或两个列表可能为空
 - 两个列表可能包含重复值
 - 一个列表中的所有节点可能会出现在另一个列表之前
 - 列表可能有不同的长度
 - 值可能为负

 该问题保证两个输入列表都已排序。 这种保证使得高效的线性时间合并成为可能。 

## 方法

 ### 蛮力方法

 解决该问题的一个直接方法是：

 1. 遍历两个链表
 2. 将所有值复制到数组中
 3. 对数组进行排序
 4. 根据排序后的值创建一个全新的链表

 这是有效的，因为对所有值进行排序可以保证最终列表的排序正确。 

例如：

 - 提取值：`[1,2,4,1,3,4]`- 种类：`[1,1,2,3,4,4]`- 建立新的链表

 尽管正确，但这种方法忽略了输入的一个重要属性：两个列表都已排序。 重新排序数据会做不必要的工作。 

它还使用额外的内存，因为我们将所有值存储在数组中并创建全新的节点。 

### 最佳方法

 关键的观察结果是两个列表都已经排序。 

这意味着最小的剩余元素必须始终位于两个列表之一的前面。 我们可以重复比较两个列表的当前节点，并将较小的节点附加到合并结果中。 

这与合并排序的合并步骤中使用的想法相同。 

我们维持：

 - 指向的指针`list1`- 指向的指针`list2`- 合并列表的尾指针

 每一步：

 - 选择较小的当前节点
 - 将其附加到合并列表中
 - 前进相应的指针

 由于每个节点只处理一次，因此该算法以线性时间运行。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O((n + m) log(n + m)) | O((n + m) log(n + m)) | O(n + m) | 提取值、排序、重建列表 |
 | 最佳 | O(n + m) | O(1) | O(1) | 直接使用指针操作合并列表 |

 这里，`n`和`m`是两个链表的长度。 

## 算法演练

 ### 迭代合并算法

 1. 创建一个虚拟节点，作为合并列表的临时开始。 

虚拟节点简化了边缘情况，因为我们从不需要第一个插入节点的特殊逻辑。 
2. 创建一个`tail`最初指向虚拟节点的指针。 

这`tail`指针始终表示合并列表中的最后一个节点。 
3. 虽然两者`list1`和`list2`不为空：

 - 比较`list1.val`和`list2.val`- 将较小的节点附加到`tail.next`- 向前移动对应的列表指针
 - 提前`tail`这保证了合并列表在每一步都保持排序。 
4. 循环结束后，一个列表可能仍包含剩余节点。 

由于剩余的节点已经排序，我们可以直接附加其余的节点，而无需进一步比较。 
5. 返回`dummy.next`。 

我们跳过虚拟节点本身，因为它仅用于简化构造。 

### 为什么它有效

 在每一步中，算法都会从两个排序列表的前面选择最小的可用节点。 由于该所选节点后面的所有剩余节点都大于或等于该节点，因此附加较小的前面节点可以保留排序顺序。 

不变量是：

 - 到目前为止构建的合并列表始终是排序的。 
- 所有尚未处理的节点仍保留在其原始列表中排序。 

因为该算法在保持这个不变性的同时对每个节点只处理一次，所以最终的合并列表是正确排序的。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

from typing import Optional

class Solution:
    def mergeTwoLists(
        self,
        list1: Optional[ListNode],
        list2: Optional[ListNode]
    ) -> Optional[ListNode]:

        dummy = ListNode()
        tail = dummy

        while list1 and list2:
            if list1.val <= list2.val:
                tail.next = list1
                list1 = list1.next
            else:
                tail.next = list2
                list2 = list2.next

            tail = tail.next

        if list1:
            tail.next = list1
        else:
            tail.next = list2

        return dummy.next
```实现首先创建一个虚拟节点。 该节点避免了对第一次插入合并列表的特殊处理。 

这`tail`指针始终跟踪合并结果中的最后一个节点。 最初，双方`tail`和`dummy`指向同一个节点。 

这`while`只要两个列表仍然包含节点，循环就会继续。 在循环内部，我们比较当前节点值：

 - 如果`list1.val`小于或等于，我们附加该节点
 - 否则，我们附加节点`list2`附加节点后，我们将相应的列表指针向前移动，因为该节点现在已被消耗。 

我们也搬家`tail`向前，因此它始终位于合并列表的末尾。 

当循环结束时，一个列表就耗尽了。 由于另一个列表已经排序，我们可以直接附加剩余部分。 

最后，我们返回`dummy.next`因为虚拟节点本身不是答案的一部分。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func mergeTwoLists(list1 *ListNode, list2 *ListNode) *ListNode {
	dummy := &ListNode{}
	tail := dummy

	for list1 != nil && list2 != nil {
		if list1.Val <= list2.Val {
			tail.Next = list1
			list1 = list1.Next
		} else {
			tail.Next = list2
			list2 = list2.Next
		}

		tail = tail.Next
	}

	if list1 != nil {
		tail.Next = list1
	} else {
		tail.Next = list2
	}

	return dummy.Next
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

主要的语言特定差异是处理`nil`指针而不是Python的`None`。 

Go 使用显式指针语法：

 -`&ListNode{}`创建一个新节点
 -`tail.Next`访问下一个指针

 这里不存在整数溢出问题，因为节点值保持在非常小的范围内。

 ## 边缘情况

 ### 一个或两个列表为空

 当代码假设节点始终存在时，就会发生常见的链表错误。 如果一个列表是`None`, 取消引用`.val`会崩溃的。 

此实现可以自然地处理这种情况，因为合并循环仅在两个列表都非空时运行：```
while list1 and list2:
```如果任一列表最初为空，则算法直接跳到附加剩余列表。 

### 重复值

 该列表可能包含重复的数字，例如：```
[1,1,1]
[1,1]
```有缺陷的实现可能会意外地跳过重复项或破坏顺序。 

该解决方案明确允许平等：```
if list1.val <= list2.val:
```这保证了合并输出中正确保留重复项。 

### 一个列表更早完成

 考虑：```
list1 = [1]
list2 = [2,3,4,5]
```一个常见的错误是忘记在主循环结束后附加剩余的节点。 

此实现通过以下方式处理该问题：```
if list1:
    tail.next = list1
else:
    tail.next = list2
```由于剩余部分已经排序，因此直接附加它可以保持正确性。
