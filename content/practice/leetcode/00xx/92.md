[LeetCode 第 92 题](https://leetcode.com/problems/reverse-linked-list-ii/)

 **难度：** 🟡 中等
 **Topics:** Linked List

 ## 解决方案

 ## 问题理解

 这个问题要求我们只反转单链表的特定部分，而不是反转整个列表。 我们给出一个链表的头和两个整数位置，`left`和`right`， 在哪里`left <= right`。 目标是反转从位置开始的所有节点`left`并结束于位置`right`，同时保持链表的其余部分不变。 

换句话说，想象一下切掉链表的一个连续段，反转该段中节点的顺序，然后将其重新连接回原始链表。 位置是 **1-indexed**，意味着第一个节点是位置`1`,第二个节点是位置`2`， 等等。 

例如，考虑：```
1 -> 2 -> 3 -> 4 -> 5
```如果`left = 2`和`right = 4`，子列表：```
2 -> 3 -> 4
```必须反转为：```
4 -> 3 -> 2
```并重新附加：```
1 -> 4 -> 3 -> 2 -> 5
```输入包括：

 -`head`，单链表的第一个节点
 -`left`, 反转的起始位置
 -`right`, 反转的结束位置

 预期输出是指定子列表反转后修改后的链表的头。 

约束告诉我们列表包含`1`和`500`节点，相对较小。 这意味着即使效率较低的解决方案也可以在限制内工作，但后续内容特别询问我们是否可以在**一次**中解决它，这强烈暗示需要一种最佳的就地链表操作方法。 

预先识别一些边缘情况非常重要。 如果`left == right`，没有什么可以反转，因为该段仅包含一个节点。 从第一个节点（`left = 1`）很棘手，因为反转后头部本身可能会发生变化。 反转列表的尾部需要仔细重新连接指针，以便反转的段仍然正确链接到列表的其余部分。 如果指针更新以错误的顺序完成，则幼稚的实现很容易丢失对节点的引用。 

## 方法

 ### 蛮力方法

 解决这个问题的一个直接方法是首先将链表转换为节点值数组。 将值存储在数组中后，反转子数组`left - 1`和`right - 1`使用标准数组操作变得简单。 反转后，我们可以重建链表或覆盖原链表中的节点值。 

这是可行的，因为数组支持直接索引，使子数组反转变得容易。 由于列表大小很小，因此对于给定的约束，性能是可以接受的。 

然而，这种方法并不理想，因为它使用额外的内存并且没有利用链表结构。 更重要的是，后续明确要求一种一次性解决方案，这表明我们应该直接操作指针而不是复制值。 

### 最佳方法

 关键的观察是，我们可以通过在单次遍历链表期间仔细地重新连接指针来**就地**反转子列表。 

主要挑战是将反向段与列表中未更改的部分重新连接。 我们需要跟踪：

 - 反转开始之前的节点
 - 子列表的第一个节点被反转
 - 反转结束后立即的节点

 一个有用的技巧是在头部之前引入一个**虚拟节点**。 这简化了处理从位置开始反转的情况`1`，因为反转段之前总是有一个节点。 

我们可以重复地将节点移动到子列表的前面，而不是使用传统的指针反转循环完全反转子列表。 该技术在一次遍历中执行反转并避免额外的内存分配。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 将链表转换为数组、反转段、重建或覆盖 |
 | 最佳| O(n) | O(1) | O(1) | 使用虚拟节点和一次传递将指针反转到位 |

 ## 算法演练

 最佳算法使用指针操作来反转链表段。 

1. **Handle trivial cases**

 如果列表为空或`left == right`，立即返回原始列表。 不需要逆转。 
2. **创建虚拟节点**

 Create a dummy node whose`next`指向`head`。 

这简化了反转从第一个节点开始的边缘情况，因为我们总是有一个有效的“前一个”节点。 

例子：```
dummy -> 1 -> 2 -> 3 -> 4 -> 5
```3. **移动到反转开始之前的节点**

 遍历列表直到到达位置`left - 1`。 

该节点很重要，因为反转后，它必须连接到反转子列表的新前面。 

为了：```
left = 2
```我们停在节点`1`。 
4. **初始化反转指针**

 让：

 -`prev_node`= 反转前的节点
 -`current`= 线段的第一个节点

 示例：```
dummy -> 1 -> 2 -> 3 -> 4 -> 5
           ^
      prev_node
                ^
              current
```5. **前插反转**

 重复`right - left`次数：

 - 删除之后的节点`current`- 之后立即插入`prev_node`迭代示例：

 初始：```
1 -> 2 -> 3 -> 4 -> 5
```移动`3`在...前面`2`：```
1 -> 3 -> 2 -> 4 -> 5
```然后移动`4`在前：```
1 -> 4 -> 3 -> 2 -> 5
```6. **归还新头**

 由于头部可能已经改变，返回`dummy.next`。 

### 为什么它有效

 该算法保持了一个重要的不变量：每次迭代之后，之间的节点`left`并且当前处理的位置已经反转并正确连接到列表中未更改的部分。 这`current`指针始终标记部分反转段的尾部，而节点则重复插入在前面。 因为每次指针更新都会保留连接性，所以列表永远不会断开连接，并且之后`right - left`迭代中目标段完全反转。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

class Solution:
    def reverseBetween(
        self,
        head: Optional[ListNode],
        left: int,
        right: int
    ) -> Optional[ListNode]:

        if not head or left == right:
            return head

        dummy = ListNode(0)
        dummy.next = head

        prev_node = dummy

        # Move to node before reversal starts
        for _ in range(left - 1):
            prev_node = prev_node.next

        current = prev_node.next

        # Reverse sublist using front insertion
        for _ in range(right - left):
            next_node = current.next
            current.next = next_node.next

            next_node.next = prev_node.next
            prev_node.next = next_node

        return dummy.next
```实现首先处理不需要逆转的琐碎情况。 如果列表为空或`left == right`，立即返回原来的头。 

然后创建一个虚拟节点并将其连接到原始头。 这简化了指针处理，特别是当反转从位置开始时`1`。 

这`prev_node`指针移动到反转段之前的节点。 该指针充当重新连接反转部分的锚点。 

变量`current`存储被反转的段的第一个节点。 在每次迭代期间，紧随其后的节点`current`被提取并插入到反转区域的前面。 这有效地反转了顺序，而不需要单独的反转过程。 

最后，`dummy.next`返回是因为链表的头可能已更改。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func reverseBetween(head *ListNode, left int, right int) *ListNode {
    if head == nil || left == right {
        return head
    }

    dummy := &ListNode{Next: head}
    prevNode := dummy

    // Move to node before reversal starts
    for i := 0; i < left-1; i++ {
        prevNode = prevNode.Next
    }

    current := prevNode.Next

    // Reverse sublist using front insertion
    for i := 0; i < right-left; i++ {
        nextNode := current.Next

        current.Next = nextNode.Next

        nextNode.Next = prevNode.Next
        prevNode.Next = nextNode
    }

    return dummy.Next
}
```Go 实现遵循与 Python 版本相同的逻辑，但显式使用指针语法。 由于 Go 没有`None`，它使用`nil`表示一个空链表。 指针操作的行为类似，尽管在大多数情况下通过字段访问自动发生取消引用。 

这里不存在整数溢出问题，因为节点值和索引很小并且算法仅执行指针操作。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 我们遍历链表一次，每个节点最多被访问固定次数 |
 | 空间| O(1) | O(1) | 仅使用了少量指针变量，没有分配额外的数据结构 |

 时间复杂度是线性的，因为我们首先移动到反转的起点，然后对目标段中的每个节点执行恒定量的工作。 尽管存在嵌套操作，但每次指针操作都是恒定时间。 

空间复杂度是恒定的，因为算法会就地修改链表，并且无论输入大小如何，都只使用固定数量的引用。

    for value in values:
        current.next = ListNode(value)

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`left == right`。 在这种情况下，子列表仅包含一个节点，这意味着反转不会产生任何效果。 有缺陷的实现可能仍会尝试指针操作并意外破坏列表。 该实现通过立即返回原始头来避免这种情况。 

另一个关键情况是当反转从列表的头部开始时，这意味着`left = 1`。 如果不仔细处理，重新连接反转的部分就会变得困难，因为头之前没有前一个节点。 虚拟节点通过为所有情况提供稳定的前驱节点，优雅地解决了这个问题。 

第三个重要的边缘情况是反转链表的尾部。 例如：```
1 -> 2 -> 3 -> 4
left = 3
right = 4
```反转后，列表应变为：```
1 -> 2 -> 4 -> 3
```不正确的指针更新很容易断开尾部或创建循环。 该实现可以安全地处理这个问题，因为`current`始终保持连接到未反转的部分，确保剩余节点永远不会丢失。 

最后一个微妙的情况是反转整个链表。 由于开始和结束连接都会发生变化，因此没有虚拟节点的实现通常无法正确更新头部。 返回`dummy.next`保证反转后始终返回正确的头。
