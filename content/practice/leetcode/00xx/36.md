 **难度：** 🟡 中等
 **主题：** 数组、哈希表、矩阵

 ## 解决方案

 ## 问题理解

 这个问题要求我们验证部分填充的数独板是否遵循核心数独规则。 板子始终是固定的`9 x 9`网格，每个单元格包含一个数字`'1'`到`'9'`或角色`'.'`，它代表一个空单元格。 

有效的数独配置必须满足三个独立条件：

 1. 每行必须包含唯一的数字`1`到`9`。 
2. 每列必须包含唯一的数字`1`到`9`。 
3. 每个`3 x 3`子框必须包含来自的唯一数字`1`到`9`。 

重要的细节是我们仅验证当前的董事会状态。 我们没有被要求解决数独难题。 棋盘可能不完整，但只要尚未违反数独规则，仍被视为有效。 

输入是一个二维数组，其中`board[i][j]`代表行的值`i`和列`j`。 输出是一个布尔值：

 -`true`如果当前棋盘满足所有数独约束
 -`false`如果行、列或子框中出现任何重复数字

 约束很小且固定：

 - 董事会始终`9 x 9`- 每个细胞都包含`'.'`或一个数字`'1'`通过`'9'`由于输入大小永远不会改变，因此问题不在于如何有效地处理大规模数据。 相反，挑战在于正确、干净地实现验证逻辑。 

一些边缘情况很重要：

 - 空单元格`'.'`必须完全忽略。 
- 重复项可以独立出现在行、列或子框中。 
- 相同的数字可以全局出现多次，只要它们不在同一行、列或子框中即可。 
- 董事会可能不完整但仍然有效。 
- 重复可能会在遍历中很早或很晚发生，因此算法应立即检测违规行为。 

## 方法

 ### 蛮力方法

 蛮力方法检查每一行、每一列和每个`3 x 3`子盒独立。 

对于每一行，我们扫描所有九个单元格并验证没有数字出现多次。 我们对所有列重复相同的过程。 然后我们分别扫描每个`3 x 3`框并再次检查是否有重复项。 

这种方法是正确的，因为数独的有效性完全由这三个条件决定。 如果每行、每列和子框都包含唯一的数字，则该棋盘有效。 

简单的实现可能会重复扫描结构或比较每对元素，从而导致不必要的重复工作。 例如，在每行或框内使用嵌套循环检查重复项会产生冗余比较。 

尽管电路板尺寸很小且固定，但这种实现方式会变得冗长且难以推理。 

### 最佳方法

 关键的见解是，数独的有效性可以在单次遍历棋盘时得到验证。 

当我们访问每个单元格时，我们同时跟踪：

 - 每行出现了哪些数字
 - 每列中出现了哪些数字
 - 每个中出现了哪些数字`3 x 3`子盒

 哈希集在这里是理想的选择，因为它们提供恒定时间的插入和查找。 

当我们遇到一个数字时：

 - 如果对应的行集中已经存在，则该棋盘无效。 
- 如果对应列集中已存在，则该板无效。 
- 如果对应的子盒集中已经存在，则该板无效。 

否则，我们将数字插入到所有三个结构中并继续。 

子框索引可以使用以下公式计算：```
box_index = (row // 3) * 3 + (col // 3)
```这映射了九个`3 x 3`盒子变成索引`0`通过`8`。 

This solution is cleaner, easier to maintain, and performs all validation in one pass.

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(9立方) | O(1) | O(1) | Separately scans rows, columns, and boxes with repeated comparisons |
 | 最佳| O(9²) | O(1) | O(1) | Single traversal using hash sets for fast duplicate detection |

 虽然我们写`O(9²)`和`O(1)`，棋盘尺寸是固定的，所以技术上都是时间恒定，实践中空间恒定。 

## 算法演练

 1. 创建三个集合来跟踪已使用的数字：

 - 一个用于行
 - 一个用于列
 - 一件用于`3 x 3`子盒

 每个集合包含九个哈希集，每个结构一组。 
2. 使用嵌套循环遍历板中的每个单元格。 

外循环遍历行，内循环遍历列。 
3. 跳过空单元格。 

如果当前值为`'.'`，它不参与数独验证，因此继续下一个单元格。 
4. 计算子框索引。 

使用：```
box_index = (row // 3) * 3 + (col // 3)
```这会将棋盘坐标转换为九个子框标识符之一。 
5. 检查该数字是否已存在于：

 - 当前行集
 - 当前列集
 - 当前的盒子设置

 如果该数字存在于其中任何一个中，则返回`False`立即因为数独规则被违反。 
6. 将数字插入所有三组中。 

这记录了该数字现在已经出现在当前行、列和框中。 
7. 继续，直到所有单元格均已处理完毕。 
8. 如果没有发现重复项，则返回`True`。 

### 为什么它有效

 该算法保持每个处理的行、列和子框仅包含唯一数字的不变性。 

插入前会检查每个数字。 因此，如果存在重复项，算法会立即检测到它。 如果遍历成功完成，则没有行、列或子框包含重复的数字，这与数独有效性定义完全匹配。 

## Python 解决方案```python
from typing import List

class Solution:
    def isValidSudoku(self, board: List[List[str]]) -> bool:
        rows = [set() for _ in range(9)]
        cols = [set() for _ in range(9)]
        boxes = [set() for _ in range(9)]

        for row in range(9):
            for col in range(9):
                value = board[row][col]

                if value == ".":
                    continue

                box_index = (row // 3) * 3 + (col // 3)

                if value in rows[row]:
                    return False

                if value in cols[col]:
                    return False

                if value in boxes[box_index]:
                    return False

                rows[row].add(value)
                cols[col].add(value)
                boxes[box_index].add(value)

        return True
```实现首先创建三个集合数组。 每组存储在特定行、列或子框中已经看到的数字。 

嵌套循环遍历每个棋盘位置。 空单元格将被忽略，因为它们不影响数独的有效性。 

对于非空单元格，我们计算相应的子框索引。 该公式将行和列分组为`3 x 3`地区。 

在插入数字之前，我们检查它是否已存在于任何相关集合中。 如果是，则棋盘违反了数独规则，因此该函数立即返回`False`。 

如果未找到重复数字，则将该数字插入到所有三个跟踪集中。 

处理完整个板子且未检测到任何冲突后，该板子有效，因此函数返回`True`。 

## 解决方案```go
func isValidSudoku(board [][]byte) bool {
    rows := make([]map[byte]bool, 9)
    cols := make([]map[byte]bool, 9)
    boxes := make([]map[byte]bool, 9)

    for i := 0; i < 9; i++ {
        rows[i] = make(map[byte]bool)
        cols[i] = make(map[byte]bool)
        boxes[i] = make(map[byte]bool)
    }

    for row := 0; row < 9; row++ {
        for col := 0; col < 9; col++ {
            value := board[row][col]

            if value == '.' {
                continue
            }

            boxIndex := (row/3)*3 + (col / 3)

            if rows[row][value] {
                return false
            }

            if cols[col][value] {
                return false
            }

            if boxes[boxIndex][value] {
                return false
            }

            rows[row][value] = true
            cols[col][value] = true
            boxes[boxIndex][value] = true
        }
    }

    return true
}
```Go 解决方案遵循与 Python 版本相同的逻辑。 由于 Go 没有内置的集合类型，因此使用带有布尔值的映射来模拟集合。 

每张地图都会跟踪某个数字是否已经出现。 访问 Go 映射中缺失的键会返回零值`false`，这使得成员资格检查变得简单。 

该板使用`[][]byte`而不是字符串，因此使用字节文字执行比较，例如`'.'`。

 ## 边缘情况

 一个重要的边缘情况是一块完全空的板。 由于所有细胞都含有`'.'`，不存在违反规则的情况。 有缺陷的实现可能会错误地将缺失值视为重复或无效输入。 该解决方案完全跳过空单元，因此空板被正确地视为有效。 

另一个重要的边缘情况是当重复项仅出现在`3 x 3`子框，而行和列仍然有效。 如果实现仅验证行和列，则很容易忽略这一点。 专注的`boxes`跟踪结构确保子盒违规被独立检测。 

当重复项出现在遍历后期时，会出现微妙的边缘情况。 例如，前八行可能完全有效，而违规可能发生在最后一个单元格中。 该算法可以正确处理此问题，因为每个插入都会在记录之前立即进行检查。 

错误的另一个潜在来源是不正确的子框索引。 如果映射公式错误，单元格可能会被分配到不正确的框。 使用：```
(row // 3) * 3 + (col // 3)
```将每个单元正确映射到九个子框之一。 这保证了每个`3 x 3`区域是独立验证的。
