[LeetCode 第 22 题](https://leetcode.com/problems/generate-parentheses/)

 **难度：** 🟡 中等
 **主题：** 字符串、动态规划、回溯

 ## 解决方案

 ## 问题理解

 该问题要求我们生成所有可能的有效组合`n`成对的括号。 

有效的括号字符串是每个左括号`(`有匹配的右括号`)`，并且括号正确嵌套。 例如，`"(()())"`有效，因为每个左括号都按正确的顺序关闭。 然而，字符串像`"(()"`或者`")("`无效，因为括号不平衡或顺序不正确。 

输入由单个整数组成`n`，它代表我们必须使用多少对括号。 由于每对包含两个字符，因此每个生成的字符串都有长度`2 * n`。 

输出应包含所有唯一的格式良好的括号组合，这些组合可以使用精确的方式形成`n`左括号和`n`右括号。 

限制相对较小：```
1 <= n <= 8
```虽然`n`很小，有效组合的数量增长很快。 有效组合的数量由加泰罗尼亚数字给出。 例如：

-`n = 1`产生 1 种组合
 -`n = 3`产生 5 种组合
 -`n = 8`产生 1430 种组合

 这意味着暴力生成变得越来越低效，因为大多数生成的字符串都是无效的。 

一个重要的边缘情况是`n = 1`，其中仅存在一个有效结果：`"()"`。 另一个微妙的问题是确保我们在构造过程中的任何时候放置的右括号都不会多于左括号。 幼稚的实现可能会生成无效的前缀，例如`")("`，以后永远不会有效。 

该问题保证了`n`至少为 1，因此我们不需要处理空输入或负值。 

## 方法

 ### 蛮力方法

 一个简单的想法是生成每个可能的长度字符串`2 * n`组成`(`和`)`人物。 由于每个位置都有两个选择，因此有`2^(2n)`可能的字符串。 

对于每个生成的字符串，我们可以使用余额计数器检查它是否有效：

 - 增加计数器`(`- 减少计数器`)`- 如果计数器变为负数，则该字符串无效
 - 最后，计数器必须为零

 这种方法是正确的，因为它会检查所有可能的候选者并过滤掉无效的候选者。 

然而，它的效率极低，因为绝大多数生成的字符串都是无效的。 例如，当`n = 8`，我们会生成`2^16 = 65536`字符串，尽管只有 1430 有效。 

### 最优回溯方法

 关键的见解是我们首先不应该构建无效的部分字符串。 

我们可以递归地仅构造有效的前缀，而不是生成所有可能的组合并随后进行过滤。 

在施工期间的任何时刻：

 - 我们可以添加`(`如果我们还有左括号
 - 我们可以添加`)`仅当使用的右括号数量少于使用的左括号数量时

 这保证了每个部分字符串仍然可能有效。 

这是一个经典的回溯问题，因为：

 - 我们逐步构建解决方案
 - 我们递归地探索多种选择
 - 我们立即放弃无效路径

 通过尽早修剪无效分支，我们可以避免不必要的工作并仅生成有效的组合。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^(2n) * n) | O(2^(2n) * n) | O(2^(2n) * n) | O(2^(2n) * n) | 生成每一个可能的字符串并验证每一个 |
 | 最佳 | O(Cn * n) | O(n) 不包括输出 | 回溯仅生成有效组合，其中 Cn 是第 n 个加泰罗尼亚数字 |

 ## 算法演练

 1. 从一个空字符串和两个计数器开始：

 -`open_count`，使用的左括号的数量
 -`close_count`, 使用的右括号的数量

 这些计数器帮助我们跟踪当前的部分字符串是否仍然有效。 
2. 如果当前字符串长度达到`2 * n`，我们使用了所有括号。 

此时，字符串必须有效，因为我们的构造规则不允许无效状态。 我们将其添加到结果列表中。 
3.如果`open_count < n`，我们可以安全地添加另一个左括号。 

我们继续递归地构建字符串：

 - 再一个`(`-`open_count + 1`4. 如果`close_count < open_count`，我们可以添加一个右括号。 

这个条件很关键。 它保证我们永远不会创建右括号多于左括号的前缀，这会立即使字符串无效。 
5. 继续递归探索这两种可能性，直到生成所有有效字符串。 
6. 递归调用返回时自然会发生回溯。 

每个递归分支独立探索一种可能的选择。 

### 为什么它有效

 该算法保持了一个重要的不变量：

 - 在每一步中，部分字符串都有效或仍然有效。 

条件`close_count <= open_count`确保我们永远不会创建无效的前缀。 因为我们只有在字符串达到长度时才停止`2 * n`，每个生成的字符串恰好包含`n`开放和`n`按有效顺序关闭括号。 

由于可以使用这些规则构造每个有效组合，并且永远不会探索无效前缀，因此该算法会一次性生成所有有效解决方案。 

## Python 解决方案```python
from typing import List

class Solution:
    def generateParenthesis(self, n: int) -> List[str]:
        result = []

        def backtrack(current: str, open_count: int, close_count: int) -> None:
            # Base case: complete valid combination
            if len(current) == 2 * n:
                result.append(current)
                return

            # Add opening parenthesis if available
            if open_count < n:
                backtrack(current + "(", open_count + 1, close_count)

            # Add closing parenthesis if valid
            if close_count < open_count:
                backtrack(current + ")", open_count, close_count + 1)

        backtrack("", 0, 0)

        return result
```该实现使用了一个名为的嵌套辅助函数`backtrack`递归地构建有效的括号字符串。 

这`result`列表存储所有有效组合。 

递归函数接受三个参数：

 -`current`，当前部分构造的字符串
 -`open_count`, 使用了多少个左括号
 -`close_count`, 使用了多少个右括号

 当字符串长度达到时，就会发生基本情况`2 * n`。 此时，该字符串是完整且有效的，因此它会被添加到结果列表中。 

如果还有剩余的空位，第一个递归分支会添加一个左括号。 

仅当第二个递归分支保持字符串有效时才添加右括号。 条件`close_count < open_count`防止无效前缀，例如`")("`。 

因为Python中的字符串是不可变的，`current + "("`为每个递归调用创建一个新字符串。 这使递归分支保持独立并避免手动回溯清理。 

最后，递归以空字符串和零个括号开始。 

## 解决方案```go
func generateParenthesis(n int) []string {
    result := []string{}

    var backtrack func(current string, openCount int, closeCount int)

    backtrack = func(current string, openCount int, closeCount int) {
        // Base case
        if len(current) == 2*n {
            result = append(result, current)
            return
        }

        // Add opening parenthesis
        if openCount < n {
            backtrack(current+"(", openCount+1, closeCount)
        }

        // Add closing parenthesis
        if closeCount < openCount {
            backtrack(current+")", openCount, closeCount+1)
        }
    }

    backtrack("", 0, 0)

    return result
}
```Go 实现遵循与 Python 版本相同的递归回溯策略。 

一个显着的区别是 Go 要求在分配函数体之前显式声明递归函数变量。 这就是代码首先声明的原因：```go
var backtrack func(current string, openCount int, closeCount int)
```然后分配实现。 

结果切片被初始化为空切片而不是`nil`，尽管两者在这里都能正常工作。 

Go 中的字符串是不可变的，类似于 Python，因此连接`"("`或者`")"`为递归调用创建新字符串。 

整数溢出不是一个问题，因为`n <= 8`，使所有值都变得非常小。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(Cn * n) | 生成所有有效组合，每个组合的长度`2n`|
 | 空间| O(n) 不包括输出 | 递归调用堆栈深度最多为`2n`|

 有效括号组合的数量是第 n 个加泰罗尼亚数字：$C_n = \frac{1}{n+1}\binom{2n}{n}$这大约增长为：$C_n \approx \frac{4^n}{n^{3/2}\sqrt{\pi}}$由于每个有效字符串都有长度`2n`，总功变为`O(Cn * n)`。 

递归深度永远不会超过`2n`，所以辅助空间的使用是线性的`n`，不包括输出列表本身。

 ## 边缘情况

 一种重要的边缘情况是最小输入值，`n = 1`。 在这种情况下，仅存在一个有效组合：`"()"`。 递归解决方案有时会在这里失败，因为它们错误地假设了多个分支的可能性。 此实现可以自然地处理它，因为一旦添加了一个左括号，唯一有效的下一步就是右括号。 

另一个关键的边缘情况涉及无效前缀。 例如，以以下字符开头的字符串`")"`以后永远不会生效。 简单的暴力解决方案仍然会生成并测试这些字符串。 回溯解决方案使用以下条件完全避免了这种情况：```
if close_count < open_count:
```这保证了构造期间右括号的数量永远不会超过左括号的数量。 

第三个重要的边缘情况发生在上约束附近，`n = 8`。 尽管输入大小看起来很小，但有效组合的数量很快增长到 1430 个。重复验证字符串或不必要地复制大型结构的低效实现可能会变得很慢。 递归修剪策略通过仅探索有效状态来保持搜索空间的可管理性。 

一个微妙的实现问题是确保每个生成的字符串都准确使用`n`开放和`n`右括号。 一些不正确的解决方案过早停止递归或允许额外的开口。 此实现通过以下方式防止这种情况发生：

 - 最多允许`n`左括号
 - 仅当字符串长度达到时停止`2 * n`这保证了所有输出都是完整且正确平衡的。
