[LeetCode 第 28 题](https://leetcode.com/problems/find-the-index-of-the-first-occurrence-in-a-string/)

 **难度：** 🟢简单
 **主题：** 两个指针、字符串、字符串匹配

 ## 解决方案

 ## 问题理解

 这个问题要求我们找到一个字符串在另一个字符串中第一次出现的位置。 我们正在搜索的字符串称为`needle`，我们在里面搜索的较大字符串称为`haystack`。 

更正式地说，我们需要确定是否`needle`显示为内部的连续子字符串`haystack`。 如果是，我们返回其第一次出现的起始索引。 如果它不存在于任何地方`haystack`，我们返回`-1`。 

例如，如果`haystack = "sadbutsad"`和`needle = "sad"`, 子串`"sad"`出现两次，一次从索引处开始`0`再次在索引处`6`。 由于该问题要求第一次出现，因此正确答案是`0`。 

输入由两个小写英文字符串组成。 约束告诉我们两个字符串的长度介于`1`和`10^4`。 这很重要，因为这意味着即使二次解决方案在实践中仍然可能通过，但我们仍然应该寻求一种更高效和可扩展的方法。 

在实施解决方案之前，需要考虑一些边缘情况。 

如果`needle`长于`haystack`，匹配不可能存在。 如果两个字符串相同，则答案应该是`0`。 如果匹配的子字符串出现多次，我们必须只返回第一次出现的情况。 另一个重要的情况是重叠模式，例如搜索`"aaa"`里面`"aaaaa"`。 在这种情况下，简单的实现很容易出现索引错误。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每个可能的起始位置`haystack`。 

在每个索引处`i`，我们将字符一一比较`haystack[i:]`和`needle`。 如果所有字符都匹配，我们返回`i`。 如果发生不匹配，我们将移动到下一个起始位置并重试。 

这种方法是正确的，因为每一个可能的对齐`needle`里面`haystack`被检查。 如果存在有效的事件，算法最终会找到它。 

然而，缺点是效率。 在最坏的情况下，对于每个起始位置，我们可以比较几乎整个`needle`在发现不匹配之前。 这导致最坏情况的时间复杂度为`O(n * m)`， 在哪里：

-`n`的长度是`haystack`-`m`的长度是`needle`对于给定的约束，这仍然是可以接受的，但是有一个更优雅的线性时间解决方案。 

### 最优方法，Knuth-Morris-Pratt (KMP)

 KMP 背后的关键见解是，当发生不匹配时，我们不需要从头开始重新匹配。 

假设我们已经成功匹配了几个字符。 匹配的前缀的某些部分也可能是后缀。 我们可以重用以前的信息来跳过不必要的比较，而不是重新检查我们已经知道匹配的字符。 

KMP 预处理`needle`构建一个称为最长前缀后缀数组的数组，通常称为`LPS`大批。 对于每个位置，数组存储最长的正确前缀（也是后缀）的长度。 

这种预处理允许搜索阶段在不匹配后智能地移动，确保每个字符最多被处理恒定的次数。 

因此，KMP 实现了线性时间复杂度。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n * m) | O(1) | O(1) | 尝试每个起始位置并直接比较字符 |
 | 最优，KMP | O(n + m) | O(米) | 使用前缀信息来避免冗余比较 |

 ## 算法演练

 ### 第 1 步：构建 LPS 阵列

 KMP 算法首先对`needle`。 

这`LPS`数组为每个位置存储最长的正确前缀的长度，该前缀也是以该位置结尾的子字符串的后缀。 

例如，对于模式`"ababaca"`：

 | 索引 | 人物 | 脂多糖 |
 | --- | --- | --- |
 | 0 | 一个 | 0 |
 | 1 | 乙| 0 |
 | 2 | 一个 | 1 |
 | 3 | 乙| 2 |
 | 4 | 一个 | 3 |
 | 5 | c | 0 |
 | 6 | 一个 | 1 |

 这种预处理告诉我们在不匹配后可以将模式移动多远而不丢失有用的信息。 

### 第 2 步：初始化搜索指针

 我们使用两个指针：

 1. 一根指针`i`为了`haystack`2. 一根指针`j`为了`needle`最初，两者都开始于`0`。 

### 步骤 3：比较字符

 每一步：

 1.如果`haystack[i] == needle[j]`，两个指针都向前移动。 
2.如果`j`到达末尾`needle`，我们找到了一个完整的匹配，所以我们返回`i - j`。 

### 步骤 4：有效处理不匹配

 当字符不匹配时：

 1.如果`j > 0`，我们不会从头开始。 
2. 相反，我们设置`j = lps[j - 1]`。 

这会将模式指针移动到最长的有效前缀位置。 

如果`j == 0`，没有可重用的前缀，所以我们只需移动`i`向前。 

### 第 5 步：返回`-1`如果不存在匹配项

 如果我们扫描完整个`haystack`没有完全匹配`needle`，子串不存在，所以我们返回`-1`。 

### 为什么它有效

 KMP 的正确性来自于当前指针之前的所有字符都已被一致处理的不变性。 这`LPS`array 保证在不匹配后，我们只跳转到仍然可以产生有效匹配的位置。 不会跳过任何可能出现的情况，并且不会出现任何字符`haystack`被不必要地重新检查多次。 这确保了正确性和线性效率。 

## Python 解决方案```python
class Solution:
    def strStr(self, haystack: str, needle: str) -> int:
        def build_lps(pattern: str) -> list[int]:
            lps = [0] * len(pattern)

            length = 0
            i = 1

            while i < len(pattern):
                if pattern[i] == pattern[length]:
                    length += 1
                    lps[i] = length
                    i += 1
                else:
                    if length != 0:
                        length = lps[length - 1]
                    else:
                        lps[i] = 0
                        i += 1

            return lps

        lps = build_lps(needle)

        haystack_index = 0
        needle_index = 0

        while haystack_index < len(haystack):
            if haystack[haystack_index] == needle[needle_index]:
                haystack_index += 1
                needle_index += 1

                if needle_index == len(needle):
                    return haystack_index - needle_index
            else:
                if needle_index != 0:
                    needle_index = lps[needle_index - 1]
                else:
                    haystack_index += 1

        return -1
```实施分为两个逻辑阶段。 

第一阶段建设`LPS`大批。 变量`length`跟踪当前最长的前缀后缀长度，而`i`扫描整个图案。 当字符匹配时，前缀长度就会增加。 当它们不匹配时，我们回退使用之前计算的`LPS`值而不是完全重新启动。 

第二阶段执行实际的子字符串搜索。 两个指数穿越`haystack`和`needle`。 匹配的字符使两个指针都前进。 完全匹配发生在`needle_index`到达模式的末尾。 

重要的优化发生在不匹配期间。 而不是从索引重新启动模式比较`0`，该算法重用之前匹配的前缀信息`LPS`大批。 

## 解决方案```go
func strStr(haystack string, needle string) int {
	buildLPS := func(pattern string) []int {
		lps := make([]int, len(pattern))

		length := 0
		i := 1

		for i < len(pattern) {
			if pattern[i] == pattern[length] {
				length++
				lps[i] = length
				i++
			} else {
				if length != 0 {
					length = lps[length-1]
				} else {
					lps[i] = 0
					i++
				}
			}
		}

		return lps
	}

	lps := buildLPS(needle)

	haystackIndex := 0
	needleIndex := 0

	for haystackIndex < len(haystack) {
		if haystack[haystackIndex] == needle[needleIndex] {
			haystackIndex++
			needleIndex++

			if needleIndex == len(needle) {
				return haystackIndex - needleIndex
			}
		} else {
			if needleIndex != 0 {
				needleIndex = lps[needleIndex-1]
			} else {
				haystackIndex++
			}
		}
	}

	return -1
}
```Go 实现遵循与 Python 版本相同的逻辑。 由于 Go 字符串是字节索引的，因此直接索引在这里可以正常工作，因为问题只保证小写英文字母。 

这`LPS`数组是使用整数切片来实现的。 Go 没有以完全相同的方式进行类型推断的 Python 风格嵌套辅助函数，因此辅助函数使用匿名函数分配给变量。 

不需要对整数溢出进行特殊处理，因为所有索引都在问题约束之内。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n + m) | 两个字符串中的每个字符最多被处理固定次数 |

 ## 边缘情况

 ### 针比干草堆还长

 如果`needle`长于`haystack`，不可能有匹配，因为较大的字符串无法放入较小的字符串中。 在这种情况下，某些实现会意外访问越界索引。 KMP 实现自然地处理这个问题，因为搜索循环永远不会达到完全匹配。 

### 重叠图案

 图案如`"aaa"`里面`"aaaaa"`很棘手，因为比赛重叠严重。 幼稚的实现可能会过于激进地重新启动并错过有效的事件。 KMP 使用以下方法正确处理此问题`LPS`数组，保留部分匹配信息并避免冗余工作。 

### 模式中的重复前缀

 图案如`"ababaca"`包含重复的前缀结构。 这些正是 KMP 提供最大效益的情况。 不正确`LPS`构造很容易导致跳过匹配或无限循环。 该实现小心地使用先前计算的前缀长度进行回退，以确保正确性。 

### 最后的比赛

 搜索等情况`"c"`里面`"abc"`可以通过一个索引错误来暴露。 该实现在增加模式指针后立即检查是否完全匹配，以确保正确检测到以最终字符结尾的匹配。
