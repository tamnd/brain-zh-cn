 # 独特的路径

 ## 问题理解

 该问题描述了一个机器人在矩形上移动`m x n`网格。 机器人从网格的左上角开始，想要到达右下角。 每一步，机器人只能向右移动一个单元格或向下移动一个单元格。 

输入由两个整数组成：

 -`m`, 网格中的行数
 -`n`, 网格中的列数

 输出应该是一个整数，表示从起始位置到目的地存在多少条不同的有效路径。 

为了更好地理解运动规则，考虑`3 x 7`网格。 要从左上角移动到右下角，机器人必须移动：

 - 准确地向下`m - 1`次
 - 完全正确`n - 1`次

 挑战在于确定这些动作可以有多少种不同的排列方式。 

约束条件很重要：

 -`1 <= m, n <= 100`这些限制对于动态编程解决方案来说足够小，但又足够大，以至于暴力递归变得不切实际。 由于结果保证符合`2 * 10^9`，标准整数类型就足够了。 

一些边缘情况很重要：

 - A`1 x 1`网格只有一条路径，因为机器人已经到达目的地。 
- 单行网格，例如`1 x 5`，只允许正确的移动，因此只有一条路径。 
- 单列网格，例如`5 x 1`，只允许向下移动，因此只有一条路径。 
- 大网格，如`100 x 100`将使朴素的递归探索变得极其缓慢，因为可能的路径数量呈指数增长。 

## 方法

 ### 暴力递归搜索

 最直接的方法是递归地探索每条可能的路径。 

在每个单元中，机器人最多有两种选择：

 - 向右移动
 - 向下移动

 递归函数将继续执行，直到出现以下情况：

 - 到达右下角，贡献一条有效路径
 - 超出网格边界，贡献零路径

 这种做法是正确的，因为它详尽地探索了每一种可能的合法途径。 每个独特的移动序列都对应于一条递归路径。 

然而，相同的子问题会被重新计算多次。 例如，从单元格开始的路径数`(2, 3)`到目的地的路径可以从不同的递归分支重复计算。 这种重复会导致运行时间呈指数增长。 

对于接近上限约束的网格，强力递归变得太慢。 

### 最优动态规划

 关键的观察结果是，到任何单元格的路径数量仅取决于正上方和正左侧的单元格。 

如果我们定义：

 -`dp[row][col]`作为到达该单元格的唯一路径的数量

 然后：

 - 机器人只能从上方或左侧到达
 - 因此：$dp[row][col] = dp[row-1][col] + dp[row][col-1]$这种递归自然会导致动态规划。 

第一行和第一列均仅包含一个可能的路径，因为移动仅限于单个方向。 

通过逐行填充表格，每个状态只计算一次，从而产生有效的解决方案。 

我们可以通过使用一维数组进一步优化空间，因为每一行仅取决于当前行和上面行中的先前值。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^(m+n)) | O(2^(m+n)) | O(m+n) | 递归探索每条可能的路径 |
 | 最佳 | O(m × n) | O(n) | 具有空间优化的动态规划|

 ## 算法演练

 ### 最优动态规划算法

 1.创建大小为一维的DP数组`n`。 

数组中的每个位置代表到达当前行中的列的方式数。 使用一维数组可以减少内存使用，同时保持正确性。 
2. 将数组中的每个值初始化为`1`。 

第一行到每个单元格只有一条可能的路径，因为机器人只能向右移动。 

示例`n = 5`：```
[1, 1, 1, 1, 1]
```3. 从 row 开始迭代剩余行`1`。 

对于每个附加行，更新每列的路径数。 
4. 对于从列开始的每一列`1`， 更新：$dp[col] = dp[col] + dp[col-1]$这里：

-`dp[col]`表示从上面开始的路径数
 -`dp[col - 1]`表示从左边算起的路径数

 将它们相加即可得到到达当前单元格的路径总数。 

1. 继续更新数组，直到处理完所有行。 
2. 返回数组中的最终值。 

最后一个元素表示到达右下角的唯一路径的数量。 

### 为什么它有效

 该算法之所以有效，是因为到单元格的每条有效路径都必须来自正上方或正左侧的单元格。 动态规划递归准确地捕获了这个属性。 由于该算法按照已经计算出依赖关系的顺序处理单元，因此每个状态都会收到正确的路径总数。 

## Python 解决方案```python
class Solution:
    def uniquePaths(self, m: int, n: int) -> int:
        dp = [1] * n

        for _ in range(1, m):
            for col in range(1, n):
                dp[col] += dp[col - 1]

        return dp[-1]
```该解决方案首先创建一个名为的一维数组`dp`。 每个值开始为`1`因为只有一种方法可以到达第一行中的任何单元格。 

外循环迭代每个附加行。 第一行不需要计算，因为它的值已经正确初始化。 

内部循环从左到右处理列。 对于每个单元格，当前值表示来自上方的路径，而数组中的前一个值表示来自左侧的路径。 

通过更新：```python
dp[col] += dp[col - 1]
```该算法结合了两个可能的传入方向。 

处理完所有行后，最后一个元素包含到达目的地的唯一路径的总数。 

## 解决方案```go
func uniquePaths(m int, n int) int {
    dp := make([]int, n)

    for i := 0; i < n; i++ {
        dp[i] = 1
    }

    for row := 1; row < m; row++ {
        for col := 1; col < n; col++ {
            dp[col] += dp[col-1]
        }
    }

    return dp[n-1]
}
```Go 实现遵循与 Python 版本相同的动态编程逻辑。 

使用切片而不是 Python 列表。 Go 需要显式初始化切片值`1`。 

这些约束保证最终答案符合 32 位有符号整数，因此标准`int`type 对于 LeetCode 来说就足够了。

 ## 边缘情况

 ### 单细胞网格

 一个`1 x 1`网格是一种特殊情况，因为机器人已经在目的地启动。 有错误的实现可能会错误地返回`0`如果它假设需要移动。 此实现正确返回`1`因为 DP 数组开始时用 1 初始化并且没有循环执行。 

### 单行或单列

 如果其中之一`m == 1`或者`n == 1`，机器人只有一条可能的路线。 某些实现会意外地尝试无效转换或创建不正确的 DP 维度。 在这里，循环自然地处理这些情况，因为外部循环或内部循环永远不会执行，结果为`1`。 

### 大网格尺寸

 大输入，如`100 x 100`由于可能的路径数量增长极快，因此暴露了递归解决方案的低效率。 由于指数递归，暴力实现会超时。 动态编程方法完全避免了重新计算，并且只处理每个状态一次，即使在最大约束下也能确保高效执行。
