 # LeetCode 88 - 合并排序数组

 ## 问题理解

 这个问题给了我们两个数组，`nums1`和`nums2`，其中两个数组已按非降序排序。 我们还给出了两个整数，`m`和`n`，它告诉我们每个数组中存在多少个有效元素。 

重要的细节是`nums1`末尾有额外的空间。 其总大小为`m + n`，其中只有第一个`m`元素是有意义的数据。 其余`n`位置是占位符，初始化为`0`， 和 被保留，以便合并结果可以容纳在内部`nums1`。 

目标是合并来自的所有元素`nums2`进入`nums1`，就地生成一个完全排序的数组。 该函数不应返回任何内容。 相反，它必须直接修改`nums1`。 

例如：

-`nums1 = [1,2,3,0,0,0]`,`m = 3`-`nums2 = [2,5,6]`,`n = 3`有意义的元素是：

 -`nums1 -> [1,2,3]`-`nums2 -> [2,5,6]`合并排序后，`nums1`应该变成：

 -`[1,2,2,3,5,6]`约束相对较小，因为`m + n <= 200`，因此即使效率较低的解决方案在技术上也能在时间限制内发挥作用。 然而，后续行动特别要求`O(m + n)`解决方案，强烈建议使用类似于合并排序的合并步骤的两指针合并策略。 

一些边缘情况很重要：

 -`nums2`可能为空
 -`nums1`最初可能不包含有效元素
 - 一个数组中的所有元素可能小于或大于另一个数组中的所有元素
 - 可能会出现重复值
 - 允许负数

 从前面进行的天真的就地合并可能会意外覆盖中未处理的值`nums1`，因此需要小心处理。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是复制所有元素`nums2`进入空的部分`nums1`，然后对整个数组进行排序。 

该算法的工作原理如下：

 1. 插入每个元素`nums2`到末尾未使用的位置`nums1`2. 整体排序`nums1`数组

 这种方法是正确的，因为将所有元素合并到一个数组中后，排序会恢复所需的非递减顺序。 

然而，这个解决方案并不是最优的。 排序需要`O((m+n) log(m+n))`时间，这比必要的要慢，因为数组已经单独排序。 

### 最佳方法

 关键的见解是两个数组都已经排序。 这意味着我们可以像合并排序中的合并步骤一样将它们合并。 

挑战在于就地执行合并而不覆盖中的值`nums1`我们还需要处理。 

重要的观察是，末尾已经存在空白`nums1`。 我们可以从后面合并，而不是从头开始合并。 

我们使用三个指针：

 - 指向最后一个有效元素的一个指针`nums1`- 一个指向最后一个元素的指针`nums2`- 一个指针指向最终位置`nums1`在每一步中，我们将较大的值放在后面的位置，并将相应的指针向后移动。 

因为我们从右到左填充数组，所以我们永远不会覆盖未处理的数据。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O((m+n) log(m+n)) | O((m+n) log(m+n)) | O(1) 或 O(log(m+n)) 取决于排序 | 将 nums2 复制到 nums1 中，然后排序 |
 | 最佳| O(m+n) | O(1) | O(1) | 使用三个指针从后面合并 |

 ## 算法演练

 ### 最优两指针算法

 1. 初始化三个指针。 

第一个指针，`i`，开始于`m - 1`，这是最后一个有效元素`nums1`。 

第二个指针，`j`，开始于`n - 1`，这是最后一个元素`nums2`。 

第三个指针，`write_index`，开始于`m + n - 1`，这是最终的位置`nums1`。 
2.比较由指向的元素`i`和`j`。 

由于两个数组都已排序，因此这两个值中较大的一个必须位于合并数组的末尾。 
3. 将较大的值置于`nums1[write_index]`。 

如果`nums1[i] > nums2[j]`， 地方`nums1[i]`进入写入位置并移动`i`落后。 

否则，放置`nums2[j]`进入写入位置并移动`j`落后。 
4. 移动`write_index`落后。 

放置一个元素后，递减`write_index`因为下一个最大值属于较早的一个位置。 
5. 继续，直到所有元素来自`nums2`被处理。 

循环条件通常是`while j >= 0`。 

如果元素保留在`nums1`，它们已经处于正确的位置，因此不需要额外的工作。 
6. 停止时`j < 0`。 

此时，每个元素都来自`nums2`已正确合并到`nums1`。 

### 为什么它有效

 该算法保持了以下不变式：`write_index`已经按排序顺序正确放置。 

在每一步中，我们都会从任一数组中选择最大的剩余元素并将其放置到当前的后面位置。 由于我们从右到左填充位置，因此没有未处理的值`nums1`被覆盖。 

因为每个元素只处理一次，所以最终的数组是完全排序且完整的。 

## Python 解决方案```python
from typing import List

class Solution:
    def merge(self, nums1: List[int], m: int, nums2: List[int], n: int) -> None:
        """
        Do not return anything, modify nums1 in-place instead.
        """
        
        i = m - 1
        j = n - 1
        write_index = m + n - 1

        while j >= 0:
            if i >= 0 and nums1[i] > nums2[j]:
                nums1[write_index] = nums1[i]
                i -= 1
            else:
                nums1[write_index] = nums2[j]
                j -= 1

            write_index -= 1
```该实现遵循上述精确算法。 

变量`i`跟踪有效部分中的当前元素`nums1`。 变量`j`跟踪当前元素`nums2`。 变量`write_index`跟踪下一个最大元素应该写入的位置。 

条件`i >= 0`很重要，因为一旦所有有效元素来自`nums1`已经耗尽了，我们必须继续复制剩余的元素`nums2`。 

循环继续，同时`j >= 0`因为每个元素都来自`nums2`最终必须放入`nums1`。 如果元素保留在原来的部分`nums1`，它们已经正确定位。 

这个实现修改了`nums1`直接使用并且仅使用恒定的额外内存。 

## 解决方案```go
func merge(nums1 []int, m int, nums2 []int, n int) {
    i := m - 1
    j := n - 1
    writeIndex := m + n - 1

    for j >= 0 {
        if i >= 0 && nums1[i] > nums2[j] {
            nums1[writeIndex] = nums1[i]
            i--
        } else {
            nums1[writeIndex] = nums2[j]
            j--
        }

        writeIndex--
    }
}
```Go 实现与 Python 版本几乎相同。 

Go 切片的行为与动态数组类似，因此修改`nums1`函数内部直接更改原始切片内容。 

这里不存在整数溢出问题，因为索引非常小并且完全在 Go 的整数范围内。 

Go 不会以影响该算法的方式区分空切片和 nil 切片。 只要满足所提供的约束，实现就可以正常工作。

 ## 边缘情况

 ###`nums2`为空

 当`n = 0`，没有什么可以合并的。 如果算法假设两个数组都包含元素，这种情况很容易导致错误。 

该实现自然地处理了这个问题，因为`j`开始于`-1`。 循环条件`while j >= 0`立即失败，所以`nums1`保持不变。 

###`nums1`没有有效元素

 当`m = 0`，所有实际数据均来自`nums2`。 有缺陷的实现可能会错误地与占位符零进行比较`nums1`。 

该解决方案避免了该问题，因为`i`开始于`-1`。 条件`i >= 0`失败，因此算法直接复制所有元素`nums2`进入`nums1`。 

### 中的所有元素`nums2`较小

 考虑：```
nums1 = [4,5,6,0,0,0]
nums2 = [1,2,3]
```前向合并可以覆盖中的值`nums1`在它们被处理之前。 

向后合并策略完全避免了这个问题。 该算法从末尾开始填充位置，保留所有未处理的值，直到不再需要它们为止。 

### 重复值

 数组可能包含重复的值，例如：```
nums1 = [1,2,2]
nums2 = [2,2,3]
```一些不正确的实现会意外地跳过重复项或错误处理指针移动。 

该算法在每一步独立地比较值，并在每次迭代时精确复制一个元素，确保所有重复项正确显示在最终合并的数组中。
