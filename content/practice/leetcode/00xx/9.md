[LeetCode 第 9 题](https://leetcode.com/problems/palindrome-number/)

 **主题：** 数学

 ## 解决方案

 ## 问题理解

 该问题要求我们确定给定的整数向前和向后读取是否相同。 这样的数字称为回文数。 例如，数字`121`是一个回文，因为反转它的数字仍然会产生`121`。 另一方面，`123`不是回文，因为反转它会产生`321`。 

输入由单个整数组成`x`。 输出应该是一个布尔值：

 - 返回`true`如果整数是回文。 
- 返回`false`否则。 

一个重要的细节是负数永远不是回文。 像这样的数字`-121`不被视为回文，因为反转其字符会产生`121-`，这不是同一个序列。 

约束指定该值位于标准 32 位有符号整数范围内：```
-2^31 <= x <= 2^31 - 1
```这告诉我们位数很少，最多10位。 尽管输入的大小很小，但后续会明确询问我们是否可以在不将整数转换为字符串的情况下解决问题。 这意味着预期的解决方案基于数学数字操作而不是字符串操作。 

一些边缘情况很重要：

 - 负数应该立即返回`false`。 
- 结尾的数字`0`通常不是回文，除非数字本身是`0`。 
- 个位数始终是回文。 
- 接近整数限制的非常大的值应该仍然可以正常工作，不会出现溢出问题。 

预先了解这些情况有助于避免稍后实施中出现细微的错误。 

## 方法

 ### 蛮力方法

 最直接的解决方案是将整数转换为字符串，然后将字符串与其反序进行比较。 

例如：

 - 转换`121`进入`"121"`- 将其反转为`"121"`- 比较两个字符串

 如果它们相等，则该数字是回文数。 

这种方法易于实施且易于理解。 反转字符串的效率很高，而且最大位数很少。 但它不满足后续要求，因为它依赖于字符串转换而不是纯算术运算。 

### 最佳方法

 关键的观察是我们不需要反转整个数字。 我们只需要反转一半即可。 

假设我们从右向左处理数字并逐渐构建一个反转的数字：```
x = 1221
reversedHalf = 0

Step 1:
digit = 1
reversedHalf = 1
x = 122

Step 2:
digit = 2
reversedHalf = 12
x = 12
```在此刻，`x`和`reversedHalf`相等，这意味着该数字是回文数。 

这种方法有几个优点：

 - 不需要字符串转换。 
- 仅处理一半的数字。 
- 避免溢出，因为反转的值永远不会超过原始数字的一半。 

对于奇数长度数字还有一个额外的细节。 例如：```
12321
```中间的数字对于回文检查并不重要。 处理完一半数字后：```
x = 12
reversedHalf = 123
```删除中间数字`reversedHalf // 10`给出：```
123 // 10 = 12
```现在两个半场比赛了。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(d) | O(d) | 将整数转换为字符串并将其反转 |
 | 最佳| O(d) | O(1) | O(1) | 在数学上仅反转一半数字 |

 这里，`d`表示整数中的位数。

### 为什么它有效

 该算法保持不变式`reversed_half`始终包含从右侧删除的数字的反转`x`。 一旦反转的一半大于或等于剩余的一半就停止，我们确保恰好一半的数字已被处理。 对于偶数长度的数字，两半应该完全匹配。 对于奇数长度的数字，中间的数字是不相关的，可以通过整数除以来删除`10`。 

## Python 解决方案```python
class Solution:
    def isPalindrome(self, x: int) -> bool:
        # Negative numbers are not palindromes
        # Numbers ending in 0 are not palindromes unless the number is 0
        if x < 0 or (x % 10 == 0 and x != 0):
            return False

        reversed_half = 0

        while x > reversed_half:
            digit = x % 10
            reversed_half = reversed_half * 10 + digit
            x //= 10

        # For even length numbers:
        # x == reversed_half
        #
        # For odd length numbers:
        # x == reversed_half // 10
        return x == reversed_half or x == reversed_half // 10
```实施从立即处理无效案例开始。 负数和以零结尾的数字将被拒绝，因为它们无法形成有效的回文数。 

变量`reversed_half`用于存储原始数字右侧的反转数字。 在循环内部，使用模算术提取最后一位数字并将其附加到反转的值上。 

循环停止一次`reversed_half`变得大于或等于`x`。 至此，一半的数字已被处理。 

最后，代码检查偶数长度和奇数长度场景。 对于奇数长度的数字，整数除以`10`在比较之前删除中心数字。 

## 解决方案```go
func isPalindrome(x int) bool {
    // Negative numbers are not palindromes
    // Numbers ending in 0 are not palindromes unless the number is 0
    if x < 0 || (x%10 == 0 && x != 0) {
        return false
    }

    reversedHalf := 0

    for x > reversedHalf {
        digit := x % 10
        reversedHalf = reversedHalf*10 + digit
        x /= 10
    }

    // Even length:
    // x == reversedHalf
    //
    // Odd length:
    // x == reversedHalf/10
    return x == reversedHalf || x == reversedHalf/10
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 一个小的语言差异是 Go 中的整数除法使用`/`而不是`//`。 由于所有值都是整数，因此结果会自动截断为零。 

不需要特殊的溢出处理，因为只有一半的数字被反转，这使得中间值安全地保持在范围内。

 ## 边缘情况

 ### 负数

 负整数是常见的错误来源。 幼稚的实现可能会反转数字并比较绝对值，从而错误地处理`-121`作为回文。 但是，负号改变了顺序，因此数字不对称。 实现立即处理这个问题：```
if x < 0:
    return False
```这保证了在任何进一步处理之前拒绝所有负输入。 

### 以零结尾的数字

 像这样的数字`10`,`100`， 和`120`可能会导致微妙的错误。 倒车`10`产生`01`，这实际上是`1`， 不是`10`。 回文不能以零开头，因此任何以零结尾的非零数必定是无效的。 

实现明确检查：```
if x % 10 == 0 and x != 0:
    return False
```这正确地允许`0`本身，同时拒绝所有其他尾随零的情况。 

### 奇数长度回文

 奇数长度回文包含不需要匹配对应项的中间数字。 例如：```
12321
```中心数字`3`可以忽略。 一个常见的错误是直接比较两半而不删除中间数字。 

该实现通过比较来处理这个问题：```
x == reversed_half // 10
```除以`10`删除多余的中间数字，允许正确识别奇数长度回文。
