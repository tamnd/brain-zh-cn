[LeetCode 第 82 题](https://leetcode.com/problems/remove-duplicates-from-sorted-list-ii/)

 **难度：** 🟡 中等
 **主题：** 链表、两个指针

 ## 解决方案

 ## 问题理解

 这个问题要求我们处理一个排序的单链表并删除每个出现多次的值。 重要的区别是我们不会保留重复值的一份副本。 相反，必须完全删除包含重复值的每个节点。 

例如，考虑以下列表：```
1 -> 2 -> 3 -> 3 -> 4 -> 4 -> 5
```价值观`3`和`4`出现多次，因此包含这些值的所有节点都将被删除。 最终结果变成：```
1 -> 2 -> 5
```输入是单链表的头节点。 由于列表已按升序排序，因此重复值始终相邻出现。 这个属性非常重要，因为它允许我们通过简单地比较相邻节点来检测重复项。 

完全删除所有重复值后，输出应该是修改后的链表的头部。 

这些约束告诉我们一些有用的信息：

 - 该列表最多包含 300 个节点，这意味着即使不太理想的解决方案仍然可以通过。 
- 值范围为`-100`到`100`，但实际值并不是特别重要，因为列表已排序。 
- 由于列表是排序的，重复的值总是形成连续的组。 

一些边缘情况尤其重要：

 - 列表可能为空。 
- 重复项可能出现在列表的开头。 
- 重复项可能会出现在列表的末尾。 
- 每个节点都可能重复，导致列表为空。 
- 一个值可能出现两次以上。 
- 可能根本没有重复项。 

当头部出现重复时，幼稚的实现通常会失败，因为删除头节点会更改列表的起点。 这就是为什么虚拟节点常用于此类链表问题。 

## 方法

 ### 蛮力方法

 一种直接的方法是使用哈希映射来计算链表中每个值的频率。 

我们首先遍历整个列表并存储每个值出现的次数。 然后我们执行第二次遍历并仅使用频率恰好为 1 的值重建链表。 

这种方法是正确的，因为频率大于 1 的每个值都被排除在重建列表之外。 

尽管此解决方案在给定的约束内运行良好，但它使用与不同值的数量成比例的额外内存。 实际上，只需使用恒定的额外空间就可以解决该问题，因为列表已经排序。 

### 最佳解决方案的关键见解

 关键的观察是链表是排序的。 由于重复值总是连续出现，因此我们可以在单次遍历期间检测重复项，而无需使用额外的存储。 

我们维护两个指针：

 - A`prev`跟踪最后确认的唯一节点的指针。 
- A`current`用于扫描列表的指针。 

每当我们遇到具有相同值的连续节点时，我们都会跳过整组重复项。 否则我们就搬家`prev`向前。 

放置在头之前的虚拟节点可以简化处理在列表开头出现重复的情况。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 使用哈希图来计算频率 |
 | 最佳| O(n) | O(1) | O(1) | 在排序列表上使用指针操作 |

 ## 算法演练

 1. 创建一个虚拟节点，其`next`指针指向原来的头部。 

此虚拟节点有助于处理前几个节点重复的情况。 如果没有它，删除重复的头节点就会变得很尴尬。 
2. 初始化一个`prev`指向虚拟节点的指针。 

这`prev`指针始终代表最后一个被确认为唯一的节点。 
3. 初始化一个`current`指向列表头部的指针。 

该指针扫描链表。 
4. 遍历列表 while`current`不是`None`。 

在每一步中，确定当前值是否重复。 
5. 检查是否`current.next`是否存在以及是否具有相同的值`current`。 

如果两个条件都成立，我们就找到了重复的序列。 
6. 跳过整个重复组。 

继续移动`current`当下一个节点具有相同值时向前转发。 
7. 到达重复组的末尾后，连接`prev.next`到`current.next`。 

这将从链表中删除具有重复值的每个节点。 
8. 如果当前值不重复，则移动`prev`向前。 

这意味着当前节点可以安全地保留最终答案。 
9. 移动`current`向前继续遍历。 
10. 返回`dummy.next`。 

如果原始头部是重复的，则实际头部可能已改变。 

### 为什么它有效

 该算法保持了之前所有节点的不变性`prev`保证是唯一的并且正确连接。 每当发现重复组时，整个组都会被跳过并从列表中排除。 由于输入列表已排序，因此所有重复项都连续出现，因此不会遗漏重复值。 当遍历完成时，每个重复值都已被删除一次。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

class Solution:
    def deleteDuplicates(self, head: Optional[ListNode]) -> Optional[ListNode]:
        dummy = ListNode(0)
        dummy.next = head

        prev = dummy
        current = head

        while current:
            if current.next and current.val == current.next.val:
                duplicate_value = current.val

                while current and current.val == duplicate_value:
                    current = current.next

                prev.next = current
            else:
                prev = current
                current = current.next

        return dummy.next
```实现首先创建一个指向头部的虚拟节点。 这简化了删除逻辑，尤其是当第一个节点重复时。 

这`prev`指针跟踪应保留在最终列表中的最后一个节点。 这`current`指针扫描链表。 

在循环内部，代码检查当前节点是否启动重复序列。 如果是这样，它将存储重复的值并跳过包含该值的每个节点。 跳过重复组后，`prev.next`已更新以绕过已删除的节点。 

如果当前节点不重复，则它是最终答案的一部分，因此两个指针都会正常向前移动。 

最后，函数返回`dummy.next`，它指向链表更新后的头。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func deleteDuplicates(head *ListNode) *ListNode {
    dummy := &ListNode{Next: head}

    prev := dummy
    current := head

    for current != nil {
        if current.Next != nil && current.Val == current.Next.Val {
            duplicateValue := current.Val

            for current != nil && current.Val == duplicateValue {
                current = current.Next
            }

            prev.Next = current
        } else {
            prev = current
            current = current.Next
        }
    }

    return dummy.Next
}
```Go 实现遵循与 Python 版本完全相同的逻辑。 

主要区别在于指针语法和`nil`处理。 Go 使用显式指针类型，因此可以通过以下方式操作节点`*ListNode`。 虚拟节点是使用结构体文字分配的。 

因为 Go 没有 Python 的动态类型或自动`None`处理时，必须仔细检查每个指针取消引用`nil`在访问字段之前`Next`或者`Val`。 

这里不存在整数溢出问题，因为节点值保持在很小的限制范围内。

 ## 边缘情况

 ### 空列表

 空列表表示为`head = None`。 如果不仔细保护指针访问，这种情况很容易导致链表问题中的空指针错误。 

该实现自然地处理了这个问题，因为遍历循环仅在 while 时运行`current`存在。 如果列表为空，则循环永远不会执行并且`dummy.next`正确返回`None`。 

### 开头重复

 案例如下：```
1 -> 1 -> 2 -> 3
```很棘手，因为头部本身必须被移除。 许多简单的解决方案都失败了，因为它们失去了新头的踪迹。 

虚拟节点干净利落地解决了这个问题。 自从`prev`从虚拟节点开始，重新连接`prev.next`正确跳过重复项后更新结果列表的头部。 

### 整个列表已删除

 一个案例比如：```
1 -> 1 -> 2 -> 2
```结果是一个空的最终列表。 

这是虚拟节点很重要的另一种情况。 跳过所有重复组后，`dummy.next`变成`None`，它正确地表示一个空链表。 

### 大于两个的重复组

 某些实现错误地假设重复项正好出现两次。 但是，输入如下：```
1 -> 1 -> 1 -> 1 -> 2
```包含较大的重复组。 

内部循环继续前进，直到值发生变化，确保删除每次出现的重复值，无论组大小如何。
