[LeetCode 第 42 题](https://leetcode.com/problems/trapping-rain-water/)

 **难度：** 🔴难
 **主题：** 数组、两个指针、动态规划、堆栈、单调堆栈

 ## 解决方案

 ## 问题理解

 问题给出了一个名为`height`，其中每个元素表示高程图中垂直条的高度。 每个条形都有宽度`1`。 降雨后，水可能会被困在较高的栅栏之间。 

任务是计算可以捕获的水总量。 

例如，考虑数组：```
[0,1,0,2,1,0,1,3,2,1,2,1]
```这些栅栏在较高的墙壁之间形成山谷。 水充满了这些山谷，被困的水总量是`6`。 

关键的观察结果是，高于特定指数的水量取决于其左侧最高的条形和右侧最高的条形。 

在任何位置`i`：```
water[i] = min(max_left, max_right) - height[i]
```如果任何一方没有更高的边界，那么那里就不会积水。 

约束条件很重要：

 -`1 <= n <= 2 * 10^4`-`0 <= height[i] <= 10^5`一个`O(n^2)`对于较小的输入，解决方案可能仍然可以通过，但效率低且不必要。 这个问题强烈建议寻找一个`O(n)`解决方案。 

一些边缘情况很重要：

 - 少于 3 条的阵列无法积水。 
- 严格增加或严格降低高度不会积水。 
- 可能存在多个山谷。 
- 两端非常高的杆可能会在内部积聚大量的水。 
- 如果边界逻辑错误，平坦区域和重复高度可能会导致计算错误。 

## 方法

 ### 蛮力方法

 强力解决方案独立评估每个位置。 

对于每个索引：

 1. 向左扫描找到左侧最高的栏。 
2. 向右扫描找到右侧最高的条形。 
3. 截留的水是这两个高度中较小的一个减去当前条的高度。 

这是有效的，因为任何位置的水位都受到较短边界的限制。 

尽管正确，但此方法效率低下，因为每个索引都会执行两次额外的扫描。 和`n`元素，每个位置可能需要`O(n)`工作，产生总体复杂性`O(n^2)`。 

和`n = 20,000`，这会变得不必要的缓慢。 

### 最佳两指针方法

 最佳解决方案使用两个指针并一次性处理数组。 

核心见解是：

 - 某个位置截留的水取决于较小的边界。 
- 如果左边界小于右边界，则左侧确定水位。 
- 同样，如果右边界较小，则右侧确定水位。 

这意味着我们不需要在每一步都知道双方的确切最大值。 我们只需要跟踪：

 -`left_max`-`right_max`使用两个指针可以让我们计算被困的水`O(n)`时间和`O(1)`额外的空间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 重新计算每个索引的左右最大值 |
 | 最佳 | O(n) | O(1) | O(1) | 使用两个指针和运行最大值 |

 ## 算法演练

 ### 最优二指针算法

 1.初始化两个指针：

 -`left = 0`-`right = len(height) - 1`这些指针代表当前正在处理的边界。 
2.初始化两个变量：

 -`left_max = 0`-`right_max = 0`这些存储着迄今为止从两侧看到的最高的酒吧。 
3. 初始化`trapped_water = 0`。 
4. 虽然`left < right`， 比较`height[left]`和`height[right]`。 
5. 如果`height[left] < height[right]`，处理左侧：

 - 如果`height[left] >= left_max`， 更新`left_max`。 
- 否则，可能会积水：```
left_max - height[left]
```- 移动`left`右一步。 
6. 否则，处理右侧：

 - 如果`height[right] >= right_max`， 更新`right_max`。 
- 否则，可能会积水：```
right_max - height[right]
```- 移动`right`还剩一步。 
7. 继续，直到指针相遇。 
8. 返回`trapped_water`。 

### 为什么它有效

 正确性取决于这个不变量：

 - 任何位置的水位由两侧最高边界中较小的一个决定。 

什么时候`height[left] < height[right]`，我们知道左侧是极限边界。 即使更右边存在更高的墙，当前的右边界已经足够高，可以保证`left_max`决定水位。 

同样的逻辑对称地适用于右侧。 

由于每个索引只处理一次，因此该算法既正确又高效。 

## Python 解决方案```python
from typing import List

class Solution:
    def trap(self, height: List[int]) -> int:
        if len(height) < 3:
            return 0

        left = 0
        right = len(height) - 1

        left_max = 0
        right_max = 0

        trapped_water = 0

        while left < right:
            if height[left] < height[right]:
                if height[left] >= left_max:
                    left_max = height[left]
                else:
                    trapped_water += left_max - height[left]

                left += 1
            else:
                if height[right] >= right_max:
                    right_max = height[right]
                else:
                    trapped_water += right_max - height[right]

                right -= 1

        return trapped_water
```实现首先处理一个小的边缘情况。 少于三根条的阵列无法捕获水，因为至少需要两个边界和一个中间位置。 

两个指针在数组的两端初始化。 当算法处理条时，这些指针向内移动。`left_max`和`right_max`跟踪每侧遇到的最高的杆。 

在每次迭代中，算法都会处理高度较小的一侧，因为该一侧决定了可能的最大水位。 

如果当前高度超过运行最大值，则更新最大值。 否则，将使用运行最大值和当前高度之间的差值来计算滞留水。 

该算法一直持续到指针相遇为止，确保每个索引都被处理一次。 

## 解决方案```go
func trap(height []int) int {
    if len(height) < 3 {
        return 0
    }

    left := 0
    right := len(height) - 1

    leftMax := 0
    rightMax := 0

    trappedWater := 0

    for left < right {
        if height[left] < height[right] {
            if height[left] >= leftMax {
                leftMax = height[left]
            } else {
                trappedWater += leftMax - height[left]
            }

            left++
        } else {
            if height[right] >= rightMax {
                rightMax = height[right]
            } else {
                trappedWater += rightMax - height[right]
            }

            right--
        }
    }

    return trappedWater
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

Go 切片是数组中动态大小的视图，因此除了检查长度之外不需要特殊处理。 

所有算术用途`int`，这已经足够了，因为在给定的约束下，最大截留水值非常适合 Go 的整数范围。 

与 Python 不同，Go 需要显式变量声明和增量语法。

 ## 边缘情况

 ### 小于三个元素的数组

 少于三个条的阵列无法捕获水，因为没有足够的边界来创建容器。 

示例：```
[]
[1]
[1,2]
```一个常见的错误是尝试正常处理这些数组，这可能会导致不必要的逻辑或索引错误。 实现立即处理这个问题：```
if len(height) < 3:
    return 0
```### 严格增加或减少高度

 数组如：```
[1,2,3,4,5]
```或者```
[5,4,3,2,1]
```不能积水，因为从来没有一个山谷被更高的栅栏包围。 

幼稚的实施有时会错误地假设每个较低的栏都会积水。 双指针算法通过仅在有效边界最大值已经存在时添加水来避免这种情况。 

### 平坦区域和等高

 数组例如：```
[3,3,3]
[0,0,0]
```不包含山谷。 

如果比较逻辑不正确，等高可能会导致指针移动错误。 该实现使用以下方法安全地处理相同的高度`else`分支，确保指针始终移动并且不会发生无限循环。 

### 具有巨大价值的深谷

 案例如下：```
[100000,0,100000]
```测试实施是否正确处理大的捕获量。 

该算法计算：```
100000 - 0 = 100000
```在给定的约束下，Python 或 Go 都不会出现溢出问题。
