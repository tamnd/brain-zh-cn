 # 两个数字相加

 ## 问题理解

 该问题给了我们两个非空单链表。 每个链表代表一个非负整数，但数字以相反的顺序存储。 

这意味着头节点包含最低有效数字。 

例如：

-`[2,4,3]`代表数字`342`-`[5,6,4]`代表数字`465`任务是将两个数字加在一起，并将结果作为另一个链表返回，也以相反的顺序存储。 

上面例子的结果是：

 -`342 + 465 = 807`- 逆序表示变为`[7,0,8]`重要的细节是我们不应该直接将链表转换为实际的整数值。 虽然 Python 可以处理非常大的整数，但其他语言可能不能，并且预期的解决方案侧重于链表操作和逐位加法。 

约束条件告诉我们：

 - 每个列表之间有`1`和`100`节点
 - 每个节点包含一个数字`0`到`9`- 除数字外不存在前导零`0`输入尺寸相对较小，但问题旨在测试链表遍历和携带传播逻辑。 

一些边缘情况在这里很重要：

 - 不同长度的列表，例如`[1,8]`和`[0]`- 跨多个数字进行传播，例如`[9,9,9] + [1]`- 处理完所有节点后最终进位，例如`999 + 1 = 1000`- 仅包含零的输入
 - 一个列表早于另一个列表结束

 当一个列表较短或最后一位数字后仍有额外进位时，简单的实现通常会失败。 

## 方法

 ### 蛮力方法

 一种简单的方法是从链表中重建两个整数，将它们加在一起，然后根据结果构建一个新的链表。 

该过程的工作原理如下：

 1. 遍历第一个链表并计算整数值。 
2. 遍历第二个链表并计算整数值。 
3. 将两个整数相加。 
4. 将结果和转换回反向链表。 

这种方法是正确的，因为它直接执行问题要求的算术运算。 

然而，它也有缺点：

 - 这取决于整数转换。 
- 在某些语言中，数字可能超出内置的整数限制。 
- 它忽略了问题的链表性质。 
- 它执行不必要的数字重建。 

尽管这里的约束足够小，以至于溢出在 Python 中不是一个实际问题，但这并不被认为是预期的解决方案。 

### 最佳方法

 更好的方法是逐位模拟小学加法。 

由于数字已经以相反的顺序存储，因此我们可以从头到尾处理链表，就像我们从右到左手动添加数字一样。 

每一步：

 - 添加两个列表中的当前数字
 - 添加上一步中的任何进位
 - 将个位存储在结果列表中
 - 将十位数向前进位

 这可以自然地与链表配合使用，并避免完全重建大整数。 

关键的观察结果是，逆序存储与加法的正常进行方式完全一致。 

## 方法比较

 | --- | --- | --- | --- |

 ## 算法演练

 1. 为结果列表创建一个虚拟头节点。 

虚拟节点简化了链表构造，因为我们总是在它后面附加新节点。 这避免了对第一个节点的特殊处理。 
2. 初始化一个名为`current`。 

该指针跟踪结果列表中的最后一个节点，因此可以有效地附加新数字。 
3. 初始化`carry = 0`。 

进位存储前一个数字加法产生的溢出。 
4. 同时遍历两个链表。 

当至少一个列表仍然有节点或进位仍然存在时继续。 
5. 提取当前数字值。 

如果列表仍有节点，请使用其数字值。 否则使用`0`。 

这自然可以处理不等长度的列表。 
6. 计算数字和。 

添加：

 - 第一个列表中的值
 - 第二个列表中的值
 - 从上一步开始
 7.更新携带。 

使用整数除法：```
carry = total // 10
```这仅保留溢出部分。 
8. 创建当前结果数字。 

使用模：```
digit = total % 10
```这会提取当前数字进行存储。 
9. 将新节点追加到结果列表中。 

使用计算出的数字创建一个节点并将其附加在后面`current`。 
10. 前进所有指针。 

移动：

-`current`-`l1`-`l2`11.返回真实的头。 

由于虚拟节点是人为的，因此返回`dummy.next`。 

### 为什么它有效

 在每次迭代中，该算法都会使用标准算术中使用的基于进位的加法来正确计算最终和的一位数。 

由于链表以相反的顺序存储，因此最低有效数字首先出现，从而允许直接从左到右遍历而无需反转任何内容。 

不变量是：

 - 在每次迭代之前，结果列表已经包含所有先前处理的数字的正确总和。 
- 进位值正确表示溢出到下一个数字位置。 

当遍历结束时，所有的数字和剩余的进位都已经处理完毕，所以构建的链表就是完整的正确和。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

from typing import Optional

class Solution:
    def addTwoNumbers(
        self,
        l1: Optional[ListNode],
        l2: Optional[ListNode]
    ) -> Optional[ListNode]:

        dummy = ListNode(0)
        current = dummy

        carry = 0

        while l1 or l2 or carry:

            value1 = l1.val if l1 else 0
            value2 = l2.val if l2 else 0

            total = value1 + value2 + carry

            carry = total // 10
            digit = total % 10

            current.next = ListNode(digit)
            current = current.next

            if l1:
                l1 = l1.next

            if l2:
                l2 = l2.next

        return dummy.next
```实现首先创建一个虚拟头节点。 该节点充当结果链表的稳定起点。 

这`current`指针始终指向结果列表的尾部。 每个新计算的数字都会附加在其后面。 

当列表中仍有剩余数字或进位仍需要处理时，循环将继续。 这个条件很关键，因为最后的进位可能会创建一个额外的节点。 

在循环内部，当一个列表比另一个列表短时，缺失的数字将被视为零。 这保持了加法逻辑的统一。 

总和分为两部分：

 -`digit`，成为当前节点值
 -`carry`，传播到下一次迭代

 最后，函数返回`dummy.next`因为虚拟节点本身不是答案的一部分。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func addTwoNumbers(l1 *ListNode, l2 *ListNode) *ListNode {

    dummy := &ListNode{}
    current := dummy

    carry := 0

    for l1 != nil || l2 != nil || carry != 0 {

        value1 := 0
        value2 := 0

        if l1 != nil {
            value1 = l1.Val
        }

        if l2 != nil {
            value2 = l2.Val
        }

        total := value1 + value2 + carry

        carry = total / 10
        digit := total % 10

        current.Next = &ListNode{Val: digit}
        current = current.Next

        if l1 != nil {
            l1 = l1.Next
        }

        if l2 != nil {
            l2 = l2.Next
        }
    }

    return dummy.Next
}
```Go 解决方案遵循与 Python 实现相同的逻辑。 

主要的语言特定差异是指针处理。 Go 使用`nil`而不是`None`，并且链表节点是使用结构指针创建的。 

整数溢出不是问题，因为每个中间计算都保持在非常小的范围内。 最大数字和为：```go
9 + 9 + 1 = 19
```所以标准整数算术是完全安全的。

 ## 边缘情况

 ### 两个输入都为零

 最简单的有效输入是：```
[0] + [0]
```如果假设应跳过零位数字，则有错误的实现可能会意外返回空列表。 

此实现正确创建了一个具有值的节点`0`因为即使总和为零，循环也会正常处理数字。 

### 遍历后的最终进位

 案例如下：```
[9] + [1]
```生产：```
[0,1]
```最常见的错误是在两个列表结束后立即停止遍历，忽略剩余的进位。 

此实现通过继续循环而避免了该问题`carry`是非零：```
while l1 or l2 or carry:
```该额外的迭代正确地创建了最终节点。 

### 不同长度的列表

 输入例如：```
[1,8] + [0]
```可能会破坏假设两个列表始终同时具有可用节点的实现。 

该解决方案通过将丢失的节点视为零来处理它们：```
value1 = l1.val if l1 else 0
value2 = l2.val if l2 else 0
```即使一个列表早于另一个列表完成，这也允许添加正确地继续。
