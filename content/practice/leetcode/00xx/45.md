[LeetCode 第 45 题](https://leetcode.com/problems/jump-game-ii/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划、贪心

 ## 解决方案

 ## 问题理解

 问题给出了一个数组`nums`其中每个值代表您可以从该位置向前跳跃的最大距离。 你从索引开始`0`，您的目标是使用尽可能少的跳跃次数达到最终索引。 

例如，如果`nums[i] = 3`，然后从索引`i`你可以跳：

 - 前进1步
 - 前进2步
 - 前进 3 步

 您不需要使用完整的跳跃距离。 任何值来自`0`到`nums[i]`是允许的，只要结果索引保留在数组内。 

任务不是确定最后一个索引是否可达。 该问题保证始终可以到达最后一个索引。 相反，挑战是计算所需的最小跳跃次数。 

约束条件很重要：

 -`nums.length`可以大到`10^4`-`nums[i]`可以达到`1000`由于路径数量呈指数级增长，快速探索每个可能的跳跃路径的强力解决方案变得太慢。 这强烈表明我们需要更有效的策略。 

有几个重要的边缘情况需要记住：

 - 长度数组`1`， 例如`[0]`，已经从目的地开始，所以答案是`0`。 
- 大的跳跃值可能允许立即到达终点。 
- 某些职位可能包含`0`，这意味着您无法从该索引继续前进。 然而，这个问题保证了整个阵列仍然是可解的。 
- 可能存在多条路径，但我们只关心最小的跳转次数。 

关键的挑战是战略性地选择跳跃，以便我们最大限度地减少移动总数，而不是贪婪地采取最大的立即跳跃。 

## 方法

 ### 蛮力方法

 一种直接的方法是递归地尝试从每个位置的每个可能的跳转。 

来自索引`i`，我们可以尝试跳转到：

 -`i + 1`-`i + 2`- ...
 -`i + nums[i]`对于每个可能的下一个位置，我们递归地计算到达终点所需的最小跳跃次数。 

这种方法是正确的，因为它探索每条有效路径并选择其中最少的跳跃次数。 然而，由于许多子问题被重复重新计算，效率极低。 

例如，多条路径最终可能到达相同的索引，从而导致冗余计算。 在最坏的情况下，递归树会变成指数树。 

动态编程可以减少这种冗余，但即使是 DP 解决方案也可能仍然需要检查索引之间的许多转换，从而导致`O(n^2)`复杂。 

### 最优贪心法

 关键的观察是我们实际上不需要单独探索每条路径。 

相反，我们可以像索引范围上的广度优先搜索一样来思考这个问题。 

假设我们已经知道使用当前跳跃次数可以到达的所有位置。 在扫描这些位置时，我们计算通过一次额外跳跃可到达的最远位置。 

一旦我们完成了对当前可达范围的扫描，我们就必须进行另一次跳跃。 此时，我们将范围更新为发现的最远位置。 

这种贪婪策略之所以有效，是因为：

 - 使用相同次数的跳跃即可到达当前范围内的每个位置。 
- 当选择下一个跳跃时，唯一重要的是我们能将触角延伸多远。 
- 延迟跳跃决策直到当前范围用完可以保证最小的跳跃次数。 

这会产生一个`O(n)`解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 递归探索所有跳跃组合 |
 | 动态规划| O(n^2) | O(n^2) | O(n) | 存储每个索引的最小跳转 |
 | 最优贪心 | O(n) | O(1) | O(1) | 贪婪地扩展可达范围 |

 ## 算法演练

 ### 贪心范围扩展算法

 1.初始化三个变量：

 -`jumps`计算我们已经使用了多少次跳跃
 -`current_end`表示使用当前跳转次数可到达的最远索引
 -`farthest`跟踪扫描当前范围时我们可以到达的最远索引
 2. 从索引处迭代数组`0`到`n - 2`。 

我们在最终索引之前停止，因为一旦我们到达最后一个位置，就不需要进一步跳转。 
3. 在每个索引处`i`，计算：```
i + nums[i]
```这表示距离索引最远的位置`i`。 
4. 更新`farthest`到目前为止看到的最大可到达位置。 

这意味着我们正在收集再跳一跳即可到达的所有可能目的地。 
5. 什么时候`i`达到`current_end`，我们已经完成了对当前跳跃范围的扫描。 

此时：

 - 我们必须再跳一次
 - 增量`jumps`- 更新`current_end = farthest`6. 继续扫描直至循环结束。 
7. 返回`jumps`。 

### 为什么它有效

 该算法保持了一个重要的不变量：

 - 每个索引高达`current_end`可以精确地使用`jumps`跳跃。 
- 扫描此范围时，`farthest`记录下一次跳跃的最佳可能延伸。 

当我们到达当前范围的末尾时，我们被迫再次跳跃。 选择最远的可到达延伸可确保我们最大限度地提高未来的到达范围，同时仍使用最少的跳跃次数。 

这实际上是对可达范围的逐级广度优先遍历，保证了最优性。 

## Python 解决方案```python
from typing import List

class Solution:
    def jump(self, nums: List[int]) -> int:
        n = len(nums)

        # Already at the destination
        if n == 1:
            return 0

        jumps = 0
        current_end = 0
        farthest = 0

        for i in range(n - 1):
            farthest = max(farthest, i + nums[i])

            # End of current jump range
            if i == current_end:
                jumps += 1
                current_end = farthest

        return jumps
```其实现完全遵循贪婪范围扩展策略。 

变量`jumps`存储迄今为止使用的最小跳跃次数。 变量`current_end`表示当前可达范围的边界。 使用当前跳转次数可以到达此边界之前的每个索引。 

当循环扫描当前范围内的索引时，算法不断更新`farthest`，它跟踪下一次跳跃的最佳可能范围。 

每当循环索引达到`current_end`，这意味着当前的跳跃不能再让我们走得更远。 此时，需要进行另一次跳转，因此我们递增`jumps`并将可达范围扩展到`farthest`。 

循环仅运行到`n - 2`因为一旦我们到达最后一个索引，就不需要从目的地本身进行额外的跳转。 

## 解决方案```go
func jump(nums []int) int {
    n := len(nums)

    // Already at the destination
    if n == 1 {
        return 0
    }

    jumps := 0
    currentEnd := 0
    farthest := 0

    for i := 0; i < n-1; i++ {
        if i+nums[i] > farthest {
            farthest = i + nums[i]
        }

        // End of current jump range
        if i == currentEnd {
            jumps++
            currentEnd = farthest
        }
    }

    return jumps
}
```Go 实现与 Python 版本几乎相同。 

Go 没有内置 Python`max`整数函数，所以我们更新`farthest`使用简单的条件比较。 

Go 中的切片自然地处理动态数组访问，类似于 Python 列表，因此不需要额外的处理。 整数溢出不是问题，因为约束很小。

 | 测量 | 复杂性 | 说明|

 贪心算法对数组执行单次遍历。 每次迭代都会进行恒定的工作，因此总运行时间随着输入大小线性增长。 

无论输入大小如何，该算法仅使用三个额外的整数变量，因此额外的空间使用量是恒定的。

 ## 边缘情况

 ### 单元素数组

 像这样的输入`[0]`是一个重要的边缘情况，因为起始索引已经是目的地。 简单的实现可能会错误地计算一次跳转，因为循环开始处理索引`0`。 

该实现通过以下方式显式处理此问题：```
if n == 1:
    return 0
```这保证了在不进入主循环的情况下得到正确的答案。 

### 包含零的数组

 值为`0`意味着从该位置不可能向前移动。 这可以很容易地打破幼稚的贪婪策略，这些策略在不考虑未来可达性的情况下跳跃得太激进。 

例如：```
[2,3,0,1,4]
```如果我们登陆索引`2`，我们陷入困境。 然而，最优策略通过在进行下一次跳跃之前考虑整个可到达范围来避免该问题。 

贪心算法之所以成功，是因为它跟踪当前范围内所有位置的最远可达索引，而不仅仅是当前位置。 

### 初始跳跃较大

 考虑：```
[10,1,1,1]
```第一个索引已经可以直接到达最后一个索引。 某些实现可能会继续不必要的处理或误计数跳转。 

该算法正确地识别出第一次跳转将可达范围扩展到了数组末尾之外。 仅计算一次跳跃，这是最佳的。
