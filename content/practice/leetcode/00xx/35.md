[LeetCode 第 35 题](https://leetcode.com/problems/search-insert-position/)

 **难度：** 🟢简单
 **主题：** 数组、二分查找

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个由不同整数组成的排序数组和一个目标值。 我们的任务是确定目标在数组中的位置。 如果目标已经存在，我们返回它的索引。 如果目标不存在，我们返回它应该插入的位置，以便数组保持排序。 

输入由两部分组成。 第一个输入，`nums`，是一个按升序排序的数组，没有重复值。 第二个输入，`target`, 是我们要搜索的整数。 预期输出是一个整数，表示目标的现有索引或将保留排序顺序的插入位置。 

这个问题的重要细节是运行时要求。 该问题明确要求`O(log n)`解决方案。 这立即排除了最佳解决方案的任何线性扫描方法，因为从左到右迭代数组将花费`O(n)`最坏情况下的时间。 

这些约束还告诉我们一些有用的信息：

 - 数组长度至少为 1，因此我们从不处理空数组。 
- 数组按升序排序，强烈建议二分搜索。 
- 所有值都是不同的，因此我们永远不需要处理重复插入的歧义。 
- 值相对较小，但值的大小并不重要，因为二分搜索取决于排序，而不是值的大小。 

尽早识别一些边缘情况很重要：

 - 目标可能小于数组中的每个元素，这意味着答案应该是索引`0`。 
- 目标可能比每​​个元素都大，这意味着答案应该是`len(nums)`。 
- 目标可能已存在于数组中。 
- 目标可能位于两个元素之间的中间位置。 

简单的实现很容易在边界附近犯一个错误，特别是在二分搜索完成后确定插入位置时。 

## 方法

 ### 蛮力方法

 最直接的解决方案是从左到右扫描数组。 对于每个元素，我们将其与目标进行比较。 

如果我们发现一个元素等于目标，我们立即返回它的索引。 如果我们遇到一个大于目标的元素，我们知道目标应该插入到它之前，因此我们返回该索引。 如果我们完成对整个数组的迭代而没有找到更大的值，则目标属于数组的末尾。 

这种方法之所以有效，是因为数组已排序。 大于或等于目标的第一个元素确定正确的插入位置。 

然而，这种方法对于问题要求来说太慢了，因为它可能会检查数组中的每个元素。 最坏情况下的运行时间是`O(n)`，而问题明确要求`O(log n)`复杂。 

### 最佳方法

 关键的观察结果是数组已经排序。 每当我们有一个排序数组并且需要对数搜索性能时，二分搜索就成为自然的解决方案。 

二分查找反复将搜索空间一分为二。 我们不是逐一检查每个元素，而是检查中间元素：

 - 如果中间元素等于目标，我们返回它的索引。 
- 如果中间元素小于目标，我们知道目标一定在右侧。 
- 如果中间元素大于目标，我们知道目标一定在左侧。 

最终，搜索空间变空。 此时，左边界代表正确的插入位置。 

重要的见解是，二分搜索不仅可以有效地找到现有元素，还可以自然地识别丢失元素所属的位置。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(1) | O(1) | 顺序扫描数组，直到找到正确的位置 |
 | 最佳| O(log n) | O(1) | O(1) | 使用二分查找重复将搜索空间减半 |

 ## 算法演练

 1.初始化两个指针，`left`和`right`。 

这`left`指针从索引处开始`0`，以及`right`指针开始于`len(nums) - 1`。 这些指针定义当前的搜索范围。 
2.继续搜索`left <= right`。 

只要搜索范围有效，目标仍然可能存在。 
3. 计算中间索引。 

我们计算：$mid = left + \frac{right - left}{2}$尽管 Python 本身不会在整数上溢出，但该公式避免了某些编程语言中潜在的整数溢出。 
4. 将中间元素与目标进行比较。 

- 如果`nums[mid] == target`，我们立即返回`mid`因为我们找到了目标。 
- 如果`nums[mid] < target`，目标必须位于右侧`mid`，所以我们移动`left = mid + 1`。 
- 如果`nums[mid] > target`，目标必须位于`mid`，所以我们移动`right = mid - 1`。 
5. 重复此操作，直至搜索空间变空。 

什么时候`left > right`，循环停止。 此时此刻，`left`指针表示目标的确切插入位置。 
6. 返回`left`。 

即使目标不存在，`left`指示可以插入目标同时保留排序顺序的第一个有效位置。 

### 为什么它有效

 该算法在整个执行过程中保持一个重要的不变量：如果目标存在，它必须始终保持在当前搜索范围内。 每次比较都会消除一半的剩余可能性，同时保留这个不变量。 当循环结束时，所有不可能的位置都已被消除，并且`left`指针最终指向目标可以合法出现的最小索引。 这保证了正确性和最佳对数运行时间。 

## Python 解决方案```python
from typing import List

class Solution:
    def searchInsert(self, nums: List[int], target: int) -> int:
        left = 0
        right = len(nums) - 1

        while left <= right:
            mid = left + (right - left) // 2

            if nums[mid] == target:
                return mid

            if nums[mid] < target:
                left = mid + 1
            else:
                right = mid - 1

        return left
```实现首先初始化二分搜索边界`left`和`right`。 这些变量跟踪目标可能存在的当前范围。 

里面的`while`循环，中点的计算方法为`left + (right - left) // 2`。 这可以安全地计算中间索引，并避免具有固定整数大小的语言中的溢出问题。 

下一部分执行关键比较逻辑。 如果中间元素等于目标，该函数立即返回索引。 否则，算法确定可以丢弃数组的哪一半：

 - 如果中间值小于目标值，则左半部分包括`mid`无法包含答案，所以`left`移动到`mid + 1`。 
- 如果中间值大于目标，则右半部分包括`mid`无法包含答案，所以`right`移动到`mid - 1`。 

最终，搜索空间变空。 那时，`left`指向正确的插入位置，因此函数返回`left`。 

## 解决方案```go
func searchInsert(nums []int, target int) int {
    left := 0
    right := len(nums) - 1

    for left <= right {
        mid := left + (right-left)/2

        if nums[mid] == target {
            return mid
        }

        if nums[mid] < target {
            left = mid + 1
        } else {
            right = mid - 1
        }
    }

    return left
}
```Go 实现遵循与 Python 解决方案完全相同的二分搜索逻辑。 一个值得注意的细节是 Go 在除法时自动使用整数除法，所以`(right-left)/2`已经产生一个整数中点。 

Go 切片的行为与动态数组类似，因此可以使用以下方式访问元素`nums[mid]`自然有效。 由于该问题保证数组中至少有一个元素，因此不需要对空切片进行特殊处理。 

中点计算使用`left + (right-left)/2`，这可以避免 Go 等具有固定整数大小的语言中的溢出。

 运行时间是对数的，因为二分搜索在每次迭代期间消除了一半的剩余元素。 开始于`n`元素，搜索空间缩小到`n/2`， 然后`n/4`， 然后`n/8`，依此类推，直到只剩下一种可能性。

 ## 边缘情况

 当目标小于数组中的每个元素时，就会出现一种重要的边缘情况。 有错误的实现可能会错误地返回`-1`或者未能正确处理左边界。 在这个实现中，二分查找最终移动到`right`以下`0`， 尽管`left`遗迹`0`。 返回`left`正确地将目标放置在数组的开头。 

另一个关键的边缘情况是当目标大于每个元素时。 某些实现错误地返回最后一个有效索引，而不是数组后面的插入位置。 在此解决方案中，`left`指针最终前进到`len(nums)`，它正确地表示在末尾插入。 

第三种重要情况涉及只有一个元素的数组。 二分搜索实现在非常小的数组中特别容易出现一错误，因为循环条件变得敏感。 此实现自然地处理单元素数组，因为搜索循环仍然可以正确计算，并且最终返回值准确地反映匹配或正确的插入位置。 

当目标落在两个现有元素之间时，就会出现最后一种微妙的边缘情况。 该算法必须返回准确的插入位置而不是最接近的值。 因为二分查找缩小了范围，直到`left`成为第一个有效的插入索引，该实现保证了相邻元素之间的正确放置。
