[LeetCode 第 11 题](https://leetcode.com/problems/container-with-most-water/)

 **难度：** 🟡 中等
 **主题：** 数组、两个指针、贪婪

 ## 解决方案

 ## 问题理解

 问题给出了一个名为`height`，其中每个元素表示在坐标平面上绘制的垂直线的高度。 索引处的线`i`开始于`(i, 0)`并结束于`(i, height[i])`。 

我们想要选择两条不同的线，它们与 x 轴一起形成一个能够盛水的容器。 容器可以容纳的水量取决于两个因素：

 - 两条线之间的宽度
 - 较短线的高度

 如果我们在位置选择线`left`和`right`，那么：

 - 宽度=`right - left`- 高度=`min(height[left], height[right])`所以蓄水面积为：$$\text{area} = (right - left) \times \min(height[left], height[right])$$任务是返回所有线对中最大可能的面积。 

约束在这里很重要：

 -`2 <= n <= 10^5`-`0 <= height[i] <= 10^4`由于数组最多可以包含十万个元素，因此任何比粗略线性或近线性时间更差的解决方案都可能太慢。 在最坏的情况下，二次解决方案需要检查数十亿对，这是不切实际的。 

有几种边缘情况值得立即考虑：

 - 只有两个元素的数组
 - 包含零的高度
 - 严格增加或严格降低高度
 - 多条线具有相同的高度
 - 非常高的线靠得很近，较短的线间隔很远

 该问题保证至少有两行，因此我们永远不需要处理空数组或单元素数组。 

## 方法

 ### 蛮力方法

 最直接的方法是检查每对可能的线。 

对于每个索引`i`，我们尝试每个索引`j > i`。 对于每一对，我们计算：$$(j - i) \times \min(height[i], height[j])$$我们跟踪遇到的最大区域。 

这种方法保证有效，因为它显式检查所有可能的容器。 由于最佳答案必须来自这些对之一，因此穷举搜索最终会找到它。 

问题是效率。 大约有：$$\frac{n(n-1)}{2}$$可能的对。 

和`n = 10^5`，这变得太大了。 时间复杂度为`O(n^2)`，这对于给定的约束是不可接受的。 

### 最佳两指针方法

 关键的观察结果是面积取决于宽度和较短的高度。 

假设我们从尽可能宽的容器开始，在数组的开头放置一个指针，在数组的末尾放置一个指针。 

每一步：

 - 我们计算当前面积。 
- 然后我们将指向较短线的指针向内移动。 

为什么要移动较短的线？ 

因为较短的线是容器高度的限制因素。 向内移动较高的线不会增加高度限制，但肯定会减少宽度。 这意味着通过移动较高的指针同时保持较短的指针固定，无法改善该区域。 

通过移动较短的指针，我们有机会找到一条较高的线，以弥补宽度的减少。 

这种贪婪的洞察力使我们能够消除许多不可能的候选者，而无需单独检查它们。 

结果是线性时间解。

 ## 算法演练

 1.初始化两个指针：

 -`left = 0`-`right = len(height) - 1`这些指针代表当前正在考虑的线对。 从极端开始给出最大可能的宽度。 
2. 初始化变量`max_area = 0`。 

该变量存储迄今为止找到的最佳答案。 
3.同时`left < right`，计算当前容器面积。 

宽度为：$$right - left$$可用高度为：$$\min(height[left], height[right])$$将它们相乘即可得到当前面积。 
4. 更新`max_area`如果当前面积更大。 

这确保我们始终跟踪迄今为止看到的最好的容器。 
5. 将较短线对应的指针向内移动。 

如果`height[left] < height[right]`, 增量`left`。 

否则，递减`right`。 

这一步是算法的核心。 由于较短的线限制了当前区域，因此在减少宽度的同时保留它并不能产生更好的结果。 
6. 继续，直到两个指针相遇。 

一次`left >= right`，所有有意义的对都已被考虑或安全地消除。 
7. 返回`max_area`。 

### 为什么它有效

 该算法依赖于一个重要的不变量：

 在每一步中，移动较高的指针都无法扩大面积，因为较短的线已经限制了高度。 由于移动任一指针都会减少宽度，因此唯一的改进可能是找到一条更高更短的线。 

通过始终丢弃较短的线，我们消除了不可能产生更好答案的线对。 这保证了永远不会跳过最优解。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxArea(self, height: List[int]) -> int:
        left = 0
        right = len(height) - 1

        max_area = 0

        while left < right:
            width = right - left
            current_height = min(height[left], height[right])

            area = width * current_height
            max_area = max(max_area, area)

            if height[left] < height[right]:
                left += 1
            else:
                right -= 1

        return max_area
```实现直接遵循两指针策略。 

变量`left`和`right`跟踪容器的当前边界。 最初，他们指向尽可能宽的一对。 

在循环内，代码计算：

 - 指针之间的宽度
 - 限制高度使用`min`- 结果面积

 迄今为止看到的最大面积在每次计算后都会更新。 

关键的决定随后才会出现。 如果左侧高度较小，则左侧指针向内移动。 否则，右指针向内移动。 这是遵循贪心观察的结果，即仅替换较短的边界就可能改善结果。 

当指针相遇时循环停止，因为超出该点不存在有效容器。 

## 解决方案```go
func maxArea(height []int) int {
    left := 0
    right := len(height) - 1

    maxArea := 0

    for left < right {
        width := right - left

        currentHeight := height[left]
        if height[right] < currentHeight {
            currentHeight = height[right]
        }

        area := width * currentHeight

        if area > maxArea {
            maxArea = area
        }

        if height[left] < height[right] {
            left++
        } else {
            right--
        }
    }

    return maxArea
}
```Go 的实现与 Python 解决方案非常相似。 

由于 Go 没有提供内置的`min`和`max`较旧的标准库版本中的整数函数，比较是使用显式编写的`if`声明。 

该解决方案仅使用整数运算，并且在给定约束下不存在溢出问题，因为最大面积为：$$10^5 \times 10^4 = 10^9$$符合 Go 的标准`int`在现代系统上键入。 

Go 中的切片的行为与动态数组类似，因此访问元素非常简单。

 ## 边缘情况

 一种重要的边缘情况是尽可能最小的输入大小，其中数组恰好包含两个元素。 在这种情况下，只有一个可能的容器。 一些实现意外地假设了多次迭代或额外的移动逻辑。 当前的解决方案可以自然地处理这个问题，因为循环执行一次，计算面积并正确终止。 

另一个重要的情况涉及包含零的高度。 高度为零的线不能有助于保持水，因为最小高度变为零。 不正确的实现有时会忽略这一点并产生负值或无效的计算。 在这里，该公式可以正确运行，因为乘以零自然会得到零面积。 

严格增加或严格减少数组也会暴露指针移动错误。 例如，在`[1,2,3,4,5]`，算法反复向内移动较小的指针。 如果运动逻辑颠倒，算法就会错过最优解。 该实现正确地遵循了只有较短边界应该移动的不变量。 

当两个高度相等时，会出现最后一个微妙的情况。 某些实现错误地同时移动两个指针，这可能会跳过有效的候选者。 当高度相等时，该解决方案仅移动一个指针，在保持正确性的同时仍保证线性复杂性。
