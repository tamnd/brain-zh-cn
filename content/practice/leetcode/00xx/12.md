 **主题：** 哈希表、数学、字符串

 ## 解决方案

 ## 问题理解

 该问题要求我们将正整数转换为其罗马数字表示形式。 罗马数字使用特定符号的组合来表示值，并且这些符号的组合规则是严格的。 与十进制等位置数字系统不同，罗马数字是从最大可能的符号值到最小的符号值贪婪地构建的。 

输入是单个整数`num`， 在哪里`1 <= num <= 3999`。 输出应该是表示等效罗马数字的字符串。 

罗马数字系统使用这些符号：

 | 符号| 价值|
 | --- | --- |
 | 我| 1 |
 | V | 5 |
 | X | 10 | 10
 | 左 | 50 | 50
 | C | 100 | 100
 | d | 500 | 500
 | 中号 | 1000 | 1000

 大多数罗马数字都是通过重复地从剩余数字中减去最大可能值并附加相应的符号来形成的。 然而，也有特殊的减法情况。 罗马数字不是连续书写四个相同的符号，而是使用紧凑的减法形式：

 | 价值| 罗马 |
 | --- | --- |
 | 4 | 四 |
 | 9 | 九 |
 | 40 | 40 XL |
 | 90 | 90 XC |
 | 400 | 光盘 |
 | 900 | 900 CM |

 例如，`4`写成`IV`而不是`IIII`， 和`900`写成`CM`而不是`DCCCC`。 

约束极限为`3999`很重要，因为标准罗马数字传统上就停在那里。 这意味着该解决方案只需要支持最多符号`M`。 

一些边缘情况可能会在简单的实现中导致错误。 包含的数字`4`或者`9`任何小数位都需要减法表示法。 例如，`49`必须成为`XLIX`， 不是`IL`。 另一个重要的情况是重复符号。 罗马数字最多允许连续三次重复`I`,`X`,`C`， 和`M`。 符号如`V`,`L`， 和`D`不能重复。 该问题保证输入始终有效且在范围内，因此我们不需要处理无效或负数。 

## 方法

 ### 蛮力方法

 强力解决方案可以尝试分别对千位、百位、十位和个位使用许多条件检查来逐位模拟罗马数字结构。 对于每个小数位，算法将根据罗马数字规则重复附加符号。 

例如，如果数字是`3749`，算法将处理：

 - 千位数字`3`→`"MMM"`- 百位数字`7`→`"DCC"`- 十位数字`4`→`"XL"`- 个位数字`9`→`"IX"`这种方法之所以有效，是因为罗马数字基本上基于小数位分解。 然而，使用嵌套条件手动实现每条规则变得冗长且容易出错。 它还跨位值复制逻辑。 

尽管由于约束限制，运行时间仍然很小，但实现复杂度却过高。 

### 最优贪心法

 关键的见解是罗马数字可以从最大值到最小值贪婪地构建。 

在每一步中，我们选择不超过剩余数字的最大罗马数字值。 我们将其符号附加到结果中，并从数字中减去其值。 这自然可以处理标准形式和减法形式。 

例如：

-`1994`- 最大值 ≤ 1994 年`1000`→ 追加`"M"`- 剩余 =`994`- 最大值 ≤ 994 是`900`→ 追加`"CM"`- 剩余 =`94`- 最大值 ≤ 94 是`90`→ 追加`"XC"`- 剩余 =`4`- 最大值 ≤ 4 是`4`→ 追加`"IV"`结果=`"MCMXCIV"`这很有效，因为罗马数字是围绕递减的值组成设计的。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(1) | O(1) | O(1) | O(1) | 对每个数字位置使用许多手动条件规则 |
 | 最佳| O(1) | O(1) | O(1) | O(1) | 使用预定义值符号对的贪婪构造 |

 尽管由于输入范围有界，两者在技术上都是恒定时间，但贪婪解决方案更干净、更具可扩展性并且更易于推理。 

## 算法演练

 1. 创建罗马数字值-符号对的有序列表。 

该列表必须包括标准符号和减法形式。 这些对按从最大到最小值的顺序排列，因此算法可以贪婪地消耗该数字。 

例子：```
1000 -> M
900  -> CM
500  -> D
400  -> CD
...
1    -> I
```2. 初始化一个空结果字符串。 

该字符串将在我们构造它时存储罗马数字。 
3. 按降序迭代值-符号对。 

对于每一对，检查当前数字是否大于或等于该值。 
4. 当当前值适合剩余数量时：

 - 将相应的罗马符号附加到结果中。 
- 从数字中减去该值。 

这个贪婪的过程确保我们总是首先使用尽可能大的罗马数字表示形式。 
5. 继续，直到剩余数字变为零。 

一旦数字达到零，罗马数字就完整了。 
6. 返回构造的结果字符串。 

### 为什么它有效

 该算法之所以有效，是因为罗马数字本质上是一种贪婪的表示系统。 每个有效的罗马数字都是通过重复取最大可能的合法符号或减法对来构造的。 由于该列表包含所有必需的减法形式，并且按从大到小的顺序排列，因此该算法始终会生成规范的罗马数字表示形式，而不会违反罗马数字规则。 

## Python 解决方案```python
class Solution:
    def intToRoman(self, num: int) -> str:
        value_symbols = [
            (1000, "M"),
            (900, "CM"),
            (500, "D"),
            (400, "CD"),
            (100, "C"),
            (90, "XC"),
            (50, "L"),
            (40, "XL"),
            (10, "X"),
            (9, "IX"),
            (5, "V"),
            (4, "IV"),
            (1, "I"),
        ]

        result = []

        for value, symbol in value_symbols:
            while num >= value:
                result.append(symbol)
                num -= value

        return "".join(result)
```该实现首先按降序定义罗马数字映射。 包括减法形式，例如`CM`和`IV`是必不可少的，因为这些特殊情况不能自动从标准符号中导出。 

这`result`使用列表而不是重复的字符串连接，因为在 Python 中追加到列表是高效的。 在最后，`"".join(result)`构造最终的罗马数字字符串。 

主循环迭代每个值符号对。 对于每一对，内部`while`只要剩余的数字足够大，循环就会重复应用该符号。 

例如，如果`num = 3000`，算法附加`"M"`移动到下一个值之前三次。 

该实现直接遵循前面描述的贪婪算法。 

## 解决方案```go
func intToRoman(num int) string {
    valueSymbols := []struct {
        value  int
        symbol string
    }{
        {1000, "M"},
        {900, "CM"},
        {500, "D"},
        {400, "CD"},
        {100, "C"},
        {90, "XC"},
        {50, "L"},
        {40, "XL"},
        {10, "X"},
        {9, "IX"},
        {5, "V"},
        {4, "IV"},
        {1, "I"},
    }

    result := ""

    for _, pair := range valueSymbols {
        for num >= pair.value {
            result += pair.symbol
            num -= pair.value
        }
    }

    return result
}
```Go 实现密切反映了 Python 逻辑。 由于 Go 没有元组，因此映射存储为匿名结构的切片，其中包含`value`和`symbol`。 

字符串连接在这里是可以接受的，因为罗马数字长度非常小，受到问题约束的限制。 在较大的弦构建问题中，`strings.Builder`出于效率考虑，通常会优先考虑。 

Go 整数可以轻松处理高达`3999`，所以溢出不是问题。

 ## 边缘情况

 一个重要的边缘情况是包含以下内容的数字`4`或者`9`在任何小数位。 罗马数字对这些值使用减法表示法，因此`4`变成`IV`而不是`IIII`， 和`90`变成`XC`而不是`LXXXX`。 重复附加符号而不考虑减法形式的简单实现将生成无效的罗马数字。 此实现通过在映射列表中显式包含减法对来正确处理该问题。 

另一个关键的边缘情况是最大有效输入，`3999`。 该数字产生最长的标准罗马数字：`"MMMCMXCIX"`。 一些不正确的实现会失败，因为它们没有按降序处理符号或忘记包含`900`和`90`映射。 由于该算法贪婪地从最大到最小消耗值，因此它可以正确地构造数字而不会产生歧义。 

第三种边缘情况涉及重复的符号。 罗马数字规则最多允许连续三次重复`I`,`X`,`C`， 和`M`。 值例如`4`,`40`， 和`400`因此必须使用减法表示法而不是四个重复的符号。 通过包括`IV`,`XL`， 和`CD`直接在查找表中，实现自动避免无效重复。 

最后一个微妙的情况是像这样的数字`49`。 一些不正确的解决方案尝试使用非标准的减法形式，例如`IL`。 罗马数字必须由小数位独立构成，所以`49`必须成为`XLIX`。 由于贪婪映射仅包含合法的罗马数字组合，因此该算法始终生成有效的规范形式。
