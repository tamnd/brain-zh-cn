[LeetCode 第 25 题](https://leetcode.com/problems/reverse-nodes-in-k-group/)

 **难度：** 🔴难
 **主题：** 链表、递归

 ## 解决方案

 ## 问题理解

 这个问题要求我们按大小组反转单链表`k`。 我们不是立即反转整个列表，而是仅反转包含确切内容的连续块`k`节点。 

例如，如果链表是：```
1 -> 2 -> 3 -> 4 -> 5
```和`k = 2`，我们反转每组两个节点：```
(1 -> 2) becomes (2 -> 1)
(3 -> 4) becomes (4 -> 3)
```最终结果是：```
2 -> 1 -> 4 -> 3 -> 5
```最后一个节点保持不变，因为没有足够的节点来形成另一个完整大小的组`2`。 

重要的细节是我们不允许修改节点值。 我们必须在物理上重新排列节点指针本身。 这意味着我们不能简单地将值复制到数组中并重写它们。 必须直接操作链接结构。 

输入包括：

 -`head`，单链表的第一个节点
 -`k`, 每个反转组的大小

 输出应该是所有有效组都已反转后修改后的链表的头。 

限制条件是：

 -`1 <= k <= n <= 5000`- 链表最多包含5000个节点

 这些限制足够小，即使是`O(n)`或者`O(n log n)`解决方案是可以接受的，但是后续具体询问是否可以实现`O(1)`额外的内存。 这强烈建议采用就地链表操作解决方案。 

一些边缘情况很重要：

 - 如果`k = 1`，不应发生逆转。 
- 如果列表长度小于`k`，整个列表保持不变。 
- 如果最终组包含少于`k`节点，它必须保持原来的顺序。 
- 单节点列表应始终原样返回。 

简单的实现在反转指针时很容易丢失对列表部分的引用，因此仔细的指针管理至关重要。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是将节点提取到辅助数据结构（例如数组或堆栈）中。 我们可以逐组遍历链表，收集`k`节点，反转它们在临时结构内的顺序，并将它们重新连接到最终列表中。 

例如：

 1. 遍历列表。 
2. 存储下一个`k`数组中的节点。 
3. 反转数组。 
4. 重新连接颠倒的节点。 
5. 继续直到列表末尾。 

这种方法之所以有效，是因为数组使反转变得简单而直接。 但是，它使用与组大小成比例的额外内存，并且根据实现可能与整个列表成比例。 

虽然这对于约束来说是可以接受的，但是它不能满足后续恒定额外内存的要求。 

### 最佳方法

 关键的观察是链表反转已经可以使用指针操作就地完成。 我们可以直接在列表内部反转每个组，而不是在外部存储节点。 

该算法的工作原理是：

 1. 判断是否是一个完整的组`k`节点存在。 
2. 逆转这些`k`节点就位。 
3. 将反向组重新连接回列表中。 
4. 对下一组重复此操作。 

虚拟节点非常有用，因为列表的头部本身可能在第一次反转后发生变化。 

这种方法实现了：

 -`O(n)`时间复杂度，因为每个节点被访问的次数是恒定的
 -`O(1)`额外的空间，因为只使用指针变量

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(k) 或 O(n) | 使用额外的存储来反转组 |
 | 最佳 | O(n) | O(1) | O(1) | 使用指针操作就地反转节点 |

 ## 算法演练

 ### 最佳就地反转算法

 1. 创建一个虚拟节点，其`next`指向原来的头部。 

这简化了第一组反转改变列表头部的边缘情况。 
2. 维护一个名为`group_prev`。 

该指针始终表示我们要反转的当前组之前的节点。 
3. 从中找到第k个节点`group_prev`。 

开始于`group_prev`, 前进`k`次。 如果我们无法到达第 k 个节点，则意味着少于`k`节点仍然存在，因此我们停止处理。 
4. 存储第k个节点之后的节点。 

该节点标记当前组的结束位置和下一组的开始位置。 我们称之为`group_next`。 
5. 反转当前组。 

使用标准链表反转技术：

 - 维护`prev`和`curr`- 指针一一反转
 - 一旦我们到达就停下来`group_next`During reversal:

 -`prev`开始为`group_next`-`curr`作为组中的第一个节点开始
 6. 重新连接颠倒的组。 

逆转后：

 - 第 k 个节点成为组的新头
 - 原来的第一个节点变成了尾部

 更新：

 -`group_prev.next`指向新组长
 - 移动`group_prev`到反转组的尾部
 7. 重复直到没有完整的组剩余。 

### 为什么它有效

 该算法保持了之前所有节点的不变性`group_prev`已经正确处理和连接。 每次迭代恰好反转一组有效的大小`k`不影响列表的其余部分。 由于每次反转都会正确地重新连接前边界和后边界，因此列表始终保持格式良好。 当少于`k`节点仍然存在，算法立即停止，保留剩余节点所需的顺序。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

from typing import Optional

class Solution:
    def reverseKGroup(
        self,
        head: Optional[ListNode],
        k: int
    ) -> Optional[ListNode]:

        dummy = ListNode(0)
        dummy.next = head

        group_prev = dummy

        while True:
            kth = group_prev

            # Find the kth node
            for _ in range(k):
                kth = kth.next
                if not kth:
                    return dummy.next

            group_next = kth.next

            # Reverse current group
            prev = group_next
            curr = group_prev.next

            while curr != group_next:
                temp = curr.next
                curr.next = prev
                prev = curr
                curr = temp

            # Reconnect reversed group
            temp = group_prev.next
            group_prev.next = kth
            group_prev = temp
```实现首先创建一个虚拟节点。 这避免了当第一个组反转更改列表头部时的特殊处理。 

变量`group_prev`始终指向当前组之前的节点。 我们反复搜索它前面的第 k 个节点。 如果第k个节点不存在，则剩余节点数小于`k`，因此算法终止。 

一旦识别出有效组，代码就会使用标准迭代反转技术执行就地反转。 关键技巧是初始化`prev`到`group_next`，在反转期间自动将反转组重新连接到剩余列表。 

反转完成后：

 -`kth`成为集团新任负责人
 - 原来的团头变成了团尾

 最后的重新连接步骤更新周围的指针并前进`group_prev`为下一次迭代做准备。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func reverseKGroup(head *ListNode, k int) *ListNode {
	dummy := &ListNode{Next: head}

	groupPrev := dummy

	for {
		kth := groupPrev

		// Find kth node
		for i := 0; i < k; i++ {
			kth = kth.Next
			if kth == nil {
				return dummy.Next
			}
		}

		groupNext := kth.Next

		// Reverse current group
		prev := groupNext
		curr := groupPrev.Next

		for curr != groupNext {
			temp := curr.Next
			curr.Next = prev
			prev = curr
			curr = temp
		}

		// Reconnect reversed group
		temp := groupPrev.Next
		groupPrev.Next = kth
		groupPrev = temp
	}
}
```Go 实现遵循与 Python 解决方案完全相同的逻辑。 主要差异与语法和指针处理有关。 

Go 使用显式指针类型，例如`*ListNode`，而 Python 则隐式引用对象。 在围棋中，`nil`需要检查而不是Python的`None`检查。 

由于 Go 使用静态类型，因此变量声明是显式的，并且内存引用更加可见。 除此之外，整体算法和指针操作策略是相同的。

 | --- | --- | --- |

不使用辅助数组、堆栈或递归调用，因此额外的内存使用量保持不变。

 ## 边缘情况

 ### 案例 1：`k = 1`什么时候`k`等于`1`，每一组仅包含一个节点。 反转单个节点不会执行任何操作，因此输出应与输入完全匹配。 

粗心的实现可能仍然会执行不必​​要的指针操作或意外中断链接。 此实现可以自然地处理这种情况，因为反转一组一个节点会使结构保持不变。 

### 情况 2：剩余节点数少于`k`假设列表是：```
1 -> 2 -> 3 -> 4 -> 5
```和`k = 3`。 

将前三个节点反转后，只剩下两个节点。 该问题明确指出这些剩余节点必须保持其原始顺序。 

该算法通过在尝试反转之前搜索第 k 个节点来安全地处理此问题。 如果少于`k`如果节点仍然存在，它会立即返回，而不修改列表的剩余部分。 

### 情况 3：整个列表长度相等`k`如果列表长度恰好等于`k`，整个列表应该反转一次。 

这是离一指针错误的常见来源，因为反转的组成为整个输出列表。 虚拟节点可以防止出现问题，因为它在头之前提供了一个稳定的节点，即使头发生变化，算法也可以正确地重新连接反向组。
