[LeetCode 第 79 题](https://leetcode.com/problems/word-search/)

 **难度：** 🟡 中等
 **主题：** 数组、字符串、回溯、深度优先搜索、矩阵

 ## 解决方案

 ## 问题理解

 在这个问题中，我们给出了一个二维字符网格，称为`board`和一个名为的目标字符串`word`。 任务是确定是否可以在一组严格的移动规则下通过遍历网格来形成单词。 

一个有效的词结构必须满足以下条件：

 - 您可以从板上的任何单元格开始。 
- 单词中的每个下一个字符必须来自水平或垂直相邻的单元格。 
- 不允许对角移动。 
- 单个单元格不能在同一单词路径中重复使用。 

输出是一个布尔值：

 - 返回`true`如果这个词可以形成的话。 
- 返回`false`否则。 

例如，假设黑板上包含字母：```
A B C E
S F C S
A D E E
```目标词是`"ABCCED"`。 

存在有效路径：```
A -> B -> C -> C -> E -> D
```其中每个移动都是水平或垂直的，并且没有重复使用任何单元格。 

约束很重要，因为它们指导预期的解决方案复杂性：

 -`1 <= m, n <= 6`- 棋盘尺寸最大为`6 x 6`，表示最多 36 个单元格。 
-`1 <= word.length <= 15`这些限制足够小，使得回溯和深度优先搜索是可行的。 然而，单纯的穷举搜索仍然会变得昂贵，因为每个字符可能分支到多个可能的方向。 

需要考虑一些重要的边缘情况：

 - 该板可能包含许多重复的字母，这会产生许多误导性的搜索路径。 
- 这个单词可能比棋盘上的单元格总数还要长，这立即使答案变得不可能。 
- 相同的字符可能会出现多次，因此算法必须正确跟踪访问过的单元格。 
- 路径可能部分匹配单词，然后失败，因此算法必须正确回溯。 
- 董事会可能包含大写和小写字母，比较区分大小写。 

## 方法

 ### 蛮力方法

 蛮力的想法是从板上的每个单元格开始尝试所有可能的路径。 

对于每个起始位置，我们通过向上、向下、向左或向右移动来递归地探索所有可能的路径。 在每一步中，我们都会检查当前单元格是否与单词中的相应字符匹配。 

如果我们成功匹配所有字符，答案是`true`。 如果所有可能的路径都失败，答案是`false`。 

这种方法是正确的，因为它详尽地探索了可能形成该词的每条有效路径。 

然而，强力方法变得昂贵，因为每个递归调用可以分支到多达四个方向。 可能的路径数量随着单词的长度呈指数增长。 

如果不进行剪枝，复杂度就会变得非常大。 

### 最优方法，使用 DFS 回溯

 关键的见解是这个问题自然地形成了一个递归搜索过程。 

对于单词中的每个字符，我们只需要考虑以下相邻单元格：

 - 保持在界限内
 - 匹配下一个所需的字符
 - 尚未在当前路径中使用

 这使得带有回溯的深度优先搜索成为理想的技术。 

回溯效果很好，因为：

 - 我们一次构建一条候选路径。 
- 如果路径无效，我们立即放弃它。 
- 我们在探索每条路径后恢复棋盘状态，以便其他搜索可以重用这些单元。 

我们还可以添加有用的修剪：

 - 如果当前单元格与目标字符不匹配，则立即停止。 
- 如果字长超过单元格总数，则返回`false`立即地。 

这大大减少了不必要的探索。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(m * n * 4^L) | O(L) | 递归尝试所有可能的路径 |
 | 最佳| O(m * n * 4^L) | O(L) | 带有剪枝和回溯的 DFS |

 这里：

-`m`是行数
 -`n`是列数
 -`L`是单词的长度

 尽管渐近复杂度看起来相同，但剪枝使实际运行时间更快。 

## 算法演练

 1. 首先，计算电路板的尺寸。 

在DFS遍历时我们需要行数和列数进行边界检查。 
2. 检查字长是否超过单元格数。 

如果`len(word) > rows * cols`，如果不重复使用单元格，这个词就不可能适合，所以我们返回`False`。 
3. 定义递归DFS 函数。 

DFS 功能将跟踪：

 - 当前行
 - 当前栏目
 - 单词中的当前索引

 这个函数回答了这个问题：

 “我们可以从这个单元格开始完成单词的剩余部分吗？”
 4. 处理成功的基本案例。 

如果当前索引等于单词长度，则意味着我们成功匹配了每个字符，因此返回`True`。 
5. 验证当前单元格。 

在继续之前，请验证：

 - 坐标在范围内
 - 单元格与当前目标字符匹配
 - 该牢房尚未被访问过

 如果任何条件不满足，则返回`False`。 
6. 将当前单元格标记为已访问。 

我们暂时用特殊标记替换该字符，例如`"#"`。 

这可以防止重新访问当前搜索路径内的同一单元。 
7. 探索所有四个方向。 

递归搜索：

 - 向上
 - 向下
 - 左
 - 右

 每个递归调用都会前进到单词中的下一个字符。 
8.恢复原来的性格。 

探索完各个方向后，恢复原来的棋盘值。 

这是回溯步骤。 它确保其他路径稍后可以重用该单元。 
9. 从每个板单元启动 DFS。 

由于这个词可能从任何地方开始，因此迭代整个板并从每个位置启动 DFS。 
10. 返回最终结果。 

如果任何 DFS 调用成功，则返回`True`。 否则返回`False`。 

### 为什么它有效

 该算法保持了一个重要的不变量：

 在每次递归调用时，当前路径与前缀完全匹配`word[0:index]`。 

仅当当前单元格正确匹配下一个所需字符时，DFS 才会继续。 回溯保证单元仅在不同的搜索路径中重用，而绝不会在同一路径内重用。 

由于该算法系统地探索所有有效路径，同时立即拒绝无效路径，因此它可以正确确定该单词是否存在于棋盘中。 

## Python 解决方案```python
from typing import List

class Solution:
    def exist(self, board: List[List[str]], word: str) -> bool:
        rows = len(board)
        cols = len(board[0])

        if len(word) > rows * cols:
            return False

        def dfs(row: int, col: int, index: int) -> bool:
            if index == len(word):
                return True

            if (
                row < 0
                or row >= rows
                or col < 0
                or col >= cols
                or board[row][col] != word[index]
            ):
                return False

            temp = board[row][col]
            board[row][col] = "#"

            found = (
                dfs(row + 1, col, index + 1)
                or dfs(row - 1, col, index + 1)
                or dfs(row, col + 1, index + 1)
                or dfs(row, col - 1, index + 1)
            )

            board[row][col] = temp

            return found

        for row in range(rows):
            for col in range(cols):
                if dfs(row, col, 0):
                    return True

        return False
```实施过程首先计算电路板尺寸。 这些值在整个 DFS 过程中重复使用以进行边界检查。 

早期剪枝条件检查单词是否长于单元格总数。 由于细胞不能重复使用，所以不可能构造这样的词。 

递归`dfs`函数处理核心搜索逻辑。 参数`index`表示单词中当前字符的位置。 

基本情况：```python
if index == len(word):
    return True
```表示整个单词已经匹配成功。 

边界和不匹配检查确保无效路径立即终止。 这种修剪对于提高效率至关重要。 

主板修改：```python
board[row][col] = "#"
```将单元格标记为已访问。 这避免了对单独的访问矩阵的需要并保持较低的空间复杂度。 

递归探索检查所有四个方向。 如果任何方向成功，结果就会变成`True`。 

最后，恢复了原来的性格。 此回溯步骤可确保该板在未来的搜索路径中保持不变。 

## 解决方案```go
func exist(board [][]byte, word string) bool {
    rows := len(board)
    cols := len(board[0])

    if len(word) > rows*cols {
        return false
    }

    var dfs func(int, int, int) bool

    dfs = func(row int, col int, index int) bool {
        if index == len(word) {
            return true
        }

        if row < 0 ||
            row >= rows ||
            col < 0 ||
            col >= cols ||
            board[row][col] != word[index] {
            return false
        }

        temp := board[row][col]
        board[row][col] = '#'

        found := dfs(row+1, col, index+1) ||
            dfs(row-1, col, index+1) ||
            dfs(row, col+1, index+1) ||
            dfs(row, col-1, index+1)

        board[row][col] = temp

        return found
    }

    for row := 0; row < rows; row++ {
        for col := 0; col < cols; col++ {
            if dfs(row, col, 0) {
                return true
            }
        }
    }

    return false
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

使用函数变量声明创建嵌套递归函数：```go
var dfs func(int, int, int) bool
```这允许函数递归地引用自身。 

该板使用`[][]byte`而不是单个字符的字符串，这使得就地修改变得简单。 

访问过的标记使用：```go
board[row][col] = '#'
```就像Python的解决方案一样。 

Go 在这里不需要对整数溢出进行特殊处理，因为所有索引在问题约束下仍然非常小。

class Solution:
    def exist(self, board: List[List[str]], word: str) -> bool:
        rows = len(board)
        cols = len(board[0])

        if len(word) > rows * cols:
            return False

        def dfs(row: int, col: int, index: int) -> bool:
            if index == len(word):
                return True

            if (
                row < 0
                or row >= rows
                or col < 0
                or col >= cols
                or board[row][col] != word[index]
            ):
                return False

            temp = board[row][col]

                dfs(row + 1, col, index + 1)
                or dfs(row - 1, col, index + 1)
                or dfs(row, col + 1, index + 1)
                or dfs(row, col - 1, index + 1)
            )

            board[row][col] = temp

            return found

        for row in range(rows):
            for col in range(cols):
                if dfs(row, col, 0):
                    return True

        return False

 ## 边缘情况

 ### 单词长于可用单元格

 当字长超过板单元总数时，就会出现一个非常重要的边缘情况。 

例如：```
board =
[
  ["A","B"],
  ["C","D"]
]

word = "ABCDE"
```黑板仅包含四个单元格，但该单词需要五个字符。 由于细胞不能重复使用，因此必须立即给出答案`False`。 

该实现通过以下方式有效地处理了这个问题：```
if len(word) > rows * cols:
    return False
```这种修剪避免了不必要的 DFS 探索。 

### 重复字符导致不正确的重用

 另一个常见的错误来源是意外地重新访问同一个单元格。 

考虑：```
board =
[
  ["A","B","C"]
]

word = "ABA"
```幼稚的实现可能会错误地重用第一个`"A"`。 

该解决方案通过临时标记已访问的单元格来防止这种情况：```
board[row][col] = "#"
```这保证了每个单元在当前路径中最多使用一次。 

### 大量回溯场景

 具有许多重复字母的主板可能会产生大量误导性路径。 

例子：```
board =
[
  ["A","A","A"],
  ["A","A","A"],
  ["A","A","A"]
]

word = "AAAAAAAAB"
```大部分单词匹配成功，但最后一个字符匹配失败。 

如果没有适当的回溯，算法可能会错过有效路径或损坏板状态。 

该实现在递归后恢复每个修改的单元格：```
board[row][col] = temp
```这确保每个 DFS 路径都以干净且正确的板状态开始。
