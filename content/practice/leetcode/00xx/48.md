 # 旋转图像

 ## 问题理解

 这个问题给了我们一个`n x n`表示图像的方阵。 矩阵中的每个元素对应于图像中的一个像素或值。 我们的任务是将整个图像顺时针旋转 90 度。 

重要的要求是轮换必须就地进行。 这意味着我们不允许创建另一个单独的`n x n`矩阵来存储旋转结果。 相反，我们必须直接修改现有矩阵。 

为了更清楚地理解转换，请考虑这个矩阵：```
1 2 3
4 5 6
7 8 9
```顺时针旋转90度后，结果变为：```
7 4 1
8 5 2
9 6 3
```注意模式：

 - 第一列按相反顺序成为第一行。 
- 第二列按相反顺序变为第二行。 
- 最后一行成为最后一列。 

这些约束告诉我们一些重要的事情：

 - 矩阵始终是方阵，这意味着行数等于列数。 
-`1 <= n <= 20`，所以矩阵相对较小。 
- 值可能是负数或正数，但实际的数字范围不会影响算法，因为我们只是重新排列位置。 

尽管约束足够小以至于暴力解决方案可以通过，但该问题明确需要就地解决方案。 这个要求才是真正的挑战。 

一些边缘情况很重要：

 - A`1 x 1`矩阵应保持不变。 
- A`2 x 2`矩阵是最小的非平凡旋转。 
- 奇数大小的矩阵包含一个永远不会移动的中心元素。 
- 偶数大小的矩阵完全通过分层交换进行旋转。 
- 负数和重复值仍必须正确旋转，因为算法仅取决于位置。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是创建第二个相同大小的矩阵，并将每个元素放置到其旋转位置。 

对于位置处的单元格`(row, col)`在原始矩阵中，其旋转位置变为：```
(col, n - 1 - row)
```使用此映射，我们可以用旋转值填充新矩阵，然后将内容复制回原始矩阵。 

这种方法很容易理解和实施。 每个元素只移动一次，因此算法是正确的。 

然而，该解决方案使用了额外的`n x n`矩阵，这需要`O(n²)`额外的空间。 该问题明确禁止分配另一个二维矩阵，因此这种方法不满足就地要求。 

### 最佳就地方法

 关键的见解是顺时针旋转可以分解为两个更简单的操作：

 1. 矩阵转置
 2.反转每一行

 转置交换行和列：```
matrix[row][col] ↔ matrix[col][row]
```转置后，行变成列。 

然后，反转每一行将方向更改为所需的顺时针旋转。 

例如：

 原文：```
1 2 3
4 5 6
7 8 9
```转置后：```
1 4 7
2 5 8
3 6 9
```反转行后：```
7 4 1
8 5 2
9 6 3
```该方法直接修改矩阵并且仅使用恒定的额外内存。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n²) | 使用附加矩阵来存储旋转值 |
 | 最佳 | O(n²) | O(1) | O(1) | 就地执行转置和行反转 |

 ## 算法演练

 1.确定矩阵大小`n`。 

由于矩阵是方阵，因此行和列具有相同的维度。 
2. 转置矩阵。 

对于每对索引`(row, col)`在哪里`col > row`， 交换：```
matrix[row][col] ↔ matrix[col][row]
```我们只处理矩阵的上三角形，因为交换两次会撤消更改。 

在此步骤之后，行变成列。 
3. 反转每行。 

对于矩阵中的每一行，就地反转元素。 

这会将转置矩阵转换为最终的顺时针旋转矩阵。 
4. 完成，不返回任何东西。 

直接修改了矩阵本身，满足了就地要求。 

### 为什么它有效

 转置运算反映矩阵的主对角线，将行位置转换为列位置。 反转每一行，然后水平重新排序元素，从而完成 90 度顺时针变换。 

这两个操作一起产生与移动每个元素完全相同的结果：```
(row, col) → (col, n - 1 - row)
```由于每次交换都直接在原始矩阵内执行，因此算法保持不变。 

## Python 解决方案```python
from typing import List

class Solution:
    def rotate(self, matrix: List[List[int]]) -> None:
        """
        Do not return anything, modify matrix in-place instead.
        """
        n = len(matrix)

        # Step 1: Transpose the matrix
        for row in range(n):
            for col in range(row + 1, n):
                matrix[row][col], matrix[col][row] = (
                    matrix[col][row],
                    matrix[row][col],
                )

        # Step 2: Reverse each row
        for row in matrix:
            row.reverse()
```该实现遵循前面描述的确切算法。 

首先，我们计算矩阵大小`n`。 

转置步骤使用嵌套循环。 外循环遍历行，而内循环从`row + 1`。 这确保我们只访问矩阵的上三角部分。 对角线上的每对对称元素都会被交换。 

接下来，我们使用 Python 的内置功能就地反转每一行`reverse()`方法。 这可以有效地重新排列每一行，而无需分配另一个矩阵。 

该函数不返回任何内容，因为 LeetCode 期望直接修改原始矩阵。 

## 解决方案```go
func rotate(matrix [][]int) {
	n := len(matrix)

	// Step 1: Transpose the matrix
	for row := 0; row < n; row++ {
		for col := row + 1; col < n; col++ {
			matrix[row][col], matrix[col][row] =
				matrix[col][row], matrix[row][col]
		}
	}

	// Step 2: Reverse each row
	for row := 0; row < n; row++ {
		left := 0
		right := n - 1

		for left < right {
			matrix[row][left], matrix[row][right] =
				matrix[row][right], matrix[row][left]

			left++
			right--
		}
	}
}
```Go 实现密切反映了 Python 逻辑。 

Go 没有像 Python 那样提供内置的行反转方法`reverse()`，因此我们使用两指针方法手动反转每一行。 一个指针从行的开头开始，另一个指针从行的末尾开始。 我们反复交换元素，直到指针相遇。 

不需要对整数溢出进行特殊处理，因为我们只交换现有值。 矩阵表示为切片的切片，所有修改都直接发生在输入结构上。

 ## 边缘情况

 一个`1 x 1`矩阵是最小的可能输入。 由于只有一个元素，旋转矩阵不会改变任何内容。 在处理非常小的矩阵时，某些实现会意外地尝试无效的交换或反转。 此实现可以自然地处理这种情况，因为两个循环都执行零有意义的操作。 

奇数大小的矩阵包含一个中心元素，该元素在旋转后应保持固定。 例如，在一个`3 x 3`矩阵，中间值永远不会改变位置。 不正确的索引计算可能会意外移动或覆盖该值。 转置和反转策略会自动保留中心元素，因为它映射到自身。 

具有重复值的矩阵可以隐藏逻辑错误。 例如，如果所有值都相同，则损坏的实现在视觉上可能仍然显示正确。 此实现完全依赖于索引转换而不是值比较，因此可以正确处理重复项而不会产生歧义。 

偶数大小的矩阵，例如`4 x 4`或者`6 x 6`没有中心枢轴元件。 每个值都会在旋转过程中参与移动。 转置操作期间不正确的循环边界可能会导致双重交换或跳过元素。 通过仅迭代哪里`col > row`，该实现保证每对恰好交换一次。
