 **难度：** 🔴难
 **主题：** 链表、分而治之、堆（优先级队列）、归并排序

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个数组`k`排序的链表。 每个链表都已按升序排序，我们的任务是将所有它们组合成一个已排序的链表。 

链表节点包含一个值和一个指向下一个节点的指针。 因此，输入不是正常的数组合并问题，因为我们无法直接索引到列表。 相反，我们必须顺序遍历节点。 

例如，如果我们给出：```
1 -> 4 -> 5
1 -> 3 -> 4
2 -> 6
```最终合并的链表应该是：```
1 -> 1 -> 2 -> 3 -> 4 -> 4 -> 5 -> 6
```关键的观察结果是每个单独的列表都已经排序。 我们应该利用这个属性，而不是收集所有值并从头开始重新排序。 

约束条件很重要：

 - 最多可以有`10^4`链表
 - 所有列表中的节点总数最多为`10^4`- 每个单独的列表都已排序

 这些约束告诉我们，解决方案必须有效地扩展列表数量和节点数量。 当以下情况时，天真的重复合并方法可能会变得低效：`k`很大。 

一些边缘情况很重要：

 -`lists`可能为空
 - 有些列表本身可能是空的
 - 所有列表可能为空
 - 链表可能只有一个
 - 值可以重复
 - 允许负数

 该问题保证每个单独的列表都按升序排序，这是实现高效合并技术的属性。 

## 方法

 ### 蛮力方法

 最简单的想法是将所有链表中的每个节点值收集到一个数组中，对数组进行排序，然后根据排序后的值重建一个新的链表。 

这种方法之所以有效，是因为对所有节点值进行全局排序可以保证最终顺序是正确的。 

该算法如下所示：

 1. 遍历每个链表
 2. 将每个值存储在数组中
 3. 对数组进行排序
 4. 根据排序后的值创建一个新的链表

 尽管正确，但该解决方案忽略了列表已排序的事实。 再次对所有值进行排序会带来不必要的工作。 

如果节点总数为`N`, 排序需要`O(N log N)`时间。 

### 最佳方法

 更好的解决方案使用最小堆，也称为优先级队列。 

关键的见解是我们只需要知道任何时刻所有列表中最小的当前节点。 

由于每个列表都已排序：

 - 列表中剩余的最小节点始终位于其头部
 - 我们可以将每个列表的当前头保留在最小堆中
 - 堆允许我们有效地检索全局最小的节点

 每次我们从堆中删除最小的节点：

 - 我们将其附加到结果中
 - 我们将该节点的下一个元素插入堆中

 这保证了堆始终包含最小的可用候选者。 

这种方法避免了对所有内容重新排序，并有效地将所有列表合并到`O(N log k)`时间，地点：

 -`N`是节点总数
 -`k`是链表的数量

 因为`k`通常比`N`，这显着提高了效率。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(N log N) | O(N log N) | O(N) | 收集所有值，对它们进行排序，重建列表 |
 | 最佳 | O(N log k) | O(N log k) | O(k) | 使用最小堆来跟踪最小的当前节点 |

 ## 算法演练

 ### 基于堆的合并算法

 1. 创建一个空的最小堆。 

堆将存储每个链表中当前最小的可用节点。 由于堆有效地返回最小元素，因此它们非常适合重复选择下一个最小节点。 
2、将每个非空链表的头节点插入堆中。 

此时堆最多包含`k`元素，每个列表中的一个。 
3. 为结果链表创建一个虚拟头节点。 

使用虚拟节点可以简化列表构造，因为我们避免了处理第一次插入的特殊情况。 
4. 反复从堆中提取最小的节点。 

堆保证提取的节点是所有列表中全局最小的剩余节点。 
5. 将提取的节点追加到结果链表中。 

连接节点后将结果指针向前移动。 
6. 如果提取的节点有下一个节点，则将该下一个节点插入到堆中。 

由于原始列表已排序，因此下一个节点将成为该列表中的下一个候选节点。 
7. 继续，直到堆变空。 

一旦堆为空，所有节点都已被处理并合并到结果中。 
8. 返回`dummy.next`。 

虚拟节点本身不是最终答案的一部分。 

### 为什么它有效

 该算法保持了一个重要的不变量：

 - 堆始终包含每个列表中最小的未处理节点。 

因为每个单独的列表都是排序的，所以一旦从列表中删除一个节点，该列表中的下一个节点就是该列表中下一个最小的候选节点。 

堆保证我们总是选择全局最小的可用节点，因此最终的合并列表是正确排序的。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

import heapq
from typing import List, Optional

class Solution:
    def mergeKLists(
        self,
        lists: List[Optional[ListNode]]
    ) -> Optional[ListNode]:

        min_heap = []

        for index, node in enumerate(lists):
            if node:
                heapq.heappush(min_heap, (node.val, index, node))

        dummy = ListNode(0)
        current = dummy

        while min_heap:
            _, index, node = heapq.heappop(min_heap)

            current.next = node
            current = current.next

            if node.next:
                heapq.heappush(
                    min_heap,
                    (node.next.val, index, node.next)
                )

        return dummy.next
```实现首先初始化一个最小堆。 蟒蛇的`heapq`模块有效地实现了二进制最小堆。 

每个堆条目包含：```python
(node.val, index, node)
```该值用于排序。 包含索引是因为Python无法直接比较`ListNode`当两个值相等时对象。 该指数充当决胜局。 

接下来，我们迭代所有链表并将每个非空头节点插入堆中。 

然后创建一个虚拟节点以简化结果列表构造。 这`current`指针始终指向合并列表中的最后一个节点。 

主循环内部：

 - 从堆中提取最小的节点
 - 该节点被附加到结果中
 - 如果该节点有后继节点，则将后继节点压入堆中

 这个过程一直持续到所有节点都被消耗为止。 

最后，`dummy.next`返回是因为虚拟节点本身只是一个占位符。 

## 解决方案```go
package main

import "container/heap"

/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */

type HeapNode struct {
	node *ListNode
}

type MinHeap []*ListNode

func (h MinHeap) Len() int {
	return len(h)
}

func (h MinHeap) Less(i, j int) bool {
	return h[i].Val < h[j].Val
}

func (h MinHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
}

func (h *MinHeap) Push(x interface{}) {
	*h = append(*h, x.(*ListNode))
}

func (h *MinHeap) Pop() interface{} {
	old := *h
	n := len(old)

	node := old[n-1]
	*h = old[:n-1]

	return node
}

func mergeKLists(lists []*ListNode) *ListNode {
	minHeap := &MinHeap{}
	heap.Init(minHeap)

	for _, node := range lists {
		if node != nil {
			heap.Push(minHeap, node)
		}
	}

	dummy := &ListNode{}
	current := dummy

	for minHeap.Len() > 0 {
		node := heap.Pop(minHeap).(*ListNode)

		current.Next = node
		current = current.Next

		if node.Next != nil {
			heap.Push(minHeap, node.Next)
		}
	}

	return dummy.Next
}
```Go 解决方案遵循与 Python 版本相同的算法逻辑，但 Go 需要显式实现堆接口`container/heap`包裹。 

习俗`MinHeap`类型定义：

 -`Len`-`Less`-`Swap`-`Push`-`Pop`Go 使用`nil`而不是Python的`None`，所以所有空列表检查都使用`nil`。 

与 Python 不同，Go 不需要平局索引，因为堆比较完全通过`Less`功能。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(N log k) | O(N log k) | N 个节点中的每一个都在堆中插入和删除一次 |
 | 空间| O(k) | 堆最多存储每个列表中的一个节点 |

 堆永远不会包含超过`k`元素，因为我们只从每个链表中保留一个活动候选节点。 

每次堆插入和删除操作的成本`O(log k)`，我们为每个节点执行一次这些操作。 

因此，总运行时间变为：```
O(N log k)
```这比对所有值进行全局排序要好得多`k`远小于`N`。

 ## 边缘情况

 ### 空输入数组

 一个重要的边缘情况是当`lists = []`。 

一种幼稚的实现可能假设至少存在一个链表并立即访问`lists[0]`，导致索引错误。 

此实现可以安全地处理这种情况，因为堆初始化循环根本不执行任何操作。 堆保持为空，主循环永远不会执行，算法正确返回`None`。 

### 仅包含空链表的列表

 另一个微妙的情况是：```
lists = [[], [], []]
```或等价：```
[None, None, None]
```一些实现意外地推送`None`到堆中，这会导致稍后比较失败。 

该解决方案明确检查：```
if node:
```在插入之前，因此只有有效的节点才会进入堆。 

### 列表中的重复值

 当多个列表包含相同的值时，Python 的堆实现会尝试比较下一个元组元素（如果第一个值相等）。 

如果没有决胜指数，Python 将尝试比较`ListNode`直接对象，提出`TypeError`。 

此实现通过存储来避免该问题：```
(node.val, index, node)
```即使节点值相同，整数索引也能保证元组保持可比较性。
