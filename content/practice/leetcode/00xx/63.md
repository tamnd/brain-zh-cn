[LeetCode 第 63 题](https://leetcode.com/problems/unique-paths-ii/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划、矩阵

 ## 解决方案

 ## 问题理解

 该问题要求我们计算机器人在避开障碍物的同时穿过网格时存在多少条不同的有效路径。 

机器人从网格的**左上角**位置开始`(0, 0)`并想要到达**右下角**位置`(m - 1, n - 1)`。 机器人只能向两个方向移动：

 - **对**
 - **向下**

 网格包含两种单元：

 -`0`代表机器人可以移动的开放空间。 
-`1`代表阻碍运动的障碍物。 

有效路径绝不能穿过障碍物。 

简单来说，我们需要确定有多少种独特的方式可以从起点移动到目的地，同时仅向右或向下移动并避开阻塞的单元格。 

输入是一个二维矩阵`obstacleGrid`有尺寸`m x n`， 在哪里：

-`m`是行数。 
-`n`是列数。 

预期输出是一个整数，表示唯一有效路径的数量。 

这些约束告诉我们一些重要的事情：

 -`1 <= m, n <= 100`，这意味着网格最多可以包含`10,000`细胞。 
- 由于暴力路径探索呈指数增长，我们需要更高效的东西。 
- 结果保证符合 32 位整数 (`<= 2 * 10^9`），所以整数溢出在Python中不是一个问题，并且在Go中使用它是安全的`int`。 

有几种重要的边缘情况很容易破坏简单的实现：

 - **起始位置可能包含障碍物**。 如果`grid[0][0] == 1`，立即有零个有效路径。 
- **目标单元格可能包含障碍物**。 如果`grid[m - 1][n - 1] == 1`，没有任何路径可以到达它。 
- 行或列可能会被完全阻塞，从而阻止进一步移动。 
- 小网格，例如`1 x 1`需要小心处理。 如果唯一的单元格是打开的，则答案是`1`。 如果被阻止，答案是`0`。 

这些边缘情况强烈建议使用结构化计数策略，而不是递归地探索每条路径。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是使用递归或深度优先搜索来探索每条可能的路径。 

开始于`(0, 0)`，我们递归地尝试：

 - 向右移动
 - 向下移动

 每当我们遇到障碍或出界时，我们就会停止探索那条路。 每当我们到达右下角时，我们就会计算出一条有效路径。 

这种方法是正确的，因为它明确枚举了每条可能的路线并仅计算有效的路线。 

然而，由于许多子问题重复出现，它变得非常慢。 例如，多条路线可能到达同一个单元格，每次我们都重新计算从该单元格到目的地的路径数。 

如果不进行优化，递归调用的数量会呈指数级增长。 

### 最佳解决方案的关键见解

 重要的观察结果是，到达某个单元格的方式数量仅取决于到达该单元格正上方的单元格及其左侧单元格的方式数量。 

如果单元格打开：$$dp[row][col] = dp[row - 1][col] + dp[row][col - 1]$$这是可行的，因为机器人只能**向下**或**向右**移动，这意味着进入单元的每条路径都必须来自这两个方向之一。 

如果单元格包含障碍物：$$dp[row][col] = 0$$因为没有任何路径可以通过它。 

这种重叠的子问题结构使**动态编程**成为理想的方法。 

我们可以构建一个 DP 表，其中每个条目存储到达该单元格的方式数量。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^(m+n)) | O(2^(m+n)) | O(m+n) | 递归探索每条可能的路径 |
 | 最优动态规划| O(m × n) | O(m × n) | 使用之前的结果计算每个单元格一次 |

 ## 算法演练

 ### 最优动态规划算法

 1. **处理不可能的启动条件**

 首先，检查起始单元格是否包含障碍物。 

如果`obstacleGrid[0][0] == 1`， 返回`0`立即，因为机器人甚至无法开始移动。 
2. **初始化DP表**

 创建一个`dp`与输入网格大小相同的矩阵。 

每个`dp[row][col]`代表达到该位置的独特方法的数量。 

最初，将所有内容填充为`0`。 
3. **初始化起始位置**

 由于机器人开始于`(0, 0)`， 放：```
dp[0][0] = 1
```这代表了一种站在起始单元的有效方式。 
4. **迭代每个单元格**

 逐行遍历网格。 

对于每个单元格：

 - 如果它包含障碍物，则将其值设置为`0`。 
- 否则，计算路径：

 - 顶部单元格
 - 左侧单元格
 5. **计算转换**

 对于每个打开的单元格`(row, col)`：

 - 添加上面的路径，如果`row > 0`- 从左侧添加路径，如果`col > 0`从概念上讲：```sql
dp[row][col] =
    paths from above +
    paths from left
```6. **返回最终答案**

 右下角的单元格存储有效路径的总数。 

返回：```
dp[m - 1][n - 1]
```### 为什么它有效

 该算法保持不变式`dp[row][col]`始终等于到达该位置的有效方式的数量。 

由于移动仅限于向右和向下，因此进入单元格的每条有效路径都必须来自两个位置之一：上方的单元格或左侧的单元格。 通过对那些已经计算出的值进行求和，我们可以正确地对每条可能的路线进行一次计数。 障碍物自然会贡献零路径，防止无效路径影响后续计算。 

因为我们从左上角到右下角处理网格，所以每个依赖项在需要之前就已经计算出来了。 

## Python 解决方案```python
from typing import List

class Solution:
    def uniquePathsWithObstacles(self, obstacleGrid: List[List[int]]) -> int:
        rows = len(obstacleGrid)
        cols = len(obstacleGrid[0])

        # If the starting cell is blocked, no path exists
        if obstacleGrid[0][0] == 1:
            return 0

        dp = [[0] * cols for _ in range(rows)]
        dp[0][0] = 1

        for row in range(rows):
            for col in range(cols):
                # Skip the starting cell
                if row == 0 and col == 0:
                    continue

                # Obstacle cell
                if obstacleGrid[row][col] == 1:
                    dp[row][col] = 0
                    continue

                paths_from_top = dp[row - 1][col] if row > 0 else 0
                paths_from_left = dp[row][col - 1] if col > 0 else 0

                dp[row][col] = paths_from_top + paths_from_left

        return dp[rows - 1][cols - 1]
```该实现紧密遵循前面描述的算法。 

我们首先计算网格尺寸，并立即处理起始位置被阻挡的情况。 如果机器人无法启动，答案是立即`0`。 

接下来，我们创建一个动态规划矩阵`dp`用零初始化。 起始位置已指定`1`，代表站在初始单元格的一种有效方式。 

然后我们逐行迭代网格。 对于每个位置：

 - 如果单元格被阻塞，我们分配`0`。 
- 否则，我们通过将顶部和左侧相邻单元格的路径数量相加来计算到达它的方式数量。 

条件表达式安全地处理第一行和第一列的边界条件，其中一个邻居可能不存在。 

最后，返回右下角的值，因为它包含到达目的地的有效路径的总数。 

## 解决方案```go
func uniquePathsWithObstacles(obstacleGrid [][]int) int {
	rows := len(obstacleGrid)
	cols := len(obstacleGrid[0])

	// If the starting cell is blocked
	if obstacleGrid[0][0] == 1 {
		return 0
	}

	dp := make([][]int, rows)
	for i := range dp {
		dp[i] = make([]int, cols)
	}

	dp[0][0] = 1

	for row := 0; row < rows; row++ {
		for col := 0; col < cols; col++ {
			// Skip starting cell
			if row == 0 && col == 0 {
				continue
			}

			// Obstacle cell
			if obstacleGrid[row][col] == 1 {
				dp[row][col] = 0
				continue
			}

			pathsFromTop := 0
			pathsFromLeft := 0

			if row > 0 {
				pathsFromTop = dp[row-1][col]
			}

			if col > 0 {
				pathsFromLeft = dp[row][col-1]
			}

			dp[row][col] = pathsFromTop + pathsFromLeft
		}
	}

	return dp[rows-1][cols-1]
}
```Go 实现遵循与 Python 版本相同的逻辑。 

分配一个二维切片来存储DP值。 由于 Go 不支持 Python 风格的列表推导式，因此必须使用以下命令单独初始化每一行`make`。 

在访问相邻小区之前，使用条件检查显式处理边界条件。 因为问题保证了答案在里面`2 * 10^9`，使用 Go 的`int`类型是安全的。 

与 Python 不同，Go 不区分`None`以及此问题中的空切片，因此不需要额外的 nil 处理，因为约束保证了有效的输入维度。

 ## 边缘情况

 ### 起始单元格被阻止

 如果`obstacleGrid[0][0] == 1`，机器人根本无法移动。 幼稚的实现可能仍将起始单元初始化为可到达，并意外地计算无效路径。 

此实现在任何计算之前显式检查起始单元并立即返回`0`。 

### 目标单元格被阻止

 如果右下角的单元格包含障碍物，则不可能达到目标。 

某些实现无法直接考虑这一点，并且可能会意外地将值传播到目标。 在此解决方案中，障碍物单元始终被分配`0`，那么目的地自然就变得无法到达了。 

### 单细胞网格

 一个`1 x 1`网格是一种特殊情况，因为机器人在同一位置开始和结束。 

如果唯一的单元格打开（`0`），只有一条有效路径，机器人只是停留在原处。 如果被阻止（`1`），路径为零。 

该实现通过初始化自然地处理这个问题：

 - 打开单元格 →`dp[0][0] = 1`- 阻塞的单元→立即返回`0`### 整个路径被阻塞

 有时，行或列的障碍物配置完全阻碍了进展。 

例如：```
[
    [0,1,0]
]
```机器人无法越过障碍物，因为运动仅限于向右和向下。 

DP 逻辑在被阻止的单元之后正确地传播零，确保不可能的区域仍然无法到达。
