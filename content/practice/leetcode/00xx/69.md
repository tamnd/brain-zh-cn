[LeetCode 第 69 题](https://leetcode.com/problems/sqrtx/)

 **难度：** 🟢简单
 **主题：** 数学、二分查找

 ## 解决方案

 ## 问题理解

 该问题要求我们计算非负整数的**整数平方根**`x`。 更具体地说，我们需要返回最大的整数`k`这样：$$k^2 \leq x$$这意味着我们并不是在寻找精确的小数平方根。 相反，我们必须**向下舍入**到最接近的整数。 例如，平方根`8`大约是`2.828`，但由于我们向下舍入，答案变成`2`。 

输入是单个整数`x`， 在哪里：$$0 \leq x \leq 2^{31} - 1$$输出是另一个非负整数，表示平方根的下限值。 

一个重要的限制是我们**不能使用内置的求幂或平方根函数**。 这意味着像这样的方法`math.sqrt(x)`,`pow(x, 0.5)`， 或者`x ** 0.5`被禁止。 我们必须通过算法得出结果。 

约束条件告诉我们`x`可以大到`2,147,483,647`，超过二十亿。 这立即表明幼稚的迭代可能会变得低效。 检查每个数字的解决方案`1`对于大的输入，向上可能需要太多的操作。 

有几个重要的边缘情况需要预先考虑：

 - 如果`x = 0`，平方根正好是`0`。 
- 如果`x = 1`，平方根正好是`1`。 
- 如果`x`是一个**完全平方**，例如`4`,`9`， 或者`16`，我们应该返回精确的根。 
- 如果`x`**不是**一个完美的正方形，例如`8`或者`15`，我们必须返回其平方仍然小于的最大整数`x`。 
- 附近非常大的输入`2^31 - 1`在某些语言中计算时可能会产生整数溢出问题`mid * mid`，特别是在具有固定大小整数的语言中。 

由于这些限制和边缘情况，我们需要一种高效且谨慎的方法。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是尝试从以下位置开始的每个整数`0`并不断检查它的平方，直到平方变得大于`x`。 

例如，如果`x = 8`：

 -`0² = 0`-`1² = 1`-`2² = 4`-`3² = 9`在此刻，`3²`超过`8`，所以答案一定是`2`。 

这种方法是正确的，因为我们按升序检查数字，并在超过有效范围时停止。 前一个数字保证是最大的有效整数。 

然而，这种方法对于大量输入来说效率很低。 在最坏的情况下，我们可能需要检查大约：$$\sqrt{x}$$数字。 自从`x`可以超过二十亿，这变得不必要的昂贵。 

### 最优方法，二分搜索

 关键的观察结果是答案空间是**排序的**。 

如果我们选择一些数字`mid`：

- 如果`mid² < x`，那么所有较小的数字也是有效的候选者。 
- 如果`mid² > x`，那么所有较大的数字都无效。 
- 如果`mid² == x`，我们找到了精确的平方根。 

这种单调行为使该问题成为**二分搜索**的完美候选者。 

我们不是检查每个数字，而是反复将搜索空间分成两半。 我们在之间搜索`0`和`x`，缩小范围，直到确定平方不超过的最大有效整数`x`。 

由于二分搜索每一步将搜索间隔减半，因此运行时间变为对数。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(√x) | O(1) | O(1) | 逐步检查每个可能的根 |
 | 最佳 | O(log x) | O(1) | O(1) | 在答案空间上使用二分搜索 |

 ## 算法演练

 ### 最优算法，二分搜索

 1. 立即处理小边缘情况。 

如果`x`是`0`或者`1`， 返回`x`直接因为平方根就是数字本身。 
2. 定义搜索边界。 

初始化：

 -`left = 1`-`right = x`我们知道平方根一定位于这个范围内。 
3. 跟踪最佳有效答案。 

创建一个变量`answer = 0`。 

这存储了迄今为止找到的最大数字，其平方小于或等于`x`。 
4. 计算中点。 

在每次迭代时：$$mid = left + (right - left) // 2$$这可以避免某些语言中的溢出问题。 
5. 比较`mid²`和`x`。 

有以下三种可能：

 - 如果`mid² == x`， 返回`mid`立即因为我们找到了精确的平方根。 
- 如果`mid² < x`,`mid`是有效的候选人。 保存在`answer`并搜索右半部分以查看是否存在更大的有效根。 
- 如果`mid² > x`,`mid`太大了，所以搜索左半部分。 
6. 继续缩小搜索空间。 

重复直到`left > right`。 
7. 返回存储的答案。 

如果不存在精确的平方根，`answer`包含平方小于的最大有效整数`x`。 

### 为什么它有效

 该算法之所以有效，是因为平方函数对于非负整数是单调的。 如果`n²`太小，那么每个较小的数字也太小。 如果`n²`太大，则每个更大的数也必定太大。 二分搜索利用了这种有序属性，并保证我们永远不会丢弃正确的答案。 通过存储最新的有效候选者，我们确保即使平方根是无理数，我们仍然返回正确的下限值。 

## Python 解决方案```python
class Solution:
    def mySqrt(self, x: int) -> int:
        if x < 2:
            return x

        left, right = 1, x
        answer = 0

        while left <= right:
            mid = left + (right - left) // 2
            square = mid * mid

            if square == x:
                return mid
            elif square < x:
                answer = mid
                left = mid + 1
            else:
                right = mid - 1

        return answer
```实现从处理最小的边缘情况开始。 如果`x`小于`2`，我们立即返回它，因为两者`0`和`1`是他们自己的平方根。 

接下来，我们初始化二分搜索范围`1`到`x`。 在搜索间隔保持有效的同时，我们计算中点并计算其平方。 

如果正方形完全匹配`x`，我们立即返回中点，因为我们找到了精确的平方根。 

当正方形小于`x`，中点成为有效候选点，因此我们将其存储在`answer`。 然而，我们继续向右搜索，因为更大的有效平方根可能仍然存在。 

当平方超过`x`，中点太大，所以我们将搜索空间缩小到左半部分。 

如果循环结束时没有完全匹配，则存储的`answer`被返回。 这保证了平方根的正确下限值。 

## 解决方案```go
func mySqrt(x int) int {
    if x < 2 {
        return x
    }

    left, right := 1, x
    answer := 0

    for left <= right {
        mid := left + (right-left)/2
        square := mid * mid

        if square == x {
            return mid
        } else if square < x {
            answer = mid
            left = mid + 1
        } else {
            right = mid - 1
        }
    }

    return answer
}
```Go 实现遵循与 Python 解决方案相同的二分搜索逻辑。 Go 中的一个重要考虑因素是整数溢出。 尽管 LeetCode 的约束可以安全地适合 Go 的约束`int`在支持的系统上，使用：```go
mid := left + (right-left)/2
```仍然是首选，因为它避免了可能发生的潜在溢出`(left + right) / 2`在具有严格整数限制的语言中。 

除了语法差异之外，逻辑保持不变。

空间复杂度是恒定的，因为无论输入大小如何，该算法仅存储几个整数变量。

 ## 边缘情况

 ### 输入是`0`最小可能的输入是`0`。 幼稚的实现可能会意外进入二分搜索循环并执行不必要的工作。 由于平方根为`0`正是`0`，执行立即返回`x`什么时候`x < 2`。 

### 输入是`1`

`1`是另一个特殊情况，因为它的平方根恰好是它本身。 如果没有显式处理，算法仍然可以工作，但是提前返回可以避免不必要的迭代并简化正确性。 

### 非完美平方

 输入如`8`,`15`， 或者`26`很重要，因为真正的平方根不是整数。 有缺陷的实现可能会错误地向上舍入或无法跟踪最后一个有效的候选者。 这个实现通过存储解决了这个问题`answer`每当`mid² < x`。 这确保我们始终返回正确的下限值。 

### 非常大的输入

 值接近`2^31 - 1`计算时可能会暴露溢出问题`mid * mid`。 有些语言如果处理不当可能会溢出。 二分查找中点计算：```
left + (right - left) / 2
```避免中点溢出，并且约束确保乘法在 Python 和 Go 中保持可管理性。
