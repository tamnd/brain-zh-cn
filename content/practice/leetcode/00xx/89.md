 # LeetCode 89 - 格雷码

 ## 问题理解

 该问题要求我们为给定的位数生成有效的格雷码序列，`n`。 

格雷码序列是一种特殊的数字排序，其中每个相邻对在二进制形式中仅相差一位。 此外，该序列是循环的，这意味着第一个和最后一个数字也必须恰好相差一位。 

对于一个`n-bit`格雷码：

 - 正好有`2^n`不同的数字。 
- 每个数字必须介于`0`和`2^n - 1`。 
- 序列必须以`0`。 
- 任何数字只能出现一次。 
- 连续的数字必须相差一位二进制位。 

输入`n`表示每个二进制数中可用的位数。 例如：

 - 如果`n = 2`，有效数字范围为`0`到`3`。 
- 如果`n = 3`，有效数字范围为`0`到`7`。 

输出可以是任何有效的格雷码排序。 可能存在多个正确答案。 

限制相对较小：

 -`1 <= n <= 16`这意味着最大序列大小为：$$2^{16} = 65536$$生成所有数字是完全可行的，但如果实施不当，指数暴力搜索仍然会太昂贵。 这个问题强烈暗示存在一种数学构造或位操作技巧可以直接有效地生成格雷码。 

一些边缘情况很重要：

 -`n = 1`，最小可能的输入
 - 较大的值，例如`n = 16`，低效的回溯可能变得不切实际
 - 确保第一个和最后一个元素也恰好有一位不同
 - 避免重复的数字

 该问题保证了有效输入，因此我们不需要处理负值或零。 

## 方法

 ### 蛮力方法

 强力解决方案将尝试使用回溯增量构建序列。 

这个想法是：

 1. 开始于`0`2. 尝试每个未使用的号码
 3.检查是否与之前的数字正好相差一位
 4.继续递归，直到全部`2^n`使用数字
 5. 最后验证最后一个数字与第一个数字是否相差一位

 要确定两个数字是否相差一位，我们可以使用 XOR：$$a \oplus b$$如果结果恰好包含一组位，则数字相差一位。 

这种方法是正确的，因为它探索所有可能的有效序列，直到满足格雷码条件。 

然而，搜索空间很快就会变得巨大。 有潜在的`(2^n)!`在最坏情况下探索的排列。 即使进行了修剪，对于较大的值来说这也是不切实际的`n`。 

### 最佳方法

 关键的见解是格雷码有一个直接的数学公式。 

对于一个号码`i`，其格雷码表示为：$G(i)=i\oplus(i\gg1)$这个公式之所以有效，是因为移位`i`右一位对齐相邻的二进制位，异或突出显示发生变化的位置。 

得到的序列自然满足格雷码属性：

 - 相邻的数字恰好相差一位
 - 所有号码都是唯一的
 - 序列开始于`0`- 序列是循环的

 我们不寻找有效的排序，而是直接在线性时间内构造一个。

 ## 算法演练

 ### 最优算法

 1. 计算所需的格雷码总数。 

自从`n-bit`序列包含所有可能的`n-bit`只数一次，我们需要：$$2^n$$价值观。 
2. 初始化一个空的结果列表。 

该列表将按顺序存储生成的格雷码。 
3. 迭代自`0`到`2^n - 1`。 

每个整数`i`对应于格雷码序列中的一个位置。 
4. 转换`i`转化为格雷码表示形式。 

使用公式：$gray=i\oplus(i\gg1)$这里：

-`i >> 1`将所有位右移一位
 - XOR 比较相邻位位置
 - 结果在连续值之间仅改变一位
 5. 将格雷码值添加到结果列表中。 

由于该公式保证了唯一性和正确的邻接性，因此不需要额外的验证。 
6. 返回完成的列表。 

处理所有值后，结果包含有效的格雷码序列。 

### 为什么它有效

 该公式之所以有效，是因为连续整数在可预测的二进制模式中有所不同。 当我们将一个数字与其本身右移一位进行异或时，所得的转换可确保连续值之间只有一个输出位发生变化。 

这种结构在整个序列中保留了格雷码属性，包括从最后一个元素回到第一个元素的过渡。 

## Python 解决方案```python
from typing import List

class Solution:
    def grayCode(self, n: int) -> List[int]:
        result = []
        
        total_numbers = 1 << n
        
        for number in range(total_numbers):
            gray = number ^ (number >> 1)
            result.append(gray)
        
        return result
```实现首先使用计算所需值的总数`1 << n`，它计算`2^n`有效地进行位移位。 

然后我们迭代每个整数`0`到`2^n - 1`。 

对于每个值，我们应用格雷码公式：```python
gray = number ^ (number >> 1)
```右移对齐相邻位，异或产生变换后的格雷码值。 

每个生成的格雷码都附加到结果列表中。 由于公式保证了正确性，因此我们不需要额外的重复检查或邻接验证。 

最后，返回完成的序列。 

## 解决方案```go
func grayCode(n int) []int {
    totalNumbers := 1 << n
    
    result := make([]int, 0, totalNumbers)
    
    for number := 0; number < totalNumbers; number++ {
        gray := number ^ (number >> 1)
        result = append(result, gray)
    }
    
    return result
}
```Go 的实现与 Python 解决方案非常相似。 

使用以下方法创建具有预分配容量的切片：```go
make([]int, 0, totalNumbers)
```这减少了追加期间的重新分配。 

Go 中的位运算对于非负整数的行为与 Python 类似，因此相同的格雷码公式直接适用。 

自从`n <= 16`，整数溢出在 Go 中不是一个问题。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(2^n) | O(2^n) | 我们只生成每个格雷码一次 |
 | 空间| O(2^n) | O(2^n) | 输出列表存储所有生成的值 |

 该算法对每个所需的数字只处理一次。 每次迭代仅执行恒定时间位操作，使得运行时间与输出大小成线性关系。 

空间复杂度也是线性的，因为结果数组必须存储所有`2^n`格雷码。

def differs_by_one_bit(a: int, b: int) -> bool:
    xor_value = a ^ b
    return xor_value != 0 and (xor_value & (xor_value - 1)) == 0

def validate_gray_code(sequence: List[int], n: int) -> bool:
    expected_size = 1 << n
    
    if len(sequence) != expected_size:
        return False
    
    if sequence[0] != 0:
        return False
    
    if len(set(sequence)) != expected_size:
        return False
    
    for i in range(expected_size):
        current_value = sequence[i]
        next_value = sequence[(i + 1) % expected_size]
        
        if not differs_by_one_bit(current_value, next_value):
            return False
    
    return True

 ## 边缘情况

 ### 尽可能最小的输入

 当`n = 1`，序列仅包含两个数字：```
[0, 1]
```这种情况很重要，因为某些实现意外地假设至少存在两个位位置。 即使对于单个位，基于公式的方法也能自然地发挥作用。 

### 最大约束

 当`n = 16`，序列包含`65536`数字。 递归回溯方法可能会变得非常慢或消耗过多的内存。 

直接的数学构造完全避免了这个问题，因为每个值都是在恒定时间内独立生成的。 

### 循环邻接要求

 一个常见的错误是仅验证数组内的相邻元素，而忘记第一个和最后一个元素也必须有一位不同。 

格雷码公式本质上会产生循环序列，因此无需额外逻辑即可自动满足此条件。 

### 重复值

 不正确的位操作可能会意外地产生重复的值，从而违反唯一性要求。 

公式：$G(i)=i\oplus(i\gg1)$在整数和格雷码之间创建一对一的映射，保证整个序列的唯一性。
