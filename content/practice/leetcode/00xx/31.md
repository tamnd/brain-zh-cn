[LeetCode 第 31 题](https://leetcode.com/problems/next-permutation/)

 **难度：** 🟡 中等
 **主题：** 数组、两个指针

 ## 解决方案

 ## 问题理解

 该问题要求我们修改一个整数数组，使其成为当前排列的下一个字典顺序更大的排列。 

排列只是元素的排序。 词典顺序的工作方式与词典顺序对单词的工作方式相同。 比较两个数组时，我们从左到右比较元素，直到找到第一个差异。 该位置数字较大的数组被认为较大。 

例如：

-`[1,2,3] < [1,3,2]`-`[1,3,2] < [2,1,3]`任务是将给定的数组转换为该排序序列中的下一个排列。 

如果当前的排列已经是最大可能的排列，比如`[3,2,1]`，则没有更大的排列可用。 在这种情况下，我们必须回绕到尽可能小的排列，即升序排列。 

一个非常重要的限制是修改必须就地进行。 我们不允许分配与输入大小成比例的另一个数组。 只能使用恒定的额外内存。 

输入大小相对较小，最多 100 个元素，但排列数量呈阶乘增长。 即使对于适度的数组大小，生成所有排列在计算上也是不可行的。 这意味着我们需要直接的数学或结构观察，而不是暴力生成。 

一些边缘情况很重要：

 - 数组已经按降序排列，例如`[5,4,3,2,1]`- 具有重复值的数组，例如`[1,1,5]`- 长度为1的数组
 - 仅最后两个元素需要交换的数组
 - 必须重新排列大后缀的数组

 该问题保证所有值都是整数并且数组长度至少为 1。 

## 方法

 ### 蛮力方法

 强力解决方案将生成数组的每种可能的排列，按字典顺序对它们进行排序，找到当前的排列，然后选择下一个排列。 

这是有效的，因为字典顺序完全定义了排列序列。 一旦生成并排序了所有排列，找到下一个排列就变得很简单。 

然而，这种方法效率极低。 长度的数组`n`有`n!`排列。 即使是为了`n = 10`，这已经超过了 300 万种排列。 内存和运行时间成本很快就会变得巨大。 

此外，该问题明确需要持续的额外内存和就地修改，而暴力解决方案违反了这一点。 

### 最佳方法

 关键的见解是我们不需要生成所有排列。 

相反，我们可以通过观察排列如何演变来直接构建下一个字典顺序更大的排列。 

从右到左考虑数组。 如果后缀严格递减，则该后缀已经是这些元素的最大可能排列。 要创建更大的排列，我们必须修改该后缀之前的某些内容。 

该算法的工作原理是：

 1. 找到序列右边第一个停止递减的位置
 2. 将该值与其右侧的下一个较大值交换
 3.反转后缀，使其尽可能小

 这会产生仍然大于原始排列的最小排列。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n! × n) | O(n! × n) | O(n! × n) | O(n! × n) | 生成并排序所有排列 |
 | 最佳| O(n) | O(1) | O(1) | 直接就地查找下一个排列 |

 ## 算法演练

 ### 逐步算法

 1. 从右向左遍历数组，找到主元索引。 

我们寻找第一个索引`i`这样：```
nums[i] < nums[i + 1]
```这标识了数组仍可以增加的第一个位置。 

该位置右侧的所有内容均形成递减后缀，这意味着它已经是这些元素的最大可能排列。 
2. 如果不存在主元，则反转整个数组。 

如果数组是完全递减的，比如`[3,2,1]`，那么它已经是最大排列了。 

因此，按字典顺序排列的下一个排列必须环绕到最小排列。 

反转整个数组会产生升序。 
3. 找到枢轴的最右后继者。 

从数组末尾开始，找到第一个大于的元素`nums[pivot]`。 

由于后缀是递减的，因此从右侧遇到的第一个较大元素是最小的有效替换。 
4. 交换枢轴和后继者。 

这会增加排列，同时尽可能少地更改数组。 
5. 反转枢轴后的后缀。 

后缀目前按降序排列。 交换后，我们需要尽可能最小的后缀排列，以确保我们得到立即的下一个排列，而不是向前跳过。 

反转将其转换为升序。 

### 为什么它有效

 递减的后缀代表这些元素的最大可能排列。 枢轴是我们仍然可以使排列变得更大的第一个地方。 

将枢轴更换为最小的较大元件可确保增量最小。 之后反转后缀可确保剩余元素以尽可能小的顺序排列。 

这些运算共同产生字典顺序上最大的最小排列，这正是下一个排列。 

## Python 解决方案```python
from typing import List

class Solution:
    def nextPermutation(self, nums: List[int]) -> None:
        """
        Do not return anything, modify nums in-place instead.
        """

        n = len(nums)

        # Step 1: Find the pivot
        pivot = n - 2

        while pivot >= 0 and nums[pivot] >= nums[pivot + 1]:
            pivot -= 1

        # Step 2: If pivot exists, find successor and swap
        if pivot >= 0:
            successor = n - 1

            while nums[successor] <= nums[pivot]:
                successor -= 1

            nums[pivot], nums[successor] = nums[successor], nums[pivot]

        # Step 3: Reverse the suffix
        left = pivot + 1
        right = n - 1

        while left < right:
            nums[left], nums[right] = nums[right], nums[left]
            left += 1
            right -= 1
```实现首先从右到左搜索主元索引。 枢轴是从右向左观察时序列增加的第一个位置。 

如果没有找到主元，则数组完全递减，这意味着它已经是最大的排列。 在这种情况下，反转整个数组会将其转换为最小排列。 

如果存在主元，代码会查找大于主元值的最右边元素。 由于后缀是递减的，这保证了最小的有效增量。 

交换后，使用两个指针就地反转后缀。 这会将递减后缀转换为升序，确保生成的排列是紧邻的下一个词典排列。 

该算法仅使用恒定的额外内存，因为所有操作都直接发生在原始数组内。 

## 解决方案```go
func nextPermutation(nums []int) {
	n := len(nums)

	// Step 1: Find pivot
	pivot := n - 2

	for pivot >= 0 && nums[pivot] >= nums[pivot+1] {
		pivot--
	}

	// Step 2: Find successor and swap
	if pivot >= 0 {
		successor := n - 1

		for nums[successor] <= nums[pivot] {
			successor--
		}

		nums[pivot], nums[successor] = nums[successor], nums[pivot]
	}

	// Step 3: Reverse suffix
	left := pivot + 1
	right := n - 1

	for left < right {
		nums[left], nums[right] = nums[right], nums[left]
		left++
		right--
	}
}
```Go 实现遵循与 Python 版本相同的逻辑。 

Go 切片是对底层数组的可变引用，因此修改会自动就地发生。 不需要额外的数组分配。 

与Python不同的是，Go没有内置切片的反转操作，因此后缀反转是通过两个指针手动实现的。 

整数溢出不是问题，因为该算法仅比较和交换现有值。

 ## 边缘情况

 ### 完全递减数组

 像这样的输入`[5,4,3,2,1]`已经是最大可能的排列。 幼稚的实现可能会失败，因为没有枢轴索引`nums[i] < nums[i+1]`。 

该算法通过检测不存在主元并反转整个数组来处理此问题。 这正确地产生了最小的排列，`[1,2,3,4,5]`。 

### 具有重复值的数组

 如果选择了错误的后继元素，重复的值可能会产生微妙的错误。 

例如：```
[1,5,1]
```该算法专门从右侧搜索大于主元的第一个值。 这保证了最小的有效增加，并且即使有重复也能保持词典编排的正确性。 

### 单元素数组

 仅包含一个元素的数组已经表示最小和最大排列。 

某些实现在搜索枢轴时会意外访问无效索引。 该解决方案安全地初始化了主元索引，并且在数组长度为1时自然地跳过了不必要的操作。 

### 大递减后缀

 输入如：```
[1,4,3,2]
```包含长递减后缀。 

一个常见的错误是对后缀进行排序而不是反转它。 由于后缀保证已经是降序排列，因此反转就足够了并且更有效。 

该实现正确地使用了两指针反转，保持`O(n)`运行时间和恒定的额外空间。
