 # LeetCode 68 - 文本对齐

 ## 问题理解

 这个问题要求我们模拟使用完全对齐时文本编辑器中文本的格式。 我们得到一个单词数组和一个目标线宽，称为`maxWidth`。 目标是将这些单词排列成多行，使得每行都包含准确的内容`maxWidth`人物。 

关键的挑战不仅仅是将单词放入行中，而是正确分配空间。 除最后一行外，每一行都必须完全合理。 完全对齐意味着线条的左右边界完美对齐。 为了实现这一点，单词之间的空格必须尽可能均匀地分布。 

该问题指定了贪婪的打包策略。 这意味着对于每一行，我们应该在移动到下一行之前放置尽可能多的单词。 一旦形成一条线，我们就确定剩余多少空格并将它们分布在单词之间的间隙中。 

有三个重要的格式规则：

 1. 每行必须准确无误`maxWidth`人物。 
2、对于普通的线路，间距应尽可能均匀分布。 如果空间不能均匀划分，则最左边的间隙会获得额外的空间。 
3. 最后一行必须始终左对齐，这意味着单词之间用一个空格分隔，所有剩余的空格都附加到末尾。 

输入包括：

 -`words`：字符串数组，其中每个字符串都是一个非空单词。 
-`maxWidth`：一个整数，指定每行的确切宽度。 

输出是一个字符串列表，其中每个字符串代表一个对齐的行。 

限制相对较小：

 - 至多`300`话
 - 最大字长`20`- 最大宽度`100`这些限制表明`O(n²)`解决方案可能仍然会通过，但问题强烈暗示了贪婪的线性模拟方法。 由于单词数量很少，并且每个单词只能处理有限的次数，因此`O(n)`或者`O(n * maxWidth)`解决方案是理想的。 

一些边缘情况使这个问题变得棘手。 一行可能只包含一个单词，在这种情况下，它必须左对齐，因为没有间隙可以分布空格。 最后一行的行为总是不同的，并且永远不能完全合理。 另一种微妙的情况是，当空间没有均匀地划分在间隙之间时，需要向左侧放置额外的空间。 

## 方法

 ### 蛮力方法

 暴力方法将尝试生成所有可能的方法将单词划分为行，然后评估哪个划分满足调整规则。 

对于每个可能的单词分组，我们将计算线宽是否适合`maxWidth`，分配空间，并检查有效性。 由于每个单词可以保留在当前行或开始一个新行，因此分区的数量呈指数级增长。 

这种方法是正确的，因为它探索了每种可能的排列并最终找到有效的格式。 然而，它的效率极低，因为随着单词数量的增加，行组合的数量变得巨大。 

即使只有几百个字，指数探索也是完全不切实际的。 

### 最优贪婪模拟

 关键的见解是，这个问题明确指示我们贪婪地打包单词。 由于我们总是需要在当前行中放置尽可能多的单词，因此单词的分组方式不会有任何歧义。 

这一观察消除了回溯或动态规划的需要。 

该过程变为：

 1、贪婪地收集一行字。 
2. 计算所需的总空间。 
3、按规则分配空间。 
4. 移至下一行。 

对于包含多个单词的非最终行，我们在间隙之间均匀划分空格。 如果有剩余空间，则从左到右分配。 

对于仅包含一个单词的行或最后一行，我们只需左对齐即可。 

因为每个单词都被处理一次，所以这会产生有效的线性解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 探索单词到行的多种可能划分 |
 | 最优贪心模拟 | O(n) | O(n) | 贪婪地形成每一行并直接分配空间|

 ## 算法演练

 ### 第 1 步：贪婪地迭代单词

 维护索引`i`代表当前行的开始。 

从这个位置开始，贪婪地包含尽可能多的单词，同时确保行长度不超过`maxWidth`。 

我们追踪：

 - 当前行单词的总长度
 - 包含的字数

 当添加另一个单词超出时我们停止`maxWidth`。 

这个贪婪的步骤是正确的，因为这个问题明确要求我们打包尽可能多的单词。 

### 第 2 步：确定这是否是特殊情况

 收集一行单词后，检查是否：

 - 这是最后一行，或者
 - 该行仅包含一个单词

 这些情况会受到不同的处理，因为它们必须左对齐。 

我们不是均匀分布空格，而是在单词之间放置一个空格，并在末尾填充剩余的空格。 

### 步骤 3：计算规则线的空间分布

 如果这不是最后一行并且包含多个单词，则计算：

 -`totalSpaces = maxWidth - totalWordLength`-`gaps = numberOfWords - 1`我们均匀地划分空间：

 -`spacesPerGap = totalSpaces // gaps`-`extraSpaces = totalSpaces % gaps`余数代表不能均匀分布的空间。 根据问题陈述，多余的空格位于最左边的间隙中。 

### 第 4 步：构建生产线

 构造线串。 

对于每个单词：

 - 附加这个词。 
- 在其后添加空格。 

如果当前间隙指数小于`extraSpaces`，添加一个额外的空格。 

这保证了最左边的间隙首先收到额外的空间。 

### 第 5 步：移至下一行

 将构造的行追加到结果列表中。 

放`i`到下一个未处理单词的开头并重复。 

### 为什么它有效

 正确性来自两个属性。 

首先，贪婪打包规则保证每行包含最大可能的单词数，这是问题明确要求的。 

其次，间距公式确保剩余空间的准确数量均匀分布。 整数除法保证每个间隙的空格数，而余数则确保将额外的空格分配给最左边的位置。 对单字行和最后一行的特殊处理与问题规范完全匹配。 

因此，每条生成的行都满足所需的格式规则。 

## Python 解决方案```python
from typing import List

class Solution:
    def fullJustify(self, words: List[str], maxWidth: int) -> List[str]:
        result = []
        n = len(words)
        index = 0

        while index < n:
            line_start = index
            line_length = 0

            # Greedily fit as many words as possible
            while (
                index < n
                and line_length + len(words[index]) + (index - line_start)
                <= maxWidth
            ):
                line_length += len(words[index])
                index += 1

            line_words = words[line_start:index]
            word_count = len(line_words)

            # Last line or single word -> left justified
            if index == n or word_count == 1:
                line = " ".join(line_words)
                remaining_spaces = maxWidth - len(line)
                line += " " * remaining_spaces
                result.append(line)
                continue

            # Fully justify
            total_spaces = maxWidth - line_length
            gaps = word_count - 1

            spaces_per_gap = total_spaces // gaps
            extra_spaces = total_spaces % gaps

            line = []

            for i in range(gaps):
                line.append(line_words[i])

                spaces = spaces_per_gap
                if i < extra_spaces:
                    spaces += 1

                line.append(" " * spaces)

            line.append(line_words[-1])

            result.append("".join(line))

        return result
```实现严格遵循算法。 

我们首先使用索引指针迭代单词。 对于每一行，我们贪婪地确定可以容纳多少个单词。 表达式：```python
line_length + len(words[index]) + (index - line_start)
```计算下一个单词是否适合。 这里：

-`line_length`存储单词的总字符数
 -`len(words[index])`是候选词的长度
 -`(index - line_start)`考虑单词之间所需的最小空格

 确定线边界后，我们检查该线是否特殊。 

如果它是最后一行或仅包含一个单词，我们使用左对齐`" ".join()`并在右侧填充空格。 

否则，我们计算空间应该如何分布。 整数除法确定空格的基数，而模数确定最左边间隙的剩余空格。 

最后，我们使用字符串列表有效地构建该行`"".join()`以避免重复的字符串连接开销。 

## 解决方案```go
func fullJustify(words []string, maxWidth int) []string {
	var result []string
	n := len(words)
	index := 0

	for index < n {
		lineStart := index
		lineLength := 0

		// Greedily fit words
		for index < n &&
			lineLength+len(words[index])+(index-lineStart) <= maxWidth {
			lineLength += len(words[index])
			index++
		}

		lineWords := words[lineStart:index]
		wordCount := len(lineWords)

		// Last line or single word
		if index == n || wordCount == 1 {
			line := ""

			for i, word := range lineWords {
				if i > 0 {
					line += " "
				}
				line += word
			}

			for len(line) < maxWidth {
				line += " "
			}

			result = append(result, line)
			continue
		}

		// Fully justify
		totalSpaces := maxWidth - lineLength
		gaps := wordCount - 1

		spacesPerGap := totalSpaces / gaps
		extraSpaces := totalSpaces % gaps

		line := ""

		for i := 0; i < gaps; i++ {
			line += lineWords[i]

			spaces := spacesPerGap
			if i < extraSpaces {
				spaces++
			}

			for j := 0; j < spaces; j++ {
				line += " "
			}
		}

		line += lineWords[wordCount-1]
		result = append(result, line)
	}

	return result
}
```Go 实现遵循与 Python 解决方案相同的逻辑，但适应了 Go 的字符串处理。 

与 Python 不同，Go 不提供内置的等效项`" ".join()`对于这种精确格式化场景中的切片，因此我们手动构建字符串。 

切片自然用于`lineWords`，整数除法的行为与均匀分布空间的要求完全相同。 

不存在整数溢出问题，因为最大宽度仅为`100`。

 ## 边缘情况

 ### 一行中的单个单词

 仅包含一个单词的行可能会成为错误的来源，因为单词之间没有空间分布的间隙。 一个幼稚的实现可能会在计算每个间隙的空间时除以零。 

实现明确检查：```
word_count == 1
```在本例中，该单词左对齐并用尾随空格填充。 

### 最后一行格式

 最后一行的行为与之前所有行不同。 单词之间必须恰好有一个空格分隔，而不是均匀分布空格。 

一个常见的错误是不小心对最后一行应用了完整的对齐方式，从而产生了不正确的间距。 

实施检测到：```
index == n
```并切换到左对齐。 

### 空间分布不均匀

 当间隙之间的空间分配不均匀时，多余的空间必须移至最左边的间隙。 

例如：```
["a", "b", "c"], width = 6
```要求：```
"a  b c"
```而不是：```
"a b  c"
```该实现使用以下方式正确处理此问题：```
if i < extra_spaces:
    spaces += 1
```这保证了左偏分布。 

### 完全填满宽度的单词

 有时一组单词加上所需的最小空间就可以完美填充`maxWidth`。 

例如：```
["abc", "def"], width = 7
```该实现正确地认识到不需要额外的空格并生成：```
"abc def"
```没有不必要的尾部填充。
