[LeetCode 第 76 题](https://leetcode.com/problems/minimum-window-substring/)

 **难度：** 🔴难
 **主题：** 哈希表、字符串、滑动窗口

 ## 解决方案

 ## 问题理解

 该问题要求我们找到字符串中最小的连续子串`s`包含字符串中的每个字符`t`，包括重复出现的情况。 

子字符串必须由连续的字符组成。 我们不允许对字符重新排序或跳过位置。 该窗口必须包含每个必需的字符，其出现频率至少相同`t`。 

例如，如果：```
t = "AABC"
```那么一个有效的窗口必须包含：

 - 两个`'A'`- 一`'B'`- 一`'C'`像这样的窗口`"ABC"`无效，因为它只包含一个`'A'`。 

The input consists of two strings:

 -`s`，我们搜索窗口的源字符串
 -`t`，定义所需字符的目标字符串

 预期输出是最短的子串`s`满足所有要求。 如果不存在这样的子字符串，我们返回一个空字符串。 

约束条件很重要：

 -`1 <= m, n <= 10^5`- 两个字符串都可以很大

 这立即告诉我们，具有二次或三次复杂度的算法将不够快。 我们需要接近线性时间的东西。 

有几个重要的边缘情况：

 -`t`可能包含重复字符
 -`s`可能短于`t`- 可能不存在有效窗口
 - 最小窗口可能是整个字符串
 - 可能有很多有效的窗口，但答案保证是唯一的
 - 大写和小写字母是不同的字符

 当正确处理重复计数时，幼稚的实现通常会失败。 例如：```
s = "AAABBC"
t = "AABC"
```一个有效的窗口必须包含两个`'A'`，不只是一个。 

## 方法

 ### 蛮力方法

 蛮力方法是生成每个可能的子串`s`并检查该子字符串是否包含以下所有字符`t`。 

对于每个起始索引`i`，我们可以尝试每个结束索引`j`并计算子串：```
s[i:j+1]
```对于每个子字符串，我们计算字符频率并将它们与`t`。 

这是可行的，因为最终会检查每个可能的子字符串，因此会找到最小的有效子字符串。 

然而，性能极差。 

有`O(m^2)`子字符串，验证每个子字符串可以花费`O(m)`如果我们重复计算频率，则时间。 整体复杂度可以变为`O(m^3)`在最坏的情况下。 

即使进行了优化，速度仍然太慢`m = 10^5`。 

### 最优滑动窗口方法

 关键的观察是我们不需要重复地重新计算每个子字符串的信息。 

相反，我们可以使用两个指针来维护一个移动窗口：

 - 左指针
 - 右指针

 当右侧指针展开窗口时，我们将字符添加到频率图中。 

一旦当前窗口变得有效，这意味着它包含所有必需的字符，我们会尝试从左侧缩小它，同时保持有效性。 

这是有效的，因为：

 - 扩大窗口增加可用字符
 - 缩小窗口有助于最小化答案
 - 每个角色最多进入和离开窗口一次

 这导致`O(m + n)`解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 氧气（立方米）| O(1) 到 O(k) | 重复检查所有子字符串 |
 | 最佳| O(m + n) | O(k) | 带频率计数的滑动窗口|

 这里：

-`m = len(s)`-`n = len(t)`-`k`是不同字符的数量

 ## 算法演练

 1. 创建字符串的频率图`t`。 

该映射存储每个字符必须在有效窗口中出现的次数。 

例子：```
t = "AABC"
```变成：```
{
    'A': 2,
    'B': 1,
    'C': 1
}
```2. 为当前窗口初始化另一个频率图。 

这会跟踪字符当前出现在活动子字符串中的次数。 
3.维护两个指针：

 -`left`, 窗口的开始
 -`right`, 窗口的末端

 最初两者都开始于`0`。 
4. 通过移动扩大窗口`right`。 

每一步：

 - 添加`s[right]`进入窗口地图
 - 检查该字符现在是否满足所需频率之一
 5. 跟踪当前满足了多少角色要求。 

认为：```
required = number of distinct characters in t
```我们还维护：```
formed = number of distinct characters currently satisfied
```在以下情况下，角色被视为满意：```
window_count[char] == target_count[char]
```6. 一旦满足所有要求，当前窗口即有效。 

出现这种情况时：```
formed == required
```7. 尝试从左侧缩小窗口。 

当窗口仍然有效时：

 - 如果当前窗口较小，则更新最佳答案
 - 删除`s[left]`从窗口
 - 如果删除它破坏了所需的频率，则减少`formed`- 移动`left`前进
 8. 继续扩展右指针，直到处理完整个字符串。 
9. 返回找到的最佳窗口。 

如果不存在有效窗口，则返回`""`。 

### 为什么它有效

 该算法保持一个不变量：

 - 每当`formed == required`，当前窗口包含具有正确频率的所有必需字符

 仅当窗口已经有效时，左指针才会移动，这保证了所考虑的每个候选者都是有效的。 通过贪婪地缩小，我们确保检查每个右边界的最小有效窗口。 

因为每个字符最多被处理两次，一次进入窗口，一次离开窗口，所以算法以线性时间运行。 

## Python 解决方案```python
from collections import Counter, defaultdict

class Solution:
    def minWindow(self, s: str, t: str) -> str:
        if len(t) > len(s):
            return ""

        target_count = Counter(t)
        window_count = defaultdict(int)

        required = len(target_count)
        formed = 0

        left = 0

        best_length = float("inf")
        best_start = 0

        for right in range(len(s)):
            char = s[right]
            window_count[char] += 1

            if (
                char in target_count
                and window_count[char] == target_count[char]
            ):
                formed += 1

            while formed == required:
                current_length = right - left + 1

                if current_length < best_length:
                    best_length = current_length
                    best_start = left

                left_char = s[left]
                window_count[left_char] -= 1

                if (
                    left_char in target_count
                    and window_count[left_char] < target_count[left_char]
                ):
                    formed -= 1

                left += 1

        if best_length == float("inf"):
            return ""

        return s[best_start:best_start + best_length]
```实现从处理最简单的不可能的情况开始。 如果`t`长于`s`，不能存在有效的子字符串。`Counter(t)`存储每个字符所需的频率。 一个`defaultdict(int)`用于当前窗口，因此缺少的键会自动默认为零。 

变量`required`存储必须满足多少个不同的字符。 变量`formed`跟踪活动窗口中当前有多少人感到满意。 

这`right`指针一次将窗口展开一个字符。 每当字符频率完全等于其所需计数时，我们就会递增`formed`。 

一旦窗口生效，内部`while`循环尝试从左侧缩小它。 收缩过程中：

 - 我们更新了最佳答案
 - 我们减少左边的字符数
 - 我们检测窗口是否再次变得无效

 处理过程中遇到的最小有效窗口使用以下方式存储：

 -`best_length`-`best_start`最后我们返回对应的子字符串。 

## 解决方案```go
func minWindow(s string, t string) string {
	if len(t) > len(s) {
		return ""
	}

	targetCount := make(map[byte]int)
	for i := 0; i < len(t); i++ {
		targetCount[t[i]]++
	}

	windowCount := make(map[byte]int)

	required := len(targetCount)
	formed := 0

	left := 0

	bestLength := len(s) + 1
	bestStart := 0

	for right := 0; right < len(s); right++ {
		char := s[right]
		windowCount[char]++

		if count, exists := targetCount[char]; exists &&
			windowCount[char] == count {
			formed++
		}

		for formed == required {
			currentLength := right - left + 1

			if currentLength < bestLength {
				bestLength = currentLength
				bestStart = left
			}

			leftChar := s[left]
			windowCount[leftChar]--

			if count, exists := targetCount[leftChar]; exists &&
				windowCount[leftChar] < count {
				formed--
			}

			left++
		}
	}

	if bestLength == len(s)+1 {
		return ""
	}

	return s[bestStart : bestStart+bestLength]
}
```Go 实现遵循与 Python 解决方案相同的逻辑，但使用`map[byte]int`而不是字典。 

由于输入仅包含英文字母，因此按字节索引既安全又高效。 

Go 没有内置`Counter`或者`defaultdict`结构，因此使用常规映射来代替。 访问时丢失的键会自动默认为零。 

使用切片语法返回子字符串结果：```go
s[start:end]
```这里不存在整数溢出问题，因为所有索引都保留在字符串范围内。

 ## 边缘情况

 一种重要的边缘情况发生在以下情况：`t`包含重复字符。 许多错误的解决方案只检查字符是否存在，而不检查它们的频率。 例如：```
s = "ABC"
t = "AABC"
```即使所有不同的字母都出现，该窗口也是无效的，因为两个`'A'`字符是必需的。 该实现通过使用哈希映射比较精确的频率计数来正确处理这个问题。 

当不存在有效窗口时，会出现另一个重要的边缘情况。 这可能发生在以下情况：`s`短于`t`，或者当所需字符完全丢失时。 该算法自然地处理这个问题，因为`formed`永远达不到`required`，因此不会记录任何答案。 在这种情况下，该函数返回一个空字符串。 

区分大小写也很重要。 大写和小写英文字母被视为不同的字符。 例如：```
s = "aA"
t = "Aa"
```该算法正确区分`'a'`和`'A'`因为哈希映射使用确切的字符作为键。 

缩小窗口时会出现最后一个微妙的边缘情况。 如果我们删除一个完全满足要求的字符，则该窗口立即变得无效。 该实现会仔细检测这种情况：```
window_count[left_char] < target_count[left_char]
```这确保算法永远不会错误地将无效窗口视为有效窗口。
