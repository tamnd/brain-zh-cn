 # LeetCode 53，最大子数组

 ## 问题理解

 问题给出一个整数数组`nums`并要求我们找到一个具有最大可能总和的连续子数组。 子数组意味着元素必须在原始数组中彼此相邻出现。 我们不允许任意重新排列元素或跳过位置。 

输出不是子数组本身，而是任何连续子数组可以产生的最大和。 

例如，在数组中：```
[-2,1,-3,4,-1,2,1,-5,4]
```最佳连续段是：```
[4,-1,2,1]
```其总和为：```
4 + (-1) + 2 + 1 = 6
```所以答案是`6`。 

约束条件很重要：

 - 数组长度可以大到`10^5`- 值可以是正数、负数或零

 由于输入可以包含十万个元素，因此任何慢于线性或接近线性时间的算法都变得不切实际。 二次解的执行情况约为`10^10`在最坏的情况下，操作速度太慢了。 

一个重要的细节是数组始终包含至少一个元素。 这意味着我们永远不需要处理空数组。 

一些边缘情况尤其重要：

 - 仅包含负数的数组
 - 仅包含正数的数组
 - 具有单个元素的数组
 - 最优子数组出现在中间的数组
 - 重新启动子数组比扩展子数组更好的数组

 幼稚的实现通常会在所有负数组上失败，因为它错误地假设答案永远不应该为负。 但是，如果每个数字都是负数，则正确答案是最小负数单个元素。 

## 方法

 ### 蛮力方法

 蛮力方法考虑每个可能的连续子数组并计算其总和。 

对于长度的数组`n`， 有：```
n * (n + 1) / 2
```可能的子数组。 

我们可以生成每个起始索引和每个结束索引，然后计算它们之间的元素之和。 在执行此操作时，我们会跟踪迄今为止看到的最大总和。 

这种方法是正确的，因为它详尽地检查了每个可能的连续子数组。 由于最佳答案必须是这些子数组之一，因此算法保证能找到它。 

然而，对于给定的约束，这种方法太慢了。 即使使用前缀和优化，检查所有子数组也需要`O(n^2)`时间，这是不可行的`n = 10^5`。 

### 最优方法，Kadane 算法

 关键的观察结果是，在构建子数组时，负的运行和是有害的。 

假设我们当前正在处理一个元素`nums[i]`。 

我们有两个选择：

 1.扩展之前的子数组
 2. 在当前元素处开始一个新的子数组

 如果之前的运行总和为负，则延长它只会使当前的总和变得更糟。 在这种情况下，最好放弃以前的子数组并从当前元素重新开始。 

这一见解引出了卡丹算法。 

在每个位置，我们计算：

 - 以当前索引结尾的最大子数组和
 - 迄今为止最好的全球最大值

 这使我们能够通过数组一次解决问题。

 ## 算法演练

 ### Kadane 算法

 1. 使用数组的第一个元素初始化两个变量。`current_sum`表示以当前位置结束的最大子数组和。`max_sum`表示迄今为止在任何地方找到的最佳子数组总和。 

我们将两者初始化为`nums[0]`因为数组保证至少包含一个元素。 
2. 从索引开始迭代数组`1`。 

对于每个元素，决定是否更好：

 - 仅使用当前元素开始一个新的子数组
 - 扩展前一个子数组
 3. 更新`current_sum`。 

递推关系为：$\text{current\_sum} = \max(\text{nums}[i],\ \text{current\_sum} + \text{nums}[i])$这意味着：

 - 如果之前的运行总和有害，请重新启动
 - 否则，扩展现有子数组
 4. 更新`max_sum`。 

计算出以当前索引结尾的最佳子数组后，将其与迄今为止看到的全局最佳答案进行比较。$\text{max\_sum} = \max(\text{max\_sum},\ \text{current\_sum})$5. 继续，直到处理完整个数组。 
6. 返回`max_sum`。 

### 为什么它有效

 该算法保持了一个重要的不变量：

 -`current_sum`始终存储以当前索引结尾的最大可能子数组和。 
-`max_sum`始终存储迄今为止在数组中任何位置看到的最大子数组和。 

在每一步，算法都会在重新启动或扩展之间做出局部最优选择。 因为任何负前缀只能减少未来的总和，所以丢弃它总是安全的。 这保证了算法永远不会错过全局最优子数组。 

## Python 解决方案```python
from typing import List

class Solution:
    def maxSubArray(self, nums: List[int]) -> int:
        current_sum = nums[0]
        max_sum = nums[0]

        for i in range(1, len(nums)):
            current_sum = max(nums[i], current_sum + nums[i])
            max_sum = max(max_sum, current_sum)

        return max_sum
```实现首先初始化两个`current_sum`和`max_sum`到第一个元素。 这很重要，因为数组可能只包含负数，因此初始化为`0`会产生不正确的结果。 

循环从索引开始`1`因为第一个元素已经用于初始化。 

在循环内部，算法决定是否继续现有子数组或在当前元素处开始一个新子数组。 该逻辑是通过以下方式实现的：```python
current_sum = max(nums[i], current_sum + nums[i])
```然后使用以下方法更新全局答案：```python
max_sum = max(max_sum, current_sum)
```处理完所有元素后，`max_sum`包含最大的子数组和。 

## 解决方案```go
func maxSubArray(nums []int) int {
    currentSum := nums[0]
    maxSum := nums[0]

    for i := 1; i < len(nums); i++ {
        if currentSum+nums[i] > nums[i] {
            currentSum = currentSum + nums[i]
        } else {
            currentSum = nums[i]
        }

        if currentSum > maxSum {
            maxSum = currentSum
        }
    }

    return maxSum
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 

Go 不提供内置的`max`函数用于整数，因此使用显式条件语句。 

该问题保证至少有一个元素，因此访问`nums[0]`是安全的。 

由于约束相对较小，标准 Go`int`值足够并且不存在整数溢出的风险。

 ## 边缘情况

 ### 所有数字均为负数

 全负数组是最常见的错误来源之一。 一个幼稚的实现可能会初始化答案`0`，这会错误地表明不允许选择任何元素。 

例如：```
[-3,-2,-5]
```正确答案是`-2`， 不是`0`。 

该实现通过初始化两者来正确处理这个问题`current_sum`和`max_sum`到第一个数组元素而不是零。 

### 单元素数组

 最小的有效输入恰好包含一个数字。 

例如：```
[7]
```该算法应立即返回`7`。 

因为初始化使用第一个元素并且循环从索引处开始`1`，实现自然地处理这种情况，无需特殊逻辑。 

### 大负前缀

 有时，数组的开头包含会减少未来总和的值。 

例如：```
[-100, 5, 6]
```扩展前缀会产生：```
-89
```这比从头开始更糟糕`5`。 

Kadane 算法使用以下方法正确丢弃有害前缀：```
current_sum = max(nums[i], current_sum + nums[i])
```这确保算法始终保留以当前位置结尾的最佳子数组。
