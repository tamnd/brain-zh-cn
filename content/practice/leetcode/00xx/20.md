[LeetCode 第 20 题](https://leetcode.com/problems/valid-parentheses/)

 **难度：** 🟢简单
 **主题：** 字符串、堆栈

 ## 解决方案

 ## 问题理解

 该问题给出一个仅包含六个可能字符的字符串：`(`,`)`,`{`,`}`,`[`和`]`。 每个左括号最终必须与正确的右括号匹配，并且匹配的顺序很重要。 

仅当每个左括号都由相同类型的括号封闭且嵌套顺序正确时，字符串才被视为有效。 这意味着括号的行为类似于嵌套容器。 例如，`"([])"`有效，因为方括号在括号关闭之前完全打开和关闭。 然而，`"([)]"`无效，因为平仓订单与开仓订单不匹配。 

输入表示一系列括号运算。 左括号开始一个新的嵌套范围，而右括号尝试关闭最近打开的范围。 预期输出是一个布尔值：

 -`true`如果整个字符串遵循有效的匹配规则
 -`false`否则

 约束告诉我们字符串长度可以大到`10^4`。 这对于线性时间解决方案来说足够小，可以舒适地运行，但又足够大，以至于低效地重复重新扫描或重建字符串会产生不必要的开销。 

一些边缘情况很重要：

 - 右括号出现在任何左括号之前，例如`"]"`，立即无效。 
- 不匹配的一对，例如`"(]"`必须被正确检测。 
- 正确的嵌套很重要，所以`"([)]"`即使计数匹配也是无效的。 
- 末尾留下额外的左括号，例如`"((("`，使字符串无效。 
- 该问题保证字符串仅包含括号字符，因此我们不需要处理字母、数字或空格。 

## 方法

 ### 蛮力方法

 暴力策略反复从字符串中删除有效的相邻括号对。 例如，如果字符串包含`"()"`,`"[]"`， 或者`"{}"`，这些子串可以被删除。 此过程一直持续到字符串变空或无法再进行删除为止。 

例如：

-`"([])"`变成`"()"`-`"()"`变成`""`- 空字符串表示有效

 这是有效的，因为当匹配对被逐层删除时，每个有效的嵌套结构最终都会减少为空字符串。 

然而，这种方法效率低下，因为每次删除操作都会创建一个新字符串，并且需要重新扫描剩余字符。 在最坏的情况下，该算法多次重复遍历几乎整个字符串，导致时间复杂度为二次。 

### 最佳方法

 关键的见解是括号验证自然遵循后进先出行为。 最近打开的括号必须始终是第一个关闭的。 

这正是堆栈的行为。 

每当我们遇到左括号时，我们都会将其压入堆栈，因为稍后它仍然需要匹配的右括号。 当我们遇到右括号时，我们检查它是否与堆栈中最近的不匹配的左括号匹配。 

如果在任何时候匹配失败，则该字符串立即无效。 处理完整个字符串后，堆栈必须为空，字符串才有效。 

这使我们能够通过字符串的单次传递来解决问题。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 反复从字符串 | 中删除匹配对
 | 最佳 | O(n) | O(n) | 使用堆栈来跟踪不匹配的左括号 |

 ## 算法演练

 1. 创建一个堆栈来存储尚未匹配的左括号。 
2. 创建一个哈希映射，将每个右括号映射到其对应的左括号。 这允许恒定时间匹配检查。 
3. 迭代字符串中的每个字符。 
4. 如果当前字符是左括号，则将其压入堆栈，因为稍后必须匹配它。 
5、如果当前字符是右括号，首先检查栈是否为空。 如果为空，则没有可匹配的左括号，因此返回`False`。 
6. 否则，从堆栈中弹出顶部元素。 这代表了最近的无与伦比的开局。 
7. 将弹出的左括号与哈希图中预期的左括号进行比较。 如果不匹配，则返回`False`。 
8. 继续处理，直到检查完所有字符。 
9. 循环结束后，检查栈是否为空。 如果任何左括号仍然不匹配，则返回`False`。 否则，返回`True`。 

### 为什么它有效

 该算法保持了一个重要的不变量：堆栈始终包含不匹配的左括号，其顺序与它们必须关闭的确切顺序相同。 由于括号必须以与打开相反的顺序结束，因此最近打开的括号必须始终首先匹配。 堆栈自动强制执行此排序。 如果每个右括号都正确匹配并且堆栈末尾为空，则每个括号对都正确匹配和排序。 

## Python 解决方案```python
class Solution:
    def isValid(self, s: str) -> bool:
        stack: list[str] = []

        bracket_map = {
            ')': '(',
            ']': '[',
            '}': '{'
        }

        opening_brackets = {'(', '[', '{'}

        for char in s:
            if char in opening_brackets:
                stack.append(char)
            else:
                if not stack:
                    return False

                top = stack.pop()

                if top != bracket_map[char]:
                    return False

        return len(stack) == 0
```实现首先创建一个空堆栈。 该堆栈存储左括号，但仍需要在字符串中稍后匹配右括号。 

这`bracket_map`字典将每个右括号映射到它期望的左括号。 这使得匹配变得高效，因为我们可以直接将当前的右括号与最近的左括号进行比较。 

这`opening_brackets`set 允许快速检查当前字符是否是左括号。 

当算法迭代字符串时：

 - 左括号被推入堆栈。 
- 右括号触发验证逻辑。 

当处理右括号时，算法首先确保堆栈不为空。 空堆栈意味着没有可匹配的左括号。 

接下来，算法弹出最近的左括号并将其与预期的匹配进行比较`bracket_map`。 如果括号不匹配，则该字符串立即无效。 

最后，处理完所有字符后，堆栈必须为空。 任何剩余的左括号表示不完全匹配。 

## 解决方案```go
func isValid(s string) bool {
    stack := []rune{}

    bracketMap := map[rune]rune{
        ')': '(',
        ']': '[',
        '}': '{',
    }

    openingBrackets := map[rune]bool{
        '(': true,
        '[': true,
        '{': true,
    }

    for _, char := range s {
        if openingBrackets[char] {
            stack = append(stack, char)
        } else {
            if len(stack) == 0 {
                return false
            }

            top := stack[len(stack)-1]
            stack = stack[:len(stack)-1]

            if top != bracketMap[char] {
                return false
            }
        }
    }

    return len(stack) == 0
}
```Go解决方案遵循与Python实现相同的逻辑，但使用切片来实现堆栈。 向切片追加内容会压入堆栈，而切掉最后一个元素则执行弹出操作。 

Go 没有 Python 风格的集合，所以`map[rune]bool`用于表示左括号的集合。 

该算法使用`rune`而不是`byte`为了字符处理的清晰性和正确性，尽管这个特定问题仅包含 ASCII 字符。

 ## 边缘情况

 当右括号出现在任何左括号之前时，就会出现一种重要的边缘情况，例如`"]"`或者`")("`。 幼稚的实现可能会尝试从空堆栈中弹出，从而导致错误。 此实现在尝试弹出之前显式检查堆栈是否为空。 如果栈为空，函数立即返回`False`。 

另一个关键的边缘情况涉及不正确的嵌套顺序。 字符串像`"([)]"`包含每个括号类型的匹配计数，但排序无效。 简单的计数解决方案会错误地接受此输入。 基于堆栈的方法正确地拒绝它，因为最近不匹配的左括号必须与当前右括号匹配。 

当处理结束时左括号保持不匹配时，会出现第三种重要的边缘情况，例如`"((("`或者`"(()"`。 一些实现错误地返回`True`处理完所有字符后不检查剩余的空位。 此实现通过确保返回之前堆栈为空来避免该错误`True`。 

最后的边缘情况涉及深度嵌套的有效表达式，例如`"{{[[(())]]}}"`。 该实现自然地处理了这个问题，因为堆栈保留了正确匹配所需的确切嵌套顺序。
