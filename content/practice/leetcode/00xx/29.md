[LeetCode 第 29 题](https://leetcode.com/problems/divide-two-integers/)

 **难度：** 🟡 中等
 **主题：** 数学、位操作

 ## 解决方案

 ## 问题理解

 该问题要求我们实现整数除法，而不使用标准算术运算符进行乘法、除法或取模。 我们有两个整数，`dividend`和`divisor`，我们必须计算被除数除以除数得到的商。 

结果必须截断为零。 这意味着任何小数部分都将被丢弃而不是四舍五入。 例如：

-`10 / 3 = 3.333...`，截断为`3`-`7 / -3 = -2.333...`，截断为`-2`该问题还引入了与 32 位有符号整数相关的重要约束。 有效范围是：$$[-2^{31}, 2^{31} - 1]$$对应于：$$[-2147483648, 2147483647]$$如果计算出的商超出这个范围，我们必须限制结果：

 - 大于`2147483647`变成`2147483647`- 小于`-2147483648`变成`-2147483648`这些约束告诉我们一些重要的事情：

 - 输入大小是恒定的，因为整数仅限于 32 位。 
- 在最坏的情况下，简单的重复减法方法可能仍然太慢。 
- 溢出处理至关重要，特别是对于：$$-2^{31} \div -1$$因为数学结果将是：$$2147483648$$它超出了 32 位有符号整数范围。 

另一个微妙的问题是正确处理负数。 整数除法向零截断，而不是向负无穷大截断。 不同的语言处理负除法的方式不同，因此我们必须仔细实现逻辑。 

重要的边缘情况包括：

 - 将最小的负整数除以`-1`- 除以`1`或者`-1`- 非常大的正或负股息
 - 商为零的情况
 - 负股息与正除数，反之亦然

 该问题保证了`divisor != 0`，因此永远不需要处理被零除的情况。 

## 方法

 ### 蛮力方法

 最直接的想法就是重复减法。 

我们不断地从被除数中减去除数，直到剩余的值变得小于除数。 成功减法的次数就是商。 

例如：

-`10 / 3`-`10 - 3 = 7`-`7 - 3 = 4`-`4 - 3 = 1`- 我们进行了 3 次减法，所以答案是`3`这种方法是正确的，因为除法基本上代表重复减法。 

然而，对于大量数据来说，这个解决方案变得极其缓慢。 考虑：$$2147483647 \div 1$$这将需要超过 20 亿次减法运算，这太慢了。 

### 最佳方法

 关键的见解是可以使用加倍和位移位来加速重复减法。 

我们不是每次迭代减去一次除数，而是反复将除数加倍，直到它变得尽可能大，同时仍然适合剩余的被除数。 

例如：

 - 除数 =`3`- 双倍值：

 -`3`-`6`-`12`-`24`- ...

 这类似于二进制长除法的工作原理。 

位移位很有用，因为：$$x << 1 = x \times 2$$加倍使我们能够一次消除大部分股息，从而大大减少操作次数。 

运行时间变成对数，因为每次减法都会删除除数的二次方倍数。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(股息/除数) | O(1) | O(1) | 一次一步地重复减去除数 |
 | 最佳 | O(log n) | O(1) | O(1) | 使用指数加倍和位操作 |

 ## 算法演练

 ### 第 1 步：处理溢出情况

 唯一的溢出情况发生在以下情况：$$-2^{31} \div -1$$因为结果变成：$$2^{31}$$这超出了最大 32 位有符号整数。 

我们立即返回：$$2^{31} - 1$$对于这个案例。 

### 步骤 2：确定结果的符号

 如果恰好有一个输入为负，则商为负。 

我们可以使用 XOR 逻辑来确定这一点：

 - 正/正 → 正
 - 负/负 → 正
 - 正/负 → 负
 - 负/正 → 负

 ### 步骤 3：将两个数字都转换为正数

 使用正整数可以简化逻辑。 

我们取被除数和除数的绝对值。 

### 步骤 4：反复查找最大的双精度数

 而剩余股息至少与除数一样大：

 1. 从以下开始：

 -`current_divisor = divisor`-`multiple = 1`2. 将两个值加倍，同时加倍仍适合股息：

 -`current_divisor <<= 1`-`multiple <<= 1`3. 从股息中减去最大的二倍除数。 
4. 将相应的倍数与商相加。 

这有效地消除了大部分股息。 

### 第 5 步：应用正确的标志

 如果结果为负，则对商求负。 

###第6步：返回最终结果

 现在可以正确计算商并截断为零。 

### 为什么它有效

 在每次迭代中，算法都会减去不超过剩余被除数的最大可能的除数的二次方倍数。 

这保证了两件事：

 1. 每次迭代都会最大化进度，从而保持运行时对数。 
2. 累加的倍数正好代表二进制形式的商。 

因为每次减法都对应于除数的有效倍数，所以最终的商在数学上是正确的。 

## Python 解决方案```python
class Solution:
    def divide(self, dividend: int, divisor: int) -> int:
        INT_MIN = -(2 ** 31)
        INT_MAX = (2 ** 31) - 1

        # Handle overflow case
        if dividend == INT_MIN and divisor == -1:
            return INT_MAX

        # Determine sign of result
        negative = (dividend < 0) != (divisor < 0)

        # Work with positive values
        dividend = abs(dividend)
        divisor = abs(divisor)

        quotient = 0

        while dividend >= divisor:
            current_divisor = divisor
            multiple = 1

            # Double divisor until it exceeds dividend
            while dividend >= (current_divisor << 1):
                current_divisor <<= 1
                multiple <<= 1

            dividend -= current_divisor
            quotient += multiple

        return -quotient if negative else quotient
```实现首先定义 32 位整数边界。 特殊的溢出情况会立即处理，因为它无法在允许的范围内表示。 

接下来，代码确定最终答案是否应该是否定的。 表达式：```python
(dividend < 0) != (divisor < 0)
```评估为`True`当恰好有一个值为负数时。 

然后使用将两个值转换为正数`abs()`。 这避免了重复减法期间负算术的复杂化。 

只要被除数仍然足够大以减去除数，外循环就会继续。 

在循环内部，算法使用左移重复将除数加倍。 每次左移都会将该数字乘以二。 

对于每一次加倍：```python
current_divisor <<= 1
multiple <<= 1
```该算法跟踪：

 - 加倍除数
 - 原除数被表示了多少次

 一旦找到最大的有效双除数，就从被除数中减去它，并将匹配的倍数添加到商中。 

最后，在返回结果之前应用符号。 

## 解决方案```go
func divide(dividend int, divisor int) int {
	INT_MIN := -1 << 31
	INT_MAX := (1 << 31) - 1

	// Handle overflow case
	if dividend == INT_MIN && divisor == -1 {
		return INT_MAX
	}

	negative := (dividend < 0) != (divisor < 0)

	// Convert to positive
	a := dividend
	if a < 0 {
		a = -a
	}

	b := divisor
	if b < 0 {
		b = -b
	}

	quotient := 0

	for a >= b {
		currentDivisor := b
		multiple := 1

		for a >= (currentDivisor << 1) {
			currentDivisor <<= 1
			multiple <<= 1
		}

		a -= currentDivisor
		quotient += multiple
	}

	if negative {
		return -quotient
	}

	return quotient
}
```Go 实现遵循与 Python 版本相同的总体策略。 

一个重要的区别是 Go 不提供内置的`abs()`标准库中的整数函数无需导入额外的包，因此绝对值是手动计算的。 

溢出处理也是明确的，因为 Go 整数可能会根据架构而变化，但 LeetCode 在 32 位约束下评估这个问题。 

位移位在 Go 中工作效率很高，并且非常适合该算法。

 ## 边缘情况

 ### 最小整数除以时溢出`-1`最重要的边缘情况是：```
-2147483648 / -1
```从数学上来说，答案是：```
2147483648
```但是，这超出了最大 32 位有符号整数值。 如果没有显式处理，某些语言会溢出并产生不正确的结果。 

该实现在任何计算之前检测到这种情况并立即返回：```
2147483647
```符合问题要求。 

### 商等于零

 案例如下：```
3 / 5
```在基于减法的算法中很容易出现错误处理。 

由于被除数从一开始就小于除数，因此外循环永远不会执行。 商仍为`0`，这是正确的截断结果。 

### 负数处理

 涉及负数的整数除法很棘手，因为向零截断与底除法不同。 

例如：```
-7 / 3 = -2
```不是`-3`。 

该实现通过以下方式完全避免了特定于语言的划分行为：

 1. 计算期间仅使用正值
 2. 之后应用标志

 这保证了所有情况下的正确截断语义。
