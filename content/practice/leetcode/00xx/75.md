[LeetCode 第 75 题](https://leetcode.com/problems/sort-colors/)

 **难度：** 🟡 中等
 **主题：** 数组、两个指针、排序

 ## 解决方案

 ## 问题理解

 此问题要求我们对仅包含三个不同值的数组进行排序：`0`,`1`， 和`2`。 这些值代表颜色：

 -`0`代表红色
 -`1`代表白色
 -`2`代表蓝色

 目标是重新排列数组，以便所有`0`s 首先出现，然后是所有`1`s，后面是所有`2`s。 

重要的要求是排序必须就地完成。 这意味着我们不允许创建另一个数组来存储排序结果。 相反，我们必须直接修改现有数组。 

例如，如果输入是：```
[2,0,2,1,1,0]
```排序结果应变为：```
[0,0,1,1,2,2]
```该问题还明确禁止使用该语言的内置排序功能。 这意味着我们必须设计自己的算法。 

约束相对较小，因为`n <= 300`，因此即使是较慢的方法在技术上也会通过。 然而，后续要求使用恒定额外空间的一次性算法。 这强烈暗示预期的解决方案在算法上比简单地计算值或应用通用排序算法更有趣。 

一些边缘情况很重要：

 - 仅包含一个元素的数组
 - 所有元素都相同的数组
 - 数组已经排序
 - 数组按相反顺序排序
 - 具有交替颜色的数组
 - 阵列完全缺少一种或两种颜色

 该问题保证每个值都是`0`,`1`， 或者`2`，所以我们不需要处理无效的输入。 

## 方法

 ### 蛮力方法

 最直接的解决方案是使用通用排序算法。 由于禁止内置排序，因此我们可以手动实现冒泡排序、选择排序或插入排序等排序。 

例如，在冒泡排序中，我们反复比较相邻元素，如果它们无序，则交换它们。 最终，所有较小的值都移向数组的前面。 

这是可行的，因为排序算法保证数组在经过足够的比较和交换后变得有序。 

然而，这种方法效率低下。 冒泡排序需要嵌套循环，导致`O(n²)`时间复杂度。 尽管约束足够小以使其通过，但它忽略了数组仅包含三个不同值的重要观察结果。 

### 更好的观察

 关键的见解是我们不需要完整的基于比较的排序算法，因为值仅限于`0`,`1`， 和`2`。 

这允许我们将数组分为三个区域：

 - 左侧包含所有`0`s
 - 中间包含所有`1`s
 - 右侧包含所有`2`s

 这被称为荷兰国旗算法。 

我们不会重复对元素进行排序，而是维护跟踪每个类别所属位置的边界。 通过扫描一次数组并将元素交换到正确的区域，我们可以在线性时间和常数空间内对数组进行排序。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(1) | O(1) | 使用重复比较和交换 |
 | 最佳| O(n) | O(1) | O(1) | 使用三指针一传 |

 ## 算法演练

 最优解使用三个指针：

 -`left`，跟踪下一个的位置`0`应该去
 -`right`，跟踪下一个的位置`2`应该去
 -`current`，扫描数组

 该算法保持这些不变量：

 - 之前的一切`left`是`0`- 之后的一切`right`是`2`- 之间的一切`left`和`current - 1`是`1`- 一切都来自`current`后续仍未处理

 ### 分步过程

 1. 初始化三个指针。 

放：

-`left = 0`-`current = 0`-`right = len(nums) - 1`最初，整个数组未经处理。 
2. 处理元素同时`current <= right`。 

一旦所有元素都被分类到正确的区域，我们就停止。 
3.如果`nums[current] == 0`，将其放入左侧区域。 

交换`nums[current]`和`nums[left]`。 

然后增加两者：

 -`left += 1`-`current += 1`这是有效的，因为放置一个`0`正确，之前的一切`left`仍然有效。 
4.如果`nums[current] == 1`，将其留在中间区域。 

自从`1`s 属于中间，不需要交换。 

简单地增加：

 -`current += 1`5. 如果`nums[current] == 2`，将其放入正确的区域。 

交换`nums[current]`和`nums[right]`。 

然后递减：

 -`right -= 1`不增加`current`然而。 

这很重要，因为从右侧换入的值尚未被处理。 
6. 继续直到`current > right`。 

此时，所有值都已正确分区。 

### 为什么它有效

 该算法在已处理区域和未处理元素之间保持严格的边界。 

每一步：

 - 之前的所有元素`left`保证是`0`- 之后的所有元素`right`保证是`2`- 之间的所有元素`left`和`current - 1`保证是`1`每个操作要么扩展左侧区域，要么扩展右侧区域，或者前进到正确放置的区域`1`s。 由于每个元素最多被处理一次，因此算法以数组完全排序而终止。 

## Python 解决方案```python
from typing import List

class Solution:
    def sortColors(self, nums: List[int]) -> None:
        """
        Do not return anything, modify nums in-place instead.
        """
        
        left = 0
        current = 0
        right = len(nums) - 1

        while current <= right:
            if nums[current] == 0:
                nums[left], nums[current] = nums[current], nums[left]
                left += 1
                current += 1

            elif nums[current] == 1:
                current += 1

            else:
                nums[current], nums[right] = nums[right], nums[current]
                right -= 1
```该实现直接遵循荷兰国旗算法。 

这`left`指针跟踪下一个位置`0`应放置。 这`right`指针跟踪下一个位置`2`应放置。 这`current`指针扫描数组。 

当当前值为`0`，我们将其交换到左侧区域并将两个指针向前移动，因为现在两个位置都已正确处理。 

当当前值为`1`，它已经属于中间区域，所以我们只需继续扫描即可。 

当当前值为`2`，我们将其与右边界交换并缩小右区域。 我们不前进`current`因为交换的元素仍然需要处理。 

该算法直接修改输入数组并且仅使用恒定的额外空间。 

## 解决方案```go
func sortColors(nums []int) {
    left := 0
    current := 0
    right := len(nums) - 1

    for current <= right {
        if nums[current] == 0 {
            nums[left], nums[current] = nums[current], nums[left]
            left++
            current++
        } else if nums[current] == 1 {
            current++
        } else {
            nums[current], nums[right] = nums[right], nums[current]
            right--
        }
    }
}
```Go 的实现与 Python 解决方案非常相似。 

Go 切片的行为与动态数组类似，因此函数内部的修改会直接影响原始数组。 

不存在整数溢出问题，因为索引保留在数组范围内。 Go 自然也能正确处理空切片或单元素切片，因为循环条件可以防止无效访问。

 ## 边缘情况

 一种重要的边缘情况是仅包含一个元素的数组。 幼稚的实现可能会意外地执行不必要的交换或访问无效的索引。 在此实现中，循环条件`current <= right`自然地正确处理单元素数组，并且算法在处理单独值后安全退出。 

另一个重要的情况是当所有元素都相同时，例如`[2,2,2]`。 一些不正确的实现可能会重复地与自身交换元素或无法正确移动指针，从而导致无限循环。 该解决方案始终更新`current`或者`right`，保证每次迭代的进展。 

第三个关键边缘情况是数组缺少三个值之一，例如`[1,1,0,0]`或者`[2,2,0,0]`。 一些算法错误地假设所有三个类别都存在，并且可能会错误地处理边界。 无论出现多少个不同的值，荷兰国旗方法都有效，因为它在遍历过程中动态地对元素进行分类。 

另一个微妙的边缘情况是当`2`从当前位置与右侧未处理的值进行交换。 如果我们错误地增加`current`交换之后，我们可以立即跳过处理传入值。 此实现通过保留来避免该错误`current`处理后就位`2`。
