[LeetCode 第 72 题](https://leetcode.com/problems/edit-distance/)

 **难度：** 🟡 中等
 **主题：** 字符串、动态规划

 ## 解决方案

 ## 问题理解

 该问题要求我们计算将一个字符串转换为另一个字符串所需的最少编辑操作数。 允许的操作包括插入、删除和替换单个字符。 每个操作的成本恰好为 1。 

我们有两个输入字符串，`word1`和`word2`。 目标是确定转换所需的尽可能少的操作数`word1`进入`word2`。 

例如，如果`word1 = "horse"`和`word2 = "ros"`，一个最佳序列是：

 - 更换`'h'`和`'r'`- 删除一个`'r'`- 删除`'e'`这需要三个操作，所以答案是`3`。 

约束告诉我们每个字符串的长度最多可达 500。这个长度足够大，以至于指数暴力搜索会太慢。 具有二次时间复杂度的解决方案，例如`O(m * n)`在哪里`m`和`n`是两个字符串的长度，是可以接受的，因为`500 * 500 = 250000`，这是可以管理的。 

一些边缘情况很重要：

 - 一个或两个字符串可能为空。 
- 字符串可能已经相同。 
- 每个角色都可能需要更换。 
- 一根绳子可能比另一根绳子长得多。 
- 可能存在多个编辑序列，但我们只关心最少的操作次数。 

该问题保证字符串只包含小写英文字母，因此我们不需要处理 Unicode 或特殊字符行为。 

## 方法

 ### 蛮力方法

 暴力解决方案将尝试所有可能的插入、删除和替换序列，直到第一个字符串变成第二个字符串。 在每个位置，我们都可以分为几种可能性：

 - 插入一个字符
 - 删除一个角色
 - 替换一个角色
 - 如果字符已经匹配，则保留该字符

 这种递归搜索最终会探索所有有效的编辑序列并返回最小成本。 

蛮力方法是正确的，因为它考虑了所有可能的转换路径。 然而，它的效率极低。 重复地重新计算相同的子问题。 例如，转换`"orse"`到`"ros"`可以从不同的递归分支多次求解。 

递归状态的数量呈指数增长，使得这种方法对于长度达到 500 的字符串不可行。 

### 最优动态规划方法

 关键的见解是该问题具有重叠的子问题和最优子结构。 

假设我们要计算转换所需的最少编辑量：```
word1[0:i]
```进入：```
word2[0:j]
```如果最后一个字符匹配，则不需要对这些字符进行任何操作，并且答案完全取决于较小的前缀。 

如果最后一个字符不同，那么我们必须执行以下三个操作之一：

 - 插入
 - 删除
 - 更换

 每个操作都会将问题简化为更小的子问题。 

这种结构使动态编程成为一种自然的选择。 我们建立一个表，其中每个条目存储两个字符串前缀之间的最小编辑距离。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(3^(m+n)) | O(3^(m+n)) | O(m+n) | 递归探索所有可能的编辑序列 |
 | 最优动态规划| O(m * n) | O(m * n) | 存储所有前缀对的结果 |

 ## 算法演练

 ### 动态规划定义

 让：```
dp[i][j]
```表示转换所需的最少操作数：```
word1[:i]
```进入：```
word2[:j]
```该表的尺寸为：```
(len(word1) + 1) x (len(word2) + 1)
```额外的行和列处理空前缀。 

### 逐步算法

 1. 初始化DP表。 

创建一个用零填充的二维表。 桌子的尺寸是`(m + 1) x (n + 1)`在哪里`m`和`n`是两个字符串的长度。 
2. 填写第一列。 

转换非空前缀`word1`转换为空字符串需要删除每个字符。 

所以：```
dp[i][0] = i
```3. 填充第一行。 

将空字符串转换为非空前缀`word2`需要插入每个字符。 

所以：```
dp[0][j] = j
```4. 处理每对字符。 

遍历每个位置`(i, j)`。 

比较：```
word1[i - 1]
word2[j - 1]
```我们减一是因为 DP 表包含用于空前缀的额外行和列。 
5. 处理匹配字符。 

如果字符相等，则不需要进行新的操作。 

所以：```
dp[i][j] = dp[i - 1][j - 1]
```6.处理不同的角色。 

如果字符不同，请考虑所有三个操作。 

插入：```
dp[i][j - 1] + 1
```删除：```
dp[i - 1][j] + 1
```代替：```
dp[i - 1][j - 1] + 1
```取三者中的最小值。 
7. 返回最终答案。 

右下角的单元格包含完整字符串的最小编辑距离：```
dp[m][n]
```### 为什么它有效

 该算法之所以有效，是因为每个有效的转换都必须以以下四种情况之一结束：

 - 最终的字符已经匹配
 - 最后的操作是插入
 - 最终操作是删除
 - 最后的手术是替换

 每种情况都会将问题简化为一个较小的子问题，其最佳答案已经被计算出来。 由于 DP 表存储了所有前缀的最佳答案，因此每个较大的状态都是从正确的较小状态构建的。 这保证了最终结果是最优的。 

## Python 解决方案```python
class Solution:
    def minDistance(self, word1: str, word2: str) -> int:
        m = len(word1)
        n = len(word2)

        dp = [[0] * (n + 1) for _ in range(m + 1)]

        for i in range(m + 1):
            dp[i][0] = i

        for j in range(n + 1):
            dp[0][j] = j

        for i in range(1, m + 1):
            for j in range(1, n + 1):
                if word1[i - 1] == word2[j - 1]:
                    dp[i][j] = dp[i - 1][j - 1]
                else:
                    insert_cost = dp[i][j - 1]
                    delete_cost = dp[i - 1][j]
                    replace_cost = dp[i - 1][j - 1]

                    dp[i][j] = 1 + min(
                        insert_cost,
                        delete_cost,
                        replace_cost
                    )

        return dp[m][n]
```实现首先计算两个字符串的长度。 这些长度决定了 DP 工作台的尺寸。 

该表用零初始化，然后填充第一行和第一列以表示涉及空字符串的转换。 这建立了基本情况。 

嵌套循环处理每对前缀。 在每个单元格，该算法都会比较两个字符串中的当前字符。 

如果字符匹配，则当前状态继承对角单元格的答案，因为不需要编辑。 

如果字符不同，算法将计算插入、删除和替换的成本。 每个操作对应于从相邻 DP 状态的移动。 选择这些可能性中的最小值并为当前操作加一。 

最后，右下角的单元格包含完整字符串之间的最小编辑距离。 

## 解决方案```go
func minDistance(word1 string, word2 string) int {
	m := len(word1)
	n := len(word2)

	dp := make([][]int, m+1)

	for i := 0; i <= m; i++ {
		dp[i] = make([]int, n+1)
	}

	for i := 0; i <= m; i++ {
		dp[i][0] = i
	}

	for j := 0; j <= n; j++ {
		dp[0][j] = j
	}

	for i := 1; i <= m; i++ {
		for j := 1; j <= n; j++ {
			if word1[i-1] == word2[j-1] {
				dp[i][j] = dp[i-1][j-1]
			} else {
				insertCost := dp[i][j-1]
				deleteCost := dp[i-1][j]
				replaceCost := dp[i-1][j-1]

				dp[i][j] = 1 + min(
					insertCost,
					deleteCost,
					replaceCost,
				)
			}
		}
	}

	return dp[m][n]
}

func min(a, b, c int) int {
	if a > b {
		a = b
	}

	if a > c {
		a = c
	}

	return a
}
```Go 的实现与 Python 解决方案非常相似。 DP 表被表示为切片的切片。 

与 Python 不同，Go 不提供内置的`min`函数用于多个整数，因此实现了辅助函数。 

Go 中的字符串内部是字节切片。 由于问题保证小写英文字母，因此按字节索引是安全且正确的。 

Go区分了nil切片和空切片，但是这个问题不需要特殊处理，因为DP表是显式分配的。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(m * n) | 每个 DP 单元计算一次 |
 | 空间| O(m * n) | DP表存储所有前缀状态|

 ## 边缘情况

 ### 空字符串

 一个或两个输入字符串可能为空。 这是错误的常见来源，因为许多实现错误地假设两个字符串都至少包含一个字符。 

如果`word1`是空的，唯一可能的创建方式`word2`是通过插入。 同样，如果`word2`为空，唯一可能的操作是删除。 

该实现通过第一行和第一列的初始化正确处理这个问题：```
dp[i][0] = i
dp[0][j] = j
```这些基本情况确保正确计算空前缀转换。 

### 相同的字符串

 如果两个字符串完全相同，则答案应该为零。 

如果字符匹配处理不正确，有缺陷的实现仍可能执行不必要的操作。 

该算法通过以下条件避免了这个问题：```
if word1[i - 1] == word2[j - 1]
```当字符匹配时，DP状态直接继承对角线值，而不增加任何操作成本。 

### 完全不同的字符串

 考虑如下输入：```
word1 = "aaaa"
word2 = "bbbb"
```每个字符都必须被替换。 

这种情况强调算法是否正确评估替换操作而不是执行低效的插入删除组合。 

递归关系明确包含替换：```
dp[i - 1][j - 1] + 1
```在插入、删除和替换中取最小值可以保证选择最佳选择。
