[LeetCode 第 98 题](https://leetcode.com/problems/validate-binary-search-tree/)

 **难度：** 🟡 中等
 **主题：** 树、深度优先搜索、二叉搜索树、二叉树

 ## 解决方案

 ## 问题理解

 该问题要求我们确定给定的二叉树是否满足二叉搜索树（通常缩写为 BST）的规则。 

二叉树由节点组成，其中每个节点包含一个值以及指向左子节点和右子节点的指针。 在 BST 中，每个节点都必须遵循以下规则：

 - 左子树中的每个值都必须严格小于当前节点的值。 
- 右子树中的每个值都必须严格大于当前节点的值。 
- 两个子树本身也必须递归地满足 BST 属性。 

重要的细节是约束适用于整个子树，而不仅仅是直接子树。 

例如，考虑这棵树：```
    5
   / \
  1   4
     / \
    3   6
```乍一看，节点`4`小于`5`，它已经违反了 BST 规则，因为它位于`5`。 虽然`3 < 4`和`6 > 4`，这棵树仍然无效，因为 的右子树中的所有节点`5`必须大于`5`。 

输入是二叉树的根节点。 输出是一个布尔值：

 -`True`如果该树是有效的 BST
 -`False`否则

 约束告诉我们树最多可以包含`10^4`节点。 这意味着我们应该寻求高效的遍历解决方案，最好是线性时间。 节点值的范围可以是`-2^31`到`2^31 - 1`，这意味着我们在处理边界值时必须小心，并且应该避免依赖可能溢出的固定整数哨兵。 

一些边缘情况很重要：

 - 单节点树始终是有效的 BST。 
- 不允许重复值，因为规则要求严格更小和严格更大的值。 
- 树可能看起来局部有效，但全局无效。 
- 非常深的树可能会产生很大的递归深度。 
- 负值和极大的值仍必须正常工作。 

幼稚的实现通常会失败，因为它只将每个节点与其直接子节点进行比较，而不是验证每个子树的整个允许范围。 

## 方法

 ### 蛮力方法

 一种简单的方法是通过检查来独立验证每个节点：

 - 左子树中的每个值都小于该节点
 - 右子树中的每个值都大于该节点

 为此，对于每个节点，我们可以：

 1. 求左子树中的最大值
 2. 求右子树中的最小值
 3.验证BST条件
 4. 对子级递归重复

 这是有效的，因为它显式地检查每个节点上的 BST 定义。 

然而，这种方法效率低下，因为子树值被重复遍历。 例如，查找每个节点的子树最小值和最大值会导致许多重复计算。 

在最坏的情况下，每个节点可能会再次扫描几乎整棵树，从而导致二次复杂度。 

### 最佳方法

 关键的见解是 BST 中的每个节点都必须位于由其祖先确定的有效数值范围内。 

例如：

 - 的左孩子`10`必须小于`10`- 的右孩子`10`必须大于`10`- 如果我们转向正确的孩子`15`，那么它下面的每个节点仍必须保持大于`10`我们不是重复检查子树，而是在遍历期间传播有效的下限和上限。 

访问节点时：

 - 其值必须严格大于下限
 - 其值必须严格小于上限

 当我们递归时：

 - 左子树接收更新的上限
 - 右子树接收更新的下界

 这保证了每个节点同时满足所有祖先约束。 

由于每个节点仅被访问一次，因此该解决方案以线性时间运行。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(h) | 重复扫描子树的最小/最大值 |
 | 最佳 | O(n) | O(h) | 在 DFS 遍历期间使用递归边界传播 |

 这里，`n`是节点数，`h`是树的高度。 

## 算法演练

 1. 从根节点开始深度优先遍历。 

最初，根没有任何限制，因此它的有效范围是`(-∞, +∞)`。 
2. 在每个节点，验证其值是否严格位于允许的范围内。 

如果节点值小于或等于下限，则违反 BST 属性。 

如果节点值大于或等于上限，则违反 BST 属性。 
3. 递归验证左子树。 

左子树中的每个节点都必须小于当前节点，因此：

 - 上限成为当前节点的值
 - 下限保持不变
 4. 递归验证右子树。 

右子树中的每个节点都必须大于当前节点，因此：

 - 下界成为当前节点的值
 - 上限保持不变
 5. 如果到达空节点，则返回`True`。 

空子树始终是有效的 BST。 
6. 合并结果。 

节点仅在以下情况下有效：

 - 其值满足界限
 - 其左子树有效
 - 其右子树有效

 ### 为什么它有效

 该算法保持一个不变量：

 > 每个递归调用都会接收该子树中所有节点必须满足的确切有效范围。 

因为祖先约束是向下传播的，所以任何节点都不能违反 BST 规则而不导致范围检查失败。 每个节点都会针对所有相关约束进行一次检查，从而保证正确性。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional

class Solution:
    def isValidBST(self, root: Optional[TreeNode]) -> bool:

        def validate(
            node: Optional[TreeNode],
            lower: float,
            upper: float
        ) -> bool:

            if not node:
                return True

            if node.val <= lower or node.val >= upper:
                return False

            left_valid = validate(node.left, lower, node.val)
            right_valid = validate(node.right, node.val, upper)

            return left_valid and right_valid

        return validate(root, float("-inf"), float("inf"))
```该实现定义了一个名为的辅助函数`validate`执行递归 DFS 遍历，同时携带有效的数字边界。 

基本情况处理空节点。 由于空子树不能违反 BST 规则，因此该函数返回`True`。 

对于每个真实节点，算法检查节点值是否严格落在下限和上限之间。 如果不是，函数立即返回`False`。 

递归调用适当地更新边界：

 - 左子树接收当前节点值作为其新的上限。 
- 右子树接收当前节点值作为其新的下界。 

最后，两个子树结果都通过逻辑与进行组合。 只有每个子树都满足 BST 规则，整棵树才有效。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */

import "math"

func isValidBST(root *TreeNode) bool {

    var validate func(node *TreeNode, lower, upper int64) bool

    validate = func(node *TreeNode, lower, upper int64) bool {

        if node == nil {
            return true
        }

        value := int64(node.Val)

        if value <= lower || value >= upper {
            return false
        }

        leftValid := validate(node.Left, lower, value)
        rightValid := validate(node.Right, value, upper)

        return leftValid && rightValid
    }

    return validate(root, math.MinInt64, math.MaxInt64)
}
```Go 实现遵循与 Python 版本相同的递归策略。 

一个重要的区别是整数处理。 由于节点值可能达到 32 位整数的限制，因此解决方案使用`int64`与`math.MinInt64`和`math.MaxInt64`以避免溢出问题。 

Go 使用`nil`而不是 Python 的`None`对于空节点。 否则，递归逻辑保持不变。

 ## 边缘情况

 ### 重复值

 BST 规则要求严格的不平等。 许多不正确的实现允许使用重复`<=`或者`>=`错误地。 

例如：```
    2
   /
  2
```这不是有效的 BST，因为左子树必须严格小于父树。 

该实现通过以下方式正确处理此问题：```
if node.val <= lower or node.val >= upper:
```这会立即拒绝重复值。 

### 深层子树违规

 一个常见的错误是只检查直系子代。 

考虑：```
      10
     /  \
    5    15
        /
       6
```节点`6`小于`10`，所以它不能出现在`10`。 

天真的亲子比较忽略了这个问题，因为`6 < 15`在本地显示有效。 

范围传播技术正确通过`10`作为整个右子树的下界，所以`6`验证失败。 

### 极端整数值

 这些约束允许值接近 32 位整数的限制。 

使用固定整数哨兵，例如`-2^31`和`2^31 - 1`因为边界可能会产生溢出或比较问题。 

Python 解决方案通过使用正无穷大和负无穷大来避免这种情况。 

Go 解决方案通过使用避免溢出`int64`与`math.MinInt64`和`math.MaxInt64`。 

这保证了所有有效输入的安全比较。
