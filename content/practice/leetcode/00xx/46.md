 # LeetCode 46 - 排列

 ## 问题理解

 这个问题给了我们一个不同整数的数组，称为`nums`，并要求我们生成这些数字的所有可能的排列。 

排列是按特定顺序排列元素。 例如，如果输入是`[1,2,3]`， 然后`[1,2,3]`,`[1,3,2]`， 和`[2,1,3]`都是不同的排列，因为元素的顺序发生了变化。 

输入数组包含唯一的整数，这简化了问题，因为我们不需要处理重复的排列。 我们的任务是返回一个列表，其中包含输入数字的所有可能的排序。 

限制很小：

 -`1 <= nums.length <= 6`- 所有值都是唯一的

 由于最大长度仅为 6，因此排列总数最多为：$$6! = 720$$这告诉我们直接生成所有排列是可行的。 事实上，任何正确的解决方案都必须至少花费`O(n!)`时间因为有`n!`输出。 

有几个重要的边缘情况需要记住：

 - 单元素数组，例如`[1]`应该返回`[[1]]`- 二元素数组应该返回两个排列
 - 负数必须与正数完全相同
 - 由于所有数字都是不同的，因此我们永远不需要重复检查逻辑
 - 算法必须确保每个排列都准确无误`n`单个排列中没有重复元素

 核心挑战是系统地探索每一个有效的排序，不遗漏任何可能性。 

## 方法

 ### 蛮力方法

 蛮力策略会尝试所有可能的数字排序，并检查它是否形成有效的排列。 

一种方法是：

 1. 生成每个长度的序列`n`2. 构建序列时允许重复选择
 3. 过滤掉重复使用元素的序列

 例如，与`[1,2,3]`，我们可以生成长度为 3 的所有可能序列：

 -`[1,1,1]`-`[1,1,2]`-`[1,1,3]`- ...
 -`[3,3,3]`然后我们将只保留每个数字恰好出现一次的序列。 

这种方法是正确的，因为每个有效的排列最终都会出现在所有生成的序列中。 然而，它的效率极低，因为它会生成许多无效的组合，这些组合稍后必须被丢弃。 

生成的序列总数为：$$n^n$$其增长速度比`n!`。 

### 最优回溯方法

 更好的方法是逐步构建排列，同时在构建过程中加强有效性。 

关键的见解是，在排列中的每个位置，我们只需要从尚未使用过的数字中进行选择。 

这自然会导致回溯：

 - 一次构建一个元素的排列
 - 跟踪哪些号码已被使用
 - 一旦排列达到长度`n`，保存它
 - 通过删除最后一个选择并尝试另一个选项来回溯

 我们不会生成无效状态并稍后进行过滤，而是在整个搜索过程中仅生成有效的部分排列。 

因为约束很小，并且最终必须产生每个排列，所以这是最佳的实际解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n^n) | O(n^n) | O(n^n) | O(n^n) | 生成所有序列并过滤无效序列 |
 | 最优回溯| O(n × n!) | O(n) 不包括输出 | 仅增量构建有效排列 |

 ## 算法演练

 ### 最优回溯算法

 1. 创建一个空结果列表来存储所有排列。 
2. 维护一个临时列表，名为`current_permutation`。 这代表当前正在构建的排列。 
3. 维护一个布尔数组，名为`used`。 每个索引对应一个数字`nums`。 如果`used[i]`是`True`，这意味着`nums[i]`已经包含在当前排列中。 
4. 定义递归回溯函数。 
5. 在递归函数内部，首先检查当前排列长度是否等于`nums`。 
6. 如果长度匹配，我们就完成了有效的排列。 将当前排列的副本附加到结果列表中。 
7. 否则，迭代中的每个数字`nums`。 
8. 对于每个数字：

 - 如果已经使用过则跳过它
 - 否则：

 - 将其标记为已使用
 - 将其添加到当前排列中
 - 递归地继续构建排列
 9. 递归返回后，撤消选择：

 - 从当前排列中删除最后一个元素
 - 再次将该号码标记为未使用
 10. 继续尝试剩余的选择，直到探索完所有可能性。 

### 为什么它有效

 该算法保持了一个重要的不变量：

 - 在每个递归级别，`current_permutation`仅包含选自以下的独特元素`nums`因为我们只选择未使用的元素，所以排列不能包含重复项。 因为递归一直持续到 length`n`，每个完成的排列只包含每个数字一次。 

回溯系统地探索每个位置的每个有效选择，保证所有排列都生成一次。 

## Python 解决方案```python
from typing import List

class Solution:
    def permute(self, nums: List[int]) -> List[List[int]]:
        result = []
        current_permutation = []
        used = [False] * len(nums)

        def backtrack():
            if len(current_permutation) == len(nums):
                result.append(current_permutation[:])
                return

            for i in range(len(nums)):
                if used[i]:
                    continue

                used[i] = True
                current_permutation.append(nums[i])

                backtrack()

                current_permutation.pop()
                used[i] = False

        backtrack()

        return result
```实现首先初始化三个结构：

 -`result`存储所有完成的排列
 -`current_permutation`存储当前正在构建的排列
 -`used`跟踪哪些元素已经包含在内

 嵌套的`backtrack()`函数执行递归探索。 

当当前排列长度与输入长度匹配时，出现基本情况。 此时，完整的排列已形成，因此将副本附加到结果列表中。 

循环遍历所有索引`nums`。 如果某个数字已在当前排列中使用过，则会跳过该数字。 

当选择一个号码时：

 - 它被标记为已使用
 - 添加到当前排列
 - 递归继续

 递归完成探索该分支后，算法回溯：

 - 最后一个数字被删除
 - 使用的标记被重置

 这会完全恢复选择之前的状态，使算法能够干净地探索下一个可能性。 

## 解决方案```go
func permute(nums []int) [][]int {
    result := [][]int{}
    currentPermutation := []int{}
    used := make([]bool, len(nums))

    var backtrack func()

    backtrack = func() {
        if len(currentPermutation) == len(nums) {
            permutationCopy := make([]int, len(currentPermutation))
            copy(permutationCopy, currentPermutation)

            result = append(result, permutationCopy)
            return
        }

        for i := 0; i < len(nums); i++ {
            if used[i] {
                continue
            }

            used[i] = true
            currentPermutation = append(currentPermutation, nums[i])

            backtrack()

            currentPermutation = currentPermutation[:len(currentPermutation)-1]
            used[i] = false
        }
    }

    backtrack()

    return result
}
```Go 实现遵循与 Python 解决方案相同的递归回溯逻辑。 

一个重要的区别是切片处理。 在 Go 中，切片引用底层数组，因此我们必须在将完整的排列附加到之前显式创建一个副本`result`。 否则，以后的修改将影响之前存储的排列。 

声明：```go
permutationCopy := make([]int, len(currentPermutation))
copy(permutationCopy, currentPermutation)
```确保每个存储的排列都是独立的。 

Go 在这里并不担心整数溢出，因为输入值和递归深度都非常小。

递归栈、当前排列和使用的数组各自最多需要`O(n)`空间。 输出本身需要`O(n × n!)`存储，但这通常被排除在辅助空间分析之外。

 ## 边缘情况

 ### 单元素输入

 输入如`[1]`是最小的有效情况。 有缺陷的实现可能会意外返回一个空列表，而不是包含一种排列的列表。 

该实现正确地处理了这个问题，因为递归在选择单个元素后立即到达基本情况，产生`[[1]]`。 

### 回溯国家腐败

 当算法忘记在递归返回后撤消状态更改时，就会出现递归回溯解决方案中的常见错误。 

例如，如果我们忘记：

 - 从排列中删除最后一个元素
 - 重置`used`标记

 那么稍后的递归分支将在损坏的状态上运行并产生不正确的结果。 

该实现在每次递归调用后显式恢复这两个结构，保证对所有分支的干净探索。 

### 可变列表参考问题

 将排列附加到结果列表时会出现另一个微妙的问题。 

如果我们重复附加相同的可变列表对象而不复制它，则以后的修改将影响所有存储的排列。 

例如：```
result.append(current_permutation)
```是不正确的。 

该实现通过附加副本来避免这种情况：```
result.append(current_permutation[:])
```这保证了即使在回溯修改工作列表之后，每个存储的排列仍然保持独立。
