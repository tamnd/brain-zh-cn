[LeetCode 第 19 题](https://leetcode.com/problems/remove-nth-node-from-end-of-list/)

 **难度：** 🟡 中等
 **主题：** 链表、两个指针

 ## 解决方案

 ## 问题理解

 这个问题要求我们删除`nth`从单链表末尾开始计数的节点并返回修改后的列表。 

单链表是一个节点序列，其中每个节点包含一个值和一个指向下一个节点的指针。 与数组不同，链表不允许直接索引，因此访问特定位置的节点需要逐步遍历链表。 

输入由两个值组成：

 -`head`，它指向链表的第一个节点
 -`n`，它告诉我们应该删除末尾的哪个节点

 输出应该是删除目标节点后更新的链表的头。 

例如，如果列表是：```
1 -> 2 -> 3 -> 4 -> 5
```和`n = 2`，倒数第二个节点是`4`，因此结果变为：```
1 -> 2 -> 3 -> 5
```约束相对较小，因为列表大小最多为 30 个节点。 甚至一个`O(n²)`解决方案在技术上会通过。 然而，后续内容明确询问我们是否可以一次性解决它，这强烈表明预期的解决方案使用了更有效的遍历策略。 

一些边缘情况在这里很重要。 

如果列表仅包含一个节点并且必须删除该节点，则结果应为空列表。 

如果要删除的节点是头本身，我们必须正确更新头指针。 这是链表问题中错误的常见来源。 

如果要删除的节点是最后一个节点，我们必须正确断开尾部。 

该问题保证了`1 <= n <= sz`，所以我们永远不需要处理无效值`n`。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是对链表执行两次传递。 

在第一遍中，我们计算列表中的节点总数。 一旦我们知道了长度，我们就可以确定必须从列表开头删除的节点的位置。 

如果列表长度是`L`，那么要删除的节点位于以下位置：```
L - n
```从一开始，就使用从零开始的索引。 

然后我们执行第二次遍历以到达目标节点之前的节点并更新其`next`跳过目标的指针。 

这种方法是正确的，因为计算总长度可以让我们精确地将从末端开始的位置转换为从开始开始的位置。 

尽管该解决方案对于给定的约束是完全可以接受的，但它需要两次遍历列表。 后续要求提供一次性解决方案，这激发了更优化的技术。 

### 最佳方法

 关键的见解是我们实际上不需要知道列表的总长度。 

相反，我们可以保持固定的间隙`n`两个指针之间的节点。 当快指针到达链表末尾时，慢指针将自动定位到需要删除的节点之前。 

这是可行的，因为指针之间的距离在整个遍历过程中保持不变。 

为了简化边缘情况，特别是在删除头节点时，我们在实际头之前引入了一个虚拟节点。 虚拟节点指向原始头部，并允许我们将头部移除与任何其他移除操作完全相同。 

该算法进行如下：

 - 移动快速指针`n`领先一步
 - 将两个指针一起移动，直到快速指针到达最后一个节点
 - 慢指针现在位于目标节点之前
 - 通过更新删除目标`slow.next`这样就达到了后续的要求，因为列表只被遍历一次。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(1) | O(1) | 两次通过，第一次计算长度，第二次删除节点 |
 | 最佳| O(n) | O(1) | O(1) | 固定间隙的一通两指针解决方案 |

 ## 算法演练

 1. 创建一个虚拟节点，其`next`指针引用原始头。 

该虚拟节点简化了删除逻辑。 如果没有它，删除头节点将需要单独处理，因为头指针本身会发生变化。 
2.初始化两个指针，`fast`和`slow`，都从虚拟节点开始。 

目标是保持精确的差距`n`它们之间的节点。 
3. 移动`fast`指针向前`n`次。 

这一步之后，`fast`是`n`前面的节点`slow`。 
4. 将两个指针一起向前移动，直到`fast.next`变成`None`。 

此时此刻：

 -`fast`位于最后一个节点
 -`slow`紧邻必须删除的节点之前
 5. 通过更新删除目标节点：```
slow.next = slow.next.next
```这会绕过目标节点并重新连接列表。 

1. 返回`dummy.next`。 

这可以正确处理所有情况，包括移除原始头部时。 

### 为什么它有效

 该算法保持了一个不变量，即`fast`指针始终是`n`前面的节点`slow`指针。 什么时候`fast`到达最终节点，`slow`因此必须位于紧邻的节点之前`n`从最后开始的位置。 由于链表移除只需要访问前一个节点，`slow`正是我们需要它的地方。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

from typing import Optional

class Solution:
    def removeNthFromEnd(
        self,
        head: Optional[ListNode],
        n: int
    ) -> Optional[ListNode]:
        
        dummy = ListNode(0, head)
        
        fast = dummy
        slow = dummy
        
        # Move fast pointer n steps ahead
        for _ in range(n):
            fast = fast.next
        
        # Move both pointers until fast reaches the end
        while fast.next:
            fast = fast.next
            slow = slow.next
        
        # Remove the target node
        slow.next = slow.next.next
        
        return dummy.next
```实现首先创建一个指向原始头的虚拟节点。 这避免了删除第一个节点的特殊情况逻辑。 

两个都`fast`和`slow`指针从虚拟节点开始。 这`fast`指针已超前`n`向前迈出一步，以便建立所需的差距。 

主遍历循环将两个指针一起移动，同时保留间隙。 一次`fast.next`变成`None`， 这`slow`指针直接位于要删除的节点之前。 

删除本身是通过单个指针更新来执行的：```python
slow.next = slow.next.next
```这会跳过目标节点并重新连接剩余的列表。 

最后，`dummy.next`被退回，因为原来的头可能已被移除。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func removeNthFromEnd(head *ListNode, n int) *ListNode {
    
    dummy := &ListNode{
        Val:  0,
        Next: head,
    }
    
    fast := dummy
    slow := dummy
    
    // Move fast pointer n steps ahead
    for i := 0; i < n; i++ {
        fast = fast.Next
    }
    
    // Move both pointers together
    for fast.Next != nil {
        fast = fast.Next
        slow = slow.Next
    }
    
    // Remove target node
    slow.Next = slow.Next.Next
    
    return dummy.Next
}
```Go 实现遵循与 Python 解决方案完全相同的逻辑。 主要区别在于显式指针语法。 

Go 使用`nil`而不是Python的`None`，并且直接使用结构指针进行操作`*ListNode`。 

内存管理由 Go 的垃圾收集器自动处理，因此删除的节点不需要显式释放。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个节点最多被访问一次 |

 该算法执行链表的单次遍历。 尽管两个指针在结构中移动，但每个指针仅向前前进，而不会重新访问节点，因此总工作量与节点数量保持线性关系。 

空间复杂度是恒定的，因为没有分配与输入大小成比例的辅助数据结构。

 ## 边缘情况

 当头节点本身必须被删除时，就会出现一种重要的边缘情况。 发生这种情况时`n`等于列表的长度。 如果没有虚拟节点，实现将需要特殊的逻辑来单独更新头指针。 虚拟节点消除了这种复杂性，因为头之前的节点始终存在。 

另一个关键情况是单节点列表。 例如：```
[1], n = 1
```删除后，列表变为空。 粗心的实现可能会尝试访问`next`不再存在的指针。 当前的解决方案可以安全地处理这个问题，因为即使真实列表变空，虚拟节点仍然有效。 

删除尾部节点也是常见的错误来源。 在单链表中，没有向后遍历，因此我们必须停在紧邻尾部之前的节点处。 两分球的差距保证了`slow`指针正好落在该位置，使尾部去除变得简单。 

最后一个微妙的边缘情况涉及非常小的列表，尤其是两节点列表。 在这些情况下，指针移动逻辑很容易丢失一。 使用不变量`fast`完全保持`n`前面的节点`slow`确保算法的行为一致，无论列表大小如何。
