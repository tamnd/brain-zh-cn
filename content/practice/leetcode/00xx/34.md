[LeetCode 第 34 题](https://leetcode.com/problems/find-first-and-last-position-of-element-in-sorted-array/)

 **难度：** 🟡 中等
 **主题：** 数组、二分查找

 ## 解决方案

 ## 问题理解

 该问题给了我们一个排序的整数数组`nums`和目标值`target`。 我们的目标是找到目标出现的第一个位置和目标出现的最后一个位置。 

该数组按非降序排序，这意味着重复的值会相邻出现。 由于这种排序特性，我们可以使用二分搜索技术而不是线性扫描数组。 

输出应该是一个二元素数组：

 - 第一个值是第一次出现的索引`target`- 第二个值是最后一次出现的索引`target`如果数组中不存在目标，则返回`[-1, -1]`。 

例如：```
nums = [5,7,7,8,8,10]
target = 8
```目标`8`在索引处出现两次`3`和`4`，所以答案是：```
[3,4]
```关键要求是运行时复杂性。 该问题明确要求`O(log n)`算法。 这一要求立即排除了任何直接的线性扫描解决方案，因为扫描整个阵列需要`O(n)`时间。 

这些约束告诉我们一些重要的事情：

 - 数组长度可以大到`10^5`- 值可以是负值或正值
 - 数组已经排序
 - 允许重复值

 排序属性是最重要的观察结果，因为二分搜索仅对有序数据有效。 

一些边缘情况很重要：

 - 数组可能为空
 - 目标可能不存在
 - 每个元素都可能等于目标
 - 目标只能出现一次
 - 目标可能出现在数组的开头或结尾

 在搜索边界时，特别是当存在重复项时，幼稚的实现很容易犯下相差一的错误。 

## 方法

 ### 蛮力方法

 最直接的解决方案是从左到右扫描数组。 

我们可以初始化两个变量，`first`和`last`， 到`-1`。 当我们遍历数组时：

 - 当我们第一次遇到目标时，我们设定`first`- 每次遇到目标时，我们都会更新`last`在遍历结束时，`first`和`last`包含所需的范围。 

这种方法是正确的，因为它检查每个元素并记录目标的所有出现。 然而，这需要`O(n)`因为在最坏的情况下我们可能需要扫描整个数组。 

由于问题明确要求`O(log n)`复杂性，这个解决方案太慢了。 

### 最佳二分搜索方法

 重要的一点是数组是有序的。 

在排序数组中，二分查找可以在对数时间内有效地定位值。 然而，标准二分搜索只能找到目标的一次出现，不一定是第一个或最后一个。 

为了有效地解决这个问题，我们执行两个单独的二分搜索：

 - 一次搜索找到目标的最左边出现的位置
 - 另一个搜索找到目标的最右边出现的位置

 这个想法是在找到目标后继续搜索：

 - 第一次出现时，只要找到目标，我们就会向左移动
 - 对于最后一次出现，只要找到目标，我们就会向右移动

 这是可行的，因为重复项在排序数组中是连续的。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(1) | O(1) | 扫描整个数组并跟踪第一次和最后一次出现 |
 | 最佳| O(log n) | O(1) | O(1) | 使用两次二分搜索来查找左边界和右边界 |

 ## 算法演练

 ### 第 1 步：搜索第一次出现的情况

 我们执行二分搜索来定位目标的最左边位置。 

什么时候`nums[mid]`等于目标：

 - 我们记录`mid`作为一个可能的答案
 - 我们继续搜索左半部分，因为数组中可能还有更早的地方出现

 当`nums[mid]`小于目标：

 - 目标必须在右侧
 - 移动`left`前进

 当`nums[mid]`大于目标：

 - 目标必须在左边
 - 移动`right`落后

 在搜索结束时，我们要么有第一次出现的索引，要么`-1`。 

### 第 2 步：搜索最后一次出现的情况

 我们以略有不同的行为重复二分搜索。 

什么时候`nums[mid]`等于目标：

 - 我们记录`mid`- 我们继续搜索右半部分，因为数组后面可能会出现另一个情况

 其余的比较与标准二分搜索相同。 

在搜索结束时，我们要么有最后一次出现的索引，要么`-1`。 

### 第三步：返回结果

 将两次搜索的结果组合成一个双元素数组：```
[first_occurrence, last_occurrence]
```如果从未找到目标，则两个值都保留`-1`。 

### 为什么它有效

 正确性来自二分查找不变量。 

在第一次搜索过程中，每当我们找到目标时，我们不会立即停止，因为可能还有更早的出现。 通过继续到左半部分，我们保证最终记录的索引是包含目标的最小有效索引。 

类似地，在第二次搜索期间，继续进入右半部分可以保证最终记录的索引是包含目标的最大有效索引。 

由于每次二分搜索每一步都会将搜索空间减半，因此运行时间保持对数。 

## Python 解决方案```python
from typing import List

class Solution:
    def searchRange(self, nums: List[int], target: int) -> List[int]:

        def find_first() -> int:
            left, right = 0, len(nums) - 1
            answer = -1

            while left <= right:
                mid = (left + right) // 2

                if nums[mid] == target:
                    answer = mid
                    right = mid - 1
                elif nums[mid] < target:
                    left = mid + 1
                else:
                    right = mid - 1

            return answer

        def find_last() -> int:
            left, right = 0, len(nums) - 1
            answer = -1

            while left <= right:
                mid = (left + right) // 2

                if nums[mid] == target:
                    answer = mid
                    left = mid + 1
                elif nums[mid] < target:
                    left = mid + 1
                else:
                    right = mid - 1

            return answer

        first = find_first()

        if first == -1:
            return [-1, -1]

        last = find_last()

        return [first, last]
```该实现定义了两个辅助函数。 

这`find_first`函数执行二分搜索，同时偏向左侧。 每当找到目标时，当前索引就会存储在`answer`，但通过移动在左半部分继续搜索`right = mid - 1`。 

这`find_last`函数几乎相同，只是它偏向右侧。 找到目标后就移动`left = mid + 1`继续搜索以后发生的情况。 

main 函数首先搜索第一个出现的位置。 如果目标不存在则立即返回`[-1, -1]`。 否则，它执行第二次搜索并返回两个索引。 

这种结构使代码保持简洁，并使两个边界搜索易于独立理解。 

## 解决方案```go
func searchRange(nums []int, target int) []int {

	findFirst := func() int {
		left, right := 0, len(nums)-1
		answer := -1

		for left <= right {
			mid := left + (right-left)/2

			if nums[mid] == target {
				answer = mid
				right = mid - 1
			} else if nums[mid] < target {
				left = mid + 1
			} else {
				right = mid - 1
			}
		}

		return answer
	}

	findLast := func() int {
		left, right := 0, len(nums)-1
		answer := -1

		for left <= right {
			mid := left + (right-left)/2

			if nums[mid] == target {
				answer = mid
				left = mid + 1
			} else if nums[mid] < target {
				left = mid + 1
			} else {
				right = mid - 1
			}
		}

		return answer
	}

	first := findFirst()

	if first == -1 {
		return []int{-1, -1}
	}

	last := findLast()

	return []int{first, last}
}
```Go 实现遵循与 Python 版本相同的逻辑。 

Go 特有的一个重要细节是中点计算：```go
mid := left + (right-left)/2
```这种形式避免了可能发生的潜在整数溢出`(left + right) / 2`在某些语言中。 

Go 切片自然会处理空数组，因此不需要特殊的 nil 处理。 如果切片为空，`right`变成`-1`，导致二分查找循环立即终止。

 ## 边缘情况

 ### 空数组

 空数组是最重要的边缘情况之一，因为二分搜索实现很容易因无效索引而失败。 

对于空数组：```
nums = []
```初始值变为：```
left = 0
right = -1
```自从`left <= right`立即为假，循环永远不会执行。 执行正确返回`[-1, -1]`无需访问无效索引。 

### 所有元素都等于目标

 考虑：```
nums = [2,2,2,2]
target = 2
```粗心的二分搜索可能会在第一次发现的事件处停止，并错误地仅返回中间索引。 

我们的实现通过在找到目标后继续搜索来避免这种情况：

 - 首次出现搜索不断向左移动
 - 最后出现的搜索继续向右移动

 这保证了全系列`[0,3]`。 

### 目标在边界

 位于数组开头或结尾的目标经常会出现相差一错误。 

例子：```
nums = [1,2,3,4,5]
target = 1
```在首次出现搜索期间，算法继续向最左边的有效位置收缩，直到不存在更小的有效索引。 

同样，对于：```
target = 5
```最后出现的搜索继续向右边界。 

由于循环条件和指针更新经过精心设计，因此实现可以正确处理这两个极端情况，而不会跳过有效索引。
