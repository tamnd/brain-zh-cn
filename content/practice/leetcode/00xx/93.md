[LeetCode Problem 93](https://leetcode.com/problems/restore-ip-addresses/)

 **难度：** 🟡 中等
 **主题：** 字符串、回溯

 ## 解决方案

 ## 问题理解

 该问题要求我们获取一个仅包含数字的字符串，并确定每种可能的方式来插入恰好三个点，以便生成的字符串成为有效的 IPv4 地址。 

有效的 IP 地址有四个由点分隔的数字段。 每个段必须满足两个条件：

 1. Its numeric value must be between 0 and 255 inclusive.
 2. It cannot contain leading zeros unless the segment itself is exactly`"0"`。 

例如：

-`"192.168.1.1"`有效，因为每个段都在范围内并且不包含前导零。 
-`"01.2.3.4"`无效，因为`"01"`包含前导零。 
-`"256.1.1.1"`无效，因为`256`大于`255`。 

输入是单个字符串`s`仅由数字组成。 我们不允许重新排列数字或删除字符。 我们只能在某些位置插入点。 

输出应包含可由字符串组成的每个有效 IP 地址。 

这些约束提供了重要的见解：

 - IP 地址始终包含 4 个段。 
- 每个段最多可以包含 3 位数字。 
- 因此，最长的有效 IP 字符串的长度为 12。 
- 最短的有效 IP 字符串长度为 4。 

尽管官方限制允许字符串长度最大为 20，但任何长度超过 12 的字符串都可能立即返回空结果，因为它不可能适合四个有效段。 

一些边缘情况很重要：

 - 包含许多零的字符串，例如`"0000"`，因为前导零处理很棘手。 
- 段等于`"255"`是有效的，同时`"256"`不是。 
- 弦太短或太长，无法形成四段。 
- 某些分区创建前导零的输入，例如`"010010"`。 

幼稚的实现通常会在前导零验证上失败，或者意外地允许大于 255 的段。 

## 方法

 ### 蛮力方法

 蛮力方法尝试一切可能的方法在字符串中放置三个点。 

由于IP地址有四个部分，我们可以选择：

 - 第一段结束
 - 第二段结束
 - 第三段结束

 其余字符成为第四段。 

对于每个可能的分区，我们检查所有四个段是否都有效。 

如果满足以下条件，则段有效：

 - 它的长度在1和3之间
 - 其数值最多为255
 - 它没有前导零，除非它完全是`"0"`这种方法是正确的，因为它详尽地检查了每个可能的点位置。 然而，它会执行不必​​要的工作，因为即使明显无法产生有效的 IP 地址，也会探索许多无效路径。 

### 最优回溯方法

 关键的见解是问题自然形成递归决策树。 

在每一步中，我们都会决定当前段要采用多少位数字：

 - 1 位数字
 - 2 位数字
 - 3 位数字

 然后我们递归地构建下一个段。 

回溯效果很好，因为：

 - 我们只需要四个部分。 
- 每个段都有严格的有效性规则。 
- 无效路径可以立即修剪。 

例如：

 - 如果一个段开始于`'0'`，我们应该在考虑个位数后停止`"0"`。 
- 如果一个段大于 255，我们将停止探索该分支。 

这种修剪极大地减少了不必要的计算。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(1) | O(1) | O(1) | O(1) | 最多固定数量的分区，但探索所有组合而不进行修剪 |
 | 最佳 | O(1) | O(1) | O(1) | O(1) | 通过剪枝回溯，仅探索有效的段结构 |

 虽然复杂性在技术上是恒定的，因为有效处理的最大输入长度受 12 限制，但回溯方法在实践中明显更干净、更高效。 

## 算法演练

 1. 首先检查IP地址的字符串长度是否有效。 如果长度小于4或大于12，则立即返回空列表，因为不存在有效的IP地址。 
2. 使用三条信息启动回溯功能：

 - 字符串中的当前索引
 - 到目前为止选择的部分
 - 结果列表
 3. 如果我们已经有 4 个段：

 - 检查我们是否已经消耗了整个字符串。 
- 如果是，请使用点连接段并将 IP 地址添加到结果中。 
- 如果仍有字符，则该路径无效。 
4. 对于当前段，尝试从当前索引中取出 1、2 或 3 位数字。 
5. 对于每个候选细分：

 - 确保我们不会超出字符串的末尾。 
- 拒绝带有前导零的段，除非该段完全正确`"0"`。 
- 将段转换为整数并确保其最大为 255。 
6. 如果该段有效：

 - 将其添加到当前路径。 
- 递归处理字符串的下一部分。 
- 之后删除该段以恢复下一个选择的状态。 
7. 继续，直到探索完所有有效组合。 

### 为什么它有效

 该算法之所以有效，是因为每个递归调用都代表部分 IP 地址构造。 在每一步中，我们仅使用有效段来扩展路径。 由于探索了从 1 到 3 的每个可能的有效段长度，因此最终生成每个有效的 IP 地址。 无效路径会被立即丢弃，保证正确性和效率。 

## Python 解决方案```python
from typing import List

class Solution:
    def restoreIpAddresses(self, s: str) -> List[str]:
        result = []

        if len(s) < 4 or len(s) > 12:
            return result

        def backtrack(index: int, segments: List[str]) -> None:
            if len(segments) == 4:
                if index == len(s):
                    result.append(".".join(segments))
                return

            for length in range(1, 4):
                if index + length > len(s):
                    break

                segment = s[index:index + length]

                if len(segment) > 1 and segment[0] == "0":
                    continue

                if int(segment) > 255:
                    continue

                segments.append(segment)
                backtrack(index + length, segments)
                segments.pop()

        backtrack(0, [])

        return result
```实施从早期长度检查开始。 由于有效的 IP 地址需要正好四个段，并且每个段最多可以包含三位数字，因此范围之外的任何字符串`[4, 12]`可以立即拒绝。 

这`backtrack`函数递归地构建候选 IP 地址。 这`index`变量跟踪输入字符串的消耗量，而`segments`存储 IP 地址的当前选定部分。 

当已经选择了四个段时，就会出现基本情况。 此时，算法会检查整个字符串是否已被使用。 如果是，则将这些段用点连接起来并添加到结果列表中。 

在循环内，算法尝试段长度 1、2 和 3。这与 IPv4 地址的规则匹配，因为每个段最多可以包含三位数字。 

前导零验证尤其重要。 如果一个段有多个字符并且以`'0'`，立即跳过。 

数字范围验证确保没有段超出`255`。 

追加和弹出操作实现了经典的回溯行为。 递归探索一个分支后，该段将被删除，以便下一个分支以干净的状态开始。 

## 解决方案```go
package main

import (
	"strconv"
	"strings"
)

func restoreIpAddresses(s string) []string {
	var result []string

	if len(s) < 4 || len(s) > 12 {
		return result
	}

	var backtrack func(index int, segments []string)

	backtrack = func(index int, segments []string) {
		if len(segments) == 4 {
			if index == len(s) {
				result = append(result, strings.Join(segments, "."))
			}
			return
		}

		for length := 1; length <= 3; length++ {
			if index+length > len(s) {
				break
			}

			segment := s[index : index+length]

			if len(segment) > 1 && segment[0] == '0' {
				continue
			}

			value, _ := strconv.Atoi(segment)

			if value > 255 {
				continue
			}

			segments = append(segments, segment)
			backtrack(index+length, segments)
			segments = segments[:len(segments)-1]
		}
	}

	backtrack(0, []string{})

	return result
}
```Go 实现遵循与 Python 版本相同的递归结构。 主要区别在于切片处理。 

在 Go 中，切片是数组上的可变视图，因此在附加段后，我们使用以下方法显式缩小切片：```go
segments = segments[:len(segments)-1]
```这会在回溯期间恢复之前的状态。 

这`strconv.Atoi`函数将字符串段转换为整数以进行范围验证。 由于输入仅包含数字，因此在此问题中不可能出现转换错误。 

结果切片被初始化为空切片而不是`nil`，这确保了干净的返回行为。

 ## 边缘情况

 ### 前导零

 包含零的输入是最常见的错误来源之一。 例如，`"01"`不是一个有效的段，即使它的整数值为`1`。 一个幼稚的实现可能会意外地允许它。 

该解决方案通过检查来处理此问题：```
if len(segment) > 1 and segment[0] == "0":
```这确保只有单个字符`"0"`是允许的。 

### 大于 255 的段

 IP 段必须保持在该范围内`[0, 255]`。 字符串像`"256"`或者`"999"`必须被拒绝。 

该实现将每个候选段转换为整数，并立即跳过任何大于的值`255`。 

这种修剪可以防止无效路径继续深入递归。 

### 长度无效的字符串

 有效的 IP 地址需要正好四个段，每个段包含 1 到 3 位数字。 

这意味着：

 - 最小长度为 4
 - 最大长度为 12

 超出此范围的输入永远无法产生有效的答案。 如果没有这种早期检查，递归算法就会浪费时间探索不可能的状态。 

该实现一开始就立即处理这个问题：```
if len(s) < 4 or len(s) > 12:
    return result
```这使得解决方案更加高效并避免不必要的递归。
