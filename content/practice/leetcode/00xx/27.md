[LeetCode 第 27 题](https://leetcode.com/problems/remove-element/)

 **难度：** 🟢简单
 **主题：** 数组、两个指针

 ## 解决方案

 ## 问题理解

 问题给了我们一个整数数组`nums`和目标值`val`。 我们的任务是消除所有出现的`val`从数组中获取，但我们必须就地进行。 这意味着我们不应该创建另一个数组并返回它。 相反，我们直接修改原始数组。 

该函数应返回一个整数`k`，它表示删除所有实例后剩余的元素数`val`。 操作完成后，首先`k`的职位`nums`必须仅包含不等于的值`val`。 

一个重要的细节是其余元素的顺序并不重要。 该问题明确允许在需要时重新排列元素。 此外，任何超出索引的内容`k - 1`被法官忽略，所以这些值并不重要。 

例如，如果：```
nums = [3,2,2,3], val = 3
```全部删除后`3`也就是说，数组可能会变成：```
[2,2,_,_]
```下划线表示数组有效部分结束后不相关的位置。 

限制非常小：

 -`0 <= nums.length <= 100`-`0 <= nums[i] <= 50`-`0 <= val <= 100`由于数组长度最多为 100，因此即使效率较低的方法在技术上也可以通过。 然而，该问题的目标是练习就地数组操作和两指针技术。 

需要考虑一些重要的边缘情况：

 - 数组可能为空。 
- 每个元素都可以相等`val`。 
- 没有元素可以相等`val`。 
- 目标值可能连续出现多次。 
- 目标值可能出现在数组的开头或结尾。 

正确的解决方案必须安全地处理所有这些问题，而不会访问无效索引或返回错误的计数。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是创建一个新的临时数组，仅存储不等于的元素`val`。 

我们迭代`nums`，每当我们看到一个不同于`val`，我们将其附加到临时数组中。 遍历完成后，我们将临时数组的内容复制回`nums`。 

这种方法是正确的，因为每个非目标元素都只保留一次，并且每个目标元素都会被跳过。 

但是，此解决方案使用与数组大小成比例的额外内存。 该问题特别要求就地解决方案，因此虽然这在逻辑上可行，但它不能满足预期的优化要求。 

### 最优方法，两个指针

 关键的见解是我们实际上不需要另一个数组。 我们只需要跟踪下一个有效元素应该写入的位置。 

我们使用两个指针：

 - 一个读取指针，扫描数组中的每个元素
 - 一个写指针，跟踪非写入的下一个位置`val`应放置元素

 每当读指针找到应该保留的值时，我们就将其复制到写指针位置并前进写指针。 

到最后：

 - 所有有效元素都被压缩到数组的前面
 - 写指针值等于有效元素的数量

 这是有效的，因为每个保留的元素都被写入最早的可用有效位置一次。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 使用额外的数组来存储有效元素 |
 | 最佳 | O(n) | O(1) | O(1) | 使用两个指针并就地修改数组 |

 ## 算法演练

 1. 初始化一个名为`write_index`到`0`。 

该指针表示应写入有效元素的下一个位置。 
2. 使用循环遍历数组。 

每个元素都被检查一次。 
3. 对于每个元素，检查它是否与`val`。 

如果它等于`val`，我们跳过它，因为它应该被删除。 
4. 如果当前元素不等于`val`，将其复制到`nums[write_index]`。 

这可确保所有有效元素都排列在数组的前面。 
5. 增量`write_index`。 

放置一个有效元素后，下一个有效元素应该进入下一个位置。 
6. 继续，直到处理完整个数组。 
7. 返回`write_index`。 

该值表示不等于的元素数量`val`。 

### 为什么它有效

 该算法保持了之前所有位置的不变性`write_index`包含不等于的有效元素`val`。 

每次遇到有效元素时，我们都会将其放入下一个可用的有效位置。 由于每个数组元素都被处理一次，并且只有非目标元素被向前复制，因此第一个`k`当循环结束时，数组的元素将恰好包含所需的值。 

## Python 解决方案```python
from typing import List

class Solution:
    def removeElement(self, nums: List[int], val: int) -> int:
        write_index = 0

        for num in nums:
            if num != val:
                nums[write_index] = num
                write_index += 1

        return write_index
```实现从初始化开始`write_index`到`0`。 该变量跟踪应存储有效元素的下一个位置。 

循环遍历中的每个值`nums`。 对于每个元素，代码检查它是否不同于`val`。 

如果应该保留该元素，则将其复制到`nums[write_index]`。 然后`write_index`递增，因此下一个有效元素将紧随其后放置。 

元素等于`val`被完全忽略，这实际上将它们从数组的有效部分中删除。 

最后，函数返回`write_index`，它等于剩余有效元素的数量。 

## 解决方案```go
func removeElement(nums []int, val int) int {
    writeIndex := 0

    for _, num := range nums {
        if num != val {
            nums[writeIndex] = num
            writeIndex++
        }
    }

    return writeIndex
}
```Go 实现遵循与 Python 版本相同的逻辑。 

Go 切片是类似引用的结构，因此修改`nums`函数内部直接更新原始底层数组。 无需额外分配。 

由于数组大小非常小，因此无需特别担心整数溢出。 空切片自然会被处理，因为循环只执行零次。

 ## 边缘情况

 ### 空数组

 空数组是一种常见的边缘情况，因为如果不小心处理，循环和索引操作可能会失败。 在此实现中，循环仅执行零次，并且`write_index`遗迹`0`。 函数正确返回`0`。 

### 所有元素等于`val`如果每个元素都与目标值匹配，则算法应删除所有元素。 有缺陷的实现可能会意外地将过时的值留在有效范围内或返回错误的计数。 

该解决方案跳过每个元素，因此`write_index`永远不会增加。 返回的结果是`0`，它正确地表明没有剩余有效元素。 

### 没有元素等于`val`如果目标值从未出现，则数组应保持不变，并且返回的长度应等于原始数组大小。 

该算法自然地处理这个问题，因为每个元素都通过`num != val`健康）状况。 每个值都被复制回其自己的位置，并且`write_index`最终等于`len(nums)`。 

### 连续目标值

 在某些实现中，连续的可移动元素可能会暴露指针移动错误。 例如，重复向左移动元素可能会意外地跳过值。 

两指针方法完全避免了这个问题，因为读指针始终在数组中独立移动，而写指针仅在找到有效元素时才前进。 连续的目标值被简单地一个接一个地跳过。
