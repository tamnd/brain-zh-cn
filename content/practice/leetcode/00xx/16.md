 **难度：** 🟡 中等
 **主题：** 数组、两个指针、排序

 ## 解决方案

 ## 问题理解

 问题给了我们一个整数数组`nums`和一个目标整数`target`。 我们必须使用不同的索引从数组中选择三个元素，并计算它们的总和。 在所有可能的三数和中，我们想要最接近目标值的那个。 

重要的细节是，我们并不是试图找到一个完全等于目标的总和，尽管这种情况可能会发生。 相反，我们最小化绝对差异：$$|(\text{sum of three numbers}) - \text{target}|$$该函数应该返回实际的总和，而不是索引，也不是差值。 

例如，如果`nums = [-1,2,1,-4]`和`target = 1`，可能的三数和为：

 -`-1 + 2 + 1 = 2`-`-1 + 2 + (-4) = -3`-`-1 + 1 + (-4) = -4`-`2 + 1 + (-4) = -1`价值`2`最接近`1`， 自从：$$|2 - 1| = 1$$它小于所有其他总和的差异。 

约束很重要，因为它们指导算法的选择：

 -`3 <= nums.length <= 500`- 每个值都介于`-1000`和`1000`500 的数组大小足够大，三次暴力解法在某些语言中仍然可以通过，但效率低下且不理想。 由于这是一个中等难度的问题，重点关注数组、排序和两个指针，因此我们应该期待一个更优化的解决方案。 

有几种边缘情况值得立即考虑：

 - 包含所有相同值的数组，例如`[0,0,0]`- 包含许多负数的数组
 - 包含许多正数的数组
 - 可以实现确切目标的情况
 - 尽管问题保证只有一个有效答案，但多项总和都相等的情况
 - 尽可能小的数组大小，恰好是 3 个元素

 该问题保证了总是存在一个解决方案，因此我们永远不需要处理不可能的情况。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查三个不同指数的每种可能的组合。 

我们可以使用三个嵌套循环：

 - 第一个循环选择第一个数字
 - 第二次循环选择第二个数字
 - 第三次循环选择第三个数字

 对于每个三元组，我们计算总和并将其与目标的距离与迄今为止看到的最佳结果进行比较。 

这种方法是正确的，因为它详尽地检查了每个有效组合。 由于对每个可能的三元组进行了评估，因此不会错过最接近的总和。 

然而，时间复杂度非常昂贵。 通过三个嵌套循环，复杂性变为：$$O(n^3)$$如果`n = 500`， 然后：$$500^3 = 125,000,000$$这远远超出了必要的工作量。 

### 最优方法，排序+两个指针

 关键的观察是，一旦数组排序，我们就可以使用两指针技术有效地调整总和。 

假设我们在索引处固定一个数字`i`。 然后我们需要找到两个额外的数字，它们的总和使我们尽可能接近目标。 

排序后：

 - 如果当前总和太小，我们可以向右移动左指针来增加总和
 - 如果当前总和太大，我们可以将右指针向左移动来减少总和

 由于数组已排序，因此指针移动变得有意义且具有确定性。 

我们不是独立检查每个三元组，而是智能地消除大部分搜索空间。 

这降低了复杂性：$$O(n^3)$$到：$$O(n^2)$$这更有效率。

 ## 算法演练

 1. 将数组按升序排序。 

排序至关重要，因为两指针技术依赖于有序值。 排序后，向左或向右移动指针可以预见地改变总和。 
2. 初始化最接近的和。 

常见的策略是使用前三个元素的总和作为初始答案。 这保证了我们从一个有效的三元组开始。 
3. 使用索引迭代数组`i`。 

在每个位置上，`nums[i]`成为三元组的固定第一个元素。 
4. 设置两个指针。 

对于每个固定索引：

 -`left = i + 1`-`right = len(nums) - 1`这些指针搜索最好的剩余对。 
5. 计算当前总和。 

步步：$$\text{currentSum} = nums[i] + nums[left] + nums[right]$$6. 如果需要，更新最接近的答案。 

比较：$$|\text{currentSum} - target|$$反对：$$|\text{closestSum} - target|$$如果当前总和更接近，则替换存储的答案。 
7. 决定如何移动指针。 

- 如果`currentSum < target`，总和太小，所以移动`left`向右增加它。 
- 如果`currentSum > target`，总和太大，所以移动`right`向左移动以减少它。 
- 如果`currentSum == target`，我们找到了最佳答案并可以立即返回。 
8. 继续直到指针交叉。 

一次`left >= right`，当前固定元素的所有对都已被探索。 
9. 返回最接近的总和。 

### 为什么它有效

 正确性取决于数组的排序顺序。 

对于固定的第一个元素：

 - 向右移动左指针会增加总和
 - 向左移动右指针会减少总和

 这保证了以结构化方式探索每个相关候选对，而不会错过任何可能更好的结果。 由于我们对每个可能的第一个元素重复此过程，因此保证找到全局最接近的三元组和。 

## Python 解决方案```python
from typing import List

class Solution:
    def threeSumClosest(self, nums: List[int], target: int) -> int:
        nums.sort()

        closest_sum = nums[0] + nums[1] + nums[2]

        for i in range(len(nums) - 2):
            left = i + 1
            right = len(nums) - 1

            while left < right:
                current_sum = nums[i] + nums[left] + nums[right]

                if abs(current_sum - target) < abs(closest_sum - target):
                    closest_sum = current_sum

                if current_sum < target:
                    left += 1
                elif current_sum > target:
                    right -= 1
                else:
                    return current_sum

        return closest_sum
```实现首先对数组进行排序。 这使得两指针策略成为可能，因为增加或减少指针位置现在可以预见地影响总和。 

变量`closest_sum`存储迄今为止找到的最佳答案。 使用前三个数字对其进行初始化可保证有效的起始值。 

外循环修复索引处的一个元素`i`。 对于每个固定值，算法使用两个指针搜索最佳对。 

里面的`while left < right`循环，计算当前三元组和。 如果这个总和比之前的最佳结果更接近目标，我们就更新`closest_sum`。 

指针移动逻辑是核心优化：

 - 如果总和太小，则移动`left`向右
 - 如果总和太大，则移动`right`向左
 - 如果总和恰好等于目标值，则立即返回

 这个过程系统地探索了二次时间内所有有用的组合。 

## 解决方案```go
package main

import (
	"math"
	"sort"
)

func threeSumClosest(nums []int, target int) int {
	sort.Ints(nums)

	closestSum := nums[0] + nums[1] + nums[2]

	for i := 0; i < len(nums)-2; i++ {
		left := i + 1
		right := len(nums) - 1

		for left < right {
			currentSum := nums[i] + nums[left] + nums[right]

			if math.Abs(float64(currentSum-target)) <
				math.Abs(float64(closestSum-target)) {
				closestSum = currentSum
			}

			if currentSum < target {
				left++
			} else if currentSum > target {
				right--
			} else {
				return currentSum
			}
		}
	}

	return closestSum
}
```Go 的实现与 Python 版本非常相似。 主要差异是特定于语言的。 

Go 需要使用显式排序`sort.Ints(nums)`。 

这`math.Abs`函数运行于`float64`，因此在比较之前必须转换整数差异。 

Go 中的切片的行为已经与动态数组类似，因此索引不需要特殊处理。 

整数溢出在这里不是一个问题，因为约束很小。 最大可能的总和幅度完全在 Go 的整数范围内。

 ## 边缘情况

 一种重要的边缘情况是最小有效输入大小，其中数组恰好包含三个元素。 在这种情况下，只有一个可能的三元组，因此算法必须立即返回该总和。 由于实现初始化`closest_sum`使用前三个元素并且仍然正确执行循环，这种情况可以自然地工作，不需要特殊处理。 

另一个重要的情况涉及所有数字都相同的数组，例如`[0,0,0]`。 当总和保持不变时，某些实现会意外地错误地移动指针或无法正确更新答案。 在这里，算法正确地计算出唯一可用的总和并返回它。 

当可以形成精确目标时，就会出现第三种关键边缘情况。 由于没有任何总和可以比精确匹配更接近，因此继续搜索会浪费时间。 该实现通过立即返回来有效地处理这个问题`current_sum == target`。 

包含较大正值和负值的数组也很重要。 这些情况可能会暴露指针移动逻辑中的错误，因为总和可能会随着指针移动而剧烈波动。 由于数组已排序并且指针调整完全基于总和是否太小或太大，因此无论值分布如何，实现都保持正确。
