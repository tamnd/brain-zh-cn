 # LeetCode 96 - 独特的二叉搜索树

 ## 问题理解

 这个问题要求我们确定使用以下整数可以形成多少个结构不同的二叉搜索树（BST）：`1`到`n`。 

二叉搜索树有一个重要的属性：

 - 左子树中的每个值都小于根。 
- 右子树中的每个值都大于根。 

输入是单个整数`n`，它表示有多少个不同的值可用。 这些值本身固定为整数`1`通过`n`。 

输出是可以使用所有构建的唯一 BST 结构的总数`n`值恰好一次。 

关键细节是我们关心结构，而不是插入顺序。 如果两个 BST 的形状不同，即使它们包含相同的值，也被认为是不同的。 

例如，当`n = 3`，可能的 BST 结构是：

 - Root = 1，所有剩余节点都在右侧
 - Root = 2，每侧一个节点
 - Root = 3，所有剩余节点都在左侧
 - 额外的结构不同的子树排列

 这总共产生 5 个独特的 BST。 

约束条件是：```
1 <= n <= 19
```这是一个相对较小的输入大小，这表明动态规划是可行的。 然而，由于 BST 的数量快速增长，每个树结构的简单递归生成仍然会变得非常昂贵。 

一个重要的观察结果是，实际数值并不像子树中的节点数那么重要。 任意序列`k`有序值产生相同数量的 BST 结构。 

一些重要的边缘情况包括：

 -`n = 1`，其中只有一棵树是可能的。 
- 非常小的值，例如`n = 2`，其中左重树和右重树必须分别计算。 
- 附近较大的值`19`，如果没有记忆或自下而上的 DP，递归重新计算会变得昂贵。 

## 方法

 ### 蛮力方法

 暴力解决方案将递归地生成所有可能的 BST。 

对于每个可能的根值：

 1. 递归生成所有可能的左子树。 
2. 递归生成所有可能的右子树。 
3. 将每个左子树与每个右子树组合。 

这种方法是正确的，因为每个 BST 必须恰好选择一个根，并且每个有效的左子树和右子树组合都会生成唯一的 BST。 

然而，相同的子树大小会被重复重新计算。 例如，在求解时`n = 5`，BST 的数量`3`节点可能被计算多次。 

递归爆炸使得暴力解决方案效率极低。 

### 最优方法，动态规划

 关键的见解是，唯一 BST 的数量仅取决于树中的节点数量，而不取决于实际值。 

假设我们定义：```
dp[i] = number of unique BSTs using i nodes
```计算`dp[i]`，我们尝试将每个节点作为根。 

如果根将树分成：

 -`left_nodes`-`right_nodes`然后：```
total_trees = dp[left_nodes] * dp[right_nodes]
```这种乘法之所以有效，是因为每个左子树都可以与每个右子树配对。 

我们总结了所有可能的根选择。 

这创建了一个经典的动态规划递归，称为加泰罗尼亚数递归。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | 指数| 指数| 重复递归生成所有 BST 组合 |
 | 最佳 | O(n²) | O(n) | 使用 Catalan 递归的自下而上 DP |

 ## 算法演练

 1. 创建一个DP数组，名称为`dp`尺寸的`n + 1`。 

各指标`i`表示可以使用精确构建的唯一 BST 的数量`i`节点。 
2. 初始化基本案例。 

我们设定：```
dp[0] = 1
dp[1] = 1
```

`dp[0] = 1`意味着空子树算作一个有效配置。 这很重要，因为根可能没有左子节点或右子节点。 
3. 迭代自`2`到`n`。 

对于每个节点数`nodes`，计算可能的 BST 数量。 
4. 尝试将每个节点作为根。 

如果根位于`root`， 然后：```
left_nodes = root - 1
right_nodes = nodes - root
```5. 计算子树组合。 

用该根形成的 BST 的数量为：```
dp[left_nodes] * dp[right_nodes]
```这种乘法之所以有效，是因为每个左子树都可以独立地与每个右子树组合。 
6. 将组合添加到总数中。 

将所有可能的根配置累积到`dp[nodes]`。 
7. 返回`dp[n]`。 

填充DP表后，原问题的答案存储在索引处`n`。 

### 为什么它有效

 该算法之所以有效，是因为每个 BST 都可以通过其根选择及其左右子树的结构来唯一定义。 

对于固定根：

 - 所有较小的值必须出现在左子树中。 
- 所有较大的值必须出现在右子树中。 

由于子树结构是独立的，因此根的树总数是左子树可能性和右子树可能性的数量的乘积。 

对每个可能的根求和可保证每个有效的 BST 结构都被精确计数一次。 

## Python 解决方案```python
class Solution:
    def numTrees(self, n: int) -> int:
        dp = [0] * (n + 1)

        dp[0] = 1
        dp[1] = 1

        for nodes in range(2, n + 1):
            total = 0

            for root in range(1, nodes + 1):
                left_nodes = root - 1
                right_nodes = nodes - root

                total += dp[left_nodes] * dp[right_nodes]

            dp[nodes] = total

        return dp[n]
```该实现首先创建一个 DP 数组，其中每个索引存储该子树大小可能的 BST 数量。 

首先初始化基本情况。 一棵空树和一棵单节点树都有一个有效的结构。 

外循环迭代每个子树大小`2`到`n`。 

在该循环内，测试每个可能的根位置。 选择根会自动确定有多少节点属于左子树和多少属于右子树。 

产品：```python
dp[left_nodes] * dp[right_nodes]
```计算左子树结构和右子树结构的每种可能的组合。 

处理完所有根选择后，该子树大小的 BST 总数将存储在 DP 表中。 

最后算法返回`dp[n]`。 

## 解决方案```go
func numTrees(n int) int {
    dp := make([]int, n+1)

    dp[0] = 1
    dp[1] = 1

    for nodes := 2; nodes <= n; nodes++ {
        total := 0

        for root := 1; root <= nodes; root++ {
            leftNodes := root - 1
            rightNodes := nodes - root

            total += dp[leftNodes] * dp[rightNodes]
        }

        dp[nodes] = total
    }

    return dp[n]
}
```Go 实现遵循与 Python 版本相同的自下而上动态编程策略。 

使用切片而不是 Python 列表。 整数运算是安全的，因为约束保证结果符合 Go 针对该问题的标准整数范围。 

与 Python 不同，Go 需要显式变量声明并使用驼峰式命名约定。

 ## 边缘情况

 一个重要的边缘情况是`n = 1`。 幼稚的实现可能会意外地将单节点树视为具有零个组合，因为没有子子树。 DP 基本情况正确定义`dp[1] = 1`，确保计算出单个有效的 BST。 

另一个重要的情况是处理空子树。 当根为最小值或最大值时，树的一侧包含零个节点。 如果`dp[0]`被初始化为`0`而不是`1`，所有边-根配置都会错误地贡献零组合。 将空树定义为一个有效配置可以解决此问题。 

第三个重要的边缘情况涉及更大的值，例如`n = 19`。 没有记忆的纯递归会重复地重新计算相同的子树计数并且变得非常慢。 动态编程解决方案存储中间结果，因此每个子树大小只计算一次。 

一个微妙的边缘情况是确保正确计算左子树和右子树的大小。 相差一的错误在这里很常见。 该实现仔细地使用了：```
left_nodes = root - 1
right_nodes = nodes - root
```这保证了除根之外的每个节点都恰好分配给一个子树。
