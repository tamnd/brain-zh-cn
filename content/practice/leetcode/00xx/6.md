[LeetCode 问题 6](https://leetcode.com/problems/zigzag-conversion/)

 **难度：** 🟡 中等
 **主题：** 字符串

 ## 解决方案

 ## 问题理解

 该问题要求我们将字符串转换为跨固定行数的锯齿形图案，然后逐行读取字符以产生最终结果。 

例如，如果输入字符串是`"PAYPALISHIRING"`行数是`3`，之字形布局如下所示：```
P   A   H   N
A P L S I I G
Y   I   R
```通过在行中垂直向下移动，然后对角向上移动来写入字符，重复此动作直到放置完所有字符。 构建此模式后，我们从左到右读取每一行并将它们连接在一起。 

此示例的预期输出是：```
"PAHNAPLSIIGYIR"
```输入包括：

 - 一根绳子`s`- 一个整数`numRows`输出是通过逐行读取锯齿形图案形成的新字符串。 

限制相对较小：

 -`1 <= s.length <= 1000`-`1 <= numRows <= 1000`由于最大字符串长度仅为 1000，`O(n)`或者`O(n * numRows)`解决方案是完全可以接受的。 然而，问题主要在于正确模拟之字形遍历，而不是处理性能限制。 

一些边缘情况很重要：

 - 如果`numRows == 1`，没有锯齿形运动。 该字符串保持不变。 
- 如果`numRows >= len(s)`，在发生任何向上对角线移动之前，每个字符实际上占据自己的行，因此输出也是原始字符串。 
- 长度非常小的字符串可能会暴露不正确的方向切换逻辑。 
- 行边界处理不正确很容易导致索引错误或字符放错位置。 

核心挑战是正确管理行之间的移动。 

## 方法

 ### 蛮力方法

 强力方法将明确构建整个二维锯齿形矩阵。 

我们可以估计所需的列数，创建一个填充空字符的网格，然后在将字符放入网格时模拟向下和向上遍历。 填充完矩阵后，我们将逐行扫描它并收集所有非空字符。 

这种方法之所以有效，是因为它直接对锯齿形结构进行建模，完全按照问题陈述中的描述进行。 然而，它浪费了空间，因为矩阵中的大多数单元格仍然是空的，特别是在对角线移动期间。 

实现也变得不必要的复杂，因为我们必须仔细管理行和列的移动，同时避免未使用的位置。 

### 最佳方法

 关键的观察是我们实际上并不需要完整的矩阵。 

最终答案仅取决于每行收集的字符。 我们可以为每一行维护一个单独的字符串生成器，而不是将每个位置存储在二维网格中。 

当我们迭代输入字符串时：

 - 我们将每个字符附加到当前行
 - 我们向下穿过行
 - 一旦我们到达底排，我们就反转方向
 - 然后我们沿对角线向上移动
 - 一旦我们到达顶排，我们再次反转方向

 这直接模拟锯齿形遍历，同时仅存储必要的数据。 

这种方法既简单又节省内存。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 使用许多未使用的单元构建显式锯齿形矩阵 |
 | 最佳 | O(n) | O(n) | 使用行构建器直接模拟行遍历 |

 ## 算法演练

 1. 首先处理琐碎的边缘情况。 

如果`numRows == 1`或者`numRows >= len(s)`，立即返回原始字符串。 在这些情况下，不会发生锯齿形变换。 
2. 为每一行创建存储。 

我们维护一个数组，其中每个元素代表锯齿形图案的一行。 每行存储分配给它的字符。 
3.初始化遍历状态。 

我们追踪：

 -`current_row`,当前接收字符的行
 -`direction`，它决定了我们是向下还是向上移动

 最初：

 -`current_row = 0`-`direction = 1`，表示向下运动
 4. 处理字符串中的每个字符。 

对于每个角色：

 - 将其附加到当前行
 - 如果我们点击顶行或底行，则更新方向
 - 根据方向移动到下一行
 5. 在边界处反转方向。 

当我们到达：

 - 最下面一排，切换方向向上
 - 最上面一排，切换方向向下

 这将创建之字形遍历模式。 
6. 合并所有行。 

处理完所有字符后，将每一行连接在一起以形成最终答案。 

### 为什么它有效

 在每一步中，该算法都保持不变，即每个字符都附加到与实际之字形布局中占据的完全相同的行。 

方向切换逻辑保证遍历遵循所需的模式：

 - 直线向下运动
 - 然后对角向上运动
 - 然后重复

 由于在遍历过程中字符是逐行存储的，因此在末尾连接行会准确产生所需的输出。 

## Python 解决方案```python
class Solution:
    def convert(self, s: str, numRows: int) -> str:
        if numRows == 1 or numRows >= len(s):
            return s

        rows = [""] * numRows

        current_row = 0
        direction = 1

        for char in s:
            rows[current_row] += char

            if current_row == 0:
                direction = 1
            elif current_row == numRows - 1:
                direction = -1

            current_row += direction

        return "".join(rows)
```该实现首先处理不需要锯齿形转换的边缘情况。 这可以避免错误的方向变化并简化其余逻辑。 

这`rows`数组存储属于每个锯齿形行的字符。 当我们遍历字符串时，每个条目都会累积字符。 

变量`current_row`跟踪下一个字符应该放置的位置。 这`direction`变量控制运动：

 -`1`意味着向下移动
 -`-1`意味着向上移动

 对于每个角色：

 - 该字符附加到当前行
 - 我们检查是否到达顶部或底部
 - 如果是这样，我们就反转方向
 - 然后我们移动到下一行

 最后，`"".join(rows)`将所有行连接成所需的答案。 

## 解决方案```go
func convert(s string, numRows int) string {
    if numRows == 1 || numRows >= len(s) {
        return s
    }

    rows := make([]string, numRows)

    currentRow := 0
    direction := 1

    for _, char := range s {
        rows[currentRow] += string(char)

        if currentRow == 0 {
            direction = 1
        } else if currentRow == numRows-1 {
            direction = -1
        }

        currentRow += direction
    }

    result := ""

    for _, row := range rows {
        result += row
    }

    return result
}
```Go 实现遵循与 Python 版本相同的逻辑。 

字符串切片用于存储行内容。 由于 Go 字符串是不可变的，因此连接会在内部创建新字符串，考虑到约束大小较小，这是可以接受的。 

该循环使用 Unicode 符文进行迭代`range`，确保正确的字符处理。 

方向切换逻辑是相同的：

 - 向下移动直到最后一行
 - 向上反向直到第一行
 - 重复

 最后，所有行都连接到结果字符串中。

 ## 边缘情况

 ### 单排

 当`numRows == 1`，没有向下和向上的运动。 盲目应用方向更改的幼稚实现可能会错误地尝试在不存在的行之间移动。 

该解决方案通过在任何遍历逻辑开始之前返回原始字符串来立即处理此问题。 

### 行数多于字符数

 如果`numRows >= len(s)`，在发生任何对角线移动之前，每个字符都会简单地占据一个单独的行。 

如果没有特殊处理，某些实现可能会错误地反转方向或访问无效的行索引。 返回原始字符串完全避免了这些问题。 

### 边界处的方向转换

 最常见的错误之一是到达第一行或最后一行时方向反转不正确。 

例如，到达底行后，算法必须立即切换到向上移动，然后再处理下一个字符。 如果不这样做会导致索引错误或重复的行。 

该实现通过在插入每个字符后立即检查边界条件并在移动到下一行之前更新方向来解决此问题。
