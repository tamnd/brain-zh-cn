[LeetCode 第 32 题](https://leetcode.com/problems/longest-valid-parentheses/)

 **难度：** 🔴难
 **主题：** 字符串、动态规划、堆栈

 ## 解决方案

 ## 问题理解

 该问题要求我们找到形成有效括号序列的最长连续子串的长度。 有效的括号序列是每个左括号`'('`有相应的右括号`')'`，并且这些对正确嵌套。 

例如，字符串`"()()"`有效，因为每个左括号都正确匹配。 字符串`"(())"`也是有效的，因为允许嵌套对。 然而，字符串像`"(()"`或者`")("`不完全有效，因为某些括号仍然不匹配。 

输入是单个字符串`s`仅包含两个可能的字符，`'('`和`')'`。 输出应该是一个整数，表示任何连续有效括号子字符串的最大长度。 

约束条件很重要：

 - 字符串长度可以大到`3 * 10^4`- 仅存在括号字符

 这些限制立即告诉我们，低效的解决方案，尤其是具有三次复杂度的解决方案，可能会超时。 我们需要一种至少是线性或接近线性的算法。 

一些边缘情况尤其重要：

 - 应该返回一个空字符串`0`- 一个字符串仅`'('`或仅`')'`应该返回`0`- 开头或结尾带有不匹配括号的字符串仍然可以包含有效的子字符串
 - 嵌套有效结构，例如`"((()))"`必须正确处理
 - 连续的有效结构，例如`"()()()"`应该组合成一个更大的有效长度

 关键的挑战是确定如何有效地跟踪匹配的括号，同时确保子字符串保持连续且格式良好。 

## 方法

 ### 蛮力方法

 最直接的解决方案是检查每个可能的子字符串并确定它是否形成有效的括号序列。 

我们可以使用两个嵌套循环生成所有子字符串。 对于每个子字符串，我们使用余额计数器检查有效性：

 - 增量为`'('`- 递减`')'`- 如果余额变为负数，则子字符串无效
 - 最后，余额必须等于零，子字符串才有效

 每当我们找到有效的子字符串时，我们就会更新最大长度。 

这种方法是正确的，因为它显式地检查每个可能的候选子字符串。 然而，对于给定的限制来说，它太慢了。 有`O(n^2)`子字符串，验证每个子字符串可能需要`O(n)`时间，导致`O(n^3)`整体复杂性。 

和`n = 30000`，这是完全不切实际的。 

### 最佳解决方案的关键见解

 重要的观察是，我们不需要从头开始重复验证整个子字符串。 

相反，我们可以处理一次字符串，同时使用堆栈跟踪不匹配的括号位置。 

核心思想是：

 - 将左括号的索引推入堆栈
 - 遇到右括号时，尝试将其与最近未匹配的左括号进行匹配
 - 如果存在匹配，则计算当前有效子字符串的长度
 - 如果不存在匹配，则将当前位置标记为新边界

 使用索引而不是字符使我们能够直接有效地计算子字符串长度。 

这将问题转化为线性时间扫描。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n3) | O(1) | O(1) | 单独检查每个子字符串 |
 | 最佳堆栈解决方案| O(n) | O(n) | 使用索引堆栈来跟踪不匹配的括号 |

 ## 算法演练

 ### 最优堆栈算法

 1. 使用值初始化堆栈`-1`。 

堆栈存储索引，而不是字符。 最初的`-1`在字符串开始之前充当哨兵边界。 当有效子字符串从索引处开始时，这有助于正确计算长度`0`。 
2. 初始化变量`max_length = 0`。 

该变量跟踪迄今为止找到的最长的有效子字符串。 
3.使用索引逐字符遍历字符串`i`。 

我们需要索引，因为子字符串长度是使用索引差来计算的。 
4. 如果当前字符是`'('`，将其索引压入堆栈。 

左括号可能与未来的右括号匹配，因此我们存储它们的位置。 
5. 如果当前字符是`')'`，从堆栈中弹出。 

这表示尝试将当前右括号与最近未匹配的左括号进行匹配。 
6、出栈后，检查栈是否为空。 

如果堆栈变空，则意味着当前右括号没有匹配的左括号。 在这种情况下，将当前索引推送为新的边界标记。 
7. 如果出栈后栈不为空，则计算当前有效子串长度。 

长度为：$\text{current length} = i - \text{stack.top}$堆栈顶部现在表示当前有效子字符串开始之前的索引。 
8. 更新`max_length`如果当前有效长度更大。 
9. 继续，直到处理完整个字符串。 
10. 返回`max_length`。 

### 为什么它有效

 堆栈始终维护不匹配的括号边界的索引。 每当形成有效匹配时，当前索引与堆栈顶部之间的差给出以当前位置结束的最大有效子字符串的长度。 

哨兵值和不匹配的右括号确保无效区域正确重置子字符串边界。 这个不变量保证每个有效的子字符串长度都被准确地计算一次。 

## Python 解决方案```python
class Solution:
    def longestValidParentheses(self, s: str) -> int:
        stack = [-1]
        max_length = 0

        for index, char in enumerate(s):
            if char == '(':
                stack.append(index)
            else:
                stack.pop()

                if not stack:
                    stack.append(index)
                else:
                    current_length = index - stack[-1]
                    max_length = max(max_length, current_length)

        return max_length
```实现首先初始化堆栈`-1`。 此标记值简化了边界计算并避免了从索引开始的有效子字符串的特殊情况逻辑`0`。 

当我们迭代字符串时，左括号索引被推入堆栈，因为它们稍后可能会参与有效的对。 

当出现右括号时，我们从堆栈中弹出以表示将其与最近未匹配的左括号匹配。 

如果弹出后堆栈变空，则当前右括号没有有效匹配。 因此，我们将其索引推入新的无效边界。 

否则，当前索引和新栈顶之间的子字符串有效。 我们计算它的长度并更新最大答案。 

该算法对每个字符只处理一次，因此非常高效。 

## 解决方案```go
func longestValidParentheses(s string) int {
    stack := []int{-1}
    maxLength := 0

    for i, ch := range s {
        if ch == '(' {
            stack = append(stack, i)
        } else {
            stack = stack[:len(stack)-1]

            if len(stack) == 0 {
                stack = append(stack, i)
            } else {
                currentLength := i - stack[len(stack)-1]

                if currentLength > maxLength {
                    maxLength = currentLength
                }
            }
        }
    }

    return maxLength
}
```Go 实现遵循与 Python 版本相同的逻辑，但使用切片来模拟堆栈。 

附加到切片会推送一个元素，同时切片`stack[:len(stack)-1]`删除顶部元素。 

Go 字符串是 UTF-8 编码的，但由于输入仅包含 ASCII 括号字符，因此迭代`range`安全高效。 

不存在整数溢出问题，因为最大字符串长度仅为`30000`。

 ## 边缘情况

 一种重要的边缘情况是空字符串。 幼稚的实现可能会意外地假设至少存在一个字符并尝试无效的堆栈操作。 在此解决方案中，循环根本不会执行，并且`max_length`遗迹`0`，这是正确的结果。 

另一个关键的边缘情况是以不匹配的右括号开头的字符串，例如`")()())"`。 如果不仔细处理边界，子串长度可能会变为负数或错误地跨越无效区域。 哨兵和边界重置逻辑通过将不匹配的右括号的索引压入堆栈来解决此问题。 

第三个重要的情况涉及深度嵌套的有效结构，例如`"(((())))"`。 一些不正确的实现仅处理相邻对并且无法正确合并嵌套区域。 这种基于堆栈的方法自然可以处理嵌套，因为每个右括号都与最近不匹配的左括号相匹配。 

第四种微妙情况是多个连续的有效区域，例如`"()()"`或者`"()(())"`。 该算法正确地组合了相邻的有效序列，因为堆栈在当前有效子字符串开始之前维护边界，从而允许长度扩展到多个匹配对。
