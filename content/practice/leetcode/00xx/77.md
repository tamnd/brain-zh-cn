[LeetCode 第 77 题](https://leetcode.com/problems/combinations/)

 **难度：** 🟡 中等
 **主题：** 回溯

 ## 解决方案

 ## 问题理解

 这个问题要求我们生成**所有可能的大小组合`k`** 从包含范围内的数字开始`[1, n]`。 

换句话说，我们有两个整数：

 -`n`，它定义了可用数字的范围`1`到`n`-`k`，它指定每个组合必须包含多少个数字

 任务是返回所有可能的方式来准确选择`k`与此范围不同的数字。 

一个关键细节是**顺序并不重要**。 例如，`[1,2]`和`[2,1]`代表相同的组合并且只能出现一次。 这意味着我们不会生成排列（排序很重要），而是生成组合（只有选定的元素很重要）。 

例如，如果`n = 4`和`k = 2`，可用的数字是`[1,2,3,4]`。 我们必须选择每一对独特的数字。 有效答案是：`[1,2]`,`[1,3]`,`[1,4]`,`[2,3]`,`[2,4]`， 和`[3,4]`。 

该问题保证：

 -`1 <= n <= 20`-`1 <= k <= n`这些限制很重要，因为组合的数量会快速增长。 例如：$$\binom{20}{10} = 184756$$这意味着任何有效的解决方案本质上都需要产生许多输出。 由于输出本身可能很大，因此有效生成组合而无需不必要的重复的算法变得很重要。 

这些约束还保证：

 -`k`永远不会大于`n`，因此始终至少存在一种有效组合。 
-`n`相对较小（`<= 20`），这使得递归搜索技术变得实用。 
- 我们永远不需要处理无效的输入，例如负数或空范围。 

需要考虑的一些重要的边缘情况包括以下情况`k = 1`,`k = n`， 或者`n`非常小。 例如，当`n = 1`和`k = 1`，只有一个可能的答案：`[[1]]`。 同样，当`k = n`，唯一有效的组合包含来自`1`到`n`。 

## 方法

 ### 蛮力方法

 强力解决方案将生成**每个可能的数字子集**`1`到`n`，然后仅过滤掉那些大小等于的子集`k`。 

由于每个数字都可以包含或排除，因此有`2^n`可能的子集。 对于每个子集，我们将检查它是否准确包含`k`元素并保留它（如果存在）。 

这种方法是正确的，因为它探索了每种可能的数字选择，保证找到所有有效的组合。 然而，它的效率很低，因为大多数生成的子集都是不相关的。 例如，如果`k = 2`，蛮力法仍然会生成大小的子集`0`,`1`,`3`，并且更大。 

因为`n`可以大到`20`，生成所有`2^20 = 1,048,576`子集变得不必要地昂贵。 

### 最优方法，回溯

 关键的见解是我们只需要构造**有效的大小组合`k`**，而不是生成每个可能的子集。 

回溯效果很好，因为组合可以逐步构建。 在每一步中，我们选择下一个数字并递归地继续构建当前组合。 

为了避免重复，我们总是按升序前进。 例如，选择后`2`，我们只考虑大于的数字`2`。 这确保了`[1,2]`和`[2,1]`永远不会同时生成。 

递归过程探索决策树：

 - 添加一个数字到当前组合
 - 递归继续构建
 - 之后删除该号码以探索其他可能性

 该技术系统地探索所有有效的组合，同时避免不必要的工作。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n × n) | O(2^n × n) | O(2^n × n) | O(2^n × n) | 生成所有子集，然后按大小过滤 |
 | 最佳| O(C(n,k) × k) | O(C(n,k) × k) | O(k) 不包括输出 | 使用回溯仅构建有效组合 |

 最佳方法要好得多，因为它只生成我们实际需要的组合。 

## 算法演练

 ### 最优算法，回溯

 1. 创建一个空结果列表来存储所有有效组合。 
2. 创建另一个列表，名为`current_combination`跟踪当前选择的号码。 
3. 定义一个递归函数，其参数为`start`价值。 这告诉我们接下来仍然可以选择哪些数字。 
4.如果长度`current_combination`等于`k`，我们已经完成了有效的组合。 将其副本添加到结果列表中并立即返回。 
5. 迭代所有数字`start`到`n`。 
6. 将当前号码添加到`current_combination`。 这代表选择该数字。 
7. 递归调用该函数`number + 1`。 这保证了未来的选择更大，防止重复并保留升序。 
8. 递归完成后，删除最后添加的数字。 这是回溯步骤，使我们能够探索替代选择。 
9. 继续，直到探索完所有递归路径。 

### 为什么它有效

 该算法保持了一个重要的不变量：`current_combination`始终按照严格递增的顺序构建。 因此，每个有效组合只会生成一次。 

每次递归调用都代表选择一个额外的数字，只有当恰好`k`号码已选定。 由于系统地探索了所有有效的选择并且不可能出现重复的排序，因此该算法保证了正确性。 

## Python 解决方案```python
from typing import List

class Solution:
    def combine(self, n: int, k: int) -> List[List[int]]:
        result = []
        current_combination = []

        def backtrack(start: int) -> None:
            if len(current_combination) == k:
                result.append(current_combination[:])
                return

            for number in range(start, n + 1):
                current_combination.append(number)
                backtrack(number + 1)
                current_combination.pop()

        backtrack(1)
        return result
```实现首先创建两个列表：`result`存储所有完成的组合和`current_combination`跟踪当前正在构建的组合。 

嵌套的`backtrack`函数执行递归搜索。 它接受一个`start`参数，它决定仍然可以选择的最小数字。 这可以防止重复组合并确保数字保持升序。 

基本情况检查是否`current_combination`已达到尺寸`k`。 如果是，则将当前列表的副本添加到`result`。 副本是必要的，因为列表是可变的，否则以后的修改会影响存储的结果。 

循环迭代自`start`通过`n`。 对于每个候选数字，算法会暂时将其包含在组合中，递归地探索进一步的选择，然后将其删除。 这种添加、递归、删除模式是回溯的本质。 

最后，该过程开始于`backtrack(1)`，这意味着我们首先考虑来自`1`通过`n`。 

## 解决方案```go
func combine(n int, k int) [][]int {
	var result [][]int
	currentCombination := []int{}

	var backtrack func(start int)

	backtrack = func(start int) {
		if len(currentCombination) == k {
			combinationCopy := make([]int, len(currentCombination))
			copy(combinationCopy, currentCombination)
			result = append(result, combinationCopy)
			return
		}

		for number := start; number <= n; number++ {
			currentCombination = append(currentCombination, number)
			backtrack(number + 1)
			currentCombination = currentCombination[:len(currentCombination)-1]
		}
	}

	backtrack(1)
	return result
}
```Go 实现遵循与 Python 相同的递归逻辑，但切片的行为方式有所不同。 

由于切片共享底层内存，因此我们必须在将完整的组合附加到之前显式创建一个副本`result`。 这是使用完成的`make()`和`copy()`。 

回溯是通过将一个元素附加到切片然后通过切片将其删除来实现的：```go
currentCombination = currentCombination[:len(currentCombination)-1]
```自从`n <= 20`，整数溢出不是问题。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(C(n,k) × k) | O(C(n,k) × k) | 我们生成每个有效的组合，复制每个组合的成本为 O(k) |
 | 空间| O(k) | 递归调用栈与临时组合存储|

 时间复杂度取决于有效组合的数量，即：$$\binom{n}{k}$$每个完成的组合必须复制到结果列表中，要求`O(k)`工作。 

辅助空间复杂度为`O(k)`因为递归深度永远不会超过`k`，临时组合列表最多存储`k`元素一次。 

如果包括输出存储本身，总内存使用量将变为：$$O\left(\binom{n}{k} \times k\right)$$因为所有的组合都必须被存储。

 ## 边缘情况

 ### 案例 1,`k = 1`什么时候`k = 1`，每个数字来自`1`到`n`成为它自己的组合。 有缺陷的实现可能会使递归过于复杂或意外地产生重复项。 

此实现可以自然地处理这种情况，因为递归在选择一个数字后立即停止。 例如，`n = 5, k = 1`产生：```
[[1], [2], [3], [4], [5]]
```### 案例 2,`k = n`什么时候`k`等于`n`，只有一个有效组合包含每个数字。 

幼稚的实现可能会意外生成重复路径或由于不正确的递归边界而错过完整的组合。 在这里，递归继续按升序选择数字，直到选择了所有元素，从而恰好产生一个结果。 

例如：```
n = 4
k = 4
```正确输出：```
[[1, 2, 3, 4]]
```### 情况 3，最小输入大小

 最小的有效输入是`n = 1, k = 1`。 

这可能会暴露涉及空循环、不正确的基本情况或递归初始化的错误。 由于算法开始于`1`并立即达到尺寸`k`，它正确返回：```
[[1]]
```无需任何特殊情况处理。
