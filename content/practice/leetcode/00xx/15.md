 # LeetCode 15 - 3Sum

 ## 问题理解

 问题给了我们一个整数数组`nums`，我们需要找到每个唯一的三元组，其总和恰好为`0`。 

三元组由三个不同的索引组成：

 -`i != j`-`i != k`-`j != k`值本身可以相等，但索引必须不同。 例如，`[0,0,0]`如果数组包含至少三个零，则有效。 

输出应包含所有不同的三元组。 如果两个三元组包含相同的值，则无论顺序如何，都被视为重复。 例如：

-`[-1,0,1]`-`[0,-1,1]`代表相同的三元组，并且只有其中一个应该出现在最终答案中。 

约束条件很重要：

 -`3 <= nums.length <= 3000`-`-10^5 <= nums[i] <= 10^5`3000 的长度立即告诉我们三次算法可能太慢了。 一个`O(n^3)`解决方案最多需要：$$3000^3 = 27,000,000,000$$在最坏的情况下进行操作，这远远超出了可接受的范围。 

该问题还包含几个棘手的边缘情况：

 - 具有许多重复值的数组
 - 仅包含零的数组
 - 没有有效三元组的数组
 - 消极和积极的价值观混合在一起
 - 多个不同的三胞胎共享一些号码

 简单的实现常常会失败，因为重复处理变得复杂。 防止重复的三元组是该问题的核心挑战之一。 

## 方法

 ### 蛮力方法

 强力解决方案检查三个元素的每种可能的组合。 

我们可以使用三个嵌套循环：

 - 第一个循环选择第一个元素。 
- 第二个循环选择第二个元素。 
- 第三个循环选择第三个元素。 

对于每个三元组，我们计算总和。 如果总和为零，我们将三元组添加到答案中。 

由于输出不能包含重复项，因此我们还需要一种方法来避免重复的三元组。 一种常见的方法是：

 - 在存储之前对每个有效的三元组进行排序。 
- 将三元组插入一组。 

这保证了正确性，因为每个可能的组合都会被检查。 

主要问题是性能。 三个嵌套循环产生`O(n^3)`时间复杂度，对于`n = 3000`。 

### 最优方法，排序+两个指针

 关键的见解是排序使我们能够有效地搜索对。 

假设我们固定一个数字`nums[i]`。 那么问题就变成了：

 > 查找索引后的两个数字`i`其总和等于`-nums[i]`。 

对数组进行排序后：

 - 如果当前总和太小，我们向右移动左指针以增加总和。 
- 如果当前总和太大，我们将右指针向左移动以减少总和。 

这将内部搜索从`O(n)`将枚举配对为高效的双指针扫描。 

排序还使重复处理变得更加容易，因为相等的值变得相邻。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 |`O(n^3)`|`O(k)`| 检查每个三元组，对于大输入来说太慢 |
 | 最佳|`O(n^2)`|`O(1)`不包括输出| 使用排序和两个指针来有效地查找对 |

 这里，`k`表示存储的三元组的数量。 

## 算法演练

 ### 最优算法

 1. 对数组进行排序。 

排序至关重要，因为两指针技术仅适用于有序数据。 它还允许我们有效地跳过重复项。 
2. 使用索引迭代数组`i`。 

每一步，`nums[i]`成为三元组的第一个元素。 
3. 跳过重复值`i`。 

如果`nums[i] == nums[i - 1]`，我们跳过这次迭代，因为我们会再次生成相同的三元组。 
4. 初始化两个指针。 

-`left = i + 1`-`right = len(nums) - 1`这些指针搜索剩余的两个值。 
5. 计算当前总和。```
total = nums[i] + nums[left] + nums[right]
```6. 如果总和太小，则移动`left`向右。 

由于数组已排序，因此递增`left`增加总和。 
7. 如果总和太大，则移动`right`向左。 

由于数组已排序，因此递减`right`减少总和。 
8. 如果总和为零，则记录三元组。 

添加：```
[nums[i], nums[left], nums[right]]
```到答案。 
9. 将两个指针向内移动。 

找到有效的三元组后，我们继续搜索更多组合。 
10. 跳过重复值`left`和`right`。 

这可以防止重复的三元组输入结果。 
11. 继续直到`left >= right`。 

此时，当前所有可能的对`i`已被检查。 

### 为什么它有效

 排序后，指针的每次移动都会以可预测的方向改变总和。 

- 搬家`left`增加总和。 
- 搬家`right`减少总和。 

这保证了对于每个固定的每个可能的对都被检查一次`i`。 

跳过重复项是有效的，因为相等的值在排序数组中是相邻的。 一旦我们处理了一个事件，处理下一个相同的值就会生成相同的三元组。 

这些特性共同确保：

 - 找到每个有效的三元组。 
- 不会产生重复的三元组。 
- 算法运行于`O(n^2)`时间。 

## Python 解决方案```python
class Solution:
    def threeSum(self, nums: list[int]) -> list[list[int]]:
        nums.sort()
        result = []

        n = len(nums)

        for i in range(n - 2):
            # Skip duplicate first elements
            if i > 0 and nums[i] == nums[i - 1]:
                continue

            left = i + 1
            right = n - 1

            while left < right:
                total = nums[i] + nums[left] + nums[right]

                if total < 0:
                    left += 1
                elif total > 0:
                    right -= 1
                else:
                    result.append([nums[i], nums[left], nums[right]])

                    left += 1
                    right -= 1

                    # Skip duplicate second elements
                    while left < right and nums[left] == nums[left - 1]:
                        left += 1

                    # Skip duplicate third elements
                    while left < right and nums[right] == nums[right + 1]:
                        right -= 1

        return result
```实现首先对数组进行排序。 这可以实现高效搜索和重复消除。 

外循环固定三元组的第一个数字。 在处理每个值之前，我们检查它是否与前一个元素匹配。 如果是，我们会跳过它，因为它会生成重复的三元组。 

然后这两个指针搜索剩余的子数组。 

当当前总和为：

 - 小于零，我们通过移动来增加总和`left`- 大于零，我们通过移动来减少总和`right`- 等于零，我们记录三元组

 找到有效的三元组后，两个指针都向内移动。 随后会立即跳过重复的值，因此无法多次添加相同的三元组。 

该算法自然地探索所有有效的组合，而无需重新访问不必要的状态。 

## 解决方案```go
package main

import "sort"

func threeSum(nums []int) [][]int {
	sort.Ints(nums)

	result := [][]int{}
	n := len(nums)

	for i := 0; i < n-2; i++ {
		// Skip duplicate first elements
		if i > 0 && nums[i] == nums[i-1] {
			continue
		}

		left := i + 1
		right := n - 1

		for left < right {
			total := nums[i] + nums[left] + nums[right]

			if total < 0 {
				left++
			} else if total > 0 {
				right--
			} else {
				result = append(result, []int{
					nums[i],
					nums[left],
					nums[right],
				})

				left++
				right--

				// Skip duplicate second elements
				for left < right && nums[left] == nums[left-1] {
					left++
				}

				// Skip duplicate third elements
				for left < right && nums[right] == nums[right+1] {
					right--
				}
			}
		}
	}

	return result
}
```Go 实现遵循与 Python 版本相同的逻辑。 

Go 切片用于动态存储三元组。 这`sort.Ints`函数按升序对数组进行排序。 

与 Python 不同，Go 没有内置的动态列表文字，其自动调整大小语义与 Python 列表相同，因此使用`append`。 

整数溢出在这里不是一个问题，因为约束完全在 Go 的范围内`int`范围。 

当不存在三元组时，返回空切片是可以接受的。

 ## 边缘情况

 ### 包含许多重复项的数组

 重复处理是此问题中最常见的错误来源。 

考虑：```
[-2,0,0,2,2]
```如果不小心跳过逻辑，该算法可能会产生：```
[-2,0,2]
[-2,0,2]
```多次。 

该实现在两个地方避免了这种情况：

 - 外循环跳过重复的起始元素。 
- 内循环跳过重复`left`和`right`记录有效三元组后的值。 

这些检查共同保证了唯一性。 

### 完全由零组成的数组

 输入如下：```
[0,0,0,0]
```包含许多可能的索引组合，但只有一个不同的三元组：```
[0,0,0]
```简单的实现通常会重复插入相同的三元组。 

记录第一个有效的三元组后，算法将两个指针前移并跳过所有相邻的重复零，从而防止重复输出。 

### 没有可能的三元组的数组

 示例包括：```
[1,2,3,4]
```或者```
[-5,-4,-3]
```由于所有数字都具有相同的符号，因此三个值之和不能为零。 

该算法自然地处理这个问题。 双指针搜索最终终止，没有找到任何有效的和，结果仍然为空。 

### 最小长度数组

 允许的最小输入大小是`3`。 

例如：```
[-1,0,1]
```该实现仍然可以正常工作，因为：

 - 外循环运行一次。 
- 两个指针恰好检查一对。 
- 返回有效的三元组。 

不需要特殊情况逻辑。
