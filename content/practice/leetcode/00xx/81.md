[LeetCode 第 81 题](https://leetcode.com/problems/search-in-rotated-sorted-array-ii/)

 **难度：** 🟡 中等
 **主题：** 数组、二分查找

 ## 解决方案

 ## 问题理解

 此问题要求我们确定目标值是否存在于可能包含重复值的旋转排序数组中。 

原始数组按非降序排序，这意味着值从小到大排列，并且允许重复。 在某个未知的主元索引处，数组被旋转。 旋转意味着数组被分成两部分并按顺序交换。 例如：```
Original: [0,1,2,4,4,5,6]
Rotated : [4,5,6,0,1,2,4]
```任务是返回`true`如果目标存在于旋转数组中的任何位置，否则返回`false`。 

关键的挑战是允许重复。 在这个问题的简单版本中，所有值都是不同的，二分搜索总是可以确定数组的哪一半已排序。 对于重复项，这变得更加困难，因为相等的值可能会掩盖旋转数组的结构。 

限制条件相对温和：

 - 数组长度最大可达5000
 - 值范围为`-10^4`到`10^4`- 该数组保证源自已排序的数组，然后进行旋转

 尽管输入大小不是很大，但该问题明确要求我们最小化操作步骤，这强烈建议使用二分搜索而不是线性扫描。 

一些边缘情况尤其重要：

 - 包含许多重复项的数组，例如`[1,1,1,1,1]`- 目标出现多次的数组
 - 重复的数组使我们无法确定排序的一侧
 - 长度数组`1`- 技术上旋转的数组`0`，意味着仍然完全排序
 - 目标根本不存在的情况

 假设不同值的简单二分搜索实现在某些重复较多的情况下会失败，因为它可能会错误地识别已排序的一半。 

## 方法

 ### 蛮力方法

 最简单的解决方案是从左到右扫描整个数组，并将每个元素与目标进行比较。 

如果任何元素等于目标，我们返回`true`。 如果我们完成扫描数组但没有找到目标，我们返回`false`。 

这种方法总是正确的，因为它直接检查每个可能的候选者。 但是，它忽略了数组最初已排序和旋转的事实。 因此，它没有利用输入的结构。 

它的运行时复杂度是线性的，这对于给定的约束是可以接受的，但不是最优的。 

### 最优方法，改进的二分搜索

 更好的解决方案使用适用于具有重复项的旋转数组的二分搜索。 

在没有重复项的正常旋转排序数组中，二分查找有效，因为数组的至少一半始终是严格排序的。 我们可以将中间元素与边界进行比较，以确定哪一半是有序的。 

例如：```
[4,5,6,7,0,1,2]
```如果`mid`位于左侧排序部分，我们可以判断目标是否在该范围内。 

复杂性来自于重复。 考虑：```
[1,1,1,3,1]
```如果：```
left = 0
mid = 2
right = 4
```然后：```
nums[left] == nums[mid] == nums[right]
```我们无法确定哪一侧被排序，因为重复项隐藏了枢轴结构。 

关键的见解是：

 - 如果重复项阻止我们确定排序的一侧，我们通过向内移动两个边界来缩小搜索空间
 - 否则，我们继续正常的旋转数组二分搜索逻辑

 这保留了正确性，同时在大多数情况下仍然受益于二分搜索。 

### 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(1) | O(1) | 按顺序检查每个元素 |
 | 最佳| 平均 O(log n)，最坏情况 O(n) | O(1) | O(1) | 修改后的二分搜索可处理重复项 |

 ## 算法演练

 1.初始化两个指针，`left`和`right`，代表当前的搜索边界。 
2.继续搜索`left <= right`。 这保证了每个可能的候选索引都被考虑。 
3. 计算中间索引：```
mid = (left + right) // 2
```4.如果`nums[mid] == target`，立即返回`true`因为目标已经找到了。 
5. 检查重复项是否会妨碍我们识别已排序的一半：```
nums[left] == nums[mid] == nums[right]
```如果这个条件成立，我们就无法确定哪一侧已排序。 我们通过以下方式安全地缩小搜索空间：```
left += 1
right -= 1
```6.否则判断左半部分是否已排序：```
nums[left] <= nums[mid]
```如果为 true，则左侧已排序。 
7. 如果左半部分已排序，请检查目标是否位于其中：```
nums[left] <= target < nums[mid]
```- 如果为 true，则丢弃右半部分：```
right = mid - 1
```- 否则，丢弃左半部分：```
left = mid + 1
```8. 如果左半部分没有排序，那么右半部分必须排序。 
9. 检查目标是否位于已排序的右半部分内：```
nums[mid] < target <= nums[right]
```- 如果为 true，则搜索右半部分：```
left = mid + 1
```- 否则，搜索左半部分：```
right = mid - 1
```10. 如果循环结束没有找到目标，则返回`false`。 

## Python 解决方案```python
from typing import List

class Solution:
    def search(self, nums: List[int], target: int) -> bool:
        left = 0
        right = len(nums) - 1

        while left <= right:
            mid = (left + right) // 2

            if nums[mid] == target:
                return True

            # Cannot determine sorted side because of duplicates
            if nums[left] == nums[mid] == nums[right]:
                left += 1
                right -= 1

            # Left half is sorted
            elif nums[left] <= nums[mid]:
                if nums[left] <= target < nums[mid]:
                    right = mid - 1
                else:
                    left = mid + 1

            # Right half is sorted
            else:
                if nums[mid] < target <= nums[right]:
                    left = mid + 1
                else:
                    right = mid - 1

        return False
```该实现首先初始化两个代表当前搜索间隔的指针。 

在循环内部，我们计算中间索引并立即检查中间值是否等于目标。 这是标准的二分查找停止条件。 

下一节将处理重复的歧义情况。 当左、中、右值都相等时，我们无法确定哪边排序。 我们没有做出错误的假设，而是安全地缩小了搜索边界。 

删除不明确的重复项后，我们确定左半部分是否已排序。 如果是，我们检查目标是否属于该范围。 如果是这样，我们丢弃右半部分。 否则，我们丢弃左半部分。 

如果左半部分未排序，则右半部分必须排序。 我们对称地应用相同的逻辑。 

最终，要么找到目标，要么搜索空间变空。 

## 解决方案```go
func search(nums []int, target int) bool {
    left := 0
    right := len(nums) - 1

    for left <= right {
        mid := (left + right) / 2

        if nums[mid] == target {
            return true
        }

        // Cannot determine sorted side because of duplicates
        if nums[left] == nums[mid] && nums[mid] == nums[right] {
            left++
            right--
        } else if nums[left] <= nums[mid] {
            // Left half is sorted
            if nums[left] <= target && target < nums[mid] {
                right = mid - 1
            } else {
                left = mid + 1
            }
        } else {
            // Right half is sorted
            if nums[mid] < target && target <= nums[right] {
                left = mid + 1
            } else {
                right = mid - 1
            }
        }
    }

    return false
}
```Go 实现遵循与 Python 版本完全相同的算法结构。 

Go在计算时自然使用整数除法`mid`， 所以`(left + right) / 2`工作正常。 

与 Python 不同，Go 没有带有类型提示的内置动态列表，因此该函数直接接受整数切片。 

这里不需要对整数溢出进行特殊处理，因为约束很小，尽管在较大的系统中更安全的中点计算，例如：```go
mid := left + (right-left)/2
```通常是首选。

## 复杂度分析

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | 平均 O(log n)，最坏情况 O(n) | 二分搜索通常会将搜索空间减半，但重复项可能会强制线性收缩 |
 | 空间| O(1) | O(1) | 仅使用了很少的指针变量|

 在平均情况下，该算法的行为与标准二分搜索类似，并且每次迭代都会丢弃一半的搜索空间。 

但是，重复会降低性能。 在最坏的情况下，数组例如：```
[1,1,1,1,1,1,1]
```强制算法一次一步地缩小边界，因为它无法确定哪一侧已排序。 这导致线性时间复杂度。 

该算法使用恒定的额外空间，因为它只维护索引指针。 

## 边缘情况

 ### 仅包含重复项的数组

 考虑：```
nums = [1,1,1,1,1]
target = 1
```标准旋转数组二分搜索可能会失败，因为每次比较看起来都相同。 当左值、中值和右值相等时，实现会通过缩小两个边界来处理此问题。 

这保证了进展并最终找到目标。 

### 目标不存在

 考虑：```
nums = [2,2,2,3,4,2]
target = 5
```该算法不断缩小搜索范围，直到区间变空。 

它正确返回`false`在大多数情况下不需要完整的线性扫描。 

### 单元素数组

 考虑：```
nums = [1]
target = 1
```该算法计算：```
mid = 0
```并立即返回`true`。 

为了：```
nums = [1]
target = 2
```循环在一次迭代后退出并返回`false`。 

### 接近结束时的轮换

 考虑：```
nums = [1,2,3,4,5]
```或者：```
nums = [5,1,2,3,4]
```该算法可以正确处理最小和最大旋转位置，因为无论枢轴位置如何，排序半检测逻辑都可以工作。 

### 围绕枢轴重复值

 考虑：```
nums = [1,0,1,1,1]
target = 0
```这是一个典型的棘手案件。 重复隐藏了主元结构，但重复收缩步骤最终暴露了足够的结构，以便二分搜索能够正确进行。
