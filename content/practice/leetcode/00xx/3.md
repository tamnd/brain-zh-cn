 # 没有重复字符的最长子串

 ## 问题理解

 问题给出了一个字符串`s`并询问不包含重复字符的最长子串的长度。 

子串是字符串的连续部分。 这个细节很重要，因为字符必须保持相邻。 例如，在`"pwwkew"`，序列`"pwke"`无效，因为这些字符在原始字符串中不连续。 

输入是单个字符串，可能包含字母、数字、符号和空格。 输出是一个整数，表示每个字符最多出现一次的任何子字符串的最大长度。 

约束告诉我们字符串长度可以大到`5 * 10^4`。 在这种规模下，二次解可能会变得太慢。 例如，一个`O(n^2)`在最坏的情况下，解决方案可能会执行数十亿次操作。 这强烈表明我们需要一个线性或接近线性的解决方案。 

尽早考虑几个边缘情况很重要：

 - 字符串可能为空。 在这种情况下，答案应该是`0`。 
- 字符串只能包含一个重复的字符，例如`"bbbb"`。 答案是`1`。 
- 最长的有效子串可能出现在字符串的中间而不是开头。 
- 重复的字符可能看起来非常靠近或相距很远。 
- 字符串可能包含空格或符号，应将其视为正常字符。 

关键挑战是在扫描字符串时有效维护仅包含唯一字符的子字符串。 

## 方法

 ### 蛮力方法

 一个简单的解决方案是生成每个可能的子字符串并检查它是否包含重复字符。 

对于每个起始索引，我们可以逐个字符扩展子字符串，同时将看到的字符存储在一个集合中。 如果遇到重复项，我们将停止扩展该子字符串并移至下一个起始位置。 

这是有效的，因为它显式检查所有可能的子字符串并记录最大有效长度。 

然而，这种方法对于大输入来说太慢了。 有`O(n^2)`可能的子字符串，检查唯一性也可能需要额外的工作。 即使进行了优化，总运行时间也会成二次方。 

对于长度为`50,000`，二次解不实用。 

### 最优方法，滑动窗口

 关键的观察是，我们不需要每次遇到重复字符时都从头开始。 

假设我们已经知道子字符串是有效的。 当我们扩展一个字符时，只有两种可能：

 - 新字符尚未位于当前子字符串内，因此窗口仍然有效。 
- 新字符已经存在于当前子字符串中，因此我们必须从左侧缩小窗口，直到删除重复字符。 

这自然导致了滑动窗口技术。 

我们维护两个指针：

 -`left`, 当前窗口的开始
 -`right`, 当前窗口结束

 我们还维护一个哈希集或哈希映射来跟踪当前在窗口内的字符。 

当我们移动时`right`向前穿过字符串，我们扩展窗口。 每当出现重复项时，我们就会移动`left`向前直到窗口再次有效。 

每个字符最多添加和删除一次，这给出了线性时间解决方案。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(min(n, 字符集)) | 检查每个可能的子字符串 |
 | 最佳| O(n) | O(min(n, 字符集)) | 带哈希集的滑动窗口|

 ## 算法演练

 1.初始化两个指针，`left`和`right`，都开始于`0`。 这些指针定义了当前的滑动窗口。 
2. 创建一个名为的哈希集`seen_characters`。 该集存储当前窗口内的所有字符。 使用哈希集是因为成员资格检查、插入和删除都是`O(1)`平均而言。 
3. 初始化变量`max_length`到`0`。 该变量跟踪迄今为止找到的最长的有效子字符串。 
4. 使用迭代遍历字符串`right`指针。 
5. 对于位置处的每个字符`right`，检查它是否已经存在于`seen_characters`。 
6. 如果该字符已经存在，则当前窗口无效，因为它包含重复项。 移动`left`指针向前移动，同时从集合中删除字符，直到删除重复字符。 
7. 删除重复项后，将当前字符添加到集合中。 
8. 使用以下方法计算当前窗口长度：$\text{window length} = right - left + 1$9. 更新`max_length`如果当前窗口大于先前的最佳答案。 
10. 继续，直到`right`指针到达字符串末尾。 

### 为什么它有效

 在每一步，滑动窗口都保持一个重要的不变量：

 > 之间的子串`left`和`right`总是包含独特的字符。 

每当出现重复项时，算法就会缩小窗口以恢复有效性。 因为两个指针都只向前移动，所以每个字符最多被处理两次，一次进入窗口时，一次离开窗口时。 这保证了正确性和线性运行时间。 

## Python 解决方案```python
class Solution:
    def lengthOfLongestSubstring(self, s: str) -> int:
        seen_characters = set()
        left = 0
        max_length = 0

        for right in range(len(s)):
            while s[right] in seen_characters:
                seen_characters.remove(s[left])
                left += 1

            seen_characters.add(s[right])

            current_length = right - left + 1
            max_length = max(max_length, current_length)

        return max_length
```其实现直接遵循滑动窗口算法。 

这`seen_characters`设置跟踪活动窗口中当前存在的字符。 这`left`指针标记子字符串的开头，而循环变量`right`一次将窗口展开一个字符。 

每当角色位于`right`集合内已经存在，则`while`循环从左侧删除字符，直到重复项消失。 这保证了窗口始终包含唯一的字符。 

窗口生效后，当前字符被插入到集合中。 然后计算窗口长度并与`max_length`。 

该解决方案自然地处理所有边缘情况。 如果字符串为空，则循环永远不会执行并且函数正确返回`0`。 

## 解决方案```go
func lengthOfLongestSubstring(s string) int {
    seenCharacters := make(map[byte]bool)

    left := 0
    maxLength := 0

    for right := 0; right < len(s); right++ {
        for seenCharacters[s[right]] {
            delete(seenCharacters, s[left])
            left++
        }

        seenCharacters[s[right]] = true

        currentLength := right - left + 1

        if currentLength > maxLength {
            maxLength = currentLength
        }
    }

    return maxLength
}
```Go 实现使用`map[byte]bool`而不是 Python 集。 逻辑保持不变。 

Go 字符串是字节切片，因此索引返回一个`byte`。 由于该问题使用标准 ASCII 样式字符，因此基于字节的索引在这里可以正常工作。 

这`delete`当窗口左侧向前移动时，函数从地图上删除字符。 

与 Python 不同，Go 没有内置的`max`函数用于整数，因此比较是使用显式编写的`if`陈述。

 ## 边缘情况

 ### 空字符串

 空字符串是一个重要的边界情况，因为根本没有子字符串。 有错误的实现可能会错误地返回`1`或尝试无效的索引操作。 

这个实现自然地处理了这种情况。 循环永远不会执行，`max_length`遗迹`0`，并返回正确答案。 

### 所有字符重复

 像这样的字符串`"bbbbbb"`可以暴露窗口缩小逻辑中的错误。 一些不正确的实现无法正确删除重复项，并且可能会错误地报告较大的窗口大小。 

在这里，`while`循环保证在重新插入当前字符之前删除重复项。 窗口大小永远不会超过`1`。 

### 当前窗口内出现重复项

 案例如`"abba"`很棘手，因为仅删除一个字符并不总是足够的。 处理第二个时`'b'`，窗口必须继续缩小，直到更早`'b'`被完全移除。 

该实现正确地使用了`while`循环而不是单个`if`陈述。 这可确保在继续之前完全清洁窗户。 

### 接近尾声的长独特片段

 在输入中，例如`"tmmzuxt"`，最长的子字符串出现在字符串的末尾而不是靠近开头。 

算法不断更新`max_length`在整个扫描过程中，因此它可以正确捕获较长的窗口，无论它们出现在何处。
