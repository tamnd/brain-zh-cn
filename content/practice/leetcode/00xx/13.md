 ## 解决方案

 ## 问题理解

 问题给出一个罗马数字字符串，要求我们将其转换成对应的整数值。 

罗马数字使用七个符号：

 | 符号| 价值|
 | --- | --- |
 | 我| 1 |
 | V | 5 |
 | X | 10 | 10
 | 左 | 50 | 50
 | C | 100 | 100
 | d | 500 | 500
 | 中号 | 1000 | 1000

 大多数罗马数字遵循简单的加法规则。 符号是从最大到最小书写的，我们将它们的值加在一起。 例如：

-`"III"`=`1 + 1 + 1 = 3`-`"XII"`=`10 + 1 + 1 = 12`棘手的部分是减法规则。 有时，较小的符号出现在较大的符号之前，这意味着我们进行减法而不是加法：

 -`"IV"`=`5 - 1 = 4`-`"IX"`=`10 - 1 = 9`-`"XL"`=`50 - 10 = 40`只有六种减法组合有效：

 -`I`前`V`或者`X`-`X`前`L`或者`C`-`C`前`D`或者`M`保证输入是介于之间的有效罗马数字`1`和`3999`。 这种保证很重要，因为这意味着我们不需要验证格式错误的输入，例如`"IC"`或者`"IIII"`。 

最大字符串长度仅为`15`，因此性能不是主要问题。 甚至一个`O(n)`或者`O(n^2)`解决方案很容易通过。 尽管如此，我们的目标是编写一个干净且正确的算法来正确处理减法情况。 

重要的边缘情况包括：

 - 仅包含附加符号的数字，例如`"III"`- 具有多个减法对的数字，例如`"MCMXCIV"`- 以小值结尾的数字，例如`"LVIII"`- 单字符输入，例如`"I"`或者`"V"`## 方法

 ### 蛮力方法

 暴力解决方案可以在扫描字符串时显式检查每个可能的减法对。 在每个位置，我们可以向前查看两个字符并与所有已知的特殊情况进行比较：

 -`"IV"`→ 4
 -`"IX"`→ 9
 -`"XL"`→ 40
 -`"XC"`→ 90
 -`"CD"`→ 400
 -`"CM"`→ 900

 如果找到特殊对，我们将添加其值并跳过两个字符。 否则，我们添加当前单个交易品种的值并向前移动一步。 

这是有效的，因为罗马数字只有六种有效的减法模式。 但是，它会在单个符号和符号对之间创建额外的分支逻辑和重复处理。 

### 最佳方法

 关键的观察结果是，当较小的值出现在较大的值之前时，总是会发生减法。 

例如：

-`"IV"`→`1 < 5`-`"XC"`→`10 < 100`我们可以一一处理字符，而不是硬编码所有减法对：

 - 如果当前符号小于下一个符号，则将其减去。 
- 否则，添加它。 

该规则自然地通过一次字符串处理来处理加法和减法情况。 

为了`"MCMXCIV"`:

 -`M`= +1000
 -`C`前`M`→ -100
 -`M`= +1000
 -`X`前`C`→ -10
 -`C`= +100
 -`I`前`V`→ -1
 -`V`= +5

 总计 = 1994 年。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(1) | O(1) | 显式检查所有减法对 |
 | 最佳| O(n) | O(1) | O(1) | 使用相邻符号之间的值比较 |

 ## 算法演练

 1. 创建一个哈希映射来存储每个罗马数字字符的整数值。 
2. 初始化一个名为`total`存储最终答案。 
3. 从左到右迭代字符串。 
4. 对于每个字符，从哈希映射中获取其数值。 
5. 检查字符串中是否有下一个字符。 
6. 如果当前值小于下一个值，则减去当前值`total`。 

这可以处理减法模式，例如：

 -`IV`-`IX`-`XL`-`XC`-`CD`-`CM`7. 否则，将当前值添加到`total`。 
8. 继续，直到处理完整个字符串。 
9. 返回`total`。 

### 为什么它有效

 罗马数字的构造使得仅当较小的数字紧邻较大的数字之前出现时才会发生减法。 通过比较相邻值，我们可以确定某个符号对总数的贡献是正值还是负值。 每个符号都被处理一次，并且每个贡献都符合罗马数字规则，因此最终的总和是正确的。 

## Python 解决方案```python
class Solution:
    def romanToInt(self, s: str) -> int:
        roman_values = {
            "I": 1,
            "V": 5,
            "X": 10,
            "L": 50,
            "C": 100,
            "D": 500,
            "M": 1000,
        }

        total = 0

        for i in range(len(s)):
            current_value = roman_values[s[i]]

            if i + 1 < len(s):
                next_value = roman_values[s[i + 1]]

                if current_value < next_value:
                    total -= current_value
                else:
                    total += current_value
            else:
                total += current_value

        return total
```该解决方案首先创建一个将罗马数字符号映射到整数值的字典。 这允许对每个字符进行恒定时间查找。 

变量`total`存储运行结果。 

该循环一次处理每个字符。 对于每个位置，算法都会在可能的情况下将当前符号与下一个符号进行比较。 

如果当前值小于下一个值，则当前数字是减法对的一部分，因此我们从总数中减去它。 

否则，我们正常添加。 

始终添加最后一个字符，因为没有下一个符号可供比较。 

该实现直接遵循罗马数字规则，同时保持紧凑且易于阅读。 

## 解决方案```go
func romanToInt(s string) int {
    romanValues := map[byte]int{
        'I': 1,
        'V': 5,
        'X': 10,
        'L': 50,
        'C': 100,
        'D': 500,
        'M': 1000,
    }

    total := 0

    for i := 0; i < len(s); i++ {
        currentValue := romanValues[s[i]]

        if i+1 < len(s) {
            nextValue := romanValues[s[i+1]]

            if currentValue < nextValue {
                total -= currentValue
            } else {
                total += currentValue
            }
        } else {
            total += currentValue
        }
    }

    return total
}
```Go 实现遵循与 Python 版本相同的逻辑。 主要区别在于 Go 使用`map[byte]int`而不是 Python 字典。 

由于罗马数字字符是 ASCII 字符，因此将字符串索引为字节是安全且高效的。 

Go 整数可以轻松处理以下的最大可能答案`3999`，所以溢出不是问题。

 ## 边缘情况

 单字符罗马数字是一种重要的边缘情况，因为没有下一个符号可供比较。 粗心的实现可能会在检查下一个值时访问越界索引。 该解决方案通过验证来避免这种情况`i + 1 < len(s)`在阅读下一个字符之前。 

减法对例如`"IV"`和`"CM"`是错误的另一个常见来源。 总是添加值的幼稚实现会错误地计算`"IV"`作为`6`而不是`4`。 该算法通过将当前符号与下一个符号进行比较来正确检测减法。 

具有多种减法模式的大数字，例如`"MCMXCIV"`，还可以暴露逻辑错误。 一些不正确的实现仅处理一对减法或错误地跳过字符。 该解决方案独立处理每个字符并一致地应用相同的比较规则，因此多个减法对自然地工作，无需特殊处理。
