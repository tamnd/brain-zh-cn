[LeetCode 第 99 题](https://leetcode.com/problems/recover-binary-search-tree/)

 **难度：** 🟡 中等
 **主题：** 树、深度优先搜索、二叉搜索树、二叉树

 ## 解决方案

 ## 问题理解

 该问题为我们提供了二叉搜索树的根，但树中恰好有两个节点的值意外交换了。 我们的任务是恢复树，使其再次满足二叉搜索树的性质，而不修改树结构本身。 

二叉搜索树（BST）有一个非常重要的属性：

 - 左子树中的每个节点都包含小于当前节点的值。 
- 右子树中的每个节点都包含比当前节点大的值。 

此属性最有用的结果之一是有效 BST 的中序遍历会产生严格递增顺序的值。 

输入是损坏的 BST 的根节点。 输出不直接返回。 相反，我们必须通过将不正确的值交换回正确的位置来修改树。 

约束告诉我们树包含 2 到 1000 个节点。 这足够小，即使是`O(n)`遍历是完全可以接受的。 然而，后续询问我们是否可以使用恒定的额外空间来解决问题，这暗示预期的最优解决方案避免存储整个遍历。 

有几个重要的边缘情况需要记住：

 - 交换的节点在中序遍历中可能是相邻的。 
- 中序遍历时交换的节点可能相距较远。 
- 一个交换的节点可能是根。 
- 树可能只包含两个节点。 
- BST 属性保证恰好两个交换节点会违反，因此我们不需要处理任意损坏。 

当交换的节点不相邻时，简单的实现可能会失败，因为可能存在两个而不是一个反转点。 正确的处理需要仔细识别两个放错位置的节点。 

## 方法

 ### 蛮力方法

 最直接的解决方案是对树进行中序遍历并将所有节点存储在数组中。 

由于有效 BST 的中序遍历应该产生排序值，因此我们可以将收集的序列与其自身的排序版本进行比较。 值不同的两个节点是交换的节点。 一旦确定，我们就将它们的值交换回来。 

这种方法之所以有效，是因为排序揭示了值的正确顺序，并且只有两个位置不正确。 

然而，这个解决方案需要与节点数量成比例的额外内存，因为我们存储遍历。 虽然对于给定的约束是可以接受的，但它不能满足要求恒定额外空间的后续要求。 

### 最佳方法

 关键的观察是 BST 的中序遍历必须是排序的。 

如果正好交换两个节点，则中序序列将包含一到两个反转。 

例如：```
Correct inorder:
1 2 3 4 5

Swapped inorder:
1 4 3 2 5
```这里：

-`4 > 3`是一个反转
 -`3 > 2`是另一种反转

 第一个错位的节点是第一次反演中较大的值。 

第二个错位的节点是上次反演中较小的值。 

我们可以在中序遍历期间检测这些反转，而无需存储整个遍历。 我们只需要：

 -`prev`, 之前访问过的节点
 -`first`, 第一个错误节点
 -`second`，第二个错误节点

 遍历完成后，交换`first.val`和`second.val`恢复 BST。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n log n) | O(n log n) | O(n) | 存储中序遍历并与排序数组进行比较 |
 | 最佳 | O(n) | O(h) | 检测中序遍历期间的反转，其中`h`是树高 |

 递归解决方案使用`O(h)`由于递归而产生的堆栈空间。 莫里斯遍历版本可以实现真正的`O(1)`辅助空间。 

## 算法演练

 1. 对树进行中序遍历。 

中序遍历按顺序访问节点：```
left -> root -> right
```对于有效的 BST，这会生成一个排序序列。 
2. 跟踪先前访问过的节点。 

在遍历过程中，存储一个名为`prev`。 

如果 BST 有效，我们应该始终有：```
prev.val < current.val
```3. 检测反转。 

如果我们遇到：```
prev.val > current.val
```则违反了 BST 排序。 
4. 记录第一个错位的节点。 

第一次出现反转时：

 -`first = prev`-`second = current`反演中较大的节点肯定放错了位置。 
5. 如果再次发生反转，则更新第二个错位的节点。 

如果稍后出现另一个反转：

 - 更新`second = current`这处理交换节点不相邻的情况。 
6. 继续遍历，直到处理完所有节点。 

我们必须遍历整棵树，因为稍后可能会出现第二个错误节点。 
7. 交换两个放错位置的节点的值。 

遍历结束后：```
first.val, second.val = second.val, first.val
```这将恢复 BST 排序。 

### 为什么它有效

 有效的 BST 会产生严格递增的有序序列。 交换两个值会导致顺序违规。 如果交换的节点相邻，则会发生一次反转。 如果分开，就会出现两次反转。 

第一个不正确的节点始终是第一次反转中较大的值。 第二个错误节点始终是上次反转的较小值。 交换这两个值可恢复排序顺序，从而恢复 BST 属性。 

## Python 解决方案```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional

class Solution:
    def recoverTree(self, root: Optional[TreeNode]) -> None:
        """
        Do not return anything, modify root in-place instead.
        """

        first = None
        second = None
        prev = None

        def inorder(node: Optional[TreeNode]) -> None:
            nonlocal first, second, prev

            if not node:
                return

            inorder(node.left)

            if prev and prev.val > node.val:
                if first is None:
                    first = prev
                second = node

            prev = node

            inorder(node.right)

        inorder(root)

        if first and second:
            first.val, second.val = second.val, first.val
```该实现遵循前面讨论的中序遍历策略。 

变量`first`和`second`存储两个错位的节点。 变量`prev`在遍历过程中跟踪先前访问过的节点。 

递归`inorder`函数按排序顺序遍历树。 在每个节点，我们将当前节点的值与前一个节点的值进行比较。 

如果`prev.val > node.val`，我们检测到了反转。 

在第一次反转期间：```python
first = prev
second = node
```如果稍后出现另一个反转，则仅`second`已更新。 

遍历完成后，将两个不正确的值交换回来。 

该解决方案直接修改树并且不创建新树。 

## 解决方案```go
/**
 * Definition for a binary tree node.
 * type TreeNode struct {
 *     Val int
 *     Left *TreeNode
 *     Right *TreeNode
 * }
 */
func recoverTree(root *TreeNode) {
    var first *TreeNode
    var second *TreeNode
    var prev *TreeNode

    var inorder func(node *TreeNode)

    inorder = func(node *TreeNode) {
        if node == nil {
            return
        }

        inorder(node.Left)

        if prev != nil && prev.Val > node.Val {
            if first == nil {
                first = prev
            }
            second = node
        }

        prev = node

        inorder(node.Right)
    }

    inorder(root)

    if first != nil && second != nil {
        first.Val, second.Val = second.Val, first.Val
    }
}
```Go 实现在结构上与 Python 版本非常相似。 

由于 Go 不支持嵌套函数`nonlocal`，我们直接在递归函数内部使用闭包变量。 

Go 使用`nil`而不是Python的`None`对于空引用。 

指针很自然地被使用，因为树节点是通过以下方式引用的：`*TreeNode`。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n) | 每个节点都被访问一次 |
 | 空间| O(h) | 递归调用堆栈使用树的高度 |

 该遍历仅对每个节点处理一次，从而给出线性时间复杂度。 

递归实现使用与树高度成比例的堆栈空间。 在完全倾斜的树的最坏情况下，这变成`O(n)`。 在平衡树中，`O(log n)`。 

Morris Traversal 实现可以将辅助空间减少到真实值`O(1)`。

 ## 边缘情况

 ### 相邻交换节点

 如果中序遍历中交换的节点相邻，则只会出现一次反转，而不是两次。 

例如：```
1 3 2 4
```有缺陷的实现可能会出现两次违规，并且无法识别正确的节点。 

此实现可以正确处理这种情况，因为第一次反转已经识别出两个放错位置的节点。 

### 非相邻交换节点

 如果交换的节点相距较远，则会出现两次反转。 

例如：```
1 5 3 4 2 6
```正确的节点是`5`和`2`。 

幼稚的实现可能会错误地交换`5`和`3`，因为它只检查第一个反演。 

此实施更新`second`每次发现反转时，确保正确捕获最终的错误节点。 

### 根节点被交换

 有时交换的节点之一是根。 

由于中序遍历纯粹按顺序而不是按位置来处理节点，因此该算法不关心节点是根节点、叶节点还是内部节点。 

比较逻辑在整个树上统一工作，因此根损坏自然会得到处理，没有任何特殊情况。
