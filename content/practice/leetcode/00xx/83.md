[LeetCode 第 83 题](https://leetcode.com/problems/remove-duplicates-from-sorted-list/)

 **难度：** 🟢简单
 **主题：** 链接列表

 ## 解决方案

 ## 问题理解

 这个问题要求我们从**排序的单链表**中删除重复的值，以便每个不同的值恰好出现一次。 重要的细节是链表已经按升序排序，这使得重复检测比未排序的列表容易得多。 

输入是`head`的单链表。 每个节点包含一个整数值和一个指向下一个节点的指针。 由于列表已排序，因此重复值始终**彼此相邻**出现。 例如，如果列表是：`1 -> 1 -> 2 -> 3 -> 3`重复的`1`值是连续的，并且重复`3`值也是连续的。 

预期的输出是相同的链表结构，经过修改，以便在保持排序顺序的同时删除重复节点。 对于前面的示例，结果变为：`1 -> 2 -> 3`约束告诉我们有关输入的一些有用的信息：

 - 节点数量范围为`0`到`300`，这意味着列表可以为空。 
- 节点值范围介于`-100`和`100`，但由于列表是排序的，所以具体的值范围对于解决方案来说并不是特别重要。 
- 排序保证是实现高效解决方案的关键属性。 

由于排序列表中的重复项总是相邻的，因此我们不需要搜索整个列表来确定某个值是否已经出现。 我们只需要将一个节点与其紧邻的下一个节点进行比较。 

有几个重要的边缘情况需要预先考虑。 该列表可能为空（`head = None`），在这种情况下没有什么可以删除的。 该列表可能只包含一个节点，该节点已经是唯一的。 所有节点可能都是相同的，例如`[1,1,1,1]`，需要重复删除重复项。 另一个棘手的情况是根本不存在重复项，例如`[1,2,3]`，其中列表应保持不变。 

## 方法

 ### 蛮力方法

 强力解决方案将忽略列表已排序的事实，而是使用辅助数据结构（例如哈希集）跟踪先前看到的值。 

我们将逐个节点迭代链表。 对于每个节点，我们将检查其值是否已存在于集合中。 如果该值之前已经见过，我们通过调整指针来删除该节点。 否则，我们将值插入集合中并继续遍历。 

此方法会产生正确的答案，因为每个值都会根据所有先前遇到的值进行检查。 重复的节点将被删除，同时保留唯一的值。 

但是，此方法不必要地使用额外的内存。 由于列表已经排序，重复的值是相邻的，这意味着集合是多余的。 通过利用排序属性，我们可以在空间方面更有效地解决问题。 

### 最佳方法

 关键的见解是，由于链表是排序的，因此重复的值总是连续出现。 

我们不需要记住我们看到的每个值，只需将当前节点与下一个节点进行比较：

 - 如果两个值相同，则下一个节点是重复的，应被跳过。 
- 如果值不同，我们前进到下一个节点。 

这是有效的，因为排序保证了一旦我们移过某个值，我们就不会再在列表中再次遇到它。 

通过简单地修改指针，我们可以在一次遍历中删除重复项，同时使用恒定的额外空间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 使用哈希集来跟踪看到的值 |
 | 最佳| O(n) | O(1) | O(1) | 遍历一次并就地删除重复项 |

 ## 算法演练

 ### 最优算法

 1. 从一个名为`current`位于链表的头部。 
2. 继续遍历，同时`current`和`current.next`存在。 我们需要`current.next`因为重复检查是通过比较相邻节点来进行的。 
3.比较`current.val`和`current.next.val`。 
4. 如果值相等，则已找到重复项。 通过更改删除重复节点：`current.next = current.next.next`这会跳过重复节点并重新连接列表。 
5. **不要**移动`current`删除重复项后立即指针。 这很重要，因为一行中可能有多个重复项，例如：`1 -> 1 -> 1 -> 2`删除一个重复项后，我们仍然需要再次比较同一节点。 
6. 如果值不同，则移动`current`到下一个节点，因为当前值已经是唯一的。 
7. 继续，直到到达列表末尾。 
8.归还原件`head`，因为列表已就地修改。 

### 为什么它有效

 该算法的正确性依赖于链表的排序特性。 由于相同的值总是连续出现，因此比较相邻节点足以检测重复项。 在每一步，算法都保持之前所有节点的不变性`current`已经是免费的。 通过在发现重复项时立即删除，最终的链表恰好包含每个值的一个副本。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

class Solution:
    def deleteDuplicates(self, head: Optional[ListNode]) -> Optional[ListNode]:
        current = head

        while current and current.next:
            if current.val == current.next.val:
                current.next = current.next.next
            else:
                current = current.next

        return head
```该实现直接遵循最优算法。 

变量`current`从链表的头部开始，一次在链表中移动一个节点。 循环条件检查两者`current`和`current.next`因为重复比较需要访问相邻节点。 

在循环内部，算法将当前节点值与下一个节点值进行比较。 如果它们匹配，则通过更改删除重复节点`next`指针。 具体来说，`current.next`被重新分配以跳过重复节点并指向其后面的节点。 

请注意，删除重复项后，算法不会移动`current`指针。 这可确保正确处理连续的重复项。 

如果值不同，算法将前进到下一个节点，因为当前节点已被确认是唯一的。 

最后该方法返回`head`，现在代表修改后的重复空闲链表。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func deleteDuplicates(head *ListNode) *ListNode {
	current := head

	for current != nil && current.Next != nil {
		if current.Val == current.Next.Val {
			current.Next = current.Next.Next
		} else {
			current = current.Next
		}
	}

	return head
}
```Go 实现几乎与 Python 版本相同，但存在一些特定于语言的差异。 

在Go中，链表节点是指针，所以`nil`用来代替Python的`None`。 字段访问使用大写名称（`Val`和`Next`）因为它们与提供的结构定义匹配。 

指针操作逻辑保持完全相同。 由于 Go 使用显式指针，因此更新`current.Next`就地修改链表而不需要额外的内存。 

这里不用担心整数溢出，因为该算法仅比较值并更新指针。

 ## 边缘情况

 一个重要的边缘情况是**空链表**。 自从`head`可以是`None`，尝试访问`head.next`不检查会导致错误。 该实现可以安全地处理这个问题，因为循环条件检查是否`current`访问前已存在`current.next`。 

另一个重要的情况是当**连续出现多个重复项**时，例如`[1,1,1,1]`。 有缺陷的实现可能会过早地移动指针并错过一些重复项。 该解决方案通过保留来避免该问题`current`删除重复项后就位，确保检查每个相邻的重复项。 

当**列表已不包含重复项**时，会出现第三种边缘情况，例如`[1,2,3,4]`。 该实现正确地使列表保持不变，因为每次比较都会找到不同的值，导致指针简单地向前移动。 

最后的边缘情况是**重复项出现在列表的开头或结尾**。 删除边界附近的节点可能会导致指针处理错误。 由于该算法仅调整`current.next`，它自然地处理头部或尾部的重复项，而不需要任何特殊情况逻辑。
