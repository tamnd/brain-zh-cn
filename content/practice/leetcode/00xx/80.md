[LeetCode 第 80 题](https://leetcode.com/problems/remove-duplicates-from-sorted-array-ii/)

 **难度：** 🟡 中等
 **主题：** 数组、两个指针

 ## 解决方案

 ## 问题理解

 这个问题要求我们就地修改一个**已排序的整数数组**，以便每个唯一值**最多出现两次**。 由于数组已经按非降序排序，重复的值将始终出现在彼此旁边，这是一个非常重要的属性，使有效的解决方案成为可能。 

简单来说，我们想要删除“额外”的重复项。 一个数字可以出现一次或两次，但如果出现三次或多次，则必须删除第二次之后出现的所有数字。 该操作必须保留剩余元素的**相对顺序**。 

**就地**这句话很重要。 我们不允许分配另一个数组来存储结果。 相反，我们必须覆盖现有的`nums`数组，使有效结果占据第一个`k`职位。 索引之后的任何内容`k - 1`是不相关的并且可以包含任何值。 

该函数应该返回`k`，去重后剩余的有效元素数。 在线法官只检查第一个`k`数组的元素。 

例如：

-`[1,1,1,2,2,3]`变成`[1,1,2,2,3]`，因为第三个`1`必须被删除。 
-`[0,0,1,1,1,1,2,3,3]`变成`[0,0,1,1,2,3,3]`，因为只有两个`1`是允许的。 

这些约束提供了有关问题规模的有用信息：

 -`1 <= nums.length <= 3 * 10^4`表示数组最多可以包含 30,000 个元素。 
-`nums`保证按非降序排序。 
- 值范围介于`-10^4`和`10^4`，但实际值范围对于算法来说并不是特别重要。 

由于数组可能相当大，因此重复移动元素或重建数组效率很低。 **O(1) 额外内存** 的要求强烈建议采用就地基于指针的解决方案。 

预先考虑一些边缘情况很重要。 如果数组只有一个或两个元素，则无需删除，因为每个数字已允许最多出现两次。 所有元素都相同的数组，例如`[5,5,5,5]`，可能会暴露重复处理中的错误，因为只应保留两个副本。 完全没有重复项的数组应该保持不变。 由于保证输入已排序，因此我们永远不需要在相距较远的位置搜索重复项。 

## 方法

 ### 蛮力方法

 解决这个问题的一个直接方法是构建一个新列表，同时计算每个数字被包含的次数。 

我们迭代排序后的数组并跟踪当前数字出现的次数。 如果计数小于或等于 2，我们将该元素添加到结果数组中。 否则，我们跳过它。 

这是可行的，因为数组已排序，因此重复的元素会分组在一起。 我们可以很容易地计算连续出现的次数。 

构造过滤后的数组后，我们将有效值复制回`nums`并返回新的长度。 

这种方法是正确的，因为它明确强制执行每个数字最多只能出现两次的规则。 但是，它违反了问题的空间约束，因为它使用与输入大小成比例的附加数组。 

### 最优方法，两个指针

 关键的观察是，因为数组是排序的，所以我们可以通过将某个值与已经写入数组有效部分的早期值进行比较来确定是否应该保留该值。 

我们没有构建一个单独的数组，而是维护一个**写入指针**来跟踪下一个有效元素应该放置的位置。 

重要的见解是：

 如果我们已经允许最多**两个副本**，那么对于任何当前数量`nums[i]`，我们只需要将它与写入指针之前**两个位置的元素进行比较。 

如果：```
nums[i] != nums[write_index - 2]
```那么这个数字相加不会超过两次，所以我们保留它。 

否则，我们会跳过它，因为它会创建第三个重复项。 

这是可行的，因为数组的有效前缀始终按排序顺序维护。

 | 蛮力 | O(n) | O(n) | 使用额外的数组来存储有效元素 |

 ## 算法演练

 1. 先处理最简单的情况。 如果数组长度小于或等于`2`，立即返回长度，因为每个元素都已被允许。 
2. 在索引处初始化一个**写指针**`2`。 我们从这里开始是因为前两个元素始终有效。 即使是重复的，也允许两份。 
3. 从索引开始迭代数组`2`。 
4. 对于每个当前数字`nums[i]`，将其与`nums[write_index - 2]`。 
5. 如果值不同，则表示添加当前元素不会创建超过两个副本。 将当前元素写入`nums[write_index]`和增量`write_index`。 
6. 如果值相同，请跳过此元素，因为保留它会导致第三次出现。 
7. 继续，直到处理完所有元素。 
8. 返回`write_index`，它表示数组有效部分的长度。 

### 为什么它有效

 该算法保持了一个重要的不变量：

 在每一步中，索引中的数组部分`0`到`write_index - 1`始终包含有效结果，其中没有元素出现超过两次。 

由于数组已排序，因此重复项会连续出现。 比较`write_index - 2`告诉我们当前的数字是否会第三次出现。 如果它与较早的元素匹配，则我们已经有两个副本并且必须跳过它。 否则，包含在内是安全的。 

## Python 解决方案```python
from typing import List

class Solution:
    def removeDuplicates(self, nums: List[int]) -> int:
        if len(nums) <= 2:
            return len(nums)

        write_index = 2

        for read_index in range(2, len(nums)):
            if nums[read_index] != nums[write_index - 2]:
                nums[write_index] = nums[read_index]
                write_index += 1

        return write_index
```该实现首先处理长度为 2 或更小的数组。 由于每个元素最多出现两次，因此在这些情况下不需要修改。 

变量`write_index`跟踪应写入下一个有效元素的位置。 它开始于`2`因为前两个元素始终有效。 

循环使用`read_index`从左到右扫描数组。 对于每个元素，我们将其与`nums[write_index - 2]`。 该比较确定包含当前值是否会超过允许的最大频率二。 

如果值不同，我们将当前数字复制到写入位置并前进写入指针。 如果它们匹配，则跳过该元素。 

在最后，`write_index`表示剩余的有效元素的数量。 

## 解决方案```go
func removeDuplicates(nums []int) int {
    if len(nums) <= 2 {
        return len(nums)
    }

    writeIndex := 2

    for readIndex := 2; readIndex < len(nums); readIndex++ {
        if nums[readIndex] != nums[writeIndex-2] {
            nums[writeIndex] = nums[readIndex]
            writeIndex++
        }
    }

    return writeIndex
}
```Go 实现遵循与 Python 版本相同的逻辑。 由于 Go 中的切片的行为与动态数组视图类似，因此我们可以修改`nums`直接到位。 

Go 在这里不需要对整数溢出进行特殊处理，因为索引保留在数组范围内。 空切片也可以通过`len(nums) <= 2`健康）状况。

 ## 边缘情况

 ### 元素少于三个的数组

 大小为一或二的数组很重要，因为算法从索引开始`2`。 粗心的实现可能会意外访问无效索引并崩溃。 由于最多允许两个副本，因此这些数组已经有效。 该实现立即安全地返回原始长度。 

### 所有元素都相同的数组

 像这样的输入`[7,7,7,7,7]`是错误的常见来源，因为必须跳过第二个之后的每个元素。 不正确的指针处理可能会意外地保留太多重复项或错误地覆盖值。 对比`write_index - 2`保证一旦存储了两个副本，所有后来的相同值都将被忽略。 

### 没有重复项的数组

 输入如`[1,2,3,4,5]`应保持不变。 某些实现会意外地不必要地覆盖值或错误地处理指针增量。 在此解决方案中，每次比较都会成功，因为相邻的唯一值不同，因此所有元素都被保留，并且原始顺序保持不变。 

### 多个重复组

 像这样的输入`[1,1,1,2,2,2,3,3,3]`测试算法是否正确重置不同值之间的重复跟踪。 由于该解决方案仅与数组的有效前缀进行比较，因此每个数字都独立地限制为出现两次，而不会干扰其他组。
