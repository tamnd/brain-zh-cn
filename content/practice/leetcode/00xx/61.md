 **难度：** 🟡 中等
 **主题：** 链表、两个指针

 ## 解决方案

 ## 问题理解

 这个问题要求我们将单链表向右旋转`k`职位。 右旋转意味着每个节点向列表末尾移动一个位置，最后一个节点回绕成为新的头。 

例如，如果链表是：```
1 → 2 → 3 → 4 → 5
```我们将它向右旋转一次，即最后一个元素（`5`) 移到前面：```
5 → 1 → 2 → 3 → 4
```如果我们再次旋转它，我们会得到：```
4 → 5 → 1 → 2 → 3
```与示例 1 匹配`k = 2`。 

输入包括：

 -`head`，单链表的头节点
 -`k`, 列表向右旋转的次数

 预期输出是新旋转的链表的头。 

这些约束告诉我们有关输入大小和行为的几个重要信息：

 - 链表包含之间`0`和`500`节点，这意味着列表相对较小。 
- 旋转计数`k`可以非常大，最多`2 * 10^9`。 
- 自从`k`可能比列表大小大得多，每次重复旋转一步会浪费工作。 

一个重要的观察是旋转长度列表`n`经过`n`位置产生相同的列表。 类似地，旋转`n + 1`相当于旋转`1`。 因此，仅`k % n`实际上很重要。 

有几种边缘情况可能会导致简单的实现失败：

 - 一个空列表（`head = None`）应该立即返回`None`。 
- 单节点列表永远不会改变，无论`k`。 
-`k = 0`意味着不应发生旋转。 
- 如果`k`是列表长度的倍数，结果不变。 
- 非常大`k`值需要模数减少以避免不必要的计算。 

## 方法

 ### 蛮力方法

 一种简单的解决方案是一次一步地模拟旋转过程。 

对于每次旋转：

 1. 遍历链表找到倒数第二个节点。 
2. 删除最后一个节点。 
3. 将最后一个节点移到前面。 
4. 重复此过程`k`次。 

这是有效的，因为每个单独的旋转都正确地执行一次右移。 重复它`k`时间最终会产生想要的安排。 

然而，这种方法效率低下。 查找最后一个和倒数第二个节点需要遍历列表，这会花费`O(n)`每次旋转的时间。 重复那句话`k`次导致`O(n × k)`复杂。 自从`k`可以非常大，最多`2 * 10^9`，这个解决方案变得不切实际。 

### 最佳解决方案的关键见解

 关键的观察是按列表长度旋转没有任何作用。 

如果列表长度是`n`， 然后：```
k rotations ≡ k % n rotations
```这大大减少了不必要的工作。 

另一个有用的见解是，我们可以暂时将链表转换为循环链表，而不是每次物理移动一个节点。 

例如：```
1 → 2 → 3 → 4 → 5
              ↓
              ↑
```如果我们将尾部连接回头部，列表就会变成循环。 那么我们只需要确定：

 - 新尾巴应该在哪里
 - 新头应该在哪里

 一旦确定，我们就在正确的位置打破圆圈。 

这避免了重复的节点移动，使我们能够在一次遍历中解决问题。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n × k) | O(n × k) | O(1) | O(1) | 通过重复移动最后一个节点来一次旋转一步 |
 | 最佳 | O(n) | O(1) | O(1) | 计算长度，形成一个循环，并在正确的位置断开它 |

 ## 算法演练

 ### 最优算法

 1. **立即处理琐碎的边缘情况**

 如果列表为空，仅包含一个节点，或者`k == 0`，返回原始列表。 无需旋转。 
2. **计算链表的长度**

 遍历列表，同时跟踪：

 - 节点总数（`length`）
 - 最后一个节点（`tail`）

 我们需要长度来减少不必要的旋转，并需要尾部来创建循环列表。 
3. **减少旋转次数**

 计算：```
k = k % length
```按列表长度旋转会产生相同的列表，因此只有余数很重要。 
4. **检查是否还需要轮换**

 如果`k == 0`，返回原来的头。 

发生这种情况时`k`是列表长度的倍数。 
5. **创建循环链表**

 将尾部连接到头部：```
tail.next = head
```这会将列表转换为循环，使我们能够有效地重新定位头部。 
6. **找到新的尾巴**

 新的尾部将位于：```
length - k - 1
```从当前头部开始的步骤。 

为什么？ 因为旋转后，最后`k`节点移动到前面，这意味着新的尾部位于这些节点之前。 
7. **找到新的头**

 新尾部之后的节点成为新头：```
new_head = new_tail.next
```8. **断开循环连接**

 设定：```
new_tail.next = None
```这恢复了单链表结构。 
9. **归还新头**

 轮换列表现已完成。 

### 为什么它有效

 该算法之所以有效，是因为将列表转换为循环可以保留所有节点顺序，同时允许旋转成为指针调整问题，而不是重复的节点移动。 

将列表制作成圆形后，有效地移动头部意味着选择一个新的突破点。 位置处的节点`length - k - 1`一定是新尾巴，因为正是`k`节点需要移动到它的前面。 打破循环可以保证生成的订单与正确的轮换相匹配`k`。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

class Solution:
    def rotateRight(self, head: Optional[ListNode], k: int) -> Optional[ListNode]:
        # Edge cases
        if not head or not head.next or k == 0:
            return head

        # Find length and tail
        length = 1
        tail = head

        while tail.next:
            tail = tail.next
            length += 1

        # Reduce unnecessary rotations
        k %= length

        if k == 0:
            return head

        # Make circular list
        tail.next = head

        # Find new tail
        steps_to_new_tail = length - k - 1
        new_tail = head

        for _ in range(steps_to_new_tail):
            new_tail = new_tail.next

        # Set new head
        new_head = new_tail.next

        # Break cycle
        new_tail.next = None

        return new_head
```实现从处理边缘情况开始。 如果列表为空，仅包含一个节点，或者不需要旋转，我们立即返回原始列表。 

接下来，我们遍历链表一次，计算链表的长度并找到尾节点。 这些都是优化解决方案所必需的。 长度可以让我们减少`k`使用模运算，而需要使用尾部来临时形成一个循环链表。 

减少后`k`，我们检查是否仍然需要旋转。 如果`k % length == 0`，列表保持不变。 

关键步骤是将尾部连接回头部以创建一个循环。 一旦循环，我们将新尾巴的位置计算为`length - k - 1`从当前头部开始的步骤。 此后的节点成为新的头。 

最后，我们通过设置来打破循环`new_tail.next = None`，恢复链表结构并返回旋转后的头。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func rotateRight(head *ListNode, k int) *ListNode {
	if head == nil || head.Next == nil || k == 0 {
		return head
	}

	// Find length and tail
	length := 1
	tail := head

	for tail.Next != nil {
		tail = tail.Next
		length++
	}

	// Reduce unnecessary rotations
	k %= length

	if k == 0 {
		return head
	}

	// Make circular list
	tail.Next = head

	// Find new tail
	stepsToNewTail := length - k - 1
	newTail := head

	for i := 0; i < stepsToNewTail; i++ {
		newTail = newTail.Next
	}

	// Set new head
	newHead := newTail.Next

	// Break cycle
	newTail.Next = nil

	return newHead
}
```Go 的实现与 Python 版本非常相似。 主要区别在于处理方式`nil`指针而不是Python的`None`。 Go 还使用显式整数变量`for`循环而不是 Python 的范围语法。 

自从`k ≤ 2 * 10^9`，整数溢出在 Go 中不是问题，因为标准`int`type 在现代系统上可以轻松处理这种大小的值。 内存使用量也保持不变，因为没有分配额外的数据结构。

 ## 边缘情况

 ### 空列表

 空链表是一种重要的边缘情况，因为没有要旋转的节点。 立即遍历列表的简单实现可能会触发空指针错误。 该实现通过检查来避免这种情况`if not head`在开始时并立即返回。 

### 单节点列表

 当列表仅包含一个节点时，任意次数的旋转都会产生完全相同的列表。 如果没有提前返回，算法可能会不必要地形成循环链接或尝试无效的指针移动。 该实现可以安全地处理这个问题`if not head.next`。 

### 旋转次数大于列表长度

 自从`k`可能非常大，重复旋转会非常慢。 例如：```
[1,2,3], k = 1,000,000
```由于列表长度是`3`， 仅有的：```
1,000,000 % 3 = 1
```实际上很重要。 模运算可防止计算浪费并保持解决方案的高效。 

### 旋转计数等于长度的倍数

 如果`k`可以被列表长度整除，列表应该保持不变。 例如：```
[1,2,3], k = 6
```自从：```
6 % 3 = 0
```没有发生有效的旋转。 实施明确检查`k == 0`模减后并立即返回原始列表。
