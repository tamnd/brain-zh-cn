[LeetCode 第 51 题](https://leetcode.com/problems/n-queens/)

 **难度：** 🔴难
 **主题：** 数组、回溯

 ## 解决方案

 ## 问题理解

 N 皇后问题要求我们放置`n`皇后区`n x n`棋盘上没有两个皇后可以互相攻击。 在国际象棋中，皇后可以水平、垂直和对角攻击。 这意味着对于任何有效的安排：

 - 两个皇后不能共用同一行
 - 两个皇后不能共用同一列
 - 两个皇后不能共用同一条对角线

 输入是单个整数`n`，代表棋盘的大小。 目标是返回所有可能的有效板配置。 

每个返回的板配置都表示为字符串列表。 每个字符串对应棋盘的一行：

 -`'Q'`代表女王
 -`'.'`代表一个空的正方形

 例如，当`n = 4`，一个有效的板是：```
.Q..
...Q
Q...
..Q.
```这意味着：

 - 第 0 行第 1 列有一个皇后
 - 第 1 行第 3 列有一个皇后
 - 第 2 行第 0 列有一个皇后
 - 第 3 行第 2 列有一个皇后

 约束相对较小，`1 <= n <= 9`，这强烈表明通过修剪进行穷举搜索是可以接受的。 然而，可能的皇后放置数量增长得非常快，因此简单的暴力解决方案仍然是低效的。 

一个重要的观察结果是，每个有效的解决方案都必须在每一行中放置一个皇后。 这显着减少了搜索空间，因为我们永远不需要考虑同一行中的多个皇后。 

一些边缘情况很重要：

 -`n = 1`是尽可能小的板并且只有一个解决方案
 -`n = 2`和`n = 3`没有有效的解决方案
 - 较大的值`n`生成许多递归状态，因此有效的冲突检查至关重要
 - 对角线冲突很容易错误地实现，因为它们需要协调关系而不是直接相等

 ## 方法

 ### 蛮力方法

 暴力解决方案将生成棋盘上所有可能的皇后排列，然后检查该排列是否有效。 

思考这个问题的一种方法是：

 - 对于每一行，尝试每一个可能的列
 - 生成所有可能的组合
 - 生成完整棋盘后，验证是否有皇后互相攻击

 如果我们允许每一行选择其中任何一个`n`列，那么有`n^n`可能的展示位置。 对于每个位置，验证棋盘都需要检查皇后对，这会增加额外的开销。 

这种方法是正确的，因为它探索了每种可能的配置。 如果存在有效的安排，蛮力最终会找到它。 

然而，它太慢了，因为大多数生成的配置显然是无效的。 例如，许多棋盘将包含共享列或对角线的皇后，但强力方法会在拒绝它之前浪费时间构建整个棋盘。 

### 最优方法，回溯与剪枝

 关键的见解是我们不需要完全构建无效的配置。 

相反，我们可以逐行构建棋盘，并在路径无效时立即停止探索。 

这种技术称为回溯。 

在每一行：

 - 尝试在每一列中放置一个皇后
 - 检查位置是否安全
 - 如果安全，继续递归到下一行
 - 如果不安全，请立即跳过该位置

 为了使冲突检查有效，我们维护三组：

 - 使用过的色谱柱
 - 使用的主对角线（`row - col`）
 - 使用反对角线（`row + col`）

 这允许恒定时间的安全检查。 

剪枝效果是巨大的，因为无效的部分配置会被立即丢弃，而不是进一步扩展。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n^n * n²) | O(n^n * n²) | O(n²) | 生成所有可能的板并随后进行验证 |
 | 最佳 | O(n!) | O(n²) | 通过早期修剪和恒定时间冲突检查进行回溯 |

 ## 算法演练

 1. 初始化一个空棋盘，表示为字符串或字符数组列表。 

我们需要一个可变的结构，因为在递归过程中皇后会被反复放置和删除。 
2. 创建三组来跟踪被攻击的位置。 

我们维持：

 -`columns`对于占用的列
 -`diag1`对于由以下确定的主对角线`row - col`-`diag2`对于由以下确定的反对角线`row + col`这些集合允许恒定时间冲突检测。 
3.从行开始递归回溯`0`。 

由于每一行必须恰好包含一个皇后，因此递归自然会逐行进行。 
4. 对于当前行，迭代每一列。 

每列代表女王的一个候选位置。 
5、放置皇后前，先检查位置是否安全。 

如果出现以下情况，则职位无效：

 - 该列已包含女王
 - 主对角线已经包含皇后
 - 反对角线已经包含皇后
 6. 如果位置安全，则放置皇后。 

这涉及：

 - 更新董事会
 - 将列添加到`columns`- 添加`row - col`到`diag1`- 添加`row + col`到`diag2`7. 递归处理下一行。 

递归调用尝试将皇后放置在下一行，同时尊重所有现有约束。 
8. 如果所有行都处理完毕，则记录当前板。 

到达行`n`意味着我们成功放置了所有皇后，没有冲突。 
9. 递归返回后，移除皇后。 

这是“回溯”步骤。 我们撤消所有更改，以便算法可以探索替代位置。 
10. 继续探索剩余的列。 

最终将探索每一种可能的有效安排。 

### 为什么它有效

 该算法保持了一个不变量，即所有已放置在棋盘上的皇后都不会攻击。 在放置任何新皇后之前，算法会验证新位置不违反此不变量。 

由于系统地探索了每一行并考虑了每个安全位置，因此该算法最终会生成每个有效配置一次。 

## Python 解决方案```python
from typing import List

class Solution:
    def solveNQueens(self, n: int) -> List[List[str]]:
        results: List[List[str]] = []

        board = [["." for _ in range(n)] for _ in range(n)]

        columns = set()
        diag1 = set()  # row - col
        diag2 = set()  # row + col

        def backtrack(row: int) -> None:
            if row == n:
                solution = ["".join(r) for r in board]
                results.append(solution)
                return

            for col in range(n):
                if (
                    col in columns
                    or (row - col) in diag1
                    or (row + col) in diag2
                ):
                    continue

                board[row][col] = "Q"
                columns.add(col)
                diag1.add(row - col)
                diag2.add(row + col)

                backtrack(row + 1)

                board[row][col] = "."
                columns.remove(col)
                diag1.remove(row - col)
                diag2.remove(row + col)

        backtrack(0)

        return results
```实现首先将棋盘初始化为充满点的 2D 网格。 该板在递归期间就地修改。 

这`results`列表存储所有有效的解决方案。 每个完成的解决方案都从字符网格转换为所需的字符串列表格式。 

这三套是核心优化：

 -`columns`跟踪占用的列
 -`diag1`跟踪主对角线
 -`diag2`追踪反对角线

 递归`backtrack`函数一次处理一行。 

基本情况发生在`row == n`。 此时，每个皇后都已成功放置，因此当前的棋盘配置将复制到结果列表中。 

在循环内，每一列都会被测试。 如果该列或任一对角线已被占用，则立即跳过该位置。 

当找到有效位置时：

 - 女王被放置
 - 跟踪集已更新
 - 递归继续到下一行

 递归完成后，皇后被移除并恢复跟踪集。 这确保了董事会状态对于未来的探索是正确的。 

## 解决方案```go
func solveNQueens(n int) [][]string {
    results := [][]string{}

    board := make([][]byte, n)
    for i := 0; i < n; i++ {
        board[i] = make([]byte, n)
        for j := 0; j < n; j++ {
            board[i][j] = '.'
        }
    }

    columns := map[int]bool{}
    diag1 := map[int]bool{}
    diag2 := map[int]bool{}

    var backtrack func(int)

    backtrack = func(row int) {
        if row == n {
            solution := make([]string, n)

            for i := 0; i < n; i++ {
                solution[i] = string(board[i])
            }

            results = append(results, solution)
            return
        }

        for col := 0; col < n; col++ {
            if columns[col] || diag1[row-col] || diag2[row+col] {
                continue
            }

            board[row][col] = 'Q'

            columns[col] = true
            diag1[row-col] = true
            diag2[row+col] = true

            backtrack(row + 1)

            board[row][col] = '.'

            delete(columns, col)
            delete(diag1, row-col)
            delete(diag2, row+col)
        }
    }

    backtrack(0)

    return results
}
```Go 实现遵循与 Python 解决方案相同的递归回溯策略。 

一个重要的区别是 Go 字符串是不可变的，因此棋盘表示为字节的 2D 切片而不是字符串。 这允许在递归期间进行有效的就地更新。 

使用带有布尔值的映射而不是 Python 集合，因为 Go 不提供内置集合类型。 

当找到解决方案时，每一行都会从`[]byte`到`string`在附加到结果列表之前。 

Go 在这里不需要对整数溢出进行特殊处理，因为所有对角线值在给定的约束内仍然很小。

 | 测量 | 复杂性 | 说明|
 | --- | --- | --- |
 | 时间 | O(n!) | 每行都在剩余的有效列中进行选择，并受到约束的严格修剪|
 | 空间| O(n²) | 板存储加上递归堆栈和跟踪集|

 时间复杂度通常近似为`O(n!)`因为每个递归级别都会减少可用列的数量。 尽管修剪显着减少了实际运行时间，但最坏情况的搜索空间仍然呈阶乘增长。 

空间复杂度包括：

 - 板本身，它使用`O(n²)`- 递归深度可达`O(n)`- 最多存储跟踪集`O(n)`条目

 主板主导着整体内存使用。

 ## 边缘情况

 ### 边缘情况 1，`n = 1`这是最小的有效电路板尺寸。 幼稚的实现可能会意外地拒绝唯一可用的位置，因为对角线或列逻辑的实现不正确。 

该解决方案自然地处理这个问题，因为递归从 row 开始`0`，成功放置皇后，并立即到达基本情况。 

### 边缘情况 2，`n = 2`和`n = 3`这些电路板尺寸没有有效的解决方案。 

一个常见的错误是假设每种电路板尺寸都必须产生至少一种配置。 不正确的实现可能会返回部分完成的板或无效的布局。 

回溯方法可以正确处理此问题，因为每个递归分支最终都会失败冲突检查，从而导致结果列表为空。 

### 边缘情况 3，对角线冲突

 对角线检查通常是问题中最棘手的部分。 

两个皇后共用一条主对角线如果`row - col`是平等的。 他们共享一个反对角线如果`row + col`是平等的。 

一个常见的错误是尝试重复扫描整个板或错误地计算对角线标识符。 

该实现通过将对角线标识符直接存储在哈希集中来避免这些问题，从而允许恒定时间冲突检测并保证正确性。
