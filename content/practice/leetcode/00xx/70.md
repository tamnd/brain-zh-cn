 # LeetCode 70 - 爬楼梯

 ## 问题理解

 该问题描述了一个楼梯`n`总步数。 你从底层开始，并想到达顶层。 每次移动时，您都可以攀爬`1`步骤或`2`步骤。 

目标是确定有多少种不同的移动序列可以带你从底部到顶部。 

例如，如果`n = 3`，有效的方法是：

 -`1 + 1 + 1`-`1 + 2`-`2 + 1`尽管总步数相同，但不同的顺序算作不同的方式。 

输入由单个整数组成`n`，代表楼梯的数量。 输出是一个整数，表示精确到达顶部步骤的不同方式的总数。 

约束条件`1 <= n <= 45`很重要，因为它告诉我们几件事：

 - 输入尺寸相对较小。 
- 从技术上讲，指数解决方案可能会传递非常小的值，但它们很快就会变得低效。 
- 答案可以安全地容纳在标准 32 位整数内。 
- 动态规划是一个自然的选择，因为该问题包含重叠的子问题。 

一个关键的观察结果是，到达某个步骤的方式数量取决于之前的步骤。 达到步骤`n`，最后一步必须来自：

 - 步骤`n - 1`使用`1`一步移动
 - 步骤`n - 2`使用`2`一步移动

 这种关系创建了与斐波那契数列相同的递归式。 

一些重要的边缘情况包括：

 -`n = 1`，其中只有一种可能的方法。 
-`n = 2`，其中恰好有两种方法。 
- 较大的值，例如`n = 45`，低效的递归解决方案变得太慢。 
- 确保实施不会意外地重复计算路径。 

## 方法

 ### 蛮力递归方法

 蛮力方法递归地尝试所有可能的路径。 

在每一步，算法都会分为两个选择：

 - 攀爬`1`楼梯
 - 攀爬`2`楼梯

 递归继续直到：

 - 到达确切的顶部，这算作一条有效路径。 
- 步数超过`n`，这是无效的。 

这种方法是正确的，因为它探索了每一种可能的动作组合。 然而，它会重复地重新计算相同的子问题。 

例如，在计算答案时`n = 5`，算法计算结果为`n = 3`通过不同的递归路径多次。 

这种重复的工作会导致运行时间呈指数增长。 

### 最优动态规划方法

 关键的见解是达到步骤的方法数量`i`仅取决于前两个状态。 

如果：

-`dp[i - 1]`代表到达步骤的方式`i - 1`-`dp[i - 2]`代表到达步骤的方式`i - 2`然后：$dp[i] = dp[i-1] + dp[i-2]$这是有效的，因为每条有效的步骤路径`i`必须来自前两个步骤之一。 

我们不是递归地重新计算值，而是从较小的子问题迭代地构建答案。 

由于任何时候只需要前两个值，因此我们可以将空间使用优化为恒定空间。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^n) | O(2^n) | O(n) | 递归探索所有可能的路径，多次重复计算 |
 | 最佳 | O(n) | O(1) | O(1) | 使用滚动变量进行动态规划 |

 ## 算法演练

 1. 首先处理最小的基本情况。 

如果`n`是`1`，只有一种可能的爬楼梯方法。 如果`n`是`2`，正好有两种方法。 
2. 存储前两步的路数。 

我们初始化两个变量：

 -`one_step_before = 1`-`two_steps_before = 2`这些代表：

 - 达到步骤的方法`1`- 达到步骤的方法`2`3. 从步骤迭代`3`直到步骤`n`。 

对于每个新步骤，使用递归关系计算路数：$current = one\_step\_before + two\_steps\_before$这是有效的，因为：

 - 每一条在上一步结束的路径都可以再添加一个楼梯。 
- 每条提前两步结束的路径都可以添加两步跳跃。 
4. 将变量前移。 

计算出当前答案后：

 - 旧的`two_steps_before`成为新的`one_step_before`- 新计算的值成为新的`two_steps_before`这保持了最后两个状态的滚动窗口。 
5. 返回最终结果。 

循环结束后，`two_steps_before`包含步骤的答案`n`。 

### 为什么它有效

 该算法之所以有效，是因为每条有效的步骤路径`n`必须以以下任一结尾：

 - 一步之遥`n - 1`- 两步距离`n - 2`这两组是不相交的，但一起涵盖了所有可能性。 因此，总路数是前两步计数的总和。 

动态规划方法保证了正确性，因为它从已经正确的较小答案中构建出更大的答案。 

## Python 解决方案```python
class Solution:
    def climbStairs(self, n: int) -> int:
        if n <= 2:
            return n

        one_step_before = 1
        two_steps_before = 2

        for _ in range(3, n + 1):
            current = one_step_before + two_steps_before
            one_step_before = two_steps_before
            two_steps_before = current

        return two_steps_before
```实现首先直接处理最小的有效输入。 什么时候`n`是`1`或者`2`，答案很简单`n`。 

然后初始化两个变量来表示到达前两个步骤的方法数。 该解决方案不存储整个 DP 数组，而是仅保留最后两个计算值，因为不再需要较早的值。 

循环从步骤开始`3`并使用递归关系迭代计算每个新状态。 计算当前的路数后，变量将向前移动，以便下一次迭代可以访问最近的两个值。 

最后，代表最新计算步骤的变量作为答案返回。 

## 解决方案```go
func climbStairs(n int) int {
    if n <= 2 {
        return n
    }

    oneStepBefore := 1
    twoStepsBefore := 2

    for i := 3; i <= n; i++ {
        current := oneStepBefore + twoStepsBefore
        oneStepBefore = twoStepsBefore
        twoStepsBefore = current
    }

    return twoStepsBefore
}
```Go 实现遵循与 Python 版本相同的逻辑。 由于 Go 使用显式变量声明，因此滚动 DP 变量使用`:=`。 

不需要对整数溢出进行特殊处理，因为约束保证结果保持在 Go 的范围内`int`类型。 

与 Python 不同，Go 不支持以同样灵活的方式进行元组分配，因此代码使用临时变量按顺序更新变量`current`多变的。

 ## 边缘情况

 ### 边缘情况 1：单楼梯

 当`n = 1`，只有一种有效的移动可能。 假设至少有两个先前状态的简单实现可能会因无效索引或不正确的初始化而失败。 

该实现通过提前返回正确处理了这个问题：```
if n <= 2:
    return n
```### 边缘情况 2：两级楼梯

 当`n = 2`，正好有两种可能：

 -`1 + 1`-`2`如果没有仔细定义基本条件，一些递归解决方案会意外地多算或少算这种情况。 

执行直接返回`2`，保证正确性。 

### 边缘情况 3：最大约束

 允许的最大输入是`n = 45`。 强力递归解决方案会执行过多的重复计算并且变得非常慢。 

动态编程解决方案通过只计算每个状态一次来避免此问题，从而允许实现有效地处理最大输入。 

### 边缘情况 4：避免额外的内存使用

 常见的 DP 方法将所有中间结果存储在数组中。 虽然这种方法是正确的，但它使用了不必要的内存。 

此实现认识到在任何时候只需要前两个值，因此它使用滚动变量。 这保证了恒定的辅助空间，同时保持正确性。
