[LeetCode 第 64 题](https://leetcode.com/problems/minimum-path-sum/)

 **难度：** 🟡 中等
 **主题：** 数组、动态规划、矩阵

 ## 解决方案

 ## 问题理解

 这个问题给了我们一个二维网格的大小`m x n`，其中每个单元格包含一个非负整数。 我们从网格的左上角开始，特别是在位置`(0, 0)`，并且想要到达右下角位置`(m - 1, n - 1)`。 

目标是找到一条值总和尽可能小的路径。 路径的成本是沿路线遇到的每个数字的总和，包括起始单元格和结束单元格。 

有一个重要的移动限制：从任何单元格，我们只能**向右**或**向下**移动。 不允许向左、向上或对角移动。 这一限制极大地影响了问题，因为它意味着每条路径都有一个可预测的结构。 

例如，在网格中：```
[
  [1,3,1],
  [1,5,1],
  [4,2,1]
]
```一种有效路径可能是：```
1 → 3 → 1 → 1 → 1
```其总和为`7`，而这恰好是可能的最小值。 

输入包括：

 -`grid`，非负整数的二维矩阵
 -`m`, 行数
 -`n`, 列数

 输出是一个整数，表示从左上角到右下角的最小路径和。 

这些约束提供了有关预期解决方案的有用线索：

 -`1 <= m, n <= 200`-`0 <= grid[i][j] <= 200`一个`200 x 200`网格最多包含`40,000`细胞。 由于每个细胞都可能需要被处理，`O(m × n)`解决方案非常合理。 然而，探索每条可能路径的指数方法将变得不可行。 

一个幼稚的实现可能会遇到几种边缘情况。 单细胞网格，例如`[[5]]`很重要，因为答案就是该单元格的值。 单行或单列网格也值得注意，因为只有一个可能的路径。 另一个考虑因素是所有值都是非负的，这保证了动态编程自然地进行，因为添加更多步骤不会意外地减少先前计算的成本。 

该问题保证网格是有效的、非空的、矩形的，因此我们不需要处理格式错误的输入。 

## 方法

 ### 蛮力方法

 解决这个问题的一个直接方法是使用递归或深度优先搜索来探索从左上角到右下角的每条可能的路径。 

在每个单元格中，我们最多有两种选择：

 1. 向右移动
 2. 向下移动

 我们递归地计算两种可能性的最小路径和并选择较小的结果。 

例如：```
minPath(i, j) =
grid[i][j] + min(
    minPath(i + 1, j),
    minPath(i, j + 1)
)
```这种方法是正确的，因为它明确评估每条有效路线并选择最小总和。 

然而，它太慢了。 许多子问题被反复重新计算。 例如，从特定单元到目的地的最小路径可能会从不同的递归分支重新计算数十或数千次。 

由于每个步骤最多分支为两个递归调用，因此可能性总数呈指数增长，大约为`O(2^(m+n))`，使得对于像这样大的网格来说不切实际`200 x 200`。 

### 最佳解决方案的关键见解

 重要的观察结果是，到达某个小区的最小成本仅取决于其相邻小区的最小成本。 

到达细胞`(i, j)`，我们只能来自：

 - 上面的单元格`(i - 1, j)`- 左边的单元格`(i, j - 1)`所以：```
minimum_cost(i, j) =
grid[i][j] +
min(
    minimum_cost(i - 1, j),
    minimum_cost(i, j - 1)
)
```这是一个经典的动态规划问题，因为：

 1. 存在重叠的子问题
 2. 最优答案可以由较小的最优答案构建

 我们不是重复重新计算值，而是存储每个单元格的最小路径和并重复使用它。 

我们甚至可以就地修改输入网格以节省内存，将每个单元格视为存储到达该位置的最小成本。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^(m+n)) | O(2^(m+n)) | O(m+n) | 递归探索所有可能的路径 |
 | 最优动态规划| O(m × n) | O(1) 额外空间 | 通过更新网格重用先前计算的结果 |

 ## 算法演练

 1. 从左上角的单元格开始。 由于这是起始位置，因此它的值保持不变，因为没有之前的路径成本需要添加。 
2. 处理第一行。 由于移动仅限于向右或向下，因此只能从左侧到达第一行中的每个单元格。 因此，从左到右累加运行路径总和。 
3. 处理第一列。 同样，第一列中的每个单元格只能从上方到达。 从上到下累加运行路径总和。 
4. 逐行处理剩余的单元格。 对于每个单元格`(i, j)`，确定以下之间较小的路径和：

 - 正上方的单元格`(i - 1, j)`- 左边的单元格`(i, j - 1)`5. 将这两个值中较小的一个添加到当前单元格值中。 这会将单元格转化为到达该位置所需的最低成本。 
6. 继续，直到处理完右下角。 
7. 返回右下单元格中的值，因为它现在包含从开始到结束的最小路径总和。 

### 为什么它有效

 该算法之所以有效，是因为具有**最佳子结构属性**。 任何到单元格的最小路径本身都必须来自到上方单元格或左侧单元格的最小路径。 如果我们已经知道这些相邻单元格的最小路径总和，那么选择较小的路径总和可以保证当前单元格也获得最小可能的成本。 通过从左上到右下系统地填充网格，每个所需的子问题在需要之前就已经被解决了。 

## Python 解决方案```python
from typing import List

class Solution:
    def minPathSum(self, grid: List[List[int]]) -> int:
        rows = len(grid)
        cols = len(grid[0])

        # Process first row
        for col in range(1, cols):
            grid[0][col] += grid[0][col - 1]

        # Process first column
        for row in range(1, rows):
            grid[row][0] += grid[row - 1][0]

        # Process remaining cells
        for row in range(1, rows):
            for col in range(1, cols):
                grid[row][col] += min(
                    grid[row - 1][col],
                    grid[row][col - 1]
                )

        return grid[rows - 1][cols - 1]
```实现首先确定网格中的行数和列数。 

第一行是单独处理的，因为每个位置只能从左侧到达。 我们累积运行总和，以便每个单元格存储达到该总和的最小成本。 

第一列的处理方式类似。 由于在此列中只能向下移动，因此每个单元格都会添加正上方单元格的值。 

边界初始化后，我们处理网格的其余部分。 在每个位置，我们查看来自顶部和左侧邻居的最小路径和。 由于这些值已经代表了到达这些单元格的最佳方式，因此采用较小的值可以保证当前单元格的最佳结果。 

该算法就地更新原始网格，避免了额外的动态规划表的需要。 最后，右下角的单元格包含答案。 

## 解决方案```go
func minPathSum(grid [][]int) int {
	rows := len(grid)
	cols := len(grid[0])

	// Process first row
	for col := 1; col < cols; col++ {
		grid[0][col] += grid[0][col-1]
	}

	// Process first column
	for row := 1; row < rows; row++ {
		grid[row][0] += grid[row-1][0]
	}

	// Process remaining cells
	for row := 1; row < rows; row++ {
		for col := 1; col < cols; col++ {
			if grid[row-1][col] < grid[row][col-1] {
				grid[row][col] += grid[row-1][col]
			} else {
				grid[row][col] += grid[row][col-1]
			}
		}
	}

	return grid[rows-1][cols-1]
}
```Go 实现遵循与 Python 版本完全相同的动态编程逻辑。 

一个小小的区别是 Go 没有提供内置的`min()`函数用于整数，因此我们使用`if`陈述。 

该解决方案会就地修改输入切片，就像 Python 版本一样。 由于该问题保证了有效的输入维度，因此不需要对空网格进行额外检查。 

Go 整数在这里也是安全的，因为最大路径和是有界的。 最坏的情况是，一个`200 x 200`网格的值为`200`产生的总和远低于 Go 的极限`int`类型。

 ## 边缘情况

 ### 单细胞网格

 一个网格，例如`[[5]]`是最小的有效输入。 由于起点和目的地是同一单元格，因此最小路径总和就是已经存在的值。 有错误的实现可能会意外地跳过处理或尝试建立无效索引。 这个实现自然地处理它，因为所有循环都从索引开始`1`，这意味着不会发生额外的工作并且返回单个值。 

### 单行或单列

 如果网格仅包含一行或一列，则只有一条可能的路径。 在一行中，我们只能向右移动。 在单列中，我们只能向下移动。 这些情况通常会破坏假设向上和向左邻居都存在的实现。 这里，第一行和第一列分别初始化，确保正确处理。 

### 大量网格

 尽管每个单元格值可以高达`200`，总路径总和在许多单元中可能会变大。 某些实现可能会担心溢出或性能下降。 然而，最大可能的路径长度是有限的，并且在 Python 和 Go 中，结果总和仍然安全地保持在整数限制内。 

### 需要转弯的路径

 最佳路径并不总是视觉上明显或笔直的。 例如：```
[
  [1,100,1],
  [1,1,1]
]
```总是选择最小的直接邻居的贪婪策略在更复杂的情况下可能会做出糟糕的选择。 动态规划通过计算每个单元的全局最优路径总和来避免这个问题，确保最终答案始终正确。
