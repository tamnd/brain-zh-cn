[LeetCode 第 24 题](https://leetcode.com/problems/swap-nodes-in-pairs/)

 **难度：** 🟡 中等
 **主题：** 链表、递归

 ## 解决方案

 ## 问题理解

 该问题给了我们一个单链表的头，并要求我们交换每对相邻节点。 重要的细节是我们不允许修改存储在节点内的值。 我们必须通过更改指针来物理地重新排列节点连接。 

例如，如果链表是：`1 -> 2 -> 3 -> 4`交换相邻对后，变为：`2 -> 1 -> 4 -> 3`交换前两个节点，然后交换接下来的两个节点，依此类推。 

如果列表包含奇数个节点，则最终节点将保留在其原始位置，因为它没有可以交换的伙伴。 例如：`1 -> 2 -> 3`变成：`2 -> 1 -> 3`输入表示单链表的头指针。 每个节点包含一个整数值和一个指向下一个节点的指针。 输出应该是所有相邻交换完成后修改后的链表的头。 

约束相对较小，最多 100 个节点，因此从原始复杂性的角度来看，性能并不困难。 然而，挑战在于指针操作。 链表问题通常较少涉及渐近复杂性，而更多涉及正确处理引用而不丢失对列表部分的访问。 

一些边缘情况很重要：

 - 列表可能为空。 
- 该列表可能只包含一个节点。 
- 该列表可能包含奇数个节点。 
- 该列表可能恰好包含两个节点。 
- 不正确的指针更新可能会创建循环或断开列表中的节点。 

由于该问题禁止修改节点值，因此简单地交换值的解决方案是无效的，即使它们看起来更容易。 

## 方法

 ### 蛮力方法

 一种简单但无效的概念方法是交换相邻节点内的值，而不是重新排列节点本身。 

例如：`1 -> 2 -> 3 -> 4`可能会变成：`2 -> 1 -> 4 -> 3`通过交换存储在每对节点中的整数值。 

这种方法在逻辑上有效，因为可见序列看起来是正确的。 但是，问题明确指出节点值无法修改。 只有节点连接本身可能会改变。 

尽管这种方法在线性时间和恒定空间中运行，但它违反了问题要求。 

另一种暴力方式的方法是将所有节点复制到数组中，交换数组内的位置，然后重建链表连接。 这工作正常，但它使用了不必要的额外内存。 

### 最佳方法

 关键的观察是交换单链表中的两个相邻节点只需要更改几个指针。 

假设我们有：`prev -> A -> B -> nextPair`交换A和B后，我们想要：`prev -> B -> A -> nextPair`这可以通过三个指针更新来完成：

 1.`A.next = B.next`2.`B.next = A`3.`prev.next = B`为了简化列表头的处理，我们在原始头之前使用一个虚拟节点。 这避免了交换第一对时的特殊情况逻辑。 

然后，我们一次迭代列表中的两个节点，交换对，直到剩下的节点少于两个。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n) | O(n) | 将节点复制到数组中并重建连接 |
 | 最佳 | O(n) | O(1) | O(1) | 使用指针操作直接交换节点 |

 ## 算法演练

 1. 创建一个虚拟节点，其`next`指针指向链表的原始头。 这个虚拟节点有助于统一处理列表开头的交换。 
2. 初始化一个名为`prev`到虚拟节点。 该指针始终表示当前正在交换的对之前的节点。 
3. 当至少有两个节点可用于交换时继续处理。 具体来说，检查两者`prev.next`和`prev.next.next`存在。 
4. 识别当前对中的两个节点：

 -`first = prev.next`-`second = first.next`5. 保存该对之后的节点：

 -`next_pair = second.next`6. 通过改变指针来反转该对：

 - 点`second.next`到`first`- 观点`first.next`到`next_pair`7. 将列表的前一部分连接到交换的对：

 -`prev.next = second`8. 移动`prev`转发至`first`，它现在是交换对中的第二个节点。 
9. 重复此操作，直至没有完整的配对剩余。 
10. 返回`dummy.next`，它指向所有交换后的新头。 

### 为什么它有效

 在每次迭代中，算法都保持之前所有节点的不变性`prev`已经正确交换和连接。 当前对被隔离并重新排列，而不会失去对剩余列表的访问，因为`next_pair`在任何指针修改发生之前存储。 由于每对都恰好交换一次并且所有连接都正确恢复，因此最终的链表包含按所需顺序的所有原始节点。 

## Python 解决方案```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

from typing import Optional

class Solution:
    def swapPairs(self, head: Optional[ListNode]) -> Optional[ListNode]:
        dummy = ListNode(0)
        dummy.next = head

        prev = dummy

        while prev.next and prev.next.next:
            first = prev.next
            second = first.next

            # Save the start of the next pair
            next_pair = second.next

            # Swap the current pair
            second.next = first
            first.next = next_pair
            prev.next = second

            # Move prev to the end of the swapped pair
            prev = first

        return dummy.next
```实现首先创建一个虚拟节点。 这简化了边缘情况，因为列表的头部在第一次交换后可能会发生变化。 

这`prev`指针跟踪当前对之前的节点。 在每次循环迭代期间，算法将被交换的两个节点标识为`first`和`second`。 

在修改任何指针之前，代码存储`second.next`里面`next_pair`。 这可以防止失去对链表其余部分的访问。 

交换本身通过三个指针更新进行：

 -`second.next = first`-`first.next = next_pair`-`prev.next = second`交换后，`first`成为该对中的第二个节点，因此`prev`前进到`first`用于下一次迭代。 

最后，`dummy.next`返回是因为交换后原来的头可能不再是实际的头。 

## 解决方案```go
/**
 * Definition for singly-linked list.
 * type ListNode struct {
 *     Val int
 *     Next *ListNode
 * }
 */
func swapPairs(head *ListNode) *ListNode {
    dummy := &ListNode{Next: head}

    prev := dummy

    for prev.Next != nil && prev.Next.Next != nil {
        first := prev.Next
        second := first.Next

        // Save the start of the next pair
        nextPair := second.Next

        // Swap the pair
        second.Next = first
        first.Next = nextPair
        prev.Next = second

        // Move prev forward
        prev = first
    }

    return dummy.Next
}
```Go 实现遵循与 Python 版本相同的指针操作逻辑。 主要区别是 Go 的显式指针语法使用`*ListNode`。 

Go 使用`nil`而不是Python的`None`。 由于链表是 Go 中基于指针的结构，因此实现自然地直接操作节点引用，而无需额外的语言特定的复杂性。 

不存在整数溢出问题，因为节点值永远不会被修改或参与算术运算。

 ## 边缘情况

 ### 空列表

 空列表表示为`head = None`。 如果实现假设至少存在一个节点，这种情况很容易导致空指针错误。 

该解决方案可以安全地处理此问题，因为循环条件会检查：```
while prev.next and prev.next.next:
```如果`prev.next`是`None`，循环永远不会执行，函数立即返回`dummy.next`，这也是`None`。 

### 单节点列表

 只有一个节点的列表不能形成一对，因此不应发生交换。 

这种情况很棘手，因为盲目访问的实现`head.next`可能会崩溃。 循环条件通过在进入交换逻辑之前要求两个连续节点来防止这种情况。 

原始节点原样返回。 

### 奇数节点

 当列表长度为奇数时，最终节点没有相邻伙伴，必须保留在原位。 

例如：`1 -> 2 -> 3 -> 4 -> 5`变成：`2 -> 1 -> 4 -> 3 -> 5`该算法自然会处理这个问题，因为循环仅在两个节点可用时运行。 一旦只剩下一个节点，条件就会失败，最后一个节点将在其应有的位置保持连接。
