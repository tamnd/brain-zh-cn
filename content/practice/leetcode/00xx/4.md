 # 两个排序数组的中值

 ## 问题理解

 该问题给出两个单独排序的整数数组，`nums1`和`nums2`，有长度`m`和`n`。 任务是计算通过合并两个数组形成的组合排序序列的中位数。 

中位数是排序序列的中间值。 如果元素总数为奇数，则中位数是单个中间元素。 如果元素总数为偶数，则中位数为中间两个元素的平均值。 

例如，如果合并的数组是`[1, 2, 3]`，中位数是`2`。 如果合并后的数组是`[1, 2, 3, 4]`，中位数是`(2 + 3) / 2 = 2.5`。 

一个非常重要的细节是所需的时间复杂度：`O(log(m + n))`。 这立即排除了直接的基于合并的方法，因为完全合并数组需要线性时间。 问题是专门测试我们是否可以利用两个数组已经排序的事实。 

这些约束告诉我们一些有用的信息：

 - 任一数组都可以为空。 
- 组合长度始终至少为 1。 
- 两个数组都已按非降序排序。 
- 值可能为负值或正值。 
- 这里的总输入大小相对较小，但所需的渐近复杂度仍然很重要，因为这从根本上来说是一个算法设计问题。 

一些边缘情况尤其重要：

 - 一个数组可能完全是空的。 
- 一个数组可能包含比另一个数组小的所有值。 
- 数组的长度可能有很大不同。 
- 数组可能包含重复值。 
- 元素总数可以是奇数或偶数。 

这些情况通常会破坏二分搜索解决方案中不正确的分区逻辑或边界处理。 

## 方法

 ### 蛮力方法

 最直接的解决方案是将两个已排序的数组合并为一个已排序的数组，就像合并排序中的合并步骤一样。 

因为两个数组都已经排序，所以我们可以维护两个指针，并将较小的当前值重复追加到合并数组中。 合并完成后，我们计算合并结果的中位数。 

这种方法很容易理解并保证正确工作，因为合并的数组是完全排序的。 

然而，时间复杂度为`O(m + n)`，这违反了所需的对数运行时约束。 尽管约束不是很大，但该问题明确要求更有效的算法。 

### 最佳方法

 关键的见解是我们实际上不需要完全合并数组。 我们只需要足够的信息来确定中间的一个或多个元素。 

我们可以考虑将两个数组分为左半部分和右半部分，而不是合并，这样：

 - 左侧的每个值都小于或等于右侧的每个值。 
- 左半部分恰好包含总元素的一半。 

如果我们能找到这样的分区，那么：

 - 对于奇数总长度，中位数是从左侧算起的最大值。 
- 对于偶数总长度，中位数是最大左值和最小右值的平均值。 

因为数组是有序的，所以我们可以对较小数组中的分区位置进行二分查找。 这将运行时间减少到`O(log(min(m, n)))`。 

## 方法比较

 | 方法| 时间复杂度| 空间复杂度| 笔记|

 ## 算法演练

 ### 最优二分查找划分算法

 1. 始终对较小的数组执行二分查找。 

这很重要，因为二分搜索的复杂性取决于搜索空间的大小。 必要时交换数组可以保证对数复杂度保持最小。 
2.设较小的数组为`nums1`更大的数组是`nums2`。 

假设我们选择一个分区索引`partition1`在`nums1`。 然后我们就可以推导出对应的分区`nums2`作为：$$partition2 = \frac{m + n + 1}{2} - partition1$$这保证了左侧元素的总数等于组合长度的一半。 
3. 确定分区周围的四个边界值。 

我们需要：

 - 左值来自`nums1`- 正确的值来自`nums1`- 左值来自`nums2`- 正确的值来自`nums2`从概念上讲：```
nums1: [ left1 | right1 ]
nums2: [ left2 | right2 ]
```如果分区位于数组的边缘，我们使用负无穷大或正无穷大，因此比较仍然可以干净地进行。 
4. 检查分区是否有效。 

如果满足以下条件，则分区正确：$$left1 \le right2$$和$$left2 \le right1$$此条件保证左侧的每个元素都小于或等于右侧的每个元素。 
5. 如果划分有效，则计算中位数。 

如果总长度是奇数：$$median = \max(left1, left2)$$如果总长度是偶数：$$median = \frac{\max(left1, left2) + \min(right1, right2)}{2}$$6. 如果分区无效，则调整二分查找。 

- 如果`left1 > right2`，然后我们向右移动得太远了`nums1`，所以向左移动。 
- 否则，向右移动。 

### 为什么它有效

 该算法保持左侧分区始终包含全部元素的一半的不变性。 二分查找调整分区，直到所有左侧元素都小于或等于所有右侧元素。 

由于两个数组都是已排序的，因此一旦满足此分区条件，中位数必定位于左分区和右分区之间的边界。 最大左值和最小右值完全决定中位数。 

## Python 解决方案```python
from typing import List

class Solution:
    def findMedianSortedArrays(self, nums1: List[int], nums2: List[int]) -> float:
        # Ensure nums1 is the smaller array
        if len(nums1) > len(nums2):
            nums1, nums2 = nums2, nums1

        m, n = len(nums1), len(nums2)

        left = 0
        right = m

        while left <= right:
            partition1 = (left + right) // 2
            partition2 = (m + n + 1) // 2 - partition1

            max_left1 = float("-inf") if partition1 == 0 else nums1[partition1 - 1]
            min_right1 = float("inf") if partition1 == m else nums1[partition1]

            max_left2 = float("-inf") if partition2 == 0 else nums2[partition2 - 1]
            min_right2 = float("inf") if partition2 == n else nums2[partition2]

            if max_left1 <= min_right2 and max_left2 <= min_right1:
                if (m + n) % 2 == 1:
                    return float(max(max_left1, max_left2))

                return (
                    max(max_left1, max_left2)
                    + min(min_right1, min_right2)
                ) / 2.0

            elif max_left1 > min_right2:
                right = partition1 - 1

            else:
                left = partition1 + 1

        return 0.0
```实施首先要确保`nums1`是较小的数组。 这保证了二分搜索在较小的搜索空间上运行。 

二分搜索范围跨越所有可能的分区位置`nums1`， 从`0`到`m`。 

在每次迭代中，算法都会计算两个数组的分区索引。 分区在`nums2`自动导出，以便左侧始终包含总元素的一半。 

四个边界变量表示与分区直接相邻的值。 在越界情况下使用无穷大可以避免复杂的特殊情况逻辑。 

主要条件检查分区是否有效。 如果是，算法将根据总长度是奇数还是偶数来计算中位数。 

如果分区无效，二分查找会适当缩小搜索空间。 

决赛`return 0.0`从技术上讲是无法访问的，因为该问题保证了有效输入。 

## 解决方案```go
import "math"

func findMedianSortedArrays(nums1 []int, nums2 []int) float64 {
	if len(nums1) > len(nums2) {
		return findMedianSortedArrays(nums2, nums1)
	}

	m := len(nums1)
	n := len(nums2)

	left := 0
	right := m

	for left <= right {
		partition1 := (left + right) / 2
		partition2 := (m + n + 1) / 2 - partition1

		maxLeft1 := math.Inf(-1)
		if partition1 > 0 {
			maxLeft1 = float64(nums1[partition1-1])
		}

		minRight1 := math.Inf(1)
		if partition1 < m {
			minRight1 = float64(nums1[partition1])
		}

		maxLeft2 := math.Inf(-1)
		if partition2 > 0 {
			maxLeft2 = float64(nums2[partition2-1])
		}

		minRight2 := math.Inf(1)
		if partition2 < n {
			minRight2 = float64(nums2[partition2])
		}

		if maxLeft1 <= minRight2 && maxLeft2 <= minRight1 {
			if (m+n)%2 == 1 {
				if maxLeft1 > maxLeft2 {
					return maxLeft1
				}
				return maxLeft2
			}

			leftMax := math.Max(maxLeft1, maxLeft2)
			rightMin := math.Min(minRight1, minRight2)

			return (leftMax + rightMin) / 2.0
		}

		if maxLeft1 > minRight2 {
			right = partition1 - 1
		} else {
			left = partition1 + 1
		}
	}

	return 0.0
}
```Go 实现遵循与 Python 版本完全相同的算法结构。 

一个重要的区别是处理无穷大。 Go 使用`math.Inf(-1)`和`math.Inf(1)`因为Go没有Python风格`float("inf")`。 

另一个区别是显式转换`int`到`float64`在进行比较和中值计算之前。 

Go 中的切片自然会处理空数组，因此不需要额外的 nil 处理。

 ## 边缘情况

 当一个数组为空时，就会出现一种重要的边缘情况。 许多实现在分区计算期间意外访问无效索引。 该解决方案使用负无穷大和正无穷大作为边界值来干净地处理这种情况。 如果分区完全落在数组之外，比较仍然可以正确运行。 

当一个数组的所有元素都小于另一个数组的所有元素时，就会出现另一种棘手的情况。 例如：```
nums1 = [1, 2]
nums2 = [100, 101]
```不正确的分区逻辑可能会失败，因为有效分区位于一个数组的最边缘。 该实现明确支持索引处的分区`0`和索引`m`，它可以正确处理这些边界配置。 

包含许多重复值的数组也很重要。 一些实现错误地使用严格的不等式而不是非严格的比较。 该算法使用`<=`，它允许跨分区边界使用相同的值并正确处理重复项。 

最后一个微妙的边缘情况是数组的大小显着不同。 例如：```
nums1 = [1]
nums2 = [2,3,4,5,6,7,8]
```对较小数组进行二分查找既保证了正确性又保证了效率。 无论大小是否不平衡，分区公式都继续有效。
