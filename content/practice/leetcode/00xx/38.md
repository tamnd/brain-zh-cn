 # LeetCode 38，数数并说

 ## 问题理解

 该问题要求我们生成`n`“数并说”序列的第一项。 该序列是递归构建的，其中每个术语都是通过描述前一个术语来创建的。 

该序列开始于：```
1
```为了生成下一项，我们从左到右读取当前字符串并描述连续的相同数字组。 

例如：```
"1"
```包含一个`1`，因此下一项变为：```
"11"
```然后：```
"11"
```包含两个`1`s，因此下一项变为：```
"21"
```然后：```
"21"
```包含一个`2`随后是一个`1`，因此下一项变为：```
"1211"
```输入`n`表示我们需要返回序列中的哪一项。 输出是与该术语相对应的确切字符串。 

限制很小：```
1 <= n <= 30
```这告诉我们几个重要的事情：

 - 我们永远不需要生成非常大的序列。 
- 指数爆炸有些有限，因为`n`上限为 30。 
- 直接迭代模拟是实用的。 
- 我们应该更多地关注干净的序列生成而不是先进的优化技术。 

一个重要的细节是序列仅从连续的组生成。 例如：```
"111221"
```必须解释为：

 - 三个`1`s
 - 两个`2`s
 - 一个`1`变成：```
"312211"
```如果幼稚的实现不能正确处理组之间的转换或者在完成循环后忘记处理最终组，则它可能会失败。 

关键的边缘情况包括：

 -`n = 1`，应该立即返回`"1"`- 每个字符都不同的字符串
 - 所有字符都相同的字符串
 - 迭代结束后正确处理最后一串数字

 该问题保证了`n`始终有效且为正，因此我们不需要额外的输入验证。 

## 方法

 ### 蛮力方法

 蛮力方法是递归地生成前面的每一项，直到我们达到`n`第 3 项。 

对于每个术语：

 1. 从左到右扫描前一个字符串。 
2. 统计连续重复的字符。 
3. 追加`"count + digit"`构建下一个字符串。 
4. 重复直到学期`n`被生成。 

这种方法是正确的，因为每个术语都是直接从前一个术语定义的。 如果我们在每一步都准确地执行游程编码，我们最终将获得正确的序列。 

然而，递归会带来不必要的开销。 由于每个术语仅依赖于前一个术语，因此存储深度递归调用堆栈并不理想。 递归方法还存在可读性降低和内存使用率稍高的风险。 

### 最佳方法

 最佳解决方案使用迭代模拟。 

关键的观察是每个项仅取决于前一项，而不取决于序列的整个历史。 

这意味着我们可以：

 - 开始于`"1"`- 重复生成下一个字符串
 - 每次迭代替换当前字符串

 为了有效地生成下一项：

 - 使用指针扫描字符串
 - 计算连续相同的数字
 - 将计数和数字附加到结果生成器
 - 继续，直到处理完整个字符串

 这种方法高效、简单，并且避免了递归开销。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(T)| O(T)| 所有项的递归生成，额外的递归堆栈 |
 | 最佳| O(T)| O(T)| 迭代游程编码生成 |

 这里，`T`表示所有序列项生成的字符总数`n`。 

## 算法演练

 1. 用基本情况初始化序列`"1"`。 

这是序列的第一项，后面的每一项都是从它派生出来的。 
2.重复生成过程`n - 1`次。 

由于我们已经有了第一项，因此我们只需要生成剩余的项。 
3. 对于每次迭代，创建一个空列表或字符串生成器来构造下一个序列。 

在许多语言中，使用串联增量构建字符串效率很低，因此最好使用构建器结构。 
4. 从左到右扫描当前字符串。 

使用索引指针来跟踪当前位置。 
5. 统计连续的相同字符。 

开始一个柜台`1`，然后在下一个字符与当前字符匹配时继续前进。 
6. 将计数后跟数字附加到构建器。 

例如：

-`"111"`变成`"31"`-`"22"`变成`"22"`7. 继续扫描，直到处理完整个字符串。 

每个字符必须恰好属于一个连续的组。 
8. 用新构造的字符串替换当前序列。 

这个新生成的字符串将成为下一次迭代的输入。 
9. 完成所有迭代后，返回最终序列。 

### 为什么它有效

 该算法之所以有效，是因为序列中的每一项都被定义为前一项的游程长度编码。 在每次迭代期间，算法将当前字符串划分为相同连续数字的最大组。 每个组都被编码一次，如下所示`"count + digit"`。 由于每个字符都属于一个且仅一个组，因此生成的字符串与问题定义精确匹配。 

## Python 解决方案```python
class Solution:
    def countAndSay(self, n: int) -> str:
        current = "1"

        for _ in range(n - 1):
            next_sequence = []
            index = 0

            while index < len(current):
                count = 1

                while (
                    index + 1 < len(current)
                    and current[index] == current[index + 1]
                ):
                    count += 1
                    index += 1

                next_sequence.append(str(count))
                next_sequence.append(current[index])

                index += 1

            current = "".join(next_sequence)

        return current
```实现从基本序列开始`"1"`。 

外循环运行`n - 1`次，因为第一个术语已经存在。 在每次迭代期间，我们都会从当前项构造下一项。 

变量`index`扫描当前字符串。 对于每个位置，我们计算出现的连续相同数字的数量。 

内部`while`只要下一个字符与当前字符匹配，循环就会前进。 这可以正确地将重复的数字组合在一起。 

计算完一组后，我们追加：

 - 频率
 - 数字本身

 到`next_sequence`列表。 

使用列表和`"".join()`是高效的，因为重复的字符串连接会创建许多中间字符串。 

最后，新生成的序列替换`current`，并且重复该过程直到产生所需的项。 

## 解决方案```go
import (
	"strconv"
	"strings"
)

func countAndSay(n int) string {
	current := "1"

	for i := 0; i < n-1; i++ {
		var builder strings.Builder

		index := 0

		for index < len(current) {
			count := 1

			for index+1 < len(current) &&
				current[index] == current[index+1] {
				count++
				index++
			}

			builder.WriteString(strconv.Itoa(count))
			builder.WriteByte(current[index])

			index++
		}

		current = builder.String()
	}

	return current
}
```Go 实现遵循与 Python 版本相同的算法结构。 

Go 没有使用列表来构造字符串，而是使用`strings.Builder`，这对于重复的字符串追加非常有效。`strconv.Itoa()`在附加之前将整数计数转换为字符串。 

由于 Go 字符串是字节索引的并且序列仅包含数字，因此可以使用`current[index]`安全高效。 

无需担心整数溢出，因为序列长度在问题约束内仍然相对较小。

 ## 边缘情况

 一个重要的边缘情况是`n = 1`。 这是整个序列的基本情况。 一个常见的错误是即使不应该创建其他项，也会运行生成循环。 该实现正确处理了这个问题，因为循环执行`n - 1`次，当`n = 1`。 

当当前字符串中的所有数字都相同时，会出现另一个重要的边缘情况。 例如：```
"1111"
```有缺陷的实现可能会意外地将运行分成多个组或无法计算所有重复次数。 解决方案中的内部循环继续前进，直到数字发生变化，从而保证整个运行都被计数在一起。 

第三个重要的边缘情况涉及处理字符串中的最后一组。 许多实现可以正确检测组之间的转换，但忘记在循环结束后附加最后一个组。 此解决方案避免了该问题，因为在遍历过程中会立即处理每个组，包括最后一个组。 

当每个数字都与下一个数字不同时，就会出现另一种微妙的情况，例如：```
"121212"
```在这种情况下，每个组的长度都是一。 该算法仍然可以正确工作，因为计数开始于`1`在检查重复数字之前。
