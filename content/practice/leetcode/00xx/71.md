[LeetCode 第 71 题](https://leetcode.com/problems/simplify-path/)

 **难度：** 🟡 中等
 **主题：** 字符串、堆栈

 ## 解决方案

 ## 问题理解

 该问题为我们提供了一个绝对的 Unix 风格的文件路径，并要求我们将其转换为其规范的简化形式。 

绝对路径总是从根目录开始，表示为`/`。 输入路径可能包含不必要的组件，例如重复的斜杠、对当前目录的引用或对父目录的引用。 我们的工作是在遵循 Unix 文件系统规则的同时标准化路径。 

输入字符串可以包含四种重要类型的路径组件：

 1. 普通目录名称如`"home"`或者`"Documents"`2. 单一时期`"."`，这意味着“留在当前目录”
 3.双周期`".."`，这意味着“移动到父目录”
 4、连续斜杠造成的空组件如`"//"`输出必须是满足以下所有条件的规范路径：

 - 它以一个斜线开头
 - 目录名称恰好由一个斜杠分隔
 - 它不会以尾部斜杠结尾，除非路径很简单`/`- 它不包含`"."`或者`".."`作为导航指令

 一个微妙但非常重要的细节是，只有`"."`和`".."`有特殊意义。 字符串如`"..."`或者`"...."`被视为普通目录名称。 专门处理任何周期序列的幼稚实现会产生不正确的结果。 

约束告诉我们路径长度最多可以为 3000 个字符。 这个值足够小，即使效率较低的解决方案也可能通过，但自然最优解决方案以线性时间运行，并且易于实现。 

一些边缘情况尤其重要：

 - 例如，不允许移动到根目录之上`"/../"`仍应成为`"/"`- 多个连续的斜线应该折叠成一个
 - 应删除尾部斜杠
 -`"."`应该完全忽略
 -`".."`应删除先前的有效目录（如果存在）
 - 名字如`"..."`应保持不变，因为它们是有效的目录名称

 ## 方法

 ### 蛮力方法

 强力解决方案可以重复扫描和修改字符串，直到无法进行更多简化。 

例如，我们可以：

 - 更换`"//"`和`"/"`- 删除出现的`"/./"`- 解决父目录模式，例如`"/a/../"`这个过程将重复进行，直到路径稳定为止。 

这是有效的，因为每一次传递都会进一步简化路径，最终达到规范形式。 然而，重复重建和重新扫描字符串效率很低。 每次替换操作可能需要遍历字符串的大部分，并且可能需要多次遍历。 

在最坏的情况下，这种方法可能会变得二次，因为每次简化都可能触发路径的另一次完整扫描。 

### 最佳方法

 关键的见解是路径处理自然地表现得像堆栈问题。 

遍历目录时：

 - 输入目录将其推送到当前路径
 - 相遇`".."`删除最近的目录
 - 相遇`"."`没有改变任何东西

 这与堆栈行为完全匹配。 

我们使用分割路径`/`作为分隔符，对各个成分一一进行处理：

 - 忽略空字符串和`"."`- 从堆栈中弹出`".."`如果可能的话
 - 将普通目录名称压入堆栈

 最后，堆栈按顺序包含规范路径组件。 

这种方法对每个组件只处理一次，使其时间复杂度呈线性。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(n²) | O(n) | 重复字符串重建和重新扫描|
 | 最佳 | O(n) | O(n) | 使用堆栈的单遍 |

 ## 算法演练

 1.使用分割路径字符串`'/'`作为分隔符。 

这会将路径转换为单独的组件。 连续的斜杠自然会创建空字符串，我们稍后可以忽略它。 

例子：```
"/home//foo/"
```变成：```
["", "home", "", "foo", ""]
```2. 创建一个空堆栈。 

堆栈表示当前有效的规范路径。 添加到堆栈中的每个目录名称都代表更深入地进入文件系统层次结构。 
3. 逐一处理每个组件。 

对于每个组件：

 - 如果组件为空或`"."`，忽略它。 

- 空字符串来自重复的斜杠
 -`"."`表示留在当前目录
 - 如果该组件是`".."`：

 - 从堆栈中删除最新的目录（如果存在）
 - 如果堆栈已经为空，则不执行任何操作，因为我们无法移动到根之上
 - 否则，将该组件视为有效的目录名并将其压入堆栈。 
4. 重建规范路径。 

使用以下命令连接堆栈中的所有目录名称`'/'`并在前面添加一个前导斜杠。 

例子：```
["home", "user", "Pictures"]
```变成：```
"/home/user/Pictures"
```5. 返回结果字符串。 

### 为什么它有效

 堆栈始终为迄今为止处理的所有组件维护正确的规范路径。 

每当我们进入一个目录时，我们都会将其压入堆栈。 每当我们遇到`".."`，我们删除最近的目录，因为移动到父目录会反转最近的下降。 忽略`"."`空字符串保留正确的文件系统语义。 

由于每个组件都被处理一次并且每个操作都维护有效的路径状态，因此最终重构的路径保证是正确的规范形式。 

## Python 解决方案```python
class Solution:
    def simplifyPath(self, path: str) -> str:
        stack: list[str] = []

        components = path.split("/")

        for component in components:
            if component == "" or component == ".":
                continue

            if component == "..":
                if stack:
                    stack.pop()
            else:
                stack.append(component)

        return "/" + "/".join(stack)
```实现首先使用将输入路径拆分为多个组件`/`作为分隔符。 这使我们能够独立处理每个目录令牌。 

这`stack`存储有效的目录层次结构。 每个普通目录名称都会附加到堆栈中，因为它代表下降到目录中。 

当算法遇到`".."`，如果可能的话，它会从堆栈中删除最新的目录。 这模拟移动到父目录。 

空字符串和`"."`被忽略，因为它们不影响规范位置。 

最后，使用单斜杠将堆栈内容连接在一起，并添加前导斜杠以生成最终的规范路径。 

## 解决方案```go
func simplifyPath(path string) string {
    stack := []string{}

    components := strings.Split(path, "/")

    for _, component := range components {
        if component == "" || component == "." {
            continue
        }

        if component == ".." {
            if len(stack) > 0 {
                stack = stack[:len(stack)-1]
            }
        } else {
            stack = append(stack, component)
        }
    }

    return "/" + strings.Join(stack, "/")
}
```Go 实现遵循与 Python 解决方案相同的逻辑。 主要区别在于 Go 使用切片而不是动态列表。 

使用切片截断从堆栈中删除顶部元素：```go
stack = stack[:len(stack)-1]
```该解决方案还使用`strings.Split`和`strings.Join`来自标准库，因此完整的 LeetCode 提交需要：```go
import "strings"
```不存在整数溢出问题，因为该算法仅操作字符串和切片索引。

 ## 边缘情况

 一种重要的边缘情况是尝试移动到根目录之上。 例如，输入`"/../../a"`在进入之前尝试多次向上移动`"a"`。 有缺陷的实现可能会错误地创建无效的负遍历状态。 此实现通过仅在堆栈非空时从堆栈中弹出来避免该问题。 

另一个关键的边缘情况涉及多个连续斜杠，例如`"/a///b//c/"`。 分裂于`/`创建空字符串组件。 如果将这些空字符串视为目录，则最终输出将变得不正确。 该实现显式忽略空组件，这会自然地将重复的斜杠折叠为单个分隔符。 

一个微妙但非常常见的错误来源是错误地处理点序列。 仅有的`"."`和`".."`很特别。 字符串如`"..."`,`"...."`， 或者`"..hidden"`是普通的目录名。 一些简单的解决方案错误地将任何包含句点的字符串视为导航语法。 该实现检查与以下内容是否完全相等`"."`和`".."`，确保所有其他名称仍然有效的路径组件。 

当最终规范路径应该是根目录本身时，会出现另一种边缘情况。 例如，输入如下`"/a/.."`或者`"/./"`最终简化为一个空栈。 该实现正确地将路径重建为`"/"`而不是返回一个空字符串。
