[LeetCode 第 44 题](https://leetcode.com/problems/wildcard-matching/)

 **难度：** 🔴难
 **主题：** 字符串、动态规划、贪心、递归

 ## 解决方案

 ## 问题理解

 这个问题要求我们判断整个输入字符串是否`s`匹配通配符模式`p`。 

该模式支持两个特殊的通配符：

 -`'?'`恰好匹配一个字符。 
-`'*'`匹配任何字符序列，包括空序列。 

重要的细节是匹配必须覆盖整个字符串。 不允许部分匹配。 中的每个角色`s`必须被模式消耗，并且模式中的每个字符也必须被考虑在内。 

例如：

-`s = "aa"`和`p = "a"`不匹配，因为模式仅覆盖一个字符，而字符串包含两个字符。 
-`s = "aa"`和`p = "*"`匹配因为`'*'`可以代表整个字符串。 
-`s = "cb"`和`p = "?a"`不匹配，因为`'?'`比赛`'c'`， 但`'a'`不匹配`'b'`。 

约束条件很重要：

 -`0 <= s.length, p.length <= 2000`暴力递归解决方案会呈指数级爆炸，因为每个`'*'`可以表示许多不同的子串长度。 由于两个字符串都可以长达 2000 个字符，因此我们需要更高效的东西。 

一些边缘情况尤其重要：

 - 空字符串和空模式。 
- 模式仅包含`'*'`。 
- 多次连续`'*'`人物。 
- 图案比字符串长。 
-`'*'`匹配零个字符。 
-`'*'`匹配许多字符。 

当需要回溯时，幼稚的实现通常会失败，特别是对于普通字符的组合，`'?'`， 和`'*'`。 

## 方法

 ### 蛮力方法

 暴力解决方案使用递归来尝试每一种可能的解释`'*'`。 

在每个位置：

 - 如果字符直接匹配，或者模式字符是`'?'`，将两个指针向前移动。 
- 如果模式字符是`'*'`，尝试所有可能性：

 - 匹配零个字符。 
- 匹配一个字符。 
- 匹配两个字符。 
- 继续直到字符串末尾。 

这种方法是正确的，因为它探索了通配符模式的每种有效解释。 如果任何递归路径成功消耗字符串和模式，则答案是`true`。 

问题是`'*'`创建分支递归。 具有许多星星的模式会导致大量重复的子问题。 复杂度呈指数级增长，这对于长度为 2000 的字符串来说太慢了。 

### 最优贪心法

 关键的见解是我们实际上不需要尝试每一种可能的扩展`'*'`立即地。 

相反，我们可以贪婪地处理字符串，同时记住：

 - 最新的`'*'`在图案中的位置。 
- 字符串中的位置`'*'`开始匹配。 

当字符正常匹配时，两个指针都会前进。 

当我们遇到`'*'`，我们记录它的位置并在模式中向前移动。 最初，我们让`'*'`匹配一个空序列。 

如果我们后来遇到不匹配的情况，我们会回溯到最近的`'*'`并将其匹配范围再增加一个字符。 

这有效是因为`'*'`是唯一能够吸收任意长度的通配符。 通过仅在必要时贪婪地扩展它，我们可以避免指数分支。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(2^(n+m)) | O(2^(n+m)) | O(n+m) | 尝试一切可能的扩展`'*'`|
 | 最佳 | O(n + m) | O(1) | O(1) | 贪婪匹配与受控回溯 |

 ## 算法演练

 ### 第 1 步：初始化指针

 我们维护两个指数：

 -`s_index`对于输入字符串。 
-`p_index`对于模式。 

我们还维护：

 -`star_index`，最近的位置`'*'`在模式中。 
-`match_index`，字符串中对应的位置`'*'`。 

最初：

-`star_index = -1`-`match_index = -1`值为`-1`意味着我们还没有看到`'*'`然而。 

### 步骤 2：在保留字符串的同时处理字符

 只要`s_index < len(s)`：

 我们将当前模式字符与当前字符串字符进行比较。 

### 第 3 步：处理直接匹配或`'?'`如果：

-`p[p_index] == s[s_index]`- 或者`p[p_index] == '?'`那么当前的字符是兼容的。 

将两个指针前移，因为一个模式字符消耗一个字符串字符。 

### 第 4 步：处理`'*'`如果当前模式字符是`'*'`：

 1.保存星星位置：

 -`star_index = p_index`2. 保存当前字符串位置：

 -`match_index = s_index`3. 向前移动花样指针。 

此时，我们假设`'*'`匹配零个字符。 

### 步骤 5：处理与先前的不匹配`'*'`如果字符不匹配，但我们之前遇到过`'*'`：

 1.返回星号后的字符：

 -`p_index = star_index + 1`2. 将星号匹配扩展一个字符：

 -`match_index += 1`3. 重新开始匹配：

 -`s_index = match_index`这实际上意味着：

 “上一个`'*'`应该再吸收一个角色。”

 ### 步骤 6：处理不可能的不匹配

 如果存在不匹配并且没有更早`'*'`存在，匹配是不可能的。 

返回`False`。 

### 步骤 7：消耗剩余的星星

 字符串处理完毕后，剩余的模式字符必须全部被`'*'`。 

跳过它们。 

### 第 8 步：最终验证

 如果模式也被完全消耗，则返回`True`。 

否则返回`False`。 

### 为什么它有效

 该算法保持了之前所有字符的不变性`s_index`和`p_index`已经正确匹配。 

每当发生不匹配时，唯一能够修复不匹配的灵活结构是最新的`'*'`。 通过逐步扩大该明星的覆盖范围，我们系统地探索所有必要的可能性，而无需重新检查早期的成功比赛。 

Since each pointer only moves forward overall, the algorithm remains linear.

 ## Python 解决方案```python
class Solution:
    def isMatch(self, s: str, p: str) -> bool:
        s_index = 0
        p_index = 0

        star_index = -1
        match_index = -1

        while s_index < len(s):
            # Direct match or '?'
            if (
                p_index < len(p)
                and (p[p_index] == s[s_index] or p[p_index] == '?')
            ):
                s_index += 1
                p_index += 1

            # Found '*'
            elif p_index < len(p) and p[p_index] == '*':
                star_index = p_index
                match_index = s_index
                p_index += 1

            # Previous '*' can absorb one more character
            elif star_index != -1:
                p_index = star_index + 1
                match_index += 1
                s_index = match_index

            # No match possible
            else:
                return False

        # Remaining pattern characters must all be '*'
        while p_index < len(p) and p[p_index] == '*':
            p_index += 1

        return p_index == len(p)
```其实现完全遵循贪婪策略。 

变量`s_index`和`p_index`跟踪我们在字符串和模式中的当前位置。 

当字符直接匹配，或者模式包含`'?'`，两个指针都会前进，因为一个模式字符消耗一个字符串字符。 

当一个`'*'`出现后，代码中存储了两条信息：

 -`star_index`，恒星出现的地方。 
-`match_index`，该星号开始在字符串中匹配。 

最初，星号被视为匹配零个字符。 

如果稍后发生不匹配，算法将重新访问最近的恒星并将其覆盖范围增加一个字符。 这避免了递归分支，同时仍然探索所有有效的可能性。 

最后，在字符串用完之后，任何剩余的模式字符都必须被`'*'`因为只有星号才能代表空后缀。 

## 解决方案```go
func isMatch(s string, p string) bool {
	sIndex := 0
	pIndex := 0

	starIndex := -1
	matchIndex := -1

	for sIndex < len(s) {

		// Direct match or '?'
		if pIndex < len(p) &&
			(p[pIndex] == s[sIndex] || p[pIndex] == '?') {

			sIndex++
			pIndex++

		// Found '*'
		} else if pIndex < len(p) && p[pIndex] == '*' {

			starIndex = pIndex
			matchIndex = sIndex
			pIndex++

		// Previous '*' absorbs one more character
		} else if starIndex != -1 {

			pIndex = starIndex + 1
			matchIndex++
			sIndex = matchIndex

		// No possible match
		} else {
			return false
		}
	}

	// Remaining pattern characters must be '*'
	for pIndex < len(p) && p[pIndex] == '*' {
		pIndex++
	}

	return pIndex == len(p)
}

Go字符串是字节索引的，这在这里是安全的，因为问题只保证小写英文字母和通配符。 不需要 Unicode 处理。 

该实现直接使用整数索引而不是切片或递归，从而保持内存使用量恒定。

 ## 边缘情况

 一种重要的边缘情况是具有非空模式的空字符串。 许多实现错误地假设任何通配符模式都可以匹配空字符串。 事实上，只有完全由`'*'`可以这样做。 该实现通过跳过末尾剩余的星号并验证没有剩余非星号字符来正确处理此问题。 

另一个棘手的情况涉及多个连续的`'*'`字符如`"**a***b*"`。 朴素的递归解决方案可能会重复探索等效状态。 贪婪的实现自然会处理这个问题，因为每个`'*'`处理方式相同，冗余星不会产生额外的复杂性。 

第三个重要的边缘情况是在先前成功的星形扩展之后发生不匹配。 例如，`"adceb"`和`"*a*b"`要求算法重新访问较早的恒星并多次扩展其覆盖范围。 许多不正确的解决方案都会失败，因为它们过早贪婪地消耗了太多字符并且无法恢复。 此实现显式存储最新的星号位置，并仅在需要时增量扩展它，从而保证正确性。 

当模式在字符串之前完成时，会出现最后一个微妙的边缘情况。 例如，`"abc"`和`"ab"`。 有些实现在部分匹配后错误地返回 true。 该算法避免了该错误，因为主循环一直持续到整个字符串被消耗为止，并且任何不匹配的剩余字符都会强制失败，除非先前的`'*'`可以吸收它们。
