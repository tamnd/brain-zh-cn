[LeetCode 第 37 题](https://leetcode.com/problems/sudoku-solver/)

 **难度：** 🔴难
 **主题：** 数组、哈希表、回溯、矩阵

 ## 解决方案

 ## 问题理解

 该问题要求我们构建一个完整的数独求解器。 我们得到了部分填充的`9 x 9`网格，其中每个单元格包含一个数字`'1'`到`'9'`或角色`'.'`，它代表一个空白空间。 我们的目标是填充每个空单元格，以便最终的棋盘满足所有数独规则。 

有效的数独板必须同时遵循三个约束：

 1. 每行必须包含以下每个数字`1`通过`9`正好一次。 
2. 每列必须包含以下每个数字`1`通过`9`正好一次。 
3. 每个`3 x 3`子网格必须包含来自`1`通过`9`正好一次。 

重要的细节是我们不会生成任何任意有效的数独板。 我们必须完成输入中给出的特定棋盘，同时保留所有现有数字。 

该函数不返回新板。 相反，它直接就地修改输入板。 这意味着我们的算法必须仔细更新单元格并在必要时撤消更改。 

这些约束告诉我们一些重要的事情：

 - 板尺寸固定为`9 x 9`- 每个单元格包含一个数字或`'.'`- 谜题总是有一个有效的解决方案

 虽然网格尺寸很小，但搜索空间却很大。 每个空单元格都可能包含多个值，这会产生指数级的可能性。 如果不及早修剪无效状态，简单的暴力搜索很快就会变得不可行。 

一些边缘情况可能会导致简单实现中出现问题：

 - 具有许多空单元格的板创建一个非常大的搜索树
 - 不正确的放置验证可能会导致无效的中间状态
 - 忘记正确回溯可能会破坏棋盘状态
 - 子框索引处理不当通常会导致微妙的错误
 - 某些单元格可能只有一个有效选项，而其他单元格可能有多个

 保证谜题只有一个解可以简化实现，因为一旦找到有效的完整棋盘，我们就可以停止搜索。 

## 方法

 ### 蛮力方法

 暴力策略会尝试每个空单元格中的每个可能的数字，而无需提前使用有关数独约束的大量信息。 

对于每个空单元格，我们尝试从`1`通过`9`。 放置一个数字后，我们递归地继续求解剩余的单元格。 如果我们最终遇到矛盾，我们会回溯并尝试另一个数字。 

这种方法是正确的，因为它系统地探索了所有可能的电路板配置。 由于有效的解决方案存在于搜索树中的某个位置，详尽的探索保证我们最终找到它。 

然而，这种方法非常慢，因为可能的状态数量呈指数增长。 如果有`k`空单元格，最坏情况的搜索空间约为`9^k`。 即使只有 50 个空单元格，这也将变得天文数字般庞大。 

主要问题是暴力方法浪费时间探索许多明显无效的状态。 

### 最优方法，带约束跟踪的回溯

 关键的见解是数独约束允许我们立即拒绝无效状态，而不是深入探索它们。 

我们不是在每次测试数字时重复扫描行、列和子框，而是维护快速查找结构来跟踪每行、列和框中已经存在的数字。 

对于每个展示位置：

 - 检查当前行中是否已存在该数字
 - 检查当前列是否存在
 - 检查对应的是否存在`3 x 3`盒子

 如果任何约束失败，我们立即跳过该数字。 

这将解决方案转变为具有积极修剪的经典回溯问题。 该算法仅探索仍然可能有效的状态。 

由于无效分支会提前终止，因此实际运行时间比简单的暴力破解要快得多。 

| 方法| 时间复杂度| 空间复杂度| 笔记|
 | --- | --- | --- | --- |
 | 蛮力 | O(9^k × 81) | O(9^k × 81) | O(k) | 重复扫描行、列和框以进行验证 |
 | 最佳| O(9^k) | O(9^k) | O(k + 81) | 使用哈希集进行恒定时间约束检查 |

 这里，`k`代表空单元格的数量。 

## 算法演练

 ### 第 1 步：初始化跟踪结构

 我们创建了三个集合：

 -`rows`-`cols`-`boxes`每个存储哪些数字已被使用。 

例如：

-`rows[0]`包含已放置在行中的所有数字`0`-`cols[3]`包含已放置在列中的所有数字`3`-`boxes[4]`包含已放置在中心的所有数字`3 x 3`盒子

 我们使用集合是因为成员资格检查非常快，大约`O(1)`。 

### 步骤 2：记录现有数字

 我们扫描黑板一次。 

每当我们遇到一个数字时：

 - 添加到对应的行集中
 - 添加到对应的列集中
 - 将其添加到相应的盒子组中

 此预处理步骤允许立即进行未来的有效性检查。 

### 第 3 步：收集空单元格

 我们不会在递归过程中重复扫描棋盘上的空单元格，而是将所有空位置预先存储在列表中。 

每个空单元格表示为`(row, col)`。 

这减少了不必要的重复工作。 

### 步骤 4：开始递归回溯

 我们一次递归地处理一个空单元格。 

在递归级别`index`：

 - 检索对应的空单元格
 - 尝试输入数字`'1'`通过`'9'`对于每个候选数字：

 - 检查行中是否已经存在
 - 检查列中是否已存在
 - 检查盒子中是否已存在

 如果数字有效：

 - 将其放在板上
 - 更新跟踪集
 - 继续递归

 ### 步骤 5：处理死胡同

 如果递归求解失败，则当前位置不正确。 

我们必须撤消所有更改：

 - 从板上删除数字
 - 将其从行跟踪中删除
 - 将其从列跟踪中删除
 - 将其从盒子跟踪中删除

 这个恢复过程的本质就是回溯。 

### 第 6 步：检测完成情况

 如果我们成功处理所有空单元格，难题就解决了。 

那时我们返回`True`并停止进一步递归。 

### 为什么它有效

 该算法在整个执行过程中保持一个重要的不变量：

 递归探索的每个部分填充的棋盘总是满足所有数独约束。 

每当我们放置一个数字时，我们首先验证它是否违反任何规则。 因此，递归调用仅在有效的中间状态上运行。 

回溯保证了完整性，因为最终会探索每个可能的有效数字分配。 由于问题保证了唯一的解决方案，因此我们找到的第一个完整的有效板必定是正确答案。 

## Python 解决方案```python
from typing import List

class Solution:
    def solveSudoku(self, board: List[List[str]]) -> None:
        """
        Do not return anything, modify board in-place instead.
        """

        rows = [set() for _ in range(9)]
        cols = [set() for _ in range(9)]
        boxes = [set() for _ in range(9)]

        empty_cells = []

        # Initialize tracking structures
        for row in range(9):
            for col in range(9):
                value = board[row][col]

                if value == ".":
                    empty_cells.append((row, col))
                else:
                    rows[row].add(value)
                    cols[col].add(value)

                    box_index = (row // 3) * 3 + (col // 3)
                    boxes[box_index].add(value)

        def backtrack(index: int) -> bool:
            # All cells filled successfully
            if index == len(empty_cells):
                return True

            row, col = empty_cells[index]
            box_index = (row // 3) * 3 + (col // 3)

            for digit in "123456789":

                # Skip invalid placements
                if (
                    digit in rows[row]
                    or digit in cols[col]
                    or digit in boxes[box_index]
                ):
                    continue

                # Place digit
                board[row][col] = digit

                rows[row].add(digit)
                cols[col].add(digit)
                boxes[box_index].add(digit)

                # Continue solving
                if backtrack(index + 1):
                    return True

                # Undo placement
                board[row][col] = "."

                rows[row].remove(digit)
                cols[col].remove(digit)
                boxes[box_index].remove(digit)

            return False

        backtrack(0)
```该实现首先创建三个集合数组来跟踪行、列和子框中使用的数字。 此预处理阶段将昂贵的重复验证转换为恒定时间的成员资格检查。 

电路板被扫描一次以填充这些结构。 在此扫描期间，所有空单元格也被收集到`empty_cells`，这避免了在递归过程中重复搜索空位置。 

递归`backtrack`函数一次处理一个空单元格。 这`index`参数确定当前正在求解哪个空单元格。 

对于每个候选数字：

 - 该算法检查该数字是否已存在于相应的行、列或框中。 
- 如果有效，则放置该数字并更新所有跟踪结构。 
- 递归继续到下一个空单元格。 

如果更深层次的递归失败，算法将删除该数字并恢复所有状态。 这确保了未来的递归分支从干净的板配置开始。 

一旦每个空单元格都被填充，递归就会成功终止。 

## 解决方案```go
func solveSudoku(board [][]byte) {
	rows := make([]map[byte]bool, 9)
	cols := make([]map[byte]bool, 9)
	boxes := make([]map[byte]bool, 9)

	for i := 0; i < 9; i++ {
		rows[i] = make(map[byte]bool)
		cols[i] = make(map[byte]bool)
		boxes[i] = make(map[byte]bool)
	}

	type Cell struct {
		row int
		col int
	}

	var emptyCells []Cell

	// Initialize tracking structures
	for row := 0; row < 9; row++ {
		for col := 0; col < 9; col++ {

			value := board[row][col]

			if value == '.' {
				emptyCells = append(emptyCells, Cell{row, col})
			} else {
				rows[row][value] = true
				cols[col][value] = true

				boxIndex := (row/3)*3 + (col / 3)
				boxes[boxIndex][value] = true
			}
		}
	}

	var backtrack func(int) bool

	backtrack = func(index int) bool {

		// Puzzle solved
		if index == len(emptyCells) {
			return true
		}

		row := emptyCells[index].row
		col := emptyCells[index].col

		boxIndex := (row/3)*3 + (col / 3)

		for digit := byte('1'); digit <= byte('9'); digit++ {

			if rows[row][digit] ||
				cols[col][digit] ||
				boxes[boxIndex][digit] {
				continue
			}

			// Place digit
			board[row][col] = digit

			rows[row][digit] = true
			cols[col][digit] = true
			boxes[boxIndex][digit] = true

			if backtrack(index + 1) {
				return true
			}

			// Undo placement
			board[row][col] = '.'

			delete(rows[row], digit)
			delete(cols[col], digit)
			delete(boxes[boxIndex], digit)
		}

		return false
	}

	backtrack(0)
}
```Go 实现遵循与 Python 版本相同的算法结构，但存在一些特定于语言的差异。 

Go 没有内置的集合类型，因此类型的映射`map[byte]bool`用于模拟集合。 集合中的存在由布尔值表示。 

该板使用`[][]byte`而不是字符串，因为为了提高效率，Go 通常将字符表示为字节。 

Go 还需要显式的结构定义来存储坐标，所以一个小的`Cell`为空单元格位置引入结构。 

回溯状态恢复使用`delete`函数从地图中删除数字。

 ## 边缘情况

 一个重要的边缘情况是已经完全解决的电路板。 某些实现假设始终存在空单元格，并且可能会错误地输入递归或修改有效值。 这个实现自然地处理了这种情况，因为`empty_cells`列表变空，导致递归函数立即返回`True`。 

另一种关键的边缘情况涉及只有一个有效候选者的单元格。 不正确的验证逻辑可能会意外拒绝唯一有效的数字或允许无效的放置。 跟踪集确保每次候选检查都是一致且恒定的时间，防止微妙的规则违规。 

更困难的边缘情况是具有许多空单元的板，需要大量回溯。 糟糕的实现可能会忘记在递归期间正确恢复状态，从而在跟踪结构中留下过时的值。 此实现在回溯期间显式地从棋盘、行集、列集和框集中删除数字，保证每个递归分支从干净的状态开始。
