[项目欧拉问题 185](https://projecteuler.net/problem=185)

 ## 解决方案

 **答案：**`4640261571849533`让未知的16位秘密成为$$x_0x_1x_2\dots x_{15}$$每个猜测都会给出以下形式的约束：

 > “正是$k$位置匹配。”

 这是一个**约束满足问题**。 

对于每一行$g$,$$\sum_{i=0}^{15} [x_i = g_i] = k$$在哪里$[P]$为 1 if 命题$P$为真，否则为 0。 

关键的观察结果是约束条件极其严格：

 - 22 个方程，
 - 只有 16 位数字，
 - 每个位置只有 10 种可能性。 

暴力搜索结束$10^{16}$候选人是不可能的，但仔细修剪的回溯搜索是非常小的。 

---

 # 数学分析

 我们将每个猜测编码为：$$(g^{(j)}, c^{(j)})$$在哪里：

-$g^{(j)}$是一个16位数字的字符串，
 -$c^{(j)}$是所需的精确匹配数。 

对于部分构建的秘密，假设我们已经分配了一些位置。 

对于每一条线索$j$， 定义：

-$m_j$：当前已经强制进行的比赛数量，
 -$r_j$： 剩余位置尚未分配。 

那么可行性需要$$m_j \le c_j \le m_j + r_j$$因为：

 - 我们不能超过所需的比赛数量，
 - 即使所有剩余位置都匹配，我们仍然必须能够到达$c_j$。 

这给出了强大的修剪规则。 

---

 ## 来自“0 正确”行的强约束

 我们被告知：$$2321386104303845 ; 0 \text{ correct}$$因此，该秘密在**每个**位置上都与这一行不同。 

所以立即：$$x_i \ne (\text{digit in that row at position } i)$$对于所有 16 个位置。 

仅此一项就消除了每个位置一位数字。 

---

 # 高效的搜索策略

 我们逐个位置递归地分配数字。 

每一步：

 1. 尝试候选数字。 
2. 更新所有线索匹配计数。 
3. 如果任何线索变得不可能，请立即拒绝：$$m_j > c_j$$或者$$m_j + r_j < c_j$$由于约束条件如此严格，树会迅速倒塌并产生独特的解决方案。 

---

 # Python 实现```python
from collections import defaultdict

# (guess, number_of_correct_positions)
clues = [
    ("5616185650518293", 2),
    ("3847439647293047", 1),
    ("5855462940810587", 3),
    ("9742855507068353", 3),
    ("4296849643607543", 3),
    ("3174248439465858", 1),
    ("4513559094146117", 2),
    ("7890971548908067", 3),
    ("8157356344118483", 1),
    ("2615250744386899", 2),
    ("8690095851526254", 3),
    ("6375711915077050", 1),
    ("6913859173121360", 1),
    ("6442889055042768", 2),
    ("2321386104303845", 0),
    ("2326509471271448", 2),
    ("5251583379644322", 2),
    ("1748270476758276", 3),
    ("4895722652190306", 1),
    ("3041631117224635", 3),
    ("1841236454324589", 3),
    ("2659862637316867", 2),
]

N = 16

# Precompute allowed digits for each position
allowed = [set("0123456789") for _ in range(N)]

# Apply the 0-correct constraint immediately
for guess, score in clues:
    if score == 0:
        for i, d in enumerate(guess):
            allowed[i].discard(d)

solution = None

def search(pos, current, matches):
    global solution

    if solution is not None:
        return

    # Finished all positions
    if pos == N:
        if all(matches[i] == clues[i][1] for i in range(len(clues))):
            solution = "".join(current)
        return

    for digit in allowed[pos]:

        new_matches = matches[:]

        # Update match counts
        for i, (guess, score) in enumerate(clues):
            if guess[pos] == digit:
                new_matches[i] += 1

        # Feasibility check
        feasible = True
        remaining = N - pos - 1

        for i, (guess, score) in enumerate(clues):
            m = new_matches[i]

            # Too many matches already
            if m > score:
                feasible = False
                break

            # Even matching everything left can't reach score
            if m + remaining < score:
                feasible = False
                break

        if feasible:
            current.append(digit)
            search(pos + 1, current, new_matches)
            current.pop()

search(0, [], [0] * len(clues))

print(solution)
```---

 # 代码演练

 ## 1. 存储线索```python
clues = [
    ("5616185650518293", 2),
    ...
]
```每个元组包含：

 - 猜测的序列，
 - 正确位置的确切数量。 

---

 ## 2. 允许的数字```python
allowed = [set("0123456789") for _ in range(N)]
```最初每个位置都可以包含任何数字。 

然后我们处理 0 个匹配的线索：```python
if score == 0:
    for i, d in enumerate(guess):
        allowed[i].discard(d)
```所以这些数字在其位置上是被禁止的。 

---

 ## 3. 递归搜索```python
search(pos, current, matches)
```参数：

-`pos`= 当前数字位置，
 -`current`=部分秘密，
 -`matches[i]`= 当前匹配的线索$i$。 

---

 ## 4.更新约束

 尝试输入数字时：```python
if guess[pos] == digit:
    new_matches[i] += 1
```---

 ## 5.修剪

 对于每条线索：```python
if m > score:
```已经有太多比赛了。 

和```python
if m + remaining < score:
```即使所有剩余位置都匹配，我们也无法达到所需的总数。 

这两个不等式几乎修剪了整个搜索树。
